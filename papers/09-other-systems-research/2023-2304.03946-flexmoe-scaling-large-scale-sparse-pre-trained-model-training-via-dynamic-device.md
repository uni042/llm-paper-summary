# FlexMoE: Scaling Large-scale Sparse Pre-trained Model Training via Dynamic Device Placement

> routing負荷に応じてexpertのGPU配置・複製数を動的に変え、token dropなしで分散MoE学習の不均衡を緩和するシステム。

## 概要
FlexMoE は、sparsely-gated MoEでexpertごとの token routing が偏り、偏りも学習中に変化するためGPU間待ち時間が増える問題を、モデル定義を変えずexpert配置を動的に変えて解決する分散学習システムである。MoEはgateがtokenを少数expertへ送りモデル容量を増やすが、固定expert parallelismでは人気expertのGPUだけ過負荷になる。DeepSpeedのcapacity制限はtoken dropでstepを短くする一方、学習信号を失い収束stepを増やす。FasterMoEの全GPU複製はdropを防ぐものの、粒度が粗く同期が重い。FlexMoEは重いexpertだけを必要数replica化しtokenを分散するfine-grained replicated expert parallelismを提案する。本論文はmodel、optimizer、activation stateをCPU/SSDへ退避するoffload研究ではなく、GPU上のexpert weightsと計算・勾配同期の配置を扱う。CPUはスケジューラ用で、CPU DRAM/NVMe、SSD caching、GDS direct I/Oは使わない。heterogeneous resourceとはCPU–GPU memory tierでなく、NVLink接続GPU、ノード間InfiniBand、各GPUの計算容量と通信帯域である。64-expert GPT-MoE traceではTop-10 expertが約75%のtokenを受け、人気度が滑らかに変化するskew/fluctuationを観測した。この実測が固定配置ではなくリアルタイムtrafficに追随するschedulerを導く。したがってFlexMoEは、offloadによる容量拡張より、複数GPU間の不均衡とtoken dropを配置と複製で解消する代表例である。
## 手法のあらまし
gateが元expertを決め、routerがそのreplica（vExpert）へtokenを貪欲に配り、replicaがforward/backwardを行う。vExpertは一つのmaster expertの複製で、同一GPU上の同expert replicaは重みを共有し、tokenを分割する最小スケジューリング単位である。Schedulerは実測token loadとexpert–GPU写像を監視し、balance ratioが閾値を越えた時だけPolicy Makerを起動する。Policy Makerは最大実行時間を基準に、Expand（複製追加）、Shrink（削減）、Migrate（GPU移動）の候補を作り、tokens-per-second、AllToAll帯域、replica間gradient AllReduce、移動コストをcost modelで見積もる。候補後の最大時間が下がる操作をgreedyに採用する。routerはlocal GPUを優先し、残りをreplicaの空きcapacityに比例して散布、expert-wise layoutで連続配置する。操作はqueue化し、同じsource/destinationはmerge、独立操作は並列化する。専用CUDA streamで学習通信と重ねるbest-effort adjustmentにより、変更が逆効果でも学習を止めない。複数expertのAllReduce deadlockはlogical IDの昇順呼び出しで回避し、NCCL groupはLRU cacheで再利用する。実装はPyTorchのcustom operator/CUDA kernelとして作られ、Hetuにも統合された。Top-2 gate、capacity factor 1.0、balance loss 0.001で元routingを保ち、tokenを別expertへ再割当て／dropしない。従ってoptimizer stateのCPU/NVMe offloadやactivation checkpointingではなく、GPU計算、AllToAll、replica AllReduceを協調させる手法である。
## 評価

### まず見るところ
- **結論:** routing偏りに合わせてhot expertだけ複製・移動すると、token dropなしでmulti-GPU MoE trainingのstragglerを大きく減らせる。
- **学習速度:** 目標品質までの時間はDeepSpeedより平均約1.7倍、FasterMoEより約1.3倍高速。
- **収束・品質:** token dropを減らすため、単なるstep time短縮だけでなく同一予算のloss/PPL/accuracyも改善する。
- **メモリ・I/O:** CPU/SSD offloadではなく、GPU間のexpert placementとAllToAll/AllReduce最適化。
- **評価の強さ／注意点:** **最大64×A100実機**。再配置頻度を上げすぎるとstate移動・同期overheadが増え、後続SYMIがこの弱点を扱う。
