# SYMI: Efficient Mixture-of-Experts Training via Model and Optimizer State Decoupling

> expert重みとoptimizer stateを分離し、動的なexpert複製・再配置時の状態移送を避けてMoE学習を効率化するシステム。

## 概要
SYMIは、hot expertを頻繁に複製・再配置したい一方、Adamのoptimizer stateまで一緒に移すと通信量とmemoryが急増する問題を扱う。

そこで **model state（expert weight）とoptimizer stateの配置を切り離す**。expert weightはrouting負荷に応じてGPU上で動かせるが、巨大なoptimizer stateはhost側へ静的にshardして動かさない。

これにより、FlexMoEのような動的expert placementをより短い間隔で行っても、毎回optimizer stateを移す必要がなくなる。

## 手法のあらまし

### 1. `model / optimizer state decoupling`

通常はexpert weightと、それに対応するmomentum/varianceなどのoptimizer stateを同じplacement単位として扱う。

SYMIはこの対応を切り離し、

- expert weight: GPU上で動的に複製・移動
- optimizer state: host DRAM上へ静的にshard

とする。

Adam混合精度ではoptimizer stateの方がweightより大きいため、**動かす対象をweightだけに限定する効果が大きい**。

### 2. 前iterationのroutingを次iterationの予測に使う

各iterationでexpert popularityを集計し、その結果を次iterationの複製数へ使う。

hot expertには多くのreplica、cold expertには最低1 replicaを割り当てる。

専用predictorを学習するわけではなく、**routingの短期的な時間局所性**を利用する方式である。

### 3. optimizer update結果を既存通信へ載せる

optimizer stateはhost側にあるが、更新後のexpert weightは次のGPU実行に必要になる。

SYMIは更新済みweightを、もともと必要なweight通信へpiggybackして送り、再配置専用の追加通信を極力作らない。

### 4. gradient通信もoptimizer shardに合わせて分散する

gradientは、対応するoptimizer shardを持つrankへ送る必要がある。

SYMIはlocal転送を優先し、remote送信はround-robinで分散して、特定rankへのhotspotを避ける。

### 5. replica gradientを二段階でreduceする

同じGPU内に同一expertのreplicaが複数ある場合、まずlocal replica間でまとめ、その後rank間AllReduceを行う。

これにより、GPU内複製が増えてもnetwork通信をreplica数に比例して増やさない。

## 評価

### まず見るところ
- **結論:** expert weightの再配置とoptimizer stateの配置を切り離すと、hot expertを頻繁に複製しても巨大optimizer stateを毎回動かさずに済む。
- **学習速度:** DeepSpeedより目標loss到達時間を約3割短縮し、FlexMoEよりも速い。
- **収束:** token dropを減らすため、1 iterationの速さだけでなく必要iteration数も減る。
- **I/O:** optimizer stateは主にCPU host DRAMへ静的shard。NVMe/GDS研究ではない。
- **注意点:** popularity予測は前iteration依存なので、routingが急変すると外れる。

### 実験設定

| 項目 | 条件 |
|---|---|
| GPU | 16 GPU |
| Model | GPT Small / Medium / Large（125M / 350M / 760M） |
| Experts | 16 |
| Routing | Top-1 |
| Capacity factor | 1.0 |
| Baseline | DeepSpeed ZeRO-1、FlexMoE |

### 目標loss到達時間

GPT-Smallでloss 4.0へ到達する時間：

| System | 時間 |
|---|---:|
| DeepSpeed | 147.84分 |
| FlexMoE-100 | 145.42分 |
| FlexMoE-50 | 141.60分 |
| FlexMoE-10 | 138.61分 |
| SYMI | 102.68分 |

SYMIはDeepSpeed比で約30.5%、FlexMoE比で約25.9〜29.4%短縮した。

### iteration数とtoken drop

| 指標 | 改善 |
|---|---:|
| loss到達までのiteration数 | 約28.5%削減 |
| token drop | DeepSpeed比69%削減 |
| token drop | FlexMoE比43〜64%削減 |

ここでは**1 stepを速くする効果だけでなく、drop削減で収束step自体を減らす効果**が大きい。

### 平均iteration latency

| Model | 改善 |
|---|---:|
| Small | 2.8%短縮 |
| Medium | 3.2%短縮 |
| Large | 9.3%短縮 |

1 iteration単体の改善は比較的小さいが、必要iteration数削減と合わせてtime-to-lossが大きく改善する。

### 通信overhead

大規模モデルを想定した解析では、baseline約0.269秒に対しSYMI約0.273秒で、追加通信overheadは約1.52%。

optimizer stateを動かさないことで、頻繁なexpert再配置を比較的小さい追加通信で実現している。

### 制約

- 実機modelは最大760M級
- 最終task accuracyよりloss到達時間が主評価
- host DRAMとPCIe帯域に依存
- routing popularityが急変するworkloadでは前iteration予測が弱い
- NVMe pagingやGDSは未評価
