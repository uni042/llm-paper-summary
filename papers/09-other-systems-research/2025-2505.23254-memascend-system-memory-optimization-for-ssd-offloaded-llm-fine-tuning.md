# MemAscend: System Memory Optimization for SSD-Offloaded LLM Fine-Tuning

> buffer fragmentation削減・direct NVMe I/O・低精度optimizerを組み合わせ、SSD-offloaded LLM fine-tuningの容量と速度を改善する方式。

## 概要
MemAscendは、ZeRO-Infinity型のSSD-offloaded LLM fine-tuningで見落とされていたCPU system memoryの浪費を削るフレームワークである。従来方式はGPUに置けないmodel weight、gradient、optimizer stateをCPU DRAM経由でNVMe SSDへ退避するが、固定サイズbuffer、pinned memoryの過剰alignment、一時的なoverflow判定テンソル、ファイルシステム／stagingの重複がRAMとCPU時間を押し上げる。MemAscendはこの「SSDを増設してもsystem memoryが先に尽きる」問題に焦点を置き、GPU容量拡大やMoE expert routingを新規提案するものではない。四つの最適化で、offloaded static stateを通常NVMeへ置きながら、CPU側のbuffer poolとI/O経路を軽くする。KV cache offloadや生成推論を扱う論文ではなく、forward/backward、gradient checkpoint、optimizer updateを含むfine-tuningが対象である。Qwen3-30B-A3Bを含むためsparse LLMにも触れるが、expertをGPU／CPUで選択的に実行するMoE servingではない。CXLメモリの容量拡張、CSD内演算、DASHのHBFとは異なり、既存のCPU DRAM＋SSD/NVMeサーバーのメモリ管理を改善するソフトウェア系統である。数値精度を変えない主構成と、任意でbf16 optimizerを選べる拡張を分けて報告する点にも注意が要る。
## 手法のあらまし
第一のadaptive buffer poolは、モデルごとのtensorサイズに合わせて複数サイズのbufferへ割り当て、最大embedding tensorに全poolを揃えるZeRO-Infinityの内部fragmentationを避ける。固定poolでは13.05GiB予約しても同時使用は3.81GiBという例があり、最大72.71%の無駄が生じる。第二のalignment-free pinned allocationは、PyTorch CachingHostAllocatorのpower-of-two丸めやページalignmentを避け、PCIe DMA用のpage-locked領域を必要量で確保する。第三のfused overflow checkはgradientのNaN/Inf判定を一回のpassへ融合し、中間Boolean tensorと二重peakを除く。第四のDirect NVMe Engineは通常filesystemを迂回し、O_DIRECT系の低レベル経路でSSD–GPU/CPUデータ管理とread/writeを行い、staging overheadを削る。さらにbf16 half-precision optimizerではparameter、gradient、momentumをfp16/bf16で転送し、fp32 optimizer stateのI/O量を減らす。既存のFlash-Attention、Liger-Kernel、gradient checkpointing、offloaded checkpointと併用でき、GPU残差メモリとCPU static-state bufferを別々に削減する設計である。各層のweightはSSDからCPU pinned bufferへ読み、GPU計算後にgradient／stateを戻すため、SSDの容量をHBMのように扱うわけではない。bufferとoverflowの改善は数値・収束を変えないが、bf16 optimizerは精度／対応GPUとのトレードオフがある。従ってweight／optimizerのNVMe offloadを、KV cache offloadやnear-storage計算と混同しない分類が必要である。
## 評価
構成1はIntel Xeon 6780E、1TB DDR5-6400、2×NVIDIA H100 PCIe、DapuStor Haishen5 H5100 7.5TB、構成2はdual AMD EPYC 7282、1TB DDR4-3200、NVIDIA A5000、2×Phison AI100E。sparse構成3はXeon 8480+、2×H100 SXM5（NVL）、2×Samsung 980 Pro。Llama3.1-8B、Qwen2.5-7B/14B/32B、Qwen3-30B-A3Bをcontext 4,096–131,072、複数batchでfine-tuneし、ZeRO-Infinity（Flash-Attention、Liger-Kernel、checkpoint共通）とpeak system memory、throughput、overflow latency、I/Oを比較する。adaptive poolはbuffer wasteを平均55.7%（最大72.71%）削減。fp16 throughputは構成1でbaseline比2.72–6.97%、構成2で6.77–18.86%向上。128GiBではbaselineがcontext 16,384／batch4付近で制約される一方、MemAscendは131,072 tokensまたはbatch32へ拡張可能と報告する。bf16 optimizerでは構成1平均27.25%（Qwen2.5-7B最大56.80%）、構成2平均17.08%（Qwen2.5-32B最大24.21%）向上し、I/O量を58%減らす。OpenWebTextでの250 stepsはZeRO-Infinityとloss曲線が一致。限界はfine-tuning専用でdecode latency・KV／expert cacheを測らず、公式codeが未公開なこと。個人PC用ではなく、CPU RAMをボトルネックとする通常SSD offloadの最適化候補である。[arXiv本文v4](https://arxiv.org/html/2505.23254v4)、[IEEE TETC情報](https://www.computer.org/csdl/journal/ec/2026/01/11391518/2dZTJTZCCAM)
