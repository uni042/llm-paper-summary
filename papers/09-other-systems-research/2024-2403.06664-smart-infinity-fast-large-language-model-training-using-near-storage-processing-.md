# Smart-Infinity: Fast Large Language Model Training using Near-Storage Processing on a Real System

> SmartSSD上でoptimizer更新をnear-storage処理し、LLM学習のSSD–CPU／GPU間データ移動を削減する実機システム。

## 概要
Smart-InfinityはLLMのSSD-offloaded fine-tuning／trainingで、SSD帯域を食い潰すoptimizer更新をストレージ側へ移すnear-storage処理系である。ZeRO-InfinityのようにGPUを越えたモデル重み、gradient、optimizer stateをCPU DRAMとNVMe SSDへ置くと、forward/backward後の更新で大量の状態をSSDから読み、更新後に書き戻す必要がある。論文の分析ではoptimizer stateの通信がGPT-2 8.4Bのbaseline時間の75.57%を占める。そこでSmart-Infinityは、SSDに直結したFPGA付きcomputational storage device（CSD）内でAdamなどのparameter updateを行い、SSD内部帯域を利用してホストPCIe通信を減らす。これは通常のNVMeを単にGPUへ直結する方式でも、CPU DRAMにexpertを置くMoE推論でもない。near-storage acceleratorへ置くのは学習時のoptimizer updateであり、推論のKV cache offloadやMoE expert選択を扱わない。GPUはforward/backwardとgradient生成、CSDは更新、SSDは永続化を分担し、複数CSDを増設して内部帯域を集約する。ストレージ側へ計算を押し込むため、モデル構造に依存しないflattened parameter subgroup処理を採用し、LLM以外のTransformerやViTにも適用可能とする。従って候補リストでは、MoNDE（CXL-NDP）やDASH（HBF）とは異なる、既製NVMe SSDパッケージ内FPGAというnear-storage系統として扱うべきである。
## 手法のあらまし
中心のSmartUpdateは、各CSDが所有するflattened parameter subgroupについて、SSDからparameterとoptimizer stateをFPGAのBRAMへ読み、AXPBY型のベクトル演算でAdamのmomentum／varianceを gradientへ適用し、更新parameterと新optimizer stateをSSDへ戻す。GPUがoptimizer updateを実行する従来系と違い、勾配以外の大きな状態をPCIeへ往復させない。data transfer handlerはCSDの固定bufferを再利用し、SSD–FPGAの内部P2P DMAをsubgroup間で重ねるため、全モデル用の一時host bufferを確保しない。さらにSmartCompはGPUで勾配の大きさ上位1%を選び、indexとvalueを合わせ元通信量の2%に圧縮し、CSD FPGAでscatter復元してからSmartUpdateへ渡す。圧縮はlossyだが学習精度を確認する設計である。実装はDeepSpeed ZeRO-Infinityのgradient offload/update経路を置換し、PyTorchからcallable moduleとして利用でき、Adam以外にmomentum SGDとAdaGradもHLS updaterで実装する。ハードウェアはXilinx Kintex UltraScale+ KU15P FPGAをSamsung SmartSSD（4TB NVMe、PCIe Gen3 x4）に接続し、複数台はPCIe expansionでまとめる。CPUを更新計算器にするMoE-Infinity等と異なり、SSD内FPGAへ演算を近づけることが帯域削減の根拠である。
## 評価

### まず見るところ
- **結論:** optimizer updateをSSD内FPGAへ移すと、ZeRO-InfinityのSSD↔host転送を減らし、SSD-offloaded trainingを実際に高速化できる。
- **学習速度:** SmartSSD台数を増やすほど伸び、代表条件で約1.5〜2倍、A100条件では最大約2.1倍。
- **品質:** SmartUpdateはbaselineと同精度。SmartCompのgradient圧縮は近似だが、評価taskでは大きな品質崩れを示さない。
- **メモリ・I/O:** **通常NVMeではなくFPGA付きcomputational storage**。optimizer stateをSSD内部で更新し、PCIe往復を減らす。
- **評価の強さ／注意点:** **実SmartSSD最大10台**。価格が通常SSDより大幅に高く、個人PC向けの汎用NVMe offloadとは別物。
