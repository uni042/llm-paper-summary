# Examining Post-Training Quantization for Mixture-of-Experts: A Benchmark

> MoEのpost-training quantizationを体系比較し、expert頻度・block位置・linear層ごとの量子化感度を示すベンチマーク。

## 概要
この研究の差分は、量子化方式を一つ発明することより、同一平均bitで「頻度・block位置・linear層」のどれを高bit化すると有利かを分離したことにある。Mixtralの均等routingとDeepSeekの不均衡routingを並べたため、頻度ヒューリスティックがモデル依存になることも検証できる。

## 手法のあらまし

### 1. この論文は「新しい量子化器」よりbit配置の比較が主題

比較するのは、全expertを同じbitへ落とす方式だけではない。同じ平均bit数を保ったまま、**どの部分へ高bitを残すか**を変えて品質差を見る。

評価粒度は主に次の4段階である。

| 粒度 | 何を見るか |
|---|---|
| expert frequency | よく使われるexpertを高bitにすべきか |
| block position | 特定のMoE blockが量子化に弱いか |
| linear layer | gate/up/down等のlinearごとに感度が違うか |
| shared / attention | routed expert以外を保護すべきか |

### 2. `frequency-based allocation`

calibration dataを流し、各MoE blockでexpertが何回選ばれたかを集計する。その上で、高頻度expertだけ4 bit、残りを2 bitにする。

ここで重要なのは、**高頻度＝常に重要、とは仮定していない**ことだ。Mixtralのようにroutingが比較的均等なモデルでは頻度差が小さく、このheuristicの利点も小さい。一方DeepSeekのように偏りが強いモデルでは有効になりやすい。

### 3. `linear-weight outlier scorer`

expert単位より細かく、各linear weightがどの程度量子化に弱いかを、重みの外れ値量から順位付けする。

上位25%や50%のlinearだけ4 bitへ戻し、それ以外を2 bitにすることで、**同じ平均bitでも感度の高い場所へ精度を集中させる**。

### 4. `MoE block scorer`

今度は逆に、linearより粗いblock単位で量子化損失を見積もり、重要blockだけ4 bitにする。

したがってこの論文は、expert / linear / blockという複数の粒度で、「低bit化する場所の選び方」を比較したbenchmarkとして読むのが分かりやすい。

### 5. GPTQとSmoothQuantの両方で確認

weight-onlyではGPTQ、weight+activationではSmoothQuantを使う。つまり結果は特定の1つの量子化アルゴリズムだけに依存するというより、**MoE構造を考慮したbit配置そのものが有効か**を確認する設計になっている。

## 評価

### まず見るところ
- **結論:** 同じ2〜4bit予算でも、どのexpert/block/linearを高精度に残すかで品質が変わる。
- **品質:** frequencyだけでなくblock/linear感度を使う構造aware mixed precisionがrandom allocationより安定する。
- **圧縮:** 平均bitをかなり下げても高感度部分を保護すれば品質を守れる余地がある。
- **実速度:** **主評価は精度とbit配置で、wall-clock speedup論文ではない**。
- **注意点:** routing頻度はmodelとcalibration dataに依存し、Mixtralのような均衡routingでは効果が小さい。

### 評価環境

| 項目 | 内容 |
|---|---|
| GPU | NVIDIA H100 ×3 |
| モデル | Mixtral-8x7B / DeepSeek-MoE-16B-base |
| calibration | WikiText 512系列 × 4096 token |
| 評価 | WinoGrande, COPA, OpenBookQA, HellaSwag, PIQA, MMLU |
| 実装 | GPTQ / SmoothQuant、group size 128 |

### Mixtral：高頻度expertを高bitにする効果

| 平均bit | 配置 | 平均精度 |
|---:|---|---:|
| 2.54 bit | 頻度上位2 expertを4 bit | 54.20% |
| 2.54 bit | ランダムに4 bit | 49.10% |
| 3.03 bit | 頻度上位4 expertを4 bit | 63.82% |
| 3.03 bit | ランダムに4 bit | 63.70% |

2.54 bitでは差が大きい一方、3.03 bitではほぼ同じになる。**高bit expert数が増えるほど、配置方法の差が小さくなる**ことが分かる。

### DeepSeek：頻度heuristicの読み方

平均2.53 bitで頻度上位10 expertを4 bitにした場合は62.99%、ランダムは62.86%で、この設定だけなら差は小さい。一方、高bitに残すexpert数を増やした設定では頻度法がより安定して優位になる。

これは「DeepSeekなら頻度だけで十分」という意味ではなく、**routingの偏りがあるモデルではfrequencyをbit配置の手掛かりに使える**という程度に読むのが妥当である。

### activation bitを増やしても改善が小さい例

Mixtralの重み平均2.54 bit条件でSmoothQuantを使った場合、activation 4 / 8 / 16 bitの平均精度は38.30 / 39.79 / 39.71%だった。

この条件ではactivationだけ高精度へ戻しても改善が限定的で、**どのweightを低bit化したかの方が支配的**だった。

### この論文で実速度を主張しない理由

実験にはH100を使っているが、中心指標はaccuracyと平均bitで、GPU latencyやtokens/sの横断比較は限定的である。

したがって後続のMxMoEのような「kernel実時間まで含めてbit allocationを決める研究」とは役割が異なり、こちらは **MoE量子化の感度マップを作ったbenchmark** と位置付けるのが適切である。
