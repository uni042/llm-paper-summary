# DynaMo: Runtime Switchable Quantization for MoE with Cross-Dataset Adaptation（旧題 MoQa）

> データ分布に応じてexpertのbit群とsalient channelを実行時に切り替え、再較正コストを抑えるMoE量子化方式。

## 概要
DynaMoは、**データセットが変わると重要expertも変わる**ことを前提にしたmixed-precision量子化である。旧版MoQaではexpertを主に二群へ分けていたが、v3 DynaMoではINT2/4/6/8の複数群と、dataset変更時に一部channelだけ切り替えるruntime機構へ拡張された。

## 手法のあらまし

### 1. まずexpertごとの`significance`を測る

DynaMoのsignificanceは単純なrouting頻度ではない。

- そのデータでどれだけ使われるか
- routing時にどの程度強く選ばれるか
- 他datasetでも同じexpertが重要か
- expert間のweight相関

などを組み合わせ、**そのexpertを低bit化したときにどれだけ影響が出そうか**を推定する。

### 2. v3では4つのprecision clusterへ分ける

旧MoQaは重要度の高低を二群へ分ける説明が中心だったが、DynaMoではfuzzy clusteringを使ってexpertをINT8 / INT6 / INT4 / INT2へ割り当てる。

`fuzzy`なのは、境界にあるexpertが完全に一つのclusterへ属するというより、複数clusterへの所属度を持つためである。最終割当では容量を節約するため境界expertを低bit側へ寄せる。

### 3. `salient channel cache`

datasetが変わるたびに全expertを再量子化するとコストが大きい。そこで、dataset変化に敏感なchannelだけFP16で別途保持する。

論文でいう **salient channel** は、入力分布が変わったときに量子化誤差やexpert重要度へ強く効くchannelを指す。

全weightの約1%だけをFP16 cacheとして持ち、新datasetへ切り替わった際はこの部分だけを新しいbit構成へ再量子化する。

### 4. `runtime switchable`はtoken単位ではない

名前からtokenごとにprecisionを切り替えるように見えるが、主な切替単位は **dataset / workloadの変更時** である。

つまり、

`dataset A向けbit配置 → dataset Bへ切替 → significance再計算 → salient channelだけ更新`

という運用で、decode tokenごとにINT2/INT8を動的変更する方式ではない。

### 5. 低bit形式を直接実行するkernel

低bit weightはINT32へpackし、CUDA側でunpackとFP16 MMAを融合する。したがってcross-dataset adaptationだけでなく、実生成速度まで評価できる構成になっている。

## 評価

### まず見るところ
- **結論:** workloadが変わると重要expertも変わるため、bit配置を固定せず少量のsalient channelだけ更新すると再較正を軽くできる。
- **品質:** 約3bit級でGPTQよりPPL・zero-shot精度を改善する。
- **実速度:** **A100でFP16比約2.9〜3.1倍**の生成速度。
- **切替overhead:** runtime switchingは一桁〜10%程度。
- **注意点:** 動的なのは主にdataset切替時で、token単位precision routingではない。

### v3 DynaMoの集計

| 指標 | GPTQ比 |
|---|---:|
| PPL改善 | 2.78〜4.54 |
| zero-shot精度 | +1.85〜3.77 point |
| 生成速度 | FP16比 2.91〜3.08倍 |

### runtime切替コスト

| 項目 | overhead |
|---|---:|
| channel switching | 7.73〜10.68% |
| 多段significance分析 | 14.90〜17.33%（offline） |

7B級ではsalient channel cacheが152.8MB、全weightの約1.02%だった。

ここから、DynaMoの利点は「常に動的にbitを変えること」ではなく、**dataset変化へ対応するためにモデル全体を再量子化し直さなくてよい**ことにある。
