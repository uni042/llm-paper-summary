# Dynamic Expert Quantization for Scalable Mixture-of-Experts Inference

> router traceのhotnessに応じてexpertを実行中に高bitへ昇格・低bitへ降格し、versioned residencyでprecision移行を非同期化する。

## 概要
DynaExqは、expert precisionを起動時に固定せず、**実際のrouting履歴からhotになったexpertだけ高精度へ昇格するruntime量子化システム**である。cold expertは低bitのままにし、HBM budget内で品質を戻す。

## 手法のあらまし

### 1. router traceから`hotness`を作る

各layer / expertについてTop-k routing回数を追跡し、EMAで長期hotnessを更新する。

短期的に一度だけ使われたexpertへすぐ高bit copyを載せると無駄な移行が増えるため、**瞬間的な頻度ではなく平滑化した利用傾向**を見る。

### 2. hot expertを高bitへ`promotion`する

GPU上では、hot expertを高precision、cold expertを低precisionで保持する。高精度版・低精度版の両方はhost DRAM側に準備しておき、必要に応じてGPU HBMへ移す。

ここでいうpromotion / demotionは、

- low-bit resident → high-bit resident
- high-bit resident → low-bit resident

へのprecision residency変更を指す。

### 3. `Versioned Expert Residency (VER)`

precisionを切り替える最中にforwardが中途半端なbufferを読むと壊れる。VERはexpertの論理handleと実際のGPU bufferを分離し、

- Resident-Hi
- Resident-Lo
- Promoting
- Demoting
- Evicting

などの状態を管理する。

転送が完了するまでは古い完全なcopyを使い、CUDA event完了後だけpointerを新bufferへ切り替える。これにより**precision migrationをbackgroundで進めてもforwardを止めない**。

### 4. `hysteresis`でprecision thrashingを抑える

hot/cold境界付近のexpertが頻繁に昇格・降格すると、転送コストだけが増える。そこで昇格条件と降格条件に差を持たせるhysteresisを入れ、短期変動でprecisionが往復しないようにする。

### 5. training-freeだがhost RAMは増える

モデル本体やrouterの再学習は不要。一方でhost側には複数precision copyを準備するため、**GPU HBMを節約する代わりにCPU RAM使用量とscheduler複雑性が増える**。

## 評価

### まず見るところ
- **結論:** routing hotnessに合わせてhot expertだけ高精度へ上げると、固定INT2より品質を大きく戻しつつHBM予算を守れる。
- **品質:** 低bit staticから数point回復し、高bit staticへ近づく。
- **実速度:** A6000でExpertFlow比1.42〜2.73倍のthroughput。
- **I/O:** host DRAM→GPU HBMのprecision copy移行。SSD/NVMeは対象外。
- **注意点:** host RAM使用量、workload shift、runtime schedulerの複雑さが増える。

| 条件 | ExpertFlow比 |

| 各種batch | 1.42〜2.73倍 |

precision migrationをcompute streamから分離することで、昇格・降格によるtail stallを抑える。

### 制約

評価はRTX A6000 48GBの単一GPU＋host DRAM中心。multi-GPU、SSD階層、CXLは未評価である。またhotnessが急に変わるdomain shiftでは、過去EMAが新workloadへ追いつくまで不適切なprecision配置が残る可能性がある。
