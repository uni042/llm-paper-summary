# Dynamic Expert Quantization for Scalable Mixture-of-Experts Inference

> router traceのhotnessに応じてexpertを実行中に高bitへ昇格・低bitへ降格し、versioned residencyでprecision移行を非同期化する。

## 概要
DynaExqはMoE expert precisionをruntimeのrouter traceに応じて変えるdynamic quantization systemである。静的PTQは全expert bit幅を事前固定するため、workloadやbatchでhot expert集合が変わると、重要expertを低bit化したり、冷たいexpertへ不要なHBMを使ったりする。offload／prefetchはcapacityを広げるが、同期転送がcritical pathに入りやすい。DynaExqはHBM budget下で長期hotnessの高いexpertだけを高精度にし、その他を低精度で常駐させる。precision promotion／demotionはbackgroundで行い、forwardを止めない。既存routerとmodel output pathは変えず、workloadに適応するmemory-quality allocationをruntimeへ追加する。登録済みMoQE、MoEQuant、QMoE、MxMoE、HOBBIT、ExpertFlow、MoE-Infinityを引用し、静的mixed precisionとexpert residencyを統合した後続研究である。pinned host DRAMからGPU HBMへの重み転送を使い、SSD／NVMe、HBF、CXLは扱わない。KV cache offloadではない。
## 手法のあらまし
router top-k traceをlayer／expert別に集計し、EMAで長期hotnessを推定する。各layerのHBM予算内でhot expertを高bit、cold expertを低bitに割り当て、高精度版と低精度版はhost側に準備する。Versioned Expert Residency（VER）はexpertの論理handleと物理bufferを分離し、Resident-Hi、Resident-Lo、Promoting、Demoting、Evictingなどの状態を管理する。promotion時は予算を予約し、固定粒度poolからbufferを確保して専用CUDA streamで非同期copyする。完了event後だけhandleを切り替えるため、forwardは転送途中weightを参照せず、それまでは完全な低bit版を使う。partitioned memory poolとdeterministic allocatorが断片化／一時OOMを防ぎ、hysteresisが短期hotness変動による昇降格thrashingを抑える。Transformers約3000行の拡張で、追加trainingなしに既存MoEへ適用する。複数precision copyをhostに持つためRAM costは増える。
## 評価

### まず見るところ
- **結論:** runtimeのrouter hotnessに合わせてhot expertだけ高精度へ昇格すると、固定INT2/4より品質を戻しつつHBM予算を守れる。
- **品質:** 低bit staticより数point規模を回復し、高bit staticに近づける。
- **実速度:** **A6000実機でExpertFlowより大きなthroughput改善**。precision migrationをbackground化してtail stallを抑える。
- **メモリ・I/O:** host DRAMに複数precision copyを持ち、GPU HBM residencyを動的変更する。SSDは対象外。
- **評価の強さ／注意点:** training-free＋公開codeだが、host RAM消費、domain shift、scheduler complexityが増える。

<summary>評価条件・詳細な数値を開く</summary>
