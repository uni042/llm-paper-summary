# MxMoE: Mixed-precision Quantization for MoE with Accuracy and Performance Co-Design

> linear-block単位の量子化感度・routing頻度・GPU kernel時間を共同最適化し、MoEのbit配置と実行速度を両立する方式。

## 概要
MxMoEは、mixed-precision量子化を **「品質が壊れにくいbit配置」だけでなく「GPU上で本当に速いbit配置」まで含めて決める** 手法である。expert単位ではなく、各expert内部のgate / up / down linear blockを別々に扱う。

## 手法のあらまし

### 1. expertより細かい`linear-block`単位でbitを決める

一つのexpert内でもgate / up / down projectionは量子化感度が同じとは限らない。

MxMoEは各linear blockについて、候補となる

- W2A16
- W4A16
- W8A8
- W4A4

などを一つずつ試し、元出力との差を測る。

ここで `W4A16` はweight 4 bit / activation 16 bitを意味する。つまりMxMoEは、**weight bitだけでなくactivation precisionも選択肢に含める**。

### 2. routing頻度から「実際のGEMM形状」を作る

MoEではexpertごとに処理token数が違う。同じW4A16でも、少数tokenを処理するexpertと大量tokenを処理するexpertではkernel効率が異なる。

そこでcalibration routingからexpertごとのtoken数を取得し、実際に発生しそうなGEMM shapeを作ってGPU上でprofileする。

これにより、単純な「bit数が低いほど速い」という仮定を置かず、**そのhardwareでそのshapeを実行した実時間**をcostとして使う。

### 3. `ILP`で品質・速度・memoryを同時に選ぶ

各linear blockには候補precisionごとに、

- 量子化誤差
- 実測kernel時間
- weight size

が付く。

MxMoEはこれを整数線形計画（ILP）で解き、総memory budgetの下で各blockへ1つのprecisionを割り当てる。

目的関数は量子化損失 `L` と実行時間 `T` を組み合わせ、係数 `r` により品質優先〜速度優先を切り替えられる。通常設定はr=0.75で、品質をやや重く見る。

### 4. bit配置に合わせた`mixed-precision Group-GEMM`

bit配置を最適化しても、precisionごとに別kernelを順番に起動するとlaunch overheadやidleが増える。

そこでMxMoEは、異なるprecisionのexpert GEMMをまとめて実行する専用Group-GEMMを作る。

論文中の

- micro-kernel specialization
- precision-aware tile scheduling
- slice-K tiling

は、**各precisionとGEMM shapeに合うtile/warp構成を選び、異なるprecisionを同じ実行スケジュールへ詰めるためのkernel最適化**である。

このkernelまで含める点が、bit配置だけを提案するmixed-precision研究との大きな違いになる。

## 評価

### まず見るところ
- **結論:** 量子化誤差だけでなく実GPU kernel時間まで含めてbitを決めると、品質と速度のParetoが改善する。
- **粒度:** expert単位よりlinear-block単位の方が、同じmemory予算で品質を守りやすい。
- **実速度:** **RTX 4090で実kernel throughputを測定**し、memory-bound / compute-bound双方で改善。
- **重要点:** 平均bitが同じでも実速度は同じではない。hardware profileとkernel実装が必要。
- **注意点:** 別GPUへ移す場合はkernel costの再profileが必要。

### 評価環境

| 項目 | 内容 |
|---|---|
| GPU | RTX 4090 |
| モデル | Mixtral-8x7B / Qwen1.5-MoE / Qwen2-MoE / DeepSeek-V2-Lite |
| calibration | WikiText2 128系列 × 4096 token |
| attention | FPのまま |
| 対象 | 主にMoE block |

### weight-only 2.25 bit付近の品質

| モデル | GPTQ | MxMoE | 主な差 |
|---|---|---|---|
| Mixtral | avg 67.56 / PPL 5.69 | 67.89 / 5.63 | 小幅改善 |
| DeepSeek-V2-Lite | 58.04 / 8.49 | 62.04 / 7.01 | 大きく改善 |
| Qwen2-MoE | 58.58 / 7.98 | 64.57 / 7.57 | 大きく改善 |

モデルによって改善幅は違い、全条件で一様に勝つわけではない。

### memory-bound / compute-boundでの速度

| 条件 | 比較 | 改善 |
|---|---|---:|
| 512-token、memory-bound | W4.25A15.5 vs W4A16 | 最大25%高速 |
| 8192-token、compute-bound | W5A5 vs W8A8 | 最大29.4%高速 |

full precision比のMoE-block throughputは、memory-boundで1.6〜2.7倍、compute-boundで3.0〜3.4倍と報告される。

### expert単位よりlinear-block単位が有利

DeepSeekではexpert-level allocationのPPL 6.32 / 平均精度67.88に対し、linear-block allocationはPPL 6.11 / 平均精度69.01だった。

つまり、同じexpertの中でも **高bitを残すべきmatrixと低bit化してよいmatrixが違う**。

### 例外

Qwen2の3.25 bit条件では、感度推定やlayer間依存の影響でGPTQにわずかに劣るケースもある。したがってILPの局所的な感度表だけで、全モデル挙動を完全に予測できるわけではない。
