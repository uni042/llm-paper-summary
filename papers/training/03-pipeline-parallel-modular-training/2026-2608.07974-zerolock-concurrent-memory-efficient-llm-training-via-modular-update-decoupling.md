# ZeroLock：局所目的関数による更新依存の解消と省メモリ並列微調整

> 大規模言語モデルを連続した層群へ分割し、各段の予測分布に局所損失を与えることで段間の逆伝播依存を切る方式。三段の実機試験では、PipeDreamに対する最大段のピークメモリを26.5%削減し、標準条件の処理量を4.9%改善した。ただし、同一段の内部では通常の逆伝播を行い、推論高速化の手法ではない。

## 概要

ZeroLockが解決しようとするのは、限られたメモリと通信帯域を持つ複数の装置で、大規模言語モデルを追加学習するときの更新待ちである。従来のパイプライン並列学習では、モデルを装置ごとに分割しても、上流段の勾配を計算するには下流段の順伝播と逆伝播が必要になる。上流段はその間、過去の小バッチの活性値を保持する。処理順を調整するだけでは、この勾配依存を完全には消せない。

提案法は、各段の出力を凍結した語彙予測器に通して局所的な学習目標を構成する。各段は下流段から勾配を受け取らず、自段内で低ランク追加重みを更新する。これにより、順伝播で得た隠れ状態を先に下流へ送り、上流の局所逆伝播と下流の順伝播を並行させられる。保持する活性値も自段の局所更新が済めば解放できる。学習目的、通信、障害復旧の三つを一緒に変更することが本研究の特徴である。

論文の対象は、学習済みモデルの低ランク適応を複数装置で行う微調整である。大規模な事前学習、単一GPU上の通常の推論、重みをCPUや記憶装置へ退避する方式とは区別する。論文は理論的収束解析と、三枚のGPUおよび三台の携帯端末による試作を報告している。

## 問題設定

モデルの層を複数の連続した群に分割し、群ごとに一つの実行段を割り当てる。標準的な逆伝播では、最終層から順番に勾配を戻す必要がある。したがって、先頭段は下流の計算が終わるまで局所パラメータの更新を確定できず、複数の小バッチに対応する活性値を長時間保持する。この現象を更新ロック（update locking）と呼ぶ。図1は、同じ段数でも更新ロックの有無によって、段の空転時間と活性値の生存期間が変わることを示す。

比較対象のGPipeは一つの論理バッチの順伝播を終えてから逆伝播を進める。1F1Bは順伝播と逆伝播を交互に配置するが、段間の勾配依存は残る。PipeDreamは重みの複数版を保持して連続的に段を稼働させるものの、下流から勾配を受け取る構造自体は変わらない。ZeroLockは、単なる実行順序の改善ではなく、局所目的関数によって段を独立更新可能にする点でこれらと異なる。

## 手法

### 1. 層群の分割と更新対象

埋め込み層の後に続く変換器の層を、連続するK個の層群へ分ける。第k段は前段から長さSの隠れ状態を受け取り、自分の層群を順伝播させて次段への隠れ状態を作る。学習済みの基底重みは凍結し、各層の低ランク適応（LoRA）の二つの行列だけを更新する。つまり、更新対象は各段に局在する。段内の複数層には通常の逆伝播を適用するため、「勾配計算を全面的に廃止する」という説明は正しくない。

第k段の出力を h_k、固定した基底重みを W_k、学習する追加重みを ΔW_k とすると、前段の出力から h_k=f_k(h_(k−1); W_k+ΔW_k) を計算する。段間では h_k を渡すが、その値に付随する逆伝播用の計算グラフは切り離す。段の境界で勾配の連鎖を切るため、下流段の局所損失が上流段のパラメータを直接更新することはない。

### 2. 語彙予測に基づく局所目的関数

各段の隠れ状態を最終層用の正規化と凍結した言語モデル出力行列へ通し、語彙上の予測分布 p_k を得る。最終段以外でも、現在の層群が正解トークンをどの程度説明できるかを測るための読み出し口である。読み出し口を凍結すれば、段ごとに大きな新規学習パラメータを導入せずに済む。

局所損失は二つの項の加重和である。第一項は、その段の予測を教師トークンに近づける課題損失であり、第二項は直前段の予測分布との整合性を保つ損失である。論文では重み係数 α を使い、`L_k = α L_task(p_k) + (1−α) L_consistency(p_k, stop_gradient(p_(k−1)))` と書く。整合性項の前段予測には勾配停止を適用するため、局所損失を通じて前段へ逆伝播が流れない。損失の定式化にはブレグマン発散を用い、実装では交差エントロピーやカルバック・ライブラー発散を利用できる。

この方式は、前段と教師信号の両方を参照して中間段の表現を調整する。ただし、最終言語モデル出力行列が中間段の隠れ状態を意味のある語彙分布へ写せることが重要な仮定である。論文は必要に応じて小規模な読み出し補助器を追加する設計も述べるが、全ての生成課題でこの仮定が成立することを証明してはいない。

### 3. 独立更新の実行順序

各段の実行は、入力隠れ状態と教師情報の取得、順伝播、出力隠れ状態の下流送信、局所逆伝播、最適化器更新という順序で進む。送信を局所逆伝播より前に行う早期転送（early forwarding）が重要である。下流段は上流の局所更新が終わる前に順伝播を開始でき、段間の空転を減らせる。

調整役は、複数の小バッチを更新窓（update window）にまとめて各段へ割り当てる。段内では小バッチごとに局所勾配を蓄積し、更新窓の末尾で最適化器を一度進める。各段は自分の重み、最適化器状態、チェックポイントを所有する。段間で交換する主データは隠れ状態であり、従来の全段逆伝播で必要な戻り勾配を送らない。低帯域の装置間リンクで効果が大きくなる理由は、この通信方向の削減にある。

### 4. 故障時の再実行と端末実装

各段には容量を制限した隠れ状態の緩衝領域を設ける。調整役は確定済みの更新窓を追跡し、障害後には必要な段だけを保存済みの隠れ状態から再実行する。全段を一斉に巻き戻す方式と異なり、すでに確定した他段の更新を保持できる。論文の障害試験は実行過程の一段が停止・再開する設定であり、プロセスやGPU文脈が完全に失われる故障を広く評価したものではない。

携帯端末では、実行環境ExecuTorchの学習用実行形式に中断位置を設ける。第一段階で順伝播を進めて隠れ状態を取り出し、下流端末へ送信する。第二段階で同じ実行を再開して局所逆伝播と端末内のAdamW更新を完了する。この二段階実行により、端末間で逆伝播勾配を遠隔手続き呼び出しする必要がなくなる。

### 5. 収束解析の意味

理論部は、各段の局所損失の最適点を、前段の予測分布から大域目的に沿って進むブレグマン正則化付きの更新として表現する。さらに段ごとのパラメータと勾配を大域の更新へ対応付け、滑らかさや確率的勾配の分散に関する仮定の下で、反復回数Tに対して収束率が `Õ(1/√T)` となることを示す。通常の逆伝播に対して対数多項式因子の差を持つ、という意味であり、有限反復で同一精度になることや、あらゆる局所損失が安定することを保証しない。

## 評価条件と結果

### 実験環境と比較対象

| 項目 | 論文の条件 |
|---|---|
| 学習済みモデル | TinyLlama。変換器の層を三つの連続群へ分割 |
| サーバー側 | NVIDIA L40 GPUを三枚使用し、各段を一枚へ配置 |
| データ | AG Newsの固定一万例。入力系列は128トークンに揃える |
| 低ランク適応 | サーバー側は階数4、拡大係数16 |
| 更新の単位 | 一呼び出し内の物理バッチ数b、小バッチ呼び出し数m、論理バッチB=b×m |
| 比較 | GPipe、1F1B、PipeDream、単一GPU逆伝播の精度参照 |
| 再現性 | 三つの乱数種を使用。図の数値は条件に依存する |

図3では、分類精度と負の対数尤度の推移が比較方式と概ね同程度であることを示す。これをもって全ての言語生成課題で精度差がないと一般化してはいけない。図4〜7では段別メモリ、処理量、通信制約、GPU稼働状態を別々に測定している。

| 指標 | GPipe比 | 1F1B比 | PipeDream比 |
|---|---:|---:|---:|
| 段ごとの平均ピークメモリ削減率 | 47.8% | 14.7% | 14.6% |
| 最もメモリを使う段のピーク削減率 | 55.3% | 26.6% | 26.5% |
| 段平均の活性値メモリ削減率 | 75.4% | 40.8% | 48.8% |
| 標準条件の処理量改善率 | 55.8% | 62.8% | 4.9% |

この表の「26.5%」は最もメモリを使う段のピーク値についてのPipeDream比であり、モデルの重み容量が26.5%減るという意味ではない。標準条件は三段、b=8、m=4である。活性値の保持期間が短くなるため、比較方式より大きなバッチを扱える場合がある。m=4の条件では、メモリ不足となるbはGPipeで10、1F1BとPipeDreamで20、ZeroLockで28だった。実測上の閾値は実行装置と実装に依存する。

図6は、段数と通信リンクの条件を変えた処理量を示す。送信側リンクは無線相当2ms・1000Mbps、携帯回線相当10ms・200Mbps、制約付き30ms・50Mbpsを模擬する。ZeroLockは下流からの勾配通信を必要としないため、低帯域条件で比較上有利になる。一方、全ての条件でPipeDreamに大差を付けるという結果ではない。図7のGPU稼働率診断では、PipeDreamに対する稼働割合が13.7%高いが、これは処理量そのものの増加率と同一ではない。

## 既存研究との差

GPipe、1F1B、PipeDreamはパイプライン内の実行順序や重み版管理を主に改善する。ZeroLockは学習目標そのものを段ごとに分け、上流の更新が下流の勾配を待たない状態を作る。既存の局所損失方式と比べても、低ランク適応を用いる言語モデルの読み出し器、段間の隠れ状態送信、更新窓、端末内の二段階実行、段局所の故障復旧を統合している点が異なる。

論文の比較は主として通常の逆伝播を使う三方式との実機比較である。局所目的関数を用いる全ての先行研究を同じ実装条件で再現して優劣を確定したわけではない。理論上の更新依存の解消と、実機で観測した処理量・メモリ改善は別の根拠として読む必要がある。

## 限界と適用条件

第一に、検証の中心はTinyLlamaとAG Newsである。大規模な数十億〜数千億パラメータ級モデルや、長い対話生成、複雑な推論課題、強化学習型の後段学習で同じ品質・速度が得られるかは未確認である。局所読み出し器が中間層の表現を十分に解釈できない課題では、追加の補助器や異なる損失設計が必要になり得る。

第二に、段内では通常の逆伝播が残り、低ランク適応のパラメータと最適化器状態も保持する。活性値の保持期間は短くなるが、学習状態全体が消えるわけではない。さらに局所読み出し器の計算や予測分布の構築には追加費用がある。比較方式に対する処理量改善は設定次第で小さく、標準条件でのPipeDream比4.9%という値をすべての配置へ外挿できない。

第三に、障害試験は一段の停止・再開を模擬したもので、プロセス消失、端末電源断、長時間の通信分断を広範に評価していない。携帯端末側の温度とメモリの値も短期試作の測定であり、長期運用時の熱制御や端末間の公平性を保証しない。論文は通信削減を示すが、ネットワーク構成や同期費用を変えた実運用上の総費用評価には限界がある。

第四に、収束率は数学的仮定の下での漸近的結果であり、局所目的を任意に選んでも同じ保証が得られるわけではない。中間層の予測を正解ラベルへ直接近づけることが最終層の生成品質にどう影響するかは、別の課題やモデルで検証する必要がある。
