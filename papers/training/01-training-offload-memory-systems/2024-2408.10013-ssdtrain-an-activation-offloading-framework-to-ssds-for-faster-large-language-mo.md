# SSDTrain: An Activation Offloading Framework to SSDs for Faster Large Language Model Training

> 順伝播で作った活性値（activation）をNVMe SSDへ非同期に退避し、逆伝播で必要になる直前に先読みすることで、GPUメモリ使用量と再計算を減らす学習システム。

## 概要

SSDTrainは、LLM学習の**順伝播（forward）で生成され、逆伝播（backward）でもう一度使う中間計算結果＝活性値（activation）**を、GPUメモリへ置き続ける代わりにNVMe SSDへ一時退避するシステムである。

学習では、順伝播で作った活性値を逆伝播まで残しておく必要がある。大規模モデルではこの活性値だけでGPUメモリを大量に消費するため、一般には一部を捨てて逆伝播時に計算し直す**活性値チェックポイント（activation checkpointing）**が使われる。しかし再計算にはGPU時間がかかる。

SSDTrainはここで、

- GPUに保持する
- 捨てて後で再計算する
- SSDへ退避して後で読み戻す

という3つ目の選択肢を加える。

対象はエキスパート重み（expert weight）やKVキャッシュ（KV cache）ではなく、**学習時の活性値**である。目的も「SSDを使って推論を高速化する」ことではなく、活性値再計算を減らしつつGPUメモリを空け、より大きなマイクロバッチ（microbatch）を使えるようにすることにある。

性能上の中心は**GPUダイレクトストレージ（GPUDirect Storage; GDS）**である。これはGPUメモリとNVMe SSDの間でデータを転送するとき、CPU DRAMを中継用バッファとして経由しない仕組みである。論文では複数のIntel Optane SSDをRAID 0で束ね、SSDへの入出力をGPU計算と同時進行させている。

## 手法のあらまし

### 1. 活性値の「使われない時間」を見て退避対象を決める

全活性値を無条件にSSDへ書くわけではない。

SSDTrainは各テンソル（tensor）について、

- データサイズ
- 順伝播で生成されてから逆伝播で再利用されるまでの時間
- どの程度再利用されるか

を追跡する。

ここでいう**寿命（lifetime）**は、「そのテンソルが作られてから、最後に必要とされるまでの期間」を指す。SSDTrainは、**大きくてGPUメモリを長時間占有する一方、しばらく使われない活性値**を優先してSSDへ退避する。

つまり「容量を多く食うのに、すぐには使わないもの」ほどSSDへ移す価値が高い。

### 2. PyTorchの保存・復元経路へフック（hook）を入れる

PyTorchは逆伝播のために必要なテンソルを内部で保存し、後で取り出す経路を持つ。

SSDTrainはこの経路へ**テンソルキャッシュフック（tensor cache hook）**を挿入し、「GPU上に保存する予定だった活性値」を必要に応じてSSD保存へ差し替える。

このためモデル本体の各層を書き換える必要がなく、BERT、GPT、T5のように活性値の使われ方が異なるモデルにも同じ仕組みを適用できる。

### 3. 同じ実データを重複してSSDへ書かない

PyTorchのテンソルには、別オブジェクトに見えても同じ実体データを共有する**ビュー（view）**がある。

たとえば形状だけを変えたテンソルは、新しいデータを複製せず元の記憶領域を参照している場合がある。これらを別物として扱うと、同じデータをSSDへ何度も書いてしまう。

SSDTrainは共有関係を追跡し、**重複排除（deduplication）**によって同じ実データを一度だけ保存する。これによりSSD帯域だけでなく、実際の書き込み量も減らす。

### 4. SSDへの書き込みと先読みをGPU計算の裏で進める

順伝播中、当面使わない活性値を**非同期書き込み（asynchronous write）**でSSDへ送る。

逆伝播で必要になる前には、**先読み（prefetch）**してGPUへ戻しておく。

理想的には、

`現在の層をGPUで計算` と `別の層の活性値をSSDへ書く／SSDから読む`

を同時に進める。

SSD入出力がGPU計算時間の中に隠れれば、データをSSDへ逃がしても学習ステップ時間（step time）はほとんど増えない。

逆にSSDが遅すぎると、逆伝播が必要な活性値の到着を待つことになり、入出力がクリティカルパス（critical path）、つまり処理全体を直接遅らせる経路になる。

### 5. GPUダイレクトストレージ（GPUDirect Storage; GDS）でCPU中継を減らす

GDS利用時は、GPUメモリとNVMe SSDの間を直接転送する。

| 経路 | データの通り道 | 特徴 |
|---|---|---|
| GDS | GPU ↔ NVMe | CPU DRAMの中継コピーを省く |
| CPU経由の退避 | GPU ↔ CPU DRAM ↔ NVMe | 広く使えるが中継コピーが増える |

CPU経由でも機能自体は成立するが、論文の主な性能結果は**GDS＋複数の高速Optane SSDを束ねた構成**に依存する。

したがって、一般的な家庭用NVMe SSDを1台追加すれば同じ性能になる、という結果ではない。

### 6. 「保持・再計算・SSD退避」を使い分ける

SSDTrainは活性値チェックポイントを完全に置き換えるわけではなく、併用できる。

活性値ごとに、

- GPUにそのまま保持する
- 捨てて逆伝播時に再計算する
- SSDへ退避して逆伝播前に読み戻す

という選択肢がある。

計算が安い活性値は再計算し、データ量に対して再計算が高価な活性値はSSDへ置く、といった使い分けができる点が本質である。

## 評価

### まず見るところ

- **結論:** 活性値をNVMeへ退避して逆伝播前に戻すことで、**学習ステップ時間をほぼ増やさず活性値用GPUメモリを大きく減らせる**。
- **メモリ:** 活性値のピーク使用量（peak activation memory）を概ね3〜5割削減し、同じGPU容量でより大きなマイクロバッチを使える。
- **学習速度:** 主な価値は単純な何倍高速化ではなく、**再計算を減らしながら処理量（throughput）を維持すること**。
- **入出力:** GDS＋複数Optane NVMe RAIDの実機評価。一般的なSSD 1台へそのまま外挿できない。
- **注意点:** SSD寿命はモデルによる推定で、長期間の実書き込み試験ではない。

### 活性値メモリ削減

| モデル系 | 活性値ピーク削減の目安 |
|---|---:|
| BERT | 約34〜47% |
| GPT | 約28〜35% |
| T5 | 約28〜35% |

論文全体では最大約47%の削減を報告する。

### 実測したSSD退避量と書き込み帯域

BERT系の代表構成では以下の規模をSSDへ書く。

| Hidden size | Offload量 | PCIe write bandwidth |
|---:|---:|---:|
| 8192 | 10.37 GB | 18.0 GB/s |
| 12288 | 12.85 GB | 13.8 GB/s |
| 16384 | 10.75 GB | 8.76 GB/s |

SSDTrainが成立するには、この入出力をGPU計算と十分に重ねられる必要がある。

### 処理量（throughput）の意味

学習ステップ時間は活性値をGPUに保持する構成とほぼ同等に保ちつつ、より少ないピークメモリで動作する。

同じメモリ予算にそろえた活性値再計算方式との比較では、特定のBERT構成でSSDTrainの処理量が高くなる。

したがって重要なのは、**「SSDを追加して何倍速くなったか」より、「再計算を増やさず、より大きな学習単位を維持できたか」**である。

### マイクロバッチ拡大による二次効果

**マイクロバッチ（microbatch）**は、1回の順伝播・逆伝播でGPUが処理するデータの小分け単位である。

これを大きくできると、

- 最適化更新（optimizer update）など固定的な処理コストをより多くのデータで割れる
- パイプライン並列（pipeline parallelism）でGPUが仕事待ちになる空白時間＝**パイプラインバブル（pipeline bubble）**を減らせる

といった二次効果がある。

BLOOMの試算では、マイクロバッチを増やすことでパイプラインバブルを11.5%以上削減できる条件が示される。

### SSD寿命と制約

| 項目 | 内容 |
|---|---|
| 想定書き込み増幅率（write amplification） | 2.5 |
| SSD寿命 | モデル上2年以上 |
| 実長期寿命試験 | なし |

**書き込み増幅率（write amplification）**は、アプリケーションが論理的に1GB書いたとき、SSD内部では何GB分の物理書き込みが発生するかを表す値である。

さらに、評価はFP16＋SGDを使った構成であり、一般的なAdam＋混合精度（mixed precision）学習と完全に同じメモリ構成ではない。SSD帯域が不足すると、入出力待ちが学習時間へ直接現れる。
