# Cache-Aware Joint Router Adaptation for Memory-Efficient MoE Inference

> MoEのnative routingを保ったまま、次tokenで再利用するexpertと次layerで必要になるexpertのcache優先度をpost-trainingで学習し、GPUに載らないexpert weightの転送回数を減らす。

## 問題
MoEはtokenごとに少数expertしか実行しないが、全expert weightはGPU memoryへ収まらないことがある。その場合、decode中に必要expertをhost/storageから繰り返し転送する必要があり、計算の疎性がそのままserving効率へつながらない。

従来のLRU/LFU系cacheは過去の利用履歴だけを使い、ProMoE等のprefetchは将来expertを予測して先に転送する。本研究はcache管理自体をpost-trainingで学習する問題として扱う。

## 新規性
native MoE routerが実行expertを選ぶTop-K規則は維持し、別の軽量routerは**実行先ではなくcache residencyだけ**を決める。これによりmodelのrouting semanticsとcache管理を分離しつつ、cache lossを通じてbackbone/native routerも含めてjoint adaptationする。

## 手法
### Temporal Router
各MoE layerで現在のhidden stateから、同じlayerで次tokenに使われそうなexpert分布を予測する。現在のnative router分布と合わせてcache保持優先度を作り、現在実行済みexpertを含めたresident setから低優先度expertをevictする。

この方式は現在のaccess後にcacheを更新するだけなので、将来expertを先にloadしない。proactive transferが0である点が重要である。

### Spatio-Temporal Router
Temporal Routerに加え、target layerへ到達する前に因果的に利用可能な直前位置のhidden stateから次のexpert需要を予測する。cache内の低優先度expertを、予測上より重要なnon-resident expertへ置換し、必要ならproactive loadする。

refinement候補数Rを上限にするため、prefetch trafficとhit rateのtrade-offをruntimeで調整できる。

### 学習
main設定ではnative routerを含むbackboneとauxiliary cache routerをjoint post-trainingする。cache coverageをsoft Top-B surrogateで学習しつつlanguage-modeling lossも維持する。auxiliary-only ablationではbackboneを固定してcache routerだけ学習する。

## 評価条件
- Backbone: Qwen3-30B-A3B-Instruct-2507（48 layers、128 routed experts/layer、Top-8）とGPT-OSS-20B（24 layers、32 local experts/layer、Top-4）。
- Task: GSM8K、MATH、CommonsenseQA。
- Qwen3 cache size 20、GPT-OSS cache size 8。Spatio-Temporalのmain refinement budgetはそれぞれ15、6。
- cache挙動はdecode-time routingと同期したtrace-driven simulatorで評価。demand missとproactive insertionをfull expert transfer 1回として数える。
- したがって本論文の主要効率値はwall-clock latencyではなく、cache hitとexpert-weight trafficのalgorithmic評価である。transfer-computation overlapや実機latencyはmodel化していない。

## 主要結果
Temporal Routerはclassical replacement policyよりcache hitを一貫して改善する。Qwen3ではGSM8Kでhit 73.13%、MATHで75.00%、CommonsenseQAで91.61%となり、対応するLRU/LFU/LRFUより高い。

Spatio-Temporal RouterはQwen3の3 taskで、評価したprefetch baseline中もっとも高いload-adjusted efficiencyを報告する。論文要旨では最強prefetch baseline比でadjusted hit rateを1.15〜18.03 point改善し、expert-weight trafficを4.6〜53.3%削減する。GPT-OSSでは改善幅はtask依存である。

auxiliary routerだけを学習するとtask精度を保ちやすい一方cache改善は小さく、backbone/native routingも含めたjoint post-trainingの方がcache効率改善が大きい。

## 限界
主要効率評価はtrace-driven cache simulationであり、実際のPCIe/NVLink/storage bandwidth、transfer overlap、kernel schedulingを含むend-to-end latency評価ではない。joint post-trainingはnative routing分布自体も変えるため、同一routing trace上の純粋なcache policy比較ではない。またSpatio-Temporal Routerはhitを増やすためproactive trafficを使うので、raw hit rateだけでは優劣を判断できない。

## 既存研究との差
LRU/LFU/LRFUは履歴ベース、ProMoE等はruntime predictorとしてfuture expertをprefetchする。本研究はcache priorityをmodel-side post-training objectiveへ組み込み、Temporal Routerではprefetchなしの保持判断、Spatio-Temporal Routerでは因果的なcross-layer情報によるbounded refinementを同一frameworkで扱う。

## 一般的な実装への示唆
expert cacheの最適化では「次に何をloadするか」だけでなく「今あるexpertのうち何を残すか」を学習対象にできる。特にproactive loadを禁止したTemporal Routerは、bandwidthが厳しく誤prefetchのcostが高い環境で使いやすい。一方、実systemへ導入する際は論文のload/token削減がwall-clockへどこまで変換されるかを別途実測する必要がある。
