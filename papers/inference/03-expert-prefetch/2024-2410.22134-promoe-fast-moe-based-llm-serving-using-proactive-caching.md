# ProMoE: Fast MoE-based LLM Serving using Proactive Caching

> 数layer先で使うexpertを予測してCPUからGPUへ先読みし、誤予測転送を小単位で止められるようにし、GPU上にあるexpertから先に計算することで、expert weight待ちを減らすlossless MoE serving方式。

## 概要

ProMoEは、GPUに入り切らないMoE-LLMをCPU DRAMへoffloadしたとき、**必要expertがGPUにないと分かってからweightを読み始めるのでは遅すぎる**という問題を扱う。

将来のroutingを軽量predictorで推定し、必要になりそうなexpertを低優先度でGPUへ先読みする。ただしpredictorはnative routerを置き換えない。実際のgate結果が出た時点で正しいexpertを必ず実行するため、SiDA-MoEとは異なりlosslessである。

ProMoEの特徴は予測精度だけでなく、

- 実際に使う時刻よりどれだけ早く予測できたか
- 誤予測したweight転送をどれだけ早く止められるか
- 正しいexpertを待つ間に、すでにGPU上にあるexpertをどこまで計算できるか

まで含めてprefetchを設計している点にある。

## 手法のあらまし

### 1. Predictor：数layer先のexpert集合を予測する

過去のgate outputや中間情報を使い、数layer先で必要になりそうなexpert集合を予測する。

ここで重要なのは**expert IDを正しく当てるだけでは不十分**という点である。予測が実際のgate直前に出てもCPU→GPU転送が間に合わないため、早い段階で予測できることも重要になる。

### 2. `GOODPRED`：正しさだけでなく「使う時までにどれだけ届いたか」も測る

ProMoEはprefetch品質を`GOODPRED`という指標で評価する。予測したexpertが実際に必要だったかだけでなく、実行時点までにweight転送をどこまで完了できたかも見るため、同じ予測精度でも早く予測して転送時間を稼げる方式を評価できる。

### 3. Expert weightを小分けして転送する

expert全体を1回の大きなtransferとして送ると、誤予測したweightの転送を始めた後に、本当に必要なexpertを急いで送りたくても長時間待つ必要がある。そこでexpert weightを小さなchunkへ分け、優先順位を細かく切り替えられるようにする。

### 4. 正しいroutingが分かったら不要転送を早く止める

現在layerのnative gateが終了すると、本当に必要なexpert集合が確定する。その時点で不要と分かった予測expertのtransferを止め、GPUにない正しいexpertの転送を最優先へ切り替える。

### 5. GPU上にあるexpertから先に実行する

同一layerのexpertをrouter順に待つのではなく、cache済みexpertを先に計算し、その間にGPUにないweightを読み込むことで**GPUがPCIe転送だけを待つ時間**を減らす。

### 6. Losslessである理由

予測はweightを先に置くためだけに使われる。native gateの結果が予測と異なっても正しいexpertをon-demandで読み、元modelと同じexpert計算を実行する。

## 評価

### まず見るところ
- **結論:** predictionだけでなく、誤予測転送を途中で止められることと、expert実行順の変更まで組み合わせてCPU offload待ちをcritical pathから外す。
- **最新版abstractの代表値:** 既存offloading方式比でprefill平均2.20×（最大3.21×）、decode平均2.07×（最大5.02×）。
- **品質:** native expertを必ず実行するためlossless。
- **メモリ/I/O:** CPU DRAM→GPU expert weight transferが対象。SSD/NVMeは扱わない。
- **実装:** Transformersとllama.cppへ統合した公式codeが公開されている。

### 制約

- consumer GPU / edge deployment中心の評価で、大規模distributed continuous batchingを主対象にしていない。
- predictorの精度とlead time、PCIe帯域、cache容量に効果が依存する。
- SSD/NVMe tierは扱わない。
