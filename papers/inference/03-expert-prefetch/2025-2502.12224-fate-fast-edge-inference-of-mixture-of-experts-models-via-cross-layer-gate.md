# Fate: Fast Edge Inference of Mixture-of-Experts Models via Cross-Layer Gate

> 現在layerのrouter入力から次layerで使うexpertを予測し、浅いlayerには多めのexpertをGPUへ置き、深いlayerは先読みで補う。さらに利用頻度の低いexpertだけを強く量子化してedge環境の転送待ちとmemory使用量を減らす。

## 概要

Fateは、別のpredictor networkを追加せず、**隣接layerのrouter入力が似ている**という性質を使って次layer expertを予測するedge向けMoE offload方式である。

浅いlayerはexpert選択が比較的ばらけて予測しにくい一方、深いlayerは一部expertへ選択が偏りやすく予測しやすい、という観察をGPU cacheの配分にも使う。

そのため、

- 現在layerの状態から次layer expertを予測して先読みする
- 浅いlayerには多めのexpertをGPUへ常駐させる
- 最近使ったexpertと長期的によく使うexpertの両方を見てcacheを入れ替える
- 利用頻度の低いexpertだけをINT2へ落とすmixed-bit quantization

を一つの設計として組み合わせる。

prefetch自体はnative routingの補助だが、最速構成ではexpert weightをINT2へ量子化するため、system全体としては完全losslessではない。

## 手法のあらまし

### 1. 現在layerのrouter入力から次layer expertを予測する

layer `i` と `i+1` のrouter入力表現には高いcosine similarityがある。

Fateは現在layerの中間表現を使って、次layerで選ばれそうなexpertを追加predictorなしで推定する。

GPU上で別modelを動かさないため、予測overheadを小さくできる。

### 2. Prefillでは複数tokenの予測expertをまとめる

prefillでは多数tokenが同時に流れるため、tokenごとの予測expertをまとめると、実際に次layerで使われるexpert集合を高い割合で先読みできる。

この複数tokenの利用頻度を転送順にも使い、よく使うexpertをGPUで計算している間に、利用頻度の低いexpertをCPUからGPUへ送る。

### 3. 浅いlayerには多めのexpertをGPUへ置く

浅いlayerではexpert選択が均等に近く、次に使うexpertを予測しにくい。

そこで浅いlayerの一定範囲 `L` までは、できるだけ多くのexpertをGPUへ常駐させて予測ミスによる転送待ちを避ける。

深いlayerはroutingが一部expertへ偏りやすいため、小さいcacheでもprefetchで補える。

### 4. 最近使ったexpertと長期的によく使うexpertを両方残す

単純LRUでは、たまたま直近で一度使われたexpertと、長期間にわたり何度も使われるexpertをうまく区別できない。

FateはARC（Adaptive Replacement Cache）を使い、**最近使われたexpert用の領域と、繰り返し使われるexpert用の領域を分け、その比率をworkloadに合わせて自動調整する**。

### 5. 利用頻度の低いexpertだけをINT2へ落とす

基本はINT4 expertを使い、prefillで利用頻度の低いexpertだけ一部INT2へ落とす。

よく使うexpertをINT2にすると品質影響が大きいため、cold側だけを低bit化する。

Qwen1.5ではINT2比率25%などを例に、品質劣化を約1%以内へ抑える運用点を探す。

### 6. Decodeはprefillと別扱い

decodeでは1 tokenずつしか進まず、prefillのように多数tokenのexpert利用傾向をまとめて判断できない。

そのため全expertをINT4中心で扱い、次layer expert予測の正確さを優先する。

## 評価

### まず見るところ
- **結論:** 隣接layerの表現だけで次layer expertを予測しても、edge PCでは十分大きなprefetch効果が得られる。
- **速度:** prefillでLoad-on-Demand比最大約4.5×、EAP比最大約1.9×。
- **品質:** INT4は小劣化だが、INT2を広げると明確に低下する。最速構成は近似。
- **メモリ:** 予測しにくい浅いlayerへcacheを多く割き、深いlayerは予測prefetchで補う。
- **注意点:** 浅いlayerをどこまで常駐させるかとINT2比率はmodel / workloadごとの調整が必要。

### 実機環境

| 環境 | GPU | CPU | RAM | PCIe |
|---|---|---|---:|---|
| High-end | RTX 3090 24GB | Core i9-9900X | 128GB | Gen3 x16 |
| Low-end | RTX 1080Ti 11GB | Xeon E5-2650 v4 | 64GB | Gen3 x16 |

ModelsはQwen1.5-MoEとDeepSeekMoE。

### Cross-layer similarity / prediction

隣接表現の平均similarityは代表値で約93.05%、88.83%、83.84%。

| Phase | Prediction accuracy |
|---|---:|
| Prefill | **99.6%超** |
| Decode | 約83.99% |

prefillは複数tokenの予測集合を統合できるため高coverageになる。

### Prefill throughput

高性能PCではLoad on Demand比最大約4.5×、EAP比約1.9×。

DeepSeek prompt 512では最大約804 tokens/sを報告する。

低性能PCでもLoad on Demand比約1.8×、EAP比約1.5×。

### Decode

Qwenでは約14 token/s。DeepSeekではLoad on Demand比最大約3.7×、EAP比約2.2×。

全条件ではLoad on Demand比最大約2.3×、EAP比約1.6×程度の改善として整理される。

### Quantization quality

Qwen1.5 MMLUの代表値。

| Precision | Accuracy |
|---|---:|
| Original | 59.6 |
| INT8 | 59.6 |
| INT4 | 59.4 |
| INT2 | 55.1 |

INT4は小差だがINT2は約4.5 point低下するため、cold expertだけを選択的にINT2化する。

### 制約

- PCIe3環境ではI/Oが強い律速。
- 浅いlayerを多く常駐させる境界 `L` はmodel依存。
- INT2比率もquality target依存。
- prediction miss時のon-demand loadは残る。
- SSD/NVMeは主要tierではない。
