# Fate: Fast Edge Inference of Mixture-of-Experts Models via Cross-Layer Gate

> 隣接層のgate入力類似性を使って次層expertを先読みし、shallow-favoring cacheとmixed-bit expert配置でedge MoEを高速化する。

## 概要

Fateは、別のpredictor networkを追加せず、**隣接layerのgate入力が似ている**という性質だけで次層expertを予測するedge向けMoE offload方式である。

浅いlayerはrouting分布が平坦で予測しにくい一方、深いlayerは一部expertへの偏りが強く予測しやすい、という観察をcache placementにも使う。

そのため、

- cross-layer gateによるprefetch
- shallow layerを厚くするcache allocation
- ARC型replacement
- 非人気expertだけをINT2へ落とすmixed-bit quantization

を一つの設計として組み合わせる。

prefetch自体はnative routingの補助だが、最速構成ではexpert weightをINT2へ量子化するため、システム全体としては完全losslessではない。

## 手法のあらまし

### 1. `Cross-Layer Gate`

layer `i` と `i+1` のgate入力表現には高いcosine similarityがある。

Fateは現在layerの中間表現を使って、次layerで選ばれそうなexpertを追加predictorなしで推定する。

GPU上で別モデルを動かさないため、予測overheadを小さくできる。

### 2. Prefillでは複数tokenの予測集合を統合

prefillでは多数tokenが同時に流れるため、tokenごとの予測expertをまとめると、実際に次層で使われるexpert集合を高いcoverageで先読みできる。

このmulti-token popularityを転送順序にも使い、popular expertの計算中にcold expert transferを隠す。

### 3. `Shallow-Favoring Cache`

浅いlayerではexpert選択が均等で予測が難しい。

そこで浅いlayerの一定範囲 `L` まではできるだけ全expertをGPUへ置き、予測に頼らない。

深いlayerはrouting偏りが強いため、小さいcacheでもprefetchで補える。

### 4. `ARC` replacement

単純LRUでは一時的なburstと長期人気を区別できない。

FateはARCの考え方を使い、recent集合とfrequent集合を両方追跡し、workloadに応じてcache比率を適応させる。

### 5. Mixed-bit expert quantization

基本はINT4 expertを使い、prefillで人気の低いexpertだけ一部INT2へ落とす。

popular expertをINT2にすると品質影響が大きいため、cold側だけを低bit化する。

Qwen1.5ではINT2比率25%などを例に、品質劣化を約1%以内へ抑える運用点を探す。

### 6. Decodeはprefillと別扱い

decodeでは1 tokenずつしか進まず、expert popularityをbatch内で集約できない。

そのため全expertをINT4中心で扱い、cross-layer predictionの正確さを優先する。

## 評価

### まず見るところ
- **結論:** 隣接layerの表現だけで次層expertを予測しても、edge PCでは十分大きなprefetch効果が得られる。
- **速度:** prefillでLoad-on-Demand比最大約4.5×、EAP比最大約1.9×。
- **品質:** INT4は小劣化だが、INT2を広げると明確に低下する。最速構成は近似。
- **メモリ:** shallow layerを厚くcacheし、deep layerは予測prefetchで補う。
- **注意点:** layer境界 `L` とINT2比率はmodel / workloadごとの調整が必要。

### 実機環境

| 環境 | GPU | CPU | RAM | PCIe |
|---|---|---|---:|---|
| High-end | RTX 3090 24GB | Core i9-9900X | 128GB | Gen3 x16 |
| Low-end | RTX 1080Ti 11GB | Xeon E5-2650 v4 | 64GB | Gen3 x16 |

ModelsはQwen1.5-MoEとDeepSeekMoE。

### Cross-layer similarity / prediction

隣接表現の平均similarityは代表値で約93.05%、88.83%、83.84%。

| Phase | Prediction accuracy |
|---|---:|
| Prefill | **99.6%超** |
| Decode | 約83.99% |

prefillは複数tokenの予測集合を統合できるため高coverageになる。

### Prefill throughput

高性能PCではLoad on Demand比最大約4.5×、EAP比約1.9×。

DeepSeek prompt 512では最大約804 tokens/sを報告する。

低性能PCでもLoad on Demand比約1.8×、EAP比約1.5×。

### Decode

Qwenでは約14 token/s。DeepSeekではLoad on Demand比最大約3.7×、EAP比約2.2×。

全条件ではLoad on Demand比最大約2.3×、EAP比約1.6×程度の改善として整理される。

### Quantization quality

Qwen1.5 MMLUの代表値。

| Precision | Accuracy |
|---|---:|
| Original | 59.6 |
| INT8 | 59.6 |
| INT4 | 59.4 |
| INT2 | 55.1 |

INT4は小差だがINT2は約4.5 point低下するため、cold expertだけを選択的にINT2化する。

### 制約

- PCIe3環境ではI/Oが強い律速。
- shallow boundary `L` はmodel依存。
- INT2比率もquality target依存。
- prediction miss時のon-demand loadは残る。
- SSD/NVMeは主要tierではない。
