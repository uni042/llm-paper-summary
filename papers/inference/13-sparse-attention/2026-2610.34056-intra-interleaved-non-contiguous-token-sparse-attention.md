# INTRA: Interleaved Non-contiguous Token spaRse Attention

> 遠距離通信を中継として設計する静的スパースアテンション。散布と収集の相補的なグループを交互に重ね、非連続トークンを密に詰め直すカーネルで、検索品質を保ちながら注意計算を大きく削る。

## 概要

Transformerのアテンションは系列長の2乗で費用が増えるため、長文脈や高解像度画像の生成では支配的なボトルネックになる。例えば画像生成モデルはA100 1基で2048画素級の画像1枚にほぼ1分を要する。スパースアテンションは注意先を絞ってこの費用を減らすが、2つの壁がある。第1に、入力に依らない静的な接続では、どの遠距離ペアが重要になるか分からないまま通信の機会を配らなければならない。第2に、細かいマスクで計算量だけを減らしても、GPUの計算ブロックが部分的にしか埋まらず、使わないスコアまで計算してから捨てる実装では実測の高速化が理論上の削減に届かない。

本論文のINTRAは、スパース化を通信の問題として設計し直す。トークン列を画像パッチや短いテキスト区間のような局所近傍へ分け、近傍内の混合は局所アテンションに任せ、近傍同士の通信を中継で確保する。具体的には、各近傍から同じ位置の代表を1つずつ集めた散布グループと、散布で分かれた経路を再びつなぐ収集グループを、層ごとに交互に使う。すべての散布グループがすべての収集グループと交わる配置にすれば、任意の出発点から任意の到達点へ2層で中継路が存在する。実行側では、計算クエリ集合と呼ぶ実行単位の制約を満たすよう索引関数を構造化し、非連続なキーと値を実行時に集めて密なタイルへ詰め直す専用カーネルで計算する。代表結果として、A100上で画像生成は2048画素級で66.78秒から43.72秒へ1.53倍速くなり、画質指標FIDは15.67で、比較した静的スパース法の32.46を大きく上回った。言語側では、長文脈検索で密アテンションの満点に対して平均0.923を保ち、アテンション単体の計時ではMoBAより3.6倍から8.4倍、密度を抑えたNSAより7.3倍から10.4倍速かった。ただし要約系の課題では品質が比較対象を下回る場面もあり、万能ではない。

## 問題設定

スパース化の難しさは、削減と到達性と実行形状の3つが同時に絡む点にある。1層あたり各クエリが注意できる相手の数が系列長よりずっと少ない場合、その層で直接つながるペアは全体のごく一部でしかない。重要な遠距離ペアを入力に応じて選ぶ動的スパース法はこの問題を回避できるが、実行時にパターンを選ぶ費用と不規則なメモリアクセスを抱える。静的な方法は実行が単純な反面、未知の需要に対して通信機会を偏りなく配る設計が要る。

実行形状の問題も独立ではない。局所ウィンドウ型の先行方式は連続した範囲を扱うため実装しやすいが、ブロック境界で部分的にしか使われない計算ブロックが生じる。マスクで後から捨てる方式では、計算したスコアのうち捨てる分だけ実効効率が落ちる。したがって設計空間は、数学的に良い接続であることと、クエリのグループ単位で構造化された索引付けができ、ブロックサイズに合うことの両方で制約される。本論文はこの実行側の制約を計算クエリ集合として明示し、その内側で通信設計を行う。近傍内は局所混合で足りるという前提を置き、解くべき問題を近傍間の通信に絞る点が、問題設定の要点である。

## 手法のあらまし

全体の流れは、局所混合、均一で非連続な中継、釣り合いの取れた再接続、の3段である。まずトークンを等しい大きさの局所近傍へ分ける。散布の層では、近傍内の位置をそろえて代表を集め、各グループが全近傍を1つずつ含むようにする。これにより各グループは系列全体の低解像度な眺めになる。次の収集の層では、散布のグループ同士がなるべく均等に交わるようグループを作り直し、散布だけでは分断されていた経路同士を接続する。画像生成では散布と、16×16近傍を使う収集を交互に重ねる。言語の検索では構成が異なり、32層中4層だけをブロック単位のスパースアテンションとし、残りはスライディングウィンドウとシンク付きで処理し、スパース化はプリフィルだけに適用してデコードは密のままにする。カーネルは、クエリ64トークンのブロックごとに索引関数で大域位置を計算し、選ばれたキーと値を共有メモリ上の密なタイルへ詰めてから通常のオンラインソフトマックス計算を行い、結果を元の位置へ書き戻す。

## 手法

### 1. 計算クエリ集合 — 実行できるスパースさの制約を先に固定する

この機構が観測するのは、クエリトークンのグループと、それに対応するキーと値の集合である。保持する状態は、局所位置から大域位置への構造化された対応付けであり、任意のマスク行列ではない。要件は3つある。全クエリがいずれかのグループに属すること。索引が構造化関数で一様に計算できること。グループの大きさがクエリブロックサイズ64で割り切れること。この制約の内側では、グループ内のクエリをまとめて処理でき、非連続なキーと値を連続に詰め直せるため、スレッドグループ間の同期なしに計算できる。

この制約を先に固定する理由は、設計した接続がそのまま実行速度に結び付くことを保証するためである。接続の良し悪しだけを最適化すると、索引付けが不規則で実測が遅いパターンに行き着きやすい。逆に実行形状だけに合わせると、局所ウィンドウのように到達性の弱い接続になる。失敗条件は、系列長がブロックで割り切れない末尾の部分ブロックや、因果マスクで許される範囲が狭まる位置であり、論文は部分ブロックを例外として扱い、因果条件の下では到達性が前方トークンに限られることを限界として認めている。

### 2. 散布と収集 — 2層の中継で全体到達性を作る

散布が入力として受け取るのは、近傍の番号と近傍内の位置で表されたトークンである。処理は、近傍内の位置が同じトークンを全近傍から集めて1グループにすることであり、出力は近傍の数だけの要素を持つグループが位置の数だけ並んだ集合である。各グループが全近傍を漏れなく含むため、どの近傍の情報もすべての散布グループへ届く。グループあたりの計算は近傍数の2乗に比例し、全体では密な計算の近傍内要素数分の1に圧縮される。

散布だけでは不十分である。位置の違うグループ同士は互いに分断されており、出発側の代表と到達側の代表が同じ位置とは限らないため、経路がつながらない組み合わせが残る。収集はこの分断を解く。散布グループと収集グループの重なりがゼロの組があると、その経路には中継の証人がいなくなる。そこで重なりの最小値を最大化する釣り合い型の構成を使い、近傍数と位置数の条件を満たせば、すべての散布グループがすべての収集グループと交わり、2層で普遍的な到達性が得られることを分割モデルの下で示している。論文はこの2つの目的、つまり散布における近傍ペア被覆の最小値最大化と、収集における重なり最小値の最大化を、付録で定理として裏付けている。

減るボトルネックは、遠距離通信のために必要な層数と注意ペア数である。直接の全ペア接続を持たなくても、中継を介して情報が届くため、静的予算の範囲で大域混合が成立する。追加費用は中継の段数であり、情報は最低2層を経由するため、1層で直接届く場合より伝播が遅れる。また前提として、近傍内の局所混合が十分に機能することが必要で、近傍の切り方が内容と合わない場合は中継の代表自体が情報を落とす。画像では収集に16×16の近傍を使う変種を用い、言語の検索では256トークンの連続ブロックを1つおきに選ぶブロック単位の変種を使うなど、具体形はモダリティごとに異なる。

### 3. 専用カーネル — 非連続な相手を密に詰めて計算する

カーネルが観測するのは、クエリブロックと索引関数が返すキーと値の大域位置である。処理の順序は、実行時に索引を計算し、選ばれたトークンを読み込み、共有メモリ上の密なタイルへ詰め、オンラインソフトマックス型の注意計算を行い、クエリの対応付けに従って結果を書き戻す、という流れである。保持する状態はタイル内の詰め替え済みデータだけであり、マスク行列を事前に作って保持することはしない。マスクの適用は詰めたタイルの内部で行い、全量と因果の両方に対応する。

この実装が効く理由は、使わないスコアを計算して捨てる無駄が消えることにある。部分的にしか使われないブロックをそのまま計算する方式と違い、選ばれたトークンだけが密な計算対象になる。追加費用は、実行時の索引計算と非連続読み込みであり、付録の分析でもこのオーバーヘッドが認められている。変更されない部分、例えばフィードフォワード層やデコード側の密アテンションが全体の時間を占めるようになると、エンドツーエンドの利得はアテンション単体の利得より小さくなる。実際、画像のエンドツーエンド高速化1.53倍に対して、アテンション単体では16Kで7.67倍という差があり、この読み分けが重要である。

### 4. 既存モデルへの適応 — 静的パターンは学習し直して使う

INTRAは学習不要の接続ではなく、既存モデルをスパースパターンへ適応させて使う。画像では自己生成データによる低ランク適応と自己蒸留を組み合わせ、言語ではランク16の低ランク適応を課題ごとに用いる。適応が担うのは、密な接続を前提に学習された重みが、届く情報の経路が変わっても品質を保てるよう調整することである。言語の検索実験では、密、MoBA、NSA、INTRAが同じ適応予算と教師強制の評価手順を共有しており、比較は適応込みの実用条件で行われている。失敗条件として、適応なしのゼロショット性能や自由生成での品質は測られておらず、適応データと無関係な分布では結果が変わりうる。画像の微調整には43GPU時間、言語の適合実験には1回あたり約8GPU時間がかかっており、導入費用として無視はできない。

## 評価

### まず見るところ

- **結論:** 静的スパースでも中継設計と専用カーネルを組にすれば、画像生成で画質と速度を同時に改善でき、言語の長文脈検索でも密に近い精度を保てる。ただし要約系の言語課題では品質が比較対象に届かず、利得は課題依存である。
- **速度・効率:** アテンション単体の大きな倍率と、エンドツーエンドの控えめな倍率を分けて読む必要がある。後者は画像で1.53倍、動画で1.43倍である。
- **品質:** 検索では強いが、要約系では弱い。画像では比較した静的スパース設定より良いが、密との同等性は主張されていない。
- **評価の強さ／注意点:** すべてA100での実機測定だが、品質指標に信頼区間はなく、計時と比較の構成が実験ごとに異なる。言語の計時比較はアテンション単体であり、モデル全体のプリフィルではない。

## 既存研究との差

静的スパースの系譜では、局所とストライドの因数分解を重ねる方式や、ブロック注意と格子注意を組み合わせる視覚向け方式が、散布と収集に近い前例である。局所ウィンドウ系の方式は連続範囲に寄せており、大域通信は別機構に頼る。本論文の差は、到達性を中継の被覆と重なりの観点で定式化し、その設計を実行制約の内側に置いたこと、そして非連続トークンを密に詰め直すカーネルまで含めて画像と言語で実測したことにある。動的スパースとの差は、実行時の選択を捨てる代わりに適応学習で品質を回復させるという分担であり、どちらが優れるかは課題で変わることを結果自体が示している。

## 限界・実装状況

論文が挙げる限界は多い。分割モデルの分析は被覆と重なりを最適化するものであり、注意の近似誤差や下流品質そのものではない。因果マスクの下では到達性は前方に限られる。他の因数分解パターンやより大きいモデルとの比較は今後の課題とされている。品質は課題依存であり、要約系では比較対象に負け、画像でも密との同等性は示されていない。動画の品質評価は49フレーム条件のみで、一部の指標の低下や共有されるゼロ値の理由は未解明である。実行面では、索引計算と非連続読み込みのオーバーヘッドがあり、再整形がスケジューリングや占有率を変えるため、その分離測定はできていない。

実装は著者らがGitHubで公開している。上流の推論フレームワークへ統合済みかどうかは論文中に示されておらず、専用カーネルを伴う研究実装として読むのが正確である。推論システムへの含意としては、プリフィル側の長文脈処理や拡散生成のような注意支配のワークロードで効く方式であり、デコード側は言語実験でも密のままである点に注意が要る。

## 一般的な実装上の含意

スパース化を検討するときは、削減率の前に、情報が何ホップで全体へ届くかと、その接続がGPUの実行単位にそのまま載るかを先に確認すべきである。本論文の除去実験が示すように、局所容量を増やすことと大域到達性を確保することは別物であり、検索のような課題では後者が品質を決める。また、アテンション単体の倍率とエンドツーエンドの倍率の差を常に併記しないと、導入効果を見誤る。静的パターンは実行が単純な代わりに適応学習が前提になるため、導入判断には微調整費用まで含める必要がある。
