# From Rigid to 動的: エントロピー-Guided Adaptive Inference for Long-Context LLMs

## 概要

長い入力を処理するLLMでは、入力文脈全体の注意機構計算がプリフィル 遅延を押し上げ、生成中は過去トークンのキー/値 (KV) が蓄積してGPU メモリを圧迫する。プリフィルを疎にする方式は位置ごとに一定のパターンを使ったり、全ヘッドで同じ基準・予算を使ったりすることが多く、ヘッドの役割が入力文脈に応じて変わる点を十分に利用しない。KV 追い出しもプリフィル時の注意機構を手掛かりにデコード前に重要トークンを決めると、生成後に変化する注意機構を捉え損なう可能性がある。

EntropyInferは、学習や事前 ヘッド 特性計測を加えず、現在の入力に対する注意機構 エントロピーをプリフィルの計算量調整に使う。論文はエントロピーが常にほぼ0のヘッドをRigid、区間やクエリに応じて値が変わるヘッドを動的と呼ぶ。同じヘッドが異なる文脈では別の状態を示し得るため、ヘッド分類を固定せず、各入力のプリフィル中に行う。

プリフィルでは、まず区間ごとのクエリ/キー特徴量の最大値・最小値から縮約した観測注意機構行列を近似計算する。その行方向のエントロピーを使い、Rigid ヘッドには各区間で同じ基礎予算を割り当てる。動的 ヘッドでは隣り合う区間間のエントロピー変化に応じてブロック数を増減し、変化が大きい箇所へ多くの注意機構計算を使う。デコードではプリフィルの終了時点でKVを確定破棄せず、少数の出力トークンを生成してからそれらのクエリを含む観測窓で元のKV トークンをスコアし、上位予算分だけを保持する。

Llama-3.1-8B-InstructとQwen2.5-7B-Instructを対象としたLongBench 16課題とInfiniteBench 8課題の表では、EntropyInferは比較対象のSnapKV、AdaKV、CritiPrefillを上回る平均値を報告する一方、full-注意機構平均よりは低い。単一NVIDIA H100上のLlamaで4Kから140Kまでの入力を与え、100 トークンの要約を生成する遅延評価では最大2.39倍のエンドツーエンド高速化を報告する。効果は長文脈で大きく、短文脈では観測注意機構計算とエントロピー計測の追加費用が利得を抑える。グラフ中の各系列長の遅延は本文に数表として掲載されていないため、最大値以外の値は推定していない。

## 問題設定と着想

プリフィルでは系列長に伴って注意機構行列が二次的に大きくなる。固定の局所・大域パターン、層単位で共通の疎性 しきい値、または区間内でヘッド共通のtop-k ブロック予算は、それぞれ文脈による位置変化、ヘッド間の違い、ヘッドと区間双方の違いの一部を無視する。デコードではKV キャッシュ トークンをプリフィル時の注意機構だけから選ぶと、生成開始後に変わる注意先に必要なKVが残らない場合がある。さらに、事前 calibration setからヘッド役割を決める方法は、今回の入力固有の変化を事前分類に反映できない。

著者らはLlama-3.1-8B-InstructとQwen2.5-7B-Instructでヘッドごとのエントロピーを観察し、ほぼ0の状態を保つヘッドと、クエリや区間をまたいで変化するヘッドを見いだした。Llama-3.1-8B-Instructの異なる文脈に対する可視化ではRigid/動的 ヘッドの分布自体が変わり、同じヘッドを固定分類するより入力ごとに測るべきだと論じる。

## 手法

### エントロピー-guided 疎 プリフィル

全行のエントロピーを正確に計算するには密な注意機構計算に戻るため、クエリ/キーを区間内の次元別最大値・最小値で代表させ、これらの組み合わせから小さな観測注意機構行列を作る。行ごとの注意機構 エントロピーを各区間のヘッド状態の代理指標として用いる。最大エントロピーがしきい値を下回るRigid ヘッドでは区間ごとに固定予算を配る。しきい値を超える動的 ヘッドでは初区間を基準にし、連続区間間のエントロピーの相対変化に応じて予算を上下させる。予算は基礎値のおよそ1〜3倍に抑える設計と記述される。しきい値は1e-5、係数は0.5、変化判定の割合は0.4である。

各区間について割り当てられた予算に対応するブロックを選び、本計算では選択ブロックに対する注意機構のみを行う。選択計算だけではなく、観測行列の構築とtop-k選択にも費用がかかる。Appendix Aの解析は観測計算・ブロック選択・疎注意機構を合わせた上界を示し、区間 sizeやブロック size、固定予算を小さくできる長文脈で密注意機構に対する利益が現れると説明する。

### デコード後に選ぶlatent KV キャッシュ

既存の追い出し方式がプリフィル直後にKVを削るのに対し、EntropyInferは圧縮を数個の出力トークン生成後へ遅らせる。出力トークン由来のクエリも観測窓へ含め、窓 クエリと全キーの相互作用を集約したimportance スコアから上位のKV トークンを選び、対応するキー/値を保持する。

こうしてプリフィルとデコードの注意機構 パターンずれを緩和する狙いである。Appendix Bのアルゴリズム 4は窓 indexを抽出し、スコアを集約し、TopK後に選択KVを返す手順を記載する。

## 既存研究との差

SnapKVやAdaKVはプリフィル後の注意信号からKVを選び、CritiPrefillは入力処理の区間内で重要なblockを選ぶ。EntropyInferは、プリフィルでヘッド・区間単位の変動を観測して疎化予算を配ることと、デコード後の出力トークンでKV選択を遅延更新することを組み合わせる点で、両段階をまたぐ。

リポジトリの [KVキャッシュ最適化・圧縮](https://github.com/uni042/llm-paper-summary/tree/main/papers/inference/07-kv-cache-optimization-compression) に分類されるトークン／ヘッド単位のKV削減・保持予算研究と関連するが、本方式はプリフィル注意機構の区間別疎化も含むため、KV保持量だけを操作する方法とは作用点が異なる。

## 評価

### 条件

- 有効性: LongBench 16課題とInfiniteBench 8課題。Llama-3.1-8B-Instruct、Qwen2.5-7B-Instruct。
- 遅延: Needle-in-a-Haystack 指示文を文脈要約向けに変更し、Llama-3.1-8B-Instructへ4K〜140K トークンの入力を与え、100 出力 トークンで停止してエンドツーエンド 遅延を測定。
- 追加モデル系列: openPangu-Embedded-1B-v1.1、openPangu-Embedded-7B-v1.1。LongBenchおよびLoCoMoの結果も掲載。
- ハードウェア: 単一NVIDIA H100 80GB、192GB CPU メモリ、8 CPU cores。
- 比較: Base/full 注意機構、SnapKV、AdaKV、CritiPrefill。論文既定値はEntropyInferの疎 プリフィル base 予算 2048 トークン、デコード キャッシュ 予算 1024 トークン。SnapKV/AdaKVのKV 予算は1024 トークン、CritiPrefillの区間予算は2048 トークン。
- 指標: LongBenchは課題ごとにF1、ROUGE-L、正解率、編集類似度。InfiniteBenchはF1、ROUGE-L-Sum、正解率、exact match。加えてエンドツーエンド 遅延と高速化率。

### 感度・除去試験

区間 sizeを大きくするとGovReportやMultiNewsの要約課題には有利で、検索やQAは小さい区間 sizeを好む傾向がある。ブロック sizeは概ね結果に鈍感だが、一部条件で大きい方がよい。プリフィル base 予算は有効性に大きく影響しにくく、デコード キャッシュ 予算を増やすと一部課題で精度が改善する代わりに計算とメモリ 費用が増える。

LlamaのLongBench 除去試験は疎 プリフィルのみ、latent デコードのみ、両方を有効にする設定を比べる。両要素は品質への影響が小さいと著者らは述べ、エンドツーエンド速度では併用が最も有効とする。一方、疎プリフィルのみの構成はヘッド別予算処理によりCritiPrefill単独よりわずかに遅い。デコード時のlatent圧縮がこの差を相殺するという説明である。

## 限界

- 短い文脈では観測注意機構行列の計算とエントロピー 特性計測の追加追加費用により高速化が限られると著者らは明記する。
- LongBenchとInfiniteBenchの平均はfull-注意機構 Baseより低く、課題ごとの増減にも幅がある。「品質を損なわない」と一般化せず、本文の報告では小さいが非ゼロの品質差がある。
- エンドツーエンド 遅延の主評価はLlama-3.1-8B-Instruct、単一H100、4K〜140K文脈、100-トークン出力という条件に限られる。最大2.39倍以外の各長さの時間は本文に表で示されない。
- 論文は計算量を上界として解析するが、追加するエントロピー観測・TopK選択・デコード KV再順位付けの費用はハードウェア条件に依存する。別GPUやオンラインserving 負荷での値は示されていない。
- アルゴリズム 3では予算を基礎値から3倍までの範囲へclipすると説明する一方、HTML変換された式のmax/min順序はその説明と矛盾して見える。ここでは実装上の式を推測で補わず、本文の記述を要約した。
