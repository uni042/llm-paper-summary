# Tactic: Adaptive Sparse Attention with Clustering and Distribution Fitting for Long-Context LLMs

> 累積注意質量を目標にKV数を動的決定し、K-meansと分布当てはめで選択費用を抑えて注意を最大7.29倍高速化するTactic。

## 概要

長文脈LLMのデコードでは、各生成トークンごとに長大なKVキャッシュを読むため、注意計算がメモリ帯域を大量に消費する。疎注意は重要そうなKVだけを読むことでこの負担を減らすが、Questのようにヘッドごとに固定数を選ぶ方式や、PyramidKV/AdaKVのように固定総予算を静的配分する方式では、**注意分布の疎性がヘッド・層・クエリ・文脈ごとに変わる**ことを十分扱えない。

Tacticは「各ヘッドから何個残すか」を先に決めず、選択したトークンの**累積注意スコアが目標値Pに達するまで**KVを残す。注意が数個へ集中しているヘッドは少数のKVで止まり、広く分散しているヘッドは多く読む。累積注意質量 `p(I)` を直接制御することで、固定トークン数より注意近似誤差を一定にしやすくする。

ただし正確な注意スコアを全KVについて計算・整列すれば、それ自体がフル注意に近い費用になる。そこでTacticは、プリフィル時のK-meansクラスタリング、クラスタ中心による粗い順位付け、注意スコアの長尾分布を `y=a/x+b` で近似する軽量推定を組み合わせる。実験では既存疎注意より精度を保ちやすく、デコード注意を最大7.29倍、プリフィルやクラスタリングを含むエンドツーエンドを最大1.58倍高速化した。

## 問題設定

固定KV予算が不安定な理由は、同じモデル内でも注意の集中度が一定ではないからである。あるヘッドではごく少数のトークンが注意の大半を占める一方、検索的なヘッドでは広い範囲のトークンへ注意が分散する。層間でも差があり、同じヘッドであっても現在のQueryによって必要KV数が変わる。

論文は疎注意の出力とフル注意の出力との差を注意距離 `ε(I)` として整理し、選択集合Iの累積注意スコアを `p(I)` とすると、`ε(I) ≤ 2(1-p(I)) max_i ||v_i||` という上界を示す。したがって「トークン数Kを固定する」より「累積注意スコアPを固定する」方が、ヘッドごとの疎性変動に自動で適応しながら近似誤差を制御できる。

しかし、最小のIを正確に求めるには全トークンを注意スコア順に並べ、正規化に必要な全体和も知る必要がある。Tacticのシステム上の課題は、この理想的な選択をフル注意より十分安く近似することにある。

## 手法

### 1. プリフィル時にKeyベクトルをK-meansでまとめる

Tacticは各層・各KVヘッドについて、プリフィル中にKeyベクトルをK-meansクラスタリングする。位置が近いトークンを同じブロックへまとめるのではなく、**Key空間で近いトークン**をまとめるのがポイントである。論文では平均クラスタサイズ32を基本とし、最大10反復までK-meansを回す。

位置順のグループ化を避けるのは、隣接トークンのKeyベクトルが必ずしも近くないからである。一方、離れた位置のトークンでもKey空間では似ることがある。デコード時には各クラスタ内の全トークンを見る前に、クラスタ中心だけを使って「このQueryに対して重要そうなクラスタ」を順位付けできる。

### 2. Queryとクラスタ中心の内積でKVを粗く並べる

新しいQueryが来ると、TacticはQueryと各クラスタ中心との内積を計算し、クラスタを重要度順に並べる。位置ではなくQuery-Keyの関係そのものに近い指標で並べるため、固定ページ順より注意スコア順の近似として使いやすい。

クラスタリングによる順位付けだけなら、フル注意に対する追加費用は平均クラスタサイズに反比例し、論文の設定では実用上2%未満とされる。ただしクラスタ中心の注意値はクラスタ内トークンの平均注意値と一致しないため、これだけでは「累積注意スコアがPへ達したか」を正確に判断できない。

### 3. 長尾分布を `y=a/x+b` で近似して必要トークン数を求める

クラスタ順に並べた後の注意スコアは、先頭に少数の大値があり、その後なだらかに減衰する長尾形状を持つ。Tacticは、この分布を `y=a/x+b` で近似する。例えば並びの10%付近と60%付近の小区間をサンプルし、その平均値からaとbを求め、残りの注意スコアを推定する。

先頭1〜2%は外れ値が多く近似誤差の影響も大きいため、そこだけはQuery-Key内積の指数値を直接計算する。これにより、全KVの注意スコアを正確に計算せずに累積和を推定し、「累積注意質量Pへ到達するのに何トークン必要か」をヘッドごと・クエリごとに決める。実運用ではクラスタ中心と少量サンプルを読むだけでよく、論文ではサンプル量をKVキャッシュの約2.5%程度としている。

### 4. GQAではQueryヘッドごとの選択集合を和集合化する

Grouped Query Attention（GQA）では複数のQueryヘッドが同じKVヘッドを共有する。各Queryヘッドが別々のKV集合を選ぶと、同じKVを何度もロードしてしまう。そこでTacticは同一グループ内のQueryヘッドが選んだKV集合の**和集合**を一度に読み込む。

全Queryヘッドを同時に満たす最小集合を厳密に探す問題は難しいため、和集合という単純な近似を採る。構成要素除去では、この和集合化だけで注意処理を最大1.65倍高速化しており、選択アルゴリズムだけでなくメモリロードの共有が重要である。

### 5. 選択KVをFlashInferで処理し、ヘッド間の不均衡を分解する

最終的な注意計算はFlashInferを使う。累積注意質量を固定するとヘッドごとの選択トークン数が異なり、処理量が不均衡になる。Tacticは各KVヘッドと対応するQueryヘッド群をサブリクエストとして扱い、ヘッド間の不均衡を「長さの異なる複数リクエスト」というFlashInferが扱いやすい形へ変換する。

新しく生成されたトークンについてはフル注意を行い、クラスタは固定間隔で更新する。論文では例として2048デコードステップごとの再クラスタリングを挙げている。

## 評価

### 代表的な評価条件

| 項目 | 設定 |
|---|---|
| モデル | Llama-3.1-8B-Instruct、MegaBeam-Mistral-7B-512k |
| 精度評価 | PG19、LongBench 6タスク、RULER |
| LongBench | HotpotQA、TriviaQA、MultiFieldQA、Qasper、NarrativeQA、Musique |
| RULER文脈長 | 16K / 32K / 64K / 96K |
| 比較対象 | Quest、PyramidKV、Ada-SnapKV、Full Attention |
| 効率評価GPU | NVIDIA RTX 6000 Ada |
| ソフトウェア | CUDA 12.4、FlashInfer |
| K-means | 最大10反復 |

### 累積注意質量を使う効果

Llama-3.1-8B-InstructのLongBenchでは、累積注意閾値90%のTacticがFull Attentionへ近い値を保ちながら、同じ平均トークン数を予算として与えたPyramidKV、AdaKV、Questを多くのタスクで上回った。例えばMultiFieldQAではFull 55.05、Tactic 54.35に対し、PyramidKV 48.15、AdaKV 49.15、Quest 52.42だった。

RULERでもLlama-3.1-8B-Instructの平均はFull Attention 86.8に対し、TacticはP=75%で84.7、P=90%で84.6だった。同じ予算条件のPyramidKV/Ada-SnapKVは約63〜73、Questは約69〜80であり、固定予算より累積注意質量で必要KV数を変えることが精度維持に効いている。

### 必要トークン数は実際に大きく変動する

Tacticの選択数は、同じPでもタスクと文脈長によって大幅に変わる。Llama-3.1-8B-Instruct、P=75%のRULERでは、16K文脈で100〜500程度のケースが多い一方、96Kでは1000〜3000超へ増えるタスクがある。MegaBeam-Mistralではさらに多く必要になるケースがある。

これは固定トークン予算が不安定だという問題設定を、そのまま内部挙動で確認する結果である。Tacticは同じ「精度側の目標P」を維持しながら、必要なKV量をモデル・クエリ・長さに応じて変える。

### 速度とオーバーヘッド

| 観点 | 結果 |
|---|---:|
| デコード注意 | 最大7.29倍高速化 |
| エンドツーエンド推論 | 最大1.58倍高速化 |
| GQA和集合化 | 最大1.65倍の注意高速化 |
| 32Kでのクラスタリング | 0.16秒、プリフィル5.66秒 |
| 64Kでのクラスタリング | 0.62秒、プリフィル15.80秒 |
| 128Kでのクラスタリング | 2.74秒、プリフィル49.53秒 |

クラスタリング時間は系列長とともに増え、距離計算が支配的だが、評価した長さではプリフィル時間の6%未満に収まった。デコードではクラスタ整列と分布当てはめの追加費用があるものの、KV読出し削減の方が大きく、最大7.29倍の注意高速化につながる。プリフィルとクラスタ作成まで含めると最大1.58倍なので、カーネル倍率と全体倍率は区別すべきである。

## 既存研究との差

Questはページや固定トークン数に基づき候補を絞り、PyramidKV/AdaKV系は固定総予算を層・ヘッドへ配分する。Tacticは予算そのものを入力にせず、**フル注意のうち何割の注意質量を保持するか**を入力にする。その結果、疎なヘッドには少なく、分散したヘッドには多くKVを割り当てる。

また、適応的な予算を決めるために毎回フル注意を計算するのではなく、Key空間クラスタ、クラスタ中心、少量サンプルによる分布近似を使う。したがって新規性は「動的予算」だけでなく、累積注意質量という品質目標を実行時に低コストで近似する一連の実装にある。

## 限界

Tacticは近似的な順位付けと分布当てはめを使うため、指定したPを毎回厳密に満たすわけではない。論文のPG19評価でも閾値に到達する成功率は設定により80%台〜90%台であり、推定値にはずれが残る。

K-meansはプリフィル時の追加処理で、系列長が長くなるほど費用が増える。さらに、選択KV数が多いヘッド・タスクでは疎化率が下がるため、固定した高速化倍率を期待できない。最大7.29倍は注意カーネル、最大1.58倍はエンドツーエンドであり、両者を同じ「推論高速化」として扱わないことも重要である。

## まとめ

Tacticは「何トークン残すか」を固定せず、「フル注意の注意質量をどこまで保持するか」を固定することで、ヘッド・層・Query・文脈ごとの疎性変動へ追随する。K-meansでKeyを意味的にまとめ、クラスタ中心で粗く並べ、`a/x+b` の分布当てはめで必要KV数を推定し、GQAの和集合化とFlashInferで実際のメモリロード削減へ結び付ける。
