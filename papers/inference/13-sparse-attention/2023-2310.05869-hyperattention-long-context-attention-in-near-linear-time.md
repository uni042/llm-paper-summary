# HyperAttention: Long-context Attention in Near-Linear Time

> HyperAttentionは、softmax注意行列を全要素計算する代わりに、局所性鋭敏ハッシュ（Locality-Sensitive Hashing; LSH）で非常に大きな注意要素を先に見つけ、残りをサンプリングして近似する。従来の「要素が有界」「安定ランクが小さい」という強い仮定を緩め、正規化後の最大列ノルムと、大要素除去後の非正規化行列の行ノルム比という二つの難易度パラメータで近線形時間の成立条件を表す。単一A100 40GB上のChatGLM2-6B-32Kでは推論を約50%高速化する一方、パープレキシティは5.6から6.3へ悪化する。131Kの因果注意単一層ではarXiv版で約5倍の高速化を報告する。

## 概要

標準自己注意は系列長Nに対してN²個のQK組を評価する。FlashAttentionはHBMとSRAM間のデータ移動を最適化するが、計算する注意要素自体は密なままである。そのため文脈長を極端に伸ばすと、I/O最適化後も二乗の演算量が支配する。

線形注意や低ランク近似はこの二乗計算を避けるが、任意のsoftmax注意行列を近似するには強い条件が必要になる。特に少数の巨大な注意値がある場合、一様サンプリングは重要要素を落としやすい。

HyperAttentionは注意行列を「少数の重い要素」と「多数の小さい残差」に分ける。重い要素はLSHで構造的に発見し、残りだけ確率的に近似することで、全QKを計算せず重要項を保つ。

## 問題設定

単純Top-k方式は重要要素を残せるが、正確なTop-kを得るため全QKを計算すれば選択処理だけで二乗時間になる。一様サンプリングは安いが、softmax前後の大値を取り逃したとき誤差が大きい。

理論面でも、注意行列の要素が無制限に大きい場合や安定ランクが大きい場合には、一般の注意近似へ二乗時間下限が知られている。HyperAttentionはこの最悪ケースを無条件に解消するのではなく、実際の注意の難しさを別の二パラメータで測り、その値が小さい範囲で高速化する。

## 手法

### 1. 二つの難易度パラメータで近似可能性を測る

一つ目はsoftmax正規化後の注意行列の最大列ノルムで、特定キーへ注意が極端に集中しているかを捉える。二つ目は、大きな要素を除いた非正規化注意行列について、行ノルム最大/最小の偏りを測る。

これらが小さい場合、行列全体が低ランクでなくても、重い要素を別扱いした後の残差を少数サンプルで推定しやすい。

### 2. sortLSHで重い注意要素を対角近傍へ集める

Q/KをLSH空間で並べ替え、内積が大きくなりやすい組を近い位置へ寄せる。すると重い要素がブロック対角近傍へ集まり、全N²組を走査せずブロック単位で計算できる。

入力はQ/Kベクトル、出力は明示的に正確計算する重い注意要素の集合である。softmaxの重い裾をここで確保することが、後段サンプリングの安定性に効く。

### 3. 残差部分を列サンプリングで近似する

重い要素を除いた残りは、多数の比較的小さな項からなる。HyperAttentionはこの残差から列をサンプリングし、softmaxの行和とAV積を推定する。

最終出力は「LSHで回収した重い要素の寄与＋サンプル推定した残差」の和になる。全注意行列をmaterializeせず、条件が良ければ系列長にほぼ線形な処理へ近づける。

### 4. 短い系列ではFlashAttentionへフォールバックする

公式実装には最小系列長の閾値があり、既定値は4096である。これ未満ではHyperAttentionのハッシュ・並べ替え・サンプリング費用が無視できないため、正確なFlashAttentionを使う。

これは「近似注意なら常に速い」わけではなく、固定費を償却できる長文脈で使う方式であることを示す。

### 5. 因果マスクは行列を分割して再帰処理する

因果注意では上三角を無効化する必要がある。HyperAttentionは行列を上左・下右・下左へ分け、対角を含む二領域には再帰的に因果マスク処理を適用し、完全に下三角に入る領域は非因果版HyperAttentionで処理する。

## 評価

### 評価条件

| 項目 | 設定 |
|---|---|
| GPU | NVIDIA A100 40GB ×1 |
| 単層ベンチ | 系列長1K〜131K |
| 比較 | FlashAttention |
| LLM | ChatGLM2-6B-32K |
| LLM評価 | LongBench系の長文入力 |
| 実装 | PyTorch 2.0系、Triton、FlashAttention系実装 |
| 既定例 | LSH投影7、block size 256、sample size 256、min seq len 4096 |
| 品質 | パープレキシティ |
| 性能 | 単一注意層時間、LLM推論時間 |

### 主な結果

| 条件 | HyperAttention | 交換条件 |
|---|---:|---|
| ChatGLM2、32K | 推論時間約50%短縮 | PPL 5.6 → 6.3 |
| 因果マスク単層、131K | arXiv版で約5倍高速化 | 近似注意 |
| 短い系列 | FlashAttentionへフォールバック | LSH等の固定費が大きい |
| 長い系列 | 相対利得が拡大 | 二つの難易度パラメータと近似誤差に依存 |

会議版・公開資料には131K単層でより大きい倍率を記す版もあるため、ここでは本リポジトリの一次URLであるarXiv要旨の約5倍を代表値として採る。版を跨いで最大倍率だけを混在させない。

## 既存研究との差

FlashAttentionは正確な注意を保ったままI/Oを減らすのに対し、HyperAttentionは計算する注意要素数自体を減らす近似方式である。

Reformer等のLSH注意はハッシュ結果をそのまま疎注意パターンとして使うが、HyperAttentionはLSHを重い要素の検出器として使い、残りをサンプリング推定する。低ランク/カーネル法より、少数の巨大要素へ強い設計になっている。

## 限界・実装状況

- 近似方式なので品質低下があり、ChatGLM2例ではPPL 5.6→6.3。
- 理論上の高速化条件は二つの難易度パラメータが小さいことに依存し、任意の注意行列で線形時間になるわけではない。
- 短系列ではハッシュ・並べ替えの固定費が不利で、公式実装もFlashAttentionへ切り替える。
- LSH投影数、block size、sample sizeは精度・速度の交換条件になる。
- 公式実装は https://github.com/insuhan/hyper-attn で公開されている。

## 一般的な実装上の含意

疎注意では「残す割合」だけでなく、重要要素を探す費用を含める必要がある。全QKを作ってからTop-kする方式は、疎化後のFLOPsだけ見てもエンドツーエンドでは速くならない。

HyperAttentionのように重い裾を構造探索し、残差だけを確率推定する設計はこの選択費用を抑えられる。ただし近似誤差と短文固定費を同じ条件で測る必要がある。
