# HyperAttention: Long-context Attention in Near-Linear Time

> HyperAttentionは「注意行列の全要素を近似的に同じ扱いにする」のではなく、**大きく効く要素と、それ以外の多数の小さい要素を分けて推定する**。大きなQK内積は局所性鋭敏ハッシュで探し、小さい残差はランダムサンプリングでまとめて推定する。この重い成分/軽い成分分解によって、全n²要素を列挙せずにsoftmax注意を近似する。

## 概要

長さnの系列に対する標準自己注意は、各クエリと全キーの内積を計算するためn²個の関係を扱う。FlashAttentionはこの厳密計算をタイル化して高帯域メモリへの中間行列書き出しを避けるが、計算するQKペア数そのものは二次のままである。

長文脈を二次未満へ落とす近似注意には理論上の難しさがある。注意行列に非常に大きい要素があると一様サンプリングはその重要要素を見逃しやすい。逆に全行列が低ランクである、あるいは全要素が十分有界であるという強い仮定を置くと、実際のTransformer注意には当てはまらない場合がある。

HyperAttentionは注意計算の難しさを、行列全体の安定ランクだけで表さず、正規化済み注意行列で特定列へ質量が集中する度合いと、大きな要素を除いた残差の行ノルム不均一性で捉える。これらの量が小さければ、元行列に極端に大きな要素が含まれていても、その大きな要素を先に回収した後の残差はサンプリングで近似しやすい。

実装では局所性鋭敏ハッシュ（Locality-Sensitive Hashing; LSH）で大きなQK内積候補を探し、残りを一様列サンプリングする。FlashAttentionと置き換えるのではなく、検出した疎部分やサンプル部分の計算に高速カーネルを利用できるモジュール構成を取る。

## 背景と問題設定

### FlashAttentionはメモリI/Oを減らすがQKペアは減らさない

厳密注意は
`softmax(QK^T / sqrt(d)) V`
を求める。FlashAttentionはスコア行列全体をGPU高帯域メモリへ保存せず、タイルごとにオンラインsoftmaxを更新することで実メモリ使用量とI/Oを大きく減らす。

しかし系列長が32K、64K、128Kと伸びると、タイル化しても計算する内積数はn²で増える。HyperAttentionが狙うのはこの**計算量そのもの**であり、厳密なタイル実装とは補完関係にある。

### 一様サンプリングだけではsoftmaxの重い要素を落とす

softmaxは大きい内積を指数関数的に強調する。ほとんどのQK内積が小さくても、ごく少数の大きな要素が注意出力の大半を決める行がある。

このとき列をランダムに少数だけ選ぶと、重要な大要素を引く確率が低く、推定誤差が急増する。したがって重い要素はサンプリングとは別経路で検出する必要がある。

### 全体低ランクという仮定も不要にしたい

過去の高速注意解析では、注意行列の全要素が有界、あるいは行列の安定ランクが小さいといった条件で高速化を証明することが多い。ところが実モデルでは少数の外れ値や集中列が存在し、グローバルな仮定だけでは「難しい部分が少数なのか、行列全体が難しいのか」を区別できない。

HyperAttentionは重い要素を取り除いた後の残差へ別の難易度指標を置くことで、「少数の難しい要素を正確に処理し、残りだけ近似する」というアルゴリズム設計を理論化する。

## 手法

### 1. 注意行列を重い成分と軽い成分に分ける

各クエリ行について、softmax後に大きな質量を持ち得るQKペアを重い成分、それ以外を軽い残差とみなす。

重い成分は出力への寄与が大きいため明示的に計算する。一方、軽い成分は個々の寄与が小さいため、全列を読む代わりにサンプルから総和と値加重和を推定する。

この分解により「重要な数個は落とさない」と「多数の小さい項を全部計算しない」を両立する。

### 2. LSHで大きなQK内積候補を見つける

局所性鋭敏ハッシュは、ベクトル内積や距離が近い組が同じハッシュ桶へ入りやすいように射影する。HyperAttentionではQとKをハッシュし、同じ/近い桶へ入ったペアを「大きな内積候補」として抽出する。

全n²ペアを調べてTop-kを探すのではなく、ハッシュ構造で候補数を絞るため、重い要素検出自体が二次計算になるのを避ける。

LSHは近似なので、ハッシュ射影数やブロックサイズを増やせば重い要素の回収率は上がるが、計算量も増える。公式実装はこの精度/速度ノブを明示的に持つ。

### 3. 軽い残差を一様列サンプリングする

重い要素を除いた後の注意行列について、キー/値列の一部を一様にサンプルし、各行の正規化量と`softmax(QK)V`の寄与を推定する。

大要素を先に除いているため、残差の寄与が比較的均され、一様サンプリングの分散を抑えられる。ここが「LSHだけの疎注意」との違いで、検出されなかった多数の小要素をゼロとして捨てるのではなく統計的に残す。

最終的には、明示計算した重い成分と、サンプル推定した軽い成分を足し合わせて注意出力を構成する。

### 4. 正規化量も同時に近似する

softmax注意では分子の値加重和だけでなく、各行の指数和である正規化分母が必要である。重い要素だけ正確に計算しても、軽い要素の総質量を無視すると出力のスケールが崩れる。

HyperAttentionはサンプリングを使って軽い成分の行和も推定し、重い成分の正確な寄与と合わせて正規化する。これにより「疎に残した要素だけでsoftmaxを取り直す」方式とは異なる近似になる。

### 5. 因果マスクでは三角行列を再帰的に処理する

自己回帰モデルでは未来トークンへ注意できないため、注意行列は下三角になる。非因果の場合のブロック近似をそのまま適用すると、マスク境界をまたぐブロックで不要要素が混ざる。

HyperAttentionは因果行列をブロックへ再帰分割し、完全に許可される矩形ブロックには高速近似を使い、対角付近のマスク境界をさらに細分化する。この追加構造のため、非因果注意より因果注意の高速化率は小さくなる。

### 6. FlashAttentionを下位カーネルとして利用できる

HyperAttentionはQK候補選択とサンプリング戦略を規定するアルゴリズム層であり、選択後の密な小ブロック計算をどのGPUカーネルで行うかは独立している。

著者実装はTritonとFlashAttention系実装を用いる。したがって比較は「HyperAttentionかFlashAttentionか」という完全排他ではなく、二次の全ペア計算をFlashAttentionで行う基準に対し、HyperAttentionが計算ペア自体を減らした上で高速ブロック演算を使う構成である。

## 一要求の流れ

各注意層へQ/K/Vが入ると、まずLSHで大内積候補を作り、そのペアのスコアを明示計算する。次に残りの列からサンプルを選び、軽い成分のsoftmax分母とV加重和を推定する。

重い成分と軽い推定を統合して各行の注意出力を返す。因果注意ならブロック再帰でマスクを守りながら同じ処理を適用する。

既存事前学習モデルへ入れる場合、全層を一度に置換する必要はない。後段の一部層だけHyperAttentionへ置き換えれば、品質劣化を抑えながら速度を得る中間点を選べる。

## 評価

### 代表的な評価条件

| 項目 | 条件 |
|---|---|
| GPU | NVIDIA A100 40GB ×1 |
| 単層ベンチマーク | 系列長1K〜131K |
| 比較 | FlashAttention |
| 条件 | 因果マスクあり/なし、前向き・後向き・両方を評価可能 |
| モデル統合 | ChatGLM2-6B-32K |
| モデル評価 | LongBench系入力、32K文脈を中心に評価 |
| 品質指標 | パープレキシティ |
| 実装 | PyTorch、Triton、FlashAttention系カーネル |
| 公式実装 | `insuhan/hyper-attn` |

### 代表的な評価結果

| 観点 | 条件 | 結果 | 解釈 |
|---|---|---|---|
| 単層速度 | 131,072、非因果 | FlashAttention比最大約54倍 | マスク境界処理がなく、近似のほぼ線形性が最も出る |
| 単層速度 | 131,072、因果 | FlashAttention比約5〜5.4倍 | 因果再帰の追加費用があるが長文ほど優位 |
| モデル推論 | ChatGLM2-6B-32K、後段20〜24層を置換 | 約50%高速化 | 部分置換でも全モデル速度へ反映 |
| 品質 | 同上 | PPL 5.6 → 6.3 | 速度の代わりに近似誤差が増える |
| 全層寄りの置換 | ChatGLM2 | 約2.3倍の速度向上が可能な設定 | 置換範囲を増やすほど速度は上がるが品質劣化も増える |

### 系列が長いほどFlashAttentionとの差が広がる

短い系列では、LSH構築、候補整理、サンプリングの固定費が二次計算削減を上回りやすい。長くなるとFlashAttention側のQKペアがn²で増える一方、HyperAttentionは重い候補とサンプル数を抑えるため差が広がる。

131Kで非因果約54倍、因果約5.4倍という差は、因果処理そのものの費用を示す。長文脈だから常に数十倍ではなく、生成モデルでは三角マスク処理を含む値を見るべきである。

### 部分置換は品質/速度交換を制御する

ChatGLM2実験では、後段の一部注意層だけをHyperAttentionへ置き換えることで、モデル全体の半分程度の速度改善と比較的小さいパープレキシティ悪化を得る。

全層を近似へ置き換えると高速化余地は増えるが、各層の近似誤差が蓄積する。したがって実運用では、層ごとの感度を測って近似層数を決める方が安全である。

## 既存研究との差

FlashAttentionは厳密注意のI/O最適化であり、計算する注意要素数は変えない。HyperAttentionは近似を許し、計算すべきQKペア自体を減らす。両者は異なる軸の最適化である。

固定窓やブロック疎注意は事前に決めた位置関係だけを残すが、HyperAttentionの重い要素はQ/K内容からLSHで動的に決まる。遠距離でも大きな内積なら明示計算の候補になり得る。

低ランク近似に対しては、注意行列全体の低ランク性を要求せず、少数の重い要素を分離した残差がサンプリングしやすければよいという条件へ緩和している。

## 限界・実装状況

第一に、HyperAttentionは近似注意なので品質は完全には保存されない。ChatGLM2ではPPLが5.6から6.3へ増えており、近似率や置換層数を上げれば誤差も増え得る。

第二に、LSHの追加処理がある。短文脈、小さいヘッド、密注意が既に十分高速な条件では、ハッシュ生成と候補整理の固定費が利得を消す可能性がある。

第三に、因果マスクでは非因果ほど大きい倍率にならない。131Kで非因果約54倍に対し因果約5.4倍であり、自己回帰生成では後者を基準に考える必要がある。

第四に、理論上の線形/準線形保証は論文が定義する難易度パラメータが小さい条件に依存する。注意が少数列へ極端に集中し、重い要素を効率的に分離できない分布ではサンプル数や候補数が増える。

第五に、公式実装は古いTriton版への依存を含み、A100 40GBで検証されている。現代のFlashAttention-3やHopper/Blackwellへ比較基準を更新すると絶対倍率は変わる可能性が高い。

## サーベイ上の含意

HyperAttentionは、長文脈注意の高速化を「どのトークンを捨てるか」だけでなく、**少数の大寄与を正確に扱い、多数の小寄与を統計推定する重尾分解問題**として捉える。これは後年のTop-k疎注意とは異なり、落とした軽い成分を完全なゼロにしない点が重要である。

また、理論計算量とGPU実装の橋渡しとして、近似アルゴリズムをFlashAttention系の下位カーネルと組み合わせる設計を示す。新しい高速注意法を比較する際は、厳密/近似、計算量削減/I/O削減、非因果/因果、単層/モデル全体を分けて読む必要がある。
