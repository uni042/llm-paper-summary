# QUILT: Rethinking Sparse-Attention Prefill through Shared Query Execution

> 隣接クエリが重なって選ぶKVを、集合分解SCSDとパイプライン実行、カスケード共有、タイル対応処理によって一度だけ読み込んで共有し、疎注意プリフィルの重複したデータ移動と逆量子化を取り除くカーネル実行方式。

## 概要

長文脈のプリフィル（入力全体を処理して最初のトークンを出すまでの段階）は、その遅延がそのままTTFT（最初のトークンまでの時間）として利用者に見える。文脈が伸びるほど注意の計算とデータ移動が膨らみ、プリフィル遅延に占める注意の割合は増えていく。疎な注意は、軽量なインデクサが各クエリについて重要なKV項目の小さな部分集合（上位K件）を動的に選び、その分だけを読むことで費用を絞る。さらにKVを低精度で保存し、選ばれたときに逆量子化して使う方式と組み合わされることも多い。

ところが、疎化は加速器への載せ方を難しくする。密な注意では複数クエリをまとめて規則的なKVタイルと一緒に処理でき、大きな行列演算として効率よく実行できる。動的な疎注意ではクエリごとに選ぶ項目が異なるため、既存カーネルはクエリ並列、つまりクエリごとに別々のコアへ割り当て、各クエリが自分の選択KVを集め、逆量子化し、処理する方式を取る。この方式は並列性は高いが、ワークロードの構造を見ていない。論文の実測では、隣接クエリ同士の選択は強く重なっており、グループの大きさ2では重なり率が全層でQasperで85.91パーセント超、GovReportで78.06パーセント超、最初の層では90.03パーセント超に達する。つまりクエリ並列実行は、同じKVを何度もHBMからオンチップメモリへ読み込み、コアごとに逆量子化し直している。プロファイルでも、KVの読み込みと逆量子化が既存カーネルの実行時間の大きな割合を占めることが示されている。

本論文のQUILTは、実行方式そのものをワークロード対応に変える。隣接クエリをグループとして共同実行し、選択集合の共通部分は一度だけ読み込んで逆量子化して全クエリで再利用し、固有部分だけを個別に処理する。これを実用にするための三つの仕掛けが中核であり、集合の分解を規則的なデータ並列演算へ帰着させるSCSD、分解処理を注意計算と重ねて隠すパイプライン実行、重なりの粒度の多様さへ適応するカスケード共有であり、最後にタイル形状との不整合を処理するタイル対応の末尾処理が付く。

**代表結果:** LongBenchでの評価（GLM-5.3とDeepSeek-3.2、テンソル並列と系列並列）で、QUILTは最先端の疎注意カーネルに対し平均カーネル遅延を最大55.1パーセント、処理するKV量を最大55.9パーセント削減し、TTFTを最大36.8パーセント削減した。精度は21データセットで比較対象とほぼ同等であり、スコアの平均絶対差はGLM-5.3で0.42点、DeepSeek-3.2で0.75点だった。実機測定に基づく研究である。

## 問題設定

問題は、疎化によって生まれた不規則さを、誰がどう負担するかという構造にある。疎注意はクエリあたりの仕事量を小さくするため、追加の帳簿処理（どのKVが共有でどれが固有かを調べる処理）に割ける余裕が元々小さい。素朴な集合演算の実装は、スカラーの走査、明示的なループ、要素ごとの所属判定といった、分岐が多く逐次的な処理になり、その費用が共有で節約できる読み込みと逆量子化を上回りかねない。実際、除去実験では素朴な集合積の実装は比較対象より21倍から33倍も遅くなっている。次に、重なりの構造は一様ではない。グループを小さくすれば重なり率は高いがグループをまたぐ再利用を取り逃がし、大きくすれば全員共通の項目しか共有できず、一部だけが共有する項目は重複処理へ戻る。固定の粒度ではどちらかの損が残る。さらに、共有と固有へ分解した後の区間はハードウェアのタイルの大きさと揃わないことが多く、数項目の残りのために追加のタイルが立ち上がって利用率が落ちる。つまり課題は三層であり、集合分解を加速器向きに安くすること、その費用をクリティカルパスから外すこと、粒度とタイル形状の不整合を吸収することである。本論文はこの三層すべてへ個別の機構で答える。なお前提として、疎注意が低精度KVと組み合わされる場合、重複するのは読み込みだけでなく逆量子化の計算でもあるため、共有の利得はデータ移動と計算の両方に及ぶ。

## 手法のあらまし

処理の流れは、隣接クエリのグループを単位として進む。まず各クエリの上位K件の索引列について、SCSD（シフト比較集合分解）が共通部分とクエリ固有部分への分解を行う。分解はカスケード共有の枠組みの中で階層的に行われ、大きなグループで全員共通の項目を取り出してから残りを小さい部分グループへ再帰的に分け、最後に残った固有分だけを個別処理する。各区間は消費される直前に構築され、注意計算の行列処理と並行してベクトル側で進むため、分解の遅延は表に出にくい。区間の末尾がタイルに揃わない場合は、タイル対応処理が、利用率の低い末尾を下の階層へ押し下げるか、最終段では重要度の低い固有項目を刈り込んで末尾タイル自体を消す。注意計算そのものは、共通区間については読み込んで逆量子化したKVをグループ全クエリで再利用し、固有区間についてはクエリごとに処理するという形になり、選択集合の意味は変えない。

## 手法

### 1. SCSD — 集合分解をソートとシフトと比較へ帰着させる

この機構が扱うのは、二つ（一般には複数）の上位K件の索引列から、共通部分と各列の固有部分を取り出す集合演算である。入力は重複のない索引列であり、出力は共通項目の列と、列ごとの固有項目の列である。素朴な実装が陥る逐次的な所属判定を避けるため、本方式は列を連結して出所ラベル付きでソートする。ソート後、両方の列に現れる索引は必ず隣り合って現れるため、右シフトした列と左シフトした列との等号比較だけで、共通項目の両方の写しを特定できる。片方の写しを選べば共通部分が得られ、どちらの隣とも一致しない要素が固有部分であり、出所ラベルで振り分ければ列ごとに分けられる。全体はソート、シフト、要素ごとの比較、論理演算、マスク選択という固定手順の規則的なデータ並列プリミティブで構成され、加速器のベクトル実行へそのまま載る。分岐の多いスカラー実行や不規則な制御フローを含まないため、帳簿処理の費用が小さく並列度も高い。なぜ効くかは除去実験が端的に示しており、素朴な実装が比較対象の21.84倍から33.65倍の遅延だったのに対し、SCSDへの置換だけで遅延は96.1パーセントから97.3パーセント削減された。追加費用はソートそのものであり、失敗条件は、共有がほとんどないワークロードでは分解の固定費だけが残って利得が出ないことである。合成ワークロードで共有長を振った測定でも、共有が小さい領域では小さなオーバーヘッドが観測されている。

### 2. パイプライン実行 — 分解処理を注意計算の裏へ隠す

この機構が扱うのは、分解処理の置き場所である。SCSDで分解自体を安くしても、それを独立した前処理として注意計算の前に置けば、その遅延はクリティカルパスへそのまま乗り、総時間は分解と注意の和になる。観測の出発点は、現代的な加速器では行列中心の演算とベクトル中心の演算が別々の計算パイプラインで動き、疎注意では行列側の処理に対してベクトル側の仕事が短く、空きスロットが残ることである。SCSDはソートや比較といったベクトル側の処理で構成されるため、この空きへ自然に入る。本方式は、各区間を消費される直前に構築する形に改め、最初の数区間だけを先に作って生産者と消費者の依存を断ち、定常状態では、行列パイプラインが現区間の注意計算をしている間に、ベクトルパイプラインが将来の区間の分解を進める。さらに、一つの分解タスクが一つの空き枠に収まらない場合に備え、分解を複数の細かい段へ分割し、連続する複数の枠へ分散させる。結果として、有効な分解遅延は注意計算と重なってほぼ見えなくなる。除去実験では、パイプライン化の追加効果として遅延がさらに45.9パーセントと36.9パーセント（GLM-5.3）、22.9パーセントと16.2パーセント（DeepSeek-3.2）削減された。失敗条件は、系列並列のように区間あたりの計算が短く、パイプラインの立ち上がり費用を償却しにくい条件であり、実際に系列並列での利得はテンソル並列より一貫して小さい。

### 3. カスケード共有 — 共有の粒度を階層で適応させる

この機構が決めるのは、各KV項目をどの大きさのクエリグループで共有するかである。既定では大きさ8のグループから始め、まず全クエリ共通の項目を取り出して共同処理し、それらを選択集合から取り除いた残りを小さい部分グループへ再帰的に分けて、部分的な共有をさらに拾い、共有できなくなった残りだけをクエリ固有として処理する。各項目は、それを共有できる最も大きな粒度で処理される。論文の例では、固定粒度2でも4でも処理KV数は10件だったのに対し、カスケードでは全体共通と部分共通の両方を拾って8件、つまり相異なる項目の数そのものまで減る。なぜ固定粒度では駄目かというと、粒度2では全体共通の項目が部分グループごとに重複処理され、粒度4では部分グループだけの共有が取り逃がされるためであり、重なりの構造が粒度ごとに異なる以上、単一粒度への固定は原理的に損を残す。実測では、カスケード共有は固定粒度2、4、8に対して処理KV数をGLM-5.3で30.8パーセント、20.6パーセント、22.9パーセント減らし、カーネル遅延の改善へつながった。追加費用は階層ごとの分解処理であり、これは前段のパイプライン実行で隠される前提である。失敗条件は、重なりが単一粒度に集中する単純なワークロードで、その場合は階層化の利得は小さく、固定粒度で十分になる。

### 4. タイル対応処理 — 末尾の不整合を押し下げと刈り込みで吸収する

この機構が扱うのは、分解後の区間の大きさとハードウェアのタイルの大きさの不整合である。区間の大きさをタイル単位で割った余りが、閾値（既定は50パーセント）以上に大きければ、末尾をパディングしてその階層で処理し、パディング分はマスクして意味を正確に保つ。余りが小さい場合は、その末尾を次のカスケード階層へ押し下げ、下の階層の仕事と合流させて利用率のよいタイルを作る。押し下げは正確な操作であり、共有の量を少し犠牲にしてタイル利用率を得る交換である。最終のクエリ固有段では押し下げ先がないため、重要度に基づく刈り込みを行う。観測では、カスケード後に残る固有項目は元の上位順位の末尾側に集中しており、重要な項目は既に共有区間で処理済みであることが多い。そこでタイルに満たない余りのうち、インデクサのスコアが最も低い項目を捨て、利用率の低い末尾タイル自体を消す。これが本方式で唯一の近似的な段であり、捨てる量が末尾の低重要項目に限られるため精度への影響は小さい。除去実験では、刈り込みによりカーネル遅延がGLM-5.3で23.71パーセントと22.68パーセント、DeepSeek-3.2で24.44パーセントと14.13パーセント削減され、出力の近さは、ランダムな刈り込みとの比較で重要度に基づく選択のほうが元の出力に近いことが余弦類似度で示されている。失敗条件は、固有項目に重要な項目が多く残るワークロードであり、その場合は刈り込みの精度影響が大きくなるため、近似を切って正確な変種を使う選択肢が用意されている。

## 評価

### まず見るところ

結論として、利得の大きさは重なりの量で決まり、モデルの構造差がそのまま結果の差になっている。GLM-5.3は層間でインデクサの選択を共有するなど重なりが大きく、カーネル遅延の削減はテンソル並列で平均53.8パーセント、処理KV量の削減は平均54.7パーセントに達する。DeepSeek-3.2では同じ指標が28.7パーセントと30.4パーセントであり、重なりが小さい分だけ利得も小さい。エンドツーエンドのTTFT削減は、GLM-5.3のテンソル並列で平均35.6パーセント、系列並列で10.4パーセント、DeepSeek-3.2では23.0パーセントと3.4パーセントであり、カーネルの利得がそのままではなく、プリフィル全体に占める疎注意の割合と、系列分割で短くなる区間長に左右される。合成ワークロードで共有長を0から2048へ振ると遅延は単調に下がり、共有が増えるほど固定費を回収して利得が支配的になる関係が確認できる。評価の強さは、比較対象と同一のサービング基盤へ両カーネルを統合し、差分をカーネルだけに限定した点にある。注意点は、基盤がAscend系のみであること、ワークロードがLongBenchの長文脈課題に限られること、共有が小さい条件では小さなオーバーヘッドが残ることである。

数値の読み方として、カーネル遅延の削減率とTTFTの削減率を分けて読む必要がある。前者は疎注意カーネル単体の話であり、後者はプリフィル全体に対する寄与である。また、処理KV量の削減は並列方式によらず同じ値になる（並列方式は仕事の配分を変えるだけ）ため、共有の本質的な効果はこの指標に最も素直に表れる。精度については、平均絶対差が小さいだけでなく、データセットごとの差の内訳も示されており、大きな悪化をする課題がないことが読み取れる。

## 既存研究との差

先行研究との差は、疎化の次の段階として「選択集合間の相関」を実行の対象にした点にある。従来の疎注意の研究は、どのKVを選ぶか（インデクサや選択方針の設計）に集中し、カーネルは選ばれた集合をクエリ独立に処理する前提だった。密な注意の高速カーネルはタイル化と入出力の意識で効率化したが、動的な疎性では規則的なタイル化がそのまま使えない。本論文は、選択方針は変えずに実行方式を変え、共通部分の再利用で読み込みと逆量子化の重複を消した。関連する方向として、プリフィルの高速化や注意のゲーティング、KVの追い出しと再利用を扱う研究があるが、それらは選択や保持の政策を変えるものであり、同一の選択集合の下でクエリ間の重複を回収する本方式とは層が異なる。集合演算をソートとシフトと比較へ帰着させる手法は、疎注意に限らず、重なりのある不規則ワークロードを加速器へ載せる際の一般的な道具立てとしても位置づけられる。

## 限界・実装状況

論文の記述から読み取れる制約は次のとおりである。第一に、評価基盤はAscend 910Cのみであり、GPU系での実測はない。設計は行列ユニットとベクトルユニットの分離、タイル実行、異種パイプラインという一般的な性質に依拠するとされるが、移植時の利得は未検証である。第二に、対象はプリフィルに限られ、デコード段階の疎注意や、バッチ化されたサービング全体での相互作用は評価されていない。第三に、利得は隣接クエリ間の重なり量に条件づけられ、共有が小さいワークロードでは分解の固定費による小さなオーバーヘッドが残る。第四に、タイル対応刈り込みは唯一の近似段であり、固有項目に重要な項目が多い場合は精度への影響が大きくなりうるため、正確な変種との使い分けが前提になる。第五に、対象モデルはモデル固有の疎注意を持つ2モデルであり、他の選択方針（固定パターンや学習型ゲーティングなど）での挙動は示されていない。実装はXYServeへ統合された研究カーネルであり、本方式自体の公式コード公開URLは論文中に確認できなかった。

## 一般的な実装上の含意

再利用できる原理は三つある。第一に、カーネルの高速化ではワークロードの相関構造を先に測るべきであり、独立性を仮定した並列化は、相関がある場合に重複したデータ移動として費用を払い続ける。重なり率のような単純な統計が、実行方式の設計判断を左右する。第二に、不規則な前処理を加速器へ載せる鍵は、処理を規則的なプリミティブの固定手順へ帰着させることと、その費用を既存パイプラインの空きへ隠すことであり、この二つを欠くと、発想が正しくても実装は負ける。除去実験で素朴実装が21倍超遅くなった事実は、その警告として読める。第三に、共有や分割の粒度は単一に固定せず階層化し、末尾の不整合はタイル形状を意識して処理することで、ワークロードの多様さとハードウェアの都合の両方へ適応できる。
