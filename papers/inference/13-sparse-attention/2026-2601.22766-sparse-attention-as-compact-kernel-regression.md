# Sparse Attention as Compact Kernel Regression：疎注意を有界支持カーネル回帰から導く

## 概要

Transformerの注意は、過去トークンのキーと現在のクエリの類似度を計算し、重み付き平均で値ベクトルを集約する。通常のsoftmax注意では、有限のスコア差であればほとんどすべてのトークンが厳密には正の重みを持つ。一方、sparsemaxやα-entmaxなどの疎注意は、関連性の低いトークンへ**正確にゼロの重み**を割り当てる。従来、こうした疎注意はsoftmaxを置き換える確率変換や、エントロピー正則化の変形として説明されてきた。

本論文は、注意を**ナダラヤ＝ワトソン推定器（Nadaraya-Watson estimator）**によるカーネル回帰として捉え直し、疎注意の重みが**有界支持カーネル（compact-support kernel）**から自然に導かれることを示す。単位長に正規化したキー・クエリでは、Gaussianカーネル回帰とsoftmax注意が対応する。同じ幾何学的な視点で、Epanechnikovカーネルと正規化ReLU、適応的な帯域幅を持つEpanechnikovカーネルとsparsemaxが対応する。さらにbiweight、triweightなどのべき多項式カーネルは、α-entmaxのパラメータを変えた場合と一致する。

著者はこの対応を理論的に整理したうえで、カーネル回帰に基づく系列モデルMemory Mosaicsに各種注意を導入し、言語モデリング、文脈内学習、学習時より長い系列への外挿を比較する。適応的な有界支持カーネルは、単純な上位k件選択や固定帯域の重み付けより良い条件があり、特に少量データと長さ外挿で有利な傾向が報告された。ただし、**本論文の主貢献は疎注意の数学的設計原理であり、LLMの実際の復号トークン毎秒やKVキャッシュ削減率を測った研究ではない**。

## 問題設定：なぜ注意の「疎さ」をカーネルから考えるか

### softmaxの重みはほぼ常に密である

クエリ `q` と過去のキー `k_i` の内積 `q·k_i` を温度 `γ` で割り、softmaxを取ると、各トークンに正の重み `a_i` が付く。あるトークンが明らかに無関係でも、数値的なアンダーフロー等を除けば重みは厳密なゼロにならない。長い文脈で全トークンを同時に参照する場合、注意分布の尾部が広くなることがあり、無関係な記憶を抑えにくい。

sparsemaxやα-entmaxは正規化の形を変え、一定の閾値より低いスコアをゼロへ切り落とす。しかし、どのようなスコア変換を選べば意味のある近傍を残せるのか、温度や閾値をどう理解すべきかは、単なる確率変換の観点だけでは説明しにくい。そこで著者は、**近いキーだけがクエリの推定へ寄与する局所回帰**として注意を解釈する。

### カーネル回帰の観点

ナダラヤ＝ワトソン推定器は、クエリ点 `q` の出力を、過去の観測点 `k_i` の値 `v_i` のカーネル重み付き平均で推定する。形式的には `ŷ(q)=Σ_i K_h(k_i−q)v_i / Σ_i K_h(k_i−q)` である。ここで `K_h` は距離に応じた非負の重みを返し、`h` は近傍の広さを制御する**帯域幅（bandwidth）**である。

Gaussianカーネルは距離が大きくなるほど滑らかに小さくなるが、任意の有限距離で正の値を持つ。対照的に有界支持カーネルは、一定距離より遠い点に**厳密にゼロ**を返す。従って、有界支持カーネルによる回帰は「近い記憶だけを使う注意」の数学的モデルになる。

### 内積と距離の関係

キーとクエリを単位長へ正規化すると、ユークリッド距離の二乗は `||k_i−q||²=2−2k_i·q` となる。つまり内積が大きいほど距離は小さい。Gaussianカーネル `exp(−||k_i−q||²/(2h²))` をこの式へ代入すると、重みは内積の指数関数に比例する。全キーで正規化すれば、温度 `γ=h²` のsoftmax注意と同じになる。この対応を出発点として、Gaussianを有界支持の別カーネルへ置き換えるとどの注意変換が得られるかを調べる。

## 手法：コンパクト支持カーネルから疎注意を導出

### 1. Epanechnikovカーネルと正規化ReLU

Epanechnikovカーネルは、距離が帯域幅 `h` より小さい場合に `1−||k_i−q||²/h²` に比例する重みを与え、それ以外ではゼロにする。`[x]_+=max(x,0)` を使えば `K_h(u)∝[1−||u||²/h²]_+` と書ける。

単位長のキー・クエリへ代入すると、内積スコアから固定の閾値を引いてReLUを適用する形になる。全トークンの重みを合計1に正規化すると、**正規化ReLU（normalized ReLU）注意**に対応する。帯域幅を固定すると、どの程度近いキーを残すかが固定の距離閾値で決まる。密なsoftmaxと違い、遠いキーは正確にゼロ重みになる。

ただし、固定帯域はクエリ周辺のキー密度が変わると問題を起こし得る。密度が高い場所では多数のキーを残し、まばらな場所ではほとんどキーを残せない。正規化の分母が小さくなることや、近傍数の変動による不安定さが生じるため、単純な固定閾値だけでは十分とは限らない。

### 2. sparsemaxと適応帯域幅

sparsemaxは、内積スコア `z_i` に対して、データから決まる閾値 `τ` を引き、正の部分だけを残す。形式的には `a_i=[z_i−τ]_+` であり、`Σ_i a_i=1` を満たすよう `τ` が決まる。この閾値はクエリごとのスコア分布に依存するため、固定値ではない。

カーネルの観点では、これは**Epanechnikovカーネルの帯域幅をデータに応じて変える**ことに対応する。周囲のキーが密なら近い領域を選び、まばらならより広い領域へ支持を調整できる。つまりsparsemaxの「疎な確率正規化」は、局所回帰における適応的な近傍選択と同じ構造を持つ。

この対応は、sparsemaxを単にsoftmaxの代用品として扱うよりも、どのキーを残すかを幾何学的に理解しやすくする。閾値 `τ` は単なる切り捨て定数ではなく、回帰カーネルの有効な支持半径を決める量になる。

### 3. α-entmaxとべき多項式カーネル

α-entmaxはsoftmaxとsparsemaxの間を連続的につなぐ注意変換であり、パラメータ `α>1` に応じて疎な重みを生成する。論文は `r≥1`、`α=1+1/r` とおくと、対応するカーネルが `K_h(u)∝[1−||u||²/h²]_+^r` となることを示す。帯域幅は `h=√(2−2rγτ)` として閾値と結び付く。

この関係の特別な場合として、`r=1` はEpanechnikovカーネルとsparsemax（α=2）、`r=2` はbiweightカーネルと1.5-entmax、`r=3` はtriweightカーネルと4/3-entmaxに対応する。`r` を大きくすると `α` は1へ近づき、極限でGaussianとsoftmaxの関係が現れる。**疎注意と密注意を別々の技法ではなく、カーネルの形状と支持範囲を変える一つの族**として説明できる点が理論的貢献である。

重要なのは、α-entmaxの疎さが上位k件をあらかじめ固定するものではないことだ。重みの分布に応じて支持集合の大きさが変わるため、クエリごとの情報密度へ適応できる。この特徴が少量データや系列長外挿での品質差につながる可能性がある。

### 4. 上位k件と固定近傍の対応

著者は、支持領域をカーネルの形状ではなく**最も近いk件**に固定する別の族も整理する。一定距離内のキーへ同じ重みを付ける一様カーネルで、ちょうどk件が入るよう支持半径を選ぶと、出力はk近傍の値の単純平均になる。これはtop-k平均注意（uniform-kNN）に対応する。

Gaussianカーネルの重みを使いつつ、最も近いk件だけを残せばtop-k softmax、すなわち切り詰めたGaussian回帰になる。どちらも支持集合のサイズを直接固定するが、重みを付ける形は異なる。単純平均では選ばれたk件を等しく扱う一方、top-k softmaxでは近いキーへより大きな重みを与える。

### 5. 最大値を基準とするReLUmax

固定帯域・適応帯域とは別に、クエリに最も近いキーのスコアを基準にして支持を切る方式も扱う。`r`-ReLUmaxは、最大スコアに基づく基準点からの差を整流し、そのべきで重みを付ける。これは局所近傍の中で相対的に関連するキーを残す方法であり、固定の絶対距離閾値とは異なる。

著者はこの方式とα-entmaxを比較し、**適応帯域幅を持つα-entmaxの方が総じて良い**と報告する。最大スコアに基づく単純な切断だけでは、クエリ周辺のキー分布全体に合わせた正規化が不足する可能性がある。

### 6. カーネルの形状と「疎さ」を独立に扱う

同じ支持集合でも、内部の重みが一様、線形、二次、三次のいずれで減衰するかで、出力の平滑性と重要記憶への集中度が変わる。反対に同じGaussian型の重みでも、全キーへ広げるか上位k件へ制限するかで疎さが変わる。本論文の整理は、**支持領域の決め方**と**領域内の重みの形**を分けて設計できることを示す。

## 評価設定：Memory Mosaicsを用いた比較

実験は、カーネル回帰型の記憶モデルMemory Mosaicsを使う。通常のTransformerの全機構を置き換えた大規模LLMサービング実験ではなく、注意カーネルの形状が記憶参照と系列長外挿へ与える影響を比較するための実験基盤である。位置埋込みを用いない構成を主に使い、EpanechnikovとALiBi位置バイアスを組み合わせた追加試験も行った。

| 評価領域 | 内容 | 測定対象 |
|---|---|---|
| 言語モデリング | Memory Mosaicsへ各注意を組み込む | 予測性能、注意方式の品質差 |
| 文脈内学習 | RegBench等、訓練標本数を変えた条件 | 最終トークン正答率、全変動距離（TVD） |
| 系列長外挿 | 学習時より長い系列へ適用 | 厳密一致率、長さに対する性能変化 |
| 合成記憶課題 | 多クエリ多トークン連想想起（MQMTAR）、反転、並べ替え | 関連する少数トークンを追跡できるか |
| 比較方式 | Gaussian/softmax、正規化ReLU、sparsemax、α-entmax、ReLUmax、top-k平均、top-k softmax | カーネルの支持と重み形状の違い |
| 追加条件 | Epanechnikov＋ALiBi位置バイアス | 位置情報追加の効果と悪化 |

評価では学習標本数や系列長を変え、単一のスコアだけで結論を出さない。RegBenchでは正答率と全変動距離を併用する。全変動距離は予測分布と参照分布の差を表し、小さい方が良い。正答率が高くても確率分布の校正が悪い場合を区別するためである。

## 実験結果

### 文脈内学習：適応的なコンパクト支持が有利

RegBenchの文脈内学習では、biweight、triweight、Epanechnikovのα-entmax系が、少量データの条件でGaussianに匹敵するか上回り、全変動距離も小さくなる傾向があった。特に訓練標本数1千～5千の低データ領域で差が見られる。最大スコアを基準にするReLUmax族より、適応帯域を持つα-entmax族の方が全体的に良いという観測も報告されている。

原著のRegBench表1に示されたtriweight系の一行では、**3-ReLUmaxの正答率は六つのデータ量条件で93.9～95.3%**、全変動距離は36.6から14.3へ低下する。同じtriweightでも**4/3-entmaxの正答率は93.9～95.3%**、全変動距離は32.9から14.4へ低下する。これらは同じカーネル族でも支持をどう調整するかで確率分布の品質が変わることを示す。個別の数値はRegBenchのモデル・訓練量条件に属し、一般的なLLMの推論精度として転用できない。

正規化ReLUは、正答率と全変動距離の両方で明確に劣る傾向があった。固定閾値で重みを切るだけでは、各クエリに適した支持領域を選べないことが理由として考えられる。また、選んだ上位k件を一様に平均する方式は、データ量を変えても全体として低調であり、**近傍の個数を固定するだけでは十分ではない**ことを示した。

### 系列長外挿：固定の近傍数より適応的な支持

学習時の系列長64を基準とし、それより長い系列でMQMTAR、反転、並べ替えの厳密一致率を測る。Gaussian注意は学習時と同じ長さでは良好だが、長い系列へ外挿すると急速に性能が落ちる条件がある。top-k平均は長さ外挿に失敗する傾向が強く、Gaussianをk近傍に切った方式も非常に長い系列では十分でない。

これに対し、triweightやbiweightのα-entmaxは、特にMQMTARで高い外挿性能を示し、triweightは反転課題でも優位な条件があった。Epanechnikovに対応するsparsemaxと1-ReLUmaxも、学習分布内の厳密一致を保ちながら比較的良好な外挿を示し、両者ではsparsemaxの方が良い傾向だった。これらは**少数の関連記憶を強く選ぶこと**が、長い入力で無関係な記憶が増えた場合の頑健性につながり得ることを示す。

ただし、合成の反転・並べ替え・連想想起は、現実のLLMの多段推論や長文書理解と同一ではない。実験の主目的は、注意のカーネル形状が長さ外挿へ与える効果を分離することであり、商用LLMの最大コンテキスト長を直接増やした結果ではない。

### 位置バイアスの追加は必ずしも有利でない

Memory Mosaicsは位置埋込みを用いない設計である。著者はEpanechnikovカーネルへALiBi位置バイアスを加えた追加実験を行い、性能が一貫して悪化する傾向を確認した。位置情報を追加すれば常に長文脈性能が上がるわけではなく、記憶の参照を距離に依存させることが、位置に依存しない連想課題では逆効果になる可能性がある。

### 言語モデリング：疎化の理論と実用品質の接点

著者はカーネル回帰型の注意をMemory Mosaicsへ組み込み、言語モデリングでも比較している。理論上、softmaxの代わりに有界支持カーネルを使うと、一定距離より遠い記憶の重みが厳密にゼロになる。実験はこうした疎な重み付けでも競争力のある予測性能が得られる条件を示すが、全モデル・全課題でGaussianより優れるとは結論していない。特に適応的な閾値を用いる方式が、固定の正規化ReLUや単純な上位k件平均より良いという傾向を重視している。

## 理論的な比較と設計上の含意

| 注意の種類 | 対応するカーネル・近傍 | 支持集合の決め方 | 主な特徴 |
|---|---|---|---|
| softmax | Gaussian | 全キーへ正の重み | 滑らかだが密な注意 |
| 正規化ReLU | Epanechnikov | 固定帯域幅 | 近いキーだけを残すが密度変化に弱い |
| sparsemax | Epanechnikov | 適応帯域幅 | 正規化閾値で支持を自動調整 |
| 1.5-entmax | biweight（r=2） | 適応帯域幅 | 二次の減衰を持つコンパクト支持 |
| 4/3-entmax | triweight（r=3） | 適応帯域幅 | 三次の減衰を持つコンパクト支持 |
| top-k平均 | 一様k近傍 | 近いk件を固定 | 選択キーの重みが等しい |
| top-k softmax | 切り詰めGaussian | 近いk件を固定 | 近傍内ではsoftmax重み |
| r-ReLUmax | 最大値基準のコンパクト支持 | 最大スコアから相対的に切断 | 適応帯域のentmaxとは異なる |

この整理から、**注意を疎にすること**と**疎な注意を高品質にすること**は別の問題だと分かる。単純に上位k件だけを残しても、近傍の密度や必要な記憶数がクエリによって異なれば最適とは限らない。コンパクト支持カーネルの形と帯域幅を選ぶことにより、関連記憶の範囲を入力に適応させられる。

また、注意が疎であることと、GPU上の計算量が自動的に削減されることも別である。正規化関数がゼロを返しても、実装が全キーとの内積を計算してからゼロへ変換するなら、内積計算の費用は残る。理論的な支持集合の疎さを、索引・近傍探索・疎行列カーネル等で実際の速度へ結び付けるには追加のシステム実装が必要である。

## 既存研究との差

softmaxをGaussianカーネル回帰とみなす対応は以前から知られている。本論文はその視点を疎注意へ広げ、Epanechnikov、biweight、triweightなどの古典的な有界支持カーネルが、sparsemaxやα-entmaxへ対応することを明確化した。特にα-entmaxのパラメータ `α=1+1/r` と多項式カーネルのべき `r` を結び付け、softmaxを極限に含む連続的な設計空間を示す。

通常のtop-k注意は、何件のトークンを残すかを直接決める。一方、α-entmaxはスコア分布から閾値が決まり、結果として支持集合の大きさが変化する。カーネル回帰の観点では、前者はk近傍を固定する方式、後者は局所データ密度へ帯域幅を適応させる方式として理解できる。これは疎注意のパラメータ選択に理論的な意味を与える。

Memory MosaicsやHopfield型の連想記憶との関係では、関連する記憶だけを局所的に参照することが、長さ外挿や少量データで有利になる条件を整理している。位置埋込みの有無を含めて、単なるGPU高速化ではなく**記憶の選択機構の設計**に焦点がある。

## 限界・適用条件

**主に理論と比較的小規模な系列モデルの評価である。** Memory Mosaicsを使った実験は、既存の大規模生成LLMの全層をsparsemax/entmaxへ差し替えて同じ性能が得られることを証明しない。事前学習の安定性、既存重みからの移行、RoPEやグループ化クエリ注意との整合性は別途検証が必要である。

**数学的対応には前提がある。** キー・クエリの正規化、内積とユークリッド距離の関係、温度・閾値・帯域幅の対応が成立する設定を使う。任意の非正規化ベクトルや異なるスコア関数へ、そのまま同じカーネル解釈を適用できるとは限らない。

**ゼロ重みと計算高速化は同じではない。** softmaxをsparsemaxへ置き換えるだけでは、注意スコアの生成に必要な全キーとの内積が残る可能性がある。厳密なゼロ重みを利用した疎な演算や近傍探索を実装しなければ、長文脈の実測速度やKV容量が改善する保証はない。本論文は主に予測性能・長さ外挿を検証しており、LLM推論基盤のトークン毎秒やメモリ使用量の体系的比較を主張していない。

**合成の長さ外挿課題と現実の長文脈タスクは異なる。** MQMTAR、反転、並べ替えは関連トークンを選ぶ能力を分離するのに有効だが、現実の検索拡張生成、コードベース理解、長い会話の指示追従を完全には代表しない。実運用へ適用するには、長文書QAや実際の生成モデルでの評価が必要である。

**すべての疎注意が同等ではない。** 固定帯域の正規化ReLUや一様top-k平均は、実験で品質低下が見られた。疎であること自体を目的にせず、支持領域の適応性、重みの形、入力分布を考慮する必要がある。

**Windowsローカル推論への直接的な速度効果は未実証である。** 本研究はGPUのCPUオフロード、llama.cpp、Ollama、12GB VRAMでの実測を対象としていない。ローカルLLM推論の高速化手段として導入できるかは、実装可能性と再学習の費用を含めた別の検討を要する。
