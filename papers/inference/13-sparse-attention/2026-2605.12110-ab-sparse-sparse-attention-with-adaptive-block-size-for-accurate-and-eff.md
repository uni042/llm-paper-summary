# AB-Sparse：注意ヘッドごとにブロック長を変える長文脈疎注意

## 概要

長文脈の大規模言語モデルでは、復号のたびに過去の鍵・値キャッシュ（KVキャッシュ）を読み出す費用が増える。ブロック疎注意（block sparse attention）は、過去トークンを一定長のブロックへ区切り、各ブロックの代表ベクトルと現在の問い合わせの類似度から重要なブロックだけを読み込む。QuestやArkValeなどは通常、全ての注意ヘッドへ同じブロック長を適用する。しかし、重要トークンが局所的に密集するヘッドと、離れた位置へ散在するヘッドでは、適切な粒度が異なる。

AB-Sparseは、注意ヘッドごとのブロック長を軽量な事前較正で割り当てる。Wikipediaから50標本を取り、候補長16・32・64で注意重みの再現率を測定し、許容損失内で最も大きいブロック長を各ヘッドへ選ぶ。細かいブロックによって代表ベクトルの数が増える問題は、チャンネルごとの非対称4ビット量子化で抑える。さらに可変長の代表ベクトル配列を接頭和索引で一括処理し、論理ブロックを既存の固定物理ページへ写像する三つのGPUカーネルを設計する。

Llama-3.1-8B、Qwen3-8B、Qwen3-32BのRULERとLongBenchで、Quest・ArkValeを同じKV予算4%、平均ブロック長32の条件で比較した。Qwen3-32BではQuestのRULER平均76.24から81.67へ5.43ポイント改善し、Llama-3.1-8BのQuest比較では78.23から81.74へ3.51ポイント改善した。A100上の64K文脈、バッチ4ではQuest比1.59倍の処理量を報告する。これはブロック長適応による品質改善と、量子化・専用カーネルによる実行効率を分けて理解する必要がある。

## 問題設定

### ブロック長の一律設定による見落とし

復号時の注意は、現在の問い合わせベクトル `q_t` と過去の鍵ベクトル `k_i` の内積を正規化し、その重みで値ベクトル `v_i` を集約する。過去の全KVを毎回読む代わりに、ブロック代表 `c_i` と `q_t` の内積 `r_i=q_t c_i^T` でブロックを順位付けし、上位だけ詳細な注意を計算すれば読出し量を減らせる。代表の計算方法はQuestの最大最小集約やArkValeの境界体積表現などがあり、AB-Sparseはそれらを変更せずブロック長の割当を改良する。

ブロックが大きいと、重要なトークンと無関係なトークンが同じ代表にまとめられ、重要ブロックの順位が下がることがある。逆にブロックが小さいと、候補ブロック数と代表ベクトル数が増え、順位計算とメモリ占有が増える。問題は全ヘッドでこの交換条件が同じではない点である。原著はLlama-3.1-8BとQwen3-8Bの32K文脈、保持トークン予算4096、候補ブロック長16・32・64でヘッド別の注意再現率を調べた。

その結果、粒度に鈍感なヘッドは大きいブロックでもほぼ完全な再現率を保つが、敏感なヘッドでは長さ32でも再現率が0.1未満へ落ちる例がある。全ヘッド長32の平均再現率はLlama-3.1-8Bで89.7%、Qwen3-8Bで77.8%だった。一方、ヘッド別に割り当てると平均ブロック長がそれぞれ44.2、39.5とむしろ大きいまま98%の再現率を得た。単に全ヘッドを細かくするより効率的な余地がある。

### 変長ブロックが生む実装上の障害

注意ヘッドごとにブロック長を変えると、同じ文脈長でも代表ベクトル数がヘッドごとに異なる。通常のGPUカーネルはヘッドを同じ長さの配列として一括処理するため、短い配列へ大量の埋め草を加えるか、ヘッドを逐次処理する必要が生じる。さらに、KVキャッシュの実体は固定サイズのページとして管理されることが多く、可変長の論理ブロックをそのまま物理ページとみなすと不整合になる。AB-Sparseはブロック長割当だけでなく、これらの実行基盤の障害も対象にする。

## 手法

### 1. 50標本を用いるヘッド別ブロック長の事前較正

ヘッド `h` のブロック長を `B` としたとき、重要と判定されたブロックが本来の注意重みをどれだけ含むかを注意再現率 `Recall(h,B)` として測る。候補の最小ブロック長を `B_min`、許容保持率を `τ` とし、`Recall(h,B) >= τ Recall(h,B_min)` を満たす最大の `B` を `B_h*` にする。これにより、粒度を粗くしても重要情報を失いにくいヘッドは大きいブロックを使い、細粒度が必要なヘッドだけ小さいブロックを使う。

この較正はWikipediaの50標本で一度行う。毎回の推論で全ブロック長候補の代表を再計算すると長文脈で高価になるため、実行時には割当を固定する。著者はWikipediaで決めた割当をRULERの異なる四つの課題群へ適用し、平均ブロック長を揃えた一律方式より高い再現率が得られることを示す。これは注意ヘッドの役割が入力によらず比較的安定しているという観測に依存する。

入力は較正文書、モデルのヘッド別注意、候補ブロック長と保持率閾値であり、出力は各ヘッドの固定割当 `B_h*` である。較正データが運用分布と大きく異なる場合、ヘッドの粒度感度が同じとは限らない。また「学習不要」はモデル重みを更新しない意味であり、事前較正の計算とデータが不要という意味ではない。

### 2. ブロック代表ベクトルの非対称4ビット量子化

敏感なヘッドへ小さいブロックを割り当てると代表ベクトルの個数が増え、推論時の代表読出しが新しい帯域ボトルネックになり得る。AB-Sparseは、代表ベクトルが最終注意出力に直接加算されるのではなく、読み込むブロックの順位付けにだけ使われることに着目する。最終的な注意演算は選択されたKVの実値を使うため、代表の精度要件はKV本体の精度要件と異なる。

著者は代表ベクトルの各チャンネルで値が比較的狭い範囲に集中することを測定した。そこでチャンネルごとに尺度と零点を持つ非対称4ビット量子化（INT4 asymmetric per-channel quantization）を適用する。2ビットは代表の順位が大きく乱れ、対称4ビットも層によって再現率を維持できない。一方、非対称4ビットは対象の二モデルで全層の上位ブロック再現率を0.9以上に保ち、8ビットより小さい代表領域を実現する。

論文はこれを「損失なし代表量子化」と呼ぶが、浮動小数点値の完全なビット同一性を保証するという意味ではない。重要ブロック選択の再現率や最終タスク精度がほぼ維持されるという実験上の意味である。量子化した代表は専用の推定カーネル内で必要時に復元し、浮動小数点の代表配列を別途丸ごと作らない。

### 3. 可変長代表を一括処理する推定カーネル

ヘッド `h` が `N_h` 個の代表を持つとき、全ヘッドの代表を一次元に連結し、`offset_(h+1)=offset_h+N_h` という接頭和索引を用意する。ヘッド `h` の代表は連結配列の `[offset_h,offset_(h+1))` に入る。この表現ならヘッドごとに長さが違っても、長いヘッドに合わせた埋め草を作る必要がない。

第一のカーネルは、問い合わせと代表の内積計算、代表の4ビット復元、ヘッドごとの可変長範囲参照を一つのGPU起動に融合する。入力はヘッド別問い合わせ、量子化代表配列、接頭和索引であり、出力は各ヘッドのブロック重要度である。逐次ヘッド処理や代表の完全復元を避けることで、長文脈ほど大きくなる代表読出しを削減する。

### 4. ヘッド別上位K選択と物理ページへの写像

第二のカーネルは、ヘッド別の重要度を使って上位ブロックを選ぶ。保持トークン予算 `T` を全ヘッドで同じにし、ヘッド `h` の選択ブロック数を `K_h=ceil(T/B_h)` とする。これにより小ブロックのヘッドだけがより多くのトークンを読むという比較の不公平を避け、改善がブロック選択の質によることを評価できる。接頭和索引を再利用し、各ヘッドの可変長スコア配列から選択する。

第三のカーネルは、選択された論理ブロックを実際のKVキャッシュへ対応付けて注意を計算する。物理ページを最小粒度に固定し、大きい論理ブロックは連続する複数の物理ページの組として表す。論理ブロックと物理ページの対応をストライド付き索引として扱うため、選択KVをいったん連続メモリへ集め直す操作を避けられる。これが標準的なページ化KV管理との互換性を保つ鍵となる。

この三つのカーネルを組み合わせることで、ヘッドごとのブロック長を変えても一括推定・選択・注意実行が可能になる。原著は素朴な実装と比較して、推定カーネル最大5.6倍、上位K選択最大9.4倍、注意カーネル最大3.1倍の局所高速化を報告する。ただしこれらは各カーネル単体の倍率であり、モデル全体のトークン処理量へ直接掛け合わせてはいけない。

### 2. 文脈長別の差と長い生成

Llama-3.1-8BのRULERでは、文脈16K/32K/64K/96KでQuestが81.57/81.02/77.48/72.83、AB-Sparse-Questが85.04/85.56/81.49/74.87だった。96Kでも改善は残るが、長文脈化に伴う精度低下そのものを完全に解消したわけではない。Qwen3-32Bでは16KでQuest77.78に対しAB-Sparse-Quest86.98、96Kで72.07に対し75.50となり、改善幅が文脈長によって変化する。

長い生成の評価では、Qwen3-8Bで入力を短くし、最大32Kトークンの生成を許可してAIME24、AMC23、MATH-500を各入力4回標本化した。温度0.6、上位K=20、累積確率上位p=0.95の条件で、正答率指標pass@4はQuestの平均47.2%からAB-Sparse-Questの53.1%へ改善した。内訳はAIME24が20.0→23.3、AMC23が47.5→60.0、MATH-500が74.0→76.0であり、改善の大きさは課題に依存する。

### 3. 注意計算遅延と処理量

64K～256Kの注意計算遅延では、短い文脈ではQuestとほぼ同等、文脈が長くなるほどAB-Sparseが速くなる傾向を示した。これは代表ベクトルをINT4へ圧縮し、重要度推定のメモリ転送量を減らした効果である。A100上のLlama-3.1-8B、64K文脈ではバッチ1の処理量がQuestと同程度だが、バッチ4ではAB-SparseがQuest比1.59倍の処理量を達成した。ヘッド別可変長を埋め草なしで一括実行する索引方式が、同時実行数の増加で効く。

これらの実測は「精度を上げるためにブロック長を変えても処理量を落とさない」だけでなく、一部条件では専用カーネルと代表圧縮により処理量自体も改善することを示す。ただしバッチ4の1.59倍はA100、Llama-3.1-8B、64Kの条件に限定され、全モデル・全バッチの倍率ではない。

### 4. 構成要素除去と感度

代表量子化の比較では、2ビットが上位ブロック再現率を大きく下げ、対称4ビットも層によって不足した。チャンネル別非対称4ビットは両モデルの全層で上位ブロック再現率0.9以上を維持し、最終RULER精度もBF16代表とほぼ同等だった。これは代表が順位付けにだけ使われるという設計と整合するが、全入力に対する数学的な完全同一性を意味しない。

GPUカーネルの構成要素除去では、素朴なヘッド逐次処理やKVの一時集約と比べ、重要度推定最大5.6倍、上位K選択最大9.4倍、注意最大3.1倍の局所高速化を示した。RULERの保持予算を2～8%へ変えた感度試験では、Llama-3.1-8Bの64KでQuestより2.97～3.69ポイント高い精度を維持した。予算を増やすだけではヘッド別の粒度適応の効果を置き換えられないことを示す。

## 既存研究との差

H2OやInfiniGenはトークン単位の重要度選択を扱い、細かい選択が可能な一方、各復号ステップでの選択費用が大きい。ClusterKVやRetroInferは意味的に近いKVをクラスタ化して検索するが、標準のページ化KV配置を変更する。QuestとArkValeはページ化配置と相性の良いブロック疎注意を用いるが、全ヘッド同一ブロック長の前提が残る。

AB-SparseはQuestの最大最小代表とArkValeの境界体積代表をそのまま利用できるようにし、ヘッド別ブロック長を共通の追加機構として挿入する。較正、代表のINT4量子化、可変長の接頭和索引、物理ページへのストライド写像が相互に補完するため、単にヘッド別に長さを選ぶだけでは原著の効率を再現できない。

## 限界

### 未評価事項

第一に、ブロック長は事前較正で固定する。Wikipediaの50標本で見られたヘッドの粒度感度が、極端に異なる運用データやモデル更新後にも不変である保証はない。実行時に適応し直す場合、代表ベクトルを作り直す費用が発生するため、論文はそれを避けている。

第二に、代表ベクトルの非対称4ビット量子化は順位付けの品質をほぼ保つが、完全に無誤差ではない。全注意の品質を常に達成するわけでもなく、Llama-3.1-8BのRULERで全注意88.71に対しAB-Sparse-Quest81.74という差が残る。品質改善を「完全に無損失の注意演算」と言い換えてはならない。

第三に、GPUの実測はA100/H800の80GB環境を中心とする。RTX 4070 Super 12GBやCPU退避のあるWindows環境では、KVのページ配置、4ビット代表の復元、カーネル起動、重み転送が異なるため、バッチ4の1.59倍をそのまま期待できない。さらに、推論基盤へ専用の可変長カーネルを組み込む実装費用がある。

第四に、性能の主な測定は64K以上の長文脈であり、短文脈では代表量子化や可変長索引の利点が小さくなる。バッチ1ではQuestと同程度の処理量である。モデルの回答品質、注意再現率、注意カーネルの遅延、エンドツーエンド処理量は異なる指標であり、最大値を横断して一つの改善率にまとめるべきでない。

第五に、平均ブロック長とKV保持予算を揃える実験設計は公平だが、モデル全体の重みメモリ、長い対話の動的キャッシュ管理、複数GPU間の転送、サービング待ち行列まで同時に最適化した結果ではない。論文は注意演算を中心とするシステム研究として読む必要がある。
