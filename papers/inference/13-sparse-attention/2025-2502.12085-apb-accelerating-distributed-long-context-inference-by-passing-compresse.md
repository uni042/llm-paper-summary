# APB：圧縮した文脈ブロックをGPU間で渡す分散長文推論

## 概要

長文入力の事前計算（prefill）では、各トークンが過去のトークンに注意を向けるため、文脈が長くなるほど注意行列の計算量が急増する。系列並列化（sequence parallelism）は入力を複数GPUへ分けることで計算を並列に進めるが、完全な注意計算を維持する方式ではGPU間で大量の情報を交換し、計算総量も大きい。逆に疎な注意だけを単一GPUで実施しても、分割による並列性は得られない。

APBは両者を組み合わせる。入力文書を複数GPUへ分割し、各GPUは自分の局所文脈から重要な鍵・値（KV）だけを選択する。選ばれたKVを全GPUへ収集し、各GPUは自分より前のブロックから来た重要KVを参照する。入力冒頭のアンカーブロックと局所全文は保持するため、過去文脈への依存をすべて切り捨てるわけではない。実装では注意マスクを改変したFlashAttentionを使う。

原著は最大速度改善をFlashAttention比9.2倍、RingAttention比4.2倍、StarAttention比1.6倍と報告する。ただしこれは評価条件内の最大値であり、全入力長・全モデルの保証ではない。評価では品質が完全注意を上回る個別項目もある一方、近似による品質差が残る個別タスクも存在する。

## 問題設定と背景

### 系列分割だけでは注意の総仕事量が残る

長文をH個のGPUへ均等に分けると、各GPUは概ね文書長の1/Hを担当する。しかしあるトークンが自分より前のブロックにある情報を必要とするとき、局所データだけで完全注意を計算できない。RingAttentionはブロック間のKVや部分結果を巡回させ、オンライン正規化を使って厳密な結果を得る。これによりメモリを分散できるが、長い入力の注意演算を削除するわけではない。

一方、MInferenceなどの近似注意は一部の注意行列要素だけを計算する。単一GPUでは演算量を削減できるが、分散時にはどの過去トークンを残すかを局所的に判断しなければならない。全GPUが全体の注意スコアを収集してから重要トークンを決める設計では、削減したい通信が前処理に復活する。

### アンカーのみを共有する方式の情報損失

StarAttentionは文書先頭の共通アンカーを各GPUに付け、ブロック間通信を避ける。これは通信量の削減に有効だが、先頭以外の過去ブロックにある重要な固有情報が見えなくなる。複数文書の照合や離れた箇所を参照する質問では、局所ブロックと冒頭だけで答えを復元できない。APBの「通過ブロック」は、この失われた遠距離情報を少量のKVで補うために設計された。

## 手法

### 1. 文書・質問の分離と局所ブロック

入力を長い文書dと比較的短い質問qへ分け、文書をH個の局所ブロックB_1〜B_Hに分割する。各GPUは原則として一つのB_hを担当する。先頭GPU以外には、文書冒頭のl_aトークンと質問を含むアンカーブロックAを付与する。質問をアンカーへ入れる理由は、後段の重要KV選択器に質問依存の手掛かりを与えるためである。

アンカーは単なる全体共有メモリではない。各GPUの局所入力として前置され、通常の自己注意の範囲に入る。先頭を共有すると各ブロックの位置関係や基本文脈が安定するが、アンカーが長すぎると各GPUで重複計算する部分が増える。原著はStarAttentionより短いアンカーを採用し、実験では4Kトークンを使う。

### 2. 局所的なKV重要度の推定

各GPUは自分の局所ブロックB_hに対し、Locretに由来する保持ヘッド（retaining heads）Rを使って各KV位置の重要度s_iを計算する。小型の多層パーセプトロンへその位置のQ・K・V情報を渡し、将来のKV計算への影響を近似する。局所の重要度上位l_p個の位置を選び、元のKVペアを圧縮ブロックB_h^Cとして残す。

ここでの圧縮は低ビット量子化ではなく、送信するトークン位置の選択である。局所選択のため全GPUの注意行列を先に集める必要がない。重要度推定器の学習には追加の長文教師あり微調整データを使うため、完全な学習不要手法ではない。また、誤った重要度で選択された位置は後段で復活せず、情報損失の原因となる。

### 3. 圧縮KVのGPU間収集と因果制約

各GPUが選んだ圧縮ブロックを全体収集（AllGather）で交換する。GPU hが注意計算で使用する通過ブロックP_hは、先行するGPU 1〜h-1の圧縮ブロックを連結したものだけである。未来側GPUの圧縮ブロックは受信していても注意の参照先から除く。これにより自己回帰モデルの因果関係を保ち、過去の重要トークンへだけ近似的にアクセスする。

全体収集の通信量は各GPUが選ぶl_pとGPU数に依存する。l_pを大きくすれば重要情報を残しやすいが、通信・注意演算が増える。小さくすれば速くなるが、離れた箇所を参照する質問の正答率が低下し得る。論文の主要な交換条件は、この通信予算と情報保持の関係にある。

### 4. 改変FlashAttentionでの計算と破棄

GPU hはアンカーA、先行GPU由来の通過ブロックP_h、自分の局所ブロックB_hを一つの論理的な注意対象として扱う。改変したマスクM'を用い、許された位置だけに注意を計算する。通過ブロックは注意計算用のKVであり、フィードフォワードネットワークの入力として同じトークンを再処理しない。注意処理後には一時的な通過ブロックを破棄する。

文書の事前計算を近似的に済ませた後、短い質問への注意と回答の復号には正確なオンライン正規化を適用する。この設計は「長い文書部分の計算を減らし、回答生成に必要な後段は正確に扱う」という役割分担であり、推論全体が完全注意と数学的に同一になるという意味ではない。

### 5. 1要求の実行経路と費用

一つの長文要求では、文書と質問を分離し、文書をGPUに配置し、アンカーを複製する。各GPUは局所QKVを作って重要度を推定し、圧縮KVを全体収集する。その後、過去GPUからの通過ブロックを組み込んだ注意計算を行い、通常の層計算へ戻る。後続の質問処理と復号は文書から作った状態を使う。

追加費用は、アンカーの重複計算、重要度推定器の実行、圧縮KVの通信、特殊マスク処理である。利得は、遠距離の大半のKVを計算対象から外し、GPU間通信を圧縮した量に限定できることから生じる。短い入力では追加費用が相対的に大きくなり、長い入力ほど削減余地が増える。

## 評価条件

原著はモデル品質と速度を分けて測る。速度は入力と出力の合計トークン数を事前計算時間と復号時間の合計で割った値であり、事前計算だけのカーネル速度とは異なる。

| 項目 | 原著の設定 |
|---|---|
| モデル | Llama-3.1-8B-Instruct、Qwen-2.5-14B-Instruct、Yi-34B-200K。入力長拡張試験はLlama-3-8B-1M |
| 品質評価 | ∞Benchの10タスク、RULERの13タスク。主実験は128K文脈 |
| 入力長感度 | 32K〜512Kトークン |
| GPU | NVIDIA A800 80GB、8 GPU/ノード。大きいYiは2ノード |
| 相互接続 | ノード内NVLink第3世代、ノード間HDR InfiniBand |
| 系列並列数 | 主実験8。別に2、4、6、8の感度実験 |
| APBの主要予算 | アンカー4K、通過KV 2K、128K文脈の主実験 |
| 比較 | FlashAttention、Ulysses、RingAttention、MInference、StarAttention |
| 推論 | 貪欲復号（温度0）。品質は全評価例、速度は各タスク先頭20例の平均 |

比較の公平性には注意が必要である。FlashAttentionとMInferenceは単一GPU、系列並列方式は主に8 GPUで測るため、倍率は同一GPU数に固定したアルゴリズム比較ではなく、実行構成を含むシステム比較である。

## 評価

### 1. 長文タスクの品質と速度

| モデル・評価 | 完全注意の平均 | APBの平均 | 重要な読み取り |
|---|---:|---:|---|
| Llama-3.1-8B、∞Bench | 47.45 | 50.91 | 平均は上昇。ただし一部のタスクでは低下 |
| Qwen-2.5-14B、∞Bench | 42.68 | 47.34 | 平均は上昇。個別タスクの改善幅は一様でない |
| Yi-34B、∞Bench | 39.39 | 43.78 | 平均は上昇。特定の検索・推論項目では劣化もある |
| Llama-3.1-8B、RULER | 82.20 | 81.63 | 完全注意を0.57ポイント下回る。無劣化という一般化は不可 |
| Qwen-2.5-14B、RULER | 77.33 | 85.28 | 複雑な検索項目で改善が大きい |
| Yi-34B、RULER | 80.94 | 85.03 | 平均は改善するがタスクごとの増減がある |

∞BenchではLlama-3.1-8BのR.KVが完全注意51.00からAPB81.8へ上昇する一方、同じモデルのE.Diaは11.00で同値、E.QAは29.04から29.25へ小幅変化である。RULERのLlama-3.1-8Bでは平均が完全注意を下回る。したがって「精度が一切低下しない」という論文の総括表現は、すべての個別条件の厳密な同等性を意味しない。

速度について論文が示す最大値は、FlashAttention比9.2倍、RingAttention比4.2倍、StarAttention比1.6倍である。StarAttentionとの比較では、対象の長文評価で少なくとも25%の速度改善を報告する。前述のように入力長とGPU構成を合わせて解釈すべき値であり、単一GPUで9.2倍になると読んではならない。

### 2. 文脈長の感度

RULERで32Kから512Kまで入力を伸ばした実験では、APBの相対優位は長文側で拡大した。これは系列並列で局所文書の処理を分散し、通過KVを圧縮して二次的な注意演算を減らす設計と整合する。ただし短文ではアンカー複製や全体収集の固定費が効き、速度上の差は小さくなる。論文の図にある曲線を、測定値が示されていない中間点の厳密な倍率へ置き換えない。

### 3. 構成要素除去実験

∞BenchのE.MCタスク、Llama-3.1-8B、128K文脈、先頭50例でアンカー、通過ブロック、重要度推定器、質問埋め込みを切り分けている。

| 構成 | E.MCスコア | 解釈 |
|---|---:|---|
| 完全APB（アンカー・通過・保持ヘッド・質問） | 72 | すべて併用した条件 |
| 質問埋め込みのみ除外 | 68 | 質問が局所重要度の推定に寄与 |
| 保持ヘッドをランダム選択に置換 | 66 | 重要KV選択がランダムより有効 |
| 通過ブロックなし、ランダム選択条件 | 64 | 遠距離情報共有が寄与 |
| アンカーなし、保持ヘッド条件 | 28 | 冒頭共有がないと大幅に劣化 |
| アンカー・通過ともなし | 22 | 分割された局所文脈だけでは不十分 |

アンカーの重要性が際立つ一方、通過ブロックや質問埋め込みにも寄与がある。保持ヘッドの効果は質問埋め込みとの組合せに依存するため、単独の部品を外した差をそのまま他条件へ加算することはできない。

### 4. 実行時間の内訳

128K文脈の内訳では事前計算が全体の大部分を占め、復号時間の割合は小さい。APBは重要度推定と圧縮KV通信という追加費用を払うが、注意演算時間の削減がそれを上回る。アンカー複製によりフィードフォワード計算が増える点も観測されるため、GPU間の通信をゼロにしたわけではない。通信と計算の交換関係を同時に評価する必要がある。

## 既存研究との差

RingAttentionとUlyssesは系列並列を使うが、原則として完全注意を保つ。MInferenceは注意演算を疎化するが単一GPUを主対象とする。StarAttentionは冒頭を複製してブロック間通信を避けるが、離れた文脈に固有の情報を見落としやすい。APBは、局所選択した重要KVだけをGPU間へ流すことで、系列並列・近似注意・限定通信を同時に扱う点に特徴がある。

## 限界

APBは近似注意であり、重要度推定器が選ばなかったKVの情報は後段で失われる。RULERのLlama-3.1-8B平均が完全注意より0.57ポイント低いように、すべての評価で厳密な品質同等性が成立するわけではない。特に質問依存の長距離検索では、アンカー・通過KVの予算や学習済み保持ヘッドの分布適合性が品質に影響する。

実験はA800 80GB級GPUを複数枚使う分散構成であり、家庭用単一GPUやCPUオフロードでの効果を直接示さない。速度比較にはGPU枚数・通信方式・モデル規模が含まれる。保持ヘッドには追加学習が必要で、モデルを変更したときの学習費用も考慮すべきである。最終的な有効性は長文文書の事前計算が支配的なワークロードで最も高く、短い会話や復号主体の用途へ同じ倍率を適用できない。


### 再現実験で優先すべき確認点

実装を検証する場合は、完全注意との品質差と、同じGPU枚数での速度差を分けて報告する必要がある。まず128K文脈、系列並列8、アンカー4K、通過2Kという主条件を固定し、モデルとタスクを原著と合わせる。次にアンカーを2K・4K・8K、通過KVを1K・2K・4Kなどへ変更して、通信量、注意演算時間、RULERの複雑検索タスクを同時に記録する。これにより、速度改善が単なる情報削減の結果なのか、分散配置による並列化の結果なのかを切り分けやすい。

評価の際は、全体の入力・出力トークン数を総処理時間で割る論文の速度定義に加え、初回トークンまでの遅延、GPUごとのピークKV使用量、AllGatherの通信時間、重要度推定器の計算時間も記録すると実装上の制約が見える。とくに複数ノードではNVLinkとInfiniBandの帯域差が効くため、ノード内8GPUとノード跨ぎを別の結果として扱う。
