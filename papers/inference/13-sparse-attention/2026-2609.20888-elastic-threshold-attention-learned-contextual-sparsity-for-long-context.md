# Elastic Threshold Attention：長文脈復号のための学習可能な文脈依存疎注意

## 概要

長い入力履歴を保持する自己回帰型大規模言語モデルでは、次の1トークンを生成するたびに過去の鍵・値（Key-Value、KV）キャッシュを参照する。文脈長が伸びると、注意演算そのものに加えて高帯域メモリ（High Bandwidth Memory、HBM）からのKV読み込みが遅延を支配する。スライディング窓や過去の注意頻度に基づく固定的な削除は読み込み量を減らせる一方、後で必要になる離れた情報を捨てる危険がある。さらに、訓練時は全トークンを見ていたモデルを推論時だけ硬く疎化すると、表現分布のずれが生じる。

Elastic Threshold Attention（ETA）は、注意ヘッドごとに現在のクエリから動的な閾値を予測する機構をモデルに組み込み、**訓練時から疎化しやすい注意分布を学習する**。閾値以下のスコアを負の無限大へ送る硬いマスクではなく、ずらしたSiLU型ゲートによってゼロ近傍へ滑らかに圧縮する。これにより小さな注意重みの集合がほぼ一様な背景成分となり、推論時に不要なKVブロックを除去しても表現が大きく変化しないことを狙う。

推論カーネルは、KVブロックの重心、座標別分散、最大ノルムを保持し、現在のクエリがそのブロックへ高い注意を向ける可能性を境界評価する。閾値を超えないと判定されたブロックはHBMから読み込まない。著者らは1.45Bパラメータのモデルを最初から訓練し、密注意と比較して言語モデリングや合成検索課題で近い品質を報告した。H100で256K文脈、バッチ64、KVブロックのグループ化クエリ注意（Grouped-Query Attention、GQA）合併密度16%という条件では、全22層を含むトークン当たり179.13msから83.24msへの短縮、すなわち2.15倍の処理速度を報告する。これは全モデル・全負荷で2.15倍を保証する結果ではない。

## 問題設定と既存方式の限界

対象はデコーダ専用Transformerであり、各時刻tに対する注意スコアは S_ts = q_t·k_s/√d_h である。密注意ではs≤tのすべての過去KVを読む。文脈長Tに比例して復号時のKV読み込みが増え、GPUのHBM帯域が制約になる。理論上の疎化率が高くても、GPUが連続したブロックを効率的に読めなければ、ランダムなトークンアクセスのオーバーヘッドが勝ってしまう。このため本研究では、**トークン単位の重要度と、実際に転送するブロック単位の密度を区別する**。

従来のH2Oは累積注意に基づいて過去トークンを保持し、StreamingLLMは冒頭の注意シンクと近傍窓を保持する。Questはクエリとブロックの座標別最小・最大値からKVページを選ぶ。これらの方式は既存モデルの重みを変更せずに推論を高速化しやすいが、学習時に「不要な注意の尾部を落としてもよい」ことをモデル自身に学習させていない。Native Sparse Attention（NSA）は学習可能な疎注意を提供するものの、複数分岐の設計と実装費用を持つ。ETAは既存の注意演算に少数の閾値予測パラメータを追加し、復号時にはブロック選別をGPU向けに融合する。

本論文は既存の学習済み7B/70Bモデルを無改変で2倍高速化する手法ではない。主たる品質評価は**ETAを組み込んで最初から訓練した1.45Bモデル**であり、学習済み重みへ単純なパッチを当てる方式と区別する必要がある。

## 手法

### 1. クエリ依存の閾値予測

各層ℓの回転位置埋め込み（Rotary Position Embedding、RoPE）適用後の全注意ヘッドのクエリを連結し、軽量な線形写像で各ヘッドの閾値τ_{t,h}を計算する。原著式(1)は τ_t^ℓ = q̄_t^ℓ W_τ^ℓ + b_τ^ℓ であり、出力はその層のH個のヘッドに対応する。RoPE適用後のクエリを使うため、位置情報と複数ヘッド間の連携を反映できる。予測器のパラメータ増加は論文の説明では0.1%未満である。

学習開始時はW_τ=0、バイアスb_τ=−8としてほぼ密注意から出発する。突然強い疎化を適用すると必要な情報が落ちて学習が不安定になるためである。学習の進行に伴い閾値が上がると、普通の次トークン予測では多くのKVを省略し、遠い情報を検索するクエリでは閾値を下げてより広い文脈を参照する。これは固定のtop-k予算ではなく、入力内容に応じて計算予算を変える設計である。

### 2. 訓練時の滑らかなゲートと注意分布の背景成分

スコアSと閾値τに対して、ゲート m = sigmoid(β(S−τ)) を計算する。βは訓練中に1から5へ線形に増やし、初期には勾配を通しやすく、後半には選択境界を鋭くする。自己トークンのマスクは常に1とし、その他のトークンにはS̃ = S·mを適用した後にsoftmaxを計算する。原著はこれをシフトしたSiLU型のロジット圧縮と呼ぶ。

S<τのスコアは一律に削除されるのではなく、正負の値が0近傍へ収縮する。softmaxの指数変換ではexp(0)=1に近い重みの帯ができ、閾値以下の多数のトークンがほぼ一様な「注意の床」を形成する。強いスコアを持つ少数のトークンは相対的に目立ち、低いスコアのトークン群は平坦になる。原著の分析では、尾部の正規化エントロピーが0.790から0.916へ上昇し、最大重み／平均重みの比が15.6から2.03へ低下する。

この背景成分を持つ訓練時の出力と、推論時に背景ブロックを除外した出力の関係を著者は理論化している。重要なKV集合K、重要でないが同じブロック内に入る集合C、読み飛ばされる集合Dに分けると、訓練出力はK∪C∪D、推論出力はK∪Cに対する正規化加重和である。CとDの値ベクトルがほぼ相殺されれば、両者は同じ重要成分の**正のスカラー倍**に近づく。RMS正規化（Root Mean Square Normalization、RMSNorm）は正のスカラー倍に対して不変なので、次層の表現差を小さくできるという説明である。

ただし、この相殺は値ベクトルの統計的な仮定に依存する近似であり、すべての入力で厳密に同じ出力を保証しない。背景値に偏りがある場合、低いスコアのトークンにも重要な意味がある場合、RMSNorm以外の演算が影響する場合には誤差が生じる。原著は訓練時と疎推論時の残差表現の平均コサイン類似度0.9917を報告するが、これも評価したモデル・データでの実測である。

### 3. KVブロックの二重境界とメタデータ

推論では連続するb個のKVを1ブロックとし、各ブロックBの鍵ベクトルについて、重心μ_B、座標ごとの分散σ_B²、最大L2ノルムM_Bを保存する。現在のクエリqに対して、重心との内積と分散から得る確率的な上側評価、Cauchy–Schwarz不等式によるノルム上限の二つを計算し、小さい方をブロックの候補上限として用いる。原著式(7)の形は次の通りである。

Score_dual(q,B) = min(〈q,μ_B〉 + z√Σ_i(q_i²σ_{B,i}²), ||q||₂ M_B)/√d_h

Score_dual<τ̃_tであればブロックをスキップする。ここでτ̃_t=τ_t−αのように安全側の余裕を設けることもできる。ノルム境界は数学的な上限だが、分散に基づく側は統計的な見積もりであり、両者のminを取ると必ず真の最大スコアを上回るという厳密保証にはならない。したがって「重要なトークンを100%取り逃さない」方式ではなく、再現率とHBM読み込み削減のトレードオフを持つ。

ブロック単位の選別では、重要トークンを1個でも含むブロック全体を読み込む。そのため、ヘッド単位で選択したトークンの割合と、GQAで実際に読み込むKVブロックの合併割合は異なる。複数クエリヘッドが同じKVヘッドを共有する場合、転送するブロックはそれらの和集合となる。原著はb=64でメタデータが約1.6%の追加メモリとなると報告している。小さいbは選択精度を上げるが管理費用と不連続アクセスが増え、大きいbは転送効率を上げるが不要トークンを巻き込みやすい。

### 4. Triton融合復号カーネルと安定化

著者らはTritonで復号カーネルを実装し、KVの実体をHBMから読む前にブロックのメタデータをSRAMへロードして境界を評価する。不要なブロックを飛ばすことで、密注意のKV読み込み量に比例する仕事を減らす。独立したチャンクを複数のストリーミングマルチプロセッサへ分配し、各チャンクの部分的なオンラインsoftmaxを結合する。すべての候補が閾値未満になった場合の数値的不安定性を避けるため、最高得点の1ブロックを必ず残すTop-1救済も導入する。

論文の「O(1)ブロック選別」は、**ブロック一つを評価するためにブロック内の全KVを読む必要がない**という意味である。全系列の選別が定数時間になるわけではなく、ブロック数に比例するメタデータ検査が残る。原著はブロック数をceil(n/b)、読み込むブロック数をmとすると、概ねO((ceil(n/b)+m·b)d)の仕事として整理する。選別が重くなる短い文脈や、閾値が低く大半のブロックを読む条件では、密なFlashAttention-2より遅くなりうる。

### 5. オフライン校正による静的閾値

対象業務が固定される場合、学習済みの動的閾値予測器をそのまま実行せず、層・ヘッドごとの定数へ変換する追加手順がある。16系列の校正データで各ヘッドの平均有効密度を測定し、各時刻tの因果的な候補数を揃えるため注意スコアのヒストグラムを1/tで重み付けする。そのヒストグラムに対して、動的予測器と同じ密度になる定数閾値を二分探索で求める。

これはモデルの訓練時から固定閾値を使うこととは異なる。論文では最初から固定閾値を学習すると動的方式より2.13倍の有効密度に収束した。**動的方式で学習した後に校正して固定化する**順序が重要である。126MモデルのC4評価では、1024トークン時の困惑度が動的91.96、校正後91.60、有効密度24.14%から22.40%となり、2048トークン外挿では困惑度100.52対100.48、有効密度44.77%対32.83%だった。ただし校正分布から外れた業務で同じ結果が保証されるわけではない。

### 速度評価の条件と「最大2.15倍」の意味

性能測定はNVIDIA H100 SXM 80GB、float16、バッチ32/64/128、最大512K文脈で行う。表20はバッチ64で22層の注意、注意以外の演算、閾値予測・メタデータ更新を加算したトークン当たり時間を示す。256Kでは密注意の注意演算167.37ms、注意以外11.76ms、計179.13ms。ETA・GQA合併密度16%では注意演算71.22ms、注意以外11.76ms、閾値予測と更新0.26msで83.24msとなる。これはモデル全体の計算時間を積算した比較であり、単独のカーネル速度比ではない。

ただし64Kで合併密度51.2%の場合は53.90msから52.35msで1.03倍にとどまる。疎化してもメタデータ処理や境界判定が相対的に重い場合、利得は小さい。512Kの単独カーネル測定では、ブロックサイズやチャンクサイズによってFlashAttention-2を下回る条件もある。例えば表10のバッチ64・512K・合併密度51.2%ではb=32、c=64のETAは16.617msで、密注意15.085msより遅い。GPU上のブロック粒度と転送密度が決定的である。

### 学習コストと負の比較

ETAは推論時のメモリ帯域を節約するため、訓練中には通常の注意に加えて閾値予測、ゲート、疎性正則化を計算する。付録の測定では、22層の学習ステップ時間は密注意190.6msに対してETA242.8msで約27.4%増える。したがって「推論時の速度向上」だけを比較して学習総費用まで減るとは言えない。

また、同じ126Mモデルを使った硬い加算マスクとの比較では、滑らかなETAのFineWeb困惑度99.80±22.59、計算密度34.09%に対し、硬い方式は116.38±24.38、密度62.74%だった。硬い削除が疎化を促すとは限らず、かえって品質と密度の両方を悪化させるという負の結果である。NSAとの126Mモデル比較では学習条件を揃え、ETAの方が低い訓練損失を報告するが、この小型実験を1.45BでのNSA全機能との優越証明と混同しない。

## 注意シンクと層ごとの自律的な密度配分

標準の密注意では、最初のトークンへ注意が集中する注意シンク（attention sink）が生じ、StreamingLLMなどは先頭トークンを固定保持する。ETAの訓練時の一様な背景成分は、この局所的な注意集中を分散させる。原著の分析では先頭トークンへの注意質量が密注意の50%超から2%未満へ下がる条件を報告する。また第0層は約96%の密度で広く文脈を集約し、中間の第7層は8%未満まで削り、後半の層は必要に応じて密度を回復する。これは全層に同じ削減率を課す設計より柔軟である。

ただし注意シンクの消失は、同じ訓練条件で学習したETAの内部統計についての観測であり、すべてのTransformerで先頭トークンの保持が不要になるという一般法則ではない。さらに、シンクが消えたという可視化と、長文脈検索の品質が維持されたという評価は別の証拠である。

## 実装可能性と他方式との差

Questのような事後的なページ選択では、既存の密注意モデルを利用しやすいが、どの情報が後で必要になるかを学習で適応させない。H2Oや固定窓は過去情報を永久に削除するため、必要な情報の復元が難しい。ETAは学習時に閾値を組み込み、推論時にスコアに応じて読み込むブロックを毎回変える。KVの実体を圧縮して永続的に小さくする方式というより、**HBMから今読むKVを動的に選別する方式**として理解する方が正確である。

原著はメタデータをページ化KVキャッシュに対応させられると記述するが、一般的なvLLMやSGLangの既存バイナリへそのまま差し込める完成プラグインを示したわけではない。Triton融合カーネル、学習済みの閾値予測器、各KVヘッドのメタデータ更新を一体として実装する必要がある。RTX 4070 Super 12GBでの利用についても、論文の主要測定はH100 80GBであり、12GB単体で256K文脈を保持できることや同じ倍率を得られることは示していない。KVキャッシュ容量そのものが不足する場合、別途量子化、オフロード、短い文脈への制限が必要になる。

## 限界・留保

第一に、1.45Bモデルを最初から訓練しているため、既存の大規模な学習済みモデルへ無学習で適用できると解釈できない。第二に、低スコアの値ベクトルが相殺されるという理論は統計的仮定を必要とし、極端な文脈や構造化データで厳密な品質保持を保証しない。第三に、確率的なブロック境界は重要トークンの取り逃しを完全には排除できず、閾値の余裕を大きくすると転送量が増える。第四に、GQA合併密度が大きい場合や短い文脈では高速化が小さく、選別処理の方が重くなる条件がある。

第五に、長文脈の品質評価は主に2048～8192トークンの言語モデリング・合成検索であり、512Kまでの性能表は主に計算速度の測定である。第六に、校正後の固定閾値は校正した分布に依存し、業務分布が変わると動的方式の利点を失いうる。第七に、学習時のカーネル追加費用は約27.4%で、推論での節約を訓練コストと切り離して評価する必要がある。第八に、密注意・Quest・NSAとの比較はモデル規模、予算、ブロックサイズ、再現率が必ずしも完全一致していない。単一の速度倍率や困惑度だけで総合的な優劣を決めるべきではない。
