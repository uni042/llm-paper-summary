# Mixture of Attention Spans: Optimizing LLM Inference Efficiency with Heterogeneous Sliding-Window Lengths

> headごとの局所性と入力長への伸び方をgradientで測り、異種sliding-window規則を自動探索して静的KV maskへ落とすMoA。

## 概要

長文脈LLMでは、decodeのたびに各attention headが過去のKey/Valueを読むため、文脈長が伸びるほどKVキャッシュ容量とmemory bandwidthが増える。Sliding-window attentionは「直近W tokenだけを見る」という固定maskを使い、Wより古いKVを捨てることで容量とattention計算を減らす。maskが静的なので、H2Oのような実行時importance選択よりGPUで規則的に実装しやすい。

しかし全headへ同じWを与えると、LLM内部の役割差を無視する。あるheadは句法や近距離依存だけを見るため小windowで十分だが、別headは文書前半の名前・数値などを遠距離から検索する。前者へ長いwindowを与えるのはKV予算の浪費で、後者を同じ短windowへ切ると長文検索能力が崩れる。

さらに入力が4K→16K→64Kと伸びたとき、「必要windowも比例して伸びるhead」と「数百tokenのlocal spanで十分なhead」が混在する。単一window長を入力長に合わせて一律拡大するだけでも、この差は使えない。

Mixture of Attention Spans（MoA）は、**各layer・各headに別々のattention spanと、そのspanを入力長に応じてどう伸ばすかというelastic ruleを持たせる**。実行時にimportanceを計算するのではなく、事前にgradient-based profilingを行い、density（平均KV保持率）制約の下でloss増加が小さいruleの組合せをmixed-integer optimizationで探索する。

50% densityではVicuna 7B/13BとLlama3 8B/70Bでfull attentionに近い長文性能を維持し、7B/13Bのdecode throughputをdense FlashAttention2比6.6〜8.2倍改善する。25% densityでもheterogeneous heads + elastic rulesにより8K retrieval accuracyをuniform windowの25%から98%へ上げる例を示す。

## 問題設定

### 「固定windowはGPUに優しい」が「全head同じwindow」は粗い

動的KV pruningは、各requestのattention scoreなどを見て重要tokenを残せる反面、score計算、indexing、gather/scatter、KV swapなどが追加される。理論的に少ないtokenを読んでも、GPU上で不規則なアクセスが増えるとwall-clock speedupを得にくい。

静的sliding windowは、各headが見る範囲を事前に決められるためcontiguousなKV領域と専用kernelを使いやすい。しかしStreamingLLM型のuniform spanでは、50% windowを残しても入力前半を必要とするglobal headまで半分へ切られる。

論文の観察では、uniform 50% spanはeffective context lengthをspan以上へほとんど延ばせず、長い入力の前半retrievalに失敗する。一方attention mapを見ると、局所headと全域headが明確に混在する。MoAは「動的に重要tokenを探す」のではなく、**静的maskのままhead間の非均一性を使う**。

### Effective context lengthとは何か

MoAは単に「設定上64K contextを受け付けるか」ではなく、long-context retrieval accuracyが90%以上を保てる最大input lengthを**effective context length**として使う。

KVを50%しか残さなくても、global headへ十分なspanを集中できれば、平均KV長よりはるかに長い入力から情報を取れる可能性がある。MoAではeffective contextが平均KV spanの約3.9倍まで伸びる結果を報告する。

## 手法

### 1. Elastic Rule — headのwindowを入力長の関数にする

MoAでは各attention head hに、input length Nからattention spanを計算するruleを割り当てる。ruleは概念的に固定項とNに比例する項を持ち、短いinputでは小さく、長くなると一定割合で伸びるspanも表現できる。

例えば「常に直近1K程度を見るlocal head」と「入力の50%程度を見るglobal head」を同じmodel内に共存させられる。各headへ単一数値Wを保存するだけではなく、**長さが変わったときの伸び方**まで探索対象にするのがelasticの意味である。

maskにはwindowに加えて少数のinitial unmasked tokensも含められる。各headのmaskは独立にattention computationと対応KV cacheをgateし、複数headのmaskを順次適用するわけではない。

### 2. Attention Influence Profiling — どの位置を切るとlossが増えるか測る

全rule候補を実際に長文benchmarkで総当たりすると高価なので、まず校正データでattention位置の重要度を近似する。

MoAはfull-attention modelのattention outputにmask perturbationを与えたとき、prediction lossがどれほど変わるかをgradientから推定する。これにより「このheadの古い位置を削るとlossへの影響が大きい／小さい」をruleごとにスコア化する。

このprofilingはruntimeには入らない。最終的に選ばれたmaskは静的なので、実推論ではgradientやimportance scoreを計算せず、決められたspanだけを読む。

### 3. 校正データをlong-context目的へ合わせる

一般的なcompressionではRedPajamaのようなlanguage-modeling corpusを校正へ使うことが多い。しかしlocal next-token prediction中心のデータでは、遠距離tokenを必要とするattention headの重要度を十分評価できない。

MoAは複数文書を横断してsummaryを作るMultiNewsを使い、長距離依存を校正へ入れる。さらにhuman-written summaryではなく**元のdense model自身が生成したsummary**を教師にする。

これは「圧縮後modelが元modelの挙動を保つ」という目的に合わせるためである。人間回答が“Blue”でも元modelが“The blue color”と出すなら、人間answerを教師にしたgradientは元modelの最初のtoken“The”を守る重要度とずれる。model-generated supervisionはこのalignment mismatchを減らす。

50 items・8K条件のablationでは、RedPajamaでretrieval 0.25だった設定が、MultiNews long-range summaryで0.87、さらにdense model自身のsummaryを教師にすると0.95へ改善した。

### 4. Mixed-Integer Search — density予算をglobal headへ集中する

各headには複数elastic rule候補がある。MoAは各profiling lengthで予測されるloss増加を目的関数とし、平均attention densityが指定予算以下になる制約でruleを選ぶ。

この問題をmixed-integer programmingとして解き、Pareto-optimal候補から未使用のvalidation lengthでlossが最小のconfigurationを選ぶ。主設定では2K/4K/8Kでprofileし、12Kでvalidationする。

推論kernelの複雑さを抑えるため、1 layer内のdistinct rule数を最大2種類へ制限する。理論上headごと完全に異なるwindowを許すより探索自由度は下がるが、GPU実装で同じmask shapeをまとめやすくするためのsystem constraintである。

### 5. 一度探索したconfigurationを全requestへ固定適用する

MoAはrequestごとにimportanceを再計算しない。modelごとに探索したhead/layer ruleを、benchmarkやinput lengthが変わっても同じconfigurationとして使う。

そのためruntime overheadは主に短いKVと少ないattention FLOPsだけで、動的score計算やKV retrievalを必要としない。長さNが変わればelastic ruleからwindowだけを計算し直す。

## 評価

### 代表的な評価条件

| 項目 | 内容 |
|---|---|
| models | Vicuna-7B/13B-16K、Llama3-8B/70B-262K |
| retrieval | LongEval |
| long-context understanding | LV-Eval、LongBench-E |
| perplexity | Qasper、MultiNews、TREC、LCC |
| calibration | MultiNews + dense-model summaries |
| profiling lengths | 2K / 4K / 8K |
| validation | 12K |
| density | 主に50%、ablationで25% |
| efficiency GPU | A100-80GB |
| baseline | StreamingLLM、H2O、InfLLM、dense FlashAttention2等 |

Densityはdecode時に保持する平均KV length / sequence lengthである。50% densityなら「全headが50%を見る」とは限らず、MoAではglobal headへ多く、local headへ少なく割り当てた平均が50%になる。

### 25% densityでのsearch-space ablation

| mask設計 | 8K retrieval | 16K retrieval | PPL 8K |
|---|---:|---:|---:|
| Uniform | 0.25 | 0.15 | 4.89 |
| + heterogeneous layers | 0.31 | 0.26 | 4.55 |
| + heterogeneous heads | 0.95 | 0.41 | 3.96 |
| + elastic rules | 0.98 | 0.43 | 3.96 |

layer差だけでは改善が小さく、**head単位のheterogeneity**を入れたところでretrievalが大幅に回復する。elastic ruleは入力長変化へのgeneralizationをさらに加える。

### Full attentionに対する品質

50% densityでLlama3-8Bはretrieval accuracyが4K/8K/16Kで0.99/1.00/1.00となり、full attentionの0.99/0.99/0.97と同等域である。Llama3-70Bも16KでMoA 0.94、full 0.93となる。

全model/lengthの平均relative retrieval dropは1%未満で、StreamingLLM等より小さい。8Kまでのprofilingと12K validationだけで、Llama3-8Bを32K〜256Kへ伸ばした評価でもdense modelに近い結果を維持した。

### throughputは何から出るか

7Bの4K条件ではdense FlashAttention2が134.6 tokens/s、静的KVだけで496.1、attention計算削減で722.5、メモリ余裕からbatchを30→50へ増やして897.7、専用kernelを加えたMoAで1099.0 tokens/sとなる。

つまり6.6〜8.2倍のheadline speedupは、単一要因ではなく
1. KV cacheを静的に短くする、
2. attention計算を減らす、
3. 空いたHBMでbatchを増やす、
4. heterogeneous span向けkernelを使う、
という複数の利得の積である。

## 既存研究との差

StreamingLLMは静的でGPU-friendlyだが全headへほぼ同じlocal spanを使う。H2O/InfLLMはrequestごとに重要KVを動的選択できる一方、importance計算やdense prefill、retrievalなど追加runtime costがある。

MoAは**静的maskの実装効率を保ちながら、headごとのglobal/local役割とinput-length scalingをoffline searchで埋め込む**。dynamic selectionとuniform static windowの中間に位置する。

## 限界

configurationは校正データで観測したattention influenceに依存する。long-range dependencyを含まない校正データや、元modelの生成分布とずれた教師を使うと性能が大きく落ちることを論文自身が示している。

またmodelごとに数時間規模のprofiling/searchが必要で、weightsを更新した場合は再探索が必要になる。主例ではVicuna-13Bで約2時間とされる。

静的maskなので、通常はlocal headだが特定requestだけ遠距離参照を必要とする、といった入力依存の例外には動的KV selectionほど細かく追随できない。50% densityや6.6〜8.2倍という値もA100・最大batch条件の結果であり、低batch latency中心の運用では利得構成が変わる。
