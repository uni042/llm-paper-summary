# Mixture of Attention Spans: Optimizing LLM Inference Efficiency with Heterogeneous Sliding-Window Lengths

> ヘッドごとの局所性と入力長への伸び方を勾配で測り、異種sliding-window規則を自動探索して静的KV maskへ落とすMoA。

## 概要

長文脈LLMでは、デコードのたびに各注意機構 ヘッドが過去のKey/Valueを読むため、文脈長が伸びるほどKVキャッシュ容量とメモリ 帯域が増える。Sliding-window 注意機構は「直近W トークンだけを見る」という固定maskを使い、Wより古いKVを捨てることで容量と注意機構計算を減らす。maskが静的なので、H2Oのような実行時importance選択よりGPUで規則的に実装しやすい。

しかし全ヘッドへ同じWを与えると、LLM内部の役割差を無視する。あるヘッドは句法や近距離依存だけを見るため小windowで十分だが、別ヘッドは文書前半の名前・数値などを遠距離から検索する。前者へ長いwindowを与えるのはKV予算の浪費で、後者を同じ短windowへ切ると長文検索能力が崩れる。

さらに入力が4K→16K→64Kと伸びたとき、「必要windowも比例して伸びるヘッド」と「数百トークンの局所 spanで十分なヘッド」が混在する。単一window長を入力長に合わせて一律拡大するだけでも、この差は使えない。

Mixture of Attention Spans（MoA）は、**各層・各ヘッドに別々の注意機構 spanと、そのspanを入力長に応じてどう伸ばすかというelastic ruleを持たせる**。実行時にimportanceを計算するのではなく、事前に勾配-based プロファイリングを行い、density（平均KV保持率）制約の下でloss増加が小さいruleの組合せをmixed-integer optimizationで探索する。

50% densityではVicuna 7B/13BとLlama3 8B/70Bで全体 注意機構に近い長文性能を維持し、7B/13Bのデコード スループットを密 FlashAttention2比6.6〜8.2倍改善する。25% densityでもheterogeneous heads + elastic rulesにより8K 検索 accuracyをuniform windowの25%から98%へ上げる例を示す。

## 問題設定

### 「固定windowはGPUに優しい」が「全head同じwindow」は粗い

動的KV 枝刈りは、各リクエストの注意機構 スコアなどを見て重要トークンを残せる反面、スコア計算、indexing、gather/scatter、KV swapなどが追加される。理論的に少ないトークンを読んでも、GPU上で不規則なアクセスが増えると実時間 高速化倍率を得にくい。

静的sliding windowは、各ヘッドが見る範囲を事前に決められるためcontiguousなKV領域と専用カーネルを使いやすい。しかしStreamingLLM型のuniform spanでは、50% windowを残しても入力前半を必要とする大域 ヘッドまで半分へ切られる。

論文の観察では、uniform 50% spanはeffective 文脈 lengthをspan以上へほとんど延ばせず、長い入力の前半検索に失敗する。一方注意機構 mapを見ると、局所ヘッドと全域ヘッドが明確に混在する。MoAは「動的に重要トークンを探す」のではなく、**静的maskのままヘッド間の非均一性を使う**。

### Effective context lengthとは何か

MoAは単に「設定上64K 文脈を受け付けるか」ではなく、long-文脈 検索 accuracyが90%以上を保てる最大入力 lengthを**effective 文脈 length**として使う。

KVを50%しか残さなくても、大域 ヘッドへ十分なspanを集中できれば、平均KV長よりはるかに長い入力から情報を取れる可能性がある。MoAではeffective 文脈が平均KV spanの約3.9倍まで伸びる結果を報告する。

## 手法

### 1. Elastic Rule — headのwindowを入力長の関数にする

MoAでは各注意機構 ヘッド hに、入力 length Nから注意機構 spanを計算するruleを割り当てる。ruleは概念的に固定項とNに比例する項を持ち、短い入力では小さく、長くなると一定割合で伸びるspanも表現できる。

例えば「常に直近1K程度を見る局所 ヘッド」と「入力の50%程度を見る大域 ヘッド」を同じモデル内に共存させられる。各ヘッドへ単一数値Wを保存するだけではなく、**長さが変わったときの伸び方**まで探索対象にするのがelasticの意味である。

maskにはwindowに加えて少数のinitial unmasked トークンも含められる。各ヘッドのmaskは独立に注意機構 computationと対応KV キャッシュをゲートし、複数ヘッドのmaskを順次適用するわけではない。

### 2. Attention Influence Profiling — どの位置を切るとlossが増えるか測る

全rule候補を実際に長文ベンチマークで総当たりすると高価なので、まず校正データで注意機構位置の重要度を近似する。

MoAは全体-注意機構 モデルの注意機構 出力にmask perturbationを与えたとき、予測 lossがどれほど変わるかを勾配から推定する。これにより「このヘッドの古い位置を削るとlossへの影響が大きい／小さい」をruleごとにスコア化する。

このプロファイリングはランタイムには入らない。最終的に選ばれたmaskは静的なので、実推論では勾配やimportance スコアを計算せず、決められたspanだけを読む。

### 3. 校正データをlong-context目的へ合わせる

一般的なcompressionではRedPajamaのようなlanguage-modeling corpusを校正へ使うことが多い。しかし局所 next-トークン 予測中心のデータでは、遠距離トークンを必要とする注意機構 ヘッドの重要度を十分評価できない。

MoAは複数文書を横断してsummaryを作るMultiNewsを使い、長距離依存を校正へ入れる。さらにhuman-written summaryではなく**元の密 モデル自身が生成したsummary**を教師にする。

これは「圧縮後モデルが元モデルの挙動を保つ」という目的に合わせるためである。人間回答が“Blue”でも元モデルが“The blue color”と出すなら、人間answerを教師にした勾配は元モデルの最初のトークン“The”を守る重要度とずれる。モデル-generated supervisionはこのalignment mismatchを減らす。

50 items・8K条件のablationでは、RedPajamaで検索 0.25だった設定が、MultiNews long-range summaryで0.87、さらに密 モデル自身のsummaryを教師にすると0.95へ改善した。

### 4. Mixed-Integer Search — density予算をglobal headへ集中する

各ヘッドには複数elastic rule候補がある。MoAは各プロファイリング lengthで予測されるloss増加を目的関数とし、平均注意機構 densityが指定予算以下になる制約でruleを選ぶ。

この問題をmixed-integer programmingとして解き、Pareto-optimal候補から未使用のvalidation lengthでlossが最小のconfigurationを選ぶ。主設定では2K/4K/8Kでprofileし、12Kでvalidationする。

推論カーネルの複雑さを抑えるため、1 層内のdistinct rule数を最大2種類へ制限する。理論上ヘッドごと完全に異なるwindowを許すより探索自由度は下がるが、GPU実装で同じmask 形状をまとめやすくするためのシステム constraintである。

### 5. 一度探索したconfigurationを全requestへ固定適用する

MoAはリクエストごとにimportanceを再計算しない。モデルごとに探索したヘッド/層 ruleを、ベンチマークや入力 lengthが変わっても同じconfigurationとして使う。

そのためランタイム オーバーヘッドは主に短いKVと少ない注意機構 FLOPsだけで、動的スコア計算やKV 検索を必要としない。長さNが変わればelastic ruleからwindowだけを計算し直す。

## 評価

### 代表的な評価条件

| 項目 | 内容 |
|---|---|
| models | Vicuna-7B/13B-16K、Llama3-8B/70B-262K |
| 検索 | LongEval |
| long-文脈 understanding | LV-Eval、LongBench-E |
| パープレキシティ | Qasper、MultiNews、TREC、LCC |
| calibration | MultiNews + 密-モデル summaries |
| プロファイリング lengths | 2K / 4K / 8K |
| validation | 12K |
| density | 主に50%、ablationで25% |
| 効率 GPU | A100-80GB |
| 比較対象 | StreamingLLM、H2O、InfLLM、密 FlashAttention2等 |

Densityはデコード時に保持する平均KV length / 系列 lengthである。50% densityなら「全ヘッドが50%を見る」とは限らず、MoAでは大域 ヘッドへ多く、局所 ヘッドへ少なく割り当てた平均が50%になる。

### 25% densityでのsearch-space ablation

| mask設計 | 8K 検索 | 16K 検索 | PPL 8K |
|---|---:|---:|---:|
| Uniform | 0.25 | 0.15 | 4.89 |
| + heterogeneous 層 | 0.31 | 0.26 | 4.55 |
| + heterogeneous heads | 0.95 | 0.41 | 3.96 |
| + elastic rules | 0.98 | 0.43 | 3.96 |

層差だけでは改善が小さく、**ヘッド単位のheterogeneity**を入れたところで検索が大幅に回復する。elastic ruleは入力長変化へのgeneralizationをさらに加える。

### Full attentionに対する品質

50% densityでLlama3-8Bは検索 accuracyが4K/8K/16Kで0.99/1.00/1.00となり、全体 注意機構の0.99/0.99/0.97と同等域である。Llama3-70Bも16KでMoA 0.94、全体 0.93となる。

全モデル/lengthの平均relative 検索 dropは1%未満で、StreamingLLM等より小さい。8Kまでのプロファイリングと12K validationだけで、Llama3-8Bを32K〜256Kへ伸ばした評価でも密 モデルに近い結果を維持した。

### throughputは何から出るか

7Bの4K条件では密 FlashAttention2が134.6 トークン/s、静的KVだけで496.1、注意機構計算削減で722.5、メモリ余裕からバッチを30→50へ増やして897.7、専用カーネルを加えたMoAで1099.0 トークン/sとなる。

つまり6.6〜8.2倍のheadline 高速化倍率は、単一要因ではなく
1. KV キャッシュを静的に短くする、
2. 注意機構計算を減らす、
3. 空いたHBMでバッチを増やす、
4. heterogeneous span向けカーネルを使う、
という複数の利得の積である。

## 既存研究との差

StreamingLLMは静的でGPU-friendlyだが全ヘッドへほぼ同じ局所 spanを使う。H2O/InfLLMはリクエストごとに重要KVを動的選択できる一方、importance計算や密 プリフィル、検索など追加ランタイム コストがある。

MoAは**静的maskの実装効率を保ちながら、ヘッドごとの大域/局所役割と入力-length scalingをoffline searchで埋め込む**。動的 selectionとuniform 静的 windowの中間に位置する。

## 限界

configurationは校正データで観測した注意機構 influenceに依存する。long-range 依存関係を含まない校正データや、元モデルの生成分布とずれた教師を使うと性能が大きく落ちることを論文自身が示している。

またモデルごとに数時間規模のプロファイリング/searchが必要で、重みを更新した場合は再探索が必要になる。主例ではVicuna-13Bで約2時間とされる。

静的maskなので、通常は局所 ヘッドだが特定リクエストだけ遠距離参照を必要とする、といった入力依存の例外には動的KV selectionほど細かく追随できない。50% densityや6.6〜8.2倍という値もA100・最大バッチ条件の結果であり、低バッチ 遅延中心の運用では利得構成が変わる。
