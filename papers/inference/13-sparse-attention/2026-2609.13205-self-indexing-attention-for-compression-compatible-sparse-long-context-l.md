# Self-Indexing Attention for Compression-Compatible Sparse Long-Context LLM Inference

> 変換領域keyの符号1-bitをprefill・decode共通の自己索引として使い、追加indexerなしで疎注意検索と低ビットKV圧縮を同居させる。

## 概要

長文脈の疎注意では、prefill時に多数queryをまとめて処理する検索と、decode時に1ステップずつ過去KVから候補を探す検索で要求が異なる。既存方式は段階ごとに別の索引器や要約を持つことが多く、索引用メタデータが増え、さらにKVを低ビット圧縮すると検索用表現との整合が難しくなる。

Self-Indexing
Attentionはkeyを共有変換領域へ写し、その各次元の符号だけを1-bit索引として保存する。符号ベクトルはビット演算で類似候補を高速に絞り込め、同じ表現をprefillとdecodeの両方で再利用できる。元の変換領域key/valueはTurboQuant等で別途低ビット圧縮できるため、検索索引のために高精度keyコピーを追加保持する必要がない。

attention density 5%の設定でLongBenchとRULERの品質をdense
attentionに近く保ち、同じ実行スタックのdense基準に対して、バッチ1のprefillは8Kで3.7倍、64Kで6.1倍、decodeは64K・バッチ8で10.3倍のattention演算高速化を示す。

## 問題設定

prefillではquery群が既知なので、ブロックやグループ単位で検索候補をまとめれば索引費用を償却できる。一方decodeでは新しいqueryが逐次到着するため、低遅延のトークン検索が必要になる。この差から、段階別の検索構造を持つ設計が生まれる。

しかしKV圧縮も同時に使うと、検索器が高精度keyや独自射影を要求し、圧縮で減らしたメモリを索引メタデータが食い戻す。Self-Indexing
Attentionは「検索用索引をKV自身から取り出せる表現」に変えることで、二つの推論段階と圧縮を統合する。

## 手法

### 変換領域の符号・大きさ分解

keyを直交的な変換領域へ写すと、各成分を符号と大きさに分けられる。Self-Indexing
Attentionは符号ビットを検索索引として使い、大きさ側は通常の低ビット量子化へ渡せる。索引は各次元1
bitなので、別の浮動小数点埋め込みを保持する方式より小さい。

queryにも同じ変換を適用し、符号一致をビット演算で評価する。符号は近似的な方向一致を表すため、候補選択の安価な第一段として機能する。候補を絞った後だけ実際の疎attentionを計算する。

### prefillとdecodeで同じ索引を再利用

prefillではqueryをグループ化し、グループ代表とkey符号の一致から必要トークンを選ぶ。多数queryを一括処理することで索引走査の固定費を共有する。

decodeでは現在queryの符号から過去keyの1-bit索引を直接検索する。同じkey表現を使うため、prefill終了時に別のdecode索引を再構築する必要がない。段階境界で索引形式を変換しないことが、長文脈でのメモリと実装複雑性の削減につながる。

### 圧縮との合成

符号ビットは検索に残し、変換後の大きさ成分はTurboQuantのような低ビットKV圧縮へ渡せる。したがって「疎化で読むトークン数を減らす」と「各トークンのKV
bytesを減らす」を別軸で組み合わせられる。

論文はDeepSeekV4-Flashの学習済み疎注意indexerとも比較・組合せを行い、専用indexerを学習しなくても自己索引が実用的な検索品質を持つことを示す。

## 既存研究との差

既存疎注意は、prefill向けのブロック選択とdecode向けの索引を別々に設計しがちである。また、検索精度を上げるため学習済みindexerや高精度の補助keyを持つ方式は、KV量子化とメモリ削減効果が競合する。

Self-Indexing
Attentionはkey自身の符号を索引にするため、索引器を独立したモデル状態として持たない。検索と圧縮が同じ変換表現を共有する点が中心的な差であり、圧縮方式そのものを新規提案する論文ではない。

## 限界

1-bit符号は候補検索の近似であり、最終attentionを置き換えるものではない。densityを下げすぎれば必要トークンを落とし、品質低下が増える。性能利得も文脈長・バッチ・候補密度に依存する。

最大10.3倍という値はattention演算子の速度であり、モデル全体の生成スループット倍率ではない。MLP、通信、スケジューリングなど他の時間が残るため、システム全体の利得はattention比率によって小さくなる。
