# Token Sparse Attention：層ごとにトークンを再選択できる疎注意

## 概要

Token Sparse Attentionは、長文脈のプリフィルで注意計算の対象トークンを減らすが、元の系列からトークンを永久に捨てない方式である。各注意ヘッドが独自の重要トークン集合を選び、その集合に対応するQ/K/Vだけを集めて短い系列で注意演算を実行する。得られた短い出力は元の系列長へ散布して残差接続へ足すため、今回の注意演算で選ばれなかったトークンも、次層の入力状態として残る。この「圧縮→注意→復元」の繰り返しにより、ヘッドと層で変わるトークン重要度に追随できる。

論文はToken Sparse Attentionを既存のFlashAttention、Minference、FlexPrefillへ追加して評価する。LLaMA-3.1-8B-InstructのRULERでは、FlashAttentionの128K注意処理を基準とする速度が1.00倍から1.36倍となり、平均正答率は87.01%から87.02%とほぼ不変だった。FlexPrefillでは2.44倍から2.76倍へ改善し、平均正答率87.27%は変わらない。これは128Kにおける**注意演算の平均遅延**から求めた速度比であり、プリフィル以外のFFN、KVメモリ管理、トークン生成まで含むエンドツーエンドの倍率ではない。

## 問題設定：恒久的なトークン破棄とブロック疎性の限界

長文脈のプリフィルでは系列長Lに対する注意行列がL×Lとなる。FlashAttentionはメモリ入出力と演算配置を改善するが、密な注意の計算量そのものは二次のままである。MinferenceやFlexPrefillのようなブロック疎注意は演算する注意領域を減らすが、重要トークンが含まれるブロックに無関係なトークンも同居すると、ブロック単位の計算が残る。逆にFastKVやGemFilterなどのトークン破棄方式は、ある層で不要と判断したトークンを以降の層から取り除くため、後で重要になるトークンを回復できない。

著者らはLLaMA-3.1-8B-Instructで、各層の重要トークン上位1%の重複率を調べた。Figure 2(a)では近い層同士には重複があるが、離れた層では重複が急速に減る。Figure 2(b)では同じ第18層でもヘッドごとに上位トークンの順位が異なる。したがって、早い層で選んだ一つのトークン集合を全層・全ヘッドで使い回すのは不適切である。提案手法は「今の注意計算では使わない」と「モデルの状態から削除する」を区別することで、この問題を避ける。

## 手法

### 1. ヘッドごとのQ/K/V圧縮と出力の復元

注意ヘッドhについて、長さLの系列から重要トークンの添字集合S_hを選ぶ。Q、K、Vの各テンソルから同じ添字に対応する行をgatherし、長さL'の連続したQ̂、K̂、V̂を構成する。注意計算はこの小さい密テンソル上で行われ、演算量の主項はO(L²d)からO(L'²d)へ減る。重要なのは、疎なL×L行列を直接GPUへ渡すのではなく、短い**密な**行列を作ることで既存のFlashAttentionカーネルを変更せず使える点である。

注意の出力Ôは長さL'なので、各ヘッドの選択添字S_hを使ってゼロ初期化した長さLの出力へscatterする。選ばれなかった位置の注意出力はゼロだが、その後に元の残差接続を足すため、入力側のトークン状態は残る。次層ではこの完全な系列から新たなS_hを選べる。ここでいう「復元」は削った注意結果を補間・推定することではない。出力テンソルの位置を復元し、残差経路を通じて未選択トークンの表現を保持することを意味する。

各ヘッドが別々のS_hを使えるため、同じ層でも局所検索を担当するヘッドと長距離依存を担当するヘッドが異なるトークン集合を参照できる。反面、QKVのgather、選択添字の生成、出力scatterには追加のメモリ転送とカーネルが必要になる。L'がLに近い短文脈や重要トークンが広く分布する入力では、注意削減の利得がこの追加費用を上回らない可能性がある。

### 2. 最近のクエリを用いたDynamic Token Coverage

各ヘッドでどのトークンを残すかを決めるため、直近の少数クエリと全キーから軽量な注意近似行列を作る。クエリ方向の注意重みを合計・プーリングした値を、そのヘッドのトークン重要度s_h[t]とする。実装はTritonで採点処理を融合し、追加のメモリ入出力を減らす。全ヘッドの重要度を合計して系列全体で正規化すると、層としての注意質量分布s_l[t]が得られる。

保持数を固定比率で決めるのではなく、重要度の小さいトークンから並べて、累積注意質量が閾値τへ達するまでの低重要度側の集合を削減対象として数える。Algorithm 1では削減数k_sparseを求め、保持数k_keep=L-k_sparseとする。その後、実際に残すトークンは各ヘッドのs_hを用いて上位k_keep個を独立に選ぶ。すなわち保持**数**はヘッドをまとめた層レベルの分布から、保持する**添字**はヘッドごとの分布から決める。この二段階の設計により、同じ計算予算でヘッドの専門性を残せる。

閾値τは重要度の低い尾部へ許容する注意質量に相当し、大きくすると削減が強まる。論文の主実験ではLLaMAにτ=0.005、Mistralにτ=0.008を使い、感度評価では0.010も調べる。注意質量分布が鋭い場合は多くの低重要度トークンを削れるが、分布が平坦な場合は少なくしか削れない。入力や層によって削減率が自動的に変わる点が、固定50%削減のような単純な方式との差である。

### 3. 層間表現ドリフトによる適用層の制限

トークンのgather/scatterを全層で行うと、表現が急激に変化する層では必要な情報を落とし、精度が大きく悪化する。そこで各層ℓの入力隠れ状態hℓ,tと次層の状態hℓ+1,tの差のL2ノルムを、元の状態のノルムで正規化した平均値Rℓを計算する。Rℓが小さいほどその層では表現の変化が少なく、注意演算の一部を省略しても影響が比較的小さいとみなす。

Figure 4ではランダムに3層を選んで疎注意を適用する実験を200回繰り返し、平均ドリフトが小さい層の組ほどRULERの4K評価で精度が高い傾向を確認する。実運用では各層のドリフトを順位化し、下位半分に相当するδ=0.5の安定層だけを疎注意対象にする。これはモデルごとの事前処理で一度決める。トークン選択は入力ごと・ヘッドごとに動的だが、疎化する**層集合**はこの評価では事前に固定される。

ドリフトは注意の出力品質を完全に予測する量ではない。低ドリフトでも特定のトークンを落とせば検索問題の正答が変わりうるし、別モデルへ同じ層番号を転用することはできない。したがってドリフトによる層選択と注意質量によるトークン選択は、異なる誤差源に対応する二つの独立した判断である。

## 評価条件

| 項目 | 一次論文の条件 |
|---|---|
| モデル | LLaMA-3.1-8B-Instruct、Mistral-Nemo-12B-Instruct |
| GPU | NVIDIA A100 80GB ×1 |
| 主評価 | RULER（4K/8K/16K/32K/64K/128K）、InfiniteBench。補助評価はLongBenchとNeedle-in-a-Haystack |
| 密注意 | FlashAttention |
| 疎注意との組合せ | Minference（Vertical-Slash）、FlexPrefill（γ=0.95） |
| 比較する恒久破棄 | PyramidInfer、FastKV、GemFilter |
| 選択実装 | 最近のクエリからの採点をTritonで融合、ヘッド別QKV gather・出力scatter、ドリフト下位50%の層へ適用 |
| 主τ | LLaMA 0.005、Mistral 0.008。感度評価に0.010 |
| 速度指標 | 128Kで全層の注意演算の平均遅延から求めたFlashAttention比。デコードは標準密注意のまま |

ここでRULERは長文脈検索・理解の課題群を含み、表の平均値は各文脈長での正答率を集計したものである。論文の「attention speedup」はFFNを含むモデル全体の処理量やサービングSLOを直接表さない。特にデコード側のKV圧縮を行う方式と同じ尺度で比較してはならない。

## 主要結果

### 既存注意カーネルとの組合せ

| RULERの条件 | 128K注意速度比 | 4K正答率 | 128K正答率 | 全長平均正答率 |
|---|---:|---:|---:|---:|
| LLaMA-3.1-8B FlashAttention | 1.00倍 | 95.82 | 74.15 | 87.01 |
| 同＋Token Sparse | 1.36倍 | 96.06 | 73.68 | 87.02 |
| LLaMA Minference | 1.12倍 | 93.46 | 73.63 | 86.49 |
| 同＋Token Sparse | 1.38倍 | 93.05 | 72.18 | 86.05 |
| LLaMA FlexPrefill | 2.44倍 | 95.48 | 73.75 | 87.27 |
| 同＋Token Sparse | 2.76倍 | 95.33 | 73.58 | 87.27 |
| Mistral-Nemo FlashAttention | 1.00倍 | 95.19 | 19.68 | 67.60 |
| 同＋Token Sparse | 1.22倍 | 95.07 | 19.44 | 67.37 |
| Mistral-Nemo FlexPrefill | 1.22倍 | 94.79 | 20.54 | 68.16 |
| 同＋Token Sparse | 1.33倍 | 94.84 | 19.58 | 67.91 |

Table 1では、同じRULERの平均正答率が維持されても、個別の長さでは低下がある。例えばLLaMAのMinference＋Token Sparseは平均86.49→86.05、128Kは73.63→72.18へ悪化する。MistralのFlexPrefill＋Token Sparseでも128Kは20.54→19.58へ低下する。従って「精度劣化ゼロ」ではなく、指定した閾値・層集合で平均的な差が小さいと解釈すべきである。

InfiniteBenchのTable 2でも、LLaMAのFlashAttention平均50.86に対してToken Sparse追加後50.88とほぼ同等だが、Minferenceは50.16→49.70、FlexPrefillは49.53→49.23へわずかに低下する。MistralではFlashAttention平均22.93→22.80、FlexPrefill24.80→24.08となる。全てのデータセットで改善するわけではなく、検索と推論の課題ごとに差が出る。

### 動的予算と固定予算の比較

| LLaMA、RULER | 注意行列疎性 | 平均正答率 | 128K注意速度比 |
|---|---:|---:|---:|
| 動的τ=0.005 | 54.44% | 87.02 | 1.36倍 |
| 動的τ=0.010 | 67.36% | 86.84 | 1.51倍 |
| 固定疎性s=0.3 | 50.96% | 86.91 | 1.32倍 |
| 固定疎性s=0.5 | 74.95% | 85.43 | 1.57倍 |

Table 4は疎性と速度が近い条件を対比している。疎性が約50%の固定方式より動的τ=0.005のほうが平均正答率が高く、さらに高疎性側では固定方式の精度低下が大きい。これは削減するトークン数を一定にせず、注意質量の尾部に応じて可変にする設計を支持する。ただしτ=0.010では平均86.84へ下がり、疎化の強化に品質費用が伴うことも示される。

Table 3ではτ=0.005の注意行列疎性が4Kで17.00%、32Kで28.44%、128Kで54.44%へ増える。τ=0.010ではそれぞれ28.02%、41.25%、67.36%となる。長文脈ほど重要度の小さい尾部が多くなり、同じτでも削減量が増えるため、Figure 6(a)の長文脈側で速度利得が大きい。Figure 6(b)では128Kで採点、添字生成、gather/scatterの追加費用が全層注意遅延の11%未満と報告されるが、この割合は測定したA100と実装・系列長に依存する。

### 恒久破棄方式との比較

| LLaMA、RULER、128K注意速度が約1.5倍 | 全長平均正答率 |
|---|---:|
| 密FlashAttention（1.00倍） | 87.01 |
| PyramidInfer（1.49倍） | 78.49 |
| GemFilter（1.53倍） | 85.12 |
| FastKV（1.50倍） | 85.64 |
| Token Sparse Attention（1.51倍） | 86.84 |

Table 5では同程度の注意速度予算で比較した場合、恒久的にトークンを捨てる方式よりToken Sparse Attentionの平均精度が高い。これはヘッド別に必要なトークンを選び、後続層で再評価できる仕組みと整合する。ただし、密FlashAttentionの87.01よりは0.17ポイント低い。各方式の最適化対象・実装・ハイパーパラメータが完全一致するわけではないため、表の比較を全環境での一般的な優位性とみなすべきではない。

## 限界・負の結果

本方式はプリフィルの注意計算を対象とし、デコードは密注意のままである。KVキャッシュを永久に削減する方式ではなく、長い生成列でKV転送が律速になる場合に同じ効果を期待することはできない。論文の最大3.23倍という見出しも128Kの注意演算高速化の上限であり、モデル全体の生成速度の最大倍率ではない。

選択トークンを次層で再利用可能にするには、長さLの残差経路を維持する必要がある。したがって注意演算をL'に縮めても、すべての層の活性化保存やFFNの系列長まで自動的にL'へ縮まるわけではない。gather/scatterとスコア計算も必要であり、短文脈や注意分布が平坦な入力では効果が小さくなりうる。

表現ドリフトの低い層だけを選ぶ設計は事前プロファイルに依存し、未知のモデル・タスク・長さでδ=0.5が最適と保証されない。直近クエリの注意重みを使った重要度推定も、過去の文脈にある希少だが必要な証拠を見落とす危険がある。Table 1の128K個別精度低下やTable 2の一部タスクの悪化は、そのリスクを無視できないことを示す。

実測はA100 80GB単体、LLaMA-3.1-8BとMistral-Nemo-12Bに限られる。GPU世代、Triton採点カーネル、FlashAttentionのバージョン、ヘッド数、系列長、バッチの変化による再評価が必要である。既存疎注意との組合せは可能だが、同じモデルで最良のγやτが変わる可能性があり、論文がすべての構成に対して単一の設定を保証しているわけではない。

## 既存研究との差

MinferenceやFlexPrefillは注意行列の領域・ブロックを選ぶのに対し、Token Sparse Attentionは演算前にヘッド別のQKV行そのものを短くする。FastKVやGemFilterが一度捨てたトークンを後段で参照できないのに対し、提案手法はscatterと残差接続によって元の系列次元を維持し、次層で別のトークンを選べる。さらにDynamic Token Coverageで層ごとの削減数を決め、表現ドリフトで適用層を制限することで、細粒度選択をGPUで実行可能な短い密注意へ落とし込んでいる。
