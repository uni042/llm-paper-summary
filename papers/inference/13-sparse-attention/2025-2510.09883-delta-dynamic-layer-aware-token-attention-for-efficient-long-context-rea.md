# DELTA：全KVを残しながら、層間で重要ページを共有する長文脈推論向け疎注意

## 概要

推論特化のLLMは数学・科学問題で長いChain-of-Thoughtを生成する。デコードでは生成するたびに過去の全トークンへ注意するため、KVキャッシュの長さが増えるにつれてHBMからの読出しと注意計算の費用が増える。古いKVを削除する方式は容量と計算の両方を減らせるが、思考過程の後半で以前の中間結論が再び重要になったとき、削除済みのKVを取り戻せない。

DELTAは**KVの保存と注意計算を分離**する。全KVはGPUメモリに残したまま、各デコードステップで少数の層だけが全注意を計算し、その層の注意分布から重要なKVページを選ぶ。後続の複数層は選ばれたページにだけ注意し、次のΔ層で選択を更新する。連続層の注意分布が相関し、層を進むにつれて重要位置が緩やかに変化するという観測を利用する。

原著はDeepSeek-R1蒸留モデルを使い、AIME、GPQA、MATH500などで固定1k～4kトークン予算の精度と速度を比較した。DS-Qwen-1.5Bの合成18kデコードでは403秒から261秒へ短縮し、スループット2921から4517 token/sへ増加する。**ただし全KVを保持するため、KVメモリ容量が4.25分の1になるわけではない**。4.25倍は参照するトークン数を減らす指標であり、HBM上のキャッシュ確保量とは別である。

## 問題設定：長い推論では過去の重要度が変わる

通常の全注意では、各デコードステップ・各層で新しいQueryと全履歴のKeyを内積し、Softmaxを通じてValueを集約する。KVの保存量は文脈長に比例し、デコード中の注意演算・読出しも履歴長に比例して増える。Questのような選択方式は全KVを保持したままQueryに近いページを選べるが、各層でページを評価するため追加コストがある。RaaSのような削除方式はKVメモリを節約できる一方、後で必要になる位置を消してしまう可能性がある。

DELTAは、長い思考過程で**現在重要なトークンが後の時点でも重要とは限らない**ことに注目する。早期に削除すると、後半の推論で参照すべき根拠を失う。逆にすべての層で全注意を実行すれば安全だが高コストになる。著者は連続する層の注意分布を比較し、ある区間では重要位置が似ている一方、特定の層境界で大きく変化することを観測した。そこで全注意を実行する「更新地点」を少数だけ選ぶ。

## 手法：3種類の層で構成する

### 1. 初期層は全注意

全モデルで層0と層1は全注意を実行する。初期層の注意分布は広く分散し、安定した重要ページをまだ選びにくいためである。層2を最初のΔ層とし、ここで全KVへ注意して重要ページを選ぶ。後続の疎注意層は、その選択集合を参照する。

### 2. Δ層は全注意からページの重要度を計算

各Δ層は毎デコードステップで全KVを使って通常の注意を計算し、その注意確率を利用する。各トークンの重要度は**ヘッドごとの注意重みの最大値** `s_t=max_j α_j(t)` とする。ヘッド平均では、特定のヘッドだけが強く参照するトークンが他のヘッドで希釈され得るため、最大値を採用する。これは一部の検索ヘッドが特定の証拠を強く参照する状況に対応する。

最新のℓトークンは必ず残す直近窓とし、残りの古い位置から重要度上位k−ℓトークンを選ぶ。直近窓は、推論途中で直前の計算や文脈を継続するための安全策である。ヘッド最大スコアだけで全枠を選ぶのではなく、一定量を直近の履歴へ予約する。

### 3. GPUではページ単位にまとめる

トークンごとにKVを不規則に集めるとGPUのメモリアクセスが断片化するため、実装はP=16トークンの固定ページを使う。各ページに含まれるトークン重要度を合計し、ページ単位で上位を選択する。主設定はK=64ページ=1024トークン、直近窓L=8ページ=128トークン。したがって重要度上位の古い56ページと、直近8ページの和集合を後続層へ渡す。1kという数字は選択して**注意する**トークン数であり、全KVの保存上限ではない。

選ばれたページは次のΔ層まで複数の疎注意層で再利用する。Δ層では毎ステップ全注意から再選択するので、生成が進んで重要位置が変わっても古い選択を固定し続けない。これが一度削除したKVを回復できない方式との本質的な違いである。ただし全KVの読出しをΔ層では残すため、全層を疎化する場合ほど大きな計算削減にはならない。

### 4. Δ層の位置はモデルごとに校正

最初のΔ層は2に固定し、残り2箇所は校正データで全注意を実行して、連続層の注意分布のコサイン非類似度を測る。変化が大きい層境界を選び、ネットワークの深さ方向に偏り過ぎないよう配置する。原著の配置はDS-Qwen-1.5Bで[2,14,23]、7Bで[2,14,22]、14Bで[2,6,42]、DS-Llama-8Bで[2,8,31]。**全モデル共通の固定層番号ではない**。一度選んだモデルごとの配置は全評価データセットで共通に使う。

## 実験条件

| 項目 | 内容 |

| モデル | DeepSeek-R1-Distill-Qwen-1.5B/7B/14B、DeepSeek-R1-Distill-Llama-8B |
| タスク | AIME-2024/2025各30問、GPQA-Diamond先頭100問、MATH500先頭100問 |
| 比較 | 全注意、Quest（選択型）、RaaS（削除型）、DELTA |
| KV管理 | ページ16トークン、主設定64ページ（1k）、直近窓8ページ（128） |
| 実装 | FlashInfer JITで注意logit取得、PyTorch topkでページ選択。比較方式はHF Transformersで再実装 |
| ハードウェア | A100 SXM4 40GB×8のノード。1.5Bは1GPU、7Bは2GPU、14Bは4GPUなど |
| 品質 | 最終解答の正誤率、生成した思考トークン長、予算別性能 |
| 速度 | 合成デコードトレースのstep latency、生成総時間、token/s、バッチ条件別比較 |

原著のAIMEは30問であり、1問の正誤が約3.33ポイントに相当する。グラフから読み取った「約50%」のような値を小数点まで確定した表値と混同しない。GPQAとMATH500は先頭100問を使い、全ベンチマークの完全なテスト集合ではない。比較手法の実装条件は著者による再現であり、各方式の最適化済み本番カーネル同士を公平に競わせた測定とは限らない。

## 評価結果：少数の全注意層で長い推論を維持

原著Figure 3では、DS-Qwen-14BのAIME-2024で1kトークン予算のQuestとRaaSは20%未満へ低下するが、DELTAは約50%で、全注意の約60%に近い。これは**DELTAでも約10ポイントの低下がある**という負の結果であり、「全注意と常に同精度」と言い切るべきではない。予算を2kへ増やすと改善する条件があり、DS-Qwen-7BのGPQAでは全注意を上回る例もある。4kへ増やしても改善が小さい、あるいはわずかに悪化する条件があり、参照数を増やせば必ず精度が上がるわけではない。

Questは全KVを保持する点ではDELTAと同じだが、各層でQueryとページの代表ベクトルを照合するため、重要ページ選択の費用が大きい。RaaSは低重要度ページを実際に削除するため、長い思考過程で後から重要になったトークンへ戻れない。DELTAは全KVを残し、少数のΔ層の注意分布を後続層へ使い回すため、品質を保ちやすい。

ただしフルキャッシュより精度が上がる例を「疎注意が必ず推論能力を向上させる」と一般化することはできない。問題数が限られ、サンプリング・生成長・モデル・予算の影響を受ける。最終正答率だけでなく、生成トークン数や失敗した問題の傾向を確認する必要がある。

## 評価結果：全KV保存でも読出しを削れば速くなる

DS-Qwen-1.5Bでバッチ64、最大18kトークンの合成デコードを行ったFigure 4では、全注意の1ステップ時間が履歴長に伴い約7.5msから約30msへ増える一方、DELTAは約13msまでの増加にとどまる。全体の生成時間は403秒から261秒へ短縮し、スループットは2,921から4,517 token/sへ増加する。比は約1.55倍で、原著の1.54倍という丸めた記述と整合する。

| 指標 | 全注意 | DELTA | 比較 |
|---|---:|---:|---|
| 合成デコード総時間 | 403秒 | 261秒 | 約35.2%短縮 |
| スループット | 2,921 token/s | 4,517 token/s | 約1.55倍 |
| 長文脈末尾のstep latency | 約30ms | 約13ms | 約2.3倍のstep時間差 |

これらは同一モデルの合成デコード条件における値で、実際のAIME解答の平均E2EレイテンシやGPUメモリ削減量を表すものではない。Δ層が全注意を続け、全KVをHBMへ保存するため、**同時リクエスト数をKV容量削減で増やす効果は原理上得られない**。主要な利得はデコード中の注意計算とHBM読出し量の減少である。

Δ層を増やすアブレーションでは、追加するたびに全注意の層が増え、平均step時間も最終step時間も長くなる。全層をΔ層に近づけると、速度は全注意の水準へ戻る。逆にΔ層を少なくしすぎると重要ページの選択が古くなり、精度が下がる可能性がある。精度と速度の最適点はモデルの注意分布の変化に依存する。

## アブレーション：配置と直近窓の感度

著者はDS-Qwen-1.5B/7Bで10種類のΔ層配置を比較し、データセット間の相対的な傾向は似ていても、**配置によって絶対精度が明確に変わる**ことを示す。特に大きなモデルで差が目立つ。これは少数の更新層を適当に均等配置すれば同じ精度になるわけではないことを意味する。校正では連続層の注意分布の変化量を使い、変化点の近くにΔ層を置くことが重要である。

直近窓Lを変えたFigure 7では、DS-Qwen-7BのMixed120で最大約10%の精度差が生じる。4kや8kの大きな予算では小さい直近窓L=8が有利なことが多いが、最小1k予算ではより大きな直近窓が有利な場合がある。これは、古い重要証拠へ予算を回すことと、直近の思考を保護することのトレードオフである。付録のデータセット別図ではAIME、GPQA、MATH500で最適Lが異なり、普遍的な直近窓設定は確認されていない。

1k→2kへの予算増加は精度改善につながる場合があるが、4kでの改善は小さくなる。4.25倍の参照トークン削減は**特定の予算と長さの条件での最大値**であり、すべての層・モデル・入力での一律な削減倍率ではない。さらに、ページ選択のtopkやFlashInferの注意logit取得には小さいが非ゼロの費用がある。全注意から疎注意への切替えが短い文脈では有利でない場合も考えられる。

## 限界：既存研究との差

DELTAはQuestと同様に全KVを保存する選択型である。ただしQuestは各層・各Queryでページ代表ベクトルを評価するのに対し、DELTAは少数のΔ層で実際の注意分布を計算し、後続層が選択を再利用する。RaaSなどの削除型とは、古いKVを復活可能な状態で保存し続ける点が異なる。KV圧縮の論文として引用されても、**キャッシュ容量を圧縮する方式ではなく、KVへのアクセスを疎化する方式**と分類するのが適切である。

第一の限界は、メモリ容量の節約がないことだ。長い文脈や多数の同時リクエストでGPUのKV容量が律速になる場合、DELTAだけではOOMを避けられない。KV量子化、オフロード、ページ共有など別の容量最適化が必要になる。第二に、モデルごとのΔ層位置の校正と直近窓設定が必要で、完全な設定不要のプラグインではない。第三に、少数の全注意層の読出しコストが残るため、理論上の最大削減率をE2E速度にそのまま換算できない。

第四に、品質評価はDeepSeek-R1蒸留モデルと数学・科学の4ベンチマーク中心であり、一般会話、コード補完、RAG、長い複数ターン対話、MoEモデル、数十万トークンの極端な文脈で同じ挙動を保証しない。AIME各30問という標本数も小さい。第五に、実装はFlashInfer JITとPyTorch topkに依存するため、別ランタイムのページ管理、GQAのヘッド配置、GPUの並列化方式へ移植すると費用が変わり得る。

実用上は、**KVを失わず長い推論の注意演算だけを減らしたい**用途に向く。容量が足りないローカルGPUでは、DELTA単独でVRAM不足を解消することはできない。導入時には全KVの確保量、選択されたページ数、Δ層ごとの全注意費用、生成長、最終正答率、P95/P99遅延を別々に測る必要がある。
