# RelaxKV: Recomputation Guided by the Query with Sparse Context Attention for Efficient KV Cache Reuse

> 層ごとのクエリ注意で修復するトークンを層別に選び、再計算時に読む文脈もその選択の和集合へ絞ることで、位置非依存キャッシュの修復費用を下げつつ長文脈品質を保つ方式で、4モデル全てで先行方式の集計品質を上回った。

## 概要

検索拡張生成（Retrieval-Augmented Generation; RAG）では、検索で得た文書の塊がリクエスト間で重なるため、各塊のキー・バリュー状態（KVキャッシュ）をあらかじめ計算して再利用すれば、入力処理（プリフィル）の費用を大きく下げられる。ただし通常の接頭辞キャッシュは文頭から完全に一致する接頭辞しか再利用できず、再利用の範囲が狭い。そこで塊ごとに独立に符号化して位置に依存せず組み合わせる位置非依存キャッシュ（Position-Independent Caching; PIC）が使われるが、独立符号化では塊同士の相互作用が隠れ状態に反映されないため、そのまま合成したキャッシュは全再計算と大きく異なる近似になる。全部を再計算すれば品質は戻るが再利用の利益が消えるため、一部のトークン状態だけを再計算して欠けた相互作用を修復する選択的修復が中間の解になってきた。

従来の選択的修復は、どのトークンを修復するかという対象選択だけを工夫してきた。境界状態を直す方式、キャッシュや隠れ状態のずれで対象を選ぶ方式、利用者の質問（クエリ）との関連で対象を選ぶ方式があるが、いずれも選ばれたトークンは再計算時に自分の因果接頭辞、つまり自分より前の全位置を読む。つまり予算は状態の再計算量だけを制御し、1件の再計算が読む注意文脈の量は制御していない。対象が少なくても文脈が長ければ注意計算は重い。本論文はここに第二の配分軸があると捉え、選択的修復を修復対象と再計算文脈の共同配分問題として定式化する。提案方式は、質問を素のキャッシュに対して走らせて得る層ごとのクエリ注意で層別に修復対象を選び、再計算時に読む文脈を全層の選択結果の和集合へ制限する。これにより、再計算する状態の数と、各再計算が触れる注意の辺の数の両方を絞る。

**代表結果:** アンカー比率15パーセントの設定で、自然な長文脈課題の集計（LongBench 7課題平均）は4モデル全てでクエリ駆動の先行方式ProphetKVを上回った。具体的にはQwen3-14Bで53.14対53.11、Llama-3.1-8B-Instructで57.64対57.20、Phi-4-14Bで46.27対45.53、Llama-3.2-3B-Instructで44.04対41.62である。さらにQwen3-14Bの長文脈評価では、合成検索課題RULER-MVの32Kで正解率95.00（ProphetKVは91.17）、自然な複数文書課題LV-Evalの32KでトークンF1値25.40（ProphetKVは19.32）と、16Kと32Kの両方で選択的手法中最良となった。評価は実機測定であり、シミュレーションではない。

## 問題設定

問題を資源の観点で見る。再利用キャッシュの修復費用は大きく二つに分かれる。一つは再計算する層・トークン状態の数で決まる射影と多層パーセプトロンの計算であり、もう一つは再計算される各トークンが注意で読むキー・バリュー項目の数で決まる注意計算である。従来方式は前者だけを予算化し、後者は全因果接頭辞という固定値だった。文脈が4Kから32Kへ伸びるにつれて後者は対象位置の平均接頭辞長に比例して膨らむため、対象比率を下げても費用の下がり方は鈍くなる。逆に品質の側では、素のキャッシュの誤差は塊間の相互作用の欠落に由来し、どのトークンの状態が質問にとって重要かは層ごとに異なる。論文の図1が示すように、クエリ注意で強く注目される位置は層によって大きく入れ替わるため、全層で共通の対象集合を1つ決める方式は、ある層では不要な状態を直し、別の層では必要な状態を取りこぼす。本論文の着眼点は、対象選択を層別に行うことと、再計算文脈を質問に関連する位置へ制限することを、一つの配分として同時に決めることにある。なお位置のずれの問題は別に扱われる。評価では各塊を最終的な全体位置番号で事前に符号化し、回転位置埋め込み（Rotary Position Embedding; RoPE）の位相ずれと文脈の古さを分離している。提案方式が直すのは位相ずれではなく、先行する塊の隠れ状態を見ずに符号化されたことによる文脈欠落である。

## 手法のあらまし

処理は、素のキャッシュに対する質問の走行、層別の対象選択、依存関係の閉包、疎な文脈での再計算、キャッシュ更新の順に進む。まず利用者の質問を、塊キャッシュを連結した素のキャッシュに対して走らせ、層ごとに質問から文脈位置への注意重みを集めて得点を付ける。次に各層で得点の高い順に、アンカー比率で決まる個数の位置を修復アンカーとして独立に選ぶ。深い層で選ばれたトークンは、その層へ到達するために浅い層から再計算しなければならないため、各トークンについて選ばれた最も深い層を求め、その層までを活性な修復対象とする。全層のアンカーの和集合は、再計算時に読める文脈として全層で共有される。各層では活性な対象だけが変換ブロックを実行し、自分の位置以前にある和集合内の位置だけへ注意を向け、得られた新しいキー・バリュー状態でキャッシュの該当項目を上書きする。対象でない位置と、最高選択層を過ぎた位置は素の値を保持する。

## 手法

### 1. 層別クエリ注意による修復対象選択 — 層ごとに質問が強く見る位置をアンカーにする

この機構が観測するのは、質問を素のキャッシュに対して走らせたときに得られる、層ごとのクエリから文脈への注意である。保持する状態は層・位置ごとの得点であり、注意ヘッドと質問位置について平均した後に層内で最小値・最大値による正規化を行った値である。行う選択は、各層で得点の上位にある位置を修復アンカーとして選ぶことであり、個数は文脈トークン数にアンカー比率を掛けて四捨五入した値と1のうち大きい方である。層ごとに独立に選ぶため、浅い層と深い層で異なる位置が対象になり得る。ここで重要なのは依存関係の閉包である。深い層で選ばれたトークンの状態は、その層までの全ての浅い層の計算を経なければ得られない。そこで各トークンについて選ばれた最も深い層を最高選択層として保持し、そのトークンは第0層から最高選択層まで各層で活性な修復対象となり、それより深い層では非活性に戻る。減るボトルネックは、質問と無関係な状態の再計算であり、全層共通の対象集合で生じる層ごとの過不足も減る。追加で消費する資源は二つある。得点を得るために質問を素のキャッシュで一度走らせる費用と、深い層の選択が浅い層の実行を伴うため、実際に実行される層・トークン状態の数が名目アンカー比率より大きくなることである。論文の予算会計では、アンカー比率15パーセントでも、8Kの合成課題で活性対象は層・トークン状態の42.85パーセントを占めた。失敗時の挙動として、クエリ注意が本当に必要な位置を取りこぼすと、その状態は修復されず素の近似のまま残る。また名目比率だけを見て実効計算量を見積もると過小評価になるため、論文は実測の最初のトークンまでの時間（Time to First Token; TTFT）を主たる費用指標にしている。

### 2. 再計算文脈選択 — 再計算が読む文脈を全層アンカーの和集合へ制限する

この機構が観測するのは、前段で得られた全層のアンカー集合である。保持する状態は、その和集合を全体位置の昇順に並べた共有文脈であり、リクエストごとに一度だけ圧縮した番号への対応付けを作る。行う選択は、各層の活性対象が注意で読める位置を、この和集合のうち自分の元の位置以前にあるものだけへ制限することである。因果条件を満たす部分集合が、その対象の再計算文脈になる。元の全体位置番号は保持されるため、回転位置埋め込みの相対ずれは変わらず、変わるのは読めるキー・バリュー位置の集合だけである。減るボトルネックは注意計算であり、対象1件あたりの接頭辞長が和集合の密度まで縮む。長文脈で無関係な文書が多い条件では、無関係な位置を読まないことが雑音の混入を抑える方向にも働き、論文はこれを暗黙の絞り込み効果として解釈している。追加で消費する資源は、和集合のキー・バリューを集める処理と圧縮番号の管理であり、和集合自体は広くなり得る点に注意が要る。アンカー比率15パーセントでも和集合は文脈位置の63.05パーセント（8Kの合成課題）を覆った。つまり文脈は状態ほどは絞られておらず、広い関連文脈を読みつつ再計算する状態だけを絞る配分になっている。失敗時の挙動として、修復に必要な先行情報が和集合の外にあると、その情報は再計算へ直接入らない。文脈構成の除去実験では、同じ対象と名目文脈量でも構成法によって品質が大きく変わり、層別に文脈を選ぶ変種は合成課題32Kで85.00まで落ちた。どの位置を残すかが疎さそのものと同じくらい重要であることが分かる。

### 3. キャッシュ更新の意味論 — 文脈内では新規状態とキャッシュ状態を混ぜて使う

この機構が観測するのは、各層で活性な対象の集合と再計算文脈の重なりである。保持する状態は、出力キャッシュ全体であり、初期値は素のキャッシュである。再計算の注意では、文脈位置のうち現層でも活性な位置については今まさに再計算された新しいキー・バリュー状態を使い、文脈内だが現層で非活性な位置については素のキャッシュ状態をそのまま使う。この新規と既存の混在が本方式の近似の一部であり、全比較で一貫して用いられる。層の実行が終わると、活性対象全ての新しい状態がキャッシュの該当項目を上書きし、追加の選択手順は要らない。最高選択層を終えたトークンはそれより深い層では再計算されず素の値を保つが、和集合の一員としては後続の再計算にキャッシュ状態を提供し続ける。減るボトルネックは、更新対象を別途判定する処理と、文脈全体を新規状態で揃えるための連鎖的な再計算である。追加費用は、集めた文脈項目のうち活性分を新規状態へ差し替える処理である。失敗時の挙動として、混在文脈は完全な全再計算とは一致しないため、品質は近似の範囲に留まる。ただし対象を固定した全接頭辞対照との比較では、文脈を制限しても品質差は0.45から1.00ポイント以内に収まり、再計算遅延は9.9から23.2パーセント減った。文脈制限の品質代償が小さいことは、この意味論が実測で裏付けられている。

| 層別アンカー選択 | 層ごとのクエリ注意得点 | 層ごとに上位位置をアンカーとして選ぶ | 質問と無関係な状態の再計算 | 得点付けに質問の走行が要る |

| 混在更新 | 活性集合と文脈の重なり | 活性分は新規状態、他はキャッシュ状態で注意し、対象分を上書き | 更新判定と連鎖再計算 | 全再計算とは一致しない近似になる |

### 4. 1リクエストの流れ — 取得済みキャッシュの修復から最初のトークンまで

1リクエストは次のように進む。検索で得た塊は同一であり、その素のキャッシュは測定開始時点でグラフィックス処理装置（GPU）上に常駐している。質問が素のキャッシュに対して走り、層別得点、アンカー、和集合、活性対象が決まる。続いて層を浅い順に進み、各層で活性対象だけが変換ブロックを実行し、制限された文脈へ注意を向けてキャッシュを更新する。全層を終えた修復済みキャッシュに対して質問の入力処理が行われ、最初のトークンが生成される。測定されるTTFTには、得点付け、対象と文脈の選択、キー・バリューの収集、再計算、キャッシュ更新、質問の入力処理、最初のトークンの生成が含まれ、再利用キャッシュの構築自体は含まれない。本方式は近似型であり、重みもキャッシュ構築も変えない。変えるのはオンライン修復の配分だけである。

## 評価

結論は四点である。第1に、アンカー比率15パーセントの提案方式は、名目20パーセントを使う選択的比較方式群に対して、4モデル全てで自然な長文脈課題の集計を上回るか互角以上に保ち、全再計算の参照値にも近づいた。第2に、文脈長が伸びるほど素の再利用や弱い修復方式は崩れるが、提案方式は32Kでも全再計算に近い品質を保ち、自然な複数文書課題では全再計算を上回る条件もあった。第3に、修復対象を先行方式に固定した対照でも文脈だけを替えて品質がほぼ保たれ、文脈構成の除去実験では構成法により品質が大きく変わった。文脈選択は独立した設計軸である。第4に、アンカー比率を5から30パーセントまで振ると品質とTTFTの釣り合いは先行方式より外側に位置し、比率を上げるほど品質は上がるが費用も増える単調な交換関係が確認された。評価は実機での端から端までの測定であり、検索自体の遅延は測定対象から除かれている。

## 既存研究との差

先行する選択的修復はいずれも対象選択の研究だった。EPICは固定した境界状態を直し、CacheBlendとKVShareはキャッシュや隠れ状態のずれから対象を決め、ProphetKVはクエリ関連性で対象を選ぶ。しかし選ばれた対象は全て全因果接頭辞を読んで再計算されていた。本論文はこの共通前提を外し、対象選択に加えて再計算文脈選択を明示的な設計軸にした。また対象の決め方も、ProphetKVの全層共通の集合から、層ごとに独立したアンカーとその依存閉包へ変えている。クエリ注意でキャッシュを圧縮するSnapKVや、復号時にクエリでページを選ぶQuestなど、クエリ誘導の疎な計算は他段階にもあるが、それらは文脈化済みキャッシュの圧縮や生成段階の高速化であり、独立符号化された塊キャッシュの合成で欠けた相互作用を直す問題ではない。学習型のKVLinkや、オフラインで境界の適応子を学ぶKV Packet、塊キャッシュ管理まで含むCache-Craftとは異なり、本方式はモデルもキャッシュ構築も変えず、オンライン修復の配分だけを変える。

## 限界・実装状況

論文の評価範囲に由来する限界が三つある。第1に、対象モデルは3Bから14Bのデコーダモデル4種に限られ、より大規模なモデルや混合専門家モデルでの挙動は未検証である。第2に、再利用の前提は検索で得た塊の共有であり、塊の重なりが小さいワークロードや検索を含む全体遅延は評価されていない。第3に、費用評価は単一GPU上の単一リクエストのTTFTが中心で、同時リクエスト下のスループットやバッチ処理との相互作用は示されていない。読み手の注意点として、名目アンカー比率は実効の文脈量や状態数と一致しないため、比率だけでの他方式との費用比較はできない。実装状況としては、公式コードは未公開で、要旨に採択後に公開予定と明記されている。論文は付録に手順の擬似コードと再現条件を詳しく収録しているが、上流の推論基盤へ統合されたという記述はない。

## 一般的な実装上の含意

選択的再計算を設計するときは、再計算する状態の数だけでなく、各再計算が読む文脈の広さを独立した予算として数えるべきである。両者は別の資源を消費し、片方だけを絞っても費用と品質の釣り合いは最適にならない。また、関連性の信号は層ごとに異なるため、全層共通の選択を前提にせず、層別の選択とその依存関係の閉包を最初から設計に入れる必要がある。名目比率と実効計算量がずれる方式では、比率ではなく実測遅延で比較する運用も重要である。さらに、文脈を絞ることは費用削減であると同時に、無関係な情報を読まないことによる品質改善にもなり得るため、長文脈では文脈選択を品質機構として評価する価値がある。
