# Dynamic Context Pruning for Efficient and Interpretable Autoregressive Transformers

> Dynamic Context Pruningは、生成の途中で「今後のトークンが参照する価値が低い」と学習した過去トークンを、注意対象とキー・バリュー（Key-Value; KV）キャッシュから動的に削除する。固定窓のように距離だけで落とさず、層ごとの学習可能な相互作用スコアで削除時点を決める。GPT-2系列では文脈1000トークン付近で約80%の疎性を品質低下なしに得る条件があり、RTX A5000の参照実装ではGPT-2-mediumで最大189%の追加スループットを、パープレキシティ悪化0.084で報告する。

## 概要

自己回帰Transformerは新しいトークンを生成するたび、それまでの全トークンのKVを参照する。系列が長くなると注意計算量とKV容量が増え、特にデコードはメモリ帯域律速になりやすい。局所注意のような固定窓はコストを抑えられるが、「近いか遠いか」だけで残すため、離れていても将来必要な固有名詞や主題を捨てる一方、近くても不要になった句読点や機能語を保持し続ける。

本論文の適応的疎注意（Adaptively Sparse Attention）は、各層で過去トークンと現在トークンの関係を軽量な学習可能機構で評価し、不要になったトークンをその層以降の文脈から削除する。既存の事前学習済みGPT-2へ追加微調整して導入でき、疎性正則化の強さで「どこまで捨てるか」を調整する。

重要なのは、単に注意行列へマスクを掛けるだけではない点である。削除済みトークンをKVストレージから物理的に詰め直し、バッチ生成でも連続メモリとして扱えるデータ構造を設計する。これにより理論的な注意要素削減を、実際のメモリ削減・より大きなバッチ・高スループットへ変換する。

## 問題設定

固定窓の局所注意は実装しやすいが、保持/削除の判断が内容に依存しない。疎注意も事前に決めた規則へ従う場合、入力や生成内容ごとに「もう不要になった情報」が変わることを利用できない。Dynamic Context Pruningは、生成中の情報価値そのものを学習し、トークンごと・層ごとに寿命を変えることを狙う。

ただし、動的削除には二つの追加費用がある。第一に、削除判定用の射影と相互作用スコアを計算する必要がある。第二に、バッチ内の文ごとに削除位置が異なるため、素朴な実装ではKV配列に「穴」ができ、GPUの連続アクセス効率を悪化させる。論文はこの2点を含めて実装し、短い文脈ではむしろ密モデルより遅いが、長文ではメモリ削減が固定費を上回ることを示す。

## 手法

### 1. 学習可能な相互作用でトークンの寿命を決める

各注意層に、通常のQuery/Keyとは別の相互作用用射影を追加する。現在トークンと過去トークンの相互作用から、過去トークンを今後も残すかを表すゲートを計算する。ゲートは学習中に疎性を促す正則化を受け、設定した強度γによって削除量を調整できる。

入力は現在の隠れ状態と、それまで保持している文脈状態である。出力は「この過去トークンを当該層の文脈に残すか」という連続的な重要度で、学習後には疎な保持判断へ近づく。固定距離ではなく内容を見て判断するため、必要な遠距離情報を残しながら不要な近距離情報を落とせる余地がある。

### 2. 疎シグモイドで学習可能性と離散削除をつなぐ

完全な0/1削除は微分できないため、論文は疎シグモイド（sparse sigmoid）を使い、学習初期は滑らかなゲートとして最適化しつつ、学習が進むと保持/削除が明確になるよう制御する。疎性を強くすると計算・メモリは減るが、重要情報を誤って消す危険が増える。

したがってγは単なる高速化ノブではなく品質との交換条件を決める。論文では同じGPT-2を密モデル、局所注意、規則的疎注意と同じ微調整条件で比較し、同じ疎性なら適応方式の方が低いパープレキシティを得る傾向を示す。

### 3. 削除判断を深い層へ伝播する

ある層で不要と判断したトークンを、その後の層でも漫然と保持するとKV容量削減が限定される。Dynamic Context Pruningでは削除判断を層方向へ反映し、不要になった表現を以後の注意対象から除く。層ごとに重要度分布は同じではなく、論文の分析では中間層が最初・最後の層より疎になりやすい。

この層依存性は、「全層で同じトークンを同じ比率だけ削る」方式より柔軟だが、実装は複雑になる。特に深いモデルでは削除確率の積み重ねが最適化を難しくするため、著者らは学習安定性も付録で検討している。

### 4. バッチ向け連続KVデータ構造

動的削除では、文ごとに残っているトークン数と位置が異なる。単純にマスクだけを持つと、削除済みKVもメモリに残り、注意カーネルが不規則な「穴」を処理してしまう。論文はpush・removeのような操作を持つKVデータ構造を用い、保持トークンを高充填率の連続領域へ詰める。

この工夫により、削除量がGPUメモリ容量の削減へ直結し、同じGPUでより大きなバッチを組める。実測スループット増加のかなりの部分は、単一系列のFLOPs削減ではなく「KVが小さくなってバッチを増やせる」ことから生じる。

## 評価

### 評価条件

| 項目 | 設定 |
|---|---|
| モデル | GPT-2-small 124M、medium 350M、large 774M、xl 1.558B |
| 最大文脈 | GPT-2の1024トークン |
| 微調整データ | English Wikipedia 20220301.en と BookCorpusの部分集合 |
| 微調整 | 25,000ステップ、バッチ6。small/mediumは学習率1e-4、large/xlは5e-5 |
| 注意実装 | PyTorch 2.0のscaled_dot_product_attentionを利用 |
| 品質 | パープレキシティ、WinoGrande/HellaSwag/PIQA/LAMBADAのゼロショット平均精度 |
| スループット | NVIDIA RTX A5000、各方式で最適バッチサイズを使用 |
| 比較 | 密なGPT-2、局所注意（Local Attention）、規則的疎注意（Sparse Attention） |
| 主な調整値 | 疎性正則化γ。相互作用射影の次元r=64 |

### 主な結果

| 条件 | 密モデルとの差 | 提案方式の結果 | 読み方 |
|---|---:|---:|---|
| 文脈長1000、約80.35%疎性 | 密モデル | パープレキシティが平均0.085改善 | 高疎性でも品質低下なしの例。全条件で改善するという意味ではない |
| GPT-2-small、長文 | 密モデル | スループット+98%、パープレキシティ悪化0.316 | 約2倍の処理量を小さい品質差と交換 |
| GPT-2-medium、文脈1000 | 密モデル | スループット+189%、パープレキシティ悪化0.084 | KV削減でより大きなバッチを組める効果が大きい |
| 短い文脈 | 密モデル | 削除判定費用のため遅い領域あり | 動的制御の固定費が削減量を上回る |
| 解釈性分析 | — | 句読点などで削除が多く、層ごとの削除傾向も異なる | 学習したゲートが文境界・局所情報の寿命を反映する可能性 |

「最大2倍」という概要だけではGPT-2-mediumの+189%を捉えきれない。これは基準の約2.89倍に相当する条件である一方、品質差と文脈長が付随するため、倍率だけを切り出すべきではない。反対に短文では追加ゲート計算により遅くなる。速度は疎性が十分大きく、KV削減でバッチを増やせる領域で現れる。

### 品質と疎性の交換条件

論文は「全トークンの80%を常に捨てても無損失」とは主張していない。疎性は現在の文脈長、層、学習したγによって変化する。同じ疎性で局所注意・規則的疎注意と比較したとき、適応的削除の方がパープレキシティを保ちやすいことが核心である。

ゼロショット評価ではWinoGrande、HellaSwag、PIQA、LAMBADAを用い、入力長が異なるため実際に生じた平均疎性と精度を対応させる。したがって評価時には「目標γ」ではなく、各データで実現した疎性を確認する必要がある。

## 既存研究との差

局所注意は「古いトークンから捨てる」、規則的疎注意は「事前定義した位置だけ残す」。Dynamic Context Pruningは「現在の生成内容に照らして、もう不要になったトークンを捨てる」。距離ではなく内容依存である点が第一の差である。

また多くの疎注意研究がマスク上の演算量を中心に議論するのに対し、この論文は削除後KVを連続配置するバッチ用データ構造まで扱う。動的疎性をGPUメモリ削減とバッチ拡大へ変換し、RTX A5000上の実スループットまで測っている。

## 限界・実装状況

- 事前学習済みモデルへ微調整が必要で、学習不要のKV eviction方式ではない。
- 実験モデルはGPT-2 124M〜1.558Bで、現在の数十B〜数百Bモデルやグループ化クエリ注意（Grouped-Query Attention; GQA）へ同じ挙動が出るかは論文評価外である。
- 削除は不可逆であり、後で必要になったトークンを再取得する経路は持たない。
- 短い文脈ではゲート計算とデータ構造操作の固定費により密モデルより遅くなる。
- バッチ内で削除率がばらつくため、実装が連続KV配置を保てないと理論疎性が実速度へ変換されにくい。
- 高い疎性では品質との交換条件があり、用途ごとにγを調整する必要がある。

## 一般的な実装上の含意

KV削減方式を比較するときは「何%捨てたか」だけでなく、削除後のKVが本当に物理メモリから除かれ、注意カーネルが連続領域だけを読むかを見る必要がある。マスク上の0が多くても、メモリ読み出しとカーネルが密なままならスループットは伸びない。

また動的方式は短文で固定費が負ける可能性がある。系列長ごとの交差点、最適バッチサイズ、パープレキシティまたは下流精度を同一設定で測ることが導入判断に必要になる。
