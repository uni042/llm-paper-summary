## 概要

HySparseは、長文脈言語モデルの注意計算と鍵・値キャッシュ（KVキャッシュ）を同時に削減するため、**少数の全体注意層を後続の疎注意層の情報供給源として再利用する**混合注意アーキテクチャである。従来の動的疎注意は、重要なトークンを予測する補助選択器が必要になり、選択誤差と計算費用が生じる。また計算対象トークンを減らしても、各層が独自の完全KVを保存すれば、生成時のキャッシュ容量は層数に比例して増え続ける。

HySparseでは一つの全体注意層の後ろに複数の疎注意層を配置する。全体層は通常の注意を計算する際にブロック単位の重要度を取得し、上位ブロックの索引と自層のKVを後続の疎層へ供給する。疎層の大域分岐はその索引とKVを再利用するため、自分専用の大域KVを持たない。一方、局所スライディング窓注意（SWA）の分岐は独立した小さなKVを保持し、二つの分岐をゲートで融合する。

7Bの密モデルと80Bの混合専門家（MoE）モデルで検証され、80B・49層の構成では全体注意層が5層だけでもKV保存量を約10分の1に削減できると報告される。長文脈RULERの32KではHySparse 87.4、全体注意82.1だが、16KではHySparse 90.6、全体注意93.6と逆転する。したがって「常に全体注意より高精度」という単純化はできず、文脈長と評価課題を区別する必要がある。

## 問題設定

密な自己注意では系列長が増えると注意スコア計算が二乗的に増え、自己回帰生成では過去トークンのKey/Valueを各層で保存する必要がある。疎注意は参照位置を絞ることで演算量を減らすが、重要トークンの選択に別の推定器を使う場合、推定費用が増えるうえ、誤った選択で長距離情報を失う危険がある。さらに各層で完全なKVを持ち続ける設計では、注意演算を減らしてもキャッシュメモリは減らない。

一方、隣接するTransformer層の注意パターンには相関がある。ある層で重要だった過去のトークンは後続層でも役立つ可能性があり、近接層のKVを再利用する余地がある。ただし全ての層で同じKVを使えば、層固有の局所表現を失う可能性がある。HySparseは、**大域的な長距離参照は共有し、局所的な短距離表現は各層に残す**という分離でこの問題を扱う。

設計上の論点は、どの頻度で全体注意層を挿入するか、どの粒度で重要ブロックを選ぶか、何トークンを大域・局所分岐へ割り当てるか、どのKVを共有するかである。全体層を減らすほどKV容量は小さくなるが、重要度の更新間隔が広がる。局所窓を広げれば短距離情報を保持しやすいが、疎層ごとの独立キャッシュが増える。

## 手法

### 1. 全体注意層を選択器として利用

HySparseは、一つの全体注意層と複数の疎注意層を組み合わせたブロックを繰り返す。全体注意層は通常の注意計算を行うため、どの過去位置が重要かを示すスコアを既に持っている。改変したFlashAttentionの計算経路でブロック単位の最大注意スコアを取り出し、巨大な注意行列全体をメモリ上に展開することなく重要度を集計する。

各ブロックの重要度を比較してTop-Kブロックを選び、選択索引を後続の疎注意層へ渡す。これは別の軽量ネットワークで重要度を予測するのではなく、直前の全体層が実際に計算した注意スコアを根拠にする。そのため著者らは「oracle token selection」と呼ぶ。ただし外部の正解ラベルによる完全な理想選択ではなく、あくまで**直前の全体注意層における実測スコア**を基準にする。

代表設定では64トークン単位のブロックから合計1024トークン相当を選び、16個のブロック索引を後続層へ供給する。ブロック化は選択の索引管理とGPU上の連続読出しを扱いやすくするが、重要トークンだけを一点ずつ選ぶ方式より不要なトークンを同じブロック内に含む可能性がある。選択粒度とカーネル効率の交換条件がある。

### 2. 大域KVの層間共有

疎注意層の大域分岐は、自分の全系列Key/Valueを新たに保存せず、直前の全体注意層のKVからTop-Kで選んだブロックを参照する。一つの全体層が後続の複数層へ大域KVを供給するため、層数に比例して大域キャッシュを複製する必要がなくなる。

80B MoEでは全体注意層と疎注意層の比率を1:11まで引き上げ、49層中5層だけを全体注意とする構成を評価する。最終層にも全体注意を残して大域情報を集約する。この比率から約10倍のKV保存量削減を報告するが、これは層構成に基づくキャッシュ保存量の比較であり、GPU実機の総メモリが10倍減ることや生成速度が10倍になることを意味しない。

### 3. 独立した局所SWAとゲート融合

各疎注意層は、大域の選択ブロックへ注意を計算する分岐とは別に、直近トークンを見るスライディング窓注意（SWA）分岐を持つ。代表設定では局所窓を128トークン程度に制限し、層ごとに独立した小さなKVを保存する。大域分岐は長距離検索、局所分岐は層固有の近傍表現を担う。

二つの出力はsigmoidゲートで重み付けして融合する。ゲートは、長距離参照を重視すべき場合と直近の文脈を重視すべき場合の寄与を調整する。全てのKVを共有してしまう方式と比べ、局所分岐の表現自由度を残すことが重要である。実際、7Bモデルの構成要素除去実験では、大域分岐のみKVを共有し局所分岐を独立させる構成が、両分岐とも共有する構成より複数課題で高いスコアを示す。

### 4. 事前入力処理と生成時の処理経路

事前入力処理では全体層が入力全体の注意とブロック重要度を計算し、Top-K索引と大域KVを保存する。後続疎層は保存索引で選ばれた大域KVへ注意し、同時に自身の短い局所窓KVを使う。次の全体層に到達すると、新しい注意スコアに基づいて重要ブロックを更新する。これを層ブロックごとに繰り返す。

自己回帰生成でも、疎層は大域の共有KVと自層の短い局所KVを参照する。これにより長い系列の全KVを毎層複製せずに済む。ただし全体層の計算とキャッシュは残り、索引選択や分岐融合のカーネル費用も存在する。したがって演算量と保存量の理論的な減少を、そのままエンドツーエンド遅延の測定結果とみなしてはならない。

## 評価

### モデル・比較・指標

| 項目 | 評価条件 |
|---|---|
| モデル規模 | 7B密モデル、80B MoEモデル |
| 全体:疎の層比 | 7Bは1:3、80Bは1:11 |
| 80Bの層数 | 49層、全体注意は5層 |
| 大域選択 | 64トークンブロック、合計1024トークン相当のTop-K |
| 局所分岐 | 約128トークンのSWA |
| 比較対象 | 全体注意（Full-Attn）、混合スライディング窓注意（Hybrid SWA） |
| 一般課題 | MMLU、MMLU-Pro、GSM8K、MATH、コード等 |
| 長文脈課題 | RULERの16K・32Kなど |
| 構成要素除去 | 大域分岐だけKV共有、または大域・局所両方を共有 |
| 主指標 | 課題別正解率・スコア、KV保存量 |

### 80B MoEの長文脈結果

| RULER条件 | 全体注意 | 混合SWA | HySparse | 注意点 |
|---|---:|---:|---:|---|
| 16KのTotal | 93.6 | 72.7 | 90.6 | HySparseは混合SWAより高いが全体注意には及ばない。 |
| 32KのTotal | 82.1 | 69.5 | 87.4 | HySparseは両比較対象を上回る。 |

この結果は、HySparseが長文脈で常に全体注意を上回るという意味ではない。16Kでは全体注意93.6に対してHySparse90.6であり、3.0ポイント低い。一方、32KではHySparse87.4に対して全体注意82.1であり、5.3ポイント高い。文脈長によって順位が変わるため、単一の平均値で品質を代表させると適用境界を見落とす。

著者らは80Bの49層中5層を全体注意にした構成でKV保存量が約10分の1になると説明する。この値は、共有される大域KVの複製数を層構成から見積もった効果である。局所SWAの小さなキャッシュやモデル重みは残るため、GPU全体のピークメモリが必ず10分の1になるわけではない。またこの論文の主要表には推論サービングのTTFT、TPOT、毎秒トークン数の代表値がないため、保存量の削減から速度倍率を推定することはできない。

### 局所KV共有の構成要素除去

7Bモデルでは、疎注意の大域分岐と局所SWA分岐の両方で全体層のKVを共有する構成と、大域分岐だけ共有して局所SWAは自層KVを持つ構成を比較する。GSM8Kでは両方共有が30.2、大域のみ共有が36.7であり、後者が6.5ポイント高い。DROP、MMLU、MMLU-Pro、BBHでも大域のみ共有が高いという結果が示される。

この比較は「キャッシュ共有を増やすほど常に良い」という仮説を否定する。大域的な長距離参照は前の全体層のKVで代替できても、局所表現は層ごとに変化するため、自層の局所KVを残す利点があるという解釈を支持する。ただし、差のすべてが表現の違いだけから生じたことを単独で証明した実験ではない。独立局所分岐の追加キャッシュ費用と精度利得を合わせて評価する必要がある。

### 7Bと80Bの評価を区別する

7B密モデルでは全体:疎の比率を1:3、80B MoEでは1:11に設定している。モデル規模、学習量、注意層の割合が異なるため、7Bの構成要素除去のスコアを80Bへ直接移すことはできない。両規模で全体注意と混合SWAを比較し、一般推論・数学・コード・長文脈検索を評価することで、疎化が単なる長文脈検索専用の技巧ではないことを検証している。

ただし研究の中心はモデルの課題性能とKV保存量であり、全体注意からHySparseへ置換した時のGPU別カーネル時間、分岐融合の通信費用、実際のサービスでの同時要求数の上限を系統的に分解したものではない。推論基盤へ導入する際には、改変FlashAttention、Top-K選択、共有KVの読出し、局所SWAの計算を含む実機プロファイルが必要である。

## 既存研究との差

従来の動的疎注意は補助的な重要度予測器や近似スコアに頼る場合がある。HySparseは全体注意層が既に計算したスコアを重要ブロック選択へ転用するため、別の予測モデルを置く必要がない。これは代理指標の予測誤差を減らす一方、全体注意層そのものの費用は残す設計である。

また一般的な疎注意は参照トークンを減らしても各層のKV保存量を必ずしも減らさない。HySparseは全体層のKVを複数の後続疎層で共有し、演算削減とキャッシュ削減を同時に狙う。層間KV共有だけを最大化するのではなく、局所SWAのKVを独立させることで、長距離参照と短距離表現の役割を分ける点も重要である。

## 限界・負の条件

第一に、全体注意層を残すため完全な疎注意ではない。全体層の比率を下げれば大域KV保存量は減るが、重要度を更新する間隔が広がり、層ごとの注意パターンが大きく変化する場合に不利になる可能性がある。直前全体層の注意スコアを「oracle」と呼んでも、後続層にとっての最適な選択を保証するものではない。

第二に、80BのRULER 16Kでは全体注意93.6に対してHySparse90.6と劣る。32Kでの改善だけを根拠にすべての長文脈課題で優位とするのは不正確である。さらに局所SWAのKVまで共有するとGSM8Kなどで精度が落ちるため、メモリ削減と表現力の間には明確な交換条件がある。

第三に、約10倍のKV保存量削減はモデル全体のメモリ削減率でも実測の推論速度倍率でもない。局所窓キャッシュ、全体層のKV、モデル重み、ブロック索引やゲート計算の費用が残る。エンドツーエンドのTTFT、TPOT、スループットの代表測定値がないため、実サービスでの速度改善は追加検証が必要である。

第四に、改変FlashAttentionでブロック重要度を抽出し、Top-K索引を後続層へ共有する実装が必要である。ブロック長、選択トークン数、局所窓長、全体層の挿入間隔はモデルや課題に依存する。7B密モデルと80B MoEの結果を、他の注意方式、GPU、モデル規模へ無条件に外挿できない。
