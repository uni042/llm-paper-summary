# ATFlash: Per-RoPE-Wavelength Attention Windows for Compute/Memory-Efficient LLM Inference

> 回転位置埋め込みの周波数対ごとに波長比例の窓で内積項を削る注意の近似を提案し、項の37から48パーセント削減と分布の近一致、100万文脈で1.31倍の高速化を示した。

## 概要

文脈が長くなると、注意機構の計算とキー・バリューキャッシュの読み出しが推論費用を支配する。高速な注意カーネルはスコア行列をメモリへ展開せずに正確に計算するが、正確であるがゆえに内積の計算量そのものは減らない。計算を減らす近似には3つの弱みがあった。削減量が入力に依存して事前に分からないこと、トークンやキャッシュを捨てると捨てた情報へ二度と到達できないこと、特定のカーネル実装と強く結び付いて移植できないことである。

本論文の出発点は、回転位置埋め込みを使う注意スコアが、回転の周波数対ごとの寄与の和へ厳密に分解できるという代数的な事実である。各対には波長があり、高周波の対は数トークンで1周期を終え、低周波の対は数百万トークンで1周期になる。1周期を超えた距離では、その対は位置を見分けられない。そこで論文は、対ごとに波長へ比例した距離窓を設け、窓の外側の距離ではその対の項だけを計算から外す。トークン自体は捨てないため、遠いトークンも低周波の対を通して常に参照できる。窓の幅はモデルの定数と保持する周期数だけで決まり、入力には依存しない。そのため削減率は文脈長の対数関数の閉形式で事前に計算できる。

代表結果は次の通りである。学習範囲内の文脈長では内積項の37から48パーセントが削減され、全注意に対する出力分布の乖離は小さい水準に収まり、最有力トークンの一致率は96から98パーセントだった。実装面では、公開済みの高速カーネル2種へ小さな差分で移植し、対象のグラフィックスプロセッサ上で全ての評価文脈長で元の実装を上回った。70億パラメータ級の長文脈モデルで100万トークンの文脈を処理する全体測定では、項の57パーセント削減のもとで1.31倍の高速化が得られた。実機測定に基づく研究であり、理論の削減率と実測の一致も検証されている。

## 問題設定

注意の費用は2か所に出る。入力処理では文脈長の2乗に比例するスコア計算、逐次生成では蓄積したキー・バリュー全体の読み出しである。どちらも文脈が伸びるほど重くなり、他の部分の最適化では相殺できない。正確なカーネルはメモリへの書き出しを避けて帯域を節約するが、掛け算の回数自体は全注意と同じである。つまり帯域の無駄は削れても、演算の無駄は残る。

近似で演算を削る従来方式は、削減の単位が粗かった。一定の距離より遠いトークンを丸ごと見ない窓方式は、遠距離の情報を構造的に失う。重要度を入力から推定して残すトークンを選ぶ動的方式は、削減量が実行するまで分からず、容量計画や遅延の見積もりができない。学習で選択器を作る方式は既存モデルへ後付けできない。不足していたのは、位置情報の担い手である周波数成分ごとに、見分けられる距離の内側だけを残すという細かい粒度の削減であり、本論文は回転位置埋め込みの波長がその粒度をモデル定数として与えることを使う。

## 手法のあらまし

まず注意スコアを周波数対ごとの寄与へ分解する。クエリとキーの各2次元対は固有の角速度で回転しており、スコアは相対距離だけの関数として、対ごとの余弦と正弦の項の和で書ける。次に対ごとに窓幅を決める。窓幅は波長に保持周期数を掛けた値と文脈長の小さい方であり、保持周期数の既定値は2である。相対距離が窓幅を超えた対の項はスコアの和から外す。高周波の対は近い距離でだけ残り、低周波の対は遠くまで残るため、距離が離れるほど有効な対の数は階段状に減る。

実装では、この規則をマスクの乗算ではなく、内積の縮約軸の切り取りとして実現する。距離が離れるほど外れるのは高周波側からであり、残る対は低周波側に連続して並ぶため、内積の長さを短くすることと等しくなる。あわせて窓の外のキー成分は共有メモリへ読み込まない。オンラインソフトマックスの最大値と正規化係数の更新、値ベクトルとの積、タイル分割は元のカーネルのまま変えない。窓を切れば元の実装とビット単位で一致する。削減率は、対の番号を連続量とみなす積分を解くことで閉形式が得られ、文脈長の対数で増え、保持周期数への依存も対数的である。

## 手法

### 1. 周波数対ごとの窓 — 位置を見分けられる距離の内側だけを残す

この機構が観測するのはクエリとキーの相対距離と、各周波数対の波長である。波長は回転の基数と次元から決まるモデルの定数で、入力からは計算しない。保持する状態は対ごとの窓幅の一覧表であり、モデルの設定から自動生成される。位置の拡大縮小を行う設定では、実効的な周波数へ読み替えて同じ規則を適用する。選択されるのは、相対距離が窓幅以下である対の項であり、配置や転送ではなくスコア計算の内積そのものが短くなる。これにより減るボトルネックは内積の演算回数と、キーの転送量である。値ベクトルの転送は減らない。追加で消費する資源は窓幅表の保持だけで無視できる水準である。失敗時の挙動がこの方式の個性で、窓の外の項を落としても低周波の対が残るため遠いトークンへの経路は切れないが、その対が担っていた細かい位置の見分けは失われる。意味の構造を持たない文字列から特定の値を正確に拾う課題ではこの損失が表に出て、既定の保持周期数では成績が大きく落ちる。ただし保持周期数を一様に64まで上げれば、項の29パーセントを削ったままで全注意の成績へ戻ることが示されており、失敗は固定された上限ではなく計算量との交換条件として調整できる。

### 2. 縮約軸の切り取りとしての実装 — カーネルの骨格を変えずに移植する

窓の規則は入力に依存しないため、各タイルで有効な対の集合は静的に決まる。実装はこの性質を使い、内積の開始位置を窓の境界まで進める形でカーネルへ入れる。境界は行列積演算の最小単位の倍数へ丸める。入力処理側のカーネルでは4ファイルに約300行の差分、逐次生成側のカーネルでは非同期読み込みの条件と内積の無効化に約100行の差分で移植された。最大値と正規化係数を逐次更新するオンラインソフトマックスの再帰、因果マスク、値ベクトルとの積は一切変更されていない。そのため窓を切った経路は元の実装とビット単位で一致し、移植の正しさを機械的に確認できる。減るボトルネックは演算とキー読み込みの両方で、理論上の削減上限に対して実測で85から96パーセントを回収できたと報告される。追加費用はコンパイル時に解決される分岐だけで、実行時の判定費用はほぼない。失敗条件はハードウェア側にあり、キー読み出しが帯域を支配しない小さいモデルでは逐次生成の利得が出ず、実測でも速度比が1.00倍にとどまった構成がある。つまり窓で削れるのは注意の内積が費用の主因である条件に限られる。

### 3. 削減率の閉形式 — 実行前に利得と代償を見積もる

削減率は、残る項の数を数えることで解析的に求められる。プリフィル全体では文脈長の対数に比例して増え、逐次生成の最終行でも同じ形で定数だけが異なる。対象モデルの32キロトークンでは閉形式が46.1パーセント、厳密な離散和が47.6パーセントで、積分近似の誤差の範囲で一致する。保持周期数を2倍にしても削減率の低下は対数的に小さいため、品質側の余裕を安く買える。文脈長が最大波長に保持周期数を掛けた値を超えると、残る項の数は文脈長によらない定数へ近づき、クエリあたり定数時間、全体で文脈長に比例する計算量になる。ただしこの漸近領域は現実の文脈長より何桁も先であり、論文の実験はすべて全トークンが低周波で到達可能な範囲にある。予測が外れる条件は、削減率が項の数の代理指標に過ぎず、ソフトマックスや値ベクトルとの積や転送を含まない点であり、論文は壁時計時間を別途実測して補っている。

## 評価

### まず見るところ

結論は2層で検証されている。第1層は全注意との近さで、学習範囲内では項を37から48パーセント削っても出力分布と最有力トークンの一致がほぼ保たれる。第2層は課題の絶対成績で、長文脈の参照や推論の成績は概ね維持されるが、構造のない文字列からの一点検索だけが既定設定で崩れ、保持周期数を上げると回復する。速度は理論の上限に対して高い回収率で実測され、文脈が長いほど利得が伸びる。注意すべき点は、速度測定が単一のハードウェア世代と単一リクエスト条件に限られることと、品質検証の中心が教師強制の指標であることである。

### 感度・スケーリング・ストレス条件

文脈長への感度は単調で、長いほど削減率も高速化も伸びる。最悪条件は構造のない文字列からの一点検索と、学習範囲を大きく超える外挿であり、後者では100万文脈で最有力一致率が0.77まで落ちる。逆にキー読み出しが帯域を支配しない小モデルでは速度利得が消える。保持周期数は対数的にしか費用へ効かないため、品質が落ちる課題では上げる判断がしやすい。

### 立ち上がり・内部挙動

学習や事前の探索は不要で、窓幅表はモデルの設定から即時に生成される。履歴学習やウォームアップもない。内部指標としては理論削減率と実測の項数が全条件で近似誤差の範囲で一致しており、予測可能性自体が検証されている。

## 既存研究との差

正確なカーネルの研究は計算の無駄を残したまま帯域の無駄を消す方向であり、本論文はその上に項の削減を重ねる。窓方式や排出方式はトークン単位で捨てるため到達可能性を失い、動的疎化は削減量が入力依存で予測できない。周波数を手がかりに使う先行方式も、周波数はトークン選択の材料に過ぎず、残したトークンは全周波数で計算していた。本論文の差は、削減の単位をトークンから周波数対の項へ移したこと、窓幅を波長から解析的に決めて削減率の閉形式を与えたこと、そして学習なしで既存モデルと既存カーネルへ後付けできる形にしたことにある。動的疎化と重ねて使えることも実測で示されており、競合ではなく直交する削減軸として位置付けられる。

## 限界・実装状況

- 近似であり無損失ではない。構造のない文字列からの一点検索では既定設定で成績が大きく落ち、課題ごとに保持周期数の調整が要る。
- 入力への適応は扱っておらず、窓は事前に固定される。内容によって必要な距離が変わる課題では動的方式に分がある場面がある。
- 削減率の理論値は項の数の代理指標であり、実際の時間は実測に依存する。値ベクトル側の計算と転送は削れていない。
- 速度の検証は単一のハードウェア世代に限られ、他の世代や提供基盤での再現は未確認である。
- 著者公式のコード公開先は一次資料で確認できず、移植は公開カーネルへの差分として説明されるにとどまる。
- 学習範囲を大きく超える外挿条件では品質の一致が崩れるため、外挿用途では全注意自体の劣化と合わせて判断が要る。

## 一般的な実装上の含意

注意の近似を設計するときは、捨てる単位をトークンではなく情報の担い手の粒度に合わせると、到達可能性を保ったまま計算を削れる場合がある。また削減量が実行前に解析的に分かる方式は、容量計画と遅延見積もりへ組み込めるため、運用上の価値が速度そのものに加わる。移植の観点では、数値経路を変えずに縮約軸だけを短くする形は、元の実装との一致を機械的に確認でき、高速カーネルへ近似を入れる際の安全な差分の作り方として再利用できる。逆に、近似の最悪条件は意味構造のない検索のような端的な課題に出るため、平均的な課題成績だけでなく、位置の精密さが要る課題を必ず別枠で測るべきである。
