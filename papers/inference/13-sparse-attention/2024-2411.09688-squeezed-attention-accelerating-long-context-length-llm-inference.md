# Squeezed Attention: Accelerating Long Context Length LLM Inference

> 固定長文脈のキーをオフラインで意味クラスタ化し、実行時クエリに関連するクラスタの元KVだけを読み込んで正確な注意を計算し、長文脈の帯域と演算を削減する。

## 概要

長文書解析やコード支援では、巨大な参照文書・システム指示が複数リクエストで共通することがある。通常の注意計算は各クエリに対して固定文脈の全キーを読み、全トークンとの内積を計算するため、文脈長に比例してKV帯域と演算量が増える。Squeezed Attentionは「固定部分なら事前に意味構造を整理できる」ことを利用する。

固定文脈のキーをオフラインでK-meansクラスタリングし、各クラスタを重心で代表させる。実行時は新しいクエリを全キーではなく重心と比較し、関連度の高いクラスタだけを選ぶ。その後は選ばれたクラスタ内の元キー・値に対して正確な注意を計算するため、選択後の注意値を重心で近似する方式とは異なる。Tritonで重心比較と疎なFlashAttentionを実装し、長文脈のプリフィルと生成で4倍超の高速化を報告する。LongBenchではKV予算を3分の1へ削っても精度低下なし、最大8分の1でも0.5点未満の精度差を示す。

## 問題設定

一般的な疎注意は各リクエストで重要トークンを判定するため、その判定自体が長文脈走査を必要とすると帯域削減効果が薄れる。Squeezed Attentionは固定文脈を前提に、クラスタ構築をオフラインへ逃がす。実行時に必要なのは重心との比較だけなので、元KV全体をGPUの高速メモリへ読み出す前に候補を絞れる。

この前提は強い。毎ターン文脈の大部分が変化する通常チャットではオフラインクラスタの再利用性が低い。一方、同じ長文書へ多数の質問を投げる文書QAや、固定コードベース・規約文書を参照するサービスでは費用を多数リクエストへ償却できる。

## 手法

### 固定KVのオフラインクラスタリング

固定文脈を一度プリフィルして各層のキーを得た後、K-meansで意味的に近いキーをクラスタ化する。各クラスタには重心と、所属する元トークンの位置を保持する。重心は検索用の小さな索引であり、最終注意値の代用品ではない。

### 実行時のクラスタ選択

新しい入力から得たクエリベクトルを重心群と比較し、関連するクラスタを選ぶ。ここで候補が絞られるため、固定文脈の全KVを毎回読み出す必要がない。選択が外れると本来重要なキーを落とすため品質が下がるが、保持予算を増やせば品質と帯域の交換条件を調整できる。

### 正確な疎注意

選ばれたクラスタに属する元キー・値を集め、そこに対して通常と同じ注意計算を行う。したがって近似は「どのキーを候補に残すか」にあり、残したキーに対する注意値は正確に計算する。論文はこの不規則アクセスを効率化するため疎FlashAttentionのTritonカーネルを用意する。

### 階層重心探索

重心数そのものが大きくなると重心比較も線形走査になる。そこで重心を階層化し、上位重心から関連枝だけを降りる探索へ変える。固定文脈長 n に対して候補探索を線形から対数的に近づける狙いがあり、超長文脈で索引探索が新しい律速になることを避ける。

## 評価

### 代表的な評価条件

| 項目 | 代表設定 |
|---|---|
| 対象 | 固定部分が大きい長文脈LLM推論 |
| 実装 | Triton重心比較 + 疎FlashAttention |
| 品質評価 | LongBenchなど長文脈ベンチマーク |
| 性能評価 | プリフィル、生成の注意処理 |
| 可変条件 | KV保持予算、クラスタ選択量、文脈長 |

### 代表的な評価結果

| 条件 | 指標 | 結果 | 読み取れること |
|---|---|---:|---|
| 長文脈 | カーネル速度 | 4倍超 | KV読出しと注意演算の削減が両段階で効く |
| LongBench | KV予算 | 3分の1 | 精度低下なしで大幅削減可能 |
| LongBench等 | KV予算 | 最大8分の1 | 精度差0.5点未満 | 強い疎化でも品質劣化を小さく保つ条件がある |

4倍超は提案カーネル・注意経路の速度であり、アプリ全体のエンドツーエンド速度と同一ではない。また、オフラインK-means費用は固定文脈を多数回再利用することで償却する設計である。

## 既存研究との差

オンラインのトークン重要度推定は、重要度を求めるためにKVを広く読むと帯域削減と競合する。Squeezed Attentionは固定文脈を先にクラスタ化して検索索引を作ることで、この判定費用を実行経路から外す。重心そのものをKV代替として使うのではなく、重心で候補を選び元KVへ戻って正確な注意を計算する点も品質維持に重要である。

## 限界・実装状況

固定文脈が大きいことが前提で、会話履歴が毎回大きく変わる負荷では再クラスタリング費用と索引再利用性が問題になる。クラスタ選択は近似なので、保持予算を削り過ぎると重要キーを落とす。報告された4倍超は注意処理の実装評価であり、tokenizer、FFN、通信、スケジューリングを含むサービス全体の倍率ではない。
