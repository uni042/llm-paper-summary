# SeerAttention-R: Sparse Attention Adaptation for Long Reasoning

> 思考連鎖が1万トークンを超える推論モデルでは、1トークン生成するたび全過去KVを読む注意が重くなる。SeerAttention-Rは、元モデルを変えずに小さなゲートだけを学習し、「今回のクエリが見るべきKVブロック」を予測してデコード注意を疎化する。

## 概要

長い推論ではプリフィルよりデコードが支配的になりやすい。生成位置が進むほどKVキャッシュが伸び、各トークンの注意計算はより多くの過去キー・値を読み出すからである。疎注意でKVの大部分を飛ばせれば帯域と計算量を減らせるが、重要なブロックを外すと、その小さな誤差が後続の推論過程へ蓄積し、回答精度だけでなく生成長まで悪化する。

SeerAttention-Rはプリフィル向けSeerAttentionの自己蒸留型注意ゲート（Attention Gate, AttnGate）を自己回帰デコード向けに作り直す。元モデルの注意分布を教師信号として、軽量ゲートにブロック単位の重要度を予測させる。元LLMのパラメータは固定され、ゲートだけを0.4Bトークンで学習する。

システム側では、この粗粒度のブロック疎性を実際の速度へ変換するため、TileLangとTritonで専用のブロック疎フラッシュデコードカーネルを実装する。特にH100のTensor Coreを使いやすいようワーク分割を調整し、系列長8k〜128k、バッチ1〜16、疎性50〜90%で評価している。

## 問題設定

### プリフィル向けゲートをデコードへそのまま持ち込めない

元のSeerAttentionでは、クエリQとキーKをブロックごとに系列方向へプーリングし、小さくしたQ/Kから2次元のブロック注意分布を予測する。プリフィルでは多数のクエリが一度に存在するため、この設計が自然である。

デコードでは新しいクエリが基本的に1トークンずつ到着する。クエリ側を系列方向にプーリングする対象がなく、プリフィル用の構造をそのまま使えない。SeerAttention-Rはクエリプーリングを削除し、現在のクエリから直接ブロック重要度を予測する。

### 粗いブロックほど速いが、選択誤差には厳しくなる

疎注意のブロックサイズを16から64、128へ大きくすると、ブロック索引やゲートの管理量が減り、GPUで規則的に実行しやすい。一方、1ブロックを外した時に失うトークン数も増える。既存のQuestはブロックを大きくするとAIME精度が落ちるが、SeerAttention-Rは64/128でも比較的安定する。

したがって本論文の焦点は、単に「疎性を上げる」ことではなく、高い再現率で重要ブロックを予測し、ハードウェア効率の良い粗粒度疎性を許容できる状態を作ることにある。

## 手法

### 1. 全注意のブロック分布を教師にしてゲートを自己蒸留する

学習時には元モデルの全注意から、どのKVブロックが重要だったかという教師分布を作る。AttnGateはこの分布を近似するよう学習するため、追加の人手ラベルは不要である。

元LLMの重みは更新しない。OpenR1-MATH-220Kを使い、最大32kトークンへパックし、0.4Bトークン相当でゲートのみ学習する。global batchは16、800 step、AMD MI300X、DeepSpeed ZeRO-2、AdamW、学習率1e-3の設定である。

### 2. デコードではクエリをプールせず、GQAグループで疎性を共有する

SeerAttention-Rでは現在のクエリを線形射影して、KVヘッド数へ合わせる。現代LLMで多いグループ化クエリ注意（Grouped-Query Attention, GQA）では複数のクエリヘッドが同じKVヘッドを共有するため、そのグループ内で同じ疎ブロックマスクを使える。

これによりヘッドごとに別々の索引を持つより管理量を減らせる。ブロック単位のスコアを生成した後、選択されたKVブロックだけを疎デコードカーネルへ渡す。

### 3. 「トークン予算」または「閾値」でブロックを選ぶ

ゲートの連続値スコアを実際の疎マスクへ変換する方法は二つある。トークン予算方式では、例えば4kトークン分まで高得点ブロックを選び、モデル間の計算量を揃えやすい。閾値方式では一定スコア以上だけを残し、並べ替えを不要にできる。

固定予算は比較と資源上限管理に向き、閾値は系列長に応じて選択量を自然に変えやすい。論文では両者の精度―疎性交換を評価している。

### 4. TileLangカーネルで不規則な疎性をGPUへ載せる

ブロック疎性は計算量を減らしても、選択ブロック数が要求ごとに違うため、そのままではGPUの仕事量が偏る。実装では総ブロック数ではなく最大選択ブロック数を基に仕事を分割し、疎性による負荷不均衡を抑える。

H100ではクエリヘッドグループ数を64へパディングし、ワープグループ行列積命令（warp-group matrix multiply-accumulate, WGMMA）を使いやすくする。TileLang側がタイル化、ワープ特殊化、パイプライン化を適用する。

## 評価

### 評価条件

| 項目 | 条件 |
| --- | --- |
| 推論モデル | Qwen3-4B / 8B / 14B、DeepSeek-R1-Distill-Qwen-14Bなど |
| 推論ベンチマーク | AIME24、AIME25、MATH-500、GPQA-Diamond |
| ゲート学習 | OpenR1-MATH-220K、0.4B tokens、最大32k、800 steps |
| 疎ブロック | 主設定64。32/64/128のoracleおよび16〜128のアブレーション |
| 注意予算 | AIME系2k/4k/6k/8k、MATH/GPQA系1k/2k/4k/6k |
| 比較 | 全注意、Quest、SeerAttention-R |
| カーネルGPU | NVIDIA H100 |
| カーネル範囲 | 系列長8k〜128k、batch 1〜16、疎性0.5〜0.9、64 Q heads / 8 KV heads / head dim 128 |
| カーネル比較 | FlashAttention-3、Triton疎カーネル、TileLang疎カーネル |

### 主要結果

| 条件 | 全注意 / 比較対象 | SeerAttention-R | 意味 |
| --- | ---: | ---: | --- |
| Qwen3-8B、AIME24、4k予算 | 全注意 74.5% | 72.3% | 4kだけ参照してほぼ全注意精度 |
| 同、8k予算 | 全注意 74.5% | 75.1% | 測定上は全注意と同等以上 |
| 同、2k予算 | Quest 13.3% | 56.6% | 強い疎化で選択精度の差が顕著 |
| 同、4k予算の生成長 | 全注意15.1k | 16.3k | 精度だけでなく余分な思考長も抑える |
| H100、90%疎性、長系列・大batch | FlashAttention-3 | 最大約8.6〜9倍 | 理論上限10倍へ近い |
| H100、TileLang vs Triton | Triton疎カーネル | 約1.7倍 | 疎性だけでなくカーネル設計が効く |
| H100、batch4、32k、90%疎性 | FlashAttention-3 | 最大約6倍 | 極端な大batch以外でも利得 |

AIME24で全注意の生成長は15.1kトークンである。Questは4k予算で22.9kまで伸びるのに対し、SeerAttention-Rは16.3kに抑える。疎注意の近似誤差が推論経路を遠回りさせると、「注意計算を減らしたのに生成トークン数が増えて総計算量が戻る」ため、この生成長は重要なシステム指標である。

Qwen3-14Bのoracle選択では2k予算で各課題がほぼ無損失になり、そもそも長推論注意に大きな疎性余地があることも確認している。一方、学習ゲートによる実際のSeerAttention-RではAIME系に4k程度必要であり、oracleとの差が今後の改善余地である。

## 既存研究との差

Questは実行時の近似スコアで重要KVブロックを探すのに対し、SeerAttention-Rは元モデルの注意分布を自己蒸留した学習ゲートを使う。その追加学習により、より大きな64/128トークンブロックでも選択精度を維持しやすい。

元のSeerAttentionとの差は対象フェーズである。SeerAttentionは長文プリフィル向けにQ/K双方をプーリングするが、SeerAttention-Rは自己回帰デコード向けにクエリプーリングを除き、GQA共有疎性と専用フラッシュデコードカーネルを導入する。

## 限界・実装状況

「近無損失」は固定の注意予算と評価課題での実測であり、厳密な無損失手法ではない。予算を2kまで下げるとAIME精度は明確に落ち、誤った疎選択は生成長も増やす。

カーネル最大9倍は90%疎性におけるカーネル単体の値であり、モデル全体のエンドツーエンド9倍を意味しない。ゲート計算や他レイヤ、MLP、サンプリングは残る。また短系列・batch1ではGPUを十分埋めにくく、長系列・大batchほど利得が大きい。

公式実装はMicrosoftのSeerAttentionリポジトリで公開されている。
