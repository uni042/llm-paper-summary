# Adaptive Layer-skipping in Pre-trained LLMs

> tokenごと・layerごとに通常のattention+FFNを実行するか小型adapterだけで済ませるかを選び、skipしたtokenのKVは残すことで文脈を保ちながら計算量を減らす。

## 概要
FlexiDepthは、元LLMのweightを固定したまま、**tokenごと・layerごとにfull処理か軽いskip経路かを選ぶ**追加module型のdynamic depth手法である。

固定layer pruningと違い、簡単なcopy tokenは浅く、計算や判断が難しいtokenは深く処理できる。各可変layerには小型routerとadapterだけを追加し、元attention/FFNは更新しない。

特徴的なのは、skipしてもhidden stateを単純に素通しせず小型adapterで補正し、さらに将来tokenがそのtokenを参照できるようK/Vは残すこと。これにより固定skipより品質をかなり守れる。

Llama-3-8Bでは平均8 layer skipでもbenchmark平均100.7%を維持する一方、論文自身が**wall-clock speedupは未達**と報告する。tokenごとに異なる経路とadapter/routerの追加weight accessが、減ったFLOPsを相殺するためである。

## 手法のあらまし

### 1. 各可変layerにfull経路と軽いskip経路を持つ

routerが各tokenに対してgating score `g` を出す。

- `g > τ`：通常のattention + FFNを実行
- `g ≤ τ`：重いblockをskipし、小型adapterだけを通す

つまりlayer自体を削除するのではなく、**tokenごとに二つの経路から選ぶ**。

### 2. Routerは小さいMLPを使う

routerはhidden dimensionを `d/16` 程度へ一度縮めて戻す小型MLPを使う。

単一linearだけのrouterでは品質が大きく落ちたため、tokenがfull layerを必要とするか判断するには、少し複雑な変換が必要だったと解釈できる。

### 3. Skip時も小型adapterで表現を補正する

attention/FFNを飛ばしたhidden stateをそのまま次layerへ渡すと、元modelが期待する表現からずれる。

そこでskip側にも中間次元1/16程度の小型FFN adapterを置く。

adapterなしの評価で品質が大きく崩れるため、FlexiDepthでは**「layerを飛ばす」より「重いlayer処理を安い近似変換へ置き換える」**と理解する方が正確である。

### 4. SkipしてもK/Vは残す

attention計算をskipするtokenでも、将来tokenがそのtokenを参照できるようK/Vは作ってcacheする。

つまり削るのは主にquery側attention計算やFFNで、過去tokenとしての文脈情報を消すわけではない。

K/Vを作らない評価では品質が落ちるため、長いgenerationで重要になる。

### 5. 0/1の経路選択を学習できるようにする

推論時はfull/skipを離散的に選ぶが、そのままではrouterへgradientを流しにくい。

そこで学習時だけ離散選択を滑らかに近似し、routerを学習できるようにする。論文では`SparseMixer`を使う。

### 6. Tokenごとの使用layer数を可視化して分析する

論文の`DepthMap`は、各tokenが実際に何layer使ったかを可視化したもの。

copy / repeatは浅く、summarize / continue / addition / multiplicationは深くなる傾向があり、単なる平均skip率だけでなく「どの種類のtokenへ計算を使ったか」を確認できる。

## 評価

### まず見るところ
- **結論:** token-adaptive routingで固定skipより大幅に品質を守れる。
- **品質:** Llama-3-8Bで8 layer skipしても平均benchmarkはほぼbaseline。
- **理論計算:** FLOPsは減る。
- **実速度:** **wall-clock speedupは未達**。
- **重要な示唆:** dynamic depthはalgorithmだけでなく、同じ経路のtokenをまとめるruntimeや専用kernelまで必要。

### 学習設定

| 項目 | 設定 |
|---|---|
| Base model | Llama-3-8B-Instructほか |
| 元LLM weight | Frozen |
| 学習対象 | Router + Adapter |
| Data | Tulu-v2 326k conversations |
| Training | 3 epochs |
| Hardware | 8×A100 PCIe 40GB、約7時間 |

### Llama-3-8B：主要benchmark

| Setting | MMLU | HellaSwag | WinoGrande | GSM8K | HumanEval | CoQA | 平均保持率 |
|---|---:|---:|---:|---:|---:|---:|---:|
| Vanilla | .673 | .706 | .744 | .679 | .299 | .784 | 100% |
| 4 layer skip | .663 | .724 | .756 | .695 | .390 | .810 | **106.5%** |
| 8 layer skip | .616 | .705 | .735 | .662 | .341 | .801 | **100.7%** |

4 layer skipでは一部taskがbaselineを上回る。

### 8 layer skip：固定skip系との比較

| Method | 平均保持率 |
|---|---:|
| FlexiDepth | **100.7%** |
| LaCo | 65.3% |
| MindSkip | 60.2% |
| LayerSkip型固定比較 | 43.9% |
| ShortGPT | 32.0% |

特にGSM8K/HumanEvalでは固定skipの崩れが大きい。

### モデルサイズとskip余地

| Model | 平均skip layer | 品質保持率 |
|---|---:|---:|
| Llama-2-13B | 6.42 | 100.2% |
| Llama-3-8B | 6.25 | 102.1% |
| Qwen-2.5-3B | 1.49 | 101.5% |

小型modelほど冗長性が少なく、skipできるlayerが減る。

### Tokenごとの平均使用layer数

| Task type | 平均使用layer |
|---|---:|
| Copy | 21.95 |
| Summarize | 28.65 |
| Continue | 30.27 |
| Repeat | 20.09 |
| Addition | 22.45 |
| Product | 23.90 |

### 各部品を外した時の品質

| 変更 | 品質保持率 |
|---|---:|
| Full FlexiDepth | baseline近傍 |
| Linear router | 68.7% |
| KVを作らない | 84.3% |
| Adapterなし | 28.1% |

adapterとKV保持が手法成立の中心である。

### 実速度が伸びない理由

- tokenごとにfull/skip経路が分かれる
- routerとadapterのweight accessが増える
- GPU kernelが同じ処理をする大きなbatchを作りにくい
- 実行経路の管理とmemory trafficがFLOPs削減を相殺する

このため、**algorithm上は省計算でも現状runtimeではwall-clock改善なし**。
