# 生成時の関連視覚情報移動が静的な視覚トークン削減を破綻させる条件とDSTP

## 概要

この論文が扱うのは、大規模マルチモーダル言語モデル（MLLM）の**推論時の視覚トークン削減**である。画像から作った多数の視覚トークンを減らせば、事前入力処理（prefill）の計算と、生成中に参照する鍵・値キャッシュ（KV cache）の負荷を抑えられる。FastV、DivPrune、VisionZipなどは、画像を受け取った時点で重要と判断した視覚トークンだけを残す。しかし図形の数学問題のように、解答途中で注目すべき位置が変わる課題では、最初に不要とされたトークンが後で必要になる。削除を不可逆にしたままでは、その情報を取り戻せない。

著者らは、事前入力時と生成中の視覚注意分布を比較し、必要な視覚情報が生成段階ごとに変化する現象を**関連視覚情報移動（Relevant Visual Information Shift; RVIS）**と名付けた。単に出力が長いから移動するのではなく、数学的推論の段階的な情報要求が変わることと関係する、と長さを統制した比較で示す。そのうえで、生成中の注意分布が初期状態から変化した時だけ、退避しておいた視覚トークンを選び直す**生成段階移動対応トークン削減（Decoding-stage Shift-aware Token Pruning; DSTP）**を提案する。モデル重みの再学習は必要とせず、既存の削減方式に追加する構成である。

主な実測では、Qwen3-VL-4Bで視覚トークンを33.3%残すFastVのMathVerse正答率32.23がDSTP追加で52.54へ上昇した。削減なしの61.29には届かないが、同じ初期保持率のまま大きく回復する。実測の例当たり時間も119.35秒から102.55秒へ減った。一方、InternVL3.5-8Bでは同条件の正答率21.57が40.22へ回復したものの、例当たり時間は9.14秒から9.99秒へ**悪化**した。速度向上を全モデルで保証する技術ではなく、品質と実行資源の交換関係を改善する方法として評価する必要がある。

## 問題設定：最初に選んだ視覚情報は最後まで十分か

一般的な視覚言語モデルは、視覚符号化器から得た視覚トークン集合 $X_v\in\mathbb{R}^{N_v\times d}$ と質問のテキストトークンを結合し、自己回帰的に回答を生成する。事前入力段階での注意重みや画像特徴に基づいて保持する $k$ 個を選べば、以降の注意計算の対象を減らせる。静的削減の典型は、最後の入力テキストトークンから視覚トークンへの注意重みの上位 $k$ 個を残し、それ以外を削除する操作である。こうして捨てた領域は後の生成段階から参照できない。

単純な画像質問応答（Visual Question Answering; VQA）では、質問が物体や色など一つの局所情報を求める場合が多く、事前入力時に選んだ領域で回答できることがある。ところが視覚数学推論（Visual Math Reasoning; VMR）では、図形の辺、角度、数字、選択肢を順番に確認する必要がある。最初に選んだ領域だけを残すと、次の推論段階に必要な数字や記号が失われる。したがって「トークンを少なくしても単純VQAの正答率が保たれた」という実験だけでは、長い視覚推論での削減品質を評価できない。

著者らは事前入力時の注意ベクトル $a_{t_0\to v}$ と、生成時刻 $l$ の注意ベクトル $a_{t_l\to v}$ の**余弦類似度**を計算し、注目領域の安定性を観測した。VQAでは初期注意との類似度が高い状態が続く一方、VMRでは急落が頻発する。出力長を揃えた比較でもVMR側の移動が多く、1〜512トークンの短いVMR応答ですら2,048〜4,096トークンの長いVQA応答より移動回数が多いという傾向が示された。これは回答長だけを削減失敗の説明変数にできないことを示す。

また、4,096トークンで打ち切られた標本を除き、VQAとVMRを各276例に揃えて移動頻度を比較した。初期注意との類似度が閾値0.7を下回る谷を一つの移動事象として数え、移動回数別にFastVの成功率を集計すると、移動が多いほど静的削減後の正答維持率が下がった。相関の観測であってすべての失敗に単一の因果要因を証明したわけではないが、削減によって失われる情報と推論段階の要求が食い違うという機構上の説明を与える。

## 手法

### 1. 初期削減と復帰可能な退避集合

DSTPはFastVなどの基底削減方式が事前入力段階で選んだ $k$ 個の視覚トークン $X_v^{Pruned}$ をそのまま利用する。追加の違いは、削減された残り $N_v-k$ 個を完全に破棄せず、**退避視覚トークン集合** $X_v^{Reserved}$ として保持する点にある。初期選択に使った注意ベクトルも、後の生成中の注意状態と比較する基準（アンカー）として保持する。基底方式を再学習する必要はないが、退避集合を保持する追加メモリ費用はゼロではない。

この設計は、最初から全トークンを毎段階処理するのではなく、普段は短い視覚列を使い、情報要求が変化したと判断した時だけ追加トークンへアクセスする。したがって削減率と正答率の両方に関係する制御は、初期選択だけでなく、**いつ・どれを・何段階復帰させるか**の三つへ分解される。

### 2. 関連視覚情報移動検出（Relevant Visual Information Shift Detect; RISD）

RISDは生成トークン $l$ において、現在保持している視覚トークンへの注意ベクトル $a^{Pruned}_{t_l\to v}$ と、初期アンカー $a^{Pruned}_{t_0\to v}$ の余弦類似度 $s_l$ を計算する。$s_l$ が固定閾値 $\tau$ を下回ると、モデルが事前入力時と異なる視覚領域を必要としている可能性があると判断し、次の復帰処理を起動する。論文の主要実験では $\tau=0.75$ を使う。原因解析の移動事象を数える閾値0.7と、実際の制御閾値0.75は用途が違うため混同しない。

検出入力はモデルが既に計算している注意の重みであり、新たな生成モデルや分類器は不要である。もっとも、注意類似度が低いことが必ず「削除済みの画像領域が必要」を意味するわけではない。誤検出すると復帰と再評価の費用が発生する。逆に閾値が低過ぎれば本当に必要な視覚情報の移動を見逃す。この費用と検出感度の関係は、閾値の感度実験で確認する必要がある。

### 3. 文脈保持型視覚トークン入替（Context-Preserving Visual Token Swap; CPTS）

RISDが移動を検出すると、CPTSは現在の生成クエリ $q_l$ を使い、通常保持している視覚トークンに加えて、退避集合 $X_v^{Reserved}$ に対する注意の重要度も計算する。両者を連結した重要度ベクトルから上位 $k$ 個を再選択し、現段階で必要そうな視覚集合 $X_v^{Pruned,l}$ を得る。初期に捨てた領域がこの上位集合へ入ることで、数学的推論の後半に必要な図形・数字などを再び参照できる。

ただし新集合で旧集合を全面置換すると、直前まで利用していた画像文脈を失い、推論が不連続になる可能性がある。そこでCPTSは初期保持集合と新集合の**和集合** $X_v^{CP,l}=X_v^{Pruned}\cup X_v^{Pruned,l}$ を作る。集合の大きさ $k^*$ は $k\le k^*\le 2k$ であり、復帰中だけ通常より多くの視覚トークンを処理する。論文の主要実験ではこの和集合を $L=20$ 生成段階の間保持し、その後は初期集合へ戻す。これにより、画像の新しい情報を参照しながら初期文脈を一時的に保つ。

CPTSの出力は、推論中に実際に参照する視覚トークン集合の変更である。恒久的に全視覚トークンへ戻すわけではなく、必要時にだけ一時的な拡張を行う。追加費用は退避トークンの保持、復帰時の重要度再計算、和集合に対する注意処理であり、復帰頻度が多い難問ではこれらが積み重なる。したがって理論演算量の微増だけを根拠に、すべての実機で遅延増が無視できると解釈してはならない。

### 4. 一連の実行経路と従来法との差

実行順は、(1) 基底方式で視覚トークンを選び残余を退避、(2) 初期注意をアンカー化、(3) 生成時にRISDが類似度を監視、(4) 閾値を割ったらCPTSが退避集合も含め再評価、(5) 初期集合と新集合の和集合を $L$ 段階だけ使用、(6) 初期集合へ戻る、という流れである。検出されない期間は基底方式と同じ削減状態を使う。

FastVは言語モデル内部の注意重みを用いて重要トークンを選ぶ。DivPruneは視覚埋め込み間の多様性を基準に静的な保持集合を選ぶ。VisionZipは視覚符号化器の特徴から圧縮する。これらは「最初にどのトークンを選ぶか」が異なる一方、選択後に捨てたトークンを必要に応じて復帰する能力を標準では持たない。DSTPはその後段の問題を扱うため、基底方式を置き換えるというより、既存の選択結果を利用する追加機構である。

## 評価条件

一次論文の主要評価は、複雑な視覚推論と比較的単純な画像理解を分け、同じ初期削減率で基底方式単体とDSTP追加を比較する。以下の数値は論文の表1〜4および付録の演算量表から取り出したもので、各行のモデル・保持率・課題・指標を固定して読む必要がある。

| 項目 | 実験条件 |
|---|---|
| 言語モデル | Qwen3-VL-4B、InternVL3.5-8B |
| 実行装置 | NVIDIA L40S GPU（論文の全実験） |
| 基底削減方式 | FastV、DivPrune、VisionZip |
| 初期視覚保持率 | 33.3%、22.2%（視覚トークンをそれぞれ66.7%、77.8%削減） |
| 複雑な視覚推論 | MathVerse、WeMath、DynaMath、LogicVista、MMMU-Pro |
| 画像理解 | SQA、VQA^T、GQA |
| DSTP制御 | 移動検出閾値 $\tau=0.75$、文脈保持期間 $L=20$ |
| 主指標 | 正答率、元モデル比の精度保持率、例当たり遅延、総処理時間、毎秒生成トークン、平均生成長、GPUメモリ、推定演算量 |
| 追加解析 | 注意分布の移動頻度、検出・復帰の構成要素除去、閾値・保持期間感度、理論演算量 |

評価の「保持率」は元モデルの正答率を100%とした相対値であり、正答率の絶対値と異なる。例えばQwen3-VL-4BのMathVerseでは元モデル61.29、FastV単体32.23、DSTP追加52.54なので、保持率はそれぞれ100%、52.6%、85.7%である。保持率85.7%を正答率85.7%と誤読してはいけない。

## 評価結果

### 1. 視覚推論での正答率と保持率

| モデル・課題・初期保持率 | 比較対象 | DSTP追加 | 改善と解釈 |
|---|---:|---:|---|
| Qwen3-VL-4B、MathVerse、33.3%、FastV | 32.23 | 52.54 | +20.31ポイント。元モデル61.29には未到達 |
| Qwen3-VL-4B、MathVerse、33.3%、DivPrune | 33.90 | 50.25 | +16.35ポイント。選択原理の異なる方式にも有効 |
| Qwen3-VL-4B、MMMU-Pro、33.3%、FastV | 19.41 | 30.52 | +11.11ポイント。元モデル37.63より低い |
| Qwen3-VL-4B、MathVerse、22.2%、FastV | 25.88 | 42.76 | +16.88ポイント。より強い削減でも回復するが33.3%時より低い |
| InternVL3.5-8B、MathVerse、33.3%、FastV | 21.57 | 40.22 | +18.65ポイント。元モデル42.00に接近 |
| InternVL3.5-8B、MathVerse、22.2%、FastV | 20.06 | 38.94 | +18.88ポイント。保持率47.8%から92.7%へ上昇 |

Qwen3-VL-4Bの5つの推論課題を平均した元モデル比の保持率は、初期保持33.3%のFastVで55.68%、FastV+DSTPで82.90%、DivPruneで55.24%、DivPrune+DSTPで83.80%だった。InternVL3.5-8Bの同じ保持率では、FastVが56.66%から92.44%、DivPruneが63.55%から90.09%へ改善した。これは単一の視覚削減方式や単一の言語モデルだけに依存しない傾向を示す。ただし両モデルとも削減なしと同等の精度がすべての条件で回復したわけではない。

### 2. 画像理解・構成要素除去・失敗条件

単純な画像理解でも改善が見られるが、複雑な推論ほど差は大きくない。Qwen3-VL-4Bで保持率33.3%のFastVは、SQAで87.98、VQA^Tで74.82、GQAで60.04だった。DSTP追加では91.84、77.95、60.93へ改善した。これらの元モデルは93.42、81.57、61.82である。静的削減が比較的良好な課題では、復帰制御の追加による改善幅も相対的に小さい。

構成要素除去実験では、同じ頻度で無作為に復帰させる方式と、注意類似度の過去平均を閾値にする方式が比較された。Qwen3-VL-4BのMathVerseで、33.3% FastV単体32.23、無作為検出+CPTS 37.69、過去平均検出+CPTS 51.51、RISD+CPTS 52.54である。無作為に戻すだけでは同じ精度に達せず、移動検出のタイミングに意味がある。

また、RISDで検出しても初期トークンを捨てて新集合だけを使う「全面置換」ではMathVerse45.05、旧集合を単一トークンへ圧縮する統合では47.58であり、和集合を使うCPTSの52.54に及ばなかった。復帰を必要とする段階で初期文脈を維持することが、単なるトークン再選択とは独立の貢献である。全視覚トークンを復帰させる上限方式は53.04だったが、平均視覚保持率100%を要する。CPTSは平均38.1%で52.54となり、精度と保持数の両方を改善している。

### 3. 理論演算量と実測速度を分ける

Qwen3-VL-4Bで保持率33.3%のFastVの推定総演算量は2.676 TFLOPs、DSTP追加では2.683 TFLOPsであり、差は0.007 TFLOPs（約0.26%）だった。削減なしは3.795 TFLOPsである。保持率22.2%ではFastV 2.489、DSTP 2.496 TFLOPsで、差は同じ0.007 TFLOPsとなる。この表は論文付録の計算モデルで、生成長1,000トークンを仮定した演算量の見積もりである。実測GPU時間やメモリ転送時間そのものではない。

| Qwen3-VL-4B、MathVerse | 削減なし | FastV（33.3%） | FastV+DSTP（33.3%） |
|---|---:|---:|---:|
| 正答率 | 61.29 | 32.23 | 52.54 |
| GPUメモリ | 18.6 GB | 14.6 GB | 15.1 GB |
| 例当たり遅延 | 127.27秒 | 119.35秒 | 102.55秒 |
| 毎秒生成トークン | 19.30 | 24.99 | 24.11 |
| 平均生成トークン | 2,419.4 | 2,931.7 | 2,412.7 |
| 総処理時間 | 27時間51分28秒 | 26時間07分27秒 | 22時間26分49秒 |

この条件でDSTPはFastVより毎秒生成トークン数がわずかに低い。それでも例当たり遅延が短いのは、生成するトークン数自体が2,931.7から2,412.7へ減っているためである。**一トークンの生成処理が高速化したから全体が短くなったわけではない**。注意復帰による情報欠落の軽減が冗長な生成を減らした、という著者の説明はこの数値と整合するが、すべての入力で同じ挙動になるわけではない。

InternVL3.5-8BのMathVerseでは、削減なしの例当たり遅延11.79秒、FastV単体9.14秒、DSTP追加9.99秒だった。GPUメモリもFastV単体25.2GBからDSTP追加26.3GBへ増えた。DSTPの正答率は21.57から40.22へ改善するが、FastVより**約9.3%遅い**。品質回復を目的に許容できる費用かは、推論時間とメモリの制約次第である。Qwen3-VLとInternVLの結果を一括して「実測遅延が改善」とまとめるのは誤りである。

### 4. 閾値と保持期間への感度

論文は検出閾値 $\tau$ と一時復帰期間 $L$ の感度をMathVerseで検討している。$L=0$ または $\tau=0$ は復帰しない基底方式に相当する。保持期間が短過ぎると、推論が新しい視覚情報を参照し終える前に元集合へ戻り、正答率が大きく下がる。閾値を高くすると移動を検出しやすいが、復帰頻度が増えて資源負荷が上がり得る。論文の主要実験は $L=20$、$\tau=0.75$ の固定値を採用し、入力ごとの最適化はしていない。

視覚復帰集合の予算を変更する付録実験では、事前入力側を33.3%に固定し、生成時の再選択予算を変更した。生成側も33.3%で、全視覚トークンを使う上限に近い性能が得られ、11.1%に制限しても基底方式に対して明確な改善が残ると報告する。ただしこの感度結果から、任意のモデルや任意の長文脈で11.1%が十分だとは結論できない。

## 既存研究との差

FastVは言語モデル内の注意スコアに基づく静的削減、DivPruneは埋め込み間の距離を使う多様性重視の静的削減、VisionZipは視覚符号化器の特徴に基づく圧縮を行う。これらは主として**どの視覚トークンを最初に残すか**を決める。DSTPはその選択を尊重しつつ、生成中に必要な情報が移った時の復帰処理を加える点で異なる。高い保持率を最初から固定するより、低い保持率を保ったまま必要な段階だけ拡張する方が有利な場合を示した。

近縁の動的方式も存在するが、論文の主張は特定の画像選択器を新たに学習することではなく、事前入力の注意と生成中の注意を比較する軽量な検出機構、および初期集合を保持する和集合型の復帰機構の組合せにある。構成要素除去実験により、無作為復帰、過去平均閾値、全面置換、単一トークン統合を別々に比較し、どちらの機構が正答率へ寄与するかを切り分けている。

## 限界と適用上の注意

第一に、初期削減された視覚トークンを復帰できるよう保持するため、完全破棄する基底方式よりメモリ使用量が増える。Qwen3-VL-4Bの実測では14.6GBから15.1GB、InternVL3.5-8Bでは25.2GBから26.3GBへ増えた。保持率を同じにしても、メモリ節約率まで同じとは限らない。さらに注意類似度の監視と退避集合の重要度再評価も実行時の処理を追加する。

第二に、論文の付録は、選択した視覚トークンを**すべての変換器層へ一様に適用する**点を限界とする。浅い層が局所特徴を処理し、深い層が高次推論を担う場合、層ごとに必要な視覚領域は異なり得る。生成時に復帰しても、事前入力段階の層別処理で失った情報を完全に再現できるとは限らない。したがって品質が元モデルへ必ず戻るわけではない。

第三に、検出閾値と復帰期間は固定値であり、画像の複雑さ、推論の段階、注意パターンに応じて最適化されていない。閾値が不適切なら復帰漏れや過剰復帰が起こる。著者らは将来、強化学習などによって復帰の時点とトークン数を適応的に決める方向を挙げるが、今回の評価で実証された成果ではない。

第四に、実験はNVIDIA L40S上のQwen3-VL-4BとInternVL3.5-8Bを中心とする。長文脈の多数同時要求を扱うサービング、CPUへの視覚トークン退避、通信を伴う分散実行、他のGPUや低ビット量子化ランタイムへの統合は、この実験から直接保証できない。生成長と視覚トークン数が増えると復帰集合の管理費用も変わる。RTX 4070 Superの12GB環境での動作保証も本論文からは導けない。

最後に、正答率の改善とシステム性能の改善を区別する必要がある。Qwen3-VLでは生成長が減って全体時間も短縮したが、InternVLでは生成トークン当たりの負担とメモリが増え、全体時間は悪化した。したがって本研究の主たる貢献は、**静的削減で失われる視覚情報を生成中に取り戻すことで品質を回復する**点であり、実機速度向上はモデルと生成挙動に依存する二次的な効果である。
