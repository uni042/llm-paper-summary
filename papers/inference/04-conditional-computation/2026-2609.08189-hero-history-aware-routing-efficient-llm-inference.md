# Do Dynamic Routers Need Memory? HeRo: History-Aware Routing for Efficient LLM Inference

> 各層の局所状態だけでなく過去のゲート選択と残差変化を線形注意メモリへ蓄積し、Llama 3.1-8Bで26.87%のパラメータ計算を回避しつつ密モデル比100.24%の性能を保つ動的FFNルーティング。

## 概要
動的レイヤールーティングはトークンごとに不要な計算を飛ばせるが、多くの既存方式は各層の現在隠れ状態だけを見て局所的に実行・スキップを決める。しかし前の層でどの分岐を選んだかによって残差ストリームが変わり、その結果が次のルータ入力を変えるため、本来は深さ方向の逐次意思決定である。HeRoは過去のルーティングスコア、残差変化、深さ位置を明示的なルータ状態へまとめ、カーネル化線形注意で深さ方向に蓄積する記憶を導入する。各対象層では現在表現だけの局所ロジットと記憶から得た履歴ロジットを合成し、凍結済みFFNを実行するか軽量アダプタへ迂回するかを選ぶ。Llama 3.1-8Bではモデルパラメータの26.87%を実行せずに7ベンチマーク平均で密モデル比100.24%を達成し、より厳しい条件でも38.82%を回避しながら97.01%を保持する。

HeRoは動的ルーティングを深さ方向の経路依存な逐次意思決定として扱い、各トークンについて過去のルーティング状態を明示的に保持する。現在の表現に、深さ位置、残り対象層、直近の残差変化量と方向、過去の履歴スコアを加えてルータ状態を作り、カーネル化線形注意で以前の対象層の状態を定数サイズのメモリへ逐次集約する。現在表現だけを見る局所ヘッドと、記憶を読む履歴ヘッドのロジットを合算して凍結FFNか軽量アダプタを選択するため、バックボーンを変更せず過去の実行経路を次の判断へ直接渡せる。

代表結果として、Llama 3.1-8B・25%目標の性能保持は7ベンチマーク、α=1e-3、3乱数種でDenseおよび10種類の剪定/ルーティング基準に対して26.87±0.80%のパラメータを回避し、密モデル比100.24±0.59%。約4分の1のモデルパラメータ計算をトークン平均で迂回しながら、密モデルの集約タスク性能を実験誤差内で維持する。
## 問題設定
動的レイヤールーティングは、予測しやすいトークンには少ない計算、難しいトークンには多い計算を割り当てることで推論費用を下げる。しかし既存ルータの多くは各層で現在の隠れ表現だけを入力し、その層を実行するか飛ばすかを独立に決める。一方、ある層でFFNを実行するか迂回するかは残差ストリームへの更新量を変え、その結果が後続層のルータ入力を変える。また学習時の利用率損失は複数層のゲート値をまとめて正則化するため、目的関数も層ごとに独立ではない。現在の隠れ状態には過去の選択結果が間接的に含まれるものの、軽量ルータがそこからゲート履歴や残差変化を正確に逆推定できる保証はない。高い計算削減率ほど実行経路の差が蓄積するため、局所状態だけのルーティングでは品質劣化が大きくなりやすい。
## 新規性
HeRoは動的ルーティングを深さ方向の経路依存な逐次意思決定として扱い、各トークンについて過去のルーティング状態を明示的に保持する。現在の表現に、深さ位置、残り対象層、直近の残差変化量と方向、過去の履歴スコアを加えてルータ状態を作り、カーネル化線形注意で以前の対象層の状態を定数サイズのメモリへ逐次集約する。現在表現だけを見る局所ヘッドと、記憶を読む履歴ヘッドのロジットを合算して凍結FFNか軽量アダプタを選択するため、バックボーンを変更せず過去の実行経路を次の判断へ直接渡せる。
## 手法
### 手法のあらまし
HeRoはTransformerの全層を対象にするのではなく、候補となる複数のFFN層だけを動的ルーティング対象にする。注意層は常に実行し、対象FFNでは各トークンについて凍結済みの元FFNと学習可能なボトルネックアダプタのどちらか一方を選ぶ。推論時と学習時の両方で閾値0.5による単一分岐を使い、FFNを選べば通常の大きな計算を行い、アダプタを選べば小さい代替経路で残差更新する。

各対象層へ到達すると、まず注意後の現在表現を低次元へ符号化する。これに、対象層列のどこまで進んだか、残り対象層の割合、直前の対象層から今回までに生じた残差変化のノルムと前回変化とのコサイン類似度、直前の履歴スコアと累積履歴スコアという6つの経路特徴を加えて一つのルータ状態を作る。この状態により、現在の意味表現だけでなく『これまでどの程度計算を使い、残差ストリームがどう変化してきたか』を明示的に次の判断材料へする。

履歴メモリは深さ方向のカーネル化線形注意として実装する。各トークンの前向き計算開始時に64×64のメモリ行列と64次元正規化器をゼロ初期化し、対象層を進むたびに現在状態から問い合わせ・キー・値を作る。現在層では先に過去だけが入ったメモリを読み、現在状態に似た過去経路情報を履歴文脈として得る。その後、層ごとに学習した忘却率を使って古い情報を減衰しつつ現在状態を書き込む。この読み取り前・書き込み後の順序により、現在判断へ未来情報が混入しない。

ゲートは二つの経路から計算する。履歴ヘッドは現在状態、取得した履歴文脈、両者のコサイン非類似度から履歴ロジットを生成する。局所ヘッドは注意後の現在表現だけからロジットを生成する。この二つを足してシグモイドへ通し、閾値以上なら元FFN、未満ならアダプタを実行する。決定後、その結果で生じた残差変化と履歴スコアを次の層の経路特徴へ引き継ぐため、ルーティング系列が明示的な状態機械として接続される。

学習ではバックボーンを固定し、ルータ状態符号化器、深さメモリ、履歴/局所ヘッド、アダプタだけを更新する。言語モデル損失に、各トークンが対象層全体で使うゲート値の合計を二乗する利用率ペナルティを加える。係数を強くするとFFN実行を減らす圧力が増え、計算削減率と品質の動作点を調節できる。

### 経路状態の明示的符号化
現在の隠れ表現だけで過去の実行経路を推測させず、対象層内の進行位置、残り深さ、直前の残差遷移の大きさと方向、以前の履歴ゲートスコアを6個のスカラー特徴として直接与える。現在表現は48次元、補助経路特徴は16次元へ符号化し、合計64次元のルータ状態にする。アブレーションで位置状態や補助状態を除くと、実現スキップ率がほぼ同程度でも9課題平均保持率が完全版100%から97%台へ落ちるため、単に保守的にFFNを多く実行して性能を稼いでいるのではなく、経路情報そのものが判断精度へ寄与している。

### 深さ方向の線形注意メモリ
過去の全対象層状態をリストとして保存して通常注意を毎層実行する代わりに、正の特徴写像ELU+1を使ったカーネル化線形注意の集約行列と正規化器だけを保持する。各層は現在状態を問い合わせとして過去の集約を読み、層固有の忘却率でメモリを減衰させてから現在状態を書き込む。主設定のメモリ次元64では各トークンにつき64×64行列と64次元ベクトルで済み、対象層数が増えても履歴保存量を直線的に増やさない。メモリ読み取りだけを除くアブレーションでも保持率が98.02%へ低下し、経路特徴を持つだけでは完全版の効果を再現できないことを示す。

### FFNと軽量アダプタの単一分岐
対象層では注意計算を常に残し、計算量の大きい元FFNを実行するか、中間幅896のボトルネックアダプタへ迂回するかをトークン単位で選ぶ。スキップ時に層を完全な恒等写像にするのではなく軽量アダプタで小さな残差更新を入れるため、後続層へ渡す表現の崩れを抑える。バックボーン重みは凍結され、追加学習はルータ・メモリ・アダプタだけなので、事前学習済みモデル全体を再学習せず動的計算機構を付加できる。実行閾値は学習・推論とも同じで、学習時だけ軟らかい経路を使う方式との乖離も避ける。さらにゲート値または1-ゲート値を選択枝へ乗算するため、ハードな閾値判定自体を微分しなくても選ばれた枝を通じてルータへ勾配を返せる。これにより学習時と推論時の実行構造を一致させたまま、利用率損失との共同最適化が可能になる。

### 全体のデータ／制御の流れ
モデルの注意層は密なまま維持し、後半を中心とした候補FFNへHeRoルータとアダプタを挿入する。各トークンは対象層を通るたびに現在表現と経路特徴から状態を作り、履歴メモリを読んで局所/履歴ロジットを合成し、元FFNかアダプタを一つだけ実行する。実行後の残差変化を次の判断へ伝え、最後まで同じトークン専用メモリを更新する。バックボーンは共有・凍結なので、計算削減の制御は軽量な追加モジュールに局所化される。
## 評価条件
- **ハードウェア**: 主設定の学習は48GB NVIDIA RTX 4090Dを4基使用し、各学習runは約12時間。評価バックボーンはMeta-Llama-3.1-8B-Instruct、Llama-2-7B、Llama-2-13Bで、推論評価GPUの機種は一次本文では別途明記されていない。
- **ソフトウェア**: lm-evaluation-harnessを用いて評価する。バックボーンを凍結し、HeRoのルータ状態符号化器、深さメモリ、履歴・局所ルータヘッド、ボトルネックアダプタだけを学習する。最適化はAdamW、bfloat16混合精度、勾配チェックポイントを用いる。
- **比較対象**: Dense、LoRA dense reference、ShortGPT、Shortened-PPL、Shortened-Taylor、SliceGPT、D-LLM、SkipGPT-Joint、SkipGPT-RT、MoD-D、LLM-Pruner、LaCo
主設定はLlama 3.1-8Bで、25%目標では各バックボーンの後半MLPをルーティング候補とし、40%目標ではLlama 3.1-8Bの9〜32層へ候補を拡大する。Tulu-3 SFTの939,344例を1エポック、グローバルバッチ128、約7,339更新で学習し、系列長は2048へ切る。学習率1e-4、重み decay 0.01、最初の3%をウォームアップ、実行閾値0.5、履歴温度0.9。主比較は乱数種42/43/44の平均±標準偏差。7課題はOpenBookQA、PIQA、BoolQ、ARC-Easy、ARC-Challenge、WinoGrande、HellaSwagで、密モデルに対する課題スコア比の平均をRetainとして集約する。アブレーションではさらにGSM8KとHumanEvalを加え、経路状態、履歴分岐、メモリ読み取り、メモリ次元の寄与を分離する。
実モデルを学習・評価しており単なる解析ではないが、効率指標は『トークン平均で計算に参加しないモデルパラメータ割合』が中心で、実測のトークン/秒、GPUカーネル時間、端末間レイテンシ、エネルギー消費は報告されない。アダプタ、ルータ、線形注意メモリの実行費用もスキップ率に直接差し引かれていないため、パラメータスキップ率をそのまま壁時計速度向上と解釈してはならない。
## 主要結果
HeRoは25%前後の計算回避目標で三つのLlama系バックボーンすべてにおいて比較した静的剪定・動的ルーティング方式中で最高の集約性能保持率を示す。Llama 3.1-8Bでは実現パラメータスキップ率26.87%で密モデル比100.24%となり、40%級の厳しい条件でも38.82%を回避しつつ97.01%を保持する。履歴分岐やメモリ読み取りを除くアブレーションでは品質が低下し、特にGSM8KとHumanEvalのような多段推論・コード生成で差が大きい。メモリ次元32〜256では結果差が小さく、効果が単なる大容量状態に依存しないことも示される。

- Llama 3.1-8B・25%目標の性能保持 / 26.87±0.80%のパラメータを回避し、密モデル比100.24±0.59% (比較対象: Denseおよび10種類の剪定/ルーティング基準; 条件: 7ベンチマーク、α=1e-3、3乱数種) — 約4分の1のモデルパラメータ計算をトークン平均で迂回しながら、密モデルの集約タスク性能を実験誤差内で維持する。

- Llama 3.1-8B・40%目標の性能保持 / 38.82±0.84%回避、密モデル比97.01±0.70% (比較対象: SkipGPT-RTは40.20%回避で81.15%保持; 条件: 対象層を9〜32層へ拡大した厳しい計算予算) — スキップが多く経路差が蓄積する条件ほど、過去の選択を明示的に記憶する利点が大きくなる。

- Llama 2-7B・25%級 / 27.87±0.82%回避、94.38±0.54%保持 (比較対象: 同予算の比較方式中で最高Retain; 条件: 7ベンチマーク) — Llama 3.1だけでなく旧世代7Bでも最高の集約保持率を示すが、密モデル比では明確な品質低下が残る。

- Llama 2-13B・25%級 / 28.38±0.76%回避、94.49±0.59%保持 (比較対象: 同予算の比較方式中で最高Retain; 条件: 7ベンチマーク) — モデル規模を13Bへ上げても局所ルータより履歴認識方式が優位だが、100%品質保持ではない。

- 履歴除去アブレーション / 9課題平均Retain 97.35%（HeRo=100%基準） (比較対象: 完全版HeRo; 条件: Llama 3.1-8B、パラメータ回避26.41%対26.87%) — ほぼ同程度の計算回避で履歴分岐だけを除くと性能が落ちるため、完全版の利得は単にFFNを多く実行する保守性では説明できない。

- メモリ読み取り除去 / 9課題平均Retain 98.02% (比較対象: 完全版HeRo=100%; 条件: パラメータ回避26.28%) — 補助経路特徴だけでは不十分で、過去状態を線形注意メモリから取得する操作が追加情報を与える。

- メモリ次元感度 / 32〜256次元でRetain 100.00〜100.12%、平均正解率73.61〜73.66 (比較対象: 64次元主設定; 条件: Llama 3.1-8B) — 試した範囲ではメモリ容量にほぼ敏感でなく、巨大な履歴表現を持たなくても効果が得られる。

### 負の結果・境界条件
- HeRoは全バックボーンで密モデル性能を完全に維持するわけではない。Llama 2-7Bと13Bの25%級では保持率が約94.4%に低下し、Llama 3.1-8Bの40%級でも97.01%である。また効率評価はパラメータスキップ率を中心としており、ルータ、アダプタ、64×64深さメモリの追加演算を含む実測速度向上率は示されない。αを1e-4から1e-3へ強めるとスキップ率は13.19%から26.87%へ単調増加する一方、同一スイープ内の性能保持は約1.73ポイント変動し、計算削減を強めれば無損失ではない。メモリ次元を256へ増やしても64次元に対する改善はごく小さく、容量を増やすだけでは大きな追加利得はない。

### 結果の読み方
履歴認識の価値は、前の層を飛ばした結果として後続表現が通常経路からずれるほど大きくなる。40%級の厳しい条件でSkipGPT-RTとの差が大きくなることはこの説明と整合する。さらに履歴分岐・メモリ読み取り・経路特徴のどれを除いても性能が落ちるため、単一特徴ではなく『現在の状態』『直近の残差変化』『蓄積履歴』を組み合わせることがルーティング判断の安定化に効いている。
## 品質への影響
条件付き計算による近似なので、品質と計算量の交換条件がある。Llama 3.1-8Bの25%級では集約値が密モデルをわずかに上回るが、これは個別課題の変動と追加学習を含む評価であり、無条件に品質向上と解釈すべきではない。より厳しいスキップや別バックボーンでは明確な低下が残る。
## 既存研究との差
ShortGPT、Shortened LLaMA、LaCo、LLM-Pruner、SliceGPTなどの静的剪定は推論前に同じ構造を固定するのに対し、HeRoはトークンごとにFFN/アダプタ分岐を変える。Mixture-of-Depths、SkipGPT、DiffSkip、ルーティング-Tuningなど既存動的方式の多くは現在層の隠れ状態を中心に判断するが、HeRoは過去のゲートスコアと残差遷移を明示的な層間状態として伝える。RMoEも専門家選択に再帰状態を使うが、HeRoは混合専門家のエキスパート選択ではなく、デコーダ深さ方向のFFN実行/迂回を制御し、線形注意メモリと残差経路特徴を組み合わせる点が異なる。
## 限界
論文はパラメータスキップ率を推論計算削減の主要代理指標とし、実測トークン生成速度、端末間レイテンシ、GPU使用率、エネルギー、追加ルータ/メモリのカーネル費用を報告しない。そのため26.87%のパラメータ回避を26.87%の速度向上と読み替えることはできない。スキップ時も軽量アダプタを実行し、全注意層は密なままなので、実際のFLOPs削減はモデル全体パラメータ回避率より小さくなり得る。バックボーンはLlama 3.1-8B、Llama 2-7B/13Bに限られ、より大きなモデル、混合専門家モデル、長文脈、量子化モデルでの挙動は未評価である。HeRo自体を導入するにはTulu-3 SFT全939,344例を使った追加学習が必要で、完全な学習不要手法ではない。

## 研究上の位置づけ
条件付き計算・動的深さ系統の推論効率化研究である。重要な概念的貢献は、ルーティングを各層で独立した判定ではなく、前の選択が次の表現を変える経路依存な逐次制御として扱う点にある。この考え方はMoE エキスパート配置・キャッシュでも直前の選択履歴を状態として使う設計と親和性があり、将来は『過去にどのエキスパートを呼んだか』『どの層をSSD/CPUからロードしたか』を同じ履歴状態へ含め、計算スキップとデータ移動を共同制御する方向へ接続できる。ただし本論文自体はSSD、オフロード、実測サービング速度を扱わない。
