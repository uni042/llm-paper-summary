# 思考モデルの自己検証と早期終了

## 概要

長い思考連鎖（Chain of Thought; CoT）を生成する推論モデルは、最初に正解へ到達しても別の推論経路を探索し、同じ問題を何度も検証することがある。この過剰思考（overthinking）は追加の生成トークンを消費し、推論時間を増やす。原著は、モデルが途中回答の正しさを内部の隠れ状態に符号化しているかを調べ、その情報を使って不要な思考を終了できるか検証した。

推論系列を途中回答を含む複数の区間へ分割し、各区間の最後のトークンにおける最終層隠れ状態から、途中回答の正誤を二値分類する軽量な検証器（probe）を学習する。検証器の出力確率が高ければ、追加の思考を省いて途中回答を最終回答として採用する。DeepSeek-R1-Distill-Llama-8BのMATHでは、確信度閾値0.85で正答率88.2%を保ちつつ生成トークン数を約24%減らしたと報告する。閾値0.9以上では基準と同じ88.6%を維持しながら19%削減した。

ただし**生成トークン数の削減率はGPU実測時間の削減率ではない**。原著第5節の評価は生成した思考系列の途中回答を順に検査し、閾値を超えたところで系列を切り取って比較する手順である。オンラインで検証器を挿入したサービングシステムの最初のトークン遅延、処理率、VRAM消費、GPU時間を直接測定した結果ではない。これは推論時の停止方策に関する研究であり、低レベルのGPU実行最適化とは区別する。

## 問題設定

長い思考連鎖を用いる推論モデルは、複数の中間回答を提示し、その後で別解を試して最終回答を決めることがある。途中ですでに正しい答えを得ているなら、後続の探索は計算資源を無駄にする可能性がある。一方、早すぎる停止は誤答を確定させてしまう。停止時点を選ぶには、途中回答が正しい確率をできるだけ精度よく推定する必要がある。

一般的な自己評価では、モデルへ「正しいと思うか」と質問したり、別の大きな検証モデルで全文を採点したりする。これらは追加の生成・推論費用を伴う。原著は、推論モデル自身の隠れ状態に正誤の情報が含まれているなら、小さな分類器でその情報を取り出せるという仮説を検証する。学習済みの分類器を早期終了の判断に使えば、複雑な外部検証モデルを毎回起動することなく、思考の継続と終了を切り替えられる。

## 手法

### 1. 長い思考系列を途中回答ごとに区切る

まず数学・論理推論課題に対して、対象の推論モデルから長い思考系列を生成する。思考部分を段落で区切り、「待て」「再確認」「別の方法」といった再考の合図となる表現を検出し、新しい推論経路の開始位置を推定する。連続する段落を同じ経路としてまとめ、途中回答を含む区間を構成する。

各区間から途中回答を抽出し、問題の正解と照合して正誤ラベルを付ける。原著ではこの抽出・判定にGemini 2.0 Flashを用いる。途中回答を含まない区間は、近傍の回答を含む区間へ統合する。これにより各区間は「思考内容」「途中回答」「正しいかどうか」の三つを持つ訓練例になる。区間の作成とラベル付けは完全に自動化された正解検証器ではなく、別モデルによる抽出・判定の品質に依存する。

この段階は、推論中に新しい自然言語の説明を作らせるための処理ではない。過去に生成した思考系列を教師データとして構造化し、軽量な分類器を訓練するための前処理である。オンライン適用では区間境界の検出と隠れ状態の取得を実行中のモデルに接続する必要がある。

### 2. 中間回答の最終層隠れ状態から正誤を予測する

区間 $c_i$ の最後のトークン位置で、対象推論モデルの最終Transformer層の隠れ状態 $e_i$ を取得する。対応する正誤ラベル $y_i\in\{0,1\}$ と組にし、二値分類データ集合を構成する。分類器は2層の多層パーセプトロン（Multilayer Perceptron; MLP）であり、線形変換、ReLU、シグモイドを通して正答確率 $p_i$ を出力する。

推論モデルが強い場合、途中回答の大部分が正しく、正例・負例の数が不均衡になる。そこで原著は、正負の頻度比と追加係数を使った重み付き二値交差エントロピーで学習する。学習率、重み減衰、重み係数、MLPの隠れ次元を格子探索し、検証精度が高い候補からパラメータ数が最小のものを選ぶ。学習・検証は8対2で分割し、最大200エポック、バッチ64で訓練する。

原著の多くの条件では線形プローブでも有用な正誤予測が可能だった。これは途中回答の正誤情報が最終層隠れ状態から比較的簡単な境界で取り出せることを示唆する。ただしプローブの分類性能が高いことと、途中で停止した回答が必ず正しいことは異なる。分類器の確率校正と誤判定率を別途評価する必要がある。

### 3. 途中回答より前の隠れ状態も分析する

原著は、区間の末尾だけでなく、区間途中の段落の最後の隠れ状態を使って、次に現れる途中回答の正しさを予測できるかも検証した。区間全体の正誤ラベルをその区間内の各段落へ割り当て、段落の位置に応じて正誤分類器の性能を測る。これにより、答えが自然言語として完全に現れる前にモデル内部で正誤に関する情報が形成されるかを調べる。

MATHとR1-Distill-Llama-8Bでは、区間の早い位置にも予測可能な信号があるが、末尾へ近づくほど正誤予測の精度が改善した。論文図4では最終位置の分類精度が約79%で、10%、50%、95%位置ではそこからそれぞれ約14、10、5ポイント低いと報告する。確率校正の指標は途中で改善するが、早い段落の予測は末尾の予測より不確実である。

この実験は、正解の中間回答が完成する前に早期終了する実運用方式を確立したという意味ではない。原著の早期終了評価では、**途中回答が現れた区間の末尾**を停止候補として使用している。途中段落での予測可能性は将来の改良に向けた分析結果として区別する。

### 4. 確信度に基づく早期終了

学習済みプローブの出力を $p_i$ とし、確信度閾値 $Thr$ を設定する。思考系列の途中回答を順番に検査し、初めて $p_i>Thr$ となった区間で思考を終了し、その区間の途中回答を最終回答として採用する。閾値を低くすると早く止まりやすく、生成トークンを節約できる一方、誤答を早期に採用する危険が増える。閾値を高くすると停止は慎重になり、削減できるトークン数は少なくなる。

比較対象として、プローブの確信度を使わず、あらかじめ決めたm番目の途中回答で停止する静的早期終了を用いる。モデルがその数の途中回答を出さなければ、静的方策は停止せず最後まで生成する。正答率と、打ち切り位置までの生成トークン数を比較し、同じトークン数を使う条件でどちらが高精度かを測る。これは停止方策の有効性を測るための設計であり、プローブ推論を含むGPUカーネル時間を評価するものではない。

## 評価条件

| 観点 | 原著の設定 |
|---|---|
| 数学課題 | GSM8K、MATH、AIME |
| 論理課題 | KnowLogic。単一正解の例に絞って使用 |
| 推論モデル | DeepSeek-R1-Distill-Llama-8B/70B、DeepSeek-R1-Distill-Qwen-1.5B/7B/32B、QwQ-32B |
| プローブ入力 | 各途中回答区間の末尾トークンの最終層隠れ状態 |
| プローブ | 2層MLP、重み付き二値交差エントロピー |
| 分割・訓練 | 8:2の学習・検証、最大200エポック、バッチ64 |
| 分類指標 | ROC-AUC、期待校正誤差（Expected Calibration Error; ECE）、Brierスコア |
| 早期終了の主実験 | R1-Distill-Llama-8B、MATH、最大生成長10,000トークン |
| 早期終了指標 | 最終回答正答率、打ち切り位置までの生成トークン数 |
| 比較 | 無停止、固定区間数で停止、確信度閾値で停止 |

分類器の評価では複数モデル・複数データ集合を使うが、約24%削減という主要な早期終了結果は**R1-Distill-Llama-8BとMATH**に限定される。全モデル・全タスクで24%削減を実測したわけではない。生成トークン数は打ち切り位置から算出される指標であり、GPU実測秒数や電力量ではない。

## 主要結果

### 1. 正誤情報は隠れ状態から比較的よく取り出せる

原著図2では、同一分布の検証で多くのプローブがROC-AUC 0.7以上を達成した。R1-Distill-Qwen-32BのAIMEでは0.9を超える例もある。期待校正誤差は多くの条件で0.1未満だったが、原著表1にはQwen-1.5BのAIMEで0.14、Qwen-32BのAIMEで0.13、QwQ-32BのMATHで0.13という例もあるため、**全条件でECEが0.1未満**と断定してはならない。

| モデルと課題 | ECE | Brier | 意味 |
|---|---:|---:|---|
| R1-Distill-Llama-8B、GSM8K | 0.05 | 0.17 | 比較的良好な確率校正 |
| R1-Distill-Llama-8B、MATH | 0.03 | 0.14 | 同一分布で低い校正誤差 |
| R1-Distill-Qwen-7B、GSM8K | 0.02 | 0.11 | 数学問題の正誤信号が強い例 |
| R1-Distill-Qwen-1.5B、AIME | 0.14 | 0.12 | 難しい課題では校正が悪化する例 |
| QwQ-32B、MATH | 0.13 | 0.10 | モデル間で校正特性が異なる |

原著表1の値。ECEは予測確率と実際の正解率のずれを測る指標であり、低いほど良い。ROC-AUCが高くても確率校正が悪い場合、固定の閾値0.85をそのまま別タスクへ移すと、誤った早期終了が増える可能性がある。

### 2. 分布外データでは校正が崩れる場合がある

原著表2のR1-Distill-Llama-8Bでは、GSM8Kで学習したプローブをMATHへ適用するとROC-AUC 0.80、ECE 0.08だったが、AIMEへ適用するとROC-AUC 0.69、ECE 0.25へ悪化した。KnowLogicへ適用するとROC-AUC 0.56であり、数学から論理への一般化も弱い。MATHで学習したプローブをAIMEへ移した場合もECE 0.28となった。

この結果は、単一の正誤プローブを全分野へ再学習なしで適用する危険を示す。分類器の確信度を早期終了に用いるには、実際に対象となるモデルとタスクの分布で校正を確認する必要がある。特に難問や分布変化が大きい状況では、学習時に高い正答率を示したプローブでも停止閾値の意味が変わり得る。

### 3. 早期終了のトークン削減と精度

| 方策 | MATH正答率 | 生成トークン数の削減 | 備考 |
|---|---:|---:|---|
| 無停止 | 88.6% | 0% | 元の長い思考系列 |
| 確信度閾値0.85 | 88.2% | 約24% | 基準とほぼ同程度の精度 |
| 確信度閾値0.9以上 | 88.6% | 約19% | 基準と同じ報告精度 |
| 確信度閾値0.8 | 87.4% | 原著図5参照 | 同程度のトークン数を使う固定停止より高精度 |

原著第5節と図5による。閾値0.85での88.2%は無停止の88.6%より0.4ポイント低いため、「精度が完全一致」と言うのは不正確である。原著は実質的な精度を維持したと評価している。閾値0.9以上の条件では同じ88.6%を保ちながら19%削減したと報告する。

同程度のトークン数を消費する条件で、閾値0.8の確信度方式は正答率87.4%、固定区間数で停止する方式は約82.5%だった。固定停止と比べた約4.9ポイントの差は、問題によって正しい回答へ到達するタイミングが異なるため、途中回答の確信度に基づいて停止位置を選ぶことの有効性を示す。

### 4. 長い思考訓練との関係

原著は、長い思考系列を学習したR1-Distill-Llama-8Bと、短い通常回答を生成するLlama-3.1-8B-Instructの隠れ状態を比較した。通常モデルの正誤プローブは分類・校正の性能が低く、長い思考連鎖の学習を通じて途中回答の正誤情報が強く符号化される可能性が示唆された。ただし、訓練方法だけが原因であると厳密に同定した因果実験ではない。

## 既存研究との差

従来の推論時の計算量削減には、質問の難易度を事前予測して思考予算を設定する方法、思考文を短く学習させる方法、途中回答を外部検証器で採点する方法などがある。原著は、モデル自身の最終層隠れ状態に含まれる正誤情報を取り出す点が異なる。軽量なプローブの確信度を使って停止時点を選ぶため、すべての問題を同じ長さで打ち切る静的方式より柔軟である。

これは層単位の早期終了（early exit）とは別の意味である。Transformerの途中層でモデル計算を打ち切るのではなく、**思考トークン列の途中で生成を停止する**。また、投機的復号（speculative decoding）のように候補トークンを検証して同じ出力分布を保つ方式でもない。途中で回答を採用するため、停止時点によって最終回答が変わる可能性がある。

## 限界・未評価事項

**第一に、生成トークン数の削減を実行時間短縮と混同できない。** 原著は生成済みの長い思考系列を区間ごとに調べ、途中回答で切り取った場合のトークン数を比較する。オンラインでモデルの隠れ状態を取り出し、区間境界を検出し、プローブを走らせ、必要なら停止する実装には追加の処理費用がある。GPU時間、バッチスループット、KVキャッシュ使用量、最初のトークンまでの遅延、電力は主実験で測っていない。

**第二に、途中回答の抽出とラベル付けは外部モデルへ依存する。** 段落分割や再考キーワードの検出が誤ると、正しい区間境界を作れない。Gemini 2.0 Flashによる途中回答の抽出と正誤判定にも誤りがあり得る。推論時に別モデルを呼び出す設計ではないものの、プローブの学習データを構築する段階で外部モデルに依存している。

**第三に、確率校正は分布に依存する。** GSM8KからAIMEへの移行でECEが0.25へ悪化する例があり、数学と論理の間でも一般化が弱い。固定閾値0.85を未知のモデルや課題へ流用すると誤った停止判断が増え得る。信頼性を確保するには、対象モデル・対象分野で校正をやり直す必要がある。

**第四に、約24%削減は特定モデル・特定課題の結果である。** R1-Distill-Llama-8B、MATH、最大10,000トークンの条件で得た結果であり、Qwen-32B、QwQ-32B、一般対話、コード生成、複雑な証明へそのまま外挿できない。高い正答率を維持できる閾値もモデルや問題分布で変わる。

**第五に、停止後の回答品質は途中回答の信頼度に左右される。** 閾値0.85の正答率88.2%は無停止の88.6%よりわずかに低い。途中で正答へ到達していても、検証器が確信を持てなければ生成を続ける。逆に誤答に高い確信度を与えると、後続の自己修正機会を失う。トークン数を減らすことだけを目的にすると精度を犠牲にし得る。

**第六に、隠れ状態を取得できる環境が前提である。** API経由でテキストだけを受け取るブラックボックスモデルでは最終層隠れ状態へ直接アクセスできない。プローブの学習と推論時利用にはモデル内部を操作できる実装が必要であり、既存サービング基盤へ追加するにはフックやメモリ転送の設計が必要になる。
