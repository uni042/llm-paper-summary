# Learned Token Pruning for Transformers — 学習型閾値によるTransformer推論のトークン剪定

## 概要

この論文の対象は、入力文の全トークンを全Transformer層で処理するために生じる推論計算量である。BERT系の双方向エンコーダでは、注意計算のトークン対が入力長の二乗に比例して増える。後段の層で分類にほとんど寄与しない語まで残すと、注意と全結合層の演算を繰り返す。学習型トークン剪定（Learned Token Pruning; LTP）は、各層の注意確率から「他のトークンにどれだけ参照されるか」を計算し、**層ごとに学習した閾値**より重要度が低いトークンを以後の層から除外する。上位k件を求める整列・選択処理を使わず、入力ごとに残すトークン数を変えられる点が特徴である。

RoBERTa-baseの言語理解・質問応答を用いた評価では、ベースラインに対する正解率低下を概ね1ポイント以内に制限した条件で、計算量は最大2.10倍相当減少した。実機での推論スループットはIntel Haswell CPUで最大約1.9倍、NVIDIA V100 GPUで最大約2.0倍と報告される。ただし**演算量削減倍率と実機スループット倍率は別の測定**であり、自己回帰型の生成LLMやKVキャッシュ付きデコードに同じ倍率を外挿することはできない。一次資料としてKDD 2022の原論文に加え、筆頭著者が2023年に公表した同方式の31ページの学位論文（UC Berkeley EECS-2023-119）の方法・評価・議論を参照した。

## 問題設定と既存研究との差

既存のトークン削減方式には、入力集合全体に対して層ごとの残存長を固定するPoWER-BERTや長さ適応Transformer（Length-Adaptive Transformer; LAT）がある。こうした設定は学習集合での平均的な長さに最適化されるため、実運用で短い文が多いと削除が足りず、逆に長い文へ同じ削減率を適用すると重要語まで落とす。SpAttenは入力長に比例して削除数を変えるが、**同じ長さで内容が異なる文**の必要トークン数を区別できない。TR-BERTは強化学習によって削除方針を獲得するが、方策探索と学習収束の費用が問題となる。

また従来の方式は注意スコアから重要な上位k件を抽出することが多い。上位k件選択は単純な比較と異なり、候補の順位付け・選択を必要とする。専用ハードウェアがなければ、削除による後段の節約を選択処理自身が相殺する可能性がある。LTPは**絶対閾値との比較だけ**で残すか否かを決め、削除数は各入力の重要度分布に委ねる。固定長の剪定方針や上位k件選択の双方を置き換える設計である。

対象モデルはRoBERTa-baseを中心とする双方向エンコーダである。重みを疎にする剪定とは異なり、トークンという系列方向の要素を構造的に減らすため、後段の行列演算を実際に短い系列で実行できれば汎用CPU/GPUでも利益が出る。一方、各トークンを除去したあとの系列を詰め直す処理、バッチ内で長さが揃わない問題、タスク精度との交換条件が残る。

## 手法

### 1. 注意確率を使ったトークン重要度

層 \(l\) のトークン \(x_i\) に対し、各注意ヘッドで他トークンから受ける注意確率を集計し、ヘッド数と系列長で正規化した値を重要度 \(s^{(l)}(x_i)\) とする。直感的には、他の位置が繰り返し参照するトークンほど次の層でも残す価値が高いとみなす。単一ヘッド・単一クエリの局所値ではなく、**ヘッドと系列全体から受ける注意の平均**を使う点が、元の注意行列を剪定判定へ接続する要である（著者学位論文の式3.6–3.7）。

各層に閾値 \(\theta^{(l)}\) を設け、\(s^{(l)}(x_i)>\theta^{(l)}\) なら保持、それ以外なら削除する二値マスク \(M^{(l)}(x_i)\) を構成する（式3.8）。この判定は各トークンについて一回の比較でよい。ある層で削除したトークンは**後続の全層の注意・全結合計算からも除く**ため、後段ほど処理する系列が短くなる。閾値が同じでも入力内容によって重要度分布が変わり、削除される個数は異なる。ここが入力長だけに比例する剪定や固定残存長との本質的な違いである。

### 2. 微分可能な軟マスクで閾値を学習

二値マスクをそのまま使うと、削除された位置から勾配が伝わらず、比較演算の閾値も勾配法で更新できない。そこで学習中は、\(\widetilde M^{(l)}(x_i)=\sigma((s^{(l)}(x_i)-\theta^{(l)})/T)\) というシグモイド型の軟マスクを使う。\(T\) は温度で、小さいほど二値判定に近づく。軟マスクを層出力の活性へ乗じることで、低重要度位置の寄与を弱めつつ、閾値付近のトークンから閾値への勾配を確保する（式3.9–3.11）。

精度損失だけで学習すると、トークンを残すほど損失を小さくしやすいため、閾値が剪定を促さない方向へ偏る。LTPは全層の軟マスクのL1ノルムを正則化項として加え、目的関数を \(L_{\mathrm{task}}+\lambda L_{\mathrm{reg}}\) とする（式3.12）。\(\lambda\) を大きくすると残存トークンへの罰則が強くなり、より積極的に削除する。したがって\(\lambda\) は「品質をどこまで守るか」と「どこまで計算量を下げるか」を選ぶ主要な制御値であり、単なる後処理パラメータではない。

### 3. 学習から推論への三段階

まず対象タスクへ適応済みのモデルに軟マスクを組み込み、**モデル重みと層別閾値を同時に学習**する。次に閾値を固定してマスクを二値化する。最後に硬い剪定を適用したままモデル重みを追加で微調整する（学位論文のAlgorithm 1）。これにより、学習時の滑らかなマスクと推論時の実際のトークン削除とのずれを調整する。実行時は学習済み閾値を使うだけで、追加の方策ネットワークや上位k件選択は必要ない。

推論時の処理順は、入力系列を各Transformer層へ通し、注意確率から重要度を計算し、層の閾値と比較して残存位置を決め、保持トークンを連続した短い系列へ詰め、次の層をその系列で実行する、という繰り返しになる。重要なのは、マスクを0にするだけでは計算を減らせないことである。実装は削除済み位置を後段の行列演算から実際に取り除かなければならない。

### 4. 不規則長バッチを実機で処理する工夫

各入力で残存長が異なると、バッチ内で最長系列までパディングする素朴な実装では削減分が再び埋め草の計算へ変わる。著者はGPUの大きいバッチにNVIDIA FasterTransformerを利用し、パディングの動的除去・再挿入により、短くなった系列を無駄な空き位置なしで実行する。CPU実験では通常のパディング付きバッチでも改善を確認した。したがって**剪定アルゴリズム単体の利益と、バッチ実装が利益を回収できるかは別問題**である。

## 評価結果

### 正解率と演算量の対応

学位論文のTable 4.2では、無剪定とLTPの精度を併記し、約1ポイント以内の精度低下を許した各タスクでの演算量を比較している。次のGFLOPsは入力当たりの平均であり、右端の倍率は**演算量比**であって直接測定した速度倍率ではない。

| タスク | 無剪定精度 → LTP精度 | 無剪定 → LTP GFLOPs | 演算量比 | 読み取り |
| --- | ---: | ---: | ---: | --- |
| MNLI-m | 87.53 → 86.53 | 6.83 → 3.64 | 1.88倍 | 自然言語推論で約半分の演算量 |
| QQP | 90.39 → 89.69 | 5.31 → 2.53 | 2.10倍 | 0.70ポイント低下で最大級の削減 |
| QNLI | 92.86 → 91.98 | 8.94 → 4.77 | 1.87倍 | 入力長の異なる推論問題でも削減 |
| SST-2 | 94.27 → 93.46 | 4.45 → 2.13 | 2.09倍 | 短文感情分類でも節約が成立 |
| MRPC | 92.14 → 91.59 | 9.33 → 4.44 | 2.10倍 | 言い換え判定でも削減 |
| RTE | 77.98 → 77.98 | 11.38 → 6.30 | 1.81倍 | 表示値上は精度維持で演算削減 |
| SQuAD 2.0 | F1 83.04 → 82.25 | 32.12 → 16.99 | 1.89倍 | 質問応答では回答位置の欠落に注意 |

GLUEの多くのタスクでLATやSpAttenに対し、同じ演算量でより高い精度を示す。著者は最大約2.5ポイントの差を報告するが、すべてのタスクで勝つわけではなく、QQPではLATが一部の条件で僅かに上回る。剪定率を強めれば計算量はさらに減るが、精度を同時に維持できるとは限らない。

### 入力長分布のずれへの頑健性

固定残存長の方式は、学習時より長い入力を一律に短くしてしまう危険がある。著者は学習入力を評価集合の中央値より短いものへ制限し、評価入力を短・中・長の三群へ分けるストレス試験を実施した。最長群で、QNLIのLTP精度91.81に対しLATは75.37、QQPではLTP 91.37に対しLAT 82.17である。差はそれぞれ**16.44ポイント、9.20ポイント**で、同じような計算予算から出発した比較である（Table 4.4）。LTPは文ごとに残す量を変えるため、長い入力を固定比率で過剰削除する失敗を抑える。

この結果は「長文でも精度が全く下がらない」ことを意味しない。対象はRoBERTaによる分類タスクの特定分布ずれであり、無制限長の生成文脈や外部記憶を評価したものではない。またLATが長文でより低いFLOPsになるのは、性能上の利点ではなく、必要なトークンまで落とした副作用でもある。

### ハードウェア実測と選択演算の内部費用

CPUはIntel Haswell、GPUはV100でバッチサイズを変えてスループットを実測した。論文がまとめる最大改善はそれぞれ約1.9倍と約2.0倍で、計算量だけの理論値ではない。GPUではFasterTransformerによるパディング除去が利益を回収するために重要であり、バッチが大きくなるほど改善が強くなる傾向がある。絶対トークン毎秒の汎用的な値は提示されていないため、別GPUや別モデルへ倍率を移す根拠にはならない。

上位k件選択と閾値比較だけをIntel Haswell CPUで1000回測定した実験では、上位k件処理の遅延は系列長128で最大7.4倍、1024で最大33.4倍となった（学位論文§4.7）。これは**選択演算単体**の比較であって、モデル全体が33.4倍速くなるという主張ではない。閾値法の低い付帯費用を説明する内部指標である。

### 構成要素除去と複合圧縮

層別閾値を手で線形に設定する対照実験に対し、学習した閾値は同等の演算量で概ね高い精度を得る。つまり利益は「閾値にしたこと」だけではなく、**層・タスクに合わせて閾値を学ぶこと**にも依存する。別の実験では、8ビット整数への量子化と知識蒸留を組み合わせ、FP16の無剪定RoBERTa-baseと比べてビット演算数（BOPs）を最大約10分の1にし、精度低下を2ポイント未満に抑えた。これは演算形式の違いを含む複合圧縮であり、LTP単独の高速化倍率と混同できない。

入力別の剪定軌跡を観察すると、LATより平均処理トークン数がMNLI-mで25.86%、SST-2で12.08%少なかった。これは各入力で必要な長さを選ぶ設計の挙動を裏付ける。一方、質問応答SQuAD 2.0では、削除率を強めると「回答あり」の問題のF1が低下し、「回答なし」のF1が上昇するという非対称な変化を報告している。正答位置の証拠トークンが削除されると、回答開始・終了位置を特定できず、回答なしと判断しやすくなるためである。\(\lambda\) は全体平均F1だけでなく、この内訳を見て選ぶ必要がある。

## 限界

**対象モデルの制約。** 検証の中心はRoBERTa-baseによる文分類・抽出型質問応答であり、自己回帰型の大規模生成モデル、デコード時のKVキャッシュ再利用、混合専門家モデル（MoE）、複数GPUのサービングを直接評価していない。特に生成中の過去トークンを消す操作には因果整合性の問題があり、この方式の精度・速度をそのまま転用できない。

**精度との交換条件。** 閾値の正則化係数を大きくすると演算量は下がるが、SQuADの回答あり事例のように不可欠な証拠を失う場合がある。評価表の「1ポイント以内」は、各タスクでその条件を満たす設定を選んだ結果であり、任意の閾値・任意の入力で保証されるものではない。長さ分布が大きく変化する条件では固定長剪定より頑健だったが、意味内容の分布ずれを包括的に評価したものではない。

**実行基盤依存。** 短くした系列を実際の行列演算へ反映できなければ、論理的な剪定だけでは高速化しない。GPUの可変長バッチではFasterTransformerの動的パディング除去に依存している。著者が報告するCPU/GPU実測はHaswellとV100の構成に限られ、最近のGPUやFlashAttention実装、量子化ランタイムとの比較は含まれない。

**学習と運用の費用。** 各層の閾値を学ぶためにタスク別の軟マスク学習、二値化、硬マスク微調整が必要であり、事前学習済みモデルへ重み変更なしで直ちに適用する手法ではない。GPUの大きなバッチに対する実装・パディング処理も必要である。TR-BERTについては著者がGLUEでの再現実験を試みたが、探索した学習率と長さ罰則の範囲で十分な精度に収束せず、定量的な公平比較を確定できなかったと記している。この不成立を「LTPがTR-BERTより何倍速い」という結論へ変換してはいけない。
