# When Neural Code Completion Models Size up the Situation: Attaining Cheaper and Faster Completion through Dynamic Model Inference

> 中間層で十分なトークンは早期に出し、予測できない補完は丸ごと打ち切る二判断の動的推論で、コード補完を平均11.2パーセント速くし無駄な提案も減らす方式。

## 概要

コード補完は、開発者が統合開発環境で入力を止めるたびに自動で呼ばれるため、対話型の生成よりはるかに頻繁に大規模コードモデル（Large Code Model）を動かす。モデルの全層を毎回最後まで通す費用は、提供側の運用費と応答の遅さに直結する。動的推論は、途中の計算で十分な結果が得られるなら残りを飛ばす考え方だが、従来の早期終了は主に分類課題で検証され、逐次生成のコード補完では事情が違う。途中のトークンを早く出すと、その隠れ状態が後続トークンの文脈になるため、飛ばし方が後続全体へ影響する。さらに補完には、そもそも文脈が不足していて正しく予測できない場面が混ざっている。

本論文はまず実証調査から始める。GPT-2の中間層の予測能力を調べると、トークンの54.4パーセントは最初の1層だけで正しく予測でき、浅い層で足りるトークンが過半数である。一方で全層を使っても14.5パーセントのトークンは誤り、その誤ったトークンから続けた補完が開発者に受け入れられる割合は4.2パーセントしかない。つまり無駄は二種類ある。易しいトークンへの過剰な計算と、見込みのない補完を最後まで生成し続けることである。

提案のStop&Exit Controller（SEC）はこの二つに対応する二つの判断を持つ。各層の後に置かれた小さな線形分類器が隠れ状態を見て、残りの層を飛ばしてそのトークンを出すExitと、補完全体を打ち切って生成済みの部分だけを返すStopを選び、どちらでもなければ通常どおり次の層へ進むContinueになる。

**代表結果:** GPT-2とCodeGen、PythonとJavaの組合せで、SECは平均で16層中1.7層を飛ばし、補完生成を11.2パーセント高速化した。品質の低下はROUGE-Lで1.1パーセントにとどまり、人手で測る受入率は大半の設定で維持または改善した。最も攻めた閾値設定では受入率が46.7パーセントから44.9パーセントへ少し下がる代わりに71パーセントの高速化が得られ、閾値で速度と品質の交換を調整できることも示される。

## 問題設定

費用の構造を分けて見る必要がある。第一の無駄はトークン単位の過剰計算である。補完で出すトークンの多くは、直前の識別子や定型的な構文のように、浅い層の表現で既に決まる。それでも通常の推論は全トークンを全層へ通すため、易しいトークンにも深い層の費用がかかる。第二の無駄は補完単位の無駄である。文脈が不足して次のトークンを原理的に当てられない場面では、全層を使っても誤りになり、その誤りを起点に続く補完はほぼ受け入れられない。それでも通常の生成は決められた長さまで出し続ける。

既存の早期終了の研究は、分類のように最終層の出力だけが問題になる課題では有効でも、生成では二つの困難がある。一つは、途中で出したトークンの隠れ状態が後続の入力になるため、浅い層で打ち切ると後続トークンの計算の前提が崩れることである。もう一つは、早期終了はトークンごとの判断であり、補完全体を見込みなしと判断して止める仕組みを持たないことである。本論文はこの二点を、状態の複写とStopという新しい判断で埋める。

## 手法のあらまし

生成は通常どおりトークンを1つずつ進める。各トークンの計算では、層を1つ進めるごとに、その層の隠れ状態がSECの線形分類器へ渡される。分類器は閾値と比較して三つの動作から選ぶ。Continueなら次の層へ進む。Exitなら残りの層を飛ばし、その層の出力でトークンを確定するが、後続トークンの計算で必要になる深い層の隠れ状態が欠けるため、確定した層の状態を残りの層の位置へ複写して埋める。Stopならそのトークン以降の生成をやめ、既に生成したトークン列だけを補完結果として返す。分類器は、どの層で正しく予測できたか、どの時点で予測が誤りになったかという学習データから別途学習され、本体のコードモデルは凍結したまま使う。閾値と許容度の設定で、どれだけ攻めて飛ばすかを再学習なしに調整できる。

## 手法

### 1. 動作分類器 — 隠れ状態から続行・早期終了・打ち切りを選ぶ

この機構が観測するのは、各層を通過した直後の隠れ状態である。保持する状態は層ごとに置かれた線形分類器と、利用者が設定する閾値であり、処理は隠れ状態を三つの動作のスコアへ変換し、閾値を超えた判断だけを実行することである。分類器のパラメータは数千規模で、本体の数億規模に比べれば費用は無視できる水準とされる。これにより減るボトルネックは、易しいトークンに対する深い層の計算である。追加で消費する資源は層ごとの分類の計算と、分類器の学習データを用意する費用である。誤判定時の挙動は非対称で、Exitを誤ると浅い表現で出したトークンが後続の文脈を汚し、Stopを誤ると本来有用な補完を途中で切ってしまう。そのため評価では再現率より適合率、つまり判断したときに当たっている割合が重視され、閾値0.9ではStopの適合率0.812、Exitの適合率0.944が報告される。判断に自信がない場合はContinueへ倒れる設計であり、通常の全層計算へ自然に戻る。

### 2. 状態複写によるExit — 飛ばした層の状態を埋めて後続を守る

この機構が観測するのは、Exitが起きた層の位置と、そのトークンについて計算されなかった残りの層である。保持する状態は各層の隠れ状態の並びであり、処理はExitした層の隠れ状態を、飛ばした層の位置へそのまま複写することである。これが必要な理由は、自己回帰の生成では次のトークンの注意が前のトークンの各層の状態を参照するため、深い層の状態が欠けたままだと後続の計算が不完全になることである。複写は近似であり、深い層で本来作られるはずの表現とは異なるが、論文の実験ではこの方式で効率を大きく得ながら精度の犠牲を無視できる水準に抑えられることが確認された。代替として状態をゼロで埋めるなどの単純な方法では整合が崩れやすい。失敗条件は、Exitの頻度が高くなりすぎる場合で、複写された近似状態が文脈に積み重なると、後続トークンの品質が徐々に劣化する方向へ働く。

### 3. Stopによる打ち切り — 見込みのない補完を生成しない

この機構が観測するのは、同じ分類器が捉える、現在の文脈では正しい予測ができないという信号である。保持する状態は生成済みトークン列であり、処理はStopの判断が出た時点で生成を終え、生成済み部分だけを開発者への提案として返すことである。実証調査で、誤ったトークンから続けた補完の受入率が4.2パーセントしかなかったことが、この判断の根拠である。つまりStopは単なる計算の節約ではなく、開発者に無駄な提案を見せないこと自体が生産性の改善になる。低めの許容度でもStopだけで平均4.1パーセントの高速化が得られ、補完の7.6パーセントが打ち切られる。許容度を10パーセントまで緩めるとStopの高速化は33.3パーセントに達し、Exitを上回る。誤判定時の挙動は、有用な補完を途中で切る損失であり、特にStopは使う層数が全層に近い場面で起きるため、節約できる残り計算が小さいのに打ち切りの判断だけが残るという非効率もあり得る。論文はこの点を、ExitとStopを併用したときの生産性測定で検証している。

| 構成要素 | 入力・観測 | 具体的な動作 | 改善対象 | 主なトレードオフ |
|---|---|---|---|---|
| 動作分類器 | 各層の隠れ状態 | Continue・Exit・Stopを閾値で選択 | 深い層の過剰計算 | 誤判定が後続へ伝播 |
| 状態複写 | Exitした層の状態 | 飛ばした層の位置へ状態を複写 | 後続計算の整合 | 近似状態の蓄積 |
| Stop | 予測不能の信号 | 補完を打ち切り生成済み分を返す | 見込みのない生成 | 有用な補完を切る危険 |

## 評価

結論は、コード補完の動的推論では、トークンを早く出すことと、補完を見込みなしと判断して止めることの両方が効く、というものである。分類器の精度は4つの設定、つまりPythonとJavaの2データセットとGPT-2とCodeGenの2モデルの組合せで測られ、閾値0.9でStopの適合率0.812、Exitの適合率0.944と、判断したときの正しさが高い水準にある。効率では、ExitとStopを併用すると平均1.7層の省略と11.2パーセントの高速化が得られ、ROUGE-Lの低下は1.1パーセントにとどまる。Stop単独でも、厳しい許容度で4.1パーセント、緩い許容度で33.3パーセントの高速化が報告される。

生産性の観点がこの論文の特徴で、Javaデータセットでは人手の受入率が併用設定でも維持または改善し、最も攻めた設定でのみ46.7パーセントから44.9パーセントへ下がったが、その設定では71パーセントの高速化が得られている。読み方として、SECの利得は単なる計算量の削減ではなく、受け入れられない提案を出さないことで開発者の確認の手間まで減らす点にあり、閾値を調整すれば再学習なしに、費用優先の配備と品質優先の配備を切り替えられる。未評価の点として、対象モデルはGPT-2級とCodeGen級であり、現在の大規模な補完モデルでの分類器の精度や、受入率の人手評価に伴うばらつきは論文内でも注意点として挙げられる。

## 既存研究との差

早期終了の先行研究との差は、対象を分類から逐次生成のコード補完へ移し、生成特有の二つの問題へ答えた点にある。第一に、飛ばした層の隠れ状態を複写で埋めることで、早期に確定したトークンが後続トークンの計算を壊さないようにした。第二に、トークン単位の早期終了に補完単位の打ち切りを加え、計算の節約と提案品質の改善を同時に狙った。コード補完の高速化がモデルの圧縮や小型化で進められてきたのに対し、本論文はモデルの中身を変えず、推論の進め方だけを変える直交する方向である。

## 限界・実装状況

限界は、評価したモデル規模が現在の補完サービスの主力より小さいこと、受入率が人手評価に依存し自動指標だけでは再現しにくいこと、分類器の学習がモデルと言語ごとに必要なことである。またStopの判断は、文脈不足で予測できない場面と、単に難しい場面を完全には区別できないため、閾値を攻めすぎると有用な補完を切る。実装状況は、公式コードが公開されており、分類器は数千パラメータの線形層として実装される。閾値による調整が再学習なしで可能なため、配備先の費用制約に応じた運用がしやすい構成である。

## 一般的な実装上の含意

逐次生成の早期終了では、出力を早く出すこと自体より、そのトークンの内部状態が後続へどう渡るかを設計することが本質である。また、生成系の効率化では、個々のトークンの計算を減らすだけでなく、見込みのない生成全体を早めに諦める判断が、計算と利用者の確認費用の両方を削減する。判断器は小さくても、誤判定の非対称な費用を踏まえて適合率を優先し、自信がない場合は通常計算へ倒れる設計にすると安全である。
