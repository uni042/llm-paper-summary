# Magic Pyramid: Accelerating Inference with Early Exiting and Token Pruning

> BERT系推論で「何個のトークンを後段へ残すか」と「何層まで進むか」を同時に削る。トークン枝刈りは長文、早期終了は短く容易な入力で効きやすいという相補性を使い、片方だけの方式より広い入力長で計算量を落とす。

## 概要

Transformer分類器は通常、入力中の全トークンを最終層まで処理する。しかし分類結果へほとんど寄与しないトークンまで深い層へ運ぶ必要はなく、また容易な入力では中間層ですでに十分な分類確信度が得られる。前者は系列の「幅」の冗長性、後者はネットワークの「深さ」の冗長性である。

既存の学習型トークン枝刈り（Learned Token Pruning; LTP）は、層が進むにつれて不要トークンを落とすため長い系列ほど削減余地が大きい。一方、FastBERT型の早期終了（early exiting）は、中間分類器が十分確信した時点で残り層を実行しないため、短く容易な入力で強い。論文は実測で両者の入力長依存性が逆方向であることを確認し、二つを同じBERTへ重ねたMagic Pyramid（MP）を提案する。

MPは各層でまず残すトークンを減らし、その縮んだ隠れ状態を使って補助分類器を評価する。補助分類器の不確実性が閾値以下ならそこで回答し、難しい入力だけ次層へ進む。したがって後段ほど「処理するトークン数」と「到達する入力数」の両方が減り、計算グラフがピラミッド状に細くなる。

## 背景：幅削減と深さ削減は同じ最適化ではない

自己注意とフィードフォワード層の計算量は系列長に依存するため、長い入力から不要トークンを早く除けば後段全体が軽くなる。ただし短い入力では削れるトークン自体が少なく、枝刈りの利得は小さい。

早期終了は逆に、分類が簡単なら系列長に関係なく残りのTransformer層を丸ごと省ける。しかし長い入力では補助分類器の不確実性が下がりにくく、深い層まで進みやすい。論文のYelp/AG Newsの入力長別結果では、LTPは長文ほど、FastBERTは短文ほど相対的に有利だった。

MPの着眼点は、この二種類を競合方式として選ぶのではなく、同一推論中に直列に適用することである。トークン枝刈りが補助分類器へ渡る表現を簡潔にし、早期終了が残り層そのものを消すため、削減対象が重ならない。

## 手法

### 1. 各層に補助分類器を置き、確信した入力を終了させる

BERT backboneの各Transformerブロック後に補助分類器を置く。補助分類器はTransformerブロック、プーリング層、射影層とソフトマックスからなり、[CLS]表現からクラス分布を出す。

学習は二段階である。まず通常どおりbackboneと最終分類器を正解ラベルで学習する。その後backboneと最終分類器を固定し、各補助分類器が最終分類器の分布を模倣するようカルバック・ライブラー（Kullback-Leibler; KL）ダイバージェンスで蒸留する。これにより浅い層の分類器が最終層の判断へ近づく。

推論時は各層のクラス分布から正規化エントロピー型の不確実性 (u_l) を計算し、(u_l\le\tau) なら終了する。閾値 (	au) を大きくすると早く終了しやすくなるため、同一モデルで速度と精度を連続的に調整できる。

### 2. トークン枝刈りで後段の系列幅を縮める

MPは早期終了だけでなく、LTP型の学習済みマスクで層を進むにつれて非重要トークンを削除する。入力時には全トークンが存在するが、後段では分類に必要なトークンだけが残るため、自己注意とフィードフォワード計算の入力行数が減る。

重要なのは、単に推論後にトークンを無視するのではなく、後続層へ入力しない点である。これにより枝刈り以降の全層で演算量を継続して削減できる。

### 3. 二つの判断を同じ要求で重ねる

一つの要求は、現在残っているトークン集合をTransformer層で処理し、枝刈り可能なら不要トークンを落とし、補助分類器の不確実性を評価する、という順に進む。十分確信できれば要求全体を終了し、そうでなければ縮んだトークン集合だけを次層へ渡す。

このため、長く難しい入力ではトークン枝刈りが主に効き、短く容易な入力では早期終了が主に効く。入力長や難易度が混在するオンライン分類でも、どちらか一方へ固定するより削減源を残しやすい。

## 評価

### 代表的な評価条件

| 項目 | 条件 |
| --- | --- |
| 基盤モデル | uncased BERT-base、12層（DistilBERT以外の主要比較） |
| データセット | AG News、Yelp、QQP、MRPC、RTE |
| 比較 | BERT、DistilBERT、学習型トークン枝刈り（LTP）、FastBERT |
| 主指標 | 分類精度、GFLOPs。論文の括弧内「speedup」はBERT比GFLOPs比 |
| 学習 | 通常学習→軟枝刈り→硬枝刈り→補助分類器学習を方式に応じて実施 |
| 速度制御 | 早期終了閾値 (	au) とトークン枝刈り閾値を調整 |
| 公平性条件 | 原則としてBERT比の精度低下を約1ポイント以内に抑える設定を比較 |

### 代表的な評価結果

| データセット | BERT 精度 / GFLOPs | FastBERT | Magic Pyramid | 読み方 |
| --- | --- | --- | --- | --- |
| AG News | 94.3 / 9.0 | 94.3 / 2.3（3.97倍） | 94.3 / 1.8（4.95倍） | 精度を維持したままFastBERTよりさらに計算削減 |
| Yelp | 95.8 / 17.2 | 94.8 / 2.8（6.18倍） | 94.5 / 2.1（8.25倍） | 約1.3ポイント低下と引き換えに大幅削減 |
| QQP | 91.3 / 5.1 | 90.7 / 1.6（3.20倍） | 90.4 / 1.3（4.03倍） | 長い入力でトークン枝刈りの寄与が出やすい |
| MRPC | 85.3 / 9.2 | 84.3 / 4.3（2.13倍） | 83.8 / 3.3（2.77倍） | 小規模データでは品質との交換が大きめ |
| RTE | 68.6 / 11.2 | 67.6 / 8.4（1.33倍） | 67.5 / 6.5（1.72倍） | 難しい/小規模課題では利得が限定的 |

論文要旨は、精度低下0.5%未満の設定で最大70%のGFLOPs削減、二つの分類課題で平均8.06倍の高速化を報告する。一方、本文の主要表では設定によって精度低下が約1ポイントを超える例もあるため、「常に0.5%未満」と一般化せず、閾値とデータセットを合わせて読む必要がある。

FastBERTとの速度制御比較では、AG Newsで(	au=0.1)のとき3.97倍→4.95倍、Yelpで3.15倍→5.35倍となり、強い早期終了設定では両方式の差が縮む。極端に浅い層で終了すると、トークン枝刈りを後段で活かす時間がなくなるためである。

## 既存研究との差

LTPは「各層へ何トークン通すか」、FastBERTは「何層通すか」を個別に最適化する。MPは両軸を同時に縮めるため、入力長と難易度が混在する状況で一方の弱点をもう一方が補う。

ただしこれは現在の生成型LLM向け投機的復号やKVキャッシュ圧縮とは対象が異なる。評価対象はBERT-base級の分類タスクであり、自己回帰デコードの1トークンずつの生成待ちを直接短縮する方式ではない。

## 限界・実装状況

補助分類器とトークンマスクの学習が必要で、既存モデルへ完全な推論時プラグインとして付ける方式ではない。早期終了閾値と枝刈り閾値の両方を品質制約に合わせて較正する必要があり、データ分布が変わると最適値も変わり得る。

また主要な「speedup」は壁時計時間ではなくGFLOPs比である。動的な系列長と可変終了深さを実ランタイムが効率良くバッチ処理できない場合、理論計算削減がそのまま実時間へ変換されない。生成型LLMや大規模GPUサービングへの適用には別途ランタイム設計が必要である。
