# EE-Tuning — 事前学習済みLLMを少量の追加学習で早期終了可能にする

## 概要

EE-Tuningは、既存の大規模言語モデル（Large Language Model; LLM）を、全パラメータの再学習なしに早期終了（early exit）できるモデルへ変換する手法である。通常のTransformerデコーダは各生成トークンに対して最後の層まで順伝播するが、早期終了ヘッド（early-exit head）を途中層へ接続すれば、十分に確信できるトークンは残りの層を通さず出力できる。ただし、途中層の隠れ状態は本来最終出力のために学習されたものであり、そのまま語彙予測に使うと品質が低い。EE-Tuningは本体を凍結したまま途中層の出力を語彙分布へ写す小さな追加モジュールだけを学習する。

重要なのは、**推論の早期終了機構そのものを発明する研究ではなく、既存モデルへ早期終了能力を安価に追加する訓練・実装研究**であることだ。著者はLlama 2-Chatの7B、13B、70Bを対象に、既存層からの初期値コピー、早期終了ヘッドだけの逆伝播、不要な後段層を読み込まない部分チェックポイントロード、パイプライン並列化を組み合わせた。主張する推論改善は、信頼度閾値を下げて後段の計算を省くことで生じる**品質と速度の交換条件**であり、すべてのトークンで同じ品質を保証した厳密な無損失復号ではない。

論文本文では13Bの追加学習を4基のA800 GPUで約5時間、ピークGPUメモリ約20GB、70Bを約30時間、ピーク約78GBと報告する。推論時には複数の下流課題で概ね1.2～1.6倍の速度改善と、基準モデルに近い、または一部で高いスコアを得る条件が示される。これらは論文固有のモデル・データ・貪欲復号・GPU環境での値であり、現行モデルへ無条件に外挿できない。

## 背景：早期終了の学習が難しい理由

一般の自己回帰LLMでは、入力トークンの埋め込みをTransformer層に通し、最終層の隠れ状態から語彙全体のロジットを計算する。通常の学習は最終出口の次トークン対数尤度を最大化する。早期終了モデルでは層 `l` の隠れ状態 `h_l` からも語彙ロジットを計算する出口 `E_l(h_l)` を置き、出口の最大確率が閾値を超えたら後続層を省略する。

従来の大規模な早期終了モデルは、最終出口と中間出口の損失を同時に最適化し、本体も含めて最初から学習する場合が多かった。これは数十億パラメータのモデルで計算・通信・データ費用が大きい。しかもすでに高品質な事前学習済みモデルがある場合、その知識を再学習し直すのは非効率である。

EE-Tuningは「途中層は最終出力に役立つ特徴をすでに含んでいる」という残差接続の性質を利用する。本体の重みを固定し、途中層の特徴から語彙予測へ到達する追加ヘッドだけを学習すれば、最終出口の挙動を変えずに早期終了の選択肢を増やせる。途中層がそもそも情報不足なら追加ヘッドだけでは補えないので、出口の深さと構造の選択が重要になる。

## 提案手法：初期化とヘッド単独学習

### 第1段階：出口を追加し、既存パラメータから初期化する

著者の実装は、途中層に追加するヘッドとして次の4種類を用意する。

| 出口構造 | 内部演算 | 学習・推論上の特徴 |
|---|---|---|
| Embedding | 隠れ状態から語彙への線形射影のみ | 最軽量だが正規化がなく、学習が不安定になりやすい |
| Norm | 正規化＋語彙射影 | 軽量で収束が安定する |
| MLP | FFN/MLP＋正規化＋語彙射影 | 追加計算と予測能力のバランスが良い |
| Layer | 完全なTransformer層＋正規化＋語彙射影 | 学習損失は低くなりやすいが出口自体が重い |

初期値をランダムにする代わりに、既存の最終出口から語彙射影と正規化パラメータをコピーする。MLP型では接続位置の元層のMLPをコピーし、Layer型では元モデルの最終Transformer層をコピーする。これは同じ演算の役割を持つ重みを再利用し、追加学習開始時の出力を意味のある分布へ近づけるためである。

このコピー初期化は厳密に元モデルの最終出力を再現するものではない。スキップした残りの層で本来行われる処理がないからだ。しかし、残差構造によって隠れ状態が大きく破壊されないという経験的仮説があり、ランダム初期化より速く収束する。実験では最終的な下流スコアの差が小さくなることもあり、コピーの主な利点は初期学習の安定性と収束速度である。

### 第2段階：本体を凍結して途中出口だけ更新する

学習目的は通常の自己回帰言語モデリング損失である。各出口 `e` の予測確率を `p_e(x_t|x_<t)` とすれば、出口損失は `L_e=-Σ_t log p_e(x_t|x_<t)` で、更新するのは追加出口のパラメータだけである。元モデル本体のパラメータは凍結するため、出口より前の隠れ状態を求める順伝播は必要でも、本体を通る逆伝播や本体のオプティマイザ状態は不要となる。

さらに、最も深い追加出口より後のTransformer層は学習に使わないので、ロード自体を省略できる。例えば全体の1/4深さに一つの出口を置く場合、前段1/4の重みだけをロードして、その隠れ状態と出口損失を計算すればよい。これが70Bでも単一80GB GPUへ学習状態を収められる主因である。70B全体を80GBへロードして学習した、という意味ではない。

複数出口の損失は、それぞれの追加ヘッドへ独立に逆伝播できる。データ並列、テンソル並列、系列並列、パイプライン並列に対応し、パイプラインでは各段の本体順伝播が完了すると、その段に付属する出口の逆伝播を局所的に開始する。通常の全パラメータ学習と異なり、本体へ逆向き勾配を流す必要がないため、後方通信を省略したスケジュールを採用できる。これにより大規模モデルへ拡張しても学習費用を抑える。

### 出口の選択と信頼度閾値

追加学習後は、複数出口のうちどれを実際に有効化するかを運用時に選べる。主実験ではモデル深さの1/4、2/4、3/4にある三つの出口を有効にする。各生成トークンで途中出口の最大次トークン確率を計算し、これが閾値を超えた時点でその出口の予測を出力する。閾値が高ければ多くのトークンが深い層まで進み、低ければ早く出力して速度が上がるが、難しいトークンの誤答が増える可能性がある。

閾値1.0は事実上早期終了を無効化する設定であり、元モデルの全層実行を速度の基準とする。これは投機的復号のように元モデルで候補を再検証して分布を厳密に保つ方式ではない。早期出口が出したトークンの分布は元モデルの最終出口と異なり得る。論文で同等品質が観測されたとしても、任意のプロンプト・乱数条件での出力同一性は保証されない。

## 実験設定と再現に必要な条件

| 項目 | 原著の条件 |
|---|---|
| 基盤モデル | Llama 2-Chat 7B、13B、70B |
| GPU | 1ノード8基のNVIDIA A800 80GBを持つクラスタ。個別の訓練では4基を使用する設定あり |
| 学習データ | Data-Juicerが整備した事前学習データから抽出 |
| 学習トークン | バッチ16 × 長さ2048 × 40,000反復 ≈ 13.1億トークン |
| オプティマイザ | Adam、β1=0.9、β2=0.95、ε=1e-5 |
| 学習率 | 最大1e-4、最小1e-5、線形減衰、ウォームアップ1% |
| 推論 | 貪欲復号、最大確率に基づく早期終了閾値、KVキャッシュ対応のパイプライン推論 |
| 品質評価 | CNN/DailyMail、XSUM、NarrativeQA、MMLU。5ショット、最大文脈2048 |
| 出力長 | CNN/DailyMail 128、XSUM 64、NarrativeQA 100、MMLU 1トークン |
| 主な指標 | 学習時間、ピークGPUメモリ、学習損失、下流スコア、壁時計遅延から求める速度倍率 |

元モデルはチャット向けの事前学習と人間の好みへの整合調整を経ているが、追加出口の訓練は一般的な次トークン予測損失である。この違いは後述の安全性・出力形式の問題に直結する。品質評価のROUGE-L、F1、完全一致（exact match）は互いに異なる指標であり、全タスクで一つの平均正答率を求めたものではない。

## 主要結果：訓練費用と推論品質・速度の分離

### 追加学習の費用

論文第3.1節は、全体深さの1/4に一つのMLP型出口を置く構成で次の費用を報告する。

| 基盤モデル | 学習時間 | ピークGPUメモリ | GPU構成と意味 |
|---|---:|---:|---|
| Llama 2-Chat 13B | 約5時間 | 約20GB | データ並列4基。24GB級GPUへ収められるメモリ量 |
| Llama 2-Chat 70B | 約30時間 | 約78GB | 前段1/4のみロード。単一80GB GPUにも収容可能な容量 |

著者は事前学習に比べGPU時間とデータ量が1/1000未満であると述べるが、これは原モデルの巨大な事前学習費用との比であり、通常のLoRA微調整と同じデータ・同じハードウェアで比較した絶対倍率ではない。また20GB/78GBは追加学習時のピークメモリであって、70Bモデル全体を推論時に収容するためのメモリ量を示すものではない。運用時に最終出口までの計算を許すなら、原モデル全体の重みは依然として必要になる。

### 推論速度・品質の交換条件

第3.2節の図5、第3.4節の図9は、閾値を `1.0, 0.9, 0.8, 0.6, 0.4, 0.2` と下げたときの下流スコアと速度倍率の曲線を示す。著者の概要で述べる約1.2～1.6倍は、複数課題で品質が基準に近い運用点の代表的な範囲であり、あらゆる閾値・タスクで常に得られる固定倍率ではない。閾値を下げれば平均的により浅い層で終了するが、途中出口の計算自体が増えるため、浅い出口が常に最良とは限らない。

付録表2には、具体的な一例として13Bの文章生成で元モデル4.8秒、閾値0.8で4.2秒、0.6で3.9秒、70Bで元モデル23.6秒、閾値0.8で19.7秒、0.6で17.1秒という壁時計時間が載る。これは**個別の例示プロンプト**であり、全評価セットの平均速度や厳密な同品質比較としては使えない。表の生成文も異なるため、実際にどの品質を許容するかは利用用途で判断する必要がある。

### 構成要素除去と設計比較

**出口構造**：13Bの40層モデルへ8個の出口を等間隔に追加して比較した。正規化なしのEmbedding型は学習が発散しやすい。Norm型は収束し、MLP型は追加計算と下流スコア・速度のバランスが最も良い。Layer型は出口の訓練損失が最も低いことがあるが、出口自体が重いため推論速度では劣る場合がある。訓練損失の大小をそのまま運用時の速度・品質の最適解と見なせないことを示す。

**初期化**：図6～7はコピー初期化とランダム初期化を比較する。コピーは学習初期の損失を下げ、特に深い出口で速く収束するが、十分に学習した後の下流スコアには大きな差がない。したがって「コピーした重みが推論品質を必ず高くする」よりも「同じ品質へ到達する学習を短くできる」が実証に近い。

**出口位置**：付録A.2では一つの出口だけを有効化する場合を調べ、浅い出口は高速だが品質不足になりやすく、深い出口は品質が高いが速度上の利得が小さいと示す。最適位置はタスクごとに変わるため、運用前に検証集合で閾値と出口の組を選ぶ必要がある。複数出口を一度学習しておけば、後から有効化する部分集合を切り替えられる。

**学習データ**：付録A.1は一般の事前学習コーパスと指示微調整（instruction fine-tuning; IFT）データを比較する。IFTデータでは出口の学習損失が最終的に低くなっても、下流評価では一般の事前学習データを用いた出口の方が良い場合がある。特定の応答形式への過適合が原因の可能性を挙げるが、因果関係の断定はしていない。

**トークン別の動的損失重み**：付録A.3では各出口の最大予測確率 `c_t` を重みとして `L=-Σ_t c_t log p(x_t|x_<t)` とする。容易なトークンを重視して学習する狙いだが、実験では固定重みとの明確な差は確認されなかった。これは否定的な構成要素除去結果であり、提案された追加機能がすべて実証されたと扱ってはいけない。

**追加の全パラメータ学習**：付録A.4はEE-Tuning後に継続事前学習（continued pre-training; CPT）を行うと出口損失がさらに下がることを示す。ただしこれは安価なEE-Tuningだけの性能ではなく、全パラメータ更新の費用を新たに支払う構成である。

## 既存手法との関係と実装上の意味

通常の早期終了モデルを一から共同学習する方法に比べ、EE-Tuningは事前学習済みモデルをそのまま活用し、追加出口に学習対象を限定する。出口を途中層へ置くという考え自体は既存研究にあり、本稿の貢献はLLM規模で使える初期化、凍結学習、メモリ節約、並列化、運用時の出口切替をまとめた点にある。

投機的復号（speculative decoding）とは役割が異なる。投機的復号はドラフトを大型モデルが検証することで、適切な方式なら元の生成分布を保てる。EE-Tuningの早期終了は最終出口を計算しないので、速度は上がり得るが元モデルと同じ確率分布を保証しない。また枝刈りと違い、原モデルの重みを恒久的に削除するわけではなく、必要なら深い出口まで実行できる。KVキャッシュについては論文が既存のパイプライン推論機構との互換性を述べるが、任意のサービングエンジンへそのまま組み込めるという保証ではない。

ローカル推論で採用する場合は、出口ヘッドが追加する語彙射影の重み容量、出口の推論カーネル、どの層で停止したトークンのKVを次のトークンでどう扱うか、バッチ内で異なる出口深さの要求をどうスケジューリングするかが重要となる。論文のA800クラスタ向け実装が、量子化された小型GPU上で同じ速度比を実現するとは限らない。まず出口を一つだけ有効にする実験から、出力品質とメモリ費用を測るのが現実的である。

## 限界・再現時の注意点

第一に、元モデル本体を凍結するため、中間層が早期出力に適した表現を持っていない場合、追加ヘッドだけでは補えない。出口の容量を増やせば品質は改善し得るが、その分だけ出口の演算と重みが増え、推論速度上の利点が減る。論文のLayer型が訓練損失で良くても速度で劣る例はこの交換条件を示す。

第二に、評価はLlama 2-Chat 7B/13B/70Bと、貪欲復号・最大確率閾値に限られる。温度付きサンプリング、top-p、長い文脈、MoEモデル、複数同時要求、異なるGPUの性能は検証されていない。70Bの学習時に前段のみロードする最適化は、推論時の全モデルメモリ必要量を削減するものではない。

第三に、追加出口は一般の言語モデリング損失だけで学習され、元のチャットモデルが受けた人間の好みへの整合調整を必ずしも継承しない。著者自身が有用性や安全性の評価を実施していないと明記する。下流ベンチマークのスコアが上がった例をもって、指示遵守や安全性が改善したとは判断できない。

第四に、1.2～1.6倍の推論速度改善は元モデル・閾値・課題・出力長に依存する。出力トークンごとの早期終了率、出口ヘッドの追加費用、バッチ化したサービングのスケジューリングで実効利得が変わる。推論スループットと単一要求の壁時計遅延も区別すべきである。

第五に、学習データの一般性と出口の過適合が問題になる。指示微調整データは学習損失を下げても下流スコアで優位とは限らず、動的トークン重みも明確な改善がなかった。コピー初期化も十分な訓練後のスコア差が小さいため、どの部品がどの費用を減らすのかを個別に確認する必要がある。

第六に、論文の実装はEE-LLMに依存する。出口位置や本体の重み共有、語彙射影のtie/untie設定によって必要な逆伝播範囲が変わる。とくに入力埋め込みと出口射影を重み共有すると、入力埋め込みへ勾配が流れ、軽量学習という前提が崩れる可能性がある。本文の実装は原則として出口間の語彙射影を独立にしている。

## まとめ

EE-Tuningは、すでに学習済みのLLMを大きく作り直さず、早期終了という推論の選択肢を追加する。設計の核心は、出口ヘッドのコピー初期化と、本体を凍結して必要な層の順伝播・出口の逆伝播だけを行う学習方式にある。13B/70Bでも追加学習の費用を抑えられ、下流課題の品質を確認しながら生成遅延を減らせることを示した。

ただし「高速化」と「元モデルの出力分布の厳密な保持」は両立が証明されていない。安全性・指示遵守の未評価、バッチ推論への適用、出口のメモリ・カーネル費用、量子化モデルへの移植は別途検証が必要である。導入判断では、同一の入力と出力条件で、出口位置・閾値ごとに品質、壁時計遅延、総GPU/CPUメモリ、準備費用を計測するべきである。
