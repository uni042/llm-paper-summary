# Dynamic-LLaVA: Efficient Multimodal Large Language Models via Dynamic Vision-language Context Sparsification

## 概要
動的-LLaVAは、マルチモーダル大規模言語モデル（マルチモーダル Large Language モデル; MLLM）の高速化を、画像トークンだけの削減ではなく「画像文脈と生成済み言語文脈の両方を、推論段階に応じて動的に疎化する」問題として扱う。従来のFastVなどはプリフィル時に画像トークンを減らせるが、出力が長くなるほど生成済みテキスト トークンが文脈の大半を占め、デコードの計算・KV キャッシュ容量に対する画像削減の寄与が薄れる。

動的-LLaVAはTransformerの早い層に二つの軽量予測器を置き、画像トークンを残すか決める画像予測器と、各生成テキスト トークンを今後の計算/KV キャッシュへ残すか決める出力予測器を学習する。予測は一度だけ行い、その保持/削除決定を後続層すべてで共有する。プリフィルでは画像トークンだけ、KV キャッシュなしデコードでは画像+過去出力トークン、KV キャッシュありデコードでは新たに生成したトークンのKVを保存するかを選ぶ。

LLaVA-1.5 7B/13B上の評価では、画像トークンを576から115へ減らし、画像関連プリフィル計算を約75%削減する。生成中もテキスト文脈を疎化し、KVなしデコード計算を約50%、KVありデコードのKV メモリを約50%削減しながら、理解・生成指標の低下を小さく保つ。さらにTokenPacker等の効率的視覚 射影器とも併用できる。

## 問題設定
LLaVA型MLLMでは、視覚 encoderが多数の画像トークンを作り、テキスト プロンプトと連結してdecoder-only LLMへ渡す。プリフィルでは画像+テキスト トークンすべてを一度処理するため、画像トークン削減は直接計算削減になる。しかしデコードが長くなると、KV キャッシュなし推論では過去出力トークン全体を再計算し、KV キャッシュあり推論では各生成トークンのK/Vを追加保存する。

したがって出力長 (N^{OT}) が大きくなると、計算量またはメモリは画像トークン数より生成済みテキスト トークン数に支配される。画像だけを75%削っても、後半デコードでは削減した画像トークンは全文脈の小部分になり、speedup/メモリ削減率が徐々に消える。

動的-LLaVAの目的は、プリフィルの画像冗長性とデコードの言語履歴冗長性を別々の予測器で減らし、一回限りのトークン削減ではなく生成全期間にわたる効率改善を得ることである。

## 手法

### 1. 二つの二値予測器
画像トークン集合に対する画像予測器 (P^I) と、生成テキスト トークンに対する出力予測器 (P^{OT}) を追加する。各トークン 特徴から保持/削除の2-class scoreを出し、二値マスクを作る。予測器は小型多層networkで、追加計算は全体の1%未満と報告される。

標準設定では第2 decoder 層後に一度だけ予測器を適用する。そこで削除されたトークンは後続層へ渡さず、保持された集合だけを残りのdecoderへ入力する。同じトークンを各層で再判定しないため、層ごとの不規則なsequence length制御や複雑なsparsity スケジュールを避ける。

### 2. prefill時の画像疎化
プリフィルでは画像トークン 特徴を (P^I) へ入力し、保持された画像トークンと元のテキスト プロンプトを結合して第3層以降を実行する。テキスト プロンプト自体はここでは削らない。これにより大部分のLLM層で画像トークン数を減らし、注意だけでなくFFNなどトークン数に比例する計算も減らす。

画像保持率は学習時の正則化で所望値へ誘導する。評価設定ではLLaVA-1.5の576画像トークンを115程度まで減らす構成があり、画像トークンに関するプリフィル TFLOPsを7Bで10.1→2.5、13Bで19.6→4.7へ削減する。

### 3. KV cacheなしdecodeで画像+言語を疎化
KV キャッシュを使わず毎段階全文脈を再計算する場合、画像トークンだけでなく過去に生成した出力テキスト トークンへ (P^{OT}) を適用する。ただし今まさに次トークンを生成するための最新出力トークンは必ず保持する。

削除された過去テキスト トークンは後続層の注意/FFNから除かれるため、生成が長くなっても処理sequenceが元の出力長に比例して増え続けるのを抑える。このモードでは「どのKVを保存するか」ではなく、後続層で実際に再計算するトークン集合そのものを小さくする。

### 4. KV cacheありdecodeではonline KV cache圧縮
KV キャッシュありの場合、現在トークンはその段階の注意には必ず含める。出力予測器は、そのトークンから生成されたK/Vを「次段階以降のキャッシュへ追加するか」を決める。削除判定なら現在段階の計算には使った後、K/Vをキャッシュへ保存しない。

この判断は現在トークンの特徴だけで行い、過去KV全体の注意 scoreを再走査してeviction対象を選ばない。したがって著者らはonline KV キャッシュ compressionと位置付ける。同一保持/削除決定を後続層へ伝えるため、第2層より後では不要トークンのKV増加を抑え続けられる。

### 5. end-to-end疎化学習
二値 マスクは通常のargmaxでは微分できないため、学習時にはGumbel-Softmaxと直線通過勾配推定器（Straight-Through 勾配 Estimator; STE）を用いる。削除 トークンが保持 トークンへ情報を流して予測器が不正に補償することを防ぐため、マスク済み softmaxで不要トークンの影響を遮断する。

さらに実保持率が指定 (r^I,r^{OT}) へ近づくよう正則化項を加える。短い回答までテキスト 疎化を強制すると学習が不安定になるため、出力トークン数が閾値 (LEN^{OT}) 以上のsampleだけに言語マスク制約を適用する。速度・メモリと品質の交換条件は保持率を変えることで調整する。

## 評価

### 条件
主な基盤はLLaVA-1.5 7B/13B。視覚 understandingではVQAv2、GQA、ScienceQA、TextVQA、POPE、MME、MMBench、SEED等を用い、生成能力はLVIS-VQAなどでperplexityとMETEORを測る。比較にはFastVなど視覚 トークン reduction法、効率的射影器のTokenPacker、KV キャッシュ compressionのH2Oなどを含む。

実機効率の例はNVIDIA A100 80GB、バッチ size 8などで測定され、論文は理論TFLOPsだけでなく実GPU 遅延/メモリも付録で評価する。

### prefill
LLaVA-1.5-7Bは576画像トークン・10.1 TFLOPs。動的-LLaVAの画像疎化は115 トークン・2.5 TFLOPsで約75%削減し、13Bでも576 トークン・19.6 TFLOPsから115 トークン・4.7 TFLOPsへ約76%削減する。

7BのVQAv2/GQA/ScienceQA/TextVQA/POPEではfull 比較基準 78.5/62.0/66.8/58.2/85.9に対し、画像+言語疎化版は77.9/61.3/68.6/56.5/85.9で、削減率に比べ品質差は小さい。ScienceQAでは+1.8ポイントとなる一方、TextVQAでは-1.7ポイントで、全タスクが改善するわけではない。

### decodeとKV memory
LVIS-VQAの7B例では、画像+言語疎化によりKV キャッシュなしデコード TFLOPsが2.75/2.99から1.52/1.57へ約45〜47%減る。KV キャッシュありの最大キャッシュ量も103/91から63/46へ約39〜49%削減する。METEORは0.3103の比較基準に対し0.3108でほぼ同等である。

ランダムに半分捨てる方式や単純構造規則は同程度の計算削減でもPPLが11.52/9.69まで悪化し、H2Oを直接MLLMへ適用した例ではMETEORが0.0388まで崩れる。したがって「トークン数を減らすこと」だけでは品質維持できず、MLLM 特徴から学習した予測器と段階別の削除規則が必要である。

### TokenPackerとの併用
動的-LLaVAは視覚 encoder/射影器自体を置き換えないためTokenPackerと直交的に組み合わせられる。TokenPacker-7Bの144画像トークン・2.5 TFLOPsに対し、動的-LLaVA併用では57 トークン・1.1 TFLOPsまで下がり、視覚 understanding平均は62.3程度を維持する。13Bでも144 トークン・4.9 TFLOPsから57 トークン・2.1 TFLOPsへ削減する。

## 既存研究との差
FastVなど視覚 文脈 疎化は主にプリフィルの画像トークン数を減らし、長いデコードでテキスト履歴が支配的になると相対利得が小さくなる。動的-LLaVAは画像と生成テキストへ別予測器を持ち、プリフィル、KVなしデコード、KVありデコードで削減対象を切り替える。

H2Oなど一般LLM向けKV圧縮は既存キャッシュの注意/importanceを使って保持KVを選ぶことが多い。動的-LLaVAは現在生成トークンの特徴から将来キャッシュへ残すか即時判断するため、KV キャッシュのないプリフィル/KVなしデコードにも同じ言語疎化思想を適用できる。

## 限界
学習不要法ではなく、二値 予測器をMLLMへ追加してエンドツーエンド 疎化 学習を行う必要がある。保持率、予測器を挿す層、短出力を除外する (LEN^{OT})、正則化重みなどの設定に品質が依存し、新しい基盤へそのまま移植して最適とは限らない。

一度削除したトークンは後続層へ戻らないため、後半層で初めて重要になる細部を失う可能性がある。テキスト 疎化も現在トークンだけから将来価値を予測するので、長距離依存が後から顕在化するタスクではキャッシュ evictionが不利になり得る。

評価の中心はLLaVA-1.5 7B/13Bであり、現代のより大きなMLLM、video長系列、複数画像、高並列continuous バッチ化でのサービング性能は直接検証していない。約50%というデコード計算/メモリ削減は設定した保持率と生成長に依存する。
