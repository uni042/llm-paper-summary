# LazyLLM：長文生成における動的トークン枝刈りと途中状態の復帰

## 概要

LazyLLMは、長い入力文のすべてのトークンを全変換層で計算する慣行を改め、**現在予測しようとしている次のトークンに重要な入力部分だけを深い層へ進める**推論時の計算削減法である。学習済みの言語モデルを再学習せず、既存の注意重みを重要度の手掛かりとして利用する。特徴は、いったん計算経路から外した入力トークンを永久に捨てない点にある。後続の生成段階で重要になれば、補助キャッシュに保存した途中層の隠れ状態を読み出して計算へ戻す。したがって、最初の出力トークンを早く得ることと、後の生成に必要な文脈を復帰させることを両立させる設計である。

著者らはLlama 2 7BとXGen 7BをNVIDIA A100で動かし、LongBenchの16データ集合・6課題群を用いて実時間を比較した。複数文書質問応答における最初のトークンまでの時間は、通常推論比でLlama 2が**2.34倍**、XGenが**2.65倍**高速になり、同じ条件でLlama 2の課題得点は22.43から22.31への小幅な変化にとどまった。ただし最初のトークンまでの高速化と、最後の出力までの高速化は異なる。要約では入力トークンの累積計算率がLlama 2で99.59%に達し、生成全体の高速化はわずか1.02倍だった。入力のどの部分を最終的に参照するかという課題特性が、実際の利得を大きく左右する。一次論文の表1・表2でこの区別を確認できる。

## 問題設定と先行方式との差

通常の自己回帰生成では、まず入力文全体を処理して各層の鍵・値キャッシュを構築し、最初のトークンを出力する。この入力処理段階は長文ほど重く、後続の生成段階と違って入力トークン数に比例する投影計算に加え、注意計算にも大きな負担が生じる。原著が示すLlama 2 7BのLongBench平均では、入力長3376トークン、出力長68トークンであり、最初のトークンの生成時間は後続の一段階の21倍、生成全体の約23%を占める。この数値は特定モデルとベンチマークの平均であり、あらゆる運用負荷に共通する比率ではない。

既存の鍵・値キャッシュ削減法の多くは、入力文の鍵・値を一度計算した後で保存量や復号時の読出し量を削減する。その方式では、入力処理自体の費用を回避できない。別の方法である静的な文脈圧縮は、入力文から不要と判断した部分を最初に削るが、後続の生成でその部分が必要になっても取り戻せない。LazyLLMは**入力処理中からトークンを選別し、かつ後の生成で選択を変更できる**点で両者と異なる。独立した予測器を学習するのではなく、直前層で実際に得られた注意分布を選択信号とすることが、学習不要という性質につながる。

## 手法

### 直前層の注意確率からトークン重要度を得る

生成段階ごとに、ある層の注意行列から、次のトークン予測に使われる位置が各入力トークンへ向けた注意確率を取り出す。注意頭が複数あるため、原著の式(1)では頭方向に平均し、各入力位置に一つの重要度を割り当てる。これを次の層へ通すかどうかの判断に使う。例えば、直前層で現在の予測位置からほとんど参照されない入力位置は、その時点の深い層で計算しても次トークン予測への寄与が小さいと見なす。ただしこの重要度は注意確率から作る近似信号であり、トークンが今後の生成全体で不要であることを証明するものではない。

層や課題によって注意確率の絶対値の分布は異なるため、単一の絶対閾値ではなく、入力位置を重要度順に並べて指定割合だけ残す順位方式を採る。ある層で除外された位置は、その生成段階では後続層の計算対象から外れる。入力位置の対応を保持しなければ、復帰した際に誤った位置の鍵・値を参照してしまうので、保持集合と元系列の対応は実行時状態として管理する。論文の図4は、ある層の出力を次層で絞り、保持位置の鍵・値と除外位置の途中状態を別々に扱う処理を示している。

### 深い層ほど強く枝刈りする

浅い層で大量に削除すると、まだ十分に構築されていない文脈表現を失い、深い層の予測まで悪化させる。原著の図6は、同じ割合を除外するなら、浅い層より深い層で除外したほうが得点が保たれやすいことをLlama 2とXGenの両方で示す。この観測を踏まえ、LazyLLMは層が進むにつれて段階的にトークンを減らす。最初から入力文を固定長に切り詰めるのではなく、表現を形成する浅い層では多く残し、後段で不要度が高い位置を追加的に除外する。残存割合、枝刈り層の位置、適用する層の数は速度と得点を同時に左右する調整値である。

ここで「ある層で除外した位置はその生成段階の後段へ渡さない」という単調性と、「次の生成段階では除外済み位置を再選択できる」という時間方向の可逆性を区別する必要がある。同じ生成段階の途中で無条件に全位置を戻す方式ではない。次に生成するトークンが変わると参照すべき文脈も変わり得るため、生成段階ごとに必要位置を再評価する設計である。

### 補助キャッシュで除外位置を途中層から復帰させる

通常の鍵・値キャッシュには、計算済みの位置の鍵と値が層ごとに保存される。一方、層 `l` で除外した位置には層 `l+1` の鍵・値が存在しない。後の生成でその位置が必要になったとき、入力層から再計算すると、先に節約した計算を重複実行してしまう。そこで補助キャッシュ（Aux Cache）に、除外直前の層の隠れ状態を保存する。後の生成段階で復帰する位置について、次層の鍵・値が既にあれば通常キャッシュから取り出し、存在しなければ前層の補助キャッシュから隠れ状態を取得して、その先だけを計算する。

原著の図4にある例では、位置T1とT8は通常の鍵・値キャッシュから再利用でき、位置T3のように後段の鍵・値が未生成のものは補助キャッシュの隠れ状態から計算を再開する。重要なのは、保存する対象が「完成した全層の鍵・値」ではなく「後で計算を続けるための途中表現」である点である。この構造によって、同じ入力位置の同じ層の計算を生成全体で何度も繰り返すことを防ぐ。原著は各位置・各層を高々一度計算するという性質を述べるが、これは計算の重複回避についての性質であり、追加の索引管理や補助キャッシュ容量を含めたあらゆる実装の壁時計時間が必ず改善するという意味に広げてはいけない。

### 実際の処理の流れと追加費用

一つの入力文が与えられると、浅い層で文脈表現と注意分布を計算し、その注意から次層へ進む入力位置を選ぶ。選ばれた位置だけで次層を実行し、除外位置の途中状態は補助キャッシュへ退避する。深い層へ進むにつれて残存位置をさらに減らし、最初の出力トークンを得る。続く生成段階では、過去に計算済みの鍵・値を再利用しつつ、今回必要だが未計算の位置だけを補助キャッシュから復帰させる。こうして、初回入力処理と後続復号の両方で不要な計算を遅延させる。

費用面では、注意確率から重要度を集計する処理、位置集合の選択・再配置、補助キャッシュへの隠れ状態保存と読出しが増える。保持位置が不規則で少数になると、密な行列演算に最適化された実装の効率が低下する可能性もある。したがって入力位置の累積計算率と実測の速度改善は同一の指標ではない。補助キャッシュを使うため、計算量の削減をそのままGPUメモリ使用量の削減とみなすこともできない。

## 評価条件と比較方法

| 項目 | 原著の条件と意味 |
|---|---|
| モデル | Llama 2 7B、XGen 7B。両者とも追加学習なしで同一の公開済み重みを使用 |
| 計算機 | NVIDIA A100。理論演算数ではなく実際の壁時計時間を測定 |
| ベンチマーク | LongBenchの16データ集合、単一文書質問応答、複数文書質問応答、要約、少数例学習、合成課題、コード補完の6群 |
| 比較方式 | 通常推論、無作為なトークン除外、静的な注意依存枝刈り、別モデルによる入力圧縮 |
| 速度指標 | 最初のトークンまでの時間の倍率と、全出力完了までの時間の倍率を別々に計測 |
| 品質指標 | 各データ集合の課題別指標をLongBenchの方式で集計した課題群得点 |
| 計測前処理 | 各条件で5回の予備実行後に測定。通常推論を1倍とする |

表1の得点は課題ごとに指標が異なる集約値なので、異なる課題群の得点同士を直接比較して「何点優秀」と結論づけない。まず同一課題群内で通常推論と比較することが重要である。入力圧縮方式では圧縮後の短い文だけを実行すれば速くても、圧縮自体の計算費を含めると最初のトークンまでの時間が長くなる。原著表1では、Llama 2の単一文書質問応答で入力圧縮は0.12倍にとどまり、速度改善ではなく大幅な悪化である。

## 評価結果

### 最初のトークンまでの時間と品質

| 課題群 | Llama 2：通常→LazyLLM得点 | Llama 2：初回高速化 | XGen：通常→LazyLLM得点 | XGen：初回高速化 |
|---|---:|---:|---:|---:|
| 単一文書質問応答 | 25.79→25.59 | 1.36倍 | 25.19→25.00 | 1.96倍 |
| 複数文書質問応答 | 22.43→22.31 | 2.34倍 | 20.71→20.68 | 2.65倍 |
| 要約 | 24.65→24.75 | 1.46倍 | 24.85→24.74 | 1.91倍 |
| 少数例学習 | 62.90→62.81 | 2.19倍 | 56.40→56.12 | 3.42倍 |
| 合成課題 | 4.97→4.98 | 2.89倍 | 5.40→5.66 | 4.77倍 |
| コード補完 | 55.18→53.30 | 1.94倍 | 36.49→36.47 | 3.47倍 |

複数文書質問応答では、無作為なトークン除外はLlama 2で1.19倍の初回高速化にとどまり、得点は22.43から16.77へ大きく落ちる。静的な枝刈りは2.16倍に達するものの得点は19.93で、LazyLLMの22.31を下回る。これは「重要な位置を選ぶ」だけでなく、生成段階が変わった際に以前の除外位置を復帰できることが品質保持に寄与するという主張を支持する。ただし表は複数の設計差を含む比較であり、補助キャッシュ単体の因果効果をこの表だけから数値化することはできない。

### 生成全体の時間と累積計算率

| 課題群 | Llama 2：入力計算率／全生成倍率 | XGen：入力計算率／全生成倍率 |
|---|---|---|
| 単一文書質問応答 | 87.31%／1.34倍 | 89.16%／1.33倍 |
| 複数文書質問応答 | 63.94%／1.56倍 | 69.60%／1.70倍 |
| 要約 | 99.59%／1.02倍 | 96.11%／1.09倍 |
| 少数例学習 | 69.98%／1.28倍 | 65.30%／1.59倍 |
| 合成課題 | 63.73%／1.79倍 | 40.54%／3.16倍 |
| コード補完 | 68.57%／1.01倍 | 72.61%／1.16倍 |

原著表2の「入力計算率」は、生成終了時点までに実際に処理された入力トークンの累積割合であり、最初の生成段階で保持した割合ではない。複数文書質問応答ではLlama 2の入力計算率が63.94%まで減り、生成全体でも1.56倍に改善する。一方、コード補完では68.57%まで減っていても全体は1.01倍にすぎない。後続復号の占める時間や、追加の状態管理費が異なるため、入力計算率だけから生成全体の倍率を予測してはいけない。

### 感度、負の結果、適用範囲

枝刈り層を前方へ移し、かつ残す割合を小さくすると、Llama 2とXGenの両方で得点が下がる。図6の一回だけ枝刈りする簡略実験は、深い層のほうが同じ除外割合に耐えやすいという設計根拠を与える。複数文書質問応答では、得点低下を約1%以内に保つ設定で2.34倍の初回高速化が得られ、より強い設定では約3倍に伸ばせるが、得点低下の許容幅は約10%に広がる。速度と品質は独立に最大化できない。

図7では、生成段階が進むと一度除外した位置の一部が再利用され、累積計算率が増える様子を層ごとに観察している。これは可逆的な選択の必要性を示す一方、最終的にほぼ全位置を使う課題では初回に延期した計算を後で実行することになり、総計算削減が小さくなることも示す。原著の結果はA100上の二つの7BモデルとLongBenchの課題群に基づき、極端な高同時実行負荷、異なるGPU世代、補助キャッシュ容量を厳しく制約した場合の性能まで保証するものではない。

## 限界と実装上の注意

第一に、注意確率を重要度の代用とするため、後で必要になる情報を早期に除外するリスクが残る。補助キャッシュはその位置を復帰できるが、未来の選択を完全に予測する機構ではない。第二に、途中隠れ状態の保持はメモリを消費する。保存先が通常の鍵・値キャッシュと異なるため、鍵・値キャッシュの単純な削減法として評価してはならない。第三に、位置選択や復帰の管理費は実装に依存する。第四に、生成が長い課題では最初のトークンの短縮が全体遅延へ十分に反映されない。第五に、枝刈り割合の強い設定では課題得点が悪化する。

この方式は、長い文書を読んで比較的短い回答を返す用途や、入力処理が遅延の主要因である用途に適している。一方、長い出力を生成する用途、すべての入力位置が順次重要になる用途、補助キャッシュの容量が厳しい用途では利得を慎重に測る必要がある。著者らが示した「各位置・各層を高々一度計算する」という計算再利用の性質は有益だが、ハードウェアでの遅延・容量・並列実行条件を別途検証することが不可欠である。
