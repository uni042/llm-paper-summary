# PLoRA: An NDP-Enhanced Pooled-Memory System for Cost-Efficient Multi-LoRA Serving

> PLoRAはLoRAアダプタとKVキャッシュをCXL級共有メモリへ置き、NDPで縮約して小さな結果だけをGPUへ返し、バッチ別戦略選択で1000超アダプタを低遅延に処理する。

- **著者・所属**: UC San Diego、New York University、UC Santa Cruz、Rice University、Rensselaer Polytechnic Institute、University of Pittsburgh、Samsung Semiconductor。

## 概要
PLoRAは、1000個超のLoRAアダプタとKVキャッシュをGPUやCPU DRAMへ詰め込まず、CXL等のメモリ意味論を持つ共有メモリへ置き、データの近くに小規模な近接データ処理（Near-Data Processing; NDP）演算器を配置するMulti-LoRAサービング方式である。GPUはホストCPUを介さずload/storeで共有メモリとNDPへ要求を出し、巨大なアダプタ行列やKVキャッシュそのものではなく縮約後の小さな結果だけをリンク越しに受け取る。各アダプタのバッチ数に応じて4種類のLoRA実行戦略と2種類のattention戦略を費用モデルで選び、GPUメモリ不足時にはcold adapter、KVキャッシュ、hot/serving adapterの保持優先度を含めて再配置する。H100 1基と4台の512GB共有メモリ装置をモデル化した評価では、1000アダプタ条件でS-LoRA実機比のデコードTPOTを平均6.6倍低減し、短文脈では32GB/sで性能が飽和した。メモリ集約だが計算量の小さいLoRA/KV処理をNDPへ移すことで、リンク帯域を追加演算へ交換し、CXL級からNVLink級まで同じ設計を容量拡張中心に利用できる。

共有メモリを単なる遠隔DRAMとして使わず、CXL Type-3相当装置へNDPコアを置き、GPUがload/storeとread-compute要求で直接協調する。さらに各アダプタの現在バッチに応じてGPU実行、遠隔読出し、NDP実行、GPU/NDP分割の4戦略を選び、attentionもGPU側KVと共有メモリ側KVを分散処理する。費用モデルとGPUメモリ管理を統合し、最速戦略が容量に入らない場合はcold adapterやKVを退避して全体最適を選ぶ。

代表結果として、S-LoRA比デコードTPOTは実行可能な2モデル、各評価負荷で実H100上S-LoRAに対して平均6.6倍低減、最大13.1倍。共有メモリNDPとGPU協調でCPU DRAM stagingを避ける効果が大きい。
## 問題設定
Multi-LoRAでは一つの基盤モデルを共有しながら利用者・課題ごとの小さなLoRAアダプタを1000個以上同時提供する。13Bモデル、1000アダプタ、4K文脈ではアダプタとKVキャッシュを含む容量が1.3TB超に達する一方、LoRA/KV処理の演算量は小さく、GPUを容量目的で増やすと演算器が余る。従来方式はGPUに入らないアダプタをCPU DRAMへ置き、必要時にPCIe経由でcudaMemcpyするため、カーネル停止、CPU介在コピー、PCIe帯域、DIMM容量の制約を受ける。PLoRAは容量をメモリ意味論付き共有メモリへ移し、メモリ側で縮約演算してリンクを通るデータ量を減らす。
## 新規性
共有メモリを単なる遠隔DRAMとして使わず、CXL Type-3相当装置へNDPコアを置き、GPUがload/storeとread-compute要求で直接協調する。さらに各アダプタの現在バッチに応じてGPU実行、遠隔読出し、NDP実行、GPU/NDP分割の4戦略を選び、attentionもGPU側KVと共有メモリ側KVを分散処理する。費用モデルとGPUメモリ管理を統合し、最速戦略が容量に入らない場合はcold adapterやKVを退避して全体最適を選ぶ。
## 手法
### 手法のあらまし
PLoRAでは最初に、計算密度が高く全要求で共有する基盤モデル重みをGPU HBMへ置き、容量を支配するLoRAアダプタ行列と各要求のKVキャッシュをCXLスイッチ配下の大容量共有メモリ装置へ置く。要求が到着するとGPU側ランタイムはアダプタIDごとに現在の要求数をまとめ、バッチ数、LoRAランク、GPU HBM空き量、リンク帯域・遅延、GPU演算性能、NDP演算性能、装置DRAM帯域を費用モデルへ入力する。LoRA演算については、A/B行列をGPUへ保持して全計算するE1、共有メモリから行列を直接読みGPUで計算するE2、入力だけを共有メモリ側へ送りNDPでA/B両行列を計算するE3、片方の行列をGPUへキャッシュしてGPUとNDPで前半・後半を分担するE4を比較する。小バッチでは巨大な行列転送を避けるNDP側戦略が有利で、大バッチではGPUにキャッシュした行列を多数要求で再利用する戦略が有利になるため、アダプタごとに同じ戦略を固定しない。NDPを使う場合、GPUはホストCPUへ戻らず、CXL ホスト-managed Device メモリ領域へGPU入力、演算種別、共有メモリ上の行列住所と寸法を含む記述子を書き、valid flagを最後に設定してCXL.ioのdoorbellを鳴らす。装置は記述子を読み、ローカルDRAMからA/B行列またはKVを読み出し、GEMV、GEMM、softmaxをNDPコアで実行し、巨大な入力データではなく縮約済みの小さな結果と完了フラグだけを共有領域へ返す。attentionでもKVキャッシュを基本的に共有メモリへ置き、GPU HBMへキャッシュできたKV部分はGPU、残りはNDP側でQK積・softmax関連処理・Vとの積を部分計算し、最終的なattention結果を統合する。これにより長文脈でもKV全体をリンク越しに毎トークン移動しない。戦略選択後、必要GPUメモリが予算を超える場合は、最近の要求頻度から温度を持つアダプタ集合を使い、まずcold adapterを共有メモリへ戻す。それでも不足する場合はKVキャッシュ、hot adapter、現在処理中のserving adapterを退避した派生候補も作る。退避すると次回アクセス費が変わるため、単に容量が空く順ではなく、各候補を費用モデルで再評価して最小時間の構成を選ぶ。要求が追加・終了してアダプタ別バッチ数が変わるとこの選択を更新する。結果として、GPUは基盤モデルの高密度演算と再利用価値の高いデータへHBMを集中し、共有メモリはテラバイト級容量を提供し、NDPはメモリ集約だが高縮約なLoRA/KV処理を担当する。大きなオペランドをリンクへ運ぶ代わりに小さな結果だけを返すため、リンク帯域要求が下がり、CXL級の帯域でも共有メモリがGPUローカルに近い性能で利用できる。

### メモリ意味論付き共有メモリとNDP
GPU、ホストCPU、複数のType-3相当メモリ装置をCXLスイッチで接続し、各装置に512GB級DRAMと小規模NDPコアを置く。GPUは共有メモリへ自分のload/store命令で直接アクセスでき、CPUへ制御を返してcudaMemcpyを起動する必要がない。LoRAとKV処理は例示13B構成で全メモリ消費の97.8%を占める一方、計算量は3%程度しか占めないため、1000TFLOPS級GPUを容量目的で増設するより、データ近傍の2TFLOPS級演算器へ縮約演算を移す方が資源比率に合う。装置内DRAM帯域はリンクより大きいため、NDPは内部帯域を使って巨大なオペランドを処理し、外部リンクには縮約結果だけを流す。

### read-compute要求
通常のload/storeだけではGPUが遠隔データを読み込んで自分で計算するためリンク転送量が残る。そこでPLoRAはGPUが入力、GEMM/GEMV/softmax等の演算種別、共有メモリ上のオペランド住所、バイト数、行列寸法を記述したread-compute要求をHDM領域へ書く。valid flagを最後に書くことでCXL.memとCXL.io間の順序問題を避け、doorbellは起動通知だけに使う。NDPはローカルDRAMから対象データを読み、入力バッファ・演算器・出力バッファを通して処理し、結果と完了フラグを書き戻す。新しいCXLトランザクションを追加せず標準CXL.memとMMIO上に構成するため、ホスト介在を消しながらCXL 3.1互換性を保つ。

### 4種類のLoRA協調実行戦略
E1はA/B行列をGPUへ保持して全てGPUで計算し、大バッチで再利用が多い場合に有利である。E2は行列を共有メモリからGPUが直接読み、NDPを使わないためGPUメモリ消費を減らせるがリンク転送が大きい。E3は入力をNDPへ送りA/B両段を装置側で計算して小さな最終結果だけを返すため、小バッチやリンク律速時に有利である。E4は一方の低ランク行列をGPUへキャッシュし、GPUとNDPで計算を分割してメモリ使用量と転送量の中間点を作る。各アダプタのバッチは時間とともに変化するため、費用モデルが4戦略を毎回比較し、最速かつGPU容量内の構成を選ぶ。

### 分散attentionとKVキャッシュ配置
KVキャッシュは要求数と文脈長に比例して巨大化するため共有メモリを基本保存先とし、GPU HBMに余裕がある場合だけ性能価値の高い一部を複製する。attentionをGPUだけで行うと、Qに対するK/V全体を毎デコード段階でリンク越しに運ぶことになり長文脈ほど帯域を圧迫する。PLoRAはGPUにあるKV部分と装置側KV部分へattention計算を分割し、装置側ではQK積やsoftmax、Vとの積をNDPで進めて縮約された部分結果を返す。GPU側部分と統合することで数学的結果を保ちながら転送量を減らす。アブレーションではこの分散attentionを除くと完全PLoRAより平均3.8倍遅くなり、KV近傍計算が主要寄与であることを示す。

### 費用モデル付きGPUメモリ管理
GPU HBMでは基盤モデル、LoRAアダプタ、KVキャッシュが競合するため、各アダプタだけを独立最適化すると合計容量が10倍以上超過し得る。PLoRAはリンク帯域・往復遅延、GPU/NDP演算性能、GPU/装置DRAM帯域、LoRAランク、現在バッチを使って各戦略の時間を推定し、全体容量制約と一緒に選ぶ。要求が来るたびアダプタ温度を上げ、時間とともに平均との差を緩和してhot/coldを分類し、50個の最もhotな非serving adapterを先読みする。容量不足時はcold adapterを先に退避し、さらに必要ならKV、hot、serving adapterを退避する候補も生成する。退避後の再読込費まで含めて再順位付けするため、単純なLRUではなく性能影響と容量解放を同時に扱う。

### 全体のデータ／制御の流れ
GPUは基盤モデルの計算を担当し、共有メモリ装置はLoRA/KV容量とNDP縮約を担当する。GPU側メモリ管理器が要求分布と容量を観測し、アダプタ単位でGPU/NDP協調戦略とKV配置を選び続ける。
## 評価条件
- **ハードウェア**: NVIDIA H100 80GB、4×512GB PLoRA/CXL-PNM modeled devices
- **比較対象**: S-LoRA real H100、CPU-LoRA-オフロード、Grace-Hopper、PLoRA-NoCXL、Pure CXL、NDP-only variants、distributed-attention/strategy-selection ablations
S-LoRAは実H100上の測定値だが、PLoRAのCXL共有メモリ/NDP装置はSamsung CXL-PNMに基づく性能・面積モデルを用いるため、PLoRA全体は実機完成システムの測定ではない。主評価はH100 1基と4台の512GB装置、最大1000 LoRAで行い、モデル規模の拡張は7Bから1.2Tまで解析モデルで評価する。
## 主要結果
PLoRAは評価した全モデル・全負荷で最小のデコードTPOTを示し、実H100上のS-LoRAと比較可能な2モデルでは平均6.6倍、最大13.1倍低いTPOTとなった。CPU DRAMからの従来オフロード比では3.7〜177倍低く、ホスト介在を除くCXL load/store、NDP縮約、分散attention、アダプタ別戦略選択の効果が積み重なる。短文脈ではリンク帯域32GB/s付近で性能が飽和し、CXL 3.1想定128GB/sの4分の1でもリンクが主要律速でなくなるため、高速リンクの余剰帯域を速度より共有容量へ使えるという設計結論を得る。

- S-LoRA比デコードTPOT / 平均6.6倍低減、最大13.1倍 (比較対象: 実H100上S-LoRA; 条件: 実行可能な2モデル、各評価負荷) — 共有メモリNDPとGPU協調でCPU DRAM stagingを避ける効果が大きい。

- CPU-LoRA-オフロード比TPOT / 3.7〜177倍低減 (比較対象: CPU DRAM/PCIeオフロード; 条件: H100、複数モデル・負荷) — ホスト介在コピーと巨大データ転送を縮約結果転送へ置換する効果を示す。

- 分散attention効果 / 平均3.8倍 (比較対象: NS構成（NDP+戦略選択、attentionはGPUのみ）; 条件: 各負荷のアブレーション) — KVキャッシュ全体をリンク越しにGPUへ運ばず、共有メモリ側でattention部分計算することが主要寄与。

- 戦略選択効果 / ND(E3)比平均30%、ND(E4)比平均10%改善 (比較対象: 固定E3/E4戦略; 条件: アダプタごとにバッチ数が異なる負荷) — 小・大バッチが混在するため単一GPU/NDP分担では全アダプタを最適化できない。

- 短文脈の帯域飽和点 / 約32GB/s (比較対象: CXL 3.1想定128GB/s; 条件: 短文脈デコード) — NDP縮約後はリンク帯域を4倍増やしても速度向上が小さく、容量側への投資余地が大きい。

- 追加装置面積 / 3.4%未満 (比較対象: 参照CXL-PNM装置; 条件: NDPコア追加) — 数TFLOPS級の小規模演算追加で大きな帯域節約を得る設計。

### 負の結果・境界条件
- 固定E4はUniform負荷では完全PLoRAより約10%良い場合があるが、1000アダプタの平均ランクで必要なGPUメモリが約91GBとなりH100 80GBには収まらず、実現不能な理想値である。Grace-Hopperの450GB/sリンクは短文脈では競合するが、長文脈Llama2-13B Uniform-longではPLoRAより13.6倍遅くなり、帯域だけではKV転送量を解決できない。PLoRAのプリフィルも長文脈・大バッチではTTFTが大きく、13B、long、バッチ 1024では約119秒となるため、その領域は対象サービング範囲外とされる。

### 結果の読み方
PLoRAの本質はCXLそのものではなく、メモリ意味論付きリンクの先で高縮約演算を行うことである。LoRA/KVは容量を大量消費するが演算は軽いため、NDPへ少量の演算器を追加して大きなデータ移動を小さな結果へ変換すると、リンク帯域より共有メモリ容量が支配資源へ変わる。
## 品質への影響
LoRA行列積とattentionをGPU/NDP間で等価に分割するため、モデル出力を近似して高速化する方式ではなく原則無損失である。評価上の差は性能・容量の配置戦略によるもので、精度低下との交換ではない。
## 既存研究との差
- **S-LoRA・Punicaとの差**: S-LoRAやPunicaは一つの基盤モデル上で多数アダプタをまとめて実行するが、GPUに入らないアダプタ容量はCPU DRAMへ置きPCIe経由でstagingする。PLoRAは容量をホストの背後ではなくGPUが直接load/storeできる共有メモリへ移し、さらにNDPで縮約して結果だけを返す。
- **通常CXLメモリ拡張との差**: 単にCXLを大容量遠隔DRAMとして使うとリンク帯域が律速になる。PLoRAはメモリ側へGEMV/GEMM/softmax用NDPを置き、LoRAとKV attentionの高縮約演算をデータ近傍で実行することで、帯域要求を演算へ交換する。
- **一般的NDPとの差**: 既存CXL-PNM等は汎用の近接データ演算基盤を提供する。PLoRAの差分はMulti-LoRAのアダプタ別バッチ変動とGPUメモリ競合を考え、どの演算をどちら側で実行し何をGPUへキャッシュするかをオンラインで決めるサービング層にある。
## 限界
- **実機PLoRA装置未評価**: S-LoRA比較値は実H100から得る一方、PLoRAのCXL共有メモリとNDPは既存CXL-PNM装置を参照したモデルである。完成した4台のPLoRA装置をH100へ接続したエンドツーエンド測定ではないため、プロトコル、キュー、実装ソフトウェアの追加費用が残る。
- **専用ハードウェア前提**: 共有メモリへload/storeで到達でき、同じインターフェースから装置側NDPを起動できることが前提である。通常PCIeホストオフロードだけの既存サーバへソフトウェア変更のみで適用できない。
- **費用モデル依存**: アダプタ別戦略と退避先はリンク、GPU、NDP、DRAMの性能モデルで選ぶため、モデル誤差や急激な要求分布変化があると最適でない戦略を選ぶ可能性がある。
## 実装状態
CXL 3.1準拠のread-computeコマンド構成、NDP演算器、GPU側戦略選択・メモリ管理を具体設計し、既存Samsung CXL-PNMの仕様を参照して面積・性能をモデル化している。論文本文から公開コードは確認できず、専用PLoRA装置の実機試作による全系測定も示されない。
## 研究上の位置づけ
Multi-LoRAサービングとCXL/共有メモリ・NDPを接続するハードウェア協調型推論システムである。既存のCPUオフロードを高速化するのではなく、アダプタとKV容量の置き場所をホストDRAMからメモリプールへ移し、リンク帯域を近接演算で節約する。リポジトリ内ではオフロード・階層メモリ、LoRA/専門家キャッシュ、GPUメモリ管理の境界に位置し、SSD/NVMeより高速だがGPU HBMより大容量・低コストな新しい共有メモリ階層を扱う。
