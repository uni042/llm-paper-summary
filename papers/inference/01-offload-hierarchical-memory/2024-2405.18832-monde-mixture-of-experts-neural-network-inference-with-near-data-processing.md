# MoNDE: Mixture-of-Experts Neural Network Inference with Near-Data Processing

> GPUにないエキスパート重みを毎回GPUへ運ばず、重みを置いた拡張メモリ デバイス側でエキスパート計算を行い、小さい活性値だけを転送することでMoEのデータ 移動を減らす方式。

## 概要
MoNDEは、あまり使われないエキスパートの重みをGPUへ運ぶ代わりに、**CXLでホスト/GPUへ接続した拡張メモリ デバイス側でエキスパート GEMMそのものを実行する**方式である。CXLはCPU・GPUと外部メモリを高速に接続する接続で、この論文では単なる追加メモリではなく、デバイス側に行列 乗算用の演算器も置く。

よく使われるエキスパートは従来通りGPUで実行し、少数トークンしか受けないエキスパートは活性値だけをCXL デバイスへ送り、デバイス内LPDDRに常駐する重みで計算する。つまり、Fiddlerが「CPU DRAMにあるエキスパートをCPUで実行する」のに対し、MoNDEは**拡張メモリ デバイスに演算器を載せ、その場で実行する**構成である。

対象はSwitch-Large-128とNLLB-MoE。GPU側の性能測定には実機A100を使うが、MoNDE デバイスそのものはハードウェアの各クロック サイクルを模擬するシミュレータで評価しており、完成したCXL対応デバイスの実機ベンチマークではない。

## 手法のあらまし

MoNDEでは、重みを動かす従来方式を **PMove（Parameter Movement）**、活性値だけを動かす提案側を **AMove（活性値 Movement）** と呼ぶ。この二つをエキスパートごとに使い分けるのが中核である。

### 1. `PMove`：よく使われるexpertはweightをGPUへ持ってくる

従来のオフロードと同じく、GPUでエキスパートを計算する場合はエキスパート パラメータをCXLメモリ側からGPUへ移す。

論文ではこの重み 移動を **PMove** と呼ぶ。

データ量は概ねエキスパート重み 大きさに比例し、式上は `2E d_model d_ff` に依存するため、エキスパート数やFFN幅が大きいほど重い。

ただし多数トークンが同じエキスパートへ流れる場合は、一度重みをGPUへ持ってきた後のGEMMで転送コストを多数トークンへ分散しやすい。

### 2. `AMove`：利用tokenが少ないexpertはactivationだけdeviceへ送る

1〜数トークンしか流れないエキスパートに対して数百MB級重みをGPUへ送るのは割に合わない。

そこでMoNDEでは隠れ活性値だけをCXL デバイスへ送り、**重みはデバイス内LPDDRに置いたまま**エキスパート GEMMを実行する。

この活性値 移動を **AMove** と呼ぶ。

データ量は概ね `2BS d_model` に依存し、バッチ / 系列が小さいとPMoveよりかなり小さくなる。

つまり、

- PMove：大きな重みをGPUへ動かす
- AMove：小さな活性値を重みのある場所へ動かす

という反対方向のデータ 移動を使い分ける。

### 3. Weightの近くにmatrix multiplication用の演算器を置く

この考え方を論文では **Near-Data Processing（NDP）** と呼ぶ。メモリから遠いGPUへ大量データを送る代わりに、**データを保存しているデバイスの近くで計算する**方式である。

MoNDEのCXLメモリは単なる容量拡張DRAMではない。デバイス内部に行列 乗算を並列実行する小型演算配列とローカルバッファを持ち、ホスト/GPUから `gemm` / `gemm+relu` のようなコマンドを送ると、**LPDDRから重みを外へ出さずにデバイス内で計算できる**想定になっている。

論文がモデル化するMoNDE デバイスは、

- 8メモリ チャネル
- 512 GB容量
- 合計約512 GB/s帯域
- 64個の4×4 行列-乗算 配列
- 264 KBバッファ
- 1 GHz

という構成である。

したがってこの結果を「普通のCXL RAMへオフロードしただけ」と読むのは正しくなく、**メモリ + 計算を一体化した専用ハードウェア**が前提である。

### 4. 何expertをGPU側へ回すかを実行時に決める

全エキスパートを固定的にGPU / デバイスへ分けるのではなく、ゲート後に各エキスパートへ流れるトークン数を見て、その反復で利用トークンが多い上位 `H` エキスパートをGPU側へ回す。

残りはAMoveでデバイス側へ活性値を送り、その場で計算する。

`H`は固定値ではなく、

- PCIe / CXL帯域
- デバイス側のメモリ帯域
- 活性化エキスパート数
- GPU / デバイスの処理速度

から決める。

論文ではプロファイル結果から係数 `α` を調整し、GPUとデバイスのどちらか片方だけが長く待つ状態を減らす。

### 5. GPUとdeviceを同時に使う

利用トークンが多いエキスパートをGPU、少ないエキスパートをデバイスへ送った後、両方を同時に走らせる。

層全体は遅い側が終わるまで待つため、目的は単純にデバイスへできるだけ多く投げることではなく、**GPUとデバイスの処理時間を近づけて片側だけが遅くならないようにすること**である。

論文中の比較表では、このGPU/デバイス協調構成を `MD+LB` と表記する。

### 6. なぜsmall-batchで効きやすいか

1エキスパートへ流れるトークンが少ないほどAMoveのデータ量は小さく、PMoveの固定重み コストとの差が大きくなる。

逆にバッチが大きくなって多くのエキスパートへ多数トークンが流れると、GPUへ重みを送ってまとめて計算する方が有利になり、デバイス側で計算する相対利得は小さくなる。

つまりMoNDEは、**エキスパート利用が強く偏り、各エキスパートへ流れるトークン数が少ない場面ほど有利**な設計である。

## 評価

### まず見るところ
- **結論:** 利用トークンが少ないエキスパートの重みをGPUへ運ばずCXL接続デバイス側で計算すると、特にエンコーダワークロードのパラメータ 移動を大きく減らせる。
- **実速度:** Switchでエンコーダ 3.1倍、NLLBでエンコーダ 6.7倍など大きな改善を示す一方、デコーダ側の改善は比較的小さい。
- **品質:** 同じネイティブエキスパートを別デバイスで実行するだけなので無損失。
- **メモリ・I/O:** 通常CPU DRAMやSSDではなく、**CXL接続メモリ + 専用計算**を想定。
- **評価の強さ／注意点:** **シミュレーションのみ**。A100 プロファイルは実機だがMoNDE デバイスはハードウェアのクロック サイクル単位のシミュレータで、512 GB/s級の将来ハードウェア仮定を含む。

### 比較構成

| 略称 | 内容 |
|---|---|
| GPU+PM | 選ばれたエキスパート 重みをGPUへ移して計算 |
| MD+AM | 全エキスパートをデバイス側で活性値だけ移して計算 |
| MD+LB | 利用トークンが多いエキスパートはGPU、少ないエキスパートはデバイスで同時実行 |
| Ideal | 全重みがGPUにある理想上限 |

`MD+LB` が提案の主構成である。

### 主なlatency改善

GPU+PMに対するMD+LBの高速化倍率。

| Model | Encoder | Decoder |
|---|---:|---:|
| Switch-Large-128 | 3.1倍 | 1.1倍 |
| NLLB-MoE | 6.7倍 | 1.9倍 |

論文内の平均的なまとめでは、エンコーダ約4.9倍、デコーダ約1.5倍。

エンコーダ側の方が大きく伸びるのは、ルーティング / トークン distributionと重み 移動の条件がデバイス側計算に有利だからである。

### Abstractで示される最大値

| 比較 | 最大高速化倍率 |
|---|---:|
| Parameter-offloading 比較対象、エンコーダ | 7.5倍 |
| Parameter-offloading 比較対象、デコーダ | 3.7倍 |

これは代表的な最大値で、全バッチ / 全モデルの平均ではない。

### CPUでexpert計算する方式との比較

NLLBでCPU計算 + 活性値 移動を使う構成と比べると、MoNDEは次の改善を報告する。

| 部分 | Device側計算の遅延改善 |
|---|---:|
| Encoder | 9.1倍 |
| Decoder | 1.9倍 |

この差の主因として、MoNDE側の想定メモリ帯域がCPUの約2.7倍であることが挙げられる。

### Hardware overhead

| 項目 | 値 |
|---|---:|
| Device内演算論理回路のarea オーバーヘッド | 約3.0 mm² |

### 評価上の制約

- CXL接続の計算機能付きメモリ デバイスそのものは実チップ測定ではない。
- 512 GB/s級メモリ帯域を仮定する。
- GPUへ回すエキスパート数の調整に性能が依存する。
- エンコーダ / デコーダを中心に評価し、オンライン multi-user 提供は扱わない。
- KVキャッシュ配置は対象外。
- 通常のCPUオフロード / SSDオフロードとはハードウェア前提が大きく異なる。
