# Asymmetric Virtual Memory Paging for Hybrid Mamba-Transformer Inference

> KVキャッシュと固定長SSM状態を別物理プール・統一仮想アドレスで扱い、割当失敗時だけ容量を移してハイブリッドLLMのメモリ不足と処理性能を改善する。
## 書誌情報
- **著者**: An Xuan Nguyen
- **著者・所属**: not specified in arXiv metadata inspected
- **公開**: arXiv
- **種別**: Preprint
- **対象**: ハイブリッドLLM、KVキャッシュ、SSM状態、仮想メモリ、動的容量再配分
- **実装**: 純Pythonの割当器試作。Tritonや実推論エンジンへのカーネル統合は今後の課題。
## 概要
Mamba層とTransformer注意層を混在させるハイブリッドLLMでは、系列長に比例して増えるKVキャッシュと、層ごとに固定長の状態空間モデル（State Space Model; SSM）状態が同居する。既存の統一メモリプールはSSM状態をKVページ寸法へ合わせて水増しし、静的な二分割方式は要求分布が変わっても容量比を変えられない。AVMPは両者を物理的には別プールへ置きつつ統一仮想アドレスで扱い、片側の割当失敗時だけ余裕のある側から容量を移す。RTX 3060 12GB上の評価では、最良静的方式に対してメモリ不足事象を7.6%減らし、合成条件で要求処理性能を1.83〜13.3倍、ShareGPT再生で2.36倍にした。

AVMPはKVとSSMを同じ物理ページ形式へ統一するのではなく、それぞれに適した粒度の物理プールを分離したまま、利用側には単一の仮想ハンドル空間として見せる。さらに容量移動を予測器や周期監視で先回りせず、実際に割当が失敗した瞬間だけ発動するため、動作を決定論的に保ちながら要求分布の変化へ追随する。異種状態の物理非対称性と、ソフトウェアから見た統一性を両立する点が論文固有の中心である。

代表結果として、合成評価のOOM回数は三種類の合成ワークロード横断でfixed_dual_mr05に対して510、最良静的方式552から7.6%削減。要求分布に応じてKV側とSSM側の容量を移せるため、固定比率では片側だけ不足する状況を減らす。
## 問題設定
JambaのようなハイブリッドLLMはTransformer注意層と状態空間モデル層を混在させるため、推論時に性質が逆の二種類の状態を保持する。KVキャッシュはトークン数に比例して伸びる一方、SSM状態は層ごとに固定長である。vLLM型の統一ページ方式では固定長SSM状態まで注意層向けページ寸法へ合わせて余分な領域を予約し、報告例では容量見積りが最大7.3倍に膨らむ。一方、SGLang型の静的二プール方式は起動時に容量比を固定するため、短文中心から長文中心へ要求分布が変わると片側が不足しても他方の空きを使えず、再起動なしには比率を修正できない。
## 新規性
AVMPはKVとSSMを同じ物理ページ形式へ統一するのではなく、それぞれに適した粒度の物理プールを分離したまま、利用側には単一の仮想ハンドル空間として見せる。さらに容量移動を予測器や周期監視で先回りせず、実際に割当が失敗した瞬間だけ発動するため、動作を決定論的に保ちながら要求分布の変化へ追随する。異種状態の物理非対称性と、ソフトウェアから見た統一性を両立する点が論文固有の中心である。
## 手法
### 手法のあらまし
割当器はGPUメモリを、細粒度KVページを保持する領域と、SSM状態の寸法に合わせた連続ブロック領域へ物理的に分ける。利用側へはプール識別子を含む32ビット仮想ハンドルを返し、仮想ページ表がハンドルから対象プールと物理オフセットを解決する。KV側は標準で16トークン単位のページを使い、SSM側は状態次元と要素バイト数から必要寸法を直接決めるため、固定SSM状態を大きなKVページへ詰める水増しを避ける。要求が到着すると、その要求が必要とするKVページとSSMブロックを各専用プールから割り当て、推論側は仮想ハンドルだけを保持する。通常は二つのプールを独立に使い、片側で容量不足例外が発生した場合だけ再配分処理へ入る。状態機械は圧迫しているプールと反対側の空き率を調べ、供与側の空き率が既定の高閾値を上回る場合にだけ容量境界を動かす。供与側を一定量縮め、同じ量だけ要求側の割当可能範囲を拡張した後、失敗した割当を再試行する。両側が同時に飽和して供与元がなければ、既存状態を破壊せず容量不足として呼出側へ返す。短時間の揺らぎで容量が往復しないよう、再配分間隔は壁時計ではなく論理操作回数で制限し、同じ要求列なら同じ位置で再配分が起きるようにする。試作では両プールの最大容量をあらかじめ大きなbacking tensorとして確保し、ページ表と計数値だけを変更するため、再配分時に実データをコピーしない。このため再配分自体は軽いが、論理予算より大きなVRAMを予約する。実運用ではGPU仮想メモリの物理ページ再マップへ置き換え、実ページを必要側へ付け替える設計を想定する。要求終了時には対応ハンドルを解放し、各物理プールへ容量を戻す。こうして、通常経路は異種状態に適した粒度を維持し、需要比が外れたときだけ例外経路で容量比を修正する。

### 非対称仮想ページ表
KVキャッシュ用のKVPagesStoreとSSM状態用のSSMBlocksStoreを物理的に分離し、それぞれに本来必要な割当粒度を与える。KVページは注意層のトークン単位データ量に合わせて伸び、SSMブロックは固定状態寸法へ正確に合わせる。呼出側にはプール種別を埋め込んだ32ビット仮想ハンドルだけを返し、仮想ページ表が物理オフセットへ変換するため、推論側は二種類の物理管理方式を直接扱う必要がない。統一ページ方式のように小さいSSM状態を大きなKVページ寸法へ切り上げないため、状態の形状差がそのまま物理効率へ反映される。一方で上位の推論コードは一種類のハンドル解決APIだけを使えるので、物理プール分離が実行系全体へ漏れない。静的AVMPと直接アクセス型二プールのメモリ不足回数が一致することで、仮想化そのものが容量を失わないことも確認している。

### 割当失敗駆動の容量再配分
片側プールの割当でCapacityErrorが発生したときだけ、状態機械が圧迫側と供与候補側を判定する。供与側の空き率が既定の高閾値0.30を超える場合に限り、一定量の容量を供与側から圧迫側へ移す。移動後は元の割当要求を同じ経路で再試行するため、通常の割当処理へ特別な予測結果を持ち込まない。予測に基づく常時監視ではないため一時的な圧力へ過剰反応しにくく、最低1000操作の論理間隔を設けて再配分の連打も防ぐ。供与側の空きが閾値以下なら、その側の将来要求を危険にさらしてまで容量を奪わない。両側が同時に飽和すれば供与元が存在しないため静的分割と同様に割当失敗へ戻り、既存のKVキャッシュやSSM状態を推測で破棄しない。この例外駆動方式により、要求分布が変わったときだけ容量比を修正し、平常時の管理処理を単純に保つ。

### 移動量と決定性の制御
再配分量は一回ごとのバッチ単位で変更し、評価では128単位が容量不足削減と移動量の均衡で有力だった。小さすぎる移動では同じ圧迫がすぐ再発して再配分回数が増え、大きすぎる移動では供与側を新たに圧迫する可能性があるため、一回の移動量が主要な調整軸になる。閾値を複数変えた感度分析ではOOM回数、再配分回数、移動量が同一となり、細かな圧力閾値より移動量の影響が大きいことが示された。壁時計時間ではなく操作回数を用いるため、同じ要求列なら再配分位置を再現でき、評価や障害解析で非決定的な時間依存を避けられる。現在の純Python試作では実データをコピーせず事前確保領域の論理境界だけを動かすので移動時間は小さいが、実運用向け物理ページ再マップではページ付け替えコストと同期費用を再検証する必要がある。

### 全体のデータ／制御の流れ
異種状態ごとの物理プール、統一仮想ハンドルを解決する多解像度ページ表、容量不足時だけ動く再配分状態機械から構成される。割当・解放の通常経路は単純なプール操作とし、例外経路だけがプール境界を変更する。
## 評価条件
- **ハードウェア**: NVIDIA RTX 3060 12GB単一GPU、CUDA 13.0。
- **ソフトウェア**: 純PythonのAVMP割当器試作。比較対象はvLLMの統一パディングを模した方式と、SGLangの静的二プール比率0.5および0.9を模した割当器。
合成評価では複数の割当器、三種類の要求特性、二種類のモデル仕様、二種類のプール容量、複数乱数種を組み合わせて評価し、対応する条件同士をペアにしたブートストラップ95%信頼区間を算出する。追加でShareGPTの最初の利用者発話5000件からプロンプト長を抽出した再生評価を行う。メモリ不足回数だけでなく、完了要求毎秒、割当・解放時間、再配分時間を分解して改善要因を検証する。
単一GPU上の割当器レベル評価であり、実際のMamba-Transformer推論エンジンへ統合したエンドツーエンド測定ではない。ShareGPT再生も単語数をトークン長の代理とし、実時間到着過程を再現しない。したがって処理性能倍率はメモリ管理試作の結果として解釈し、実モデル推論へそのまま外挿しない。
## 主要結果
動的AVMPは最良の静的二プール方式に対して合成評価全体のメモリ不足事象を7.6%減らした。要求処理性能は合成条件で1.83〜13.30倍となり、より現実的なShareGPT再生では2.36倍だった。圧迫条件ではメモリ不足からの回復時間短縮が主因だが、短文中心条件ではメモリ不足差がほぼないにもかかわらず割当・解放呼出し自体が速く、大きな倍率が出た。この後者は実装上の観測であり、実推論エンジン統合後にも維持されるかは未確認である。

- 合成評価のOOM回数 / 510、最良静的方式552から7.6%削減 (比較対象: fixed_dual_mr05; 条件: 三種類の合成ワークロード横断) — 要求分布に応じてKV側とSSM側の容量を移せるため、固定比率では片側だけ不足する状況を減らす。

- 要求処理性能 / uniform_short 13.30倍、mixed_long 2.39倍、agentic_burst 1.83倍 (比較対象: 各条件の最良静的方式; 条件: 合成ワークロード) — 圧迫条件ではOOM回復時間の短縮、短文条件では割当・解放呼出しの高速化という異なる要因で改善する。

- ShareGPT再生の要求処理性能 / 2.36倍、95%信頼区間1.33〜5.65 (比較対象: 最良静的二プール方式; 条件: ShareGPT由来プロンプト長の60セル再生) — 合成の最大13.3倍より現実的な中心推定として報告され、OOM差ゼロでも割当処理短縮が効く。

- mixed_longのOOM回復時間割合 / 26.3%から8.5%へ低下 (比較対象: 最良静的方式; 条件: 容量圧迫の強い長文混合条件) — 動的容量移動が失敗後の再試行時間を直接減らすことを示す。

### 負の結果・境界条件
- 再配分を開始する圧力閾値を変えた感度分析ではOOM回数、再配分回数、移動量が同一となり、事前に想定した閾値調整効果は確認されなかった。両プールが同時に飽和すると供与元がないため動的方式でも静的分割と同様に失敗する。

### 結果の読み方
AVMPの本質的な利点は、KVとSSMの需要比が時間とともに変わる場合に固定容量比の不一致を修正できる点にある。ただし最大倍率の一部は純Python試作における仮想ハンドル経路の割当呼出し高速化に由来し、GPUカーネルを含む本番推論で同じ倍率が得られるとは限らない。
## 品質への影響
モデル演算や重みを近似しないメモリ管理方式であり、生成品質を意図的に変更しない。評価対象は割当器の性能と容量効率である。
## 既存研究との差
vLLM型の統一ハイブリッドキャッシュは異種状態を同じページ粒度へ合わせるためSSM側にパディング浪費が生じる。SGLang型の静的二プールは物理分離できるが容量比を起動時に固定する。AVMPは物理分離を維持しながら仮想アドレスを統一し、実際の割当失敗時だけ容量境界を動かすことで、両方式の欠点を同時に避けようとする。
## 限界
現在の試作は両プールが取り得る最大容量を事前確保するため、4GiBの論理プール予算に対して約9GiBを予約し、静的方式より大きなVRAM占有を持つ。純Python割当器でありTritonやCUDAカーネルを含む実推論エンジンへ未統合で、評価もRTX 3060単一GPUに限られる。ShareGPT再生は単語数によるトークン長代理と決定論的到着を使うため、実サービスの到着時刻、多利用者競合、SLO制御を再現しない。
## 実装状態
公開研究試作は純Pythonで実装され、仮想ハンドル、二種類の物理プール、割当失敗駆動の再配分状態機械を検証する。実データ移動は事前確保した backing tensor の論理境界変更で模擬しており、cuMemMapによる物理ページ再マップ、Triton統合、実推論エンジン統合は将来作業。
## 研究上の位置づけ
従来のKVキャッシュ管理がTransformerの一種類の可変長状態を主対象としてきたのに対し、AVMPはMamba-Transformer混成モデルで固定長SSM状態と可変長KV状態が共存することを出発点とする。SSDやCPUへのオフロードではなくGPU内部の容量分割問題を扱うが、異種メモリ需要へ動的に容量を融通するという点で階層メモリ管理と共通する。今後ハイブリッドモデルが普及した場合、推論エンジンのキャッシュ管理を単一ページ型から異種状態対応へ拡張する設計候補になる。
