# M6-10T：層間重み共有・分離と細粒度CPUオフロードによる超大規模事前学習

## 概要

数兆パラメータ級の大規模言語モデルを学習するには、重みだけでなく勾配、最適化器状態、活性化のための大量のメモリが必要になる。混合専門家（MoE）モデルは一回の入力で使う専門家を絞れるが、全専門家の重みと学習状態を保持する必要がある。CPUやNVMeへ重みを退避すればGPUメモリの制約を緩められる一方、CPUとGPU間の転送が学習の律速となる。GPUの台数を増やさずモデル容量を拡大するには、学習初期の収束効率と学習状態の配置を同時に改善する必要がある。

M6-10Tは、初期には複数Transformer層の重みを共有して学習し、後期には各層の重みを独立させる「Pseudo-to-Real」という二段階方式を提案する。最初の段階では巨大な計算グラフを保ちながら実際に保存するパラメータを減らし、より大きなバッチと少ない通信・メモリ転送で損失を速く下げる。次の段階で共有重みを各層へ複製し、独立した重みを学習してモデル容量を生かす。さらにGPUに残す層とCPUへ退避する層を選ぶ細粒度CPUオフロードを導入する。

著者は48層・各層10,240専門家のM6モデルを、512基のNVIDIA V100で約10日学習したと報告する。大規模実験のPseudo段階は256基のGPUで行い、Real段階で512基へ専門家を再配置した。10兆という値はMoEモデルの総パラメータ容量であり、各トークンの計算で10兆パラメータすべてが密に活性化するという意味ではない。また本論文は2021年の査読状況が明記されない作業中プレプリントであり、実験規模の主張と、現代のモデルに対する一般的な優越性を区別する。

## 問題設定と設計動機

大規模学習の費用は、モデルを一回通す演算量だけでは決まらない。Adam系最適化器では重みと同程度以上の状態を持ち、逆伝播では勾配と活性化も保持する。MoEでは専門家が複数GPUへ分散され、トークンの専門家割当による通信も発生する。ZeROなどの状態分割方式やCPUオフロードは、GPUメモリ不足を解消するが、退避した重みを順伝播と逆伝播のたびに読み込む必要がある。

本研究の着眼点は、学習の初期と後期で必要な自由度が同じではないという仮説にある。初期段階では層間で重みを共有した小容量モデルでも損失を急速に下げられ、後期には層ごとの独立した重みを導入することで性能を伸ばせる。層間共有は、Transformerの各層が同じ構造を持つことを利用する。したがって、任意の異種層を含むモデルへ機械的に適用できるわけではない。

もう一つの着眼点は、CPUオフロードの粒度である。全重みをCPUへ退避するとGPUメモリが空いているにもかかわらずPCIe転送が増える。GPUに残せる層は残し、容量制約を超える層だけをCPUへ移す方が転送量を減らせる。論文はこれを78Bモデルのステップ時間で検証している。

## 手法

### 1. Pseudo段階：層間重み共有で計算グラフと保存容量を分離

元のTransformerがL層で、各層が同じ構造を持つとする。Pseudo段階では、L層分の順伝播・逆伝播を実行する計算グラフは残すが、対応する層の重みθを共有する。各層の勾配は同じ共有重みへ蓄積する。元のL層が別々の重みを持つ場合に比べ、論文は重みと最適化器状態の容量を概念的に約1/L、勾配関連容量を約2/Lへ減らせると説明する。これは層の共有対象部分についての比較であり、埋込み、ルータ、全活性化などを含む総メモリが必ず1/Lになるという意味ではない。

この段階のモデルを著者はPseudo Giantと呼ぶ。計算グラフは深いままなので、同じ共有変換を複数回適用した表現を学習する。保存すべき重みが少ないため、同じGPU容量でバッチを大きくでき、通信とCPUオフロードを減らせる。MoEでも各層の専門家重みを共有できるが、専門家はGPU群へ分散されるため、後段の再配置を見越した配置が必要になる。原著は例として、512専門家を持つ層を256GPUへ各2専門家ずつ置くPseudo段階と、512GPUへ各1専門家ずつ置くReal段階を示す。

### 2. Real段階：共有重みを層別に複製して学習を継続

Pseudo段階で損失が十分下がった後、共有重みθsharedをL層それぞれの初期重みθ1〜θLへコピーする。この操作を著者はdelinking（重みの分離）と呼ぶ。コピー直後は各層の値が同じであり、Pseudoモデルと同じ計算を表せる。その後の学習では各層の重みを独立に更新し、共有状態では表現できなかった層ごとの機能分化を許す。これにより、最初から巨大な独立重みモデルを学習する場合より、損失が下がった初期値から学習を始められる。

入力は収束途中のPseudoモデルの共有重みとモデル構造、出力は独立した重みを持つReal Giantである。分離は単なる学習率変更ではなく、学習対象パラメータの自由度と必要メモリを大きく増やす操作となる。従って分離後にはCPUオフロードや専門家のGPU間再配置が必要になる。原著のM6-10TではPseudoを256GPU、Realを512GPUへ配置している。

### 3. 段階切替時刻の探索

Pseudo段階を長く続ければ小容量モデルの損失は下がるが、層ごとに独立した重みがないため性能の上限がある。早すぎる分離は学習初期の高速収束を十分利用できない。著者は一定間隔でPseudoモデルを一時的にRealへ変換し、短時間（例：30分）だけ学習した場合の損失低下速度を測る。その後Pseudoの元の状態へ戻し、同じ時間だけPseudoを学習して損失低下速度を比較する。Realの方が速く損失を下げられる時点を切替候補とする。

この判定は損失の絶対値だけではなく、同じ壁時計時間でどちらが速く改善するかに基づく。大規模Realモデルの一ステップが重い場合、ステップ数だけを比較すると切替時刻を誤る。短い試行学習には追加の計算費用があるが、巨大モデルを最初から学習し直す費用と比較して、段階切替の判断に用いる。

### 4. 細粒度CPUオフロード：GPUへ残す層を選ぶ

学習の順伝播、逆伝播、最適化器更新では重みと勾配の移動が発生する。著者のモデル化では、重み容量をWとしたとき、全重みをCPUへ退避し、活性化再計算を行うと、順伝播と逆伝播の読み込み、勾配の退避などによって概ね4Wの移動が必要になる。PCIe帯域が律速なら、GPU演算器の能力が高くても転送待ちが発生する。

Granular CPU Offloadingは、すべての層を一律にCPUへ退避するのではなく、GPUメモリに収まる層をGPUへ残し、残りをCPUへ移す。GPUに常駐する層の重みは順伝播・逆伝播のたびに再転送する必要がないため、GPUメモリの空き領域を活用して通信を減らせる。入力は各層の状態容量、GPU空きメモリ、CPU退避対象で、出力はGPU常駐層とCPU退避層の配置である。図3は順伝播F、逆伝播B、更新Aの各段階でCPU・GPU間を移動する状態を示す。

この方式は学習用の重み・勾配・最適化器状態を扱うもので、推論時のKVキャッシュをCPUへ退避する方式とは転送対象が異なる。またCPU容量自体も有限であり、全モデルをCPUへ置くとCPU側でメモリ不足となる場合がある。細粒度化はPCIe転送を減らす一方、配置と転送のスケジューリングを複雑にする。

### 5. M6-10TのMoE構成と専門家再配置

大規模実験のM6は48層で、各層のFFNをMoEへ置き換える。隠れ次元は1,024、中間次元は9,984、各MoE層の専門家数は10,240、専門家プロトタイプは80である。著者は補助損失のメモリ費用を減らす構成を採用し、Whaleフレームワークで専門家の分散と細粒度オフロードを扱う。8GPUのワーカーノードを100Gb RDMAで接続し、各ノードのCPUメモリは約750GBとする。これは一般的な単一GPU推論ではなく、数百GPUの分散学習構成である。

Pseudo段階は同じ計算グラフを持つが共有重みにより保存容量が小さいため、256GPUでCPUオフロードなしに学習できた。Real段階では重みを独立化し、専門家を512GPUへ再配置してCPUオフロードを使用した。専門家の数が大きいことと、各トークンで全専門家が実行されることは異なる。論文の10兆パラメータは総モデル容量であり、活性化されるパラメータ数や推論速度を直接表す指標ではない。

## 評価

### 1. 中規模モデルの比較条件

手法の妥当性を検証する中規模実験では、BookCorpusと英語Wikipediaの約16GBのテキストを用い、系列長512、語彙数約50,000、48基のNVIDIA V100で事前学習した。比較するM6は、24層・約350MのBase、36層の計算グラフを共有重みで実行するPseudo、36層が独立重みを持つ約1.4BのReal、二段階学習のP2Rである。Pseudoの実保存パラメータは約90Mと説明される一方、表1の「#Params」欄は計算グラフの規模に合わせて1.4Bと表記されるため、両者を混同しない。

最適化器はAdamW、ピーク学習率はPseudoで2×10^-4、Realで8×10^-5、ウォームアップ比率は0.001。総バッチサイズは6,144で、マイクロバッチ32、勾配蓄積4とする。比較は同じ壁時計時間の制約下と、より長く学習したP2Rの二条件で行う。WikiText-103の困惑度とGigawordの要約ROUGEを測り、学習時間に対する損失低下も比較する。

### 2. 中規模モデルの処理速度と品質：原著表1・表2

| 構成 | 48GPUでの学習処理量（samples/s） | 備考 |
|---|---:|---|
| M6 Base 350M | 650 | 24層の小型モデル |
| Pseudo（36層計算グラフ） | 248 | 共有重みで保存容量約90M |
| Real（36層独立重み） | 48 | 約1.4Bの独立パラメータ |

同じ36層計算グラフではPseudoがRealの約5.17倍のサンプル処理量を得る。ただしBaseの650 samples/sはモデル幅・層数が異なるため、Pseudoとの直接のアルゴリズム比較ではない。

| 条件 | WikiText-103困惑度（低いほど良い） | Gigaword ROUGE-1/2/L |
|---|---:|---|
| Base M6 350M | 16.59 | 38.8 / 20.1 / 36.0 |
| Pseudo単独・時間制約 | 56.79 | 36.8 / 17.9 / 34.1 |
| Real単独・時間制約 | 26.80 | 36.9 / 18.2 / 34.2 |
| P2R・時間制約 | 23.60 | 37.3 / 18.3 / 34.5 |
| P2R・長時間学習 | 16.52 | 38.0 / 19.2 / 35.4 |

同じ時間制約ではP2RがPseudo単独・Real単独より困惑度を改善した。ただし小型Baseの16.59より悪く、二段階学習が同じ時間で常に小型モデルの品質を超えるわけではない。長時間学習では困惑度16.52へ改善するが、GigawordのROUGEはBaseの38.8/20.1/36.0を超えていない。著者自身も要約タスクで最高性能へ達していないことを限界として述べている。

### 3. 細粒度オフロードのステップ時間

78Bパラメータ、48層のM6を8基のV100で学習する予備実験では、全層をCPUへ退避すると1ステップ89秒かかった。最初の24層だけをCPUへ退避し、残り24層をGPUに常駐させると45秒へ短縮した。約1.98倍のステップ時間改善であり、GPUメモリの空き領域を活用して転送を減らした効果を示す。これは78Bの特定の層分割と装置条件における結果で、全モデル規模で必ず同じ倍率となるわけではない。

### 4. 10兆パラメータの大規模実験

| 項目 | 原著の設定・結果 |
|---|---|
| モデル | M6の48層MoE、各層10,240専門家 |
| 計算環境 | 8GPUノード、100Gb RDMA、各ノード約750GB CPUメモリ |
| Pseudo段階 | 256基V100、CPUオフロードなし、約14秒/ステップ |
| Real段階 | 512基V100、細粒度CPUオフロード、約180秒/ステップ |
| 二段階学習全体 | 約10日、約15,000ステップ |
| Realを最初から学習した比較 | 約3日、約1,300ステップ |

Pseudo段階の1ステップは約14秒、Real段階は約180秒であり、約12.9倍のステップ時間差がある。これは二つの段階でモデルの実保存容量とGPU台数、CPUオフロードの有無が異なるためで、同じモデル・同じGPU数に対する純粋なカーネル高速化率ではない。原著図4(a)は時間軸に対する学習損失を比較し、二段階方式の方が速く損失を下げたことを示す。ただしP2Rは約10日、Real単独の比較は約3日であり、総学習期間は一致していない。公平に見るべきなのは図の重なる時間領域での損失推移である。

著者は従来の1兆パラメータM6-Tとの比較も図4(b)に示し、学習サンプル数に対する損失の低下で10Tモデルの利点を報告する。しかし10Tモデルの下流タスクでの広範な優越性を実証した表はなく、論文も超大規模モデルの微調整と下流能力の検証を今後の課題とする。したがって「10日で10Tを学習した」は学習システムの実装可能性を示す結果であり、同じ計算予算であらゆる用途の品質が最高になったという主張ではない。

## 限界と適用条件

Pseudo-to-Realは同じ構造の層を複数重ねたモデルに適用しやすいが、層ごとに異なる形状や役割を持つ構造では単純な共有と複製ができない。初期段階の重み共有は表現の自由度を制限するため、分離時刻を誤ると最終品質や学習効率が悪化し得る。切替判断のための短時間の試行学習にも追加費用がある。MoEの専門家再配置は通信トポロジーやノードのメモリ容量に依存し、単一GPUで再現できる設計ではない。

細粒度CPUオフロードはGPU常駐層を選んでPCIe転送を減らすが、CPUメモリ、PCIe帯域、活性化再計算、GPUの空き容量によって最適な退避層数は変わる。78Bの89→45秒という結果を、10Tや推論時のKVキャッシュ退避へそのまま外挿してはならない。Real段階の180秒/ステップは大規模モデルのCPUオフロード費用がなお重いことを示す。学習初期のPseudo段階で多くのステップを安く実行できることが全体の効率改善の主要因である。

原著の10T実験は2021年のV100・100Gb RDMA・EFLOPS・Whale環境に基づく。モデルは総パラメータ10兆のMoEであり、同じ数の密モデルと演算費用やメモリ転送を比較できない。大規模学習の品質評価は主に学習損失で、10Tの幅広い下流タスク精度や実サービスの推論速度は示されていない。中規模の長時間学習でもGigaword要約では小型Baseを超えない負の結果がある。論文は査読済み会議論文ではなく作業中のプレプリントであるため、当時の技術的実証と一般的な品質保証を区別する必要がある。
