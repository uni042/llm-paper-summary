# OLED-MoE: Accelerating MoE-Based dLLM Inference via Inter-Iteration Locality-Aware Expert Offloading

> dLLMの隣接デノイズ反復で専門家経路が再利用される性質を、確信度予測・層別保持・CPU/GPU協調へ利用するMoEオフロード。既存方式比TPOTを1.23〜7.93倍改善。

## 概要
混合専門家モデル（Mixture-of-Experts; MoE）は全専門家を毎回計算しないが、専門家重み自体は大きく、GPUへ全常駐できない場合がある。自己回帰モデルでは一反復がほぼ1トークンなので、現在層を計算する間に次層の必要専門家をCPUからGPUへ先読みしやすい。ところが拡散型LLM（diffusion LLM; dLLM）はブロック内の多数トークンを同時にデノイズし、一反復の活性専門家集合が最大約8倍へ広がる。転送量が増えて先読みが間に合わず、誤予測転送が現在のミス補償用PCIe帯域まで奪う。

OLED-MoEは、同じブロックを何度もデノイズするため隣接反復の同一層で専門家集合が重なる点へ着目する。次層を先読みするのではなく、現在GPUにある専門家のうち次反復でも使われそうなものを残す。既存オフロード方式に対し出力トークン当たり時間（time per output token; TPOT）を1.23〜7.93倍改善し、専門家キャッシュ利用率を1.44〜4.23倍高める。

## 問題設定
dLLMではブロック内の複数トークンが各層で専門家を選ぶため、一反復中の作業集合が広い。自己回帰向け先読みは「次層へ到達するまでの計算時間」を転送猶予として使うが、必要専門家数が増えるとPCIe転送を隠せない。しかも外れた先読みはキャッシュを汚染し、現在必要な専門家の転送を遅らせる。

一方、反復tとt+1は同じトークンブロックを段階的に確定していくので、専門家経路は独立ではない。高確信度トークンほど次反復でも同じ専門家へ行きやすい。OLED-MoEはこの反復間局所性を、追加の予測モデルを走らせずに利用する。

## 手法
### 確信度誘導の反復間保持
各トークンのデノイズ確信度とゲートスコアを専門家単位へ集約し、次反復で再利用される価値を計算する。入力は現在反復のルーティングと確信度、出力は各専門家の保持優先度である。最近使っただけのLRUでは、不安定トークンが一時的に選んだ専門家を残すため、再利用価値を明示的に使う。

### 層適応キャッシュ配分
層ごとに活性専門家数と反復間重複が異なるため、全層へ同じ専門家枠を割り当てない。観測された局所性に応じてGPU専門家キャッシュを層間で配分し、同じ総メモリ予算でも再利用されやすい層へ容量を寄せる。

### CPU–GPU協調ミス補償
保持予測が正しくてもGPU容量不足でミスは残る。ミス専門家をCPUで計算すればH2D転送は不要だが、将来も繰り返し使う専門家ならGPUへ持ってきた方が後続反復を速くできる。OLED-MoEは現在の専門家計算負荷と予測再利用を同時に見て、CPU実行かGPU転送かを決める。

この選択は現在反復だけの最短時間ではなく、転送した専門家が次反復のキャッシュを温める効果まで含む。これが単純なload-only協調との差である。

## 評価条件
|項目|内容|
|---|---|
|対象|MoE型dLLM、LLaDA2.0系を含む|
|GPU構成A|GeForce RTX 5090 32GB、16B級モデル向け|
|GPU構成B|RTX PRO系大容量GPU、100B級モデル向け|
|ワークロード|GSM8K、HumanEval、GPQA等の混合を含む|
|比較軸|TPOT、専門家キャッシュ利用率、TTFT、PCIe帯域・キャッシュ容量感度|
|比較|自己回帰MoE向け既存オフロード方式、LRU/LFU等|

## 主要結果
既存の最先端オフロード方式に対し、OLED-MoEはTPOTを1.23〜7.93倍改善し、専門家キャッシュ利用率を1.44〜4.23倍高める。専門家GPUメモリを全常駐の40%に削っても、全常駐構成に対するTPOT増加は23%に留まる。

構成要素除去では、単純な反復間キャッシュから始め、再利用優先度、層適応配分、協調補償を順に追加するとTPOTが段階的に低下する。論文はキャッシュ容量、PCIe帯域、バッチサイズ、ブロック長への感度も評価し、利得が単一設定だけに依存しないことを確認している。

## 既存研究との差
従来のMoE-Infinity系や先読み型方式は層方向の未来、つまり同一反復内の次層専門家を予測する。OLED-MoEはdLLM固有の時間方向、つまり同一層の次デノイズ反復を予測対象に変える。新たな先読み転送を増やさず、既にGPUへある専門家を捨てない判断へ予測を使うため、PCIe競合を避けやすい。

## 限界・実装状況
利得は隣接デノイズ反復に専門家局所性があることへ依存する。ルーティングが反復ごとに大きく変わるモデルでは保持予測が弱くなる。CPU補償性能とPCIe帯域にも依存し、ハードウェア比率が異なれば最適な転送/CPU実行境界は変わる。論文はソースコード公開を明記し、EuroSys 2027採録情報を示している。
