# EMA: Elastic and Performance Transparent Memory Across GPUs

## 概要
複数GPUサーバでは総メモリ量が十分でも、各GPUへ固定分割されているため局所的な不足が起きる。LLM推論では要求長やKVキャッシュ量が時間とともに変わり、GPU Aが容量不足で要求を拒否している横でGPU Bに未使用領域が残ることがある。EMAはこの断片化を、GPU間でメモリを貸借する弾力的な容量プールとして扱う。

設計目標は単に遠隔GPUメモリを読めることではなく、借り手と貸し手の双方に性能透過性を与えることである。借り手には先読みで遠隔アクセス費を隠し、貸し手には必要になった容量を回収できる仕組みを用意する。評価では個々の利用者スループットを最大52%改善し、メモリ容量を2倍に用意した構成の96%のスループットを達成しながら、遅延は静的ローカル基準と同程度に保った。

## 問題設定
GPUメモリを静的に予約すると性能予測は容易だが、需要変動を吸収できない。特にLLMサービングではKVキャッシュが要求ごとに異なり、同じモデルでも長文脈要求が集中したGPUだけが高帯域メモリを使い切る。要求を別GPUへ移す方法はモデル重みや実行状態の移動を伴い、単なるメモリ不足に対して高価である。

一方、統合メモリのように遠隔領域を自動利用するだけでは、借り手の遠隔アクセス遅延と貸し手の容量圧迫が問題になる。貸した側の需要が戻ったとき、借り手がページを保持し続ければ貸し手性能が静的分割より悪くなる。EMAは「余剰時だけ貸し、必要時には元の所有者が取り戻せる」という契約を中心に置く。

## 手法
第一の機構は、GPUごとの未使用メモリを貸出可能領域として公開する弾力的プールである。借り手GPUでローカル容量が不足すると、同一サーバ内の別GPUからページを借りる。入力は各GPUの需要と空き容量、出力はローカルと遠隔を組み合わせた仮想的な割当であり、アプリケーションは総容量をより柔軟に使える。

貸出先を無制限に増やすと遠隔アクセスが増え、相互接続帯域を圧迫する。したがってEMAはローカルメモリを第一選択とし、不足分だけを遠隔へ置く。GPU間接続が遅い環境ではこの費用を隠せないため、高帯域なサーバ内接続が重要な前提になる。

第二の機構は借り手向けのプリフェッチである。遠隔ページを実際に参照してから取り寄せると、その遅延がカーネル実行へ直接現れる。EMAはアクセス順序を利用して必要なページを事前にローカル側へ準備し、現在の計算とデータ移動を重ねることで遠隔とローカルの性能差を小さくする。

先読みが当たればアプリケーションは遠隔配置を意識せずに近い性能を得る。需要が予測から外れたり、同時転送が相互接続帯域を使い切ったりすると待ちが発生する。このため「性能透過」は物理的に遠隔アクセスが無料という意味ではなく、典型的アクセスで費用を重畳して隠す設計目標である。

第三の機構は貸し手の回収権である。貸し手GPU自身の需要が増えたとき、他GPUへ貸していた領域を回収し、静的に自分へ割り当てられていた容量を再び利用できるようにする。これにより、他利用者へ善意で貸したことが将来の自分の性能低下へ直結しない。

回収時には借り手側のデータを別領域へ移す必要があり、瞬間的な転送費が発生する。EMAは回収を需要変化と協調させ、貸し手が静的分割より悪くならないことを優先する。借り手に代替容量が無ければ、借り手側の余裕は減るため、弾力性はサーバ全体の実空き容量を超えて作れるものではない。

第四の機構は、貸借・先読み・回収をアプリケーションから隠す実行時管理である。利用者が個別にGPU間コピーを記述するのではなく、メモリ割当とアクセスを観測して配置を調整する。これにより既存ワークロードへ導入しやすくし、資源共有をアプリケーション固有の手作業から切り離す。

一つのLLM要求で見ると、KVキャッシュ増加でローカル容量が不足した時点で遠隔GPUの余剰ページを借りる。次に読むページは先読みされ、GPU計算と転送が重なる。貸し手側で新要求が来れば回収を開始し、借り手のデータを別の余剰領域へ移す。こうして容量不足時だけ共有し、需要が戻れば元の境界へ近づく。

## 評価条件と主要結果
評価は複数GPU環境で、静的に各GPUへメモリを分割する基準と、より大きな容量を用意した理想寄り構成を比較する。EMAは利用者単位のスループットを最大52%改善した。これはGPU演算を52%高速化したのではなく、局所的なメモリ不足による停止や低効率配置を空き容量共有で減らした結果である。

さらにEMAは容量を2倍に静的用意したシステムの96%のスループットを達成し、遅延は静的ローカル基準と同程度を維持した。余剰メモリを共有することで、常時2倍容量を購入する場合に近い性能を狙えることを示す。

## 既存研究との差
従来の統合メモリや遠隔メモリは、借り手が容量を拡張できても貸し手の性能保証を中心に据えない場合がある。EMAは借り手の先読みと貸し手の回収可能性を同時に設計し、共有前の静的分割を性能下限として扱う点が特徴である。

## 限界
高帯域GPU間接続を前提とし、PCIeだけの構成では遠隔転送を十分隠せない可能性がある。サーバ全体のメモリが同時に不足する場合、貸し借りだけでは容量を増やせない。またアクセス予測が外れるワークロードでは借り手側の遠隔遅延が見えやすくなる。

## 実装状況
研究は実際の複数GPUサーバ上でスループットと遅延を測り、静的分割および増設容量相当の構成と比較している。LLM推論の動的メモリ需要を主要動機にしつつ、原理は他のGPUワークロードにも拡張できるとしている。
