# FlashMoE: Reducing SSD I/O Bottlenecks via ML-Based Cache Replacement for Mixture-of-Experts Inference on Edge Devices

> 大規模MoEの非活性expertをSSDへ置き、recencyとfrequencyから将来再利用距離を推定する軽量学習cacheでSSD I/Oを削減し、メモリ制約下の実機推論を高速化する。

## 問題
MoEは各tokenで一部expertだけを実行するため計算量は疎だが、近年のモデルは全expert weightが数十〜数百GB級になり得る。FiddlerやDAOPなどDRAMを下位階層として使うoffloadは、16〜64GB程度のconsumer desktopでは全モデルをDRAMへ保持する前提自体が成立しにくい。SSDを最下位階層にすると容量問題は解ける一方、expert cache missごとのSSD I/Oがdecode latencyを支配する。

## 新規性
FlashMoEは、(1) expert/non-expertをファイルレベルで分離しexpertをlayer・expert単位の `.pt` としてSSDからon-demand loadする構成と、(2) LRUのrecencyとLFUのfrequencyを入力にしてBeladyのoracle evictionを近似する小型FFN cache policyを組み合わせる。単なるSSD offloadではなく、SSD miss penaltyが大きい環境向けにexpert-aware replacementを学習する点が中心である。

## 手法
### モデル分割と読み込み
attention、normalization、routing gateなど常時必要なnon-expert部分だけを起動時にmemoryへ載せ、expertはlayer/index別ファイルとしてSSDに置く。prefillではbatch中にrouteされたunique expertを各layerで一度だけ読み込み、複数tokenをまとめてexpert MLPへ通す。これにより全モデルを最初にDRAMへロードする方式を避ける。

### Decode時のexpert cache
各layerに固定数のresident expert枠を設け、VRAM容量に応じてcache sizeを調整する。論文の実測ではexpert loadがdecode時間の70%以上を占め、SSDから1 expertを読む時間は約3msである。一方、cache policyのFFN推論は平均158µsで、expert loadと非同期に重ねることでpolicy overheadを隠す。

### 学習cache replacement
各expertについて最終accessからの距離を表すrecencyと累積routing回数のfrequencyを正規化し、3層・hidden size 128・SiLUのFFNへ入力する。教師はrouting trace上でBelady optimal policyを適用して作る将来再利用距離／eviction対象である。TriviaQA 512 sample（各最大512 token）のrouting traceを使い、OLMoE-1B-7BではA100 1枚・batch 32でtrace抽出20分未満、feature生成と学習を含むpipeline全体は約2時間、per-layer modelは約113KBと報告する。

## 評価条件
- 実機: Ryzen 9 9600X、RTX 5070 Ti 16GB、SK hynix P51 PCIe 5.0 NVMe SSD（read 7.4GB/s）、DDR5-6000 16GB×4、Ubuntu 24.04、PyTorch 2.7/CUDA 12.9。
- system DRAMは干渉を抑えるため約1GBだけ利用可能に制限。
- model: OLMoE-1B-7B、Qwen3-30B-A3B。
- cache学習と速度・hit-rate評価はTriviaQAの分離splitを使用。
- 比較: LRU、LFU、ARC、LeCaR、およびsystem baselineとしてllama.cpp、Fiddler、DAOP。

## 主要結果
OLMoE-1B-7Bでは学習cacheがLRUよりcache hit rateを21%、LFUより51%改善し、I/Oをそれぞれ22%、35%削減した。ARC、LeCaRに対しても最大28%、21%高いhit rateを報告する。cache policyだけをLRUから学習方式へ変えたtoken生成速度はOLMoEで約22%、Qwen3-30B-A3Bで約7%向上した。

起動時にnon-expertだけを読む分割方式により、初期model loadはllama.cpp比4倍、Fiddler/DAOP比6.8倍高速。prefillで必要expertをSSDから読む時間まで含めても、合計latencyはllama.cpp比2.5倍、Fiddler/DAOP比4.1倍高速と報告する。全体では既存MoE inference systemに対し最大2.6倍のspeedupを示す。

入力長が32→64→128→256 tokenと倍増してもrouteされるexpert割合は約47%→58%→64%→67%とsublinearに増え、長いpromptでも全expertを読む必要はないという観測も示される。

## 限界
評価は高速PCIe 5.0 NVMe SSDとRTX 5070 Tiを備えた単一desktop構成が中心で、低速SSD・PCIe世代・異なるfilesystemやOSでの一般性は未確認である。学習cacheはTriviaQA routing traceから作られており、domainやrouting distribution shiftへの頑健性は十分評価されていない。Fiddler/DAOPはDRAM offloadを主眼とするため、約1GBにDRAMを制限した環境では設計上不利であり、比較値は「同じ厳しいmemory制約下」でのsystem差として解釈する必要がある。

また、cache policyはBelady由来の教師を使うためoffline trace収集と事前学習が必要で、未知modelへ即適用できる完全training-free policyではない。論文はSSD耐久性、write amplification、複数requestを同時serveする際のcache interferenceを主要評価対象としていない。

## 既存研究との差
FiddlerやDAOPなどが主にGPU↔CPU/DRAM階層でexpertをoffloadするのに対し、FlashMoEは全expertがDRAMにも収まらないconsumer environmentを対象にSSDを実質的なlast-level model storeとする。LRU/LFU単独ではなく、両者の信号からBeladyの将来再利用判断を近似し、SSD miss回数を直接減らす点が特徴である。

## 一般的な実装への示唆
SSD expert offloadでは単純な帯域幅だけでなく「1 missあたりの固定load latency × miss回数」がdecode性能を大きく左右する。policy推論がSSD I/Oより十分短ければ、I/Oとoverlapさせることで高度なreplacement policyの計算costを隠せる。また、expert/non-expertを事前に物理分割しておくことでstartup時に全weightを経由させない設計は、容量階層化とcold-start短縮を同時に狙える。
