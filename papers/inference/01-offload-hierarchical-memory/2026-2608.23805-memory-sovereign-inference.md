# Memory-Sovereign Inference：全常駐を超える出力完全一致推論

## 書誌情報

Lukas Stepanekによる2026年8月24日投稿の研究で、arXiv識別子は2608.23805である。ストレージを容量階層として使うLLM推論について、「生成できた」ことと「メモリ制約を守り、正しい非同期再利用を行い、出力が一致した」ことを分離して検証する計測・実行研究である。

## 概要

重みをストレージから逐次読み込む推論では、プロセスの常駐集合だけを見ればページキャッシュを見落とし、プロセス内GPU計測だけではボード全体の使用量を見落とす。また一度正しい文章が出ても、非同期再利用が別要求で壊れない保証にはならない。このため容量超過推論の主張は測定境界を曖昧にすると過大評価されやすい。

本研究は表現量、意味的に要求された重み、スケジューラが要求した転送、実際の入出力を別々に記録し、資源を誰が課金するかと、どこまで出力一致を検証したかを明示する。固定Qwen3-Next条件では32Kプリフィルで48×512個の管理対象層・専門家がすべて選ばれ、重複除去後の意味的要求下限43.59375 GiBが宣言34 GiB常駐枠を超える一方、LRU64実行は設定したホスト・GPU契約内で64出力をオラクルと完全一致させた。

## 問題設定

容量超過推論を示すには、モデル全体の論理サイズと実際に一要求が触れた重み量を区別する必要がある。ルータが一部専門家だけを選ぶMoEでは、全モデルが大きくても要求が少数専門家しか触れなければ「全常駐を超えた」証拠にはならない。そこで実際に選択された管理対象の重複なし和集合を意味的要求量として測る。

さらにLinuxのページキャッシュやGPUの他プロセス使用量を無視すると、ホストやデバイスの実消費を過小評価できる。研究はホスト側の強制上限、物理デバイス側の監査、ストレージ読み出し量を別の権威ある計測面として扱い、単一のRSS値だけで容量主張を行わない。

## 手法

第一の機構は四層の証明書である。モデル表現として存在する重み集合、実行が意味的に必要とした重み集合、スケジューラが読み込みを要求した集合、物理的に発生したストレージ転送を別々に記録する。これにより「必要だったが再利用で読まなかった」場合と「そもそも選択されなかった」場合を区別できる。

入力はルーティング記録、重み識別子、転送要求、物理入出力記録で、出力は重複のない容量・転送証明になる。識別子が重複したり範囲が重なったりすると容量を二重計上できるため、正規和集合として計算する。計測面が欠けた場合は強い主張へ昇格せず、証明できた範囲だけを残す。

第二の機構は資源権威の明示である。ホストメモリは強制上限と課金イベント、GPUはボード全体の監査値、ストレージは物理ソースバイトを使い、各資源についてどの計測が上限判定を担当するかを固定する。これによりプロセス局所値だけを使った見かけ上の省メモリを避ける。

固定実験ではホスト11 GiBの強制上限と物理24 GiB級GPUを組み合わせ、意味的要求量がこの同時常駐範囲を超えることを確認する。バッファ経路は正しい出力を得てもホスト上限へ達し多数の上限イベントを記録したため、正しさと資源契約合格を別判定する。

第三の機構はLRU64型のストレージ再利用実行である。必要な専門家重みをストレージから読み込み、限られた常駐枠へ保持し、再利用可能なものは残しながら容量圧力に応じて追い出す。全重みを同時常駐させず、ルータの需要に従って必要な対象を供給する。

再利用が誤って別の重みや古い転送を参照すると生成結果が変わるため、単なるトークン一致だけでなく完全なロジット行、ルーティングイベント、応答バイト、消費側・転送先識別子まで照合する。64トークンの検証範囲外や再帰状態など、検証していない内部状態は一致主張から除外する。

第四の機構は非同期一窓転送である。ブロッキングで一つずつ読み込む基準に対し、キュー深さ、転送と計算の重なり、バッファ寿命を管理した非同期構成を作る。物理ソースバイトを同一に保ちながら、待ち時間を重ねて実行時間を短縮する。

六つの反転順序ペアで、完全な非同期構成はブロッキング直接経路の32.3%の壁時計時間となった。ただしこの比較はキュー深さ、重なり、寿命管理を同時に変更しているため、単一要因の高速化倍率ではない。資源上限イベントが発生した場合は高速でも契約不合格とする。

一要求ではルータ選択を記録し、必要な重みを常駐集合から検索する。無ければストレージ転送を発行し、非同期窓内で計算と重ねる。使用後は再利用履歴に従って保持または追い出し、生成したトークンとロジット、ルーティング、転送識別子をオラクル記録と照合する。

## 評価

主実験は一つのQwen3-Next同一構成、32Kプリフィル、64出力という固定条件で行う。意味的要求量、ホスト上限イベント、GPU監査、物理転送バイト、トークン、完全ロジット行、3,408件のルーティングイベントを確認する。別途、後期Qwen3-NextとGemma 4バイナリで14個の制御・故障セルも試験する。

標準ルータは管理対象48×512個をすべて選び、重複なしの意味的要求量は43.59375 GiBとなった。これは34 GiBの全常駐枠と、11 GiBホスト強制枠を含む宣言環境を超える。LRU64経路は64個のトークン識別子、各151,936要素の64完全ロジット行、3,408ルートイベントなどをゼロキャッシュオラクルと一致させた。

一方、バッファ経路は出力一致しても11 GiB上限へ達し33,481件のメモリ上限イベントを記録した。完全非同期構成は同じ物理ソースバイトでブロッキング直接経路の32.3%の時間だった。したがって論文の強みは「速い」だけでなく、正しさ、容量、入出力を別々に反証可能にした点にある。

## 既存研究との差

従来の重みオフロード研究は速度、メモリ量、キャッシュ命中率を主指標にすることが多い。本研究は、容量超過を主張するために意味的要求量そのものを証明し、ページキャッシュを含む資源課金、物理入出力、出力完全一致を同じ証明書へ束ねる。新しい置換アルゴリズムだけでなく評価契約を主要貢献とする。

## 限界・実装状況

主要な完全一致主張は一つの固定モデル、ワークロード、ランタイム、デバイス、64出力範囲に限定される。再帰状態や上流ランタイム全体の一致は対象外である。32.3%という時間比も複数の実装差を同時に含み、一般的な非同期化単独の高速化倍率として外挿できない。
