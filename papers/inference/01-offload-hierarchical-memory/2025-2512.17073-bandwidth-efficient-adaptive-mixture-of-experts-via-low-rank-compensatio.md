# Bandwidth-Efficient Adaptive Mixture-of-Experts via Low-Rank Compensation

## 概要
本論文は、CPUや近傍メモリ処理（Near-Data Processing; NDP）側へexpertをoffloadするMixture-of-Experts（MoE）推論で、PCIe等のexpert転送が全体を支配する問題に対し、「ほとんどのexpertはINT2/INT3のまま転送し、routerがそのtokenに特に重要だと判断した少数expertだけ低ランク補償を追加転送して高精度化する」方式を提案する。Mixtral-OffloadingのH100 PCIe計測ではexpert loadが推論時間の89.1%、expert計算は1.8%に過ぎず、演算削減より転送byte削減が重要である。

単純に全expertを同じ低bitへ落とすと、router scoreが大きい支配的expertの量子化誤差まで同じように扱うため品質が急落する。一方で全expertの高精度weightや補償行列を送ればbandwidth削減を失う。提案法は二種類の不均一性を利用する。offlineではweight kurtosisが大きいexpertほど量子化残差が大きい傾向から、低ランク補償（low-rank compensation）のrank budgetをexpertごとに変える。onlineでは現在tokenのrouter scoreを使いTop-(n) expertだけ補償する。

Mixtral-8×7B/8×22BとDeepSeek-MoE-16BをINT2/INT3化し、GPU-only offloadとGPU–NDP hybridの双方で評価する。Mixtral-8×7Bの入力256・出力512ではMixtral-Offloadingが2.37 token/sなのに対し、INT3+補償で12.27、INT2+補償で18.11 token/sとなり5.17〜7.64倍。GPU–NDPでも4.75〜6.69倍の改善を示す。品質面ではMixtral-8×7BのINT2平均accuracyをHQQ比8.24ポイント、MMLUを10.50ポイント改善する。

## 問題設定
MoEは各tokenでTop-(k) expertだけを活性化するためFLOPsは抑えられるが、全expert parameterは巨大である。Mixtral-8×7Bはloading時96.8 GB、peak inference memory 112.6 GBで、80 GB A100一枚を超える。そこでinactive expertをCPU memoryへ置き、routerが選んだexpertを必要時にGPUへfetchするoffloadが使われる。

しかしtokenごとに選ばれるexpertが変わるためcache hitやprefetchが不規則で、H100 PCIe + AMD EPYC 9334のprofileではhost-to-device data movementがほぼ支配的になる。expertをINT2/INT3へ量子化すれば転送量は大きく減るが、MoEのrouter scoreは均等ではなく、MixtralではTop-1 expertが出力へ大きく寄与する。支配expertまで低精度のままにすると品質低下が大きい。

さらにexpert間でも量子化しやすさは異なる。重み (W_i) と量子化後の復号重み (Q^{-1}(Q(W_i))) の残差
[
E_i=W_i-Q^{-1}(Q(W_i))
]
のFrobenius normはweight kurtosisと正相関する。全expertへ同じrankの補償を割り当てると、低kurtosis expertには過剰、高kurtosis expertには不足する。したがってbandwidth budgetを「expertごとの量子化難度」と「tokenごとのrouter重要度」の二軸で配る必要がある。

## 手法

### 1. 量子化残差の低ランク化
各expertの三つの投影行列などをHQQ型の低bit量子化でINT2/INT3へ変換する。その後、残差 (E_i) にtruncated SVDを一度だけofflineで適用し、
[
E_iapprox U_iV_i
]
となる低ランクfactorを作る。特異値は左右factorへ平方根で分配し、補償factor自体もINT3で保存する。

推論時に補償対象となったexpertは、低bit expertを復号した行列に (U_iV_i) を加えることで元weightの主要な量子化誤差方向を復元する。元FP16 expert全体を再転送する必要はなく、rankが小さければfactor転送量はweight本体よりはるかに小さい。

### 2. kurtosis-guided rank allocation
全expertへ同一rankを使わず、各weight matrixのkurtosis
[
kappa_i=rac{1}{d}sum_j rac{(w_{i,j}-mu_i)^4}{sigma_i^4}
]
をofflineで計算する。候補rankは ({0,16,32,128,256,512,1024}) のbucketに離散化し、kurtosisの高いexpertから大きいrankを割り当てる。ただし全expert平均rank (R_{avg}) のglobal budgetを超えない。

これにより外れ値が強く低bit化で残差が大きいexpertへ補償parameterを集中する。WikiText-2の構成要素除去実験（ablation）では同じrank budgetでもkurtosis-guidedがuniform assignmentを一貫して上回り、rank 16でPPL 7.55→7.05、rank 128で8.54→3.77まで改善する。

### 3. router-guided online compensation
offlineで全expert用の低bit weightと低ランクfactorを準備しても、推論時には全factorをGPUへ送らない。各tokenのrouter scoreを降順に並べ、Top-(n) expertだけ補償factorを転送する。残りactive expertはINT2/INT3のまま実行する。

Mixtralではrouter分布が強くskewするためTop-1だけで大部分の品質を回復する。DeepSeek-MoE-16Bは64 expertからshared 2 + routed 6を使いrouter分布がより均一なのでTop-3程度まで補償する必要がある。この違いを固定「Top-1」規則ではなく、architectureとbudgetに応じる (n) として扱う。

### 4. GPU-onlyとGPU–NDPへの統合
GPU-onlyでは低bit expert本体と選択Top-(n)の補償factorをhost memoryからH100へ転送し、GPU上で復号・補償・expert計算を行う。既存offload systemに対して転送byteを減らす。

GPU–NDP構成では、非選択expertはNDP側で低bitのまま計算し、Top-(n) expertのcompensatorだけをGPU側へ運ぶ。NDPは512 GB/s bandwidth・512 GB capacityを仮定し、MoNDEを基礎とする。高精度化に必要なdataだけをGPUへ寄せるため、GPU–memory境界のtrafficをさらに抑える。

## 評価

### 条件
モデルはMixtral-8×7B（8 expert, Top-2, 45.1B expert parameters）、Mixtral-8×22B（8 expert, Top-2, 135.5B）、DeepSeek-MoE-16B（64 routed expert、shared 2 + routed Top-6）。品質はMathQA、HellaSwag、ARC-easy/challenge、BoolQ、WinoGrande、PIQAのzero-shot平均、MMLU 5-shot、WikiText-2 PPLで測る。

GPU-only環境はNVIDIA H100 80GB HBM3 + DDRで、expertをPCIe経由でon-demand loadする。system比較はMixtral-Offloadingとmixed-precision offloaderのHobbit、GPU–NDPではMoNDEを使う。system testはinput 256、複数output lengthを評価する。

### 品質
HQQのみのuniform low-bitと比べ、router上位expertだけを補償することで特にINT2の品質が大きく戻る。Mixtral-8×7BではINT3平均accuracyを+0.45ポイント、INT2を+8.24ポイント、MMLUはそれぞれ+1.11/+10.50ポイント。Mixtral-8×22BでもINT2平均+8.70ポイントである。

DeepSeek-MoE-16Bでは改善がINT3平均+1.63、INT2+2.30ポイントと小さい。router scoreがMixtralほどTop expertへ集中せず、Top-3を補償しても他active expertの誤差が残るためである。これは本手法の利得がrouter skewへ依存する負の条件を示す。

### GPU-only throughput
input/output 256/512でMixtral-OffloadingはMixtral-8×7B 2.37 token/s、8×22B 0.79 token/s。提案法は8×7BでINT3 12.27、INT2 18.11 token/sとなり5.17倍/7.64倍。8×22Bでも約5.18倍/7.63倍である。

Hobbitに対しても8×7Bで6.75 token/sから25.43/36.97 token/sへ上がり3.77〜5.48倍。DeepSeek-MoE-16Bはactivated expert数が多いためtransfer頻度が増え、Mixtral-Offloading比4.38〜5.93倍、Hobbit比2.95〜3.78倍と相対利得が小さい。

### GPU–NDP throughput
MoNDE上のMixtral-8×7Bは11.56 token/sからINT3 54.96、INT2 77.33 token/sへ増え4.75〜6.69倍。Mixtral-8×22BもINT2で3.56→25.75 token/s、DeepSeek-MoE-16Bは61.75→194.51/233.24 token/sで3.15〜3.78倍となる。論文全体では両systemで3〜8倍のend-to-end accelerationを報告する。

### 補償数・rankのablation
Mixtral-8×7BではTop-1補償だけでMMLU 47.53、WikiText PPL 6.32、Top-2まで増やして48.79/6.21と追加利得は小さい。逆に「Top-2だけ」を補償するとMMLU 25.26、PPL 16.76となり、補償数よりrouter順位が重要である。

DeepSeekではTop-1→Top-3でMMLU 25.80→28.75、PPL 17.81→10.99と改善し、3を越えると飽和する。rank budgetは16→128でqualityを改善するが、compensator overheadも0.75%→6.03%へ増えるため、rankを無制限に増やせない。

## 既存研究との差
static uniform quantizationは全active expertへ同じbit幅を適用するため、tokenごとのrouter重要度を使わない。mixed-precision offloadは高精度expertをcache/predictするが、cache miss時にFP16 weight全体を転送する。本手法はexpert本体を常に低bitのまま維持し、必要時だけ小さい低rank residualを足す。

また通常のquantize-then-compensateは全行列に同じrankを置くことが多いが、MoEではexpertごとのkurtosisからrankを不均一に配る。したがってbandwidth-accuracy budgetをofflineの量子化難度とonlineのrouter重要度の両方で制御する。

## 限界
利得はrouter分布がskewして「少数expertだけ高精度に戻せば十分」な場合に大きい。DeepSeek-MoE-16Bのようにactive expertが多くscoreが均一なarchitectureでは補償対象数とtransfer量が増え、speedup・accuracy recoveryの双方が小さくなる。

SVD factorはofflineでmodelごとに生成・保存する必要があり、rankを上げるほどstorageとbandwidth overheadが増える。kurtosisは量子化難度のproxyであり、task/inputごとの実際の誤差を直接最適化しているわけではない。

GPU–NDP評価はMoNDE/Ramulatorを基礎とするsystem構成を含み、すべてが市販hardware上のend-to-end実測ではない。さらに評価はMixtral/DeepSeek系に限られ、expert parallelismやmulti-GPU all-to-allとoffloadが同時に競合する大規模clusterは未評価である。
