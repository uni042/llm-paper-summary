# Bandwidth-Efficient Adaptive Mixture-of-Experts via Low-Rank Compensation

## 概要
本論文は、CPUや近傍メモリ処理（Near-Data Processing; NDP）側へエキスパートをオフロードする混合エキスパート（MoE）推論で、PCIe等のエキスパート転送が全体を支配する問題に対し、「ほとんどのエキスパートはINT2/INT3のまま転送し、ルータがそのトークンに特に重要だと判断した少数エキスパートだけ低ランク補償を追加転送して高精度化する」方式を提案する。Mixtral-オフロードのH100 PCIe計測ではエキスパート 読み込みが推論時間の89.1%、エキスパート計算は1.8%に過ぎず、演算削減より転送byte削減が重要である。

単純に全エキスパートを同じ低ビットへ落とすと、ルータ スコアが大きい支配的エキスパートの量子化誤差まで同じように扱うため品質が急落する。一方で全エキスパートの高精度重みや補償行列を送れば帯域削減を失う。提案法は二種類の不均一性を利用する。オフラインでは重み 尖度が大きいエキスパートほど量子化残差が大きい傾向から、低ランク補償（低ランク補償）のランク 予算をエキスパートごとに変える。onlineでは現在トークンのルータ スコアを使いTop-(n) エキスパートだけ補償する。

Mixtral-8×7B/8×22BとDeepSeek-MoE-16BをINT2/INT3化し、GPUのみ オフロードとGPU–NDP hybridの双方で評価する。Mixtral-8×7Bの入力256・出力512ではMixtral-オフロードが2.37 トークン/sなのに対し、INT3+補償で12.27、INT2+補償で18.11 トークン/sとなり5.17〜7.64倍。GPU–NDPでも4.75〜6.69倍の改善を示す。品質面ではMixtral-8×7BのINT2平均精度をHQQ比8.24ポイント、MMLUを10.50ポイント改善する。

## 問題設定
MoEは各トークンでTop-(k) エキスパートだけを活性化するためFLOPsは抑えられるが、全エキスパート parameterは巨大である。Mixtral-8×7Bはloading時96.8 GB、peak 推論 メモリ 112.6 GBで、80 GB A100一枚を超える。そこでinactive エキスパートをCPU メモリへ置き、ルータが選んだエキスパートを必要時にGPUへfetchするオフロードが使われる。

しかしトークンごとに選ばれるエキスパートが変わるためキャッシュ hitやprefetchが不規則で、H100 PCIe + AMD EPYC 9334のprofileではhost-to-device data movementがほぼ支配的になる。エキスパートをINT2/INT3へ量子化すれば転送量は大きく減るが、MoEのルータ スコアは均等ではなく、MixtralではTop-1 エキスパートが出力へ大きく寄与する。支配エキスパートまで低精度のままにすると品質低下が大きい。

さらにエキスパート間でも量子化しやすさは異なる。重み (W_i) と量子化後の復号重み (Q^{-1}(Q(W_i))) の残差
[
E_i=W_i-Q^{-1}(Q(W_i))
]
のFrobenius normは重み 尖度と正相関する。全エキスパートへ同じランクの補償を割り当てると、低尖度 エキスパートには過剰、高尖度 エキスパートには不足する。したがって帯域 予算を「エキスパートごとの量子化難度」と「トークンごとのルータ重要度」の二軸で配る必要がある。

## 手法

### 1. 量子化残差の低ランク化
各エキスパートの三つの投影行列などをHQQ型の低ビット量子化でINT2/INT3へ変換する。その後、残差 (E_i) にtruncated SVDを一度だけオフラインで適用し、
[
E_iapprox U_iV_i
]
となる低ランク係数を作る。特異値は左右係数へ平方根で分配し、補償係数自体もINT3で保存する。

推論時に補償対象となったエキスパートは、低ビット エキスパートを復号した行列に (U_iV_i) を加えることで元重みの主要な量子化誤差方向を復元する。元FP16 エキスパート全体を再転送する必要はなく、ランクが小さければ係数転送量は重み本体よりはるかに小さい。

### 2. kurtosis-guided rank allocation
全エキスパートへ同一ランクを使わず、各重み 行列の尖度
[
kappa_i=rac{1}{d}sum_j rac{(w_{i,j}-mu_i)^4}{sigma_i^4}
]
をオフラインで計算する。候補ランクは ({0,16,32,128,256,512,1024}) のbucketに離散化し、尖度の高いエキスパートから大きいランクを割り当てる。ただし全エキスパート平均ランク (R_{avg}) のglobal 予算を超えない。

これにより外れ値が強く低ビット化で残差が大きいエキスパートへ補償parameterを集中する。WikiText-2の構成要素除去実験（ablation）では同じランク 予算でも尖度-guidedがuniform assignmentを一貫して上回り、ランク 16でPPL 7.55→7.05、ランク 128で8.54→3.77まで改善する。

### 3. router-guided online compensation
オフラインで全エキスパート用の低ビット 重みと低ランク係数を準備しても、推論時には全係数をGPUへ送らない。各トークンのルータ スコアを降順に並べ、Top-(n) エキスパートだけ補償係数を転送する。残り活性 エキスパートはINT2/INT3のまま実行する。

Mixtralではルータ分布が強くskewするためTop-1だけで大部分の品質を回復する。DeepSeek-MoE-16Bは64 エキスパートからshared 2 + routed 6を使いルータ分布がより均一なのでTop-3程度まで補償する必要がある。この違いを固定「Top-1」規則ではなく、architectureと予算に応じる (n) として扱う。

### 4. GPU-onlyとGPU–NDPへの統合
GPUのみでは低ビット エキスパート本体と選択Top-(n)の補償係数をhost メモリからH100へ転送し、GPU上で復号・補償・エキスパート計算を行う。既存オフロード システムに対して転送byteを減らす。

GPU–NDP構成では、非選択エキスパートはNDP側で低ビットのまま計算し、Top-(n) エキスパートのcompensatorだけをGPU側へ運ぶ。NDPは512 GB/s 帯域・512 GB capacityを仮定し、MoNDEを基礎とする。高精度化に必要なdataだけをGPUへ寄せるため、GPU–メモリ境界のtrafficをさらに抑える。

## 評価

### 条件
モデルはMixtral-8×7B（8 エキスパート, Top-2, 45.1B エキスパート parameters）、Mixtral-8×22B（8 エキスパート, Top-2, 135.5B）、DeepSeek-MoE-16B（64 routed エキスパート、shared 2 + routed Top-6）。品質はMathQA、HellaSwag、ARC-easy/challenge、BoolQ、WinoGrande、PIQAのzero-shot平均、MMLU 5-shot、WikiText-2 PPLで測る。

GPUのみ環境はNVIDIA H100 80GB HBM3 + DDRで、エキスパートをPCIe経由でon-demand 読み込みする。システム比較はMixtral-オフロードとmixed-precision offloaderのHobbit、GPU–NDPではMoNDEを使う。システム testは入力 256、複数output lengthを評価する。

### 品質
HQQのみのuniform low-ビットと比べ、ルータ上位エキスパートだけを補償することで特にINT2の品質が大きく戻る。Mixtral-8×7BではINT3平均精度を+0.45ポイント、INT2を+8.24ポイント、MMLUはそれぞれ+1.11/+10.50ポイント。Mixtral-8×22BでもINT2平均+8.70ポイントである。

DeepSeek-MoE-16Bでは改善がINT3平均+1.63、INT2+2.30ポイントと小さい。ルータ スコアがMixtralほどTop エキスパートへ集中せず、Top-3を補償しても他活性 エキスパートの誤差が残るためである。これは本手法の利得がルータ skewへ依存する負の条件を示す。

### GPU-only throughput
入力/output 256/512でMixtral-オフロードはMixtral-8×7B 2.37 トークン/s、8×22B 0.79 トークン/s。提案法は8×7BでINT3 12.27、INT2 18.11 トークン/sとなり5.17倍/7.64倍。8×22Bでも約5.18倍/7.63倍である。

Hobbitに対しても8×7Bで6.75 トークン/sから25.43/36.97 トークン/sへ上がり3.77〜5.48倍。DeepSeek-MoE-16Bはactivated エキスパート数が多いため転送頻度が増え、Mixtral-オフロード比4.38〜5.93倍、Hobbit比2.95〜3.78倍と相対利得が小さい。

### GPU–NDP throughput
MoNDE上のMixtral-8×7Bは11.56 トークン/sからINT3 54.96、INT2 77.33 トークン/sへ増え4.75〜6.69倍。Mixtral-8×22BもINT2で3.56→25.75 トークン/s、DeepSeek-MoE-16Bは61.75→194.51/233.24 トークン/sで3.15〜3.78倍となる。論文全体では両システムで3〜8倍のend-to-end accelerationを報告する。

### 補償数・rankのablation
Mixtral-8×7BではTop-1補償だけでMMLU 47.53、WikiText PPL 6.32、Top-2まで増やして48.79/6.21と追加利得は小さい。逆に「Top-2だけ」を補償するとMMLU 25.26、PPL 16.76となり、補償数よりルータ順位が重要である。

DeepSeekではTop-1→Top-3でMMLU 25.80→28.75、PPL 17.81→10.99と改善し、3を越えると飽和する。ランク 予算は16→128で品質を改善するが、compensator overheadも0.75%→6.03%へ増えるため、ランクを無制限に増やせない。

## 既存研究との差
static uniform 量子化は全活性 エキスパートへ同じビット幅を適用するため、トークンごとのルータ重要度を使わない。mixed-precision オフロードは高精度エキスパートをキャッシュ/predictするが、キャッシュ miss時にFP16 重み全体を転送する。本手法はエキスパート本体を常に低ビットのまま維持し、必要時だけ小さい低ランク 残差を足す。

また通常のquantize-then-compensateは全行列に同じランクを置くことが多いが、MoEではエキスパートごとの尖度からランクを不均一に配る。したがって帯域-精度 予算をオフラインの量子化難度とonlineのルータ重要度の両方で制御する。

## 限界
利得はルータ分布がskewして「少数エキスパートだけ高精度に戻せば十分」な場合に大きい。DeepSeek-MoE-16Bのように活性 エキスパートが多くスコアが均一なarchitectureでは補償対象数と転送量が増え、speedup・精度 recoveryの双方が小さくなる。

SVD 係数はオフラインでmodelごとに生成・保存する必要があり、ランクを上げるほど保存領域と帯域 overheadが増える。尖度は量子化難度のproxyであり、task/入力ごとの実際の誤差を直接最適化しているわけではない。

GPU–NDP評価はMoNDE/Ramulatorを基礎とするシステム構成を含み、すべてが市販hardware上のend-to-end実測ではない。さらに評価はMixtral/DeepSeek系に限られ、エキスパート parallelismやmulti-GPU all-to-allとオフロードが同時に競合する大規模clusterは未評価である。
