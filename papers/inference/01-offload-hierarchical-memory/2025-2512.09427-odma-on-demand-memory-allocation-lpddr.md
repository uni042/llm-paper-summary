# ODMA: On-Demand Memory Allocation Framework for LLM Serving on LPDDR-Class Accelerators

> LPDDR系アクセラレータで長さ予測と動的連続バケットによりKVキャッシュをオンデマンド確保し、メモリ利用率とRPS/TPSを改善する方式。
## 書誌情報
- **著者**: Guoqiang Zou, Wanyu Wang, Hao Zheng, Longxiang Yin, Yinhe Han
- **公開**: arXiv
- **種別**: Preprint
- **対象**: KVキャッシュ、メモリ割当、LPDDR5、LLMサービング、Cambricon MLU370
- **実装**: Cambricon-vLLM互換の試作系として、Predictor、Task Pool、スケジューラ、Allocator、メモリ Pool、ランタイムとクラスタ管理を統合。
## 概要
ODMAはLPDDR5のように細粒度ランダムアクセス帯域が弱いアクセラレータ向けに、生成長予測、動的バケット分割、大容量バケットの安全策を組み合わせて連続KVキャッシュ領域を必要量だけ確保する。Cambricon MLU370-X4でDeepSeek-R1-Distill-Qwen-7Bを配信し、静的割当比でメモリ利用率を55.05%から72.45%、RPS/TPSを29%/27%改善したと報告する。

ODMAは生成長を軽量に予測して要求へ長さ・不確実性タグを付け、その分布から連続KV領域のバケット境界を動的に再分割する。通常要求は予測に近い最小バケットへ入れ、予測不確実性が高い要求や極端な長文は大容量バケットへ逃がす。通常バケットを超えた場合も細粒度ページを継ぎ足すのではなく、より大きな連続領域へKVを順次コピーしてポインタを切り替えることで、LPDDRが得意な連続アクセスを維持する点がハードウェア固有の新規性である。

代表結果として、生成長予測精度はAlpaca / Google-NQでS3 predictorに対してAlpaca 98.60%→99.55%、Google-NQ 82.68%→93.36%。重い裾を持つGoogle-NQで特に大きく改善し、より小さい通常バケットを安全に使う基盤になる。
## 問題設定
LLMサービングでは要求ごとの生成長が事前に分からないため、KVキャッシュ容量を最大生成長で静的予約すると未使用領域が大量に残る。HBM系GPUではPagedAttentionのように小ブロックへ分割して必要に応じて追加する方式が有効だが、LPDDR5クラスのアクセラレータは連続ストリーミングに比べ細粒度ランダムアクセス帯域が弱く、ページ表を介した散在アクセスや頻繁な小粒度割当が性能上不利になる。このため、最悪長の連続予約とHBM向け細粒度ページングの間に、RACM特性へ適した割当方式が必要になる。さらに生成長分布は重い裾を持ち、運用中に分布も変化するため固定バケットだけでは浪費またはオーバーフローが増える。
## 新規性
ODMAは生成長を軽量に予測して要求へ長さ・不確実性タグを付け、その分布から連続KV領域のバケット境界を動的に再分割する。通常要求は予測に近い最小バケットへ入れ、予測不確実性が高い要求や極端な長文は大容量バケットへ逃がす。通常バケットを超えた場合も細粒度ページを継ぎ足すのではなく、より大きな連続領域へKVを順次コピーしてポインタを切り替えることで、LPDDRが得意な連続アクセスを維持する点がハードウェア固有の新規性である。
## 手法
### 手法のあらまし
要求が到着すると生成長予測器がプロンプト長などの軽量特徴から予測生成長と不確実性を算出する。スケジューラは同じまたは近いバケットタグを持つ要求をまとめ、Allocatorは装置ごとのメモリ Poolに用意された複数サイズの連続空きリストから、予測長を収容できる最小クラスを選んでKVキャッシュ領域をreserveする。通常のデコード中はKVをこの連続領域へ追記するため、PagedAttentionのような多数の小ページへのランダム参照を避ける。実際の完了長はオンライン履歴へ戻し、Bucket Managerが一定周期で長さヒストグラムを更新して境界を再計算する。これにより要求分布が変化しても、各バケットの内部断片化と大きすぎる予約を抑える。不確実性が閾値を超える要求は初めからlarge bucketへ送り、重い裾による予測外れを通常バケットから隔離する。通常要求が割当上限を超えてデコードを続けた場合は、large bucketまたは次の大きな連続ブロックを確保し、既存KVを連続コピーして内部ポインタを新領域へ切り替え、旧領域を元のfree listへ返す。このコピーはLPDDR上でも連続転送として扱えるため、細粒度ランダムページアクセスを常態化させず安全性を確保する。クラスタ管理器は複数MLUのバケット在庫と負荷を見て要求配置を調整し、ランタイムはreserve/release APIを通じてAllocatorを利用する。

### 生成長・不確実性予測器
各要求の生成長を事前推定し、同時に予測の信頼度を表す不確実性を出す。通常の予測値は最小限の連続KVバケットを選ぶために使い、高不確実性要求は安全側の大容量バケットへ直接送る。AlpacaとGoogle-NQで従来予測器より精度を上げ、特にGoogle-NQでは82.68%から93.36%へ改善したと報告する。実完了長を履歴へ戻すことで運用中の分布変化にも追従する。予測が短すぎると後段の移行コピーが発生し、長すぎると静的予約と同様にKV領域を浪費するため、不確実性を別信号として扱って通常バケットの効率と安全性を分離する。予測器の出力は生成内容そのものを変えず、Allocatorへ渡す容量クラス選択情報だけなので、誤差の影響は主にメモリ効率と移行頻度へ現れる。

### 動的バケット分割と連続メモリプール
装置メモリを固定最大長で要求ごとに予約せず、複数サイズの連続KVブロック用free listへ分割する。オンラインの生成長ヒストグラムからバケット境界を周期的に再計算し、現在の要求分布で内部断片化と余剰予約が小さくなるよう容量配分を更新する。要求は予測長を覆う最小バケットへ割り当てられ、デコード中のKVアクセスは連続配置を維持するため、細粒度ランダムアクセスが弱いLPDDR系装置の帯域特性に適合する。分布が変化すると固定境界では特定サイズの空きが不足するため、完了要求の観測長を次回再分割へ反映し、free listの容量構成を更新する。連続領域を優先する代償として細粒度ページングほど任意サイズへ密に詰められないが、LPDDRではランダム参照を減らす帯域上の利益がその内部断片化を上回るという設計判断である。

### 大容量バケット安全策とオーバーフロー移行
重い裾や予測外れを吸収するため大容量バケットを保険領域として確保する。不確実性の高い要求は最初からそこへ送り、通常バケットを使う要求が上限を超えた場合はより大きな連続ブロックを確保して既存KVを順次コピーし、ポインタを切り替えて旧ブロックを返却する。常時ページングするのではなく例外時だけ連続コピーを行うことで、メモリ利用率を高めながらLPDDR上のランダムアクセス罰則を避ける。コピー中は追加領域を一時的に必要とするため大容量バケットの余裕が不足すると待機や割当失敗が起こり得るが、高不確実性要求を事前隔離することで通常経路での発生率を抑える。移行後もKVの論理順序は維持されるため生成結果は変えず、失敗条件を通常時の細粒度アクセス増加ではなく稀な連続コピーへ局所化する。

### 全体のデータ／制御の流れ
Predictor→Task Pool→スケジューラ→Allocator→device-specific メモリ Pool→ランタイムというサービング経路に、オンラインBucket Managerと複数装置を調整するCluster Managerを組み込む。Allocatorはreserve/releaseの薄い境界を提供し、既存推論ランタイムから連続KV領域管理を分離する。
## 評価条件
- **ハードウェア**: 4×Cambricon MLU370-X4アクセラレータを備えるノード。対象メモリはLPDDR5クラスのランダムアクセス制約メモリ。
- **ソフトウェア**: Cambricon-vLLM互換プロトタイプ上でDeepSeek-R1-Distill-Qwen-7Bを配信し、ODMAの予測器、動的バケット管理、Allocator/メモリ Poolを統合する。
AlpacaとGoogle-NQを用いて生成長予測精度を既存S3予測器と比較し、実サービングでは静的な最悪長事前割当を基準として装置メモリ利用率、リクエスト per second（RPS）、トークン per second（TPS）を測る。動的バケットとlarge-bucket safeguardにより、予測誤差・重い裾を吸収しつつ連続KV配置を維持する効果を評価する。
評価はDeepSeek-R1-Distill-Qwen-7BとCambricon MLU370-X4を中心とし、HBM GPUや他のLPDDR系アクセラレータへの一般化、極端な分布ドリフト時の再分割コスト、大容量バケットへの移行コピーが頻発する条件は十分には網羅されない。
## 主要結果
ODMAは生成長予測と動的連続バケットを組み合わせ、Cambricon MLU370-X4で静的事前割当よりメモリ利用率とスループットを改善した。Alpacaではメモリ利用率を55.05%から72.45%へ上げ、RPSを29%、TPSを27%向上する。Google-NQでもメモリ利用率を42.54%から61.79%へ改善し、予測精度は従来方式の82.68%から93.36%へ上がる。

- 生成長予測精度 / Alpaca 98.60%→99.55%、Google-NQ 82.68%→93.36% (比較対象: S3 predictor; 条件: Alpaca / Google-NQ) — 重い裾を持つGoogle-NQで特に大きく改善し、より小さい通常バケットを安全に使う基盤になる。

- 装置メモリ利用率 / Alpaca 55.05%→72.45% (比較対象: Cambricon-vLLM静的事前割当; 条件: DeepSeek-R1-Distill-Qwen-7B、MLU370-X4) — 最大生成長分を全要求へ予約せず予測長に近い連続領域を割り当てることで未使用KV予約を減らす。

- 装置メモリ利用率 / Google-NQ 42.54%→61.79% (比較対象: 静的事前割当; 条件: Google-NQ、MLU370-X4) — 長さ分布が異なるワークロードでも動的バケット再分割が容量利用を改善する。

- RPS / +29% (比較対象: 静的事前割当; 条件: Alpaca、DeepSeek-R1-Distill-Qwen-7B、MLU370-X4) — 空いたメモリでより多くの要求を同時収容できる効果が要求処理率へ反映される。

- TPS / +27% (比較対象: 静的事前割当; 条件: 同上) — 連続アクセスを維持したまま同時実行数を増やし、トークン処理率も向上する。

### 負の結果・境界条件
- 細粒度ページングを避ける代わりに、予測外れで通常バケットを超える要求は大きな連続領域へのKVコピーを必要とする。予測誤差やheavy-tailが極端でlarge bucket移行が頻発する場合、そのコピー費用と保険領域の予約が利得を削る可能性がある。

### 結果の読み方
HBMで成功したページング方式を普遍解とせず、メモリ媒体のランダムアクセス特性に合わせて割当粒度と配置を変えることが主要な示唆である。予測器単独ではなく、分布適応バケットと例外時安全策を組み合わせることで予測誤差を実運用可能な形へ閉じ込めている。
## 品質への影響
生成アルゴリズムやモデル重みを変更せずKVキャッシュ配置を管理するため、生成品質への直接影響は想定しない。
## 既存研究との差
PagedAttentionはHBMの高いランダムアクセス性能を前提にKVを細粒度ブロックへ分散配置して内部断片化を抑えるが、ODMAはLPDDR系でその散在アクセス自体が高価になる点を出発点とする。静的事前割当の連続性は保ちながら、予測長に応じた少数の連続バケットを動的に再分割し、例外時だけ大きな連続領域へコピーする。したがって同じKVメモリ効率化でも、メモリ媒体のアクセス特性に応じてページングと予測型連続割当を使い分ける位置付けである。
## 限界
主評価はCambricon MLU370-X4とDeepSeek-R1-Distill-Qwen-7Bに集中し、他のLPDDRアクセラレータやHBM系GPUとの横断比較は限定的である。生成長予測に依存するため急激な分布変化ではバケット再学習まで余剰予約やオーバーフローが増え得る。large bucketは安全性を高める一方で常時一定容量を保険として保持し、通常バケット超過時はKV全体の連続コピーが必要になる。極端な長文率や高い予測不確実性でこの経路が頻発する場合の最悪時性能は追加検証が必要である。
## 実装状態
Cambricon-vLLM互換プロトタイプとしてPredictor、スケジューラ、Allocator、メモリ Pool、ランタイム、Cluster Managerを統合し、MLU370-X4実機で評価されている。公開コードURLは今回確認できていない。
## 研究上の位置づけ
LLM推論の階層メモリ・KVキャッシュ研究に対し、容量だけでなくランダムアクセス帯域という装置特性が最適なメモリ管理方式を変えることを示す。特に安価なLPDDR系推論アクセラレータを使う場合、HBM中心のソフトウェア設計を移植するより、連続アクセスを維持しつつ予測で予約量を削る方が有利になり得る。将来は予測器の頑健性、バケット再構成コスト、複数モデル・複数装置間のメモリ平衡との統合が重要になる。
