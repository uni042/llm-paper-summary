# DyMoE: Dynamic Expert Orchestration with Mixed-Precision Quantization for Efficient MoE Inference on Edge

## 概要
混合専門家モデル（Mixture-of-Experts; MoE）は1トークンで使う専門家を少数に絞れるが、配備時には専門家プール全体の重みを保持しなければならない。GPUメモリに収まらない場合、使う専門家をCPUからPCIe経由で読み込むため、特に復号では「重み待ち」が逐次生成のクリティカルパスへ入る。静的な量子化は転送量を減らせる一方、全専門家を同じ精度へ落とすと品質を損ねやすい。

DyMoEは、専門家の重要度が偏っており、その感度が層深度でも変わるという観測を使う。重要専門家は高めの精度で保護し、重要度の低い専門家は2ビット化または省略し、必要な専門家を次層の計算前に先読みする。Mixtral-8×7BとQwen3-30B-A3Bを12～24GB相当のメモリ制約で評価し、既存オフロード基盤比で最初のトークンまでの時間（Time-to-First-Token; TTFT）を3.44～22.7倍、出力1トークン当たり時間（Time-Per-Output-Token; TPOT）を最大14.58倍改善した。

## 問題設定
端末MoEでは、モデル重みの総量に対してGPUメモリが小さい。キャッシュにない専門家が選択されるたび、CPUメモリからGPUへ重みを転送する必要がある。プリフィルでは多数トークンのルータ情報が得られるが、復号では1ステップ先の専門家が未確定で、重み転送が逐次待ちになりやすい。

一方、全専門家を一律2ビットにすると、論文の品質表でも4ビットやBF16よりMMLU、CMMLU、GSM8Kが大きく低下する。つまり「転送量を減らすため精度を下げる」と「重要な計算を壊さない」を専門家単位・層単位で分離する必要がある。

## 手法
### プリフィル時のトークン誘導重要度
プリフィルでは入力列全体に対するルーティングを観測できるため、専門家がどれだけ使われるかをトークン側の情報から推定する。DyMoEはこの偏りを使って重要専門家を優先し、低重要度側だけを強く圧縮する。出力は、各専門家を高精度キャッシュへ置くか、低精度表現として扱うかの優先順位であり、全専門家を同じビット幅にする静的量子化とは異なる。

### 復号時のゲート誘導重要度
復号では未来トークンを先に観測できないため、ルータのゲート情報を使って現在の専門家重要度を更新する。重要度の高い専門家は4ビット側へ残し、重要度の低いものは2ビット、さらに攻める4/0構成では非重要専門家を省略する。これにより品質へ効く経路へ精度を集中させつつ、CPU–GPU間で運ぶ重み量を削る。

### 深度適応精度スケジューリング
同じ量子化誤差でも層によって品質影響が異なるため、DyMoEは層深度に応じて圧縮の強さを変える。入力は層位置と専門家重要度、出力は層ごとの混合精度配置である。重要層へ高精度を残すことで、一律低ビット化より品質を保ちやすくする。

### 混合精度キャッシュと先読み
実行系は高精度・低精度の専門家表現をGPUキャッシュで管理し、次に必要になりそうな重要専門家を先読みする。先読みは層間の専門家利用の類似性を利用し、現在の非MoE計算や注意計算中に次の重み転送を重ねる。量子化で転送bytes自体を減らし、先読みで残る転送時間を計算と重畳するため、二つの機構が同じPCIe待ちを異なる方向から削る。

## 評価条件
|項目|内容|
|---|---|
|CPU / GPU|AMD EPYC 7542、NVIDIA RTX 3090 24GB|
|接続|PCIe Gen3 ×16|
|メモリ制約|ソフトウェア割当器で12～24GB相当へ制限|
|モデル|Mixtral-8×7B、Qwen3-30B-A3B|
|比較|Accelerate、Mixtral-Offloading、MoE-Infinity、Fiddler|
|主設定|専門家保持率0.75、4/2および4/0混合精度|
|指標|TTFT、TPOT、MMLU、CMMLU、GSM8K|

## 主要結果
Mixtral-8×7Bの24GB設定では、4/0構成のTTFTがFiddler比22.7倍改善し、16GBでも15.7倍となる。Accelerate比では7.2～8.3倍、Mixtral-Offloading比では4.2～14.58倍である。Qwen3-30B-A3Bの12GB設定でもAccelerate比3.44倍のTTFT改善を示す。重要度に応じた低精度化で転送量を減らし、キャッシュ命中率を上げることがプリフィル側の主因とされる。

復号ではMixtral-8×7B・16GBでFiddler比14.58倍、Accelerate比8.31倍、Mixtral-Offloading比最大2.27倍のTPOT改善となる。Qwen3-30B-A3B・12GBでは2.86倍である。ここでは先読みした専門家転送を注意などの非MoE計算へ重ねることで、直列の重み待ちを隠す効果が大きい。

品質面では一律2ビット化が大きく劣化する一方、一律4ビットはBF16へ近い。例えばQwen3-30B-A3BのMMLUはInt2 0.4950、Int4 0.7705、BF16 0.7800である。DyMoEはこの感度差を専門家・層単位の混合精度へ利用する。

## 既存研究との差
MoE-Infinityのような専門家キャッシュ・先読み方式に対し、DyMoEは「どの専門家をどの精度で運ぶか」を実行時に変え、I/O量そのものも削る。FiddlerのCPU–GPU協調実行とも異なり、重要度に応じた混合精度と層間先読みを同じキャッシュ管理へ組み込む。

## 限界
評価はRTX 3090とPCIe Gen3環境をソフトウェアで12～24GBへ制限したもので、物理的に異なる端末SoCのメモリ階層をそのまま再現するわけではない。4/0構成は非重要専門家を省くため、入力分布が変わって重要度推定が外れる場合には品質リスクがある。また先読みの利得は層間の専門家利用相関と、転送を隠せる計算時間に依存する。
