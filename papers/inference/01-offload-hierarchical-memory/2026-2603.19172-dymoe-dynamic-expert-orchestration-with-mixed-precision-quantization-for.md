# DyMoE: Dynamic Expert Orchestration with Mixed-Precision Quantization for Efficient MoE Inference on Edge

## 概要

DyMoEは、混合専門家モデル（Mixture-of-Experts、MoE）をGPUメモリが12〜24GB程度に制約された端末で動かすため、**専門家ごと・層ごと・入力ごとに必要な重み精度を変える**推論システムである。MoEは各トークンで少数の専門家しか使わないため演算回数は抑えられるが、全専門家の重みは巨大で、GPUに収まらない部分をCPUメモリからPCIe経由で読み込む必要がある。復号では重み転送待ちが1トークンずつの逐次生成を止める。単純な全専門家一律2ビット量子化は転送量を減らせても正答率を大きく損なう。

著者らは重要トークンが少数の専門家に集中すること、浅い層ほど量子化誤差に敏感なこと、隣接層の隠れ状態が似ていることを観測した。これに基づき、プリフィルでは重要トークンの処理数、復号ではルータのゲート得点で専門家重要度を測り、浅い層ほど高精度の専門家を多く残す。重要度の低い専門家は2ビットへ落とすか、0ビット相当として計算を省略する。次層のルータを現在層の隠れ状態から予測して重みを先読みし、混合精度のGPUキャッシュと連携させる。

RTX 3090 24GB上でソフトウェアにより12〜24GBのGPUメモリ制限を課した実験では、Mixtral-8×7BとQwen3-30B-A3Bに対し、既存オフロード方式比で最初のトークンまでの時間（TTFT）を最大22.7倍、出力1トークン当たり時間（TPOT）を最大14.58倍短縮した。12GB条件のQwen3-30B-A3BではAccelerate比TTFT 3.44倍、TPOT 2.86倍である。ただしこれらの倍率はモデル・メモリ条件・比較相手が異なり、同一条件で22.7倍と14.58倍を同時達成したという意味ではない。

## 問題設定：疎な計算と巨大な重みの不一致

Mixtral-8×7BはBF16重みが約86〜87GBで、トークン当たり実際に使うパラメータは約27%と説明される。Qwen3-30B-A3BはBF16重み約60GBに対し、活性化するパラメータは約10%である。GPUが12〜24GBしかない場合、すべての専門家を高精度で常駐させられない。専門家の選択は入力ごとに変わるため、必要になった専門家をホスト側から転送すると、PCIe帯域と転送遅延が演算より支配的になる。特にバッチ1の対話型推論では、別要求との重畳で待ちを隠すことが難しい。

静的な4ビット量子化でもQwen3-30B-A3Bの重みは11GB程度に加えて共有パラメータや作業領域が必要になり、12GB制限で十分な余裕があるとは限らない。一律2ビットでは、例えばQwen3-30B-A3BのMMLUがBF16の0.7800から0.4950へ落ちる。これは転送量削減だけを最適化すると生成品質が壊れることを示す。逆に重要な専門家だけを高精度で保持すれば、品質へ効く重みの精度を保ちつつ、他の重みをより強く圧縮できる可能性がある。

本論文は、重要度を事前に固定する方式も不十分だとする。入力ごとに重要トークンの位置やルーティング先が変わり、層ごとの量子化感度も均一ではない。そこで専門家の重要度推定、深度別の保持割合、転送の先読み、GPUキャッシュの格納精度を一つの実行系で連動させる。

## 手法：入力重要度、深度別精度、先読み、混合精度キャッシュ

### 1. プリフィル：重要トークンが多く通る専門家を保護

プリフィルでは入力系列全体が見えるため、各トークンの注意得点を複数ヘッドにわたって平均し、トークン重要度 `s_i` を計算する。重要度上位k個のトークン集合を `T_imp` とし、専門家 `E_j` に割り当てられたトークンのうち `T_imp` に属する個数を `I_prefill(E_j)` と定義する。これがプリフィル時の専門家重要度となる。単に専門家が呼ばれた総回数ではなく、重要と判断したトークンの処理数を重視することで、限られた高精度枠を品質への寄与が大きい専門家へ優先配分する。

論文図4では、重要トークンのルーティング先が入力ごとに変化し、少数の専門家へ偏ることを示す。従って全入力で同じ専門家だけを常時高精度にする方式は適切ではない。プリフィル時に得られた重要度の順位は、どの専門家を4ビットで保持し、どれを2ビットまたは省略扱いにするかという後段の精度スケジューラへ渡される。ただし重要トークンの判定は注意得点に依存し、必ずしもすべての課題で真の因果的重要性を表すわけではない。

### 2. 復号：ゲート得点を使って逐次重要度を更新

復号では各時刻に新しいトークンを1個ずつ処理するため、プリフィルのように系列全体の統計を集めてから決定することはできない。そこでルータが各専門家へ与えるゲート重み `g_j` を、そのまま `I_decode(E_j)=g_j` として重要度に使う。ゲート得点が高い専門家は出力への寄与が大きいとみなし、高精度での実行を優先する。ゲート得点の低い専門家は低ビット表現または省略へ割り当てる。

プリフィルと復号で異なる重要度尺度を用いるのは、入力全体が既知か、現在の1トークンしか見えないかという情報条件の違いに対応するためである。どちらも最終的には専門家の優先順位を出力するため、同じ深度別精度スケジューラへ接続できる。ルータのゲート得点を用いる方式は、入力変化への即応性を得る一方、ゲート得点が低い専門家の省略が予期せぬ品質劣化を起こす可能性を残す。

### 3. 深度依存の保持割合

著者らはMixtral-8×7B-Instructで各層の専門家だけを2ビット化し、他の層をBF16のままにする感度実験を行う。図5では浅い層の量子化がC-EvalやCMMLUの精度を大きく下げ、深い層は比較的頑健である。この観測に基づき、層番号 `l`、全層数 `L`、最低保持割合 `λ` から、`r(l)=(1−λ)(cos(πl/(L−1))+1)/2+λ` を計算する。各層で高精度に保つ専門家数は `ceil(r(l) M)`、`M` は専門家数である。

余弦曲線は最初の層でほぼ1から始まり、浅い層ではゆっくり下がり、深い層ほど高精度の枠を減らす。線形に一定速度で減らすより初期特徴抽出の量子化誤差を抑えられる。重要度推定は「同じ層のどの専門家を守るか」を、深度依存の保持割合は「その層で何個守るか」を決めるため、二つの機構は役割が異なる。論文は全層で一定割合を守る方式との比較も行い、深度依存のほうが専門家削減時の品質を維持しやすいと報告する。

### 4. 先読み：現在層の状態から次層のゲートを予測

残差接続の影響で隣接層の隠れ状態が似ているという図6の観測を利用し、現在層の隠れ状態 `h^(l)` を次層のゲート重み `W_g^(l+1)` に入力して `Softmax(h^(l) W_g^(l+1))` を計算し、次層の専門家選択を先読みする。プリフィルでは入力系列の各トークンについて予測上位専門家を求め、専門家ごとの予測活性化回数を集計し、その頻度が高いものを先に転送する。復号では現在のトークンの予測ゲート得点上位を直接先読みする。

この処理により、次層で専門家重みが必要になる前にCPUメモリ側からGPUへ転送を始められる。重み転送を注意計算や現在層の専門家計算と重ねられれば、PCIe待ちをクリティカルパスから隠せる。ただし隣接層の相関が弱い場合やゲート予測が外れた場合は不要な専門家を読み込み、結局必要な重みを後から転送する費用が生じる。先読みは予測の正確さと、転送を重ねるだけの計算時間があることに依存する。

### 5. 混合精度キャッシュの格納規則

GPUメモリ上の専門家キャッシュは、従来の最近使用時刻に基づく追い出し（LRU）を拡張し、同じ専門家の高精度版と低精度版を重複格納しない。高精度が必要なのに低精度版しかない場合はキャッシュ不一致とみなし、ホストから高精度版を読み込み低精度版を追い出す。逆に低精度でよい要求に対して高精度版が存在すれば、それを再利用し追加転送を避ける。限られたGPUメモリを複数精度の重複保存で浪費しない設計である。

量子化には専門家重みを対象としてGPTQを採用し、二つの構成を主に比較する。`4/2` は重要専門家を4ビット、非重要専門家を2ビットで実行する。`4/0` は重要専門家を4ビットで実行し、非重要専門家の計算を省く。0ビットは通常の数値表現として0ビット量子化するのではなく、**その専門家をスキップする**ことを意味する。4/0は転送と演算をさらに削れるが、非重要と判定した専門家が持つ情報を完全に失う危険がある。

### 6. 一要求の実行経路

要求を受けると、プリフィルなら重要トークンの専門家割当数、復号なら現在のゲート得点から重要度を計算する。層の深さに応じて高精度枠を決め、専門家ごとに4/2または4/0の処理経路を割り当てる。GPUキャッシュに要求精度の重みがあればそのまま実行し、なければホスト側から読み込む。同時に次層のゲートを予測し、重要度が高い専門家の重みを先読みする。計算・転送・キャッシュ更新を一つの推論経路で連携させる点が、静的な量子化だけを使う方式との差である。

ここでTTFTは要求を受けてから最初の出力トークンが得られるまで、TPOTは出力トークン一個当たりの平均時間を表す。論文図10の性能値はRTX 3090上でメモリ容量をソフトウェア制限した実測であり、12GBの別GPU機種で同じ倍率を得たという結果ではない。また22.7倍はMixtralの24GB条件とFiddlerの比較、3.44倍はQwen3の12GB条件とAccelerateの比較であり、対象と比較基準が異なる。

品質面では、全専門家一律2ビット量子化はMixtralのMMLUを0.4979、Qwen3のMMLUを0.4950へ落とす。一律4ビットではそれぞれ0.6795、0.7705、BF16では0.6889、0.7800である。Qwen3のCMMLUは2ビット0.4300、4ビット0.8044、BF16 0.8063で、2ビットの品質劣化が特に大きい。したがって一律2ビット化より、重要専門家だけを4ビットで保護する混合精度の意義がある。

DyMoEの表2ではMixtralのMMLUが4/0・保持率0.9で0.6807、4/2・保持率0.9で0.6821となり、一律4ビット0.6795と近い。一方、MixtralのCMMLUは保持率0.75の4/0で0.4822、4/2で0.4947となる。非重要専門家を2ビットで残すと約1.25ポイント回復するため、4/0の省略が常に無害ではないことが分かる。Qwen3のGSM8Kでは4/0・保持率0.9で0.9174、一律4ビット0.8908を上回る例もあるが、単一評価の改善をすべてのタスクへ一般化すべきではない。

図3では専門家を無作為に残す方式、重要トークンで選ぶ方式、全層均一の保持割合、深度依存の保持割合を比較する。C-Evalで保持率0.9の場合、無作為・均一では72.5%、重要トークン＋深度依存では79.2%と報告され、重要度と層感度を組み合わせる効果を示す。保持率を0.6まで下げると同方式でも77.8%へ低下し、品質が全く変わらないわけではない。精度を守るには保持率と4/2・4/0の選択が重要になる。

## 既存研究との差

Accelerateは異種デバイスへの重み配置と量子化を扱うが、入力ごとに専門家の重要度を見て精度とスキップを切り替える仕組みではない。Mixtral-Offloadingは専門家のLRUキャッシュとオフロードを使うが、DyMoEは重み精度を動的に切り替え、同じ専門家を複数精度で重複保存しない。MoE-Infinityは活性化情報に基づく先読みとキャッシュを利用するが、DyMoEは**先読みする重みの精度と専門家の省略自体**も同じ判断へ統合する。FiddlerはCPUとGPUの協調実行でオフロード負荷を減らすが、CPU計算や転送の待ちが支配的になる条件ではDyMoEの低精度転送・先読みが有利になる。

一律4ビットや2ビットの量子化とも異なり、DyMoEはトークン重要度、ルータ得点、層深度を組み合わせて必要な専門家だけを保護する。これにより計算の疎性と重み転送の疎性を近づける。ただし学習不要・事前校正不要という設計上の利点は、モデルごとの品質検証や運用時の閾値調整が不要であることを意味しない。

## 限界・負の結果

第一に、12〜24GB条件はRTX 3090 24GBをソフトウェアで制限して作ったものであり、物理的なRTX 4070系12GB GPUやJetsonのメモリ帯域、CUDA演算性能、ドライバ、CPU接続条件まで再現したものではない。PCIe Gen3 ×16の帯域が結果に強く関係するため、より高速な接続やCPUメモリ条件では倍率が変わる可能性がある。バッチ1での結果を多人数同時サービングへ無条件に外挿できない。

第二に、4/0は非重要と判定された専門家を省くため、誤判定した場合に情報を失う。実際にMixtralのCMMLUでは保持率0.75の4/0が4/2より低い。浅い層を保護する余弦保持率やゲート得点の重要度推定も、すべてのモデル・課題で最適である保証はない。品質が厳しい場合は保持率を高くし、2ビット側を残す必要がある。

第三に、先読みは隣接層の隠れ状態とゲートの相関を利用する。予測が外れれば不要な専門家を先読みしてGPUキャッシュを圧迫し、必要な重みを後から読み込む。量子化で転送量を減らしても、計算と転送を重ねられる時間が短いと待ちを完全には隠せない。専門家重み以外の共有パラメータ、KVキャッシュ、作業領域もGPUメモリを消費するため、単純な専門家サイズだけで配置可能性を判断できない。

第四に、評価モデルはMixtral-8×7BとQwen3-30B-A3Bに限られ、異なる専門家構造やルーティング規則、長文脈、量子化方式の組み合わせに対する一般性は追加検証が必要である。本文で公式コードURLを特定できず、実装が公開されているかは未確認である。従って論文の性能を特定のローカル推論環境で直ちに再現可能とは断定しない。
