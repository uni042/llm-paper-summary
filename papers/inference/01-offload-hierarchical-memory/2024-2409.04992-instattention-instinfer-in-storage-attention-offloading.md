# InstAttention: In-Storage Attention Offloading for Cost-Effective Long-Context LLM Inference

> KV cacheとdecode時attentionをComputational Storage Drive内へ置き、flash内部帯域でattentionを処理することで、SSD↔GPU間の巨大なKV転送を避ける長context向けin-storage inference system。

旧preprint名は **InstInfer**（arXiv:2409.04992）。HPCA 2025採択版では **InstAttention** に改題されているため、同一研究としてこのページへ集約する。

## 概要

InstAttentionは、SSDへKV cacheを置く従来offloadでは、decodeのたびにKVをSSD→host→GPUへ読み戻すI/Oがbottleneckになる問題を、**attention計算そのものをstorage側へ移す**ことで解消する研究である。

対象hardwareは通常のNVMe SSDではなく、SSD controller付近にFPGA等の計算資源を持つ **Computational Storage Drive（CSD）**。GPUはQKV projection、O projection、FFNなどを担当し、CSDは大量のKV cacheをflashへ保存すると同時にdecode時attentionを実行する。

この設計により、PCIeを通るのは主に現在tokenの小さいq/k/vやattention outputとなり、KV cache全体はCSD内部のflash channelで読まれる。通常SSDの外部PCIe帯域ではなく、複数flash chipを束ねた内部帯域を利用する点が中心である。

## 問題設定

long-context・large-batchのoffline inferenceではKV cache容量がmodel weightを超えることがある。論文では13B model、batch=32、4K tokensの例でKV cacheを約100GB、model sizeの約4.2倍と見積もっている。

FlexGen等はSSD容量を利用できるものの、decode attentionではKV cacheを繰り返しGPUへ読み込む必要があり、SSDの外部PCIe bandwidthが支配的になる。

CSDには大容量flashと内部帯域がある一方、計算能力はGPUより数桁低い。そのためInstAttentionはdecode全体をstorageへ移すのではなく、**KVアクセスが多く演算密度の低いattentionだけをCSDへ切り出す**。

## 手法

### 1. Decode attentionだけをCSDへoffloadする

GPUにはmodel weightとactivationを置き、prefillは基本的にGPUで実行する。decodeではQKV projection、O projection、FFNをGPUに残し、KV cacheを読むLogit / Attend部分をCSDへ移す。

CSD側attentionはmodel parameterを必要とせず、主にKV cache bandwidthへ支配されるため、GPUより計算能力の低いstorage-side acceleratorでも比較的適合しやすい。

### 2. GPUとCSDをpeer-to-peerで接続する

従来SSD offloadではhost filesystemとhost memoryを経由する。InstAttentionはGPUとCSD間のPCIe peer-to-peer DMAを使い、hostへの余分なcopyを避ける。

prefillで生成したKVもlayer単位でCSDへ送るため、一時的なKV bufferがGPU VRAMを圧迫しにくい。host CPUはrequest管理・scheduling・data movement coordinationを中心に担当する。

### 3. Flash向けのSparF Attentionで読むKV量を減らす

CSD内部帯域もGPU VRAMより低いため、dense attentionをそのままstorageで処理するとKV accessが残る。そこで論文はSparQをflash access向けに変更した **SparF Attention** を追加する。

まずqの重要なhidden dimensionだけを使って各tokenのattention重要度を近似し、その後重要tokenの完全なK/Vだけを読む。つまり、

1. hidden dimension方向に粗く候補を絞る
2. token方向に重要tokenを絞る
3. 最終attentionに必要なKVだけflashから読む

という二段階でKV trafficを削減する。

### 4. Flash page粒度に合わせた二段階loading

通常のsparse attentionは必要tokenを細かくrandom accessするが、NAND flashはpage単位でしか効率よく読めない。

InstAttentionは複数tokenをflash pageに合うgroupへまとめ、まずpage単位で候補を読み、SSD controller側のfilterで不要なunitをさらに落とす。これによりsparsityを保ちながらflash channelの無駄なreadを抑える。

### 5. KV向けのaddress mappingをFTLへ組み込む

SparFはhidden dimension方向とtoken方向の両方からK cacheを参照する。通常SSDのlogical-to-physical mappingではこのrandom accessが非効率になるため、InstAttentionはKV cache向けのmappingをFTLへ追加する。

storage容量が安いことを利用し、Kを異なるindex方向で参照しやすい形に配置し、書き込み量よりread効率を優先する。これは単なる「SSDにKVファイルを置く」方式とは大きく異なる。

## 評価

### 条件

| 項目 | 条件 |
|---|---|
| GPU | NVIDIA A6000 48GB |
| CPU | Intel Xeon 5320 2.2GHz |
| Host memory | 96GB DDR4 |
| Storage baseline | Samsung 980 Pro 2TB |
| CSD compute | Zynq-7045 FPGAベースのInstCSD |
| 想定flash構成 | 8 channels × 1.4GB/s = 11.2GB/s internal bandwidth |
| Model | OPT-13B（accuracyではLLaMA-2-7Bも使用） |
| Precision | FP16 |
| Sequence | input 1024 + output 1024 |
| Dataset | ShareGPT / WikiText-2 / SQuAD / TriviaQA |
| Baseline | DeepSpeed-MII + ZeRO-Inference、FlexGen、FlexGen + SparQ |

### Throughput

1 CSDのdense InstAttentionはbatch=64でFlexGenを **6.85倍**上回った。dense版だけを見ると、CSD内部帯域11.2GB/sがhost↔GPU PCIeの32GB/sより低いため、DeepSpeedの最良小batch throughputに対しては大差がない。

SparFを1/8 KV比率で使うとdense InstAttentionから最大 **2.08倍**向上し、batch=256でFlexGen比 **最大11.1倍**のthroughputを報告している。

2 CSD構成ではdense InstAttentionがFlexGenの最大throughputを10.5倍上回った。論文の拡張scaling評価では1→20 CSDでdense 8.99倍、SparF 7.29倍のthroughput向上を示している。

### KV accessとaccuracy

latency breakdownでは、FlexGen batch=64でdecode latencyの98.9%を占めるKV access部分に対し、dense InstAttentionはKV access overheadを大幅に削減する。論文は構成によりKV cache access overheadを最大94.0%削減したと報告している。

SparFはlosslessではないが、1/8設定までのaccuracy低下は論文評価では小さく、SparQと近い挙動を示した。したがって **dense InstAttentionはplacement / compute offload、InstAttention + SparFはそれにapproximate KV sparsityを加えた構成**として区別して読む必要がある。

## 既存研究との差

### FlexGenとの違い

FlexGenでは通常SSDは低価格な保存階層であり、KVを計算時にGPU側へ持ってくる。InstAttentionはCSD内部でattentionを実行するため、**KV cacheをPCIeの外へ出さず、storage内部帯域で消費する**。

### FastDecodeとの違い

FastDecodeもKV cacheとattentionをGPU外へ移すが、実行先は複数CPU nodeのDRAMである。InstAttentionはさらに低価格・大容量なflashへKVを置き、storage controller近傍の専用acceleratorでattentionを処理する。

つまり両者は「dataをcomputeへ運ぶのではなくcomputeをKVへ近づける」という発想を共有するが、FastDecodeはCPU memory bandwidth、InstAttentionはflash internal bandwidthを利用する。

### PIM系との違い

論文執筆時点のPIM-based LLM attention研究の多くがsimulation中心だったのに対し、InstAttentionはFPGA-based CSD上のattention engineを実装・評価している。ただし製品化された汎用CSD上でそのまま再現できるという意味ではなく、専用hardware設計を含む研究prototypeである。

## 限界

- 一般的なNVMe SSDだけでは使えず、attention engineとKV-aware controllerを持つCSDが必要。
- 評価modelの中心はOPT-13Bで、現代的なGQA / MQAや非常に大きいmodelでの検証は限定的。
- 最大11.1倍の結果はapproximateなSparF 1/8設定を含み、dense版とは品質条件が異なる。
- SparFはattention approximationを使うためlosslessではない。
- flash random accessに合わせた専用FTL / data layoutが必要で、既存SSD software stackへ簡単に追加できる機構ではない。
- 多数CSDへのscalingはhardware cost・PCIe topology・実装複雑性を伴う。
- preprintではopen-source予定と記載されていたが、2026-09-06時点で著者による完全な公式実装repoは確認できなかった。

## 一般的な実装上の含意

InstAttentionが示すのは、NVMe offloadの性能を外部PCIe bandwidthだけで考える必要はないという点である。storage内部のflash bandwidthが外部interfaceより高い場合、**KV cacheをstorageから読み出すのではなく、memory-bound computeをstorage側へ押し込む**ことで内部帯域を利用できる。

一方、そのためにはattention algorithmをflash page粒度やcontroller architectureへ合わせる必要があり、単純なGPU kernel移植では足りない。SSD / CSD offload研究では、capacity・external I/Oだけでなく、device内部帯域とnear-data computeの有無を分けて評価する必要がある。
