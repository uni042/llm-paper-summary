# Mira

## 概要

混合専門家（Mixture-of-Experts; MoE）モデルはトークンごとに一部専門家だけを計算するためFLOPsは抑えられるが、全専門家の重みを保持する容量は依然として大きい。単一GPUでVRAMに収まらない場合、専門家をCPUメモリへ置き、ルータが選んだ専門家だけPCIe経由でGPUへ移す。しかしルータ出力を待ってから転送すると、その間GPU計算が止まりやすい。

Miraはこの反応型オフロードを予測型へ変える。各MoE層の軽量predictorが2層先で使われる専門家を予測し、GPUのSTAGE領域へ先読みする。頻繁に使う専門家はHOT領域へ長期保持し、トークン単位のルーティング telemetryでHOT/STAGEの配分を更新する。さらに専門家重みを専用形式で圧縮し、PCIe転送byteとscale metadataを減らす。

この三機構を一つのランタイムで連携させ、転送を現在層の計算へ重ねる。メモリ制約GPUで既存方式に対し平均スループット最大5.71倍、最初のトークンまでの時間（Time to First Token; TTFT）最大11.71倍、beam search平均3.84倍を報告する。

## 問題設定

MoEの専門家 ルーティングはトークンごとに変わり、分布も一様ではない。全専門家をGPUへ置けないとき、単純な最少使用頻度（LRU等）キャッシュでは将来必要な専門家がルータ確定まで分からず、キャッシュ missのたびにCPU→GPU転送がcritical pathへ入る。

一方、頻出専門家には時間的・タスク的な局所性がある。Miraはこの局所性を長期保持用キャッシュに使うだけでなく、隠れ 状態、ルータ情報、直近ルーティング履歴から近未来の専門家を予測し、転送開始を前倒しする。

## 手法

### 2層先predictor

各MoE層へ軽量な予測器を付け、現在の隠れ 状態・ルータ logitsと専門家選択履歴から、2層先で選ばれる専門家分布を推定する。1層先では単一トークン デコード時にPCIe転送を隠す時間が短すぎるため、2層先を狙う。

予測された上位専門家はルータが実際に必要と判断する前に非同期転送を開始する。予測が当たれば、対象層へ到達した時点で重みがGPU上にあり、専門家 miss 待ちを回避できる。外れた専門家はSTAGE領域の短期候補なので、頻出専門家を恒久的に追い出しにくい。

### HOT+STAGE二層cache

GPU上の専門家領域をHOTとSTAGEへ分ける。HOTはルーティング telemetryで継続的に使われる専門家を保持し、STAGEはpredictorが近い将来必要と判断した専門家の先行配置窓として使う。

管理器はHOT命中、STAGE命中、CPUから直接供給された回数などトークン単位の統計を使い、候補とvictimを評価してbounded swapする。予測プリフェッチと長期人気度を同じLRU列へ混ぜないため、短期予測の外れで人気専門家がthrashするのを抑える。

### expert圧縮と融合実行

専門家のup/ゲート/down行列でscale metadataを共有するINT8系表現を使い、重み本体だけでなくscale転送とcopy呼出しの費用を削減する。GPU側では逆量子化とFFN計算を融合し、圧縮転送の利得を中間バッファで失わないようにする。

ランタイムはpredictor実行、STAGE プリフェッチ、現在専門家計算、キャッシュ更新を非同期に重ねる。したがって高速化の源泉は量子化単独ではなく、「早く知る」「置き場所を分離する」「少ないbyteで運ぶ」の組合せである。

## 既存研究との差

MoE-Infinity等の専門家 オフロードはルータが専門家を選んだ後のキャッシュ・転送を最適化する。Miraは2層先を予測してルータ確定前に転送を始めるため、PCIe通信を現在の計算へ隠せる時間を作る。

単純なpredictive キャッシュとも異なり、予測専門家用STAGEと頻出専門家用HOTを分離する。これにより短期予測と長期局所性を別々の寿命で管理し、予測外れによるキャッシュ汚染を抑える。さらに圧縮形式をランタイムと共同設計し、プリフェッチするbyte数自体も減らす。

## 限界

predictorはルーティング分布が学習時・直近履歴と大きく変わると精度が下がり、誤プリフェッチはPCIe帯域とSTAGE容量を消費する。予測効果が48GBで1.08倍、16GBで1.49倍という感度は、十分なHOT容量がある条件では追加機構の利得が小さくなることも示す。

単一GPU+CPU オフロードが主対象であり、専門家 並列化を使う複数GPUクラスタのAll-to-All通信最適化を直接解く方式ではない。また専用量子化による品質影響は小さいと報告されるが、全タスクで完全にFP16同等という結果ではない。
