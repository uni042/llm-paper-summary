# DASH-KV: Accelerating Long-Context LLM Inference via Asymmetric KV Cache Hashing

> 注意の全キー内積を学習済み非対称ハッシュ検索へ置換し、重要トークンだけ完全精度へ戻すことで、長文脈の計算量を線形化しつつLongBench品質をFull Attention近傍に維持する。

## 概要
DASH-KVは、長文脈推論で各クエリと全キーを高精度内積する注意機構の二乗計算を、ハミング空間での近似近傍検索へ置き換える手法である。動的なクエリには3層MLP、再利用されるキーには線形射影という非対称ハッシュ器を使い、複数ヘッドの合意と前層の注意分布で検索距離を補正する。さらに重要度に応じて完全精度、ハッシュ＋残差補正、計算除外の3段階へ振り分ける。LongBenchでは3モデルでFull Attentionと同程度の平均品質を保つ一方、学習済み非対称ハッシュはRecall@100 86.06%、1トークン当たり22msを示した。ただし実験は1ビット演算を実装せずFP16で模擬しており、理論上の1ビット圧縮格納による容量・高速化と実測を区別して解釈する必要がある。

論文固有の核は、クエリとキーを同じ写像へ入れる一般的な局所性鋭敏ハッシュではなく、役割の違いを利用した非対称な学習済みハッシュを注意内部へ入れる点にある。毎トークン変化し検索精度に敏感なクエリには表現力のある3層MLPを使い、一度生成後に何度も再利用されるキーには軽い線形射影だけを使う。さらにハッシュ検索の誤りを、ヘッド間投票、前層の注意分布、残差MLP、重要度別の完全精度への昇格で段階的に補う。単なるKV圧縮ではなく、検索・近似スコア・完全精度計算を同一の実行経路で切り替える。

代表結果として、LongBench 6課題平均はQwen2-7B-InstructでFull Attention 38.71、SnapKV 35.84に対して38.73。近似検索へ置き換えても平均品質を密注意と同等に保ち、代表的なKV選択法を約2.89点上回る。
## 問題設定
標準的な自己注意では、デコード時の新しいクエリが過去の全キーと高次元の浮動小数点内積を行う。文脈長が伸びるほど比較対象が増え、注意計算は系列長に対して二乗的に増える。既存のKVキャッシュ最適化は、低ビット量子化で容量を減らす、重要でない履歴を追い出す、ヘッドや層で表現を共有するといった方法が中心だが、量子化は復号・精度低下、追い出しは情報の不可逆損失、共有はモデル内部の異質性を無視しやすい。さらに多くの方式は、残したキーとの類似度を結局高次元の浮動小数点内積で計算するため、注意そのものの計算形式を変えない。DASH-KVはこの比較処理を情報検索の近似近傍検索として捉え直し、キーを短い二値コードへ写して高速なハミング距離で候補を絞ることで、保存量と照合計算の両方を減らそうとする。
## 新規性

## 手法
### 手法のあらまし
入力処理で各層のキーが生成されると、DASH-KVはキーを線形射影して符号化し、短い二値ハッシュコードをKVキャッシュと対応付けて保持する。デコードで新しいクエリが来るたび、3層MLPでクエリ側の二値コードを作る。まず各キーとのハミング距離を計算し、同じトークンを複数の注意ヘッドが重要とみなす度合いと、直前の層でそのトークンへ向いた注意の大きさを使って距離を補正する。これにより単一ヘッドの誤検索や層ごとの揺らぎを弱める。

補正済み距離の分布から2つの百分位しきい値をその場で計算し、キーを三段階に分ける。非常に関連の強いキーと、シンクトークン・近傍トークンなど事前に保護した位置は、元のクエリ・キーを使った完全精度の内積へ戻す。中程度のキーは二値コードの類似度を使いつつ、小さな残差MLPが完全精度スコアとの差を補う。関連が弱いキーはその時点の計算から外すがKV自体は削除しないため、後のクエリで再び候補になれる。

ハッシュ器は元モデルの注意分布を教師として学習する。主損失は学生側のハッシュ注意分布と教師側の完全精度注意分布のKL距離で、各ビットが片側へ偏らないためのビット均衡損失と、連続値を±1へ寄せる量子化損失を0.1ずつ加える。学習中は符号関数の代わりに係数を徐々に強めるtanhを用い、推論時に符号化する。

層ごとの感度解析では初期層と終端層をハッシュ注意へ置換すると品質が大きく崩れ、中間層は比較的頑健だった。このため実運用では両端を完全精度のまま残し、中間層だけDASH-KVへ置換するサンドイッチ配置を採る。著者はこの構成と候補選別により、全キーへの高精度類似度計算を避けて系列長に対する計算量を線形化できると主張する。ただし現試作は二値演算をFP16で模擬するため、理論上のビット演算効率がそのまま実機速度になったわけではない。

### 非対称深層ハッシュ
クエリ側はLayerNormとGELUを含む3層MLPで動的に256次元の隠れ表現を経てlビットのコードへ写し、キー側はd×lの線形射影だけでコードを作る。学習中は符号関数では勾配が流れないため、係数を1から最大10へ徐々に増やすtanhで二値化を近似し、推論時だけ符号関数へ切り替える。クエリは毎トークン生成され検索精度が必要なので表現力へ計算を使い、キーは一度符号化すれば後続トークンで繰り返し使えるため軽い写像で十分という非対称性を利用する。対称ハッシュよりRecall@100が高い結果は、この役割分離が単なるモデル容量増加ではなく検索精度に効いていることを示す。

### 構造情報による検索距離補正
生のハミング距離だけでは、少数ビットへの量子化誤差によって本来重要なキーが候補外へ落ちるため、Transformer内部にもともと存在する二種類の冗長な観測を補助信号にする。まず同じキーを重要と判断した注意ヘッド数を投票として集計し、多数のヘッドが一致したキーほど距離を短くして候補へ戻す。次に前の層で得た注意スコアを正規化し、直前まで継続的に注目されていたキーにも負の距離補正を与える。二つの補正係数は学習可能なので、課題や層に応じてヘッド合意と前層履歴の重みを変えられる。これにより単一ヘッドのハッシュが誤っても、別ヘッドや前層が同じキーを支持していれば検索漏れを修復し、後段の完全精度・残差計算へ重要情報を渡せる。反対に複数の信号がそろわないキーは優先度が上がらないため、全キーを高精度計算へ戻して高速化を失うことを避ける。

### 重要度別の三段階混合精度
補正済み距離を固定しきい値で切ると、文脈長や入力内容によって距離分布が変わった際に候補数が過剰または過少になる。そこでDASH-KVは現在系列の距離分布から二つの百分位しきい値を毎回計算し、キーを重要度で三段階に分ける。最重要キーは元のクエリとキーによる完全精度内積を実行し、中程度のキーは二値ハッシュの粗いスコアへ小さな残差MLPを加えて量子化誤差を補う。低重要度キーはそのデコードステップの計算対象から外す。さらにシンクトークン、特別トークン、直近の近傍は距離に関係なく完全精度へ固定するため、数値安定性と局所依存を守る。計算から外したキーもKVキャッシュから削除はしないので、後続クエリで関連度が上がれば再び候補へ復帰できる。この可逆性により、追い出し型方式のように一度の誤判定が以後の全生成へ残る危険を抑えながら、毎ステップの高価な内積数を削減する。

### 層感度に基づくサンドイッチ配置
全Transformer層を一律に近似注意へ置き換えると、どの層でも同じ冗長性があるという誤った仮定を置くことになる。著者はQwen2-7Bの各層を一つずつDASH-KVへ置換し、6つのLongBench課題で品質変化を測定した。その結果、入力表現を形成する初期0〜4層と出力直前の表現を整える終端27〜32層は近似に敏感で、置換時に品質が大きく崩れた一方、中間5〜27層は比較的頑健だった。そこで実配置では両端を完全精度の注意として残し、中間だけハッシュ検索へ置き換えるサンドイッチ構成を採る。これは全層置換より理論上の削減量を一部失うが、近似誤差が表現形成の入口や出口で増幅されるのを避ける。層感度を事前測定して配置範囲を決めることが、品質をFull Attention近傍に保つための条件である。

### 全体のデータ／制御の流れ
元モデルの重みを全面的に再学習するのではなく、層ごとにクエリ・キー用ハッシュ器、距離補正係数、残差補正器を教師の完全精度注意分布に合わせて学習する。推論ではキー生成時にコードを事前計算して保持し、各デコードステップでクエリコード生成→ハミング検索→ヘッド・層事前情報による補正→百分位分類→完全精度/近似/除外の実行→値ベクトル集約という順に流れる。現状はPyTorch上のFP16テンソルで二値コードを模擬するため、論文が想定するネイティブ1ビット演算と圧縮格納は将来実装であり、計算量解析と物理的なGPU実測を混同しない必要がある。
## 評価条件
- **ハードウェア**: 具体的なGPU型番、CPU、メモリ容量は本文に記載されていない。二値コードの格納・類似度計算はPyTorchのFP16演算で模擬され、ネイティブ1ビット演算器は使っていない。
- **ソフトウェア**: Qwen2-7B-Instruct、Llama-3.1-8B-Instruct、Qwen2.5-14B-Instructを用い、PyTorch最適化カーネル上で試作した。論文は著者コードURLを示すが、2026-09-14のGitHub API確認ではリポジトリを取得できなかった。
- **比較対象**: Full Attention、StreamingLLM、H2O、SnapKV、局所性鋭敏ハッシュによるDASH-KV-Naive、対称ハッシュによるDASH-KV-Sym
学習系列長は3kトークン、LongBench推論は最大32kトークン。NarrativeQA、HotpotQA、Qasper、MultiNews、GovReport、TriviaQAの6課題を3モデルで評価し、Full Attention、StreamingLLM、H2O、SnapKVと比較する。ハッシュ部分では局所性鋭敏ハッシュ、対称学習ハッシュ、提案法をRecall@100、完全精度注意分布とのKL距離、1トークン当たり遅延で比較する。さらに4k〜128kの合成系列で拡張性、層単位置換で感度を調べる。
LongBenchの品質比較は実モデル推論だが、ネイティブ1ビットカーネルや実際の1ビット圧縮KV格納は実装していない。したがって品質・検索再現率は実験結果として扱える一方、1ビット圧縮格納の容量削減やビット演算による将来速度は理論・モデル化を含む。具体的ハードウェアが非開示のため、他GPUへの遅延一般化にも制約がある。
## 主要結果
LongBench平均ではDASH-KVは3モデルすべてでFull Attention近傍に留まり、Qwen2.5-14Bでは42.92と密注意42.26をわずかに上回った。対してStreamingLLM/H2O/SnapKVは多くの長文課題で平均が大きく低下する。検索機構の比較では提案非対称ハッシュがRecall@100 86.06%、KL距離0.4054、1トークン22msで、対称ハッシュ68.28%・1.3200・38ms、素朴なLSH 8.91%・3.2000・28msより精度と遅延の両方で良い。これは学習済みのクエリ・キー別写像と残差補正が検索品質を支えることを示す。一方、ネイティブ1ビット演算は未実装なので、論文の線形計算量と理論的圧縮利得を実GPUの最終高速化倍率として読んではならない。

- LongBench 6課題平均 / 38.73 (比較対象: Full Attention 38.71、SnapKV 35.84; 条件: Qwen2-7B-Instruct) — 近似検索へ置き換えても平均品質を密注意と同等に保ち、代表的なKV選択法を約2.89点上回る。

- LongBench 6課題平均 / 42.43 (比較対象: Full Attention 42.70、SnapKV 34.57; 条件: Llama-3.1-8B-Instruct) — 密注意との差は0.27点に収まり、SnapKVとの差は7.86点あるため、モデルが変わっても検索近似による品質損失は小さい。

- LongBench 6課題平均 / 42.92 (比較対象: Full Attention 42.26、SnapKV 34.76; 条件: Qwen2.5-14B-Instruct) — 平均では密注意を0.66点上回るが、近似法が本質的に密注意より正確という意味ではなく、課題ごとのばらつきや近似の正則化効果を含む評価結果として解釈すべきである。

- Recall@100 / 86.06% (比較対象: 対称ハッシュ68.28%、素朴なLSH 8.91%; 条件: Table 2の検索比較) — クエリとキーを別符号器で学習する非対称設計が、一般的な対称写像や非学習LSHより重要キーを候補集合へ戻しやすい。

- 注意分布KL距離 / 1トークン遅延 / 0.4054 / 22ms (比較対象: 対称ハッシュ1.3200 / 38ms、素朴なLSH 3.2000 / 28ms; 条件: Table 2) — 提案法は検索精度を上げただけでなく、この試作条件では対称版より短い遅延も示す。ただし二値演算はFP16模擬でありネイティブ1ビットカーネルの測定ではない。

- 拡張性 / 4k〜128kでDASH-KVは線形O(N)スケーリングを主張 (比較対象: 標準注意O(N^2); 条件: 合成系列のストレス試験) — 全キーとの高精度内積を避ける設計上、系列長増大時の計算量の増え方を抑えられる。ただし図の速度値と1ビット格納利得は実装制約を踏まえて読む必要がある。

### 負の結果・境界条件
- 初期層0〜4と終端層27〜32をDASH-KVへ置換すると品質が大きく崩れ、全層一律置換は適さない。中間層だけを置換するサンドイッチ配置が必要である。また著者自身が、二値コードをFP16で模擬し低レベルのビット演算を実装していないと明記する。したがって1ビット圧縮格納に基づく容量削減と、ビット演算がもたらす理論上の高速化は完全な実機エンドツーエンド検証ではない。

### 結果の読み方
品質面の優位は、重要キーを永久削除せず毎ステップ再選択できること、重要トークンを完全精度へ戻すこと、ハッシュ誤差を残差・ヘッド合意・前層情報で補うことから説明できる。特にHotpotQAではQwen2-7Bが44.50、Llama-3.1-8Bが58.01とFull Attention 44.04/57.43に近く、長距離検索型課題での候補再現が保たれている。一方、層感度が高い部分では近似誤差が後段へ増幅するため両端層を完全精度に残す必要がある。実装面ではFP16模擬のため、実際のGPU上でビット演算・メモリアクセスがボトルネックになった場合の最終性能は未確定である。
## 品質への影響
近似手法であり理論的に無損失ではない。6課題平均はFull Attentionと同程度だが、個別課題・層配置では差が出る。弱関連キーはそのステップの計算から外されるもののKV自体は保持され、重要キーと保護トークンは完全精度へ戻すため、不可逆追い出しより品質を守りやすい。
## 既存研究との差
KIVI等の量子化はKV表現を低精度化しても注意の候補照合は基本的に数値演算として残る。H2OやStreamingLLMは不要と判断したKVを追い出して計算対象を減らすが、後から必要になった情報を復元できない。SnapKVは観測窓から重要KVを選択する検索型だが、DASH-KVはキーを保持したまま毎クエリで二値近似近傍検索し、完全精度・近似・除外を動的に切り替える。Reformer系のハッシュ注意とも異なり、既存LLMのクエリとキーの分布差を前提に非対称学習器を用い、教師の完全精度注意分布へ蒸留する。
## 限界
最大の制約は、論文が主張する1ビット検索を低レベルGPU演算として実装していない点である。試作は二値コードをFP16で表現してPyTorch演算を使い、ストレージ量と高速化利得の一部は厳密な1ビット圧縮格納モデルから計算する。具体的GPU型番も記載されないため、22msという遅延や128kでのスケーリングを特定ハードウェアの再現可能なエンドツーエンド性能として扱いにくい。さらに初期・終端層は近似に弱く完全精度を残す必要があり、全層を線形化できるわけではない。著者コードURLも確認時点ではGitHubから取得不能だった。

## 研究上の位置づけ
KVキャッシュ圧縮というより、長文脈注意を検索システムへ再定式化する近似注意・推論高速化研究として位置付けるのが適切である。容量削減、候補選別、計算形式の低ビット化を一体化しており、KV量子化・疎注意・近似近傍検索の交点にある。SSD/NVMe階層そのものは扱わないが、下位層に全KVを保持しGPU側にはハッシュ索引と重要KVだけを置く設計へ拡張すれば、低速階層からの再取得候補をハッシュで絞る信号として利用できる。
