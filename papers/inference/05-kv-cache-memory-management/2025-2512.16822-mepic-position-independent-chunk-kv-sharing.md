# MEPIC: Memory Efficient Position Independent Caching for LLM Serving

> 位置非依存KVをページ境界へ正規配置し、最初の1ブロックだけ再計算、RoPEを注意時に融合することで、同一チャンクのHBMページを要求間共有し、既存PICよりHBM重複と再計算を大幅に減らす。
## 書誌情報

- **著者・所属**: Huawei Technologies Canada Co., Ltd. および Huawei Technologies Co., Ltd.
- **公開**: arXiv:2512.16822v1
- **種別**: Preprint
- **対象**: 位置非依存キャッシュ、KVキャッシュ共有、PagedAttention、HBM管理、RoPE融合、RAG、LMCache
- **実装**: vLLMとLMCacheを拡張した実装で、チャンク常駐管理、決定的なページ境界配置、最初のブロックのみの再計算、位置情報を保存しないKV、RoPE融合注意を実装する。論文本文には著者公式コード公開URLを確認できない。
## 概要
MEPICは、同じ文書チャンクを異なる位置で再利用する位置非依存キャッシュ（position-independent キャッシュ; PIC）が、要求ごとの再計算と位置補正のため同一チャンクでもKVブロックを共有できず、HBM重複を残す問題を扱う。vLLMのページ化KVへチャンクをブロック境界で正規配置し、再計算を最初の1ブロックへ固定し、回転位置埋め込み（Rotary Position Embedding; RoPE）をキャッシュ保存時ではなく注意カーネル内部で適用することで、残りのチャンクKVを要求間で同一ページとして共有する。Ascend 910B 64GB上のMistral-7Bで、CacheBlend/EPICと同等の精度を保ちつつ、データセット比較ではピークHBMを最大約2倍削減し、高負荷では5.25〜5.74倍、長文脈では2.97〜5.21倍少ないHBMを使い、遅延も9〜11%改善した。

MEPICの新規性は、同一チャンクの『共有可能な正本KV』をvLLM内部のページ化HBMに直接成立させるため、三つの原因を同時に固定する点にある。第一にチャンクをページ境界へ決定的に整列し、要求ごとの開始位置差を消す。第二に選択的再計算を任意トークンではなく最初の1ブロックだけへ固定し、それ以降を常に清浄な共有ブロックにする。第三にRoPEを保存済みKVから外し、注意カーネルが読み出した直後に要求固有位置を融合適用する。この正規表現をChunk キャッシュ Coordinatorが接頭辞KVと同じブロックプールで管理し、LMCacheのCPU/ディスク層とも連携する。

代表結果として、SQuADピークHBM使用率 / 遅延は300要求、Mistral-7B-Instruct-v0.3でCacheBlend 54.47% / 119.41秒、EPIC 54.13% / 114.73秒に対して27.67% / 116.03秒。HBMはほぼ半減する一方、遅延はEPICより約1.3秒長く、この条件ではメモリ節約が常に最短遅延へ直結するわけではない。
## 問題設定
検索拡張生成やコーディングエージェントでは、同じ文書チャンクが要求ごとに異なる順序・位置で繰り返し現れる。通常の接頭辞キャッシュは先頭が完全一致した場合しか再利用できないため、位置非依存キャッシュ（position-independent キャッシュ; PIC）は任意位置のチャンクKVを再利用する。しかし既存PICは、位置ずれを直すための選択的再計算やRoPE補正を要求ごとに行う。その結果、同じ論理チャンクでも再計算されたトークン位置や絶対位置が異なり、vLLMの固定ページ境界へ入れた物理KVが要求ごとに分岐する。1個でも要求固有トークンが含まれるページは共有不能になるため、計算やCPU/ディスク転送を減らしてもHBMには複製が残る。高並行時にはこの複製がページ枯渇、追い出し、再ステージング、待ち時間増加を招く。MEPICはPICをアルゴリズムだけでなくページ化KVの配置・常駐・位置表現を含むシステム問題として扱う。
## 新規性
MEPICの新規性は、同一チャンクの『共有可能な正本KV』をvLLM内部のページ化HBMに直接成立させるため、三つの原因を同時に固定する点にある。第一にチャンクをページ境界へ決定的に整列し、要求ごとの開始位置差を消す。第二に選択的再計算を任意トークンではなく最初の1ブロックだけへ固定し、それ以降を常に清浄な共有ブロックにする。第三にRoPEを保存済みKVから外し、注意カーネルが読み出した直後に要求固有位置を融合適用する。この正規表現をChunk キャッシュ Coordinatorが接頭辞KVと同じブロックプールで管理し、LMCacheのCPU/ディスク層とも連携する。
## 手法
### 手法のあらまし
要求はまずスケジューラで再利用可能な文書チャンク領域と要求固有のプロンプト領域へ分割される。MEPICはチャンクの先頭へ、プロンプトの末尾へページ単位の埋め草を入れ、再利用可能チャンクが必ずKVブロック境界から始まるようにする。埋め草の方向自体が領域種別を符号化するため、計算側へ追加の複雑なメタデータを渡さずにチャンクかプロンプトかを判別できる。チャンクのトークン列をハッシュして論理識別子を作り、Prefix キャッシュ CoordinatorとChunk キャッシュ Coordinatorを束ねるHybrid KV ManagerがHBM内の既存ブロックとLMCache側の遠隔コピーを照合する。

HBMに空きがあれば非常駐領域へページを割り当てる。不足時は参照数が0のチャンクだけをChunk LRU Managerから追い出し候補にし、接頭辞KVは予測可能な遅延と正しさを守るため追い出さない。必要ページを確保できなければ要求を受理せず、共有プールを無理に破壊しない。新しいチャンクは全体を一度計算するが、すでに正本KVが存在するチャンクは最初の1ブロックだけを要求固有文脈に合わせて再計算し、残りは正本ページをそのまま参照する。最初のブロックは接頭辞キャッシュ側へ置き、残りをチャンクキャッシュ側へ置くため、汚れた境界と共有可能部分が物理ページ単位で明確に分離される。

位置依存性については、通常vLLMのようにRoPEをキーへ適用してからKVキャッシュへ保存せず、位置符号を含まないNoPE形式で保存する。注意カーネルが正本KVをHBMから読み込む際、その要求での実際のトークン位置に対応する回転角をその場で適用する。RoPE処理を注意演算へ融合することで、位置ごとのKVコピーや補正用の追加メモリ往復を作らない。このため同じチャンクの2ブロック目以降は、別要求・別位置・別バッチでも完全に同じHBMページを参照できる。

この方式はPICの再計算アルゴリズムを新しくするより、既存の再利用可能性を実際のHBM共有へ変換することが目的である。チャンクが高頻度に再利用されるほど物理KVコピー数が要求数ではなく論理チャンク数へ近づき、HBM圧力と再計算が同時に下がる。一方、再利用率が低い要求では正規配置や管理の利得が小さく、接頭辞KVとチャンクKVが同じプールを奪い合うため、常駐優先度や追い出し方策が性能境界になる。

### ページ境界へ正規化するチャンク配置
Chunk Processorは要求中の再利用可能チャンクと要求固有プロンプトを分離し、固定KVページサイズに合わせて埋め草を挿入する。チャンクは先頭側、プロンプトは末尾側を埋め、最後のプロンプトだけはそのままにする。これにより同じトークン列のチャンクは前に置かれた質問や別チャンクの長さが違っても同じブロック境界から始まる。ページ化注意では共有単位がブロックなので、トークン内容が同一でも開始オフセットが違えば物理ページ共有はできない。MEPICはこのアドレス配置差をスケジューリング時に除去する。さらに埋め草の形から計算側が領域種別を推測でき、既存vLLMの『トークン列とブロック対応』という実行インターフェースを大きく変えずに共有配置を実現する。

### 接頭辞とチャンクを統合するHBM常駐管理
Hybrid KV ManagerはvLLMのPrefix キャッシュ Coordinatorと新しいChunk キャッシュ Coordinatorを同じページ化KVプール上で協調させる。要求が来ると各領域についてHBM常駐、LMCacheのCPU・ディスク側コピー、未生成のどれかを判定し、非常駐分だけ必要ページ数を見積もる。Chunk LRU Managerはチャンク単位の参照数と最近利用時刻を持ち、空きが足りない場合でも参照中のチャンクは守り、参照数0のチャンクだけを追い出す。接頭辞KVはこの方策では追い出さず、従来の接頭辞再利用の予測可能性を保つ。必要量を追い出しても確保できなければ要求を拒否する。この統合により、外部バッファから毎回HBMへコピーする従来PICと違い、注意カーネルが直接読める正規ページを長く常駐させられる。

### 最初の1ブロックだけに固定した選択的再計算
既存PICでは質問や注意状態に応じて再計算トークンを動的に選ぶため、少数の再計算トークンがチャンク内の多数ページへ散らばる。一つのトークンが変わるだけでもページ全体が要求固有の『汚れた』ブロックになり、論理的には再利用したKVでもHBMでは共有できない。MEPICはこの粒度をブロック単位へ変え、キャッシュ済みチャンクでは最初のKVブロックだけを現在要求の前文脈に合わせて再計算する。境界ブロックはPrefix キャッシュ側へ要求固有として置き、2ブロック目以降はChunk キャッシュの正本ページを参照する。新規チャンクだけは全体を計算して正本を作る。この固定境界により、精度回復に必要な文脈依存計算を残しながら、残り全ページの共有可能性を決定的に保証する。

### 位置情報を保存しないKVとRoPE融合注意
通常のRoPEモデルでは絶対位置に応じた回転をキーへ適用してからKVへ保存するため、同じ文章でもプロンプト中の開始位置が違えば保存テンソルが異なる。MEPICはKV生成時にはRoPEを適用せず、位置情報を含まないNoPE形式を正本としてページ化HBMへ保存する。各要求の注意計算時にカーネルが正本KVをオンチップバッファへ読み出し、その要求での位置オフセットに対応するRoPEを直前に適用して注意スコアを計算する。位置補正と注意を一つの演算経路へ融合するため、補正済みKVを別バッファへ書き戻すメモリ通信を増やさない。これによって保存表現は位置から独立し、一つのチャンクKVを任意位置・複数要求で共有しながら、モデルが期待する位置依存の注意だけを実行時に復元できる。

### 全体のデータ／制御の流れ
MEPICはvLLM+LMCacheを基盤に、スケジューリング経路へChunk Processor、Chunk Matcher、Hybrid KV Manager、Chunk キャッシュ Coordinator、Chunk LRU Managerを追加し、計算経路へブロック単位再計算とRoPE融合注意を追加する。チャンクKVと接頭辞KVは別プールにせず同じページ化HBMを使い、遠隔層はLMCacheのコネクタを利用する。既存のトークン列とページ対応を出力するスケジューラ・インターフェースを保ち、モデル変更なしで位置非依存共有を実現する。設計上は正規チャンクKVを第一級オブジェクトにすることで、将来の量子化、圧縮、熱度別追い出し、CPU/ディスク階層化を同じ正本単位へ適用できる。
## 評価条件
- **ハードウェア**: Huawei Ascend 910B NPU、各64GB HBM。
- **ソフトウェア**: Mistral-7B-Instruct-v0.3をvLLM+LMCache上で実行し、MEPIC、CacheBlend、EPICを同じスケジューリング・バッチ・実行条件で実装する。CacheBlendは15%再計算、EPICは各チャンク16トークン再計算に設定する。
- **比較対象**: CacheBlend（15%再計算）、EPIC（16トークン再計算）
SQuAD、NewsQA、NarrativeQA、emrQAから各300要求を構成し、段落を再利用可能な意味チャンクとして扱う。平均要求長は1435〜2224トークン、再利用率はNewsQA 61.4%、SQuAD 84.9%、NarrativeQA 93.9%、emrQA 98.2%。通常比較ではエンドツーエンド遅延、KVだけのピークHBM使用率、F1またはRouge-Lを測る。負荷試験ではQPS 2〜25で200要求、長文脈試験ではQPS 15、2〜16チャンクへ合成拡張した200要求を評価する。
実機NPU上のシステム評価であり、HBM値はモデル重み・活性値・最適化器状態を除いたKVキャッシュ使用量である。品質・遅延・メモリを同一基盤の比較対象と測っている一方、モデルはMistral-7B-Instruct-v0.3の1種類、アクセラレータもAscend 910Bの1種類に限られる。長文脈スケーリングは意味内容を固定した実データではなく合成的にチャンク数を増やした評価である。
## 主要結果
4データセットの直接比較ではMEPICの品質はCacheBlend/EPICとほぼ同等で、要求ごとのKV複製を減らした結果、ピークHBM使用率はSQuAD 27.67%、NewsQA 36.43%、NarrativeQA 29.67%、emrQA 23.20%まで低下した。比較対象はそれぞれ約37〜54%を使うため、通常データセットでも最大約2倍のメモリ差がある。QPSを2〜25へ上げた負荷試験ではCacheBlend比5.74倍、EPIC比5.25倍少ないHBMを使い、遅延も11.48%/9.1%低下した。2〜16チャンクへ伸ばす長文脈試験では2.97〜5.21倍少ないHBMで40%未満を維持した。利得は再利用率が高いほど大きいが、再利用率61.4%のNewsQAでもメモリ・遅延改善が残る。

- SQuADピークHBM使用率 / 遅延 / 27.67% / 116.03秒 (比較対象: CacheBlend 54.47% / 119.41秒、EPIC 54.13% / 114.73秒; 条件: 300要求、Mistral-7B-Instruct-v0.3) — HBMはほぼ半減する一方、遅延はEPICより約1.3秒長く、この条件ではメモリ節約が常に最短遅延へ直結するわけではない。

- NewsQAピークHBM使用率 / 遅延 / 36.43% / 112.36秒 (比較対象: CacheBlend 45.97% / 117.00秒、EPIC 45.43% / 115.39秒; 条件: 再利用率61.4%、300要求) — 最も再利用率が低いワークロードでもHBMを約20%削減し、遅延も両比較対象より短いので、ほぼ全トークン再利用できる理想条件だけの効果ではない。

- 高負荷時HBM削減 / CacheBlend比5.74倍、EPIC比5.25倍少ない (比較対象: CacheBlend / EPIC; 条件: QPS 2〜25、200要求) — 同一正規チャンクページを並行要求が別コピーせず参照するため、要求数増加に伴うHBM複製が抑えられる。

- 高負荷時エンドツーエンド遅延 / EPIC比9.1%低下、CacheBlend比11.48%低下 (比較対象: EPIC / CacheBlend; 条件: QPS 2〜25、200要求) — HBM節約だけでなく、最初の1ブロック以外の再計算・再ステージングを省くことが応答時間にも寄与する。

- 長文脈HBM削減 / 2.97〜5.21倍少ない、MEPICは40%未満を維持 (比較対象: CacheBlend / EPIC; 条件: QPS=15、2〜16チャンク、200要求の合成拡張) — 比較対象は文脈増加でHBMを早く飽和するが、共有正本ページのためMEPICは追加バッチ余地を残す。

- 品質 / SQuAD 0.74、NewsQA 0.65、NarrativeQA 0.60、emrQA 0.39 (比較対象: CacheBlend 0.73/0.66/0.61/0.39、EPIC 0.72/0.66/0.61/0.39; 条件: F1（SQuAD/NewsQA/emrQA）、Rouge-L（NarrativeQA）) — 最初のチャンクブロックのみ再計算し残りを位置非依存共有しても、比較対象と同程度の出力品質を保つ。

### 負の結果・境界条件
- SQuADではMEPIC 116.03秒に対してEPIC 114.73秒で、MEPICが全条件で最短遅延ではない。利得は共有可能チャンク割合に依存し、NewsQAのように再利用率が低いほどHBM差は縮む。接頭辞KVを追い出さずチャンクと共有プールを使う設計は安定性を優先する反面、接頭辞中心ワークロードではチャンク常駐量を制限し得る。評価は単一モデル・単一NPU系統で、長文脈試験も合成拡張である。

### 結果の読み方
MEPICのメモリ差はKVをさらに低精度化した結果ではなく、同じ論理チャンクについて複数要求が持っていた物理コピーを一つの正規ページ列へ畳み込むことで生じる。そのため同一チャンクを同時利用する要求が増える高QPS条件ほど倍率が大きくなる。遅延差は、固定1ブロック再計算による計算削減と、CPU/ディスクからの再搬入およびHBM内複製を避ける効果の組合せで説明できる。一方、再利用が少なければ共有対象自体が減るため効果も縮小する。
## 品質への影響
近似によるKV値の圧縮ではなく、位置情報を実行時に適用し、要求固有の境界ブロックだけを再計算する方式である。完全な再計算と数学的に同一とは限らずPIC由来の近似性は残るが、4データセットのF1/Rouge-LではCacheBlend/EPICと同程度で、目立つ品質崩壊は観測されていない。
## 既存研究との差
CacheBlendやEPICは位置非依存KVの『どのトークンを再計算するか』を主に最適化するが、要求ごとに出来上がったKVをページ化HBMへ別々に置くため、同一チャンクの物理複製を十分には除かない。MEPICは再計算方策そのものより、共有単位をページ境界へ固定し、最初の1ブロックだけを要求固有化し、位置符号を保存表現から分離することで、vLLMの注意カーネルが直接参照できる一つの正規チャンクKVを作る。LMCacheはGPU/CPU/ストレージ間のKVデータ面を提供するのに対し、MEPICはその上でHBM内のチャンク常駐・共有・追い出しを第一級に扱う。
## 限界
評価はMistral-7B-Instruct-v0.3とAscend 910B 64GBの一構成に集中し、CUDA GPUや異なるKVページサイズ、複数モデルでの実測一般化は示していない。長文脈の2〜16チャンク試験は合成拡張であり、意味依存や実運用の検索分布を完全には再現しない。Prefix KVを追い出さずChunk KVだけをLRU対象とする方針は予測可能性を得る代わりに、接頭辞主体の負荷でチャンク側を圧迫し得る。チャンク境界の意味分割と再利用識別子が既知であることも前提で、プライバシーを跨ぐ利用者間共有は将来課題として残る。
## 実装状態
vLLMのページ化KV管理とLMCacheを拡張した実機システムをAscend 910B上で評価しており、概念提案だけではない。スケジューラ側にチャンク認識・正規配置・HBM常駐管理を、計算側に固定ブロック再計算とRoPE融合注意を実装する。ただし論文本文ではMEPIC本体の著者公式コード公開URLを確認できないため、公開成果物だけで同一差分を再現できる状態かは不明である。
## 研究上の位置づけ
位置非依存キャッシュ、PagedAttention、階層KVキャッシュを接続するサービング基盤研究である。特に『再利用可能KVをCPU/ディスクから毎回持ってくる』段階から、『HBM内で多数要求が同じ物理ページを直接共有する』段階へPICを進める。SSD/NVMe研究との関係では、LMCacheの下位層に退避した正規チャンクを再取得する単位が安定するため、チャンク熱度・先読み・SSD配置をページ列単位で最適化しやすい。将来的には共有HBM正本、DRAM、SSDを同一チャンク識別子で階層化する土台になる。
