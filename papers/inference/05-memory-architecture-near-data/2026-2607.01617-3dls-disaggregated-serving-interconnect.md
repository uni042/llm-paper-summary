# 3DLS: A 3D Logic-Stacked Architecture for Disaggregated LLM Serving

> プリフィル→デコードのKV転送とデコード側テンソル並列AllReduceを同じ横方向リンクで競合させず、KVだけを3D縦リンクへ物理分離するチップレット構成。等帯域条件でも最大1.49倍のスループットと60.2%の遅延削減を示す。

## 概要
3DLSは、プリフィルとデコードを分離したLLMサービングをチップレット上へ載せると、プリフィル側からデコード側へ送るKVキャッシュと、テンソル並列デコードで各層ごとに発生するAllReduceが同じ横方向ダイ間リンクを奪い合い、平均帯域に余裕があってもデコードのクリティカルパスが詰まる問題を扱う。従来の平面構成では優先度制御や仮想チャネルで干渉を配分できても物理リンク自体は共有されるため、3DLSはプリフィル計算を上段、デコード計算と横方向集合通信網を下段へ置くロジック積層を採用し、KV転送だけを縦方向3Dリンクへ分離する。HBMは下段側に置き、上段プリフィルは縦リンクで重みを読み、反対方向の帯域でKVを下段へ送る。等帯域条件のトレース駆動シミュレーションでLLaMA3-8B/70BとOPT-175Bを評価し、共有平面構成比でエンドツーエンド遅延を最大60.2%削減、スループットを最大1.49倍、ワークロード別に最適化した優先度制御平面構成に対しても最大31.4%低遅延・1.17倍高スループットを示す。

3DLSの差分は3D積層を単に追加帯域として使うのではなく、通信種類を物理経路へ対応付ける点にある。プリフィル側チップレットを上段、デコード側チップレットとテンソル並列の横方向D2D網を下段に配置し、KV転送はUCIe-3D級の縦リンク、デコードAllReduceは下段の横リンクへ分離する。さらにHBMを下段側へ残し、上段プリフィルの重み読出しを下→上、生成KVを上→下という全二重の反対方向へ割り当てる。等しい総リンク帯域で比較しているため、主張する利得を『3D化で帯域を増やしたから』ではなく『競合する通信を別経路へ隔離したから』として切り分けている。

代表結果として、競合時累積AllReduce遅延はOPT-175B、TP=16、KV負荷=(バッチ 16, context 16K)、出力128、D2D 512 GB/sで同一条件の競合なしに対して510 ms → 16.37 s、32.1倍。KV転送の一時的な混雑が各層の集合通信へ積み重なる。
## 問題設定
プリフィル・デコード分離では入力処理を計算向け資源、逐次生成をメモリ帯域向け資源へ分けられるが、プリフィルで生成したKVキャッシュをデコード側へ渡す必要がある。大規模モデルではさらにテンソル並列でモデルを複数チップレットへ分割し、デコードの各Transformer層で注意計算後とFFN後に集合通信のAllReduceを行う。平面2D/2.5Dパッケージでは、この遅延に敏感なAllReduceと層単位KV転送が同じ横方向ダイ間接続を使うため、KV転送が一時的に流れるたびAllReduceがキュー待ちし、その遅延が生成トークンごとに繰り返される。OPT-175B、TP=16、D2D 512 GB/sの高KV負荷では、共有経路により累積AllReduce遅延が510 msから16.37 sへ32.1倍、デコードのトークン間時間が61.11 msから184.92 msへ3.03倍になる。優先度や仮想チャネルはどちらを先に通すかを変えるだけで、同じ物理リンクを奪い合う根本原因を消せない。
## 新規性
3DLSの差分は3D積層を単に追加帯域として使うのではなく、通信種類を物理経路へ対応付ける点にある。プリフィル側チップレットを上段、デコード側チップレットとテンソル並列の横方向D2D網を下段に配置し、KV転送はUCIe-3D級の縦リンク、デコードAllReduceは下段の横リンクへ分離する。さらにHBMを下段側へ残し、上段プリフィルの重み読出しを下→上、生成KVを上→下という全二重の反対方向へ割り当てる。等しい総リンク帯域で比較しているため、主張する利得を『3D化で帯域を増やしたから』ではなく『競合する通信を別経路へ隔離したから』として切り分けている。
## 手法
### 手法のあらまし
要求が到着すると、まず上段のプリフィル計算機群で入力トークンをまとめて処理する。各Transformer層のKVキャッシュが生成されると、その層の計算が終わるまで全KVを待つのではなく、対応するデコード側テンソル並列シャードのKV入口へ上段から下段の縦方向リンクを使って順次送る。下段のデコード計算機群は必要なKVが到着した要求を逐次生成へ移し、各層の注意計算とFFN計算の間で必要になるAllReduceは下段の横方向ダイ間接続だけを使う。したがってKV転送が長文や大バッチで急増しても、デコードの集合通信と同じ横方向キューへ入らない。プリフィル:デコードの2:1などの比率は論理プール比であり、上段ダイと下段ダイを一対一で固定対応させる設計ではない。各KV転送は宛先シャードへ整列して入り、テンソル並列度が上がった場合にも単一のデコードダイへ通信を集中させない。HBMは下段・インターポーザ側へ共有配置し、上段プリフィルが必要とする重みや活性値タイルは縦リンクの下→上方向で読み出す。反対の上→下方向は生成済みKV転送に使うため、全二重リンクの方向を別用途へ割り当てる。プリフィルはデコードより演算密度が高いため、この追加メモリホップを行列演算と重畳できるという設計前提を置く。評価では平面共有網の単純構成だけでなく、KV転送とAllReduceを別仮想チャネルへ分けて帯域を静的予約する強い比較対象も用意し、横・縦リンクの総帯域を同程度にそろえる。これにより、性能差を追加帯域ではなく通信種類の物理隔離へ帰属させる。実装時には縦リンク、接合、PHY/制御、KV入口、電力供給の面積・電力、熱、接合歩留まりが新しい設計制約となる。

### 通信種類ごとの物理経路分離
プリフィルからデコードへ渡すKVキャッシュを上段→下段の縦リンクへ、デコード側テンソル並列AllReduceを下段の横方向D2Dへ固定する。従来の平面構成では両者が同じリンクキューを共有するため、KVの大きな転送が入ると、その直後のAllReduceが待たされ、待ち時間がTransformerの各層と生成トークンごとに反復する。3DLSではKV転送のパケットを横方向網へ投入しないので、デコード側の集合通信がKVバーストに巻き込まれない。重要なのは単なる優先度変更ではなく、競合する二種類の通信について物理キューと配線資源そのものを分ける点である。これにより一方の優先度を上げて他方を犠牲にする交換条件を避け、KV転送量が増えてもデコードのクリティカルパスを安定させる。

### 論理プールとシャード整列KV入口
プリフィル:デコード比を物理ダイの積層個数とは切り離し、各プールをテンソル並列シャードの論理群として扱う。各プリフィルシャードが生成したKVは、その情報を必要とする対応デコードシャードの入口へ縦方向に配送されるため、高TP度や非対称なプール比でも単一デコードダイへ全KVを集中させない。平面構成ではTP度が増えるほど宛先までの横方向ホップや共有リンク利用が増え、同時にAllReduceの参加ダイ数も増えるため干渉が悪化する。3DLSは縦方向の入口を使ってKVを共有横網から外し、横方向網をデコード集合通信へ専念させる。プール比を論理的に選べるので、上段と下段を固定した一対一対応にせず、負荷に応じたサービング構成と3D物理配置を分離して考えられる。

### 双方向縦リンクによるHBM共有
HBMは下段側に残し、上段プリフィルは下→上方向で重みと必要なデータタイルを受け取る。一方、上→下方向はプリフィルが生成したKVキャッシュに使う。UCIe-3D級の全二重リンクの二方向を異なるデータ流へ割り当てることで、上段へ専用HBMを追加せずにプリフィル計算を積層し、横方向のデコード集合通信網を汚さない。評価設定では縦リンク総双方向帯域を512 GB/s、各方向を256 GB/sとし、ピーク261.12 TFLOPSのプリフィル計算に必要な重みストリームが下→上方向の範囲へ収まると確認する。プリフィルは比較的演算密度が高いため、重み転送を行列演算と重畳して追加ホップを隠す設計である。ただし、この前提が崩れる低演算密度モデルや帯域不足条件では上段のメモリ読出しが新しい律速になり得る。

### 等帯域比較と優先度管理平面ベースライン
平面共有網のNaive Planarだけを比較対象にすると、3D化による帯域増加と経路分離の効果を区別できない。そこで論文はKV転送とAllReduceを別仮想チャネルへ分け、静的帯域予約を25:75、50:50、75:25からワークロードごとに最善選択するPM-Planarも用意する。さらに3DLSの横方向・縦方向リンクを同じ512 GB/s級にそろえ、総帯域を不当に増やさない条件で評価する。会話負荷では生成が長くAllReduceが支配的なのでAR優先、コード負荷では入力が長くKV転送が支配的なのでKV優先が有利になる。これは共有リンク上の静的優先度が負荷依存であり、最適比率を事前に知ってもなお物理競合が残ることを示す。3DLSはその強い平面比較対象に対しても改善するため、主効果を物理隔離として解釈できる。

### 全体のデータ／制御の流れ
二段ロジック積層の上段に複数プリフィルプール、下段に複数デコードプールと横方向D2D、下段・インターポーザ側にHBMを置く。サービング制御上のプール比は論理配置として選び、KVは層単位で縦方向、デコード集合通信は横方向へ流す。パッケージ資源としては横方向のダイ端配線をHBMや集合通信へ温存し、縦方向をKVと上段メモリ読出しへ使う。
## 評価条件
- **ハードウェア**: Tesla Dojo D1を16×16へスケールした計算モデル、二段ロジック3D積層のモデル、UCIe風横方向D2DとUCIe-3D級縦方向リンク
- **ソフトウェア**: テンソル並列・層単位計算/通信・KV転送を含むトレース駆動社内シミュレータ
- **モデル**: LLaMA3-8B (TP=4)、LLaMA3-70B (TP=8)、OPT-175B (TP=16)
- **データセット／トレース**: Azure conversation トレース：生成が長いデコード優勢負荷、Azure code トレース：入力/KVが長いプリフィル・KV転送優勢負荷
- **比較対象**: Naive Planar：KV転送とAllReduceが同じ横方向D2Dを共有、PM-Planar：別仮想チャネル + 静的重み付き帯域予約だが物理リンクは共有
- **正確性・品質**: モデル演算と通信量を変えず、同一モデル・同一負荷・等帯域設定で通信経路だけを比較する。生成品質ではなくアーキテクチャ性能を評価する。
- **等帯域比較**: 平面の横リンク、3DLSの横リンク、縦リンクを同じ512 GB/s級として評価し、3Dによる追加生帯域ではなく経路隔離の効果を測る。縦リンクは全二重で各方向256 GB/s。
- **計算・メモリ設定**: ピーク261.12 TFLOPS、メモリ帯域3.35 TB/s。プリフィル:デコードの論理プール比は2:1。
- **優先度平面**: PM-PlanarはKVT:ARの静的予約を25:75、50:50、75:25で探索し、会話負荷は25:75、コード負荷は75:25という各負荷に有利な設定を報告する。
- **負荷掃引**: 各モデル・負荷で到着率をスケールし、プリフィルバッチとデコードバッチを掃引する。Naive Planarの遅延・スループットが均衡する代表点を選び、同じ点をPM-Planarと3DLSへ適用する。
- **競合特性評価**: OPT-175B、TP=16、D2D 512 GB/sでKV負荷を(1,1K)から(16,16K)まで変え、出力長128〜1024で累積AllReduce遅延と平均トークン間時間を測る。
まず共有平面でKV転送とAllReduce競合の増幅度を定量化し、その後、同じトレース・モデル・帯域条件でNaive Planar、負荷別に最適化したPM-Planar、3DLSを比較する。性能はエンドツーエンド遅延と要求スループットを中心に測り、3DLSの優位が単なる帯域増加や不利な優先度設定によるものではないよう比較条件をそろえる。
チップレット型PD分離サービングのパッケージ内通信に限定したアーキテクチャ研究。実GPU/実シリコン、NIC/RDMAをまたぐラック間分離、動的オンライン帯域制御、実装コストの詳細回路評価は対象外。
## 主要結果
3DLSは共有横方向リンクからKV転送を外すことで、長文・大モデル・高TP度ほど深刻になるKV/AllReduce干渉を抑えた。Naive Planar比では6つのモデル×負荷組合せの幾何平均でエンドツーエンド遅延40.6%削減、スループット1.22倍、最大では60.2%削減と1.49倍を達成した。ワークロードごとに有利な静的帯域予約を選んだPM-Planarに対しても、幾何平均18.2%低遅延・1.11倍スループットであり、共有物理リンク上の優先度制御だけでは残る干渉を物理分離が除くことを示す。

- 競合時累積AllReduce遅延 / 510 ms → 16.37 s、32.1倍 (比較対象: 同一条件の競合なし; 条件: OPT-175B、TP=16、KV負荷=(バッチ 16, context 16K)、出力128、D2D 512 GB/s) — KV転送の一時的な混雑が各層の集合通信へ積み重なる。

- デコードのトークン間時間 / 61.11 ms → 184.92 ms、3.03倍 (比較対象: 競合なし; 条件: 同上、出力128) — 共有リンク競合が生成トークン間隔へ直接現れる。出力1024でも2.39倍で問題は残る。

- エンドツーエンド遅延 / 最大60.2%削減、幾何平均40.6%削減 (比較対象: Naive Planar; 条件: 最大はConversation / OPT-175B。6モデル×負荷組合せ全体で平均) — KVとAllReduceの物理経路分離が特に大モデル・デコード優勢条件で効く。

- スループット / 最大1.49倍、幾何平均1.22倍 (比較対象: Naive Planar; 条件: 最大はCode / LLaMA3-8B) — KV優勢のコード負荷でも横網を集合通信専用に戻すことで処理率が上がる。

- エンドツーエンド遅延 / 最大31.4%削減、幾何平均18.2%削減 (比較対象: ワークロード最適PM-Planar; 条件: 各負荷でKVT:AR予約を有利に選択) — 論理分離・優先度管理を強くした平面構成よりも物理分離が優位。

- スループット / 最大1.17倍、幾何平均1.11倍 (比較対象: ワークロード最適PM-Planar; 条件: 最大はCode / LLaMA3-70B) — 静的帯域配分は負荷依存で、共有リンクを残す限り完全には競合を除けない。

- 代表遅延 / 44.99 s / 26.08 s / 17.89 s (比較対象: Naive Planar / PM-Planar / 3DLS; 条件: Conversation / OPT-175B、scale=1、PB=16、DB=64) — 大規模・デコード優勢条件で物理隔離の差が大きい。

- 代表スループット / 24.32 / 32.92 / 36.30 req/s (比較対象: Naive Planar / PM-Planar / 3DLS; 条件: Code / LLaMA3-8B、scale=8、PB=1、DB=4) — 優先度制御でも改善するが、3DLSは同じ帯域でさらに上積みする。

### 負の結果・境界条件
- PM-Planarの最適帯域比は会話負荷とコード負荷で逆になり、静的分割を外すとNaive Planarを下回る場合がある。3DLS自身については実シリコン測定がなく、3D積層の熱・面積・接合・歩留まりコストを性能値へ織り込んだ詳細評価はない。上段HBM読出しの追加縦ホップも、プリフィル計算と十分重畳できるというモデル仮定に依存する。

### 結果の読み方
平均帯域を増やすだけでは、遅延に敏感な集合通信とバースト状KV転送が同じキューを共有する問題は残る。3DLSの利得は帯域量ではなく、通信のクリティカル性と方向性に応じて別の物理経路を与えることから生じる。これは分離サービングをソフトウェア資源配置だけでなくパッケージ配線まで共同設計する価値を示す。
## 品質への影響
推論の数値内容を変更しないため生成品質への近似劣化はない。
## 既存研究との差
DistServeやSplitwiseはプリフィルとデコードの資源分離・配置をサービング層で扱う。WSC-LLMはウェハ規模でサービングとアーキテクチャを共同探索するが、3DLSはKV転送とデコード集合通信が同じ横方向物理リンクへ重なる具体的な競合を切り出し、3D積層の縦経路へKVを逃がすことを主眼にする。PM-Planarのような仮想チャネル・サービス品質制御は同じ物理帯域を配分する論理分離であり、3DLSは異種通信を別物理経路へ分ける点が差分である。
## 限界
評価はトレース駆動の社内シミュレータであり、実チップレット・実3D積層・実UCIe-3Dの測定ではない。200 W/cm²という熱設計枠は一次近似で、温度分布、熱スロットリング、電力供給網、接合面積、PHY/制御回路、縦リンク冗長化、実歩留まりを詳細モデル化していない。縦リンクの下→上256 GB/sが上段プリフィルの重みストリームを満たすという設定も、より低演算密度のモデルや異なるメモリ構成へ一般化される保証はない。負荷はAzure会話/コード、モデルはLLaMA3-8B/70BとOPT-175Bに限定され、MoE、推論時量子化、ラック間PD分離、動的ネットワーク制御は未評価。シミュレータの公開コードも確認できない。
## 実装状態
IEEE Computer Architecture Letters採録済みのアーキテクチャ提案。トレース駆動社内シミュレータで評価され、実シリコン実装や著者公式コード公開は一次資料から確認できない。
## 研究上の位置づけ
メモリアーキテクチャ・近データ系統とLLMサービング・分離推論系統を横断するハードウェア/ソフトウェア共同設計。KVキャッシュを保存する階層そのものより、KVがプリフィルからデコードへ移動する経路とテンソル並列通信の衝突をパッケージ構造で解く。
