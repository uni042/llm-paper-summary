# Rethinking Unified Memory for NPU-PIM Systems: Dual-View Memory for Dynamic Inference of LLM

> NPU/PIMで共有する物理配置と各デバイスが見る論理配置を分離し、実行時の演算特性に応じて実行先を切り替えても帯域を落とさない統合メモリ方式。
## 書誌情報
- **著者**: Shixin Zhao, Lian Liu, Tianhua Han, Mengdi Wang, Yinhe Han, Ying Wang
- **著者・所属**: Institute of Computing Technology, Chinese Academy of Sciences; University of Chinese Academy of Sciences
- **公開**: arXiv
- **種別**: Preprint
- **対象**: NPU-PIM、統合メモリ、動的演算配置、MoE推論、メモリ内処理
- **実装**: 研究用システムシミュレータへPFMのアドレス再対応付け・スケジューラを実装し、ARU/FASをRTLで合成。公開コードURLは一次資料で確認できない。
## 概要
PFMは、NPUとメモリ内処理（Processing-in-メモリ; PIM）が同じテンソルを共有しつつ、推論中の計算特性に応じて実行先を切り替えるための二重視点メモリ方式である。従来の統合メモリはテンソルごとにNPU向けまたはPIM向けの固定配置を選ぶため、プリフィルとデコード、混合専門家モデルの活性エキスパート数が変化すると、実行先と物理配置が不一致になり帯域が低下する。PFMは2 MBスーパーページ内の物理配置を両デバイス向けに共同最適化し、アドレス再対応付けと要求スケジューリングで各デバイスへ異なる論理視点を見せる。さらに実行時性能モデルで演算をNPU/PIMへ動的配置し、データ複製や再配置なしに最大2.32倍のスループット改善を報告する。

PFMの中心的な新規性は、一つの物理配置をNPU/PIM双方にそのまま見せるのではなく、物理配置とアクセス側が見る論理視点を分離する点にある。2 MBスーパーページ内のアドレスビット配置を両デバイスの帯域目標で共同最適化し、メモリ制御器が要求元に応じて物理アドレスをハードウェア位置へ再対応付けする。さらにNPU要求はチャネル並列性と行局所性、PIM要求はバンク並列放送を優先して別々に整列する。これにより同じデータを複製・再配置せず、実行時に演算をNPUとPIMの間で切り替えられる。

代表結果として、大バッチ推論スループットはバッチ128〜512、LLaMA3/DeepSeekMoE/Mixtral/GPT-OSSでPIM偏重統合メモリPUMに対してPUM比平均1.55倍、最大2.32倍。物理再配置なしの動的演算切替が、固定PIM向け配置のNPU帯域低下を避ける。
## 問題設定
NPUとメモリ内処理（PIM）を組み合わせるLLM推論では、NPUは計算量の大きい行列演算、PIMは帯域律速の注意計算や低活性エキスパートを得意とする。しかしNPUは連続データを複数チャネルへ細かく分散した配置を好み、PIMは同一バンク内の連続性と多数バンクの並列性を好むため、最適なDRAM配置が異なる。既存の統合メモリはテンソル割当時にどちらか一方へ偏った配置を固定する。ところがプリフィルからデコードへの相転移やMoEの動的ルーティングで同じテンソルの最適実行先が変わると、実行先と配置が不一致になり実効帯域がピークの20%未満まで落ちる場合がある。実行先変更のたびに物理再配置すると大規模重みの移動費用が利益を相殺する。
## 新規性
PFMの中心的な新規性は、一つの物理配置をNPU/PIM双方にそのまま見せるのではなく、物理配置とアクセス側が見る論理視点を分離する点にある。2 MBスーパーページ内のアドレスビット配置を両デバイスの帯域目標で共同最適化し、メモリ制御器が要求元に応じて物理アドレスをハードウェア位置へ再対応付けする。さらにNPU要求はチャネル並列性と行局所性、PIM要求はバンク並列放送を優先して別々に整列する。これにより同じデータを複製・再配置せず、実行時に演算をNPUとPIMの間で切り替えられる。
## 手法
### 手法のあらまし
オフライン段階ではモデル仕様からNPU/PIMの双方が使う重みやKVキャッシュを抽出し、テンソル形状・型・論理配置を入力として2 MBスーパーページ内の物理アドレスビットをチャネル、バンク、行、列へどう割り当てるか探索する。目的関数はNPU側のチャネル分散・行競合抑制とPIM側のバンク並列性・局所連続性を同時に評価し、得られた対応付けへMapIDを付けて記述表へ保存する。割当時には標準のメモリ確保をPFMMallocへ置き換え、必要なスーパーページを確保してMapIDと物理フットプリントを結び付ける。解放後は同じフットプリントを利用できる別MapIDのテンソルにもページを再利用でき、互換ページがなければ新しいページを割り当てる。実行時は通常の仮想→物理変換後、アドレス再対応付け器がMapIDと要求元を見てハードウェア位置へ変換する。柔軟アクセススケジューラはNPU要求をチャネル並列向け、PIM要求をバンク並列向けに並べ替え、競合時は遅延敏感要求を優先しつつ空き時間を利用する。ソフトウェア側では同じ演算のNPU版とPIM版を用意する。実行時性能モデルが演算量、実効帯域、PIMのバンク並列度、固定起動費用から両デバイスの予測時間を比較し、速い側へ演算を送る。NPUを選んだ場合は通常の実行ストリームへ、PIMを選んだ場合は演算識別子と引数を制御メッセージとしてPIM配列へ送る。どちらを選んでも参照する物理データは同じであり、メモリ制御器が要求元に合わせた論理視点と要求順序を作る。したがってデータは一度配置したまま、演算だけがプリフィル/デコード相転移やMoE活性変動に応じて移動し、従来必要だった重み複製・全体再配置と、それに伴う帯域浪費を避ける。

### 二重視点物理配置の共同最適化
各2 MBスーパーページを探索単位とし、テンソルの連続次元とストライド次元をアドレスビットへ分解する。各ビットをチャネル、バンク、行、列などのDRAM階層へ一意に割り当てる制約の下で、NPUが多数チャネルを同時利用できる度合いと、PIMがバンク内連続性・全バンク並列性を得られる度合いを解析モデルで評価する。最終的な対応付けはMapIDとして記述表へ登録される。これによりNPU専用配置とPIM専用配置のどちらかへ固定せず、同じ物理ページから両方に効率的なアクセス順を生成できる。断片化で同じ物理位置を再利用できない場合でも互換なフットプリントを持つ新しいスーパーページを割り当てるため、正しさは理想的な再利用に依存しない。

### アドレス再対応付けと要求元別スケジューリング
仮想アドレスから物理アドレスへの通常変換は維持し、その後段だけにアドレス再対応付け器を追加する。器はMapIDと要求元がNPUかPIMかを見て、共同最適化済みの物理データを要求元に適したハードウェア順序として解釈する。柔軟アクセススケジューラはNPUではチャネル同時利用と行局所性を高めるよう要求を並べ、PIMでは複数バンクへの放送をまとめる。競合時は遅延敏感な要求を優先し、空き周期へ他方を詰める。これが物理再配置なしの『二重視点』を実際の帯域へ変換する機構であり、PUMのようなPIM偏重配置でNPU帯域が落ちる問題を避ける。

### 実行時NPU/PIM演算選択
モデル実行系は同じ演算のNPU版とPIM版を準備し、呼び出し時に屋根線モデル型の予測器で実行時間を比較する。NPU側は演算量/ピーク演算性能と重み量/実効帯域の大きい方、PIM側はバンク並列度で補正した演算・帯域時間に固定起動費用を加えて見積もる。MoEでは各デコード段階の活性トークン数が変わるため、同じエキスパートでも計算律速ならNPU、帯域律速ならPIMへ切り替わる。データはPFM上で共有されているため、この切替に重み複製や全体再配置を伴わない。予測やプロファイルが古くなると不適切な実行先を選ぶ可能性があり、その場合は再プロファイルが必要になる。

### 全体のデータ／制御の流れ
ソフトウェア変更は主にPFMMallocと統一起動接口、オフライン配置探索・性能モデルに限定し、既存NPUカーネル自体は変更しない。ハードウェア変更はメモリ制御器内のアドレス再対応付け器、32項目の対応付け記述表、NPU/PIM要求バッファ、柔軟アクセススケジューラ、64 KBの再整列バッファで構成する。DRAMセル、タイミング規約、NPUコアは変更しない。評価した設計では追加面積2.82 mm²で、A100の有効HBMインターフェース領域に対し4.95%、全ダイに対し0.34%相当と見積もる。
## 評価条件
- **ハードウェア**: A100級計算資源とHBM-PIMを組み合わせる構成を使用。各HBM-PIMスタックは16 GB、8チャネル、3.2 Gbps、各バンクに666 MHz処理器を置き、スタック当たり12.8 TFLOPSをモデル化する。ARU/FASは7 nm想定でRTL合成する。
- **ソフトウェア**: vLLMで実モデルのCUDAカーネルとアクセスを採取し、GPGPU-Sim 4.0とRamulator 2.0を統合したシステムシミュレータへ再生。PIM制約とPFM制御器をRamulatorへ追加する。
LLaMA3-8B、DeepSeekMoE-16B、Mixtral 8x7B、GPT-OSS-120Bを対象に、NPUのみ、分離メモリ型PSM、PIM偏重統合メモリ型PUMと比較する。バッチ1・4の遅延重視条件と128〜512のスループット重視条件、異なる入力・出力長を評価する。シミュレータは実A100と既存NPU-PIMシミュレータに照合し、誤差は-15.57%〜0%、平均-5.14%。
主な性能値は実機そのものではなく、実ワークロードから取得したカーネル・メモリアクセストレースを用いる検証済みシステムシミュレーションである。面積はRTL合成による。したがって実製品NPU-PIMでのエンドツーエンド実測ではない点を区別する必要がある。
## 主要結果
PFMは、静的なPIM偏重配置やNPU/PIM分離配置の弱点を、同一物理ページを両デバイスから効率良く読める共同配置と実行時演算切替で緩和する。小バッチではNPUのみ・PSM・PUMに対し平均でそれぞれ1.04倍、2.10倍、2.23倍の高速化を示し、大バッチのスループットではPUM比平均1.55倍、最大2.32倍に達する。MoEでは活性エキスパート数の段階変動へ追随するため静的割当との差が大きく、NPU/PIM双方で90%以上の帯域利用率を維持する。

- 大バッチ推論スループット / PUM比平均1.55倍、最大2.32倍 (比較対象: PIM偏重統合メモリPUM; 条件: バッチ128〜512、LLaMA3/DeepSeekMoE/Mixtral/GPT-OSS) — 物理再配置なしの動的演算切替が、固定PIM向け配置のNPU帯域低下を避ける。

- プリフィル遅延 / 3.43倍短縮 (比較対象: PUM; 条件: 単一バッチ、入力1024・出力128) — 共同最適化配置が計算律速プリフィル時のNPU帯域を回復する。

- MoEブロック遅延 / NPUのみ比1.76倍、PSM比2.01倍、PUM比2.05倍短縮 (比較対象: 各比較方式; 条件: MoEモデルの動的エキスパート活性) — 段階ごとの活性度に応じたNPU/PIM選択が静的配置の負荷不均衡を減らす。

- 帯域利用率 / NPU 92.10%、PIM 94.85% (比較対象: PUMのNPU側は代表形状で14.33〜23.52%; 条件: Mixtral推論のQKV、KV、MoE重みアクセス) — 一つの物理配置から両アクセス様式を高効率に供給できる。

- 制御器面積 / 2.82 mm² (比較対象: A100有効HBMインターフェース領域57.0 mm²; 条件: 7 nm想定RTL合成) — 追加面積は同領域の4.95%、全ダイ換算0.34%相当。

### 負の結果・境界条件
- 動的な物理再配置方式はデータ移動が大きく、Oracle比でDeepSeekMoE 13.61%、GPT-OSS 53.6%、Mixtral 49.83%低い。PFM自身もオフラインプロファイルと32項目の対応付け表に依存し、モデル集合や活性傾向が大きく変わると再プロファイルまたは表拡張が必要になる。

### 結果の読み方
PFMの利益は、NPU向け配置とPIM向け配置のどちらか一方を選ぶのではなく、両者の物理要件を共同最適化し、要求順序だけを実行時に変えることで得られる。プリフィルではNPUのチャネル帯域、デコードや低活性MoEではPIMのバンク並列性を維持できるため、相ごとに最適実行先が変わっても再配置費用を払わない。
## 品質への影響
演算近似や量子化を導入する方式ではなく、データ配置・アドレス解釈・実行デバイスを変えるシステム最適化であるため、モデル品質を意図的に下げる要因はない。評価は性能シミュレーション中心で、精度指標の変化を主張する論文ではない。
## 既存研究との差
NeuPIMs型の分離メモリはデバイスごとの最適配置を保つ代わりに共有時の移動を要し、IANUSやFACIL型の統合メモリは共有空間を得る代わりに静的なデバイス偏重配置を使う。PFMは共有物理空間を保ったまま物理配置と論理視点を分離し、同じテンソルをNPU/PIMのどちらからも効率良く読めるようにする点が異なる。
## 限界
32項目の対応付け記述表とオフラインプロファイルに依存するため、提供モデル集合やMoE活性傾向が大きく変化すると再プロファイルや記述表拡張が必要になる。性能評価は検証済みシステムシミュレータ中心であり、実製品NPU-PIM上の完全なエンドツーエンド実測ではない。
## 実装状態
GPGPU-SimとRamulatorを統合した評価実装、PFMメモリ制御器の機能モデル、ARU/FASのRTL合成まで実施。一次資料で一般公開された完全実装リポジトリは確認できない。
## 研究上の位置づけ
階層メモリ・近データ処理系の研究として、データをCPU/GPU/SSD間で移すオフロードとは異なり、同じ物理データを複数アクセサが異なる論理視点で読むことで移動そのものを避ける設計である。MoEの動的ルーティングとプリフィル/デコード相転移をメモリ配置問題へ結び付け、実行時演算配置とアドレス変換を一体化した点が重要である。
