# MagicDec: Breaking the Latency-Throughput Tradeoff for Long Context Generation with Speculative Decoding

## 概要
投機的復号は小さなドラフトが複数tokenを提案し、大きな対象モデルが一括検証することで対象モデル呼出し回数を減らす。一般にはバッチを大きくすると対象モデルの検証計算が重くなり、投機の利得が消えると考えられてきた。MagicDecは長文脈ではこの前提が変わることを示す。系列長とバッチが大きいほどKVキャッシュ読出しが支配し、通常復号と複数token検証の双方が同じ巨大KVを読むため、検証tokenを増やす追加費用の相対比が下がる。

MagicDecは対象モデル自身をドラフトとして使いつつ、ドラフト時だけ疎なKVキャッシュを参照する自己投機を採用する。StreamingLLMやSnapKV等でドラフトのKV読出し量を小さくし、対象モデルの完全KVで候補を検証する。さらにハードウェア、系列長、バッチ、ドラフトKV予算、受理率から最適ドラフト長を選ぶ解析モデルを使う。Llama-3.1-8Bでは8枚H100、10万token級の長文脈で最大2.51倍を報告する。

## 問題設定
投機的復号の1サイクル時間は、ドラフト生成費用、対象モデルの検証費用、1回に受理できるtoken数で決まる。短文脈では大バッチ化により検証GEMMが計算律速になり、候補を増やすほど高価になる。しかし長文脈では各tokenが過去KV全体を読むため、KV帯域費用が系列長とバッチに比例して増える。対象モデル重みの相対費用は小さくなり、通常復号も検証もKV読出し待ちになる。

ここで小型の別ドラフトモデルを使うだけでは、そのモデル自身も長いKVを持つためメモリ帯域を消費する。MagicDecは「パラメータを小さくする」より「ドラフトが読むKVを小さくする」方が長文脈では重要と捉える。

## 手法
### 律速遷移モデル
系列長S、バッチB、ドラフト長γ、ドラフト時間、検証時間、期待受理token数Ωを使って、自己回帰復号と投機的復号の1 token当たり費用を比較する。解析から、系列長がある屈曲点を越えるとKV読出しが支配し、Bを増やしても投機の相対利得が再び大きくなる領域を導く。出力は、そのhardware/workloadで投機を使うべきかと最適γの指針である。

### 疎KV自己投機
同じLlamaをドラフトと対象に使うが、ドラフトでは過去KVの一部だけを参照する。StreamingLLM型ではattention sinkと直近tokenを固定予算で残す。SnapKVはprompt側の重要KVを静的に選ぶ。これによりドラフトは同じ重みを使って高い候補品質を保ちながら、長文脈で支配的なKV転送量を削る。

候補は完全KVを使う対象計算で検証されるため、ドラフト近似を最終出力へ直接採用しない。投機的復号の受理・補正式に従うことで対象モデルの生成結果を保つ。疎KVは速度だけでなく受理率にも影響するので、KV予算を小さくしすぎると候補品質が落ちる。

### KV選択方式の費用まで含める
動的top-kのように毎step重要KVを検索する方式は高い受理率を得ても、選択費用T_selectが大きければドラフト全体が遅くなる。MagicDecはSnapKVの静的選択とPQCache等の動的選択を、受理率だけでなくドラフト/対象費用比で比較し、最終speedupへ効く選択方式を選ぶ。

## 評価条件・主要結果
|項目|内容|
|---|---|
|主モデル|Llama-3.1-8B、補助評価にLlama-2-7B-32K等|
|GPU|8×A100、8×H100など|
|主データ|PG-19、RULERのQA/CWE等|
|系列長|4K～100K級|
|バッチ|32～256を含む|
|ドラフトKV|StreamingLLM、SnapKV等の疎KV|
|品質|完全KV対象モデルで検証する損失なし投機|

|条件|結果|解釈|
|---|---|---|
|Llama-3.1-8B、8×H100、100K、CWE|最大2.51倍|長文脈・大バッチでも投機が有効|
|Llama-3.1-8B、8×H100、100K、QA-1|2.43倍|taskが変わってもKV律速領域で大きい|
|Llama-3.1-8B、8×H100、64K、PG-19|2.21倍|中長文脈でも利得|
|短い4K、大バッチ|1倍未満の条件あり|compute-boundでは投機overheadが勝つ|

8×A100の表でもLlama-3.1-8Bは4K/B=64で0.81倍と遅くなる一方、64K/B=64では1.58倍へ上がる。これは「大バッチなら投機は常に不利」ではなく、系列長による律速遷移が決定的であることを裏付ける。

## 既存研究との差
従来の投機的復号研究は小型ドラフトのパラメータ費用と受理率を中心に最適化する。MagicDecは長文脈でKV読出しが支配することを出発点にし、ドラフトモデルのKVだけを疎化する。また単一設定の高速化ではなく、系列長・バッチ・hardwareのFLOPS/帯域比から投機が有利になる境界を説明する。

## 限界
短文脈や計算律速の大バッチでは実際に1倍未満となる条件があり、無条件の高速化ではない。動的KV選択は受理率が高くても検索費用で不利になり得る。最大2.51倍は8×H100、Llama-3.1-8B、特定長文脈taskの値で、すべてのモデルやGPUへ直接外挿できない。疎KVドラフトの品質はtask依存で、最適KV予算とγを選ぶ必要がある。
