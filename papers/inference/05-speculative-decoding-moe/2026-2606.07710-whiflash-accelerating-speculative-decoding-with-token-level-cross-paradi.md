# WhiFlash: Accelerating Speculative Decoding with Token-Level Cross-Paradigm Routing

## 書誌情報

Young D. Kwon、Miles Williams、Rui Li、Alexandros Kouris、Stylianos I. Venierisによる2026年6月5日公開のプレプリント（arXiv:2606.07710v1）。投機的復号（speculative decoding）において、自己回帰型（autoregressive; AR）と拡散型（diffusion-based）の草稿モデルを同時に用意し、目標モデルによる検証ラウンドごとに適切な方式を選択するシステムを提案する。

従来の複数草稿器ルーティングが同種の草稿器間の選択やタスク単位の選択に重点を置いていたのに対し、本研究は**生成中の同一系列内でも草稿器の優劣が反転する**点を問題として扱う。推論アルゴリズムだけでなく、切替時のKVキャッシュ整合とGPU実行費用を考慮した設計である。

## 概要

投機的復号では小型草稿器が次のトークン候補を提案し、大型目標モデルが候補をまとめて検証する。草稿器が正しい候補を長く提案できるほど、目標モデル1回の検証で進むトークン数が増える。ただし、草稿器の構造には得意・不得意がある。自己回帰型のEAGLE-3は逐次的な依存関係を捉えやすく、自由記述や複雑な推論で有利になりやすい。DFlashのような拡散型草稿器は複数位置を一度に予測するため、構造的で予測しやすい出力で有利になりやすい。

原著の観測では、**同じ生成系列の途中でも受理長が1〜6トークン程度に大きく変動**し、どちらの草稿器が優れるかも入れ替わる。WhiFlashはこの変動に対応するため、検証ラウンド単位のルータを設ける。軽量版は目標モデルの次トークン分布のエントロピーを閾値比較し、学習版は目標モデルの隠れ状態から2方式の受理長差を予測する。

草稿器を切り替えると、使っていなかった自己回帰型草稿器のKVキャッシュが最新の確定接頭辞に追い付いていない。WhiFlashは非稼働中の更新を遅延し、切替時に不足分を一括再計算する。また、過去の確定トークンの予測ロジットは不要なので、必要なKVだけを再構築する。原著はこの切替処理の費用を検証ラウンド遅延の7%未満に抑えたと報告する。

## 問題設定と比較対象

### なぜ草稿器の固定選択では不十分か

目標モデルの各検証ラウンド $t$ で受理できるトークン数を $AL_t$ とする。草稿器の平均受理長が高くても、生成中の一部の位置で受理が短くなると、そこで大きな目標モデル呼び出しが増える。原著図2では、EAGLE-3とDFlashの受理長が同一系列内で異なるタイミングに上下する。全体平均だけを使って最初に草稿器を一つ決めると、局所的な改善機会を捨てる。

タスク単位のルーティング（Oracle-Task）は、チャット・数学・コード・エージェントなどのカテゴリごとに事後的に最良の草稿器を選ぶ。プロンプト単位のルーティング（Oracle-Prompt）は、各入力について事後的に最良の草稿器を選ぶ。トークン単位の理想選択（Oracle-Token）は各検証位置で最良の草稿器を選ぶ。WhiFlashは理想選択の効果を、実行時に利用できる情報から低費用で近似することを狙う。

ここで「トークン単位」とは、**確定したトークンを一つ生成するたびに必ず切り替える**ことではない。目標モデルが草稿を検証した各ラウンドの境界で、次の草稿器を選択できるという粒度である。1ラウンドで複数トークンを受理することがある。

### 草稿方式の非対称性

自己回帰型草稿器は $y_1,y_2,\ldots$ を先行候補に条件付けて逐次生成し、候補木を構築する。拡散型草稿器は一つの前向き計算で候補ブロックの複数位置を並列に予測できるが、同一ブロック内部の逐次依存を明示的には表現しにくい。両者は生成遅延もKVキャッシュの保持方法も異なる。したがって単純に「受理長の大きい方式」を選ぶだけでは最終的な秒当たり生成トークン数を最大化できない。

## 手法

### 1. 検証ラウンドごとの処理フロー

WhiFlashの入力は、目標モデルが既に確定した接頭辞、現在の目標モデル状態、自己回帰型草稿器と拡散型草稿器の二つである。各ラウンドでは、(1)目標モデルの直近の出力からルーティング特徴を得る、(2)ルータが次ラウンドで使う草稿器を決定する、(3)選ばれた草稿器が候補木または候補ブロックを作る、(4)目標モデルが候補を並列検証する、(5)受理した接頭辞を確定して次ラウンドへ進む。

この設計では、検証のために目標モデルを余計に呼び出す必要はない。ルーティング特徴は直近の検証から得られる分布や隠れ状態を利用する。未選択の草稿器は次の草稿を作らず、切替に必要な状態だけ後で追い付かせる。

### 2. エントロピーに基づく軽量ルータ

WhiFlash-Entropyは目標モデルの次トークン分布 $p_t$ から

\[
H_t=-\sum_{x\in V}p_t(x)\log p_t(x)
\]

を計算する。$H_t$ が小さいと、目標モデルは少数の候補に高い確率を与えているため、拡散型の並列ブロック草稿が当たりやすいと期待する。$H_t$ が大きいと、次トークンの不確実性が高く、逐次依存を使う自己回帰型草稿器を選ぶ。閾値 $\tau_{\mathrm{entropy}}$ は、チャット・コード・数学・エージェントなどのカテゴリごとに32〜64件の保留プロンプトを使って格子探索し、平均処理量を最大化する値を選ぶ。

エントロピー計算は語彙サイズ $|V|$ に対する総和を一回計算するため $O(|V|)$ であり、草稿モデルの順伝播に比べて小さい。ただし、目標モデルの最終分布を利用するため、目標モデル側の確率計算が全く無料というわけではない。貪欲復号の場合はソフトマックス計算が追加で必要となり得ることを原著は明記している。

### 3. 受理長差を回帰する学習ルータ

WhiFlash-Neuralは目標モデルの最終層隠れ状態 $h_t\in\mathbb R^d$ を入力し、軽量な2層主体の多層パーセプトロン（MLP）$f_\theta$ から

\[
\Delta\widehat{AL}_t=f_\theta(h_t)
\]

を出力する。教師信号は同じ位置で二つの草稿器をそれぞれ動かして得た受理長の差 $\Delta AL_t=AL_{\mathrm{AR},t}-AL_{\mathrm{Diff},t}$ である。単なる二値分類ではなく差の大きさを回帰するため、切替によって何トークン程度の利益が期待できるかを表現できる。

学習データはタスク固有のラベルではなくDolci Instruct SFTの一般的な指示データから構築する。原著は目標モデルごとに2500万トークンの部分集合を使い、AdamW、平均二乗誤差、ピーク学習率 $10^{-3}$、1エポック、8192トークンのバッチで学習する。学習時には両草稿器を同じ位置で評価する費用がかかるが、推論時には小さな回帰器だけを実行し、学習費用は複数要求へ償却する。

### 4. ハードウェア費用を考慮した選択

予測された $\Delta\widehat{AL}_t$ の符号だけで草稿器を選ぶと、草稿器ごとの実行遅延や切替費用を無視してしまう。WhiFlash-Neuralは、草稿器ごとの遅延と切替遅延に基づく閾値 $\tau_{\mathrm{neural}}$ を設け、予想される受理トークン増加が費用に見合うときだけ方式を変更する。これは「受理長を最大化する」ことと「実時間処理量を最大化する」ことの違いを扱う重要な設計である。

ハードウェアや草稿器実装が変われば、同じ受理長差でも有利な方式は変わる。従って、論文で得られた閾値を別のGPUへ無条件に移すべきではない。エントロピー版は学習不要だがカテゴリごとの閾値較正を要し、学習版はモデルごとの教師データ作成と学習を要する。

### 5. 非稼働草稿器のKVキャッシュを遅延更新する

異なる草稿器を毎ラウンド切り替える際の最大の実装問題は、非稼働中の自己回帰型草稿器が、目標モデルで確定したトークンのKVキャッシュをまだ持っていないことである。素朴な実装では、非稼働中も毎ラウンドその草稿器を更新しておけば切替は速いが、小さな再計算を何度も実行してしまい、二つの草稿器を維持する費用が高くなる。

遅延追い付き（Lazy Catch-up）では、非稼働中の草稿器の更新を完全に保留する。切替が決まったときだけ、非稼働期間に目標モデルが受理したトークン列（backlog）をまとめて前処理し、キャッシュを最新の確定接頭辞へ追い付かせる。非稼働中に不要な計算をせず、切替時は不足トークンをまとめて処理するため、細切れの処理を減らせる。

さらにKV専用前処理（KV-only Prefill）は、追い付きに必要なものが過去トークンのKVキャッシュであり、過去トークンの新たな予測ロジットではない点を利用する。既に確定済みのトークンについては、最終出力に不要なMLPや語彙ヘッドの処理を避け、KV構築に必要な注意処理を進める。次の草稿生成に使う最後のトークンだけは、後段に必要な隠れ状態を得るために通常の計算を行う。この二つの最適化により、原著は切替費用を検証ラウンド遅延の7%未満に抑えたと報告している。

## 主要結果

### Qwen3-4Bのカテゴリ別比較（原著の主結果表）

速度倍率は、同じ目標モデルの通常の自己回帰復号を1倍とした値である。以下の数値はEAGLE-3やDFlashに対する直接倍率ではない。

| 手法 | Chat 受理長/速度 | Math 受理長/速度 | Coding 受理長/速度 | Agentic 受理長/速度 | 総平均 受理長/速度 |
|---|---|---|---|---|---|
| EAGLE-3 | 5.21 / 2.58倍 | 5.44 / 2.94倍 | 5.25 / 2.79倍 | 3.99 / 2.02倍 | 4.95 / 2.57倍 |
| DFlash | 3.43 / 2.08倍 | 7.22 / 4.75倍 | 6.45 / 4.29倍 | 3.56 / 2.34倍 | 5.08 / 3.30倍 |
| WhiFlash-Entropy | 5.19 / 2.69倍 | 7.36 / 4.90倍 | 6.73 / 4.46倍 | 4.22 / 2.41倍 | 5.82 / 3.56倍 |
| WhiFlash-Neural | 5.41 / 2.78倍 | 7.66 / 4.98倍 | 6.97 / 4.57倍 | 4.40 / 2.42倍 | 6.05 / 3.63倍 |

Qwen3-4Bの総平均では、学習ルータ版の速度倍率3.63はEAGLE-3の2.57、DFlashの3.30より大きい。カテゴリ別に見ると、数学ではDFlashが4.75倍とEAGLE-3の2.94倍を大きく上回り、チャットではEAGLE-3が2.58倍とDFlashの2.08倍より速い。この非対称性がルーティングの利点を説明する。

### 他のモデルへの一般化と負の結果

Qwen3-8Bの総平均はEAGLE-3が受理長5.12・2.78倍、DFlashが5.29・3.55倍、WhiFlash-Entropyが6.08・3.82倍、WhiFlash-Neuralが6.26・3.87倍であった。Qwen3-4Bと同様に学習ルータ版が平均で最も高い処理量を示す。

一方、Llama-3.1-8Bの総平均ではEAGLE-3が4.99・2.30倍、DFlashが3.97・2.55倍、WhiFlash-Entropyが5.01・2.59倍、WhiFlash-Neuralが5.14・2.59倍である。**受理長は伸びても速度改善は小さく、学習ルータ版とエントロピー版の総平均速度倍率は同じ**だった。数学カテゴリではWhiFlash-Neuralが2.88倍、WhiFlash-Entropyが2.89倍で、学習版が常に勝つわけではない。コードカテゴリでも学習版3.07倍はエントロピー版3.09倍を下回る。追加学習の費用を支払っても必ず大きな利益が得られるとは限らないことを示す。

原著はタスクカテゴリ別の最大値として、EAGLE-3比で処理量69.6%増、DFlash比で37.3%増を報告する。これは全モデル・全タスクに共通する一律の改善率ではない。実際、チャット・数学・コード・エージェントで草稿器の優劣と改善幅が異なる。

### 理想ルーティングとの比較

Qwen3-4BではOracle-Taskの総平均受理長5.67・速度3.44倍、Oracle-Promptの5.71・3.60倍に対し、WhiFlash-Neuralは6.05・3.63倍である。カテゴリやプロンプトで草稿器を固定するより、検証ラウンドごとに切り替える方が有利になり得ることを示す。Oracle-Tokenの総平均受理長は6.59であり、WhiFlash-Neuralの6.05との間にはなお改善余地がある。ただし、Oracle-Tokenはfloat32での理想選択に基づくため、同一精度での実測速度上界として扱えない。

Qwen3-8BではOracle-Tokenの総平均受理長6.81に対しWhiFlash-Neuralは6.26、Llama-3.1-8Bでは5.36に対し5.14であった。理想選択との差が残ることは、エントロピーや隠れ状態だけでは草稿器の局所的な優劣を完全には予測できないことを示唆する。受理長の上界が大きくても、実際の処理量は切替・草稿・検証の費用に依存する。

## 既存研究との差

EAGLE-3は目標モデルの特徴を利用した自己回帰型草稿生成を高速化し、DFlashは拡散型の並列ブロック草稿で逐次依存の費用を減らす。WhiFlashはどちらかの草稿器そのものを置き換える新しい生成モデルではなく、**異なる二つの草稿方式を同じ目標モデルの検証ラウンド内で選択する制御層**を追加する。

HedgeSpecなどの同種草稿器ルーティングは、タスク中に最適な専門家を選び続ける枠組みとして設計される。WhiFlashは最適な方式が一つの生成系列内でも反転することを前提に、毎ラウンド切替を許す。また、接頭辞の繰返しを利用する検索型の投機的復号とは異なり、過去の文字列一致をルーティングの前提としない。エントロピー版は次トークン分布を、学習版は目標モデルの隠れ状態を使う。

最大のシステム上の差は、異種草稿器を頻繁に切り替える際のKVキャッシュ費用を明示的に解決する点にある。非稼働中の草稿器まで毎回更新する設計では、局所的な受理長の利益が状態同期の費用で相殺される。遅延追い付きとKV専用前処理は、ルータを実際のGPU上で利用可能にするための要素である。

## 限界と適用上の注意

第一に、評価はH100とQwen3-4B/8B、Llama-3.1-8Bに限定される。GPUメモリ容量、帯域、計算能力、カーネル効率が異なる端末向けGPUや、連続バッチ処理を行う本番サーバで同じ倍率が得られるとは限らない。とくに異種草稿器を同時に保持するための追加メモリ、モデルロード費用、複数要求をまとめる場合のルータ挙動は個別に検証する必要がある。

第二に、学習版は目標モデルごとに教師データを作成し、両草稿器の受理長差を測定して学習する費用がある。実験の一部ではエントロピー版と速度差がほとんどなく、追加学習が正当化されるかはワークロード次第である。エントロピー版も閾値の較正を必要とし、カテゴリ分布が変われば最適値が変化する可能性がある。

第三に、論文の速度倍率はデコード段階の処理量であり、要求受付からの先頭トークンまでの時間やモデルの読み込み、キュー待ち、複数ユーザー同時実行を含むエンドツーエンドのサービス遅延を直接示すものではない。受理長が伸びても、ルータと草稿器の実行費用が増えれば速度向上は小さくなる。実際にLlama-3.1-8Bでは両ルータの平均速度が同率であった。

第四に、Oracle-Tokenの結果はfloat32を使う理想選択に基づき、bfloat16で測った他手法の処理量と同列に比較できない。原著も速度倍率を表示していない。理想選択の受理長をそのまま達成可能なGPU処理量の上界と解釈することは不適切である。

第五に、EAGLE-3とDFlashの二方式を組み合わせるため、別の草稿方式や異なる目標モデルへ適用する場合はルーティング特徴、切替費用、KVキャッシュの状態管理を再設計する必要がある。提案の主な実証範囲はこの二つの草稿器の組合せであり、任意の草稿器集合に対する最適選択を保証するものではない。
