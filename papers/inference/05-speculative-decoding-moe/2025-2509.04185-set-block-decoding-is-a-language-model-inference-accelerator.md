# Set Block Decoding is a Language Model Inference Accelerator

> 次トークン予測とマスク位置予測を同一Transformerへ統合し、未来ブロックの非連続位置をEB-Samplerで並列確定するSBD。8Bモデルで品質を概ね維持しながら前向き計算回数を約3〜5倍削減し、H100屋根線モデルで実時間化の可能性を分析する。

## 概要

通常の自己回帰型大規模言語モデル（Large Language Model; LLM）は、位置 (t) のトークンを確定してから位置 (t+1) を予測する。鍵・値キャッシュ（Key-Value cache; KVキャッシュ）によって過去部分の再計算は避けられるが、生成を1トークン進めるたびに巨大なモデル重みを読む前向き計算が必要になる。この逐次性がデコードの主要な律速である。

投機的復号（speculative decoding）は小さなドラフトモデルに数トークン先読みさせ、対象モデルがまとめて検証することで前向き回数を減らす。ただし候補列は基本的に先頭から連続して受理され、前の候補が外れると、その後ろに正しい候補があっても利用しにくい。並列な複数トークン予測（multi-token prediction）も、未来位置同士の依存を十分に表現しなければ品質が落ちる。

集合ブロック復号（Set Block Decoding; SBD）は、未来の (k) トークンを「左から順にしか決められない列」ではなく、**一部だけ確定済みでも残りを再予測できる集合**として扱う。同じTransformerに、通常の次トークン予測（Next Token Prediction; NTP）と、未来ブロック内のマスク位置予測（masked token prediction）を同時に学習させる。確定済み過去には因果的注意（causal attention）、現在の未来ブロックには双方向注意（bidirectional attention）を用いる。

推論時にはエントロピー制約サンプラー（Entropy Bounded Sampler; EB-Sampler）が、予測分布のエントロピーが低い位置から複数を選び、非連続位置でも同時に確定する。ブロック全体が完成した時点で、それを通常の因果的履歴としてKVキャッシュへ固定する。これにより、マスク拡散型復号（masked diffusion decoding）の柔軟な確定順序と、自己回帰LLMのKVキャッシュを両立する。

Llama-3.1 8BとQwen-3 8Bを70Bトークンで追加学習した評価では、低い閾値設定で自己回帰ベースラインの品質を概ね維持しながら、必要なモデル前向き計算回数（number of function evaluations; NFE）をベンチマーク依存でおおむね3〜5倍削減した。ただし表の「高速化」は主としてNFE比であり、実測壁時計時間ではない。論文はH100を仮定した屋根線モデル（roofline model）で、ブロック長16なら1回のブロック前向き計算の追加費用が小さく、NFE削減が理論上ほぼ同じ倍率の壁時計時間短縮へ転化し得ると分析している。

## 問題設定

### 独立な未来予測では、トークン間依存を落としてしまう

未来の複数位置を一度に予測する最も単純な方法は、各位置を過去の接頭辞だけから独立に予測することである。しかし言語では未来トークン同士が強く依存する。たとえば後続語が何になるかは、同じブロック内で先に決まった固有名詞や構文に左右される。

SBDは、未来ブロックの一部集合 (mathcal{J}) がすでに確定している場合、残りの位置 (i) を
(p(x_i mid x_{<t}, x_{mathcal{J}}))
として再予測する。したがって、一度に全位置を独立確定するのではなく、依存が弱いと見込まれる位置だけを並列に進め、難しい位置は後の反復へ残せる。

### マスク型並列復号はKVキャッシュと衝突しやすい

通常のマスク拡散型モデルは、未確定位置を何度も更新する。そのまま自己回帰Transformerへ持ち込むと、過去全体の内部状態まで毎回再計算する必要が生じ、KVキャッシュの利点を失う。

SBDは系列を「確定済みの因果的接頭辞」と「現在だけ書き換える未来ブロック」に分ける。過去側は不変なのでKVキャッシュでき、ブロック側だけを双方向に再計算する。ブロック完成後はその内容を二度と変更せず、次の因果的履歴へ昇格させる。

## 処理の流れ

1. 接頭辞を通常の自己回帰Transformerとして事前充填（prefill）し、KVキャッシュを作る。
2. 次の (k) 位置をすべてマスクトークンで初期化する。
3. 接頭辞は因果的注意、現在ブロックは双方向注意で1回前向き計算し、全マスク位置の分布を得る。
4. EB-Samplerが低エントロピー位置を選び、累積エントロピーが閾値 (gamma) を超えない範囲で複数位置を同時確定する。
5. 未確定位置が残れば、今確定した非連続位置を条件としてブロックを再計算する。
6. ブロック全位置が確定したら因果的履歴へ追加し、次のブロックへ進む。

この設計では、1反復で何トークン進めるかは固定ではない。モデルが自信を持つ位置が多いブロックでは一気に進み、依存が強いブロックでは慎重に反復する。

## 手法

### 1. 因果的接頭辞と双方向未来ブロックを同じTransformerで扱う

SBDは別のドラフトネットワークや追加ヘッドを必要としない。区切りより左の確定済みトークンには通常の因果的注意を、右側の未来ブロックには双方向注意を適用する。

未来位置は実トークンまたはマスクトークンを取れるため、「1番目と3番目は確定、2番目と4番目は未確定」のような状態を表現できる。1回の前向き計算から未確定位置すべてのロジットが得られ、既知になった未来位置を次反復の条件に利用できる。

### 2. NTP損失を残したままマスク予測能力を追加する

学習では各系列についてマスク率を一様分布からランダムに選び、ブロック内の一部をマスクする。損失は通常のNTP損失と、マスクされた未来位置を復元する損失の和である。

NTP損失を残す理由は、並列復号能力を加えても元モデルの自己回帰能力を失わないためである。3Bモデルの構成要素除去実験では、最後の100BトークンをSBD学習する際にNTP損失を外すと、MMLUが50.9から43.2、ARC-Easyが71.2から58.8へ大きく低下した。完全なSBD損失ではそれぞれ49.9、69.9にとどまり、NTP項が自己回帰能力の保持に必要だと分かる。

8B評価では学習ブロック長を2〜16から毎ステップ一様に選ぶ。これにより単一の固定ブロック長へ過度に依存しないようにする。

### 3. EB-Samplerで依存の弱い位置だけをまとめて進める

本来、複数位置を独立に同時確定してよいかを知るには位置間の相互情報量（mutual information）が必要だが、完全な同時分布を計算するのは現実的でない。EB-Samplerは各位置の周辺分布エントロピーを上界として使う。

未確定位置をエントロピーの低い順に並べ、累積エントロピーが閾値 (gamma) 以下に収まる最大集合を同時に確定する。最低1位置は必ず進める。(gamma) が小さいほど慎重で品質を保ちやすく、大きいほど1反復の確定数が増えるが誤った独立近似による品質低下が増える。

この単一閾値がSBDの速度・品質交換条件（speed-quality trade-off）を制御する主要パラメータである。

### 4. 「連続した先頭」ではなく非連続位置を先に確定できる

投機的復号では、候補列の先頭で不一致が起きると、その後ろの候補を通常は捨てる。SBDではブロック先頭が難しくても、後方の低エントロピー位置を先に確定できる。

次の反復では、その後方トークンも条件に含めて難しい位置を再予測する。したがって並列性は「連続して何トークン正解できるか」だけに依存しない。ここがSBDと通常のドラフト・検証型投機的復号の最も重要な差である。

### 5. ブロック境界でKVキャッシュを正確に固定する

現在ブロックは双方向注意を使うため、ブロック内部のKV状態はマスク解除のたびに変わる。一方、前のブロックまでの接頭辞は確定済みなので再計算不要である。

推論アルゴリズムは、各新ブロックの最初の反復で直前までのKVキャッシュを再利用し、現在ブロックだけを処理する。全位置が確定したら、その完成ブロックを因果的履歴へ追加する。この境界によって、マスク復号の反復費用を現在ブロックへ閉じ込める。

「3〜5倍」は全ベンチマークで固定の値ではない。低閾値でも約2.2倍から3.9倍程度までばらつき、高閾値では5倍を超える条件がある一方、品質低下が大きくなる。

### NFE削減は壁時計時間と同じではない

SBDの各前向き計算は1トークンではなくブロックを同時処理するため、1回あたりの計算量はNTPより大きい。論文はH100について、FP8演算性能1978 TFLOP/s、注意計算はBF16 989 TFLOP/s、メモリ帯域3.35 TB/sを仮定した屋根線モデルでこの追加費用を推定する。

8B相当モデル、ブロック長16では、バッチ1の1回のブロック前向き時間は単一トークン前向きの約1.004倍、バッチ4でも約1.015倍と推定される。この領域ではメモリ帯域律速が強く、同時に16トークンを扱っても重み読出し費用が支配的なため、NFE削減が理論上かなり直接的に壁時計時間へ転化する。

ただしバッチやブロックを大きくすると計算律速へ移り、収益逓減が生じる。論文自身も、実際のハードウェア向け実装で屋根線分析を再現することを将来課題としている。したがって本サーベイでは「実測3〜5倍高速化」ではなく、「NFEを約3〜5倍削減し、H100理論モデルで近い壁時計短縮を見込む」と記録する。

## 既存研究との差

投機的復号は別のドラフトモデルまたは追加ヘッドから候補を作り、対象モデルの検証で分布を保つ。候補列は先頭からの連続受理に強く依存する。

マスク拡散型言語モデルは任意順序で位置を確定できるが、系列全体を反復更新するため、自己回帰モデルの正確なKVキャッシュをそのまま活用しにくい。

SBDは**自己回帰NTP能力を残した一つのTransformer**に、現在ブロックだけのマスク復号能力を追加する。非連続位置を先に確定しながら、ブロック境界では通常の因果的KVキャッシュへ戻る点が両者の中間にある。

## 限界・実装状況

SBDは無学習の推論最適化ではない。8B実験では70Bトークン規模の追加学習を行っているため、任意の既存チェックポイントへ即座に適用できる方式ではない。

EB-Samplerは位置間依存を直接計算せず、周辺エントロピーを用いた上界で近似する。複数の低エントロピー位置が実際には強く依存している場合、同時確定による品質低下が起こり得る。高い (gamma) でAIME25等が悪化する結果はこの交換条件を示す。

また、主評価の高速化指標はNFEである。vLLMやSGLangのような配信ランタイム（serving runtime）に統合した初回トークン遅延（Time To First Token; TTFT）、1トークン当たり時間（Time Per Output Token; TPOT）、連続バッチ処理（continuous batching）、複数利用者スループットは報告されていない。

ブロック内双方向注意とマスク更新を実際のGPUカーネルへ効率良く落とせるか、バッチが大きい本番配信で屋根線モデルどおりの利得が残るかは未検証である。

## 一般的な実装上の含意

並列復号を評価するときは、「1回のモデル呼出しで何トークン進むか」と「その1回が単一トークン復号より何倍重いか」を分離して測る必要がある。SBDは前者で大きな改善を示す一方、後者は理論モデルで評価している。

また、投機的復号のように連続候補だけを使う設計では、先頭の難しい位置が並列性を制限する。非連続位置を先に確定できる形式は、その制約を外す別の設計点を示している。ただし依存を無視した並列確定は品質と交換条件になるため、実装では (gamma) とサービス水準目標（Service Level Objective; SLO）を同時に調整する必要がある。
