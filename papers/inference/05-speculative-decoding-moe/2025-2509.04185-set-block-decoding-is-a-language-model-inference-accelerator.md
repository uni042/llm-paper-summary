# Set Block Decoding is a Language Model Inference Accelerator

> NTPとblock内masked predictionを1 Transformerへ統合し、entropyの低い非連続な未来位置を並列確定してforward回数を3〜5倍減らすSBD。

## 概要

通常の自己回帰LLMは、時刻tのtokenを確定しないとt+1を生成できない。デコードでは1 tokenごとに巨大なmodel weightとKV cacheを読み、forwardを繰り返すため、GPU上では「1 forwardで1 tokenしか進めない逐次性」が大きな律速になる。

投機的復号は小型draft modelに複数tokenを先読みさせ、target modelが連続prefixをまとめて検証する。しかし候補列に誤りが1つあると、それ以降の候補は正しくても通常は捨てられる。Medusaなどのmulti-token headも複数未来tokenを独立予測できるが、最終的には「先頭から連続して何token受理できるか」という制約を強く受ける。

Set Block Decoding（SBD）は、ここを**未来block内のtokenを任意の順序で確定してよい問題**へ変える。同じTransformerに通常のNext Token Prediction（NTP）とMasked Token Prediction（MATP）を同時学習させ、確定済みprefixの後ろにk個の未来位置を置く。未来block内では、一部tokenが既に分かっていて他が[MASK]という任意状態から、残り位置の分布を同時に予測できる。

この柔軟性により、block先頭がまだ不確かでも、後方の「確信度が高く、互いの依存が弱そうな位置」を先に複数確定できる。論文ではmasked diffusionで使われるEntropy Bounded（EB）Samplerを利用し、予測entropyが低い位置をまとめてunmaskする。block全体が完成すると、そのblockは通常のcausal historyとしてKV cacheへ固定され、次blockへ進む。

Llama-3.1 8BとQwen-3 8Bを70B tokenでfine-tuneした評価では、同じtraining data・条件で学習したNTP baselineと同等のtask性能を保ちながら、低い(gamma)設定で生成に必要なmodel forward数をbenchmark依存で3〜5倍削減する。ここでのheadlineは**forward回数削減**であり、専用kernelまで含むwall-clock speedupと同一ではない。

## 問題設定

### なぜ「複数tokenを独立予測」するだけでは不十分なのか

未来k tokenの真の同時分布

[
p(x_t,ldots,x_{t+k-1}mid x_{<t})
]

をそのまま表現しようとすると、語彙数Vに対して状態数は (V^k) になり現実的でない。そのため従来のparallel block decodingは各位置の周辺分布

[
p(x_imid x_{<t})
]

を独立に予測する近似を使う。

しかし実際の文章では未来token同士が依存する。「New」の次が「York」である可能性は、同じblock内の別位置が何であるかに左右される。未来位置をprefixだけから完全独立に予測すると、この依存を表現できない。

SBDは、block内で既に確定した任意subset (x_mathcal{J}) を条件にし、

[
p(x_imid x_{<t},x_mathcal{J})
]

として残りmaskを予測する。1回ですべて独立確定するのではなく、**依存の弱い位置を並列に、依存の強い位置は後のiterationへ残す**。

### diffusion的samplingと通常LLMのKV cacheをどう両立するか

Masked diffusion型modelは系列全体を何度も書き換えるため、通常のAR LLMの「過去tokenは不変なのでKVを一度だけ計算する」というcache方式と相性が悪い。

SBDは系列全体を拡散させず、**確定済みprefixはcausal attentionで不変、現在の未来blockだけbidirectional attention**にする。block内のmask状態は何度か更新しても、block完成後は二度と変更しない。この境界により、完成済みblockのKVは正確なcacheとして次blockで再利用できる。

## 手法

### 1. 1つのTransformerにcausal prefixとbidirectional future blockを同居させる

SBD modelは通常のNTP入力では、従来Transformerと同じcausal attentionを使う。一方SBD modeでは、prefix (x_{<t}) の後ろにk位置のfuture blockを置き、その部分だけbidirectional attentionを許す。

future block内の各位置は実tokenまたは特殊mask token `m` を取れる。したがって「位置1,3は既に確定、2,4だけmask」といった任意subset状態から、mask位置すべてのlogitsを1 forwardで得られる。

model architecture自体へdraft headを足すのではなく、attention maskとtraining objectiveを変えて同じparameter setへ2種類の能力を持たせる。

### 2. NTP lossとmasked-token lossを同時に学習する

各training sequenceからrandom mask率 (etasim U(0,1)) を引き、future block内の一部tokenをmaskする。

lossは
- 全通常位置に対するNTP loss
- block内でmaskされた位置に対するMATP loss

の和である。

NTP objectiveを残すため、SBD化したmodelは通常の1-token decoding能力も維持する。論文は同じdata・optimizerでNTP-only baselineも学習し、SBD lossを足してもbenchmarksの能力が大きく落ちないことを確認する。

trainingではblock sizeを固定せず2〜16から毎step sampleし、推論時に異なるblock長へ対応できるようにする。

### 3. Entropy Bounded Samplerで「今まとめて決めてよい位置」を選ぶ

推論開始時、future blockのk位置はすべてmaskである。1 forwardで各mask位置のprobability distributionを得た後、entropyが低い位置ほど「modelの迷いが小さい」とみなす。

EB-Samplerはmask位置をentropy昇順に並べ、累積entropyがthreshold (gamma) 以下になる最大個数sを一度にunmaskする。少なくとも1 tokenは毎iteration確定する。

(gamma) が小さいと慎重になり、同時確定数が減る代わりにNTP baselineに近いqualityを維持しやすい。(gamma) を大きくするとより多くの位置を一度に確定しforward数を減らせるが、互いに依存したtokenを独立にsampleする近似が強くなりquality低下が出やすい。

この(gamma)が、SBDのspeed-quality trade-offを操作する推論時の主要knobである。

### 4. 位置は連続していなくてよい

従来のspeculative verificationでは、候補 ([x_t,x_{t+1},x_{t+2},...]) を先頭から検証し、x_tでrejectすれば後ろを使えない。

SBDではfuture blockのうち位置t+1とt+3だけ先に確定し、tとt+2はmaskのまま残すこともできる。次forwardでは既知になったt+1/t+3をcontextへ使って、残る位置をより正確に予測する。

この**非連続future tokenの先行確定**が、SBDを単純multi-token predictionやdraft-target speculative decodingと区別する中心である。

### 5. block完成後だけexact KV cacheへcommitする

最初のSBD iterationでは、前blockの確定tokenをKV cacheとして再利用し、現在blockのmask tokenだけを追加計算する。

current block内ではbidirectional relationshipが変わるため、maskをunmaskするたびにblock部分は再forwardする。しかしprefix側のKVは変更しない。全k tokenが確定した時点でcurrent blockをcausal historyへcommitし、そのKVを次blockで再利用する。

この設計により、masked diffusionの柔軟なunmask順序を使いつつ、過去全tokenを毎iteration再計算する必要を避ける。

## 評価

### 代表的な評価条件

| 項目 | 内容 |
|---|---|
| base models | Llama-3.1 8B、Qwen-3 8B |
| fine-tuning量 | 70B tokens |
| context length | 32K |
| training block size | 2〜16をuniform sampling |
| reasoning | AIME25、MATH500、LiveCodeBench v6 |
| chat/code | GSM8K、HumanEval+、MBPP |
| reasoning生成 | thinkingあり、最大32K tokens |
| sampling | EB-Sampler、temperature 0 |
| 比較 | 同一data/optimizerで学習したNTP baseline |
| 主効率指標 | NTPに対するmodel forward数削減 |

「3〜5倍speedup」という表現は、論文では主に**同じ長さの生成に必要なforward回数の比**を指す。GPU kernelやblock内bidirectional attentionのwall-clock costがNTP forwardと完全に同じではないため、そのまま3〜5倍の実時間短縮と読むべきではない。

### Llama-3.1 8Bの例

NTP baselineはMATH500 80.2、AIME25 33.3、LiveCodeBench v6 31.5、GSM8K 85.3、HumanEval+ 56.7、MBPP 70.4を示す。同じtrainingでSBD lossを加えたmodelを通常NTP samplingすると81.6/30.0/31.3/85.6/57.9/70.9で、model能力そのものは概ね同じ範囲に保たれている。

EB-Samplerの低(gamma)側では、task性能をNTPへ近く保ちながらbenchmark依存で約3〜5倍forward数を減らす。高(gamma)ではさらにforward数を減らせる一方、AIME25などでaccuracy低下が大きくなる。

この結果は「MATP学習だけでmodelが高性能化した」というより、**NTP能力を保った同じmodelから、推論時だけparallel unmaskを選べる**ことを示す。

### 何を評価していないか

論文の中心はforward-count reductionとtask qualityであり、vLLM/SGLang等のproduction serving engineへ統合したTTFT/TPOT、continuous batching、multi-user throughputの評価は主張の中心ではない。

そのため実配備では、SBD block内のbidirectional attention、mask更新、KV commitをoptimized kernelでどう実装するかが、forward数削減をwall-clock speedupへ変換する次の課題になる。

## 既存研究との差

Speculative decodingはdraftとtargetの2 modelを持ち、targetが連続prefixをverifyする。Medusa等はtargetへ複数headを追加してfuture tokenを並列予測するが、候補の関係は主にprefix acceptanceで扱う。

Masked diffusionは任意順序でtokenをunmaskできるが、通常は最終generator全体をdiffusion processとして設計する。

SBDは**1つのNTP Transformerを維持したまま、現在のfuture blockにだけmasked-diffusion sampling能力を足す**。NTPとMATPを同じparameterへ学習し、block境界でexact causal KV cacheへ戻るため、AR LLMの強い性能とdiffusion solverの並列性を橋渡しする。

## 限界

SBDは既存NTP checkpointへfine-tuneできるが、70B token規模の追加学習を行っており「推論時に無学習で後付け」できる方式ではない。

EB-Samplerはentropyをtoken間依存の上界として使う近似であり、低entropyな複数位置が実際には強く依存している場合、同時unmaskがqualityを落とし得る。(gamma)を上げるほどこの危険が増える。

またblock内はbidirectional attentionなので、通常causal decodeと同じkernel pathをそのまま使えるとは限らない。forward数3〜5倍削減が実時間3〜5倍を保証しない点は、システムサーベイ上特に区別すべきである。
