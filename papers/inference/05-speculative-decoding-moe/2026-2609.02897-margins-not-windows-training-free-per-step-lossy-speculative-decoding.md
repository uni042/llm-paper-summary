# Margins, Not Windows: Training-Free Per-Step Lossy Speculative Decoding

## 概要

自己回帰LLMは次トークンを前トークンの計算後にしか出せず、生成長に比例してtargetモデルの順伝播が必要になる。投機的復号は小さなdraftモデルに複数トークンまたは候補木を作らせ、targetモデルがまとめて検証することでこの逐次性を緩める。しかし既存方式には、トークンが完全一致しなければ拒否する固定の無損失検証と、推論中に同じ木形状を使う固定の候補計算予算という二つの制約がある。AdaptiveSpecはこの二点を、targetモデル/draftモデルがデコード中に既に出す確率・受理信号だけでステップごとに変える。

代表結果として、単一A100上の主評価で両軸併用方式は9条件すべてでEAGLE-3を上回り、モデル平均の高速化倍率は16–44%、最大改善は56%だった。課題正解率の回復率は課題ごとに異なり、近似検証器は出力分布の保存を保証しない。

## 問題設定

EAGLE-3の木構造候補生成では、一回の候補生成段階で深さn_steps、各節点の分岐数top-k、target検証に渡す節点数ndtを使って候補を組み立てる。固定構成では、容易なステップにも難しいステップにも同じ形と量のdraft計算を費やす。加えて厳密検証器は最初のdraft-target間のトークン不一致でdraftの続行を捨てるため、targetモデル側が候補トークンにも高い確率を割り当てている「僅差」の不一致まで同じように拒否する。

FLyは学習不要の近似検証器として先読み窓内の追加不一致の有無を使うが、窓の長さがdraft候補列に対して長すぎると、受理済みの候補列が窓を満たさない。著者らのEAGLE-3評価では厳密構成(3,1,4)の平均受理長τはモデル平均でLlama-3.1-8Bが2.49、Qwen3-8Bが2.23、DeepSeek-R1-8Bが3.05。FLyの標準窓w=6に届かないため、同方式の前提が浅い木構造候補生成と噛み合わない。もう一つの系統TALONは木の幅と深さを信頼度で適応するが、総節点予算を固定して幅・深さへ再配分する。AdaptiveSpecは検証条件を緩める軸と候補計算量を変える軸を別々に扱い、一つのステップ内で併用する。

## 手法

### 不一致位置での確率比による検証

厳密な復号は最初の不一致位置jで候補トークンを拒み、targetモデル側で通常どおり次トークンを生成する。AdaptiveSpecはその位置でtargetが候補トークンに与えた確率を、targetモデルのtop-1トークンの確率で割る。

`margin(j) = p_target(draft_j) / p_target(top1_j)`、値域は[0,1]。

marginが全体共通閾値κ以上なら、top-1と候補トークンが異なっても候補トークンを採用する。κが高いほど厳しくなり、targetが候補トークンにも十分な確率を付けた僅差だけを通す。targetの検証パスが保持する確率だけを使い、別の学習済み判定器を要さず、後続トークンの先読みやdraft候補列の長さにも依存しない。これは確率分布を保つ通常の投機的サンプリング検証器と異なる、意図的な近似検証である。

### 候補木のステップ単位適応

draft信頼度指標は、当ステップでのdraftモデルのtop-1 softmax確率と、targetが過去の候補トークンを受理した比率の指数移動平均（受理率EMA、α=0.3）を掛けて得る。スコアを除数dで規格化し、dに達すると1へ飽和させる。スコアが高いステップでは深さを増やし分岐を減らした候補列、低いステップでは浅く広い候補木を選ぶ。n_stepsとtop-kを反対向きに線形補間し、ndtも設定候補に含めて、(3,4,4)から(7,1,8)の構成範囲を選ぶ。この両端は同じ総トークン予算ではないので、弱いdraftのステップでは候補計算量自体を抑え、強いステップでは深く検証する計算を増やせる。5ステップ連続で受理トークンが0なら、その要求は初期構成へ戻す。

SGLangはCUDA計算グラフ向けにtensor shapeを静的にするため、著者らは方策が選べる各(n_steps, top-k, ndt)の計算グラフを起動時に事前作成し、デコード中に切り替える。候補生成段階の形状選択と検証段階のmargin判定は異なる箇所で動くため、組み合わせ時に各効果が積み上がるという設計である。追加の判定器・学習を使わないことは著者らの説明であり、性能測定は後述の実験条件内のものに限られる。

### 既存法との差と実装上の比較条件

EAGLE-3は無損失の固定候補木、TALONは無損失の適応型候補木、FLyは固定候補木と近似検証を組み合わせる比較方式である。TALONとFLyは、元論文の公開SGLang実装をそのまま使った比較ではない。著者らがEAGLE-3のdraftモデルを使い、同じ実行基盤内で再実装した。

FLy本来のw=6と15–25トークンの候補列は深いdraft列を前提とする。軽量draftモデルで同じ長さにすると候補品質が下がるという先行報告があるため、著者らはEAGLE-3の短い受理長に合わせて、この実験ではw=3、7ステップの候補列へ調整した。したがってFLyとの結果は、この再実装・調整条件での比較である。

## 評価

### 実験条件

- Target / draftモデル: Llama-3.1-8B-Instruct / lmsys EAGLE-3 Llama 8B、DeepSeek-R1-Distill-Llama-8B / EAGLE-3 DeepSeek 8B、Qwen3-8B / AngelSlim EAGLE-3 Qwen3-8B。
- 評価課題: GSM8KとMATH-500数学推論、HumanEval code generation。
- 主評価: SGLang + SpecForge、単一NVIDIA A100 80 GB、バッチサイズ1、貪欲復号 T=0。各手法・モデル・評価課題の条件はA100で2–6時間と記載。
- 比較方式: EAGLE-3の厳密な固定木(3,1,4)、同じ実行基盤・draftモデルで再実装したTALONとFLy。高速化倍率は通常の自己回帰復号に対する比。τは平均受理トークン長、Rec.%は無損失EAGLE-3に対して保たれた課題正解率。
- AdaptiveSpecは近似検証の全条件で共通κ=0.2。木形状適応のみはd=0.5。近似検証のみは固定候補列(7,1,8)、併用方式は(3,4,4)↔(7,1,8)とd=0.5。

### 主結果

併用方式の処理量の高速化倍率とEAGLE-3に対する正解率回復率（Table 1）は次の通り。数値は著者らが報告した相対高速化倍率 / 回復率であり、絶対トークン/sではない。

| Target | Task | 高速化倍率（通常の自己回帰方式比） | 回復率（無損失EAGLE-3比） |
|---|---|---:|---:|
| Llama-3.1-8B | GSM8K | 2.43× | 94% |
|  | MATH-500 | 2.15× | 90% |
|  | HumanEval | 2.82× | 103% |
| Qwen3-8B | GSM8K | 1.95× | 99% |
|  | MATH-500 | 1.74× | 82% |
|  | HumanEval | 1.82× | 104% |
| DeepSeek-R1-8B | GSM8K | 3.20× | 97% |
|  | MATH-500 | 2.97× | 98% |
|  | HumanEval | 2.74× | 88% |

全9条件で併用方式がEAGLE-3より速く、改善幅は12–56%。最大はLlama-3.1-8B + HumanEvalの2.82×対1.81×、+56%、正解率回復率103%。モデル平均の高速化倍率はLlama 2.47×対1.71×（+44%）、Qwen3 1.84×対1.58×（+16%）、DeepSeek 2.97×対2.16×（+38%）。回復率が100%を超える評価条件は、無損失EAGLE-3との課題正解率比がその測定で100%を上回ったことを表し、近似検証方式が一般に品質を改善する保証ではない。

要因分離では、3モデル・3課題の平均で木形状適応のみがEAGLE-3の1.82×から2.21×へ+21.4%、正解率回復率100%。固定木の近似検証のみは2.10×へ+15.4%で回復率93%。木形状適応と近似検証の併用方式は2.42×、回復率95%となり、平均値が最良だった。確率比による検証の単独比較はFLyより9条件中8条件で高速だが、例外のDeepSeek-R1-8B + MATH-500では1.80×対FLy 2.57×と低い。したがって、二軸の併用は全課題でどの基準方式にも常に勝つという意味ではない。

### 感度・バッチ・サンプリング・分散

Draft Confidenceの除数はd=0.2–0.5で比較され、木形状適応のみの9 条件全てでd=0.5が最速だった。marginのκ 条件別測定は閾値を下げるほど高速化倍率が増えて回復率が下がる傾向で、著者らはκ=0.2を3モデル共通の折衷として固定した。これは評価対象で選んだ値で、未評価モデルへの普遍最適を示すものではない。

バッチサイズ1–16では高速化倍率が小さくなる傾向がある。付録DのLlama MATH-500ではバッチサイズ4以上でEAGLE-3がAdaptiveSpecを上回る。Qwen3ではバッチサイズ16時にEAGLE-3がGSM8KとMATH-500でわずかに上回り、HumanEvalではほぼ同等。DeepSeekでは報告された全バッチ・課題条件でAdaptiveSpecが上回る。高バッチで常に優位とは主張できない。

Llama-3.1-8BのT=1・3 seed評価でも併用方式はEAGLE-3より高速化倍率がGSM8Kで+16%、MATH-500で+41%、HumanEvalで+17%。高速化倍率はそれぞれ1.91±0.07×、1.56±0.06×、2.29±0.07×、回復率は98.1±2.2%、94.6±3.1%、93.2±2.0%。貪欲復号条件を各条件で3回独立実行した付録Fでは処理量のばらつき幅は最大1.8%。貪欲復号では生成列が決定的なため正解率とτは一致し、処理量のみ平均±標準偏差で示す。

## 既存研究との差

投機的復号本来の厳密な受理はtargetの出力分布を保存する。AdaptiveSpecのmarginによる候補採用はこの理論保証を意図的に外し、targetが候補トークンにも高確率を持つケースを処理量優先で採用する方式であり、論文は課題正解率の回復率を実測で報告する。外部判定器を学習する先行法が判定モジュールの学習を行い、FLyがエントロピーによるゲートと後続窓で自己修正を推定するのに対し、AdaptiveSpecは不一致箇所のtarget確率のみを見る。木形状側ではTALONが固定予算内で節点数を幅・深さ間に再配分するのに対し、AdaptiveSpecは候補木構成の候補総数も変え、候補計算量をステップごとに伸縮させる。

リポジトリの既存投機的復号群にあるEAGLE-3を直接のdraftモデルおよび基準方式として、適応型候補木と近似検証を一つのSGLang実験へ接続した研究である。既存のEAGLE-3本文とTALON・FLyの一次論文を踏まえると、「同じEAGLE-3 draftモデル、同じSGLang」で再実装した条件における統合効果が主な追加点となる。既存実装を置き換えた実運用全体の比較や別実行基盤への移植を示したものではない。

## 限界

1. marginを用いた近似検証器はtargetモデルの確率分布を形式的に保たない。正解率回復は3課題上の実測値で、評価外課題では異なりうると著者ら自身が述べる。
2. 実験対象はEAGLE-3のdraftモデル、3種類の8B級target、3つの評価課題。DFlashやDDTree等の拡散型候補木での結果はなく、移転可能性は今後の検証課題。
3. 主表は単一A100 80 GB、バッチサイズ1、貪欲復号での結果。T=1はLlama一モデル、バッチサイズ別の測定は3モデルだが、バッチ拡大で利得が薄れ基準方式が勝つ条件もある。したがって、多GPU、CPU、他ハードウェア、実運用の負荷へそのまま一般化できない。
4. FLy/TALONは著者らによるSGLang再実装であり、特にFLyの窓を本来の6から3へ調整した。基準方式順位にはこの実装・設定差が影響しうる。
5. 論文はSGLang上の実装と実験を報告するが、arXiv書誌・本文で公開code repository URLを示していないため、第三者による実装再現性はそこからは確認できない。
