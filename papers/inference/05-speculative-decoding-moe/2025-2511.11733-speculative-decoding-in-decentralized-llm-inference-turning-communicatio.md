# Speculative Decoding in Decentralized LLM Inference: Turning Communication Latency into Computation Throughput

## 概要

通常の投機的復号は小さなドラフトモデルが複数トークンを提案し、大きな対象モデルが一括検証することで対象モデル呼出し回数を減らす。DSDはこの考えを、GPU間がNVLinkで密結合されたサーバではなく、ネットワーク遅延が支配的な分散・分権型推論へ適用する。

モデルを複数ノードへ分割した自己回帰推論では、1トークンごとにノード間同期が必要になる。DSDは一度の通信ラウンドで複数候補トークンを検証し、待ち時間の間に有用な計算を進める。さらに重要度の低いトークンだけ受理条件を緩め、平均受理長を増やす。

## 問題設定

Nノードを直列に跨ぐ標準復号では、kトークン生成に各トークンの局所計算 t0 と(N-1)回のリンク遅延 t1 が繰り返される。広域・一般ネットワークではt1が大きく、GPUが計算せず待つ時間が支配的になる。

中央集約型の投機的復号をそのまま使っても、分散対象モデルの各検証で通信同期が残る。必要なのは受理トークン数kを増やし、通信回数そのものをkトークンに一回へ償却することである。

## 手法

DSDでは軽量ドラフトモデルが候補列を作り、分散配置された対象モデルが複数候補を一括検証する。標準方式の概算時間 k(t0+(N-1)t1) に対し、DSDは k t0+(N-1)t1 として通信項を一ラウンドへまとめる。kが大きく、通信遅延が計算より大きいほど効果が増える。

受理率を高めるため、適応投機検証を導入する。ドラフトと対象モデルの不確実性・意味的重要度をトークン単位で調べ、重要なトークンには厳しい一致条件を維持し、意味影響が小さいトークンでは閾値を緩和する。これにより対象モデルの品質誘導を残しながら、候補列の早期棄却を減らす。

この方式はモデル重みやアーキテクチャを変更せず、推論時のドラフト・検証・同期手順だけを変える。そのため既存の分散推論エンジンへ追加できることを狙う。

## 評価

| 観点 | 条件・結果 |
|---|---|
| モデル | Llama3.1-8B、Qwen3-8B |
| エンジン | Parallax系の分散推論 |
| ハードウェア | NVIDIA A800、4〜8ノード |
| タスク | HumanEval、GSM8K、CNN/DailyMail、AlpacaEval等 |
| HumanEval | 最大2.56倍高速化 |
| GSM8K | 最大2.59倍高速化 |
| AlpacaEval | 約2.34倍の条件、平均受理長3.59対Eagle3 2.79 |
| 8ノード通信 | 約37%削減 |
| 適応検証 | 固定検証から追加15〜20%のエンドツーエンド高速化 |

速度向上はネットワーク遅延が十分大きいほど増え、低遅延相互接続では通信償却の価値が小さくなる。論文はHumanEval/GSM8Kで精度を維持したままEagle3を上回ると報告する。

## 既存研究との差

Eagle系を含む投機的復号は主に一台または高速相互接続クラスタ内の対象モデル計算削減を狙う。DSDは計算量だけでなく「同期回数」を主要目的変数にし、投機窓をネットワーク往復の償却単位として使う。適応検証も受理率だけでなく、通信ラウンド当たりの有効トークン数を増やすために位置付けられる。

## 限界・実装状況

通信が支配的でない単一GPU・NVLink環境では理論上の利得が縮む。閾値緩和は品質との交換条件を持つため、重要トークン判定が外れる分布では品質低下の可能性がある。評価は8B級モデルと最大8ノードが中心で、数十〜数百ノードや超大規模MoEへのスケーリングは別途検証が必要である。
