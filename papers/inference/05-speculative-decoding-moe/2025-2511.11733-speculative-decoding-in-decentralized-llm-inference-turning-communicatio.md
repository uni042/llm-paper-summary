# Speculative Decoding in Decentralized LLM Inference: Turning Communication Latency into Computation Throughput

## 概要
Decentralized Speculative Decoding（DSD）は、投機的復号（speculative decoding）の目的を「対象モデルの計算回数削減」だけでなく「分散ノード間の同期回数削減」へ拡張した推論方式である。一般的な投機的復号は、小さいドラフトモデルが複数トークンを提案し、対象モデルがまとめて検証することで逐次復号の対象モデル呼び出しを減らす。しかしモデル自体が複数の独立ノードへ分割され、各復号ステップでノード間通信が必要な環境では、計算を減らしてもネットワーク往復待ちが残る。

DSDは、ドラフト窓内の複数候補を分散した対象モデルでまとめて検証し、受理された連続トークンを一回の同期でコミットする。これにより、通信待ち時間を次の候補を処理する計算へ置き換え、通信遅延を複数トークンへ償却する。さらに、すべての候補へ同じ厳格な受理条件を課すのではなく、意味的影響が大きい「重要トークン」は厳格に検証し、影響が小さいトークンだけ検証分布を緩和する適応投機検証（adaptive speculative verification）を導入する。重み再学習やモデル構造変更は不要で、Parallax分散推論エンジンへ推論時機構として実装される。

## 問題設定
論文は、対象モデルの一回の局所計算時間を (t_0)、隣接ノード間の通信遅延を (t_1)、モデルを跨ぐノード数を (N) と置く。標準的な自己回帰復号では1トークンごとにモデル分割を跨ぐ同期が必要で、(k) トークンを生成する時間を概略
[
T_{std}=k{t_0+(N-1)t_1}
]
と表す。一般ネットワークや地理的に離れたノードでは (t_1) が (t_0) より大きくなり、GPUが計算せず通信を待つ時間が支配的になる。

DSDでは (k) 個の候補を一つの投機窓として対象モデルへ流し、一回の同期ラウンドで検証するため、
[
T_{DSD}=k t_0+(N-1)t_1
]
となる。通信項が毎トークンから毎窓へ減るため、(k) が大きく、かつ通信が計算より遅いほど利得が大きい。論文の分析では特に (3le Nle8)、(3t_0<t_1<10t_0) の通信律速領域で効果が大きい。一方、単一GPUや低遅延相互接続のように (t_1) が小さい環境では、追加のドラフト・検証処理を償却しにくい。

## 手法

### 1. 分散投機窓の一括検証
軽量ドラフトモデル (M_d) は長さ (gamma) の候補列を生成する。分散配置された対象モデル (M_t) は候補を順に一トークンずつ通信して確認するのではなく、窓全体を対象モデルの分割ノードへ流して一括検証する。先頭から (k) 個が受理された場合、その (k) 個をまとめてコミットし、その後に対象モデルから追加の1トークンを得て次の窓へ進む。

この設計で削減しているのは対象モデルの総浮動小数点演算（FLOPs）だけではない。分散推論では各トークンで発生する ((N-1)t_1) の同期費用が支配的になり得るため、通信回数を (k) トークンにつき一回へまとめること自体が主要な高速化要因になる。平均受理率を (ho=k/(gamma+1)) とすると、論文は期待高速化を
[

]
で整理し、受理長と通信償却の双方が性能へ効くことを示す。

### 2. 重要トークンの識別
投機窓を長くしても、ドラフトと対象モデルの分布差が大きければ途中で棄却され、平均受理長 (k) は伸びない。DSDは各候補トークンについて、ドラフトと対象の交差エントロピー比、予測確率差、上位候補分布の正規化一致度（NormMatch）を観測する。これらのいずれかが閾値を超えて分布差が大きいトークンを重要トークンとして扱う。閾値は小規模な検証集合で校正する。

重要トークンでは対象モデル分布をそのまま使い、通常の厳格な検証を行う。推論の意味や後続分布を大きく変えやすい位置まで緩和してしまうことを避けるためである。

### 3. 非重要トークンだけを緩和する適応検証
非重要トークンでは、対象分布 (P_t) とドラフト分布 (P_d) を緩和係数 (	au) で混ぜた
[
	ilde P_t(y_i)propto P_t(y_i)^{1-	au}P_d(y_i)^	au
]
を作り、この分布に対して受理判定する。重要トークンは常に (	au=0) とし、非重要トークンだけに小さい (	au) を使う。論文では0.1〜0.3程度の穏当な範囲を例示している。

この処理の目的は「品質を多少犠牲にして何でも受理する」ことではなく、対象モデルとドラフトモデルが実質的に近い非重要位置で過度に厳しい棄却を避け、通信一回あたりの有効トークン数を増やすことにある。追加統計は既に得られるロジットから計算するため、追加費用は標準復号に対する小さな定数倍に留まる。

## 評価

### 評価条件
実装はParallax分散推論エンジン上で行う。対象モデルはLlama 3.1 8BとQwen3-8Bで、各レプリカは4〜8ノードに跨る。各ノードはNVIDIA A800 80 GBを1基と100 Gbps InfiniBandを持つ。比較対象は通常の自己回帰復号、Eagle3、DSDである。

タスクはHumanEval（コード生成、pass@k）、GSM8K（数学推論、完全一致）、AlpacaEval（指示追従）、MT-Bench（対話）、CNN/DailyMail（要約、ROUGE-L）を含む。したがって単一の合成通信ベンチマークだけでなく、受理長と最終タスク品質を同時に確認している。

### 速度・受理長
横断比較ではDSDはEagle3より長い平均受理長を得る。例えばHumanEvalではEagle3が2.313倍・平均受理長3.340に対し、DSDは2.562倍・3.855、GSM8Kでは2.274倍・3.403に対し2.517倍・4.042となる条件が報告される。個別設定ではHumanEvalで最大2.56倍、GSM8Kで最大2.59倍の高速化を、精度を大きく崩さない設定で示す。

適応検証は非適応の投機復号に対し、最大で追加15〜20%のエンドツーエンド高速化を与える。これは重要度判定そのものが高速化するのではなく、非重要トークンの不要な棄却を減らして平均受理長を増やし、結果として同期回数を減らすためである。

### ノード数と通信削減
ノード数を2〜16へ変えるスケーリング実験では、8ノード時に標準投機復号に対して通信費を約37%削減する。ノード数が増えるほど一同期あたりの通信費は増えるため、複数トークンへ償却する価値も増える。ただし無制限に改善するわけではなく、受理長が短い場合や通信が十分に遅くない場合は分母側の局所計算・検証費が支配的になる。

### 品質との交換条件
適応検証には明確な速度・品質の交換条件がある。HumanEvalのQwen3-8Bでは緩和を強くすると平均受理長と速度が増える一方、精度が落ちる設定も表に現れる。したがって「最大2.6倍」と「品質維持」は任意の緩和係数で同時に成立するわけではない。実運用では (	au)、受理窓 (gamma)、重要トークン判定閾値を、対象タスクの品質制約に合わせて選ぶ必要がある。

## 既存研究との差
Eagle系など従来の投機的復号は主として中央集約環境で対象モデル計算を減らすことを狙う。DSDは分散環境では通信待ちが別の主要律速になると捉え、投機窓を「対象モデル呼び出しの削減単位」だけでなく「ネットワーク同期の償却単位」として使う点が異なる。

また適応検証は全候補へ一律に受理閾値を緩めるのではなく、対象・ドラフトの分布差から重要トークンを識別し、重要位置だけ厳格な対象分布を維持する。したがって高速化機構と品質保護機構を分離して設計している。

## 限界
評価は8B級モデル、A800、主に4〜8ノードのParallax環境が中心であり、数十〜数百ノード、異種GPU、低帯域WAN、巨大MoEで同じ倍率になるとは限らない。理論式も通信と計算を単純化したモデルなので、実システムの輻輳、再送、非対称リンク、負荷不均衡は別途考慮が必要である。

適応検証は閾値を検証集合で校正するため、タスク分布が変わると重要トークン判定や最適 (	au) も変わり得る。さらに通信が支配的でない環境では、ドラフト生成・追加統計・一括検証の費用が相対的に目立ち、DSDの利得は小さくなる。
