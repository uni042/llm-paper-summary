# Accelerating Speculative Decoding with Block Diffusion Draft Trees

> DFlashが1回で得た位置別確率分布から高確率な複数接頭辞をDDTreeとして組み、1回の対象モデル検証で複数経路を試して単一路径投機より受理長と速度を高める。

## 概要

投機的復号（speculative decoding）は、小さなドラフトモデルが将来トークンを先に提案し、大きな対象モデル（target model）が複数候補をまとめて検証することで、対象モデルの逐次前向き計算回数を減らす。高速化を左右するのは、1回の検証で何トークン先まで受理できるかという受理長である。DFlashはブロック拡散ドラフト器を使い、複数位置の候補分布を1回で生成できるが、従来は各位置から1トークンずつ選んだ単一系列しか検証しない。そのため、分岐が曖昧な位置で一度外すと、その後ろに高確率候補があっても同じ検証回では利用できない。

DDTreeは、DFlashがすでに計算した各位置の周辺確率分布 (q_i) を再利用し、固定ノード予算 (B) の範囲で確率の高い接頭辞を複数枝として残す。真の対象モデル分布は検証前には分からないため、位置ごとの周辺分布を独立とみなした代理分布 (Q(y_{1:L})=prod_i q_i(y_i)) を使う。この代理分布の下では、高確率な接頭辞を上位から (B) 個選べば期待受理長を最大化できることを示し、最良優先ヒープで木を構成する。

作った木は、各ノードが根・過去キャッシュ・自身の祖先だけを参照する木注意（tree attention）で対象モデルへ1回だけ入力する。対象モデルのサンプリング結果と一致する子をたどり、一致しなくなった位置で検証を終了するため、出力分布は対象モデルに従い、木構築自体は品質を近似しない。実験ではQwen3-4B/8BやQwen3-Coder-30B-A3B-InstructなどでDFlashより長い受理系列を得て、複数の推論・コード生成ベンチマークでDFlashに対する追加高速化を示す。

## 背景: ブロック拡散ドラフトで「捨てていた確率質量」を候補木へ戻す

自己回帰ドラフト器で候補木を作る場合、枝ごとに次トークン分布が異なるため、深い木を作るには通常複数回のドラフト計算が必要になる。これに対しDFlashのブロック拡散ドラフト器は、長さ (L) のブロックについて位置ごとの分布を1回で出す。高速だが、その分布は「前のドラフトトークンを条件にした枝ごとの分布」ではなく位置別の周辺分布である。

従来DFlashは各位置の代表トークンだけをつないだ1本の系列を検証する。たとえばある位置で第1候補と第2候補が拮抗していても、第1候補を外した瞬間にその検証回は短く終わる。DDTreeは第2候補以下にも割り当てられていた確率質量を候補木へ変換し、対象モデル1回の検証で複数の有望な未来を同時に試す。

ただし木を大きくすれば必ず速くなるわけではない。ノード数を増やすほど平均受理長は伸びる一方、対象モデルが検証するトークン数も増える。したがってノード予算 (B) は、受理長と検証計算量の交換条件を決める重要な設定値である。

## 問題設定

DFlashが1回のドラフトで得る情報量は単一系列より多いのに、単一路径検証ではその大半を使わない。一方、通常の自己回帰型の木構築をそのまま導入すると、木の深さに応じたドラフト前向き計算が増え、DFlashの「1回でブロックを提案できる」という利点を失う。

そこで本論文は、追加のドラフト前向き計算を増やさず、DFlashの位置別分布だけから、固定ノード予算で期待受理長が大きい候補木を構築する問題として定式化する。必要なのは、(1) 分岐候補の価値を比較できる代理目的、(2) 全候補列を列挙せず上位接頭辞だけを取り出す探索、(3) 木全体を対象モデルへ1回で検証する実行方法である。

## 手法

### 1. 位置別分布から接頭辞確率を作る

ブロック拡散ドラフト器が文脈 (c) と補助トークンから長さ (L) の位置別分布 (q_1,ldots,q_L) を返す。DDTreeはこれらを独立とみなす代理分布 (Q) を定義し、接頭辞 (u=(u_1,ldots,u_d)) のスコアを (prod_{i=1}^{d}q_i(u_i)) とする。

この値は対象モデルの真の受理確率そのものではない。しかしDFlashがすでに持つ情報だけで計算でき、追加のドラフト推論を要求しない。さらに、子の接頭辞確率は必ず親以下なので、確率上位の接頭辞集合は自然に親を含み、木として閉じる。この性質を使って「上位 (B) 接頭辞」を固定予算の候補木として選べる。

### 2. 最良優先ヒープで上位 (B) ノードだけを展開する

全語彙・全深さの候補を列挙すると組合せ爆発するため、DDTreeは最大ヒープを使った最良優先探索を行う。各ノードには現在の接頭辞確率を持たせ、最も高いノードから順に取り出す。取り出した候補から次の深さの第1候補（子）と、同じ深さの次順位候補（兄弟）を追加し、高確率領域だけを展開する。

論文のアルゴリズムでは (B) 回までの取り出しと高々約 (2B) 回の追加で済み、木構築は概ね (O(Blog B)) である。重要なのは、木を作るために対象モデルもドラフトモデルも再実行しない点である。

### 3. 祖先限定注意で木全体を1回検証する

選ばれたノードを平坦化し、各ノードに木の深さに対応した位置を与える。注意マスクは、元の文脈、木の根、自分の祖先、自分自身だけを参照できるようにする。これにより互いに異なる枝のトークンが混ざらず、複数の接頭辞を1回の対象モデル前向き計算へ詰め込める。

検証時には対象モデルが実際に出したトークンと一致する子を木上でたどる。一致する子がなくなった時点で、その対象モデルのトークンを次ラウンドの補助トークンとして採用する。KVキャッシュ（key-value cache）は受理された経路だけに圧縮して次ラウンドへ引き継ぐ。

### 4. 品質を変えずに速度だけを狙う

DDTreeの確率モデルは候補木の「どこへ検証予算を使うか」を決めるだけで、最終トークンを確定しない。最終的な受理判定と新規トークン生成は対象モデルが行うため、通常の投機的復号と同様に対象モデルの分布を保つ。

失敗条件は品質劣化ではなく性能側に現れる。位置別周辺分布が対象モデルの条件付き分布をうまく近似しない場合は有望でない枝へノードを使い、木を大きくし過ぎれば検証費用が増える。そのため、受理長だけでなくトークン当たり時間まで測る必要がある。

## 評価

### 代表的な評価条件

| 項目 | 条件 |
| --- | --- |
| 対象モデル | Qwen3-4B、Qwen3-8B、Qwen3-Coder-30B-A3B-Instruct |
| ドラフト | 各対象モデルに対応するDFlashのブロック拡散ドラフト器 |
| 比較の中心 | 自己回帰復号、DFlash、既存の強い投機的復号方式 |
| 代表ワークロード | 数学推論、コード生成、一般指示追従など複数ベンチマーク |
| 木予算 | 固定ノード予算 (B) を変化させ、受理長と検証費用の交換条件を測定 |
| 主指標 | トークン当たり時間、自己回帰復号比の高速化率、平均受理長 |
| 品質 | 対象モデル検証により出力分布を維持するため、主評価は速度・受理効率 |

### 代表的な評価結果

| 条件 | 比較 | DDTreeで確認できること |
| --- | --- | --- |
| Qwen3系列・複数ベンチマーク | DFlash | 単一軌跡では捨てていた代替候補を木へ入れることで、DFlashより長い平均受理長を一貫して得る |
| Qwen3-4B / MATH-500の代表例 | DFlash 約5.54倍 | DDTree 約7.50倍の自己回帰復号比高速化が報告され、木検証の追加費用を上回る利得が出る |
| ノード予算を増加 | 小さい木 vs. 大きい木 | 平均受理長は伸びるが、対象モデルの木検証時間も増えるため、速度は単調には改善しない |
| 受理長分布 | DFlash | 短い1〜3トークン受理が減り、ブロック末端まで長く受理するラウンドが増える |

この評価で重要なのは、「木を大きくすれば受理長が伸びる」ことと「トークン当たり時間が短くなる」ことを分けている点である。ノード予算が過大になると、追加枝を検証する対象モデル計算が支配的になり、受理長の増分より実行時間の増分が大きくなる。したがってDDTreeは固定予算内での木構造は最適化するが、予算そのものの自動選択は本論文の範囲外である。

## 既存研究との差

DFlashとの差は、ドラフト器を変えずに1回のブロック拡散出力を「1系列」から「候補木」へ使い直す点にある。自己回帰ドラフト器を使う木方式では枝の条件付き分布を得るため複数のドラフト前向き計算が必要になりやすいが、DDTreeは位置別周辺分布を代理分布として使うため追加のドラフト計算を避ける。

また、N-gramなど外部の連続性情報から木を作る方式と違い、DDTreeは現在のブロック拡散ドラフト器が出した確率を直接利用する。その代わり枝ごとの条件依存性は表現できず、位置独立の代理分布の精度が候補選択の質を左右する。

## 限界・実装状況

固定ノード予算 (B) はハイパーパラメータであり、最適値は対象モデル、データ、温度、検証カーネルによって変わる。大きい (B) は受理長を伸ばしても速度を悪化させ得るため、自動的な予算選択は今後の余地である。

また、代理分布は各位置を独立とみなすため、強い枝依存性を持つ候補の確率を正確には表さない。公式コードは公開されているが、論文の高速化倍率はQwen系列と評価環境に依存するため、別の対象モデル・GPUへそのまま外挿できない。
