# PARD: Accelerating LLM Inference with Low-Cost PARallel Draft Model Adaptation

> 小型AR draftをmask-token型の並列draftへ変換し、KV整合性を保つConditional Dropで学習費を抑えつつmodel family内で再利用するPARD。

## 概要

投機的復号では、小型draft modelが先のK tokenを予測し、大型target modelがK個をまとめて検証する。target verificationは並列化できても、vanilla speculative decoding（VSD）のdraft modelは通常の自己回帰LLMなので、候補K個を作るためにK回forwardする必要がある。draftが十分小さければ許容できるが、高い受理率を求めて1B級など強いdraftを使うと、このK回の逐次draftが無視できない。

EAGLE/Medusa系はtarget modelのhidden stateや専用headを使い、targetに密着した軽いdraftを学習することでこの問題を緩和する。しかしtargetごとにdraftを別学習する必要がある。LLaMA3 familyの8B、70B、405Bをすべて配備する場合、それぞれ専用adaptationを持つことになり、model variant数に比例して学習・管理コストが増える。

PARD（PARallel Draft）は別の方向を取る。まずLLaMA3.2-1BやQwen2.5-0.5Bのような**既存の高品質な小型AR modelをtarget-independent draftとして使う**。そのdraftをmask-token trainingで改造し、未来K tokenを1回のforwardで同時予測できるようにする。target modelのhidden stateを入力にしないため、1つのPARD draftを同一familyの複数targetへ適用できる。

並列draft化の素朴な学習は、+1、+2、…、+K token predictionを別subtaskとして並べるためtoken数がNからK×Nへ膨らむ。PARDはここにConditional Drop-token（COD）を導入し、後段subtaskほど学習位置を幾何級数的に間引きながら、残す位置ではattentionが必要とするprefix Key/Valueが欠けないようにする。これによりtraining costを大きく減らす。

vLLM/A100-40GB評価ではLLaMA3.1-8BのHumanEvalで264.88 tokens/s、自己回帰比3.63倍となり、vanilla SDより1.72倍、EAGLE-3より1.15倍速い。CODは通常mask-predict trainingより約3倍学習効率を上げ、target-dependent方式と比べるとtarget family全体にわたるadaptationコストも小さい。

## 問題設定

### Target-independent draftは再利用しやすいが重い

vanilla SDではtargetとは独立に学習済みの小型LMをdraftへ使える。例えばLLaMA3.2-1BはLLaMA3.1-8Bだけでなく70B/405Bにも候補を出せるため、target variantごとにdraft headを作る必要がない。

しかも独立した1B modelは単純な専用headより言語能力が高く、最初のcandidate tokenのaccuracyが高い場合がある。しかしK tokenを自己回帰で作るとdraft時間は

[
T_{mathrm{AR draft}}=K T_D+T_T
]

となる。(T_D) はdraft 1 forward、(T_T) はtarget verificationである。1B draftが高精度でもK回分の重み読出しが必要になり、VSD全体がdraft側に律速される。

### 並列予測へ変えると、今度はtraining token数がK倍になる

Mask-Predict型では、未来位置をmask placeholderへ置き換え、+1 token、+2 token…を互いに依存させず予測する。推論ではK個を同時に出せるため、

[
T_{mathrm{PARD}}=T_D+T_T
]

までdraft critical pathを短くできる。

ただし既存AR modelをこの能力へfine-tuneするには、各offset用のtraining subtaskを作る必要がある。長さNのsampleにK種類の予測offsetをそのまま展開すると計算対象はK×Nになる。PARDでは推論adaptation費を減らしたいのに、素朴なparallel trainingが新たなコストになるため、CODが必要になる。

## 手法

### 1. Mask placeholderでK個のtoken間依存を切る

vanilla draftでは

[
P(x_n,ldots,x_{n+K-1})
=prod_{k=0}^{K-1}P(x_{n+k}mid x_{<n+k})
]

なので、(x_{n+1}) を出すには先に (x_n) が必要である。

PARDでは未来tokenそのものを条件に入れず、位置ごとに (m_0,m_1,ldots) というmask placeholderを置く。k番目の候補は「確定済みprefix + k個のmask」から予測され、同じforward中の別candidate predictionへ依存しない。

これによりdraft modelはK個のlogitsを同時に出す。target modelは従来通り候補列を検証するので、並列draftが外しても最終output qualityを直接変えない。

### 2. 既存AR modelをparallel draftへadaptする

trainingでは+1 prediction、+2 prediction…をそれぞれsubtaskとして作る。各subtaskは推論時と同じmask patternを見るため、標準AR modelの「左側は全て実token」というtraining distributionからparallel drafting用distributionへ適応できる。

PARDのtarget-independent性はここで重要である。training labelはdraft familyのデータから作れ、特定targetのhidden statesやlogitsを教師として必須にしない。論文では各model familyの最小variantをPARD化し、同familyのより大きいtargetへ使う。

### 3. Conditional Drop-token — 後ろのsubtaskほどtokenを間引く

全subtaskをN tokenずつ残すとK×Nになる。CODはi番目subtaskの保持token数を概ね

[
N_i=N r^{i-1}
]

とし、(0<r<1) の幾何級数で減らす。例えばr=0.5なら総token数はKが大きくても2N未満へ近づく。

重要なのは**ランダムdropではない**ことだ。Transformerのある位置を残しても、それより前に必要なtokenを削ると、その位置のKey/Value prefixが不完全になり、training時attentionが推論時と違う文脈を見る。

CODは残すprediction位置について完全なpreceding KV stateが構成できるようにdrop patternを選び、その後compactなsequenceへ詰め直す。これが名前の“Conditional”の意味である。

### 4. 最小保持率で遠い未来predictionも消し切らない

幾何減衰だけだと大きいoffsetのsubtaskがほぼ学習されなくなる。そこで (r_{min}) を置き、

[
N_i'=Nmax(r^{i-1},r_{min})
]

として下限を保証する。主trainingではK=8、r=0.7、(r_{min}=0.2) を使う。

これにより+1/+2の重要な近未来を多く学習しつつ、+8までのparallel prediction能力も残す。推論時のcandidate数を増やすために全offsetを同量学習する必要はない、という非均一なtraining allocationである。

### 5. 1つのdraftをmodel family内で共有する

LLaMA3系なら小型LLaMA3、Qwen系なら小型QwenをPARD化する。target-specific hidden stateを使わないため、そのPARD checkpointを8Bだけでなく同familyのより大きなtargetへ適用できる。

これは「どんなtarget modelにも1つのdraftでよい」という意味ではなく、tokenizerやdistributionが近い**同一model family内での再利用**が主張である。EAGLE-styleのようにtarget checkpointごとに専用draftを学習する方式との差は、variant追加時のadaptation costに現れる。

## 評価

### 代表的な評価条件

| 項目 | 内容 |
|---|---|
| model family | LLaMA3、Qwen2/2.5、DeepSeek-R1-Qwen |
| draft例 | LLaMA3.2-1B、Qwen2.5-0.5B/小型variant |
| task | HumanEval、GSM8K、MATH500、SpecBench |
| training | 8×AMD MI250X、4 epochs |
| PARD training | K=8、r=0.7、r_min=0.2 |
| inference | vLLM |
| GPU | NVIDIA A100 40GB |
| 比較 | AR、vanilla SD、EAGLE、EAGLE-3 |
| 指標 | tokens/s、AR比speedup、training cost |

### 代表結果

| target / 条件 | 方法 | 平均speedup | 読み取り |
|---|---|---:|---|
| LLaMA3.1-8B | VSD | 1.84倍 | 高精度1B draftでも逐次draftが重い |
| LLaMA3.1-8B | EAGLE-3 | 2.65倍 | target-specific軽量draft |
| LLaMA3.1-8B | PARD | 3.00倍 | target-independentでもparallel draftで上回る |
| LLaMA3.3-70B | EAGLE-3 | 3.22倍 | 大targetではverification amortizationが効く |
| LLaMA3.3-70B | PARD | 3.49倍 | 同じfamily draftを大targetへ再利用 |
| Qwen2.5-14B | PARD | 3.71倍 | model familyを跨いで同設計が有効 |

LLaMA3.1-8B HumanEval単体ではPARDが264.88 TPS、3.63倍で、VSD 155.47 TPS、EAGLE-3 233.43 TPSを上回る。論文abstractの「最大3.67倍」と表中のtask別値には条件差があるため、代表値は同じ表・task条件で読む必要がある。

### Training cost

CODはmask-token parallel trainingを約3倍効率化する。さらにLLaMA3.3-70Bをtargetとした計算量比較では、target modelのfeatureをtrainingに通す必要があるEAGLE/EAGLE-3に対し、PARDはおよそ7倍/10倍高いtraining efficiencyを示す。

この差は一度のfine-tuning costだけでなく、複数target variantを運用するときに効く。EAGLE型はtargetごとのdraftが必要なのに対し、PARDは同family内で1つのadapted draftを共有できるからである。

## 既存研究との差

Vanilla SDはtarget-independentだがdraftがARなのでK回forwardする。EAGLE/Medusaはdraftを軽量化・高精度化できるがtarget-specific adaptationを必要とする。

PARDはその中間を狙い、**強い既存小型LMのtarget-independenceを保ったまま、draftだけをparallel mask predictionへ変える**。さらにCODにより、このparallel能力を身につけるtraining cost自体も抑える。

DFlashのようなdiffusion draftingとも目的は似るが、PARDは既存AR small modelへmask-token能力をfine-tuneする設計であり、block diffusion architectureを新たにdraftとして採用する方式ではない。

## 限界

target-independent性は同一family内の互換性を利用する。tokenizerや語彙、instruction distributionが大きく異なるtargetへ同じPARD draftをそのまま適用できる保証はない。

parallel predictionでは候補token同士の真の自己回帰依存をmaskで置き換えるため、遠いoffsetほどaccuracyが下がり得る。Kを増やせば常に速くなるわけではなく、受理率と1 forwardのsequence length、target verification costの釣り合いが必要である。

また論文の主要speedupはA100-40GB、batch条件、vLLM実装に依存する。別frameworkではVSD自体の効率が大きく異なることを論文も示しており、相対倍率をframework非依存のアルゴリズム値として扱うべきではない。
