# PARD: Accelerating LLM Inference with Low-Cost PARallel Draft Model Adaptation

> 小型AR ドラフトをmask-トークン型の並列ドラフトへ変換し、KV整合性を保つConditional Dropで学習費を抑えつつモデル family内で再利用するPARD。

## 概要

投機的復号では、小型下書きモデルが先のK トークンを予測し、大型対象モデルがK個をまとめて検証する。対象 検証は並列化できても、vanilla 投機的復号（VSD）の下書きモデルは通常の自己回帰LLMなので、候補K個を作るためにK回順伝播する必要がある。ドラフトが十分小さければ許容できるが、高い受理率を求めて1B級など強いドラフトを使うと、このK回の逐次ドラフトが無視できない。

EAGLE/Medusa系は対象モデルの隠れ 状態や専用ヘッドを使い、対象に密着した軽いドラフトを学習することでこの問題を緩和する。しかし対象ごとにドラフトを別学習する必要がある。LLaMA3 familyの8B、70B、405Bをすべて配備する場合、それぞれ専用adaptationを持つことになり、モデル variant数に比例して学習・管理コストが増える。

PARD（PARallel Draft）は別の方向を取る。まずLLaMA3.2-1BやQwen2.5-0.5Bのような**既存の高品質な小型AR モデルを対象-independent ドラフトとして使う**。そのドラフトをmask-トークン 学習で改造し、未来K トークンを1回の順伝播で同時予測できるようにする。対象モデルの隠れ 状態を入力にしないため、1つのPARD ドラフトを同一familyの複数対象へ適用できる。

並列ドラフト化の素朴な学習は、+1、+2、…、+K トークン 予測を別subtaskとして並べるためトークン数がNからK×Nへ膨らむ。PARDはここにConditional Drop-トークン（COD）を導入し、後段subtaskほど学習位置を幾何級数的に間引きながら、残す位置では注意機構が必要とする接頭辞 Key/Valueが欠けないようにする。これにより学習 コストを大きく減らす。

vLLM/A100-40GB評価ではLLaMA3.1-8BのHumanEvalで264.88 トークン/s、自己回帰比3.63倍となり、vanilla SDより1.72倍、EAGLE-3より1.15倍速い。CODは通常mask-predict 学習より約3倍学習効率を上げ、対象-dependent方式と比べると対象 family全体にわたるadaptationコストも小さい。

## 問題設定

### Target-independent draftは再利用しやすいが重い

vanilla SDでは対象とは独立に学習済みの小型LMをドラフトへ使える。例えばLLaMA3.2-1BはLLaMA3.1-8Bだけでなく70B/405Bにも候補を出せるため、対象 variantごとにドラフト ヘッドを作る必要がない。

しかも独立した1B モデルは単純な専用ヘッドより言語能力が高く、最初のcandidate トークンのaccuracyが高い場合がある。しかしK トークンを自己回帰で作るとドラフト時間は

[
T_{mathrm{AR ドラフト}}=K T_D+T_T
]

となる。(T_D) はドラフト 1 順伝播、(T_T) は対象 検証である。1B ドラフトが高精度でもK回分の重み読出しが必要になり、VSD全体がドラフト側に律速される。

### 並列予測へ変えると、今度はtraining token数がK倍になる

Mask-Predict型では、未来位置をmask placeholderへ置き換え、+1 トークン、+2 トークン…を互いに依存させず予測する。推論ではK個を同時に出せるため、

[
T_{mathrm{PARD}}=T_D+T_T
]

までドラフト critical pathを短くできる。

ただし既存AR モデルをこの能力へfine-tuneするには、各offset用の学習 subtaskを作る必要がある。長さNのサンプルにK種類の予測offsetをそのまま展開すると計算対象はK×Nになる。PARDでは推論adaptation費を減らしたいのに、素朴な並列 学習が新たなコストになるため、CODが必要になる。

## 手法

### 1. Mask placeholderでK個のtoken間依存を切る

vanilla ドラフトでは

[
P(x_n,ldots,x_{n+K-1})
=prod_{k=0}^{K-1}P(x_{n+k}mid x_{<n+k})
]

なので、(x_{n+1}) を出すには先に (x_n) が必要である。

PARDでは未来トークンそのものを条件に入れず、位置ごとに (m_0,m_1,ldots) というmask placeholderを置く。k番目の候補は「確定済み接頭辞 + k個のmask」から予測され、同じ順伝播中の別candidate 予測へ依存しない。

これにより下書きモデルはK個のlogitsを同時に出す。対象モデルは従来通り候補列を検証するので、並列ドラフトが外しても最終出力 qualityを直接変えない。

### 2. 既存AR modelをparallel draftへadaptする

学習では+1 予測、+2 予測…をそれぞれsubtaskとして作る。各subtaskは推論時と同じmask patternを見るため、標準AR モデルの「左側は全て実トークン」という学習 分布から並列 drafting用分布へ適応できる。

PARDの対象-independent性はここで重要である。学習 ラベルはドラフト familyのデータから作れ、特定対象の隠れ statesやlogitsを教師として必須にしない。論文では各モデル familyの最小variantをPARD化し、同familyのより大きい対象へ使う。

### 3. Conditional Drop-token — 後ろのsubtaskほどtokenを間引く

全subtaskをN トークンずつ残すとK×Nになる。CODはi番目subtaskの保持トークン数を概ね

[
N_i=N r^{i-1}
]

とし、(0<r<1) の幾何級数で減らす。例えばr=0.5なら総トークン数はKが大きくても2N未満へ近づく。

重要なのは**ランダムdropではない**ことだ。Transformerのある位置を残しても、それより前に必要なトークンを削ると、その位置のKey/Value 接頭辞が不完全になり、学習時注意機構が推論時と違う文脈を見る。

CODは残す予測位置について完全なpreceding KV 状態が構成できるようにdrop patternを選び、その後compactな系列へ詰め直す。これが名前の“Conditional”の意味である。

### 4. 最小保持率で遠い未来predictionも消し切らない

幾何減衰だけだと大きいoffsetのsubtaskがほぼ学習されなくなる。そこで (r_{min}) を置き、

[
N_i'=Nmax(r^{i-1},r_{min})
]

として下限を保証する。主学習ではK=8、r=0.7、(r_{min}=0.2) を使う。

これにより+1/+2の重要な近未来を多く学習しつつ、+8までの並列 予測能力も残す。推論時のcandidate数を増やすために全offsetを同量学習する必要はない、という非均一な学習 allocationである。

### 5. 1つのdraftをmodel family内で共有する

LLaMA3系なら小型LLaMA3、Qwen系なら小型QwenをPARD化する。対象-specific 隠れ 状態を使わないため、そのPARD チェックポイントを8Bだけでなく同familyのより大きな対象へ適用できる。

これは「どんな対象モデルにも1つのドラフトでよい」という意味ではなく、tokenizerや分布が近い**同一モデル family内での再利用**が主張である。EAGLE-styleのように対象 チェックポイントごとに専用ドラフトを学習する方式との差は、variant追加時のadaptation コストに現れる。

## 評価

### 代表的な評価条件

| 項目 | 内容 |
|---|---|
| モデル family | LLaMA3、Qwen2/2.5、DeepSeek-R1-Qwen |
| ドラフト例 | LLaMA3.2-1B、Qwen2.5-0.5B/小型variant |
| タスク | HumanEval、GSM8K、MATH500、SpecBench |
| 学習 | 8×AMD MI250X、4 epochs |
| PARD 学習 | K=8、r=0.7、r_min=0.2 |
| inference | vLLM |
| GPU | NVIDIA A100 40GB |
| 比較 | AR、vanilla SD、EAGLE、EAGLE-3 |
| 指標 | トークン/s、AR比高速化倍率、学習 コスト |

### 代表結果

| 対象 / 条件 | 方法 | 平均高速化倍率 | 読み取り |
|---|---|---:|---|
| LLaMA3.1-8B | VSD | 1.84倍 | 高精度1B ドラフトでも逐次ドラフトが重い |
| LLaMA3.1-8B | EAGLE-3 | 2.65倍 | 対象-specific軽量ドラフト |
| LLaMA3.1-8B | PARD | 3.00倍 | 対象-independentでも並列 ドラフトで上回る |
| LLaMA3.3-70B | EAGLE-3 | 3.22倍 | 大対象では検証 amortizationが効く |
| LLaMA3.3-70B | PARD | 3.49倍 | 同じfamily ドラフトを大対象へ再利用 |
| Qwen2.5-14B | PARD | 3.71倍 | モデル familyを跨いで同設計が有効 |

LLaMA3.1-8B HumanEval単体ではPARDが264.88 TPS、3.63倍で、VSD 155.47 TPS、EAGLE-3 233.43 TPSを上回る。論文abstractの「最大3.67倍」と表中のタスク別値には条件差があるため、代表値は同じ表・タスク条件で読む必要がある。

### Training cost

CODはmask-トークン 並列 学習を約3倍効率化する。さらにLLaMA3.3-70Bを対象とした計算量比較では、対象モデルのfeatureを学習に通す必要があるEAGLE/EAGLE-3に対し、PARDはおよそ7倍/10倍高い学習 効率を示す。

この差は一度の微調整 コストだけでなく、複数対象 variantを運用するときに効く。EAGLE型は対象ごとのドラフトが必要なのに対し、PARDは同family内で1つのadapted ドラフトを共有できるからである。

## 既存研究との差

Vanilla SDは対象-independentだがドラフトがARなのでK回順伝播する。EAGLE/Medusaはドラフトを軽量化・高精度化できるが対象-specific adaptationを必要とする。

PARDはその中間を狙い、**強い既存小型LMの対象-independenceを保ったまま、ドラフトだけを並列 mask 予測へ変える**。さらにCODにより、この並列能力を身につける学習 コスト自体も抑える。

DFlashのようなdiffusion draftingとも目的は似るが、PARDは既存AR small モデルへmask-トークン能力をfine-tuneする設計であり、ブロック diffusion 構成を新たにドラフトとして採用する方式ではない。

## 限界

対象-independent性は同一family内の互換性を利用する。tokenizerや語彙、instruction 分布が大きく異なる対象へ同じPARD ドラフトをそのまま適用できる保証はない。

並列 予測では候補トークン同士の真の自己回帰依存をmaskで置き換えるため、遠いoffsetほどaccuracyが下がり得る。Kを増やせば常に速くなるわけではなく、受理率と1 順伝播の系列 length、対象 検証コストの釣り合いが必要である。

また論文の主要高速化倍率はA100-40GB、バッチ条件、vLLM実装に依存する。別フレームワークではVSD自体の効率が大きく異なることを論文も示しており、相対倍率をフレームワーク非依存のアルゴリズム値として扱うべきではない。
