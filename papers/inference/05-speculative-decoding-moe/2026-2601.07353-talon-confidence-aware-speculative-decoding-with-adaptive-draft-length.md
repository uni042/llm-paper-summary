# TALON: Confidence-Aware Speculative Decoding with Adaptive Token Trees

> 投機木の形をあらかじめ「幅10・深さ8」のように固定すると、簡単な箇所では深さが足りず、難しい箇所では大量の枝を作って捨てる。TALONは総ノード数だけを固定し、ドラフトモデルの確信度に応じて予算を深さと幅へその場で配分する。

## 概要

投機的復号（speculative decoding）は、小さなドラフトモデルが複数候補を先に生成し、大きな対象モデルが一度に検証することで自己回帰の逐次回数を減らす。木型方式では複数の候補経路を同時に提示できるため、単一チェーンより受理トークン数を増やせる。

しかしEAGLE系の静的木では幅と深さが固定される。ドラフトモデルが対象モデルとよく一致する低エントロピー箇所では、本来もっと深く先読みできるのに固定深さで止まる。逆に不確実な高エントロピー箇所では、深い枝を大量に作っても後で棄却され、ドラフト計算だけが増える。

TALONはこの問題を「固定形状」ではなく「固定予算」の問題として扱う。木全体で使えるノード数Nを与え、第1層は上位K候補で広く始め、第2層以降は候補の累積確率がその層の最大値に対して十分高い枝だけを伸ばす。確定的なら少数枝が深く伸び、不確実なら幅を広く残しつつ早めに深さを止める。

## 問題設定

### 固定幅には「受理漏れ」と「無駄枝」の両方がある

論文が観測する受理ファネル（Acceptance Funnel）は、木の第1層では正解候補の位置が比較的散らばるが、深い層では受理確率が上位少数候補へ急速に集中する現象である。

つまり根元では探索幅が必要だが、深い層で同じ幅を維持する意味は薄い。EAGLEのように各層でTop-Kを固定すると、後段ほど受理されない枝を大量に作る。

### 固定深さは入力難易度の変化を扱えない

同じ数学問題の集合でも平均受理トークン数は入力ごとに大きく変わる。ドラフトが高確信で正しい箇所では、固定深さを超えてさらに先読みできる。一方、ドラフトと対象モデルがずれる箇所では、深く進むほど累積誤差が大きくなり、作った候補の大半が無駄になる。

そのため「毎回何層生成するか」ではなく、「今の文脈で追加ノード1個へ計算を投資する価値があるか」を逐次判断する必要がある。

## 手法

### 1. 木の形ではなく総ノード予算Nだけを固定する

TALONはドラフト木の最大幅・最大深さではなく、全体ノード数Nを主制約にする。実験の既定値はN=60である。木は層ごとに拡張され、総ノード数がNへ達した時点で終了する。

このため同じ60ノードでも、ある入力では多数層の細い木、別の入力では少数層の広い木を作れる。

### 2. 第1層だけはTop-Kで頑健に初期化する

小型ドラフトモデルは最初のトークンで過信することがある。誤った候補へ0.99以上の確率を与えた場合、相対閾値だけで選ぶと最初から一本の誤枝へ木が潰れ、対象モデル検証で木全体が早期棄却される。

そこで根直後の第1層は確信度に関係なく上位K候補を残す。既定値K=10である。この頑健な木初期化（Robust Tree Initialization）により、最も致命的な根元の較正誤差へ探索幅を確保する。

### 3. 第2層以降は累積経路確率を相対閾値でゲートする

各候補ノードuには、根からそのノードまでのドラフト確率の積を累積経路確率p(u)として持たせる。その層の候補集合で最大の確率を (m_d) とし、(p(u) ge mu m_d) を満たす候補だけを残す。既定の相対閾値は (mu=0.03)。

絶対確率ではなく「その層の最有力候補に対してどれくらいか」で判定するため、確率分布の鋭さへ自然に適応する。最大候補が圧倒的な場合は少数枝だけが残り、分布が平坦なら多くの枝が残る。

### 4. 予算超過時は経路確率の高い候補から打ち切る

次層候補を全部追加するとNを超える場合、残り予算ぶんだけ経路確率の高い候補を採用する。この「生成して最後に大規模探索する」方式ではなく、展開しながら刈る構造により、OPT-Treeのような探索・剪定処理の費用を避ける。

### 5. 対象モデル検証は通常の木型投機的復号と同じ

TALONが変えるのはドラフト木の構築だけである。最終的な採否は対象モデルによって検証されるため、対象モデルの出力分布を保つ無損失投機的復号の枠組みを維持する。

著者らはドラフト効率（Draft Efficiency, δ）として「対象モデル検証1回あたり何回ドラフト前向き計算を使ったか」を導入し、平均受理トークン数と一緒に見る。難しい入力でδを下げ、簡単な入力でδを増やして受理長を伸ばせるかを評価する。

## 評価

### 評価条件

| 項目 | 条件 |
| --- | --- |
| 対象モデル | Vicuna-13B、DeepSeek-R1-Distill-LLaMA-8B、Llama-3.1-8B-Instruct、Qwen3-8B、Qwen3-32B |
| 課題 | Alpaca、GSM8K、HumanEval、MT-Bench、QA、CNN/DM |
| 主要比較 | EAGLE-3。VicunaではSD、MEDUSA、HYDRA、OPT-Treeも比較 |
| 公平性 | TALON/EAGLE-3/OPT-Treeは同一ドラフト重みを使用 |
| GPU | 1×NVIDIA H200 141GB |
| batch | 1 |
| ソフトウェア | PyTorch 2.6.0+cu124、Transformers 4.57.1、CUDA 12.8 |
| 復号 | 主表はtemperature=0、最大生成長1024 |
| 木設定 | TALON N=60, μ=0.03, root K=10。EAGLE-3 K=10, D=8 |
| 指標 | 平均受理トークン数（Mean Accepted Tokens, MAT）、自己回帰比の実時間高速化 |

### 代表結果

| モデル / 課題 | EAGLE-3 | TALON | 差 |
| --- | ---: | ---: | ---: |
| Vicuna-13B / HumanEval | 4.77× | **5.16×** | +0.39× |
| Vicuna-13B / MT-Bench | 4.05× | **4.27×** | +0.22× |
| Vicuna-13B / CNN/DM | 3.43× | **3.58×** | +0.15× |
| Qwen3-8B / GSM8K | 2.37× | **2.67×** | +0.30× |
| Qwen3-8B / CNN/DM | 1.95× | **2.30×** | +0.35× |
| Llama3-8B / Alpaca | 3.92× | **4.04×** | +0.12× |
| Qwen3-32B / GSM8K | 2.22× | **2.38×** | +0.16× |

Vicuna-13B/HumanEvalではTALONのMATは9.48で、EAGLE-3の8.31より長く受理される。一方、全課題で必ずMATが増えるわけではない。例えばQwen3-8B/AlpacaではEAGLE-3の3.45に対しTALONは3.39だが、速度は2.08×から2.44×へ上がる。難しい箇所で不要なドラフト計算を減らせば、受理長が同等でも実時間は改善できるためである。

第1層だけTop-Kを使うアブレーションでは、Top-Kを使わない設定や2〜3層まで固定Top-Kを続ける設定より良い。根元では探索幅が必要だが、深層まで固定幅を続けると再び無駄が増えるという設計仮説と整合する。

## 既存研究との差

EAGLE-3との差はドラフトモデルではなく木構造である。本評価では同じEAGLE-3ドラフト重みを使っているため、速度差を「より強いドラフトモデルを学習したから」と説明できない。

OPT-Treeも木構造を最適化するが、候補を生成してから探索・剪定する処理を使う。TALONは固定予算内で展開しながら相対確信度ゲートを適用するため、オンライン探索費用を抑える。

Dynamic Speculation Lookaheadのようなチェーン長適応と比べると、TALONは長さだけでなく幅も同時に変え、木型検証の候補カバレッジを保持する。

## 限界・実装状況

評価は単一H200・batch 1の遅延重視条件が中心である。連続バッチ配信では、要求ごとに異なる木形状をまとめてGPUへ載せる効率が別問題になる。

μ=0.03、N=60は多くのモデル・課題で頑健だったが、論文自身も特殊な領域では調整余地があるとする。Qwen3-8B/32Bのドラフト効率曲線は理想線からまだ離れており、動的閾値調整の余地も残る。
