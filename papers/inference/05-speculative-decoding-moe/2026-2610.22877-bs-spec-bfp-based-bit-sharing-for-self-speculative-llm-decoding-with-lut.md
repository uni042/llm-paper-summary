# BS-Spec: BFP-Based Bit-Sharing for Self-Speculative LLM Decoding with LUT-Driven Mixed-Precision Acceleration

> ブロック浮動小数点の対象表現から最上位ビットの部分読み込みで下書きを作り、重みとキャッシュの精度を負荷ごとに参照表で切り替え、専用データパスで実行することで、モデル評価で自己回帰比最大1.9倍の高速化を得る自己投機の共同設計。

## 概要

デコードは、重みとキーと値のキャッシュを繰り返し読むメモリ律速の処理である。投機的デコードは軽い下書きで候補を作り対象モデルに一括検証させることで高速化するが、別の下書きモデルを持つと、その重みとキャッシュの保存と読み込みが負担になる。対象モデル自身から下書きを派生させる自己投機はこの負担を避けるが、従来方式は下書きの構成が固定で、負荷条件が変わると費用と採用率の釣り合いが崩れる。層を飛ばす方式は飛ばせる層数に限界があり、特徴を再利用する方式は追加の学習が要り、量子化を使う方式は重みとキャッシュを別々に扱い固定精度で動くため、効く負荷範囲が狭い。

ここで効く観察は、メモリ交通の主役が条件で入れ替わることである。小さいバッチと短い文脈では重みの読み込みが支配的だが、バッチや文脈が伸びるとキャッシュの読み込みが急増して主役になる。したがって重みの精度とキャッシュの精度は独立にではなく、現在の負荷に合わせて組で選ぶ必要がある。本論文の提案は、この選択を可能にする土台として、対象モデル全体をブロック浮動小数点、つまり値の組ごとに指数を共有し仮数を揃えた表現で保持する。この表現では、最上位のビットだけを読み込むことで、変換も再構成もなしに低精度の下書きが得られ、精度の段階も細かく選べる。重みは事前に変換して9ビット表現で保存し、キャッシュは推論中に組を作って変換する。どの精度の組を使うかは、費用の見積もりと実測の採用率から事前に較正し、バッチと文脈長の条件ごとに最良の組を参照表へ格納して、実行時は表を引くだけで切り替える。実行側には、5ビットから9ビットまでの可変精度をビット直列に処理する専用データパスを用意し、参照表（ルックアップテーブル）による蓄積で直列処理の遅さを補う。

代表結果は全てハードウェアのモデル評価に基づく。自己回帰に対する高速化は、バッチ4で3モデルについて1.83倍、1.84倍、1.90倍、バッチ32で1.62倍、1.68倍、1.92倍であり、エネルギーは自己回帰の0.43倍から0.55倍に下がった。要旨では、評価したビット共有型の自己投機の比較対象に対する高速化の改善が平均67.2パーセントとされる。採用率は高く、最も精度を落とす組み合わせでも多くの条件で9割前後を保ち、対象表現そのものを9ビットへ圧縮しても数学課題の精度は16ビットの77.7パーセント、84.5パーセント、91.4パーセントに対して77.8パーセント、85.5パーセント、91.0パーセントとほぼ同等だった。実チップでの測定ではない点は、結果の読み方として常に付けて回る必要がある。

## 問題設定

自己投機の成否は、下書きの費用と採用率の積で決まる。下書きが安くても採用されなければ検証の費用だけが残り、採用率が高くても下書きが高くつけば利得は消える。費用の側は、重みの交通量とキャッシュの交通量の合計であり、両者の比率はバッチと文脈長で大きく動く。重みの量はモデルの形で固定だが、キャッシュの量はバッチと文脈長に比例して伸びるためである。精度を1段落とす効果も、どちらの交通をどれだけ削るかで条件ごとに違う。つまり最適な精度の組は点ではなく、負荷条件ごとの面として存在し、固定精度の設計はその面のごく一部でしか最良になれない。先行方式の評価でも、短文脈で強い方式が長文脈で失速し、長文脈と小バッチで強い方式が他の範囲で伸びないという、効く範囲の偏りが実際に観測されている。

もう一つの問題は実行側である。ビット共有による下書きは、低い精度の下書き実行と高い精度の検証実行を同じ基盤で行き来する。浮動小数点の演算路を複数持つ従来の混合精度設計では、低精度実行で余分なビットを読む無駄や、高精度実行で演算路が遊ぶ無駄が出る。可変の精度へ素直に対応するビット直列の方式は、1ビットずつ処理するため蓄積の回数が増えて遅くなる。この問題設定に対し、提案は表現、選択、実行の三層を一組で設計し直すことで答える。

## 手法のあらまし

流れは、事前準備と実行時に分かれる。事前準備では、重みをブロック浮動小数点の9ビット表現へ変換して保存し、あらゆる精度の組について、下書き費用の見積もりと、代表課題で測った採用率を組み合わせて予想高速化を計算し、バッチと文脈長の条件ごとに最良の組を選んで精度参照表へ格納する。実行時には、現在のバッチと文脈長で参照表を引き、重みの精度とキャッシュの精度の組を決める。下書きのフェーズでは、対象表現からその精度分の最上位ビットだけを読み込んで候補トークン列を生成し、一時的なキャッシュ項目を作る。検証のフェーズでは全精度の表現で候補を検証し、採用された分だけを確定状態へ反映する。キャッシュの値は推論中に組が揃った時点で同じ表現へ変換され、対象側は常に全精度を保持する。演算はビット平面を単位とする配置で保存されたデータを、参照表駆動の蓄積路がビット直列に処理し、下書きと検証は読み込む平面の数だけが違う同じ経路を通る。

## 手法

### 1. ビット共有の下書き生成 — 指数を共有するから部分読み込みで足りる

ブロック浮動小数点では、値の組が1つの指数を共有し、各値は揃えられた仮数で表される。この性質により、仮数の上位ビットだけを読むことが、そのまま妥当な低精度近似になる。通常の16ビット浮動小数点から仮数だけを抜くと数値の尺度が壊れて近似が大きく歪むが、共有指数を保持する提案方式では歪みが最小になることが、論文の数値例で示されている。組の大きさを大きく取れば共有指数の負担は薄まる。重みは事前に変換され、キャッシュは、キーはチャネル方向、値はトークン方向に組を作って推論中に変換される。キーは組が揃うまで一時的に保持される。活性値は元の16ビットのまま扱い、変換の対象は重みとキャッシュだけに限る。減るボトルネックは下書き時のメモリ交通であり、追加で消費するのは変換と一時保持の費用である。別の下書きモデルを保存する方式と違い、保存量は対象の表現1つ分で済み、精度の段階は読み込む平面の数で連続的に変えられる。

### 2. 精度参照表 — 費用と採用率から事前に最適な組を選ぶ

精度の組の評価は二つの量で行う。費用側は、メモリ律速を前提に、重みとキャッシュの読み込み比率から下書きと対象の遅延比を見積もる。重みとキャッシュの量はバッチと文脈長から式で求まるため、条件ごとの比率は事前に計算できる。品質側は採用率であり、3モデルと3課題で、重み5から9ビット級とキャッシュ5から9ビットの全組み合わせに近い範囲が実測されている。傾向として、重みの精度を落とす方が採用率の低下が大きく、キャッシュの最低精度では急落が見られるなど、組ごとの差が具体的に測られている。下書きの候補数は5から8で試され、期待される採用長が最大になる7が選ばれた。両者を投機の高速化の式へ入れて条件ごとに最良の組を選び、参照表へ格納する。表の中身は条件で系統的に動き、短い文脈では重みを落としてキャッシュを厚く、長い文脈では逆にキャッシュを落とす組が選ばれるなど、問題設定で述べた交通の主役の交代をそのまま反映している。実行時の判断は表を引くだけなので、実行時の追加費用はほぼない。弱点は、較正が事前の測定と見積もりに依存する点で、較正に使った課題と違う分布の入力では採用率がずれ、表の最適性が崩れる可能性がある。

### 3. 参照表駆動の可変精度データパス — 直列の遅さを蓄積の工夫で補う

実行側は、ビット平面を単位とする保存と処理を採る。同じ桁のビットを集めて連続配置することで、下書きでは上位の平面だけを転送し、検証では残りの平面を足す、という読み分けが転送量と演算回数の両方にそのまま効く。演算は、活性値の組から全てのビットパターンに対する部分和を事前に作り、重みのビットを索引として参照表を引いて蓄積する方式で、乗算を参照と加算へ置き換える。共有指数の調整は参照表の生成時に織り込まれ、符号は符号平面を別に解釈する軽い回路で扱う。データの流れは参照表を各演算単位に留め、重みの平面を全体へ配信する形を取り、デコードのように行数が小さい演算でも再利用が効くようにしている。参照表の生成は次の組の実行と重ねて隠される。比較対象の計算面積が大きい中で提案の計算単位の面積が最も小さいことも報告されており、少なくともモデル評価の前提では、提案が面積で有利に評価を稼いでいる形にはなっていない。

| 構成要素 | 入力・観測 | 具体的な動作 | 改善対象 | 主なトレードオフ |
|---|---|---|---|---|
| ビット共有表現 | 対象の重みとキャッシュ | 指数を共有する表現で保持し、上位ビットだけを読んで下書きを作る | 下書きの交通と保存量 | 変換と組の保持の費用 |
| 精度参照表 | バッチと文脈長、較正済みの費用と採用率 | 条件ごとに最良の精度の組を引き、実行を切り替える | 条件ごとの費用と採用率の釣り合い | 較正した分布から外れると最適性が崩れる |
| 可変精度データパス | ビット平面単位のデータと活性値 | 参照表による蓄積をビット直列に行い、平面数で精度を変える | 混合精度実行の無駄 | 専用ハードウェアが前提になる |
| 対象の精度圧縮 | 対象表現そのもの | 対象も9ビット表現で保持し、検証自体も安くする | 検証の費用 | 近似が最終品質へ直接触れる |

1回の生成を通すと、参照表が精度を決め、下書きが部分読み込みで候補を作り、検証が全平面で確かめ、採用分が確定する。精度の切り替えは読み込む平面の数の変更だけであり、モデルの切り替えや再構成は発生しない点が、この共同設計の要である。

## 評価

### まず見るところ

結論は、ビット共有という一つの表現で下書き生成、精度選択、実行を貫くことで、固定精度の自己投機が持つ「効く範囲の狭さ」を広げられる、という設計の主張であり、モデル評価の数値はそれを裏づける形で提示されている。速度とエネルギーの改善は全条件で一貫し、採用率と対象圧縮の精度も実測で支えられている。ただし決定的な注意点として、速度とエネルギーの数値は、論理合成とメモリのモデルとサイクル単位のモデルを組み合わせた推定であり、実チップでも実装置でも測られていない。比較対象についても、一方は本来は汎用装置向けのカーネルとして提案された方式を、専用回路の形へ写像し直して比較しており、写像の前提が結果に影響し得る。したがって本論文は、実測で証明された性能ではなく、前提を揃えたモデル上で設計の優位を示した研究として読むべきである。

| モデル／モデル規模 | 30億級、80億級、140億級の指示調整モデル3種 |
| 精度形式 | 対象はブロック浮動小数点の9ビット表現（比較として16ビット表現も評価）、下書きは重みとキャッシュを5から9ビットで可変、活性値は16ビット |
| ランタイム／実装 | サイクル単位のモデルで計算、オンチップメモリ、外部メモリのアクセスと重なりを計算。全方式でメモリ階層と帯域の前提を統一 |
| データセット／ワークロード | 採用率と精度は符号生成、数学、符号生成の3課題で測定。速度はバッチ4と32、短文脈と長文脈の範囲で評価 |
| バッチ／同時要求数 | バッチ4と32が中心。下書きの候補数は7 |

| 比較対象 | 方式・比較上の意味 |
|---|---|
| 自己回帰（汎用型の演算配列） | 投機なしの基準。高速化とエネルギーの分母 |
| 浮動小数点のビット共有方式 | 対象表現から浮動小数点の情報で下書きを作る先行方式。短文脈に強い |
| 量子化キャッシュの自己投機方式 | キャッシュ量子化で下書きを作る先行方式。完全に自己投機な版と、量子化重みを別に持つ版の両方を比較 |

|---|---|---:|---:|---:|---|

### 感度・スケーリング・ストレス条件

精度の組の最適解は文脈長に対して系統的に動き、参照表の中身がその感度を具体化している。文脈が短い条件では先行の浮動小数点共有方式が相対的に強く、長い条件では量子化方式が強くなるという先行方式の偏りに対し、提案は両範囲で水準を保つ。分布の異なる入力での採用率の変化や、較正に使っていない課題での最適性の検証は限られており、感度の評価は較正に使った3課題の範囲が中心である。

### 立ち上がり・内部挙動

立ち上がりは事前較正に依存し、較正済みの条件では即座に最適な組が引ける。逆に、較正の範囲外のモデルや負荷では、表の新設か再較正が必要になる。内部挙動として、下書きの回数分の外部メモリアクセスがエネルギーと遅延の最大項目であり、部分読み込みの削減がそのまま全体の改善になる構造が内訳で示されている。

### 評価上の制約

- 速度とエネルギーは全てモデル評価による推定で、実チップや実装置での測定は未評価である。
- 比較対象の一方は、本来は汎用装置向けの方式を専用回路へ写像し直したもので、写像の前提が公平性に影響し得る。
- 精度と採用率の実測は3課題が中心で、対話や要約など他の分布での検証は限られる。
- 消費電力の絶対値は外部メモリの電力仮定に依存する相対評価である。
- 原稿は投稿中の下書きと明記されており、今後の査読で数値や主張が変わる可能性がある。

## 既存研究との差

層を飛ばす自己投機は構成の自由度が低く、特徴を再利用する方式は学習を要する。量子化を使う自己投機の先行方式は、浮動小数点の情報を共有するものと、キャッシュの量子化を中心にするものに分かれ、いずれも重みとキャッシュの扱いが非対称で、精度の適応も片側にとどまった。本論文は、両方を一つのビット共有表現で扱い、組としての精度選択を参照表で制度化し、さらにその可変精度を素直に実行できる専用データパスまでを一組にした点が異なる。混合精度アクセラレータの系譜に対しても、固定された精度の組み合わせを効率よく回すのではなく、投機の下書きと検証の行き来そのものを実行の単位にした点が新しい。

## 限界・実装状況

- 最大の限界は評価方法である。性能とエネルギーは合成とシミュレーションに基づくモデル評価であり、実チップでの実測がない。設計の優位は前提の中での話であり、実装置での再現は今後の検証を待つ。
- 専用ハードウェアが前提であり、汎用の加速器やプロセッサの上で同じ利得が得られるかは示されていない。ソフトウェアだけでの部分適用の効果は未評価である。
- 精度参照表は事前較正に依存する。較正に使った課題と分布の異なる入力、較正範囲外のバッチや文脈長では、採用率がずれて最適な組もずれる可能性がある。
- 対象表現への変換は重みについては事前に行えるが、キャッシュは推論中の変換と組の保持が必要であり、その実装費用と既存基盤への統合方法は詳しく示されていない。
- 原稿は学会投稿中の下書きであり、著者ら自身が配布不可と記した段階の文書である。数値の扱いにはその前提を付けるべきである。公式コードの公開案内も確認できなかった。

## 一般的な実装上の含意

負荷条件で支配的な資源が入れ替わる系では、最適な設定は1点ではなく条件ごとの面になる。事前に較正して参照表へ落とし、実行時は引くだけにする方式は、実行時の判断費用をゼロに近づけながら適応性を得る型として、精度以外の資源配分にも応用できる。また、アルゴリズムの自由度は実行基盤が受け止められる範囲でしか活きない。下書きの精度を細かく変えられる表現と、それを無駄なく実行できるデータパスを同時に設計した点は、共同設計の進め方そのものの見本である。ただし、モデル評価だけに基づく性能主張は、実測による裏付けが得られるまで割り引いて扱うべきだという注意も、本論文の読み方として残る。
