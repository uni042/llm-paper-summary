## 概要

LLM agentは一回の推論で終わらず、思考、tool呼出し、観測、再思考を長時間繰り返す。このため単一モデルのトークン スループットを上げても、不要な大モデル呼出し、増え続ける文脈、KV キャッシュを無視したリクエスト スケジューラ、過去セッションと似た文字列の再生成が残るとタスク完了時間は十分に短くならない。AgentInferはこれらを一つのエンドツーエンド agent システムとして共同最適化する。

四つの構成要素は、進捗に応じて大小モデルを切り替えるAgentCollab、KV キャッシュ価値を考慮するAgentSched、過去セッションをsuffix automatonへ統合してドラフト トークンを作るAgentSAM、reasoningを保ちながらenvironment interaction履歴を非同期要約するAgentCompressである。統合すると無効トークン消費を50%以上減らし、BrowseComp-zh/DeepDiverで精度を維持しながら1.8〜2.5倍のエンドツーエンド高速化を報告する。

## 問題設定

agent ワークロードではリクエストが互いに独立した短いchatではなく、同じセッションが長い文脈とKV キャッシュを持って再登場する。単純なshortest-job スケジューラはキャッシュを捨てて再プリフィルを増やす場合があり、逆にキャッシュ保持だけを優先すると短いリクエストが待つ。

さらに大モデルを全turnで使うと、簡単なtool操作にも高い計算費用を払う。文脈にはreasoning上重要な履歴と、検索結果・tool出力のように圧縮可能な環境情報が混在する。AgentInferはこれらの異質性をモデル selection、メモリ、スケジューラ、デコードの各層へ分けて扱う。

## 手法

### AgentCollab

大モデルは初期planningとreasoning stagnationからの回復を担当し、小モデルは進捗が順調な通常段階を担当する。各段階でprogress checkを行い、停滞時だけ大モデルへescalateし、回復後は小モデルへ戻す。これにより大モデル呼出し回数を減らしつつ、難しい局面のaccuracyを保護する。

### AgentSched

KV キャッシュ容量に余裕があるときは短いjobを優先し、メモリ pressureが高まるとキャッシュ 命中を価値として加えたKV-aware スケジューラへ連続的に移る。shadow priceを使って「新規KV allocationの費用」を表現し、固定policyではなく現在の容量とdemandに応じて優先順位を変える。

### AgentSAM

suffix automaton（接尾辞オートマトン; SAM）を使う投機的復号を、現在セッションだけでなく意味的に近い過去セッションへ拡張する。current 文脈と検索したhistorical SAMを合成し、繰り返しやすいagent表現からドラフト トークンを低オーバーヘッドで生成する。長文脈や大バッチで投機利得が小さいときは適応的に無効化する。

### AgentCompress

メモリをreasoning メモリとenvironment-interaction メモリへ分け、後者を文脈 閾値超過時に非同期圧縮する。進行中のreasoningをブロックせず、検索結果やtool出力を短く再構成することでプリフィルと注意機構対象トークンを減らす。

## 評価条件

| 項目 | 条件 |
|---|---|
| ベンチマーク | BrowseComp-zh、DeepDiver |
| 主指標 | タスク accuracy、エンドツーエンド 遅延/QPS、トークン消費 |
| 構成要素 | AgentCollab、AgentSched、AgentSAM、AgentCompress |
| ワークロード | multi-turn reasoning + tool interaction |
| 比較 | 大モデル単独、各構成要素なしの比較対象 |

## 主要結果

| 構成 | 結果 |
|---|---:|
| 統合AgentInfer | エンドツーエンド 1.8〜2.5倍高速化 |
| 統合AgentInfer | 無効トークン消費50%以上削減 |
| AgentCollab例 | accuracy 33.8%（large-only 34.6%、small-only 18.3%）、1.32倍高速化 |
| AgentSched | 平均LLM call 遅延 0.902倍、KV 命中 63%→72% |
| AgentSAM | LLM 遅延最大26%削減、エンドツーエンド最大21.2%改善 |

構成要素ごとの結果から、統合利得は単一カーネルの高速化ではなく、大モデル呼出し削減、文脈短縮、キャッシュ再利用、デコード ドラフトの累積で生じる。16 並列 セッションでは統合時にQPS 2.52倍という条件も報告される。

## 既存研究との差

通常のLLM 推論提供はリクエスト-level TTFT/TPOTやトークン/sを主指標にし、agentのtool待ちやreasoning loopを外側のapplication問題として扱う。AgentInferはタスク completionを最終目的に置き、モデル ルーティング、文脈 management、KV スケジューラ、投機的復号を同じagent lifecycleへ接続する。

## 限界

agent ベンチマークとtool interaction patternへの依存が大きく、単純chat ワークロードで同じ倍率が得られるとは限らない。AgentCollabはprogress self-evaluationが誤ると不要なescalationまたは品質低下を起こし得る。AgentSAMは過去セッションに再利用可能なpatternが少ない場合、AgentCompressは要約可能なenvironment履歴が少ない場合に利得が縮む。公式実装URLは確認した一次資料から特定できなかった。
