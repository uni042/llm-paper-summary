# Learning Harmonized Representations for Speculative Sampling

> EAGLE系ドラフトの学習時／復号時の文脈差と蒸留目的のずれをTop-K蒸留＋multi-step context alignmentで揃えるHASS。

## 概要

投機的復号（speculative decoding）は、小さなドラフトモデルに先のトークン候補を複数生成させ、大きな対象LLMがまとめて検証することで、対象LLMを1トークンずつ呼び出す回数を減らす。最終的な採否は対象モデルが決めるため、検証規則を変えなければ元の出力分布を保ったまま高速化できる。

この方式の性能を決める重要な指標が**acceptance length (	au)** である。1回のdraft→verify周期で、対象モデルが平均何トークン受理するかを表す。受理長が長いほど1回の対象モデル実行で先へ進めるため、wall-clock speedupが大きくなりやすい。

EAGLE/EAGLE-2は、単なる小型言語モデルではなく、対象LLMの中間hidden stateを利用する軽量draft modelを学習することで受理率を高める。しかしHASSは、EAGLE系の学習には2つの「学習時と実際の復号時のずれ」が残っていると指摘する。

1つ目は**objective mismatch**である。蒸留時には語彙全体の分布へ合わせようとする一方、実際の投機検証で重要なのは、対象モデルが高確率を与える「採用され得る候補」の順位を正しく合わせることにある。2つ目は**context mismatch**で、学習時には正確なtarget hidden stateを前提に次のdraft featureを予測するのに、実際の自己回帰draftでは2歩目以降、自分が予測した不正確なfeatureを入力に使う。その誤差が後段へ累積する。

HASS（HArmonized Speculative Sampling）は、Top-K候補を重視する**Harmonized Objective Distillation**と、過去draft featureを学習時にも再利用する**Harmonized Context Alignment**でこの2つを揃える。変更は学習側だけなので、推論時のdraft model構造やverification条件はEAGLE-2と同じまま使える。LLaMA2-Chat 7B/13B、LLaMA3-Instruct 8B/70Bで、自己回帰生成比2.81〜4.05倍の平均高速化を報告し、EAGLE-2を8〜20%上回る。

## 問題設定

### 投機的復号では「全語彙を似せる」ことが最終目的ではない

draft modelは対象モデルより小さいため、両者の確率分布を完全一致させることは難しい。しかし投機的復号で本当に必要なのは、対象モデルが受理しやすい候補をdraft側も上位へ出せることである。

対象モデルがほぼ選ばない低確率トークンまで均等に蒸留しても、acceptance lengthへ直接効かない可能性がある。HASSはこの点を推薦システムのranking distillationに近い問題として捉え、target LLMの上位候補を優先して学習する。

### EAGLEの学習時と推論時で「前のfeature」が違う

EAGLEでは、対象LLMの上位層hidden stateをdraft modelへ渡し、次時刻のhidden stateを予測する。学習時は各位置についてtarget LLMが生成した正確なfeatureを入力に使えるため、並列に教師あり学習できる。

しかし実際のdraft生成では、最初の1歩だけtarget featureを使い、2歩目以降はdraft model自身が直前に予測したfeatureを使う。予測誤差を含むfeatureを再入力するため、stepが深くなるほど誤差が積み重なる。

EAGLE-2はdraft treeを動的に構成して探索効率を上げるが、このfeature contextの不一致自体は残る。HASSはtree searchではなく、その前段の**draft representation学習**を推論時条件へ近づける。

## 手法

### 1. Harmonized Objective Distillation — targetのTop-K候補へ学習を集中する

HASSはtarget LLMの次トークン分布から確率上位K個の集合 (hat{Omega}) を取り、その候補だけに蒸留損失を掛ける。

[
L_{Top-K}=-sum_{xinhat{Omega}}q(x)log p(x)
]

ここで (q(x)) はtarget LLM、(p(x)) はdraft modelの確率である。語彙全体を同じ重要度で一致させるのではなく、実際のverificationで受理候補になりやすい部分を重点的に合わせる。

EAGLEではtarget hidden stateとLM headを学習時に利用できるため、Top-K集合を得るために別の大型モデル推論を追加する必要はない。論文の主設定ではK=10、Top-K lossの重みを1.0としてEAGLEのfeature regression lossへ追加している。

### 2. なぜTop-Kだけが効くのか

acceptance lengthはtarget/draft間の分布差に依存するが、全語彙での平均的な差より、targetが実際に選び得る上位候補での順位ずれの方が受理判定へ強く効く。

構成要素除去ではTop-K lossを加えた設定がlossなしより一貫して改善した。一方、Kを小さくし過ぎると1位候補だけへ過度に集中し、温度付きsamplingで選ばれ得る他候補を無視する。LLaMA2-Chat 7Bの感度評価ではK=5付近でacceptance lengthが最大となり、単純にK=1が最適ではない。

### 3. Harmonized Context Alignment — 学習時にも自分の誤差を再入力する

context alignmentでは、draft modelを学習中に複数step呼び出す。第1 stepはEAGLEと同じで、正しいtarget featureからdraft feature (f^{(s_1)}) を作る。

第2 stepでは、その (f^{(s_1)}) を現在queryへ使い、key/value側にもtarget featureだけでなく前stepのdraft featureを混ぜる。第3 step以降も同様に、より古い部分はtarget feature、直近部分は過去draft stepで生成したfeatureという形にする。

これにより、推論時に「自分の予測featureを受け取って次を予測する」状態を学習中にも再現する。教師featureだけを見て訓練したモデルが、deploymentで突然自己生成featureへ切り替わるteacher-forcing gapを小さくする発想に近い。

### 4. attention maskを変えてmulti-step alignmentを並列学習する

素朴に推論と同じ自己回帰を学習中に再現すると、各stepを逐次実行するため学習コストが大きくなる。HASSはattention maskを調整し、各training step内では系列位置を並列処理しながら「どの位置がtarget featureを見るか／過去draft featureを見るか」を制御する。

主実験ではcontext alignmentを3 stepまで行う。EAGLEより追加training overheadはあるが、decode時にはこのmulti-step学習処理を実行しないため、**推論オーバーヘッドはEAGLE-2と同じ**である。

### 5. EAGLE-2のdynamic draft treeはそのまま利用する

HASSはdraft tree探索やverificationルールを置き換える方式ではない。EAGLE-2のdynamic treeを使い、総draft token数60、tree depth 6など同等のdecode条件で比較する。

したがって高速化は、探索アルゴリズムを軽くした結果ではなく、同じように候補を展開・検証したときに**より多くの候補がtarget LLMへ受理される表現を学んだ結果**として読むことができる。

## 評価

### 代表的な評価条件

| 項目 | 内容 |
|---|---|
| target LLM | LLaMA2-Chat 7B / 13B、LLaMA3-Instruct 8B / 70B |
| タスク | MT-bench、HumanEval、GSM8K |
| batch | 1 |
| GPU | NVIDIA H800 |
| sampling | temperature 0 / 1 |
| 比較 | 自己回帰、PLD、Lookahead、vanilla speculative sampling、Medusa、EAGLE、EAGLE-2 |
| EAGLE系学習データ | ShareGPT 68,000 dialogues |
| HASS主設定 | Top-K K=10、loss weight 1.0、context alignment 3 steps |
| draft tree | total draft tokens 60、depth 6 |

Speedup Ratioは通常の自己回帰生成を1.0倍とした実時間比で、Acceptance Length (	au) は1回のdraft-verification周期で平均何トークン受理されたかを表す。HASSはtarget LLMの重みとverification条件を変えないため、論文ではlossless accelerationとして速度と受理長を主に評価する。

### acceptance length

| target | EAGLE-2 平均 (	au) | HASS 平均 (	au) | 傾向 |
|---|---:|---:|---|
| LLaMA2-Chat 7B, T=0 | 4.61 | 5.15 | 後段draft tokenまで受理されやすい |
| LLaMA2-Chat 13B, T=0 | 5.16 | 5.58 | EAGLE-2より長い連続受理 |
| LLaMA3-Instruct 8B, T=0 | 4.52 | 5.08 | model familyを跨いで改善 |
| LLaMA3-Instruct 70B, T=0 | 4.50 | 5.21 | 大型targetでも改善 |
| LLaMA3-Instruct 70B, T=1 | 4.43 | 5.16 | sampling時にも改善 |

例えばLLaMA3-70B・temperature 0では、MT-bench/HumanEval/GSM8K平均のacceptance lengthがEAGLE-2の4.50からHASSの5.21へ伸びる。1回のtarget verificationで約0.7 token多く進めることが、実時間高速化へつながる。

### 実時間高速化

論文全体では、4種類のLLaMA × 3タスク平均でHASSが自己回帰比2.81〜4.05倍のwall-clock speedupを達成し、EAGLE-2比で8〜20%改善する。

LLaMA2-Chat 7Bではtemperature 0の3タスク平均がEAGLE-2 2.81倍に対しHASS 3.24倍、temperature 1では2.60倍に対し2.90倍である。受理長だけでなく実時間でも改善が再現される。

### 構成要素除去

Top-K lossの重みを0にするとacceptance lengthが低下し、上位候補に重点を置くobjective alignmentが有効であることを確認している。Kも極端に小さいと悪化し、targetの複数有力候補を残す必要がある。

Context alignmentでは複数training stepを入れることで改善するが、stepを増やすほど学習費用も増える。論文は小さいstep数で効果が収束するとし、主設定では3 stepsを採用する。reweight factor (eta) のLLaMA3-70B評価では0.5付近で平均acceptance length 4.65となり、default 1.0の4.61をわずかに上回るなど、自己生成featureをどの程度強く混ぜるかにも感度がある。

## 既存研究との差

Vanilla speculative samplingは独立した小型LMをdraftに使うため、対象モデルとの能力差が受理率を制約する。EAGLEはtarget hidden stateを利用することでdraftを強化し、EAGLE-2はさらにdynamic treeで良い候補へ探索を集中する。

HASSはその探索器をさらに複雑にするのではなく、**EAGLE系draft modelの学習目標と学習文脈を、実際のverification・自己回帰draft条件へ揃える**。objective側は「全語彙を似せる」から「target上位候補を正しく順位付けする」へ、context側は「常に正しいteacher featureを見る」から「自分の過去予測誤差も見た状態で学習する」へ変える。

## 限界

HASSは推論時オーバーヘッドを増やさない代わりに、draft modelの追加学習が必要である。対象モデルを変更した場合は、そのtarget hidden stateと分布に合わせてdraftを再学習する必要がある。

またmulti-step context alignmentはtraining step数だけ追加計算・メモリを使う。論文は小さいstep数で収束すると報告するが、最適step数やTop-KのK、loss weightは対象モデル・データに依存する。

実時間speedupはH800・batch 1・EAGLE-2実装上の値である。大バッチや別GPUではtarget verificationとdraft生成の相対コストが変わるため、同じacceptance length改善が同じ倍率のwall-clock高速化へ直結するとは限らない。
