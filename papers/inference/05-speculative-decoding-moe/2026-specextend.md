# SpecExtend: A Drop-in Enhancement for Speculative Decoding of Long Sequences

> 対象モデルの注意重みでドラフト側KVキャッシュの重要文脈を動的選択し、再学習なしで長文の投機的復号を高速化する拡張。
## 書誌情報
- **著者**: Jungyoub Cha, Hyunjong Kim, Sungzoon Cho
- **公開**: Findings of the Association for Computational Linguistics: ACL 2026
- **種別**: conference_findings
- **対象**: 投機的復号、長文推論、KVキャッシュ、効率的注意機構
- **実装**: 著者実装が公開されている。論文は既存の投機的復号へ追加できる再学習不要の構成として評価している。
## 概要
長い入力で投機的復号の性能が早期に崩れる問題に対し、再学習なしで既存方式へ追加できる拡張を提案する。対象モデルの注意重みを利用してドラフトモデルのKVキャッシュから現在の生成に重要な文脈チャンクを動的に選び、ドラフトの計算量と対象モデルとの分布ずれを同時に抑える。さらに事前充填と検証に効率的注意機構を組み合わせ、短い入力での既存方式の強みを維持しながら長文要約と長い推論出力で実測速度を改善する。

SpecExtendの中心的な新規性は、対象モデルを追加の前向き計算なしで疎な検索器として使い、その直近の検証時に得た注意重みからドラフトモデルに必要な文脈を選ぶモデル間検索である。大きな対象モデルが重要と判断したチャンクだけを小型ドラフト側の作業KVキャッシュへ残すことで、単なる位置ベース削除ではなく両モデルの有効文脈を動的に整合させる。これを効率的な事前充填・検証機構と組み合わせ、既存ドラフトを再学習せず差し込み可能にした点が特徴である。

代表結果として、標準投機的復号に対する速度向上はLlama-3.1-8B-Instruct系を含む16K長文要約設定でSpecExtendなしの標準投機的復号に対して最大2.84倍。長い入力で低下するドラフト精度と注意計算の双方を改善し、既存投機方式への追加だけで大きな速度回復を得た。
## 問題設定
投機的復号では小さなドラフトモデルが候補トークンを生成し、大きな対象モデルがまとめて検証する。しかし入力が長くなると、KVキャッシュが主なメモリ律速になるほど極端に長くなる前から速度が低下する。原因は、対象モデルとドラフトモデルの双方で注意計算が重くなることに加え、短い文脈で学習された小型ドラフトモデルの精度が長文で落ち、対象モデルとの分布差が広がって受理長が短くなることにある。既存の長文向け方式は大きな対象モデル自身でドラフトしたり、長文専用ドラフトを再学習したりするため、中程度の長さでモデル重みが依然として支配的な領域では速度上の利点が小さい。静的KV削減は高速化できても、過去の重要文脈を落としてドラフト精度を損ねる。
## 新規性
SpecExtendの中心的な新規性は、対象モデルを追加の前向き計算なしで疎な検索器として使い、その直近の検証時に得た注意重みからドラフトモデルに必要な文脈を選ぶモデル間検索である。大きな対象モデルが重要と判断したチャンクだけを小型ドラフト側の作業KVキャッシュへ残すことで、単なる位置ベース削除ではなく両モデルの有効文脈を動的に整合させる。これを効率的な事前充填・検証機構と組み合わせ、既存ドラフトを再学習せず差し込み可能にした点が特徴である。
## 手法
### 手法のあらまし
入力の事前充填では対象モデルとドラフトモデルの双方にFlashAttentionを用い、長い入力全体に対する中間注意行列の実体化を避けて初期計算を軽くする。生成ループでは小型ドラフトモデルが複数候補を作り、対象モデルが木構造の候補をまとめて検証する。この検証にはHybrid Tree Attentionを用いて長いKV系列方向の並列性を確保する。モデル間検索を行う回では、入力接頭辞を固定長チャンクに分割し、最後に受理されたトークンを問い合わせとして対象モデル最終層の注意重みを集約する。平均注意重みでチャンクを順位付けし、上位kチャンクだけをドラフトモデルの作業KVキャッシュへ反映する。対象モデルの検証は通常FlashDecoding系で完全な注意行列を生成しないため、最終層だけ標準注意へ切り替えて重みを取得し、それ以前の層は高速経路を維持する。得られた注意重みは直近の検証計算の副産物なので、検索のための追加の対象モデル前向き計算は不要である。縮小されたドラフトKVは注意計算を短くしつつ、対象モデルが現在重要と判断した遠距離文脈を保持するため、ドラフト速度と受理精度の双方を改善する。検証・補正そのものは標準投機的復号を維持するため、出力分布を変えずに既存方式へ追加できる。

### モデル間検索（Cross-model Retrieval）
対象モデルの直近の検証で得た最終層の注意重みを、ドラフト側のKVキャッシュ選択信号として再利用する。入力接頭辞を固定長チャンクへ分割し、最後に受理されたトークンから各チャンクへの平均注意重みを計算して上位k個を選ぶ。選択チャンクで小型ドラフトモデルの作業KVキャッシュを更新するため、保持量を減らして注意計算を軽くしながら、位置だけで決める静的削除では失われやすい遠距離の意味的に重要な文脈を残せる。対象モデルとドラフトモデルの自然な分布ずれを抑え、候補の受理長を伸ばすことが狙いである。検索信号取得のための追加前向き計算は行わず、更新頻度も下げられるため追加費用を小さく抑える。

### 効率的事前充填と木構造検証
長文で増える対象・ドラフト双方の注意計算を抑えるため、事前充填にはFlashAttentionを適用し、大きな中間注意行列を高帯域メモリへ展開する負担を避ける。生成中の対象モデル検証にはHybrid Tree Attentionを使い、投機候補の木構造を保ったままKV系列方向の並列化を利用する。ただしモデル間検索に必要な注意重みを得るため、対象モデルの最終層だけは標準注意で計算し、他層は高速経路を維持する。短い入力では木構造検証の追加費用が利点を上回るため、論文では4Kトークンを超える入力で有効化している。

### 全体のデータ／制御の流れ
既存の投機的復号実装を基盤とし、事前充填、ドラフト、対象モデル検証、ドラフトKV更新の各段階へ局所的に追加する設計である。対象モデルの完全KVキャッシュは保持したままなので正確な検証を維持し、縮小するのはドラフト側の作業KVだけである。モデル間検索のキャッシュ更新は16K入力で0.34ms、注意重み取得を含む対象前向き計算は53.76msから54.11msへの増加と報告され、更新自体は単一ドラフト前向き計算より短い。極端な長文では対象モデル側の完全KV注意が残るため、入力長に伴う速度低下そのものは消えない。
## 評価条件
- **ハードウェア**: 主要実験は単一のNVIDIA A100 80GB GPU。Vicuna/LongChat向けEAGLEドラフトの学習には4基のA100 40GB GPUを使用したと付録に記載される。
- **ソフトウェア**: 標準の木構造投機的復号、EAGLE、EAGLE-3を基盤に、FlashAttention、FlashDecoding互換のHybrid Tree Attention、モデル間検索を組み合わせる。比較対象はFlashDecoding、TriForce、MagicDec、StreamingLLM等。
長文要約ではVicuna-7B-16KまたはLongChat-7B-16Kを対象モデルとし、Vicuna/LLaMA-68MまたはEAGLEをドラフトとしてGovReport、PG-19、BookSumを1K〜16K入力で評価し、256トークンを生成する。各入力長で20入力を抽出し各2回実行して平均する。長い推論ではDeepSeek-R1-Distill-Llama-8BとEAGLE-3をAIME-24で最大32K生成まで評価する。さらにLlama-3.1-8B-InstructとEAGLE/EAGLE-3、およびPG-19で最大128K入力も調べる。
実GPU上の単一GPUレイテンシ・トークン毎秒・平均受理長を中心とした評価であり、分散サービングや多利用者スループットの評価ではない。長文要約、長い推論、針検索を含み、短文から128Kまでの入力長依存性を確認する一方、主結果は7B〜8B級対象モデルと特定のドラフト構成に集中する。
## 主要結果
SpecExtendは入力長が伸びるほど崩れやすい標準投機的復号の受理長と実効速度を回復し、特に8K〜16K以上で効果が大きい。長文要約では既存ドラフトモデルを再学習せず、16K入力で標準投機的復号に対して最大2.84倍、長い推論ではEAGLE-3へ追加して3.86倍の高速化を示した。アブレーションではモデル間検索が16Kで最大の寄与を持ち、単なる注意カーネル高速化だけでなくドラフト精度の回復が主要因であることを示す。

- 標準投機的復号に対する速度向上 / 最大2.84倍 (比較対象: SpecExtendなしの標準投機的復号; 条件: Llama-3.1-8B-Instruct系を含む16K長文要約設定) — 長い入力で低下するドラフト精度と注意計算の双方を改善し、既存投機方式への追加だけで大きな速度回復を得た。

- 長い推論での速度向上 / 標準EAGLE-3比3.86倍、単純自己回帰比3.73倍 (比較対象: EAGLE-3単体および単純自己回帰生成; 条件: DeepSeek-R1-Distill-Llama-8B / EAGLE-3、AIME-24、最大32K生成) — 短文では強いEAGLE-3が長い生成で急激に失うドラフト精度をモデル間検索が回復し、長い思考列でも投機の利点を維持した。

- ドラフト精度の改善 / 平均受理長で最大2.55倍 (比較対象: SpecExtendなし; 条件: 最大16K入力の新しいモデル構成) — 対象モデル由来の重要文脈を小型ドラフトへ与えることで、静的位置削除より対象・ドラフト分布を近づけられることを示す。

- 構成要素単独の速度寄与 / 16KでCMR 1.46倍、FlashAttention 1.25倍、Hybrid Tree Attention 1.19倍 (比較対象: Vicuna-7B/68Mの標準木構造投機的復号; 条件: GovReport、16K入力) — 最も大きい寄与はモデル間検索であり、カーネル高速化だけでは説明できない。

- 極長入力での速度 / 128Kで22.59 トークン/s、標準設定8.45 トークン/s (比較対象: SpecExtendなし; 条件: Llama-3.1-8B-Instruct / EAGLE、PG-19、128K入力) — KVキャッシュが主要律速になる領域でも縮小ドラフトKVが有効で、標準投機的復号の急激な劣化を緩和する。

### 負の結果・境界条件
- 入力が長くなるほどトークン生成速度そのものは依然として低下する。対象モデルは完全KVキャッシュで前向き計算するため、対象側の事前充填と復号が長文で律速として残る。また長文専用に学習したLongSpecのような方式を速度で上回るところまでは到達しない。Hybrid Tree Attentionは短い入力では小さな追加費用があり、論文では4K超でのみ有効化している。

### 結果の読み方
中程度の長さではモデル重みがまだ大きな律速なので、大型対象モデル自身をドラフトに使う長文向け方式は不利である。SpecExtendは小型ドラフトを維持したまま、そのKVだけを対象モデルの注意情報で意味的に絞るため、計算量を下げつつ受理率も上げられる。入力がさらに長くKV容量が支配的になっても縮小ドラフトKVは効くが、対象モデル側の完全KV処理は残るため改善率には上限がある。
## 品質への影響
標準の投機的復号が持つ検証・補正手続きを維持する損失なしの高速化であり、生成品質を落として速度を得る方式ではない。報告された改善は主に受理長、レイテンシ、トークン毎秒の改善で、対象モデルの出力分布を近似へ変更するものではない。
## 既存研究との差
TriForceやMagicDecは極長文で対象モデル側の疎なKVを使ってドラフトするため、モデル重みが支配的な中程度の長さでは大型モデルを動かす費用が残る。LongSpecは長文専用ドラフトを学習するのに対し、SpecExtendは既存の小型ドラフトを再学習せず利用する。StreamingLLMの静的位置削除と異なり、対象モデルの注意重みを用いて現在必要な遠距離文脈を動的に選ぶため、速度だけでなくドラフト精度と対象モデルとの整合も改善する。
## 限界
対象モデルの完全KVキャッシュは削減しないため、長文で増大する対象モデル側の事前充填・復号計算は残る。したがって入力長増加に伴う絶対速度低下を消すものではない。評価は主として7B〜8B級モデルの単一A100実測であり、大規模分散サービング、多利用者混在、より大きな対象モデルへの一般化は直接検証されていない。長文専用ドラフトを学習するLongSpec等を速度で上回るものでもない。
## 実装状態
著者コードがGitHubで公開されており、論文はVicuna、LongChat、Llama-3.1、EAGLE、EAGLE-3等との組合せを実装・評価している。FlashAttention、Hybrid Tree Attention、モデル間検索の統合が必要で、対象モデル最終層だけ注意重みを取得する変更を加える。
## 研究上の位置づけ
長文向け投機的復号の中でも、KVキャッシュが支配的になる極端な長さだけでなく、それ以前の中程度の長さで起きる速度低下を明示的に対象化した研究である。小型ドラフトのモデル重み上の利点を残しつつ、対象モデルを検索信号源として利用してドラフト文脈を整えるため、投機的復号とKVキャッシュ削減を結ぶ位置にある。既存の短文向け高性能ドラフトをそのまま長文へ拡張できる差し込み型の設計として、再学習方式と静的キャッシュ削減方式の間を埋める。
