# Phase-Scoped Query Layouts for Reference-Preserving Speculative Decoding

> 投機的検証で変わる注意のクエリ配置をビュー変換で局所的に直し、参照出力をビット級に保ちながらクエリ単位注意より最大6.17パーセント速くし、状態とバックエンドの転移限界も切り分けた研究。

## 概要

投機的復号（speculative decoding）は、小さな下書きモデルが複数トークンを提案し、対象モデルがまとめて検証することで、対象モデルの逐次呼び出しを減らす手法である。ところが検証では、通常の継続が1位置ずつ進めるのに対し、複数のクエリ位置を同時に評価するため、対象モデルの実行の幾何、つまりテンソルの組み方と演算の順序が変わる。浮動小数点の評価はこの幾何に依存するため、アルゴリズムとして数学的に等価でも、量子化した配置では貪欲な生成結果が既存の参照出力と食い違うことがある。導入済みの実行レシピを回帰の基準として守らなければならない配置では、このずれ自体が障害になる。

本論文が守る対象は、モデルとトークナイザのバイト列、プロンプト構成、数値ランタイム、サンプリングと停止規則まで含めた参照であり、候補の実行経路は完全なトークン列が参照と一致して初めて、遅延を参照保存の高速化として比較できる。提案するQB（query-to-batch）は、フラッシュでない注意の内部だけで働く局所的な修理である。全体を直列化する方式GSは対象の行を射影、注意、フィードフォワードまで1行ずつ処理し、クエリ単位注意PQは周囲のバッチを保ちながらクエリごとに注意の部分グラフを作る。これに対しQBは、クエリテンソルを（d、q、h、1）から（d、1、h、q）へのビューとして読み替え、マスクも対応するビューへ組み替え、KとVは共有したまま、同じ局所的な分離をビューの読み替えだけで表す。

**代表結果:** 2日にわたる6セッションのCUDA実験で、QBはPQに比べて投機的リクエスト遅延をQwen3で3.06パーセント、SmolLM2で6.17パーセント、Llamaで2.83パーセント下げ、固定パネルで参照出力との完全一致を保った。別途72文脈のCUDAリプレイでは、3つの層位置、両方の実行段階、クエリ幅1から4の全組合せで、QBとPQがQK、ソフトマックス、AVの各段階でビット単位に一致した。高速化の数値自体は小さいが、参照を壊さずに得た局所的な実装利益である点と、その利益が状態形成やバックエンドの受理条件に依存して転移しない場合がある点まで含めて示すのが本論文の形である。

## 問題設定

資源の観点では、問題は計算量ではなく数値の再現性とグラフ構築の費用である。投機的検証は対象モデルの呼び出し回数を減らすが、その代わりにクエリのバッチの組み方が変わり、量子化した重みの下では丸めの違いがargmaxを跨いで最終トークンを変え得る。参照を守る素朴な方法は全体直列化GSだが、射影やフィードフォワードまで1行ずつ処理するため、バッチ計算の利益を丸ごと捨てる。PQは注意だけをクエリ単位に分けるため周囲のバッチを保てるが、クエリごとに部分グラフを構築し結果を連結する費用が残る。

既存の数値一貫性の研究は、リダクションの制御、実行形状の固定、固定形状の検証とロールバックなどで安定化を図る。本論文の問いかけは配置の接点にあり、注意の局所的な表現だけを変えて、対象全体のバッチを保ったまま、明示的なクエリ分離より安く参照を再現できるか、である。さらに本論文は、局所的な修理が正しくても、それが消費する状態が上流の異なる実行で作られていれば結論が移らないこと、数学的に合法なビューでもバックエンドが受理しないことがあることを、転移の条件として分けて扱う。

## 手法のあらまし

処理の流れは、通常の投機的トランザクションを一切変えないことから始まる。下書きが最大kトークンを提案し、対象は保留トークンと提案位置を評価し、受理、修正、ボーナスで確定接頭辞が決まり、却下位置は次の周期の前に調整される。QBが変えるのはこの内部の注意の表現だけである。対象のプリフィルと継続、下書きのプリフィルと継続の4段階にビットを割り当てた段階マスクで変換の適用範囲を決め、役割と段階から決まる有効フラグをグラフのパラメータへ入れ、キャッシュしたグラフの再利用の検査にもそのフラグを含める。注意ではクエリとマスクのビューを組み替え、元のクエリ列のストライドを新しい第4軸のストライドとして保ち、KとVは単一ストリームのまま新しいクエリのバッチ座標へブロードキャストし、QK、ソフトマックス、AVの後に元の順序へ戻してバッチの出力射影へ渡す。診断の観測を切った高速経路でもガードは先に実行され、修理が観測の有無で消えないようになっている。

## 手法

### 1. クエリとマスクの対ビュー変換 — 同じスカラーを指す読み替え

この機構が観測するのは、注意へ入るクエリテンソルとマスクの形状、ストライド、ヘッド対応である。保持する状態は新しいビュー記述子であり、値そのものは複製しない。処理は、クエリを（d、q、h、1）から（d、1、h、q）へ、マスクを（n、q、1、1）から（n、1、1、q）へ読み替え、チャネル、ヘッド、論理クエリの各要素が元のアドレスと同じスカラーを指すことをアドレス式で保証することである。グループ化クエリ注意のヘッド対応は元の対応をそのまま使い、KとVは共有される。これにより減るボトルネックは、PQがクエリごとに部分グラフを作り連結するグラフ構築と実行の費用であり、射影とフィードフォワードはバッチのまま残る。追加で消費する資源はビューの管理と順序復元であり、値の複製は起きない。失敗条件として、ストライドの前提が成り立たない配置や、クエリ依存の因果マスクを共有列で置き換えるような誤った読み替えでは意味が壊れるため、元のマスク値とキー範囲をそのまま保つことが義務になる。厳密算術ではQBと元の注意が同じ論理出力を返すことが命題として示されるが、浮動小数点の結合順やデバイスのアルゴリズム選択までは保証しないため、数値の一致は実験で別途確かめる設計である。

### 2. 段階の束縛とグラフ再利用の整合 — どの段階で直すかを固定する

この機構が観測するのは、現在の役割と段階であり、対象プリフィル、対象継続、下書きプリフィル、下書き継続に1、2、4、8のビットを割り当てる。保持する状態はプロセス固定の4ビットマスクと、スコープに入る前のフラグの値である。処理は、リクエストのリセットで段階をプリフィルへ戻し、役割と段階のビットから有効フラグを導いてグラフパラメータへ入れ、終了時に前の値を復元すること、そしてキャッシュしたグラフのレイアウトフラグが現在の要求と違えば再利用を拒否することである。先行する16通りのマスク実験では3、7、11、15が通過し、対象の2段階だけを有効にする3が包含の意味で最小だったため、以後の評価はマスク3で固定される。これにより減るボトルネックは、段階の取り違えやレイアウトの違うグラフの誤った再利用による静かな参照破壊である。追加費用はフラグ管理と再利用拒否時のグラフ再構築である。誤った場合の挙動として、下書き段階まで広げても有用な高速化は得られなかったことが補足資料に残され、適用範囲を広げること自体が利益にならないことが示される。

### 3. 受理条件 — 対応できる配置を方法の一部として限定する

この機構が観測するのは、対象グラフの特徴であり、単一の系列とKVストリーム、フラッシュでない注意、対応するQwen3系または密なLlama系のグラフ経路、互換なヘッド次元、整数のグループ化クエリ比、F32のクエリとマスク、F16のKとV、占有クエリ最大4件が条件になる。保持する状態はソース側のガードであり、注意のバイアスやシンク、多頭潜在注意の値射影などは除外される。処理は、条件を満たさない場合に変換を適用せず、宣言した未変換グラフを保つか、対応しない有効ケースを拒否することである。これにより減るボトルネックは、意味の違う配置へ変換を誤適用して参照を壊す事故である。追加費用は適用範囲の狭さそのものであり、複数ストリームや融合注意カーネルではこの結果を継承できない。失敗条件は評価の節で実際に現れ、Vulkanバックエンドでは持ち上げたクエリ軸が必要条件に反して受理されなかった。つまり合法なビューと実行可能なバックエンド対応付けは別の問題であり、バックエンドごとに演算子対応を検証しなければならない。

## 評価

結論は、QBが参照保存の局所的な修理として実際に安く利くこと、そしてその利益の転移には状態とバックエンドの別条件が要ることの二点である。大きな凍結パネルの確認では、家族ごとに24入力で修理済みの対象のみ経路と投機経路が240件すべての終端で参照と一致したのに対し、無制約のバッチ経路はQwen3で5件、SmolLM2で14件、Llamaで9件の課題で失敗し、容量を合わせるだけでは参照を再現できないことが分かる。72文脈のリプレイでは、PQとQBが全段階でビット単位に一致し、多クエリの54文脈では元の多クエリ経路がQKで最大0.078583の絶対差を示したため、一致は自明な同一経路の結果ではない。6セッションの再現実験では1620リクエストが失敗なく完了し、投機経路の比は1.0316、1.0658、1.0291で、いずれも事前に宣言した実用閾値1.02を上回った。対象のみ経路の効果は小さく、Llamaでは1.0156と閾値を下回るため、利益は投機の文脈でこそ安定すると読める。

転移の境界も対照実験で示される。Vulkanの実験では、プリフィルを外部で分割するかどうかでKV状態が変わり、単一クエリの継続でも生成47番目や81番目で分岐した。状態の部品置換では、終端が一致する状態同士でも層0のKやVだけの置換で第三の軌跡が生まれる場合があり、置換範囲を広げれば効果が保たれる単調性も否定された。さらに固定したVulkanバックエンドでは、持ち上げたクエリ軸が第4軸の範囲の一致という必要条件に反し、QKとAVの両方が拒否された。未評価の点として、本番スループット、継続的なGPU常駐、部品ごとの時間内訳、エネルギー効率はどちらの基盤でも確立されておらず、長い文脈での挙動もリプレイの範囲外である。

## 既存研究との差

バッチ不変カーネルで数値評価を安定化する研究や、プリフィル分離と固定形状デコードを組み合わせる研究、固定形状の検証とロールバックで高速経路を確かめる研究との差は、注意の局所的なグラフ表現に対象を絞り、周囲のバッチ計算を一切直列化しない点にある。従来の局所修理であるPQと同じ分離を、部分グラフではなくビューで表すことで構築費用を削るのが新規の実装判断である。加えて本論文は、修理の正しさだけでなく、状態の合成とバックエンドの受理という転移条件を対照実験で切り分けた点で、高速化の報告に留まる研究と異なる。

## 限界・実装状況

限界は、対応配置が単一ストリーム、非フラッシュ注意、占有クエリ最大4件などに限定されること、長い文脈での数値対応が未確認であること、Vulkanでは固定したバックエンドの演算子条件により変換が受理されず移植が成立しないこと、状態形成が上流の実行に依存するため局所修理だけでは参照保存を保証できないこと、本番スループットやエネルギー効率が未評価であることである。実装状況は、llama.cppとGGMLの固定したソースに対する研究実装であり、arXivのソースに報告データとCPU一貫性チェッカーが付属するが、完全なランタイムとテンソルのアーカイブは別管理である。

## 一般的な実装上の含意

実行経路を最適化するときは、数学的な等価性、ビット級の数値対応、終端の一致、バックエンドの受理を別の主張として分けて検証する必要がある。また、局所的な変換の正しさは、それが消費する状態の作られ方まで含めて初めて配置全体の主張になる。終端が一致する状態同士でも部品は交換可能とは限らず、置換範囲の拡大が効果を保つ単調性も仮定できない。グラフのキャッシュを持つランタイムでは、レイアウトの選択を再利用の鍵へ含めることが静かな参照破壊を防ぐ要点になる。
