# LibraSpec：拡散型投機的復号の検証長を限界利得で最適化する

## 概要

投機的復号（speculative decoding）は小型のドラフトモデルが先行生成した複数トークンを、大型のターゲットモデルでまとめて検証する。従来の動的投機長制御は「何トークン受理されそうか」を予測して長さを決めることが多い。自己回帰ドラフトでは追加トークンを一つずつ生成する費用が大きいため、この方針には合理性がある。しかしDFlashなどの拡散型ドラフトは、候補ブロックを並列に一括生成する。追加の候補トークンを作る費用が相対的に小さく、むしろターゲットモデルが追加候補を検証する費用が重要になる。

LibraSpecはこの費用構造の違いに着目し、期待受理長だけでなく検証時間を分母に含む**期待高速化率**を最大化する。現在の投機長より長くする場合、追加区間の受理利得を追加検証費用で割った限界効率が、現行の平均効率を上回るときだけ延長する。短縮する場合は、削る末尾区間の効率が現行平均より低いときに短縮する。著者らはこの更新の条件、期待高速化率の単峰性、反復更新の収束を論じる。

実装ではターゲット側の事前受理確率が未知なので、ドラフトモデル自身の信頼度を代用する。最大投機長と追加ブロック生成の予算を設け、長さが過度に伸びたり、ドラフトモデルを細かく呼び直したりすることを抑える。追加学習も補助予測器も不要で、FastdLLM、DFlash、DDTreeへ組み込める。Qwen2.5およびQwen3の六つのターゲット、数学・コード・会話の四つのベンチマークで、静的投機長や既存の動的手法を上回る高速化を示した。

## 問題設定と費用モデル

### 自己回帰ドラフトと拡散ドラフトの費用差

自己回帰ドラフトは候補長dを一つ増やすたびに追加の逐次計算を行うため、受理確率が低いトークンを多く生成するとドラフト側の計算費用が膨らむ。拡散ドラフトはブロックを並列に生成でき、長さを少し変えてもドラフト費用がほとんど変わらない領域がある。したがって「受理される候補をなるべく多く作る」だけでは、検証対象を増やすことでターゲットの演算時間が伸び、結果として遅くなる可能性がある。

論文はドラフト長d、受理される連続トークン数τ_d、ドラフト時間T_d^draft、検証時間T_d^verify、ターゲットの通常一トークン時間L_d^targetを用いて、投機的復号の高速化率を次のように表す。

`η_d = τ_d × L_d^target / (T_d^draft + T_d^verify)`

拡散ドラフトが十分速く、候補ブロックが既に得られている近似では、投機長を変えたときのドラフト費用を固定として扱い、`η_d ≈ τ_d × L_d^target / T_d^verify` と簡略化できる。これにより、期待受理トークン数と検証費用の比を改善する長さを探す問題になる。重要なのは、この簡略化は理想化であって、実装で追加ブロックを生成する費用が完全にゼロになるという意味ではない。

### 限界利得と限界費用

長さdからd'へ延長する場合、追加区間がもたらす期待受理トークン数をE[τ_{d:d'}]、追加検証時間をT_{d:d'}^verifyとする。論文の定理3.2は、`E[τ_{d:d'}] / T_{d:d'}^verify` が現行の `E[τ_d] / T_d^verify` より大きいことを、延長が期待高速化率を改善する必要十分条件として示す。短縮では、削る末尾の限界効率が現行平均より低いときに改善が起きる。

投機的復号は接頭辞から順に受理するため、後ろのトークンが受理されるには前の全トークンが受理されている必要がある。位置kの受理確率をp_kとすると、ある区間の期待受理数は各位置までの受理確率の積を足し合わせる形になる。候補長が伸びるにつれ、この積は増えないので、追加候補の限界利得は一般に小さくなる。これが単峰性を導く構造である。

## 手法

### 1. 位置ごとの限界条件から更新上限を作る

単に全体の追加区間の平均効率を見るだけでは、途中に効率の悪い末尾が含まれていても延長できると誤判定する恐れがある。LibraSpecは投機列の各開始位置iについて、そこから先の候補が生む限界利得を計算し、現行の平均効率より有利な範囲を表す上限ε_iを作る。全位置で条件を満たす必要があるため、次の長さの上限を`ε* = min_i ε_i`とする。

論文の定理3.3と3.4は、接頭辞受理による限界利得の単調性を利用し、位置ごとの必要条件と十分条件を導く。条件を満たす候補長は連続した区間を形成するため、各位置での許容区間の交差をとると、改善が保証される最大の更新先を決められる。この議論は理想化した期待高速化モデルと正しい受理確率に依存する。

### 2. ドラフト信頼度を受理確率の代用にする

実際にはターゲットの検証が終わるまでp_kを観測できない。そこで、既に生成したドラフトトークンの信頼度q_kを代用する。論文は、ドラフト信頼度がターゲット側の受理確率へ十分校正されているという仮定3.7を明示する。モデルや文脈が変わって信頼度と実際の受理が乖離すれば、理論上の最適性はそのまま保証されない。

アルゴリズム1は、現在の長さdについて各開始位置iの候補上限を `ε_i = floor(α × Σ_{j=i}^{d} Π_{k=i}^{j} q_k + i)` と計算する。αは検証時間、受理長、位置当たり検証費用をまとめたトレードオフ係数で、投機長を積極的に伸ばすか慎重にするかを調整する。ε*が現在のdを超える場合は延長し、超えない場合はその長さへ一度だけ戻して更新を終える。

ここでq_kは**実際のターゲット受理確率そのものではない**。したがって、アルゴリズムの収束定理は真のp_kを用いた理論モデルに対するもので、信頼度近似を使った実装のすべての局面で真の最適長が得られることを意味しない。実験はその近似がどの程度有効かを検証する役割を持つ。

### 3. ドラフトブロックの生成予算

拡散モデルは通常、長さnの候補ブロックを一度に生成する。投機長を少し伸ばすたびにドラフトモデルを呼び直すと、理論で無視したドラフト費用が支配的になってしまう。LibraSpecはドラフト予算Bを持ち、長さを伸ばすとその増分を予算から差し引く。Bが負になったときだけ、足りない長さを覆う個数のブロックをまとめて追加生成する。例えば不足分がmなら`ceil(m/n)`ブロックを要求する。

この仕組みにより、現在の候補の信頼度から必要な検証長を見積もり、追加生成が本当に必要になった時点でのみ拡散ドラフトを実行する。最大長d_maxも設定し、長い投機地平で信頼度校正が悪化する問題と、無制限の検証拡大を抑制する。d_maxは性能上の感度パラメータであり、長ければ必ず速くなるわけではない。

### 4. 一度だけの巻き戻しと反復収束

初期長dをドラフトモデル既定のブロック長nに置き、ε*がdより大きければ更新を繰り返す。ε*がd以下になったときは一度だけ短縮して停止する。信頼度の近似誤差とブロック生成の相互作用によって、細かな伸長・短縮を繰り返す振動が起き得るため、実装は一回の巻き戻しに制限する。

理論では、接頭辞受理の限界利得が単調に減り、追加検証費用を近似的に一定としたとき、期待高速化率が投機長に対して単峰になる。定理3.5はこの構造を、定理3.6は改善する更新を繰り返すと有限回で大域的最適区間へ到達することを示す。実装上のd_max、近似q_k、ブロック生成費用はこの理想化との差分として評価すべきである。

### 思考モードとハイパーパラメータ

Qwen3の思考モードを有効にした試験でも、DFlashへLibraSpecを追加すると、温度0で平均総倍率が約0.29〜0.30ポイント、温度1で約0.27〜0.29ポイント増加し、元のDFlashに対して相対約9〜11%の改善となった。思考過程の高い不確実性によって受理率が下がる局面でも、投機長を固定するより有利な条件があることを示す。ただし非思考モードと同じ改善幅を保証するわけではない。

αの感度では、Qwen2.5-7BとFastdLLMの平均総倍率はα=1.8で2.95倍、1.9で3.01倍、2.0で3.04倍、2.1で2.96倍、2.2で2.87倍であった。Qwen3-8BとDFlashではα=1.8で4.86倍、2.0で5.02倍、2.2で5.11倍であり、より強いドラフトでは積極的な延長が有利だった。論文の採用値はFastdLLMでα=2.0、DFlash・DDTreeでα=2.2である。

## 既存研究との差

EAGLE-3のような自己回帰ドラフトは、追加候補生成に逐次的な費用がかかるため、受理長予測を重視する設計が合理的である。FailFastやGemma 4型の動的長さ調整も、信頼度や履歴受理率を使うが、追加検証の時間費用を明示的に目的関数へ入れない場合がある。LibraSpecは拡散ドラフトの一括生成特性を前提に、期待受理長を検証費用で割る指標を直接最適化する。

DFlashやDDTreeは候補ブロックを生成する方式そのものを改良する研究である。LibraSpecは候補の作り方を変えるのではなく、既に得られた候補のうち何トークンを検証へ渡すかを決める上位の制御層である。そのため、複数のドラフト方式に追加でき、学習済みの重みを変更しない。実装上はドラフト信頼度が取得できること、ブロック生成と検証長を制御できることが前提となる。

## 限界と実装上の注意

理論上の収束は、ドラフト生成費用を固定・無視できるという近似、位置ごとの受理確率、検証費用のモデルに依存する。実際のドラフト信頼度q_kはターゲット受理確率p_kと完全には一致しない。特に長い投機地平では校正が悪化し得るため、d_maxを制限する。長さ更新の途中でブロックを追加生成すれば、そのドラフト費用が無視できない条件もある。

αの最適値はドラフト方式・モデル・ハードウェアで変わる。A100での評価を、異なるGPUや推論エンジンへ無調整で一般化できない。六つのQwen系ターゲットと三つの拡散ドラフトに限られ、別系列モデル、極端に長い文脈、GPU間通信が支配的な大規模サービングでは再測定が必要である。理論上の「大域最適」は近似モデル内の性質であり、あらゆる実装条件での実測最適を保証しない。

一次論文内では§4.2の改善倍率記述と表1のη比が単純には一致しないため、報告書では総倍率と追加倍率を明示的に区別した。公式実装URLは一次資料から独立に確認できておらず、ここでは「公開なし」と断定しない。
