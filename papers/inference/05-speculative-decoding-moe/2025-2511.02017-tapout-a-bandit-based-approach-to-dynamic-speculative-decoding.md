# TapOut：停止規則のオンライン選択による投機的復号の最適化

## 概要

投機的復号（speculative decoding）では、小型のドラフトモデルが生成した複数のトークンを、大型の対象モデルがまとめて検証する。対象モデルを一回実行する間に受理されるトークン数が増えれば高速化できるが、長く候補を生成しすぎると棄却されるトークンへの小型モデルの計算が無駄になる。候補の受理しやすさは、入力課題、モデルの組合せ、同一応答中の位置によって異なる。固定のドラフト長や固定の不確実性閾値では、これらの変化を吸収できない。

TapOutは、確率分布に基づく五つの停止規則を候補とし、多腕バンディット（multi-armed bandit）が検証結果からその時点で有利な規則を選ぶ方式である。最も安定した系列単位の上側信頼限界方式（UCB1）は、Llama 3.2 1B／Llama 3.1 8BのMT-Benchで固定ドラフト長6比1.25倍、OLMo-2 1B／32BのMT-Benchで1.27倍の速度比を得た。一方、Gemma 3 270M／27BのMT-Benchでは0.90倍となった。ここでの速度比は、通常の自己回帰生成ではなく**固定長6の投機的復号を1.00とした値**である。

## 問題設定と既存方式との差

ドラフトモデルが生成する候補列をX、そのうち対象モデルが受理した最長の接頭辞をY、最大候補長をγとする。受理長m=|Y|を増やすには長くドラフトを続けることが有利に見える。しかし、受理率|Y|/|X|が下がれば候補生成の計算は浪費される。逆に早すぎる停止は対象モデルの検証呼び出しを増やす。TapOutは、検証一回当たりの受理長と小型モデルの候補生成効率を同時に高めることを目指す。

SVIPやAdaEDLは、予測分布のエントロピー等から停止を判断する。最大確信度方式は最上位候補の確率を閾値と比較する。これらの閾値を各モデル対や課題へ合わせるには探索が必要であり、学習時や校正時と異なる分布に移ると最適な値が変わる。BanditSpecは生成全体の静的構成を選ぶのに対し、TapOutは各ドラフト内の停止判断に用いる**規則そのもの**を動的に選択する。モデルの重みを変更せず、対象モデルによる通常の検証を保持する点が特徴である。

## 手法

### 停止規則を候補の腕として構成する

TapOutの行動集合Aには五つの規則を用意する。最大確信度（Max-Confidence）は最有力トークンの確率が0.8未満で停止する。SVIPはエントロピーの平方根が0.6を超えた場合、SVIP差分（SVIPDifference）は直前位置からの同指標の増加が0.2を超えた場合に停止する。ロジット余裕（LogitMargin）は上位二候補の確率差が0.2未満となった場合に停止する。AdaEDLはエントロピーと過去の受理情報から更新される条件で停止する。いずれもドラフトモデルの出力分布を観測し、「続行」または「停止」を返す。

論文がいう追加調整不要とは、腕に数値閾値が一切ないという意味ではない。表1の定数は固定であり、評価対象ごとに再探索していない。従来の比較手法はLlama 1B／8BのSpecBenchで閾値を探索してから他のモデルへ転用するため、比較上むしろ有利な校正条件を与えられている。TapOutの新規性は、五つの既存・派生規則からオンラインに選ぶ制御器にある。

### ドラフト生成からバンディット更新までの処理順

ドラフト開始時にバンディットが一つの規則を選び、ドラフトモデルが次のトークンと確率分布を生成する。選択した規則へ確率分布を渡して停止判断を得る。停止でなければ次のトークンを生成し、停止または最大長γに達するまで繰り返す。対象モデルは候補列Xを並列に検証し、受理接頭辞Yを確定したうえで最後のトークンを生成する。この検証で得た|Y|と|X|を用いて今回選んだ規則の報酬を更新し、次回ドラフトの規則選択へ反映する。論文のアルゴリズム1に対応する一連の流れであり、モデル本体の再学習は必要ない。

この制御器が保持する状態は、規則ごとの選択回数、報酬の統計、選択方策に必要な分布である。検証結果を受け取るたびに更新するため、入力分布が変われば有利な腕の推定値も変化する。一方で、追加の制御演算と状態管理は発生する。論文は制御器だけのGPU実行時間や長時間サービングにおける競合を独立測定していないため、無視できると断定はできない。

### 受理長と受理率の複合報酬

受理長だけの単純報酬は r_simple=|Y|/γ である。これを最大化すると、候補を長く出し続けて受理長を増やす腕が選ばれやすいが、不採用の候補を多く生成した費用を反映できない。そこでTapOutは r_blend=α|Y|/γ+(1−α)|Y|/|X| を用い、α=0.5として両項を等重みにする。第1項は検証一回で受理できた量、第2項はドラフト計算の無駄の少なさを表す。

この報酬は実際の処理時間そのものではなく代理指標である。ドラフトモデルと対象モデルの速度比、GPU上の実装、バッチ条件が変われば、同じ受理率でも実時間への寄与は異なる。ただし論文の表2では単純報酬より複合報酬の方が、受理率と固定長6に対する速度比の双方を広い課題で改善した。受理長だけを最大化しないことが本方式の主要な設計判断である。

### 系列単位UCB1とトークン単位方式

系列単位では一回のドラフトに一つの腕を割り当てる。UCB1は腕aの平均報酬μ_aに探索項 sqrt(2 log(t)/N_a) を加えた値が最大の腕を選び、試行回数N_aの少ない規則にも試行機会を与える。検証一回で得た複合報酬をその腕に帰属できるため、生成速度と結び付いた情報を更新しやすい。分散を用いるUCB-Tunedや、事後分布から報酬を標本化するトンプソン標本化（Thompson Sampling）も比較したが、実験では単純な系列単位UCB1が総じて有利だった。

トークン単位方式はドラフト位置ごとにバンディットを置き、各トークンが受理されたかどうかの二値を報酬とする。局所的には精密に見えても、位置別のバンディットには候補列全体の速度への影響が届かない。受理率が高い規則を選べてもドラフトを早く切り上げすぎれば大型モデルの呼び出しが増える。この違いが、トークン単位方式が系列単位方式より遅い条件を説明する。

## 評価

### 評価条件と測定指標

論文の表3はLlama 3.2 1B／Llama 3.1 70B、Llama 3.2 1B／Llama 3.1 8B、OLMo-2 1B／32B、Gemma 3 270M／27Bの四つのモデル対を扱う。課題はMT-BenchとHumanEvalで、SpecBenchの追加結果と構成要素除去実験も報告する。固定長6の投機的復号をStatic-6と呼び、その速度比を各モデル対・課題で1.00とする。動的停止規則の最大ドラフト長は128であり、固定長6と同じ最大長条件ではない。受理長m、受理率、相対速度比sを区別して評価する。受理長が増えても受理率が低ければ高速化しないため、単一指標から速度を推定してはならない。

比較対象はAdaEDL、SVIP、最大確信度（MC）、学習型のSpecDec++、TapOutの系列・トークン単位UCB1およびトンプソン標本化である。SpecDec++はAlpacaの訓練分割4万例を用いて分類器を学習する。既存閾値方式はSpecBenchで閾値を調整したうえで他のモデルへ転用し、TapOut側の腕の閾値は固定する。論文の主要表からはGPU型番、絶対トークン毎秒、電力、複数同時要求時の遅延分布を十分に確定できず、固定長6との速度比を特定GPUでの絶対利得と混同しない。

### 主要な速度比と負の結果（原著表3）

|モデル対|課題|Static-6|TapOut 系列UCB1|代表的な競合方式|解釈|
|---|---|---:|---:|---:|---|
|Llama 1B/70B|MT-Bench|1.00|1.15|MC 1.16|最良よりわずかに低い|
|Llama 1B/70B|HumanEval|1.00|1.19|MC 1.14|比較中で上位|
|Llama 1B/8B|MT-Bench|1.00|1.25|SVIP 1.25|最良と同等|
|Llama 1B/8B|HumanEval|1.00|1.09|MC 1.09|最良と同等|
|OLMo-2 1B/32B|MT-Bench|1.00|1.27|MC 1.25|MCを上回る|
|OLMo-2 1B/32B|HumanEval|1.00|1.25|MC 1.38|最良に及ばない|
|Gemma 3 270M/27B|MT-Bench|1.00|0.90|MC 0.89|固定長より遅い|
|Gemma 3 270M/27B|HumanEval|1.00|1.52|AdaEDL 1.52|最良と同等|

Llama 1B／8BのMT-Benchでは、Static-6の受理長m=3.47、受理率0.58に対し、系列UCB1はm=3.14、受理率0.82、速度比1.25である。受理長が短くなっても不採用候補が減り高速化する例である。同じモデル対のHumanEvalではStatic-6がm=4.35、受理率0.72、系列UCB1がm=4.62、受理率0.86、速度比1.09となる。コード生成では両指標が改善するが、速度の増分はMT-Benchより小さい。OLMo-2のMT-Benchでもmは1.91から1.37へ減る一方、受理率は0.32から0.59へ改善し、速度比は1.27となった。

Gemma 3のMT-Benchで0.90倍へ減速する点は重要である。原著はGemma 3の疎注意がTransformersライブラリで十分最適化されていない可能性を脚注で挙げるが、これだけで原因を確定できない。またOLMo-2のHumanEvalではMCが1.38倍でTapOutの1.25倍を上回る。従って、TapOutがあらゆるモデル対と課題で最速であるという結論は原著の数値に反する。

### 報酬設計の構成要素除去（原著表2）

Llama 1B／8BのSpecBenchで、単純報酬から複合報酬へ変更すると、コード生成の受理率は0.48から0.83、速度比は0.78から1.18に改善する。翻訳では受理率0.42から0.73、速度比0.99から1.34、数学では受理率0.53から0.86、速度比0.82から1.13に変化する。これらは各方式を固定長6と比較した速度比であり、報酬方式間の直接倍率ではない。役割演技では両報酬とも速度比1.28であり、すべてのカテゴリで速度が厳密に増加したわけではない。この例外は「複合報酬が全課題で速度を改善する」と単純化できないことを示す。

報酬設計を変えると候補生成の平均長も変わる。図3では単純報酬が長いドラフトを選びがちなのに対し、複合報酬はより保守的に停止する。図4では系列単位UCB1が分散推定を用いるUCB-Tunedより多くのカテゴリで高速だった。複合報酬の分散が小さく、複雑な分散対応の探索項が利益を生みにくいと著者は解釈している。ただし全GPU実行時間の構成要素別内訳を示したものではない。

### 学習型方式、選択粒度、腕の数の比較

Llama 1B／8BのSpecBenchでは、Static-6の速度比1.00、Alpaca 4万例で学習したSpecDec++が0.99、TapOut系列UCB1が1.22だった。系列トンプソン標本化は0.90、トークン単位トンプソン標本化は1.05、トークン単位UCB1は1.13である。系列UCB1が他の選択粒度・方策より優れた条件だが、別のモデル対でも同順位になるとは限らない。

付録A.2では同一の停止規則に複数の閾値を割り当てて腕の種類を増やしたところ、もとの一規則一腕より速度比が約12%低下した。候補を増やすほどオンライン探索が必要となり、各腕への報酬観測が薄くなる可能性がある。図5の腕の価値推移ではMT-Benchで有力腕と他の腕の差が約0.2、HumanEvalでは平均約0.025であり、課題によって腕の優劣の明瞭さが変わる。これは選択の解釈可能性を示すが、突然の分布変化から何要求で回復するかを直接測定したものではない。

## 限界と推論基盤への適用

TapOutの改善対象は停止規則の選択であり、候補を生成するドラフトモデルの計算量自体を削る新しいカーネルではない。各腕が良い停止規則を含まなければ、上位の選択器だけで最適な停止条件を作ることはできない。報酬は受理長と受理率を合成した代理値であり、GPUの実時間遅延を直接最適化していない。評価データセットは比較的小さく、長期サービングの分布変化、複数要求の競合、メモリ使用量、電力の評価は不十分である。

系列単位UCB1は、過去の検証結果から停止規則を適応選択するため、同一モデル対で課題が変化する環境には合理的な構成である。しかしGemma 3のMT-Benchで固定長6より遅い事実から、実運用では固定長へ戻す条件やサービス品質目標に応じた選択を別途検証する必要がある。固定長を一つの腕に加える案は本サーベイの実装上の提案であり、原著で評価された方式ではない。論文の比較は通常生成との倍率ではなく固定長投機的復号との倍率であり、異なる推論エンジンへの性能外挿には新たな実測が必要である。
