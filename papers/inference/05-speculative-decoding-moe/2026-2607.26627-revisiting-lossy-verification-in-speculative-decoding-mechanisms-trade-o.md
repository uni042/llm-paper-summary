# 投機的復号の損失あり検証を再検討する：分布の歪みと速度・品質の交換関係

## 概要

投機的復号は軽量なドラフトモデルqが候補を提案し、ターゲットモデルpがまとめて検証することで、逐次生成のターゲットforward pass回数を減らす。標準方式では候補トークンxを `min(1,p(x)/q(x))` の確率で受理し、棄却時には残差分布から補正トークンを抽出するため、出力分布はターゲットpに一致する。これをlossless verificationと呼ぶ。一方、候補をより多く受理するため検証を緩めるlossy方式は、速度と引き換えに出力分布を変え、難しいタスクで品質を損なうことがある。

本稿はlossy verificationの方式名ごとの比較ではなく、**実際に生成される確率分布**を導出して二群へ整理する。第一のtruncation-based verificationは、ターゲット分布から作った許可語彙集合にドラフト候補が入れば無条件に受理する方式である。これは「ターゲットにmin-pまたはηサンプリングを適用した出力」とは異なり、許可集合内で正規化された**ドラフト分布**に従う。第二のcollaborative verificationは、ターゲットとドラフトを混合する、過大評価したドラフト確率に上限を設ける、または学習済みjudgeに受理を決めさせる方式である。著者は分布の違いを導出し、単純な混合よりも過大確率の抑制とjudgeの教師信号が重要と示す。

EAGLE-3を用いたLlama-3.1-8Bの比較では、η-samplingをターゲットへ正しく適用したMATH正答率76.12%に対し、typical acceptanceは69.84%だった。MBPP+のPass@1も62.17%から56.88%へ低下する。他方、typical acceptanceのblock efficiencyはMATHで3.93から4.61へ増え、復号速度も140.05から162.73 token/sへ上がる。速度だけを見ると有利だが、同じ切断条件の正しい比較より品質が悪い。<https://arxiv.org/html/2607.26627v2>

## 問題設定：比較対象を揃えないと検証の価値を誤認する

Medusaのtypical acceptanceやSpecCascadeは、ドラフト候補が確率閾値で定義した許可集合に入るかを調べ、入ればターゲットとの正確な分布比に関係なく受理する。min-pやηサンプリングは元々、ターゲット自身の低確率な尾部を取り除き、生成の品質を上げるために使われる。したがって「標準の非切断ターゲット」だけを比較相手にすると、サンプリング自体の改善と、緩い検証による速度改善が混ざってしまう。

本稿が採用する重要な対照は、**同じ切断規則をターゲットへ適用し、なおかつ正しいlossless検証をする方式**である。これをTrue baselineとし、切断しないターゲットをWrong baselineとして区別する。例えば難しい数学問題AIMEでは、適切な切断ターゲットに対するlossy方式の品質差がGSM8Kより大きいと報告する。GSM8Kのような容易な課題だけで性能劣化が小さいと結論付けることは危険である。

また、lossy検証を一つの方式としてまとめて評価すると、なぜ品質が落ちたかを説明しにくい。著者は出力分布の数式を先に導出し、候補の受理規則がどの確率質量をドラフトへ移すかを確認したうえで、MATH、MBPP+、INCLUDE、BFCLの4種類の自動採点可能なタスクで速度と品質を同時に測定する。

## 手法・数理的整理

### 1. 標準のlossless speculative decoding

ターゲットの次トークン分布をp、ドラフトの分布をqとする。標準方式はqから抽出した候補xを `h(x)=min(1,p(x)/q(x))` で受理し、棄却された確率質量を `max(p-q,0)` に比例する残差分布から再サンプリングする。この補正により出力分布はpと一致する。ドラフトがターゲットに近いほど受理が増えるが、出力を変えないまま無制限に受理できるわけではない。lossy方式はこの制約を緩め、出力分布がpから変化することを許容する。

### 2. Truncation-based verification：許可集合内のドラフトを無条件受理

ターゲットpの確率に基づき、許可集合Aを作る。min-pは最大確率に対する比で閾値を決め、η-samplingは分布エントロピーから閾値を決める。通常のターゲット切断サンプリングは、A内で `p_A(x)=p(x)/Σ_{v∈A}p(v)` を生成する。一方、truncation-based verificationは受理規則を `h(x)=1{x∈A}` に変更するため、実際の出力は `q_A(x)=q(x)/Σ_{v∈A}q(v)` となる。A内に入ったからといって、pとqの相対確率が一致するわけではない。

この違いが本稿の中心的な失敗機構である。たとえばドラフトが許可集合内のある誤ったトークンを過大評価していれば、そのトークンは高確率で生成され、ターゲットが想定した切断分布へは戻らない。SpecCascadeはmin-p型、Medusaのtypical acceptanceはη型の許可集合を使う。どちらも「低確率尾部を除去する」効果と「ドラフトに従う」効果を切り分けて評価する必要がある。

著者のLemma 1は、切断による受理確率の変化を、許可集合内の確率再配分で増える項と、除外された尾部で失う項に分解する。min-pでは閾値を厳しくすると増分が縮み得る一方、評価したη設定では受理効率の増分が一貫して正となる。これは**切断サンプリング自体の効率変化**であり、lossy検証の品質保証ではない。

### 3. Collaborative verification：ターゲットとドラフトの協調分布

この群にはCoS、DIVERSED、Fuzzy SDの補間型、LenienceやDistillSpecの寛容度型、Judge DecodingやAutoJudgeの学習判定型が含まれる。補間型は `r(x)=λp(x)+(1-λ)q(x)` の混合分布を検証対象にする。λが小さいほどドラフトへ近づき、受理効率は高くなりやすいが、ターゲットからの歪みも増える。

Lenienceは `h(x)=min(1,p(x)/(ℓq(x)))` という受理規則を使い、0<ℓ≤1の寛容度で受理を緩める。原著の分布導出では、q≤pの過小評価領域では適応的補間、p<q≤p/ℓの中程度の過大評価領域ではqをそのまま採用、q≥p/ℓの極端な過大評価領域では出力確率をp/ℓへ抑える。重要なのは単なる補間係数ではなく、**ドラフトがターゲットを大幅に上回るovershootを上限で切る**ことである。

Judge型は学習済み判定器の信号j(x)を使い、q>pの過大評価領域で候補を追加受理するか決める。judgeが不適切なトークンを受理すれば分布はqへ寄り、品質が落ちる。逆に高品質な教師信号で学習したjudgeは、単純な線形補間より好ましい速度・品質の境界を実現し得る。著者はAutoJudgeの学習データの構成を変えて、その差を実験する。

### 4. EAGLE-3の木検証で歪みが残る理由

標準の単一ドラフト方式では、qがpに近づけば、許可集合内のq_Aもp_Aに近づき、切断ターゲットとの差は小さくなる。著者のTheorem 1は、EAGLE-3型の木検証に同じ許可集合ルールを組み込むと、q→pの極限でも対応するKL歪みがゼロにならないことを示す。木構造で候補をまとめて受理する規則が、切断ターゲットの条件付き分布と一致しないためである。

この理論結果はEAGLE-3での品質差拡大と対応する。ただしTheoremの条件・検証実装を離れてすべての木検証器が同じ歪みを持つと一般化できない。著者が評価した具体的な受理ルールに対する警告として読むべきである。

### EAGLE-3での切断型検証：速度増と品質悪化の併存

原著Table 3はLlama-3.1-8B EAGLE-3で、パラメータ掃引の平均を示す。以下は対応する切断サンプリングとlossy検証の比較である。

| 条件・方式 | MATH BE / DS / 正答率 | MBPP+ BE / DS / Pass@1 | INCLUDE 正答率 | BFCL 正答率 |
|---|---|---|---:|---:|
| min-p sampling | 3.98 / 143.22 / 76.88% | 4.90 / 168.57 / 61.80% | 37.00% | 86.60% |
| SpecCascade | **4.22 / 152.74 / 76.16%** | **5.00 / 175.91 / 60.74%** | 33.27% | 85.40% |
| η-sampling | 3.93 / 140.05 / 76.12% | 4.87 / 165.61 / 62.17% | 36.73% | 86.30% |
| typical acceptance | **4.61 / 162.73 / 69.84%** | **5.20 / 180.10 / 56.88%** | 27.91% | 81.40% |

SpecCascadeはMATHでBEが3.98から4.22へ増え、DSも143.22から152.74へ改善するが、正答率は76.88%から76.16%へ下がる。typical acceptanceはMATHでBE3.93→4.61、DS140.05→162.73と速くなる反面、正答率76.12%→69.84%へ6.28ポイント低下する。MBPP+でも62.17%→56.88%へ5.29ポイント低下し、INCLUDEでは36.73%→27.91%へ8.82ポイント落ちる。**速さの代償は課題によって異なり、単一の平均速度指標では判断できない。**

原著Table 3にはEAGLE-3の無切断基準もあり、MATH 73.20%、MBPP+ 59.30%、INCLUDE 35.50%、BFCL 86.00%を報告する。切断サンプリングの正答率がこれを上回る条件もあるので、非切断基準に勝ったことだけをlossy検証の品質改善と誤認しない。著者は標準SDでも同じ傾向を確認し、木検証では差がさらに大きくなると述べる。

### Lenienceの構成要素除去

著者はMBPP+で、Lenienceの二つの性質を別々に組み込むアブレーションを実施した。過小評価領域に適応補間を導入するだけの方式と、過大評価領域の確率へ上限を設ける方式を比較する。原著Table 1の例では、λ=0.2で前者はBE9.15・Pass@1 50.26%、後者はBE5.59・Pass@1 75.93%。λ=0.8でも前者BE5.95・Pass@1 66.14%に対し、後者BE5.54・Pass@1 75.13%だった。

単純に受理数を増やすと品質が落ちる一方、overshootを制限する方式は受理数をある程度保ちつつ正答率を高く維持した。ここでの二方式は元のLenience全体と完全に同じものではなく、メカニズムを分解した実験条件である。数値はMBPP+の特定モデル組・設定に依存するが、分布のどの領域を緩めるかが、単なる補間係数より重要であることを示す。

### AutoJudgeの教師データ混合比

AutoJudgeの学習に使うGSM8KとLiveCodeBenchの比率を変え、受理閾値0.2、0.4、0.6、0.8の平均で評価した。原著Table 2では数学:コードが9:1のときMATHはBE8.62・正答率83.10%、MBPP+はBE5.82・Pass@1 76.72%、INCLUDE正答率62.96%、BFCL正答率88.00%。一方1:9ではMATHがBE10.55・正答率64.45%、MBPP+はBE8.34・Pass@1 57.87%、INCLUDE43.52%、BFCL63.00%へ低下する。

この結果はjudgeの教師信号の質・ドメインが速度・品質の境界を強く左右することを示す。コードの学習比率を増やしてもMBPP+が改善しないという負の結果もあり、単純なタスク名の一致だけで教師混合比を決めるのは危険である。原著は数学寄りデータの品質が高かった可能性を論じるが、すべてのモデルとタスクで数学寄りが最適という普遍的な結論ではない。

## 既存研究との差

Medusa、SpecCascade、CoS、Fuzzy SD、Lenience、DistillSpec、AutoJudgeなどは個別の検証規則として提案されてきた。本稿はそれらを、出力分布が許可集合内のqに従うか、pとqの混合・制限・judgeによる協調分布に従うかで統一する。単なる分類ではなく、**同じ切断規則を適用したターゲット分布を比較対象に置く**ことで、サンプリングによる品質改善と検証の歪みを切り分けた点に意義がある。

さらに、Lenienceを過小評価領域の補間と過大評価領域の上限制限へ分解し、後者の寄与をアブレーションで確かめた。judge型でも学習データの混合比を変え、学習済み受理器の品質が重要であることを定量的に示す。EAGLE-3における分布歪みの理論解析は、木検証へ単一ドラフト向けのlossy受理規則を移植する際の注意点を与える。

## 限界・適用判断

評価はMATH、MBPP+、INCLUDE、BFCLという正解参照のある課題に集中しており、min-pやη-samplingが本来対象とする自由作文での不自然な尾部生成抑制を十分に測定していない。自動採点できる正答率の低下が、そのまま会話品質の主観的低下と一致するわけではない。著者自身もオープンエンド生成を評価対象外と明記する。さらに本稿の理論的統一は検証規則に焦点を当てており、ドラフトモデルの学習、木の展開方法、システムスケジューリング、GPU間通信までを統一したものではない。

速度・品質のトレードオフはモデル組、量子化、GPU、デコード設定、評価課題によって変わる。BEの改善はターゲットforward passの削減を示唆するが、追加judge推論、同期、メモリ移動を含む実サービングのレイテンシと同一ではない。AutoJudgeが一部条件でlossless基準より高品質になったとしても、出力分布がターゲットpと一致する保証を回復したことにはならない。むしろ目的が「pを厳密に再現すること」か「下流タスクの正答率を上げること」かを明確に分ける必要がある。

実務的には、まずターゲットへ同じ切断サンプリングを適用したlossless方式を対照に置き、BE・DSと下流品質を併記する。さらにドラフトがターゲットを大きく上回る候補の受理を制限し、judgeの教師データを対象ドメインで検証する。著者コードは公開されているが、今回の結果は原著本文・表の読解であり、コードを独立実行して再現した測定ではない。
