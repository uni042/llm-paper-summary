# UniVer：木状投機的復号の受理質量を条件付き最適輸送で統合する検証法

## 概要

投機的復号は軽量な草案モデルが次の候補トークンを提案し、大きなターゲットモデルが並列に検証する。通常の逐次生成と同じ出力分布を保ちながら、1回のターゲット検証で複数トークンを確定することが狙いである。複数候補を同じ位置に用意するmulti-draftと、複数位置にわたって草案を伸ばすmulti-stepを組み合わせると、候補は木になる。検証では同じ深さの兄弟候補のうちどれを選ぶか、そして先行位置が受理された確率質量を後続へどう配るかが相互に依存する。

UniVerはこの二つを別々の問題として解く従来法を改め、**親までの接頭辞が受理される確率を使ってターゲット分布を縮小した条件付き最適輸送（conditional optimal transport）**を各親ノードで解く。兄弟の候補間に受理質量を配り、その質量を次の深さへ伝播させることで、木の幅方向と深さ方向を同時に扱う。最後に事後順の木走査で実際の採否を決める。追加の草案モデルを学習する方式ではなく、**検証アルゴリズム**の改良である。

原著のSpec-Bench、温度1、Vicuna-7B、二分木深さ5では平均受理長がRRSwの3.06からUniVerの3.29へ増加し、平均TPSは67.5から72.2へ改善した。Llama3.1-8B-Instructでは2.72から2.95、TPS48.5から52.2である。受理長のRRSw比改善はモデルと木形状により4.2～8.5%で、**トークン毎秒が同じ割合で必ず増えるという意味ではない**。原著は特定の混合草案規則の下で分布不変性を証明するが、任意の木生成法・任意の候補選択に対して無条件に最適という主張ではない。

## 問題設定：横方向の選択と縦方向の依存

通常の1候補投機検証では、ターゲットの次トークン分布をp、草案分布をqとすると、最適な受理率は両者の重なり `sum_x min(p(x),q(x))` に等しい。これは1から全変動距離を引いた値である。複数の候補を用意する場合、候補を順に検証し、棄却された分だけ残余分布を再正規化するRecursive Rejection Sampling（RRS）や、同じ語の重複を防ぐwithout-replacement版RRSwが使われる。ただしこれらは各候補を局所的に扱うため、兄弟候補の受理質量を一つの確率空間で最適配分する方法に比べて損失があり得る。

横方向の改善法として、SpecTrやGreedy系の最適輸送法は同一位置の複数候補を共同選択する。原著で採用するGreedyの草案規則は、草案分布の上位m−1語を決定的に選び、残り1語をその上位語を除いた残余草案分布からサンプリングするというもの。この構造なら候補集合に対して最適な受理確率を計算できる。一方、これを木の各ノードで独立に使うだけでは、親が棄却されて到達できない枝へ質量を割り当てる可能性を十分に考慮しない。

縦方向の改善法としてBlock Verificationは、各位置の比率を1で切り詰めてから積にする局所法と違い、累積した比率を最後に切り詰める。後続位置でターゲット確率が高いと、前位置の低い受理確率をある程度回復できる。Traversal Verificationはこれを木へ拡張し事後順で候補を確認するが、同じ親の兄弟候補選択にはRRSwを使うため、横方向の最適化が残る。UniVerはこの分離を解消する。

## 手法

### 1. 接頭辞受理質量による条件付きOT

木の根をrとし、根の接頭辞受理確率を1に初期化する。親ノードvへ到達する有効確率を `a_v` とすると、子候補へ分配できるターゲットの確率質量は `a_v p(.|v)` である。ここでpはターゲット分布、qは草案分布。`a_v` を掛けることにより、親が必ず受理されると仮定して各深さの候補を最適化する誤りを避ける。

各親では草案qの上位m−1語と残余qからの1サンプルを候補にする。上位候補に配る質量と残余サンプルへ配る質量は、`a_v p` と残余草案分布の重なりを使って同時に計算する。原著の式(3)～(7)では、正規化係数Z_v、残余サンプルの受理率、決定的候補の非負残差、全候補を棄却する確率を明示している。これは単に各子の `min(p/q,1)` を独立に計算するのではなく、**兄弟全体で使える確率質量を一度に配分する**手続きである。

親ごとに得た子の周辺受理確率を、事後順で先に調べた兄弟が棄却された条件に合わせて割り直し、子へ渡す条件付き受理確率を得る。例えばj番目の子へ渡す値は、その子の周辺受理質量を、先行する兄弟へ既に配った質量を除いた残量で割る。各階層では親ごとの計算を並列化でき、親の質量が定まったら次の階層へ伝播する。したがって木の全候補を指数的な巨大OTとして一度に解くのではなく、局所OTを接頭辞確率で連結する。

### 2. 上からの割当と下からの決定

アルゴリズムは二段階からなる。第一段階はrootから葉へ向かう割当で、同じ深さにある独立した親について子候補の受理質量を並列計算する。第二段階は事後順の木走査であり、各ノードに独立した一様乱数を割り当て、葉ではその葉の条件付き受理率、内部ノードでは子が採択されなかった後の残余採択率と比較する。採択された葉ならターゲット分布から次の語を生成し、内部ノードなら対応する残余分布から次語を選ぶ。

この二段階分離は、RRSwのように候補を一つ棄却するたびに次候補の残余分布を逐次再計算する方式と異なる。確率割当を先に求めておくことで、検証時の候補探索は事後順の一回の走査になる。ただし木の深さごとの割当には前段階の接頭辞質量が必要なので、**全深さを無条件に同時並列化できるわけではない**。また、ターゲットモデルによる候補木の確率評価自体の費用がゼロになるわけでもない。

### 3. 分布不変性と最適性の範囲

原著はまず、各親の候補集合に関する期待受理質量が、その親へ到達する確率とターゲット分布の積に等しいことを局所的なlosslessnessとして定義する。UniVerの割当がこの条件を満たすことを証明し、局所的にlosslessな木を二段階検証すれば、最終的な出力列がターゲットの確率分布と一致することを示す。したがって**検証によってターゲット分布を変えない**という投機的復号の重要条件が理論的に保証される。

条件付き最適性の定理は、親の到達確率が固定され、草案が「上位m−1候補＋残余から1サンプル」という規則に従うとき、子集合に割り当てられる受理確率が最大になるというもの。さらに同じ草案規則に基づくGreedy方式と比較して、木全体での期待受理長がそれを下回らないことを示す。これは**あらゆる草案分布・木形状・候補抽出方式の組合せに対する大域的な無条件最適性ではない**。草案生成法や木構造まで共同最適化する問題は残る。

## 評価

| 項目 | 原著の条件 |
|---|---|
| データセット | Spec-Bench。MT-Bench対話、WMT14独英翻訳、CNN/DailyMail要約、Natural Questions QA、GSM8K数学、DPR検索拡張の6領域、各80例 |
| 主対象 | Vicuna-7B-v1.3とEAGLE草案、追加でLlama3.1-8B-Instructなど |
| GPU・再現 | NVIDIA RTX A6000 48GB、3乱数seed、各条件の平均と標準偏差を記載 |
| 木 | 2候補×5段の二分木（深さ5、32葉・全63ノード）、3候補×3段、非対称EAGLE木 |
| 温度 | 0、0.3、0.6、1.0。主結果は温度1.0 |
| 比較法 | Vanilla RRSw、Traversal Verification、Greedy（単一階層OT）、UniVer |
| 指標 | 1検証サイクル当たりの平均受理長τ、実測生成TPS。正解率向上を主張する実験ではない |

本評価では、木の検証によって一度に確定できたトークン数を受理長として数える。受理長が大きいほど、同じ長さの出力を生成するためにターゲットモデルを呼び出す回数を減らせる可能性がある。しかし実際の生成速度には、草案を作る時間、候補木を評価する時間、残余分布を計算する時間も含まれる。そのため受理長と実測トークン毎秒の双方を提示し、前者の改善が後者にどの程度反映されたかを区別する。さらに、温度を変えると分布の鋭さが変わり、兄弟候補へ配分できる確率質量が変わるので、温度一での結果だけを決定的生成へ外挿しない。

Vicunaの主設定ではRRSw比の受理長増加は `(3.29/3.06−1)≈7.5%`、Llama3.1-8Bでは `(2.95/2.72−1)≈8.5%`。一方、VicunaのTPSは67.5から72.2へ約7.0%改善、Llamaでは48.5から52.2へ約7.6%改善した。受理長とTPSの差は、検証アルゴリズムの計算費用、モデルの実行時間、草案・ターゲット間の相互作用が入るためである。自己回帰TPSの参考値はVicunaが35.9、Llama3.1が34.5で、上表の各投機方式は既に自己回帰より速い。UniVerの改善率を**自己回帰からの全高速化率**と取り違えない。

### 深さと木形状の感度

原著のMT-Benchにおける深さ別の受理率では、最初の深さではGreedyとUniVerがともに82.6%で、同じ横方向のOT選択を使うことが現れている。深い位置ではRRSwの受理率が下がり、Traversalは縦方向の質量回復で低下を抑えるが、兄弟候補選択の不足が残る。UniVerは深さごとの受理率を77%以上に維持し、縦と横の両方を最適化する利点を示した。ただし深さを伸ばすほど無限に利得が増えるという結果ではなく、草案モデルの予測精度も深さとともに変わる。

木形状による差も大きい。温度1のVicunaでは、二分木深さ5でRRSw比+7.5%、3候補×3段で+4.8%、非対称EAGLE木で+4.2%である。兄弟候補の数と深さのバランスが、条件付きOTで再配分できる確率質量を変える。木を大きくすれば必ず最大の利得が出るわけではなく、同じ検証計算予算でどの形状がよいかは別途最適化が必要になる。

### 温度による負の結果

低温ではターゲット分布が鋭くなり、候補間の確率質量配分の自由度が減る。Vicunaの二分木深さ5では温度0.3でTraversal、Greedy、UniVerの平均τがいずれも3.39で、温度0では3.40へほぼ収束する。温度0.6ではRRSw3.29、Greedy3.34、UniVer3.37と差は小さい。**温度0またはそれに近いgreedy運用で、UniVerの検証方式だけを入れ替えて大きな高速化が得られるという証拠はない**。原著自身も、方式間の差は温度が正であるときに顕在化すると明記している。

## 既存研究との差

SpecTrと単一階層Greedyは、同じ位置で複数候補を用意する場合の最適輸送を改善するが、木の親子の到達確率を横断的に使わない。Block Verificationは複数位置の受理確率の積の切り詰め方を改善し、Traversal Verificationは木の縦方向へ拡張するが、兄弟選択はRRSwである。UniVerはこれらの間の未最適化部分を、**親の接頭辞受理確率をスケーリング係数にした条件付きOT**として定式化し、局所的な最適輸送計画を階層間で結合する。

新しい草案モデルの学習やKV圧縮、GPUカーネルの最適化ではなく、既に評価済みのターゲット・草案分布を使って**検証の確率的選択規則を改善する**点が主な貢献である。したがって、EAGLEやMedusaなどの草案品質を高める研究と補完的だが、草案生成方式が異なれば定理の前提となる混合サンプリング規則を満たすよう再設計が必要になる。

## 限界

- **最適性の条件付き性**：定理は上位m−1候補と残余分布からの1サンプルという草案規則、および親の到達確率を固定した条件で成立する。任意の木生成器、任意の候補サンプル法を横断する最適性ではない。
- **低温での追加利得消失**：温度0近傍ではGreedy・Traversalとほぼ同じ受理長になり、確率的生成を行わないサービスでの導入利益は小さい可能性がある。
- **木形状の依存性**：深さ・分岐数・非対称性によって改善幅は4.2～7.5%程度に変わる。木形状、草案サンプル、検証器の共同探索は今後の課題である。
- **測定範囲**：RTX A6000とEAGLE系、Spec-Benchの各80例を中心とする。高バッチ同時実行、極端な長文脈、量子化草案、分散検証、MoEなどの運用条件での速度は測定されていない。
- **精度と出力分布の区別**：losslessnessはターゲットの生成分布を保存する数学的性質であり、モデルそのものの正答率を改善する主張ではない。表の数値は受理長とTPSである。
- **実装公開の確認**：実験はEAGLE公開実装を基礎とするが、UniVer著者独自の公式公開コードURLは原著本文から確認できなかった。EAGLEのコードをUniVerの公式実装として記載しない。

## 実装判断と再現時の確認事項

実装を既存の推論エンジンへ組み込む場合、まず検証の前提となる草案集合の作り方を固定しなければならない。上位候補を決定的に選び、最後の一候補を残余分布から抽出するという構造を変えると、論文の確率質量配分式をそのまま適用できない。特に、木の各節点で異なる候補数を採用する実装や、草案の枝を途中で打ち切る実装では、親の到達確率と子の受理確率の正規化が一貫しているかを個別に確認する必要がある。単に従来の検証処理を別の受理率の式に置き換えるだけでは、分布不変性の証明に用いた仮定が破れる可能性がある。

再現試験では、最終的な受理長だけでなく、各深さでの到達率、兄弟候補の採択率、残余分布から次トークンを引く頻度を別々に測ることが有用である。浅い階層の受理率が上がっても、深い階層へ伝わる質量が不足すれば木全体の受理長は伸びない。逆に、深い階層の採択が改善しても、そこまで到達する要求が少なければ総合効果は小さい。原著が深さ別の受理率を示しているのは、最終的な平均値だけでは改善機構を説明できないためである。特定の一領域だけで得た利得を、対話、翻訳、要約、検索、数学の全領域へ無条件に外挿するべきではない。

生成分布の保存を検証するには、同じターゲットモデルで通常の自己回帰生成を行い、多数の反復サンプルについて語彙の出現頻度や系列確率を比較することが考えられる。ただし有限サンプルの統計的一致は理論的な証明を置き換えない。原著の定理が保証するのは、指定された確率計算とサンプリング規則が正確に実装されたときの分布の一致である。数値誤差、乱数の使い方、残余確率の正規化、候補の重複処理などに実装上の不具合があれば、その保証は実システムへ自動的には移らない。特に小さい残余質量を扱うときは、丸め誤差が負の確率や総和のずれを生まないかを確認する必要がある。

導入の優先順位は、温度と木形状によって変わる。決定的な生成を中心とする運用では、論文の低温結果から見て、検証器だけを複雑化しても改善余地は限られる。一方、複数候補を持つ確率的生成で、ターゲット検証の計算費用が高く、草案の枝が十分に深く伸びる場合には、追加の受理トークンがターゲット呼び出し回数の削減につながり得る。ただし受理長の向上分をそのまま応答遅延の短縮率とみなすことはできない。実際の選定では、草案生成、確率割当、木走査、ターゲット検証、メモリ確保の各費用を含めた一要求当たりの遅延と、同時処理時のスループットを測るべきである。

候補木の大きさを増やすと、ターゲット側で並列に評価できる候補数が増える一方、候補確率の取得や検証器の管理に必要な計算量とメモリも増える。受理長の増分だけを最適化するのではなく、限られた計算予算の中で一回の検証に投入する候補数を決める必要がある。論文の結果は特定の木と草案モデルで測定したものであり、別の実装へ移植する際は同じ木を使った比較と、同じ処理時間を使った比較の双方を用意すると解釈しやすい。さらに、乱数を固定した反復試験と異なる乱数を用いた反復試験を区別し、確率的な揺らぎを受理長の差と混同しないことが重要である。
