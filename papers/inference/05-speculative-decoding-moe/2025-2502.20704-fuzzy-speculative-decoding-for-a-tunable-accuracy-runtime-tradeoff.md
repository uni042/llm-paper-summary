# Fuzzy Speculative Decoding：分布の厳密一致を緩める投機的復号

## 概要

標準的な投機的復号（speculative decoding; SD）は、小さいドラフトモデルが複数トークンを先に生成し、大きいターゲットモデルがそれらを一括検証することで、ターゲットモデルの逐次実行回数を減らす。標準SDは候補の受理確率と拒否時の補正再標本化を組み合わせ、最終的な出力の確率分布をターゲットモデル単独の場合と一致させる。その保証は品質上の利点だが、タスク正解率がほとんど変わらない候補まで棄却する場合があり、速度と品質の交換条件を調節できない。

Fuzzy Speculative Decoding（FSD）は、候補位置におけるドラフトとターゲットの次トークン分布の乖離を測り、その値が利用者指定の閾値T未満なら候補を受理する。閾値を緩めればより多くの候補を通し、ターゲットモデルの再実行回数を減らせるが、厳密な分布保存は失う。原著はLlama 3.1、Gemma 2、Qwen 2.5の三つの大小モデル組を用い、四つの質問応答・数学・コード課題で正解率とトークン毎秒を測定した。たとえばQwen 2.5 7B/32BのGSM8Kでは、標準SDの95.1%・17.4トークン/秒に対し、低閾値FSDは94.7%・21.4トークン/秒となる。正解率0.4ポイント減と引き換えに毎秒4.0トークン増という条件付きの結果であり、全モデル・全課題に無損失の高速化を保証するものではない。

## 問題設定：標準SDの受理規則が持つ制約

標準SDでは、ドラフトモデルMDが生成した候補xiについて、ターゲットモデルMTとドラフトモデルの条件付き確率pT(xi)、pD(xi)を求め、min(1,pT(xi)/pD(xi))で受理確率を決める。受理判定には一様乱数を使い、最初の棄却位置では正規化した正の差分分布に相当する補正分布から再標本化する。これにより候補採用が出力分布へ与える偏りを相殺する。受理率が高いほど、ドラフトの逐次生成に要する費用を上回るターゲット側の呼び出し削減が得られる。

しかし標準SDの速度はモデル組だけでなく入力タスクに依存する。原著のLlama 3.1 8B/70Bの表1では、候補長10の標準SDの速度はGSM8Kで13.2トークン/秒、HumanEvalで16.0、CommonsenseQAで9.3、MMLUで7.2であり、候補長を15へ延ばしても常に速くなるわけではない。長すぎる候補は棄却後に無駄となるドラフト計算を増やす。FSDは「ターゲット分布と同一でなければならない」という制約自体を緩め、候補の受理を増やすための独立した操作量Tを導入する。

## 手法：候補生成、分布乖離、閾値受理

### 1. ドラフト候補とターゲット分布の一括取得

FSDも基本構造は標準SDと同じである。小さいMDが長さLの候補列を逐次生成し、大きいMTがその列の各位置について次トークン確率分布を一回の検証前向き計算で求める。各候補位置iには、MDの分布PD[i]とMTの分布PT[i]が対応する。FSDが追加するのはこの二分布を比較する処理であり、ドラフトモデルを別途学習し直すことは必須ではない。

標準SDが候補トークンxi一つの確率比で受理を決めるのに対し、FSDはその位置の語彙全体に対する二つの確率分布の差を測る。たとえば候補トークンが偶然ターゲット側で低確率であっても、分布全体の差が小さい位置なら閾値に応じて受理され得る。逆に分布全体の乖離が大きい位置は、候補一個だけが高確率でも棄却対象となり得る。これは「候補の正しさ」を別の判定規則へ置き換えるものであり、標準SDの確率的な分布補正と同義ではない。

### 2. 乖離閾値Tによる決定的な受理

各候補位置でDiv(PT[i],PD[i])を計算し、Div<Tならその候補を受理、そうでなければ棄却する。受理判定は二分布とTが固定されれば決定的である。最初の棄却位置では、FSDはターゲットモデルの元の分布PT[i]から利用者指定の標本化規則でトークンを再生成する。標準SDのような確率比に基づく受理と差分分布からの補正再標本化は行わないため、ターゲット単独の分布と厳密には一致しない。

乖離尺度として原著はカルバック・ライブラー乖離（KL divergence）、ジェンセン・シャノン乖離（JS divergence）、全変動距離（total variation distance）を比較し、主要実験では予備評価で最も良好だったJS乖離を採用する。尺度が変わればTの数値的意味も変わるため、ある尺度で選んだTを別尺度へそのまま流用して同等の品質を期待できない。

Tを小さくすると、分布が極めて近い位置だけを通すためターゲットの品質へ近づく一方、受理長は短くなる。Tを大きくすると受理長が伸びるので、標準SDで最適だった候補長Lより長い候補を用いて速度を上げられる場合がある。ただし長い候補を生成するドラフト計算費用も増え、TとLは入力分布ごとに調節する必要がある。

### 3. 分布差の上界と品質保証の違い

原著§4.2は、生成長N、最終トークンのうちドラフト由来の割合、閾値Tを用いて、生成列全体の分布乖離を上から制限する式を議論する。ただしこの形式的な分布差の上界は、数学問題の正解率やコード実行成功率が何ポイント下がるかを直接示すものではない。少数の重要トークンでの差異は、分布全体の平均的な近さ以上に最終解答を変える可能性がある。著者らも、どの位置で分岐したかが下流の品質を左右するため、実測による評価が必要と明記する。

厳密な分布同値性を残したい用途向けには、縮約可能なFSD（reducible FSD; rFSD）も提案する。rFSDは乖離閾値による受理に加えて、標準SDの確率的受理も許し、T=0で標準SDと同じ受理・補正再標本化へ戻る。主要結果表は通常FSDであり、rFSDの追加検証は付録に置かれる。通常FSDでTを小さくしたときに「実測正解率がSDへ近づく」ことと、rFSDのT=0で「受理規則がSDへ一致する」ことは区別する必要がある。

### 4. 既存の投機的復号拡張への適用

FSDはドラフトとターゲットの各候補位置の分布が取得できれば、候補木の生成方式自体を変えずに受理規則を差し替えられる。原著は動的ドラフト木を用いるEAGLE-2へFSDを組み込み、CommonsenseQAとGSM8Kで正解率と速度の交換条件が維持されることを図5で示した。ただし、これだけで全ての投機的復号拡張に追加費用なく適用可能と証明したわけではない。全語彙の分布を利用できることと、乖離計算の追加費用が実用的であることが前提となる。

### 感度・構成要素除去・負の結果

### 課題分布とモデル間の整合

原著の図3は、LlamaのドラフトとターゲットのJS乖離の分布を課題ごとに示す。GSM8KやHumanEvalでは低乖離に集中し、CommonsenseQAやMMLUでは乖離が大きい位置が相対的に増える。この違いは、標準SDでもFSDでも候補受理率と速度に影響する。したがって「モデル組が同じなら閾値Tと速度の関係も同じ」とは言えず、タスク分布に応じた検証が必要になる。

### 小さい開発集合による閾値調整

原著Table 4では、CSQAとGSM8Kについて、開発集合の問題数を4、8、16、32へ変え、10通りの標本で測定した速度がテスト集合の速度とどれだけずれるかを調べる。GSM8KのT=0.7では、4問の平均速度推定誤差が3.7%、8問で2.2%、16問で1.3%、32問で0.9%となる。一方、CSQAのT=0.5では4問2.6%、8問3.9%、16問1.2%、32問1.4%で、問題数を増やすたび単調に改善するわけではない。小規模な開発集合でも初期の閾値選択は可能だが、少数標本での誤差と課題依存性が残る。

### 比較基準と生成規則

図2では、要求をドラフト単独とターゲット単独へランダムに振り分けることで速度・正解率を調整する単純な混合方式と比較する。FSDは、同じ速度ならこの要求単位の混合より高い正解率を得る傾向を示す。これはトークン位置ごとの分布近さを利用する利点を示すが、他の高度な近似投機的復号方式すべてに対する優位性を意味しない。

図4では拒否時にターゲット分布から貪欲に選ぶ設定でもFSDの傾向を検証する。低閾値では標準SDの正解率へ近づき、高閾値では速度を増やす代わりに品質が低下する。EAGLE-2への統合（図5）でも同様の交換条件を確認するが、実測したのは主としてLlama 3.1 8B Instructを使うCSQA/GSM8Kである。

### 分布保存を放棄することの制約

FSDの出力分布はターゲットモデルと厳密に同一ではない。ベンチマーク正解率が同じでも、個別トークンの確率、出力の多様性、希少事象、長文生成の分布差は同じとは限らない。品質差はどの位置で乖離したかに左右されるため、数式上の分布差上界を実用タスクの正解率保証と読み替えてはいけない。厳密な分布保存が契約上必要な用途には、通常FSDではなく標準SDまたはT=0で標準SDへ戻るrFSDの選択を検討すべきである。

また、原著はバッチサイズ1と限られたGPU/モデル組での実測である。多要求同時サービング、巨大語彙での分布乖離計算費用、CPUオフロード環境、ネットワーク分離型の投機生成まで一般化した速度を示していない。原著付録にはGemma 2のCSQAプロンプトに意図しないトークンが含まれた点も記載され、著者らは影響が小さいと確認したうえで結果を維持したとしている。この実験上の注意も完全な再現を試みる際に必要である。

### 既存研究との差と実装上の位置づけ

標準SD、EAGLE-2などの主流方式は、ドラフト生成とターゲット検証の構造を工夫して受理長を増やしつつ、最終分布をターゲットへ合わせる。FSDは候補生成器や検証木を変更するのではなく、**受理判定そのもの**に分布乖離閾値を導入して近似性を許容する点が異なる。学習済みの判定器で候補を選ぶJudge Decodingと比べると、追加の判定器学習を要しないという利点がある一方、語彙分布を評価する追加費用と分布保存の喪失を伴う。

著者はTransformersの補助生成経路を改造した公式実装を公開している。実装移植では、(1) ドラフト候補の生成、(2) ターゲットによる候補位置の確率分布取得、(3) JS乖離計算、(4) 閾値による最初の棄却位置の決定、(5) 拒否時のターゲット分布からの再標本化、という処理を一貫して保持する必要がある。通常SDの補正再標本化をFSDへ誤って残す、または通常FSDの再標本化を標準SDへ流用する、といった混同は分布特性を変えてしまう。
