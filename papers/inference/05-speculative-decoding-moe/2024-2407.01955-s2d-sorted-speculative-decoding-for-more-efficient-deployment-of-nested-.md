# S2D：入れ子型ドラフトを用いる複数LLM向け投機的復号

## 概要

投機的復号は、小さなドラフトモデルが先の複数トークンを予測し、大きな対象モデルがそれらを一括検証することで、逐次デコードに必要な対象モデルの実行回数を減らす。しかし、サービスが7B、13B、70Bなど異なる対象LLMを同時に提供すると、単一ドラフトの予測一致率と実行時間の最適点は対象ごとに異なる。対象ごとに独立したドラフトを学習・保存する方式は運用費を増やし、対象モデルを改変する自己投機方式も外部提供モデルには適用しづらい。

S2D（Sorted Speculative Decoding）は、1つのドラフト重みから6層・9層・12層の部分モデルを取り出せるよう同時に調整し、各トークンの確信度を見ながらどこまで計算するか選ぶ。Vicuna-7Bから取り出した12層を共通ドラフトとして利用し、対象側のVicuna-7B、Vicuna-13B、LLaMA-2-Chat-70Bを変更せずに検証する。Spec-BenchのMT-Bench評価では、3対象×greedy/非greedyの6条件における自己回帰生成比の単純平均高速化が**1.55倍**であった（Table 2）。この平均は常に最良であることを意味しない。Vicuna-7Bでは固定6層ドラフトの方が速い条件があり、70Bでは深いドラフトの受理トークン長が重要になる。

## 問題設定と設計上の狙い

通常の投機的復号は、ドラフトの1トークン生成が十分安価で、しかも対象モデルが多くのドラフトトークンを受理するときに有利になる。浅いドラフトは安いが、分布が対象と離れると受理長が短くなる。深いドラフトは一致率を上げやすい一方、候補生成が遅くなる。対象モデルの大きさが変わると、対象側1回の検証時間も変わるため、同じドラフトの最適な深さは一定ではない。

本論文が解くのは「複数の対象モデルを1つのドラフト系で支援しながら、対象ごとに計算費用と受理長の釣合いを変える」という配備問題である。単に小型モデルを圧縮する研究ではなく、ドラフト生成器の再利用可能性とトークン単位の動的計算量制御が中心である。対象LLMを再学習しないことも重要な制約である。対象の内部表現に合わせた特徴蒸留を必要とするドラフト方式では、対象を交換するたびに再調整が必要になる。

従来の自己投機的復号では対象モデルの中間層を直接利用するが、S2Dでは**ドラフト側だけ**に入れ子構造と調整を施す。これにより対象の重みを変更しない一方、対象に完全に依存しないドラフトでも必ず高い受理率を得られるわけではない。特に別の語彙・トークナイザを持つ対象へそのまま適用できることは、論文の評価からは確認できない。

## 手法

### 1. 12層の共通ドラフトと入れ子部分モデル

最初にVicuna-7Bの32層から先頭12層を取り出し、これをドラフトの最大深さとする。さらに先頭6層、先頭9層、先頭12層をそれぞれ独立した出力可能点として設定する。各部分モデルは同じ前段重みを共有するため、3個の別モデルを丸ごと保存するのではなく、最大12層の内部に3種類の計算経路を内包できる。共通の言語モデル出力ヘッドを通して各深さから次トークン分布を得る設計である（Section 3.1、Figure 1）。

学習ではSorted Fine-Tuning（SoFT）を使い、各深さの損失を平均した目的関数を最適化する。論文の式(3)は `L = (Σ_{n∈B} L_n(x; θ_n))/|B|` であり、`B` は使用する部分モデル深さの集合である。通常の教師あり調整（SFT）で12層だけを最適化すると、途中6層・9層の出力は十分に学習されない。SoFTは中間出口を同時に学習させることで、浅い出口にも候補生成能力を持たせる。訓練はShareGPTを用いて3エポック行い、実験では6/9/12層の3出口を固定している。

この構造は推論時の重み管理を簡略化するが、学習を不要にするわけではない。12層を切り出しただけの未調整モデルと、SoFT後の入れ子ドラフトは異なる。部分モデルを増やす場合、出口ごとの出力品質と学習負担、キャッシュ・ヘッドの実装を再検証する必要がある。

### 2. 確信度によるトークン単位の早期終了

候補トークンを1つ生成するたび、まず最も浅い6層の出口で予測分布と確信度 `c` を得る。6層用の閾値 `τ6` 以上ならそのトークンをドラフト候補として採用し、深い層は実行しない。閾値を満たさなければ同じ入力状態を9層へ進め、`τ9` を満たすか調べる。それでも不足する場合は最大12層まで計算する。これはAlgorithm 1の `GenerateCandidates` に対応し、各段で `c ≥ τ_n` を検査する。

出力は採用したトークン候補と確信度であり、複数の候補を順次ドラフト列へ追加する。各トークンの難しさに応じて計算する層数が変わるため、簡単なトークンでは浅い出口で安価に済ませ、曖昧なトークンでは深い出口を使う。重要なのは、確信度が高いことは**対象モデルの受理保証ではない**点である。対象の分布とずれていれば、ドラフトが自信を持っても検証で棄却され得る。

閾値は対象ごとに調整する。小型対象ではドラフト側の遅延が相対的に大きいため、浅い出口を通しやすい低閾値が有利になりやすい。70B対象では対象の検証が高価なので、深い出口によって受理長を伸ばす方が利益になり得る。論文のFigure 3は3種類の閾値設定を比較し、対象サイズによって最適値が異なることを示す。これは対象に依存する新たなハイパーパラメータであり、完全な無調整の汎用ドラフトではない。

### 3. 対象モデルによる一括検証と出力確定

候補列を作ったら対象LLMに渡し、ドラフトの各位置について対象側の確率分布を一括計算する。検証関数が受理したトークンを出力列へ連結し、次の候補生成へ進む。Algorithm 1では `VerifyTokens(target, context, candidates)` がこの役割を担う。対象モデルはSoFT学習の対象ではなく、元の対象LLMが生成結果の妥当性を判定する。

通常の投機的復号では、greedyなら対象の予測との一致、確率的サンプリングなら適切な棄却・補正手続きが出力分布保存の鍵となる。本論文はgreedy（温度0）と非greedy（温度1）の速度を評価するが、Section 2では一般化された投機的サンプリングとの統合を今後の課題とも記している。そのため「全てのサンプリング条件で対象モデルと厳密に同じ確率分布を証明した」とまでは読み取れない。実装時には採用した検証手続きを別途確認すべきである。

### 4. 一連の実行例と追加費用

1リクエストで候補列を作る際、各候補位置について6層から開始し、閾値を満たすまで9層・12層へ進む。候補が揃った時点で対象LLMを一度走らせ、受理列を確定して次の候補列へ移る。したがってS2Dの費用は、出口ごとの平均実行層数、候補列長、対象側の検証時間、棄却によるやり直しに分解できる。浅い出口の確信度が過大なら受理率が落ち、過小なら深い出口を多用してドラフトが重くなる。

また、3つの出口を支える学習、対象ごとの閾値探索、推論時の中間出力の計算・管理が必要になる。最大12層を超えるドラフトの容量や、異なるモデル系列・トークナイザ間の共通運用はこの実験では証明されていない。

## 評価

### 実験条件と比較対象

主要評価はSpec-Bench（翻訳、複数ターン会話、検索拡張生成、数学推論、質問応答、要約の6課題、各80例）である。Table 2はそのうちMT-Benchで、対象モデルVicuna-7B、Vicuna-13B、LLaMA-2-Chat-70Bを使い、温度0と温度1を比較する。ドラフトはVicuna-7Bの先頭12層から抽出し、ShareGPTで3エポック学習したものを用いる。速度倍率は対象モデルの通常の自己回帰生成を1倍とした値であり、モデル間の絶対token/s比較ではない。

比較対象には、通常SFTした12層ドラフト、SoFTした固定6/9/12層ドラフト、SoFT＋S2Dがある。EAGLE、Medusa、Hydraの公開済み対象依存チェックポイントはVicuna-7Bにのみ適用可能であり、13B・70Bの欄は比較不能と明記されている。注意木を外した場合の結果も別途示されているため、木を使う方式の倍率をそのまま同じ実行条件の公平比較と解釈しない。

### GSM8Kでの対象側改変との比較（Table 1）

Llama2-13BをGSM8Kで評価すると、通常の対象モデルは正答率48.97、速度1倍である。対象そのものをSoFTして自己投機する構成は1.21倍だが正答率33.51へ低下した。これに対しドラフト側のみSoFTしたS2Dは1.53倍で、正答率48.97を維持したと報告する。ここでの16ポイント弱の精度差はこの特定の対象側SoFT構成との比較であり、自己投機方式全般が精度を落とすという結論ではない。

Table 5ではGSM8K用に対象モデルも調整した場合、S2Dは1.53倍・正答率48.97、対象未調整の場合は1.38倍・正答率28.7となる。速度の差は対象とドラフトの分布整合に依存することを示すが、両者の正答率は対象モデル自体の学習条件も異なるため、S2D単独の精度改善として読んではならない。

### 感度・構成要素除去・負の結果

Figure 3の閾値感度では、低閾値の構成はVicuna-7B/13Bで有利になり、高閾値の構成は70Bで有利になる。閾値は対象に応じて選んだ後に他の実験で固定している。これは対象サイズを知らなくても閾値が自動的に最適化される、という主張とは異なる。

Table 4では、12層ドラフトの初期重みをVicuna-7Bからの切り出しではなく、事前学習済みの約160Mモデルへ置き換える。温度0のVicuna-7B/13B/70BでS2Dは1.17/1.28/1.91倍となり、元の切り出し構成の1.34/1.38/1.95倍より低い。特に小型対象では初期化の違いが無視できず、「事前学習済み小型ドラフトなら常に有利」とは言えない。

Table 3は別のEAGLEドラフトの特徴整合損失を検証している。Llama2-13BのGSM8Kでは、特徴整合とトークン整合の両方を使う場合2.73倍、トークン整合を外しても2.70倍だが、特徴整合を外すと1.61倍へ落ちる。これはEAGLEの対象依存性の根拠であって、S2Dの機構そのものの除去実験ではない。比較対象を区別して扱う必要がある。

## 既存研究との差

一般的な投機的復号は対象とドラフトの一対一対応を前提にしがちで、複数対象へ最適化する場合はドラフトの選択・再学習・配備が複雑になる。S2Dは一つの12層ドラフトに複数の出口を内包し、トークンの確信度で浅い出口と深い出口を切り替える点が異なる。対象の内部特徴に合わせて専用のドラフトを訓練するEAGLE型の手法とは、モデル間の再利用性を重視する設計目標が異なる。

一方、SoFT自体は既存のSortedNet/Sorted Llama系の学習思想であり、S2Dの寄与はその仕組みをドラフト側へ適用し、対象を変更せず複数対象へ使い分ける投機的復号の運用と閾値選択にある。固定6層ドラフトの方が良い条件も存在するため、個別対象だけを最速にする手法というより、複数モデルの共通運用で性能を大きく落とさない手法と捉える方が正確である。

## 限界と再現時の注意

第一に、出口ごとの確信度閾値は新たなハイパーパラメータであり、原著は対象サイズごとに最良値を選んでいる。対象モデルやタスクが頻繁に入れ替わる環境では、閾値探索の運用費を無視できない。実測の高速化が1.55倍であっても、学習・閾値調整・モデル配備を含めた総所有費用の改善率は論文に示されていない。

第二に、評価は主としてVicuna系列とLLaMA-2-Chat-70B、ShareGPTで学習したドラフトに限られる。別の語彙、トークナイザ、注意構造、MoE対象へそのまま適用可能かは未評価である。推論基盤へ実装する際はドラフトと対象のトークン空間の整合、および中間出口を切り替えた際のKVキャッシュ管理を確認する必要がある。

第三に、原著はSpec-Benchの速度倍率とMATを示すが、GPU機種・同時実行数・メモリ常駐容量を揃えた大規模サービングの費用や、実際の複数対象を同時に処理するキューイング効果を網羅的には測定していない。多対象の「同時利用」は共通ドラフトを各対象へ使えるという意味であり、複数モデルを同一GPUに同時常駐させた際の全体スループット保証ではない。

第四に、最小6層固定の方が速い負の結果を隠してはならない。対象の検証が安い場合、深い出口への分岐と確信度判定が追加費用になる。逆に大きな対象では受理長を優先した深い出口が有利であり、1つの固定閾値が万能ではない。さらに非greedyの分布保存の形式的保証や、一般的な投機的サンプリングとの完全な統合については論文の記述だけでは確定できない。
