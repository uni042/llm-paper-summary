# Context-Aware Assistant Selection for Improved Inference Acceleration with Large Language Models

## 一文解説

投機的復号で用いる小型ドラフトモデルを一つに固定せず、入力の分野や内容に応じて複数候補から選ぶ方策を、対象モデルと候補モデルの独立生成結果だけを使って学習する研究である。

## 概要

投機的復号（Speculative Decoding）は小さなドラフトモデルが複数トークンを先読みし、大きな対象モデルがまとめて検証することで逐次生成の遅延を削減する。ドラフトの予測が対象モデルとよく一致すれば多くのトークンが受理され、高価な対象モデルの実行回数を減らせる。しかしドラフトが不得意な分野では予測が棄却されやすく、ドラフトの計算費用だけが増えてかえって遅くなる。

本研究は、翻訳に強いドラフトと要約に強いドラフトのように、専門分野が異なる複数候補を持つ場合の選択問題を扱う。入力クエリを文脈、ドラフト候補を行動、その候補を選んだ場合の効率を報酬とみなす文脈付きバンディット（Contextual Bandit）として定式化する。学習時には各候補と対象モデルをそれぞれ独立に貪欲生成させ、出力間の類似度を測る。対象モデル内部の構造やドラフトの学習データを知らなくても、どの入力でどのドラフトが有効そうかを推定できるようにする。

実験ではFlan-T5-XXLを対象モデルとし、T5-Smallや要約向けに調整されたT5-Small-XSumなどを候補に用いる。翻訳IWSLT2017 En-Deと要約XSumを混ぜた条件では、ドラフトを固定すると片方のタスクで速度低下するのに対し、選択方策は両方で高速化を達成する。投機的復号での貪欲選択方策は翻訳1.09倍、要約1.17倍、両タスク平均1.13倍を報告する。これは単独の最良ドラフトが得意タスクで出す最大速度より必ず速いという意味ではなく、**分野をまたいだ速度低下を減らす**ことが中心的な価値である。

さらに候補モデルのサイズを報酬へ組み込むと、出力が対象モデルに似ていても計算費用が大きいドラフトを避けられる。全ての候補が役に立たない場合に対象モデルの通常の自己回帰生成を選択肢へ加えることも検証する。GSM8Kのような候補ドラフトが不向きな分野では、選択方策がドラフトを使わない判断を学ぶことが重要になる。

## 背景と問題設定

自己回帰型LLMは次トークンを一つ生成するたびにモデルを実行するため、巨大モデルでは逐次的な実行回数が遅延を支配する。投機的復号では小型モデルが先に複数トークンを生成し、大型モデルがそれらを並列に検証する。候補が受理される長さが大きければ対象モデルの実行回数を減らせるが、ドラフトの予測分布が対象モデルと大きく異なる場合、候補の棄却が多くなり高速化できない。

例えば翻訳でよく一致する小型モデルが要約では不得意な場合、同じドラフトを全要求に使うと翻訳は速くなっても要約は遅くなる。逆に要約へ特化したドラフトを使えば翻訳で同じ問題が起こる。候補の内部構造や学習履歴が分からなくても、入力の特徴から最も有効な候補を選ぶ仕組みが必要になる。複数ドラフトを同時に走らせてその場で最良を選ぶ方法は費用が大きいため、軽量な選択方策を事前学習する方が実用的である。

選択すべきドラフトは、対象モデルとの予測一致度だけで決まらない。大型のドラフトは対象モデルに近い文章を出すかもしれないが、ドラフト自身の逐次生成が遅ければ、受理率が高くても全体の遅延は改善しない。したがって候補選択には、対象モデルとの整合とドラフトの計算費用の二つの情報が必要である。原著はこれらを報酬として組み合わせ、入力文脈ごとの選択方策を学ぶ。

## 手法

### 1. 文脈付きバンディットとしての候補選択

各入力クエリqを文脈とし、候補ドラフトjを行動とみなす。方策はqから各候補を選ぶ確率を出力し、選んだ候補で投機的復号したときの効率を高めるよう学習する。理想的には各候補で実際に投機的復号を行い、実時間の速度向上を報酬にすればよいが、全入力・全候補で対象モデルの検証まで実行するのは高価である。

そこで原著は、対象モデルと各ドラフトを独立に貪欲生成し、出力文の類似度を計算して代理報酬とする。出力がよく似ていれば投機的復号でも候補が受理されやすいと期待できる。ただし文章単位の類似度とトークン単位の受理確率は同じではなく、代理報酬は速度を直接測定した値ではない。この違いを踏まえ、必要に応じてドラフトのサイズや推論費用も報酬へ加える。

### 2. オフライン生成結果から報酬データを作る

学習用クエリ集合を用意し、対象モデルと全ドラフト候補がそれぞれ文章を生成する。各ドラフトの出力と対象モデルの出力を比較し、原著はROUGE-Lを類似度として用いる。これにより「この入力で候補Aは対象に近く、候補Bは遠い」という報酬データを作る。対象モデルの確率分布やドラフトの内部層へアクセスする必要はなく、独立した生成結果だけで訓練データを得られる。

類似度だけでは大きいドラフトを過度に選ぶ場合があるため、報酬を類似度と候補の計算費用の重み付き和に拡張する。論文の式では重み係数を0〜1の範囲で変え、どちらの要素を重視するかを調整できる。係数の説明は本文中の表記と図の解釈に注意を要するため、実装では係数が「類似度重視」と「費用重視」のどちらを表すか、報酬の正規化も含めて検証する必要がある。

### 3. 軽量な選択方策の学習

方策の入力は対象モデルから得たクエリの文埋め込みで、出力はドラフト候補ごとの選択確率である。原著は512次元の隠れ層を持つ3層多層パーセプトロンを用い、tanh活性化関数で学習する。オフライン報酬を用いて方策勾配のREINFORCEに相当する目的関数を最大化する。訓練は3エポック、バッチ64、AdamW、学習率0.001、重み減衰0.01で行う。

推論時には入力クエリを一度埋め込みへ変換し、方策が選んだ一つのドラフトを用いて投機的復号を開始する。候補を全て実行してから選ぶわけではないため、選択の追加費用を小さくできる。選択には最大確率の候補を使う貪欲方策と、確率分布から候補を抽選する動的方策の二種類を評価する。実験では両者の性能差は大きくない。

### 4. 受理率とドラフト費用の交換条件

投機的復号の全体速度はドラフトが候補トークンを作る時間、対象モデルが候補を検証する時間、受理されたトークン数によって決まる。ドラフトが大きいほど対象モデルに近い文章を生成できる場合があるが、候補生成にかかる時間も長くなる。原著は60M〜220M程度の複数サイズのドラフトを比較し、出力一致度が高いだけでは最良の速度を得られないことを示す。

候補のサイズを費用の近似として用いる方式は、正確な実測遅延を全て収集するより安価である。ただしモデルサイズと実時間の関係はGPU、バッチサイズ、量子化、カーネル実装によって変わるため、サイズだけで速度を決めることはできない。実運用では実測の候補生成時間を利用できるなら、その方が適切な場合もある。原著の目的は、限られた情報からでも有効な候補選択を学習できることを示す点にある。

### 5. 自己回帰生成を選択肢に含める

全てのドラフトが対象モデルと一致しにくい分野では、投機的復号を使わず対象モデルだけで生成する方が速い場合がある。原著はこの「ドラフトなし」の選択肢を候補集合へ追加する。学習時には対象モデル自身の出力と比較するために、通常の貪欲生成だけでなくサンプリング結果も用い、自己回帰選択が自動的に完全一致で報酬最大にならないようにする。

この設計は候補モデルが全て不適切な入力を見分けるために重要である。投機的復号を常に使う方式では、受理率が低いと候補生成費用が無駄になる。方策が通常生成を選べれば、分野外の入力での速度低下を抑えられる。ただし方策の予測が誤れば不適切なドラフトを選ぶ可能性は残るため、速度の保証ではなく期待性能を改善する仕組みである。

## 評価

### 実験条件と比較の枠組み

主な対象モデルはFlan-T5-XXLで、ドラフトはT5-Small、要約向けに調整されたT5-Small-XSum、Flan-T5-Small、Flan-T5-Baseなどである。翻訳はIWSLT2017英語・ドイツ語、要約はXSumを用いる。追加の検証としてGSM8Kの数学的推論も扱い、全候補が不向きな入力で通常生成を選べるかを調べる。

投機的復号ではドラフトトークン数を7、サンプリング温度を1とする条件を中心に評価する。速度は対象モデル単独の自己回帰生成を1倍とした倍率と、トークン当たりの実時間を併記する。翻訳の品質はBLEU、要約はROUGE-Lで測定する。貪欲生成を用いた支援復号と、サンプリングを用いた投機的復号は品質の基準が異なるため、速度と品質を別々に比較する必要がある。

### 分野別のドラフト固定と方策選択

| 方式 | 翻訳速度 | 要約速度 | 両タスク平均 | 解釈 |
| --- | ---: | ---: | ---: | --- |
| 対象モデル単独 | 1.00倍 | 1.00倍 | 1.00倍 | 基準 |
| T5-Small固定 | 1.10倍 | 0.99倍 | 1.04倍 | 翻訳に比較的適合 |
| T5-Small-XSum固定 | 0.83倍 | 1.18倍 | 1.01倍 | 要約に適合、翻訳では減速 |
| 方策・貪欲選択 | 1.09倍 | 1.17倍 | 1.13倍 | 両分野で高速化 |
| 方策・確率的選択 | 1.07倍 | 1.16倍 | 1.11倍 | 両分野で高速化 |

この表はサンプリングを伴う投機的復号の結果である。T5-Small-XSumは要約では1.18倍だが翻訳では0.83倍へ減速する。選択方策は翻訳で1.09倍、要約で1.17倍と、どちらでも対象モデル単独より速い。平均1.13倍は全ての入力で1.13倍を保証するものではなく、二つの異なる分野をまとめた平均である。最良の単一候補に常に勝つわけでもないが、苦手分野での大きな速度低下を避ける利点がある。

貪欲支援復号の表では、T5-Smallの翻訳受理率41.68%、要約28.21%、T5-Small-XSumの翻訳7.23%、要約40.24%と分野差が大きい。投機的復号の受理率でも、T5-Smallは翻訳38.21%、要約26.02%、T5-Small-XSumは翻訳8.75%、要約38.29%である。ドラフトの得意分野と対象モデルの出力一致が、受理率を通じて速度に反映されることが分かる。

### 実時間と品質の読み方

対象モデルのサンプリング自己回帰生成は、翻訳で約31.06ミリ秒/トークン、要約で約37.06ミリ秒/トークンだった。貪欲選択方策を使った投機的復号は翻訳28.56ミリ秒、要約31.63ミリ秒である。実時間を併記することで、速度倍率が対象モデル単独のどの条件を分母としているか確認できる。生成品質はサンプリング設定に依存し、表にあるBLEUやROUGE-Lの違いを速度改善と混同してはいけない。

通常の貪欲生成による支援復号では、対象モデルの翻訳BLEU18.26、要約ROUGE-L35.93を維持したまま速度を測る。一方サンプリングを使う投機的復号では対象モデル自身の翻訳BLEU9.85、要約ROUGE-L29.83が基準となり、方策選択時の翻訳BLEU9.76、要約ROUGE-L29.83などと比較する。二つの表を跨いでBLEU18.26と9.76を直接比べ、「方策が品質を大幅に落とした」と結論するのは不適切である。サンプリング方式が異なるためである。

### ドラフトのサイズと整合度

| XSum、Flan-T5-XXL対象 | 対象モデル単独比 | トークン当たり時間 |
| --- | ---: | ---: |
| 対象モデル単独 | 1.00倍 | 37.06 ms |
| T5-Small | 0.97倍 | 38.60 ms |
| T5-Small-XSum | 1.21倍 | 30.71 ms |
| Flan-T5-Small | 1.09倍 | 34.15 ms |
| Flan-T5-Base | 1.00倍 | 37.02 ms |

この比較は、大きいドラフトほど速いわけではないことを示す。Flan-T5-BaseはFlan-T5-Smallより大きいが、XSumでの投機的復号は1.00倍にとどまり、より小さいT5-Small-XSumが1.21倍を得る。出力整合度とドラフト自身の費用を同時に考慮する必要がある。原著は報酬の重みを変え、速度を重視する方策と出力一致を重視する方策の選択傾向が変わることを示す。

### 学習データ量と一般化

方策は約40万件のオフライン学習例を用意した実験で、1万件未満の学習例でも全データを使った場合に近い選択性能を得たと報告する。これは、対象モデルと候補ドラフトの独立生成結果から比較的少ない例を集めるだけでも、翻訳と要約の分野差を学習できることを示す。ただし候補モデルや対象分野が変わると必要な学習例も変わる可能性があり、1万件という値を全用途の保証として扱うべきではない。

オフライン学習は本番推論時の選択費用を小さくする一方、学習例を作るためには対象モデルと全候補の生成を事前に行う必要がある。候補数が多いほど準備の費用が増えるため、候補の追加・削除や分野分布の変化が頻繁な環境では再学習の負担も考慮すべきである。本文は特定の候補集合での結果を示しており、無制限に多数の候補を同時運用しても同じ費用で済むわけではない。

### ドラフトなしの選択肢とGSM8K

| GSM8K、Flan-T5-XXL対象 | 速度 | トークン当たり時間 |
| --- | ---: | ---: |
| 対象モデル単独 | 1.00倍 | 22.03 ms |
| T5-Small固定 | 0.78倍 | 28.08 ms |
| T5-Small-XSum固定 | 0.74倍 | 29.91 ms |
| 方策・貪欲選択 | 0.95倍 | 23.54 ms |
| 方策・確率的選択 | 0.95倍 | 23.45 ms |

GSM8Kではどちらのドラフトも不向きで、固定すると対象モデル単独より遅くなる。方策へ通常の自己回帰生成を候補として追加すると、速度は0.95倍まで回復する。これはドラフトを無理に使わない判断を学んだことを支持するが、対象モデル単独の1.00倍へ完全に一致していない点も重要である。選択器の費用や選択誤りが残るため、速度低下をゼロにする保証はない。

## 既存研究との差

通常の投機的復号は対象モデルとドラフトモデルの組を固定し、受理率が高い場合に対象モデルの逐次実行回数を減らす。ドラフトを対象モデルに合わせて追加学習する方式もあるが、候補の重みや訓練データへアクセスできない場合には難しい。提案法は既存の複数候補を変更せず、独立生成した文章の類似度だけを用いて入力ごとの選択方策を学習する点が異なる。

一般的なモデルルーティングは入力に応じて回答を生成する主モデルそのものを選ぶことが多い。ここでは最終出力を担当する対象モデルは固定し、あくまでその対象モデルの生成を高速化する補助ドラフトを選ぶ。したがって品質や分布の最終的な基準は対象モデル側にある。ドラフトが変わると検証の受理率が変わるが、対象モデルを別の安価なモデルへ置き換えるのではない。

入力の文脈を使って候補を選ぶ点では混合専門家のルーティングと似るが、専門家は一つのモデル内部の層ではなく、独立して実行できるドラフトモデルである。選択器は候補の内部構造を知らず、対象モデルとの出力一致と計算費用を報酬として利用する。これにより翻訳・要約など複数分野の混合要求で、単一ドラフト固定による速度低下を抑えられる。

## 限界・実装状況

主な実験はFlan-T5-XXLとT5系の小型ドラフト、翻訳・要約・数学問題という限られた候補と分野で行われる。異なるアーキテクチャや多数の候補、非常に長い文脈、複数要求を同時処理する配信環境での選択器の性能は、同じ条件で保証されていない。複数ドラフトをGPUへ常駐させる場合は重みメモリが増えるため、選択による速度利得と追加メモリ費用の交換条件が生じる。

代理報酬として用いる文章類似度は、投機的復号のトークン単位の受理率と完全に一致しない。類似した文章でも途中のトークンが異なれば棄却が多くなる場合があり、実際の速度はドラフトの生成費用と対象モデルの検証費用にも依存する。候補のサイズだけを計算費用の代理とする場合も、GPUや量子化形式によって実時間が変わるため注意が必要である。

方策の学習には対象モデルと全候補によるオフライン生成が必要で、候補集合や対象モデルを変更するとデータを作り直す負担がある。入力分布が学習時から大きく変わる場合、誤ったドラフトを選ぶ可能性も残る。GSM8Kの例ではドラフトなしを選べても0.95倍であり、最悪時の速度低下を完全に排除するものではない。

実装は文埋め込みを使う3層の多層パーセプトロン選択器を中心とする。公開コードの正確なURLは一次資料から特定できなかったため、公式実装が公開済みと断定しない。論文の速度は特定のモデルと実験環境に依存し、Windowsや小容量GPUで同じ倍率を得られる保証はない。

## 読解上の注意

提案法は対象モデルの演算そのものを高速化するのではなく、ドラフト候補の選択を改善して投機的復号の無駄を減らす。1.13倍という平均は翻訳と要約の特定の混合評価であり、GSM8Kではドラフトなしを選んでも0.95倍にとどまる。受理率、文章類似度、トークン当たり実時間、生成品質の指標を区別して解釈する必要がある。
