# Parallel Token Prediction：乱数を入力化して依存した複数トークンを一度に予測する

## 概要

通常の自己回帰言語モデルは、直前までの確定トークンから次の確率分布を計算し、その分布から1トークンを標本抽出する。この操作を繰り返すため、出力が長いほど順伝播の回数が増える。投機的復号（speculative decoding）は小さなモデルに先読みさせて大きなモデルでまとめて検証するが、草案モデル自身が1トークンずつ順次生成する費用は残る。複数トークンを独立に予測する方法は速い反面、後続語が前の語と矛盾する系列を生みやすい。

並列トークン予測（Parallel Token Prediction; PTP）は、次トークンの確率分布を計算した**後**で乱数を引くのではなく、先に乱数 `u_i` を引いて**モデルの入力**に与える。各将来トークンは過去トークンと乱数列の決定論的な関数として表現できるため、互いに依存した複数トークンを1回の順伝播で予測する。理論上の表現可能性と、有限モデルでの誤差を教師モデルの検証で補正する実装を分けて提示する。

Vicuna-7Bを教師として学習したPTPは、RTX A6000単体でSpecBenchの6種類の文章生成課題において、通常の自己回帰生成比で平均**2.40倍**の実時間高速化を報告した。逐次検証での平均受理トークン数は**4.21**。ただしこの速度は教師との検証を含む特定の投機的復号構成と並列計算能力に依存する。理論上「任意長を一度に表現できる」ことと、現実に無制限の長さを一度で正しく生成できることは同義ではない。

## 問題設定：独立予測では系列の整合性が失われる

通常の生成では位置 `i` のトークン `t_i` の条件付き分布 `P(t_i|t_<i)` を計算し、その確率に従って抽出する。次の位置 `i+1` の分布は抽出済みの `t_i` に依存するため、トークンごとの依存が計算の逐次性を生む。たとえばプログラム生成では、先頭の語が `import` か `def` かで次に適切な語が異なる。後続語を独立に予測すると、実際には整合しない組合せが出る。

独立した複数出力ヘッドは並列に候補を出せるが、各ヘッドが先行ヘッドの確定結果を条件として見ていない。PTPはこの問題を「依存を無視して並列化する」のではなく、「将来の選択を決める乱数を先に全て提示する」ことで扱う。各位置がそれ以前の乱数を参照すれば、前のトークンがどの選択になったかを関数として再現できる、という発想である。

投機的復号で重要なのは、草案が何トークン先まで教師と一致するかである。草案が速くても早期に誤ると、教師の検証呼出しが頻繁に必要になる。PTPは、1回の草案順伝播で相互に整合する候補を多く出すことで、この受理長を増やす。なおモデルの表現力、乱数の埋め込み方法、検証方式、GPU上の並列性がすべて実際の速度に影響する。

## 手法

### 1. 一様乱数によるトークン選択をモデル内部へ移す

ある位置の語彙分布 `P_i` に対し、通常の標本抽出は一様乱数 `u_i∼U[0,1]` と累積分布 `F_ij=Σ_{l≤j}P_il` を使い、`Pick(u_i,P_i)=min{j:F_ij>u_i}` と書ける。分布と乱数が定まれば抽出結果は決定論的である。論文の定理1は、未来の `t_k` が、確定した過去 `t_<i` と乱数列 `u_i,...,u_k` の関数 `f_P` として表せることを示す。

PTPはこの `f_P` を直接学習する。入力の確定済みトークンの後ろへ将来位置に対応する乱数列を並べ、因果的な注意を用いて各位置の出力を並列計算する。乱数列が将来の標本抽出結果を決めるので、後続位置の予測は前のトークンを明示的に生成し終えるまで待たなくてよい。これは「未来トークンが独立である」という仮定ではなく、依存関係を乱数列へ移した表現である。

実装では浮動小数点数の乱数 `u` を32ビットの二進表現へ変換し、学習可能な線形変換 `W·binary(u)+b` で言語モデルの埋め込み空間へ写す。単一のスカラー値をそのまま入力するより、乱数の区間に応じて抽出語が切り替わる構造を学びやすくする狙いがある。将来トークン数を増やすと並列位置の計算とモデル容量への要求も増えるため、任意長の理論は無料の高速化を意味しない。

### 2. 一点分布版O-PTPと確率分布版C-PTP

一点分布型（One-Hot PTP; O-PTP）は、位置 `k` の予測に**その位置自身の乱数 `u_k` まで**与える。理想的には抽出されるトークンが確定するので、出力は1つの語へ集中する。学習済み教師から高速な草案生成器を蒸留する場合に向くが、元の次トークン確率分布そのものは得られない。このため温度変更や不確実性の推定を、教師の確率分布と同じように扱うことはできない。

カテゴリ分布型（Categorical PTP; C-PTP）は、位置 `k` の予測から**その位置の乱数 `u_k` を隠し**、それ以前の乱数 `u_i,...,u_{k-1}` だけを条件にする。論文の定理2によれば、この条件付き分布は元の自己回帰条件付き分布 `P(t_k|t_<k)` を再現できる。次トークンの確率を保持したい場合や、教師モデルなしでデータから学習する場合に重要な区別である。

両方式とも同じ「乱数を入力にする」考え方に立つが、出力するものが異なる。O-PTPは高速に確定候補を得るための構成、C-PTPは確率分布の情報を残す構成である。論文は両者の表現力を理論的に示す一方、実機での2.40倍という主結果は主として教師から蒸留したO-PTPによる。

### 3. 教師からの蒸留：乱数と正解系列の対応を逆算する

学習用系列 `t_1,...,t_T` を確定済み文脈と予測区間に分ける。教師モデルが各正解トークンに割り当てる累積分布を計算し、そのトークンが抽出される乱数区間 `[F_{k,t_k-1},F_{k,t_k})` から `u_k` を選ぶ。これにより「この乱数列を与えたとき、正解の系列を出す」という教師あり学習の組を作れる。

O-PTPでは `u_k` を含む乱数列を入力して正解トークンへの交差エントロピーを最小化する。C-PTPでは位置自身の乱数を除いた条件で分布を学習し、必要に応じて教師分布とのカルバック・ライブラー距離を使う。論文は教師生成系列を学習に用いる方式が分散の小さい選択肢だったと述べる。教師の出力を一度生成し、同じ系列を複数回の学習に再利用できる。

教師なしC-PTPでは、自身の現在の条件付き分布を用いて正解トークンと整合する乱数を逐次選び、交差エントロピーで更新する。乱数の逆算自体は逐次的だが、これは学習時の手続きであり、学習後の複数トークン予測を1回の順伝播で行う構成とは分けて考える必要がある。教師なしでの実験は小型の系列データであり、大規模LLMを教師なしで訓練して同じ速度・品質を示したものではない。

### 4. 教師による誤り訂正と部分的な二次分岐復号

有限容量のPTPは、理想の関数 `f_P` を完全には再現できない。そこでPTPが一度に提案した候補列を教師モデルで並列検証し、教師が**同じ乱数**を使って抽出するトークンと一致する最長の接頭部を採用する。最初に不一致が起きた位置では教師の結果へ置き換える。この検証を正しく行えば、草案の誤りによって教師の出力分布を変えずに済む。平均受理トークン数は教師呼出し当たりに進める長さを表す。

教師検証と次の草案生成を直列に実行すると、両者の遅延が加算される。そこで論文は二次分岐復号（Quadratic Decoding）の考え方を用い、先の候補が0個、1個、2個……何個正しかったかという各可能性に対する続きの候補を、教師の検証と並列に計算する。教師が真の一致長を決めたら該当分岐だけを採用する。ただし全分岐を均等に計算すると、候補長が増えたとき計算費用が膨らむ。

部分二次分岐復号（Partial Quadratic Decoding）は、草案モデルが出す各トークンの信頼度 `c_k` を利用する。最初の `m` 個が正しい確率を概ね `(1−c_{i+m})·Π_{k=i}^{i+m−1}c_k` と見積もり、限られた追加候補予算 `C` を確率の高い分岐へ重点配分する。こうして教師検証と次草案を重ねながら、不要な分岐を減らす。信頼度と実際の受理率がずれれば予算配分が非効率になる点は残る。

### 構成要素・感度・負の結果

論文の小型モデル比較では、同じ草案モデル規模であっても、複数トークンを1回で出すPTPは小型自己回帰草案より少ない呼出しで進む。図6では、最良構成が必ずしも最小の草案モデルではなく、教師モデルそのものを微調整する方式だった。ただし著者は、小型比較モデルをゼロから学習させたことが影響した可能性を認めており、全モデル規模で大きい草案が優れるという結論ではない。

乱数の埋め込み方法も重要である。PTPは32ビットの乱数表現を線形変換する方式を採用し、付録の比較では構造化した埋め込みの方が学習収束が安定した。教師系列から逆算する乱数の選択、蒸留時の教師生成データ、LoRA階数、草案トークン数、部分二次分岐復号の候補予算はすべて受理率と実時間の交換条件になる。論文のTinyLlama設定では階数256を使用したが、階数64でも近い高速化が可能と報告している。

教師検証と自己検証の区別は特に重要である。教師検証では、提案が教師の同一乱数に基づく抽出結果と一致した範囲だけを採用するため、教師と同じ生成分布を維持できる。自己検証では別の教師呼出しが不要で受理数が6.1に増える一方、保証されるのは**学生モデル自身**の分布に対する整合性であり、教師と同一の出力分布ではない。高速化と分布忠実性を取り違えないよう、運用上は検証者を明示する必要がある。

## 既存研究との差

標準的な投機的復号は、草案モデルが軽量でも将来の語を順に生成する。PTPは草案生成そのものを1回のモデル呼出しで並列化するため、教師検証前の逐次処理を減らす。EAGLEやMedusaなども複数候補を利用するが、PTPの新規性は**出力を決める乱数を条件としてモデルへ渡し、トークン間の任意の依存を表現できる**という定式化にある。

複数トークンを独立予測する方式は、同じ文脈に対する周辺分布を並べるため、先の候補と後の候補が矛盾し得る。PTPの後続位置は先行位置に対応する乱数を参照するので、依存関係を表現できる。離散拡散型の反復修正とも異なり、まず並列に候補を出し、必要な場合だけ教師検証で正確性を確保する。部分二次分岐復号は、この候補と検証を重ねて実時間を短くする追加のシステム技術である。

## 限界

表現力に関する定理は、十分なモデル容量を仮定した理論上の結果である。有限容量・有限学習では長い候補列ほど誤りが蓄積し、検証・再提案が必要になる。実測高速化はRTX A6000の並列性を利用したもので、GPUが弱い、メモリが厳しい、並列候補の計算が高価な環境では同じ倍率を期待できない。特にゲート付きLoRAと特殊な注意マスク、教師と草案の同時処理を実装する必要があり、既存推論ランタイムへそのまま設定だけで組み込めることは示していない。

教師なし学習の実証は小型タクシー系列モデルに限られ、大規模LLMを最初からPTPとして訓練した際の品質改善は未実証である。Vicuna-7Bでの速度比較は6種類のSpecBench課題、温度0.7、RTX A6000という条件であり、別の推論モデル、長文脈、多人数サービング、CPUオフロード、MoEでの結果は報告されていない。受理トークン数が増えても、GPUカーネルや通信の追加費用が大きければ実時間は同じ比率で短縮しない。

教師の出力分布を守る用途では、自己検証の受理数6.1を教師検証の4.2より単純に優れた結果として採用してはならない。自己検証は学生モデルの分布へ切り替わる別設定である。論文の理論と実装は投機的復号を改良する有力な方向を示すが、汎用の「1回の呼出しで任意長の正しい文章を生成する」製品機能が完成したという意味ではない。
