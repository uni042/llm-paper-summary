# Adaptive Multi-Token Prediction: How far should we go?

> マルチトークン予測の投機ホライズンを、受理サバイバルと棄却ハザードのオンライン学習で毎ラウンド事前に選ぶ再学習不要の制御器を提案し、予測誤差からスループット後悔と完了時間への理論的な橋渡しと、固定窓に対する最大10パーセントの実測改善を示した研究。

## 概要

投機的デコードは、安いドラフトが提案した複数トークンを対象モデルが1回のパスで並列に検証し、受理された分だけを確定することで生成を速くする仕組みである。マルチトークン予測は、共有した表現から未来の複数トークンを予測するヘッド群をドラフトとして使う方式で、実運用モデルにも組み込まれている。ここで毎ラウンド必ず決めなければならないのが、何トークン先まで投機するかという投機ホライズンである。ホライズンが長いほど、ドラフトが当たれば検証コストを多くの確定トークンで償却できるが、早い位置で棄却されると、それより後ろのドラフトは計算だけが無駄になる。最適な長さは文脈ごとに変わる。

自己回帰型のドラフトなら、トークンを1つ出すごとに続けるかどうかを判断できる。しかしマルチトークン予測では全ヘッドが同じ順伝播で同時に発火するため、ドラフトのコストは先に全額かかり、ホライズンはドラフトを見る前に固定しなければならない。ドラフトを見てから切り詰めると検証コストは節約できてもドラフトのコストは戻らず、選び方によっては正確性そのものが壊れる。本論文はこの制約を正面から扱い、ホライズン選択を検証フィードバックで学ぶオンライン制御問題として定式化する。

中心となる量は受理サバイバル、すなわちドラフトの接頭辞が全て受理される確率である。本論文は、位置ごとの条件付き棄却確率である棄却ハザードの積からサバイバルが決まり、サバイバルの和から各ホライズンの期待確定トークン数が厳密に決まることを示す。提案手法はこのハザードを検証のたびにオンラインで学習し、ラウンドの予測コストで割った予測スループットが最大のホライズンを選ぶ。再学習は不要で、正確な検証器は一切変えないため、出力は対象モデルの分布のままである。代表結果として、5つのドラフトと対象の組み合わせでは通常デコードより最大4.1倍速く、固定窓に対しては10設定中8設定で同等以上となり、スループットの上乗せは最大10パーセント、ドラフトと対象が別モデルでコスト非対称の大きい組み合わせでは固定窓比で268パーセントの改善も観測された。

## 問題設定

ホライズン選択が難しい理由は、情報とコストの到着順序にある。判断の時点ではドラフトはまだ存在せず、使えるのは過去の検証結果だけである。しかも、短いホライズンを選ぶと後方の位置については検証フィードバック自体が得られないため、後方が本当は信頼できるかどうかを学ぶ機会が失われる。貪欲に短くし続けると、後方を永遠に観測できず、見積もりの誤りが固定されてしまうという部分フィードバックの問題が生じる。

もう1つの落とし穴は、各ヘッドの周辺予測精度だけを見てホライズンを決めることである。独立ヘッドは各位置の周辺分布を完全に合わせても、未来トークン同士の依存関係を表せないため、ブロック全体の不一致は残る。本論文の付録の例では、各位置の周辺が完全でも、期待確定トークン数がどのホライズンでも3未満に頭打ちになり、窓を伸ばすほど検証コストだけが増える。つまり効くかどうかは周辺精度ではなく、接頭辞が実際にどこまで生き残るかと、1ラウンドにかかるコストで決まる。評価軸は最初からこの2つに置く必要がある。

既存の適応手法の多くは、自己回帰ドラフトを前提に、学習済みの分類器やエントロピー基準でトークンごとに停止を決めるか、ドラフト後に木の形を整えるものであり、ドラフト前に長さを決めなければならないマルチトークン予測にはそのまま使えない。学習済みのルーターで長さを選ぶ同時期の研究もあるが、新しい予測ヘッドの学習が必要で、検証も貪欲デコードに限られる。再学習なしで、ドラフト前に、文脈ごとに最適なホライズンへ近づく制御が求められていた。

## 手法のあらまし

まず1ラウンドを、ドラフト、検証、確定の3段として定義する。ホライズンはドラフトがサンプリングされる前に、そのラウンド開始時点で利用可能な情報だけから選ぶ。この条件の下では、ホライズンを適応的に選んでも正確な投機的検証の正しさは保たれる。次に、各位置について、その位置に到達した条件での棄却確率であるハザードを定義し、サバイバルがハザードの積で、期待確定トークン数がサバイバルの和で書けることを示す。制御器はハザードの予測値から全ホライズンの期待利得を計算し、コストモデルの推定で割って、予測トークン毎秒が最大のホライズンを選ぶ。検証が終わると、そのラウンドで観測されたドラフトと対象の分布のずれが、次の予測を更新する材料になる。短いホライズンで見えなかった位置については、一定確率で全長までドラフトする探索ラウンドを混ぜ、観測された損失を観測確率で割り戻すことで偏りのない学習を保つ。

## 手法

### 1. 受理サバイバルと棄却ハザード — 全ホライズンの利得を決める1本のベクトル

各位置の局所的なずれは、対象分布とドラフト分布の全変動距離で測る。これは、検証がその位置に到達したときに、その位置が棄却される確率そのものである。ただし接頭辞全体の生存は、任意のドラフト接頭辞に対する平均ではなく、生き残った接頭辞の分布の下での平均で決まる。棄却ハザードはこの生存で重み付けした条件付き棄却確率として定義され、先行位置まで受理された接頭辞ほど重く数える。サバイバルはハザードの積、期待確定トークン数は棄却時の訂正トークンまたは全受理時のボーナストークンを含めてサバイバルの和に1を加えたものになる。したがってハザードのベクトル1本が分かれば、全てのホライズンの期待利得をドラフト前に計算できる。この恒等式はヘッド間の独立性を仮定しないため、独立ヘッドにも相関ヘッドにもそのまま成り立つ。重み付けを外した素朴な平均ずれを使うと、到達しにくい接頭辞を過大に数えて利得を誤ることが、論文中の二値語彙の例で具体的に示されている。

### 2. ハザードのオンライン学習 — 生存で重み付けした回帰とオンライン勾配降下

予測器はドラフト前の特徴と位置からハザードを出す。学習の損失は、観測されたずれと予測ハザードの二乗誤差を、前位置までの受理重みで重み付けして全位置で合計したものとする。この損失の過剰分は、ちょうどサバイバルで重み付けしたハザード予測誤差の二乗和に一致するという較正恒等式が成り立つ。つまり、到達しやすい位置の誤差ほど重く罰せられ、制御の判断に効く誤差と学習の誤差が同じ物差しで結ばれる。更新は射影付きオンライン勾配降下で、ラウンドごとに1ステップだけ進める。予測器の形は線形に限らず、任意のオンライン学習器の予測誤差が後述のスループット後悔へそのまま変換されるという学習器非依存の形で理論が組まれている。コスト側は、文脈長などを含む特徴からラウンドの実測時間を学習するコストモデルが担い、ホライズンごとの予測コストを与える。

### 3. 部分フィードバックへの対処 — 全長探索と逆確率重み付け

ホライズンが短いラウンドでは、それより後方の位置のずれは観測できない。この欠落を放置すると、後方を過小評価した制御器が短い窓を選び続け、誤りを正す機会を失う。そこで制御器は、確率エプシロンで貪欲な選択を外し、最大ホライズンまでドラフトする探索を行う。位置ごとの観測確率は既知になるため、観測された損失の各項をその観測確率で割る逆確率重み付けにより、部分フィードバックの下でも損失の不偏推定が得られる。代償は2つある。探索ラウンドでは長いドラフトのコストを払うことと、割り戻しによって勾配のノイズが大きくなることである。理論ではこの2つを釣り合わせた結果として、完全フィードバックの場合より少し弱いが、それでも劣線形の後悔が得られることが示されている。

### 4. 予測誤差から実時間への変換 — 後悔の理論

本論文の理論の核は3段の変換である。第一に、較正恒等式とサバイバル積の望遠鏡的な展開により、任意のホライズンについて予測スループットと真のスループットの差が、そのラウンドの過剰予測損失の平方根で抑えられる。第二に、これをラウンドごとに合計すると、文脈ごとに最適なホライズンに対する累積スループット後悔が、学習器の回帰後悔と近似誤差の平方根のオーダーで抑えられる。この比較対象は固定した最良ホライズンではなく、訪れた文脈ごとに変わる最良ホライズンであり、従来のバンディット型の保証より強い。第三に、固定した出力トークン予算の下で、後悔は期待完了時間の上限と、通常デコードに対する高速化の下限へ変換される。オンライン勾配降下を用いた場合、完全フィードバックではラウンド数の4分の3乗、部分フィードバックでは5分の4乗のオーダーの劣線形後悔となり、学習の代償は生成が長くなるほど相対的に消えていく。平方根への依存は、決定境界に任意に近い構成例によって改善できないことも示されている。

## 評価

### まず見るところ

- **結論:** 適応制御は、ドラフトと対象が別モデルでコスト非対称が大きい場合に最も効き、同じ順伝播を共有する自己投機型では利得が小さいか、条件によっては悪化もする。固定窓に負けたのは10設定中2設定である。
- **速度・効率:** 全てのマルチトークン予測条件が通常デコードを上回った。受理率そのものは窓を短くすれば機械的に上がるため、論文は受理率を単独の成功指標にせず、ラウンドコスト込みのスループットで判断している。
- **品質:** 検証器を変えない無損失型であり、精度の変化は本来生じないはずだが、ベースモデルの停止挙動などにより実測の正解率には条件間のばらつきが出ている。論文はこれを隠さず報告している。
- **評価の強さ／注意点:** 実機測定だが、全条件でケーブイキャッシュを無効化し、1系列ずつ処理している。バッチサービングやキャッシュありの環境への一般化は未評価である。各条件はシードなしの単回実行である。

## 既存研究との差

自己回帰ドラフトの適応的停止は、ドラフトの途中で得られる情報を使って止めるかどうかを決める研究であり、本論文はその判断時点自体がマルチトークン予測では存在しないことを出発点にする。ドラフト後に木を整形する方式とも異なり、本論文はドラフト前の情報だけで長さを決める。検証フィードバックをオンラインで使う先行研究は、ドラフトモデル自体を更新するか、ドラフト候補や固定した設定の中から選ぶもので、比較対象は最良の固定設定だった。本論文は比較対象を文脈ごとの最良ホライズンまで強め、その保証を特定の学習器ではなく予測誤差一般から導く点が新しい。また、学習済みルーターで区間長を選ぶ同時期の研究に対して、本論文は新しいヘッドの学習を不要とし、正確な検証の下で成り立つ点を区別している。

## 限界・実装状況

最大の限界は評価条件である。全実験がケーブイキャッシュなし、バッチなしであり、キャッシュとバッチでコスト構造が変わる実サービングでは、どの窓が得かも変わりうる。コストモデルの精度がそのまま制御の質に効く構成であり、文脈長を特徴に入れないとラウンドコストの分散をほとんど説明できなかったことが付録で報告されている。木構造のドラフトへの拡張や、ハザード経由ではなくサバイバルを直接予測する方式との比較は未実施である。拡散型の投機への拡張も今後の課題とされる。実装面では、制御器は軽量で、ホライズンの採点は窓の数に比例する時間で済む。実験コードの存在は言及されるが、一次資料中に公式の公開ユーアールエルは明示されていない。

## 一般的な実装上の含意

投機の長さを決めるときは、ドラフトの周辺精度ではなく、接頭辞が実際に生き残る確率とラウンドの実測コストの比で見るべきである。受理率だけを上げても、窓を短くすれば機械的に上がるため、速度の証拠にはならない。適応制御を入れるなら、短い選択が後方の観測機会を奪う部分フィードバックを、探索と不偏な重み付けで必ず処理する必要がある。また、ドラフトと検証のコスト非対称が大きい構成ほど適応の利得は大きく、同じ順伝播を共有する構成では利得が限られるため、導入の優先順位はコスト構造から判断できる。
