# LongSpec: Long-Context Lossless Speculative Decoding with Efficient Drafting and Verification

## 概要
長文脈での投機的復号は、短文脈より三つの問題が強くなる。第一に自己回帰型ドラフト自身のKVキャッシュが文脈長に比例して増え、対象LLMとは別の大きなメモリを要求する。第二にEAGLE等のドラフトは数千トークン以下で学習されることが多く、推論時に数万トークン以上の位置へ出ると位置分布が学習時とずれる。第三に、複数候補を一括検証する木注意の不規則マスクはFlash Attentionのような長文脈向け高速カーネルと相性が悪い。

LongSpecは、512-トークンのスライディングウィンドウ自己注意と対象LLMの既存KVを読むcross-注意機構からなる1-ブロックドラフト、短い学習系列でも大きな位置を経験させるAnchor-Offset Indices、接頭辞部分をFlash Attentionで計算して候補木部分だけ専用Triton カーネルへ分離するHybrid Tree Attentionを組み合わせる。5つの長文脈理解データセット・5 対象 LLMでFlash Attention自己回帰基準比最大3.26倍、QwQを用いる長推論でも実時間最大2.34倍を報告する。

## 問題設定
長文脈投機では「ドラフトが小さい」だけでは不十分である。自己回帰ドラフトが文脈全体のKVを保持すれば、モデルパラメータが小さくてもKV容量が文脈長に比例する。特にエージェントや長い推論では生成中にもドラフトKVが増え続け、対象LLMのKVに加えて二重の状態を持つ。

さらに、短文脈学習では小さい位置indexほど出現頻度が高く、大きい位置indexは十分更新されない。長文脈推論で突然大きい位置へ移るとドラフトの一致率が落ちる。検証側でも通常の木注意機構 maskは不規則なので、規則的なcausal 注意機構向けに最適化されたFlash Attentionの効率をそのまま利用できない。LongSpecはこの三つを独立の機構で処理する。

## 手法

### 定数サイズのドラフトKV
ドラフトは自己注意とcross-注意機構の二段構成を持つ。自己注意は直近512 トークンだけを見るスライディングウィンドウに制限し、ドラフト自身が保持するKVを文脈長から切り離す。局所情報だけでは長距離依存を失うため、後段cross-注意機構が対象LLMの既存KVキャッシュを参照して長文脈情報を取り込む。

対象LLMのKVは投機の有無にかかわらず必要なので、cross-注意機構用に長文脈状態を二重保存しない。さらにembeddingとLM ヘッドも対象とドラフトで共有し、Llama-3やQwen-2.5のような大語彙モデルで追加パラメータ メモリを抑える。結果としてドラフト追加KVは文脈が伸びてもwindow分で頭打ちになる。

### Anchor-Offset Indices
通常の位置番号0,1,2,…で短い系列だけを学習すると、大きい位置番号はほとんど訓練されない。LongSpecは一部をanchorとして固定し、それ以外の位置へランダムoffsetを加えるAnchor-Offset Indicesを使い、短い系列でも長文脈で現れる大きな位置番号を学習させる。

学習は短文脈の事前段階から長文脈SFTへ移行する複数段階で行われ、後段では通常位置へ戻す。論文ではAnchor-Offset初期化が実長文脈学習で同じlossへ3.93倍速く到達し、Multi-Newsでは85.98→91.11 トークン/s、RepoBench-Pでは85.21→91.28 トークン/sへ改善している。位置一般化が単なる学習曲線だけでなく受理長と推論速度へつながる。

### Hybrid Tree Attention
投機候補の木を対象LLMで検証するとき、長い接頭辞は通常のcausal 注意機構、追加候補部分だけがtree maskを必要とする。LongSpecはこの二つを一つの不規則カーネルへ押し込まず、長い接頭辞計算をFlash Attentionへ渡し、候補木の小さい部分をTriton実装の `fused_mask_attn` で処理する。

両部分の注意機構出力を正規化情報に基づいて集約し、標準的なtree 検証と同じ結果を作る。これにより長文脈の大部分では成熟したFlash Attention カーネルを利用しつつ、木構造に必要な柔軟性だけを専用カーネルへ限定する。論文では対象注意機構 遅延を標準HuggingFace実装比で約75%削減する。

### 投機復号全体
対象LLMが持つ長文脈KVをcross-注意機構で参照しながら、軽量ドラフトが複数候補トークンを生成する。ドラフト側の自己注意は512-トークン windowなので追加KVは増え続けない。候補は木としてまとめ、Hybrid Tree Attentionで対象LLMが一括検証する。受理された最長部分を文脈へ追加して次の段階へ進む。

対象LLMの検証を最終決定に使うため、近似ドラフトによって最終分布を変更する量子化・枝刈り方式とは異なる。速度はドラフト受理長だけでなく、長接頭辞検証を高速カーネルへ載せられるかにも依存する。

## 主要結果
|条件|結果|意味|
|---|---:|---|
|長文脈5データセット|Flash Attention基準比最大3.26倍|高速注意機構を既に使った強い基準の上でも利得が残る|
|コード補完条件の代表例|96.96 トークン/s、3.26倍|平均受理長4.46と高速検証が同時に効く|
|QwQ・4数学推論タスク|実時間最大2.34倍|理解ベンチマークだけでなく長いreasoning生成でも有効|
|Anchor-Offsetあり / Multi-News|85.98→91.11 トークン/s|位置学習改善が推論速度へ反映|
|Anchor-Offsetあり / RepoBench-P|85.21→91.28 トークン/s|受理長も3.26→3.39へ増加|
|Hybrid Tree Attention|対象注意機構 遅延約75%削減|不規則木部分を分離するカーネル設計の効果|

重要な負の比較として、MagicDecは低バッチ条件ではドラフトが重く、guess lengthが3以上で約0.7倍、つまり自己回帰より遅くなる条件がある。PLDも検索が弱いデータでは負の高速化になる。LongSpecは「投機を使えば必ず速い」のではなく、長文脈でドラフト状態と検証カーネルを軽量化することが必要だと示している。

文脈長別分析では、最短から最長範囲へドラフト時間は8.91→9.25 ms、検証時間は6.18→6.28 msとほぼ一定で、対象モデル時間は25.63→30.89 msへ増える。定数サイズのドラフト状態とHybrid Tree Attentionが、文脈増加時の追加費用を抑えていることを裏付ける。

## 既存研究との差
EAGLE系の自己回帰ドラフトは対象LLMの隠れ 状態を使って高い受理率を得るが、ドラフト自身のKVが長文脈で増える。LongSpecは自己注意を局所windowへ制限し、長距離情報を対象LLMの既存KVからcross-注意機構で取ることで追加状態を定数化する。

TriForce/MagicDecは長文脈向けに対象モデルの疎KV等をドラフトとして使うが、低バッチではドラフト計算自体が重くなり得る。LongSpecは1-ブロックの専用軽量ドラフトを使う。また木検証についても、汎用tree 注意機構をそのまま長接頭辞へ適用せず、Flash Attentionと専用tree カーネルへ計算を分解する。

## 限界
LongSpecはドラフト学習を必要とし、Anchor-Offsetを含む段階的な訓練工程が追加される。cross-注意機構は対象LLMのKV形式へ依存するため、モデル構成ごとの統合が必要になる。ドラフト追加KVは定数化されても、対象LLM本体の長文脈KV容量は削減しない。

主な高速化は低〜中バッチの長文脈生成で示され、MagicDecのように大バッチ・テンソル 並列向けの方式とは得意領域が異なる。最大3.26倍は特定モデル・データセット条件の値であり、全条件の保証ではない。また無損失投機で品質を維持する代わりに、ドラフト学習・追加カーネル・対象KVへのcross-注意機構という実装複雑性を受け入れる。
