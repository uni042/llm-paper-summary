# DiffuSpec: Unlocking Diffusion Language Models for Speculative Decoding

> 拡散言語モデルで複数トークンを一括提案し、因果整合経路探索と適応ドラフト長制御でQwen2.5-32Bの投機的復号を平均3.08倍高速化する。

## 概要

投機的復号は小さいドラフタが複数トークンを先に提案し、大きい対象モデルがまとめて検証する。しかし一般的なドラフタも自己回帰型なので、k個の候補にk回の逐次前向き計算が必要で、検証並列化の利得をドラフト時間が食い潰す。

DiffuSpecは事前学習済み拡散言語モデル（Diffusion Language Model; DLM）をドラフタに使う。DLMは複数位置を1回の前向き計算で同時に予測できる。一方で双方向条件付けを使うため、位置ごとの最高確率トークンを並べても、左から右へ読む自己回帰対象モデルが高確率とみなす列とは限らない。

そこで因果整合経路探索（Causal-Consistency Path Search; CPS）が候補格子から自己回帰的に自然な経路を選び、適応ドラフト長（Adaptive Draft Length; ADL）が直近の生成長と受理長から次の提案長を調整する。A100 80GB上でQwen2.5-32Bを対象、Dream-7Bをドラフタとした評価では6タスク平均3.08倍、平均受理トークン6.99を達成した。

## 問題設定

投機的復号の速度は、ドラフタ速度と受理率の両方で決まる。受理率が高くてもドラフタが逐次なら新しいボトルネックになる。逆に一括提案が速くても最初の数トークンで対象モデルと食い違えば、残りは捨てられる。

DLMは前者を改善できるが、未来位置も見ながら予測するので、AR検証器との因果性がずれる。また提案ブロック長を長くすると一度に進める可能性は増える一方、不要な候補計算と棄却も増える。

## 手法

### DLMドラフタ — k回の逐次生成を一括提案へ変える

現在prefixの後ろへ `k_t` 個のマスクを置き、DLMで複数位置を同時復元する。主設定では精緻化回数 `S=1` とし、ドラフト時間を抑える。検証時には未来位置をマスクした左から右の代理確率を作り、標準の投機的復号の受理比へ使う。

この構成により、対象ARモデルの分布を保つ検証規則を維持しつつ、候補生成だけを並列型へ置換する。ただしDLMの局所top-1列はAR検証に最適とは限らないため、次のCPSが必要になる。

### CPS — 候補格子を因果的に探索する

各位置の候補直積は指数的に増えるため、CPSは累積確率質量が閾値 `τ` を超える最小候補数だけを残し、最大 `M_max` で制限する。確信度の高い位置では少数、曖昧な位置では多めに候補を残す。

枝刈り後、DLM対数確率と小さな因果代理モデルの対数確率を重み `λ` で混ぜ、beam幅 `B` で左から右へ探索する。最初のEOSで停止する。これによりDLMとして自然なだけでなく、AR検証器に受け入れられやすい経路を選ぶ。

### ADL — 提案しすぎと不足を動的に避ける

固定長では短すぎると一度に進めず、長すぎるとDLMが内容を終えた後まで計算する。ADLはDLMがEOSまで生成した長さ `L_gen` と、対象モデルが連続受理した長さ `L_acc` を観測し、それぞれの指数移動平均を取る。

受理長が生成長へ追いついているときだけ増分 `δ` を加え、`k_min` と `k_max` の範囲で次の長さを決める。受理が追いつかない場合は無闇に長くしない。CPSが受理率を上げ、ADLがその利得を壁時計時間へ変換する役割分担である。

### 1ステップの流れ

DLMが候補集合を一括生成し、CPSが枝刈りとbeam探索で経路を選ぶ。対象Qwenがブロック検証し、連続受理prefixだけを確定する。最後にADLが観測値を更新して次の `k_t` を決める。この4段階をEOSまで反復する。

## 評価

### 代表的な評価条件

| 項目 | 代表設定 |
|---|---|
| GPU | NVIDIA A100 80GB 1基 |
| CPU／RAM | 11 CPU cores、100GB RAM |
| ランタイム | PyTorch 2.6.0 |
| 対象ARモデル | Qwen2.5-32B |
| DLMドラフタ | Dream-7B |
| ARドラフタ比較 | Qwen2.5-7B（SPS） |
| タスク／データセット | 指標 |
|---|---|
| MT-Bench（対話） | pairwise win rate |
| Spec-Bench翻訳（WMT形式） | BLEU |
| CNN/DailyMail要約 | ROUGE-L |
| Natural Questions | EM／F1 |
| GSM8K数学 | accuracy |
| DPR over Wikipedia（RAG） | accuracy |
| バッチ | 1 |
| 検証 | greedy、温度0、KVキャッシュ有効 |
| 主設定 | S=1, B=3, τ=0.8, M_max=15, k=20〜30 |

### 代表的な評価結果

| 条件 | 指標 | 比較対象 | DiffuSpec | 読み取れること |
|---|---|---|---|---|
| 6タスク平均 | 高速化 | AR-greedy | 3.08倍 | DLM一括提案が実時間短縮へつながる |
| 6タスク平均 | 平均受理トークン | SPS 6.18 | 6.99 | CPSを含む提案が長く受理される |
| 数学 | 高速化 | AR-greedy | 4.02倍 | タスク依存で利得が大きい |
| RAG | 高速化 | AR-greedy | 2.38倍 | 平均値だけでは条件差を表せない |
| CPS+ADL | 高速化 | 両方なし2.69倍 | 3.08倍 | 両機構で+0.39倍 |
| CPSのみ | MAT/高速化 | 6.05/2.69倍 | 6.95/2.98倍 | 受理改善の主因はCPS |
| ADLのみ | MAT/高速化 | 6.05/2.69倍 | 6.43/2.73倍 | 単独寄与は小さくCPSとの組合せが重要 |
| S=1→10 | MAT/高速化 | S=1 | 6.99→7.33 / 3.08→0.93倍 | ドラフト品質を上げすぎると逆に遅い |

CPS探索の平均オーバーヘッドは1.1%。特に重要なのは、精緻化回数を増やすと受理数は増えるのに速度は悪化する点である。S=10では平均受理7.33まで上がる一方、高速化は0.93倍となり通常ARより遅い。したがって投機的復号では受理率最大化ではなく総壁時計時間の最小化が必要である。

品質は温度0のgreedy検証で固定し、タスク指標はAR-greedyと統計的に区別できない設定で比較している。速度は品質低下との交換ではない。

## 既存研究との差

SPSの小型ARドラフタは候補生成が逐次である。MedusaやEAGLE系は高い受理率を得るが追加学習や専用部品が必要になる。DiffuSpecは既存DLMを訓練なしでドラフタにし、双方向条件付けとAR検証の不一致をCPS、固定長問題をADLで処理する。

## 限界・実装状況

主評価は単一A100、バッチ1であり、多数同時リクエストのサービング競合は未評価である。DLMと対象ARモデルのトークナイザ整合も必要。DLM側には成熟したKV再利用がなく、論文自身もKVキャッシュ型再利用や融合カーネルを今後の課題に挙げる。

## 一般的な実装上の含意

投機的復号では受理率だけでなく、ドラフト・探索・検証を全部含む実時間を見る必要がある。並列生成器をAR検証へ接続する場合、局所top-1ではなく因果整合した経路選択が重要になる。
