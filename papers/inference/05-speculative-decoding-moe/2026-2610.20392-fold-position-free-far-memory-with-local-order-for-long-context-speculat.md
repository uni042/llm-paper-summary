# FOLD: Position-Free Far Memory with Local Order for Long-Context Speculative Decoding

> 近い文脈は正確な位置で、遠い文脈は位置を共有する遠方メモリとしてドラフタに読ませ、再訓練なしに長文脈の投機的デコードを回復させる訓練不要の手法。

## 概要

投機的デコードは、軽いドラフタが候補トークンをまとめて提案し、対象モデルが並列に検証することで生成を速くする。長文脈ではKVキャッシュの読み出し費用を多くの受理トークンへ割り勘できるため本来は有利だが、実際には逆に利得が縮む。多くのドラフタは数千トークンで訓練されており、訓練範囲を超えた相対位置に弱い。例えばLlama-3.1-8B用のドラフタの高速化は32kトークン以内でほぼ半減し、Gemma-4-12B用は入力が128kを超えると3.18倍から1.94倍へ落ちる。再訓練は組ごとにデータと計算が要り、文脈を捨てる方式や位置を伸縮する方式、遠方を検索で戻す方式といった訓練不要の対策も、情報の喪失や追加費用を抱える。

FOLDの着眼点は、ドラフタが対象モデルの隠れ状態を読む以上、遠方項目の正確な位置は必須ではないという診断にある。代表結果として、Llama-3.1-8Bでは平均の高速化が元のドラフタの2.11倍から3.40倍へ上がり、Long Code Arenaの122kトークンでは2.08倍から4.22倍へ伸びた。Qwen3.5-9Bでは2.98倍から3.39倍、Gemma-4-12Bでは2.46倍から2.68倍となり、対象とドラフタの組を通して主に最高の高速化を示した。

## 問題設定

劣化の原因を切り分けるため、論文は2つの診断を行う。第1に、距離だけを制御した実験で、大きな相対距離そのものがドラフタの提案を崩すことを示す。位置符号化の回転は距離とともに位相が進み、訓練で見た範囲を超えるとクエリとキーの整合が崩れる。第2に、文脈特徴そのものへ粗い位置の情報が既に入っていることを、特徴から位置を読み出す探りで示す。対象モデルが全接頭辞を読んで作った隠れ状態には、順序の大まかな手掛かりが残る。したがって遠方については、正確な相対位置を捨てても、内容による選択はまだ働くはずである。

既存の訓練不要対策はこの診断と合わない。窓だけを残す方式は遠方の情報を捨て、位置を伸縮する方式は近い文脈の解像度まで落とし、検索方式は遠方項目の選択と更新に毎回費用が掛かる。必要なのは、全項目を保持したまま、遠方の位置だけを無効化し、かつ項目数が増えても注意が薄まらない読み方である。

## 手法のあらまし

FOLDはドラフタの注意の読み先を2つに分ける。直近の窓の中にある項目は元の正確な位置で読む。それより遠い項目はすべて、窓の外側に置いた共有の位置で読む遠方メモリとする。共有位置はブロック内のずれ分だけを持ち、入力長には依存しないため、訓練範囲を超える相対距離は現れない。遠方のキーは回転していない形で保持し、位置の変換はブロックのクエリ側へ一度だけ適用して使い回す。注意の計算は窓とメモリで分けて行い、メモリ側では集中係数で分布を鋭くし、窓との合計の重みは別に制御する。文脈が窓以下なら遠方メモリは空であり、FOLDは元のドラフタと正確に一致する。

## 手法

### 1. 診断 — 距離が壊すものと、特徴に残るもの

手法に先立つ観測を2件押さえる。距離の制御実験では、内容を保ったまま相対距離だけを広げると受理が落ちることを確認し、劣化の主因が内容の古さではなく位置の範囲外れであることを示した。位置の探りでは、文脈特徴から粗い位置が読み取れることを確認し、遠方項目の順序情報は位置符号化を外しても完全には失われないという前提を得た。この2件があるため、遠方の位置を共有化する設計は、情報を捨てる操作ではなく、壊れた手掛かりを外して残った手掛かりへ寄せる操作として正当化される。診断なしに位置を外すと、近い文脈で要る精密な順序まで壊しかねないため、窓の中は正確な位置のままにする線引きも診断から来ている。

### 2. 位置なし遠方メモリ — 全項目を保って距離だけを消す

入力はドラフタが読む文脈のキーとバリューである。処理は、直近の窓を境に項目を分け、遠い側の全項目へ共有の実効距離を与えることである。ブロック並列のドラフタでは、ブロック内の位置ごとに共有距離へブロック内のずれを加えたものを使い、ブロック内の局所的な順序は保つ。共有の回転はクエリ側へ移せるため、遠方のキーは回転なしの写しをキャッシュして複数回の読みで使い回せる。出力は、位置の壊れがない文脈表現であり、対象モデルの検証手順や出力分布は変えない。追加費用は、回転なしキーの追加保持であり、副次キャッシュは最大で約6.0ギビバイトと報告されている。失敗条件は、遠方の正確な順序そのものが答えを決める作業であり、その場合は窓側の利得が中心になり、メモリ側の寄与は小さくなる。

### 3. 分離正規化 — 薄まる注意と、膨らむ合計を分けて抑える

遠方メモリは項目数が文脈長とともに増えるため、2つの問題が出る。関連の弱い項目が集まって分布が薄まることと、メモリ全体の注意の重みが窓を圧倒することである。FOLDは窓とメモリで注意を別々に計算し、メモリ側のスコアへ集中係数を掛けて分布を鋭くすることで関連項目を際立たせ、窓とメモリの合成比は別に制御する。評価では集中係数を2に固定している。除去に近い比較では、メモリ側の寄与が受理長へ0.15から1.29の上乗せとして現れる一方、短い入力や短い回答の課題ではメモリが受理長を下げる例もあり、係数と窓幅は作業に依存する。誤った場合の扱いは穏当で、遠方メモリが空なら元方式へ戻り、利得が出ない条件ではわずかに遅くなる程度にとどまる。

## 評価

結論は、短い系列で訓練されたドラフタでも、文脈の読み方を変えるだけで長文脈の受理を回復できるという点にある。利得は元のドラフタの劣化が大きい組ほど大きく、劣化が小さい組ではほぼ互角になる。検索型の比較対象は受理長で並ぶことがあっても、選択と更新の費用で速度では負けており、全項目保持と追加費用の小ささの両立がFOLDの強みである。

## 既存研究との差

窓保持の方式は遠方を捨て、位置の再調整系は全位置を写し替え、検索系は遠方の一部を選んで戻す。本論文の差は、全項目を保持したまま遠方の位置だけを共有化し、注意の重みの制御を分離正規化として独立に持つ点にある。また、長文脈の劣化対策を対象モデルではなくドラフタ側へ適用し、対象モデルの隠れ状態が持つ粗い位置情報を根拠にした点も、対象側の文脈拡張とは異なる軸である。

## 限界・実装状況

- 論文自身が挙げる限界として、受理長と利得が対象モデルと課題に強く依存すること、対象モデル自体の長文脈劣化は直せないこと、対象がブロック並列ドラフタに限られ自己回帰型ドラフタは未評価であることがある。
- 遠方のキーとバリューの回転なしの写しを余分に保持するため、文脈長に比例してメモリが増える。軽いドラフタでは小さいが、メモリ予算が厳しい場合や高並行では効いてくる。窓幅と集中係数は手で決めた固定値で、推論中の適応は今後の課題とされている。
- 実装状況は本グループで最も進んでおり、公式コードが公開され、vLLMとSGLangの両方で結果が示されている。検証を通る方式のため、導入しても出力の分布は変わらない。

## 一般的な実装上の含意

長文脈の劣化を見たら、まず内容の陳腐化ではなく位置の範囲外れを疑い、距離だけを制御した切り分けを行う価値がある。位置の手掛かりが壊れている範囲では、正確な位置を守るより、共有位置へ畳んで内容による選択へ寄せる方が受理を回復させる場合がある。その際、項目数の増加による注意の希釈と、合計の重みの膨張は別の問題として分けて制御すべきである。また、補助モデルの文脈拡張は、補助モデルが読む対象側の表現にどれだけ情報が残っているかで設計が変わる。
