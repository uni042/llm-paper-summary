# 3-Model Speculative Decoding: 中間検証モデルを用いるPyramidSD

## 書誌情報

Sanghyun Byun、Mohanad Odema、Jung Ick Guack、Baisub Lee、Jacob Song、Woo Seong Chung。arXiv:2510.12966v1、2025年10月14日。NeurIPS SPIGM 2025ワークショップ採択と記載されている。主分類は計算言語学（cs.CL）。原著の正式題名は「3-Model Speculative Decoding」で、提案方式の名称は**Pyramid Speculative Decoding（PyramidSD）**である。

## 概要

標準的な投機的デコードでは、小さなドラフトモデルが先のトークンを複数予測し、大きなターゲットモデルがまとめて検証する。ドラフトが速くてもターゲットと予測分布が大きく異なれば、検証時に多くの候補が棄却され、期待した高速化が得られない。ドラフトを大きくすれば一致率は上がるが、今度は候補生成そのものが遅くなる。

PyramidSDは、1Bのドラフトと8Bのターゲットの間に3Bの中間検証モデル（qualifier）を配置する。1Bから3B、3Bから8Bの二段階で候補を検証し、確率分布の乖離が指定閾値以下なら候補を通す「曖昧許容（fuzzy）判定」を利用する。著者らは同じLlama系列のトークナイザを共有するモデルを使い、RTX 4090 24GB上のCommonsenseQAで、通常の投機的デコード比最大1.91倍、最大124トークン/秒の生成速度を報告する。より保守的なassisted版は最大1.44倍で、品質分散が小さい。

ただし**曖昧許容によって元のターゲットモデルの確率分布を厳密に保存する方式ではない**。原著Table 1では通常の投機的デコードのCSQAスコア69.58±2.20に対し、fuzzy版の一条件は63.50±13.20まで低下している。速度と品質を同時に見ないと評価を誤る論文である。

## 問題設定

### ドラフトサイズと受理率の対立

投機的デコードでは、ドラフトモデルが長さℓの候補を生成し、ターゲットモデルが一回の検証で受理できるトークン数を増やす。ターゲットを毎トークン逐次実行するより、並列に検証できれば生成速度が上がる。一方、ドラフトとターゲットの分布が離れるほど、長い候補列の途中で不一致が発生しやすい。ドラフトを1Bまで小さくすると高速な候補生成が可能でも、8Bターゲットとの間に分布差が生じ、長い投機列を活用できない。

原著Figure 3は1B、3B、8Bのモデルの予測分布を比較し、モデルが大きくなるほどエントロピーが低くなり、最大トークン確率が高くなる傾向を示す。3Bの中間モデルは1Bより確信度が高く、8Bより計算が軽いため、1Bの候補をいったん中間モデルで選別すればターゲットに近い候補列を作れるという着想につながる。ただしこれは特定のLlama系列とCommonsenseQAで観測した性質であり、全モデル族に保証される単調な性質ではない。

### 厳密な一致判定だけでは中間モデルが無意味になる

三モデルを単に連結して、1Bの候補が3Bと8Bの双方の最尤トークンに完全一致する場合だけ受理すると、中間モデルが追加されても1Bと8Bの厳密一致という制約は緩まない。むしろ3Bの実行時間が増えるため、性能が悪化し得る。著者らはこの問題を避けるため、標準的な厳密一致ではなく、分布間の乖離が閾値以下なら候補を受理するFuzzy Speculative Decodingの考え方を二段階へ拡張した。

## 手法

### 1. 三モデルの役割と二段階検証

PyramidSDのモデルは、ドラフト `M_D`、中間検証 `M_Q`、最終ターゲット `M_T` の三つで、パラメータ数は `|M_T| > |M_Q| > |M_D|` である。実験ではLlama-3.2-1Bをドラフト、Llama-3.2-3Bを中間検証、Llama-3.1-8Bをターゲットにする。まずドラフトがℓ_D個の候補トークンを生成し、中間モデルがその列を検証する。次に中間モデル側で構成したℓ_Q個の候補を大型ターゲットへ渡し、最終的に受理されたトークンを出力する。

重要なのは、ターゲットへ直接1Bの長い列を渡す代わりに、中間モデルが1Bの明らかな不一致を早期に除外し、8Bに近い分布の候補を渡す点である。入力は同じトークナイザのモデル群と現在の文脈、出力はターゲットの検証を経た次のトークン列である。二つのモデル間でトークンIDの意味が一致しなければ比較できないため、モデル系列の互換性が前提となる。

### 2. 二つの分布乖離閾値

原著式では、1Bと3Bの予測分布の乖離を `Div(P_Q, P_D)`、3Bと8Bの乖離を `Div(P_T, P_Q)` とし、それぞれ `τ_Q`、`τ_T` を超えないとき候補を通す。閾値が大きいほど多少異なる分布も許容するため受理率は高まりやすいが、ターゲットが本来選びにくいトークンまで通過させる危険がある。二段階で受理を緩めると、その誤差が連鎖し、出力品質と速度のばらつきが大きくなる。

著者らは `τ_Q <= τ_T` を推奨する。初段の中間モデルで明白に不適切な候補を除外し、後段のターゲット検証では相対的に緩い閾値を許すという役割分担である。実験では `τ_Q, τ_T ∈ {0.2, 0.3, 0.4, 0.5}` を探索した。最適な閾値はモデルやデータセットに依存するため、運用時には速度だけでなく品質スコアと分散も見て選ぶ必要がある。

### 3. fuzzy版とassisted版

**PSD_F**は両段階で曖昧許容判定を使う。ドラフトが速く、かつ閾値を緩めるほど長い列を受理しやすく、最大スループットを狙える。しかし二段階の確率分布差を同時に許容するため、出力品質の揺れが大きくなる。原著ではこの版が最大1.91倍を示す一方、CSQAスコアの標準偏差が大きい条件がある。

**PSD_A**は初段で中間モデルの補助的な復号を用い、ドラフト候補が棄却された場合に中間モデルの分布から候補を生成する。これにより1Bの不適切な候補を中間段で補正し、fuzzy版より安定した品質を目指す。原著は中間モデルの品質を下限とする設計意図を述べるが、最終出力が厳密な8Bターゲット分布に一致することの証明とは異なる。PSD_Aの最高速度は通常投機的復号比1.44倍で、PSD_Fより低い。

### 4. 投機長と期待スループットのモデル

ドラフトの投機長ℓ_Dを増やすと一回の中間検証で多くの候補を処理できるが、途中で不一致が生じると後続候補を無駄に生成したことになる。同様に中間モデルがターゲットへ渡す投機長ℓ_Qを伸ばせば、ターゲット呼出し回数を減らせる可能性がある一方、検証失敗が増える。著者らは各モデルの生成速度Vと受理率βを用い、初段の有効速度を `V_QD = β_QD(ℓ_D+1)/(ℓ_D/V_D+1/V_Q)` と表し、次段の速度を `V_PSD = β_TQ(ℓ_Q+1)/(ℓ_Q/V_QD+1/V_T)` と近似する（原著式3–5）。

この分解は「中間モデルの計算費用を追加しても、受理率が十分改善すれば全体のトークン/秒が増える」という設計条件を明確にする。実験ではℓ_Dを2、4、6、ℓ_Qを1、2、3、4、5、7、10、15、20、25から探索し、概ねℓ_Dをℓ_Qの半分から3分の1程度にする設定が有利と報告する。ただし大きなℓ_Qや緩い閾値を選べば常に速いわけではなく、受理率低下が速度利得を相殺する。

## 評価

### 評価条件

| 観点 | 原著で確認した条件 |
|---|---|
| GPU | NVIDIA GeForce RTX 4090、VRAM 24GB |
| 実装基盤 | Hugging Face Transformersの投機的復号実装を拡張 |
| モデル | Llama-3.2-1B（ドラフト）、Llama-3.2-3B（中間）、Llama-3.1-8B（ターゲット）、いずれも指示追従版 |
| データセット | CommonsenseQA（CSQA）評価セット |
| 生成条件 | 最大2048トークン、サンプリング温度0.7 |
| サンプル | 各プロンプトに対し事前決定したQAサンプル5件、平均と標準偏差を報告 |
| 比較 | 標準投機的復号（SD）、Fuzzy SD（FSD）、PSD_A、PSD_F |
| 閾値探索 | τ_Q、τ_Tとも0.2/0.3/0.4/0.5 |
| 投機長探索 | ℓ_D=2/4/6、ℓ_Q=1/2/3/4/5/7/10/15/20/25 |
| 主指標 | 生成トークン/秒、CSQAスコアと標準偏差 |

この評価は**同じLlamaモデル族と一つのQAベンチマーク**に限定される。サーバーGPUでの多バッチ配信、長い会話の実運用負荷、異種トークナイザの組合せ、他のサンプリング温度での包括的な比較は行っていない。RTX 4090上での単一GPU評価を、複数GPUの推論サーバーの実測性能として読み替えない。

### 感度・悪化条件

中間モデルを挟むことで、ドラフトとターゲットの分布差を二段階へ分けられるが、追加した3Bモデルの推論コストは必ず発生する。初段で十分な受理率が得られなければ、1Bから3Bへの検証にかけた時間が無駄になる。さらに後段で受理率が下がると、初段の高速化も最終スループットへ伝わらない。二段階の受理率の積が効くことが、速度の非単調性の原因である。

原著のablationでは、ℓ_Qを25まで伸ばすと有利な設定もあるが、ℓ_Dを増やすだけでは速度は単調に改善しない。長い候補ほど後半が棄却されやすく、余分なドラフト計算が増える。著者らはℓ_D/ℓ_Qをおおむね1/2〜1/3にする構成を推奨するが、これは今回の1B/3B/8Bモデル群での観測であり、一般に保証された最適比ではない。

品質面ではPSD_Fの標準偏差が大きく、τ_T=0.5かつτ_Q=0.2では63.50±13.20と、通常SDの69.58±2.20を明確に下回る。PSD_Aは高いピーク速度を一部犠牲にする代わりに分散を抑える。実用上は単純なトークン/秒だけでなく、タスク精度とそのばらつき、閾値のチューニング費用を含めて選択すべきである。

## 既存研究との差

標準SDは小型ドラフトと大型ターゲットの二モデルで厳密に検証する。Fuzzy SDはこの二モデル間の分布乖離を許容する。PyramidSDは**三つのサイズを持つ同系列モデル**の中間に3Bのqualifierを置き、ドラフトからqualifier、qualifierからターゲットの二つの検証を別々に調整する点が新しい。これによりドラフトを1Bまで小さくしても受理率を改善し、ターゲット呼出しの費用を減らす。

EAGLEやMedusaのように追加の学習済み予測ヘッドを必要とせず、既存の同系列モデルを組み合わせられることが利点である。ただし「追加学習が不要」は「追加メモリが不要」ではない。1B、3B、8Bのモデルを同時に保持し、二段階の検証を実行する必要がある。原著の小メモリ設定への言及も、全モデルのメモリ占有がターゲット単体と同じになることを意味しない。

## 限界と実装状況

モデル群が同じトークナイザと語彙を共有することが前提であり、異なるモデル系列や注意機構を混ぜた構成での効果は未実証である。最適な閾値・投機長はモデルとタスクで変わり、二段階の探索空間は二モデル方式より大きい。高いfuzzy閾値はターゲットモデルの厳密な出力分布保存を犠牲にし、品質低下や出力変動を引き起こし得る。

評価はRTX 4090、Llama 1B/3B/8B、CSQA、温度0.7に限定され、バッチ処理、長文脈でのKVキャッシュ圧迫、モデルロード時間、消費電力、別系列での再現性は未測定である。原著はTransformersを使った実装を説明するが、公式コードURLは確認できない。現行の推論エンジンへそのまま統合できるかは別途検証が必要である。
