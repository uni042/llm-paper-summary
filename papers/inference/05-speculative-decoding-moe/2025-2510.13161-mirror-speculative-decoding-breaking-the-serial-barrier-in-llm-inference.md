# Mirror Speculative Decoding：GPUの検証中にNPUで次の投機を先行する

## 概要

通常の投機的復号は、軽いドラフトモデルが候補トークンを作ってから、大きなターゲットモデルがそれを検証する。ドラフトの精度を高めようとモデルや候補長を大きくすると、受理されるトークン数は増えてもドラフト生成時間が延び、検証開始までの直列待ちが残る。Mirror Speculative Decoding（Mirror-SD）は、**ターゲットの中間層が出した次トークン候補を使い、ターゲットの残り層が計算中に次のドラフトを並列生成する**ことで、この待ち時間を重ね合わせる。

ターゲットをGPU、ドラフトをNPUへ分け、両者の間では上位κ件のトークンIDと対数確率だけを交換する。ターゲットの早期出力は確定回答ではなく、次の分岐を事前計算するための予測である。最終的に確定するトークンはターゲット最終層の検証結果に従う。ドラフト側には複数先読み位置を一回の前向き計算で扱う投機ストリーミングも適用する。

論文v2のSpecBench Table 1では、Qwen3-32Bの数学推論、温度0で自己回帰復号比5.84倍、EAGLE3の3.77倍を上回った。Qwen3-14Bの要約、温度1ではMirror-SDが2.81倍、EAGLE3が2.84倍で、**個々の条件ではEAGLE3に負ける場合もある**。総括の2.8〜5.8倍はモデル・タスク・サンプリング設定をまたぐ自己回帰比であり、EAGLE3に対する一律の倍率ではない。

## 問題設定

自己回帰生成はトークンごとに大きなモデルを呼ぶ。投機的復号はドラフトのγトークンをまとめて検証し、受理長A_tだけ先へ進めるが、一般的な手順では「ドラフト生成→ターゲット検証→次ドラフト生成」という順序がある。したがって1ステップ時間は概ねドラフト時間と検証時間の和となり、ドラフトを大きくして受理率を上げるほど生成時間の費用も増える。

Mirror-SDは、ターゲットの中間層の予測が最終層と一定程度相関することを利用する。中間層の上位候補を早くドラフトへ渡せば、最終層が実際に確定するトークンがその候補集合に含まれる限り、ドラフトは後で必要になる分岐を事前に作れる。これはターゲットの計算を途中で打ち切る早期終了方式ではない。ターゲットは後半層を最後まで実行し、正しさを決める。

## 手法

### 中間層のTop-κを使った分岐完全な先読み

ターゲットN層のうち早期出力層ℓ_eを選び、隠れ状態へ語彙投影を適用して上位κ候補のトークンと対数確率を得る。論文の式(6)、(7)ではこれをM_tと呼ぶ。実験の既定値はℓ_e=N/2、κ=8である。送信するのは巨大な隠れ状態ではなくO(Bκ)件の小さなトークン情報で、ターゲットは送信後もℓ_e+1から最終層Nまで処理を続ける。

ドラフト側は、各候補トークンを起点として長さγまでの継続を並列に用意し、分岐木T_tへ保存する。これは単一の最有力トークンだけを予測するより計算量と一時状態が大きいが、ターゲットが最終的に別の候補を選んでも、その候補の分岐が既に用意されていれば再計算を避けられる。分岐幅κを増やすと再利用確率は上がる一方、枝数・ドラフト計算・メッセージ量が増える。

### 検証後の訂正経路と再利用判定

ターゲットは既存の投機的復号と同じく、提案された候補列の先頭から最長の一致部分を検証し、不一致位置τではターゲットの訂正トークンを出す。Mirror-SDは、受理済み接頭辞と訂正トークンを連結した列が、先ほど事前計算した分岐木の経路に存在するかを調べる。存在すればその枝の続きを次ステップへ再利用し、存在しなければ確定した接頭辞からドラフトを作り直す。

この**訂正経路まで含めた再利用条件**が重要である。単に早期出力と最終出力の先頭トークンが一致するだけでは、後続の受理済み接頭辞と訂正先の整合性を保証できない。事前分岐の候補が外れればフォールバックが発生し、先読み費用を回収できない。論文付録Eは、κを増やす、あるいは早期出力を深い層へ移すとフォールバック頻度が減ることを示すが、深い層へ移すほどターゲット後半の並列実行時間は短くなる。

### ドラフト専用の投機ストリーミング

ドラフトの内部生成にも逐次依存がある。Mirror-SDはSpeculative Streaming（SS）をドラフトだけに適用し、主ストリームと複数の先読みストリームを注意マスクで分離する。主ストリームは検証済み接頭辞を参照し、先読みストリームは先行する先読み位置を参照できる。一回の前向き処理で前回候補の検証と次の複数トークン提案を行い、長さγの分岐を用意するための内部ステップ数Jを減らす。

SSをターゲットへ直接適用するとターゲットの復号分布が変わり得るため、論文はSSをドラフトに限定する。出力の確定は最終ターゲットの検証に委ねる。ただし、付録Bの分布同等性の証明は、検証へ渡すドラフト列の条件付き分布が通常の投機復号と同じであることを前提にする。早期候補の選択や枝の再利用がその条件を満たさない場合まで、無条件に厳密同分布を証明したものではない。

### GPU/NPU配置と通信の臨界経路

ターゲットはGPU上のMegatron式テンソル並列で実行し、ドラフトはNPU上のSPD式分割で実行する。論文§3.3ではドラフト層を二つの連続区間へ分け、各区間内ではNPUごとの常駐重み分割を使って計算する。区間境界での再整列と出力ロジット組立ての計2回の同期に抑えることで、各層ごとに同期する構成よりドラフトの通信費を下げる。ターゲットとドラフトの集合通信は別々であり、GPUとNPUをまたぐ全結合通信を行うわけではない。

ターゲット前半時間をT_pre、後半をT_suf、ドラフト分岐生成をT_d、二回のトークン交換をT_rvとすると、Mirror-SDの一ステップ時間は概ね`T_pre + max(T_suf, T_d) + T_rv`となる。従来の直列方式の`T_pre + T_suf + T_d`と比べ、T_dがT_suf以内に収まればドラフト計算をほぼ隠蔽できる。反対にドラフトが長過ぎる、NPUが遅い、トークン交換が高価、あるいは早期出力が深過ぎる場合は並列化利得が小さくなる。

## 評価

### モデル、装置、設定

| 項目 | 一次論文v2の条件 |
|---|---|
| ターゲット | Qwen3-14B、Qwen3-32B、Mistral-24B、OPT-66B |
| ドラフト | Qwen用0.6B、Mistral用0.5B、OPT用0.2B。UltraChatでSS目的により学習 |
| ハードウェア | Apple M2 Ultraシステム8台。ターゲットは各GPU、ドラフトは各NPUへ分散 |
| 主実験 | SpecBench、翻訳、要約、QA、数学推論、RAG、多ターン対話。温度0/1 |
| 既定の分岐 | 中間層ℓ_e=N/2、κ=8、バッチ1 |
| 比較対象 | 自己回帰、Vanilla-SD、EAGLE2/3、Hydra、Medusa、Recycling、PLD、REST、Lookahead等 |
| 指標 | 自己回帰に対する壁時計時間の速度倍率、受理長、ドラフト時間、分岐再計算頻度 |

論文付録Fによれば、GPU/NPUの各群へモデルを分割し、装置間ではトークンIDと対数確率を送る。対象は8システムの異種アクセラレータ構成であり、単一のRTX GPUだけで同じ倍率を得られるという結果ではない。ドラフト学習を必要とするため、任意の既存LLMへ学習不要で即時適用できる方式でもない。

### 感度・負の条件・正しさの前提

Figure 3は、ドラフト規模を大きくすると通常の投機復号では受理長の改善とともに生成時間が増えるのに対し、Mirror-SDではターゲット後半と重なる範囲でドラフトを大きくしてもステップ時間の増加が小さいことを示す。SSを併用すると内部ドラフトステップ数を減らし、並列に隠せる範囲が広がる。Mistral-24BとOPT-66BのFigure 4も、通常ドラフト、SSドラフト、Mirror-SD、Mirror-SD+SSの順で概ね改善することを示している。

付録Dのバッチ感度では、バッチサイズが増えるとドラフト計算・検証の双方が重くなり、Mirror-SDでも速度倍率が低下する。Qwen3-14BのMT-Benchでは図中の例で通常SDが2.84倍から1.77倍へ、Mirror-SDが3.05倍から1.95倍へ低下する。したがってバッチ1での最大倍率を高負荷サービングへそのまま適用できない。付録Eのκ・早期出力深さの検討では、κを大きくするほど再計算が減る一方で枝の生成費用が増えるため、κ=8と中間層出力を実用的な既定値としている。

出力の正しさは、ターゲット最終層が検証したトークンだけを確定する規則による。論文付録Bは通常SDと同じ受理規則を明示し、さらに同一の条件付きドラフト分布という前提のもとで受理長の分布一致を導く。これは生成品質のベンチマークを別途測定した結果ではなく、アルゴリズムの確定規則と条件付き理論保証である。

## 既存研究との差

MedusaやHydraはターゲットに複数候補を出すヘッドを付け、EAGLE系は専用ドラフトを学習するが、追加のドラフト計算がターゲットと直列に置かれれば臨界経路を伸ばす。Mirror-SDは**ターゲット中間層からの分岐準備、訂正経路の再利用、NPUでのドラフト計算、ドラフト専用SS**を一つの実行手順として組み合わせる。トークン単位の少量通信を利用し、GPUとNPUの並列性を直接利用する点が差分である。

## 限界

最大の前提は、GPUとは別に十分なNPU資源と高速な通信路があることである。単一GPU環境では同じ並列実行を再現できず、NPUが遅い場合はドラフトがターゲット後半の時間を超えて臨界経路へ戻る。Top-κ分岐は受理されない候補の計算を含むため、分岐幅を増やし続ければ効率が落ちる。ドラフトをターゲットに合わせて学習する費用も、オンライン推論速度の表からは差し引かれていない。

論文は主にSpecBenchのバッチ1条件を中心に評価しており、多数利用者の連続バッチ化、長期運用でのKV配置、実サービスの尾部遅延や消費電力の改善を全面的に保証するものではない。特に論文の「品質維持」は最終ターゲットの検証と同一ドラフト分布の条件に依存する。実装時には分岐選択・乱数・訂正処理がこの条件を満たすか確認する必要がある。
