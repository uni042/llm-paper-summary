# PowerSlider: Exploiting Phase Asymmetry for LLM Serving under Demand Response

> 入力処理・思考・回答生成の電力感度とKV容量の非対称性を段階別周波数制御、KV予約、GPU割当に利用し、時間変動する電力上限の下でもLLM提供の達成要求率を維持する。
## 書誌情報
- **著者**: Yueying Li, Jiayang Chen, Yuanfan Chen, Leo Han, Haoran Qiu, Esha Choukse, Rodrigo Fonseca, Udit Gupta
- **著者・所属**: Cornell University; Microsoft Azure Research; Cornell Tech
- **公開**: arXiv:2608.21719
- **種別**: プレプリント
- **対象**: 需要応答、動的周波数制御、LLM提供、推論型生成、KVキャッシュ、SGLang
- **実装**: SGLang上に三段階分離、電力最適化器、配置制御器、要求振分け制御器を実装。KV転送はTCPまたはRDMA、GPU周波数と電力上限はNVMLで制御する。
## 概要
PowerSliderはデータセンターが需要応答で時間変動する瞬時電力上限を課される状況に対し、LLM推論の入力処理・思考・回答生成で動作周波数への感度とKVメモリ圧力が異なることを利用して電力を再配分する。入力・思考・回答の三段階分離、許容遅延を契約化する柔軟サービス等級、最適性条件から導くオンライン電力配分、段階別の周波数・KV容量・GPU群制御を統合する。SGLang実装と実運用由来トレース評価で、推論型高負荷かつ30%電力削減時にオンライン達成要求率78.3%を維持し、最良比較方式の47.6%を大きく上回る。

PowerSliderは、時変電力上限、段階ごとの周波数感度、KVメモリ容量、サービス等級ごとの許容遅延を一つのオンライン最適化へ統合する。推論処理を入力処理・思考・回答の三段階へ分離して各段階に周波数、GPU数、KV予約粒度を独立に与え、柔軟サービス契約で利用者が許容する限定的な遅延を数理制約へ変換する。巨大な離散設定を事前総当たりせず、電力・処理容量モデルを連続緩和した最適化問題のカルーシュ・クーン・タッカー条件から、各段階・等級群の最適動作点を高速に解く。
## 問題設定
需要応答ではクラスタへ時間変動する瞬時電力上限が課されるため、総エネルギー最小化のように処理を後ろへずらすだけでは制約を満たせない。GPU周波数を一律に下げると、演算律速の入力処理は周波数低下にほぼ比例して遅くなる一方、メモリ帯域律速の回答生成はA100で公称周波数の約0.57倍まで処理量をほぼ維持できるため、性能損失の小さい場所から電力を削る余地が失われる。さらに推論型モデルでは長い思考列がKVキャッシュを長時間占有し、従来の入力処理・生成二分割では思考と回答が同じ生成側GPU群を争って同時処理数を制限する。出力長も裾の重い分布なので事前長さ予測による振分けが崩れやすい。
## 新規性
PowerSliderは、時変電力上限、段階ごとの周波数感度、KVメモリ容量、サービス等級ごとの許容遅延を一つのオンライン最適化へ統合する。推論処理を入力処理・思考・回答の三段階へ分離して各段階に周波数、GPU数、KV予約粒度を独立に与え、柔軟サービス契約で利用者が許容する限定的な遅延を数理制約へ変換する。巨大な離散設定を事前総当たりせず、電力・処理容量モデルを連続緩和した最適化問題のカルーシュ・クーン・タッカー条件から、各段階・等級群の最適動作点を高速に解く。
## 手法
### 手法のあらまし
まず入力処理・思考・回答を別GPU群へ分離し、長い思考KVが短い回答生成の同時処理容量を圧迫する干渉を切る。各段階・等級群について、GPU数、動作周波数、KV予約粒度から演算律速容量とメモリ律速容量を計算し、小さい方を実効処理容量とする。演算側は実測した複数GPU拡張率とルーフライン解析から得る演算律速割合で周波数感度を表し、電力はGPUごとに周波数の三次式で近似する。柔軟等級には基準遅延に対して最大何倍までの遅延をイベント時間の何割まで許すかを契約として与え、到着率分布から容量不足による影響上限へ写像する。最適化器は電力上限、影響上限、厳格等級の制約下で共同割当を解き、各群の周波数、GPU数、KV予算を決める。実行側は数分周期でGPU群を再配置し、移動時には新規要求を止めて実行中要求を完了またはKV状態を移送してから所属を変更する。周波数変更は要求ごとの段階境界で希望値を登録し、50〜100ミリ秒ごとにサービス重要度を考慮して集約し、一回のNVML呼出しで適用する。要求振分けは出力長を事前予測せず、観測した段階別トークン長の移動平均からKV予約と受入数を更新し、長さが伸びれば同時実行数を絞ってKV枯渇を防ぐ。最適化器の推定誤差があってもGPU電力上限をハードウェア側の安全柵として常時設定し、最低周波数でも静的電力が大きすぎる場合は使用GPU数を減らして退避済みGPUを停止する。

### 入力・思考・回答の三段階分離
従来の入力処理・生成二分割では、推論型モデルの長い思考列と利用者へ返す比較的短い回答列が同じ生成側GPU群を共有する。思考列は数千から数万トークンに及び、その全期間にわたってKV状態をHBMへ保持するため、短い回答処理が使える同時実行枠を奪い、電力上限でGPU処理量が落ちたときに待ち行列を急速に悪化させる。PowerSliderは生成段階を思考と回答へ分け、入力処理・思考・回答の三つを専用GPU群として扱う。これにより思考側と回答側で異なるKV予約粒度を選べ、典型設定では思考側インスタンスの同時処理容量が従来二分割より44%増える。また各段階へ独立した動作周波数を設定できるので、演算律速の入力処理には高い周波数を残し、メモリ帯域律速の回答生成では周波数を大きく下げるという電力非対称性を直接利用できる。三段階構成は固定ではなく、思考トラフィックが減ると配置制御器が思考群を順次退避してゼロまで縮め、通常の入力・生成二段階相当へ戻す。逆に推論要求が増えれば思考群を再拡大するため、推論型と通常型が時間変動する混合負荷にも適応できる。

### 柔軟サービス契約
単純な優先度方式では電力上限が深くなると低優先要求を丸ごと捨て、その後は高優先要求まで待ち行列が伸びる。PowerSliderは利用者が許容できる限定的な遅延余裕を明示的な契約へ変える。柔軟等級cには基準遅延Lに対し最大何倍までの遅延を許すかを表す係数と、需要応答イベント時間のうちその劣化を何割まで許すかを表す割合を与える。例えば三倍遅延を三割の時間まで許す、といった形で利用者側の上限を定義する。最適化器は到着率分布と現在処理容量から、容量を削ったときに契約違反へ近づく度合いを影響関数として計算し、この上限を電力配分問題の制約へ組み込む。厳格等級は硬い遅延制約、最善努力等級は24時間以内に完了すればよい遅延可能処理として別扱いする。電力が不足するとまず最善努力処理を遅らせ、次に契約で許された柔軟等級の余裕を使うため、特定等級を即座に全停止する方式より滑らかに性能を落とせる。実行時には柔軟要求が契約上限を超えて待たないよう、期限に近づいた要求を厳格等級相当へ昇格する。

### 最適性条件に基づくオンライン電力配分
入力・思考・回答の三段階と複数サービス等級を組み合わせると、各群がGPU数、周波数、KV予約粒度を持つため設定空間は非常に大きく、電力上限や要求構成が変わるたびに事前測定表を総当たりする方式は現実的でない。PowerSliderは各群の処理容量を演算律速容量とメモリ容量律速容量の小さい方として表し、演算側にはルーフライン解析から得る演算律速割合を導入する。GPU電力は静的電力項と周波数依存項を持つ三次式で近似し、実測点に対して決定係数0.95超を得る。柔軟契約から得た影響上限とクラスタ全体の瞬時電力上限を制約として、連続緩和した共同割当問題を構成する。カルーシュ・クーン・タッカー条件により、周波数を一段上げる限界電力費用と、その群の処理容量増加がサービス影響を減らす限界利益を釣り合わせる。演算律速割合が高い入力処理は周波数低下の損失が大きいため電力を残し、メモリ律速の生成段階から先に削る。九群なら20回の二分探索と各群80判断段階を7.7ミリ秒、81群でも63ミリ秒で解け、100ミリ秒周波数制御周期内に収まる。

### 実行時配置・振分け制御
最適化器が求めた設定は、GPU群の再配置、動作周波数、要求受入という異なる時間尺度の操作へ変換する必要がある。配置制御器はGPUを別段階へ移す際、新規要求の受入を止め、実行中要求を完了させるかKV状態を別GPUへ移してから所属を変更する退避後再配置を行う。再配置は残存処理量に応じて時間がかかるため数分周期とし、その間の速い電力変動は周波数制御で吸収する。市販GPUの周波数固定呼出し自体が数十から数百ミリ秒かかり、同一GPU上の要求が異なる希望周波数を持つため、各要求は段階境界で希望値と重要度を投票し、50〜100ミリ秒ごとに集約して一回だけNVMLへ反映する。要求振分け側は裾の重い思考出力長を事前予測せず、観測した段階別トークン長の移動平均をKV予約粒度へ反映する。長くなれば受入同時数を減らしてKV枯渇を避け、短くなれば増やす。さらにGPUごとのハードウェア電力上限を常時設定し、最適化誤差があっても瞬時上限を越えない安全柵とする。

### 全体のデータ／制御の流れ
電力最適化器が電力上限を各段階・等級群のGPU数、周波数、KV予算へ変換し、配置制御器がGPU群と周波数・電力上限を適用し、振分け制御器が要求単位の受入と配送を行う三層制御。SGLangを基盤とし、段階間KV状態はTCPまたはRDMAで転送する。
## 評価条件
- **ハードウェア**: 実機はDGX-A100とGH200サーバを用い、八GPU以下のノードで測定する。64〜512 GPU規模は実機測定値で拡張した離散事象シミュレータを使用する。A100は公称1410MHz、最低210MHz。100Gbps InfiniBand上のRDMAによるKV転送は一リンク11.2GB/s、TCPは6.8GB/s。
- **ソフトウェア**: SGLangとMooncake系KV転送機構を基盤に、三段階分離、電力最適化器、配置制御器、要求振分け制御器を実装する。GPU周波数固定と電力上限はNVMLで制御する。
推論型負荷にはMagpie-ReasoningとS1K、通常負荷にはAzureのLLM推論コード・対話トレースを使い、突発性を持つガンマ到着過程も生成する。既定の要求構成は厳格等級30%、柔軟等級30%、最善努力等級40%で、柔軟等級は基準遅延の三倍までをイベント時間の30%以内で許す。静的電力削減率0〜60%と24時間の動的需要応答トレースを評価する。指標は等級別のSLO達成要求率、回答開始までと完了までの90・99百分位遅延、最善努力処理量。比較対象は一律周波数方式、POLCA、SplitWise、DynamoLLM拡張、SLOs-Serve拡張。シミュレータは未使用測定点に対して構成要素誤差4%未満、電力近似の決定係数0.95超、八GPUトレース再生で達成要求率差4%未満、90百分位完了遅延差9%未満を確認する。
八GPU以下は実機、64〜512 GPU規模は検証済みシミュレーションを含む。推論型と通常型の混在、静的・動的電力上限、サービス等級構成の時間変動を評価する。電力モデルはGPU機種ごとに再適合が必要。
## 主要結果
通常推論負荷では突発到着・毎秒14要求の条件で全等級の達成要求率100%を電力60%削減まで維持する。推論型負荷の128 GPU・毎秒60要求では30%削減時にオンライン達成要求率78.3%、最善努力処理54%を保ち、最良比較方式のオンライン47.6%、最善努力0%に対して1.64倍となる。深い電力上限でも末尾遅延を公称時に近く保ち、電力配分、三段階分離、柔軟契約の三要素すべてが寄与する。

- 推論型負荷のオンライン達成要求率 / 78.3% (比較対象: 最良比較47.6%; 条件: 128 GPU、毎秒60要求、30%電力削減) — 1.64倍。最善努力処理も54%残り、比較方式の0%より段階的に劣化できる。

- 通常負荷の達成要求率 / 全等級100%を60%削減まで維持 (比較対象: POLCA 67.7%、他方式は40%超削減で15%未満; 条件: 毎秒14要求の突発到着) — メモリ律速生成を公称0.57倍周波数まで下げられる非対称性と柔軟契約が大きな余裕を作る。

- 90百分位末尾遅延 / 厳格等級の完了89秒、回答開始54秒 (比較対象: 無制限時比1.1倍、1.3倍。POLCA完了220秒; 条件: 60%電力削減) — 受入要求量を処理容量以下へ保ち待ち行列の発散を防ぐ。

- 構成要素除去 / 一要素除去で完了遅延74〜100%、回答開始遅延59〜101%増 (比較対象: 完全版PowerSlider; 条件: 30%電力削減) — 電力配分、思考隔離、契約余裕は別々の律速を担当し相互代替できない。

- 最適化計算時間 / 九群7.7ミリ秒、81群63ミリ秒 (比較対象: 100ミリ秒の周波数制御周期; 条件: 二分探索20回、各群80判断段階) — クラスタGPU数ではなく制御群数で増えるため電力上限変化へオンライン追随できる。

- 三段階分離の遅延改善 / 端末間遅延12.5倍低下 (比較対象: 入力・生成二段階分離; 条件: 長い推論負荷、40%電力削減) — 思考KVを回答生成から隔離して生成側待ち行列をほぼ消す。

### 負の結果・境界条件
- 周波数制御だけでは静的電力床より深い電力上限を満たせず、GPU集約と停止が必要になる。三段階分離は推論要求ごとに思考から回答への追加KV転送を一回増やすが、公称電力では処理重畳によりほぼ隠れる。電力近似モデルは機種ごとの再測定が必要。

### 結果の読み方
核心は、同じ一ワットを削っても処理段階ごとの性能費用が違うことと、推論型負荷では電力だけでなくKV容量も同時に制約になることを最適化へ入れた点にある。浅い上限は周波数配分で吸収し、深い上限では思考隔離と契約済み遅延余裕、さらに静的電力床以下ではGPU集約へ段階的に移る。
## 品質への影響
モデルの生成品質は変更せず、サービス目標達成率と電力上限を最適化する。柔軟契約は許容遅延劣化の確率上限を明示し、60%削減でも観測された最大違反割合27.5%で契約上限30%以内と報告する。
## 既存研究との差
DynamoLLMやVoltanaLLMなどは総エネルギーやサービス目標を静的電力条件で最適化し、POLCAは優先度しきい値で周波数を制御する。PowerWeave、Power Sloshing、PowerGradは固定された電力枠の内部再配分であり、電力網から来る時間変動上限を処理段階、サービス等級、KV設定へ変換しない。DistServeやSplitWiseは入力処理と生成を分離するが、推論時の思考を独立段階にせず、長い思考KVが回答側容量を圧迫する。PowerSliderは三段階分離、柔軟契約、オンライン最適化を統合して時間変動電力上限を直接入力として扱う。
## 限界
64〜512 GPUの主要クラスタ規模結果には検証済みシミュレータを用いた結果が含まれ、全規模を実クラスタで測定したわけではない。電力三次式と処理量モデルはGPU機種、モデル、並列構成ごとに測定し直す必要がある。市販GPUの周波数変更には数十〜数百ミリ秒かかるため要求単位の即時変更はできず、50〜100ミリ秒ごとの投票集約が必要。三段階分離は思考から回答へのKV転送を追加するため、ネットワークが遅い環境や転送を計算と重ねられない環境では利得が縮み得る。最低周波数でも基板・HBMの静的電力が残るため、極端な電力上限はGPU集約・停止なしでは達成できない。
## 実装状態
SGLang上に実行系を実装し、Mooncake系KV転送、TCP・RDMA接続再利用、NVMLによる周波数・電力上限制御、退避後GPU再配置を備える。DGX-A100とGH200実機、および実機測定で検証したシミュレータで評価する。arXiv本文から公開コード保管庫は確認できなかった。
## 研究上の位置づけ
LLM提供スケジューラを、電力、演算性能、HBM上のKV容量という複数資源の共同制御へ拡張する研究。特に推論型負荷では長い思考KVの占有を独立した容量制約として扱い、処理段階分離とKV予約・受入制御を周波数・GPU割当と同じ最適化へ結合する点が、従来の電力対応提供や入力・生成分離からの重要な拡張となる。
