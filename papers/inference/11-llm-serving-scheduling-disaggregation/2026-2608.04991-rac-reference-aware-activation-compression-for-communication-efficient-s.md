# RAC：参照を利用する中間活性圧縮と分割推論の通信最適化

## 概要

RACは大規模言語モデル（LLM）の先頭層と末尾層を信頼端末、中央層をクラウドで動かす三分割推論を対象とする。端末からクラウドへ送る境界活性と、クラウドから端末へ返す境界活性を、そのまま低ビット量子化するのではなく、送受信側で共有可能な参照状態との差分として符号化する。長い入力を処理する事前処理（prefill）と、一語ずつ生成する復号（decode）では利用可能な参照が違うため、段階と通信方向によって参照源を切り替える。

原著が評価した3モデルと9種類のモデル・回線条件では、無圧縮との比較で平均初回トークン時間（TTFT）の比が1.24～2.72倍、平均出力トークン時間（TPOT）の比が1.01～2.79倍である。値ペイロードだけを見ると事前処理は無圧縮の27.8%、復号は25.0%となる。ただし整合係数や制御メッセージを含む総転送量が同率で減るわけではなく、高帯域条件では圧縮計算が通信削減益を上回る。RACは通信効率化の研究であり、活性値からの情報漏えいを防ぐ暗号学的な保証を与えるものではない。

## 問題設定

三分割モデルは端末の先頭層、クラウドの中央層、端末の末尾層を直列に実行する。上りの境界状態を `H_l2c`、下りを `H_c2l` とすると、事前処理では各境界を形状 `[B,N,d]` の活性が通過する。入力長 `N` が増えるほど送信バイト数が増えて初回トークン時間を圧迫する。復号では `[B,1,d]` の活性を生成トークンごとに往復させるため、帯域だけでなく往復遅延と小さなパケットの固定費用が支配的になる。エージェントがツール結果を繰り返し取り込む場合は、この転送が複数回繰り返される。

直接4ビット化では少数の大きな活性成分に量子化幅が引きずられ、多数の小さい成分が粗く丸められる。上位値のみを残す方式は値を捨てるだけでなく索引も必要になる。RACは現在の活性に似た参照を引き、残差の値域を縮めてから量子化する。参照を送信側だけが知っていても受信側は復元できないので、両端が同じ参照を決定できることが設計上の必要条件である。参照の検索・予測が通信の節約より高価になれば、速度改善は得られない。

RACが操作するのは層境界の一時的な活性であり、モデル重みのオフロード、注意の鍵値キャッシュの圧縮、分割層の探索、サンプリングアルゴリズムを変更しない。したがって、推論基盤へ組み込む際には別のメモリ最適化と混同せず、ネットワーク経路と符号化費用を独立に計測する必要がある。

## 手法

### 1. 事前処理の上り：過去の完全一致トークン区間を検索

現在の入力トークン列から固定長窓の転がりハッシュを作り、過去の要求に同じ窓があるかを検索する。見つかった候補は一致区間を延長して最長の完全一致区間とし、区間長を優先し同長なら新しい履歴を選ぶ。原著は各ハッシュ区画に直近8件までを保持する。入力を左から走査し、選択した区間の長さだけ位置を進めることで、選択結果を決定的にする。過去の同一トークン列でも位置や前文脈が違えば活性は同一ではないため、参照は後段の整合処理を経て使用する。

一致区間は過去に保存した活性を参照し、未被覆位置で現在列の先行位置に同じトークンがある場合は再構成済み活性を再利用する。どちらにも該当しなければ直接符号化する。ハッシュ探索、区間選択、履歴活性の先読みを端末の先頭層実行と重ね、現在の上り活性が完成した時点で残差形成へ進む。反復入力が少ない要求では履歴参照の効用が下がるが、直接符号化への退避によって推論を継続できる。

### 2. 事前処理の下り：同じ往復で再構成した上り状態を共有

クラウドは受信した上り活性を復号し、その状態を中央層へ入力する。端末側も通信形式から同じ上り状態を再構成できるため、下りの参照に `R_cross = Ĥ_l2c` を用いる。別途参照を送る必要がなく、過去要求の検索も不要である。ただし上りと下りは異なる層から生じ、原著図2の余弦類似度はモデルと分割幅に大きく依存する。例えばQwenでおおむね0.58～0.88、Llamaではおおむね0.04～0.32であり、同じ往復の活性だからそのまま引き算すればよいというわけではない。群別アフィン整合が必要になる。

### 3. 復号：境界ごとに学習した軽量因果予測器

最初の復号ステップには前回の境界活性がないため、参照を用いず直接送る。2ステップ目以降は上り・下り境界ごとに独立に学習した1層の因果Transformerを使い、前回の再構成済み境界活性と予測器の有限履歴状態から次の参照を生成する。予測器が持つ鍵値キャッシュは通信参照生成用であり、本体LLMの鍵値キャッシュを置換するものではない。原著図4では、前回活性をそのまま再利用する場合より平均余弦類似度が上りで0.156～0.201、下りで0.059～0.118増えた。

予測参照は圧縮時にだけ使い、モデル本体の活性や生成トークンを予測器の値に置換しない。予測器の計算は本体の層計算や通信と重ね、追加の直列遅延を抑える。両端で参照が食い違わないよう、送信側も実際の通信形式から丸め済み状態を再構成して次回予測へ入力する。量子化前の高精度活性を次回参照に用いると、受信側の状態とのずれが蓄積し得る。

### 4. 群別アフィン整合、残差量子化、校正

送信側は現在の活性 `H` と共有参照 `R` を隠れ次元の幅 `g_a` ごとに分け、各群で `||H_j-(α_j R_j+β_j)||²` を最小化する係数を求める。参照の分散がゼロの場合は傾きをゼロにして切片を現在値の平均とする。係数は通信形式に丸めた値を送受信側で共通利用し、整合参照 `Ṙ` と残差 `E=H-Ṙ` を得る。細かい群は近似精度を改善する一方、群数だけ係数の送信量が増えるため、復号では粗い群が適する場合がある。

残差は幅 `g_q` の群ごとに4ビットまたは8ビット整数へ量子化する。尺度は群内の最大絶対値に基づいて決め、送信形式へ切り上げて飽和を避ける。4ビット整数は2値を1バイトに詰める。事前処理では大きな残差を外れ値として選び、群内位置と16ビット浮動小数点値を別送できる。復号では1トークンごとの付帯情報を抑えるため、外れ値別送を使わず量子化群を隠れ次元全体 `g_q=d` とする。受信側は整数を逆量子化し、必要なら外れ値を戻し、整合済み参照へ足して復元する。

参照が両端で一致するなら復元誤差は `H-Ĥ=E-Ê` となり、参照を使ったこと自体で独立の誤差項が生じるわけではない。しかし尺度の通信丸めや外れ値の半精度化による誤差は残る。群幅、量子化ビット幅、外れ値数はモデル、分割点、方向、事前処理・復号の段階ごとに事前校正し、品質目標と実際の詰め込み後バイト数、計算負担を併せて選ぶ。理想化した値ペイロードだけで最適化しない点が重要である。

## 評価

### 評価条件と比較対象

原著第V節は端末側にNVIDIA RTX 3090を2基、クラウド側にNVIDIA A800を1基または4基用いた。モデルはGLM-4-9B-0414、Qwen3-30B-A3B、Llama-3.3-70B-Instructで、会話負荷にはShareGPTを用いる。通信帯域はLinux Traffic Controlで模擬し、主な図5では事前処理を100 Mbit/s、復号を10、5、1 Mbit/sに変化させ、3モデルと合わせた9条件を測定した。同時要求は主として8件である。比較対象は無圧縮のRaw、上位成分を保持するTopK、直接量子化のINT4/INT8であり、品質指標はWikiText-2困惑度、HellaSwag、GSM8K、MATH-500である。

### 評価結果：品質とペイロード（表I）

無圧縮に対する活性値だけのペイロードは、事前処理27.8%、復号25.0%であり、それぞれ72.2%、75.0%の削減となる。整合係数、量子化尺度、外れ値位置、制御情報を除く比率であるため、ネットワークの総バイト数削減率として引用してはならない。非困惑度の12個の課題スコア差は−0.40～＋2.50ポイントであり、圧縮後の品質は一律に改善するわけではない。

GLM-4 9BのWikiText-2困惑度はRawの40.77に対しRACが39.66、GSM8K厳密一致率は80.44から80.36、MATH-500は56.00から56.60である。Qwen3-30B-A3Bでは困惑度19.18から19.45、GSM8K厳密一致率89.38から89.76、MATH-500は80.00から79.80となった。Llama-3.3-70Bでは困惑度13.46から13.54、GSM8K厳密一致率73.77から76.27、MATH-500は65.80から65.40である。良化と悪化が混在することを明示する。直接INT4量子化ではGLMの困惑度214.87、Qwenで1110.52、Llamaで16932.98まで悪化し、参照差分を用いる設計の意義を示す。ただし比較方式間で品質目標を完全に揃えた実験ではない。

### 評価結果：初回・生成時間と末尾遅延（図5・図6）

主要9条件では平均初回トークン時間が1.24～2.72倍、平均出力トークン時間が1.01～2.79倍改善し、99パーセンタイルの初回トークン時間も9条件すべてで改善した。しかしQwen3-30B-A3Bの事前処理100／復号5 Mbit/s条件では、中央値の初回トークン時間が12.16 ms、中央値の出力トークン時間が6.81 ms、99パーセンタイルの出力トークン時間が11.66 ms悪化する。100／10 Mbit/sでも99パーセンタイル出力トークン時間は4.23 ms悪化した。平均改善を全分位点の改善と取り違えない。

帯域をより広く振った探索的25条件では、初回トークン時間の改善が21条件、出力トークン時間が18条件、出力トークン処理量が19条件に留まる。残りは無圧縮が優位であり、通信帯域が大きいほど符号化計算の固定費用が表面化する。原著は探索図の一部モデルについてチェックポイント識別子を保持していないと記載しているため、この探索的結果を厳密に同一モデル版で再現された性能曲線とみなさない。

### 評価結果：構成要素除去と実行時費用（表II・図7）

GLMのMATH-500は完全版56.60に対し、復号予測器を除くと34.60、履歴検索を除くと47.40、群別アフィン整合を除くと49.40へ低下した。GLMのGSM8K厳密一致率も完全版80.36に対して予測器なし70.51、検索なし78.39、整合なし79.38となる。QwenやLlamaでも多くの数学指標で構成要素除去に伴う低下があるが、WikiText-2やHellaSwagでは小差や符号の混在がある。全指標で同じ寄与と一般化しない。

図7では復号側の図示された符号化各段階の平均は1 ms未満で、同一往復の上り状態を下り参照として待つ平均は0.007 ms未満である。一方、履歴ハッシュ、区間選択、先読み、予測器の実行・待ち時間は重畳する設計として図の露出時間に含まれない。図示段階の合計をシステム全体の追加処理時間と誤読しない。原著が報告するのは分割推論経路の実測であり、単体量子化カーネルの速度ではない。

## 既存研究との差

直接INT4/INT8は現在の活性そのものを量子化し、TopKは一部の大きな成分を残す。RACは送受信で共通化できる参照を事前処理上り・下り・復号で切り替え、群別整合後の残差を低ビット化する。分割配置を探索する方式とは異なり層配置を固定し、鍵値キャッシュ転送とも異なり一時的な境界活性を対象とする。原著の固有性は、反復入力の完全一致区間、同一往復の再構成上り状態、直前復号状態の因果予測という三つの参照源を、送受信側の状態同期と合わせて利用する点にある。

## 限界

評価は3モデル、端末RTX 3090×2とクラウドA800×1/4、主に8並列要求、模擬回線に限定される。高帯域の一部条件では無圧縮が優位であり、初回トークン時間・出力トークン時間の平均が改善しても中央値や99パーセンタイルが悪化する例がある。反復トークン区間が少ない入力では履歴参照が効きにくく、モデルや分割幅が変わると上り・下りの類似度と予測器の品質が変わるため再校正が必要である。

外れ値位置、整合係数、尺度、予測器の計算・記憶領域を含めた実運用の資源効率は、回線条件とモデル構成に依存する。公開された著者公式実装URLを一次資料から確認できず、独立再現実験は未実施である。平文を端末に置く三分割構成は情報露出を減らす動機だが、通信する活性からの復元を防ぐ形式的なプライバシー保証はない。品質評価も圧縮方式ごとの目標精度を完全に揃えていないため、全方式に対する普遍的優位性は示されていない。
