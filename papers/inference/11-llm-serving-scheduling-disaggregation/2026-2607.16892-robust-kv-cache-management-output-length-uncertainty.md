# Robust KV Cache Management for LLM Serving under Output Token Length Uncertainty

> request到着時には最終出力長が分からないため、KVを少なく予約するとpreemption、多く予約するとHBM浪費になる。本研究は固定P90/P95予約をやめ、costと分布変化に応じて予約量・routing・GPU構成を同時に決める。

## 問題設定

Serving engineは入力長を知っていても、生成が終わるまで出力token数を確定できない。KV cacheを過小予約すると途中で容量不足となり、preemptionと再計算が発生する。過大予約すると未使用HBMが増え、同時処理request数を下げる。固定quantile予約はpreemption costとmemory waste costの比やworkload distributionが変わると最適点を外れる。

## 手法

### 1. 4種類のdecisionを共同最適化する

control planeは、GPU clusterのtensor/pipeline parallel構成、request classごとのKV予約token数、異なるserving groupへのrouting、共有promptのprefix cachingを同じoptimization problemとして扱う。latency SLOとqueueing delayもconstraintへ入れる。

### 2. Wasserstein分布ロバスト最適化で出力長shiftへ備える

過去sampleの出力長分布だけを正しいと仮定せず、その分布からWasserstein distance内にある複数の可能な分布を考え、その中で不利な場合にもcostが大きく崩れない予約policyを選ぶ。これにより昨日より長い出力が増える等のdistribution shiftへ耐性を持たせる。

### 3. Preemption対memory wasteのcost比から予約quantileを決める

解析ではpreemption costとwaste costの比に応じたcritical fractileが現れ、固定P90/P95を手動選択する代わりに、cost構造から必要な予約quantileが決まる。

### 4. Block Coordinate Descentで大規模問題を解く

GPU構成・routing・予約・prefix cacheを一度に解くmixed-integer問題を、変数groupごとに交互最適化する。これによりproduction規模のclass/configuration数でもrolling optimizationに使える計算量を狙う。

## 評価

BurstGPT、Azure、ShareGPT等のtraceを使ったsimulationで評価する。

- 固定quantile予約baseline比で総costを最大 **56%削減**。
- P99 latency、goodput、SLO violationを競争力のある範囲に維持。
- workload distribution shift下ではsample-average approximationよりtail latencyとSLO violationの悪化を抑える。

重要な注意点として、これは実vLLM clusterで測ったend-to-end speedupではなく、**trace-driven simulationとqueueing/cost modelに基づく結果**である。

## 既存研究との差

vLLM/PagedAttention等は割り当てられたmemoryを細粒度に管理するが、本研究はその上位のcontrol planeで「request classへ最初にどれだけKVを予約するか」を扱う。DistServe等のGPU配置最適化とも異なり、**出力長の不確実性とpreemption/waste costを明示的に予約policyへ入れる**。

## 限界

- 主評価はsimulationで、production runtimeへ統合した実機結果ではない。
- queueing modelはarrival/service-timeを近似しており、極端にburstyなtrafficで誤差が増える可能性がある。
- preemption時の再計算costもmodel化された値で、runtime実装によって変わる。
- request class内で出力長分布がある程度まとまっていることを仮定する。
- 大規模化するとre-optimization時間が増え、online適用にはwarm start等が必要になる。

## 一般的な実装上の含意

Paged KV allocatorだけでは、未知の出力長に対する**予約policy**の問題は残る。Serving control planeは出力長予測を一点推定として使うより、予測誤差・分布shift・preemption cost・memory opportunity costを同時に扱う方が安定する可能性がある。
