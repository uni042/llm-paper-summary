# LServe: Efficient Long-sequence LLM Serving with Unified Sparse Attention

> 長文LLMでは、プリフィルでは系列長に対して二乗で増える注意計算、デコードでは過去KVを毎トークン読み直すメモリ帯域が別々の律速になる。LServeは両者を**ブロック疎注意（block-sparse attention）**という共通の実行形式へ落とし、オフラインで決めるストリーミングヘッドと、実行時に選ぶ重要KVページを同じカーネル群で処理する。MLSys 2025評価ではプリフィル最大2.9倍、デコード平均1.3〜2.1倍の高速化を報告する。

## 概要

長い入力を処理するプリフィルでは、通常の密注意は各クエリがそれ以前の全キーを見るため、系列長が伸びるほど計算量が二乗で増える。一方、生成段階のデコードではクエリは1トークンだけだが、各ステップで長いKVキャッシュ全体を読み直すため、演算より高帯域メモリ（High Bandwidth Memory; HBM）の読み出しが支配しやすい。

この二つの律速へ別々の疎注意カーネルを作ると、プリフィル用とデコード用で異なるデータ構造・索引・量子化処理を保守する必要がある。LServeは注意行列をブロック単位で処理し、「計算するブロックだけを反復する」という共通カーネル抽象へ統一する。

プリフィルではDuoAttention由来のオフライン識別で注意ヘッドを**検索ヘッド（retrieval head）**と**ストリーミングヘッド（streaming head）**へ分ける。既定の50%疎性では半数をストリーミングヘッドとし、先頭のシンク領域と直近の局所領域だけへ注意させる。検索ヘッドは密注意を維持するため、長距離検索能力を全ヘッドから一律に奪わない。

デコードでは検索ヘッドにも動的疎性を入れる。各KV物理ページに保存したキー統計から、現在クエリに重要なページだけを選び、短いページテーブルを密注意カーネルへ渡す。量子化効率のため物理ページを大きく保ちながら、重要度推定は細かな論理ページで行う**階層ページング（hierarchical paging）**と、隣接デコードトークンで選択結果を使い回す**再利用可能ページ選択（reusable page selection）**が中心になる。

## 問題設定

長文配信で単純なKV量子化だけを行っても、KV一要素当たりのバイト数は減るが、デコード時に読むトークン数そのものは系列長に比例したままである。プリフィル側も注意計算のブロック数は変わらない。このため、長さ256K級では量子化後も注意が主な律速になり得る。

静的疎注意だけなら、ストリーミング注意のように各トークンが少数の局所ブロックとシンクブロックだけを見るため計算量を一定に近づけられる。しかし全ヘッドをストリーミング化すると、文書の遠方にある情報を検索する能力が失われやすい。

逆に動的ページ選択を全ヘッド・全ステップで行うと、ページ重要度を毎回計算する選択器自体が新しい律速になる。特にKV量子化では連続メモリアクセスを保つため物理ページを大きくしたいが、ページが大きいほど「ページ内に重要トークンが一つあるだけでページ全体を残す」粗い選択になり、疎性と精度の交換条件が悪化する。

LServeは、静的疎性で安く削れるヘッドと、動的選択が必要なヘッドを分離し、さらに論理的な選択粒度と物理的なメモリ配置を切り離すことでこの三つの衝突を解く。

## 手法

### 1. オフラインで検索ヘッドとストリーミングヘッドを分ける

LServeはDuoAttentionの最適化ベース識別を用い、各注意ヘッドにゲーティング値 (alphain[0,1]) を与える。値が1に近いヘッドは遠距離情報の検索に重要、0に近いヘッドは局所・シンクだけでも機能しやすいとみなす。

目標疎性50%なら (alpha) の中央値を閾値にし、半数を検索ヘッド、半数をストリーミングヘッドへ固定する。この分類は入力要求ごとに実行せずオフラインで一度決めるため、実行時のヘッド選別コストを持たない。

ストリーミングヘッドは先頭のシンクブロックと直近の局所ブロックだけを参照する。各トークンが見るブロック数が系列長によらずほぼ一定になるため、プリフィルでスキップできる注意タイルが増え、デコードでは保持・読出しKVも限定できる。

### 2. プリフィルでは密ヘッドと疎ヘッドを一つのブロック疎カーネルで融合する

プリフィルの検索ヘッドは通常の因果的密注意を行い、ストリーミングヘッドはシンク＋局所ブロックだけを処理する。LServeはこれらを別々のカーネル起動へ分けず、ブロック反復子で必要なタイルだけを列挙する融合CUDAカーネルにする。

GPUでは「全タイルを走査して条件分岐で飛ばす」実装は分岐と無駄な索引計算が残る。LServeの反復子抽象は、各ヘッドに必要なブロックのオフセットを直接計算し、不要タイルの反復そのものを省く。

このカーネル単体評価では、同じ疎性でMInference実装より一貫して約1.3倍高速だった。したがってアルゴリズム上の疎性だけでなく、ブロックをGPUが連続して処理できる形へ落としたことが実速度へ寄与する。

### 3. KVキャッシュをストリーミング用と検索用へ分離する

ストリーミングヘッドはシンクと局所領域だけを保持すればよい。一方、検索ヘッドは遠距離情報へアクセスするため長い履歴を保持する必要がある。LServeは両者を別のページ化KVキャッシュ（paged KV cache）として管理する。

検索ヘッド側の物理ページ末尾には、ページ中キーのチャネルごとの最大値 (k_{max}) と最小値 (k_{min}) を統計として保存する。これはデコード時にページ全体のキーを読む前に、現在クエリとそのページが強く反応し得るかを安価に上界評価するための情報である。

入力は現在クエリと各ページの統計、出力は次の疎注意カーネルへ渡す短いページテーブルになる。選ばれなかった物理ページのKVはデコード注意で読み出さないため、計算量だけでなくHBMトラフィックも削減できる。

### 4. 階層ページングで量子化向け物理ページと選択精度を両立する

KV量子化では、小さ過ぎるページはメタデータやスケール管理の比率を増やし、GPUメモリの連続性も悪くする。論文のQServe測定ではページサイズ16は、系列長8192でページ128に比べ最大1.52倍の遅延になった。一方、物理ページを64や128トークンへ大きくすると、ページ単位の重要度が平均化され、Quest型選択の精度が落ちる。

LServeは一つの大きな**物理ページ（physical page）**を複数の小さな**論理ページ（logical page）**へ分ける。KVの実メモリ配置と量子化は物理ページのまま維持し、重要度だけを論理ページ単位で計算する。

論理ページ (j) の重要度は、現在クエリ (q) の各チャネルについて (q_i k_{max,i}^{j}) と (q_i k_{min,i}^{j}) の大きい方を足し合わせて求める。物理ページの重要度は内部論理ページの最大値で決め、上位物理ページだけを実際の注意へ渡す。

これにより、選択器は細粒度情報を利用しながら、注意カーネルは連続した大きい物理ページを読む。論文のNeedle-in-a-Haystack評価では、物理ページ64でも論理ページ16相当の選択精度を保てた。

### 5. ページ選択結果を隣接クエリで再利用する

動的疎注意は、注意本体を一定KV予算へ抑えても、ページ選択器が全履歴統計を走査するため系列長に比例して重くなる。128K・KV予算4Kの例では、素朴なページ選択0.24 msが疎注意本体0.12 msの約2倍になり、選択器が律速になる。

自然言語では隣接生成トークンのクエリが似た履歴ページへ注意しやすいという時間的局所性がある。LServeはチャンク先頭でだけページ選択を実行し、続く数トークンは同じ選択結果を使う。

既定の再利用間隔は4で、RULER 64Kでは間隔4でもLServe-4096が85.6を維持した一方、16まで伸ばすと83.2へ下がった。選択費用を約4分の1へ減らしながら精度をほぼ維持する設定として4を採用している。

## 既存研究との差

DuoAttentionは一部ヘッドをストリーミング化してデコードを高速化するが、LServeは同じ静的ヘッド分類をプリフィル側の融合ブロック疎カーネルにも使い、さらに検索ヘッドへ動的ページ選択を重ねる。

Questはクエリ依存のKVページ重要度からデコードを疎化するが、物理ページサイズを細かくするとGPU効率が落ち、大きくすると重要度推定が粗くなる。LServeは論理ページと物理ページを分けることで、この精度とメモリ配置の衝突を緩和する。

MInferenceはプリフィルの疎注意を高速化するが、デコードを同じ実行枠組みでは扱わない。LServeの設計上の特徴は、プリフィルの静的疎性とデコードの動的疎性を**同じブロック疎注意抽象とページ化KV管理**へ統合した点にある。

## 限界・実装状況

静的ヘッド分類にはオフラインのDuoAttention型プロファイルが必要で、未プロファイルのモデルへ完全な無準備で適用する方式ではない。モデルや長文能力が変われば分類をやり直す必要がある。

動的ページ選択は近似なので、KV予算を小さく固定した極長文ではRULER精度が低下する。再利用間隔も長過ぎるとページ選択が現在クエリへ追従できなくなり、精度が下がる。

検索ヘッド用のキー統計、論理・物理ページの対応、再利用状態には追加メタデータと管理処理が必要である。短文脈ではこの固定費用の比率が上がるため、論文はオフラインプロファイルにより短文で不要な動的疎性を避ける。

公式実装はMIT HAN LabのOmniServeで公開されており、CUDA/PTX、QServe由来のW4A8KV4量子化、TensorRT-LLMとの統合を含む。論文の評価は主にA100/L40Sであり、異なるGPUや最新ランタイムで同じ倍率になるとは限らない。
