# Efficiently Serving Large Multimodal Models Using EPD Disaggregation

## 概要
大規模マルチモーダルモデル（Large Multimodal Model; LMM）は、通常の大規模言語モデル（Large Language Model; LLM）のプリフィルと復号に加え、画像や動画を高次元トークンへ変換するマルチモーダル符号化を必要とする。既存の単体構成やプリフィル・復号分離では、符号化器とLLMを同じプリフィルGPUへ置くため、符号化の計算とメモリがプリフィルを妨げる。EPD分離（Encode-Prefill-Decode Disaggregation）は符号化（E）、プリフィル（P）、復号（D）を独立GPU群へ分け、段階ごとにバッチ、並列度、キャッシュを最適化する。

MiniCPM-V 2.6、InternVL2-8B、InternVL2-26Bを用いた評価では、分離による空きメモリでピークメモリ使用量を最大15分の1、最大バッチを22倍、1要求当たり画像数を10倍、KVキャッシュ容量を2.2倍へ拡張した。オンライン負荷では先頭トークンまでの時間（Time To First Token; TTFT）を最大約71%削減し、ベースラインが10%未満のサービス水準目標（Service Level Objective; SLO）達成率へ落ちる要求率でもEPDは90%以上を維持する条件がある。

## 問題設定
LMMではマルチモーダル符号化器（Multimodal Encoder; MME）が画像パッチを処理して視覚トークンを作る。高解像度画像や動画ではパッチ数が増え、符号化計算そのものが重いだけでなく、生成された視覚トークンがプリフィル長を増やす。従来のvLLM型単体構成ではMME、LLM、マルチモーダルキャッシュ、KVキャッシュが同じGPU容量を奪い合う。

DistServe型のプリフィル・復号分離をLMMへ拡張しても、符号化とプリフィルは同じGPU群に残る。符号化の長い要求が来ると後続プリフィルが待たされ、逆にプリフィル中は符号化器が遊休する。さらにMMEとLLMを同居させるため、画像数、バッチ、KV容量のいずれかを小さくせざるを得ない。EPDはこの干渉を三段階の資源分離として扱う。

## 手法
### 三段階パイプラインと二種類の移送
入力テキストを i_p、マルチモーダル入力を i_m とすると、E段階は v_t^e=E(i_m) として視覚トークンを生成する。EP移送関数 ψ_EP がこのトークンを符号化側マルチモーダルキャッシュからプリフィル側へ移し、P段階はテキストと統合して最初の出力トークンと kv_1^p を生成する。続いてPD移送がKVキャッシュと最初のトークンをD段階へ渡し、Dは通常の自己回帰復号を続ける。

各段階は独立したデータ並列インスタンスを持ち、インスタンス内部ではテンソル並列またはパイプライン並列を使える。Eワーカーは符号化器重みとマルチモーダルキャッシュだけ、PはLLM重み・マルチモーダルキャッシュ・KVキャッシュ、DはLLM重みとKVキャッシュを保持する。この分離が「不要なモデル重みを各段階から外して空きメモリを増やす」という容量上の利得を作る。

### 非同期トークン転送とMMBlockManager
EとPを分離すると視覚トークン転送が新しいオーバーヘッドになる。EPDはNVLinkまたはInfiniBandを使って、下流インスタンスが要求を受け入れられる時点で直接非同期転送する。E側は符号化完了後にトークンをマルチモーダルキャッシュへ置き、イベントループがP側キャッシュへの転送を開始するため、転送中でもEは次要求の符号化を進められる。

MMBlockManagerは要求ごとに必要なマルチモーダルキャッシュブロックを事前確保し、転送確認後にE側ブロックを解放する。単なる三分割では転送待ちが直列化し得るが、キャッシュ所有権と転送を非同期化することで符号化GPUを通信待ちから切り離す。

### 要求内並列
要求内並列（Intra-Request Parallelism; IRP）は、1要求に複数画像・動画フレームがあるとき、そのパッチ集合を複数Eワーカーへ分割する。各ワーカーは担当パッチを独立に符号化し、得られたトークンをPへ非同期転送する。P側は全パッチが揃った後に順序を合わせ、射影・結合して完全なマルチモーダルトークン列を作る。

これは要求間データ並列だけでは短縮できない「単一の巨大動画要求」の符号化時間を縮める機構である。一方、画像が1枚で軽い場合には分割・同期の余地が小さく、IRPの利得も小さくなる。

### 資源配分最適化
E/P/DのGPU台数、最大バッチ、スケジューリング、並列方式は負荷で最適点が変わる。EPDは履歴ワークロードを入力に、DistServe由来のシミュレータで候補構成のグッドプット（SLOを満たせる最大要求率）を評価し、ベイズ最適化で性能とGPU費用の目的関数を探索する。

ここで出力はE/P/Dごとの構成であり、符号化が重い負荷ならEへ、長い出力ならDへ資源を寄せる。固定比率で分離するだけでは片側に待ち行列が集中するため、この負荷依存配分が分離構成を実用化する。

### 動的役割切替
オンライン負荷が変化すると、事前に選んだ比率も外れる。EPDは各段階の待ち行列を監視し、インスタンスをE/P/D間で役割変更する。移行元は新規受付を止め、未処理要求を同段階の他インスタンスへ再配分し、必要ならモデル・キャッシュ種別を切り替えて移行先として再開する。

PとDはLLM重みとKVキャッシュを共有できるため切替が軽く、Eを含む切替ではMMEとの重み交換が必要になる。論文では役割切替は通常0.7秒未満で、全システム再初期化と進行中要求の再実行を避ける。

## 評価条件
|項目|内容|
|---|---|
|モデル|MiniCPM-V 2.6、InternVL2-8B、InternVL2-26B|
|比較|vLLM型単体構成、LMM対応へ拡張したDistServe型P/D分離|
|負荷|合成画像負荷、NextQA動画QA|
|オンライン評価|100要求、ポアソン到着、代表条件で出力10トークン|
|画像条件|代表実験で2/4画像、4032×3024、追加で6/8画像|
|NextQA|100例、8フレーム/動画、平均入力11.42、平均出力2.75トークン|
|指標|TTFT、出力トークン間時間、SLO達成率、グッドプット、ピークメモリ|

## 主要結果
|条件・指標|結果|意味|
|---|---|---|
|ピークメモリ|最大15倍削減|段階に不要な重み・キャッシュを外す容量効果|
|最大バッチ|最大22倍|空きメモリを同時処理へ変換|
|画像/要求|最大10倍|符号化専用資源で高画像数要求を収容|
|KV容量|最大2.2倍|D/P側の空き容量をKVへ利用|
|TTFT|最大約71%削減|符号化干渉の除去とIRPの効果|
|SLO達成率|一部高負荷でEPD 90%以上、ベースライン10%未満|単純平均遅延だけでなく尾部・待ち行列を改善|
|役割切替|通常0.7秒未満|負荷変化へ全再起動なしで追随|

InternVLはMiniCPM-Vより画像トークンが多くプリフィル支配になりやすいため、要求率上昇時の待ち行列が強い。これは分離だけで無限に伸びるわけではなく、EだけでなくP側資源も適切に増やす必要があることを示す。NextQAでもEPDだけが低要求率で90% SLO達成を満たす条件が報告され、合成画像だけに限定した効果ではない。

## 既存研究との差
Splitwise、DistServe、MooncakeなどはLLMのP/D分離を主対象にするため、LMM固有の符号化器をP側へ同居させたままになる。Inf-MLLMなどは単一GPUのマルチモーダル推論を軽量化するが、クラウドサービングでE/P/Dを独立に資源配分する問題を扱わない。EPDは符号化を第三の独立段階として切り出し、視覚トークン移送、要求内並列、構成探索、役割切替まで一つのサービング系へ接続する。

## 限界
分離はEPとPDの二種類のネットワーク転送を追加するため、高速なNVLink/InfiniBandがない環境では通信が利得を削る。IRPは複数パッチを独立処理できるMME構造と複数画像・フレーム負荷で特に有効で、軽い単一画像要求では余地が小さい。構成探索は履歴負荷とシミュレータに依存し、急激な分布変化には動的役割切替で追随する必要がある。報告された最大値はモデル・画像数・SLO条件ごとに異なり、すべてが同一構成で同時に達成される値ではない。
