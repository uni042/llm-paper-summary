# Same Request, Different Answer: Quantization Amplifies Cache-Induced Divergence in LLM Serving

> 接頭辞キャッシュは要求外のサーバ状態を出力へ持ち込み、エージェント軌跡差を16ビット36.2%から4ビット75.0%へ増幅することを制御実験で確認。
## 書誌情報
- **著者**: Aditi Patodiya
- **公開**: arXiv preprint arXiv:2609.04748v1; submitted to IEEE
- **種別**: arXivプレプリント・IEEE投稿中
- **対象**: 接頭辞キャッシュ、再現性、量子化、決定性、エージェント推論
- **実装**: 実験harness、リクエスト log、server-reported キャッシュ exposure、解析パイプラインをartifactとして公開すると記載。
## 概要
接頭辞キャッシュを透過的な高速化とみなした場合の再現性コストを、llama.cppとvLLM、16ビットから3ビットまでの重み形式、80件の複数ターン道具利用エージェントで制御測定する。キャッシュ無効時は10構成800エピソードの反復が完全一致した一方、キャッシュ経路と再計算経路の軌跡差はQwen2.5-7Bで16ビット36.2%、4ビット75.0%へ増幅した。キャッシュ状態を復元すると各経路は40/40で再現しつつ経路間では14/40が異なり、実用上の非再現性は要求に含まれないサーバ状態への依存であると示す。これは単なる数値誤差の観測ではなく、同一入力を後日再実行したときにサーバ履歴の違いだけで道具呼出しや後続会話が変わり得ることを意味する。監査や障害再現を必要とする運用では、モデル名と乱数種だけでなく、キャッシュ設定、サーバ寿命、状態初期化条件まで実験記録へ含める必要がある。

本研究の新規性は、既知の浮動小数点非結合性を再発見することではなく、キャッシュ以外の非決定要因を除いた対照実験で、その影響を複数ターンの道具利用エージェント、二つの独立推論基盤、複数重み精度へ拡張して定量化した点にある。各構成をキャッシュ有効・無効で二回ずつ完全反復し、無効側が800エピソードすべて完全一致することを内部対照にする。さらに実行順、llama.cppのサーバ水準プロンプトキャッシュ設定、キャッシュ状態復元を個別に操作し、『キャッシュ経路自体がランダム』ではなく『要求に含まれないキャッシュ状態まで固定すれば決定的』という原因を分離する。量子化精度を16ビットから3ビットまで順序付けて軌跡差の増幅を測り、平均精度ではなく個別結果の不安定性を評価軸に加える。

代表結果として、キャッシュ-off反復発散は10 configurationsで同一キャッシュ-off run repetitionに対して0/800 episodes、95%上限0.5%。sampling、batching、一般的engine noiseは観測差を説明しない。
## 問題設定
接頭辞キャッシュは同じ先頭文脈のキー・バリューを要求間で再利用し、初回トークン時間と計算費用を削減するため主要な推論基盤で既定有効になっている。通常は再計算を省くだけの透明な最適化と考えられるが、キャッシュ経路と再計算経路では浮動小数点の加算順序が変わり、低位ビットの差がトークン決定境界を越える可能性がある。単一ターンなら小さな文面差でも、エージェントでは変更されたトークンが道具呼出し、次の観測、後続プロンプトを変え、軌跡全体へ増幅する。さらに実運用では低ビット重みが多用されるが、量子化がこのキャッシュ由来差をどの程度増幅するか、サーバ内に残るキャッシュ状態が反復実行の再現性へどう影響するかは体系測定されていなかった。

## 手法
### 手法のあらまし
主実験はBerkeley Function Calling Leaderboardの複数ターン基礎カテゴリから識別子順に80エピソードを固定選択し、Qwen2.5-7B/14BとLlama-3.1-8Bをllama.cppおよびvLLMで実行する。温度0、乱数種42、バッチ1、要求直列という条件で、モデル重み、要求順、復号条件、ハードウェアを固定し、接頭辞キャッシュだけを有効・無効にする。各セルを二回完全実行して、同じ側の反復差と有効・無効間の差を分離する。キー・バリューキャッシュ自体は全構成16ビットに固定し、重みだけをF16、Q8_0、Q4_K_M、Q3_K_Mへ変えることで量子化の交絡を避ける。llama.cppでは各応答のキャッシュ済みトークン数を記録し、vLLMでは起動ログのキャッシュ有効化と命中率で操作を確認する。軌跡差は要求列を同期走査し、最初に異なるプロンプト、出力トークン識別子、要求数の差を検出したエピソードを発散として数える。原因分離ではQwen2.5-7B Q4_K_Mを使い、キャッシュ有効パス同士を隣接実行するか途中に無効パスを挟むか、llama.cppの8GiBサーバ水準プロンプトキャッシュを既定か無効にするかを交差させる。さらに40項目を再計算2回・キャッシュ命中2回で実行し、各再計算前に冷状態を復元して各経路内再現性と経路間差を同時に測る。単一ターン橋渡しとしてGSM8Kを各項目4回実行し、各経路が自己一致した項目だけで経路間出力差と正誤反転を集計する。割合はWilson区間、状態依存のある主要構成では移動ブロックブートストラップも併用し、量子化傾向はCochran–Armitage検定、正誤反転の方向性は正確McNemar検定で評価する。

### 反復付きキャッシュ対照実験
各モデル・重み形式・推論基盤について、接頭辞キャッシュ無効の全80エピソードを二回、同じく有効を二回実行する。これにより有効対無効という通常の比較だけでなく、無効対無効、有効対有効という自己比較が得られる。温度0、固定乱数種、バッチ1、直列要求にして連続バッチや要求並べ替えを排除し、無効側が10構成800エピソードで完全一致することを確認する。この内部対照があるため、有効側の差を一般的なGPU非決定性や乱数へ帰属せず、キャッシュに関連する状態変化へ絞り込める。さらに各エピソードの要求列を順番に照合し、最初に異なる要求位置と出力トークン位置まで記録するため、単なる最終回答差だけでなく差が軌跡のどこで発生し後続へ伝播したかを追跡できる。キャッシュ無効側が完全一致するという否定対照は、後続の量子化比較と状態操作すべての因果解釈を支える基準になる。

### 量子化精度の独立操作
Qwen2.5-7BではF16、Q8_0、Q4_K_M、Q3_K_Mを順に比較し、Llama-3.1-8Bでも複数量子化形式を測る。一方でキー・バリューキャッシュの保存精度は全て16ビットへ固定するため、観測された勾配はキャッシュ自体の量子化ではなく重み量子化がトークン境界の余裕へ与える影響として解釈できる。キャッシュ経路と再計算経路の差はF16でも存在するので量子化は原因ではなく増幅器であり、4ビット以下では増幅が飽和するという非単調な境界まで測る。Qwen2.5-7Bでは有効対無効差が36.2%、61.3%、75.0%、77.5%と増え、順序傾向の検定でも有意になる。さらにサーバ水準プロンプトキャッシュを無効にした制御条件でも16ビット40.0%、4ビット81.2%、3ビット77.5%となるため、初期測定に含まれた別キャッシュ層の影響だけではこの精度勾配を説明できない。

### サーバ状態原因分離実験
llama.cppには要求単位の接頭辞キャッシュとは別に、会話状態をホストメモリへ保持し類似接頭辞で選ぶサーバ水準プロンプトキャッシュがある。これを既定の8GiBから無効へ変える以外を固定すると、キャッシュ有効反復の発散が38.8%から1.2%へ低下する。さらに二つの有効パスの間へ無効パスを挟む順序操作は、このサーバ水準層が有効なときだけ38.8%から77.5%へ増幅し、無効時は1.2%のままである。したがって実行順そのものではなく、順序が書き換えるサーバ状態が原因であることを切り分ける。

### キャッシュ状態復元による決定性検証
40項目について再計算経路を二回、キャッシュ命中経路を二回実行し、再計算前には冷状態を明示的に再確立する。キャッシュ済みトークン数が冷要求では0、暖要求では正であることも計測して操作を確認する。この条件では再計算経路は40/40、キャッシュ経路も40/40で自己一致する一方、二経路同士は14/40で異なる。つまりキャッシュ経路は本質的な乱数源ではなく、同じキャッシュ状態なら決定的である。実運用で再現しないのは、その状態が要求に記録されずサーバ履歴で変わるためである。vLLMでも毎回新しいサーバを起動して空状態から始めると有効側の反復差が0/80になり、同じプロセスを継続すると7/80や22/80へ増えるため、異なる実装でもサーバ寿命と状態保持が同じ方向へ作用する。これにより『キャッシュを使うと必ず確率的になる』のではなく、『再現に必要な状態がAPI契約の外へ隠れている』という運用上の問題として整理できる。

### 軌跡・結果分離評価
複数ターンエージェントでは最初のトークン差が後続の道具呼出しと観測を変えるため、要求単位だけでなくエピソード全体の軌跡差を測る。これとは別にGSM8Kで各項目を冷2回・暖2回実行し、各経路が自己一致した場合だけキャッシュ由来差と認定する。低ビットでは出力文面が約41.5～48.0%変わる一方、正誤反転は両方向に起き、1300 distinct itemsで13件がキャッシュ側有利、7件が再計算側有利となる。平均精度が変わらなくても個別項目の再現性は失われるため、品質低下と不安定性を別指標として扱う。

### 全体のデータ／制御の流れ
サービング基盤を『要求だけの関数』ではなく『要求と隠れたキャッシュ状態の関数』として捉え直し、同一入力反復、キャッシュ有無、状態復元、量子化精度という操作を段階的に組み合わせて、数値差、状態依存、エージェント軌跡、最終正誤を切り分ける実証設計である。
## 評価条件
- **ハードウェア**: NVIDIA RTX 4090 24GB、Ubuntu 24.04、CUDA 12.6、driver 570.211.01 / controlled experiments 580.126.20
- **データセット／トレース**: Berkeley Function Calling Leaderboard multi-turn base 80 episodes、GSM8K 200～500 items
- **比較対象**: prefix キャッシュ disabled recomputation path、prefix キャッシュ enabled path、llama.cpp server prompt キャッシュ default/disabled、fresh server vs persistent server
7～14B公開モデル、単一RTX 4090、英語の一つのエージェントベンチマークと数学ベンチマークに限定される。フロンティア規模、複数利用者の共有キャッシュ、他GPU、他言語では発散率が異なる可能性がある。
## 主要結果
キャッシュ無効の反復は10構成800エピソードで0件の差となり、他の非決定要因を0.5%以下へ抑える。一方Qwen2.5-7B llama.cppの有効対無効軌跡差はF16 36.2%、Q8_0 61.3%、Q4_K_M 75.0%、Q3_K_M 77.5%へ増え、量子化傾向はp=1.3×10^-8。llama.cppの別サーバ水準プロンプトキャッシュを無効化すると有効側の反復差は38.8%から1.2%へ低下する。状態復元時は冷・暖経路が各40/40で自己一致しつつ14/40で互いに異なる。GSM8Kでは低ビットで出力差が41.5～48.0%に達するが平均正解率の方向性は変わらない。

- キャッシュ-off反復発散 / 0/800 episodes、95%上限0.5% (比較対象: 同一キャッシュ-off run repetition; 条件: 10 configurations) — sampling、batching、一般的engine noiseは観測差を説明しない。

- Qwen2.5-7B cross-arm divergence / 36.2% F16 → 61.3% Q8_0 → 75.0% Q4_K_M → 77.5% Q3_K_M (比較対象: キャッシュ-off vs キャッシュ-on; 条件: llama.cpp、80 episodes each) — 量子化は原因ではないがキャッシュ由来摂動を強く増幅する。

- server prompt-キャッシュ effect / 38.8% → 1.2% (比較対象: default vs disabled; 条件: Qwen2.5-7B Q4_K_M キャッシュ-on repetition) — 一つのサーバ設定が反復再現性を37.5ポイント動かす。

- キャッシュ-state reset control / cold 40/40、warm 40/40 self-identical、cross-path 14/40 different (比較対象: restored キャッシュ state; 条件: Qwen2.5-7B Q4_K_M) — 各経路は状態を固定すれば決定的で、実用上の非再現性は隠れた状態依存。

- GSM8K Q4_K_M cross-path output divergence / 45.4% (比較対象: cold vs warm; 条件: Qwen2.5-7B、500 items) — 単一ターンでも低ビットでは文面差が大きい。

- GSM8K correctness flips / 20/1300 distinct items; キャッシュ wins 13, recompute wins 7, p=0.26 (比較対象: cold vs warm correctness; 条件: five distinct configurations) — 不安定性はあるが平均精度の有意な方向性はない。

### 負の結果・境界条件
- 量子化なしF16でも36.2%のagent trajectory差があり、量子化だけを原因にはできない。
- Q4_K_MとQ3_K_Mの発散率は近く、4bit以下で増幅は飽和する。
- agent ベンチマークは正解率1.2～18.8%と床が低く、最終task successへの方向性は判断できない。
- vLLMで同じ方向は再現するがsessionごとのrun-to-run divergenceは8.8%と27.5%で幅があり、差の要因は未分離。

### 結果の読み方
キャッシュ-enabled servingはランダムなのではなくリクエストとキャッシュ stateの決定的関数である。しかしキャッシュ stateはリクエストに含まれずresponseにも十分記録されず、通常run境界でresetされないため、利用者から見ると同一リクエストが再現しない。監査、デバッグ、A/B評価ではキャッシュ configurationとstate exposureを実験条件として扱う必要がある。
## 品質への影響
平均精度低下ではなくrepeatabilityの喪失。個別項目の正誤は両方向へ反転し、集計精度では相殺される。
## 既存研究との差
既存の単一ターン十六ビット浮動小数点研究がキャッシュ経路と再計算経路の数値非等価性を示したのに対し、本研究は二種類の実推論基盤、複数ターンの道具利用エージェント、三～十六ビット重み、サーバ状態の復元実験を加え、発散頻度と運用上の原因を測る。量子化研究が平均精度を主指標にするのに対し、平均精度が同じでも個別項目の出力が入れ替わる不安定性を独立した品質軸として扱う。
## 限界
- 七十億～百四十億規模の公開重みモデルと単一の民生向け高性能画像処理装置に限定され、大規模な商用提供モデルは未評価である。
- エージェント負荷は一種類で課題成功率が低く、エージェント最終成功率への方向性は結論できない。
- 複数利用者の同時トラフィックで他利用者がキャッシュ状態を書き換える条件は測定していない。
- 一方の推論基盤のセッション間に見られる発散率差について、画像処理装置メモリ割当率、駆動ソフトウェア、起動手順などの寄与を完全には分離できていない。
- トークン発散は意味的に同等な言い換えも差として数えるため、再現性指標には適切だが意味品質そのものの指標ではない。
## 実装状態
実験ハーネス、要求ログ、キャッシュ露出量の計測情報、解析処理系を公開し、保存済み応答から全数値を再生成可能とする。二種類の実サーバを使う実測研究であり、シミュレーションではない。
## 研究上の位置づけ
大規模言語モデルサービングのサービス水準目標を遅延・処理量だけでなく再現性まで拡張する研究である。キャッシュを無効化する必要はなく、状態を実行境界で復元し設定を固定・記録すれば、性能利益を残しながら反復再現性を改善できるという運用上の示唆を与える。
