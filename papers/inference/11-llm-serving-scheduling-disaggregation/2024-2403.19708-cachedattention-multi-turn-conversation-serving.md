# Cost-Efficient Large Language Model Serving for Multi-turn Conversations with CachedAttention

> multi-turn conversationのhistory KVをDRAM / SSDへ階層保存し、次turnでlayer-wise preloadして再利用することで、history再prefillを避けつつ低速storage accessをGPU計算へ重ねるstateful serving手法。

## 概要

multi-turn conversationでは、次turnのpromptが前turnまでのhistoryをほぼそのまま含むため、stateless servingは同じhistory tokenのKV cacheを毎回再計算する。ShareGPTを使った分析では、長い会話になるとprefill costの最大99%がこの重複計算になり得る。

CachedAttentionは、request終了時にKV cacheを捨てず **AttentionStore** と呼ぶ階層cacheへ保存し、次turnで再利用する。GPU memoryだけでは全sessionを保持できないため、DRAMやSSDを含む低cost tierへstateを置き、必要になる前にlayer単位でpreloadする。

単なるKV保存ではstorage accessが新しいbottleneckになるため、schedulerが次に実行するsessionを知っていることを利用したprefetch / eviction、asynchronous save、position encodingをcacheから切り離す工夫を組み合わせる。

## 問題設定

multi-turn servingでKV reuseを実用化するには、以下を同時に解く必要がある。

- 全sessionのKVをGPUへ常駐させられない
- DRAM / SSDからKVを戻すとTTFTが増える
- request終了時の大量KV saveが次requestのGPU executionを邪魔する
- schedulerがsessionを実行する直前までcache placementが最適でない場合がある
- context window overflowで古いtokenをtruncateするとRoPE等のposition依存KVが無効化される

## 手法

### 1. AttentionStoreによるhierarchical KV reuse

各sessionの過去KVをGPU外のDRAM / SSDにも保存し、次turnでhistoryを再prefillする代わりに読み戻す。

GPUはactiveなsessionのfast tier、DRAM / SSDはinactive sessionを保持するcapacity tierとして使う。

### 2. Layer-wise pre-loading

session全体のKVをGPUへ読み終わるまで待つのではなく、**次に必要なlayerのKVだけ先にloadし、現在layerのGPU計算と次layerのtransferを重ねる**。

これによりslow tierからのaccess latencyをprefill計算の裏へ隠す。

### 3. Asynchronous saving

request終了時のKV saveもGPU execution pathで同期的に待たず、次のinferenceと重ねてbackgroundでDRAM / storageへ退避する。

### 4. Scheduler-aware fetching / eviction

一般的なLRUは過去のaccessだけを使うが、LLM serving schedulerは「次にどのrequest / sessionをbatchへ入れるか」を知っている。

CachedAttentionはこのfuture hintをcache managerへ渡し、近く実行されるsessionのKVをfast tierへ先回りして配置し、直近で使わないstateを遅いtierへ追い出す。

### 5. Positional encoding decoupling

context windowを超えたconversationでは古いtokenをtruncateする必要がある。位置情報がKVへ直接焼き込まれていると、残ったKVのpositionが変わった時にcacheが無効になる。

CachedAttentionはposition encodingの扱いをKV生成から切り離し、truncation後も保存済みKVの主要部分を再利用できるようにする。

## 評価

USENIX ATC 2024版では、multi-turn conversation workloadで以下を報告する。

- TTFT: 最大 **87%削減**
- prompt prefilling throughput: 最大 **7.8×向上**
- end-to-end inference cost: 最大 **70%削減**

長いhistory・turn数の多いsessionほど、stateless baselineで重複prefillが増えるため効果が大きくなる。

またlayer-wise preloadとasynchronous saveにより、単純にKVをSSD / DRAMへ保存するだけの方式よりstorage access overheadを抑えられることを示す。

## 既存研究との差

### Pensieveとの違い

Pensieveもmulti-turn sessionのKVをGPU / CPU tierへ保持してrequest間reuseする。

CachedAttentionは同じ問題設定をさらに広げ、**DRAM / SSDを含むhierarchical storage、scheduler-aware placement、context truncation後もcacheを有効に保つposition encoding処理**を明確な設計要素として持つ。

### vLLMとの違い

vLLMのPagedAttentionは1 request実行中のKV allocationを効率化する。CachedAttentionはrequest終了後もsession stateを保存し、次turnで再利用することが中心である。

### KV Cache Offload系との違い

single long requestのHBM不足を解消するためのKV offloadではなく、**session間のidle期間をまたいでstateを保存し、future requestの重複計算をなくす**ことが主目的なのでServing系統に分類する。

## 限界

- 利得はmulti-turn / repeated-history workloadに依存し、独立requestでは小さい。
- session catalogとhistoryが非常に大きい場合、SSD capacity / bandwidthとcache evictionがbottleneckになる。
- slow-tier hitは再計算より速い必要があり、model・context長・storage性能によってbreak-evenが変わる。
- scheduler-aware prefetchは将来の実行順が大きく変わると外れる可能性がある。
- positional encoding decouplingはmodel architecture依存で、すべてのposition encoding方式へ同じ形で適用できるとは限らない。

## 一般的な実装上の含意

multi-turn workloadではKV reuseの価値は単なるGPU memory optimizationではなく、**過去turnのprefill計算そのものをstorage accessへ置き換えること**にある。

このため最適なtierは常にGPUとは限らず、「再計算時間」と「DRAM / SSDからのload時間」を比較してstateを残す価値を決める必要がある。

またserving schedulerのqueue情報はcache managerにとって有用なfuture hintになるため、request schedulingとmemory hierarchyを独立に設計するより協調させた方がよい。
