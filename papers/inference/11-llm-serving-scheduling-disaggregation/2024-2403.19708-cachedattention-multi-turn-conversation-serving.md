# Cost-Efficient Large Language Model Serving for Multi-turn Conversations with CachedAttention

> 複数ターン会話の過去KVを要求終了後もDRAM / SSDへ保存し、次ターンで使う層のKVを少し前からGPUへ戻すことで、履歴全体の再プリフィルと記憶装置待ちを減らす状態保持型推論提供手法。

## 概要

複数ターン会話では、次ターンのプロンプトが前ターンまでの履歴をほぼそのまま含むため、状態なし型推論提供は同じ履歴トークンのKVキャッシュを毎回再計算する。ShareGPTを使った分析では、長い会話になるとプリフィルコストの最大99%がこの重複計算になり得る。

CachedAttentionは、要求終了時にKVキャッシュを捨てず、**GPU・CPU DRAM・SSDをまたぐ会話用キャッシュへ保存し、次ターンで再利用する**。

GPUメモリだけでは全セッションを保持できないため、最近使う状態だけGPUへ置き、しばらく使わない会話のKVはDRAMやSSDへ移す。次ターンが近づいたら必要なKVをGPUへ戻す。

単に保存するだけではSSD / DRAMからの読込が新しい待ち時間になるため、**次にどのセッションを実行するかというスケジューラ情報を使って先読みし、GPU計算と記憶装置転送を重ねる**のが重要になる。

## 問題設定

複数ターン推論提供でKV再利用を実用化するには、以下を同時に解く必要がある。

- 全セッションのKVをGPUへ常駐させられない
- DRAM / SSDからKVを戻すとTTFTが増える
- 要求終了時の大量KV保存が次要求のGPU実行を邪魔する
- スケジューラがセッションを実行する直前までキャッシュ配置が最適でない場合がある
- 文脈窓あふれで古いトークンを削ると、位置符号化の扱いによっては保存済みKVをそのまま再利用できない

## 手法

### 1. GPU / DRAM / SSDを会話KVの3段階の置き場として使う

各セッションの過去KVをGPU外のDRAM / SSDにも保存し、次ターンで履歴を再プリフィルする代わりに読み戻す。

- GPU: 近く使う実行中セッション向けの高速階層
- DRAM: GPUより遅いが大容量の中間階層
- SSD: さらに遅いが多数セッションを保持できる大容量階層

論文の注意機構保存は、この複数メモリ階層をまとめて会話 KVキャッシュとして扱う仕組みである。

### 2. セッション全体を待たず、次の層のKVだけ先に戻す

次ターン開始時に全層のKVをGPUへ読み終わるまで待つのではなく、**現在層をGPUで計算している間に次層で使うKVをDRAM / SSDからGPUへ運ぶ**。

論文の層ごとの事前読み込みはこの先読みを指す。記憶装置からの転送をGPU計算の裏へ隠すことで、低速階層を使ったときの追加遅延を減らす。

層単位にするのは、全KVを一括で戻すより必要な先行量を小さくできるためである。層 `l` を計算している間に層 `l+1` のKVだけを転送できれば、GPUには次に使う分だけを用意すればよく、セッション全体のKVがGPUへ揃うまで開始を待つ必要がない。逆に記憶装置帯域が遅すぎて1層の計算時間内に次層KVを供給できない場合は転送待ちが表面化するため、保存階層を選ぶ際には再計算時間だけでなく層ごとの供給速度も見る必要がある。

### 3. 要求終了時のKV保存も次のGPU処理と重ねる

要求終了時に全KVが保存し終わるまでGPU側処理を止めず、次の推論と並行してDRAM / SSDへ書き出す。

論文の非同期保存は、**KV保存を前景の重要な経路から外す**ための仕組みである。

### 4. 「次に実行するセッション」をキャッシュ管理器へ教える

一般的なLRUは過去のアクセスだけを見てキャッシュを追い出すが、LLM推論提供スケジューラは次にバッチへ入れる要求 / セッションをある程度知っている。

CachedAttentionはこの情報をキャッシュ管理器へ渡し、

- 近く実行されるセッションのKVはGPUへ先に戻す
- すぐ使わないセッションはDRAM / SSDへ出す

ようにする。

つまりスケジューラを考慮した取得 / 追い出しは、**未来の実行順をキャッシュ置換の手掛かりに使う**ことを意味する。

### 5. 古いトークンを削っても残りKVを再利用しやすくする

会話が文脈上限を超えると、古いトークンを削る必要がある。RoPEなどではトークン位置がアテンション計算へ影響するため、実装方法によっては位置が変わると保存済みKVをそのまま使いにくい。

CachedAttentionは位置符号化の適用をKV保存形式からできるだけ切り離し、**古い接頭部を切り詰めした後も残った履歴 KVを再利用できるようにする**。

## 評価

USENIX ATC 2024版では、複数ターン会話ワークロードで以下を報告する。

- TTFT: 最大 **87%削減**
- プロンプトプリフィルスループット: 最大 **7.8×向上**
- エンドツーエンド推論コスト: 最大 **70%削減**

長い履歴・ターン数の多いセッションほど、状態なし型比較対象で重複プリフィルが増えるため効果が大きくなる。

また層ごとの先読みと非同期保存により、単純にKVをSSD / DRAMへ保存するだけの方式より記憶装置アクセスオーバーヘッドを抑えられることを示す。

## 既存研究との差

### Pensieveとの違い

Pensieveも複数ターンセッションのKVをGPU / CPUへ保持して要求間再利用する。

CachedAttentionは同じ問題設定をさらに広げ、**SSDまで含む多段記憶装置、スケジューラの次実行情報を使った先読み、文脈切り詰め後もKVを再利用する位置処理**を明確な設計要素として持つ。

### vLLMとの違い

vLLMのPagedAttentionは主に1要求実行中のKV割り当てを効率化する。CachedAttentionは要求終了後もセッション状態を保存し、次ターンで再利用することが中心である。

### KVキャッシュオフロード系との違い

単一 long要求のHBM不足を解消するためのKVオフロードではなく、**セッション間のアイドル期間をまたいで状態を保存し、将来要求の重複計算をなくす**ことが主目的なので推論提供系統に分類する。

## 限界

- 利得は複数ターン / 繰り返し履歴ワークロードに依存し、独立要求では小さい。
- セッション一覧と履歴が非常に大きい場合、SSD容量・帯域とキャッシュ追い出しがボトルネックになる。
- 低速階層ヒットは再計算より速い必要があり、モデル・文脈長・記憶装置性能によって「保存して読む方が得か、再計算した方が得か」の境界が変わる。
- スケジューラを考慮した先読みは将来の実行順が大きく変わると外れる可能性がある。
- 位置符号化の分離はモデル構成依存で、すべての位置符号化方式へ同じ形で適用できるとは限らない。

## 一般的な実装上の含意

複数ターンワークロードではKV再利用の価値は単なるGPUメモリ最適化ではなく、**過去ターンのプリフィル計算そのものを記憶装置アクセスへ置き換えること**にある。

このため最適な階層は常にGPUとは限らず、「再計算時間」と「DRAM / SSDからの読み込み時間」を比較して状態を残す価値を決める必要がある。

また推論提供スケジューラの待ち行列情報はキャッシュ管理器にとって有用な将来手掛かりになるため、要求スケジューリングとメモリ階層を独立に設計するより協調させた方がよい。
