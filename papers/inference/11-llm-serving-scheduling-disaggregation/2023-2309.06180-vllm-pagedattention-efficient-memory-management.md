# Efficient Memory Management for Large Language Model Serving with PagedAttention

> vLLMは、要求ごとに大きな連続領域を予約していたKVキャッシュを固定長ブロックへ分解し、論理的な並びとGPU上の物理配置を分離する。必要なブロックだけ動的に割り当て、同じ接頭辞のKVを共有することで、限られたGPUメモリへより多くの要求を同時に載せる。

## 概要
LLMサービングでは、モデル重みだけでなく各要求が生成中に保持するKVキャッシュが大きなGPUメモリを占める。論文の例ではA100 40 GB上で13Bモデルを扱うと、モデル重みが約65%を占め、KVキャッシュなど要求ごとの動的状態にも30%近い領域が必要になる。したがって、計算器が空いていてもKVキャッシュが入らなければバッチを増やせない。

従来方式は深層学習フレームワークの連続テンソル管理に合わせ、要求ごとに最大系列長を想定した連続メモリを予約することが多かった。しかし出力長は実行前には分からず、多くの要求は予約上限まで生成しない。このため「将来使うかもしれない予約領域」、割当単位内部の余り、異なるサイズの領域を出し入れして生じる外部断片化が重なる。

vLLMはこの問題を、OSの仮想記憶とページングに似た構造で解く。PagedAttentionではKVを固定数トークン単位のブロックへ分け、系列から見える論理ブロック番号を、GPU上の任意の物理ブロックへ対応付ける。連続した系列だからといって、物理メモリまで連続である必要をなくすことが核心である。

## 問題設定
自己回帰生成では、1トークン増えるたびにK/Vが追加され、終了すると要求全体のKVが解放される。つまり必要量は時間とともに伸び、要求ごとの寿命も長さも事前には確定しない。この性質は、形状がほぼ固定された通常の推論テンソルと異なる。

論文のプロファイルでは、従来方式でKVキャッシュ用に確保した領域のうち、実際のトークン状態に使われている割合が20.4～38.2%にとどまる条件があった。残りがすべて同じ種類の無駄ではないが、予約、内部断片化、外部断片化によって、本来なら別要求を入れられるGPUメモリが使えなくなる。

さらに並列サンプリングやビーム探索では、複数候補が同じプロンプトや途中まで同じ系列を共有する。連続領域を候補ごとに複製すると、内容が同一のKVまで重複保持するため、複雑なデコードほどメモリ効率が悪化する。

## 手法

### 1. 論理KVブロックと物理KVブロックを分離する
各系列のKVキャッシュを、固定数トークンを収容する**論理ブロック**の列として表す。系列が新しいトークンを生成し、現在の末尾ブロックが満杯になったときだけ、ブロック管理器が空いている**物理ブロック**を1つ割り当てる。物理ブロックはGPUメモリ上のどこにあってもよい。

系列ごとに持つブロック表が「論理ブロック0は物理ブロック7、論理ブロック1は物理ブロック1」のような対応を記録する。Attentionカーネルはこの表を参照して必要なK/Vを読み込むため、系列全体を1本の連続テンソルとして配置する必要がない。

この方式では、固定サイズの物理ブロックを共通プールから割り当てるので、異なる大きさの連続領域を確保・解放することで生じる外部断片化を除ける。内部断片化も原則として各系列の最後の未充填ブロックだけに局所化されるため、最大系列長全体を先に予約する方式より小さくなる。

### 2. PagedAttentionで非連続KVをそのままAttentionへ使う
メモリをページ化するだけでは、既存のAttentionカーネルが連続したK/Vを前提としていれば、計算前に再び連続領域へ集め直す必要が生じる。そこでPagedAttentionは、ブロック表から複数の物理ブロックを直接たどりながらAttentionを計算する。

入力は現在トークンのQueryと、その系列が参照する物理KVブロック一覧である。カーネルはブロック単位でK/Vを読み、各ブロックに対するAttention計算を進める。論理的には通常のAttentionと同じ系列を参照するので、KVの内容を近似・圧縮しているわけではない。

代償として、物理アドレスの間接参照と非連続アクセスが増える。vLLMはブロック読み込みをGPU上で並列化し、メモリ参照処理をAttention側へ統合することでこのオーバーヘッドを抑える。つまり高速化の源泉はAttention演算そのものを減らすことではなく、追加の間接参照コストよりも、節約したメモリでバッチを大きくできる利得が上回る点にある。

### 3. KVをブロック単位で共有し、書き込み時だけ複製する
並列サンプリングでは、同じプロンプトから複数の出力候補を生成する。vLLMは各候補の論理ブロックを同じ物理ブロックへ対応付け、プロンプト部分のKVを1コピーだけ保持する。各物理ブロックには参照数を持たせ、何系列から共有されているかを管理する。

共有している末尾ブロックへ新しいトークンを書き込む必要が生じた場合だけ、書き込み時コピー（copy-on-write）を行う。共有物理ブロックを新しい物理ブロックへ複製し、その系列の論理ブロック対応だけを新しい方へ切り替える。共有していないブロックはそのまま更新できる。

ビーム探索では候補の親子関係が反復ごとに変わるが、ブロック対応と参照数を更新するだけで共通部分を共有し続けられる。大きなKVテンソルを候補間で何度も丸ごとコピーする代わりに、分岐して書き換えるブロックだけを複製すればよい。長い共通プロンプトほど節約効果が大きい。

### 4. メモリ不足時は要求単位でプリエンプトし、交換または再計算で復帰する
動的割り当てでも、到着率が高ければ物理KVブロックが枯渇する。vLLMは先着順（FCFS）を基本とし、プリエンプトが必要な場合は後から到着した要求を先に止める。同じ要求内の複数系列はKVを共有している可能性があるため、系列群としてまとめて扱う。

KVは各生成反復でその系列の全履歴を参照するため、一部の古いブロックだけを捨てて残りを実行することはできない。そこで論文版vLLMは、対象系列のKVブロックを**全部退避するか、全部残すか**の方針を採る。復帰方法として、GPUからCPUメモリへKVを交換する方法と、破棄して後からKVを再計算する方法の両方を実装している。

再計算では、これまで生成したトークンを元プロンプトへ連結し、プロンプト処理としてまとめてK/Vを作り直す。論文の比較では、小さいブロックでは多数の細かいPCIe転送が交換効率を下げるため再計算が有利になりやすく、大きいブロックでは交換が相対的に有利になる。メモリ管理方式と復帰方式が独立ではない点が重要である。

## ブロックサイズのトレードオフ
ブロックを小さくすると、各系列の末尾で余るKV量が減り、共有できる単位も細かくなる。一方でブロック表が長くなり、小さなメモリアクセスや転送が増え、GPUの並列性やPCIe帯域を十分使いにくくなる。

逆にブロックを大きくすると管理は単純になるが、短い系列では最後のブロックに大きな未使用領域が残り、共有可能性も下がる。論文ではShareGPTとAlpacaでブロックサイズを比較し、多くの条件で16トークンを実用上の既定値として採用している。これは普遍的な最適値ではなく、系列長分布とハードウェアに依存する。

## なぜこの設計で速くなるのか
vLLMは1要求の1トークンを大幅に安くする研究ではない。主な因果関係は、**KVメモリの無駄を減らす → 同時に保持できる要求数が増える → 連続バッチ処理のバッチが大きくなる → GPUをより効率よく使える**という流れである。

このため利得は、長い系列、大きいモデル、並列サンプリングやビーム探索のようにKV容量・共有機会が大きい条件ほど増えやすい。反対にKVが小さく、もともと計算律速で十分大きなバッチを組めているワークロードでは、ページ表参照の追加コストに対する利得は小さくなる。

## 評価
主な評価はNVIDIA A100上のOPT-13B、66B、175Bなどを用い、ShareGPTとAlpaca由来の要求長分布で行う。比較対象にはFasterTransformerとOrcaが含まれ、同程度の遅延となる条件で受け入れ可能な要求率・スループットを測る。

論文全体では、既存方式に対して**同程度の遅延で2～4倍のスループット**を報告する。改善は長い系列、大きいモデル、複雑なデコード方式で大きい。これはPagedAttentionカーネルだけの速度倍率ではなく、メモリ効率向上によって同時実行数を増やしたサービング全体の結果である。

ShareGPTでは、出力長を事前に知る理想化Orca実装に対しても**1.7～2.7倍**高い要求率を維持した。OPT-13B / ShareGPTの例では平均同時要求数がOrca約13.6に対しvLLM約30.4で、節約したKV領域がより大きな連続バッチへ変換されていることが分かる。

## 既存研究との差
Orcaは反復単位スケジューリングによって、終了要求を外し新着要求を途中参加させる。しかし論文版Orcaは新規要求の最大K/V量を事前予約するため、柔軟に要求を混ぜるほどKV状態のメモリ効率が新しい制約になる。

vLLMはOrcaの細粒度スケジューリングと競合する発想ではなく、**より多くの要求の作業状態をGPUへ載せるためのメモリ管理**として補完する。KV圧縮のように値を削除・量子化するのではなく、同じKVを非連続配置・共有することで容量効率を改善する点も区別が必要である。

## 限界
非連続ブロックをたどるためのアドレス変換とメモリアクセス管理にはオーバーヘッドがある。KV容量がボトルネックでない計算律速ワークロードへ同じページ化を持ち込むと、同時実行数を増やす利得がないまま間接参照コストだけ増える可能性がある。

ブロックサイズは内部断片化、共有粒度、GPUアクセス効率、交換時のPCIe効率を同時に左右する。論文の16トークンという既定値を、異なるAttention構造・GPU・長文分布へ無条件に適用できるわけではない。

また評価モデルはOPT / LLaMA初期世代が中心で、現在のPagedAttention実装は論文後に大きく発展している。現在のvLLMの機能や性能を説明するときは、このSOSP 2023論文の実装・評価結果と最新ソフトウェアを分けて扱う必要がある。

## 一般的な実装上の含意
出力長が未知で寿命が要求ごとに異なる状態をGPUへ保持する場合、最大量を要求単位で予約するより、固定小ブロックを共通プールから必要時に割り当てる方が高密度に詰められる。LLMではこの状態がKVキャッシュだったため、OSのページングに近い抽象化が直接サービング容量へ効いた。

さらに、論理状態と物理配置を分離すると、共有、書き込み時コピー、プリエンプト、CPU退避、再計算を同じブロック管理の上で扱える。単なる断片化対策ではなく、動的な生成状態を統一的に管理する抽象化になった点がPagedAttention / vLLMの重要な意義である。
