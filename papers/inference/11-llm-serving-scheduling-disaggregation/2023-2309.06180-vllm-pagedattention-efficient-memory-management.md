# Efficient Memory Management for Large Language Model Serving with PagedAttention

> KV cacheを固定長blockへ分け、必要になった分だけGPU memoryを割り当てて複数sequence間でも共有し、未使用領域を減らして同時に処理できるrequest数を増やすvLLM serving system。

## 概要

vLLMは、LLM servingではGPUの計算能力だけでなく**KV cacheの置き方がbatch sizeを制限する**ことに注目した研究である。

従来方式ではrequestごとに最大sequence lengthを想定した大きな連続領域を先に確保することが多く、実際のoutputが短い場合の予約浪費やmemory fragmentationが大きい。

vLLMはKV cacheを固定token数のblockへ分け、各blockをGPU memory上の任意位置へ置ける **PagedAttention** を導入した。requestのKVを1つの連続領域に置く必要をなくし、新しいtokenが増えた時だけblockを追加する。また同じprefixを持つ複数sequenceでは共通KV blockを共有できる。

## 手法

### 1. KV cacheを固定長blockへ分ける

sequence側から見たblock順序と物理GPU memory位置を分離し、attention kernelがblock tableを使って必要なK/Vを読む。現在blockが一杯になった時だけ次blockを割り当てる。

### 2. 空きblockを共通poolとして管理する

schedulerがfree KV blockを管理し必要requestへ割り当てる。memory不足時にはrequestをpreemptし、KVをCPUへswapするか後で再計算する選択肢も持つ。

### 3. 同じprefixのKVを共有する

parallel samplingやbeam searchで分岐前のKV blockを共有し、書換えが必要になった時だけcopy-on-writeで新blockを作る。

## 評価

主な評価はA100上のOPT-13B / 66B / 175Bで、ShareGPTとAlpaca由来のrequest長を使用。論文では同程度のlatency条件で既存system比**2〜4倍のthroughput**を報告する。

ShareGPTではoutput長を事前に知る理想化Orca実装に対しても**1.7〜2.7倍**高いrequest rateを維持した。OPT-13B / ShareGPTでは平均同時request数がOrca約13.6に対しvLLM約30.4となり、KV memory効率化がcontinuous batch拡大へつながることを示した。

## 既存研究との差

Orcaがiteration-level schedulingでbatchを柔軟化したのに対し、vLLMは**KV memoryを必要量だけ確保・共有する仕組み**を加える。KV compressionとは異なり、KV内容を近似・削除・量子化せずmemory配置を効率化する。

## 限界

- 非連続blockを読むaddress lookup costがある。
- block sizeに内部fragmentationと管理costのtrade-offがある。
- 評価modelはOPT / LLaMA世代中心。
- cluster routingやprefill / decode分離は主題ではない。

## 一般的な実装上の含意

KV cacheを連続tensorとして予約せずpage化すると、unknown output length、preemption、beam search、prefix共有を同じmemory abstractionで扱える。servingでは節約したVRAMを追加requestへ使ってbatchを拡大できることがthroughput改善の核心となる。
