# ParVTS：視覚情報を質問トークンへ移してから背景経路を削る並列スケジューリング

## 概要

ParVTS（Parallel Vision Token Scheduling）は、高解像度画像を入力するマルチモーダル大規模言語モデル（MLLM）において、視覚トークンを一律に残すか捨てるかという二者択一を避ける推論時手法である。主体に対応する視覚トークンと、背景・周辺物体に対応する非主体トークンを視覚エンコーダの注意情報で分割する。初期Transformer層では双方の経路に質問トークンを置いて視覚情報を吸収させ、所定層で質問表現を融合する。その後は非主体の視覚経路を削除して、主体トークンと融合済み質問表現だけを処理する。モデルの再学習や追加の圧縮器は不要である。

原著Table 1では、LLaVA-1.5-7Bの576視覚トークンを64へ削減（88.89%削減）した条件で、複数ベンチマークの正規化平均品質が元モデルの92.45%となる。FastVとSparseVLMはいずれも78.64%であり、背景の情報を初期層で移しておくことが精度の差を生む。Table 5では、MMEスコアをおおむね揃えた別条件で、入力1件あたり285.17msから161.33msへの短縮（1.77倍）と、推定演算量8.48→2.57 TFLOPsを報告する。**92.45%という品質比と1.77倍の速度は異なる実験条件**であり、同じ1行の同時達成値ではない。

## 問題設定：視覚トークンの大半を消したいが、背景情報も必要

視覚言語モデルは画像を視覚エンコーダで多数のパッチ表現に変換し、言語モデルの質問トークンと連結して推論する。画像解像度が高いと、文章より視覚トークンがはるかに多くなり、入力処理（プリフィル）の注意演算量と後続のKVキャッシュ容量を押し上げる。LLaVA-1.5の576個、LLaVA-Nextの2880個という視覚トークン数は、短い質問に対して大きな計算負担となる。

従来のFastV等は、注意の重要度が低い視覚トークンを途中で直接削除する。人物の服装や物体の種類のような主体中心の質問では機能しても、背景看板の文字、透明なコップ、周辺物体の位置などを尋ねる質問では、削除したトークンの情報を取り戻せない。原著Figure 1の四つの視覚QAデータセットでは、主体以外に関わる質問が約19〜27%存在すると分析する。この比率は著者がLLaVA-1.5-7Bで質問を分類した結果であり、人手による完全な真値ラベルと同一ではない。

一方、初期の自己注意層では画像の情報が質問トークンの隠れ表現へ移る現象が知られている。背景トークンを最終層まで保持しなくても、早い段階で質問表現へその情報を移せれば、後半層の計算とKV保持を減らしつつ背景質問へ対応できる可能性がある。ParVTSはこの「情報移行」を、いつ、どのトークン群へ計算を割り当てるかというスケジューリング問題に変える。

## 手法

### 1. [CLS]注意による主体・非主体の分割

入力画像を視覚エンコーダへ通し、[CLS]トークンから各視覚パッチへの注意重みを取得する。上位k個を主体集合 `V_sub`、残りを非主体集合 `V_non` として分割する。ここで重要なのは、分類対象が「回答に必要なトークン」そのものではなく、視覚エンコーダから見た画像の中心的領域であることだ。背景の看板や周辺物体は、視覚的には非主体でも質問への回答には不可欠な場合がある。

kは保持予算であり、576個から64個へ削減する場合、主体集合は64個、非主体集合は512個となる。通常の重要度上位k個選択と違い、後者をすぐに捨てない。非主体集合は初期層で質問表現へ情報を移すための一時的な計算入力として使われる。この追加の初期層処理と主体・非主体の分類が本方式の費用である。

### 2. 逐次切替方式が失敗する理由

原著§3.2は、主体を先に処理して途中で背景へ切り替える方式（Sub-FS）と、その逆順（Non-Sub-FS）を検討する。Sub-FSは初期n層で主体の特徴を質問へ移した後、同じ視覚スロットへ未処理の背景埋め込みを挿入する。nが小さいと主体情報の移行が足りず、nを大きくすると背景が後半まで登場しないため質問との統合が遅れる。計算節約と意味情報の取得が衝突する。

Non-Sub-FSでは背景を先に処理して主体へ切り替える。しかし後から挿入した主体トークンは前半のTransformer層を通っていない浅い表現であり、既に高次の表現へ進んだ質問トークンとの意味空間がずれる。単に「前半は背景、後半は主体」と分割しても、必要な特徴の段階的精緻化が失われる。この二つの負例が、双方を初期層から並列に処理する設計の根拠となる。

### 3. 質問トークンを複製した並列初期層

ParVTSは初期n層で、システム・質問・主体視覚トークンからなる経路と、システム・質問・非主体視覚トークンからなる経路を同時に処理する。各経路の質問トークンは、自分の経路の視覚トークンへ自己注意を行い、主体情報または背景情報を隠れ表現に取り込む。原著の式(7)〜(9)は、この二つの経路の出力を `T_sub_n` と `T_non_n` として表す。

単純に二回のモデル実行を行うのではなく、バッチ次元で並列化し、さらに注意マスクを変更して主体と非主体の視覚トークンを互いに不可視にする。質問表現はそれぞれの視覚集合を参照する。この実装により、両経路の独立性を維持しつつ、GPU上で別々の全モデルを複製することを避ける。付録Bは**最初のTransformer層は全トークンを共同処理し、並列スケジューリングは第2層以降から有効**と明記する。図2の簡略化を、そのまま第1層から完全分離する実装と誤読してはならない。

### 4. 質問表現の融合と非主体経路の破棄

層nに達すると、主体経路と非主体経路の質問トークンを `T_fused = α T_non_n + β T_sub_n` で重み付き平均する。原著の標準設定は `α=β=0.5`。以降の状態は、主体経路のシステムトークン、主体視覚トークン、融合済み質問トークンから構成し、層n+1以降のTransformerを実行する。非主体視覚トークンとその経路はここで捨てる。

この設計は、背景情報を明示的に圧縮した別トークンへ格納するのではなく、質問トークンの隠れ状態を情報の受け皿にする。削除後の復号は主体側の短い視覚文脈に対して行うため、KVキャッシュを読み出す対象も減る。著者は非主体トークン用のKVキャッシュを後続推論のために保持する必要がないとする。ただし質問表現への情報移行が不完全なら、削除した視覚パッチの細部を後から復元する保証はない。

### 5. 深さn、保持率、融合重みの設計

層nを浅くすれば後半層の計算を多く省けるが、質問表現へ移る視覚情報が不足する。逆に深くすると品質が改善し得る一方、非主体経路を長く維持するので高速化利得が減る。付録Bの設定ではLLaVA-1.5-7Bでn=3、LLaVA-Next-7Bでn=16、Qwen2.5-VL-3Bでn=18を使用する。入力の視覚トークン数やモデルによって必要な移行深さが異なるため、単一のnをすべてのモデルへ移植する方式ではない。

式(10)の融合重みも固定であり、質問が背景に強く依存するかどうかを実行時に判別して動的調整するわけではない。著者のTable 7では等重みが良いが、他の画像分布や質問構成でも同じ重みが最適とまでは証明されていない。重要なのは「背景を残す」ことではなく、背景を処理する時間を前半層へ集中し、後半層の計算・状態を短くすることである。

## 評価：主要結果、感度と負の結果

### 1. 88.89%の視覚トークン削減における品質

| モデル・評価表 | 無削減 | FastV | ParVTS | 解釈 |
|---|---:|---:|---:|---|
| LLaVA-1.5-7B / Table 1 | 100.00% | 78.64% | **92.45%** | 576→64トークン。主体だけを残す方式より損失を抑制 |
| LLaVA-Next-7B / Table 1 | 100.00% | 85.87% | **89.07%** | 2880→320トークン。改善はあるが無削減には及ばない |
| InternVL2.5-2B / Table 2 | 100.00% | 91.43% | **95.88%** | 動的トークン予算で88.89%削減 |
| Qwen2.5-VL-3B / Table 3 | 100.00% | 67.46% | **77.21%** | FastVより良いが元モデル比22.79%の品質低下 |

LLaVA-1.5ではFastVに対して約13.8ポイントの正規化平均品質改善があるが、元モデルからはなお7.55ポイント低い。Qwen2.5-VLでは大幅削減時の品質低下がより深刻であり、「ほぼ精度を落とさない」という一般化はできない。さらにTable 4のVideo-LLaVA-7Bでは、2056→1032トークンの削減時に平均Accuracyが58.2→57.8となり、FastVの58.1もわずかに下回る。視覚経路の並列化が全モデル・全課題で必ず精度優位となるわけではない。

1.77倍という最大値は、無削減よりMMEが約177ポイント低い条件である。8.48→2.57 TFLOPsは約69.7%の演算量削減であり、実際の応答時間短縮率と同じ百分率ではない。Table 5では、同程度のMME品質を持つFastV・SparseVLMよりParVTSの時間/件が短い。例えばMME約1810群ではFastV 224.94ms、SparseVLM 210.19msに対してParVTS 185.34msである。比較する際は品質水準を固定しなければ、単に多く削った方式が速く見える。

### 3. 移行深さnと逐次方式のアブレーション

Table 6ではLLaVA-1.5-7Bの64トークン保持（88.89%削減）で、n=3の正規化平均92.91%、n=7で92.19%、n=11で92.42%、n=15で94.38%となる。深くすれば単調に改善するわけではないが、非常に強い削減では深い移行層が有利な条件がある。一方192トークン保持（66.67%削減）ではn=3が97.95%、n=15が95.86%であり、深くするほど良いという単純な規則は成立しない。

同じ192トークン保持で、n=3のParVTSは97.95%、Non-Sub-FSは97.28%、Sub-FSは77.77%である。逐次方式が初期層の特徴抽出を欠くと品質が大きく落ちるという設計仮説と整合する。64トークン保持ではParVTS 92.91%、Non-Sub-FS 89.80%、Sub-FS 85.97%となる。Table 1の92.45%との差は、Table 6で平均化するベンチマーク集合が異なるためである。

### 4. 質問表現の融合重みと情報保持

Table 7の64トークン保持条件では、`α=0, β=1`（主体側だけ）の平均品質が91.55%、`α=0.5, β=0.5`が92.91%、`α=1, β=0`（非主体側だけ）が92.52%である。両方の経路を利用した等重み融合が最良となるが、差はモデルや質問分布に依存する。質問表現へ非主体情報を移す効果は、背景トークンを完全に無視する方式との比較で検証されている。ただし本論文は質問ごとにα・βを推定する適応器を提案していない。

### 5. プリフィルと復号の差：実装上の利得と頭打ち

付録DのTable 22では、LLaVA-1.5-7Bでバッチ1・出力約195トークンの条件において、無削減のプリフィル0.39秒が88.89%削減時0.27秒（1.46倍）へ短縮する一方、復号速度は約5.3 token/sから約5.4 token/sへしか変わらない。視覚トークン削減による注意演算節約が、メモリ帯域律速の逐次復号へそのまま反映されないためである。

バッチ8・出力1トークンの条件では、プリフィル1.24秒が0.52秒（2.40倍）となり、短い出力を多数同時処理する場面で効果が大きい。これはTable 5の入力1件あたり1.77倍と評価条件が異なる。推論全体の高速化を議論する際は、入力処理、逐次復号、バッチ形成、出力長のどこが律速かを分ける必要がある。付録Eの理論モデルも、移行深さnは主にプリフィル側の計算量へ効き、復号側は削減後の視覚文脈長と出力長に依存することを示す。

## 既存研究との差

FastVやSparseVLMは、削除すべき視覚トークンを重要度で選び、残すトークンだけを後半層へ通す。一方ParVTSは、削除候補の情報も初期層で質問表現へ移してから視覚トークンを捨てる。PruMergeのようなトークン合併でも、LLaVA-Miniのような追加学習した圧縮器でもなく、モデル内部の既存自己注意を利用する。新しい圧縮ネットワークを導入しない点が移植性の利点となる。

また逐次切替のSub-FS/Non-Sub-FSを負例として実測し、初期層の表現深さを揃えることが必要だと示す。主体・非主体を別の経路で初期処理するのは、背景をすべて保持するためではなく、質問トークンへ必要な情報を転写する時間を確保するためである。FlashAttentionとKVキャッシュ再利用に適合すると著者は主張するが、実際の本番サービングシステムでの多利用者・長時間負荷に対する保証とは区別する。

## 限界・負の結果・適用範囲

最大の限界は、[CLS]注意による主体選択と、初期層での情報移行が質問ごとに最適化されていないことである。背景が主要な質問では非主体側の情報が不可欠で、単一の固定深さnで十分に転写できるとは限らない。非主体トークンを削除した後は、失った細部を後半層で直接参照できない。Qwen2.5-VL-3Bの88.89%削減時には平均品質77.21%へ低下し、Video-LLaVAではFastVよりわずかに悪い条件もある。

実装上、初期層で二経路を処理するためのマスク制御・質問表現融合が必要であり、単純な全層トークン削減より前半層の計算は重い。画像数やパッチ数、出力長、バッチ数によって利得が変わり、バッチ1の長い復号ではプリフィル高速化がトークン生成速度へほとんど波及しない。付録Dでは復号速度がほぼ横ばいの例があるため、1.77倍をすべてのLLMデコードで再現可能な倍率と扱わない。

今回確認した一次資料には、速度測定のGPU型番・ランタイム・精度形式を再現可能な形で明記した箇所を見つけられなかった。Table 5のms値を別のGPU、量子化モデル、推論サーバーへそのまま移すことはできない。著者は公式コードURLを本文に明示しておらず、独立再現の容易さにも不確実性が残る。学習不要であることは追加のモデル重み学習が不要という意味で、実装変更・移行深さの選択・実機ベンチマークが不要という意味ではない。
