# MACE：LLM推論と継続再学習を同じGPUで混載するスケジューラ

## 概要

推論サーバでモデルを個人の嗜好や新しいフィードバックへ追随させたい場合、モデルの再学習と応答生成が同じGPU資源を奪い合う。一定時間ごとに再学習する方式はモデル更新が遅れ、更新を最優先する方式は利用者への応答を待たせる。MACEはこの二択を、prefill、decode、LoRA fine-tuneを**反復単位で一緒に詰める**スケジューリング問題として扱う。

中核は、経過待ち時間とアラインメント改善余地に応じて優先度を更新する仕組み、GPUの空きメモリと処理時間の両方を見たbest-fit配置、共通prefixのKV再利用とデコード時のKVキャッシュ枝刈りである。A6000 AdaではAdaInf比で10%再学習率の推論スループット最大1.46倍、prefill遅延最大63%削減を報告する。ただし、GPUがほぼ飽和するAGX Orinでは利得が限定的であり、KV枝刈りは一部のアラインメント品質を損なう。

## 問題設定

prefillは入力長とバッチに応じて大きな計算を行い、decodeは小さな演算を逐次繰り返すがKVキャッシュが成長する。LoRA fine-tuneは全重み更新より軽いとはいえ、逆伝播とoptimizer状態のため推論より高いメモリ・計算需要を持つ。この三者を個別のキューで処理すると、GPUメモリの未使用領域と時間的な待ちが同時に発生する。

比較対象のEkyaは再学習を周期的に実行して推論をブロックする。AdaInfは継続再学習を高優先で処理するためモデル更新は速いが、推論要求が待ちやすい。MACEは一つのiteration内へ短いdecodeと大きな再学習を混ぜ、SLO違反を抑えつつ再学習の飢餓も避ける。最適化対象は純粋な学習スループットではなく、**応答遅延、トークン処理能力、モデルの嗜好追随精度の三者**である。

## 手法

### 時間とアラインメント損失で優先度を変える

要求はprefill、decode、fine-tuneに分類され、到着時刻と基本優先度を持つ。通常の基本優先度はdecode > prefill > fine-tuneとして応答生成を守る。一方、待ち時間に伴う優先度の増加率はfine-tune > prefill > decodeと逆にする。これにより長く待った再学習は徐々に前へ出て、永遠に延期されない。

fine-tune要求ではさらにDPO損失を優先度へ加える。現在のモデルが望ましい応答と望ましくない応答を十分区別できていない例は、アラインメント改善余地が大きいとみなして優先的に学習する。入力はユーザーの好みの対（x, y+, y−）、出力は更新されたLoRA重みである。再学習を単純な到着順ではなく、更新価値と待ち時間の双方で扱う。

### 反復単位の二次元best-fit

スケジューラは、各候補の必要メモリmと予測実行時間ℓをプロファイルから見積もる。GPUメモリの空きと、同じ反復に詰める他タスクとの実行時間差を重み付きで評価し、メモリ断片化と処理時間の不整合が小さくなるbinへ割り当てる。候補binに入らない場合は新しいbinを作り、今回実行する先頭binを選ぶ。メモリ閾値やタスク数の閾値に達したら追加を止める。

実行が終わると、decodeはEOSまたは最大ステップ数、fine-tuneはDPO損失閾値に基づいて終了判定し、未完了タスクを更新優先度で再キューイングする。論文の図では、初期には複数decodeとprefillを優先し、後の反復で待ち時間の増えたfine-tuneを先行させる。全要求を一度に完了させる静的bin packingではなく、生成トークン単位で状態が変わるオンラインのbin packingである。

### prefix共有とKV枝刈り

同じsystem promptなどを持つ要求群に対し、Trie状のprefix木を構築する。共通prefixは一度prefillしてKVをキャッシュし、子要求が再利用する。深さ優先走査により共通計算をまとめ、メモリが足りない場合はLRUで不要キャッシュをオフロードする。これによりprefillの再計算を抑え、同じGPUへ再学習タスクを載せる余地を増やす。

decodeでは容量制約に応じて寄与の小さいKV要素を枝刈りし、キャッシュ占有を下げる。これは可逆なprefix共有と異なり、過去情報を実際に失う近似操作である。原著のアブレーションでKV枝刈りを無効にしたMACE/Pruneが最も高いCLPDを示す点は、スループット向上とアラインメント精度が完全には両立しないことを示す。

### 実装と対象範囲

producerスレッドが要求を受け、schedulerスレッドが優先度・bin配置を更新し、executor群がGPU作業を実行する。対象は単一ノード・単一GPUでの混載であり、複数ノード間のモデル更新同期や分散KVキャッシュ整合性を解決した方式ではない。prefill/decode/LoRAをGPU上で協調させる設計は、複数GPUに独立して分けるdisaggregationとは異なる。

## 評価

### 実験条件

| 項目 | 条件 |
|---|---|
| サーバ | NVIDIA RTX A6000 Ada、48GB VRAM、Mistral-7B |
| エッジ | NVIDIA AGX Orin、32GB LPDDR5、Mistral-3B |
| 入力・到着 | Poisson到着の推論要求、再学習率を変化させる混合負荷 |
| 嗜好データ | Anthropic HH-RLHF（harmlessness）、Stanford SHP（helpfulness） |
| 再学習 | LoRAとDPOを用いた連続的な嗜好追随 |
| 比較 | Ekya（周期再学習）、AdaInf（継続再学習・FIFO優先） |
| 指標 | 推論スループット、TTFT、TBT、fine-tune遅延、win rate、CLPD、SLO達成率、GPU利用率 |
| 設計上の制約 | 同一GPU型のオフラインプロファイルを前提。分散ノードの同期評価はない |

CLPDは好ましい応答と好ましくない応答の対数確率差で、高いほど好みを区別する余裕が大きい。win rateは好ましい応答へ高い確率を割り当てた割合である。TTFTは最初のトークンまでの遅延、TBTは生成トークン間の遅延を表す。各改善倍率は異なるベースライン・条件で得られており、一つの条件の全指標が同時に最大改善するという意味ではない。

### 主結果とGPUの制約

| 条件 | 比較・指標 | MACEの結果 | 解釈 |
|---|---|---|---|
| A6000、再学習率10% | AdaInf比推論throughput | 最大1.46倍 | 混載とキャッシュ最適化でGPUの空き時間を利用 |
| Orin、再学習率を変化 | AdaInf比throughput | 平均1.12倍 | 計算資源が飽和しやすく利得は小さい |
| A6000 | AdaInf比prefill遅延 | 最大63%削減 | 共通prefix再利用が有効 |
| Orin | AdaInf比decode遅延 | 最大30%削減 | KVキャッシュ容量を抑える効果 |
| SHP | AdaInf比win rate / CLPD | 最大1.03倍 / 1.21倍 | 再学習と応答の両立による品質改善 |
| HH-RLHF | AdaInf比win rate / CLPD | 最大1.02倍 / 1.34倍 | 品質指標ごとに利得が異なる |
| A6000 | GPU利用率（Periodic/Continuous/Hybrid） | 17.8% / 21.1% / 27.7% | 断片化が大きいサーバで混載余地がある |
| Orin | GPU利用率（Periodic/Continuous/Hybrid） | 82.7% / 80.6% / 85.2% | すでに高負荷で混載余地が小さい |

原著Figure 5ではOrinのTTFT改善が0.92～0.98倍程度、TBTは約1.01倍となる比較があり、混載によって全遅延が常に短くなるわけではない。論文のabstractの「最大63%削減」をOrinやすべての負荷へ外挿しない。

### 構成要素除去と負の結果

SLO達成率はTTFTが「forward遅延の5倍以内」という期限に入る割合で測る。固定batch・FIFOへ戻したMACE/Binは高負荷で達成率が20%未満へ落ち、prefix共有を外したMACE/Prefixは150 rpsで完全版より達成率が35～40%低い。throughputは完全版が225 tokens/s超に対し、MACE/Binは17.6%低下、MACE/PruneとMACE/Prefixはそれぞれ7～11%低下する。三つの機構は異なるボトルネックを減らしている。

一方、**KV枝刈りを無効化したMACE/PruneがCLPDで最良**という原著Figure 12の結果は、枝刈りで必要な履歴情報が失われ得ることを示す。スループットを上げても、生成品質と嗜好追随の両方が単調に良くなるわけではない。

### スケジューラの追加コストと原著内の不整合

原著Table 1はスケジューラ遅延をEkya 0.03ms、AdaInf 0.08ms、MACE 0.15ms程度と記す。一方、直後の本文はMACEの追加オーバーヘッドを「約15ms/request」、AdaInfとの差を「約7ms/request」と説明している。**表と本文で約2桁の差があり、単位または測定粒度の説明が一致しない。** さらに「15msは数十～数百msの実行時間に対して0.1%未満」とする主張も、そのままでは算術的に成立しない。再現・実装判断ではTable 1と本文の数値を同じ指標として扱わず、追加の確認が必要である。スケジューラメモリはTable 1で4MBとされ、本文では5MB未満と説明される。

## 既存研究との差

OrcaやvLLMは推論要求のcontinuous batchingとKV管理を主眼とし、継続的な嗜好再学習を同じ反復へ詰めることは主題ではない。Ekyaは周期的な再学習により更新鮮度と応答遅延を分離する。AdaInfは更新鮮度を優先するが、prefill・decode・LoRAの異なる資源形状をまとめて扱わない。MACEは**GPUローカルの一反復**を資源配分単位とし、再学習の重要度とGPU空き容量を同時に考慮する。

## 限界・適用条件

対象GPUはA6000 AdaとAGX Orinの単一ノードであり、複数GPU間で異なるモデル版を共有する整合性、ノード間の再学習同期、分散キャッシュは未評価である。GPU型が異なる環境へはprefill/decode/LoRAのオフライン性能プロファイルを再作成する必要がある。CPUへのfallback、異種GPUの通信費用、長期間の概念ドリフト下での安全性評価も主な実験範囲外である。

再学習要求の生成はPoisson到着・特定の嗜好データセットに基づく模擬的な混合負荷であり、実際の大規模マルチテナント環境の障害、チェックポイント競合、プライバシー制御、学習済みLoRA版のロールバックまで実証したものではない。原著内のscheduler overheadの単位不整合は未解決の再現性リスクとして残る。公式コードのURLは確認できない。
