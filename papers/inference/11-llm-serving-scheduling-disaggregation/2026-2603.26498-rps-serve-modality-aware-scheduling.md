# TCM-Serve: Modality-aware Scheduling for Multimodal Large Language Model Inference

> プリフィル遅延とKV占有量からマルチモーダル要求を3資源クラスへ分け、クラス別キューとエージング付き優先制御で巨大動画による先頭待ちを抑え、平均TTFTを54%、遅延重視要求で78.5%削減する。
## 書誌情報
- **著者**: Konstantinos Papaioannou, Thaleia Dimitra Doudali
- **著者・所属**: Konstantinos Papaioannou（IMDEA Software Institute、Universidad Politécnica de Madrid）、Thaleia Dimitra Doudali（IMDEA Software Institute）。
- **公開**: arXiv:2603.26498v2
- **種別**: プレプリント
- **対象**: マルチモーダルLLMサービング、要求スケジューリング、先頭待ち、KVキャッシュ圧力、優先度エージング、vLLM、SLO
- **実装**: vLLM 0.8.4のV1実行系とチャンク化プリフィルを基盤に、プロファイラ、資源推定器、3クラス要求分類器、クラス別キュー、エージング付き優先レギュレータ、追加計測を統合した試作。論文は公開予定と記すが、一次資料には著者公式コードURLがない。
## 概要
TCM-Serveは、テキスト・画像・動画を同じマルチモーダルLLMへ流すと、前処理・視覚エンコーダ・プリフィルの資源需要が桁違いになり、先着順では巨大な動画要求が軽量なテキスト要求を長時間待たせる問題を扱う。モデル・モダリティごとの事前プロファイルからプリフィル遅延とKVキャッシュ占有量を予測し、その2軸で要求を軽量・中量・重量の3クラスへ分類する。各クラスは先着順を保つ別キューへ入れ、軽量要求を優先しつつ待機時間に応じて優先度を増やすエージングで重量要求の飢餓を防ぐ。vLLM 0.8.4のV1実行系へ統合し、A100実機と7種類のマルチモーダルLLM、ShareGPT・LLaVA系データを用いた評価で、現行方式に対し平均TTFTを全体で54%、遅延重視要求で78.5%削減する。

TCM-Serveの中心差分は、要求をテキスト・画像・動画という入力種別そのもので分類せず、モデルごとに予測したプリフィル遅延とKVキャッシュ占有量という時間・空間の2資源へ写像し、その2軸で軽量なmotorcycle、中量のcar、重量のtruckへクラスタリングする点にある。さらに3クラスを別キューへ分け、軽量要求へ静的な優先度を与えつつ、待機時間が長くなるほど非線形に優先度を引き上げるエージングを組み合わせる。これにより大要求による先頭待ちを避けながら、重量要求を永久に後回しにしない。

代表結果として、平均TTFTは論文全体の評価要約で現行マルチモーダルサービング方式に対して全要求で54%削減。重量要求を軽量要求の前へ無条件に置かないことで、プリフィル競合とキュー待ちを減らす。
## 問題設定
マルチモーダルLLMの要求は、同じサーバへ届いても必要資源が大きく異なる。短いテキストは数十から数千トークン程度で前処理も軽い一方、画像は視覚エンコーダ処理と数百から数千の視覚トークンを追加し、動画では十万規模のトークンへ膨らむ場合がある。現行vLLMは先着順とチャンク化プリフィルを組み合わせるが、巨大な動画要求が先頭へ入ると、プリフィル計算とKVキャッシュ確保が長時間GPUを占有し、後続の軽量要求まで待たされる。重いマルチモーダル構成ではSLO違反率が60%を超え、メモリ余裕を縮めると最大90%へ達する。単にモダリティ名で優先順位を決めても、画像・動画内の長さ差やモデルごとの視覚トークン化差が大きいため、実際の資源需要を正しく分離できない。
## 新規性
TCM-Serveの中心差分は、要求をテキスト・画像・動画という入力種別そのもので分類せず、モデルごとに予測したプリフィル遅延とKVキャッシュ占有量という時間・空間の2資源へ写像し、その2軸で軽量なmotorcycle、中量のcar、重量のtruckへクラスタリングする点にある。さらに3クラスを別キューへ分け、軽量要求へ静的な優先度を与えつつ、待機時間が長くなるほど非線形に優先度を引き上げるエージングを組み合わせる。これにより大要求による先頭待ちを避けながら、重量要求を永久に後回しにしない。
## 手法
### 手法のあらまし
まず各モデルと入力モダリティについて、代表要求を少量オフライン実行するワークロードプロファイラが、前処理時間、視覚エンコーダ時間、プリフィル時間、生成トークン数などを採取する。この測定から影響推定器を構築し、テキストでは入力トークン長を説明変数とする軽量な線形回帰、画像・動画では長さと視覚負荷のばらつきで過小評価しにくい90パーセンタイル量子回帰を使って、要求ごとのプリフィル遅延とKVキャッシュ必要量を予測する。次に要求分類器がこの2値を標準化し、モデルごとに3つの資源クラスへクラスタリングする。実行時には各要求を対応するクラス別キューへ入れ、各キュー内の先着順は維持する。スケジューラはmotorcycle、car、truckの順に静的優先度を持つが、待機時間が増えるとクラス固有の係数と指数を使うエージング項を加算し、時間とともに重量クラスの優先度を上げる。各スケジューリング時点で3キューの先頭要求を比較し、現在の動的スコアが最も高いクラスからチャンク化プリフィルやデコード対象を選ぶ。要求の計算内容や注意機構は変更せず、vLLM V1の既存KV管理・継続バッチ・チャンク化プリフィルを利用するため、速度改善は要求順序と資源競合の緩和から得られる。

### ワークロードプロファイラと影響推定器
モデルごとに入力モダリティの計算特性が異なるため、TCM-Serveは固定の経験則を使わず、配備前に代表要求を実行して時間とメモリの関係を学習する。プロファイラは前処理、視覚エンコード、プリフィル、生成の各時間と入力・出力長を記録する。テキストは入力長とプリフィル負荷の関係が比較的滑らかなので線形回帰を使う。一方、画像や動画は解像度・フレーム数・視覚トークン化でばらつきが大きく、平均回帰では重い要求を過小評価しやすいため90パーセンタイルを狙う量子回帰を採用する。推定結果は要求ごとの予想プリフィル遅延とKV占有量として分類器へ渡され、オンライン経路では重いモデル推論を追加せず軽量な予測だけで済む。

### 資源需要に基づく3クラス分類
単純な『テキストは軽い、画像は中間、動画は重い』という分類では、長文テキストと短い画像、短い動画と高解像度画像などの資源需要が重なり、誤分類が生じる。TCM-Serveは予測プリフィル遅延とKV占有量の2次元空間で要求をクラスタリングし、軽量なmotorcycle、中量のcar、重量のtruckという3群へ分ける。分類境界はモデルごとに作るため、同じ動画でも視覚エンコーダやトークン化方式が違うモデルの差を吸収できる。時間だけでなくKV占有も使うことで、GPU計算が短くても大量のキャッシュを長く保持して後続要求をプリエンプトさせる要求を重量側へ置ける。

### クラス別キューと優先度エージング
分類後の要求は3つの独立キューへ入り、同一クラス内では先着順を維持する。クラス間では軽量要求へ高い初期優先度を与え、大きな動画が先頭に来てもテキストや軽い画像を先に進められる。ただし静的優先だけではtruckが飢餓するため、待機時間tに応じて1-exp(-k*t^p)型のエージング値を加え、長く待つほど動的優先度を上げる。係数kと指数pはクラス別に設定し、motorcycleは早く上限へ達し、truckは緩やかだが確実に上昇する。スケジューラはこの優先度をスコアへ変換して各キュー先頭を比較し、軽量要求の低遅延と重量要求の進行保証を両立する。

### vLLM V1への非侵襲統合
TCM-Serveは視覚トークン削除やモデル分割を行わず、vLLM 0.8.4のV1実行系とチャンク化プリフィルのスケジューラを拡張する。既存のKVキャッシュ管理、プリエンプション、バッチ形成は利用しつつ、要求投入時に資源クラスを付与し、バッチ選択時だけ3キューの動的優先順位を参照する。これによりモデル固有カーネルへ手を入れず、多数のマルチモーダルモデルへ同じ制御を適用できる。軽量要求を先に処理すると短時間でKVを解放できるため、単なる順序変更以上にプリエンプションと再計算の連鎖を抑え、メモリ圧力下でもSLO違反を減らす。

### 全体のデータ／制御の流れ
配備前のプロファイラがモデル・モダリティ別の回帰器と分類境界を生成し、オンラインでは要求受信時に入力特徴からプリフィル時間とKV量を推定して3クラスの一つへ振り分ける。キュー管理器はクラス別先着順と待機時刻を保持し、優先度レギュレータが毎回エージングを更新する。vLLMスケジューラは最も高優先度のキューから既存のトークン予算・KV容量条件を満たす要求を選び、通常のモデルランナーへ渡す。
## 評価条件
- **ハードウェア**: 1×NVIDIA A100 40GB、2×AMD EPYC 7313 16-core CPU（合計32スレッド）、256GBホストDRAM
- **ソフトウェア**: vLLM 0.8.4 V1実行系、チャンク化プリフィル、TCM-Serveスケジューラ拡張
- **モデル**: LLaVA-OneVision 0.5B、LLaVA-OneVision 7B、Gemma 3 4B、Gemma 3 12B、Qwen2.5-VL 3B、Qwen2.5-VL 7B、Pixtral 12B
- **データセット／トレース**: ShareGPT（テキスト）、LLaVA-Instruct（画像）、LLaVA-Video（動画）
- **比較対象**: vLLMチャンク化プリフィルの先着順、最早期限優先（Earliest Deadline First; EDF）
- **正確性・品質**: 要求順序とスケジューリングだけを変更し、視覚トークンやモデル演算を近似しない。したがって同じ要求を実行したときのモデル計算内容を変えず、品質低下を速度へ交換する方式ではない。
- **ワークロード混合**: テキストのみ、軽量マルチモーダル、重量マルチモーダルの3構成を用意し、最近の本番特性報告を参考にテキスト・画像・動画比率を設定する。要求到着はPoisson過程で生成する。
- **標準評価**: LLaVA-OneVision 7B、重量マルチモーダル構成、到着率2要求/秒を既定とし、SLOは競合なしエンドツーエンド遅延の5倍に設定する。
- **KV容量感度**: GPU側KVキャッシュへ使えるメモリを通常量から25%まで段階的に減らし、資源圧力下で各クラスの遅延・SLO違反・プリエンプションがどう変わるかを測る。
- **分類器切り分け**: 単純なモダリティ対応分類と、推定プリフィル時間・KV占有量によるスマート分類を比較し、さらに静的優先だけとエージング付き完全版を分離評価する。
各モデルへ実データセット由来のテキスト・画像・動画要求を投入し、モダリティ混合率、到着率、KV容量を変えながら、平均およびP90のTTFT、正規化遅延、SLO違反率、違反深刻度、プリエンプション時間を測る。モデル横断評価に加え、分類方式と優先制御の切り分けを行い、軽量要求への利益が重量要求の飢餓によるものではないかを確認する。
単一A100ノードの実機評価であり、複数GPU・複数ノード通信、テンソル並列、段階分離は含まない。対象入力はテキスト・画像・動画で、音声、3D、任意入力任意出力モデルは未対応。要求到着はPoisson生成で、実サービスの長時間到着トレースを直接再生しない。GemmaとPixtralでは動画を画像列として模擬する。
## 主要結果
TCM-Serveは、要求の重さを資源需要から分類して軽量クラスを先に進めることで、マルチモーダル混在時の先頭待ちを大幅に抑える。抄録では現行方式に対し平均TTFTを全体で54%、遅延重視要求で78.5%削減する。重量マルチモーダル負荷では軽量クラスのTTFTを1秒未満へ維持し、エージングを含む完全版は静的優先よりSLO違反をさらに減らす。KVメモリを通常の25%まで縮小しても軽量要求は平均TTFT 1秒未満を維持する一方、重量要求は遅延が悪化し、資源の厳しい条件では明確な優先順位の交換関係が現れる。

- 平均TTFT / 全要求で54%削減 (比較対象: 現行マルチモーダルサービング方式; 条件: 論文全体の評価要約) — 重量要求を軽量要求の前へ無条件に置かないことで、プリフィル競合とキュー待ちを減らす。

- 遅延重視要求TTFT / 78.5%削減 (比較対象: 現行方式; 条件: 軽量・遅延重視要求) — 時間・KV資源の両方で軽量と判定された要求へ先にGPU機会を与える効果が最も強く出る。

- 分類・静的優先の切り分け / 正規化遅延を全体で約50%、SLO違反を約45%削減 (比較対象: vLLM先着順; 条件: 重量マルチモーダル構成) — モダリティ混在を別キューへ分離するだけでも先頭待ちの大部分を除ける。

- 軽量クラス正規化遅延 / 約60%低下 (比較対象: vLLM先着順; 条件: スマート分類 + 静的優先) — 実資源需要で軽量要求を特定することで、単純モダリティ分類より短い要求を正確に先行させる。

- エージング効果 / 軽量クラスSLO違反を静的スマート分類からさらに約半減 (比較対象: スマート分類 + 静的優先; 条件: 完全な優先度レギュレータ) — 待機時間を優先度へ反映しつつ、軽量要求の期限違反を追加で抑える。

- KVメモリ圧力耐性 / KV容量25%でも軽量クラス平均TTFT 1秒未満 (比較対象: vLLM / EDF; 条件: GPU KVキャッシュを通常の25%へ制限) — 短く終わる要求を先に完了してKVを解放することで、強いメモリ圧力下でも軽量要求を保護する。

- テキストのみ負荷 / 平均TTFT約0.05秒、SLO違反0.5%未満 (比較対象: 同論文設定; 条件: テキストのみ構成) — モダリティ差がない場合でも追加スケジューリング機構が大きな悪化を招かない。

### 負の結果・境界条件
- 軽量要求を優先するため、重量truck要求の遅延は条件によってvLLMやEDFより悪化する。特にKV容量を25%まで縮めると重量要求が強く影響を受ける。単純モダリティ分類は実資源需要の重なりを捉えられず、truckの遅延を悪化させる場合がある。オフライン推定器はモデル・モダリティごとの約20分プロファイルを必要とし、モデル更新や入力分布変化で再調整が必要になる。

### 結果の読み方
マルチモーダルサービングでは、全要求を公平な先着順へ置くことが必ずしも利用者体験の公平性にならない。十万トークン級の動画が短いテキストを数十秒止める状況では、資源需要を先に推定し短時間で完了する要求を抜き出す方が、多数の要求のSLOを満たしながらGPUとKVを早く解放できる。エージングが重量要求の進行保証を担うため、単純な短ジョブ優先より実運用へ適用しやすい。
## 品質への影響
モデル内部計算や視覚トークンを削減しないため、生成品質を速度へ交換する近似方式ではない。交換条件はクラス間の待機時間と公平性であり、重量要求の遅延増加を許容して軽量要求のSLOを守る設計である。
## 既存研究との差
ModServeは画像・動画の前処理やエンコーダなどモダリティ固有段階を別資源へ分離し、段階間の資源配置でスループットを高める。一方TCM-Serveは単一ノード内の既存vLLMを前提に、要求順序を時間・KV資源の2軸で制御して先頭待ちを減らす。視覚トークン削減やInf-MLLM系は入力表現自体を短くして計算を減らすが、品質影響を伴いうる。本方式はモデル計算を変えない。チャンク化プリフィルやSarathi系は長いプリフィルを分割してデコードとの干渉を減らすものの、極端に重い視覚要求を軽量要求より先に置く先着順の問題は残る。EDFはSLO期限だけを見るのに対し、TCM-Serveは資源需要クラスと待機時間を同時に使う。
## 限界
単一A100 40GBノードでの評価に限定され、複数GPU・複数ノード、テンソル並列、プリフィル・デコード分離との相互作用は未検証である。対象はテキスト・画像・動画で、音声、3D、任意入力任意出力などの将来モダリティは扱わない。要求到着はPoisson生成であり、本番クラスタの時間相関やテナント偏りを直接再現しない。モデル・モダリティごとのオフラインプロファイルと回帰器を前提にするため、モデル更新、入力解像度分布、前処理実装が変わると再プロファイルが必要になる。軽量要求を優先する設計なのでtruckの遅延を悪化させる条件があり、KVメモリが極端に少ない場合はその交換条件が強くなる。一次資料はコードを公開予定と述べるが、現行arXivページから著者公式コードURLを確認できない。

## 研究上の位置づけ
