# A Policy-Driven Runtime Layer for Agentic LLM Serving

> エージェント識別子を共通座標に観測・採点・予測・作用を推論基盤へ挿入し、オンライン遷移学習を鍵値追い出しと先読みに使ってヒット率と遅延を改善する。
## 書誌情報
- **著者**: Rui Zhang, Chaeeun Kim, Liting Hu
- **著者・所属**: カリフォルニア大学サンタクルーズ校。
- **公開**: arXiv:2605.27744v2
- **種別**: プレプリント
- **対象**: エージェント型大規模言語モデル提供、鍵値キャッシュ、予測的先読み、追い出し方策、実行時抽象化、マルコフ遷移
- **実装**: キャッシュスカウトを鍵値キャッシュへ接続する事例実装を評価。必要なエンジンフックはブロック接触の観測転送と追い出し時の採点参照の二つ。著者公式コード公開先は本文で確認できない。
## 概要
本論文は、エージェント枠組みが知る役割・遷移構造と、推論エンジンが観測するキャッシュ・要求イベントの情報断絶を埋める実行時層を提案する。観測、採点、予測、作用の四原語を共通契約とし、実証事例のキャッシュスカウトではオンライン遷移学習を鍵値追い出しと次エージェント先読みに利用する。五ワークロードで標準推論基盤比のキャッシュヒット率を十三〜三十七ポイント改善し、端から端までの遅延を六〜二十六パーセント、処理量を六〜十四パーセント改善する。ただし九方針のうち定量評価は鍵値キャッシュ事例だけである。

中心提案は特定の鍵値キャッシュ方策ではなく、エージェント枠組みと推論エンジンの間へ第三の実行時層を置き、方針依存処理を観測、採点、予測、作用という四つの原語へ統一することである。エージェント識別子を全イベントの共有座標として保持し、同じ観測流からキャッシュ、バッチ、公平性、安全など異なる方針を実装できる。実証例のキャッシュスカウトでは、静的なワークフロー宣言ではなく、実行中のエージェント遷移をオンライン学習し、将来再利用される鍵値を予測的に保護・先読みする。遷移構造が弱いと予測項が小さくなり、既存の最近最少使用方式へ自然に近づくため、予測を絶対視しない設計になっている。
## 問題設定
現在のエージェント型大規模言語モデル基盤では、上位のエージェント枠組みと下位の推論エンジンが別々の情報を持つ。上位はエージェントの識別子、役割、道具、遷移構造を知るが、どの鍵値キャッシュ片が触られたか、どの要求が待っているか、何が追い出されたかを見ない。下位は実行イベントを全て見るが、その要求がどの役割や遷移に属するかを知らない。この分断のため、鍵値キャッシュ、バッチ形成、事前充填と逐次生成の配置、投機的エージェント実行、公平性、安全方針など、両方の情報を必要とする最適化が個別改修になりやすい。特に共有可能なエージェントのシステム指示と道具定義は次セッションでも再利用されるのに、最近最少使用方式はセッション間の空白時間だけを見て追い出してしまう。
## 新規性
中心提案は特定の鍵値キャッシュ方策ではなく、エージェント枠組みと推論エンジンの間へ第三の実行時層を置き、方針依存処理を観測、採点、予測、作用という四つの原語へ統一することである。エージェント識別子を全イベントの共有座標として保持し、同じ観測流からキャッシュ、バッチ、公平性、安全など異なる方針を実装できる。実証例のキャッシュスカウトでは、静的なワークフロー宣言ではなく、実行中のエージェント遷移をオンライン学習し、将来再利用される鍵値を予測的に保護・先読みする。遷移構造が弱いと予測項が小さくなり、既存の最近最少使用方式へ自然に近づくため、予測を絶対視しない設計になっている。
## 手法
### 手法のあらまし
実行時層は既存の会話制御や行列演算を置き換えず、エージェントの意味情報と実行イベントの交点だけを保持する。観測処理はブロック接触、要求到着、道具返却、エージェント切替などを識別子付きで受けて状態を更新する。採点処理は追い出し対象や入場要求へ順位値を返す。予測処理は次エージェントや次道具など将来活動の確率を返す。作用処理だけがキャッシュ温存、要求延期、投機呼出しなどの副作用を外部へ出す。鍵値事例では、同じエージェントのシステム指示と道具定義から安定識別子を作り、エージェント間の遷移回数を滑動窓で保持する。あるエージェントから次のエージェントへ移った回数をその出発元からの全遷移回数で割り、一次マルコフ連鎖としてオンライン更新する。評価対象では現在のエージェントを知ることで次エージェントの不確実性が四十〜四十八パーセント減る。追い出し時には、十分な遷移確率を持つ辺だけのグラフを幅優先探索し、到達距離で将来再利用可能性を近似する。その値を既存の新しさ指標へ加え、総合点の低い鍵値から追い出す。キャッシュに存在しない有望な次エージェントには、共有可能なシステム指示と道具定義だけを通常推論経路で事前生成する。

### 四原語のエージェント実行時層
エージェント枠組みと推論エンジンの間に、観測、採点、予測、作用という方針非依存の四操作だけを持つ中間層を置く。観測はエンジンや枠組みから到着要求、ブロック接触、道具返却、エージェント切替を受け、安定したエージェント識別子に結び付けて履歴へ蓄積する。採点は追い出しや入場など、隣接層が既に持つ順位決定へ数値を返すだけに留める。予測は次エージェントや次の道具利用など将来活動の確率を返し、作用だけがキャッシュ温存、要求延期、事前温めなど副作用を非同期に実行する。こうして情報収集、意思決定用の数値、将来予測、実際の副作用を分離すると、鍵値キャッシュ以外の方針でも同じ観測流を再利用できる。推論エンジン内部へ方針ごとの専用条件分岐を追加する代わりに、共通の少数フックへ変更を局所化できることが抽象化の主目的である。

### オンライン遷移学習
キャッシュスカウトは配置時に固定したワークフロー図を前提にせず、実際の呼出し履歴からエージェント間遷移を一次マルコフ連鎖として学ぶ。エージェント切替が起きるたびに滑動窓内の遷移回数を更新し、出発元ごとの総回数で割って次エージェントの条件付き確率を得る。滑動窓を使うため、利用者の課題構成や道具利用が変わると古い経路の影響は徐々に弱まり、新しい実負荷へ追随できる。同じ六エージェント監督構成でも課題種類によって遷移確率が大きく変わるため、静的グラフは過保護と過小保護の両方を起こし得る。評価では現在のエージェントを知るだけで次エージェントの不確実性が四十〜四十八パーセント減り、複雑な学習器を置かなくても再利用予測へ使える信号がある。全エージェント数が五十未満では状態量が二十キロバイト以下で、調停状態が鍵値キャッシュ節約を相殺しない。

### 生存近似による鍵値追い出し
将来数ステップ以内に各エージェントが再登場する正確な確率を追い出しのたびに行列演算で求めると、キャッシュ管理の重要経路へ大きな計算を持ち込むことになる。そこで十分な遷移確率を持つ辺だけを残した有向グラフを作り、現在エージェントから一度の幅優先探索で各エージェントまでの到達距離を求める。距離が近いほど近い将来に再利用される可能性が高いとみなし、零から一の範囲へ正規化した生存近似値を作る。その値を従来の新しさ指標へ加え、総合点が小さい鍵値ブロックから追い出す。予測構造が強い場合は次に使われそうな共有アンカーがセッション境界を越えて保護される一方、遷移グラフが疎で予測できない場合は加点が零へ近づき、従来の新しさ規則へ自然に戻る。固定時間保護のように無関係な鍵値を長く固定し続ける危険を抑えつつ、意味情報を補助信号として使う設計である。

### 次エージェントのセッション間先読み
追い出し保護はまだ残っている共有アンカーには有効だが、既に失われたアンカーを次の呼出し前に戻すことはできない。そこで現在エージェントから最も遷移確率が高い次エージェントを選び、そのエージェントの共有可能なシステム指示と道具定義を使った軽量な温め要求を通常の推論経路へ発行する。利用者固有の長い会話履歴は含めず、最小の利用者入力と一トークン生成だけを組み合わせることで、複数セッションで再利用できるアンカー鍵値だけを事前に作る。特別なキャッシュ書込み経路を設けず通常経路を使うため、ブロックハッシュや整合性規則を二重管理しない。作用処理を本要求の重要経路から分離するので、本要求の逐次生成を直接停止させない。予測を外した場合の主な損失は余分な小規模計算と一時的なキャッシュ占有であり、遷移学習と追い出し採点を組み合わせてその損失を抑える。

### 全体のデータ／制御の流れ
枠組み側から渡されるエージェント識別子と役割情報を、エンジン側のブロック接触・追い出しイベントへ結び付ける制御面として実装する。キャッシュスカウトは遷移学習器、生存近似採点器、先読み処理から構成される。ブロック接触を観測し、エージェント切替時に遷移グラフを更新し、追い出し時には既存の新しさへ予測点を加える。ステップ間では次エージェント予測から温め要求を通常経路へ流す。鍵値保存キー自体は従来のブロックハッシュを保ち、エージェント識別子は予測索引としてだけ使うため、キャッシュ一致判定の正しさを意味情報へ依存させない。論文が列挙する他の八方針は同じ契約への設計写像であり、現時点の実装完成度は鍵値事例より低い。
## 評価条件
- **ハードウェア**: エヌビディアH100 80ギガバイト演算装置。
- **ソフトウェア**: Llama-3.1-8B-Instruct、複数エージェント会話枠組み、大規模言語モデル推論基盤を組み合わせる。キャッシュスカウトはブロック接触の観測転送と追い出し時の採点参照を追加する。
- **比較対象**: 標準推論基盤、固定時間保護型の鍵値キャッシュ調停
多肢選択、対話、汎用助手、算数の四実タスクを同じ六エージェント監督構成で実行し、遷移構造が強い十二エージェント合成鎖も加える。実タスクは並行度四・百二十ブロックのキャッシュ予算、合成鎖は並行度一・二百五十ブロック予算で評価する。各ワークロードは五十課題の追跡列を使い、合計九百四十八〜千四百十七ターンを含む。標準推論基盤と固定時間保護型の鍵値キャッシュ方式を比較し、ヒット率、ターン単位の端から端までの遅延、一秒当たりターン数を測る。加えて初回ターン中に共有可能アンカーが占める割合と、現在エージェントを条件にした次エージェント不確実性の減少を測定する。
キャッシュが圧迫される小さなブロック予算を設定し、セッション間共有アンカー保持の効果を測る。主要モデルと演算装置は一種類で、五ワークロードのうち一つは合成である。完全な記憶量・遅延微小測定、キャッシュ予算や並行度への感度、実行時層を無効化した比較は拡張版へ延期されている。
## 主要結果
キャッシュスカウトは五ワークロードすべてで標準推論基盤および固定時間保護方式より高い鍵値キャッシュヒット率と低いターン遅延を示した。標準基盤比のヒット率改善は十三〜三十七ポイント、本文では端から端までのターン遅延を六〜二十六パーセント削減し、処理量を六〜十四パーセント改善する。要旨は平均初回トークン待ち時間を十二〜二十九パーセント低減と要約しており、本文のターン遅延とは別指標である。共有可能なアンカーは初回ターン入力の三十四〜五十二パーセントを占め、現在エージェントを条件にすると次エージェント不確実性は四十〜四十八パーセント減る。重要経路の負担はブロック接触観測が約一マイクロ秒、生存近似採点が一桁マイクロ秒、二十四エージェントでも状態量は二十五キロバイト未満である。

- 鍵値キャッシュヒット率改善 / 十三〜三十七ポイント (比較対象: 標準推論基盤; 条件: 五つの複数エージェントワークロード) — セッション境界で落ちやすい共有アンカーを次エージェント予測で保護・先読みする。

- ターン単位の端から端までの遅延 / 六〜二十六パーセント削減 (比較対象: 標準基盤および固定時間保護方式; 条件: 五ワークロード) — キャッシュヒット増加で事前充填の再計算を減らす。要旨の初回トークン待ち時間低減とは別指標。

- 処理量 / 六〜十四パーセント改善 (比較対象: 標準提供構成; 条件: 五ワークロード) — 共有アンカーの再計算削減が演算余力を生み、一秒当たりターン数を増やす。

- 初回ターンの共有可能面積 / 三十四〜五十二パーセント (比較対象: なし; 条件: 実ワークロードの性質分析) — 各セッション冒頭入力の三〜五割が複数セッションで共有可能なアンカーとなる。

- 次エージェント不確実性の相対減少 / 四十〜四十八パーセント (比較対象: 現在エージェント情報なし; 条件: 五ワークロード) — 一次マルコフ連鎖だけでも再利用予測へ十分な信号が得られる。

- 実行時層の負担 / 観測約一マイクロ秒、採点一桁マイクロ秒、状態二十五キロバイト未満 (比較対象: なし; 条件: 二十四エージェント以下) — 予測方針自体の重要経路負担が小さく、キャッシュ利得を大きく相殺しない。

### 負の結果・境界条件
- 固定時間保護方式は四実タスク中三つでヒット率を九〜二十三ポイント下げたと報告され、固定時間の保護が短いターン間隔と合わない場合にキャッシュ汚染を起こす。キャッシュスカウトの評価も予備的で、完全な記憶量・遅延微小測定、キャッシュ予算と並行度への感度、実行時層無効化比較を今後へ延期している。九つの提案方針のうち実測したのは鍵値キャッシュだけである。

### 結果の読み方
利得の源泉はエージェント情報をキャッシュキーに置き換えることではなく、従来のブロックハッシュによる正しい保存・照合を維持したまま、エージェント識別子を将来利用価値の予測索引として追加することにある。セッション間の空白時間だけでは落ちる共有アンカーに、遷移学習が追加の再利用信号を与える。静的な固定時間保護と異なりワークロードごとの遷移をオンライン学習し、構造が弱い場合に従来方式へ近づくため過保護を抑えられる。
## 品質への影響
生成品質を近似・圧縮する手法ではないため、正答率低下を主要結果として扱わない。ただし先読みを外した場合には余分な計算とキャッシュ占有が生じ、追い出し順序の変更は他要求のヒット機会へ影響し得る。
## 既存研究との差
既存のエージェント対応鍵値管理には、道具実行中や複数ターン中の鍵値を固定時間保護・移動する方式や、配置時にエージェント手順グラフを宣言して追い出しを最適化する方式がある。キャッシュスカウトは実際の呼出し履歴から遷移を学習し、ワークロードごとに変化する経路へ適応する。さらに論文はキャッシュスカウト単体を目的にせず、エージェント単位のメタデータと推論エンジンの実行イベントを統合する独立した実行時層を置く。エージェント対応スケジューリングをエンジン内部へ直接埋め込む方式と比べ、方針ごとの内部改修を観測・採点・予測・作用という共通フックへ局所化することを狙う。
## 限界
本論文は実行時層の設計提案にキャッシュスカウトという一事例を組み合わせた予備的研究である。九つのエージェント対応方針を同じ四原語へ整理するが、実装・定量評価されたのは鍵値キャッシュだけで、バッチ形成、事前充填と逐次生成の分離配置、投機的エージェント実行、公平性、安全、再試行などは未実装課題として残る。評価は演算装置一種類、八十億級モデル一種類、六エージェント監督構成が中心で、別枠組み・別モデル・大規模クラスタでの移植性は未検証である。さらにキャッシュ予算や並行度への感度、実行時層を無効化した比較、完全な記憶量・遅延微小測定は拡張版へ延期されている。
## 実装状態
キャッシュスカウト事例はエヌビディアH100上の大規模言語モデル推論基盤へ接続して実測され、遷移学習器、生存近似採点器、セッション間先読みを実装している。ブロック接触観測と追い出し採点参照の二つのエンジンフックを使い、先読みは通常の提供経路を通る。一方、実行時層が列挙する他八方針は完成実装ではなく、著者公式コード公開先も本文で確認できない。
## 研究上の位置づけ
エージェント型大規模言語モデル提供における意味情報と実行情報の断絶を埋める中間制御層の研究として位置付けられる。従来のスケジューラ、鍵値キャッシュ、投機実行研究が個別にエージェント情報を取り込むのに対し、エージェント識別子を共通座標として複数方針へ再利用可能な実行時抽象を提案する。鍵値研究としてはセッション間の接頭辞再利用と予測的追い出し・先読みの系統であり、提供アーキテクチャとしては枠組みと推論エンジンの間に方針制御層を追加する提案である。
