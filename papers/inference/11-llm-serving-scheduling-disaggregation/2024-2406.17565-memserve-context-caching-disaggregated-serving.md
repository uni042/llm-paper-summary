# MemServe: Context Caching for Disaggregated LLM Serving with Elastic Memory Pool

## 一文要約

分離推論（disaggregated inference）と要求間の文脈キャッシュ（context caching）を同時に使えるよう、GPU HBM・CPU DRAM上のKV cacheを推論instance横断で管理・検索・転送する弾力的memory pool `MemPool` と、cache localityを考慮するglobal schedulerを導入したLLM serving system。

## 問題設定

LLM servingでは、同じprefixを持つ別request間で過去のKV cacheを再利用する文脈キャッシュと、prefill / decodeを別instanceへ分けて干渉を減らす分離推論がそれぞれ有効である。しかし従来のserving engineはKV cacheを「1 request・1 instanceに閉じた中間状態」として扱う設計が多く、両者を組み合わせにくい。

分離推論ではprefillで作ったKVをdecode instanceへ転送する必要があり、さらにそのKVを将来のrequestへ再利用するには、request終了後もcluster内のどこにKVが残っているかを検索し、必要なinstanceへ移せなければならない。また複数instanceへのroutingを単純なloadだけで決めると、別instanceに存在する長いcached prefixを使えず再prefillが発生する。

## 手法

### 1. 弾力的memory pool（MemPool）

MemPoolは各推論instance上で動作し、cluster内のGPU HBMとCPU DRAMをKV cache用の分散memory substrateとして扱う。主に次の3種類のAPIを提供する。

- **memory block管理:** 固定長blockの確保・解放、HBMとDRAM間のswap。
- **index管理:** prompt token列とKV cache addressを対応付け、実行中のactive KVだけでなくrequest終了後のhistorical KVも検索可能にする。
- **分散転送:** instance間でKVを転送し、送信元と受信先でparallelism、network、memory mediumが異なる場合もtransfer layer側で吸収する。

これによりinference engine自身が「KVがどのinstance・どのmemoryにあるか」を個別に扱う必要を減らす。

### 2. 文脈キャッシュとP/D分離の統合

MemServeはMemPool APIを使い、通常のprefill/decode同居構成だけでなくP/D分離構成でもhistorical KVを再利用する。prefill側でcached prefixを使うだけでなく、decode側に存在するKVも再利用対象とし、必要ならdecodeからprefillへKVを戻して将来のrequestで利用できるようにする。

この点がDistServe / SplitwiseのようなP/D分離だけの設計との大きな違いで、**phase間KV transferを一度きりのrequest state移動ではなく、cluster全体で再利用可能なstate管理へ拡張する**。

### 3. memory layoutとnetwork transferの協調

PagedAttention型の細かなKV blockをそのままpoint-to-pointで多数転送するとnetwork API callが増える。MemServeは複数blockを大きな転送単位へまとめるblock aggregation（論文ではhuge-page的な設計）を使い、分散KV transferのoverheadを減らす。

### 4. global prompt treeによるlocality-aware scheduling

schedulerは各instanceにどのprefix KVが存在するかをglobal prompt treeとして把握する。request routingでは単純なqueue lengthだけでなく、再利用できるprefix長と待ち時間を考慮し、既存KVを多く使えるinstanceへrequestを寄せる。

これはSGLangのような単一runtime内のprefix cacheを、**複数serving instanceを跨ぐrouting decisionへ引き上げる**方向の設計である。

## 実装・評価条件

- MemPool / global schedulerを新規実装。
- vLLMを改造して文脈キャッシュとP/D分離を統合。
- GPU間転送にはNCCL send/recv、DRAMが関わる転送にはsocketを使用。
- 主評価環境は **8× NVIDIA H800 80GB** の単一server。
- ShareGPT、LooGLEなど、prompt / generation長やprefix共有率の異なるworkloadで評価。
- P/D同居、同居＋cache、P/D分離、P/D分離＋cacheを比較する。

## 主要結果

論文v3で報告される代表値は以下。

- ShareGPTではMemPoolベースのP/D分離により、P/D同居構成に対してjob completion time (JCT)を最大 **42%改善**。
- さらにP/D分離へ文脈キャッシュを加えることで、JCTを追加で最大 **29%改善**。
- 長prompt・比較的短いgenerationを持つLooGLEでは、P/D分離がJCTを最大 **10.8%改善**し、文脈キャッシュの追加でさらに最大 **26.9%改善**。

重要なのはcache単体やP/D分離単体の高速化より、両者が必要とするKV state管理を共通基盤へまとめ、組合せ可能にした点にある。

## 既存研究との差

- **vLLM / PagedAttention:** request内のKV block管理とmemory fragmentation削減が中心。MemServeはそのKVをrequest終了後・instance横断まで長寿命化し、分散memory objectとして扱う。
- **SGLang:** shared prefixをradix treeで保持してrequest間reuseする。MemServeはこの種のcontext cachingをP/D分離clusterへ広げ、remote KV transferとglobal routingまで扱う。
- **Pensieve / CachedAttention:** multi-turn historyをGPU / CPU / storageへ保持して次turnの再prefillを減らすstateful serving。MemServeはsession単位だけでなくshared prefixをcluster-wideに検索し、P/D間でも移動・再利用できるmemory substrateを主題にする。
- **DistServe / Splitwise:** prefillとdecodeを分離してphase interferenceやresource allocationを改善する。MemServeはそのphase間KV transferをhistorical cache reuseと統合する。
- **Mooncake:** 同じくP/D分離とglobal KV cacheを強く結び付ける後続のKV-centric architecture。MemServeはMemPoolという汎用distributed memory APIとcontext caching / intra-request optimizationの統合を中心に据える。

## 実装上の含意

LLM servingをstatefulにするほど、schedulerだけでなくKV cacheの**所在・寿命・index・transfer**をcluster-wide resourceとして扱う必要が出る。特にP/D分離、prefix caching、session cache、sequence parallelismを個別機構として実装するとKV transfer pathが重複しやすく、MemServeのような共通memory substrateを挟む設計は組合せ爆発を抑える方向として有用である。

一方、cache localityを優先しすぎれば特定instanceへrequestが集中するため、実運用ではprefix hitの計算削減量とqueueing delay、KV transfer costを同じcost modelで比較する必要がある。

## 限界

- 主評価は8×H800の**単一server**であり、複数node・異種networkを跨ぐ大規模clusterでのscalabilityは評価範囲が限定される。
- historical KVを長く保持するほどcache capacityとeviction policyが重要になるが、storage tierまで含む大規模階層cacheが主題ではない。
- prefix locality-aware routingはcache reuseを増やす一方、load balanceとのtrade-offを持つ。
- model weight placementやserverless cold startそのものは扱わない。

## 引用関係・研究系統上の位置

MemServeはvLLM、SGLang、Pensieve、Splitwise、DistServeなどを土台に、**context cachingとdisaggregated inferenceを同一KV memory substrateで結合する**位置にある。後続のMooncakeなどと合わせると、serving architectureが「compute instance中心」から「cluster-wide KV state中心」へ移る流れを理解しやすい。

研究系統としては `LLM Serving / Scheduling / Disaggregation` に分類する。KV cache offload自体ではなく、distributed KV managementを使ってserving architectureとrequest routingを改善することが最終目的だからである。
