# Seesaw: High-throughput LLM Inference via Model Re-sharding

> プリフィルとデコードでモデルの並列分割を動的に切り替え、CPU階層KVバッファと遷移最小化で再配置費用を償却し、vLLM比最大1.78倍・平均1.36倍のスループットを達成する。

## 概要

分散LLM推論では、モデル重みを複数GPUへどう分けるかが性能を大きく左右す。テンソル並列（tensor parallelism; TP）は一つの層の行列演算をGPU間で分割するため各GPUが同じ層を同時に進められる一方、層ごとに集合通信が発生する。パイプライン並列（pipeline parallelism; PP）は層のまとまりをGPUごとに置き、要求やマイクロバッチをパイプラインへ流すため、層内の頻繁な集合通信を避けられるが、処理するトークン数が少ないと段間の空き時間が目立つ。

LLM推論には、入力プロンプトを一括処理するプリフィル（prefill）と、1トークンずつ生成するデコード（decode）がある。プリフィルは一度に多数トークンを行列積へ投入できるため計算律速になりやすく、PPでも各段へ十分な仕事を供給できる。デコードは各系列が一度に1トークンしか進まないため、重み読出しやKVキャッシュ容量が支配的になりやすく、大きなバッチで重み読出しを償却できるTPが有利になる場合がある。つまり、一つの固定並列設定を両段階に使うと、どちらか一方へ妥協することになる。

Seesawはこの非対称性を前提に、プリフィルとデコードの境界でモデル重みとKVキャッシュのシャーディングを動的に切り替える**動的モデル再シャーディング（dynamic model re-sharding）**を提案する。代表例ではプリフィルをPP4、デコードをTP4で処理し、それぞれの段階で単独に最適な並列方式へ近づける。

ただし、連続バッチ（continuous batching）では新規プリフィルと既存デコードが細かく交互に現れる。そのたびに重みを再配置すれば切替費用が利得を食い潰す。SeesawはCPUメモリを補助KVバッファとして使い、プリフィル済み要求のKVを一時退避して要求をためる。CPU側のKVバッファが十分埋まってからデコード段階へまとめて切り替えることで、再シャーディング回数を減らしつつデコードの大バッチを確保する。

MLSys 2025の評価では、NVIDIA A10、L4、A100を用い、15B・34B・70B級モデルをShareGPTとarXiv要約ワークロードで測定する。vLLM 0.5.4に対してエンドツーエンドスループットは最大1.78倍、全体の幾何平均で1.36倍となる。利得は特にGPU計算に比べGPU間通信が遅いPCIe系で大きく、NVLink接続A100では差が縮む。

## 背景: なぜプリフィルとデコードで最適並列が変わるか

TPでは各層の重みを複数GPUへ横方向に分けるため、一つのトークンを全GPUで共同処理できる。GPUごとの重み量とKV負担を分散しやすく、デコード時には多くの系列を同時に載せて重み読出しを償却しやすい。一方、各層で全還元（all-reduce）などの通信が必要になり、プリフィルの大きな行列積が高速になるほど通信待ちの割合が増える。

PPでは層をGPUごとに縦方向へ分け、各GPUは自分の層だけを持つ。層内のTP通信を避けられるため、入力トークンが多く各段に十分な計算があるプリフィルでは効率が高い。一方、デコードでは1系列あたりの仕事が小さく、パイプラインを埋めるのに多数要求が必要で、段間の空きや同期が相対的に大きくなる。

Seesawの測定では、たとえば4枚A10上のCodeLLaMA-34BとarXiv要約でTP4がデコードに有利、PP4がプリフィルに有利となる。固定構成ではTP2+PP2のような折衷を選ぶことになるが、どちらの段階でも段階専用の最適構成には届かない。Seesawは「並列方式はモデル起動時に固定するもの」という前提を外し、推論段階ごとに変える。

## 問題設定

動的再シャーディングには二つの費用がある。第一は、プリフィル用配置からデコード用配置へモデル重みを動かす費用である。第二は、KVキャッシュの分割軸や配置も並列方式とともに変わるため、各要求のKVをGPU間またはCPU-GPU間で移し直す費用である。

通常のプリフィル優先スケジューリングでは、新規要求が来るたびプリフィルを挟み、その後デコードへ戻る。この挙動と再シャーディングを単純に組み合わせると「プリフィル→デコード→プリフィル→デコード」と切替が頻発する。逆にデコード優先で一群の要求を最後まで生成してから次のプリフィルへ移ると切替回数は減るが、GPU上の系列数が減ってデコードバッチが小さくなり、重み読出しを十分償却できない。

したがって必要なのは、段階ごとに最適な並列方式を選ぶだけではなく、**切替回数を少なくしながらデコード時の系列数を大きく保つスケジューリング**である。

## 手法

### 1. 段階ごとにTP/PP構成を選ぶ動的モデル再シャーディング

Seesawは各ハードウェア、モデル規模、GPU数について、プリフィルとデコードに適したテンソル並列度・パイプライン並列度を選ぶ。実行時にはプリフィル群を一つの構成で処理し、十分な要求がたまった段階でモデルを再シャーディングしてデコード用構成へ切り替える。

論文ではデータ並列（data parallelism; DP）まで頻繁に動的変更する方式は採らない。DP度を変えるとモデルレプリカ数が変わり、GPUメモリにおける重みとKVキャッシュの配分が大きく変化して追加のデータ移動が増えるためである。主にTPとPPを動かすことで、並列切替の自由度と再配置費用のバランスを取る。

再シャーディング時にはモデル重みだけでなくKVキャッシュの配置も整合させる。たとえばPPでは層方向、TPでは注意ヘッドやテンソル次元方向の分割が変わるため、同じKVを別のワーカー配置へ変換する必要がある。

### 2. CPUを使う階層KVキャッシュバッファ

頻繁な段階切替を避けるため、Seesawはプリフィルが終わった要求のKVキャッシュをCPUメモリへ書き戻す。GPUは次のプリフィル要求を処理し続け、CPU側には「デコード待ち」のKVが蓄積される。

CPUバッファが満たされたタイミングでプリフィルからデコードへ切り替え、必要なKVをデコード用シャーディングへ変換しながらGPUへ戻す。これにより一度のモデル再シャーディングで多数要求をまとめてデコードでき、再配置費用を多くのトークンへ償却できる。

CPUメモリは単なる容量退避先ではなく、KV再シャーディングの中間共有領域としても使われる。GPU間で直接複雑な再分配を行う代わりに、プリフィル後のKVをCPUへ戻す段階と、デコード前にCPUから読み込む段階で新しい配置へ整える。

### 3. 遷移最小化スケジューリング

スケジューラはCPU KVバッファの占有量を使って段階切替をまとめる。プリフィル期間では新規要求を連続して処理し、CPU側に十分なKVがたまるまでデコードへ移らない。デコードへ切り替えた後は、大きな系列集合を一括して処理する。

この方式は、プリフィル優先の「常に新規要求をすぐ混ぜる」低待ち時間指向とは異なる。Seesawの対象は高スループットのオフライン推論であり、個々の要求の初回応答時間を最小化するより、GPU群全体が単位時間に処理できるトークン数を増やすことを優先する。

### 4. 非同期KV転送とメモリ配置

CPU-GPU間KV転送が直列に入ると階層バッファの利得が失われるため、Seesawは非同期パイプライン（asynchronous pipeline）を使う。デコード用KVの読み込みはプリフィル計算と重ね、プリフィル後のKV書き戻しは別のプリフェッチャースレッドで処理する。

CPU上のKV配置には、ヘッド・系列・ヘッド次元の順に並べるHND配置を利用する。TPでは注意ヘッド方向へKVを分けるため、ヘッドが連続するHNDの方が、系列を先に置くNHD配置より再シャーディング時に連続アクセスを作りやすい。こうしたデータ配置まで含めて、再シャーディングの理論利得を実際の転送帯域へ変換する。

## 既存研究との差

vLLMなど一般的な推論基盤は、一度選んだTP/PP構成をリクエストの生存期間を通じて固定する。チャンク化プリフィル（chunked prefill）は長いプリフィルを分割してデコードと混ぜることでGPU利用率や待ち時間を改善するが、プリフィルとデコードで**モデル配置自体を変える**わけではない。

プリフィル・デコード分離（prefill-decode disaggregation）は両段階を別GPU群へ置くことでそれぞれに最適化できるが、段階ごとに専用資源を確保し、KVをネットワーク越しに転送する必要がある。Seesawは同じGPU集合の中で時間方向に配置を変えるため、追加クラスタを恒常的に分けずに段階特化を狙う。

CPUオフロード型推論は重みやKVの一部をCPUへ逃がしてGPU容量不足を補うことが主目的である。SeesawのCPU KVバッファは、容量拡張だけでなく「段階切替をまとめるための待機領域」と「KV再シャーディングの中間領域」というスケジューリング上の役割を持つ点が異なる。

## 限界・実装状況

Seesawは高スループットのオフライン推論を主対象とする。プリフィル済み要求をCPUバッファへためてからデコードへ移すため、個々の要求の初回トークン時間（Time To First Token; TTFT）を最小化する対話型配信とは目的が異なる。低遅延サービスへそのまま適用すると、待機時間がサービス品質目標（Service-Level Objective; SLO）に抵触する可能性がある。

利得はGPU間帯域に強く依存する。PCIe環境ではTPの集合通信を避ける価値が大きいが、NVLinkのように高速な接続では差が小さくなる。さらにCPU-GPU帯域が低い環境では、階層KVバッファの転送自体が新しい律速になり得る。

モデル再シャーディングとKV再配置は実装を複雑にする。Seesawは非同期化とHND配置で費用を隠すが、短い出力でデコード期間が短い場合や、十分な要求数がなく大バッチを作れない場合は、切替費用を償却しにくい。
