# SPLASH：注意並列の所有権分離と稼働中の配置切替

## 概要

SPLASHは、LLM推論配信中に注意演算のGPU間並列配置を切り替えるシステムである。少数の同時要求にはテンソル並列（TP）、多数の独立要求には注意のデータ並列（DP-attention）、非常に長い文脈には文脈並列（CP）が有利になりやすい。推論型エージェントや強化学習のロールアウトでは、開始時に多数の短い要求があり、完了が進むにつれて少数の長文脈要求が残る。固定した並列配置では、時間とともに最適な方式から外れてしまう。

著者は注意投影重みの配置とKVキャッシュの所有権を独立した二軸で整理し、両方の複製を避ける第四の配置、分離所有並列（Decoupled Ownership Parallelism、DOP）を提案する。さらに、切替前後で同じGPUに残せる重み・KVを再利用し、不足分を次の層の計算に間に合うよう転送することで、処理中の要求を停止せずに配置を切り替える。B200でGLM-5.3を配信する評価では、固定配置に対する端から端までの総処理量が1.3～1.73倍となる。B200、16要求、各256K文脈という切替測定では、12方向の切替追加時間中央値は0.02～11.76ミリ秒で、対応する長い一ステップ時間の0.51%未満である。これは**任意の短い推論ステップでも同じ割合になるという主張ではない**。

## 問題設定：なぜ注意配置を変えにくいか

注意機構の投影行列は読み取り専用の重みである一方、各要求のKVキャッシュは生成トークンとともに増える可変状態である。TPでは投影重みをヘッド方向に分割するが、多頭潜在注意（MLA）の潜在KVはヘッドごとに分割できず、同じ要求の履歴を複数GPUへ複製しがちになる。DP-attentionでは要求単位でKVを分配できる反面、注意投影重みを各GPUへ複製する。CPでは文脈位置方向に履歴を分割するが、やはり投影重みの複製が必要になる。

切替時には、新配置で必要な重みとKVが適切なGPUへ存在し、各要求の過去トークンの順序と位置情報が失われず、全GPUの集合通信の順番が一致しなければならない。いったん要求を排出してワーカーを再起動する方式なら整合性は保ちやすいが、長い生成ほど排出に時間がかかる。配置を変えるべき長文脈の局面で、切替自体が最も高価になる逆説がある。

SPLASHは注意部分だけの並列配置を変え、密結合層や混合専門家（MoE）層の並列化は維持する。重みとKVの配置の違いを明示的に数えれば、全状態を移し直す必要がない。旧配置と新配置が同じブロックを持つ場合、そのブロックは移動せず再利用する。この「差分だけを運ぶ」という性質が、稼働中の切替を成立させる。

## 手法

### 1. 注意重みとKV所有者の二軸モデル

GPUランク数を$T$、要求数を$B$、各要求の文脈長を$s$、注意投影重み総量を$W_A$、1トークンのKV容量を$k$とする。均衡した要求とMLAを仮定した一GPU当たりの保持量は、TPで$W_A/T+Bks$、DOPで$W_A/T+Bks/T$、DP-attentionとCPで$W_A+Bks/T$となる。TPはKVを複製し、DP-attentionとCPは重みを複製するが、DOPは両方を一度ずつしか保持しない。

この式は「DOPがいつも速い」ことを意味しない。容量の余裕と通信費は別の評価軸である。DOPは重みとKVの複製を省けるため、メモリ制約で受け付けられる要求数が増える可能性がある。一方、要求所有者が全注意ヘッドの問い合わせを処理できるよう、各層で活性値をGPU間に交換する費用が生じる。モデルが通常の多頭注意でKVヘッドをTP分割できる場合、MLAほどDOPの容量上の優位は大きくない。

### 2. DOPの計算と通信

DOPでは投影重みをTPのようにヘッド方向へ分割する。各GPUが問い合わせの一部ヘッドを計算した後、全対全通信（all-to-all）によって同じ要求に属する問い合わせをKV所有者へ集める。所有者は自分の要求の全KV履歴を使って注意演算を行い、結果を逆方向に交換して元の重み分割配置へ戻す。入力はヘッド分割された問い合わせと要求所有のKV、出力はヘッド分割へ戻した注意結果である。

追加の活性通信量は各ステップの問い合わせ行数に比例し、保持済み文脈長に直接比例しない。長文脈では重み・KVの複製削減が効く一方、短文脈や少数要求では毎層の全対全通信が相対的に重くなる。B200、GLM-5.3、FP8、8ランクでは重み複製の削減により一GPU当たり12.69GiBのKV用余地を得ると著者は算定する。これはGPUメモリを増設したのではなく、重複保持を除いた結果である。

### 3. 四配置間の12方向を差分転送へ分解

四つの配置には順序付きで12通りの切替がある。各GPUの旧配置で保持するKV集合と、新配置で必要なKV集合の差を計算し、投影重みについても同じ差分を求める。新配置が旧配置の部分集合で済むなら不要分を破棄するだけでよく、ネットワーク転送は不要である。各GPUに分散しているブロックを全員が必要とする場合は全収集（all-gather）、要求単位の所有から文脈位置単位の所有へ移す場合は全対全通信を使う。

たとえばTP→DOPでは、各GPUが保持していた複製KVのうち所有者以外のコピーを捨てる。DP-attention→DOPでは、要求所有のKVを保持し、複製された投影重みを不要なGPUで破棄する。これらは状態を運ぶ必要がほとんどない。反対にDOP→CPでは、投影重みの全収集とKVの所有再配置の両方が必要になる。切替費用が方向によって大きく異なるのは、この必要差分の非対称性による。

差分の再利用には、量子化尺度、データ精度、位置符号化規約、KV索引、再帰状態などの互換性が必要である。単に同じ大きさのバイト列があれば使い回せるわけではない。著者はこれらの状態を切替対象の層とともに扱い、全GPUが同じ通信順序を実行するようにする。

### 4. 層単位の転送・計算重畳と切替境界

切替は通常の推論ステップの境界で開始する。まず第一層に必要な不足状態を転送し、層$i-1$を新配置で計算している間に、別の通信ストリームで層$i$の不足状態を転送する。層$i$は必要な重み・KVが揃った後で実行する。転送済みの旧ページは安全に解放し、後続ステップでは起動時に取得しておいた新配置用のCUDA Graphを再利用する。

GLM-5.3は78層で、B200、FP8、8ランクにおける注意投影重みの全層分は約11.3GiBに相当する。切替時に一度に移すのは原則として一層分、約145.73MiBで済むため、全層の重みを二重に常駐させずに切り替えられる。ただし切替中には旧配置・新配置のどちらか大きい方の保持量に加え、一層分の転送バッファと予約領域が必要になる。SPLASHはこの一時容量も事前に検査し、溢れる切替を許可しない。

切替による露出時間は第一層の転送と、後続層の転送が直前層の計算時間を超えた残り時間の和で近似される。層の計算が通信を十分に隠せるほど長い場合に利益が大きく、計算が短い場合や通信帯域が混雑する場合には転送待ちが露出する。したがって「通信量を減らす」のではなく、**必要差分を減らし、残る通信を計算へ重ねる**のが二段階の設計である。

### 5. 負荷追従の配置選択

制御器は現在の同時要求数、要求ごとの文脈長、各ステップの問い合わせ行数を入力にする。GPU数・容量・演算速度・重み読出帯域・KV読出帯域・集合通信帯域と固定遅延を環境別に較正し、四配置それぞれの一ステップ時間を予測する。候補が定常状態でメモリに収まるだけでなく、切替途中の一時領域まで収まることを条件に、実行可能な配置から最短予測時間の方式を選ぶ。

新配置が現在方式より所定の余裕幅だけ速い場合にのみ切り替える。これにより負荷が境界付近を往復する際の過剰な切替を抑える。選択するのは注意の並列配置であり、要求の受入数やバッチ形成自体を同時に最適化する方式ではない。切替費用が方向ごとに違うため、モデルとGPUに応じて余裕幅を調整する必要がある。

## 評価

### 測定環境と指標

| 項目 | 原著の設定 | 解釈 |
|---|---|---|
| 実装 | SGLang 0.5.10を拡張 | 著者公開実装、上流標準機能ではない |
| B200主評価 | GLM-5.3、78層、FP8重み・FP8 KV | 事前処理側8GPU、生成側16GPUの分離配信 |
| 追加環境 | H200でDeepSeek-V3.2、BW1000 DCUでGLM-5.3-Flash | 異種GPUで傾向を確認 |
| 固定配置比較 | 入力1K～512K、同時要求16/32、または入力64K/128Kで同時要求1～256 | 四配置×32測定位置＝128測定 |
| 出力 | 各要求1,024トークン | 入力・出力の両方を総処理量の分子に含める |
| 測定統計 | 固定配置は各点10回平均 | 切替では中央値とp95を提示 |
| 切替実験 | B200、16要求、各256K文脈 | 長い一ステップでの転送隠蔽を測定 |

固定配置の総処理量は、要求数×（入力トークン数＋1,024）を、待ち行列、事前処理、KV転送、生成を含むバッチ完了時間で割った値である。純粋なデコードの生成トークン毎秒ではない。B200の事前処理・生成分離構成では生成側の注意配置を共通にし、主として事前処理側の配置の違いを測る。従って報告倍率を単一注意カーネルの速度倍率へ読み替えない。

### 文脈長・同時要求数ごとの優勢配置

| B200/GLM-5.3の条件 | 最も速い配置 | 根拠と限界 |
|---|---|---|
| 同時要求16、入力1K～4K | TP | 少数短文脈では重み分割の利点 |
| 同時要求16、入力16K～64K | DP-attention | 独立要求の分配が有利 |
| 同時要求16、入力128K | CP | 文脈を位置方向に分割 |
| 同時要求16、入力256K～512K | DOP | 長文脈の容量・通信の均衡 |
| 同時要求32、入力1K | TP | 短文脈での低固定費用 |
| 同時要求32、入力4K～32K | DP-attention | 要求数に応じた優勢領域 |
| 同時要求32、入力64K～128K | CP | 文脈処理の分割が効く |
| 同時要求32、入力256K～512K | DOP | 長文脈での重複保持削減 |
| 入力128K、同時要求256 | DOP 30,724 tok/s、CP 27,677 tok/s | DOPが9～11%程度優勢 |
| 入力128K、同時要求1/4 | DOPはCPより42.2%/35.1%遅い | DOP常時使用は不適切 |

固定配置の32測定位置のうち、DOPが最速なのは8位置だけである。64K文脈では同時要求1でTP、4～16でDP-attention、32～64でCP、128～256でDOPが優勢となる。ロールアウトの要求が完了して同時要求数が減っていくと、同じモデルでも最適な配置が順に変わることが確認できる。DOPの強みは常時最速であることではなく、容量が足りない場合の選択肢を増やすことである。

### KV容量と要求受入

B200のメモリ使用率85%設定では、保持できる異なるKVトークン数はDOPが8,271,360、DP-attentionが6,497,792、CPが6,738,944、TPが1,045,312である。DOPはDP-attentionより27.3%、CPより22.7%多く保持できる。H200のメモリ使用率90%設定ではDP-attentionより59.7%多く、DCUでは一所有者当たりの容量が1,118,656対940,224トークンで19.0%多い。

GLM-5.3で512K文脈の要求を保持する例では、DOPなら16要求、DP-attentionでは12要求が常駐できる。容量が増えた結果、GPUを増やさずに受入可能な要求数が増える。ただしDOPの活性交換費用は毎層発生するため、容量だけを根拠にDOPへ固定するのは不適切である。

### 転送原語と切替追加時間

| 条件 | 測定値 | 意味 |
|---|---|---|
| B200、一層の重み全収集 | 0.292～0.302ms | 重みの転送量は文脈長と独立 |
| B200、16要求・各256K文脈、一層のKV転送 | 3.471～3.807ms | KV転送量は文脈総量に比例 |
| 全12方向の切替追加時間中央値 | 0.02～11.76ms | 長い一ステップ中の露出時間 |
| 同切替追加時間p95 | 0.07～16.79ms | ばらつきの大きい側 |
| ネットワーク転送を伴う10方向、ブロッキング比 | 中央値の切替追加時間98.24～98.78%減 | 層計算への転送隠蔽 |
| CP→TP | ブロッキング606.53ms、提案7.78ms | 大部分の転送が隠蔽される |
| DOP→CP | ブロッキング667.31ms、提案11.76ms | 重みとKVの両方を移す重い方向 |
| TP→DOP、DP-attention→DOP | いずれも中央値0.02ms | 旧状態の破棄・再利用のみ |

「切替の中央値追加時間が一ステップの0.51%未満」という比率は、256K文脈で対象の一ステップが1.96～5.53秒もかかる条件に依存する。短文脈・小バッチのステップが数十ミリ秒なら同じ追加時間の割合は大きくなり得る。また三つのTP向け切替は通信費用を測定していても、この256K条件で実際にメモリ容量を超える場合は制御器が切替を拒否する。計測できる転送原語と運用上の実行可能性は別である。

### 固定配置に対する全体効果

B200上のGLM-5.3では、負荷に応じた四配置の選択により固定配置比1.3～1.73倍の端から端までの総処理量を報告する。ここには個々の配置の適材適所、DOPによるKV容量増、層単位の転送・計算重畳が関係する。追加のH200とDCUでも同様に文脈長や同時要求数で優勢な配置が変わる傾向を観測しているが、B200の改善倍率を他環境へそのまま当てはめない。

## 既存研究との差と限界

従来の並列配置切替は特定の二方式だけを対象にしたり、切替中に要求を停止したりする場合が多い。SPLASHは重み所有とKV所有を別軸として形式化し、四配置の全12方向を同じ差分転送規則で扱う。PagedAttentionやKV量子化はキャッシュ表現・容量を変える技術であり、本方式は既存キャッシュのGPU間所有を変える技術である。MoE専門家の並列化を同時に変えるわけでもない。

効果が大きいのはMLAのようにKVヘッド数が少なく、TPでKVが複製されやすいモデルである。通常の多頭注意でヘッド別KV分割がすでに効く場合、DOPの容量優位は縮む。切替の一時メモリ余地がなければ実行不能であり、層計算が短い場合や通信が混雑する場合は転送を十分に隠せない。位置規約、キャッシュ索引、再帰状態、量子化尺度、CUDA Graphの参照先なども一貫して移す必要がある。制御器は注意配置を選ぶが、要求受入とバッチサイズを共同最適化していない。

著者の公開実装はSGLang 0.5.10を基礎にした別リポジトリであり、上流SGLangへ標準統合済みと断定できない。B200の主実験は複数GPUでの分離配信構成であり、単一GPU環境で同じ改善を期待できない。論文中の図1および付録Bの一部の曲線は仮定を置いた性能モデルで、実測の図4・表1と区別する必要がある。評価結果はモデル、GPU、メモリ予算、文脈長、同時要求数、転送と計算の重なり方に依存する。
