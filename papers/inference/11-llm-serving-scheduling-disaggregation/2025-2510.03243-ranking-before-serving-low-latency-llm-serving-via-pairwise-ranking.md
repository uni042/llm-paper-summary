# Ranking Before Serving: Low-Latency LLM Serving via Pairwise Learning-to-Rank

> PARSの要点は「出力長を正確に当てる」ことではない。SJF型スケジューリングに必要なのは、待機中の要求について**どちらを先に流すべきかという相対順序**である。絶対長回帰を捨て、長さ差が十分ある要求対だけから順位を学ぶことで、生成長のノイズを避けながらHOL blockingを減らす。

## 概要

LLMサービングでは、同じ入力長でも出力長が大きく異なる。特に推論モデルでは、単純な質問に数十トークンで答える場合と、数千トークンの思考を生成する場合が混在する。

vLLMのような連続バッチ処理はGPU利用率を高めるが、待機列の順序問題は残る。FCFSでは長い要求が先に入ると、その要求がバッチ内で長く生き残り、後ろの短要求の完了時間を押し延ばす。古典的なSJFなら短要求を先に処理して平均完了時間を下げられるが、ジョブ長である最終出力トークン数は到着時点では未知である。

既存の出力長予測は「何トークン出るか」を回帰する。しかし同じプロンプトでもサンプリングやモデル挙動で長さが揺れ、絶対誤差が大きくなりやすい。さらにスケジューラにとって、1200と1300を正確に当てることより、100と3000の順序を間違えないことの方が重要である。

PARSはこの観察から、予測対象を絶対長から相対順位へ変える。BERTでプロンプトを埋め込み、成対順位損失（margin ranking loss）で「AよりBの方が長い」を学ぶ。長さ差が小さい要求対は訓練から除外し、不安定なラベルを減らす。

オンラインでは各要求へ順位スコアを付け、短いと予測される順へ待機列を並べる。一定時間以上待った要求には優先度ブーストを与え、長要求が永久に後回しになる飢餓を防ぐ。

## 背景と問題設定

### FCFSではサービス時間の分散がそのままHOL blockingになる

GPUサービングでは要求を一つずつ完全直列に処理するわけではない。しかし連続バッチでも、長い要求がバッチスロットやKVキャッシュを長時間占有すると短い要求が不利になる。

出力長分布が狭ければFCFSでも大きな問題にならない。推論LLMでは数千トークン級の思考が混ざり分散が大きいため、要求順序の影響が増える。

### Oracle SJFは強いが実用できない

事後的に真の生成長を知って短い順へ並べれば、平均完了時間の強い下界を作れる。論文はこれをOracle SJFとして比較する。

実運用では真の長さを事前に知らないため、課題は「Oracle順序をどれだけ安価に近似できるか」になる。予測器の目的は言語生成を行うことではなく、スケジューラが意味のある順序を決める程度の信号を安価に出すことである。

### 絶対長の誤差と順位誤差は違う

例えば真の出力長が100と3000の二要求なら、予測が200と2000でもSJF順序は正しい。逆に真値100と110で予測順を逆転しても、完了時間への影響は小さい。

PARSはこの「差が大きい対を正しく並べることが重要」というスケジューリング目的へ学習目標を合わせる。

## 手法

### 1. 応答長から成対訓練データを作る

過去のプロンプトと実際の出力長を収集し、二つの要求を組にする。どちらの応答が長かったかを順位ラベルにする。

ただし長さ差が小さい対は、別の生成サンプルでは順序が逆転し得る。公式コードの公開前処理では、相対長さ差しきい値0.2を既定値として、差が十分大きい対を残す。

このフィルタにより、スケジューリング上ほぼ同等な要求を無理に順位付けする学習ノイズを減らす。

### 2. BERTからスカラー順位スコアを出す

各プロンプトをBERTへ入力し、得られた文表現を軽い線形ヘッドへ渡してスカラー順位スコアを得る。公式公開コードは`bert-base-uncased`を標準にする。

二つのスコア差へ成対マージン順位損失を適用し、長い応答を持つ側が一貫して高い（または実装定義に沿った）順位になるよう学習する。

絶対トークン数を出力しないため、1000トークンの誤差といった回帰誤差を最小化する必要はない。待機列を並べるための単調な順序だけを学ぶ。

### 3. オンライン予測を要求到着時に行う

新しいプロンプトが到着すると、LLM本体を実行する前に小型順位器へ通してスコアを計算する。公式コードは単発・バッチのスコアAPIを用意する。

この推論費用はLLM生成より十分小さい必要がある。順位器が高価すぎると短要求の待ち時間削減を予測器自身が食い潰すため、BERT級の軽量モデルを使う。

### 4. vLLM待機列を近似SJF順へ並べる

待機中要求を予測スコアで並べ、短いと推定される要求へ高い実行優先度を与える。vLLMの優先度スケジューラに接続できるため、AttentionやKV管理を作り直す必要はない。

PARSは一度だけ静的に並べるのではなく、要求到着と実行進行に応じて待機列の構成を更新する。したがってバースト到着でも、新しい短要求を既存長要求より前へ入れられる。

### 5. 飢餓防止

純粋SJFは長要求を延々後回しにする可能性がある。PARSは到着時刻を記録し、待ち時間がしきい値を超えた要求の優先度を上げる。

論文の代表設定では2分を既定しきい値としている。これにより平均遅延だけを最適化して長要求の最悪待ち時間を無制限に悪化させることを避ける。

## 一要求の流れ

要求が到着すると、まずプロンプトだけをBERT順位器へ入力してスコアを得る。スコアと到着時刻を待機列へ登録する。

スケジューラは現在の待機要求を短い予測順へ並べ、vLLMの次の実行候補として渡す。待機が長すぎる要求は経過時間条件でブーストされる。

LLMが実際に何トークン生成するかは最後まで確定しないが、順位が概ね正しければHOL blockingを減らせる。予測値が絶対長ではないため、実測長と数値比較して補正する経路は不要である。

## 評価

### 代表的な評価条件

| 項目 | 条件 |
|---|---|
| 配信基盤 | vLLM |
| 比較 | FCFS、点ごとの長さ回帰SJF、リスト順位SJF、Oracle SJF、PARS |
| 代表テストベッド | NVIDIA A100 40GB ×2、Arm Neoverse-N1 CPU |
| モデル | Llama 3.1系、DeepSeek-R1系など。版ごとに複数LLMを評価 |
| データ | Alpaca、LMSYS-Chat-1M、推論・コード・数学系ワークロード |
| 代表データ分割 | 40,000訓練、5,000試験。バースト評価では試験から2,000要求 |
| 順位器 | BERT、成対マージン順位損失 |
| 公開コード既定 | 長さ差しきい値0.2、`bert-base-uncased` |
| 指標 | 平均/裾遅延、要求完了時間、順位精度、予測器オーバーヘッド |
| 最大改善 | vLLM既定FCFS比で遅延最大15.7倍改善 |

### 代表的な評価結果

| 観点 | 結果 | 何を示すか |
|---|---|---|
| エンドツーエンド遅延 | FCFS比最大15.7倍削減 | 順位改善がHOL blocking削減へ実際につながる |
| 順位品質 | 成対学習が点回帰・リスト順位を多くの条件で上回る | 絶対長ではなく比較へ目的を合わせる効果 |
| 推論ワークロード | 長い思考と短い回答が混在する条件で利得が大きい | 出力長分散が大きいほどSJF近似が有利 |
| 交差モデル | 別LLMで作った順位器でも有効な条件を確認 | 毎モデル専用再学習を必須にしない可能性 |
| バースト到着 | FCFSより短要求を早く排出 | 一時的な待機列増大でHOL blockingが顕在化する条件に強い |
| 公平性 | 待ち時間ブーストで長要求の飢餓を抑制 | 平均遅延だけを最小化する純粋SJFとの差 |

最大15.7倍は、すべての負荷・モデルで固定して出る倍率ではない。出力長分布が狭い場合や到着率が低く待機列がほぼない場合、そもそも並べ替える余地が小さくなる。

### なぜ交差モデル一般化が重要か

出力の絶対トークン数はモデルごとに大きく異なる。例えば推論モデルは通常モデルより桁違いに長い思考を出すことがある。

PARSが必要とするのは絶対値ではなく「この質問は相対的に長くなりそう」という意味的特徴である。そのためモデル間で応答長スケールが違っても、質問難易度やタスク種類から得た順位信号が移植できる余地がある。論文はこの点を交差モデル評価で確認する。

## 既存研究との差

FCFSとの差は明確で、到着順をジョブサイズの代理順位へ置き換える。

絶対出力長予測型SJFとの差は、予測目標そのものにある。PARSは最終長の数値精度を追わず、スケジューリング上重要な大差ペアの順序を直接学ぶ。

既存の学習順位型スケジューリングに対しては、成対マージン損失と長さ差フィルタにより、近い応答長から生じるラベル不安定性を抑える。さらにvLLM統合、飢餓防止、交差モデル一般化まで含めてオンライン配信として評価する。

## 限界・実装状況

第一に、順位器は過去のプロンプト・応答長分布から学ぶ。新しいタスク分布や言語へ大きく外れると順位精度が落ちる可能性がある。

第二に、待機列が短い低負荷ではスケジューリング順序の影響自体が小さい。PARSの最大利得は高負荷・高分散条件で読む必要がある。

第三に、SJF系の本質として長要求を後回しにする。待ち時間ブーストで制御するが、しきい値は平均遅延と公平性の交換条件になる。

第四に、順位器推論はゼロコストではない。BERTバッチ推論や別CPU/GPUサービスの配置を含め、非常に短い要求では追加費用が相対的に大きくなり得る。

第五に、出力長以外の資源差、例えば巨大な入力プリフィル、マルチモーダルエンコーダ、異なるKV容量などは単一の応答長順位では完全には表せない。

## サーベイ上の含意

PARSはLLMスケジューリングで「未来を正確に予測する必要はない」ことを示す。実際の意思決定に必要な統計量が順序だけなら、**予測問題を回帰から順位学習へ弱める**ことで、ノイズへ強く安価な制御器を作れる。

この発想は出力長以外にも一般化できる。将来のGPU時間、KV消費、通信量を絶対値で高精度予測するのが難しくても、候補要求間の相対的な重さだけがスケジューラに十分な場合がある。
