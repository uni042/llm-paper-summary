# SmartGen: Seamless Disaggregated LLM Inference with Selective KV Cache Transfer

## 一文要約

prefill / decode分離で巨大なKV cacheを丸ごとnode間転送する代わりに、**decodeで使われやすいKVだけをprefill中に先送りし、足りないKVはdecode中にlocal読出しと並列でremote取得し、残りはnetworkの空き時間に送る**ことで、低帯域cloud上のstage切替待ちを減らす。

## 書誌情報

- **Authors:** Xuchuan Luo, Jiacheng Shen, Xin Wang, Yangfan Zhou
- **arXiv:** 2607.28150
- **初回公開:** 2026-07-30
- **Last checked:** 2026-09-07

## 問題設定

prefillとdecodeを別nodeへ分離すると、prefillで生成したKV cacheをdecode nodeへ渡す必要がある。長contextではKVが巨大になり、cloud instanceの10–35 Gbps級networkでは転送がprefill計算より長くなり、2 token目の生成開始を止めるstage-transition stallが生じる。

## 手法

SmartGenはKVを3種類に分ける。

1. **普遍的に重要なKV:** offline profilingで位置ごとの選択頻度を測り、prefill計算中にRDMA WRITEで先に送る。
2. **query依存で重要なKV:** decode時に不足が判明したKVをremote nodeから取得する。ただしlocal CPU memoryからGPUへKVを読む処理とremote取得を2 laneで並列化し、network round-tripを隠す。
3. **重要度が低い残りKV:** networkが空いた時間に投機的に転送し、後続tokenでremote fetchが必要になる確率を下げる。

転送可能量はprofilingしたprefill時間とfull KV transfer時間から決める。重要KVの選択自体はInfiniGen等のsparse attentionと組み合わせられる。

## 評価条件

- **Models:** Llama-3.1、Qwen3、Gemma-3、Phi-4
- **Hardware:** Alibaba Cloud NVIDIA L20、25 Gbps RDMAを中心に評価
- **Workloads:** LongBench、GovReport、SAMSum、LCC等
- **比較:** full KV cache transfer

## 主要結果

- full KV transfer比で **TTST（2 token目までの時間）を最大4.3×短縮**し、その後のdecode性能と精度は同程度。
- 48K batched inputではKV転送がprefill計算より最大6.5×長くなる観測を示し、selective transferの必要性を確認。

## 既存研究との差

Mooncake / DistServe / Splitwise等がprefill / decode分離やKV転送を扱うのに対し、SmartGenは**全KVを必ずstage間転送する前提を崩し、attention sparsityをnetwork transfer量削減へ直接使う**。KV圧縮だけではなく、先行・on-demand・投機の3経路で最終的には必要KVを利用可能にする点が中心。

## 一般的な実装上の含意

P/D分離ではGPU計算だけでなく、KVのstage間network転送を独立したbottleneckとして測る必要がある。長contextかつnetwork帯域が小さい構成では、KV selection metadataを転送schedulerへ接続し、local memory loadとremote RDMAを並列化する設計が有効になる。

## 限界

- offline profilingしたKV位置重要度がmodel・prompt分布へ依存する。
- 主な評価は低帯域cloudを想定しており、高帯域networkでは相対利得が小さくなる可能性がある。
- sparse KV selection機構との統合を前提とし、selection品質がremote fetch量へ影響する。
