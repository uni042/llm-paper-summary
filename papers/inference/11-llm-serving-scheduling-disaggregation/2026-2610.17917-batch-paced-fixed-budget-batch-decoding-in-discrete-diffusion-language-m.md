# Batch-Paced: Fixed-Budget Batch Decoding in Discrete Diffusion Language Models

> 拡散言語モデルのバッチデコードで、マスク位置の信頼度をバッチ全体で順位付けして確定位置を選び、固定された総デノイズ予算を系列間で融通させることで同一予算のバッチ品質を上げる訓練不要の配分方式。

## 概要

離散拡散言語モデルは、生成領域をすべてマスクした状態から始め、各デノイズ pass で残りのマスク位置すべてを並列に予測し、その一部を確定させて残りをマスクのまま次へ送る。自己回帰型と違い、1回の前向き計算で複数トークンを進められる点が効率の源泉だが、確定の歩調を決める従来方針は系列ごとに独立である。各系列が毎回同じ個数を確定させる均等配分では、易しいリクエストも難しいリクエストも同じ歩調になり、バッチ全体で見れば計算の配り方が硬直する。信頼度しきい値で確定数を変える適応型も系列単位の判断であり、バッチの総予算を直接は制御できない。

本論文は、バッチ全体の総デノイズ予算が固定された条件で、その配分を系列横断で決める問題を定式化し、訓練不要の方式を提案する。各 pass では全系列のマスク位置の信頼度を1つの順位へ並べ、残り予算プールから決まる個数だけを上位から確定させる。早く終わった系列は後続 pass の費用を下げ、余った予算は残りの系列へ自然に移る。代表結果として、バッチ16、系列あたり平均予算64の条件で、数学課題の正解率は均等配分の67.8パーセントから77.5パーセントへ、コード生成課題では18.4パーセントから29.3パーセントへ上がった。利得はバッチサイズが大きいほど伸び、低信頼度のリクエストの確定トークン信頼度を引き上げることで生じると分析されている。評価は形成済みバッチに対する統制実験であり、オンライン到着を伴う実サービングの遅延は測られていない。

## 問題設定

資源はデノイズ pass の総量である。バッチの系列数を掛けた平均予算が総予算となり、1回の pass の費用は未完了系列の数に比例する。均等配分では各系列が毎回ほぼ同じ個数の位置を確定させるため、総予算は守れても配分の柔軟性がない。逆にしきい値型の適応デコードは、しきい値次第で pass 数がモデルや課題やバッチ構成ごとに変わり、目標予算へ合わせるには設定ごとの探索実行が要る。サービング側が各バッチへ計算上限を与えたい場面、例えば共有アクセラレータ上でバッチ間に計算を分ける場面や、計算の段階を価格帯で分ける場面では、予算を直接指定でき、その範囲で品質を最大化する配分が必要になる。ここで効く資源配分の単位は系列ではなくバッチであり、どの位置を確定させるかの判断をバッチ全体の信頼度順位へ移すことが本論文の着眼点である。

## 手法のあらまし

入力は未完了系列の集合と、各マスク位置に対するモデルの予測分布から作る信頼度スコア、そして残り予算プールである。まずバッチ全体の候補位置を集め、未完了系列数と残りプールから今回の pass で確定させる個数を式で決める。次に信頼度の高い順にその個数だけ位置を選び、どの系列からも最低1位置は確定させる保証を加える。選ばれた位置へ予測トークンを置き、完了した系列を集合から外し、pass の費用をプールから差し引く。これをプールが尽きるか全系列が完了するまで繰り返す。出力は各系列で歩調の異なる生成結果であり、総予算は設計上超えない。

## 手法

### 1. 全体順位付けによる確定位置の選択 — 予算を系列間で融通する仕組み

観測するのは各 pass の予測分布から得る位置ごとの信頼度であり、既定では最も確率の高いトークンの確率を使う。保持する状態は残り予算プールと未完了系列の集合だけである。選択は、候補全体の中で信頼度の高い位置から順に、今回の確定個数へ達するまで取ることであり、これにより信頼度の高い系列は速く進み、低い系列は少ない確定で慎重に進むという歩調の差が自動で生まれる。減るボトルネックは、易しい系列へ固定で配られていた無駄な再計算と、難しい系列の早すぎる確定による品質低下である。追加費用は順位付けの計算だけで、モデルの前向き計算そのものは増えない。失敗条件は信頼度スコアの質であり、スコアが実際の正しさとずれる課題では配分が逆効果になり得る。論文でも指示追従の単独課題では均等配分をわずかに下回る条件があり、万能ではないことが数値に表れている。

### 2. 残りプールからの確定個数の決定 — 予算を守る式

各 pass の確定個数は、残っているマスク位置の総数を、残りプールと未完了系列数から決まる残り pass 数の目安で割って決める。完了した系列が抜けると1 pass あたりの費用が下がるため、同じプールでも残りの系列へ回せる pass が増える。つまり早期完了の節約が自動で残りへ再配分される構造であり、別途の再計画は要らない。最低保証として、全体順位で選ばれなかった未完了系列にも最も信頼度の高い1位置を確定させるため、特定系列が止まり続けることはない。この保証は公平性の下限であり、極端な偏りを防ぐ代わりに、最も難しい系列へも毎回少しずつ予算を使う。

### 3. 深さ上限による拡張 — 時間との交換

全体順位付けは系列ごとの歩調をばらけさせるため、バッチ全体の逐次ステップ数が増えてデコード時間が伸びる場合がある。拡張ではバッチのデノイズステップ数へ上限を設け、残り深さが減るにつれて系列あたりの最低確定数を引き上げる。追加の確定は引き続き全体順位に従うため、配分の考え方は保ったまま時間だけを締めることができる。論文の測定では、上限を締めるほど強い適応型の比較対象の実行時間へ近づき、性能は元の方式から少し下がるという交換関係が示されている。深さ上限は品質と時間のつまみであり、サービング側がバッチ完了時間の上限を持つ場合に使う位置づけである。

### 4. データと制御の流れ

1つのバッチは、プロンプト集合と総予算を受け取って開始する。各 pass でモデルの予測が信頼度へ変換され、全体順位と確定個数の式が確定集合を決め、状態が更新される。系列が完了すれば集合から外れ、プールの減り方が緩む。最終的にプールを使い切るか全系列が完了した時点でバッチが終わり、品質は系列ごとの正解率の平均として測られる。到着や離脱が途中で起きるオンライン運用は対象外で、バッチは形成済みであることが前提である。

| 構成要素 | 入力・観測 | 具体的な動作 | 改善対象 | 主なトレードオフ |
|---|---|---|---|---|
| 全体順位付け | 全系列のマスク位置の信頼度 | 上位から確定個数だけ横断選択 | 固定予算の品質 | スコアの質に依存する |
| 予算プール | 残り予算と未完了系列数 | pass ごとに費用を差し引き確定個数を再計算 | 予算の厳守と再配分 | 完了が遅い系列が多いと歩調が締まる |
| 最低保証 | 選ばれなかった系列 | 最良の1位置を必ず確定 | 系列の停滞防止 | 難しい系列へも最小予算を使う |
| 深さ上限 | 残りステップ数 | 最低確定数を引き上げ | バッチ完了時間 | 性能が少し下がる |

## 評価

### まず見るところ

結論として、同一予算では全体配分が均等配分をほぼ全面的に上回り、特にコード課題と混合バッチで差が大きい。強い適応型の比較対象とは概ね互角であり、しかも提案法は予算を直接指定できるため、較正実行が要るしきい値型より運用が単純である。時間は均等配分と概ね同等で適応型よりは長く、深さ上限でその差を詰められる。品質の利得は低信頼度リクエストの改善から来るという内部分析があり、単なる平均の水増しではない。

## 既存研究との差

系列内のデコード研究は、信頼度やエントロピーや時間的一貫性などの信号で1つの系列の確定歩調を制御し、系列の効率を上げることに集中してきた。推論計算の配分研究は、自己回帰型を対象にクエリ間で予算を配る問題を扱った例があるが、拡散型のバッチ内配分は未開拓だった。サービング基盤側の研究は要求の実行やサービス目標の達成を扱い、形成済みバッチ内部のデノイズ配分は扱わない。本論文はこの空白へ、バッチ全体の信頼度順位という単純な仕組みを持ち込み、予算を直接指定できる形で統制実験を行った点に新規性がある。

## 限界・実装状況

論文自身が挙げる限界は3つある。第1に、マスクからトークンへの通常のデコードだけを対象とし、任意順序の生成や確定済みトークンの編集は扱っていない。第2に、ワークロードは標準ベンチマークと人工混合であり、実サービスの多様な要求構成を反映しない。第3に、時間評価は形成済みバッチの同期デコード時間に限られ、到着と動的バッチ形成を含むオンライン遅延は測っていない。実装は訓練不要の選択規則であり既存の拡散デコードへ組み込みやすい一方、論文中に公式コードの公開先は示されていない。信頼度スコアの定義を変えても利得が概ね残ることは確認されているが、指示追従課題のように下回る条件もあり、スコアと課題の相性は運用前に確認が要る。

## 一般的な実装上の含意

固定予算の下では、配分の単位を個々の要求からバッチ全体へ上げるだけで品質が上がり得る。完了した要求の節約を残りへ自動で回すプール方式は、再計画なしに再配分を実現する単純な形として、拡散型以外の並列生成や投機的実行の予算管理にも応用できる。逆に、予算を直接指定できる方式としきい値で間接制御する方式では運用の手間が大きく違い、サービングへ載せる場合は制御の直接さ自体が設計要件になる。
