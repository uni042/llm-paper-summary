# QuRL：量子化した応答生成を使う推論モデルの強化学習

## 概要

大規模言語モデル（LLM）の推論能力を検証可能報酬付き強化学習（RLVR）で伸ばす場合、各学習反復は、応答系列を自己回帰生成するロールアウト（rollout）、生成トークンの確率を評価する順方向計算、方策を更新する逆方向計算に分かれる。長い思考系列では前者が学習時間の最大約70%を占める。生成用モデルだけを8ビットに量子化すれば行列積を高速化できるが、生成したトークンの確率分布が学習更新に使う高精度モデルと一致しなくなり、単純な置換は学習を不安定にする。

QuRLは、量子化された旧方策を**行動方策**として応答生成に使用し、更新対象および近接方策には高精度モデルを保持する。行動方策と近接方策の差が大きいトークンでの重要度比の切り詰め方を調整する**適応的クリッピング範囲（ACR）**と、微小な学習更新が量子化の丸め幅に埋もれる問題を抑える**更新認識量子化（UAQ）**が中核である。INT8とFP8で検証し、量子化推論の要求処理量はモデル・GPUに応じて改善する。一方、報告された20〜80%のロールアウト高速化を、そのまま全学習工程の同率短縮と読んではならない。

DeepScaleRの五つの数学推論課題で32回生成平均正答率は、BF16強化学習56.40%、通常INT8強化学習52.31%、FlashRLのINT8 53.80%、QuRLのINT8（UAQあり）55.48%であった。これは品質をほぼ回復した結果であり、BF16を超えたという結果ではない（原著表3）。

## 問題設定：生成高速化がなぜ学習を壊すのか

方策勾配系の強化学習では、古い方策で得た系列を使って新しい方策を更新する。近接方策最適化（PPO）やグループ相対方策最適化（GRPO）は、各トークンの新旧確率比を使って更新の大きさを調整し、一定範囲を超えた比を切り詰める。量子化した旧方策で系列を生成した場合、**実際にサンプルを出した確率**は量子化旧方策のものだが、**更新を制限する基準**は高精度旧方策のものになる。この二つを同一視すると重要度補正に偏りが生じる。

著者は、量子化旧方策をそのまま確率比の分母に使う単純な目的関数（原著式3）で、学習途中に報酬が崩壊することを観察した。単純な確率比クリッピングでは切り詰め対象トークンの比率が急増し、更新に寄与できる系列が変質する。一方、近接方策を高精度旧方策に分離した目的関数（原著式4）でも、学習が長期化すると量子化モデルとの乖離が蓄積する。単なる低ビット行列積の置換ではなく、サンプル分布のずれを補正する学習則が必要になる。

さらに、強化学習の重み更新は学習率が小さい。論文の例では学習率10^-6、勾配が0.1〜1.0程度のとき更新幅は10^-7〜10^-6程度であり、8ビット量子化による丸め幅より小さいことがある。学習側で重みが少し変わっても次のロールアウト用モデルを再量子化すると同じ離散値に戻り、**生成方策が学習の進展を追従できない**。これは確率比のずれとは別の故障機構である。

## 手法

### 1. 量子化生成と高精度更新を分ける実行経路

各反復の入力は高精度の旧重み θ_old と、数学問題などの入力群である。まず旧重みを8ビットへ変換した Q(θ_old) を生成エンジンへ配置し、これを使って応答を生成する。生成されたトークン列と量子化行動方策の確率を学習エンジンへ渡す。学習側は高精度モデルで各トークンの確率を再計算し、報酬から得た優位度を使って重み θ を更新する。更新後は次の反復で再び量子化し、生成用モデルを入れ替える。

量子化は重みにチャネル単位、活性化にトークン単位の尺度を使い、INT8またはFP8の行列積をvLLMの最適化カーネルで実行する。これは量子化を学習対象に含める量子化考慮学習（QAT）ではない。重み更新の勾配は高精度側で計算し、量子化生成モデルは系列の採取を担当する。論文の性能評価ではKVキャッシュ自体のFP8量子化は含めていない。対象vLLM版ではその最適化から測定可能な処理量改善を得られなかったためである。

### 2. 行動方策と近接方策を分離した重要度補正

記号 π_behav を量子化旧方策、π_prox を高精度旧方策、π_θ を更新中の高精度方策とする。更新を制限する比は R=π_θ(token)/π_prox(token) とし、実際の生成分布の違いは π_prox/π_behav によって補正する。これは、量子化モデルから生成した系列を高精度方策の学習に再利用するためのオフ方策（off-policy）補正である。

既存のFlashRLが用いる切り詰め重要度サンプリング（TIS）は、π_prox/π_behav が閾値 C を超えると C で頭打ちにする。生成エンジンと学習エンジンの実装差が確率比を極端にする場合にも勾配爆発を抑えられる。ただし切り詰めは補正を偏らせ、原著図3では長期学習で行動方策と近接方策のKL乖離が約0.002から0.025へ増大し、1000ステップを超える領域で崩壊が生じる。

### 3. 適応的クリッピング範囲（ACR）

原著式6〜9では、TISで用いる切り詰め後の行動確率を max(π_behav, π_prox/C) と定義し、比 r=π_behav/π_behav_trunc（0<r≤1）を求める。通常の切り詰め範囲をこの r に応じて機械的に縮めると、特に正の優位度を持つトークンが過度に除外される。そこでACRは**上側の許容閾値を (1+ε)/r に拡張**し、下側は通常の (1−ε) を維持する形で更新式を組み直す。

この調整はすべてのトークンを無制限に通すものではない。π_prox/π_behav が C 以下なら r=1 で通常の範囲へ戻る。大きな分布差のあるトークンだけ上側境界を緩め、重要度補正で勾配を抑えつつ、正の学習信号を失い過ぎないようにする。出力は新しい高精度方策の勾配であり、生成モデルそのものの重みは次の量子化更新まで変えない。原著はこの機構が長期学習の崩壊を防ぐことを図2・図3で示している。

### 4. 更新認識量子化（UAQ）

ACRだけでは重み更新が量子化後に消える問題は解消しない。UAQは学習前に、線形層の入力 X と重み W を出力を変えずに再尺度化する。原著式11の WX=(W/s)(sX) が基本式である。入力側の尺度を直前の層正規化へ吸収できる箇所では、追加の推論演算を抑えつつ、重みの値域と勾配の値域を変えられる。

尺度 s>1 により、量子化誤差の規模を約1/sに縮める一方、入力活性化が大きくなることで重み勾配の更新幅は約s倍になる。したがって**重み更新幅と量子化雑音の比**は理論上約s²倍改善する（原著式12）。実験では s=1.5 を採用する。大きくし過ぎれば更新が過剰になりクリッピングが増えるため、単純にsを最大化すればよいわけではない。

UAQは毎反復で重い較正処理を実行するのではなく、学習開始前の一度の再パラメータ化である。出力は同じ関数を表す再尺度化重みと活性化経路であり、次の反復で8ビット化しても学習による変化が離散値へ反映されやすくなる。著者の実験では高い学習率を使う小規模PPO設定ではUAQを無効にしており、すべての学習設定で必須という主張ではない。

### 生成処理量と感度

原著図8では、INT8生成のBF16比の要求処理量は7BでA6000 1.36倍、A100 1.30倍、H100 1.16倍、14Bでそれぞれ1.56倍、1.33倍、1.30倍、32Bの2GPU構成で1.40倍、1.66倍、1.83倍だった。モデル規模だけでなくGPU世代やカーネルの実装によって改善率が異なる。特に7BのH100では1.16倍であり、「常に80%高速化」とはならない。

UAQの尺度感度（原著表4、DAPO INT8）では s=1、学習率10^-6でAvg@32=30.63、s=1.5で31.25、s=2で29.15となる。学習率だけを1.5倍にした場合29.06、2倍では26.66であり、UAQの利点は単に学習率を上げることとは異なる。尺度を大きくし過ぎるとクリッピングと不安定化が増えるという失敗条件も確認されている。

## 先行研究との差

通常の事後量子化（PTQ）は推論の重みと活性化の近似誤差を減らすことが中心で、学習反復の中で小さな更新を量子化生成器へ追従させる問題を直接扱わない。量子化考慮学習（QAT）は学習の計算経路に量子化を組み込むが、QuRLは高精度の学習側を維持し、生成側の処理量を改善する。

FlashRLの切り詰め重要度サンプリングは量子化生成方策の確率比を扱う先行手法である。QuRLは、切り詰めが正の優位度のトークンを過剰に排除する点に対してACRを導入し、さらに重み更新が量子化刻みに埋没する点にUAQを導入する。二つは異なる原因への対処であり、どちらか一方だけで十分と主張していない。

## 限界・再現上の注意

本研究の実験は数学推論タスク、指定されたモデル系列、VeRLとvLLM、INT8/FP8の生成カーネルに基づく。異なる量子化方式、生成器、超長文脈、非数学タスクで同じ品質差と速度差が出るとは検証されていない。FP8のKVキャッシュ量子化は性能改善を得られず評価対象から除かれたため、キャッシュ容量まで減る設計として引用してはならない。

量子化した行動方策から得る系列の確率は、高精度方策で直接生成した系列とは異なる。ACRはその分布差を完全にゼロにするわけではなく、重要度補正とクリッピングの交換条件を設計している。UAQは尺度を増やし過ぎると逆効果であり、学習率・重み分布・量子化形式に依存する。生成処理量の測定と学習全体の時間短縮を混同しないことが重要である。
