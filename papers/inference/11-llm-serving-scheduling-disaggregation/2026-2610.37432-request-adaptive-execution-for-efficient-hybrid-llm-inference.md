# Request-Adaptive Execution for Efficient Hybrid LLM Inference

> 注意層と状態空間モデルの層の配置をリクエストごとにプリフィルで決めて固定し、分割統合のバッチ処理と層履歴まで見る文脈キャッシュで効率的に捌く共同設計で、品質指標18件中13件で最良となりスループットはvLLM比で最大3.87倍になった。

## 概要

注意機構は全トークン間の関係を直接扱えるが、計算が文脈長の二乗で増え、デコードではKVキャッシュが伸び続ける。状態空間モデル（SSM）は履歴を固定サイズの再帰状態へ圧縮し、線形時間で更新できる代わりに、文脈依存の情報を正確に思い出す力に限界がある。両者を層単位で混ぜたハイブリッドLLMは、この相補性で品質と効率のバランスを取る設計として発展してきた。ただし既存のハイブリッドLLMは、注意層とSSM層の配置（レイアウト）がモデル構築時に経験的に決められ、全リクエストに同じ配置が適用される静的設計だった。

本論文は、この静的さが実ワークロードで損をしていることを二つの観測で示す。観測1として、最適な配置はワークロードごとに異なる。推論課題のARC-Challengeでは注意1層にSSM6層の配置が最良だが、常識質問のPIQAと長文要約のPubMedでは注意1層にSSM1層が最良であり、SSMの比率を上げるとスループットは毎秒23.83トークンから87.11トークンへ大きく変わる。観測2として、同じ課題の中でもリクエストごとに最適な配置が変わる。ARC-Challengeを100件ずつの6部分集合に分けると、最良の配置は部分集合ごとに異なった。つまり配置は課題の種類ではなく、個々のリクエストの文脈依存の持ち方で決めるべきものである。

提案するFlexは、モデルとランタイムの共同設計でリクエスト適応実行を実現する。モデル側では、各ブロックに軽量なゲートと、対になった注意層とSSM層と、共有の全結合層を置く。ゲートはプリフィル時に全入力トークンからリクエスト単位の表現を作り、ブロックごとにどちらの層を使うかを一度だけ決め、その選択はデコード中ずっと固定される。これをプリフィル指向ゲーティングと呼ぶ。トークン単位で選択を変えると、過去トークンのKVキャッシュやSSM状態を新しい選択の下で作り直す必要が生じるため、リクエスト単位で固定するのが要である。ランタイム側では、分岐の異なるリクエストが混ざるバッチを、分岐非依存の演算は詰めたバッチのまま、分岐依存の計算だけ分割して実行し統合する選択的バッチ処理で処理し、分岐の重さに応じてGPUのストリーミングマルチプロセッサ（SM）を配分する負荷考慮の分岐協調を加える。さらに、同じテキスト接頭辞でも層選択が違えば再利用できるキャッシュが違うという問題に対し、テキスト接頭辞の基数木の内側に層選択経路の基数木を持つ二階層構造で、互換な層キャッシュだけを再利用するハイブリッド対応文脈キャッシュを備える。

**代表結果:** H100単体、3つのモデル規模と6データセットで、Flexは18の品質指標のうち13で最良となり、推定演算量（デコード1トークンあたり）は注意のみのLlama比で規模ごとに40.5、33.2、67.2パーセント削減した。システム評価では、リクエストスループットがvLLM比で最大3.87倍（規模別に最大3.79、3.87、3.44倍）になり、最大バッチ条件では最初のトークンまでの時間（TTFT）がvLLM比で平均80.9パーセント減、出力トークン間隔（TPOT）が平均71.6パーセント減った。

## 問題設定

問題は、モデル側の非効率と、それを直すと壊れるサービング側の前提の二層にある。モデル側では、静的配置は両方向に損をする。単純なリクエストにまで注意層を使えば、文脈長の二乗に比例する計算とKVキャッシュの読み出しを無駄に払う。逆に文脈依存の強いリクエストで注意が不足すれば、SSMの圧縮状態では拾えない長距離の依存を取りこぼして品質が落ちる。配置の良し悪しは品質とスループットの両方に直結するのに、構築時に一回決めた配置はどちらの損も避けられない。

リクエスト適応へ動かすと、サービングの前提が二つ崩れる。第1にバッチ処理である。通常のサービングエンジンは、バッチ内の全リクエストが同じ演算列を実行する前提で成り立つ。リクエストごとに層選択が違えばこの前提が崩れ、単純に直列化すれば並列性を失い、リクエストごとに分けて実行すればバッチが断片化し、正規化や全結合のような分岐非依存の演算まで細切れになる。第2に接頭辞キャッシュである。従来の文脈キャッシュは、テキスト接頭辞が一致すれば再利用できるキャッシュが一意に決まる前提に立つ。しかし動的配置では、同じ接頭辞でも層選択の履歴が違えば、あるブロックではKVキャッシュが、別の経路ではSSM状態が作られており、一致した接頭辞の全体を再利用すると中間表現が不整合になり、全体を捨てると再利用機会を失う。さらに退避も、文脈単位で消すと頻繁に使われる層キャッシュまで巻き添えになる。本論文は、配置の決定粒度をプリフィル時のリクエスト単位に固定することでキャッシュの再利用可能性を保ち、その上でバッチ処理とキャッシュの両方を動的配置前提へ作り替える。

## 手法のあらまし

全体の流れは次のとおりである。リクエストが届くと、ランタイムはバッチを組み、文脈キャッシュで再利用可能な接頭辞を探す。プリフィルでは、各ブロックのゲートが入力全体からリクエスト表現を作り、注意かSSMかを選ぶ。選ばれた層が全入力トークンを処理し、KVキャッシュまたはSSM状態を残す。層選択はリクエストごとに記録され、デコードではゲートを動かさず、記録された選択に従ってリクエストを分岐ごとにまとめて処理する。学習時は微分可能性のため、ゲートの確率で両分岐の出力を重み付き合成するソフトルーティングを使い、教師あり微調整の損失に、層ごとの正規化費用で重み付けした費用考慮の正則化を加える。推論時は確率の大きい側だけを実行するハードルーティングへ切り替える。モデルは、事前学習済みの注意モデルとSSMモデルの部品から初期化し、隠れ次元の整合には構造化枝刈りを、深さの違いにはKLダイバージェンスに基づく重要度で選んだ層の対を作り、共有の埋め込みと全結合と正規化は注意側の土台から凍結して、ゲートと対の分岐だけを微調整する。

## 手法

### 1. プリフィル指向ゲーティング — 選択を一度だけ決めて固定する

この機構が観測するのは、プリフィルで処理される全入力トークンの隠れ状態である。保持する状態は、リクエストごとに記録された全ブロック分の層選択であり、デコード中は不変である。行う動作は、隠れ状態を集約して小さなリクエスト表現を作り、軽量なゲートネットワークで注意とSSMの選択確率を出し、上位1件、つまり確率の大きい側を実行することである。粒度の設計が要点であり、トークン単位のゲーティングは自己回帰デコードと相性が悪い。生成トークンは過去トークンのキャッシュに依存するため、途中で選択が変わると過去分を新しい層で計算し直す必要がある。プリフィルで固定すれば、キャッシュは一貫し、ゲートの実行もリクエストあたり各ブロック1回で済む。プリフィルの入力には課題の種類や文脈長や依存の持ち方が既に表れているため、入力だけで全体の選択を決めることにも根拠がある。減るボトルネックは、不要な注意計算と、選択変更に伴う再計算である。追加費用は、対の両方の層を保持することによる総パラメータの増加であり、例えば中規模では総パラメータ14.5Bに対し、1リクエストで活性化するのは平均6.5Bである。失敗条件は、生成の途中で文脈依存の性質が変わるリクエストであり、プリフィル時点の判断が最後まで固定されるため、後半で必要になった注意を後から足すことはできない。

### 2. 選択的バッチ処理と負荷考慮の分岐協調 — 混在バッチを割らずに捌く

この機構が観測するのは、各ブロックでの各リクエストの層選択と、分岐ごとの作業量の特徴量である。保持する状態は、詰めたバッチの配置と、分岐ごとの部分バッチへの対応表である。行う動作は、ゲートや全結合のような分岐非依存の演算は元の詰めたバッチのまま実行し、注意とSSMの計算の直前だけリクエストを分岐ごとの部分バッチへ圧縮して、それぞれのカーネルで実行し、出力を元の配置へ統合することである。これにより、動的な層選択の影響はブロック内の分岐計算だけに閉じ、他の演算は通常のバッチ効率を保つ。分岐協調では、注意分岐は文脈長とKV長に、SSM分岐は状態更新に費用が寄るという非対称性に対処する。プロファイル済みの費用モデルで両分岐の相対費用を予測し（予測誤差は注意側6.32パーセント、SSM側5.18パーセント以内）、重い側へSMを多く配分する。配分は16個のSMを単位とし、H100の132個のうち128個を配分対象のプールとして、GreenContextで部分バッチごとにSMプールを縛り、別々のストリームで同時実行してイベントで同期する。既存のFlashAttentionやmamba_ssmのカーネルは無変更で使える。減るボトルネックは、統合時の待ち、つまり軽い分岐が重い分岐を待つ同期の無駄である。除去実験では、分岐協調を切るとエンドツーエンド遅延が増え、協調ありは協調なし比で平均21.7から28.2パーセントの遅延削減があった。追加費用は、分割と統合のデータ移動と、費用モデルのプロファイル（モデルとGPUの組ごとに一度）である。失敗条件は、片方の分岐にリクエストが偏りすぎるバッチであり、その場合は配分の余地がなく、空の分岐がある場合は分割自体を省く。

### 3. ハイブリッド対応文脈キャッシュ — テキストと層経路の二段で照合する

この機構が観測するのは、新規リクエストのテキスト接頭辞と、その層選択の履歴である。保持する状態は、外側のテキスト基数木と、各文脈ノードにぶら下がる内側の層選択基数木であり、層ごとのKVキャッシュとSSM状態と、再構成に使う入力隠れ状態と終端のSSM状態を保持する。行う動作は、まず外側で最長のテキスト一致を取り、次に内側で先頭ブロックから層選択が一致する経路を探し、再利用できる接頭辞長と先行ブロック数から再計算費用が最小の候補を選ぶことである。途中で経路が食い違った場合でも、食い違うブロックまでの隠れ状態は有効であり、そこから後を再計算して内側の木へ新しい分岐として追加する。部分的な再利用ができるのが、従来方式との差である。退避は文脈単位ではなく層キャッシュ単位で行い、優先度は、最近のアクセス頻度と再利用で節約できる再計算費用の積をメモリ量で割り、浅いブロックを優遇する深さ係数を掛けた値で決め、低いものから捨てる。浅い層のキャッシュは複数の経路の共通祖先になるため、深さの優遇には構造的な理由がある。効果の実測では、共有文脈の数を2から20へ増やす条件で、有効ヒット率が平均43.4パーセントと従来方式の18.7パーセントを24.7ポイント上回り、TTFTは平均で10.68秒から5.92秒へ44.6パーセント減った。減るボトルネックは、共有接頭辞の再計算である。追加費用は、経路ごとのキャッシュ保持によるメモリ圧力であり、同じ文脈に複数の経路のキャッシュがぶら下がる分、退避の管理が重要になる。失敗条件は、経路の多様性が爆発するワークロードであり、その場合は内側の木が膨らみ、ヒット率も論文の条件より下がり得る。

### 4. データと制御の流れ

経路の実態を見ると、28ブロックのモデルでは、注意の選択率はブロックの深さと課題で系統的に変わる。ARC-Challengeでは深いブロックほど注意が増え、TruthfulQAでは前半から中盤に山があり、CNN/DailyMailでは中盤が高い。また、ARC-Challengeの500リクエストは35種類の配置を使い、上位6種類で9割以上を覆う。つまり経路は、少数の頻出配置と長い裾野の組み合わせであり、バッチ内で同じ分岐を取るリクエストをまとめる選択的バッチ処理が効く構造になっている。バッチが大きいほど同じ分岐の相手が見つかりやすいため、スループットの優位はバッチサイズとともに広がると報告されている。

| 構成要素 | 入力・観測 | 具体的な動作 | 改善対象 | 主なトレードオフ |
|---|---|---|---|---|
| プリフィル指向ゲーティング | プリフィルの全入力の隠れ状態 | リクエスト単位で層選択を決め固定 | 不要な注意計算と再計算 | 総パラメータが増え、途中で選択を変えられない |
| 選択的バッチ処理 | ブロックごとの層選択 | 分岐計算だけ分割し統合 | バッチの断片化 | 分割と統合の移動費用 |
| 負荷考慮の分岐協調 | 分岐ごとの特徴量と費用モデル | SMを重い分岐へ寄せる | 統合時の同期待ち | モデルとGPUごとにプロファイルが要る |
| ハイブリッド対応文脈キャッシュ | テキスト接頭辞と層選択履歴 | 二階層基数木で互換な層キャッシュを再利用 | 共有接頭辞の再計算 | 経路ごとの保持でメモリ圧力が増える |

## 評価

結論は三点である。第1に品質面では、リクエスト適応の配置が静的な最良配置すら上回る。検証データから選んだ全体最適の固定配置と、データセットごとの最適配置のどちらに対しても、適応版が18の規模とデータセットの組合せすべてで勝ち、データセット最適との差は正解率で平均4.86ポイント、ROUGE-Lで2.55ポイントだった。第2にシステム面では、選択的バッチ処理と文脈再利用の両方が独立に効き、片方を切った変種はいずれも全体に劣った。第3に、利得の出所は条件で異なり、TTFTの改善は主に文脈再利用、TPOTの改善は主に選択的バッチ処理に由来する。評価は実機の単一GPUであり、複数GPUや分散サービングは未評価である。エネルギー効率も未評価である。

## 既存研究との差

ハイブリッドLLMの先行研究であるJamba、Zamba、Nemotron-H、Hymba等は、配置の決め方こそ違えど、構築後に配置が固定される点で共通していた。本論文は配置をリクエストの実行時に決める対象へ変えた。サービング側では、Orcaの反復レベルスケジューリング、vLLMのPagedAttention、SGLangのRadixAttentionが前提とする「バッチ内は同一演算列」「接頭辞が一致すればキャッシュは一意」という二つの前提を、動的配置の下で置き換えた点が差分である。具体的には、バッチ処理は分岐依存部分だけを分割する形へ、文脈キャッシュはテキストと層経路の二段照合へ作り替えられている。Jengaのような異種キャッシュのメモリ管理とは補完関係にあり、本論文のランタイムもその方式を取り入れている。

## 限界・実装状況

総パラメータは対の両分岐を保持するため大きくなる。大規模では総61Bに対し活性は平均23Bであり、メモリ容量の制約が厳しい環境では搭載自体が問題になる。層選択はプリフィルで固定されるため、生成途中で性質が変わるリクエストには追従できない。モデルは既存の注意モデルとSSMモデルの部品を組み合わせて微調整する構成であり、ゼロからの事前学習で同じ性質が得られるかは未評価である。評価は単一GPUと6データセットに限られ、分散サービング、複数モデルの混在、エネルギー効率は未評価である。実装は約6500行の試作であり、スケジューラは通常の連続バッチ処理が前提で、他のスケジューリング方針との併用は互換性の言及にとどまる。公式コードの公開先は論文本文では確認できず、本稿ではコードなしとして扱う。なお、arXivの最新メタデータの要旨ではシステム名がMorphと表記される一方、今回通読したHTML本文では一貫してFlexと表記されており、本稿は本文に従った。

## 一般的な実装上の含意

推論基盤への示唆は三つある。第1に、モデルの動的構造化は、モデル単体の効率化では完結せず、バッチ処理とキャッシュというランタイムの前提を同時に作り替える必要がある。第2に、動的選択の粒度はキャッシュの再利用可能性で決めるべきであり、トークン単位の自由度は、過去分の再計算という形で費用になって返ってくる。第3に、接頭辞キャッシュはテキストの一致だけでなく、そのキャッシュを作った実行経路の一致まで見ないと、動的モデルでは正しさとヒット率のどちらかを失う。
