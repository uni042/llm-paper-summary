# DualMap: Enabling Both Cache Affinity and Load Balancing for Distributed LLM Serving

## 概要

DualMapは、分散LLM推論でプロンプト接頭辞のKVキャッシュを再利用したいという要求と、各推論インスタンスへ負荷を均等に分けたいという要求の衝突を解く配車方式である。会話履歴やエージェントの共通指示は複数の要求で繰り返されるため、同じ接頭辞のKVを保持するインスタンスへ送れば事前充填（prefill）を省略できる。しかし人気接頭辞の要求が一つのノードへ集中すると、そのノードの待ち行列が伸び、初回トークン時間（TTFT）が悪化する。最小負荷ノードへ分散するだけでは、同じ接頭辞のKVがクラスタ全体へ散って再計算が増える。

DualMapはプロンプト接頭辞を二つの独立したハッシュ関数へ渡し、各要求に二つの安定した候補インスタンスを与える。同じ接頭辞の要求は同じ候補対へ集まるためキャッシュの局所性を保ち、二者択一（power of two choices）の負荷分散効果も利用できる。通常はキャッシュ命中率が高い候補へ送り、予測TTFTがサービス水準目標（SLO）を超える場合だけ低負荷側へ切り替える。ホットスポットでは待機中要求をもう一方の候補へ移し、クラスタの増減では二重ハッシュリングにより全体の再写像を防ぐ。

ICLR 2026の論文は、vLLMを用いた分散推論クラスタで実際の会話・ツール利用負荷を評価し、同じTTFT目標を満たす有効要求容量を既存方式比で最大2.25倍に改善したと報告する。この数値は一要求のトークン生成速度が2.25倍になったことではなく、**遅延目標を守って処理できる要求数の増加**である。

## 問題設定と設計の前提

LLM推論は入力トークンをまとめて処理する事前充填と、出力トークンを逐次生成する復号に分かれる。事前充填で計算したキー・値（KV）を保存しておけば、次の要求が同じ接頭辞を持つ場合にその部分の計算を再利用できる。エージェントが同じツール仕様を何度も送る場合や、会話の履歴が次の要求に含まれる場合は、接頭辞の共有が多い。保存先と次の要求の実行先が違えば、再利用のために転送するか再計算する必要がある。

純粋なキャッシュ親和型配車では、同じ接頭辞を持つ要求を固定ノードへ集める。キャッシュ命中は高いが、人気接頭辞のノードに要求が集中する。純粋な最小負荷型配車では、待ち行列の短いノードを選ぶので負荷は均等になるが、共有接頭辞が複数ノードへ散り、キャッシュ命中が低下する。既存のPrebleやMooncake系は、状況によってキャッシュ優先と負荷優先を切り替えるが、単一の候補空間での切替では両方を同時に高めにくい。

論文の動機実験では8インスタンスのQwen2.5-7Bを使い、Conversation負荷で純キャッシュ親和方式の命中率が最小負荷方式より1.21倍高かった。一方で各インスタンスの待機事前充填トークン数の変動係数（CV）は大きくなり、負荷の偏りを示した。CVは標準偏差を平均で割った値であり、小さいほど均等で、0は完全に同じ負荷を表す。キャッシュ命中率だけで方式を選ぶと、ホットスポットでTTFTを悪化させる。

## 手法

### 1. 二つのハッシュで安定した候補対を作る

DualMapのグローバル配車器は、各要求の接頭辞を二つの独立ハッシュ関数 `f1` と `f2` へ渡し、二つの候補インスタンスを求める。同じ接頭辞を持つ要求は同じ候補対へ写るため、キャッシュが無制限にクラスタ全体へ散らばらない。もし二つのハッシュが同じインスタンスを返した場合は、第二候補を `(第一候補のID+1) mod インスタンス数` へずらし、二つの候補を必ず異なるものにする。

この方式は二者択一の原理に基づく。理想化したランダム割当では、`n`個のインスタンスへ`m`個の要求を分配するとき、各要求が二候補の軽い方を選ぶと、最大負荷は平均`m/n`からおおむね`log log n`程度のずれに抑えられる。単一候補の場合より最大負荷の偏りが小さくなる。ただしこれは独立で均一なハッシュと理想化した到着分布に基づく理論であり、人気接頭辞が偏る実トラフィックで無条件に成立する保証ではない。

二候補に限定する理由は、三候補・四候補へ増やしても最大負荷の改善は逓減する一方、同じ接頭辞のKVを保持するノード数が増えて再利用率が落ちるからである。同じ接頭辞の要求数を`m`とすると、二候補へ限定する方式のキャッシュ命中率の下限を`max(0,1−2/m)`と説明し、一候補固定の`max(0,1−1/m)`へ近づく。要求数が多い人気接頭辞では、二候補でもキャッシュ局所性を高く保てる。

### 2. 接頭辞の長さを人気度で変える

ハッシュへ入れる接頭辞を固定長にすると問題が起こる。長すぎると本来共有している接頭辞より先まで含んでしまい、少しだけ異なる要求が別ノードへ散る。短すぎると異なる要求群が同じハッシュキーに衝突し、人気キーへ負荷が集中する。そこでDualMapは接頭辞人気度の木（prefix hotness tree）を持ち、トラフィックの滑動窓から各接頭辞の出現割合`ρ`を測る。

インスタンス数を`n`とすると、接頭辞のトラフィック比が`ρ>2/n`なら人気が高いと判定し、木の子ノードを増やしてハッシュに使う接頭辞を長くする。これにより人気接頭辞をさらに細分化し、二候補対を複数へ分散できる。逆に出現割合が`ρ<1/n`まで下がれば子を削除して接頭辞を短くし、キャッシュ再利用を高める。人気度が変わったときにキー長を動かす点が、固定長ハッシュとの違いである。

### 3. TTFT目標に合わせてキャッシュ優先を切り替える

各要求について二候補の予測TTFTを計算する。概念的には`TTFT(r,i)=待ち行列遅延Tq(r,i)+計算時間Tc(r,i)`であり、計算時間は接頭辞KVの再利用可否によって変わる。通常はより多くのKVを再利用できる候補を選ぶ。キャッシュ優先候補の負荷が増え、予測TTFTが設定されたSLOを超えそうな場合だけ、二候補のうち負荷の軽い方へ切り替える。

単純な最小予測TTFT方式は、一要求の予測遅延がわずかに小さい候補へ頻繁に切り替えるため、キャッシュ命中が不安定になる。DualMapはSLOを守れる間はキャッシュ親和を維持し、必要なときだけ負荷分散するため、局所性を壊す頻度を減らす。二候補の接頭辞命中率が同じ場合は負荷の軽い方を選ぶ。負荷指標には待機中の事前充填トークン数を使い、SLO内で処理できる最大待機トークン数を閾値として配車の切替条件にする。

### 4. ホットスポットの待機要求を第2候補へ移す

人気接頭辞の偏りが大きい場合、二候補のどちらか一方が既に過負荷になっていることがある。DualMapは新規要求の配車だけでなく、待ち行列にある要求をもう一方の候補へ移すホットスポット再均衡を行う。移送先は無制限にクラスタ全体から探すのではなく、最初にハッシュで決めた候補対のもう一方である。

移送する要求は、移送元と移送先の待ち時間、キャッシュ再利用後の事前充填計算時間を比較し、TTFT改善が見込めるものを優先する。移送先の負荷が低く、かつ再利用可能な接頭辞が多ければ、待ち行列を短くしながら再計算の増加を抑えられる。逆に移送先のキャッシュがほとんどなく、再計算費が大きい場合は、単純な移送が必ずしも得にならない。

### 5. 二重ハッシュリングでクラスタ伸縮の影響を局所化

インスタンスの追加・削除時に単純なハッシュの剰余を変えると、多くの接頭辞の割当先が一斉に変わり、蓄積したKVキャッシュの局所性が失われる。DualMapは二つの整合ハッシュリングを維持し、各要求の二候補をリング上の相対位置から決める。ノード追加や削除では、そのノード周辺の接頭辞だけが再写像され、全体を一度にシャッフルしない。

この仕組みは弾力拡縮を支えるが、ノード追加後にKVキャッシュが瞬時に全ノードへ複製されるわけではない。変更された一部のキーでは新しいノードのキャッシュが冷たい状態になり得る。二重リングの利点はその影響範囲を限定することであり、キャッシュ移動の費用がゼロになるという主張ではない。

### 6. vLLMとの統合

実装はvLLMの推論実行器を複数インスタンスとして配置し、その前段にグローバル配車器を置く。各インスタンスはモデル重み、KVキャッシュ、要求待ち行列を持ち、配車器へ待機トークン数やキャッシュ命中に必要な情報を返す。DualMapはvLLMの個別バッチ処理そのものを置き換えるのではなく、どの要求をどのインスタンスへ送るかを決める層に位置する。

## 評価

### 実機構成と測定指標

| 項目 | 論文の評価条件 |
|---|---|
| 推論実行器 | vLLMベースの分散LLM推論クラスタ |
| NPU | Ascend 910B3または910B4、各ノードに8基 |
| メモリ | 910B3は1基64GB HBM、910B4は1基32GB HBM、ノードに1.5TB DRAM |
| モデル例 | Qwen2.5-7B（動機実験で8インスタンス） |
| 実負荷 | Conversation、Tool&Agentなど接頭辞共有のあるワークロード |
| TTFT目標 | 主な評価では5秒 |
| 比較対象 | Cache Affinity、Least Loaded、Preble、Min TTFT（Mooncake系の簡略化） |
| 指標 | SLO内で処理できる有効要求容量、goodput、P50/P90 TTFT、E2E遅延、KV命中率、負荷CV |

実験の「有効要求容量」は単にクラスタへ到着した要求数やモデルの生成トークン数ではなく、設定したTTFT SLOを満たして処理できる要求数に着目する。キャッシュ命中率は事前充填の再計算を避けられる割合、負荷CVは各インスタンスの待機事前充填トークン数のばらつき、P90 TTFTは遅い側10%に相当する初回応答時間を表す。単一の平均TTFTだけではホットスポットの尾部遅延を見落とすため、複数指標を併用している。

### キャッシュ親和性と負荷分散の衝突

動機実験のConversationワークロードでは、純キャッシュ親和方式のKV命中率がLeast Loadedより1.21倍高かった。これは接頭辞を同じノードへ集める利点を示す。しかし負荷CVではLeast Loadedがほぼ0に近く、キャッシュ親和方式は人気接頭辞が集中して負荷の偏りが大きい。Tool&Agentでもキャッシュ親和方式は高い命中率を示すが、人気の高い共通指示に要求が偏ると一部ノードの待ち行列が長くなる。

DualMapは二候補の範囲内でキャッシュ優先と負荷優先を選び、両方の指標の中間に妥協するだけではなく、キャッシュ命中を高く保ちながら負荷CVを下げる方向へ移動する。二候補方式の価値は「命中率だけ最大」でも「CVだけ最小」でもなく、TTFT SLOの下で処理できる要求容量を増やすことにある。

### 有効要求容量と尾部遅延

実ワークロードの評価で、DualMapは同じTTFT SLOの下で有効要求容量を既存の配車方式より**最大2.25倍**改善した。SLOを守る要求数の改善であり、トークン生成の単体スループット、モデルの計算速度、単一要求のTTFTが一律に2.25倍改善したという意味ではない。論文はP90 TTFTの低下も報告し、ホットスポットによる待ち行列の尾部遅延を抑えたことを示す。

負荷が軽いときはキャッシュ優先で再利用を高め、負荷が増えるとSLOを超えないように第2候補へ逃がす。最小予測TTFTだけを逐次選ぶ方式は候補の切替が多くなり、長期的なキャッシュ命中を不安定にしやすい。DualMapはTTFT目標を閾値として切替を抑えるため、接頭辞の再計算を減らしつつ待ち行列の集中を防ぐ。最大2.25倍は評価条件に依存する上限の観測値であり、すべての負荷で同じ改善率ではない。

### ホットスポットと拡縮に対する頑健性

人気接頭辞が一つのノードへ集中すると、単純な二候補のうち片側へ要求が偏る場合がある。DualMapは接頭辞人気度木を使ってハッシュキーを細分化し、既存の待機要求も第2候補へ移送するため、単なる二者択一より偏りに対応できる。再均衡は全クラスタへの無差別移送ではなく、候補対内でキャッシュ再利用を考慮するため、負荷分散とキャッシュ局所性を同時に考える。

ノードの増減では二重ハッシュリングにより再写像範囲を局所化する。クラスタ全体の割当先を毎回変える方式に比べ、既存KVキャッシュを保持したノードへの親和性を残しやすい。ただし再写像される一部の接頭辞は新ノードでキャッシュを再構築する必要があり、伸縮時のキャッシュ命中率が完全に不変になるわけではない。

### 比較方式の読み方

| 方式 | 強い点 | 失敗しやすい条件 |
|---|---|---|
| Cache Affinity | 接頭辞KVを再利用しやすい | 人気接頭辞へ要求が集中し、尾部TTFTが悪化 |
| Least Loaded | 待機トークン数を均等化しやすい | 共有接頭辞が分散してKV再計算が増える |
| Min TTFT | 個別要求の短期的な予測遅延を最小化 | 負荷変動で配車先が揺れ、キャッシュ命中が不安定 |
| Preble | 接頭辞の再利用量で配車を切替 | 単一写像空間で局所性と分散の交換条件が残る |
| DualMap | 二候補の局所性を残しつつSLOで切替 | 二候補とも混雑する条件や予測誤差に弱い |

この比較は、各方式の目的関数が異なることを明確にするためのものである。KV命中率が最高でもSLOを破れば有効要求容量は下がり、負荷CVが最低でもキャッシュ再計算が増えればTTFTが悪化する。したがって、複数の指標を同時に見ることが必要である。

## 既存研究との差

PrebleやMooncake/Dynamo系は単一の配車空間でキャッシュ優先と負荷優先を切り替える。DualMapは各接頭辞に二つの安定した候補を持たせ、SLOに応じた選択と待機要求の再配置を候補対の内部で行う。二候補を固定することで、負荷逃がしのたびに全クラスタから新しい行き先を探す必要がなく、キャッシュの局所性を維持しやすい。

通常の整合ハッシュはノード増減の再写像を抑えるが、一つの候補しか持たないと人気接頭辞の負荷集中を解消しにくい。DualMapは二重ハッシュリングを使って候補対を維持し、増減時の局所性と負荷分散の両方を狙う。vLLMの実行器内部の連続バッチ化とは別層の最適化であり、両者は組み合わせられる。

## 限界と負の結果

TTFTの推定は待機事前充填トークン数とキャッシュ再利用による計算時間の変化を中心に組み立てる。復号側のメモリ不足、複雑な実行干渉、予測不能な負荷急増が強いと、推定TTFTと実際の遅延がずれる可能性がある。二候補とも混雑している場合、二者択一だけでは新しい空き容量を生み出せない。接頭辞人気度木の閾値もインスタンス数と負荷分布に依存する。

実機評価はAscend 910B3/910B4を用いたクラスタであり、CUDA GPU、異なるネットワーク、異なるキャッシュ管理方式で同じ絶対遅延や最大改善倍率になることを示していない。2.25倍は有効要求容量の最大改善であって、個別要求の生成速度やすべてのワークロードの平均改善率ではない。二重リングの再写像は局所化されるが、影響を受けた接頭辞のキャッシュ再構築費は残る。
