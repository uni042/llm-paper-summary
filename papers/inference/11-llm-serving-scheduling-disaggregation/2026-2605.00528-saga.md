# SAGA: Workflow-Atomic Scheduling for AI Agent Inference on GPU Clusters

> エージェントの全ワークフローを単位にKV保持・セッション親和性・公平性を共同制御し、64基A100でタスク完了時間を幾何平均1.64倍短縮する。
## 書誌情報
- **著者**: Dongxin Guo, Jikun Wu, Siu Ming Yiu
- **著者・所属**: The University of Hong Kong
- **公開**: arXiv:2605.00528v2
- **種別**: arXivプレプリント
- **対象**: エージェント推論、ワークフロー認識スケジューリング、KVキャッシュ管理、GPUクラスタ、マルチテナント公平性
- **実装**: vLLM 0.6.0 V1 engineを約8.5K行Pythonと1.2K行C++/CUDAで拡張し、RayとgRPCの分散スケジューラ、KV管理、AFS公平性モジュールを実装。公開コードURLは本文から確認できない。
## 概要
SAGAは、AIエージェントが1タスクで数十〜数百回のLLM呼び出しとツール実行を繰り返すのに、従来サーバが各呼び出しを独立要求として扱うためKVキャッシュを失い、再計算と負荷偏りを起こす問題を、ワークフロー全体を第一級のスケジューリング単位にして解く。エージェント実行グラフ（Agent Execution Graph; AEG）から次段のKV再利用確率とツール待ち時間を推定し、ワークフロー認識LRUとツール別TTLでキャッシュを保持する。さらにセッション親和性ルーティングと仕事奪取で局所性と負荷分散を両立し、Agent Fair Shareで要求数ではなくタスク完了時間の公平性を制御する。64基A100の評価でvLLM 0.15.1の自動プレフィックスキャッシュ＋親和性ルーティング比でタスク完了時間を幾何平均1.64倍短縮し、GPUメモリ有効利用を1.22倍、マルチテナントSLO達成率を99.2%へ改善した。

SAGAは個別要求ではなくエージェントのワークフロー全体を第一級のスケジューリング単位とする。AEGで次段の構造と遷移確率、ツール種別を表現し、その情報をKV追い出し、TTL、ルーティング、仕事奪取、公平性へ一貫して伝える。ワークフロー認識LRUは再利用確率・経過時間・キャッシュサイズを組み合わせて将来価値の低いKVを選び、実運用トレースでオフライン最適Belady法の1.31倍以内へ近づく。セッション親和性と仕事奪取は局所性を優先しつつ過負荷時だけ移行し、Agent Fair Shareは残作業と締切からタスク完了の緊急度を計算してマルチテナント公平性を保つ。

代表結果として、SWE-bench TCTは64 GPU、500 verified tasksでvLLM 0.15.1 + APC + affinity ルーティング 352.1±21.4秒に対して203.4±12.8秒、vLLM+APC比1.73倍短縮。プレフィックス共有だけでなくセッション固有KVをツール境界越しに保持する利得が残る。
## 問題設定
従来のLLMサーバは各推論呼び出しを独立要求として扱い、到着要求を連続バッチ化してGPU処理量を最大化する。しかしエージェントは推論、ツール実行、観測追加、次の推論を同一タスク内で反復し、各段の文脈とKVキャッシュが強く連続する。ツール待ちが50msから数十秒ある間にLRUでKVが追い出されると次段で再生成が必要になり、32K文脈・70B級ではセッション当たり数GBの状態を失う。実測ではvLLMがタスク時間の38%をKV再生成に使い、GPUメモリ有効利用は42%、端から端の完了時間は純粋な推論時間の6倍に膨らむ。プレフィックスキャッシュや通常の親和性ルーティングは共有プレフィックスを再利用しても、セッション固有の将来再利用、ツール待ち時間、タスク単位公平性を同時に扱えない。
## 新規性

## 手法
### 手法のあらまし
入力はエージェントフレームワークから届く複数段タスクと各段のLLM要求、ツール呼び出し情報である。まずAgent InterfaceがLangChain等の注釈を読み、各推論段をノード、依存関係を辺、遷移確率とツール種別を属性とするAEGを構築する。注釈がなければ過去要求列からツール型パターンと遷移確率を推定し、信頼度0.7以上の辺を残す。次にGlobal スケジューラがセッションIDとKV所在、各worker負荷、テナント別公平性状態を参照し、既存KVを持つworkerを優先して次要求を配送する。各workerではAEGから次段でKVが再利用される確率とプレフィックス重複を推定し、ワークフロー認識LRUの追い出し得点とツール種別ごとのTTLを計算して、ツール実行中も価値の高いKVをHBMへ残す。workerが過負荷なら閾値付き仕事奪取で別workerへタスクとKV状態を移行し、局所性より負荷分散の利益が大きい時だけ配置を変える。並行してAgent Fair Shareが各テナントの残作業量と締切までの残時間から緊急度を更新し、容量配分や必要なpreemptionを決める。最終的に次段要求は可能なら既存KVをそのまま再利用してvLLMで実行され、生成結果とツール観測がAEG状態へ反映されて次の周期へ進む。出力は個々のトークンだけでなく、KV連続性を保ったタスク全体の完了であり、全層が同じworkflow identityを共有する。

### エージェント実行グラフ（AEG）
各LLM推論段をノード、段間の依存を有向辺として表し、辺に遷移確率、ノードにツール種別を持たせる。明示的なフレームワーク注釈があればタスク受付時に構築し、なければ過去要求からツール型パターンを抽出して遷移確率を学習する。現在ノードから次段候補と再利用確率を計算し、現在KVプレフィックスと予想次段プロンプトの重複率を推定する。この情報がキャッシュ保持、TTL、ルーティングの共通入力となるため、個別要求だけでは見えない『ツールから戻った後に同じ状態を使う』価値をスケジューラへ伝える。

### ワークフロー認識LRUとツール別TTL
各セッションについて最終利用からの経過時間、AEGが予測する将来再利用確率、KVサイズを0〜1へ正規化し、重み付きの追い出し優先度を計算する。再利用確率の重みを最も大きくし、単純LRUが長いツール呼び出し中の重要KVを捨てる問題を避ける。さらにコード実行、Web/API、DB等のツール種別ごとに待ち時間分布を指数移動平均で維持し、既定では95パーセンタイルをTTLにする。GPUメモリ使用が70%を超えるとTTLを縮め、90%付近では強い追い出しへ移るため、将来再利用と現在のメモリ圧力を同時に扱う。

### セッション親和性と仕事奪取
次段要求が来るとGlobal スケジューラはそのセッションのKVを保持するworkerを第一候補にし、負荷が閾値以下なら同じworkerへ配送して再生成やネットワーク移送を避ける。一方、親和性だけを守ると特定workerへ要求が集中するため、idle時間と最大・最小負荷比を監視し、条件を超えた時だけ軽いworkerが重いworkerからタスクを奪う。移行時はKVキャッシュとworkflow-aware TTL状態を一緒に移し、移行後も将来再利用予測を継続する。これにより局所性を通常経路、仕事奪取を過負荷時の例外として使い分け、GPUを遊ばせずにKV再利用も維持する。

### Agent Fair Share
要求数ではなくエージェントタスクの完了を公平性の単位にする。各テナントについて、活動中タスクの推定残作業量を締切までの残時間で割った緊急度を集約し、容量配分と優先順位へ使う。重いエージェントが多数の要求を発行してキューを占有したり、逆に短いタスクが長いワークフローの途中状態を壊したりすることを避ける。高優先タスクが低優先タスクに阻害される場合はpreemptionとKV移行を行うが、移行先へTTL状態も渡すため公平性制御がキャッシュ予測を無効化しない。論文は有界な需要異質性の下で完了時間偏差を抑える保証を与える。

### パターン推定とcold-start退避
フレームワークがAEGを明示しない場合、SAGAは観測した要求列からツール種別の並びと遷移を抽出し、信頼度0.7以上の辺だけでAEGを作る。保持トレースでは次段予測精度87%で、明示ヒントよりTCTが15.6%悪化するが、AEGなしより大幅に速い。未知エージェント型は最初の30タスクを通常の要求単位方式で処理し、履歴が貯まってから推定を有効化する。誤予測は実際の次要求到着時に検出して以後のルーティングを修正するため、誤った枝のKVを保持する無駄は生じても誤りが連鎖して生成結果を変えることはない。

### 全体のデータ／制御の流れ
三層構成で、Agent InterfaceがAEGを作り、Global スケジューラがクラスタ全体のsession-to-worker対応、負荷、AFSを管理し、Worker Poolの拡張vLLMがWA-LRUとTTLを実行する。RayとgRPCで分散調停し、worker-to-coordinatorのP99遅延は5ms未満。公平性preemptionや仕事奪取で移行する場合もworkflow-aware TTL状態を移行メタデータへ載せ、移行先が新規KVとして扱わない。状態更新は100msのスケジューリングepochまでの有界な遅れを許す。
## 評価条件
- **ハードウェア**: 8ノード×NVIDIA A100-80GB 8基＝64 GPU、各ノードAMD EPYC 7763 CPU 2基・128コア、DDR4-3200 1TB、NVMe 4×3.84TB、ノード間200Gbps InfiniBand HDR + GPUDirect RDMA、総GPUメモリ5.12TB
- **ソフトウェア**: Ubuntu 22.04、CUDA 12.1.1、Python 3.10.12、PyTorch 2.1.2+cu121、vLLM 0.6.0、FlashAttention 2.5.6、Ray 2.9.0。
- **データセット／トレース**: SWE-bench verified 500タスク、WebArena 812タスク、BurstGPT由来10テナント合成ワークロード
- **比較対象**: vLLM 0.6.0 FCFS + PagedAttention、vLLM 0.15.1 Automatic Prefix キャッシュ + PrefixCacheAffinityRouter、SGLang 0.5.8 + RadixAttention、Llumnix 1.2 + live KV migration、TensorRT-LLM 1.1 + Scaffolding、vLLM上のKVFlow再実装
各実験10回を異なる乱数seedで実行し平均±標準偏差を報告。両側Welch t検定で有意差を評価し、3回のwarm-upを除外。1.5×IQR外れ値は2%未満を除外。
単一データセンターのA100クラスタとLlama-3-70B-Instructに限定した実機評価。SWE-benchは平均37段・最大150段、WebArenaは平均18段の長いエージェントワークフローを含む。マルチテナント負荷はクラスタ最大処理量のおよそ80%を狙う競合状態。95%超のHBM過剰割当、地理分散、MoEモデルは未評価。
## 主要結果
SAGAは最新vLLM 0.15.1の自動プレフィックスキャッシュと親和性ルーティングを併用した比較対象に対し、SWE-benchで1.73倍、WebArenaで1.55倍、幾何平均1.64倍のTCT短縮を達成する。KV再生成割合を38%から8%へ、GPUメモリ有効利用をvLLMの42%からSAGAの71〜75%へ改善し、マルチテナントSLO達成率を99.2%へ高める。一方、タスク完了時間を優先するため純粋な処理量最大化方式よりピーク処理量は約30%低い。

- SWE-bench TCT / 203.4±12.8秒、vLLM+APC比1.73倍短縮 (比較対象: vLLM 0.15.1 + APC + affinity ルーティング 352.1±21.4秒; 条件: 64 GPU、500 verified tasks) — プレフィックス共有だけでなくセッション固有KVをツール境界越しに保持する利得が残る。

- WebArena TCT / 82.1±6.8秒、vLLM+APC比1.55倍短縮 (比較対象: vLLM+APC 127.3±10.1秒; 条件: 64 GPU、812 tasks) — 異なるエージェント種別でもワークフロー単位制御が有効。

- GPUメモリ有効利用 / SWE-bench 71.3%、WebArena 74.6% (比較対象: vLLM+APC 58.7%、61.2%; 条件: 端から端評価) — 将来再利用価値を見てKVを保持し、空きHBMを有用状態へ使う。

- KV再生成時間割合 / 8% (比較対象: vLLM 38%、vLLM+APC 22%; 条件: SWE-bench時間内訳) — ツール待ち中のworkflow-aware TTLがセッション固有KVの消失を抑える。

- WA-LRUのBelady比 / SWE-bench 1.31倍、WebArena 1.28倍、平均1.30倍 (比較対象: 標準LRU平均2.48倍、prefix LRU平均1.86倍; 条件: production トレース replay) — ワークフロー構造が見えるとオンラインKV管理がオフライン最適へ大きく近づく。

- マルチテナントSLO達成率 / 全体99.2%、light tenant 98.7% (比較対象: vLLM全体67.3%、light 43.2%; 条件: BurstGPT由来10 tenant、約80% offered load) — Agent Fair Shareが要求量の少ないテナントの長い待ちを抑える。

- 拡張性 / 8→64 GPUで6.4倍、80%効率 (比較対象: 8 GPU; 条件: 固定ワークロード) — 分散coordinatorを含めてもクラスタ規模で有効。

- ピーク処理量の代償 / スループット-optimal BFSより約30%低い (比較対象: 純BFS 12.4 tasks/min; 条件: 32 GPU SWE-bench) — SAGAはバッチ処理量より対話型タスクのTCTを優先する設計。

### 負の結果・境界条件
- フレームワークからAEGヒントがなくパターン推定だけの場合、予測精度87%で明示ヒント比TCTが15.6%悪化する。
- 未知エージェントの最初の30タスクは要求単位処理へ退避するためcold-start費用がある。
- 5×P99を超える異常に長いツール待ちではTTL予測が外れてKVを追い出し得る。
- 95%超のHBM過剰割当状態は実験で検証していない。
- TCT最適化は純粋な処理量最大化に対し約30%のピーク処理量を犠牲にする。

### 結果の読み方
最大寄与はセッション親和性で、除去するとTCTが96%悪化する。これはエージェントの次段要求を既存KVのあるworkerへ戻すことが再生成回避の前提だからである。workflow-aware 追い出しとTTLは42〜54%、仕事奪取は31%の寄与を持ち、局所性だけでは負荷偏り、負荷分散だけではKV移行が増えるため両者の組合せが必要になる。AFSは単一ベンチマークでは8%の寄与だが、競合する複数テナントではlight tenantのSLOを43.2%から98.7%へ引き上げるため役割が異なる。
## 品質への影響
スケジューリングとKV状態管理のみを変更し、モデルの数値計算や生成確率を近似しない。
## 既存研究との差
既存のvLLM affinity ルーティングは類似プレフィックスを持つ要求を同じworkerへ送るがセッションIDとツール境界を追跡せず、長い待ちの間はLRUでセッション固有KVを失う。KVFlowはワークフロー認識の追い出しを扱うが、SAGAはそれに分散ルーティング、仕事奪取、ツール別TTL、タスク単位公平性を加える。SOLA等のSLOスケジューラが要求遅延を最適化するのに対し、SAGAのAgent Fair Shareは複数段タスクの残作業と締切から完了時間公平性を定義する。
## 限界
- AEGの明示ヒントがないとパターン推定精度87%となりTCTが15.6%悪化する。
- 動的なmulti-agent debateのように構造自体が頻繁に変わる場合はAEG再推定が増える。
- ツール待ち時間の極端な外れ値ではTTL予測が外れる。
- AFSは未知エージェントの残作業時間推定誤差に影響される。
- 単一データセンターのみで、地理分散KV移行は未対応。
- 実機評価モデルはLlama-3-70B-Instructのみで、Mistral/Qwen/DeepSeekやMoEは未検証。
- 95%超のHBM過剰割当領域は未検証。
- 対話型TCTを優先するため処理量最大化方式よりピーク処理量が約30%低い。
## 実装状態
vLLM 0.6.0 V1 engineを拡張し、約8.5K行Python、1.2K行C++/CUDAで実装。Ray+gRPCのGlobal スケジューラ、PagedAttentionを拡張したKV キャッシュ Manager、AFSモジュールを持つ。64 GPU実機で評価済みだが、確認した本文には公開コードURLの明記がない。
## 研究上の位置づけ
エージェント推論の性能問題を、個々のLLM呼び出しではなくツール待ちを含むプログラム全体の状態保存問題として捉え直した研究である。今後のagentic servingではKVキャッシュの価値が単なる最近利用時刻ではなくワークフロー上の将来再利用に依存することを示し、リクエスト-centric servingからworkflow-centric servingへの比較基準を与える。
