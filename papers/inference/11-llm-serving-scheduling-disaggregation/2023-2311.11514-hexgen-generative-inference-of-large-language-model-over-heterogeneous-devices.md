# HexGen: Generative Inference of Large Language Model over Heterogeneous Environment

> HexGenは、異種GPUを「同じ速さのワーカー」とみなさず、各GPUの計算性能・メモリ容量とリンク帯域に応じてテンソル並列（Tensor Parallelism; TP）とパイプライン並列（Pipeline Parallelism; PP）の仕事量を非対称に割り当てる。目的は、最遅GPU・最遅リンクが全体同期を支配する異種クラスタ特有のストラグラー問題を避けることである。

## 概要

均質GPUクラスタでは、TPの行列分割やPPの層分割を均等にしても各ワーカーの処理時間は近い。しかし、世代・価格帯の違うGPUとクロスデータセンターネットワークを混ぜると、同じ量の仕事を割り当てるほど遅いGPUや狭いリンクが同期点になる。

HexGenは生成推論を非対称TP/PPとして表し、GPUごとに異なる計算量を割り当てられる実行系を用意する。その上で、GPU性能、メモリ、GPU間帯域、予算、要求到着率、遅延サービスレベル目標（Service Level Objective; SLO）を制約にした配置探索を行う。

Llama-2 70Bの評価では、同額の均質ベースラインより最大2.3倍厳しい遅延期限を満たす構成、または最大4倍高い要求到着率を処理する構成を選択できる。

## 背景と問題設定

### 異種環境では「均等分割」が公平でも高速でもない

TPは各層の行列をGPU間で分けるため、1台だけ遅ければ集合通信前に他GPUが待つ。PPも同様に、遅い段へ同じ層数を割り当てるとパイプライン周期がその段で決まる。

さらにクロスデータセンターではGPU間リンクも非均質である。計算が速いGPUへ大量の仕事を移しても、その配置が大きなテンソルを低帯域リンク越しに往復させれば逆効果になる。

## 手法

### 1. TPとPPの両方を非対称化する

HexGenはGPUごとに同一比率のテンソル断片・同一層数を要求しない。高速GPUには大きい計算断片や多い層、低速GPUには小さい仕事を割り当てる。

### 2. ハードウェアとネットワークをコストモデル化する

各候補配置について、演算時間、メモリ収容可否、TP通信、PP段間通信を推定する。ネットワークトポロジーを無視せず、「どのGPU同士をTP群にするか」まで性能に含める。

### 3. 制約付き最適化でSLOと予算を同時に扱う

入力は利用可能GPU群、GPU価格、リンク、モデル、要求率と遅延期限である。探索器は配置候補を作り、容量超過やSLO違反を除外し、与えた予算で要求を処理できる非対称計画を選ぶ。

論文では遺伝的探索を用い、ランダムな配置変更ではなく制約を壊しにくい突然変異を使って探索を収束させる。

### 4. 実行時は静的に選んだ計画へ生成要求を流す

オンラインで毎トークン再配置するのではなく、環境と負荷に対して選んだ並列構成を実行エンジンへ反映する。これにより毎ステップの再計画費用を避けつつ、異種性は配置段階で吸収する。

## 評価

### 評価条件

| 項目 | 条件 |
|---|---|
| モデル | Llama-2 70B |
| 環境 | 性能・価格の異なるGPUと不均一ネットワークを含む異種/クロスDC構成 |
| 比較 | 同予算の均質GPUベースライン、対称版HexGen、Petals |
| 指標 | 達成可能な遅延期限、最大要求率、SLO達成率、探索時間、予算 |
| 配置探索 | 制約付き遺伝的探索 |

### 主な結果

| 比較 | 結果 | 解釈 |
|---|---:|---|
| 同予算の均質ベースライン | 最大 **2.3倍**低い遅延期限 | 異種GPUを価格性能比まで含めて使える |
| 同予算の均質ベースライン | 最大 **4倍**高い要求率 | 低価格GPUを追加した構成が容量へ変換される |
| 対称版HexGen | 最大 **1.8倍**低い遅延期限、**2倍**高いピーク要求率 | 非対称分割そのものの寄与 |
| Petals、半額予算条件 | 最大 **3.5倍**低い遅延期限、**10倍**高い要求率 | 動的スウォーム型との差を代表条件で確認 |
| 探索 | 全額予算例で約 **2.1分** | オンライン要求処理ではなく配備計画として償却可能 |
| コストモデル | 代表例で推定SLO 92%対実測94% | 配置探索に使える程度の整合を確認 |

## 既存研究との差

均質クラスタ向けMegatron型TP/PPは対称性を前提にしやすい。Petalsは分散参加ノードを動的に利用する一方、HexGenは既知の異種資源集合に対し、生成推論のTP/PP粒度を制約最適化して静的計画へ落とす。

## 限界・実装状況

性能モデルの精度はGPUカーネル、通信ライブラリ、ネットワーク混雑に依存する。背景トラフィックが大きく変動する環境では、配備時の帯域見積りから外れる可能性がある。

また、最大4倍等は特定の価格・GPU集合で得た値であり、異種GPUを混ぜれば常に安く速くなるわけではない。通信量の大きいTP群を狭いWANリンクへ跨がせると利得は消える。
