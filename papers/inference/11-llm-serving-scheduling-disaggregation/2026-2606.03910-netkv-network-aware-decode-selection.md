# NetKV: Network-Aware Decode Instance Selection for Disaggregated LLM Inference

> 分離推論のデコード先選択へネットワーク階層・帯域・混雑を加え、KV転送・キュー・初回デコード時間の合計が最小のGPUを要求ごとに選ぶ。
## 書誌情報
- **著者**: Mubarak Adetunji Ojewale
- **著者・所属**: 一次資料の著者欄を確認。
- **公開**: arXiv
- **種別**: Preprint
- **対象**: KV転送、分離推論、ネットワーク認識スケジューリング、TTFT、接頭辞キャッシュ
- **実装**: llm-dのEndpoint PickerやDynamo KV-aware ルーティングへ追加スコアラーとして統合可能な設計。NIXL/NCCL/RDMA、vLLM/SGLang、ネットワークハードウェアの変更不要。
## 概要
プリフィル/デコード分離ではプリフィル後のKVキャッシュをデコードGPUへネットワーク転送する必要があり、長文脈では転送時間がTTFTを支配する。NetKVは既存の負荷・接頭辞キャッシュ局所性に加え、プリフィル/デコード間の物理トポロジ階層、帯域、遅延、混雑、同時KV転送数をネットワーク費用オラクルから受け取り、転送+待ち行列+最初のデコード時間が最小のデコード先をO(|D|)で選ぶ。64 GPU fat-treeシミュレータとMooncakeトレースでは平均TTFTをRR比最大21.2%、調整済みキャッシュ+load比最大17.6%削減し、SLO達成率を最大20.1ポイント改善する。

NetKVはアプリ層スケジューラへ生のネットワーク構成を渡すのではなく、運用者がインスタンス対の局所性階層、階層帯域・遅延、集約混雑率だけを提供する薄いネットワーク費用オラクルを定義する。スケジューラは既存の接頭辞命中長とキュー状態へこの情報を組み合わせ、KV転送時間、待ち行列時間、最初のデコード反復時間の合計を直接最小化する。さらに自分が開始したKV転送数を別に追跡して自己混雑を二重計上せず、古い混雑情報でも階層順位が反転しない十分条件を示す。

代表結果として、平均TTFTは64 GPU fat-tree、Mooncake トレースでround-robin / キャッシュ+load-awareに対してRR比最大21.2%、調整済みCLA*比最大17.6%削減。デコードGPUの計算負荷とキャッシュ命中だけでは見えないKV転送経路を選択へ入れることで、TTFTのネットワーク部分を削減する。
## 問題設定
プリフィルとデコードを別GPUプールへ分離すると相互干渉を避けられる一方、プリフィルで生成したKVキャッシュをデコード開始前にネットワーク越しに運ぶ必要がある。128K文脈のLlama-3-70BではKV全体が約40GB、テンソル並列4ならGPU対ごとに約10GBとなり、25Gbpsの遠隔直接メモリアクセスでは約3.2秒かかり得る。既存ルータはデコードGPUの計算負荷と接頭辞キャッシュ命中を評価するが、同一ラック・同一ポッド・ポッド間の帯域差や動的混雑を要求単位の選択へ入れないため、暖かいキャッシュを持つ遠隔GPUが近い未命中GPUより遅い場合がある。
## 新規性
NetKVはアプリ層スケジューラへ生のネットワーク構成を渡すのではなく、運用者がインスタンス対の局所性階層、階層帯域・遅延、集約混雑率だけを提供する薄いネットワーク費用オラクルを定義する。スケジューラは既存の接頭辞命中長とキュー状態へこの情報を組み合わせ、KV転送時間、待ち行列時間、最初のデコード反復時間の合計を直接最小化する。さらに自分が開始したKV転送数を別に追跡して自己混雑を二重計上せず、古い混雑情報でも階層順位が反転しない十分条件を示す。
## 手法
### 手法のあらまし
処理は要求のプリフィル完了からデコード開始までを一つの流れとして扱う。まずプリフィルGPUで要求のKVキャッシュが完成すると、スケジューラは全デコード候補を列挙し、各候補が既に持つ接頭辞ブロックとの最長一致を調べる。この一致分を元KV容量から差し引き、実際にネットワークへ流す必要があるKV容量を候補ごとに決める。次に運用者側オラクルから、プリフィルGPUと候補GPUの物理的な局所性階層、その階層の公称帯域、基本遅延、現在の外部混雑率を取得する。さらにスケジューラ自身が同じ送信元・同じ階層へ既に開始しているKV転送数を加え、帯域を同時フローで分け合うと仮定して実効帯域を求める。実効KV容量をこの帯域で割り基本遅延を加えた値が転送時間になる。その後、候補GPUの待ち要求数、現在バッチ、空きバッチ枠からデコードへ参加できるまでの待ち時間を推定し、要求を追加した直後の最初のデコード反復時間も算出する。必要KVと安全予約領域を保持できない候補は除外する。残った候補について「KV転送時間＋キュー待ち時間＋最初のデコード時間」を同じ時間単位で足し、最小のGPUを選択する。選択後は既存のKV転送機構へそのまま転送を依頼し、送信元と局所性階層に対応する自己混雑カウンタを増やす。転送完了時にはvLLMやDynamoが元々持つ完了通知でカウンタを減らす。運用者側では標準スイッチ監視値を定期集約して混雑率だけを更新する。この入力取得、候補評価、転送開始、完了反映という一連の閉ループにより、次の要求では直前の自分の転送も考慮した状態から再び最適候補を選べる。候補ごとの処理は定数時間なので全体は候補数に線形であり、既存の接頭辞・負荷スコアリング経路へ追加できる。

### ネットワーク費用オラクル
クラスタ運用者がスケジューラへ、インスタンス対を0〜3の局所性階層へ写す静的対応表、各階層の公称帯域と基本遅延、動的な階層別混雑率を渡す。スケジューラは物理スイッチ構成や等コスト複数経路を直接理解する必要がなく、運用者も要求の意味を知る必要がない。静的情報はKubernetesの構成ラベルとハードウェア仕様から作れ、動的値は標準スイッチ監視値を集約できる。要求ごとの候補評価では送信元プリフィルGPUと各デコードGPUの階層を問い合わせ、その階層の帯域・遅延・混雑率を同一の時間費用へ変換する。この抽象化により、実装側は特定のファブリックやスイッチ製品へ依存せず、同一ノード、同一ラック、同一ポッド、ポッド間という粗い距離差を利用できる。監視値の更新が遅くても静的な帯域階層が大きく異なる限り順位を保ちやすく、細粒度テレメトリを必須条件にしない。既存の転送層やGPUハードウェアを変更せず、既存スコアラーへネットワーク費用を見せる情報境界として機能する。

### KV転送・キャッシュ・負荷の三項費用
各候補について、接頭辞ブロックの最長一致から既存KV率を求め、要求文脈長に比例する元KVサイズから命中部分を引いて実効転送量を算出する。階層帯域は外部混雑率と自分自身の同時転送数で割り引き、実効転送量を実効帯域で割って基本遅延を加え転送費用にする。これへデコードGPUのキュー長と空きバッチ枠から推定する待ち時間、要求追加後の最初のデコード反復時間を加える。三つの費用をすべて時間へ正規化するため、遠いが高いキャッシュ命中を持つ候補、近いが未命中の候補、近いが重負荷の候補を同じTTFT尺度で比較できる。さらに必要KV容量と安全予約領域を収容できない候補を先に除外するので、最低費用でも実行不能なGPUを選ばない。候補ごとの計算は局所的な状態参照と算術だけで、全候補を一度走査する線形時間で済む。既存のキャッシュ認識・負荷認識ルータを置換するのではなく、それらが持つ接頭辞一致とキュー情報をネットワーク転送費用と統合する点が中核である。

### 自己混雑追跡と古い情報への耐性
オラクルが観測する外部混雑と、スケジューラ自身が直前に開始したKV転送を分離する。要求を候補へ割り当てるたびに送信元と局所性階層の転送中カウンタを増やし、既存KV転送完了通知で減らすことで、短時間に同じ近距離階層へ要求を集中させて帯域を自己飽和することを防ぐ。候補評価時には外部混雑率だけでなく、この未完了転送数を使って利用可能帯域をさらに割り引くため、監視系がまだ自分の直前の転送を観測していなくても即座に負荷を反映できる。混雑監視値は更新間隔の間に古くなり得るため、静的帯域差と混雑誤差から階層順位が維持される十分条件も導出する。4対1の帯域差と中程度混雑の例では誤差42ポイントまで順位が保たれ、評価でも静的階層情報が利益の大半を占めるため高頻度の精密監視を必須にしない。これにより制御ループの高速性とネットワーク監視の低頻度性を分離している。

### 全体のデータ／制御の流れ
既存のプリフィル/デコード分離構成を維持し、プリフィル完了イベントでNetKVの候補評価を呼ぶ。候補GPUのメモリ、キャッシュ、負荷状態とオラクルのネットワーク状態を読み、候補数に線形の計算で最低費用候補を選び、そのまま既存KV転送へ依頼する。完了イベントで自己混雑状態を更新し、次要求の判断へ反映する。
## 評価条件
- **ハードウェア**: 64 H100相当GPUをモデル化した4階層fat-tree。TP=4。Tier 0同一node、Tier 1同一rack、Tier 2同一pod、Tier 3 cross-podの帯域/遅延差を設定。
- **ソフトウェア**: 離散イベント・フロー単位シミュレータ。Llama-3-70BのKVサイズと公開DistServe/vLLM/MLPerf値から推論時間モデルを構成。
Mooncake production トレースでchatbot、RAG、long-contextの3 ワークロードを駆動する。各KV転送をECMPで経路選択するフローとして扱い、共有linkではmax-min fair 帯域を再計算する。背景traffic、fat-tree oversubscription、リクエスト load、context length、oracle更新周期、prefix sharing、cluster sizeを個別に掃引する。比較はround-robin、キャッシュ-aware、load-aware、調整済みキャッシュ+load-aware CLA*、静的tierのみNetKV、full NetKV。CLA*重みは測定区間と分離したトレース sliceでgrid searchする。TTFT分布、TBT、SLO達成率、有効スループット、tier利用率、転送時間を5 seedで測る。
全数値はシミュレーションであり物理GPU/RDMA cluster実測ではない。ネットワークモデルは単一flowとfair sharingを解析値へ0.1%以内で検証し、推論時間は公開値へ25%以内でcross-validationするが、NIC driver queue、completion queue、カーネル bypass等はモデル外。
## 主要結果
NetKVはネットワーク距離と混雑を考慮してKV転送を近いtierへ寄せ、転送時間を直接削減する。RAG 100%負荷ではCLA*のcross-pod比68%を31.1%へ下げ、same-podを32%から68.9%へ増やし、平均転送時間を835msから620msへ25.7%削減する。負荷・文脈長・oversubscriptionが増えネットワーク項が大きくなるほどTTFT利益が拡大し、TBT増加は全条件0.5ms未満に留まる。

- 平均TTFT / RR比最大21.2%、調整済みCLA*比最大17.6%削減 (比較対象: round-robin / キャッシュ+load-aware; 条件: 64 GPU fat-tree、Mooncake トレース) — デコードGPUの計算負荷とキャッシュ命中だけでは見えないKV転送経路を選択へ入れることで、TTFTのネットワーク部分を削減する。

- SLO達成率 / 最大+20.1ポイント (比較対象: RR; 条件: RAG、16K context sweep) — KV転送がSLO境界を支配する領域では数百msの転送削減がdeadline missを大きく回復する。

- TBT オーバーヘッド / 全評価条件で+0.5ms未満 (比較対象: CLA*等; 条件: load/context/topology sweeps) — ネットワークを優先してデコード先を変えてもデコード バッチ効率への副作用は小さい。

- tier shifting / cross-pod 68.0%→31.1%、same-pod 32.0%→68.9%、転送835→620ms (比較対象: CLA*; 条件: RAG 100% load) — 性能改善の主要機構は遠いtierを避ける配置変更であり、静的topology情報だけでも利益の大半を得られる。

### 負の結果・境界条件
- 64K contextなどcluster capacity自体を超える領域では全スケジューラがSLOを失いNetKVの差はほぼ消える。1:1 oversubscription・背景trafficなしではtier帯域差が小さいためCLA*比利益も小さい。INT8等でKVを半減すればnetwork項の重みが下がり利益も縮む。実評価はシミュレーションのみで、serial transfer→queue→デコードモデルはproductionのtransfer-compute overlapを無視するため絶対TTFT差を過大評価し得る。

### 結果の読み方
KVサイズはcontext長へ線形増加する一方、デコード queue差は同様には増えないため、長文脈ほどnetwork pathの選択が支配的になる。ただし容量超過で全候補が過負荷になるとnetwork最適化だけでは救えない。静的tier signalが大半の効果を持つため、細粒度telemetryなしでも導入価値がある。
## 品質への影響
配置先だけを変更しモデル計算・KV精度を変えないため生成品質への影響はない。
## 既存研究との差
DistServeは配置時にsame-nodeを好むが要求ごとのnetwork stateを使わず、Mooncake/llm-d/Dynamoはキャッシュ localityとloadを使うが物理距離・混雑をscoreへ直接入れない。FlowKV等はKV転送機構自体を高速化するのに対しNetKVはどのデコード instanceへ送るかを変えるため相補的である。training向けnetwork-aware スケジューラは周期的で既知のcollectiveを対象とするが、NetKVは到着時刻もpayloadも変動するinference KV transferをonlineに選ぶ。
## 限界
評価はflow-level simulatorのみで実GPU/RDMA clusterのエンドツーエンド測定がない。デコード iteration時間も公開値からfitしており、NIC queueingやカーネル-bypass オーバーヘッドを含まない。transfer、queue、first デコードを直列加算するため、Mooncake等が行う転送と計算の重畳が強い環境ではnetwork項の可視時間を過大評価する。tier別混雑集約はECMPの個別link collisionを見えなくし、greedy per-リクエスト選択は複数同時要求をjoint optimizeしない。TP=4中心でTP=8の候補pool縮小は未検証。
## 実装状態
現状はシミュレーション研究だが、設計はllm-d scorer chainまたはDynamo KV-aware ルーティングの追加scorerとして実装可能。静的 oracleは既存topology labels、動的 congestionは標準switch telemetryから生成し、既存transport/inference engine/hardwareを変更しない。
## 研究上の位置づけ
プリフィル/デコード分離とKV キャッシュ ルーティングの間にnetwork topologyを第三のスケジューリング信号として加える研究。CPU DRAM/SSDを経由するmulti-hop KV ルーティングへも自然に拡張でき、各hopのtier costを加算できるため、階層KV保存研究と直接接続する。SSD-backed KVではstorage read 遅延だけでなく、SSD/CPU nodeからデコード GPUまでのnetwork pathも共同最適化する余地を示す。
