# Pallas: A Proactive KV Cache Migration Framework for LLM Inference in AI-RAN

> 移動端末の基地局切替前に、安定した履歴prefixは移行先GPUで再計算し、増え続けるsuffix KVは移行元から転送して、切替後の生成停止と遠隔転送遅延を抑える。

## 概要

無線アクセス網AI基盤（AI-RAN）では、基地局近傍のGPUでLLMを動かすことで通信経路を短くできる。しかし利用者が別基地局へハンドオーバーすると、生成に必要なKVキャッシュが旧基地局に残る。旧側で生成を続ければトークン間遅延（ITL）が継続的に増え、切替後に全KVを移動・再計算すればサービス中断時間（SIT）が長くなる。

Pallasはハンドオーバー予測を利用し、切替時点を復旧開始ではなく準備期限として扱う。旧基地局でtoken生成を続けながら、移行先へ推論状態を先回りして用意する。

## 手法

### 安定prefixの再計算と増分suffixの転送

準備開始時点までのtoken列を安定prefixとし、移行先は小さいtoken列を受け取って事前充填（prefill）によりKVを再構築する。その後に旧側で生成されるtokenは変化するsuffixとして、対応KV blockを順次転送する。

この分割により、大きな歴史KVをすべて低帯域回線で転送せず、同時に生成継続中の最新状態も追従する。

### 先読み窓（prefetching window）の選択

準備を早く始めるほどprefix再計算の余裕は増えるが、その後に転送すべきsuffixが長くなる。遅すぎれば切替時に処理が残る。schedulerは文脈長、prefill / decode速度、基地局間goodput、移動予測から開始時点をオンラインで選ぶ。

予測した移行先や時刻が変わった場合は、準備済み状態の鮮度と残作業を見て計画を更新する。

## 評価

vLLM 0.8.5ベースのprototypeを、各1台のNVIDIA RTX A6000を備えた物理server 2台と1 Gbps Ethernet上へ実装した。Llama-3-8B、Qwen3-14B、Qwen3-32Bを用い、基地局間帯域100〜500 Mbpsの条件と、反復ハンドオーバーのtrace-driven simulationを評価する。

移行先で切替後に復旧する方式に対し平均SITを2.28〜89.68倍短縮し、旧基地局から転送し続ける方式に対し平均ITLを16.0〜50.0%削減した。値はmodel、文脈長、帯域、予測誤差により変わる。

## 既存研究との差

datacenter内のKV live migrationは通常、既知のnetworkと移行先で負荷移動を行う。Pallasは移動端末の切替予測を前提に、帯域の限られる基地局間で「既存prefixは再計算、生成中suffixは転送」を並行させる点が特徴である。

## 限界

- sourceとtargetが同一model構成を実行できる前提である。
- 移行先と切替時刻の予測誤差が大きいと、先行準備が無駄になる。
- 物理prototypeはserver 2台であり、大規模RAN全体の混雑は主にtrace-driven simulationで扱う。
- 100〜500 Mbpsの基地局間帯域を想定しており、network条件が結果を大きく左右する。
- 2026-09-08確認時点で公式コード公開は確認できない。

## 一般的な実装上の含意

増え続ける推論状態を移行する場合、状態全体を静的objectとしてコピーするより、確定済み部分を再計算し、更新部分だけをstreamする方がcritical pathを短くできる。予測時点は単なる早期開始ではなく、再計算量と増分転送量の両方を決める制御変数になる。
