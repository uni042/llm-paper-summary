# DualScale: Energy-Efficient Disaggregated LLM Serving via Phase-Aware Placement and DVFS

> DualScaleは、プリフィル・デコード分離のGPU台数・並列度・周波数・振り分け比率を数分単位で配置し、プリフィルの将来待ち行列とデコードのTPOT余裕を反復ごとに制御してSLO内の電力を減らす二段階方式。

## 概要

プリフィルは計算量が大きく到着集中でTTFTが悪化し、デコードはメモリ帯域に律速されやすい。両段階を同じ周期・周波数で制御すると、低負荷時の高周波数電力を削れず、急なプリフィル負荷ではSLOを破りやすい。

DualScaleは、数分単位でGPU台数・テンソル並列度・基準周波数・振り分け比率を整数計画から配置し、その安全域でプリフィルは将来バッチを見越すモデル予測制御、デコードはTPOTを満たす最小周波数選択を反復ごとに行う。KV使用率が高いときは省電力設定を上書きして処理を急ぐ。

16基H100のLlama 3.3 70B実機評価では、DistServe比でプリフィルのエネルギーを最大39%、デコードを最大48%削減し、TTFTとTPOTの目標を維持した。

## 問題設定
プリフィルとデコードを分離したLLM提供では、入力処理を行うプリフィル群と逐次生成を行うデコード群で性能特性が大きく違う。プリフィルは計算量に支配されやすく、短時間の到着集中で待ち行列が急増するためGPU周波数を下げると最初のトークンまでの時間が悪化しやすい。一方、デコードはメモリ帯域に支配されやすく、各要求が多数の反復に残るため負荷変化は比較的滑らかだが、KVキャッシュがGPUメモリを長時間占有する。数分単位の自動スケーリングだけでは秒以下の負荷変動に追従できず、全GPUを高周波数で動かすと低負荷時に無駄なエネルギーを消費する。逆に両段階へ同じ周波数制御則を適用すると、プリフィルの急変やデコードのメモリ圧迫を見落としてサービス品質目標を破りやすい。さらに、分離構成では各段階のインスタンス数、テンソル並列度、基準周波数、要求振り分け比率を同時に決める必要があり、配置と周波数の探索空間が組合せ的に膨らむ。
## 新規性
DualScaleの新規性は、分離型推論のエネルギー最適化を、数分単位の配置決定と反復単位の周波数調整という二つの時間尺度へ明確に分け、しかもプリフィルとデコードで別の制御方式を使う点にある。上位層では予測された次の負荷区間について、各段階のGPU台数、テンソル並列度、基準周波数、振り分け比率を整数線形計画で選び、まず遅延とメモリの実行可能領域を確保する。下位層では、その安全域の中で短時間の余裕を回収する。プリフィルには将来の待ち行列まで見越すモデル予測制御を、デコードには各反復がトークン間時間を満たす最小周波数を選ぶ軽量方式を用いる。これにより、配置予測の誤差を細粒度の周波数制御で補正する構造になっている。
## 手法
### 手法のあらまし
処理は事前計測とオンライン制御に分かれる。まず各モデルとGPUの組合せについて、バッチ中の要求数、入力長統計、テンソル並列度、GPU周波数を変えながらvLLMの反復遅延と消費電力を測定する。得られたデータからプリフィル用・デコード用の遅延モデルと電力モデルを学習し、配置探索用の反復単位シミュレータを構成する。このシミュレータは実際の要求到着列を再生し、待ち行列、バッチ形成、TTFT、TPOT、KVキャッシュ使用量、各反復の電力を追跡する。

上位の第1層は約5分ごとに働く。直前の5分間を次の5分間の負荷予測として用い、プリフィル・デコードそれぞれの候補構成について、GPU使用数、サービス品質目標を満たせる最大要求率、1要求当たりエネルギーをシミュレータで事前計算する。最大要求率は要求列を間引きながら二分探索し、TTFTまたはTPOT違反が出ない最大点を求める。これらを構成表にして整数線形計画へ入力し、クラスタ全体のGPU台数制約の下で、両段階が予測ピーク要求率に安全余裕を加えた処理能力を持つようにインスタンス数と構成を選ぶ。振り分け比率は各インスタンスの処理能力に比例させる。

下位の第2層は反復ごとに周波数を変える。プリフィルでは新規要求が短時間に集中し、現在の周波数選択が後続要求の待ち時間まで変えるため、単一バッチだけではなく複数の将来バッチを予測するモデル予測制御を使う。候補周波数列を最大周波数から段階的に下げ、予測TTFTを満たす範囲で消費電力が最小になる割当てを探す。実装では7段階の候補周波数と最大8バッチの予測区間を用い、枝刈りと並列化で平均約4 msに抑える。新規要求到着時にも再計算し、予測より実測が遅ければ直ちに最大周波数へ戻す。

デコードでは負荷が滑らかで、現在の周波数が遠い将来の待ち行列へ与える影響が小さいため、長い予測区間を使わない。各反復について低い周波数から順に遅延を予測し、トークン間時間の制約を満たす最小周波数を採用する。低周波数化で各要求の滞在時間が延びると同時実行要求数とKVキャッシュ量が増えるため、キャッシュ使用率が閾値を超えた場合は最大周波数へ強制的に戻し、要求完了を早めてメモリを回収する。こうして上位層が確保した余裕を下位層が局所的に使い切る。

### 第1層の段階別配置最適化
各候補インスタンスを、プリフィルかデコードか、テンソル並列度、基準GPU周波数の三要素で表す。要求列を反復単位シミュレータへ流し、GPU使用数、サービス品質目標を満たせる最大要求率、1要求当たりエネルギーを求める。最大要求率は要求をランダムに間引く方法で負荷を変え、到着時系列の局所的な集中を保ったまま二分探索する。整数線形計画は、総GPU数を超えず、プリフィルとデコードの双方が予測ピーク要求率に安全余裕を加えた処理能力を持つという独立制約を課す。片側を過剰配置しても他方の不足を補えない分離型推論の性質を明示的に制約へ入れる点が重要で、選ばれた処理能力に比例して振り分け比率も決める。

### プリフィル向けモデル予測周波数制御
プリフィルでは一つの大きな入力処理が現在のバッチ時間だけでなく後続要求の待ち時間を増やし、最初のトークンまでの時間へ連鎖的に影響する。そのためDualScaleは、現在の待ち行列と将来数バッチの構成を遅延モデルで投影し、候補周波数の系列全体を評価する。最初は高周波数で実行可能な系列を作り、各位置の周波数を段階的に下げた候補を生成して、TTFT制約を満たす中から電力最小の系列を残す。7周波数、最大8バッチの範囲では平均約4 msで探索できる。新規要求到着や予測誤差を検出した場合には再計算または最大周波数復帰を行い、急なバーストに対して安全側へ倒す。

### デコード向け軽量周波数選択とKV保護
デコードでは各要求が多数のトークン生成反復に残るので、待ち行列はプリフィルより滑らかに変化する。また処理はメモリ帯域律速になりやすく、SM周波数を下げても遅延増加が比較的小さい。そこで各バッチに対して候補周波数を低い順に試し、予測反復時間がトークン間時間の上限を満たす最小周波数だけを採用する。出力長は実行前に分からないため、TPOTそのものではなく各反復のトークン間時間を保守的な代理指標にする。ただし低周波数化で要求の滞在が長くなるとKVキャッシュ使用量が増えるため、使用率が閾値を越えた場合は省エネルギー判断を上書きして最大周波数に戻し、メモリ不足を防ぐ。

### 全体のデータ／制御の流れ
フロントエンドのルータが要求をプリフィルインスタンスへ送り、入力処理完了後にKVキャッシュとともにデコードインスタンスへ引き渡す。制御面では、約5分ごとの配置制御器がインスタンス数・テンソル並列度・基準周波数・振り分け比率を更新し、別の細粒度制御器が各インスタンスの待ち行列とバッチ統計を監視して周波数を反復単位で変更する。両制御器は同じ事前学習済み遅延・電力モデルを共有し、上位層が容量と遅延の安全域を作り、下位層がその範囲内の短期的余裕を回収する構成である。
## 評価条件
- **ハードウェア**: 16基のNVIDIA H100 GPUを用いた実機クラスタでLlama 3.3 70Bを提供する。配置例ではプリフィルにテンソル並列度2、デコードにテンソル並列度4のインスタンスを複数配置し、GPU周波数は最大1.83 GHzを含む複数段階から選ぶ。NVMLで周波数を変更し、電力は約100 ms間隔で観測する。
- **ソフトウェア**: vLLMを反復単位の遅延計測ができるように計装し、事前学習した遅延モデルと電力モデル、要求列を再生するシミュレータ、整数線形計画による配置制御器、プリフィル用モデル予測制御器、デコード用周波数選択器を組み合わせる。
比較対象は、DistServe方式でサービス品質目標を満たす配置を作り全GPUを最大周波数で動かす構成と、DualScaleの第1層だけを使って固定周波数の省エネルギー配置を選ぶPlaceOnlyである。制御負荷では10 RPSから85 RPSまで15 RPS刻みで評価し、実運用風の時変負荷では負荷をクラスタ全容量の67%と85%に縮尺して30分間評価する。5分ごとに直前5分の負荷を次区間の予測として配置を更新する。起動後30秒と要求送信終了後の排出区間を除外し、定常区間だけで遅延とエネルギーを集計する。
主要な省エネルギー結果は実機H100クラスタで測定しており、シミュレーションだけの研究ではない。ただし第1層の配置候補評価そのものは事前学習モデルを使うシミュレータに依存する。また構成切替の完全な無停止実装は評価対象外で、各5分区間を定常状態として個別に評価しているため、実運用でのモデル再配置・インスタンス排出・起動コストを含む総合的な省エネルギー量は別途検証が必要である。
## 主要結果
DualScaleは、最大周波数で動くDistServeに対し、まず5分単位の配置最適化だけでも大きなエネルギー削減を得て、その上に反復単位の動的電圧周波数制御を重ねることで追加削減を得る。特にプリフィルでは負荷が短時間に大きく変動するため細粒度制御の寄与が大きく、実運用風トレースでは最大39%の削減に達する。デコードはもともとメモリ帯域律速で周波数を下げやすいため配置段階だけで大きく削減でき、動的制御の追加効果は比較的小さい。それでも最大48%の削減を達成し、DualScale自身は評価した条件でTTFTとTPOTの目標を維持した。

- プリフィルのエネルギー削減 / 最大39%削減 (比較対象: DistServe; 条件: 16基H100、Llama 3.3 70B、実運用風の時変負荷。67%負荷では28〜39%削減。) — 第1層の固定配置だけでも16〜29%削減し、短時間の到着集中と空き時間を第2層が利用して追加の周波数低下を行うため、プリフィルで動的制御の利益が大きい。

- デコードのエネルギー削減 / 最大48%削減 (比較対象: DistServe; 条件: 16基H100、Llama 3.3 70B、実運用風の時変負荷。67%負荷では44〜48%削減。) — デコードはメモリ帯域に支配されやすく、最大周波数が不要な領域が多いため、第1層で低い固定周波数を選ぶだけでも37〜45%削減できる。反復単位制御の追加利益は相対的に小さい。

- 第2層による追加削減 / 平均でプリフィル15%、デコード6% (比較対象: PlaceOnly; 条件: 制御負荷と実運用風負荷を含む評価全体の傾向。) — 省エネルギーの大部分は数分単位の配置と基準周波数選択から生じるが、予測誤差や秒以下の負荷変動が大きいプリフィルでは細粒度制御が有効で、追加削減の寄与はデコードのおよそ2.5倍と報告される。

- 予測モデル精度 / 遅延MAPE 2.9%/2.7%、電力MAPE 4.1%/1.0% (比較対象: 実機測定値; 条件: プリフィル/デコードの順。反復単位の遅延と10秒窓の電力を比較。) — 配置探索とオンライン周波数判断に使うモデル誤差は数%に収まり、5%の安全余裕と実測超過時の最大周波数復帰で制御に利用できる精度を確保している。

- 配置シミュレータのエネルギー予測精度 / プリフィル2.3%、デコード1.2%のMAPE (比較対象: 実機実行; 条件: 10、25、40 RPSの制御負荷で同一周波数構成を比較。) — 第1層が配置候補を実機で総当たりせずシミュレータで評価しても、エネルギー予測は実測に近い。TPOT上位尾部ではやや保守的であり、危険側より安全側へずれる。

### 負の結果・境界条件
- 細粒度の周波数制御は常に利益を増やすわけではない。デコードではPlaceOnlyに対する追加削減が平均6%程度に留まり、ある5分窓では見かけ上-4%となったが、その比較対象のPlaceOnlyはサービス品質目標を違反していた。また85%負荷の20〜25分区間ではPlaceOnlyがTPOT目標を1.5 ms超過した一方、DualScaleは目標内へ戻している。実際のGPU周波数変更には数十msの遅延があり、複数GPUで同期せず、昇圧周波数は熱・電力余裕にも依存するため、理想的な周波数軌跡を常に実現できるわけではない。

### 結果の読み方
結果は、分離型LLM提供の省エネルギー化では『常に細粒度制御を賢くする』より、まず各5分窓で適切なGPU台数・テンソル並列度・基準周波数を選ぶ方が寄与が大きいことを示す。そのうえで、上位配置が過剰なら下位制御は余裕を回収し、上位配置が負荷を過小予測した場合には周波数を上げてサービス品質違反を防ぐ。プリフィルは短期変動が大きいためこの補正機構の恩恵が大きく、デコードは周波数感度が低いので固定低周波数化だけでも多くの利益が得られる。
## 品質への影響
同一のLlama 3.3 70Bを同じ数値精度で実行し、モデルの重み、生成アルゴリズム、量子化精度を変えないため、モデル品質を犠牲にした削減ではない。トレードオフ対象は主に遅延余裕であり、DualScaleはTTFTとTPOTを上限近くまで延ばしてエネルギーを削減する。
## 既存研究との差
DistServeはプリフィルとデコードを分離してサービス品質目標を満たす配置を選ぶが、エネルギー最小化を目的とせずGPUを最大周波数で動かす。DynamoLLMは配置・並列度・周波数を使った省エネルギー化を扱うが、プリフィルとデコードを分離した二段階の非対称性を対象としない。throttLL’eMは予測に基づくGPU周波数低下を行うが、配置や並列度を固定したまま細粒度制御する。DualScaleは、分離型推論で両段階の配置を同時に決める上位層と、プリフィル・デコードそれぞれの動特性に合わせた下位層を結び、配置予測の誤差も下位の周波数制御で補う点が異なる。
## 限界
第1層の負荷予測は直前5分を次の5分へそのまま外挿する単純方式で、急激な需要変化や入力長・出力長分布の変化を十分に予測できない。第2層はこの誤差をある程度補正するが、容量自体が不足するほど大きな予測外れは周波数変更だけでは救えない。さらに論文の評価では5分ごとの構成切替を無停止で実行する完全な再配置機構を実装せず、各区間を定常状態として個別評価している。そのためモデル重み読込み、進行中要求の排出、新インスタンス起動などの遷移コストを含む実運用全体の省エネルギー量は未確定である。周波数変更にも数十msの遅延とGPU間非同期性があり、予測モデルは特定のモデルとGPUの組合せごとに事前計測が必要である。
## 実装状態
vLLM上の実機試作として16基H100クラスタで評価されており、単なる解析モデルや概念提案ではない。配置探索には整数線形計画と事前学習済み遅延・電力モデルを使い、プリフィルのモデル予測制御は平均約4 msで周波数系列を探索する。論文本文から公開コードの明示的な配布先は確認できず、完全な構成遷移機構は今後の実装課題として残る。
## 研究上の位置づけ
本研究はLLM提供システムの『性能を最大化する配置』から『サービス品質目標を満たす範囲でエネルギーを最小化する配置と実行時制御』へ目的関数を広げる系統に位置する。特にプリフィル・デコード分離では両段階のボトルネックが異なるため、同じ周波数制御を全GPUへ適用するより、時間尺度と段階を分けて制御する方が合理的であることを実機で示した。研究上は、より高精度な負荷予測、再配置遷移コストを含む最適化、異種GPUや電力上限制約との共同最適化、KVキャッシュ転送やネットワーク消費電力まで含めた総合エネルギー制御へ拡張できる。
