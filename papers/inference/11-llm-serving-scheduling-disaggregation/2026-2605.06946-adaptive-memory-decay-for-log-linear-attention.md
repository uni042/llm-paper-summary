# Adaptive Memory Decay for Log-Linear Attention

## 概要

通常の自己注意では各トークンが過去の鍵・値を参照するため、系列長を伸ばすと注意の計算が二次的に増える。線形注意や状態空間モデルは過去を固定長の状態へ圧縮することで生成時の記憶量を一定にできるが、長い文脈の細かな情報を再び取り出すのが難しい。対数線形注意（log-linear attention）は、この二者の中間として、過去をFenwick木の階層的な状態へ分けて保持する。系列長Tに対して状態はO(log T)個、学習計算はO(T log T)であり、最近の情報を細かく、遠い情報を粗く残す。

本論文はこの記憶構造そのものを変更せず、各階層の状態をどれだけ使うかを決める重み`λ`だけを入力依存にする。基準方式のほぼ固定的な線形投影に代わり、二層の多層パーセプトロン（MLP）とsoftplus活性化を使う。これにより、直近の記憶と遠方の記憶を互いに排他的に選ぶのではなく、必要な階層を独立に強められる。追加パラメータは全モデルの0.007%未満と報告する。

実験は多問い合わせ連想想起、選択コピー、WikiText-103の小規模言語モデルで行う。系列長1024の選択コピーでは、基準の正解率40.6±19.8%に対しsoftplus版54.8±2.3%で、平均と試行間安定性が改善する。WikiText-103では隠れ幅512の検証困惑度が224.71から218.57へ改善した。ただしこれは学習したモデルの品質評価であり、実GPUの生成速度や商用サービングの高速化を測定した論文ではない。

## 問題設定

全注意の計算は系列長Tに対してO(T²)で、FlashAttentionのような実装はGPUメモリ転送を減らして実時間を短縮するが、計算の漸近的な二次依存は残る。線形注意では過去の鍵・値を少数の状態へ畳み込めるため、生成時に全過去トークンをKVキャッシュとして保持する必要がない。しかし一つの状態へ多数の情報を混ぜるため、遠方の特定キーに対応する値を正確に取り出す連想記憶では容量不足が起こる。

対数線形注意はFenwick木のように二の累乗幅の区間をまとめる。最近の短い区間は細かい状態として残り、古い区間は大きなブロックの要約として残る。トークン位置tで利用できる階層状態`M_t^(ℓ)`を、階層ごとの重み`λ_t^(ℓ)`で加算して出力を作る。階層数が対数的なので、通常の全注意より小さな復号状態で、単一状態より多くの時間尺度を扱える。

しかし、どの階層が重要かは現在の入力トークンの意味によって変わる。短い直近の関係を答える場合と、長い系列の冒頭で定義されたキーを想起する場合では、必要な時間尺度が違う。基準方式の`λ`は単純な線形投影から作られ、実際の可視化では入力や階層が変わっても0.688〜0.698付近のほぼ一様な値を取る。これは異なる記憶階層を活用する柔軟性が不足している可能性を示す。

## 手法

### 1. Fenwick木による階層記憶を維持

各トークンの過去を、長さが二の累乗に対応する複数の記憶階層へ分割する。階層`ℓ`の状態`M_t^(ℓ)`は、その時間幅の過去をまとめた表現である。出力は`o_t = Σ_ℓ λ_t^(ℓ) M_t^(ℓ)`で計算する。全過去を一つの再帰状態に押し込めず、時間尺度の異なる複数の状態を同時に参照することが目的である。

提案方式はこの階層の生成、状態更新、系列の分割規則を変更しない。したがって記憶容量を増やすための追加キャッシュや新たな木探索を導入するのではなく、既存の階層状態をどの程度出力へ反映するかを変える。推論時の状態数は引き続きO(log T)である。固定長の線形注意とは異なり、系列長が増えると階層状態は対数的に増えるため、O(1)の復号記憶だと説明してはならない。

### 2. 二層MLPによる入力依存の階層重み

基準の投影から得られる中間表現`d_t`を保持し、その後に二層MLPを追加する。各注意ヘッドと各記憶階層に対し、`h_t = d_t W1`、`λ_t = softplus(h_t W2 + b)`を計算する。`W1`は階層数Lから中間幅`d_h`へ、`W2`は中間幅からLへ写像する。出力はバッチ、トークン、ヘッド、階層に対応する重みであり、同じ層にいる二つのトークンでも異なる記憶尺度を選べる。

学習開始時の安定性を確保するため、`W1`はXavier一様初期化、`W2`はゼロ、バイアスは0.54とする。softplus(0.54)はおよそ1なので、学習初期にはすべての階層を極端に抑制せず、基準に近い状態から更新を始められる。突然強いゲートを導入して記憶を消すよりも、学習が不安定になりにくい初期条件を与える。

### 3. softplusとsoftmaxの差

階層重みをsoftmaxで正規化すると、すべての階層の重みの和が1に固定される。遠方の記憶を強めれば、同じ問い合わせに必要な直近の記憶の相対重みは必ず弱まる。著者はこれを階層間の不要な競合とみなす。一方softplusは各階層へ独立した正の重みを出し、複数の時間尺度を同時に強められる。これは「softplusなら必ず長距離情報を正しく覚える」という保証ではなく、学習で選べる重みの自由度が異なるという設計上の違いである。

実験では基準の線形投影、MLP＋softmax、MLP＋softplusを同じ課題で比較する。これによりMLPの非線形性による利得と、階層間を競合させない活性化の効果を分離しようとしている。特に難しい連想想起では、softmax版は中程度のキー数では高得点でも、キー数が増えると不安定になる条件がある。

### 4. 計算量と追加費用

MLPが扱うのは全過去トークンではなく、階層数`L=O(log T)`の軸である。原著は追加計算を`O(T H L d_h)`と整理し、実験で用いる小さな中間幅の下では元のO(T log T)の計算特性を維持するとする。中間幅が系列長とともに増える設定を任意に選べば、追加計算の定数や厳密な次数の解釈は変わるため、原著の複雑度主張は実装設定とともに読む必要がある。

追加パラメータは全体の0.007%未満と報告される。これはモデルの重み数についての比率であり、GPUカーネルの実測時間、電力、メモリ帯域の増分が0.007%という意味ではない。Fenwick木の状態管理自体の費用は基準方式と共通であるため、提案方式の性能差は主に重みの表現力と学習挙動から生じると解釈できる。

## 評価

### 1. 実験設計

| 項目 | 設定 |
|---|---|
| 比較 | 基準の線形λ、MLP＋softmax、MLP＋softplus |
| 連想想起 | 系列長128、キー値対4/8/16/32、隠れ幅64、5,000学習ステップ、5乱数種 |
| 選択コピー | 系列長256/512/1024、指定された16トークンを雑音列から復元、30,000ステップ |
| 言語モデル | WikiText-103、GPT-2トークナイザ、語彙50,257、6層、4注意ヘッド |
| 言語モデル規模 | 隠れ幅512または256、系列長512、40,000ステップ |
| 最適化 | 合成課題はAdam・学習率1e-3・バッチ64。言語モデルはAdamW・学習率3e-4・バッチ8 |
| 指標 | 正解率、乱数種間の平均・標準偏差、検証困惑度（低いほど良い） |
| 未測定 | GPU推論スループット、トークン遅延、複数利用者のサービング、実際のKVキャッシュ容量比較 |

### 2. 多問い合わせ連想想起（MQAR）

MQARは先に提示されたキーと値の対応を、後の問い合わせで正しく返す課題である。系列長128でキー値対を4、8、16、32と増やし、記憶の混雑が起きる条件を作る。原著Table 2の5乱数種平均では、キー値対32で基準2.9%、MLP＋softmax 35.2%、MLP＋softplus 57.9%となる。一方、最良の乱数種だけを見ると三方式とも99%前後へ達するため、平均値の差は学習の成功・失敗のばらつきに大きく影響される。

| キー値対 | 基準平均 | softmax平均 | softplus平均 |
|---|---:|---:|---:|
| 4 | 35.1 | 2.7 | 67.0 |
| 8 | 35.8 | 66.8 | 66.7 |
| 16 | 34.8 | 67.0 | 66.7 |
| 32 | 2.9 | 35.2 | 57.9 |

**数値整合性の注意：** 原著本文はキー値対32について別の実行条件で基準60.9±46.7%、softplus99.6±0.1%とも述べ、脚注でTable 2とは異なる乱数種の実験と説明する。したがって表の2.9%と本文の60.9%を同一実験の矛盾として統合せず、表と別実行を分けて記録する。系列長128で学習して256へ外挿した別実験では基準3.3%、softplus33.2%で、長距離想起の改善を示すが絶対正解率はなお低い。

### 3. 選択コピー

選択コピーは、雑音を含む系列から指定された16個のトークンを再現する。短い系列では方式間の差が小さく、系列長256では基準52.6±3.5%、softplus53.1±2.2%、softmax54.3±5.8%である。系列長512では基準54.6±3.4%、softplus51.9±0.8%、softmax50.3±0.8%で、**softplusが基準より低い**。したがって全長で一貫して最高とは言えない。

最も長い1024では基準40.6±19.8%に対しsoftplus54.8±2.3%、softmax52.6±2.5%である。平均14.2百分点の改善と、試行間のばらつきの減少が確認される。ここでの「安定性」は異なる乱数種で学習したときの正解率のばらつきであり、生成時の応答遅延の安定性を意味しない。長い系列で固定的な階層重みがうまく学習できない場合に、入力依存の重みが役立つという説明に対応する。

### 4. WikiText-103言語モデル

| 隠れ幅 | 基準PPL | softmax PPL | softplus PPL | 試行数 |
|---|---:|---:|---:|---|
| 512 | 224.71 | 226.06 | 218.57 | 各1種 |
| 256 | 257.02±0.29 | 257.31±0.25 | 256.82±0.20 | 各3種 |

困惑度（perplexity; PPL）は、検証データの次トークン予測にどれほど不確実性が残るかを示し、低いほど良い。隠れ幅512ではsoftplusが基準より6.14ポイント低く、隠れ幅256では差が0.20と小さい。512幅の結果は単一乱数種なので、ばらつきや統計的有意性をこの表から確定できない。実験は6層の比較的小さなモデルであり、数十億パラメータ級のLLMの品質改善率として転用できない。

### 5. λの可視化と負の結果

基準のλは入力位置や階層に対してほぼ一様な値を示す。MLP＋softplusではキー値対を提示するトークンや問い合わせトークンで特定の細かな階層が強くなるパターンが観察される。これは入力の内容に応じて記憶階層の重みが変わるという機構の直接的な証拠である。ただし可視化は主に合成連想課題における観測であり、自然言語の意味的な長距離依存を常に正しく選べることの証明ではない。

負の結果として、softmax版はキー値対4の平均で2.7%と基準35.1%を大きく下回り、選択コピー長512ではsoftplus版も基準より悪い。自然言語モデルでの改善幅も小さい条件がある。実験では学習時の収束と正解率を調べるが、同じハードウェア上での推論実測時間やメモリ転送量は報告していないため、理論計算量を根拠に高速化倍率を主張しない。

## 既存研究との差

FlashAttentionは全注意を正確に保ったままメモリ転送とGPU演算を最適化する。一方、線形注意や状態空間モデルは過去を小さな再帰状態へ要約して計算量を変える。対数線形注意はFenwick木の複数時間尺度を持つことで、その中間の記憶容量と計算量を選ぶ。今回の研究はこの構造を提案したGuoらの対数線形注意を基準にし、木の形や計算順序ではなく、階層ごとの記憶寄与`λ`のパラメータ化だけを変更する。

また、RoPEのような位置依存の重み付けではなく、現在トークンの中間表現から階層重みを作る点に意味がある。softmaxとsoftplusを直接比較し、階層間の重みを総和1へ制約することが必ずしも望ましくないと示す。これは既存の注意カーネルの速度改善ではなく、効率的な記憶構造の表現力を改善する研究である。

## 限界と実装状況

評価の中心は合成想起・コピーと、小規模なWikiText-103言語モデルである。巨大LLMの長文脈生成、実機GPUでのトークン遅延、KVキャッシュの実バイト数、カーネル効率、サービング負荷、複数GPUへの分散などは直接評価されていない。理論上O(log T)の復号状態であることと、実装が高速に動くことは別である。

連想想起の一部数値は主表と別乱数種実行の本文で異なる。これは脚注で区別されているため、都合の良い最大値だけを一般的な平均性能として使うべきではない。選択コピーの中間系列長では基準が勝つこともあり、常にsoftplusが最良ではない。追加パラメータが少ないという主張も、追加計算やカーネル起動費用が実測で無視できることを示すものではない。

実装の公式コードURLは原著から特定できなかった。既存のFenwick木注意の実装へMLPを追加する設計だが、主流推論エンジンへ統合されたという根拠はない。現段階では、記憶階層の入力適応というアルゴリズム上の知見として収録するのが適切である。
