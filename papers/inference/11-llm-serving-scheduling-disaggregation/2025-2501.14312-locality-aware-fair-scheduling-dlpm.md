# Locality-aware Fair Scheduling in LLM Serving

## 一文要約

VTCのようなclient-level fairnessとSGLangのLongest Prefix Matchのようなprefix localityを二者択一にせず、**一定量の公平性credit（deficit）の範囲内でprefixが近いrequestをまとめて実行するDLPM**と、その考えを複数GPUへ拡張してload balanceも扱うD²LPMにより、fairness guaranteeを保ちながらKV prefix reuseによるthroughput / latency改善を狙うserving scheduler。

## 問題設定

LLM servingでは、複数clientが同じGPUを共有するときに一部clientがresourceを独占しないようfairnessを保証したい。一方、同一・類似prefixを持つrequestを近い順序で処理すると、prefix KV cacheを共有してprefill計算とKV memoryを節約できる。

既存のVTCはclientごとの累積service量を追跡して公平に処理するが、prefix localityを見ないため、同じprefixを持つrequestをばらしてcache reuseを失いやすい。逆にSGLangのLongest Prefix Match (LPM)のようなlocality-oriented schedulingはprefix hitを増やせるが、同じprefixを大量投入するclientがschedulerを占有し、他clientをstarvationさせる可能性がある。

分散servingではさらに、同じprefixを同じGPUへ寄せるほどlocalityは高まる一方、worker間のload imbalanceが悪化するため、**fairness・prefix locality・load balancingの3目的**を同時に扱う必要がある。

## 手法

### DLPM: Deficit Longest Prefix Match

DLPMはfair schedulerの厳密なdispatch順序を緩め、各clientに許容されるservice deficitの範囲内でLongest Prefix Matchを利用する。

直感的には、client間のservice量を完全に同一順序で交互処理するのではなく、一定のquantumだけ公平性のずれを許容する。その許容範囲ではprefix localityが高いrequestをまとめて選べるため、共有prefixのKVを再利用しやすくなる。quantumを小さくするとVTC寄りの強いfairness、大きくするとLPM寄りの高localityとなり、fairness / throughputのtrade-offを明示的に調整できる。

論文はDLPMについてapproximate max-min fairnessを対象としたservice boundとlatency boundを導出し、localityを優先してもclient isolationが無制限に崩れないことを理論的に保証する。

### D²LPM: Double Deficit LPM

複数workerでは、local schedulerだけでなくglobal dispatcherにもdeficitの考えを導入する。これにより、

1. client間のglobal fairness、
2. 各GPU内でのprefix locality、
3. GPU間のload balancing

を同時に調整する。

単純に同一prefixを1 GPUへ固定するとcache hitは高いがhotspotになる一方、round-robin的に均等分配すると同じprefixを複数GPUで再計算する。D²LPMはこの中間点をdeficit-based dispatchで選ぶ。

## 評価と主要結果

論文はsingle-workerとdistributed servingの双方でVTC、LPMおよび既存のlocality-aware distributed schedulingと比較している。

主要な報告値は以下。

- DLPM / D²LPMはfairness guaranteeを維持しながら、VTC比で**最大2.87× throughput**を達成。
- locality-awareな既存distributed serving手法との比較では、client単位latencyを**最大7.18×削減**。
- quantumを変えることで、VTCに近いfairnessからLPMに近いthroughputまで連続的なPareto trade-offを作れる。

したがって主な成果は単なる平均throughput向上ではなく、**prefix reuseを使うためにrequest順序を変えても、client-level fairnessを理論bound付きで維持できる**点にある。

## 既存研究との差

### Fairness in Serving Large Language Models / VTC

VTCは入力・出力tokenに基づく累積serviceをclientごとにaccountingし、work-conservingなfair schedulingを実現する。ただしrequest間のprefix関係を考慮しない。

DLPMはVTCが提示したLLM serving fairnessの問題設定を直接引き継ぎつつ、dispatch順序をboundedに緩めてprefix localityを取り込むfollow-upと位置づけられる。

### SGLang / LPM

SGLangのRadixAttentionとLPMはprefix KV reuseを大きくするが、client isolationを目的としていない。DLPMはLPMをfairness constraintの内側で使うことで、locality-only schedulerによるstarvationを防ぐ。

### Preble

distributed prefix-aware servingでは、同じprefixを持つrequestを同じworkerへ寄せることがcache localityには有利だがload balanceと衝突する。本論文のD²LPMはさらにclient fairnessを目的関数へ入れ、3者のtrade-offを扱う。

## 実装上の含意

prefix cachingを持つserving engineでは、cache eviction policyだけでなく**request admission / orderingそのものをfairness accountingと共同設計する価値がある**。特にagent、Tree-of-Thought、MCTS、multi-turn conversationなど同一client内で長いprefixが繰り返されるworkloadでは、厳密なfair queueingはprefix reuseを壊しやすい。

逆にlocalityだけを最大化すると、長い共通prefixを大量に持つclientが有利になる。そのためmulti-tenant servingでは、prefix hit率を単独metricとして最大化するより、client service deficitを制約としてlocalityを最適化する方が安全である。

## 限界

- fairnessとlocalityのtrade-offはquantum設定に依存し、workloadに対して適切な値を選ぶ必要がある。
- prefix sharingが少ないworkloadではlocality-aware schedulingの利益自体が小さい。
- fairnessは主としてresource service量に対する保証であり、application-level job completion timeやagent workflow全体のcritical pathを直接最適化するものではない。
- arXiv v1時点の研究であり、確認時点では会議最終版への更新は確認できていない。
