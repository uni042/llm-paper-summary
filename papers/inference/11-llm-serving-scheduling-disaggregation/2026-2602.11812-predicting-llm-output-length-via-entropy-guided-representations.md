## 概要

大規模言語モデル（LLM）のオンライン推論や強化学習サンプリングでは、同じバッチに入った要求でも生成されるトークン数が大きく異なる。固定形状のバッチ処理では最長系列へ合わせたパディングが必要になり、短い要求に対して不要な計算を実行する。生成長を事前に予測して近い長さの要求をまとめればこの無駄を減らせるが、既存法はDistilBERTのような補助モデルを別途動かすため、追加遅延とGPUメモリを消費する。また同じプロンプトから異なる長さの回答が生じる確率的生成では、開始前の静的予測だけでは実際の生成軌道を追えない。

本論文は、主LLMがすでに計算している隠れ状態に生成長の情報が含まれることを利用する。エントロピー誘導トークンプーリング（Entropy-Guided Token Pooling; EGTP）はプリフィル中の隠れ状態をトークンごとの予測不確実性で重み付けし、軽量な予測ヘッドへ渡す。漸進的長さ予測（Progressive Length Prediction; PLP）は生成が進むたびに実際の生成トークンの状態を加えて残り長を再推定する。長系列・思考連鎖（Chain-of-Thought; CoT）・強化学習（reinforcement learning; RL）を含むForeLenでは、EGTPは最良既存法より平均絶対誤差（Mean Absolute Error; MAE）を29.16%削減する。

## 問題設定

長さ認識スケジューリングでは、要求ごとの出力長予測が誤ると短い要求と長い要求が同じバッチへ混在し、いわゆる「樽効果」により短い系列が長い系列の終了を待つ。最短ジョブ優先（Shortest Job First; SJF）のような方針は、真の生成長を知っていれば効率的だが、実運用では生成前に長さが未知である。したがって予測器の誤差だけでなく、予測器自身の遅延・GPUメモリ占有もサービング効率へ直接効く。

さらに思考連鎖やRLサンプリングでは、同じ入力でもサンプリング結果に応じて推論ステップ数が変わる。一つのプロンプトから一つの固定長だけを予測する方式は、この一対多の分布を表現できない。論文は「開始前に安価で予測する」問題と「生成軌道が見えた後に予測を修正する」問題を分け、EGTPとPLPを対応させる。

## 手法

### エントロピー誘導トークンプーリング

プリフィルで得られる各入力トークンの隠れ状態を \(h_i\)、その位置での次トークン分布のエントロピーを \(H_i\) とする。論文は、長さ予測損失に対する各隠れ状態の重要度とエントロピーの間に正の相関を観測し、Pearson相関係数0.451を報告する。つまり、モデルが次の語を決めにくい位置ほど、その後の応答の複雑さ・長さを示す情報を持つ傾向がある。

EGTPは \(H_i\) を温度係数付きsoftmaxへ通して重み \(w_i\) を作り、入力全体を \(h=Σ_i w_i h_i\) へ集約する。単純平均や末尾トークンだけを使う方式と違い、全トークンを同じ重要度で扱わない。主モデルの既存活性値を再利用するため、大きな補助Transformerを別途実行する必要がなく、予測器の追加資源を小さくできる。

### ソフトラベル分布による長さ回帰

生成長は長尾分布を持つため、通常の平均二乗誤差だけでは極端に長い系列の影響を受けやすい。一方、長さを離散ビンへ単純分類すると、隣接ビンと遠いビンの距離情報が失われる。そこで真の長さを複数の長さビン上のソフトな確率分布へ変換し、近いビンほど大きい教師確率を与える。

学習損失は確率分布を合わせる交差エントロピーと、実長との差を測る平均二乗誤差を組み合わせる。これにより「おおよそどの長さ領域か」と「具体的に何トークン程度か」を同時に学習する。構成要素除去実験では、このソフトラベルと複合損失が単純回帰より安定した予測に寄与する。

### 漸進的長さ予測

PLPは静的な入力表現だけで予測を固定せず、復号ステップ \(t\) ごとに残り生成長を再予測する。初期プロンプト表現と、それまでに実際に生成されたトークンの隠れ状態を動的表現へ取り込み、残りトークン数を出力する。生成が複雑な導出へ入った、あるいは早く終端へ向かったといった情報を予測へ反映できる。

学習時には生成系列の各時点について真の残り長を教師とし、全ステップの予測損失を平均する。したがってPLPの目的は最初の長さ予測を単に置換することではなく、確率的生成で静的予測が外れた要求を途中から再分類・再バッチ可能にすることである。

### 長さ認識スケジューラへの接続

予測値を得るだけではシステム性能は改善しない。論文は予測長に基づいて近い要求をまとめる長さ認識スケジューラへEGTPを接続し、バッチ内の長さばらつきを減らす。予測が正確になるほど最長系列に合わせて発生するパディングが減り、同じGPU時間で有効トークンをより多く処理できる。

この接続により、予測精度のMAEだけでなく、パディング率、平均ジョブ完了時間、スループットをエンドツーエンドで評価できる。EGTPの利点は予測精度と予測器の低オーバーヘッドの双方がスケジューラへ効く点にある。

## 評価条件

| 観点 | 条件 |
|---|---|
| ベンチマーク | ForeLen |
| ワークロード | 長系列、CoT推論、RLサンプリング |
| モデル例 | Qwen2.5系、Llama 3.2系 |
| 予測指標 | MAEを中心に評価 |
| システム指標 | スループット、平均ジョブ完了時間、パディング率 |
| 統合先 | 長さ認識型のLLMサービング・スケジューリング |
| 比較対象 | 補助モデル型予測、既存の静的長さ予測、長さ予測なし/弱い予測を使うスケジューリング |

ForeLenは通常の短い対話だけでなく、長い出力、推論ステップ数が変動するCoT、一つの入力から複数completionを生成するRLデータを含める。これにより、静的予測器が得意な一対一の短文応答だけで性能を測らない。

## 主要結果

| 条件・指標 | 結果 | 読み取れること |
|---|---:|---|
| ForeLen全体のMAE | 最良既存法より29.16%削減 | 主モデル内部表現の再利用でも専用補助モデルを上回れる |
| 既存SSJF-RegとのMAE | 55.09%削減 | proxy model型の長さ予測に対する大幅改善 |
| トークンエントロピーと長さ予測重要度 | Pearson r = 0.451 | EGTPの重み付けに経験的根拠がある |
| 長系列ワークロードのパディング | 強い既存法に対し約3分の1 | 長さ予測改善が実際の無駄計算削減へ接続 |
| 予測器追加遅延 | 約0.66〜0.67 ms | 大型補助モデルを別途走らせる方式よりcritical pathを増やしにくい |
| 追加GPUメモリ | 約5〜10 MB級 | サービング用GPU容量への影響が小さい |

PLPは生成が進むにつれて残り長のMAEを改善し、特に一対多性の強いRL条件で効果が大きい。これは開始前のpromptだけでは確定しない生成軌道を、実際の復号状態から逐次修正する設計と整合する。

一方、システム利得は予測器だけの固定倍率ではない。要求長分布、バッチ方式、同時要求数、スケジューラが予測値をどう利用するかでパディング削減量とスループット改善量は変わる。29.16%は長さ予測MAEの改善であり、そのまま推論スループット29.16%増を意味しない。

## 既存研究との差

従来のproxy model型手法は、入力promptをDistilBERT等の別モデルへ渡して出力長を予測する。これは主LLMとは別のforward passとVRAMを必要とし、分布外の長い推論やモデル変更への追従にも追加学習を要する。EGTPは主LLMのプリフィルで既に得た隠れ状態と確率分布を利用するため、予測用特徴抽出を主推論から分離しない。

また既存の静的予測は一つのpromptに一つの長さを割り当てるが、PLPは生成中の状態を観測して残り長を更新する。この違いにより、同じpromptから複数の長さが生じる確率的サンプリングを明示的に対象にする。

## 限界

EGTPは主モデルの内部隠れ状態へアクセスできることを前提とするため、隠れ状態を公開しない外部APIだけを使う環境ではそのまま適用できない。評価では最終層表現を主に利用しており、別アーキテクチャで長さ情報がどの層に最も強く現れるかは追加検証が必要である。

PLPは復号途中で予測を更新できる一方、その更新を実際の再バッチ・移送へ使うにはランタイム側のスケジューラ対応が必要になる。再配置コストが大きいシステムでは予測精度向上がそのまま利得にならない可能性がある。また100B超級モデルや視覚言語モデルまで同じ予測特性が一般化するかは本評価範囲からは確定できない。
