# Accelerating Diffusion LLM Inference via Local Determinism Propagation — LocalLeap

## 概要

本論文は、拡散型大規模言語モデル（diffusion large language model; dLLM）の生成を遅くする原因を、モデルの計算構造そのものではなく**既に予測が安定した位置を確定させない復号規則**に見いだす。マスクを順に外す標準的な復号では、各反復で最も確信度の高い一位置だけを確定する保守的方式が品質維持のために用いられる。ところが著者らの観測では、最終的に得られる文字列と一致し、その後も変わらないトークンが初期反復の段階から多数存在する。これを確定遅延（delayed decoding）と呼ぶ。

提案するLocalLeapは、確信度の高いトークンをアンカー（anchor）とし、その左右の限られた近傍にある中程度の確信度の位置も同時に確定する。モデルの再学習や重み変更は行わず、生成ステップごとに既に計算したトークン確率を使って確定位置集合だけを変更する。LLaDA-8B-InstructのGSM8K・生成長512では、逐次確定の7.76トークン/秒を53.82トークン/秒へ、反復512回を73回へ削減し、正答率は78.24%から78.54%であった。ただしこれは対象モデル・問題・復号長に依存する結果であり、Dream-7B-InstructのGSM8Kでは速度向上と同時に正答率が1.52ポイント低下している。論文はモデル間で確信度の意味が異なることも確認している。

## 問題設定と背景

自己回帰型言語モデルは確定済みの接頭辞に続く次の一トークンを生成するため、出力トークン数に沿った逐次依存がある。対照的に、拡散言語モデルでは長さを決めた出力領域を最初はすべて特殊記号`[MASK]`で埋め、マスク位置の予測を複数回更新する。双方向注意を使うモデルなら同じ反復で多くのマスク位置の確率分布を得られる。しかし、確信度が十分高い位置を一つずつ確定する運用では、並列に得た候補のほとんどを次回へ持ち越す。モデルの順伝播自体が並列でも、**何回順伝播するか**が生成時間を支配する。

低確信度再マスク（low-confidence remasking）は、各反復の候補のうち確信度の高い位置だけを確定し、残りをマスクのまま維持する方式である。半自己回帰型再マスク（semi-autoregressive remasking）は、早すぎる終了記号`[EOS]`の生成を抑えるため、出力を一定長のブロックに分け、ブロック内では双方向に更新しながらブロック間は左から右へ進める。論文の主要実験はブロック長32を採用し、比較対象間でこの条件を揃えている。

確信度閾値を下げて多数位置を同時確定する単純な対策には、誤った位置を確定すると後の反復で修正できないという欠点がある。確信度に応じた全域並列復号（Fast-dLLM型）では高い閾値を採用すると安全性は高いが、確定可能な位置が残っていても閾値を越えず待たされる。本論文の問いは、全域で閾値を緩めず、**どの位置の近傍なら閾値を緩められるか**を決めることである。

### 確定遅延を測るための観測

著者らはLLaDA-8B-InstructについてGSM8K、HumanEval、IFEvalから各40例、合計120例を採取した。各反復のマスク位置に対して、現在の最頻予測が最終生成文字列と同じである「一致性（consistency）」と、その後の反復でも予測が変わらない「安定性（stability）」を別々に追跡する。これらは**正解ラベルとの一致ではなく、同じ復号試行の最終結果との一致**である。従って、観測した安定性だけで回答の意味的正確さが保証されるわけではない。

観測の結果、ブロック内の最初の反復で45.2%の位置が最終的に一致・安定し、全反復の最初の25%までには63.7%が一致・安定していた。確信度0.8超の予測は97.8%が最終結果と一致する一方、全域で閾値を下げると誤確定が増える。著者らは、ある位置に確信度0.9以上の予測が現れると、その左右の比較的近い位置でも、確信度が0.75程度であっても最終結果との一致が高い傾向を見いだした。逆に中心位置の確信度が低い場合、近傍の中程度の確信度だけでは同様の安定性を期待できない。

この観測を、局所的決定性伝播（local determinism propagation）と距離に伴う一致性減衰（spatial consistency decay）の二原則として整理する。前者は高確信度位置の周囲に安全に早期確定できる位置が集まること、後者はアンカーから離れるほどその根拠が弱まることを表す。双方向注意だからといって無制限の距離で同じ閾値を適用してよいわけではない。著者らは中心位置の左右最大16位置を観測し、後述の近傍半径を選んでいる。

## 手法：LocalLeapの入力、処理、更新

### 1. マスク位置ごとの予測と確信度

現在の出力状態を`x`、生成対象の現行ブロックを`B_s`、そのうちまだ`[MASK]`の位置集合を`M_s`とする。モデルの一回の順伝播から、各位置`i ∈ M_s`の語彙上の確率分布を得る。最頻トークンを`argmax_v pθ(v | x)`、その確率を`c_s^i = max_v pθ(v | x)`とする。これは従来の確信度に基づく再マスクでも必要な情報であり、LocalLeap専用の別の推論モデルや学習済み判定器を追加しない。

この確信度はモデル自身の確率であって、現実世界での正解確率を直接測った値ではない。たとえば、確信度0.9を超える予測が複数ある場合、それらの位置が相互に独立であることも意味しない。LocalLeapは個別確率の高さと、同一系列で観測された局所的な一致傾向を組み合わせ、確定してよい候補集合を制限する。

### 2. 高確信度アンカーの抽出

アンカー閾値を`κ`とすると、`A_s = {i ∈ M_s | c_s^i ≥ κ}`を抽出する。基本設定は`κ = 0.9`である。アンカーが一つでも見つかった反復だけ、局所的な閾値緩和を発動する。高確信度の中心がない場合は、近傍を推測で広げず、従来と同様に最も確信度が高いマスク位置を一つ確定する。これが、難しいブロックで無条件に低閾値並列復号へ進まないための後退経路となる。

アンカーはトークンの最終的な正しさを保証する証明ではない。あくまで近傍の確定を早めるための条件付きの観測信号である。高確信度の中心が誤っていた場合には、その誤りが近傍の同時確定にも波及し得る。この失敗可能性が、`κ`を小さくしすぎない設計に直結する。

### 3. 距離制限付き近傍の形成

各アンカー`i`から左右`W`位置以内にある未確定位置`j`を集め、近傍集合`N_s(A_s)`を作る。条件は`|j-i| ≤ W`であり、アンカー自身は除く。複数アンカーの近傍が重なる場合は和集合を取るので、同じ位置を重複して確定しない。既に確定済みの位置や現在のブロック外の位置は候補に入れない。

基本設定の`W = 4`は、最大でアンカーの前後4位置までに低い閾値を適用することを意味する。`W`は注意機構が実際に参照できる範囲ではなく、**復号規則が早期確定を許す範囲**である。したがって、これを設定してもTransformerの注意行列やKVキャッシュが同じ幅に切り詰められるわけではない。削減対象は、残りのマスクを確定するために必要な反復回数である。

### 4. 近傍だけの緩和閾値と確定集合

アンカー自体は高い`κ`を満たす。近傍の位置はそれより低い閾値`τ`を満たすときに確定対象へ加える。式で書くと`D_s = A_s ∪ {j ∈ N_s(A_s) | c_s^j ≥ τ}`であり、基本設定は`τ = 0.75 < κ`である。`D_s`の各位置へ、その反復で既に求めた最頻トークンを確定書き込みする。その他のマスク位置は残し、次のモデル順伝播で更新する。

ここで重要なのは、`τ`を出力全体へ適用するのではなく、アンカーの周辺だけに適用する点である。遠方の確信度0.75の位置は早期確定しない一方、同じ確信度でも高確信度アンカーから2位置しか離れていなければ確定候補になる。これにより、単純な全域閾値緩和が招く誤確定を抑えながら、確定遅延を減らす。

### 5. ブロックの反復終了と後続ブロック

一回の順伝播で複数位置が確定すると、次回のマスク数が複数減る。現行ブロックのマスクがすべて埋まるまでこの操作を繰り返し、完了したら次のブロックへ進む。論文の実験では、長さ32のブロックを左から右へ処理する半自己回帰型構成を採用する。複数位置を同時に確定しても、ブロック間の順序を勝手に変更しないため、早すぎる終了記号の問題に対する既存の実務的対策を維持できる。

一連の処理を一文で追うと、モデル順伝播→全マスク位置の最頻候補・確信度計算→アンカー抽出→半径`W`の未確定近傍の形成→近傍に限る`τ`判定→選択位置を一斉確定→残余マスクで再推論、となる。計算を節約する主因は確定判定の比較演算が速いことではなく、**後続の大きなモデル順伝播を呼ぶ回数そのものが減ること**にある。

### 6. 理論的検討の適用範囲

付録Bでは、同時に確定する位置を一つのアンカーとその近傍からなる互いに素なクラスタとして扱い、各位置の候補確率から誤差予算を構成する。個別位置の最頻候補を掛け合わせた独立近似分布と、実際の同時分布の最頻配置が一致するための**十分条件**を議論し、近傍数を増やすと条件が厳しくなることを示す。また、独立近似と同時分布の距離について上界を導く。

ただし、実装の`κ = 0.9`、`τ = 0.75`、`W = 4`という固定値が、あらゆる入力で厳密な同一出力を保証するわけではない。理論節の条件付き主張と、ベンチマークで測定したほぼ同等の回答品質は区別する必要がある。とくに近傍クラスタが重なる場合、理論の互いに素という設定をそのまま全実装状況へ一般化しない。

## 感度・構成要素除去の検討

### アンカー閾値`κ`

LLaDAのHumanEval、最大生成長256、ブロック32、他のパラメータ固定で`κ`を変える。`κ = 0.95`では逐次基準に対して約3.5倍、`κ = 0.9`では約4.1倍の処理量改善を報告する。閾値をさらに下げると処理量の上積みは小さい一方で品質が大きく低下する。アンカーとして採用する位置の信頼性が低くなると、周囲の中程度の確信度を安全に採用する根拠まで失われるからである。`κ = 1`の極端な場合はアンカーがほぼ出ず、逐次確定に近づく。

### 近傍半径`W`

同じ感度評価で`W = 1`から4の範囲では品質が基準と同等以上に維持されるが、4を超えると品質低下が顕著になる。`W = 32`はブロック全域で`τ`を適用する状態に近づき、局所性による保護が失われる。処理量の改善も`W ≥ 4`では頭打ちになる。半径4は「最も遠くまで広げれば速い」という設定ではなく、**十分な並列性を得ながら局所一致性の観測が保たれる上限付近**として選ばれている。

### 緩和閾値`τ`

`τ`を0.9から下げるとアンカー近傍で確定できる位置が増えるが、0.75より低くすると品質が大きく落ちる。LLaDAでは0.75を基本とするが、Dream-Instructは同じ値でも安全でないため0.8へ引き上げるというモデル依存性が記されている。これはLocalLeapが学習不要であっても、すべてのモデルに一組のパラメータを無調整で適用できることを意味しない、という実務上の重要な結果である。

### アンカー・近傍・後退経路の寄与

本論文の主要機構は、①高信頼アンカーの存在を発動条件とする、②距離制限された近傍だけを緩和する、③アンカーがなければ逐次確定へ戻る、という組み合わせである。感度実験から、アンカー閾値を緩めすぎると品質が落ち、近傍半径を広げすぎても品質が落ちることが分かる。したがって、単に一括で確定数を増やすのではなく、**確信度の高い中心と近傍の限定**の両方が必要という因果関係を支持する。ただし、各構成要素を完全に取り除いたすべての組合せの実験が報告されているわけではないので、数値を未提示の構成要素除去実験として創作しない。

## 既存研究との違い

逐次確定では、ブロック内のマスク位置を一つずつ埋めるため、生成長に近い回数の反復が必要になる。Fast-dLLM型の確信度並列復号では、全域の各位置が高い閾値を越えたときだけ複数確定する。LocalLeapは、全域の高閾値を維持したまま、**アンカー周囲の限定領域にだけ追加の低閾値を許す**。論文のGSM8Kの三者比較で、Fast-dLLM型の95反復からLocalLeapの73反復へさらに削減できる点が、この差分の直接的な証拠である。

他方、生成済みトークン列をあとから一括で確定させる早期停止方式とは異なり、LocalLeapは各反復で個々の位置を早期に確定する。新しい下書きモデルを学習して検証器で受理する投機的復号（speculative decoding）とも異なり、単一の拡散モデルの既存確率分布と位置関係を利用する。外部の下書きモデル、追加の重み、追加のGPU間通信を必須としない点が導入上の利点である。

## 限界・再現上の注意

第一に、速度改善は拡散モデルの反復回数削減に由来するため、自己回帰型の通常の次トークン生成へ同じルールをそのまま適用できない。`[MASK]`位置を並列予測するモデル構造と、その位置の確定を操作できる復号器が前提である。第二に、確信度と最終結果の一致性はモデル・課題に依存する。DreamのGSM8Kの品質低下やHumanEval長系列での低下が示すように、無条件に無損失の高速化とは呼べない。

第三に、半自己回帰型のブロック長32、H800環境、使用モデル、出力長256・512・1024という評価条件の外では性能が未確定である。異なるGPU、異なるブロック長、複数同時要求、通信を含む分散サービングの全体処理量、GPUメモリ削減、エネルギー消費量は、この論文の主表からは直接求められない。LocalLeapはKVキャッシュ圧縮方式でも、MoE専門家配置方式でもない。

第四に、確定済みトークンは原則として再びマスクされないため、誤った近傍確定が後続予測へ影響し得る。確信度の高いアンカーが常に正しいとは限らず、数学的な条件付き上界は個々の実験の全出力一致を保証しない。精度優先の運用では、`κ`と`τ`の感度を対象モデルで測り、速度と正答率の両方を追跡する必要がある。

第五に、論文の本文にあるFast-dLLM比1.63倍という記述と表1の53.82/41.22 ≈ 1.31倍には不整合がある。本稿では一次資料の表を優先し、再現・引用時にこの数値を混同しない。GSM8Kの逐次比6.94倍、反復数の7.01倍、Fast-dLLM比約1.31倍は、それぞれ異なる比較である。

## 実装上の検討事項

既存のLLaDAやDreamを扱う復号器へ導入するなら、マスク位置ごとの最頻トークンと確信度を取得する処理は維持し、確定集合を選ぶ箇所だけLocalLeapに差し替える。CPUへ毎反復の確信度を取り出す設計は転送・同期を増やし得るため、GPU上で比較と近傍集合形成を実行できるかが重要である。ただし、これは論文の原理から導く実装検討であり、著者がすべてのランタイムでGPU上の融合実装を評価したという主張ではない。

モデルを替える際は、まずアンカー確信度と近傍の最終一致率を検査し、次に`κ`、`W`、`τ`を調整する。実務的には単一要求の生成TPSだけでなく、同時要求の平均・末尾遅延、正答率、反復数、確定位置数の分布を別々に測る必要がある。確定位置が少ない難しい入力では後退経路により利得が小さくなり、アンカーが多い入力では反復削減の利得が大きくなる可能性がある。この条件付き予測は論文の方式説明からの推論であり、特定の実測倍率としては扱わない。
