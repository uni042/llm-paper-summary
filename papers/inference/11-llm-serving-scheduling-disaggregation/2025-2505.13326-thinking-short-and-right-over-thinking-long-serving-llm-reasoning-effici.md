# Thinking Short and Right Over Thinking Long: Serving LLM Reasoning Efficiently and Accurately

> 余分な推論分岐を先に走らせて必要数の完了時に長考分岐を停止し、過程報酬で低品質分岐のKVを早期解放して連続バッチの待ち時間を削減する推論サービング方式。

## 概要

推論能力を上げる方法には、1本の思考連鎖を長くする逐次スケーリングと、同じ質問から複数の思考分岐を生成して多数決や報酬順位で選ぶ並列スケーリングがある。両者を組み合わせると精度は上がるが、サービングでは二つの問題が起きる。第一に、分岐長が大きくばらつき、最も長い分岐を待つため単一要求の遅延が伸びる。第二に、多数の分岐がKVキャッシュとバッチ枠を占有し、後続要求の待ち時間が増える。

SARTは「長く考える」代わりに「短く正しい分岐を早く確保する」。必要な完成分岐数より多くを同時に開始し、必要数が完了した時点で残りを打ち切る。さらにQwen2.5-Math-PRM-7Bのような過程報酬モデル（Process Reward Model; PRM）で途中分岐を評価し、初期は慎重に、最初の完成分岐が得られた後は強く低品質分岐を削る。削除した分岐のKVは直ちに解放し、vLLMの連続バッチへ別要求を入れる。

8台のH100 80GB、DeepSeek-R1-Distill-Qwen-14BとDeepSeek-R1-Distill-Llama-70B、GPQA/GAOKAOで評価し、同程度の精度条件でSelf-Consistencyより最大28.2倍、平均15.7倍の効率改善を報告する。

## 問題設定

分岐サンプリングでは複数分岐を同じバッチでデコードできるが、最終回答を作るまで全分岐を待つ方式では最長分岐が要求遅延を決める。著者らの事前観測では同じ質問でも応答長が大きく変わる一方、正解かどうかと長さの相関は弱い。つまり極端に長い分岐を待つことが品質向上に直結しない。

サーバ全体では、各分岐が独立したデコード状態とKVを持つため、一つの要求が多数分岐を展開するとGPUメモリとバッチ枠を占有する。デコードはメモリ帯域律速になりやすく、複数要求をバッチしてGPU利用率を上げることが重要なので、分岐数増加は他要求のキュー待ちを悪化させる。

## 手法のあらまし

SARTはまず、最終判断にm本の完成分岐が必要ならm本だけを開始するのではなく、それより多いn本を開始する。m本が完成した時点で残りを止めるため、完了時間はn本中の最長ではなくm番目に早く終わる分岐へ近づく。順序統計の分析で、nを増やすほどm番目の完了長が短くなる確率が高まることを示す。

ただし余分なn-m本はGPU資源を増やす。そこでPRMを使い、途中分岐の品質が低いものを削る。最初の完成分岐が出る前は探索を残すため閾値を低くし、削除本数にも上限を設ける。完成分岐が出た後は、その分岐の報酬を新しい閾値として低品質分岐を積極的に落とす。

この二つをvLLMの連続バッチへ統合し、枝を実行単位として待ち行列へ入れる。削除・完了・早期停止した枝のKVを即時解放し、空いたバッチ枠へ別要求の枝を入れる。

## 手法

### 1. 冗長サンプリングと早期停止

通常のSelf-Consistencyでは必要本数を生成し切る。SARTは必要完成数mに対してn>m本を並列開始する。m本が完成したら未完了枝を終了するため、過剰思考に入った長い枝が最終遅延を支配しにくい。

この方法は追加FLOPsを使うため単独ではサーバ全体を速くする保証がない。実際、アブレーションでは早期停止だけだと応答長は短くなるが、余分な枝がキュー待ちを増やし、Self-Consistencyと同程度の効率に留まる。次の枝刈りが必要になる。

### 2. 二段階動的枝刈り

PRMは途中の推論軌跡へ報酬を付ける。第一段階では低い閾値を使い、明らかに悪い枝だけを削る。また最大削除数を設け、初期評価の誤りで全候補を失うことを防ぐ。

最初の枝が完成すると第二段階へ移り、その完成枝の報酬を基準に閾値を引き上げる。以降はそれより弱い未完了枝を積極的に削る。簡単な質問で短い高報酬枝が得られれば長考枝を早く捨てられ、難問で全枝の報酬が低ければ相対的に良い枝へ資源を集中する。

### 3. 連続バッチスケジューラ

SARTは枝をバッチの単位として扱う。現在バッチに空きがあれば待機枝を優先し、それでも空きがあれば新しい要求をプリフィルして枝を生成する。一定デコードステップごとに報酬計算・枝刈り・早期停止判定を行うため、毎トークンPRMを呼ぶ費用を避ける。

要求ごとに枝刈り段階、閾値、完了枝数、削除枝数をメタデータとして保持する。同一要求の枝は接頭辞KVを共有し、個別枝のKVは終了時に直ちに解放する。共有接頭辞は全枝が終わった時点で解放する。

### 4. 早期停止と枝刈りの相互作用

冗長サンプリングは単一要求の最長尾を短くするが、同時枝数を増やす。動的枝刈りはこの追加資源を途中で回収し、別要求の待ち時間を減らす。SARTのエンドツーエンド利得は、どちらか一方ではなく「短い完成枝を早く得る」と「不要KVを早く返す」の組合せから生じる。

PRMが誤って正しい枝を低評価すれば品質を落とし得るため、第一段階を保守的にする設計が安全弁になる。ただし完全な無損失方式ではない。

## 評価

### 代表的な評価条件

| 項目 | 設定 |
|---|---|
| GPU | NVIDIA H100 80GB ×8、NVLink 900GB/s |
| 対象モデル | DeepSeek-R1-Distill-Qwen-14B、DeepSeek-R1-Distill-Llama-70B |
| PRM | Qwen2.5-Math-PRM-7B |
| データ | GPQA、GAOKAO |
| 到着率 | 1 req/s、4 req/s |
| ランタイム | vLLM上に実装 |
| 比較 | Vanilla、Self-Consistency、Rebase |
| 指標 | P50/P90/P97/P99等のE2E遅延、正解率 |

### 代表的な評価結果

| 比較 | 効率改善 | 補足 |
|---|---:|---|
| Vanilla | 最大3.1倍、平均2.0倍 | 分岐なし推論より高精度も狙う |
| Self-Consistency | 最大28.2倍、平均15.7倍 | 同程度精度条件で長尾とキュー待ちを削減 |
| Rebase | 最大14.4倍、平均8.0倍 | 長い推論で木探索が重くなる条件 |
| Self-Consistencyとの精度差 | 最大でも約1.6ポイント以内の低下条件 | 大幅な速度差に対する品質交換 |

アブレーションでは、冗長サンプリング＋早期停止だけで応答長は短くなるがキュー待ちが増え、全体効率は十分改善しない。二段階枝刈りを加えるとキュー待ちが縮み、精度をほぼ保ったままE2E遅延が下がる。したがって枝刈りは単なる追加機能ではなく、冗長サンプリングの資源増を打ち消す機構である。

## 既存研究との差

Self-Consistencyは複数完成回答を集約するが、サーバ資源の占有時間を最適化しない。Rebaseは木探索で推論経路を広げるが、数千トークン級の長い推論では探索空間が急増する。SARTは探索アルゴリズム自体より、複数推論枝を連続バッチ環境でどう生存・終了させるかを扱う。

また、特定語「wait」などを見て再考枝を止める方式と違い、PRMの連続値を閾値として使うため、言語や表現に依存しにくい一方、PRM推論費用と評価誤差を持つ。

## 限界・実装状況

追加ハイパーパラメータがあり、枝数、必要完成数、PRM評価間隔、枝刈り閾値をワークロードに合わせて調整する必要がある。論文自身もこの調整複雑性を限界として挙げる。

スケジューラは先着順を前提とし、プリエンプションを持つ公平性・優先度スケジューリングへ組み込むには再設計が必要である。評価は数学・STEM推論と2種類のDeepSeek蒸留モデルが中心で、一般会話やツール利用エージェントで同じPRM判定が成立するとは限らない。

## 一般的な実装上の含意

推論時スケーリングでは、1要求のトークン数だけでなく、分岐がKVを占有する時間をサーバ資源として扱う必要がある。長尾枝を止めるだけでは不十分で、解放したKVとバッチ枠を直ちに別要求へ再利用できるスケジューラとの統合が重要になる。
