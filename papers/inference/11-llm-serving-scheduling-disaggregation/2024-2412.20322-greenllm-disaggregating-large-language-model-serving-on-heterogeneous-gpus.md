# GreenLLM: Disaggregating Large Language Model Serving on Heterogeneous GPUs for Lower Carbon Emissions

> 「古いGPUは遅いからLLM配信には使えない」と一括りにせず、処理段階・モデルサイズ・要求率ごとにエネルギー効率を測る。A100が必要な重い部分だけを新GPUへ残し、T4/V100でもSLOを守れる部分を旧GPUへ移すことで、運用時電力だけでなく新GPU製造に伴う体現炭素も含めた総排出量を減らす。

## 概要

LLM配信の炭素排出には、電力消費に電力網の炭素強度を掛けた運用炭素（operational carbon）と、GPU製造時に発生する体現炭素（embodied carbon）がある。最新GPUへ全面更新すると処理性能は上がるが、旧GPUの早期廃棄と新GPU製造による体現炭素が増える。

GreenLLMは、旧世代GPUを「最新GPUの代替」として単独利用するのではなく、LLM配信パイプラインの一部分だけを担当させる。論文は二つの分離方式を扱う。

1つ目の事前入力処理・復号分離（Disaggregated Prefill-Decode, Disg-Pref-Decode）は、計算律速になりやすい事前入力処理（prefill）をA100へ、相対的に計算量の軽い復号（decode）をT4/V100へ割り当てる。ただし段階間でKVキャッシュを転送するため高いネットワーク帯域が必要になる。

2つ目の分離投機的復号（Disaggregated Speculative Decode, Disg-Spec-Decode）は、7B対象モデルと検証器をA100へ、300Mまたは1BのドラフトモデルをT4/V100へ置く。GPU間で主に候補tokenと確率分布を送るため、巨大なKVキャッシュ転送を避けられ、低帯域環境でも旧GPUを再利用しやすい。

GreenLLMはこれらを固定的に選ぶのではなく、要求率、入力/出力長、ネットワーク帯域、遅延SLO、GPU電力特性から、総炭素が小さくなる構成を要求条件ごとに選ぶ。

## 問題設定

### 古いGPUは常にエネルギー効率が悪いわけではない

A100は高性能だが、小さい300M/1Bモデルを低〜中QPSで処理する場合、T4/V100の方が1 tokenあたりのエネルギーが小さい領域がある。7Bでは旧GPUの優位領域は低QPSへ縮むが、それでも「処理の種類を選べば旧GPUを使える」余地がある。

このためGreenLLMはGPU世代そのものではなく、モデルサイズ・QPS・処理段階の組合せをプロファイルする。

### prefill/decode分離はKVキャッシュ転送が壁になる

prefillをA100、decodeを旧GPUへ分けると、prefillで生成したKVキャッシュをGPU間で渡す必要がある。7Bでも要求率1 prompt/sで10Gbps超を必要とする例があり、論文のGCP標準16GbpsではQPS上昇に伴ってネットワークが律速になる。

したがって高帯域ならDisg-Pref-Decode、帯域が足りなければ通信量の小さいDisg-Spec-Decodeという代替経路が必要になる。

## 手法

### 1. 二種類の異種GPU分離方式を用意する

**Disg-Pref-Decode**では、7BモデルのprefillをA100、decodeをT4/V100へ置く。prefillは大きな行列積をまとめて処理するため新GPUの演算性能を使い、decodeは旧GPUでSLOを守れる負荷領域へ限定する。

**Disg-Spec-Decode**では、7B対象モデルとverifierをA100、300M/1BドラフトをT4/V100へ置く。旧GPUは小型モデルだけを担当し、A100は正確な対象分布を維持する。

投機的復号の通信では、旧GPUが生成した候補tokenとproposal distributionをA100側へ送り、対象モデルの検証結果を戻す。KVキャッシュ丸ごとの転送より小さいため、ネットワーク要求が低い。

### 2. 通信と対象モデル計算を非同期に重ねる

Disg-Spec-Decodeでは、ドラフト/対象モデルを別server groupに分け、NCCLとPyTorchの非同期通信（isend/irecv）を使う。候補分布の通信を対象モデルやverifierの実行と重ね、分離による待ちを隠す。

この最適化がないと、旧GPUを使って電力を下げても通信待ちで実行時間が伸び、体現炭素の時間按分や運用電力が増えて利点を相殺する。

### 3. プロファイラが性能・電力・通信を実測する

各GPU・モデル・要求サイズ・QPSについて、最初のtokenまでの時間（Time To First Token, TTFT）、出力token間時間（Time Per Output Token, TPOT）、GPU電力を測る。電力はpynvmlで取得し、複数serverの測定値はREST APIで集約する。

総炭素は、
- GPU製造時炭素をハードウェア寿命と要求実行時間で按分した体現炭素
- 要求エネルギー×地域の炭素強度で計算する運用炭素
の和として評価する。

### 4. SLO-aware schedulerが構成を選ぶ

候補はA100単独、A100上の単一GPU投機的復号、A100+T4/V100のDisg-Pref-Decode、A100+T4/V100のDisg-Spec-Decodeなどである。

schedulerは現在の要求サイズ・QPS・ネットワーク帯域に対して、TTFT/TPOTのSLO達成率が要求水準を満たす候補だけを残し、その中から総炭素が最小の構成を選ぶ。

高負荷では性能不足の旧GPU構成を捨ててA100単独へ戻せるため、「炭素削減のためSLOを犠牲にする」固定配置にならない。

## 評価

### 評価条件

| 項目 | 条件 |
| --- | --- |
| 環境 | Google Cloud Platform |
| 新GPU | 1×A100 40GB、a2-highgpu-1g |
| 旧GPU | 1×T4 16GB または 1×V100 16GB、n1-standard-8 |
| GPU間帯域 | 標準16Gbps。感度分析では1〜16Gbps |
| モデル | Llama 7B target、1B/300M draft |
| 配信基盤 | vLLM。分離通信はNCCL + PyTorch async |
| ワークロード | ShareGPT、HumanEval、LongBench |
| SLO | ShareGPT: TTFT 200ms / TPOT 80ms、HumanEval: 125ms / 200ms、LongBench: 15s / 150ms |
| 入出力長 | 各データセットのP25/P50/P75実分布を使用 |
| 基準 | Standalone A100 |
| 炭素指標 | 1 token当たり総炭素、運用炭素、体現炭素 |
| SLO条件 | 主な炭素比較は90% SLO attainment |

### 代表結果

| 条件 | 結果 | 解釈 |
| --- | --- | --- |
| 各ワークロード・可変QPS | Standalone A100比 **31.3〜40.6%** 最大炭素削減 | 低〜中負荷では旧GPUの効率を利用できる |
| SLO達成 | 90%以上を維持する構成をschedulerが選択 | 炭素最小化を遅延違反と交換しない |
| 低炭素地域・GPU寿命感度 | 最大27.9%削減を報告 | 電力由来排出が小さくても体現炭素再利用の余地が残る |
| Disg-Pref-Decode | 7B・1 QPSでも10Gbps超の帯域を要求する例 | KV転送が適用範囲を制約 |
| Disg-Spec-Decode | token/分布転送中心でDPDより帯域要求が小さい | 低帯域時の旧GPU再利用経路になる |

炭素削減が最大になるQPS範囲はワークロードで異なる。LongBenchは入力/出力が長いため旧GPUがSLOを守れるのはおおむね低QPS側で、HumanEvalのような短い要求ではより高いQPSまで異種構成を利用できる。

## 炭素評価の読み方

GreenLLMの「旧GPU再利用」は、旧GPUを追加で使えば自動的に体現炭素が減るという意味ではない。各要求に旧GPUを追加すると、その旧GPUの体現炭素按分も総量へ加算される。実際、低QPSでは運用炭素削減が主な利得で、高QPSではschedulerがA100上の投機的復号へ戻ることがある。

また体現炭素はGPU寿命へ按分するモデルなので、想定寿命を変えると結果も変わる。論文はこの感度を明示的に評価している。

## 既存研究との差

DistServe/Splitwiseもprefillとdecodeを分離するが、主に高性能GPU同士で性能・コストを最適化する。GreenLLMは旧GPUを積極的に組み込み、目的関数を総炭素へ置く。

投機的復号でも通常はtarget/draftを同じ新GPUまたは同種GPUへ置くが、GreenLLMは小型draftだけを旧GPUへ分離することで、性能の弱いGPUを「対象モデルを置くには不足だが、ドラフトには十分」な資源として使う。

## 限界・実装状況

Disg-Pref-DecodeはKVキャッシュ転送のため高帯域ネットワークへ強く依存する。異なるrackや低速Ethernetでは利点が消える可能性がある。

炭素削減率は電力網の炭素強度、GPU寿命、製造炭素推定値に依存する。これらは地域・設備ごとに異なるため、40.6%を普遍的な値として扱うべきではない。

評価モデルは7B targetと300M/1B draftが中心で、現代の70B〜数百BモデルやMoE、多node tensor parallelで同じscheduler判断が成立するかは別途検証が必要である。

実装はvLLM上で行われているが、一次資料で公式コードURLは確認できなかった。
