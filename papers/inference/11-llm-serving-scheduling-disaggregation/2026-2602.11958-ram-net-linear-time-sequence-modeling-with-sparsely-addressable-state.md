# RAM-Net：疎アドレスによる固定長再帰メモリの読書き

## 概要

全注意型Transformerは、過去トークンを独立したkey/valueとして保存し、現在のqueryに適合する位置へ集中してアクセスできる。一方でKVキャッシュは系列長に比例して増え、長文推論のメモリ容量と帯域を圧迫する。線形注意や状態空間型の再帰モデルは、履歴を固定サイズの状態へ畳み込んでこの成長を抑えるが、異なるトークンの情報を同じ状態行列へ重ね書きするため、遠い位置にある細かな情報を取り出す際に干渉が生じる。

RAM-Net（Random Access Memory Network）は、固定サイズ状態を多数の独立したスロットに分割し、現在のkeyが選ぶ少数のスロットへだけ書き込み、queryが選ぶ少数のスロットからだけ読み出す。アドレスが重ならないトークン同士は同じ状態を汚さない。スロット総数を増やしても毎ステップのアクセスはTop-K件に制限できるよう、アドレス分布を小さなsoftmaxの積で表し、木探索で上位アドレスだけを求める。

原著v2の340Mモデルでは、RULERの単一針探索S-NIAH（1K～16K、3種類×5長さ）の平均正答率がTop-32で72.9となり、Gated DeltaNetの51.3、Mamba2の35.0、全注意のTransformer++の48.6を上回った。ただし、実文書を用いた別の検索課題の平均では同じ340M Top-32が32.0で、Transformer++の35.1に届かない。1.3Bでも実文書検索の全注意との差は残る。したがって「固定長メモリでもあらゆる長文検索で全注意より高精度」という主張ではない。<https://arxiv.org/pdf/2602.11958v2> の表1～3を参照した。

## 問題設定：固定長状態の容量とアクセス費用を切り離す

全注意は各時刻のkey/valueを保持し、読み出し時には全履歴を照合する。トークン単位の情報分離と選択的な注意が長所である一方、KV容量と読み出し費用が系列長とともに増える。線形注意はkeyとvalueの外積を一つの再帰行列へ蓄積し、固定長の状態を実現するが、複数トークンの寄与が同じ行列へ混在する。ゲートやdelta-ruleは古い情報の減衰・上書きを改善しても、全状態を毎回読み書きする構造が残る。

著者らはこの二つを「状態の粒度」と「アクセスの疎密」という別々の設計軸に分ける。RAM-Netは状態の総容量を固定しつつ、独立スロットの集合として保持し、各時刻に選ぶスロット数だけを小さくする。重要なのは、過去トークンを完全に独立して保持するわけではない点である。同じスロットに書き込まれた値は依然として混合するため、アドレスの衝突確率と適切なquery/key対応が検索品質を左右する。

## 手法

### 1. スロット配列と疎アドレス

層・headごとにアドレス集合 A の各要素aへ値ベクトルs_t[a]を置き、状態を |A|×d_v の配列として表す。時刻tのkey k_tから書込み重みw_t、query q_tから読出し重みr_tを求める。両重みは全スロットに密に分布させず、非ゼロ要素がK個だけになる。書込みでは選ばれたスロットの内容と書込み質量を更新し、読出しではr_t[a]で重み付けした選択スロットの値を合算する。選ばれないスロットは変更しない。

この構造では二つのトークンが別のアドレスへ書かれる限り、再帰状態を共有していても直接の書込み干渉が起きない。一方、似た内容が同じアドレスへ集中すると衝突は残る。読出しアドレスが正しい記憶スロットに重ならなければ、保持されている情報も取り出せない。容量が固定であることと検索の完全性は同義ではない。

### 2. Product SoftmaxとTop-Kアドレス木探索

単純に|A|個のスロットへ一度にsoftmaxをかけると、スロット数に比例する投影・正規化・上位選択が必要となり、大容量化の利点が消える。RAM-NetのAddress Decoderはkeyまたはqueryのd_k次元をU個の部分ベクトルに分割する。各部分の幅をd_pとすると、アドレスはU桁のd_p進数で表せ、総スロット数は |A|=d_p^U となる。

各桁の候補d_p個に対して小さなsoftmaxを計算し、完全なアドレスの確率を各桁確率の積として定義する。これは巨大な|A|次元分布を明示生成しない積形式softmaxである。上位K個のアドレスを得る際には、桁を順に延長する木探索を使い、各段階でK個の高確率部分アドレスだけを残す。すべての部分アドレスに同じ残余桁分布が続くため、この枝刈りでも厳密な上位K件を取得できる。論文の計算量は O(UKd_p+Ud_p log d_p) であり、全スロット数|A|を走査する計算量ではない。

Uを増やせばアドレス空間を指数的に拡張できるが、計算費用がゼロになるわけではない。木探索、選択アドレスの間接参照、メモリ配置、書込みイベントの整列などの追加費用は残る。学習信号は桁の選択肢を共有する多数のアドレスに伝わるため、巨大な独立softmaxを直接学習するより最適化しやすいという設計である。

### 3. CAPEによる位置依存のアドレス移動

内容だけからアドレスを作ると、同じ内容は系列中の位置に関係なく同じスロットへ書き込まれる。RAM-NetはCyclic Address Positional Embedding（CAPE）を導入し、時刻tで選ばれたアドレスaを (a−t) mod |A| へ循環移動する。書込み時刻sと読出し時刻tの差がアドレスの重なり方へ反映され、相対位置に応じた記憶の参照が可能になる。

全headをCAPEへ統一するのではなく、位置依存のheadと内容だけで参照するNoPE headを併用する。これは繰り返し現れる妨害文の扱いにも関係する。内容だけのheadでは同じ妨害文が少数スロットへ集まり、別のスロットに保存された針の情報を比較的汚しにくい。他方、位置を使うheadは同一内容の異なる出現を区別する役割を持つ。両者の組合せを実験で使っている。

### 4. Gated Sparse Update：選択スロットだけの忘却

通常のゲート付き線形注意は、忘却係数を再帰状態全体に掛けるため、全スロットを毎ステップ操作してしまう。RAM-NetのGated Sparse Update（GSU）は、各スロットの内容s_t[a]に加えて累積書込み質量m_t[a]を持つ。現在の書込み重みw_t[a]と、入力から計算する忘却強度γ_tを使い、質量を m_t[a]=λ_t[a]m_(t−1)[a]+w_t[a] と更新する。

内容の更新は `s_t[a]=s_(t−1)[a]+η_t[a](v_t−s_(t−1)[a])`、`η_t[a]=w_t[a]/(m_t[a]+ε)` である。書込みがないスロットは `w_t[a]=0`、`λ_t[a]=1`、`η_t[a]=0` となり、質量も内容もそのまま残る。選ばれたスロットでは過去の内容から新しいvalueへ、0～1の範囲の係数で近づくため、無制限な加算蓄積による値の発散を抑える。

同じスロットへ多数回書かれれば質量が大きくなり、次の書込みによる変化が小さくなる。γ_tは忘却の強さを調整し、過去を保持する累積平均に近い動作から新規値による置換に近い動作まで切り替える。読出し側では選択スロットの加重和にhead単位のRMSNormと出力ゲートを施し、出力射影へ渡す。つまりアドレス選択、状態の局所更新、正規化付き読出しまでが一連の推論経路となる。

### 5. GPU実装と時刻順の維持

スロットへのアクセスはトークンごとに散在するため、単純なGPU実装では不規則なメモリアクセスが生じる。学習・prefillでは全トークンの読書きアドレスを並列に生成し、スロットごとにイベントを並べ替え、各スロット内では時間順に更新を適用する。異なるスロット間と値ベクトルのチャネル間は並列化できる。処理量は系列長×選択スロット数Kに比例し、全スロット数への密アクセスを避ける。

自己回帰復号では新しいトークンに対応するK個の書込み・読出しを実行する。実装上の整列・散在アクセスの費用があるため、単に「状態アクセス量が小さい」ことから実機スループットを推定するのではなく、論文は別途RTX 5090上で復号速度を測定している。

## 評価結果：能力とアクセス量の交換関係

### 言語モデル能力（原著表1）

| 規模・条件 | WikiText PPL（低いほど良い） | 常識推論平均（高いほど良い） | 1ステップの活動状態要素数 |
|---|---:|---:|---:|
| 340M Mamba2 | 26.23 | 50.6 | 12.9M |
| 340M Gated DeltaNet | 26.85 | 50.1 | 8.5M |
| 340M RAM-Net Top-8 | 26.89 | 50.3 | 0.4M |
| 340M RAM-Net Top-32 | **25.87** | **50.9** | 1.6M |
| 1.3B Mamba2 | 15.96 | 57.8 | 26.0M |
| 1.3B RAM-Net Top-8 | 16.49 | 57.4 | 0.8M |
| 1.3B RAM-Net Top-16 | **15.90** | 57.8 | 1.6M |

340MのTop-32はWikiText PPLと常識推論平均で比較群の最良値を記録した。ただしTop-8ではMamba2よりPPLが悪く、スロット数Kを絞るほど常に精度が良いわけではない。1.3BのTop-16はPPLでMamba2をわずかに上回るが、常識推論平均は同点であり、全指標で一方的な改善を主張できない。活動状態要素数は毎ステップにアクセスする量であり、総状態サイズではない。RAM-Netの総状態は340Mで26.2M、1.3Bで52.4M要素と論文に記載されている。

### 長距離針探索（原著表2）

| モデル | 340M S-NIAH平均 | 1.3B S-NIAH平均 |
|---|---:|---:|
| Transformer++ | 48.6 | 56.4 |
| Gated DeltaNet | 51.3 | 61.0 |
| Mamba2 | 35.0 | 62.4 |
| RAM-Net Top-8 | 64.7 | 65.0 |
| RAM-Net Top-16 | 65.1 | **70.1** |
| RAM-Net Top-32 | **72.9** | 原著表2に該当構成なし |

340M Top-32の72.9はGated DeltaNetより21.6ポイント高く、1.3B Top-16の70.1はMamba2より7.7ポイント高い。これは特定の合成的針探索の平均であり、汎用的な長文QAの平均ではない。S-NIAH-1の反復妨害文では16Kまで高い精度を維持するが、多様な自然文を妨害に使うS-NIAH-2/3は難しく、16KではRAM-Netを含む全方式が大きく低下する。Top-Kを増やすと改善する一方で、活動状態アクセス量も増える。

### 実文書検索の負の結果（原著表3）

| 規模・方式 | 実文書検索平均 |
|---|---:|
| 340M Transformer++ | **35.1** |
| 340M Mamba2 | 26.9 |
| 340M RAM-Net Top-8 | 23.2 |
| 340M RAM-Net Top-32 | 32.0 |
| 1.3B Transformer++ | **49.8** |

実文書からの情報抽出では全注意のTransformer++が両規模で最高である。340M Top-32は同規模の再帰型比較群を上回るものの、全注意には3.1ポイント届かない。1.3BではRAM-Net Top-8がTop-16より高く、単純にKを増やせば全課題が改善するわけでもない。合成的な反復妨害と、実文書に含まれる多様な候補情報の違いが重要である。

### 速度と内部機構（原著図4・図5）

単一RTX 5090での340M自己回帰復号では、RAM-Net Top-8はGLAと同程度の生成スループットで、Mamba2、DeltaNet、Gated DeltaNetを測定した文脈長の範囲で上回った。原著図5はグラフであり、この確認では個別系列長の絶対token/sを数値として抽出していないため、速度倍率は創作しない。GLAは状態そのものが小さく、RAM-Netはより大きな状態を持ちながらアクセスする部分だけが小さいという違いがある。

別の合成的な多問い合わせ連想検索（MQAR）では、同程度の総状態容量を持つ再帰型基準より少ない活動状態で高い精度を達成した。これはアドレスの選択性が干渉を減らすという仮説を支える。ただし、学習・prefillのスロットイベント整列費用や商用サービングの同時実行・バッチ効率を直接示す測定ではない。

## 既存研究との差

Mamba2、GLA、Gated DeltaNetは固定長の再帰状態を扱うが、基本的にはその状態の広い部分を毎ステップ更新・参照する。RAM-Netは状態を独立スロットに分割し、書込みと読出しの両方をアドレスで制限する点が異なる。MoMなどの複数メモリ経路も情報の混合を減らすが、RAM-Netの設計単位は独立した値ベクトルのスロットであり、疎アドレスが書込みと読出しの交差を直接規定する。

PQCacheなどのKV検索方式は、過去トークンのkey/valueを保存したまま、近似探索で読む位置を減らす。一方RAM-Netは各トークンを独立したKVエントリとして保存せず、固定長のスロットへ値を再帰的に統合する。両者は「疎検索」を共有しても、保存する状態の意味と容量増大の仕組みが違う。Product-Key Memoryのような学習済みパラメータメモリとも異なり、RAM-Netのスロット内容は入力系列に応じて実行時に更新される。

## 限界・未評価事項

最大モデルは1.3Bであり、7B・70B級の既存Transformerをそのまま置換した際の精度・推論性能は示されていない。著者らの比較は同規模モデルを学習し直すもので、既存のTransformer重みから無学習でRAM-Netへ変換できるという実験ではない。学習量も340Mで10B、1.3Bで100Bトークンと明示され、商用大規模モデルへの一般化には検証が必要である。

アドレスが重ならない情報は干渉しにくい反面、関連する情報が別アドレスへ書かれた場合、queryがそれを読めない。特に多様な妨害文を含む長い文脈ではこの取りこぼしが顕著であり、S-NIAH-2/3の16K条件は弱い。スロット単位で独立に値を更新するGSUは、同時に参照される複数スロットを協調的に修正するdelta-rule的な機構を備えていない。アドレス分布に偏りがあることは観測されているが、頻繁に参照するスロットを高速メモリへ配置する階層化最適化は未実装である。

速度評価は単一RTX 5090上の340Mモデルの復号に限定される。学習・prefillの整列費用、異なるバッチサイズ、長時間稼働のGPUメモリ管理、マルチGPU分散、既存推論エンジンとの統合、TTFTやp99遅延の改善は本論文で十分に示されていない。活動状態要素数の削減は、GPU上の実効メモリ帯域・総VRAM・レイテンシを同じ倍率で削減する保証ではない。
