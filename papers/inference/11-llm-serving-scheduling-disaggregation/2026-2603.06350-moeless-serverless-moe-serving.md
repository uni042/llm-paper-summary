# MoEless: Efficient MoE LLM Serving via Serverless Computing

> expert parallelismで一部expertへtokenが集中してstragglerになる問題に対し、将来のexpert loadを予測し、必要なexpert replicaをserverlessに増減・配置するMoE serving system。

## 問題設定
Distributed MoEではexpertごとのrouting量が偏るため、人気expertを持つGPUが遅れ、all-to-all後の同期で他GPUも待たされる。固定構成のexpert parallelismでは、この時間変動するhot expertへ柔軟にresourceを追加しにくい。

## 手法
MoElessはlayer-awareな軽量predictorで次layerのexpert load distributionを推定し、straggler候補を事前に特定する。その予測に基づきserverless expert replica数を動的に増減し、function locality、GPU utilization、all-to-all communicationを考慮して配置する。

predictorは最大でも約80K parameterで、prediction delayはlayer当たり0.2 ms未満。expert scaling / placementは非同期に行う。

## 評価条件
Megatron-LM上へprototypeを構築し、8× NVIDIA A6000（合計384 GB、NVLink）でMixtral-8×7B、Phi-3.5-MoE、Llama-4-ScoutをLMSYS-Chat-1MとShareGPT workloadで評価する。

## 主要結果
MoElessはMegatron-LMに対して平均MoE layer forward latencyを**43.19%削減**し、EPLBに対して21.89%削減した（Fig. 8–9 / §6.2）。総inference costはEPLB比で**84.06%削減**し、Megatron-LM比では92.68%削減した（Fig. 10 / §6.2）。

## 限界
serverless functionのcold start対策はpre-warmingと固定keep-aliveを前提とし、prediction distanceやload-balancing thresholdも主にoffline profilingで決めている。実cloud serverless基盤のbilling / isolation / cold-start特性が異なる場合は結果が変わり得る。

## 既存研究との差
EPLBなどは既存GPU群の中でexpert replicaやplacementを調整する。MoElessはexpert executionをserverless functionとしてelasticに増減し、load imbalanceに応じてresource量そのものを変える点が異なる。ProMoE等のoffload/prefetchはmemory制約が中心で、本研究はdistributed expert stragglerが中心である。

## 一般的な実装上の含意
MoE servingでexpert popularityが時間変動する場合、routingを変えてqualityを犠牲にする以外にも、hot expertだけを短時間複製する設計がある。特にexpert parallelismではmodel全体のautoscalingより細粒度なexpert単位elasticityが有効になり得る。

## 引用関係
Megatron-LM、EPLB、ProMoE、MoE-Infinity等を比較対象・関連研究とし、expert load balancingとserverless LLM servingを接続する。
