# Loquetier: A Virtualized Multi-LoRA Framework for Unified LLM Fine-tuning and Serving

> 共有基盤LLM上でLoRAごとの仮想モデルを隔離し、SMLMカーネルで微調整・評価・プリフィル・デコードを同一実行系へ統合する多数LoRA基盤。推論でFlexLLM比最大3.0倍、統一負荷でPEFT比46.4倍のSLO達成率を報告する。
## 書誌情報
- **著者**: Yuchen Zhang, Hanyue Du, Chun Cao, Jingwei Xu
- **著者・所属**: State Key Laboratory for Novel Software Technology, Nanjing University, China。
- **公開**: Advances in Neural Information Processing Systems 38 (NeurIPS 2025), Main Conference Track
- **種別**: conference
- **対象**: 多数LoRAサービング、LoRA微調整、学習・サービング統合、SMLMカーネル、モデル仮想化、PEFT、FlashInfer
- **実装**: 公式実装が公開され、`カーネル_src`にSMLM関連カーネル、`src/loquetier_src`に仮想化モジュールと統一実行系、実行例と試験コードを含む。論文はFlashInfer、PyTorch Autograd、Transformers Trainer拡張と組み合わせた実装を説明する。
## 概要
Loquetierは、同じ基盤LLMに多数のLoRAを載せる環境で、微調整と推論を別ランタイムへ分離すると基盤重みの重複、アダプタ切替時の停止、異種処理を混在できないことによるGPU利用率低下が生じる問題を扱う。基盤モデルを読み取り専用の共有ライブラリとして保持し、PEFTによる変更だけを仮想化モジュール（Virtualized Module）へ隔離して独立した仮想モデルを作る。さらにPunica系カーネルを層単位へ分解した分割型多数LoRA行列積（Segmented Multi-LoRA Multiplication; SMLM）と統一前向き計算フローにより、微調整・評価・プリフィル・デコードを一つのランタイムで混在させる。Llama-3 8Bを用いたA6000/H800実機評価では、推論専用でFlexLLM比最大3.0倍、統一微調整・推論でPEFT比46.4倍のSLO達成率を報告し、BurstGPTを用いた120分負荷でも92.37%のSLO達成率を示す。

Loquetierは、PEFTによるモデル変更を共有基盤モデルから切り離す仮想化モジュール（Virtualized Module）と、Punicaの多数LoRA演算を層単位へ再設計した分割型多数LoRA行列積（Segmented Multi-LoRA Multiplication; SMLM）を組み合わせる。前者により一つの読み取り専用基盤モデルから複数の独立仮想モデルを生成し、アダプタの動的な読み込み・解放やGPU間移動を基盤重みの複製なしに扱う。後者によりLoRA重みを層横断で事前連結せず、その線形層で必要なアダプタだけを一回のカーネル呼出しへ集約できるため、微調整・評価・プリフィル・デコードを同一の前向き計算へ混在させられる。

代表結果として、推論専用SLO達成率はLlama-3 8B、A6000、到着率を増加でPEFT / FlexLLMに対してPEFT比20.8倍、FlexLLM比最大3.0倍。層単位SMLMと推論用FlashInfer経路により、多数LoRAを同時処理しても高いデコードスループットを維持する。
## 問題設定
実運用のLoRAでは、同じ基盤モデルから多数の利用者・用途向けアダプタが派生し、アダプタの微調整と更新済みアダプタの推論配信を同時に行いたい。しかし既存系では、多数のLoRAを扱う推論基盤とPEFT学習基盤が分離され、基盤モデルや実行系を重複保持しやすい。Punica系の高速な多数LoRA演算は複数層のLoRA重みを静的に連結するため、層ごとに異なるLoRA構成や学習中の動的更新と相性が悪く、アダプタ交換時に計算を止めて重みを再構成する必要がある。FlexLLMのような共同実行系にも複数LoRAや一部の逆伝播演算に制約があり、推論・微調整・評価・プリフィル・デコードという異質な処理を一つの前向き計算へまとめにくい。課題は、共有基盤重みを壊さず複数アダプタを独立管理し、学習に必要な勾配経路と推論用高速カーネルを共存させながら、異種要求を十分大きなバッチへ統合することである。
## 新規性
Loquetierは、PEFTによるモデル変更を共有基盤モデルから切り離す仮想化モジュール（Virtualized Module）と、Punicaの多数LoRA演算を層単位へ再設計した分割型多数LoRA行列積（Segmented Multi-LoRA Multiplication; SMLM）を組み合わせる。前者により一つの読み取り専用基盤モデルから複数の独立仮想モデルを生成し、アダプタの動的な読み込み・解放やGPU間移動を基盤重みの複製なしに扱う。後者によりLoRA重みを層横断で事前連結せず、その線形層で必要なアダプタだけを一回のカーネル呼出しへ集約できるため、微調整・評価・プリフィル・デコードを同一の前向き計算へ混在させられる。
## 手法
### 手法のあらまし
Loquetierは基盤LLMをCPU/GPU上の共有モデルライブラリへ一度だけ読み込み、その各構成要素に対してデータと処理手続きを仲介する仮想化モジュールを被せる。アダプタごとにMixedLoraModelという仮想モデルを作り、LoRAのA/B行列、倍率、対象構成要素などPEFT固有状態は仮想側に保持する。基盤側の重みや設定を破壊的に変更しないため、複数仮想モデルが同じ大きな基盤重みを共有したまま独立して微調整・推論できる。実行時生成クラスを単純複製すると基盤重みまで複製される問題には、基盤への参照を一時的に外して仮想側だけを直列化し、別GPU上の同じ基盤モデルへ結び直す手順を用いる。これにより、微調整中のアダプタ状態だけを移動できる。

計算面では、PunicaのLoRA演算を改造したSMLMを各線形層単位で適用する。Punicaは同じ構成要素位置のLoRA重みを層横断で静的連結して高速化するため、学習時に層ごとのアダプタ構成を変えにくく、交換時に再連結が必要になる。Loquetierはその前処理をなくし、同じ線形層へ到達した有効リクエストのLoRA A/B行列を区間情報で一回のカーネル呼出しにまとめる。固定倍率はMixedLoraModel生成時に重みへ畳み込み、リクエスト依存の倍率だけを前向き計算時に適用する。これにより、アダプタ追加・削除や層ごとの異質構成を保ったまま、多数LoRAのバッチ処理を維持する。

統一計算フローでは微調整、評価、プリフィル、デコードの入力を一つの隠れ状態列へまとめ、Q/K/V射影など共有可能な線形演算とLoRA差分を先に一括計算する。その後、注意機構だけを用途別に分岐する。微調整は勾配が必要なのでPyTorch Autograd対応経路、プリフィルとデコードはFlashInferのバッチカーネルを使う。出力を再結合してO射影もSMLMで処理する。因果言語モデルでは各微調整・評価区間だけ出力確率と正解ラベルを切り出して損失を計算し、勾配蓄積係数で正規化する。Transformers Trainerも途中割込み可能な形へ拡張し、複数の学習器が一つのMixedLoraModel計算フローを共有しつつ、更新対象マスクで自分のアダプタだけを更新する。推論負荷が増えると共有前向き計算へ推論リクエストを多く入れ、学習側は残余計算資源を使うため、別サービス間で巨大な基盤モデルを交換せずに容量を融通できる。

### 仮想化モジュールと共有基盤モデル
基盤Transformerの線形層、注意機構、MLPなどを直接書き換える代わりに、各構成要素へ処理手続きとデータ参照を仲介する仮想ラッパを実行時に生成し、LoRAなどPEFT固有の状態だけを仮想モデルへ保持する。大容量の基盤重みは読み取り専用で共有されるため、アダプタ数が増えても基盤モデルを複製しない。各仮想モデルは独立したLoRA設定とパラメータを持ち、一つを微調整中にしても別の仮想モデルを推論へ使える。実行時生成クラスの複製・直列化で基盤重みまで複製されないよう基盤参照を一時的に外す仕組みを導入し、アダプタ状態を別GPU上の同一基盤モデルへ再接続できるため、微調整中の個体をサービス停止なしに移動できる。

### 分割型多数LoRA行列積（SMLM）
複数LoRAをアダプタごとに逐次計算すると小さな行列積のカーネル起動が増えるため、同じ線形層へ入る入力をアダプタ区間ごとに整理し、一回の多数LoRAカーネルで処理する。PunicaのCutlassベース設計を出発点とするが、層をまたいだLoRA重みの静的連結をやめ、各線形層で必要なA/B重みだけを渡す。これによりQ/K/V/OやMLPの上向き・ゲート・下向き射影の一部だけへLoRAを適用する異質構成、学習中に更新される重み、アダプタの動的交換を許容する。固定倍率はモデル生成時に重みへ適用して頻繁に通る計算経路から除外し、リクエスト依存倍率だけを実行時に処理するため、柔軟性を増やしつつ多数LoRAバッチ処理のカーネル呼出し削減を維持する。

### 微調整・推論の統一前向き計算と文脈管理
微調整、評価、プリフィル、デコードを別の実行系で順番に走らせず、各リクエストのバッチ範囲と系列範囲を文脈情報として保持し、共有可能な射影を同一の前向き計算で一括実行する。注意機構では微調整区間だけPyTorch Autograd対応経路へ、プリフィルとデコードはFlashInferへ分岐し、結果を元のリクエスト順へ連結して次の線形層へ渡す。評価は損失を計算するが逆伝播しない一回の前向き計算、プリフィルはKVキャッシュを初期化してデコードへ移るなど役割を分離する。学習器拡張では複数学習器の入力を共有前向き計算へ積み、更新対象マスクにより各逆伝播が対応LoRAだけを更新する。この構造により推論流量が増えたときGPU計算を推論へ寄せ、空き時間には微調整スループットを戻す動的な容量配分を同じランタイム内で実現する。

### 全体のデータ／制御の流れ
共有モデルライブラリにLlama基盤を置き、その上にアダプタ単位の仮想モデルとMixedLoraModelを生成する。文脈管理器が異種リクエストを一つの前向き計算へ構成し、線形層はSMLM、推論の注意機構はFlashInfer、学習の注意機構と逆伝播はPyTorch Autogradへ振り分ける。Trainerは更新対象マスクで更新対象を隔離し、アダプタ状態だけを読み込み・解放・移動できる。
## 評価条件
- **ハードウェア**: 推論専用は4基のNVIDIA A6000 48GB GPUを備えるサーバ、微調整専用と統一微調整・推論は4基のNVIDIA H800 80GB GPUを備えるサーバを使用する。各試験プロセスには少なくとも128GBのホストメモリを確保する。
- **ソフトウェア**: Loquetier公式実装、PyTorch、Transformers、PEFT、FlashInferを使用する。比較対象はFlexLLM、S-LoRAとPEFTの組合せ、HuggingFace TransformersとPEFTの組合せである。FlexLLMは公開Docker手順に従い、論文付録Bで不足していた逆伝播演算を実装して評価可能な状態へ補正する。
- **比較対象**: FlexLLM、S-LoRA + PEFT、HuggingFace Transformers + PEFT
基盤モデルはLlama-3 8Bである。推論用アダプタはAlpacaで学習したLoRAを使用し、推論入力はShareGPTを使う。微調整では同じLoRA設定を用い、重みをガウス分布で初期化し、AlpacaとGSM8Kを入力にする。推論専用試験ではリクエスト到着率を変え、SLO達成率、デコードのスループット、リクエストのスループットを測る。微調整専用試験では指定エポックを終えるまでの時間、学習と評価のスループットを測る。統一試験では単一または複数LoRAの微調整と、単一または複数LoRAの推論を組み合わせ、微調整効率と推論SLOを同時評価する。さらにBurstGPTから低負荷・中負荷・高負荷の6区間を抽出した動的試験と、120分の実負荷模擬を行う。
評価対象はLlama-3 8BとLoRAが中心で、単一ノード4 GPU環境に限られる。クラスタ間分散、70B以上の基盤モデル、複数ノードでのアダプタ移動、他のPEFT方式の性能は評価していない。S-LoRAはLlama-3のGQA形状にそのまま対応しないためK/V重み複製の回避策を用いており、カーネル不安定性も観測された。このため比較結果は実装条件の非対称性を含む。
## 主要結果
Loquetierは推論専用試験で到着率が高いほどFlexLLMとの差を広げ、論文総括ではSLO達成率がPEFT比20.8倍、FlexLLM比最大3.0倍になる。統一微調整・推論では推論専用時に近いSLOを維持しつつ、微調整側も平均で単独微調整時のおよそ40%の効率を確保し、PEFT比46.4倍のSLO達成率を報告する。モデル読み込みは合計5.336秒、追加ストレージ0Bで、FlexLLMの38.857秒、15.00GBを大きく下回る。BurstGPTを用いた120分の実負荷模擬では全体SLO達成率92.37%で、失敗はハードウェア容量を超える高負荷の瞬間、特にRPSが5を超える区間へ集中した。

- 推論専用SLO達成率 / PEFT比20.8倍、FlexLLM比最大3.0倍 (比較対象: PEFT / FlexLLM; 条件: Llama-3 8B、A6000、到着率を増加) — 層単位SMLMと推論用FlashInfer経路により、多数LoRAを同時処理しても高いデコードスループットを維持する。

- 統一微調整・推論のSLO達成率 / PEFT比46.4倍 (比較対象: HuggingFace PEFT; 条件: H800、単一・複数LoRA微調整と単一・複数LoRA推論の組合せ) — PEFTでは推論要求の90%以上が開始前に時間切れとなる条件がある一方、Loquetierは推論SLOを優先しながら微調整も継続する。

- 統一負荷下の微調整効率 / 単独微調整時の平均約40% (比較対象: Loquetier微調整専用実行; 条件: 3種類の推論到着率を併走) — 推論へ資源を譲りつつ、別ランタイムを停止するのではなく、同じ前向き計算の残余容量を微調整へ割り当てる。

- モデル読み込み合計時間と追加ストレージ / 5.336 s / 0 B (比較対象: PEFT 4.791 s / 0 B、S-LoRA 33.985 s / 0 B、FlexLLM 38.857 s / 15.00 GB; 条件: Table 2の読み込み単体試験) — 仮想化モジュール生成のためPEFTより少し遅いが、FlexLLMの重み変換と保存に伴う大きな時間・ストレージ増加を避ける。

- 実負荷模擬でのSLO達成率 / 92.37% (比較対象: Loquetier動的統一負荷; 条件: BurstGPT 120分複合負荷) — 失敗リクエストはRPSが5を超える一時的なハードウェア容量超過へ集中し、それ以外の区間ではSLOを満たす。

### 負の結果・境界条件
- 微調整専用ではLoquetierはPEFTよりわずかに遅く、論文はLoRA線形層の逆伝播が独立呼出しになることを主因と説明する。SMLMと協調する専用逆伝播カーネルは未実装で、付録Aでも今後の改善点とされる。FlexLLMは全7個のLoRA構成要素を扱えず、複数LoRA推論で10分以上の読み込み反復へ入る条件があり、比較条件は完全には対称でない。S-LoRAにもLlama-3 GQA対応の回避策とカーネルのNaN/Inf不安定性がある。さらに推論到着率が約3 RPSを超えるとA6000のメモリアクセスがボトルネックになり、Loquetier自身もSLO失敗が増える。

### 結果の読み方
主要な利得は、多数LoRAカーネルを単純に高速化したことだけではなく、基盤モデル、アダプタ状態、リクエスト種類の境界を分離し直したことにある。基盤重みを共有したまま仮想モデルごとの更新対象を隔離し、前向き計算の共有可能部分だけを統合するため、学習と推論をサービス単位で交互停止する必要がない。一方、逆伝播はまだPyTorch Autograd経路なので、統一処理時の学習効率には明確な改善余地が残る。
## 品質への影響
SMLMや仮想化モジュールは同じLoRA演算を別のバッチ構造とカーネル構成で実行するシステム最適化で、モデル品質を近似して速度を得る方式ではない。論文の主評価はSLOとスループットであり、精度改善を主張していない。微調整の更新対象マスクにより各学習器が対応アダプタだけを更新し、共有基盤重みを誤って更新しない設計になっている。
## 既存研究との差
Punicaは異なるLoRAを同一推論バッチへまとめるSGMVを導入したが、層横断の静的な重み連結が動的な学習や層別構成を制約する。S-LoRAはホストとGPU間のページングおよび異種バッチ処理で大量アダプタ推論を拡張するが、微調整を同一ランタイムで扱わない。FlexLLMは推論とPEFT微調整の共同実行を行うが、Loquetierの評価では複数LoRAや一部の逆伝播・構成要素に制約がある。Loquetierは仮想化モジュールでアダプタ状態を基盤から分離し、層単位SMLMと用途別の注意機構実装を組み合わせて、複数LoRAの微調整・評価・プリフィル・デコードを一つの前向き計算計画へ統合する点が異なる。
## 限界
評価はLlama-3 8Bと単一ノード4 GPU環境に限られ、70B級以上の基盤モデル、複数ノード、アダプタ移動時の実ネットワーク費用、数千アダプタ規模のメモリ階層は未評価である。仮想化モジュールは、基盤構成要素の重みや設定を破壊的に変更しないPEFT方式を前提とし、基盤を直接上書きする手法では前向き計算設計を正規化する必要がある。実行時生成クラスは通常のプロセス複製や深い複製と相性が悪く、独自の直列化と基盤参照の着脱機構を要する。微調整の逆伝播はSMLM化されておらず、PyTorch Autogradによる独立LoRA線形層呼出しが残るため、学習側はPEFTよりわずかに遅い。論文自身もSMLMと協調する逆伝播カーネル、クラスタ管理器との統合、LoRA以外のPEFT支援を将来課題に挙げる。
## 実装状態
NeurIPS 2025採択・公開済み。公式 `NJUDeepEngine/Loquetier` リポジトリにSMLM関連カーネル、仮想化モジュールとLoquetierランタイム、Llamaの単一・混在実行例、試験コードを公開している。
## 研究上の位置づけ
LLMサービング、多数LoRA、学習と配信の統合系統に位置する。推論専用アダプタ配信の効率化を、アダプタ更新が継続する環境へ拡張し、巨大な基盤モデルを共有資産、LoRAを移動可能な仮想個体として扱うことで、学習と配信の境界を薄くする研究である。オンライン適応や継続的な個人化を同じGPU群で実行するためのランタイム基盤として位置付けられる。
