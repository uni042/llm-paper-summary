# PecSched: Preemptive and Efficient Cluster Scheduling for LLM Inference

> 長入力事前計算を短入力事前計算で選択的に横取りし、事前計算・復号の分離同居と高速系列並列を組み合わせて、短入力の待ち時間と長入力の飢餓を両立して抑える。
## 書誌情報
- **著者**: Zeyu Zhang, Haiying Shen
- **公開**: arXiv:2409.15104v2
- **種別**: arXivプレプリント
- **対象**: クラスタスケジューリング、長文脈推論、横取り、系列並列
- **実装**: vLLMを拡張し、DistributedAttention、Ray worker、PyTorch distributed/NCCL、FlashAttention-2を用いて実装。論文はコード公開済みと記載する。
## 概要
最新版v2では初版CSPSから題名と主題が大幅に更新され、短入力が多数・長入力が少数という実運用の長尾分布を対象に、長入力による先頭待ち阻害と長入力の飢餓を同時に抑えるクラスタスケジューラPecSchedを提案する。短入力の事前計算だけが長入力事前計算を横取りし、短入力の復号は専用資源へ分離する一方、長入力復号と短入力事前計算は計算・メモリ特性の違いを利用して同居させる。さらにノード間リング注意とノード内Megatron/Ulysses型系列並列を組み合わせ、長入力事前計算を短縮する。Azure追跡データを基にした評価で短入力の99百分位待ち時間を最大92%削減し、処理量を最大595%改善する。

PecSchedは入力長が開始時に既知である点と、事前計算が計算律速・復号がメモリ律速という段階差を同時に利用する。短入力の事前計算だけが長入力事前計算を横取りし、短入力復号は専用資源へ分離する。長入力の巨大KVは元GPUへ残したまま長入力復号と短入力事前計算を同居させる。さらにノード間リング注意とノード内Megatron/Ulysses型系列並列を組み合わせ、長入力事前計算を短縮して横取り頻度自体を減らす。
## 問題設定
実際のLLM推論クラスタでは短入力と長入力の頻度が大きく異なる。Azure LLM推論追跡では約80%の入力が2Kトークン未満で、入力長が伸びるほど頻度が低下する一方、文書要約や検索では100K〜500K級の長入力も存在する。先着順では少数の長入力が多数の短入力より先にGPUを長時間占有し、短入力の99百分位待ち時間を最大10.2倍まで悪化させる。長入力用GPUを固定予約する方式は長入力が希少な時間帯にGPUを遊休させ、短入力へ使える資源を減らす。短入力を常に高優先度にする方式は短入力性能を守れるが長入力の92〜100%が飢餓する。単純横取りも未知の出力長と巨大KV移動が問題となるため、段階別制御と長入力事前計算の高速化が同時に必要である。
## 新規性
PecSchedは入力長が開始時に既知である点と、事前計算が計算律速・復号がメモリ律速という段階差を同時に利用する。短入力の事前計算だけが長入力事前計算を横取りし、短入力復号は専用資源へ分離する。長入力の巨大KVは元GPUへ残したまま長入力復号と短入力事前計算を同居させる。さらにノード間リング注意とノード内Megatron/Ulysses型系列並列を組み合わせ、長入力事前計算を短縮して横取り頻度自体を減らす。
## 手法
### 手法のあらまし
要求が到着すると入力長を基に長短を判定し、クラスタ全体待ち行列から各モデル複製の局所待ち行列へ配置する。短入力はまず完全に空いている複製へ送る。空きがなければ、長入力が復号中で演算器に余力があるGPUを探し、短入力の事前計算だけを同居させる。それも不可能な場合に限り、長入力の事前計算をカーネル境界で一時停止する。停止時には完了層で生成済みのKVと、現在層の直前カーネル出力に相当する中間値を保存する。短入力事前計算が終わるとそのKVを専用復号ノードへ転送し、短入力はそこで復号を続けるため、未知の出力長が長入力の停止時間へ入らない。長入力は保存した中間値から同じカーネル列を再開する。長入力が復号段階に入ると巨大KVは元GPU群へ保持し、各反復で新しい単一トークンの問い合わせQだけを他GPUへ送り、各GPUが局所KVとの注意を計算した後に出力を集約する。これにより巨大KVの移動を避ける。長入力の事前計算自体は系列並列で複数GPUへ分割し、ノード間では通信量が小さく系列長への拡張性が高いリング注意を使う。ノード内ではNVLink等の高帯域を利用し、Megatron型またはUlysses型系列並列について、系列長、テンソル並列度、問い合わせ・鍵値ヘッド数、パラメータ転送量から注意段とMLP段の通信時間・演算時間を推定する。注意段とMLP段でそれぞれ方式を選べるため四つの組合せを比較し、合計遅延が最小の構成を採用する。こうして短入力の尾部待ち時間を守りながら長入力を飢餓させず、長入力事前計算を短くして将来の横取り回数まで減らす。

### 選択的横取り
短入力の事前計算だけに長入力事前計算を横取りする権利を与える。短入力の入力長は到着時に既知なので事前計算時間を比較的安定して見積もれる一方、出力長は生成が終わるまで不明である。したがって短入力復号まで横取り対象にすると長入力の停止時間が予測不能になり、短入力が長く生成するたびに長入力が飢餓へ近づく。PecSchedは長入力事前計算をカーネル境界で止め、完了済み層のKVと現在層の直前カーネル出力だけを保存する。現在層の中間値は全KVに比べ小さく、論文では通常5%未満とされるため、横取りのために巨大な状態を別GPUへ移す必要がない。短入力事前計算が終われば保存位置から同じ長入力を直ちに再開する。横取り対象を既知時間の計算律速区間へ限定することで、短入力の先頭待ちを防ぎつつ長入力の進捗保証を保つ。

### 事前計算・復号の分離と同居
短入力は事前計算が完了すると比較的小さいKVを専用復号ノードへ送り、以後の未知長復号を長入力が使うGPUから切り離す。対照的に100K〜500K級長入力のKVは非常に大きいため、長入力は事前計算に使ったGPU群へKVを残したまま復号する。復号はメモリ帯域律速で行列演算器に余力が生じやすく、短入力事前計算は計算律速なので両者を同じGPUへ同居させると資源特性が補完する。長入力復号の各反復では新しい一トークン分の問い合わせQだけを分散KV保持GPUへ転送し、各GPUが局所KVで注意計算した結果を全体集約する。KV全体を動かさないため通信量を抑えられる。さらにGPUごとの短入力トークン数に閾値を設け、短入力事前計算を詰め込み過ぎて長入力復号の一反復時間を悪化させないよう制御する。

### 高速系列並列
長入力事前計算が長いほど、その実行中に新しい短入力が到着して横取りされる回数も増えるため、PecSchedはスケジューリングだけでなく長入力事前計算そのものを短縮する。ノード間ではリング注意を使い、系列区間をモデル複製へ分割してKVを循環させる。リング注意は通信量と系列長への拡張性に優れるが、リングが長いと計算効率が落ちる。そこでノード内ではNVLink等の高帯域を利用し、より通信量が多くても計算効率の高いMegatron型またはUlysses型系列並列を選択する。テンソル並列度、GPU数、系列区間長、問い合わせ・鍵値ヘッド数、パラメータ転送の有無から各方式の通信量と演算量を式で見積もり、注意段とMLP段について四つの方式組合せを比較する。最小推定遅延の構成を選ぶことで、ノード間の通信効率とノード内の演算効率を同時に得て、長入力の占有時間と横取り頻度を下げる。

### 長短入力混在スケジューラ
スケジューラは短入力を恒久的に最優先へ固定せず、完全に空いたモデル複製、長入力復号との安全な同居、長入力事前計算の横取りという順序で配置先を探す。この優先順序により不要な停止を避ける。長入力は入力長に応じて必要数のモデル複製へ系列並列配置し、同一ノード内の複製を優先してノード間通信を減らす。複数の有効候補がある場合は各局所待ち行列の総トークン数を合計し、最小の組合せを選ぶ。短入力の到着が続いても長入力復号は横取り対象外なので進捗を維持でき、長入力事前計算も短入力事前計算終了ごとに再開される。この段階別制御により、先着順の先頭待ち阻害、固定予約のGPU遊休、短入力優先方式の長入力飢餓を同時に抑える。

### 全体のデータ／制御の流れ
全体・局所待ち行列、入力長を使う配置器、横取り・再開機構、短入力の事前計算・復号分離、長入力復号との同居、高速系列並列選択器から構成される。
## 評価条件
- **ハードウェア**: AWS p4de.24xlarge ×4、NVIDIA A100 80GiB ×32、400Gbpsネットワーク
- **ソフトウェア**: vLLM拡張、FlashAttention-2 Triton版、Ray、PyTorch distributed、NCCL
- **データセット／トレース**: Microsoft Azure LLM inference トレース
- **比較対象**: FIFO vLLM、Reservation Llumnix、Priority Past-Future
各方式で同一追跡負荷を実行し、短入力の待ち時間・処理量と長入力の完了時間を比較する。長入力は必要に応じリング注意系列並列で複数モデル複製へ分割する。
短入力が多数、100K〜500Kの長入力が少数混在するクラスタ推論。
## 主要結果
PecSchedは短入力の99百分位待ち時間を先着順比58〜87%、予約方式比61〜92%削減し、短入力処理量を先着順比42〜318%、予約方式比193〜595%向上した。優先度方式は短入力性能だけならPecSchedに近いが、長入力の92〜100%を飢餓させる。一方PecSchedでは長入力を継続的に進めながら、長入力平均完了時間の増加を先着順比4〜7%、予約方式比6〜13%に抑えた。実運用上の意味は、短入力の尾部遅延を大幅に改善するために長入力を捨てたり専用GPUを固定予約したりする必要がなく、推論段階ごとの横取り・分離・同居と長入力事前計算の高速化を組み合わせれば、長短入力を同じGPUクラスタへ高利用率で共存させられることである。アブレーションでは高速系列並列を外すだけで長入力完了時間が39〜55%悪化し、長入力事前計算を短縮して横取り機会そのものを減らす設計が重要であることも確認される。

- 短入力99百分位待ち時間 / 最大92%削減 (比較対象: 予約方式; 条件: 4モデルのAzure追跡負荷) — 希少な長入力用資源を固定予約せず、短入力事前計算の選択的横取りで待ち時間を抑える。

- 短入力処理量 / 最大595%向上 (比較対象: 予約方式; 条件: Mistral 7B〜Llama 70B) — 予約GPUの遊休と長入力による先頭待ち阻害を避ける効果が大きい。

- 長入力平均完了時間 / 先着順比4〜7%増 (比較対象: FIFO; 条件: 短入力が横取りする混在負荷) — 短入力性能を大きく改善しながら長入力への影響を小幅に抑える。

- 高速系列並列の寄与 / 無効化で長入力完了時間39〜55%悪化 (比較対象: PecSched/FSP; 条件: アブレーション) — 長入力事前計算短縮が横取り頻度と停止時間を減らす主要因である。

### 負の結果・境界条件
- 横取りを無効化すると短入力99百分位待ち時間が75〜376%増え、処理量が21〜48%低下する。
- 短入力の事前計算・復号分離を無効化すると長入力完了時間が21〜29%悪化する。
- 長入力復号と短入力事前計算の同居を無効化すると長入力完了時間が23〜26%悪化する。

### 結果の読み方
長短入力混在では単純な先着順、固定予約、短入力優先のいずれも片側を犠牲にする。PecSchedは段階別の資源特性を使って横取り範囲を限定し、長入力を高速化することで両者の干渉を制御する。
## 品質への影響
推論の数学的意味を近似せず、要求の配置・横取り・並列方式を変更するため生成品質は維持される。
## 既存研究との差
vLLM型先着順は長入力の先頭待ち阻害を防げず、Llumnix型予約は希少な長入力向け資源を遊休させ、Past-Future型優先度は長入力を飢餓させる。PecSchedは短入力事前計算だけに横取り権を与え、短入力復号を分離し、長入力復号との同居と高速系列並列を組み合わせる点が異なる。
## 限界
- 長入力部分は元Azure追跡の上位5%を100K〜500Kへ合成置換しており、完全に自然な長文脈到着追跡ではない。
- 評価クラスタはA100中心で、異種GPUや広域ネットワーク条件の一般化は未検証である。
- 短入力復号専用資源数など運用パラメータはモデルごとに設定される。
- 最新版v2は初版CSPSから題名と主題が大幅変更されており、旧題名を前提とする索引は更新が必要である。
