# FocusUI: Efficient UI Grounding via Position-Preserving Visual Token Selection

> 指示に合うパッチだけを顕著性で残し、落とした区間を末尾の標識でつなぐ位置保存型の視覚トークン選択で、保持率30パーセントでもUI位置特定の精度低下を3.2ポイントに抑え、推論を1.44倍速くした。

## 概要

画面操作エージェントの基礎であるUI位置特定（UI grounding）は、自然言語の指示に対して画面上の対象要素の場所を当てる課題である。視覚言語モデルは高解像度の画面を数千個の視覚トークン（画像パッチの埋め込み）へ変換して処理する。2K解像度では約4,700個に達し、論文の実測では視覚トークンが全トークンの85.4パーセント以上を占める。画面の大部分は空白や均一な背景であり、この偏りが計算量と注意の希釈を招く。自然画像向けの視覚トークン枝刈りを流用すれば削減できそうだが、実際に適用すると位置特定の精度が大きく崩れる。理由は位置情報である。Qwen系のモデルは多次元回転位置埋め込み（M-RoPE）で縦横の座標を符号化しており、トークンを素朴に落とすと座標の列に飛びが生じ、細かい対象の位置がずれる。

本論文のFocusUIは、何を落とすかと、どう落とすかを分けて解く。何を落とすかは、指示に応じたパッチ顕著性（saliency、注目度）で決める。正解の枠との重なり具合と、色の近い隣接パッチを連結成分として数え大きな均一領域を割り引くUIグラフの prior を融合した密な教師信号を作り、軽量な採点器に学習させる。どう落とすかはPosPadが担う。落としたトークンの連続区間ごとに、その末尾の位置へ学習可能な特殊トークン1個を置き、区間があったこととその終端の座標をモデルへ残す。これにより列の長さは縮みながら、位置の連続性は保たれる。

**代表結果:** ScreenSpot-ProでFocusUI-7B（保持率100パーセント）は平均48.3で、GUI特化の比較対象GUI-Actor-7Bの44.6を3.7ポイント上回った。保持率を30パーセントまで下げても45.1で低下は3.2ポイントにとどまり、その条件で推論時間は1サンプル1.75秒から1.22秒へ（1.44倍）、最大GPUメモリは20,994MBから17,392MBへ約17パーセント減った。

## 問題設定

資源の面では、視覚トークンの数がそのまま言語モデルの系列長を決め、注意計算とメモリを押し上げる。テキスト指示は数十トークンしかないのに、画面側が数千トークンを占めるため、削減の余地はほぼ視覚側にしかない。精度の面では、UI位置特定は一般の画像理解と違い、答えが座標そのものである。対象は小さなアイコンやボタンであることが多く、数パッチのずれがそのまま誤答になる。論文の予備実験では、一般的な枝刈り手法を保持率30パーセントで適用すると、Qwen2.5-VL-3BのScreenSpot-Pro精度が26.1からFastVでは4.8へ、VisionZipでも18.9へ落ちた。つまりこの課題では「重要でないトークンを落とす」だけでは不十分で、「落とした跡の位置情報をどう残すか」が独立した設計問題になる。さらに、顕著性の教師信号にも工夫が要る。正解枠の内側だけを正例にすると、枠外の小さな要素や背景との区別を学べず、逆に注意スコアだけに頼ると均一な背景の冗長さを見抜けない。本論文は、枠の重なりと画面構造の prior の融合で教師信号を作り、落とし方はPosPadで位置を保存するという、二層の答えを用意する。

## 手法のあらまし

処理の流れは学習時と推論時で共通する骨格を持つ。まず画面をパッチ格子へ分け、各パッチへ顕著性スコアの教師信号を構築する。教師信号は、正解枠との重なり面積の割合と、色の近さで隣接パッチをつないだ連結成分の大きさから決まるUIグラフスコアを、重み0.8対0.2で融合したものである。次に軽量な問い合わせ誘導型の顕著性採点器が、視覚符号器のパッチ埋め込みと指示文の埋め込みの類似度から、パッチごとの顕著性を予測するよう学習される。推論時は保持率に応じて上位のパッチだけを残し、落とした連続区間をPosPadで末尾標識へ圧縮してから、短くなった視覚系列を言語モデルへ渡す。位置特定はGUI-Actor式の座標なし方式で、言語モデルの出力にある動作トークンの隠れ状態と残ったパッチ特徴を照合し、最も合うパッチを答えとする。学習では保持率を0.1から1.0の間で一様に抽選するため、一つのモデルが複数の保持率に対応できる。

## 手法

### 1. 指示からパッチへの顕著性スコア — 枠の重なりと画面構造の融合教師

この機構が観測するのは、学習データの画面、正解の要素枠、パッチ同士の色の近さである。保持する状態は持たず、学習前にパッチ格子ごとの教師スコアを計算する。行う動作は二つのスコアの融合である。第1の枠スコアは、各パッチと正解枠の重なり面積をパッチ面積で割った値で、枠の中心で高く縁でなだらかに下がる。第2のUIグラフスコアは、RGB空間での距離が閾値未満の隣接パッチ同士をunion-findで連結し、連結成分の大きさの対数に反比例する重みを与える。大きな均一領域、例えば空白の背景は成分が大きいため重みが下がり、小さく際立つ要素は重みが残る。融合は枠スコアに0.8、UIグラフスコアに0.2の重みで行う。選択するものは教師信号そのものであり、これが後段の採点器の学習目標になる。減るボトルネックは、枠内だけを正例とする粗い教師では枠外の構造を学べない問題と、注意任せでは背景の冗長さを見抜けない問題である。追加で消費する資源は学習前のスコア構築だけで、推論時には不要である。失敗条件は、正解枠の注釈品質であり、論文ではOmniParserによる検出枠との重なりが0.3未満のサンプルを除外して学習データを約22.9パーセント絞っている。注釈が粗いデータでは融合教師も粗くなる。

### 2. 問い合わせ誘導型の顕著性採点器 — 軽量な類似度計算で残すパッチを決める

この機構が観測するのは、視覚符号器が出すパッチ埋め込みと、言語モデル空間にある指示文のトークン埋め込みである。保持する状態は、自己注意で特徴を整える小さな層と射影の重みだけであり、本体モデルに比べて軽量である。行う動作は、各モダリティへ自己注意を掛けて双曲線正接と正規化で類似度を有界化した後、パッチと指示トークンの全組合せの類似度行列を作り、指示側で平均してパッチごとの顕著性スコアを得ることである。学習では、融合教師と予測スコアをそれぞれ確率分布へ変換した間のKLダイバージェンスを損失にする。推論時は保持率rに対して上位r割のパッチを残す集合として選択する。減るボトルネックは、言語モデルが処理する視覚系列の長さであり、プリフィルの計算と後段の注意がそのまま軽くなる。またこの採点は中間の注意重みを必要としないため、FlashAttentionとそのまま併用できる。追加で消費する資源は採点器自体の小さな計算であり、削減量に比べれば小さい。失敗条件は採点の誤りであり、対象パッチを落とせば後段では取り戻せない。付録のパッチ再現率の分析がこの上限を測っており、採点の質がそのまま精度の天井になる。誤って落とした場合の回復機構はなく、保持率を上げることが唯一の緩和策である。

### 3. PosPad — 落とした区間を末尾の標識へ圧縮して位置をつなぐ

この機構が観測するのは、選択で落とされたパッチの添字列である。保持する状態は持たず、系列の変換として動作する。行う動作は、一次元化したパッチ列の中で落とされた連続区間を列挙し、各区間について末尾の位置だけを残してそこへ学習可能な特殊トークン「pos_pad」を置き、区間の残りを削除することである。この標識は末尾位置の縦横座標（M-RoPEの位置）を受け継ぐため、後続のパッチから見て「ここまでに区間があった」という位置の段差が、実座標と矛盾しない形で残る。直接削除では座標列に説明のない飛びが生じるのに対し、PosPadでは終端が明示される。全部の落下位置へ標識を置く全詰め方式と比べると、標識の数が区間の数だけに減るため系列長も節約できる。除去実験では、保持率50パーセントで直接削除が29.2だったのに対しPosPadは42.3、全詰めは42.1であり、PosPadは全詰めと同等の精度を短い系列で得た。減るボトルネックは、位置の不連続による定位のずれである。追加で消費する資源は区間数分の標識トークンであり、例えば保持率50パーセントでは視覚トークン3,009個に対して標識433個が付く。失敗条件は保持率を極端に下げた場合で、10パーセントでは精度36.6まで下がる。標識は位置を伝えても落としたパッチの内容は伝えないため、小さな対象自体が落とされれば位置情報だけでは救えない。また付録の分析では、標識を区間の先頭や中間に置くより末尾が最も良く、走査順序と位置埋め込みの整合が理由とされている。

### 4. 座標なし位置特定との統合 — 残ったパッチの中から動作対象を選ぶ

この機構が観測するのは、短縮された視覚系列を処理した言語モデルの出力と、残ったパッチ特徴である。行う動作は、GUI-Actor式の動作ヘッドによる照合である。言語モデルは動作開始と終了を示す特殊トークンに挟まれた動作トークンを出し、その隠れ状態と、自己注意で文脈化した各パッチ特徴を別々のMLPで射影して内積を取り、ソフトマックスでパッチ上の分布を作る。最も確率の高いパッチが指示対象の位置になる。選択の前段で無関係なパッチが減っているため、照合の候補が絞られ、分布も乱れにくい。学習目的は、顕著性のKL損失、次トークン予測損失、動作注意の損失の和である。減るボトルネックは、数千候補からの照合の曖昧さである。追加費用は動作ヘッドの小さな計算だけである。失敗条件は前段の選択ミスと連動し、対象パッチが残っていない場合は分布の正解が存在しない。なおQwen3-VLのように深い視覚特徴を重ねる符号器では、深層の特徴は残ったパッチについてだけ集めるよう調整されている。

| 構成要素 | 入力・観測 | 具体的な動作 | 改善対象 | 主なトレードオフ |
|---|---|---|---|---|
| 融合教師の構築 | 正解枠、パッチの色の近さ | 枠の重なりとUIグラフの重みを0.8対0.2で融合 | 粗い教師信号 | 注釈品質への依存 |
| 顕著性採点器 | パッチ埋め込み、指示の埋め込み | 類似度の平均で顕著性を予測し上位を残す | 視覚系列の長さ | 落とした対象は回復不能 |
| PosPad | 落とされた添字列 | 連続区間を末尾位置の標識1個へ圧縮 | 位置の不連続 | 内容までは伝わらない |
| 動作ヘッド | 言語モデルの出力、残ったパッチ | 内積とソフトマックスで対象パッチを選ぶ | 照合候補の多さ | 前段の選択ミスに引きずられる |

## 評価

結論は三点である。第1に、FocusUIは全トークンを使う自らの完全版が既にGUI特化の比較対象を上回り、選択と学習の設計自体が精度に効いている。第2に、保持率30パーセントでも精度低下は小さく、一般枝刈りの崩壊とは対照的であり、差はPosPadによる位置保存と専用の顕著性学習にある。第3に、効率の実測でも時間とメモリの両方が下がり、精度と効率の交換が実測で裏付けられている。評価は4つの位置特定ベンチマークでの実機生成評価である。

### 感度・スケーリング・ストレス条件

保持率を100から10パーセントまで下げた分析では、精度はなだらかに下がり、25パーセントで40.6、10パーセントで36.6（3B、ScreenSpot-Pro、除去実験条件）となった。急落ではなく漸減である点は、保持率を用途に応じて選べることを意味する。悪化条件は小さな対象が多い高解像度画面であり、ScreenSpot-Proのアイコン系カテゴリでは保持率30パーセントで低下が相対的に大きい。動画や複数画面にまたがる時系列の効率化は論文では未評価であり、今後の課題とされている。エネルギー消費も未評価である。

### 評価上の制約

- 対象はQwen系の2系列のみで、符号器や位置埋め込みの方式が異なるモデルへの移植は未検証である。

## 既存研究との差

一般の視覚トークン削減（FastV、VisionZip、HiPrune等）は、自然画像の理解を前提に重要度でトークンを落とす研究であり、位置の連続性は設計対象ではなかった。GUI特化の位置特定（GUI-Actor、UI-TARS、Jedi等）は精度を競うが、全トークンを使う前提で効率は扱わなかった。本論文は、効率化されたUI位置特定という課題自体を立て、落とす対象の学習に画面構造の prior を入れ、落とし方にPosPadを持ち込んだ点が異なる。特にPosPadは、枝刈りの問題を「選択の精度」から「削除後の系列の形」へ広げた提案である。

## 限界・実装状況

論文自身が挙げる限界は、効率化が空間方向の削減にとどまり、UI操作が本来持つ時系列方向、つまり複数回の操作にまたがる冗長さは扱っていない点である。読み手の注意点として、方式は微調整を前提としており、学習なしに既存モデルへ後付けはできない。学習には約100万画面の注釈付きデータとH200を8台使う1エポックの訓練が要る。顕著性の誤りで対象を落とした場合の回復手段はなく、保持率が安全側の調整つまみになる。実装状況としては、プロジェクトページが公開されているが、論文中に公式コードのURLは明示されていない。Qwen2.5-VLとQwen3-VLへの統合が示されており、上流ランタイムへの統合済みとは記述されていない。

## 一般的な実装上の含意

トークンを落とす系の最適化では、落とした後の系列がモデルの位置符号化と矛盾しないかを必ず確認すべきである。位置が答えそのものになる課題では特に、削除は情報の欠落であると同時に座標系の破壊でもある。区間の終端に標識を残すという発想は、間引き一般に応用でき、削除位置の境界情報を最小限のトークンで伝える設計として再利用できる。また、教師信号にドメインの構造 prior（ここでは画面の均一領域）を混ぜると、限られた注釈でも採点器の汎化が安定する。
