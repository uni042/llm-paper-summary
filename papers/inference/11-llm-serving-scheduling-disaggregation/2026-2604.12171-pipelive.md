# PipeLive: Efficient Live In-place Pipeline Parallelism Reconfiguration for Dynamic LLM Serving

> 実行中のKVキャッシュ容量とレイヤー配置を動的に組み替え、差分KV同期で停止を約10msに抑えながら、ワークロードに応じたパイプライン並列構成へ切り替えるLLMサービング方式。

## 概要
PipeLiveは、動的なワークロードや異種GPU環境で最適なパイプライン並列構成が変化しても、推論サービスを停止せずにレイヤー配置を切り替えるサービング機構である。KVキャッシュを実行中に縮小・拡張できる非連続ブロック配置とレイヤースタッキングを導入し、移動中に更新されたKV状態を差分パッチとして継続同期する。これにより、旧構成を動かしたまま新構成の重みとKV状態を準備し、安全な収束点で短時間だけ同期して切り替える。A100 80GBとL40S 48GBの実機評価では、Llama 3-70BとQwen3-30Bの混合ワークロードで静的構成より総合性能を33〜36%改善し、再構成時のサービス停止をおおむね10msまで抑えた。

PipeLiveの中心的な新規性は、パイプライン並列の配置を起動時固定値ではなく実行時に変更できる対象として扱い、メモリ確保、重み移動、KV状態移動、整合性維持を一つの再構成プロトコルへまとめた点にある。PagedAttentionを非連続な物理KVブロックへ直接アクセスできるよう拡張し、複数層のKV領域を一つの物理割当単位へ詰めるレイヤースタッキングでGPUの粗い割当粒度による内部断片化を抑える。さらに仮想機械のライブ移行に似た差分KVパッチを用い、推論継続中に更新されたスロットだけを反復転送して旧構成と新構成の差を縮め、最後の同期停止を短くする。

代表結果として、総合性能値はA100 80GB + L40S 48GB、プリフィル重視とデコード重視を切り替える200要求の混合ワークロードで代表的な静的パイプライン並列構成に対してLlama 3-70Bで36%改善、Qwen3-30Bで33%改善。局面ごとに最適な層配置が異なるため、再起動なしで配置を切り替えることで単一静的配置の妥協を避けられる。
## 問題設定
大規模モデルを複数GPUへ分割するパイプライン並列では、各GPUへ何層を置くかでプリフィルとデコードの性能が大きく変わる。異種GPUでは計算性能とメモリ帯域の強みが異なり、入力が長い処理と出力が長い処理で最適配置が入れ替わる。しかし既存サービング基盤はモデル重みとKVキャッシュを起動時に大きく事前確保するため、配置変更にはサービス再起動が必要になり、数分規模の停止と実行中リクエストの破棄を招く。単純に旧配置と新配置を同時保持しようとしてもGPUメモリに余裕がなく、KVキャッシュを縮める必要がある。さらに既存の連続メモリ配置は実行中の縮小に不向きであり、KV状態を停止して一括コピーすれば長時間止まり、背景コピーだけでは推論中に増えるKV状態との不整合が生じる。
## 新規性
PipeLiveの中心的な新規性は、パイプライン並列の配置を起動時固定値ではなく実行時に変更できる対象として扱い、メモリ確保、重み移動、KV状態移動、整合性維持を一つの再構成プロトコルへまとめた点にある。PagedAttentionを非連続な物理KVブロックへ直接アクセスできるよう拡張し、複数層のKV領域を一つの物理割当単位へ詰めるレイヤースタッキングでGPUの粗い割当粒度による内部断片化を抑える。さらに仮想機械のライブ移行に似た差分KVパッチを用い、推論継続中に更新されたスロットだけを反復転送して旧構成と新構成の差を縮め、最後の同期停止を短くする。
## 手法
### 手法のあらまし
入力は現在のパイプライン並列構成と目標構成である。中央の再構成コーディネータは、各GPUについて現在保持する層と目標で必要な層の和集合を一時構成として作る。これは切替前に旧構成を動かし続けながら、新構成で必要な層を同じGPU群へ追加するためである。次に各GPUの総メモリ、利用可能比率、層当たり重み量、KVページ量から、一時構成でも保持できるKVブロック上限を計算し、全GPUの最小値を共通の縮小先容量とする。現在実際に使用中のKVブロック数がこの値を超える場合は、既存リクエストの状態を失わずに新しい層を置く空間を作れないため、安全に再構成を中止する。実行可能ならKVブロックを詰め直した後、全GPUのKV容量を共通の安全値まで縮小して、新しい層の重みとKV状態を置く物理メモリを確保する。続いて、新構成で追加が必要な層の重みをCPUメモリから非同期に読み込みながら、それらの層に対応する既存KV状態を元GPUから移動先GPUへ送る。この間も推論は旧構成で継続するため、移動開始後にも各リクエストの新しいトークンに対応するKV状態が増え続ける。そこで各移動元は、推論ステップごとに更新された物理KVスロットをダーティビットマップへ記録し、背景送信スレッドが更新集合を原子的に取り出して差分パッチとして繰り返し転送する。受信側は到着したパッチを新しい層のKV領域へ適用し、旧構成と新構成の状態差を徐々に縮める。コーディネータは推論側が最後に処理したトークン位置と、移動先へ反映済みの位置との差を監視する。差が設定しきい値未満まで収束すると短い同期点を設け、最後の残差を転送してから新構成へ原子的に切り替える。切替後は旧構成でのみ必要だった層とKV領域を解放し、新構成の層数から再計算した容量までKVキャッシュを拡張する。このため、停止後に全重みと全KVをコピーする方式と違い、主要なデータ移動を通常推論と重ねられ、利用者から見える停止時間は最後の小さな差分同期へ限定される。

### 動的KV容量変更とレイヤースタッキング
従来のPagedAttentionは論理的にはページ単位でKVを管理する一方、各層の物理KV領域を大きな連続領域として事前確保するため、実行中に一部を返却して新しい重み用の空間へ転用しにくい。PipeLiveは物理メモリをブロック単位で非連続に確保し、注意計算側をその配置へ直接アクセスできるよう拡張する。ただしGPUの最小物理割当単位は個々の論理KVブロックより大きく、層ごとに割り当てるだけでは内部断片化が増える。そこで複数層の同じ位置に対応するKV領域を一つの物理割当へ積み重ねる。これにより小さな論理ブロックをまとめて物理粒度へ近づけ、必要なブロック群を即時に返却・追加できる。スタッキング数を増やし過ぎると層をその単位でしか動かせず配置自由度が落ちるため、評価では4層を既定値としている。

### 差分KVパッチによるライブ移行
KVキャッシュ全体を一度止めてコピーすると移動量に比例してサービス停止が長くなるため、PipeLiveは推論中に大部分を背景転送する。移動元の各GPU対は、推論ステップで書き換えられた物理KVスロットをダーティビットマップへ記録する。送信スレッドはビットマップから更新集合を原子的に取り出してリセットし、該当KVだけを集めて移動先へ送り、受信側が対応する層キャッシュへ反映する。この反復により新旧状態の差を小さくし、最後は未反映トークン数がしきい値未満になった時点で短時間だけ同期して確定する。移動用NCCL通信は推論用とは別の通信グループと低優先度CUDAストリームを使い、推論処理を優先する。

### NCCLデッドロック回避と非同期重み読込み
推論用とKV移動用の二つのNCCL通信グループが同じGPU群で同時に動くと、互いの送受信待ちが循環して停止する可能性がある。PipeLiveはGPUごとの排他制御と二段階の合意手順を用い、移動送信側が排他制御を得てTCPで確認を送り、受信側も排他制御を取得できた場合だけ転送を開始する。取得できなければ拒否して再試行し、推論側の中間活性値転送を優先する。同時に、新構成で必要なモデル重みはCPU側からGPUへ背景で読み込み、KV移動と重ねる。これにより再構成の主要なデータ移動を通常推論の裏で進め、最終切替時に残す作業を減らす。

### 全体のデータ／制御の流れ
中央コーディネータが全GPUの一時構成、KV容量、移動進捗を管理し、各GPUの再構成ワーカーがKV容量変更、重み読込み、KV移動を担当する。安全性は、一時構成を保持できるメモリがあることを開始前に確認すること、全層で共通に利用可能なKVブロック数へ縮小すること、移動差分が収束するまで旧構成を実行し続けること、最後の同期と構成切替を一体化することで確保する。論文は再構成をいつ発火するか、どの目標配置が最適かの上位方策は扱わず、与えられた現在構成から目標構成への安全で低停止な実行機構に範囲を限定する。
## 評価条件
- **ハードウェア**: 異種GPUの実機2ノード構成。NVIDIA A100 80GB（メモリ帯域2039GB/s、FP16/BF16 Tensor Core 624TFLOPS）とNVIDIA L40S 48GB（メモリ帯域864GB/s、FP16/BF16 Tensor Core 733TFLOPS）をInfiniBandで接続し、NCCLによるGPU間通信を使用する。
- **ソフトウェア**: vLLMを基盤にPipeLiveを実装し、2段のパイプライン並列で動的再構成を評価する。KV移動は専用NCCL通信グループと低優先度CUDAストリームを用いる。
- **比較対象**: プリフィル最適の静的PP構成、デコード最適の静的PP構成、両ワークロードを均衡させた静的PP構成、KV容量変更を無効化したPipeLive、KV差分パッチを無効化したPipeLive、非同期重み読込みとKV差分パッチを無効化した同期型変種
A100とL40S上で実行可能なパイプライン並列配置を2層粒度で事前計測し、プリフィル重視とデコード重視それぞれの最適配置を求める。混合ベンチマークではワークロードパターンを切り替え、その都度対応する最適配置へPipeLiveで再構成する。高負荷条件としてLlama 3-70Bは毎秒3要求、Qwen3-30Bは毎秒5要求を用い、静的配置とのエンドツーエンド差を測る。さらにKV容量変更、レイヤースタッキング数、KV差分パッチ、非同期重み読込みを個別に無効化し、各機構の寄与を分離する。
評価は1基のA100と1基のL40Sからなる2段パイプライン並列の実機環境に限定される。異種GPUでワークロード依存の最適配置が変わる状況を強く意識した評価であり、多数GPU、多段パイプライン、同種GPU大規模クラスタ、複数モデル同時運用への一般化は直接測定していない。再構成の発火時刻や最適目標配置を決める上位制御も評価対象外で、既知の目標構成へ安全に切り替える機構を評価している。
## 主要結果
異種GPU上でプリフィル重視とデコード重視のワークロードを交互に与えると、単一の静的パイプライン配置では一方の局面で性能を失う。PipeLiveは局面ごとの最適配置へ実行中に切り替えることで、Llama 3-70BとQwen3-30Bの総合性能をそれぞれ36%と33%改善した。効果は単なる配置変更だけでなく、移行時にKV容量を新配置へ合わせて変えられることと、差分KV同期と非同期重み読込みによって停止時間を約10msへ抑えることから生じる。レイヤースタッキングには、断片化低減と配置自由度の間に明確なトレードオフがあり、4層程度が実験環境では実用的な折衷点だった。

- 総合性能値 / Llama 3-70Bで36%改善、Qwen3-30Bで33%改善 (比較対象: 代表的な静的パイプライン並列構成; 条件: A100 80GB + L40S 48GB、プリフィル重視とデコード重視を切り替える200要求の混合ワークロード) — 局面ごとに最適な層配置が異なるため、再起動なしで配置を切り替えることで単一静的配置の妥協を避けられる。

- TTFTとTPOT / Llama 3-70BでTTFT最大45%改善、TPOT最大61%改善 (比較対象: 均衡型の静的構成; 条件: 高負荷の混合ワークロード) — デコード重視局面でKV圧迫を避けられる配置へ切り替え、KV容量も新配置に合わせて拡張できるため遅延悪化を抑える。

- KV容量変更の効果 / 高負荷でスループット45%以上改善し、最大2.5倍高い要求率までKV過負荷を回避 (比較対象: KV容量変更を無効化した変種; 条件: Llama 3-70Bの混合ワークロード、要求率を増加) — 配置変更後のGPUごとの重み占有量に合わせてKV領域を再配分できるため、固定容量で生じるKV不足を防ぐ。

- 有効KVメモリ利用率 / スタッキングなし56.4%、4層84.9%、16層95.6% (比較対象: レイヤースタッキングなし; 条件: ブロック単位の非連続KV物理割当) — 複数層の小さなKVブロックを同じ物理割当へまとめるほど内部断片化は減るが、過大なスタッキングは配置変更粒度を粗くする。

- 再構成時のサービス停止 / 移動層数4〜16でもおおむね10ms (比較対象: KV差分パッチなし、または差分パッチと非同期重み読込みなし; 条件: 混合ワークロードでレイヤー移動数を変化) — 大部分のKV状態を推論中に背景転送し、最後に残った差分だけを同期するため、停止時間が全移動量に比例しにくい。

- 再構成近傍の遅延 / KV差分パッチ単独でTTFT最大49.7%、TPOT最大29.5%改善。非同期重み読込みも有効化するとTTFT最大72.4%、TPOT最大26.7%改善 (比較対象: 対応機構を無効化した同期型変種; 条件: 移行時刻前後15秒の区間) — 重みとKVの移動を通常推論へ重ねることで、移行に伴う一時的な処理停止と待ちを小さくできる。

### 負の結果・境界条件
- Qwen3-30BではPipeLiveのTTFTが均衡型静的構成より7%悪化する条件があり、配置切替がすべての指標を同時に最良化するわけではない。またレイヤースタッキングを増やし過ぎるとKVメモリ利用率は上がる一方、移動可能な層数の粒度が粗くなって最適配置へ合わせにくくなり、TTFTとTPOTが悪化する。再構成開始時点で現在使用中のKVブロックが一時構成で保持可能な上限を超える場合、方式は安全性のため再構成自体を中止する。

### 結果の読み方
性能向上の主因は、異種GPUの計算能力とメモリ帯域の非対称性に合わせて層配置を変えられる点にある。プリフィルは計算能力、デコードはメモリ帯域とKV容量の影響を強く受けるため、同じ配置を固定すると局面ごとに別の資源が律速する。PipeLiveは配置変更だけでなくKV容量も連動して変更し、移動処理を背景化することで、その理論的な配置利益を長い停止時間で相殺しないようにしている。一方、Qwen3-30Bのようにメモリ圧迫が弱いモデルではTTFTの一部が悪化し、利益の出方はモデル規模と指標によって異なる。
## 品質への影響
モデル重みやKV値を近似・圧縮する方式ではなく、数値精度や生成品質を意図的に変更しない。論文の評価も生成品質ではなく、同一モデルを用いたサービング性能とメモリ効率を対象とするため、品質低下との交換条件ではない。
## 既存研究との差
vLLMやSGLang、DistServe、Llumnixなどはスケジューリング、KV管理、プリフィルとデコードの分離、インスタンス管理を改善するが、基本的には実行レイアウトを固定したまま性能を上げる。PipeLiveはその下のパイプライン並列レイヤー配置そのものを稼働中に変更する。近いHydraServeとFlexPipeは参加GPU集合の変更を扱うが、既存GPU集合内で大きく層を再配置する際のGPUメモリ制約とKV状態移動を同時には扱わない。DynaPipeは末尾段を中心とした限定的な層再分配で、KV移動量とメモリ制約を十分に扱わない。KVcachedのような仮想メモリ方式に対しては、毎推論ステップの仮想物理再対応付けを避け、非連続ブロックへの直接アクセスとレイヤースタッキングで即時のKV領域回収を狙う点が異なる。
## 限界
論文は再構成を実行する機構を扱い、いつ再構成を開始するか、どのパイプライン並列配置を目標に選ぶかは解かない。評価環境もA100とL40Sを各1基用いた2段構成であり、多数GPUや多段パイプライン、同種GPUクラスタ、複数モデル同時運用での拡張性は未評価である。再構成中は旧配置と新配置の層集合を一時的に共存させるため、現在使用中KV量が縮小後の安全容量を超える場合は再構成できない。レイヤースタッキングは断片化を減らすほど配置変更粒度を粗くするため、メモリ効率と適応性にトレードオフが残る。

## 研究上の位置づけ
リポジトリ内では、LLMサービングのスケジューリング・分離実行系統と、KVキャッシュ管理・移動系統をつなぐ論文として位置付けられる。特に異種GPUでの動的資源配置に対し、上位スケジューラが選んだ目標配置を実際に低停止で反映する実行機構を提供する点が重要である。将来的には、負荷予測やSLOに基づく配置選択器、テンソル並列・データ並列との共同再構成、より大規模な異種クラスタ制御と組み合わせる余地がある。
