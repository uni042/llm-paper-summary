# PrefillOnly: An Inference Engine for Prefill-only Workloads in Large Language Model Applications

> PrefillOnlyは、推薦・信用審査・ラベル付けのように「長い入力を読むが出力は1トークンだけ」というプリフィル専用（prefill-only）要求へ通常の生成エンジンをそのまま使う無駄を取り除く。後続デコードで再利用しないキー・バリュー（Key-Value; KV）キャッシュを全層分保持せず、固定出力長から完了時間を予測して要求を並べ替える。2基のL4/A100/H100系構成と2種類の長入力ワークロードで、平均・P99遅延を膨らませず処理可能な毎秒クエリ数を1.4〜4.0倍へ拡大し、単一モデル並列化なしで扱える最大入力長を最大5倍にする。

## 概要

一般的な大規模言語モデル（Large Language Model; LLM）配信エンジンは、入力を一度処理するプリフィルの後に、何十〜何百トークンもの自己回帰デコードが続くことを前提に設計されている。そのため各層で計算したKVキャッシュをGPUメモリへ残し、次の生成ステップで再利用する。ところが推薦、信用審査、分類、データラベル付けでは、長い履歴を読ませても最終出力が「yes/no」「カテゴリ番号」のような1トークンだけで終わる要求がある。PrefillOnlyはこのワークロードを通常生成と別種のものとして扱う。

1トークンで終わるなら、ある層を通過した後、その層のKVを次のデコードステップで参照する機会はない。PrefillOnlyは計算済みKVを全層について保持する通常設計をやめ、現在必要な最小限だけを残す。これにより長入力で支配的になるKVメモリを減らし、テンソル並列（tensor parallelism）やパイプライン並列（pipeline parallelism）で複数GPUへ分散しなければ載らなかった入力を、GPUごとの独立インスタンスで処理しやすくする。

さらに出力長が必ず1なので、通常生成のように「いつEOSへ到達するか」が不明ではない。入力長と校正済み実行時間から要求完了時間（Job Completion Time; JCT）を事前に見積もり、短い残り仕事を先に処理する最短残余処理時間優先（Shortest Remaining Job First; SRJF）型のスケジューリングへ利用できる。メモリ削減と待ち時間削減を同じエンジンで組み合わせるのが論文の中心である。

## 問題設定

プリフィル専用要求では、計算のほぼ全てが入力トークン処理に集中する。論文の例ではLlama-3.1-8B、単一H100、入力2048トークンの場合、出力256トークンの通常生成は出力1トークンの要求より1.5倍遅い。つまり出力が短いだけでなく、エンジン内部の資源構成も通常生成とは異なる。

既存のPagedAttentionはKV領域の断片化を抑えるが、「後続デコードに不要なKVをそもそも持たない」という前提までは使わない。チャンク化プリフィル（chunked prefill）は長い入力を分割して干渉を抑えるが、依然として生成用KV管理を行う。テンソル並列やパイプライン並列は1要求を複数GPUへ分散できる一方、装置間通信を追加する。プリフィル専用ではKV再利用がないため、この通信費用を払ってモデルを跨がせるより、各GPUを独立要求へ割り当てた方が高スループットになる領域がある。

もう一つの問題は待ち行列である。通常の生成では出力長が未知なので、到着した要求の終了時刻を正確に予測しにくい。プリフィル専用なら出力長が固定なので、入力処理時間の校正からJCTをかなり直接的に見積もれる。この情報を使わない先着順では、非常に長いプリフィルが短い要求を後ろで待たせ、P99遅延を悪化させる。

## 手法

### 1. 全層KVを保持しないプリフィル専用メモリ管理

通常デコードでは、第ℓ層のKVは将来トークンが第ℓ層へ来たときに参照するため保存する。PrefillOnlyでは出力トークンを1個計算したら要求が終了するので、既に通過した層のKVを将来再利用しない。そこでGPUメモリに全層分を常駐させず、現在の計算で必要な状態だけを保持する。

入力は長いトークン列、処理は通常のTransformer前向き計算だが、出力は最終1トークンだけである。メモリ管理側は層を進むたび不要になったKV領域を解放・再利用できるため、ピークKV容量が通常生成より小さくなる。効果は演算削減というより「同時に収容できる長入力を増やす」ことに現れる。

この設計は出力が複数トークンなら成立しない。第2トークン以降のデコードでは過去KVが必要であり、捨てた場合は再計算が発生する。したがって要求種別を正しく識別し、通常生成とは別経路へ送ることが前提である。

### 2. 非注意部分のチャンク化で要求を差し込みやすくする

長い入力を丸ごと一つの巨大処理単位にすると、その要求がGPUを長時間占有し、後着の短い要求が待つ。PrefillOnlyはプリフィルを実行可能な単位へ分け、非注意層も含めて長要求を細かく進めることでスケジューラが要求間を切り替えられる余地を作る。

単にチャンクを細かくし過ぎると、カーネル起動やスケジューリングの固定費が増える。論文の設計は、プリフィル専用という出力長固定の性質と組み合わせ、完了までの残仕事を見ながらチャンク実行順を選ぶ。狙いは一要求の最短レイテンシだけではなく、多数要求の平均と裾遅延を同時に抑えることである。

### 3. 固定出力長を利用したJCT予測と短要求優先

PrefillOnlyは入力長ごとの処理時間を校正し、要求到着時点でJCTを推定する。通常生成では出力長予測の誤差が大きな問題になるが、ここでは生成が1トークンで固定なので、主要な不確実性が入力処理側に限定される。

この予測を使って短い残余仕事を先に実行する。短要求を優先すると長要求の飢餓が起き得るため、実装には公平性を調整するパラメータλを持ち、論文評価ではλ=500を既定値にする。つまり純粋な最短ジョブ優先ではなく、待ち時間との均衡を取る制御である。

### 4. 複数GPUではモデル分割より独立インスタンスを優先

モデルが単一GPUへ収まる条件では、PrefillOnlyは複数GPUへ1要求を分割せず、GPUごとに独立した推論インスタンスを置く。同じユーザーの要求は接頭辞キャッシュ（prefix cache）を再利用しやすいよう同じインスタンスへルーティングする。

テンソル並列やパイプライン並列は1要求の遅延を低負荷時に下げる場合がある。しかし高負荷ではGPU間通信と1要求による複数GPU占有のため、同時に処理できる要求数が減る。PrefillOnlyはKVメモリを削ったことで単一GPUでより長い入力を扱えるようにし、GPUを要求並列へ回す。

## 評価

### 評価条件

| 項目 | 設定 |

| 低価格帯GPU | 2×NVIDIA L4 PCIe 24GB、Llama-3.1-8B |
| 中価格帯GPU | 2×NVIDIA A100 PCIe 40GB、DeepSeek-R1-Distill-Qwen-32BのFP8版 |
| 高価格帯GPU | 2×NVIDIA H100 PCIe 80GB、Llama-3.3-70B-InstructのFP8版 |
| 高速接続条件 | 2×NVIDIA H100 80GB、NVLinkあり |
| ワークロード1 | 投稿推薦。20ユーザー、ユーザープロファイル11K〜17Kトークン、投稿150トークン、1ユーザー50要求 |
| ワークロード2 | 信用審査。60ユーザー、入力40K〜60Kトークン、1ユーザー1要求 |
| 到着 | ポアソン過程（Poisson process）で毎秒クエリ数を変化 |
| 比較 | PagedAttention、チャンク化プリフィル、テンソル並列、パイプライン並列 |
| 共通条件 | PrefillOnlyと比較方式の双方で接頭辞キャッシュを有効化 |
| 指標 | 毎秒クエリ数（Queries Per Second; QPS）、平均遅延、P99遅延、処理可能最大入力長 |

### 主な結果

| 観点 | 結果 | 解釈 |
|---|---|---|
| QPS–遅延 | 平均・P99遅延を膨らませず、比較方式より1.4〜4.0倍高いQPSを処理 | KV保持削減とJCT-aware schedulingの両方が効く |
| 最大入力長 | 単一要求をGPU間並列化せず最大5倍へ拡大 | 全層KVを保持しないことでメモリ上限を押し上げる |
| 高負荷 | PrefillOnlyが最小遅延になる傾向 | 通信を伴うモデル並列より要求並列が有利 |
| 低負荷 | テンソル並列などがPrefillOnlyより低遅延になる場合あり | 1要求へ複数GPUを投入できるため。PrefillOnlyが常に最小単発遅延ではない |
| NVLink | 通信集約的なテンソル並列の性能を改善するが、信用審査ではPrefillOnlyが最高スループット | 高速相互接続があってもKVメモリと通信回避の利点が残る |

重要なのは「4倍」が単一の固定設定における万能倍率ではなく、GPU・モデル・ワークロードを跨ぐ最大値である点である。論文の主張は、同程度の平均/P99遅延制約を置いたときに処理可能QPSが1.4〜4.0倍になるという範囲で読むべきである。

### どの機構が効くか

投稿推薦は同一ユーザーのプロファイルを多数要求で共有するため、接頭辞キャッシュ再利用とスケジューリングの効果が出やすい。信用審査は40K〜60Kという長入力で、KVメモリを全層保持しない効果がより直接に現れる。論文が2種類を分けているのは、同じ「1トークン出力」でもボトルネックが異なるためである。

一方、低QPSではテンソル並列の方が単一要求のレイテンシを短くできる条件がある。これはPrefillOnlyの失敗ではなく、目的関数が異なることを示す。要求が疎でGPUが余っている環境では、複数GPUを1要求へ投入する方が合理的な場合がある。

## 既存研究との差

PagedAttentionやチャンク化プリフィルは通常生成を対象とし、出力が将来何トークン続くか分からない前提でKVを管理する。PrefillOnlyはワークロード契約を「出力1トークン」に狭めることで、全層KV保持という通常は不可欠な機構そのものを外す。

テンソル並列・パイプライン並列との差は、長入力を載せるためにモデル計算をGPU間へ分割するのではなく、KVメモリ削減によって単一GPUで収容し、GPU間は要求レベルで並列化する点にある。また固定出力長からJCTを予測し、メモリ管理とスケジューリングを同じワークロード特性から導いている。

## 限界・実装状況

- 出力が1トークンより長い通常生成へそのまま適用できない。KVを捨てると後続デコードで再計算が必要になる。
- 評価ワークロードは投稿推薦と信用審査を模した合成データであり、本番到着分布・入力分布によってQPS倍率は変わる。
- 低負荷では複数GPU並列の方が単一要求レイテンシを短くできる場合がある。
- 同一ユーザーを同一インスタンスへ寄せる接頭辞キャッシュ戦略は、ユーザーごとの負荷偏りが大きい場合にルーティングとの交換条件を生む。
- 公開一次資料で確認できる実装はvLLMを基盤とした研究実装であり、上流vLLMの標準実行モードとして同一機能が提供されることを意味しない。

## 一般的な実装上の含意

LLMサービングでは、モデル名だけでなく「最大出力長が固定か」を要求クラスとして扱う価値がある。出力長1が契約で保証されるなら、通常生成用に残しているKV、メモリ予約、スケジューリング上の不確実性をまとめて削れる。逆に、実際には複数トークンが必要な要求を同じ経路へ混ぜると設計前提が崩れる。

評価では最大入力長、QPS、平均遅延、P99遅延を同時に見る必要がある。単に「KVメモリが減った」だけでは、チャンク化やスケジューラの固定費で遅延が悪化する可能性があるからである。
