# Efficiency and Cost Alignment in Batched LLM Serving via Resource-Fair Scheduling

> 長短要求を同居させたバッチで短い要求まで最大KV量相当の費用を負担する外部性を定式化し、デコード進捗差を制限するISJLを提案。一般のバッチ幅で競争比3/4を保証し、LMSYS再生ではLJFより最大17%高いスループットと21%低い平均遅延を示す。

## 概要
大規模言語モデル（LLM）の連続バッチ推論では、短い要求と長い要求を同じデコードバッチに入れると、注意計算の実行時間がバッチ内で最大のKVキャッシュ量に引きずられ、短い要求が自分のトークン量に見合わない共有計算費用を負担する。本論文はこの現象をバッチ外部性として形式化し、同時実行要求のデコード進捗差をαトークン以内に保つ資源公平性を導入する。提案する短いジョブ制限挿入法（Insert-Short-Jobs-with-Limit; ISJL）は、長い要求を軸に短い要求を公平性制約の範囲だけ組み込み、条件が整った後は空いた実行枠へ要求を連続投入する半静的・イベント駆動の混成方式である。一般のバッチ幅B≥2で最悪時競争比3/4を保証し、出力長予測が不確かな場合にも実進捗で公平性を守るRobust-ISJLへ拡張する。LMSYS-Chat-1Mから抽出した2,000会話を用いるトークン段階シミュレーションでは、B=32でα=150のスループットがLJF比17%高く、α=50の平均エンドツーエンド遅延がLJF比21%低い。実GPU実装の性能評価ではなく、抽象化した計算量モデルとシミュレーションに基づく理論寄りの研究である。

本論文は公平性を待ち時間の均等化ではなく、同時実行要求が消費する資源量の近さとして定義する。時刻tの同時実行集合で最大デコード進捗と最小進捗の差をα以下に制約し、KVキャッシュ占有量のばらつきを直接抑える。その制約下で高いバッチ充填率を維持するISJLを設計し、一般のバッチ幅で3/4の競争比を証明する。さらに予測出力長が区間でしか分からない場合も、実行時の実進捗を公平性判定に使うRobust-ISJLを与える。加えて、最大KV量で決まるバッチ原価を『ワークロード固有費用・時間オーバーヘッド・スケジュール起因外部性』へ分解し、資源公平性がトークン課金と推論原価のずれをどのように抑えるかを示す。

代表結果として、一般Bでの競争比はB≥2、オフラインの待機要求集合で公平性制約下の最適スループットに対して3/4以上。α公平性を課しても、ISJLは最悪の場合でも最適公平スケジュールの75%以上のスループットを維持する。
## 問題設定
連続バッチ推論では、1要求が1トークン進むたびにKVキャッシュが伸びる。異なる進捗の要求を同じバッチへ入れると、注意計算の壁時計時間は各要求のKV量の合計ではなく、概ねバッチ内最大KV量に支配される。全結合層も一定範囲まではバッチ拡大を並列化できるため、短い要求を長い要求と同居させると、短い要求自身の計算量が小さくても長い要求の大きなKV量に対応する段階時間を一緒に支払う。先着順（FCFS）はこの外部性を大きくし、短い要求優先は平均遅延を下げても長い要求を飢餓させ得る。一方、長い要求だけを固定バッチ化すれば公平になるが、短い要求が先に終わった後も空いた枠を使えずスループットを失う。
## 新規性

## 手法
### 手法のあらまし
入力は各要求の総トークン長、または出力長予測区間の上限、最大同時実行数B、資源同質性予算αである。主解析は多くの要求が既に待機している混雑時スナップショットを想定し、各論理サービス段階でバッチ中の各要求を1トークンずつ進める。スケジューラは同時実行中の要求について、生成済みトークン数の最大値と最小値の差がα以下になるようにバッチを構成する。これはKVキャッシュ量のばらつきを抑え、短い要求が長い要求の大きなKVキャッシュによって決まる段階時間を過剰に負担することを防ぐ制約である。ISJLは二つの段階を繰り返す。第1段階では未処理要求を長い順に見て、最長要求と次に長い要求の長さ差およびαから、短い要求をどこまで先行処理・挿入できるかを計算する。短い要求群の累積長が公平性窓を超える場合には一部を単独で先に進め、その後に最長要求と同時実行する。一般のBでは複数の実行枠へ短い要求群を割り当て、各枠の尾部だけを最長要求と重ねることで、同居開始時点の進捗差を制御する。第2段階はイベント駆動で、要求完了により実行枠が空くたびに現在の最大進捗を確認する。最大進捗がα以下なら進捗0の新しい要求を投入しても差がαを超えないため、未処理の最長要求を即座に入れる。最大進捗がαを超えていれば新規投入を止め、残存要求が進んで次の公平な編成を作れる局面まで待つ。この半静的な初期編成と連続投入の組合せによって、完全静的バッチの遊休を減らしながら、無制限な連続投入が生む長短要求の外部性を抑える。出力長が未知の場合はRobust-ISJLが予測区間の上限を並べ替え・群構成に使う一方、公平性の可否は予測値ではなく実際の生成進捗で判定する。そのため予測誤差があっても公平性制約自体は維持されるが、過大予測が大きいほど不必要な保守性が増え、スループット保証は悪化する。

### 資源同質性制約
同時実行集合について、各要求のデコード進捗、すなわち生成済みトークン数の最大値と最小値の差をα以下に保つ。著者は進捗をKVキャッシュ占有量の代理として使う。注意計算の段階時間がバッチ内最大KV量に引きずられる計算制約型の領域では、進捗の小さい要求を進捗の大きい要求と混ぜるほど、短い要求が自分には不要な共有計算時間を負担する。そこでαを小さくすれば同居要求のKV量を近づけ、外部性を直接抑えられる。ただし条件を満たす待機要求が少ないと実行枠を埋められず、スループットが落ちる。したがってαは公平性の強さだけでなく、どこまで異なる長さの要求を同時実行してよいかを決める運用パラメータである。

### 短いジョブ制限挿入法（ISJL）
第1段階では未処理要求を長い順に並べ、最長要求と次に長い要求の差、α、補助閾値から短い要求を挿入できる容量を求める。容量に収まる短い要求を選び、必要ならその一部を単独で先に実行して進捗をそろえた後、最長要求と同じ実行期間へ重ねる。一般のバッチ幅Bでは、最長要求以外の複数枠へ短い要求群を詰め、それぞれの残り部分が最長要求と並行するように構成する。短い要求を無制限に挿入すると長い要求との進捗差が広がる一方、全く挿入しなければ空き枠が増えるため、ISJLはこの挿入量を明示的に制限する。理論解析では過剰挿入と過少挿入の双方を最悪ケースとして評価し、一般Bで競争比3/4を下回らないことを示す。

### 半静的・連続バッチ混成
ISJLは最初から最後まで固定バッチを保つ方式でも、空き枠が出るたび無条件に新要求を入れる方式でもない。第1段階では、公平性制約を満たす初期進捗関係を作るため短い要求群と長い要求の重ね方を半静的に決める。第2段階では要求が完了して枠が空くたびに現在の最大進捗を観測し、それがα以下なら進捗0の新要求を入れても最大差がα以内なので、未処理の最長要求を即座に投入する。最大進捗がαを超える場合は投入を止める。この条件付き連続投入によって、LJFのような固定バッチで発生する遊休時間を回収しつつ、FCFSのように進捗0の短い要求が大きく進んだ長い要求へ無制限に混ざることを防ぐ。

### Robust-ISJL
現実には要求の最終出力長を到着時に正確には知らないため、各要求に下限と上限からなる予測区間がある設定へ拡張する。並べ替え、短い要求群の構成、各枠の容量計算では安全側の上限値を要求サイズの代理として使う。一方、新しい要求を実行集合へ入れてよいかどうかは予測値ではなく、その時点で実際に生成済みのトークン数から計算した最大進捗で判定する。したがって長さ予測が外れてもα公平性そのものは維持される。代償は過大予測による保守的な編成であり、上限と実長の差の総和が大きいほどスループット保証が悪くなる。予測が完全なら誤差項は0となり、元の3/4保証へ戻る。

### 原価分解と課金整合
固定された受理ワークロードでは、トークン単価が線形なら総売上は要求の総トークン数で決まり、スケジュールを変えても同じである。そこで著者は推論原価を、ワークロード自体が必ず必要とする固有項、サービス段階数に比例する時間オーバーヘッド項、最大KV量に引きずられることで余分に生じるバッチ外部性項へ分解する。α公平なスケジュールでは外部性項をαと総トークン量の積で上から抑えられる。ISJLのメイクスパン保証と組み合わせることで、完全に同質なLJFよりどれだけ時間を短縮できるか、外部性の大きいFCFSよりどれだけ原価のずれを抑えられるかを同じ式で比較できる。つまり公平性パラメータαが性能だけでなく、トークン課金と実際のGPU原価の整合度も調整する。

### 全体のデータ／制御の流れ
これは実推論エンジンの実装アーキテクチャではなく、単一worker上のスケジューリング抽象である。待機要求列からISJLが実行集合を決め、各論理段階で各要求を1トークン進める。要求完了で枠が空くと第2段階の投入判定を行い、進捗差がαを超えそうなら新規投入を止めて、残存要求が公平性窓へ入るまで待つ。メモリ容量上限ではなく最大同時実行数Bを主制約とする計算制約型のモデルなので、KV容量が先に尽きる環境、多GPU間移動、プリエンプション費用は直接モデル化しない。
## 評価条件
- **ハードウェア**: 実GPUハードウェアによる計測は行わない。主要評価は論理トークン段階シミュレーションであり、バッチ幅B=16と32を計算資源容量として設定する。
- **ソフトウェア**: 論文中の理論アルゴリズムと数値シミュレーション。vLLM、SGLang等への統合実装は評価しておらず、公式コード公開URLも一次資料から確認できない。
- **比較対象**: 先着順（FCFS）、短いジョブ優先（SJF）、長いジョブ優先（LJF）、公平性制約下の最適解（理論競争比の基準）
理論面では公平性制約下の最適スループットに対する競争比を解析し、B=2の詳細解析から一般B≥2へ拡張する。実証面ではLMSYS-Chat-1Mから2,000会話を無作為抽出し、会話の総トークン数を要求サイズとして固定到着列をシミュレーションする。総トークン長は平均126、中央値90、最大905、分散14938。B=16/32でFCFS、SJF、LJF、ISJL(α=50/100/150)を比較し、スループットと平均エンドツーエンド遅延を測る。利益分析は固定受理ワークロードと外生的な線形トークン課金を仮定し、スケジュール差を推論原価差として評価する。
主理論は全要求が時刻0に存在する混雑時のオフラインスナップショットで、完全なオンライン到着に対する3/4保証ではない。計算制約型の単一workerを対象とし、KV容量が支配するメモリ制約型、多GPU分散、ネットワーク、プリエンプション、実カーネルの非線形段階時間は評価対象外。システム効率評価も実GPU時間ではなく論理段階数である。
## 主要結果
ISJLは一般のバッチ幅B≥2で公平性を守りながら最適公平スケジュールの少なくとも3/4のスループットを保証する。B=2ではβ≈0.78αの設定で下限約0.77まで改善する。LMSYS-Chat-1M再生では比較したFCFS/SJF/LJFをスループットと平均遅延の両方で上回り、αを大きくするとバッチ充填率とスループットが上がり、αを小さくすると要求進捗を揃える力が強くなって平均遅延が下がる。利益分析ではLJFが外部性ゼロの原価整合基準、FCFSが小さいメイクスパンと大きい外部性の極、ISJLがその中間となる。

- 一般Bでの競争比 / 3/4以上 (比較対象: 公平性制約下の最適スループット; 条件: B≥2、オフラインの待機要求集合) — α公平性を課しても、ISJLは最悪の場合でも最適公平スケジュールの75%以上のスループットを維持する。

- B=2での競争比 / 約0.77 (比較対象: 公平性制約下の最適スループット; 条件: β=(√17−1)α/4≈0.78α) — 短い要求をどこまで挿入するかをαに合わせて調整すると、単純な3/4下限より少し強い保証になる。

- B=16 スループット / ISJL α=150: 276 (比較対象: LJF 243 / SJF 196 / FCFS 216; 条件: LMSYS 2,000会話) — LJF比約14%、SJF比約28%高い。公平性を緩めると新規要求を入れやすくなり、バッチ充填率が上がる。

- B=16 平均エンドツーエンド遅延 / ISJL α=50: 53 (比較対象: LJF 66 / SJF 60 / FCFS 62; 条件: LMSYS 2,000会話) — LJF比約20%、SJF比約12%低い。厳しい進捗差制約が長短要求の同居による待ちを抑える。

- B=32 スループット / ISJL α=150: 378 (比較対象: LJF 323 / SJF 259 / FCFS 278; 条件: LMSYS 2,000会話) — LJF比約17%、SJF比約46%高い。

- B=32 平均エンドツーエンド遅延 / ISJL α=50: 62 (比較対象: LJF 78 / SJF 67 / FCFS 70; 条件: LMSYS 2,000会話) — LJF比約21%、SJF比約7%低い。

### 負の結果・境界条件
- αを小さくすれば常にすべての指標が改善するわけではない。α=50は平均遅延が最良だが、スループット最大値はα=150で得られる。完全静的なLJFはバッチ外部性をゼロにできても空いた枠を再利用しにくく、メイクスパンが長くなる。利益評価の基準パラメータでは固定段階オーバーヘッドcが小さいためLJFが高利益になり、ISJL α=50がLJFを利益で上回るのはc>0.0162の領域とされる。また大規模な待機要求プールがあり、長さが近い要求を容易にクラスタ化できる場合は、初期バッチ形成における本手法の優位性が小さくなる可能性を著者自身が指摘する。

### 結果の読み方
本論文の中心的な結果は、スループットを落として公平性を得る単純な二者択一ではない。要求の進捗差を直接制限しつつ、公平性が許す瞬間だけ連続バッチ投入を再開することで、比較対象ではスループットと平均遅延を同時に改善できる。ただし評価は抽象段階モデルなので、実GPU上の段階時間が最大KV量にどの程度比例するか、プリフィルやカーネル融合がどの程度影響するかは別途検証が必要である。
## 品質への影響
生成内容を近似しないため出力品質の劣化は想定されない。トレードオフは品質ではなく、資源公平性、バッチ充填率、遅延、推論原価の間に生じる。
## 既存研究との差
Fairness in Serving Large Language ModelsやEnsuring Fair LLM Serving amid Diverse Applicationsなどがサービス量・待ち時間の公平性を中心に扱うのに対し、本論文は同じGPUバッチ内で誰のKV量が共有計算費用を決めるかという資源消費の公平性を主対象にする。vLLM/PagedAttention、Sarathi-Serve等はKV管理やプリフィル・デコード混載を実装面から効率化するが、本論文はそれらの上に載り得るバッチ構成規則を理論解析する。KV容量制約を直接扱うOnline スケジューラ for LLM Inference with KV キャッシュ Constraintsとは、主制約が総KV容量ではなく最大同時実行数Bである点が異なる。
## 限界
主理論は全要求が同時に待機するオフラインのスナップショットであり、到着が敵対的な完全オンライン環境へ3/4保証をそのまま持ち込めない。要求総トークン長を既知とする主解析も現実には成立しにくく、Robust-ISJLで予測不確実性を扱うが、予測誤差が大きいほど性能保証は弱くなる。計算制約型の単一workerモデルなので、KVキャッシュ容量が先に上限へ達するメモリ制約型環境、複数GPU間の移動、KV再配置、プリエンプション、ネットワーク費用は含まれない。主要評価は実GPUではなくトークン段階シミュレーションで、最大KV進捗が壁時計費用を十分表すかの実機校正がない。利益モデルでは受理済み需要を固定し、遅延が将来需要や支払意思へ与える影響を扱わない。待機プールが非常に大きい多サーバ環境では長さの近い要求を単純にまとめやすくなり、本方式の初期バッチ形成上の差が縮む可能性がある。

arXiv v1の理論・数値研究。著者はISJL、Robust-ISJL、整数計画による最適解比較、LMSYSを用いたシミュレーションを記述するが、一次資料から公式公開コードやvLLM/SGLang統合実装は確認できない。
## 研究上の位置づけ
LLMサービングのスケジューリングを、単なる待ち時間最小化ではなく『トークン課金は各要求に加算的なのに、実際のバッチ原価は最大KV量で非加算的に決まる』という原価整合問題として扱う点に価値がある。長さ予測、KVキャッシュ管理、連続バッチ制御と組み合わせる際に、要求間の進捗差を追加制約として入れる理論的根拠を与える。実システムへ導入するなら、αを固定トークン差ではなく実測GPU時間・KVバイト・SLOへ校正することが次の課題になる。
