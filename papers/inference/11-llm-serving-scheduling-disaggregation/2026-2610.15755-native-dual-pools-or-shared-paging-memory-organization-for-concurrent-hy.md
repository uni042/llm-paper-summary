# Native Dual Pools or Shared Paging? Memory Organization for Concurrent Hybrid LLM Serving

> ハイブリッドモデルの再帰チェックポイント内部をページ化し畳み込み状態を詰め込む共有プール改良と、種別別ネイティブプールの二択を実機で比較し、改良段の利得と、優劣が予算・負荷・受付方針で反転する条件を測定した研究。

## 概要

注意機構（アテンション）と状態空間モデル（State Space Model; SSM）を組み合わせたハイブリッドモデルをサービングすると、GPUメモリの中身が一様でなくなる。注意機構のKVキャッシュは保持するトークン履歴とともに伸び続けるのに対し、SSMの再帰状態と畳み込み状態はモデル構成で決まる固定サイズであり、しかも過去位置から再開するには、その位置で保存された再帰チェックポイントが丸ごと有効でなければならない。プレフィックスを再利用できるのは、注意状態と完全な再帰チェックポイントが同じ入力位置でそろって有効なときだけであり、チェックポイントの物理表現が、そのまま保存効率と再開点の生存を決める。

本論文はこの物理表現そのものを実験対象にし、改変したvLLMへ4通りのメモリ組織を実装する。S0は全状態を1,557KiBの粗い共有ページへ入れる基準方式、S1は再帰チェックポイントの内部を512KiBのメンバーページへ割り、再帰カーネルがページマッピングを直接たどる方式、S2は21KiBの畳み込み状態を32KiBスロットへ16個ずつ詰めてスラブを共有する方式、D0は注意用16KiB単位と再帰用1,557KiB複合体を起動時に固定分割した別々のプールへ置くネイティブ二重プールである。評価はFalcon-H1-7B-InstructをA100 40GB 1台で動かし、9つの評価質問で保存費用とサービング挙動を追う。

**代表結果:** 主負荷である3リクエスト毎秒・共通プレフィックスありの条件では、S0からS1への段でスループットがメモリ予算別に51.8、47.6、56.2パーセント増え、S1からS2への段でさらに8.9、12.6、10.0パーセント増えた（全段で多重比較補正後も有意）。一方、完成形同士のS2とD0は、予算が小さい側ではD0が4.98パーセント速く、大きい側ではS2が12.56パーセント速いという反転を示し、どちらが良いかは物理組織だけでなく受付方針まで含めて決まることが示された。

## 問題設定

PagedAttentionは論理KVブロックと物理割当を分離してKVの断片化と重複を減らしたが、ハイブリッドモデルでは事情が異なる。再帰チェックポイントは代表形状でSSM状態1,536KiBと畳み込み状態21KiBからなる約1,557KiBの複合体であり、512トークン分の注意ブロックはKVペイロードが512KiBしかない。両者を同じ1,557KiBページへ入れると、注意ブロック1個ごとに1,045KiBが未使用のまま残る。逆にページを細かくすると、チェックポイントは複数の物理ページへ散らばり、どれか1つでも再割当されればチェックポイント全体が無効になるため、参照管理と無効化の仕事が増える。さらに畳み込み状態のように極端に小さい部品は、専用ページを与えると割当の無駄が支配的になる。

もう一つの論点は容量の効き方である。本論文は固定予算の下で支えられる有用な状態の量を実効状態容量と呼び、割当容量の代理指標として、論理的な状態の混合に対する物理割当量で予算を割った値を用いる。共有ページを細かくすれば割当内の無駄は減るが、静的プール方式では片方のプールが満杯でも他方に空きがあれば使えないという実現可能性の制約が残る。つまり物理組織の良し悪しは、保存費用だけでなく、実行時に再利用可能なチェックポイントがどれだけ生き残るかまで含めて測る必要がある。これが、保存費用の式とサービング実験を同じ論文で扱う理由である。

## 手法のあらまし

4方式は共通の規則を土台にする。再利用は注意・SSM・畳み込みの全状態が共通境界で有効なときだけ成立し、実行中のリクエストが参照する記憶は保護され、最後の実行参照が外れた後も論理エントリはキャッシュとして残るが、裏付けページを再割当するときはそのエントリを無効化しなければならない。S0はこの規則を粗い単一ページで素直に実装した基準である。S1は論理境界を512トークンに保ったまま、チェックポイント内部だけをページ化し、再帰カーネルへ物理メンバーページの対応表を直接渡すことで、デコードのたびにチェックポイント全体を連続領域へ再構成する作業をなくす。S2はS1の上に畳み込みスロットの詰め込みを足し、スラブとスロットの位置をカーネルが直接参照する。D0だけは別の完成形で、注意は16トークン単位、チェックポイントは1,792トークン間隔のネイティブ複合体とし、プール分割は起動時に固定する。後半の実験では、S2の物理表現を保ったまま、需要のあったチェックポイントの生産側寿命を延ばす保持策も検証する。

## 手法

### 1. S0 — 粗い共有ページという基準点

S0が観測するのは512トークン境界ごとの注意ブロックと再帰チェックポイントであり、保持する状態はどちらも1,557KiBの共有ページ1枚である。チェックポイントは1,536KiBのSSMペイロードと21KiBの畳み込み状態でほぼページを埋めるが、注意ブロックは512KiBしか使わず1,045KiBが余る。境界を越えるとき、ランタイムは以前の状態を読み、次の状態を別のページへ計算し、前のチェックポイントは元のページに残す。キャッシュされたエントリは裏付けページが再割当されるまで発見可能であり、その時点で無効化される。減るボトルネックは管理の単純さだけであり、追加費用は小さい対象への大きな内部無駄である。割当量は注意対象数とチェックポイント数の合計に1,557KiBを掛けたものになり、状態の混合比が注意寄りになるほど無駄が支配的になる。

### 2. S1 — チェックポイント内部のページ化とカーネルの直接参照

S1は割当単位だけを細かくする。注意ブロックは512KiBページ1枚、チェックポイントは512KiBのSSMメンバーページ3枚と畳み込み専用ページ1枚の計2,048KiBで表す。保持する状態は論理チェックポイントと物理ページの対応表であり、参照は全メンバーが有効なときだけ成功し、どれか1枚でも再割当されればチェックポイント全体が無効になる。核心は実行経路で、再帰カーネルが境界ごとのページマッピング、ページ間ストライド、メンバー内オフセットからアドレスを直接計算するため、デコードステップごとにチェックポイントを連続領域へ集め直すコピーが消える。チャンク分割プリフィルや回復プリフィルでは初期チェックポイントを連続アリーナへ集める場合があるが、通常のデコードは対応表をたどる。これにより減るボトルネックは注意ブロック側の内部無駄と再構成コピーであり、割当量は注意1件あたり1,557KiBから512KiBへ減る。追加費用はチェックポイント側で、1件あたり1,557KiBから2,048KiBへ増える。したがってS1が総割当を減らすのは、注意側の節約1件あたり1,045KiBが、チェックポイント側の増加1件あたり491KiBを、混合比の重み付きで上回るときだけであり、論文はこの損益分岐を式として明示している。

### 3. S2 — 畳み込み状態のスラブ詰め込み

S2はS1のSSMページ化を保ち、残った畳み込み専用ページの無駄を取り除く。21KiBの畳み込み状態は32KiBスロット1つへ入り、512KiBスラブ1枚に16スロットが並ぶ。カーネルはスラブページ番号とスロット番号から作る行識別子と32KiBのストライドを直接使い、ステップごとに連続した畳み込みバッファを再構成しない。畳み込み状態が存在しないことは明示的な無効センチネルで表し、ページ0や負オフセットへの誤った別名付けを防ぐ。減るボトルネックは小さい部品への専用ページ割当であり、割当量は注意512KiB×件数、SSM 1,536KiB×チェックポイント数、スラブ512KiB×枚数の和になる。追加費用は寿命の結合である。1枚のスラブを複数のチェックポイントが共有するため、スラブを再割当する前に、そのスロットを使う全キャッシュ済みチェックポイントを無効化しなければならない。割当履歴によって部分的にしか埋まっていないスラブが残ると、節約量は理論下限より小さくなる。

### 4. D0 — ネイティブ単位の静的二重プール

D0は共有プールの改良段とは別の完成形で、状態種別ごとに本来の単位を使う。注意は16トークン・16KiB単位、再帰チェックポイントは1,792トークン間隔の1,557KiB連続複合体で、どちらも起動時に容量を固定された専用プールから取る。観測するのは種別ごとのプール残量であり、処理は各プール内でのみ割当を判断することである。減るボトルネックは粗いページの内部無駄とページ丸めの両方だが、追加費用は柔軟性の喪失である。合計容量が足りていても、注意プールか再帰プールのどちらか一方が上限へ達すれば、その状態混合は実現不可能になる。チェックポイント間隔も512トークンではなく1,792トークンと粗いため、再開点の粒度そのものがS2と異なる。したがってS2とD0の比較は、割当単位だけでなく、チェックポイント格子とプール実現可能性の検査まで含めた組織全体の比較として読む必要がある。

### 5. 生産側保持 — チェックポイント寿命の延長

後半の機構は物理表現ではなく寿命を変える。S2+保持では、生成元リクエストの実行中に、相異なる2リクエストから需要があった512トークンチェックポイントを解放対象から外し、完了やプリエンプションの後に通常のキャッシュと固定の規則へ戻す。保持する状態は需要しきい値を満たしたチェックポイントの集合であり、狙いは、注意プレフィックスが届く範囲内に完全な再帰チェックポイントが残っている確率を上げることである。追加費用は、保持されたチェックポイントが固定ページ予算を占有し続けることであり、再利用されないまま残れば通常キャッシュの容量を圧迫する。誤った場合の挙動として、リクエスト間で再利用が起きない分離条件では利得が消えるはずだという予測を立て、共有条件と分離条件を交差させた確認実験で検証している。

|---|---|---|---|---|
| S0 | 512トークン境界の全状態 | 1,557KiB共有ページへ一律に配置 | 管理の単純さ | 注意ブロックで1,045KiBの無駄 |

## 評価

結論は2つに分かれる。共有プールの改良段S0からS1、S2は、主負荷では保存と実行の両方を改善する一方向の改良である。対して完成形同士のS2とD0に普遍的な優劣はなく、予算・負荷・受付余裕の組み合わせで順位が入れ替わる。さらに状態トレースは、テストしたS2の実行では再利用の深さを決めていたのが注意側ではなく再帰チェックポイントの在庫だったことを示し、物理表現の議論を寿命と受付の方針へ接続した。

速度面では、主負荷の段階利得が大きい。3リクエスト毎秒・共通プレフィックスありでは、S1化の利得が予算b63、b83、b108で51.8、47.6、56.2パーセント、S2化の追加利得が8.9、12.6、10.0パーセントで、全段が多重比較補正後も区別可能だった。低負荷0.8リクエスト毎秒では3方式とも約190トークン毎秒で並ぶが、末尾遅延に差が出る。b63ではS0のTTFT p99が平均3.687秒なのに対しS1が0.578秒、S2が0.686秒で、待ちリクエストの標本最大値もS0の3〜5件に対してS1は0件だった。読み方として、段の利得はスループットが飽和する負荷で大きく、軽い負荷では待ち行列の解消として現れる。

仕事量の内訳も利得の理由を裏づける。b63・3リクエスト毎秒では、記録された初期入力トークンが実行あたり約766kから612kへ減り、待ちリクエストの中央値は78.8から25.7へ、実行中リクエストの中央値は6.7から17.0へ動いた。b108・4.5リクエスト毎秒でも初期入力は約698kから430kへ減る。ただし共有なし対照では、記録された入力仕事もプリエンプションも3方式で同一にもかかわらず、スループットが293.8、405.4、415.9トークン毎秒と段階的に上がった。つまり利得の一部は入力仕事の削減では説明できず、割当と実行経路そのものの改善が残る。共通プレフィックスの割合を0から1へ上げると段階利得は約10ポイント強まり、再利用機会が多いほど物理表現の差が効くことも確認された。

予算と負荷の軸では順位が反転する。受付余裕ゼロ・3リクエスト毎秒でのD0対S2の平均差は、b63で+4.98パーセント、b83で−1.73パーセント（結論なし）、b108で−12.56パーセントだった。負荷を上げると、b108の4.5リクエスト毎秒では差が−5.97パーセントへ縮み、S2の相対優位は負荷が高いほど小さくなる。受付余裕の実験では、事前に選んだ余裕値でS2がb63で13.61パーセント、b83で18.81パーセント自方式比で伸び、D0の伸びは2.86、2.50パーセントにとどまった結果、事前選択値同士では全予算でS2が上になった。物理組織の選択と受付方針は独立には決められない、というのがこの一連の結果の読み方である。

寿命の実験では、注意プレフィックス内で使える最深のチェックポイントが、全セルで利用可能な再帰チェックポイントの深さと一致し、再帰側の供給が共同再利用を律速していた。同じ254ページ予算で生産側保持を入れると、採用される共同深さはシード別に約703、1,439、1,092トークン毎リクエスト増え、注意側の可用性の増加（約51、123、72トークン）を大きく上回った。新シードの確認実験では、保持の交互作用の主分析が+14.3パーセント（95パーセント信頼区間は−0.1から+30.8）で区間にゼロを含み統計的には未確定である一方、共有条件の副次効果は+15.3パーセント（同+0.8から+31.8）、分離条件では+0.8パーセントだった。保持は有望だが確定ではない、という著者らの慎重な結論をそのまま受け取るべき結果である。

## 既存研究との差

PagedAttentionやvAttentionがKVブロックの物理管理を扱い、SGLangのRadixAttentionがプレフィックス木キャッシュと順序付けを扱うのに対し、本論文はページ化を再帰チェックポイントの内部へ持ち込み、メンバーページの対応表を再帰カーネルへ直接渡す点が異なる。ハイブリッド向けのMarconiがチェックポイントの受付と追い出しを、Sparse Prefix Cachingが論理チェックポイント位置の選択を、Jengaが異種割当と層別キャッシュを扱うのに対し、本論文は論理位置を固定したまま物理表現とカーネルアクセスを変え、その効果を保存費用の式と実測の両方で追う。受付余裕の実験は、OrcaやSarathi-Serveのスケジューリング研究とは別に、メモリ組織と受付方針の相互作用を組織比較の内部で測った点に位置づけられる。

## 限界・実装状況

限界は、対象がFalcon-H1-7B-InstructとA100 40GBに限られること、予算がプランナー照合の名目値で実効使用可能容量をそろえた比較ではないこと、保持状態による継続の正確性が未解決で、保持経路と独立再計算の出力差異の原因が特定されていないことである。S2のスラブ共有は、再割当前に依存する全チェックポイントを無効化する依存追跡を恒常的に必要とし、この管理費用は組織の一部として数える必要がある。実装状況は、著者らによるvLLM V1の改変実装で評価されており、上流への統合や公式コード公開は論文中に示されていない。補足付録に実行の同一性、統計手順、正しさの証拠条件が記録されているが、一部の過去実行には正確なコミットや生記録が残っていない。

## 一般的な実装上の含意

異種状態を持つサービングでは、割当単位の無駄を減らす物理表現の改良と、再利用可能な状態が生き残るかは別の問題であり、保存費用の式だけでも実測だけでも片方しか見えない。特に共同再利用では、最も供給が細い状態種別が再開深さを決めるため、注意側の可用性だけでなく再帰側の在庫を計測対象に含めるべきである。また、メモリ組織の優劣が受付余裕で反転する以上、組織の選択は受付方針とセットで評価し、事前に選んだ方針値で独立シードの確認を取る手順が有効である。
