# SMetric: Rethink LLM Scheduling for Serving Agents with Balanced Session-centric Scheduling

> セッションの初回だけ負荷分散し、後続要求はKV局所性を優先しつつ過負荷・キャッシュ消失時だけ再配置することで、エージェント配信のクラスタTPSを10〜16%改善する。

- **実装**: vLLM v0.12.0を基盤に、LMCacheとMooncakeを用いるグローバルKV層を組み合わせて実装。論文はSMetricと本番トレースを正式公開時にオープンソース化すると述べるが、2026-09-14時点のv1一次資料では恒久的な公式コードURLは確認できない。
## 概要
エージェント型LLMでは、一つの利用者セッションが何度も追加入力を送り、以前の会話履歴を再利用するため、KVキャッシュの局所性が通常チャットより非常に高い。BAILIANの本番トレースでは入力トークンの約81〜82%が再利用可能で、その約3分の2が同一セッション内の後続要求に由来する。一方、既存のキャッシュ優先ルーティングは最初に選んだGPUへ後続要求をほぼ固定し、長く重いセッションが一部インスタンスを過負荷にする。SMetricはセッションの最初の要求だけを純粋な負荷分散で配置し、後続要求は原則としてKV命中が最大のインスタンスへ戻す。これにより最初の一回でセッションを均等にばらまき、その後は高い局所再利用を維持する。さらに対象インスタンスが平均負荷を大きく超える場合や、セッションKVが実質的に追い出された場合は負荷分散へ戻して長大セッションを移行する。H20×32 GPUと本番由来トレースで、プリフィル・デコード同居構成のクラスタTPSを最良比較方式より10〜16%、分離構成のプリフィルTPSを2〜34%改善する。

SMetricは、セッションの最初の要求だけを局所性から切り離して最小負荷インスタンスへ配置し、その決定を後続ターンの自然な固定点として利用する。後続要求はローカルKV命中が最大のインスタンスへ戻すため、初回配置でセッション数を平準化しながら高いセッション内再利用を保てる。さらに、固定先が平均負荷を大きく超えた場合と、期待される会話履歴に比べ実際のKV命中が少なくキャッシュ消失が疑われる場合だけ負荷分散へ戻す。ルータは明示的なセッション表を持たず、通常APIに含まれる会話履歴から初回か後続かを判定する。

代表結果として、同居構成のSLO内クラスタTPSはQwen3-Coder-30B-A3B、グローバルKV容量を掃引でBAILIAN / LMetric / Load Balanceに対して最良比較方式比+10〜16%。初回要求を均等配置し、後続だけをKV局所性へ戻すことでキャッシュ命中と負荷均衡を両立する。
## 問題設定
エージェント型LLMの要求は、同じセッションでツール実行と追加入力を繰り返すため、直前までの長い会話履歴を後続要求が何度も共有する。BAILIAN本番トレースでは入力の81〜82%が再利用可能で、再利用の約3分の2が同一セッション内に集中する。このためKVキャッシュ命中を最大化するルーティングは一見有利だが、最初に偶然選ばれたインスタンスへ重いセッションを固定し続け、セッション長の偏りによって一部GPUだけが過負荷になる。純粋な負荷分散は逆にローカルKVをほぼ捨て、グローバルKV層や再計算へ負荷を移す。要求単位で局所性と負荷を混ぜる既存指標も、長いセッションが作る時間的な固定関係を十分扱えない。
## 新規性
SMetricは、セッションの最初の要求だけを局所性から切り離して最小負荷インスタンスへ配置し、その決定を後続ターンの自然な固定点として利用する。後続要求はローカルKV命中が最大のインスタンスへ戻すため、初回配置でセッション数を平準化しながら高いセッション内再利用を保てる。さらに、固定先が平均負荷を大きく超えた場合と、期待される会話履歴に比べ実際のKV命中が少なくキャッシュ消失が疑われる場合だけ負荷分散へ戻す。ルータは明示的なセッション表を持たず、通常APIに含まれる会話履歴から初回か後続かを判定する。
## 手法
### 手法のあらまし
ルータは要求ごとに各インスタンスのローカルKV命中長と負荷を取得する。プリフィル・デコード同居構成では負荷を処理中要求数、分離構成ではまだプリフィルされていないトークン数で表す。会話履歴から初回ターンと判定した場合はKV命中を無視し、最小負荷インスタンスへ送る。これがそのセッションの最初の配置点となる。後続ターンでは最大KV命中を持つインスタンスを候補にし、通常は同じ場所へ戻すため、長い履歴の再利用をローカルHBM上で継続できる。候補の負荷がクラスタ平均の一定倍を超えていないかを確認し、超える場合は長大セッションの固定による偏りと判断して最小負荷側へ移す。さらに要求内の過去メッセージ数から本来命中するはずの履歴量を推定し、実命中が一定比率を下回る場合はローカルKVが既に追い出されたと判断して固定を解除する。別インスタンスへ移る場合も共有システムプロンプトや過去KVをグローバルKV層から取得できる。したがって初回は負荷均衡、通常の後続は局所性優先、異常時だけ再均衡という三段階で動く。要求が完了すると既存の推論基盤が通常どおりKVを管理し、SMetric専用のセッション表や終了通知は不要である。これによりルータの判断は各要求時点の命中量と負荷だけで完結し、セッション数が多い本番環境でも状態同期を増やさず適用できる。

### 初回ターンだけの純粋な負荷分散
SMetricはセッションの最初の要求を、ローカルKV命中率ではなく現在負荷だけで配置する。エージェント負荷では後続要求が最初の要求の長い履歴を引き継ぐため、初回配置はその後数十〜数百秒のセッション居場所をほぼ決める。したがって毎要求で局所性と負荷を細かく調整するより、セッション開始時に重い将来負荷の種をクラスタ全体へ均等に撒く方が安定する。初回要求に共通システムプロンプトがある場合はグローバルKV層から取得できるため、負荷分散しても共有接頭辞の再利用を完全には失わない。これにより後続の高いローカルKV命中を維持する土台を、追加のセッション状態管理なしで作る。

### 後続ターンのセッション局所性維持
初回以外の要求では各インスタンスのKV命中長を比較し、最も長く命中するインスタンスを優先する。BAILIANでは再利用可能入力の約3分の2が同一セッションの後続ターンに由来し、約90%の再利用が100秒以内に起きるため、直前まで処理していたGPUへ戻す価値が高い。SMetricはこの特性を利用し、初回だけ負荷分散した後は同一セッションを原則同じインスタンスへ戻す。ルータ側に永続的なセッション表を作らず、要求に含まれる過去メッセージからターン番号を推定するので、セッション終了時のガベージコレクションや状態同期を追加しない。履歴を送らないエージェントはそもそもKV再利用できないため、新規セッション扱いでも整合する。

### 過負荷を検知する固定解除
セッションを固定し続けるだけでは、極端に長い会話や生成量の多い利用者が一台を占有する可能性が残る。そこで最大KV命中インスタンスの現在負荷をクラスタ平均と比較し、既定では平均の約2倍を超えるような過負荷状態なら局所性を捨てて最小負荷インスタンスへ送る。これは毎回の負荷差へ敏感に反応するのではなく、明確な偏りが発生したときだけ長いセッションを移す安全弁である。閾値を1から無限大まで変える感度評価でもTPSと再利用率の変化は小さく、初回配置による基本的な均衡が効いているため、この条件は頻繁な移行を起こさず尾部遅延の悪化を抑える役割を持つ。

### KV消失を検知する固定解除
最大命中インスタンスが以前のセッション担当だったとしても、メモリ圧迫で履歴KVが追い出されていれば、そこへ戻る意味はない。SMetricは要求に含まれる会話履歴から、最新ターンを除いた過去部分が本来どの程度KV命中するはずかを見積もる。実際の最大命中長がその期待量の一定割合を下回る場合、セッションKVが失われたと判断して最小負荷インスタンスへ再配置する。これにより古い親和性情報へ固執せず、キャッシュ消失を新しい負荷分散機会として利用する。閾値を広く変えてもTPSは4%以内、全体KV再利用率は75〜76%程度に保たれ、局所性を大きく失わず再均衡できる。

### 全体のデータ／制御の流れ
ルータは既存推論基盤が提供する各インスタンスのKV命中情報と負荷統計だけを利用し、セッション状態を別DBへ保存しない。ローカルHBMのKVキャッシュを第一層、LMCacheとMooncakeによるCPUメモリ上のRDMA共有KVを第二層として使う。プリフィル・デコード同居構成と分離構成の両方で同じセッション中心の判断を使い、負荷指標だけを構成に応じて切り替える。
## 評価条件
- **ハードウェア**: 4台のサーバーに各NVIDIA H20 GPU 8基を搭載し、合計32 GPUを使用する。各GPUは96GB HBM3、各サーバーは160 CPUコアと1280GB DRAMを持ち、サーバー間は200 Gbps RDMAで接続する。ルータは別の64コアCPU・256GB DRAMサーバーで動かす。
- **ソフトウェア**: vLLM v0.12.0を基盤にし、グローバルKV層としてLMCacheとMooncakeを利用する。グローバル層は200 Gbps RDMAで接続されたCPUメモリを用いる。プリフィル・デコード同居構成と分離構成の両方を評価し、分離構成ではプリフィル側の負荷を未処理トークン量で測る。
- **比較対象**: Load Balance、LMetric、BAILIAN production スケジューラ
Alibaba BAILIANの商用コーディングエージェントから、2026年5月29日10:00〜12:00のピーク時間帯に取得した2種類の本番トレースを分析する。Trace1はTB級で人気のモデル、Trace2は約280Bモデルのクラスタから得られ、いずれも少なくとも数千アクセラレータ規模で運用される。性能評価ではTrace1を対象負荷へ標本化して再生し、記録された生成長に合わせて応答を生成した後、後続要求中の応答部分を書き換えて元トレースのKV再利用形態を維持する。モデルはQwen3-Coder-30B-A3Bを単一GPU×32インスタンス、Qwen3-235B-A22B-FP8を4GPU×8インスタンスで評価する。比較方式は純粋負荷分散、LMetric、BAILIAN本番スケジューラ。グローバルKV容量をローカルKV容量の0、0.4、0.8、1.6、3.2倍に変え、到着負荷も掃引する。
実機32 H20 GPUでの評価で、商用本番トレースを利用する点は強いが、性能再生は主にTrace1で行い、モデルもQwen3系MoEの2種類に限られる。両トレースは同じ商用コーディングエージェント製品に由来し、検索・ブラウザ操作・音声など他のエージェント負荷への一般化は未検証。クラスタ間の広域スケジューリングは対象外である。
## 主要結果
プリフィル・デコード同居構成では、グローバルKV層を利用できる条件でSMetricは最良比較方式よりSLO内クラスタTPSを10〜16%改善する。グローバルKV層がない場合はBAILIANとの差が1%以内まで縮み、初回負荷分散と共有接頭辞のグローバル再利用が組み合わさることが主な利得源だと分かる。Qwen3-235Bではピーク有効TPS 516 tok/sでBAILIANより8%高い。プリフィル・デコード分離構成では、グローバルKV容量全域で最強比較方式よりプリフィルTPSを2〜34%改善する。局所KV命中率をBAILIANとほぼ同等に保ちながら負荷偏りを減らし、TTFTとTPOTの尾部も改善する。

- 同居構成のSLO内クラスタTPS / 最良比較方式比+10〜16% (比較対象: BAILIAN / LMetric / Load Balance; 条件: Qwen3-Coder-30B-A3B、グローバルKV容量を掃引) — 初回要求を均等配置し、後続だけをKV局所性へ戻すことでキャッシュ命中と負荷均衡を両立する。

- グローバルKVなしのTPS / BAILIANとの差1%以内 (比較対象: BAILIAN; 条件: global tier=0) — 初回負荷分散では共有システム接頭辞のローカル命中を失うため、グローバルKV層が主要改善を引き出す。

- Qwen3-235Bピーク有効TPS / 516 tok/s、BAILIAN比+8%、同一運転点のLMetric比+20% (比較対象: BAILIAN / LMetric; 条件: 4GPU×8インスタンス) — より大きいモデルでもセッション単位の初回均衡が有効で、重いセッションの固定偏りを抑える。

- 分離構成のプリフィルTPS / 最強比較方式比+2〜34% (比較対象: BAILIAN / LMetric / Load Balance; 条件: Qwen3-Coder-30B-A3B、32 プリフィル instances) — 未プリフィルトークン量を負荷指標に切り替えても同じセッション中心方針が機能する。

- 同居構成のローカルKV命中率 / SMetric約64%、BAILIAN約65%、全体再利用約76% (比較対象: BAILIAN; 条件: グローバルKV十分) — 負荷分散を導入しても後続セッションを固定するため局所再利用をほぼ失わない。

- 負荷偏り / 最大/平均負荷比2.6×、BAILIAN 3.0×、LMetric 3.2×、負荷分散2.0× (比較対象: BAILIAN / LMetric / Load Balance; 条件: Qwen3-Coder-30B-A3B) — 純粋負荷分散ほど均一ではないが、キャッシュ優先方式の偏りを明確に緩和する。

- 同居構成TTFT / 中央値1.1s、BAILIAN比17%低下 (比較対象: BAILIAN; 条件: Qwen3-Coder-30B-A3B) — キュー偏りを減らすことでキャッシュ局所性を維持しながら最初のトークン待ちを短縮する。

- 同居構成TPOT / P50/P90が各最良比較方式より10%/20%低い (比較対象: 各percentileの最良比較方式; 条件: Qwen3-Coder-30B-A3B) — 過負荷インスタンスへのセッション集中を抑える効果が継続生成にも現れる。

- 分離構成TTFT / 中央値1.1s vs BAILIAN 1.8sで37%低下、P90 18%低下、P99 7%低下 (比較対象: BAILIAN / Load Balance / LMetric; 条件: Qwen3-Coder-30B-A3B) — プリフィル負荷の均衡が尾部待ち時間を抑える。

- 事前フィルタの効果 / P90/P99 TTFT 16.1/51.2s→12.1/45.3s、P95 TPOT 89.2→82.5ms (比較対象: SMetric basic without overload/追い出し guards; 条件: guard ablation) — 通常時TPSへの影響は小さいが、極端な長セッションやKV消失時の尾部遅延を安全弁が抑える。

### 負の結果・境界条件
- グローバルKV層がない条件ではBAILIANに対するTPS改善が1%以内で、SMetric単独の優位性は小さい。低負荷の1.0倍付近でも方式間差は1%未満で、スケジューリングが効くのは主に資源競合が生じる領域である。負荷を2倍まで上げると全方式が深刻な過負荷となってTPSが低下する。Qwen3-Coder-30B-A3BのTPOT P99ではBAILIANよりやや悪い条件もあり、全ての尾部指標で常に優位ではない。また評価対象はコーディングエージェントとQwen3系に偏る。

### 結果の読み方
エージェント型負荷では、後続ターンを毎回再配置する必要はなく、将来多数の後続要求を生むセッションの最初の一回を均等に撒くことが負荷均衡に大きく効く。初回後は強いセッション内局所性を利用して同じGPUへ戻せるため、純粋負荷分散のようにKV再利用を犠牲にしない。グローバルKV層は初回配置で失う共有接頭辞を補い、局所性と均衡の交換条件をさらに緩める。
## 品質への影響
要求ルーティングだけを変更しモデル演算やKV値を近似しないため、生成品質の交換条件はない。評価で用いる有効TPSは本番TTFT/TPOT SLOを両方満たした要求だけを数えるため、単に遅い要求を増やして処理量を見かけ上高くする方式でもない。
## 既存研究との差
純粋負荷分散はGPU負荷を均す代わりにローカルKVをほぼ捨て、BAILIANのようなキャッシュ優先方式は高い命中率を得る代わりに最初の配置へセッションを固定して負荷偏りを作る。LMetricは局所性と負荷を要求単位の指標で組み合わせるが、エージェントの強いセッション内再利用を独立した構造として扱わない。SMetricは初回ターンと後続ターンの役割を分け、初回だけ負荷均衡、後続は局所性維持という時間方向の制御へ置き換える。さらに過負荷とKV消失の二つだけを固定解除条件にするため、局所性を細かく揺らさず長大セッションだけを移せる。
## 限界
評価はH20×32 GPUの単一クラスタとQwen3系MoEモデル2種類に限られ、性能再生に使う主トレースも商用コーディングエージェントのTrace1である。Trace2は特性分析には使うが同規模の性能比較を行わず、検索・ブラウザ・音声など異なるエージェント負荷への一般化は未検証。主要な10〜16%のTPS改善はグローバルKV層が利用できる条件で現れ、グローバル層なしではBAILIANとの差は1%以内に縮む。極端な2倍負荷では全方式が過負荷になる。ルータは要求に会話履歴が含まれることを利用してターン番号を推定するため、履歴を省略する独自APIではセッション局所性を直接識別できない。クラスタ間の広域配置は対象外で、v1時点でコードとトレースの公開も未完了である。
## 実装状態
vLLM v0.12.0上で実装され、LMCacheとMooncakeによるCPUメモリのグローバルKV層、200 Gbps RDMA、プリフィル・デコード同居/分離の両構成で実機評価されている。論文はSMetric実装とトレースを正式公開時にオープンソース化すると明記するが、2026-09-14時点のarXiv v1では公式リポジトリURLを確認できない。
## 研究上の位置づけ
LLMサービングの要求ルーティング・KVキャッシュ親和性の系統で、一般チャットではなくエージェントの長寿命セッションを第一級のスケジューリング単位として扱う研究である。新しいキャッシュ圧縮やGPUカーネルではなく、本番トレースから観測したセッション内再利用と負荷偏りを利用してルーティング規則を単純化する。ルータ側の永続セッション状態を持たないため、既存の階層KVストアやプリフィル・デコード分離基盤へ重ねやすい。
