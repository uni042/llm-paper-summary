# Beyond the Buzz：LLM推論のプリフィル・デコード分離はいつ有利か

## 概要

大規模言語モデルの推論サービングでは、入力を一括処理して最初のトークンを出す段階と、その後のトークンを一つずつ生成する段階で、望ましいGPUの使い方が異なる。前者は大きな行列演算をまとめて処理する計算効率、後者はユーザーが次のトークンを待つ時間の短さが重要である。二つの段階を同じGPU群で混在させる同居方式は、片方を最適化するともう片方が悪化しやすい。

プリフィル・デコード分離は、それぞれを異なるGPU群へ配置して独立に最適化する。ただし、入力処理で作ったKVキャッシュを生成側へ転送し、両側の処理率を釣り合わせ、GPU数を整数単位で割り当てなければならない。分離すれば常に速くなるわけではない。本論文は専有のGPU性能シミュレータで**数十万の設計点**を比較し、モデル規模、入力長と出力長の比、遅延目標、並列方式、GPU接続の範囲が、分離の優劣をどう変えるかを整理する。

主要な発見は、分離の利点が**入力処理偏重の負荷と大規模モデル**で大きい一方、**生成偏重の負荷や小型モデル**では同居方式の方が競争力を持つということである。最適なプリフィルGPU対デコードGPUの比率も一定ではなく、モデルや遅延制約が変わるたびに調整する必要がある。結果の多くは正規化されたシミュレーション上の傾向であり、特定の商用クラスタでの絶対処理率を保証するものではない。

## 問題設定：二つの遅延と一つの資源配分

同居方式では、同じモデル複製がプリフィルとデコードを実行する。実行中の要求をバッチへ追加する連続バッチ処理によりGPU利用率を高められるが、新しい長文入力を一気に処理すると、進行中の要求のトークン生成が止まる。このためプリフィルを短いチャンクへ分けてデコードの合間へ挿入する方式が用いられる。ただし、チャンクが小さくなるとプリフィルの計算効率や注意演算の再利用が変わる。

本論文は二種類の遅延制約を区別する。先頭トークン遅延（FTL）は新しい要求が最初の出力を得るまでの時間、トークン間遅延（TTL）は継続生成中に次のトークンを得る間隔である。TTLの逆数は利用者一人当たりのトークン生成速度を表す。厳しいTTLを守るには生成側のバッチを小さくし、より多くのGPUでモデルを並列化することがある。一方、FTLを短くするにはプリフィル側の演算を十分な並列度で実行する必要がある。

分離方式は、プリフィル側でFTLを、デコード側でTTLをそれぞれ最適化できる。しかしプリフィルが一秒に処理できる要求数と、デコードが一秒に完了できる要求数が釣り合わなければ、一方が待ち行列を作り、他方のGPUが遊ぶ。モデルを何台のGPUへ分割するか、各段階に何台割り当てるか、KVをどの速度で転送できるかまで同時に決める必要がある。

## 手法：設計空間を構成して比較する

### 1. 分割方式とバッチの探索

著者らはテンソル並列（TP）、専門家並列（EP）、パイプライン並列（PP）、チャンク化パイプライン並列（CPP）、注意部分をTP、フィードフォワードの専門家部分をEPで処理する混成方式などを候補にする。これらの組合せを、バッチ数、入力長、出力長、GPU構成、モデルの注意機構ごとに評価する。

専有の高忠実度GPU性能シミュレータへモデル構造とトラフィックを入力し、候補の処理率と遅延を算出する。各候補から、ユーザー当たりのトークン生成速度を変えたときに、GPU当たり処理率を最大化できるパレート前線を構築する。最も速い一構成だけを比べるのではなく、対話性を厳しくしたときに処理率がどう犠牲になるかを比較する。

同居方式では、プリフィルをデコードへ相乗りさせる場合と、相乗りさせない場合の両方を考慮する。相乗り構成ではプリフィルのチャンクとデコードのトークンを混ぜる割合を、入力長と出力長および遅延制約ごとに調整する。分離方式ではプリフィルとデコードのモデル分割・バッチを別々に選ぶ。両者を同じ指標で比べることにより、分離だけに有利な比較条件を避ける。

### 2. チャンク化パイプライン並列の位置づけ

長い入力をプリフィルする際、入力を複数チャンクへ分割し、先行チャンクが後段の層を処理している間に後続チャンクが前段の層を処理する。先行チャンクのKVを参照しつつ、パイプラインの空きを減らす構造である。著者らはDeepSeek-R1の256K入力・64GPUの例を使い、厳しいFTLを守りながら処理率を維持するためにCPPが有効な構成を示す。

ただし、チャンク化がどのモデルでも有利とは限らない。DeepSeek-R1の多頭潜在注意（MLA）では、同居方式で入力をチャンク化すると、下向き・上向き射影の計算が繰り返されることがあり、重複した演算費用が発生する。論文はこの重複を減らす一時的なKV保持の選択肢も比較へ含める。一般的なグループ化クエリ注意（GQA）と同じ前提で評価できない点が重要である。

### 3. GPU配分を決める処理率整合

分離方式では、FTLを満たすプリフィル構成を固定した上で、TTLを満たすデコード構成を組み合わせる。著者らは整数最適化を用い、プリフィルが作る要求の流量とデコードが消費する要求の流量を釣り合わせながら、必要なGPU数を最小化する。FTLが10秒を超える候補は探索から除外する。

この処理率整合を行わずにGPU数の比率を固定すると、プリフィルとデコードのどちらかがボトルネックになる。原著のDeepSeek-R1の例では、文脈処理側と生成側のGPU比3.5は緩い遅延目標では有効でも、厳しい目標では悪化する。逆に0.5は厳しい遅延に向く一方、緩い条件では処理率を落とす。最適比はモデルとSLOに応じて変わるため、実際の負荷変動へ追随する弾力的なGPU配分が必要になる。

### 4. KV転送の重畳と通信帯域

分離すると、プリフィルGPUが作った鍵値をデコードGPUへ移さなければならない。論文はKV転送を完全に無料と仮定するのではなく、層ごとにKVが完成した時点で転送を始め、後続層の計算と重ねることを想定する。その重畳が成立するための送出帯域・受信帯域を、層数、バッチ、入力長、KV頭数、頭次元、要素のバイト数、FTL、TTL、出力長、KVを一意に分割するGPU数から導出する。

プリフィル側の送出帯域は、概念的には「一要求で作るKV量×同時処理要求数」を「プリフィル時間×実際にKVを分割するGPU数」で割った量になる。デコード側では「受信するKV量」を「トークン間時間×生成長×分割GPU数」で割った量が必要帯域の目安になる。テンソル並列の次数がKV頭数を超えてKVが複製される場合、GPU数で単純に割ると必要帯域を過小評価するため、実際に異なるKV部分を持つGPU数で正規化する。

この解析では、入力が長くなるとKV量は線形増加する一方、プリフィル計算時間は注意の費用でより速く増えるため、プリフィル側の必要送出帯域が必ずしも入力長とともに増えるわけではない。デコード側では入力長によるKV量とTTLの増加が相殺される傾向があり、出力長の短さが受信帯域要求を高める。著者らは対象としたデータセンター構成で既存の帯域が重畳に十分と評価するが、これはあらゆる接続網・配置での保証ではない。

## 評価条件

本論文は主として**大規模な構成探索シミュレーション**であり、独立に公開された実行コードで実測ベンチマークを再現した研究ではない。絶対値よりパレート前線の形状と、条件を変えたときの傾向を重視している。原著の図1、5～12および第3～5節に基づき、主要条件を整理する。

| 項目 | 条件・意味 |
|---|---|
| モデル | DeepSeek-R1、Llama-3.1 8B／70B／405Bなど |
| 装置 | Blackwell世代を主対象としたデータセンター級GPU構成、FP4を想定 |
| 設計点 | 数十万のモデル分割・バッチ・GPU比・遅延条件の組合せ |
| 負荷 | 入力長（ISL）、出力長（OSL）、要求到着率を変化 |
| 遅延 | 先頭トークン遅延FTL、トークン間遅延TTL |
| 対話性 | 利用者一人当たりのトークン生成速度（TTLの逆数） |
| 効率 | 全GPUを考慮した処理率、パレート前線 |
| 比較 | 分離方式、同居方式、同居でのプリフィル相乗りの有無 |
| 通信 | NVLink領域サイズ、KV転送を計算へ重ねるための必要帯域 |
| 制約 | FTLが10秒を超える設計点は除外 |
| 実装上の前提 | 専有GPU性能シミュレータ、KVの層単位転送重畳、十分な要求とGPUを想定 |

## 評価結果と解釈

### 1. 入力処理偏重では分離が有利、生成偏重では利点が縮む

DeepSeek-R1を使った原著の図8は、入力長と出力長の比を変えてパレート前線を比較する。入力長が出力長より大きい条件では、同居方式がデコードのTTLを守るためにプリフィルのバッチやチャンクを制限される一方、分離方式はプリフィル専用GPUで計算効率を高められる。そのため分離の優位が大きい。

逆に、生成するトークン数が多い条件ではデコードが処理時間の大部分を占め、同居方式が短いプリフィルをデコードの合間に相乗りさせる利点が大きくなる。分離による独立最適化の余地が小さくなり、KV転送と二つのGPU群の調整が余計な費用になり得る。分離は単なる新旧方式の優劣ではなく、負荷の入力・出力比で採否が変わる。

### 2. モデル規模と注意機構による違い

Llama 8B、70B、405Bを比較した図7では、モデルが大きいほど分離による選択肢が増える。大規模モデルは複数GPUに分割されるため、プリフィルには大きな演算バッチ、デコードには低遅延の並列構成を独立に選びやすい。小型モデルでは分割構成の自由度が小さく、同居方式でも十分な効率を得られる場合がある。

DeepSeek-R1ではMLAの射影計算がチャンク化によって繰り返される点も重要である。同じ入力長・出力長でも、注意機構がGQAかMLAかで同居方式の費用が変わる。モデルの総パラメータ数だけで分離の優劣を判断することはできない。

### 3. 厳しい対話性目標ではデコード側の並列化が増える

原著の図6などでは、TTL制約を厳しくするほど、デコード側が小さいバッチと高いテンソル並列次数へ移る。Llama-3.1-70Bでは並列次数が2から64へ増える例が示され、DeepSeek-R1でも高処理率側の大バッチから、対話性重視側の小バッチへ移行する。分離方式はプリフィル側の分割方式を変えずにデコード側を調整できるため、中程度の遅延領域で優位を得やすい。

一方、同居方式も厳しい遅延を満たすために高い並列度を使えるため、最も厳しい遅延領域で常に分離が勝つとは限らない。パレート前線のどこで比較するかを指定せずに、分離の速度倍率を一つだけ報告するのは適切でない。

### 4. GPU比とNVLinkの接続範囲

原著の図9～10は、プリフィル対デコードのGPU比がモデルと遅延目標により大きく変わることを示す。固定比3.5と0.5の比較は、同じ比率がどの条件でも良いわけではないという反例である。処理率整合と弾力的なGPU配分は、単なる細かなチューニングではなく分離の利得を実現するための主要条件となる。

図11ではNVLink領域が大きい構成の方が、専門家並列やテンソル並列の選択肢を広く取れるため、分離方式の性能が改善する。GPU数が同じでも接続範囲が狭い場合には、同じ分割方式を選べず、デコード側の処理率や遅延が悪化し得る。

### 5. 通信帯域とシミュレーションの範囲

第5節はKV転送の必要帯域を解析し、対象のデータセンター構成では既存の帯域で転送を計算へ重ねられると述べる。ただし、これは層ごとにKVを早期転送でき、通信と計算の重畳が十分成立する前提に依存する。KVキャッシュを複製する並列構成、接続網の競合、要求到着の偏りが大きい環境では追加検証が必要である。

本論文は多くの図を正規化値で示し、特定のGPU製品における絶対トークン毎秒を一般的な性能保証としていない。専有シミュレータの予測と実運用の測定結果は区別する必要がある。論文が示すのは**どの設計変数が優劣を変えるか**という構造的な知見である。

## 既存研究との差

既存の分離サービング研究には、DistServeやMooncakeのように特定の実装・スケジューラを設計して測定するものがある。本論文は単一の新しい推論ランタイムを提案するのではなく、分離と同居の双方を同じパレート前線上で比較し、モデル規模、入力と出力の比、GPU比、並列方式、NVLink、KV転送帯域の影響を横断して整理する。したがって実装方式の競争結果というより、導入判断のための設計空間分析として読むべきである。

## 限界と適用条件

第一に、主な根拠は専有シミュレータによる大規模探索である。数十万の構成を試せる利点がある一方、同じ実行環境を公開コードだけで完全に再現することはできない。図の多くは傾向比較のため正規化されており、実際のGPUクラスタで得られる絶対的な要求処理率や応答時間をそのまま示すものではない。

第二に、動的トラフィックは入力長と出力長の中央値を2の冪へ近似するモデルを用いている。実サービスの長い裾を持つ要求分布、急激な到着率変動、キャッシュ再利用、GPUの部分的な遊休、ネットワーク混雑は、実際の最適なGPU比を変え得る。シミュレーションの平均的な負荷条件だけで導入効果を決めるのは危険である。

第三に、プリフィルとデコード間のKV転送を層単位で計算へ重ねられるという前提がある。実際の転送遅延、通信ライブラリのオーバーヘッド、KV複製、トポロジー制約を測る必要がある。帯域の必要量を式から見積もれても、同時転送の競合や実装上の待ち時間が必ず隠蔽できるとは限らない。

第四に、KV再利用、投機的復号、推論時の追加計算、モデル構造の変化は将来課題とされている。これらが導入されるとプリフィルとデコードの負荷比が変わるため、現在の設計原則をそのまま固定的なGPU配分へ落とし込めない。分離方式は万能ではなく、対象モデル・負荷・SLO・接続構成を測ってから採用を判断する必要がある。
