# Splitwise: Efficient Generative LLM Inference Using Phase Splitting

> prefillとdecodeを別machine poolへ分け、それぞれに向くGPU世代・電力設定・台数を使い分けて、cluster全体のthroughput・cost・消費電力を改善するserving設計。

## 概要

prefillは多数tokenをまとめて処理するためGPUの計算性能を使いやすい。一方decodeは1 tokenずつ進むためmemory bandwidthの影響が大きく、最新GPUの高いFLOPsを使い切れない場合がある。

Splitwiseはこの差を利用し、**prefillとdecodeを別GPU群へ分離する**。prefillには計算性能の高いGPU、decodeにはより安価な旧世代GPUや消費電力を抑えたGPUを割り当てることで、同じcostやpower budgetでより多くのrequestを処理することを狙う。

prefillで生成したKV cacheはdecode側へ転送する。

## 問題設定

H100はA100より計算性能の伸びが大きい一方、memory bandwidthの伸びはそれほど大きくない。そのためdecodeだけを見ると、高価なH100の計算性能を十分使えないことがある。

またH100の消費電力上限を下げてもdecode latencyはあまり悪化しない条件がある一方、prefillは大きく遅くなる。つまりprefillとdecodeでは適したGPUや電力設定が違う。

## 手法

### 1. Prefill / Decode / Mixedの3種類のGPU pool

通常requestはprefill poolでpromptを処理し、そのKV cacheをdecode poolへ送る。

trafficが想定からずれた時に片方だけGPUが余らないよう、一部GPUはprefillにもdecodeにも使えるmixed poolとして動かす。

### 2. Phaseごとにhardwareを選ぶ

論文では、prefillとdecodeの両方をH100で処理する構成だけでなく、prefillをH100、decodeをA100にする構成や、decode側H100の消費電力上限を下げる構成などを比較する。

狙いは、**計算性能が効くprefillへ高性能GPUを集中し、decodeにはmemory性能あたりのcostが良いGPUを使う**ことにある。

### 3. KV転送をprefill計算と重ねる

prefill全体が終わってからKVをまとめて送ると、その転送時間がそのまま待ち時間になる。

SplitwiseはlayerごとにKVが生成された時点でdecode GPUへ送り、次layerのprefill計算とnetwork転送を同時に進める。

### 4. 実機測定からcluster構成を比較する

A100 / H100上でprefill・decode latencyと消費電力を測定し、その値とAzureのproduction traceをsimulationへ入力する。

そのため大規模clusterの主要結果は、**実機で測った性能を基にしたsimulation**であり、すべてのGPU構成を実際に組んで測った結果ではない。

## 評価

Llama-70BやBLOOM-176Bを使ってA100 / H100の特性を測定した。

同じcostで比較した条件では、Splitwise構成がH100のみのbaselineより**1.4倍高いthroughput**を示した。

同じthroughputなら**25%低いcost**で済む構成も報告している。

同じcostとpowerを揃えた条件では、最大**2.35倍のthroughput**を報告した。

またdecodeではH100のpower capを700Wから350Wへ下げてもlatencyへの影響が小さい一方、prefillは大きく遅くなることを確認している。

## 既存研究との差

### DistServeとの違い

両者ともprefillとdecodeを別GPUへ分ける。

DistServeはSLOを満たして処理できるrequest数を増やすために、各phaseのGPU数やparallelismを決める。Splitwiseはさらに**GPU世代、cost、消費電力**までcluster設計へ含める。

### Mooncakeとの違い

SplitwiseのKV転送は主に同じrequestのprefill→decode移動である。MooncakeはKVをcluster全体へ保存し、別requestでもprefixを再利用できるようにする。

## 限界

- cluster-levelの主要結果はsimulation中心。
- A100 / H100世代の性能差を前提としており、新しいGPUでは最適構成が変わる。
- phase間KV転送には高速networkが必要。
- trafficが大きく変化すると、prefill / decodeの固定割合が合わなくなる。
- GQA / MLAなどでKV sizeが変わると転送costも変わる。

## 一般的な実装上の含意

prefill / decode分離の利点は、両者の干渉をなくすことだけではない。**phaseごとに異なるGPUや電力設定を使える**ため、datacenterのGPU構成や電力配分そのものを効率化できる。
