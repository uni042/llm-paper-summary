# Parallax: Efficient LLM Inference Service over Decentralized Environment

> Parallaxは、地理的に離れた異種GPUを公衆ネットワーク越しに束ねる分散LLMサービングで、計算性能・VRAM容量・通信帯域の差が大きいため均等なモデル分割では最遅GPUや低速回線が全体を律速する問題を、二段階スケジューリングで解く。第1段階ではGPU容量と地域境界を考慮した動的計画法で複数モデル複製の層配置を求め、追加段数による通信遅延を抑えながら複製数を増やす。さらに水充填法で各パイプライン内の層数をGPU計算性能に合わせて再配分する。第2段階では複数複製に置かれた各層を有向非巡回グラフとして捉え、分散ハッシュ表から得る層処理時間とGPU間往復時間を使って要求ごとに最小遅延の実行経路を選ぶ。5台のRTX 5090と2台のRTX 4090を複数データセンターへ分散した実機環境で、HexGenに対してスループット最大3.6倍、平均1.58倍、遅延最大3.2倍、平均1.66倍の改善を報告し、256 GPUを想定したスケジューラ計算も低ミリ秒台に収める。

## 問題設定
分散協調型のLLM推論では、家庭・研究室・地域データセンターなどにある遊休GPUを一つのサービスへ束ねられる一方、GPU世代、演算性能、VRAM容量、地域間ネットワークが大きく異なる。データセンター向けの均等なテンソル並列やパイプライン並列をそのまま使うと、遅いGPUへ割り当てた段が全要求を待たせ、高速GPUが遊休する。さらに地域間リンクは数百MB/s級まで低下し得るため、パイプライン段を増やして計算を細かく分散するほど活性値通信が計算時間を上回る。Petalsのような分散推論は実現可能性を示すが、局所的な貪欲経路選択ではクラスタ全体のGPU容量・通信費を同時に最適化できず、モデル複製数と1要求あたり段数のトレードオフも扱いにくい。加えて参加GPUは増減するため、起動時に一度決めた静的配置だけでは現在の負荷やネットワーク状態から外れる。Parallaxは、モデル層をどこへ置くかという比較的低頻度の問題と、各要求がどの層複製を通るかという高頻度の問題を分離し、異種性と動的性を両方扱う。
## 新規性
Parallaxの中心は、NP困難な層配置と要求経路の同時最適化を二段階へ分ける点にある。第1段階では、地域間通信が極端に高価という観測を使って配置探索を地域内へ制限し、各モデル複製のパイプライン段数を小さくしつつ複製数を増やす動的計画法を使う。その後、同じパイプライン内でもGPU演算性能が異なるため、水充填法で各GPUの連続層数を性能比例で再配分する。第2段階では、複数モデル複製にまたがる同一層のコピーを一つの有向非巡回グラフへ重ね、DHTに保存された現在の層処理遅延とGPU間通信遅延を辺・頂点費用として、要求ごとに最小遅延経路を動的計画法で選ぶ。これにより静的複製の境界を越えて層コピーをつなぎ直せる。
## 手法
### 手法のあらまし
最初に各GPUについて、利用可能VRAMから搭載できるTransformer層数と、実測した層あたり処理性能、地域、通信遅延を収集する。第1段階は同一地域内のGPUごとに、モデル全L層を何個の複製へ収容できるかを探索する。動的計画状態は、処理済みGPU、未完成パイプラインに残る層数、完成済み複製数を保持し、GPUを使わない、既存パイプラインを延長する、新しい複製を開始するという遷移から必要段数が最小の構成を求める。複製数kを増やすと並行要求数は増えるが、容量を細分化して各複製の段数が増えると地域内でも通信遅延が増えるため、複製数と平均段数、実測計算時間、段間RTTを含む評価式で最終kを選ぶ。次に同じパイプラインを構成するGPUの演算性能に応じて水充填法で層数を再配分し、遅いGPUへ過剰な層が残らないようにする。ここまでが比較的低頻度のモデル配置である。実行時には、各GPUが自分の層処理遅延とGPU間片方向RTTを1〜2秒周期で分散ハッシュ表へ公開する。第2段階は、層番号とGPUの組を頂点とし、連続する層を保持するGPU間だけを辺で結ぶ有向非巡回グラフを作る。要求到着時に先頭層から最終層まで一度前向きに走査し、頂点の現在処理遅延と辺の通信遅延の総和が最小になる経路を求める。この経路は一つのモデル複製に固定されず、前半を複製A、中盤を複製B、後半を複製Cから選べるため、混雑したGPUを迂回して空いている層コピーを利用できる。GPU参加時は負荷の高い層付近へ連続層を局所追加し、離脱時は該当配置を削除する。全層を覆う経路が失われた場合や層負荷の変動係数が閾値を超えた場合だけ第1段階を再実行し、それ以外は局所修正で済ませる。

### 地域・遅延優先のモデル配置動的計画法
地域間の低帯域リンクでは、追加GPUへ計算を分けて得られる演算短縮より、活性値を次段へ送る時間の方が大きくなりやすい。Parallaxはこの観測を探索空間削減に使い、第1段階の層配置を原則として地域境界内で組み立てる。各GPUのVRAMから最大搭載層数を容量として、対象複製数ごとに未完成パイプラインの残り層数を状態として保持し、GPUを飛ばす、既存複製へ連続層を追加する、新しい複製を開始するという三つの選択を評価する。目的は全モデル複製を完成させつつ総パイプライン段数を最小化することであり、その上で複製数を増やすスループット利得と段数増加による遅延を評価式で比較する。これにより、単に全GPUを使うのではなく、低速回線を跨ぐ小さな段を増やさない配置を得る。

### 水充填法による異種GPU内の層再配分
VRAM容量だけを基準に層を割り当てると、同じ数の層でもRTX 5090とRTX 4090のように演算性能が違うGPUで段処理時間が揃わず、最遅段がパイプライン周期を決める。Parallaxは第1段階でGPU集合と複製構造を決めた後、その順序を変えずに水充填法で各GPUへ割り当てる層数を再計算する。各GPUの割当は演算能力に比例して増やしつつ、VRAMによる最大層数を上限とする。連続値で得た層数は最大剰余法で整数化し、全L層を隙間・重複なしの連続区間へ戻す。この再配分により速いGPUが多くの層を担当し、遅いGPUの段時間を下げるため、通信段数を増やさずに異種計算性能へ追従できる。

### DHT上のライブ性能地図と要求単位の経路選択
静的なモデル複製を複数作っても、実行時には特定複製へ要求が集中したりネットワーク遅延が変化したりする。Parallaxでは各GPUが層ごとの現在処理遅延と他GPUへの通信遅延を1〜2秒ごとに分散ハッシュ表へ公開する。配置済みの全層コピーを層番号順の有向非巡回グラフとして表し、要求ごとに頂点費用として層処理遅延、辺費用としてGPU間RTTを加算する。先頭層から最終層へ一度だけ動的計画法で走査すると、全層を順番通り一度ずつ通りながら現在の総遅延が最小のGPU列を得られる。この列は静的な一つの複製境界に従う必要がないため、混雑している中間段だけ別複製の同一層コピーへ迂回でき、要求負荷を実時間で分散する。

### 動的参加・離脱への局所更新と条件付き全体再配置
ボランティアGPUは常時稼働を前提にできないため、参加・離脱のたびに全モデルを再配置すると重み読み込みが頻発してサービスを止める。新しいGPUが参加した場合、ParallaxはDHTの負荷情報から資源が不足している層付近を選び、そのGPU容量に収まる連続層区間だけを追加する。GPUが離脱した場合はその区間と性能情報を失効させ、第2段階の経路候補から自然に除外する。すべての層を覆う完全経路が消えた場合、または層負荷の変動係数が設定閾値を超えた場合にだけ第1段階を再実行する。したがって通常の小さな構成変化は局所的な重み追加・削除で吸収し、必要なときだけ全体最適化へ戻るため、動的な参加環境でも継続中要求への影響を限定する。

### 全体のデータ／制御の流れ
各参加GPUは連続するTransformer層区間とその層のKV容量を持つパイプライン段として動作する。配置計画を作る第1段階スケジューラ、DHTに蓄積したライブ性能情報から要求経路を作る第2段階スケジューラ、モデル実行ランタイムから構成される。第1段階は構成変化時に低頻度で動き、第2段階は要求到着ごとに動くため、重い配置探索と高速なオンライン負荷分散を分離している。
## 評価条件
- **ハードウェア**: 複数データセンターに分散した実機7ノードで評価し、5台はNVIDIA RTX 5090、2台はNVIDIA RTX 4090を搭載する。ノード間は公衆ネットワークで接続し、平均マシン間通信遅延は約10 ms。データセンター内の均質高速相互接続ではなく、地域間通信を含む分散環境を主対象とする。
- **ソフトウェア**: Parallaxの公式公開プロトタイプを使用し、モデル層を連続区間として異種GPUへ配置する。DHTはGPUごとの層処理遅延とGPU間通信遅延を1〜2秒周期で更新し、オンライン経路選択へ供給する。比較対象は異種分散GPU向け推論基盤HexGen。
Qwen3-32BをBF16で扱う32B条件とFP8で扱う16B相当条件を評価し、ShareGPTとWildGPTから抽出した実会話由来トレースを使う。到着率を4、8、32などに変え、平均遅延とp95〜p100の末尾遅延、および要求/秒のスループットをHexGenと比較する。第1段階配置の効果は、地域境界・通信遅延を考慮した動的計画法と水充填法を含む構成として測定し、第2段階は要求ごとにDHTの最新値から最小遅延GPU列を選ぶ。スケジューラ単体では4〜256 GPUまで候補規模を拡大し、第1段階の全体配置計算時間と第2段階の1要求あたり経路選択時間を測る。動的メンバーシップについても、参加・離脱に対する局所更新と必要時の全体再配置が現実的な時間で可能かを評価する。
エンドツーエンド評価は7台のRTX 5090/4090実機を用いる点が強い一方、GPU種類は2系列、地域数と公衆ネットワーク条件も限定される。256 GPU評価はスケジューラ計算時間の拡張性であり、256台実機上のモデル実行性能ではない。比較対象は主にHexGenで、Petals、Helixなどとの同一条件エンドツーエンド比較はない。要求セッション中に選んだGPU列は固定されるため、単一長時間要求の途中で状態が急変した場合の再経路化は主評価対象ではない。
## 主要結果
Parallaxは、異種GPUと地域間低帯域通信を配置時・要求時の双方で考慮することで、静的な異種分散推論基盤HexGenより一貫して低い遅延と高いスループットを示した。論文全体ではスループット最大3.6倍、平均1.58倍、遅延最大3.2倍、平均1.66倍の改善を報告する。特にWildGPT、32B条件、要求率32ではスループットが0.11 req/sから0.40 req/sへ約3.6倍となり、同条件のp99遅延は207.0秒から78.1秒へ約2.6倍短縮した。第1段階の配置計算は4 GPUで0.10 ms、256 GPUでも8.55 ms、第2段階の要求経路選択は4 GPUで0.0136 ms/要求、256 GPUで6.6339 ms/要求に収まり、オンライン選択の制御費はモデル推論時間より小さい。

- 最大スループット改善 / 3.6×（0.40 req/s vs 0.11 req/s） (比較対象: HexGen; 条件: WildGPT、Qwen3-32B BF16、要求率32) — 低帯域地域間リンクを跨ぐ段数を配置時に抑え、実行時には混雑した層コピーを避けることで、静的分割よりパイプライン滞留を減らす。

- p99遅延短縮 / 約2.6×（78.1 s vs 207.0 s） (比較対象: HexGen; 条件: WildGPT、Qwen3-32B BF16、要求率32) — 高負荷では通信と遅い段の待ちが末尾遅延へ蓄積するため、現在の層処理時間とGPU間RTTを使う要求単位経路選択の効果が大きい。

- ShareGPTでのp99遅延 / 111.4 s vs 151.4 s、約1.36×短縮 (比較対象: HexGen; 条件: Qwen3-32B BF16、要求率4) — 比較的軽い負荷でも地域・通信制約を配置に含めることで末尾要求の停滞を減らす。

- FP8条件のスループット / 0.43 req/s vs 0.33 req/s (比較対象: HexGen; 条件: ShareGPT、16B相当FP8条件、要求率8) — モデルが軽く通信制約が相対的に弱い条件では差は縮むが、二段階スケジューリングの利得は残る。

- 第1段階配置計算時間 / 0.10 ms → 8.55 ms (比較対象: 4 GPU → 256 GPU; 条件: モデル配置アルゴリズムの拡張性評価) — 地域境界と遅延優先ヒューリスティックで探索空間を削るため、256 GPU候補でも構成変化時の全体再配置判断を低ミリ秒台で実行できる。

- 第2段階経路選択時間 / 0.0136 ms/req → 6.6339 ms/req (比較対象: 4 GPU → 256 GPU; 条件: 要求単位DAG動的計画法) — 候補層コピー数に依存するが、連続層配置によってグラフを小さく保つため、要求ごとの経路選択を推論時間に比べ小さい制御費で行える。

### 負の結果・境界条件
- Parallaxの利得は通信が重く異種性が強いほど大きく、FP8の軽いモデルや低負荷条件ではHexGenとの差が小さくなる。例えばShareGPTのFP8条件ではp99が82.1秒対87.0秒のように差が限定的な設定もある。第1段階は地域を跨ぐ配置を原則避けるヒューリスティックを使うため、非常に高速な地域間接続や地域内資源不足など、地域を跨いだ方が有利な特殊条件で大域最適を逃す可能性がある。第2段階で選んだ経路は要求セッション中固定され、途中でGPUやネットワーク状態が急変した場合の要求内再経路化は示されていない。256 GPUの結果はスケジューラ計算時間だけで、同規模の実機推論性能を実証したものではない。

### 結果の読み方
Parallaxの改善は、異種GPU環境で『計算を多くのGPUへ分ければ速い』というデータセンター前提を捨てたことから生じる。地域間通信がGPU計算より遅い環境では段数を増やすほど逆効果なので、第1段階は少ない段数と多いモデル複製の両立を優先する。その上で水充填法により速いGPUへ多くの層を持たせるため、各段の計算時間も揃う。しかし静的配置だけでは要求偏りを吸収できないため、第2段階で複製境界を越えて現在空いている層コピーをつなぐ。高負荷・重いBF16条件ほど混雑回避と通信削減の両方が効き、軽いFP8条件では通信・計算の絶対時間が小さいため改善倍率も縮む。
## 品質への影響
Parallax自体はモデル計算を近似せず、層の配置と実行経路だけを変更する。BF16とFP8は評価するモデル条件の違いであり、Parallax固有の量子化処理ではない。合法な経路は全モデル層を順番に一度ずつ覆る制約を持つため、経路を複数モデル複製から組み合わせても計算グラフの意味は保たれる。
## 既存研究との差
PetalsはボランティアGPU上の分散推論を成立させる先行基盤だが、分散ハッシュ表と貪欲な群並列経路選択を中心とし、クラスタ全体の異種GPU性能と地域間通信を使ってモデル複製配置を大域的に計画しない。HexGenは異種・分散環境を対象に静的負荷分割を最適化するが、Parallaxは配置後にも複数複製の層コピーを横断して要求ごとの実行パイプラインを再構成するため、時々刻々の混雑を避けられる。Helixのような異種GPU・ネットワークを考慮したサービングとも近いが、Parallaxはボランティア型の地域分散、動的参加・離脱を前提に、配置を低頻度の第1段階と要求単位の第2段階へ明示的に分離する。テンソル並列のような高通信量方式よりパイプライン並列を主軸とし、超低帯域環境で層間活性値だけを送ることを重視する。
## 限界
エンドツーエンド評価は実際に複数データセンターへ分散した7台のRTX 5090/4090で行う一方、GPU種類・地域数・ネットワーク条件は限定され、数百GPU規模はスケジューラ単体の計算時間評価に留まる。第1段階は地域間通信が計算より支配的という観測を強いヒューリスティックとして使うため、地域間が十分高速な環境や一地域だけではモデルを収容できない環境では探索制約を再調整する必要がある。DHTの性能情報は1〜2秒周期で更新されるため、それより速い混雑変化は経路選択時に古い値として見える可能性がある。また一度選んだ要求のGPU列はセッション中固定され、進行中要求を別経路へ移す障害復旧は主設計に含まれない。ボランティア環境で重要な信頼性、悪意あるノード、機密性についても本論文の性能設計とは別課題として残る。
## 実装状態
論文はParallaxを研究プロトタイプとして実装し、公式GitHubリポジトリ `GradientHQ/parallax` を公開している。5台のRTX 5090と2台のRTX 4090を実際の複数データセンターへ配置した公衆ネットワーク環境でQwen3系モデルを評価しており、シミュレーションだけの提案ではない。DHTによる性能公開、第1段階のモデル配置、第2段階の要求経路選択、参加・離脱処理まで論文中で実装・評価されている。
## 研究上の位置づけ
この研究は、単一データセンター内のGPU配置最適化よりもはるかに遅く不均一な相互接続を前提とし、『計算資源を追加するほど通信段数が増えて遅くなり得る』領域を扱う。LLM推論システム研究としては、モデル重みやKVをCPU・SSDへ退避する階層メモリとは異なるが、低速階層を跨ぐ転送費と計算再配置を同時に考えるという点で共通する。特にParallaxの二時間尺度の設計、すなわち高価な大域配置を構成変化時だけ行い、要求ごとは軽量な経路選択で追従する構造は、GPU/CPU/SSDを含む階層配置でも応用しやすい。容量・帯域・現在負荷が大きく異なる資源を一枚岩として扱わず、低頻度の物理配置と高頻度の論理経路を分離する設計例として価値がある。
