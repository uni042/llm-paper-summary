## 概要

StreamVLNは、視覚・言語・行動を連続して扱うロボット誘導システムにおいて、動画言語モデルの文脈長と鍵・値キャッシュ（KVキャッシュ）が際限なく増える問題を解決しようとする。単発の画像質問応答と異なり、ロボットはカメラ画像を受け取り、複数の行動を出力し、次の画像を受け取るという対話を繰り返す。毎回過去の全履歴を事前入力処理し直せば遅延が大きくなり、逆に全履歴のKVを保持すればGPUメモリが増え続ける。

提案方式は、直近の数ターンを高速に参照する**対話用の固定長窓**と、過去の視覚観測だけを低頻度で更新する**長期記憶**を分離する。窓内のKVを次のターンで再利用し、窓から出る古い画像パッチは深度情報を使った三次元の重複除去で圧縮する。主目的はロボット誘導の品質だが、計算基盤上の貢献として、継続するマルチモーダル入力のKV再利用、文脈長の上限化、視覚トークンの間引き、推論遅延の制御が直接評価されているため、LLM推論システムの関連研究として収録する。

## 問題設定

従来の動画言語行動モデルでは、毎回の観測を独立した問い合わせとして扱い、以前の観測と行動の系列を再度入力して次の行動を求めることが多い。この場合、過去の画像に由来する大量の視覚トークンを毎回事前入力処理する。KVをターン間で保持すれば、以前の計算を再利用できるが、長い行動系列ではキャッシュ容量が増大する。原著は2,000トークンで約5GBのKVを要する例を挙げ、無制限に保持する方法の非現実性を説明している。**この5GBは原著のモデル構成に依存する例示値**であり、すべての7Bモデルに一般化できない。

古い映像を一律にフレーム間引きする方法では、時間的な情報量を減らせても、似た景色を連続して観測するロボットの画像パッチの重複が残る。視覚特徴を平均化する圧縮や学習済み問い合わせによる圧縮は、事前学習済みの入力分布を変えてモデル品質を下げる場合がある。そこで、画像の特徴ベクトル同士を比較するのではなく、深度と三次元座標で**同じ場所を何度も観測しているか**を判定する方法を採用する。

## 手法

### 1. 高速側：直近対話の固定長KVキャッシュ

時刻$i$の観測$o_i$と行動$a_i$を一組の対話とし、直近$N$組の対話を活動窓$W_j$に保持する。新しい観測が入るたびに、既存窓のKVを再利用し、追加観測に対応する部分だけを事前入力処理して次の行動を生成する。原著の評価では窓幅8ターンを主に使用する。窓が満杯になると古いKVを活動窓から外し、プロンプトや過去の行動など、視覚観測ではない履歴の状態は捨てる。

長期に必要な観測情報は、後述する低頻度の記憶として保持する。したがって行動生成は、現在の観測、最近の窓内KV、過去の記憶トークンを条件に行われる。活動窓の長さを固定すれば、直近対話のKV容量は長い実行時間に比例して増えない。ただし記憶側も制御しなければ全体容量の上限は保証されないため、記憶に移す視覚トークンを別途圧縮することが重要である。

KV再利用の効果は、窓内のターン間で過去の事前入力をやり直さない点にある。一方、窓の切り替え時には以前の文脈を記憶として再構成する費用が生じ、完全な全ターンKV保持より遅延が増える場合がある。原著図7は、全ターン保持、8ターンの滑動窓、毎ターン独立という三条件を比較し、全ターン保持が最も低遅延だが容量費用が大きいことを示す。滑動窓はこの両者の折衷である。

### 2. 低速側：三次元ボクセルに基づく視覚トークン削減

画像パッチを深度情報で三次元空間へ逆投影し、一定の大きさのボクセルへ量子化する。時間を一定の区間へ分け、同じ時間区間かつ同じボクセルへ複数のパッチが投影された場合は、最も新しい観測のパッチだけを残す。これは似た特徴ベクトルを持つトークンを除くのではなく、**同じ空間位置を繰り返し観測したパッチを重複とみなす**選択則である。ボクセル索引を持つ表を更新し、最終的な保持マスクを生成する。

Algorithm 1は時間区間の幅$K$、ボクセル索引、閾値$\theta$を入力とする。各パッチ$(t,x,y)$について、区間索引$\lfloor t/K\rfloor$と三次元ボクセル番号の組をキーにし、そこへ最新時刻のパッチを登録する。最後に保持数が$\theta HW$未満のフレームは保持マスクを全てゼロにする。このため局所的な重複だけでなく、残存情報が極端に少ないフレームも除去できる。

距離行列や大規模な注意行列を使う圧縮と異なり、空間索引による重複判定は連続した動画を逐次処理しやすい。特徴空間の類似性ではなく三次元幾何に依存するため、深度の精度やカメラ位置推定が不安定な環境では保持判断を誤る可能性がある。三次元の同じ場所でも照明、視点、動く物体が変化すれば重要な新情報が生じ得るが、単純なボクセル重複判定だけではそれを十分に表現できない。

### 3. 記憶だけ削る構成と活動窓も削る構成

原著は二つの間引き設定を比較する。**Prune-Mem**は過去の8記憶フレームだけに三次元選択を適用する。現在の活動窓はそのままなので、直近の行動に必要な細部を残しやすい。**Prune-All**は長期記憶だけでなく、活動窓にあるストリーミング画像のKVにも間引きを適用する。後者の方が視覚トークン削減率は高いが、近傍の情報を失う危険も増える。二つの構成を同じ品質・メモリ条件とみなしてはならない。

### 4. モデル構成と学習の関係

基盤はLLaVA-Video 7Bで、言語モデルにはQwen2-7Bを使用する。訓練はまず正解経路を使った1エポックの微調整、次にモデル自身の行動から集めたDAgger補正データと一般的な視覚言語データを混合する1エポックの学習という二段階である。ナビゲーションデータに加え、動画質問応答、三次元質問応答、画像・文章の交互入力も用いる。

**KV再利用と三次元間引きは推論時の機構だが、最終的な誘導成功率はこの二段階学習にも強く依存する。** 提案方式の成功率改善をすべてキャッシュ管理だけの効果と解釈してはならない。原著は訓練データ構成の除去実験と、記憶容量・窓幅の除去実験を別々に示している。

## 評価条件

シミュレーションはHabitat上の連続ナビゲーション環境で行い、R2R-CEとRxR-CEの未知環境検証集合を使用する。R2R-CEは約5,600の英語経路、RxR-CEは英語・ヒンディー語・テルグ語を含む約126,000の指示を持つ。指標はナビゲーション誤差（NE、低いほど良い）、成功率（SR）、経路長で重み付けした成功率（SPL）などである。異なるモデルが追加データを使う条件と使わない条件を表の脚注で区別している。

実機ではUnitree Go2ロボット犬のIntel RealSense D455 RGB-Dカメラから映像を取得し、遠隔のRTX 4090搭載ワークステーションへ送信して推論する。原著は4行動の推論を平均0.27秒、通信を屋内0.2秒・屋外1.0秒と報告する。**0.27秒は通信込みのエンドツーエンド遅延ではない。** 訓練費用は約1,500 A100 GPU時間であり、RTX 4090の推論時間とは別の測定である。

訓練データには、Matterport3Dの60環境から約45万クリップ、HM3Dの700環境から約30万クリップ、DAgger補正約24万サンプルが含まれる。一般的な視覚言語データとして動画質問応答約24.8万件、画像文章の交互入力約23万件を混合する。これらのデータ追加による成功率の変化は推論時キャッシュ設計の効果とは切り分ける必要がある。

| NaVILA（追加データあり） | 5.22 | 54.0 | 49.0 |
| StreamVLN（追加データあり） | 4.90 | 56.4 | 50.2 |
| StreamVLN-Prune-Mem（追加データあり） | 4.73 | 57.4 | 51.1 |

表Iに基づく。追加データありの条件では、記憶だけの間引きでSRが56.4から57.4へ改善する一方、活動窓まで間引くと56.0へ低下する。後者も多くの比較対象に対して競争力はあるが、記憶だけの間引きより性能を失っている。なお原著本文§IV-Cは追加データありのStreamVLNについてR2R SR「56.9%」と記述するが、表Iは「56.4%」である。**本稿では表の値を採用し、本文と表の不一致を未解決の原著内差異として記録する。**

### 2. トークン削減率と成功率の交換関係

原著§IV-Cによれば、Prune-MemはR2Rで記憶トークンを28%、RxRで22%削減する。Prune-AllはR2Rで視覚トークンを32%、RxRで30%削減する。削減率の母集団が異なり、前者は記憶トークンのみ、後者は活動窓も含む視覚トークンである。28%と32%をそのまま同じ母数の差として比較することは適切でない。

R2RでのPrune-MemのSR57.4は元の56.4より1.0ポイント高い。これは重複観測を除いたことで推論に必要な情報が整理された可能性を示すが、すべてのタスクで削減が精度を改善するわけではない。RxRではPrune-MemのSR53.9に対し元の54.4、Prune-Allでは53.3と、両構成で少し悪化している。空間情報の削減が常に無害とは言えない。

### 4. KV再利用と実ロボット遅延

図7は、全ターンのKVを保持する場合、8ターンの滑動窓で保持する場合、毎ターン新たに事前入力する場合を比較する。全ターン保持は追加観測だけを事前入力すればよく最も低遅延だが、メモリ容量が継続的に増える。毎ターン独立では過去の観測を繰り返し処理するため、ターン数が増えるほど遅延が大きくなる。滑動窓は切替直後に再構成の費用が生じるが、その後のターンでは低い遅延に戻る。原著の図からは厳密な全ターン平均倍率を再計算できないため、未掲載の数値を補間しない。

実ロボットのRTX 4090試験では、4行動のモデル推論が平均0.27秒、通信は屋内0.2秒、屋外1.0秒である。通信は環境によって推論より大きく、遠隔GPUでのモデル高速化だけではロボットの応答時間を十分に短縮できない可能性がある。原著は屋内廊下、寝室、オフィスなどの試験を各方式20回ずつ行い、成功率と経路誤差を比較しているが、ここでの通信条件は一般のデータセンター内サービングとは異なる。

## 既存研究との差

NaVILAなどの従来の動画言語ナビゲーションは、各行動ステップで過去の映像と指示を再処理しやすく、文脈長と事前入力費用が増える。StreamVLNは**ターン間のKVキャッシュを再利用し、窓から出る古い視覚状態を別の長期記憶へ移す**点で、単発の動画質問応答と異なる。これは長時間動作するエージェントの推論メモリ階層という観点で重要である。

画像特徴の類似度に基づく間引きとは異なり、三次元ボクセルの同じ位置を重複の単位とする。ロボットが同じ場所を何度も見た場合、特徴距離の全対比較を行わずに冗長な観測を削減できる。一方、深度が必要であり、視覚特徴だけから動作する汎用LLMサーバにそのまま移植できるものではない。Prune-MemとPrune-Allの比較は、**直近情報の品質を優先して記憶だけを削る**設計と、**容量をさらに減らすため活動窓も削る**設計の交換関係を具体的に示す。

## 限界

第一に、主評価はロボットの連続ナビゲーションであり、一般の対話LLM、文章生成、推論APIサービングのスループット・同時実行要求数・GPU間通信は測定していない。LLaVA-Video 7BとQwen2-7Bを使った結果を他のモデル規模やアーキテクチャへ無条件に一般化できない。

第二に、三次元間引きは深度と空間座標の品質に依存する。深度推定が誤る場合や動的物体が同じボクセルへ現れる場合、重要な観測を誤って削る可能性がある。ロボットの視点変化、遮蔽、動的環境への頑健性は、ここで示したトークン削減率だけでは保証できない。Prune-AllはR2RのSRを56.4から56.0へ、RxRのSRを54.4から53.3へ下げるため、容量削減には品質の代償がある。

第三に、全ターンのKV保持は遅延を抑えるがメモリが増え続ける。滑動窓は上限を与える代わりに切替時の再事前入力が必要であり、原著図7の定性的比較だけから、すべての窓幅・要求頻度での平均遅延やスループットを導けない。長期記憶も完全に一定サイズとなるためには、記憶フレーム数と各フレームの保持数を別途固定する必要がある。

第四に、成功率の改善には追加学習データとDAggerの効果が大きい。表IIIでは訓練データの追加だけでR2RのSRが45.6から56.4へ改善する。これはキャッシュ機構単独の効果ではない。表IVの窓幅変更は訓練サンプル数も変えるため、窓幅が推論品質へ与える純粋な因果効果を完全には分離できない。

第五に、原著本文§IV-Cと表Iの追加データありR2R SRに56.9%と56.4%の不一致がある。本文の数値を表に合わせて無断で補正せず、原著内の差異として記録した。実機での0.27秒は4行動の推論だけで、屋外では通信1.0秒が別に必要である。RTX 4070 Super 12GBの動作可否や遅延を、RTX 4090の測定から推定して保証することはできない。
