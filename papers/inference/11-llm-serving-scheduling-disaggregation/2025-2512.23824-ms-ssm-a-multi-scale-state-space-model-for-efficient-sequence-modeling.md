# MS-SSM：多尺度の状態空間モデルによる長距離系列モデリング

## 概要

状態空間モデル（state space model; SSM）は、過去の情報を有限次元の内部状態へ圧縮し、入力を逐次取り込むことで長い系列を効率よく処理する。自己注意（self-attention）では系列長に応じて過去トークンの鍵・値を参照するのに対し、SSMの再帰形は一定サイズの状態を更新できる。ただし固定次元の線形再帰は、短い局所的な変化と長期の大域的な傾向を同時に保持しにくい。長期の記憶を延ばそうとすると状態次元の拡大が必要になり、計算・メモリの利点が薄れる場合がある。

本研究の**多尺度状態空間モデル（Multi-Scale State Space Model; MS-SSM）**は、入力系列を複数の時間解像度へ分解する因果的な拡張畳み込みと、各尺度に専用のSSMを組み合わせる。細かな尺度では局所変化、粗い尺度では長期傾向を表現し、最後に入力依存の尺度混合器で結果を統合する。さらに、粗い尺度の状態遷移を長期記憶に適した値で初期化する。S4を用いた入力非依存版と、Mamba系のS6を用いた入力依存版を評価し、提案の効果が特定のSSM実装だけに依存しないかを検証する。

ListOpsの階層演算予測ではMambaの38.02%に対してMS-SSM(S6)は63.04%、MS-SSM(S4)は62.83%を報告する。画像のピクセルを1次元系列として処理するsCIFARでは、Mambaの90.1%に対してMS-SSM(S6)は93.3%となる。一方、長距離系列ベンチマークのすべてで最良ではなく、Long Range Arenaの平均ではMS-SSM(S4)が91.89、MS-SSM(S6)が86.73で、他方式のMega 93.22、S5 92.52を下回る。**効率的な系列表現の研究であり、実際のLLMサービング速度やGPUメモリを測った論文ではない**点を最初に区別する。

## 背景：SSMの記憶と複数時間尺度

### SSMの状態更新と注意機構の違い

通常のSSMは入力x_tを状態h_tへ写し、前の状態と現在の入力から次の状態を計算する。離散時間では一般に

`h_t = A_bar h_(t-1) + B_bar x_t,  y_t = C h_t`

と表せる。A_barは過去状態をどれだけ残すか、B_barは現在の入力をどう取り込むか、Cは状態から出力をどう読むかを決める。状態次元が一定なら、推論時に保持する状態量は系列長に依存しない。一方、過去の全トークンへ直接注意を向けるTransformerは、長い文脈でKVキャッシュが大きくなる。これがSSMが長系列向けの候補とされる理由である。

しかし、固定の状態次元は無限の記憶容量を意味しない。状態遷移行列A_barの固有値の絶対値が1より小さいと、古い入力の寄与は更新のたびに減衰する。固有値が1から離れるほど速く忘れ、1に近いほど長く保持する。論文は固有値が1−delta以下のとき、有効記憶長が概ね1/deltaのオーダーになる関係を用いる。長期情報を保つためすべての状態を1近くへ置けば、今度は短期の局所変化へ敏感な表現を作りにくい。多様な時間尺度を単一の再帰へ押し込むことが問題になる。

### 多尺度分解とウェーブレットの考え方

画像には輪郭と大きな構図があり、時系列には短い周期と長期トレンドがある。言語にも文字・語・句・文・段落などの階層がある。多解像度解析（multi-resolution analysis; MRA）は、入力を粗い近似成分と細かな差分成分に分け、複数尺度で表現する考え方である。離散ウェーブレット変換では低域通過・高域通過フィルタと間引きによって各尺度を作るが、間引きによる平行移動への敏感さや、因果的なオンライン処理との整合が問題になる。

MS-SSMは定常ウェーブレット変換（stationary wavelet transform; SWT）の発想を取り入れ、**系列を間引かずに**尺度を作る。フィルタの間隔を段階的に広げた因果的な1次元畳み込みを使い、各尺度の系列長を維持する。この冗長表現はメモリ・演算の追加費用を伴うが、入力の位置ずれに対する安定性と、同じ時刻の異なる尺度を組み合わせやすいという利点がある。

### なぜ畳み込みだけでも不十分か

拡張畳み込みは、カーネル間隔を2倍、4倍、8倍と広げることで、少ない層でも比較的広い過去を参照できる。しかし有限段数・有限カーネルの畳み込みには、扱える過去の範囲がある。長期の相関をさらに保持するには、畳み込みで得た各尺度の系列へSSMを適用し、その尺度の過去を状態として蓄積する必要がある。MS-SSMの設計は、局所パターンの抽出を畳み込み、長期の履歴保持をSSM、尺度間の適応的な統合を混合器へ分担させるものである。

## 手法：多尺度分解から出力まで

### 1. 入力を近似成分と差分成分に分ける

入力系列を`a^0=x`とする。尺度sで前段の近似系列a^(s−1)へ、低域フィルタphiと高域フィルタpsiを適用する。フィルタ長Kの各係数は学習可能で、尺度sでは畳み込みの間隔を`2^(s−1)`に広げる。近似成分a^sと詳細成分d^sは、概念的には

`a^s[t] = sum_l phi[l] * a^(s-1)[t - 2^(s-1)*l]`

`d^s[t] = sum_l psi[l] * a^(s-1)[t - 2^(s-1)*l]`

である。過去方向の値しか使わない因果的な演算なので、将来のトークンを参照せずに現在の表現を作れる。各尺度で入力の系列長は維持されるため、詳細成分d^1〜d^Sと最終近似成分a^Sは時刻tごとに並べて扱える。

実装上は、各尺度の拡張率を持つ因果的な深さ方向1次元畳み込み（causal depthwise Conv1d）で近似・詳細の2出力を生成する。単一の巨大カーネルで遠方の情報を一度に読むのではなく、短い学習可能フィルタを段階的に適用する。論文はこの部分の計算量を系列長L、カーネル長K、尺度数Sに対して`O(L*K*S)`、追加パラメータを`O(K*S)`とする。これは多尺度化が無料という意味ではなく、SとKを小さく保つことで線形オーバーヘッドへ抑える設計である。

### 2. 元の入力と各尺度へ独立したSSMを割り当てる

MS-SSMは元の入力系列も含め、尺度ごとの詳細・近似系列を別々のSSMへ入力する。尺度数Sの場合、論文の構成は合計`S+2`個のSSMを並列に動かす。各SSMの状態次元をNとすると、入力チャネル当たりの合計状態次元は`(S+2)*N`となる。比較対象より状態を増やして有利にしていると誤解しないよう、論文は**総状態次元を比較モデルと揃える**設計を採用している。

各SSMは自身の尺度の過去を再帰的に統合する。細かな詳細系列では短期的な変化を、大きい尺度では長期のトレンドを表現する。元の入力を通す経路を残すため、多尺度畳み込みで捨てられた細部を補う直接経路もある。複数のSSMを完全に独立した巨大モデルとして扱うのではなく、総状態容量を分割して専門化することが重要である。

### 3. 尺度に応じた状態遷移の初期化

粗い尺度は長い過去を保持する必要があるため、状態遷移A_barの固有値を1に近づけて初期化する。細かい尺度では固有値をより小さくし、古い情報を速く忘れる初期化にする。論文は実数の対角状態遷移を使い、尺度sの連続時間の対角要素をNと尺度数から決まる区間に分布させる。離散化後は安定性のため固有値を単位円の内側に置き、尺度によって異なる有効記憶長を与える。

これは「学習後も固有値が固定される」という意味ではない。初期化時点で細部と大域に異なる記憶の役割を与え、学習が多尺度の情報を分担しやすい状態から始めるための帰納的な設計である。すべての尺度を同じ記憶時間で初期化する単一SSMと比べ、階層構造に合わせた時間定数を最初から用意する。

### 4. 入力依存のパラメータと尺度混合

Mamba系の選択的SSM（S6）では、入力に応じて状態への書き込みB、状態からの読み出しC、離散化刻みDeltaを変える。MS-SSMのS6版では、尺度sのSSMに入る変換後の値だけではなく、**元の入力x_t**から各尺度のB、C、Deltaを作る。これにより、尺度が違っても共通の入力に基づいて情報の保持・忘却を調整できる。付録の除去実験では、尺度ごとの入力から制御する場合より元入力を使う方がわずかに良い。

各尺度のSSMから時刻tの出力が得られたら、`S+2`個の値をベクトルy_tへ集める。入力依存の尺度混合器（scale mixer）は元の入力x_tから重みE_tを生成し、`z_t = E_t * y_t`として各尺度を加重和する。ある時刻では局所的な細部、別の時刻では長期傾向を強調できる。重みは入力から線形写像で作り、固定の平均ではない。ここまでの処理は、入力→多尺度畳み込み→尺度別SSM→入力依存混合→出力という一連の因果的な経路を持つ。

### 5. S4版とS6版の位置づけ

S4版は入力非依存の線形状態空間ブロックを使い、再帰計算の畳み込み表現を活用できる。一方S6版は入力依存のパラメータを使い、選択的走査（selective scan）で計算する。論文は両方を実装して比較し、多尺度畳み込みと混合器の効果が、特定の入力依存ゲートにしか成立しないわけではないことを示す。実際、ListOpsではS4版62.83%、S6版63.04%と近い。

ただし入力非依存のS4と入力依存のS6では、GPUでの効率的な計算経路、状態の更新方法、モデルの表現力が異なる。論文の実験はこの構造の有効性を主に**予測精度**で比較したものであり、GPUカーネルの速度やモデル全体のtokens/sをS4とS6で厳密に比較した結果ではない。

ListOpsでは、括弧が入れ子になった演算の中間結果を長く保持し、最後に組み合わせる必要がある。局所的なパターンを抽出するだけでなく、遠く離れた演算子と被演算子の依存を保持しなければならない。MS-SSMは尺度別のSSMで長距離の履歴を残し、入力依存の混合器で局所・大域を統合するため、Mamba単体より有利になったと考えられる。

ただし、MambaとのListOps差が約25ポイントあるからといって、自然言語LLMのベンチマークや実際の生成品質も同程度改善すると予測する根拠はない。ListOpsは人工的な階層演算タスクであり、言語モデルの次トークン予測、指示追従、長文推論の実機評価ではない。またImageNetではS4版がMambaより低いなど、どのSSMブロックを使っても必ず改善するわけではない。

## 構成要素の除去実験

| 構成 | PTB-XLの評価値 | ListOps正解率（%） | 何を確認するか |
|---|---:|---:|---|
| MS-SSM(S6) | 0.939 | 63.04 | 基準構成 |
| S6をS4へ変更 | 0.939 | 62.83 | 多尺度設計が入力非依存SSMでも成立 |
| SSMを除去 | 0.936 | 62.59 | 再帰状態の追加効果はListOpsで小さい |
| 多尺度畳み込みを通常Conv1dへ変更 | 0.916 | 37.98 | 多尺度分解が特にListOpsで重要 |
| 制御入力を尺度別へ変更 | 0.938 | 62.91 | 元入力からのゲートがわずかに有利 |
| 入力非依存の尺度混合へ変更 | 0.932 | 61.28 | 入力依存の混合器が改善に寄与 |

最も重要なのは、多尺度畳み込みを通常の1次元畳み込みへ置き換えるとListOpsが63.04から37.98へ大きく下がることである。SSMを除去した場合は62.59であり、ListOpsでの改善の大半が「多尺度分解」側に由来する可能性がある。論文の名称だけから「SSMの再帰能力が全改善を生む」と解釈してはいけない。

一方、入力依存の尺度混合を固定の混合へ変えると61.28へ低下する。入力に応じて細かな尺度と粗い尺度の重要度を切り替える設計も寄与している。PTB-XLではSSM除去やゲート変更の差が比較的小さいため、全タスクで同じ機構が支配的とは限らない。MS-SSMの優位性は「SSM単体」よりも、尺度分解・尺度ごとの記憶・動的混合を組み合わせた設計にある。

## 計算量・メモリ・実装上の注意

多尺度畳み込みの計算量は`O(L*K*S)`で系列長Lに線形だが、通常の単一尺度SSMへ比べると尺度数Sに応じた追加演算が必要になる。各尺度の中間系列は間引かれないため、訓練時の活性化メモリも増える。再帰状態の総次元を比較対象と揃えても、畳み込みの中間表現や尺度混合の一時領域まで同じメモリになるわけではない。

S4版は入力非依存の線形再帰を畳み込みとして処理できる一方、S6版は入力ごとにパラメータが変わるため選択的走査を必要とする。理論上の計算量だけではGPU上の速度を決められず、カーネル融合、畳み込みのメモリ配置、並列走査の効率が実装に影響する。論文はこれらをLLMサービングで比較していない。状態次元が一定でも、モデルの重みメモリ、並列化の通信、複数尺度の活性化は別途必要である。

実際のLLMへ組み込む場合は、学習済みTransformerのKVキャッシュを後処理で置き換えるパッチとは異なり、**モデルアーキテクチャ自体を変更する**必要がある。既存の学習済みTransformerへそのまま適用して速度だけ改善できるものではない。トークン埋め込み、因果畳み込み、尺度別SSM、尺度混合を持つモデルを訓練する必要があり、LLMの事前学習コスト、長文脈の生成品質、推論時のメモリ使用量は別途測定しなければならない。

## 既存研究との違い

Mambaは入力依存の状態更新で、現在のトークンに応じて情報の保持・忘却を選択する。MS-SSMはMambaのS6をそのまま用いる構成も評価するが、**複数尺度へ入力を分解して各尺度へ別のSSMを割り当てる**点が違う。つまりS6の選択的状態更新を置き換えるのではなく、その前後に多尺度の表現と混合を追加する。

MultiResNetやSGConvは長距離の畳み込みで多尺度・長期パターンを扱うが、MS-SSMは各尺度へ再帰的なSSM状態を持たせる。S4/S5はSSMによる系列記憶を主に扱うが、入力を多尺度へ分解して独立の状態群を学習させる設計ではない。Griffinは局所注意とゲート付き再帰を組み合わせるが、MS-SSMのような定常ウェーブレット由来の多尺度畳み込みと尺度依存初期化は中心ではない。

先行する周波数領域の多尺度表現には、全系列を用いる非因果的なフーリエ変換がある。MS-SSMは因果的な畳み込みで系列の未来を見ずに尺度表現を作るため、原理上は逐次入力に対応できる。ただし、因果的に定義されていることと、LLMの生成カーネルが高速であることは別問題である。

## 負の結果・限界

第一に、LRAの平均ではMS-SSM(S6)が86.73で、S4版91.89より低い。Megaの93.22やS5の92.52にも及ばない。したがって、入力依存S6と多尺度を組み合わせれば常に最良という結論は支持されない。sCIFARではS6が良いが、LRAではS4が良いというタスク依存性がある。

第二に、ImageNet-1KではMS-SSM(S4)が79.7で、Mambaの80.5、S4Dの80.4より低い。多尺度化が一律に改善するのではなく、SSMの種類とタスクが結果を左右する。さらにListOpsの除去実験では、SSMそのものを除去しても62.59と基準63.04に近く、主要な利得が多尺度畳み込みに偏る条件がある。

第三に、評価は画像分類、階層演算、長距離系列、心電図などが中心で、数B〜数十Bパラメータの言語モデルを事前学習した実験、実際のテキスト生成品質、長文脈のneedle-in-a-haystack、KVキャッシュ容量、GPU推論時間、TTFT、TPOT、サービングスループットは報告されていない。**効率的な系列モデルの設計研究**であることと、**LLM推論を実機で高速化した研究**であることを混同してはいけない。

第四に、複数尺度の中間系列を保持することで活性化メモリが増える可能性がある。状態総次元を揃える公平な比較は行っているが、同じハードウェア・同じGPUメモリ・同じ学習時間でのLLM比較を意味しない。論文から公式実装URLを確定できなかったため、コードの公開・実装最適化・上流推論基盤への統合状況は未確認とする。

## まとめ：推論基盤研究との接点

MS-SSMの価値は、SSMが持つ定常的な再帰状態の利点を維持しながら、短期の局所情報と長期の大域情報を別の尺度で保持する設計を示した点にある。特にListOpsの大幅な改善と、多尺度畳み込みを外したときの精度低下は、単一尺度の再帰だけでは階層構造を捉えにくいという問題設定を支持する。

LLM推論の観点では、長い文脈をKVキャッシュへすべて保持するTransformerに代わるアーキテクチャ研究として関係する。ただし、既存LLMへ後付けできるKV圧縮や推論高速化手法ではなく、モデル訓練から必要な設計変更である。採用判断には、大規模な言語事前学習、長文生成の品質、トークン当たりの実測レイテンシ、GPUメモリ、訓練費用を同一条件で比較する追加実験が必要である。
