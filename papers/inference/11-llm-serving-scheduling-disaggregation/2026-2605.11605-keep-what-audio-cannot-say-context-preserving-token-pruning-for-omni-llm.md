# ContextGuard：音声で説明できない視覚的文脈を守る入力トークン圧縮

## 概要

動画と音声を同時に理解する全モダリティ大規模言語モデルは、短い動画からも大量の映像トークンを作る。音声は短い特徴系列に圧縮されることが多い一方、映像はフレーム数と空間パッチ数に比例して長くなり、事前充填の計算、注意用メモリ、入力長の制限に影響する。一般的な映像枝刈りは注意の大きいトークンや質問と関係するトークンを優先するが、質問が変わったとき必要になる背景情報を落とす危険がある。

ContextGuardは、音声と映像の**一致している部分を残す**という発想を逆転させる。音声だけで予測できる粗い視覚意味を重複とみなし、音声からは分からない文字、色、物体の姿勢などの視覚情報を保持する。そのために音声から視覚意味を推測する予測器、空間的な細部を救う格子選択、時間的な重複を減らす区間統合を組み合わせる。復号器を追加学習せずに入力列を短縮するが、予測器自体は別途学習する。

Qwen2.5-Omni 7Bの6つの音声映像課題では、入力トークンを平均55%減らして、無圧縮を100とする正規化平均性能100.0を得た。これは全課題の正答率100%でも全条件で無劣化でもない。同モデルのAVQAは87.6から87.1に下がり、Video-SALMONN2+ 3Bの正規化平均は96.9に下がる。別の速度測定ではQwen2.5-Omni 7Bの総遅延が6.7秒から4.5秒へ短縮した。これらは異なる評価集合の数値であり混ぜて解釈しない。

## 問題設定：なぜ音声と一致する映像を捨てるのか

動画を音声と映像の時間チャンクへ分ける全モダリティモデルでは、各チャンクに大量の視覚埋め込みと比較的少量の音声埋め込みが含まれる。車のエンジン音から車が走っていることは推測できるが、車体色、看板の文字、画面内の曜日表示までは確定しない。既存の音声整合型の選択方式では、音声とよく一致する車の領域が残り、質問の答えになる看板が削除され得る。ContextGuardは、音声の持つ情報を利用して映像の冗長部分を見つけることを目的とする。

論文は映像系列をV、音声系列をA、圧縮後の映像をZとし、条件付き相互情報量 I(V;Z|A) と圧縮列の計算費用 C(Z) を組み合わせた理想的な目的を示す。直観的には、音声を知っていてもなお映像から新しく得られる情報を残し、そのために必要なトークン数を抑える。ただし実装がこの相互情報量を直接推定・最適化するわけではない。類似度に基づく選択と統合は、その目的に近づけるための経験的な近似である。理論上の目的関数があることを、品質保持の数学的保証と取り違えてはならない。

従来のFastVは注意に基づく重要度で映像トークンを減らす方式であり、OmniZipは音声の顕著な出来事に整合する視覚情報を保持する。ContextGuardは逆に、音声から説明できない視覚的証拠を優先する。この違いは、単一の既知質問にだけ最適化するのではなく、あとからどのような質問が来ても使える文脈を残すという設計目的に結びつく。一方、視覚的証拠の重要度を質問なしで完全に決めることは不可能であり、後述の空間格子も細部の保存を保証しない。

## 手法

### 1. 音声から視覚意味を推測する軽量予測器

各チャンクtについて、既存の音声符号化器の特徴 hᵃ と映像符号化器の特徴 hᵛ を受け取る。音声から視覚意味を推測する小型予測器（A2V predictor）は、学習可能な問い合わせベクトルを使った交差注意（cross-attention）で音声特徴を参照し、音声から予測できる粗い視覚埋め込みを出力する。標準設定は問い合わせ128個、交差注意2層と多層パーセプトロンである。問い合わせごとの予測結果を平均してチャンクの代表ベクトルを作る。

各映像トークンとその代表ベクトルの余弦類似度 u(t,j) を計算する。類似度が高ければ、その視覚特徴は音声から予測できる粗い意味に近いと解釈する。ここでは高いものを残すのではなく、**低い順に**意味選択率ρ_sem=0.5の映像トークンを残す。例えば走行音と一致する車の粗い特徴より、音声だけでは説明できない字幕や背景を優先する。これは「低類似度なら必ず重要」という意味ではなく、音声で重複説明できない可能性を利用した順位付けである。

予測器の学習にはAudioSetとVGGSoundを用い、対応する音声・映像の余弦類似度を上げる損失と、別動画の組を負例とする対照損失を組み合わせる。原著の付録では対照学習の温度0.07、余弦損失の係数5.0、バッチ8、勾配累積2、4基のGPUによる約1万～1万5000ステップを示す。予測器を固定して推論時に使うため、Qwen2.5-OmniやVideo-SALMONN2+本体を再学習する必要はない。ただし「学習不要の枝刈り」と一括りにしてはならず、圧縮器側の訓練・実行費用が残る。

### 2. 格子による空間細部の保護

意味選択だけでは、音声と関連する物体の内部にある色や小さな文字を落としやすい。そこで映像チャンクのFフレーム×H×Wの特徴をフレーム方向に平均し、H×Wの特徴地図を作る。この地図を格子セルに分割し、各セルの内部で上下左右の近傍特徴とのL2距離の合計が大きい位置を代表として選ぶ。変化の大きい位置は境界や局所細部を含む可能性があるためである。

標準の空間保持率ρ_spa=0.1に対応する位置を選び、その位置をチャンク内の各フレームに適用する。意味選択の位置集合と空間選択の位置集合を和集合にするため、両方で選ばれた位置は一度しか保持しない。したがって保持率は0.5+0.1と単純に加算できず、時間統合後の最終圧縮率とも異なる。WorldSenseを使った分析では両集合の交差率が低く、空間分岐が意味選択と異なる位置を補っていることが示される。

この空間分岐は全領域から代表位置を確保する設計であり、重要度を完全に理解する認識器ではない。フレーム間で同じ空間位置を再利用するので、速く動く小物体や短時間だけ出る文字の位置が変わると取りこぼしが起こり得る。格子の粒度を増やせば細部の保持は改善し得るが、削減できるトークン数は減る。つまり空間的な保護は、圧縮率と文脈保持の交換条件を調整する役割を持つ。

### 3. 音声と映像の変化点に沿った時間区間の統合

意味・空間選択後も、隣接する映像チャンクには似た画面が繰り返し含まれる。単純に隣接チャンクを平均すると、場面が切り替わった瞬間の情報を失うため、まず音声と映像のそれぞれでチャンク平均特徴の隣接余弦類似度を計算する。前後の類似度に比べて局所的に低い位置を深さ得点（depth score）で検出し、音声・映像の境界候補の和集合で時間区間を区切る。二つのモダリティのいずれかが変わったとき区間を分ける設計である。

区間内では、各チャンクの音声由来の意味類似度を平均して共通の意味選択位置を決め、空間位置は区間先頭チャンクから引き継ぐ。これにより異なるチャンクの映像トークンを同じ位置同士で比較できる。隣接チャンクの映像特徴類似度が閾値τ_merge=0.98を超えた場合に、対応する保持トークンの埋め込みを平均して統合する。音声トークン自体は削除せず、最終的な音声と映像の並び順を復号器に渡す。

区間境界の判定には後続チャンクの類似度も使うため、主要方式は動画全体を見渡せるオフライン推論を想定する。動画を1チャンクずつ即時処理する厳密なライブ配信に同じ処理をそのまま適用できない。論文は局所的な隣接類似度だけを用いるオンライン向け簡易変種も評価するが、これをライブ応答の実測遅延や同一品質の証明として扱わない。

### 4. 全体のデータフローと追加費用

1つの入力動画は、既存の音声・映像符号化器で時間チャンクの特徴へ変換される。各チャンクの音声特徴から小型予測器が粗い視覚意味を生成し、映像特徴のうち低類似度の位置を意味選択する。同時に空間格子が局所変化の大きい位置を選び、両集合を統合する。次に音声・映像の時間的変化点から区間を作り、区間内の共通位置にそろえて類似チャンクを統合する。残った映像トークンと元の音声トークンを、既存モデルの復号器へ入力する。

この処理は映像トークン数を減らす一方、予測器の交差注意、特徴の類似度計算、格子内の近傍差分、時間区間の検出、埋め込み統合の費用を新たに生む。元の映像符号化器そのものの処理量が55%減るという主張ではない。復号器の事前充填が支配的な条件ほど利益が見込めるが、短い動画や低負荷条件では圧縮前処理の比率が高くなる可能性がある。この区別は後述の速度・メモリの実測結果にも現れる。

## 評価

### 実験環境・比較条件

| 項目 | 一次論文に記載された条件 |
|---|---|
| 下流モデル | Qwen2.5-Omni 3B/7B、Video-SALMONN2+ 3B/7B |
| ハードウェア | NVIDIA A6000、GPUメモリ48GB |
| 課題 | WorldSense、Daily-Omni、Video-MME、OmniVideoBench、AVQA、video-SALMONN2 testの6件 |
| 品質指標 | 最初の5課題は正答率（大きいほど良い）、最後は総誤り率（小さいほど良い） |
| 比較対象 | 無圧縮、無作為選択、FastVの音声映像拡張、OmniZip |
| 共通設定 | ρ_sem=0.5、ρ_spa=0.1、τ_merge=0.98 |
| 評価上の制限 | WorldSense、Video-MME、OmniVideoBenchは無圧縮モデルのGPUメモリ制約により1分未満の動画を評価 |

正規化平均は各課題の無圧縮性能を100として相対化し、動画説明の誤り率には逆比率を用いて平均する。したがって100.0は各課題の生の正答率ではない。比較方式の圧縮率は完全には一致せず、圧縮率が近い比較と、無圧縮との差を区別する必要がある。特に無圧縮比較で用いた短い動画の部分集合は長時間動画の品質を保証しない。

### 構成要素除去実験と仮説の確認

Qwen2.5-Omni 7BのWorldSense/Daily-Omniでは、意味選択だけで47.7/56.4、圧縮46%となる。空間細部の保持を追加すると48.1/56.8へ改善するが圧縮率は40%へ低下する。さらに時間統合を加えると47.7/57.2、圧縮52%となる。空間分岐が情報を追加し、時間統合が重複を減らすという役割分担が読み取れる。最終構成の全課題平均55%と、ここでの2課題における52%は別の集計であり混同しない。

音声から予測した視覚意味との**低類似度**を残す中心仮説は、選択方向の反転実験で検証される。Qwen2.5-Omni 7Bでは、高類似度を残す方式のWorldSense/Daily-Omniが45.2/53.8で、最初の生成トークン分布と無圧縮分布のKL距離は0.079となる。低類似度を残す提案方式では47.7/57.2、KL距離0.028である。無作為保持のKL距離は0.039。KL距離は二つの出力分布の差であり、低いほど無圧縮の振る舞いに近い。少なくともこのモデルと評価では低類似度を残す方が、音声に重複する映像を残すより有効である。

予測器そのものの妥当性はVGGSoundの音声→映像検索でも測定される。Qwen2.5-Omni 7Bで元の音声埋め込みを直接使うと上位1件の検索再現率は5.8%、上位5件は17.8%、順位中央値44である。音声から視覚意味を予測した埋め込みでは12.9%、36.9%、順位中央値11へ改善する。Video-SALMONN2+ 7Bでも上位1件2.3%→8.7%、上位5件8.4%→24.0%となる。ただし検索精度が高いことは、下流の全質問への正答保証とは異なる。

時間統合の比較ではVideo-SALMONN2+ 7BのWorldSense/Daily-Omniが、固定3チャンク分割で49.3/54.3、区間単位で代表チャンクだけ残す方式で49.2/54.3となる。提案する区間内平均統合では50.6/55.5である。意味の切替点に沿った区間形成と、代表チャンクの単純削除ではなく埋め込みを平均することの利点が確認できる。一方、モデルや課題を替えたときに同じ差が必ず再現するとは言えない。

### オンライン向け簡易変種

主要方式は将来のチャンクも見て時間境界を決める。付録の簡易変種は直前チャンクとの類似度が0.99を超える場合に前のチャンクを削除するなど、局所情報だけを使う。Qwen2.5-Omni 7Bでは、オンライン向け変種の圧縮率50%、WorldSense47.1、Daily-Omni56.1に対し、オフライン版は圧縮52%、47.7、57.2である。Video-SALMONN2+ 7Bではオンライン向けが50%、51.2、55.4、オフライン版が54%、50.6、55.5となる。局所変種は一部の課題で勝つ場合もあるが、全体としての遅延・メモリ・実ストリーミング条件の検証は限定的である。

## 限界・負の結果・導入判断

まず、予測器が音声から説明できる映像の意味を正確に推定できることを前提とする。音声と映像の対応が弱い、背景音が多い、字幕や背番号などの細部が音声から予測できない場合、低類似度の選択と格子による保護だけでは重要なトークンを確実に残せない。原著の失敗例には細い文字やスポーツ選手の背番号、表情の手掛かりを落として回答を誤る事例がある。高い平均値だけで失敗例を消してはならない。

次に、圧縮器には別途学習と追加の計算が必要である。下流モデルを微調整しないことは、方式全体が無学習・無費用であることを意味しない。A6000 48GBでの単発動画評価から、異なるGPU、複数同時要求、長時間ストリーム、サーバーのP95/P99遅延やトークン毎の復号速度に同じ改善が得られるとは結論できない。メモリ削減も映像入力の圧縮率に比例しない。

最後に、主方式の時間区間決定は将来の情報を参照するため、ライブ会話やリアルタイム監視へそのまま導入できない。オンライン向け変種の品質評価はあるが、実サービスでの逐次処理遅延や長時間の品質は未検証である。対象として適するのは、音声と映像の両方が存在し、動画をまとめて入力し、事前充填費用が大きい推論である。テキスト専用モデルのKVキャッシュ圧縮、復号ステップの高速化、映像符号化器自体の計算削減とは異なる問題を解いている。
