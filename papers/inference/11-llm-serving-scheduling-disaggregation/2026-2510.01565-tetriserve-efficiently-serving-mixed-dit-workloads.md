# TetriServe：異なる画像解像度・締切を持つDiT要求のstep単位GPU割当

## 概要

Diffusion Transformer（DiT）は画像生成で高い品質を示すが、複数回のdenoising stepを順番に実行する必要があり、高解像度では1要求あたりの計算時間が長くなる。GPUを複数枚使うsequence parallelism（SP）は大きい画像を高速化できる一方、小さい画像では通信費用が増えてかえって効率が悪い。固定SP=1/2/4/8を要求単位で選ぶ既存サービングでは、画像解像度と締切が混在すると、ある要求にGPUを過剰配分し、別の要求が待ち行列で締切を逃す。

TetriServeは、**要求のdenoising stepごとにGPU並列度を変えられる**スケジューラを設計する。時間を短いラウンドへ区切り、各ラウンドで締切に間に合う最小GPU割当を求め、余ったGPUを他の要求へ回す。さらにGPU配置の維持、空きGPUの弾力的な追加配分、同解像度の小さい要求だけを選ぶバッチ処理を組み合わせる。

FLUX.1-devを8枚のH100、SD3 Mediumを4枚のA40で実測し、固定SP方式に対してSLO達成率を最大32%改善したと報告する。これは画像生成のサービングであり、**LLMの自己回帰トークン生成のスループットを32%改善したという結果ではない**。LLMサービングのGPU配置・締切スケジューリングに参考になるが、モデル実行パターンは異なる。

## 問題設定：解像度と並列度の不一致

DiTのdenoisingでは、同じモデルでも256×256と2048×2048で潜在トークン数が大きく異なる。SPを増やすと大きい画像の処理は速くなるが、小さい画像ではGPU間のall-to-allなどの通信が計算に対して大きくなる。固定SP=8で小画像を処理すれば多くのGPUを長時間占有し、他要求の実行を妨げる。逆に固定SP=1では大画像のstepが長く、厳しい締切を守れない。

さらに、従来のDiT実行エンジンは要求を開始すると同じGPU集合を完了まで保持する非プリエンプティブな設計が多い。要求の前半は余裕があっても、後半に締切が近づいたときにGPUを増やせない。TetriServeは、要求のstepの途中ではなく**step境界でGPU台数を変える**ことで、状態転送を比較的軽くしながら実行計画を変更する。

著者は各stepのGPU並列度と物理GPU配置を含む最適な締切充足スケジュールの問題を定式化し、NP-hardであることを示す。要求数とGPU台数が増えると全探索は実用にならないため、ミリ秒単位で判断できる近似的なラウンド型スケジューラが必要になる。

## 手法：ラウンド型のdeadline-aware GPU割当

### 1. 実行時間のオフラインプロファイル

各モデル・解像度・GPU台数で、1 denoising stepの実行時間を事前に測る。スケジューラは要求の残りstep数、締切までの残時間、SP台数ごとの予測実行時間から、締切を満たせる最小のGPU割当を求める。単純に最速SPを選ぶのではなく、**GPU時間を節約して他要求へ回す**ことを目的とする。

この費用モデルはGPUの相互接続にも依存する。H100ノードのNVLinkと、A40のペア内NVLink・ペア間PCIeでは同じSP=4の通信費用が違う。したがって、別GPU機種へ移植するときはプロファイルを再測定する必要がある。

### 2. 固定時間のラウンドへ離散化

時間をラウンド長τで区切り、各ラウンドで複数のdenoising stepを実行する。τが短いと新しい要求を早く取り込めるが、スケジューリング回数が増える。長いとオーバーヘッドは減るが、新規要求の待ち時間が伸び、締切違反が増える。著者はモデルのstep実行時間を参考に、複数stepが同じラウンド境界で終わりやすい長さを選ぶ。

各ラウンドでは、締切に間に合う最小GPU台数の候補を列挙し、要求をGPU集合へ詰め合わせる。計画の目的は単純なGPU利用率最大化ではなく、**次のラウンドで締切に遅れる要求をできるだけ少なくする**ことにある。ラウンド型の動的計画法と近似規則により、実行中の要求を全探索しないで割当てを決める。

### 3. GPU配置維持とElastic Scale-up

ラウンドごとにGPU集合を変更すると、中間潜在状態の転送や通信グループの切替えが発生する。そこで、前ラウンドと同じGPUを可能な限り使う**Placement Preservation**を導入する。これによりGPUの再配置に伴う空白時間を減らす。

割当て後にGPUが余った場合は、追加GPUでstepが速くなる要求へ一時的に割り当てる**Elastic Scale-up**を行う。締切が近い大画像要求にGPUを増やし、余裕のある小画像要求には少ないGPUを維持する。これによりGPUを遊ばせず、次のラウンドでの待ち行列も減らす。

### 4. 実装上の工夫

実装はPython/C++約5,033行で、xDiTのSP実行、vLLMの非同期処理、MuxServe/SGLangのプロセス起動を再利用する。C++スケジューラの決定時間は10ms未満で、数十秒かかる全探索とは異なる。

NCCL通信グループは最初の使用時に永続バッファを確保するため、考えられる全GPU組合せを事前にウォームアップするとHBMを圧迫する。著者は頻出する少数の組合せだけを事前ウォームアップし、残りは必要時に初期化する。中間潜在状態は非同期転送し、測定した転送費用はstep時間の最大0.05%と小さい。一方、VAEデコーダは高解像度で一時メモリを大きく使うため、要求ごとに逐次実行してピークメモリを抑える。

Selective Continuous Batchingは、同じ小解像度で締切を侵害しない要求だけをまとめる。異なる解像度を無条件に一つのバッチへ詰めるわけではない。これはDiT特有のstep単位の状態管理を前提としており、LLMのprefill/decode混合バッチとは異なる。

## 評価条件

| 項目 | 内容 |
|---|---|
| モデル | FLUX.1-dev、Stable Diffusion 3 Medium |
| GPU | H100 80GB×8（NVLink 4.0）、A40 48GB×4（ペア内NVLink、ペア間PCIe） |
| ソフトウェア | CUDA 12.5、NCCL 2.22.3、PyTorch 2.4.0、xDiT特定コミット |
| データ | DiffusionDBから300プロンプトを抽出 |
| 到着 | 基本Poisson過程、12要求/分。burstinessも評価 |
| 解像度 | 256、512、1024、2048ピクセルの正方画像 |
| 混合比 | Uniform（4解像度均等）、Skewed（大画像寄り） |
| SLO基準 | 256:1.5秒、512:2.0秒、1024:3.0秒、2048:5.0秒。scale 1.0～1.5倍 |
| 比較 | xDiT固定SP=1/2/4/8、解像度別最適固定SPを選ぶRSSP |
| 指標 | SLO Attainment Ratio（SAR、締切内完了要求の割合）、平均・tail latency |

SLO scale=1.5は各解像度の基準時間を1.5倍に緩める設定であり、1.5倍速いという意味ではない。画像品質の指標は実行スケジューラが同じdenoising計算を行うため原理的に維持されるが、出力画像の主観的品質を直接比較した大規模ユーザー評価ではない。

## 主要結果：SLO達成率の改善

FLUX/H100で12要求/分の混合負荷では、最良の固定SP方式に対して平均SARがUniformで約10%、Skewedで約15%改善する。特定のSLO条件ではUniformの1.1倍SLOで28%、Skewedの1.2倍SLOで32%の相対改善を報告する。これは**最大値と平均値を区別すべき結果**であり、すべての解像度・負荷で32%改善するわけではない。

固定SP=1は小画像では良いが大画像の締切に弱い。固定SP=8は大画像を速く処理する一方、小画像で通信オーバーヘッドとGPU占有が増える。RSSPは解像度ごとに最良SPを選ぶ強いベースラインだが、同じ解像度でも要求の残り締切や待ち行列状況に応じてstep単位でGPU数を変えられない。TetriServeはその柔軟性によって、異なる解像度が混ざる場合のSLO達成率を高める。

ただし原著Figure 7～8の曲線はSLO scaleと混合比に依存し、個別の解像度では固定SP=1がわずかにTetriServeを上回る条件もある。これは**全要求・全解像度で常に最良ではない**という負の結果である。混合ワークロード全体での達成率を改善する設計であり、単一解像度だけのベンチマークでは優位が小さくなる場合がある。

## 評価結果：配置保持と追加GPU割当

| 混合負荷 | SLO scale | 基本ラウンドスケジューラSAR / 平均遅延 | 配置保持追加 | Elastic Scale-up追加 |
|---|---|---|---|---|
| Uniform | 1.0 | 0.54 / 4.45秒 | 0.56 / 3.96秒 | **0.63 / 3.89秒** |
| Uniform | 1.5 | 0.74 / 4.81秒 | 0.69 / 5.14秒 | **0.78 / 4.83秒** |
| Skewed | 1.0 | 0.27 / 8.43秒 | 0.31 / 7.64秒 | **0.36 / 7.68秒** |
| Skewed | 1.5 | 0.38 / 9.92秒 | 0.45 / 8.16秒 | **0.55 / 7.71秒** |

原著Table 5。Elastic Scale-upはすべての設定でSARを改善する。Skewed/SLO1.5では基本0.38から最終0.55へ0.17の絶対改善である。**配置保持だけではUniform/SLO1.5でSARが0.74から0.69へ下がる**ため、配置保持を単独で常に有利とは言えない。著者の「両者が重要」という結論は、最終構成の性能と複数条件の平均を踏まえたものだ。

平均遅延は成功要求だけの条件付き値ではなく、負荷全体の遅延分布にも左右される。SARが上がると以前は完了できなかった重い要求が完了するため、平均遅延が必ず単調に下がるとは限らない。SLOと平均遅延は異なる目的関数として扱う必要がある。

## オーバーヘッドとハードウェア依存

全探索の正確解を求める比較では、8GPU・3要求の時点で60秒のタイムアウトを超えた。TetriServeの計画決定は10ms未満であり、オンラインのラウンド制御が可能になる。GPU集合の変更に伴う潜在状態転送は測定した構成でstep時間の0.05%以下だが、NCCLグループの初期化は永続バッファを確保するため、全組合せを事前にウォームアップするとHBM不足になる。このため一部グループのみ事前準備する設計が必要である。

A40ではGPUペア間がPCIeになるため、SP=4の通信がNVLinkのみのH100と比べて不利になり、SP=2でも配置を誤るとPCIeを跨ぐ。TetriServeはGPUの物理配置を保持・考慮するため、同じSP台数でもどのGPU集合を選ぶかが重要になる。これは、単純な「GPU台数を増やすほど高速」という仮定が破れる条件である。

Burstiness評価では、固定SP方式は要求到着の山でGPU利用の空白と待ち行列が生じ、SARが周期的に低下する。TetriServeは要求の締切と残stepに合わせてSPを変え、相対的に安定したSARを維持した。ただし評価は限られた2モデル・2ハードウェア構成であり、数百GPUの本番クラスタや異なる通信トポロジーで同じ結果になるとは限らない。

## 限界：既存研究との差

xDiTはDiTのsequence parallelismを実装するが、サービング中に要求のSPを柔軟に変えるスケジューラを提供しない。TetriServeはその実行エンジンを活用し、**step境界で並列度を変える制御面**を追加する。vLLMやSGLangの非同期実行や起動機構を一部再利用するものの、LLMのprefill/decode最適化をそのままDiTへ適用したわけではない。

本方式の限界は、事前のstep時間プロファイルがモデル・解像度・GPU構成に依存すること、通信グループの初期化や潜在状態転送を完全には無視できないこと、ラウンド長の選択が待ち時間とスケジューラ費用の交換になること、厳しいSLOや極端な大画像偏重負荷ではSARが依然として低いことだ。例えばSkewed/SLO1.0では最終SARでも0.36で、64%の要求が締切に間に合わない。固定方式より良いことと、十分なサービス品質を達成したことは別である。

さらに画像生成はdenoising stepが比較的規則的で、step単位のGPU再配置をしやすい。自己回帰LLMのKVキャッシュは要求ごとに長さが伸び、GPU間で巨大なKVを移動すると費用が大きくなる。DiTの中間latentが小さく転送費用0.05%以下だったという結果を、LLMのKV移動にも適用できるとは限らない。

実務的には、画像生成サーバで異なる解像度と締切を混在させる場合に有効な設計である。LLMサービング研究へ応用するなら、要求の残り計算量の推定、GPU再配置の状態転送、通信トポロジー、deadline-awareなリソース配分を別途設計し直す必要がある。TetriServeの本質は**固定並列度ではなく、実行中の段階に合わせてGPUを再配分する**というスケジューリング原理にある。
