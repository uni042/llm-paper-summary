# HoneyRoute: Honeypot-Model Routing for Adversarial LLM Serving

> 悪意要求を安価なハニーポットへ分流し、本番GPU保護と攻撃指紋収集を両立するサービング層ルータ。
## 書誌情報
- **著者**: Han Jin
- **公開**: arXiv:2609.08306v2
- **種別**: arXivプレプリント
- **対象**: adversarial serving、honeypot ルーティング、resource protection
- **実装**: vLLM本番8B・複製9B、凍結0.8B埋め込みと領域別MLP、GPU不要コードハニーポットを統合。
## 概要
API入口で悪意要求を38ms中央値の小型ルータで検出し、本番モデルではなくGPU不要または同系列複製のハニーポットへ迂回する。捕捉対話を指紋化して次世代検出器へ戻し、同時攻撃時の本番トークン消費を97.8%削減する。 LLMの公開APIでは、脱獄、抽出、長文フラッディングなどの悪意要求が本番モデルと同じ推論資源を消費する。 従来のガードモデルは遮断判定のために高価な二段目モデルを呼び、ハニーポットはSSH等のプロトコル層か単一モデル内部に置かれていた。

HoneyRouteは要求を拒否するのではなく、凍結0.8B埋め込み器と攻撃領域別の小型MLPで要求を採点し、悪意側だけを専用ハニーポットへ経路変更する。ハニーポットはGPU不要の規則・プロンプト実装と、同系列9B複製モデルの二方式を持ち、攻撃種別で費用と忠実度を選べる。捕捉した対話を戦術、目的、行動特徴へ要約して次世代ルータ学習へ戻す閉ループも統合し、単なる防御フィルタではなく資源隔離・欺瞞・フォレンジック収集を一つの推論経路制御にする。

代表結果として、ルーティング detectionはheld-out seven-domain attacksでtwo-tier cascade F1=.948, 14.6s p50に対してP=.903 R=.918 F1=.911 AUROC=.975, 38ms p50。大型ガードを直列に呼ぶ方式に近い検出力を維持しながら、API入口で要求ごとに経路変更できる遅延まで判定コストを下げる。
## 問題設定
LLMの公開APIでは、脱獄、抽出、長文フラッディングなどの悪意要求が本番モデルと同じ推論資源を消費する。従来のガードモデルは遮断判定のために高価な二段目モデルを呼び、ハニーポットはSSH等のプロトコル層か単一モデル内部に置かれていた。そのためAPIゲートウェイで悪意要求を安価に識別し、本番GPUから隔離しつつ攻撃者の行動を継続観測するサービング層の仕組みが欠ける。単純な囮応答は攻撃者に露見しやすく、精巧な複製モデルは追加GPU費を要するため、検出遅延、囮の忠実度、追跡可能性、資源防御を同時に扱う必要がある。
## 新規性
HoneyRouteは要求を拒否するのではなく、凍結0.8B埋め込み器と攻撃領域別の小型MLPで要求を採点し、悪意側だけを専用ハニーポットへ経路変更する。ハニーポットはGPU不要の規則・プロンプト実装と、同系列9B複製モデルの二方式を持ち、攻撃種別で費用と忠実度を選べる。捕捉した対話を戦術、目的、行動特徴へ要約して次世代ルータ学習へ戻す閉ループも統合し、単なる防御フィルタではなく資源隔離・欺瞞・フォレンジック収集を一つの推論経路制御にする。
## 手法
### 手法のあらまし
要求がAPI入口へ到着すると、まず約0.8Bパラメータの凍結埋め込み器が要求表現を生成し、七つの攻撃領域ごとに独立した約0.07Mパラメータの小型分類頭が危険度を計算する。各分類頭の出力は検証集合で求めた領域別閾値により正規化され、最大正規化危険度が一以上なら要求を本番8Bモデルから切り離してハニーポット経路へ送る。骨格を固定して分類頭だけを追加学習するため、新しい攻撃族を導入しても全ルータを再学習する必要がなく、既存領域の表現を崩しにくい。単発要求を閾値未満へ分割する多ターン攻撃には、セッション追跡器が直近ターンの危険度、累積値、上昇傾向を保持し、個々のターンが弱くても継続的なエスカレーションを検知して再検査または迂回を発火する。迂回後は攻撃特性に応じて二種類のハニーポットを選ぶ。GPU不要版はテンプレート、キャッシュ済み例、短い応答、選択的な自然文囮を組み合わせ、長文フラッディングを高価な生成から外す。高忠実度が必要な場合は本番と同じチャット形式を持つ同系列9B複製モデルへ送り、応答本文を改変せず側路ログから追跡信号を得る。捕捉したセッションは戦術、狙う能力、埋め込み特徴、要求間隔、識別子安定性へ要約され、同一攻撃キャンペーンの再結合と次世代分類頭の弱教師データに使われる。さらに良性のセキュリティ研究が誤迂回された事例を補正頭へ戻して閾値を改善し、検出、資源隔離、欺瞞、フォレンジック、再学習を閉ループ化する。

### 凍結埋め込み・領域別ルータ
約0.8Bの埋め込み骨格を固定し、七つの攻撃領域ごとに約0.07Mパラメータの分類頭を持つ。各頭の確率を検証時に校正した領域別閾値で割り、最大正規化値が一以上なら本番モデルではなくハニーポットへ迂回する。骨格を固定するため新しい資源枯渇攻撃などを追加しても既存表現を再学習せず、小型頭だけを追加できる。これにより更新費用と表現ドリフトを抑えつつ攻撃領域を拡張できる。七領域の保留データでは適合率0.903、再現率0.918、F1 0.911、AUROC 0.975を達成し、判定遅延中央値は38msだった。二段ガードはF1 0.948だが中央値14.6秒を要するため、この部品がオンライン経路制御を可能にする遅延差を作る。

### 二種類のハニーポット
迂回要求を一律に同じ囮へ送らず、資源節約を優先するGPU不要版と、攻撃者に露見しにくい高忠実度9B複製版を使い分ける。GPU不要版は意図別テンプレート、キャッシュ済み例、短い応答、自然な囮情報を用いて長文フラッドを本番生成から切り離す。複製版は本番と同じチャット形式で動かし、応答本文を変えず側路ログから追跡信号を取得する。無条件に囮を挿入すると良性応答一致率は7.6%まで落ちるが、危険度やカナリア探索信号がある場合だけ自然文囮を挿入すると88.9%へ回復し、複製モデルは92.9%を保つ。この二段構成により攻撃種別ごとにGPU費、応答忠実度、追跡情報量を運用上の交換条件として選べる。

### セッション追跡と継続分析
単発要求の危険度だけでは、攻撃者が目的を複数ターンへ分割して各要求を閾値未満に保つソフトエスカレーションを見逃す。そこでセッション追跡器は直近危険度、累積危険度、上昇傾向を保持し、弱い要求が連続した場合にも再検査や迂回を発火する。捕捉後は攻撃戦術、狙う能力、埋め込み上の行動特徴、要求間隔、識別子の安定性を指紋へまとめ、APIキー等を変えた要求をキャンペーン単位で再結合する。この指紋と捕捉トレースは次世代ルータの弱教師データへ戻され、良性のセキュリティ研究を誤迂回する事例から補正頭も学習する。補正後は誤迂回率が0.30から0.033へ低下し、全体F1も0.911から0.933へ改善しており、捕捉機構が単なるログ保存ではなく検出器の継続改善へ接続される。

### 資源防御と忠実度・追跡可能性制御
ルータの最終目的は危険要求を分類すること自体ではなく、高価な本番生成へ流れる悪意トークンを別経路へ移すことである。同時フラッディング実験では本番モデルの生成トークンが708,077から15,351へ減り、97.8%削減された。これにより攻撃者が要求数や生成長を増やしても、本番GPUの計算量へそのまま転嫁されにくくなる。一方、囮信号を応答本文へ強く埋め込むほど追跡情報は増えるが本番応答との差も増えるため、危険信号時だけ自然文囮を使う方式と、応答を変えず側路計測する複製方式を選択する。運用では本番費、ハニーポット費、忠実度、追跡可能性を同じ経路制御の変数として扱い、攻撃種類と負荷に応じて資源保護と欺瞞品質を調整する。

### 全体のデータ／制御の流れ
API入口、ストリーミングルータ、本番8Bモデル、GPU不要ハニーポット、9B複製ハニーポット、セッション追跡器、捕捉後の継続分析器からなる。本番と複製はvLLMで動かし、ルータが攻撃領域と危険度に応じて本番、軽量囮、高忠実度囮のいずれかを選ぶ。捕捉ログはオンライン応答経路から分離して保存され、キャンペーン再識別と分類頭の更新へ利用される。
## 評価条件
- **ハードウェア**: 1×8 NVIDIA H20 node
- **ソフトウェア**: vLLM、frozen 0.8B embedding ルーティング、per-domain MLP heads
- **データセット／トレース**: 710 production-トレース リクエスト、seven-domain attack seeds、JailbreakBench 496 prompts、13 adversarial transformations、multi-turn soft escalation
- **比較対象**: keyword/regex heuristic、SingGuard-8B guard LLM、two-tier guard cascade
各実験ブロックで検出、忠実度、資源防御、学習ループ、再識別、多ターン検出を個別に測定する。
単一モデル系列・単一8×H20環境で、教師判定にはGLM-5.3を主使用。実商用攻撃分布や他モデル族への一般化は未検証。
## 主要結果
HoneyRouteは、悪意要求の検出精度を大きく犠牲にせず、ガード用大型モデルを直列実行する方式より経路判定を大幅に軽量化し、攻撃時に本番GPUへ流れる生成負荷そのものを隔離できることを示した。凍結0.8B埋め込み器と領域別小型分類頭によるルータはF1 0.911、AUROC 0.975を38ms中央値で達成し、F1 0.948だが14.6秒中央値を要する二段ガードに対して、オンラインAPI入口で使える遅延水準へ検出を落とし込む。同時フラッディングでは本番モデルの生成トークンを708,077から15,351へ減らして97.8%削減し、単なる拒否判定ではなく推論資源の保護に直結することを実証した。さらに、複製ハニーポットは良性応答一致率92.9%、危険信号時だけ囮を入れる軽量方式は88.9%を保ち、無条件囮の7.6%より大幅に高い忠実度を得る。捕捉データを補正頭へ還流すると誤迂回率が0.30から0.033へ低下しF1も0.933へ改善するため、運用中に得た攻撃トレースを次の防御へ利用できる閉ループとしても機能する。

- ルーティング detection / P=.903 R=.918 F1=.911 AUROC=.975, 38ms p50 (比較対象: two-tier cascade F1=.948, 14.6s p50; 条件: held-out seven-domain attacks) — 大型ガードを直列に呼ぶ方式に近い検出力を維持しながら、API入口で要求ごとに経路変更できる遅延まで判定コストを下げる。

- production トークン protection / 708,077→15,351 トークン, 97.8% cut (比較対象: production serving; 条件: concurrent flooding) — 悪意生成を本番GPUから安価なハニーポットへ隔離し、攻撃者が生成長を増やしても本番推論資源の消費へ直結しにくくする。

- honeypot fidelity / trained .929; naive code .076; selective code .889 (比較対象: production response agreement; 条件: 300 benign holdout) — GPU不要の軽量囮でも選択的挿入なら本番応答との差を抑えられ、高忠実度が必要な場合だけ複製モデルへ費用を払う運用が可能になる。

- feedback loop / misroute FPR .30→.033; F1 .911→.933 (比較対象: before correction head; 条件: legitimate security research correction) — 捕捉トレースを補正学習へ戻すことで、良性セキュリティ研究などの誤迂回を継続的に減らせる。

### 負の結果・境界条件
- 無条件囮挿入は忠実度を7.6%まで崩す。
- 選択囮も良性トレースで一定の発火があり閾値校正が必要。

### 結果の読み方
HoneyRouteの主要な意味は、セキュリティ判定を推論前段の軽量分類だけで終わらせず、判定結果をモデル選択へ接続して悪意トークンを本番GPUから物理的に分離した点にある。これにより検出精度・判定遅延・欺瞞忠実度・GPU資源保護を同じサービング経路制御として最適化でき、捕捉トレースを再学習へ戻すことで攻撃分布の変化にも追従する余地を持つ。
## 品質への影響
本番へ通る良性要求のモデル品質は変えないが、誤迂回時はハニーポット応答品質に依存する。高忠実度複製は品質を保つ代わりにGPU費が残り、GPU不要方式は囮設計と発火閾値が品質を左右する。
## 既存研究との差
RouteLLM等が能力と費用でモデルを選ぶのに対し、HoneyRouteは危険度で本番か欺瞞面かを選び、捕捉対話を検出学習へ戻す。従来ハニーポットがプロトコル層またはモデル内部にあるのに対し、推論API層で要求ごとにモデルを切り替える。
## 限界
- 単一SingGuardモデル系列と8×H20環境中心である。
- 攻撃分布が変わると領域別分類頭と閾値の再校正が必要。
- 軽量囮は発火条件次第で良性利用者に露見する可能性がある。
- 複製ハニーポットはGPU費をゼロにはできない。
## 実装状態
凍結埋め込み、領域別MLP、セッション追跡、vLLM本番/複製、コードハニーポットを統合した実験実装。
## 研究上の位置づけ
LLMサービングの耐攻撃性と資源保護を、ルーティング・スケジューリング問題として扱う新しい比較軸を提供する。
