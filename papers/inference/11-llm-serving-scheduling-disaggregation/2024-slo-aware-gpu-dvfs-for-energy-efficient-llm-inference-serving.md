# SLO-Aware GPU DVFS for Energy-Efficient LLM Inference Serving

> 要求到着率とGPU周波数から裾遅延を予測し、生成中にSLOを満たす最小周波数へ約25反復ごとに調整するDVFS制御で、A100/A30上のGPT-J-6B配信エネルギーを22.8〜45.5%削減する。

## 概要

GPUでLLMを配信するとき、常に最大周波数で動かせば遅延には余裕を持たせやすいが、低負荷時にも同じ電力を消費する。逆にGPU周波数を固定的に下げると、負荷が上がった瞬間に要求待ち行列が伸び、99パーセンタイル（p99）の応答時間のようなサービス品質目標（Service-Level Objective; SLO）を破りやすい。したがって省電力化には「どこまで遅くしてもSLOを守れるか」を負荷に合わせて継続的に判断する必要がある。

LLM配信ではこの問題が通常の定常バッチ推論より難しい。自己回帰デコードは1反復ごとに各要求から1トークンを進め、連続バッチ処理（inflight/continuous batching）では生成終了した要求が抜け、新規要求が加わるため、同じ1リクエストの生成中でも実効バッチサイズとGPU負荷が変化する。生成開始時に一度だけ周波数を決めても、その後の負荷を正しく表せない。

一方、この反復構造は細粒度制御の機会にもなる。本論文はGPUの動的電圧・周波数スケーリング（Dynamic Voltage and Frequency Scaling; DVFS）を数十反復ごとに更新し、現在の要求到着率と候補周波数から裾遅延を予測する。制御器は予測されたSLOを満たす中で最も低いGPU周波数を選び、負荷が低い期間だけクロックを落として電力を削る。

重要なのは、TritonやTensorRT-LLMのスケジューラを作り替えるのではなく、その外側から観測・予測・周波数設定を行うことである。事前には少数の負荷×周波数点だけを測り、未測定の周波数も機械学習モデルで補間する。この構成により、A100 SXM 40GBとA30 24GBでGPT-J-6Bを配信した実験では、基準のTriton + TensorRT-LLMに対してSLOを維持しながら22.8〜45.5%のエネルギー削減を報告する。

## 背景: なぜ固定DVFSではLLM配信に向かないか

GPUの動的電力は一般に電圧・周波数を下げると大きく減るため、DVFSは古くから省電力手法として使われてきた。ただし周波数低下は演算時間を延ばす。オフラインバッチ処理ならエネルギー最小点だけを選べるが、対話型LLMでは応答時間SLOがあるため、単純な最低周波数固定は使えない。

さらにLLMのデコードは、要求到着率（requests per second; RPS）が同じでも、その時点で何件が生成中かによって1反復のバッチサイズが変わる。ある時刻にはGPUが混雑し、数秒後には複数要求が終わって余裕が生じる。最大周波数固定はこの余裕を電力削減に変換できず、静的な低周波数固定は混雑区間への追従ができない。

SLOを平均遅延ではなく裾遅延で定義する点も重要である。平均値が十分速くても、一部の要求だけ大幅に遅れればユーザー体験や契約上のSLOを破る。そこで制御器は「現在のRPSと周波数ならp95/p99などの裾遅延が何秒になるか」を予測する必要がある。

## 問題設定

目標は、既存LLM配信系の出力やスケジューリング方針を変えず、GPU周波数だけを操作してエネルギーを最小化することである。制約は指定された裾遅延SLOを満たすことであり、最適化問題としては「SLOを満たす候補周波数のうち最小のもの」を逐次選ぶ。

全ての周波数×RPSを事前に総当たりで測れば単純な参照表（lookup table; LUT）を作れるが、GPU周波数は細かい刻みを持ち、負荷軸まで含めるとプロファイル費用が増える。しかも未測定点へ一般化できない。本論文は少数の測定点から裾遅延曲線を学習し、周波数の補間を可能にすることで事前測定量を減らす。

オンライン制御自体も遅延を増やしてはならない。RPSの取得、予測モデル推論、nvidia-smiによる周波数変更には時間がかかるため、毎トークンではなく「数十反復ごと」という粒度を選ぶ。

## 手法

### 1. オフラインでRPS・GPU周波数・裾遅延の関係を少量測定する

最初に対象モデルとGPUについて、複数の要求到着率と複数GPU周波数で配信を動かし、p90/p95/p99などの応答時間を記録する。ただしGPUが提供する全15MHz刻みを網羅せず、より粗い周波数間隔から一部の点をサンプリングする。

このデータから、RPSとGPU周波数を入力し、指定パーセンタイルの応答時間を出力する軽量な予測モデルを学習する。目的は未来の生成長を個別に当てることではなく、現在の集合負荷でどの周波数まで下げられるかを推定することである。

A100の分析では、完全プロファイルの12.5%だけを学習へ使っても、裾遅延予測の平均絶対誤差（Mean Absolute Error; MAE）は0.2秒未満に収まると報告する。これにより全周波数を事前測定するLUTよりプロファイル量を減らせる。

### 2. オンラインで要求到着率を約25反復ごとに測る

実行時にはTritonが公開する情報またはログから要求数と経過時間を取り、RPSを計算する。論文実装では約25 LLM反復、時間にしておよそ1秒ごとに測定する。

短い窓のRPSは揺らぐため、滑動平均（sliding-window average）で平滑化する。ただし急な負荷スパイクまで平滑化して追従を遅らせないよう、現在値と平均値に大きな乖離が出ると平均状態をリセットする。

25反復という粒度は理論的に固定された最適値ではなく、予測モデルの実行とnvidia-smiによる周波数変更に必要な制御遅延から決めた実装上の下限である。

### 3. 各候補周波数の裾遅延を予測する

RPSが更新されると、利用可能なGPU周波数を予測モデルへ順に入力し、それぞれで期待される裾遅延を計算する。オフライン測定で直接見ていない周波数も予測対象にできるため、LUTより細かい15MHz単位で周波数候補を扱える。

ここで出力は「この1反復が何msになるか」ではなく、負荷と周波数から得られる応答時間分布の上位パーセンタイルである。制御対象をSLOと同じ指標へ合わせることで、平均性能だけを見て裾遅延を壊すのを避ける。

### 4. SLOを満たす最低周波数へGPUを設定する

予測した候補から、指定SLO以下になる最も低い周波数を選ぶ。負荷が低ければ周波数を大きく下げ、RPSが増えれば高い周波数へ戻す。以後、次のRPS測定時に同じ判断を繰り返す。

これがエネルギー削減へつながる因果関係は明快である。最大周波数はレイテンシに不要な余裕を作る区間がある。その余裕をGPUクロック低下へ変換すれば、処理時間をSLOの範囲で伸ばす代わりに瞬時電力を下げられる。

モデルの出力値、トークン選択、KVキャッシュ、バッチング方式には触れないため、品質劣化を伴う近似最適化ではない。守るべき品質条件はモデル精度ではなく配信レイテンシSLOである。

### 5. LUT版との違いはプロファイル量と周波数粒度

論文は事前測定値から直接周波数を引くLUT版と、機械学習（Machine Learning; ML）予測版を比較する。LUTは単純だが、事前に測った105MHz程度の粗い周波数点へ選択が制限される。

ML版はその間を補間して15MHz粒度でより低いSLO適合周波数を選べるため、同じSLOでも余分なクロックを削りやすい。論文ではML版がLUT版より一貫して高いエネルギー削減を示す。

## 評価

### 代表的な評価条件

| 項目 | 条件 |
| --- | --- |
| 配信基盤 | NVIDIA Triton Inference Server + TensorRT-LLM |
| モデル | GPT-J-6B |
| GPU | NVIDIA A100 SXM 40GB、NVIDIA A30 24GB |
| 負荷 | Poisson到着を用い、Alibaba由来GPUトレースを対象ハードウェアへスケーリング |
| 生成長 | MLPerf仕様に合わせ128新規トークンまで生成 |
| 入力長 | 可変 |
| SLO | p90/p95/p99などの裾応答時間制約。代表的な上限10秒 |
| オンライン観測 | 約25反復（約1秒）ごとにRPS測定 |
| 比較 | 最大周波数の標準Triton + TensorRT-LLM、LUT DVFS、ML予測DVFS |
| 主指標 | SLO遵守、総エネルギー、裾遅延予測MAE |

### 代表的な評価結果

| 条件 | 指標 | 結果 | 読み取れること |
| --- | --- | --- | --- |
| A100、少量プロファイル | 裾遅延予測MAE | 完全データの12.5%利用でも0.2秒未満 | 全周波数・全RPSの総当たり測定は不要 |
| A100/A30、各SLO | エネルギー | 標準実装比22.8〜45.5%削減 | 余剰性能を周波数低下へ変換できる |
| SLOを緩和 | エネルギー削減率 | より大きくなる | 許容遅延が大きいほど低周波数を選べる |
| p99→p95などを緩和 | エネルギー削減率 | より大きくなる傾向 | 許容できる裾違反が増えると電力余地が増す |
| ML予測版 vs LUT | エネルギー | ML版が一貫して有利 | 105MHz級のLUTより15MHz級の細粒度選択が効く |

22.8〜45.5%という範囲はGPUとSLO条件によって変わる。最大45.5%を任意のLLM配信へ一般化できず、特に厳しいSLOや高負荷では選べる周波数が最大値に近づき、省電力余地が小さくなる。

また本論文のSLOは主として応答時間の裾である。現在広く使われる初回トークン時間（Time To First Token; TTFT）やトークン間時間（Time Per Output Token; TPOT）を別々に最適化する現代的配信系へ適用する場合は、予測対象と制約式を再設計する必要がある。

## 既存研究との差

静的電力上限（power capping）や固定周波数DVFSは、負荷変動へ追従しないためSLOを守るには保守的な設定になりやすい。本論文は自己回帰LLMの反復性と連続バッチによる負荷変化を利用し、生成中にも周波数を更新する。

GPUの省電力制御をLLM配信エンジン内部へ組み込む方式に対しては、Tritonのログと外部周波数制御だけで動かす点が異なる。配信実装を侵襲的に改変しないため導入は軽い一方、内部の将来バッチサイズやKV使用量を直接見て最適化する後続方式ほど先読み能力は持たない。

量子化、投機的復号、KV圧縮はモデル計算量・データ量そのものを減らす。本方式は同じ計算を周波数だけ変えて実行するため、原理的にはそれらと併用できる。ただし併用後は周波数に対するレイテンシ感度が変わるため、予測モデルを再プロファイルする必要がある。

## 限界・実装状況

評価対象はGPT-J-6B、A100/A30、Triton + TensorRT-LLMという限定された組合せである。大規模MoE、マルチGPUの集合通信律速、最新GPU、メモリ帯域律速が強いモデルでは、コア周波数を下げても性能がほとんど変わらない場合と、逆に制御可能な範囲が変わる場合がある。

制御はRPSを主要な負荷指標とするため、入力長・生成長・バッチ構成が同じRPSでも大きく変化する現実のワークロードでは予測誤差が増え得る。論文は変動トレースで評価するが、要求ごとの将来生成長を明示的には予測しない。

周波数変更とRPS測定には約25反復単位という制御周期がある。この周期より速い負荷スパイクには完全追従できず、平滑化と急変検出の設計がSLO違反リスクへ影響する。

さらに、エネルギー最小化と電力ピーク削減は同じではない。周波数を下げて処理時間が伸びるため、瞬時電力は下がっても総エネルギーが必ず下がるとは限らない。本論文の結果は実測された22.8〜45.5%削減を根拠とし、DVFS一般の自動的な省エネ保証ではない。
