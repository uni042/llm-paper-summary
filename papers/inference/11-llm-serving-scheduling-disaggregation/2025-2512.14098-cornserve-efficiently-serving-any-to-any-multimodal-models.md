# Cornfigurator：任意入力・任意出力マルチモーダルモデルの配置を自動計画する

## 概要

テキスト・画像・動画・音声を入力と出力の両方に扱うモデルでは、要求ごとに必要な構成要素が異なる。画像入力なら画像符号化器を通り、音声出力なら思考用の大規模言語モデル（LLM）に加えて発話用LLMや音声生成器を通る。これらを一つのGPU集合へ固定すると遅い構成要素が全体を止め、逆にすべてを分離すると使われないGPUや通信費が増える。

Cornfiguratorは、任意入力・任意出力（Any-to-Any; A2A）モデルの構成要素を、同居させるか、別GPUへ分離するか、何複製を配置するか、要求をどの経路へ何割流すかを自動で決める配置計画器である。目的は単純な要求処理率ではなく、要求種別ごとの遅延目標を満たした要求の処理率（goodput）を最大化することにある。実機評価ではQwen 3 Omni、InternVL 3、Qwen 3 VL、Qwen-Imageなどを対象に、既存方式や専門家調整配置と同等または最大6.32倍のgoodputを報告する。

**書誌上の重要な訂正：** 同じarXiv識別子2512.14098の旧GitHub原稿は「Cornserve: Efficiently Serving Any-to-Any Multimodal Models」と記していた。しかし2026年4月15日改訂の原著v3の正式表題は「Cornfigurator: Automated Planning for Any-to-Any Multimodal Model Serving」である。Cornfiguratorは配置計画器、Cornserveはその下で動く別の分散実行基盤であり、混同してはならない。旧原稿の最大3.81倍の処理率・5.79倍の末尾遅延という数値を現行版の主結果として流用しない。

## 問題設定

従来のテキストLLM配信では、要求が主に入力の事前計算と自己回帰生成という共通経路を通る。A2Aモデルでは、画像や動画の符号化器、思考用LLM、発話用LLM、音声生成器、画像拡散器などが有向非巡回グラフを構成する。要求種別によって実際に通る部分グラフが異なるため、各構成要素へ到着する要求率が大きく違う。原著表2ではQwen 3 Omniの構成要素の処理率がA100上で5.43、2.93、21.43、2.15、0.12要求/秒など大幅に異なり、最も遅い構成要素へすべてのGPUを割り当てればよいわけでもない。

配置には二つの粒度がある。グラフ水準では構成要素を同じ実行器へまとめるか、別実行器へ分離するかを決める。実行器水準ではバッチ上限、テンソル並列度、系列並列度、専門家並列度などを決める。画像符号化器を分離すれば独立に拡縮できるが、そのGPUはLLMのKVキャッシュを置くためには使えない。並列度を増やせば単一要求の遅延が短くなることがある一方、通信費が増えて全体処理率が落ちる。モデル・要求混合・GPU予算ごとに最適解が変わるため、単一の固定分離方針では不十分である。

## 手法

### 1. 入力を計算グラフ・構成空間・負荷として定義する

モデル開発者は構成要素とテンソル依存関係を有向非巡回グラフで与える。実行基盤が利用できる実行器の種類と、その並列度・バッチ上限などの選択肢も指定する。負荷は要求種別の集合と各種別の出現割合で表し、GPU総数と種別ごとの遅延目標を与える。例えばQwen Omniでは、画像・動画・音声の符号化器から思考用LLMへ入り、音声出力要求だけが発話用LLMと音声生成器を追加で通る。

全要求に一つの遅延目標を課すと、音声出力のような重い要求に基準が引きずられ、短いテキスト応答を必要以上に遅くしても制約違反にならない。そこでCornfiguratorは要求種別tごとに遅延目標L_tを持ち、その種別の目標を満たす要求の処理率を評価する。既定の目標設定では、単独実行時の高処理率構成から測定した遅延の25パーセンタイルを参考にする。目的関数は各種別の有効処理率の合計を最大化するものであり、単純な総要求率最大化とは異なる。

### 2. 論理的な分離候補を列挙する

まずグラフをどこで切るか、どの構成要素を同じ実行器へまとめるかという論理部分計画を列挙する。要求種別ごとに異なる部分グラフを通す計画を許し、共通構成要素を共有する部分計画は複合部分計画へ統合する。完全同居から完全分離までを含み、要求の一部だけが分離経路を通る混合構成も候補にする。例えば動画入力だけを専用動画符号化器へ流し、その他の入力を同居構成で処理できる。

次に各論理ノードへ実行器の種類、並列度、バッチ上限、複製数を割り当てる。複数の実行経路が同じ要求種別を処理できる場合は経路ごとの配分確率も決める。これらを合わせた実際に起動可能な仕様を物理計画と呼ぶ。GPU予算を超える候補や通信の依存関係を満たせない候補は除外する。

### 3. 実機プロファイルを取る

計画器は対象ハードウェア上で構成要素を動かし、実行器の並列度・バッチ上限などを変えて処理率と遅延を測る。測定は飽和した到着率の定常区間で行い、立上がり・停止期間を除く。実行時のトレースから待ち行列の時間を差し引き、実行器自身の処理時間を推定する。計画器はこの結果を使うため、モデルのパラメータ数だけから処理率を推測するよりも現実的な候補比較ができる。

### 4. 安価な推定から精密な模擬へ段階的に絞る

物理計画は多数あるため、すべてを詳細シミュレーションすると計画時間が大きくなる。第一段階ではネットワーク流を用い、各実行器の容量と要求の経路から理論的な処理率上限を求める。明らかに他候補より劣る計画をここで除外する。第二段階ではモンテカルロ標本化で構成要素ごとの処理時間を組み合わせ、要求種別ごとの遅延を近似する。第三段階では残った候補だけを要求単位のシミュレータで評価し、待ち行列、競合、共有実行器の占有状態をより精密に再現する。

各段階で要求種別ごとの有効処理率をベクトルとして比較し、すべての種別で他候補に劣る計画を除外する。最終的には残った候補から合計goodputを最大にするものを選ぶ。安価な流量上限で全候補を絞り、時間のかかる要求単位模擬を少数に限定することで、大規模な構成空間を探索できる。

### 5. 実行器の占有状態と転送費を考慮する

単純な定常プロファイルでは、負荷が低い構成要素も最大バッチで処理すると仮定しがちで、実際の遅延を過大評価する。Cornfiguratorは非律速実行器の実効バッチを推定し、遅延を補正する。画像符号化器ではCPU側の画像復号とGPU推論が重なる場合がある。空の実行器へ最初の要求が来たときはCPU＋GPU時間が必要だが、既に忙しい実行器では待機中にCPU処理を済ませられる。この違いもシミュレータで扱う。

分離した実行器間の中間テンソル転送には通信費がある。原著の実機では代表的な転送遅延の中央値が約10ミリ秒であり、計画器は分離辺ごとにその費用を加えられる。通信が常に無視できると仮定するのではなく、計算時間と転送時間の相対関係を含めて配置を比較する。

### 6. 計画を再利用して負荷変化へ追従する

GPU台数だけが変わる場合は、同じプロファイルを使ってGPU予算を変更し再探索できる。要求種別の割合だけが変わる場合も、測定した各種別の処理時間を再重み付けして再計画できる。一方、新しい要求種別が追加されたり、既存要求の入力長が大きく変わったりすれば、その部分の再測定が必要になる。モデル構造やGPU機種が変わる場合はプロファイルを取り直す。実行時の各要求を逐一動的最適化する方式ではなく、計画の前提となる負荷が変化したときに再計画する方式である。

### 7. Cornserve実行基盤との役割分担

Cornfigurator自体は実行基盤に依存しない配置計画器であり、論文ではCornserveという別の分散A2A実行基盤の上に実装する。計画器は約5000行のRustで実装され、実行器の起動・テンソル転送・要求処理はCornserveが担当する。vLLM-Omniや既存の専門家調整配置もCornserve上で同じ計画として実行し、実行基盤の差が配置計画の比較を歪めないようにする。名称が似ていても、計画器とランタイムは同一物ではない。

## 評価

### 装置・モデル・比較条件

| 項目 | 原著v3の条件 |
|---|---|
| 装置 | AWS p4de.24xlargeを2台、各8×A100 80GB、合計16 GPU |
| 接続 | ノード内NVSwitch、ノード間400Gbps |
| 対象 | Qwen 3 Omni 30B、InternVL 3 38B、Qwen 3 VL 32B、Qwen-Image |
| 負荷 | ServeGenのモダリティ混合要求、Qwen-ImageではDiffusionDBの解像度混合 |
| 比較 | vLLM、vLLM-Omni、ModServe、EPD、完全分離配置、専門家調整構成 |
| 指標 | 種別ごとの遅延目標を満たした要求の毎秒処理数（goodput） |
| 遅延目標 | 通常は単独実行での高処理率構成の25パーセンタイルを参考に設定 |
| 実行環境 | 比較計画を同じCornserve基盤上で実行 |

従来の最大処理率と異なり、遅延目標を超えた要求をgoodputへ数えない。テキスト出力と音声出力では目標が異なるため、単一のP99や総処理率だけを比べると改善の意味を取り違える。原著の改善倍率はこのgoodputに関するものであり、全要求の生処理率や単一要求の遅延が同倍率で改善したという意味ではない。

### 主要結果

| モデル・条件 | 比較対象に対する結果 | 主な原因 |
|---|---|---|
| Qwen 3 Omni・音声出力1/3 | goodput 1.24～1.84倍 | 構成要素ごとの負荷配分を調整 |
| Qwen 3 Omni・音声出力2/3 | goodput 1.25～2.73倍 | 発話用LLM・音声生成器が律速になりやすい |
| InternVL 3・8 GPU | goodput 1.12～6.06倍 | 大きな画像符号化器の分離が有効 |
| InternVL 3・16 GPU | goodput 1.27～3.95倍 | GPU予算に応じて同居と分離を再配置 |
| Qwen 3 VL | 既存方式と同等～最大6.32倍 | 小さな画像符号化器を分離しない方がよい場合を発見 |
| Qwen-Image | 単純な同居配置を選択 | 軽いLLM前処理を独立GPUへ分ける利益が小さい |

Qwen 3 Omniの音声出力が1/3から2/3へ増えると、発話用LLMと音声生成器の負荷が大きくなり、そこへGPUを配分する利益が増える。Qwen 3 VLでは画像符号化器が小さいため、画像符号化器を分離する固定方針が必ずしも良くない。最大6.32倍は特定比較方式に対する上限であり、すべてのモデルや負荷での改善率ではない。一般的なA2AモデルのQwen 3 Omniでは1.24～2.73倍、特殊な入力・出力構造を含めると同等～6.32倍と分けて報告されている。

### 要求種別別の計画例

原著のQwen 3 Omni・16 GPU・音声出力1/3では、音声符号化器の単独実行器を1、画像・動画符号化器と思考用LLMの同居実行器を4、発話用LLMと音声生成器の同居実行器を11という構成を選ぶ。音声出力2/3では発話用LLMと音声生成器の配置がさらに重くなる。これは全要素を分離したり、すべてを同居させたりする単純な方針では再現しにくい。動画入力の重い要求だけを専用動画符号化器へ送る混合経路も使われる。

### 予測精度と負荷変化

Qwen 3 Omniで実機のgoodputを予測した誤差は、ネットワーク流＋モンテカルロだけでは集約平均絶対誤差10.7%だったが、要求単位シミュレーションを加えると4.1%へ下がる。中央値も8.6%から3.3%へ改善する。安価な評価は粗い候補除外には使えるが、共有実行器での競合を正確に扱うには後段の模擬が必要という根拠である。

InternVL 3の画像入力率を25%、50%、75%へ変える実験では、16 GPUのCornfiguratorのgoodputはそれぞれ3.60、2.48、1.75要求/秒となる。50%でのvLLMは1.95、ModServeは1.33、EPDは0.63要求/秒である。画像率75%ではModServeとCornfiguratorが同じ1.75となり、常に差が開くわけではない。要求比率だけが変わる場合は再測定なしで再計画でき、所要時間は一桁～十数秒程度と報告する。

## 既存研究との差

vLLM-OmniやSGLang-OmniはA2Aの構成要素を分離して実行する機構を提供するが、どの構成を採るかは人手調整に依存する場合がある。ModServeやEPDは画像符号化器の分離、あるいは事前計算・生成の分離など特定の構造を想定する。Cornfiguratorは実行基盤ではなく、モデルの有向非巡回グラフと要求混合から、同居・完全分離・部分分離・混合経路までの候補を生成して自動評価する計画器である。すべての方式をCornserve上の同一ランタイムで実行するため、配置の効果と基盤実装の差を分離しやすい。

## 限界

事前プロファイルは対象GPU、モデル、要求長に依存する。GPU機種やモデル構造が変われば測定をやり直す必要がある。要求比率だけの変化には再計画で対応できるが、未観測の新しいモダリティや入力長が現れた場合は再プロファイルが必要である。完全分離が不利な場合もあり、通信費、GPUの空き領域、KVキャッシュ容量を含む共同判断が必要となる。実験はA100を16基まで用いる単一環境であり、異種GPUクラスタやネットワーク帯域が低い環境への直接一般化はできない。

計画器の探索は測定した実行器構成空間に制限され、未知のカーネル最適化やモデル構造変更を自動生成するわけではない。要求種別ごとの遅延目標をどう設定するかによって最適計画は変わる。goodput最大化はモデル出力品質の改善ではなく、計画時の要求分布から大きく外れれば再計画が必要となる。旧版の3.81倍処理率・5.79倍末尾遅延と現行版の6.32倍goodputは評価指標も原稿版も異なるため、同じ表へ無条件に並べてはいけない。
