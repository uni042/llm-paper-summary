# 質問依存の圧縮ビューによるRAG用KVキャッシュ融合：QCFuse

## 概要

検索拡張生成（Retrieval-Augmented Generation; RAG）では、外部文書から取り出した複数の根拠チャンクを質問とともに言語モデルへ入力する。文書群は要求間で再利用できる一方、質問や検索順序は毎回異なる。全チャンクをその都度プレフィルすると長い文脈の注意計算が重いが、各チャンクを単独で事前計算した鍵・値キャッシュ（KV cache）を単純連結すると、チャンク間の注意関係が失われて回答品質が下がる。

キャッシュ融合（cache fusion）は、チャンクごとに事前構築した位置独立キャッシュ（Position-Independent Cache; PIC）を再利用し、重要なトークン位置だけ現在の質問とチャンク順序に合わせて再計算する折衷方式である。従来の選択器には二律背反がある。質問を見ない選択器や最終層だけを見る選択器は高速だが、複数チャンクに散在する証拠を見落としやすい。質問と全文脈・全層を照合する選択器は品質を保ちやすいものの、再計算を開始する前に大量のKVを読み込む必要があり、層ごとの転送・計算の重畳を妨げる。

QCFuseは、質問に必要な根拠を見つけるための情報を**トークン方向と層方向の両方で圧縮**する。オフラインで各チャンクの代表トークン（アンカー）と重要な注意層を選び、オンラインでは少量のアンカーKVだけを読んで質問を条件付け、重要層の鍵を使って元の文脈上の再計算位置を選ぶ。その後はSGLangの層別キャッシュ融合により、必要なKVだけをTritonカーネルで再計算する。

著者らはSGLang 0.5.4上で4種類の公開重みモデル、六つの長文脈データセットを用いて評価し、同等の回答品質を達成する動作点で、全プレフィルに対して初回トークン時間（Time To First Token; TTFT）が平均1.7倍高速、全層質問依存選択器ProphetKVに対して平均1.5倍高速と報告する。これは**初回トークンまでの遅延**の比較であり、生成全体の処理量やトークン毎秒が1.7倍になることを意味しない。

## 問題設定と先行研究との差

一つの要求の取得文脈をC=[c1;c2;…;cm]、質問をU、文脈トークン総数をNとする。質問UはオンラインでCの後ろに入力されるが、再利用対象のキャッシュはCに対応する。全プレフィルで構築したKV^Full(C)は、各チャンクの先行文脈を含めて計算される。これに対し、各チャンクc_iのPICを単独で計算し、回転位置埋め込み等に合わせて鍵の位置を再写像して連結したKV^PIC(C)は、元のチャンク間依存を持たない。位置の付け替えは可能でも、前のチャンクを見て作った特徴に変わるわけではない。

キャッシュ融合は再計算位置集合Pを選び、p∈Pなら現在の文脈順序に沿ってKVを作り直し、p∉PならPICを使う。再計算率ρ=|P|/Nが小さいほど計算は軽いが、質問の回答に重要な位置を見落とすと品質が低下する。逆に全位置を再計算すると通常の全プレフィルに戻る。

CacheBlendは浅い層でのKV偏差、EPICはチャンク境界の固定規則を利用し、選択は速いが質問に依存しない。FusionRAGは質問に関する最終層の注意を利用するが、質問単独の信号は複数文書の意味関係を十分に反映しない場合がある。ProphetKVは質問を全チャンクのキャッシュへ条件付けし、全層の質問→文脈注意を集約するため、重要な証拠を選びやすい。しかし選択前に全層の鍵をGPUへ転送する処理が直列化される。原著では再計算率30%の例でProphetKVの選択処理が応答全体時間の34%を占めると報告する。

QCFuseの着眼点は、再計算をするトークンの割合だけでなく、**再計算対象を決めるために事前に読むKVの量**を減らすことにある。チャンクアンカーは質問の文脈条件付けを小さくし、重要層の選択は全層の鍵転送を避ける。選択集合Pを早く確定できれば、残りのキャッシュ読込みと層別再計算を再び重ねられる。

## 手法

### 1. オフラインの位置独立キャッシュ構築

安定したRAG文書集合を検索単位のチャンクへ分割し、各チャンク単独でモデルを実行して全層のPICを保存する。チャンクが別の要求に再登場したときは、このPICをストレージから読み、要求内の順序・位置へ鍵を再写像する。値は元のトークン順に連結する。これにより文書内容が同じなら計算済みKVを繰り返し使える。

QCFuseはPICとともに、チャンクごとの少数のアンカー位置とアンカーKVを保存する。アンカーは後でオンラインの質問を条件付けるための代表であり、元の文脈から最終的に再計算する位置集合Pとは異なる。つまりアンカーを10%にしたから、再計算するトークンが必ず10%になるわけではない。後者の予算ρは別に指定する。

### 2. チャンクアンカーによる質問の条件付け

質問だけを単独で処理して得た表現は、取得文書の具体的な証拠を見ていない。逆に全文脈のKVを読んで質問を処理すると、選択段階だけで大量の転送が必要になる。そこで各チャンクの代表トークンを先に選び、要求内でそのアンカーKVをつなぎ、**小さな疑似文脈を見た質問表現**を計算する。

候補となるアンカーの順位付けには、チャンク先頭の注意吸収位置を残すSink、鍵ベクトルのノルムによるKnorm、チャンク再構成プローブに基づくKVzipを比較する。校正では、正解の根拠スパンが含まれる位置をどれだけ選べるかをRecall@10%で測る。KVzipで各チャンクの上位10%を残す構成が、全文脈で質問を条件付けた参照方式に近い根拠位置の再現率を示したため、既定のアンカー比r_a=0.1とした。

オンラインでは取得チャンクのアンカーを元の要求位置IDを保って連結する。質問の位置IDは元の全文脈Cの後ろにあるものとして扱い、圧縮されたアンカーの数に合わせて質問の位置を詰めない。これにより位置依存の注意計算が、本来のチャンク配置から不必要にずれるのを避ける。アンカーを使って質問の隠れ状態Q_U(C_A)を得るが、最終的な重要度は**元の全トークン位置**に対して計算する。

### 3. 重要層だけによる再計算位置の局所化

全層の質問→文脈注意を合計する方式は、モデルの各層にある全文脈の鍵を読まなければならない。QCFuseはオフライン校正で、各層単独の注意スコアが正解根拠位置をどれだけ拾うかを評価する。校正データはSQuAD、NewsQA、Natural Questionsの根拠スパン付き例であり、最終のLongBench・RULER評価データと区別している。

各層lについて、アンカーで条件付けた質問表現と、元の文脈位置のPIC鍵の注意を計算する。そのスコア上位10%に正解根拠スパンがどれだけ含まれるかをRecall@10%で測り、層ごとの評価R(l)を得る。原著の図では、中間層が全層参照方式とよく一致し、最終層が必ずしも最良ではない。上位層を1、2、3…と増やして再現率を調べると、上位3層で改善の大部分を得られるため、モデルごとに**重要3層**を固定する。

オンラインではその3層の鍵だけを先に読み込み、アンカーで条件付けた質問との注意を集約して、元の文脈位置から上位ρN個をPとして選ぶ。重要層の鍵は質問の処理と並行して先読みできる。残りの層のPICは再計算パイプライン側で順次読み込めばよく、選択開始時点で全層を揃える必要がない。

### 4. 層別の選択的KV再計算と転送重畳

集合Pが確定すると、SGLangのキャッシュ融合処理が各層を進む。選択位置pについては、現在の文脈順序に従い、p以前の再利用済み・再計算済みKVを参照して新しいK/Vを計算し、元の位置のPICエントリへ書き戻す。未選択位置のPICは変更しない。Tritonの疎再計算カーネルは選択位置だけを処理し、次の層のPIC読込みと現在層の計算を重ねる。

この設計では、オフラインのアンカー作成や層校正の費用は要求ごとのオンライン遅延から切り離せる。一方、文書が頻繁に更新される場合はPICとアンカーを再生成する必要があり、モデルを変更した場合には重要層の再校正が必要になる。既定の3層・10%アンカーは論文の評価モデル群で選んだ動作点であって、すべてのモデルに数学的な最適性を保証する値ではない。

## 主要結果

### 1. 同等品質での初回トークン時間

原著の図10・図11は、モデル×六課題×再計算率の品質とTTFTの関係を示す。QCFuseは質問に依存した選択により、同じ再計算率でもCacheBlend、EPIC、FusionRAGより高い品質領域へ達しやすく、ProphetKVに近い品質を維持する。一方、ProphetKVと異なり選択段階で全文脈・全層のKVを先読みしないため、同じ品質の動作点でTTFTを小さくできる。

**品質を揃えた動作点の平均**では、QCFuseのTTFT速度倍率は全プレフィル比1.7倍、ProphetKV比1.5倍である。これは単一の固定再計算率・単一データセットに対する万能な速度倍率ではなく、原著が品質一致点を選んで集計した結果である。再計算率を0.5まで上げると全プレフィルに近い品質領域へ到達しやすいが、その分再計算量とTTFTは増える。直接PIC再利用は速いが、必要なチャンク間依存を再構築できず品質を失いやすい。

原著は例外として、Mistral-v0.3-7BのRULER変数追跡（vt）で、直接再利用が全プレフィルの品質を上回る条件を報告する。この場合、再計算率を増やすと全プレフィルの品質に近づくため、単調に品質が改善するとは限らない。全プレフィルは通常の品質参照であるが、すべての合成課題で数学的な上限値ではない。

### 2. 長文脈と転送帯域の感度

RULERの文脈を、チャンク数またはチャンク長を増やす二通りで伸ばし、再計算率ρ=0.5を固定して比較した。QCFuseは長文脈でも全プレフィル・ProphetKVに近い品質群に残り、質問を見ない方式や最終層のみの方式より安定する。短い文脈では全プレフィルやProphetKVがわずかに上回る条件もあり、長文脈での冗長性が大きいほど選択的再計算の利点が現れやすい。

NVMe読込帯域を変える実験では、ProphetKVの全層選択が転送待ちを引き起こし、約3GB/s付近では選択処理の直列化により全プレフィルよりTTFTが悪化する条件がある。QCFuseは先に読む情報をアンカーと重要3層に絞るため、帯域低下時も選択段階の待ちが小さい。これは単に再計算率を減らした効果ではなく、**再計算開始前のI/O量を削った効果**である。

### 3. 同時要求とスループット

再計算率ρ=0.5で要求到着率を増やし、要求/秒とTTFTの曲線を比較すると、QCFuseは4モデルで曲線を右へ移し、同じTTFTでより多くの要求を処理し、同じ要求率なら初回トークンを早く返す。全プレフィルは全トークン計算が律速となり、ProphetKVは選択前のKV読込がボトルネックとして残る。QCFuseは前処理の直列部分を短くすることで、負荷増加時の待ち時間の立上りを緩やかにする。

ただし、図14の曲線から読める傾向と、具体的な要求/秒の倍率は区別する。原著本文にない固定のスループット倍率を推測で補わない。本文の1.7倍と1.5倍は品質一致のTTFT比較であり、同時処理量の倍率ではない。

### 4. 構成要素除去実験

アンカー比r_a=0、すなわち質問だけを処理する設定から10%アンカーへ変えると、LongBenchとRULERの双方で根拠位置の選択品質が大きく改善する。10%を超えてアンカーを増やした場合の改善は相対的に小さい。RULERの正確なキー・値追跡ではアンカー増加が多少有利な条件もあり、最適な比率はタスク依存である。

層選択の比較では、先頭層、固定の中間層、最終層、全層集約、校正で選んだ重要層を比べる。校正済みの重要1層は平均品質が最も高く、固定中間層も比較的良い。最終層だけの注意は回答生成・書式などの影響を含み、根拠位置の局所化には必ずしも最良ではない。上位3層に増やすと校正時のRecall@10%の改善の大部分を確保できるため、オンラインでは重要3層を既定とした。全層を読むと根拠の情報は増えるが、I/Oの直列化が性能上の不利益となる。

## 限界・適用条件

第一に、RAG文書が再利用されることが前提である。PIC、アンカーKV、重要層の校正はオフラインで行うため、文書が頻繁に変更されるワークロードでは再構築の費用と無効化管理が必要になる。論文のTTFT計測はオフライン準備時間を含まないので、利用頻度が低いチャンクにまで事前計算する費用対効果は別に評価すべきである。

第二に、全プレフィルのKVとPICのKVは一般に一致せず、選択的再計算はその差を近似的に埋める。ρ<1で全位置の厳密な等価性を保証する方式ではない。品質が同等とされるのは評価したデータセット・動作点における経験的な結果であり、未知の長文や重要証拠が非常に散らばる条件では品質が低下し得る。正確性が重要な用途では、再計算率の増加や全プレフィルへのフォールバックを検討する必要がある。

第三に、アンカーの選択にはKVzipの再構成プローブを用い、重要層はモデル別に校正する。モデルやトークナイザを変更すると、既存のアンカー・層順位がそのまま適切とは限らない。特にKVzipのオフライン計算費用と追加保存領域は、オンラインTTFTの改善とは別に計上すべきである。

第四に、実験はH20 GPU×2、DRAM 128GB、NVMe SSD 1TB、SGLang 0.5.4で行われた。GPU常駐メモリに全KVが収まる、CPU帯域が十分に広い、SSDの読込が非常に遅いなどの構成では、選択・転送・再計算の律速関係が変わる。単一の消費者向けGPUやWindows上の別推論基盤へ、そのまま同じ倍率を適用できる証拠ではない。

第五に、評価の中心は初回トークン時間、長文脈QAの品質、同時要求の収容力である。生成後半のトークン毎秒、電力効率、複雑な文書更新・キャッシュ失効、検索器そのものの時間を含めたアプリケーション全体の応答時間は別の指標となる。QCFuseが高速化するのは主として**取得文脈のプレフィルとそのKV構築・読込経路**であり、検索器の索引探索や最終出力長を直接短縮する方式ではない。
