# Whose Turn Is It? Context-Guided Model Routing for Stateful Agents

> 状態を持つエージェントのターン単位ルーティングを比較し、履歴を見ることが同じ振り分け率で成功率を3.3ポイント上げることと、切替の費用が方向で非対称であり下方の切替だけが短期間で元を取ることを示した分析研究。

## 概要

モデルルーティングは、易しいリクエストを安いモデルへ、難しいリクエストを高いモデルへ回すことで、品質を保ったまま推論費用を下げる手法である。ところが従来のルーターは、各リクエストを独立した入力として扱ってきた。状態を持つエージェントでは、この前提が崩れる。1つの利用者ターンは複数のモデルの呼び出しと道具の実行を含み、その難しさは前のターンが作った状態に依存する。たとえば「同じ書式を第3四半期にも適用して」という依頼は、どの書式でどのシートかが分からなければ難しさすら判断できない。さらに、モデルを切り替えると、提供事業者がモデルごとに保持する会話のプロンプトキャッシュが使えなくなり、蓄積した文脈を未キャッシュの入力として再度課金される。

本論文は、利用者ターンの単位で振り分ける方針を体系的に比べる。振り分けは、セッション全体を1つのモデルへ固定する粗さと、呼び出しごとに決める細かさの中間にあたる。比較の軸は、判断規則、ルーターが見る情報、候補の組の性質、キャッシュとの相互作用の4つである。代表結果として、安いモデルへの振り分け率がほぼ同じ条件では、履歴を見るルーターの成功率は25.0パーセントから28.3パーセントへ3.3ポイント上がり、高いモデルだけを使う場合と1ポイント以内に収まった。一方で、安いモデルの課題あたりの割引は、長いセッションでは単価の5倍から3.2倍まで目減りした。キャッシュの分析では、高いモデルから安いモデルへの下方の切替は損益分岐が約1.25回の呼び出しで、2回程度で元が取れるのに対し、逆方向の切替は評価条件では元が取れないことが示された。

## 問題設定

逐次性が生む問題は4つある。第1に、難しさがセッションの中で変わる。表を作る作業、条件を1つ変える作業、壊れた数式の連鎖を直す作業では、必要な能力が違う。第2に、現在の依頼だけでは意味が取れないことが多い。第3に、前の判断が後のターンの難しさを変える。高いモデルが解法の骨格を作った後なら、安いモデルでもその跡をたどって拡張できることがある。第4に、切替は無料ではない。キャッシュはモデルごとの接頭辞に対して効くため、切り替えた先のモデルは、共通の土台の部分は再利用できても、会話の蓄積部分は未キャッシュとして読み直す。本論文は、すぐに配備できる方針に絞るため、2つの制約を置く。ルーターはゼロショットでなければならず、学習済みのルーターは候補が数か月で入れ替わるたびに教師付けが要り、エージェントのセッションでは1ターンのラベル付けに候補それぞれでの全実行が要るため現実的でない。そして方針は費用の削減を目的とし、品質を上げるために計算を増やす方式は対象外とする。

## 手法のあらまし

方針は3つの次元で表される。何を見るかは、現在の依頼だけか、依頼と履歴の両方かである。履歴には過去の依頼、応答、道具の呼び出しと観測、実行の誤り、過去の振り分けの判断が直列化されて入る。いつ決めるかは、ターンごとにか、ターンの中かである。どう割り当てるかには、軽いモデルをルーターとしてターン全体をどちらかへ割り当てる方式、安いモデルから始めて難しいと判断したら高いモデルへ残りを渡す昇格、高いモデルから始めて安いモデルへ渡す降格、そして判断材料なしに無作為に選ぶ方式がある。割り当てられたモデルは、そのターンのすべての呼び出しと道具の実行を担い、結果は実行基盤が履歴へ追加する。モデル同士は隠れ状態や事業者側のキャッシュを共有せず、直列化された状態だけで引き継ぐ。評価は成功率と費用の組で行い、ルーター自身の呼び出しとキャッシュの効果も費用へ含める。

## 手法

### 1. ターン単位の割り当て — 判断の粒度をセッションと呼び出しの間へ置く

粒度の選択が最初の設計判断である。セッション単位の固定は、難しさの変化へ追随できない。呼び出し単位の振り分けは、エージェントのループの中に判断を何度も差し込むことになり、先行する学習型の方式はこの粒度を取るものが多い。本論文の粒度では、ルーターは利用者の依頼が来た直後、そのターンが始まる前に1回だけ呼ばれ、割り当てはターンが終わるまで固定される。入力は依頼と、履歴ありの場合は直列化された履歴であり、出力は単純か複雑かという構造化されたラベルで、それが安いモデルか高いモデルかへ対応する。時間切れや形式の崩れやサービスの失敗の場合は高いモデルへ倒す。なぜこの粒度が重要かというと、判断の回数が少なく費用が読みやすい一方で、ターンの中で作られた状態は次の判断の入力になるため、逐次性は保たれるからである。失敗条件は、ターンの中で難しさが変わる場合で、後半だけ難しいターンは丸ごと高いモデルへ行くか、安いモデルのまま苦戦する。

### 2. 昇格と降格 — 判断を作業中のモデル自身へ移す

昇格と降格は、判断を別のルーターではなく作業中のモデル自身へ移し、ターンの途中で切り替える方式である。昇格では全ターンが安いモデルから始まり、自分には難しいと判断した時点で残りを高いモデルへ渡す。引き継ぎは同じ履歴と道具と成果物の状態から続く。降格はその逆である。この方式の狙いは、実際の作業の手触りから難しさを判断できることだが、評価では自己評価の弱さが現れた。昇格はほとんどのターンを安いモデルに残し、昇格の割合は条件により0.6から16.6パーセントにとどまった。降格は成功率で固定のモデルにも及ばない場面が多く、費用も膨らんだ。つまり、モデルは自分の限界を正確には申告できず、特に降格では高いモデルの費用を払った後に安いモデルへ移るため、両方の悪い面を拾いやすい。

### 3. キャッシュとの相互作用 — 切替の損益分岐を閉じた形で出す

切替の費用は2つに分かれる。ルーターの呼び出しそのものと、蓄積した会話のキャッシュを失うことで増える入力の費用である。同じモデルが続く場合、次のターンは安定した土台の接頭辞と、そのモデルが蓄積した会話の両方を再利用できる。切り替えると、土台の部分は先のモデルでも温まっているため再利用できるが、会話の部分は未キャッシュとして読み直され、その後に先のモデルが自分のキャッシュを育て直す。本論文はこの費用を、切替時点の文脈の長さと、両モデルの未キャッシュ価格とキャッシュ価格から近似し、下方の切替が何回の呼び出しで元を取るかを閉じた形で表した。その回数は文脈の長さに依存せず、価格だけから決まる。対象の価格では約1.25回であり、下方の切替はそのターンが続けば取り戻せる。逆に上方への切替は、文脈100万トークンあたり約4.9ドルと下方の約0.5ドルの10倍の費用がかかり、その後の呼び出しも高い方のキャッシュを読むため、入力の面では元が取れない。文脈はターンごとに育つため、遅い段階での上方の切替ほど高くつく。ここから、切替は粘着的にし、文脈の長さを意識して、下方へは早めに移って留まり、上方へは期待できる品質の改善が文脈とともに育つ費用を上回るときだけ移る、という設計原則が導かれる。

### 4. 費用の会計 — 単価ではなく課題あたりで比べる

評価の会計では、会話の中のすべての呼び出しを価格表で課金し、キャッシュされた入力はキャッシュ価格で数える。ルーターの呼び出しも含める。この会計により、単価の安さと課題あたりの安さの乖離が見える。安いモデルの中には、呼び出し回数と入力トークンが多くなることで割引が目減りするものがある。固定モデルの基準は、会話のキャッシュが全ターンで保たれる最も有利な前提で数えられており、ルーティング側に不利な、つまり控えめな比較になっていることも明記されている。切断や有効期限でキャッシュが消える実運用では、固定モデルの有利さは縮む。

| 構成要素 | 入力・観測 | 具体的な動作 | 改善対象 | 主なトレードオフ |
|---|---|---|---|---|
| 履歴つきルーター | 現在の依頼と直列化された履歴 | ターン全体を安いモデルか高いモデルへ割り当てる | 誤った振り分けの削減 | ルーターの呼び出し費用と履歴の入力費用 |
| 昇格と降格 | 作業中のモデル自身の判断 | ターンの途中で残りをもう一方のモデルへ渡す | 作業の手触りからの判断 | 自己評価の不正確さと二重の費用 |
| 切替の損益分岐 | 両モデルの価格と文脈の長さ | 元を取るまでの呼び出し回数を価格だけから決める | 切替方針の設計 | 価格の前提が変わると結論も動く |

## 評価

### まず見るところ

- **結論:** 履歴を見るターン単位のルーターだけが、高いモデルの品質をほぼ保った。自己評価による昇格と降格と、無作為な切替は、固定のモデルにすら負ける場面があった。
- **速度・効率:** 遅延ではなく費用の評価である。費用の節約は候補の組に強く依存し、組によってはルーターつきでも高いモデルだけの場合より費用がわずかに増えた。
- **品質:** 成功率そのものは低く、最良の先行モデルでも多ターンの課題の31.2パーセント程度しか解けない領域での比較である。
- **評価の強さ／注意点:** 費用が厳密に計算できるのは、候補同士が価格を共有する組だけである。他の組の費用は価格表からの会計であり、昇格などの方式は別の実行基盤で走っている。

**数値の読み方。** 履歴の効果は、振り分け率をそろえた比較で読む必要がある。振り分ける量ではなく、どのターンを振り分けるかが改善の源である。また、安いモデルの割引は単価ではなく課題あたりで見るべきで、長いセッションほど呼び出し回数の多いモデルの割引が縮む。ルーターの費用対効果は組ごとに逆転しうるため、倍率や節約率は組とセットで読む。

## 既存研究との差

従来の費用配慮のルーティングは、独立なリクエストを単位とし、選好データや成績のラベルで学ぶ方式と、安いモデルの出力を検査してから昇格させるカスケードが中心だった。多ターンのルーティングを扱う最近の研究は、対話の履歴を見る学習型の方式や、呼び出しごとに選ぶ学習型の方式がある。本論文の差分は、ゼロショットでターンという中間の粒度を取り、見る情報と決める頻度と切替の方向を分けて測ったこと、そして切替とプロンプトキャッシュの相互作用を損益分岐の形で定量化したことにある。表計算のエージェントでルーティングを調べた研究は、著者らの知る限りこれまでなかった。

## 限界・実装状況

対象はゼロショットで費用配慮の方針に限られ、学習済みルーターなら結果は変わりうる。セッションは平均3ターン程度と短く、より長い履歴、独立な課題が混ざる対話、シートをまたぐ相互作用は今後の課題とされる。ターンは既存の課題を小課題へ分解して作られており、自然な対話の多様さを完全には捉えていない。費用の厳密な計算は候補が価格を共有する組に限られ、方式によって実行基盤が違う点も比較の割り引き要素である。成功率自体が低い領域の研究であり、絶対水準の低さはエージェント側の未熟さも映している。論文中に公式コードの公開先は示されていない。

## 一般的な実装上の含意

ルーティングを基盤へ入れるなら、判断の入力に履歴を含めることが最も効く。同じ振り分け率でも、どのターンを回すかで結果が変わるためである。切替は粘着的に設計し、下方への切替は早めに、上方への切替は文脈が育つほど高くつくことを前提に慎重にすべきである。安いモデルの選定は単価ではなく、対象のワークロードでの課題あたりの実績費用で行うべきで、呼び出し回数の増え方は短い評価では見えない。候補の組の選択自体がルーティングと同じくらい結果を左右するため、組の見直しを先に行う方が費用対効果が高い場合がある。キャッシュの前提も重要で、固定モデルの有利さはキャッシュが切れない前提に依存する。
