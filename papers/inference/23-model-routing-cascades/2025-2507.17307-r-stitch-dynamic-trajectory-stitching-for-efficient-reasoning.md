# R-Stitch：小型・大型言語モデルの思考軌跡を動的に接続する混合復号

## 概要

R-Stitchは、長い思考過程（Chain-of-Thought、CoT）を生成する際、**小型言語モデル（SLM）が確信を持って生成できる部分は小型側に任せ、難しいトークンだけ大型言語モデル（LLM）へ移す**方式である。大型モデルが確信度の高い領域へ戻ったら再び小型側へ処理を戻すため、一方向の段階的モデル選択とは異なる。両モデルは同一の語彙分割器（tokenizer）を共有し、モデルごとに別の鍵・値キャッシュ（KV cache）を保持する。切替後は不足したトークン区間だけを事前計算（partial prefill）する。

2025年7月公開の初版では、NVIDIA A800単一GPU・同時要求数1の数学推論を評価し、MATHで大型モデル単独の69.57秒/件・正答率76.80%に対し、切替閾値0.6のR-Stitchは9.39秒/件・76.20%となった。これは**7.41倍の遅延短縮例**だが、精度は0.60ポイント低い。AIMEでは133.37秒から22.85秒に短縮する一方、正答率は23.33%から16.67%に下がり、「精度を完全に維持する高速化」と解釈してはならない。

著者は2025年9月に拡張版を公開し、最大3.00倍（7B）、3.85倍（14B）、4.10倍（32B）の高速化を公式プロジェクトページで報告した。これらは初版の表1とは異なる評価構成・版の数値であり、同じ実験として混ぜない。拡張版は確率分布のエントロピーを切替信号とし、強化学習（RL）で切替を選ぶR-Stitch+も紹介する。以下は**全文を確認できた初版の機構・表の数値を主軸**とし、後続版については著者公式ページで確認できた範囲を明確に区別する。

## 問題設定：投機的復号では利用しにくい「短いが異なる思考」

思考型LLMでは、最終回答に至るまで数百から数千のトークンを自己回帰的に生成する。大型モデルを毎トークン実行すると重み読み出しやKVキャッシュアクセスが繰り返される。小型モデルは各トークンを安価に生成でき、しかも正解へ到達する場合に大型モデルより短い思考で済むことがある。したがって、生成トークン当たりの費用だけでなく、**そもそも何トークン生成するか**が終端間遅延に効く。

一般的な投機的復号（speculative decoding）は、小型の草稿モデルが先行生成したトークンを大型モデルが照合する。草稿が大型モデルの予測と一致しなければ、その部分は受理されない。R-Stitchの初版は、AMCのモデル組合せごとの一致率と高速化率を調べ、一致率が低い組合せで高速化が小さくなること、個別問題では投機的復号が1倍を下回ること、両モデルが正解した問題でも小型側の思考列が短い場合があることを示す。ここから「大型モデルと同じ文章を草稿で再現する」以外の協調方式を動機づける。

R-Stitchは小型モデルの**別の正しい推論軌跡**をそのまま活用し得るが、分布保存型の投機的復号と異なり、大型モデル単独と同じ出力分布を保証しない。したがって速度と回答品質の交換条件を測定する必要がある。

## 手法

### 手法：双方向切替とKVキャッシュの差分同期

### 1. 同一接頭辞と予測確信度

初版の設定では、二つの自己回帰モデル `f_SLM` と `f_LLM` は同じ語彙分割器を使う。入力質問 `x` と既に確定した生成列 `y_1...y_(t-1)` を受け、現在担当するモデルが次トークンの確率分布 `p_t` を計算する。確信度は `c_t = max(p_t)`、つまり最も確率の高い候補トークンの確率である。閾値 `τ` は事前設定される。

小型モデルから開始するのは、難しい箇所以外では安価なモデルを使いたいからである。小型側の `c_t >= τ` ならそのトークンを採用して小型側で次へ進む。`c_t < τ` なら、**小型側の当該トークンは破棄**し、同じ生成位置を大型モデルで再処理して置き換える。これは小型側が生成した長い草稿列を後からまとめて照合する処理ではなく、不確実な位置に対する局所的な委譲である。

### 2. 大型モデルから小型モデルへの復帰

大型モデルが担当中は、その確信度が閾値未満の間は大型側で生成を続ける。`c_t >= τ` になったら、生成済み接頭辞を保持したまま**次の位置から小型モデルへ制御を戻す**。この復帰経路がないと、一度難しいトークンに出会った後は残りを大型側で生成することになり、容易な区間の節約が失われる。

初版の切替則は `SLM→LLM: c_SLM < τ` と `LLM→SLM: c_LLM >= τ` であり、同一閾値を両方向に用いる。閾値を変えると大型モデルの担当区間と切替頻度が変わるため、遅延・正答率が単調に改善する保証はない。特に確信度が問題の難しさを正しく表さない場合、簡単な箇所で大型側を呼ぶ、難しい箇所を小型側で確定する、といった誤判断が生じる。

### 3. モデルごとのKVキャッシュと差分事前計算

二つのモデルは重みと注意状態が異なるため、KVキャッシュをそのまま共用しない。初めて担当するモデルは、それまでの質問・生成接頭辞について事前計算を行って自分のKVキャッシュを構築する。その後は、自分が最後に処理した位置までのキャッシュを残す。

別モデルが数トークン生成してから元のモデルへ戻る際は、元モデルのキャッシュにまだ入っていない**新しいトークン区間だけ**を事前計算する。例えば小型モデルが位置1〜30、大型モデルが31〜35を担当し、位置36から小型へ戻るなら、小型側は31〜35の新しい接頭辞を自分の重みで処理してKVを追記する。全履歴を毎回事前計算し直す場合より切替の費用を小さくできる。

ただし、二つのモデルをGPUへ同時配置できるか、KVキャッシュ二組を保持できるか、頻繁な差分事前計算がどれだけかかるかが実用上の制約となる。初版の単一GPU・バッチ1という設定は、多数要求を連続バッチ処理するサービングの効率を直接示すものではない。

### 4. 拡張版：エントロピー信号とR-Stitch+

2025年9月の著者公式ページは、初版で使う最大確率ベースの説明を拡張し、トークン予測分布の**エントロピー（entropy）**を不確実性の代理指標として説明する。AMCの分析では小型モデルのトークンの89%超がエントロピー0.1以下であり、誤答に先行する局所的な高エントロピー領域が切替の手掛かりとなると報告する。最大確率とエントロピーは関連するが同じ統計量ではない。初版の `max(p_t)` 閾値の表1を、後続版のエントロピー切替の測定結果と取り違えない。

R-Stitch+は固定閾値を軽量な強化学習ルータへ置き換える拡張である。ルータは隠れ状態と現在の文脈長を入力に、エントロピーの高い箇所で小型モデル継続か大型モデル移行かを判断する。報酬は回答正答率と遅延見積もりを組み合わせ、事前計算・復号費用を文脈長やKV量の関数として扱う。著者ページで確認できるのはこの設計説明と総括値であり、初版の表1と同条件の詳細表を今回独立照合したわけではない。

### 後続版の総括値との区別

著者公式ページが2025年9月更新版として示す最大高速化は、7Bで3.00倍、14Bで3.85倍、QWQ-32Bで4.10倍である。これらは初版のA800・7B・数学表1の7.41倍とは実験条件が一致しない。詳細な条件表・品質変化を同じ表に統合せず、版差があることを残す。更新版の「精度が大型モデルに近い」という表現も、全データセット・全閾値で完全同一の正答率という意味ではない。

## 既存方式との差と限界

投機的復号では小型モデルが生成したトークン列を大型モデルが検証するのに対し、R-Stitchはトークン単位の不確実性に応じて**生成主体そのものを切り替える**。そのため大型モデルの出力分布を厳密に再現する必要はなく、小型モデルの短い別解を活かせる。一方、分布保存保証を捨てるため、誤った小型推論が確信度高く進む場合や大型モデルから早く戻り過ぎる場合には回答品質が下がる。これは方式の本質的な交換条件である。

早期終了方式DEERは生成するトークン数を減らすのに対し、R-Stitchは担当モデルの切替でトークン当たり費用を減らす。初版は両者の併用を試みるが、DEER側の公開実装が毎回全接頭辞を再事前計算してしまう点を指摘しており、圧縮率と実際の遅延を分けて報告している。単純に両手法の倍率を掛け算することはできない。

実装上は小型・大型モデルを同じGPUで維持し、それぞれのKVキャッシュを保持するため、モデル二つ分の重み・キャッシュ容量と切替時の差分事前計算が必要となる。初版はバッチ1でしか評価しておらず、実運用の多数同時要求、異なるモデルのメモリ競合、トークン単位の細かな切替が連続バッチ編成へ及ぼす影響は示していない。著者も固定閾値の入力分布依存性とバッチ1の制約を限界として挙げる。

さらに、著者の公開リポジトリは存在するものの、2026年10月23日のREADMEでは**実装コードは整理中で後日公開予定**と明記されている。したがって実行可能なコードが現在公開済みであるかのように扱わず、`code: null` とした。公式ページの設計図や論文の擬似コードを実装の再現性と混同しない。
