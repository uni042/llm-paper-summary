# 思考表現の混合を用いた大規模言語モデルの費用効率的カスケード推論

## 書誌と対象範囲

原著はICLR 2024の査読付き論文で、確認したPDFはarXiv `2310.03094v3`（2024年2月8日版、38ページ）である。対象は言語モデルの学習高速化ではなく、**推論時にどのモデルを何回呼ぶか**を制御する要求ルーティングである。計算機の低レベルなカーネル最適化やKVキャッシュ圧縮ではないが、推論サービングの単位費用と品質を両立させる実行時の制御方式として収録対象となる。

## 概要

強力な言語モデルをすべての要求へ使用すると、簡単な算数問題にも難しい因果推論にも同じ高価なAPIを呼ぶことになる。一方、安価なモデルだけに切り替えると難問で正答率が落ちる。本研究は、まず安価なモデルから複数の推論経路で回答を得て、**回答の一致度が高い問題はそのまま採用し、一致しない問題だけ強いモデルへ送る**カスケード（cascade）を構成する。問題文だけを分類するのではなく、実際に弱いモデルが出した複数の解答を観測して判断する点が中心である。

推論過程の表現として、自然言語で段階的に説明する思考連鎖（Chain-of-Thought; CoT）と、計算手順をプログラムとして出力するプログラム思考（Program-of-Thought; PoT）を組み合わせる。両者は同じ誤りを繰り返しにくいため、CoTだけの複数サンプルが誤答で一致してしまう難問を、CoTとPoTの不一致から検出しやすくなる。複数回答の多数決の支持率を閾値と比較する方式と、異なるプロンプト条件で得た多数決結果が一致するかを照合する方式を提案し、計10通りの変種を比較する。

GPT-3.5-turboを弱いモデル、GPT-4を強いモデルとした六つの推論データセットで、思考表現を混合した方式はGPT-4の思考連鎖自己整合性推論とほぼ同等の平均正答率（約0.929対0.931）を、約40%の相対API費用で達成する。CREPEでは提案約0.885、比較0.871の正答率を47%の相対費用で得た。これらは論文当時のモデル・価格・データセット条件での結果であり、別モデルや現行料金へ倍率をそのまま転用できない。

## 問題設定

### どの要求を強いモデルへ送るか

質問Qを受けたとき、弱いモデル `LLM_w` が先に回答候補を生成する。判定器がその回答を受理すれば弱いモデルの回答を返し、拒否すれば強いモデル `LLM_s` を呼んで回答を置き換える。質問一件の費用は、弱いモデルを呼ぶ費用 `C_w`、判定費用 `C_d`、拒否した場合だけ発生する強いモデルの費用 `C_s` の合計となる。つまり `C=C_w+C_d+1_reject*C_s` である。

この式から、拒否率を下げれば強いモデルの呼出しを節約できるが、誤答を受理すると品質が落ちることが分かる。反対に、弱いモデルの回答をすべて拒否すれば強いモデルの品質に近づくが、弱いモデルと判定器の費用が上乗せされ、カスケードを組む意味がなくなる。目的は、**弱いモデルが正答しやすい問題だけを安価に確定し、難しい問題を適切に選別すること**である。

### 問題文の見た目だけでは難易度を判定しにくい

数学や因果推論では、問題文が簡単そうでも中間計算で誤る場合がある。外部の小さな判定モデルへ質問文と単一回答を与えるだけでは、推論の誤りが見かけ上もっともらしい場合に検出できない。著者は、同じ問題を弱いモデルが複数回解いたとき、易しい問題では回答が安定し、難しい問題では異なる答えが出やすいという仮説を使う。必要なのは絶対的な確率校正ではなく、複数サンプルの**一致という観測可能な信号**である。

ただし同じ推論形式を繰り返すだけでは、共通の系統的誤りで全サンプルが同じ誤答に集中し得る。そのため回答数を増やすことより、誤りの相関を減らす異なる思考表現の利用を重視する。

## 手法

### 二段階の推論パイプライン

最初に質問Qと少数の例示を弱いモデルへ与え、温度を設定して複数の解答経路をサンプリングする。CoTの場合は文章の最終回答を抽出し、PoTの場合は生成された計算プログラムを実行して最終値を得る。複数回答を集約して代表回答を求め、その一致度をルーティング判定器へ渡す。受理なら代表回答を最終出力とし、拒否なら強いモデルに通常の推論プロンプトを与える。強いモデルには原則として弱いモデルの不確かな回答をヒントとして渡さない。

判定器を新規に教師あり学習する必要がないため、質問と回答の正誤を大量にラベル付けする費用を避けられる。一方で、弱いモデルへ複数回問い合わせる費用は常に発生する。従って、強いモデルが十分高価で、かつ弱いモデルが一定割合の問題を安定して正答できる条件が重要になる。

### 投票による一致度判定

投票方式では、弱いモデルからK個の回答を得て、最頻回答を代表回答とする。一致度 `s` はその回答に一致したサンプル数をKで割った値である。二種類のプロンプトを使う場合は、両プロンプトから得たK1個とK2個の回答を同じ重みで数える。判定器は `s >= τ` なら弱いモデルの回答を受理し、そうでなければ強いモデルへ送る。閾値τは品質と費用のトレードオフを調整するつまみである。

閾値を低くすると弱いモデルの回答を多く採用し、強いモデルの費用を抑えられるが誤答を採用する危険が増す。閾値を高くすると多くの問題を強いモデルへ送る。論文では閾値を0.4から1まで変え、正答率と相対費用の曲線を比較している。MoTの投票方式では高すぎる閾値の追加効果が小さく、著者の実験では0.5〜0.6付近が費用と正答率の均衡点となることが多い。

### 異なるプロンプトの代表回答を照合する方式

照合方式では、異なる二つのプロンプト条件から回答集合を得て、それぞれの集合内で多数決の代表回答を作る。二つの代表回答が一致する場合だけ弱いモデルを採用し、不一致なら強いモデルへ送る。この方式は閾値τを探索しなくてよい反面、費用上限に応じて連続的に受理率を調整する自由度が小さい。異なるプロンプト条件を持つ場合だけ適用できるため、同一条件での単純な一組のサンプルには対応しない。

### 思考表現と例示の多様化

著者は回答の生成源を三種類に整理する。第一は同じプロンプトを温度付きで繰り返しサンプリングする方法。第二は同じ思考表現のまま例示集合を二種類に変える方法。第三は自然言語のCoTとプログラムのPoTを混合する方法である。CoTは自然言語の説明を重視し、PoTは計算をコード実行へ移すため、誤りの種類が変わる可能性がある。

この組合せから、投票方式はCoT単独・PoT単独・MoT混合それぞれに対し一種類の例示または二種類の例示を使う計6変種を定義する。照合方式は二種類のCoT例示、二種類のPoT例示、CoTとPoTを同じ例示で混合、CoTとPoTを別の例示で混合する計4変種である。MoT-1D-Voteは同じ例示集合からCoTとPoTの回答を得て一括投票し、MoT-2D-Verifyは思考表現と例示集合の双方を変えた二組の代表回答を照合する。

### 推論費用の整合と注意点

同じ総サンプル数でも、プロンプトを二種類に分けると例示部分の入力トークンを二回送ることになり、単一プロンプトのK回生成と費用が一致しない。著者は比較のため、各方式の弱いモデル呼出し費用が概ね同等になるようサンプル数を調整する。ただし厳密に同じ費用ではないため、実際の入力・出力トークン数に基づく相対費用を別途報告する。CoTとPoTでは生成される中間出力の長さも異なり、単純にサンプル数だけで費用を比べてはいけない。

## 評価

### 評価対象と設定

六つの推論課題は、数学推論のGSM8k、ASDIV、TabMWP、記号推論のBIG-Bench Hard由来DATEとNavigate、因果推論のCREPEである。弱いモデルはGPT-3.5-turbo（4千トークン文脈）、強いモデルはGPT-4（8千トークン文脈）で、強いモデル側にはCoTの自己整合性推論を使う。例示は基本8件、弱いモデルのサンプル数は基本20、強いモデルのサンプル数は3、温度は両者0.4とする。正答率と、GPT-4-CoT-SCを1.0とした相対API費用を評価する。

| 項目 | 原著の設定 |
|---|---|
| 課題 | GSM8k、ASDIV、TabMWP、DATE、Navigate、CREPEの六種類 |
| 弱いモデル | GPT-3.5-turbo、文脈4K、基本20サンプル |
| 強いモデル | GPT-4、文脈8K、CoT自己整合性、基本3サンプル |
| 例示と温度 | 基本8-shot、温度0.4 |
| 主な比較 | 弱いモデル単独、強いモデル単独、CoT/PoTの投票・照合、外部判定器 |
| 指標 | 課題正答率、GPT-4-CoT-SCを基準とした相対API費用 |
| 投票の感度 | 一致度閾値0.4〜1.0、温度0.4/0.8、サンプル数20/40 |

### 六課題の費用対正答率

図3では、思考表現混合の四変種が平均正答率約0.929を示し、強いモデル単独のGPT-4-CoT-SCの0.931に近い一方、相対費用は約0.40である。つまり約60%の費用を削減した条件で、平均正答率の差は約0.002にとどまる。ただしこれは一つの評価設定の平均であり、全問題・全価格設定で正答率を保証する意味ではない。因果推論CREPEでは、混合方式0.885に対して強いモデル単独0.871で、相対費用0.47という例もある。

混合しないCoT-2D-Voteでも平均正答率0.924、相対費用0.57という結果があり、カスケードそのものにも費用削減効果がある。その上で、思考表現を混合することで、同じ費用条件での難問判定がさらに改善する。単に強いモデルの呼出し回数を減らしただけではなく、弱いモデルのどの回答を信頼するかを工夫したことが寄与している。

| 原著の比較条件 | 平均正答率 | 相対API費用 | 解釈 |
|---|---:|---:|---|
| GPT-4-CoT-SC単独 | 0.931 | 1.00 | 強いモデルの基準 |
| MoT混合の代表的条件 | 約0.929 | 約0.40 | ほぼ同等の正答率で費用を削減 |
| CoT-2D-Vote | 0.924 | 0.57 | 例示多様化のみでも一定の改善 |
| CREPEでのMoT混合 | 0.885 | 0.47 | 同課題のGPT-4-CoT-SC 0.871を上回る |

### 例示の変更と思考表現の変更を比較

図3では、同じCoTを使いながら例示を二種類にしたCoT-2D-Voteが、同じ例示だけを使うCoT-1D-Voteより、相対費用0.4付近で平均正答率を約1.4ポイント高めた。しかしCoTとPoTを混合するMoTの利得は、多くのデータセットでさらに大きい。例外としてDATEでは、試験問題と例示問題の類似性が高く、思考表現の混合による優位性が明確でない。MoT-1D-VoteとMoT-2D-Voteの差も顕著ではなく、例示集合を増やすより思考表現そのものを変える方が有効な条件が多いと解釈される。

図4では、弱いモデルが正答する易問と誤答する難問を分け、一致度の平均差を分析する。CoTだけのサンプルは、別の例示に変えても同じ誤りを繰り返す場合がある。PoTを混ぜると別の計算過程で異なる誤答が出やすく、難問の一致度が下がる。従って易問と難問の一致度の差が大きくなり、強いモデルへ送るべき質問を見分けやすくなる。これはモデルの不確実性を直接推定したというより、**表現を変えた回答の相互不一致**を難易度の代理指標にした結果である。

### 温度・サンプル数・閾値の感度

図5では、温度を0.4から0.8へ上げるとCoT-2D-VoteとMoT-1D-Voteの正答率は概ね同程度かやや改善する。サンプルの多様性が増えるためである。一方、サンプル数を20から40へ増やすと、同じ正答率を得るための費用が増える方向へ曲線が移動する。サンプル数の単純増加は易問・難問の判別に大きく寄与しなかった。多様な思考表現を使うことと、単に同じ表現の出力を倍増させることは同等ではない。

投票方式の閾値を高くしすぎると、易問でも偶発的な異常サンプルが混ざるため、弱いモデルの代表回答を必要以上に拒否し、高価なモデルへの転送が増える。著者はMoTで0.5〜0.6付近が均衡しやすいと報告するが、これは課題・モデル・価格に依存する調整値である。照合方式は閾値調整が不要だが、費用制約を細かく指定したい運用には投票方式の方が柔軟である。

### 外部判定器との比較

図6では、RoBERTa-baseを質問文だけまたは質問文と弱いモデルの回答で微調整した外部判定器と、GPT-3.5-turboへ同様の判定を依頼する方式を比較する。GSM8kでは外部判定器の最高正答率0.892に対し、GPT-4-CoT-SCは0.958、提案方式は0.951である。外部判定器は質問文や単一回答の表層情報から難易度を推定するため、推論の中間段階にある誤りを捉えにくい。複数回答の一致度を使う提案は、追加の判定器学習を必要とせずに、同じ費用水準でより良い正答率を示した。

### 弱いモデルの能力不足とヒント伝達の負の結果

追加実験では弱いモデルをLlama 2 13Bへ置き換え、強いモデルをGPT-4のままにする。DATEでは機能する一方、GSM8kとCREPEでは弱いモデルにとって問題が難しすぎ、十分な一致度を得られず良好な費用対性能を示さない。弱いモデルが「ある程度の問題を安定して正答できる」ことは重要な前提であり、安ければどんな小型モデルでも良いわけではない。

また、弱いモデルが互いに矛盾する二つの代表回答を強いモデルへのヒントとして渡す実験では、DATEでわずかな改善がある一方、GSM8kとCREPEでは強いモデルの性能が大きく悪化した。従って本方式は、弱いモデルが不確かだと判定された場合、その不確かな推論を強いモデルへ無条件に引き継がない設計を採る。これも、単純な「安いモデルの推論結果を次のモデルへ渡す」方式との差である。

## 品質への影響と負の結果

カスケードは常に強いモデルの正答率を保証するわけではない。弱いモデルが誤答で一致してしまえば判定器はその誤答を受理し得る。CoTとPoTの混合はその危険を下げるための経験的な工夫であり、正しさを形式的に証明するものではない。難問で弱いモデルの回答が一致しなければ、強いモデルを呼ぶ前に多重サンプリング費用だけを追加で支払う。

原著の負の結果として、サンプル数20から40への増加は費用を増やしても難易度判定を十分改善しないこと、DATEでは思考表現混合の優位性が明確でないこと、Llama 2 13Bを弱いモデルにした場合はGSM8kとCREPEで十分に機能しないこと、不確かな弱いモデルの回答をヒントとして渡すとGSM8kとCREPEの性能が悪化することがある。閾値を高くしすぎると強いモデルへの不要な転送が増え、安くする目的を損なう。これらは採用条件を判断する上で重要である。

## 既存研究との差

従来のカスケード方式は、質問や一つの回答を入力する別の小型モデルを学習し、強いモデルへ回すべきかを予測することが多かった。これに対し本研究は、弱いモデル自身の複数サンプルから一致度を計算し、追加の教師あり判定器を不要にする。CoTやPoTを単独で使って正答率を高める研究とも異なり、**異なる思考表現が生む誤りの非相関性を、推論時のモデル選択の信号として使う**点に寄与がある。

重み量子化や枝刈りは同一モデルの一回の推論を軽くするのに対し、本方式は要求ごとに呼ぶモデルの種類と回数を変える。ハードウェア効率化とは別の階層の最適化であり、APIサービスや複数モデルのサービング基盤に適用しやすい。ただし多重サンプリングを行うため、推論呼出し数や待ち時間が必ず減るとは限らない。最適化する主指標は論文当時のトークン課金に基づく金銭費用と正答率であり、GPU時間や実際の端から端までの遅延を直接最小化した研究ではない。

## 限界・実装状況

評価はGPT-3.5-turbo、GPT-4、論文当時のAPI料金、六つの推論課題に基づく。価格差が縮まる、弱いモデルが十分に正答できない、強いモデルの性能が変化する、回答を多数サンプリングするための入力・出力トークンが増える、といった条件では費用削減率が変わる。CoTとPoTの最終回答を比較できる形式の問題が中心であり、自由記述の長文回答や主観的評価では、回答の同一性をどのように判定するかが別の課題となる。

プログラム思考ではコード実行環境が必要であり、生成コードの実行時間・失敗・安全な隔離の費用も運用上考慮する必要がある。原著の相対API費用はGPU利用率、モデル配置、バッチ化、キャッシュ効率、尾部遅延を直接測定したものではない。強いモデルへエスカレーションした場合には、弱いモデルの多重サンプリングを先に実行した分だけ、単独の強いモデルより応答遅延が長くなる可能性がある。著者は公式コードを公開しているが、実サービスのスケジューラにそのまま組み込めるという保証ではない。

## 総括

この論文は、言語モデルの推論を「すべての要求に同じ高性能モデルを使う」方式から、「弱いモデルの回答の安定性に応じて強いモデルを呼ぶ」方式へ切り替える実行時制御を具体化した。CoTとPoTを混ぜることで、単一形式の繰返しでは見逃す誤答の一致を減らし、強いモデルの呼出し費用を削減する。平均正答率0.929対0.931、相対費用0.40という結果は重要だが、弱いモデルの能力、推論形式、API料金、サンプル数、閾値に依存する。費用最適化と遅延最適化を混同せず、ルーティング方針の研究として位置付けるのが適切である。
