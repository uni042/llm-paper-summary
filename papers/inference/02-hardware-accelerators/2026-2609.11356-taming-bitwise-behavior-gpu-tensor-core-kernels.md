# Taming Bitwise Behavior in GPU Kernels with Tensor Core: Black-Box Reconstruction, Compiler Enforcement, and Static Verification

> GPU縮約順序を記述子化し、非公開行列積のビット挙動復元、コンパイラでの平衡木強制、命令列の静的同値判定を接続して再現性と自動調整を両立する。
## 書誌情報
- **著者**: Ziteng Yang, Nicholas J. Riasanovsky, Warren Deng, Vivek Sarkar
- **公開**: arXiv preprint arXiv:2609.11356v1
- **種別**: arXivプレプリント
- **対象**: GPUカーネル、数値再現性、テンソルコア、コンパイラ、静的検証
- **実装**: Triton後段コンパイラ変更、行列積生成系、静的命令同値判定器、自動調整統合を実装。
## 概要
浮動小数点加算の非結合性により、数学的に同じGPUカーネルでも縮約順序、部分和精度、融合積和、丸め位置が違えばビット列が変わる問題を、記述・復元・強制・静的検証まで一貫して扱う。行列積の縮約順序を決める要素だけを記録する記述子を定義し、非公開の行列積ライブラリをブラックボックス計測して同一ビットの生成系を再構築する。三世代の対象GPUで行列積を100%ビット一致させ、コンパイラには平衡木縮約を強制する後段処理とデータ配置最適化を追加し、27カーネル中19個を自由順序版の10%以内へ戻す。さらに二社のGPU命令列に対する健全な静的同値判定器を作り、自動調整候補を同一ビット同値類の中だけで探索できるようにする。

本研究の中心的な発想は、ビット再現性を特定カーネル名や実行スケジュールへ固定するのではなく、出力ビットを決める縮約依存木を算術意味として抽出し、その同値類の内部では性能スケジュールを自由に最適化する点にある。第一にGEMMのK軸をどこで分割するか、部分和をどの型で保持してどこで丸めるか、部分和をどの順序で統合するか、Tensor Core命令が一度に畳む縮約幅など、ビット列を決める属性だけを記述子化し、tile幅やwarp配置など速度だけに効く属性から分離する。第二に非公開ベンダーライブラリを実行時間、選択アルゴリズム、出力ビットの境界変化からブラックボックス復元し、推定記述子と同じ算術木を生成カーネルで再現する。第三にコンパイラへ平衡縮約木を意味属性として保持させ、順序固定後もデータ配置を変えて並列度を回復する。第四にコンパイル済みGPU命令列から縮約式を静的再構成する健全な判定器を作り、自動調整を要求されたビット同値類の中だけへ制約する。この四層を同じ縮約木表現で接続することが論文固有の新規性である。
## 問題設定
同じ数学式を計算するGPUカーネルでも、IEEE浮動小数点加算は結合則を満たさないため、並列縮約木、部分和を閉じる位置と型、融合積和の有無、Tensor Core命令内部の丸め境界が違えば最終ビットが変わる。高速なベンダー行列積ライブラリは入力形状、バッチ、GPU世代に応じて非公開アルゴリズムを選択し、Triton等の自動調整器もtile、warp数、パイプライン段数を変えるので、数学的には同じ要求でも配置やバッチが変わるだけで算術順序が変化し得る。従来のdeterministic modeは既知の安全な実装へ候補を絞ることで再現性を得るが、その代償として高速候補を捨て、評価では最大約20%級の性能差が生じる。また数百から数千の自動調整候補のうち、どれが基準実装と同じビット同値類に属するかを実行前に判定する一般的手段がない。推論、学習、特に別エンジン間でlog probabilityを比較する強化学習では微小差が後続生成へ増幅され得るため、再現性を性能探索と両立させることが問題となる。
## 新規性
本研究の中心的な発想は、ビット再現性を特定カーネル名や実行スケジュールへ固定するのではなく、出力ビットを決める縮約依存木を算術意味として抽出し、その同値類の内部では性能スケジュールを自由に最適化する点にある。第一にGEMMのK軸をどこで分割するか、部分和をどの型で保持してどこで丸めるか、部分和をどの順序で統合するか、Tensor Core命令が一度に畳む縮約幅など、ビット列を決める属性だけを記述子化し、tile幅やwarp配置など速度だけに効く属性から分離する。第二に非公開ベンダーライブラリを実行時間、選択アルゴリズム、出力ビットの境界変化からブラックボックス復元し、推定記述子と同じ算術木を生成カーネルで再現する。第三にコンパイラへ平衡縮約木を意味属性として保持させ、順序固定後もデータ配置を変えて並列度を回復する。第四にコンパイル済みGPU命令列から縮約式を静的再構成する健全な判定器を作り、自動調整を要求されたビット同値類の中だけへ制約する。この四層を同じ縮約木表現で接続することが論文固有の新規性である。
## 手法
### 手法のあらまし
処理は算術意味の抽出、閉鎖実装の復元、意味を保存するコード生成、最終バイナリの検証、自動調整への統合という順に進む。まず各出力要素へ寄与する浮動小数点積和を依存木として表し、thread内register reduction、warp内shuffle、shared メモリを介したwarp間reduction、Tensor Core命令内の縮約を一つの木へ合成する。GEMMについて通常のsingle-CTA reduction、split-K、CTA内多段reduction、GEMV型warp treeなどを分類し、K分割の入れ子、partial accumulator type、merge type、MMA instruction kind、tail処理位置を記述子へ保存する。次にcuBLAS系の非公開実装を多数形状と数値入力で走らせ、ランタイム、algorithm selection、bitwise output差から記述子を推定し、同じ記述子を実現するTriton カーネルを生成してbyte-for-byte一致で検証する。コンパイラ側ではreductionへbalanced-tree semantic attributeを付け、loweringがregister、warp、shared-メモリ各段で同じ木を保持するよう強制しつつ、reduction axisへ多くのlaneを割り当てるlayout transformationで性能を回収する。最後にPTXやAMD GCN命令からdef-useとlane communicationを追跡してsymbolic reduction expressionを再構成し、安全な正規化後に基準カーネルと比較する。autotunerは静的に同値と証明された候補だけをベンチマークし、その中の最速構成を選ぶため、再現性を維持したままhardware/shape固有の最適化を継続できる。

### 縮約依存木と行列積記述子
各浮動小数点加算を内部節、入力値を葉とする依存木として縮約順序を明示し、単なる出力値の一致ではなく、どの入力がどの順序と精度で結合されたかを表現する。行列積では出力タイル形状そのものより、K方向の縮約軸をどの階層で分割するか、各部分和をFP32などどの型で保持してどこで丸めるか、部分和をどの順序で統合するか、Tensor Core命令一回が何個の積を一つの丸めへまとめるかがビット列を決める。記述子はこれら算術木を決定する属性だけを保持し、タイル幅、warp配置、パイプライン段数など速度を変えても同じ木を実現できるスケジューリング属性を分離する。その結果、再現性を一つの固定カーネルへ縛るのではなく、同じ算術意味を持つ複数の高速実装を探索できる余地を残す。さらに通常GEMM、split-K、多段縮約、GEMV型などを同じ表現へ落とすことで、ベンダーライブラリ、Triton生成カーネル、コンパイラ生成コードの間で比較可能な共通契約を作る。

### 非公開ライブラリのブラックボックス復元
cuBLASなど内部アルゴリズムが公開されない高速行列積ライブラリに対して、多数の行列形状、データ型、入力パターンを実行し、実行時間、選択されたカーネルやアルゴリズム識別情報、出力ビットの変化を観測する。観測された境界変化からK方向の分割数、Tensor Core命令の縮約幅、部分和型、端数処理位置、部分和の統合順序を推定し、前述の算術記述子へ落とす。次に、その記述子が規定する依存木を明示的に実現するTritonカーネル族を生成し、非公開実装とビット単位で照合することで推定を検証する。単に数値誤差が小さいことではなく、入力を変えても同じビット列になることを要求する点が重要である。複数GPU世代とFP16、BF16、FP8系条件を横断して復元を試し、既知のライブラリ不具合を除く対象で完全なビット一致を確認することで、ブラックボックスから算術計画を再構成できることを示す。この復元結果は後段のコンパイラ強制と静的検証の基準同値類として利用できる。

### コンパイラによる平衡木強制と配置最適化
再現性を得るため縮約順序を固定する際、単純な左から右への逐次和に変換すると依存鎖が長くなりGPUの並列性を失うため、論文は理論上短い依存深さを持つ平衡二分木を縮約演算の意味属性としてコンパイラ中間表現へ保持する。後段のコード生成はこの木をレジスタ内、warp内シャッフル、warp間共有メモリといった階層へ一貫して写し、最適化パスが勝手に再結合してビット挙動を変えないようにする。同時に、固定順序によって失われたスループットを回収するため、縮約軸へより多くの実行レーンを割り当て、保持次元をwarpへ分散し、残りをレジスタへ置く配置変換を適用する。レジスタ圧力や既存分散度を解析して逆効果になる場合は変換を抑制する。これにより同じビット依存木の範囲内で並列配置を最適化でき、27カーネル中19個を自由順序版の10%以内へ戻し、一部では自由版を上回る。

### 静的同値判定と自動調整統合
最終的な機械語が要求された縮約木を実装しているかを実行テストだけに頼らず静的に確認する。NVIDIAおよびAMD系GPUのアセンブリから浮動小数点演算、レジスタ定義使用関係、lane間shuffle、共有メモリ通信を追跡し、各出力要素へ寄与する入力と演算順序をsymbolic expressionとして再構成する。ビット同値性を壊さない安全な正規化だけを行い、同じ依存木と型・丸め境界を持つ場合にのみ同値と判定し、解析不能な場合は同値と推測しない健全性を優先する。この判定器をautotuner前段へ組み込み、数百から数千のtile、warp数、パイプライン構成を算術同値類へ分類し、基準カーネルと同じ類だけをベンチマークする。したがってdeterminismのためautotuning全体を無効化する必要がなく、同じbitwise behaviorを保証したままhardwareやshapeごとの最速scheduleを選べる。

### 全体のデータ／制御の流れ
カーネル templateから多数構成をcompileし、assembly-level verifierでbitwise equivalence classへ分割し、要求類だけをベンチマークして最速候補を選ぶ経路と、vendor libraryをblack-box observationからarithmetic descriptorへ復元し、同一descriptorのgenerated カーネルへ写す経路を共通のreduction-tree semanticsで接続する。
## 評価条件
- **ハードウェア**: NVIDIA H100、NVIDIA GB200、NVIDIA GB300、AMD instruction-set analysis for GCN checker
- **ソフトウェア**: Triton compiler/backend、NVIDIA cuBLAS/cuBLASLt 12.8.5 and 13.1.x、PyTorch Inductor generated カーネル、PTX and AMD GCN 静的 analysis
- **データセット／トレース**: realistic GEMM shapes extracted from 16 model configurations、random and exponent-spread numeric inputs、compiled reduction/normalization/fused-カーネル suites
- **比較対象**: cuBLAS/cuBLASLt、free-order Triton reduction、torch.compile generated カーネル、動的 execution-based equivalence grouping
同一入力の出力バイト列を直接比較し、通常乱数だけでなく指数範囲を広げた入力でも縮約再編成を検出する。静的判定器は実行比較結果と照合し、同値と判定した組に不一致がない健全性を優先する。
主対象はGPUカーネルのビット再現性。サービング全体のスループットやモデル最終精度を直接最適化する研究ではない。注意の縮約順序は理論分析が中心で評価範囲が限定される。
## 主要結果
算術記述子から再構築した行列積は対象のHopper/Blackwell三世代で非公開ライブラリと100%ビット一致し、現実的なLLM形状の後処理融合でも生成系の性能は一般的なコンパイル経路と同等以上になる場合がある。平衡木縮約をコンパイラで強制した際の性能低下は配置最適化で大きく回復し、27カーネル中19個が自由順序版の10%以内、対象H100の一部では自由版を上回った。静的判定器は二社命令集合を扱い、自動調整候補を実行前に同値類へ分割できる。さらにブラックボックス解析の過程で、特定の縮約軸分割経路が末尾要素を落とす非公開ライブラリ不具合も発見した。

- 非公開行列積とのビット一致 / 100% (比較対象: cuBLAS family; 条件: GB300、GB200、H100、対象fp16/bf16/fp8条件) — 縮約順序を決める記述子だけで閉鎖ライブラリの算術を再現できる。

- 固定縮約の性能回復 / 27カーネル中19個が自由順序版の10%以内、H100の10件中5件は上回る (比較対象: free-order mode; 条件: balanced-tree compiler enforcement + layout optimization) — ビット順序固定は必ずしも大きな並列性損失を意味しない。

- 大規模加速のビット検証 / 154,904 byte comparisonsで差0 (比較対象: descriptor-equivalent reference; 条件: GB300 acceleration arm) — 同じ記述子内ならpersistent grid等のスケジュール最適化を追加しても同じビットを維持できる。

- 非公開ライブラリ末尾欠落条件 / H100で各ライブラリ1,542,555実行を調べ、条件が全欠落を誤検出なしで予測 (比較対象: full-K reference; 条件: split-K tail bug) — 算術復元は再現性だけでなく閉鎖実装の論理不具合検出にも使える。

- 記述子起動のホスト費 / 約100µs対ポインタ起動約20µs (比較対象: pointer launch; 条件: descriptor path) — 100µs未満の短い行列積ではホスト側記述子構築費が見える。

### 負の結果・境界条件
- 順序固定を単純適用すると最大約20%級の性能懸念があり、配置最適化が必要。
- 27カーネルすべてが10%以内に入るわけではなく8件は差が残る。
- 注意カーネルの縮約順序は理論分析が中心で、行列積ほど深く実装・評価していない。
- 静的判定は健全性を優先するため、実際は同値な二カーネルを別類へ分ける偽陰性が残り得る。

### 結果の読み方
再現性を得るために高速カーネルや自動調整を全面禁止するのではなく、算術同値類を先に固定し、その内部でスケジュール・配置を自由に最適化する設計が有効である。
## 品質への影響
同じ重み・入力・乱数種でも実行構成で出力ビットが変わる経路を制御し、バッチ不変性、推論再現性、学習・推論エンジン整合性を改善する。
## 既存研究との差
従来の決定論モードは安全な既知カーネルへ固定して探索自由度を落とすことが多い。本研究は縮約順序を意味記述子として速度スケジュールから分離し、同一算術類の内部ではタイル、持続実行、パイプライン等を最適化できる。動的実行比較だけでなくコンパイル済み命令列の静的判定を自動調整前へ置く点も異なる。
## 限界
- 注意カーネルは理論分析中心で実装評価が限定的。
- 静的判定器は健全性優先のため同値候補を取りこぼす可能性がある。
- 記述子構築の約100µsホスト費は短いカーネルで無視できない。
- 非公開ライブラリの復元は対象世代・版ごとの事前計測を必要とする。
- モデル全体の再現性には乱数、通信、他演算子、ドライバ等も関与し本手法だけで全スタックを保証しない。
## 実装状態
Triton後段の平衡木属性・配置変換、記述子駆動行列積族、PTX/AMD命令列の静的同値判定、自動調整枝刈りを実装して評価。
## 研究上の位置づけ
カーネル性能とビット再現性を二者択一にせず、算術意味を固定した同値類の中でスケジュール最適化するというコンパイラ設計。
