# AgentKVShift: Efficient KV Cache Reuse for Agentic Memory Systems

> 構造化エージェントメモリの一部トークンだけを再計算し、そこから推定したメモリ単位のKV残差を未再計算トークン全体へ加えて、低い再計算率で品質を回復する。
## 書誌情報
- **著者**: Nilesh Prasad Pandey, Jason Kong, Lanxiang Hu, Quanling Zhao, Yujie Zhao, Onat Gungor, Hao Zhang, Tajana Rosing
- **著者・所属**: University of California, San Diego
- **公開**: arXiv
- **種別**: Preprint
- **対象**: KVキャッシュ再利用、エージェントメモリ、プリフィル高速化、部分再計算、KV量子化
- **実装**: 学習不要。第1層でプローブ候補を決め、各層でそのプローブだけ新しいKVを計算してメモリ単位の平均残差を推定し、未再計算KVへ重み付きベクトル加算する。既存のKV量子化とも併用できる。
## 概要
長期対話エージェントは、過去の会話を要約・タグ・関係情報付きの構造化メモリとして保存し、質問ごとに必要なメモリ単位を取り出す。しかし同じメモリ文字列でも現在の質問や前後文脈が変わるとTransformer内部のKV状態は変わるため、保存済みKVをそのまま再利用すると品質が落ち、毎回全トークンを再計算するとプリフィル遅延が大きい。AgentKVShiftは、再利用KVと現在文脈で再計算したKVの差がメモリ単位で共通のオフセットを強く含むことを利用する。各メモリの10〜30%程度だけをプローブとして再計算し、その差の平均を残りの未再計算トークンにも加えて補正することで、少ない再計算量からメモリ全体を現在文脈へ近づける。

AgentKVShiftは、構造化メモリで生じるKV再利用誤差を特異値分解して調べ、各トークン固有のばらつきだけでなく、同じメモリ単位の全トークンへ共通する大きな残差オフセットが存在することを利用する。少数のプローブトークンだけを現在文脈で再計算し、再利用KVとの差から層ごとの平均オフセットを推定する。その推定値をプローブ以外のKVにも重み付きで加えるため、再計算予算が直接触れていない90%程度のトークンまで現在文脈へ補正できる。トークン選択だけで終わる従来法と異なり、少数の新鮮な計算をメモリ単位の補正信号として全体へ広げる点が中核である。

代表結果として、LoCoMo F1は再計算率10%で完全再計算0.339/0.390、CacheBlend 0.178/0.286、ProphetKV 0.125/0.329に対してQwen2.5-3B + AMemで0.319、LiCoMemoryで0.384。少数プローブから得た共通残差を未再計算トークンにも配ることで、90%を古いまま残す選択型方式より完全再計算へ大幅に近づく。
## 問題設定
エージェントメモリでは、過去の会話を単なる原文断片ではなく、要約、キーワード、タグ、時系列や関係情報を含むメモリ単位へ加工して保存する。質問時には関連メモリを取り出してプロンプトへ挿入するが、同じメモリ文字列でも周囲の質問・指示・会話履歴が変わればTransformer各層のキーと値は変化する。そのため保存時のKVをそのまま使うと注意出力がずれ、毎回全KVを作り直すと長いメモリほどプリフィル計算が支配的になる。CacheBlendなどの既存法はRAGの生文書を想定し、ずれの大きい少数トークンだけを再計算して残りを古いまま使うが、メタデータが豊富な構造化メモリではずれがメモリ全体へ広がるため低い再計算率で品質が大きく落ちる。
## 新規性
AgentKVShiftは、構造化メモリで生じるKV再利用誤差を特異値分解して調べ、各トークン固有のばらつきだけでなく、同じメモリ単位の全トークンへ共通する大きな残差オフセットが存在することを利用する。少数のプローブトークンだけを現在文脈で再計算し、再利用KVとの差から層ごとの平均オフセットを推定する。その推定値をプローブ以外のKVにも重み付きで加えるため、再計算予算が直接触れていない90%程度のトークンまで現在文脈へ補正できる。トークン選択だけで終わる従来法と異なり、少数の新鮮な計算をメモリ単位の補正信号として全体へ広げる点が中核である。
## 手法
### 手法のあらまし
メモリシステムは各保存メモリについて、以前その文字列を符号化したときの層別KVを保持している。新しい質問でそのメモリが再取得されたら、まず保存KVを候補として読み込む。第1層では各トークンについて、現在文脈で計算したKVと保存KVの差の大きさを調べ、キー用と値用に差が大きい上位トークンをプローブとして選ぶ。再計算率rならメモリ長nに対して約rn個を選び、このプローブ位置は後続層でも固定する。各層ではプローブだけを完全に再計算し、その新しいKVと保存KVの差を平均して、そのメモリ単位・その層に固有のキー残差と値残差の代表ベクトルを得る。プローブ自身は新しいKVをそのまま使う。残りのトークンは再計算せず、保存KVへ代表残差を加える。補正量は第1層で観測した各トークンのずれを0〜1へ制限した重みで調整し、元から新鮮なKVに近いトークンへ過剰補正しない。これを全層で繰り返すことで、全トークンを再符号化せずに現在文脈で得られるKVへ近づける。理論上は残差をメモリ共通バイアスと軽い裾を持つトークン固有変動に分解し、プローブ平均が共通バイアスを十分正確に推定できれば、補正後の注意出力誤差上界が未補正再利用より小さくなることを示す。

### メモリ単位の残差構造分析
保存時KVと現在文脈で完全再計算したKVの差をメモリ単位で行列化し、各層で特異値分解する。キー・値の両方で先頭特異値が支配的で、各トークンの残差からメモリ内平均を引くとその支配成分が大きく減ることを確認する。これは再利用誤差が独立なトークン雑音だけではなく、メモリ単位で共有される方向を持つことを意味する。付録では平均補正が残差エネルギーの64〜86%程度を説明し、先頭特異値を元の約24〜45%へ落とす条件を示す。この観測により、どのトークンを捨てて再計算するかだけでなく、少数トークンから共有ずれを推定して未再計算トークンへ伝える設計が正当化される。

### プローブ選択と層別平均残差推定
第1層で各トークンの新旧キー・値のL2差を計算し、キー用と値用に差が大きい上位b個をプローブとして選ぶ。bは再計算率rとメモリ長nから決まり、選択した位置は全層で再利用するので層ごとの探索を省く。各後続層ではプローブ位置だけを現在文脈で再計算し、保存KVとの差を平均して、その層におけるメモリ共通のキー残差ベクトルと値残差ベクトルを得る。プローブ数を増やすほど平均推定誤差は小さくなる一方、プリフィル計算は増える。したがって再計算率は品質と速度を直接調整するつまみとなり、実験では10%付近でもLoCoMo品質を完全再計算近くへ戻せる。

### 未再計算KVへの重み付きシフト
プローブトークンは完全再計算したKVへ置き換え、それ以外は保存KVを残したまま、推定したメモリ共通残差を一回のベクトル加算で足す。各トークンの補正係数には第1層で測った新旧KV差を上限1で切った値を使い、元の保存KVが現在文脈と近いトークンは小さく、ずれの大きいトークンは強く補正する。従来法では再計算されない大多数のトークンが完全に古いまま残るのに対し、この方式では再計算予算から得た情報がメモリ全体へ作用する。量子化済みKVを再利用する場合も、プローブで観測する新旧差には文脈変化と平均量子化誤差の両方が含まれるため、同じ補正が両者をまとめて吸収できる。

### 全体のデータ／制御の流れ
既存エージェントメモリが保存するメモリ単位とKVキャッシュをそのまま利用し、取得時にプローブ再計算とベクトル補正を挟む。モデル再学習や専用パラメータは不要で、再計算率をメモリ単位で設定できる。第1層でプローブ位置と重みを決め、以後の各層では同じ位置だけを再計算して層固有の平均残差を更新する。
## 評価条件
- **ハードウェア**: LoCoMoのQwen2.5-3B、Qwen3-4B、Mistral-7Bは単一NVIDIA A100で評価する。AMA-BenchのQwen3-32Bとスループット測定はメモリ・計算量のため単一H200を使用する。スループットは2K、4K、8K、16Kトークン/要求とバッチ1、4、8、16を掃引する。
- **ソフトウェア**: エージェントメモリはノート型AMemと階層グラフ型LiCoMemoryを使用し、KV再利用比較対象は高ずれトークンを選ぶCacheBlendと質問依存選択のProphetKV。完全KV再計算を品質上限として比較する。量子化併用ではFP8、KIVI 2/4-bit、OTT 2/4-bitを試す。
長期対話メモリのLoCoMoでは10個の長い複数セッション会話から多段・時間・推論質問を評価し、F1、ROUGE-1、BLEU-1を測る。3B〜7Bの三モデルとAMem/LiCoMemoryの組合せで主に再計算率10%を比較する。AMA-Bench-RecallではQwen3-32BとAMemを使い、Embodied AI、Game、OpenWorld QA、Software、Text2SQL、Webの6領域でF1とGPT-4o判定の二値正解率を測り、主に再計算率30%を使う。さらにLoCoMo Qwen2.5-3Bで再計算率5〜95%を掃引し、品質が完全再計算へ近づく速度を比較する。プリフィル性能はモデル規模、文脈長、バッチを変え、完全再計算に対する高速化倍率を測定する。KV量子化併用では再計算率10%と30%でF1を比較する。
方式は取得済みメモリ単位のKV再利用に特化し、通常の安定した共通接頭辞キャッシュとは問題設定が異なる。主品質評価はLoCoMoとAMA-Benchで、AMA-Benchの状態更新・因果推論・状態抽象化など複数メモリ間の高度な推論では完全再計算との差がRecallより大きい。スループットは単一GPU環境であり、分散サービング、KV転送、複数要求間スケジューリングの効果は含まない。
## 主要結果
AgentKVShiftは再計算率10%でもLoCoMoで完全再計算に近い品質を維持し、同じ予算で未再計算KVを放置する既存方式との差を大きく広げる。Qwen2.5-3BとAMemではF1 0.319で完全再計算0.339から相対5.9%低下に留まる一方、CacheBlendは0.178、ProphetKVは0.125まで落ちる。LiCoMemoryでは三モデルで完全再計算との差が1.5〜3.5%程度になる。再計算率を掃引すると既存法が完全再計算近傍へ達する45〜55%に対し、本方式は10%付近で約2 F1ポイント以内へ到達する。

- LoCoMo F1 / Qwen2.5-3B + AMemで0.319、LiCoMemoryで0.384 (比較対象: 完全再計算0.339/0.390、CacheBlend 0.178/0.286、ProphetKV 0.125/0.329; 条件: 再計算率10%) — 少数プローブから得た共通残差を未再計算トークンにも配ることで、90%を古いまま残す選択型方式より完全再計算へ大幅に近づく。

- 再計算量 / 約10%で完全再計算から約2 F1ポイント以内、既存法は45〜55%付近で同等品質 (比較対象: CacheBlend / ProphetKV; 条件: LoCoMo、Qwen2.5-3B、再計算率5〜95%掃引) — 同等品質に必要な再計算量を最大約5分の1へ下げ、速度向上を品質劣化で相殺しにくい。

- プリフィル高速化 / 4K・バッチ16で3Bは3.33倍、32Bは3.65倍。長文脈でも概ね2.4〜3.0倍 (比較対象: 完全KV再計算; 条件: 再計算率10%、単一A100またはH200) — 補正は層ごとのメモリ単位ベクトル加算なので、同じ再計算率なら既存法とほぼ同じ速度曲線を保ちつつ品質を高くできる。

- 2-bit量子化併用F1 / KIVI 2-bit・再計算率10%で0.203、OTT 2-bitで0.202 (比較対象: CacheBlend 0.076/0.080、ProphetKV 0.012/0.038; 条件: LoCoMo、Qwen2.5-3B、AMem) — プローブ平均が文脈ずれだけでなく平均量子化誤差も吸収するため、低ビットKV保存と計算削減を重ねても既存再利用法より品質が残る。

### 負の結果・境界条件
- 単一要求・短文脈では補正処理の固定費が効き、Qwen2.5-3Bの2K・バッチ1・再計算率10%では0.94倍で完全再計算よりわずかに遅い。AMA-BenchのRecall以外、特に複数メモリ間の状態更新や因果推論では全KV再利用法が完全再計算との差をより大きく残す。量子化併用でも2-bitではAgentKVShift自体のF1が無量子化0.319から約0.20へ低下し、補正が量子化損失を完全には消さない。理論上の改善条件も、メモリ共通バイアスがプローブ推定誤差などを上回る場合に限られる。

### 結果の読み方
構造化メモリでは要約やタグなど同じメモリ内トークンが現在文脈の影響を共有しやすく、再利用誤差にメモリ共通成分が生じる。この成分が大きいほど少数プローブの平均が全体のずれをよく表し、未再計算トークンまで一括補正できるため低い再計算率で利益が大きい。逆に短い入力や小さいバッチでは再計算自体が軽く、補正固定費の比率が上がる。複数メモリをまたぐ推論ではKV近似だけでなくエージェント側推論状態も効くため、局所メモリ補正だけでは完全再計算との差を閉じにくい。
## 品質への影響
近似KVを使うため完全再計算と同一品質ではないが、10〜30%の再計算で多くの条件を完全再計算近傍へ戻し、同じ再計算率の既存法より品質劣化を大幅に抑える。
## 既存研究との差
vLLMの接頭辞キャッシュやSGLangのRadixAttentionは同じ長い接頭辞が再出現する場合にKVを正確に再利用するが、質問ごとに取得メモリと順序が変わる動的検索では共有接頭辞が少ない。CacheBlendは保存KVと現在KVの差が大きいトークンだけを選択して再計算し、ProphetKVは質問依存の選択基準を使うが、選ばれなかったKVは古いまま残す。AgentKVShiftは選択したトークンを単なる置換対象ではなく残差推定用プローブとして使い、その情報を未選択KV全体へ伝える。KV量子化とは目的が異なり、量子化が保存・転送量を減らすのに対し、本方式はプリフィル再計算を減らすため併用できる。
## 限界
補正モデルは各メモリ単位の残差が共有オフセットと比較的小さいトークン固有変動へ分かれるという仮定に依存する。論文はスペクトル分析と集中性診断でこの傾向を支持するが、すべてのメモリ形式・モデル・層で保証されるわけではない。キー残差と値残差には非対称性があり、単純な平均シフトで表せない高次構造は残る。主方式は各メモリ単位を独立に補正するため、複数取得チャンク間の関係やエージェントの内部推論状態を直接モデル化しない。単一GPU評価で、分散KV保存・転送やキャッシュ容量管理を含む実サービング全体の性能は未評価。
## 実装状態
学習不要で既存モデルの重みを変更しない。必要なのはメモリ単位で以前の層別KVを保存し、取得時に第1層でプローブ位置を決め、各層でプローブKVの再計算と平均残差ベクトルの加算を行う処理である。論文はA100/H200上で実測し、同じ再計算率なら既存選択法とほぼ同じ速度曲線になることを示す。公式コードURLは一次資料本文では確認できなかった。
## 研究上の位置づけ
KVキャッシュ再利用研究のうち、固定接頭辞ではなく動的に取得される文脈を再利用する系統に属する。特にエージェントメモリでは、同じメモリ内容が異なる質問や会話状態の下で何度も再取得されるため、保存KVの再利用価値が高い一方、文脈依存ずれも大きい。本方式はそのずれをトークン単位の再計算対象選択ではなくメモリ単位の低次残差として扱う点で、CacheBlend/ProphetKVから一段異なる。階層KVキャッシュやSSD退避と組み合わせる場合、保存先から読み戻したKVを再計算せず補正して使えるため、I/O削減とプリフィル計算削減を別軸で重ねられる可能性がある。
