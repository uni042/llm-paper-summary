# DistillCache：KL分布保存を目的とする適応的KVキャッシュ削除

## 概要

自己回帰型の大規模言語モデルは、過去トークンの鍵と値をKVキャッシュへ保持して注意計算の再実行を避ける。しかし長い文脈ではキャッシュ容量がほぼトークン数に比例して増え、同時要求数、実効帯域、復号処理率の制約になる。従来のH2OやSnapKVは累積注意量や観測窓の注意統計から保持候補を選ぶが、将来の推論で重要になる語が現在低注意である場合を直接評価できない。DistillCacheは削除方策を強化学習で訓練し、教師モデルの完全キャッシュと生徒モデルの削減キャッシュから得られる次トークン確率分布の差を小さくする。

特徴量はトークン当たり5個で、注意量、値ベクトルの大きさ、ヘッド間分散、最近の注意分布のエントロピー、相対位置からなる。学習時には確率的に上位B件を選び、報酬を負のカルバック・ライブラー（KL）ダイバージェンスとする。実行時には教師側計算を捨て、特徴抽出と軽量方策の決定的選択だけを追加する。したがって学習時の教師・生徒二重計算と実行時の一回の前向き計算を混同してはならない。

原著表1によると、Mistral-7B-Instruct-v0.3のLongBenchで完全キャッシュ41.5に対して、25%予算の提案法は39.1±1.1（完全版の94.2%）を得る。比較対象のH2Oは36.4±1.5、SnapKVは37.0±1.3である。ただし同じ25%予算、RTX 4090二枚での端から端までの処理率は提案法38.0トークン/秒で、H2Oの42.8、SnapKVの41.5を下回る。品質を重視する保持方策の利点と、毎ステップの方策評価費用を別々に評価する必要がある。

## 問題設定と設計上の前提

対象は自己回帰型変換器（Transformer）の復号過程である。モデルが保持する時刻tのキャッシュをC_t、残すトークン集合をC'_t、保持上限をBとすると、|C'_t|≤Bの範囲で出力分布のずれを抑えることが目的となる。これは「現在もっとも注目されたトークンを残す」という局所的な代理目標と異なり、過去の削除判断が後続の推論へ累積的に影響することを考慮する。

たとえば否定語、節の主語、後から参照される根拠の位置は、ある時点の注意質量だけでは重要性が小さく見える場合がある。削除したトークンの情報は次ステップ以降の生徒キャッシュから消えるため、後から必要になっても回復できない。著者は教師側を常に完全キャッシュに保ち、削減側がどの程度将来の分布を変えたかを報酬として観測する。

ここでの「25%予算」はKV項目の保持率を指し、モデル重みを25%に圧縮する意味ではない。また、完全版比94.2%はLongBenchのスコア比であり、全タスクの正答率が94.2%という意味でもない。端から端までの処理率には注意計算以外のメモリ管理、特徴抽出、方策計算が含まれる。

## 手法

### 1. トークン状態の5特徴とスコア化

保持候補iごとに、平均注意質量α_i、値ベクトルの二乗ノルム、注意ヘッド間の受信注意分散σ_i、注意エントロピーH_i、正規化した系列内位置pos_iを計算する。α_iは各層・各ヘッドをまたいで直近の前向き計算で受けた注意量を表す。値ベクトルの大きさは、同程度の注意重みでも出力への寄与が異なり得ることを表す補助信号である。ヘッド間分散は特定のヘッドだけで高い重要度を持つ場合を区別する。

H_iはトークンi自身の情報量ではなく、最近64クエリの注意分布エントロピーを、そのクエリがiへ割いた注意重みで平均した値である。集中したクエリから強く参照される場合と、広く薄い注意の一部として参照される場合を区別するための特徴である。原著の式では各クエリqの注意分布a_qについてH(a_q)を計算し、a_q(i)を重みとして平均する。注意エントロピーの定義をトークンiの出現頻度と取り違えないことが重要である。

これらを多層パーセプトロン（MLP）f_φへ入力し、各トークンの保持スコアs_iを得る。全候補を独立に採点するため、トークンの組合せの相乗効果を明示的な注意ネットワークで直接学習するわけではない。トークン集合はスコア上位B件で構成され、実行時には初期の注意シンクや直近窓を規則として強制保存しない。原著の図2は、方策がそれらの重要トークンを学習によって保持する傾向を示す定性的な例であり、一般的な保証ではない。

### 2. 確率的保持と逐次報酬

学習時には各スコアへガンベル（Gumbel）雑音を加えて順位を標本化し、上位B個の部分集合を保持する。探索を伴う確率的選択により、どのトークンを落とすと将来の出力分布が変わるかを試せる。実行時は雑音を使わず決定的に上位B個を選ぶため、学習用の標本化費用をオンライン推論へ持ち込まない。

教師キャッシュは削除せず全履歴を保持する。生徒キャッシュは過去の削除を引き継ぎ、毎ステップの新しい鍵・値を追加してから再選択する。両者の次トークン分布をそれぞれP_t、P̂_tとすると報酬はR_t=−D_KL(P_t||P̂_t)である。単一トークンの正解ラベルではなく、全語彙に対する確率分布を教師信号に使うため、特定ベンチマークの正誤だけを目的とする方式とは異なる。

著者は削除された注意質量ε_tと値ベクトルのノルム上限を用い、注意出力の誤差が2Cε_t以下になること、さらに局所的な仮定のもとで分布差を抑える関係を導く。この理論は誤差を抑える目的の動機付けであって、すべての長文脈・全モデルに対する正答率保証ではない。実際の方策は近似的な確率的最適化であり、分布差を常にゼロにするわけではない。

### 3. 方策勾配と分散低減

最適化にはREINFORCEを用い、各時刻の割引累積報酬G_tと基準値b_tとの差に、選択集合の対数確率の勾配を掛ける。割引率は0.99、方策エントロピーの正則化係数は0.01である。単純な方策勾配は標本分散が大きいため、バッチ内の他の標本の平均を用いるleave-one-out基準と指数移動平均の基準を併用する。方策エントロピーは選択確率から単一標本で推定する。

原著付録Cでは部分集合の分配関数を動的計画法で厳密計算するとし、系列長Lと保持数Bに対して時間O(LB)、空間O(B)と記述する。これをオンライン推論の計算量と混同してはいけない。実行時は上位B選択のみであり、分配関数の計算は不要である。一方、訓練対象の長さを4,096以下としているため、128Kなどへの学習時の計算費用は未検証である。

**再現上の注意**：付録Cはガンベル上位B選択をPlackett–Luce分布と呼びながら、無順序集合の確率を「選択集合の重み積を全B部分集合の重み積和で正規化した式」として提示する。一般には、逐次順位に由来するPlackett–Luceの無順序上位B集合確率はその単純な積正規化と一致しない。この式をそのまま実装した場合、記述された標本化分布と方策勾配が食い違う可能性がある。著者実装を確認できない段階では、正しい確率モデルを一意に再構成できたとは扱わない。

### 4. オンライン推論の処理順と保持予算

推論では削減済みキャッシュを使って現在のトークンの前向き計算を一度実行し、ロジット、注意重み、新規鍵・値を得る。特徴を更新し、方策が全保持候補を採点して上位B件だけを次ステップへ渡す。現在の生成トークンは削除前に得たロジットから選ぶので、今回の削除の影響は次回以降に現れる。教師モデルとの二重計算やKL報酬計算はオンライン経路に含まれない。

原著アルゴリズム1はB=max(floor(r×|C_t|),32)と記述する。ここでrは保持率、|C_t|はその時点で採点するキャッシュ長、32は最低保持数である。ただし本文には「元の完全履歴長」ではなく「現在キャッシュ長」を基準にした記述もあるため、長い復号でこの式を文字どおり逐次適用した場合の実効保持率には解釈上の注意が必要である。原著の表にある25%予算の結果を再現する際は、採点前後のキャッシュ長と予算更新の定義をコードで確定する必要がある。

特徴抽出には注意重みと値テンソルへのアクセスが必要である。高度に融合された注意カーネルがこれらの中間値を通常は外部に公開しない場合、特徴収集の追加転送やカーネル変更が必要になる可能性がある。原著は特徴抽出0.9ミリ秒、方策評価0.5ミリ秒という追加費用を報告するが、すべての推論エンジンで同じ値になるわけではない。

### 別モデルへの移植

付録EではMistral-7Bで学習した方策をLlama-3-8B-Instructへ追加学習なしで移す実験を示す。これは「別の7〜8B級モデルで一定の性能を保てる」という限定的な証拠であり、異なる注意機構、巨大なMoE、状態空間モデル、長い128K文脈に無調整で対応する保証ではない。また比較対象の強化学習方式は移植先モデルで再学習した条件を含むため、計算費用の比較と品質の比較は分けて解釈する必要がある。

## 既存研究との差

H2Oは過去の累積注意量に基づく重要トークン保持を基本とし、StreamingLLMは初期の注意シンクと直近窓を保存する。SnapKVは観測窓の注意分布から代表的なKV項目を選ぶ。これらは訓練不要で簡便な一方、後続の生成結果を教師信号として直接学習しない。DistillCacheは削除後の次トークン分布が完全版と一致するかを報酬化し、将来の誤削除の影響を含む逐次決定を最適化する。

ForesightKVは将来寄与の予測を用い、RLKVは推論上重要な注意ヘッドを対象とする。DistillCacheはトークン単位の単一方策であり、同じ保持予算でも選択の粒度と報酬の対象が異なる。原著はForesightKVとRLKVの公式実装を使わず公開説明に基づく再実装で比較したと明記するため、実装差を統制した厳密な第三者比較とは位置付けない。著者はヘッド単位とトークン単位の組合せを将来の方向としているが、正式な統合基盤の実装が示されたわけではない。

## 限界と監査上の留意点

第一に、方策の学習は2枚のRTX 4090を用い、教師・生徒の二重キャッシュと約130 GPU時間を必要とする。原著は5種の乱数種の実験を報告するが、130 GPU時間の集計対象の説明は付録の「5回の壁時計時間」と本文の「学習費用」の記述を併読する必要がある。追加のオフライン学習費を繰り返し推論で償却できるかは、実際の要求量とGPU単価による。

第二に、25%保持時の品質ではH2Oより高いものの、端から端までの処理率はH2Oより低い。特徴量抽出には注意行列などの内部信号が必要で、カーネル融合や量子化・オフロードを併用した場合の実装費用は測られていない。論文で示した約2.1倍は完全キャッシュ基準との比較であり、既存の高速なKV削除方式に対する速度優位ではない。

第三に、文脈長の評価は2K〜8Kが中心で、32K〜128Kや13B以上のモデルは今後の課題として明示されている。Llama-3-8Bへの一度の移植は有益だが、広範なアーキテクチャ間の一般化の証明ではない。単一方策は各トークンを独立採点し、複数トークンの相互依存を明示的にモデル化しない。

第四に、原著付録Cの「ガンベル上位Bの無順序集合確率」と「単純な重み積による分配関数」は一般には同じ分布ではない。これは方策勾配の再現性に関わるため、公開コードや著者の訂正が確認できるまでは確率式の厳密性に留保を付す。本文の実験結果自体をこの数学的疑義だけで否定するわけではないが、実装と論文式が一致するかは別途検証が必要である。

第五に、付録Dは「入力5、隠れ幅128の二層MLP」と「約20万パラメータ」を同時に記載する。一般的な全結合層を5→128→128→1と解釈すると重み・バイアスは約1.7万であり、LayerNormを加えても約20万には達しない。実際の層数、共有方式、パラメータの数え方に追加情報が必要である。再現実装では論文の「約20万」を構成から自動的に導けると断定しない。

第六に、付録Gは「実験は単一GPU設定に限定」と記す一方、付録Dと表3は「RTX 4090二枚のテンソル並列」を明記しており、実験環境の記述に不整合がある。ここでは実測表の明示条件を採用し、単一GPUで同じ速度を再現したとは扱わない。さらに付録Cは「released code」の関数名を記すが公式リポジトリURLは本文から確認できず、コードの公開状況は未確認とする。
