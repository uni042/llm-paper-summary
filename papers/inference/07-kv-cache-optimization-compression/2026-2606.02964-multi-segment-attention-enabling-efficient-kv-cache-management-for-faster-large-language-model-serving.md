# Multi-Segment Attention: Enabling Efficient KV-Cache Management for Faster Large Language Model Serving

> 長文・複数ターンのLLMサービングでは、GPUメモリ不足時にKVキャッシュを追い出して後で再計算する損失なし管理が必要になるが、従来方式は再利用頻度や位置だけを見ており、どのKVブロックを残すとGPU注意計算そのものがどれだけ速くなるかを十分扱っていない。AsymCacheは、非連続に残った複数KV区間を1回のGPU注意カーネルで処理する複数区間注意（Multi-Segment Attention; MSA）、再利用確率と位置依存の再計算遅延を掛け合わせる追い出し器、負荷に応じてプリフィル分割量を変える適応チャンク化を統合する。vLLM上のH20実機評価で、最新比較対象に対し先頭トークン時間を最大1.90〜2.03倍、出力トークン当たり時間を1.62〜1.71倍改善し、出力値は近似せず保持する。

- **実装**: vLLMを拡張し、Python約6千行とC++/CUDA約2千行で実装。複数区間注意はCUTLASSを用いてFlashAttention/PagedAttention系の注意カーネルを拡張し、追い出し器はC++で実装する。
## 問題設定
損失なしKVキャッシュ管理では、GPUメモリが不足すると一部のKVブロックを捨て、同じ接頭辞が再び必要になった時にプリフィル計算をやり直して復元する。vLLMのLRUは再利用頻度を重視し、Pensieve系は後方トークンほど再計算費が大きい位置効果を重視するが、実ワークロードでは多数リクエストで共有される接頭辞と、長い会話の末尾の両方が価値を持つ。また中間だけを捨てるとGPU上のKVが非連続になり、既存注意カーネルを区間ごとに別起動すると起動・同期費が増える。したがって『どのブロックを残すか』と『残した非連続ブロックをGPUでどう速く計算するか』を同時に設計しなければ、単純な命中率最大化では実際の遅延を最小化できない。
## 新規性
AsymCacheの新規性は、KVブロックの価値を単なる命中確率ではなく、そのブロックを失った時に増えるGPU注意計算・再計算遅延との積で評価し、注意カーネルの性能特性を追い出し規則へ直接入れる点にある。さらに接頭辞と末尾のような非連続区間を1回の融合カーネルで処理するMSAを用意し、細粒度の追い出しを可能にする。追い出し選択は位置固定の費用モデルと順序保存可能な再利用頻度表現に変形して対数時間で実行し、負荷時にはプリフィルのチャンク長も動的に調整する。
## 手法
### 手法のあらまし
要求が到着すると、AsymCacheは既存KVの命中区間を確認し、新規KV用のGPUブロックを割り当てる。容量が不足する場合、各候補ブロックについて将来再利用される頻度と、そのブロックを失った場合に必要になる追加再計算遅延を組み合わせた期待費用を評価し、期待損失が最も小さいブロックから追い出す。再計算費はトークン位置で異なり、後方ブロックを復元するにはその前段までの計算も必要になるため一般に高い。一方、共有システムプロンプトなど前方ブロックは多くの要求から再利用されやすい。この二つを同じ尺度で扱うことで、接頭辞だけ、末尾だけという固定規則ではなく、現在のワークロードに応じて両端や複数ピークを残せる。

中間ブロックを追い出すとKVは複数の非連続区間に分かれる。既存カーネルを区間ごとに呼ぶとCPUからの起動とGPU同期が区間数だけ増えるため、AsymCacheはMSAを導入する。MSAは各KV区間を協調スレッド配列のグループへ割り当て、単一CUDAカーネル内で複数区間の注意を並列計算する。これにより追い出し器はカーネル起動費を恐れて連続接頭辞だけを残す必要がなくなり、計算価値の高い末尾も保持できる。

追い出し候補を毎回全走査するとKVブロック数が増えた時にCPUスケジューラがボトルネックになる。そこで再計算費をブロック位置だけから得られる不変量へ整理し、将来再利用頻度は時間減衰を含む順序保存可能な値として二つの平衡木で管理する。最小期待費用候補の取得と更新を対数時間に抑える。また再利用寿命は直近要求からオンライン推定し、会話間隔が変わっても固定タイムアウトに依存しない。

実行時スケジューラはチャンク化プリフィルとデコードを同居させる。デコード要求が多い時はプリフィルチャンクを小さくして、長い再計算プリフィルがGPUを占有して出力トークン待ちを悪化させない。一方、負荷が低い時は大きなチャンクでプリフィル効率を確保する。以上により、メモリ保持、再計算、注意カーネル、プリフィル分割を一つの遅延最小化目的へ接続する。

### 複数区間注意による非連続KV処理
接頭辞と末尾を残して中間を追い出すと、1要求の有効KVが複数の離れた区間になる。単純実装では各区間ごとに注意カーネルを起動し、部分結果を後で結合するため、短い系列ほどCUDAカーネル起動とホスト同期の固定費が支配する。MSAは複数区間の計算を単一カーネルへ融合し、それぞれの区間を協調スレッド配列群へ割り当て、GPUのストリーミングマルチプロセッサへ同時配置させる。入力は各要求のクエリと複数KV区間、出力は通常注意と同じ最終注意出力である。これにより非連続配置そのものの実行費を小さくし、追い出し器が命中率と再計算費だけで細粒度にブロックを選びやすくなる。ただし区間が極端に細かい場合やカーネル内負荷不均衡が大きい場合は融合の利得が弱まる。

### 期待遅延に基づくブロック追い出し
各KVブロックについて、将来再利用される度合いと、失った時に必要となる追加計算時間を別々に推定し、その積を『残す価値』として扱う。前方の共有接頭辞は多くの要求で再利用されるため頻度が高く、後方ブロックは再利用回数が少なくても、そこまで復元するための累積プリフィル計算が大きいため再計算費が高い。容量不足時にはこの期待損失が小さいブロックを優先して追い出す。入力はブロック位置、履歴再利用情報、モデル・系列長に対応する費用モデル、出力は追い出し候補である。これにより中央部だけを落として両端を残すような非対称配置を自然に選べる。再利用分布が急変すると履歴推定が遅れて一時的に不適切な選択をする可能性がある。

### 対数時間の費用モデル付き候補管理
正確な期待費用を全ブロックについて毎回計算すると、数千から十万規模のKVブロックでCPU側の追い出し選択が高価になる。AsymCacheは約1.1千点の実測プロファイルから再計算遅延を近似し、決定係数R²が0.999を超える費用モデルを構築する。さらに再計算費を不変な位置依存値として保持し、時間で変わる再利用頻度を区分指数関数へ変形して順序が保たれるようにする。二つの平衡木では各ブロックの順位を全件再計算せず更新でき、最小費用候補の取得をO(log n)へ抑える。約8千ブロック条件では全走査版の約200ms/要求に対し約2ms/要求まで制御費を下げる。費用モデルが異なるGPUやモデルへ外挿できない場合は再プロファイルが必要になる。

### 適応チャンク化と再利用寿命のオンライン調整
追い出したKVを再計算するプリフィルは計算量が大きく、デコード要求と同じGPUへ大きなチャンクを投入すると出力トークン生成を長時間待たせる。一方でチャンクを常に小さくするとプリフィルのGPU利用効率が落ちる。AsymCacheは実行中デコード要求数など現在の混雑度を観測し、混雑時にはプリフィルチャンクを最小値へ寄せ、余裕がある時には大きくして計算効率を確保する。またブロック再利用頻度の時間減衰に使う寿命係数を直近要求間隔の滑動統計から更新する。これにより固定した会話間隔や固定負荷を仮定せず、メモリ追い出しとGPUスケジューリングを同じ実行状況へ適応させる。急激な負荷変動時には統計追従まで短時間ずれる可能性がある。

### 全体のデータ／制御の流れ
AsymCacheはAPIサーバー、KVブロック管理器、費用認識追い出し器、MSA注意カーネル、チャンク化スケジューラをvLLM内部で連携させる。要求到着時に命中区間を特定して必要ブロックを確保し、容量不足なら期待遅延の小さいブロックを追い出す。残った非連続区間と再計算が必要な区間をスケジューラがプリフィルチャンクへ分割し、MSAが同一バッチ内で非連続KVを効率よく処理する。追い出しはGPUメモリ内だけで完結し、現版はCPU DRAMやSSDへの階層退避を使わない。
## 評価条件
- **ハードウェア**: AMD EPYC 9K84 96コアCPU、NVIDIA H20 96GB GPU×4、NVLink、CUDA 12.8
- **ソフトウェア**: vLLM拡張AsymCache、CUTLASS、FlashAttention/PagedAttention系MSA、POD-Attention比較基盤、Continuum統合
- **モデル**: Llama 3.1-8B-Instruct（1 GPU）、Llama 3.1-70B-Instruct（4 GPUテンソル並列）
- **データセット／トレース**: LongBench 300要求、LooGLE 300要求、BFCLv4 Web Searchエージェント評価
- **比較対象**: vLLM-LRU、Max-score O(n)再利用スコア、Pensieve+MSA再実装、Continuum
- **正確性・品質**: KV値を近似して捨てるのではなく、追い出した区間は必要になった時に元モデルで再計算するため、モデル出力を損失なく保持する。MSAも複数区間の注意を数学的に同じ結果へ結合する実装であり、性能と容量の交換で精度を落とす方式ではない。
- **長文複数セッション**: LongBenchとLooGLEから各300要求を構成し、ガンマ分布到着で複数セッション・複数ターンを再現する。LongBenchは平均入力約34.8K、出力約2.6Kトークン、LooGLEは約24.4K/0.7Kで、要求間隔の分散を変えて接頭辞共有と末尾再利用の混在条件を作る。
- **8B・70B実機サービング**: Llama 3.1-8BはH20 1枚、70Bは4枚のテンソル並列で動かし、先頭トークン時間、出力トークン当たり時間、要求・ブロックKV命中率を比較する。70Bでは利用可能KV容量を約505Kトークンに制限し、追い出しが実際に起きる条件で測る。
- **追い出し計算量アブレーション**: 同じ期待遅延方針を全走査O(n)で実装した版と、AsymCacheのO(log n)管理版を比較し、方針そのものの効果とCPU管理費削減を分離する。約8千ブロック規模の追い出し処理時間も別途測定する。
- **MSAカーネル単体**: 非連続接頭辞・末尾を別々の注意カーネルで処理する方式と、単一MSAカーネルを比較する。1Kと10Kトークン級系列を使い、短い系列ほど固定カーネル起動費が支配するかを検証する。
- **エージェント統合**: BFCLv4 Web Searchを用い、再現性のためGPT-5.1で出力を事前生成してサービング系の待ち・KV管理を比較する。AsymCache単独とContinuum統合の両方で平均ジョブ遅延とP90尾部遅延を測る。
命中率だけではなくTTFTとTPOTを主要指標にし、LRU、全走査スコア、Pensieve系と比較する。さらにO(log n)候補管理、MSA、ハイパーパラメータ、エージェント統合を個別に切り分けることで、追い出し規則とカーネル・スケジューラの寄与を分離している。
現版はGPUメモリ内での損失なしKV保持・追い出し・再計算が対象で、CPU DRAM、SSD、遠隔KVストアへの多階層退避は実装していない。長文、多セッション、複数ターン、エージェントのようにKV再利用と容量圧力が同時にある条件を主対象とする。
## 主要結果
AsymCacheは、単純なKV命中率最大化より実際のGPU計算遅延を重視することで、命中率がわずかに低い条件でもTTFTを短縮した。70B長文評価ではvLLM-LRU、Max-score、Pensieve+MSAに対してTTFTを最大1.86倍、1.91倍、1.86倍改善し、TPOTも最大1.62倍、1.63倍、1.71倍改善する。論文結論の全条件集約では最新方式に対しTTFT 1.90〜2.03倍、TPOT 1.62〜1.71倍と報告する。Continuumへの統合では平均ジョブ遅延を最大18.1%、P90を最大16.6%追加削減した。

- 70B先頭トークン時間 / 最大1.86倍 / 1.91倍 / 1.86倍改善 (比較対象: vLLM-LRU / Max-score / Pensieve+MSA; 条件: Llama 3.1-70B、長文複数セッション) — 接頭辞命中だけでなく後方ブロックの高い再計算費も評価するため、同じGPU容量をより遅延削減価値の高いKVへ割り当てられる。

- 70B出力トークン当たり時間 / 最大1.62倍 / 1.63倍 / 1.71倍改善 (比較対象: vLLM-LRU / Max-score / Pensieve+MSA; 条件: 同じ長文サービング評価) — 非連続KVをMSAで一括処理し、適応チャンク化で長い再計算プリフィルがデコードを塞ぐ時間を抑える。

- 混雑時TTFT・TPOT / TTFT最大60%/70%削減、TPOT最大62%/71%削減 (比較対象: vLLM-LRU / Pensieve+MSA; 条件: LongBench、70B、QPS 0.04付近) — メモリ方針だけでなくプリフィル再計算の分割を負荷に合わせるため、待ち行列が形成される条件で差が大きくなる。

- O(log n)追い出し制御費 / 約200ms/要求→約2ms/要求 (比較対象: O(n)全走査版; 条件: 約2.4K要求・約8K KVブロック) — 全候補走査を避け、CPU管理費をプリフィル時間の約10%から約0.1%へ縮める。

- MSA固定費削減 / 1K系列で別カーネル方式の固定追加費約4.61msを回避 (比較対象: 区間別注意カーネル; 条件: 非連続接頭辞・末尾注意) — 短い区間では複数カーネル起動・同期が支配するため、一つの融合カーネルにすることが非連続キャッシュを実用化する。

- Continuum統合 / 平均ジョブ遅延4.4〜18.1%削減、P90 6.8〜16.6%削減 (比較対象: Continuum単独; 条件: BFCLv4 Web Searchエージェント) — 要求粒度のエージェントスケジューリングとブロック粒度のAsymCacheが異なる階層でKV再利用を改善する。

### 負の結果・境界条件
- **命中率最大化と最小遅延は一致しない**: 低分散LongBench 70Bでは従来方針が最大約33%のブロック命中率を得る一方、AsymCacheは条件によって命中率がわずかに低くてもTTFTを最大1.36倍改善した。後方ブロックの再計算費が大きいため、命中率だけを性能指標にすると誤った方針を選ぶ。
- **エージェント単独利得は小さい条件がある**: BFCLv4 Web SearchでAsymCacheだけをvLLM-LRUへ加えた場合の平均ジョブ遅延削減は約0.4〜4.2%に留まる条件がある。上位実行系の待ちが支配するとKV管理だけの改善は全体へ薄まる。
- **多階層KV退避を扱わない**: KVはGPU内に残すか追い出して再計算する設計で、CPU DRAM、SSD、遠隔ストレージから読み戻す経路は未実装である。下位階層からの読込費は位置だけでなくサイズや帯域にも依存するため、そのまま同一追い出し式を適用できるとは限らない。
- **費用モデルは環境依存**: 再計算遅延モデルは対象GPU・モデルの実測プロファイルで高精度に近似する。異なるGPU世代、注意実装、モデル構造へ移ると位置ごとの限界費用が変わるため、再計測とモデル更新が必要になる。

### 結果の読み方
結果が示す中心点は、KVキャッシュ管理では『何トークン再利用できたか』ではなく『そのKVを残すことで何ミリ秒のGPU処理を避けられたか』を最適化すべきということである。接頭辞は再利用回数が多く、末尾は失った時の再計算費が大きいので、両方を残して中間を落とす選択が有効になる。ただしこの配置を実際に速くするには、非連続KVを一つの注意カーネルで処理するMSAと、追い出し判断自体を対数時間に抑えるデータ構造が必要であり、方針・カーネル・制御費を共同設計したことが速度差へつながっている。
## 品質への影響
近似KV枝刈りや低ビット圧縮とは異なり、必要なKVは再計算して元のモデル状態を復元するため出力品質は維持される。その代わり、容量削減を無料で得るのではなく再計算時間を支払う。AsymCacheはその再計算時間を位置と再利用確率から予測し、最も安い部分へ費用を集中させる方式である。
## 既存研究との差
- vLLMやSGLangのLRU型接頭辞キャッシュは共有接頭辞を残すことに強いが、後方KVを失った際の位置依存再計算費を直接評価しない。AsymCacheは再利用頻度と限界再計算遅延を同じ期待費用へまとめ、接頭辞と末尾を同時に残せる。
- Pensieve系は複数ターン会話で後方トークンの再計算費に注目するが、一般サービングで多数要求が共有する接頭辞の価値とGPU注意カーネル上の非連続区間処理を統合しない。AsymCacheは両端・複数ピークを一般化し、MSAでその配置を直接実行する。
- 近似KV圧縮・枝刈りは品質との交換で容量を下げる。AsymCacheはKV内容を近似せず、追い出し後に必要部分を再計算するので損失なしだが、計算費をどこへ払うかを最適化対象とする。
- CPU/SSDへのKVオフロード方式は再利用時に転送帯域・I/O遅延を支払うが、現版AsymCacheはGPU常駐か再計算かだけを選ぶ。したがって07-kv-キャッシュ-optimization-compressionが主系統で、10-kv-キャッシュ-オフロード-recomputationとは隣接するが多階層転送自体は未実装である。
## 限界
- 現版のKV保存階層はGPUのみで、CPU DRAM、SSD、遠隔KVキャッシュを使わない。多階層化すると読み戻し費が位置だけでなくブロックサイズ、帯域、混雑度に依存するため追い出し目的関数の拡張が必要になる。
- 再利用確率は履歴から推定するため、会話パターンや要求分布が急変すると一時的に古い頻度を使う。オンライン寿命調整はあるが、任意の分布変化を即時に捉える保証はない。
- MSAは非連続区間を単一カーネルへ融合するが、区間数や長さが極端に不均衡な場合にはCTA間の負荷不均衡が残り得る。論文評価はH20とLlama 3.1中心で、他GPU・MLA等への一般化は追加評価が必要である。
- 費用認識追い出しは正確な遅延モデルに依存する。約1.1千点のプロファイルではR²>0.999だが、カーネルやGPUを更新した後は再プロファイルしないと順位がずれる可能性がある。
- 損失なし性の代わりに、追い出したKVの再計算そのものは消えない。GPUメモリ圧力が極端で大半を追い出す条件では、選択最適化だけでは再計算量の絶対値を抑えきれない。
## 実装状態
vLLM上に約6千行のPythonと約2千行のC++/CUDAを追加した実機システム。MSAはCUTLASSを用いてFlashAttention/PagedAttention系処理を拡張し、追い出し器をC++、実行時統合をPythonで実装する。論文v1で公開コードURLは確認できなかった。
## 研究上の位置づけ
主系統は07-kv-キャッシュ-optimization-compressionが適切である。理由は、研究の中心が下位メモリへの退避経路ではなく、限られたGPU KV容量の中でどのブロックを保持するかと、その非連続配置をGPU注意計算へどう効率よく接続するかにあるためである。既存研究との重要な差は、キャッシュ命中率を代理指標として最大化するのではなく、KVブロックごとの将来再利用確率と位置依存の限界再計算遅延を結合し、実際のTTFT/TPOTへ近い目的で追い出しを決める点にある。またMSAを同時設計したことで、従来ならカーネル効率のため避けた非連続保持を実用的な選択肢にした。SSD研究への示唆として、多階層KVへ拡張する場合は命中率だけでなく『再計算費、下位階層読込費、非連続GPU処理費』を同一の限界遅延へ換算して配置判断する方向が自然である。
## 監査メモ
arXiv:2606.02964v1本文を全文確認した。概要の1.90〜2.03倍TTFT、1.62〜1.71倍TPOTは論文全体のまとめであり、本文の70B比較ではvLLM-LRU/Max-score/Pensieve+MSAに対するTTFT最大1.86/1.91/1.86倍、TPOT最大1.62/1.63/1.71倍として区別した。低分散条件では命中率が必ずしも最大でなくてもTTFTを改善する結果を確認し、AsymCacheの主張が命中率最大化ではなく期待遅延最小化であることを明示した。
