# Reducing Peak Memory Usage for Modern Multimodal Large Language Model Pipelines

> 入力をブロック単位に処理し各ブロック直後に固定予算を超えた分を追い出す前処理中の圧縮で、約九割削っても平均正解率の低下を〇・七八ポイントに抑えた条件があり、タイルを増やしてもピークメモリがほぼ一定に保たれたと報告した。

## 概要

画像や動画を読み取って文章と一緒に推論するマルチモーダル大規模言語モデルでは、入力のほとんどを視覚トークンが占める。高解像度の画像は小さな区画へ分割されて数千個のトークンになり、動画は多数のフレームが並ぶ。本文の例では、四千九十六画素級の画像が一万四千画素のパッチ換算で四万二千個を超える視覚トークンを生む。推論では、過去のトークンのキーと値を保存して再計算を避けるキャッシュを使うが、このキャッシュはトークン数に比例して膨らみ、全層と全ヘッド分を保持するため、入力を読み込む前処理の段階でメモリ使用量が最大になる。つまり生成が始まる前の時点で、メモリ不足で落ちるかどうかが決まってしまう。

従来のキャッシュ圧縮は、全文を処理してキャッシュを全部作ってから、不要な分を追い出したりまとめたりする順序だった。この順序では生成中のメモリは減らせても、前処理の最中に生じるピークは一切下がらない。本論文は順序を入れ替え、処理しながら圧縮する方式を提案する。入力を連続したブロックへ分け、一ブロックを符号化するたびにキャッシュへ追加し、固定した予算を超えた分をその場で追い出す。これによりキャッシュの大きさは処理の全程を通じて予算以下に保たれ、ピークメモリは入力の長さではなく予算で決まるようになる。

追い出しの基準は二通り用意される。一つは単一の対話を想定し、質問文を代理の問い合わせとして、視覚トークンへの注意の強さで重要度を測る方式である。もう一つは、後の対話でどんな質問が来るか分からない多ターンを想定し、質問を使わずにキーの表現の平均から遠いものを残して多様性を保つ方式である。代表結果として、八十億級モデルに質問を使う方式を組み合わせ、予算を千二十四トークンまで絞った条件、すなわち約九割の削減でも、四つの課題の平均正解率の低下は全キャッシュ比で〇・七八ポイントにとどまった。また画像のタイル数を増やしてもピークメモリはほぼ一定に保たれ、全キャッシュではメモリ不足になる入力でも実行を続けられた。ただしピークを抑える代償として、逐次処理のために最初のトークンまでの時間は伸びる。

## 問題設定

キャッシュのメモリ量は、層数、ヘッド数、ヘッドの次元、精度、系列長の積に比例する。文章だけのモデルでも長い文脈では問題になるが、マルチモーダルでは視覚トークンが系列長を支配し、しかもその大半は生成前に一括で入ってくるため、使用量の曲線は前処理で急峻に立ち上がって頂点を作る。ここで重要なのは、最終的にキャッシュが何バイト残るかではなく、途中で一度でも確保が必要になる最大量である。従来方式は最終量だけを小さくしていたため、頂点の高さは無圧縮のときと変わらず、大きな画像や長い動画では確保に失敗して推論自体が始まらなかった。

もう一つの論点は、何を捨てるかの粒度である。入力トークンそのものを入り口で捨てる枝刈りは、層やヘッドごとに異なるトークンの役割を区別できない。本文が注目するのは、画像は空間的にまとまった領域から成り、動画はフレーム間の重なりが大きいという視覚入力の構造的な規則性である。似た内容が粗い表現から細かい表現まで重なって存在するため、全部を同じ重みで保持する必要はない。ただし削る単位がこの構造とずれると、意味のあるまとまりの途中で切断が起き、重要な情報まで落ちる。問題設定はしたがって、前処理の途中でも予算を守れる逐次的な圧縮の手続きと、視覚の構造に合った追い出しの基準の二点になる。

## 手法のあらまし

流れは単純である。入力系列を大きさが決まった連続ブロックへ分割し、先頭から順に処理する。各ブロックについてキーと値を計算してキャッシュへ追加し、キャッシュの総量が予算を超えたら、超過分だけを追い出し基準に従って削除して予算まで戻す。全部のブロックを処理し終えた時点で、予算内に収まった圧縮済みキャッシュが残り、その後の生成は通常どおり行われる。ブロックの境界は、画像ならタイル、動画ならフレームのまとまりといった視覚の構造に合わせる。実装上の工夫として、最初の予算分は一括で処理し、ブロック処理が必要な残りだけを逐次にする混成の実行が既定で使われ、逐次化による遅延の増加を抑えている。追い出し基準は、質問文が使える場合は質問への注意に基づく方式、使えない場合はキーの多様性に基づく方式を選ぶ。

## 手法

### 1. ブロック単位の前処理と予算の強制 — 頂点を予算で頭打ちにする

この機構が観測するのは、各ブロックを処理した直後のキャッシュの総量であり、保持する状態は予算の値と現在のキャッシュだけである。動作は、ブロックのキーと値を追加した直後に総量と予算を比べ、超えた分とちょうど同じ数だけを追い出しで削除することである。これを全ブロックで繰り返すため、どの時点でもキャッシュは予算に一ブロック分を加えた範囲を超えない。この機構が減らすボトルネックは、前処理の最中のピークメモリである。従来は入力が長いほど頂点が高くなったが、ここでは頂点が予算で頭打ちになる。追加で消費する資源は時間である。入力を一括で処理できず逐次になるため、最初のトークンまでの時間は伸び、本文の測定でも予算を小さくするほどこの時間は長くなる。失敗時の挙動として、予算が極端に小さいと必要な視覚情報まで追い出され、正解率が大きく落ちる条件も報告されている。特に後述するモデルでは、予算千二十四で画像探索の課題が大きく崩れた。

### 2. 質問を使う追い出し — 質問への注意で残す場所を決める

第二の機構は、単一の対話で質問文が前処理の時点で手元にある場合の基準である。観測するのは、質問文から取り出した代理の問い合わせと、キャッシュ済みの各キーの組であり、保持する状態は予算だけである。動作は、代理の問い合わせと各キーの内積を次元の平方根で割って確率化した注意の強さを重要度とし、重要度の低いトークンから超過分だけを削除することである。いわば、モデル自身が生成前に何を見ようとするかを先読みして、質問と関係の薄い視覚領域を早めに捨てる。この機構が減らすボトルネックは、無関係な視覚トークンが予算を食い潰すことである。評価ではこの方式が最も小さな予算でも正解率を保ち、八十億級モデルでは予算千二十四でも平均の低下が〇・七八ポイントにとどまった。追加で消費する資源は、質問文への依存である。質問が後から変わる多ターンでは、先の質問に合わせて捨てた情報が後の質問で必要になる危険がある。失敗時の挙動もモデル差が大きく、別の七十億級モデルでは同じ予算千二十四で画像探索の正解率が八十三・七から四十五・三へ崩れ、平均の低下が十一・〇六ポイントに達した。ブロックの粒度がそのモデルの視覚の区切りとずれていたことが一因として分析されている。

### 3. 質問を使わない追い出し — 平均から遠いキーを残して多様性を守る

第三の機構は、質問が使えない、あるいは将来の質問が読めない場合の基準である。観測するのはキャッシュ済みのキー全体であり、保持する状態はキーの平均ベクトルである。動作は、平均に似ているキー、つまりありふれた表現のトークンを優先して追い出し、平均から遠い外れ値のキーを残すことである。全ペアの比較を避けて平均との距離だけで判定するため、計算は軽い。この機構が守るのは表現の多様性であり、珍しい視覚的特徴が冗長な背景に埋もれて消えることを防ぐ。この機構が減らすボトルネックは、質問なしでは重要度を測れないという行き詰まりである。追加で消費する資源は、課題との関連の情報を使えないことによる精度であり、評価では質問を使う方式より低下が大きい傾向がある。それでも八十億級モデルでは予算千二十四で平均の低下が四・七〇ポイント、予算二千四十八では二・二三ポイントにとどまり、多ターン向けの現実的な受け皿になっている。失敗時の挙動として、画像探索のように特定の小さな対象を探す課題では、視覚探索の課題で七十四点台まで落ちるなど、質問への関連で残す方式との差が開く。

### 4. 一つの入力が処理される流れ

高解像度画像と質問文が届くと、画像はタイルへ分割されて視覚トークン列になり、質問文と合わせて一つの入力系列を成す。処理は先頭の予算分を一括で符号化する混成の形で始まり、残りはブロックごとに、キーと値の追加、予算超過の確認、基準に従う追い出し、を繰り返す。各時点でキャッシュは予算以下に保たれるため、タイル数が増えてもピークはほぼ動かない。全ブロックが終わると圧縮済みキャッシュが確定し、生成はそのキャッシュの上で通常どおり進む。途中で捨てられたトークンは生成中には戻らないため、追い出しの基準とブロック境界の置き方が、そのまま最終的な正解率を左右する。

| 構成要素 | 入力・観測 | 具体的な動作 | 改善対象 | 主なトレードオフ |
|---|---|---|---|---|
| ブロック単位の前処理 | 各ブロック直後のキャッシュ総量 | 超過分だけをその場で追い出して予算へ戻す | 前処理のピークメモリ | 逐次処理で最初のトークンまでの時間が伸びる |
| 質問を使う追い出し | 質問文の代理の問い合わせと各キー | 注意の強さが低いトークンから削除する | 無関係な視覚領域の保持 | 質問が変わると捨てた情報が要る危険 |
| 質問を使わない追い出し | キャッシュ済みキーの平均 | 平均から遠いキーを残し似たキーを削除する | 質問なしでの重要度の不在 | 関連を使えず低下が大きめになる |

## 評価

### まず見るところ

結論は、前処理の途中で圧縮すれば、最終的なキャッシュの大きさだけでなくピークそのものを予算で抑えられ、しかも条件を選べば約九割の削減でも正解率の低下は小さい、ということである。速度面の主張は速さではなく実行可能性であり、全キャッシュではメモリ不足で落ちる入力が、多少の遅延と引き換えに実行可能になる点が中心である。品質は近似であり無損失ではない。低下の大きさはモデル、追い出し基準、予算、ブロックの粒度で大きく変わり、最も良い条件と最も悪い条件では一桁違う。評価の強さは、画像と動画の両方、モデル規模の違い、予算の段階付け、配分方式や入力削減との対照まで同じ枠組みで測っている点にある。弱さは、ピークメモリの絶対値が表として十分に示されず図中心であることと、ハードウェアが一種類に限られることである。

## 既存研究との差

生成中のキャッシュを対象にした追い出しの研究群は、注意の蓄積や重みのあるトークンの保持によって最終的なキャッシュを小さくしてきたが、圧縮の適用は全文の処理後であり、前処理のピークは対象外だった。マルチモーダル向けの追い出しや層ごとの予算配分の研究も、視覚トークンの冗長性を使う点では近いが、やはり処理後の圧縮が前提である。入力トークンの枝刈りは入り口で数を減らすものの、層やヘッドごとの役割の違いを無視する。本論文は、既存の追い出し基準そのものは先行方式から借りながら、適用の時点を前処理の途中へ前倒しし、ブロック単位の逐次処理と固定予算の強制でピークを抑える点に新規性がある。あわせて、配分の動的化が前処理では逆効果になること、粒度と視覚構造の一致が効くことを対照実験で示した点も、先行研究への追加である。

## 限界・実装状況

- 逐次処理のためメモリと遅延の交換が避けられず、予算を絞るほど最初のトークンまでの時間は伸びる。混成の実行で緩和はされるが解消はしない。
- 効果はブロック境界と視覚構造の一致に依存し、ずれた粒度では正解率が大きく落ちるモデルがある。構造に合う粒度の自動決定は示されていない。
- 質問を使う方式は質問の変化に弱く、質問を使わない方式は関連の情報を使えないため低下が大きめになる。
- 学習を伴わない推論時の最適化であり、前処理中の圧縮を前提に学習したモデルなら頑健性が上がる可能性が今後の方向として挙げられている。
- 公式のコード公開先は本文中に示されていない。実装は既存の追い出し方式をブロック処理へ組み込む形である。

## 一般的な実装上の含意

メモリの最適化では、最終的な使用量だけでなく、処理の途中で現れる頂点を目的にする必要がある。特に前処理が支配的な長い入力では、圧縮を後段に置く設計は頂点を一切下げられない。また圧縮の粒度は、データの意味的なまとまりと一致させて初めて安全になる。粒度の不一致は、予算の大きさ以上に品質を壊し得る。さらに、途中の統計が未完成な段階では、凝った動的配分より単純な一律配分の方が堅い場合がある点も、段階的な処理へ適応制御を入れる際の一般的な注意になる。
