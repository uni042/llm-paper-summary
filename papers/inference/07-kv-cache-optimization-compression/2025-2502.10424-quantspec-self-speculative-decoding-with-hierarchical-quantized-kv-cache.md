# QuantSpec: Self-Speculative Decoding with Hierarchical Quantized KV Cache

## 概要

QuantSpecは、長い文脈を持つ大規模言語モデルの復号で、鍵値キャッシュ（KVキャッシュ）の読出しがGPU帯域と容量を圧迫する問題を、階層量子化キャッシュを共有する自己投機的復号によって改善する。別の小型ドラフトモデルを追加するのではなく、対象モデルと同じ構造を4ビット重み・4ビットKVキャッシュで走らせて候補トークンを作り、元の対象モデルがまとめて検証する。対象側は8ビットKV表現を使い、ドラフト側と同じキャッシュの上位4ビットを共有する。

独自性は、ドラフトと対象のキャッシュを別々に確保しないことと、投機の受理・棄却に対応した二重の高精度バッファを設けることにある。対象モデルの8ビットKVを上位4ビットと下位4ビットへ分けて保存し、ドラフトでは上位だけを、検証では両方を読み出す。さらに最近のKVを16ビットで保持して、棄却したトークンの巻戻しで量子化済みキャッシュを繰り返し書き換える費用を避ける。

Llama-2-7B-32K-InstructとLWM-Text-Chat-128kを用いた実測では、長さ4千〜12.8万の文脈で、通常の自己回帰生成に対して最大2.49倍の端から端高速化を報告する。12.8万トークンの条件では、疎KVを用いる比較方式がGPUメモリ不足になった一方、QuantSpecはGPUメモリ61.22GB、受理率94.31%で実行できた。ただしこの条件はGPU2枚であり、単一GPUに12.8万トークンを載せた結果ではない。専用注意カーネルの最大2.88倍という数字も、生成処理全体の速度ではなくカーネル単体の比較である。

## 問題設定と律速の変化

一般的な投機的復号では、軽いドラフトモデルが候補を複数生成し、重い対象モデルがそれらを並列に検証する。候補が対象分布に近いほど一回の検証で多くのトークンを確定できる。しかし小型モデルは長文脈の理解が弱い場合があり、対象モデルとの予測差によって受理率が落ちる。またドラフトと対象で別々のKVキャッシュを持つと、文脈長に比例するメモリ費用が二重化する。

短い文脈の復号では、各トークンで読むモデル重みの容量が支配的になりやすい。文脈が長くなると、注意演算が過去全体の鍵・値を読み出すため、重みだけを低ビット化してもKVの帯域費用が残る。論文は算術強度、すなわちメモリから読み出す1バイト当たりの浮動小数点演算数を用い、A6000とLlama-2-7Bの屋根線モデルで律速を分析する。前処理段階では多数トークンをまとめた大きな行列積で演算器を利用しやすいが、1トークンずつ復号する段階では低算術強度になりやすい。

文脈長が隠れ次元より十分短い場合、復号の線形層は重み読出しが大きな割合を占める。一方、文脈長が長い場合は注意層のKV読出しが支配的になる。バッチを増やすと線形層では重み再利用が増えるが、長文脈の注意は各系列で別々のKVを読むため同じ利得を得にくい。QuantSpecが重みとKVの双方を4ビット化する理由は、短文脈と長文脈で律速が変わるからである。

## 手法

### 1. 同一構造を用いる自己投機的復号

ドラフトは対象モデルと同じ層構造を使い、重みを4ビット量子化して高速に候補を生成する。別の小型モデルを学習する方式と異なり、長文脈での表現能力や注意構造の差が小さく、候補の受理率を維持しやすい。対象モデルは元の16ビット重みを使い、ドラフトの候補をまとめて検証する。受理された先頭部分を確定し、最初に棄却された位置以降は対象分布に従うため、投機的復号の確率的整合性を保つ設計である。

ただし同一構造であることは、ドラフトと対象の出力分布が完全に同じことを意味しない。4ビット重みとKVの近似誤差は残り、受理率はモデル・入力・文脈長で変わる。受理率が下がれば候補生成と検証の追加費用を回収しにくくなるため、単純にドラフト1ステップを最速にするだけでなく、対象モデルとの整合性を重視する。

### 2. 上位4ビットと残差4ビットの階層KV表現

対象側のKVを8ビットで扱っても品質がほぼ維持されることを確認し、その8ビット量子化値を上位4ビットと下位4ビットへ分けて保存する。まずKVを非対称の丸め量子化で上位4ビットへ変換し、元値との差である量子化誤差を対称の4ビット量子化で保存する。上位は0〜15、下位残差は−8〜7の値域を使う。対象モデルの8ビット値は、上位4ビットを16倍した値に下位残差を足すことで再構成できる。

ドラフトの注意カーネルは上位4ビットだけをGPUメモリから読み、低精度のKVとして復号する。対象の検証では上位と下位を合わせて8ビットKVとして扱う。二つの経路が上位4ビットの実体を共有するため、ドラフト専用の4ビットKVコピーを別に保存する必要がない。長文脈ではキャッシュ容量とメモリ転送量の両方を抑えられる。

量子化単位は鍵と値で異なる。鍵はチャネル方向、値はトークン方向の量子化が誤差を小さくするという既存知見に従い、グループ単位でスケールとゼロ点を管理する。鍵・値の量子化誤差は注意スコアと重み付き和へ異なる形で影響するため、単に両方へ同じ量子化軸を適用しないことが重要である。

### 3. 最近のKVを保持する二重高精度バッファ

投機的復号では候補が棄却されると、棄却トークンのKVを捨て、確定トークンから生成し直す。最近のKVまで逐次量子化していると、巻戻しのたびに量子化済みグループを再構築する必要がある。QuantSpecはこの問題に対し、量子化グループ長Gの2倍の高精度バッファを用意する。二つの区画をCF1とCF2と呼び、各区画の長さはGである。

前処理では古いKVをG個ずつ量子化し、最近のG〜2Gトークンを高精度で残す。復号では新しい候補トークンのKVをCF2へ格納する。バッファが2Gまで埋まったら対象モデルの検証を待ち、棄却トークンに対応するCF2の領域を破棄する。その後、確定済みのCF1をまとめて量子化キャッシュへ移し、CF2をCF1へ移動して次の生成に備える。

これにより直近GトークンのKVは常に高精度で保持され、受理率に有利である。量子化・移動の頻度も毎トークンではなくおおむねGステップごとになり、巻戻しの対象は高精度バッファ内で完結する。代償として2G分の高精度領域が追加で必要だが、長い文脈全体を高精度で二重保持するより小さい。

### 4. 量子化KV向けの注意カーネル

階層KVを毎回一般的な16ビットテンソルへ展開してから注意演算を行うと、帯域削減の利点が失われる。QuantSpecは専用CUDA注意カーネルで上位4ビット、または上位・下位の両方を読み、演算中に復元して注意を計算する。ドラフトは上位のみ、対象は両方という読み分けが可能で、量子化済みキャッシュを別の形式へコピーする費用を抑える。

量子化キャッシュの読み出し量は文脈長に比例するため、文脈が長いほど低ビット表現の利得が大きくなる。ただし注意カーネル単体が高速でも、ドラフト生成、対象検証、受理・棄却、バッファ管理の全費用を含む生成処理が同じ倍率で速くなるとは限らない。

## 評価条件

| 項目 | 実験設定 | 評価指標 |
|---|---|---|
| 計算環境 | NVIDIA RTX A6000×8を備えたノード | 各条件ではGPU1枚または2枚を使用 |
| 対象モデル | Llama-2-7B-32K-Instruct、LWM-Text-Chat-128k | 長文脈での受理率、GPUピークメモリ、通常生成比高速化 |
| データ | PG-19、∞BENCH Sum、Multi-LexSum | 文脈4k〜128k、各条件10例の平均 |
| 比較方式 | 通常自己回帰生成、StreamingLLM型、SnapKV型の疎KV自己投機 | 疎KVのドラフト予算を文脈長の1/4に統一 |
| 量子化 | グループ長128、最近の高精度残差長256 | 重み4ビット、ドラフトKV4ビット、対象KV8ビット |

速度は通常の対象モデルの自己回帰生成を基準とする。比較する疎KV方式には同じ1/4文脈長のドラフト予算を与えているが、保持する情報の性質は異なる。疎KVはトークンを落とし、QuantSpecは全トークンの情報を低ビット化して保持する。文脈の重要な箇所が散らばる要約タスクでは、この違いが受理率へ影響し得る。

## 主要結果

### 1. 8ビット対象KVの品質保持

| KV精度 | WikiText-2の困惑度 | C4の困惑度 |
|---|---:|---:|
| 16ビット（基準） | 6.4595 | 7.2617 |
| 8ビット（対象経路） | 6.4696 | 7.2620 |

Llama-2-7Bでの結果であり、8ビットKVは16ビットと近い困惑度を示す。WikiText-2では差0.0101、C4では差0.0003である。これは8ビット化がすべてのモデル・タスクで無損失である証明ではなく、採用した量子化方式と指定データでの品質確認である。ドラフトの4ビットKVには別途近似誤差があり、受理率の評価が必要になる。

### 2. 長文脈での受理率・容量・生成速度

| モデル・データ・文脈 | 方式 | 受理率 | GPUピークメモリ | 通常生成比 |
|---|---|---:|---:|---:|
| Llama-2 / PG-19 / 4k | QuantSpec | 92.46% | 16.26GB | 1.35倍 |
| Llama-2 / PG-19 / 8k | QuantSpec | 89.88% | 17.66GB | 1.44倍 |
| Llama-2 / Multi-LexSum / 8k | QuantSpec | 91.23% | 17.66GB | 1.61倍 |
| Llama-2 / Multi-LexSum / 32k | QuantSpec | 91.16% | 25.84GB | 2.08倍 |
| LWM / ∞BENCH Sum / 16k | QuantSpec | 91.64% | 20.36GB | 1.78倍 |
| LWM / ∞BENCH Sum / 32k | QuantSpec | 90.99% | 25.86GB | 1.99倍 |
| LWM / Multi-LexSum / 64k | QuantSpec | 92.18% | 38.18GB | 2.23倍 |
| LWM / Multi-LexSum / 128k | QuantSpec | 94.31% | 61.22GB | 2.49倍 |

表の4k条件ではSnapKVの受理率93.59%がQuantSpecの92.46%より高く、QuantSpecが全条件で最大受理率とは限らない。一方、32kのMulti-LexSumではStreamingLLMが受理率91.19%、メモリ32.61GB、速度1.84倍、SnapKVが72.54%、33.96GB、1.63倍であり、QuantSpecは91.16%、25.84GB、2.08倍を達成する。受理率を保ちながら帯域・容量を削ることが全体速度に効く例である。

128kの条件では疎KVの二方式がメモリ不足で完走できず、QuantSpecだけがGPU2枚で実行できた。したがって「疎KVより2.49倍速い」という直接比較ではなく、通常の自己回帰生成比で2.49倍、疎KV比較方式は当該条件で実行不能という結果である。論文要旨の「受理率90%以上」は概括値であり、PG-19の8kでは89.88%と90%をわずかに下回る。

### 3. 量子化注意カーネル単体の性能

| 文脈長 | 16ビットFlashAttention | 8ビットQuantSpec | 4ビットQuantSpec |
|---|---:|---:|---:|
| 64k | 3.07ms | 1.08ms | 0.54ms |
| 256k | 6.16ms | 4.06ms | 2.15ms |

論文表4では、4ビットカーネルの速度向上を64kで約2.88倍、256kで約2.86倍と記載する。ただし64kの数値3.07/0.54を単純に割ると約5.69倍であり、表の倍率表記と整合しない。8ビットの64kも3.07/1.08は約2.84倍で、記載の1.44倍と異なる。256kでは6.16/4.06が約1.52倍、6.16/2.15が約2.87倍で表記と整合する。原表の数値と倍率の不整合を隠さず、実際の速度比較では同じ列の時間を確認する必要がある。

### 4. 重みとKVの量子化の寄与

論文の要素除去実験では、短文脈では重み4ビット化が速度向上の主因となり、長文脈ではKV4ビット化が支配的になる。中間長では双方が寄与する。これは算術強度の分析と整合する。長文脈の自己投機的復号で別モデルを小さくするだけでは不十分であり、ドラフトが読むキャッシュの帯域を減らす必要があることを示す。

## 既存研究との差

従来の投機的復号は、対象より小さい独立モデルで候補を生成する。QuantSpecは同じ構造の重み・KVを低精度で再利用するため、モデル間の長文脈能力差を抑える。TriForceやMagicDecなどの疎KV型自己投機では、ドラフトが見る履歴の一部を省く。QuantSpecは履歴トークン自体は保持し、数値精度を落とすことで容量を減らす。文書要約のように遠い位置の情報も重要な場合に受理率を維持しやすい。

また対象用の8ビットKVを上位・下位の4ビットへ分け、ドラフトは上位だけを読むという階層共有は、独立した4ビットドラフトKVを別に持つ方式より容量効率が高い。二重高精度バッファは投機的復号の棄却・巻戻しと量子化グループの更新を両立させる実装上の工夫であり、単なるKV量子化だけでは得られない利点である。

## 限界と注意点

評価は主に7B級の長文脈モデル、A6000環境、最大90出力トークンの生成を対象とする。より大きなモデル、別のGPU、長い生成、複数同時要求、CPUへのKVオフロードでは同じ倍率になるとは限らない。投機長γは条件ごとに探索しており、固定設定をあらゆる入力へ適用した結果ではない。疎KV方式のドラフト予算は揃えているが、内部実装と情報保持の仕方は異なる。

低ビットKVでも品質が完全に無損失であるわけではない。対象側の8ビット化で困惑度の差は小さいがゼロではなく、投機的復号の分布整合性を論じる際には「8ビット対象モデルの出力分布を保つ」のか「元の16ビットモデルと完全一致する」のかを区別する必要がある。対象が8ビットKVを使うなら、元の16ビットKVと数値的に厳密同一の分布を保証するものではない。

さらに原論文の注意カーネル表には、64kの実測ミリ秒値と括弧内の倍率が整合しない箇所がある。速度の最大値を引用するときは、カーネル単体と端から端までの生成を混同せず、原表の絶対時間と比較条件を併記すべきである。長文脈ほどKV量子化が重要という知見は広く参考になるが、個別の実装では量子化誤差、バッファ管理、受理率、GPU帯域の全体最適化が必要となる。
