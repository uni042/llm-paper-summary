# SKVQ: Sliding-window Key and Value Cache Quantization for Large Language Models

> KVチャネルを量子化しやすい順へ並べ替え、外れ値をクリップし、直近KVだけ高精度で残すことで鍵2ビット・値1.5ビット級まで圧縮し、長文脈の容量・帯域律速を緩和する。

## 概要

自己回帰型LLMでは、一度計算した過去トークンの鍵状態（Key state）と値状態（Value state）をKVキャッシュへ保持し、次のトークン生成で再利用する。これにより過去のTransformer計算を毎回やり直さずに済む一方、KVキャッシュ容量は層数、注意ヘッド数、隠れ次元、バッチ数、文脈長に比例して増える。長文脈ではモデル重みよりKVキャッシュが大きくなることもあり、GPUメモリ容量だけでなく、毎トークン読み出すメモリ帯域も復号の律速になる。

単純な低ビット量子化では、KVテンソル内のチャネルごとに値域が大きく異なることが問題になる。複数チャネルを一つの量子化群として同じスケールで表すと、一つの大きな外れ値チャネルが群全体のレンジを広げ、通常値へ割り当てられる整数段階が粗くなる。2ビット前後まで下げるとこの影響が急激に強まり、容量を減らせても注意出力の誤差が大きくなる。

SKVQはこの問題を三つに分ける。第一に、統計的に似たチャネル同士が同じ量子化群へ入るようチャネルを並べ替える。第二に、各群の極端な外れ値を一定範囲で飽和させるクリップ付き動的量子化（clipped dynamic quantization）を用い、少数の外れ値より多数の通常値へ分解能を割り当てる。第三に、最近のトークンほど強く参照されやすい注意の局所性（attention locality）を利用し、直近の滑動窓（sliding window）だけは高精度のまま保持する。

論文はこの組合せにより、鍵を2ビット、値を1.5ビットまで下げても長文脈精度を保ちやすくなることを示す。屋根線モデル（roofline model）によるシステム分析では、LLaMA-7BをA100 80GB上で100万トークン級まで扱える容量を見積もり、バッチ128・系列長200kではFP16に対し理論上約7倍の復号高速化余地を報告する。ただし公開実装は論文の主要精度結果が擬似量子化（fake quantization）で得られたこと、公開カーネルが完全に最適化された実装ではないことを明記しており、理論帯域削減と現行コードの実測速度は区別して読む必要がある。

## 背景: KV量子化で何が難しいか

重み量子化では、重みは推論前に固定されているため、オフラインでチャネルごとの統計を調べ、量子化しやすい配置へ変換できる。KVキャッシュは入力トークンから動的に生成されるため、値域が要求や位置によって変わり、推論中に繰り返し量子化・逆量子化する必要がある。したがって精度だけでなく、量子化パラメータの保存量と実行時処理量も重要になる。

一般的な群量子化（group-wise quantization）では、例えば複数の隠れ次元チャネルを一群として最小値・最大値からスケールを決める。もし一群の中に値域が非常に広いチャネルと狭いチャネルが混ざると、広いチャネルに合わせたスケールを狭いチャネルも共有し、狭い側の値が少数の量子化段階へ潰れる。このため「何ビットにするか」だけでなく、「どのチャネル同士でスケールを共有するか」が低ビット域では支配的になる。

また、古いKVと直近KVを同じ精度で扱う必要もない。生成中の注意は直近トークンへ強く向く局面が多く、直近部分の量子化誤差は次トークンへ直接影響しやすい。一方、長い履歴全体をFP16で残すと容量削減の意味が薄れる。SKVQは「大部分の古いKVを極低ビット化し、少量の直近KVだけ高精度で守る」ことでこの交換条件を利用する。

## 問題設定

目標は、長文脈でKVキャッシュのメモリ使用量と読出し量を大幅に減らしながら、パープレキシティ（perplexity）や長文脈検索・理解性能を可能な限り維持することである。特に2ビット級では、単純な最近傍丸め（round-to-nearest）や通常の群量子化だけでは外れ値の影響が大きく、精度が急落する。

この問題では容量と帯域を分けて考える必要がある。低ビット化すれば保存バイト数は直接減るが、実際の高速化には、逆量子化と注意計算を効率良く融合し、削減したバイト数がGPUのメモリ交通削減へ変換されなければならない。したがってSKVQのアルゴリズム上の精度改善と、論文の屋根線モデルによる性能上限、公開CUDA実装の現状は別々に評価する必要がある。

## 手法

### 1. チャネル再配置で量子化群を均質化する

SKVQは、KVキャッシュの各チャネルが持つ値域や外れ値の強さを校正データから調べ、似た統計のチャネルが同じ量子化群へ入るよう順序を変更する。これにより、ある一つの広い値域を持つチャネルが、値域の狭い多数のチャネルの量子化スケールまで引き延ばす状況を減らす。

重要なのは、この並べ替えがモデルの意味を変える任意のシャッフルではないことである。注意計算は対応する次元を同じ置換で扱えば等価性を保てるため、クエリ・キーや関連する射影重み側へ対応する置換を吸収できる。実行時に毎トークン複雑なクラスタリングを行うのではなく、校正で得た置換をモデルへ組み込んで利用する。

この機構が効くのは、量子化誤差の一因が「群内チャネルの値域不一致」にあるからである。チャネルを似た分布ごとにまとめれば、同じビット数・同じ群サイズでも量子化刻みを細かくできる。

### 2. クリップ付き動的量子化で外れ値にレンジを独占させない

チャネル再配置後も、各群にはまれな極端値が残る。通常の最小最大量子化では、その極端値まで表現範囲へ入れるため、大多数の通常値が粗い格子へ押し込まれる。SKVQは量子化範囲を縮めるクリッピング係数を使い、一部の外れ値を飽和させる代わりに通常値の分解能を高める。

クリッピングを強くし過ぎれば外れ値自身の誤差が大きくなるため、校正時に再構成誤差を見ながら範囲を選ぶ。論文の発想は「全値を完全に範囲内へ収める」ことではなく、低ビットという限られた表現段階を、注意計算全体の誤差が小さくなる領域へ配分することである。

この処理はチャネル再配置と補完関係にある。再配置が群内の統計差を小さくし、クリッピングが残った外れ値の影響を抑えるため、どちらか一方より2ビット級の量子化を安定させやすい。

### 3. 直近トークンを高精度で残す滑動窓

SKVQは全KVを即座に低ビット化せず、直近の一定数トークンを高精度の滑動窓に置く。新しいトークンが生成されると窓も前進し、窓から外れた古いKVを量子化して長期保存側へ移す。

この設計は、最近のトークンほど高い注意を受けやすいという局所性を利用する。高感度な直近KVをFP16等で保護すれば、古い履歴側をより強く圧縮しても品質を維持しやすい。論文の消融では窓を広げるほど概ね精度が改善し、代表的には128トークン程度が精度と高精度部分の容量とのバランスになる。

滑動窓には別の実装上の利点もある。生成された直後のKVをいったん高精度で使い、古くなった時点でまとめて量子化できるため、毎回すべてのキャッシュを再量子化する必要がない。

### 4. 鍵と値を極低ビットへ落とす

SKVQは鍵2ビット・値1.5ビットという非常に低い設定まで評価する。ここで1.5ビットは一般的な単一整数型を意味するというより、論文実装のパッキングとビット配分を含む実効的な保存形式として理解する必要がある。

鍵側の誤差は注意スコアそのものを変え、値側の誤差は重み付き和の内容を変えるため、両者の影響は同一ではない。SKVQはチャネル統計、クリッピング、滑動窓を組み合わせることで、単純に同じ量子化器をKとVへ当てるより低いビット幅へ踏み込む。

品質面では、Needle-in-a-HaystackとLongBenchで低ビット化後の長距離検索・理解能力を確認している。これはパープレキシティだけでは見えにくい「遠い過去の情報を取り出せるか」を評価するためで、滑動窓が直近精度だけを守って古い情報を壊していないかを確認する役割を持つ。

## 既存研究との差

KIVIも鍵・値の統計差を考慮してKVキャッシュを低ビット化し、最近のトークンを高精度で残す。SKVQの差は、量子化前にチャネル順序そのものを変えて群内分布を揃えること、さらに群ごとのクリッピングで外れ値に量子化レンジを独占させないことにある。

KV追い出し（KV eviction）は古いエントリそのものを削除するため容量削減率を高くできる一方、消した情報は復元できない。SKVQは基本的にエントリを残したままビット幅を下げるため、非常に長い履歴全体を保持したい用途に向く。ただし量子化誤差という別の品質リスクを持つ。

重み量子化と違い、KVは要求ごとに動的生成される。したがってSKVQはオフライン変換だけで完結せず、滑動窓から古いKVが出るたびに量子化し、注意時に逆量子化する実行経路まで含めて考える必要がある。

## 限界・実装状況

論文の主要な品質評価は擬似量子化を使う。公式コードにはCUDA拡張があるものの、READMEは公開されている逆量子化・行列ベクトル積（GEMV）カーネルが単純で非効率であると明記している。したがって論文の屋根線モデルが示す最大速度を、現在の公開コードをそのまま動かした速度と解釈してはいけない。

クリッピング係数やチャネル統計には校正が必要である。公式READMEでは群ごとのクリッピングを評価スクリプト内で扱い、過適合を避けるため統一クリッピングも利用すると説明している。モデルや入力分布が変われば適切な係数が変化し得る。

滑動窓を大きくすれば品質は上がりやすいが、高精度部分が増えて圧縮率と帯域削減が弱くなる。逆に窓を小さくし過ぎると直近の高感度KVまで極低ビット化される。この交換条件は文脈長、注意パターン、モデルごとに再確認が必要である。
