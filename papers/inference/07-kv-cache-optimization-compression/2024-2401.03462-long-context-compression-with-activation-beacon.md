# Long Context Compression with Activation Beacon

## 概要

長文を大規模言語モデルへ入力すると、過去トークンの鍵・値（KV）キャッシュが文脈長に比例して増え、自己注意の計算も重くなる。文章を短い要約や少数の仮想トークンへ変換する方法は、細部の情報が失われたり、次の質問に答えるため再符号化を要したりする。Activation Beaconは、文章そのものを短く書き換えるのではなく、Transformerの各層に生じる鍵・値活性を、追加したビーコントークンの活性へ直接圧縮する。

長文を固定長のチャンクへ分割し、細かい単位ごとにビーコンを一つ挿入する。各チャンクを処理したら生トークンのKVを破棄し、ビーコンのKVだけを蓄積して次チャンクから参照する。圧縮率を8倍にした128K文脈の実験では、非圧縮で同じデータにより微調整した比較モデルに対し、推論時間を約半分、KVキャッシュを約8分の1にした。短文能力も概ね維持されるが、ビーコン用の追加投影行列を学習する必要があり、圧縮率を高めるほど情報損失の危険は増す。

## 問題設定と圧縮対象

通常の自己回帰推論では、過去の全トークンに対応する鍵・値活性を各層に保持し、次のトークンから参照する。文脈が長いほどキャッシュのメモリ容量が増え、入力全体の注意計算にも費用がかかる。文書を単に削除すれば重要な根拠が失われる。別の圧縮器が少数の仮想トークンを生成する方式は、その仮想トークンを後続の言語モデルへ再入力する費用を伴う場合がある。質問に合わせて残すトークンを選ぶ方式では、別の質問が来るたびに重要度の再計算が必要になり得る。

本研究の圧縮対象は、各層の注意機構がすでに計算した鍵・値の活性である。生の過去トークン列を `X`、保持するビーコン活性列を `Ψ` とすると、次トークン予測は過去全文でなく `Ψ` と現在チャンクへ条件付けられる。`|Ψ|<|X|` ならキャッシュ容量と過去への注意計算を減らせる。文脈を一度に要約するのではなく、細かい単位で順次圧縮することで、情報を少数のトークンへ一度に押し込む難しさを避ける。

## 手法

### チャンクと細粒度単位への分割

入力長をn、チャンク長をw、圧縮率をαとする。入力をw個程度の生トークンからなるチャンクへ区切り、各チャンクをα個のトークンからなる細粒度単位へ分ける。各単位の末尾へ特殊なビーコントークンを一つ挿入する。例えばw=1024、α=8なら、一つのチャンクから128個のビーコンが得られる。ビーコンは全て共通の埋め込みを用いるが、置かれる位置が異なるため注意できる範囲が異なる。チャンク末尾へ全ビーコンをまとめて置く方法より、細かい単位の末尾へ分散配置した方が情報保持に優れることを構成要素除去実験で確認している。

モデルはチャンクを順番に符号化し、生トークンとビーコンの両方を自己注意へ通す。ビーコンの鍵・値は、その時点までの局所トークンの情報を取り込む。処理が終わると生トークンの鍵・値を捨て、ビーコンの鍵・値だけを各層の累積キャッシュへ追加する。次チャンクでは、過去チャンクの生トークンの代わりに累積ビーコンを参照する。新しい入力が追加される場合も、既存の圧縮活性を再符号化せず、その後ろへ新たなビーコンを追加できる。

### ビーコン専用の問い合わせ・鍵・値投影

元モデルの通常トークン用の問い合わせ・鍵・値射影は維持し、ビーコン用に別の射影行列を用意する。注意機構の入力を通常トークンとビーコンへ分けてそれぞれ射影し、元の並び順へ戻して自己注意を計算する。圧縮済みの過去ビーコンは通常の過去キャッシュの代わりに参照される。ビーコンの鍵・値はチャンク処理後に残るが、生トークンの鍵・値は残さない。

この構成では元の言語モデルのパラメータを凍結し、ビーコンの埋め込みと専用射影行列だけを学習する。したがって既存モデルの短文能力を直接上書きしにくい。一方、元モデルを完全に無変更で使う学習不要方式ではない。推論時にはビーコンの計算が追加されるため、注意計算の削減とビーコン処理の増分が性能を決める。長文ほど過去への注意が大きくなり、圧縮の利得が増える。

### 圧縮条件付き自己回帰学習

学習目標は、圧縮された過去ビーコンと現在の生トークンから次の生トークンを予測することである。ビーコン自体には正解ラベルを与えず、通常の生トークンの予測損失を使う。最初のチャンク以降の各トークンを学習信号に利用できるため、圧縮表現の品質を多くの位置で検証できる。過去チャンクの中間活性を参照するため、従来の再帰メモリ方式のようにチャンク間で勾配を打ち切る必要もない。

事前学習ではRedPajama由来の約10億トークンを使い、続いてLongAlpaca、BookSum、GPT-3.5で作成したデータなどで微調整する。学習サンプルの最大長は20Kであり、128Kの入力を直接使って学習したわけではない。圧縮率は学習中にチャンクごとに2・4・8・16・32から無作為に選ぶ。これにより一つの固定圧縮率だけでなく、推論時の要求に応じて複数の圧縮率を選べるようにする。

### 圧縮率と情報量の交換条件

圧縮率αを大きくすると保持するビーコン数はおおむね1/αになり、KVキャッシュも縮小する。しかし各ビーコンへ集約する情報が増え、細部を失う危険が高まる。著者らは総合的に8倍を推奨する。圧縮は質問内容を事前に知らない状態で行うため、同じ圧縮活性を後から異なる質問に使えるが、どの質問に対しても全ての情報を損失なく保持できると保証するものではない。

## 評価条件と主要結果

| 項目 | 設定 | 注意点 |
|---|---|---|
| 基盤モデル | Llama-2-7B chat、Qwen-2-7B instruct | 元のモデルの重みは凍結 |
| チャンク長 | Llama-2は1024、Qwen-2は2048 | モデルごとに設定が異なる |
| 学習 | A800 80GB×8、事前学習約10億トークン、微調整、最大20K長 | 128Kの評価は学習長を超える一般化 |
| 評価 | LongBench、複数針検索、短文MMLU・ARC-C・BoolQ・GSM8K | 正答率と遅延は別指標 |
| 比較 | 非圧縮、同じデータで微調整した非圧縮、AutoCompressor、ICAE、LongLLMLingua、SnapKV | 比較方式により対応する最大文脈長が異なる |

| 条件 | 指標 | 原著の値 | 解釈 |
|---|---|---|---|
| Qwen-2-7B、128K、8倍圧縮 | 圧縮・生成を含む推論時間 | 非圧縮微調整モデル比約2倍高速 | 圧縮後の注意計算を減らした効果 |
| 同条件 | KVキャッシュ容量 | 非圧縮の約8分の1 | 保持ビーコン数による削減 |
| Qwen-2、128K、複数針検索、3ターン | 遅延 | 非圧縮6.153秒、提案法2.981秒 | 1回の問い合わせだけでなく複数ターンの条件 |
| 同条件 | 針検索の評点（10点満点） | 非圧縮9.20、提案法9.10 | 高速化に対し小さな評点差 |
| 同条件 | LongLLMLingua、SnapKVの遅延 | 27.751秒、10.659秒 | 質問依存方式の再圧縮が不利 |
| Llama-2、32K、3ターン | 提案法と非圧縮の遅延 | 1.638秒、1.726秒 | 短めの文脈では差が小さい |
| Qwen-2、LongBenchの単一文書課題、32K | 非圧縮微調整41.0、提案法40.5 | 圧縮品質がほぼ維持される例 |
| Llama-2、LongBenchの単一文書課題、32K | 非圧縮微調整34.8、提案法34.9 | 非圧縮と同程度の品質 |
| Llama-2、短文MMLU | 元47.5、提案法46.6 | 短文能力に0.9ポイントの低下 |
| Qwen-2、短文GSM8K | 元76.0、提案法76.2 | この指標では低下なし |

長文での2倍高速化は、128K・8倍圧縮という特定条件での推論時間の比較であり、どの文脈長でも2倍になるという意味ではない。3ターンの複数針検索では、質問非依存で圧縮済みの活性を再利用できるため、質問が変わるたび再圧縮する方式に対して大きな遅延差が生じる。原著はAutoCompressor比1.8倍、LongLLMLingua比9.3倍、SnapKV比3.6倍の高速化を報告するが、これらは同じモデル・長さ・ターン数での比較であり、非圧縮モデル比2倍とは別の数値である。

構成要素除去では、Qwen-2-7BのLongBench単一文書課題（32K、4倍圧縮）を使い、標準設定40.5に対して細粒度圧縮を外すと35.2、チャンク単位の無作為圧縮率を外すと37.7、事前学習を外すと34.9、微調整を外すと35.5となった。したがって単に特殊トークンを挿入するだけでなく、細粒度の注意範囲と可変圧縮率を学ぶ過程が品質へ寄与している。

短文能力については、Llama-2のMMLUが47.5から46.6、Qwen-2のMMLUが70.1から69.1へ低下する一方、BoolQやGSM8Kではほぼ同等の値もある。全く性能が落ちないという意味ではなく、長文圧縮を学習した後でも元の短文能力の多くが維持される、という範囲の主張である。

## 既存方式との差

AutoCompressorやICAEはチャンクの情報を少数の仮想トークンへ集約し、後続の処理で再符号化する場合がある。Activation Beaconは各層の鍵・値活性そのものを保持するため、既存の圧縮結果を再符号化せず次チャンクや次の質問に渡せる。LongLLMLinguaやSnapKVは入力質問を使って重要なトークンを選ぶため、質問が変わった場合に圧縮処理を繰り返す必要が生じ得る。提案法は質問に依存しない漸進圧縮によって、複数ターンの再利用と文脈窓を超える入力の処理を両立させる。

## 限界

圧縮率を高めればビーコンに多くの情報を集約する必要があり、細部を失う可能性が増す。著者が推奨する8倍は全タスクで厳密な無損失を保証する値ではない。128Kでの良好な結果は、最大20Kの学習から長文へ一般化した特定の2モデルと評価課題で確認されたものであり、任意のモデル・専門領域・極端な文脈長へそのまま適用できる保証はない。

ビーコン専用の問い合わせ・鍵・値投影と埋め込みを追加学習する必要があり、元モデルの推論だけで即時に導入できる学習不要方式ではない。ビーコンの計算自体も追加されるため、短い入力では圧縮の利益が小さい場合がある。質問非依存の圧縮は再利用に有利だが、後から来る質問にとって重要な稀な情報を必ず保持できるわけではない。短文MMLUには約1ポイントの低下があり、能力を完全に維持したという主張も避けるべきである。
