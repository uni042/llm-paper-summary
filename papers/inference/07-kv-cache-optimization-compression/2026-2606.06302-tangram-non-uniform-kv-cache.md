# Tangram: Unlocking Non-Uniform KV Cache Compression for Efficient Multi-turn LLM Serving

> 非一様KVキャッシュ圧縮のhead別保持量を少数サンプルで事前較正し、固定予算・head-group単位のragged paging・事前負荷分散へ落とし込むvLLMベースのserving system。動的な非一様圧縮の精度をほぼ保ちながらfragmentation、page reclaim、decode workload imbalanceを解消し、実機で最大2.6倍のthroughputを報告する。
## 書誌情報
- **著者**: Hyungmin Kim, Minsoo Kim, Hongseok Kim, Jungwook Choi
- **公開**: arXiv v2, 2026-06-15 (v1: 2026-06-04)
- **種別**: preprint
- **対象**: KV cache compression、LLM serving、non-uniform KV cache、PagedAttention、multi-turn serving、memory management、load balancing
- **実装**: Official code is public at https://github.com/aiha-lab/TANGRAM; vLLM-based and Apache-2.0.
## 問題設定
複数ターン会話では過去履歴を再計算しないためKV cacheを保持するが、会話ターン数と同時request数に比例して容量が増える。非一様KV圧縮は長距離情報を保持すべきattention headへ多く、局所的なheadへ少なくbudgetを配るため一様圧縮より品質を保ちやすい。しかし既存serving stackは全headのKV長が同じことを前提にする。PagedAttentionのmonolithic pageでは短いheadが解放した領域も長いheadとpageを共有するため返却できず、dynamic compressionではforward後に散在pageを回収・remapするhost-side処理が必要になる。さらにheadごとのKV長差はGPU workload imbalanceを生む。論文の測定ではpage reclamationがprefill時間の最大25%、静的partitionではdecode attentionが最大1.7倍遅くなり、FlashInfer型の動的re-planningもdecode stepの15–20%をCPU planningに費やす。
## 新規性
Tangramは非一様圧縮後のhead別retention profileに、headの順位はほぼinput-invariantで各headの絶対保持率も狭い範囲に収まる二段階の構造的規則性があると観察する。これを50個のpilot sampleからoffline calibrationし、実行時に未知だったhead別memory footprintを事前既知のstatic blueprintへ変換する。この静的化を利用してBudget Reservation、Ragged Paging、Ahead-of-Time Load Balancingを同じprofileで結び、圧縮score自体ではなく高throughput servingで実際に回収可能なmemory layoutとkernel schedulingをco-designする。
## 手法
### 手法のあらまし
まず対象modelと圧縮方式ごとにcalibration contextを流し、元の非一様圧縮が各layer・各KV headへ割り当てたretention ratioを記録する。各headについて平均μと標準偏差σを求め、B_l,h=min(1, μ_l,h+α·σ_l,h)という安全余裕付きの固定budgetを作る。online prefillではchunked prefillとcontinuous batchingを維持し、各chunkのKV生成直後に元のimportance scorerでtokenを採点する。ただし保持個数はoffline B_l,hに従うためschedulerはforward前からpost-compression page数を予約でき、over-allocation後のcompress-and-reclaimを不要にする。次にRagged Pagingでは全headを一つのpage tableで管理せず、budgetの近いheadをH_p個ずつgroup化し、layer・groupごとに独立page tableを持つ。group内で最長のheadにだけ合わせればよいため、短いheadから解放されたcapacityをphysical page poolへ戻せる。headはbudget順にoffline sortし、group数増加によるCPU管理costはVectorized Block TableをOpenMPとSIMDで並列処理して抑える。decode attentionでは各head-groupの固定budget比から計算量を事前推定し、GPUが同時実行できるCTA数へ比例配分したWorkload Split Mapをoffline作成する。runtimeではこのmapを読むだけでper-layer re-planningを行わない。context lengthが変わっても各group長は同じ比率で伸びるためrelative workloadはほぼ不変で、batchingしてもstatic planを再利用できる。

### Budget Reservation
50 pilot sampleでhead別retention ratioを測り、平均と分散から安全係数α付き固定budgetを算出する。schedulerが必要pageを事前予約でき、compress-and-reclaim pathを除去する。評価ではα=2。

### Ragged Paging
同一layerのH_p個のKV headを一groupとして独立page tableを持たせる。budgetが近いheadをoffline clusteringし、monolithic pageで閉じ込められていたmemoryを実際に解放する。adjacent groupingよりfull KVの12–25%を追加回収する。

### Vectorized Block Table
細粒度group化で増えるhost-side mapping costをOpenMPとSIMD/AVX-512で並列化し、fragmentation削減とCPU管理overheadのtrade-offを改善する。

### Ahead-of-Time Load Balancing
固定budgetからhead-group workloadを求め、GPU CTA数へwork量比例で配分するWorkload Split Mapをoffline計算する。decode時はmapを読み、static heuristicのstragglerとdynamic planner costを避ける。

### 全体のデータ／制御の流れ
offline calibrationでhead budget、grouping、Workload Split Mapを決める。onlineではschedulerが固定budgetからpageを先取りし、chunked prefillでimportance scoring→head別圧縮→ragged page格納を行う。decodeはgroup別実効KV長でattentionを計算し、thread-block配分はoffline mapから決める。memory allocation、compression、paging、GPU schedulingが同じstatic retention profileで接続される。成立条件はhead retention profileの安定性とH_pをfragmentationとCPU管理costの中間へ置けること。H_pが小さすぎるとpage-table管理が増え、大きすぎるとfragmentationが戻る。underlying compressorのtoken選択誤りはTangramでは修正しない。
## 評価条件
- **Hardware**: Intel Xeon Gold 6326 @ 2.90 GHz, 16 physical cores、4× NVIDIA A100 80GB
- **Software**: Tangram on vLLM、custom CUDA kernels based on FlashAttention、OpenMP/SIMD vectorized block table
- **Model**: Qwen3-4B、Llama-3.1-8B、Gemma-3-12B、GPT-OSS-20B、Qwen3-30B-A3B
- **Dataset / Trace**: SCBench: Many-Shot, RepoQA, Multi-Choice QA, MathFind, Retrieve Prefix-Suffix, KV, Summary、50 pilot samples for calibration
- **Baseline**: vLLM Full-KV、original dynamic Ada-SnapKV, Expected Attention, FastKVzip、FlashDecoding、FlashInfer
- **Correctness**: Tangram is compared with each compression method's original dynamic implementation while keeping the scorer fixed. Static budgets closely track and sometimes exceed original accuracy across three methods and five models.
- **retention ratios**: accuracy ρ=0.7/0.5/0.3; throughput includes ρ=0.25
- **calibration**: 50 samples, α=2
- **context**: Short <20K, Mid 20K–100K, Long >100K
- **H_p**: 4–8 best measured trade-off; breakdown at H_p=4
All throughput, latency and fragmentation results are actual execution on the stated A100 server, not simulation. Evaluation separates quality, throughput, prefill reclaim cost, decode attention latency, TTFT, and fragmentation/management trade-offs.
Strong evidence for vLLM on one A100 server and SCBench multi-turn workloads; no proof that calibration profile or optimal H_p transfers unchanged to other GPU generations, engines, or large workload shifts.
## 主要結果
Tangram converts irregular non-uniform KV retention into allocatable memory and balanced GPU work. Static profiles remove reclaim/planning overhead while preserving underlying compression accuracy. The 2.6× headline combines compression capacity gain and Tangram system efficiency; cumulative ablations isolate the latter.

- end-to-end throughput / up to 2.6× (比較対象: vLLM Full-KV; 条件: SCBench with FastKVzip; Short-to-Long contexts) — Compression increases capacity and Tangram converts it into realized serving throughput.

- page reclamation overhead / up to 25% of prefill time eliminated (比較対象: dynamic allocation/compress-and-reclaim; 条件: dynamic vs static budget allocation) — Known footprint removes host reclaim path.

- additional memory reclaimed / 12–25% of full KV cache (比較対象: adjacent grouping; 条件: budget-aware clustering at same H_p) — Similar-budget head grouping reduces slack.

- runtime planning overhead avoided / 15–20% of decode step (比較対象: FlashInfer-style dynamic planning; 条件: heterogeneous head lengths) — AOT map removes per-layer planning.

- static imbalance avoided / up to 1.7× latency inflation in baseline (比較対象: FlashDecoding-style static split; 条件: non-uniform head lengths) — CTA allocation follows calibrated workload.

### 負の結果・境界条件
- **group-size trade-off**: H_p too small raises CPU/page-table cost; H_p too large restores fragmentation. H_p=4–8 is the measured sweet spot.
- **speedup attribution**: 2.6× includes the capacity effect of compression and is not Tangram-only speedup.
- **static-profile dependency**: Offline calibration assumes stable retention patterns; arbitrary domain shifts or unseen architectures are not proven.

### 結果の読み方
Most valuable when KV memory limits batch size and a quality-preserving non-uniform compressor creates heterogeneous head lengths. Less useful if KV memory is not limiting or retention profiles vary strongly.
## 品質への影響
Across Ada-SnapKV, Expected Attention and FastKVzip on five models, Tangram closely tracks and sometimes exceeds original dynamic-compression accuracy at ρ=0.7/0.5/0.3; it does not repair the compressor's own quality failures.
## 既存研究との差
- Existing KV compressors choose tokens/budgets; Tangram makes their heterogeneous output practical in a serving system.
- PagedAttention reduces request-level external fragmentation but assumes uniform head lengths; Tangram targets internal fragmentation caused by non-uniform head retention.
- Jenga handles coarser layer heterogeneity and DiffKV differentiated head management; Tangram exploits cross-head retention regularity to static-plan budget, paging, and kernel partition together.
- Unlike FlashDecoding static heuristics or FlashInfer runtime planning, Tangram moves partitioning fully offline using calibrated budget ratios.
## 限界
- Depends on offline-calibrated retention stability.
- Main real-system evaluation is one 4×A100 server; transfer to other GPU/CPU/multi-node systems is unproven.
- Optimal H_p is hardware-dependent.
- 2.6× headline includes underlying compression capacity gain.
- Does not fix quality loss caused by the compression scorer itself.
## 実装状態
Official aiha-lab/TANGRAM repository is public, vLLM-based and Apache-2.0. It documents installation, reproduction, ragged paging, multiple scorers, Ampere/sm_80+ requirement, and verified Qwen/Llama/Gemma/GPT-OSS models with some tensor-parallel restrictions.
