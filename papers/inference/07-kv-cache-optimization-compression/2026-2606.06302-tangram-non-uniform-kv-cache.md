# Tangram: Unlocking Non-Uniform KV Cache Compression for Efficient Multi-turn LLM Serving

> Tangramは、ヘッド別KV保持量を少数サンプルで事前較正し、固定予算のraggedページ化と負荷分散へ変換して、非一様圧縮の断片化・回収費・デコード不均衡を減らす。

## 概要

非一様KV圧縮は品質を保ちやすい一方、ヘッドごとの保持量が違うとページ断片化、回収、デコード仕事量の偏りが生じる。Tangramは少数サンプルでヘッド別保持量を静的較正し、固定予算のraggedページ表とAOT負荷分散へ変換して、実行時の回収・計画費を抑える。A100実機のSCBench評価ではvLLM Full-KV比エンドツーエンドスループット最大2.6倍、ページ回収でプリフィル時間最大25%、デコード計画でステップ15〜20%を削減した。

## 問題設定
複数ターン会話では過去履歴を再計算しないためKV キャッシュを保持するが、会話ターン数と同時リクエスト数に比例して容量が増える。非一様KV圧縮は長距離情報を保持すべき注意機構 ヘッドへ多く、局所的なヘッドへ少なく予算を配るため一様圧縮より品質を保ちやすい。しかし既存サービング stackは全ヘッドのKV長が同じことを前提にする。PagedAttentionの単一 ページでは短いヘッドが解放した領域も長いヘッドとページを共有するため返却できず、動的 圧縮では順伝播後に散在ページを回収・remapするホスト-side処理が必要になる。さらにヘッドごとのKV長差はGPU ワークロード imbalanceを生む。論文の測定ではページ 回収がプリフィル時間の最大25%、静的partitionではデコード 注意機構が最大1.7倍遅くなり、FlashInfer型の動的再計画もデコード ステップの15–20%をCPU 計画に費やす。
## 新規性
Tangramは非一様圧縮後のヘッド別保持 プロファイルに、ヘッドの順位はほぼ入力-invariantで各ヘッドの絶対保持率も狭い範囲に収まる二段階の構造的規則性があると観察する。これを50個の試行 サンプルから事前 較正し、実行時に未知だったヘッド別メモリ 使用量を事前既知の静的 設計図へ変換する。この静的化を利用して予算 予約、Ragged ページ化、Ahead-of-時間 Load Balancingを同じプロファイルで結び、圧縮スコア自体ではなく高スループット サービングで実際に回収可能なメモリ 配置とカーネル スケジューリングを協調設計する。
## 手法
### 手法のあらまし
まず対象モデルと圧縮方式ごとに較正 文脈を流し、元の非一様圧縮が各層・各KV ヘッドへ割り当てた保持 比率を記録する。各ヘッドについて平均μと標準偏差σを求め、B_l,h=min(1, μ_l,h+α·σ_l,h)という安全余裕付きの固定予算を作る。オンライン プリフィルでは分割 プリフィルと連続 batchingを維持し、各chunkのKV生成直後に元の重要度 評価器でトークンを採点する。ただし保持個数は事前 B_l,hに従うためスケジューラは順伝播前から圧縮後 ページ数を予約でき、過剰割り当て後の圧縮する-and-回収を不要にする。次にRagged ページ化では全ヘッドを一つのページ 表で管理せず、予算の近いヘッドをH_p個ずつグループ化し、層・グループごとに独立ページ 表を持つ。グループ内で最長のヘッドにだけ合わせればよいため、短いヘッドから解放された容量を物理 ページ プールへ戻せる。ヘッドは予算順に事前 並べ替えし、グループ数増加によるCPU管理コストはベクトル化 ブロック 表をOpenMPとSIMDで並列処理して抑える。デコード 注意機構では各ヘッド-グループの固定予算比から計算量を事前推定し、GPUが同時実行できるCTA数へ比例配分したワークロード Split 対応表を事前作成する。実行時ではこの対応表を読むだけで層ごと 再計画を行わない。文脈 長さが変わっても各グループ長は同じ比率で伸びるため相対 ワークロードはほぼ不変で、batchingしても静的 計画を再利用できる。

この一連の流れで重要なのは、保持率の予測を単なる圧縮設定で終わらせず、メモリ予約・ページ配置・GPU仕事量の三つへ同じ設計値として伝播させる点である。保持量だけを固定しても実行側が不均一長を知らなければ待ち時間が残り、実行側だけを最適化してもページを返却できなければ同時処理数は増えない。Tangramは一つの較正結果を複数層の制御へ共有することで、圧縮で生じた不均一性を実際の処理量向上へ変換する。

### Budget Reservation
50 試行 サンプルでヘッド別保持 比率を測り、平均と分散から安全係数α付き固定予算を算出する。スケジューラが必要ページを事前予約でき、圧縮する-and-回収 pathを除去する。評価ではα=2。

安全係数αは動的 圧縮器の揺らぎを固定予算へ吸収する余裕である。αを小さくするとメモリを強く節約できる反面、実入力で較正平均を超える保持需要が出たとき予算不足になりやすい。大きくするとプロファイル外入力へ頑健になるが、各ヘッドへ未使用容量を予約して非一様 圧縮のメモリ利得を失う。つまり決定的 割り当ては完全な平均値固定ではなく、観測分散に応じた安全 帯を持つ。

### Ragged Paging
同一層のH_p個のKV ヘッドを一グループとして独立ページ 表を持たせる。予算が近いヘッドを事前 クラスタ化し、単一 ページで閉じ込められていたメモリを実際に解放する。隣接 グループ化よりfull KVの12–25%を追加回収する。

予算が近いヘッドを同グループへ入れる理由は、グループ ページ内の物理 割り当てがそのグループで最も長いヘッドに引っ張られるためである。保持率30%のヘッドと90%のヘッドを同じグループにすると短いヘッドの空きが再び内部断片化として残る。事前 並べ替え/クラスタ化で似た長さをまとめれば、グループ数を無限に増やさなくてもmax-minus-実際のの差を小さくでき、ページ 表 オーバーヘッドとメモリ 回収の中間点を作れる。

### Vectorized Block Table
細粒度グループ化で増えるホスト-side 対応付け コストをOpenMPとSIMD/AVX-512で並列化し、断片化削減とCPU管理オーバーヘッドのトレードオフを改善する。

ヘッド-グループごとに独立表を持つと、スケジューラが更新・参照するブロック-表 エントリ数とポインタ操作が増える。ベクトル化 ブロック 表はこの管理処理を複数グループまとめて連続配列として処理し、OpenMPでコア間、SIMDでエントリ間を並列化する。これによりH_pを小さくしてメモリを細粒度回収したときも、ホスト-side bookkeepingがプリフィル/デコードの新しいボトルネックになりにくくする。

### Ahead-of-Time Load Balancing
固定予算からヘッド-グループ ワークロードを求め、GPU CTA数へwork量比例で配分するワークロード Split 対応表を事前計算する。デコード時は対応表を読み、静的 ヒューリスティックの遅延要因と動的 計画器 コストを避ける。

AOT 対応表はヘッド-グループの相対KV長が文脈成長後もほぼ同じ比率で伸びるという観察を利用する。実行時 計画器なら毎ステップの実長からCTA配分を最適化できるが、CPU 計画 コストが発生する。固定equal splitならコストはないが長いグループが遅延要因になる。較正比率から事前にwork 共有するを決めれば、実行時では参照だけで長いグループへ多くCTAを配り、この二つの失敗を同時に避ける。

### 全体のデータ／制御の流れ
事前 較正でヘッド 予算、グループ化、ワークロード Split 対応表を決める。オンラインではスケジューラが固定予算からページを先取りし、分割 プリフィルで重要度 採点→ヘッド別圧縮→ragged ページ格納を行う。デコードはグループ別実効KV長で注意機構を計算し、スレッド-ブロック配分は事前 対応表から決める。メモリ 割り当て、圧縮、ページ化、GPU スケジューリングが同じ静的 保持 プロファイルで接続される。成立条件はヘッド 保持 プロファイルの安定性とH_pを断片化とCPU管理コストの中間へ置けること。H_pが小さすぎるとページ-表管理が増え、大きすぎると断片化が戻る。元の 圧縮器のトークン選択誤りはTangramでは修正しない。

この設計は、圧縮アルゴリズムとサービング システムの責任を分ける。オンラインでも重要度 スコア自体は元圧縮器が計算し、Tangramが固定するのは各ヘッドで保持できる個数の上限である。したがって『どのトークンを残すか』の品質特性は既存圧縮器に従い、『その不均一な保持量をどう事前予約・ページ化・GPUへ割り当てるか』だけを静的 プロファイルで安定化する。

同じ保持 プロファイルを割り当て・ページ化・load balancingの3層で共有することも重要である。メモリ allocatorだけ固定予算を知っていてカーネル スケジューラが実長を知らなければ、容量は回収できてもデコード imbalanceが残る。逆にカーネルだけ静的配分してもページ 配置が単一ならメモリが返らない。Tangramは事前 較正結果を制御 平面全体の共通設計図として使い、各最適化が同じヘッド-長さ予測に基づいて噛み合うようにしている。
## 評価条件
- **ハードウェア**: Intel Xeon Gold 6326 @ 2.90 GHz、物理コア16個、NVIDIA A100 80GB×4
- **ソフトウェア**: vLLM上のTangram、FlashAttentionを基盤とする独自CUDAカーネル、OpenMP/SIMDベクトル化ブロック表
- **モデル**: Qwen3-4B、Llama-3.1-8B、Gemma-3-12B、GPT-OSS-20B、Qwen3-30B-A3B
- **データセット／トレース**: SCBench（Many-Shot、RepoQA、Multi-Choice QA、MathFind、Retrieve Prefix-Suffix、KV、Summary）、較正用試行サンプル50個
- **比較対象**: vLLM Full-KV、元の動的Ada-SnapKV、Expected Attention、FastKVzip、FlashDecoding、FlashInfer
- **正しさ**: 各圧縮手法の元の動的実装と、評価器を固定したTangramを比較する。静的予算は3手法・5モデルで元の精度に近く、ときに上回る。
- **保持率**: 精度ρ=0.7/0.5/0.3、スループット測定にはρ=0.25も含む
- **較正**: サンプル50個、α=2
- **文脈長**: 短文脈 <20K、中文脈20K–100K、長文脈 >100K
- **H_p**: 実測上の最良トレードオフは4–8、内訳はH_p=4で測定
スループット、遅延、断片化の結果は、記載したA100サーバーでの実機実行であり、シミュレーションではない。評価では品質、スループット、プリフィル回収コスト、デコード注意機構の遅延、TTFT、断片化と管理コストを分けて測定する。
vLLMを1台のA100サーバーでSCBenchの複数ターン負荷に適用した証拠は強いが、較正プロファイルや最適H_pが他世代GPU、他エンジン、大きな負荷変動にもそのまま移ることは示されていない。
## 主要結果
Tangramは不規則な非一様KV保持を、割り当て可能なメモリと均衡したGPU仕事量へ変換する。静的プロファイルにより回収と計画のオーバーヘッドを除きつつ、元の圧縮精度を保つ。2.6倍という見出し値は、圧縮による容量増加とTangramのシステム効率を合わせたものであり、累積アブレーションで後者を切り分けている。

- エンドツーエンドのスループット / 最大2.6倍（比較対象: vLLM Full-KV、条件: FastKVzipを用いたSCBench、短文脈から長文脈）— 圧縮で容量を増やし、Tangramが実際の推論スループットへ変換する。

- ページ回収オーバーヘッド / プリフィル時間の最大25%を削減（比較対象: 動的割り当てと圧縮・回収、条件: 動的対静的予算割り当て）— 既知の使用量によりホスト側の回収経路を除く。

- 追加回収メモリ / 完全KVキャッシュの12–25%（比較対象: 隣接グループ化、条件: 同じH_pで予算を考慮したクラスタ化）— 予算の近いヘッドをまとめることで余白を減らす。

- 実行時計画オーバーヘッドの回避 / デコードステップの15–20%（比較対象: FlashInfer型の動的計画、条件: 不均一なヘッド長）— AOT対応表により層ごとの計画を除く。

- 静的不均衡の回避 / 比較対象で最大1.7倍の遅延増加（比較対象: FlashDecoding型の静的分割、条件: 非一様なヘッド長）— CTA割り当てを較正済みワークロードに合わせる。

### 負の結果・境界条件
- **グループサイズのトレードオフ**: H_pが小さすぎるとCPUとページ表のコストが増え、大きすぎると断片化が戻る。実測上の適点はH_p=4–8である。
- **高速化倍率の帰属**: 2.6倍には圧縮による容量効果も含まれ、Tangram単独の高速化倍率ではない。
- **静的プロファイルへの依存**: 事前較正は保持パターンが安定していると仮定しており、任意のドメイン変化や未知の構成への適用は未証明である。

### 結果の読み方
KVメモリがバッチサイズを制限し、品質を保つ非一様圧縮器がヘッド長を不均一にする場合に最も有用である。KVメモリが制約でない場合や保持プロファイルの変動が大きい場合は有用性が下がる。
## 品質への影響
5モデル上のAda-SnapKV、Expected Attention、FastKVzipに対し、Tangramはρ=0.7/0.5/0.3で元の動的圧縮精度に近く、ときに上回る。ただし圧縮器自身の品質低下は修復しない。
## 既存研究との差
- 既存のKV圧縮器はトークンと予算を選ぶ。Tangramはその不均一な出力を推論提供システムで実用化する。
- PagedAttentionはリクエスト単位の外部断片化を減らすが、ヘッド長が一様であることを仮定する。Tangramは非一様なヘッド保持が生む内部断片化を対象とする。
- Jengaは粗い層の不均一性、DiffKVは差別化したヘッド管理を扱う。Tangramはヘッド間の保持規則性を利用し、予算、ページ化、カーネル分割をまとめて静的計画する。
- FlashDecodingの静的ヒューリスティックやFlashInferの実行時計画と異なり、Tangramは較正済み予算比率を使って分割を完全に事前計画する。
## 限界
- 事前較正した保持パターンの安定性に依存する。
- 主な実システム評価は4×A100サーバー1台であり、他のGPU、CPU、複数ノードへの移植性は未証明である。
- 最適なH_pはハードウェアに依存する。
- 2.6倍の見出し値には元の圧縮による容量利得が含まれる。
- 圧縮評価器自身が生む品質低下は修正しない。
## 実装状態
公式aiha-lab/TANGRAMリポジトリは公開され、vLLMを基盤とするApache-2.0実装である。インストール、再現、raggedページ化、複数評価器、Ampere/sm_80+要件、検証済みのQwen/Llama/Gemma/GPT-OSSモデルと一部テンソル並列の制限を記載する。
## 研究上の位置づけ
KVキャッシュの最適化・圧縮とLLM推論提供の境界に位置するシステム論文である。アルゴリズム的な追い出しより、非一様圧縮を連続バッチ化とPagedAttentionへ載せるメモリ割り当て器・ページ表・スケジューラ・注意機構カーネルの協調設計が主題である。
