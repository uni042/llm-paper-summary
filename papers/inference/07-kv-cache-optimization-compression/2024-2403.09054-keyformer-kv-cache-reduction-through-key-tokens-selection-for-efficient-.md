# Keyformer

## 概要
自己回帰生成では過去トークンのkey/valueを保存するKVキャッシュが文脈長とともに線形に増える。各生成段階はモデル重みだけでなくKVも読み出すため、長文脈ではメモリ容量だけでなく帯域が律速になる。Keyformerは注意機構重みのおよそ90%が一部トークンへ集中するという観察を使い、重要トークンだけを残す。

単純に注意機構 スコアが低いトークンを削除すると、softmaxの正規化集合が変わり、削除後のスコア分布が時間とともにずれる。Keyformerは最近トークンを保持するrecency windowと、履歴から選んだkey トークンを組み合わせ、Gumbel項と温度scheduleを含むスコアで重要度を更新する。モデル再学習を要求しない。

## 問題設定
KV キャッシュを半分にすれば容量は減るが、誤って将来参照されるトークンを捨てれば品質が崩れる。固定windowだけでは遠い重要情報を保持できず、過去注意機構だけを素朴に積算する方式もトークン削除後の分布変化を十分扱えない。

Keyformerの課題は、各生成段階で限られたKV budgetへ「最近必要になったトークン」と「長距離でも継続的に重要なトークン」を共存させることである。追加学習やモデル改変を避け、既存生成パイプラインへ推論時policyとして挿入する。

## 手法
### key tokenの選択
各ヘッド/層で過去トークンへの注意機構から重要度を作り、上位トークンをkey トークンとして残す。最近のトークンは別の固定windowとして保護するため、直近局所依存をスコア変動で誤って捨てにくい。

### Gumbel正則化付きscore
トークンを削除するとsoftmaxの母集合が変わるため、残存トークンの確率が再配分される。KeyformerはGumbel由来の摂動をスコアへ加え、温度を生成段階に応じて変化させる。これにより一度の注意機構ピークだけへ過度に固定せず、将来重要になる候補も残せるようにする。

### 固定budgetでの更新
新トークンが生成されるたび、そのKVを追加する一方、budgetを超えればkey スコアに基づいて履歴トークンを落とす。出力は通常と同じKV集合なので注意機構 カーネル自体を別演算へ置き換える必要はなく、減ったKV分だけread量と注意機構計算が減る。

## 評価条件
| 項目 | 条件 |
|---|---|
| models | GPT-J、Cerebras-GPT、MPT |
| 位置表現 | 異なるpositional embeddingを持つ複数モデル |
| tasks | summarization、conversation、少数例等 |
| 比較軸 | accuracy/ROUGE等の品質、KV容量、data 転送、遅延、スループット |
| 学習 | 追加微調整なし |

## 主要結果
| 指標 | 結果 | 読み取れること |
|---|---|---|
| KV キャッシュ | 最大50%削減 | 容量と注意機構対象を同時に削減 |
| KV data 転送 | 約2.9倍削減 | メモリ-帯域律速を直接緩和 |
| inference 遅延 | 最大2.1倍短縮 | KV read削減がエンドツーエンド生成へ反映 |
| トークン スループット | 最大2.4倍向上 | 長文脈生成の処理率を改善 |
| タスク quality | 比較対象を概ね維持 | 重要トークン選択で圧縮損失を抑制 |

## 既存研究との差
量子化のように各KV要素のbit数を減らすのではなく、注意機構対象トークンそのものを選択する。固定sliding windowだけとも異なり、遠距離の重要トークンをスコアで残す。再学習を必要とするキャッシュ圧縮と比べ、既存モデルへ推論時に適用できる。

## 限界
注意機構が少数トークンへ集中する性質に依存するため、広い範囲へ均等に注意機構するタスクでは削除余地が小さくなる。固定budgetを強く絞るほど重要トークンを誤削除する危険は増える。評価モデルはGPT-J/Cerebras-GPT/MPT中心で、現代のGQA/MQAを持つ超長文脈モデルや大規模multi-tenant 推論提供でのtail 遅延は論文の主評価外である。
