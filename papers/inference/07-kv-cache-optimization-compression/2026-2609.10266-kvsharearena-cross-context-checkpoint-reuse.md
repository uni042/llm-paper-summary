# KVShareArena: KV-Cache Reuse Across Contexts and Model Checkpoints

> 本論文は、検索拡張生成や複数エージェント連携で、別々に作ったKVキャッシュを新しい文脈へ組み込むと、位置のずれだけでなく、各情報源が互いを見ずに符号化されたため必要な相互作用が欠ける問題を、共通条件で測るベンチマークを提案する。さらに、同一構造でも異なるチェックポイントが作ったKVを受信側モデルが読めるかを独立要因として加え、文脈変化と重み変化を交差させる。品質は共有情報なしを床、同じ情報を完全に再計算した場合を天井として、その差をどれだけ回収したかで正規化し、計算量、KV容量、同一実行基盤上の初回トークン時間も併記する。結果として、単一情報源ではほぼ無料の位置補正で十分だが、複数情報源をまたぐ推論では選択的再計算や注意機構の補正が必要になり、圧縮だけでは品質を落としやすいことを示す。

## 問題設定
既存のKVキャッシュ再利用は、同じ接頭辞がそのまま再登場する場合には正確で高速だが、検索拡張生成や複数エージェント連携では同じ情報源が別の指示文、別の並び順、別の情報源集合の中へ差し込まれる。すると、事前計算したKVは元の位置を持ったままで、さらに各情報源は他の情報源を見ずに独立して符号化されているため、単純な連結では本来の密な入力処理が作る情報源間の注意接続が欠落する。加えて、専門モデルや以前のチェックポイントが作ったKVを別の受信モデルが利用する場合、テンソル形状が一致しても値そのものは一致しない。従来研究は、位置補正、選択的再計算、注意機構の較正、学習済み修復、圧縮などを個別の課題と評価条件で報告しており、品質の床と天井、計算量、容量、実行時間をそろえた比較がなかった。そのため、どの条件で無料の補正だけで十分か、どこから有償の修復が必要かを判断しにくかった。
## 新規性
KVShareArenaの新規性は、文脈変化と生成側チェックポイント変化を独立した二要因として交差させ、検索で得た生の断片と、専門エージェントが生成した報告という二つの再利用ワークロードを、共通の品質尺度と費用尺度で比較する点にある。品質は共有情報を一切与えない床と、同じ共有情報を受信側が完全に再計算した天井の間で、失われた性能差をどれだけ回収したかとして正規化する。さらに、入力処理の再計算量、実際のKVバイト数、同一実行基盤上の初回トークン時間を別々の前線として示し、一つの任意な換算率へ潰さない。これにより、位置ずれだけの問題と、情報源間の相互不可視性、異なる重みが作った表現の互換性を切り分けられる。
## 手法
### 手法のあらまし
評価の出発点では、共有する文書断片またはエージェント報告を、問い合わせを見せずに一つずつ独立してKVへ変換する。この生成時の接頭辞と位置をKVの出生文脈と定義する。利用時には、受信側の固定指示、複数の独立KV、質問を一つの入力として組み立てる。文脈条件では出生時と利用時が同じか異なるかを変え、チェックポイント条件ではKVを作る生成側と回答する受信側の重みが同じか異なるかを変える。これにより、同一文脈・同一重み、同一文脈・異なる重み、異なる文脈・同一重み、異なる文脈・異なる重みの四つを分離する。主順位表では異なる文脈を対象とし、単純連結、位置補正、選択的再計算、注意機構の較正、学習済み修復、軟らかいトークンを使う修復、圧縮などを同じ凍結済み問い合わせ集合へ適用する。品質は性能差回収率で比較し、計算面では密な入力処理に対してどれだけ層×トークン再計算を省いたか、容量面では実テンソルのKVバイト数をどれだけ減らしたか、実行面では同一実行基盤上でキャッシュが手元にある状態の初回トークン時間をどれだけ短縮したかを測る。キャッシュを最初に作る一回限りの費用は、再利用回数に依存するため要求ごとの費用へ混ぜず別に報告する。

### 出生文脈を外れたKVの二要因分離
各情報源KVは独立した正規文脈で作り、その後の利用時に位置と前置き文を変える。これにより、単に接頭辞が一致しないことによる位置ずれと、複数情報源が互いを見ずに作られたため密な入力処理が持つ情報源間の注意接続を欠く問題を同時に発生させる。さらに生成側の重みだけを変え、構造、トークナイザ、受信側、文章、質問、採点を固定することで、異なるチェックポイント由来のKVがどこまで互換かを別の軸として測る。単純なテンソル形状一致を互換性と見なさず、値のずれが回答へ与える影響を直接評価する設計である。

### 床と天井で正規化する性能差回収率
異なるデータ集合や方法の生の正解率を直接比べると、そもそも共有情報の価値が異なるため、同じ一点差でも意味が変わる。そこで、受信側が共有情報をまったく使わず回答した得点を床、各方式が実際に消費する同じ共有情報を完全に再計算した得点を天井とする。方式の得点が床から天井までの差を何割回収したかを性能差回収率として計算する。値は床で0、天井で1となり、再利用がむしろ有害なら負になる。この尺度により、単純連結が共有情報なしより悪い失敗も、小さな生得点低下として隠れず明示される。また、各方式の天井を『その方式が実際に使った同じ共有情報』から作るため、情報量を増やした方式が不当に有利にならない。例えば、ある質問集合で共有情報自体の価値が小さければ、生の正解率が高くても回収できる余地は小さい。一方、床と天井の差が大きい条件で負の値になれば、KV再利用によって有用な情報を渡したはずなのに、壊れた表現が回答をむしろ悪化させたと解釈できる。この正規化を使うことで、データ集合や再利用方式をまたいで『失われた情報価値をどこまで戻したか』という同じ問いで比較できる。

### 計算・容量・初回トークン時間の三前線
再利用方式ごとに支払う資源が違うため、単一の費用指標にまとめず三つに分ける。計算前線は密な共有情報の層×トークン総量に対して再計算した割合から節約量を求める。容量前線は量子化の尺度値や索引など付随データまで含む実テンソルのバイト数を密なBF16 KVと比較する。実行前線は同一実行基盤でキャッシュがすでに存在する状態から初回トークンまでの時間を測り、キャッシュ生成費は別に出す。これにより、計算を省く方式と容量を省く方式が同じ品質を持つとは限らないことを、交換条件を隠さず示せる。

### 凍結済み問い合わせと方式別の適用可能性管理
Retrieved EvidenceではLongBenchの三種類の質問応答とFRAMES派生条件を用い、各部分集合の問い合わせを方式実行前に固定する。Agent Reportsでは専門エージェントが質問を知らずに生成した報告を固定し、全方式が同じ報告を使う。方式ごとに共有設定を変えず、設定が合わない方式は専用条件を与えるのではなく適用不可として残す。公式実装、著者らの移植、参照行を区別し、移植方式には機構や得点の再現確認を設ける。これにより、方式ごとに都合のよいデータや設定へ変えることを防ぎ、差を修復機構そのものへ帰属しやすくする。

### 全体のデータ／制御の流れ
実際の流れは、共有情報を問い合わせなしで独立KVへ変換して保存し、利用時に複数KVを受信側文脈へ組み込み、対象方式による位置補正・再計算・較正・圧縮などを施して回答する。その出力をデータ集合の公式指標で採点し、同一サンプルの床と天井から性能差回収率を求める。同時に各サンプルの再計算層×トークン数、KV実バイト数、同一実行基盤での初回トークン時間を保存する。チェックポイント試験では同じ処理のKV生成側だけを受信側の以前の重みまたは追加学習された同構造モデルへ置き換え、各修復方式の変化量を見る。最終的には、無料の位置補正で十分な領域、再計算や学習へ費用を払う価値がある領域、圧縮が品質を損なう領域を同じ座標上で判断できるようにする。

- **方法採用規則**: 同一順位表では評価方式だけを独立変数にし、共通設定で動作できない方式は専用設定を与えず適用不可とする。公式実装、著者らの移植、参照行を区別し、移植方式は機構一致または再現確認を行う。採用基準に落ちた候補も付録で公開する。

まず文脈と重みの二要因を交差させ、同一文脈・同一重み、同一文脈・異なる重み、異なる文脈・同一重み、異なる文脈・異なる重みを分ける。主順位表は異なる文脈での再利用を比較し、単純連結、位置補正、選択的再計算、注意機構較正、学習済み修復、圧縮などを同じ固定質問へ適用する。方式の品質は床0・天井1となる性能差回収率で表し、無料補正を有意に上回るかを対応あり検定で判定する。別系統8Bと4Bでは同じ傾向が再現するかだけを確認し、順位そのものは横断比較しない。

## 主要結果
結果は、KVが出生文脈を離れたときの損失を『無料で直せる位置ずれ』と『情報源同士が互いを見ていないため欠けた相互作用』へ分けて考えるべきだと示す。単一情報源の受け渡しでは位置補正だけで性能差をほぼ完全に回収できる一方、複数情報源をまたぐ推論では無料補正が床を下回り、選択的再計算や注意機構較正へ計算費を払う価値が出る。Agent Reportsでも単純連結は性能差回収率-0.82まで崩れ、再計算する二方式だけが無料補正を有意に上回る。実行面ではキャッシュが手元にある場合に再利用行が密な入力処理より約90%短い初回トークン時間を示すが、キャッシュ生成費と保存階層の転送費は別に考える必要がある。

- 複数段推論の無料位置補正 / 性能差回収率 -0.196 (比較対象: 共有情報なしの床=0、完全入力処理の天井=1; 条件: Retrieved Evidenceの複数段推論、異なる文脈でKV再利用) — 位置を直すだけでは、独立生成された複数情報源の間に欠けた注意接続を再構築できず、共有情報なしより悪化する。

- 複数段推論の有償修復 / 性能差回収率 約0.39〜0.46 (比較対象: 無料位置補正 -0.196; 条件: 選択的再計算または注意機構較正を適用) — 質問が複数情報源の結合を必要とする領域では、欠けた相互作用を作り直す修復へ費用を払うことが有効である。

- 選択的再計算量 / LegoLinkは共有情報の0.5%未満、CacheBlendは約15% (比較対象: 完全入力処理=100%再計算; 条件: Retrieved Evidenceの有効な修復行) — 同じ修復分類でも必要な再計算量は大きく異なり、品質だけでなく層×トークン計算量を併記する必要がある。

- Agent Reportsの単純組み立て / 性能差回収率 -0.82 (比較対象: 共有情報なしの床=0; 条件: 質問を知らない複数エージェントが独立生成した報告KVを補正なしで組み立てる) — 独立した報告をKVのまま並べるだけでは情報源間の相互不可視性が強く、共有情報そのものが回答を害する場合がある。

- Agent Reportsの上位修復 / CacheBlendは無料位置補正比 +0.11、RelayCachingは +0.08 (比較対象: 無料位置補正; 条件: Agent Reports順位表) — 無料補正を有意に上回ったのは再計算を行う二方式で、両者は統計的に同率だった。それでも性能差の約3分の1は残る。

- 単一情報源の位置補正 / 単純受け渡し -0.22/-0.37/-0.98 → 位置補正 0.93/0.98/1.05 (比較対象: 補正なしの単一情報源KV受け渡し; 条件: 三つの単一情報源条件) — 相互に結合すべき複数情報源がない場合、主な問題は位置の幾何学であり、ほぼ無料の位置補正だけで天井近くまで戻る。

- 同一実行基盤の初回トークン時間 / 科学論文質問応答で密な入力処理0.35秒、再利用行約0.04秒 (比較対象: 密な入力処理; 条件: キャッシュが既に実行ノードに存在する状態。同じ要求のキャッシュ生成は0.44〜0.73秒) — 再利用の要求時遅延は約90%短いが、一回限りの生成費まで含めると数回以上の再利用が必要になり、実際の損益は再利用頻度と保存階層帯域に依存する。

- KV容量 / 4ビット量子化の実測削減71.9%、KVPacket/MiniPICは約3%増加 (比較対象: 密なBF16 KV容量; 条件: 尺度値・索引・追加状態を含む実テンソルバイト数) — 名目ビット幅だけでは実容量を表せず、圧縮は容量を減らせても本ベンチマークでは品質面で無料位置補正を有意に上回らない。

- チェックポイント横断の頑健性 / 大半の方式は変化0.06以下、KVPacketは6条件中4条件で有意低下し最大-0.135、LegoLink再計算なしは最大-0.231 (比較対象: 同じ受信側チェックポイントが生成したKV; 条件: 構造・トークナイザ・RoPE基準を固定し生成側チェックポイントだけ変更) — 推論時に再選択して修復する方式は比較的頑健だが、生成側KV表現へ学習で適合した修復は重み変化へ脆弱になり得る。

### 負の結果・境界条件
- **圧縮は品質修復にならない**: 圧縮方式はRetrieved Evidenceで無料位置補正を有意に上回らず、四つの条件では有意に下回る。Agent Reportsではすべての圧縮行が無料位置補正より有意に低く、新しく生成された報告には削ってよい冗長性が少ない。容量削減と文脈横断修復は別問題として扱う必要がある。
- **学習済み修復は生成側重みへ過適合し得る**: KVPacketは同一チェックポイントでは再計算なしで強いが、生成側チェックポイントを変えると6条件中4条件で有意に低下する。LegoLinkでも再計算なしの端点は複数段推論で大きく低下する一方、再計算あり版は安定する。形状互換だけでは表現互換を保証しない。
- **無料補正が十分な領域では有償方式の差が消える**: 科学論文質問応答や単一情報源の受け渡しでは位置補正がほぼ性能差を回収し、追加修復の有意な利益が出ない。常に再計算するのではなく、情報源間の依存が必要な条件を見極める必要がある。
- **順位の一般化には制約がある**: 個別方式の順位は主に一つの8Bモデルで測り、別8B系統と4Bモデルでは傾向だけを確認する。100件条件の検出可能差はおよそ0.10で、それより小さい差は同率として扱う。入力上限も29Kトークンである。

### 結果の読み方
最も重要な読み方は、非接頭辞KV再利用の失敗を一つの『キャッシュ誤差』としてまとめないことである。単一情報源では出生時と利用時の位置差が支配的で、位置補正だけでほぼ解ける。複数情報源では、それぞれが他方を見ずに符号化された相互不可視性が増え、質問が情報源横断推論を要求するほど損失が大きくなる。この領域で初めて再計算や較正が費用に見合う。チェックポイントを変えたときの結果も、固定された生成側表現へ学習で適合する方式より、要求時に誤差を再観測して再計算する方式の方が頑健であることを示す。
## 品質への影響
文脈横断KV再利用は原理的に品質無損失ではない。無料位置補正で天井近くまで戻る条件もあるが、複数情報源の結合では床を下回ることさえある。したがって本論文は単一の万能方式を推薦するのではなく、品質回復量とオンライン再計算、KV容量、初回トークン時間を同時に見て方式を選ぶための評価枠組みを提供する。
## 既存研究との差
- 正確な接頭辞一致だけを扱うキャッシュ評価と異なり、KVShareArenaはキャッシュが出生文脈を離れて別の前置き文・位置・情報源集合へ組み込まれる非接頭辞再利用を主対象にする。これにより検索拡張生成や複数エージェント連携で実際に起きる位置ずれと相互不可視性を測れる。
- 各方式の生の正解率だけを比べず、共有情報なしの床と同一情報を完全再計算した天井から性能差回収率を作る。データ集合ごとに共有情報の価値が違っても、方式が失われた情報価値をどこまで取り戻したかを比較しやすい。
- 再計算量だけでなく実KVバイト数と同一実行基盤の初回トークン時間を別々に示す。これにより圧縮、選択的再計算、学習済み修復のように支払う資源が異なる方式を、一つの恣意的な費用換算へ押し込めず比較できる。
- 文脈変化だけでなく生成側チェックポイント変化を独立因子として扱う。テンソル形状が同じでも学習済み修復が生成側表現へ過適合し得ることを示し、キャッシュ互換性を重み更新後の運用まで拡張している。
- 方式だけでなくデータ集合の採用にも事前登録した基準を設け、無料位置補正ですでに十分な領域は『修復が不要な条件』として残す。常に提案方式へ有利な難しい条件だけを選ぶ設計を避けている。
## 限界
- 個別方式の主順位は一つの8B公開重みモデルに基づく。別の8B系統と4B同系モデルで傾向は再確認するが、順位そのものの一般化は主張しない。
- Retrieved Evidenceは各部分集合100件で、対応差がおよそ0.10未満の場合は統計的に区別しにくい。細かな順位差は同率として扱う必要がある。
- 入力上限は29Kトークンであり、100K級以上の極長文脈で相互不可視性やI/O費用がどう変わるかはこの版では直接測っていない。
- Agent Reportsは設計上評価可能な方式が少なく、報告生成パイプライン自体も著者構築である。元文書を直接読む方式との比較ではなく、同じ報告文を密に入力処理した天井との比較である。
- 同一実行基盤の遅延比較は同じ推論エンジンを共有できる方式に限られ、異なるエンジンの方式を横断した絶対遅延順位は提供しない。
- チェックポイント横断試験は構造、トークナイザ、RoPE基準が一致する場合だけで、異なるモデル構造間のKV受け渡しは対象外である。
## 実装状態
公開評価基盤あり。論文は `pip install kvsharearena` で導入できるパッケージ、固定済み問い合わせ集合、方式提出の自動再採点、公開順位表、Agent Reports生成パイプラインを提供すると明記する。arXiv HTML変換ではリンク先が `[repo link]` 等の表示に置き換わっており、この確認では正確なGitHub URLを一次資料から復元できなかったため、未確認URLを推測して記載しない。
## 研究上の位置づけ
KVキャッシュ研究では、接頭辞キャッシュ、KVのメモリ階層移動、KV圧縮、異なる文脈へ持ち出したKVの修復がしばしば別々に評価される。KVShareArenaはこのうち文脈横断再利用を中心に、選択的再計算、注意機構較正、位置補正、学習済み修復、圧縮を同じ床・天井と費用尺度へ置く評価基盤である。結果は、単一情報源では位置補正がほぼ無料で十分だが、複数情報源の相互依存が強くなるほど有償修復が必要になるという境界を示す。さらにチェックポイント横断を追加し、保存済みKVをモデル更新後も資産として使えるかという運用上の問題へ評価軸を広げる。
