# RotateKV: Accurate and Robust 2-Bit KV Cache Quantization for LLMs via Outlier-Aware Adaptive Rotations

> RotateKVは、キー・バリュー（Key-Value; KV）キャッシュを2ビットへ落とす前に、外れ値が特定チャネルへ集中しないよう適応回転する。チャネル並べ替えと高速Walsh–Hadamard変換（Fast Walsh-Hadamard Transform; FWHT）を組み合わせる外れ値対応回転、回転位置埋め込み（Rotary Positional Embedding; RoPE）前のグループ化ヘッド回転、注意シンク保護の3機構を統合する。LLaMA-2-13BではWikiText-2のパープレキシティ悪化0.3未満、GSM8K低下1.7%未満を保ち、実装評価ではピークメモリ3.97倍削減、最大バッチ5.75倍、デコード2.32倍高速化を報告する。

## 概要

KVキャッシュの2ビット量子化が難しい主因は、値の分布が均一でないことにある。ごく少数のチャネルに巨大な外れ値が集中すると、同じ量子化スケールを共有する通常のグループ量子化では、その外れ値にレンジを合わせるため多数の通常値が粗く丸められる。

QuaRot/SpinQuant系の回転は特徴空間を直交変換して外れ値を分散できる。しかしKVキーにはRoPEが掛かり、ヘッドごと・層ごとに外れ値チャネルも違う。固定Hadamard回転だけでは、この分布差や位置回転後の再集中を十分抑えられない。

RotateKVは、まず各層の外れ値チャネルを並べ替えてからFWHTを適用し、回転を層の分布に適応させる。さらにキー側はRoPE前に複数ヘッドをまとめて回転し、位置回転で量子化しにくい外れ値が再出現するのを抑える。最後に、注意シンクとなる特殊トークンは高精度のまま保護する。

## 問題設定

低ビットKV量子化では平均ビット数だけ下げても、少数のFP16外れ値を大量に残せば実圧縮率は上がらない。逆に例外をほとんど残さない2ビット量子化では、外れ値誤差が注意スコアへ増幅され、パープレキシティや長文検索・推論が崩れやすい。

特にキーはQK内積を直接変えるため外れ値誤差に敏感で、RoPEがチャネルを混ぜることで校正時の分布と実際に量子化する分布が変化する。また冒頭トークンなど注意シンクは非常に大きい活性を持ち、通常トークンと同じ2ビット格子へ入れると誤差が大きい。

RotateKVは「大半のKVを本当に2ビットへ落とす」ため、分布平滑化と例外保護の役割を分ける。

## 手法

### 1. 外れ値対応回転：並べ替え後にFWHTを掛ける

校正データから各層・チャネルの外れ値分布を観測し、外れ値が回転グループへ均等に分散するようチャネル順序を並べ替える。その後、FWHTで高速な直交回転を行う。

入力は元のK/V投影出力、処理はオフラインで決めた並べ替え＋Hadamard回転、出力は外れ値が多数チャネルへ平準化された表現である。回転行列を完全に自由学習する方式より、FWHTの高速性を残すのが狙いである。

### 2. キーはRoPE前にグループ化ヘッド回転する

RoPEはキーのチャネル対を位置依存で回転するため、RoPE後に単純な回転を置くと位置処理との干渉が生じる。RotateKVはキーをRoPE前で回転し、複数ヘッドのチャネルをまとめて平滑化する。

グループ化ヘッド回転により、単一ヘッド内だけでは逃がしにくい外れ値をヘッド方向にも分散する。これにより量子化スケールへ入る最大値を下げ、2ビットでも通常値の分解能を確保する。

### 3. 注意シンクだけを明示的に高精度保護する

注意シンクは多くの生成ステップから強く参照され、KV活性も巨大になりやすい。これを2ビットへ押し込むと、少数トークンの誤差が全生成へ波及する。

RotateKVは巨大活性と注意パターンからシンクを特定し、そこだけを高精度で保持する。重要なのは、幅広い「外れ値全部」をFP16へ逃がすのではなく、機能的に重要なシンクへ例外を限定することで平均ビット幅を低く保つ点である。

### 4. 回転を投影重みへ融合して実行時費用を抑える

チャネル並べ替えや回転の一部はK/V投影重みへ事前融合できる。実行時に巨大な追加行列積を毎トークン挿入するのではなく、既存投影とFWHT中心で処理する。

したがって品質改善だけでなく、低ビットKVによるメモリ帯域削減をデコード速度へ変換できる。公式実装はシミュレーション評価コードを公開している。

## 評価

### 評価条件と代表結果

| 観点 | 条件/結果 |
|---|---|
| 品質モデル例 | LLaMA-2-13B |
| 言語モデル品質 | WikiText-2、2-bitでパープレキシティ悪化0.3未満 |
| 推論 | GSM8K、精度低下1.7%未満 |
| 長文 | 長文脈能力も評価し、既存低ビットKV法より堅牢と報告 |
| 実装評価例 | LLaMA-2-7B、8×NVIDIA RTX 4090D |
| ピークメモリ | 3.97倍削減 |
| 最大バッチ | 5.75倍へ拡大 |
| デコード | 2.32倍高速化 |

### 各機構が必要な理由

固定回転だけでは層・チャネルごとの外れ値偏りが残る。外れ値対応並べ替えはこの偏りを均す。RoPE前グループ化ヘッド回転はキー側に特有の位置回転問題を抑える。注意シンク保護は、残った少数の巨大・重要トークンを低ビット誤差から守る。

この三つは同じ問題を重複して解くのではなく、チャネル外れ値、RoPE/ヘッド構造、特殊トークンという異なる誤差源を担当する。

### 結果の読み方

3.97倍メモリ削減は理想的なFP16→2bitの8倍より小さい。スケール、メタデータ、保護トークン、高精度部分など実装オーバーヘッドが残るためである。したがって「2ビット」という名目だけから8倍の実メモリ削減を期待すべきではない。

デコード2.32倍もメモリ帯域・バッチ・カーネル形状に依存する。プリフィルは大きなGEMM比率が高く、KV読み出し削減が同じ倍率で効くわけではない。

## 既存研究との差

KIVIなどはチャネル/トークンごとの量子化粒度を工夫し、重要な外れ値を高精度へ残す。RotateKVは量子化前に特徴空間を回転し、外れ値自体を分散して2ビット格子へ入りやすくする。

QuaRot/SpinQuant型の回転との差は、チャネル並べ替えで回転を層ごとの外れ値分布へ適応させ、KVキーのRoPE前・ヘッド間構造まで扱う点にある。さらに注意シンク保護を組み込み、長文推論で重要な例外を明示的に残す。

## 限界・実装状況

- 完全な2ビット一様表現ではなく、注意シンクなど一部は高精度保持する。
- 回転・並べ替えは校正分布に依存し、モデル変更時には再校正が必要。
- 実速度は低ビットKV対応カーネルとメモリ帯域に依存し、名目圧縮率がそのまま速度倍率にはならない。
- 報告された2.32倍デコード速度、5.75倍バッチは特定GPU/モデル条件の最大値。
- 公式コードは https://github.com/ZunhaiSu/RotateKV で公開されている。

## 一般的な実装上の含意

2ビットKV量子化では、量子化器そのものより前処理後の外れ値分布を確認すべきである。最大値の少数チャネル集中が残ると、グループサイズを細かくするしかなく、スケールメタデータが増えて実圧縮率を落とす。

また、キーと値を同じ方式で扱わず、RoPEと注意スコアへの感度を分けて設計する方がよい。長文では注意シンクの保護も平均指標以上に重要になる。
