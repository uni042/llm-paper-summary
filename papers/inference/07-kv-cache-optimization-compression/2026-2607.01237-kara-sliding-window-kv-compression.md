# KARA: Efficient Reasoning LLM Serving via Sliding-Window KV Cache Compression

> 長いchain-of-thoughtでdecode中に増え続けるKVを、cache全体の閾値到達ごとに何度も圧縮するのではなく、新しく生成された区間だけを周期的に圧縮する。

## 問題設定

Reasoning modelは長い出力を生成するためdecode中のKV cacheが大きくなり、batch concurrencyとthroughputを制限する。既存のthreshold-triggered圧縮ではcache長が閾値に達するたびに大きな領域を再処理し、batchが大きい条件では圧縮頻度が増えてthroughput改善を打ち消すことがある。またtoken単体や固定chunkだけを残す方式では、意味的にまとまった可変長区間を保持しにくい。

## 手法

### 1. Sliding-windowで新規KVだけを圧縮する

KARAは直近に生成されたwindowだけを圧縮対象とする。既に処理済みの古い領域を何度も再圧縮しないため、sequenceが長くなっても1回あたりのcompression workを限定できる。

### 2. Bidirectional attentionでwindow内の重要tokenを選ぶ

圧縮対象window内部で双方向に情報を見て重要tokenをscoreする。通常のcausal generationそのものを双方向へ変えるのではなく、**どのKVを残すかを決めるcompression stage**でwindow全体の関係を使う。

### 3. Token2Chunkで可変長の意味区間を残す

重要tokenを孤立した1 tokenとして残すだけでなく、その周辺へ範囲を拡張して可変長chunkとして保持する。固定chunk境界に重要情報がまたがる場合でも、必要部分をまとめて残しやすくする。

### 4. KvLLMとしてPagedAttentionへ統合する

vLLM上のKvLLMではglobal decoding-step counterを使い、一定間隔で圧縮対象sequenceを選ぶ。PagedAttention blockとwindow進行を合わせ、未圧縮の新規領域を順番に処理することでbatch sizeに圧縮頻度が強く引きずられる問題を避ける。

## 評価

Qwen3-14B等のreasoning modelで数学reasoningとserving効率を評価する。論文はKARA/KvLLMが既存KV compression方式に対し、品質を保ちながらKV memoryを減らしoutput throughputを改善すると報告する。MATH-500ではQwen3-14Bで **30% retention** でもfull KVに近いaccuracyを維持する条件を示す。

本研究の中心は「圧縮率だけ」ではなく、実際のPagedAttention servingでcompression処理がthroughputを食わないようにする点にある。

## 既存研究との差

従来のthreshold-triggered方式がcache全体の長さを基準に圧縮を発火するのに対し、KARAは**時間方向にwindowを進め、新しく生成されたKVだけを処理する**。また重要token単体ではなくToken2Chunkで可変長の周辺文脈を残す。

## 限界

- KV evictionを行う近似方式であり、retention ratioを下げすぎるとreasoning品質が低下し得る。
- bidirectional scoringとToken2Chunk自体にも計算overheadがあり、短出力では利得が小さい可能性がある。
- reasoning modelの長decodeを主対象とし、短いchat workloadでの優位性は限定的。
- vLLM/PagedAttention統合を前提にした実装上の工夫が多く、他runtimeでは再実装が必要。

## 一般的な実装上の含意

Online KV compressionでは「どれだけ削れるか」だけでなく、**圧縮処理そのものを何回、どの範囲へ実行するか**がthroughputを左右する。長decodeでは処理済みKVを再走査せず、増分領域だけを一定量ずつ処理する設計が重要になる。
