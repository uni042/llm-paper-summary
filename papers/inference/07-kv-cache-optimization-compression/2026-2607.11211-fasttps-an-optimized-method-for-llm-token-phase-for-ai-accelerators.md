# FastTPS: An Optimized Method for LLM Token Phase for AI accelerators

> トークン生成段階のKV連結を静的キャッシュへの直接書き込みで消し、注意とMLPを深く融合して演算強度を上げるデータフロー最適化。NPU実機で最大6.0倍の高速化と帯域利用率93パーセントを達成。

## 概要

デコーダ型LLMの推論は、入力をまとめて処理するプリフィル段階と、自己回帰的に1トークンずつ生成するトークン段階（論文のいう token phase）に分かれる。トークン段階はバッチも系列長も実質1であり、行列積の並列度がほぼ消えるため、計算そのものよりメモリ帯域が律速になる。標準実装ではさらに、生成のたびに新しいキーと値を過去のKVキャッシュへ連結する処理が入り、キャッシュ全体の読み直しと書き戻しが発生する。注意ブロックとMLPブロックの各演算子も、その都度最下層キャッシュとの間で入出力を往復させる。

FastTPSは、この帯域浪費を3つの仕組みで断つ。第1のGKVCは、最大系列長分を事前に確保した静的な3次元KVキャッシュへ、新しいキーと値をアドレス計算で直接書き込む方式で、連結演算子そのものを消し、処理全体をアクセラレータ上に留める。第2のTPSFLATは、回転位置埋め込み（RoPE）を含む注意計算を、ヘッド方向へタイル化してオンチップキャッシュ内で連続実行する融合データフローである。第3のFusion MLPは、ゲート射影とアップ射影の重みをタイル単位で交互に並べ替え、活性化と要素積までを1つの大きな行列積へ融合する。代表結果として、AMD Ryzen AI 300シリーズNPU上のPhi3-mini-4k-instructで、融合なしの標準実装と比べて6.0倍の高速化とピークメモリ帯域利用率93パーセントを達成し、注意ブロック単体では最大13.07倍、MLPブロック単体では最大3.14倍の高速化が報告されている。数値誤差は最大でも0.22パーセント未満に収まる。

## 問題設定

トークン段階の非効率は、演算強度（Operational Intensity; OI、メモリアクセスあたりの演算量）の低さとして表れる。トークン段階ではバッチと新規トークン数がともに1のため、重みとKVキャッシュを読み出す量に対して実行できる演算が少なく、ルーフライン上の性能は帯域側の天井で決まる。ここへ標準実装の2つの無駄が重なる。1つはKVキャッシュの連結で、これは演算を一切含まない純粋なメモリ再編成でありながら、系列が伸びるほど読み書き量が増え、注意ブロックの遅延の66から82パーセントを占めるまでになる。もう1つは演算子単位の実行で、RoPE、転置、行列積、ソフトマックスなどが個別カーネルとして最下層キャッシュと往復し、同期点がその都度発生する。さらに連結処理はCPU側が担うことが多く、アクセラレータ側の連続実行が断たれて細粒度のスケジューリングができない。MLP側も事情は同じで、パラメータの約3分の2を占めるにもかかわらず、新規トークン数が1のため行列積ユニットが遊び、重みの読み出しが支配的になる。本論文は、計算を近似するのではなく、メモリ再編成を消し、同期点をオンチップ側へ寄せることで演算強度そのものを引き上げる。

## 手法のあらまし

まずGKVCが、推論開始時に最大系列長までのKVキャッシュ領域を静的に確保する。新しいトークンのキーと値は、バッチとヘッドの位置から決まるアドレスへ飛びながら直接書き込まれ、過去分の読み直しや連結は発生しない。次にTPSFLATが、ヘッド方向の2階層タイル化のもとで、クエリとキーへのRoPE適用、キャッシュへの書き込み、クエリとキーの積、ソフトマックス、値との積までをオンチップキャッシュ内で連続実行し、書き戻すのはキャッシュ更新分だけにする。最後にFusion MLPが、ゲートとアップの重みタイルを交互配置した大きな重み行列を用意し、2つの射影とSiLUと要素積を細粒度パイプラインで融合実行してから、ダウン射影で元の次元へ戻す。3つとも計算結果を変えない変換であり、精度を犠牲にせず帯域を取り戻す設計になっている。

## 手法

### 1. GKVC — 連結を消す静的KVキャッシュ管理

GKVC（Global KV Cache management）が観測するのは、各ステップで生まれる新しいキーと値の書き込み先である。通常の連結方式では、過去分と新規分を読み出して並べ直し、全体を書き戻すため、系列長に比例する転送が毎ステップ発生する。GKVCは代わりに、バッチ数、ヘッド数、ヘッド次元が決まれば最大系列長が定まることを利用し、キャッシュ領域を最初に静的に確保する。書き込みは、ヘッドごとに決まるストライドでアドレスを飛びながら、確保済み領域の空き位置へ新しいベクトルを直接置く。読み手である注意計算は、埋まった分だけをそのまま参照できる。効果は3つある。連結の読み書きが消えること、連結を担っていたCPUとの同期が消えて推論全体がアクセラレータ上に留まること、そして後段の演算子融合が連続したデータフローの上で設計できることである。代償は、最大系列長分の領域を常に確保することと、アドレス計算に合ったレイアウトを前提にすることである。系列長が上限へ近づくほど連結方式との差は開く一方、上限を超える系列には別途の対処が要る。

### 2. TPSFLAT — RoPEまで含めた注意の融合データフロー

TPSFLATは、ソフトマックスの正規化方向に沿って計算を分割できるというFLATの考え方を、トークン段階へ特化させたものである。トークン段階ではバッチと新規トークン数が1なので、分割軸はヘッド方向だけに整理できる。処理は2階層のタイル化で行われる。外側のループがヘッド群を下層から中間キャッシュへ運び、内側のループがヘッド単位で最上位キャッシュへ載せ、クエリとキーを1つの連続テンソルとしてまとめてRoPEを1回だけ適用する。正弦と余弦のテーブルも共有されるため、演算子呼び出し自体が減る。続いて新しいキーをGKVCでキャッシュへ書き込み、キャッシュ済みキーとの積、ソフトマックス、値との積までを最上位キャッシュの中で連続実行する。書き戻されるのはキャッシュ更新分だけで、中間テンソルは階層間を往復しない。なぜ効くかというと、同期点が最下層キャッシュから最上位キャッシュへ移り、1回のロードで4つのカーネルを連続実行できるため、演算強度が約3倍へ上がるからである。失敗条件は、ヘッド次元やキャッシュ容量の異なるハードウェアではタイル形状の再調整が要ることで、論文もタイル設定はアクセラレータ依存としている。

### 3. Fusion MLP — 重みの交互配置によるMLP融合とパイプライン

MLPブロックでは、重みの読み出しが支配的な費用である。Fusion MLPの第1の工夫はレイアウトである。ゲート重みとアップ重みを、中間次元の方向へ半タイルずつに割って交互に並べ替え、1つの大きな重み行列として用意する。第2の工夫は融合で、この大きな行列積の直後にSiLUと要素積を続けて実行する複合演算子とし、中間結果の書き戻しを消す。これによりMLP全体の入出力回数は7回から2回へ減る。第3の工夫はパイプラインスケジューリングで、大きな行列積の内部で重みのロードと計算を重ね、重み転送の待ち時間を計算の裏へ隠す。入力側の比率が小さいモデルほど効果が大きいのは、削減されるのが主に入力と中間結果の往復であり、重みそのものの読み出しは残るためである。論文の近似式も、高速化率が中間次元と隠れ次元の比で決まることを示している。追加費用は、重みを事前に並べ替えるオフライン処理と、タイル寸法をハードウェアに合わせる調整である。

### 4. 1トークンの流れ — 3つの仕組みがどうつながるか

1トークンの処理を通して見ると、流れは次のようになる。まず入力トークンの隠れ状態からクエリ、キー、値が作られ、値はそのまま静的キャッシュの所定位置へ書き込まれる。次にヘッド群がタイル単位でオンチップへ運ばれ、クエリとキーへの回転位置埋め込み、新しいキーのキャッシュ書き込み、キャッシュ全体との内積、ソフトマックス、値との加重和が途切れずに続く。注意の出力は整流を経てMLPへ渡り、交互配置された大きな重み行列との積、活性化と要素積、ダウン射影を経て次の層の入力になる。標準実装ではこの間に十数回の階層間往復と1回の連結が挟まっていたが、提案方式では書き戻しはキャッシュ更新とMLP中間結果など最小限に絞られる。帯域の観点では、読み出しの中心が「過去のキャッシュ全体の読み直し」から「重みと必要なキャッシュ範囲の読み出し」へ移ることが本質であり、系列が伸びても1ステップあたりの転送量の増え方が緩やかになる。

| GKVC | 新しいキーと値、ヘッド位置 | 静的確保した領域へアドレスジャンプで直接書き込む | 連結の読み書きとCPU同期 | 最大系列長分の領域を常時確保 |
| TPSFLAT | クエリ、キー、値とキャッシュ | ヘッド方向タイル化でRoPEから値との積までをオンチップ融合 | 階層間往復と同期点 | タイル形状がハードウェア依存 |
| Fusion MLP | ゲートとアップの重みタイル | 交互配置した大きな行列積へ活性化と要素積を融合しパイプライン実行 | 入出力回数と重み待ち時間 | 重みの事前並べ替えが必要 |

## 評価

### まず見るところ

- **結論:** トークン段階の支配的費用であるKV連結と階層間往復を取り除くことで、精度を保ったまま帯域利用率を理論上限近くまで引き上げられる。
- **速度・効率:** モデル全体ではLlama3.2-1Bで2.64倍、Llama2-7Bで5.30倍、Phi3-mini-4k-instructで5.95倍（要旨では6倍と総括）の高速化。帯域利用率は平均86パーセント、Phi3で93パーセントに達する。
- **品質:** 近似ではなく再編成の最適化であり、BF16シミュレーションの最大誤差は0.22パーセント未満。FlashAttentionの誤差水準の約10分の1とされる。
- **評価の強さ／注意点:** 実機はAMDのNPU単体で、CPUオーバーヘッドは計測から除かれている。プリフィル段階は対象外である。

**数値の読み方。** 注意ブロックの遅延削減は最大で93パーセント（Llama3、系列長4096）に達するが、その大半は連結の除去によるもので、計算部分の削減は40から64パーセントである。つまり倍率の大きさは系列長とともに育つ性質を持ち、短い系列では小さい。MLP側の改善が20から68パーセントにとどまるのは、重み読み出しという消せない費用が残るためであり、2つのブロックで改善の天井が違う。

## 既存研究との差

FlashAttention系は注意計算の入出力を意識した融合で帯域を節約するが、低精度化に伴う数値誤差や補助処理が残る。FLATは注意のデータフロー最適化の原型だが、トークン段階のKVキャッシュ管理やMLPまで含めた設計ではない。本論文の差分は、連結というメモリ再編成そのものを静的レイアウトで消したこと、RoPEを含む注意融合をトークン段階の形状に合わせて再設計したこと、そしてパラメータの大半を占めるMLPへ重みの交互配置というレイアウト側の工夫を持ち込んだことにある。量子化や枝刈りとは競合せず、併用可能な層の最適化として位置づけられる。

## 限界・実装状況

対象はトークン段階のみで、プリフィル段階の最適化は含まない。評価はAMDのNPU単体であり、タイル寸法やキャッシュ階層の前提が異なるハードウェアでは再調整が必要になる。CPUオーバーヘッドを除いた計測である点も、実利用の遅延とずれる可能性がある。静的キャッシュは最大系列長を事前に決める必要があり、それを超える文脈への扱いは示されていない。実装はAMD向けの最適化として記述され、論文中に公式コードの公開先は示されていない。

## 一般的な実装上の含意

帯域律速の段階では、演算の近似より先に「演算を含まない転送」を数えるべきである。連結や並べ替えのような再編成演算子は、プロファイル上は小さく見えても系列長とともに支配的になる。また、融合の効果は同期点をどのキャッシュ階層へ移せるかで決まる。レイアウトを事前に組み替えることで実行時の融合可能性が広がる点は、MLPに限らず重み配置全般へ応用できる。
