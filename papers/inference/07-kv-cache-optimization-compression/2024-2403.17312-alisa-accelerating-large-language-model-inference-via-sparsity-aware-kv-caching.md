# ALISA: Accelerating Large Language Model Inference via Sparsity-Aware KV Caching

> ALISAは、すべての過去トークンのKVを同じように保存・参照するのではなく、直近トークンと過去に重要だったトークンを選んで注意機構対象を減らす。そのうえで系列が伸びるにつれ、KVをGPUだけに保持する段階、CPUへ一部退避する段階、古いKVを保存せず必要時に再計算する段階へ切り替え、容量・PCIe転送・再計算の合計時間を抑える。

## 概要
KVキャッシュは過去トークンのK/Vを再利用することで、自己回帰デコードで過去系列全体を毎回計算し直す必要をなくす。一方、KV容量はバッチサイズと系列長に比例して増えるため、単一GPUでは長い系列や大きいバッチでVRAMを圧迫する。CPUへ退避すれば容量は増やせるが、今度はPCIeを介したKVの読み戻しが遅延になる。

ALISAはこの問題を、(1) 注意機構で参照するKVそのものを疎にする、(2) 残したKVの保存先と再計算を系列長に応じて変える、(3) KVをINT8へ量子化して1トークン当たりの容量と転送量を減らす、というアルゴリズム／システム協調設計で扱う。

重要なのは、単に「古いKVを削除する」方式ではないことである。どのトークンを注意機構対象へ残すかと、残したKVをGPU・CPU・再計算のどれで供給するかを別々に最適化するため、精度とI/Oのトレードオフを段階的に制御できる。

## 問題設定
すべてのKVをGPUに置ける間はGPUキャッシュが最も単純で速い。しかし系列が伸びてVRAMを超えると、KVをCPUメモリへ移し、注意機構で必要になるたびGPUへ読み戻す必要が出る。論文のプロファイルでは、KVをCPUへ50%置くだけでも実行時間が約3倍、全量をCPUへ置くと約5倍になる条件があり、容量問題をI/O問題へ置き換えるだけでは十分でない。

一方、KVを保存せず再計算する方式はGPU計算量を増やすが、系列が十分長くなりCPU→GPU転送が大きくなると、古いKVをPCIeから読むよりGPU上で作り直す方が速い領域が生じる。したがって最適方針は系列全体で固定ではなく、生成進行とともに変わる。

ALISAはこの変化を利用し、系列長を状態変数として3段階の方針を切り替える。さらに注意機構を疎にして必要KV数を先に減らすことで、GPUだけで処理できる期間を延ばし、CPU退避・再計算へ移る時点も後ろへずらす。

## 手法

### 1. 疎窓Attentionで「直近」と「過去の重要トークン」を半分ずつ残す
疎窓注意機構（疎 Window 注意機構; SWA）の入力は、現在のクエリ、過去のK/V、直近の注意機構重み、保持率 `r`、現在系列長 `n` である。まず保持する総トークン数 `nr` を決め、その半分を直近トークン、残り半分を過去の重要トークンへ割り当てる。

直近側は、現在位置から最も近い `k` トークンを無条件に残す。これは文法・局所的な語順など、直前文脈への依存を確実に保持するためで、論文では局所固定（locally 静的）パターンと呼ぶ。

過去側は、直近複数ステップで得られた注意機構重みをトークンごとに合計し、その値が大きい上位 `k` トークンを残す。特定の固定位置を残すのではなく、生成が進むたび重要度が変わるため、論文では大域動的（globally 動的）パターンと呼ぶ。直近数ステップの注意機構を使うことで、1ステップだけの偶然な重みより安定した重要度を得る。

最終的に直近集合と過去重要集合を連結し、そのインデックスに対応するK/Vだけで注意機構を計算する。予測が外れて重要トークンを除外すると注意機構出力自体が変わるため、この部分は損失なし最適化ではない。保持率を下げるほどKV容量・計算は減るが、品質低下リスクは増える。

### 2. 系列長に応じてGPU保持→CPU併用→再計算へ切り替える
ALISAの動的スケジューラは、GPU容量、CPU容量、CPU-GPU帯域、系列長、2つの切替点 `p1/p2`、CPU退避割合 `α`、再計算割合 `β` を入力として使う。出力は、各生成ステップでどのトークンのKVをGPUへ残し、どれをCPUへ置き、どれを破棄して後で再計算するかという配置方針である。

第1段階では、疎化後のKV全体がVRAMへ収まるため、すべてGPUに保持する。CPUとの転送は行わず、通常のGPU KVキャッシュに近い状態で動く。この段階では再計算を入れる利点もないため、容量に余裕がある間は最も単純なGPU保持を選ぶ。

系列が `p1` を超えVRAMだけでは不足する第2段階では、KVをトークン単位でGPUとCPUへ分ける。大域動的集合は生成ステップごとに変わり将来参照位置を予言しにくいため、ALISAは直近固定トークンのKVをGPUへ優先して残し、それ以前のKVをCPU側へ退避する。必要時にはCPUからGPUへ戻して注意機構へ渡す。

さらに系列が `p2` を超える第3段階では、CPUに置いた最古KVの一部を削除し、必要になった場合にGPUで再計算する。ここではPCIeから読み戻す時間と、対応するK/Vを再計算する時間を比較し、転送より計算の方が安くなる領域を再計算へ置き換える。つまり再計算は常時使うのではなく、I/Oが十分重くなった後にだけ使う。

### 3. 切替点と退避・再計算割合を合計実行時間から決める
`p1` は主にKV容量がGPU容量へ達する時点から決まり、`p2` はCPUからKVを読み戻す時間とGPU再計算時間の関係から決まる。KVサイズはモデルの層数・隠れ次元・バッチサイズ・保持率で変わり、転送時間はCPU-GPU帯域に依存するため、同じ固定値をすべてのモデル・GPUへ使わない。

論文は各ステップのキャッシュ転送時間と再計算時間を数式化し、総生成時間が小さくなるよう退避割合 `α` と再計算割合 `β` を選ぶ。保持率を高くすると品質は保ちやすいがKV量が増え、`p1/p2` が早く訪れる。保持率を下げるとKVは減るが注意機構近似が強くなるため、品質制約と実行時間の両方を見る必要がある。

この設計の意味は「VRAMが足りなくなったらCPUへ退避」という1回の判断ではなく、生成が進むにつれて**容量律速→PCIe律速→再計算有利**へボトルネックが移ることを明示的に扱う点にある。ハードウェア帯域が変われば切替点も変わるので、20 GB/s程度の評価環境より高速な接続ではCPU保持期間が長くなる可能性がある。

### 4. INT8 KV量子化で容量と転送量をさらに半減する
ALISAはSWAと動的配置に加え、K/VをFP16からINT8へ量子化して保存する。対象はモデル重みではなく生成中に増えるKVキャッシュであり、目的はVRAM／CPUメモリ使用量とCPU-GPU転送バイト数を減らすことである。

KVサイズが小さくなると、同じ保持率でも第1段階でGPUだけに置ける系列長が伸び、第2段階で必要なPCIe転送量も減る。つまり量子化単独のメモリ節約だけでなく、3段階スケジューラの切替時点と転送コストにも効く。

一方、量子化・逆量子化の計算と数値誤差が増えるため、SWAによる近似と合わせた品質評価が必要になる。ALISAの主設定はSWA 80%疎化とKV INT8を含むため、性能値を「KV内容を一切変えない損失なしキャッシュ管理」の結果として解釈してはいけない。

## なぜこの設計で速くなるのか
SWAで注意機構対象のKV数を減らすと、GPU内のKVアクセス量と保存容量が減る。その結果、同じVRAMでもより長い系列・大きいバッチを保持でき、CPU退避が必要になる時点を遅らせられる。

それでも系列が伸びた場合は、CPU退避と再計算のどちらが安いかを区間ごとに切り替える。CPUアクセスがまだ安い間は計算を繰り返さずKVを保存し、PCIe読み戻しが重くなった後だけ古いKVを再計算へ変えるため、固定方式より不要なI/Oと不要な再計算の両方を減らせる。

## 評価条件
7B/13B級ではNVIDIA V100 16/32 GB、30BではNVIDIA H100 80 GBを使用し、CPUはIntel Xeon 2.60 GHz、ホストメモリ128 GB、CPU-GPU帯域20 GB/sとしている。モデルはOPT / LLaMA / Pythia、システム評価の代表負荷はAlpaca、入力128・出力512、バッチ4～64である。

比較対象はDeepSpeed-ZeRO、HuggingFace Accelerate、FlexGen、vLLM。システム評価ではモデル重み・活性値は主にGPUへ置き、KV管理方式の違いを中心に比較する。

## 主要結果
80% KV疎化を主設定としたエンドツーエンド評価で、FlexGen比**1.4～3.0倍**、vLLM比最大**1.9倍**のスループットを報告する。再計算だけのアブレーションでは、第3段階でCPUアクセスを再計算へ置き換えることで総実行時間を約1.2～1.3倍改善している。

品質評価では80%疎化でも多くのモデル／タスクで密 注意機構からの低下を5%以内に保ち、Alpacaでは約3%の低下とする。ただし「平均的に小さい低下」であって損失なしではなく、重要トークン選択が外れるタスクでは差が大きくなる可能性がある。

## 限界
SWAは注意機構対象を削るため損失なしではない。直近注意機構の累積が将来重要度を十分表さない場合、遠距離依存に必要なトークンを落とす可能性がある。品質制約が厳しい用途では保持率を高める必要があり、その分メモリ・I/O利得は小さくなる。

3段階の切替点と `α/β` はモデル、バッチサイズ、KV保持率、VRAM容量、CPU-GPU帯域へ依存する。主評価は単一GPU-CPU構成かつ20 GB/s程度のホスト接続であり、NVLink-C2Cや高速共有メモリ構成では「CPUから読むより再計算が速い」境界が変わる。

モデル重みのCPU/NVMeオフロード自体は主要評価対象ではないため、モデル重みもVRAMへ収まらない環境ではKVと重みがPCIe帯域を競合し、論文の最適比率をそのまま使えない可能性がある。

## 既存研究との差
FlexGenは重み・活性値・KVの階層配置と静的スケジュールを扱うが、KVの注意機構参照集合そのものは基本的に保持する。ALISAはまずトークン単位のSWAで参照KVを減らし、その疎KVをさらにGPU／CPU／再計算へ動的に割り当てる。

vLLM / PagedAttentionはKV内容を変えず、ブロック割当・共有でメモリの無駄を減らす。ALISAはメモリ配置効率ではなく、保持トークン数とI/O量自体を減らす近似方式なので、同じ「KVキャッシュ最適化」でも品質特性が異なる。

## 一般的な実装上の含意
KVキャッシュ管理を生成全体で固定せず、系列長と現在のハードウェアコストによって「GPU保持」「CPU退避」「再計算」を切り替える設計は、KVが時間とともに成長するLLMに適している。特に再計算は常に悪いわけではなく、外部メモリI/Oが十分遅ければ計算の方が安くなる。

また疎化・量子化・階層配置・再計算は独立な最適化ではない。疎化率や量子化でKVサイズを変えると、GPUが満杯になる時点もCPU転送と再計算の損益分岐点も変わるため、同じランタイム費用モデルでまとめて評価する必要がある。
