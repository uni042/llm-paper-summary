# ALISA: Accelerating Large Language Model Inference via Sparsity-Aware KV Caching

> attentionで重要な過去tokenだけを参照し、sequenceが伸びるにつれてKVをGPU保持・CPU退避・GPU再計算へ切り替えることで、KV容量とPCIe転送を減らす手法。

## 概要
ALISAは、長sequenceで増え続けるKV cacheを単にGPU/CPUへ置き分けるだけでなく、**attentionで重要なtokenを選んで参照KV自体を減らし、残ったKVについてもGPU保持・CPU offload・再計算を状況に応じて切り替える**研究である。手法は、直近tokenと過去にattentionが強かったtokenを残して参照KV数を減らす段階と、sequence進行に応じてGPU保持・GPU+CPU分散・再計算を切り替える段階からなる。さらにKVをINT8へ量子化してmemory trafficを減らす。

## 問題設定
KV cacheをすべてGPUへ保持できればdecodeは速いが、batch sizeとsequence lengthに比例してVRAMを消費する。CPUへoffloadすれば容量問題は緩和できるが、PCIe経由でKVを戻す待ち時間が新しいbottleneckになる。またsequenceが短い時点ではGPU cachingが最速でも、長くなるとCPU memoryへ追い出す必要が生じ、さらに長くなるとCPUから古いKVを読み戻す時間が、必要時にGPUで再計算する時間より長くなる領域がある。

## 手法
### Sparse Window Attention
ALISAはattention weightの偏りを利用し、直近token（locally static）と過去の高attention token（globally dynamic）を残す。単純なsliding windowより長距離情報を保ちながらattentionへ渡すKV数を減らす。

### 3段階のKV scheduling
Phase IではKV全体がVRAMへ収まる間はGPUへ保持する。Phase IIではVRAM超過後に一部tokenのKVをCPU DRAMへoffloadする。Phase IIIではさらにsequenceが伸びると一部の古いKVを保存せず、必要時にGPUで再計算する。phase切替位置、offload割合、recompute割合はmodel・batch・CPU-GPU bandwidthから合計実行時間が短くなる組合せを選ぶ。

### INT8 KV compression
FP16 KVをINT8へ量子化し、cache容量とtransfer byteを追加削減する。これはmodel weight quantizationではなくKV cacheの保存量とmemory accessを軽くする目的で使う。

## 評価条件
- GPU: 7B/13BはNVIDIA V100 16/32GB、30BはNVIDIA H100 80GB
- CPU: Intel Xeon 2.60GHz、host memory 128GB、CPU-GPU bandwidth 20GB/s
- Model family: OPT / LLaMA / Pythia
- System workload: Alpaca、input 128 / output 512、batch 4〜64
- Baseline: DeepSpeed-ZeRO、HF Accelerate、FlexGen、vLLM
- system評価ではmodel weightとactivationはGPUへ置き、KV managementを主に比較

## 主要結果
80% KV sparsityを主設定としたend-to-end評価で、FlexGen比1.4〜3.0倍、vLLM比最大1.9倍のthroughputを報告する。accuracy評価では80% sparsityでも多くのmodel/taskでdense attentionからの低下を5%以内に保ち、Alpacaでは約3%の低下としている。ただしlosslessではない。

## 限界
- sparse attentionを使うためlosslessではなく、task/modelによってaccuracy低下が変わる。
- 重要token選択がattention需要と合わない場合、必要な長距離情報を落とす可能性がある。
- phase切替やoffload/recompute比率はhardware・model・batch sizeへ依存する。
- H100評価も含むがhost-GPU bandwidth 20GB/sのsingle GPU-CPU構成が中心で、高速interconnectでは最適分担が変わる。
- model weight offload自体は主評価対象ではない。
- 2026-09-08時点で独立した公式code repositoryは確認できなかった。

## 既存研究との差
FlexGenはweight / activation / KVの階層配置とscheduleを最適化するが、KVの中身自体は基本的に保持する。ALISAは参照すべきKVを減らし、sequence進行に応じて保存先とrecomputationをtoken単位で変える。vLLMはPagedAttentionでKV memory割当の無駄を減らすのに対し、ALISAはtoken-level sparsityとCPU offload / recomputationまで含めてKVの総量・I/Oを減らす。

## 一般的な実装上の含意
KV cache managementをsequence全体で固定したpolicyにせず、短いsequenceではGPU cache、memory pressureが上がればCPU offload、I/Oがcomputeより高くなればrecomputeと切り替える設計が有効になり得る。cache量削減・compression・hierarchical memory・recomputationを同じruntime cost modelで比較することが重要である。
