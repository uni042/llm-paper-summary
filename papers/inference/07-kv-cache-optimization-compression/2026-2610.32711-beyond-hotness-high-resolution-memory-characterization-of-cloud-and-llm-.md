# Beyond Hotness: High-Resolution Memory Characterization of Cloud and LLM Workloads for Tiered Memory with ARM SPE

> プロセッサのサンプリング拡張でLLM推論を含む8ワークロードのメモリ挙動を細かく測り、遅延の集中とアイドル期間で階層メモリへの適性を判定した計測研究。

## 概要

データセンターのメモリは、容量の需要が増え続ける一方で価格も重い。そこで、速いが高価な層と、遅いが大容量で安い層を組み合わせる階層メモリが現実解になっている。ただし階層が効くかどうかは、どのデータを速い層へ置き、どのデータを遅い層へ逃がすかの判断で決まる。その判断には、ワークロードがメモリをどう使うか、どの領域が何度触られ、どれだけの遅延を生み、どれだけの間触られないかを細かく知る必要がある。従来の計測は、カーネルがページテーブルを定期的に走査する方式が中心で、ページ単位の粗さ、短い区間の変化の取りこぼし、頻度の低いアクセスの欠落という弱さを持っていた。

本論文は、ARMプロセッサの統計プロファイリング拡張（SPE）を使い、命令のサンプリングでアドレス、遅延、データの出所までを記録する高解像度の計測手法を作った。対象はクラウド系とLLM系を合わせた8つのメモリ集約ワークロードで、LLM推論とLLM学習も含まれる。計測から得た知見の核は表題の通りで、アクセス回数で測る熱さだけでは階層への適性は分からない。遅延が少数の領域へ集中しているか、移行の作業を隠せる長いアイドル期間があるかが、実際に効く指標になる。

**代表結果:** 計測ツールの熱い領域の特定精度は3つの検証ベンチマーク全てで1.0を維持し、実行時の過負荷は多くの条件で0.6%未満、カーネル方式の1.5〜6.1%より小さかった。領域別の遅延集中では、インメモリ分析は遅延の50%がわずか0.7%の領域へ集中する一方、LLM推論は50%の遅延に27.7%の領域を要する分散型だった。指標に基づく実行時移行の実験では、適性が高いと判定されたワークロードで性能が上がり、LLM推論とメモリキャッシュ系では利益が出ず、後者では99パーセンタイル遅延が大きく悪化した。

## 問題設定

階層メモリの配置判断は、限られた速い層を誰に使わせるかの配分問題である。判断を誤れば、遅い層へ置かれた熱いデータが遅延を生み、速い層へ置かれた冷たいデータが容量を無駄にする。配分の入力になる計測には、時間方向と空間方向の両方の解像度が要る。実行の局面が速く切り替わるワークロードでは粗い時間解像度では局面を混ぜてしまい、ページ単位の空間解像度では領域の中の偏りが見えない。さらに、数十から数百のスレッドが走る環境では、スレッドごとの分離も必要になる。

もう1つの問題は、熱さという指標の素朴さである。アクセス回数が多い領域が、必ずしも遅延の主犯とは限らない。同時実行の競合で遅延の裾が伸びる領域もあれば、回数は多くてもキャッシュで吸収される領域もある。さらに、実行時にデータを移す方式では、移行の最中にその領域へ触られない時間が十分に長いかも成否を分ける。回数だけでは、この2つは測れない。本論文は計測基盤そのものと、配置判断のための指標の両方を作り直す研究である。

## 手法のあらまし

処理の流れは、サンプリング、相関付け、指標化の3段である。まず、プロセッサのサンプリング拡張で、一定間隔ごとに選ばれた命令を追跡し、メモリ命令については仮想アドレス、遅延、キャッシュやメモリのどの階層からデータが来たかを記録する。本研究では1次データキャッシュの読み込みミスを対象に、サンプリング間隔1024、バッファ1メガバイトで測る。記録はコアごとに分けて集め、スレッドをコアへ固定すればスレッド別の分析ができる。次に、データの出所情報をメモリ領域へ対応付け、領域ごとにアクセスの様式、階層の利用、遅延の分布、アイドル期間を集計する。最後に、遅延で重み付けした集中度と、最長のアイドル期間の割合という2つの指標で、速い層への配置と実行時移行の適性を判定する。検証として、アクセス様式が既知のベンチマークで正しさを確かめ、カーネルの走査型方式と精度と過負荷を比べている。

## 手法

### 1. サンプリング拡張による計測 — 命令単位で遅延と出所を取る

観測するのは、サンプリングで選ばれたメモリ命令の振る舞いである。サンプリング拡張は、設定した間隔で命令を選び、実行パイプラインを通して追跡し、キャッシュや変換バッファのイベント、データの出所、遅延の内訳を1つの記録として残す。保持する状態はコアごとの段階バッファで、スレッド間の同期を避けて拡張性を保つ。時間解像度は最も細かく200ミリ秒の窓まで、空間解像度はバイトアドレス単位まで届く。ツールは動的リンカの事前読み込みで対象プログラムへ透過的に差し込まれ、言語や枠組みを選ばない。イベントの絞り込みとサンプリング間隔が精度と過負荷の交換条件であり、間隔を広げれば過負荷は下がるが、短い局面や疎なアクセスを取りこぼしやすくなる。カーネルの走査型がページテーブルのアクセスビットを定期的に見るのに対し、こちらは命令そのものを標本にするため、走査の合間に繰り返し触られる様子や、頻度の低い領域の分布まで形が残る。

### 2. 階層利用の相関付け — どの領域がどの層で吸収されるか

サンプリング記録の出所情報を使い、各メモリ領域のアクセスが、1次・2次キャッシュ、共有の最終段キャッシュ、他のコアやクラスタ、主メモリのどこで処理されたかを対応付ける。これにより、領域ごとのアクセス様式と階層の効き方を結び付けて読める。論文の観測では、私有の2次キャッシュが最もよく使われる層であり、大きな私有2次を持つクラウド向け設計の妥当性を裏付けた。共有の最終段キャッシュは多くのワークロードで効くが、LLM推論ではほぼ使われていなかった。アクセス様式は、等間隔に進むストライド型、疎らに散るスパース型、短時間に領域へ集中するブロック型の3つへ整理され、LLM推論では広い範囲のブロック型と、KVキャッシュの再利用を反映した繰り返しの帯状パターンが観測されている。

### 3. 遅延で重み付けした集中度 — 熱さではなく実害で領域を順位付けする

配置の優先度を決める第1の指標は、領域ごとの主メモリアクセス遅延の分布である。アクセス回数で順位付けすると見かけの熱さに引きずられるため、本論文は遅延で重み付けした累積分布を作り、遅延全体の50%が何割の領域へ集中するかで適性を測る。集中が高いワークロードは、速い層へ置くべき領域が少数で済むため階層と相性が良い。逆に分散しているワークロードは、速い層の容量を広く食う割に効果が薄い。同じく熱い2つの領域でも、遅延の裾が2500サイクルまで伸びる領域と、300〜500サイクルへ収まる領域では優先度が違うという実測が、この指標の動機になっている。領域の大きさも併せて見て、小さくて遅延の裾が長い領域を先に速い層へ置く判断につなげる。

### 4. 最長アイドル期間 — 移行を隠せる時間があるかを測る

第2の指標は、各領域について、主メモリアクセスの記録が最も長く途切れた期間を実行時間全体で割った割合である。全アイドル時間の合計ではなく最長の連続期間を見るのは、実行時移行の作業を隠せるかどうかが、まとまった空白の長さで決まるためである。頻繁に触られる領域は、空白が細切れで移行と競合しやすい。この割合が30%を超える領域が多いワークロードは移行の候補になり、少ないワークロードは移行が干渉して逆効果になりやすい。サンプリングに基づく観測であるため、記録がない期間にアクセスが皆無だったことまでは保証しない点は、論文も注意している。

### 5. 指標で駆動する移行ランタイム — 判定を実地で試す

指標の有用性を示すため、計測を組み込んだ実行時移行の試作も評価している。ランタイムは一定間隔でサンプルを集め、最終段キャッシュのミスが多い上位の領域を選び、物理アドレスから現在の層を判定して、遅い層にあるものを速い層へ移す。1回の間隔で移せる量には上限を設け、移行はページ移行のシステムコールでまとめて行い、頻度は毎秒1回である。階層は2つのNUMAノードで疑似的に作り、帯域比1.8倍、容量比2倍という控えめな差の条件で試している。指標が適性を言い当てれば、集中度が高くアイドル期間の長いワークロードで性能が上がり、逆のワークロードでは上がらないか悪化するはずだ、という検証可能な形で実験が組まれている。

## 評価

### まず見るところ

- **結論:** 計測の解像度と指標の選び方で、階層メモリへの適性は事前にかなり判定できる。熱さだけの判断は不十分であり、遅延の集中とアイドル期間が実効的な指標になる。
- **速度・効率:** 提案は高速化手法そのものではなく計測と判定である。移行実験での性能変化はワークロード依存で、適性の高いものは改善し、LLM推論は改善せず、キャッシュ系は大きく悪化した。
- **品質:** 計測は対象の計算結果を変えない。検証ベンチマークでは熱い領域の特定精度が1.0を維持した。
- **メモリ・入出力:** 階層間の帯域比1.8倍・容量比2倍という疑似階層での実験であり、実物の高帯域メモリやCXLプールでの値は未評価である。
- **評価の強さ／注意点:** 既知の様式を持つベンチマークでの正しさ検証、既存方式との精度・過負荷の比較、8ワークロードの実測、移行実験まで一貫している。一方、LLM系の実測はCPU実行の推論と学習であり、GPU推論のメモリ挙動は対象外である。

**代表結果の読み方:** LLM推論の結果は、階層メモリへの期待を調整する内容になっている。遅延が27.7%もの領域へ分散し、アイドル期間の長い領域も乏しいため、速い層への静的配置も実行時移行も効きにくい。逆に、遅延が0.7%の領域へ集中するインメモリ分析のようなワークロードでは、小さな速い層でも大きな効果が出る。つまり階層の成否はハードウェアの層構成より先に、ワークロード側の集中度でほぼ決まる。推論基盤で階層メモリを検討する際は、まずこの集中度を測ることが先決だというのが実務的な含意である。

## 既存研究との差

カーネルの走査型計測は、ページテーブルのアクセスビットを定期的に確認する方式で、軽い反面、走査間隔の中の繰り返しや頻度の低いアクセスを捉えられず、局面の変化にも鈍い。本論文はプロセッサのサンプリング拡張を使い、命令単位の標本から遅延と出所までを取ることで、解像度と精度を取りにいった。ページの汚染やフォルト処理で追う方式が高コストなのとも対照的である。指標の面でも、アクセス回数の熱さで配置を決める従来の考え方に対し、遅延で重み付けした集中度と最長アイドル期間という、配置と移行の成否へ直接つながる2指標を足した点が差である。

## 限界・実装状況

対象プラットフォームはARM系に限られ、サンプリング拡張の有無と仕様に依存する。他アーキテクチャのサンプリング機構への移植性は、別チップでの再現確認はあるものの限定的である。LLM系の実測はCPU実行であり、現在の主流であるGPU推論のメモリ階層、特に高帯域メモリ上の重みとKVキャッシュの挙動は測れていない。階層の実験もNUMAによる疑似構成で、帯域差が実物の階層より小さい条件である。再現率はワークロードの様式に依存し、均一に熱い条件では上位選択の取りこぼしが大きい。計測ツールの公式公開先は論文中に明記されておらず、再現は手順記述への依拠になる。参考文献には識別子つきの項目がテキスト上で確認できなかったため、本まとめの参考文献欄は空とし、総数のみを記録した。

## 一般的な実装上の含意

推論基盤で階層メモリやオフロードを設計する際の第一歩は、帯域や容量の見積もりではなく、遅延の集中度を測ることである。集中していれば小さな速い層で足り、分散していれば層を増やしても効かない。本論文のLLM推論の結果は、重みやKVキャッシュを安易に遅い層へ逃がす設計への警告にもなっている。また、実行時移行はアイドル期間の長さで成否が分かれるため、移行の仕組みを作る前に空白の分布を測るべきである。計測については、ハードウェアのサンプリング機構を使えば本番に近い負荷でも1%未満の過負荷で細かい挙動が取れることが示されており、運用中の継続計測という選択肢を現実的にする。
