# Get More with LESS: Synthesizing Recurrence with KV Cache Compression for Efficient LLM Inference

> **LESS**は、キー・値キャッシュ（Key-Value Cache; KVキャッシュ）の追い出しを「残すか捨てるか」の二択にしない。重要なトークンは従来どおり疎KVキャッシュへ明示的に残し、追い出すトークンは固定サイズの低ランク状態へ順次圧縮する。次の注意計算では両方を合成するため、疎キャッシュから消えたトークンにも低解像度ながら参照経路が残る。

## 概要

自己回帰生成では、各デコード段階で過去トークンのKVを再利用するためにKVキャッシュを保持する。完全キャッシュは精度面では安全だが、必要容量が文脈長とバッチサイズに比例して増える。H2Oのような追い出し方式は、注意上重要とみなした少数トークンだけを残すことで容量を大幅に削減できる。

問題は、追い出しが不可逆なことである。現在のクエリでは重要でなくても、後の生成で古い情報が必要になることがある。特に文書全体を要約する課題のように「過去の大部分が少しずつ必要」な場合、少数の重い打者（heavy hitter）だけを残す方針では情報が不足する。一方、全トークンを低ランク状態だけへ押し込む線形注意（linear attention）的な方式は固定メモリにできるが、個別トークンを正確に取り出す経路が弱くなる。

LESSの着眼点は、**重要な少数トークンは疎キャッシュで高精度に残し、それ以外の広い過去は低ランク状態で薄く残す**ことである。疎注意が完全注意から落とした残差には低ランク構造があるという観察を利用し、明示KVと低ランク近似を同じ注意出力の中で合成する。

追加の低ランク状態は系列長に依存せず固定サイズで、論文の代表設定では約4組のKVを追加保存する程度に相当する。Llama 2/Falconと複数の追い出し方策で、言語モデリング・分類・要約を評価し、疎化による品質低下を一貫して縮めながら、完全KVより小さいメモリと高い実測スループットを維持する。

## 背景と問題設定

### 追い出し型KV圧縮は「今の重要度」を将来へ外挿する

H2Oなどでは、限られたKV予算に収まるよう、注意スコア等から重要なトークンを残し、それ以外をキャッシュから削除する。これは局所的な生成や、少数の重要位置に注意が集中する課題では有効である。

しかし削除後のトークンは、後のクエリから完全に見えなくなる。たとえば長い記事の後半で前半の補助事実が必要になっても、既に追い出されていれば通常の注意では復元できない。キャッシュ予算をさらに小さくするほど、この不可逆性が品質劣化として現れやすい。

### 低ランクだけでも個別参照がぼやける

線形注意では、過去のキーと値を再帰状態へ累積することで系列長に依存しないメモリにできる。ただし、多数のトークンを同じ固定サイズ状態へ畳み込むため、特定の一位置を鋭く取り出す能力は完全なsoftmax注意より弱い。

LESSはどちらか一方を選ばず、疎キャッシュを「高解像度の短期/重要記憶」、低ランク状態を「低解像度だが全履歴を覆う補助記憶」として併用する。

## 手法

### 1. 既存の疎KV方策はそのまま使う

LESS自身が「どのKVを明示的に残すか」を置き換えるわけではない。H2OやΛ-maskingなど既存の疎方策が通常どおり保持集合と追い出し集合を決める。

この設計により、疎方策の選択能力とLESSの補完能力を分離できる。疎方策が本当に重要な少数トークンを残せれば、そのKVには通常のsoftmax注意をかけられる。LESSは主に「追い出した残りを完全には失わない」役割を担う。

### 2. 追い出したKVを固定サイズの低ランク状態へ累積する

各注意層には、クエリ用とキー用の小さなカーネル関数を置く。これらは元の高次元クエリ/キーを非負の低ランク特徴へ写像する。

追い出されるキー・値の組については、キーの低ランク特徴と値の外積を状態 (H_t) へ加算し、正規化に必要なキー特徴の和を状態 (z_t) へ加算する。新たなKVが追い出されるたびに同じ二状態へ足すため、履歴が10倍、100倍に伸びても低ランク側の保存サイズは増えない。

ここで元KVを復元して保存し直すわけではない。多数の過去トークンが注意出力へ与える合計寄与を、将来のクエリから再利用しやすい統計として保持する。

### 3. 明示的な疎注意と低ランク寄与を一つの注意出力へ合成する

新しいクエリが来ると、まず疎KVキャッシュに残ったキー・値へ通常の指数型softmax注意を計算する。同時に、クエリの低ランク特徴を (H_t) と (z_t) へ掛け、追い出された全履歴からの近似寄与と正規化項を求める。

最終出力では、疎KV側の分子/分母と低ランク側の分子/分母を足し合わせて正規化する。つまり「疎注意の答え」と「別の低ランク注意の答え」を後段で平均するのではなく、**一つの注意分布を近似する二つの項として合成する**。この構造により、明示KVの鋭い注意と、追い出し履歴の広い補助情報を同時に使える。

### 4. 元LLMは固定し、層ごとの補助関数だけを学習する

LESSを使うためにモデル全体を再学習する必要はない。元LLMの重みを凍結したまま、完全キャッシュ注意の出力とLESS注意の出力の二乗誤差が小さくなるよう、低ランク写像を各注意層ごとに独立学習する。

層ごとに分離できるため学習は並列化しやすい。これは訓練不要方式ではないが、モデル全体の継続事前学習や微調整より対象パラメータを限定できる。推論時には学習済みの小型写像と低ランク状態更新だけが追加される。

### 5. 1トークン生成時の流れ

各デコード段階では、現在クエリから疎KVへ通常注意を行い、同時に低ランク状態から過去の追い出し情報を読み出す。疎方策がキャッシュ予算を超えたKVを選ぶと、そのKVを捨てる直前に低ランク状態へ加算する。その後は元KV自体を保持しない。

したがって容量は「疎方策が保持するKV数 + 固定サイズのLESS状態」で決まり、全履歴長には比例しない。一方、低ランク写像と状態参照の演算が追加されるため、同じ疎KV方策だけを使う場合より計算負担は増える。この追加費用と品質回復の交換条件がLESSの中心である。

## 評価

### 代表的な評価条件

| 項目 | 条件 |
|---|---|
| モデル | Llama 2 7B/13B、Falcon 7Bなど |
| 疎KV方策 | H2O、Λ-masking等 |
| 言語モデリング | WikiText、PG-19 |
| 要約 | CNN/DailyMail、MultiNews、XSum |
| 代表キャッシュ率 | H2O 2%、5%、10%など |
| 追加低ランク容量 | 代表設定で約4 KV組分に相当する固定サイズ |
| 学習 | 元LLMを固定し、各注意層の低ランクカーネル関数を独立学習 |
| 実機性能 | NVIDIA A100、FP16を用いた遅延・スループット評価 |
| 主指標 | パープレキシティ（Perplexity; PPL）、ROUGE、遅延、スループット、追加メモリ |

### 代表的な評価結果

| 条件 | 疎方策のみ | LESS併用 | 読み取れること |
|---|---:|---:|---|
| Llama 2 7B / WikiText / H2O 2% | PPL **13.333** | **10.745** | 完全KV 8.791との差を大きく縮める |
| Llama 2 7B / PG-19 / H2O 2% | PPL **37.013** | **32.157** | 別の長文言語モデリングでも改善 |
| Falcon 7B / CNN-DailyMail / H2O 10% | 疎化でROUGE-1低下 | 低下分の **41.4%回復** | 多数の過去情報が必要な要約で補助状態が効く |
| 追加容量 | — | 約 **4 KV組分** | 文脈長に依存しない小さい固定追加量 |
| 完全KV比の遅延 | — | **1.1〜1.3倍**低遅延 | KV削減による帯域/容量利得を維持 |
| 完全KV比のスループット | — | 最大 **1.7倍** | 小容量化を実処理率へ変換 |
| 追加カーネル計算 | 疎方策のみより小さい | デコード時間の約 **15%** | 品質回復は無料ではなく追加演算を伴う |

LESSの比較で重要なのは、疎方策単体より必ず速くなることではない。低ランク処理を追加するため、**同じ疎率のH2Oだけ**と比べれば遅延は増え得る。その代わり、完全KVより十分小さいキャッシュを維持したまま、H2Oだけで失う品質を回復する。したがって主な交換条件は「疎方策の最大速度」対「小容量のまま品質を完全KVへ近づけること」である。

## 既存研究との差

H2Oなどの追い出し方式は、重要な少数トークンを高精度に残せるが、削除部分への参照経路がなくなる。線形注意は全過去を固定状態へ集約できるが、個別位置への高解像度アクセスが弱い。

LESSは両者を足し合わせ、疎注意が得意な**少数の鋭い参照**と、低ランク再帰状態が得意な**広い履歴の集約**を同時に残す。また、元の疎方策を交換できるため、特定の重要度規則そのものへの依存を小さくしている。

## 限界・実装状況

低ランク状態は追い出したKVを可逆保存するものではない。特定の削除トークンを後から完全に再現するのではなく、その集合の注意寄与を近似する。したがって、非常に鋭い一点検索が必要なのにそのトークンを疎方策が追い出した場合、LESSが完全KVと同じ結果を保証するわけではない。

また、各注意層の補助関数を事前に学習する必要があるため、完全な訓練不要（training-free）KV圧縮ではない。モデルを変更すれば補助関数も学習し直す必要があり、運用モデルが頻繁に更新される環境ではその校正費用を考慮する必要がある。

性能面では、低ランク側の計算がデコード時間の一部を占める。短い文脈やKV容量に余裕がある小バッチでは、完全KVを削る利得より追加カーネル費用が相対的に大きくなり得る。逆に長文・大バッチでKV容量や帯域が律速になるほど、固定サイズ補助状態の価値が高くなる。

公式実装は `hdong920/LESS` で公開され、H2O等と組み合わせた学習・評価コードが提供されている。
