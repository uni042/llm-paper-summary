# Unifying Sparse Attention with Hierarchical Memory for Scalable Long-Context LLM Serving

> 動的疎注意は各デコード段で重要な少数KVだけをGPUへ読み込めば長文注意計算を減らせるが、選択粒度が方式ごとに異なり、CPU上の完全KVから細粒度・不連続なデータをPCIeで取り出す費用が利得を打ち消しやすい。SPINは、方式固有のブロックやクラスタを共通の論理パーティションへ写し、物理転送は固定ページへ統一する。さらに要求ごとのGPU KV予算を動的に伸縮し、直近に使ったページをGPU向けバケット化LRUで残し、二階層メタデータで最悪論理空間ではなく実際の物理ワーキングセットに比例させることで、疎注意をGPU・CPU階層メモリ上の実用サービングへ接続する。

## 問題設定
長文デコードではKVキャッシュ量が系列長に比例して増え、全履歴を毎トークン読む密注意はHBM容量と帯域の両方を圧迫する。動的疎注意は、その時のクエリに重要な一部のトークンだけを選んで注意計算するため、完全KVを大容量CPU DRAMへ置き、必要分だけGPUへ戻す構成と相性がよい。しかしShadowKVはブロック、RetroInferは可変クラスタ、SeerAttentionは別の粒度を使うなど、論理的な選択単位が方式ごとに異なる。この違いをそのまま実装すると、各方式が独自のKV管理・転送・スケジューリングを持ち、最適化を共有できない。さらに疎な選択結果はヘッド・層・デコード段ごとに変わる不連続なページ集合なので、CPUからGPUへの細かなPCIe転送が増え、理論上減らした注意計算より転送待ちが大きくなる場合がある。
## 新規性
SPINは疎注意のアルゴリズム固有部分と階層KV管理を、論理パーティションと物理ページの二層に分離する。各方式は索引作成、選択、注意計算という固有処理だけを定義し、オフロードと取得は共通実行系へ任せる。その共通層では、要求ごとのGPU KV領域を現在の必須ページ量と全体負荷に応じて伸縮し、複数デコード段にまたがる時間局所性をバケット化LRUで利用する。さらにヘッド別ページ管理で膨張するメタデータをGPUとCPUへ分割し、二階層ページ表によって実際に割り当てた物理ページ数に比例させる。疎注意方式の柔軟性、PCIe転送効率、HBM容量、メタデータ費を同じ実行基盤で共同最適化する点が中心である。
## 手法
### 手法のあらまし
SPINは疎注意の1デコード段を、索引作成、重要領域選択、KVオフロード、必要KV取得、注意計算という共通パイプラインへ分解する。このうち各方式で意味が違う索引作成・選択・注意計算だけを方式側が実装し、データ移動はSPINが担当する。方式側のブロックやクラスタなどを『パーティション』という連続トークン群へ統一し、実メモリの割当・転送は固定長ページで行う。パーティションが複数ページを持つ場合も対応表でGPUまたはCPUの物理ページへ変換するため、論理粒度を変えても転送カーネルとメモリ管理を再実装しなくてよい。

CPU DRAMには完全KVを保持し、GPUには現在の注意計算に絶対必要な必須ページと、過去に取得したページを再利用のため残すバッファページを置く。要求を新たにバッチへ入れる際は、その要求の必須ページに加えて最低限のバッファ量を確保できる場合だけ受け入れる。論文では経験的に必須ページの5倍を最低バッファ量として使う。要求数が増えたり系列が伸びたりしてHBM圧力が上がると、既存要求から系列長に応じてバッファページを回収し、要求数と1要求あたりキャッシュ命中率の均衡を取る。

バッファ内では、厳密なLRU順序をGPU上で維持せず、直近64デコード段程度を固定個数の時刻バケットで表す。選択されたページは最新バケットへ上げ、古いページは段階的に下げる。追い出しが必要になるとGPUページ表を並列走査してバケットごとのページ数ヒストグラムを作り、必要ページ数を満たす古い境界までまとめて追い出す。疎注意では1段で複数ページを同時に使うため、同一段内の厳密な順序を保持しない近似が実際のアクセス特性に合う。

細粒度管理では各ヘッド・層・要求のページ対応情報が巨大になり得るため、SPINはメタデータも階層化する。頻繁に参照するパーティション状態とGPUページ情報はGPUへ置き、容量を占めるCPU物理ページ列は固定メモリへ置いてGPUカーネルから参照する。さらに全最大系列長分を平坦に確保せず、小さな上位ディレクトリから必要になった二次セグメントだけを割り当てる。最後に、不連続なヘッド別KVページを転送する専用CUDAカーネルでは各ワープが1ページをベクトル化コピーし、永続カーネルとして全ワープへページを配ることでPCIe帯域を使いやすくする。

### パーティション抽象化と固定ページ転送
入力は各疎注意方式が作る論理的な重要領域で、ShadowKVの固定ブロック、RetroInferの可変クラスタ、SeerAttention系の選択単位など粒度が異なる。SPINはこれらを連続トークン集合であるパーティションとして表し、各パーティションから固定長物理ページ列への対応だけを共通管理する。方式側はどのパーティションを選ぶかを決め、実際にCPU・GPU間で運ぶ単位はページへ揃えるため、メモリ断片化を抑えつつ転送カーネルを共有できる。ヘッドごとに物理ページを分けることで、あるヘッドが不要と判断したKVまでPCIeで運ぶ無駄も避ける。代わりにパーティションとページの対応メタデータが必要になり、その増加を後段の階層メタデータ機構で抑える。

### 要求別に伸縮するGPU KVバッファ
各要求のGPU領域を、現在段の注意計算に必須なページと、将来の再利用を期待して残すバッファページに分ける。新規要求は必須領域と最低バッファを確保できる場合だけ実行バッチへ入り、容量不足なら待ち行列に残る。負荷が上がると既存要求のバッファから系列長に比例してページを回収し、少数要求へHBMを過剰配分して同時実行数を下げることを避ける。一方、負荷が低い時には余分なページを残してCPUからの再取得を減らす。最低バッファは必須ページの5倍という経験値を使うため、時間局所性が弱い方式や異なるモデルでは最適値が変わる可能性がある。

### GPU向けバケット化LRU
取得済みページが次の数段でも再び重要になる時間局所性を使い、CPUから同じKVを何度も取り直すことを減らす。厳密LRUでは全ページの順序更新や並べ替えがGPU上で高価なので、各ページへ有限範囲の時刻値を持たせ、同じデコード段で触れたページを同一の新しいバケットへ入れる。追い出し時はページ表を一度走査して共有メモリ上に時刻別ヒストグラムを作り、古いバケットから必要量をまとめて選ぶ。これによりヘッド・層ごとに毎段実行しても制御費を抑えられる。ただし64段を超える細かな新旧順序は失われるので、非常に長い再利用間隔を厳密に区別する用途には向かない。

### 二階層・階層分割メタデータ
ヘッド別KV管理を最大バッチ数×最大文脈長×層数×ヘッド数で平坦確保すると、実際に使っていない論理空間のために数十〜数百GB級の管理情報を予約し得る。SPINはGPUに小さな上位ディレクトリと頻繁に使う状態を置き、実ページが割り当てられた部分だけ二次セグメントをGPU上の共有プールから確保する。容量の大きいCPUページ列は固定ホストメモリへ置き、GPUから直接参照可能にする。結果としてメタデータ量は最大論理空間ではなく物理ワーキングセットへ追従する。セグメント割当と多段参照の追加処理は発生するが、HBMをKV本体へ回せる効果が大きい。

### 全体のデータ／制御の流れ
vLLMの要求スケジューラとメモリアロケータをSPIN向けに拡張し、要求到着・進行・完了のたびにGPU KV予算を更新する。各デコード段では方式固有の索引と選択から重要パーティションIDを得て、GPU側メタデータで命中・未命中を分類する。未命中に必要なページ数だけ古いバッファを追い出し、CPU固定メモリ上のページ対応を参照して専用CUDAコピーでGPUへ取得する。その後、選択KVで方式固有の注意計算を行う。完全KVはCPUに残るため疎注意方式の選択が次段で変わっても取り戻せる。方式固有処理と共通階層メモリ処理を明確に分けることで、新しい疎注意方式を追加してもサービング、GPUキャッシュ、PCIe転送、メタデータ最適化を再利用できる。
## 評価条件
- **ハードウェア**: A100 80GB×4、AMD EPYC 7V12、DRAM 850GB、PCIe Gen4 32GB/s/GPU、B200 180GB×4、Intel Xeon Platinum 8570、DRAM 1.5TB、PCIe Gen5 64GB/s/GPU
- **ソフトウェア**: vLLMベースSPIN、約7千行のC++/CUDA中核、約3千行のPython統合、AIPerfオンライン評価
- **モデル**: Qwen3-14B、Qwen3-32B、Llama-3.1-70B
- **データセット／トレース**: LongBench-v2: 入力32K〜120K、平均55K、出力平均5K、LongGenBench: 入力16K〜19K、平均18K、出力平均12K
- **比較対象**: vLLM密注意、CPUへKVを退避するvLLM-オフロード、GPUのみの疎注意LServe、ShadowKV原実装、RetroInfer原実装、SeerAttention-R原実装
- **正確性・品質**: SPINはShadowKV、RetroInfer、SeerAttention-Rそれぞれの重要KV選択規則と既定取得量を保ち、主に実行・保存・転送を共通化する。したがってSPIN固有の比較では、元疎注意方式に対して新たなモデル近似を追加せず同じ選択KVで性能を改善する。
- **オンラインサービング**: 要求到着をポアソン過程で生成して到着率を変え、1・2・4 GPUで測定する。原則として1 GPUはQwen3-14B、2 GPUはQwen3-32B、4 GPUはLlama-3.1-70Bを用い、LongBench-v2とLongGenBenchの異なる入出力長比でオンラインスループット、TTFT、TPOT、平均バッチ数を比較する。
- **3種類の疎注意統合**: ShadowKVは取得予算1.56%、パーティション8トークン、物理ページ8トークン、RetroInferは取得予算1.8%、可変パーティション、ページ8トークン、SeerAttention-Rは固定2Kトークン取得、パーティション・ページ32トークンという原方式の既定条件を使う。
- **オフライン段階別評価**: Qwen3-14Bを中心に文脈長16K、32K、64K、さらに120K級まで変え、プリフィルとデコードを分離して測定する。オンラインスケジューラを持たない原疎注意実装やLServeとも、この制御条件で直接比較する。
- **構成要素評価**: GPUキャッシュなし、現在段の必須ページのみ保持、バケット化LRU追加を順に比較するほか、バッファ対必須ページ比と二階層索引のメタデータ量を測り、転送削減とHBM管理費の寄与を分離する。
A100とB200、三つのモデル規模、長入力中心と長出力中心の二つの長文ベンチマークを組み合わせ、オンラインとオフラインを分けて評価する。密注意、単純CPU退避、GPU疎注意、各疎注意原実装を比較し、単に疎性による理論計算削減ではなく、要求同時実行数、PCIe取得時間、GPUバッファ命中、メタデータHBM量まで測ってシステム寄与を検証する。
単一サーバー内のGPU・CPU DRAM階層を対象とする実機研究で、SSD、CXL、遠隔KVストアは評価対象ではない。B200の低負荷では密注意の高速なHBM・計算能力によりSPINがvLLMを下回る条件もあり、疎注意と階層転送の固定費が常に回収できるわけではない。
## 主要結果
SPINは疎注意が減らした計算量を、要求ごとのHBM割当、時間局所性を使うGPUキャッシュ、不連続PCIe転送、階層メタデータまで含むサービング系へ接続し、vLLM比でエンドツーエンドスループットを1.66〜5.66倍に高める。高負荷では1要求あたりのHBM使用量を抑えて平均実行バッチを2.5〜3.3倍へ広げるため、待ち行列が短くなりTTFTは最大9倍短くなる。一方、低負荷のB200では密注意の計算・HBM帯域が十分高く、疎注意の索引・選択・PCIe取得費が回収できずvLLMを下回る条件もある。

- エンドツーエンドスループット / vLLM比1.66〜5.66倍 (比較対象: vLLM密注意; 条件: A100/B200、Qwen3-14B・32B、Llama-3.1-70B、LongBench-v2とLongGenBench) — 疎注意で1要求あたりのHBM需要を抑え、CPU上の完全KVから必要ページだけ取得することで、密注意より大きい同時実行バッチを維持できる。

- LongBench-v2高負荷スループット / A100で2.34〜3.80倍、B200で2.27〜4.03倍 (比較対象: vLLM; 条件: A100 1.5要求/秒、B200 4要求/秒) — 高負荷ほどvLLMはメモリ圧力で飽和する一方、SPINは階層KVで要求をより多く同時実行できるため差が広がる。

- LongGenBench高負荷スループット / A100で2.62〜5.66倍、B200で1.66〜3.72倍 (比較対象: vLLM; 条件: A100 1.5要求/秒、B200 4要求/秒) — 長出力でデコード比率が高い条件でも、疎注意と局所性キャッシュによりKV読出し量を抑え、大きなバッチを継続できる。

- 平均実行バッチ数 / vLLM/vLLM-オフロード比2.5〜3.3倍 (比較対象: vLLM、vLLM-オフロード; 条件: Qwen3-14B、A100、LongBench-v2/LongGenBench、1.5要求/秒) — SPINの主なオンライン利得が単体トークン計算の高速化だけでなく、HBM容量削減による同時実行性から来ることを示す。

- 先頭トークン時間 / 高負荷で最大9倍低減 (比較対象: vLLM; 条件: Qwen3-14B、A100、LongBench-v2、0.5要求/秒) — プリフィル自体は同程度だが、より高い処理能力により新規要求の待ち行列時間が短くなる。

- 元疎注意実装に対するデコード遅延 / バッチ1で21%/22%/47%低減、各最適バッチで35%/8.4%/58%低減 (比較対象: ShadowKV / RetroInfer / SeerAttention-R原実装; 条件: SPINへ同じ疎注意アルゴリズムを移植) — ShadowKVとRetroInferでは時間局所性キャッシュによるPCIe取得削減、SeerAttention-Rでは最適化CUDAカーネルが主に寄与する。

- GPUバッファ管理の効果 / デコードスループット49%向上、総合では局所性管理で最大2.18倍 (比較対象: 必須ページ中心またはGPUキャッシュなし; 条件: SPIN-ShadowKV、Qwen3-14B、32K、A100) — 直前段だけでなく複数段にまたがる重要KVの再利用をバケット化LRUで保持し、重複したPCIe取得を避ける。

- 階層メタデータ / HBM使用量49〜78分の1 (比較対象: 最悪論理空間を平坦に確保する方式; 条件: 細粒度ヘッド別KV管理) — 二階層索引を実割当ページに応じて増やすことで、管理情報がKV本体のHBM領域を侵食する問題を抑える。

### 負の結果・境界条件
- **低負荷B200では密注意が有利**: B200は計算能力とHBM帯域が高く、小バッチでは全注意のボトルネックが弱い。この条件では疎注意の索引作成、選択、GPU・CPU取得という固定費が相対的に大きく、SPINのデコード性能がvLLMを下回る。
- **TPOTはvLLMより増える場合がある**: オンライン高負荷ではSPINが大きなデコードバッチを維持し、さらに未命中KVをPCIeで取得するため、1要求だけ見た出力トークン当たり時間はvLLMより高くなる。TTFTと全体スループットを改善する代わりに個々のデコード間隔へ費用を払う。
- **方式ごとに取得予算の差が残る**: SeerAttention-Rは固定2Kトークンなど取得量が大きく、SPIN-ShadowKVよりTPOTが107%高い条件がある。共通実行基盤はアルゴリズム固有の疎性・選択精度・取得量そのものを解消しない。
- **SSD・CXLなど下位階層は未評価**: 完全KVの下位保存先はCPU DRAMであり、SSDやCXLへ拡張した際の媒体遅延、先読み、入出力スケジューリングは含まれない。不連続な疎KVアクセスをさらに遅い階層へ伸ばすには追加設計が必要である。

### 結果の読み方
SPINが示す重要点は、疎注意の価値が『選ぶKVが少ない』だけでは決まらず、選んだKVがGPUに残っている確率と、未命中をPCIeでどれだけまとめて速く運べるかで決まることである。高負荷ではHBM容量を節約して多くの要求を同時実行できるため、単体TPOTが多少悪化しても待ち行列を含むTTFTと全体処理量が改善する。逆に低負荷で密注意が十分速いGPUでは、この階層化固定費を回収できない。
## 品質への影響
SPINは疎注意アルゴリズム側の選択規則を変更せず、その選択KVを保存・取得する実行系を最適化する。したがってSPIN固有の高速化は追加量子化や追加枝刈りによる品質低下を前提にしないが、基礎となる各疎注意方式の精度特性はそのまま引き継ぐ。
## 既存研究との差
- ShadowKVやRetroInferなどの原実装は、それぞれ独自に疎KV選択とGPU・CPU転送を実装する。SPINは索引作成・選択・注意計算だけを方式固有部分として残し、論理パーティションから固定物理ページへの変換、オフロード、取得、GPUキャッシュを共通化する。
- vLLM-オフロードはHBM圧力時にKVをCPUへ退避するが、密注意を前提にしており各デコード段で選択された細粒度KVだけをヘッド別に取得する仕組みを持たない。SPINは疎注意の不連続アクセスを前提にページ配置と専用コピーカーネルを設計する。
- LServeはGPU内で疎注意を高速化するが、CPU DRAMを容量層として完全KVを保持する階層構成ではない。SPINはHBM容量を越える完全KVをCPUへ置き、重要な一部だけをGPUへ戻すことで、より大きい同時実行数を狙う。
- 一般的なLRUをCPU側で厳密管理する代わりに、SPINはデコード段を時刻単位とする有限バケット近似をGPU上で並列処理する。これによりヘッド・層ごとの細粒度追い出しを毎段行っても、管理費がキャッシュ命中の利得を打ち消しにくい。
## 限界
- 評価する下位KV階層はCPU DRAMまでで、SSD、CXL、遠隔KVストアの媒体遅延や入出力キューは扱わない。より遅い階層では現在のページ単位オンデマンド取得だけでは遅延を隠せない可能性がある。
- 各要求へ最低でも必須ページの5倍のバッファを与える規則や64段程度の時刻バケットは経験的設定である。時間局所性が弱いモデル・疎注意方式・ワークロードでは最適な配分が変わり得る。
- 低負荷B200のように密注意が十分速い条件では、索引・選択・PCIe取得の追加費が相対的に大きく、SPINがvLLMを下回る。常に疎注意を使えばよいわけではなく、負荷とGPU能力に応じた切替余地がある。
- SPINは疎注意方式自体の品質特性を改善するものではない。ShadowKV、RetroInfer、SeerAttention-Rが選ぶ重要KV集合の誤りや取得予算不足による精度影響は原方式から引き継ぐ。
- 原疎注意実装の多くはオンラインスケジューラを持たないため、オンライン比較では直接対決できず、原実装との比較は主にオフライン段階別評価で行われる。
## 実装状態
vLLMのスケジューラとメモリアロケータへ約3千行のPython変更を加え、SPIN中核を約7千行のC++/CUDAで実装する。ShadowKV、RetroInfer、SeerAttention-Rを統合し、ヘッド別不連続KVページをPCIeで運ぶワープ単位の永続CUDAコピーカーネルも実装済み。arXiv本文から専用公開リポジトリURLは確認できない。
## 研究上の位置づけ
KVキャッシュ最適化・圧縮系統のうち、動的疎注意をアルゴリズム単体ではなくGPU・CPU階層メモリ上のサービングシステムとして成立させる研究に位置づけられる。既存方式との差は、重要KVを選ぶアルゴリズムを新しく提案するより、異なる選択粒度をパーティション抽象化へ統一し、HBM予算、局所性、PCIe転送、メタデータを共通基盤で最適化する点にある。SSD活用研究への示唆としては、CPU DRAMのさらに下へSSDを置く場合も『選択単位と物理入出力単位を分離する』考え方が有効で、論理的には細かな疎注意を保ちつつ、SSDでは大きなページ・先読み・バッチ入出力へまとめる設計へ発展できる。
