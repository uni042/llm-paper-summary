# EchoPress：仮想文脈再構成による質問非依存のKVキャッシュ剪定

## 概要

長い入力を処理する大規模言語モデルでは、過去の鍵・値（Key–Value、KV）を保持するキャッシュが文脈長に比例して増える。複数の質問で同じ長文を再利用したい場合、質問を受け取ってから重要なトークンを決める方法では、圧縮済みキャッシュを別の質問へ使い回すことが難しい。そこで、質問に依存せず元の文脈だけからKVの重要度を求める方法が必要になる。

比較対象のKVzipは、元文脈を分割し、モデルに各分割片を再度復唱させることで、復唱時に参照されたKVの重要度を測る。各層・KVヘッド・トークンについて再構成時の最大注意確率を記録し、全体の低得点KVを捨てる。質問非依存で精度が高い一方、元文脈全体を参照しながら各片を再生成する追加の前向き計算が大きい。著者の実測では、KVzipの圧縮追加時間が対応する通常の入力処理時間の約2.1〜2.2倍になる。

EchoPressは、KVzipが再構成で求める重要度順位の多くを、通常の入力処理（prefill）で既に計算した照会（query）と鍵（key）から近似できると示した。主要な操作は、元の因果的な注意を全チャンク可視に変えること、復唱時の回転位置埋め込み（RoPE）を再現すること、復唱した片の因果的な仮想複製を追加すること、そして最初の片のみ本物の再構成を実施して各層・KVヘッドの得点尺度を補正することである。追加の学習データやモデル別の予測器は不要である。

この論文の核心は、**重要度順位の近似**と**異なるヘッド間で比較可能な尺度への校正**を別問題として解いた点にある。前者は回転位置補正で大幅に改善し、後者は最初のチャンクの厳密再構成から得た分位点写像で実現する。精度評価では、KVを50〜90%削除する条件の平均課題成績がKVzipに近い。一方、平均が近くても個別の検索・コード課題で悪化があり、完全に無損失とは主張できない。

## 問題設定と従来方式の計算負担

対象は、長文の入力処理が終わった直後、質問や生成を始める前にキャッシュを物理的に圧縮する場面である。入力長を n、分割片の上限を C、モデル層数を L、照会ヘッド数を H、ヘッド次元を d とする。KVzipは n/C 個ほどのチャンクを順に復唱するが、各復唱の注意は元の長さ n のキャッシュを参照する。この追加の注意計算は概ね O(L H d n²) となり、長文になるほど費用が急増する。これは**圧縮のための追加注意計算**の計算量であり、通常の入力処理そのものが線形化されるわけではない。

重要度の定義にも注意が必要である。KVzipでは、あるチャンクを復唱する照会は、元キャッシュの冒頭の少数のシンクトークン、対象チャンクの全鍵、および復唱列の因果的に見える鍵を正規化対象とする。対象外の元文脈の鍵は得点の正規化から除くが、復唱時の隠れ状態の形成には元文脈が関与する。したがって「単に入力処理時の注意重みを平均する」方法ではKVzipの得点を再現できない。

著者は入力処理と復唱処理の差を、(1) 元チャンク内の未来の鍵への可視性、(2) 復唱トークンのRoPE位置移動、(3) 復唱照会が全文に条件づけられていること、の三つに分解する。EchoPressは最初の二つを近似得点の内部で明示的に再現し、三つ目に伴う残差を最初のチャンクによる校正で扱う。

## 手法：入力処理状態からの仮想再構成

### 1. チャンクと保存済み照会・鍵の準備

入力文脈を C_t=[a_t,b_t) に分割する。元の入力処理で計算した各トークン位置 j の照会 q_j と鍵 k_j を使う。通常の因果的入力処理では q_j が参照できるのは j 以前の鍵だけだが、KVzipの復唱照会は対象チャンクの全ての元キャッシュ鍵を参照できる。EchoPressは、対象チャンクの全鍵を参照する仮想的な得点計算を構成し、モデルの各層をもう一度前向きに実行することを避ける。

この操作では各照会ヘッドと、それが共有するKVヘッドの対応を維持する。元論文は照会ヘッド数 H、KVヘッド数 Hkv、共有比 G=H/Hkv と定義し、KVの得点を、共有するG個の照会ヘッドおよびチャンク内の照会位置にわたる最大注意確率として計算する。これは平均注意とは異なり、ある一箇所で強く参照されるKVを残しやすい規則である。

### 2. 復唱位置へのRoPE補正

復唱の前には全文 n トークンと反復指示文 P_t トークンが存在する。元チャンクの先頭位置 a_t と復唱開始位置の差は Δ_t=n+P_t−a_t である。EchoPressは、元の照会 q_j に回転 R_{Δ_t} を適用して仮想照会を作り、復唱位置から元キャッシュの鍵を見たときの相対位置を再現する。これにより、同じ単語でも位置差の違いによって注意の順位が変わる現象を修正できる。

この補正が重要なのは、入力処理時と復唱時の照会が同じ意味的内容を指していても、RoPEによる相対位相が違えば内積が大きく変わるためである。単に元の q_j・k_i の内積を流用するだけでは、KVzipの復唱時の重要度をうまく近似できない。著者の構成要素除去実験でも、全チャンク可視化より位置補正の効果が明確に大きい。

### 3. 因果的な仮想複製と一つの正規化

KVzipの復唱には、元キャッシュに加えて復唱済みのトークン列の鍵が存在する。EchoPressは対象チャンクの鍵を、復唱後の位置に置いた仮想複製として扱い、照会 j が見る仮想複製の鍵を j 以前に制限する。得点の分母は、シンク鍵と対象チャンクの元鍵、それに因果的に可視な仮想複製鍵の指数内積の和である。つまり二つの枝を別々に正規化するのではなく、一つのソフトマックスで競合させる。

仮想複製の照会と鍵には同じ回転 R_{Δ_t} を適用するため、両者の内積では回転が打ち消し合う。式 (3) の (RΔ q)·(RΔ k)=q·k を利用し、元の入力処理時の照会・鍵積を再利用できる。元チャンクの鍵に対する枝では、回転済み照会と元の鍵を掛ける。この二枝を融合した得点計算は、復唱文全体の隠れ状態を再計算しない点でKVzipより軽い。論文の実装では融合Tritonカーネルを用い、各層の照会は得点を抽出した後に解放している。

仮想得点は、KVzipの厳密な復唱得点そのものではない。元の因果的隠れ状態を使うため、全文条件づけによる照会変化は再現できず、反復指示文の照会行・鍵列も得点計算から省いている。したがって、仮想得点の**ヘッド内順位**はある程度合っても、層やKVヘッド間の絶対尺度が一致するとは限らない。

### 4. 最初のチャンクだけを厳密再構成して尺度校正

EchoPressは各要求で最初のチャンクを一度だけKVzipと同じように厳密再構成する。最初のチャンクについて、各層 ℓ・KVヘッド h の仮想得点と厳密得点をそれぞれ昇順に並べ、同じ順位の値同士を対応させる経験的分位点写像 M_{ℓh} を作る。節点間は区分線形補間し、学習範囲外は端点へ切り詰める。後続チャンクの仮想得点だけをこの写像で厳密得点の尺度へ変換し、最初のチャンクの厳密得点は変更しない。

この「層ごと・KVヘッドごと」の写像は不可欠である。全層・全ヘッドで一つの変換を使うと、異なる尺度のKVを一つの全局閾値で比較してしまい、あるヘッドから過剰に削除する恐れがある。逆方向、すなわち厳密得点を仮想尺度へ写す方法も、信頼性の高い最初のチャンクを歪める。著者は両者を比較しており、提案した仮想→厳密の個別写像が最も良い。

正確な復唱に使う入力予算は2,048トークンであり、最初のチャンクは反復指示文を含めてこの予算内に収める。後続の仮想チャンクは最大2,048トークンまで使える。文脈全体が最初のチャンクに収まる場合、EchoPressの得点計算はKVzipと一致する。校正は要求ごとにその場で行い、外部の校正例や事前学習済みの写像を保存しない。

### 5. 全局剪定と計算量

校正後、最初のチャンクの厳密得点と後続チャンクの補正済み得点を一つの集合にし、全層・KVヘッド・トークンのうち低得点の割合 r を削除する。各ヘッドに固定割合を割り当てるのではなく、重要度の尺度を合わせたうえで全局的に保持予算を配分する。キャッシュの物理的な詰め直しまで実施するため、単に計算時にKVを参照しない方式とは異なる。

チャンク数が約n/C、各チャンクの仮想注意がO(LHdC²)なので、圧縮用の追加注意計算は O(LHdnC) となる。固定チャンク長Cでは文脈長nに対して線形である。ただし、元の入力処理、KVの物理的な再配置、校正用の最初のチャンク、照会の保存・得点の保持にはそれぞれ費用が残る。論文は校正写像の構築を O(LHkv C log C)、適用を O(LHkv n log C) としている。理論計算量だけでなく、実測した圧縮追加時間と総入力処理時間を区別する必要がある。

## 既存研究との違い

KVzipは復唱により得点を得るため質問非依存の圧縮精度が高いが、文脈全体を再構成する追加前向き処理を必要とする。EchoPressは同じ復唱得点の**近似**を狙い、既存の照会・鍵の回転補正と一度の校正で反復を置き換える。KVzipの保持規則である全局的な重要度閾値は維持するが、得点生成の費用を大幅に削る。

KVzap-MLPやFast KVzipは、学習済みの予測器やゲートで復唱費用を下げる。EchoPressは事前学習やモデル固有の追加パラメータを使わない代わりに、要求ごとに最初のチャンクを厳密再構成する。これにより別モデルへ展開する際の学習負担はないが、学習済み得点器より圧縮追加時間が常に短いとは限らない。Expected Attentionや鍵の幾何情報を用いる方法は通常入力処理に近い費用で得点を作るが、KVzipの復唱時の位置・正規化構造を直接近似する点が異なる。

重要度の全局的な配分という観点では、層ごとの固定予算を使う方式とも異なる。EchoPressは各層・ヘッドの尺度補正後に全局閾値を適用するため、必要に応じて異なる層へ異なる保持率を割り当てられる。この配分が有効なのは分位点校正が後続チャンクにも転用できる場合であり、その条件は独立の問題である。

## 限界・負の結果・実装上の注意

第一に、**最初のチャンクの校正写像が後続の全チャンクに適用できるか**という仮定が残る。最初のチャンクでは入力処理と復唱の隠れ状態の差が最大であるという測定を根拠に校正対象を選ぶが、これはそのチャンクの分位点写像が後続の異なる話題・構文にも最適であることを証明しない。写像の端点外の値は切り詰められるため、後続チャンクの得点分布が大きく変わると順位をつぶす恐れがある。著者も付録Cで最適な校正チャンクは確立していないと認める。

第二に、精度評価は単一の乱数種42による結果で、分散や信頼区間を示していない。RULER-32K/64Kは各課題20例であり、小さな平均差を安定した優越と解釈できない。個別のコード補完や共通語抽出の負の結果は、平均精度だけでは判断できないことを示している。削除率90%という厳しい条件では、用途に合わせた評価が不可欠である。

第三に、時間評価は1枚のA100・バッチ1であり、複数要求が並行するサービング、分離型入力処理・復号、他のGPU世代、複数GPU、CPUへのオフロード、生成中の再圧縮についての実測ではない。128Kでの圧縮追加時間19.6倍短縮は強い結果だが、生成トークン毎秒の高速化やサーバ全体のスループットを直接示していない。

第四に、性能測定ではKVzip公式CUDA実装とEchoPressのアダプタを同条件で比較する一方、品質測定はKVPress/SDPAを使用する。学習済み比較方式も別の実装・前処理を使うため、方式間の秒数だけをそのまま一般化しない。圧縮されたキャッシュを何回再利用するかによって、前処理時間の削減が総コストに占める割合も変わる。

第五に、KVを**削除する**方式であるため、後から必要になった情報を元の精度で復元する仕組みではない。最初の質問では問題がなくても別の質問や深い検索で必要なKVを失う可能性があり、質問非依存とはすべての質問で完全無損失を意味しない。著者の評価は長文検索や質問応答を含むが、任意の将来質問に対する保証はない。

## 再現・導入判断

著者が指定する公式実装は `ljwljwljwljw/kvpress` の `echo-press` ブランチである。論文の品質評価と時間評価は別実装系を使用しているため、再現時には論文付録Bの実装版、注意方式、チャンク長、入力長、バッチ、削除率を一致させる必要がある。特に速度を比較するなら、モデル読み込み・コンパイル・トークン化を除いた区間を揃え、KVの物理圧縮まで含める。品質を比較するなら、質問の前に圧縮し、質問トークンと生成トークンは圧縮しないという原論文の条件を保つ。

推論基盤へ組み込む場合の最初の確認事項は、(1) 既存入力処理カーネルから各層の照会を取得できるか、(2) 回転位置とチャンク分割の定義が既存モデルのRoPE実装に一致するか、(3) 層・KVヘッド別の得点を全局的に比較できるか、(4) 物理圧縮が既存KVメモリ配置と両立するか、である。これは実装の検討事項であって、原著が他のランタイムへ統合済みと報告した事実ではない。
