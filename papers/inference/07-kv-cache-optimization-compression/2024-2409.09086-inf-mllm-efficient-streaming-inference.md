# Inf-MLLM: Efficient Streaming Inference of Multimodal Large Language Models on a Single GPU

> attention saddlesを追跡して最新・重要トークンだけを固定KVへ残し、attention biasで長期ストリーム中の注意移動にも追随するInf-MLLM。

## 概要

動画を含むマルチモーダルLLM（MLLM）のストリーミング推論では、会話ラウンドが進むたびに画像・動画由来トークンとテキストトークンが増える。通常のTransformerは過去全トークンのKV状態を保持するため、KVキャッシュが履歴長に比例して増加し、単一GPUではやがてメモリ不足になる。

Inf-MLLMは、LLM/MLLMの注意マップを観察すると「直近トークン」「動画由来の重要トークン」「多数のデコードステップから継続して参照される散在トークン」に高い注意が集中し、それらが縦線状に現れることを利用する。著者らはこの高注意トークン群を**attention saddles**と呼ぶ。全履歴を保存する代わりに、最新トークンとattention saddlesだけを固定容量KVキャッシュへ残す。

単純な累積注意スコアだけでは古いトークンが何ラウンドも加点され、新しい重要トークンが入りにくくなる。そこでInf-MLLMは、古いトークンほど不利になるattention biasを選択スコアへ加え、会話の進行に伴って高注意領域が前方へ移る「shifting」パターンへ追随する。複数LLM/MLLMで最大4Mトークンのテキスト、最大1時間の動画を使う多ラウンド会話を単一GPUで処理し、H2Oより約2倍高速であることを報告する。

## 問題設定

StreamingLLMは冒頭のattention sinkと直近windowを残すことで長いストリームを扱うが、会話途中で重要になった散在トークンや、動画中の重要情報を動的に追跡する仕組みが弱い。H2Oは高注意トークンを保持するが、注意スコアを長期に累積すると古いトークンへスコアが偏りやすく、マルチラウンド会話で注意対象が移る状況を扱いにくい。

MLLMではこの問題がさらに強い。動画トークンは多数で、しかもモデルが後から特定場面を参照する可能性がある。固定windowだけでは長期情報を失い、全KV保持ではメモリが増え続ける。必要なのは、固定容量のまま「最近」と「以前だが今も重要」の両方を動的に残すキャッシュ更新である。

## 手法

### 1. 注意マップから4つのパターンを抽出する

Inf-MLLMの設計は、Chat-UniVi-7Bなどの注意マップ観察から始まる。著者らは主に4種類の挙動を整理する。

1. **直近トークンは高注意を受ける。** 現在の生成と位置・意味の両面で近いためである。
2. **動画由来トークンは高注意になりやすい。** 一部VLMでは動画先頭部分だけで注意質量の40%以上を受ける例もある。
3. **散在する重要トークンが縦線として残る。** ある過去トークンが数十〜数百デコードステップ継続して参照される。
4. **高注意位置は会話ラウンドとともに前へ移る。** 新しい質問が来ると、以前重要だったトークンから新しい文脈へ注意が移る。

Inf-MLLMは1〜3の高注意点をattention saddlesとしてキャッシュへ保持し、4の移動をattention biasで処理する。

### 2. 新規プロンプトをretrieval windowとして注意スコアを集める

新しい会話ラウンドが来ると、その新規トークンのQ/K/Vを計算し、長さLの**retrieval window**として扱う。既存キャッシュにt個の過去KVがある場合、新規window内のQueryと、過去KVおよび新規KVとの注意スコアを計算する。

重要度を測るとき、全履歴のQueryを使って過去から延々とスコアを加算するのではなく、新しいwindow内で得られた注意を局所的に集約する。縦線として継続する重要トークンなら短いwindowでも繰り返し高得点になるため、attention saddleを検出できる。

### 3. 正規化スコア上位の過去KVと最新windowを残す

過去トークンは存在期間が長いほど累積回数も多いため、そのままの総和では古いKVが有利になる。Inf-MLLMはwindow内の注意を平均・正規化して比較し、過去KVから上位r個を**relevant tokens**として選ぶ。

これに最新L個のトークンを必ず加え、キャッシュを「重要な過去r個 + 最新L個」の固定容量に保つ。選外の過去KVは削除される。処理は層ごとだが、実装ではPyTorchの並列性を使って各層のキャッシュ更新を並行して行う。

### 4. attention biasで古い高得点の固定化を防ぐ

正規化しても、複数ラウンドにわたり選ばれ続けた古いトークンはスコア優位を持ち、新しいattention saddleがキャッシュへ入れなくなることがある。極端になるとキャッシュがほとんど更新されず、長文脈でモデルが崩壊する。

そこでInf-MLLMは、トークンの古さに応じた負のattention biasを重要度スコアへ加える。アルゴリズム上は、過去トークン数に沿って線形に変化するバイアスDを作り、windowから得た平均注意Sに加えてからTop-kを取る。

バイアスが大きいほど新しいトークンへ入れ替わりやすく、ストリーミング適応性が上がる。一方、小さくすると古い重要トークンを長く残せるため長期記憶に有利になる。この値は単純に大きい／小さいほどよいわけではなく、必要な記憶距離との交換条件になる。

### 5. 既存モデルを再学習せずストリーミング化する

Inf-MLLMはモデル重みや位置符号化を学習し直す方式ではなく、推論時のKVキャッシュ管理として外付けする。このため元モデルの最大文脈長を超える入力でも、GPU上のKV容量自体は一定にできる。

ただし、全過去情報を厳密に残すわけではない。品質は「後から必要になる情報をattention saddleとして検出できるか」と「attention biasが古い重要情報を早く捨て過ぎないか」に依存する。

## 評価

### 代表的な評価条件

| 項目 | 内容 |
|---|---|
| GPU | 単一NVIDIA RTX 4090D またはNVIDIA Orin |
| LLM | Vicuna-7B、Pythia-2.8B、LLaMA-2-7B-32K |
| MLLM/VLM | Chat-UniVi、Flash-VStream |
| 長文テキスト | WikiText-103、最大4Mトークン |
| 長期記憶 | LongEval-LineRetrievalを基にした300プロンプトの多ラウンドQA |
| 動画QA | MSVD-QA、MSRVTT-QA、TGIF-QA、VStream-QA |
| 比較 | Window Attention、StreamingLLM、H2O |
| 代表KV容量 | 2Kでの動画QA・attention bias評価 |

### 長文テキスト

20Kまでのテキストで、Inf-MLLMはWindow Attention、H2O、StreamingLLMより安定したperplexityを示す。さらにVicuna-7B、Pythia-2.8B、LLaMA-2-7B-32Kを最大4Mトークンへ延長しても、固定容量KVのままperplexityを安定させる実験を行っている。

これは「最大文脈長を4Mへ再学習で伸ばした」という意味ではなく、ストリーミング入力を全KV保持せず処理し続けた結果である。過去全トークンへ自由に厳密注意できるわけではない点を区別する必要がある。

### 多ラウンド動画QA

Chat-UniViとFlash-VStreamにInf-MLLMを組み込み、MSVD-QA、MSRVTT-QA、TGIF-QAのサンプルを連結して5、10、300ラウンドの動画QAを行う。元モデルは履歴が伸びるとOOMになるが、Inf-MLLMは2K程度のKVキャッシュを維持したまま300ラウンドまで継続でき、多くの条件で回答品質も維持または改善する。

VStream-QAでは、最大1時間規模の動画ストリームに対する質問応答を評価しており、「履歴長は伸び続けるがGPU上のKV容量は一定」という設計の主用途に近い。

### attention biasの感度

Vicuna-7B、KV容量2Kの長期記憶実験では、必要なトークン距離が伸びるほど最適なattention biasは小さくなる。例えば近距離では大きなバイアスでも新しい情報を優先できるが、遠い情報を保持したい場合は古いトークンへのペナルティを弱める必要がある。

一方でバイアスを小さくし過ぎると古いトークンが固定化し、長文脈でキャッシュ更新が止まる。論文では0.01未満の設定で精度がほぼゼロへ落ちるケースを示しており、attention biasは「長期記憶を増やすため小さくすればよい」パラメータではない。

### 速度

Inf-MLLMは、同じく重要KVを保持するH2Oと比較して約2倍の推論高速化を報告する。主因は、更新対象を新規retrieval windowに限定して局所的に注意を集約し、固定KV上で選択を行うことにある。

この倍率は単一GPU・論文のモデル／KV設定での比較であり、4Mトークンという処理可能長そのものを速度倍率と混同しない。

## 既存研究との差

StreamingLLMはattention sinkと直近windowを固定保持するため実装が単純だが、会話途中で現れる重要な動画・テキストトークンを動的に残すことが難しい。Inf-MLLMは、実際の注意マップからattention saddlesを毎ラウンド再選択する。

H2Oも高注意トークンを使うが、Inf-MLLMはMLLMの動画トークンと多ラウンド注意移動を明示的に観察し、**retrieval windowによる局所スコア集約 + 年齢依存attention bias**で古い累積スコアの固定化を防ぐ。これが連続動画・多ラウンド会話へ適用するための主要差になる。

## 限界

固定容量KVである以上、同時に保持すべき重要情報量がr+Lを超えるタスクでは必ず情報を落とす。attention saddleが現在の短いretrieval windowで十分高い注意を受けない場合も、将来必要になる情報を先に捨てる可能性がある。

attention biasには明確な感度があり、新しい文脈への追随と長期記憶保持を同時に最大化できる単一設定はない。論文の4Mトークン／1時間動画は「無限履歴を完全保持する」ことを意味せず、固定キャッシュへ情報を要約的に残しながらストリーム処理を継続できることを示す結果として読むべきである。
