# Cache Merging as a Convergent Replicated State for Multi-Agent Latent Reasoning

> エージェント間のKVキャッシュ交換を、内容で順序を決める正準マージと集合和による収束型複製状態に作り替え、入力順序や重複配達に依存しない潜在推論の合成を、精度をほぼ落とさず実現した。

## 概要

複数のエージェントが文章ではなく潜在空間でやり取りする方式では、各エージェントが自分の担当断片について潜在推論を行い、その過程で生じたKVキャッシュ、すなわち各層のキーとバリューの蓄積を、最終判断役のエージェントへ渡す。判断役は受け取ったキャッシュ群を1つの文脈へ合成し、その上で答えを生成する。ここで合成の実体は、先行研究Agent Primitivesが暗黙に使っていた、キャッシュを系列方向へ連結し、後続断片のキーへ回転位置符号化（Rotary Position Embedding; RoPE）を掛け直して位置をずらす操作である。本論文はこれをBagMergeと名付ける。連結は順序を持つ操作であり、先頭の位置0を占める断片だけが元の回転のまま読まれる特権スロットになるため、BagMergeは非可換、つまり入力順序を入れ替えると別のキャッシュになり、生成される答えも変わる。しかも最良の順序は事前に分からない。質問を各思考役へ配る調整型の運用形態と、質問を判断役だけが知る連合型の運用形態とで最良順序は逆転し、潜在ステップ数やモデル規模によっても動く。

本論文の答えは2段階である。第1段階のCanonicalMergeは、順序を呼出し側の都合ではなく断片の内容で決める。中間層1層における平均Kノルム、つまりキーベクトルの大きさの平均を断片ごとに測り、大きい順に並べてから連結する。スコアが各断片自身のキーだけから決まるため、入力列をどう並べ替えても同じ正準順序が得られ、マージ済みキャッシュはバイト単位で同一になる。第2段階では、永続化する状態とデコード時の配置を分離する。保持する対象は、回転を掛けていない断片にその全バイト列のハッシュを識別子として付けたものの集合LatentFragmentSetであり、状態同士のマージは集合和である。集合和は可換・結合的・冪等・吸収的であり、これは分散システムで収束型複製データ型（Conflict-free Replicated Data Type; CRDT）のうち状態ベースのもの（CvRDT）が満たす性質そのものである。CanonicalMergeはこの集合に対する決定的な描画として位置付けられ、描画結果は従来の連結とバイト単位で一致するため、精度の数値はそのまま引き継がれ、再配達された重複断片は集合側で吸収されて再連結されない。

**代表結果:** 単独では解けない2断片を統合しないと解けないよう作った分割推論ベンチマーク（100問、Qwen3-1.7B）で、CanonicalMergeは運用形態2種×潜在ステップ予算2種の全セルで最良のBagMerge固定順序から4ポイント以内に収まり（差は+0.03、+0.03、0.00、−0.04）、3つの独立した問題抽選を合わせた検定でも最良順序と統計的に区別がつかなかった。重複断片を4回再配達する実験では、素朴な再連結が精度0.93から0.45へ落ちキャッシュ長も308トークンから1232トークンへ膨らむ一方、複製状態経由では精度0.93と長さ308トークンのまま不変だった。実文書質問応答のHotpotQA（200問）ではテキストをそのまま渡す上限にF1で約7ポイント劣るが、キャッシュ方式の中では最良であり、出力融合のPackLLMには生成予算を揃えた条件で45ポイント勝った。

## 問題設定

問題を資源と配置の観点で見る。潜在推論の合成で消費されるのは、各思考役が潜在ステップを回して作るキャッシュであり、判断役はその合計長に等しい接頭辞の上で注意計算を行う。ボトルネックは計算量そのものよりも、配置の任意性にある。独立に符号化されたキャッシュを連結するとき、どれか1つの断片を位置0の範囲へ置き、残りをずらした末尾範囲へ置く割当てが必ず発生する。位置0の断片は学習時にモデルが見慣れた回転幾何のまま読まれるが、末尾の断片は符号化時には存在しなかった位置へ回転し直され、より長い相対距離越しに読まれる。論文が実測したところ、同じ断片のバイト列でも先頭スロットと末尾スロットでは判断役からの注意量が1トークンあたり8.5パーセント違い、この非対称が2思考役の場合で6ポイントの精度差を生む。

既存対策の不足は、順序を決める根拠がどこにもないことにある。固定順序は運用形態が変われば裏目に出る。論文の行列では、質問既知ではswap順序が最良（0.90と0.91）、質問盲検ではdefault順序が最良（0.90と0.85）であり、間違った固定順序を選ぶと最悪で7から14ポイントを失う。モデル規模を4Bへ変えると逆転自体が消えてswapが両形態で最良になり、Llama-3.1-8Bでは順序差が19ポイントまで広がる。つまり順序は検証なしには決められない運用パラメータであり、調整役が順序を指定する設計自体が、調整役のいない連合型運用では成立しない。さらに連合型では、同じ断片がゴシップや再送で複数回到着し得る。描画済みキャッシュへ再連結する素朴な扱いは、重複をそのまま接頭辞へ積み増しする。

本論文の着眼点は、この配置問題を分散システムの複製状態の問題として読み替えることにある。順序非依存、配達スケジュール非依存、重複耐性は、まさにCRDTが分散状態へ与える保証である。ただしキャッシュには位置構造があるため、集合和をそのままキャッシュへ適用はできない。そこで状態と描画を分け、状態側で収束性を持ち、描画側で内容決定的に配置を固定する二層構造にする。

## 手法のあらまし

処理の流れは、符号化、状態への取り込み、描画、生成の順である。各思考役は担当断片だけを入力として同じモデルを独立に走らせ、決められた回数の潜在ステップ、つまり文章を出さず内部状態だけを自己回帰的に進める計算を行い、全層のキーとバリューからなるキャッシュ断片を作る。質問既知の運用形態では断片と併せて全体の質問も思考役へ渡り、質問盲検では質問は判断役にだけ届く。各断片は回転を掛け直されていない元の形で、その全バイト列に対するハッシュを識別子として、断片集合へ取り込まれる。同じ断片が再び届いても識別子が一致するため集合は変わらない。判断役が答えを生成する段になって初めて描画が行われる。中間層における平均Kノルムで断片を降順に並べ、同点なら内容ハッシュで順序を確定し、先頭断片は元の回転のまま、後続断片は累積オフセット分だけキーを回転し直して連結する。判断役は潜在ステップを持たず、この描画済みキャッシュを接頭辞として答えを自己回帰的に生成する。学習は一切行わず、設計パラメータはKノルムを測る層の選択だけである。

## 手法

### 1. BagMergeの方向性の欠陥 — 連結順序が特権スロットの割当てになる

この機構は先行方式の分析であり、観測するものは2つの思考役キャッシュを両順序で連結したときの判断役の出力差である。BagMergeは保持する状態を持たず、呼出し側が与えた順序どおりに、後続断片のキーへ累積位置オフセット分の回転行列を掛けて位置範囲をずらし、バリューはそのまま連結する。減らすべき対象として本論文が特定したのは、この割当ての任意性である。先頭スロットのキーは元の回転を保ちモデルの学習幾何と一致する一方、末尾スロットのキーは符号化時に存在しなかった位置へ写され、注意の偏り（文頭への集中や文中情報の利用低下）の影響を受ける。論文は同一断片を両スロットへ置いて判断役の注意量を測り、先頭では1トークンあたりの注意が8.5パーセント少ないこと（合算比0.915）を示した。純粋な注意量では末尾が有利でも、回転幾何の正しさでは先頭が有利であり、どちらが精度へ効くかは運用形態次第で変わるため、固定順序では原理的に勝ち続けられない。追加で消費する資源はないが、順序選択を誤る費用が精度7から19ポイントとして現れる。

### 2. CanonicalMerge — 平均Kノルムで先頭スロットの占有者を内容から決める

この機構が観測するのは、各断片のルーティング層におけるキーベクトルである。保持する状態は断片ごとのスコアであり、最短のキャッシュ長に末尾を揃えた上で、その層のキーについて位置・バッチ・ヘッド全体でL2ノルムの平均を取った値ρと、同点解消に使う全内容ハッシュである。行う動作は配置の決定であり、ρの降順、同点ではハッシュ降順という全順序で断片を並べ、その順序でBagMergeと同じ連結と回転し直しを行う。これにより情報密度の高い断片、すなわち答えを拘束する条件を担っている可能性が高い断片が、判断役に最も確実に読まれる先頭スロットを占め、密度の低い断片が回転劣化のある末尾を引き受ける。減るボトルネックは順序選択そのものである。スコアは断片自身の内容だけの関数なので、入力列の任意の並べ替えに対して正準順序は不変であり、出力はバイト単位で同一になる。この可換性は構成による性質で、合成テンソルでは最大5断片・152通りの並べ替え、実モデルではQwen3-1.7Bの28層とQwen3-4Bの36層のKV状態でビット単位に検証された。追加で消費する資源はスコア計算と連結・再回転であり、実測では断片1件141トークン分についてハッシュ51ミリ秒、描画全体142ミリ秒で、256トークンの判断役生成16.4秒の1.2パーセントにすぎない。失敗条件は信号の質である。Kノルムが情報密度の代理になるのは思考役が質問を見て符号化した場合であり、質問盲検では質問条件付きの構造が消えてスコアが平坦化し、先頭選択はほぼ同点解消に近づく。ただしその場合でも可換性はスコアの有益さに依存せず保たれる。もう一つの境界は、敵対的な寄稿者がKノルムを水増しした断片を作れば先頭スロットを奪える点であり、真正性の担保は本方式の範囲外と論文自身が述べる。

### 3. LatentFragmentSet — 状態と描画を分け、集合和で収束性を持つ

この機構が観測するのは、到着した断片の識別子、すなわち回転前の全層キー・バリューのバイト列に対するハッシュである。保持する状態は識別子と断片の組の集合であり、取り込みも複製間のマージも集合和で定義される。選択・削除に相当する動作は吸収であり、バイト単位で同一の再配達は同じ識別子を持つため集合の要素数が増えず、描画結果も変わらない。なぜ描画済みキャッシュ自体を状態にできないかというと、一度末尾へ回転し直された断片は内容スコアから元の断片として認識できなくなり、描画演算だけでは冪等性が成り立たないからである。回転前の断片を状態として保持し、位置の割当てを描画時にだけ行うことで、集合和の可換性・結合性・冪等性・吸収性がそのまま状態の収束性になり、包含関係による半格子として状態ベースCvRDTを構成する。描画は集合の純粋関数であり、CanonicalMergeの順序不変性のおかげで列挙順に依存しない。描画結果は2断片の場合にCanonicalMergeの出力とバイト単位で一致するため、第5節の精度数値はすべてそのまま継承される。減るボトルネックは重複配達による状態膨張と出力変動である。追加で消費する資源は、断片の生バイト保持と、新規断片が吸収されるたびに集合全体を再描画する費用であり、遅延描画のためバッチ推論では無視できるが、ストリーミング再配達では再描画が断片数に比例する。失敗条件は同一性の定義が構文的である点にある。同じ情報を異なるバイトで符号化した断片、例えば別ハードウェアや別カーネルで再符号化され下位ビットが異なるコピーは別要素として扱われ吸収されない。収束そのものは崩れないが、重複除去の効きが弱まる。

| 構成要素 | 入力・観測 | 具体的な動作 | 改善対象 | 主なトレードオフ |
|---|---|---|---|---|
| CanonicalMerge | 各断片のルーティング層のキー | 平均Kノルム降順に並べ、同点は内容ハッシュで確定して連結・再回転 | 順序選択の任意性と非可換性 | 質問盲検ではスコアが平坦化し選択の利得が消える |
| LatentFragmentSet | 断片の全バイト列のハッシュ | 回転前の断片を集合へ取り込み、マージは集合和 | 重複再配達による膨張と出力変動 | 意味的に同じでもバイトが異なる断片は吸収できない |
| 描画 | 断片集合全体 | デコード時に正準順序でキャッシュを構築 | 状態へ位置情報を混入させないこと | 新規吸収のたびに全体を再描画する |

### 4. 1問の流れ — 分割、潜在推論、取り込み、描画、生成

分割推論ベンチマークの1問では、答えを一意に決める情報が2つの断片へ分かれており、片方だけでは解けない。思考役0が断片a、思考役1が断片bを受け取り、それぞれ20回または40回の潜在ステップを回してキャッシュを作る。質問既知では両者とも質問文を見ており、断片の符号化自体が質問条件付きになる。両断片が集合へ取り込まれると、描画では中間層のKノルムが大きい方、例えば換算表を持つ断片か比率の条件を持つ断片か、その問題で拘束の強い方が先頭へ置かれる。判断役はこの接頭辞の上で答えの整数を生成する。近似の区別として、本方式は生成内容を近似しない。連結されるキーとバリューの数値はBagMergeと同一で、変わるのは並びだけであり、品質への影響は順序経由でのみ現れる。

## 評価

結論は三点である。第1に、構造的保証は正確である。入力順序に対するバイト一致と重複吸収は構成により成り立ち、実モデルでもビット単位で確認された。第2に、経験的な精度は最良の固定順序と互角である。順序を選ばない代償は全セルで4ポイント以内、複数抽選の統合検定では統計的に区別がつかず、宣言した5ポイントの非劣性マージンも問題単位の検定では満たした。第3に、キャッシュ段での合成は出力段の融合とは別物である。同じ生成予算でPackLLMが45ポイント劣ることは、判断役が注意で辿れる中間状態を残すかどうかが決定的であることを示す。逆に、断片をテキストとして渡す上限にはHotpotQAで約7ポイント届かず、3断片以上では合成そのものが成立しないという境界も明確である。評価はすべて実モデル実行であり、ハードウェアはApple M3である。

## 既存研究との差

潜在推論の先行研究は合成を直列に行ってきた。Coconutは単一モデルの内部で連続潜在状態を回し、LatentMASは各エージェントのキャッシュを次エージェントの作業記憶へ前に置く直列の連鎖であり、順序は処理順で固定される。Agent Primitivesの投票・選択プリミティブは並列だが、各解法役が課題全体を解いた完全な候補の中から選ぶ設定であり、断片同士を合成する必要がない。本論文は、断片が単独不十分・共同必要という並列合成そのものを対象にし、そこで初めて現れる順序選択の問題を特定した点が異なる。最も近い並列合成のParallel-Synthesisは固定の作業者順序で連結し、キャッシュ写像器と合成役の低ランク適応による事後学習を要するのに対し、本方式は学習不要で内容決定的な順序付けだけで順序不変性を得る。出力段の融合（自己整合性、複数エージェント討論、PackLLM等）は潜在状態を捨てて文章や分布だけを混ぜるため、合成の段そのものが違う。重み段のモデルマージへCRDTを持ち込んだGillespieの研究は二層構造の発想で近いが、対象は永続的な重みのオフライン統合であり、位置構造を持つ推論時のKV状態ではない。本論文の新規性は、推論時の潜在状態に対する初の状態ベースCvRDT化と、その描画としての正準マージにある。

## 限界・実装状況

論文が挙げる限界は複数ある。第1に、精度の主張は2断片までであり、3断片以上ではキャッシュの同居だけでは合成が成立せず、モデルの再処理が必要になる。第2に、重複吸収はバイト単位で同一のコピーに限る構文的なもので、意味的に近いがバイトの異なる断片を統合する意味的収束は将来課題である。第3に、バイト一致の主張は同一モデル・同一装置・決定的な数値カーネルを前提とし、異種ハードウェア間では下位ビットの差でハッシュ吸収とバイト一致が崩れ得る。論文は許容誤差ベースの同一性を将来の対処として挙げる。第4に、評価は回転位置符号化を持つモデルに限られ、自然言語評価も支持段落2つの問題までで、攪乱文書の多い検索設定は未検証である。第5に、描画は遅延実行で、新規断片の吸収ごとに集合全体を再描画するため、頻繁な再配達のあるストリーミングでは費用が断片数に比例する。実装状況としては、全数値を再現する匿名コード成果物が付録Gに示されており、実装は既存のページング型キャッシュ抽象の上に順序付けと再回転カーネルを追加する形で、推論基盤への新しい基本機能は要らないとされる。広い影響として論文自身が、KVキャッシュは出所断片の機微な内容を含み得て潜在交換は秘匿化ではないこと、Kノルムを水増しした悪意ある断片が先頭スロットを奪えること、断片ハッシュが安定識別子となり寄稿の連結可能性を生むことを挙げている。

## 一般的な実装上の含意

複数エージェントの状態交換を設計するときは、永続化する状態と実行時に構築する配置を分けることが要点である。位置や順序といった提示方法を状態へ焼き込むと、重複除去や再送耐性のような分布システムの基本性質が後から付けられなくなる。順序を呼出し側の都合で決める操作は、調整役のいない設定では未定義の意思決定を残すため、内容だけから決まる全順序で置き換えると、検証項目が精度比較から構成による保証へ移る。また、合成の段をどこに置くかは精度の上限を決める。出力段の融合は安いが共同制約を再構成できず、キャッシュ段の合成は帯域を約4桁食う代わりに中間表現を残す。転送量が支配的な費用になるため、潜在交換を採用するなら圧縮と出所管理は最初から設計に入れるべきである。最後に、輸送と合成は別の能力であり、断片数が増えたときに同居だけで解けるかは、再処理の継ぎ目の有無で別途検証する必要がある。
