# KVCapsule：画像KVの鍵と値を非対称に圧縮し、注意の変化に応じて復元する

## 概要

KVCapsuleは、視覚言語モデルの画像トークンが作る鍵・値キャッシュを、単に重要度の低いトークンから削除するのではなく、後で復元できる表現へ圧縮する手法である。画像は一枚でも数百から数千トークンになり、複数画像や動画を扱うと生成中に参照する過去のキャッシュが大きくなる。従来のテキスト向け削減方式は、入力をまとめて処理した段階で得た注意重みをもとに残すトークンを決めることが多い。しかし視覚言語モデルは、回答の最初と後半で別の画像領域を参照する場合がある。入力時点で目立たなかった領域を永久に削除すると、後から必要になっても復元できない。

著者らは画像トークンの鍵と値に異なる冗長性があることを測定した。鍵はトークン間のコサイン類似度が高く、代表的な鍵から全体を再構成しやすい。一方、値はトークン間の類似度が低いが、系列全体を行列として見ると主成分で圧縮できる。そこで鍵は選択した少数のトークンから小型の復元器で戻し、値は画像トークンの系列方向へ主成分射影する。生成時には必要な注意計算を保つよう復元する。事前学習済みモデル本体の重みと注意演算の意味は変えず、圧縮・復元部品だけを追加学習する。

五つの視覚言語モデルと画像・動画評価で、視覚KVを平均約60%削減しながら多くの品質指標を保つ。融合実装では生成スループットが最大約2倍、KVキャッシュ容量は条件によって最大約2.4倍小さくなると報告する。ただし品質劣化がゼロではない。Qwen2.5-VLの動画理解では、MMBench-Videoの粗粒度指標が1.18から0.90へ低下する。また、短い入力では復元器と射影基底の固定費が相対的に大きい。最大倍率だけを普遍的な速度向上と扱わないことが重要である。

## 問題設定と観測された非対称性

### 視覚トークンの重要度は生成中に変わる

視覚言語モデルの注意は、入力画像の位置、質問内容、生成した回答の途中段階に依存する。たとえば画像の全体像を説明した後、特定の物体の色を述べるときには、必要な画像領域が変わる。著者らはMEGABenchから無作為に選んだ500例を分析し、生成ステップ間で注意上位10%の画像トークン集合がどれだけ一致するかを調べた。ステップ0と5、0と10の一致率はともに0.16であり、ステップ0を基準にした平均一致率も0.25にすぎない。後のステップ同士でも完全には一致しない。

この観測は、入力処理時に上位だったトークンだけを残す方式が、生成後半で必要な領域を失う可能性を示す。注意重みの変化だけで最終的な正答率の悪化を定量的に説明できるわけではないが、削除を不可逆にすることの危険を具体的に示している。KVCapsuleは、重要度を一度決めたら変更できないトークン削除とは異なり、圧縮した情報から元の画像系列に対応する鍵・値を再構成する設計を選ぶ。

### 鍵は似ており、値は局所的に異なる

同じ500例で、画像トークン間のコサイン類似度を層ごとに比較した。鍵の平均類似度は第0層で0.99、第10層で0.87、第20層で0.66だった。値はそれぞれ0.35、0.40、0.30である。鍵は特に浅い層で似た方向を持つため、少数の代表点を残してもクエリとの内積構造をある程度再現できる。一方、値は異なる局所情報を持つため、同じ方法で行を削ると画像の細部が失われやすい。

ただし値同士の類似度が低いことは、系列全体の行列が低ランク近似できないことを意味しない。二つのベクトルの類似度と、行列の主成分へ分散が集中するかどうかは異なる性質である。著者らは値の特徴次元方向の圧縮も検証したが、128次元のうち95%の分散を残すには113〜114次元、99%には125次元が必要だった。特徴次元を大幅に削るのは難しいため、値については画像トークン数の方向へ圧縮する。

### 層によって圧縮許容量が違う

浅い層の誤差は後続層へ伝播し、深い層では画像情報の抽象化が進んでいる。原著は浅い層に比較的多くの視覚KVを残し、深い層ほど強く圧縮するピラミッド状の保持率を採用する。付録の感度実験では、ある深い層は95%の圧縮でも復元後のコサイン類似度が0.93を超える条件を示す。ただしこの結果は特定層の再構成誤差であり、全層を95%圧縮しても下流タスク精度が保たれるという証拠ではない。

## 手法

### 1. 鍵：代表トークンの選択と復元器

各層の画像由来の鍵行列から、学習済みの選択マスクで一部の行を保持する。元の画像トークン数をn、層の保持率をrとすると、保存する行数はおおむねr×nとなる。保持した鍵を小型の二層多層パーセプトロンへ入力し、注意計算の前に元のn行に対応する鍵を再構成する。選択マスクと復元器は、元の鍵との再構成二乗誤差、マスクの選択を促す損失、目標保持率を守る損失を組み合わせて学習する。

代表鍵を選ぶだけで残りのトークンを永久削除するのではなく、全位置に対応する近似鍵を作る点が重要である。注意の重みはクエリと鍵の内積から決まるため、再構成した鍵の方向が変わると、注目する画像領域も変わる。復元器はこの幾何学的な関係を保つよう学習するが、完全な復元ではなく近似であり、学習に使った画像分布と異なる入力では誤差が増える可能性がある。

### 2. 値：画像トークン系列方向の主成分射影

値行列は、各トークンの特徴を行に持つ。まず画像トークン全体の平均ベクトルを引いて中心化し、学習データから求めた主成分基底へ系列方向に射影する。元のn行を、保持率rに対応する少数の主成分係数へ変換して保存する。生成時には主成分基底の転置を掛け、平均ベクトルを戻して元の画像トークン数の値行列を近似的に再構成する。値の各行を丸ごと捨てる方式と異なり、圧縮された係数には全トークンの情報が寄与する。

この主成分基底はモデルの層ごとに学習した固定パラメータである。推論中に毎回特異値分解を行うのではない。主成分による近似は、固定された基底と二乗誤差の観点で優れていても、質問ごとの正答率を最適化するとは限らない。また、基底行列や平均ベクトルを保存するための追加メモリが必要であり、入力が短い場合は圧縮したキャッシュより復元用パラメータの費用が目立つ。

### 3. 入力処理と生成時の実行経路

入力をまとめて処理する段階では、画像トークンの鍵だけを選択し、値だけを主成分へ射影して、圧縮した状態をキャッシュへ保存する。テキストトークンの鍵・値は通常のまま残す。生成時には圧縮画像KVから元の長さに対応する近似鍵・値を再構成し、テキストKVと連結して元の注意機構へ渡す。したがってモデル本体の注意層や事前学習済みの重みを改造せずに組み込める。ただし圧縮器・復元器の学習は必要であり、学習を全く要しない方式ではない。

元の長さのKVを毎ステップ明示的に作ると、復元とメモリ書き込みの費用が大きくなる。著者らは融合版を用意し、鍵については圧縮鍵との内積から得たスコアを復元してから正規化し、値については行列積の結合法則を利用して、注意重みを先に主成分空間へ射影して圧縮値と掛ける。これにより、元の長さの値行列をGPUメモリ上へ完全に書き戻す必要がない。復元後の全位置に対応する注意の意味を維持しつつ、キャッシュ読出し量を減らす設計である。

### 4. 保持率と固定費の交換条件

標準の鍵・値キャッシュは、テキスト、画像、生成済みトークンの合計長に比例して増える。KVCapsuleは画像部分の長さnだけをおおむねr×nへ縮め、テキストと生成部分はそのまま保持する。画像部分が全体の大半を占めるときほど削減率は大きい。復元器と主成分基底の固定費はバッチ数や生成トークン数とは異なる項として加わる。原著の単層モデルでの計算では、画像トークン数が約626を超えると、圧縮による保存量削減が復元器の追加費用を上回る。これは理論上の損益分岐点であり、すべてのGPUやモデルに共通する実測閾値ではない。

## 評価

### 実験条件と比較の仕方

| 観点 | 原著での条件 |
|---|---|
| 視覚言語モデル | Qwen2-VL-7B、Qwen2.5-VL-7B、Qwen3-VL-8B、LLaVA-Mistral-7B、LLaVA-Llama-8B |
| 画像評価 | MME、MMMU、COCO、MMBench、LLaVABench、HallusionBench |
| 動画評価 | Video-MMEの短・中・長尺、MMBench-Videoの粗粒度・細粒度 |
| 比較方式 | 全KV保持、FastV、SparseVLM、PruMerge |
| 主圧縮率 | 視覚KVを平均約60%削減、比較方式は55〜65%削減へ調整 |
| 効率測定 | AMD MI250X、生成スループットと9K〜15Kトークン入力の単一要求遅延 |
| 補助分析 | MEGABench 500例の類似度・注意集合、層別圧縮感度、再構成の除去実験 |

原著の比較は、画像KVだけを圧縮した場合の品質とメモリ効率を測る。すべてのモデルで同じ絶対トークン数を削った比較ではなく、圧縮率をおおむね揃えた比較である。画像理解指標には百分率、独自の点数、文章類似度などが混在するため、表の数値を単純平均して総合能力の順位を付けるべきではない。速度測定も、モデルの全工程を同じ割合で高速化したという意味ではなく、主に生成時のキャッシュ参照に対する効果を示す。

### 画像理解の主結果

| モデル・指標 | 全KV保持 | KVCapsule | 重要な留保 |
|---|---:|---:|---|
| Qwen2-VLのMME | 1687.70 | 1634.22 | 一部の知覚性能は低下 |
| Qwen2-VLのMMBench | 0.82 | 0.83 | ほぼ同等 |
| Qwen2.5-VLのMME | 1685.80 | 1635.80 | 完全には保持しない |
| Qwen2.5-VLのMMBench | 0.80 | 0.79 | 小幅低下 |
| Qwen3-VLのMME | 1735.60 | 1708.49 | 小幅低下 |
| Qwen3-VLのMMMU | 0.52 | 0.48 | 難しい理解課題で低下 |
| LLaVA-MistralのMME | 1458.12 | 1458.10 | ほぼ一致 |
| LLaVA-LlamaのMMMU | 0.46 | 0.60 | この評価では改善 |

五つのモデルで概ね高い精度を保つが、すべての指標が不変ではない。Qwen3-VLのMMMUは0.52から0.48へ低下する。これは画像KVを圧縮しても品質劣化が無視できると一律に断定できないことを示す。LLaVA-Llamaで一部指標が改善しても、圧縮によって一般に推論能力が向上するという因果的な主張にはならない。各モデルの入力長、画像枚数、質問の種類によって損失が変わり得る。

### 動画理解の負の結果

Video-MMEのQwen3-VLでは短尺0.66、中尺0.54、長尺0.50が全KV保持と圧縮後で一致した。一方、Qwen2.5-VLでは長尺0.46から0.44へ下がり、MMBench-Videoの粗粒度指標は1.18から0.90、細粒度指標は1.22から1.01へ下がった。これは視覚KVを復元できる設計でも、複雑な時間的情報を完全には保てないことを示す。FastVのような静的削除方式がさらに大きく悪化する条件があることと、KVCapsuleが無損失であることは別の主張である。

### 実行遅延・容量と限界

| 入力長 | 全KV保持の生成遅延 | KVCapsule | 短縮率 |
|---|---:|---:|---:|
| 9K | 74.58ミリ秒/トークン | 70.22 | 5.8% |
| 10K | 73.23 | 67.02 | 8.5% |
| 11K | 76.47 | 68.46 | 10.5% |
| 12K | 79.69 | 67.69 | 15.1% |
| 13K | 82.91 | 67.00 | 19.2% |
| 14K | 86.05 | 67.58 | 21.5% |
| 15K | 89.16 | 66.18 | 25.8% |

これはAMD MI250X上の単一要求の生成遅延であり、モデルやバッチ条件が異なれば同じ値にはならない。長い入力ほど通常のKV読出し量が増えるため、圧縮の利点が大きくなる。一方、9Kでは改善率が5.8%と小さく、固定費が残る。原著は別のスループット図で最大約2倍を報告するが、その最大値をこの表の全入力長へ適用してはいけない。

理論上のKV容量は、画像トークンの保存長を約40%へ減らすことで縮むが、復元器と主成分基底が追加される。画像トークンが短いと総メモリが増える場合があり、約626トークンの損益分岐点が示される。最大2.4倍のKV容量削減は特定の長い画像文脈での値であり、モデル重みを含むGPU全体のVRAMが2.4分の1になるという意味ではない。画像以外のテキストKVやモデル本体の重みは残るため、圧縮率と総VRAM節約率を混同しない。

### 機構の検証と比較上の注意

著者らは鍵と値の圧縮を入れ替えた構成、鍵だけまたは値だけを復元する構成、固定圧縮のまま注意を計算する構成、層ごとの保持率を変える構成を比較した。鍵の代表選択と復元器、値の系列方向主成分射影という非対称な組合せが有利であり、入力時点の重要度だけで固定削除する方式より、生成中の注意変化に対応しやすいとする。原著の付録は鍵・値の類似度と特徴次元の主成分分析も示し、設計上の根拠を補強している。ただし各要素の効果はモデルと圧縮率に依存し、復元器が常に厳密な注意重みを再現するわけではない。

## 既存研究との差

H2OやFastVなどの重要度選択方式は、ある時点で低重要度と判断したKVを削除する。KVCapsuleは画像の重要領域が生成中に変わることを実測し、後から全画像位置に対応する近似KVを作れる表現を保存する。単純な低ビット量子化は一要素当たりのビット幅を減らすが、本方式は画像トークン系列方向の情報を圧縮する。MLA型の潜在KV圧縮は特徴次元を減らすことが多いのに対し、画像の値は特徴次元方向に密であるという観測から、系列方向へ主成分を取る点が異なる。

事前学習済みモデル本体を凍結するため、元の視覚言語モデルの大規模再学習は必要ない。しかし選択マスク、復元器、主成分基底を用意するための学習と較正は必要である。モデルや画像解像度が変わると、画像トークン数と主成分基底の適合性も変わる。新しいモデルへ移植する際に圧縮器を無条件で使い回せるわけではない。

## 限界と未解決事項

第一に、画像トークンの鍵・値を復元するのは近似であり、厳密に元の全KVを保存する方式と同じ出力分布を保証しない。特に画像中のまれな細部や長い動画の時間的関係が重要な場合、低ランク射影で情報が失われる可能性がある。実際にQwen2.5-VLの動画指標で負の結果がある。品質を重要視する用途では、平均精度だけでなく対象タスク別の低下を確認する必要がある。

第二に、実行上の利得は視覚トークンの比率、入力長、復元器の固定費、GPU上の行列演算の効率に依存する。約626トークンの損益分岐点は原著の理論モデルに基づくもので、任意のモデル・GPUで同じ境界になるとは限らない。最大2倍の生成スループットは評価した装置と負荷での結果であり、多数同時要求の待ち行列やP99遅延、CPU前処理、画像エンコーダを含む全体の応答時間を一律に2倍改善することは示していない。

第三に、主成分基底と復元器は事前に学習する。新しい画像解像度や未学習の視覚分布、モデルの層数・ヘッド数の変更で適合性が変わる可能性がある。値の特徴次元方向の低ランク性が弱いという観測は500例に基づくもので、あらゆる視覚モデルへ一般化するには追加検証が必要である。動画を含む長文脈、画像枚数、圧縮率を変えた品質・メモリ・遅延の同時測定が今後の課題となる。
