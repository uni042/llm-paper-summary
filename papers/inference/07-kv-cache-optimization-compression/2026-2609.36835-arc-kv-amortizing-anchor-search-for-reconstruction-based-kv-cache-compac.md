# ARC-KV：アンカー選択を使い回し、再構成品質を保つKV圧縮

## 概要

ARC-KVは、長い文脈を何度も参照する大規模言語モデルの鍵・値キャッシュを小さくする研究である。通常の削除型圧縮では、残すトークンを選んで元の鍵と値をそのまま保存する。しかし、削除したトークンの注意質量や値の寄与を残存トークンが表現できず、極端な圧縮では品質が落ちる。Attention Matching（AM）は元の注意出力を再構成するように残存KVを補正するが、直交マッチング追跡（OMP）によるアンカー探索が文脈ごとに非常に遅い。

著者らは、どの元の鍵を代表点として残すかを予測する索引器を文脈をまたいで学習し、推論時には一度の採点でアンカーを決める。その後、各文脈固有の注意応答に合わせて鍵を凸包内で結合し、注意質量を補正するバイアスと小さな値行列を再推定する。学習するのはアンカー選択方針であり、圧縮されたKV自体をすべての文脈へ共通化するわけではない。

Llama-3.1-8B-InstructとQuALITYの評価では、KV保持率10%でAMの正解率0.6409に対してARC-KVは0.6474、圧縮時間は959.8秒から37.3秒へ短縮し、25.73倍となった。保持率5%でも圧縮時間269.46秒から31.8秒へ短縮した。ただし、これらは**文脈ごとのキャッシュ圧縮処理の時間**であり、要求を受けてから回答を終えるまでの推論全体の速度ではない。再利用する接頭辞が多いほど前処理費用を償却しやすい方式である。

## 問題設定と既存方式の限界

系列長Tに比例してKVキャッシュは増える。長い文章や検索結果を一度プリフィルし、多数の質問が同じ接頭辞を共有する場合、全長KVを各デコード段階で読む費用と保持容量が問題となる。保持率ρを0.1とすると保存するKVは概ね元の10%になるが、残した10%の元トークンだけでは削除した90%の注意分布を再現できない。単純な重要トークン削除と、注意出力の再構成を区別する必要がある。

AMは代表となる実在鍵を選び、選択鍵に対応する注意質量バイアスと圧縮値を推定して、全長KVで計算した注意出力に近づける。しかし、OMPでは候補鍵を一つ追加するたびに選択集合と回帰を更新する。選択数が増えるほど計算が膨らむため、保持率を高めるほど前処理が長くなる逆説がある。長い接頭辞を多く使う実運用でも、圧縮準備に数百秒を要するなら利点を生かしにくい。

ARC-KVの設計原則は**選択規則は文脈間で再利用し、再構成は文脈ごとに行う**ことである。すべてを学習済み圧縮器で直接合成する方式とは異なり、元の鍵を基点として保持し、推論時の文脈固有の幾何と値を利用する。これによりアンカー探索の繰り返しを減らしつつ、削除型圧縮より表現力の高いキャッシュを作る。

## 手法

### 参照質問から圧縮キャッシュを組み立てる

#### 1. 参照問い合わせ集合の構築

対象の文脈を一度プリフィルした後、同じ文脈をモデルに再提示する反復プリフィル（repeat-prefill）で参照問い合わせを作る。各位置について、問い合わせ射影前の活性`x_i`と回転位置埋め込み適用後の問い合わせ`q_i`を対として保存する。元の鍵Kと値Vは初回の文脈プリフィルから取得する。参照問い合わせは、将来の個別質問そのものではなく、文脈の内容に対するモデルの注意応答を模した較正用サンプルである。

この参照集合を索引器の採点、鍵結合、補正値の推定へ渡す。学習中は採点用、当てはめ用、未使用評価用の三つへ分割し、同じ問い合わせで選択と評価を行う過学習を避ける。推論時は参照集合を分割せず、構築した圧縮キャッシュを同一接頭辞に対する後続の質問へ使い回す。反復プリフィルは一回の追加計算として必要であり、長文脈ではこの費用自体が残る。

#### 2. 値ベクトルを考慮した索引器で実在鍵を選ぶ

索引器`Iθ(x_i,q_i,K,V)`は、各キャッシュ位置jに一つの重要度対数値を出す。DeepSeek Sparse Attention系の低次元問い合わせ・鍵採点器を基礎に、値ベクトルの違いも反映する補助の値注意経路を加えている。同じ注意重みでも値が異なれば最終出力への寄与が変わるため、鍵の類似度だけでは不十分である。グループ化問い合わせ注意（GQA）では、一つのKVヘッドを共有する複数の問い合わせヘッドから参照情報を集める。

各参照問い合わせで得た位置ごとの採点をソフトマックスで正規化し、位置jについて二乗平均平方根`score_j = sqrt(mean_i p_ij^2)`を取る。平均値だけで集約すると少数の問い合わせで非常に重要な位置が埋もれやすいが、二乗平均平方根はそのような局所的ピークを強く反映する。保持予算`t=ceil(ρT)`に従い、上位t個の**実在する鍵**をアンカー集合Sとする。問い合わせごとに別の鍵集合を選ぶのではなく、接頭辞に対して一回選んで固定する。

#### 3. 凸包制約付きの鍵結合

アンカー以外の各鍵を、参照問い合わせに対する注意応答の形が最も似たアンカーへ割り当てる。具体的には、各鍵が参照問い合わせへ返す指数化した注意対数値の列を正規化したプロファイル`u_j`を作り、内積が最大のアンカープロファイルの群`G_r`へ割り当てる。生の鍵ベクトルのユークリッド距離ではなく、**問い合わせに対する振る舞い**を使う点が重要である。

群内では、参照問い合わせ全体の平均注意質量に比例する重みで元の鍵を平均し、代表アンカー`k_sr`をその重心へ近づける。式は`c_k,r=(1-λ_m) k_sr + λ_m μ_r`、`0≤λ_m≤1`である。得られる圧縮鍵は群内の実在鍵の凸包から外れない。したがって、どの問い合わせに対しても群内の実在鍵が作る注意対数値の範囲から大きく外挿することを避ける。ここで結合するのは鍵であり、値は単純平均せず次の段階で再構成する。

#### 4. 注意質量バイアスと値行列の再推定

鍵の本数を減らすと、元の多くの鍵が受け持っていた注意質量を代表鍵へ配り直す必要がある。ARC-KVは選択・結合した圧縮鍵`C_k`を固定し、参照問い合わせに対する指数化した注意の総質量が元の全長キャッシュに近くなるよう非負重みを求め、その対数をバイアス`β`とする。次に正則化付き最小二乗法で圧縮値`C_v`を当てはめ、圧縮後の注意出力が全長KVの出力を近似するようにする。これらの補正は文脈ごとの閉形式または数値最適化であり、新しい学習パラメータを増やさない。

結果として圧縮キャッシュは`(C_k, β, C_v)`となる。推論時の問い合わせは、この固定した圧縮表現に対して注意を計算する。削除型の`(K_S,V_S)`と異なり、選んだ鍵が元の値をそのまま保持するとは限らない。長い接頭辞の多回再利用に適している一方、生成が進むたびに新しいKVをオンラインで再圧縮する機構は論文の対象外である。

#### 5. 索引器の学習と損失

各基盤モデルを凍結し、索引器だけを学習する。まず全長注意の位置分布に索引器の出力を近づけるKL損失で事前調整し、次に圧縮後の注意出力と全長出力の差を減らす再構成損失を加える。上位選択は離散操作なので、前向きには実際のアンカー選択を使い、逆向きには滑らかな代理経路の勾配を通す直通推定器を使う。これにより、繰り返しOMPを教師ラベルとして実行しなくても、値を考慮したアンカー採点を学習できる。

学習は11種類の長文脈データ集合から採った600文書と検証用60文書を用い、KLのみ10エポック、共同目的5エポックとした。追加索引器は基盤モデルの0.57～2.13%のパラメータを持ち、学習には34～151 B200 GPU時間を要する。これは推論時の各文脈で繰り返す費用ではなく、モデルごとに一度支払う費用である。

## 評価

### 評価環境と比較

| 項目 | 一次論文での条件 |
|---|---|
| 基盤モデル | Llama-3.1-8B-Instructを主対象、Qwen3-8BとGemma-3-12B-ITでも検証 |
| 計算環境 | NVIDIA B200、FP16。基盤モデル重みは凍結 |
| QuALITY | 50記事に対する894問、多肢選択の正解率 |
| RULER | 4K文脈の550例、公式文字列一致集計 |
| LongBench v1 | 21タスク×50例＝1,050例、タスク別指標の集計 |
| 保持率 | 20%、10%、5%、2%、1% |
| 比較対象 | 全長KV、無文脈、AM、SnapKV、KVzip、Expected Attention |
| 測定の区別 | キャッシュ圧縮の準備時間、注意層単体の遅延、下流課題の正解率。全体デコード遅延とは別 |

Gemma-3-12B-ITは混合注意構造のため、全注意を使う8層だけを圧縮し、残り40の局所窓注意層はそのままにした。したがってGemmaの「保持率5%」はモデルの全KVメモリが5%になるという意味ではない。LongBenchではOMP版AMの全1,050例実行が実用的でなかったため、最重要注意選択による代替AM-HAを比較に使用した。この違いも比較表の解釈に必要である。

### 主要結果、負の結果、構成要素除去

| 条件 | 比較対象 | ARC-KV | 読み取れること |
|---|---:|---:|---|
| QuALITY、保持10%、正解率 | AM 0.6409 | 0.6474 | 0.65ポイント改善 |
| QuALITY、保持10%、圧縮時間 | AM 959.83秒 | 37.3秒 | 25.73倍短縮 |
| QuALITY、保持5%、圧縮時間 | AM 269.46秒 | 31.8秒 | 8.47倍短縮、正解率も3.63ポイント改善 |
| QuALITY、保持1%、圧縮時間 | AM 36.34秒 | 28.0秒 | 1.30倍と利得は小さい |
| RULER、Llama、保持5%、集計値 | AM 0.4800 | 0.7394 | 25.94ポイント改善 |
| RULER、Qwen3-8B、保持5% | KVzip 0.4040 | 0.3815 | **ARC-KVが2.25ポイント下回る** |
| RULER、Gemma-3-12B、保持5% | KVzip 0.2273 | 0.3954 | 16.81ポイント改善 |
| RULER、Llama、保持20% | AM 0.9527 | 0.9515 | **わずかにAMが上回る** |
| LongBench、Llama、保持1% | AM-HA 0.2451 | 0.2355 | **低保持率ではAM-HAに負ける** |

15通りの主要なベンチマークと保持率の組合せでは13通りで圧縮方式中の首位だった。ただし、上表の例外のように常に勝つわけではない。軽量なSnapKV、KVzip、Expected Attentionは、AMより速いARC-KVよりも**絶対的な圧縮準備時間は短い**。その代わり、同じ予算での精度が低いという交換関係にある。したがって、短命な接頭辞へ一回だけ質問する場合は、ARC-KVの準備費用が過大になり得る。

長さ4K～64Kの全256層・KVヘッド組合せの内部計測では、OMPのアンカー選択が14.932秒から29.49分へ増えるのに対し、学習済み索引器は0.516～7.273秒で済んだ。索引選択部分だけの高速化は28.9～243.3倍である。ただし64K文脈では反復プリフィルだけで70.8秒かかり、ARC-KVの総準備99.8秒の大部分を占めた。アンカー探索を高速化した結果、参照問い合わせ生成が新しい律速になる。

注意層単体の計測では、保持率20%で全長FlashAttention-2に対し3.19～4.43倍の速度、約5分の1のKV保持を報告した。ただしこれは層単位であり、モデル全体のトークン毎秒が同じ倍率で増えたという測定ではない。構成要素除去では、二乗平均平方根の集約が平均・最大集約を保持率5%以下で4.59～8.95ポイント上回り、KVヘッドごとの予算を均等化すると1.68～16.22ポイント失った。鍵結合を使うと注意質量の誤差が良好な条件で43.9～56.9%減った。

## 限界・既存研究との差

単純なKV削除は代表トークンを残すだけで、失った注意出力を補償しない。AMは補償するが代表鍵の探索が高価である。ARC-KVは**代表鍵を選ぶ政策だけを学習して文脈をまたいで償却し、鍵・質量・値の補償は文脈固有に保つ**。索引器の追加学習が必要なので、学習不要の削除方式と同じ導入条件ではない。また、ベンチマークは接頭辞を一度圧縮して後続問い合わせへ再利用する設定であり、進行中のデコードで新しいKVを逐次統合する設計は今後の課題である。

参照問い合わせの生成には元の長文脈をもう一度処理する費用があり、鍵群への割当ても長文脈では重くなる。固定した保持率の各層への配分はモデル固有であり、別のアーキテクチャにそのまま移植できるとは限らない。原著の比較値は主としてB200上のFP16実験で、GPU世代やカーネル実装を変えた場合の実測は別途必要である。結論は「再構成型KV圧縮を現実的な前処理時間に近づける」ことであって、「あらゆるLLM要求の終端間遅延を25.73倍短縮する」ことではない。
