# MPCache：秘匿計算に適合するKVキャッシュの静的削除・動的選択

## 概要

大規模言語モデル（LLM）のKVキャッシュ圧縮は、通常のGPU推論では過去トークンの一部を削除・選択することで注意計算量とメモリを減らす。しかし、**秘匿分散計算（secure multi-party computation; MPC）では、トークンを選ぶ処理自体が高コスト**になる。各トークンの重要度を秘密にしたまま比較し、top-kを求め、秘密のインデックスに従ってKVを取り出すには、多数の暗号プロトコル通信が必要である。平文推論では高速な動的KV選択が、MPCではむしろフルKVより遅くなる場合がある。

MPCacheは、prefill後に不要なKVを一度だけ削除する静的選択と、デコードの各ステップで必要なKVを選ぶ動的選択を組み合わせる。動的選択では、隣接トークンをクラスタ化し、クラスタのキーの最大値・最小値からクエリとの類似度を安価に近似する。さらに粗いクラスタから細かいクラスタへ選択を絞り、近接Transformer層の選択インデックスを共有することで、MPC特有の比較と秘密インデックスgatherの費用を削減する。追加学習は不要である。

原著のNeurIPS 2025版では、SecretFlow/PUMAの3者MPC条件でフルKVと比較し、系列長とモデルに応じてデコード遅延を約1.26〜2.01倍、通信量を3.39〜8.37倍削減する。本文要旨では代表範囲を遅延1.8〜2.01倍とするが、Figure 10の詳細では1.26倍という小さい改善も存在する。**MPCの暗号計算と通信を含む測定であり、通常のCUDA上のトークン/秒の改善ではない**。LongBench等では保持KVを大きく削っても精度を比較的維持するが、タスクによって性能低下が残る。

## 問題設定：MPCではKV選択のコストが支配的になり得る

### 2者・3者の秘匿推論

MPCでは、ユーザーの入力やサービス提供者のモデル重みを複数の計算主体へ秘密分散し、各主体が自分の持つshareだけでは元の値を復元できないようにして計算する。論文はhonest-but-curious（手順は守るが、観測した情報から秘密を推測しようとする）脅威モデルを採用し、2者計算（2PC）と3者計算（3PC）を対象とする。演算の正しさと秘匿性はMPCプロトコルの前提に依存し、任意の悪意ある計算主体に対する耐性を無条件に主張するものではない。

通常のLLMデコードは、過去トークンのキーと値をキャッシュして再計算を避ける。系列長T、特徴次元dの注意では、全履歴を走査する処理が長文脈で重くなる。MPCでは特にsoftmaxの最大値・指数関数・除算などの非線形演算と、秘密分散データの通信が高価である。原著Figure 1はGPT-2の2PC/3PC実行で注意が遅延・通信の主要部分を占め、系列長が伸びるとsoftmax費用が急増することを示す。

### 平文用top-k・gatherの逆効果

一般的な動的KV選択では、現在のクエリqと過去のキーKから類似度を計算し、top-kのインデックスを求め、その位置のK,Vをgatherして疎な注意を行う。平文では通常の比較・インデックスアクセスとして実装できるが、MPCでは類似度の比較、秘密のtop-k、秘密インデックスに基づくgatherが通信と暗号演算を必要とする。とくに秘密インデックスからone-hotベクトルを作り、キャッシュと掛け合わせて要素を抽出する処理は高コストである。

そのため、注意に参加するトークンを5%へ減らしても、選択の費用が削減した注意計算を上回り、かえって遅くなることがある。原著Figure 1(d)とFigure 11は、平文用の動的選択をそのままMPCへ移植するだけでは改善しないという負の結果を示す。MPCacheの目的は単なるKV削除率の最大化ではなく、**選択・暗号通信・注意計算の合計費用を小さくすること**である。

## 手法

### 1. 三種類のトークンと二段階処理

著者らは過去トークンの注意寄与を三種類に分ける。多くの将来トークンから参照されるIA（important to all）は常に残す。ほぼ参照されないUIA（unimportant to all）は一度削除できる。特定の将来トークンだけに重要なIC（important to certain）は、デコード時のクエリに応じて選択する必要がある。原著Figure 2/3では、LLaMA-2-7Bの長い入力において約60%のトークンを静的に削っても性能を維持できる条件があり、各デコードステップでは残ったトークンの20%未満が強く寄与するという観察を報告する。

この観察に基づき、prefill段階でUIAを削除し、残りからデコード時にICを選ぶ。静的削除は一度だけなので比較費用を生成全体へ償却できる。動的選択は毎トークン繰り返すため、クラスタ単位で行い、層間共有などで高コストな暗号演算を抑える。重要なIAは静的選択で保護され、ICはクエリに応じて選び直せるため、固定ウィンドウ方式より柔軟性が高い。

### 2. Look-once静的削除

prefill時の注意重みを利用し、過去トークンがどの程度参照されるかを累積して重要度を求める。原著は、入力の最後の20%のトークンからの注意を集計すれば重要度の近似に十分な場合があると報告する。累積スコアの高いトークンを残し、低いトークンをUIAとして削除する。累積自体は局所演算で行え、秘密比較の費用は一度だけ発生する。

この段階では将来のクエリを知らないので、ICを全て安全に削除できるわけではない。原著Figure 3(a)では静的削除率を約60%よりさらに上げると性能が落ち始める。したがって、**最初に全てを削り切る方式ではなく、将来の質問で必要になる可能性があるKVを残す**ことが次の動的選択の前提となる。

### 3. 隣接トークンのクラスタ化

残ったKVを一つずつ比較する代わりに、近接するトークンをクラスタにまとめる。系列長Tのトークンを平均s個ずつのクラスタへ分ければ、比較対象はC≈T/s個となる。トークン単位の秘密top-kとgatherをクラスタ単位に置き換えることで、秘密比較の対象数とインデックスのビット幅を減らす。

原著Table 2の例では、T=1024のトークンをC=64クラスタへまとめ、25%を選ぶ条件で、秘密gatherのプロトコル遅延が4.780秒から0.065秒へ、通信が416.0MBから1.125MBへ減る。これは**gatherプロトコル部分だけ**の73.5倍・369.8倍の改善であり、LLM全体の推論が73.5倍速いという意味ではない。

クラスタが大きすぎると、重要な一部のトークンを残すために不要なトークンも一緒に残る。逆に小さすぎるとクラスタ数が増え、暗号比較が高価になる。MPCacheは粗いクラスタから細かいクラスタへ段階的に選択する階層構造を使い、費用と精度の折衷を図る。公式実装では粗いクラスタサイズ32、細かいクラスタサイズ16を既定値としている。

### 4. MPC-friendly類似度近似と線形化

現在のクエリqとクラスタ内の各キーkの内積を全て計算し、その最大値を取る方式は、重要なトークンを見落としにくいが、MPCでは比較が高価である。原著は各クラスタの各特徴次元について最大値r_maxと最小値r_minを事前に計算し、`max_k q·k`の上界を用いる。q_iの符号によって最大値と最小値を切り替える厳密な上界計算も、秘密比較を含む。

そこで、`Sim(q,K_c) ≈ Σ_i q_i [α r_max,i + (1−α) r_min,i]`という線形近似を採用する。係数αは実験で0.6に設定する。クラスタごとの括弧内の項を事前に合成できるため、デコード時にはクエリとの積和が中心となり、毎回のmax比較を省ける。原著は最大値・最小値を使う素朴な式と比べ、MPCのmax演算をゼロにし、必要な乗算を約半分にできると説明する。

この近似は**厳密な最大内積と同じ順位を保証しない**。原著Figure 7は平均キーを使う方式では品質が悪化し、提案近似は性能と遅延の折衷が良いことを示す。αの最適値はモデルやデータに依存し得るため、固定0.6を全条件の理論最適値とみなさない。

### 5. 階層選択と層間インデックス共有

粗いクラスタで候補を絞り、細かいクラスタで必要なKVを選ぶ階層選択により、全クラスタへ毎回同じ費用を掛けない。さらに、隣接するTransformer層ではクエリが参照するKV位置に共通性があることを利用し、選択インデックスを複数層で共有する。原著Figure 3(c)では近接層のtop-k集合に高い共通性があり、共有する層数が増えるほど共通性が低下することを確認する。

選択インデックスを共有すれば、秘密top-kを層ごとに再実行する費用が減る。しかし層間の注意パターンは完全一致ではないため、共有範囲を広げすぎると品質が下がる。MPCacheは層間共通性と暗号計算費用の交換条件を考慮する。インデックス自体も秘密分散されたまま扱うため、トークンの重要位置を外部へ公開する方式ではない。

### MPCデコード遅延・通信量（原著Figure 10）

原著は3PC、系列長512/1024/2048、静的削除率70%などの条件で、フルKV、LongCache、head merging、ArkValeと比較する。フルKV比で、条件別のデコード遅延は約1.26〜2.01倍、通信量は約3.39〜8.37倍改善する。系列長が伸びると暗号化softmaxとKV参照の通信費用が増えるため、削減の効果も変わる。LongCacheと比べた最大3.85倍の遅延改善と19.47倍の通信削減も報告される。

これらの倍率はMPCプロトコルを実行するLAN環境での結果であり、**通常のGPU上でFlashAttentionを実行した場合の倍率ではない**。GPU品質評価のA100 80GBと、SecretFlow SPUの暗号計算効率評価は実験目的が異なる。MPC通信量が8.37倍削減されても、モデル重み・KVキャッシュが同じ割合で小さくなるわけではない。

### アブレーションと選択費用（原著Table 2、Figure 11、Table 6）

Figure 11は、フルKVから静的削除、クラスタ化、線形化・演算順序変更、動的選択、層間インデックス共有へと機構を加えた比較である。静的削除だけでも通信・遅延を削減するが、動的選択を素朴に追加すると暗号比較とgatherが重くなる。クラスタ化と線形化によってその費用を下げ、最後に層間共有を加えることで、1024系列長の条件ではフルKV比約1.9倍の遅延改善と5.9倍の通信削減に到達する。

Table 6では粗いクラスタ32・細かいクラスタ16の構成で、選択比を変えるとF1と通信量が変わる。たとえば粗い段階0.5、細かい段階0.40ではF1 30.2、通信140.2MB、粗い段階0.3、細かい段階0.67ではF1 29.2、通信108.8MBとなる。通信を小さくするほど品質が一様に良くなるわけではない。粗いクラスタ64・細かいクラスタ16でも、F1と通信量の折衷が異なる。

Table 2の4.780秒→0.065秒、416MB→1.125MBという大幅改善は、**秘密インデックスgatherの部分プロトコルの理論・例示値**である。全LLMのデコード遅延の改善とは異なるため、これを推論全体の73.5倍高速化と誤記してはならない。

## 主要結果と解釈

第一に、平文用の動的KV選択はMPCへ直接移植すると高コストになる。重要トークンだけを選ぶための秘密top-kとgatherが、削減した注意計算より重くなることがある。したがって、MPCのKV圧縮では「保持率」だけでなく、選択プロトコルの通信と比較回数が設計対象となる。

第二に、静的削除と動的選択の役割分担が有効である。常に不要なUIAをprefill後に一度だけ捨て、クエリ依存のICをデコード時に選ぶことで、固定ウィンドウだけでは失われる長距離依存を保ちやすい。層間共有と階層クラスタは暗号化された選択の費用を削減するが、保持率や共有範囲を強くすると品質低下が残る。

第三に、MPCacheの価値は通常のGPU推論より**秘密分散されたインデックス・データに対する通信の削減**にある。3PCでデコード遅延約1.26〜2.01倍、通信量3.39〜8.37倍の改善は、プライバシーを保ちながら長文脈推論を高速化する方向性を示す。一方、通常のCUDAサービングや単一GPUローカルLLMで同倍率を得るとは主張できない。

## 既存研究との差

StreamingLLMは固定の重要位置や直近ウィンドウを残すため実装が単純だが、質問によって遠方の重要トークンが変わる場合に対応しにくい。H2OやSnapKVは累積注意や観測窓を使う静的選択に強みがあるが、将来のクエリに応じた柔軟な再選択は限定的である。InfLLM、LongCache、Questなどの動的方式はクエリ依存の重要度を利用するが、MPCではtop-kやgatherの暗号化費用が問題になる。

MPCacheは、通常の注意カーネルで高速な処理をそのまま暗号化するのではなく、**秘密比較・秘密インデックスアクセスを減らすために選択アルゴリズムを変える**。クラスタのキーの最大値・最小値から作る線形化スコア、粗密階層選択、層間インデックス共有が特徴である。MPC専用のプロトコル最適化とKVキャッシュアルゴリズムを共同設計する点が、平文向けKV圧縮との本質的な差である。

## 限界・負の結果・再現性

MPCの脅威モデルはhonest-but-curiousであり、悪意ある主体がプロトコルを逸脱する場合の保証を論文の結果から導けない。暗号計算の費用は使用する2PC/3PCプロトコル、LANの帯域・遅延、秘密比較の実装に依存する。評価した3PCの倍率を別のMPCライブラリやインターネット越しの高遅延環境へそのまま外挿できない。

KV削除・選択は近似であり、フルKVの品質を完全には保たない。Table 3のPassageRetrieval 5%はフル32.50に対しMPCache 19.75へ低下し、LongCache 21.42よりも低い。Table 5のTRECでもフル72.50に対しMPCache 69.50である。静的削除率やクラスタ粒度を強くすると、将来必要なトークンが失われる可能性がある。

提案の類似度は厳密な最大内積を計算しない。α=0.6の線形近似はMPCの比較費用を減らす代わりに順位誤差を許容する。クラスタを大きくすると通信費用は下がるが、不要トークンをまとめて選びやすくなる。隣接層のインデックス共有も、層ごとの注意が異なる場合は品質に影響する。これらは理論上の完全な精度保証ではなく、原著の評価条件で妥当な交換条件を示したものである。

品質評価はA100 80GBで、暗号計算効率評価はSecretFlow/PUMA 3PCで実施している。単一GPUの一般的なvLLM/SGLang/llama.cppにおけるprefill、TTFT、TPOT、ピークVRAM、量子化との組合せ、同時リクエスト処理は評価されていない。MPCacheをそのまま通常のCUDAサービングへ導入するだけで速度が上がる保証はない。

公開コードは`zwxandy/MPCache`で、LongBench評価、LLaMA向けKV選択実装、SecretFlow SPUのMPC評価コードが含まれる。原著のNeurIPS 2025版とリポジトリREADMEでは著者表記や細部が異なる可能性があるため、数値と書誌は**arXiv v2の本文を優先**した。環境依存のSecretFlow/PUMAプロトコル、GPU版の依存パッケージ、モデル重み、データセットの準備が必要であり、READMEのコマンドだけで全実験の完全再現が保証されるわけではない。
