# SqueezeAttention: 2D Management of KV-Cache in LLM Inference via Layer-wise Optimal Budget

## 概要
SqueezeAttentionは、KVキャッシュ圧縮を「各層の中でどのトークンを残すか」という系列方向だけでなく、「総KV予算をどの注意機構層へ配るか」という層方向まで含む二次元問題として扱う。既存のH2O、Sliding Window、StreamingLLMなどはトークン重要度の決め方が異なるが、通常は全層へ同じ保持トークン数を割り当てる。ところが著者らは、self-注意機構前後で隠れ 状態をどれだけ変えるかが層ごとに大きく異なり、同じトークン削減率でも品質への影響が違うことを観測する。

SqueezeAttentionはプリフィル中の実プロンプトから各注意機構層のimportanceを計算し、層をspecial / important / unimportantの3群へ分ける。重要度の低いGroup 3からKV budgetを回収し、Group 1/2へ再配分したうえで、各層固有budgetの中で既存系列-wise圧縮器を実行する。したがってH2O等のトークン スコアを置き換えるのではなく、その外側で層 allocationを最適化する管理層である。

7種類の6.7B〜70Bモデルと5データセットで、同じ品質を狙ったときFull Cache比でトークン当たりKV メモリを70〜80%削減する代表条件があり、系列-wise 比較対象比でも25〜66%削減する。8枚のA100 40GBで、Mistral-7Bは同一バッチ条件でFull Cache比最大2.2倍、Llama2-70Bは最大1.4倍のスループットを示す。

## 問題設定
decoder-only LLMでは、各層が過去トークンのK/Vを保持するため、KV容量は概ね「層数 × バッチ × 文脈 length × 隠れ幅」に比例して増える。論文の例ではLlama-2-7B FP16の重みが約14GBなのに対し、KVはトークン当たり約0.5MBで増え、合計28K トークン程度でモデル 重み容量を上回る。

系列-wise圧縮はこの文脈方向を疎にするが、全層へ同一budgetを与えると、注意機構出力がほとんど隠れ 表現を変えない層にも、強く変換する層と同量のKVを使う。総budgetが一定なら、低感度層から高感度層へトークン枠を移した方が、同じメモリで精度を保ちやすい。

一方、層importanceを固定のoffline calibrationだけで決めるとタスクやプロンプトが変わったときにずれる。実際、付録ではMistral-7BやLlama2-70Bのimportant 層数がdatasetによって変わる。そこでSqueezeAttentionは現在のプロンプトをプリフィルした際の活性値を使い、リクエストごとに配分を決める。

## 手法
### layer importanceの測定
各self-注意機構層について、注意機構 sublayerへ入るプロンプト 隠れ 状態と注意機構処理後の隠れ 状態の差を取り、その変化をcosine similarityで測る。入力と出力が非常に似ている層は、このプロンプトでは注意機構が表現へ与える影響が小さいとみなし、KVを強く削れる候補にする。逆に変化が大きい層はKV削除へ敏感な重要層として保護する。

この指標は追加の学習モデルを必要とせず、プリフィル時にすでに存在する活性値から計算できる。ただし真のタスク lossに対する因果感度を直接測るわけではなく、後述のgroupingとbudget係数で粗く扱う。

### 3群へのclustering
論文は7モデルで層 importanceに共通した3群構造を観測する。Group 1は主に最初と最後の少数層で、常に守るべきspecial 層として扱う。残りをK-meansでGroup 2（important）とGroup 3（unimportant）へ分ける。実験ではGroup 3が全層の約50〜70%を占める。

これは「単純な二群化」ではない。まず特殊層を別枠にし、その後で残りを増額対象と減額対象へ分ける3群policyである。多数clusterにしても最終的にはbudgetを減らすか増やすかへ還元されるため、著者らは3群を実装上の折衷として採用する。

### 総budgetを保存した再配分
全層一律の初期budgetを \(b_{init}\)、Group 3へ残す割合を \(p\) とする。Group 3は \(p b_{init}\) まで削り、その回収分をGroup 1/2へ等分して、全層の総KV budgetは変えない。したがって品質向上を「総メモリ増加」で買っているわけではない。

\(p\) が小さいほど再配分が強くなる。論文では0.3〜0.4が多くの条件で良く、Mistral-7B/SAMSUM、総KV budget 20%の感度実験ではROUGE-Lが \(p=0.3\) で37.26、0.4で37.69となる一方、0.1では15.7まで崩れる。低感度層でもbudgetを極端に削れば必要情報を失うため、再配分には下限がある。

### sequence-wise圧縮との合成
各層へ個別budget \(b^{(i)}\) を与えた後、その層のKVがbudgetを超えるたびに既存の系列-wise compressor \(C_{seq}\) を適用する。H2Oなら累積注意機構のheavy hitter、Sliding Windowならrecent トークン、StreamingLLMなら注意機構 sink + recent トークンという各方式固有の選択規則をそのまま使う。

したがってSqueezeAttentionの出力は「どのトークンを捨てるか」ではなく「この層には何トークン残せるか」である。層方向と系列方向が直交するため、複数のトークン圧縮方式へ重ねられる。

## 主要結果
同じbest accuracyを狙うTable 2では、Mistral-7B/SAMSUMでSqueezeAttentionは20% KV budgetでROUGE-L 41.05、best 比較対象のSliding Windowは30%で40.0、Full Cacheは43.53である。GPT-NeoX-20B/XSUMでは20% budgetで0.09を維持するのに対しH2Oは60%で0.08、Llama2-70B/XSUMでは30% budgetで0.17、StreamingLLMは40%で0.19となる。単純に「同一budgetで常に最高」というより、同程度の品質へ達するための必要budgetを下げるのが主効果である。

PyTorch Profilerで重み メモリを除いたトークン生成時メモリを測ると、これらの代表設定でFull Cache比70〜80%、best 系列-wise 比較対象比25〜66%の削減を報告する。特にGPT-NeoX-20BではH2Oの約3分の1のキャッシュ budgetで同等以上のスコアへ達する。

スループットは8枚のA100 40GBで測定する。Mistral-7B、プロンプト 512 + generation 1024ではSqueezeAttentionがバッチ 32で496.5 トークン/sに対しFull Cache 254.0、バッチ 64で682.7対304.8。SqueezeAttentionはバッチ 224まで892.5 トークン/sで動くが、Full Cacheはバッチ 128以上でout-of-メモリになる。Llama2-70B、プロンプト 256 + generation 512ではバッチ 32で116.2対84.8 トークン/s、SqueezeAttentionはバッチ 64で170.7 トークン/sまで拡張できる一方Full CacheはOOMとなる。論文の要約値では同一バッチ比較でMistral最大2.2×、Llama2-70B最大1.4×である。

層 importance計算とK-meansはプリフィル時に一度だけ行う。Mistral-7B、最大8K プロンプトのプロファイリングではプリフィル時間が0.636 sから0.676 sへ増え、オーバーヘッドは6.3%。デコード各段階でimportanceを再計算しないため、長いgenerationほどこの一回費用は相対的に小さくなる。

## 既存研究との差
H2O、Sliding Window、StreamingLLMなどは系列内のトークン重要度を設計するが、全層のbudgetは原則同一である。SqueezeAttentionはこれらを競合手法として置き換えるのではなく、各層へ異なるbudgetを与える上位allocatorとして組み合わせる。したがって既存トークン 枝刈りの改善をそのまま利用できる。

また固定層 枝刈りとは異なり、層そのものをスキップするのではなく、各注意機構層は残したままKV保持量だけを変える。タスクごとにimportant 層が多少変動するため、プロンプト時のonline測定を使う点も特徴である。

## 限界
論文自身が述べる前提は、組み合わせる系列-wise 追い出し法が「ある程度のキャッシュ削減ならaccuracyを許容範囲に保てる」ことである。この前提が崩れるモデル/タスクでは、層 budgetを巧く配っても救えない。SqueezeAttentionはトークン選択規則自体の失敗を補償する方式ではない。

importanceはself-注意機構前後のcosine similarityという代理指標で、タスク lossへの真の因果寄与ではない。3群化と単一 \(p\) も粗い近似であり、付録の感度実験が示すように削りすぎると急激に品質が崩れる。さらにプリフィルへ6.3%程度の追加費用があるため、短プロンプト・短generation・KVに余裕がある環境ではメモリ節約に対する相対的な利得が小さい。
