# SqueezeAttention: 2D Management of KV-Cache in LLM Inference via Layer-wise Optimal Budget

## 概要
SqueezeAttentionは、KVキャッシュ圧縮を「各層の中でどのtokenを残すか」という系列方向だけでなく、「総KV予算をどのattention層へ配るか」という層方向まで含む二次元問題として扱う。既存のH2O、Sliding Window、StreamingLLMなどはtoken重要度の決め方が異なるが、通常は全層へ同じ保持token数を割り当てる。ところが著者らは、self-attention前後でhidden stateをどれだけ変えるかが層ごとに大きく異なり、同じtoken削減率でも品質への影響が違うことを観測する。

SqueezeAttentionはprefill中の実promptから各attention層のimportanceを計算し、層をspecial / important / unimportantの3群へ分ける。重要度の低いGroup 3からKV budgetを回収し、Group 1/2へ再配分したうえで、各層固有budgetの中で既存sequence-wise圧縮器を実行する。したがってH2O等のtoken scoreを置き換えるのではなく、その外側でlayer-wise allocationを最適化する管理層である。

7種類の6.7B〜70Bモデルと5データセットで、同じ品質を狙ったときFull Cache比でtoken当たりKV memoryを70〜80%削減する代表条件があり、sequence-wise baseline比でも25〜66%削減する。8枚のA100 40GBで、Mistral-7Bは同一batch条件でFull Cache比最大2.2倍、Llama2-70Bは最大1.4倍のthroughputを示す。

## 問題設定
decoder-only LLMでは、各層が過去tokenのK/Vを保持するため、KV容量は概ね「層数 × batch × context length × hidden幅」に比例して増える。論文の例ではLlama-2-7B FP16のweightが約14GBなのに対し、KVはtoken当たり約0.5MBで増え、合計28K token程度でmodel weight容量を上回る。

sequence-wise圧縮はこのcontext方向を疎にするが、全層へ同一budgetを与えると、attention出力がほとんどhidden representationを変えない層にも、強く変換する層と同量のKVを使う。総budgetが一定なら、低感度層から高感度層へtoken枠を移した方が、同じmemoryで精度を保ちやすい。

一方、層importanceを固定のoffline calibrationだけで決めるとtaskやpromptが変わったときにずれる。実際、付録ではMistral-7BやLlama2-70Bのimportant layer数がdatasetによって変わる。そこでSqueezeAttentionは現在のpromptをprefillした際のactivationを使い、requestごとに配分を決める。

## 手法
### layer importanceの測定
各self-attention層について、attention sublayerへ入るprompt hidden stateとattention処理後のhidden stateの差を取り、その変化をcosine similarityで測る。入力と出力が非常に似ている層は、このpromptではattentionがrepresentationへ与える影響が小さいとみなし、KVを強く削れる候補にする。逆に変化が大きい層はKV削除へ敏感な重要層として保護する。

この指標は追加の学習モデルを必要とせず、prefill時にすでに存在するactivationから計算できる。ただし真のtask lossに対する因果感度を直接測るわけではなく、後述のgroupingとbudget係数で粗く扱う。

### 3群へのclustering
論文は7モデルでlayer importanceに共通した3群構造を観測する。Group 1は主に最初と最後の少数層で、常に守るべきspecial layerとして扱う。残りをK-meansでGroup 2（important）とGroup 3（unimportant）へ分ける。実験ではGroup 3が全層の約50〜70%を占める。

これは「単純な二群化」ではない。まず特殊層を別枠にし、その後で残りを増額対象と減額対象へ分ける3群policyである。多数clusterにしても最終的にはbudgetを減らすか増やすかへ還元されるため、著者らは3群を実装上の折衷として採用する。

### 総budgetを保存した再配分
全層一律の初期budgetを \(b_{init}\)、Group 3へ残す割合を \(p\) とする。Group 3は \(p b_{init}\) まで削り、その回収分をGroup 1/2へ等分して、全層の総KV budgetは変えない。したがって品質向上を「総memory増加」で買っているわけではない。

\(p\) が小さいほど再配分が強くなる。論文では0.3〜0.4が多くの条件で良く、Mistral-7B/SAMSUM、総KV budget 20%の感度実験ではROUGE-Lが \(p=0.3\) で37.26、0.4で37.69となる一方、0.1では15.7まで崩れる。低感度層でもbudgetを極端に削れば必要情報を失うため、再配分には下限がある。

### sequence-wise圧縮との合成
各層へ個別budget \(b^{(i)}\) を与えた後、その層のKVがbudgetを超えるたびに既存のsequence-wise compressor \(C_{seq}\) を適用する。H2Oなら累積attentionのheavy hitter、Sliding Windowならrecent token、StreamingLLMならattention sink + recent tokenという各方式固有の選択規則をそのまま使う。

したがってSqueezeAttentionの出力は「どのtokenを捨てるか」ではなく「この層には何token残せるか」である。layer方向とsequence方向が直交するため、複数のtoken圧縮方式へ重ねられる。

## 主要結果
同じbest accuracyを狙うTable 2では、Mistral-7B/SAMSUMでSqueezeAttentionは20% KV budgetでROUGE-L 41.05、best baselineのSliding Windowは30%で40.0、Full Cacheは43.53である。GPT-NeoX-20B/XSUMでは20% budgetで0.09を維持するのに対しH2Oは60%で0.08、Llama2-70B/XSUMでは30% budgetで0.17、StreamingLLMは40%で0.19となる。単純に「同一budgetで常に最高」というより、同程度の品質へ達するための必要budgetを下げるのが主効果である。

PyTorch Profilerでweight memoryを除いたtoken生成時memoryを測ると、これらの代表設定でFull Cache比70〜80%、best sequence-wise baseline比25〜66%の削減を報告する。特にGPT-NeoX-20BではH2Oの約3分の1のcache budgetで同等以上のscoreへ達する。

throughputは8枚のA100 40GBで測定する。Mistral-7B、prompt 512 + generation 1024ではSqueezeAttentionがbatch 32で496.5 token/sに対しFull Cache 254.0、batch 64で682.7対304.8。SqueezeAttentionはbatch 224まで892.5 token/sで動くが、Full Cacheはbatch 128以上でout-of-memoryになる。Llama2-70B、prompt 256 + generation 512ではbatch 32で116.2対84.8 token/s、SqueezeAttentionはbatch 64で170.7 token/sまで拡張できる一方Full CacheはOOMとなる。論文の要約値では同一batch比較でMistral最大2.2×、Llama2-70B最大1.4×である。

layer importance計算とK-meansはprefill時に一度だけ行う。Mistral-7B、最大8K promptのprofilingではprefill時間が0.636 sから0.676 sへ増え、overheadは6.3%。decode各stepでimportanceを再計算しないため、長いgenerationほどこの一回費用は相対的に小さくなる。

## 既存研究との差
H2O、Sliding Window、StreamingLLMなどは系列内のtoken重要度を設計するが、全層のbudgetは原則同一である。SqueezeAttentionはこれらを競合手法として置き換えるのではなく、各層へ異なるbudgetを与える上位allocatorとして組み合わせる。したがって既存token pruningの改善をそのまま利用できる。

また固定layer pruningとは異なり、層そのものをskipするのではなく、各attention層は残したままKV保持量だけを変える。taskごとにimportant layerが多少変動するため、prompt時のonline測定を使う点も特徴である。

## 限界
論文自身が述べる前提は、組み合わせるsequence-wise eviction法が「ある程度のcache削減ならaccuracyを許容範囲に保てる」ことである。この前提が崩れるmodel/taskでは、layer budgetを巧く配っても救えない。SqueezeAttentionはtoken選択規則自体の失敗を補償する方式ではない。

importanceはself-attention前後のcosine similarityというproxyで、task lossへの真の因果寄与ではない。3群化と単一 \(p\) も粗い近似であり、付録の感度実験が示すように削りすぎると急激に品質が崩れる。さらにprefillへ6.3%程度の追加費用があるため、短prompt・短generation・KVに余裕がある環境ではmemory節約に対する相対的な利得が小さい。
