# SqueezeAttention: 2D Management of KV-Cache in LLM Inference via Layer-wise Optimal Budget

## 概要
KVキャッシュ圧縮の多くは、各層の中で重要トークンを選び、古い・低注意機構 トークンを捨てる「系列方向」の最適化を行う。しかし全Transformer層へ同じKV budgetを割り当てると、トークン削除に敏感な層と鈍感な層へ同量のメモリを使う。SqueezeAttentionはこの均等配分を外し、層 importanceと系列-wise トークン importanceを組み合わせる二次元管理を行う。

プロンプトを処理したとき、各self-注意機構層の入力と出力の差をcosine similarityで測り、注意機構変換が表現を大きく変える層を重要とみなす。重要層には多く、低感度層には少ないKV budgetを割り当てる。その後、H2O、StreamingLLM等の既存トークン選択方式を各層固有budgetで動かす。論文は約30〜70%のKV メモリ削減と最大2.2倍スループット改善を報告する。

## 問題設定
同じトークン 追い出し率を全層へ適用する方式は実装が単純だが、層ごとの役割差を無視する。ある層では大量にトークンを削っても最終出力がほぼ変わらない一方、別層では同じ削減率で注意機構出力が大きく変わる。総KV容量が固定なら、前者から後者へbudgetを移した方が品質を保ちやすい。

層重要度をoffline calibration datasetで決める方法も考えられるが、入力分布が変われば感度が変わる可能性がある。SqueezeAttentionは実際のプロンプトから軽量にimportanceを測り、リクエストに応じた配分を狙う。

## 手法

### layer importance測定
各self-注意機構層について、層へ入る隠れ 状態と注意機構処理後の表現差をcosine similarityで測る。入力と出力が非常に近い層は、そのリクエストでは注意機構の寄与が相対的に小さいと解釈し、KVを強く圧縮する候補にする。逆に差が大きい層は情報変換への寄与が大きいとして保護する。

この測定はプロンプト処理中の既存活性値を使うため、別の学習モデルを必要としない。ただしimportance計算とbudget決定の追加処理があり、極端に短い文脈ではメモリ節約の価値が小さい。

### 二群化とlayer-wise budget
importanceに基づいて層を高重要度群と低重要度群へ分け、総KV budgetを不均等に配る。全層で平均budgetは同じでも、低感度層から削った分を重要層へ回すため、同じ総メモリで品質低下を抑えられる。

この層配分はトークン 追い出しそのものを置き換えない。各層へ「何トークン分保持できるか」を渡し、そのbudget内で系列-wise algorithmがどのトークンを残すかを決める。したがって層 dimensionと系列 dimensionを直交して最適化できる。

### 既存sequence-wise法との組合せ
論文は代表的な複数KV圧縮方式へSqueezeAttentionを重ねる。heavy hitter、recent windowなど各方式固有のトークン importanceはそのまま使い、均一budgetだけを層-awareへ変更する。そのため新しいトークン スコアを一から設計する方式ではなく、既存圧縮法の上位allocation 層として働く。

|項目|条件|
|---|---|
|対象|decoder-only LLMのKV キャッシュ|
|比較|均等層 budgetの代表的系列-wise KV圧縮法|
|組合せ|3種類の代表的トークン圧縮algorithm|
|評価|複数LLM・長文脈ベンチマーク|
|指標|KV メモリ、スループット、タスク品質|

## 主要結果
|条件|結果|意味|
|---|---:|---|
|複数モデル/ベンチマーク|約30〜70% KV メモリ削減|層とトークンの二方向で容量を絞れる|
|代表条件|最大2.2倍スループット|KV縮小がデコード メモリ 通信量/収容バッチへ反映|
|同一総budget|均等配分より品質維持|層 sensitivityを使う配分の価値を示す|
|複数系列-wise法との併用|一貫した改善傾向|特定トークン スコアだけに依存しない上位機構|

メモリ削減率とスループット倍率は同一条件の単一値ではなく、モデル・budget・組み合わせる圧縮法で変わる。低budgetほど容量利得は大きいが、重要層まで削る領域では品質との交換条件が強くなる。

## 既存研究との差
H2O、StreamingLLM等は主に「層内のどのトークンを残すか」を解く。SqueezeAttentionは「総budgetをどの層へ何個配るか」を先に解き、既存方式をその内側で利用する。したがって新規トークン 追い出し規則ではなく、既存KV圧縮を層-awareにする補完的な管理層である。

## 限界
importance 代理指標は注意機構層前後のcosine similarityであり、最終タスク lossへの真の因果寄与を直接測るものではない。二群化は実装を簡単にする一方、連続的な最適budget配分より粗い。またプロンプトごとの測定が必要で、短文脈やKV メモリが十分な環境では追加管理費用に対する利得が小さい。
