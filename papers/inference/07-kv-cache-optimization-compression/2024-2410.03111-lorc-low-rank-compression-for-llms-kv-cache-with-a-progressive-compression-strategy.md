# LoRC: Low-Rank Compression for LLMs KV Cache with a Progressive Compression Strategy

> KVキャッシュから「どのトークンを捨てるか」を決めるのではなく、キー・値を作る射影行列そのものを低ランク化する。さらに、浅い層の近似誤差ほど後段で増幅されやすいことを利用し、浅層は保守的、深層は積極的に圧縮する。

## 概要

自己回帰推論では、過去トークンのキー（Key）と値（Value）をKVキャッシュへ保存することで、次トークン生成のたびに過去系列を再計算せずに済む。その代わりKVキャッシュ容量は系列長とバッチサイズに比例して増える。長文脈・大バッチでは、モデル重みよりKVキャッシュが収容数を制限する場合がある。

既存のトークン追い出し方式は「どの過去トークンを残すか」を実行時に選ぶが、課題ごとの注意パターンへ依存しやすい。LoRCは別の軸を使う。キー・値射影行列を特異値分解（Singular Value Decomposition, SVD）し、元の隠れ次元より小さい低ランク次元へ射影した中間表現だけをキャッシュする。残りの分解因子をクエリ射影や出力射影へ融合することで、キャッシュを小さくしながら元の注意計算へ近い演算を維持する。

ただし全層を同じ比率で低ランク化すると、浅い層で生じた近似誤差が後続層を通って増幅される。LoRCは層ごとの累積条件数を感度指標として使い、感度が高い層には大きい圧縮後次元を、感度が低い層には小さい次元を割り当てる漸進的圧縮（progressive compression）を導入する。

## 問題設定

### トークン数を減らさずにKVの「幅」を減らす

通常の多頭注意（Multi-Head Attention, MHA）では、入力ベクトルをキー射影行列と値射影行列へ掛け、その出力をトークンごとに保存する。LoRCはこの射影行列に低ランク構造があることを利用する。

この方法では過去トークン自体を削除しないため、Heavy-Hitter型や最近傍保持型のようなトークン選択則を必要としない。また、複数クエリ注意（Multi-Query Attention, MQA）やグループ化クエリ注意（Grouped-Query Attention, GQA）のように学習時から注意構造を変える必要もない。既に学習済みのモデルへ後処理で適用できる点が狙いである。

### 一律圧縮では浅い層が危険

低ランク近似の誤差はその層だけで完結しない。浅い層の出力は多くの後続層を通るため、小さな誤差でも深いネットワークを通じて増幅され得る。論文の単層圧縮実験でも、LLaMA-3-Instruct-8Bの深い層15〜31は強く圧縮しても比較的安定だが、浅い層は敏感だった。

したがってLoRCの主要点はSVDそのものより、「どの層に何次元残すか」を誤差伝播の感度に合わせることにある。

## 手法

### 1. キー射影を低ランク分解し、低次元表現をキャッシュする

キー射影行列をSVDし、上位特異成分だけを残して二つの行列へ分ける。入力Xに対し、キャッシュへ保存するのは元のキー次元ではなく、圧縮後次元 (d_c) の中間表現である。これにより1トークン当たりのキーキャッシュ幅を元の (hd) から (d_c) へ縮める。

もう一方の因子はクエリ側へ事前融合する。したがってデコード時に「低次元キーをいったん完全なキーへ復元してから注意する」という追加経路を避け、圧縮空間でクエリとキーを対応させる。

### 2. 値射影も低ランク化し、復元因子を出力射影へ融合する

値側も同様にSVDするが、注意後に値を元次元へ戻す因子は出力射影へ融合する。実行時には低次元値をKVキャッシュへ保存し、注意重みとの積を取った後、その結果を融合済み出力射影へ渡す。

キーではクエリ射影へ、値では出力射影へ因子を押し込むため、低ランク化で増える行列積を既存の注意経路へ吸収できる。

### 3. 層ごとの感度を累積条件数で表す

著者らは各層の近似誤差が後段へ伝播する上界を解析し、層感度を累積条件数で表す。直感的には、浅い層ほど後ろに多くの変換が残っているため、同じ局所誤差でも最終出力へ与える影響が大きくなりやすい。

この感度を対数スケールで正規化し、圧縮後次元 (d_c^l) を (d_{min}) と (d_{max}) の間で層ごとに割り当てる。感度が高い層ほど (d_c^l) を大きく、感度が低い層ほど小さくする。

### 4. 高感度層は圧縮対象から外す

実装では累積条件数へ閾値を設け、極端に敏感な層は圧縮しない。LLaMA-3-Instruct-8Bでは閾値30、LLaMA-2-13BとLLaMA-3-Instruct-70Bでは90を使用する。残りの層へ漸進的な次元配分を行う。

比較用の一律圧縮基準も同じ高感度層を非圧縮にするため、漸進配分そのものの効果を比較できる。

### 5. RoPEとMHA/GQAへ合わせる

回転位置埋め込み（Rotary Position Embedding, RoPE）はキーへ位置依存回転を掛けるため、低ランクキーをそのまま通常経路へ置き換えるだけでは整合しない。LoRCは回転とキー射影の一部をクエリ計算へ組み込み、圧縮キーをキャッシュしたままRoPE互換の注意を構成する。

MHAだけでなくGQAにも対応し、LLaMA-3のように既にKVヘッド数を削減したモデルでも、隠れ次元方向をさらに圧縮する。

## 評価

### 評価条件

| 項目 | 条件 |
| --- | --- |
| モデル | LLaMA-2-13B（MHA）、LLaMA-3-Instruct-8B / 70B（GQA） |
| 課題 | BoolQ、XSum、OpenBookQA、GSM8K |
| 指標 | BoolQ/OpenBookQA/GSM8Kは正解率、XSumはROUGE-LSum |
| few-shot | LLaMA-2のBoolQのみ2-shot、その他は0-shot |
| ハードウェア | 13B/8Bは4×A100、70Bは8×V100 |
| メモリ比較 | batch 64、系列長2048 |
| 比較 | 非圧縮、同じ非圧縮層を固定した一律圧縮、LoRCの漸進的圧縮 |
| 学習 | 再学習なし。オフラインSVDのみ |

### 主要結果

| 条件 | 非圧縮KV | LoRC KV | 圧縮率 | 平均性能低下 |
| --- | ---: | ---: | ---: | ---: |
| LLaMA-2-13B | 50 GB | 27.5 GB | 55% | 0.47% |
| LLaMA-3-8B | 8 GB | 4.8 GB | 60% | 0.92% |
| LLaMA-3-70B | 20 GB | 11 GB | 55% | 0.22% |

この表の平均性能低下は、論文の定義に従いGSM8Kを除外した4課題平均である。GSM8Kでは圧縮によって10%以上良くなる例があり、それを平均へ入れると「圧縮による劣化」が過小評価されるためである。

浅層感度の検証では差がさらに明瞭である。OpenBookQAでLLaMA-3-Instruct-70Bの非圧縮精度は91.2、LoRCの60%全体圧縮も91.2だった。一方、第0層だけを50%圧縮すると84.2、最初の1/8層を圧縮すると23.2まで落ちた。LLaMA-3-Instruct-8Bでも78.0の基準に対し、浅い1/8層圧縮は61.4となる。単純に「同じ総圧縮率ならどの層を削っても同じ」ではないことを直接示している。

最大モデルLLaMA-3-Instruct-70Bの全80層SVDはNumPyで約40秒と報告され、オフライン前処理としては小さい。

## 既存研究との差

トークン追い出し方式は系列長方向を圧縮するのに対し、LoRCは各トークンのキー・値ベクトルの隠れ次元を圧縮する。そのため両者は原理上併用可能である。

MQA/GQA/MLAのような注意構造変更は学習時または追加学習を前提にすることが多いが、LoRCは既存重みへ後処理で適用する。Paluなど後続の低ランクKV圧縮と比べたときの中心的特徴は、誤差伝播解析を層別圧縮率へ直接結び付けた点である。

## 限界・実装状況

評価はKV容量とタスク品質を中心としており、モデル全体のトークン/秒高速化を主結果として示す論文ではない。キャッシュが小さくなればメモリ帯域や収容数には有利だが、低ランク演算の実カーネル効率次第では容量削減率がそのまま速度向上率になるわけではない。

層感度の閾値と圧縮後次元はモデルごとに設定されており、別アーキテクチャへ移す場合は条件数分布を再計算する必要がある。また極端な圧縮では低ランク仮定が崩れ、品質を保てない。
