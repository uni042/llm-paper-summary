# KV Cache Compression for Inference Efficiency in LLMs：推論時KV圧縮の手法と比較上の注意

## 概要

本論文は、大規模言語モデル（LLM）の自己回帰推論で増加する鍵・値キャッシュ（key-value cache、KVキャッシュ）のメモリ使用量を抑える技術を整理した**レビュー論文**である。長文脈や多数の同時要求を扱うと、各層・各トークンのK/Vを保存する容量が増え、GPUメモリが配信可能な文脈長とバッチ数を制約する。著者はKV圧縮を、重要なトークンを選んで残す方式、K/Vのビット幅を下げる量子化、注意構造やヘッドの冗長性を利用する方式、複数の技術を組み合わせる方式に分類する。

このレビューの価値は、KV圧縮の設計空間を俯瞰し、**何を減らすか**（保存トークン数、要素のビット数、層・ヘッド間の重複、注意計算）と**何を守るか**（検索精度、生成品質、遅延、スループット）を切り分ける点にある。重要な限界として、原著自身は統一条件のGPU実験を実施していない。表中の速度倍率、圧縮率、パープレキシティは、異なる一次論文のモデル、データセット、GPU、文脈長、バッチ条件から抜き出されたものである。**一つのベンチマークのランキングとして比較してはならない**。

論文の将来方向は、選択・量子化・注意構造を組み合わせる複合圧縮、入力や負荷に応じた動的適応、ハードウェアとソフトウェアの共同設計である。これらはレビュー著者による研究課題の提案であり、実装して速度を実測した新手法ではない。たとえば本文に登場するCacheBlendの2.8～5倍、KIVIの2.35～3.47倍、PyramidInferの1.7～2.8倍などは、それぞれの先行研究の条件に依存する値で、レビューが独自に再測定した数字ではない。

## 問題設定：KVキャッシュが推論を制約する理由

自己回帰型Transformerは、新しいトークンを生成するたびに過去の全トークンを再計算しないよう、各層のK/Vを保持する。層数をL、KVヘッド数をH、ヘッド次元をD、系列長をT、同時要求数をB、要素の保存バイト数をsとすると、基本的なキャッシュ容量は概ね2×L×H×D×T×B×sで増える。注意演算を高速化しても、キャッシュを保持するVRAMと読み出すメモリ帯域がボトルネックになる場合がある。特に長い入力や多くの同時要求を扱うサービングでは、モデル重みだけでなくキャッシュの占有量が最大バッチ数を決める。

KV圧縮の効果は二種類に分ける必要がある。第一は容量削減であり、同じVRAMにより長い履歴やより多くの要求を置ける。第二は実行速度改善であり、注意計算で読み込むKV量を減らす、あるいはバッチ数を増やしてGPUをより高い稼働率で使うことで得られる。容量を半分にしても、量子化の復元計算や非連続アクセスが増えれば単一要求の速度は必ずしも向上しない。逆に単一要求の速度が同じでも、最大同時要求数が増えれば総スループットは改善する可能性がある。

レビューは主に推論時のKVを対象とする。重みの量子化や低ランク適応学習、投機的復号そのものとは対象が異なる。重み量子化でモデル重みのVRAMを節約しても、長文脈時のKVキャッシュが同じビット幅ならKV使用量は変わらない。KVの低ビット化や削除は、モデル重みとは別に適用・評価する必要がある。

## 手法

### 1. 重要トークン選択と追い出し

トークン選択型（KV pruning / eviction）は、すべての過去トークンのK/Vを保存する代わりに、重要度が高いと推定したトークンだけを残す。入力は過去トークンのKVと注意スコア、層・ヘッドごとの状態などであり、選択器が残す位置を決め、残りをキャッシュから削除する。容量は保持トークン数にほぼ比例するため、例えば半分の位置だけ残せば論理的なKV要素数を半分にできる。ただし、削除したトークンを後で参照したくなっても元の情報は失われる。

レビューが挙げるZigZagKVは層の注意や隠れ状態の不確実性に応じて容量予算を割り当てる。NACLは代理トークンとランダムな追い出しを組み合わせる。RazorAttentionは注意ヘッドの性質を利用し、補償トークンを使って重要情報を残す。PyramidInferは層間・トークン間の冗長性を利用して階層的にキャッシュを削る。これらはすべて「トークンを消す」点で似ていても、重要度をどこから推定するか、層・ヘッドごとに予算をどう配分するか、補償情報をどう持つかが異なる。

この系統は長文脈の検索や情報抽出で、遠い位置にある一つの重要トークンを誤って削除すると大きく品質が落ちる危険がある。注意スコアが低いことは将来の質問に不要であることの保証ではない。レビューは各方式の代表的な速度・圧縮値を列挙するが、同じタスクで一律に精度を保証したものではない。

### 2. KV量子化によるビット幅削減

量子化型（KV quantization）は、保存するトークン数を維持しながらK/Vの各要素を低ビット表現へ変換する。FP16を4ビットへ置き換えると理論上の生データ量は1/4になるが、スケール、ゼロ点、外れ値処理、グループ情報などの追加メタデータが必要になるため、実メモリは単純な4分の1と一致しない。低ビットK/Vを注意計算で使うために復元や専用カーネルが必要な場合もある。

KIVIはKとVで量子化軸を変える非対称2ビット量子化を採用し、KVQuantは外れ値を意識した量子化と専用CUDAカーネルを使う。Coupled Quantization（CQ）は複数チャネルの依存関係を考慮し、QAQは感度に応じて精度を配分する。Lexicoは辞書に対する疎な線形結合でKVを表す。これらは「低ビット化」という共通点があっても、K/Vのどの軸でスケールを持つか、外れ値を別に保存するか、量子化誤差をどの程度許容するかが異なる。

量子化はトークンを捨てないため、長い履歴の検索ではトークン追い出しより有利になる場合がある。ただし、2ビット化がすべてのモデル・タスクで品質無損失になるわけではない。小さい値域や外れ値の多いチャネル、RoPE適用前後のK表現、長文脈での誤差蓄積などに注意が必要である。ビット数だけでなく、量子化グループサイズとカーネル実装を合わせて比較する必要がある。

### 3. 注意構造と層・ヘッドの冗長性の削減

注意構造型（attention compression）は、各層・各ヘッドが保持するKVの重複を利用する。層間で類似したKVを共有するKVSharer、注意ヘッドの特性に応じて保持量を変える方式、注意計算を疎にする方式などが含まれる。重要トークンの選択と重なるものもあり、レビューの分類は相互排他的な厳密分類ではない。

レビューはH2O、Keyformer、ALISA、SQUEEZEATTENTION、PyramidInfer、POD、L0-Orthoなどを挙げる。H2Oは注意の重要度を使って保持するKVを選ぶ。Keyformerは注意重みの分布を利用して重要位置を残す。SQUEEZEATTENTIONは層間の類似性からキャッシュを減らす。PODは類似層のグループ化や注意集約を利用する。L0-Orthoは直交変換と蒸留学習を用いる。これらは注意演算の構造や学習方法を変えるものもあり、単純な推論時フラグで有効化できるとは限らない。

注意ヘッド間・層間の共有は、保存する要素数だけでなく参照先を変えるため、既存モデルとの互換性が問題になる。例えば層間共有は同じキャッシュを複数層から参照する実装を必要とし、学習済みモデルの重み構造によっては追加学習が必要になる。論文中の「attention compression」は単一の標準化されたアルゴリズム名ではなく、複数の方式を束ねる分類名である。

### 4. 複合方式と配信基盤の最適化

複合方式（hybrid methods）は、トークン選択、量子化、注意構造の削減を同時または段階的に適用する。例えば重要なトークンだけを高精度で残し、それ以外を低ビットで保存する方法や、KVの一部を再計算しながらキャッシュ済みの知識を融合する方法がある。レビューが取り上げるCacheBlendは複数のテキストブロックのキャッシュ融合、GEARは量子化誤差の補償、PQCacheは積量子化と検索、DistAttentionは計算資源の配分を扱う。これらは最適化対象が必ずしも同じではない。

複合方式で注意すべき点は、二つの手法の容量削減率を単純に足してはいけないことである。トークン数を半分、要素ビット幅を半分にすると、理論上のKV生データ量は元の1/4になるが、メタデータやインデックス、カーネルの実行費用が増える。さらに、トークン選択の重要度を量子化された注意値から推定すると、量子化誤差が選択結果に影響する可能性がある。個別方式の実験結果を掛け合わせただけで、複合時の実測スループットを求めることはできない。

### 性能とスループットの比較図の扱い

原著第6節は、KVSharer、NACL、RazorAttention、CQ、KVQuantなどの改善率を図示し、CacheBlendやDistAttentionの処理量改善を比較する。しかしモデル構成や測定条件が揃った対照実験ではない。例えばCacheBlendはRAG入力の複数知識ブロックの再利用を扱い、KIVIはKVの低ビット表現を扱う。改善の分母が異なるため、図で棒が高い方式をそのまま「すべての用途で最速」と解釈するのは誤りである。

論文中には分類・単位・引用番号に曖昧さが残る箇所もある。例えば「inference efficiency (%)」の定義が表全体で統一されておらず、パープレキシティを百分率のように示す列もある。これらは一次資料の再照合なしに精密な比較数値として使うべきではない。原著が収集した結果を参考値として紹介する場合は、必ず元の実験のGPU、バッチ、モデル、文脈長、評価指標を添えることが必要である。

### 何が実測されていないか

本レビューは、複合圧縮を同じモデルへ適用したときの追加効果、量子化と追い出しの干渉、GPUカーネルの融合費用、CPU/SSDオフロード、GPU間通信を統一環境で測っていない。長文脈の検索精度、生成品質、トークン間遅延、メモリピーク、電力量を横断的に同じ指標で評価した表もない。レビュー著者自身のコード実装や統一測定スクリプトの公開も確認できない。したがって、サーベイを読んだだけで特定GPU向けの最適構成を数値で決定することはできない。

## 将来方向と設計上の論点

### 複合圧縮の相互作用

トークン選択と量子化を組み合わせると、保存するトークン数とビット幅の両方を減らせる。一方、選択に使う注意スコアが低精度になると重要度推定が不安定になり、検索タスクで必要な位置を消してしまう可能性がある。どの順序で量子化・選択・キャッシュ融合を適用するかによって結果が変わるため、単独方式の倍率を足し合わせるだけでは十分ではない。

### 入力・負荷に応じた動的な適応

入力の長さ、タスク、要求到着率、GPUメモリの残量に応じて圧縮率や保持位置を変える方式が将来方向として挙げられる。例えば短い対話では圧縮を弱くし、長文脈の検索では重要位置を保持しながら低ビット化する、といった方針が考えられる。ただし、タスクの必要精度や将来参照する位置を正確に予測するのは難しく、動的な方針決定の計算費用が利得を相殺する可能性もある。

### ハードウェアとソフトウェアの共同設計

同じKV圧縮率でも、GPUのメモリ帯域、低ビット演算の対応、ページ管理、カーネル起動費用によって速度は変わる。量子化されたKVを毎回FP16へ復元する方式と、低ビットのまま注意計算する方式では、メモリ転送と演算の交換条件が異なる。CPU/SSDオフロードを組み合わせる場合は、圧縮されたKVの転送バイト数だけでなくPCIeの帯域・遅延も考慮する必要がある。レビューはこれらを今後の課題と位置づけるが、特定の共同設計を実装した結果ではない。
