# KVmix：勾配感度によるKVキャッシュの層別混合精度量子化

## 概要

KVmixは、長い文脈や多数の同時要求でGPUメモリを圧迫するKVキャッシュを、モデルの品質に影響しやすい層と影響しにくい層に分けて量子化する方式である。各層のKeyとValueを生成する投影行列の損失勾配を使って重要度を計算し、重要な層だけ高いbit幅を与える。さらに直近の重要なKV（Recent Pivotal Context; RPC）をFP16で保持し、古いKVを段階的に量子化する。実装では量子化・連結と復号・行列ベクトル積をそれぞれ融合したCUDAカーネルを用いる。〔AAAI 2026版§Methodology、Fig.3–4〕

Llama 2-7Bの代表設定では、Key平均2.1875ビット、Value平均2.375ビットで、KVの動的ピークメモリをFP16比4.9分の1へ削減する。RTX 4090 24GBで入力688トークン・最大生成1024トークンの実験では、最大バッチサイズを増やせることを含めた処理率が194.06から1032.06 tokens/sへ上昇する。ただしこれは同一バッチサイズで1要求が5.32倍速くなるという意味ではない。LongBenchの入力長は最大4096トークンに制限されており、32Kや128Kの長文脈精度は実証されていない。〔Fig.7–8、Table 1–3〕

## 問題設定

自己回帰生成では、過去のKeyとValueを再計算せず再利用するため、系列長に比例してKVキャッシュが増える。複数要求を同時処理するサービングでは、モデル重みは共有できても要求固有のKVを共有できない。したがってKV容量がGPU高帯域メモリを圧迫し、バッチを増やせず、オフロードが発生すると転送が律速となる。均一な2ビット量子化は容量を削減するが、どの層も同じ精度でよいわけではない。

KVmixの動機となるFig.1は、Llama 2-7Bの異なる層だけを2ビットへ量子化したとき、GSM8KとTruthfulQAの精度への影響が層・Key/Valueによって異なることを示す。Keyの特定層が重要でも、同じ層のValueが同程度に重要とは限らない。層全体を同一bit幅にする方法では、その差を利用できない。一方、推論の各ステップで全KVの重要度を精密に推定し続ける方式は、その計算自体が生成速度を損なう。著者は、モデルの固定投影重みを使った**オフラインの感度分析**と、生成時の**軽量な直近KVの保持**を組み合わせる。〔Fig.1–2、§Motivation〕

## 手法

### 1. Key/Value投影行列の勾配ノルムで重要度を測る

各Transformer層iで、前段の隠れ状態Hから `K_i=W_{k,i}H`、`V_i=W_{v,i}H` を計算する。量子化誤差ΔK、ΔVがモデル損失Lに与える影響を一次Taylor近似すると、損失変化はKey/Valueに対する勾配と量子化誤差の内積で近似される。誤差が同程度なら、勾配ノルムが大きいKVほど損失へ与える影響が大きい。そこで重み投影行列の勾配 `∇_{Wk_i}L`、`∇_{Wv_i}L` のL2ノルムを、層別Key/Value重要度の代理指標とする。〔原著Eq.1–11〕

手順は、全精度モデルへ対象データから抽出した複数のプロンプトを入力し、次トークン予測損失を計算して逆伝播し、層ごとにKey投影重みとValue投影重みの勾配ノルムを取得する。複数プロンプトの値を平均して偶然の入力への依存を減らす。重要度はKeyとValueで**別々に順位付け**する。出力は各層のK/V重要度スコアと、後段の量子化bit割当である。代表実験ではLongBenchから30プロンプトを用い、同一環境でのプロファイル所要時間は10～15分だった。推論中に逆伝播を行う方式ではなく、この前処理結果を後の要求で再利用する。〔原著Fig.3、§Profiling Results〕

### 2. 層ごとにKの2/3ビットとVの2/4ビットを選ぶ

平均重要度の上位20%を高精度層として選び、Keyは3ビット、Valueは4ビット、残り80%はそれぞれ2ビットとする。KeyとValueは独立に順位付けするので、高精度化する層集合が一致するとは限らない。高精度層の割合は性能要件に応じて変更可能だが、代表実験では20%が精度・容量・処理率の折衷点となった。32層モデルの平均bit数はKey `(6×3+26×2)/32=2.1875`、Value `(6×4+26×2)/32=2.375` に相当する。〔原著Fig.5–6〕

重要度の順位は固定モデルの投影行列から得るため、各要求の実行時に全層のbit幅を探索する必要はない。高精度層の割合を10%や30%へ変えると、品質とメモリの交換条件が変化する。これは**モデル単位の事前設定**であり、入力プロンプトごとにbit幅をリアルタイムで再選択する機構とは区別すべきである。論文も将来課題として実行時のbit幅調整を挙げている。

### 3. Keyはチャネル別、Valueはトークン別に非対称量子化する

KVテンソルの形状を `[batch, heads, tokens, head_dim]` とすると、Keyはチャネル方向の外れ値が顕著なので、各チャネル内の時系列値を一組として量子化する。これにより大きな値を持つ一部チャネルの量子化範囲が、他チャネルの分解能を不必要に下げることを避ける。Valueはトークン単位でhead内のチャネルを一組とし、あるトークンの分布を別トークンへ波及させない。両者を同じ「トークン別2ビット」にする対称的方式とは異なる。〔原著§Asymmetric Low-Bit Quantization〕

各グループの最小値・最大値からスケールを決め、整数値へ丸め、クリップし、復号時には `x≈q·scale+min` で復元する。1/2/4ビットは32ビット整数へ素直に詰め込めるが、3ビットは32を割り切れない。そこで**10個を3ビット、最後の1個を2ビット**として32ビットに11要素を格納する。3ビットを10個だけ格納する方式より要素数が10%増えるが、11番目は2ビットなので「11個すべてが3ビットの精度」と誤解してはいけない。量子化の実効精度と格納効率の折衷である。〔原著Eq.12〕

### 4. RPCで直近重要KVをFP16保持し、古い分を量子化する

直近トークンのKVをRecent Pivotal Context（RPC）としてFP16で残し、それ以外を上記の層別bit幅へ量子化する。重要度の高い層ではRPC比率を20%、低bit層では10%に設定する。各時刻で新しいKVと前時刻までのRPCを候補とし、`floor(r×current_RPC)` 個をFP16で保持するよう再選択する。ここで`current_RPC`は現在の新規KV数と過去に保持したRPC数の合計である。KeyとValueの重要度が異なる場合、同じ層でもそれぞれのRPC比率を変えられる。〔原著Fig.4、§Dynamic Pivotal Context Selection〕

新しいトークンが増えるたびにFP16領域を無制限に増やすのではなく、候補集合から保持数を調整し、選外となった古いKVを低bitで保存する。従来の「固定数のFP16残差を永久保持する」方式と比べ、系列が長くなった際の容量を抑える狙いがある。ただし、全履歴の情報をFP16のまま残すわけではないため、古い位置にある重要情報の復元品質は量子化誤差に左右される。RPCは重要な過去位置を任意に完全検索する保証ではない。

### 5. CUDA融合カーネルで量子化の追加費用を抑える

KVを量子化してから過去KVへ連結する実装では、量子化出力の書込みと連結用の読書きが重複する。KVmixは量子化とキャッシュへの連結を一つのCUDAカーネルへ融合し、新しいKVを量子化しながら既存キャッシュへ直接追記する。共有メモリを使って中間データの局所性を高め、メモリ往復を減らす。〔原著§CUDA Implementation〕

また、量子化KVを先にすべてFP16へ復号すると、復号後の巨大な中間テンソルをHBMに置く必要がある。KVmixは復号と行列ベクトル積を融合し、要素を読み出した時点で復号して積和へ渡す。1/2/3/4ビットに対応する量子化・復号カーネルと行列ベクトル積を用意するため、層ごとに異なるbit幅でも実行できる。量子化率だけでなく、このメモリ読み書きの削減が実際の生成処理率を左右する。〔原著§CUDA Implementation〕

## 評価

### モデル、GPU、入力長と評価軸

対象はLlama 2-7B-hf、Llama 3-8B-Instruct、Llama 3.1-8B、Mistral-7B-Instruct-v0.3、Falcon-7B。長文脈評価はLongBenchの8データセット、言語モデル品質はWikiText-2の困惑度、数学推論はGSM8Kの正答率を使う。LongBenchはGPUメモリ制約のため**最大4096トークン**に切られている。実行効率とKVメモリはRTX 4090 24GBで測定した。混合精度の代表設定はKの上位20%を3ビット、Vの上位20%を4ビット、残りを2ビット、グループサイズ32、RPC比率は高bit層20%、低bit層10%である。〔原著§Experimental Setup、§Profiling Results〕

### 重要度の有効性とRPCの寄与

LongBenchの4モデル平均では、FP16からの平均スコア低下が全層2ビットのKVmix-2bitで4.53%、高bit層をランダムに選ぶ設定で4.06%、勾配感度で選ぶKVmix-k2.19v2.38で1.67%となる。高bit層を増やすこと自体だけではなく、**どの層を選ぶか**が重要である。同じ混合精度からRPCを外すと、RPC付きに対して平均スコアが3.28%低下する。これにより、層別bit割当と直近FP16保持の両方が精度を支えると読める。〔原著Table 1、Fig.5〕

| Llama 2-7B・LongBench 8課題平均 | スコア（高いほど良い） |
|---|---:|
| FP16 | 33.839 |
| KIVI-2bit-r64 | 33.216 |
| QJL-3bit | 33.486 |
| KVQuant-3bit-1% | 33.703 |
| KVmix-k2.19v2.38 | **33.714** |
| KVmix-k2.28v2.56（高bit層30%） | **33.814** |

この表では代表KVmixのスコアはFP16に近く、KIVIより高い。一方、KVQuantとの差は0.011ポイントと小さく、提案法があらゆるベンチマークで大幅な精度優位を示したわけではない。高bit層30%ではFP16との差をさらに縮めるが、KVキャッシュの容量節約は相応に減る。個別課題ではQasperやQMSumなどで提案法がFP16を上回る項目もあるが、測定誤差やサンプル差を考慮せず「量子化で能力が増えた」と結論しない。〔原著Table 2〕

### 数学推論と量子化粒度の悪化例

| Llama 2-7Bの方式 | GSM8K正答率↑ | WikiText-2 PPL↓ |
|---|---:|---:|
| FP16 | 13.52% | 8.71 |
| Key/Valueともトークン別2bit、RPCなし | **0.83%** | **11089** |
| Key/Valueともトークン別4bit、RPCなし | 12.28% | 9.17 |
| KVmix全層2bit | 11.80% | 8.73 |
| 高bit層ランダム選択 | 11.97% | 8.73 |
| KIVI-2bit-r64 | 12.75% | 8.80 |
| QJL-3bit | 13.11% | 8.75 |
| KVQuant-3bit-1% | 13.23% | 8.71 |
| **KVmix-k2.19v2.38** | **13.25%** | **8.71** |

KeyとValueを同じトークン別量子化にする素朴な2ビット方式は、GSM8Kが13.52%から0.83%へ崩壊し、PPLが11089へ悪化する。これは単なる「2ビット一般」の失敗ではなく、Keyのチャネル別処理を使わずRPCもない比較条件の結果である。KVmixはKey/Valueの粒度を変え、層別bit幅とRPCを併用することで、この悪化を大幅に回避する。ただしGSM8Kの絶対正答率はFP16でも13.52%と低いモデル設定なので、現在の高性能推論モデルに対する数学能力を直接推定できない。〔原著Table 3〕

### 動的KVメモリと最大処理率

速度・容量測定はLlama 2-7B-hf、入力688トークン、最大生成1024トークン。メモリはバッチ4で、**モデル本体の事前占有メモリを引いた推論中の動的ピークメモリ**を比較する。したがって「GPU全体のVRAMを4.9分の1にした」という意味ではない。Fig.7の圧縮率はAtom-4bit 3.6倍、KIVI 4.6倍、KVQuant 4.8倍、QJL 5.0倍、KVmix 4.9倍（FP16基準）。QJLの方がわずかに大きい圧縮率を示すが、KVmixは精度と処理率を合わせた折衷を狙う。〔原著Fig.7〕

| RTX 4090 24GB、最大バッチ探索 | 最大処理率（tokens/s） | FP16比 |
|---|---:|---:|
| FP16 | 194.06 | 1.00倍 |
| KVmix-k2.19v2.38 | **1032.06** | **5.32倍** |
| KIVI-2bit-r64 | 871.78 | 4.49倍 |
| KVQuant-3bit-1% | 859.23 | 4.43倍 |
| Atom-4bit | 918.74 | 4.73倍 |
| QJL-3bit | 353.62 | 1.82倍 |

KVmixは最大バッチ30で1032 tokens/sに達する。一方、FP16はバッチ4でメモリ不足、Atomは18、KIVIは28でメモリ不足となる。ここでの5.32倍は**最大収容バッチサイズを増やせた効果を含む処理率**であり、同じバッチ・同じ系列長での1要求の生成遅延が5.32分の1になったとは言えない。原著の図は各方式で異なる最大バッチにおける比較である。RTX 4090 24GB以外のGPU、PCIeオフロードを含む環境、12GB VRAMで同じ倍率を期待する根拠もない。〔原著Fig.8〕

## 既存研究との差

KIVIはKeyをチャネル別、Valueをトークン別に量子化するが、FP16残差を固定数で残す。KVQuantは外れ値処理を伴う低bit量子化、QJLは追加定数を抑える量子化、KVTunerは層別精度の探索最適化を行う。KVmixはK/V投影重みの勾配ノルムから層別のbit幅を比較的短時間で決定し、さらにRPCを更新して古いFP16残差を縮小し、復号融合CUDAで処理率を補う。〔原著§Related Work、§Methodology〕

この組合せは、精度を守る高bit層の選択と、実行時に保持するFP16領域の縮小という異なる時間尺度の判断を分離している。前者はオフラインで一度実行し、後者はトークン生成ごとに更新する。勾配計算を生成時に繰り返すわけではないため、オンライン推論での追加費用はRPC管理と量子化・復号である。論文のCUDA融合カーネルは、この後者の費用を抑えるために必要になる。

## 限界

長文脈ベンチマークは最大4096トークンであり、KVキャッシュが本当に巨大化する32K、128K、百万トークン規模の情報保持性能は測定していない。GSM8Kの絶対正答率も13%程度のモデル設定であり、現在の推論特化モデルの長い思考過程に対して同じ精度差が出るとは限らない。評価モデルは主に7B～8Bで、70B級のMoEや多数GPUにまたがるサービングは対象外である。

勾配に基づく層別重要度の算出には、全精度モデルを読み込み、30程度のプロンプトに対する逆伝播が必要になる。代表環境では10～15分だが、巨大モデルでのコストは検証されていない。bit幅はオフラインで固定されるため、入力ごとに必要な精度が大きく変化する状況への即時適応はできない。RPC比率も代表実験では高bit層20%、低bit層10%という設定であり、あらゆる文脈で最適な比率を自動探索する仕組みではない。

メモリ4.9倍の削減はモデル重みを除いた動的推論メモリの比較であり、総VRAM削減倍率ではない。5.32倍の処理率改善は各方式の最大バッチが異なる条件で得られたもので、単一要求遅延の改善と同一視できない。量子化・復号カーネルの実装はCUDAに依存し、CPUやMetalへの移植性能は未測定である。公式コードがあることと、任意の推論基盤へ組み込み済みであることは別である。
