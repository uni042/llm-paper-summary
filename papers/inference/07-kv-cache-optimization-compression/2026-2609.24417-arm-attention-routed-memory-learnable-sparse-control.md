# ARM: Attention with Routed-Memory for Learnable Sparse Control

> 増え続けるKVキャッシュを固定数256スロットの階層メモリへ置き換え、書込み先と混合率、さらに読み出すメモリ量まで学習する。Llama-3.1-8Bで128Kまで動作し、RULER平均15.12を報告する。

## 概要

通常の自己注意では、生成が進むたびに各過去トークンのキー・バリュー（Key-Value; KV）をキャッシュへ追加する。再計算を避けられる一方、KV容量は文脈長に比例して増え、長文脈ではモデル重み以上のメモリを占めることもある。さらにデコード時には増え続けるKVを読み続けるため、計算能力ではなくメモリ帯域が律速になりやすい。

代表的な対処は、KVを低ビット量子化する、重要度が低いトークンを捨てる、CPUへオフロードする、あるいは疎注意で一部だけ読む方法である。量子化は1トークン当たりを小さくしても総トークン数は増え続ける。枝刈り・追い出しは容量を固定できるが、後から必要になる情報を完全に捨てる。オフロードはGPU容量を逃がせる一方、PCIe/ホストメモリ転送が遅延になる。

ARM（Attention with Routed Memory）は、過去トークンごとに独立KVを残す代わりに、固定サイズの階層メモリへ新しい情報を「混ぜて」保存する。新トークンは階層ルーターで意味的に近いバケットへ送られ、バケット内の1スロットをGumbel-Softmaxで選ぶ。更新時は既存内容を即座に捨てず、シグモイドゲートで旧情報と新情報を混合する。

読み出し側でも固定個数を常に参照せず、マルコフ決定過程（Markov Decision Process; MDP）として学習した方策が、入力・層ごとにTop-MのMを増やすか停止するかを決める。したがってARMは「固定容量」と「可変読出し幅」を同時に実現し、単純なスライディング窓より多様な過去情報を保持しつつ、全メモリを毎回読む必要をなくす。

Llama-3.1-8Bを基に、256スロットのARMをSliding Window Attention 256、StreamingLLM、KIVI型4bit量子化、CPUオフロード、完全注意と比較する。LongBench平均は完全注意17.09に対してARM 18.02、RULER平均は完全注意8.01に対して15.12で、128Kでは完全注意・量子化・オフロードがメモリ不足（Out Of Memory; OOM）となる一方、ARMは5.78を保つ。一方、一般的な短文タスク平均は完全注意72.27に対しARM 71.89であり、常に品質が向上する方式ではない。

## 問題設定

通常のKVキャッシュでは、時刻tで新しいトークンが来ると新しいK/V行を追加する。この方式は過去情報を一切圧縮しないため忠実だが、文脈長Tに対して保存量がO(T)で増え、各デコードステップの参照量も伸びる。長文脈になるほどGPU高帯域メモリ（High Bandwidth Memory; HBM）の容量と帯域を同時に圧迫する。

スライディング窓は最近のトークンだけを残すため容量を固定できるが、窓外の情報を失う。StreamingLLMのようなsink tokenを残す方式でも、選択規則は固定である。動的KV選択は全KVをCPUへ置いて必要分をGPUへ戻す構成が多く、転送帯域が新しいボトルネックになる。量子化は内容を保持しやすいが、長さ方向の線形成長自体は止めない。

そこでARMは、「過去トークンを保存する」のではなく「固定個数の記憶表現を更新し続ける」問題へ置き換える。難しさは、異なる過去情報が同じスロットへ衝突したとき何を残すか、そして現在の問い合わせに対して何個のスロットを読めば十分かである。本論文はこの書込みと読出しの両方を学習対象にする。

## 手法

### 1. 固定サイズの階層ルーテッドメモリ

ARMのメモリは固定木として構成され、内部ノードがルーター、葉がバケットになる。評価の256スロット構成では4分岐・4階層の木を使い、256個の葉バケットへ到達する。各トークンは根から順にルーティングスコア最大の子を選び、1つの葉へ送られる。

ルーターには自己教師ありのバランス損失を加え、意味的に近いトークンを同じ領域へ集めつつ、一部バケットだけが過密にならないよう割当を均す。バケット数とKVスロット数は推論中に増えないため、系列長が4Kから128Kへ伸びてもKV保存領域そのものは固定である。

### 2. Gumbel-Softmaxで書込みスロットを学習する

葉バケットへ到達した後、バケット内のどのスロットを更新するかを選ぶ。新しいKと既存スロットKを比較する共有スコア関数から候補ロジットを作り、Gumbel-Softmaxで離散選択を微分可能な近似へ変える。これにより、モデルは言語モデル損失から「どこへ書くと将来役に立つか」を学習できる。

単に最も似たスロットへ上書きするのではなく、選択自体に学習信号を通す点が重要である。固定LRUやFIFOと違い、書込み先が意味内容と将来利用に合わせて変化する。

### 3. シグモイドゲートでハードな追い出しを避ける

選ばれたスロットでは、旧メモリと新しいK/Vをゲート付きで線形混合する。新しい値へ完全上書きするのではなく、ゲート量に応じて既存情報を残すため、1スロットへ複数の過去情報を圧縮して共存させられる。

論文は、この共有スロットを将来どの書込み候補が参照されるか不確実な意思決定として定式化する。将来利用確率に比例して複数候補を混ぜる重みが、二乗再構成誤差の意味で最適になる条件を示す。これは全ARMの最適性を証明するものではないが、「衝突したら1件だけ残す」ハード追い出しより表現力の高い書込み規則を理論的に支える。

### 4. 書込みゲートをプリフィルでも並列化できる形へ変換する

逐次ゲート更新は、本来は前時刻のスロット内容に依存するため、そのままでは長いプリフィルを直列処理してしまう。ARMはゲート更新を再パラメータ化し、prefix-scan型の並列計算へ落とせる形を用いる。固定メモリ化でデコードを軽くしても、プリフィルを極端に遅くすれば全体として使えないため、この並列化は実装上の重要点になる。

### 5. MDPでTop-M読出し幅を入力ごとに変える

現在トークンが来ると、階層ルーターは関連度の高いバケットを順位付けする。ARMは最初から固定M個を読むのではなく、M個で止めるかM+1へ増やすかを方策が逐次判断する。推論時は継続確率が0.5以上なら読出し幅を1つ増やし、下回れば停止する。

学習時にはTop-MとTop-(M+1)の出力を継続確率で補間し、離散的な停止判断にも勾配を通す。さらに探索率0.1のε-greedyを用いて、早すぎる停止方策へ固定されることを避ける。簡単な入力では少数スロットだけ、より多くの履歴が必要な入力では広く読むことで、メモリ帯域を入力難度へ合わせる。

## 評価

### 評価条件

| 項目 | 条件 |
|---|---|
| モデル | Llama-3.1-8B |
| ARM容量 | 256メモリスロット、4分岐×4階層 |
| 学習データ | FineWeb-Edu 100億トークンサブセット |
| 学習長 | 2,048トークン |
| 学習GPU | 2ノード、各4× NVIDIA A100 40GB、NVLink |
| 推論GPU | NVIDIA H100 80GB |
| 数値形式 | BF16、量子化比較は4bit |
| 比較 | 完全注意/FlashAttention、SWA(256)、StreamingLLM(4,256)、KIVI型量子化、CPUオフロード |
| 評価 | lm-eval系一般タスク、短文検索、LongBench、RULER 4K〜128K、生成時KVメモリ・遅延 |

### 代表的な品質結果

| 評価 | 完全注意 | ARM | 読み方 |
|---|---:|---:|---|
| 一般言語/常識タスク平均 | 72.27 | 71.89 | 固定メモリ化で平均はわずかに低下し、通常タスクで一律改善ではない |
| 短文検索系平均 | 25.31 | 25.40 | 文脈が短い領域では完全注意とほぼ同等 |
| LongBench平均 | 17.09 | 18.02 | 長文タスク全体では平均を上回るが、個別タスク差が大きい |
| RULER平均 4K〜128K | 8.01 | 15.12 | 長さが伸びる領域で差が大きくなる |
| RULER 128K | OOM | 5.78 | 完全KVが収まらない長さでも固定容量で継続可能 |

RULERでは完全注意が4K 14.23、8K 6.90、16K 7.85、32K 5.04、64K 5.84、128KでOOMとなるのに対し、ARMは32.67、17.70、10.01、8.55、6.65、5.78で動作する。平均値の差には、128Kで比較対象が実行不能になることも含まれるため、「同じ実行可能条件で常に2倍精度」という意味ではない。

LongBenchではARMがNarrativeQA 2.45、Qasper 7.11、MultiFieldQA 15.41、QMSum 20.36などで完全注意を上回る一方、コード系や一部要約では下回る。平均18.02だけでなく、タスクごとの情報圧縮適性にばらつきがある点を読む必要がある。

### メモリと遅延

ARMは系列長にかかわらず256スロットを維持するため、完全注意や量子化KVのようにコンテキスト長に比例してKV容量が増えない。生成遅延はSWAやsink cacheと同程度の傾向を示し、全KV維持方式より長文で有利になる。CPUオフロードは同程度のGPUメモリ使用量に抑えられる一方、論文の生成ベンチマークでは10倍超の遅延になる条件がある。

この比較は「ARMなら計算量ゼロ」という意味ではない。階層ルーティング、Gumbel学習、ゲート更新、可変Top-M読出しの追加処理がある。利得は、これらの制御コストよりも全KVの保存・読出しを避ける効果が大きくなる長文脈で現れる。

## 既存研究との差

量子化は各KVを圧縮するがトークン数は保持する。SWA/StreamingLLMは保持トークン数を固定するが、捨てた情報は戻らない。CPUオフロードや動的選択は全履歴を外部に保持し、必要時に転送する。ARMはこれらと異なり、GPU内の固定個数スロットそのものを「過去情報の混合表現」にする。

また、疎注意方式の多くは「保存したKVのうちどれを読むか」を決めるのに対し、ARMは「どこへ書くか」「既存内容とどれだけ混ぜるか」「いくつ読むか」の3点を共同学習する。容量管理とアクセス制御を同じルーティング構造で扱う点が新しい。

## 限界

- 既存モデルへ学習なしで後付けするKV圧縮器ではない。ARM固有の書込み・読出しモジュールを学習する必要がある。
- 評価はLlama-3.1-8B中心で、70B級やMoEモデル、多様なアーキテクチャへ同じ品質差が出るかは未検証である。
- 固定容量なので情報損失がなくなるわけではない。多数の独立事実を正確に保持する課題では、同一スロットへの混合が衝突になる。
- 一般タスク平均は完全注意72.27に対し71.89で、短文・通常タスクで品質向上を保証しない。
- 128Kで完全注意がOOMになる比較では、品質値の直接比較より「実行可能性」を示す意味が強い。
- 学習コストとして100億トークン規模の追加事前学習を行っており、推論メモリ削減だけを見て導入費用を無視できない。
- 階層ルーターと可変読出しの効率は専用実装に依存し、一般的なvLLM等へそのまま統合した時のエンドツーエンド性能は別途評価が必要である。
