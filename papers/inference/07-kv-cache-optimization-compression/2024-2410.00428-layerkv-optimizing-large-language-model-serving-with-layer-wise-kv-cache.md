# LayerKV: Optimizing Large Language Model Serving with Layer-wise KV Cache Management

## 概要

LayerKVは、長い入力を受ける言語モデルのサービングで、初回トークンまでの時間（Time to First Token、TTFT）が急増する原因を**新規要求がGPU上の鍵・値（KV）キャッシュ領域を確保できず待たされること**に求めたシステムである。従来の要求単位のKV管理では、プリフィル（prefill）開始前に要求の入力系列に相当するKVブロックを確保する。長文脈要求が同時に到着すると、先行要求の生成が終わりGPUのブロックが返却されるまで後続要求が待機し、演算性能が余っていてもTTFTが伸びる。

LayerKVは、要求の全層KVを一括してGPUに保持するという前提を緩め、**層ごとにGPUとCPUの間でKVを移動する**。プリフィル計算中に生成された層のKVをCPUへ非同期に退避し、GPUブロックを次の要求へ回す。さらに、すでに生成中の要求のトークン当たり時間（Time per Output Token、TPOT）が目標値を超えない範囲で新規プリフィルを投入する、サービス水準目標対応スケジューラ（SLO-aware scheduler）を組み合わせる。容量を空けるだけでなく、既存要求への遅延干渉を制御する点が重要である。

著者らはvLLM 0.5.5を拡張し、NVIDIA L20 48GBを用いてLlama-2-7B、Yi-34B-200K、Llama-3.1-70Bを測定した。ShareGPTに基づく到着率変化実験ではvLLM比で平均TTFTを最大69倍、99パーセンタイルTTFTを最大45倍改善し、過負荷時のスループット低下は3%未満に抑えたと報告する。69倍は特定の混雑条件における相対差であり、あらゆる長文脈要求が69倍速くなるという意味ではない。

## 問題設定：プリフィル計算より前の待ち行列

論文の動機付け実験はLlama-2-7B、単一L20、到着率1要求/秒、100要求平均である。出力512トークンを固定し、入力を128から16384トークンへ伸ばすと、TTFTは急増する一方、TPOTの増え方は相対的に緩やかである。TTFTを待ち行列と実際のプリフィル処理に分けると、入力が1024トークン程度に達した時点から待ち行列が支配的になる。単純に注意カーネルを高速化しても、この待機が残れば利用者の最初の応答は改善しない。

vLLMのページ化注意（PagedAttention）はKV領域の断片化を抑え、要求の伸長に応じてブロックを動的割当する。しかし新規プリフィルを開始するには、その時点で必要なブロックがGPUに存在しなければならない。さらにサービング起動時に最大入力長を大きく設定すると、プロファイリングで活性値用に必要と見積もるメモリが増え、KV用に予約できるブロックが減る。長い要求ほど必要ブロック数が多く、空き領域の不足にぶつかりやすい。

単純にCPUへKVを退避すればGPU容量は空くが、生成中の各層でCPUからKVを取り戻す通信が増え、TPOTと秒間処理要求数（QPS）を悪化させる。LayerKVは三つの制約を同時に扱う。第一に新規要求を待たせないこと、第二に既存生成のTPOT目標を守ること、第三にPCIeの通信を計算へ重ねてスループットを極力落とさないことである。ここでの「精度を落とさない」はKVの情報量を量子化や枝刈りで減らさず、配置場所を変えるという意味である。

## 手法：スケジューリングと層単位KV配置の連携

### 生成中要求のTPOT余裕を計算するスケジューラ

スケジューラは生成中の各要求iについて、経過した生成時間 `T_past^i` と生成済みトークン数 `N_past^i` を監視する。残り生成トークン数 `N_future^i` は出力長を複数区間へ分類する予測器から求め、予測区間の下限を使って保守的に見積もる。残り生成時間 `T_future^i` は現在のTPOTと残りトークン数の積で推定する。要求iのTPOT目標 `T_tpot^i` に対して、新たなプリフィルへ割り込ませられる時間余裕を次で定義する。

\[
T_{allow\_prefill}^{i}=T_{tpot}^{i}(N_{past}^{i}+N_{future}^{i})-(T_{past}^{i}+T_{future}^{i}).
\]

待ち行列の先頭から要求qのプリフィル時間を予測し、その累積が**生成中の全要求の許容時間の最小値**より小さい範囲で、今回投入するプリフィル件数を決める。プリフィル時間は系列長、モデルパラメータ数、隠れ次元、GPUの計算能力から近似し、実機計測で補正係数を決める。これにより、TTFT改善のためにプリフィルを無制限に挿入して既存要求の出力トークン当たり時間を破綻させることを防ぐ。出力長予測が外れれば余裕推定も外れるため、絶対的なSLO保証ではなく予測に基づく実行時制御である。

### 層数xを選び、通信をプリフィル計算へ隠す

モデルがL層なら、入力要求のKVのうちGPUへ残す層数をx、CPUへ退避する層数をL−xとする。LayerKVは単に「可能な限り退避する」のではなく、**退避時間がプリフィル計算時間以下**となる条件から、計算中に通信を隠せる最小のxを選ぶ。論文の近似では退避時間は系列長、退避層数、注意ヘッド数・次元、精度あたりバイト数に比例し、PCIe帯域に反比例する。一方プリフィル時間は注意計算の影響で長文脈ほど超線形に増える。したがって入力が長いほど、計算の裏側で大量のKVをCPUへ送る余地が生まれる。

長い系列ではx=0、すなわち全層KVをCPUへ退避しても通信を隠せる条件があり得る。短い系列では計算時間が短いため、ある程度の層をGPUに保持しなければ転送が重要経路へ露出する。xはモデルの層数だけで決まる定数ではなく、要求長、GPU演算能力、PCIe帯域、注意ヘッド形状に依存する。保持層数の最小化と通信の隠蔽を同時に扱うことが、要求単位の一括退避との差である。

### 将来のブロック不足を予測して保持層を追加退避

最初にx層を残すことができても、後続の要求が到着するとGPUブロックが再び不足する。LayerKVは段階tでの空きブロック `Avail(t)`、完了要求が返す `Released(t)`、新たに割り当てる `Allocated(t)` から `Avail(t+1)=Avail(t)+Released(t)−Allocated(t)` を見積もる。要求が終了する時点は出力長予測器の区間中央値を使って概算する。生成中の要求が次のトークンのために必要とするブロックも見込み、プリフィルへ割り当てられる量を推定する。

空きブロックの予測が閾値を下回れば、最近処理した要求から保持中のx層の半分程度をまずCPUへ退避し、それでも不足する場合は残りも退避する。つまり「GPUに残すx層」は固定的な永続予約ではなく、必要に応じて開放できる送信バッファでもある。この二段階の退避によって、通常は通信の重畳余地を残しつつ、突発的な長文脈要求へ空きブロックを回す。

### 層を分散配置して計算と転送を重ねる

GPUに残す層をモデルの先頭へ固めると、CPUから戻す必要のある層が連続し、転送を隠せる計算区間が短くなる。そこで保持層をモデルの深さ方向へ均等に分散する。論文の8層・4層保持例では、GPUに1、3、5、7層、CPUに0、2、4、6層を配置する。ある層の演算中に次に必要な層のKV転送を進められるようにする配置である。

通常のブロック表は要求ごとの物理ブロック番号を管理するが、LayerKVでは各層の位置とGPU/CPUの所在を追えるよう拡張する。実装は層ごとに別々の物理テンソルを作るのではなく、一つのPyTorchテンソルへ物理KVを確保し、論理的に層単位のブロックを割り当てる。専用CUDAストリームでGPU計算と転送を並行させ、CPU側のピン留めメモリから通常メモリへのコピーを別CPUスレッドへ渡してGPU側を待たせない。

### 複数GPUのPCIe競合を回避

NVLinkのあるGPU群なら、テンソル並列の全削減通信はNVLink、KV退避はPCIeと経路を分けやすい。NVLinkがない構成では全削減もPCIeを使い、KV転送が重なると推論の重要経路に干渉する。LayerKVはPCIe使用状況を確認し、全削減が進行中ならKV転送を少し遅らせて再確認する。さらに転送を小さな単位に分け、各単位で競合を確認する。層単位の退避だけでは実現できない、複数GPU構成におけるスループット維持のための実装上の工夫である。

## 評価：待ち時間、生成速度、SLO違反を分離する

### 実験環境

| 観点 | 一次論文に記載された条件 |
|---|---|
| サーバ | NVIDIA L20 48GB GPU×8、CPU 64コア、ホストメモリ2048GB、GPU/CPU間PCIe |
| ソフトウェア | PyTorch 2.4.0、CUDA 12.2、vLLM 0.5.5を拡張 |
| モデル | Llama-2-7BはGPU1基・TP1、Yi-34B-200KはGPU2基・TP2、Llama-3.1-70BはGPU4基・TP4 |
| 入力 | 固定入力長の系列と、長さ4〜約2300トークンのShareGPT会話データ |
| 主比較 | 同じGPU条件のvLLM 0.5.5 |
| 指標 | 平均TTFT、P99 TTFT、出力トークン当たり時間、処理量、TTFT/出力トークン当たり時間のSLO違反率 |

### 入力長とGPU並列度

図4の到着率1要求/秒の実験では、入力系列を長くするほどvLLMの平均TTFTが急増し、LayerKVはより緩やかな増加に抑える。一方、入力が長くなればどちらの方式もスループット自体は低下し、この負荷条件では両者のスループットは概ね同等である。すなわち主な改善は「行列積を69倍高速化した」のではなく、KV不足で開始できない要求の待ちを減らしたことによる。

Yi-34B-200KでGPU並列度を増やす図5では、GPUを増やすと演算能力とKV領域が増え、vLLM自体の資源競合も軽くなる。それでもLayerKVの初回トークン時間優位は残るが、スループットの差は小さくなる。改善率はメモリが厳しいほど大きくなり得るため、GPUを十分に増やした環境へ最大改善値をそのまま適用できない。

### 到着率と末尾遅延

ShareGPTを使う図6・図7では、到着率が上がるとvLLMの待ち行列が急増する一方、LayerKVは空きKVブロックを増やすことで初回トークン時間を抑える。最も大きな相対差として**平均初回トークン時間最大69倍、P99 初回トークン時間最大45倍**を報告する。これは負荷増大によりvLLMが詰まる条件で観測された値であり、低負荷・短入力・十分なGPUメモリの条件では同じ差は期待できない。

過負荷に入るとLayerKVも生成時にCPUからKVを戻すため、処理量はvLLMよりわずかに低くなる。著者らはこのスループット差を**3%未満**に抑えたと報告する。初回トークン時間改善だけを抜き出すと、生成速度に費用がないように見えるが、実際には中央処理装置退避に伴う転送の代償がある。

### SLO違反率とスケジューラの必要性

Llama-2-7Bの図8では初回トークン時間上限3000ミリ秒、出力トークン当たり時間上限200ミリ秒を設定し、どちらかを超えればサービス水準目標違反とする。到着率6要求/秒付近からvLLMで違反が増え、LayerKVの違反率はvLLMより**17.7〜28.7%低い**と報告される。本文の「17.7〜28.7% lower」は百分率差の記述であり、図の生値を確認せず「17.7〜28.7ポイント低下」と言い換えることは避ける。

サービス水準目標対応スケジューラを外したLayerKVでは、プリフィル投入が生成を圧迫し出力トークン当たり時間が増える。到着率5.5要求/秒では一部条件でvLLMより違反が多くなる。これは層単位退避だけでは十分でなく、生成中要求の時間余裕を見てプリフィルを制御する必要があることを示す構成要素除去実験である。サービス水準目標対応制御を加えるとこの悪化が緩和される。

## 限界と実用上の注意

LayerKVの効果は**GPU KV容量が新規要求の投入を阻害する条件**に強く依存する。KVが十分に空いている低負荷では待ち行列削減の余地が小さい。長文脈ではプリフィル計算の背後にPCIe転送を隠しやすいが、短文脈では計算時間が短く、退避しすぎると通信が露出する。xの推定に使うモデル演算量、帯域、実測補正係数が環境とずれれば、想定した重畳は成立しない可能性がある。

サービス水準目標対応スケジューラは出力長を区間分類で予測するため、長い応答の予測が外れると許容プリフィル時間の見積りが不正確になる。論文が示す違反率の改善は特定の出力トークン当たり時間/初回トークン時間閾値と到着率に対する実測であり、すべての要求に厳密な期限保証を与える仕組みではない。過負荷では中央処理装置からのKV復元により処理量がvLLMより最大3%弱低下するという交換条件がある。

評価はL20と大容量ホストメモリのサーバを使う。GPU/中央処理装置間のPCIe帯域、ピン留めメモリ容量、ホスト側コピー速度、複数画像処理装置の全削減経路が異なれば最適なxや通信の隠蔽率は変わる。RTX系単一画像処理装置の小メモリPCへそのまま69倍を外挿することはできない。長文脈入力におけるデータセットはShareGPTと固定長要求であり、極端に長い実業務会話、モデルを跨ぐ負荷、別の推論カーネルでの結果は本実験から確定できない。

著者らはKV量子化とプリフィル・デコード分離（disaggregated serving）との統合を将来課題に挙げている。したがって、本論文が示すのは**KVの精度を変えずに配置と実行時刻を最適化する**効果であり、量子化と組み合わせた追加のメモリ節約や分離サービングでの性能を実証したものではない。

## 既存研究との違いと結論

ページ化注意はKVの物理断片化を抑えるが、要求開始時に必要な画像処理装置ブロックをまとめて確保する制約を残す。KV枝刈り・量子化は情報量を減らすのに対し、LayerKVはKVの精度を維持したまま層ごとに配置を変える。プリフィルとデコードを別画像処理装置に置く方式や、入力を小分けにする方式とも異なり、**同じ画像処理装置上で新規プリフィルを始められるようKV容量を細粒度に融通し、既存生成の出力トークン当たり時間をサービス水準目標対応スケジューラで保護する**ことに主眼がある。
