# InfiniPot: Infinite Context Processing on Memory-Constrained LLMs

## 概要
多くのKV圧縮法は長い入力全体を一度処理してから不要KVを捨てる。この方式では最終キャッシュは小さくても、プリフィル途中には全入力分のKVを保持する必要があり、厳しい端末メモリ制約では入力自体を処理できない。InfiniPotはKV容量を固定した「ポット」とみなし、満杯になるたびに内容を小さく蒸留して新しい入力を受け入れる。

残すトークンは二つの指標で選ぶ。触媒プロンプト（Catalyst Prompt; CaP）は将来の問い合わせを模した短いプロンプトから、後で参照されそうな代表的情報を測る。圧縮下新規性（Novelty under Compression; NuC）は、現在の圧縮文脈から予測しにくいトークンを高く評価し、CaPだけでは落としやすい固有情報を保護する。さらに文脈再設定回転位置埋め込み（Context-Reset RoPE; CR-RoPE）で保持トークンの位置を再構成する。追加学習なしで、4Kの固定メモリ予算から最大1MトークンのNeedle-in-a-Haystackを扱い、LongBenchでもメモリ制約付き基準を上回る。

## 問題設定
KVキャッシュは入力長に比例して増える。SnapKVのように重要KVだけ残す方式でも、重要度を決める前に長い入力全体をプリフィルする設計ではピークメモリを抑えられない。モバイルやエッジでは「最終的に圧縮できる」ことではなく、「処理のどの瞬間にも固定予算を超えない」ことが必要になる。

逐次圧縮には別の難しさがある。未来の入力をまだ見ていないため、現在捨てるトークンが後で重要になるか分からない。また圧縮を繰り返すと、古いが固有な事実が代表的情報に埋もれやすい。保持トークンだけをつなぎ直すと、学習時に見ていない位置範囲や位置の穴も生じる。

## 手法
### 継続的文脈蒸留
継続的文脈蒸留（CCD）は、固定容量 `M` のKVが満杯になると、その内容をより小さい保持集合 `C` へ圧縮し、空いた領域へ次の入力チャンクを追加する。この「消費→圧縮→追加」を繰り返すため、総入力長が増えてもKVのピーク容量は `M` で固定される。

圧縮頻度は予算と圧縮率で決まり、圧縮率は事前設定である。したがって極端に情報密度が高い区間でも自動的に予算を増やすわけではなく、何を残すかという選択精度が品質を左右する。

### CaPによる将来関連性
CaPは、未来の質問そのものがまだ存在しない状況で、短い触媒プロンプトを追加して現在のKVへ注意を向けさせる。そこから得た注意量を「将来も参照されそうな代表性」の代理指標として使う。

CaPだけでは、代表的ではないが一度しか現れない固有情報を落とす可能性がある。そのためInfiniPotは次のNuC用スロットを別に確保し、二種類の重要性を競合させずに保持する。

### NuCによる固有情報保護
NuCはトークンの負の対数尤度、すなわち現在の圧縮文脈からどれだけ予測しにくいかを新規性として扱う。高NuCのトークンは既存文脈から復元しにくいため、捨てると情報損失が大きいとみなす。

保持集合の一部をNuC上位へ、残りをCaP上位へ割り当てることで、珍しい事実と将来関連性の双方を残す。圧縮を何度も繰り返す長文脈で、単純な最近傍保持や注意量だけの選別より長期情報を保ちやすくする。

### CR-RoPEによる位置再設定
圧縮後には元系列の位置が飛び飛びになる。CR-RoPEは保持されたKVへ対応する回転位置表現を再設定し、次チャンクを固定長の有効位置範囲へ接続する。これにより学習時の最大位置を大幅に越えることによる分布外の位置表現を抑える。

## 評価
### 代表条件
|項目|内容|
|---|---|
|モデル|LLaMA系を含む事前学習済みLLM|
|学習|追加学習なし|
|評価|LongBench、Needle-in-a-Haystack|
|比較|StreamingLLM、SnapKV等の長文脈/KV圧縮法|
|メモリ条件|固定KV予算、代表例4K|
|長文脈|最大1Mトークンの検索評価|

### 主要結果
|条件|結果|意味|
|---|---|---|
|4K固定予算・Needle-in-a-Haystack|最大1Mトークンまで高い検索精度|有効文脈を30倍超へ拡張してもピークKVを固定|
|LongBench・LLaMA-3.1|メモリ制約付き基準より6%以上改善する設定|逐次圧縮でも下流品質を維持|
|効率|蒸留処理は初回トークン時間の約1〜3%|圧縮自体の追加計算は小さい|
|メモリ|総文脈長に依存せず一定|入力全体を一度保持する圧縮法との差|

## 既存研究との差
StreamingLLMは最近トークンと注意シンクを固定窓に残すため古い固有情報を落としやすい。SnapKVなどは重要KVを選択するが、長入力全体を先に処理する方式ではピークメモリ制約を解けない。InfiniPotは入力途中から繰り返し圧縮し、未来関連性の代理と新規性を別々に保持する点が異なる。

## 限界
圧縮率は事前定義で、入力の情報密度に応じて自動調整されない。非常に長期の依存関係を多様な条件でどこまで保存できるかは網羅的に検証されていない。またモバイルを主要動機とするが、論文評価は実際の多様な端末上での包括的な実機検証ではない。
