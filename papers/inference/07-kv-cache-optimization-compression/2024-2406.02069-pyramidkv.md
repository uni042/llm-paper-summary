# PyramidKV: Dynamic KV Cache Compression based on Pyramidal Information Funneling

> 注意の層間集約パターンに合わせてKV予算を下層から上層へ逓減させ、同じ総メモリで固定予算型より長文脈性能を保つKVキャッシュ圧縮法。
## 書誌情報
- **著者**: Zefan Cai, Yichi Zhang, Bofei Gao, Yuliang Liu, Yucheng Li, Tianyu Liu, Keming Lu, Wayne Xiong, Yue Dong, Junjie Hu, Wen Xiao
- **著者・所属**: University of Wisconsin-Madison; Peking University; Nanjing University; University of Surrey; Qwen; Microsoft; University of California-Riverside
- **公開**: arXiv
- **種別**: プレプリント
- **対象**: KVキャッシュ圧縮、長文脈推論、層別メモリ配分、注意スコア選択、LLaMA
- **実装**: 公式GitHub実装を公開し、v4ではvLLM統合も付録で示す。
## 概要
PyramidKVは、長文脈LLMの注意分布が下層では広く、上層ほど少数トークンへ集中する『ピラミッド型情報集約』を観察し、層ごとのKVキャッシュ予算を下層多め・上層少なめに変える圧縮法である。各層では末尾の指示トークンを保持し、その注意スコアから重要KVを選択する。LongBenchではKVキャッシュ12%保持でFullKV相当の性能を維持し、極端な0.7%保持でも固定予算型圧縮法を上回る。LLaMA-3-70Bでは128エントリ保持のNeedle-in-a-Haystackで100%精度を報告する。

PyramidKVの新規性は、トークン重要度の選び方だけでなく『各層に何個のKVを残すか』を独立した設計変数として扱い、注意のピラミッド型情報集約に合わせて下層から上層へ保持数を単調に減らす点にある。従来の固定層budget方式に対し、同じ総KV数を使いながら層ごとの情報密度へ予算を合わせる。

具体的には最下層と最上層のbudgetを総予算と形状係数βから決め、その間を等差数列で補間する。各層内のトークン選択はSnapKV系の局所観測窓を利用し、末尾α個のinstruction トークンを必ず残したうえで、それらから高い注意を受ける過去トークンをheadごとに選ぶ。このため層別budget配分は既存のattention-based selectionと組み合わせられる。

代表結果として、LongBench性能保持はKV キャッシュ size 2048、LongBench 17 datasetsでFullKVに対して約12% KV保持でFullKV相当。層別budget再配分により大幅なメモリ削減でも長文脈task性能を保てる。
## 問題設定
長文脈LLMでは過去トークンのKey/Valueを再計算しないためKVキャッシュをGPUへ保持するが、必要容量は系列長と層数に比例する。論文はLLaMA-2 7Bで100K トークンのKVが50GB超になる例を挙げる。H2O、SnapKV、StreamingLLMなどは重要トークンだけを残して容量を削減するが、多くは全Transformer層へ同じキャッシュ sizeを割り当てる。

著者らは長文脈QAの注意分布を層別に観察し、下層では広範なトークンへ注意が分散し、中層で文書内へ局所化し、上層では少数トークンへ極端に集中することを確認する。この層間差を無視して同じ保持数を使うと、上層では不要KVを残す一方、情報が分散する下層では重要KVを捨てる可能性がある。同じ総メモリ予算を層間でどう再配分するかが課題である。
## 新規性
PyramidKVの新規性は、トークン重要度の選び方だけでなく『各層に何個のKVを残すか』を独立した設計変数として扱い、注意のピラミッド型情報集約に合わせて下層から上層へ保持数を単調に減らす点にある。従来の固定層budget方式に対し、同じ総KV数を使いながら層ごとの情報密度へ予算を合わせる。

## 手法
### 手法のあらまし
最初にモデルの長文脈注意を層ごとに調べる。下層では注意が広く分散し、中層では文書単位に局所化し、上層ではmassive attentionやattention sinkに対応する少数トークンへ集中する。PyramidKVはこの『ピラミッド型情報集約』を、層ごとのキャッシュ budget k^lへ写像する。m層全体で使える総budget k_totalを固定し、最上層budgetをk_total/(βm)、最下層budgetを総和制約から大きく設定し、中間層を等差数列で補間する。βは上層をどれだけ絞るかを制御し、実験ではβ=20を用いる。

次に各層内で残すトークンを決める。直近α トークンはtask instructionやqueryに近い情報を持つ局所窓として全層で無条件保持し、実験ではα=8とする。各attention headについてinstruction トークンから過去トークンへのattention scoreを計算し、poolingで局所的な極端値の影響を緩和する。過去トークン iの重要度はinstruction トークン群から受けるattentionの和として計算し、その層に割り当てられたk^lの範囲でscore上位トークンのK/Vだけを保持する。選外KVは以後の生成で使わない。

総budgetは比較対象と同一になるよう平均キャッシュ sizeを合わせるため、PyramidKVの利得は単純に多くのKVを保存した結果ではなく層間再配分から生じる。推論時にはprompt処理後に各層の保持集合を圧縮し、デコードでは縮小したKVを参照する。したがってモデル重みの再学習やfine-tuningは不要で、既存モデルへplug-in的に適用できる。

### ピラミッド型情報集約の層別観察
多文書QAで各層・各headのattentionを観察すると、初期層は文脈全体へ比較的均等に注意し、中間層では同一文書内へ局所化し、上位層ではごく少数トークンへmassive attentionが集中する。これは同じpromptでも層ごとに重要情報の分散度が異なることを示す。

この観察を『下層ほど多くのKV候補が必要で、上層ほど少数KVへ圧縮できる』というbudget設計原理へ変換する。attention sinkやmassive 活性値の存在だけでなく、その現れ方が層をまたいで変化することをKV圧縮へ直接利用する点が方法の出発点である。

### 層別KV予算の等差配分
m層全体の総KV budgetを固定し、上層budgetをk_total/(βm)として小さく、下層budgetを総和制約を満たすよう大きく置く。中間層は最下層から最上層まで等差的に減らし、モデル全体としてピラミッド形の保持数を作る。最下層値は全層budgetの総和がk_totalと一致するよう決めるため、上層を削った分がそのまま下層側へ再配分される。

βはピラミッドの傾きを決め、βが大きいほど上層の保持数を絞る。実験ではβ=20を用い、比較対象との比較では層あたり平均budgetを一致させるため、総KVメモリは同じである。この制約により、性能差を『より多く保存したから』ではなく層間配分の差として評価できる。付録ではallocation strategyとβのablationも行い、単調に減らす設計の妥当性を検証する。

### instruction トークンの常時保持
各層でprompt末尾α トークンをinstruction トークン、すなわち局所観測窓として必ずKVへ残す。これらは現在のtask指示やqueryに近く、次トークン生成で直接必要になる可能性が高い。実験ではα=8を用い、長距離候補を選ぶbudgetとは別枠で直近情報を保護する。

直近トークンを無条件保持することで、長距離トークンのimportance rankingが多少誤っても局所連続性を確保する。また、この末尾窓自体を過去トークンの重要度推定に使い、各instruction queryから過去keyへ向くattentionをselection signalとして集約する。したがって末尾窓は単なるrecent キャッシュではなく、どの古いKVを残すかを決める観測窓も兼ねる。

### attention scoreによるhead別トークン選択
各attention headでinstruction トークンから全過去トークンへのattentionを計算し、過度なmassive 活性値に選択が支配されないようpoolingを適用する。過去トークン iがinstruction トークン群から受けるattention scoreを合計し、生成に関係するimportance scoreとみなす。

層l・head hごとにscore上位k^l トークンを選び、そのK/Vのみを保持する。選ばれなかったKVは以後のデコードで参照しない。トークン selection自体はSnapKVに近いが、k^lが層ごとに変わるため、同じscore機構でも情報が広い下層には多く、集中した上層には少なく保存できる。

### 全体のデータ／制御の流れ
PyramidKVはモデル重みやattention演算そのものを変更せず、promptから得られたKVの保持方針だけを変える。まず層別budget allocatorが総メモリを下層厚め・上層薄めに分配し、そのbudgetの中でhead別selectorがinstruction トークン由来のattention scoreを使ってトークンを選ぶ。

この二段構成により、総メモリ量を固定したまま層間配分と層内選択を分離できる。固定budgetのH2O/SnapKV/StreamingLLMに対しては同一総容量で比較でき、v4ではvLLMへの統合やMInferenceとの組み合わせも検討されるため、KV管理層へ差し込む実装として位置付けられる。
## 評価条件
- **ハードウェア**: 主評価はLLaMA-3-8B-Instruct、LLaMA-3-70B-Instruct、Mistral-7B-Instructの推論。v4ではメモリ消費、追加オーバーヘッド、推論速度およびvLLM統合も評価・補足する。
- **ソフトウェア**: PyramidKV公式実装。層別budgetはβ=20、末尾instruction windowはα=8。各headでinstruction トークン由来のattention scoreをpooling後に集約し、層budget内の上位KVを保持する。
LongBenchの17データセットを用い、single/multi-document QA、summarization、few-shot、合成、codeを標準指標で評価する。入力平均長は約1,235〜18,409 トークン。全taskをgreedy デコードで実行し、FullKV、StreamingLLM、H2O、SnapKVと比較する。比較対象は全層固定キャッシュ size、PyramidKVは層ごとに異なるが平均キャッシュ sizeを一致させ、総メモリを公平にする。キャッシュ size 64/96/128/256および2048などを評価し、Needle-in-a-Haystackで長距離retrieval保持も検証する。
長文脈prompt後のKV 枝刈りを中心とする。モデル再学習なしで適用できるが、主な品質評価はLLaMA-3/Mistral系列とLongBench/Needleに集中する。層別budgetの形状はβによる手設計で、ワークロードごとのオンライン最適化や他architectureへの一般化は限定的である。
## 主要結果
PyramidKVは同じ総KV予算でも固定層budget方式よりLongBench性能を高く保ち、特に64〜256エントリの極端な圧縮で差が大きい。論文は2048保持、すなわちFullKVのおよそ12%でFullKV相当のLongBench性能を維持し、約0.7%保持の極端条件でも既存法を上回ると報告する。LLaMA-3-8Bのキャッシュ size 64ではLongBench平均34.76で、SnapKV 33.05、H2O 33.89、StreamingLLM 30.43を上回る。Needle-in-a-HaystackではLLaMA-3-70Bが128 KV entryで100%精度を達成する。

- LongBench性能保持 / 約12% KV保持でFullKV相当 (比較対象: FullKV; 条件: KV キャッシュ size 2048、LongBench 17 datasets) — 層別budget再配分により大幅なメモリ削減でも長文脈task性能を保てる。

- LLaMA-3-8B LongBench平均 / 34.76 (比較対象: SnapKV 33.05; H2O 33.89; StreamingLLM 30.43; 条件: KV size 64) — 極小budgetで固定層budget方式より平均性能を維持する。

- LLaMA-3-8B TREC accuracy / 58.0 (比較対象: SnapKV 38.5; H2O 38.0; StreamingLLM 38.0; 条件: KV size 64) — 同一総キャッシュで最大20ポイント級のtask差が生じ、層間配分の影響が大きい例である。

- Needle-in-a-Haystack / 100.0% accuracy (比較対象: FullKV相当; 条件: LLaMA-3-70B-Instruct, 128 KV entries) — 極端なKV削減でも長距離retrieval情報を保持できることを示す。

- 極端圧縮率 / 約0.7% KV保持でも既存圧縮法を上回る (比較対象: H2O / SnapKV / StreamingLLM; 条件: メモリ-constrained setting) — キャッシュ予算が厳しいほどピラミッド配分の利点が顕在化する。

### 負の結果・境界条件
- キャッシュ size 64のLLaMA-3-8B平均34.76はFullKV 41.46を下回り、極端な圧縮が無損失ではない。task別にもMusiqueなど一部では固定budget 比較対象を常に上回るわけではなく、平均改善と個別taskの最適性は区別が必要である。budget形状はβ=20、instruction windowはα=8という固定hyperparameterに依存し、モデル・taskごとの最適値をオンラインで学習する方式ではない。

### 結果の読み方
結果はKV トークン selectionだけでなく層間budget allocationが重要であることを示す。上層attentionが疎になるなら、上層から削った容量を下層へ移すことで同じ総メモリでも重要情報の欠落を減らせる。圧縮率が高いほど固定一律配分の無駄が相対的に大きくなるため、PyramidKVの優位性も大きくなる。
## 品質への影響
2048保持ではFullKVに近い性能を維持する一方、64保持では平均scoreが低下する。したがってPyramidKVは品質劣化を完全に消す方式ではなく、同一メモリbudget下で劣化を小さくする方式である。Needle評価は長距離retrieval保持に強い証拠だが、全LongBench taskで無損失を保証するものではない。
## 既存研究との差
StreamingLLMはattention sinkと局所windowを固定保持し、H2Oはrecent トークンとheavy hitter、SnapKVはprompt末尾の観測窓から重要KVをhead別に選ぶが、これらの代表的設定は層ごとのキャッシュ sizeを同一にする。PyramidKVはトークン importanceの推定機構を全面的に置き換えるのではなく、層ごとのattention密度に合わせて総budgetを再配分する点が差分である。FastGenのhead別policyとは粒度が異なり、PyramidKVは層-level budget allocationを主軸にする。
## 限界
評価は主にLLaMA-3-8B/70B-InstructとMistral-7B-Instructへ集中し、GQA/MQA構造や層数が大きく異なるモデル、MoE、encoder-decoderへの一般性は十分示されない。層budgetは注意の平均的な傾向をもとに単調な等差数列で決めるため、特定層だけretrieval headが重要になる入力など、非単調な層別需要を直接適応しない。α=8、β=20は固定で、要求ごとに最適化されない。極端な圧縮ではFullKVから品質低下が残り、重要トークンを一度削除すると後続デコードで復元できない。attention score計算とselectionにも追加処理が必要であり、実際の利得は実装・prompt長・デコード長に依存する。
## 実装状態

## 研究上の位置づけ
KVキャッシュ圧縮研究を『トークン selection』と『層 budget allocation』の二軸に分け、後者の重要性を明確化した研究である。特に階層的なattention情報集約をメモリ allocationへ直接結び付けるため、KV 追い出し policyや量子化と直交して組み合わせられる。サービング基盤の観点では、全層一律のpage/キャッシュ quotaを前提とせず、層ごとの有効情報密度を利用して限られたGPUメモリを配分する設計へつながる。
