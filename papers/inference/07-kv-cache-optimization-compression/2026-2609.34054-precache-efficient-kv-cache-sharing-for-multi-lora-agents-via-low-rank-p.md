# PReCache: Efficient KV Cache Sharing for Multi-LoRA Agents via Low-Rank Precomputation and Neutral Reconstruction

> 共有軌跡が初めて処理される時点で全エージェント分の低ランクキャッシュを事前計算し、さらにアダプターなしの隠れ状態から基底キャッシュを再構成することで、繰り返しプリフィルを消しながら精度低下を平均1.1ポイントに抑える学習不要のKVキャッシュ共有方式。

## 概要

役割分担するエージェント群は、共通の基盤モデルに役割ごとの小さなアダプター（低ランク適応、LoRA）を付けて専門化するのが定番になっている。重みは共有できても、推論の状態は共有できていない。利用者の依頼、検索結果、ツールの観測、前のエージェントの出力が積み上がった共有軌跡は全エージェントに共通なのに、各エージェントが自分のアダプターで軌跡全体を処理し直し、自分専用のKVキャッシュを作る。軌跡が長くなるほど、この繰り返し入力処理（プリフィル）とキャッシュの複製が計算とメモリを食う。

かといって前のエージェントのキャッシュをそのまま使うと精度が落ちる。アダプターが違うと、同じ文脈でもキーとバリューの中身が変わるからである。本論文のPReCacheは学習不要の共有枠組みで、二つの設計を組み合わせる。第一のPreLRSharedは、文脈の断片が初めて処理されるその場で、全エージェント分の小さな低ランクキャッシュをまとめて作ってしまう。第二のReBaseSharedは、共有する基底キャッシュを前エージェントのアダプター付き隠れ状態ではなく、アダプターを外した中立な隠れ状態から作り直し、前任者への依存を弱める。代表結果として、単一ストリーム推論でPreLRSharedは共有なしに比べて最初のトークンまでの時間（TTFT）を最大3.1倍短縮し、リクエストあたりスループットを最大2.3倍に上げた。ReBaseSharedは評価した共有方式の中で精度を最もよく保ち、共有なしに対する平均低下は1.1ポイントだった。

## 問題設定

射影の出力は、基盤の重みによる基底成分と、アダプターによる低ランク成分に分解できる。低ランク成分はエージェントごとに違うだけでなく、その違いが後続の層へ伝播するため、基底成分すらエージェント依存になる。つまり文脈が同じでも、正しいキャッシュはエージェントごとに異なる。これが共有の難しさの正体である。

既存対策は三つに分かれる。第一に、ずれの大きい層やトークンだけを現エージェントで再計算する選択的再計算は、再計算率を上げると節約が消え、下げると精度が残らない。第二に、先行研究のLRAgentが提案したBaseSharedは、基底キャッシュを共有しエージェント固有の低ランクキャッシュだけを別に持つことで精度とメモリを両立させたが、自分の低ランクキャッシュを作るために結局は軌跡全体を基盤モデルで処理し直す必要があり、計算の節約にならなかった。第三に、低ランク射影を全エージェントで共有する変種は再処理を消せるが、アダプターの学習時にその制約が必要で、既存のアダプターには適用できない。本論文の課題は、既存アダプターのまま、メモリと繰り返し計算の両方を削ることである。

## 手法のあらまし

処理の流れはターンの連鎖で理解できる。前のエージェントが新しい文脈断片を処理するとき、PReCacheはその隠れ状態に対して全エージェントの下向き射影をその場で適用し、全員分の低ランクキャッシュを一括で作る。次のエージェントの番では、共有基底キャッシュと自分の事前計算済み低ランクキャッシュを組み合わせて使うため、蓄積した軌跡を再処理せず、新しく増えた文脈だけを自分のアダプターで処理すればよい。ReBaseSharedではさらに、基底キャッシュの材料をアダプターなしで処理した隠れ状態へ差し替える。この再構成の実行タイミングは環境で使い分け、単一ストリームではターン終了後にまとめて行う遅延プリフィル（LP）、同時サービングでは現エージェントの実行と並べて行う二重バッチ（DB）を用いる。どちらの日程でも、最終的に基底キャッシュと全員の低ランクキャッシュが軌跡全体を覆う状態で次のターンへ渡る。

## 手法

### 1. PreLRShared — 低ランクキャッシュの事前計算

観測対象は、ある文脈断片が初めて処理されるときに生じる隠れ状態である。保持する状態は、共有基底キャッシュ1本と、エージェントごとに幅がランク幅（既定では8）しかない低ランクキャッシュである。動作の核心はタイミングの前倒しで、断片を処理したエージェントの隠れ状態へ他の全エージェントの下向き射影をその場で掛け、他者分の低ランクキャッシュまで作ってしまう。後で必要になる全次元の基盤処理を、幅8の小さな射影へ置き換えるわけである。これで減るのは繰り返しプリフィルの計算であり、追加で消費するのは射影の計算と人数分の小さなキャッシュの保持だけである。失敗条件は、事前計算の材料が前エージェントのアダプター付き隠れ状態である点に残る。基底キャッシュも低ランクキャッシュも前任者の表現に引きずられ、精度低下が1.0〜3.3ポイント残ったことが評価で確認されている。エージェント数が増えると射影の本数は増えるが、幅が小さいためメモリの増え方は緩やかで、論文の付録でも人数を増やした条件で効率が保たれることが示されている。

### 2. ReBaseShared — 中立な基底キャッシュの再構成

この機構が変えるのは、共有基底キャッシュの材料である。基底の重み自体は全員共通でも、入力の隠れ状態に前エージェントのアダプターの影響が混ざっているため、基底キャッシュは前任者依存になっていた。そこでアダプターを無効にして同じ文脈を処理した中立な隠れ状態から基底キャッシュを作り直す。論文は、現在エージェント自身の基底キャッシュを正解として相対誤差を測り、中立な材料の方が前任者の材料より誤差が小さいことを層ごととターン遷移ごとの両方で示し、付録で誤差が減る条件を理論的にも導いている。効果は精度の回復で、PreLRSharedの低下を平均で押し戻した。追加費用はアダプターなし処理を文脈断片ごとに1回行うことで、これは次の機構の日程設計で吸収する。なお既定の評価設定ではLoRAはクエリとバリューの射影にだけ付いており、キーの射影には低ランク成分がないためキーは完全に共有され、バリュー側だけが基底と低ランクに分解される。付録では全射影へ付けた条件でも効率の利得が残ることが確認されている。

### 3. 再構成の日程 — 遅延プリフィルと二重バッチ

同じ再構成でも、置く場所で向き不向きが分かれる。遅延プリフィルは現エージェントの生成が終わった後に、アダプターなし処理を1本の連続したプリフィルとして実行する。次のエージェントのTTFTには割り込まず、アダプターなしのデコード経路を持たなくてよいため、端末上の単一ストリーム推論に向く。二重バッチは、アダプター付き経路とアダプターなし経路を同じバッチに入れてプリフィルとデコードの両方で並行に進める。再構成専用のプリフィルが待ち行列の後ろの要求を止めないため、同時サービングに向く。両者は論理的に同じキャッシュ状態を作り、違いは実行タイミングだけである。評価でも、単一ストリームでは遅延プリフィルが、二重バッチは高負荷のサービングでそれぞれ優位になることが分かれている。

## 評価

結論は、事前計算が計算の節約を、中立再構成が精度の回復を担い、両者を合わせると先行の基底共有と同等の精度をその計算の大半なしに得られる、というものである。精度は近似の代償として小幅に下がるが、選択的再計算の比較対象よりは保たれている。メモリは全共有にほぼ並ぶ水準まで下がり、再計算系より明確に小さい。

## 既存研究との差

選択的再計算（DroidSpeak、CacheBlend、RelayCaching）は、ずれた部分だけ直す発想で、再計算率30パーセントの条件でも精度低下が残り、直した部分は全次元のキャッシュを持つためメモリも削れない。接頭辞の違いを補正する系の手法は、接頭辞が一致する本設定では補正が働かず全共有と等価になる。LRAgentのBaseSharedは分解そのものを導入した直接の先行研究で、本論文はその分解を保ったまま、低ランク側の構築タイミングを「必要になったとき」から「文脈が生まれたとき」へ前倒しし、さらに基底側の材料を中立な隠れ状態へ替えた点が新しい。低ランク射影を共有して再処理を消す変種との差は、学習時の制約なしに既存アダプターへ適用できる点にある。

## 限界・実装状況

- 精度は無損失ではなく、条件により1.0〜3.3ポイント（PreLRShared）程度の下げが残る。役割の違いが大きいアダプター同士ではさらに広がる可能性がある。
- 評価は2モデル、2ベンチマーク、3エージェント構成が中心で、エージェント数が大幅に多い構成や異なる基盤モデルでの一般性は限定的である。
- 効率測定は日程とトークン数を固定したトレース再生であり、ツール呼び出しの実待ち時間を含む運用条件とは異なる。
- 公式コードの公開先は論文中に示されておらず、上流のサービング基盤へ統合済みという記述もない。試作実装による実機評価として読むべきである。

## 一般的な実装上の含意

共有できる状態とできない状態を、重みの分解に沿って分けることが第一の教訓である。共通部分は1本だけ持ち、固有部分は幅の小さい表現に圧縮して持てば、メモリと正確さの交換条件が大きく改善する。第二に、固有部分の構築は必要になった時点ではなく、材料の隠れ状態が手元にある時点で済ませる方が安い。状態の生成タイミングと消費タイミングをずらす設計は、プリフィックスキャッシュなど他の共有機構にも応用できる。第三に、共有物の材料に前任者の癖が混ざる場合は、中立な基準状態から作り直すという選択肢があり、その再構成費用は実行環境に合わせて日程へ埋め込むことで表に出さずに済む。

## 引用関係

LRAgentの基底共有と低ランク分解を直接の土台とし、選択的再計算の系譜（DroidSpeak、CacheBlend、RelayCaching）と精度、速度、メモリで比較している。サービング基盤としてはvLLMのページ式KV管理とプリフィックスキャッシュを前提にしている。
