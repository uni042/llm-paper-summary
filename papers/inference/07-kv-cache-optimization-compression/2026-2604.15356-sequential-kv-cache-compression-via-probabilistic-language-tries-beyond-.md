# Sequential KV Cache Compression：トークン系列の予測可能性を利用したKV圧縮の理論

## 概要

本論文は、言語モデルの鍵・値キャッシュ（KV Cache）を独立した浮動小数点ベクトルの集合として圧縮する従来の考え方を改め、**元のトークン系列の確率構造に基づいてキャッシュ系列全体を圧縮する**構想を示す。提案は二層からなる。第一層では複数セッションの共通接頭辞を確率的言語トライ（Probabilistic Language Trie; PLT）で見つけ、代表セッションとの差分だけを持つ。第二層では、次トークンの確率分布から予測されるKVベクトルを計算し、実際のKVとの残差だけを符号化する。

著者は、固定された決定的な推論モデルにおいてKV状態がトークン接頭辞の関数であることを利用し、KVの条件付きエントロピーを次トークンの条件付きエントロピーで上から抑える理論を提示する。70B規模、80層、64ヘッド、ヘッド次元128、トークン当たりの予測エントロピー約4.3ビットという例では、3ビット/成分のTurboQuant相当の保存量との比として約91万倍という理論的な数値を挙げる。

**この91万倍は実装された圧縮器のメモリ削減率でも、推論速度向上率でもない。** 原著に対応するGPU実験表はなく、復号時の予測KV再計算、誤差許容、索引維持、圧縮・復元時間を含めた実用性は検証されていない。トークン系列からKVを再計算できるという情報理論上の事実と、再計算を避けるためにKVをキャッシュするという推論システムの目的の違いが、本論文を評価する際の中心的な注意点である。

## 問題設定

自己注意では、過去トークンの鍵と値を保持し、次のトークンの問い合わせに対して再利用する。層数`L`、ヘッド数`H`、ヘッド次元`d`、文脈長`n`なら保存要素数は`2LHdn`であり、文脈が長くなるほどGPUメモリを圧迫する。量子化は各ベクトルの精度を下げ、削除方式は重要度の低い位置を捨て、接頭辞共有は同じトークン列に対応する計算結果を再利用する。

著者が問題視するのは、ベクトルごとの量子化がトークン列の予測可能性を利用しないことである。KVベクトルは任意の連続値ではなく、固定重みと入力トークンの組合せから決まる。元の入力系列が低エントロピーなら、連続値のベクトル全体を独立に記録するより短い記述が理論上存在する。原著はこの着眼を、セッション間の共通部分と、同一セッション内の逐次予測という二種類の冗長性に分けて扱う。

ただし、情報量が少ないことは、その情報からKVを**低計算費用で**復元できることを意味しない。例えば全トークンIDを保存すれば固定モデルのKVは再計算可能だが、それでは自己回帰推論でKVを保持する利点が失われる。本論文は情報理論上の可能性を示す段階であり、計算時間と保存量の交換条件を実測で閉じていない。

## 手法

### 固定モデルにおけるKVの決定性

モデル重みが固定され、推論時の計算が決定的であれば、位置`i`の全層・全ヘッドのKVはトークン接頭辞`(t_1,...,t_i)`から決まる関数`F_M`である。したがって、トークン列を確率変数と見たとき、KVがトークン列以上の情報を持つことはない。著者は、過去のKV系列が過去のトークン系列を識別できるという追加の条件を使い、`H(KV_i | KV_<i) <= H(t_i | t_<i)`という上界を論じる。

ここでのエントロピーは、モデルから生成される離散的なトークン系列に誘導された確率変数のシャノンエントロピーである。GPU上で浮動小数点KVを何ビットで保持すれば、所定の注意誤差や生成品質を達成できるかという、実装上のレート・歪み問題とは同一ではない。また過去KVから過去トークンを一意に復元できるという論証は、埋め込みと第一層の射影がトークンを識別できるという一般位置条件に依存する。あらゆる学習済みモデルで成立すると確認された実測結果ではない。

### 第一層：確率的接頭辞の重複排除

確率的言語トライは、モデルが各接頭辞に割り当てる次トークン確率を辺の重みとする木である。二つの系列`s,s'`について最長共通接頭辞`s∧s'`を取り、`d_T(s,s')=-log2 P_M(s∧s')`という量で共有構造を表す。共通接頭辞が長ければ、その部分のKVは固定モデルの決定性によって完全一致する。代表セッションを一つ保持し、他セッションでは代表との分岐以降の差分だけを保持すれば、同じKVの重複保存を避けられる。

原著は一定の距離閾値でセッションをクラスタ化し、確率が高い接頭辞を代表とする。代表の全KVを保存し、他セッションのKVとの差`Δ(s,s*)`を保存する。分岐以前の差はゼロなので、長い共通接頭辞があれば保存量を減らせる。分岐後の差が小さいという主張には、埋め込み差と層ごとのリプシッツ定数に基づく上界を使う。ただし深い層で定数が大きければ上界は緩くなり、差分が小さいとは保証されない。

名称に「意味的な接頭辞」とあるが、定義に現れる`s∧s'`は**トークン列の最長共通接頭辞**である。言い換えによって異なるトークン列が、意味が似ているだけで同じKVになるという仕組みではない。完全一致部分の共有は厳密だが、分岐後の近似差分には復元誤差が伴う可能性がある。この区別を曖昧にすると、通常の接頭辞キャッシュとの差分を過大評価する。

### 第二層：予測KVからの残差符号化

位置`i`の前までの文脈に対し、モデルが予測する次トークン分布`P_M(t_i|t_<i)`を使う。各候補トークンを入力した場合のKVを確率で重み付けした期待値を、予測KV `KVhat_i` とする。実際に選ばれたトークンのKVから期待値を引き、`R_i=KV_i-KVhat_i`だけを保存する。復号時は残差に同じ予測KVを加える。

次トークンがほぼ一意に決まる文脈では、期待値と実際のKVが近くなり、残差の大きさが小さくなると期待できる。原著は残差の二乗ノルム期待値を、候補トークンに関するKVの分散に結び付ける。残差の条件付きエントロピーについては、既知の文脈に依存する定数を引いても情報量が変わらないという性質を使う。**残差の平均がゼロに近いこと自体が、有限精度でどれだけ安全に圧縮できるかの証明ではない**ため、実際には分布と歪み許容の評価が必要である。

### 予測KVの計算費用を下げる案

正確な予測KVを求めるには、語彙の各候補トークンについてKVを計算する必要があり、約5万語彙なら極めて高価になる。原著は上位`k`個だけを計算する近似、または各層のKVを埋め込みの線形関数として近似する方法を提案する。前者は例えば`k=20`を用いる構想だが、20個の候補を評価する追加計算が完全にゼロになるわけではない。後者は期待埋め込みを一度計算し線形写像することで費用を抑えるが、非線形なTransformer全体のKVをどの程度正確に近似できるかは未測定である。

原著は推論ループに、KV書込前の予測・差分計算、KV読出前の予測再構成を挿入することを提案する。読み出し時に同じ予測値を得るためには、過去の文脈情報や予測に必要な状態が利用可能でなければならない。圧縮した全位置を復号するたびに大きな計算が必要なら、HBM節約が演算増加で相殺される。この依存関係が実用実装での重要な未解決点である。

### 二層と量子化の合成

共有接頭辞に対応する位置は代表キャッシュへの参照とし、分岐後の位置には予測KVからの残差符号化を使い、さらに残差ベクトルをTurboQuant等で量子化する三段階を提案する。接頭辞共有はセッション間の冗長性、残差符号化は同一系列の逐次冗長性を対象にするという整理である。

ただし、二種類の処理対象位置が異なることと、二つの圧縮利得が統計的に独立であることは別の主張である。原著は両者を直交的と説明するが、実データ上の独立性や合成利得を測定していない。共有できる接頭辞が少ないワークロードでは第一層の効果が小さくなり、トークン予測が難しいワークロードでは第二層の残差が大きくなる。

## 評価

この論文は**数式による上界と実装構想を中心とする理論研究**であり、原著にGPU上のエンドツーエンド推論時間、圧縮器の実測メモリ使用量、復元誤差と正答率の対応を示す比較表はない。以下は著者が示した仮定からの計算であり、実験結果ではない。

| 項目 | 原著の仮定・計算 |
|---|---|
| モデル規模の例 | 80層、64ヘッド、ヘッド次元128、鍵と値の両方 |
| 比較するベクトル量子化 | TurboQuant相当の約3ビット/成分 |
| トークン分布の仮定 | パープレキシティ10〜20、平均予測情報量約3.3〜4.3ビット/トークン |
| TurboQuant相当の保存量 | `2×80×64×128×3 ≈ 393万ビット/トークン` |
| 理論的な比 | 約393万/4.3 ≈ 91万倍 |
| 仮にエントロピー下限の1000倍で符号化できるとした比 | 約393万/4300 ≈ 914倍 |
| 実機GPU性能、モデル正答率 | 未評価 |

「エントロピー下限の1000倍でも914倍」という値は、実装が1000倍以内の符号長で動くと実証した結果ではなく、**仮定した符号長を代入した算術結果**である。KVを少数ビットで表現できても、その再構成に必要な計算時間や補助状態を無視している。従って、913,000倍程度のメモリ節約が可能だと実証されたという解釈は不適切である。

評価の比較軸は、各トークンに対応して保存するK/Vの理論符号量と、TurboQuant相当の約3ビット/成分という既存方式の仮定である。著者の計算例は80層・64ヘッド・ヘッド次元128で、鍵と値の両方を数える。予測エントロピーを3.3〜4.3ビット/トークンと置いた値から圧縮比を算出するが、これはデータセット上の実測符号長ではない。したがって比較表から分かるのは仮定に対する上界の大きさであり、実装後のVRAM削減率、遅延、生成品質の優劣ではない。

### 感度・構成要素除去・悪化条件

原著は、予測エントロピーが低いほど残差分散が小さくなるという理論上の関係、接頭辞共有率が高いほど共有の利得が増えるという関係、対象数と共通接頭辞長の関係を論じる。一方、接頭辞閾値を変えた際の実測キャッシュヒット率、上位`k`を変えた際の予測KV誤差、各層の圧縮率、実機での復号負荷を比較する構成要素除去実験はない。実験がないことを数値上の改善として補ってはいけない。

## 既存研究との差

KIVIやKVQuant、TurboQuantなどのベクトル量子化は、KVを保存したまま各成分のビット数を削減する。H2OやSnapKVなどの削除方式は、一部トークン位置のKVを破棄する。vLLMやSGLangの接頭辞共有は、複数要求の共通部分を再利用する。本論文は、こうした方式に加え、元トークン系列の確率構造から導かれる情報理論的な上限を利用しようとする。

特に、各位置のKVがトークン系列の決定的な関数である点を明示して、情報量とベクトル表現量の差を論じることは研究上の着眼点になる。しかし、実装可能な量子化手法のレート・歪み限界と、無制限の計算を許してトークンからKVを再生成できるという記述長の限界を同列に比較すると、速度・品質を含む実用的な優位性を誤認しやすい。

## 限界・批判的検討

第一に、モデルの出力トークン列からKVを再計算できるという事実は、再計算を避けるKVキャッシュの役割と緊張する。理論的な圧縮比は復号計算量を拘束しておらず、実機の高速化を保証しない。第二に、予測KVの期待値は本来語彙全体の候補計算を要する。上位`k`近似や線形近似は計算を抑える案だが、近似誤差と最終生成品質の関係は測定されていない。

第三に、最長共通接頭辞に基づく距離は、意味が似ていても文字列やトークンが異なる二系列のKVを厳密に共有できることを保証しない。分岐後の差分が小さいという主張にはモデルのリプシッツ定数に関する条件が必要で、深層で上界が大きくなる可能性がある。第四に、論文の理論は固定モデル・決定的前向き計算・モデル分布からのサンプリングという条件に依存する。外部から与えられる長文書や、モデルが予測しにくいコード・数値列などの分布では、仮定したパープレキシティが成立しない場合がある。

第五に、原著の第一層KV射影の単射性に関する論証は、トークン埋め込みと射影が異なるトークンを識別するという一般位置条件に依存する。これは実際のモデルについて全トークン対を検査したものではない。第六に、接頭辞索引、代表キャッシュ、残差符号、予測状態、復元時の作業領域を含めた総メモリを測っていない。実装判断には、単なる理論上の情報量ではなく、**保存量・復元演算・メモリ帯域・遅延・品質の同時評価**が必要である。
