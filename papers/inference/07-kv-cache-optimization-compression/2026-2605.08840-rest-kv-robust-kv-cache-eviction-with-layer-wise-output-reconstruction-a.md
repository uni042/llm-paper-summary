# ReST-KV：層別出力再構成と時空間平滑化による頑健なKVキャッシュ削除

## 書誌・位置づけ

Yongqi Anらによる、長文脈大規模言語モデルの推論時キャッシュ管理を扱う研究である。2026年5月9日にarXivへ公開された第1版を確認した。arXiv書誌にはICLR 2026採録と記載される。実装は著者公開の `an-yongqi/rest-kv` である。推論時の既存キー・バリュー（KV）対の選択を扱い、モデルの重みを再学習する手法ではない。重点は「削除前に注意を集めていたトークンが、削除後にも同じ寄与を持つとは限らない」という問題にある。

## 概要

自己回帰生成では、過去トークンのキーとバリューを各層・各ヘッドに保存する。入力文脈が伸びるとキャッシュの占有量と復号時の読み出しが増え、長文脈の同時提供でメモリ容量・帯域の制約が強くなる。従来のH2OやSnapKVなどは注意重みの累積・観測窓内の集約を重視するが、トークンを削除するとソフトマックスの分母が変わり、残されたトークンへの注意が再分配される。単なる重み順位では、削除によって注意出力がどの程度変わるかを直接評価できない。

ReST-KVは、各候補のKV対を一つ取り除いた場合に生じる注意出力の差を重要度として使う。全候補について注意演算を最初から再実行するのではなく、元の注意重み、バリューベクトル、出力射影から再構成誤差を解析的に求める。さらに短い観測窓内での時間変動を指数移動平均で抑え、重要位置の移動を観測窓の前半・後半から推定して空間平滑化する。事前充填時に各層・ヘッドの保持位置を決定し、その後の復号では小さいキャッシュを使う。

原著のLlama 3.1-8B-Instruct／RULERでは、4K～128K文脈の平均点がSnapKVの67.11点から82.27点へ上昇した。128K文脈では全キャッシュを維持するFlashAttention-2基準に対し、デコード遅延を約10.61分の1と報告する。ただし同条件の事前充填の初回トークン時間はSnapKVより約2.0%長く、全キャッシュと比べると約3.0%長い。速度改善の対象をデコード段階と明記する必要がある。

## 問題設定：注意重みだけでKV対を選べない理由

単一ヘッドの注意出力を `z = A V`、出力射影後を `o = A V W_O` とする。ここで `A[n]` は候補トークンnへの注意重みであり、通常の重みベース削除ではこの値が大きいものを保持する。だがnを削除すると、残存要素mの重みは `A[m]/(1-A[n])` へ再正規化される。除去したnの寄与が失われるだけでなく、他の値ベクトルの寄与も同時に増える。

たとえば大きな注意重みを持つトークンでも、そのバリューが他の保持候補と似ていれば、削除後の再配分によって注意出力が保たれる場合がある。逆に重みが比較的小さくても、他のバリューでは代替しにくい情報を持つ候補を削除すると出力誤差が大きくなる。従来の注意重みのみの選択は、この二つを同じ基準で区別できない。ReST-KVは、各層の出力を保つことをキャッシュ予算付きの最適化問題として定式化し、単純な重要度の大きさではなく削除の影響を測る。

## 手法

### 1. 層別出力再構成指標（Layer-wise Output Reconstruction; LOR）

層・ヘッドごとの予算をBとし、元のKV集合からB個以下を選んだ注意出力と、削除前の出力とのL2距離を最小化する。全組合せの最適化は高価なので、各候補を一つ除去したときの誤差を重要度として求め、重要度上位B個を貪欲に保持する。重要度 `I_t[n]` は、元の多頭注意出力と、nを除いた出力のL2距離である。

著者はソフトマックス再正規化を代入して、単一候補の誤差を次の式へ整理する。

`I_t[n] = A_t[n] / (1 - A_t[n]) × || MHA_t - v_n W_O ||_2`

第一因子は注意重みの非線形増幅で、特に重みの大きな候補を区別する。第二因子は、削除候補の射影済みバリューと現在の注意出力との差を測り、残存KVへの再分配で元の出力を再構成できるかを反映する。これにより全候補ごとにソフトマックスをやり直す代わりに、既に得られた注意とバリューから削除指標を構築する。分母 `1-A_t[n]` が小さい極端な注意集中では指標が大きくなり、その候補を強く保持する方向へ働く。

この指標は層・ヘッド単位の局所出力差であり、最終的な生成文章の意味誤差を直接最小化するものではない。各層での再構成を代理目的とし、予算Bの選択を局所的に行う点が近似である。重要度が各トークンの削除単独の影響から導かれるため、複数トークンを同時に削除したときの相互作用は貪欲選択に残る。

### 2. 時間方向の指数移動平均（Exponential Moving Average; EMA）

重要度は観測するクエリ位置によって変動するため、直近のクエリ窓 `S_w` にわたって `I_t[n]` を指数移動平均する。更新は `EMA_t = α I_t + (1-α) EMA_(t-1)` で、著者は `α=0.3` を採用する。直近の観測を優先しつつ、ある一つのクエリで偶然注目された候補が過大評価されるのを抑える。

一方、最近の `S_w` 個のトークンには非常に大きな保持優先度Ωを与え、平滑化の対象から事実上除外して残す。古い重要トークンをLORとEMAで評価し、直近トークンは局所文脈のため保護する二層構造である。これは観測窓の短さに由来する不安定さを緩和するが、最新トークンの固定保護は小予算で古い情報を残す余地を減らし得る。

### 3. 空間方向の適応窓平滑化（Adaptive Window-based Smoothing; AWS）

重要度が高い位置は、クエリが進むにつれて一定の方向へ移動する場合がある。著者は観測窓を前半と後半に分け、それぞれで上位B個の重要位置の平均 `D_front`、`D_rear` を求める。両者の差を位置の移動量とみなし、拡張窓幅 `W_s = 2 floor(|D_rear-D_front|/β)+1` と移動方向を反映する窓のシフトを計算する。`β=2000` は移動幅の刻みを調節する係数である。

平滑化後の各位置の重要度は、この適応窓で近傍の時間平滑化指標を平均した値となる。固定幅の近傍集約と異なり、観測された移動が大きいほど窓を広げ、窓の中心もずらすため、重要な縦線・斜線状の注意構造を追跡しやすい。AWSはLORを置き換えるのではなく、LORから得たスコアを位置方向に安定化する後処理である。

### 4. 保持位置の確定と復号への接続

LORで各候補の除去誤差を計算し、EMAで観測時刻方向を平滑化し、AWSで位置方向を平滑化した最終指標の上位B位置 `D_t` を選ぶ。各層・ヘッドに対し `K[D_t,:]` と `V[D_t,:]` を残し、残りを削除する。原著の比較条件では削除は事前充填時に一度だけ行い、復号中に逐次再評価して入れ替える方式ではない。選択結果は復号時の注意演算が読み込むKV対数を直接減らす。

観測窓は原則 `S_w=32`、通常の近傍カーネル幅は5、RULERとInfiniteBenchでは21である。平滑化係数 `α=0.3` と空間係数 `β=2000` はモデル・タスク別に調整せず固定している。KV削除方式と予算配分方式を分離しているため、PyramidKVの層別配分やAdaKVのヘッド別配分と組み合わせられる。

## 評価条件と主要結果

原著はNVIDIA A800 80GB GPUを使用し、多頭注意のLlama2-7B-Chat、Gemma-7B-Instructと、グループ化クエリ注意のLlama3.1-8B-Instruct、Mistral-7B-Instruct-v0.3、Qwen2.5-7B-Instructを比較する。追加実験にはLlama2-13B-ChatとLlama3-70B-Instructが含まれる。予算は各層のKV対数nと層数Lの積 `B_total=nL` で表し、nを64～1024で変更する。主な比較方式はStreamingLLM、H2O、TOVA、SnapKV、LaCacheである。評価は長文脈理解のLongBench（16データセット）、RULER、針探索、InfiniteBenchを含む。

RULERの長さ別結果を見ると、4KではReST-KV 94.01点、SnapKV 83.60点で、128Kでは68.28点対47.99点である。長さが伸びると両方式とも精度が低下するが、重要度の再分配と移動を扱う提案方式は、低予算で情報を拾い直す能力を相対的に保つ。全キャッシュの128K精度79.32点にはなお届かないため、「キャッシュを削除しても性能劣化がない」という結論は誤りである。

### 構成要素除去実験と感度

Llama3.1-8B、LongBench、128L予算で、全機構35.86点に対し、LORなし33.95点、EMAなし34.02点、AWSなし33.50点となる。寄与はそれぞれ1.91、1.84、2.36点であり、三要素は別々の誤差源に作用する。LORは注意再分配を扱い、EMAはクエリ時刻ごとの短期変動を抑え、AWSは重要位置の移動を補足する。各除去による点数差を単純に足して全体の改善幅とみなすことはできない。

層別予算配分のPyramidKVと組み合わせたLlama2-7Bの五予算平均は30.48点から30.93点へ、ヘッド別配分のAdaKVと組み合わせた場合は30.48点から31.20点へ上がる。これは選択指標と予算配分が独立に調整できる証拠だが、加算利得は0.45点、0.72点と小さく、追加の配分計算を含む端から端までの速度改善は示されていない。原著の感度実験ではαとβを広い範囲で動かしても比較的安定していたが、データ分布が大きく変わる運用条件で同じ設定が最適とは限らない。

### 事前充填の費用と推論高速化の境界

事前充填では短い観測窓について元の注意出力とバリュー射影から重要度を計算するため、追加の読み書きと集約処理がある。著者は支配的計算量をSnapKVと同じ `O(wND)` と記し、wを観測クエリ窓、Nを文脈長、Dを特徴次元としている。しかし同じ漸近計算量は同じ実測時間を意味しない。128K条件でSnapKV 28.510秒に対しReST-KV 29.082秒であり、約0.572秒の追加時間がある。

一方、復号では保持KV数が小さいので読み出しと注意演算の仕事量が減る。10.61倍という結果はこの復号局面で全キャッシュと比較した数値で、事前充填、モデルの他層演算、ネットワーク、スケジューリングを含むサービング全体の改善率ではない。原著の本文には疎な事前充填注意との組合せによる初回トークン時間の高速化倍率として2.37倍と3.42倍の異なる記載がある。比較構成が明示されないまま単一の確定倍率として採用せず、実験図表と条件が揃うまで参考値とする。

## 既存研究との差

StreamingLLMは先頭・近傍トークンを保護する固定パターン、H2Oは重い注意の蓄積、SnapKVは観測窓の注意重みを集約する。これらは保持すべきトークンの位置や重みを推定する一方、削除後に残存KVのソフトマックス重みが変わる影響を直接目的化しない。ReST-KVは出力再構成誤差を解析式にして保持指標とし、時間変動と空間移動の二つの平滑化を組み合わせる。

PyramidKVとAdaKVは主に層間・ヘッド間で予算をどう分配するかを扱う。ReST-KVは与えられた予算内でどのKV対を残すかを決めるため、両者と組み合わせられる。KIVIなどのKV量子化は保持する値の表現精度を削る別軸であり、トークン単位の削除とはトレードオフが異なる。これらの組合せによる速度・品質は、個別に測定した削減率を単純に掛け合わせて見積もれない。

## 限界・未評価事項

第一に、削除の指標は各層・各ヘッドの単一KV対を取り除いたときの局所出力差であり、複数対の同時削除や後続層を通じた生成品質を厳密に最適化するものではない。出力誤差が小さくても、固有名詞の取り違えなど下流タスクの失敗が完全に防げるとは限らない。長文脈での性能差は保持予算とモデルに強く依存し、RULERの128Kでは全キャッシュより11.04点低い。

第二に、EMAとAWSは最近のクエリ窓から重要度の安定性・移動傾向を推定する。急激な話題転換や後から参照される古い情報では、事前充填時に一度決めた保持集合を復号中に再評価しない制約が表面化し得る。新しいトークンの固定保護、平滑化係数、窓幅、予算配分も、極端な小予算や長い複数ターン対話で別の最適値を持つ可能性がある。

第三に、実験は主にNVIDIA A800 80GB上の特定モデル・評価ベンチマークであり、GPUメモリ断片化、実サービングでの多数同時要求、CPUオフロード、分散KVキャッシュ、独自注意カーネルとの統合性能を包括的に測ったものではない。とくにWindowsローカル推論環境へそのまま速度倍率を外挿できない。学習不要という性質は導入障壁を下げるが、推論器が層・ヘッドごとの非連続KV保持と専用の事前充填時選択を実装する必要がある。

第四に、公開原稿の一部には数値・説明の不整合がある。初回トークン時間の表では全キャッシュ比約3%増、SnapKV比約2%増だが、本文中の「約2%追加」とは比較基準が異なる。疎な事前充填注意と組み合わせた改善率にも異なる値がある。ここでは表に直接載る実測値を優先し、比較基準が不明な倍率を確定的に一般化しない。
