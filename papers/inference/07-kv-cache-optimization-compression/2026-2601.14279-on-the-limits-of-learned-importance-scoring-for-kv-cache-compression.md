# 学習型KV重要度評価の限界：複雑な予測器が位置ヒューリスティックに勝てなかった負の結果

## 概要

「On the Limits of Learned Importance Scoring for KV Cache Compression」は、長文脈推論の鍵値（KV）キャッシュから保持するトークンを選ぶ際、**KVの内容を学習器で評価すれば、位置や入力処理時の注意に基づく単純な選択を上回るか**を検証した研究である。著者は1.7百万パラメータの重要度予測器SIP（Speculative Importance Prediction）を構築し、将来1・4・16・64トークン先の注意を予測する複数期間の出力、直近32位置への交差注意、位置・鍵・値・過去の注意特徴を組み合わせた。

しかし、TinyLlama-1.1B-Chat-v1.0、最大2048トークンの評価では、5乱数種・4保持率・3課題のいずれでも、SIPは単純な基準方式に対する統計的に有意な優位を示さなかった。WikiText-2の保持率50%でパープレキシティはSIP 8.91、位置ヒューリスティック8.85、入力処理時の注意に基づく方式8.82だった。SIPの複雑な部品を外しても成績は悪化せず、位置特徴だけを使った構成がむしろ8.85と良かった。

この論文は学習型KV圧縮全般の不可能性を主張するものではない。対象は、**生成時の現在の問い合わせを使わず、固定保持予算の中でどのトークンを残すかを予測する方式**である。層・ヘッド間の予算配分、量子化、生成時問い合わせに応じた選択、再構成可能な圧縮は異なる問題として区別する。単純な方式を上回れなかったという結果自体が、研究資源の配分とベースライン設計に有用である。

## 問題設定：保持すべきKVは未来の問い合わせで変わる

自己回帰LLMでは、生成ステップごとに過去の鍵と値を参照する。KVキャッシュは系列長に比例して増えるため、限られた装置メモリで長文脈や複数要求を扱うには、一部のトークンを保持し、残りを削除する方式がある。先頭の注意の吸い込み点（attention sink）と直近のトークンを残す位置ベースの方法、入力処理時の注意を使う方法、累積注意を使うH2Oなどが代表的である。

学習型の重要度推定は、鍵・値ベクトルに意味情報が含まれ、単純な位置や注意スコアでは表せない将来の重要度を推測できるという仮説に立つ。SIPはこの仮説を強く試すために設計された。推論時の問い合わせ `q_t` を見ず、キャッシュ挿入時に各位置の重要度 `s_i=f(k_i,v_i,i,c_i)` を一度計算する。これなら生成ステップごとの追加評価が不要で、低遅延配信に向く。

ただし、どの過去トークンを参照するかは将来の問い合わせベクトルに依存する。将来の問い合わせはこれから生成される文脈に依存し、さらに生成される文脈自体がKVの保持・削除判断で変わり得る。論文はこれを将来注意と生成経路の循環依存と説明する。現在のKVだけから将来の全問い合わせを推定するのは本質的に難しい可能性があるが、数学的な不可能性の証明ではない。

## 手法：複数期間の将来注意を予測するSIP

### 入力特徴と局所的な交差注意

SIPは各層・ヘッド・トークン位置の鍵ベクトル `k_{h,i}`、値ベクトルのノルム `||v_{h,i}||`、位置埋め込み `PE(i)`、最近受け取った注意 `a_recent` を連結して特徴 `x_{h,i}` を作る。単に位置だけで決めるのではなく、モデル内部のKV表現と過去の利用傾向も取り込む。

次に、位置 `i` から直近32位置の特徴へ交差注意（cross-attention）を適用し、局所文脈表現 `c_i` を得る。これにより、一つのトークンの重要度を孤立したベクトルだけから評価するのではなく、周辺トークンとの関係を取り込むことを狙う。評価器全体のパラメータ数は約1.7Mで、交差注意が約0.8M、複数の多層パーセプトロン（MLP）が約0.7M、埋め込みが約0.2Mを占める。

### 複数の将来期間と重み付き統合

将来1、4、16、64トークンの四つの期間 `τ` について、別々のMLPが重要度 `s^(τ)_{h,i}` を予測する。各予測は `σ(MLP_τ([x_{h,i};c_i]))` の形で作られ、最終スコアは `s_{h,i}=Σ_τ w_τ s^(τ)_{h,i}`、`Σ_τ w_τ=1` として統合する。短期の注意と長期の注意で重要なトークンが異なる可能性に対応するための設計である。

学習時の教師信号は、実際の生成後に観測した将来 `τ` トークンの平均注意である。各期間の予測と観測を二値交差エントロピーで照合し、さらに期待校正誤差（expected calibration error; ECE）による校正項を損失へ加える。SIPは予測器であり、対象LLMの注意機構を置き換えるものではない。学習済みスコアの順位から保持予算分だけKVを残し、その状態で対象モデルの生成品質を評価する。

### 学習と評価の分離

TinyLlama-1.1B-Chat-v1.0の注意パターンを用い、OpenWebTextから1,000系列（各2048トークン）を学習に使用する。最適化はAdamW、学習率3×10^-4、バッチ32、重み減衰0.01、最大50エポック、早期停止の忍耐5エポック、初期1000ステップの線形ウォームアップ、勾配ノルム上限1.0で行った。評価時には学習器だけでなく、乱数選択、先頭4トークンと直近を残す位置法、入力処理時注意、H2O、StreamingLLMを同じモデル実行条件で比較する。

この設計では、SIPが勝たなかった原因を単に「学習器が小さすぎた」と断定することはできないが、複数期間・交差注意・校正損失を追加しても簡単な規則を超える信号が抽出できなかったことは検証できる。

## 評価

評価では、将来の問い合わせを見ずに保持トークンを決める学習型予測器SIPが、単純な位置選択・入力処理時の注意・累積注意・ランダム選択より有利かを検証している。対象はTinyLlama-1.1B-Chat-v1.0で、学習にはOpenWebTextの2048トークン系列を1000件使用した。評価はWikiText-2の言語モデル困惑度、SQuADの完全一致率、文書中に埋め込んだ事実の検索正答率という異なる三課題である。乱数種を5つ変え、KV保持率を10・25・50・75%に設定し、同一系列で方式間を対応付けた統計検定を行った。したがって単発の小差ではなく、条件を揃えた相対評価を読める。

言語モデルの保持率10%では、SIPの困惑度12.31に対して位置法11.98、入力時注意法12.15であり、SIPは最良ではない。25%でもSIP9.87に対して位置法9.71、50%ではSIP8.91に対して入力時注意法8.82、75%でもSIP8.58に対して入力時注意法8.51だった。低い困惑度ほど良い指標である。SIPと単純方式の差は5乱数種の対応あり検定で有意な改善と認められず、10%保持のSIP信頼区間幅±0.42はランダム方式との差0.14より大きい。結果を「ランダムと完全同一」と断定するのではなく、優位を示す証拠が不足したと読む。

保持率50%の質問応答ではSIPの完全一致率68.2%に対して入力時注意法70.3%、検索ではSIP89.5%に対して同方式92.8%である。全KV保持ではそれぞれ72.4%、98.0%なので、圧縮自体の品質損失も残る。部品除去では交差注意を外した困惑度8.93、複数期間予測を外した8.90、位置特徴のみ8.85で、複雑な構造が有効だったとは言い難い。相互情報量推定でも位置0.31±0.05ビット、鍵特徴0.12±0.03ビットという差があり、位置の予測信号が強い。ただし推定方法に依存し、将来問い合わせの予測が理論的に不可能と証明したわけではない。実機の復号速度やGPUメモリ節約の実測を示す論文ではなく、**固定保持率における生成品質**の比較が中心である。

### 評価条件複数乱数種と同一計算条件

| 項目 | 条件 |
|---|---|
| 対象モデル | TinyLlama-1.1B-Chat-v1.0 |
| GPU | 単一NVIDIA A100 40GB |
| 学習 | OpenWebText 1,000系列×2048トークン、SIP 1.7Mパラメータ |
| 言語モデル評価 | WikiText-2、100系列×2048トークン、パープレキシティ（低いほど良い） |
| 質問応答 | SQuADの50例、完全一致率（高いほど良い） |
| 検索 | Needle-in-a-Haystack、文書中の異なる深さに事実を配置した検索正答率 |
| KV保持率 | 10%、25%、50%、75%、無圧縮100% |
| 反復・統計 | 乱数種5、階層ブートストラップによる95%信頼区間、対応ありt検定（有意水準0.05） |
| 総計算量 | 論文記載の実験総量約12 GPU時間 |

同じ評価系列とモデルの前向き計算を用い、保持戦略だけを変えている。対応ありt検定を採用したのは、同じ系列に対する方法間の差を比較するためである。信頼区間は系列内と乱数種間の変動を考慮している。モデルの速度改善を実測した研究ではなく、固定保持予算における生成品質の比較である。

### 主要結果1：学習型スコアは単純な保持法に勝てなかった

WikiText-2のパープレキシティを保持率別に示す。低い値ほど良く、全KVを保持した場合は8.42±0.03だった。

| 保持法 | 10% | 25% | 50% | 75% |
|---|---:|---:|---:|---:|
| SIP（学習型） | 12.31 | 9.87 | 8.91 | 8.58 |
| ランダム | 12.45 | 9.92 | 8.89 | 8.55 |
| 位置ヒューリスティック | **11.98** | **9.71** | 8.85 | 8.54 |
| 入力時注意 | 12.15 | 9.78 | **8.82** | **8.51** |
| H2O | 12.28 | 9.85 | 8.88 | 8.56 |
| StreamingLLM | 12.02 | 9.73 | 8.86 | 8.55 |

表1の結果では、最も厳しい10%・25%保持で位置法が最良、50%・75%保持では入力時注意法が最良だった。SIPとランダムの差は10%保持で12.31対12.45、50%保持で8.91対8.89と小さく、5乱数種の対応あり検定で統計的有意差を確認できなかった。SIPの10%保持の95%信頼区間は±0.42、ランダムは±0.51で、差0.14を大きく上回るばらつきがある。

この結果は「学習器がランダムより必ず悪い」ではない。観測された差からは学習器が優位である証拠を得られなかった、という主張である。75%保持では全方式の差が小さくなり、保持予算が十分あると選択方式の差が見えにくくなることも示した。

### 主要結果2：質問応答と検索でも優位はない

保持率50%での三課題の比較を示す。言語モデルはパープレキシティ、質問応答は完全一致率、検索は正答率である。

| 方式 | WikiText-2 PPL↓ | SQuAD EM↑ | Needle正答率↑ |
|---|---:|---:|---:|
| 全KV | 8.42 | 72.4% | 98.0% |
| SIP | 8.91 | 68.2% | 89.5% |
| 位置法 | 8.85 | 69.1% | 91.2% |
| 入力時注意 | **8.82** | **70.3%** | **92.8%** |
| H2O | 8.88 | 68.8% | 90.1% |
| StreamingLLM | 8.86 | 69.5% | 91.5% |
| ランダム | 8.89 | 67.5% | 88.2% |

表2では、SIPの質問応答68.2%は入力時注意の70.3%を下回り、Needle検索89.5%も入力時注意の92.8%を下回る。全KVとの差も残るため、複雑な重要度予測器が単純な入力時注意より品質を守れるという仮説は支持されなかった。言語モデル評価だけの偶然ではなく、質問応答・検索でも同じ傾向がある点が重要である。

ただしSQuADは50例、WikiText-2は100系列であり、評価対象は大規模な実運用負荷ではない。検索の位置を変えた試験を含むものの、32K以上の文脈で同じ順位が成立するとは限らない。

### 主要結果3：部品を外しても性能が下がらない

SIPの複雑な設計が有効かを確かめるため、保持率50%で構成要素を除去した。表3のパープレキシティは次のとおりである。

| 構成 | PPL（低いほど良い） |
|---|---:|
| 完全SIP | 8.91 |
| 交差注意を除去 | 8.93 |
| 複数期間の予測を除去 | 8.90 |
| 鍵ベクトル特徴を除去 | 8.88 |
| 値ベクトル特徴を除去 | 8.89 |
| 位置特徴のみ | **8.85** |
| ランダム | 8.89 |

交差注意を除去しても8.93でほぼ同じ、複数期間の予測を除去すると8.90へわずかに改善し、鍵・値特徴を除いても性能は悪化しない。位置だけの8.85が完全SIPを上回る。これは学習器が鍵・値の豊かな意味情報を利用しているというより、位置に依存する単純な規則を再学習している可能性を示す。学習器を大きくする前に、どの特徴が実際に予測力を持つかを検証すべきという示唆が得られる。

## なぜ負けたのか：未来の問い合わせを見られない問題

論文は、将来位置 `t` から過去位置 `i` への注意 `A_{t→i}` は、将来の問い合わせ `q_t` と現在の鍵 `k_i` の相性で決まると考える。ところがSIPは`q_t`を知らず、現在のKVと位置情報だけから平均的な将来注意を予測しなければならない。将来の問い合わせは生成経路に依存し、その生成経路はKVの削除によっても変化するため、予測問題は循環依存を含む。

論文の相互情報量の推定では、鍵特徴と将来注意の間は約0.12±0.03ビット、位置と将来注意は0.31±0.05ビット、入力時注意と将来注意は0.28±0.04ビットだった。少なくともこの実験では、位置と入力時注意の方が鍵表現より予測に使える情報を持っている。相互情報量は離散化の設定に依存する推定であり、因果関係や理論上の不可能性を示すものではない。

校正分析では、SIPの期待校正誤差（ECE）が0.18で、重要度の予測値が実際の将来注意を十分に表していないことも分かった。予測が過信気味で、重要度を高低に識別する能力が弱いという図6の観測は、単に評価の平均値が低いだけではない失敗の形を示す。

## 既存方式との違いと実務上の判断

H2OやStreamingLLMは、注意や位置に基づく単純な保持法であり、追加学習が不要である。SIPは1.7Mパラメータの学習器、教師となる将来注意の収集、交差注意、複数期間予測、校正損失を追加している。それでも品質が改善しなければ、追加の学習・運用費用を正当化しにくい。

一方、QuestやTokenButlerのように**現在の問い合わせを使って毎ステップ重要度を再評価する方式**は、SIPとは情報条件が違う。生成時の問い合わせを使えるなら、どの過去トークンが必要かを直接推定できる可能性がある。ただし再評価の計算費用を負うため、速度・品質・メモリの別の交換になる。また、PyramidKVやDMCのように層・ヘッドへの予算配分や固定スロットへの圧縮を学習する方式も、本論文の固定予算内の二値選択とは異なる。

このため実務上の結論は、KVを厳しく削るならまず先頭の注意吸い込み点と最近のトークンを残す位置法、比較的緩い圧縮なら入力時注意に基づく保持法を強いベースラインにする、という範囲にとどめるべきである。別モデルや長文脈での最適方式は改めて検証する必要がある。

## 限界と再現可能性

第一に、評価はTinyLlama-1.1Bと最大2048トークンに限定される。7B以上のモデル、32K以上の長文脈、MambaやRWKVなど別の構造、複数GPUの推論配信へは結果を直接一般化できない。研究が対象とするのはKV内のトークン保持順位であり、エンドツーエンド推論TPSの改善倍率を示すものではない。

第二に、SIPは学習型重要度推定の一実装にすぎない。より適切な教師信号、問い合わせ条件付きの特徴、層別の予算配分などで結果が変わる可能性は排除されない。「学習型KV圧縮は全て無効」と読むのは論文の主張を超える。

第三に、相互情報量の分析は観測的で、離散化の方法に依存する。将来の問い合わせと生成経路の循環依存はもっともらしい説明だが、実験だけで普遍的な限界を証明したわけではない。予測器の校正誤差0.18も、他モデルの全ての学習器に当てはまる値ではない。

第四に、負の結果は評価の厳密さによって支えられている。5乱数種、階層ブートストラップ信頼区間、対応あり検定、複数保持率と三課題、部品除去を揃えたからこそ、見かけ上の小差を「改善」と誤認せずに済む。単一試行で0.1程度のPPL差を見て新方式の優位を主張することは避けるべきである。
