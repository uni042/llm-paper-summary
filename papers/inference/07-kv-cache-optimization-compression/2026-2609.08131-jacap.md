# Jacap: Robust KV Cache Eviction via Jacobian-Based Nonlinear Information Capacity Preservation

> KV cache evictionをsoftmax attentionの非線形通信channelとして捉え、future queryからattention outputへの局所Jacobianに基づく情報容量を導出する。実用版Jacapはquery relevance、softmax sensitivity、value/output方向のdiversityを統合した重み付きleverage scoreでtokenを選び、高圧縮LongBench、NIAH、decoding-stage AIME25で既存法より頑健な保持性能を示す。
## 書誌情報
- **著者**: Jiaming Yang, Chenwei Tang, Liangli Zhen, Chenyang Zhang, Jiancheng Lv
- **公開**: arXiv:2609.08131v1, 2026-09-08
- **種別**: arXiv preprint
- **対象**: KV cache eviction、KV cache compression、long-context inference、information theory、softmax attention、Jacobian、leverage score、decoding memory
- **実装**: arXiv v1本文ではJacap固有の公式code repository公開を確認できない。実験は4x NVIDIA RTX Pro 6000、Ubuntu 22.04、1024 GB system memoryで実施。
## 問題設定
attention score、recency、value norm等のKV eviction heuristicはtokenを独立に評価しやすく、retained subset内の冗長性・補完性を十分扱えない。CapKVはinformation capacityを導入したがlinear-Gaussian surrogateのため、softmaxの正規化・飽和・token間competitionという本来の非線形性を捨てている。
## 新規性
retained attentionをfuture queryからoutputへの非線形Gaussian channelとして定式化し、代表query周辺の局所Jacobianからmutual-information型のJacobian Information Capacityを導出する。実用algorithmではsoftmax sensitivityとquery-response varianceをtoken重みに落とし、output-space diversityをleverage scoreで保持する。
## 手法
### 手法のあらまし
future queryを平均mu_Q、共分散Lambda_Qの局所分布とみなし、f_C(q)=U_C softmax(K_C q/sqrt(d_k))を一次Taylor展開する。J_C=U_C S_C K_C/sqrt(d_k)から0.5 logdet(I+Sigma_noise^-1 J_C Lambda_Q J_C^T)を容量とする。online subset searchを避けるためpre-eviction poolでattention priorを計算し、softmax Jacobianとquery covarianceを対角近似してw_i=(1/d_k) alpha_i^2(1-alpha_i)^2 kappa_iを得る。A=I+sum w_i u_i u_i^Tを作り、score_i=w_i u_i^T A^-1 u_iで上位tokenを保持する。

### Local nonlinear attention channel
retained KV subsetが定義するsoftmax attention mappingをnoise付き非線形channelとして扱い、future queryの局所分布を導入する。

### Jacobian Information Capacity
Jacobian J_C=U_C S_C K_C/sqrt(d_k)によりkey accessibility、output direction、softmax competition、query statistics、model uncertaintyを同じlog-det objectiveへ統合する。

### Softmax-sensitive token weight
subset依存attentionをfull candidate poolで近似し、S_CとK Lambda_Q K^Tを対角化。alpha^2(1-alpha)^2により低attentionだけでなく飽和した高attention tokenも局所感度が低いことを表現する。

### Capacity matrix and leverage score
A_Jac=I+sum_j w_j u_j u_j^Tを構成し、w_i u_i^T A^-1 u_iで重要性とstructural diversityを同時評価する。

### Query-statistics estimation and temperature
historical queryからmu_Q/Lambda_Qを推定し、temperature tauでattention priorのsharpnessを調整。LongBench ablationではtau≈10が最良。

### 全体のデータ／制御の流れ
既存LLMを再学習せず、各layer/headのeviction時にcandidate KVとquery statisticsからscoreを算出してbudget Bのsubsetを残す。prefill後の圧縮だけでなくautoregressive decoding中の動的evictionにも適用でき、KV量そのものを削減するためquantizationやPagedAttention等のsystem-level memory managementと直交的に併用可能。
## 評価条件
- **Hardware**: 4x NVIDIA RTX Pro 6000 GPUs、1024 GB system memory、runtime appendix: Qwen3-8B generation-time benchmark uses a single NVIDIA RTX Pro 6000 GPU
- **Software**: Ubuntu 22.04、Jacap-specific official code repository was not linked in arXiv v1
- **Model**: Qwen3-8B、Qwen3-14B、Llama3.1-8B、Nemotron-7B
- **Dataset / Trace**: LongBench、Needle-in-a-Haystack (NIAH)、AIME25
- **Baseline**: CapKV、SnapKV、KeyDiff、Expected Attention (EA)、KNorm
- **Correctness**: Jacap is a lossy KV-cache eviction method: discarded states can change model outputs, so equivalence to the uncompressed model is not guaranteed. Quality is measured on LongBench, NIAH, and AIME25. No retraining is required.
- **LongBench**: Qwen3-8B, Qwen3-14B, Llama3.1-8B; compression ratios 0.25, 0.5, 0.75, 0.9; main discussion emphasizes 0.75/0.9.
- **NIAH**: Qwen3-8B; compression ratio 0.75 in main text and 0.5 in appendix; context lengths 10k-120k tokens; needle depths 0.15-0.95.
- **decoding eviction**: AIME25 with Nemotron-7B; reserved-token budgets 2048, 4096, 8192, 16384.
- **temperature ablation**: Qwen3-8B LongBench; best overall behavior around tau=10.
- **runtime**: Generate 100 tokens with Qwen3-8B on one RTX Pro 6000; input contexts 8k-64k; compression ratios 0.6 and 0.8.
Three long-context model architectures are compared on LongBench, sparse long-range retrieval is stressed with NIAH, dynamic decode-time eviction is tested with AIME25, and Appendix C measures runtime overhead. Query statistics are estimated from historical decoding queries; diagonal covariance is used in practice.
Evidence supports retention quality under KV compression rather than a complete serving-system speedup claim. Runtime is described as comparable to mainstream baselines, but exact Figure 5 timings are not tabulated in the HTML text. Theoretical per-layer/eviction complexity is O(N d_h^2 + d_h^3).
## 主要結果
Jacap is strongest under high KV compression. LongBench and NIAH show more robust retention than heuristic baselines, while AIME25 decode-time eviction is mixed across cache budgets.

- LongBench average / 40.91 (比較対象: CapKV 36.57; EA 36.35; 条件: Qwen3-8B, compression ratio 0.9) — +4.34 points over CapKV under extreme compression.

- LongBench average / 35.98 (比較対象: KeyDiff 34.89; EA 34.51; CapKV 30.48; 条件: Llama3.1-8B, compression ratio 0.9) — Smaller but positive gain over the next-best listed baseline.

- AIME25 score / 0.30 (比較対象: CapKV 0.20; EA 0.17; KeyDiff 0.07; KNorm 0; 条件: Nemotron-7B, 2048 reserved tokens) — Best result at the tightest tested decode-cache budget.

- AIME25 score / 0.50 (比較対象: CapKV 0.50; 条件: Nemotron-7B, 4096 reserved tokens) — Ties CapKV.

- AIME25 score / 0.73 (比較対象: CapKV 0.67; KeyDiff 0.67; EA 0.63; 条件: Nemotron-7B, 16384 reserved tokens) — Best result at the largest tested budget.

- NIAH retrieval / best overall robustness (比較対象: CapKV, SnapKV, KeyDiff, EA, KNorm; 条件: Qwen3-8B; 10k-120k contexts; needle depths 0.15-0.95; C.R. 0.75 main and 0.5 appendix) — Jacap remains stronger for long contexts and deep needle positions.

### 負の結果・境界条件
- **AIME25 8192-token reversal**: Jacap scores 0.53 while CapKV reaches 0.73; Jacap is not uniformly best across budgets.
- **Approximation boundary**: The practical score diagonalizes softmax competition and query covariance, so pairwise and higher-order interactions are omitted.
- **Extra scoring cost**: Per-layer eviction complexity is O(N d_h^2 + d_h^3), higher than typical independent heuristic scoring.

### 結果の読み方
The contribution is improved robustness under aggressive lossy compression rather than universal dominance. Softmax sensitivity discounts saturated attention, and the leverage term discourages redundant output directions.
## 品質への影響
KV eviction is lossy and can change task accuracy. Jacap generally degrades more gracefully at high compression, but the AIME25 8192-token condition is a clear counterexample.
## 既存研究との差
- H2O/SnapKVなどのattention heuristicは主に観測attentionや頻度でtokenを個別採点するのに対し、Jacapはfuture-query分布に対するsoftmax局所感度と、保持subset内のoutput方向の重複を同時に扱う。
- KeyDiff/KNormはkey geometryやnormなど軽量proxyを使うのに対し、Jacapは非線形attention channelの情報容量から重みを導出し、weighted leverage scoreでsubset diversityを評価する。
- CapKVがlinear-Gaussian attention surrogateのlog-det information capacityを使うのに対し、Jacapはsoftmax Jacobian S=Diag(alpha)-alpha alpha^Tを導入し、飽和とtoken competitionを理論目的へ明示的に含める。
- PagedAttentionやKV quantizationのような配置・表現圧縮とは異なり、Jacapは保持するtokenそのものを選ぶstructural KV compressionであり、system-level memory managementと原理上は併用可能。
## 限界
- 理論は代表query周辺の一次Taylor近似であり、future query分布が大きく移動する高度に動的なdecodingでは高次非線形性を取り逃がす可能性がある。
- 実用Jacapはsoftmax competition matrixとK Lambda_Q K^Tを対角近似するため、理論式が持つtoken間pairwise couplingを完全には保持しない。
- capacity matrix構築・逆行列・leverage scoreによりO(N d_h^2 + d_h^3)の追加計算があり、単純attention/norm heuristicより重い。
- LongBench/NIAH/AIME25中心の評価で、production servingのthroughput、batching、memory allocator、multi-tenant workloadまで含むend-to-end system評価ではない。
- AIME25の8192 reserved-token条件ではCapKV 0.73に対しJacap 0.53で、budgetによって順位が反転する。
- arXiv v1本文・arXiv pageではJacap固有の公式code repositoryを確認できず、現時点の再現性は論文記述に依存する。
