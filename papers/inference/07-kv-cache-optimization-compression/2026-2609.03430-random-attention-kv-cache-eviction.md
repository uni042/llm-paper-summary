# Random Attention: Rethinking KV Cache Eviction for Efficient Reasoning

> promptを固定保護したうえで生成済みreasoning tokenのKVをattention headごとにランダム保持し、重要度score計算なしで高い品質とserving throughputを両立する。

## 書誌

- **著者**: Heng Wang, Jielin Qiu, Wenting Zhao, Cheng Qian, Liangwei Yang, Jiawei Han, Heng Ji, Silvio Savarese, Shelby Heinecke, Huan Wang
- **公開**: arXiv:2609.03430v1, 2026-09-03
- **公式コード**: SalesforceAIResearch/Random-Attention

## 問題

長いreasoning traceではKV cacheが大きなmemory bottleneckになる。既存のeviction方式はattention scoreやvalue統計等から「将来重要なtoken」を順位付けするが、そのscore計算自体がruntime overheadになる。

## 手法

Random Attentionはprompt部分を必ず保持し、その後の生成tokenについて各KV headで独立に一様ランダムなsubsetを残す。短いrecent windowも保持するが、attention score・value statistic・calibration dataを重要度判定に使わない。

論文のmechanism studyでは、reasoning taskで壊れやすいのはprompt側であり、生成されたreasoning traceは文章上の再記述とhead間の冗長性によってevictionへ比較的頑健だと分析する。

## 評価条件と主要結果

Qwen3-4B / 14B / 32B、Phi-4-reasoning等をMATH-500、GPQA-Diamond、AIME、HMMT、LiveCodeBench等で評価。matched KV budgetで複数のsignal-based selectorと同等以上の品質を示し、vLLM servingでは比較対象の強いevictorより **32〜43%高いthroughput**を報告する。公式repositoryによれば主要実験は8×H200 141GBで実施されている。

## 既存研究との差

新しい重要度scoreを設計するのではなく、「promptさえ保護すればreasoning tokenの精密rankingは本当に必要か」をnull hypothesisとして検証する点が特徴である。複雑なselectorのaccuracy gainとselector overheadを分離して評価している。

## 限界

- promptを完全保護できることが前提で、prompt自体が非常に長い場合の容量問題は残る。
- reasoning traceの冗長性が小さいtaskやmodelで同じ頑健性が得られるとは限らない。
- ランダム選択のため個々のrunでは保持tokenが変わり得る。

## 一般的な実装含意

KV evictionではselectorの精度だけでなく、score計算とcompactionを含むend-to-end overheadを比較すべきである。特にreasoning workloadでは、複雑なrankingよりprompt保護と安価なevictionを優先する方がthroughput上有利な場合がある。
