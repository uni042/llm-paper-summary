# Random Attention: Rethinking KV Cache Eviction for Efficient Reasoning

> **Random 注意機構は「重要トークンを賢く選ぶ」KV圧縮を疑い、質問文だけは絶対に守ったうえで、モデル自身が生成した推論過程履歴はヘッドごとにランダムに残す。それでも多くの推論過程 タスクで強い選択器と同等の正答率になり、選択器計算が無いぶんサービングは速い。**

## 概要

推論過程 モデルは、最終回答を出す前に何千〜何万トークンもの思考過程を生成することがある。autoregressive デコードでは、生成した各トークンのキー/値をKV キャッシュへ追加するため、推論過程が長くなるほどGPU メモリ使用量も直線的に増える。

そこでKV キャッシュを一定予算へ抑える**KV削除（KV 追い出し）**が使われる。

従来法の多くは、cached トークンごとに

- 過去にどれだけ注意機構されたか
- 最近のクエリからどれだけ注目されたか
- キーが他トークンと似ていないか
- 値のrangeが大きいか
- キー/クエリ geometryから将来重要そうか

などの**重要度スコア**を計算し、高スコア トークンだけを残す。

直感的には、賢いスコアほど品質を保てそうに見える。

Random 注意機構はこの前提そのものを検証する。

結論はかなり極端で、推論過程 ワークロードでは

> **入力文を守りさえすれば、生成 推論過程 トークンをどれにするかという選択 手掛かりは驚くほど重要でない**

というものだった。

そこで提案法は、

1. システム 入力文、chat template、user questionなどプリフィル時の入力トークンは絶対に追い出すしない。
2. モデル自身が生成した推論過程 トークンには無作為 スコアを振る。
3. 各KV ヘッドが独立にTop-Kを残す。
4. 最近生成した短いバッファは次回追い出しまでそのまま保持する。

だけである。

## まず「KV eviction 回」とは何か

KV キャッシュを常に1 トークンずつ削除すると、毎デコード ステップで詰め直しが発生して遅い。

そこで論文の共通評価モデルでは、各KV ヘッドについて

- 長期保持予算: `K`
- 最近の バッファ: `r`

を持つ。

キャッシュには`K + r`程度の履歴を保持し、デコードで最近の バッファが埋まるたびに**追い出し 回**を実行する。

このとき最近の バッファより古い候補 トークンへスコアを付け、K個だけ残す。捨てたKVは後から復元しない。

従来法はこのスコア関数だけが違う。

Random 注意機構は、そのスコアを単なる一様乱数にする。

## 手法のあらまし

### 1. 入力文は無条件に保持する

ここでいう入力文はuser questionだけではない。

プリフィルで入力された

- システム 入力文
- instruction
- chat template
- retrieved 文脈
- user question

などを含むinitial 入力全体を保護する。

この領域のトークンには実質的に無限大スコアを与え、予算競争から外す。

なぜここだけ特別扱いするのか。

モデルが生成した推論過程 トレースは後続トークンの中で内容を言い換えたり再利用したりすることが多い。一方、userが最初に一度だけ与えた条件や数字は、失われてもモデル自身が正確に再生成する保証がない。

つまり入力文は**外部から一度だけ与えられた不可逆な情報**で、推論過程 トレースよりfragileである。

### 2. 生成 推論過程はuniform 無作為で残す

入力文以外のキャッシュ済み positionには、各追い出し時に一様乱数を与える。

その中からK個をTop-Kとして残す。

数式上は

`入力文 トークン → +∞`

`生成 トークン → Uniform(0,1)`

だけである。

注意機構 スコアも値 statisticも較正 データも使わない。

### 3. 「全ヘッドで同じトークンを無作為に選ぶ」わけではない

重要なのは、無作為 samplingを**KV ヘッドごとに独立**に行う点である。

たとえば推論過程 トークン 5000がヘッド 0では捨てられても、ヘッド 3やヘッド 7では残るかもしれない。

このためモデル全体として見ると、1つの推論過程 状態がすべてのヘッドから同時に消える確率は下がる。

論文はこれを推論過程 トレースの**ヘッド間冗長性**として説明する。

### 4. recent bufferは即座に削除しない

最新トークンは次のトークンを作るとき重要になりやすい。

また毎トークンで無作為 選択すると詰め直し オーバーヘッドも増える。

そのためK個の長期保持領域とは別に短い最近の バッファを持ち、バッファが満杯になるまでは新トークンをそのまま追加する。

満杯になった時だけ古い候補を再選択する。

## なぜ無作為でも壊れにくいのか

この論文の価値は「無作為 policyを提案した」だけでなく、なぜ推論過程で成立するのかをmechanism studyで調べた点にある。

### 1. 入力文が最もfragile

既存選択器を入力文保護あり/なしで比較すると、品質差の大きな部分が「どの高度なスコアを使ったか」ではなく、**入力文をどれだけ残せたか**で説明できる。

質問に一度しか書かれていない数字や条件を消すと、その後の推論過程 トレースに同じ情報が存在しなければ取り戻せない。

そのため無作為 追い出しを入力文まで含めて行うと弱い。

Random 注意機構の主張は「何でも無作為に消してよい」ではなく、**不可逆な入力はpinし、その後の生成 トレースにだけ無作為 追い出しを使う**ことである。

### 2. 推論過程文章は自分で情報を再記述する

長い数理推論過程では、モデルが途中結果を何度も言い換える。

例えば

> x=7 therefore …

と一度出した後、数ステップ先で

> 使う the 値 x=7 …

と再び書くことがある。

古いトークンが追い出すされても、必要情報が新しいトークンへ再符号化されていれば計算を続けられる。

論文はこれを推論過程 トレースの**textual redundancy**として扱う。

### 3. 注意機構 ヘッド間にも複製がある

同じsequence positionのKVは複数ヘッドに存在する。

ヘッドごとに無作為 subsetを独立に選ぶため、全ヘッドでまったく同じhistory fragmentを消すわけではない。

この分散された残り方も冗長性になる。

### 4. だから「一度だけ現れる事実」には弱い

逆に、

- 入力文外で一度だけ登場したfact
- 後で再記述されないintermediate 結果
- 特定のヘッドだけが保持している特殊な依存

では無作為 追い出しは失敗しやすい。

したがって、論文結果を「注意機構 スコアはどんなタスクでも不要」と一般化するのは危険である。

中心claimは**長い推論過程 トレースに限定した実証**である。

## 既存選択器はなぜ遅いのか

KV 追い出しはメモリを減らして注意機構を短くできるため、本来ならサービング スループットを上げられる。

しかし選択 手掛かりを計算するために

- 注意機構 statistics集計
- キー 類似性
- 値 statistic
- 較正した geometric スコア

などを毎追い出し 回で走らせると、その計算自体がデコード critical pathへ入る。

推論過程が32K トークン続けば追い出し 回も繰り返されるので、1回あたり小さなスコア オーバーヘッドでも累積する。

Random 注意機構は`rand + topk + 詰め直し`だけなので、このスコア passを省ける。

つまり品質が同じ程度なら、**賢い選択器より単純な選択器の方がエンドツーエンド スループットで有利**になる。

## 評価

### modelとtask

4 モデルを評価する。

- Qwen3-4B
- Qwen3-14B
- Qwen3-32B
- Phi-4-推論過程 14B

推論過程 タスクは数学・科学・codingを含み、主要表では

- MATH500
- GPQA-Diamond
- AIME 2025/2026
- HMMT
- LiveCodeBench-v6

などを使う。

最大 generationは32K トークン。タスクごとに典型トレースの約4×圧縮、LiveCodeBenchは約3×圧縮になるKV 予算を設定する。

### 正答率では手掛かり-based methodと概ね同等

主 比較ではSnapKV、R-KV、VaSE、TriAttentionとmatched 予算で比較する。

60個の比較対象 比較 cellのうち、Random 注意機構が統計的に有意に上回ったものが31、明確に下回ったものは1つだった。

例えばQwen3-4Bでは

- MATH500: Random **0.874**、TriAttention 0.864
- GPQA-D: Random **0.530**、TriAttention 0.533
- LiveCodeBench: Random **0.744**、TriAttention 0.755

のように、常にnominal 最良ではないが強い選択器と近い。

Qwen3-32BでもMATH500はRandom 0.891、TriAttention 0.887、GPQA-Dは両方0.683。一方LiveCodeBenchではRandom 0.806に対しTriAttention 0.834で、無作為が一律最良というわけではない。

### vLLM servingでは強い選択器より32〜43%高スループット

paper headlineでは、vLLM deploymentにおいて最も強い比較選択器より**32〜43%高いスループット**を報告する。

これはRandom 注意機構の注意機構計算そのものが特別高速だからではない。

同じKV 予算なら、最終的に残るキャッシュ サイズは他手法と近い。差の主因は**追い出し時の重要度 採点を走らせないこと**である。

したがってこの結果は、KV 圧縮を評価するとき「品質 at matched キャッシュ サイズ」だけでなく、**selector自身の実行時 コストまで含めるべき**ことを示す。

## 結果の読み方

### 「無作為がFull Attentionと同じ品質」ではない

Full 注意機構より精度が落ちる条件は普通にある。

Random 注意機構の主張は

> 同じ厳しいKV 予算を与えたとき、複雑な選択 手掛かりを使っても無作為を一貫して上回れない

というもの。

KV 追い出しそのものはlossyである。

### 「selection 手掛かりは永久に不要」でもない

推論過程 トレースの冗長性が高いワークロードで成立した結果である。

retrieval、exact copy、長文脈 fact recallなど、トークンを一度失うと代替情報がないタスクでは別の選択器が必要になる可能性が高い。

### 新しいnull baselineとして重要

今後「新しいKV 重要度 スコアで品質が改善した」と主張する研究は、入力文を保護しないnaive 無作為ではなく、**入力文-protected ヘッドごと 無作為**を比較対象にする必要がある。

そうでなければ、手掛かりの価値ではなく入力文 保持の差を測っているだけかもしれない。

## 既存研究との差

H2O、SnapKV、R-KV、VaSE、TriAttentionはいずれも「トークン 重要度を推定する手掛かり」を設計する。

Random 注意機構は新しい重要度 指標を設計しない。

むしろ、

> その指標は本当に必要なのか

を問うnegative/diagnostic研究である。

StreamingLLMのようなrecency方式とも違い、最近の contiguous windowだけに偏らず、生成 トレース全体からヘッドごとに散らして残す。そのため古い推論過程 状態にも一定確率で参照 pathを残せる。

## 限界と適用境界

- **推論過程 ワークロード中心。** retrieval-heavy タスクへそのまま一般化できない。
- **入力文を完全保護するメモリが必要。** 入力文自体が100K トークン級なら入力文だけでKV 予算を圧迫する。
- **lossy。** Full 注意機構と同一出力を保証しない。
- **randomnessがある。** 同じ入力でも保持KV subsetが実行するごとに変わり得る。
- **rare unique factに弱い。** 生成 トレース内で一度だけ現れ、後で再記述されない情報は落ちやすい。
- **ヘッドごと independenceが前提。** 複数ヘッドの冗長性を利用しており、アーキテクチャによって効果が変わる可能性がある。
- **選択器 オーバーヘッドの優位は実行時実装依存。** 採点 カーネルが高度にfuseされた将来実行時ではスループット差が縮む可能性がある。

## 実装上の含意

推論過程 モデル向けKV 追い出しを作る場合、最初に複雑なスコアを実装するより、

1. プリフィル KVをpinする。
2. 短い recency バッファを確保する。
3. 生成 トレースをヘッドごと 無作為 サンプルする。
4. matched メモリで精度とエンドツーエンド サービング スループットを測る。

という比較対象から始める価値がある。

新しいselectorがこの比較対象より精度を1〜2 点上げても、スコア計算でスループットを30%落とすならシステムとしては得でない場合がある。

この論文の最も大きな実務的示唆は、**KV selectorは「何を残したか」だけでなく「残すものを決めるのに何ms使ったか」まで評価すべき**という点である。

## 読み方の要点

この手法の核心は、推論過程の全履歴を同じ基準で守るのではなく、外部から一度だけ与えられた入力文と、モデルが後から作った履歴を分けて扱う点にある。入力文を残せば、生成履歴の一部を無作為に落としても、別の位置や別のヘッドに残った情報から計算を続けられる場合が多い。反対に、入力文まで削ると、失われた数値や条件を後の履歴から復元できず、同じ容量でも正答率が大きく下がり得る。

実装では、各ヘッドの保持枠と直近バッファを分け、バッファが一杯になった時だけ古い履歴を詰め直す。これにより毎ステップの選別計算を避け、生成処理の主要経路に追加する処理を小さくする。評価値は完全な注意機構との同一性ではなく、同一のKV容量で強い選択器と比べた正答率と処理速度として読むべきである。検索や一度しか現れない固有情報を重視する用途、入力文そのものが巨大な用途では、別の保持規則やより大きな容量が必要になる。
