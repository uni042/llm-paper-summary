# Random Attention: Rethinking KV Cache Eviction for Efficient Reasoning

> **Random Attentionは「重要tokenを賢く選ぶ」KV圧縮を疑い、質問文だけは絶対に守ったうえで、model自身が生成したreasoning履歴はheadごとにランダムに残す。それでも多くのreasoning taskで強いselectorと同等の正答率になり、selector計算が無いぶんservingは速い。**

## 概要

reasoning modelは、最終回答を出す前に何千〜何万tokenもの思考過程を生成することがある。autoregressive decodeでは、生成した各tokenのkey/valueをKV cacheへ追加するため、reasoningが長くなるほどGPU memory使用量も直線的に増える。

そこでKV cacheを一定budgetへ抑える**KV削除（KV eviction）**が使われる。

従来法の多くは、cached tokenごとに

- 過去にどれだけattentionされたか
- 最近のqueryからどれだけ注目されたか
- keyが他tokenと似ていないか
- valueのrangeが大きいか
- key/query geometryから将来重要そうか

などの**重要度score**を計算し、高score tokenだけを残す。

直感的には、賢いscoreほどqualityを保てそうに見える。

Random Attentionはこの前提そのものを検証する。

結論はかなり極端で、reasoning workloadでは

> **promptを守りさえすれば、generated reasoning tokenをどれにするかというselection signalは驚くほど重要でない**

というものだった。

そこで提案法は、

1. system prompt、chat template、user questionなどprefill時の入力tokenは絶対にevictしない。
2. model自身が生成したreasoning tokenにはrandom scoreを振る。
3. 各KV headが独立にTop-Kを残す。
4. 最近生成した短いbufferは次回evictionまでそのまま保持する。

だけである。

## まず「KV eviction round」とは何か

KV cacheを常に1 tokenずつ削除すると、毎decode stepでcompactionが発生して遅い。

そこで論文の共通評価modelでは、各KV headについて

- 長期保持budget: `K`
- recent buffer: `r`

を持つ。

cacheには`K + r`程度の履歴を保持し、decodeでrecent bufferが埋まるたびに**eviction round**を実行する。

このときrecent bufferより古いcandidate tokenへscoreを付け、K個だけ残す。捨てたKVは後から復元しない。

従来法はこのscore関数だけが違う。

Random Attentionは、そのscoreを単なる一様乱数にする。

## 手法のあらまし

### 1. promptは無条件に保持する

ここでいうpromptはuser questionだけではない。

prefillで入力された

- system prompt
- instruction
- chat template
- retrieved context
- user question

などを含むinitial input全体を保護する。

この領域のtokenには実質的に無限大scoreを与え、budget競争から外す。

なぜここだけ特別扱いするのか。

modelが生成したreasoning traceは後続tokenの中で内容を言い換えたり再利用したりすることが多い。一方、userが最初に一度だけ与えた条件や数字は、失われてもmodel自身が正確に再生成する保証がない。

つまりpromptは**外部から一度だけ与えられた不可逆な情報**で、reasoning traceよりfragileである。

### 2. generated reasoningはuniform randomで残す

prompt以外のcached positionには、各eviction時に一様乱数を与える。

その中からK個をTop-Kとして残す。

数式上は

`prompt token → +∞`

`generated token → Uniform(0,1)`

だけである。

attention scoreもvalue statisticもcalibration dataも使わない。

### 3. 「全headで同じtokenをrandomに選ぶ」わけではない

重要なのは、random samplingを**KV headごとに独立**に行う点である。

たとえばreasoning token 5000がhead 0では捨てられても、head 3やhead 7では残るかもしれない。

このためmodel全体として見ると、1つのreasoning stateがすべてのheadから同時に消える確率は下がる。

論文はこれをreasoning traceの**head間冗長性**として説明する。

### 4. recent bufferは即座に削除しない

最新tokenは次のtokenを作るとき重要になりやすい。

また毎tokenでrandom selectionするとcompaction overheadも増える。

そのためK個の長期保持領域とは別に短いrecent bufferを持ち、bufferが満杯になるまでは新tokenをそのまま追加する。

満杯になった時だけ古いcandidateを再選択する。

## なぜrandomでも壊れにくいのか

この論文の価値は「random policyを提案した」だけでなく、なぜreasoningで成立するのかをmechanism studyで調べた点にある。

### 1. promptが最もfragile

既存selectorをprompt保護あり/なしで比較すると、quality差の大きな部分が「どの高度なscoreを使ったか」ではなく、**promptをどれだけ残せたか**で説明できる。

質問に一度しか書かれていない数字や条件を消すと、その後のreasoning traceに同じ情報が存在しなければ取り戻せない。

そのためrandom evictionをpromptまで含めて行うと弱い。

Random Attentionの主張は「何でもrandomに消してよい」ではなく、**不可逆なinputはpinし、その後のgenerated traceにだけrandom evictionを使う**ことである。

### 2. reasoning文章は自分で情報を再記述する

長い数理reasoningでは、modelが途中結果を何度も言い換える。

例えば

> x=7 therefore …

と一度出した後、数step先で

> using the value x=7 …

と再び書くことがある。

古いtokenがevictされても、必要情報が新しいtokenへ再符号化されていれば計算を続けられる。

論文はこれをreasoning traceの**textual redundancy**として扱う。

### 3. attention head間にも複製がある

同じsequence positionのKVは複数headに存在する。

headごとにrandom subsetを独立に選ぶため、全headでまったく同じhistory fragmentを消すわけではない。

この分散された残り方も冗長性になる。

### 4. だから「一度だけ現れる事実」には弱い

逆に、

- prompt外で一度だけ登場したfact
- 後で再記述されないintermediate result
- 特定のheadだけが保持している特殊なdependency

ではrandom evictionは失敗しやすい。

したがって、論文結果を「attention scoreはどんなtaskでも不要」と一般化するのは危険である。

中心claimは**長いreasoning traceに限定した実証**である。

## 既存selectorはなぜ遅いのか

KV evictionはmemoryを減らしてattentionを短くできるため、本来ならserving throughputを上げられる。

しかしselection signalを計算するために

- attention statistics集計
- key similarity
- value statistic
- calibrated geometric score

などを毎eviction roundで走らせると、その計算自体がdecode critical pathへ入る。

reasoningが32K token続けばeviction roundも繰り返されるので、1回あたり小さなscore overheadでも累積する。

Random Attentionは`rand + topk + compaction`だけなので、このscore passを省ける。

つまりqualityが同じ程度なら、**賢いselectorより単純なselectorの方がend-to-end throughputで有利**になる。

## 評価

### modelとtask

4 modelsを評価する。

- Qwen3-4B
- Qwen3-14B
- Qwen3-32B
- Phi-4-reasoning 14B

reasoning taskは数学・科学・codingを含み、主要表では

- MATH500
- GPQA-Diamond
- AIME 2025/2026
- HMMT
- LiveCodeBench-v6

などを使う。

maximum generationは32K token。taskごとに典型traceの約4×圧縮、LiveCodeBenchは約3×圧縮になるKV budgetを設定する。

### accuracyではsignal-based methodと概ね同等

main comparisonではSnapKV、R-KV、VaSE、TriAttentionとmatched budgetで比較する。

60個のbaseline comparison cellのうち、Random Attentionが統計的に有意に上回ったものが31、明確に下回ったものは1つだった。

例えばQwen3-4Bでは

- MATH500: Random **0.874**、TriAttention 0.864
- GPQA-D: Random **0.530**、TriAttention 0.533
- LiveCodeBench: Random **0.744**、TriAttention 0.755

のように、常にnominal bestではないが強いselectorと近い。

Qwen3-32BでもMATH500はRandom 0.891、TriAttention 0.887、GPQA-Dは両方0.683。一方LiveCodeBenchではRandom 0.806に対しTriAttention 0.834で、randomが一律bestというわけではない。

### vLLM servingでは強いselectorより32〜43%高throughput

paper headlineでは、vLLM deploymentにおいて最も強い比較selectorより**32〜43%高いthroughput**を報告する。

これはRandom Attentionのattention計算そのものが特別高速だからではない。

同じKV budgetなら、最終的に残るcache sizeは他methodと近い。差の主因は**eviction時のimportance scoringを走らせないこと**である。

したがってこの結果は、KV compressionを評価するとき「quality at matched cache size」だけでなく、**selector自身のruntime costまで含めるべき**ことを示す。

## 結果の読み方

### 「randomがFull Attentionと同じquality」ではない

Full Attentionよりaccuracyが落ちる条件は普通にある。

Random Attentionの主張は

> 同じ厳しいKV budgetを与えたとき、複雑なselection signalを使ってもrandomを一貫して上回れない

というもの。

KV evictionそのものはlossyである。

### 「selection signalは永久に不要」でもない

reasoning traceの冗長性が高いworkloadで成立した結果である。

retrieval、exact copy、long-context fact recallなど、tokenを一度失うと代替情報がないtaskでは別のselectorが必要になる可能性が高い。

### 新しいnull baselineとして重要

今後「新しいKV importance scoreでqualityが改善した」と主張する研究は、promptを保護しないnaive randomではなく、**prompt-protected per-head random**をbaselineにする必要がある。

そうでなければ、signalの価値ではなくprompt retentionの差を測っているだけかもしれない。

## 既存研究との差

H2O、SnapKV、R-KV、VaSE、TriAttentionはいずれも「token importanceを推定するsignal」を設計する。

Random Attentionは新しいimportance metricを設計しない。

むしろ、

> そのmetricは本当に必要なのか

を問うnegative/diagnostic研究である。

StreamingLLMのようなrecency方式とも違い、recent contiguous windowだけに偏らず、generated trace全体からheadごとに散らして残す。そのため古いreasoning stateにも一定確率でaccess pathを残せる。

## 限界と適用境界

- **reasoning workload中心。** retrieval-heavy taskへそのまま一般化できない。
- **promptを完全保護するmemoryが必要。** prompt自体が100K token級ならpromptだけでKV budgetを圧迫する。
- **lossy。** Full Attentionと同一出力を保証しない。
- **randomnessがある。** 同じ入力でも保持KV subsetがrunごとに変わり得る。
- **rare unique factに弱い。** generated trace内で一度だけ現れ、後で再記述されない情報は落ちやすい。
- **per-head independenceが前提。** 複数headの冗長性を利用しており、architectureによって効果が変わる可能性がある。
- **selector overheadの優位はruntime実装依存。** scoring kernelが高度にfuseされた将来runtimeではthroughput差が縮む可能性がある。

## 実装上の含意

reasoning model向けKV evictionを作る場合、最初に複雑なscoreを実装するより、

1. prefill KVをpinする。
2. short recency bufferを確保する。
3. generated traceをper-head random sampleする。
4. matched memoryでaccuracyとend-to-end serving throughputを測る。

というbaselineから始める価値がある。

新しいselectorがこのbaselineよりaccuracyを1〜2 point上げても、score計算でthroughputを30%落とすならsystemとしては得でない場合がある。

この論文の最も大きな実務的示唆は、**KV selectorは「何を残したか」だけでなく「残すものを決めるのに何ms使ったか」まで評価すべき**という点である。
