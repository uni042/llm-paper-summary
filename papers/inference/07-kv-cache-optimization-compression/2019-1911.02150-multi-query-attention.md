# Fast Transformer Decoding: One Write-Head is All You Need

> 複数クエリ注意（Multi-Query Attention; MQA）は、通常の複数ヘッド注意（Multi-Head Attention; MHA）が各ヘッドごとに持つキー（Key; K）とバリュー（Value; V）を1組だけに共有し、クエリ（Query; Q）は複数ヘッドのまま残す。増分デコードで毎トークン読み出すKVキャッシュ量をヘッド数分削減し、算術量よりメモリ帯域が律速になる領域を直接狙う。WMT英独翻訳の単一TPUv2評価ではデコーダ部分が46 µs/tokenから3.8 µs/tokenへ約12.1倍短縮し、dev BLEUは26.7から26.5、Billion Word言語モデルのperplexityは29.9から30.2という小さな品質差に留まった。

## 概要

Transformer訓練では系列全位置を並列処理できるため、注意は大きな行列積になり演算器を使いやすい。一方、自己回帰デコードでは新しい1トークンだけを処理し、過去全トークンのK/Vをキャッシュから読み出す。

MHAはh個のQヘッドごとに別のK/Vヘッドを保存するため、1ステップのKV読み出し量が系列長とヘッド数に比例する。小バッチの増分デコードでは、QK内積のFLOPsよりも「過去KVをHBMから運ぶ」時間が支配しやすい。

MQAは複数のQヘッドを維持しながら、検索対象となるK/V表現だけを全Qヘッドで共有する。注意分布自体はQが違うのでヘッドごとに異なり得る。単純にヘッド数を1へ減らす方式より、複数視点のQを残したままKV帯域を削減する設計である。

## 問題設定

MHAでは各層・各時刻についてh組のK/Vをキャッシュする。新トークン生成のたびにそれらを読み直すため、系列長が伸びるほどメモリ帯域需要が大きくなる。

K/V次元やヘッド数自体を減らす代替はキャッシュを小さくできるが、Q側の表現力も同時に削る。論文は総パラメータ数を揃えた比較で、MQAの方が速度と品質のPareto前線に近いことを示す。

## 手法

### 1. Qは複数ヘッド、K/Vは単一ヘッドにする

隠れ状態XからQ投影は通常どおりh個のヘッドを生成する。一方KとVはヘッド次元を持たない1組だけを生成する。

各Qヘッドは同じK/Vに対し別のQベクトルを使うため、異なる注意重みを学習できる。共有するのは過去系列の表現であり、クエリ側の読み方ではない。

### 2. KVキャッシュと読み出し帯域を約h分の1へ近づける

8ヘッドのMHAなら、K/Vを1ヘッドに共有することでキャッシュの主要部分を概ね8分の1へ減らせる。増分デコード時にHBMから読む量も同様に減る。

ただしQヘッド数はhのままなので、注意スコア・出力合成の算術量すべてが8分の1になるわけではない。高速化の中心はFLOPs削減ではなく帯域削減である。

### 3. 品質比較では減った注意パラメータをFFNへ戻す

MQAはK/V投影パラメータが小さくなるため、そのまま比較すると総パラメータ数も減る。WMT実験ではフィードフォワードネットワーク（Feed-Forward Network; FFN）を広げて総パラメータ数を整合させる。

これにより「小さいモデルだから速い」という要因を避け、K/V共有の速度・品質交換条件を測る。

## 評価

### 評価条件

| 項目 | 条件 |
|---|---|
| 翻訳 | WMT 2014 English→German |
| 構成 | 6層encoder-decoder、d_model=1024、8 heads |
| MHA | d_k=d_v=128、FFN幅4096 |
| MQA | 8 Q heads＋共有K/V、FFNを拡大してパラメータ整合 |
| 速度測定 | 単一TPUv2（8 cores） |
| デコード | greedy、beam=4 |
| 追加品質 | Billion Word Language Modeling Benchmark |

### 品質と速度

| 指標 | MHA | MQA | 差 |
|---|---:|---:|---:|
| WMT dev BLEU | 26.7 | 26.5 | -0.2 |
| WMT test greedy BLEU | 27.7 | 27.5 | -0.2 |
| WMT test beam-4 BLEU | 28.4 | 28.5 | +0.1 |
| Billion Word dev perplexity | 29.9 | 30.2 | +0.3 |
| 訓練時間 | 13.2 µs/token | 13.0 µs/token | ほぼ同じ |
| Encoder inference | 1.7 µs/token | 1.5 µs/token | 小差 |
| Decoder greedy | 46 µs/token | 3.8 µs/token | 約12.1倍高速 |
| Decoder beam-4 | 203 µs/token | 32 µs/token | 約6.3倍高速 |

訓練とencoderでは差が小さく、増分decoderだけで差が大きいことが機構と一致する。訓練は大きな行列積で演算律速になりやすいが、1トークンずつのデコードはKV読み出し帯域が支配するためである。

## 既存研究との差

単一ヘッド注意へ戻す方式はQ/K/Vすべてのヘッド多様性を失う。MQAはQ側だけ複数ヘッドを残し、K/V共有へ限定する。

後のグループ化クエリ注意（Grouped-Query Attention; GQA）は、MHAとMQAの中間として複数Qヘッドを複数KVグループへ割り当てる。MQAはKVヘッド数1という最も強い共有端点であり、容量・帯域削減は大きい一方、モデルによって品質差が出やすい。

## 限界・実装状況

- 主評価は2019年の翻訳・言語モデルとTPUv2で、現在の巨大LLMへ速度倍率を直接移植できない。
- K/V表現を全Qヘッドで共有するためMHAより自由度が低く、Billion WordではPPLが29.9→30.2へ悪化する。
- 最大級の速度差は増分デコードで現れ、訓練時間は13.2→13.0 µs/tokenとほぼ変わらない。
- 大規模テンソル並列では単一KVヘッドの複製や通信が必要になり、別の配置交換条件が生じる。
- 現代モデルではGQAが品質とKV容量の中間点として採用されることが多い。

## 一般的な実装上の含意

デコード最適化ではFLOPsだけでなく、1トークン生成ごとに何バイトのKVを読むかを測る必要がある。MQAは算術構造を大きく変えずデータ移動を減らして大きな速度差を出した代表例である。

一方、KVヘッド数は少ないほど常に良いわけではない。モデル品質、テンソル並列配置、KV容量、デコード帯域を同時に見てMHA/GQA/MQAを選ぶ必要がある。
