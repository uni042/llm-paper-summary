# Cache Me If You Must: Adaptive Key-Value Quantization for Large Language Models — AQUA-KV

## 概要

長文脈の大規模言語モデル（LLM）では、生成済みトークンの注意機構に使う鍵・値（KV）を各層に保存する。再計算を省ける反面、キャッシュ容量は系列長に比例して増える。原著の例では、131,072トークンを保持するLlama 3.2 3Bの16ビットKVは約15 GiB、Llama 3.1 70Bでは約42.9 GB（論文の導入部における十進表記）を占める。量子化を2ビットまで進めると容量は減るが、通常の量子化は鍵・値の分布をそれぞれ独立に近似するため、誤差が蓄積して長文脈の回答品質が落ちやすい。

AQUA-KVは「キャッシュに含まれる情報の全量を個別に符号化する必要はない」という観察を使う。前のTransformer層の鍵・値から次の層の鍵・値を予測できれば、保存すべきものは予測値との差分である。具体的には、前層の**復元済み鍵**から現層の鍵を予測し、次に前層の**復元済み値と現層の復元済み鍵**から現層の値を予測する。残差を既存の量子化器で符号化し、復号時に予測値を足し戻す。予測器は小規模な線形回帰で、基盤モデルの重みは変更しない。

原著表2のLlama 3.1 70B、131Kトークン、バッチ1では、無圧縮KVが40 GiB、AQUA-KV（実効2.09ビット）は5.7 GiBとなる。長文脈評価LongBenchの平均は52.92から52.79への変化である。対照となるHIGGS単独2.02ビットでは容量5.1 GiBとやや小さいが、平均52.18で、予測器による品質上の利得が見える。**本方式は圧縮と品質の交換条件を改善する研究であって、生成を高速化する方式ではない。** A100上の単一系列生成では、同じ2ビットHIGGSを使う場合に予測器の追加分だけ約3%遅くなる。論文はこの負の結果も明示している。

## 問題設定と着想

鍵・値の量子化では、低ビット表現へ写した値と元の値の差が注意得点と重み付き和に伝わる。鍵の誤差はどの過去トークンへ注意を向けるかを変え、値の誤差は取り出す内容そのものを変える。従来のKIVIやKVQuantは量子化単位や外れ値の扱いを工夫するが、層をまたいで再利用できる情報の予測を基本設計には置かない。MiniCacheやKVSharerの層共有は容量削減に踏み込むものの、共有先を直接置き換えるため残差情報が失われやすい。

著者らはLlama 3.2 3Bの各層のKVを線形回帰で推定し、説明分散率を測った。直前の層の鍵だけで次層の鍵の大きな割合を説明でき、値についても前層の値が半分以上の分散を説明する。一方、前のトークンから同じ層のKVを予測する関係は弱く、さらに離れた複数層を入力へ加えても直前層だけの場合から改善が小さい。そこで時間方向の複雑な予測ではなく、**同じトークンの層間依存**に絞る。層をまたぐ予測はTransformerの残差接続に由来する相関を利用し、KV射影が近接する隠れ状態から生成される点に根拠を持つ。

予測精度が高くても、予測値だけを保存する層共有では元の情報を完全に復元できない。AQUA-KVは予測できた部分を再構成し、残りの残差だけを量子化する。残差の分散が小さくなるほど同じビット数での再構成誤差を減らせるが、線形予測が万能なわけではない。どの層にも予測器の係数を持つ追加費用があり、復号は前層の再構成に依存するため並列性が制限される。

## 手法

### 層間依存を測る線形探索

較正用データから、ある層の鍵・値を目的変数、前層の鍵・値や近傍トークンを説明変数とする線形回帰を学習する。指標は単なる平均二乗誤差ではなく、層や鍵・値でスケールが異なることを考慮した**説明分散率**である。説明分散率90%なら、残り10%の変動を量子化器へ渡せばよいという直感が得られる。ただし「2ビット節約できる」といった説明は厳密なビット保証ではない。原著は1・2ビット量子化器の説明分散率の目安と比較しているが、実際の精度は後続のタスク評価で検証する。

この探索では前の1、2、3層、前の1、2、3トークン、同層の鍵と値の相互予測を比較する。未来の層や未来トークンを使えば符号化はできても自己回帰生成時に復号できないため候補から除く。前層の鍵が現層の鍵をよく予測し、値については前層の値と現層の鍵の組合せが有効という結果から、後述の復号順を決める。現層の鍵と値を互いに同時予測する循環依存は作らない。

### 鍵の予測と残差符号化

層 `i` の真の鍵を `K_i`、前層の**量子化後に復元した**鍵を `K̂_{i-1}` とする。線形予測器 `f^K_i` は `K̂_{i-1}` を入力として `K_i` を近似する。保存するのは `Q(K_i − f^K_i(K̂_{i-1}))` であり、`Q` は量子化、`Q^{-1}` は逆量子化である。復号では `K̂_i = f^K_i(K̂_{i-1}) + Q^{-1}(残差符号)` とする。

重要なのは、較正中も**真の前層鍵をそのまま入力しない**点である。実際の推論では前層の鍵も既に量子化誤差を含むため、真値で学習すると予測器の入力分布がずれて後続層で誤差が増える。原著のアルゴリズム1は第1層から最終層へ進み、毎層の復元値を次の学習入力へ渡す。第1層には前層がないため、通常の量子化だけを適用する。この層別逐次較正はモデル全体の勾配更新を要しない。

### 値の予測と復号順序

値については、前層の復元済み値 `V̂_{i-1}` だけでなく、**今復元した鍵 `K̂_i`** も連結して入力する。線形予測器 `f^V_i([V̂_{i-1}; K̂_i])` が現層の値を近似し、`Q(V_i − f^V_i(...))` を保存する。復号は「前層の鍵・値 → 現層の鍵 → 現層の値」の順になる。鍵を先に復元する理由は、値の予測に現層の鍵が必要だからである。逆方向に値から鍵も予測すると復号の循環依存を招くため、値の方が予測しにくいという測定結果に基づいてこの一方向を選んだ。

予測器を使う方式では、KVの容量だけでなく線形変換の重みも保持する。原著のLlama 3.2 3Bの比較では線形予測器の追加容量は162 MiB、多層パーセプトロンは540 MiB、低階数回帰は68 MiB、予測器重みをGPTQで4ビット化すると41 MiBである。多層パーセプトロンはLongBenchをわずかに改善するが、予測器容量と演算増加を正当化するほどではないとして線形回帰を標準にした。グループ化クエリ注意（GQA）ではKVヘッド数が少ないため、予測器の演算は基盤モデル本体より十分小さい。70B級では1トークン当たりの予測演算はモデル本体の少なくとも500分の1と見積もられているが、これだけで追加遅延がゼロになるわけではない。

### 量子化器、注意の吸い込み点、位置回転

AQUA-KVは残差を量子化する仕組みなので、丸めによる一様量子化のQuantoにも、アダマール回転と格子量子化を用いるHIGGSにも接続できる。原著ではHIGGSの群サイズ1024、Quantoの群サイズ64を主に試す。HIGGSは通常の鍵・値を直接量子化する場合にも精度が高く、AQUA-KVはそこへ層間予測を追加して残差の量子化誤差をさらに下げる。予測器の学習は使用する量子化器を前提に復元済み入力を作るが、量子化器非依存の学習も比較している。

先頭のトークンは意味内容とは無関係に強い注意を集める**注意の吸い込み点**になりやすい。この部分を粗く量子化すると、後続トークンの注意分布だけでなく予測器へ入る鍵・値の分布まで変わる。そこで実験では先頭4トークンを無圧縮で保持し、比較方式にも同じ条件を適用した。さらに直近128トークンまでの小さな非圧縮バッファを使い、バッファが満ちた段階で層順にまとめて圧縮する。1トークンごとに全層の残差を毎回符号化するより実装効率を確保できるが、バッファや例外トークンの容量は実効ビット数へ含める必要がある。

回転位置埋め込み（RoPE）の適用前後も比較している。単純な線形予測器は位置に依存する回転へ厳密には等変ではないため、**RoPE適用前の鍵**を予測・圧縮する方が精度が良い。Quantoの単純量子化はRoPE適用後がやや有利な場合もあるが、HIGGSは回転変換を内部で使うため両条件で近い。鍵・値の量子化単位は両方ともトークン単位とし、予測残差なら鍵をチャネル単位で量子化しなくても良好な結果を得たと報告する。

### 実行時の復号と統合範囲

推論では、過去系列の圧縮済みKVを各層の計算直前に復元する。前層から渡された復元済みKVを入力に、鍵の残差を戻し、続いて値の残差を戻す。新しく生成されたトークンのKVも同じ順に符号化して保存する。論文のアルゴリズム2〜4はこの層順の符号化・復号と通常のTransformer層の計算を接続する。圧縮済みキャッシュ全体を全層同時に展開する必要はなく、必要な層を順次復元できる。

ただし既存の注意カーネルにそのまま適用すれば必ず高速になるという主張ではない。予測器演算、残差の復号、層間依存のための同期が追加される。実際の圧縮カーネルやサービング実装との融合が重要で、著者らもvLLM等への統合を今後の課題としている。モデル並列化、オフロード、投機的復号、系列統合とは原理上併用できるが、各方式との組合せを実機サービング負荷で網羅的に測定したわけではない。

| Llama 3.1 70B・3ビット域PPL | 2.54 | 2.55（3.06ビット） | HIGGS単独2.57（3.02ビット） | 高ビット側では品質差が縮む。 |

原著表2の実効ビット数と容量は比較方式ごとに厳密には同じではない。AQUA-KVは予測器を保存するため、HIGGS単独と同じ2ビット符号を使っても実効容量が大きくなる。したがって「同一容量での完全な優越」とは書けない。Qwen 2.5 7BのHIGGSは3・4ビットでもLongBench平均が低い値（14.61、11.54）を示すため、単純な「ビット数が多ければ常に精度が上がる」という説明は原著表と一致しない。原因を原著が確定していない数値異常として扱い、ここから一般的な品質単調性を推測しない。

#### 構成要素除去と予測器の費用

| Llama 3.2 3B・表1の条件 | PPL（低いほど良い） | LongBench平均（高いほど良い） | 意味 |
|---|---:|---:|---|
| AQUA-KV標準（HIGGS、実効2.16ビット） | 7.03 | 44.26 | 基準。 |
| 鍵予測器を除去 | 7.50 | 42.92 | 鍵の層間予測が特に重要。 |
| 値予測器を除去 | 7.06 | 43.91 | 値の予測にも独立した寄与。 |
| 先頭4トークンの16ビット保持を除去 | 7.15 | 44.13 | 注意の吸い込み点を保護する効果。 |
| RoPE適用前圧縮を使わない | 7.05 | 44.13 | 単純線形予測器は回転前が有利。 |
| 量子化器非依存の予測器学習 | 7.13 | 44.26 | 汎用性を優先するとPPLがやや悪化。 |
| 予測器を多層パーセプトロンへ変更 | 7.03 | 44.61 | 162→540 MiBの容量増に対し品質利得は限定的。 |
| 予測器を4ビットGPTQで圧縮 | 7.03 | 44.19 | 162→41 MiBでほぼ同等の品質。 |

この比較から、鍵の予測器と値の予測器を単にまとめて「相関利用」と呼ぶのは不十分と分かる。鍵の再構成が先に正確でないと、現層の値の予測入力も悪くなる。鍵予測器を取り除いたときの悪化が大きいのは、後続の値予測へ誤差が波及する経路を持つためと解釈できる。ただし構成要素除去実験は小規模モデルの特定条件であり、全モデルで同じ寄与率を保証するものではない。

#### トークン削減との併用と実測生成速度

| 評価 | 比較方式 | AQUA-KV | 留意点 |
|---|---:|---:|---|
| H2Oで20%トークン保持・Llama 3.2 3B・LongBench | H2Oのみ38.82、H2O＋HIGGS 37.02 | H2O＋AQUA-KV 38.43 | 圧縮を追加してもH2O単独との差は0.39点。 |
| H2Oで20%トークン保持・Llama 3.1 8B・LongBench | H2Oのみ41.42、H2O＋HIGGS 40.53 | H2O＋AQUA-KV 40.88 | HIGGSより高いが、H2O単独より低い。 |
| H2O＋量子化のメモリ削減倍率 | H2O＋HIGGS 39.6倍 | H2O＋AQUA-KV 38.3倍 | 容量面は予測器のため僅かに不利。 |
| A100・8B単一系列生成 | HIGGS 24.02トークン/秒 | AQUA-KV 23.31トークン/秒 | 約2.96%低速。 |
| A100×2・70B単一系列生成 | HIGGS 5.91トークン/秒 | AQUA-KV 5.76トークン/秒 | 約2.54%低速。 |

トークン削減H2Oは重要トークンのみを残す方式で、AQUA-KVは残したトークンの値を低ビット化する方式なので原理的に直交する。ただしH2O自体の情報損失は残り、併用で元の無圧縮・全トークン保持品質まで回復するわけではない。生成速度についても、量子化によるメモリ節約とトークン毎秒の改善を同一視できない。著者は予測器の演算による約3%の減速を報告し、PyTorch実装が未最適化であることを明記している。今後のカーネル融合で改善する可能性はあるが、論文の測定値を超える高速化を実証済みとは扱わない。

## 既存研究との差

HIGGS単独は各KV値を直接低ビット化する。AQUA-KVはHIGGSを置き換えるのではなく、**線形予測で差分を小さくしてからHIGGSで残差を符号化**する。Quantoに接続しても改善するため、量子化器の種類に限定されない。KVSharerのように複数層のキャッシュを単純に共有すると、共有しなかった情報が失われやすいが、AQUA-KVは残差を残すため品質を維持しやすい。

Paluの低階数射影やGEARの低階数誤差補償とも異なる。AQUA-KVの予測器は**前層の復元済みKVと現層の鍵**という復号可能な依存関係を使う。量子化誤差が次層へ伝わる現実を較正時に模擬する点が重要で、真のKVから学習した予測器を推論時にそのまま使う方式ではない。トークン削減やオフロードと併用する余地はあるが、他方式と一体化した実機サービング評価は別途必要である。

## 限界と実装上の注意

第一に、予測器を持つぶん容量と演算が増える。2ビットHIGGS単独よりAQUA-KVの実効ビット数がやや高く、復号は層順に依存する。層間予測が効かないモデルや量子化器では、追加演算の割に品質改善が小さくなる可能性がある。原著の実機速度では実際に約3%の減速があるため、導入目的を「同一程度の容量での精度維持」に置くべきである。

第二に、較正はRedPajamaの224系列で線形予測器を学習し、32系列で設定を選ぶ。モデル規模に応じて1〜6時間程度の較正を要し、70Bの具体例では単一GPU・最大16GBのビデオメモリで約4時間とされる。これは推論開始前の準備費用であり、オンラインで要求ごとに行う処理ではない。モデルや量子化器の変更時には再較正が必要になる場合がある。

第三に、長文脈品質の主要指標は英語14課題の平均であり、他言語、極端な長さ、特定の指示追従能力まで保証しない。基盤モデルのPPLと指示調整モデルのLongBenchは異なるモデル変種で測るため、単一の生成設定で両方を直接比較した値ではない。モデル系列間の一部HIGGS結果に単調でない値もあり、結果表を「全モデル・全ビットで品質単調改善」と一般化しない。

第四に、公開された参照実装とA100上の逐次生成評価は、同時接続数、入出力長分布、ページ化KV管理、CPU退避、PCIe転送、分散サービングの総合費用を測ったものではない。論文自身がvLLM等への統合や予測器と基盤モデル演算の融合を今後の課題としている。推論基盤へ実装する場合は、復号順序を崩さないカーネル統合、先頭4トークンと直近128トークンの例外処理、予測器重みの配置、量子化後の層間依存による待ちを確認する必要がある。
