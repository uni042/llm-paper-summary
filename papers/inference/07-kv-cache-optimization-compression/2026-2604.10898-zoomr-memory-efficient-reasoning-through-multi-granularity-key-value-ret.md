# ZoomR: Memory Efficient Reasoning through Multi-Granularity Key Value Retrieval

> 推論の段落要約を索引にして、注意ヘッドの合意が取れた区間だけ原文をCPUから読み戻すKV管理で、全キャッシュ退避比でもメモリを4倍超削りながら同予算の圧縮方式を正解率で大きく上回った。

## 概要

推論モデルは、答えの前に長い思考を生成することで性能を得る。その代償として、生成済みトークンのキーとバリューを保持するKVキャッシュが出力長に比例して膨らむ。論文の例では、Llama-3.1-8Bで16Kトークンをバッチ8で生成すると、KVキャッシュだけで16ギガバイトを超える。各トークンの生成費用もキャッシュ長に比例して増えるため、長出力の推論ではメモリと計算の両方が苦しくなる。既存のKVキャッシュ圧縮の多くは、長い入力文脈を処理するプリフィル段階を対象に設計されており、デコード中に育っていく推論履歴の管理は手薄だった。静的な窓で古い履歴を捨てる方式は中間の重要な推論ステップを永久に失い、トークン単位の動的選択は毎ステップのスコア計算が高く、意味のまとまりを壊しやすい。

提案するZoomRは、推論履歴を2つの粒度で保持する。モデルを微調整して、推論の段落ごとに自分の推論の要約を生成させる。要約は粗い表現として常に手元に置き、原文の詳細はCPUメモリに置く。各生成ステップでは、現在のクエリと要約キーの平均との内積で区間の重要度を測り、全ての層とヘッドの投票を集計する。多くのヘッドが一致して選んだ区間（合意集合）については原文の詳細を読み戻して細かい粒度で注意し、候補には入ったが合意に届かなかった区間は要約のまま使う。これに、注意の受け皿となる冒頭のプロンプトと、直近の窓を常に加える。

**代表結果:** 数学と推論の3ベンチマーク（MATH500、GPQA Diamond、AIME2025）で、ZoomRは同予算のStreamingLLMとH2Oを全課題で上回り、平均正解率はLlama系で51.0パーセント、Qwen系で51.3パーセントと、全キャッシュの54.8、57.2パーセントに近づけた。AIME2025のLlama系では26.7パーセントで全キャッシュに一致した。要約だけを使う簡略版SumRより平均8パーセント高く、詳細の読み戻しが効いている。メモリは、生成長16K、バッチ16で、GPU常駐の全キャッシュと比べて20倍超、全キャッシュをCPUへ退避する構成と比べても4倍超の削減だった。

## 問題設定

長出力で効くボトルネックは、長入力とは性質が違う。プリフィル向けの圧縮は、与えられた文脈を一度絞ればよい。しかし推論履歴は生成とともに増え続け、どの過去の区間が要るかは現在の推論の局面で変わる。しかも推論の区間は、補題の導出や条件の確認といった意味の単位をなしており、トークン単位で間引くとその単位が壊れる。逆に要約だけに潰すと、細かい条件や中間結果を取り違えて誤ったステップを生むことが論文の図で示されている。必要なのは、粗い表現で全体を見渡しつつ、要る場所だけ細部へ戻れる階層的な保持であり、その行き先を現在のクエリから安く決める仕組みである。本論文は、要約をモデルの生成物として履歴内に埋め込み、そのキーの平均を索引に使うことで、追加の索引構造を持たずにこの階層を実現する問題として設定する。

## 手法のあらまし

準備として、Bespoke-17Kの推論データを段落ごとにLlama3-70Bで要約して拡張し、区切りトークンで要約を挟んだ形式で対象モデルをLoRA微調整する。これによりモデルは推論中に、段落の終わりで自分の推論の要約を続けて生成するようになる。推論時、全KVキャッシュはCPUメモリに置かれる。各区間について、要約トークンのキーの平均（平均要約キー）を層とヘッドごとに計算し、GPUに保持する。選択の更新は文の終わりなどの意味境界でのみ行う。現在のクエリと全ての平均要約キーの内積を取り、各ヘッドが上位k件に投票し、全層全ヘッドの票を集計して、票数の多い上位c件を合意集合とする。最終的な文脈は、プロンプト、直近の窓、合意集合の原文区間、候補集合の残りの要約区間の和集合であり、その部分だけをGPUへ読み込んで注意を計算する。転送は層ごとにパイプライン化され、次の層の読み込みを現在の層の計算と重ねる。

## 手法

### 1. 要約生成の微調整 — 推論履歴の中に粗い索引を埋め込む

この機構が観測するのは、推論データの段落である。データ準備では、各段落を、その指示と段落だけを入力としてLlama3-70Bに要約させ、要約の開始と終了を示す専用トークンで挟んで学習データへ入れる。保持される状態は、微調整済みモデルの振る舞いそのものであり、推論時には段落ごとに要約が自動で生成され、履歴は原文区間と要約区間が交互に並んだ構造になる。行う動作は、LoRAによる軽い微調整でこの形式を覚えさせることであり、大規模モデルなら指示だけで同じ形式を出せるため微調整自体が不要な場合もあると論文は述べる。減るボトルネックは、索引を別途構築する費用であり、要約は生成の副産物として得られる。追加で消費する資源は、データ拡張時の70Bモデルの要約生成と一度の微調整である。失敗条件は要約の品質そのもので、より強いモデルで要約を作った場合の効果は未評価と論文が認めている。また区切りの粒度は段落に固定されており、より細かい、あるいは粗い区切りの良し悪しも未検証である。

### 2. 平均要約キーと合意投票 — 全ヘッドの一致で詳細へ戻る先を決める

この機構が観測するのは、現在の生成ステップのクエリと、全区間の平均要約キーである。平均要約キーは、要約区間の全トークンのキーを層とヘッドごとに平均した1本のベクトルで、短い意味のまとまりではキーが局所性を持つという観測に基づく。保持する状態はこの平均キーの集合で、GPU上に小さく収まる。各ヘッドはクエリとの内積が大きい上位k件の要約へ投票し、全層全ヘッドの票数を数える。票の多い上位c件が合意集合となり、その原文区間が詳細として読み戻される。候補集合に入ったが合意に届かない区間は要約のまま残る。減るボトルネックは、トークン単位の重要度計算の費用と、単一ヘッドの偏った選択であり、合意を要求することでモデル全体として重要とみなす区間だけに詳細の費用を払う。感度では、cとkはともに2が釣り合い点で、1では正解率が約3ポイント落ち、増やしても改善は1ポイント程度で、選ばれるKVは4割超増える。誤った場合の挙動として、合意が誤った区間に集まれば詳細が無駄に読み戻されるが、要約側の情報は残るため、要約だけの方式よりは悪化しにくい。分析では、正解軌跡は序盤に合意度が高く安定し、不正解軌跡は合意度のばらつきが大きいことも報告され、合意は品質の診断信号にもなっている。

### 3. CPU退避と層別パイプライン — 読む量を絞り、転送を計算で隠す

この機構が観測するのは、選択された索引集合である。全KVキャッシュはCPUメモリに置かれ、各ステップでは選択集合の分だけがGPUへ読み込まれる。生成された新しいKVはCPU側の全キャッシュへ追加される。保持する状態はCPU上の完全なキャッシュであり、情報そのものは捨てられていない点が、追い出し型の圧縮と違う。行う動作は、選択の再計算を意味境界に限って償却することと、層ごとに必要な部分を転送し、終わった層のKVを非同期に戻しながら次の層を先読みすることで、転送遅延を計算で隠すことである。減るボトルネックはGPUメモリであり、計算例では生成長16Kで5.48倍、32Kでは約7.11倍の削減率になる。追加で消費する資源はPCIe転送であり、その代償としてスループットは全キャッシュより下がることが図で正直に示されている。失敗条件は転送帯域が細い環境で、メモリの余裕と引き換えに速度を失う度合いが大きくなる。

## 評価

### まず見るところ

- **結論:** 要約を索引にした多粒度の選択で、同予算の圧縮方式を正解率で大きく上回り、全キャッシュに近い精度を保ったままGPUメモリを桁違いに減らせた。
- **速度・効率:** 実機測定。メモリ削減は全キャッシュGPU常駐比20倍超、CPU退避比でも4倍超。一方でスループットはPCIe転送のために低下する。速度ではなくメモリの方式である。
- **品質:** 近似。平均正解率は全キャッシュより数ポイント低いが、AIME2025のLlamaでは一致。要約のみの簡略版より平均8パーセント高い。
- **評価の強さ／注意点:** 数学推論が中心で、コード生成や創作など推論構造の違う領域は未評価と論文が明記している。比較対象へはZoomRと同じGPU予算を割り当てる公平な設定である。

数値の読み方として、全キャッシュとの平均正解率の差（Llamaで3.8ポイント、Qwenで5.9ポイント）は残っており、無損失ではない。ただし同予算の既存方式との差はそれより大きく、本方式の主張は「同じメモリなら最も精度が高い」ことに置かれている。合意の動態の分析では、正解軌跡は最初の38回の再計算ステップで合意度が5.7ポイント高く、その後は逆転し、不正解軌跡の合意度の標準偏差は14.82パーセントと正解の7.87パーセントより大きい。つまり合意の安定性自体が推論の成否と結びついており、選択機構が偶然ではなく構造を捉えている傍証になっている。

## 既存研究との差

StreamingLLMは冒頭と直近だけを残す静的な方式であり、本論文は過去全体を要約として残し、必要に応じて詳細へ戻る点が異なる。H2Oはトークン単位の重要度で選ぶ方式であり、本論文は意味区間単位で選び、粒度の細かさによる意味の分断を避ける。QuestやShadowKV等の検索型はプリフィルで生じたキャッシュの検索が主対象であり、本論文はデコード中に生成される推論履歴を対象にする。LightThinker等の要約型の効率的推論は、要約を潜在表現や要点トークンへ潰して原文を捨てるが、本方式は原文をCPUに保持し、検証可能な形で詳細へ戻れる点が異なる。

## 限界・実装状況

- 要約の品質が性能を左右するが、要約生成に使ったのはLlama3-70Bであり、より強いモデルで要約を作った場合の効果は未評価である、と論文が述べている。
- 区間の粒度は段落に固定されており、より細かい、あるいは粗い区切りの影響は未検証である。
- 評価は数学推論が中心で、コード生成や創作など、推論構造の異なる領域への適用は今後の課題とされる。
- スループットはPCIe転送のために全キャッシュより低下する。メモリに余裕のある環境では得にならない場面がある。公式コードのURLは論文中で特定できなかったため、本稿ではcodeをnullとした。

## 一般的な実装上の含意

長い履歴を扱う推論では、履歴を捨てるか全て持つかの二択ではなく、粗い表現を常時保持し、詳細は合意のような強い信号がある場所だけ読み戻す階層化が有効である。その際、索引は外部に作るより、モデルの生成物として履歴内に埋め込むと、追加の索引保守が要らない。また、圧縮方式の比較はメモリ予算を揃えて初めて意味を持ち、精度とメモリとスループットの3者を同じ条件で示すことが、方式の使いどころを正しく伝える。
