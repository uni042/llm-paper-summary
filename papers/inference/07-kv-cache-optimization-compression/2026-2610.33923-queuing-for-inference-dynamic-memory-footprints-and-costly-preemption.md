# Queuing for Inference: Dynamic Memory Footprints and Costly Preemption

> 生成とともに増えるKVキャッシュ、容量超過時の速度低下、状態退避を伴う高価なプリエンプションを待ち行列モデルへ組み込み、古典的最適方針が崩れる理由と、プリエンプション回数を制限しながら短いジョブを優先する方針の平均応答時間を解析した理論研究。

## 概要

大規模言語モデルの推論では、リクエストごとに必要な処理量が到着時点では分からず、しかも処理が進むほどキーと値のキャッシュが増えてメモリを占有する。古典的な待ち行列理論は、処理量が未知のジョブに対して年齢、つまり到達済み処理量に基づく優先付けが平均応答時間を最小化することを示してきた。しかし推論では、長いジョブを中断して短いジョブへ切り替えるたびに、蓄積したキャッシュ状態を退避し、再開時に復元する費用が発生する。さらに占有量がメモリ容量を超えると、残りの処理そのものが遅くなる。本論文はこの3つの効果、すなわち占有量の増加、容量超過時の速度低下、占有量に比例するプリエンプション費用を、単一サーバ待ち行列へ同時に組み込んだモデルを提案する理論研究である。

このモデルで著者らは、まず非プリエンプティブ方針の下での安定領域、つまりシステムが発散せずに処理できる到着率の範囲を特徴づけた。安定領域は平均ジョブ長だけでなく、メモリしきい値を超える裾の大きさに依存する。次に、古典モデルの最適方針であるギッティンズ指標方針が、切り替え費用のために大きな追加負荷を抱えることを示し、代わりに量子と呼ばれる処理量の区切りで優先度を段階化する多段優先度しきい値方針を提案した。この方針は、受けた処理量が量子の倍数に達するたびにジョブを1段下の優先度へ移すことでプリエンプション回数を抑えつつ、新着の短いジョブへ高い優先度を残す。代表結果として、ジョブ長が対数正規分布、基本負荷が約0.82、メモリしきい値が平均ジョブ長の3倍という条件の数値評価で、最適化した2段方針は先着順より平均応答時間を46.6パーセント短くし、段数を無限にした方針は50.3パーセント短くした。量子の最適値を与える経験則も示され、数値最適化なしでも最適点に近い性能が得られる。

## 問題設定

推論のデコード段階では、トークンを1つ生成するごとに、そのトークンのキーと値がキャッシュへ追加され、後続の注意計算で再利用される。したがってリクエストのメモリ占有は、到達済み処理量の非減少関数として増え続ける。占有が小さい間は通常の速度で処理できるが、有限のメモリ容量を超えると、キャッシュの退避や再計算のために実効的な処理速度が係数倍へ低下する。長いリクエストほど容量超過の区間が長く、速度低下による追加の処理量も大きい。

スケジューリングの観点では別の問題がある。ジョブ長の分布は裾が重く、長いジョブの後ろに短いジョブが並ぶと、短いジョブまで大きく待たされる先頭ブロッキングが起きる。これへの古典的な答えは、到達済み処理量が小さいジョブを優先する年齢ベースの方針であり、切り替え費用がゼロなら最適になる。しかし推論では中断のたびにキャッシュ状態の移動か再構築が必要で、その費用は到達済み処理量、つまり占有量とともに増える。優先付けを細かくするほど切り替え回数が増え、切り替え費用が系全体の負荷を押し上げる。つまり短いジョブを助ける利益と、切り替え費用の損失が正面からぶつかる。この交換条件を、メモリ効果と切り離さずに扱えるモデルが従来はなかった。

## 手法のあらまし

著者らは到着がポアソン過程、ジョブ長が既知の分布に従う未知量である単一サーバモデルを出発点に、3つの拡張を入れる。第1に、実行中ジョブの占有量は到達済み処理量の非減少関数で決まる。第2に、占有量が容量を超えると処理速度が係数倍へ落ちる。第3に、ジョブをプリエンプションすると、占有量に比例する追加の仕事が発生する。この下で、まず安定条件を導き、次に提案方針である多段優先度しきい値方針の平均応答時間を、レベルを統合した変換系とビジー期間の議論で閉形式に表す。最後に、平均応答時間を量子について微分した条件から、最適な量子の候補と実務的な経験則を導く。評価は実機ではなく、解析式の数値計算とシミュレーションで行う。

## 手法

### 1. メモリ効果を持つ待ち行列モデル — 占有、速度、切り替えを1つの式系へ

モデルでは、固有ジョブ長という、速度低下も切り替えもない状態で必要な処理量を基本量とする。実行中ジョブの占有量は到達済み処理量の関数として増え、容量を超えた後は不足分が低下した速度で処理されるため、実際に必要な処理量は固有ジョブ長より大きくなる。プリエンプション費用は占有量に比例する追加仕事として加わる。ここで重要なのは、速度低下による追加負荷が、しきい値を超える裾の期待残量で決まる点である。平均が同じ分布でも、裾が重い分布ほど容量超過区間が長く、安定に流せる到着率が下がる。著者らは非プリエンプティブ方針についてこの安定条件を明示し、メモリ制約が単なる同時実行数の上限ではなく、サービス過程そのものを変えることを示した。

### 2. 多段優先度しきい値方針 — 量子で切り替え回数を数える

提案方針は、量子と段数という2つのパラメータを持つ。ジョブは到着すると最上位のレベルへ入り、受けた処理量が量子に達するごとに1段下のレベルへ移る。最下段へ達したジョブはそれ以上中断されない。段数が2ならプリエンプションは最大で1回、段数を増やすほど年齢による優先付けは細かくなるが、切り替え回数の上限も増える。最上位レベルでは短いジョブが先に終わるため、長いジョブに短いジョブが巻き込まれる問題は和らぐ。一方で量子を小さくしすぎると、多くのジョブが境界を越えて切り替え費用を払う。量子はこの境界を決める唯一のつまみであり、方針全体の性能は量子の選び方に強く依存する。

### 3. 平均応答時間の解析と量子の経験則 — 最適点を式で追う

著者らは各レベルで終わるジョブの平均待ち時間を、上のレベルを統合した変換系で求め、ビジー期間の議論で本来の系へ戻すことで、方針の平均応答時間を導出する。そのうえで平均応答時間を量子で微分し、最適な量子が満たす条件を、分布のハザード率に似た量と、速度低下と切り替え費用から決まる関数の交点として表す。数値例からは、メモリしきい値が小さい場合はしきい値自体が量子の強い候補になるという経験則が得られる。しきい値より早く中断すると、低下区間へ入る前に終わるはずの小さなジョブまで不必要な切り替えを払い、遅く中断すると長いジョブが低下した速度のまま走って後続を待たせるからである。ただししきい値が極端に小さい場合は、境界を越えるジョブの割合自体が大きくなり、最適な量子はしきい値より上へずれる。経験則で選んだ量子は、最適化した量子と比べても平均応答時間の改善幅が0.3ポイントしか劣らないことが数値評価で示されている。

## 評価

### まず見るところ

- **結論:** メモリ効果を入れると安定領域は縮み、古典的最適方針は切り替え費用で崩れる。量子で切り替えを制限する提案方針は、先着順より平均応答時間を大きく短縮し、その利得はメモリが厳しい条件ほど大きい。
- **速度・効率:** 指標は平均応答時間と安定な到着率の範囲であり、実機のスループットや遅延の測定ではない。数値は解析式の数値計算とシミュレーションによる。
- **品質:** 生成品質は扱わない。スケジューリング方針の理論性能だけを評価する。
- **評価の強さ／注意点:** 単一サーバ、デコードのみ、実行中ジョブの状態だけを保持するという強い抽象化の上での結果であり、バッチ処理や複数リクエストの同時実行を含む実基盤への直接の換算はできない。

メモリしきい値が平均ジョブ長の6倍、基本負荷が約0.82の条件では、最適化した2段方針が平均応答時間を21.7パーセント短縮し、段数を無限にした方針は32.2パーセント短縮した。読み方として、段数を増やす利得は、年齢による優先付けが細かくなることで中程度のジョブが長いジョブより先に進めるようになるために生じる。しきい値が3倍まで厳しくなると利得は46.6パーセントと50.3パーセントへ広がる。メモリが厳しいほど低下区間で長いジョブが滞留する害が大きく、それを避けるスケジューリングの価値が上がるためである。逆にしきい値が8倍と緩い条件では利得は14.9パーセントと24.6パーセントへ縮む。負荷を上げた比較では、プリエンプション回数に上限を付けたギッティンズ方針は高負荷で応答時間が急増して先着順より悪化し、不安定になる点まで達したのに対し、提案方針は高負荷でも安定を保った。切り替え費用がある世界では、最適性の根拠だった細かな優先付け自体が負荷源になることが分かる。

## 既存研究との差

従来のサービング研究は、連続バッチ処理、プリフィルの分割、プリフィルとデコードの分離、ページ化したキャッシュ管理といった仕組みの設計で効率化を図ってきた。待ち行列側の従来研究は、切り替え費用のあるスケジューリングや年齢ベース方針の解析を進めてきたが、占有量が処理とともに増え、速度と切り替え費用の両方が到達済み処理量に依存する設定は扱っていなかった。推論向けの理論モデル化でも、バッチやキャッシュ制約を取り入れた安定性やスループットの解析はあるが、プリエンプティブなスケジューリングの平均応答時間を定常状態で明示したものはなかった。本論文はこの空白を埋め、メモリ効果と古典的な遅延解析を直接つないだ点に新規性がある。

## 限界・実装状況

- 単一サーバで同時に1リクエストだけを処理する抽象化であり、実基盤のバッチ処理や並行実行とは構造が異なる。著者らも複数サーバ化を今後の課題としている。
- 中断したジョブの状態は保持されない前提であり、状態をホストメモリへ退避して保持する方式では、切り替え費用と他ジョブへのメモリ圧迫の関係が変わる。この変種は未評価である。
- 分布が既知という前提、ポアソン到着という前提に依存し、実トレースでの検証は行われていない。
- 実装はなく、公式コードの公開も確認できない。実基盤への組み込みは今後の課題として論文に明記されている。

## 一般的な実装上の含意

実基盤のスケジューラを設計するときは、優先付けの細かさそのものが切り替え費用という負荷を生むことを前提にすべきである。中断回数に上限を設ける、境界をメモリしきい値の近傍に置く、といった単純な規則でも理論的な裏付けが得られる。また安定性の見積もりは平均ジョブ長だけでは不十分で、長いリクエストの裾がどれだけメモリしきい値を超えるかを見積もりに含める必要がある。
