# Efficient Many-Shot In-Context Learning with Dynamic Block-Sparse Attention

## 書誌・対象範囲

Emily Xiao、Chin-Jou Li、Yilin Zhang、Graham Neubig、Amanda Bertsch（Carnegie Mellon University）、arXiv:2503.08640v2（2025年3月18日）。対象は数千例を推論時の文脈へ含める多数例文脈内学習（many-shot in-context learning; many-shot ICL）であり、特に利用者の要求ごとに適切な実演例（demonstration）を選びたい場合の初回符号化費用とKVキャッシュ再利用の両立を扱う。追加学習を必要としない推論基盤技術であり、分類器そのものの新しい学習目的を提案する論文ではない。

## 概要

通常の多数例ICLは、同じモデルを複数の分類課題へ転用できる反面、数千件の入力・正解ラベル例を毎要求の文脈へ入れるため推論が高価になる。固定した例集合を事前符号化してKVキャッシュを再利用すれば初回符号化は一度で済むが、要求ごとに検索した異なる例集合を使えない。一方、検索ICLは要求に適した例を選べるが、毎回その例集合を改めて符号化するので遅い。

Dynamic Block-Sparse Attention（DBSA）はこの二者を分離する。第1段階では、全実演例を50例単位のブロックに分け、アンカー・近傍・自身にだけ注意する構造化疎注意（structured block-sparse attention）でKVを事前計算する。第2段階では、BM25によって要求に関連するブロックを30%検索し、保存したKV断片を連結し直してから新しい要求を生成する。原著は5つの分類データセットで、Llama-3.1-8Bの90kトークン条件において平均精度0.90（固定ICLと検索ICLはいずれも0.91）を保ちつつ、非キャッシュ検索ICLの約5.3%の1要求遅延に抑えたと報告する。

## 問題設定：固定KVキャッシュと要求依存検索の衝突

固定ICL（Fixed ICL）は例集合全体を一度だけ符号化し、全要求が同じKVキャッシュを読む。長文脈を毎回作り直さない点では効率的だが、個々の要求に不要な例まで注意対象となる。検索ICL（Retrieval ICL、原著表ではRetICL）はBM25などで関連する例を選ぶため精度が高くなり得るが、選択集合が要求ごとに変わるので通常はその都度KVを再計算する。

一般的な接頭辞キャッシュは同じ前方文脈が再利用される場合に効くが、異なる例集合を組み替えると事前計算時の注意依存関係と位置符号が変わる。任意の例集合を通常の全注意で事前符号化したKVを単純に切り貼りすると、例同士が事前に見ていた文脈が再構成後の並びと一致しない。DBSAは最初から注意依存をブロック内・アンカー・局所先行ブロックに制限することで、KVの再利用可能な単位を明確化する。

## 手法：2段階の疎注意符号化とKV断片選択

### 第1段階：実演例プールのブロック化

実演例集合を `D={d1,...,dn}` とし、各 `di` は入力 `qi` と正解 `ai` の組とする。これを `k` 例ずつのブロック `D=[b1,b2,...]` へ分割する。主実験では `k=50` でランダムにグループ化する。各ブロックの注意先は、(1)最初のアンカーブロック `b1`、(2)直前 `j=2` ブロック、(3)そのブロック自身の因果的注意である。全例が全例へ注意するわけではないので、長いプールを一度の全注意計算へ載せる必要がない。

この注意マスクを適用すると、ブロック `bi` を新しく追加する際の入力依存は `b1` と直前2ブロックと `bi` に限定される。したがって既存プールが大きくなっても、追加ブロックの符号化に必要な文脈量は固定される。原著の第7節では追加データのセットアップ費用が追加例数に線形に増えると説明している。これは「全プールの再符号化が不要」という意味であり、保存KV総量が一定になることを意味しない。

### 第1段階の実装：RoPE適用前KVとFlex Attention

事前符号化はFlex Attentionを用い、ブロックマスクで遮断された注意計算を実際に省略する。FlashAttention-2で全注意を計算してから結果をゼロ化する方式ではない。著者はStreamingLLMを参考に、実演例を元の連続位置IDで符号化し、回転位置埋め込み（rotary positional embedding; RoPE）を適用する前のKV状態をブロックごとに保持する。ここが後段の位置再割当てに必要である。

注意シンク（attention sink）として先頭ブロックを残す点はStreamingLLMに似るが、StreamingLLMが古いトークンを捨てる用途なのに対し、DBSAは将来の要求によって選択される例が変わるため全ブロックのKVを保存する。疎注意は主として「事前符号化計算量」を減らし、検索は「要求時に読むKV量」を減らす。保存容量まで自動的に圧縮されるわけではない。

### 第2段階：要求ごとの関連ブロック検索

新しいテスト要求 `q*` が来ると、BM25で例プールのブロックを検索し、関連する部分集合 `D'={b'1,...,b'm}` を選ぶ。主実験では全例プールの30%に相当するブロックを取得する。最初のアンカーブロック `b1` は検索順位にかかわらず必ず含める。これは事前符号化時に他ブロックが参照した共通文脈を残すためだが、要求に無関係な例を強制的に含むという精度上の費用も持つ。

選択した各ブロックのKVキャッシュを連結し、新しい順序の位置ID `0,...,|D'|-1` に基づいて位置符号を再適用する。第1段階でRoPE適用前のKVを保持した理由は、この再配置時に位置情報を作り直せるようにするためである。最後に `q*` のトークンを、選択済みKV全体へ注意できる形で符号化し、分類ラベルを自己回帰的に出力する。主実験のICL方式では出力を有効ラベルに限定する制約付き復号（constrained decoding）を用いる。

### なぜ「ブロック単位」なのか

個別の実演例を好きな順序で取り出すと、符号化時にその例が参照していた直前の例と、推論時に隣接する例が食い違う。例えば例6を符号化したとき例4を参照していたのに、推論時には例3と例6だけを連結すると、例6のKVは例3との相互作用を表現していない。隣接例を同じブロックで扱うと、内部の文脈依存をより多く保てる。原著の10%検索率の比較では、30k・Llama-2の個別例選択は通常0.82対DBSA0.79、ブロック選択は通常0.79対DBSA0.79だった。ブロック単位は精度差を減らし、検索とメモリ操作の単位を粗くして実行負荷も抑える。

## 主要結果：準備時間と1要求遅延

原著表2の数値は**非キャッシュ検索ICL（RetICL）を各設定で1.00とした相対時間**である。小さいほど速い。「DBSAが固定ICLより何倍速いか」は同じ列の時間比から計算する必要がある。

| 条件 | 方式 | 準備時間（RetICL比） | 1要求遅延（RetICL比） |
|---|---|---:|---:|
| 30k・Llama-2-7B・L40S | RetICL | 1.0 | 1.00 |
| 同上 | 固定キャッシュICL | 4.5 | 0.51 |
| 同上 | LoRA微調整 | 600超 | 0.12 |
| 同上 | **DBSA** | **3.0** | **0.22** |
| 30k・Llama-3.1-8B・L40S | RetICL | 1.0 | 1.00 |
| 同上 | 固定キャッシュICL | 5.0 | 0.11 |
| 同上 | LoRA微調整 | 600超 | 0.08 |
| 同上 | **DBSA** | **3.0** | **0.10** |
| 90k・Llama-3.1-8B・A100 | RetICL | 1.0 | 1.00 |
| 同上 | 固定キャッシュICL | 6.5 | 0.060 |
| 同上 | LoRA微調整 | 1500超 | 0.046 |
| 同上 | **DBSA** | **4.0** | **0.053** |

30k・Llama-2ではDBSAの要求時遅延0.22は固定ICLの0.51より小さく、約2.32倍高速い。30k・Llama-3.1では0.10対0.11で約1.10倍、90k・Llama-3.1では0.053対0.060で約1.13倍である。Llama-3.1のグループ化クエリ注意（grouped-query attention; GQA）が固定キャッシュICLにも有利に働くため、固定ICL比の利得はモデルと文脈条件によって小さくなる。非キャッシュ検索ICL比の大幅な改善だけを示して固定キャッシュ方式との差を省略すると、実用上の比較を誤る。

初期準備時間はDBSAがRetICLの3〜4倍だが、固定ICLの4.5〜6.5倍より小さく、LoRA微調整の600〜1500倍超より大幅に小さい。LoRAの学習は30kの例プールで約30分を要したと著者は述べる（表の準備時間では評価ステップの時間を除外）。要求数が増えると準備時間は償却される。原著図1・図3は10万件超の要求を想定してもDBSAが総計算時間で有利と報告するが、これはバッチサイズ1の論文設定と準備・推論時間の積算に基づく結果であり、すべての商用サービング環境での普遍的優位を示すものではない。

90kではDBSAの平均精度0.90は最高基準0.91に近い。30kではClinic-150のDBSA 0.80が固定ICL 0.86を下回り、検索ICL 0.83も下回る。著者はその要因として、最初の50例のアンカーを常に含めることと、ランダムに組んだブロック単位の検索が最適な個別例を取りこぼすことを挙げる。したがって「平均で最高基準の95%以上」は、すべての課題・すべての条件で精度低下が5%以内という意味ではない。

微調整の学習データ量を変えた原著表4では、90k例プール相当の微調整平均0.832、全学習データ（各課題5千〜2万例）での微調整平均0.904、90k DBSA平均0.900であった。DBSAの優位は「学習データが限られたときの準備時間と精度」の両立にあり、全データでの微調整精度を必ず上回るわけではない。

## 構成要素除去実験：疎注意の形が重要

原著表5はLlama-2、30k、50例/ブロックで、検索前の事前符号化に用いる注意マスクだけを変え、テスト要求は符号化済み文脈全体へ注意させた比較である。

| 注意パターン | 5課題平均精度 |
|---|---:|
| 全注意（Full） | 0.84 |
| **アンカー＋直前ブロック＋自身** | **0.82** |
| アンカー＋自身 | 0.27 |
| 自身のみ | 0.09 |

単に注意を疎化すればよいわけではない。アンカーと自身だけでは平均0.27へ崩壊し、自身だけでは0.09まで下がる。直前2ブロックへの局所依存が、追加学習なしで元のモデル能力を維持するための重要な構成要素だと分かる。90kではこのパターンの注意マスクが90%以上疎でも精度を保ったという観測も、局所依存を残す設計の根拠になる。

## ブロック選択とグループ化の感度

原著表6では検索率を主実験の30%から10%へ変更し、個別例単位とブロック単位の選択を比べる。90k・Llama-3.1では、個別例検索の通常実装0.90に対しDBSA 0.86（4ポイント低下）だが、ブロック検索の通常実装0.89に対しDBSA 0.88（1ポイント低下）となる。ブロック単位は符号化時の局所依存を維持しやすい反面、検索粒度が粗くなるため、最適な関連例の選択とはトレードオフになる。

原著表7はランダムグループ化、BM25類似度に基づくクラスタ化、クラスタ間で10%の例を交換して多様性を増した方式を比較する。5課題平均精度は順に**0.827、0.764、0.810**で、ランダムグループ化が最も高い。Banking-77はランダム0.820に対しクラスタ0.696、混合0.740、TREC Fineは0.766に対し0.692、0.764である。類似例を厳密に集めればよいとは限らず、ブロック内の多様性が学習不要のICL性能に寄与する可能性を示す。

原著表8では符号化済みブロックの順序を保持する方式と、BM25関連度の低い順から高い順に並べ替える方式、元順序を反転する方式を比較する。Llama-2・30kのDBSA平均精度は元順0.834、低→高順0.835、逆順0.794であり、逆順は有意に悪化した。事前符号化時に直前2ブロックへの注意を許しているため、KV断片の順序には弱い依存関係が残る。RoPE位置の再割当てだけで任意の順序入替えが無損失になるわけではない。

## 保存容量と実装上の制約

Llama-3.1-8BのKVキャッシュは原著で0.125 MiB/トークンとされ、30kの実演例プールで約3.7 GB、90kで約11.1 GBを要する。LoRA rank 8のタスク別アダプタは約0.01 GBであり、単一課題ではDBSAの全例KV保存の方が重い。DBSAが有利になるのは、モデルを再学習せずに多数のタスクへ適応したい、例集合が頻繁に変わる、キャッシュを複数要求で再利用できるといった条件である。タスクが増えるほどキャッシュを永続保持するコストも増えるため、必要に応じた再符号化やオフロードが必要になる。

GPU側ではFlex Attentionのブロックマスク、RoPE適用前のKV保存、検索後のKV連結、位置ID再割当てが必須の実装要素となる。単に既存のPagedAttentionへ検索したKVページのポインタを渡すだけでは、事前符号化時の注意依存と位置符号の整合が保証されない。DBSAの局所注意パターンを保持したままKVを再利用することが重要である。

## 既存研究との差

固定キャッシュICLは事前計算を再利用できるが要求依存の例検索ができない。通常の検索ICLは要求ごとに関連例を選べるが毎回の長文脈符号化を必要とする。DBSAは疎注意で各ブロックを独立性の高い形に事前符号化し、検索したブロックのKVだけを再利用する点で両者を統合する。

StreamingLLMは古いKVを捨てて長い生成を継続する方式だが、DBSAは将来の検索対象が変わるため全ブロックのKVを保持する。StarAttentionなどのアンカー＋自身型の疎注意は、追加学習なしの多数例ICLでは原著表5のとおり精度を大きく損ねる。関連する検索拡張生成（retrieval-augmented generation; RAG）のKV再利用方式には疎注意パターンへの適応学習を必要とするものがあるが、DBSAは局所先行ブロックへの注意を含めることで学習不要を目指す。

## 限界・負の結果・適用範囲

実験は5つの**分類**データセット、Llama-2-7BとLlama-3.1-8B、30k/90k文脈、単一GPUを中心とする。自由形式の長文生成、複数GPUでの大規模同時サービング、数百万トークン規模の実演例プールで同じ性能が得られるかは検証されていない。90kの11.1 GBというKV保存費用はタスク数が多い環境で重大になる。

また、30kのClinic-150では固定ICLより精度が6ポイント低く、アンカー＋自身のみの注意パターンは平均0.27へ崩れる。ブロック検索は個別例の関連性を取りこぼし、逆順に並べ替えると平均0.834→0.794へ下がる。これらは「疎注意のどの形でも十分」「KVを任意順で再配置しても同等」という解釈を否定する、論文固有の重要な負の結果である。

検索率30%は主実験で固定されており、各要求に最適な検索率をオンライン最適化した実験ではない。著者は検索品質の向上がDBSAの精度上限を押し上げ得るとするが、これは追加研究の余地であり、実測済みの適応検索性能ではない。
