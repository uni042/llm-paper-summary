# Dynamic Flow, Static Graph: KV Cache Reuse for Efficient LLM Serving on Mobile NPUs

> 静的グラフ制約下のモバイルNPUで選択的KV再計算、階層KV管理、I/O重畳を協調させ、prefix・非prefix双方の再利用を実現する。

## 概要

クラウドGPU向けのKV再利用は、要求ごとに動的なキャッシュ参照や再計算範囲を選びやすい。一方、モバイルNPUは実行前に計算グラフとテンソル形状を静的コンパイルすることが多く、メモリ容量と外部ストレージ帯域も小さい。このため「再利用できるチャンクだけKVを読み、残りだけ再計算する」という動的処理をそのまま持ち込めない。

本論文は、端末内のprefix再利用と非prefix再利用を一つの計算・ストレージ協調系として扱う。グラフ内では選択的KV再計算を静的NPUグラフへ埋め込み、グラフ間では動的計画法でチャンクを結合してpaddingを減らす。保存側は木・ハッシュ・意味検索を組み合わせた階層KV管理器を使い、費用認識型の先読みと退避を行う。

さらにKV読込み、回転位置埋め込み（RoPE）の再回転、保存をNPU計算と重ねる2次元パイプラインを構成する。代表的な端末上LLMワークロードで、再利用なしおよびprefix-onlyキャッシュに対して初回トークン時間（TTFT）を40〜60%削減した。EuroSys 2027 Spring Cycle採択論文である。

## 問題設定

端末内エージェントでは、同じ文書や会話履歴を少し編集して再投入する要求が多い。完全一致prefixだけを再利用すると、途中の挿入・削除・並べ替え後に残る共通チャンクを捨てることになる。非prefix再利用ならこれらも使えるが、再利用位置に応じたKVの位置補正と部分再計算が必要になる。

GPUでは要求ごとに動的kernelやindexを組み立てられるが、モバイルNPUは静的グラフを要求する。さらにKVをフラッシュ等へ逃がすと、NPU計算よりI/O待ちが長くなり、再計算を減らしたはずがTTFTを悪化させる場合がある。

したがって「何を再利用するか」「どの静的グラフへ割り当てるか」「どのKVを先に読み込むか」「位置変更したKVをどう補正するか」を独立に最適化せず、一つの実行経路として設計する必要がある。

## 手法

### 静的グラフ内の選択的再計算

要求を固定サイズのチャンクへ分け、再利用可能チャンクと再計算チャンクを判定する。動的な選択結果を直接NPUの制御分岐にせず、あらかじめ用意した静的形状の計算へ写像することで、NPUコンパイラの制約を守りながら不要なTransformer計算を省く。

非prefixチャンクを別位置で再利用するとRoPE位相が変わるため、保存済みkeyを新しい絶対位置へ合わせて再回転する。これにより内容が同じでも位置がずれたチャンクを再計算せず利用できる。

### グラフ間スケジューラ

再計算チャンク数が要求ごとに違うと、固定形状グラフへ詰めた際のpaddingが無駄になる。グラフ間スケジューラは動的計画法を使い、複数チャンクの結合と実行グラフ選択を同時に決めて、NPUへ送る無効計算を減らす。

この層は「動的な要求」を「有限集合の静的グラフ」へ変換する役割を持つ。グラフ数を無制限に増やすのではなく、コンパイル済み形状を再利用しながらpaddingと起動回数を抑える。

### 階層KV管理

KVの照合には木構造によるprefix一致、ハッシュによる完全チャンク一致、意味的類似性を組み合わせる。高速・確実な一致を先に使い、より柔軟な非prefix再利用へ段階的に進むことで検索費用を抑える。

端末ストレージからKVを読む費用を考慮し、再計算より読込みが高い場合まで無条件に再利用しない。先読みと退避も将来利用価値だけでなくI/O費用を含めて決める。

### 2次元パイプライン

データ移動とNPU計算を直列化すると、低帯域端末ではKV読込みがTTFTを支配する。提案系はKV load、RoPE再回転、KV保存をNPU実行と時間的に重ねる。

さらに複数チャンク間でも処理を重ねるため、1チャンク内部の「I/O対計算」とチャンク列方向の「前後処理対NPU」を二つの軸でパイプライン化する。これがストレージ再利用を実際の待ち時間短縮へ変換する。

| 条件 | 指標 | 比較対象 | 提案系 | 読み取れること |

| 代表端末ワークロード | TTFT | 再利用なし | 40〜60%削減 | KV再利用が端末初回応答へ直接効く |

## 既存研究との差

クラウド向けprefix cacheは同じ先頭列を持つ要求のKV共有に強いが、途中編集後の共通部分は使いにくい。非prefix再利用方式もGPUの動的実行を前提とすることが多い。本論文は、非prefix再利用を静的NPUグラフへ落とすこと自体をシステム問題として扱う。

また、キャッシュ検索だけでなく、外部ストレージからのload、RoPE位置補正、NPU実行、保存を同じパイプラインへ含める。モバイルでは「再計算FLOPsを減らす」だけではI/O律速を解けないためである。

## 限界

設計は静的グラフ型のモバイルNPUを主対象とし、動的kernelを自由に使えるGPUでは同じ複雑さが必要とは限らない。端末のフラッシュ帯域、NPUグラフ制約、KVサイズによって再利用と再計算の損益分岐が変わる。

非prefix再利用には位置補正と検索メタデータが必要で、prefix完全一致より管理費用が高い。論文の代表結果はTTFT中心であり、高同時実行クラウドサービングのトークン間遅延やクラスタ規模のスループットを評価する研究ではない。
