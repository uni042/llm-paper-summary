# GraniKV: Asymmetric Granularity KV-Cache Paging for Multi-Agent Systems with Long Shared Prefix

## 監査上の重要事項
この論文は、撤回前の版（v1）では複数エージェント推論で共有される長い接頭辞と、要求ごとに伸びる接尾辞を異なる粒度で管理する鍵値キャッシュ（KV cache）設計を提案していた。しかし2026年8月23日に登録されたv2で、著者は**スループット測定方法に誤りが見つかったことを理由に論文を撤回**し、論文の詳細を非推奨（deprecated）とした。したがって、撤回前の要旨に残る2.16倍、1.98倍、1.57倍、1.95倍などの性能値を、現在有効な実証結果として引用してはいけない。

以下では、設計思想そのものと、撤回前の版が何を主張していたかを区別して記録する。設計案は研究上の発想として説明する一方、評価値は「旧版が報告していた値」に限定して扱い、性能優位の根拠には用いない。

## 概要
複数エージェント型の大規模言語モデル推論では、システム指示、道具定義、共有メモリなどからなる長い接頭辞を複数要求が共有し、その後ろに各要求固有の生成履歴が接尾辞として伸びる。両者は鍵値キャッシュの利用特性が異なる。共有接頭辞は多数の要求から何度も参照されるため、連続した配置にして大きな行列演算へ渡しやすい方が都合がよい。一方、接尾辞は要求ごとに長さと寿命が異なるため、大きな固定ページで確保すると未使用領域が生じやすく、細かな単位で増減できる方がよい。

撤回前のGraniKVは、この相反する要求を一つのページ粒度で処理するのではなく、共有接頭辞を連続領域のHOTプールへ、要求固有接尾辞をトークン粒度のCOLDプールへ分離する「非対称粒度」の鍵値キャッシュ層を提案した。さらに、各復号ステップで計算律速、メモリ律速、通信律速のどれが支配的かに応じ、二つの注意計算バックエンドから実行方式を選ぶディスパッチャを組み合わせる構成だった。

ただし、これらの設計がどの程度の実効性能を与えるかについては、著者自身が測定方法の誤りを理由に論文を撤回している。したがって本サーベイでは、GraniKVを「有効性が確立した高速化方式」ではなく、「共有接頭辞と個別接尾辞の配置粒度を分けるという設計仮説を提示したが、公開性能評価が失効した研究」として扱う。

## 問題設定
一般的なページ化された鍵値キャッシュ管理では、鍵と値の格納領域を一定サイズのページへ分け、要求の伸長に応じてページを割り当てる。これは連続した巨大領域を要求ごとに予約する方式より外部断片化を抑えやすく、動的な推論提供に向く。一方、複数要求が非常に長い同一接頭辞を共有する場合、同じ細粒度ページ化が別の費用を生む。

共有接頭辞は多数の要求が繰り返し読むため、配置が連続していれば、接頭辞部分をまとめて処理する行列積や専用の注意計算経路へ載せやすい。細かなページ表を何度も辿る必要も減らせる。反対に、各要求固有の接尾辞は一トークンずつ増え、要求終了時には個別に解放されるため、粗いページを使うほど「確保したが使わない領域」が増える。つまり共有接頭辞では連続性が重要で、接尾辞では割当の細粒度が重要という逆向きの要求がある。

撤回前の論文は、既存の実運用向けページ化推論エンジンがこの二領域へ同じ粒度を適用することを問題とした。また、バッチ全体が同一の接頭辞境界を持つことを前提に共有部分をまとめて計算するカスケード注意方式は、要求ごとに接頭辞長や内容が異なる条件では適用しにくい。このため、注意カーネルだけを高速化するのではなく、キャッシュ格納層そのものへ「共有領域」と「個別領域」の意味を持たせることを狙っていた。

## 手法

### 1. 共有接頭辞を置くHOTプール
撤回前の設計では、複数要求から再利用される共有接頭辞の鍵値キャッシュを、ページ列へ細かく分散させず連続したHOTプールへ配置する。入力は共有接頭辞に対応する鍵・値テンソルで、出力は複数要求から同じ範囲を参照しやすい連続配置である。狙いは二つあり、第一にページ表探索や散在読み出しを減らすこと、第二に共有接頭辞の注意計算を比較的大きな行列演算として実行できる形を保つことである。

この方式の利得は、十分に長く、かつ多数の要求から再利用される接頭辞が存在する場合に大きくなる。逆に、接頭辞共有がほとんどない、共有範囲が短い、あるいは連続領域を確保する余裕が小さい場合は、HOTプールを別管理する費用に見合わない可能性がある。したがって「全KVを連続配置すればよい」という方式ではなく、再利用頻度が高い領域だけを別扱いする設計である。

### 2. 要求固有接尾辞を置くCOLDプール
要求ごとの生成履歴に対応する接尾辞は、トークン単位で増加し、終了時刻も要求ごとに異なる。撤回前のGraniKVはこの部分をCOLDプールへ置き、トークン粒度で割当・解放できるようにした。入力は各要求の新規トークンに対応する鍵・値で、出力は必要量だけ追加された要求固有キャッシュである。

この細粒度化の目的は内部断片化を抑えることである。大きなページを一つ確保して一部しか使わない場合、残りは他要求へ回せない。要求長のばらつきが大きい複数エージェント環境では、この未使用予約が積み上がる。COLDプールは連続大行列としての扱いやすさより、寿命の異なる小領域を詰めて保持することを優先する。そのためHOTとCOLDを分けること自体が、連続性とメモリ利用率のどちらか一方へ妥協する必要を減らす。

### 3. 二種類の注意計算バックエンド
撤回前の論文は、単一の注意計算実装を常に使うのではなく、共有接頭辞をまとめて処理しやすい経路と、一般的なページ化された接尾辞を扱いやすい経路を併用する構成を説明していた。共有接頭辞が十分大きく規則的なら、連続HOT領域を利用するバッチ化された行列演算が有利になり得る。一方、要求ごとの差が大きい場合や接尾辞側が支配的な場合は、ページ化された一般経路の方が扱いやすい。

ここで重要なのは、保存形式と計算バックエンドを独立に決めない点である。共有接頭辞を連続配置することが、共有部分をまとめた計算経路を利用する前提になる。反対にCOLD側は細粒度配置を保つことで、要求ごとの伸縮に追従する。つまりHOT/COLDの配置方針と注意計算方式が相互に依存する設計である。

### 4. ステップ単位のディスパッチ
撤回前の提案では、各復号ステップの実行状態に応じ、二つのバックエンドから有利な方を選ぶディスパッチャを置く。論文要旨では、計算律速、メモリ律速、通信律速という実行領域の違いを考慮すると説明されている。入力は現在のバッチ構成や共有接頭辞の状態、並列化による通信条件などで、出力はそのステップで利用する注意計算経路である。

固定方式では、共有率やバッチ形状が変化しても同じカーネルを使い続けるため、ある条件では効率がよくても別条件で不利になり得る。ステップ単位の選択はこの変化へ追従するための機構だった。ただし、どの判定規則がどの条件で正しく性能を予測するかを含め、公開版の定量評価は撤回によって信頼できる検証結果ではなくなっている。

## 評価と撤回の影響

### 撤回前に報告されていた内容
撤回前の要旨は、共有接頭辞長16Kトークンの条件で、実運用向け比較対象に対する出力トークン処理量がLlama-3.1-8B、Qwen2.5-14B、Qwen2.5-32Bの各構成でそれぞれ2.16倍、1.98倍、1.57倍になったと主張していた。また、共有接頭辞処理をまとめるカスケード注意統合が飽和時の主要利得で、非対称ストレージ層自体にも1.05〜1.15倍の追加効果があるとしていた。異なる長さ・内容のプロンプトが混在する条件では、バッチ全体を前提にしたカスケード方式が比較対象相当まで低下する一方、GraniKVは1.95倍を維持すると報告していた。

### なぜ現在はこれらを性能証拠に使えないか
2026年8月23日のv2で著者は、**スループット測定方法の誤り**を理由に論文を撤回し、論文の詳細を非推奨とした。撤回理由が性能測定そのものに関係するため、上記の倍率だけでなく、「どの構成要素が何倍寄与したか」「異種プロンプト条件でどの方式が優位か」といった性能帰属も、そのまま確定的な結論として残すことはできない。

この点は通常の「後続版で数値を少し修正した」ケースより重い。著者が訂正版の有効な評価を提示しているのではなく、公開論文を撤回して詳細をdeprecatedとしているためである。本サーベイでは、旧版数値を歴史的な主張として記録することはできても、他方式との速度比較表や「最大何倍高速」といった総括へ再利用しない。

### 再監査で残せる知見
撤回後も、共有接頭辞と要求固有接尾辞が異なる配置特性を持つという問題設定と、「同じ粒度で全KVを管理せず、再利用の強い領域と動的な領域で粒度を変える」という設計空間は研究上の着眼点として理解できる。ただし、この着眼点が実際にどれだけ有効か、どの程度のメモリ節約やスループット改善をもたらすかは、現在の公開版からは確証できない。

したがってGraniKVを関連研究として参照する場合は、**非対称KVキャッシュ粒度というアイデアの出典**としてのみ扱い、性能評価の根拠には別の有効な一次資料を用いる必要がある。将来、著者が修正版を再公開した場合は、その新しい評価条件・測定方法・数値を改めて監査する必要がある。

## 既存研究との差
ページ化注意（PagedAttention）系は、要求ごとの鍵値キャッシュをページ単位で管理して動的なメモリ利用を可能にする。撤回前のGraniKVが変えようとしたのは、ページ化そのものの有無ではなく、共有接頭辞と要求固有接尾辞へ同一粒度を適用する点だった。共有接頭辞は再利用と連続性を優先し、接尾辞は細粒度割当を優先するという非対称性を明示した点が設計上の差である。

また、共有接頭辞をまとめて計算する注意最適化だけを提案したのではなく、その計算経路を成立させるための格納形式と、異種要求へ戻れる別経路を一体化しようとしていた。ただし、これらの統合が既存方式より実際に優れるという定量的主張は撤回済みであり、差分の説明と性能優位の証明を分けて読む必要がある。

## 限界
最大の限界は、論文自体が著者によって撤回されていることである。しかも理由はスループット測定方法の誤りであり、本論文の中心的な性能主張へ直接関係する。そのため旧版の絶対値、相対倍率、構成要素別寄与、異種プロンプト条件での優位性を有効な評価結果として利用できない。

設計上も、長い共有接頭辞が頻繁に再利用されることが前提である。共有が少ないワークロードではHOTプールを分ける価値が小さく、連続領域の確保や管理自体が追加費用になる。COLDプールの細粒度管理にもメタデータと割当処理が必要であり、実装複雑性は増える。どの条件でこれらの費用を上回る利得が得られるかは、撤回後の信頼できる実験からは確認できない。
