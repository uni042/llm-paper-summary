# No Token Left Behind: Reliable KV Cache Compression via Importance-Aware Mixed Precision Quantization

## 概要

自己回帰推論の鍵・値キャッシュ（KVキャッシュ）は、生成済みの各トークンの中間状態を再利用して再計算を避ける一方、必要容量が同時要求数と文脈長にほぼ比例して増える。既存の重要度ベース追い出し（eviction）は、直近の注意頻度が低いトークンを削除するが、そのトークンが将来の質問に必要になる可能性を完全には予測できない。著者らはH2Oによる50%の追い出しで文脈の矛盾や幻覚、安全指示の逸脱が起こる具体例を示し、将来の重要度を事後的に推定するオラクルに近い追い出しでも品質損失が残ると報告する。

提案する混合精度KVキャッシュ（MiKV）は、重要トークンを高精度で保持し、従来なら追い出すトークンも2〜4ビットで保存する。情報をゼロにする代わりに粗い表現を残すため、後から必要になったトークンを注意計算で参照できる。さらに問い合わせQと鍵Kの外れ値をプリフィル中に観測してチャネルごとに再スケールし、極低ビット化の誤差を抑える。Llama-2-7Bのバッチ8、文脈4096の例では、KV容量を34.36GBから6.87GBへ減らしつつ、MMLU正解率は44.0%から42.7%となる。これは容量と品質の交換条件であり、実際のオンライン処理量が5倍になるという主張ではない。

## 問題設定：削除した文脈は戻せない

過去のトークンをキャッシュから削除すると、そのトークンの鍵と値は以後の生成ステップで参照できない。H2Oのように過去の注意重みから重要度を推定しても、次の利用者質問や会話の話題転換は予見できない。重要度推定が当時は妥当でも、後の質問で必要な人名、数値、指示文が削除済みなら復元できず、文章の整合性を失う。著者らは安全指示を含むプロンプトの情報が失われる危険も示しているが、これらの例示から任意の安全機構が必ず破られると一般化してはならない。

本論文のLine Retrievalは、20行の索引と値の組を与え、指定された索引の値を取り出させる課題である。500件の合成評価を用いるため、単純な文脈内情報の残存を比較しやすい。重要比率50%のH2O追い出しは正解率43.2%、20%では4.0%まで落ちる。削除するはずのKVを低精度で保持するだけで、50%重要比率のINT4では63%の容量で正解率100.0%、20%重要比率のINT3では36%の容量で100.0%を回復する。ただしINT2は20%重要比率で64.0%に下がるため、量子化誤差の対策が不可欠となる。

## 手法

### 重要度を保った二層の混合精度保存

MiKVは既存の注意履歴ベース重要度方策をそのまま利用し、選択された重要KVを高精度の重要キャッシュへ、それ以外を低精度の保持キャッシュへ分ける。重要キャッシュは初期設定でFP16、保持キャッシュはINT2、INT3、INT4などのビット幅を選べる。生成時には両群の鍵・値を一緒に注意計算へ渡すため、低重要と判断されたトークンも完全には失われない。重要度判定を無くすのではなく、判定結果を「残すか捨てるか」から「何ビットを割り当てるか」へ転用することが設計上の核心である。

通常のトークン単位非対称量子化では、各トークンの最小値と最大値の差を2^N−1段階へ写像し、量子化後に逆変換する。少数の外れ値が最大値・最小値を引き延ばすと、一般的な値に割り当てられる量子化段階が粗くなる。特に2ビットでは4段階しかないため、単に全KVをINT2へ変換すると、トークンを保持していても連想検索に必要な値を十分表現できない。したがって「追い出しを低ビット保持へ置き換える」ことと「低ビットの誤差を抑える」ことは別々に設計する必要がある。

### 問い合わせ・鍵の外れ値を移す動的チャネル調整

著者らは問い合わせQと鍵Kの各チャネルに系統的な外れ値が現れ、回転位置埋込み（RoPE）によって外れ値が重複することを観測した。プリフィル時に層l、注意ヘッドh、チャネルcごとのQとKの絶対値最大値を計測し、**b_lhc = sqrt(max|Q_lhc| / max|K_lhc|)** という調整係数を計算する。元原稿で平方根と絶対値が省かれやすいが、一次論文の式(2)には両方が明記されている。

鍵Kへbを掛けてから量子化し、浮動小数点のまま扱う問い合わせQはbで割る。理想的な内積では両操作が打ち消し合うので、注意スコアの尺度を保ちながら量子化されるKの外れ値を弱められる。重要なのは、外れ値を完全に削除するのではなく、誤差に敏感な低ビット鍵から、より精度を保てる浮動小数点問い合わせへ負担を移す点である。調整係数は入力プロンプトのプリフィルで求め、生成時には要素ごとの乗除算を行う。RoPEの影響を考慮して、量子化グループの大きさを注意ヘッド次元の半分にする。

この処理の効果は、重要比率20%・保持側INT2のLine Retrievalで、外れ値対策なしの32%容量・64.0%正解率から、対策ありの33%容量・92.6%へ改善する結果で確認できる。ただし調整係数を計算する前処理と要素演算が不要になるわけではなく、特定のモデルと精度条件での効果を他の注意構造へ無条件に一般化できない。

### 重要キャッシュも量子化する場合の限界

重要比率20%・低重要側INT2・外れ値対策ありの条件では、重要側FP16でキャッシュ33%・正解率92.6%、重要側INT8で23%・92.4%、INT4で18%・92.0%となる。しかし重要側までINT2にすると16%・65.0%に急落する。したがって、重要度の高い情報へ一定の精度を割り当てるという混合精度設計が不可欠であり、均一なINT2量子化へ置き換えるだけでは同等品質を得られない。

### 精度別配置と生成時の実装

生成時の注意は鍵・値を大量に読み出すため、メモリ帯域が律速になりやすい。MiKVは位置埋込み適用後の鍵・値を同じ順序で並べ替える限り注意の結果が変わらない性質を利用し、精度ごとにKVをまとめて配置する。これにより精度別の読み出しや、重み専用量子化カーネルに類似した処理を使いやすくする。問い合わせと注意重みは浮動小数点のまま残し、鍵・値側の転送バイト数を減らす。

ただし、全トークンを保持するため注意対象トークン数は減らない。圧縮と復号の費用、精度別バッファ、再配置、重要度の更新が実装上の負担となる。論文の主な性能指標は品質とKVメモリ容量であり、カーネル設計上の可能性をオンラインサービング全体の高速化実測と混同しない。

## 評価

### 実験条件

| 推論基盤 | Hugging Faceの生成機構、モデルと中間活性は基本FP16、NVIDIA V100/A100、決定的な貪欲復号 |
| 課題 | MMLU、GSM8K（各1-shot）、HumanEval（164問）、Line Retrieval（500件）、Llama-2-70B-chatのAlpacaEval |
| 比較 | H2O追い出し、一様な四捨五入量子化（RTN）、完全KVキャッシュ |
| 可変条件 | 重要比率20/25/50%、保持側INT2/3/4、重要側FP16/INT8/INT4/INT2、外れ値対策の有無 |
| 容量表 | バッチ8、系列長4096のKV容量。モデル重みや一時バッファを含む総GPU使用量ではない |

### 文脈検索・量子化感度

| Line Retrievalの条件 | 容量（完全KV比） | 正解率 | 意味 |
|---|---:|---:|---|
| 重要比率50%、低重要KVを完全追い出し | 50% | 43.2% | 将来の必要情報を失う |
| 同条件、低重要KVをINT4保持 | 63% | 100.0% | 少量の数値情報保持で回復 |
| 重要比率20%、完全追い出し | 20% | 4.0% | 高圧縮時の破綻例 |
| 同条件、保持側INT3 | 36% | 100.0% | 低ビット保持の有効性 |
| 同条件、保持側INT2・外れ値対策なし | 32% | 64.0% | 極低ビット誤差が残る |
| 同条件、保持側INT2・外れ値対策あり | 33% | 92.6% | Q/K調整が精度回復へ寄与 |
| 同条件、重要側INT4・保持側INT2 | 18% | 92.0% | 重要側も一部量子化可能 |
| 同条件、重要側INT2・保持側INT2 | 16% | 65.0% | 重要側を削り過ぎる負の結果 |

この表の容量比はビット幅に応じたKV保存量であり、生成遅延の倍率ではない。INT3が20%重要比率で100.0%を維持する一方、INT2は外れ値対策後も92.6%にとどまるため、目標精度に応じてビット幅を選ぶ必要がある。付録ではチャネル単位量子化も試し、INT2で33%容量・99.2%という良好な値を報告するが、重要度方策やバッファを改造した仮想的条件であり、現行MiKVへそのまま組み込んだ実装結果とは区別されている。

### 実モデルの品質とKV容量

| モデル・バッチ8・系列4096 | 完全KV容量 / MMLU | MiKV 20%容量 / MMLU | 解釈 |
|---|---|---|---|
| Llama-2-7B | 34.36GB / 44.0% | 6.87GB / 42.7% | 約80%削減と1.3ポイントの精度低下 |
| Llama-2-13B | 53.69GB / 52.7% | 10.74GB / 52.6% | 約80%削減、精度差0.1ポイント |
| Llama-2-70B（GQA） | 17.18GB / 67.7% | 3.44GB / 67.8% | GQA構成でも容量削減 |
| Mistral-7B（GQA） | 8.59GB / 61.0% | 1.72GB / 60.7% | GQAでも有効、0.3ポイント低下 |

モデル間で完全KV容量が単純にパラメータ数順にならないのは、Llama-2-70BやMistral-7BがGQAを使い鍵・値ヘッドを共有するためである。表はKV容量のみの比較なので、モデル重み・一時領域を含む全GPUメモリが80%減るという意味ではない。MMLUの差はモデルによって方向も異なるため、「全てのモデルで精度完全不変」とは言えない。

Llama-2-70B-chatのAlpacaEvalでは、完全KVを基準とする勝率が50%となり、MiKV 50%容量で50.9%、25%で51.1%、20%で48.6%である。25%までは目立つ勝率低下が観測されない一方、20%ではわずかに下がる。GSM8KとHumanEvalについても、論文は複数のモデルでMiKVが20%付近の容量でも一様RTNや追い出しより品質を保つと報告するが、個々の実測値を図から無理に読み取って表へ作り足さない。

## 既存研究との差

H2Oは重要度の低いトークンを物理的に削除する。MiKVはH2Oの重要度判断を利用しつつ、その集合を極低ビットの保持キャッシュへ移すため、将来の質問で必要になった情報が完全に消える危険を下げる。一様量子化は全KVに同じビット幅を与えるのに対し、MiKVは重要KVに高精度を集中する。加えてQ/Kのチャネル調整でINT2の外れ値誤差を減らし、容量と品質の両方を制御する点が独自である。

## 限界・実装状況

第一に、全トークンを保存する以上、完全追い出しのように注意対象数を減らせず、量子化・復号・精度別再配置の費用が生じる。第二に、重要度推定が誤れば、本来重要なトークンを低精度へ落とすため、完全消去よりは安全でも精度低下はあり得る。第三に、重要側まで2ビットへ圧縮すると検索精度が大きく下がる。第四に、外れ値の統計はプリフィル中に測るので、入力分布や注意構造が異なるモデルで同じ最適設定になる保証はない。

第五に、主な比較はV100/A100と特定のLlama/Mistralモデル、貪欲復号の品質評価である。MiKVのキャッシュ容量比から、オンラインサービングの処理量・初回トークン遅延・生成トークン間遅延・電力の改善を直接推定することはできない。第六に、安全指示の逸脱や幻覚の例は完全追い出しのリスクを示すが、MiKVが安全性を形式的に保証するわけではない。論文から公式コードURLを確認できないため、特定の公開実装を著者の公式成果として断定しない。
