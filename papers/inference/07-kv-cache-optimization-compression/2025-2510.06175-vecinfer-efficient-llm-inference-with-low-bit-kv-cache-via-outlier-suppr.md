# VecInfer: Efficient LLM Inference with Low-Bit KV Cache via Outlier-Suppressed Vector Quantization

> 平滑化とHadamard回転でkey外れ値を抑えてベクトル量子化のコードブック利用を改善し、融合CUDAカーネルで低ビットKVを直接注意計算へ供給する。

## 概要

長文脈推論では鍵値キャッシュ（KV
cache）が系列長とともに増え、容量だけでなくデコード時の高帯域メモリ（HBM）読出しが律速になる。ベクトル量子化（vector
quantization;
VQ）は複数要素をコードブックの代表ベクトルへ置換するため柔軟な低ビット表現を作れるが、keyに大きな外れ値があるとコードブックがその外れ値範囲へ容量を使い、通常値の表現能力が落ちる。

VecInferは量子化前に二つの等価変換を適用する。チャネルごとの平滑化でチャネル間の値幅差を減らし、Hadamard回転でチャネル内に残る外れ値を複数次元へ拡散する。query側へ対応する逆スケールと同じ直交回転を入れることで、変換前後のQK内積を保つ。

量子化表現を実際の速度へつなぐため、復号と注意を融合したCUDAカーネルも実装する。Llama-3.1-8B、196K文脈、2-bit
KVではH100の大バッチ自己注意をFP16比最大2.7倍、A100では2.8倍高速化し、H100の単一バッチend-to-end
decode遅延を8.3倍削減する。

## 問題設定

スカラー量子化よりVQは複数次元の相関をコードブックへ取り込めるが、コードブックサイズにはGPU共有メモリ等の上限がある。外れ値のためにコード語が偏ると、1.5〜2
bitのような強い圧縮で長文脈理解や推論品質が急落する。

また圧縮率だけ高くても、注意のたびに圧縮KVを一度完全復号して一時テンソルへ書き戻せば、HBM交通量とカーネル起動が増える。したがって表現誤差と実行時メモリ交通の両方を同時に処理する必要がある。

## 手法

### チャネル平滑化

keyの各チャネル最大絶対値からスケールλを事前校正する。keyをλの逆数で縮め、queryをλで拡大するため、QK積は数学的に不変である。大きなチャネルだけを縮めることでチャネル間分散を均す。

この変換だけでは同一チャネル内の極端値は残る。構成要素除去では1.5-bit
LongBench平均で平滑化単独よりHadamard単独の寄与が大きく、二段階を組み合わせる必要性が示される。

### Hadamard回転とVQ

平滑化後のquery/keyへ同じ直交Hadamard行列を掛ける。直交性により内積を保ったまま、少数次元へ集中した大値を近傍次元へ分散できる。変換済みkeyを事前学習したK-meansコードブックへ割り当て、valueもVQ表現へする。

コードブックを大きくすれば精度は上がるが共有メモリ消費も増え、カーネル効率が落ちる。論文は2-bitでは256×4次元、1.5-bitでは4096×8次元相当のコードブックを選び、この品質・実装費用を調整する。

### 融合CUDAカーネル

圧縮コードからKVを完全な中間テンソルへ復元せず、注意計算のタイル内で必要なベクトルを復号してQK積とvalue集約へ直接使う。key/valueコードの共有メモリ配置を調整してbank
conflictを減らし、非同期pipelineでglobal-memory転送と計算を重ねる。

この融合により、圧縮がHBM容量削減だけでなくattention read
bytesの削減にもなる。変換自体の追加時間は評価上小さく、196K・2-bitではattention
breakdownでもSDPA比2.0倍の自己注意高速化を確認している。

## 既存研究との差

KIVI等のスカラー量子化はチャネル・トークン粒度の外れ値対策を行う。VecInferはVQのコードブック利用率に焦点を置き、外れ値分布そのものを内積不変な二重変換で均してからベクトル単位で符号化する。

量子化表現だけでなく、復号とattentionを一つのCUDAカーネルへ融合する点も重要である。圧縮率を報告するだけでなく、圧縮表現をHBMへ戻さず計算へ使うことで実際のdecode
latencyへ結びつける。

## 限界

スケールとコードブックには校正データが必要で、完全なデータ非依存量子化ではない。コードブックを増やすと品質は上がる一方で共有メモリを消費し、速度との交換条件がある。

最大8.3倍は長い192K級入力の単一バッチdecodeという、KV読出しが非常に大きい条件での値である。短文脈や計算律速の大バッチではend-to-end倍率は同じにならない。KIVIは一部条件で融合kernel不足によりメモリ不足となっており、全比較が同程度に最適化された実装とは限らない。
