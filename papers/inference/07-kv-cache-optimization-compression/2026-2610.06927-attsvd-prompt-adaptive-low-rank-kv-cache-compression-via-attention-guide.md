# AttSVD: Prompt-Adaptive Low-Rank KV Cache Compression via Attention-Guided SVD

> トークンを捨てず、プロンプトごとにクエリ共分散と注意質量で重み付けした特異値分解の因子だけを保持し、生成の長さに応じて蓄積型とストリーミング型のデコードを使い分ける低ランクKVキャッシュ圧縮。

## 概要

自己回帰型の生成では、過去の全トークンについて層ごと・ヘッドごとにキーとバリューを保持するKVキャッシュが文脈長に比例して増え、長い文脈ではメモリを支配する。学習なしの対策の主流はエビクション、つまり重要度の低いトークンを選んで捨てる方法であり、系列の軸で不可逆な選択をするため、誤って落としたトークンへは以後一切注意できない。本論文のAttSVDは逆の軸を取る。全位置を残したまま、特徴の軸で安く持つ。具体的には、プロンプトが読み込まれた時点で、そのプロンプト自身のキーとバリューに対して切り捨て特異値分解を行い、ランク分の因子だけを保持する。基底は校正コーパスや重みから事前に作るのではなく、その場の注意の幾何から決める。キーはクエリの共分散で重み付けして注意ロジットが保たれるようにし、バリューはトークンごとに受け取った注意質量で重み付けして注意出力が保たれるようにする。

保持メモリはランクに比例して減る。ヘッド次元128でランク64なら理論比は2分の1であり、実測でも文脈32KでPhi-4-14BのKVメモリが密なキャッシュの6.250GiBから3.139GiBへ、Qwen3-8Bでは4.500GiBから2.260GiBへ減り、比率はどちらも0.502だった。品質はほぼ保たれる。同じ50パーセント設定でLongBench平均は、Phi-4-14Bで密なキャッシュ36.7に対して蓄積方式36.0、ストリーミング方式35.7、Qwen3-8Bで51.8に対して51.8と51.9であり、最強のエビクション比較対象と同等かそれ以上だった。生成が長い場合に備え、古くなった生成トークンを凍結した低ランクブロックへ移すストリーミング方式も用意され、正確な窓を有界に保っても品質がほぼ落ちないことが示されている。

## 問題設定

1ヘッドが保持する量はキーとバリュー合わせてトークン数とヘッド次元の積の2倍であり、層数とヘッド数を掛けると文脈長に比例して膨らむ。エビクションはこのうちトークンの軸を削る。重み付きの注意質量、キーの類似度、再構成のしやすさなど採点の流儀は様々だが、いずれも予算分の位置だけを残し、残りは完全に消える。後から必要になった位置は復元できない。一方、キーとバリューをそのまま低ランク近似する再構成型の方法は全位置を残せるが、生の行列への特異値分解はフロベニウスノルムの誤差を最小化するだけで、分散の大きい方向へランクを配ってしまう。注意が実際には読まない方向を正確に残し、読む方向を落とすことが起こり得る。さらに従来の低ランク法の多くは、基底を重みの分解や校正コーパスから事前に作って全プロンプトで使い回すため、目の前のプロンプトの注意の偏りに基底が合わない。もう一つの不足はデコード側である。入力を圧縮できても、生成トークンを正確なまま追加し続ければ、生成が長い思考型の使い方ではキャッシュが生成長に比例して再び増える。本論文は、基底を誰の何に合わせるか、キーとバリューでランクを分けるか、生成側をどう有界に保つか、という3点を同時に解く問題として設定されている。

## 手法のあらまし

処理はプリフィルで始まる。プロンプトのキーとバリューから、直近の数トークンだけを正確な末尾として切り分け、残りの本体を注意重み付きの分解にかける。キーについてはクエリ共分散で重み付けした行列の特異値分解を取り、逆変換を片方の因子へ吸収させて元の座標へ戻す。バリューについては、トークンごとに受け取った注意質量の平方根で各行を重み付けして分解し、重みを戻してから保持する。保持するのは薄い因子の組と正確な末尾だけであり、プリフィル自体の出力は手元にある正確なキーとバリューで計算するため、密なキャッシュとビット単位で同じになる。近似が効くのはデコードで過去を参照するときだけであり、その都度、因子の積で本体を一時的に復元し、正確な末尾と連結して注意を計算する。デコードの維持方法は2通りある。蓄積方式は生成トークンを正確なまま追加し続け、短い生成に向く。ストリーミング方式は正確な窓を滑らせ、溢れた塊を正確な値のまま低ランクブロックへ変換して凍結することで、長い生成でも正確な部分を有界に保つ。ランクは、圧縮率から一律に決める方法と、行列ごとの特異値のエネルギー割合から動的に決める方法を選べる。

## 手法

### 1. 注意重み付きの分解 — キーはロジット空間、バリューは出力空間で切る

観測対象は、そのプロンプトのプリフィルで得られるクエリ群と注意分布である。キーを近似値へ置き換えるとロジットがずれるため、キー側の目的はロジットの誤差そのものである。これはクエリ共分散を計量とする誤差と等しく、共分散の平方根をキーへ掛けた行列について通常の切り捨て特異値分解を行い、片方の因子へ逆平方根を掛けて戻すことで、一般化された最適解が得られる。証明は付録にあり、変換が全単射であることと、切り捨て分解の最適性を与えるエッカート・ヤングの定理から従う。バリュー側では、置き換えが出力をずらす量が問題になる。厳密な計量は注意行列から作る大きなグラム行列を必要とし、文脈長の2乗の大きさになって本末転倒であるため、本論文は対角近似を使う。各トークンが全クエリから受け取った注意質量の合計を行の重みとし、重み付き行列を分解して重みを戻す。これにより、よく読まれるトークンのバリューほど正確に残る。クエリと質量はプリフィルで得られ、クエリは軽いフックで取得し、質量は注意の形をした集約を1回行って読む。グループ化クエリ注意では、1つのキーヘッドを複数のクエリヘッドが共有するため、共分散と質量は共有先をまとめて作る。効く理由は、予算であるランクが、行列の見た目の大きさではなく注意が消費する量の大きい方向へ優先的に配られることにある。追加費用はプリフィル時の分解と、数値安定のための小さなリッジや質量の下限処理である。失敗条件も明確で、合成ヘッドでの対照実験が示すように、クエリが読む方向と特異値の大きい方向がずれている場合にこそ生の分解は崩れ、本手法はそのずれを前提に設計されている。なおキーは回転位置埋め込みを適用した後のものを使う。ロジットの内積は回転後のクエリとの間で定義されるため、回転前のキーで基底を作ると計量がずれるからである。

### 2. ランクの決め方 — 一律の圧縮率と、行列ごとのエネルギー規則

ランクの決め方は2通りある。第1は圧縮率を指定する方法で、キーとバリューが同じランクを使い、メモリ予算が正確に読める代わりに行列ごとの圧縮しやすさは反映されない。第2はエネルギー規則で、各行列について特異値の二乗和のうち割合タウ、既定では0.99、を占めるまでに必要な本数をその行列自身のランクとする。スペクトルが急に減衰する行列は小さいランクで足り、平らな行列は大きいランクを取る。ヘッドごとに得られたランクは、最大値などの集約でキャッシュ全体の形へ揃える。実測ではこの非対称が大きく、タウ0.997ではキーのランクが約65、バリューが約127と、キーがほぼ半分になる一方でバリューはほぼフルランクに残った。つまり一律ランクはキーへ過剰に配るかバリューを削りすぎるかのどちらかになりやすく、行列ごとに決めることで同じ品質をより小さい合計ランクで得られる。個別にランクを直接指定することもでき、キーをバリューよりはるかに小さくする非対称な配分の検証にも使われている。

### 3. デコードの2方式 — 蓄積とストリーミング

プリフィル後の保持形は共通で、因子の組と正確な末尾である。デコードの各ステップでは、層ごとに因子の積で本体を一時的に復元し、正確な部分と連結して注意を計算し、使い終われば解放する。一時的なピークは1層分にとどまり、持続するのは因子だけである。蓄積方式では、生成トークンは正確なまま末尾へ追加され続け、デコード側の分解は一切行われない。生成が短い多肢選択や思考なしの使い方では、正確な生成分は全体の小さな割合にとどまるため、これで十分に安い。ストリーミング方式では、正確な窓は直近の一定トークンだけに限られ、窓から塊単位で溢れた最も古いトークンを、その正確な値から分解して凍結ブロックの列へ移す。各トークンは最大で1回だけ圧縮され、すでに近似された本体を再圧縮することはないため、誤差が生成を通じて累積しない。実験では塊の大きさは128、窓は64が標準的に使われている。トレードオフは、ストリーミングではデコード中にも塊ごとの分解費用がかかる代わりに、正確な部分が生成長によらず有界になることである。

### 4. データと制御の流れ、解釈可能性

1リクエストの流れを通すと、プリフィルで正確に計算しながら本体の因子と正確な末尾を作り、デコードでは毎ステップ、復元した本体、凍結ブロック、正確な窓を位置順に連結して注意を計算する。副産物として、保持した基底そのものが診断情報になる。行列ごとのランクは、そのヘッドのロジット空間と出力空間の実効的な次元、つまり圧縮しやすさを示す。クエリ共分散のスペクトルの減衰は、そのヘッドの注意が少数の方向へ集中しているか拡散しているかを示す。トークンごとの注意質量は、そのまま顕著なトークンの一覧になる。ただしこれは幾何学的な情報であり、基底ベクトルは意味のある概念ではなく、位置と内容が混ざった方向である点に論文自身が注意を促している。

## 評価

### まず見るところ

- **結論:** キャッシュを半分にしても、エージェント型ベンチマークとLongBenchの両方で密なキャッシュとほぼ同等の品質が得られ、エビクション系と他の低ランク系の双方を同等メモリで上回るか並ぶ。
- **速度・効率:** 本論文の主結果はメモリと品質であり、エンドツーエンドの速度や遅延の実測は主結果に含まれない。メモリ比は理論式どおりに実測され、文脈が長いほど理論値へ一致する。
- **品質:** 近似手法である。ただしフルランクでは密なキャッシュとビット単位で一致することが小規模モデルで確認されており、ランクを上げるほど誤差が単調に減る。
- **評価の強さ／注意点:** 比較はすべてトークン予算を本手法のメモリへ揃えた同等メモリ条件である。ストリーミングの差は、多くのタスクで生成が短く窓が溢れないため、そのままでは測れない点に注意が要る。

**数値の読み方。** 生のキーとバリューへの分解との差が、本手法の核心を最もよく示す。同じランク64でも、生の分解はLongBench平均でPhi-4-14Bで31.0まで落ちるのに対し、本手法は36.0から36.7の範囲に留まる。つまり効いているのは低ランク化そのものではなく、基底を注意の空間で選ぶことである。逆に、ストリーミングと蓄積の差は平均で0.3点以内と小さく、これは生成の長いタスクが少ないためであり、窓の大きさを変えた専用のアブレーションで別途確認されている。

## 既存研究との差

エビクション系はトークンの軸を削り、本手法は特徴の軸を削るため、全位置へ注意できる点が根本的に違う。低ランク系の中では、重みを分解する方式と校正コーパスから基底を推定する方式は、基底を全プロンプトで共有する。本手法は基底をプロンプトごとに、その場で厳密な切り捨て分解として求め、校正も学習も実行中の基底の更新管理も要らない。逐次的に基底を追う方式は校正による種付けと近似的な更新を伴うのに対し、本手法の基底は生成中は凍結される。注意を意識する点では、クエリとキーの積やバリューと出力射影の積を校正で低ランク化する方式に近いが、本手法は積そのものではなく通常のキーとバリューの因子を保持し、分解の計量だけを注意に合わせる。そのため1つの校正なしの規則で、キーはロジット、バリューは出力という別々の目的へ同時に対応できる。回転前のキーを圧縮して値を持ち出す方式とも異なり、本手法はキーとバリューの両方を回転後の空間で圧縮する。

## 限界・実装状況

近似である以上、ランクを下げるほど品質は下がり、特に注意質量の小さいトークンのバリューは粗く再構成される。対角近似は意図的な割り切りであり、注意行列の非対角の相互作用は捨てられている。論文自身も、その近似で出力誤差の大半の改善が得られることを根拠に挙げている。評価面では、速度と遅延の実測がなく、プリフィルでの特異値分解の費用とデコードでの毎ステップの復元費用が、メモリ削減と引き換えにどれだけ時間を増やすかは分からない。ストリーミングの実証も生成の長いタスクが少なく、長い思考生成での大規模な検証は今後の課題である。対象モデルは3機種と比較的小規模な可視化用モデルにとどまる。実装は、再現性記述によれば中核コードと動的キャッシュクラスが匿名の補足資料として公開され、完全なリポジトリは採択後に公開予定であり、既存のサービング基盤への統合状況は論文中に示されていない。

## 一般的な実装上の含意

圧縮の目的関数を、保存するテンソル自身の再構成誤差ではなく、そのテンソルが下流で消費される形、つまりロジットと注意出力に置くと、同じメモリ予算でも品質が大きく変わる。実装では、近似対象ごとに消費側の計量を定義できるかが設計の分かれ目になる。また、キーとバリューのように見た目が対称な対象でも圧縮しやすさは大きく違い得るため、予算は一律ではなく対象ごとにスペクトルを見て配る方がよい。さらに、入力側の圧縮だけで満足せず、生成側の増え方を有界化する経路を最初から用意しておくと、生成長の分布が変わってもメモリの見通しが崩れない。
