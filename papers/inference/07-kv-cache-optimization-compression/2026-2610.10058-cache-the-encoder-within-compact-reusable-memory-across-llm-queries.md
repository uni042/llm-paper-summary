# Cache the Encoder Within:Compact, Reusable Memory across LLM Queries

> LLMの下位層を文書エンコーダーとして再利用し、分割境界の残差状態を低ビットで永続保存して適応済み上位層が読み直す方式を提案した研究。

## 概要

長い文書や会話履歴に対する質問応答では、同じ資料が何度もクエリの文脈として使われる。そのたびに資料全体をモデルの全層へ通し直すのは無駄だが、計算済みの状態を保存しておくにも費用がかかる。テキストとして保存すれば小さく済むが計算は残らず、全層のキーと値のキャッシュを保存すれば計算は残るが容量が大きい。例えばQwen3-8Bでは、全層の16ビットKVは1トークンあたり144 KiBに達する。本論文のEncBankは、その中間にあたる対象を保存する。モデルを途中の層で分割し、下位層を文書エンコーダー、上位層をリーダーとして扱い、分割境界におけるトークンごとの残差状態だけを保存するのである。この残差は1トークンあたり8 KiBで、さらに保存精度を4ビットまで下げると2.25 KiBになる。

設計の要点は3つある。第1に、独立に符号化したチャンクの状態はそのままでは読めないため、上位層へ自己蒸留で適応させたリーダーが要る。第2に、再利用の深さ（分割位置）を深くするとプリフィルは速くなるが品質が落ちるため、深さには実用的な妥協点がある。第3に、保存するバイト数を決めるのは深さではなく保存精度であり、精度はリーダーを固定したまま変えられる。代表結果として、5つのベンチマークスイートの集計値では、4ビット保存が本来精度のEncBankから1ポイント以内の差に収まり、固定したQwen3-8Bのワークロードでは永続GPU保存量が本来精度の28.1パーセントになった。ただし、証拠と適応を完全に揃えた本来精度同士の再生比較では、再利用によるプリフィルの高速化は1.40倍にとどまり、RULER精度が3.12ポイント下がった。保存の旨さと再利用そのものの忠実度費用は別物だというのが、論文の正直な結論である。

## 問題設定

再利用メモリの設計は、何の計算を残すかと、どれだけ小さく保存するかの2つの決定からなる。残す計算が少ないほど保存は小さいが、クエリ時にやり直す計算が増える。逆に全層KVのように多く残すと、位置依存やチャンク結合の扱いが難しくなり、保存量も文書集合の成長に比例して膨らむ。境界の残差はこの中間で、1トークンに1状態だけを残し、下位層の計算を丸ごと再利用できる代わりに、上位層の計算はクエリごとに残る。

しかし残差の再利用には2つの障害がある。1つは、チャンクを独立に符号化すると位置が各チャンクでゼロから始まり、チャンク間の注意も欠けるため、連続した全文を通したときの状態とは分布がずれることである。論文の診断では、分割位置12で適応なしの場合にLoCoMoのスコアが24.52にとどまり、上位層だけを適応させると38.27へ上がった。もう1つは保存量で、残差でも128Kトークンで1 GiBに達し、文書集合全体を保持すれば際限なく増える。オンラインで読む量は検索で絞れても、保持する総量は絞れない。したがって、保持バイト数を直接決める保存精度を、品質を大きく壊さずに下げることが、再利用メモリを実用にする条件になる。

## 手法のあらまし

流れは書き込み、選択、読みの3段階である。クエリが来る前に、資料を最大512トークンのチャンクへ分け、各チャンクを下位層だけで独立に符号化し、分割境界の残差を16ビット、8ビット、4ビットのいずれかの形式で詰めて保存する。クエリが来たら、トークンIDに対するBM25検索を3ラウンド繰り返して最大12チャンクを選び、重複を除いて元の順序へ戻し、選ばれた状態だけを復元する。復元した状態列の前後に、独立に符号化したシンクとクエリの状態を置き、上位層が新しい連続位置と因果注意で読む。生成トークンは全層を通る。リーダーの適応は事前に1回だけ行い、連続した全文を処理する教師（適応を無効にした自分自身）に対して、チャンク分割した学生が上位層のLoRAで出力分布を合わせる自己蒸留である。このリーダーは保存精度によらず共有される。

## 手法

### 1. 書き込みと低ビット保存 — 64値グループの affine 量子化で残差を詰める

観測して保持する状態は、チャンク内の各トークンについて、分割境界における隠れ状態ベクトルである。下位層はチャンクごとに位置をゼロから数え直して符号化し、下位層の文書KVは保持しない。保存形式は3通りで、16ビットは元の値をそのまま、8ビットと4ビットはチャンク全体を64値のグループへ平坦化し、グループごとに最小値と刻み幅を持つ affine 量子化で符号へ変換する。符号は32ビット浮動小数で計算し、メタデータは16ビットで保存され、復元時に32ビットへ戻してから元のデータ型へ変換する。重みや演算やクエリ側の状態や要求内のKVは本来精度のままであり、量子化されるのは永続保存される文書状態だけである点が、KVキャッシュ量子化との違いである。保存量の式は明快で、16ビットでは1トークンあたり隠れ幅の2倍バイト、4ビットではメタデータ込みでその28.125パーセントになる。量子化誤差は復元された状態へそのまま入り、上位層が読む入力が本来精度とずれる。論文は精度専用のリーダーを用意せず、このずれを適応済みリーダー共通で受ける設計を取り、その代償が小さいことを集計値で示した。符号化し直しが必要になるのは、資料やチャンク分割やエンコーダーや分割位置が変わった場合で、リーダーだけの変更では既存の保存は壊れない。

### 2. 選択と再構成と読み — 検索は量子化状態を使わず、読みは新しい位置で因果的に行う

クエリ時の選択は、トークンIDに対する反復BM25で行う。1ラウンドで最大4チャンクを取り、新しく取れたチャンクを次の検索の手がかりにして3ラウンドで最大12チャンク集め、重複を除いて資料の元の順序へ戻す。選択が量子化された状態を使わないため、保存精度を変えても選ばれる証拠は完全に一致し、精度比較が証拠の差に汚染されない。これは評価設計として重要な統制である。読みでは、選ばれたチャンクの状態を復元して並べ、先頭に本来のシンク1トークン、末尾にクエリの境界状態を置き、上位層は新しい連続位置を振り直して因果注意で処理する。後のチャンクは前のチャンクを見られ、クエリは選ばれた全チャンクを見られる。下位層のKVはクエリと生成分だけを持ち、上位層のKVは選択パックも含むため、両者の位置履歴は別々に進む。再構成された状態と生成キャッシュは要求内だけのもので、保存された文書項目だけが要求をまたいで残る。証拠同士の注意を遮断する統制では多キー精度が大きく落ちたため、読み側でチャンク間注意を残すことは、独立符号化の欠けを補う実質的な機構になっている。選択が外れた場合、その証拠は原理的に読めず、必要チャンク数が増えると想起率は下がる。論文でも必要チャンク16、24、32件に対する想起率が0.75、0.50、0.375と報告されており、広い集約が要る質問は本方式の弱点である。

### 3. 自己蒸留によるリーダーの適応 — 教師の上位64候補の支持集合で合わせる

適応の目的は、独立符号化でずれた境界状態を上位層が読めるようにすることである。教師は適応を無効にした同じモデルで、順序のある全文を連続処理する。学生はチャンクとシンクとクエリを別々に符号化し、上位層の注意と全結合層の射影にだけLoRAを入れて学ぶ。エンコーダー側と土台の重みは凍結される。損失は、各クエリ位置で教師の確率上位64候補の集合へ教師と学生の分布を絞り直し、順方向と逆方向のカルバック・ライブラー発散を0.6と0.4で混ぜたものである。学習には検索も量子化もベンチマークの監督も使わず、本来精度の状態だけで行うため、得られたリーダーは3つの保存精度すべてにそのまま使える。適応の効果は予測の忠実度でも確認されており、保持した書籍での全語彙の順方向発散が0.442から0.304へ、次トークンの負の対数尤度が2.680から2.579へ下がった。ただし目的関数は支持集合へ絞った分布しか縛らないため、全語彙での振る舞いが保証されるわけではなく、論文もその点を分けて検証している。追加費用はバックボーンごとに1回の適応学習で、分割位置12の適応器は約58.20Mパラメータである。

## 評価

### まず見るところ

- **結論:** 保存精度については、4ビットでも集計品質がほぼ保たれるという肯定的な結果である。一方、再利用そのものについては、揃えた比較で精度費用と限定的な高速化が残るという慎重な結果であり、論文はこの2つを分けて主張している。
- **速度・効率:** 選択パックのプリフィルは再利用で1.40倍速くなるが、デコードを含めると1.07倍から1.09倍へ縮む。書き込み費用を含めると、再利用回数が損益分岐を超える場合だけ得になる。
- **品質:** 集計値の近さと個別回答の一致は別物で、単一キーの統制では完全な生成列が本来精度と一致する割合は8ビットで100件中68件、4ビットで34件まで下がった。
- **メモリ・入出力:** 永続保存は大きく減るが、要求時の初回トークン時間やピークメモリはほぼ比例しては減らない。重みと復元バッファと要求内KVが残るためである。
- **評価の強さ／注意点:** 精度の主証拠はQwen3-8Bの統制研究にあり、ハイブリッド型バックボーンの低ビット結果は供給された集計値で、チェックポイントや判定の結び付きが8Bほど完全ではない。論文自身がその格差を明記している。

数値の読み方を整理する。Qwen3-8Bで分割位置12の場合、4ビット保存は本来精度に対してRULERでマイナス0.22、LongEvalでプラス0.60、LongBenchでマイナス0.09、BABILongでプラス0.90、LoCoMoでマイナス0.46ポイントの差であり、確かに全集計が1ポイント以内に収まる。しかし同じ論文の再生統制では、再利用しない再生（全層を通す）がRULER-Bで99.19、再利用が96.07と、再利用自体に3.12ポイントの費用がある。つまり「4ビットは本来精度の再利用とほぼ同じ」であって、「再利用は全文処理とほぼ同じ」ではない。この区別が本論文の評価の誠実さであり、読み手が混同しやすい点でもある。深さの診断では、分割を6から12へ深めるとプリフィルが830.3ミリ秒から664.4ミリ秒へ減る代わりにRULER-Bが98.29から96.07へ下がり、18では499.5ミリ秒と55.41まで崩れるため、深さは精度との交換が急な調整軸であることも分かる。

費用面では、固定したRTX 5090の条件で、永続GPU保存は本来精度59.64 MiBに対して4ビットで16.78 MiBまで減るが、初回トークン時間は約1.38秒でほぼ変わらず、ピークも約20.6 GiBで変わらない。保存の削減がそのまま要求の削減にはならない。また準備費用の回収には再利用回数が必要で、本来精度の条件では32Kトークンの資料で出力128トークンまでなら9回から11回のクエリが損益分岐であり、資料が長くなるほど、また出力が長くなるほど分岐点は遠のき、条件によっては有限の分岐点が存在しない。エージェント評価では、Qwen3.8-27Bの本来精度の構成がTerminal-Bench 2.1で89件中70件に合格し、全履歴を読み直す密な条件の61件を上回ったが、適応器と実行経路が異なるため、論文はこれを再利用効果の分離された証拠としては扱っていない。

## 既存研究との差

再利用可能な表現の研究には、テキスト表現を再利用するReadOnceや埋め込みリサイクル、オフライン圧縮とLoRAを組み合わせるLLoCO、側メモリや交差注意を使う方式などがある。直接の土台であるCoMemは、独立符号化した残差チャンクを検索して上位層で続きを読む接口を与えたが、保存は本来精度のままだった。本論文の差は、その接口へ低ビット永続保存を加え、精度ごとにリーダーを作り直さずに済むことを示した点にある。KV側の研究であるPrompt CacheやTurboRAGやCacheBlendは全層KVの組織化や修復を扱い、KIVIやKVQuantは注意KVそのものを量子化する。本論文は量子化の対象を保存される残差へ移し、保存量と品質と要求費用を分けて測る点で異なる。

## 限界・実装状況

- 再利用の忠実度費用は残っており、特に証拠同士の相互作用が強い質問や、広い集約が要る質問では精度が落ちる。局所的な修復として試された左重なり書き込みは、合成的な多キーでは改善したが自然な質問応答では悪化し、既定には採用されていない。
- 準備費用の回収は再利用頻度に依存し、1回しか読まれない資料では再利用は割に合わない。出力が長い条件では分岐点が消える場合もある。
- 永続状態は資料と同等のアクセス権と削除の扱いが必要であり、低ビット保存はプライバシーの保証にはならないと論文は明記している。
- コードは匿名化リポジトリで示されている段階であり、上流ランタイムへの統合や公開実装での再現報告はまだない。

## 一般的な実装上の含意

再利用メモリを設計するときは、保存対象の深さと保存精度を別の調整軸として分けるべきである。深さは1回あたりの再計算と品質を、精度は保持バイト数を主に決める。また、保存量の削減率をそのまま要求費用の削減率として報告せず、初回トークン時間、ピークメモリ、準備費用、損益分岐の再利用回数を分けて測ることが要る。評価では、選択される証拠を精度条件の間で固定する統制と、集計値だけでなく個別回答の一致率を見ることが、再利用方式の過大評価を防ぐ。適応済みリーダーを精度間で共有できれば、保存形式の変更が学習のやり直しを伴わないため、運用中に精度を切り替える余地が生まれる。
