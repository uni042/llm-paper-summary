# GrowPage: On-Demand KV Budgeting for Efficient LLM Reasoning Serving

> reasoning中に「過去contextをどれだけ広く参照し始めたか」を追跡し、必要な時だけKV cache容量をpage単位で少しずつ増やすserving方式。

## 書誌情報

- 公開日: 2026-09-03
- 状態: Preprint
- arXiv: 2609.03494
- 著者: Qiankun Maほか
- 所属: SIAT CAS, Pengcheng Laboratory, UCASほか
- 主題: dynamic KV cache budgeting

## 概要

GrowPageは、reasoning中に必要なKV cache量が一定ではないことを利用する。

最初からFullKV相当の大きな容量を確保するのではなく、**現在の生成tokenが過去contextのどの範囲を強く参照しているかを継続的に観測し、より広い過去情報が必要になった時だけKV budgetを1 pageずつ増やす**。

需要が増えていない間は現在の容量の中で重要KVを残すため、不要なVRAM確保を避けられる。CPU DRAMやSSDへKVを逃がすoffloadではなく、GPU上で使うKV容量そのものを動的に決める手法である。

## 手法

### 1. 短期と長期のquery傾向を比較する

各decode stepのqueryをそのまま1stepずつ見ると変動が大きいため、最近の傾向を表す短期平均と、より長い傾向を表す長期平均を作る。

新しいqueryがどの過去token群へattentionしそうかを、この2つの平均から推定する。

論文では指数移動平均（EMA）を使い、**直近だけで参照先が変わったのか、それとも継続的に必要な過去範囲が広がっているのか**を区別しやすくする。

### 2. 現在のKV容量へ到達したときだけ判断する

まだKV budgetに余裕がある間は通常通り追加する。

容量上限へ達した時点で、次のどちらかを選ぶ。

- **Compress & Hold:** 今のpage数を増やさず、重要度の低いKVを外して現在容量内へ収める。
- **Grow by One Page:** 将来もより広い過去contextが必要と判断した場合、KV用pageを1枚だけ増やす。

一気に大きく増やさず1 pageずつ拡張するため、必要以上のVRAM予約を抑えられる。

### 3. 「一時的なattention変化」と「本当に必要量が増えた状態」を分ける

reasoningでは一時的に古いtokenへattentionすることがあっても、それだけで以後ずっと大容量KVが必要とは限らない。

GrowPageは短期・長期signalの差から、**一時的な参照変化なら圧縮したまま、継続的な需要増加なら容量追加**という判断を行う。

### 4. 既存serving基盤と共存する

PagedAttention、continuous batching、prefix caching、CUDA Graphなどを前提に実装でき、追加学習を必要としない。

ここでのpageは、PagedAttentionのようにKV memoryを固定サイズblockで管理する仕組みと合わせやすい単位である。

## 評価

NVIDIA A100 80GB上でDeepSeek-R1-Distill-Llama-8BとQwen3-8Bを評価している。

- DeepSeek系: FullKV vLLM **1472 tok/s、平均pass@1 69.2** に対し、GrowPageは **2417 tok/s、68.7**。
- Qwen3-8B: FullKV **1357 tok/s、88.7** に対し、GrowPageは **2174 tok/s、87.5**。
- online signalとfuture demand changeのSpearman相関は **0.78**、変化方向の符号一致率は **80.3%**。

Spearman相関0.78は、GrowPageが実行中に計算する需要signalの順位と、その後実際に起きるKV需要変化の順位が比較的よく一致したことを示す。

## スコープと制約

- 対象はKV cacheのGPU内budget制御であり、MoE expert weightのresidencyやweight offloadは扱わない。
- CPU offload、SSD / NVMe offload、CXL memory、High-Bandwidth Flash（HBF）は評価対象外。
- 容量を増やさない場合はKV compressionを行うため、FullKVと完全同一の計算ではなく小さな品質差があり得る。
- 将来需要の判定が外れると、不要なpageを増やすか、必要な局面で圧縮を続けて品質を落とす可能性がある。
- 実機評価はA100中心で、他GPUのpage管理costやmemory容量では最適設定が変わり得る。

## 実装上の含意

固定KV budgetでは、難しいreasoningへ合わせて常に大容量を確保するとVRAMを浪費し、逆に小容量へ固定すると必要な場面で品質が落ちる。

GrowPageは、**オンラインで観測できるattention需要から「今後も容量増加が必要か」を判断し、最小単位で追加する**設計を示す。KV allocatorやpage managerがrequestごとに異なるbudgetを持てるserving engineと相性がよい。
