# KunServe: Elastic and Efficient Large Language Model Serving with Parameter-centric Memory Management

> 負荷急増時にリクエスト固有KVではなく複製パラメータを選択的に解放し、注意演算を他GPUへ遠隔実行してKV空間を確保するパラメータ中心のLLMサービング方式。

## 概要

オンラインLLMサービングでは、負荷急増や長い思考連鎖生成によりKVキャッシュが急増するとGPUメモリが枯渇する。既存のKV中心方式は、進行中リクエストのKVを捨てる、CPUへ退避する、別GPUへ移すことで新規要求の空間を作る。しかしKVはリクエスト固有状態なので、捨てれば再計算、移せば通信が発生し、既存要求と新規要求のどちらかのサービス品質目標（Service-Level Objective; SLO）を悪化させる。

KunServeは逆に、複数GPUへ複製されているモデルパラメータはリクエスト状態ではないため、一部を一時的に解放できると考える。空いたGPUメモリをKVへ転用し、欠けたパラメータに必要な注意演算はパラメータを持つ別GPUへ遠隔実行する。負荷が戻ればパラメータを復元する。評価ではスロットリング時の末尾初回トークン時間（Time To First Token; TTFT）を既存最先端方式比最大27.3倍短縮する。

## 問題設定

KVキャッシュは要求ごとに異なり、生成を継続するための状態である。これを追い出すと後で同じprefixを再計算するか、PCIe・ネットワーク越しに戻す必要がある。一方、モデル重みは多数GPUに複製されていることがあり、同じ内容が複数箇所に存在する。KunServeはこの非対称性を利用し、「状態を守り、複製物を一時的に減らす」方針を採る。

ただしパラメータを落としたGPUは通常ならその層を計算できない。特にKVは各層の注意演算と結び付いているため、単純に重みを削除すると既存要求まで停止する。そこで注意演算を他GPUへ分離して実行できるようにする必要がある。

## 手法

### パラメータ中心のメモリ解放

メモリ圧迫を検出すると、KunServeは複製パラメータの一部を選択的にGPUから解放し、その領域を新規・継続要求のKVキャッシュへ割り当てる。KVを捨てないため、長いprefixの再計算やKV全量のCPU退避を避けられる。解放量を増やすほどKV余裕は増えるが、遠隔計算へ依存する範囲も増える。

### 遠隔注意機構

注意演算は他の演算から切り離せるという観察を使い、パラメータが欠けたGPUの要求について必要な注意処理を、対応パラメータを保持するGPUへパイプライン並列的に委譲する。これにより、要求のKVは元GPU側の空いたメモリに保持しつつ、計算能力はクラスタ内で借りる。通信が増えるため、すべてを遠隔化するのではなくメモリ不足量と協調実行費を釣り合わせる。

### 不完全パラメータ状態でのKV交換

負荷中は各GPUが同じ完全モデル複製を持たないため、従来の「どのGPUでも同じ層を計算できる」という前提が崩れる。KunServeはKVの所在と利用可能パラメータを追跡し、要求を移動・継続するときに、欠けた層の計算をどこへ送るかを同時に扱う。単なるメモリ追い出しではなく、計算配置と状態配置を結合した制御になる。

### 計画生成と復元

必要メモリ量、遠隔注意の通信・計算費、進行中要求への影響から、どのパラメータを解放するかを計画する。負荷が下がるとパラメータを段階的に戻し、通常のローカル実行へ復帰する。急激な再配置で全要求を止めないことが弾力性の要点である。

## 既存研究との差

vLLM系のページ化やKV退避方式は、要求状態であるKVを中心にメモリをやりくりする。KunServeは複製パラメータを可変容量として扱う点が逆である。単に重みをCPUへオフロードするのではなく、欠けた状態でもサービスを継続するために遠隔注意と配置計画を組み合わせるところが主要差になる。

## 限界・実装状況

複数GPUにパラメータ複製があることが利得の源なので、もともと極限までテンソル並列化され複製余地が少ない配置では解放できる容量が小さい。遠隔注意はネットワーク帯域と相手GPUの余力を消費するため、クラスタが全体的に飽和すると利得が縮む。負荷復帰時には重みを戻す転送も必要であり、頻繁な負荷振動では再配置費が問題になる。最大27.3倍はスロットリング時の末尾TTFTであり、定常時の平均生成速度とは別指標である。
