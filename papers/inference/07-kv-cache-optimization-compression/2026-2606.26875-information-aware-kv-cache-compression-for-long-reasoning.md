# Information-Aware KV Cache Compression for Long Reasoning

## 概要
長い推論では、現在の注意重みが小さい過去トークンでも、数千トークン後の推論で再び必要になることがある。従来の鍵値キャッシュ（KV cache）圧縮は、直近の問い合わせから大きな注意（attention）を受けたトークンを残す設計が多い。そのため、短距離では目立たないが将来の予測分布を大きく変える情報を削除する可能性がある。

InfoKVは、この問題を「将来影響度（Forward Influence）」という分析量で調べる。ある過去トークンを除いたとき、後続トークンの予測分布がどれだけ変わるかをカルバック・ライブラー発散（KL divergence）で測ると、注意重みの大きいトークンは近距離で強く影響する一方、生成時の予測不確実性が高いトークンは遠い将来まで影響を残しやすい。そこで実運用時の保持スコアには、注意重みだけでなく、予測エントロピーと層を通した表現変化を組み込む。

提案法は、Llama-3.1-8B-InstructとLlama-3.2-3B-Instructを使う長文プリフィル評価、およびDeepSeek-R1-Distill-Qwen-7B/Llama-8Bを使う長い復号評価で検証される。LongReasonでは40%・20%の鍵値キャッシュ保持率でSnapKV、PyramidKV、Expected Attentionを上回り、長い復号でもRPCより高いタスク性能を示す。ただし本論文が主に示すのは「圧縮後の品質」であり、実測トークン毎秒、遅延、GPUメモリ使用量を総合した推論システム高速化を直接証明するものではない。

## 問題設定と将来影響度
注意重みに基づく圧縮は、「いまの問い合わせがどの過去トークンを参照しているか」を直接利用できるため合理的である。しかし長い思考連鎖では推論状態が時間とともに変わる。初期に導出した条件、途中で導入した変数、後で再利用する中間結論などは、直近数百トークンでは参照されなくても、後続の分岐で再び必要になり得る。

論文はこの違いを将来影響度で診断する。トークン (x_i) を残した場合と除いた場合で、その後の予測分布の差を測り、将来の複数位置にわたって平均する。これは実行時に全候補トークンへ毎回計算する保持スコアではなく、「何を残す信号が必要か」を分析するための道具である。

最初の2048トークンを圧縮し、その後の128トークン単位の区間への影響を追跡すると、注意重み上位のトークンが持つ影響は距離とともに急速に弱まる。一方、生成時のエントロピーが高いトークンは、約14Kトークン先の領域でも比較的強い将来影響度を示す。これは、注意重みが主に現在の関連性を表し、予測エントロピーが「その時点でモデルがどれだけ情報を確定できていなかったか」という別の信号を与えることを意味する。

InfoKVはこの観察から、保持判断を一つの信号へ寄せない。短距離で現在の計算に重要なトークンは注意重みで拾い、長距離で再利用される可能性のある情報は予測エントロピーと表現変化で補う。どちらか一方だけを強くすると性能が下がるという構成要素除去実験も、この補完関係を支持する。

## 手法

### 1. 上位候補限定の予測エントロピー
各トークンを生成した時点の語彙確率分布から予測エントロピーを計算する。ただし全語彙をそのまま使うと、ごく低確率の長い裾が多数入り、保持判断に必要な不確実性よりノイズを増やしやすい。そこでInfoKVは確率上位 (k) 候補だけを使う上位候補限定エントロピー（Top-k Restricted Entropy）を用いる。

入力はトークン生成時の語彙分布、出力はそのトークンに対応する不確実性スコアである。論文の感度評価では (k=256) が安定して良く、全語彙エントロピーよりも良い品質を示す。ここでエントロピーが高いこと自体を「重要」と断定するのではなく、注意重みでは捉えにくい長距離影響の候補を補助的に浮かび上がらせる。

追加費用は、生成時の確率分布から上位候補を取り出してエントロピーを保持することである。注意重みを再利用するだけの方式より状態管理は増えるため、品質改善がそのまま実時間高速化になるわけではない。

### 2. 層間の表現進化を使う情報スコア
同じトークンでも、浅い層から最終層までほとんど表現が変わらない場合と、層を進むにつれて大きく意味表現が更新される場合がある。InfoKVは層 (l) の隠れ状態と最終層の隠れ状態の余弦距離を (D_i^{(l)}) とし、予測エントロピー (H_i) と組み合わせて情報スコア (E_i^{(l)}) を作る。

直感的には、生成時に不確実性が高く、さらにネットワーク内部で表現が大きく洗練されるトークンへ高い値を与える。浅い層ですでに最終表現へ近いトークンは相対的に小さくなる。最終層では距離がゼロへ近づくため、スコアが機械的に消えないようバイアス (	au) を加える。既定設定では (	au=1) が使われる。

入力は各層の隠れ状態と生成時エントロピー、出力は層ごとの情報スコアである。この機構により、同じトークンを全層で同じ重要度とみなさず、層ごとに「残す価値」を変えられる。その代わり、層間表現を参照し距離を計算する管理費用が増える。

### 3. 注意重みとの混合と鍵値キャッシュ選択
最終的な保持スコアは、注意重み由来のスコア (A_i^{(l)}) と、情報スコアを正規化した値を混合して作る。

[
S_i^{(l)}=alpha A_i^{(l)}+(1-alpha)operatorname{Softmax}(E^{(l)})_i
]

各層でこのスコアが高いトークンから、与えられた保持予算の範囲で鍵値キャッシュへ残す。入力は現在の注意重み、予測エントロピー、層間表現変化、保持率であり、出力は層ごとの保持トークン集合である。

(alpha=1) にすれば純粋な注意重み方式へ戻る。構成要素除去実験では情報側を少量混ぜる方が良く、長文プリフィルでは (alpha=0.9) が代表設定となる。長い復号ではタスクごとに設定が異なり、IFEvalでは0.9、AIME 2024とLiveCodeBenchでは0.95が使われる。したがって「InfoKVは常に0.9」と一般化するのは正しくない。

### 4. 長い復号での反復圧縮
長文プリフィルを一度だけ圧縮する方式では、生成が数万トークン続くと新しい鍵値キャッシュが再び増え続ける。InfoKVは長い復号実験で1024トークン生成するたびに圧縮を実行し、推論途中で新しく生じた履歴にも同じ重要度判定を適用する。

この反復処理により、初期入力だけでなく思考連鎖全体のキャッシュ量を抑えられる。ただし1024トークンごとに保持スコアを再計算するため、圧縮処理自体の時間が追加される。論文はタスク精度を中心に比較しており、この追加計算まで含めた壁時計遅延の削減率は主要な検証対象ではない。

### 5. 層別の適応保持予算
論文は、すべての層へ同じ保持率を割り当てる一様予算だけでなく、層ごとの重要度に応じて保持量を変える適応予算も検討する。DeepSeek-R1-Distill-Llama-8Bの25%保持条件では、適応予算が61.18%、一様予算が60.07%となり改善する設定が報告される一方、Qwen-7Bでは過度な層間不均衡が逆効果になる。

この負の結果は重要である。層ごとに重要度が違うからといって、予算を強く偏らせれば常に良いわけではない。そのため論文の既定評価では一様予算を中心に扱い、適応割当はモデル依存の追加最適化として位置付ける。

## 評価条件
長文プリフィル評価ではLlama-3.1-8B-InstructとLlama-3.2-3B-Instructを使い、LongReasonの16K、32K、64K文脈で推論する。比較対象は完全キャッシュ、SnapKV、PyramidKV、Expected Attentionなどで、40%および20%保持率を中心に、思考連鎖あり・なしの正答率を測る。

長い復号評価ではDeepSeek-R1-Distill-Qwen-7BとDeepSeek-R1-Distill-Llama-8Bを用い、IFEval、AIME 2024、LiveCodeBenchを評価する。最大出力長は32768トークンで、1024トークン生成するごとに鍵値キャッシュを再圧縮する。IFEvalは各入力1生成、AIME 2024は各問題8生成、LiveCodeBenchは各問題4生成という設定で評価される。

比較対象のRPCも復号途中で鍵値キャッシュを圧縮する方式であるため、InfoKVの長い復号評価は「一度だけ入力を圧縮する方法」との比較ではなく、成長し続けるキャッシュを反復して削減する条件での比較になっている。重要な指標は、同じ保持率でどれだけタスク性能を残せるかであり、推論時間や圧縮処理時間を直接最適化した評価ではない。

## 主要結果
LongReasonのLlama-3.1-8B-Instructでは、40%保持時の平均正答率がInfoKVで思考連鎖あり52.53%、なし48.88%となる。SnapKVは51.09%/47.15%、PyramidKVは50.76%/46.25%、Expected Attentionは51.13%/46.81%であり、同じ保持率ではInfoKVがすべてを上回る。20%保持でもInfoKVは49.79%/46.89%で、SnapKVの49.37%/45.70%、PyramidKVの48.57%/45.83%、Expected Attentionの48.70%/45.68%より高い。

Llama-3.2-3B-Instructでも40%保持時の思考連鎖あり平均はInfoKV 43.95%で、SnapKV 43.03%、PyramidKV 42.86%、Expected Attention 43.11%を上回る。論文の長さ別分析では、系列が長くなるほど注意重みだけの方式との差が大きくなる傾向があり、遠距離情報を別信号で拾うという問題設定と対応する。

長い復号では、DeepSeek-R1-DistillのQwen系・Llama系の双方でInfoKVがRPCよりIFEval、AIME 2024、LiveCodeBenchの品質を改善する。特にLlama-8BのIFEvalでは25%と12.5%の保持率で完全キャッシュを上回る条件も報告される。これは圧縮そのものが常に品質を上げることを意味せず、不要または攪乱的な履歴を除いた結果として一部条件で完全キャッシュより高いタスク得点になったと読むべきである。

構成要素除去では、上位256候補のエントロピー、(	au=1)、注意重みを主成分に残す混合が安定している。注意だけへ戻すと品質が下がり、反対に情報スコア側を強くしすぎても短距離依存を失って悪化する。したがってInfoKVの利得は「エントロピーだけで選べばよい」ことではなく、局所関連性を持つ注意重みと長距離影響の代理信号を組み合わせることにある。

また、層別適応予算はモデルをまたいで一貫して有利ではない。Llama系で改善する設定がある一方、Qwen系では悪化するため、層ごとの保持量を強く偏らせる最適化にはモデル依存性がある。これは提案法の適用範囲を判断するうえで、平均値だけでは見えない重要な負の結果である。

## 既存研究との差
SnapKVやPyramidKVは、直近の観測窓から得られる注意重みを中心に過去トークンの重要度を決める。Expected Attentionは将来の問い合わせを考慮するが、InfoKVは「生成時の不確実性」と「層を通して表現がどれだけ変化したか」を、注意重みとは独立した情報信号として加える。

RPCとの違いは、長い復号中に反復圧縮するという運用だけではない。InfoKVは、そのたびに現在の注意重みだけでなく、トークン生成時のエントロピーと層別表現を使って保持候補を順位付けする。したがって新規性の中心は圧縮頻度ではなく、「将来影響を捉えるための補助信号を保持判断へ入れる」点にある。

## 限界
第一に、品質改善とシステム高速化を分けて読む必要がある。InfoKVは保持する鍵値キャッシュ量を減らすが、予測エントロピーの保存、層間表現距離の計算、スコア統合、長い復号での反復圧縮という追加処理がある。論文は実測トークン毎秒、最初のトークンまでの時間、トークン間遅延、圧縮処理込みの壁時計時間を主要結果として定量化していないため、保持率20%を「推論が5倍速い」と読み替えることはできない。

第二に、評価対象はLlama-3.1/3.2とDeepSeek-R1-Distillの特定構成、およびLongReason、IFEval、AIME 2024、LiveCodeBenchに限られる。別の注意パターン、混合専門家モデル、長文会話、検索拡張生成などでも同じ保持信号が最適とは限らない。

第三に、層別の適応保持予算はモデル依存である。Llama系では改善する条件があるが、Qwen系では悪化する。保持率を極端に下げるほど重要トークンの誤削除リスクも高まり、注意と情報スコアの混合係数もタスクごとに調整されている。したがって単一の固定設定をあらゆる長推論へそのまま適用できるとは示されていない。

最後に、一次資料から公式実装の公開URLは確認できていない。再現性や実装上の追加メモリ・計算費を評価するには、今後のコード公開または独立実装による検証が必要である。
