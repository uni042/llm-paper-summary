# BitDecoding-FP4: Native FP4 KV Cache Decoding via Algorithm-System Co-Design

> クエリの二重残差表現、確率のアンダーフロー対策、キーの外れ値対策と転置ソフトマックスを組み合わせ、FP4テンソルコアで直接デコードしながらBF16並みの精度と2.4倍から3.0倍のサービングスループットを得るFP4 KVキャッシュ方式。

## 概要

長文脈の言語モデルサービングでは、過去トークンのキーとバリューを保持するKVキャッシュが、文脈長と同時リクエスト数に比例して増え、GPUメモリ容量とメモリ帯域の両方を支配する。キャッシュを4ビットへ量子化すれば容量と転送量は減る。特にブロックごとにスケールを持つマイクロスケーリング形式のNVFP4とMXFP4は、Blackwell世代のテンソルコアでそのまま行列積を実行でき、逆量子化の手間も省ける。しかし論文は、既存のFP4 KVシステムは素朴な量子化で精度が大きく落ち、逆に精度を重視するTurboQuantのようなベクトル量子化はコードブック参照の費用でデコードスループットが崩れるという溝を指摘する。著者らの測定では、TensorRT-LLMの素朴なNVFP4はQwen3-4BでBF16のKVより平均8.5ポイント精度が低く、TurboQuantは256K文脈でBF16より10倍以上遅い。

本論文のBitDecoding-FP4は、ネイティブFP4注意で生じる三つの誤差源を個別に潰す。クエリ量子化の誤差、ソフトマックス確率のスケールアンダーフロー、キーのチャネル外れ値である。さらにカーネル側では、行列積が速くなるほど相対的に重くなるソフトマックスを転置配置で並列化し、確率の量子化をその削減処理へ融合する。

**代表結果:** 密モデルとMoEモデル、GQAとMLAにわたる評価で、NVFP4版はBF16のKVとの平均精度差が0.5ポイント以内、MXFP4版でも1ポイント以内に収まる。エンドツーエンドではNVIDIA B300上でQwen3-4BとQwen3-30B-A3Bを使い、BF16のKVに比べてピークサービングスループットが2.4倍から3.0倍、KVキャッシュ容量は最大3.5倍小さいと報告される。

## 問題設定

ネイティブFP4注意では、クエリ、キー、確率、バリューの四つの被演算子すべてが4ビットのブロック形式でなければならない。ここで三つの誤差が重なる。第一にクエリの丸め誤差は数千トークンへ放送される。論文の分解では、NVFP4キーに対してNVFP4クエリがロジット誤差の60パーセントを占め、キー自身より大きい。第二に、オンラインソフトマックスの確率は長文脈では大半が極小になり、ブロック最大値から決まるE4M3スケールが表現下限を割り込む。著者らの観測では長い推論トレースで約90パーセントのブロックがゼロスケールになり、そのトークンは事実上参照されなくなる。第三にキーには少数の固定チャネルに大きな外れ値が集中するが、テンソルコアの都合でキーはトークン単位にチャネル方向へ量子化せざるを得ず、一つの外れ値がブロック全体のスケールを膨らませて通常チャネルの分解能を潰す。

システム側の問題も独立にある。従来のカーネルはスレッドを行方向へ割り当てるため、デコードではクエリヘッド数が少なく大半のスレッドが遊び、少数のスレッドがキー方向へ直列に走査する。KVの精度を下げるほど行列積は速くなるのに、ソフトマックスが上限を決めてテンソルコアが空転する。逆量子化型カーネルでは、FlashInfer-XQAで逆量子化がカーネル時間の7パーセントから21パーセントを占めることも示される。

## 手法のあらまし

処理はキー登録時とデコード時の二段に分かれる。キーは静的に較正したチャネル平均を引いて平滑化し、ハダマード回転で外れ値を分散させ、ブロックごとに再構成誤差が小さいスケールを探してFP4化してキャッシュへ置く。デコード時はクエリにも同じ回転を掛け、通常の量子化結果と、その残差をもう一度量子化した結果の二本で表す。注意計算はタイルごとに進み、二本のクエリとキーの行列積をFP32で合算し、転置ソフトマックスで確率を求め、その場で確率をFP4化してバリューとの行列積へ渡す。直近トークンと先頭16トークンのアテンションシンクはBF16のまま同じ起動の中で処理し、ページが満杯になった直近分はFP4ページへ昇格させる。

## 手法

### 1. 二重残差クエリ量子化 — 残差をもう一本のFP4で表す

この機構が観測するのは回転後のクエリであり、保持する状態は一本目の量子化クエリと、その再構成値と元のクエリの差である残差を量子化した二本目という、二組のブロックとスケールである。選択されるのは追加の近似精度であり、ロジットは二本それぞれとキーとの行列積の和として計算される。これにより減るボトルネックはクエリ丸めが全キーへ放送される誤差であり、測定ではロジット誤差に占めるクエリ寄与が60パーセントから1パーセントへ下がる。平滑化だけの代替案では20パーセントが残り、MXFP8クエリでも5パーセントが残るため、二重残差の優位が示される。追加で消費する資源は二本目の行列積だが、後述の積み重ねにより単一の行列積へ畳まれる。誤った場合の挙動として、残差自体も4ビットで丸められるため誤差はゼロにはならず、残りの1パーセントとキーの誤差が精度の下限を決める。

### 2. アンダーフロー配慮型の確率スケーリング — 小さい確率をゼロにしない

この機構が観測するのは各ブロックの確率最大値であり、保持する状態はブロックごとのスケール最大値の選択結果である。処理は二つある。一つ目は確率へ定数8を掛ける操作を、オンラインソフトマックスの指数部へ対数の形で畳み込み、追加の乗算なしにスケールをE4M3の表現範囲へ持ち上げることで、正規化で相殺される。二つ目は小さいブロックではスケール最大値を6ではなく2にし、スケールを3倍へ引き上げてサブノーマル領域の誤差を均す。閾値は小さい較正データでオフラインに決める。これによりアンダーフローの下限は従来比で24倍低い位置まで下がり、長文脈の検索精度が回復する。追加費用はブロック最大値への単一の述語判定だけである。失敗条件として、MXFP4ではスケールが2の冪でアンダーフローしないためこの機構は不要であり、論文でもMXFP4版では省略される。

### 3. 外れ値配慮型キー量子化 — 平滑化と回転とスケール探索

この機構が観測するのはキーのチャネル統計であり、保持する状態はヘッドごとに8件のプロンプトでオフライン較正した静的なチャネル平均である。処理は、平均を引く静的平滑化、正規化ハダマード回転による外れ値の全座標への分散、ブロックごとのスケール候補探索の三段である。NVFP4ではスケール最大値6と4の候補から、MXFP4では標準スケールと次の2の冪から、再構成誤差が小さい方を選ぶ。これにより減るボトルネックは、トークン単位スケーリングで一つの外れチャネルが他チャネルを潰す誤差である。追加費用は登録時の前処理だけであり、デコード時のキーは既に変換済みである。誤った場合の挙動として、較正分布から外れた入力では静的平均がずれて平滑化の効果が弱まる可能性があり、論文はこの感度を主評価では分離していない。

### 4. 転置ソフトマックスと積み重ねクエリ行列積 — ソフトマックスを並列化する

この機構が観測するのはタイル内のスコア行列であり、従来と逆にキーをMMAタイルの行へ割り当て、列方向のソフトマックスを取る。保持する状態はレジスタ上のキー別スコアであり、削減はワープ内のバタフライシャッフルで並列に進み、ブロック最大値がその過程で得られるため確率のブロック最大値の追加走査が要らない。確率スケーリングの規則もこの場へ融合され、各スレッドが自分の確率をそのままE2M1へ丸める。二重残差については、二本目のクエリを行列積タイルのゼロ埋め行へ積み重ね、ブロック単位で別スケールを持てる性質を使って一回の狭いFP4行列積で両方の積を取り、ソフトマックス直前でFP32合算する。これにより精度レシピ全体の追加費用は4パーセント以内に収まるとされる。追加で消費する資源は共有メモリ上の横断削減と制御カーネルであり、資源不足時の挙動として、ページ型キャッシュのメタデータはデバイス側制御カーネルが管理し、ホスト同期なしでCUDAグラフとも両立させる。

| 構成要素 | 入力・観測 | 具体的な動作 | 改善対象 | 主なトレードオフ |
|---|---|---|---|---|
| 二重残差クエリ量子化 | 回転後のクエリと残差 | 二本のFP4で表し積を合算する | クエリ誤差の放送 | 追加の行列積を積み重ねで吸収 |
| 確率スケーリング | ブロック確率最大値 | 指数部へ定数を畳みスケール最大値を切り替える | 小確率のゼロ化 | 較正済み閾値への依存 |
| キー量子化 | キーのチャネル統計 | 平滑化、回転、スケール探索 | 外れ値による分解能喪失 | オフライン較正が必要 |
| 転置ソフトマックス | タイル内スコア | キー方向へ並列削減し確率量子化を融合 | ソフトマックスの直列処理 | カーネル実装の複雑さ |

## 評価

結論は、ネイティブFP4でも誤差源を分解して個別に対策すればBF16並みの精度を保てること、そして精度対策をカーネルへ融合すれば対策込みでも高速化が残ることである。主表ではQwen3-4Bの平均精度がBF16の67.69に対してNVFP4版67.27、MXFP4版66.70であり、FP8の66.21を4ビット側が上回る。対照的に素朴なNVFP4は59.19、TurboQuantは62.56にとどまる。256K文脈のTPOTはBF16の7.74ミリ秒に対してNVFP4版4.28ミリ秒で1.81倍の高速化であり、TurboQuantは94.46ミリ秒と桁違いに遅い。Qwen3-30B-A3Bでも平均72.74対73.15、TPOTは1.53倍である。

大規模モデルでも傾向は保たれる。355BのGLM-4.7では200KトークンのKVが71.88GiBから20.27GiBへ3.5倍小さくなり精度差は0.4ポイント以内、770BでMLAを使うHy4-previewでは100万トークンのKVが90.46GiBから34.41GiBへ減り精度差は0.12ポイント以内とされる。強化学習のロールアウトでも、素朴なNVFP4が大きく劣化する一方で提案法はBF16を追跡する。カーネル単体では128K文脈でB300上最大2.99倍、RTX PRO 5000上最大4.01倍であり、精度レシピの費用は4パーセント以内と除去実験で分離される。除去実験では、二重残差とキー対策がMXFP4の利得を担い、NVFP4では二重残差が差の大半を回復し、確率スケーリングがRULERの検索を回復させると報告される。

読み方として注意すべきは、スループットの2.4倍から3.0倍が容量節約で同時実行数が増える効果を含むピーク値である点である。単一リクエストの遅延改善は1.53倍から1.81倍であり、両者を混同しない。評価はBlackwell世代の二機種に限られ、旧世代GPUではネイティブFP4自体が使えない。

## 既存研究との差

素朴なNVFP4システムとの差は、量子化レシピ自体を注意の誤差構造に合わせて作り替えた点にある。TurboQuantとの差は、コードブック参照を避けテンソルコアのブロック形式のまま精度を確保した点であり、速度差が桁で現れる。先行のBitDecodingとの差は、逆量子化型からネイティブFP4実行へ進み、ソフトマックス側のボトルネックまで設計対象に含めた点にある。SageAttention3などプリフィル向けのFP4注意との差は、キャッシュ済みKVからの自己回帰デコードを対象にする点である。

## 限界・実装状況

限界は、評価がBlackwell世代GPUと特定モデル群に限られる点、キーの静的平均と確率スケーリングの閾値にオフライン較正が要る点、MLAでは疎な有効窓のため遅延改善ではなく容量改善が主になる点である。実装はvLLMへ統合され公式コードが公開されているが、上流へのマージ状況は論文からは読み取れない。近似は量子化によるもので無損失ではなく、BF16との差は小さいが残る。較正データと実ワークロードの分布が大きくずれた場合の精度は未評価である。

## 一般的な実装上の含意

低ビット化では、誤差を総量で見るのではなく被演算子ごとに分解し、支配的な誤差源へ個別に対策を割り当てることが効く。行列積を速くするとソフトマックスのような周辺処理が新しい上限になるため、量子化方式とカーネル配置は最初から一体で設計すべきである。スケールのアンダーフローのように形式の表現下限が作る失敗は、アルゴリズム側の持ち上げで安く回避できる場合がある。
