# ClusterKV: Manipulating LLM KV Cache in Semantic Space for Recallable Compression

## 概要

自己回帰復号では、過去トークンのキー・値を鍵値キャッシュ（KV cache）へ保持し、新しいトークンの注意計算で読み出す。文脈が32K、128Kと伸びるとKV容量はほぼ線形に増え、復号時には過去KVを大量に読み込むためメモリ帯域も律速になる。既存圧縮には、不要と判断したトークンを永久削除する方式と、GPU外へ退避したKVを固定ページ単位で呼び戻す方式がある。前者は後で重要になった情報を復元できず、後者は意味的に無関係なトークンまで同じページとして転送する。

ClusterKVは、KVを「テキスト上の隣接位置」ではなく「意味的な近さ」でクラスタ化する。各クラスタの代表を索引し、現在のクエリと近いクラスタを選択して、そのクラスタに属するKVだけを高速側キャッシュへ呼び戻す。これにより、過去の任意位置にある重要トークンを再取得できる一方、ページ単位の過剰転送を避ける。

32K文脈の各種タスクでは、GPU側で実際に注意へ使うKVを1K～2Kトークン相当へ抑えても精度劣化を小さく保ち、フルKVキャッシュと比べて遅延を最大2倍、復号スループットを最大2.5倍改善した。論文はクラスタリング、選択、索引、キャッシュ管理を単なるアルゴリズムではなく一体のシステムとして実装し、選択処理のオーバーヘッドが全体を食い潰さないことも確認している。

## 問題設定

非再呼出し型のKV圧縮は、観測時点で重要度の低いトークンを捨てる。長文書では、序盤では不要に見えた情報が後半の質問で突然必要になるため、この不可逆性が精度低下につながる。再呼出し型のInfiniGenなどは過去KVを外部階層から戻せるが、位置ベースのページ粒度では、必要トークンが少数でもページ全体を転送する「断片化」が起きる。

ClusterKVは、選択粒度を意味クラスタへ変えることでこの二者択一を崩す。必要な情報を永久削除せず、かつ固定ページの不要データを一緒に運ばないことが目的である。主要な設計課題は、クラスタリング自体の費用、復号ステップごとの関連クラスタ探索、GPU側の限られたKV予算への配置を、フル注意より軽く保つことである。

## 手法

### 意味クラスタの構築

プリフィルで得たキー表現を意味空間上でクラスタ化し、近いトークンを同じグループへまとめる。位置が離れていても意味的に近ければ同一クラスタへ入り得るため、固定ページの境界に縛られない。クラスタには代表情報を持たせ、復号時に全トークンを毎回走査しなくても関連候補を絞れるようにする。

クラスタ化は追加コストを生むため、著者実装はGPU向けの近似探索・クラスタ処理を使う。公開実装はRAFT等を利用し、長文脈のプリフィル時にクラスタを準備する。論文の分解評価ではクラスタリング費用はプリフィル時間の一部に収まり、全推論時間に対する選択・管理費が小さいことを示す。

### クエリ依存のクラスタ選択と再呼出し

各復号ステップで現在のクエリ表現を使い、関連するクラスタを選択する。選ばれたクラスタに属するトークンのKVを注意計算へ供給し、重要でないクラスタは高速側KV予算から外す。これにより、直近窓だけを見る方式と違い、文脈の遠い位置からも意味的に関連する情報を呼び戻せる。

選択結果はキャッシュ管理へ接続される。GPU側には1K～2Kトークン相当など固定の作業予算を設定し、その範囲へ選択クラスタを載せる。アクセスされるクラスタが変われば内容を入れ替えるため、圧縮は不可逆削除ではなく「低速側に残し、高速側へ必要時に戻す」階層型動作になる。

### 索引とキャッシュを含むシステム統合

単純なクラスタ検索は、毎トークンで全履歴を走査すると長文脈ほど高価になる。ClusterKVは索引を使って選択対象を絞り、キャッシュされたクラスタの再利用を組み合わせる。これにより、履歴長とともに選択費用が直線的に増える方式を避ける。

この統合が重要なのは、KV圧縮では「注意に読むKVが少ない」だけでは高速化にならないからである。選択、索引探索、転送、キャッシュ置換の総費用が削減したメモリ読み出しより大きければ逆効果になる。ClusterKVはこれらをGPU向け実装としてまとめ、実測遅延とスループットで利得を確認する。

## 評価条件

| 項目 | 条件 |
|---|---|
| 文脈長 | 最大32Kを中心に評価 |
| KV作業予算 | 1K～2Kトークン相当を代表条件として使用 |
| 比較対象 | フルKV、Quest、InfiniGen等の圧縮・再呼出し方式 |
| 品質 | 長文脈QA、検索・推論系タスク、PG19言語モデリング等 |
| 効率 | 復号遅延、復号スループット、選択/クラスタリングの内訳 |
| 公開実装 | CUDA、RAFT、FlashAttention、FlashInferを利用 |
| 再現例 | Llama 3 8B向け効率測定スクリプトを公開 |

## 主要結果

| 条件 | 指標 | 結果 | 読み取れること |
|---|---|---|---|
| 32K文脈、1K～2K KV予算 | 精度・出力品質 | フルKVに近い品質 | 16～32分の1規模の作業KVでも重要情報を再取得できる |
| 長文脈復号 | 遅延 | フルKV比で最大2倍高速化 | 注意時のKV読み出し削減がシステム全体の遅延へ反映 |
| 長文脈復号 | スループット | 最大2.5倍 | 小さい作業KVによりメモリ帯域律速を緩和 |
| PG19等 | 困惑度 | フルKVに近い傾向 | 意味クラスタ選択が言語モデリング品質を保つ |
| システム内訳 | クラスタ/選択費 | 全体に対して小さい | 圧縮のための検索費が高速化を相殺しにくい |

## 既存研究との差

SnapKVやQuestのような非再呼出し型方式は、保持対象を一度決めると捨てたKVを後から使えない。InfiniGenのような再呼出し方式はこの不可逆性を解消するが、位置ページを単位とするため、必要トークンがページ内に散在すると不要なKVも転送する。ClusterKVは再呼出し可能性を保ったまま、転送・選択単位を意味クラスタへ変更する点が差である。

また、アルゴリズムだけでなくクラスタリング、索引、選択、キャッシュをまとめて実装し、GPU上の実測速度まで評価している。これは「注意計算量が減る」という理論値だけでなく、検索オーバーヘッドを含めて得になるかを検証するためである。

## 限界

クラスタリングと索引は追加状態を必要とし、プリフィルにも前処理費用を加える。意味クラスタの品質が悪い場合、関連トークンが別クラスタへ分散し、限られたKV予算で取りこぼす可能性がある。また評価は主に32K級文脈であり、128K～100万トークン級で索引更新・転送が同じ割合で収まるかは別途検証が必要である。

ClusterKVはモデルのKV生成量そのものをなくすわけではなく、保持階層と注意へ供給する集合を制御する方式である。したがって、外部メモリ容量・転送帯域が極端に小さい環境や、ほぼ全履歴へ均等に注意するワークロードでは利得が縮む可能性がある。
