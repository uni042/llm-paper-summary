# Not All Heads Matter: A Head-Level KV Cache Compression Method with Integrated Retrieval and Reasoning

## 概要
KVキャッシュ圧縮の多くは、各層でどのトークンを残すか、あるいは層ごとにどれだけ予算を与えるかを決める。しかしMulti-Head Attentionの各ヘッドは同じ役割を持つとは限らず、長文脈から特定情報を探すヘッドと、その情報を推論へ使うヘッドの重要度は異なる。HeadKVはこのヘッド間異質性をKV予算配分へ利用する。

HeadKV-Rは検索能力の高いヘッドを優先し、HeadKV-R2は検索に加えて文脈情報を使った推論能力を測る。Llama-3-8B-Instruct、Mistral-7B-Instruct、LongBench、LooGLE等で、KV size 64/128の厳しい条件ほど既存のSnapKV、PyramidKV、Ada-SnapKVを上回る。代表結果では元KVの約1.5%だけを保持しながら文脈QAで完全KVの97%の性能を維持する。

## 問題設定
層単位の予算配分は「この層全体が重要」という粒度であり、同じ層内のヘッド差を利用しない。ところが長文脈能力の機構分析では、特定位置の情報を検索するretrieval headが一部に集中することが知られている。均等予算では重要ヘッドにも不要ヘッドにも同量のKVを与え、厳しい予算ほど損失が大きい。

さらに検索能力だけを指標にすると、「答えに必要な文を見つける」能力は測れても、その文を他の条件と組み合わせて推論する能力を十分に表せない。HeadKV-R2はこの検索と推論の差を圧縮指標へ取り込む。

## 手法
### ヘッド単位予算
総KV予算を注意ヘッドごとに分配する。重要度の高いヘッドへ多くの過去KVを残し、重要度の低いヘッドはより強く圧縮する。各ヘッド内でのトークン保持は既存のKV選択機構と組み合わせられるため、HeadKVの主な変更点は「予算をどこへ配るか」である。

### HeadKV-R
検索用の評価から各注意ヘッドが長文脈中の根拠位置へ注意できる度合いを測り、retrieval headを同定する。そのスコアをヘッド重要度として使い、検索能力の高いヘッドへ大きなKV予算を割り当てる。これにより、全ヘッドを同じ圧縮率にするより長距離情報を保持しやすい。

### HeadKV-R2
文脈QAでは根拠を見つけるだけでなく、複数情報を統合して答える必要がある。R2では検索のみのスコアを拡張し、文脈推論能力を含むヘッド重要度を推定する。検索は強いが推論への寄与が小さいヘッドと、最終回答形成に必要なヘッドを区別し、厳しいKV予算を後者にも配る。

## 評価
|項目|内容|
|---|---|
|モデル|Llama-3-8B-Instruct、Mistral-7B-Instruct|
|データ|LongBench、LooGLE、長文脈能力評価|
|比較|SnapKV、PyramidKV、Ada-SnapKV等|
|厳しい予算|KV size 64 / 128|
|主指標|長文脈QA・検索/推論タスク性能|

|条件|結果|
|---|---|
|Llama-3-8B-Instruct、KV size 128|HeadKV-R2平均32.00、Ada-SnapKV 28.52、SnapKV 26.43、PyramidKV 26.20|
|代表的文脈QA|約1.5%のKV保持で完全KVの97%性能|
|傾向|KV予算が小さいほどヘッド単位配分の差が顕著|

この結果は単にキャッシュ量を減らした効果ではなく、同じ小さな予算をどのヘッドへ割り当てるかが品質を左右することを示す。特にR2が検索だけでなく推論能力を扱うため、単純なneedle retrieval以外の長文脈QAでも優位になる。

## 既存研究との差
SnapKVは観測窓の注意パターンから重要トークンを選び、PyramidKVは層ごとに異なる予算を与える。HeadKVはさらに細かい注意ヘッド単位へ予算配分を下ろす。Retrieval Head研究の機構分析を、実際のKVメモリ配分へ利用し、R2では検索能力だけでは不足する推論寄与まで含める点が差である。

## 限界
ヘッド重要度を事前に推定するための評価が必要で、任意タスクへ完全にオンライン適応する方式ではない。検索・推論以外にもコード、数学、安全性など別機能へ重要なヘッドがあり得る。主評価はLlama-3-8B-InstructとMistral-7B-Instructを中心としており、より大規模なモデルや異なる注意構造で同じ重要度分布になる保証はない。
