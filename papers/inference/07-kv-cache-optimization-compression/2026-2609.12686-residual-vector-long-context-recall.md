# Residual Vector-based Reconstruction as Long-Context Recall Regardless of Context Window Size

> 長文書を事実単位の外部残差ベクトルへ変換し、質問時にFFN活性で選択注入して元トークン/KVなしに事実を再構成することで、文書長にほぼ依存しないGPU記憶量で長文脈recallを実現する。
## 書誌情報
- **著者**: MyungHoon Ryu, XinYu Piao, Jong-Kook Kim
- **著者・所属**: 一次資料記載の著者所属。
- **公開**: arXiv:2609.12686v1
- **種別**: プレプリント
- **対象**: 長文脈recall、残差ベクトル、FFN活性メモリ、KVキャッシュ削減、外部記憶、訓練不要
- **実装**: 凍結モデルにFFN活性取得・残差最適化・応答時フックを追加する訓練不要方式。公開コードURLはarXiv一次ページでは確認できない。
## 概要
本手法は、長文書を固定サイズ窓で読み、将来の質問を知らない状態で事実文を抽出し、凍結LLMのFFN層における活性をアドレスとして、各事実を再生成する残差ベクトルを外部保存する。元文書トークンとKVキャッシュは記憶化後に破棄でき、質問時には密・語彙検索で関連アンカーを選び、対応する再現プロンプトの活性と保存キーのコサイン類似度が閾値を超えたときだけ残差を層出力へ注入して事実文を決定的に再構成する。記憶量は文書長ではなく固定事実予算に従うため、200万トークンまでGPUメモリをほぼ一定に保ち、3モデルの単一事実QAで50〜80%を達成した一方、比較した訓練不要方式はゼロまたはほぼゼロまで低下した。

論文固有の着想は、長期保持する事実を短縮トークンやKVではなく『FFN活性でアドレス指定される外部残差ベクトル』へ変換する点にある。各事実にアンカーと番号からなる専用recall keyを作り、固定recall promptを凍結LLMへ入れたときの特定FFN層down-projection入力活性を保存キーにする。そのキー位置で層出力へ加えるd_model次元残差だけを事実文の再生成損失で最適化し、重み自体は一切変更しない。質問時には検索で候補事実を絞った後、同じpromptから再現された活性が保存キーと十分類似するときだけ対応残差を注入し、元の事実文を決定的に再構成する。これにより文書全体のトークン/KVを保持する必要がなく、外部記憶を削除すれば基底モデルも完全に元へ戻せるという、KV圧縮・RAG・知識編集のいずれとも異なる可逆な表現レベル記憶を実現する。

代表結果として、200万トークン単一事実QA精度はBABILong QA1、Phi-3.5-mini/Qwen3-4B/Llama-3.1-8Bで比較した訓練不要方式は0またはほぼ0に対して3モデルで50〜80%。事前学習文脈窓を大幅に越えても、元トークンを保持せず選択事実を再構成できる。
## 問題設定
長文脈LLMの直接推論では、入力が長くなるほど各トークンの注意キー／値を保持するKVキャッシュが線形に増え、モデルが事前学習で対応した文脈窓を越える文書は一度に処理できない。位置補間や長文脈微調整は対応窓を伸ばせるが追加最適化を要し、推論時にトークン単位状態を保持するという根本的な記憶量増加は残る。H2OやSnapKVのようなKV選択、ストリーミング、プロンプト圧縮はGPU状態を減らす代わりに過去トークンや細部を捨てるため、将来どの事実が質問されるか未知の長期記憶では必要証拠を失いうる。RAGは原文を外部へ残すので情報自体は保持できるが、文書アーカイブと索引が入力長に応じて増え、質問時の検索漏れで回答に必要な文がコンテキストへ入らない。したがって課題は、モデル重みを再学習せず、元文書トークンとKVを記憶後に破棄しながら、将来質問に必要な選択事実を高忠実度で再現し、GPU常駐量を入力長ではなく固定予算で上限化することである。
## 新規性
論文固有の着想は、長期保持する事実を短縮トークンやKVではなく『FFN活性でアドレス指定される外部残差ベクトル』へ変換する点にある。各事実にアンカーと番号からなる専用recall keyを作り、固定recall promptを凍結LLMへ入れたときの特定FFN層down-projection入力活性を保存キーにする。そのキー位置で層出力へ加えるd_model次元残差だけを事実文の再生成損失で最適化し、重み自体は一切変更しない。質問時には検索で候補事実を絞った後、同じpromptから再現された活性が保存キーと十分類似するときだけ対応残差を注入し、元の事実文を決定的に再構成する。これにより文書全体のトークン/KVを保持する必要がなく、外部記憶を削除すれば基底モデルも完全に元へ戻せるという、KV圧縮・RAG・知識編集のいずれとも異なる可逆な表現レベル記憶を実現する。
## 手法
### 手法のあらまし
記憶化段階では文書を固定サイズの窓で走査し、固有表現、数値、識別子などを含む文を高再現率フィルタで候補化する。凍結LLMが短いアンカーを提案し、拒否時は決定的な文スパンを使って、アンカーe、同一アンカー内番号j、原文事実v、元位置oから事実レコードを作る。保持数Bはアンカー数に対する情報予算と、K個の保存層×層当たり容量Cの小さい方で上限化し、同一アンカーでは新しい事実を優先する。保持事実を、事前のrecall probeで選んだK個のFFN層へアンカー順と事実番号に基づく巡回方式で分散する。各事実について固定文型『Recall the fact about {key}:』を入力し、割当層のdown projection入力で最終key トークンの活性を取得・正規化して外部キーとする。同時にモデル重みを凍結したまま、割当層出力へ加えるd_model次元残差δだけを、事実文vの負の対数尤度が下がるよう最適化する。最初の40段階はteacher forcing、再生成に失敗した事実は生成済みprefixを使って20段階追加調整し、最終残差r、正規化活性キー、層番号、元位置、長さを外部保存する。元文書と処理中KVはその後破棄できる。質問時はアンカーごとに保存した文書表現と語彙表現をそれぞれ検索し、相互順位融合で最大5アンカーを選ぶ。選択アンカーを最大24事実へ展開し、各事実の固定recall promptを再生する。割当FFN層の各トークン位置で現在活性xと保存キーのコサイン類似度を計算し、最大類似度がθ=0.6を超えた場合だけゲートを開く。β=50のsoftmaxで同層キー間の勝者をほぼtop-1化し、その残差rをdown projection出力へ加える。貪欲復号なので同じ事実は毎回同じ文へ再構成される。最後に再構成事実を元位置順に並べ、元質問とともに通常生成へ渡して回答する。

### 問い合わせ非依存の事実抽出と固定容量配分
将来質問を使わず、固定窓で文書を一回走査して固有表現・数値・識別子を含む事実候補を拾い、短いアンカー、同一アンカー内の事実番号、原文事実文、元文書位置を記録する。保持予算Bは、抽出アンカー数に一アンカー当たり保持深度を掛けた情報上限と、K個の保存層に層当たり名目容量Cを掛けた物理上限の小さい方で決まる。アンカー数が予算内なら各アンカーから最新事実を均等に残し、アンカー数自体が予算を超える場合はモデル検証済み事実数などでアンカーを順位付けして先頭B個の最新事実を保持する。この選択を残差符号化前に行うため、文書が何百万トークンへ伸びても保存事実数NはBを越えず、将来質問を知らない状態でもGPU外部記憶の容量を明示的に固定できる。

### FFN活性アドレス付き残差符号化
各事実を選択済みFFN層へ割り当て、固定recall promptの最終key トークンでdown-projection入力活性を取得して正規化キーとする。モデル重みを凍結したまま、その層出力へ加えるd_model次元残差だけを事実文の負対数尤度で最適化する。40段階のteacher forcing後に自由生成を検査し、失敗時はモデル生成prefixを使って20段階追加調整する。保存物は活性キー、残差、層番号、元位置、長さであり、処理済み原文トークンとKVキャッシュは破棄できる。

### 保存層分散とコサイン連想ゲート
held-out recall probeで各FFN層の残差注入後の再構成品質を測り、保存に適したK個の層だけを選ぶ。アンカー抽出順と同一アンカー内事実番号の和をKで剰余化する巡回割当を使い、一つの層へ連想記憶が集中して容量飽和するのを避ける。応答時は割当層の全トークン位置で現在活性xとその層の保存キー集合をコサイン比較し、最大類似度がθ=0.6を超えた場合だけゲートを開く。β=50のsoftmaxで同層候補の最良キーへ重みを強く集中させ、その残差をdown-projection出力へ加える。したがってルーティングで候補になっただけでは注入されず、活性アドレスが一致した生成位置だけで記憶が発火するため、同一層に複数事実を格納しても誤混入を抑えられる。

### 密・語彙融合ルーティングと事実再回答
記憶化時にアンカー、保持事実、事実から生成した言い換え質問をまとめたルーティング文書をアンカーごとに作り、質問時には密意味検索と希少な名前・識別子に強いIDF型語彙検索を並列に行う。両順位を相互順位融合し、質問中にアンカーが逐語一致する場合はそれを優先し、それ以外は首位融合得点の0.6以上を満たす最大5アンカーを選ぶ。選択アンカーを最大24事実へ展開し、各事実を残差注入で独立に再構成する。復元文は保存した元位置順に整列し、アンカータグと元質問を含む短い回答promptへ渡す。これにより質問ごとに長大な原文を再検索・再投入せず、ルーティングされた少数の高忠実度事実だけを回答モデルへ供給し、応答時の文脈長とKV量も選択事実量へ制限できる。

### 全体のデータ／制御の流れ
記憶化は文書窓処理→事実抽出→層割当→残差最適化→外部索引保存で構成され、応答は質問ルーティング→ゲート付き残差注入による事実再構成→再構成事実を用いた回答生成の三段階となる。モデル本体は全段階で凍結される。
## 評価条件
- **ハードウェア**: GPU上での凍結LLM推論と残差符号化
- **比較対象**: 通常のfull-context/closed-book条件、ストリーミング・KV選択系訓練不要方式、プロンプト圧縮、Chunk RAG等の検索方式
3種類の凍結命令調整モデルで、事前学習文脈窓内から最大200万トークンまでの長文脈事実recallを評価する。単一事実、二事実合成、RULER系質問、再構成容量、事実位置、GPUメモリを測定し、訓練不要の長文脈方式と比較する。
## 主要結果
提案法は200万トークンのBABILong単一事実recallで3モデルすべて50〜80%の精度を維持し、比較した訓練不要方式がゼロまたはほぼゼロへ低下する領域でも回答可能だった。元文書を固定窓で処理後に破棄し、保存状態を固定事実予算に制限するため、入力長の増加に対してGPUメモリはほぼ一定で、測定した保存事実メモリは全条件で1GB未満だった。再構成は同じ保存文を決定的に出す一方、最終QA精度は抽出、ルーティング、再構成、回答推論の積で決まり、アンカー対応不足が主要制約となる。

- 200万トークン単一事実QA精度 / 3モデルで50〜80% (比較対象: 比較した訓練不要方式は0またはほぼ0; 条件: BABILong QA1、Phi-3.5-mini/Qwen3-4B/Llama-3.1-8B) — 事前学習文脈窓を大幅に越えても、元トークンを保持せず選択事実を再構成できる。

- 保存事実メモリ / 測定全条件で1GB未満 (比較対象: KV/原文保持は文脈長に比例; 条件: 固定事実予算の外部キー+残差保存) — 文書長ではなく保持事実数とベクトル幅で記憶量が決まる。

- GPUメモリの文脈長依存 / 入力長増加に対しほぼ一定 (比較対象: 通常KVキャッシュは線形成長; 条件: 記憶化後に元文書とKVを破棄) — 長文書全体を同時にGPUへ常駐させないため、2M条件まで拡張できる。

- 再構成挙動 / 選択された事実は貪欲復号で決定的に再生成 (比較対象: 検索断片や損失圧縮は内容が欠落しうる; 条件: 活性キー類似度ゲート+保存残差) — 保存された文単位の内容を再現し、回答段階へ明示的な証拠文として渡せる。

### 負の結果・境界条件
- 固定事実予算のため抽出されなかった情報は回収できず、複数事実合成は単一事実より難しい。段階分析では、必要事実が保存されていても質問とアンカーの対応が弱いとルーティングに失敗する。また保存層の連想容量や残差符号化が限界に達すると再構成できない。長文脈側のサンプル数も小さく、2M条件の統計的不確実性は大きい。

### 結果の読み方
長文脈メモリを『すべてのトークンを後で注意できる状態』として保持する代わりに、『選択事実を必要時に元文へ戻せる外部パラメトリック表現』へ変換する。KV圧縮・階層化とは異なり、記憶表現そのものをトークン系列からモデル活性空間へ移す設計である。
## 品質への影響
保持された事実の再構成忠実度は高いが、固定容量選択による情報非保持とルーティング失敗がQA品質を制約する。モデル重みは凍結されるため外部記憶を削除すれば元モデルへ完全に戻る。
## 既存研究との差
- **KVキャッシュ圧縮との差**: SnapKV/H2O等はトークンに対応するKVの一部を残すが、本手法は元トークン/KVを記憶化後に破棄し、事実文を再生成する外部残差ベクトルへ変換する。保存単位が注意状態ではなく事実表現である。
- **RAGとの差**: RAGは原文チャンクと索引を文書長に応じて保存し、質問時に原文を取得する。本手法は固定予算の事実だけを残差へ符号化し、原文なしに文を再構成するため保存量を文書長から切り離す一方、抽出時の選択損失を受ける。
- **モデル編集との差**: 知識編集は重み自体を書き換えて知識を恒久化する。本手法はモデル重みを凍結し、外部残差をフックで一時注入するため、記憶エントリを削除すれば基底モデルを完全に元へ戻せる。
- **長文脈微調整との差**: 位置補間やLongLoRAはモデルが一度に扱えるトークン窓を拡張するが、推論時KVの長さ依存は残る。本手法は窓自体を拡張せず、固定窓で事前記憶化して後から必要事実だけを復元する。
## 限界
- **固定事実予算による選択損失**: 保存量を文書長から切り離すため、すべての原文を可逆保持する方式ではない。候補抽出や容量配分で捨てた事実は後の質問で再構成できず、未知の将来質問に対する完全recallは保証されない。
- **アンカーとルーティングへの依存**: 質問時に関連アンカーを密・語彙検索で選ぶため、表現の対応が弱い事実は保存済みでも到達できない。論文の段階分析でも限定的なアンカー対応が選択recallの中心的制約として挙げられる。
- **事実単位・小規模長文脈サンプル**: 強い結果は単一事実recallが中心で、二事実合成は1Mまでである。2M条件はモデルごと数例とサンプル数が小さく、複雑な多段推論や大規模実運用での一般化は追加検証が必要である。
- **記憶化計算コスト**: 各保持事実について残差ベクトルを数十最適化段階で符号化するため、オンラインKV保存より前処理が重い。長大文書で抽出候補が多い場合は、GPU常駐量は抑えられても記憶化時間と総計算量が増える。
## 実装状態
凍結TransformerのFFN層に活性取得と残差注入フックを追加し、事実抽出・層選択・残差最適化・検索索引・回答生成までを実装して3モデルで評価している。追加学習や重み更新は不要。
## 研究上の位置づけ
KVキャッシュ最適化、長文脈圧縮、外部記憶、パラメトリックメモリの境界に位置する。メモリ階層へKVを移すのではなく、長期保持すべき情報を活性アドレス付きベクトルへ変換するため、SSD/CPUオフロード研究に対する表現レベルの代替軸となる。
