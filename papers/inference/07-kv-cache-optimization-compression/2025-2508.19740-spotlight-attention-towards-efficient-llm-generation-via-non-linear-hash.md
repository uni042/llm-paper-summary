# Spotlight Attention：非線形ハッシュで長文脈KVキャッシュを高速検索する

## 概要

Spotlight Attentionは、大規模言語モデル（LLM）の長文脈生成で、過去の鍵・値キャッシュ（KV cache）のうち現在の問い合わせに重要な少数トークンだけを取り出して注意計算を行う方式である。全KVを保持したまま毎回全トークンと内積を取ると、文脈長に比例してデコードのメモリ転送量が増える。そこで問い合わせと鍵を短い二値符号へ変換し、ビット演算で類似候補を検索する。ただし既存のランダム線形ハッシュでは、LLM特有の問い合わせ・鍵の分布に対して検索精度が悪く、長い符号が必要になる。

本研究は、ランダムな超平面で空間を分割する代わりに、小さな多層パーセプトロン（MLP）で非線形の分割境界を学習する。真の注意スコアが上位となるトークン集合と、ハッシュ距離で選ぶ集合が一致するよう順位損失で学習し、層・注意ヘッドごとに128ビットの符号を作る。問い合わせと鍵の符号の距離を専用CUDAカーネルで評価し、必要なKVを集めて疎な注意計算を行う。

著者はMagicPIG型の線形ハッシュで最低720ビット程度必要な条件に対して、128ビットの非線形符号で高い検索品質を得たと報告する。A100単体で512Kトークンに対するハッシュ検索を100マイクロ秒未満とし、通常の全注意デコードに比べ端から端まで最大約3倍のスループットを示した。これは符号化・検索・選択KVへの注意を含む特定条件の測定であり、全モデル・全文脈で常に3倍になるという主張ではない。

## 背景：KVを捨てる方式と検索する方式の違い

長文脈LLMのデコードでは、各新トークンの問い合わせ $q$ が過去の全鍵 $k_i$ と照合され、注意重みで値 $v_i$ を集約する。KVキャッシュが大きいほど読み出し費用が増え、GPUの高帯域メモリ（HBM）上でも帯域律速になりやすい。固定予算のKV削除方式は重要でないと判断したトークンを永久に消すため、後からその情報が必要になっても復元できない。一方、動的KV検索方式は元のKVを保持し、各問い合わせで注意計算へ参加させる候補だけを選ぶ。

Spotlight Attentionは後者を採用する。つまり注意計算で扱うKV量は減らすが、元の全KVを保存するためのメモリ容量そのものが同じ比率で減るわけではない。長いキャッシュに対するメモリ帯域と演算の節約を主眼とする方式である。全KVの保持先、符号配列の追加容量、選択したKVを集める費用が性能を左右する。

## 既存の線形ハッシュがLLMで苦手な理由

局所性鋭敏型ハッシュ（Locality-Sensitive Hashing、LSH）は、類似するベクトルを同じ二値符号へ写しやすくする。ランダムな超平面で符号の各ビットを作る線形ハッシュでは、ベクトルの分布が広く多方向へ散っている場合に空間分割が働きやすい。しかしLLMの問い合わせと鍵はそれぞれ狭い円錐状の領域へ偏り、しかも二つの領域がほぼ直交するという観察がある。

この状況では、ランダムな超平面が問い合わせ・鍵の区別に有用な境界を十分に作れず、異なるベクトルが似た符号へ潰れる。検索精度を上げようとすると多数のビットを必要とし、符号の保存容量、符号化時の射影計算、検索時のビット比較量が増える。先行するMagicPIGは鍵の正規化などで対処するが、問い合わせ側の分布と鍵側の分布を合わせて扱う最適化ではない。

## 手法

### 1. 非線形MLPによる符号化

Spotlight Attentionは、問い合わせと鍵を入力する小型MLPハッシュ関数 $\mathcal H$ を学習し、その出力を二値化して符号とする。非線形変換により、線形ハッシュの超平面では表現しにくい曲がった決定境界を作り、偏った問い合わせ・鍵の分布を区別しやすくする。論文の主要構成では入力・中間・出力が128次元のMLPを使い、層・ヘッドごとに別の関数を用意して128ビット符号を生成する。

同じLLMでも注意ヘッドや層によって問い合わせ・鍵の分布が異なるため、単一の汎用ハッシュ関数を全層へ強制するのではなく、各ヘッドの特徴に合わせる。学習対象はハッシュ関数だけであり、基盤LLMの重み全体を再訓練しない。元のKVに対応する符号を作って保存し、新しい問い合わせを符号化したら短い二値距離で候補を順位付けする。

### 2. 上位集合を直接学習する順位損失

非線形ハッシュをどう学習するかが主要な工夫である。LLMの言語モデル損失をそのまま使うと、基盤モデル全体を通した逆伝播と、非微分な上位K選択の近似が必要になり重い。注意内積の再構成誤差（MSE）を最小化する方式では、重要な上位Kを正しく選ぶことより、重要でない下位候補の相対順位へ学習容量を費やすおそれがある。

そこで真の注意スコアで選んだ上位K集合とそれ以外の集合を教師とし、ハッシュ距離から作る類似スコアが「上位集合の候補は下位集合より高い」となるように学習する。Bradley–Terry型の順位損失を使い、重要集合と非重要集合のペアの順序を直接最適化する。絶対的な内積値を正確に復元する必要はなく、限られた符号長で上位Kを選び当てることへ容量を集中できる。

### 3. ハッシュ検索と選択KVへの注意計算

生成時には新しい問い合わせをハッシュ符号へ変換し、保存済みの鍵符号とのハミング距離をビット演算で比較する。近い符号の鍵を上位K候補として選び、元のKV配列からその位置の鍵・値を集める。最終的な注意計算は選択集合に対して通常の注意重みと値の集約を行う。全KVとの密な注意計算を、短い符号の検索と選択KVへの疎な注意に置き換える構成である。

専用CUDAカーネルは、符号比較のようなビット演算をGPU上で大量に実行できる点を利用する。符号長が短ければメモリ転送量と比較演算が減る一方、検索の精度が悪いと重要なKVを選べず生成品質が落ちる。MLPの学習と順位損失は、この符号長と検索精度の交換条件を改善するためのものである。

### 4. 学習時の計算費用を抑える

著者はBookとarXiv由来の8,192サンプルを均等に使い、基盤モデルの各層の隠れ状態を事前計算して保存する。その後は層ごとのハッシュ関数を独立に訓練できるため、毎回LLM全体を逆伝播する必要がない。主要設定では学習時の削減率を98%に固定し、1エポックの訓練を行う。論文要旨では16GBのGPUメモリを用いて約8時間で学習可能と報告する。

この8時間は学習時の負担を示す値であり、推論の一要求ごとの遅延ではない。層・ヘッドごとの小型MLPは追加重みとして保持する必要があるが、主モデル全体を微調整する方式と比べれば学習対象は限定される。ハッシュ学習に用いるデータ分布と運用時の問い合わせ・鍵分布が大きく異なる場合は、順位選択の品質が落ちる可能性がある。

## 評価

### 実験設定

| 項目 | 論文の設定 |
|---|---|
| 基盤モデル | LLaMA2-7B、LLaMA2-7B-Chat、LLaMA3-8B、Qwen2.5の1.5B・7B・14B |
| 比較方式 | 真の注意スコアのOracle Top-K、線形LSH、Quest、MagicPIG、Spotlight |
| 学習 | Book/arXiv由来8,192サンプル、層・ヘッド別MLP、1エポック |
| 符号長 | Spotlightは128ビット、MagicPIGは少なくとも720ビットを要する比較条件 |
| 主な品質指標 | 上位KV検索の一致度（IoU）、困惑度（PPL）、Needle-in-a-Haystack、LongBench |
| 実行指標 | CUDA検索時間、端から端までの生成スループット |
| 主なハードウェア | 検索・スループット評価にNVIDIA A100を使用 |

原著はKVの永久削除ではなく、選択した部分集合での注意計算を評価する。したがって「98%をpruneした」という実験表現は、そのステップの注意計算から除外した割合として読むべきであり、過去の全KVを物理的に永久削除して98%の保存容量を削減したという意味ではない。

### ハッシュ長・検索精度・生成品質

従来の線形LSHは、問い合わせと鍵の偏った分布を短い符号で区別しにくい。Spotlightは非線形MLPの順位学習によって128ビットで上位集合の検索精度を高める。MagicPIGの最低720ビットとの比較では符号長が5.6倍以上短い。これは符号配列のビット数に関する比較であり、GPU全体のメモリ消費が5.6倍減ったわけではない。

論文表5のQwen2.5-7Bでは、通常生成のPG19困惑度11.112、数学3.833、コード4.951に対し、Spotlightで上位2%のKVを選んだ条件は9.930、3.497、4.645となる。Qwen2.5-14Bでは通常8.416、3.230、4.472に対してSpotlightは8.261、3.196、4.440である。これらの値は低い方が良い困惑度であり、選択的注意が場合によって通常の密な注意よりも低い困惑度を示したという観測である。必ずしも疎化が一般に精度を向上させるという理論的主張ではない。

### 検索カーネルと端から端までの高速化

著者はA100で512Kトークンのハッシュ検索を100マイクロ秒未満と報告し、端から端までの生成スループットが通常デコード比で最大約3倍となる条件を示す。検索の単独時間と、MLP符号化・KVの集約・疎な注意・残りのTransformer演算を含む全生成時間は異なる。短い文脈や小さいバッチでは検索の固定費が利益を相殺し得るため、最大3倍を任意の条件へ外挿しない。

LongBenchでは回答と基準とのROUGE-Lなどを使い、Needle-in-a-Haystackでは長文から埋め込まれた情報を取り出せるかを測定する。これは検索IoUや困惑度とは異なる品質軸である。重要な鍵を上位Kに入れる能力が高くても、生成タスクの評価はモデルと文脈、選択予算に依存するため、複数指標で確認する設計になっている。

### 汎化と除去実験

論文表6ではLLaMA3-8Bのハッシュ学習コーパスを変え、PG19/数学/コードの困惑度を比較する。標準のBook+arXivで8.977/3.621/5.434、C4で8.958/3.631/5.417、GitHub Codeで8.891/3.611/5.393と、学習コーパスが変わっても大きな崩れは見られない。ただし試したコーパスの範囲内の結果であり、任意のドメインへ無調整で適合する保証ではない。

またQwen2.5の1.5B・7B・14Bで上位2%のKVを用いる評価を行い、モデル規模を変えても良好な困惑度を示す。真の注意スコアによるOracle Top-Kは選択品質の上限に近い参照系であり、実運用で同じ費用で利用できる手法ではない。Spotlightの価値は、真の全内積を計算せずに近い集合を安価に選べることにある。

## 既存方式との差とシステム設計上の位置付け

Questはブロック単位でKV候補を絞るため、細かいトークン単位の重要度を取り逃がす場合がある。MagicPIGはトークン単位のハッシュ検索へ進んだが、ランダム線形符号と長いビット列に依存する。Spotlightは非線形ハッシュと順位損失で短い符号でも重要トークンを選びやすくし、専用CUDA実装でビット検索を高速化する。

固定予算のKV削除やオフロードとは最適化対象が異なる。Spotlightは保存済みKVから毎回必要な部分だけを選ぶため、削除によって失われた過去情報を復元する問題を避けられる。一方、保存容量が大きいままなら、全KVをどこへ置くかというメモリ階層設計は別途必要である。長文脈サービングでは、KV保持のためのHBM容量と、生成時に読み出すKVの帯域を分けて考える必要がある。

## 限界・負の結果

学習したハッシュ関数の精度は、問い合わせと鍵の分布が学習データとどの程度似ているかに依存する。層・ヘッド別にMLPを持つため追加のパラメータと符号配列が必要であり、ハッシュ検索後に選択KVを不連続な位置から集める費用も発生する。小さい文脈では密な注意計算の方が単純で高速な可能性がある。

論文は検索上位Kの近似を用いるため、厳密な全注意と同じ出力分布を保証しない。高い検索IoUや低い困惑度は良い指標だが、長い生成での意味的品質や全タスクでの完全一致とは異なる。98%の疎化はその反復で計算に使わない割合であり、全KVの物理保存容量を98%減らすわけではない。最大3倍の高速化と512K検索100マイクロ秒未満も評価ハードウェア・符号長・検索実装の条件に依存する。
