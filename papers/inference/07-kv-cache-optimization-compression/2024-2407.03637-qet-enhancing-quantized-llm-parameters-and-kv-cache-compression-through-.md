# QET: Enhancing Quantized LLM Parameters and KV Cache Compression through Element Substitution and Residual Clustering

## 概要

QET（Quantum Entanglement Trees）は、LLM重みやKV cacheなどの行列を、同じ保存容量の制約下で元の数値に近く復元するための行列量子化手法である。名称にQuantumとあるが量子計算機を使うわけではなく、行列内の要素を局所的に入れ替えて相関構造を作り、列方向のグループ量子化、残差量子化、コードブック圧縮を組み合わせる。原著が最小化するのは主にMSE/MAEなどの行列再構成誤差であり、LLMの文章生成正答率を直接最適化するわけではない。

原著v4の主張は、圧縮比4でLLaMA2の重み行列についてPQのMSEを5.05%まで、K cacheで13.33%、V cacheで11.89%まで減らせるというものである。これはMSEの相対比であり、生成速度5倍、KVメモリを5%にする、モデルの正答率を95%上げる、のいずれでもない。CPUでの量子化・復元時間も測定されるが、GPUサービングの実測トークン/秒は提示されない。圧縮・再構成の数学的性能と推論システム性能を厳密に分ける必要がある。

## 問題設定

量子化対象の行列Xと復元行列X'に対し、同じ保存容量の予算の下で距離を小さくするQuantization Error Minimization（QEM）問題を考える。通常のRTNは要素を独立に丸めるため、近傍要素間の構造を利用しない。PQは複数要素をまとめてコードブック化するが、列やグループ内の要素の順序が復元誤差に影響する。例えば行ベクトル[1,2]と[2,1]を同じグループで表現する場合、異なるコードが必要になるが、並びを整えれば同じ代表ベクトルを使える可能性がある。QETはこの局所的な整列可能性を利用する。

対象は重み、KV cache、画像、グラフ等の一般行列である。ただし、LLM重みの行列要素を任意に並べ替えるだけではモデルの演算と整合しないため、復元時には元の順序に戻すための指示情報を保持しなければならない。この置換情報やコードブックの記憶量も圧縮比の計算に含める。精度の改善だけを示し、置換情報を無料とみなす方式ではない。

## 手法

### 1. 局所要素入替による整列

行列を対象として、隣接要素の交換を繰り返し、局所的に似た値が同じコードブックへ集まりやすい配置を作る。反復回数lを増やすとより広い範囲の局所秩序を作れる一方、前処理コストと置換指示情報が増える。整列した行列を列方向にグループ化し、PQに近いコードブック量子化を行う。復元時は量子化表現から値を戻した後、交換操作の逆を適用する。圧縮率はコードブック・インデックス・交換記録を含めて評価する。

### 2. 残差量子化最適化（RQO）

最初の量子化でX'を得た後、残差R=X-X'を再び量子化して保存する。復元時に残差の復元値を加算し、MSEを減らす。残差段数を増やすと精度が改善しやすいが、同じ容量予算では各段に割り当てるコードブック容量が減り、ある圧縮比以上では効果が小さくなる。原著の標準設定は通常QETと1段の残差QETの組合せで、2段の記憶配分を70%/30%にしている。

### 3. コードブック量子化最適化（CQO）

コードブックは圧縮された行列の代表値を格納するため、圧縮率が高くなると相対的に大きな容量を占める。原著Table 1によると、圧縮比12ではコードブックが記憶量の71.8%、圧縮比4では87.5%を占める条件がある。CQOはコードブック自体をRTNで低bit化し、余った容量を残差や代表値の精度へ配分する。コードブック量子化は再構成誤差を増やす可能性もあるため、RQOと組み合わせた総合効果で評価する。

### 4. 記憶予算と探索

原著は行列サイズn×d、元のbit幅a、圧縮比θ、反復回数l、残差段数r、グループ数m、コードブックbit幅a'、段ごとの容量配分R_iを明示し、容量制約を満たすクラスタ数k_iを二分探索で決める。標準設定はd/m=8、a'=10、l=3、R_1=70%、R_2=30%である。圧縮率の比較において、単に量子化ビット幅だけを揃えるのではなく、置換とコードブックを含む実記憶量を合わせる点が重要である。

## 評価

### データと比較方式

実験はIntel Xeon Platinum 6462C（16 vCPU、64GB RAM）で行われ、対象は合成正規分布行列、LLaMA2重み行列11008×4096、KVQuant由来のK/V cache行列4096×4096、Gist、Wikiなどである。重み行列は32bit要素、KV cacheは16bit要素として扱う。比較対象はRTN、PQ、OPQ、LOPQ、最適化なしVanilla、RQOのみ、CQOのみである。圧縮比2〜16を走査し、MSE/MAEと量子化時間QT・復元時間DQTを評価する。モデルの下流QA正答率や生成遅延を評価する試験とは異なる。

### 実行時間と失敗条件

原著Figure 4ではQETの量子化時間QTは低圧縮比で長く、圧縮率が上がるとクラスタ数が減るため短くなる。VanillaはQETよりQTが短く、精度との交換がある。復元時間DQTは圧縮比を変えても比較的安定だが、Vanillaの方が速い傾向にある。OPQ/LOPQは正方行列で回転行列自体が巨大になり、所定の容量予算では実行不能になる条件がある。グラフ上の正確な時間値を本文にない桁まで推測せず、評価の性質と負の結果を記録する。

### アブレーション

RQOをVanillaに追加すると低圧縮比でQETに近いMSEへ改善するが、高圧縮比では追加コードブックが容量を消費し、代表値のクラスタ数が減るためQETとの差が広がる。CQOはコードブック自体の占有容量を削減する。両者を組み合わせたQETが一般に最小MSEを得るが、処理時間は最短ではない。原著のFigure 5はこの交換関係を示している。高圧縮比13〜16ではVanillaがQETへ近づくケースもあり、最適化の利益が圧縮率により変わる。

## 主要結果と既存研究との差

RTNは要素独立の丸め、PQは列グループ内の代表値共有、OPQは回転による前処理である。QETは要素の局所交換を導入し、残差量子化とコードブックの再量子化を同一の記憶予算に組み込む。既存のGPTQ/AWQは言語モデルの層出力や重要重みを重視するが、QETはより一般的な行列再構成誤差を目的とする。そのため低MSEがそのまま低困惑度や生成品質維持を保証するわけではない。LLM向けに応用するにはモデルの構造、KV更新頻度、オンラインでの置換・復元コストとの整合が必要となる。

## 限界・実装状況

本論文の評価はCPU上で抽出した行列を圧縮・復元する実験であり、実際のGPUカーネルでtoken/s、TTFT、p95、長文脈QAを測ったものではない。KV cacheはトークン生成ごとに更新されるため、複雑な要素置換や多段残差をオンライン適用すると転送・復元オーバーヘッドが大きくなり得る。量子化誤差が小さくてもattention scoreやsoftmaxへの影響は非線形である。実装上の有望性はあるが、GPU推論高速化の実証を伴わないため、完成原稿では「行列圧縮の基礎手法」として位置付ける。
