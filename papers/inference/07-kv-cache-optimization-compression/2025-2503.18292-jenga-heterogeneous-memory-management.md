# Jenga: Effective Memory Management for Serving LLM with Heterogeneity

> 異なる大きさ・依存関係のKV/視覚/Mamba状態を、LCM大ページと層別キャッシュAPIで統合管理し、vLLM比でスループット最大4.92倍、GPUメモリ利用を最大79.6%改善する。
## 書誌情報
- **著者**: Chen Zhang, Kuntai Du, Shu Liu, Woosuk Kwon, Xiangxi Mo, Yufeng Wang, Xiaoxuan Liu, Kaichao You, Zhuohan Li, Mingsheng Long, Jidong Zhai, Joseph Gonzalez, Ion Stoica
- **著者・所属**: Tsinghua University、University of Chicago、UC Berkeley、Independent Researcher。
- **公開**: arXiv:2503.18292v1
- **種別**: プレプリント
- **対象**: KVキャッシュ、異種メモリ割当、PagedAttention、プレフィックスキャッシュ、VLM、Mamba
- **実装**: vLLM v0.6.x上に約4000行のPythonで実装し、既存PagedAttention CUDAカーネルは変更しない。一次資料に独立した公式コードURLは記載されていない。
## 概要
PagedAttentionは各層のKVキャッシュが同じ大きさで、各トークンが全プレフィックスへ依存するという均質Transformerの前提を置く。しかしVLMの視覚埋め込み、スライディング窓、Mamba状態、投機的復号の複数モデルでは、記憶要素の大きさと必要なプレフィックス集合が層ごとに異なる。Jengaは全種類の小ページサイズの最小公倍数を大ページとして共有する二段階アロケータと、層ごとにキャッシュヒット・最終アクセス・追い出し優先度を定義できるプレフィックス部分集合APIを導入する。リクエスト単位で小ページを同じ大ページへ寄せ、解放時に大ページを戻しやすくする。vLLM上約4000行のPythonで実装しCUDAカーネル変更なしで90モデルに対応し、H100でスループット最大4.92倍・平均1.80倍、L4で最大3.29倍・平均1.69倍、KVメモリ浪費を代表条件で38.2%から0.04%へ削減する。

Jengaは互換層とカスタマイズ層からなる二段階メモリ管理を導入する。互換層では各種類の小ページサイズの最小公倍数を大ページサイズに選び、異種メモリ種別間で大ページを融通できる。カスタマイズ層は各層種別の小ページ割当と、プレフィックスのどこが必要かに応じたキャッシュヒット・追い出し規則を提供する。さらに同一リクエストの小ページを同じ大ページへ寄せ、リクエスト終了時に大ページ全体を回収しやすくする。

代表結果として、H100 serving スループットは異種モデル群・各対応データセットでvLLMに対して最大4.92倍、平均1.80倍。断片化削減と層別プレフィックス再利用でより大きいバッチを実行できる。
## 問題設定
PagedAttentionは固定サイズページでKVキャッシュ断片化を抑えるが、近年のLLMでは一つのモデル内に異なるサイズ・寿命・依存関係の状態が混在する。VLMでは画像トークン用クロス注意とテキスト自己注意のキャッシュサイズが違い、Mambaは各層に大きな再帰状態を持ち、スライディング窓層は古いトークンを不要とする。従来方式が最大サイズに合わせて全層へ一律メモリを確保すると、Llama 3.2 VisionのMMMU-pro条件では79.6%のメモリが無駄になり得る。また全層へ同じLRU・ヒット規則を使うと、実際には不要な古い窓外トークンを保持し、異なる層で別トークンを追い出してモデル全体の共通プレフィックスヒットを失う。
## 新規性
Jengaは互換層とカスタマイズ層からなる二段階メモリ管理を導入する。互換層では各種類の小ページサイズの最小公倍数を大ページサイズに選び、異種メモリ種別間で大ページを融通できる。カスタマイズ層は各層種別の小ページ割当と、プレフィックスのどこが必要かに応じたキャッシュヒット・追い出し規則を提供する。さらに同一リクエストの小ページを同じ大ページへ寄せ、リクエスト終了時に大ページ全体を回収しやすくする。
## 手法
### 手法のあらまし
エンドツーエンドの処理の流れは次の通りである。①モデル読込み時に自己注意、スライディング窓、Mamba、クロス注意など各層種別が1ページに必要とする状態量を調べ、その最小公倍数を互換大ページとしてGPU上の共通メモリプールを作る。②要求が到着すると各層種別の専用アロケータが必要量だけ大ページを借り、内部をその層向けの小ページへ分割する。同じ要求の小ページは同じ大ページへ優先的に集約し、要求終了時に大ページ全体を共通プールへ戻しやすくする。③プリフィルとデコード中は、自己注意なら先頭からの全KV、スライディング窓なら直近窓、Mambaなら離散的な再帰状態というように、層ごとの依存関係に応じて最終アクセス時刻と再利用可能なプレフィックス集合を更新する。④新しい要求が既存キャッシュを再利用するときは、各層が返した候補集合の共通部分からモデル全体で安全に使える最長プレフィックスだけを選ぶ。⑤容量が不足すると、まず大ページ全体を回収できる候補を優先し、必要な場合だけ小ページ単位のLRU追い出しへ細分化する。⑥実際の注意計算では各層に開始ポインタ、ページサイズ、ページIDを渡すだけなので既存PagedAttention CUDAカーネルを変更せず実行できる。この一連の流れにより、異種状態のサイズ差による断片化と依存関係の違いによる不要保持を同時に減らし、空いたGPU容量をより大きな実行バッチと高いプレフィックス再利用率へ変換して、最終的にサービングの処理量と待ち時間を改善する。

### LCM二段階アロケータ
異なる層種別の小ページサイズ全てで割り切れる最小公倍数を大ページとして共通プール化する。各種別は大ページを借りて自分専用の小ページへ分割するため、種別ごとの領域を固定分割せずワークロードに応じて容量を移せる。最大ページ方式のように小さい状態で大きな内部断片化を生まず、GCD方式のようにGPUカーネルが要求する連続次元を細かく分断する必要もない。大ページは異なる層種別の境界をまたいで再利用できるため、ある状態種別の需要が減ったときに、その容量を別種別へ返せる。小ページの物理連続性は各実行カーネルが期待する単位で維持されるので、メモリ効率のために専用カーネルを増やす必要がない。将来、互いに素なページサイズが増えると最小公倍数が大きくなる点は制約になる。

### リクエスト認識配置
小ページを空き場所へ単純に散らすと、リクエスト終了時に多数の小ページが解放されても各大ページに別リクエストの生存ページが残り、大ページを共通プールへ戻せない。Jengaは同一リクエストの小ページを既に関連付けた大ページへ優先配置し、なければ新しい大ページをそのリクエストへ関連付ける。これにより割当と解放の寿命をそろえ、大ページ内部の断片化を減らす。この配置は割当時の局所性ではなく解放時の回収可能性を高めるためのものでもある。同じ要求の状態は終了時刻が近いため、同じ大ページへ集めておけば、その要求が終わった際に大ページ全体が一度に空きやすい。別要求の寿命が混在する場合に起こる外部断片化を抑え、共通プールへの容量返却を早める。

### 層別プレフィックス部分集合API
自己注意は先頭から連続した全KVが必要だが、スライディング窓は直近窓だけ、Mambaは離散的な再帰状態だけが必要である。Jengaは最終アクセス時刻の更新、同時追い出し整列用プレフィックス長、可能なヒットプレフィックス集合を層種別ごとに定義させる。互換層は各種別が返した候補の最長共通プレフィックスだけを再利用し、層ごとに別々の意味を保ちながらモデル全体のヒットを成立させる。たとえばスライディング窓層では古いKVをヒット条件から外し、自己注意層では先頭から連続したKVを要求する。Mambaでは離散的に保存する状態単位を扱う。各層が必要プレフィックス集合を返し、全層で同時に成立する最長部分だけを再利用することで、一部層だけヒットした状態を誤って全体ヒットと扱わず、正確性を保つ。

### 大ページ・小ページ協調追い出し
小ページは空、追い出し可能、実行中使用の3状態を持つ。割当は同一リクエストの空き小ページ、空の大ページ、全小ページが追い出し可能な大ページのLRU追い出し、任意空き小ページ、最後に小ページ単独LRUの順で進める。大ページ単位で状態をそろえることを優先するため、異種種別間の容量交換と細粒度キャッシュヒットの両方を維持できる。優先順位は大ページ全体を回収できる場合を先にし、それが無理な場合だけ小ページ単位へ細分化する。これにより、細かいLRUだけでは生き残りページが各大ページへ散らばる問題を避ける。実行中のページは追い出し対象から除外するため、容量不足時にも進行中要求の状態を破壊せず、次に安全に回収できるまとまりを選べる。

### 全体のデータ／制御の流れ
vLLMのKVメモリを単一テンソルとして確保し、層種別ごとに異なるオフセットとページ表を与える。互換LCM大ページが種別間の容量交換を担い、その中の小ページを各層専用アロケータとエビクタが管理する。既存注意カーネルはstart_ptr、実行ページサイズ、page_idを受け取るだけなのでCUDA変更を不要にする。
## 評価条件
- **ハードウェア**: NVIDIA H100 80GB + 2×Intel Xeon Platinum 8480C (CUDA 12.5)、NVIDIA L4 24GB + 2×AMD EPYC 7F52 16-Core (CUDA 12.4)。
- **ソフトウェア**: vLLM v0.6.3をエンドツーエンド比較に使用。JengaはvLLM上約4000行Python。分解比較はvLLM、SGLang、TGI。
- **比較対象**: vLLM、SGLang、TGI
Llama 3.2 Vision、Gemma-2、Ministral、Jamba-1.5、character.ai模擬モデル、PyramidKV、Llama 3.1などを、MMMU-pro、MMLU-pro、長文arXiv-QAで評価。標準vLLMからメモリ管理だけをJengaへ置換してスループット、E2E遅延、TTFT、TPOT、バッチサイズ、断片化、プレフィックスヒット率を測る。VLM視覚キャッシュと投機的復号もケーススタディ評価する。
異種KV/状態を持つLLM servingのGPUメモリ管理。均質なLlamaではオーバーヘッドがほぼないことも確認。
## 主要結果
H100ではvLLM比でスループット最大4.92倍、平均1.80倍、L4では最大3.29倍、平均1.69倍。低負荷ではE2E遅延差は平均2.6%に留まり、高負荷ではE2E遅延を最大2.24倍、TTFTを最大29.43倍短縮する。Ministralの代表トレースではvLLMがKVメモリの38.2%を浪費するのに対しJengaは0.04%まで削減し、平均デコードバッチは2.5〜2.74程度から5.39へ1.95倍増加する。プレフィックスキャッシュはヒット率最大1.60倍、スループット最大1.77倍。

- H100 serving スループット / 最大4.92倍、平均1.80倍 (比較対象: vLLM; 条件: 異種モデル群・各対応データセット) — 断片化削減と層別プレフィックス再利用でより大きいバッチを実行できる。

- L4 serving スループット / 最大3.29倍、平均1.69倍 (比較対象: vLLM; 条件: 24GB L4で動作可能なモデル群) — 小容量GPUでも異種状態の無駄削減が直接バッチ容量へ変換される。

- KVメモリ浪費 / 38.2%→0.04% (比較対象: vLLM; 条件: Ministral、静的/動的トレース) — 窓外KV解放と二段階配置で断片化をほぼ除去する。

- 平均デコードバッチ / 5.39（他エンジン平均2.50-2.74、約1.95倍） (比較対象: vLLM/SGLang/TGI; 条件: Ministral、20同時要求、入力55k-110k) — 同一GPU容量でより多くの要求を同時デコードできる。

- 高負荷TTFT / 最大29.43倍短縮 (比較対象: vLLM; 条件: Llama Vision、要求率増加時) — メモリ不足による待ちと小バッチ化を抑える効果が高負荷で顕在化する。

### 負の結果・境界条件
- 低要求率ではvLLMとのE2E遅延差は平均2.6%程度で大きな利得はない。より多くの要求を同時実行するためJengaのTPOTはvLLMより大きくなる場合があるが、同じ同時要求数に揃えれば同等TPOTになる。プレフィックス記事数が少なく全てキャッシュできる条件では二段階割当の追加処理によりわずかなオーバーヘッドがある。

### 結果の読み方
Jengaの利得はカーネル高速化ではなく、異種状態に合わせて不要メモリを解放し、容量を要求間・層種別間で再配分してバッチと再利用率を増やすことから生じる。
## 品質への影響
モデル演算・重み・注意結果を近似せず、必要状態だけを正確に保持するため生成品質への変更はない。
## 既存研究との差
PagedAttentionは固定ページと全プレフィックス依存を前提とするのに対し、Jengaは大きさの異なる状態をLCM大ページ上の種別別小ページへ分離し、依存関係も層別APIで表現する。MAXページ方式より断片化を抑え、GCD方式のような多数の専用GPUカーネルを要求しない。SGLang/TGIの既存ページ管理に対しても、異種層間の容量交換と整列した追い出しを新たに提供する。
## 限界
LCM大ページは理論上ページサイズの組合せによって非常に大きくなる可能性がある。論文ではvLLM v0.6.4対応モデル中最大のJambaでも小ページの84倍で性能低下を観測しないが、将来さらに異質な状態サイズが混在するモデルでは再検討が必要である。複数モデルを同一エンジンで完全に共有する機能は将来課題として残る。評価はNVIDIA H100/L4とvLLM中心で、AMD等の別実装は未検証。大バッチ化を優先すると個々のTPOTが増えることがある。
## 実装状態
vLLM上約4000行Pythonで実装し、既存PagedAttention CUDAカーネル変更なし。vLLM v0.6.4の90モデルと互換と報告。一次資料から独立公開コードURLは確認できない。
## 研究上の位置づけ
PagedAttentionを出発点とするKVキャッシュ仮想化の次段階として、モデル内部の異種注意・状態空間・マルチモーダル・複数モデルを同じメモリ管理抽象化で扱う研究。
