# ViMoD：推論段階に応じて視覚的な証拠を呼び戻す粗粒度・細粒度KV記憶

## 概要

高解像度の画像を扱うマルチモーダル大規模言語モデル（MLLM）では、画像が多数の視覚トークンへ変換される。画像の内容を一度だけ要約して視覚トークンを削減すると、生成する文章の最初の段階では十分でも、後の推論段階で必要な細部が削除済みという問題が起こる。例えば図形問題で、最初に三角形の形を確認し、次に特定の辺の数値を読み、最後に別の角度の関係を検証する場合、必要な領域は段階ごとに変化する。固定的な重要度で一回だけ残す方式は、この変化を事前にすべて予測する必要がある。

ViMoD（Visual Memory on Demand）は、原画像の細粒度トークンに対応する鍵・値キャッシュ（Fine KV）を削除せず保存しながら、常時参照する少数の粗粒度KV（Coarse KV）を別に構築する。画像内容に応じて群の大きさと所属を学習するDART、生成履歴から次に必要な領域を予測するTRACE、選択されたFine KVとCoarse KVを元の凍結モデルへ渡すJoint-KVを組み合わせる。これにより、細部をいつでも呼び戻せる一方、生成の各ステップで注意演算が読む視覚KVの数を減らす。

Qwen3-VL-4B-Instructで視覚トークンの平均活動予算を20%に設定すると、数学・論理・複合推論8課題のFull比正規化平均は80.33で、最良の固定削減方式DivPruneの57.78を22.55ポイント上回る。差をDivPrune基準の相対値に直すと約39.0%増である。ただしこれは絶対正答率80.33%ではない。またFineとCoarseの両方を保存するため、実測ピークGPUメモリはFullの38.40 GiBに対してViMoDが42.67 GiBと増える。**視覚KVの保存容量削減と、生成中の注意参照量削減は別の指標**である。

## 問題設定：固定削減では将来の証拠が消える

視覚符号化器から得た細粒度埋め込みを $X^F\in\mathbb{R}^{N\times d}$ とする。標準のモデルは、画像の全 $N$ トークンから作ったKVを各生成ステップで参照する。FastV、VisionZip、DivPruneのような固定的削減方式は、プレフィル後の参照集合を一度選んで固定するため、削除した位置を後から戻せない。推論の途中で必要な領域が変わる場合、最初の選別時に重要でなかった証拠を使えないことが失敗の原因となる。

原著図1の三角形問題では、異なる推論段階で重要となる画像領域が移り、段階ごとの重要領域は平均11.8%であっても、それらの和集合は36.5%を占める。図2の診断では、将来必要な領域を知っているという理想的な条件でも、各段階で必要な領域だけを渡す方式はFull精度の70%に達するために約23.9%の視覚予算を使い、すべての段階の領域を最初から固定的に渡す方式は約36.0%を必要とする。これは動的な証拠アクセスの潜在的価値を示すが、提案方式が未来を完全に知るという意味ではない。

さらに、1トークン当たりの計算を削減しても、回答が長くなれば合計の生成計算量は増えることがある。原著はFastVの一部設定で、トークン当たりの演算削減が出力長増加によって相殺される例を示す。したがって評価は単なる保持率と単発カーネル速度ではなく、生成中の活動集合、回答品質、総生成時間、ピークメモリを区別する必要がある。

## 手法

### 1. DART：画像内容に応じた群容量の割当

DART（Deformable Aggregation of Region-wise Tokens）は、$N$ 個のFineトークンを $M\ll N$ 個の群へ割り当て、各群を一つのCoarseトークンへ集約する。初期状態では画像を格子状に分け、各群の平均特徴から学習スコア $a_j=w_c^T\overline{x}_j$ を求める。群の目標容量は $\widetilde{c}_j=1+(U-1)\operatorname{sigmoid}(b_j+a_j+\mu)$ と定義され、共通補正量 $\mu$ を調整して $\sum_j\widetilde{c}_j=N$ とする。最後に総和を保つ整数丸めを行う。$U$ は一群が含められる最大Fineトークン数である。

群容量が小さい場所では一つのCoarseトークンが少数のFineトークンを代表するため、細部を保持しやすく、群を呼び戻す際の追加参照費用も小さい。画像の空白領域は大きな群に、文字・図形の境界などには小さな群を割り当てる。群数を固定したまま容量を画像内容に応じて変えることで、粗粒度表現の総数を制御しながら重要領域の細かさを変える。

### 2. DART：変形可能な所属と粗粒度KVの生成

初期格子だけで群の所属を固定せず、各Fineトークンと群の平均特徴を学習射影して類似度を計算する。原著式(3)の所属スコアは、初期格子への所属を表す指示関数に係数 $\gamma$ を掛けた項と、射影特徴の内積を組み合わせる。各トークンをスコア順に、まだ容量の残る群へ割り当てるため、群は元の格子境界をまたいで三角形の辺などに沿うことができる。

各群内の所属スコアを正規化した重みを行列 $W$ とし、Coarse埋め込みを $X^C=W^T X^F$ で作る。重要なのは、群 $j$ のFineトークン集合を $\Pi(j)$ として保存し、**集約に使った群と、後から細部を呼び戻す群が同一**である点である。これにより、Coarse表現が示す画像内容と再参照される元トークンの対応が一貫する。

デコーダ層 $\ell$ の粗粒度キーは $K^{C,\ell}=W^T K^{F,\ell}$、値は学習済み残差エンコーダ $E_\phi$ を通して $V^{C,\ell}=W^T E_\phi(V^{F,\ell})$ とする。Fine KVは削除せず残す。離散的な群割当の勾配を扱うため、学習時には容量制約付きのSinkhorn近似を使い、前向きでは実際の離散群を利用する。これは群容量・所属を学習するための追加工程であり、バックボーン本体の重みは更新しない。

### 3. TRACE：生成履歴を複数の時間尺度で要約

TRACE（Temporal Routing for Adaptive Contextual Evidence）は、生成中の隠れ状態から、次の推論区間で必要となるFine領域を選ぶ。原著の設定では16生成トークンごとに判断し、バックボーンの層27・31・35の状態を学習的に融合して入力 $u_t$ を作る。4本の再帰枝は異なる時間尺度を持ち、各枝で $s_t^{(m)}=\rho_t^{(m)}\odot s_{t-1}^{(m)}+(1-\rho_t^{(m)})\odot f(u_t)$ に従って過去状態と新情報を混合する。枝をsoftmax重みで合成した $z_t$ が、生成履歴を表す状態になる。

短い時間尺度の枝は直近の言及や注視領域の変化を反映し、長い枝は前段の問題設定や参照した図形を残す。状態次元は256、領域照合のキー・クエリ次元は128である。ここで予測するのは、将来の回答そのものではなく、次の区間で必要となりそうな画像の証拠群である。追加の学習済み小規模ネットワークで実現し、元の大規模モデルの重みを変更しない。

### 4. TRACE：証拠群の選択と保持・更新ゲート

状態 $z_t$ と各Coarse領域の記述子の内積から群ごとの得点を作り、学習した境界値を引いてsigmoidを適用する。確率が0.5を超える群を次の提案集合 $\widehat{A}_t$ とする。別のゲートが、直前の活動集合 $A_{t-1}$ と提案集合、時系列状態を比較してHOLDかUPDATEを選ぶ。HOLDなら前のFine集合を継続し、UPDATEなら新しい集合へ置換する。更新は追加だけでなく削除や空集合も許すため、Coarseだけで推論する区間も作れる。

選択した群 $j$ からは $\Pi(j)$ に属する元Fineトークン全員を参照する。したがって群を一つ選ぶ費用は一定ではなく、DARTが決めた群容量 $c_j$ に依存する。重要な細部を含む小群は安く呼び戻せるが、空白を広く集約した大群を選ぶと参照費用が増える。これがDARTとTRACEを共同で設計する理由である。16トークンの判断間隔内で必要な証拠が変化した場合は、更新が遅れて品質が下がる可能性も残る。

### 5. Joint-KV：注意対象と保存対象を分離

生成ステップ $n$ で、活動群から得たFine位置集合を $F_{t(n)}=\bigcup_{j\in A_{t(n)}}\Pi(j)$ とする。Joint-KVは、常時Coarse KV、活動Fine KV、テキスト履歴KVを連結して $KV_J(n)=[KV_C;KV_F[F_{t(n)}];KV_T(n)]$ を作り、凍結バックボーンの注意へ渡す。生成中に実際に参照する視覚トークン数は $M+|F_t|$ となる。非活動Fine KVも保存されているが、現在の注意演算では参照されない。

この方式はFine KVを圧縮して消すのではなく、**保存しているKVのうち、毎回読む部分を小さくする**。したがって生成トークン当たりの注意計算やKV読み出しは減る一方、FineとCoarseの両方を保持するメモリ費用が増える。画像プレフィルもFull相当の処理が必要なので、短い回答では初期費用を回収しにくい。長い生成で毎ステップの注意費用が支配的になる場合に効果が出やすい。

### 6. 学習：記憶蒸留、証拠教師、方策最適化

学習は二段階で行う。まずDARTを、正答確認済みの応答軌跡57,420件から、Fullの出力分布を教師としたトークン交差エントロピーとKL蒸留で学習する。その後DARTを固定し、Qwen3.8-27Bの教師が次の推論区間で必要な画像領域を注釈した80,000例を使ってTRACEの群選択とHOLD/UPDATEゲートを教師付き学習する。続いて学生モデル自身の軌跡から、正答性とFine活動率に応じたRLOO型の方策最適化を行う。最後の4,800問は教師付き集合の部分集合であり、独立した追加の評価集合ではない。

学習する追加パラメータはDART約118.5万、TRACE約123.6万、合計約242.1万で、約44.4億パラメータのバックボーンに対して0.0546%に当たる。少ない学習パラメータで実現する一方、正解確認済み軌跡、教師の領域注釈、方策最適化、容量制約付き群割当の実装が必要であり、学習費用がゼロという意味ではない。

## 評価

### 1. 主結果：20%活動予算で固定削減を上回る

8推論課題のFull比正規化平均では、20%活動予算でViMoD 80.33、DivPrune 57.78、FastV 55.25、VisionZip 53.31、DSTP† 72.96となる。ViMoDとDivPruneの差は22.55ポイント、相対39.0%である。ここでの平均は各課題でFullを100に正規化した得点の等重み平均であり、80.33%の絶対正答率ではない。ViMoDが固定削減を上回るという主張は、同じモデル・評価設定・平均活動予算の範囲で成立する。

| 評価条件 | 比較方式 | ViMoD | 読み取れること |
|---|---:|---:|---|
| 推論8課題、20%、Full比正規化平均 | DivPrune 57.78 | 80.33 | +22.55ポイント |
| 推論8課題、20%、同じDART記憶 | DSTP† 72.96 | 80.33 | +7.37ポイント |
| 推論8課題、30%、9:1 | DSTP† 76.41 | 86.14 | +9.73ポイント |
| 推論8課題、30%、4:1 | DSTP† 84.26 | 87.71 | +3.45ポイント |
| 推論8課題、40%、4:1 | DSTP† 86.32 | 91.06 | +4.74ポイント |
| 一般視覚10指標、20%、正規化平均 | DivPrune 78.68 | 93.77 | +15.09ポイント |

20%活動予算でのDynaMath絶対正答率はViMoD 51.14、DivPrune 39.06、MMMU-Proは19.54対8.38である。しかしMMMU-ProのFullは30.92なので、ViMoDはFullの品質へ戻ったわけではない。高い相対平均値だけを見てFullと同等と判断するのは不適切である。

### 2. 構成要素除去：再参照と群構築の独立した寄与

Fine再参照を禁止すると、30%予算でDynaMathはViMoDの53.65から47.72へ、MMMU-Proは25.03から12.20へ低下する。再参照を一度だけ許してもそれぞれ50.30、16.91にとどまる。推論の進行に合わせて繰り返し詳細を呼び戻すことが、初回だけの選択より有効であることを示す。

DARTの内容適応的な群構築を固定格子の平均集約へ置き換えると、同じ30%予算でDynaMathは53.65から42.38、MMMU-Proは25.03から14.68へ低下する。再参照機構だけを残しても、粗粒度表現とFine群の対応が悪いと品質を保てない。TRACEの方策最適化を除くとDynaMathは47.66、MMMU-Proは20.81となり、教師付き初期化後に学生自身の生成軌跡へ合わせる段階にも効果がある。

| 30%予算・9:1 | DynaMath | MMMU-Pro |
|---|---:|---:|
| ViMoD | 53.65 | 25.03 |
| Fine再参照なし | 47.72 | 12.20 |
| Fine再参照1回 | 50.30 | 16.91 |
| DARTを固定格子平均集約へ変更 | 42.38 | 14.68 |
| TRACEの方策最適化なし | 47.66 | 20.81 |

### 3. 実測時間：生成長まで含めて評価する

MMMU-Proの効率評価では、H200単体・バッチ8・最大8192出力トークンで20〜90%の活動予算を調べる。ViMoDは試した予算でFullより合計推論時間を短縮した。40%予算では一括削減3方式より高精度で、合計時間も15.2〜20.4%短い。一括削減方式はトークン当たりの復号を速めても、回答がFullより15.9〜29.9%長くなる条件があり、総生成時間での利得が小さくなる。

この評価でFullの実行時間の94.4%は自己回帰デコードが占める。ViMoDはFull相当のプレフィルとCoarse構築を必要とするため、20〜50%予算では一括削減方式より初回トークンまでの遅延（TTFT）が悪化する。長い生成ではデコード時の注意参照削減で回収できるが、短い回答を多く返す対話用途でも同じ結果になるとは示されていない。

### 4. メモリと補助モジュールの負の結果

ViMoDはFineとCoarseのKVを両方保持するため、ピークGPUメモリは42.67 GiBで、Fullの38.40 GiBより4.27 GiB大きい。20%という活動予算は保存KVの20%化を意味しない。追加ネットワークの実行時間比はDART 0.078%、TRACE 0.616%、合計0.694%と報告されるが、これだけで記憶構築、Fine KV保存、初期化費用をすべて表しているわけではない。

50%予算ではViMoDがFullと同等の精度を達成し、同程度の精度に80%の視覚予算を必要とするDivPruneより実測活動占有率を39.5%低くし、合計時間を3.9%短縮した。ただしこれはMMMU-Proの長い生成を伴う特定の実機設定における比較である。GPUメモリが限られた端末や大規模同時処理では、むしろFine KV保存の費用がボトルネックになり得る。

## 既存研究との差

FastV、VisionZip、DivPruneは、入力後に視覚トークンを固定的に削減する。これらは保存容量と注意計算の両方を減らしやすいが、削除した細部を生成途中で再参照できない。ViMoDは元Fine KVを保持することでその欠点を避け、Coarseを常時見せながら必要なFineだけを有効化する。注意変化に応じて詳細を呼び戻すDSTP†と比べ、TRACEは生成履歴の複数時間尺度を学習し、次区間で必要になる証拠を予測する。

ViMoDの特徴は、DARTの群容量・所属、TRACEの活動群、Joint-KVの参照対象が同じFine→Coarse対応表を使う点にある。別の視覚符号化器を毎回呼ぶ切り抜き方式とは異なり、既に計算したFine KVを内部から取り出す。ただし、外部メモリへのオフロードやKV圧縮と組み合わせた場合の転送費用は論文では評価されていない。

## 限界・負の結果・再現上の注意

第一に、GPUメモリはFullより増える。Fine KVとCoarse KVの二重保存が必要なため、視覚活動率の削減をメモリ削減と同一視してはならない。第二に、プレフィルはFull相当であり、短い出力ではCoarse構築とTRACEの費用を償却できない可能性がある。第三に、16トークンごとの更新の間に必要な証拠が変化すると選択が遅れ、群を一つ呼び戻すと不要なFineも含めて読むため、実際の活動数は群容量に依存する。

第四に、教師モデルの領域注釈と正答確認済みデータが必要で、学習パラメータが少ないことは学習手順が簡単であることを意味しない。第五に、評価は凍結したQwen3-VL-4Bと特定の貪欲復号条件に限られ、他のモデル、確率的生成、複数GPUのサービング、長期稼働のメモリ管理は未検証である。第六に、DSTP†は同じDART記憶へ移植した比較版であり、公開された元方式と全実装条件が同一とは限らない。
