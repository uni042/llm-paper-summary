# Efficient Serving for Dynamic Agent Workflows with Prediction-based KV-Cache Management

## 概要

PBKVは、複数の言語モデルエージェントが同じ処理を分担する動的ワークフローで、次に使われる可能性が高いキー・値キャッシュ（KVキャッシュ）をGPUに残し、必要に応じてホストメモリから先読みする仕組みである。計画・コード生成・検証・再試行のような処理では、各エージェントが長いシステム指示や過去の会話を共有する。前の呼出しで作った接頭辞のKVを再利用できれば、同じトークン列のプリフィル計算を省ける。しかし分岐やループがあると将来の呼出し順序は固定できず、最近使ったキャッシュを残す最終使用時刻方式（LRU）も、静的な呼出しグラフを前提とするKVFlowも十分に対応できない。

PBKVは、現在の呼出し位置、これまでの経路、要求の意味表現を融合して数ステップ先の呼出し分布を予測し、複数ワークフローから見た各キャッシュの再利用価値を算出する。終了したワークフロー専用キャッシュは予測値に依存せず優先的に回収し、活動中のキャッシュだけを予測スコアで比較する。さらにGPUの空き領域と復号中の未使用転送帯域だけで保守的に先読みするため、誤予測が有用なキャッシュを押し出す事態を避ける。

8基のNVIDIA A6000を備えるサーバで、HoVer、SWE-bench、FinanceBenchを用いた実験では、HoVerとQwen3-32Bで平均ワークフロー完了時間がLRUの189.66秒から102.60秒へ短縮された。静的なFinanceBenchではKVFlowの101.57秒に対して80.53秒である。著者らの最大1.85倍・最大1.26倍という数字はそれぞれ異なる比較対象とワークロードに対応する。

## 問題設定と再利用単位

エージェント型の処理は、ノードをエージェント、辺を可能な呼出し遷移とする有向グラフG=(V,E)として表せる。一回の実行はそのグラフ上のエージェント列a1,a2,…であり、同じグラフでも検証失敗や検索結果によって経路が変わる。例えばコード生成の検証器が失敗を検出すれば、解析器とコード生成器を再度呼ぶ。直前に使わなかった検証器のKVが数ステップ後に必要になることがある。

キャッシュは、異なるワークフローにも共通するシステム指示やエージェント説明などの全体共有部分と、個々の実行で生まれた会話履歴などの専用部分に分かれる。後者は確率的な生成結果に依存するため、別の実行へそのまま共有できない場合が多い。GPUメモリは有限で、キャッシュを捨てるとホストからの再読込、あるいは長い接頭辞のプリフィル再計算が必要になる。LRUは使用時刻だけで追い出すため、ワークフロー構造に起因する将来の再利用を見落とす。

KVFlowは静的なエージェント呼出しグラフから次の実行までのステップ数を推定する。しかし条件分岐や再試行があると、どのノードへ進むかが実行時に決まり、その距離自体が確定しない。PBKVが解くのは将来を確実に知る問題ではなく、不確実な多段予測を用いてキャッシュ破棄の損失を小さくする問題である。誤った破棄は再計算を生み、誤った先読みは帯域とGPU容量を消費するという非対称な費用を設計の中心に置く。

## 手法

### 1. 呼出しグラフ・経路・意味を融合する多段予測

PBKVの予測器は、オフラインの実行履歴から推定した遷移グラフに二層のGraphSAGEを適用し、現在のエージェントの近傍を含む埋め込みh_curを得る。さらに現在のエージェントを問い合わせとして過去のエージェント列を注意集約し、経路依存のh_pathを作る。同じ現在ノードにいても、どの経路を通って来たかによって次の遷移が変わるためである。三つ目は、プリフィルの最後のトークンの正規化済み隠れ状態から投影した意味信号h_txtで、同じ経路でも利用者の要求内容が異なる場合を区別する。

三つの表現を連結し、二層の多層パーセプトロンで今後K回の呼出し確率分布を一度に出す。次の一手を自己回帰的に繰り返し予測する方式と違い、予測誤差が逐次的に伝播しない。学習では履歴の接頭辞とプリフィル埋め込みを入力、続くK回のエージェントを教師ラベルとし、終了後の埋め草位置を損失から除く。論文の予測器は約35万パラメータで、1024要求のバッチを1.56ミリ秒で処理した。

HoVerのLangChainワークフローで1000本の履歴を使った場合、500本の試験履歴に対する予測精度は1ステップ先0.94、3ステップ先0.77だった。遠い将来ほど不確かになるため、予測器の確率をそのまま足し合わせず、後述する生存確率と距離減衰を組み合わせる。予測器は差し替え可能で、キャッシュ管理器は予測モデルの内部実装を固定しない。

### 2. 終了済みキャッシュを先に回収する階層的追い出し

基数木（Radix Tree）の各キャッシュノードcに、そのノードを利用したワークフローの集合を記録する。クライアントからワークフロー終了通知を受けたとき、関連するすべての実行が終了した専用キャッシュをretiredとして識別する。これらは以後の専用再利用がほぼ期待できないため、予測に依存せず優先的に破棄する。複数の実行に使われた共有接頭辞は、単に古いという理由だけで同じ扱いにしない。この寿命認識だけの変種PBKV-LAEでも、実験ではキャッシュ命中率をLRU比最大1.66倍に改善した。

終了済みキャッシュを使い切った後は、活動中のキャッシュの将来価値を使う。各ノードcについて、ワークフローwがそのキャッシュをどのエージェントで利用したかを二値ベクトルA_w(c)に保持する。予測器が出すkステップ先のエージェント確率ベクトルP_w^(k)との内積は、その実行がそのノードを再利用する確率の推定値になる。複数の実行が共有するキャッシュは、全ワークフローからの寄与を合計して評価するため、人気の高い接頭辞が自然に優先される。

### 3. 生存確率と減衰を含む将来再利用スコア

遠い予測ほど信頼度が低く、途中で処理が終了した後の呼出しは意味を持たない。そこでkステップ先まで終了しない確率s_w^(k)を、先行ステップの非終了確率の積で計算する。各ノードのScore(c)は、k=1,…,Kについて、γ^(k−1)×s_w^(k)×A_w(c)・P_w^(k)を全活動ワークフローで足した値である。γ<1は遠い将来の不確実性を抑える係数で、主実験はK=3、γ=0.7を使う。

GPUの容量不足時はScore(c)が小さいノードから順に破棄する。ただし活動中のノードのスコアが予測誤りでゼロになっても、終了済みノードが残る間は先に後者を破棄する。終了判定は確定情報、活動中のスコアは推定値であるため、同じゼロとして扱わない階層化が重要である。予測更新はエージェント呼出しや終了など状態変化時に行い、ヒープでノードを管理する。先頭参照はO(1)、挿入・削除・スコア更新はO(log n)である。

### 4. GPU空き容量と未使用帯域に限定した保守的先読み

ホスト側のHiCacheからGPUへキャッシュを先読みすると、次の要求での転送待ちを減らせる。しかし先読みは正解か否かにかかわらず転送帯域を使う。PBKVは活動中の有用キャッシュを追い出してまで先読みしない。空き領域と終了済みキャッシュの領域の合計をS_aとし、利用可能な先読み容量の上限にする。

また、プリフィルとPCIe帯域を競合させないため、純粋な復号バッチでだけ先読みを行う。実測ではこのバッチが全体の90%超を占める。現在の帯域推定値と復号一ステップ時間の積をS_bwとし、実際の転送予算をS=min(S_a,S_bw)に制限する。候補の優先順位は一ステップ先のValue(c)を使い、予算内に収まるノードを価値の高い順に貪欲に選ぶ。追い出しは数ステップ先を見る一方、先読みは直近一手だけを見るのは、先読みは次のステップでも間に合うが、誤った追い出しは高価な再計算を伴うからである。

先読み候補の最適選択は容量制約付きの組合せ問題であり、厳密解は高価である。そこで軽量な貪欲法を用いる。これらの安全策は、誤予測時に活動中のキャッシュを追い出して先読みする攻撃的な方式と対照的である。予測が不確かな環境では、先読みの最大利益を狙うより、悪化を防ぐことを優先している。

## 評価：条件・比較・主要結果

### 実験基盤とワークロード

| 項目 | 実験条件 | 評価上の意味 |
|---|---|---|
| GPU | NVIDIA A6000 48GBを8基、NVLink接続 | GPUキャッシュの競合を再現 |
| CPU・メモリ | 128仮想CPU、ホストRAM 512GB | 二層キャッシュのホスト側 |
| PCIe帯域 | 20GB/s | 先読みの帯域制約 |
| 言語モデル | Qwen3-14B、Qwen3-32B | 32Bは二方向テンソル並列 |
| HoVer + LangChain | 事実検証、再試行あり、同時72ワークフロー | 動的処理 |
| SWE-bench + AutoGen | コード生成、再試行あり、同時24 | 動的処理 |
| FinanceBench + CrewAI | 文書解析、静的構造、同時48 | KVFlowとの公平な比較 |
| 比較対象 | SGLang+HiCacheのLRU、静的構造のKVFlow | 既存のキャッシュ管理方式 |

主要指標はワークフロー全体の平均完了時間、各エージェント呼出しの初回トークン時間、GPU内のトークン単位KV命中率である。LRUはGPUとホストのキャッシュ容量を等しく割り当てるHiCache構成で実行した。KVFlowは静的なエージェント呼出し順序が必要なため、動的な二つの実験では比較対象にしていない。静的FinanceBenchだけで直接比較する。この区別なしに「動的ワークフローでKVFlowより速い」と断定することはできない。

HoVerでQwen3-32Bを使うと、LRUの189.66秒に対し完全PBKVは102.60秒で、完了時間比は約1.85倍である。GPU命中率は27.09%から69.10%に増え、比率では約2.55倍になる。初回トークン時間も16.65秒から8.22秒へ短縮した。これらはそれぞれ異なる指標であり、2.55倍をワークフロー処理速度の倍率と呼んではならない。

構成要素除去では、寿命認識のみの146.67秒から階層追い出しを加えると108.86秒へ大きく改善し、さらに保守的先読みを加えると102.60秒へ改善する。先読みの追加効果は比較的小さいが安定している。著者らは、予測誤りと、価値のある活動中キャッシュを守る保守的設計がこの差を説明すると述べる。静的FinanceBenchでもQwen3-32BのKVFlow比で101.57/80.53≈1.26倍となり、共有接頭辞の人気度を複数ワークフローで合算する方式の効果が残る。

### 感度・負の結果・予測器の品質

HoVerとQwen3-32Bの同時実行数を変えると、60未満ではGPUキャッシュの追い出しが少なく方式差が目立たない。84並列ではLRUが10回中3回、96並列では10回中10回メモリ不足で失敗した。主実験の72並列は比較方式が稼働でき、なお十分なメモリ圧力がある条件として選ばれている。すべての同時実行数で同じ速度倍率が出るわけではない。

予測器の基盤をGraphSAGEからR-GCNや三次マルコフモデルへ替えると予測精度と命中率が低下するが、最も弱い予測器でも寿命認識のみの方式を上回った。先読み長Kは3で命中率が最良となり、短すぎると先の再利用を見落とし、長すぎると不確かな予測がスコアを汚染する。先読みの順位は一手先だけを使うため、Kを変えても階層追い出しから完全PBKVへの差は概ね一定である。

時系列では、開始直後のGPUに余裕がある段階では全方式が高命中率だが、メモリが満杯になるとLRUが急落する。終了済みワークフローが現れると寿命認識方式も回復するが、その領域が尽きると再びLRUに近づく。階層追い出しはその後も予測スコアで活動中キャッシュを守り、定常区間ではLRUが約10%、完全PBKVが約50%の命中率を維持する。これは平均値だけでは見えない持続的な差である。

## 既存研究との差

SGLangの基数木接頭辞共有やHiCacheのGPU・ホスト階層化は、再利用可能なKVを保存・移送する基盤である。PBKVはその上で「どのキャッシュを保持し、いつ先読みするか」をワークフローの将来予測に結び付ける。KVFlowは静的グラフで次の使用までの距離を見積もるが、動的な再試行・条件分岐では距離を確定できない。PBKVは確率的な呼出し予測と寿命の確定情報を組み合わせ、動的構造にも適用する。

KVFlowが複数ワークフローの最短再利用距離を用いるのに対し、PBKVは各実行の再利用確率を合算するため、人気の高い共有キャッシュが優先される。単なるGPUキャッシュ容量拡張ではなく、共有価値の評価方法と誤予測時の安全策が差分である。エージェントの次の行動を投機実行する研究とも異なり、予測結果をキャッシュ配置へ使うことに焦点を当てる。

## 限界と適用範囲

予測器は特定ワークロードの実行履歴で学習する。エージェントの呼出し構造、クライアントが履歴を引き継ぐ規則、共有接頭辞の構成が変われば予測精度と再利用価値も変化する。論文はアクセス指標A_w(c)を各エージェントが直接使ったキャッシュとして定義しており、別エージェントが履歴を自動継承するフレームワークでは指標の定義を調整する必要がある。

予測誤りに対する損失の上界は、予測誤差に対して連続的に増えることを示すもので、すべての入力で必ず高速化するという保証ではない。保守的先読みは活動中キャッシュを守る代わりに先読みの機会を制限し、より攻撃的な方式より最大利益が小さくなる場合がある。GPU空き領域がほぼなく、復号以外のバッチが続くと先読みは実行されにくい。

8基のA6000、20GB/sのPCIe帯域、Qwen3-14B/32B、三つのワークフローを用いた評価であり、別のGPU、ストレージ階層、巨大な同時実行数、モデル構造への性能の外挿はできない。共有接頭辞がほとんどない用途では予測が正しくても削減できるプリフィルが少ない。予測器の学習と状態更新、キャッシュスコア維持にも追加計算があり、論文の35万パラメータ・1.56ミリ秒という測定はこの実験条件の値である。
