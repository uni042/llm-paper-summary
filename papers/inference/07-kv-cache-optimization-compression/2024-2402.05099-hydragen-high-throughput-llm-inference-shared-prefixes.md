# Hydragen: High-Throughput LLM Inference with Shared Prefixes

> batch内で複数sequenceが共有するprefixと各sequence固有suffixのattentionを分離し、共有prefixへのqueryをsequence間でまとめてmatrix-matrix計算することで、同じKVの重複memory readと非効率なmatrix-vector計算を減らすexact attention手法。

## 概要

few-shot prompt、同じsystem promptを使うchatbot、多数sampleを生成するself-consistencyなどでは、batch内の複数sequenceが長いprefixを共有する。

KV cache自体を共有してmemory容量を減らしても、通常のdecode attentionでは各sequenceが同じprefix KVを個別にHBMから読み、1 queryずつmatrix-vector計算するためmemory bandwidthとGPU utilizationの無駄が残る。

Hydragenはattentionを**shared prefix部分とunique suffix部分へ分解**し、shared prefixに対する複数sequenceのqueryを一つの大きなbatchへまとめる。これにより同じKVを繰り返し読む量を減らし、GPUが得意なmatrix-matrix計算へ変換する。

## 手法

### 1. Attention decomposition

各sequence全体へ一度にattentionする代わりに、

- 全sequenceで共有されるprefix
- sequenceごとに異なるsuffix

へ分けてattentionを計算する。

それぞれのattention出力とsoftmax denominatorに相当するlog-sum-expを保持し、最後に正確に合成する。そのため近似やtoken削除ではなく、通常attentionと同じ結果を得るexact methodである。

### 2. Inter-sequence batching

shared prefixに対するqueryをsequenceごとに別々に処理せず、複数sequence分を一つにまとめる。

通常decodeでは`1 query × 長いKV`というmemory-boundなmatrix-vector処理になりやすいが、Hydragenでは`多数query × 同じKV`へ変わるため、shared KVを一度読みながらmatrix-matrix計算として高いGPU utilizationを得やすい。

### 3. Unique suffixは通常attention

sequence固有suffixは他sequenceと共有できないため通常のattentionで処理する。shared prefixで得た結果とsuffix側の結果をlog-sum-expを使って結合する。

### 4. Hierarchical sharing

単一の共通prefixだけでなく、tree状に一部prefixを共有する構造へ一般化できる。例えば複数problemが共通instructionを持ち、その下でproblemごとに複数candidate completionを生成するような階層共有を扱える。

## 評価

CodeLlama-13Bなどでshared-prefix batchを評価し、competitive baselineに対して**end-to-end throughput最大32×**を報告する。

特にbatch sizeとshared prefixが大きいほど利得が増える。

長いshared contextの評価では、prefix lengthを1Kから16K tokenへ増やしても大batchのHydragen throughput低下は15%未満だった一方、baselineは90%以上低下した。

またtree状prompt sharingをcompetitive programming workloadへ適用し、inference timeを**55%削減**した。

## 既存研究との差

### vLLM / PagedAttentionとの違い

PagedAttentionは同じprefix KVを複数sequenceで共有してmemory容量を減らせるが、attention kernel自体は各sequenceについてKVを読むため、shared prefixのmemory readとmatrix-vector計算が重複する。

Hydragenは**memory allocationではなくattention computationそのものをshared-prefix awareにする**ことで、その重複を減らす。

### SGLang / RadixAttentionとの違い

SGLangはradix treeでrequest間のprefix KVを発見・保持し、cache-aware schedulingでreuse機会を増やす。Hydragenはcacheの発見・保持policyよりも、**すでに共有されているKVをattention kernelでどう高速に読むか**が中心である。

両者は補完的で、RadixAttention型cacheで共有prefixを見つけ、Hydragen型kernelで共有部分のattentionを効率化できる。

### KV compressionとの違い

KVを削除・量子化・圧縮せず、全KVを保持したまま同じ数学結果を出す。品質とmemory容量ではなく、shared KVへのmemory accessとGPU演算形態を最適化する研究である。

## 限界

- shared prefixが短い、またはbatch sizeが小さい場合はmatrix-matrix化の効果が小さい。
- unique suffixが長くなるほどshared部分の割合が下がり、利得も小さくなる。
- 公開実装はfull serving engineではなく、論文時点では主にLlama-familyと専用generation pathを対象とする。
- continuous batching、request arrival、preemptionなどproduction serving機能は主題ではない。
- prefix sharing構造をruntime側が把握できる必要がある。

## 一般的な実装上の含意

KV prefix sharingでは「同じKVを1コピーだけ保存する」だけでは十分ではない。decode時に各requestがそのKVを別々に読めば、**memory capacityは節約できてもHBM bandwidthはほぼ節約できない**。

shared prefixを持つrequestを同時に処理し、query側をbatch化して共有KVを一度の大きな演算へ使うことで、cache reuseをmemory節約からcompute / bandwidth高速化へつなげられる。
