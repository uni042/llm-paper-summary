# Hydragen: High-Throughput LLM Inference with Shared Prefixes

> 同じ長いprefixを共有する複数sequenceのqueryをまとめて処理し、共有KVをsequenceごとに何度もHBMから読み直す無駄を減らすexact attention手法。

## 概要

few-shot prompt、同じsystem promptを使うchatbot、多数sampleを生成するself-consistencyなどでは、batch内の複数sequenceが長いprefixを共有する。

KV cache自体を1コピーに共有してmemory容量を減らしても、通常のdecode attentionでは各sequenceが同じprefix KVを個別にHBMから読み、1 queryずつ計算するため、memory bandwidthの無駄が残る。

Hydragenはattentionを**全sequenceで共有するprefix部分と、各sequenceだけが持つsuffix部分へ分ける**。共有prefixに対する複数sequenceのqueryをまとめて一度に計算することで、同じKVを何度も読み直す量を減らし、GPUが効率よく処理しやすい大きな行列計算へ変える。

KVを削除・近似する方式ではなく、通常attentionと数学的に同じ出力を得る。

## 手法

### 1. Shared prefixとunique suffixを別々にattentionする

各sequence全体へ一度にattentionする代わりに、

- 全sequenceで共有されるprefix
- sequenceごとに異なるsuffix

へ分けてattentionを計算する。

共有側・suffix側それぞれについてattention出力と、softmaxで重みを正規化するために必要な値を保持し、最後に両者を正確に合成する。

論文ではこの正規化値の計算にlog-sum-expを使うが、重要なのは**prefix側とsuffix側を別々に計算しても、最後に通常attentionと同じ結果へ戻せる**ことである。

### 2. 複数sequenceのqueryをまとめて共有KVへ当てる

通常decodeでは、sequenceごとに `1 query × 長い共有KV` を繰り返すため、同じKVをHBMから何度も読む。

Hydragenは複数sequenceのqueryをまとめ、`多数query × 同じ共有KV` として一度に処理する。

これにより、1 queryずつのmatrix-vector計算を繰り返す代わりに、複数queryをまとめたmatrix-matrix計算にでき、**共有KVの再利用とGPU計算効率の両方を高める**。

論文ではこのsequence間のまとめ処理を `inter-sequence batching` と呼ぶ。

### 3. Sequence固有suffixは通常attentionで処理する

sequence固有suffixは他sequenceと共有できないため通常のattentionで処理する。

最後にshared prefix側とsuffix側のattention結果を、softmaxの正規化を崩さないように結合する。

### 4. Prefix共有が階層的な場合にも拡張できる

全requestが完全に同じprefixを持つ場合だけでなく、

- 全requestで共通するsystem prompt
- その下でproblemごとに共通するprompt
- さらに各candidateだけが持つsuffix

のように、共有範囲が木構造になっている場合にも適用できる。

## 評価

CodeLlama-13Bなどでshared-prefix batchを評価し、既存実装に対して**end-to-end throughput最大32×**を報告する。

特にbatch sizeとshared prefixが大きいほど利得が増える。

長いshared contextの評価では、prefix lengthを1Kから16K tokenへ増やしても大batchのHydragen throughput低下は15%未満だった一方、baselineは90%以上低下した。

また木構造のprompt sharingをcompetitive programming workloadへ適用し、inference timeを**55%削減**した。

## 既存研究との差

### vLLM / PagedAttentionとの違い

PagedAttentionは同じprefix KVを複数sequenceで共有してmemory容量を減らせるが、attention計算自体は各sequenceについて個別に行うため、shared prefix KVのmemory readが繰り返される。

Hydragenは**KVを1コピーにするだけでなく、そのKVを複数sequenceのqueryでまとめて使うattention計算へ変える**ことで、HBM bandwidthの重複まで減らす。

### SGLang / RadixAttentionとの違い

SGLangは、requestのprefixを木構造で管理し、複数requestに共通するprefix KVを見つけて再利用する。

Hydragenは「どのprefixを共有できるかを見つける」ことより、**共有できると分かったKVをattention kernelでどう効率よく読むか**が中心である。

両者は補完的で、SGLang型cacheで共有prefixを見つけ、Hydragen型kernelで共有部分のattentionを高速化できる。

### KV compressionとの違い

KVを削除・量子化・圧縮せず、全KVを保持したまま同じattention結果を出す。

したがって主な改善対象はKV容量ではなく、**共有KVへのHBM read回数とGPU上のattention計算効率**である。

## 限界

- shared prefixが短い、またはbatch sizeが小さい場合は複数queryをまとめる効果が小さい。
- unique suffixが長くなるほどshared部分の割合が下がり、利得も小さくなる。
- 公開実装はfull serving engineではなく、論文時点では主にLlama-familyと専用generation pathを対象とする。
- continuous batching、request arrival、preemptionなどproduction serving機能は主題ではない。
- runtime側がrequest間のprefix共有関係を把握できる必要がある。

## 一般的な実装上の含意

KV prefix sharingでは「同じKVを1コピーだけ保存する」だけでは十分ではない。decode時に各requestがそのKVを別々に読めば、**memory capacityは節約できてもHBM bandwidthはほぼ節約できない**。

shared prefixを持つrequestを同時に処理し、query側をまとめて共有KVへattentionすることで、cache reuseをmemory節約から実際のthroughput改善へつなげられる。
