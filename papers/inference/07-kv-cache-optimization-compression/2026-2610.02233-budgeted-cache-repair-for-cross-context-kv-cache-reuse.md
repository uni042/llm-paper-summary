# Budgeted Cache Repair for Cross-Context KV-Cache Reuse

> 文脈横断キャッシュ再利用の精度損失はゲートや呼び出し選択では消えず、2トークンのドラフトで注意の集まる行を選び固定予算だけ正確に再計算することでGSM8Kの精度を稠密水準へ回復させる方式。

## 概要

複数エージェントの言語モデルシステムでは、同じ課題文や前のエージェントの出力を各エージェントが繰り返し処理する。エージェントが3人と集約役が1人の構成では、課題は4回、最初の回答は3回プリフィルされる。文脈をまたぐKVキャッシュ再利用は、共有区間のキーとバリューを新しい接頭辞の下で再計算せず予測することで、この重複を消す。KVCommは、区間を接頭辞なしで計算したキャッシュとの偏差をアンカーとして蓄積し、新しい区間の偏差を似たアンカーの重み付き和で予測する。エントロピーによるゲートで、予測がアンカーとよく合う場合だけ再利用し、70パーセント超の再利用率と最大7.8倍の初回トークン高速化を無損失で報告した。

本論文はこの報告を再測し、無損失ではないことを示す。まず隠れた費用として、MMLUとGSM8Kで再利用が大幅な精度損失を生む。固定した条件ではGSM8Kで13.7ポイント、MMLUで14.3ポイントの損失であり、ゲートを締めても、どの呼び出しを再利用するか選んでも、生成が始まってから判断を先送りしても消えない。次に判断の単位の問題として、情報を持つ選択の価値は単位が大きくなるほど落ちる。行単位では偶然を超えてキャッシュ誤差の49.5パーセントを除けるが、64トークンのチャンクでは10.6パーセント、呼び出し単位では消える。提案するBudgeted Cache Repair（BCR）はこの2つを踏まえ、再利用するかどうかを決めず、固定した予算でキャッシュの一部を正確に修復する。組み立て済みキャッシュから2トークンをドラフト生成し、そのドラフトが注意を向けた行の順位で選び、キャッシュの2割を正確に再計算する。代表結果として、GSM8Kでは固定条件で精度を71.0パーセントから84.3パーセントへ回復し、稠密プリフィルの84.7パーセントに並んだ。呼び出しの約63パーセントはキャッシュから提供したままで、初回トークンは稠密比で2.85倍速い。ただしMMLUでは回復は限定的で、損失の約半分はトークン化の差にあり修復の対象外である。

## 問題設定

再利用の仕組みは、区間のキャッシュが接頭辞に依存するという性質と衝突する。キャッシュの各行は接頭辞を通じて注意計算に依存するため、厳密な再利用には接頭辞の完全一致が要る。KVCommは偏差を予測することでこの条件を緩めるが、予測が正しいかどうかは生成前には分からない。ゲートが見るのはプロンプト側の幾何情報だけで、再利用が答えを変えるかどうかを直接は見ない。先送りする修正も、決定の時点を移すだけで、近似そのものを変えない。呼び出し単位の選択も同じで、誤りがキャッシュのごく一部の行に集中していても、呼び出し単位ではキャッシュ全体を信じるか全部捨てるかしかできない。つまり問題は「いつ、どの呼び出しを再利用するか」ではなく、「どの粒度で何を修復するか」である。本論文はこの転換を、方策の対照実験と選択価値の単位依存性で実証してから修復へ進む。

## 手法のあらまし

処理の流れは次の通りである。まずKVCommの仕組みで、再利用する区間ごとにアンカーとの類似度のエントロピーでゲートを判定する。ただしBCRはこのゲートの結果に精度を依存させない。組み立て済みキャッシュで生成を始めるとき、まず2トークンをドラフトとして生成し、その後ドラフトを巻き戻す。ドラフト生成で残したクエリ行が各キャッシュ行へ向けた注意を集計し、行ごとのスコアとする。次に予算としてキャッシュ行の2割を上限に、スコアの高い行または行の集まりを、元の位置で正確に再計算する。修復したキャッシュで生成を始め、ドラフトのトークンは再生成される。レイアウトは3種類で、固定64トークンのチャンク、スコアの高い行を種にして隣接行へ伸ばす成長スパン、行を1本ずつ選ぶ個別行である。3つは行数が互いに12パーセント以内に収まるよう予算を合わせ、比較が予算の大小ではなく単位の差になるよう設計されている。

## 手法

### 1. ゲートとその限界の実測 — 信頼判断では損失が消えない

入力は再利用候補の区間と蓄積されたアンカー群である。KVCommのゲートは、候補と各アンカーとの値空間でのL2距離をソフトマックスで重み付けし、その分布のエントロピーを最大エントロピーに対する割合の閾値で判定する。尖った分布は候補が特定のアンカーに近いことを意味し、そのアンカーの偏差が転用できると期待される。観測対象は、ゲートを締めたときの精度と再利用率の関係である。実測では、ゲートを締めるほど精度は下がりこそすれ稠密へ戻らず、無条件の再利用と稠密を結ぶ1本の直線上を動くだけだった。生成開始後に2トークンのドラフトの信頼度で判断するOpenGateも、固定条件で6.7ポイントの損失を出し、有意に負ける。つまりゲートは再利用率と精度の交換位置を動かすだけで、近似そのものの誤りには届かない。この実測が、判断から修復への転換の根拠になる。失敗条件として、アンカープールの温まり具合で最初の評価ブロックだけ再利用が負けないという見かけの例外もあり、短い評価では費用が見えないことが示されている。

### 2. 単位の価値曲線 — 選択が効くのは細かい単位だけ

入力は2048トークンの再利用区間と、名目2割の修復予算である。保持する状態は、行・チャンク・呼び出しという単位の選択結果と、無作為選択での対照結果である。実験では、行を単位に注意で選ぶと偶然を超えて49.5パーセントの誤差が除け、64トークンのチャンクでは10.6パーセント、1024トークンではマイナス5.7パーセントと、単位が粗くなるほど選択の価値が落ちる。呼び出し単位の選択は、5種の配分方策で測っても、再利用率で決まる直線上から1.6ポイント以内しか離れず、無作為な方策ですら構造的な方策と同等か上回る。これは誤りの集中の仕方で説明される。区間の中では注意の質量が極端に偏るため行の間には選ぶ甲斐があるが、呼び出しの間では候補が同じ形のプロンプト全体であり、選ぶ差が小さい。この曲線が、修復の単位をチャンク以下に置く理由になる。ただしチャンク単位での選択価値は行単位の約5分の1しかなく、修復の利得の大部分は「選ぶこと」ではなく「修復すること」から来ると予測される。この予測と課題レベルの実測が食い違う点も、論文が数値で追っている。

### 3. ドラフトによる行選択 — 生成そのものに選ばせる

BCRの核は、ドラフト生成をゲートではなく選択子として使うことである。組み立て済みキャッシュで2トークンを生成し、各層で直近のクエリ行が予測キーへ向けた注意を集計して行スコアとする。第1層を除く全層の平均であり、グループ化クエリの場合はクエリヘッドへ展開する。スコアが決まっているのは疑わしい予測キー側のテンソルであるという点が重要で、信号は信じる対象そのものから読んでいる。ドラフトは生成後に巻き戻され、修復も実生成も元のキャッシュから始める。ドラフトのトークンは修復後のキャッシュで再生成されるため、同じになるとは限らない。追加費用はドラフトの2ステップと修復の再計算であり、無作為選択の対照はドラフトを飛ばすため、BCRが対照と同等ならそれは勝利ではなく敗北になる設計である。失敗条件は、ドラフトのクエリ行が2行しかないことで、論文はドラフト長を掃引せず、2トークンという1つの答え側クエリ行の価値の見積もりとして結果を読むよう釘を刺している。

### 4. 3つの修復レイアウト — 固定チャンク、成長スパン、個別行

予算の使い方には3つの形がある。固定チャンクはキャッシュを64トークンの区切りへ分け、平均スコアの高いチャンクから予算分だけ再計算する。区間がKVCommのデータ構造と相性が良く、オフセットやアンカーの選別、位置回転が連続区間を前提にしているためである。成長スパンは固定単位を捨て、最もスコアの高い行を種にして、隣接行のスコアが種の25パーセント以上ある限り区間を伸ばす。長さと位置はスコア面に従う。個別行は集まりを捨て、予算を1行ずつ使う最も細かい単位である。3つのレイアウトは1回の呼び出しで再計算する行数が互いに近いため、比較は予算の大小ではなく単位の差になる。課題レベルでの順序はベンチマークで変わり、GSM8Kでは個別行が先行し、MMLUでは順序が反転して弱まる。つまり最適なレイアウトは単一ではなく、選択価値の単位依存性が課題ごとに現れる。

## 評価

### まず見るところ

- **結論:** 再利用の精度損失は、ゲートや呼び出し選択では消えず、固定予算の修復でGSM8Kでは稠密水準まで回復する。MMLUでは損失の約半分がトークン化にあり、修復では届かない。
- **速度・効率:** 修復は遅延と交換である。4096トークンの合成区間での初回トークンは、稠密542.7ミリ秒、再利用72.9ミリ秒、修復190.1ミリ秒で、修復は稠密比2.85倍、再利用比では2.6倍遅い。
- **品質:** 近似手法である。修復はGSM8Kの固定条件で13.7ポイントの損失のうち13.3ポイントを回復し、対にした不一致は9対49で有意である。MMLUでは3.0ポイントの回復にとどまり有意ではない。
- **評価の強さ／注意点:** 統計は、同じ問題を同じ条件で解く対にした比較に基づき、正確マクネマー検定を使う。グリッドの4セルをまたいだ集計は、同じ問題の繰り返し測定になるため検定には使わず、記述として扱う。撤回した集計検定も付録に記録されている。
- **再利用率:** 固定条件での修復時の再利用率は0.629であり、呼び出しの約63パーセントがキャッシュから提供されている。

**数値の読み方。** 固定条件と参照グリッドの数値は別物である。参照グリッドでは各セルが150から160問で有意差はなく、方向だけが読める。主張の統計的根拠は300問の固定条件の単発実行にある。また、MMLUの参照列は、分析エージェントがウィキペディアへの生取得を差し込むため当初は再現性がなく、取得を切ったオフライン条件で再測されたものであることも、数値の出所として重要である。

## 既存研究との差

プリフィックスキャッシュとPrompt Cacheは、再利用の適用範囲を広げる方向だった。CacheBlendは独立にキャッシュされたチャンクを、選択したトークンの再計算で修復するが、対象は検索拡張生成のチャンク融合である。KVCommは偏差の予測とゲートで信頼判断をする。BCRの差分は、信頼判断をやめて固定予算の修復へ切り替えたことと、選択の対照実験を入れたことにある。クエリからの注意で再計算対象を選ぶ近年の方式と比べても、BCRは「選ぶことの価値」を無作為選択との対照と単位の関数で測り、選択が効く単位と効かない単位を分けた点が異なる。ドラフト生成も、投機的デコードの提案としてではなく、修復対象の選択子として使う転用である。

## 限界・実装状況

著者自身の付録が挙げる制約として、標本サイズ、遅延、証拠の及ぶ範囲がある。単一のトポロジと単一のチャンクサイズ、単一のGPUでの測定であり、他の再利用システムへの一般化は示されていない。修復は遅延と交換であり、再利用の7.63倍の高速化に対し2.85倍へ落ちる。MMLUの損失の約半分はトークン化にあり、修復では届かない。ドラフト長は2で固定され、最適予算も掃引で決められていない。レイアウトの順序はベンチマークで変わり、万能な1つはない。公式コードの公開先は論文中に示されていないが、評価は公開実装を土台にしている。

## 一般的な実装上の含意

キャッシュ再利用の設計では、「再利用するかどうか」という二値の判断に精度を頼らせるのではなく、固定予算で「どこを直すか」という設計へ切り替える価値がある。選択の価値は単位の関数であり、行単位で効いても呼び出し単位では消えるため、選択の主張には単位を付けて読むべきである。選択的再計算の評価では、無作為選択を同じ予算で対照に置くことで、修復そのものの寄与と選択の寄与を分離できる。さらに、再利用経路でのトークン連結が入力そのものを変える場合、精度損失がキャッシュの近似ではなくトークン化に由来することを、トークン一致の対照で切り分けられる。
