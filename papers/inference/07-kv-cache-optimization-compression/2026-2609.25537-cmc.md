# CMC：回答整合の長文記憶埋め込みと二層KVによる推論

## 概要

長文脈の質問応答では、原文をすべてデコーダへ渡すと事前計算の注意演算とKVキャッシュ容量が大きくなる。文脈を単純に短くすると計算は減るが、質問に必要な証拠が消える。CMC（Context-to-Answer-Aligned Memory Compression）は、長文を少数の連続的な文脈記憶埋め込み（Context Memory Embeddings、CME）へ変換し、質問に関連する記憶と原文の局所窓を組み合わせて凍結したデコーダへ渡す方式である。

圧縮器とデコーダのモデル系列が異なっても使えるよう、ContextEncoderが作るCMEをMemoryBridgeがデコーダの入力埋め込み空間へ投影する。学習は二段階で、最初に文脈再構成によってデコーダとの整合を取り、次に正解回答を使った交差エントロピー、教師デコーダ分布とのKL距離、回答スパンとの対照学習を組み合わせる。推論時は質問とのコサイン類似度でCMEを選び、局所原文窓と一緒にデコーダへ渡す。

9通りのエンコーダ・デコーダ組合せと4種類の抽出型質問応答データセットで評価する。Llama-3 8Bの全データSQuADでは完全一致率（EM）が48.28から55.56へ7.28ポイント上がるが、**Mistral-7Bでは45.36から30.67へ14.69ポイント下がる**。したがって抄録の「一貫して改善」という表現を、すべてのデコーダ・条件で品質が上がる保証として扱ってはいけない。

システム評価では、SQuADの1,000サンプル、3,000生成トークン条件で合計推論時間が41,963秒から33,562秒へ約20%短縮する。Llamaの予約GPUメモリピークは19.7GBから9.8GBへ約50%減り、付録のMistral条件では24.3GBから9.1GBへ62.5%減る。ただし圧縮器の費用、デコーダ、評価条件によって効果が変わり、実運用では局所窓の位置特定が必要になる。

## 問題設定

長文脈を扱う通常の自己注意では、文脈長が増えるとプリフィルの計算量が大きくなり、生成中のKVキャッシュは保存するトークン数に比例して増える。ハード圧縮は不要と判定した原文トークンを削るため、重要な固有名詞や証拠が除去されると後で復元できない。ソフト圧縮は複数トークンを連続埋め込みへまとめるが、質問と無関係に全記憶を渡したり、回答ではなく文書再構成だけを教師としたりすると、質問応答の品質を十分に守れない場合がある。

CMCはこの問題を、文書全体を記憶へ圧縮する段階と、質問に応じて必要な記憶を選ぶ段階へ分ける。さらに局所原文窓を残し、圧縮表現だけでは失いやすい細部を保つ。推論時の入力は、選択したK個のCME、Wトークンの局所窓、質問qの連結である。文書全体のトークンを直接デコーダへ入力しないことで、長い履歴に対する注意計算とKV保存量を抑える。

一方、この構成には明確な制約がある。局所窓が回答の存在する位置を含まなければ、重要な証拠を失う可能性がある。原著の主実験では**正解回答スパンの位置情報を使って局所窓を中心化**しており、通常の本番推論で未知の正解位置をどう見つけるかは別問題である。論文はBM25やCME誘導の位置特定を代替案として示すが、主要評価の品質・費用をそのまま本番へ移せるとは限らない。

## 手法

### 1. グラフに基づく文脈の雑音除去

まず原文トークンを埋め込み空間で比較し、近傍の後続gトークンとのコサイン類似度がしきい値τに達しない孤立したトークンを除去する。これは単純な頻度フィルタではなく、局所的な意味的つながりを持つトークンを残す前処理である。残った系列を長さtの重ならないチャンクへ分割し、それぞれに固定の記憶プレースホルダーをm個付加する。

1チャンクの元トークン数tを記憶トークン数mで割ったr=t/mが圧縮率の設定であり、原著はr=2、4、8を比較する。rを大きくすると少ないCMEで長い文書を表せるが、個別情報の損失が増える。雑音除去のしきい値が高すぎると必要な根拠まで除去する危険があるため、圧縮率とともに品質へ影響する。

### 2. ContextEncoderによるCME生成

ContextEncoderは学習可能な因果言語モデルで、チャンクと記憶プレースホルダーを一緒に処理する。プレースホルダーの最終隠れ状態を取り出すことで、その前にあるチャンク内容を少数のベクトルへ集約する。プレースホルダーのトークン自体は固定でも、ContextEncoderの重みが学習されるため、その隠れ状態は回答に有用な表現へ変化する。

チャンクごとのCMEを連結すると、長文全体の記憶行列ができる。原文の各トークンをそのまま保存するのではなく、各チャンクを少数の連続ベクトルで代表する。この段階のCMEはContextEncoderの隠れ次元を持つため、異なるデコーダへそのまま渡せるとは限らない。次のMemoryBridgeでモデル間の埋め込み空間を合わせる。

### 3. MemoryBridgeによる異種デコーダへの投影

MemoryBridgeは2層の多層パーセプトロン（MLP）で、ContextEncoderのCMEを凍結デコーダの埋め込み次元へ変換する。単に次元を合わせるだけでは、投影後のベクトルのノルムが通常のトークン埋め込みより大きくなり、デコーダが不安定になる可能性がある。そこでLayerNorm、tanh、デコーダ埋め込みの平均ノルムに基づく上限を組み合わせる。

原著の式では、投影後CMEのL2ノルムが、基準となる埋め込みノルムνの2倍を超えないようにする。これによりモデル系列の異なるContextEncoderとDecoderLLMを組み合わせられる。ただし「任意のデコーダへ接続できる」は重みを変更せずに接続可能という設計上の意味であり、任意のモデル対で同じ品質が出るという意味ではない。実験は3エンコーダ×3デコーダの9組合せである。

### 4. 二段階学習：再構成から回答整合へ

第1段階ではCMEを使って凍結デコーダに原文を再構成させる自己符号化（AE）損失と、原文前半を自己回帰的に復元するAR損失を組み合わせる。目的はCMEがデコーダの埋め込み空間で意味のある入力になるようにし、長文の情報を再構成可能な形で保持させることである。第1段階だけでは回答に重要な箇所が優先されるとは限らない。

第2段階では、同じ凍結デコーダを教師（educator）と学習側（learner）の両方に使い、入力条件だけを変える。教師は質問と局所原文窓を見て回答し、学習側はCMEと局所窓を見て回答する。正解回答トークンに対する交差エントロピー、教師・学習側の出力分布を合わせるKL距離、CME平均と教師の回答スパン隠れ状態を近づける対照損失を同時に最適化する。

デコーダの重みは両段階で固定され、ContextEncoderとMemoryBridgeだけを学習する。これはデコーダを再学習しないという意味では配備しやすいが、圧縮器の訓練や教師デコーダの呼出しには費用がかかる。原著の構成要素除去実験では、KL損失または対照損失を外すと第1段階のみと同じEMへ低下し、3つの第2段階損失の組合せが重要であることを示す。

### 5. 質問誘導の上位K記憶選択

推論時は質問を凍結デコーダの埋め込み層へ通して平均し、質問ベクトルを作る。各CMEとのコサイン類似度を計算し、上位K個を選択する。選ばれたCMEは元文書の出現順へ並べ直してデコーダへ渡す。これにより長文の全CMEを無条件に渡すのではなく、質問に関係する記憶を優先する。

Kが小さすぎれば重要な情報を選び漏らし、大きすぎればデコーダの注意負荷と無関係な記憶が増える。原著の比較では、同数のCMEを無作為に選ぶとSQuADのEMが0.670から0.589へ下がる。単にCMEの数を制限するだけでなく、質問との関連性に基づく選択が重要である。

### 6. 局所原文窓と二層KVキャッシュ

第1層（Tier-1）は質問に関連するCME、第2層（Tier-2）は長さWの原文トークン窓である。局所窓は回答の重要領域を高い解像度で残す役割を持つ。デコーダの入力は、選択CME、局所窓、質問を連結したものになる。長文全体を直接渡さないため、原著はデコーダへ入力するKVの基礎長をK+W+|q|に制限できると説明する。

ただし、この上界は原著が二層キャッシュの文脈側予算として記載する値であり、生成した出力トークンを保持する通常の実装すべてでKV容量が増えないと一般化するのは危険である。実測では生成トークン数が増えてもCMC側の予約メモリがほぼ一定であると報告するが、具体的なキャッシュ管理実装に依存する。

局所窓の中心位置αは主実験ではベンチマークの正解スパン注釈、または原文内の文字列一致から得る。これは質問を受けた時点で正解位置が未知の本番運用と異なる。原著は位置特定をBM25やCME誘導検索で代替できると述べるが、その検索の誤差・時間・費用を主結果へ無条件に織り込んでよいわけではない。

| 全データ設定 | SQuAD EM：比較→CMC | HotpotQA EM：比較→CMC | AdversarialQA EM：比較→CMC |
|---|---:|---:|---:|
| Llama-3 8B | 48.28 → 55.56（+7.28） | 44.31 → 47.77（+3.46） | 32.47 → 35.43（+2.96） |
| Mistral-7B | 45.36 → 30.67（**−14.69**） | 53.41 → 48.33（−5.08） | 26.37 → 29.77（+3.40） |

LlamaとGemmaはこの条件で3課題とも改善する。一方MistralはSQuADとHotpotQAで明確に悪化する。著者らは、全データ設定では第1段階の学習ステップが約8.8倍増えるのに、第2段階の知識蒸留ステップ数が固定のため、Mistralが学習段階間の不均衡に敏感になった可能性を説明している。これは原因の仮説であり、すべての失敗を確定的に説明した実験ではない。

小規模制御設定では、LlamaのSQuAD EMが62.4→67.0、HotpotQAが44.1→49.6、CovidQAが22.5→29.5となる。GemmaでもSQuADが55.1→61.1、HotpotQAが40.1→42.0と改善する。ただしMistralのSQuADは61.0→60.2とわずかに悪化する。原著の「大部分の条件で改善」を「全条件で改善」と読み替えないことが重要である。

公開済み別方式との比較では、CMCは3課題のF1で最良だが、SQuADのEMはPCC-Large 60.04に対しCMC 55.56、AdversarialQAはPCC-Large 39.37に対しCMC 35.43で劣る。各方式のデコーダ構成が異なるため、単純に圧縮方式のみの因果的な優劣とは言い切れない。

### 圧縮率の感度

CMEの圧縮率r=2は、記憶数が多すぎて質問と無関係な情報が上位記憶列へ混ざり、9組合せで最も低い性能となる傾向がある。r=8はCMEが少なくなりすぎて長文の重要情報が失われやすい。中間のr=4が9組合せ中6組合せで最良または同率最良のEMとなる。圧縮率を高くすれば必ず良いわけでも、記憶数を増やせば必ず品質が上がるわけでもない。

### 実時間・エネルギー・メモリ

| SQuAD、1,000サンプル | 主比較 | CMC | 差 |
|---|---:|---:|---:|
| 512生成トークンの総時間 | 6,043秒 | 5,763秒 | 約4.6%減 |
| 3,000生成トークンの総時間 | 41,963秒 | 33,562秒 | 約20.0%減 |
| 3,000生成トークンのエネルギー | 原著の比較値 | 原著のCMC値 | 約20.3%減 |
| Llama、3,000トークンの予約GPUメモリピーク | 19.7GB | 9.8GB | 約50.3%減 |
| Llama、割当GPUメモリピーク | 約10.2GB | 約8.85GB | 約1.35GB減 |
| Mistral、予約GPUメモリピーク | 24.3GB | 9.1GB | 約62.5%減 |

予約メモリ（reserved）と実際に割り当てられたメモリ（allocated）は異なる指標である。Llamaの予約メモリはほぼ半減するが、割当メモリの差は約1.35GBである。予約メモリ50%削減を、GPUの全用途に対する実使用量が50%減ったと断定してはいけない。また、Mistralの62.5%削減は付録の特定条件であり、抄録の最大50%と単純に矛盾するものではない。

圧縮工程の時間は生成トークン数に対してほぼ一定の約25秒で、長い生成ほど復号段階の節約がその費用を上回りやすい。短い生成では総時間削減が4.6%にとどまり、3,000トークンで20.0%となる。したがって短い質問応答や圧縮対象文書が小さい場合には、前処理費用に対して利得が小さい可能性がある。

局所窓を除くとEMが0.670から0.170へ急落する。つまりCMEだけで正解に必要な細部を完全に保持できているわけではなく、原文局所窓への依存が非常に大きい。この事実は、実運用で正解位置が未知の場合に位置特定が重要な理由でもある。雑音除去を除いてもEMが大きく低下し、質問誘導選択や第2段階の各損失も品質に寄与する。

## 既存研究との差

LLMLingua系のハード圧縮は不要な原文トークンを除去するのに対し、CMCは連続的な記憶埋め込みへ圧縮する。AutoCompressorやICAEなどのソフト圧縮は、文書再構成を中心とする場合がある。CMCは回答対象の教師信号と質問誘導の記憶選択を組み合わせる点が異なる。PCC系の異種モデル間投影とも異なり、質問依存の上位K選択と二層KV窓を明示的に備える。

ただし、他方式との公開ベンチマーク比較は使用デコーダが完全に揃っていない場合がある。差がすべて圧縮アルゴリズムの効果と証明されたわけではない。また、二層KVの局所窓は正解スパン位置を利用するため、通常の質問応答サービスで同じ前提を用いることはできない。

## 限界・適用条件

第一に、主実験は英語の抽出型質問応答4課題に限られる。自由形式の文章生成、要約、検索拡張生成（RAG）、コード生成、多言語文書、訓練と評価で異なるデータセットへの転用は未検証である。圧縮器の学習は各ベンチマーク内で行われており、未知領域へそのまま一般化するとは言えない。

第二に、局所窓は主実験で正解回答の位置情報を利用する。比較対象にも同じ位置情報を使うため、論文内の比較条件としては揃っているが、未知の質問に対する本番推論では正解位置は通常わからない。BM25やCME誘導検索による位置特定を別途行うと、検索の誤差・遅延・費用が増える。局所窓を除くとEMが0.670から0.170へ低下するため、位置特定は小さな実装詳細ではない。

第三に、デコーダごとの品質は一様でない。Mistral-7Bの全データSQuADではEMが45.36から30.67へ14.69ポイント悪化し、HotpotQAも53.41から48.33へ低下する。学習段階間のステップ配分、圧縮率、モデルの埋め込み特性が変われば、他の組合せでも再校正が必要である。

第四に、予約メモリの削減と割当メモリの削減を区別する必要がある。Llamaの3,000トークン条件では予約メモリが19.7GBから9.8GBへ減るが、割当メモリは約10.2GBから8.85GBへの減少である。実際の収容可能な同時要求数やGPU使用料金が同じ比率で改善することを保証するものではない。

第五に、圧縮器の学習と推論時の前処理は無償ではない。凍結デコーダへ接続できても、ContextEncoderとMemoryBridgeの学習が必要で、圧縮工程の約25秒が短い生成では利得を相殺し得る。原著の生成トークン数が大きい条件での20%削減を、短い対話へそのまま適用しない。
