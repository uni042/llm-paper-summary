# FastOCR：文書認識中の視覚注視を追跡して注意計算だけを減らす

## 概要

この研究が対象にするのは、視覚言語モデル（Vision-Language Model、VLM）にスキャン文書、数式、表、多段組みなどを入力し、光学文字認識（Optical Character Recognition、OCR）や文書構造解析を逐次生成させる場合の**生成段階の自己注意計算**である。文書には細かな文字や罫線が広範囲に分布するため、一般画像の物体認識より多数の画像トークンが必要になる。画像トークンを初回入力処理（prefill）で削除すると、後続の生成で読みたくなった箇所を二度と参照できず、文字列や表の内容が壊れる。

著者が観測した重要な違いは、「文書全体で不要な画像トークン」と「**ある生成ステップで一時的に参照しなくてよい画像トークン**」を区別できる点である。文書のすべての領域は後で必要になり得るが、ある単語を出力する瞬間の注意はその単語周辺に集中し、次の出力で少しずつ移動する。この動的視覚注視（Dynamic Visual Fixation）を利用すれば、鍵・値キャッシュ（Key-Value cache、KVキャッシュ）を丸ごと残したまま、各ステップの注意対象だけを減らせる。

FastOCRは追加学習不要で、焦点層誘導型の枝刈り（Focal-Guided Pruning、FGP）とステップ間注視再利用（Cross-Step Fixation Reuse、CSFR）を組み合わせる。焦点層は全画像トークンを参照して重要な画像位置を更新し、その他の層はその部分集合だけを参照する。さらに前ステップの焦点集合を次ステップの初期集合に使う。これによって文字を読む場所の移動に追随し、静的な画像削除と異なる精度・速度の交換関係を得る。

Qwen2.5-VLでは画像トークンの保持率5%でOmniDocBench総合スコア72.76から71.34（98.0%保持）となる。H800上の別の速度測定条件では、注意処理遅延26.00→8.69ミリ秒（2.99倍）に対して、生成1ステップ全体は54.15→38.69ミリ秒（1.40倍）である。**注意演算の倍率をシステム全体の倍率に読み替えてはいけない。** また、全KVを保持するためピークGPUメモリ削減を主張する手法ではない。

## 問題設定：なぜ従来の画像トークン削除はOCRで破綻するか

### 恒久的な削除と一時的な非参照は異なる

一般の視覚トークン削減では、画像符号器の出力、あるいは言語モデルの初回入力処理時に重要度の低いトークンを捨てる。自然画像について「犬がいるか」を答えるなら背景の細部を失っても正答できることがある。しかし文書の転写では、画像内の各文字が最終出力のいずれかの位置に対応し得る。文書の右下の一語は、冒頭の出力時にはほぼ無関係でも、後半の出力では不可欠になる。初回入力処理時にそれを消した方式は、後から復元できない。

論文の図1は、画像トークンを恒久削除した結果として施設名の文字列が別の語へ誤読される例を示す。これは単に重要度スコアの精度が悪いというより、**生成前に全時点共通の保持集合を決める設計**と、逐次読み進めるOCRの要求が一致しないことによる。FastOCRでは画像KVの実体を残し、計算に参加させる画像位置だけをステップごとに選ぶため、前に見なかった領域を後のステップで再び選べる。

### 画像を見る層は全層に均等に分布しない

もう一つの観測は、Transformerの層ごとに画像トークンへ割く注意質量が大きく異なることである。著者のOmniDocBench上の測定では、焦点層の画像注意比率が平均42.2%、非焦点層が14.3%であり、約3倍の差があった。図3の50ステップの可視化では、画像への注意が高い層は生成中もおおむね固定される。特に文書OCRでは、中間から後段の層に焦点層が多い。自然画像のFastVで浅い層に画像注意が集中するという観測を、そのまま文書OCRへ適用できない。

全層が毎回全画像を参照する必要はないが、どの層が画像の重要位置を見つけるかは重要である。そこでFastOCRは一部の層を「全画像から重要位置を探す担当」に固定し、その他の層を「直前の担当層が選んだ位置だけを読む担当」に分ける。これは層の重みやネットワーク構造を削る方法ではなく、**層ごとに注意の参照先を切り替える**方法である。

## 手法

### 1. 生成冒頭の観測から焦点層を決める

モデルの層数をL、生成ステップをtとする。最初のwステップは画像トークンを削らず通常の注意を実行する。この短い観測区間で各層・各ステップの注意重みを頭方向に平均し、画像トークン集合Iへ向いた注意質量を、画像IとテキストTへ向いた注意質量の合計で割る。原著式(1)の画像注意比率は次の形である。

`r_i^(t) = sum_{j in I} a_bar_ij / (sum_{j in I} a_bar_ij + sum_{j in T} a_bar_ij)`

この値をwステップで平均して各層を降順に並べ、上位およそ `floor(rho * L)` 層を焦点層集合Cへ採用する。ただし近接層は似た画像領域を見る傾向があるため、選択済み層から距離g以内の候補は除外する。こうして焦点層を深さ方向へ分散させ、異なる画像領域を観測する機会を確保する。原著の標準設定は焦点層比率rho=0.1、間隔g=1、観測ステップ数w=10である。

この焦点層集合は生成中に繰り返し更新しない。したがって毎ステップの層選択費用は不要になるが、文書内容が大きく変化した際に最適な層集合へ適応する能力は制限される。なおw=0では入力処理段階の注意から焦点層を選ぶことになり、後述の構成要素除去実験で精度が低下している。**生成中の観測**であることが設計上の重要条件である。

### 2. 焦点層で全画像を参照し、非焦点層へ選択集合を渡す

観測区間終了後、焦点層 `l in C` ではその層の全KVキャッシュに対する注意を計算し、画像トークンN個から注意重みの高い上位 `ceil(tau*N)` 個を選ぶ。tauは画像保持率で、標準設定では0.05である。テキストトークンはこの選択で削らない。新しい参照集合Kは「全テキスト位置Tと、その焦点層で選んだ画像位置Fの和集合」とする。

次の焦点層に到達するまでの非焦点層は、全画像ではなく直前の焦点層から渡されたKだけを参照して注意を計算する。次の焦点層へ到達すると、その層は再び全KVを読んで新しい画像上位集合を選び、Kを更新する。この繰り返しにより、層深さ方向に**全画像探索→局所注意→全画像探索→局所注意**の順序が形成される。原著式(2)は焦点層と非焦点層で注意入力のK/Vを切り替えることを明示している。

焦点層を完全に省略したり、非焦点層のパラメータを削ったりするわけではない。全層の順伝播を維持し、各層の注意が参照する画像KVの位置数を減らす。焦点層での全画像走査は依然として必要であり、rhoを大きくするとその費用が増える。反対にrhoを小さくし過ぎると新しい視覚位置を見つける機会が減る。tauを小さくするほど計算は減るが、重要な文字領域を取りこぼすリスクが上がる。

### 3. 最初の非焦点層を前ステップの注視集合で初期化する

多くのモデルでは最初の層0は焦点層ではない。ここには「直前の焦点層」が存在しないため、単純に上記の深さ方向の伝搬だけを実装すると、最初の層で全画像を読むか、初期集合を別途推定する必要がある。FastOCRはステップ間注視再利用（CSFR）でこれを解決する。

各ステップの終わりに、最も深い焦点層が選んだ画像集合を `F_last` として保存する。次のステップ開始時、層0が非焦点層なら `T ∪ F_last` を初期参照集合として用いる。その後、最初の焦点層に到達した時点で新しい注意重みから画像集合を再選択する。文字列の出力は通常隣接領域へ進むので、前ステップの注視位置が次のステップの有効な初期値になるという設計である。

この仕組みは前ステップの画像トークン集合を永続的な保持集合に固定するわけではない。焦点層が次ステップで全画像を見直せるため、注視が大きく移動した場合も新しい位置を選択できる。ただし最初の焦点層へ到達するまでの非焦点層は古い注視位置を使うので、極端に急な視点移動では品質が落ちる可能性がある。原著はそうした条件を網羅的には検証していない。

### 4. 一つの要求の処理順と保持する状態

一要求の処理を時系列で整理すると、(a)画像とテキストを入力して全KVを構築、(b)最初のw生成ステップで全層の画像注意比率を測定、(c)平均比率と層間隔から焦点層集合Cを固定、(d)各生成ステップの開始で前回の最深焦点層の画像集合を再利用、(e)焦点層では全画像を走査して上位画像位置を更新、(f)非焦点層では選択位置と全テキスト位置だけを参照、(g)最深焦点層の集合を次ステップ用に保存、という流れになる。原著付録Aの擬似コードはこの順序を示す。

実装上保持すべき状態は、全KVキャッシュ、焦点層の識別集合、各層間で渡す参照位置集合、次ステップ用のF_lastである。画像KVの実体を削除しないため、実行時の主な利得はGPUメモリ**容量**ではなく、注意計算の読み出し量・演算量・遅延の削減にある。追加費用として、観測区間の注意統計、焦点層での全画像注意、上位選択処理、参照位置の管理が発生する。論文はこれらを含む実測生成ステップ遅延を表2に報告しているが、各管理処理の独立した絶対時間をすべて切り分けてはいない。

## 評価条件と比較方法

| 項目 | 一次論文で確認できる条件 |
|---|---|
| 主な評価対象 | Qwen2.5-VL 3B、dots.ocr 1.7B |
| 追加モデル | DeepSeek-OCR 3B、olmOCR 7B、LLaVA-OneVision 7B |
| 評価資料 | OmniDocBench、olmOCR-Bench。文字ブロック、数式、表、読み順などを含む |
| 比較方式 | FastV、VisionZip、H2O、PyramidKV、削減なし（Vanilla） |
| 比較の合わせ方 | 自己注意の1ステップ当たり理論FLOPsを一致させるように各比較方式の枝刈り予算を調整 |
| GPU | NVIDIA H800。原著は各ベンチマークの1回の評価に約5時間と記載 |
| 標準パラメータ | rho=0.1、g=1、tau=0.05、w=10 |
| 汎化比較のパラメータ | rho=0.2、tau=0.2（品質優先） |
| 速度測定条件A | Qwen2.5-VL、バッチ12、入力4096/生成1024トークン |
| 速度測定条件B | Qwen2.5-VL、バッチ4、入力8192/生成2048トークン |
| 理論FLOPsの範囲 | 注意層の射影と注意演算。フィードフォワード層などは含まない |

OmniDocBenchの総合スコアは、文字・数式・読み順の編集距離を `1−Edit Distance` に変換した値と、表の構造類似度TEDSを組み合わせたものである。編集距離は小さい方が良く、TEDSは大きい方が良い。異なるベンチマークのOverallを同じ絶対精度尺度として比較しない。olmOCR-Benchの総合値はテストケースの合格率に基づく。

比較方式の枝刈り予算を単純な「保持トークン率」で一致させたわけではない。FastOCRでは一部の焦点層が全KVを参照するため、同じtauでも全層の計算量は一律tau倍にはならない。論文は付録Bで `b*l*(8h^2+4hs)` を1ステップの自己注意演算量の近似式として導き、主比較ではバッチ8・代表系列長4096を使う。この式の `8h^2` は各層のQ/K/V/出力射影、`4hs` は注意演算であり、全モデルの総演算量ではない。

## 評価結果

### 1. 同じ注意演算予算でOCR精度を保持する

| モデル・OmniDocBench | 条件 | 削減なしOverall | FastOCR Overall | 非削減時に対する保持率 | 同予算の比較例 |
|---|---|---:|---:|---:|---|
| Qwen2.5-VL | tau=0.25、注意12.88G FLOPs | 72.76 | 72.40 | 99.5% | VisionZip 63.41、FastV 10.69、H2O 7.88 |
| Qwen2.5-VL | tau=0.05、注意11.17G FLOPs | 72.76 | 71.34 | 98.0% | VisionZip 42.11、PyramidKV 14.89 |
| dots.ocr | tau=0.25、注意5.89G FLOPs | 85.45 | 84.31 | 98.7% | VisionZip 67.11、H2O 7.83 |
| dots.ocr | tau=0.05、注意4.92G FLOPs | 85.45 | 83.68 | 97.9% | VisionZip 40.60、PyramidKV 22.33 |

この比較から、同じ自己注意演算予算でも**永久に画像KVを捨てる方法**と**そのステップの参照先だけを制限する方法**では品質が大きく異なることが分かる。たとえばQwen2.5-VLのtau=0.05ではFastOCRが71.34点なのに対し、VisionZipは42.11点である。単に計算量を下げれば良いのではなく、将来の文字領域を回復可能にしておくことがOCRの品質保持に効いている。

一方、FastOCRも非削減時と完全一致ではない。表1のQwen2.5-VLでは数式編集距離が0.364から0.384へ、文字ブロック編集距離が0.158から0.175へ悪化する。dots.ocrでも表のTEDSが82.12から79.43へ下がる条件がある。総合スコアの高い保持率だけをもって、文字単位の誤りがゼロと判断してはいけない。

### 2. 注意処理と生成ステップ全体の速度は別々に評価する

| モデルと条件 | 指標 | 削減なし | FastOCR | 改善倍率 |
|---|---|---:|---:|---:|
| Qwen2.5-VL、バッチ12、4096/1024 | 自己注意の遅延 | 26.00 ms | 8.69 ms | 2.99倍 |
| 同上 | 生成1ステップの実時間 | 54.15 ms | 38.69 ms | 1.40倍 |
| Qwen2.5-VL、バッチ4、8192/2048 | 自己注意の遅延 | 17.70 ms | 7.96 ms | 2.22倍 |
| 同上 | 生成1ステップの実時間 | 44.55 ms | 37.45 ms | 1.19倍 |
| dots.ocr、バッチ12、4096/1024 | 自己注意の遅延 | 15.55 ms | 5.57 ms | 2.79倍 |
| 同上 | 生成1ステップの実時間 | 35.12 ms | 26.07 ms | 1.35倍 |
| dots.ocr、バッチ4、8192/2048 | 自己注意の遅延 | 10.62 ms | 5.51 ms | 1.93倍 |
| 同上 | 生成1ステップの実時間 | 28.83 ms | 24.95 ms | 1.16倍 |

理論的な自己注意FLOPs削減率より実測注意遅延の改善が大きい条件があるのは、GPUの生成処理が演算だけでなくKV読出しのメモリ帯域にも律速されるためと原著は解釈する。反対に、生成ステップ全体にはフィードフォワード層などFastOCRで削らない処理が含まれるので、注意だけの2～3倍改善が全体では約1.2～1.4倍に縮む。論文の表2は生成ステップの平均実時間であり、入力処理、通信、キュー待ち、最終出力までの全サービス遅延を統合したオンライン測定ではない。

### 3. 他モデルへの汎化には明確な性能差がある

汎化評価ではrho=tau=0.2へ変更して5モデルを比較した。Qwen2.5-VLは72.76→72.23（99.3%）、dots.ocrは86.06→84.05（97.7%）、olmOCRは71.87→69.70（97.0%）、LLaVA-OneVisionは16.06→15.04（93.6%）、DeepSeek-OCRは55.98→48.19（86.1%）である。つまり「どのモデルでも98%を維持」と一般化することはできない。特にDeepSeek-OCRでは保持率が86.1%に低下し、同一パラメータでもアーキテクチャによって品質への影響が異なる。

### 4. 構成要素除去実験は二つの機構の相乗効果を示す

Qwen2.5-VLのOmniDocBenchにおいて、FGPもCSFRも使わない単純な生成時枝刈りはOverall 24.09である。FGPだけを加えると51.22へ改善し、CSFRも加えると71.34へ改善する。非削減時は72.76である。この結果は、画像をよく見る層へ全画像走査を集約することだけでなく、前ステップの注視位置を最初の層へ渡すことが必要だと示している。

パラメータ感度では、画像保持率tau=0のOverallは16.46と大幅に悪化するが、tau=0.05で71点台へ戻り、それ以上の保持率を増やしても改善は緩やかになる。観測ステップw=0では61.35、w=5で70.98、w=10で71.34、w=20で71.50となる。入力処理段階の注意で焦点層を決めるより、少なくとも数ステップの生成中の注意で選ぶ方が良い。焦点層間隔gと比率rhoについては、論文が走査した範囲ではスコア変化が比較的小さい。

付録Fの層分布は、Qwen2.5-VLの34層のうち全サンプルを通して焦点に選ばれた層が10層、個別サンプルでは約6層であることを示す。層17・19・21・31・33は全サンプルで選ばれた。これは焦点層が比較的安定する根拠である一方、全モデル・全用途で固定層を使えるという証明ではない。

## 既存方式との差

FastVやVisionZipは、入力時または途中層で画像トークンを不可逆的に削除・統合し、後続生成で元の細部へ戻れない。H2OやPyramidKVは一般言語モデルの注意統計や層別予算からKVを削減するが、文書の文字領域が将来必要になるという視覚的・時間的性質を特別扱いしない。FastOCRは**全画像KVを保持したまま参照位置だけを動かす**ため、長い文字列を逐次読み進めるOCRで大きな違いが生まれる。

FlashAttentionやPagedAttentionはメモリアクセスやKV配置を効率化するが、原則として注意の意味的な参照集合を「読んでいる文字の位置」に応じて決めるものではない。FastOCRの貢献はキャッシュ配置の改善ではなく、生成ステップ・層ごとの注意対象選択である。実装時には既存の高速注意カーネルと併用できる余地があるが、論文はすべてのランタイム組合せについて統合ベンチマークを提供していない。

## 限界・負の結果・未評価事項

第一に、全KVを保持するため**ピークKVメモリ量は非削減モデルと同程度**である。長い入力をメモリに収められない場合や、GPUメモリ予算を減らして同時要求数を増やしたい場合の直接解決策ではない。原著付録Gは、効果が主に注意計算と読出し遅延へ現れ、メモリ容量の余裕には結びつかないと明記する。

第二に、焦点層集合は初期wステップの後に固定される。後続の文書構造変化に合わせて層集合を更新する方法は未提案であり、生成中に異なる種類の情報へ急に切り替わるタスクへの適用は今後の課題である。第三に、評価対象は主として高密度文書の転写・構造解析である。一般の場面文字認識、図表質問応答、グラフィカル操作エージェントなどへの汎化は未検証である。

第四に、5モデルの精度保持率は86.1～99.3%と幅があり、DeepSeek-OCRでは相応の低下がある。高い平均保持率の条件でも数式や表の細部に誤りが残る。第五に、原著の速度評価はH800での特定バッチ・系列長の生成ステップ測定であり、CPU・低VRAM環境、複数ノード、オンライン到着分布、要求ごとの最終完了遅延、消費電力、長期運用での安定性は示していない。単一ベンチマーク評価に約5時間を要した旨はあるが、統計的な反復測定の信頼区間は本文から確認できない。

最後に、コードの公開状況は慎重に扱う。論文は既存の公開モデル・ベンチマーク・比較方式を用いているが、今回確認したarXiv v1の本文からFastOCR専用の公式リポジトリURLは特定できなかった。`code: null` は公開コードが存在しないとの断定ではない。
