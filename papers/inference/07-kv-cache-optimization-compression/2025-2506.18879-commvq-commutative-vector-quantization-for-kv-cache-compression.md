# CommVQ: Commutative Vector Quantization for KV Cache Compression

> CommVQは、KVキャッシュを複数の符号帳ベクトルの和で表す加算型ベクトル量子化（additive vector quantization）を使い、特にキー側の符号帳を回転位置埋め込み（Rotary Position Embedding; RoPE）と交換可能になるよう学習する。これにより「圧縮KVをいったん全復号→RoPE→注意」という高価な経路を避け、符号帳を使った行列積へ注意計算を統合できる。LLaMA-3.1-8B-Instructでは2ビットでFP16 KV容量を87.5%削減し、LongBench平均48.05に対して47.98を維持する。1ビット級ではLongBench 44.94まで落ちるが、128K文脈を単一RTX 4090で実行可能にする。

## 概要

長文脈ではKVキャッシュ容量が系列長に比例して増える。スカラー量子化は各要素を低ビットへ丸めて容量を減らせるが、1〜2ビットでは誤差が大きくなる。ベクトル量子化（Vector Quantization; VQ）は特徴ベクトル全体を符号帳のインデックスで表すため、同じビット数でも表現力を上げられる一方、デコード時に符号帳からベクトルを復号する追加計算が必要になる。

キーにはもう一つ難しさがある。注意計算前にRoPEで位置回転されるため、圧縮した「RoPE前キー」を復元してから各位置の回転を適用すると、長文脈で復号コストが系列長に比例する。圧縮率を上げても毎トークン全KVを復号すれば実時間は悪化し得る。

CommVQは符号帳の構造をRoPE回転と交換可能に制約する。復号と位置回転の順序を代数的に入れ替えられるようにすることで、クエリと小さな符号帳を先に掛け、その結果をインデックスで集約する。保存量だけでなく復号演算の場所を変えるのが主要な工夫である。

## 問題設定

KV量子化では「ビット数を減らしたときの精度」と「圧縮形式を注意カーネルでどう使うか」を同時に解く必要がある。KIVIやKVQuantのようなスカラー系は実装が比較的単純だが、超低ビットでは量子化誤差が増える。VQLLMのような残差VQは表現力を高めるが、符号帳復号が追加される。

加算型VQでは一つのベクトルを複数符号帳エントリの和として表せるため、1つの符号帳だけより精密に近似できる。ただし符号帳数を増やすほど復号演算も増える。特にRoPEキーでは各トークン位置ごとの回転があるため、素朴復号は長文で高価になる。

## 手法

### 1. 軽量エンコーダでKVを加算型符号帳へ写像する

各KVベクトルを軽量エンコーダへ入力し、複数の小さな符号帳から選んだコードベクトルの和として表現する。保存するのは高精度ベクトルではなくコードインデックスである。

2ビット/1ビット級ではインデックス記憶が支配的に小さくなり、FP16キャッシュより大幅に容量を削減できる。値（Value）はこの加算型表現を比較的直接に使える。

### 2. キー符号帳をRoPEと交換可能に制約する

キーKへRoPE回転Rを掛ける通常注意では、圧縮表現をKへ復号してからRKを作る必要がある。CommVQは符号帳を特殊な構造にし、回転と符号帳復号の演算順序を交換できるようにする。

これにより、全トークンの高次元キーを復元してから注意を計算する代わりに、クエリと小さな符号帳の積を計算し、その結果をコードインデックスに従って集約できる。系列長に比例する高価な復号を避ける。

### 3. EMで離散インデックスと符号帳を共同学習する

交換可能性という構造制約があるため、通常のVQ学習をそのまま使うと近似精度が落ちる。CommVQは期待値最大化法（Expectation-Maximization; EM）を用い、ソフト割当から始めてアニーリングしながらインデックスと符号帳を最適化する。

校正にはFineWeb-Eduの部分集合を用いる。これは学習済みLLMの重みを再訓練するのではなく、KV分布を表すエンコーダ・符号帳を学習する事後圧縮である。

### 4. Tritonカーネルで復号と注意を融合する

理論上の交換可能性だけでは速度・メモリ削減は得られないため、論文はTritonカーネルを実装する。素朴実装では8K/32K/128Kで1層1トークンあたり2.4/9.2/36.6 msだが、最適化版は0.4/1.1/3.8 msとなり、それぞれ6.0/8.4/9.6倍速い。

この結果は「VQの量子化精度」ではなく「交換可能符号帳が実行時復号コストを下げる」ことを検証する。

## 評価

### 評価条件

| 項目 | 設定 |
|---|---|
| 主モデル | LLaMA-3.1-8B-Instruct、最大128K文脈 |
| 追加モデル | LLaMA-2系、Mistral系 |
| 符号帳校正 | FineWeb-Edu部分集合 |
| 圧縮 | 2-bit、1-bit級 |
| 比較 | KIVI、KVQuant、VQLLMの公式実装 |
| 長文評価 | LongBench、InfiniteBench、Needle-in-a-Haystack |
| 推論/推論能力 | GSM8Kも評価 |
| 実装 | Triton最適化カーネル |
| メモリ例 | H100-80GBで測定し、圧縮後はRTX 4090級単一GPUで128K実行可能と報告 |

### 主な結果

| 条件 | FP16 | CommVQ | 読み方 |
|---|---:|---:|---|
| LongBench平均 | 48.05 | 2-bit: 47.98 | 2-bitでは平均差0.07でほぼ維持 |
| LongBench平均 | 48.05 | 1-bit級: 44.94 | 「最小精度低下」でも完全無損失ではない |
| InfiniteBench平均 | 48.67 | 2-bit: 42.75 | 超長文では2-bitでも差が大きい課題群がある |
| InfiniteBench R.KV | 55.20 | 2-bit: 12.20、1-bit級: 0.00 | 正確なKV検索は強い圧縮で崩れる重要な負の結果 |
| KV容量 | 16-bit | 2-bitで87.5%削減 | 理論上8分の1相当のビット数 |
| 128K実行 | FP16では大容量 | 1-bit級でLLaMA-3.1 8BをRTX 4090単体へ | 容量削減の実用的な効果 |
| 1層1トークン、8K | 素朴VQ 2.4 ms | 最適化0.4 ms | 6.0倍 |
| 同32K | 9.2 ms | 1.1 ms | 8.4倍 |
| 同128K | 36.6 ms | 3.8 ms | 9.6倍 |

LongBenchではCommVQ-2が平均47.98で、KIVI-2の47.62、KVQuant-2の45.35、VQLLM-2の45.45を上回る。1-bit級でも44.94でVQLLM-1の27.42を大きく上回る。

一方InfiniteBenchでは、正確な情報検索を要求するR.KVがFP16 55.20に対して2-bit 12.20、1-bit級0.00まで落ちる。このため「1-bitでも最小限の精度低下」という要約は、平均・一部課題には当てはまっても、すべての長文検索能力が保たれるという意味ではない。

### 分布ずれとメモリ測定

論文はFineWeb-Eduで校正した符号帳をGSM8K、RepoBench-P、KV Retrievalなどへ持ち出し、パープレキシティ差を測る。2-bitではFP16比で+0.47〜+1.37程度の差を報告する。ただしパープレキシティは正確検索能力の崩壊を十分表さない場合があり、タスクスコアも併せて見る必要がある。

## 既存研究との差

KIVI/KVQuantは主にスカラー量子化で、VQLLMは残差ベクトル量子化を使う。CommVQは加算型VQで超低ビット表現力を確保しつつ、RoPEと交換可能な符号帳構造を導入する。

通常のVQでは「圧縮→全復号→RoPE→注意」となるのに対し、CommVQは小さな符号帳との計算を注意へ融合する。したがって差は量子化誤差だけでなく、デコード実行経路そのものにある。

## 限界・実装状況

- 1-bit級は平均性能をかなり維持するが、InfiniteBenchのR.KVなど正確検索では大きな品質低下がある。
- 符号帳はFineWeb-Edu部分集合で学習するため、未知分布への一般化は校正データ依存性を持つ。
- 低遅延化には専用Tritonカーネルが重要で、素朴復号では長文脈ほど費用が増える。
- メモリ削減とタスク精度は別軸で、128Kが「動く」ことと元品質が完全維持されることは同義ではない。
- 公式コードは https://github.com/UMass-Embodied-AGI/CommVQ で公開されている。

## 一般的な実装上の含意

KV量子化を1〜2ビットまで下げる場合、平均ベンチマークだけでなく「正確なキー検索」「長距離コピー」のような誤差へ敏感な課題を別に測る必要がある。平均値が近くても個別能力が崩れることがある。

またVQ方式ではビット数だけでなく復号カーネルが重要である。圧縮キャッシュを毎トークン完全展開する設計では、系列長が伸びるほど容量削減を計算オーバーヘッドが打ち消す。
