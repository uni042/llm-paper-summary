# Minimal-Intervention KV Retention via Set-Conditioned Diversity

## 概要

本研究は、長い思考過程を生成する言語モデルで、極端に少ないKVキャッシュを残す際の「どの過去トークンを保存するか」を対象とする。基準方式TriAttentionの保持重要度を変更せず、既に選んだトークンの値ベクトル（value vector; V）と重複する候補を次の選択で減点する、集合条件付き（set-conditioned）の保持選択器αを提案する。保存するK/V表現、注意ヘッドの振り分け、圧縮タイミング、生成方式は変えない。

論文はまず、キャッシュ表現・経路選択・圧縮頻度・生成制御・保持スコアという五つの変更軸にまたがる七つの案を検討し、採用できなかった理由を報告する。成功したのは最後のαだけであり、単に変更規模が小さいからではなく、保持集合が増えるたびに候補の冗長性が変化する点を重視する。数学推論MATH-500の独立確認集合で、DeepSeek-R1-Distill-Qwen-7BとDeepSeek-R1-Distill-Llama-8Bを各64/128トークンの保持予算で評価し、4条件中2条件が多重比較補正後も有意に改善した。ただし改善は**正解率の百分点差**であり、生成速度の倍率ではない。

## 問題設定と既存方式

KVキャッシュは自己注意の過去トークンの鍵と値を保持し、復号中に同じ過去位置を再計算しないためのものである。長い推論列では生成するたびにキャッシュが増え、層数・ヘッド数・トークン数に比例して記憶容量を消費する。小容量に制限する場合は古いトークンを削るが、数学的推論では序盤の定義や途中の計算結果を後から参照することがあり、誤った削除が最終解答を壊す。

TriAttentionの基準スコア「1d」は、事前に集めた問い合わせ・鍵の周波数統計から各過去位置の重要度s_iを算出し、得点の高いk位置を独立に選ぶ。通常の上位k件選択（top-k）は各候補の得点だけを見るため、類似した内容のトークンが上位を占める場合でも、それらをまとめて残しうる。これに対し本研究は、**高得点でも、既に選んだVと似ているなら追加情報が小さい**という仮説を検証する。

評価方法自体にも難しさがある。入力末尾のキャッシュ長だけを揃えても、復号中に再圧縮しない方式は長い生成の間にキャッシュを何倍も使える。論文は一部方式が名目予算の約5倍を消費しうると指摘し、全生成ステップを通じた平均キャッシュ長を合わせる。さらに少数問題での偶然の正解差や、調整に使った問題での再評価による過大評価を避けるため、開発集合と確認集合を固定して分離する。

## 手法：集合条件付きの値ベクトル多様性

### 基準スコアとV署名の構築

各圧縮イベントで、現在の候補トークン数n、保持予算k、TriAttention 1dが返す重要度ベクトルsを受け取る。αはこのsを再学習・再校正しない。代わりに候補iの全層・全注意ヘッドの値ベクトルV_i^(l,h)を平均してu_iを作り、L2ノルムで正規化した署名v_iを計算する。各署名は同じ次元dのベクトルであり、二つの署名の内積を余弦類似度として使える。

層・ヘッドの平均は簡潔な実装だが、どの層の情報が重要かを区別しないという制約も持つ。著者は学習可能な署名やヘッド別署名を実験で確定したとは主張せず、将来の変更余地としている。ここで重要なのは、元の鍵・値テンソル自体を量子化・再配置せず、**保持位置の選択のためだけ**に署名を使う点である。

### 既選択集合に依存する限界利得

最初の1トークンは元のsが最大の候補を選ぶ。以降、既に選んだ集合S_tを参照し、候補iの限界利得を「s_i − λ × max(0, S_t内のv_jとの最大余弦類似度)」として計算する。λは冗長性罰則の強さである。類似度が負の場合に追加ボーナスを与えないよう0で下限を設けるため、反対向きのベクトルは単に非冗長として扱う。

一つ選ぶたびにS_tへ追加し、候補ごとの最大類似度を更新する。したがって同じトークンiでも、既に似た位置を保存していれば次回の得点が下がる。固定方向との類似度を一度だけ加算する方式とは異なり、候補間の関係を逐次考慮する。k件を満たしたら選んだインデックスを整列して返し、後段のキャッシュ保持処理へ渡す。元の復号器はその集合だけを残して生成を続ける。

### 実装上の費用と互換性

実装はn個の署名間のn×n余弦類似度行列を計算し、各候補の最大既選択類似度m_iを更新しながらk−1回の貪欲選択を行う。論文の計算量は1圧縮イベントあたりO(n²d+nk)であり、単純な上位k件選択より明確に高い。実験の64/128予算では他の復号費用に比べ無視できると著者は述べるが、選択器単体を最適化しておらず、長文脈・大きな候補プールでのGPU処理速度を保証する測定ではない。

λ=0の場合は専用の高速経路で元の上位k件選択を返し、TriAttention 1dとビット単位で同じ結果になるようにする。これはαを既存システムに挿入しても、罰則を無効化すれば従来動作へ戻せることを意味する。論文は目的関数が一般には劣モジュラでないと明記しており、貪欲法に一般的な(1−1/e)近似保証を付与していない。性能の根拠は後述の実測正解率である。

### 設計空間で不採用となった七案

状態表現では、各ヘッドのVを階数32の主成分基底へ圧縮する案と、複数トークンの平均を合成記憶位置として持つ案を試した。経路選択ではヘッドごとに均等保持と注意得点保持を切り替え、圧縮頻度では生成段階に応じて予算を移し、生成制御では「State:」形式の要約アンカーを生成させて保存しやすくした。得点変更では固定V方向への余弦事前項と、数学問題から再集計した問い合わせ・鍵統計を検討した。

これら七案は最終的に不採用だったが、根拠の強さは一様でない。主成分・固定方向・ヘッド経路選択では、事前の代理指標が良くても実際の数学正解率へつながらなかった。生成段階で予算を移す案は平均キャッシュ容量を合わせると約6百分点の劣後が生じた。要約アンカーは容量128で推論に必要な記憶を押し出した。数学統計の再集計案はQwenの50問だけの予備試験で判断されており、二モデル・200問以上の確証実験と同列に「否定された」と解釈できない。

## 評価：条件と統計的確認

### 実験条件

| 項目 | 実際の条件と解釈 |
| --- | --- |
| 対象モデル | DeepSeek-R1-Distill-Qwen-7B、DeepSeek-R1-Distill-Llama-8B。いずれも数学的な長い思考を生成する蒸留モデル |
| 問題 | MATH-500。数式として等価な解答をSymPyで採点し、単純な文字列一致による誤判定を減らす |
| KV予算 | b=64または128。入力末尾だけでなく生成全体で測った平均キャッシュ量を一致させる |
| 基準方式 | TriAttentionの1d保持スコアと上位k件選択。後段のK/V表現・経路・生成を固定 |
| 開発集合 | 問題IDのMD5剰余で決めた201問。λ∈{0.5,1.0,1.5}を一つの乱数種で探索 |
| 確認集合 | 開発集合と重ならない299問。モデル2×予算2×乱数種3の12実験でλ=0.5を確認 |
| 統計手法 | 問題単位の対応差を10,000回のクラスターブートストラップで推定。4条件のBonferroni補正閾値p<0.0125 |
| 公開物 | 選択器、問題分割、分析コード、問題単位の生出力。GPU種類や実運用での秒単位の生成速度は主結果に記載されない |

分割は問題IDのMD5値を5で割った剰余を使い、0と1の区画を開発、2〜4を確認に割り当てる。λを選ぶときは4条件の正解率改善百分点の平均を最大にし、0.5百分点以内の同点なら小さいλを選ぶ。開発集合ではλ=0.5の平均改善が+0.75百分点、λ=1.5は+0.43、λ=1.0は−0.50であり、λ=0.5を固定して確認実験へ進んだ。λ=1.5の開発試験には未完セルがあり、選択結果は独立確認で検証する必要がある。

### 独立確認集合での結果

| モデル | 保持予算b | α−1dの正解率差 | 95%信頼区間 | p値 | 多重比較補正後 |
| --- | ---: | ---: | --- | ---: | --- |
| Qwen-7B | 64 | +1.56百分点 | −0.89〜+4.01 | 0.20 | 有意差なし |
| Qwen-7B | 128 | **+4.79百分点** | +1.67〜+7.92 | 0.0022 | **有意改善** |
| Llama-8B | 64 | **+2.23百分点** | +0.56〜+3.90 | 0.0054 | **有意改善** |
| Llama-8B | 128 | −0.22百分点 | −2.45〜+2.01 | 0.86 | 有意差なし |

表の数値は対応する数学問題の正解率差であり、トークン毎秒やKVメモリ削減倍率ではない。二つの条件ではp<0.0125を満たす一方、Qwenの64予算は正方向でも信頼区間が0を跨ぎ、Llamaの128予算はほぼ効果がない。したがって「全モデル・全予算で改善する」という結論は支持されない。事前に定義したBranch Aの条件は、Qwenで正の有意差があること、Llamaの平均差が正であること、Llamaに有意な負差がないことであり、この実験では満たされた。

さらに論文は、事前登録外のSnapKV型窓注意方式との比較も行った。αは4条件とも点推定が正で、Qwenの2条件では多重比較補正後に有意差があり、Qwen条件の平均改善は+3.93百分点だった。ただしこれは事後比較であり、事前登録した主要主張の根拠はあくまでTriAttention 1dとの独立確認比較である。SnapKVの完全な原実装と同一であることも本稿からは断言しない。

### 不利な結果・測定上の注意

64トークン予算では、誤答の44〜62%が採点対象となる枠付き解答を出力できない形で終わった。これは記憶削除による推論誤りと、正解形式を最後まで出せない失敗が混在することを意味する。Qwen-7Bの64予算での基準正解率は約8%と低く、+1.56百分点の差が有意にならなかった理由を解釈するときにも、この低い基準値を考慮する必要がある。

著者は、50問の予備実験で+5.6百分点に見えた改善が、200問・二モデルの検証では+0.2〜+0.5百分点程度へ縮んだ例を報告する。したがって小規模な選択試験の最高値を本結果として転記してはならない。さらにLlama-8Bの128予算では差が−0.22百分点、p=0.86であり、罰則を導入しても改善が観測されない条件が実在する。なぜこの条件が無効なのかについて論文は確定的な機構説明を示していない。

## 既存研究との差と位置づけ

H2OやSnapKVなどは注意スコアや事前の問い合わせ窓から重要な位置を推定し、通常は各候補のスコアに従って残す。TriAttentionは問い合わせ・鍵の統計に基づく1dスコアを与えるが、既に残した位置との値ベクトル重複は直接は考慮しない。αはそのスコアを温存し、選択過程にだけ集合条件付きの冗長性罰則を追加する。独立に再得点して上位k件を選ぶ固定方向の余弦事前項との違いは、各追加選択が現在の保持集合に依存することである。

PyramidKVやAda-KVは層・ヘッド間で予算を配る方式であり、αは**与えられた予算の内側で**位置を選ぶ方式である。両者の組合せは論理的には可能だが、論文の独立確認試験では検証されていない。KIVIやKVQuantのような量子化方式は、保持した各値の表現ビット数を減らすため、αの位置選択とは別の軸にある。V空間の類似性を利用するR-KVとも、別の段階を増やすのではなく既存スコア選択器を差し替える点が異なる。

## 限界と実装判断

確認された効果はMATH-500、7〜8B規模の蒸留推論モデル、保持予算64/128に限定される。LongBench、複数文書質問応答、コード生成、非推論特化モデル、70B級のモデルへ一般化する実験はない。λは{0.5,1.0,1.5}の粗い格子で選ばれ、最適値であるとは証明されていない。層・ヘッドを平坦に平均した署名や、生成段階によってλを変える方式は将来課題である。

最も重要なシステム上の未解決点は、n×n類似度行列の構築と逐次選択が、大規模キャッシュ・高同時実行のGPUサービングでどの程度の追加遅延になるかである。論文は正解率を主要評価軸とし、実装可能性を公開コードで示すが、実際の推論速度やGPUメモリ帯域、商用推論基盤への統合後の効果は定量評価していない。小容量下での数学推論品質を改善する方式として扱い、推論高速化や圧縮倍率を実証した研究と混同しない。
