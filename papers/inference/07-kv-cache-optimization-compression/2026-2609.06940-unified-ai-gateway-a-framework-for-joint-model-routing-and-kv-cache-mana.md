# Unified AI Gateway: A Framework for Joint Model Routing and KV Cache Management

## 概要
複数LLMを品質・価格・遅延に応じて切り替えるモデルルーティングは、単一モデル固定より効率的になり得る。しかし長文脈では、ルータが別モデルを選ぶと元モデルの鍵値キャッシュ（KV cache）が互換でなくなり、新モデルが全入力を再度プリフィルする。この再計算費用を無視すると、モデル切替で得た価格・能力上の利得を文脈再構築が打ち消す。

Unified AI Gatewayは、モデルルーティング、実行場所、KVキャッシュ処理を別々に決めず、一つの大域制御面（Global Control Plane）で同時選択する設計を提示する。要求ごとに厳密キャッシュヒット、モデル間KV写像、遠隔キャッシュ転送、エッジ側プリフィル、対象モデルでの再プリフィルの5経路を比較し、品質、遅延、費用、帯域・メモリ等の資源制約を満たす経路を選ぶ。

これは稼働実装の実測論文ではなく、既存研究の実現可能性を統合した設計・解析研究である。8種類のワークロードを使う解析シミュレーションでは、キャッシュ準備時間をTTFTの代理指標として1.25〜13.28倍、入力トークン費用を1.20〜6.16倍改善する可能性を報告する。

## 問題設定
従来のAIゲートウェイは統一API、負荷分散、フェイルオーバー、モデルルーティングを提供するが、KV状態をルーティング決定と共同管理しない。長文脈コーディングエージェントのように80K token級の履歴を反復利用する場合、モデルを変えるたびに全履歴をプリフィルし直すと、最初のトークンまでの時間（time to first token; TTFT）と入力課金が大きくなる。

一方、vLLM/SGLangのprefix再利用、LMCache/Mooncakeの分散キャッシュ、KV圧縮、モデル間KV写像など個別技術は存在する。しかし「どのモデルを選ぶか」と「そのモデルが必要とする状態をどう用意するか」を端末・エッジ・クラウド横断で同時に最適化する制御面が欠ける。

## 手法
### 要求時の共同選択
要求が到着すると、制御面は候補モデル、実行場所、KV処理方法の組を列挙する。候補は、同一モデルの互換キャッシュをそのまま使う厳密ヒット、別モデル用へKVを変換するモデル間写像、別ノードから圧縮転送する遠隔取得、エッジでプリフィルしてKVだけ送る方法、最終的に対象モデルが入力を再計算する方法である。

統一キャッシュ選択器（Unified Cache Selector）は各経路について、キャッシュが存在しアクセス可能かという可用性、写像・圧縮後の品質が許容範囲かという忠実度、検索・転送・写像・再計算等の費用、帯域・メモリ・計算資源を評価する。品質条件を満たさない写像は捨て、利用可能な高速経路がなければ再プリフィルへ戻す。

### 背景のキャッシュ配置
要求経路とは別に、背景処理がキャッシュの配置、複製、退避、移動、寿命を管理する。将来使われそうなキャッシュを実行場所へ近づけることで、要求時の選択肢を増やす。ただし本論文はこの背景方策そのものを実装・評価しておらず、解析では既に利用可能な状態として扱う。

### モデル間写像と安全なフォールバック
最も不確実なのは異なるモデル間でKV表現を写像する経路である。既存研究では一部の近いモデル対で線形写像が成立するが、モデル対によって品質保持率が大きく異なる。そのためUnified AI Gatewayはモデル間写像を常に使うのではなく、忠実度検査を通る場合だけ候補にし、失敗時は転送や再プリフィルへ戻す。

## 評価条件
|項目|条件|
|---|---|
|評価形態|実装実測ではなく解析シミュレーション|
|ワークロード|8種類。Preble由来5 profile、multi-turn chat、RAG、long-horizon coding agent|
|モデル切替率|25%、50%、75%|
|基準帯域|8 GB/s|
|KV実効容量|15 KB/token|
|圧縮率|4倍|
|プリフィル係数|A100のDistServe profileを基に校正|
|長期coding agent|約80K input token、610 output token、hit率94.2%|

## 主要結果
|条件|指標|結果|解釈|
|---|---|---:|---|
|8 workload全体|キャッシュ準備時間の改善|1.25〜13.28倍|長い共有文脈・高hit率ほど効果大|
|8 workload全体|入力費用改善|1.20〜6.16倍|cached input価格差を活用|
|long-horizon coding / 切替50%|準備時間|8.97倍|80K級文脈の再プリフィル回避効果|
|同条件|入力費用|3.79倍|モデル切替時の再入力課金を抑制|

解析ではモデル切替率が高いほど改善が増える。これは「切替でキャッシュを失う」従来ゲートウェイとの差が増えるためである。ただしモデル間写像が成功する切替ヒットを前提とし、写像計算を転送と重畳できると仮定するため、上記は配備済みシステムの実測速度ではない。

## 既存研究との差
LMCacheやMooncakeはキャッシュの保存・転送を、RouteLLM等はモデル選択を主に扱う。Unified AI Gatewayの差は、キャッシュ状態をルーティング後の実装詳細ではなく**モデル選択そのものの状態変数**として扱うことにある。また端末・エッジ・クラウドを跨ぐ配置とモデル間写像を同じ候補集合へ入れる。

## 限界
解析結果は多数の仮定に依存する。特にモデル切替時に利用可能なキャッシュがあればモデル間写像が成功するという設定、写像計算を転送に隠蔽できる設定、背景の配置・複製・退避費用を償却済みとする設定は、実配備では保証されない。異なるプロバイダ間で共通KV形式も存在せず、paged cacheのscatter/gather転送、広域ネットワーク遅延、認可・プライバシーも未解決である。したがって報告倍率は実装済みgatewayのベンチマークではなく、構成技術が成立した場合の解析上の余地として読む必要がある。
