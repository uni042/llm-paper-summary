# StepKV: Step-Aware KV Cache Compression for LLM Agents

## 概要

大規模言語モデルの自己回帰生成では、過去トークンの鍵と値を保存する鍵値キャッシュ（KVキャッシュ）が、次トークンの注意計算で過去の隠れ状態を再計算せずに済ませる。一方、保存量は文脈長に従って増え、特に推論と検索を繰り返すエージェントでは、同じ要求の途中で観測結果が長い履歴に蓄積する。キャッシュ圧縮で一部のトークンを捨てると容量を減らせるが、注意重みが小さいトークンが将来も不要であるとは限らない。

本論文は、エージェントの推論単位が「思考・行動・観測」の段階であるのに対し、従来のH2OやTOVAがキャッシュを平坦なトークン列として扱う不一致を問題とする。重要な観測の断片が後続の検索や回答合成前に消える現象を「推論連続性の破壊（Reasoning Continuity Disruption）」と呼ぶ。提案するStepKVは、完了した各段階に、即時の証拠貢献と後続段階からの再利用を反映した効用を付ける。その効用を各トークンの顕著度と合成し、限られたキャッシュ予算の上位トークンを選択する。段階全体を永久保存する方式ではなく、段階の価値をトークン単位の選別に反映する点が特徴である。

Qwen2.5-7B-InstructのHotpotQAで、圧縮対象トークンの20%を残すとき、完全一致率（EM）はStepKVが18.07±0.81%、H2Oが1.53±1.21%、TOVAが0.73±0.58%だった。Llama-3.1-8B-Instructでも同じ設定で19.93±0.12%、H2Oが0.53±0.46%となる。これらは三つの乱数種の平均と標準偏差であり、速度倍率ではない。BrowseComp-Plusの10万トークン超の軌跡では、論文はキャッシュと遅延の減少に加えて回答品質の改善を報告するが、汎用サービングの処理率や実機GPU構成ごとの高速化を検証したものではない。

## 問題設定：圧縮の単位と推論の単位が異なる

ReAct型エージェントは、質問に対して思考（Thought）を生成し、検索や照会の行動（Action）を実行し、外部から観測（Observation）を受け取る。これを複数回繰り返して回答へ到達する。初期段階の観測は、その時点では次のトークンの注意をほとんど集めなくても、数段階後の情報統合では必要になる。トークン顕著度だけに従って削除すると、一つの段階の証拠が分散して失われ、後続の判断で必要な根拠を再構成できない。

論文の図1では、映画『Snatch』の監督の出生都市を尋ねる例を示す。初期検索で監督がGuy Ritchieと分かり、その後の検索でHatfieldという出生地を得る。トークン単位の削除では途中の名前や関係が失われ、最終回答が誤る一方、StepKVは後続の回答に必要な証拠を保持する。この図は機構を説明する個別例であり、統計的な性能評価と混同しない。

著者は図2で、H2OとTOVAの削除トークンを生成元の段階ごとに追跡する。古い段階だけでなく、直前の段階のトークンも後続1〜2段階で急速に減ることがある。さらに完了直前の段階を削るlag-1、2段階前を削るlag-2、最新2段階以外を削るwindow-2を比較し、いずれも完全保持より完全一致率とF1が低下した。lag-1の影響が最大であり、単純に古い情報だけを削ればよいという仮定も成立しない。ただし、これは履歴削除の制御実験であって、すべての圧縮失敗の原因を証明するものではない。

圧縮の定式化では、完了段階tまでのトークン集合I^(t)のうち削除可能なN_t個を対象とし、質問文・初期プロンプトに対応する保護キャッシュC_protを別扱いにする。保持率ρからB_t=max(1, floor(ρN_t))を定め、段階境界で上位B_t個を残す。したがって論文の「20%保持」は、質問文を含む全メモリを常に20%へ減らすことを意味しない。保護部分は別に残り、生成段階が増えると削除可能集合の大きさ自体も変化する。

## 手法：段階効用の生成、再利用更新、トークン選択

### 1. 完了段階の即時貢献を測る

StepKVは、各段階kが終わった時点で、その思考Th_k、行動Act_k、観測Obs_kを区別して扱う。観測が空、エラー、利用不能なら有効性valid_k=0、利用可能なら1とする。新しい証拠を得たかどうかは、現在の思考と観測を連結したテキストと、過去の各段階の思考・観測の連結テキストとの重なりから測る。最大類似度を用い、gain_k=1−max_{u<k}sim(Th_k||Obs_k,Th_u||Obs_u)とする。第1段階ではgain_1=1である。

同じ検索を繰り返すことの罰則は、現在の行動と過去の行動との最大類似度red_k=max_{u<k}sim(Act_k,Act_u)で求める。第1段階のred_1は0である。三信号を合わせた即時スコアはr_k=valid_k+gain_k−λred_kとなる。標準設定のλ=0.3は、無効観測や同じ検索の反復に対して高い評価を与えないための係数である。新しい有効証拠が得られれば、過去と似た行動でも加点要素が残る。

類似度は、各フィールドから最大64個の証拠手掛かりを抽出したうえで、そのテキスト上の重なりから求める。言語モデルに別途重要度を判定させる方式ではなく、軽量な文字列・証拠の重複信号である。この設計は低費用だが、言い換えられた同義証拠、暗黙の因果関係、ノイズの多いツール出力では意味上の重要性を取り違える可能性がある。

### 2. 後から重要になった過去段階を再評価する

生成時点で段階の最終的な価値を確定すると、後から使われる証拠を早期に捨てやすい。そこで各段階kは再利用累積値c_kを持ち、完了時は0で初期化する。新しい段階tの観測Obs_tが得られたら、すべての過去観測Obs_kと比較し、c_k←c_k+min(1,ηsim(Obs_t,Obs_k))で更新する。標準のηは1.5で、単回の加算は1に制限される。重なりがゼロなら累積値は増えない。

段階効用S_kは、即時スコアを範囲[−1,2]へ切り詰めた項と、後続再利用をlog(1+c_k)で緩やかに加える項を合成し、最終的に[0,8]へ制限する。式はS_k=clip(w_r clip(r_k,−1,2)+w_c log(1+c_k),0,8)で、標準値はw_r=0.85、w_c=0.15である。後続の観測が以前の証拠を繰り返し参照すると、その段階の保持優先度が後から上がる。一方、過去の情報がすでに削除されている場合、その削除済み鍵値を再生成する仕組みではない。更新は残存候補の順位に反映されるのであり、不可逆な過去の削除を回復する保証ではない。

### 3. 段階効用と個別トークンの顕著度を合成する

段階を一括で保護すると不要なトークンまで残り、細粒度圧縮の利点が失われる。StepKVは各トークンiについて、注意由来の顕著度T_iと、その生成元段階kの効用S_kをP_i=αT_i+βS_kとして合成する。標準値はα=0.2、β=0.8であり、顕著度は最後の3層から取得する。T_iは既存の観測入力の事前入力計算中に集めるため、追加のモデル前向き計算を必要としないと著者は説明する。

同じ段階のトークンは共通のS_kを受けるが、T_iは個別に異なる。高効用段階のトークンは全体的に順位が上がる一方、低効用段階の中でも特に重要なトークンは残り得る。最終的に全削除可能トークンをP_iで順位付けし、上位B_tを選ぶ。いずれの段階も永続保護されないため、予算が厳しくなれば高効用段階からも削除が発生する。

計算手順は、段階tの完了→有効性・新規証拠・行動重複の計算→過去段階の再利用累積値更新→各段階効用の再計算→各トークンの合成スコア→全体上位選択、である。段階間の類似度比較は証拠手掛かり数が64個に制限されるためO(t)、トークンへの効用付与はO(N_t)、全体の順位付けは最悪O(N_t log N_t)となる。追加モデル呼出しは不要でも、順位付け・段階比較の計算費用はゼロではなく、推論段階の数と軌跡長が増えるほど負担が増す。

### 長いWeb推論の実行費用

BrowseComp-Plusでは10万トークンを超える軌跡があり、図4はFull KV、StepKV保持率50%、20%の完全一致率、F1、平均時間、最大時間、平均キャッシュ、最大キャッシュを正規化して比較する。著者は圧縮設定でキャッシュと推論遅延が減り、回答品質もFull KVを上回ると報告する。ただし図4は正規化図であり、図から未表示のミリ秒値や特定GPUでの倍率を作ってはならない。図5は多段階質問応答での推論遅延と最終キャッシュ量を示し、単に削除率が同じでも、情報を失った方式が余分な推論を繰り返して最終キャッシュ量を増やし得ることを示す。

この現象は圧縮の重要な副作用である。圧縮で1段階あたりのキャッシュを小さくしても、回答に必要な情報が失われれば検索・思考を繰り返し、全体の生成トークンや実行時間が増える可能性がある。StepKVは段階効用で必要な証拠を残し、不要な再生成を抑えることを狙う。ただし、図5は一般的な複数同時要求サーバーの処理率、尾部遅延、GPU間通信費を測定しておらず、その改善を主張できない。

### 構成要素除去による因果の切り分け

論文表3は、段階効用とトークン顕著度の片方を除くと品質がどう変わるかを調べる。Qwen2.5-7Bの2Wikiでは完全なStepKVがEM 23.60、F1 26.85であるのに対し、段階効用を外すとEMが15.60ポイント、F1が12.45ポイント低下する。トークン顕著度を外す場合はEMが1.40ポイント上がるが、F1は0.27ポイント上昇にとどまり、すべての課題でトークン成分が単調に有利とは限らない。MuSiQueではトークン顕著度を外すとQwenのEMが4.60ポイント、F1が8.43ポイント低下し、両信号を使う理由が明瞭になる。

表2ではMuSiQueで段階スコアを分解している。Qwen2.5-7Bで完全構成はEM 7.00、F1 12.49だが、行動冗長性の罰則を外すとEM −2.40、F1 −5.52ポイント、新規証拠の利得を外すとEM −3.40、F1 −5.47ポイント、観測有効性を外すとEM −2.80、F1 −5.58ポイント、後続再利用更新を外すとEM −3.00、F1 −6.45ポイントとなる。Llama-3.1-8Bでも後続再利用を外すとEM −1.40、F1 −3.73ポイントである。したがって遅延再利用は単なる説明用の補助量ではなく、品質へ寄与する構成要素として評価されている。

### 推論の深さと係数感度

図6は推論段階数でサンプルを分け、段階が深くなるほど圧縮下の完全一致率とF1が下がりやすいことを示す。StepKVは従来方式より高い品質を保つが、段階間依存が長くなれば限られた予算の中で全証拠を保持することは難しい。図7では段階効用の混合係数を変えたとき、中間的な重みが良い傾向を示す。つまり段階信号を無制限に強めればよいのではなく、個々のトークンの重要性と両立させる必要がある。

## 既存研究との差

H2Oは過去の注意統計を累積し、重い注意を集めたトークンを残す。TOVAは復号中の直近の注意分布を使い、TokenSkippingは定めた規則で一部のトークンを省く。これらはトークン自体の観測値や規則を主に使うため、どの思考・行動・観測の段階に属するかを明示的な保持信号として扱わない。StepKVは「段階を全部保持する」という粗い方式に置き換えるのではなく、段階効用を各トークンの保持優先度へ加算する。段階をまたいで将来再利用された観測を評価し直す点が、単なる直近優先方式との差である。

SnapKVやQuestのような問い合わせ依存の選択は、注意の局所分布や問い合わせに関連するトークンの探索を改善する。一方、本論文が直接狙うのは、エージェントの複数段階で証拠の重要性が遅れて現れる問題である。したがって既存のトークン顕著度計算を差し替えても段階効用を重ねられる設計となっている。ただし、各方式を同じ実装へ統合した場合の相乗効果は論文の主評価で網羅されていない。

## 限界と運用上の注意

第1に、段階効用は最大64個の抽出手掛かりのテキスト重なりを使う近似であり、観測が重要かどうかの因果的な真値ではない。ツール応答が曖昧、エラー混在、別表現への言い換えが多い、証拠が暗黙に含まれる場合、観測有効性・証拠利得・再利用回数が誤る。特に将来必要になるがまだ一度も再利用されていない情報は、更新前に低い効用と見なされ得る。

第2に、削除済みの鍵値を復元する再計算機構は提案していない。後から再利用されたと分かっても、既に消したトークンの鍵値を再び持ち込むことはできない。高効用段階のトークンも永久保存されず、保持率20%のような厳しい予算では推論が深まるほど品質が低下する。MuSiQueの低い絶対EMは、提案方式がすべての複雑な推論を解決したわけではないことを示す。

第3に、実験は7B/8B級の二モデルと四つのベンチマークに限られる。巨大な混合専門家モデル、複数GPUサービング、並列要求の混雑、長期の本番ツール実行で同じ改善が出るかは示されていない。著者はReAct型の明示的な思考・行動・観測境界を前提としているため、境界が曖昧な自由形式エージェントへ適用する際は、段階分割自体が追加の実装問題になる。

第4に、顕著度取得に追加モデル前向き計算は不要でも、段階比較O(t)と全トークン順位付けO(N_t log N_t)は残る。論文はGPU型番やホストメモリ条件を示した実機スループット比較を主表に置いていないため、メモリ節約をそのまま推論サーバーの処理率改善と同一視してはならない。圧縮率と最終的なキャッシュ使用量も、推論段階数や追加生成に左右される。
