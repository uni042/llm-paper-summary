# AnTKV：注意出力への誤差伝播を用いるアンカー選択と1bit未満のKVキャッシュ量子化

## 概要

AnTKVは、TransformerのKVキャッシュを極端に低いビット幅へ圧縮したときの品質劣化を、**トークンごとの誤差感度が均一ではない**という観察から抑える方式である。既存のscalar quantizationは各値を量子化するため、表現上1bit/要素が下限になる。一方、vector quantization（VQ）は複数のチャネルを一つのコードブック番号に置き換えるため、1要素当たり1bit未満にできる。しかし圧縮率を高めると、少数のKVだけが注意出力の大きな誤差を生み、文脈理解やPPLを急激に悪化させる。

著者らは、この少数をanchor tokenと呼び、オフラインでは誤差に敏感なKVを重視してVQの代表ベクトルを学習し、オンラインでは入力ごとのAnchor Score（AnS）を求めて重要トークンのKVをFP16のまま残す。単に最初のsink tokenを固定保持するのではなく、入力の注意分布から高感度な位置を特定する点が重要である。FP16のアンカーが全体の1%でも、1bit以下の領域で大きな品質改善が報告される。

論文はLLaMA-2/3とMistralの5チェックポイントで品質を評価し、LLaMA-3-8BとA100 80GBで容量と復号処理率を測定する。Mistral-7BのWikiText-2で1bitのPPLは、FP16の4.73に対しAnTKV-1%が6.32、CQが7.25、KVQuant-1%が15.36である。0.375bitではAnTKV-1%が8.87、CQが13.20であり、圧縮率を上げても無損失という意味ではない。復号処理率最大3.5倍は1K文脈での特定条件の比較であり、全サービング負荷・長文脈・prefillを含む一般的な高速化率ではない。

## 問題設定：同じ量子化誤差でも注意出力への影響が違う

### 量子化単位と誤差の位置依存性

KVキャッシュはprefill時に生成された各トークンのKeyとValueを保持し、decode時に過去の全KVを参照する。文脈長と同時要求数に比例して増えるため、重みを量子化した後でもGPUメモリを圧迫する。長文脈ではGPU HBM容量だけでなく、decodeでKVを繰り返し読み出す帯域が問題となる。KVを削除する方法は必要な過去情報を失う危険があり、CPU/SSDへ退避して検索する方式は転送・検索費用を負う。VQは保持する位置を減らさず、各KVの表現を小さなコードに置換する。

従来の一律VQでは、各トークンの量子化ベクトル誤差が近くても、softmax注意を通した出力誤差は均等にならない。論文Figure 1はMistral-7Bの第31層で各位置のKVだけを1bit化した場合を調べ、少数の位置の注意出力L1誤差が他より数十倍大きいことを示す。したがって全トークンに同じ精度を配ることは、限られたFP16保持予算の使い方として非効率である。重要なのは「その位置の量子化誤差が大きいか」ではなく「その位置の誤差が最終的な注意出力へどの程度伝わるか」である。

### アンカーとsink tokenは同義ではない

注意分布の先頭へ重みが集まるattention sinkは有力な候補だが、入力の内容に依存する高感度トークンは必ずしも先頭に限定されない。AnTKVはprefillの注意統計から入力依存のAnSを計算する。decode中には高感度位置が系列の先頭と末尾へ偏る傾向が観測されるため、先頭側はprefillで捕捉し、末尾側はsliding-window近似を使う。既に低ビットへ変換してしまった過去KVを後からFP16へ復元できないので、**いつ選ぶか**も重要な設計制約になる。

## 手法

### 1. オフラインで感度付きコードブックを学習する

まず校正データをモデルへ通し、層・ヘッドのKとVを集める。各トークンのKVベクトルを複数の部分ベクトルに分割し、各部分ベクトルを有限個のcentroidへ対応付ける。推論時には元のFP16値ではなくコードブックのインデックスを格納し、必要時にcentroidを引いて近似値を得る。例えば論文の表記`d8m256`は8次元部分ベクトルと256 centroidの組合せで、インデックス8bitを8要素へ配るため、コードブック費用を除けば1bit/要素となる。`d32m4096`は12bitのインデックスを32要素へ配り、0.375bit/要素を実現する。

通常のk-meansはベクトルの二乗誤差を均等に扱うが、AnTKVは校正時にモデル損失をK/Vで微分した誤差伝播係数を重みとして使う。式(1)(2)の考え方は、量子化前後の損失差を一次Taylor展開すると、各位置のKV差分と損失勾配の内積の和で近似できるというものだ。誤差伝播が大きい位置を重視するようcentroidを調整すれば、同じコードブック数でも重要な位置の近似精度を高められる。実装ではカスタムLinearWithActがKVと勾配を取得し、cuMLのweighted k-meansで代表ベクトルを求める。これは**校正時に勾配を使う**のであって、オンライン推論のたびに逆伝播する設計ではない。

### 2. オンラインのAnchor Scoreを注意行列から求める

オンラインでは勾配計算を避けるため、注意出力の摂動解析から軽量なAnSを導く。注意行列を`A = softmax(QK^T/sqrt(d))`としたとき、Value側の指標は`AnS(V_j)=sum_i A_ij`、Key側は`AnS(K_j)=sum_i A_ij(1-A_ij)||Q_i||_2`である（原著式(5)）。Valueの重要度はどれだけ参照されるかに対応する。Key側にはsoftmaxの局所感度`A(1-A)`とQueryノルムが入り、単なる列方向の注意総量とは異なる。厳密なKey摂動上界にはValueを含む高価な項があるが、オンラインAnSではこの項を省略する近似を使う。

処理の順序は、(a)prefillでQ/K/Vを計算、(b)FlashAttentionで注意出力と再利用可能な統計を生成、(c)別のTritonカーネルで各KV位置のAnSを集計、(d)高AnS位置を選び、そのKVだけFP16で保持、(e)残りのKVをオフラインで学習したcentroid番号に置き換える、という流れである。AnSはKeyとValueで式が異なり、値の大きな位置を優先する。アンカーの保持割合は評価ごとに固定され、PPLでは系列長の1%、ゼロショット推論では16位置、LongBenchでは64位置である。全評価が同じ1%条件というわけではない。

### 3. FlashAttentionとの両立と実装上の代償

AnSは注意行列のQuery方向にわたる集約を必要とするため、通常のFlashAttentionのタイル内還元にそのまま融合するのは難しい。著者らはFlashAttention側へQueryのL2ノルムとsoftmax復元に必要な補助統計を出力させ、**直後の独立したTritonカーネル**で注意確率を復元して列方向のAnSを集計する。付録Algorithm 1ではKeyブロックをGPUブロックへ割り当て、Queryブロックを走査してスコアを蓄積する。したがって「AnS計算の追加費用ゼロ」ではなく、中間統計出力と後段カーネルの費用がある。著者はこれを低オーバーヘッドと説明するが、任意のFlashAttention実装に無変更で差し込めるわけではない。

Keyの量子化にはRoPE適用前の分布を利用する。付録Aの比較では、RoPE後のKeyよりRoPE前のKeyの方がクラスタ内分散とクラスタ間距離の観点でVQに適した分布を持つとされる。位置情報の適用順序を無視してコードブックを学習すると、再現時の量子化誤差が変わり得る。decode時には新規トークンのAnSと近傍のsliding windowを使い、既に量子化済みの遠い位置をFP16へ復元することはしない。

### 4. 圧縮率の計算とFP16アンカーの上乗せ

論文で示す0.375bitや1bitは、主にVQインデックスの要素当たりビット数であり、**centroid保存領域を含めない**。さらにアンカーとしてFP16保持する1%の位置と、実行時のメタデータ、コードブック、選択カーネル用作業領域が追加される。例えば単純な概算では、非アンカー99%を1bit、アンカー1%を16bitとすれば、インデックスだけを数えても平均`0.99*1+0.01*16=1.15bit/要素`となる。0.375bitの場合も同じ仮定なら`0.99*0.375+0.01*16≈0.531bit/要素`である。この計算は原著の測定値ではなく、報告ビット幅と実メモリ占有が一致しない理由を示す算術例である。実際の容量は層・ヘッド・Key/Value別保持、コードブック、実装上のバッファを含めて評価する必要がある。

### 理解・推論・長文脈の品質

MMLU、ARC-C、PIQA、MathQAではLLaMA-3-8B-InstructとMistral-7B-Instructを用い、1bit以下で一律量子化の品質が落ちやすい一方、AnTKVは比較的高い正答率を維持すると報告する。ただし論文Figure 4の棒グラフから正確な数値を読み取れない部分については、図にない精度値を創作しない。KIVIとKVQuantは著者が公式実装を利用できなかったため、この比較には含まれない。PPL表のすべての方式が推論ベンチマークにも並ぶと解釈するのは誤りである。

LongBenchは11サブタスクを評価し、4bitと2bitではほぼFP16に近い性能を保つが、1bitでKIVI/SKVQの品質低下が大きくなる。AnTKVはCQに対し0.75bitと0.375bitでも優位とされ、0.375bitの平均スコアはFP16の46.2から38.1へ低下する。**平均8.1ポイントの損失は残る**ため、840Kまで保持できるという容量上の結果と、長文脈で無損失という主張を混同しない。LongBenchの比較ではtriviaqaとgov_reportを外しているため、全タスク共通の完全同条件比較ではない。

### メモリ容量と復号スループット（原著Figure 6・7）

単一A100 80GB上のLLaMA-3-8Bでは、比較したHugging Face FP16実装の最大文脈長が128K、通常のAnTKVで384Kへ伸びたと報告する。長文脈時にはKV以外の中間activationも大きな容量を消費するため、著者はin-place演算子を追加した。この最適化後、1bitで810K、0.375bitで840Kまで保持できた。840Kは圧縮だけの成果ではなく、**in-place化による作業領域削減を含む構成**の値である。128Kから840Kへの伸びを、そのままKVビット幅比や任意のGPUに一般化しない。

decode throughputは1K文脈を固定してバッチサイズを変えた測定であり、FP16比で最大3.5倍に達する。序論には1bit時最大バッチ3.3倍、throughput 3.4倍という概数も記載され、本文効率節は最大3.5倍と記す。これは測定・丸め・対象条件の差を持つ記載として扱い、すべての条件で一律3.5倍とはしない。長い入力のTTFT、CPUオフロード、マルチGPUサービング、通信遅延、エンドツーエンド要求完了時間の改善率は、この数値だけからは導けない。

### アンカー数・校正集合の感度と悪化条件

付録GではMistral-7BとLLaMA-3-8Bの8192文脈で、アンカー比率0、1%、2%、5%、10%、15%、20%を比較する。2/4bitでは1%保持だけでFP16との差をPPL 0.6以内に抑えられるが、1bit以下ではより多くのFP16アンカーが必要となる場合がある。つまり保持率を増やせば品質は上がるが、圧縮率は下がる。ゼロから1%への改善が大きく、そこから先は限界利得が小さくなるという傾向も観測される。

付録Fは校正データをWikiText-2とC4で変え、Mistral-7BのPPLとLongBenchサブタスクを比較する。例えば0.375bit、WikiText-2評価ではアンカーなしAnTKVのPPLがWikiText-2校正11.65に対しC4校正24.16へ悪化するが、1%アンカー保持では8.87と12.87になる。低ビットVQは校正分布に敏感であり、アンカー保持はその悪化を緩和するが、完全に取り除くわけではない。TRECやRepoBench-Pでは校正集合による差があり、すべてのタスクで頑健とは限らない。

## 主要結果と実装上の意味

本論文の中心的な寄与は、低ビット量子化における「圧縮誤差の大きさ」から「注意出力への伝播感度」への選択基準の転換である。VQのコードブック学習時は損失勾配で感度を反映し、オンラインではsoftmax注意に基づくAnSを使う。両者は同じ目的を持つが同じ計算式ではない。オフラインの学習済みcentroidとオンラインの高精度アンカー保持を組み合わせることで、アンカーなしVQでは崩壊する0.75bit・0.375bit領域でも品質をある程度回復できる。

実装者にとって重要なのは、(1)centroidの学習・配布、(2)RoPE前Keyの扱い、(3)FlashAttentionの中間統計追加、(4)AnS集計Tritonカーネル、(5)FP16とVQインデックスを混在させるKV管理、(6)in-placeな長文脈演算子、という複数の要素が一体になっている点である。単にKVを1bit化するだけでは論文の品質と処理率を再現できない。AnSは追加カーネルを要するため、短い文脈・低バッチではその費用が利得を相殺する可能性があるが、論文は全条件の境界を測定していない。

## 既存方式との差

KIVIはKeyのチャネル別・Valueのトークン別量子化と直近窓保持により2bit KVを実現する。SKVQはチャネル再配置やclipping、sliding windowを使い、KVQuantはRoPE前Keyや非一様量子化、外れ値処理を用いる。これらは主にscalar量子化を基盤とし、超低ビットへ下げたときの精度が難しい。CQは複数チャネルの相関を利用するVQで1bit未満に対応するが、重要位置を一律に扱うとアンカーの誤差を抑えにくい。AnTKVはCQと同じVQ系の利点を使いながら、勾配重み付きcentroidと入力依存のFP16アンカー保持を追加する。

KVを一部削除するH2O等のeviction方式とは、保持する位置数を削らず各位置の値を近似する点が異なる。RetrievalAttention等のCPU検索・オフロード方式とも異なり、AnTKVはKVをGPUに圧縮保持してdecode時の転送量を減らすことが狙いである。将来的な併用可能性はあるが、原著でそれらを統合したマルチ階層サービング実測は示されていない。モデル重み量子化とKV量子化も別の資源対象であり、重みの圧縮率を本方式のKV容量改善として数えない。

## 限界・負の結果・再現上の注意

第一に、極低ビットでもFP16同等の品質を保証する方式ではない。Mistral-7Bの0.375bit PPLは8.87対FP16 4.73、LongBench平均は38.1対46.2である。アンカー比率を増やせば精度は改善するが、その分FP16領域が増え、実メモリ圧縮率は下がる。centroid保存費用や補助バッファも必要で、論文のbit表示は完全なGPU常駐容量ではない。

第二に、オンラインAnSは厳密な摂動上界を簡略化した代理指標であり、誤差伝播を常に正確に予測するとは限らない。prefill後に新しく重要になった過去トークンは、すでに量子化されていればFP16へ戻せない。decode時の窓近似とsinkの局所性は実験観測に基づくが、分布変化や特殊な注意パターンでの保証は示されていない。著者自身もAnSの精度とカーネル性能の改善余地を認める。

第三に、比較条件に制約がある。CQは著者再実装で、KIVI/KVQuantは一部の推論ベンチマークで実装欠如により除外される。LongBenchのprefillではFP16 KVを使用し、triviaqa・gov_reportを一部比較から除外する。性能評価は単一A100 80GB、LLaMA-3-8Bの特定条件に限定され、vLLM/SGLangでの実運用、複数同時要求のSLO、ホストオフロード、ネットワークを含むTTFT・TPOT分布などは報告されない。

第四に、論文付録H.3はコードと学習済みcentroidを採択後公開すると記しており、今回確認した一次資料から公式コードURLを特定できない。実装の存在を断定してリンクを捏造しない。FlashAttentionの変更点、cuMLによるweighted k-means、Tritonの集計とin-place演算子が再現上の要点であるが、公開実装の実行検証は行っていない。
