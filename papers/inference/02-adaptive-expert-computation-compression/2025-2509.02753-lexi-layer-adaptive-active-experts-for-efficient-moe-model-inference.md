# LExI: Layer-Adaptive Active Experts for Efficient MoE Model Inference

> 層ごとのtop-k感度を重みだけから推定し、global expert budgetをlayer間へ再配分して固定Top-kより少ない計算で品質維持を狙う。

## 概要
LExIは、全MoE layerで同じtop-kを使うのではなく、**top-kを下げても壊れにくいlayerではKを減らし、敏感なlayerへKを残す**data-freeな推論最適化である。

expert weight自体は削除しないためresident model sizeは変わらない。狙いはmemory compressionではなく、実行時のactive expert数とFLOPsを減らすこと。

layer感度はreal calibration dataではなくsynthetic inputから推定し、総expert activation予算`B`の範囲内で各layerの`k_j`を進化探索により決める。実行時には探索済みのlayer-wise Kを固定するため、tokenごとの追加predictorは不要である。

## 手法のあらまし

LExIでは `synthetic sensitivity profiling`、`D_j(k)`、global budget `B`、evolutionary allocationが中心になる。

### 1. `Synthetic Sensitivity Profiling`：実データなしでlayerのtop-k感度を測る

各MoE layerへ標準正規乱数のsynthetic hidden stateを入れ、元top-k出力と、Kを1〜`k_base`へ減らした出力との差を測る。

ここでsynthetic inputはreal data distributionを再現するためではない。

目的は**同じsynthetic分布上で各layerを比較し、どのlayerがK削減へ敏感か順位付けすること**である。

### 2. `D_j(k)`：layer jをk expertsへ減らしたときの摂動score

元出力とK削減後出力のFrobenius norm差を多数sampleで平均し、layer `j` / candidate Kに対するscore `D_j(k)`を作る。

`D_j(k)`が小さいほど、そのlayerはKを減らしてもoutputが変わりにくいとみなす。

この表を一度作れば、異なるglobal budgetに対してmodel forwardを何度も実行せずallocationだけ再探索できる。

### 3. `Global Budget B`：全layerのactive expert数合計を固定する

各layerのKを`k_j`とすると、

`Σ_j k_j = B`

という制約を置く。

例えば全layer一律K=4にするのではなく、敏感なlayerへ5〜6、鈍感なlayerへ1〜2を割り当てながら総budgetだけ揃える。

LExIの本質は**Kを減らすこと自体ではなく、同じ総Kをlayer間で再配分すること**にある。

### 4. `Evolutionary Search`：整数K配分を探索する

各layerのKは整数で、総budget制約もあるため単純gradient optimizationにしにくい。

LExIは候補allocation vectorを個体として、

- tournament selection
- uniform crossover
- ±1 mutation
- budget repair

を行い、`Σ_j D_j(k_j)`が小さい配分を探す。

探索対象はweightではなく**layerごとのK割当**だけなので比較的軽量である。

### 5. Modelごとに感度profileの形が違う

論文では、

- Mixtralは後半layerが敏感
- Qwenは初期layerが敏感
- DeepSeekは中間が高いbell-shaped傾向

など、同じ「後半を減らす」「前半を残す」といった固定heuristicでは一般化しないことを示す。

これがdata-freeでもlayer別profileを取る理由である。

### 6. Token-adaptiveではなくlayer-adaptive

一度`k_j`を決めた後は、そのlayer内の全tokenが同じKを使う。

したがってXMoE / Alloc-MoEのようなtoken-level dynamic Kとは異なり、**runtimeの分岐overheadが小さい代わりにtoken難度までは見ない**。

### 7. Memory footprintは減らない

使わないexpertもweightはmodel内に残るため、GPU / CPU resident model sizeは変わらない。

そのためVRAM capacityそのものが問題の環境には効かず、compute-boundなserving向けの最適化である。

## 評価

### まず見るところ
- **結論:** layerごとのtop-k感度を使うと、固定pruningより同じthroughput帯で品質を大きく守れる。
- **実速度:** 多くのモデルでinter/intra pruningより良いthroughput–quality Paretoを示す。
- **品質:** OLMoEやMiniCPMでは同速度baselineより10〜15%級の精度差が出る条件もある。
- **メモリ:** weightを削除しないためresident memoryは減らない。
- **注意点:** synthetic perturbation scoreがtask品質のproxyであり、tokenごとの難度適応はしない。

### 代表的Pareto比較

| Model | 同程度の速度baselineに対するLExIの差 |
|---|---|
| OLMoE | 50% intra-pruning比 **精度+10%**、inter比+15% |
| Qwen1.5 | pruning比 throughput **+5.1%以上**、精度+0.5pt |
| MiniCPM | 25% inter-pruningと同速度で **精度+15%** |
| DeepSeek | inter-pruningと同精度で **throughput+6.5%** |
| DeepSeek | intra-pruning比 **精度+6pt** |

### Long-context例

QasperでQwenを評価。

| Method | F1 | Throughput |
|---|---:|---:|
| LExI | **35.5** | 約4.1k |
| Inter-pruning | 34 | 約3.9k |
| Intra-pruning | 30 | 約3.75k |

### Mixtral PPL

| Dataset | LExI | 同速度inter-pruning |
|---|---|---|
| C4 | 約2.4k throughput / PPL約23 | PPLは約2倍 |
| WikiText | 約2.2k / PPL約10 | PPLは約2倍 |

固定expert削除より、weightを残してlayer-wise active Kだけ変える方が品質を保ちやすいことを示す。

### VLM

DeepSeekVL2-Tiny（3B、12 layers、64 experts、top-6）でMME / MMMU / ScienceQAを評価し、layer-adaptive allocationが安定して機能すると報告する。

### 評価上の制約

- resident model memoryは削減しない。
- synthetic inputのFrobenius距離はtask lossそのものではない。
- base top-kが2など探索幅が狭いmodelでは利得も限定的。
- 絶対throughputはhardware / kernelに依存。
- token-level difficultyは考慮しない。
