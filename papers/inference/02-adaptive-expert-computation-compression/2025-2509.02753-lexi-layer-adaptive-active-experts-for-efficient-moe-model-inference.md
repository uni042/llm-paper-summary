# LExI: Layer-Adaptive Active Experts for Efficient MoE Model Inference

> layerごとにTop-kを減らした時の出力変化を事前に測り、影響が小さいlayerではexpert数を減らし、影響が大きいlayerへexpert実行予算を回すことで、固定Top-kより少ない計算で品質維持を狙う。

## 概要
LExIは、全MoE layerで同じTop-kを使うのではなく、**Top-kを下げても出力があまり変わらないlayerではKを減らし、変化が大きいlayerにはKを多く残す**data-freeな推論最適化である。

expert weight自体は削除しないためresident model sizeは変わらない。狙いはmemory compressionではなく、実行時のactive expert数とFLOPsを減らすこと。

layerごとの感度は実calibration dataではなくsynthetic inputから推定し、モデル全体で許すexpert実行回数の合計`B`を各layerへどう配るか探索する。実行時には探索済みのlayer-wise Kを固定するため、tokenごとの追加predictorは不要である。

## 手法のあらまし

### 1. 実データなしでlayerのTop-k感度を測る

各MoE layerへ標準正規乱数から作ったsynthetic hidden stateを入れ、元Top-k出力と、Kを1〜`k_base`へ減らした出力との差を測る。

ここでsynthetic inputはreal data distributionを再現するためではない。

目的は**同じsynthetic分布上で各layerを比較し、どのlayerがK削減へ敏感か順位付けすること**である。

### 2. `D_j(k)`：layer jのexpert数をkへ減らした時の出力変化

元出力とK削減後出力について、行列要素ごとの差をまとめた距離を多数sampleで平均し、layer `j` / candidate Kに対するscore `D_j(k)`を作る。

`D_j(k)`が小さいほど、そのlayerはKを減らしてもoutputが変わりにくいとみなす。

この表を一度作れば、異なる総expert実行予算に対してmodel forwardを何度も実行せず、Kの配分だけ再探索できる。

### 3. `Global Budget B`：全layerのactive expert数合計を固定する

各layerのKを`k_j`とすると、

`Σ_j k_j = B`

という制約を置く。

例えば全layer一律K=4にするのではなく、敏感なlayerへ5〜6、鈍感なlayerへ1〜2を割り当てながら総budgetだけ揃える。

LExIの本質は**Kを減らすこと自体ではなく、同じ総Kをlayer間で再配分すること**にある。

### 4. 候補配分を少しずつ変えながら良い整数Kの組み合わせを探す

各layerのKは整数で、合計も`B`に合わせる必要があるため、LExIは候補となるK配分を多数作り、良い候補同士を組み合わせたり一部を±1変えたりしながら、`Σ_j D_j(k_j)`が小さい配分を探す。

これは一般にevolutionary searchと呼ばれる探索法だが、ここで探索しているのはweightではなく**layerごとのK割当だけ**なので比較的軽量である。

### 5. Modelごとに感度profileの形が違う

論文では、

- Mixtralは後半layerが敏感
- Qwenは初期layerが敏感
- DeepSeekは中間layerが敏感

など、同じ「後半を減らす」「前半を残す」といった固定heuristicでは一般化しないことを示す。

これがdata-freeでもlayer別profileを取る理由である。

### 6. Token-adaptiveではなくlayer-adaptive

一度`k_j`を決めた後は、そのlayer内の全tokenが同じKを使う。

したがってXMoE / Alloc-MoEのようなtoken-level dynamic Kとは異なり、**runtimeの分岐overheadが小さい代わりにtokenごとの難しさまでは見ない**。

### 7. Memory footprintは減らない

使わないexpertもweightはmodel内に残るため、GPU / CPU resident model sizeは変わらない。

そのためVRAM capacityそのものが問題の環境には効かず、expert計算時間が支配的なserving向けの最適化である。

## 評価

### まず見るところ
- **結論:** layerごとのTop-k感度を使うと、全layerから同じ割合でexpertを減らす方法より、同じthroughput帯で品質を大きく守れる。
- **実速度:** 多くのmodelで「同程度の品質ならより速い、同程度の速度ならより高品質」という関係を示す。
- **品質:** OLMoEやMiniCPMでは同速度baselineより10〜15%級の精度差が出る条件もある。
- **メモリ:** weightを削除しないためresident memoryは減らない。
- **注意点:** synthetic inputで測った出力変化が実task品質の代用指標であり、tokenごとの難度適応はしない。

### 代表的な速度・品質比較

| Model | 同程度の速度baselineに対するLExIの差 |
|---|---|
| OLMoE | 全layerから同数を減らす方法比 **精度+10%**、layer単位で丸ごとexpertを減らす方法比+15% |

| DeepSeek | 比較法と同精度で **throughput+6.5%** |
| DeepSeek | 別の一律削減法比 **精度+6pt** |

### Long-context例

QasperでQwenを評価。

| Method | F1 | Throughput |
|---|---:|---:|
| LExI | **35.5** | 約4.1k |
| Layer単位の一律削減 | 34 | 約3.9k |
| 各layer内で一律削減 | 30 | 約3.75k |

### Mixtral PPL

| Dataset | LExI | 同速度の一律削減法 |
|---|---|---|
| C4 | 約2.4k throughput / PPL約23 | PPLは約2倍 |
| WikiText | 約2.2k / PPL約10 | PPLは約2倍 |

固定expert削除より、weightを残してlayer-wise active Kだけ変える方が品質を保ちやすいことを示す。

### VLM

DeepSeekVL2-Tiny（3B、12 layers、64 experts、top-6）でMME / MMMU / ScienceQAを評価し、layer-adaptive allocationが安定して機能すると報告する。

### 評価上の制約

- resident model memoryは削減しない。
- synthetic inputで測った出力距離はtask lossそのものではない。
- base Top-kが2など探索幅が狭いmodelでは利得も限定的。
- 絶対throughputはhardware / kernelに依存。
- token-level difficultyは考慮しない。
