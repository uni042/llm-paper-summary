# LExI: 層-適応型 Active エキスパート for Efficient MoE Model Inference

> LExIは層ごとのTop-k削減による出力変化を合成入力で測り、影響の小さい層の専門家数を減らして重要層へ予算を回し、固定Top-kの計算を減らす。

## 概要
LExIは、全MoE 層で同じTop-kを使うのではなく、**Top-kを下げても出力があまり変わらない層ではKを減らし、変化が大きい層にはKを多く残す**data-freeな推論最適化である。

エキスパート重み自体は削除しないため常駐モデルサイズは変わらない。狙いはメモリ圧縮ではなく、実行時の活動エキスパート数とFLOPsを減らすこと。

層ごとの感度は実calibration dataではなく合成 inputから推定し、モデル全体で許すエキスパート実行回数の合計`B`を各層へどう配るか探索する。実行時には探索済みの層単位 Kを固定するため、トークンごとの追加predictorは不要である。


速度を揃えた比較では、OLMoEで全層一律削減比の精度を10%高め、Qwen1.5でスループットを5.1%以上・精度を0.5ポイント高め、DeepSeekでは同精度のままスループットを6.5%高めた。

## 手法のあらまし

### 1. 実データなしで層のTop-k感度を測る

各MoE層へ標準正規乱数から作った合成隠れ状態を入れ、元Top-k出力と、Kを1〜`k_base`へ減らした出力との差を測る。

ここで合成入力は実データ分布を再現するためではない。

目的は**同じ合成分布上で各層を比較し、どの層がK削減へ敏感か順位付けすること**である。

実データを使わない利点は、配備するタスクごとに較正集合を用意せずチェックポイントだけから特性表を作れる点にある。ただし合成隠れ状態は実トークン分布そのものではないため、ここで測っているのはタスク精度ではなく『この層のMoE出力がエキスパート数削減に対してどれだけ構造的に変わりやすいか』という代理指標である。LExIは絶対値より層間の相対順位として使うことで実データ不要にしている。

### 2. `D_j(k)`：層 jのエキスパート数をkへ減らした時の出力変化

元出力とK削減後出力について、行列要素ごとの差をまとめた距離を多数の標本で平均し、層 `j` ／候補Kに対するスコア `D_j(k)`を作る。

`D_j(k)`が小さいほど、その層はKを減らしてもoutputが変わりにくいとみなす。

この表を一度作れば、異なる総エキスパート実行予算に対してmodel forwardを何度も実行せず、Kの配分だけ再探索できる。

また特性表は各層・各候補Kの局所的な距離を表にしたものなので、総予算を変えるたびにLLM全体へ大量の較正文を流す必要がない。運用者は同じ特性表から品質重視の大きいBとスループット重視の小さいBを複数作り、サービス要件に応じて層単位のK設定を切り替えられる。

### 3. `Global Budget B`：全層のactive エキスパート数合計を固定する

各層のKを`k_j`とすると、

`Σ_j k_j = B`

という制約を置く。

例えば全層一律K=4にするのではなく、敏感な層へ5〜6、鈍感な層へ1〜2を割り当てながら総budgetだけ揃える。

LExIの本質は**Kを減らすこと自体ではなく、同じ総Kを層間で再配分すること**にある。

この再配分は、各層を独立に削るのではなく、モデル全体の計算上限を守りながら行う。ある層で一つ減らした分を別の層へ回すため、削減の影響が小さい場所で節約した計算を、出力に強く効く場所で使える。したがって評価時には、単に平均Kを下げたかではなく、同じ総エキスパート実行数でどれだけ品質を保てたかを比較することが重要になる。

例えば総budgetが全層平均K=3相当でも、敏感な層へK=4を残す代わりに鈍感な層をK=1〜2へ落とせる。全層を一律K=3にする方式では、この『余分な1 エキスパートが品質へ効く場所』と『削ってもほぼ変わらない場所』を区別できない。総active エキスパート数を同じに固定して比較することで、LExIの利得が単なる計算量増加ではなく層間の配分改善から来ることを確認できる。

### 4. 候補配分を少しずつ変えながら良い整数Kの組み合わせを探す

各層のKは整数で、合計も`B`に合わせる必要があるため、LExIは候補となるK配分を多数作り、良い候補同士を組み合わせたり一部を±1変えたりしながら、`Σ_j D_j(k_j)`が小さい配分を探す。

これは一般にevolutionary searchと呼ばれる探索法だが、ここで探索しているのは重みではなく**層ごとのK割当だけ**なので比較的軽量である。

探索の入力は各層の感度表と総予算だけであり、候補を評価するたびに大規模な再学習を行う必要はない。運用者は品質と速度の目標に応じて予算を選び、同じモデルから複数の設定を用意できる。これにより、利用状況が変わっても重みを作り直さず実行時の層設定を切り替えられる。

### 5. Modelごとに感度profileの形が違う

論文では、

- Mixtralは後半層が敏感
- Qwenは初期層が敏感
- DeepSeekは中間層が敏感

など、同じ「後半を減らす」「前半を残す」といった固定heuristicでは一般化しないことを示す。

これが実データなしでも層別特性表を取る理由である。

### 6. トークン-適応型ではなく層-適応型

一度`k_j`を決めた後は、その層内の全トークンが同じKを使う。

したがってXMoE / Alloc-MoEのようなトークン単位 動的 Kとは異なり、**実行時の分岐オーバーヘッドが小さい代わりにトークンごとの難しさまでは見ない**。

### 7. メモリ footprintは減らない

使わないエキスパートも重みはモデル内に残るため、GPU／CPU常駐モデルサイズは変わらない。

そのためVRAM capacityそのものが問題の環境には効かず、エキスパート計算時間が支配的なserving向けの最適化である。

以上の整理は、提案手法の動作原理と前提条件を保ったまま、一次資料の記述を要約したものである。

## 評価

### まず見るところ
- **結論:** 層ごとのTop-k感度を使うと、全層から同じ割合でエキスパートを減らす方法より、同じスループット帯で品質を大きく守れる。
- **実速度:** 多くのmodelで「同程度の品質ならより速い、同程度の速度ならより高品質」という関係を示す。
- **品質:** OLMoEやMiniCPMでは同速度比較対象より10〜15%級の精度差が出る条件もある。
- **メモリ:** 重みを削除しないため常駐 メモリは減らない。
- **注意点:** 合成 inputで測った出力変化が実task品質の代用指標であり、トークンごとの難度適応はしない。
