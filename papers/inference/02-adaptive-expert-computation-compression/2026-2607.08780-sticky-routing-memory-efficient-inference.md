# Sticky Routing: Training MoE Models for Memory-Efficient Inference

> 混合専門家モデルの隣接トークンで専門家が頻繁に切り替わる問題を、学習時の経路一貫性損失で直接抑え、最大59%の切替削減と最大3.92倍のキャッシュミス削減を示した研究である。

## 概要

混合専門家（Mixture-of-Experts;
MoE）モデルは各トークンで一部の専門家だけを活性化するため演算量を抑えられる一方、端末側では全専門家重みを高速メモリへ常駐できないことがある。隣接トークンが別々の専門家を選ぶと、低速な主記憶やストレージから重みを繰り返し入れ替える必要が生じ、疎な計算という利点がメモリ転送で相殺される。

StickyMoE
はこの問題を推論時キャッシュだけで処理せず、学習時から隣接トークンの経路が急変しにくいモデルを作る。実験では専門家切替率を最大59%減らし、キャッシュミスを最大3.92倍減らした。中規模モデルでは適度な正則化強度でパープレキシティも改善し、事後的なルータ微調整より品質と局所性の両立で優位だった。

## 背景: MoEの「演算は疎」でも、重み転送まで疎になるとは限らない

混合専門家モデル（Mixture-of-Experts; MoE）は、各トークンで多数の専門家のうち上位K個だけを実行するため、総パラメータ数を増やしても1トークン当たりの演算量を抑えられる。しかしメモリ容量が限られた端末やGPUでは、全専門家の重みを高速メモリへ常駐できない。現在選ばれた専門家がキャッシュに無ければCPUメモリやNVMeなど低速階層から重みを読み込む必要があり、演算量の削減より重み転送待ちが支配的になる。

通常のMoEルータは各トークンの隠れ状態から独立に専門家スコアを計算する。言語モデル損失と負荷分散は最適化しても、「直前トークンと同じ専門家を使えば重みを再利用できる」というシステム上の価値は目的関数に入っていない。そのため意味的に連続する区間でも専門家集合が細かく切り替わり、キャッシュ容量が小さいほどミスと重み入替えが増える。

既存のLRU/LFU、expert prefetch、推論時キャッシュは、すでに決まった経路列をできるだけうまく処理する**事後的な対策**である。ルータだけを後から微調整する方法も、専門家表現自体が局所性を考えずに学習済みなので、経路だけを強く変えると品質との衝突が起きる。StickyMoEは経路の時間局所性を学習開始時から損失へ入れ、専門家とルータを同じ制約下で共同適応させる。

## 問題設定

通常の上位K専門家選択では、ルータは各トークンの隠れ状態から専門家確率を作るが、目的関数は言語モデル品質や負荷分散を主に最適化し、直前トークンと同じ専門家を使うこと自体には価値を与えない。そのため意味的に連続した短い区間でも専門家集合が頻繁に変わり、容量の小さい高速メモリではキャッシュ置換が増える。

推論側の最近最少使用キャッシュや先読みは、すでに形成された経路列に対して転送を隠す仕組みであり、経路列そのものの時間局所性は変えない。事後的にルータだけを微調整する方法も、専門家表現が局所性を意識せず学習済みであるため、経路を大きく変えると品質を損ないやすいという表現不整合が残る。

## 手法

第一の機構は経路一貫性損失である。各混合専門家層について、トークン t
のルータが出すソフトマックス確率ベクトルと直前トークン t-1
の確率ベクトルとの差の二乗ノルムを計算し、系列内と全層で平均する。この値を通常の言語モデル損失へ係数
λ を掛けて加える。

入力は通常のトークン系列で、追加の推論器を必要としない。ルータ確率の隣接差が大きいほど罰則が増えるため、勾配はルータだけでなく共同学習される専門家表現にも伝わる。出力形式や上位K選択の構造は変わらず、学習された確率分布だけが時間方向に滑らかになる。

第二の重要点は、局所性を事前学習の最初から専門家とルータへ共同適応させることである。ある意味区間を同じ専門家へ送り続けることが品質上不利なら、専門家側の表現もその制約の下で役割を調整できる。事後微調整では固定済み専門家に合わせてルータだけを曲げるため、この共同適応が起きない。

第三の機構は単一係数 λ による品質と局所性の調整である。λ
が小さければ通常学習に近く、増やすほど隣接経路の一貫性を強く要求する。強すぎる場合には、本来別の専門家へ送るべきトークンまで同じ経路へ拘束し、言語モデル品質を落とす可能性がある。

一つの生成区間で見ると、各トークンの隠れ状態からルータ確率が計算され、通常どおり専門家が選択される。学習時だけ直前トークンとの確率差が損失へ入るため、連続する意味区間で同じ専門家が選ばれやすくなる。推論時には追加損失計算は不要で、同じ専門家重みが高速メモリに残る期間が長くなり、重み再読込が減る。

系列の話題や機能が急変する位置では専門家切替が必要であり、過度な一貫性は誤った専門化を強制する。また高速メモリに十分な容量があり全専門家が常駐できる環境では、切替率低下による入出力上の利益は小さい。このため失敗時の挙動は速度低下だけでなく品質低下としても現れ得る。

## 評価

### 代表的な評価条件

| 項目 | 条件 |
| --- | --- |
| モデル規模 | 小規模・中規模のMoE言語モデル |
| ルーティング | 標準top-k MoEルータを維持し、学習時だけ隣接トークンの確率分布差へ罰則を追加 |
| 比較対象 | 通常学習、StickyMoE、学習済みモデルに対する事後ルータ微調整 |
| 主ハイパーパラメータ | 経路一貫性損失の重み λ |
| 品質指標 | パープレキシティ（低いほど言語モデル予測が良い） |
| 局所性指標 | 隣接トークン間の専門家切替率（低いほど同じ専門家を再利用しやすい） |
| システム代理指標 | 制約付きexpert cacheでのキャッシュミス |
| 推論時追加処理 | なし。学習済みルータのtop-k選択をそのまま使用 |
| 評価範囲の注意 | 大規模商用級MoEや実機I/O/エネルギーの包括的評価ではない |

論文は小規模および中規模の混合専門家言語モデルで、通常学習、StickyMoE、事後的なルータ微調整を比較する。評価軸はパープレキシティ、隣接トークン間の専門家切替率、メモリ制約推論を模したキャッシュミスである。

### 代表的な評価結果

| 条件 | 指標 | 比較対象 | StickyMoE | 読み取れること |
| --- | --- | --- | --- | --- |
| 小・中規模MoE | 専門家切替率 | 通常学習 | 最大59%低下 | 経路そのものへ時間局所性を学習できる |
| 制約付きexpert cache | キャッシュミス | 通常学習 | 最大3.92倍削減 | 切替率低下が実際の重み再利用指標へつながる |
| 中規模モデル / 適度なλ | パープレキシティ | 通常学習 | 改善する条件あり | 局所性獲得が必ず品質劣化との交換になるわけではない |
| 強い一貫性制約 | パープレキシティ | 通常学習 | 悪化し得る | 必要な専門家切替まで抑えると品質を損なう |
| 事後ルータ微調整 | 切替率と品質の両立 | StickyMoE | StickyMoEが優位 | 専門家表現とルータを最初から共同適応させることが重要 |

代表結果は専門家切替率が最大59%低下し、キャッシュミスが最大3.92倍減少した点である。中規模モデルでは適度な
λ
でパープレキシティが基準より改善する条件も報告され、単純に品質を犠牲にして局所性を得た結果ではない。一方、効果量はモデル規模と
λ に依存する。

事後ルータ微調整は両モデル規模・複数層で基準から切替率をほとんど変えず、著者は専門家表現と経路の共同適応がないことを原因として議論する。これは推論時キャッシュを工夫する研究とは別に、学習時にメモリアクセス特性を形成する価値を示す。

## 既存研究との差

従来のキャッシュ置換や専門家先読みは、所与の経路列に対して必要重みをいつ保持・転送するかを最適化する。StickyMoE
はその一段上流で、経路列自体を時間局所性の高いものへ変えるため、推論システムのキャッシュ方策とは競合せず組み合わせられる。

事後ルータ微調整と違い、専門家重みとルータを最初から同じ局所性目的の下で学習する点が核心である。アーキテクチャ変更や推論時の追加ネットワークを要求せず、既存の疎な専門家選択を維持する。

## 限界・実装状況

最大の限界は評価が小・中規模モデル中心で、大規模商用級混合専門家モデルで同じ品質・局所性曲線が成立するか未確定な点である。端末の実測入出力時間やエネルギーまでを大規模に評価した研究ではなく、切替率とキャッシュミスの改善を実速度へ換算するときはハードウェア条件が必要になる。

λ
の最適値はモデル、データ、専門家数、キャッシュ容量に依存する。局所性を強くしすぎると専門家の役割分担を損なう可能性がある。コードは著者により公開されているが、本稿の主張はプレプリント段階の実験結果として扱うべきである。
