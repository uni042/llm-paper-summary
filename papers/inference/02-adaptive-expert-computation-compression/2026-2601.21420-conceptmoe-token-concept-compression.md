# ConceptMoE: Adaptive Token-to-Concept Compression for Implicit Compute Allocation

> 意味類似トークンを概念へ適応圧縮し、同一パラメータ・同一平均演算量下で節約計算を専門家混合モデルへ再配分して性能と長文脈推論効率を同時改善する。
## 書誌情報
- **著者**: Zihao Huang, Jundong Zhou, Xingwei Qu, Qiyang Min, Ge Zhang
- **著者・所属**: ByteDance Seed
- **公開**: arXiv
- **種別**: プレプリント
- **対象**: 適応トークン圧縮、概念表現、専門家混合モデル、計算再配分、KVキャッシュ削減、長文脈推論
- **実装**: 公式ConceptMoEコードページを公開。論文付録にはPyTorch形式のチャンク化・復元・直通推定量の実装例を掲載し、Hopper GPU上で3000億級構成の実測推論を評価する。
## 概要
ConceptMoEは、隣接トークンの意味類似度から学習可能な境界を決め、予測容易な連続トークンを概念表現へ動的圧縮して計算量を暗黙に再配分する専門家混合モデル（MoE）である。圧縮で節約した計算を活性化専門家数・中間層ループ・隠れ幅へ戻し、総パラメータ数とトークン当たり演算量を標準MoEと揃えて比較する。言語事前学習、600億パラメータ級視覚言語モデル、900億級継続学習変換、3000億級推論で評価し、長文脈平均+2.3点、継続学習変換+5.5点、圧縮率2で事前充填最大175.1%、復号最大117.1%の速度向上を報告する。

学習可能な隣接トークン類似度で分割境界を動的決定し、概念モデルへ入る系列を目標比率Rで短縮する。専門家混合モデルでは総専門家数と活性化専門家数を独立に調整できるため、圧縮で節約した計算を活性化専門家数、概念モデル層ループ、隠れ幅へ再配分し、総パラメータと平均演算量を標準モデルに一致させられる。これにより概念レベル処理の効果を比較しつつ、注意行列計算とKVキャッシュ削減は残る。さらに指数移動平均型の復元、概念とトークンを共同利用する復号器のQ/K/V射影、境界ノイズを組み合わせ、既存MoEからの継続学習変換も可能にする。

代表結果として、12B language OpenBench averageは243B training トークン, same total parameters and average FLOPsでMoE-A0.5B-12B 35.6に対して36.4。適応概念圧縮と計算再配分で+0.8点。固定chunkは34.2まで低下する。
## 問題設定
標準的な大規模言語モデルは各トークンへほぼ一様な計算を割り当てるが、自然言語には容易に予測できる連続部分と推論上重要な部分が混在する。固定長の統合や規則ベース圧縮は情報密度に適応せず、バイト単位の動的分割では入力表現変更や総パラメータ増加が比較を交絡させる。単純にトークン数を減らしたモデルを深く・広くすると、改善が概念処理によるのか追加パラメータによるのか分離できない。ConceptMoEは、総パラメータ数と平均トークン当たり演算量を同一に保ったまま、意味的冗長部分だけを圧縮し、節約計算を重要な概念処理へ戻せる設計を狙う。
## 新規性
学習可能な隣接トークン類似度で分割境界を動的決定し、概念モデルへ入る系列を目標比率Rで短縮する。専門家混合モデルでは総専門家数と活性化専門家数を独立に調整できるため、圧縮で節約した計算を活性化専門家数、概念モデル層ループ、隠れ幅へ再配分し、総パラメータと平均演算量を標準モデルに一致させられる。これにより概念レベル処理の効果を比較しつつ、注意行列計算とKVキャッシュ削減は残る。さらに指数移動平均型の復元、概念とトークンを共同利用する復号器のQ/K/V射影、境界ノイズを組み合わせ、既存MoEからの継続学習変換も可能にする。
## 手法
### 手法のあらまし
処理は入力トークン→浅い符号化器→適応分割→概念モデル→概念復元→浅い復号器の順に進む。まず符号化器が各トークン表現を作り、分割器が隣接表現を学習可能な問い合わせ・鍵射影へ通して余弦類似度を計算する。類似度が低い位置ほど境界確率を高くし、0.5以上を新概念の開始位置として、境界間の連続トークンを一つの概念表現へまとめる。補助損失は全装置・全標本の境界確率と実際の境界頻度を目標圧縮率へ誘導するため、難しい標本では境界を増やし、容易な標本ではより強く圧縮できる。短縮された概念系列だけを計算量の大部分を占める概念モデルへ入力するため、系列長依存の注意計算とKV保持量が減る。

概念モデル出力は境界確率による指数移動平均で隣接概念を滑らかに接続し、境界写像を使って元の各トークン位置へ展開して符号化器表現へ加える。最後に浅い復号器がトークン表現と対応概念の両方から問い合わせ・鍵・値を作って共同復号し、元のトークン列に対する次トークン予測を出す。訓練時には境界確率0.5付近を確率的に反転して評価分布移動時の過圧縮を抑える。圧縮で空いた演算量は活性化専門家増加、概念層ループ、または概念モデルの隠れ幅増加へ再投資し、比較対象と総パラメータ・平均演算量を揃える。

### 適応分割モジュール
隣接トークンを学習可能な問い合わせ・鍵線形層へ通し、正規化後の余弦類似度から境界確率を求める。先頭は必ず境界とし、確率0.5以上を新概念の開始位置にする。意味が連続する予測容易な区間では境界が減って大きな概念へまとまり、意味変化が大きい位置では境界が残るため、固定長分割より情報密度に応じた粒度を選べる。

概念表現は区間内トークンの和、または浅い符号化器で文脈を集約した末尾トークンを利用する。論文の固定分割比較では、適応分割が平均36.4に対し固定分割は34.2、分割なしは35.6であり、単に系列を短くするだけではなく境界選択自体が重要である。

### 圧縮率制御と境界ノイズ
境界と非境界を二つの専門家に見立て、平均確率と実際の選択頻度から補助損失を構成して目標圧縮率を維持する。統計を標本ごとではなく現在の装置群全体で集約するので、バッチ内の難しい標本へ多くの境界を与え、容易な標本を強く圧縮する標本間の計算再配分も許す。

評価分布が変わると0.5近傍の境界が反転して過圧縮しやすいため、訓練では確率を鋭くした後にベルヌーイ標本化し、低信頼境界だけを主に揺らして頑健性を高める。境界ノイズ比較ではτ=4が平均30.3、τ=6が30.0、ノイズなしが28.9となり、著者らは学習損失への影響を抑えるτ=6を主設定に採用する。

### 概念復元と共同復号
概念モデル出力をそのまま複製するのではなく、各境界確率を係数とした指数移動平均で前概念と混合する。これにより境界確率にも予測損失から勾配が届き、不要な境界を消す方向へ学習できる。境界から概念番号への写像を逆引きして各元トークンへ対応概念を展開し、符号化器のトークン表現へ加える。

復号器では対応概念専用の追加Q/K/V射影を標準トークン射影へ加算し、概念モデルが計算した高水準情報を各トークンの自己注意へ直接戻す。共同復号を外すと学習損失はわずかに下がる一方、下流平均は36.4から35.1へ低下するため、概念情報を最終トークン予測へ明示的に戻す経路が一般化に寄与する。

### 計算再配分と公平比較
概念系列をR倍短くすると主概念モデルのトークン線形計算がおよそR分の1になるため、その余力を三方式で戻す。第一は活性化専門家数を増やす方式、第二は専門家数を増やしつつ中間層をループする方式、第三は隠れ幅と専門家計算を増やす方式である。総専門家プールを調整できるMoEの性質により、総パラメータ数と平均トークン演算量を標準MoEへ合わせられる。

それでも短縮系列による注意行列とKVキャッシュの利点は残り、方式に応じて注意計算を最大Rの2乗倍、KVを最大R倍削減する。継続学習では専門家だけ増やすtop15より、11専門家と8層ループを組み合わせる方式の改善が大きく、節約計算をどこへ戻すかも性能を左右する。

### 全体のデータ／制御の流れ
全体は符号化器、適応分割器、概念モデル、復元器、復号器の五段構成である。主計算を担う概念モデルだけを短縮系列で動かし、前後の符号化器・復号器を浅くすることで、圧縮処理自体の負担を抑える。

既存MoEから変換する場合は分割・復元器と最後4自己注意層の概念用Q/K/V射影だけを追加し、追加射影をゼロ初期化する。したがって変換直後は既存モデル挙動を大きく乱さず、継続学習の中で概念処理を獲得できる。
## 評価条件
- **ハードウェア**: モデル能力評価は総パラメータ12B/24Bの小規模言語MoE、60Bのvision-language MoE、90Bの継続学習変換を含む。推論速度はMoE-A10B-300Bを比較対象としてHopper GPU上で測定し、プリフィルは4K〜1024K系列、デコードはバッチ size 256でKV長4K〜64Kを評価する。
- **ソフトウェア**: AdamWとcosine learning-rate decayを使用。共通設定は比較対象がトークン当たり8 エキスパート活性化、ConceptMoEの補助損失λ=0.03、境界ノイズτ=6（約4% トークン flip）。公式コードページと付録のPyTorch形式Chunk/Dechunk/STE実装がある。
12B/24Bでは243B/559B トークン、TPP=400で事前学習し、R=16/9でhidden widthとMoE計算を再配分する。60B VLMは500B text pretraining後、NaViTを統合して32K系列で200B トークン継続学習し、text/image両方をR≈2で圧縮する。90B CTでは700B-トークン pretrained MoEから変換し、32Kで400B、128Kで40B、さらに3B SFTを行いR=1.5、top15またはtop11+8-層 loopを比較する。全主要比較は総パラメータと平均トークン FLOPs（attention map計算を除く）を一致させる。OpenBench、long-context、multimodal、in-house ベンチマークと構造ablationを評価する。
概念圧縮の効果を複数規模・modalities・from-scratch/CTで検証し、300B級で実測推論速度も測る。一方、FLOPs matchingはattention-map計算を除外するためConceptMoE側が実際にはその分少ない計算となる。VLMではlocation、image Q&A、chart textの一部が低下し、R=4の過圧縮は明確に性能を損なう。Hopper以外の推論hardwareや分散servingの通信・エキスパート load balanceは主要評価ではない。
## 主要結果
ConceptMoEはcompute-matched標準MoEに対し、12B/24B言語事前学習で総合平均を35.6→36.4、50.0→50.9へ改善した。60B VLMではtext平均33.5→34.4、long-context 49.4→51.7、multimodal 53.6→54.2。90B CTではtop11-loop8がOpenBench 40.9→46.4（+5.5）、from-scratchは47.3。300B級Hopper推論ではR=2効率構成が長系列プリフィル最大175.1%、デコード最大117.1%高速化する。

- 12B language OpenBench average / 36.4 (比較対象: MoE-A0.5B-12B 35.6; 条件: 243B training トークン, same total parameters and average FLOPs) — 適応概念圧縮と計算再配分で+0.8点。固定chunkは34.2まで低下する。

- 24B language OpenBench average / 50.9 (比較対象: MoE-A1B-24B 50.0; 条件: 559B training トークン, same total parameters and average FLOPs) — +0.9点。R=2系は比較対象を上回るがR=4では47.7へ悪化する。

- 60B long-context average / 51.7 (比較対象: MoE-A2.5B-60B 49.4; 条件: R≈2 dual-modality compression) — +2.3点。LC reasoningは10.3→17.1、understandingは40.9→45.1だがsummary/Q&Aは63.7→59.0。

- 90B CT OpenBench overall / 46.4 (比較対象: MoE 40.9; 条件: ConceptMoE-top11-loop8, R=1.5, compute/parameter matched) — +5.5点。reasoning +8.3、math +12.2、code +6.4。from-scratchは47.3。

- R=2 プリフィル 高速化倍率 / 最大175.1% (比較対象: MoE-A10B-300B; 条件: ConceptMoE-1L-top24-R2, Hopper, sequence up to 1024K) — 系列が長いほど注意行列削減の利得が拡大する。

- R=2 デコード 高速化倍率 / 最大117.1% (比較対象: MoE-A10B-300B; 条件: ConceptMoE-1L-top24-R2, Hopper, バッチ 256, KV up to 64K) — KV短縮がデコードのメモリ・注意コストを削減する。

### 負の結果・境界条件
- 圧縮率R=4ではOpenBench平均47.7となり比較対象 50.0およびR=2の50.8を下回り、reasoning 51.3対56.8、math 46.3対50.0と過圧縮の悪影響が明確。VLMでもlocation 82.2→81.9、image Q&A 61.4→58.0、chart text 34.7→33.6と細粒度視覚課題が低下する。線形boundary ルーティングはtraining lossを0.003改善する一方downstream平均34.4でcosine ルーティング 36.4を下回り、joint デコード除去もtraining lossは0.002改善するが平均35.1へ低下する。

### 結果の読み方
利益はトークン数を単に減らすことではなく、意味的冗長度に合わせた動的chunkingと、節約計算をconcept処理へ戻す設計の組合せから生じる。長文脈では系列短縮が注意行列とKVの両方へ直接効く。CTでは層ループへの再配分がエキスパート数だけ増やすtop15より有効で、既存MoEを大きく壊さず導入できる。
## 品質への影響
R=1.5〜2ではcompute-matched条件で平均品質を維持または改善するが無損失圧縮ではない。タスク依存の細粒度情報損失とR=4の明確な劣化があり、自然な意味冗長度に合わせた圧縮率調整が必要。
## 既存研究との差
H-Netやbyte-level 適応型 chunkingと異なり、通常トークン表現を維持し、MoEの活性化エキスパート数を計算量調整ノブとして総パラメータと平均FLOPsを同時に揃える。DLCMなどconcept modelとの比較では、ConceptMoEは圧縮後にモデル規模を単純増加させず公平なcompute/parameter matchingを重視する。固定トークン mergingや固定chunkと異なり、learnable cosine boundaryでsample/トークンごとの情報密度に適応する。MoE++等のexplicit トークン エキスパート skippingがトークンを残したまま活性化計算を変えるのに対し、ConceptMoEは系列長自体を縮めるためattention mapとKV キャッシュも削減する。
## 限界
圧縮は無損失ではなく、R=4ではreasoning/mathを含む性能が比較対象未満へ低下する。VLMでは画像トークンを逐次概念化するため空間関係が重要なlocation、image Q&A、chart textで低下が見られる。主要なcompute matchingはattention-map FLOPsを除外するため、厳密な総実行FLOPsはConceptMoEの方が小さく、純粋な同一実時間コスト比較ではない。推論速度評価はHopper中心で、分散MoE servingのall-to-all、エキスパート load balance、通信ボトルネックは検証していない。CTで大きな+5.5点を得る構成は8-層 loopingも併用しており、改善全量をchunking単独へ帰属できない。
## 実装状態
ByteDance SeedによるarXiv v1。公式GitHubコードページが論文に記載され、付録にChunkModule、DechunkModule、STE、ConceptMoE forwardのPyTorch形式コードを掲載する。300B級構成のHopper実測があり、単なる理論FLOPs評価に留まらない。
## 研究上の位置づけ
適応型 エキスパート Computation / Compression系の中でも、エキスパートそのものをprune/キャッシュ/skipするのではなく、エキスパートへ到達するトークン系列を意味単位へ適応圧縮する方向。MoEの疎性を『総パラメータを固定したまま節約FLOPsを再投資する機構』として使うため、トークン compressionとエキスパート computationの接点に位置する。長文脈ではKV キャッシュとattention map削減が直接的なシステム利点となり、既存MoEのCT変換経路も示す。
