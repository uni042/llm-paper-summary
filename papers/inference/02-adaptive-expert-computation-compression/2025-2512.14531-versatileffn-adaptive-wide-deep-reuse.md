# VersatileFFN: Achieving Parameter Efficiency in LLMs via Adaptive Wide-and-Deep Reuse

> 同一FFNを仮想専門家として幅方向に分割し、難しいトークンには深さ方向に再帰利用することで、追加パラメータをほぼ増やさず計算量を適応配分し、1.21Bで8タスク平均60.47%を達成する。
## 書誌情報
- **著者**: Ying Nie, Kai Han, Hongguang Li, Hang Zhou, Tianyu Guo, Enhua Wu, Xinghao Chen, Yunhe Wang
- **著者・所属**: Huawei Noah’s Ark Lab; ISCAS; University of Macau
- **公開**: arXiv:2512.14531v2
- **種別**: プレプリント
- **対象**: パラメータ再利用、仮想MoE、動的深さ、再帰計算、適応計算、FFN、メモリ効率
- **実装**: 著者コードをHuawei Noah's Ark Labのnoah-research内で公開。論文実装はOLMo2を基盤とする。
## 概要
VersatileFFNは、LLMのメモリ量を増やさずにFFNの表現能力を高めるため、同一FFN重みを幅方向と深さ方向の二通りに再利用する。幅経路はhidden次元の非重複部分を仮想専門家として切り出しTop-kで疎に選択し、深さ経路はFFN全体をトークンごとに予測した回数だけ再帰適用する。予測ループ数の期待値を難易度信号として両経路を融合し、容易なトークンでは幅経路、難しいトークンでは反復深さを重視する。FineWeb-Eduで354M/720M/1.21Bモデルを学習し、1.21Bでは8タスク平均60.47%でdense 56.74%、実専門家MoE 59.65%、4-Loop 60.09%を上回る。パラメータは1.21Bのまま、FFN FLOPsは4.69Gで6-Loopの9.06Gより小さい。

一つのFFNをhidden次元の構造化部分空間から作る複数の仮想専門家として幅方向に再利用すると同時に、FFN全体を反復適用して深さ方向にも再利用する。物理的な専門家パラメータを増やさず、MoE的な専門化と再帰的な追加計算を同じW_proj/W_outから得る。

さらに深さ制御器が予測する期待ループ数をトークン難易度の代理変数とし、幅経路と深さ経路の融合係数を追加の難易度教師なしで決める。深さを決める信号を幅・深さ間の計算配分にも再利用する点が中心的差分である。
## 問題設定
LLMの性能向上をパラメータ数の増加に頼ると、全重みをHBM/DRAMへ保持するメモリ費用が急増する。疎な混合専門家（Mixture-of-エキスパート; MoE）は活性計算を抑えても、多数の独立専門家重み自体は保持するためメモリ容量問題を残す。剪定・量子化・低ランク化も既存モデルを近似して保存量を減らす方式で、元アーキテクチャの表現能力上限を越える仕組みではない。

逆に単純な再帰FFNは重みを増やさないが、全トークンへ同じ回数の逐次反復を課すと、容易なトークンにも不要なFLOPsとレイテンシを使う。従って固定パラメータ予算のまま重みを複数機能へ再利用し、トークンの難しさに応じて並列的な幅と逐次的な深さのどちらへ計算を振るかを変える必要がある。
## 新規性
一つのFFNをhidden次元の構造化部分空間から作る複数の仮想専門家として幅方向に再利用すると同時に、FFN全体を反復適用して深さ方向にも再利用する。物理的な専門家パラメータを増やさず、MoE的な専門化と再帰的な追加計算を同じW_proj/W_outから得る。

さらに深さ制御器が予測する期待ループ数をトークン難易度の代理変数とし、幅経路と深さ経路の融合係数を追加の難易度教師なしで決める。深さを決める信号を幅・深さ間の計算配分にも再利用する点が中心的差分である。
## 手法
### 手法のあらまし
入力は各Transformer層で自己注意、残差接続、正規化を終えたトークン表現Hである。処理の第1段階ではHを幅経路と深さ経路へ同時に渡す。幅経路は共有FFNのhidden次元をN個の構造化部分空間へ切り出し、ルーティングのTop-k確率で少数の仮想専門家だけを選び、各専門家出力を加重和してY_widthを得る。処理の第2段階では同じHを共有FFN全体へ入力し、loop predictorが1～Lmaxの反復回数分布pを予測する。FFNを再帰的に適用してH^(1), H^(2), ...を生成し、学習時はGumbel-Softmaxと直通推定量（Straight-Through Estimator; STE）を使って離散選択を保ちながら勾配を流す。

処理の第3段階ではpから期待ループ数E[L]を計算し、lambda=(Lmax-E[L])/Lmaxを難易度依存の融合係数にする。最終出力はY=lambda Y_width+(1-lambda)Y_depthで、容易なトークンほど幅経路、難しいトークンほど深さ経路の寄与が増える。このYが通常FFNの出力と同じ位置で残差系列へ戻り、次のTransformer層への入力になる。推論時はpのargmaxでhat_lを決め、深さ経路はhat_l回で早期終了する。lambda=0なら幅経路を実行せず、それ以外は幅と深さを並列化する。従って入力Hからルーティング選択、loop回数予測、二経路計算、難易度融合、次層への出力までが一つのエンドツーエンド経路として定義される。

### 幅可変仮想専門家
共有FFNの中間次元d_hiddenを専門家ごとのd_エキスパート幅で切り出し、N×d_エキスパート≤d_hiddenを満たすようstrided slicingする。投影重みW_projと出力重みW_outで同じindex集合を使うため、一つのFFN内部の対応した部分空間が一つの仮想専門家になる。専門家ごとの新しい重み行列は複製しない。

Top-k ルーティングが各トークンに必要なsliceだけを選択し、Softmax ルーティングと負荷分散補助損失で専門家崩壊を防ぐ。主設定の8-choose-2では8個の仮想専門家から2個だけを活性化し、354Mの設定探索で4-choose-1、8-choose-4、16-choose-4より高い平均accuracyを得た。

### 深さ可変再帰FFN
幅経路のsliceとは異なり、W_proj/W_out全体を使う標準FFN FをH^(l)=F(H^(l-1))として繰り返す。W_loopはトークン表現から1～Lmax回の確率分布を出力し、学習時はGumbel-Softmaxの温度を5.0から0.1へannealしつつSTEで離散forwardと連続gradientを両立する。

学習時の出力は各反復hidden stateを確率p_lで加重し、推論時はargmaxで選ばれたhat_l回だけ実行してH^(hat_l)を返す。このため固定4-Loop/6-Loopのように全トークンへ最大計算量を課さない。354Mの探索では4 loopsが平均accuracy 51.98%で最良となりLmax=4を主設定に採用する。

### 難易度認識融合
loop predictorの分布からE[L]=Σl·l·p_lを計算し、必要な反復深さそのものをトークン難易度の代理信号にする。lambda=(Lmax-E[L])/Lmaxなので、容易なトークンではlambdaが1へ近づき幅経路を強くし、難しいトークンではlambdaが0へ近づき深さ経路を強くする。

最終出力はY=lambda Y_width+(1-lambda)Y_depthで、同じ制御信号を反復回数決定と経路融合へ再利用する。ARC-c可視化では低lambda側に特定動作語、高lambda側に高頻度一般語が現れ、層別平均ループ数もモデル規模により後段集中・中段集中・前段集中へ変化した。

### 推論時最適化
推論では学習時のsoftな中間状態加重和をやめ、loop predictorのargmaxで決めた離散回数hat_lに到達した時点で深さ経路を終了する離散早期終了を使う。これによりLmaxまで全反復を計算してから捨てる無駄を避ける。

lambda=0なら幅経路の寄与が無いため仮想専門家の構築・ルーティング・FFN計算を完全に枝刈りする。lambda>0では幅経路と深さ経路を可能な限り並列実行する。ARC-c実行統計による354MのFFN FLOPsは1.24Gで、固定4-Loop 1.50G、6-Loop 2.25Gより低い。

### 全体のデータ／制御の流れ
標準Transformerの自己注意は変更せず、各層のFFNをVersatileFFNへ置換する。幅・深さの両経路は同じW_proj/W_outを共有し、追加パラメータは幅ルーティングとloop predictorが中心で総パラメータに対して無視できる程度とされる。

主実験は幅8専門家中Top-2、深さ最大4ループである。354Mの設定探索では8-choose-2が幅単独の最高accuracy、4 loopsが固定再帰のaccuracyと計算量の最良バランスだったため、この組合せを主要比較に使う。

## 主要結果
VersatileFFNは全3規模でBaseを大幅に上回り、実専門家MoEや固定Loopより高い8タスク平均accuracyを得た。354Mでは52.33%でBase 47.98%、MoE 51.48%、4-Loop 51.98%。720Mでは57.03%でBase 53.83%、MoE 55.87%、6-Loop 56.55%。1.21Bでは60.47%でBase 56.74%、MoE 59.65%、4-Loop 60.09%。追加専門家を持つMoEと異なり総パラメータはBaseと同等で、固定深さ再帰よりFLOPsを抑える。

- 8-task average accuracy / 60.47% (比較対象: Base 56.74%; MoE 59.65%; 4-Loop 60.09%; 6-Loop 60.05%; 条件: 1.21B, 100B-トークン corpus, continued pre-training) — 同一パラメータ再利用と適応計算の組合せが最大規模でも比較方式を上回る。

- parameter count / 1.21B (比較対象: MoE 1.97B; 条件: 1.21B scale) — MoE比で約0.76B、約39%少ない総パラメータでより高い平均accuracyを得る。

- FFN FLOPs / 4.69G (比較対象: 4-Loop 6.04G; 6-Loop 9.06G; 条件: 1.21B; VersatileFFNはARC-c実行統計から算出) — 固定回数再帰より動的深さで計算を節約する。

- 354M average accuracy / 52.33% (比較対象: Base 47.98%; MoE 51.48%; 4-Loop 51.98%; 条件: 354M, 40B トークン) — 小規模でも幅・深さ融合が単独経路を上回る。

- 354M FFN FLOPs / 1.24G (比較対象: 4-Loop 1.50G; 6-Loop 2.25G; Base 0.38G; 条件: ARC-c実行統計) — Baseより計算は増えるが固定再帰より少ない計算で高accuracyを得る。

- ablation accuracy / width only 50.98%; depth only 51.35%; width+depth 52.10%; +difficulty gating 52.33% (比較対象: Base 47.98%; 条件: 354M, 40B トークン) — 二経路が相補的で、難易度認識融合にも追加利得がある。

- from-scratch average accuracy / 51.14% (比較対象: Base 47.98%; MoE 50.90%; 4-Loop 50.81%; 条件: 354M, continued pre-trainingなし) — 継続事前学習だけに依存せず、初期学習からも利得がある。

### 負の結果・境界条件
- 再帰を増やせば単調に精度が上がるわけではない。354Mでは6 loopsがloss 2.615と4 loopsの2.617より低い一方、平均accuracyは51.61%で4 loopsの52.33%を下回る。幅経路も8-choose-4や16-choose-4へ活性容量を増やしても52.22%、51.72%となり8-choose-2の52.33%を超えない。VersatileFFNはBaseよりFLOPsが増え、逐次再帰のwall-clock効果は主要表で直接測定していない。

### 結果の読み方
結果は、メモリ制約下ではパラメータを増やす代わりに既存FFNを異なる計算経路で再利用する余地があることを示す。特に固定k-Loopより少ない平均計算で精度が高く、実専門家MoEより少ない重みで精度が高いことから、幅と深さをトークン難易度で配分する設計が単なる計算量増加以上の効果を持つ。
## 品質への影響
圧縮による品質保持ではなく、同一パラメータ予算でBaseより品質を上げる設計。代償は追加FLOPsと再帰による逐次性であり、実レイテンシ・電力・メモリ帯域の評価は不足する。
## 既存研究との差
通常MoEは複数の独立専門家重みを保持し、活性計算だけを疎化するのに対し、VersatileFFNは単一FFNのhidden部分空間を仮想専門家として切り出すため専門家の物理的メモリ増加を避ける。Mixture-of-DepthsやMixture-of-Recurrenceなどの動的深さ系に対しては、深さだけでなく幅方向の仮想専門化を同時に利用し、同じloop predictorの出力を二経路の融合にも使う。剪定・量子化とは異なり既存モデルを近似圧縮するのではなく、同一パラメータ予算で計算再利用により能力を増やすことを狙う。
## 限界
評価規模は最大1.21Bであり、数十B～数百Bの実運用LLMへ同じルーティング・再帰特性がスケールするかは未検証。主要結果はaccuracy、loss、理論/統計FLOPs中心で、実GPU上のトークン/s、TTFT、電力、HBM帯域、カーネル効率を直接比較していない。深さ経路は本質的に逐次依存を持つため、FLOPs削減がwall-clock 遅延削減へそのまま変換されるとは限らない。GPU型や学習時間も主要本文・付録では確認できない。難易度は予測ループ数から内生的に定義されるため、難易度推定自体の校正や誤配分の詳細分析は限定的。
## 実装状態
著者公式コードがHuawei Noah's Ark Labのnoah-researchリポジトリ内VersatileFFNとして公開されている。論文実装はOLMo2を基盤とし、推論では離散早期終了と条件付き並列実行を提案する。
## 研究上の位置づけ
適応的専門家計算・圧縮系統の中でも、重みオフロードや専門家キャッシュではなく『専門家を物理的に増やさない』方向のメモリ効率化。compute-heavy/メモリ-light設計として、メモリ容量が主制約で演算余力がある環境に適する。再帰計算と仮想MoEを同一FFN上で統合するため、MoE圧縮と動的計算深さの境界に位置する。
