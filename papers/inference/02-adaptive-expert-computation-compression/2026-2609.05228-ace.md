# ACE: 適応型 Calibration-Free エキスパート Skipping for MoE-based LLMs

> ACEはルータ重みと専門家変換能力の事前統計を組み合わせ、Top-k内でも寄与の小さいスロットだけをトークン単位で省く。元重みとTop-1を保ち、追加学習なしでFFN計算を減らす。

## 概要

A100実機のBF16評価でQwen3.6-35B-A3Bのエキスパートスロットを50%skipし、元ルータ方式（9.42 PPL／71.42平均正解率）に対してPPL8.67／平均正解率75.57を示した（WikiText-2系列長2048、下流7課題）。Qwen3-30Bの同50%設定では上位-P、AIMER、GSPとも比較し、ACEはPPL8.85／平均正解率74.30（上位-P 8.85／74.17、AIMER 8.86／73.40、GSP 8.99／74.10）だった。60%skipでもA100のTTFT 1.72〜2.25倍、TPOT 1.31〜1.41倍だが、いずれも損失ありの近似結果である。

## 問題設定
固定上位kのMoEではトークンごとの実寄与が違っても同数のエキスパートスロットを実行するため、低寄与エキスパートにもFFN計算と振り分けが発生する。ルータゲートは候補間の相対的な割当嗜好であり、エキスパート固有の非線形変換能力や方向特化を直接は表さない。既存の動的削減には、ルータ再学習、補助モジュール、較正・感度分析、バッチ前提などを要する方式が多い。
## 新規性
ACEは元ルータと上位k候補集合を維持し、全体スペクトル代理指標（GSP）とルータ条件付き精密化（RCR）の二つの指標を事前計算する。実行時はトークンのルータゲートで両指標を条件付けし、最大値で融合して、両方が低寄与と判断したスロットだけをスキップする。
## 手法
### 手法のあらまし
展開前にGSP/RCRの表を作る。GSPはSwiGLUのゲート・上流・下流投影とRMSNormの尺度調整を結合したスペクトル代理指標を層内正規化し、エキスパート全体の変換能力を表す。RCRはルータ重みから層平均を引き、その方向をRMS正規化した原型としてエキスパートへ事前に順伝播し、ルーティング優先方向の増幅率を表にする。推論時は上位k候補ごとにゲート×GSPとゲート×RCRを計算して候補集合内で正規化し、最大値を最終スコアとする。予算に対応する閾値未満だけをスキップし、上位1エキスパートは必ず残す。残存エキスパートだけFFNを実行し、ゲートを再正規化してMoE出力を合成する。

ACEが直接変更するのは元モデル ルータが選んだ上位k候補の内部だけで、候補外エキスパートを新たに探索するわけではない。したがって元ルータの大まかな専門化構造は維持しつつ、第二位以下のスロットに本当に計算を使う価値があるかを追加評価する。これはルーティングを置き換える新ルータではなく、既存ルーティング後段に置く実行抑制器として理解すると分かりやすい。

### Global Spectral Proxy (GSP)
SwiGLUの三投影の結合を保つ分岐対称指標、スペクトル代理指標、RMSNormの尺度調整から、実入力サンプルなしで全体の増幅を推定し、層内で正規化する。

GSPだけを見ると入力方向を区別せず、そのエキスパートが全体としてどの程度大きな変換を作り得るかを重み 幾何から測る。したがって平均的には強いエキスパートを保護しやすい一方、特定のルーティング方向だけで重要になるエキスパートは見落とし得る。この方向盲性を補うためにRCRが別視点として必要になる。

### ルータ条件付き精密化 (RCR)
中心化 ルータ 重みからエキスパート固有ルーティング方向を作り、その原型に対するエキスパート応答増幅を事前計算評価してGSPの方向盲性を補う。

ルータ 重みを層平均から引くことで、全エキスパートに共通する成分ではなく『このエキスパートが相対的に好む方向』を原型へ残す。その方向をエキスパートへ通したときの応答が大きければ、全体 代理指標が低くても特定トークン群では重要な可能性がある。ただし一方向の原型で実入力分布すべてを代表できないため、RCR単独では高スキップ率で不安定になり得る。

### 保守的な二視点融合
GSP/RCRの寄与分布の最大値を使うため、スキップ集合は両方が低寄与とした集合の共通部分となる。片方が重要とみなしたエキスパートは保持する。

max融合は平均融合より保守的で、どちらか一方の代理指標が高いスロットを削除しない。これは2つの代理指標が互いの失敗様式を補う設計である。GSPは方向特化を見落とし、RCRは原型が実入力を代表しない可能性があるため、両方が同時に低いときだけ省くことで偽陰性による重要エキスパート削除を減らす。

### 予算から閾値への対応付け
推定器はデータ不要だが、報告された10〜60%の予算を閾値へ変換する際は、ラベルなしの全モデル通過処理で候補スコアを集め、分位点として対応付ける。

したがって「較正不要」は、エキスパート重要度表の作成に課題データを必要としないという意味であり、所望スキップ率の閾値まで完全に負荷非依存という意味ではない。実験ではラベルなし入力のスコア分布から分位点を求めるため、未知領域へ同じ閾値を持ち出すと実現スキップ率や品質がずれる可能性がある。この境界は展開時の再設定コストとして扱う必要がある。

### Safeguards
上位1を常時保持し、必要なら最小活性数を課し、残存ゲートを再正規化する。

上位1の保持は、ルータが最も強く選んだ主経路を必ず残すための下限保証である。最小活性数を追加すれば、代理指標が多数スロットを低寄与と判定したトークンでも計算量が極端に落ちるのを防げる。一方、残存ゲートの再正規化は出力尺度を保つが、省いたエキスパートの方向成分そのものは復元できないため、これらは安全策であって無損失保証ではない。

### 全体のデータ／制御の流れ
トークン→元ルータの上位k/ゲート→GSP/RCR表の参照とスコア計算→閾値・上位1の安全策→残存エキスパートだけFFN→ゲート再正規化→MoE出力の順に処理する。事前計算表はチェックポイントごとに再利用できるが、所定スキップ率の閾値は報告実験では負荷のスコア分布に対応付けている。

実行経路では新しいニューラル予測器を動かさず、ルータゲートと2種類の表値をスカラー演算するだけなので、FFNを省いた利得を制御オーバーヘッドが食いにくい。反面、分散エキスパート並列環境ではスロット削減が全対全転送量や装置間の負荷均衡へどう波及するかは別問題であり、単一GPUでのFFN削減率がそのままクラスタ高速化倍率になるとは限らない。
## 評価条件
- **ハードウェア**: NVIDIA A100 GPU 向け 遅延 評価
- **ソフトウェア**: BF16 推論、Hugging Face-based 評価 パイプライン、EvalScope 1.4.1
- **モデル**: Qwen3-30B-A3B-Instruct-2507、Qwen3.6-35B-A3B、Gemma-4-26B-A4B-it
- **データセット / トレース**: WikiText-2、ARC-Challenge、ARC-Easy、PIQA、MATH-500、GPQA-Diamond、HumanEval、LiveコードBench
- **比較対象**: スコア、NAEE、方式、DiEP、AIMER (Qwen3-30B)、上位-P ルーティング (Qwen3-30B)、SERE (Qwen3-30B)、XShare (Qwen3-30B)、エキスパートparsity (Qwen3-30B)、GSP-のみ、RCR-のみ
- **正しさ**: 損失ありのエキスパートスキップであり、厳密なBF16出力同値性は保証しない。上位1は常に保持し、残存ゲートを再正規化する。
- **予算**: 経路選択済み上位kエキスパートのスロットを10、20、30、40、50、60%スキップし、上位1は常に保持。
- **閾値対応付け**: ラベルなし全モデルの通過処理を1回行い、選択スコアを集めて要求予算へ分位点対応付けする。推定器の表はパラメータだけから作る。
- **WikiText-2**: 系列長2048でPPLを測定。
- **下流評価**: 同一プロンプト・分割でzero-shot、貪欲デコード。ARC-C/E/PIQAは最大1024、推論・コード課題は2048まで生成。
- **再現性**: 乱数種42の決定的な単一実行であり、論文は小数点以下の差を過大解釈しないよう注意している。
- **遅延**: A100で60%スキップを測定し、長さ256〜1024、バッチ1〜4のTTFT/TPOTを報告。
各手法で実現スロット予算をそろえ、三つのMoEモデル、八つのベンチマーク、構成要素・融合の除去実験、閾値準備時間、A100のTTFT/TPOTを比較する。品質と実行エキスパート数、単一GPU遅延の根拠は得られるが、分散エキスパート並列の提供性能は未評価であり、閾値は負荷に対応付けた単一の決定的実行に基づく。
## 主要結果
ACEの利得は積極的にスキップするほど明確になる。Qwen3.6では50%でPPL 8.67、平均正解率75.57となり、比較方式の9.42、71.42を上回る。60%でも9.98、70.70を保つ。A100測定ではエキスパート数の削減だけでなく、実際の遅延短縮も確認した。

- Qwen3.6 PPL @50% / 8.67（比較対象: 比較方式9.42、条件: エキスパートスロット50%スキップ）—PPLを7.96%相対削減。

- Qwen3.6平均正解率 @50% / 75.57（比較対象: 比較方式71.42、条件: 下流課題7種）—4.15点向上。

- Qwen3.6 @60% / PPL 9.98、平均70.70（比較対象: 比較方式10.87/69.04、スコア方式13.38/54.66、条件: 60%スキップ）—積極的な予算でも品質差を維持。

- Qwen3-30B @50% / PPL 8.85、平均74.30（比較対象: 上位P 8.85/74.17、AIMER 8.86/73.40、GSP 8.99/74.10、条件: 50%スキップ）—外部比較で最良のPPLと最高の平均正解率に並ぶ。

- 融合除去実験 @50% / 最大値融合とACE 8.85/74.30（比較対象: 平均値8.97/74.01、最小値9.20/73.12、条件: Qwen3-30B）—保守的な最大値融合が最良。

- 閾値準備 / 1.8分（比較対象: 二分探索16.5分、方式の境界探索18.9分、条件: Qwen3-30B 10%）—展開準備を9.2〜10.5倍高速化。

- A100 TTFT高速化倍率 @60% / 1.72〜2.25倍（比較対象: BF16、条件: 長さ256〜1024、バッチ1〜4）—例として1024/b1は270.9→120.3ms。

- A100 TPOT高速化倍率 @60% / 1.31〜1.41倍（比較対象: BF16、条件: 同じ評価一式）—例として1024/b1は85.1→63.0ms/トークン。

### 負の結果・境界条件
- **低疎性の例外**: Qwen3.6の10%ではルータ方式の平均81.66に対しACEは81.41。
- **RCR単独は弱い**: Qwen3-30Bの50%でRCRは11.62/67.01、GSPは8.99/74.10。一つのルータ原型では入力分布全体を表せないためである。
- **負荷対応の閾値**: 報告された予算対応付けはラベルなし負荷のスコア通過処理を使い、閾値移行は今後の課題。
- **単一実行の不確実性**: 決定的な乱数種一つだけで、反復実行の不確実性は今後の課題。
- **分散提供は未実施**: 分散エキスパートの振り分けは今後の課題。

### 結果の読み方
ACEは新しいルータではなく、固定したエキスパート実行予算で安全側に選択する規則である。GSPが主要な全体信号を与え、RCRが方向特化したエキスパートを保護する。
## 品質への影響
損失あり。同じスキップ率では一般に比較対象より品質保持が良いが、低疎性の例外と閾値移行の不確実性がある。
## 既存研究との差
- スコア/NAEEなどルータ中心のimportanceに対し、ACEはルータ p基準とエキスパート パラメータ structureを分けて測って実行時 ゲートで再結合する。
- 上位-P/Ada-Kのvariable-cardinality ルーティングと違い、元上位k候補を維持して候補内secondary スロットのみスキップする。
- AIMER/DiEP等の静的 圧縮と違い、エキスパート poolを恒久削除せずトークンごとに実行集合を変える。
- 方式等に対しGSP/RCR 推定器自体は重み/ルータ 幾何だけで構築する。ただし予算 閾値 対応付けはラベルなし ワークロード 通過処理を使う。
- SERE/XShareのバッチ-level sharing/re-ルーティングと違いトークン-localでバッチ compositionに依存しない。
## 限界
- 報告された閾値は負荷対応であり、未知領域への移行は保証しない。
- 決定的な乱数種一つで、信頼区間はない。
- RCRはルータ-derived 原型を1方向しか使わず単独では高スキップ率で劣化。
- A100 単一GPU 遅延中心で分散 全対全/負荷 均衡未評価。
- arXiv v1本文・pageでACE固有の公式GitHub リポジトリを確認できない。
- 上位-1保持でも損失yでoriginal 出力との厳密 同値性なし。
