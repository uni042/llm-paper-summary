# One Student Knows All Experts Know: From Sparse to Dense

> MoE expert群のweightをTop-KG/SVD-KGなどで単一dense FFNへ集約し、teacher MoEから蒸留してroutingを除去する。NLPでMoE利得88.2%を保持し、TPU v3-8で3.7倍高速化する。

## 概要

混合専門家モデル（Mixture of Experts; MoE）は、各tokenを少数のexpertだけへ送ることでparameter数を増やしながら1 token当たりの演算を抑えられる。しかしdeployment側から見ると、gate/router、expertごとの分岐、sparse gather/scatter、expert間の不均衡を扱う必要があり、同じFLOPsのdense modelよりhardware utilizationが悪くなることがある。

OneSが狙うのはMoEをそのまま高速に実行することではない。**既に学習済みのMoEが持つ複数expertの知識を、一つのdense studentへ統合し、推論時にはMoE自体を捨てる**。論文はこの設定をknowledge integrationと呼ぶ。

単純にexpert weightを平均するだけでは、expertごとに異なるfeatureが相殺される。そこでまずMoE layerのweightから「重要な方向」を選んでdense FFNへ初期化するknowledge gatheringを行い、その後、元のMoE teacherの出力を使うknowledge distillationでweight統合時のnoiseを補正する。

結果として推論時のmodelは通常のdense Transformerになり、routerもexpert dispatchも不要になる。NLPではMoEによる改善の88.2%を保持しつつ、TPU v3-8上でteacher MoE比3.7倍のinference speedupを報告する。重要なのは、これは「同じMoEを3.7倍高速にserveする」のではなく、**性能の一部をdense modelへ移してMoEをdeployment pathから除去する**方式だという点である。

## 問題設定

### MoEのdeployment costはFLOPsだけでは決まらない

MoE layerではgateがexpertを選び、tokenをexpert別に並べ替えてFFNを実行し、結果を元のtoken順へ戻す。Expert数が多いほどparameter capacityは増えるが、sparse einsumやrouting処理はdense GEMMほどregularではない。

論文のteacher WideNetではMoE/FFN layer単体のFLOPsはdense studentの2.4倍だが、実測inference speedは3.7倍差になる。つまりFLOPs削減だけでは説明できず、dense architectureがhardwareで効率よく実行できる効果も含まれる。

### 「teacherの出力だけ蒸留」ではexpert内のpre-trained knowledgeを使い切れない

通常のknowledge distillationではrandomまたは既存dense checkpointからstudentを初期化し、teacher logitsを追わせる。しかし既にMoE teacher内にはexpertごとに異なるpre-trained weightが存在する。

OneSはこのweight自体をstudent initializationへ使う。したがってtrainingは、

1. expert parameterからdense weightを作るknowledge gathering、
2. teacher predictionでその初期化をrefineするknowledge distillation、

の二段階になる。

## 手法のあらまし

Embeddingやself-attentionのようにteacherとstudentで形が同じ層はteacher weightを直接引き継ぐ。違いがあるのは、teacherでは複数expert FFN、studentでは1個のdense FFNになる部分である。

そこで各expertのweight matrixをsummation、averaging、Top-KG、SVD-KGのいずれかでstudent sizeへ圧縮・統合する。論文ではSVD-KGが最も安定して高性能で、以降の主方式として使われる。

初期化後はteacher MoEをfreezeし、task lossとsoft distillation lossの組合せでstudentを追加学習する。Downstream fine-tuning時にはteacherを持ち続けず、dense OneSだけを使うため、deployment時にMoE runtimeを要求しない。

## 手法

### 1. Summation / averaging — 最も単純なexpert統合

各expertのFFN weightを同じ座標ごとに足す、またはexpert数で割って平均する。実装は簡単だが、異なるexpertで強いfeature directionが違う場合、互いに相殺したり、student capacityへ収める際の選択性がない。

このbaselineがあることで、OneSの改善が「MoE weightを使ったこと」だけなのか、それとも重要componentを選んで統合したことに由来するのかを切り分けられる。

### 2. Top-K Knowledge Gathering（Top-KG） — 大きなweight featureだけを残す

Top-KGはexpert weightのcolumn/rowなどをnormでrank付けし、重要度が高いcomponentをstudent capacityに合う数だけ選ぶ。

入力はE個のexpert weight、出力は単一dense FFNと同じshapeのweightである。すべてのexpertを平均して情報をぼかす代わりに、各expertで強く学習されたfeatureを優先してdense modelへ持ち込む。

一方、normが小さいが組合せとして重要なdirectionを落とす可能性があり、selectionがhardである。論文ではlarge modelでSVD-KGに近い結果を示すが、base-scaleではSVD-KGがより良い。

### 3. Singular Value Decomposition Knowledge Gathering（SVD-KG） — expertの重要subspaceを集める

SVD-KGでは各expert weight (W_i) を特異値分解（Singular Value Decomposition; SVD）し、

`W_i = U_i S_i V_i^T`

として扱う。大きなsingular valueに対応するdirectionほど、そのweight matrixの主要な構造を表すとみなし、adaptiveなSVD ratio `λ` に従って上位componentを残す。

各expertから圧縮したlow-rank componentを集め、studentのdense weightへ再構成する。Top-KGが個々のcolumn/rowを直接選ぶのに対し、SVD-KGはexpert weightが張るsubspaceを重要度順に扱えるため、異なるexpertの知識をより滑らかに統合できる。

AblationではSVD ratioにも最適領域があり、圧縮し過ぎればexpert knowledgeを失い、残し過ぎればstudent capacityへ収まらない。論文はSVD-KGを主方式に採用する。

### 4. Knowledge distillation — weight集約で混ざったnoiseをteacher predictionで補正する

Knowledge gatheringはparameter空間の操作なので、統合後weightが元MoEと同じfunctionを実現する保証はない。そこでteacher MoEのlogitsとstudent logitsの差をsoft distillation lossで縮める。

基本形はtemperature `T` を使ったsoftmax間のKL divergenceで、taskのmain lossと線形結合する。Vision実験ではteacherをfreezeし、studentだけを更新する。

NLP pre-trainingではmasked language modelingやsentence order predictionのmain objectiveにdistillation lossを加える。ただしdownstream taskへfine-tuneするときはteacherを使わない。これは「deploymentを簡単にする」という目的上、fine-tuning時までMoE teacherを必須にするとMoE実行環境を残してしまうためである。

## 評価

### 代表的な評価条件

| 項目 | 条件 |
|---|---|
| Vision | ImageNet、CIFAR-10 |
| NLP | SQuAD1.1、SQuAD2.0、MNLI、SST-2 |
| MoE teacher | WideNet |
| Dense NLP baseline | ALBERT |
| 比較 | Dense baseline、Distill、Switch、各knowledge-gathering方式 |
| Inference hardware | TPU v3-8 |
| NLP student | 12M parameters |
| NLP teacher | 26M parameters |
| FLOPs表記 | FFN/MoE layer部分のみを比較 |
| Downstream fine-tuning | OneS単体、teacher distillationなし |

### NLP結果

| Model | Params | FFN/MoE FLOPs | Speedup | SQuAD1.1 F1/EM | SQuAD2.0 F1/EM | MNLI | SST-2 | Avg | MoE benefit |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| WideNet teacher | 26M | 2.4 | 1.0× | 89.6 / 82.7 | 80.6 / 77.4 | 82.6 | 91.1 | 84.71 | — |
| ALBERT | 12M | 1.0 | 3.7× | 89.3 / 82.3 | 80.0 / 77.1 | 81.5 | 90.3 | 84.03 | 0% |
| Distill | 12M | 1.0 | 3.7× | 89.4 / 82.7 | 79.8 / 76.6 | 81.9 | 90.7 | 84.21 | 26.5% |
| Switch | 12M | 1.0 | 3.7× | 89.5 / 82.6 | 79.9 / 77.0 | 82.0 | 90.3 | 84.20 | 25.0% |
| OneS | 12M | 1.0 | 3.7× | 89.7 / 83.0 | 80.2 / 77.1 | 82.3 | 91.2 | 84.63 | 88.2% |

OneSはteacherの平均84.71に対して84.63まで近づき、SQuAD1.1とSST-2ではteacherをわずかに上回る。論文はこれを、MoEが小さいdownstream datasetでoverfitしやすい一方、dense化したOneSではpre-training knowledgeを移しやすい可能性として解釈している。

### Vision結果とablation

ImageNetではOneS-L-SVDが15M parametersで78.4% top-1を達成し、MoEによる改善の61.7%を保持する。Dense WideNet-L相当は76.9%であり、同じdense architectureでもMoEからknowledge gatheringした初期化が差を生む。

| ImageNet model | Top-1 |
|---|---:|
| OneS-B | 75.7 |
| OneS-B without KG | 73.8 |
| OneS-B without KD | 75.0 |
| OneS-B without KG/KD | 72.8 |
| OneS-L | 78.4 |
| OneS-L without KG | 77.3 |
| OneS-L without KD | 77.6 |
| OneS-L without KG/KD | 76.9 |

Knowledge gathering（KG）を外した低下の方が大きく、distillation（KD）も追加改善を持つ。つまりOneSは「普通のdistillationだけ」ではなく、**MoE expert weightをstudent initializationへ直接再利用する段階が主要component** である。

### 3.7倍speedupの読み方

論文のspeedupはTPU v3-8でのteacher MoE対dense student比較である。MoE layerのFLOPsはteacherが2.4倍だが、実測speedupは3.7倍なので、差の一部はrouting/sparse operatorを除いたregular dense executionに由来する。

一方、model全体のFLOPsが2.4倍違うわけではない。Attention等の他layerは同じため、論文自身もglobal FLOPs差は2.4倍未満と明記している。この点が「dense化するとhardware-friendly」という主張を支える。

## 既存研究との差

通常のknowledge distillationはteacherの出力distributionやhidden representationをstudentへ学ばせる。OneSはその前に **teacherのexpert parameterをdense studentへ物理的に集約するknowledge gathering** を置く。

Switch Transformer等のMoE圧縮とは異なり、推論時にexpert選択を残さない。Deployment後のmodelは普通のdense Transformerなので、expert parallelism、router、all-to-all、sparse kernelを必要としない。

この設計は、MoEをserveし続けるのではなく「pre-trainingではMoEのcapacityを利用し、deployment時にはdenseへ変換する」という別のライフサイクルを提案している。

## 限界・実装状況

MoEの全benefitを保持するわけではない。ImageNetでは61.7%、NLPでは88.2%であり、task/modelによってknowledge lossが変わる。

SVD-KGはexpertが同じarchitecture/weight shapeを持つことを前提にする。論文自身も、異なるarchitectureのexpertをどう統合するか、GLaM級の巨大MoEへscaleするかを将来課題として挙げる。

Dense studentを作るため追加trainingが必要で、training-time costを削減する方式ではない。Inference deploymentを簡単にする代わりに、変換・distillation stageを事前に支払う。

評価modelは現在の数百B級LLM MoEより小さく、TPU v3-8での3.7倍を現代GPU clusterへそのまま外挿できない。現在のfused MoE kernelやhigh-speed interconnectではsparse execution costも変化している。

公式code repositoryは確認できない。

## 一般的な実装上の含意

MoEの価値を「推論時もexpertを保持すること」と同一視する必要はない。MoEをpre-training時のcapacity拡張として使い、その後にdense化できるなら、serving runtimeは大幅に単純化できる。

またmodel compressionではparameter数やFLOPsだけでなく、routing、gather/scatter、sparse operatorなど **hardware上で不規則になる制御cost** を除けるかが重要である。OneSの2.4倍FFN-FLOPs差に対する3.7倍実測差は、その典型例として読める。
