# One Student Knows All Experts Know: From Sparse to Dense

> 事前学習済みMoEの専門家FFNを上位K抽出またはSVDで単一の密モデルへ統合し、MoE教師による蒸留で補正するOneSを提案。NLPでMoE利得88.2%を保持し、TPU v3-8上でWideNet比3.7倍の推論高速化を示す。

## 概要

混合専門家モデル（Mixture of Experts; MoE）は、各入力を全てのフィードフォワードネットワーク（Feed-Forward Network; FFN）へ通すのではなく、ルータが上位K個の専門家だけを選ぶことで、活性計算量を抑えながら多数のパラメータを持てる。ただし「計算する専門家が少ない」ことと「ハードウェアで速い」ことは同じではない。

複数装置へ専門家を分けると、トークンを担当専門家へ送り直す全対全通信（all-to-all communication）が必要になる。単一装置内でも、上位K選択、トークンマスク生成、専門家別の並べ替え、疎な行列演算など小さく不規則な処理が増え、カーネル起動やデータ移動の費用が無視できない。本論文はこの配備問題を、MoEをそのまま高速化するのではなく、**MoEで学習した知識を一つの密モデルへ移して、推論時のMoEそのものを消す**方向から解く。

提案するOneSは、まず事前学習済みMoEの各専門家FFNを一つの学生FFNへまとめる**知識集約（Knowledge Gathering; KG）**を行う。単純な加算・平均に加えて、専門家ごとに重要な列を選ぶ**上位K知識集約（Top-K Knowledge Gathering; Top-KG）**と、特異値分解で重要部分を抽出して結合する**特異値分解知識集約（Singular Value Decomposition Knowledge Gathering; SVD-KG）**を提案する。

ただし複数専門家を一つへ押し込むと、条件付きルーティングが表現していた「入力ごとに専門家を切り替える」構造が失われ、重み統合にもノイズが入る。そこで第二段階として、元MoE全体を教師とする**知識蒸留（Knowledge Distillation; KD）**を行い、学生出力を教師出力へ近づける。

評価ではImageNetで15MパラメータのOneS-Lが78.4% top-1を達成し、構成によってMoEが密モデルに対して持っていた改善の最大61.7%を保持する。NLPでは12MパラメータのOneSがMoE利得の88.2%を保持し、TPU v3-8上で教師WideNet MoE比3.7倍の推論速度を報告する。一方、この研究は2022年のWideNet/ALBERT級モデルが中心で、現代の数十〜数百B級デコーダ型LLMや大規模専門家並列を直接評価したものではない。

## 問題設定

### MoEの「疎さ」は必ずしも実装上の効率にならない

MoE層では、入力表現 (x) に対してルータが専門家ごとの重みを計算し、通常は上位1〜2個だけを活性化する。理論上は全専門家を計算しないため、同程度のFLOPsで密モデルより大きな容量を持てる。

しかし実行系では、ルータの上位K選択、各専門家へ送るトークンのインデックス生成、マスク作成、累積和、専門家ごとの疎な演算が必要になる。複数装置ならさらにall-to-all通信が加わる。論文は、こうした疎テンソル操作と多数のカーネル呼び出しがMoEを「ハードウェア非友好的」にすると位置付ける。

また、MoEは学習可能パラメータが多いため、事前学習後に小規模な下流データセットへ微調整すると過学習しやすいという問題も扱う。つまりOneSの目的は、単純な推論高速化だけでなく、**MoEの事前学習で獲得した容量上の利点を、扱いやすい密モデルへ持ち越すこと**にある。

### 何を「MoEの知識」とみなすか

対象MoEでは各専門家がFFNであり、専門家 (i) は二つの線形層を持つ。学生モデルは専門家一個と同じ形の単一FFNを持つ。注意層、埋め込み、正規化など教師と学生で形が一致する層は、そのまま重みをコピーできる。

難しいのは、E個の専門家に分散したFFN重みを一個のFFNへどう収めるかである。単純平均では専門家ごとの特徴が相殺され得る。一方、全専門家の全パラメータを保持すれば密モデルへ縮めた意味がない。OneSはここを「各専門家の重要な部分だけを抽出し、学生FFNの限られた幅へ詰め直す」問題として定式化する。

## 手法全体

OneSの知識統合は二段階で進む。

1. **知識集約:** 教師MoEと学生で同形の層は重みをコピーする。MoE層では複数専門家FFNの重みから、加算・平均・Top-KG・SVD-KGのいずれかで一つの学生FFNを構築する。バイアスは専門家間で平均する。
2. **知識蒸留:** 集約済みの密学生を初期値として、元MoEのロジットを教師信号に使い、主タスク損失と蒸留損失の加重和で再学習する。

推論時には教師MoEを使わない。完成したOneSは通常の密Transformerなので、ルータ、専門家ディスパッチ、all-to-all通信、疎な専門家演算が消える。ここが実行時最適化としての本質である。

## 手法

### 1. 単純加算・平均 — 基準となる集約

最も単純には、E個の専門家重み (W_f^i) を足し合わせるか平均し、学生の重み (W_g) とする。バイアスはパラメータ数が少ないため全専門家で平均する。

この方法は追加の分解計算を必要としないが、専門家が異なる入力領域へ特化している場合、重要方向と不要方向を区別せず混ぜる。論文では、より選択的なTop-KGとSVD-KGの比較基準として使う。

### 2. Top-KG — 大きな列を専門家ごとに残す

**上位K知識集約（Top-KG）**では、各専門家の重み行列について列ごとのL2ノルムを計算し、ノルムが大きい上位K列だけを取り出す。学生の出力幅を (d_2)、専門家数をEとすると、基本的に各専門家から (K=d_2/E) 列を取り、全専門家分を連結して元の学生幅へ戻す。

TransformerのFFNは二つの線形層を連続して使うため、第一層の列だけを独立に選ぶと、第二層で対応する中間次元がずれる。そこで第一層の列ノルムと第二層の対応行ノルムを合算し、そのスコアで同じ中間ユニットを選ぶ。

入力は各専門家FFNの重み、処理は重要中間次元の選択、出力は複数専門家由来の列を持つ一つの学生FFNである。利点はSVDより単純なことだが、列単位で削るため、重要情報が複数方向へ分散している場合は取りこぼしやすい。

### 3. SVD-KG — 各専門家の重要な特異方向を集める

**SVD-KG**では各専門家重みを特異値分解（Singular Value Decomposition; SVD）し、重要な特異方向を低ランク表現として抽出する。ただし目的は最終モデルを低ランクのまま実行することではない。SVDはあくまで、各専門家が持つ主要方向を選び出す中間操作である。

固定ランクKを全専門家へ同じように割り当てると、複雑な専門家と単純な専門家へ同じ容量を使ってしまう。そこでSVD-KGは、特異値総和の一定比率 (lambda) を保持するまで専門家ごとにランク (K^i) を選ぶ。必要ランクは専門家ごとに変わる。

その後、各専門家の左特異ベクトル、特異値、右特異ベクトルをブロック状に連結し、学生用の一つの高ランク重み (W_g) を再構成する。これにより、単純な列選択より「専門家ごとの主要な低ランク方向」を保った状態から学生を開始できる。

評価ではSVD-KGがImageNetの基本構成で最も良く、以降の標準設定として使われる。一方、SVD自体にはオフライン計算費用があり、現代の巨大MoEで全専門家へ適用する場合のコストは本論文では評価されていない。

### 4. 知識蒸留 — 集約で失われた条件付き構造を出力から補う

知識集約だけでは、元のMoEが入力ごとに異なる専門家を選んでいた条件付き計算を一個の重みへ完全には写せない。論文はこのずれを「集約ノイズ」と捉え、元MoE全体の出力を教師として学生を再学習する。

ソフト蒸留では、教師と学生のロジットを温度付きsoftmaxへ通し、カルバック・ライブラー発散（Kullback-Leibler divergence; KL divergence）を最小化する。最終損失は主タスク損失と蒸留損失の加重和である。

重要なのは、蒸留だけの比較対象と違って、OneSは**教師MoEの専門家重みを使った初期化の後に蒸留する**点である。構成要素除去実験では、知識集約を外した時の性能低下が蒸留だけを外す場合より大きく、両段階が補完的であることを示している。

### 5. 推論時にはMoE機構を完全に外す

学習が終わるとOneSは通常の密モデルとして動く。ルータも専門家の分散配置も不要で、FFNは通常の密な行列演算になる。

NLP評価のWideNetではMoE層のFLOPsがOneSの2.4倍だが、モデル全体ではMoE以外の層が共通なので全体FLOPs差は2.4倍未満である。それでも実測推論速度は3.7倍になった。論文は、この差を計算量だけでなく、MoEのゲート処理、疎なeinsum、カーネル起動などの非効率が消えるためだと説明する。

## 評価

### 評価条件

| 項目 | 条件 |
|---|---|
| 視覚教師 | WideNet-Base / WideNet-Large（MoE） |
| 視覚学生 | OneS-Base / OneS-Large。教師と形が合う層は共有・コピーし、MoE FFNを密FFNへ統合 |
| 視覚データ | ImageNet ILSVRC-2012（1000クラス、約1.3M画像）、CIFAR-10 |
| ImageNet学習 | バッチ4096、学習率0.004、LAMB。蒸留係数 (alpha=0.25)、温度T=1.0 |
| NLP事前学習 | English Wikipedia + BookCorpus |
| NLP下流評価 | SQuAD1.1、SQuAD2.0、MNLI、SST-2。GLUE系は5回の中央値 |
| NLP学生 | ALBERTに近い12Mパラメータの密モデル |
| NLP教師 | 26MパラメータのWideNet MoE |
| 推論速度 | TPU v3-8で比較 |
| 主指標 | ImageNet top-1、NLP平均スコア、MoE benefits、パラメータ数、FFN/MoE層FLOPs、推論速度 |

論文独自の**MoE利得（MoE benefits）**は、通常の密モデルから教師MoEへ改善した差のうち、学生が何割を回収したかを
((score_{student}-score_{dense})/(score_{MoE}-score_{dense}))
で表す。100%なら教師MoEの改善を全て密学生へ移せたことになる。

| 条件 | 比較 | OneS | 結果・意味 |

| ImageNet、OneS-B SVD | WideNet-B教師 77.5%、通常密モデル 72.8% | 75.7%、10M | MoE利得61.7%。Switch-Bの42.6%を上回る |

| FFN/MoE層FLOPs | WideNet 2.4× | OneS 1.0× | 対象層の計算量を削減 |
| TPU v3-8推論 | WideNet 1.0× | OneS 3.7× | FLOPs差以上に、疎ルーティング・疎演算の除去が速度へ効く |
| CIFAR-10、Large | Switch-L 98.3、WideNet-L 98.8 | OneS-L 98.5 | ImageNetで統合した知識が下流微調整へ持ち越される |

NLPではOneSがSQuAD1.1やSST-2で教師MoEをわずかに上回る条件もある。論文は、MoEが小規模下流データで過学習しやすいことが理由の一つだと解釈している。ただしこれは一般に密モデルがMoEより優れるという主張ではなく、評価したWideNetと下流設定での観察である。

### 知識集約方式の比較

ImageNetでは単純加算、平均、Top-KG、SVD-KGを比較している。Base構成ではSVD-KGが75.7%で最良、Top-KGと平均は75.3%、加算は75.2%だった。Large構成ではTop-KGとSVD-KGはいずれも78.4%で、モデル容量が大きいと列選択の損失へ頑健になる可能性を論文は示唆する。

この結果から、OneSの改善を「蒸留したから」とだけ説明するのは不十分である。重み空間での初期知識集約が学生の出発点を改善し、その後の蒸留が集約ノイズを補正するという二段階が中心である。

## 既存研究との差

従来の知識蒸留では、学生をランダム初期化するか、教師と形が一致する層だけをコピーして、MoE固有の専門家重みは学生へ直接使わないことが多い。Switch系の初期化も、対応しない専門家FFNは新規学習に任せる。

OneSはここを変え、**専門家FFNそのものを学生FFNの初期値へ変換する**。Top-KGは重要中間次元、SVD-KGは重要特異方向を専門家ごとに抽出し、複数専門家の内部知識を蒸留前から一つの重みへ埋め込む。

また、MoE推論高速化研究の多くがルーティング、専門家配置、all-to-all通信の最適化を狙うのに対し、OneSは推論段階からMoE構造を除去する。その代わり、推論時に入力ごとに異なる専門家を使い分ける能力は失われる。これは「MoEを速くする」方式ではなく「MoEを学習用教師として密モデルへ変換する」方式である。

## 限界・実装状況

評価モデルはWideNet、ALBERT、ViT系であり、2022年時点の比較的小規模なTransformerが中心である。現代のデコーダ型LLM、数十〜数百B級MoE、数百専門家を持つモデルで同じ保持率や3.7倍高速化が得られることは示していない。

推論3.7倍はTPU v3-8上のWideNet対OneS比較であり、GPU上の現代的な融合MoEカーネル、DeepEPのような通信最適化、低ビットMoE、連続バッチ配信との比較ではない。現在のMoEランタイムでは疎実行効率が大きく改善しているため、倍率をそのまま外挿できない。

SVD-KGは全専門家の重みを分解するオフライン処理を必要とする。教師MoEが極端に大きい場合のCPU/GPUメモリ、分解時間、ストレージI/Oは論文で主評価されていない。

最終学生は密モデルなので、推論は容易になる一方、MoEの総パラメータ容量を完全には保持できない。NLPで88.2%、ImageNetで最大61.7%というMoE利得は、知識の一部が失われることを示す指標でもある。

また、論文自身が将来課題として、異なるアーキテクチャを持つ専門家からの集約やGLaM級巨大MoEへの拡張を挙げている。現在の手法は専門家が同型FFNであることを強く利用している。

## 一般的な実装上の含意

MoEを本番で運用する際、必要なのが「入力ごとの専門家切替」そのものではなく、事前学習で得た高容量モデルの知識であるなら、配信時に疎構造を維持しない選択肢がある。特に通信やルーティング管理費用が大きい環境では、教師MoEを密モデルへ変換することで実装を単純化できる。

その際、単純な出力蒸留だけでなく、教師内部の専門家重みを学生の初期化へ利用すると学習効率を改善できる可能性がある。OneSの構成要素除去では、知識集約を外す方が蒸留だけを外すより大きく性能が落ちており、内部パラメータ転送と出力蒸留を組み合わせる意義が示されている。

一方、現代の大規模MoEへ応用するなら、SVDのオフライン費用、専門家間の不均一性、量子化済み重み、共有専門家、細粒度専門家、デコーダ自己回帰品質などを再評価する必要がある。
