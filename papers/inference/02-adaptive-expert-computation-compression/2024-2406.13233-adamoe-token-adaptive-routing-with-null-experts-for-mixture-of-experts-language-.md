# AdaMoE：計算しない空専門家を選ばせて、トークンごとの専門家数を変える

## 概要

混合専門家モデル（Mixture-of-Experts、MoE）の多くは、各トークンについてルータが上位k個の専門家を選び、毎回ちょうどk個のフィードフォワード計算を行う。しかし、終了記号のように比較的単純なトークンと、複雑な推論を要するトークンが同じ数の専門家を必要とするとは限らない。単純なトークンにも固定のk個を実行すると計算が余り、逆に難しいトークンへ多く割り当てる自由度がなくなる。

AdaMoEは計算を行わない「空専門家（null expert）」をルータの候補へ追加し、上位k件を選ぶ仕組みは保ちながら、選択された候補のうち**実際の専門家が占める数だけ**計算する。例えば上位3件のうち実専門家1個・空専門家2個なら、フィードフォワード計算は1個分で済む。空専門家の利用を調整する補助損失により、トークンごとの専門家数を変化させつつ、平均的な計算予算を制御する。

原著は既存のMixtral-8x7Bを微調整した6課題で、通常の上位2専門家選択の平均実行数2.00に対し、AdaMoEの設定m=8、k=3では1.66へ低下し、浮動小数点演算量（FLOPs）が平均15.21%減ったと報告する。精度の6課題平均は84.64から85.35へ改善した。ただし、PIQAとOpenBookQAでは小幅な精度低下があり、**FLOPs削減率をそのまま実機の応答時間短縮率として扱ってはならない**。

## 問題設定

通常のMoEでは、ルータが各トークンに対してn個の専門家の得点を計算し、上位k件の得点だけを残して正規化し、各専門家の出力を加重合算する。Mixtral-8x7Bは8個の実専門家から常に2個を選ぶ。この規則は配信実装にとって単純だが、専門家の利用価値が入力ごとに変化しても、計算量を変えられない。原著はSocialIQAの入力でMixtralのルーティング得点分布を観測し、少数の専門家へ確率が集中するトークンと、複数へ分散するトークンが混在することを示す。

既存の専門家側選択方式（expert-choice routing）は、専門家がトークンを選ぶため、各トークンが使う専門家数を変えられる。しかし未来のトークンを含む集合で割当を決める方式は、次トークンがまだ存在しない自己回帰生成と相性が悪い。AdaMoEはトークン側の上位k件選択を維持し、未来の入力を参照せずに実行専門家数を変える。

## 手法

### 1. 空専門家をルータ候補へ加える

通常のn個の実専門家にm個の空専門家を加え、ルータの出力次元をn+mへ拡張する。空専門家は原著の主設定ではゼロ写像であり、入力を受けても重い行列積を実行せず、出力の寄与がゼロになる。上位k件を選ぶ操作は従来と同じで、選択枠に空専門家が入るほど実専門家の計算が減る。例えば8実専門家、8空専門家、上位3件選択のとき、あるトークンは実専門家3個、別のトークンは1個だけを選び得る。

ここでmは追加する空専門家の個数、kは実専門家と空専門家を合算した候補から選ぶ総数である。原著の図2は、通常の上位2件選択に対して、空専門家を含む上位4件選択でトークンごとに実専門家数を変える例を示す。全候補が空専門家なら、トークンは実質的にそのMoE層の計算を迂回できる。ルータの選択数は固定でも、計算を実行する実専門家数は可変になる。

### 2. 空専門家を同一視する負荷分散損失

通常のMoEには、一部の専門家へトークンが集中しすぎないようにする負荷分散損失がある。これを空専門家へそのまま適用すると、計算しない空専門家同士まで均等に選ばせようとし、同じ機能の候補間に不要な制約を課す。AdaMoEの式(6)は、実専門家にはそれぞれの選択頻度f_iを使う一方、空専門家には空専門家全体の選択頻度をmで割った平均値を使う。これにより空専門家全体の利用量は制御しつつ、どの空専門家が選ばれるかまでは強制しない。

この設計は「簡単なトークンを必ず何個の空専門家へ送る」という固定規則ではない。個々のトークンはルータの得点に応じて異なる数の空専門家を選ぶ。補助損失は平均的な計算量を調整し、トークンごとの選択には自由度を残す。原著Table 3では空専門家同士も個別に均等化する通常型損失と比較し、RTEで56.68対67.51、CoLAで83.68対85.01と、空専門家を同一視する方式が改善した。

### 3. 学習前半と後半で制約の強さを変える

空専門家の利用を最初から自由にしすぎると、実専門家へ負荷が偏ったり、計算を減らしすぎたりする。AdaMoEは補助損失の係数αを学習初期に大きくし、後半で小さくする。Mixtralの主実験では2エポックの微調整を行い、最初のα=0.02から次のα=0.0001へ緩める。初期に平均負荷を制御してから、後半で各トークンに必要な専門家を選ぶ自由度を増す。

原著Table 5では、WinoGrandeで第1エポック後のAdaMoE正解率76.24・負荷1.65が、第2エポック後に81.93・負荷1.66となる。負荷をほとんど増やさず精度を改善したという意味であり、推論時に係数を毎トークン変える処理ではない。学習中の係数変化と、完成モデルが推論時に行うルーティングを混同しない。

### 4. 実専門家だけで出力の正規化を行う

選択された上位k件の得点を全候補で正規化すると、出力ゼロの空専門家にも確率質量が割り当てられ、実専門家からの加重出力が小さくなる。AdaMoEは実専門家だけを対象に確率を正規化し、通常のMoEと出力スケールを揃える。原著Table 4ではSIQAの精度が全候補正規化の80.19から実専門家のみ正規化の81.27へ改善した。平均負荷は1.50から1.54であり、単なる専門家数の増加だけで説明できない差がある。

### 5. 既存モデルへ組み込む際の変更

密なLlama2-7Bには低ランク適応（LoRA）の分岐を複数設け、Mo-LoRAのルータへ空専門家を加える。既存のMixtral-8x7Bでは、元の8実専門家を保持したまま、空専門家へ得点を出す追加ゲートを設ける。原著の実装では既存ゲートのパラメータを利用して新しいゲートを初期化し、量子化付き低ランク微調整（QLoRA）でルータと対象行列を更新する。**単に推論時に空専門家を追加すれば同じ性能になるわけではなく、利用の仕方を微調整で学習する必要がある**。

## 評価

### 評価設定

| 観点 | 条件 |
|---|---|
| 主モデル | Mixtral-8x7B。元の上位2件ルータと比較。密なLlama2-7BのMo-LoRA構成も評価 |
| データセット | WinoGrande、HellaSwag、PIQA、SocialIQA、OpenBookQA、ARC-Challenge |
| 微調整 | 各課題1000例、2エポック、4ビットQLoRA、LoRAランク8、学習率5×10⁻⁵ |
| 負荷分散係数 | 第1エポック0.02、第2エポック0.0001 |
| 代表的な空専門家設定 | m=8、k=3。元モデルはm=0、k=2 |
| 指標 | 課題正解率、平均実専門家数（Load）、演算量（FLOPs）削減率 |
| 評価の範囲 | 微調整後のモデルの品質と演算量。配信環境での端点遅延・処理率は主要実測に含まれない |

原著のTable 1は、同じ課題で微調整したMixtralとAdaMoEを比較する。元の未微調整Mixtralとの比較では学習による改善が混ざるため、計算削減の効果を見るには微調整済み比較対象を使う必要がある。実専門家数が2.00から1.66へ減ることはフィードフォワード層の計算が減ることを示すが、注意機構、ルータ、通信などの費用は残る。

Table 2では空専門家数mと上位選択数kを変えた感度を検証する。SocialIQAでm=32、k=4では平均負荷0.77まで下がるが、正解率は66.27と基準76.36を大きく下回る。m=32、k=6では負荷1.54で正解率76.46となり、基準をわずかに上回る。同じ計算予算でも設定によって品質が異なるので、空専門家を増やせば無条件に効率が良くなるとは言えない。

補助損失の検証では、空専門家を区別せず平均負荷だけを使う損失が、個々の空専門家まで均等化する損失よりRTE、CoLA、ScienceQA、OpenBookQAで高い精度を示す。出力の正規化を実専門家だけに限定する構成要素除去実験も、SocialIQAで80.19から81.27へ改善する。これらは単に空専門家を追加するだけでなく、**学習時の負荷制御と出力の正規化が精度を左右する**ことを裏付ける。

## 既存研究との差

専門家選択型ルーティングは専門家がトークンを選ぶため、未来のトークンがまだ存在しない自己回帰生成では扱いにくい。AdaMoEはトークン側の上位k件選択を保ち、空専門家を使って実計算量だけを変える。単純に上位kの数をトークンごとに変える方法と違い、従来の上位k件選択機構を再利用できる点が実装上の利点である。一方、学習時の空専門家利用制御が必要であり、既存の固定ルータを無変更で使えるわけではない。

## 限界

論文の限界節では、資源の制約からAdaMoEを使ったMoEの事前学習を行っていないと明記する。既存モデルの微調整結果が中心であり、初期学習から同じ効果が得られるかは未検証である。また空専門家をゼロ写像でなく恒等写像にする構成は評価していない。計算量削減は演算数の測定であって、GPUカーネルの負荷分散、トークンの振り分け、バッチ形状による端点遅延の変化を測ったものではない。

空専門家を選ぶ割合が高すぎるとSocialIQAで正解率が大きく落ちる。学習データ、タスク、空専門家の個数、補助損失係数の選択に依存するため、平均実専門家数1.66やFLOPs15.21%削減を別モデルへ固定適用できない。公式コードは公開されているが、実配信での速度・電力・メモリ帯域の検証は別途必要となる。
