# Dynamic Experts Search: Enhancing Reasoning in Mixture-of-Experts LLMs at Test Time

> MoEの活性化エキスパート数をTTSの探索軸に加え、推論軌跡ごとに構成を継承して同程度の計算量で推論多様性と正解率を高める。

## 概要
動的 エキスパート Search（DES）は、混合エキスパート（Mixture-of-エキスパート; MoE）モデルで推論時に活性化するエキスパート数を探索変数として扱うテスト時スケーリング（Test-Time Scaling; TTS）手法である。異なる活性化数は平均精度を大きく変えない一方、正解できる問題集合が相補的になるという観察を利用する。動的 MoEで各ロールアウトの活性化数を変更し、エキスパート Configuration Inheritanceで同一推論軌跡内の活性化数を固定することで、検証器が高報酬の構成を自然に残す。Qwen3-30B-A3B、Ling-lite-1.5、OLMoE、DeepSeek-V2-Liteを用いた数学・コード・知識推論で、同程度の生成トークン数のBest-of-N、Beam Search、DVTSより概ね高い精度を示す。

DESはMoEの活性化エキスパート数kを固定ハイパーパラメータではなくTTSの探索変数へ昇格させる。動的 MoEにより同じ状態から異なるkで候補ステップを生成し、エキスパート Configuration Inheritanceにより一度選ばれたkをその推論軌跡の後続ステップへ継承する。初期段階では複数のkへ計算予算を均等配分するが、検証器が低報酬の状態を枝刈りするため、結果的に有望なkを持つ軌跡へ後段の計算が集中する。重要なのは、単純に活性化数を増やしてFLOPsを増やすのではなく、既定値を挟む複数のkを同じロールアウト予算内で探索し、構造的多様性を利用する点である。

代表結果として、Qwen3 MATH500 AccuracyはQwen3-30B-A3B-Instruct、Qwen2.5-Math-PRM-7B、N=32でBest-of-N 92.40%、BeamSearch 93.00%、DVTS 87.40%に対して93.20%。同じロールアウト予算で構造的探索軸を加えることで小幅ながら最高精度を得る。
## 問題設定
既存のテスト時スケーリング（Test-Time Scaling; TTS）は、同じ方策モデルから温度サンプリングで複数の回答や中間ステップを作り、検証器や多数決で最終解を選ぶ。しかし多様性の源は出力トークンの確率性にほぼ限定され、モデル内部の計算経路は固定される。このためロールアウト数を増やしても似た失敗軌跡を繰り返し、固定計算予算で探索できる解集合が狭くなる。混合エキスパート（Mixture-of-エキスパート; MoE）は多数のFFNエキスパートから一部をルーティングで選ぶ構造を持つのに、従来TTSはこの構造自由度を利用していなかった。

著者らはMoEの活性化エキスパート数を変える予備実験で、活性化数ごとの平均Accuracyは大きく変わらない一方、正解できる問題集合のJaccard類似度が低く、あるkで失敗した問題を別のkで解けることを確認した。したがってボトルネックは単純なモデル容量不足ではなく、固定kの計算経路だけを繰り返し探索することにある。毎ステップ全kを無差別に試すと計算予算を浪費するため、初期には構成を広く探索しつつ、途中から有望な構成へ予算を集中する仕組みが必要になる。
## 新規性
DESはMoEの活性化エキスパート数kを固定ハイパーパラメータではなくTTSの探索変数へ昇格させる。動的 MoEにより同じ状態から異なるkで候補ステップを生成し、エキスパート Configuration Inheritanceにより一度選ばれたkをその推論軌跡の後続ステップへ継承する。初期段階では複数のkへ計算予算を均等配分するが、検証器が低報酬の状態を枝刈りするため、結果的に有望なkを持つ軌跡へ後段の計算が集中する。重要なのは、単純に活性化数を増やしてFLOPsを増やすのではなく、既定値を挟む複数のkを同じロールアウト予算内で探索し、構造的多様性を利用する点である。
## 手法
### 手法のあらまし
入力は質問q、MoE方策モデルπθ、検証器Rφ、総ロールアウト予算N、各段階で保持する候補数M、最大推論ステップT、互いに異なる活性化数集合K={k0,...,kn-1}である。まずs0=qを各kiと組にしてC0={(s0,k0),...}を作り、Nをn構成へ均等配分する。動的 MoEは各kiでN/n個の中間ステップaをπθ(・|s0,ki)から生成し、各結果を([s0,a],ki)として保存する。Rφが全N候補を採点し、上位MだけをC1へ残す。この初期段階で、出力サンプリングとMoE構成の双方に多様性を持つ探索母集団を作る。

次の時刻tではC_tに残った各(s,k)を同じkのまま展開し、各状態からN/|C_t|個の次ステップを生成する。生成したテキストを状態へ連結し、kも一緒に引き継いで再びRφで採点、top-Mへ枝刈りする。低得点軌跡とそのkは消え、高得点軌跡のkが次段へ残るため、明示的な構成選択器を学習せずに検証器が構成レベルの信用割当も担う。この生成→連結→採点→枝刈り→構成継承をEOSまたはTまで繰り返し、最後に完全回答群から最高検証器得点または多数決で単一回答を返す。主設定はN=32、M=N/4、T=10、K={4,5,6,7,8,9,10,11}、温度0.8である。

### 活性化数による構造的多様性
MoEではルーティングがトークン表現に応じて上位エキスパートを選び、通常は学習・推論を通じてtop-kのkを固定する。kを変えると同じ重みでも通過するFFN集合と合成出力が変わるため、温度サンプリングとは別の内部計算経路の多様性が生まれる。著者らは複数kで平均Accuracyが近いにもかかわらず正解問題集合の重なりが小さいことを確認し、構成差を探索資源として利用できると判断した。

DESはこの相補性を候補状態へ明示的に埋め込む。各候補をテキスト状態sだけでなく(s,k)として管理することで、同じ質問・同じ方策重みでも異なる内部経路から推論候補を作る。これにより従来TTSの出力サンプリング多様性を置き換えるのではなく、その上へ構造多様性を追加し、固定ロールアウト予算で到達可能な正解候補集合を広げる。

### 動的 MoE
動的 MoEは標準MoEの固定top-kを推論時パラメータへ変え、方策分布をπθ(・|s,k)として実行する。初期状態ではk=4〜11など複数構成を用意し、総ロールアウトNを均等配分する。各前向き計算では指定k個のエキスパートを活性化し、同じテキスト状態から構成の異なる中間推論ステップを生成する。モデル重みの再学習や新規エキスパート追加は行わない。

重要なのはkを大きくすること自体を目的にしない点である。Qwen3の既定活性化数8に対して主設定は4〜11を対称的に含み、実測平均は既定値以下になる。初期範囲を2〜9から10〜17までずらした実験でも平均活性化数は範囲の平均に追随するため、ルーティングが大きなkだけを選好して性能を上げる方式ではなく、複数構成を探索する方式である。

### エキスパート Configuration Inheritance
各候補状態は、その中間推論ステップを生成した活性化数kを明示的に保持する。状態s_t=[s_{t-1},a_{t-1}]を次に展開するときは、a_{t-1}を生成したのと同じkを使う。この制約によって一つの推論軌跡の途中でMoE構成が頻繁に切り替わらず、検証器が一貫した構成のもとで進んだ推論を段階的に評価できる。毎ステップ全kを再試行せず、初期探索で得た構成差を後続状態へ保存する。

各段階では検証器が全展開候補を採点しtop-Mだけを残すため、低得点軌跡に結び付いたkは自然に消え、高得点軌跡のkへ後続ロールアウトが集中する。明示的な構成別報酬モデルを学習せず、通常のプロセス報酬が構成レベルの暗黙的信用割当として働く。付録のアブレーションでは継承によりAccuracyだけでなくpass@Nも改善し、単なる多様化ではなく有望構成への計算集中が寄与する。

### 検証器誘導の段階的探索
時刻tの候補集合C_tにM個の状態があれば、各(s,k)からN/|C_t|個のアクションを同じkで生成し、合計N個の展開候補を作る。各候補はRφで採点され、上位MだけがC_{t+1}へ進む。したがって通常のBeam Searchと同様の段階的な枝刈りを使いながら、候補にkが付随することでテキスト探索と構成探索を同時に実行する。

探索は最大TステップまたはEOSまで続き、最後は最高検証器得点または多数決で答えを選ぶ。検証器としてQwen2.5-Math-PRM-7BとLlama3.1-8B-PRM-Deepseek-Dataを用い、異なる検証器でもDESの改善傾向を確認する。ただし検証器が誤った中間状態を高く評価すれば、その状態のkも誤って継承されるため、検証器品質は方式の主要依存要因である。

### 固定計算予算内での比較
DES、Best-of-N、Beam Search、DVTSには同じロールアウト予算Nを与え、AccuracyとPrecisionに加えて平均生成トークン数も報告する。同じロールアウト数でもk変更で1トークン当たりFLOPsが変わり得るため、DESの平均活性化エキスパート数も測定する。主設定では平均kが方策モデルの既定8を超えず、生成トークン数もBest-of-NやBeam Searchと概ね同程度である。

動的 MoE単独のアブレーションでは、OLMoEのMATH500でN=128時に固定kのBeam Search 27.4%から異なるk探索31.0%へ改善する。さらに構成継承を加えるとpass@NとAccuracyが改善する。これにより『追加計算量だけ』『構成多様性だけ』という説明を分離し、構造的探索と継承による集中の両方を検証している。

### 全体のデータ／制御の流れ
実装は既存MoE方策モデルのルーティング/top-k制御を推論時に変更可能にし、その上に検証器誘導探索を置く。方策モデルはvLLMで提供し、報酬モデルはTransformersで提供する。各候補状態にはテキスト履歴と活性化数を持たせ、候補の生成・採点・枝刈りの各段階で両者を一緒に伝播する。

モデル重みの追加学習や新しいエキスパートは不要で、変更の中心は推論オーケストレーションである。主設定では4枚のRTX A6000上でN=32、M=N/4、最大10ステップ、温度0.8を用い、初期構成4〜11から探索を開始する。
## 評価条件
- **ハードウェア**: 全実験はNVIDIA RTX A6000 GPU 4枚で実施。論文はGPUメモリ容量やテンソル並列の詳細をモデル別には報告していない。
- **ソフトウェア**: 方策モデルはvLLMで提供し、報酬モデルはTransformersで提供。動的 MoEとして推論時の活性化エキスパート数を制御する。コードは採択後公開予定と付録に記載され、公開リポジトリURLは本文中にない。
方策モデルはQwen3-30B-A3B、Ling-lite-1.5、OLMoE-1B-7B-Instruct、DeepSeek-V2-Lite-Chatの4種類。検証器はQwen2.5-Math-PRM-7BとLlama3.1-8B-PRM-Deepseek-Data。数学はMATH500、AIME24、AIME25を中心に、小型モデルではGSM8KとSVAMPも使用。コードはHumanEvalとLiveCodeBench v6-lite、知識推論はLiveBench reasoningを0-shotで評価する。主設定はN=32ロールアウト、M=N/4、T=10、温度0.8、初期活性化数4〜11。小型モデル追加実験はN=64。比較対象はBest-of-N、Beam Search、DVTSで、Accuracy、候補中の正答率Precision、平均生成トークン数を報告する。動的 MoE単独、構成継承、初期活性化範囲、異なる計算予算、異なる検証器をアブレーションする。
評価は推論・コード・知識ベンチマークに集中し、実サービングのスループット、レイテンシ、KVキャッシュ量、PCIe/NVLink通信量などシステム指標は直接測っていない。『追加コストなし』は主に同じロールアウト予算、同程度の生成トークン数、平均活性化数が既定値以下という観点で論じられる。学習済みMoEで活性化数を変更しても破綻しにくいことが前提であり、denseモデルには直接適用できない。
## 主要結果
DESは複数のMoE方策モデルと2種類のプロセス報酬モデルで、固定活性化数のTTSより多くの条件で高いAccuracy/Precisionを示す。Qwen3-30B-A3B-Instruct＋Qwen2.5-Math-PRM-7B、N=32ではMATH500 93.2%、AIME24 86.67%、AIME25 70.0%、HumanEval 94.51%、LiveBench reasoning 91.5%。DeepSeek-V2-Lite-Chat＋Qwen PRM、N=64ではGSM8K 82.8%、MATH500 41.8%、HumanEval 47.56%となり、Best-of-N/BeamSearch/DVTSを大きく上回る条件がある。生成トークン数はベースラインと同程度で、平均活性化エキスパート数も既定8を超えない。

- Qwen3 MATH500 Accuracy / 93.20% (比較対象: Best-of-N 92.40%、BeamSearch 93.00%、DVTS 87.40%; 条件: Qwen3-30B-A3B-Instruct、Qwen2.5-Math-PRM-7B、N=32) — 同じロールアウト予算で構造的探索軸を加えることで小幅ながら最高精度を得る。

- Qwen3 HumanEval Accuracy / 94.51% (比較対象: Best-of-N 92.07%、BeamSearch 89.02%、DVTS 93.90%; 条件: Qwen3-30B-A3B-Instruct、N=32) — 数学だけでなくコード生成でも構成探索の利得が確認される。

- DeepSeek-V2-Lite GSM8K Accuracy / 82.80% (比較対象: Best-of-N 68.80%、BeamSearch 69.39%、DVTS 72.60%; 条件: DeepSeek-V2-Lite-Chat、Qwen2.5-Math-PRM-7B、N=64) — 小型MoEでは活性化数の違いによる相補性が大きな改善へつながる条件がある。

- DeepSeek-V2-Lite MATH500 Accuracy / 41.80% (比較対象: Best-of-N 30.40%、BeamSearch 35.80%、DVTS 34.00%; 条件: DeepSeek-V2-Lite-Chat、Qwen PRM、N=64) — 難しい数学でも通常のbeam型探索より高い正答率を示す。

- 異なる検証器でのDeepSeek-V2-Lite GSM8K Accuracy / 87.60% (比較対象: Best-of-N 68.80%、BeamSearch 67.60%、DVTS 71.00%; 条件: Llama3.1-8B-PRM-Deepseek-Data、N=64) — 改善が単一のQwen PRMに限定されない。

- 動的 MoE単独アブレーション / N=128でMATH500 31.0% (比較対象: 固定活性化数BeamSearch 27.4%; 条件: OLMoE-1B-7B-Instruct、Llama3.1 PRM) — 構成継承を外して活性化数探索だけを加えても、高計算予算で+3.6ポイント改善する。

- Qwen3 MATH500生成トークン数 / 33.9k (比較対象: Best-of-N 32.9k、BeamSearch 33.9k、DVTS 22.7k; 条件: N=32) — 少なくともBest-of-N/BeamSearchと近い生成量で精度改善しており、単純な長文化だけでは説明しにくい。

### 負の結果・境界条件
- DESが全モデル・全ベンチマークで常に最高ではない。Qwen3のLiveCodeBenchではDES 33.59%に対してBeamSearch 37.40%、Ling-liteのAIME25ではDES 16.33%に対してBest-of-N/DVTS 23.33%、Ling-liteのLiveCodeBenchではDES 19.84%でBeamSearchと同値かつDVTS 20.61%を下回る。OLMoEのSVAMPではDES 83.67%に対してBeamSearch 84.67%である。また外部検証器が必須で、検証器が誤ると探索も誤った構成へ集中する。

### 結果の読み方
結果は『より多くのエキスパートを使えば良い』という説明を支持しない。初期活性化範囲をずらすと平均活性化数はその範囲の平均に追随し、主設定では既定8を超えない。動的 MoE単独でも改善し、構成継承を加えるとpass@NとAccuracyがさらに上がるため、構造的多様性の導入と有望構成への計算集中の双方が寄与していると解釈できる。
## 品質への影響
DESはモデル重みを変更せず推論時探索だけを変えるため、品質改善は個々の単一生成を恒常的に高品質化するというより、固定予算内で正解候補へ到達する確率と最終選択品質を上げる形で現れる。検証器品質への依存は残る。
## 既存研究との差
Best-of-Nや通常Beam Searchは同一モデル構成のまま出力サンプリングだけで探索多様性を作る。DVTSは探索木を複数の独立部分木へ分割して出力側の多様性を増やす。DESはこれらと異なり、MoE内部の活性化エキスパート数を探索状態へ含め、モデルの計算経路そのものを変える。既存の動的MoE研究が入力難易度などに応じて計算量やルーティングを適応させるのに対し、DESは正解集合の相補性を利用するTTS目的で複数構成を明示的に探索する。構成継承により、毎ステップ一様に全kを試す方式より有望構成へ計算を集中する点も特徴である。
## 限界
外部のプロセス報酬モデルまたは検証器が必要で、その評価誤差が探索経路と最終回答の双方へ伝播する。活性化数を学習時設定から変えても性能が急落しないMoEであることも前提で、denseモデルやtop-k変更に敏感なMoEへはそのまま適用できない。評価は4枚のRTX A6000上のベンチマーク中心で、実サービングの同時要求、メモリ圧、通信、エネルギーは測定していない。コードは論文中で採択後公開予定とされ、現時点の再現性は実装詳細記述に依存する。また一部ベンチマークではBeamSearchやDVTSを下回るため、DESが常に最適な探索戦略ではない。
## 実装状態
論文実験ではvLLM上でMoE方策モデルを提供し、推論時に活性化数kを変更して探索する。報酬モデルはTransformersで提供。N=32、M=N/4、T=10、k=4〜11、温度0.8など主要設定は付録に記載されている。一方、付録のライセンス節にはコードは採択後公開するとあり、一次資料から公開GitHubリポジトリは確認できないため、公開実装済みとは扱わない。
## 研究上の位置づけ
MoE推論研究では、従来はルーティングを計算量削減、負荷分散、専門化、エキスパート配置・オフロードの観点から扱うことが多い。DESは同じ構造自由度を『推論品質を上げる探索軸』として使う点で異なる。特にエキスパート数ごとに正解問題集合がずれるという観察は、MoEのルーティング/configurationをテスト時適応計算へ利用する系統につながる。システム研究の観点では、異なるkが計算・メモリ・通信負荷も変えるため、将来は検証器報酬だけでなくGPUメモリ圧、エキスパート キャッシュ hit率、CPU/SSDオフロード費用を状態へ含め、品質と階層メモリコストを同時最適化する拡張が考えられる。
