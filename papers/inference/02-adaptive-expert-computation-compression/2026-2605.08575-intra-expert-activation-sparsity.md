# Uncovering Intra-expert Activation Sparsity for Efficient Mixture-of-Expert Model Execution

> 既存MoEのエキスパート内活性値 sparsityをvLLMへ統合し、再学習なしでMoE 層最大2.5倍・エンドツーエンド最大1.2倍を実現する。
## 書誌情報
- **著者**: Jongseok Park, Sunga Kim, Zhenyu Gu, Ion Stoica, Alvin Cheung
- **著者・所属**: University of California, Berkeley; Advanced Micro Devices, Inc.
- **公開**: arXiv
- **種別**: プレプリント
- **対象**: MoE推論、活性値 sparsity、vLLM、Triton、GPU sparse execution
- **実装**: vLLM開発版へTriton製のcustom sparse 活性値 カーネルとfused sparse up-down projectionを組み込む。完全なカーネル sourceは論文Appendix Bに掲載。
## 概要
既存の事前学習済みMoEには、選択済みエキスパート内部にも大きな活性値 sparsityが残ることを8モデル（1B〜400B）で示し、vLLMのfused MoE経路へthreshold-based sparse executionを統合した研究。モデル再学習や活性化関数変更なしに最大約90%のエキスパート内sparsityを利用し、MoE 層で最大2.5倍、エンドツーエンドで最大1.2倍の高速化を報告する。

既存の学習済み混合エキスパートモデル八種類を再学習せず調査し、選択済みエキスパート内部で最大約九割の活性値疎性を精度を大きく落とさず利用できることを示す。さらにvLLMのルータ、振り分け、結合、エキスパート並列を維持したまま、ルーティングされたエキスパートの内部実行だけへ疎な処理経路を追加する。単なるマスクによる演算量削減ではなく、GPU上の実測高速化まで結び付ける点が特徴である。共有エキスパートのニューロンはルーティング対象より重要度が高いこと、モデル規模が大きいほど疎化耐性が増すことも分析する。

代表結果として、最大sparsity cutoffはLlama-4-Maverick、比較対象平均scoreの95%維持基準でunmodified model average ベンチマーク scoreに対して90.8%。大規模MoEほど選択エキスパート内部に大きな冗長性が残ることを示す。
## 問題設定
混合エキスパートモデルはトークンごとに一部のエキスパートだけを選ぶことで計算量を抑える。しかしエキスパート数を増やして粒度を細かくすると、特定エキスパートへの偏り、負荷不均衡、表現の均質化、エキスパート当たりの勾配更新減少など学習上の問題が強くなる。一方、選択済みエキスパートのフィードフォワード網内部にも入力ごとに寄与の小さいニューロンが多数存在する。近年のSwiGLU系モデルでこの内部疎性をどこまで利用できるか、さらに高度に最適化されたvLLMの実運用経路で実速度向上へ変換できるかが課題である。
## 新規性
既存の学習済み混合エキスパートモデル八種類を再学習せず調査し、選択済みエキスパート内部で最大約九割の活性値疎性を精度を大きく落とさず利用できることを示す。さらにvLLMのルータ、振り分け、結合、エキスパート並列を維持したまま、ルーティングされたエキスパートの内部実行だけへ疎な処理経路を追加する。単なるマスクによる演算量削減ではなく、GPU上の実測高速化まで結び付ける点が特徴である。共有エキスパートのニューロンはルーティング対象より重要度が高いこと、モデル規模が大きいほど疎化耐性が増すことも分析する。
## 手法
### 手法のあらまし
入力は既存の学習済み混合エキスパートモデル、要求された疎化率、実行時バッチサイズであり、出力は精度許容範囲内でニューロン計算を省いたエキスパート出力である。まず各エキスパートの活性化後出力を絶対値で順位付けし、寄与の小さいニューロンをゼロ化する。五つの評価課題の平均精度が元モデル平均の九五パーセントを維持できる最大疎化率をモデルごとの上限として測る。実行系では共有エキスパート、ルータ、トークン振り分け、結果結合を変更せず、ルーティング対象エキスパート内部だけを疎な経路へ差し替える。

推論時は最初のゲート射影を密なバッチ行列積で計算し、起動時に作成したモデル別参照表から目標疎化率に対応する閾値を得る。専用のTriton活性化カーネルが絶対値の小さいニューロンを一回の走査でマスクし、残ったニューロン番号を連続バッファへ集約する。その番号に対応する上向き射影と下向き射影の重みだけを読み出して共有メモリ上に詰め、上向き射影、活性値との積、下向き射影を融合した疎カーネルで処理する。グラフ捕捉との互換性を保つため番号バッファを固定長へ埋め、六四ニューロン単位で起動する。大きなバッチでは密な行列積の方が効率的になるため、起動時に転換点を測定し、各推論段階で疎経路と既存の密経路を切り替える。

### 既存モデルのエキスパート内疎性測定
八種類の混合エキスパートモデルについて、ルータが選択したエキスパートの活性化後出力を観測し、絶対値が小さいニューロンから段階的にゼロ化する。ARC-Challenge、ARC-Easy、HellaSwag、WinoGrande、TruthfulQA-mc2の五課題で平均点を測り、元モデル平均の九五パーセントを維持できる最大疎化率をモデル上限と定義する。

この測定はエキスパートそのものを削除するのではなく、選択されたエキスパート内部でその入力に寄与しにくい中間ニューロンを対象にする。共有エキスパートの有無、モデル規模、エキスパート種別ごとに結果を分け、共有エキスパートはルーティング対象より疎化に敏感であることや、大規模モデルほど内部疎性を利用しやすい傾向を確認する。これにより実行系でどこを疎化対象にすべきかを決める。

### 閾値による疎な活性化カーネル
密なゲート射影を計算した直後の活性値に、モデルと目標疎化率から決まる閾値を適用する。絶対値が閾値未満のニューロンを専用Tritonカーネル内で無効化し、残ったニューロン番号を連続した作業バッファへ書き込む。全要素を並べ替えて上位要素を選ぶ方法ではなく、一回の走査で判定するため選別自体の追加費用を抑える。

閾値は起動時に作成するモデル別参照表から取得するため、推論要求ごとに高価な順位付けを行う必要がない。ここで生成した番号列が次の疎な射影処理への入力となる。疎化率が高くても選別処理が支配的にならないよう、マスク生成と番号収集を同じ流れで行い、後段が連続した番号列を直接利用できる形へ整える。

### 融合した疎な上下射影
活性化カーネルが残したニューロン番号を使い、対応する上向き射影と下向き射影の重みベクトルだけをまとめて読み出す。読み出した重みは共有メモリ上で詰め直し、疎な不規則構造を小さな密行列として扱える形にする。これにより無効化したニューロンに対応する主要な行列積を実行せずに済む。

詰め直した重みに対する上向き射影、活性値との要素積、下向き射影を一つの連続したカーネル経路へ融合する。単にゼロを掛けるだけでは密な行列積の計算量が残るが、必要な重みだけを集めてから計算するため実演算そのものを削減できる。一方で重み収集は不規則なメモリアクセスを生むため、後述のバッチサイズ適応切替と組み合わせて損益を制御する。

### グラフ互換とバッチサイズ適応切替
CUDAまたはHIPのグラフ捕捉と互換にするため、活性ニューロン番号のバッファを最大ニューロン数まで固定長に埋め、六四ニューロン単位のタイルでカーネルを起動する。入力ごとに可変長の動的起動へすると既存vLLMの実行最適化を壊すため、外形を固定したまま内部で有効要素だけを処理する。

小から中程度のバッチでは省いたニューロン計算が重み収集の追加費用を上回るため疎経路を使う。大きなバッチでは密なバッチ行列積がGPUを効率よく使い、疎な重み収集が逆に律速になるため既存の密経路へ戻す。転換バッチサイズはエンジン起動時に測定し、各推論段階で自動選択することで、疎化が不利な領域まで強制適用しない。

### 全体のデータ／制御の流れ
既存vLLMのエキスパート一括処理の流れを維持し、ルーティング対象エキスパート内部だけを活性値に応じた疎実行へ差し替える。処理順は密なゲート射影、閾値によるマスクと番号生成、必要重みの収集、融合した疎な上下射影であり、ルータやトークン振り分け、結果結合は従来経路をそのまま利用する。

エキスパート並列、カーネル融合、CUDA/HIPグラフなど既存の最適化との互換性を残すことを設計条件とする。共有エキスパートは精度への寄与が大きく、ルーティング対象と並列に実行されるため疎化対象外とする。疎経路が有利なバッチ領域だけで利用することで、研究用の演算量削減を実運用のスループット改善へ変換する。
## 評価条件
- **ハードウェア**: MoE 層 microbenchmarkはAMD MI355X、NVIDIA H200、NVIDIA RTX4090を使用。Qwen3.5-35B-A3BとQwen3.5-122B-A10Bを評価し、エンドツーエンドはMI355XとH200上のQwen3.5-35B-A3Bを中心に測定する。
- **ソフトウェア**: vLLM development build 0.1.dev15965+g6506aec54へTriton製sparse 活性値 カーネルとfused sparse up-down projectionを統合。精度評価はlm-eval-harnessをvLLM backendで用いる。比較対象は同じvLLMのoriginal dense MoE execution。
sparsity特性はGranite-1B-A400M、OLMoE-1B-7B、DeepSeek-V2-Lite、GPT-OSS-20B、Qwen3.5-35B-A3B/122B-A10B/397B-A17B、Llama-4-Maverickの8モデルをARC-Challenge、ARC-Easy、HellaSwag、WinoGrande、TruthfulQA-mc2で評価し、比較対象平均scoreの95%を維持する最大total 活性値 sparsityをcutoffとする。性能はWikiText-2入力で最初のMoE 層を100回実行し96% confidence interval付きで測定。target sparsity 60/70/80/85/87%を比較する。エンドツーエンドではinput/output トークン数とリクエスト数を変え、startup profileでdense/sparse自動切替を有効化する。
活性値 sparsityの存在は1B〜400Bの8 MoEへ広く確認する一方、カーネル性能の詳細評価は主にQwen3.5-35B-A3B/122B-A10B、エンドツーエンドは35B-A3Bに集中する。GPU実装はgather-basedで、CPUや他accelerator、training時の効果は対象外。
## 主要結果
8モデルの調査ではモデル規模が大きいほどエキスパート内活性値 sparsityへの耐性が高く、Granite-1B-A400Mのcutoff 26.5%に対しLlama-4-Maverickは90.8%に達する。Qwen3.5-35B-A3B/122B-A10Bの実装評価では85〜87%付近でMoE 層を最大1.5〜2.5倍高速化し、Qwen3.5-35B-A3BのエンドツーエンドではH200で最大1.2倍、MI355Xで最大1.1倍を達成する。

- 最大sparsity cutoff / 90.8% (比較対象: unmodified model average ベンチマーク score; 条件: Llama-4-Maverick、比較対象平均scoreの95%維持基準) — 大規模MoEほど選択エキスパート内部に大きな冗長性が残ることを示す。

- MoE 層 高速化倍率 / 最大2.5× (比較対象: dense vLLM MoE execution; 条件: Qwen3.5-122B-A10B、RTX4090、85〜87%級sparsity、バッチ size 16〜128付近) — 資源制約が強く大規模なワークロードほどgather-based sparse executionの利得が大きい。

- Qwen3.5-35B-A3B MI355X 層 高速化倍率 / 1.55× at 85% target; 1.8× at 87% target (比較対象: dense 0.354 ms; 条件: バッチ size 128。85%時0.229 ms、87%時0.197 ms) — 95%精度維持cutoff付近でも実測高速化が得られる。

- エンドツーエンド 高速化倍率 / 最大1.20× H200、最大1.10× MI355X (比較対象: dense vLLM; 条件: Qwen3.5-35B-A3B、85% target sparsity、dense/sparse バッチ-size switching有効) — MoE 層高速化はAmdahl則で希釈されるがserving全体でも有意な改善を残す。

- near-zero 活性値比率 / 54.85% (比較対象: unmasked 活性値; 条件: Qwen3.5-35B-A3B エキスパート 0 層 0、WikiText-2 2048 samples、-0.003〜0.003 bin) — SwiGLUでも多数のneuronが実質的に寄与しない長尾分布を持つ。

### 負の結果・境界条件
- 60% target sparsityではQwen3.5-35B-A3B/MI355X/batch128で0.92×とdenseより遅く、sparsityだけでは高速化を保証しない。小バッチではカーネル launch等の固定オーバーヘッド、大バッチではdense BMMの高スループットが優位になる。dense gate projectionを必ず先に計算するためsparse化できるのは主にup/downの約2/3で、理論上の上限は約3×。shared エキスパートはneuron重要度が高く、疎化しても並列実行のため性能利得が小さい。

### 結果の読み方
本研究はMoEの粗粒度ルーティング sparsityと、選択エキスパート内部の細粒度活性値 sparsityを直交する最適化軸として組み合わせる。最大の価値はsparsity比率そのものではなく、既存vLLMのgraph/エキスパート-parallel実行と共存するカーネル経路を作り、精度・GPU効率・バッチ依存性まで含めてエンドツーエンドで成立条件を示した点にある。
## 品質への影響
Qwen3.5-35B-A3Bではdense平均accuracy 70.9%に対し85% targetで67.5%（約95.2%保持）、87% targetでは65.7%まで低下する。threshold maskingの実sparsityはtargetから±3 percentage points以内で、85% targetまでは比較対象平均scoreの95%基準を維持する。
## 既存研究との差
従来の混合エキスパート高速化は、ルータで選択するエキスパート数を減らすスキップ、エキスパート粒度の変更、エキスパート並列など、エキスパート間の疎性を主に利用する。本研究はルータが選択した後の各エキスパート内部でニューロン計算をさらに省くため、それらの方式と原理的に併用できる。

ReLU系の活性値疎性を前提とする方式と異なり、SwiGLUを含む現行の学習済みモデルを再学習せず、活性化関数も変更せずに対象とする。分析だけでマスクを適用する研究に対しては、実運用向けvLLMへ疎なGPUカーネルを統合し、既存のルータや並列化を維持したまま端から端までのサービング速度を評価する点が異なる。
## 限界
現実装はゲート射影を密に実行してからマスクを作るため、エキスパートのフィードフォワード網全体を疎化できず、理論上の高速化には上限がある。活性ニューロンごとの重み収集は不規則なメモリアクセスを伴い、大きなバッチで演算律速になる領域では密なバッチ行列積より処理量が低くなる。詳細なカーネル評価はQwen3.5系の二モデル、端から端までの評価は35B-A3B中心であり、調査した八モデルすべてに同じ実速度利得が出ることまでは示していない。

閾値はモデルごとの参照表をエンジン起動時に作る必要があり、モデルや運用条件が変わる場合には再校正費用が生じる。精度基準も五つの評価課題の平均点が元モデルの九五パーセントを維持することなので、自由生成の品質、長文脈、エージェント型処理など別種の負荷に対する影響は追加検証が必要である。
## 実装状態
論文付録にはvLLMへ挿入できる疎な混合エキスパート実行カーネルの完全なソースコードを掲載し、補足資料も提供すると記載されている。評価実装はvLLMの開発版を基盤とし、TritonとPyTorchを用いてGPU上で実装・測定されている。独立した公開GitHubリポジトリのURLは本文から確認できない。

実装上は既存のルータ、トークン振り分け、結果結合、エキスパート並列を残し、ルーティング対象エキスパート内部の活性化と上下射影だけを置き換える。そのため論文の主張は理論的な演算量削減だけでなく、既存推論基盤へ統合した際の追加費用を含む実測結果で検証されている。
## 研究上の位置づけ
混合エキスパートの圧縮・実行系統では、エキスパート削除、統合、ルーティング最適化とは異なる『エキスパート内部の活性値疎性』を実システム最適化へ引き上げた研究として位置付けられる。大規模モデルほど疎化耐性が高いという観測は、エキスパート数をさらに増やして学習を難しくする代わりに、既存エキスパート内部の不要計算を入力ごとに省く方向を示す。

GPUカーネル設計の観点では、細粒度な疎性による理論演算削減と、GPUが得意とする規則的な密タイル計算の間を、必要重みの収集と詰め直し、さらにバッチサイズに応じた疎経路・密経路の切替で折衷している。したがってモデル圧縮だけでなく、疎なモデル構造を実ハードウェア上の処理量改善へ変換する推論システム研究としても重要である。
