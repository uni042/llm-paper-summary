# Harder Tasks Need More Experts：トークンの難しさに応じて専門家数を変える動的MoE

## 概要

混合専門家モデル（Mixture of Experts、MoE）は、各トークンを複数の専門家ネットワークの一部だけへ送り、全パラメータ数を増やしながら一回の計算量を抑える。多くの方式では、ルータが計算した専門家の確率上位K個を固定的に選ぶ。例えばTop-2なら、単純な機能語でも複雑な数学推論のトークンでも常に二つの専門家を起動する。*Harder Tasks Need More Experts*は、入力によって必要な専門家数が違うことを利用し、選択確率の累積がしきい値を超えるまで専門家を追加する動的ルーティングを提案する。

学習時には、ルータ確率が一様に広がって大量の専門家を起動しないようにエントロピーを抑える損失を導入し、特定専門家への集中を防ぐ負荷均衡損失も併用する。24層・16専門家/層のLLaMA型モデルをRedPajama 100Bトークンで訓練した評価では、Top-2方式の5課題平均41.6に対し、動的方式は42.3を達成した。平均活性専門家数は2から1.76へ減少し、特に複雑な推論課題BBHでは23.3から25.6へ改善した。

重要なのは、この研究が専門家の実行回数・活性パラメータ量を削減したことと、GPU上の実測生成速度を改善したことを区別する点である。専門家数が少なくても、ルーティング、トークンの並べ替え、通信、少量の行列積の効率などが変わるため、トークン毎秒が同じ割合で改善する保証はない。原著の主要結果はモデル品質と平均活性専門家数であり、特定の推論基盤での端から端の遅延を直接測った結果ではない。

## 問題設定と従来Top-Kの制約

TransformerのMoE層は、通常の多層パーセプトロン（MLP）部分をN個の専門家e_iに置き換える。入力トークンの隠れ状態xをルータの線形層W_rへ通し、Softmax(W_r x)から専門家ごとの確率P_iを得る。Top-K方式は上位K個の専門家だけを起動し、その出力をルータの重みで加重和する。固定Kは実行計画が予測しやすく、トークンごとの専門家数を揃えられるが、各入力の難しさを考慮しない。

単純な入力で専門家一つの確率が突出しているなら、二つ目を起動する費用は無駄かもしれない。一方、複数専門家の確率が拮抗している入力は、単一専門家に確信を持てず、複数の表現を組み合わせる方が有利な可能性がある。固定Kを大きくすれば複雑な入力に対応しやすくなるが、全トークンで計算量が増える。Kを小さくすれば計算量は減るが、難しい入力の品質が落ちる。

この論文の仮説は、ルータの選択確率分布の集中度を入力ごとの必要計算量の代理として使える、というものである。ただし「ルータ確率が分散している」ことと「その入力が客観的に難しい」ことは同義ではない。後者はBBHのような難しい課題で平均活性数が増えるという実験で間接的に検証される。難易度の教師ラベルを別途与える方式ではない。

## 手法

### 1. ルータ確率の累積で専門家数を決める

入力xに対してN個の専門家確率P_iを計算し、確率の大きい順に並べる。しきい値p（0<p<1）を設定し、上位から確率を加えて、累積確率がp以上になる最小個数tを選ぶ。例えば最大確率が0.7でp=0.4なら専門家一つで十分だが、上位確率が0.25、0.20、0.15と分散しているなら二つを選ぶ。専門家数tはトークンごと、層ごとに変化する。固定Top-2とは異なり、同じ層でもあるトークンは一つ、別のトークンは二つ以上を起動できる。

選択された集合Sに対してルータ出力はΣ_{i∈S}P_i e_i(x)となり、非選択専門家の重みはゼロにする。原著の式(5)ではTop-Kのような選択集合内での再正規化を明示しておらず、選択した確率P_iをそのまま使う。従って、専門家数を変えたときの出力スケールや学習済みルータの分布も、固定Top-Kから単純に置き換えた場合とは異なる可能性がある。

しきい値pを大きくすると累積確率の目標が上がり、より多くの専門家を起動しやすくなる。pを小さくすると一つの専門家で停止しやすくなるが、品質低下の可能性がある。実験の主設定はp=0.4で、学習済みモデルを使った推論時の感度評価では0.1〜0.7を走査する。ここでのしきい値は出力トークンの採択確率ではなく、MoE内部の専門家選択確率の累積である。

### 2. エントロピー損失で専門家の無制限な起動を防ぐ

ルータ確率が一様に広がると、累積確率をpへ到達させるため多数の専門家を選ぶことになる。例えば16専門家へ均等な確率を配ると、p=0.5を超えるには多くの専門家が必要になる。学習が精度だけを最大化するなら、ルータが広く分散して専門家を大量に起動し、計算効率を損なう恐れがある。

そこで著者らはルータ確率のエントロピーH(P)=−Σ_i P_i log P_iを動的損失として加える。エントロピーを小さくする方向の学習は、必要な少数の専門家へ確率を集中させる。これにより、容易な入力では早く累積しきい値へ到達し、活性専門家数を減らせる。ただしエントロピーだけを強く抑えると全トークンが特定の専門家へ集中し、学習負荷の偏りや表現力の不足を招き得る。

### 3. 負荷均衡と次トークン損失を組み合わせる

特定専門家への偏りを防ぐため、既存MoEと同様に負荷均衡損失を使う。専門家iを選んだトークンの割合f_iと、ルータが専門家iへ割り当てた確率の平均Q_iを求め、NΣ_i f_iQ_iを負荷均衡損失とする。言語モデルの次トークン予測損失L_lmに、負荷均衡損失αL_bと動的エントロピー損失βL_dを加え、L=L_lm+αL_b+βL_dで学習する。

実験ではα=10^-2、β=10^-4である。エントロピーを抑える効果と、専門家間の利用率を均す効果は方向が異なる場合があるため、係数の調整が重要になる。論文はこの組合せで学習したモデルを評価しており、既存のTop-2学習済みモデルへ推論時にpだけ追加すれば同じ品質になると保証するものではない。専門家の選択個数が変わるため、学習時から動的ルーティングに適応させる必要がある。

### 4. 学習・推論でのデータフロー

学習時はトークンの隠れ状態をルータへ送り、専門家確率を計算し、累積しきい値で選択集合を作り、選択した専門家のFFN出力を合成する。次トークン損失、負荷均衡損失、エントロピー損失からモデルを更新する。推論時には同じルータと累積選択を使うが、損失の計算と勾配更新は不要である。トークンごとの専門家数が可変なので、推論実装は各専門家へ送るトークン数の変動を扱う必要がある。

この変動は理論的には平均活性パラメータを減らすが、専門家ごとのトークンを集約する操作、分散環境での通信、負荷偏り、GPUカーネルのバッチ効率を複雑にする。原著は平均活性専門家数を測定しているものの、GPUのメモリ帯域、実際の専門家行列積の占有率、通信量を包括的に評価したわけではない。

## 評価

### 実験条件

| 学習量 | 各モデルを100Bトークンで一から学習 |
| モデル | LLaMA型、24層、隠れ幅1024、Llama2語彙32,000 |
| MoE | 各MoE層16専門家、総パラメータ約3.5B |

| 活性パラメータ | Top1約374M、Top2約581M。動的方式は入力に依存 |
| 主設定 | p=0.4、負荷均衡係数0.01、動的損失係数0.0001 |
| 評価 | PIQA、HellaSwag、ARC-Easy、CommonsenseQA、BBH、OpenCompass |

このモデルは近年の数十B〜数百B規模の商用MoEと比べると小さい。総パラメータ3.5Bという数字は全専門家を合計した容量であり、毎トークン3.5Bすべてを実行するという意味ではない。評価の「活性パラメータ」は選択した専門家の実行量の近似であり、GPU上の実測メモリ使用量や生成速度ではない。

### 下流課題の正答率

|---|---:|---:|---:|---:|
| PIQA | 64.3 | 67.3 | 68.1 | **68.1** |
| HellaSwag | 36.1 | 42.3 | 43.9 | **44.3** |
| ARC-Easy | 37.9 | 39.5 | **40.4** | 39.9 |
| CommonsenseQA | 32.2 | 30.3 | 32.1 | **33.6** |

Top2から動的方式への平均改善は0.7ポイントであり、相対改善率0.7%と同一視しない。BBHでは2.3ポイント改善する一方、ARC-Easyでは40.4から39.9へ0.5ポイント悪化する。全課題で単調に改善するわけではない。PIQAは同点である。モデルの総パラメータと学習トークン数を揃えた比較により、単純なモデル拡大だけでなく専門家の割当て方が効いている可能性を示す。

### 活性専門家数と学習過程

| 評価データ | 平均活性専門家数/トークン |
|---|---:|
| PIQA | 1.72 |
| WinoGrande | 1.76 |
| ARC-Easy | 1.73 |
| CommonsenseQA | 1.74 |
| BBH | **1.87** |
| 平均 | **1.76** |

固定Top2は全トークンで二つを起動するため、平均1.76は約12%少ない。原著の要旨では活性パラメータがTop2の90%未満と説明する。厳密なパラメータ削減率は、共通の注意・埋め込み部分を含むか、専門家FFN部分だけを見るかで変わるため、専門家数の12%減をモデル全体のFLOPs 12%減と直結させない。

RedPajamaの学習過程では、初期には平均活性専門家数が多いが、約60Bトークンを超える頃に2未満となり、100B終了時の各データ源でも2未満になる。Common Crawl 1.82、C4 1.84、GitHub 1.88、Wikipedia 1.78、書籍1.73、arXiv 1.90、StackExchange 1.79であり、全体平均は1.82である。推論課題平均1.76と学習データ平均1.82は異なる集合の値なので混同しない。

### しきい値・トークン種類・層位置の分析

しきい値pを学習済みモデルの推論時に0.1〜0.7へ変えた実験では、p=0.1や0.2のように小さ過ぎる値では専門家を十分起動できず下流精度が低下する。一定値を超えると品質改善が飽和する。pを高くすれば無制限に品質が良くなるという結果ではない。p=0.4は、学習時に採用した性能と活性数の折衷点である。

BBHの平均活性数1.87は他の課題より多く、複雑な推論を必要とする入力で専門家を追加するという仮説に整合する。著者は語彙中の頻出トークンを対象に平均活性数を分析し、曖昧な意味を持つ断片的なトークンで専門家数が多くなる傾向を示す。一方、よくある機能語は少数専門家で処理できる傾向がある。ただしこれはルータが人間の定義する難易度を正確に測っていることの証明ではない。

層別には、Transformerの下層ほど複数専門家が必要で、上層では一つで十分な傾向を観測する。これは全層で同じKを使う固定MoEに対して、層ごとに専門家数の上限や構造を変える余地を示す。ただし、原著がそのような異種専門家構造の新しいモデルを設計して実測高速化したわけではない。

## 先行方式との差と実装上の意味

固定Top-Kは専門家数が一定であり、容量計画やトークン分配を単純化できる。Top-Pに似た累積確率の選択を専門家ルーティングへ適用する本方式は、ルータの確信度が高い入力では一つの専門家で停止し、曖昧な入力では複数を組み合わせる。加えて、エントロピー損失で過度な専門家起動を抑え、負荷均衡損失で特定専門家への集中を抑える点が特徴である。

実運用での導入には、可変個数の専門家を効率的に実行できるルータ・トークン分配器が必要になる。固定Top2向けに最適化されたカーネルや専門家並列通信では、活性数が可変になることでトークン数の偏りが増える可能性がある。推論基盤の観点では、活性専門家数の平均だけでなく、専門家ごとの最大負荷、トークンの並べ替え、All-to-All通信、キャッシュとバッチの挙動を測るべきである。論文の実験値からこれらの費用を推定することはできない。

## 限界と負の結果

第一に、主要評価モデルは総3.5Bパラメータ・16専門家/層のLLaMA型であり、より大規模なMoE、専門家を複数GPUへ分散した推論基盤、長文脈・高並列要求への一般化は直接実証されていない。大規模モデルでは専門家通信やメモリ帯域が別の律速となり得る。

第二に、平均活性専門家数が減ったことは、実機のトークン毎秒、初回トークン時間、電力、GPUメモリの削減を直接示さない。活性専門家数のばらつきは、GPUバッチ化や専門家間負荷均衡に影響する。固定Kの実行器へそのまま移植した場合、理論的な演算量削減が実速度へ反映されない可能性がある。

第三に、下流精度の改善は平均0.7ポイントであり、ARC-Easyでは悪化、PIQAでは同点である。BBHの改善が大きいことを、全タスクで2ポイント以上の改善があるように一般化してはいけない。学習量、しきい値、エントロピー係数を変えた場合に同じ結果になる保証もない。

第四に、専門家確率の分散は入力難易度の代理であり、明示的な難易度ラベルを使った教師あり予測ではない。ルータの校正が不十分な場合、確信度が高くても誤った専門家を選ぶことがあり得る。pを小さくし過ぎたときの性能低下は、必要な専門家を削り過ぎるリスクを示す。

第五に、学習にはRedPajama 100Bトークンを使用しており、学習費用自体は小さくない。エントロピーと負荷均衡の二つの補助損失は、追加のハイパーパラメータを必要とする。既存のTop2学習済みモデルに後からルーティング規則だけを置き換えても、同じ性能・活性数を得られるとは限らない。

第六に、層別専門家数の観測は新しい設計の示唆だが、層ごとに専門家数を変えた専用モデルを構築し、実測性能を示した結果ではない。ローカルGPUへ収まるかは総重み容量、量子化、専門家オフロード、KVキャッシュなどの条件で決まり、活性専門家数の減少だけでは容量問題を解決できない。
