# Training-Free Halving of Activated Experts in Fine-Grained Mixture-of-Experts Models

> 実行expert数k1とrouter正規化分母のreference set k2を分離し、fine-grained MoEでexpert computeを減らしつつ訓練時のexpert-branch gainを保つ。Qwen3.6-35B-A3Bの8→4 expertでMMLU低下を4.65ptから0.35ptへ縮小する。
## 書誌情報
- **著者**: Xing Chen, Hengshuai Yao
- **公開**: arXiv:2609.04575v1, 2026-09-04
- **種別**: arXiv preprint
- **対象**: Mixture-of-Experts、router renormalization、expert activation reduction、training-free inference
- **実装**: PyTorch/Hugging Face Transformersのrouter forward差し替え。weights変更なし。Transformers 5.3–5.14でrouter computation一致を確認。公式code linkはarXiv v1本文で未確認。
## 問題設定
細粒度Mixture-of-Experts（MoE）では、routerが多数のexpertへ確率を割り当てた後、上位k個だけを実行し、その選択expertの重みを合計1へ再正規化する実装が一般的である。細粒度MoEではtop-kが受け持つ確率質量がもともと小さいため、この再正規化はexpert branch全体へ大きなgainを掛ける役割も持つ。訓練後に実行expert数だけをkからk1へ減らして同じ再正規化を行うと、少数expertへさらに大きなgainが掛かり、純粋なexpert削減によるcapacity lossと、訓練時と異なるbranch amplitudeによるgain miscalibrationが混ざる。したがって単純なtop-k削減で見える品質低下の一部は、expertを半分にしたこと自体ではなく、survivorへ過大な重みを掛けた副作用である可能性がある。
## 新規性
本手法は、実際にFFN計算を行うexpert集合の大きさk1と、router確率の正規化分母を作るreference集合の大きさk2を分離する。expert identityやrouter rankingは変更せず、k1が計算量を、k2がexpert branchのgainを独立に制御する。k2を訓練時top-kやその近傍へ置けば、k1を減らしても訓練時に近いbranch amplitudeを保てる。追加学習、追加parameter、補助routerを必要とせず、既に計算済みのrouter logitsからより広いtop-k2の確率質量を求めるだけなので、追加costはexpert FFN削減量に比べ小さい。
## 手法
### 手法のあらまし
各tokenのhidden stateは、まず元モデルと同じrouterへ入り、全E expertに対するsoftmax probabilityを得る。次に、その確率順位の上位k1個をactivation setとして選び、実際にFFNを実行するexpertはこのk1個だけに限定する。同時に、同じrouter probabilityからより広い上位k2個をreference setとして取り、その確率質量の合計を正規化分母に使う。activation set内の各expert weightは、従来のようにtop-k1 massで割るのではなくtop-k2 massで割るため、k2>k1ではsurvivor weightの合計は1未満となり、expert branch全体がtokenごとにdown-scaleされる。k2=k1なら標準的なreduced-k再正規化へ戻り、k2を訓練時kへ置けば訓練時に近いgainへanchorでき、k2=Eならほぼ再正規化なしの端点になる。重要なのは、k2に含めた追加expertは分母計算に使うだけでFFNを実行しないため、実際のexpert computeはk1個のままである。残ったk1 expertの出力は調整済みrouter weightで加重和され、shared expertを持つモデルではその出力と通常どおり合成される。論文はk1を固定したままk2を掃引することで、expert capacity不足とgain miscalibrationを分離して評価する。結果として、半数のexpertしか実行しなくても、適切なk2なら標準reduced-kより大幅に品質を回復できる一方、k2を大きくしすぎて再正規化を実質的に外すと品質が壊れるため、gainそのものは不可欠である。

### Activation set k1 — 実際に計算するexpert数
router rankingの上位k1個だけをFFNへ送る集合で、token当たりのrouted-expert computeと関連するweight trafficを直接決める。k1を8から4、10から5のように減らせば実行expert計算はほぼ比例して減るが、expert parameter自体は削除しないのでresident VRAM/RAM容量は減らない。expert identityは元routerのtop-k順位をそのまま使うため、別の選択器を学習する方式ではない。

### Reference set k2 — 正規化gainだけを決めるexpert集合
上位k2個のrouter probability massを分母として使い、activation set内のweight振幅を決める。k2はFFN実行集合ではないため、k2>k1でも追加expertのFFN計算は発生しない。k2=k1は標準再正規化、k2を訓練時kへ戻す設定は訓練時gainへのanchor、k2=Eは再正規化をほぼ外す端点として解釈できる。

### Gain anchoring — expert削減と振幅ずれを分離
k1を減らしただけでtop-k1 massへ再正規化すると、survivorへ訓練時より大きいgainが掛かる。本手法は分母だけ広いk2へ戻すことで、その過剰gainを抑えながらexpert数削減のcompute savingを維持する。Qwen系ではこれにより半数expert時のMMLU低下が標準reduced-kより大幅に縮小したが、k2=Eのようにgainを落としすぎると逆に大幅劣化する。

### Paired downstream selection — k2を品質指標で検証
最適なk2はperplexityとdownstream accuracyで一致しない場合があり、35Bモデルではperplexityがk2=8を好む一方、MMLUはk2=16を好む。したがってk2は単一のunlabeled perplexityだけで決め切るのではなく、k1、訓練時k、2kなど少数候補をdownstream taskでpairedに比較することが推奨される。これは追加学習ではないが、deployment時の設定選択という実務上の境界条件になる。

### 全体のデータ／制御の流れ
1 tokenの流れは、hidden state→元routerの全E expert softmax→同じ順位からactivation set top-k1とreference set top-k2を取得→top-k2 probability massでtop-k1 weightを割る→k1個のexpert FFNだけを実行→調整済みweightで加重和→shared expert等の既存branchと合成、となる。制御信号はrouter probabilityだけで、新しいpredictorや履歴stateは持たないためdrop-in変更として実装できる。k1を小さくするほどcompute削減は大きいがcapacity lossは増え、k2を小さくしすぎるとsurvivor gainが過大、大きくしすぎるとbranch gain不足になる。したがって本手法が効くのは、元routerのexpert ranking自体は十分良い一方、post-trainingのk変更で主にnormalization gainがずれる細粒度MoEであり、coarse routerや異なるarchitectureへ同じk2規則がそのまま一般化する保証はない。
## 評価条件
- **Hardware**: Qwen3.6-35B-A3B: single 98GB accelerator (~72GB resident)、Qwen3.5-397B-A17B: sharded across machine (~752GB bf16)
- **Software**: PyTorch、Hugging Face Transformers 5.3–5.14、bf16
- **Model**: Qwen3.6-35B-A3B、Qwen3.5-397B-A17B、Gemma-4-26B-A4B preliminary appendix
- **Dataset / Trace**: WikiText-103、CodeParrot Python subset、MMLU、C-Eval、GSM8K
- **Baseline**: native trained-k、standard reduced-k renormalization k2=k1、no renormalization k2=E、uniform expert weights、router-probability sampling、random expert selection
- **Correctness**: Lossy compute reduction; statistically non-significant downstream difference is not proof of exact equivalence.
- **MMLU**: 2000 fixed-seed questions across 57 subjects, 5-shot, A–D single-token logits, paired McNemar test.
- **GSM8K**: 500 questions, 0-shot, greedy up to 512 tokens, reasoning disabled, exact final-number match.
- **perplexity**: 100K-token WikiText-103 and CodeParrot samples, context 2048, byte-identical chunks; held-out WikiText checks k2 selection.
- **routing analysis**: 500K tokens/domain with forward hooks over all gates.
Scan k2 while holding k1 fixed to separate expert capacity loss from gain miscalibration; paired tests are used because effects are sub-percent to few-percent.
Main matched k1/k2 evidence is two Qwen fine-grained MoEs from same series; third-architecture Gemma uses earlier scalar-gain formulation and is directional only.
## 主要結果
Standard reduced-k renormalization exaggerates the cost of using fewer experts. An interior reference set restores most downstream quality, whereas both k2=k1 and k2=E can be harmful. Perplexity and MMLU prefer different k2 on the 35B model.

- Qwen3.6 MMLU, 8→4 experts / 81.30%, -0.35pt (比較対象: native 81.65%; standard k2=4 77.00% (-4.65pt); 条件: k1=4,k2=16,n=2000) — halves routed-expert compute with no statistically detectable loss (p=0.66).

- Qwen3.5-397B MMLU,10→5 / 88.90%, -0.55pt (比較対象: native 89.45%; standard k2=5 87.35% (-2.10pt); 条件: k1=5,k2=10,n=2000) — same mechanism at 11× model scale; p=0.24.

- No-renormalization failure / 35B MMLU -27.45pt; WikiText PPL +356% (比較対象: native; 条件: k1=6,k2=E=256) — gain is essential; simply disabling normalization is catastrophic.

- 35B PPL optimum / k1=6,k2=8: -1.61% WikiText PPL vs native (比較対象: native top-8; 条件: 25% fewer routed experts) — trained-k reference mass preserves PPL.

- GSM8K 35B half experts / 94.40%, -0.60pt (比較対象: native 95.00%; standard k2=4 88.40% (-6.60pt); 条件: k1=4,k2=16,n=500) — effect survives autoregressive generation.

- Compute accounting / routed expert params/token 1.006B→0.503B; total expert term 1.132B→0.629B (比較対象: k1=8; 条件: 35B k1=4) — 50% routed-expert compute reduction, 44% expert-term reduction, estimated 17% end-to-end active-parameter reduction.

### 負の結果・境界条件
- **Perplexity mis-ranks k2**: 35B PPL prefers k2=8 while MMLU prefers k2=16; k2=8 is significantly -1.10 MMLU points (p=0.021).
- **No memory saving**: all E experts remain resident; method only reduces executed expert compute and related weight traffic.
- **Same-series evidence**: two main models are Qwen family; cross-architecture generalization remains hypothesis.
- **Coarse router boundary**: mechanism predicts smaller benefit when top-k mass is less flat; Gemma top-8 mass 0.302 shows weaker normalization sensitivity.

### 結果の読み方
Gain calibration is a hidden confounder in post-training k reduction. Expert identity matters substantially more than precise weighting, enabling a cheap amplitude correction while preserving exact router ranking.
## 品質への影響
Selected k2 recovers most downstream quality, but exact equivalence is not shown and k2 should be validated on downstream tasks.
## 既存研究との差
- LExI等のactive-expert削減はsurviving probabilitiesを通常再正規化するため、本論文のparameterizationではk2=k1となる。本手法は実行数とgainを分離する。
- self-distillation等のelastic-k/post-trained MoEは訓練でk変化へ適応させるのに対し、本手法はrouter forwardの小変更だけでweightsを更新しない。
- expert pruning/mergingはresident memoryを減らすがk不変ならcomputeを減らさない。本手法は逆にmemoryを変えずexecuted expert computeだけを減らし、quantization/pruningと直交する。
- router approximationやstochastic selectionではなくtop-k argmax expert identityを保ち、weight amplitudeだけ補正する。
## 限界
- main evidenceは同じQwen seriesの2 models。
- English/Python corpora中心でlong-contextとlong-form generation未評価。
- k2はgeometric grid scanでper-layer/per-domain最適化は未検討。
- perplexityとdownstream accuracyでbest k2が異なりunlabeled tuningだけでは安全でない。
- all experts remain resident so VRAM/RAM capacity is unchanged。
- Gemma appendixはscalar gainでprotocolも異なりmatched k1/k2 replicationではない。
## 実装状態
PyTorch/Hugging Face Transformersでrouter forwardをdrop-in置換しweights不変。Transformers 5.3–5.14でrouter計算一致を検証。arXiv v1本文に専用code repository linkは確認できない。
## 研究上の位置づけ
Adaptive Expert Computation / Compression系。fine-grained MoEのactivated expert削減を、routing identityではなくrenormalization gain calibrationの問題として再定式化するcompute-side lever。
