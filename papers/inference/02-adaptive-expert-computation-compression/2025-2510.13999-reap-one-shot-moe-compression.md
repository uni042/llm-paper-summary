# REAP the Experts: Why Pruning Prevails for One-Shot MoE compression

> ルーターゲート値と活性ノルムを組み合わせ、生成性能への寄与が小さい専門家をone-shotで削除し、最大1T級MoEでも50%圧縮を高品質に実現する。
## 書誌情報
- **著者**: Mike Lasby, Ivan Lazarevich, Nish Sinnadurai, Sean Lie, Yani Ioannou, Vithursan Thangarasa
- **公開**: arXiv preprint
- **種別**: preprint
- **対象**: MoE、エキスパート 枝刈り、model compression、generative evaluation
- **実装**: 公式PyTorch実装と一部圧縮済みチェックポイントをCerebrasResearch/reapおよびHugging Faceで公開。
## 概要
MoEの専門家統合は多肢選択では有効でも生成ではルーターの入力依存な独立制御を失い、機能部分空間を崩壊させると理論・実験で示す。REAPは専門家が実際に活性化したトークンだけについてルーティング gate×エキスパート output normを平均し、出力寄与の小さい専門家を枝刈りする。頻度とは分離されたsaliencyで専門家を選び、圧縮後も残存専門家への独立ルーティングを維持する。21B〜1T、7種のSMoEをone-shot・再学習なしで25/50%圧縮し、コード、数学、創作、tool-useなど生成課題で統合手法と他の枝刈りを上回る。Qwen3-Coder-480BとKimi-K2では50%枝刈り後も非agentic code平均低下を約1.2%に抑える。

REAPは枝刈りの置換誤差上界g_j(||f_j||+||f_i||)から、既知で制御可能なg_j||f_j||を直接小さくする基準を導く。専門家jが活性化されたトークン集合X_jだけでgate値g_jとエキスパート出力L2 normの積を平均するため、全トークン平均と違って使用頻度から機能的重要度を分離する。これを最小順に削るだけで、探索・勾配・fine-tuningを使わず大規模MoEへ適用できる。

代表結果として、Qwen3-30B 50% compression Code Avgはdomain-specific coding calibration, one-shot, no fine-tuningでuncompressed 0.558; EAN 0.530; M-SMoE 0.397; HC-SMoE 0.364に対して0.541。半数エキスパート削除でも比較対象差0.017に抑え、mergingより生成品質を大幅に維持する。
## 問題設定
疎なMoEは1トークン当たりの計算量を抑えながら総パラメータを増やせる一方、全専門家重みを保存・ロードするためメモリ容量が大きい。one-shot圧縮では専門家を削除する枝刈りと複数専門家を1つへ統合するmergingが主要選択肢で、従来研究はperplexityや多肢選択課題を根拠にmerging優位を報告していた。しかし生成課題では各時点の小さな誤差が後続生成へ累積し、ルーティングが入力ごとに専門家出力を独立に重み付けする自由度が重要になる。二専門家を統合してgateをg_i+g_jへ束ねると、本来の入力依存混合比r(x)f_i+(1-r(x))f_jを固定係数alphaの一つの専門家で近似することになり、ルーティング policyの分散と専門家間機能差が非ゼロなら消せない再構成誤差が残る。高granularity MoEほど多くの小専門家を可変比率で組み合わせるためこの損失が大きく、後段では機能manifoldが中心へ収縮する。対して枝刈りは一つの関数を除くが残存gateの独立制御を保持するため、適切な専門家を選べば生成に有利である。課題は、単なる利用頻度では稀だが重要なspecialistを誤って消すため、ルーティングとエキスパートの実際の出力寄与を同時に反映したone-shot saliencyが必要な点にある。
## 新規性
REAPは枝刈りの置換誤差上界g_j(||f_j||+||f_i||)から、既知で制御可能なg_j||f_j||を直接小さくする基準を導く。専門家jが活性化されたトークン集合X_jだけでgate値g_jとエキスパート出力L2 normの積を平均するため、全トークン平均と違って使用頻度から機能的重要度を分離する。これを最小順に削るだけで、探索・勾配・fine-tuningを使わず大規模MoEへ適用できる。
## 手法
### 手法のあらまし
まず少量の校正データを元SMoEへ通し、各MoE層で通常Top-k ルーティングが専門家jを選択したトークン集合X_jを記録する。同じトークンについて正規化後のルーティング gate g_j(x)と専門家FFN出力f_j(x)のL2 normを取得し、S_j=(1/|X_j|)Σ_{x∈X_j} g_j(x)||f_j(x)||_2を計算する。条件付き平均なので、頻繁に呼ばれるだけの弱い専門家が過大評価されず、稀でも選ばれた際の出力が大きいspecialistは高いscoreを得て保護される。各層で指定圧縮率25%または50%に達するまでS_jの小さい専門家を削除し、ルーティングから対応出力次元を除く。推論では元のTop-k数を維持し、削除された専門家が選ばれる代わりに次順位の残存専門家が昇格し、残存gateを再正規化する。専門家を平均して新しい関数を作らないため、残存専門家へのルーティングの入力依存な独立変調はそのまま残る。圧縮後の追加fine-tuningは一切行わず、校正から枝刈りまで一回で完了する。大規模モデルでは全専門家全トークンの活性を必要とするmergingより収集量が小さく、量子化済み重みでも再量子化せず専門家単位で削除できる。

### 条件付きルーティング-weighted エキスパート 活性値 saliency
入力は校正トークンに対する通常ルーティングのTop-k選択、正規化gate値g_j(x)、選択されたエキスパートの出力活性f_j(x)である。専門家jが実際に選ばれた集合X_jだけを分母にしてg_j(x)||f_j(x)||_2を平均しS_jを作る。全データ上でゼロを含めて平均すると利用頻度がscoreへ混入し、稀にしか呼ばれないが呼ばれた時に大きな寄与を持つspecialistを誤って低重要度と判定する。条件付き平均はこの頻度要因を切り離し、ルーティングが当該エキスパートへ割り当てた重みとエキスパート自身の出力強度だけを測る。理論上の枝刈り substitution error上界には削除エキスパートのg_j||f_j||が直接現れるため、S_jが小さい順に削ることは既知部分の再構成誤差を抑え、未知の昇格エキスパート normへ掛かるg_jも同時に小さくする。

### 層別one-shot エキスパート 枝刈り
各MoE層でREAP scoreを昇順に並べ、目標圧縮率まで低score エキスパートを専門家単位で削除する。25%と50%圧縮では各層の専門家数をそれぞれ4分の3、半分へ減らし、元のTop-k ルーティングは残存集合上で継続する。削除エキスパートが元なら選ばれた入力では次順位の残存エキスパートが昇格し、gateを再正規化して層出力を構成する。mergingのように複数専門家の重みを平均した新関数を挿入せず、残った各エキスパートと個別gateの対応を維持するため、ルーティングの入力依存な制御自由度を失わない。圧縮後fine-tuningを行わないone-shot条件なので、score自体の良否を直接評価できる。大規模Qwen3-CoderやKimi-K2でも同じ手順で適用でき、量子化済みエキスパートを再量子化する追加工程も不要である。

### 生成課題を中心とした校正・評価設計
小〜中規模モデルでは校正用に1,024 samplesを2,048 トークンへpackし、110B以上では12,228 samples、最大16,384 トークンをtruncation/packingなしで用いる。一般C4だけでなくcodeにはevol-codealpaca、tool callingにはxlam-function-calling、agentic codingにはSWE-smith trajectories、creative writingにはWritingPrompts、mathにはTulu系math SFTを使い、domain-specific calibrationの重要性を検証する。実験ではC4校正だと生成精度が崩壊する場合があるため、圧縮対象の実利用分布に近い校正データが必要である。REAPはcombined calibrationでも他手法より品質を保つが、domain-specificの方が高精度であり、one-shotでも校正分布選択が主要な失敗条件となる。

### 全体のデータ／制御の流れ
保存時は削除エキスパート重みを物理的に除けるため総モデルメモリを圧縮率に応じて削減し、推論時のactive エキスパート数はTop-kのまま維持する。特に小バッチ・ローカル配備で全エキスパートを常駐させるメモリ負担を下げる。
## 評価条件
- **ハードウェア**: 評価対象は21.9B ERNIE-4.5-21B-A3B-PT、30.5B Qwen3-30B-A3B、46.7B Mixtral-8x7B、106.9B GLM-4.5-Air、107.8B Llama-4-Scout、480.2B Qwen3-Coder-480B-A35B-FP8、1.026T Kimi-K2-Instruct-W4A16。論文は品質圧縮を主眼とし、特定GPU上の速度測定は主要評価ではない。
- **ソフトウェア**: REAPと比較対象 compressionはPyTorch実装。公式コードはCerebrasResearch/reap。
各層のエキスパートを25%または50%削除/統合し、圧縮後fine-tuningなしのone-shot条件で比較する。比較対象はfrequency 枝刈り、エキスパート 活性値 Norm、M-SMoE、HC-SMoE。<=110Bは校正1,024 samplesを2,048 トークンへpackし、>=110Bは12,228 samples、最大16,384 トークンを使用。C4、evol-codealpaca、xlam-function-calling、SWE-smith-trajectories、WritingPrompts、math SFTなど一般・domain-specific校正を使う。評価はMC、EvalPlus/LiveCode等code generation、SWE-Bench Verified、BFCLv3 tool-use、GSM8K/MATH-500、WildBench creative writing。<=50Bのcoding/MCは3 seed平均、より大規模モデル等は原則1 seed。
20B級から1T級まで高・低granularity、shared エキスパート有無、量子化済み大規模モデルを含む広いarchitectureで評価する。一方、圧縮後の実測GPUメモリ節約量、トークン/s、ロード時間は主要表に含まれず、品質中心。domain-specific calibrationへの依存が強く、分布外利用時のone-shot頑健性には注意が必要。
## 主要結果
生成課題では枝刈りがmergingを明確に上回り、REAPが特に50%圧縮で安定する。中小モデル群のcoding平均低下は25%圧縮で1.9%、50%で6.9%に対し、HC-SMoE/M-SMoEは25%で5%超、50%で20%超低下。Qwen3-30Bのcode平均は比較対象 0.558、50% REAP 0.541で、EAN 0.530、frequency 0.452、HC-SMoE 0.364、M-SMoE 0.397を上回る。大規模Qwen3-Coder/Kimi-K2では25/50%で非agentic coding平均低下がそれぞれ0.16%/1.2%とnear-無損失である。

- Qwen3-30B 50% compression Code Avg / 0.541 (比較対象: uncompressed 0.558; EAN 0.530; M-SMoE 0.397; HC-SMoE 0.364; 条件: domain-specific coding calibration, one-shot, no fine-tuning) — 半数エキスパート削除でも比較対象差0.017に抑え、mergingより生成品質を大幅に維持する。

- 大規模Qwen3-Coder/Kimi-K2 non-agentic coding平均低下 / 1.2% (比較対象: uncompressed models; 条件: 50% エキスパート 枝刈り with REAP) — 480B〜1T級かつ量子化済みモデルでも半数エキスパート削除がnear-無損失。

- 中小モデル generative coding平均低下 / 6.9% (比較対象: HC-SMoE/M-SMoE >20%; 条件: 50% compression, excluding large-scale SMoEs) — MCでは差が小さいが自己回帰生成ではルーティング独立制御を残す枝刈りの優位が拡大する。

- GLM-4.5-Air 50% Math Avg / 0.857 (比較対象: uncompressed 0.882; EAN 0.809; M-SMoE 0.465; 条件: domain-specific math calibration) — 高圧縮でも数学推論品質を比較的維持する。

### 負の結果・境界条件
- MCではmergingも競争力があり、REAPが常に全指標で最良ではない。Qwen3-30B 50% creative writingではM-SMoE 0.725がREAP 0.718をわずかに上回る。domain-specific calibrationが重要で、codeモデルをC4で校正すると複数圧縮モデルがcoherent outputを失い0% accuracyへ崩壊する例がある。Kimi-K2 50%ではtool-use Overallが比較対象 0.666からREAP 0.564へ下がり、全生成用途が完全無損失ではない。

### 結果の読み方
エキスパート mergingは個々の関数を残す代わりにgate自由度を束ねるため、長い自己回帰生成ほどlogitずれが累積する。REAPは関数数を減らすが残存関数のルーティング制御を保ち、低寄与エキスパートだけを選ぶため、生成trajectoryを比較対象へ近く保てる。
## 品質への影響
50%の大幅圧縮でもcode/math/creative generationを実用水準に維持するが、校正分布とtask依存性があり、用途別校正が推奨される。
## 既存研究との差
frequency 枝刈りは呼出回数だけ、EANはエキスパート output norm中心だが、REAPはルーティング gateと活性値 normの積をエキスパートが活性化した条件付き集合で平均し、頻度から独立した実出力寄与を測る。EASY-EPのgate-weighted norm集計と近いが、REAPは条件付き平均でfrequency biasを除き、枝刈り error上界から基準を導出する。M-SMoE/HC-SMoEはエキスパートを統合して情報を残す代わりにルーティング gateを束ねるが、REAPは情報を削る代わりに残存エキスパートへの独立制御を保持する。
## 限界
one-shot品質は校正分布へ強く依存し、C4でcode向け圧縮を校正すると生成崩壊する例がある。エキスパートを物理削除するため、後で別domainが必要とするspecialistを復元できず、動的キャッシュ/オフロードのように容量を保持する方式とは異なる。MCではmergingとの差が小さく一部条件でmergingが勝つため、枝刈り優位は特に生成・高granularityで強いという条件付き結論である。圧縮後の実測遅延/メモリ 帯域評価は主要焦点ではなく、品質改善がハードウェア速度へどの程度直結するかは別評価が必要。
## 実装状態
公式PyTorchコードがCerebrasResearch/reapで公開され、Hugging Faceに選択圧縮チェックポイントも公開。FP8 Qwen3-Coder-480BやW4A16 Kimi-K2まで実際に圧縮しており、大規模・量子化済みMoEへの適用を実証している。
## 研究上の位置づけ
MoEメモリ削減の『mergingなら削除より情報を残せるので有利』という直感を、生成時のルーティング制御自由度という観点から反転させた研究。CPU/SSD エキスパート オフロードやエキスパート キャッシュとは直交し、モデル自体の総エキスパート数を事前に半減して常駐・転送対象集合を縮める前処理として組み合わせられる。特にローカル推論や小バッチで全重み容量が支配的な環境に適する。
