# Mem0: Building Production-Ready AI Agents with Scalable Long-Term Memory

> 会話から重要事実だけを抽出・統合し、意味検索と矛盾更新で永続記憶を保つことで、全文履歴を毎回読むエージェント推論のトークン量と遅延を削る。

## 概要

長期間動くLLMエージェントは、過去の会話をモデル重みに保持できない。単純に全履歴を毎回コンテキストへ戻すと、会話が長くなるほど入力トークン数、プリフィル時間、利用料金が増え、重要事実が大量の無関係履歴へ埋もれる。Mem0はこの問題を「文脈窓を伸ばす」のではなく、会話から持続価値のある事実だけを永続メモリへ圧縮することで扱う。

基本版Mem0は新しいユーザー・アシスタント対話から候補記憶を抽出し、意味的に近い既存記憶と照合して追加・更新・削除・無変更をLLMに選ばせる。拡張版Mem0gはエンティティと関係を有向グラフへ保存し、関係探索と意味検索を併用する。LOCOMOでは全文約26Kトークンを毎回投入する比較方式が総合LLM-as-a-Judge 72.90で最高だが、p95総応答遅延は17.117秒だった。Mem0は66.88を保ちながら1.440秒、Mem0gは68.44で2.590秒までp95を下げ、品質と推論費の交換条件を明示している。

## 問題設定

長文脈モデルでも、数週間・数か月の履歴は最終的に窓を超える。また窓内に収まっても、質問と無関係な過去会話まで毎回プリフィルすると計算量が増える。さらに「ユーザーは乳製品を避ける」のような長期制約が大量の別話題に埋もれると、単純な長文脈だけでは検索品質も保証されない。

固定長チャンクをベクトル検索する検索拡張生成（Retrieval-Augmented Generation; RAG）は全文投入を避けられるが、チャンク境界と粒度に依存し、重要事実以外の周辺テキストも一緒に戻す。Mem0は会話をそのまま保存せず、抽出時点で「記憶として残す事実」へ変換し、その後の検索対象自体を小さくする。

## 手法のあらまし

新しいメッセージ対 `(m_t-1, m_t)` が到着すると、Mem0は最近m件のメッセージと非同期更新された会話要約を合わせて抽出プロンプトを作る。LLM抽出器 `φ` が新しい対話から候補事実集合 `Ω` を生成する。各候補についてベクトルDBから意味的に近い既存記憶を上位s件取得し、LLMの関数呼出しでADD、UPDATE、DELETE、NOOPのどれを行うか決める。

### 抽出と非同期会話要約

実験設定では最近10メッセージと会話全体の要約を併用する。最近の発話だけでは古い前提を見落とし、全履歴を毎回入れるとMem0自身が長文脈問題を再導入するため、要約を大域文脈、最近の発話を局所文脈として分担させる。会話要約は主処理と独立して非同期更新され、抽出経路の待ち時間へ直接載せない。

抽出器はこの文脈を見ながら「今回の新しい交換から将来必要になりそうな事実」を自然言語記憶へ変換する。ここで情報量を減らすことが、後段の検索トークン量とLLM入力長の削減につながる。

### 類似検索と4種の更新操作

候補事実ごとに上位10件の類似記憶を検索し、候補と既存記憶をGPT-4o-miniへ渡す。別分類器を置かず、関数呼出しでADD（新規）、UPDATE（既存へ統合）、DELETE（新情報と矛盾する古い記憶の除去）、NOOP（変更不要）を選ぶ。単純追記型と違い、ユーザーの好みが変わった場合に古い事実を残し続けることを避ける。

この更新はLLM推論を追加で使うため無料ではない。論文の主評価は質問応答時の検索・応答遅延とトークン費を中心にしており、記憶構築費と問い合わせ費を分けて読む必要がある。

### Mem0gの関係グラフ

Mem0gは記憶を有向ラベル付きグラフ `G=(V,E,L)` として持つ。ノードは人物・場所・イベント等のエンティティ、辺は `lives_in` や `prefers` のような関係である。LLMがエンティティと関係三つ組を抽出し、新規ノードを意味類似度で既存ノードへ統合する。矛盾する関係は物理削除せず無効化して時系列推論へ残す。

検索時は、質問中のエンティティから近いノードを探して入出力辺を辿る経路と、質問全体の埋め込みを関係三つ組のテキスト表現と照合する経路を併用する。関係情報は時間推論に効く一方、グラフ探索とより大きな記憶表現により基本版より遅い。

## 評価

| 項目 | 代表設定 |
|---|---|
| データ | LOCOMO、10長期会話、各約600対話・平均26Kトークン、各約200質問 |
| 質問 | single-hop、multi-hop、temporal、open-domain |
| LLM | 主にGPT-4o-mini |
| 埋め込み | text-embedding-small-3 |
| Mem0設定 | 最近10メッセージ、類似記憶上位10件 |
| 比較 | LoCoMo、ReadAgent、MemoryBank、MemGPT、A-Mem、LangMem、RAG、全文、OpenAI memory、Zep |
| 指標 | F1、BLEU-1、LLM-as-a-Judge、検索p50/p95、総応答p50/p95、トークン量 |

| 条件 | 品質 / 遅延 | 読み取れること |
|---|---|---|
| 全文26,031 tokens | J=72.90、p95=17.117秒 | 品質は高いが毎回の長文プリフィルが重い |
| Mem0、1,764 memory tokens | J=66.88、p95=1.440秒 | 約8%絶対のJ低下と引換えに尾部遅延を大幅削減 |
| Mem0g、3,616 tokens | J=68.44、p95=2.590秒 | 関係表現で品質を上げるが基本版より検索費増 |
| Mem0検索 | p50 0.148秒、p95 0.200秒 | 選択的な小さな記憶集合の検索が軽い |
| temporal | Mem0g J=58.13、Mem0 J=55.51 | 関係・時系列構造が時間質問に有効 |
| open-domain | Zep J=76.60、Mem0g 75.71 | 全カテゴリで常に最良ではない |
| multi-hop | Mem0 J=51.15、Mem0g 47.19 | グラフ化が複数段推論を必ず改善するわけではない |

RAGではチャンク128〜8192、k=1/2を振っており、最良総合Jは約60.97でMem0系を下回る。全文方式は品質ではMem0系を上回るため、Mem0は「品質無損失の高速化」ではない。長期エージェントで許容できる品質差と応答費の交換条件を選ぶシステムである。

## 既存研究との差

MemGPTのような階層メモリや通常RAGは、履歴の一部を検索して再投入する発想が中心である。Mem0は保存時点で会話を事実単位へ圧縮し、矛盾を含む更新操作までメモリ管理へ入れる。Mem0gはさらに自然言語事実と関係グラフを組み合わせ、時間関係を明示的に保持する。

Zepもグラフ型メモリを使うが、論文評価では平均会話あたり60万トークン超の表現になり、Mem0gの約14K、Mem0の約7Kより大きい。また著者らはZepで記憶投入直後の検索品質が安定せず数時間後に改善する挙動を観測し、Mem0gのグラフ構築は最悪でも1分未満と報告する。

## 限界・実装状況

記憶抽出・更新そのものがLLM呼出しに依存するため、誤抽出や誤ったDELETE/UPDATEは後続質問へ持続的に影響する。LOCOMOは10会話の長期会話ベンチマークであり、実運用の多様なエージェント作業へ同じ品質差を一般化できない。Mem0gは時間質問に強い一方、multi-hopでは基本版より低く、グラフ化の追加費用が常に性能向上へ結び付くわけではない。全文方式より品質が低いという負の結果も明確である。
