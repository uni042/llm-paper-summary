# DynBranch：分岐確定前の先行実行と要求横断の部分グラフ再利用

## 概要

DynBranchは、エージェント型大規模言語モデルの推論基盤で生じる**分岐解決障壁（branch-resolution barrier）**を短縮するサービング方式である。エージェントが次の検索対象、呼び出す道具、担当する下位エージェントを生成する間、実際には予測可能な後続の計算も待機する。通常の結果キャッシュは確定した入力を鍵にするため、この待機時間を隠せない。逆に、予測に従って先行計算を開始するだけでは、誤った分岐の結果が外部に見える危険、計算資源の浪費、次の要求への結果の持越し不能という問題が残る。

本方式は、**部分グラフの厳密な再利用（C1）**、**分岐解決中の先行実行（C2）**、**負荷に価格を付ける実行許可（C3）**を独立の契約として実装する。C2が作る候補の結果は、確定要求が来るまで参照不能な影の状態に置く。C1は要求内容と外部データの読取依存を検証してから昇格させ、別要求でも利用できるようにする。C3は候補生成器の起動費用と、個々の候補を実行する費用を別々に判断し、GPUの復号スロットと鍵・値キャッシュ（KV cache）の圧迫を反映する。

4枚のH200 NVLでQwen3-32Bを提供する評価では、4種類のエージェント処理の各条件で、外部比較方式のうち最良のものに対して低負荷時の平均遅延を14～32%削減した。負荷を掛けた条件では、Routing、Sub-Agent、HCIで15～31%、分岐予測が難しいReActで6.2%削減した。投機と要求横断再利用の両方を無効にした同一基盤との比較では46～66%の遅延削減である。これらは**要求全体の経過時間**であり、トークン生成速度の倍率ではない。また「最大32%」は各処理の最良外部方式との比較、「46～66%」は同一実装の無再利用条件との比較であり、分母を混同できない。

## 問題設定：分岐解決障壁と三つの未解決課題

### 分岐前には結果の正式な鍵がない

エージェントの有向非巡回グラフ（DAG）は、固定した全経路が事前にわかる通常の処理フローと異なり、実行途中のモデル出力やユーザー選択で枝が決まる。例えば複数の処理担当を持つRoutingでは、モデルが担当名を生成し終わるまで担当処理が待つ。検索と推論を交互に行うReActでは、検索すべき固有名詞が出力されるまで検索を開始できない。論文が参照するエージェント処理の観測では、処理全体の45～57%がモデル出力後に直列化された下流処理に相当する。この比率は当該観測条件での分析であり、あらゆるエージェントに共通の定数ではない。

通常の完全一致キャッシュでは、次の入力が確定してから結果を検索する。接頭辞KVの再利用はモデル内部の共通接頭辞を扱うが、外部検索や道具の出力を含む部分グラフを、異なる上流要求の間で同一と判定する仕組みではない。先行実行だけなら分岐決定までの時間を隠せるが、誤予測で走った処理をそのまま公開できず、実行後の結果を別要求に引き継ぐことも難しい。

### C1：どの範囲を安全に再利用するか

完全な要求単位のキャッシュは、上流の無関係な一部が変わっただけでヒットしなくなる。部分グラフ単位へ粒度を細かくすると再利用機会は増えるが、同じ入力であっても外部データの版が変わっていれば以前の検索結果を返してはいけない。複数ノードを異なる実行から継ぎ合わせて一つの結果とみなすことも危険である。したがってC1には、部分グラフの入力境界、実行来歴、外部読取集合、更新による無効化を組み合わせる必要がある。

### C2：分岐先が未確定でも何を走らせられるか

先行実行には、分岐の結果と独立して事前に認識できる**分岐座標（branch coordinate）**が必要である。論文の対象ワークフローでは、テンプレート上のルータ段階や選択地点を安定座標として識別できる。一方、この座標は「ここで分岐が起きる」ことを示すだけで、どの結果を正式に使ってよいかを証明しない。分岐座標による早期着手と、確定後の正式入力による認可を分離することが方式の中心になる。

### C3：予測を増やすほど得になるわけではない

候補を広げれば実際の分岐を含む確率は上がるが、外れた候補はGPU計算、実行枠、KVメモリを消費する。投機が通常要求を遅らせれば、個々の候補で数秒を節約してもシステム全体では逆効果になり得る。論文の負荷観測では、同時に存在する先行処理が増えるほど通常処理の伸長とKV占有が強まる。そこでC3は固定の候補数や単一の確率閾値ではなく、現在から候補が終わるまでの資源圧迫を費用として扱う。

## 手法：三つの契約をつないだ実行経路

### C1：入力の完全一致、来歴、外部依存の鮮度

再利用対象は要求全体ではなく、分岐を根とする自己完結した部分グラフである。保存されるのは部分グラフの識別指紋、実際に描画・確定された入力、その入力のハッシュ、出力、外部読取集合、そして一回の実行に由来する来歴である。正式な要求が到着したとき、入力のハッシュと部分グラフの指紋を照合し、記録された読取依存が現在も有効か確認する。入力が違う、依存関係が不明、あるいはデータが更新されていればキャッシュミスとして通常実行する。

外部データの書き込みには逆引き索引を用いる。書き換えられたレコードを読んでいた結果だけでなく、その結果を親とする保存済みの派生結果やエンジン常駐状態も無効化する。依存情報が不完全なら保守的に無効化範囲を広げる。読取と無効化は同期し、並行更新の曖昧さを高速なヒットとして処理しない。これにより、意味的に似ているだけの要求を返す近似キャッシュとは異なり、**同じ入力・同じ依存版に対する再生**という契約を守る。

部分グラフを単位にすると、別の要求で上流の説明や前段の分岐が違っていても、下流の実際の入力が同じなら再利用できる。論文の図7では、変更のある六つの実行ノードのうち、単純な全体鍵では0、接頭辞を含む方式では2、自己完結した部分グラフ鍵では4を再利用できる例を示す。これは一般的なヒット率の測定値ではなく、粒度の違いを示す構成例である。

### C2：分岐座標からの候補生成と影の結果

分岐の未確定状態を認識すると、候補生成器へ分岐座標と履歴を渡す。候補は履歴から次の段階を予測するモデル、検索順位付け器、軽量な下書き言語モデルなどで提案できる。論文の実装ではQwen3-0.6Bも候補生成に用いる。候補生成器が出す順位は利用するが、その生の信頼度を正しい確率と仮定しない。候補の順位ごとに、実際に選ばれ、期限内に消費された頻度をオンラインで学ぶ。

候補のうち、二度実行しても外部に副作用を出さないものだけを**先行充填（early fill）**として実行する。具体的には、固定されたモデル・決定的な計算条件での推論や、版付きスナップショットを対象にした読取専用検索が想定される。確率的なサンプリング、外部書き込みを伴う道具、明示的に安全と指定されていない段階は、分岐が確定してから通常実行する。ここでの安全性は単に同じ道具名であることではなく、同じ入力と依存版から同じ結果を返し、外部状態を変えないことを意味する。

先行充填の入力が描画できた時点でC1の再利用鍵を計算し、結果を取得したら**影の状態（shadow）**へ保存する。影は通常の要求処理から読めない。分岐が確定すると外れた候補を破棄するが、当たりの候補であっても分岐選択だけでは昇格させない。後から到着する正式な段階要求について、入力完全一致と外部依存の鮮度が成立したときに初めて昇格・返却する。この二段階の認可が、先行実行を観測可能な結果の変更にしない条件となる。

候補が複数段階を含む場合も、各段階の入力が本来の正式実行で描画されたはずの内容と一致するかを連鎖的に検査する。ある段階で前提が崩れればその結果は使用せず通常経路に戻す。実行を早めたことによって、外れた分岐が正式な回答や道具の外部状態に混ざることを防ぐ設計である。

### C3：候補生成ゲートと充填ゲートの二段階判断

C3は**候補生成ゲート（Action 0）**と**候補実行ゲート（Action 1）**を分ける。前者は分岐に対して小型予測器を起動し候補集合を作る固定費用を払う価値があるかを判断する。後者は生成された各候補について、実行により隠せる下流時間と、他の正式要求へ課す遅延費用を比較する。候補生成を行っただけで有益な候補がない場合、生成時間は取り戻せないため、この二つを単一の閾値で置き換えることはできない。

負荷の観測量には、通常要求の復号枠の利用、キューの圧迫、KVメモリ占有などを使う。現在の負荷だけでなく候補が実行を終えるまでの予測負荷を評価し、負荷が高いほど充填の価格を上げる。候補を一つ許可したら、その分の予測負荷を反映して次候補を再評価する。さらに充填数とKV予約には厳格な容量制約を適用し、価格が低いという理由だけで予約限界を超えない。

Action 0では、分岐座標を共有する履歴を一つのクラスとし、消費された先行充填の節約時間から候補生成費用・先行実行費用・期限切れ待機の費用を差し引いた収益を学ぶ。文脈付きリッジ回帰と上側信頼限界により、収益が正になると見込める場合にゲートを開く。初期の少数試行は学習用として許容するが、繰り返し高い生成費用を払いながら有効候補が得られなければ、その分岐のゲートは閉じる。候補生成器の処理が遅い場合は期限を設け、期限切れを空集合として扱い、かかった時間は費用に含める。

Action 1では、候補が実際に選択される確率と、選択された際に期限内に使える確率を分離して推定する。前者は順位ごとのベータ分布の上側分位点、後者は条件付き消費率の事後平均を用いる。両者の積から有用な充填の見込みを作り、見込み節約時間が負荷連動の実行費用を超えた場合にだけ実行する。分岐解決後には選択されたかを候補ごとに学習し、期限内に使えたかは実際に許可・選択された候補について学習する。こうして予測誤りと「正しい予測だったが遅くて使えない」を別々に扱う。

### 経路の統合と配置

エージェント側の段階到着、未確定分岐の開始、確定後の正式要求という三つのイベントをHTTP傍受層で受け取る。ワークフローの種類、要求、エージェントの識別情報を正規化し、SGLangまたはvLLMの既存実行器へ通常要求と先行充填を流す。候補生成と充填は既存のキュー・スロット・KV会計を共有するため、独立した無制限の投機用GPUを仮定しない。エージェントの制御ループやモデルの内部実装を変更しなくても導入できることが利点であるが、安定分岐座標の付与と安全な段階の注記は必要である。

## 評価条件と主要結果

### 実験構成と指標

| 項目 | 論文に記載された条件 |
|---|---|
| 主サーバー | AMD EPYC 9755を2基、主記憶2.2 TiB、NVIDIA H200 NVLを4枚、各141 GiB HBM |
| 提供する言語モデル | Qwen3-32B。分岐候補生成にはQwen3-0.6Bを使用 |
| 小型GPU構成 | 4つの分散ワーカーノード、各Qwen3-8BとRTX 4090（24 GiB） |
| Routing | BFCLの関数呼び出し記録を再生し、担当処理と引数を含む経路を評価 |
| ReAct | MuSiQueの多段質問とHotpotQA由来の局所検索資料を用いる検索・推論経路 |
| Sub-Agent | MuSiQue由来の調査下位課題を複数段階で処理 |
| HCI | Schema-Guided Dialogueのメニュー提示・利用者選択を模した操作、選択待ち時間を挿入 |
| 比較方式 | InstCache、Helium+、Parrot、DSP、SPAgent、および同一実装の投機・再利用を無効にした基準 |
| 主要指標 | クライアント観測の要求単位平均経過時間、p99、課題精度、先行充填の消費率とGPU資源費用 |

比較の「無再利用基準」はDynBranchと同じ実行基盤で先行充填と要求横断再利用を切ったものであり、各ワークロードで最も良い外部方式と同一ではない。前者に対する大きな削減率を後者に対する成果と読み替えない。また、HCIは利用者の選択後の応答時間を測る条件を含むため、単純なモデル復号遅延と同じものではない。

### 端から端の平均遅延と末尾遅延

| 比較条件 | 報告された結果 | 読み方 |
|---|---|---|
| Qwen3-32B/H200、低負荷、各ワークロードの最良外部方式比 | 平均遅延14～32%削減 | 処理ごとに比較相手が異なる |
| Qwen3-32B/H200、負荷あり、Routing/Sub-Agent/HCI | 平均遅延15～31%削減 | 通常要求との資源競合がある条件 |
| Qwen3-32B/H200、負荷あり、ReAct | 平均遅延6.2%削減 | 分岐候補が外れやすい検索経路 |
| Qwen3-32B/H200、無再利用基準比 | 平均遅延46～66%削減 | 同一実装の機能無効化との比較 |
| Qwen3-32B/H200、Routing/ReAct/Sub-Agent、無再利用基準比 | p99を低負荷で19～36%、負荷時11～33%削減 | HCIのp99は無再利用基準と同程度 |
| Qwen3-8B/RTX 4090×4、各最良外部方式比 | 平均遅延6.9～37.6%削減 | 小型モデル・分散ノードでも効果を観測 |
| Qwen3-8B/RTX 4090×4、無再利用基準比 | 平均遅延29.6～54.6%削減 | H200と同一の倍率ではない |

論文では各実験群で課題精度が無再利用基準に追随し、提供した負荷で実行失敗は0だったと報告する。ただし「安全性が数学的に保証される」といえるのは、入力一致・依存鮮度・副作用のない段階という前提を満たす場合の昇格規則についてである。一般の任意の外部道具、確率的生成、未知の副作用まで無条件に保証したわけではない。

### 構成要素除去：C1のみとC2のみ

| 条件 | DynBranch | 比較 | 何を示すか |
|---|---:|---:|---|
| C2無効、部分的に重複する要求、Qwen3-32B | 10.2秒（基準14.8秒から31%削減） | Helium+ 10.3秒（30%削減）、InstCache 13.8秒（7%削減） | 要求全体が違っても下流部分グラフを厳密に再利用できる |
| C1無効、Routing、GPU 2枚 | 平均遅延18.6%削減 | SPAgent 12.3%、DSP 13.1%削減 | 要求横断再利用なしでも先行充填に利益がある |
| C1無効、ReAct、GPU 2枚 | 平均遅延8.7%削減 | SPAgent 0.7%、DSP 0.4%削減 | 自由語彙の分岐では先行実行の効果が小さい |
| C1無効、Sub-Agent、GPU 2枚 | 平均遅延34.4%削減 | SPAgent 23.6%、DSP 23.8%削減 | 下位段階の連鎖を先行して隠せる |
| C1無効、HCI、GPU 2枚 | 選択後遅延46.6%削減 | SPAgent 1.0%、DSP 0.7%削減 | 人間の選択待ち時間を先行実行に転用できる |
| C1無効、Routing/ReAct/Sub-Agent/HCI、GPU 4枚 | 21.9%／8.5%／34.0%／47.7%削減 | 各方式の固有許可制御 | GPU増加だけで各処理の利益が比例するわけではない |

C1のみの評価は、同じ要求の完全な繰返し、部分グラフだけ共通する要求、完全に新しい要求を混ぜた実験である。完全な繰返しでは全体キャッシュも有利だが、部分的な重複ではDynBranchがより広い再利用範囲を得る。新しい要求では再利用利益はない。論文の別集計ではこの混合条件で平均32.2%の遅延削減と、不正な部分グラフ結合0件を報告している。これも実測した入力条件に限定される。

C2のみの実験では、先行充填349回が連鎖昇格を通じて500個の段階を消費可能にしたRoutingの例がある。先行充填一つが単一の道具呼び出しだけを節約するわけではなく、後続段階まで連鎖して先行できることを示す。一方、C1とC2の節約時間には重なりがあるため、それぞれの削減率を足して全体削減率とすることはできない。

### 候補幅、予測器、負荷感度

候補の枝数を0から3へ増やした4ワーカー構成では、平均遅延が18.2秒から15.2秒へ短縮した一方、要求当たりの投機的GPU作業が19.8 GPU秒増えた。使われずに捨てられる充填の割合は枝数1で20%、枝数3で33%に増えた。したがって「候補を増やすほど良い」とは言えず、低負荷で得た遅延利益を高負荷へそのまま外挿するのは危険である。

分岐予測器を0.6Bから8Bへ大型化した実験では、上位1候補の予測正解率は改善しても、端から端の速度倍率は1.63～1.70倍で、三つの乱数種を通じてモデルサイズ間の統計的に有意な差はなかった。8B候補生成器は多くの充填を出す一方、消費率は50%であり、1.7B候補生成器の70%を下回った。予測器の正答率だけでなく、正式要求が来る前に充填が完成するかが重要である。32Bの分岐決定を小型LoRA下書き器へ蒸留した場合、0.6Bでも上位1候補正解率0.34を達成し、8Bより低い生成費用で候補を出した。

ReActの先行充填単独の効果は低負荷で16.0%の遅延削減だったが、高負荷では0.4%へ縮小した。外れた候補の比率はどちらも53～55%でほぼ同じであり、予測精度の低下ではなく、先行計算で隠せる時間が高負荷時に減ることが主因と分析されている。この負の結果は、投機実行の有効性が単純な命中率では決まらないことを示す。

二段階許可を固定閾値と比較したReAct実験では、動的方式は候補生成時間を0.89秒に抑え、固定方式より2.8倍少ない生成時間で平均遅延を4.5%削減した。固定閾値方式の削減は2.5～3.5%で、信頼区間が0を含む条件だった。論文は動的方式について95%信頼区間0.5～8.5%、三つの順序を調整した乱数種で174試行と記載している。これは全ワークロード共通の効果ではなく、該当する分離実験の結果である。

負荷を段階的に変えるRoutingの追跡実験では、価格付き許可の平均遅延は8.09秒で、固定制御より5.7%、常時実行より5.5%短かった。繰返しが増えた区間では候補生成を許可する分岐の割合が43%から100%へ増え、収支均衡の閾値が0.678から0.380へ下がった。再利用機会が増えればC1の利益が増し、C3が追加のC2を許可する判断も変化する。

## 既存研究との差と実装上の意味

InstCacheは予測命令に対する完全一致キャッシュ、Helium+はキャッシュを意識したスケジューリングと演算結果再利用、Parrotは意味変数によるワークフロー依存関係、DSPとSPAgentは要求内の投機計画・次の行動の先行実行を主として扱う。DynBranchの違いは、**未確定分岐の座標で先に計算を始め、確定後に厳密に昇格し、その結果を別要求にも残す**という二つの時間軸を結合したことにある。これは通常のトークン投機的復号のように下書きトークンを対象モデルで受理・棄却する方式とは異なり、モデル呼び出しと道具呼び出しを含むエージェント段階の再利用である。

実装面ではモデル実行エンジン内部のカーネルや重みを変更せず、モデルAPI境界で制御できることが利点となる。一方、分岐座標、段階の決定性と副作用の注記、外部依存版の追跡、KV資源の予約と無効化を正しく実装する必要がある。単にHTTP応答を保存して似た問い合わせへ返すだけでは、C1の完全一致・鮮度保証を再現できない。特に検索結果が外部文書の更新に依存する場合、逆引き索引から派生結果へ無効化を伝播しなければ誤った古い結果を返す可能性がある。

## 限界・失敗条件・未検証事項

第一に、評価された処理では分岐座標が結果の確定前からテンプレートで識別できる。分岐自体が自由形式の生成文から新しく生まれ、安定した識別子が存在しない処理には、そのまま適用できない。論文は将来課題として、生成された計画からテンプレートを抽出する方向を挙げるが、現行の実験結果ではない。

第二に、先行できるのは再実行安全な段階だけである。決済、ファイル書換え、通知送信、不可逆な外部API操作を投機的に実行して後で破棄する設計にはしていない。確率的なサンプリングや実行環境の非決定性についても、入力一致だけで出力一致を保証できると仮定してはならない。論文の正しさの主張は、決定的段階と鮮度付き外部読取という契約の内側に限られる。

第三に、候補の予測可能性と要求間の部分グラフ再出現率に依存する。ReActのように検索対象が自由語彙で変化しやすい場合、先行充填の多くが使われず、負荷下の効果が0.4%まで縮む条件がある。利用者の選択待ち時間を使うHCIは利益が大きいが、同じ値を機械的に通常のチャット生成へ当てはめることはできない。

第四に、候補が使われない場合でもGPU秒、KV容量、候補生成の遅延を消費する。負荷連動ゲートはこの損失を抑えるが、資源不足の極端な環境や高負荷で常に正の利益を保証するわけではない。候補幅を増やす実験では破棄割合が上がり、生成器の大型化でも平均遅延が改善しない条件が確認されている。

第五に、主な評価は同種の提供モデル、SGLang/vLLM経路、読み取り中心の道具である。状態を変更する道具のトランザクション隔離、異種モデルを組み合わせた多様な資源スケジューリング、複雑なマルチモーダル段階への一般化は今後の課題である。RTX 4090構成の検証はあるが、単一RTX 4070 SUPER 12GBでQwen3-8Bを同じ形で動かした結果は示されていない。
