# Zep: A Temporal Knowledge Graph Architecture for Agent Memory

> 長期エージェントの記憶を、単なる「過去文書の検索」ではなく「時間とともに変わる事実の履歴」として扱う。LongMemEval_sではgpt-4oの全履歴投入60.2%に対して71.2%へ精度を上げつつ、平均文脈長を115k→1.6kトークン、応答遅延を28.9→2.58秒へ削減した。

## 書誌情報

Preston Rasmussen、Pavlo Paliychuk、Travis Beauvais、Jack Ryan、Daniel Chalefによる2025年1月20日投稿のプレプリントで、arXiv識別子は2501.13956である。対象は大規模言語モデル（Large Language Model; LLM）そのものの高速化ではなく、長期稼働するエージェントへ必要な過去情報を低遅延で供給する外部記憶層である。

## 概要

一般的な検索拡張生成（Retrieval-Augmented Generation; RAG）は、あまり変化しない文書集合から関連チャンクを探す用途には強い。しかし会話型エージェントでは、「先月はA社勤務だったが今月B社へ転職した」「以前の好みが後から変わった」のように、同じ対象について複数時点の事実が共存する。古い記述を上書きすれば履歴を失い、全部を残して単純検索すれば現在有効な事実と失効済みの事実を区別しにくい。

Zepはこの問題をGraphitiという時間認識知識グラフ（temporally-aware knowledge graph）で扱う。生の会話を失わないエピソード層、抽出・統合したエンティティと事実を持つ意味層、密に結び付いた概念群を要約するコミュニティ層の3階層を持ち、事実には「現実世界でいつ有効だったか」と「システムへいつ登録・失効したか」の二つの時間軸を付ける。検索時は意味類似度、全文検索、グラフ近傍探索を組み合わせ、再順位付け（reranking）した少量の事実・エンティティだけをLLMへ返す。

評価では、比較的短い深層記憶検索（Deep Memory Retrieval; DMR）でgpt-4-turbo使用時に94.8%を達成し、MemGPT報告値93.4%と全会話投入94.4%をわずかに上回った。より長いLongMemEval_sでは平均約115kトークンの全会話を約1.6kトークンの検索結果へ縮め、gpt-4oで精度60.2%→71.2%、遅延28.9秒→2.58秒、gpt-4o-miniで55.4%→63.8%、31.3秒→3.20秒を報告する。重要なのは、単なる「検索で速くなった」ではなく、時間更新を含む記憶表現を保ちながら入力文脈を約1/70へ減らした点である。

## 背景：静的RAGでは「現在の事実」と「過去に正しかった事実」を分離しにくい

通常のRAGは、問い合わせを埋め込みへ変換し、ベクトル類似度や全文検索で近い文書断片を選び、その断片をLLMのプロンプトへ足す。文書が静的なら「関連しているか」が主問題だが、エージェント記憶では「いつの時点で正しいか」も同時に問われる。会話履歴をそのまま長いコンテキストへ入れる方法は情報を失わない反面、入力長に比例してプリフィル計算量と料金が増え、長文脈中から必要情報を正しく利用できるとも限らない。

要約型記憶は文脈長を抑えられるが、更新を繰り返すほど古い詳細や根拠が要約から消える。一般的な知識グラフ（knowledge graph）はエンティティ間の関係を明示できるものの、単一の最新状態だけを保持すると「以前は正しかった関係」を失う。Zepの着眼点は、元会話を非損失で残しつつ、検索用の意味表現と時間的な有効期間を別レイヤとして持つことである。

## 問題設定

入力は継続的に追加されるメッセージ、テキスト、JSONなどであり、問い合わせ時には巨大な履歴全体ではなく、その質問へ必要な少数の事実・エンティティを返したい。同時に、情報更新があっても古い事実を削除せず、「いつ有効だったか」を追跡できる必要がある。

このため、Zepには二つの相反する要件がある。第一に取り込み時にはエンティティ解決、事実抽出、矛盾検出など比較的重い処理を行っても、検索時の文脈は小さくしたい。第二に、抽出した意味表現だけへ依存して誤りが入った場合にも、元のエピソードへ遡れる非損失性を保ちたい。論文はこの要件を、階層グラフと二時間モデル、複数検索器の組合せで実現する。

## 手法

### 1. エピソード・意味エンティティ・コミュニティの3層

最下層のエピソード部分グラフは、メッセージ・テキスト・JSONの原文をそのまま保持する。入力メッセージには話者と参照時刻が付き、抽出されたエンティティや事実から元エピソードへ双方向に辿れる索引を持つ。したがって意味層で短い要約を利用しても、引用や検証が必要なときは原文へ戻れる。

中間の意味エンティティ部分グラフでは、現在メッセージと直前4メッセージを文脈にしてエンティティを抽出し、反省（reflection）処理で抜けや幻覚を抑える。エンティティ名を1024次元へ埋め込み、コサイン類似検索と全文検索で既存候補を集め、LLMが同一エンティティか解決する。登録はLLM生成のデータベース問い合わせではなく定義済みCypherを使い、グラフスキーマのぶれを抑える。

最上層のコミュニティ部分グラフでは、密に接続するエンティティ群をまとめて高水準の要約を持つ。GraphRAGでよく使われるLeiden法ではなくラベル伝播法（label propagation）を採用し、新規ノードを近隣の多数派コミュニティへ追加して要約だけ更新できるようにする。全グラフを毎回再クラスタリングしないため更新費用を抑えられるが、逐次更新を続けると完全再計算結果からずれるため、定期的な全面更新は必要である。

### 2. 二時間モデルで「出来事の時間」と「登録の時間」を分ける

各メッセージは参照時刻を持ち、相対表現も含めて事実の時間を抽出する。事実の辺には、システムへ登録された時刻と失効処理された時刻に加え、現実世界で事実が有効になった時刻と無効になった時刻を記録する。これにより「システムがいつ知ったか」と「現実にいつ正しかったか」を分離できる。

新しい辺が既存事実と意味的に矛盾する場合、LLMで関連辺を比較し、時間範囲が重なる古い辺の有効終了時刻を新しい事実の開始時刻へ設定する。古い辺そのものは消さないため、現在状態だけでなく履歴質問にも答えられる。一方、矛盾検出をLLMへ依存するため、抽出や解決の誤りはグラフ品質へ直接伝播する。

### 3. 検索→再順位付け→文脈構築の3段階

問い合わせではまず候補の再現率を高く取る。意味類似検索、BM25全文検索、幅優先探索（Breadth-First Search; BFS）を併用し、意味が近い事実、語が一致する事実、グラフ上で近い事実を別々の経路から集める。最近のエピソードをBFSの種にすることで、直前に話題となった人物や関係の近傍も拾える。

次に候補を再順位付けする。相互順位融合（Reciprocal Rank Fusion; RRF）、最大周辺関連性（Maximal Marginal Relevance; MMR）に加え、会話中の言及回数や指定ノードからのグラフ距離を利用できる。最も重い選択肢として交差符号化器（cross-encoder）も用意されるが、精度向上と計算費用の交換になる。最後に上位の事実には有効期間を、エンティティには名前・要約を付け、短いテキスト文脈へ組み立ててLLMへ渡す。

### 4. 1件の新規会話から回答まで

新しい会話が入ると、まず原文エピソードと参照時刻を保存する。次に周辺会話を含めてエンティティと事実を抽出し、既存グラフと同一性を解決する。新しい事実が過去の事実を覆す場合は古い辺を削除せず有効終了時刻を設定し、コミュニティを増分更新する。

質問時は、質問文を複数の検索器へ渡して候補辺・候補ノードを集め、再順位付けして上位項目だけを文脈へ変換する。LongMemEval_sの実験では、平均約115kトークンの全会話に対してZep側の平均入力は約1.6kトークンであり、長大な履歴のプリフィルを検索処理へ置き換えることで応答待ち時間を大きく減らす。

## 評価

### 代表的な評価条件

| 項目 | 条件 |
| --- | --- |
| 評価1 | 深層記憶検索（Deep Memory Retrieval; DMR）、500会話、各5セッション・最大12メッセージ/セッション |
| 評価2 | LongMemEval_s、平均会話文脈約115kトークン、6種類の質問カテゴリ |
| グラフ構築 | gpt-4o-mini-2024-07-18 |
| 埋め込み・再順位付け | BGE-m3 |
| 回答モデル | DMRではgpt-4-turbo-2024-04-09およびgpt-4o-mini、LongMemEval_sではgpt-4o-miniとgpt-4o |
| Zep検索文脈 | 上位の事実・エンティティを取得し、LongMemEval_sでは平均約1.6kトークン |
| 主な比較 | 全会話投入、セッション要約、DMRではMemGPT報告値 |
| LongMemEval遅延測定 | 2024年12月〜2025年1月、Bostonの一般消費者向けノートPCからAWS us-west-2上のZepへ接続 |
| 判定 | LongMemEvalはGPT-4oを用いた質問種別別の評価プロンプト |

### 代表的な評価結果

| 条件 | 指標 | 比較対象 | Zep | 読み取れること |
| --- | --- | --- | --- | --- |
| DMR + gpt-4-turbo | 正解率 | MemGPT 93.4%、全会話94.4% | 94.8% | MemGPTは上回るが、60メッセージ程度なら全会話投入との差は小さい |
| DMR + gpt-4o-mini | 正解率 | 全会話98.0%、セッション要約88.0% | 98.2% | DMRは現行コンテキスト窓へ容易に収まるため、記憶方式の差を測るには弱い |
| LongMemEval_s + gpt-4o-mini | 正解率 | 全会話55.4% | 63.8% | 絶対+8.4ポイント、相対約15.2%改善 |
| 同上 | 応答遅延 / 平均入力 | 31.3秒 / 115k | 3.20秒 / 1.6k | 約90%の遅延削減。主因はLLMへ渡す入力の大幅削減 |
| LongMemEval_s + gpt-4o | 正解率 | 全会話60.2% | 71.2% | 絶対+11.0ポイント、相対約18.5%改善 |
| 同上 | 応答遅延 / 平均入力 | 28.9秒 / 115k | 2.58秒 / 1.6k | 精度を上げながら入力を約1/70へ縮小 |
| gpt-4o・single-session-assistant | 正解率 | 94.6% | 80.4% | 全質問種で改善したわけではなく、この種別では17.7%相対低下 |
| gpt-4o-mini・knowledge-update | 正解率 | 76.9% | 74.4% | 小型モデルでは更新表現の利用が必ずしも改善につながらない |

DMRの94.8%対93.4%だけを見ると差は小さい。論文自身もDMRは各会話が最大約60メッセージで現在の長文脈モデルに容易に収まり、単発の事実検索が中心なので記憶システム評価として弱いと指摘している。Zepの意義がより明確なのはLongMemEval_sで、全履歴投入より短い入力で高い精度を得た点である。

一方で、LongMemEval_sでも全カテゴリで優位ではない。特にsingle-session-assistantでは両回答モデルで低下し、gpt-4o-miniではknowledge-updateもわずかに低下する。したがって「時間グラフ化すれば常に精度が上がる」のではなく、検索器が必要情報を落とす質問や、回答モデルが時間表現を十分利用できない条件が残る。

## 既存研究との差

MemGPTのようなエージェント記憶は長期履歴を外部化するが、Zepの中心は時間付きの事実グラフを継続更新する点にある。一般的なベクトルRAGは関連度を主に距離で測るのに対し、Graphitiはエピソード原文、意味エンティティ、コミュニティを併存させ、事実の有効期間と失効を明示する。

GraphRAGとの違いも、静的な大規模コーパスをまとめてクラスタリング・要約するだけでなく、新しい会話が入るたびにエンティティ解決、矛盾検出、辺の無効化、コミュニティの増分更新を行う点にある。検索でも意味・語彙・グラフ距離の三経路を統合し、時間範囲を含む短い文脈へ変換する。

## 限界・実装状況

最大の注意点は、グラフ構築自体の費用と誤りが評価表に十分現れていないことである。エンティティ抽出・同一性解決・事実抽出・矛盾検出・要約の複数箇所でLLMを使うため、取り込みコストと更新遅延が別に発生する。検索時に高速でも、書き込み頻度が高い用途では総費用を測る必要がある。

増分コミュニティ更新は完全再計算から徐々にずれるため定期再構築が必要である。また、LongMemEval_sは長期会話記憶のベンチマークであり、論文自身が述べる構造化業務データと会話の統合能力を直接評価していない。MemGPTについてもLongMemEvalへ十分な条件で比較できていないため、同ベンチマークでの優位性は主として全会話投入ベースラインとの比較で読むべきである。
