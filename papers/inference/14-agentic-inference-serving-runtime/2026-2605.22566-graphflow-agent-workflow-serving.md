# GraphFlow: A Graph-Based Workflow Management for Efficient LLM-Agent Serving

> 共有操作グラフからエージェント手順を動的生成し、操作単位の差分KV状態で約4倍のメモリ削減を狙うエージェント・サービング基盤。
## 書誌情報
- **著者**: Ao Li, Shangpeng Yang, Fahao Chen, Tianheng Xu, Peng Li, Zhou Su
- **公開**: ICML 2026 / arXiv:2605.22566v1
- **種別**: 国際会議採択論文・arXivプレプリント
- **対象**: エージェント・サービング、ワークフロー生成、KVキャッシュ状態管理
- **実装**: wGraph、グラフニューラルネットワークによるタスク適応ワークフロー生成、差分KVキャッシュ、経路枝刈りを統合した研究実装。公開コードURLは確認できなかった。
## 概要
GraphFlowは、固定テンプレートの選択に依存するエージェント・ワークフローを、原子的操作を共有する統一グラフwGraphからタスクごとに動的生成する。さらに同じ操作が異なるワークフローで繰り返される際のKVキャッシュ冗長性を、操作ごとの共有基底状態と経路依存の差分状態へ分解して削減する。五つの推論・コード・質問応答ベンチマークで既存手法より平均約4.95ポイント高いタスク性能を示し、KVキャッシュのメモリ占有を約4分の1へ削減した。

GraphFlowは複数ワークフローを別々のテンプレートとして扱わず、原子的操作と有効な依存関係を一つの共有操作グラフwGraphへ統合する。要求の意味と制約から必要な部分グラフを動的に取り出して手順を構成すると同時に、同じ操作ノードのKV状態を文脈非依存の共有基底と実行経路固有の疎な差分へ分解する。ワークフロー構造そのものをKV共有単位として利用するため、エージェント計画とサービング状態管理が同じグラフ表現で接続される。

代表結果として、平均タスク性能は五ベンチマーク・複数基盤モデルでMetaGPT / LLMCompiler / TaskWeaver / AFlow等に対して既存手法比 約+4.95 percentage points。共有グラフから細粒度に操作を組み替えることで、メモリ最適化と独立にエージェントの手順品質も改善する。
## 問題設定
既存のワークフロー支援型LLMエージェントは、あらかじめ用意した粗粒度テンプレートを要求へ当てはめる方式が多く、未知タスクや複数制約を含む要求に対して操作間の細かな意味関係を捉えにくい。同時に、異なるワークフローが検索、推論、検証など同じ操作を共有していても、推論時のKVキャッシュをワークフロー単位で独立保持すると同一操作の状態が重複し、並行エージェント数の増加に伴ってメモリが膨張する。単に状態を捨てれば再計算が増え、全状態を保持すれば容量を圧迫するため、手順生成の柔軟性と状態共有の効率を同時に解く必要がある。
## 新規性
GraphFlowは複数ワークフローを別々のテンプレートとして扱わず、原子的操作と有効な依存関係を一つの共有操作グラフwGraphへ統合する。要求の意味と制約から必要な部分グラフを動的に取り出して手順を構成すると同時に、同じ操作ノードのKV状態を文脈非依存の共有基底と実行経路固有の疎な差分へ分解する。ワークフロー構造そのものをKV共有単位として利用するため、エージェント計画とサービング状態管理が同じグラフ表現で接続される。
## 手法
### 手法のあらまし
まず既存ワークフロー群を、検索、推論、ツール呼び出し、検証などの原子的操作ノードと、操作間で許される依存・遷移辺からなる統一操作グラフwGraphへ正規化する。新しい要求が来ると要求表現をタスクノードとしてグラフへ接続し、グラフニューラルネットワークがメッセージ伝播によって要求の意味、制約、各操作の役割、近傍依存を同じ埋め込み空間へ反映する。続いて多層パーセプトロンが候補遷移の適合度を推定し、高得点で整合する辺を選んで要求固有の連結部分グラフを実行ワークフローとして構成する。実行段階では、同じ操作が複数の経路から到達されてもKVキャッシュ全体を経路ごとに複製しない。操作単体の記述から得られる文脈非依存の基底KV状態を一度だけ共有保存し、先行操作列が与える文脈差だけを経路依存の疎な差分KVとして保持する。必要な状態は共有基底と差分を組み合わせて復元するため、操作重複を持つワークフロー間で大部分の状態を共有できる。さらに理論上可能な全経路の差分を保存すると組合せ爆発するため、有効な遷移だけを残す経路枝刈りと、頻繁に利用される経路の差分を優先して実体化する方針を使う。希少経路は必要時に状態を計算し、メモリ消費を理論上の全経路数ではなく実際の作業集合へ近づける。こうして要求適応の手順生成、操作状態共有、経路ごとの文脈保持、メモリ上限管理を一つのwGraph上で連携させる。

### 統一操作グラフwGraph
複数の既存ワークフローを独立テンプレートとして保存する代わりに、検索、推論、ツール呼び出し、検証など再利用可能な原子的操作をノードへ分解し、実行可能な依存関係を有向辺として一つの共有グラフへ統合する。同じ操作が複数ワークフローに現れてもノードを共有するため、手順知識の重複を明示的に表現できる。新規要求はタスクノードとしてこのグラフへ接続され、要求と操作の関係を局所テンプレート一致ではなくグラフ全体の構造から評価する。この共有表現が後段のKV状態共有単位にもなり、計画層と推論メモリ層を同じ操作識別子で接続する。

### タスク適応ワークフロー生成
要求の意味と制約をタスク特徴へ変換し、グラフニューラルネットワークでタスクノードと操作ノードの間にメッセージを伝播して、各操作が今回の要求へどの程度必要かを文脈化する。多層パーセプトロン型の復号器は候補辺ごとに遷移適合度を計算し、整合する高得点辺から連結部分グラフを抽出して実行手順を作る。固定テンプレートを丸ごと選ぶ方式と異なり、既存操作を新しい組合せで再利用できるため、未知・合成タスクへ一般化しやすい。五ベンチマークで既存手法より平均約4.95ポイント高い性能を得た結果は、この細粒度構成が単なるメモリ最適化ではなくタスク品質にも寄与することを示す。

### 差分KV状態管理
同じ操作ノードでも先行経路が異なれば注意状態は完全には同一でない一方、大部分は共通するという観察を利用する。各操作について単体記述から得られる文脈非依存の基底KVを一度だけ保存し、特定の先行経路が追加する差だけを疎な差分KVとして保持する。実行時には基底と該当差分を組み合わせてその経路の状態を復元するため、ワークフローごとに完全なKVを複製する必要がない。公開本文の例ではHotpotQAでメモリが約85GBから25GBへ低下し、全体として約4倍のKVメモリ削減を報告する。状態を単純に破棄するのではないため、再計算だけに依存する方式より実行遅延を抑えられる。

### 有効経路枝刈りと実体化制御
wGraph上の全操作列に対して差分KVを事前保存すると、同じ操作へ至る接頭経路の組合せに比例して差分状態が増え、基底KVを共有してもメモリ節約が相殺される。そこでGraphFlowは無効・到達不能な遷移をグラフから除去し、実際の要求で頻繁に使われる有効経路だけを差分状態の主要な実体化対象にする。利用頻度の低い経路は恒久的な差分KVを予約せず、要求がその経路を選んだ時点で必要状態をオンデマンド計算する。これにより容量は理論上可能な全ワークフロー数ではなく、現実の要求分布が形成する作業集合へ近い形で増える。要求分布が変われば実体化対象も変えられるため、共有操作が多い一方で経路の裾が長いエージェント環境でも、頻出経路の低遅延と希少経路の省メモリを両立する。差分KV表現だけでは残る経路爆発をこの制御が抑え、約4倍のメモリ削減を実運用可能な状態管理へつなげる。

### 全体のデータ／制御の流れ
共有wGraph、要求埋め込み、グラフニューラルネットワーク、多層パーセプトロン型遷移選択器、要求固有ワークフロー実行器、操作単位の共有基底KV保管部、経路依存差分KV保管部、経路枝刈りから構成される。計画時のグラフ構造をそのまま状態共有の索引として使う点が特徴である。
## 評価条件
- **ソフトウェア**: wGraph workflow manager、graph neural network workflow generator、differential KV キャッシュ manager
- **データセット／トレース**: GSM8K、MATH、HumanEval、MBPP、HotpotQA
- **比較対象**: MetaGPT、LLMCompiler、TaskWeaver、AFlow
同一ベンチマーク上で既存ワークフロー方式とGraphFlowを比較し、手順生成によるタスク性能と、差分KV・経路枝刈りによるメモリ効率を同時に測る。公開本文ではHumanEvalのQwen-2.5-7Bで既存適応方式78.1%に対し86.2%、MATHで72.1%に対し76.4%という例を示し、全設定平均で約4.95ポイント改善する。
五種類の公開ベンチマークと複数の約7B〜9B級モデルで一般化を確認するが、実運用の長時間エージェント、極端に大きいwGraph、異種GPUクラスタでのスケール特性は公開評価からは確認できない。取得できた一次公開本文では具体的GPU型番を確認できなかった。
## 主要結果
GraphFlowは、共有操作グラフから要求固有の手順を組み立てることで、固定・浅いワークフロー選択よりタスク性能を高めながら、同じ操作のKV状態を共有基底と経路差分へ分けることでサービング・メモリも削減した。五ベンチマークと複数基盤モデルを通した平均タスク性能は既存手法より約4.95ポイント高く、HumanEvalのQwen-2.5-7Bでは78.1%から86.2%、MATHでは72.1%から76.4%へ改善した。状態管理ではKVキャッシュのメモリ占有を全体として約4分の1にし、公開本文のHotpotQA例では約85GBから25GBへ低下する。さらに全データセットでP90推論遅延も低下したと報告され、メモリ節約のために単純再計算へ寄せるのではなく、共有状態を保持しつつ実行効率も改善する設計になっている。

- 平均タスク性能 / 既存手法比 約+4.95 percentage points (比較対象: MetaGPT / LLMCompiler / TaskWeaver / AFlow等; 条件: 五ベンチマーク・複数基盤モデル) — 共有グラフから細粒度に操作を組み替えることで、メモリ最適化と独立にエージェントの手順品質も改善する。

- HumanEval accuracy / 86.2% (比較対象: previous 適応型 system 78.1%; 条件: Qwen-2.5-7B) — コード生成でも固定テンプレート選択より要求に適した操作構成を作れることを示す。

- KV キャッシュ メモリ footprint / approximately 4x reduction; HotpotQA example 85GB→25GB (比較対象: standard stateful workflow management; 条件: shared-operation workflows) — 操作ごとの基底KV共有と疎な経路差分により、重複する完全KVをワークフローごとに保持する必要を減らす。

- tail 遅延 / lower P90 inference 遅延 across evaluated datasets (比較対象: workflow 比較対象; 条件: five ベンチマーク datasets) — 希少経路をオンデマンド計算しても、全体では状態共有と簡潔な生成手順による節約が勝ち、メモリ削減だけでなく尾部遅延も悪化させない。

### 負の結果・境界条件
- 全経路の差分KVを保持すると状態数が組合せ的に増えるため、経路枝刈りと実体化制御が必要である。
- 公開評価は五ベンチマーク中心で、非常に大規模な実運用wGraphや長時間エージェントでの容量・更新費は未確認である。

### 結果の読み方
重要なのは、エージェントのワークフロー構造を計画用メタデータに留めず、推論状態を共有する物理的な単位へ昇格させた点である。同一操作を多く共有するワークロードほど基底KVの再利用余地が増え、差分だけで経路文脈を保持できる。経路枝刈りを組み合わせることで状態空間の爆発を抑え、タスク品質、メモリ容量、尾部遅延を同じグラフ設計から改善する。
## 品質への影響
KV状態を量子化・破棄する近似圧縮ではなく、共有可能な基底と経路依存差分へ再表現するため、メモリ削減そのものによる品質低下を狙う方式ではない。むしろタスク適応ワークフロー生成により最終性能は平均約4.95ポイント改善する。
## 既存研究との差
AFlowなどの自動ワークフロー生成は主に実行手順の探索・品質最適化を狙うのに対し、GraphFlowは操作ノードの共有構造をKV状態の共有にも利用する。PagedAttentionなど一般的なKV管理はトークン・ページ単位の配置効率を扱うが、GraphFlowはエージェント操作と実行経路という意味構造から共有可能状態を定義する。
## 限界
- 大規模な実サービスでwGraph自体を継続更新する費用や整合性は公開評価から不明である。
- 操作単位のKVが経路間で十分似るという性質が弱いワークロードでは差分状態が大きくなり削減率が下がる可能性がある。
- 希少経路をオンデマンド計算するため、経路分布が急変すると再計算負荷が増える可能性がある。
- 取得できた一次公開本文では具体的GPU型番やクラスタ規模を確認できなかった。
## 実装状態
wGraph、グラフニューラルネットワーク型生成器、差分KV状態管理、経路枝刈りを統合した研究実装。ICML 2026採択。公式コードURLは確認できなかった。
## 研究上の位置づけ
エージェント・サービングでは、手順の意味構造がKVキャッシュ共有の新しい局所性信号になり得ることを示す。従来のトークン列・ページ・セッション中心のKV管理に対し、操作グラフ中心の状態管理という系統を形成する。
