# Memory Compression for High-Fanout Agent Sandboxes

> AgentZipは共有テンプレートと兄弟サンドボックスの類似性を使ってページを圧縮し、LLM応答待ちに圧縮、再利用前に復元先読みする。16並列ロールアウトでサンドボックス所有メモリを88.55%削減した。

## 書誌情報

- **著者**: Mengming Li、Ceyu Xu、Qijun Zhang、Jiangnan Yu、Xiangfeng Sun、Haohui Mai、Zhiyao Xie（LiとXuは共同筆頭著者）
- **公開**: 2026-09-10、arXiv:2609.11294v1
- **種別**: cs.AI、cs.OSのプレプリント
- **対象**: 高並列エージェント、ツール実行サンドボックス、ホストメモリ管理
- **実装**: Zeroboot/KVMへ実装。E2B互換の呼出し口を備えるが、論文本文に公式コードの公開先は記載されていない。

## 概要

一つの課題から複数のエージェント候補や強化学習軌跡を並行実行すると、各サンドボックスは同じリポジトリ、依存ライブラリ、初期イメージを共有し、似たコマンドも実行する。プロセッサは次のLLM出力待ちで空く時間がある一方、各環境のプライベートページはメモリに残る。このため高ファンアウトでは、演算資源よりもサンドボックスが占有する物理メモリが同時実行数を制限する。

AgentZipは、ページを独立した一般データとして圧縮するのではなく、同じ不変テンプレートとの差、同じタスクから分岐したサンドボックス間の共通パターン、ページ内部の反復を使い分ける。さらに、圧縮可能なページを広く対象にしつつ、ツール処理中は候補を軽く調べ、LLMが次の操作を考えている間に圧縮する。後で必要になるページはアクセス前に復元する。

## 問題設定

Linuxのzswapのような方式はページ内部のバイト列を圧縮するが、テンプレートや兄弟環境にある似たデータを参照しない。KSMはページ全体が一致する場合に共有するものの、サンドボックス生成時のcopy-on-writeですでに共有される領域が多く、少し異なるプライベートページの冗長性は扱えない。また従来の圧縮は将来アクセスが少ないページを選びがちで、再訪時のページフォルトを避ける代わりに、温かいページの圧縮機会を逃す。

本論文は圧縮判断を「どう表現するか」「どのページを圧縮するか」「いつ行うか」に分け直す。AgentZipは、実行環境に特有の重複を使った複数表現、圧縮時の冷温選別に頼らない復元先読み、エージェントのツール実行とLLM待機を区別するスケジューリングを組み合わせる。評価の主眼はモデルの学習手順ではなく、エージェント推論・ツール実行時のメモリ容量と完了時間である。

## 手法

### ページ圧縮の基盤と候補判定

AgentZipはZerobootがFirecrackerスナップショットから作るcopy-on-writeサンドボックスに組み込まれ、圧縮データをユーザー空間のプールへ保存する。4 KiBページの符号化後、元フレームを解放し、Linuxのuserfaultfd（UFFD）でページを登録する。後続アクセスはUFFDが捕捉し、保存メタデータに従って元アドレスへページを復元する。各符号化方式のデータと管理情報を合わせた容量を比較し、正の節約がある最小表現を採用する。

プール項目には符号化形式と再構築に必要な情報を保持し、復元後のページを元と同じ仮想位置へ戻す。圧縮するかどうかはページの再利用頻度でなく、最良の表現が正味の容量を節約するかで決まる。この設計でページ選別と表現選択を分離し、次に使われそうなページも圧縮候補にできる。

### 三つの圧縮表現

テンプレート差分圧縮は、プライベートページを同じ仮想ページ位置の不変テンプレートと固定サイズブロック単位で比較し、異なるブロックだけを保存する。コホート辞書圧縮はテンプレートIDと要求IDから関連環境をまとめ、兄弟サンドボックスの常駐ページからZstandard辞書を学習する。別の検証用ページでデータ節約を確かめ、辞書自体のメモリ量も予算に含めて公開する。辞書IDと参照数を各圧縮ページに結び付け、復元中に古い辞書を失わない。

ページ内の同一バイト列にはランレングス符号化（RLE）を使う。各候補ページに対してRLE、テンプレート差分、辞書圧縮の実サイズを試算し、メタデータを含む最小のものを選ぶ。RLEと差分で効率よく保存できるページを先に扱うことで、すべてを辞書圧縮する場合に比べ、辞書符号化の計算負荷を抑える。したがってページごとに、内部反復、初期状態との近さ、兄弟間の類似性のどれが支配的かを選択へ反映する。

辞書の学習ではサンプルページを訓練用と検証用に分ける。候補辞書の検証には圧縮後のページ群と辞書容量の合計を使い、節約量が十分で、かつ全辞書のグローバル予算を超えない場合だけ新しい辞書を公開する。更新前の辞書はそれを参照するページがなくなるまで保持するため、並行サンドボックス間でも圧縮済みページを正しく戻せる。

### 復元時の先読み

圧縮時に将来のアクセス頻度を理由としてページを除外する代わりに、復元されたページの順序を学び、次に必要な圧縮ページを非同期に復元する。連続ページを予測するstride方式、同一サンドボックス内のページ遷移を学ぶ局所時間方式、兄弟環境間で遷移を共有するコホート時間方式、同じ要求のツール呼出し位置で頻出するページを記録するhotset方式を併用する。予測候補は有界キューで処理し、需要アクセスより先に物理ページへ戻す。

各予測器は異なる規則性を補い、コホート単位の時間予測は先行する兄弟軌跡で観測した復元遷移を他のサンドボックスへ使える。実際に圧縮状態のページだけをキューへ入れ、非同期にデコードしてUFFD経由で再常駐させる。需要フォルトを完全になくす保証ではなく、ホットページも圧縮対象へ広げたときの同期復元をどれだけ前倒しできるかが性能を左右する。

### 実行段階に合わせた圧縮

ツールが動作している間は、軽量な調査処理が常駐プライベートページの圧縮見込みを見積もって候補を順位付けする。ツール呼出しが終わると、サンドボックスが次のLLM出力を待つ時間に、見込みの大きい順で符号化とフレーム解放を行う。新たなツール呼出しが来たら新しい圧縮処理を止めるが、ページ対応付けを変更中の一件は整合性のため完了する。これにより前景のツール処理と重い圧縮処理の競合を避ける。

ページを探す調査はツール動作中に非同期で行い、実際の符号化と解放はモデル生成待ちに移す。再生実験でも各ツール呼出し前の記録済みLLM推論時間を待機時間として与えるため、圧縮が使えるアイドル窓は実際のモデル生成を含むと想定した条件で測られている。次の操作が始まれば協調停止するので、LLM待機が短い実運用では回収できる候補が減り得る。

## 評価条件と代表結果

評価はIntel Xeon Platinum 8480Cサーバー、Linux 5.15.0、Zeroboot/KVM上で行う。R2E-Gymの10 Pythonリポジトリを使い、16軌跡を並行実行するロールアウト（学習向け）と、役割・温度の異なる4候補を走らせる生成・選別（推論向け）を構成した。同じツール操作列と記録済みLLM待ち時間を全方式へ再生する。指標はプライベート常駐ページと圧縮プールを合算した時間平均のサンドボックス所有メモリ、ならびに全軌跡完了までの時間である。

ロールアウトでは無圧縮実行に対し、AgentZipは平均メモリを88.55%削減し、zswapの48.66%、KSMとzswap併用の51.24%を上回った。実行時間は無圧縮比1.403倍で、zswapの1.436倍と併用方式の1.517倍より短い。生成・選別ではメモリを64.29%削減した一方、実行時間は1.468倍となり、zswapの1.118倍、併用方式の1.159倍より遅かった。候補の実行経路が多様な推論ワークロードでは、メモリ節約に対する時間コストが大きくなる。

構成要素の比較では、ロールアウト時のメモリ削減率はテンプレート差分だけで81.95%、辞書だけで88.63%、RLEだけで24.74%。複合方式は辞書単独に近い88.55%を保ちながら、辞書符号化ページ数を約60%減らし、実行時間倍率を2.703から1.403へ下げた。復元先読みを外すとロールアウトの遅延倍率は3.052となり、全方式の1.403に比べて大きく悪化する。複合圧縮と先読みの両方が、メモリ節約を実用的な時間内に保つのに寄与する。

## 既存研究との位置付け

AgentZipは、エージェントのツール待機中にサンドボックスの物理メモリを圧縮する点で、KVキャッシュ管理やモデル重みのオフロードとは管理対象が異なる。リポジトリ内のAgentCgroupはエージェントのCPU・メモリ要求をツール呼出し単位で制御し、CacheWiseやMORIはツール待機・再入場を利用してGPU上のKVキャッシュを管理する。AgentZipはゲスト環境のページを対象に、テンプレートと兄弟セッション間の近似重複を削減する補完的な仕組みである。

## 適用範囲と限界

実験は10のPythonリポジトリ、単一のZerobootランタイム、再生したロールアウトと生成・選別トレースに限られる。測定でも実行時間倍率は推論用生成・選別の方が大きく、兄弟軌跡の類似度が低い状況ほど、利得とオーバーヘッドの両方を環境ごとに検証する必要がある。ユーザー空間UFFDによる需要復元ではp95 110.52 ms、p99 223.27 msの尾遅延が報告され、先読みを外したときの遅延倍率も大きい。異なるテナントの辞書・予測状態は分離する設計だが、論文は本番規模の敵対的ワークロードや詳細な隔離評価を示していない。

圧縮・復元は元ページを戻すためモデル計算の近似ではないものの、公開評価でエージェント回答品質や追加推論負荷を網羅的に比較してはいない。また、LLM待ち時間が十分あること、サンドボックスが共有テンプレートから作られること、関連軌跡が存在することが前提となる。従って、効果は同一タスクから多数の実行を並行させる環境に最も期待でき、単発または互いに無関係な環境へそのまま一般化できるとは限らない。

## まとめ

AgentZipは、エージェントサンドボックスの共有起源と似た実行経路をメモリ圧縮へ利用する。三種のページ表現、需要アクセス前の復元、LLM待機時間に合わせたスケジューリングを組み合わせ、ロールアウトでは大幅な平均メモリ削減と比較的小さい時間増加を示した。一方で推論用生成・選別では1.468倍の実行時間となるため、導入価値はファンアウト数、候補間の類似度、待ち時間、復元先読みの有効性に左右される。
