# RecursiveMAS：文章を経由しない異種エージェント協調と再帰的推論

## 概要

通常の複数エージェントシステムでは、計画役が文章を生成し、批評役がその文章を読み、解答役が批評を受け取る。こうしたやり取りを何巡も繰り返すと、各段階で語彙への射影、トークン生成、次モデルへの再埋め込みが生じる。RecursiveMASは、異種の大規模言語モデル（LLM）を役割別に保持したまま、中間協調を文章ではなく連続的な隠れ状態（latent state）で進めるシステムを提案する。各エージェントを再帰モデルの一層に見立て、最後のエージェントの表現を最初へ戻すことで、同じ協調構造を何ラウンドも反復できる。

重要なのは、単なるトークン削減の後処理ではない点である。モデル内部の最終隠れ状態は、そのまま別モデルの入力埋め込みとして使うには分布・次元が合わない。そこでエージェント内とエージェント間の二種類の軽量変換器RecursiveLinkを学習し、途中では語彙トークンを出さず、最終ラウンドの最後のエージェントだけが回答文を出力する。文章媒介型の同じ再帰的協調構造（Recursive-TextMAS）に対し、再帰1、2、3ラウンドで平均推論実行時間の相対改善が1.2、1.9、2.4倍へ広がり、外部トークン使用量は34.6%、65.5%、75.6%少なくなると報告する。

この結果は、同じ協調構造・再帰予算における比較であり、すべての単独モデルや他のシステムより常に2.4倍速いことを意味しない。また再帰を深めれば、RecursiveMAS自身の絶対計算時間も増える。学習段階ではモデル本体を凍結し、二種類のLinkを学習するため、推論時の高速化と、事前に必要な追加学習コストを区別する。

## 問題設定

### 文章を中間インターフェースに使う費用

例えばPlanner→Critic→Solverという三役構造では、Plannerが文章を出し切るまでCriticは次段の入力を確定できず、Criticも文章を生成する。この待ち時間は、同じ役割を複数回巡回させると累積する。文章の生成には、最終隠れ状態を全語彙へ射影してトークンを選び、そのトークンを次のモデルで再び埋め込む処理が必要である。トークン数が増えるほど、モデル計算だけでなく語彙射影・入出力のコストが増える。

論文の理論解析では、エージェント数`N`、各段階の潜在ステップ数`m`、入力長`t`、隠れ次元`d_h`、語彙数`|V|`に対し、文章型の計算量に`N*m*|V|*d_h`項が現れる。RecursiveMASは中間語彙射影を避け、同じ部分を`N*m*d_h^2`相当の軽量な連続表現変換へ置き換える。`d_h`が語彙数より十分小さい場合に有利になるという比較であり、自己注意の`(t+m)^2*d_h`などの共通費用が消えるわけではない。

### 異種モデルの隠れ状態は互換ではない

各役割にQwen、Llama、Gemma、Mistralなどを割り当てると、最終層の表現次元も入力埋め込みの分布も異なる。単に前モデルの隠れベクトルを次モデルへ渡すだけでは、受信側が学習時に見た入力分布から外れる。さらに再帰中にすべてのモデル重みを更新すると、メモリと計算の負担が大きい。RecursiveMASはモデル本体を固定し、変換器だけを学習することで、異種構成を保ちながら中間文章生成を取り除く。

## 手法

### 1. エージェント内のinner RecursiveLink

各エージェントのTransformer最終層が出す隠れ状態`h`を受け取り、`R_in(h) = h + W2 * GELU(W1*h)`で変換する。ここで二層の線形変換と活性化関数は分布を補正し、残差項`h`は元の意味情報を保持する。変換後のベクトルを次の生成ステップの入力埋め込みとして再投入することで、語彙空間へ射影せずに`m`個の潜在思考状態を逐次生成する。

入力は現在の最終隠れ状態、出力は同じエージェントの次ステップが受け取れる埋め込みである。改善対象は中間トークンの生成と再埋め込みだが、各潜在ステップではTransformer本体の順伝播が残る。したがって潜在ステップを増やし過ぎれば、トークンを出さなくても計算時間は増える。残差を削る構成要素除去実験で精度が落ちるのは、この意味保存の重要性を裏付ける。

### 2. エージェント間のouter RecursiveLink

エージェント`A_i`の隠れ次元が次の`A_j`と異なる場合、外側の変換器`R_out(h) = W3*h + W2*GELU(W1*h)`を使う。`W3`は受信モデルの次元へ射影する枝であり、二層の補正枝と合わせて受信側の入力空間へ写像する。前エージェントが作った潜在状態列を変換し、次エージェントの役割別入力文脈へ連結して渡す。ここで交換するのは人間可読の回答文ではなく、学習済みの連続表現である。

Planner→Critic→Solverの最後にSolverが潜在列を生成すると、外側のLinkを経由してPlannerへ戻す。これで1巡の協調を閉じ、次巡のPlannerは前巡で全役割が得た情報を条件として推論する。最終ラウンドのSolverだけが語彙へ射影し、文章を生成する。この処理順を保持することで、既存の直列型だけでなく、専門家混合型、専門家・学習者型、反省・ツール呼出型の協調構造にも適用できる。

### 3. 内外二段階の学習

まず内側の学習では、正解文章`y`を各モデルの入力埋め込み層で変換し、生成した潜在思考とその埋め込みとの余弦距離`1 - cos(R_in(H), Emb(y))`を小さくする。これは潜在状態を入力分布へ近づけるウォームアップであり、各エージェントの内側Linkを並列に準備できる。

続いて外側の学習では、協調構造を指定回数だけ展開し、最終ラウンドの回答と正解の交差エントロピーを最小化する。誤差勾配は全ラウンドの外側Linkを逆向きに伝わり、各Linkは局所の文章正解だけでなく、最終回答への寄与を通じて更新される。ベースモデルの重みは凍結され、学習対象はLinkだけである。本文は、確信度が高いトークンのsoftmaxを経由する文章型勾配は小さくなりやすい一方、残差を含む連続写像では勾配が保たれるという条件付き理論解析も示す。これは実測の推論速度と独立した学習安定性の説明である。

### 4. 役割別構成への適用

直列型の軽量構成はPlannerにQwen3-1.7B、CriticにLlama3.2-1B、SolverにQwen2.5-Math-1.5Bを使う。拡張構成ではGemma3-4B、Llama3.2-3B、Qwen3.5-4Bを用いる。専門家混合型ではコード・科学・数学の専門モデルからQwen3.5-2Bの集約器へ渡す。蒸留型ではQwen3.5-9BのExpertとQwen3.5-4BのLearnerを接続し、熟議型ではQwen3.5-4BのReflectorと、Pythonや検索APIを呼ぶTool-Callerを連携させる。これらは同じLinkの考え方を異なる協調グラフへ適用した検証であり、GPU上のMoE専門家並列化そのものではない。

| 2 | 平均速度比 | 1.0倍 | 1.9倍 | ラウンドを増やすほど文章型の費用が膨らむ |

| 3 | 平均速度比 | 1.0倍 | 2.4倍 | 同一3巡の比較。1巡時より絶対速度が速いという意味ではない |
| 3 | トークン使用量削減率 | 基準 | 75.6%減 | 最終出力以外の文章生成を減らす |

### 学習資源と実装上の負担

原著の公式プロジェクトページは、学習可能パラメータ数をRecursiveMAS約1312万（全体系の0.31%）、LoRA約1592万（0.37%）、全量微調整42.1億と示す。対応するピークGPUメモリはRecursiveMAS 15.29 GB、LoRA 21.67 GB、全量微調整41.40 GBである。これらは**学習時の資源比較**であり、推論時のピークVRAM削減と取り違えてはいけない。多段階の学習が必要なため、事前学習済みの任意のモデルを接続するだけで同じ結果が出る保証はない。

## 既存研究との差

Mixture-of-Agents（MoA）やTextGradなどの従来協調方式は、エージェントの役割や相互批評を構成しても、途中の情報交換を文章で行う。単体の再帰型言語モデルLoopLMは、同じモデル内部の計算深度を増やすが、隠れ次元が異なる複数の専門モデルを接続する設計ではない。RecursiveMASは「各エージェントを再帰モデルの一層とみなす」ことで、**エージェント内の潜在生成**と**エージェント間の潜在転送**を分け、両方を小さな学習可能Linkで結ぶ。役割分担を維持しながら、中間の語彙射影と文章再入力を削減する点がシステム上の貢献である。

このため、GPUカーネルの並列化やKVキャッシュの階層配置を直接最適化する研究とは異なる。効果は、協調するモデル数・中間生成トークン数・再帰回数によって変わる。外側の学習を通じて異種モデル間の意味表現を整合させることが必要で、一般のAPI型ブラックボックスモデル同士を文章なしで即座に接続できる方式ではない。

## 限界と注意点

潜在状態の交換には各モデルの最終隠れ状態へアクセスできることが前提である。閉じたAPIだけを持つモデルでは、RecursiveLinkを接続するインターフェースがない。モデル本体は凍結するが、役割別データによる内外Link学習が必要であり、追加学習なしのプラグインではない。公式配布の参考チェックポイントと、論文のタスク別学習設定を同一視しないよう、公開実装側も注意している。

速度の主な比較対象は**同じ協調構造の文章型再帰MAS**である。異なる役割数、推論ラウンド、生成上限、外部検索時間を含む実運用のすべてで同倍率が成立するとは限らない。GPU評価はH100/A100上で、分散クラスタの通信帯域や数百要求の同時サービング、CPUオフロード、異種GPU間の転送性能は主評価ではない。学習資源の削減と推論トークン削減を混同しないことも重要である。

理論計算量は語彙射影の費用が`d_h^2`へ置き換わることを示すが、Transformer本体の自己注意や複数ラウンドの計算は残る。さらに精度の改善は、タスクと役割構成、潜在状態を学習した分布に依存する。深い再帰を追加すれば常に得になるとは言えず、応答遅延予算に合わせて深度を選ぶ必要がある。ツール呼出型では外部検索APIの遅延・可用性もシステム全体の律速となり得るが、論文はネットワーク障害下の実測を示していない。
