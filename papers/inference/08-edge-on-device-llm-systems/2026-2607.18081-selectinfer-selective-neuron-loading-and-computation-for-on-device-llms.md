# SelectInfer: Selective Neuron Loading and Computation for On-Device LLMs

> オフラインで重要FFNニューロンを選別して必要分だけロードし、入力ごとの活性で計算対象も絞ることで、端末LLMのメモリ量と計算量を独立に調整する方式。
## 書誌情報
- **著者**: Huzaifa Shaaban Kabakibo, Eric Schniedermeyer, Artem Burchanow, Lin Wang
- **著者・所属**: Paderborn University
- **公開**: arXiv
- **種別**: Preprint
- **対象**: on-device LLM inference、selective neuron loading、活性値 sparsity、edge inference
- **実装**: FFNの各射影行列から選択ニューロンに対応する重みスライスだけをロードし、静的ニューロンとプリフィルで選ぶ動的ニューロンだけをデコード時に計算する。
## 概要
SelectInferは、端末上のLLMで全FFN重みを常駐させるとメモリが不足し、単純な量子化や枝刈りでは精度・再学習・低精度カーネル対応の制約が生じる問題に対し、ニューロン単位でロード量と計算量を別々に制御する。オフライン解析でタスク固有ニューロンとモデル共通ニューロンを順位付けし、端末では前者を基底集合として常駐、後者を加えてメモリ上限まで選択ロードする。さらにプリフィル時の活性から入力ごとの動的ニューロンを選び、デコードではロード済み集合の一部だけを計算する。Jetson Orin Nano上でLlama3.2-1B/3BとQwen2.5-3Bを評価し、3Bモデルを実行可能なメモリへ収めつつ、4-bit量子化より高いデコード速度を示した。

SelectInferの論文固有の着想は、ニューロン疎性を『計算を飛ばすため』だけでなく『どのFFN重みを端末へ常駐させるか』の判断にも使い、さらに二つの選択を別の割合で制御する点にある。オフライン解析では同一タスク内で安定して重要なタスク固有ニューロンと、複数タスクに共通して重要なモデル固有ニューロンを分けて順位付けする。配備時には前者を基底集合として必ずロードし、後者を追加してメモリ上限γまで埋めるため、単なるランダムな部分モデルではなく、事前に観測した意味的な重要度を使って常駐集合を作る。推論時にはロード済み集合を全部計算せず、基底集合δを静的に計算しつつ、プリフィル中の現在入力の活性から追加の動的集合εを選ぶ。これによりロード割合γと実計算割合φ=δ+εを独立に設定でき、メモリ容量はγ、速度と精度はφを中心に調整できる。量子化のように重み精度を落とさず、枝刈りのような再学習も要求せず、CoreInferのように全重み常駐も要求しない組み合わせが新規性である。

代表結果として、peak メモリは70% loaded neuronsでoriginal 6.88/2.86/6.48 GB; CoreInfer 7.44/2.86/7.52 GBに対してLlama3.2-3B 5.97 GB、Llama3.2-1B 2.60 GB、Qwen2.5-3B 5.37 GB。3Bモデルで約0.9〜1.1 GBを削減し、全重み常駐が難しい端末条件へ収める。
## 問題設定
端末LLMでは、Transformerの全結合ネットワーク（Feed-Forward Network; FFN）がモデル重みの大部分を占めるため、計算能力以前に重みを端末メモリへ常駐できるかが制約になる。論文のJetson Orin Nanoは物理8 GB共有メモリを持つが、OSなどを除く実利用可能量は約6.5 GBで、3B級モデルは通常の実行環境を含めると約8.5〜9.5 GBを要求する。このため全重みを載せる通常推論は成立しない。4-bit量子化は容量を大きく削減できる一方、低精度カーネルを効率よく実行できない端末では速度が伸びず、ビット幅単位の粗い調整しかできない。枝刈り・蒸留は重みを恒久的に削るか再学習を必要とし、配備後にタスクやメモリ予算へ合わせて柔軟に戻せない。CPUやディスクへのオフロードはPCIeやストレージ転送が待ち時間になり、共有メモリ型SoCでは前提自体が合わない場合もある。CoreInferのような活性疎性方式はプリフィルから重要ニューロンを選び計算量を減らせるが、全モデル重みを先にメモリへ載せるため、3Bモデルがそもそも収まらない問題を解けない。したがって、再学習せずに常駐重み量そのものを減らし、その上で入力ごとの計算量も別に削減できる仕組みが必要になる。
## 新規性

## 手法
### 手法のあらまし
処理はオフライン解析と端末上のオンライン推論の二段階に分かれる。最初にオフラインLLM解析器へ対象モデルとQA・翻訳・要約などのデータを与える。解析器は各トークンを通常どおりモデルへ通し、FFNニューロンの活性を記録して重要度を集計する。同一タスク内の複数データセットから得た順位はタスク固有ニューロンとして保存し、異なるタスクから選んだデータの混合集合から得た順位はモデル共通ニューロンとして保存する。論文はタスク固有ニューロンが同一タスクの別プロンプトでも比較的重なりやすいことを確認し、これを配備時の安定した基底集合として利用する。次に端末へモデルをロードする。attentionや埋め込みなどFFN以外は通常どおり載せるが、FFNの各射影行列ではタスク固有順位の上位δを基底ニューロンとして選び、その重みに対応する行・列のスライスだけをロードする。さらにモデル共通順位の上位から二次ニューロンを追加し、合計ロード割合がγへ達したところで止める。選ばれなかったFFNニューロンは端末メモリへ載せないため、全重み常駐時よりピークメモリを下げられる。推論要求が来ると、基底ニューロンは静的集合として常に計算対象にする。プリフィルではロード済み二次ニューロンの活性を観測し、各トークンで上位に現れる頻度から現在の入力に関連する動的ニューロンを選ぶ。静的割合δと動的割合εの合計φだけをデコード時のFFN計算へ残し、ロード済みでも今回の入力に不要なニューロンは演算しない。したがってデータの流れは、オフライン活性計測→タスク固有/モデル共通順位生成→γに合わせたFFN重みスライスの選択ロード→プリフィル活性による動的集合選択→φだけを使う疎なデコード、という一本道になる。主評価ではδ=30%、二次40%を加えγ=70%をロードし、ε=10%を動的に選んでφ=40%だけ計算する。γを下げればメモリと重み読み込み量は減るが精度が落ちやすく、φを下げれば演算量は減るが必要ニューロンを外す危険が増えるため、二つを端末容量と要求性能に合わせて別々に調整する。

### オフラインLLM解析器
入力は対象LLMと、QA・翻訳・要約など配備先を代表するデータである。解析器は推論中のFFN活性をトークン単位で記録し、各ニューロンがどれだけ強く・一貫して使われたかを集計して層ごとの重要度順位を作る。同一タスクの複数データセットをまとめて解析した順位はタスク固有ファイルとなり、PIQA・WMT14・XSumのように異なるタスク群を混ぜた解析結果はモデル共通ファイルになる。論文では同一タスクの上位ニューロンがプロンプトをまたいで比較的安定し、δ=30%付近では約60%が重なることを観測している。出力される二種類の順位表は、オンラインでその都度全ニューロンを探索する代わりに、配備前に『常に残す候補』と『追加候補』を絞るために使われる。解析自体はL40S上で3Bモデル約44Mトークンにつき約5時間を要するが、一度作った順位を端末配備で再利用することで、端末側に重い予測器や再学習を要求しない。

### 選択的ロード
入力はオフライン解析が作ったタスク固有順位・モデル共通順位、端末の利用可能メモリから決める総ロード割合γ、基底割合δである。各FFN層についてまずタスク固有順位の上位δを基底ニューロンとして選び、次にモデル共通順位の上位から二次ニューロンを追加して総数がγへ達するまで埋める。実際のモデルロードでは、gate_projなどFFN射影行列のうち選択ニューロンに対応する重みスライスだけをメモリへ読み込み、非選択ニューロンの重みは読み込まない。attentionなどFFN以外の構成要素は通常どおり保持する。したがって出力は全モデルの縮小コピーではなく、元の全精度重みから重要FFNスライスだけを残した実行可能な常駐モデルになる。Llama3.2-3Bではγ=70%と対象層割合から理論上約0.945 GBのFFN重み削減となり、実測でも6.88 GBから5.97 GBへ減る。ランダムに70%を残す対照実験では多くのタスク精度が大きく崩れるため、単なる部分ロードではなく事前重要度に基づく選択が必要である。

### 静的・動的ニューロンによる選択的計算
ロード後もγ分のFFNを毎回すべて計算するとメモリ問題は軽くなるが演算量は十分に減らないため、SelectInferは計算対象をさらにφまで絞る。基底ニューロンδは対象タスクで安定して重要と判断済みなので静的集合として全プロンプトで必ず計算する。一方、二次ニューロンは入力依存性が高いため、プリフィル中に各トークンの活性上位へ何度現れたかを観測し、頻出するニューロンから割合εの動的集合を作る。デコードでは静的集合と動的集合の和だけをFFN演算へ渡し、ロード済みでも現在入力に関連しない残りニューロンの行列計算を省く。主設定ではδ=30%、ε=10%でφ=40%となるため、70%をメモリへ置きながら実際には40%だけを計算する。CoreInferと同様に入力活性を使う利点を残しつつ、候補集合自体をオフライン解析で70%へ狭めているため、全モデル常駐を必要としない点が接続上の違いである。

### メモリ量と計算量の独立調整
γは『何個のニューロン重みを端末へ常駐させるか』を決め、φは『常駐した中から何個を各デコードで実際に計算するか』を決めるため、異なる資源制約へ対応する。メモリが厳しい端末ではγを下げ、演算能力や遅延要求が厳しい場合はφを下げる。両者を同じ値へ固定しないので、空いているメモリは精度維持のため候補重みに使いながら、演算だけをより強く疎化することもできる。評価では3BモデルがJetsonのメモリへ収まる最大値としてγ=70%を選び、CoreInferの知見と実験からφ=40%を採用した。γを40%から80%へ上げる実験ではLlama3.2-3Bの速度が9.75から8.65 トークン/sへ下がる一方、SQuADv2精度は14.87から24.70へ上がり、資源と品質の明示的な交換関係が確認できる。この機構の出力は固定の圧縮モデルではなく、端末ごとに調整可能な配備点である。

### 全体のデータ／制御の流れ
高性能GPUでのオフライン解析と、共有メモリ型端末でのオンライン推論を分離する。オフライン側はニューロン重要度だけを生成し、端末側はその順位を使ってFFN重みを部分ロードする。要求ごとのプリフィルでは動的集合だけを更新し、デコードでは静的＋動的集合へ計算を限定する。この構成により、重い重要度学習を端末へ持ち込まず、全モデル常駐も避け、端末では選択済み全精度重みを使った通常のTransformer推論へ近い形を保つ。
## 評価条件
- **ハードウェア**: NVIDIA Jetson Orin Nano Developer Kit: 6-core Arm Cortex-A78AE CPU、Ampere GPU 1024 CUDA cores/32 Tensor Cores、8 GB LPDDR5共有メモリ。オフライン解析はNVIDIA L40S、バッチ size 16。
- **ソフトウェア**: 比較対象としてCoreInfer、bitsandbytes 4-bit量子化、ディスクオフロードを使用。SelectInferはFFNニューロンの重みスライス選択ロードとプリフィル由来の動的選択を実装。
- **比較対象**: CoreInfer、CoreInfer + Selective Loading、CoreInfer + Random Loading、70% Dense、bitsandbytes 4-bit 量子化、disk オフロード
Llama3.2-3B、Llama3.2-1B、Qwen2.5-3BをQA・翻訳・要約で評価する。QAはSQuAD、TriviaQA、MLQA、PIQA、翻訳はWMT16 de-en/en-deとWMT14 fr-en/en-fr、要約はCNN/DailyMail、Samsum、XSumを用いる。主設定は最初の4層程度と末尾2層を避け、静的30%、動的10%、計算40%、二次40%、総ロード70%。精度、ピークメモリ、デコードトークン/sを測定し、ランダムロード、選択ロードのみ、CoreInfer、70% dense、4-bit量子化、ディスクオフロードと比較する。
3B以下のdense LLMを共有メモリ型の端末GPUへ載せる条件。オフライン解析コストと端末上のメモリ・精度・デコード速度の三軸を評価。
## 主要結果
70%のFFNニューロンだけをロードするSelectInferは、Llama3.2-3Bのピークメモリを6.88 GBから5.97 GBへ13.2%削減し、Qwen2.5-3Bも6.48 GBから5.37 GBへ削減した。40%計算のLlama3.2-3Bでは9.85 トークン/sで、4-bit量子化6.41 トークン/sの約1.5倍、ディスクオフロード0.75 トークン/sの13倍超。精度は多くのQA・翻訳・要約でCoreInferを上回るが、Qwen2.5-3BのSQuADv2ではSelectInfer 24.32に対しCoreInfer 32.58で劣る。

- peak メモリ / Llama3.2-3B 5.97 GB、Llama3.2-1B 2.60 GB、Qwen2.5-3B 5.37 GB (比較対象: original 6.88/2.86/6.48 GB; CoreInfer 7.44/2.86/7.52 GB; 条件: 70% loaded neurons) — 3Bモデルで約0.9〜1.1 GBを削減し、全重み常駐が難しい端末条件へ収める。

- デコード スループット / Llama3.2-3B 9.85 トークン/s (比較対象: 4-bit 量子化 6.41 トークン/s; disk オフロード 0.75 トークン/s; 条件: 70% loaded, 40% computed on Jetson Orin Nano) — ロード削減に加えて実計算ニューロンも40%へ絞ることで量子化より約1.5倍、ディスク退避より13倍超。

- Llama3.2-3B WMT16 translation BLEU / 25.68 de-en、25.96 ro-en (比較対象: CoreInfer 4.97/4.98; CoreInfer + selective loading 1.70/1.65; 条件: SelectInfer main configuration) — オフラインで選ぶ静的集合と入力適応の動的集合を組み合わせることが翻訳精度維持に寄与。

- Qwen2.5-3B SQuADv2 Exact Match / 24.32 (比較対象: CoreInfer 32.58; CoreInfer + selective loading 35.69; 条件: SelectInfer main configuration) — 全タスクで優位ではなく、モデル・タスク依存の精度損失が残る。

- loading ratio trade-off / 40% loadで9.75 トークン/s、80% loadで8.65 トークン/s; SQuADv2 14.87から24.70へ上昇 (比較対象: same method across load ratios; 条件: Llama3.2-3B) — ロード量を減らすほど速度は上がるが精度が低下し、γが明示的なメモリ・速度・精度調整ノブになる。

### 負の結果・境界条件
- 4-bit量子化はSelectInferより大幅に小さいメモリを実現し、Llama3.2-3Bでは3.03 GB対5.97 GB。Qwen2.5-3BのSQuADv2ではCoreInferに精度で負ける。パラメータ割合はハードウェアとタスクに依存し、論文自身も基底・二次・計算割合を経験的に検証する必要があるとしている。

### 結果の読み方
FFN重みの一部をそもそも常駐させないためメモリを削減でき、さらに常駐集合の一部だけを入力適応で演算するため速度も上げられる。量子化ほどメモリは縮まない代わりに全精度重みと高い演算速度を保ち、二つの割合を独立に調整できる。
## 品質への影響
多くの条件でCoreInfer系より高い精度を保ちつつメモリと速度を改善するが、タスク依存の劣化があり、量子化との比較でも精度・速度・容量の優劣は一様ではない。
## 既存研究との差
PowerInfer/PowerInfer-2は層ごとの予測器で実行時活性ニューロンを予測するが予測器自体のメモリ・計算負担があり、LLM-in-a-Flashは必要重みをフラッシュから都度取得するためI/O帯域に制約される。CoreInferはプリフィルの活性だけで計算対象を絞るため速度は上がるが全モデル常駐が必要。SelectInferはオフラインのタスク・モデル知識で常駐集合そのものを先に縮め、その中から入力適応で計算集合をさらに絞る。量子化と違いロード済み重みは全精度、枝刈りと違い再学習や永久削除を要求しない。
## 限界
オフライン解析にはL40Sで3Bモデル約44M トークンあたり約5.0〜5.5時間を要し、事前計算コストがある。主評価は1B〜3B denseモデルとJetson Orin Nanoに限られ、より大きなモデルやMoE、他の端末SoCでの一般化は未検証。ロード割合・静的/動的割合は端末容量とタスクに合わせた経験的調整が必要。4-bit量子化よりピークメモリは大きく、Qwen2.5-3BのSQuADv2のように精度でCoreInferへ負ける条件もある。

## 研究上の位置づけ
端末推論の階層メモリ系と活性疎性系を接続する方式。『全モデルをどこへ置くか』だけでなく、オフラインで重要度を学習してFFN重みの常駐集合を縮め、オンラインではさらに入力依存の計算集合を選ぶ。これによりメモリ容量制約と演算帯域制約を別々の制御変数で扱う。
