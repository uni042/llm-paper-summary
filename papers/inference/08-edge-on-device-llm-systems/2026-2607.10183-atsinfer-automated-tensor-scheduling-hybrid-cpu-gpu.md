# Automated Tensor Scheduling for Hybrid CPU-GPU LLM Inference on Consumer Devices

> CPU/GPUでの実測速度と実行中の負荷をテンソル単位で見て、限られたVRAMへの常駐と一時転送を選び、個人PCでのLLMオフロード待ちとCPU律速を減らす。

## 問題
個人PCではモデル重みがGPUメモリに収まらずCPUメモリへの退避（offloading）が必要になる。GPU中心方式はPCIeで重みを運ぶ時間が律速になり、CPU/GPU混合実行は転送量を減らせる代わりに遅いCPU計算がGPUを待たせる。さらに既存方式はlayerまたはexpert単位の粗い配置が多く、同じlayer内でもGPUへ置く価値が大きく異なるtensorを区別できない。個人PCでは他applicationや熱・電力制約でCPU/GPU性能も実行中に変動する。

## 新規性
ATSInferは配置・転送・計算をtensor粒度へ細分化し、(1) CPU/GPU非同期協調、(2) 実測性能に基づく静的tensor配置、(3) 実行時負荷を見た動的tensor転送、を一つのruntimeで組み合わせる。DenseとMoEの両方を対象にし、固定配置だけでなく一時的なhardware contentionにも追従する点が特徴である。

## 手法
### 静的tensor配置
各tensorについてCPUとGPUのoperator実行時間とmemory footprintを事前測定し、限られたVRAMを使ったときのlatency削減効果が大きいtensorを優先してGPUへ常駐させる。layer全体を一括で置くのではなく、同一layer内の異質性を利用する。

### 負荷認識型の動的転送
prefill前および各decode stepで最近のCPU速度、GPU速度、転送cost、計算とのoverlap可能量を推定し、CPU常駐tensorの一部を一時的にGPUへ昇格させる。CPUが混雑すればGPU計算を増やし、GPUやPCIeが律速なら転送を抑える。

### 非同期CPU-GPU協調
GPUには永続常駐領域と再利用可能な一時bufferを設け、CPU側はmapped pinned memoryに重みを置く。compute streamはoperatorとactivation転送、transfer streamはweight転送を担当する。小さいactivation転送はGPU SM上のcopy kernel、大きいweight転送はCUDA copy engineへ分け、consumer GPUでcopy engineが1基しかない場合のhead-of-line blockingを避ける。

## 評価条件
- Laptop: Intel i7-11800H、RTX 3060 6GB、32GB DDR4、PCIe Gen4 x16
- Desktop: Intel i7-11700、RTX 4090 24GB、64GB DDR4、PCIe Gen4 x16
- Laptop models: GLM-Z1-9B、Qwen3-14B、Qwen3-30B-A3B、GPT-OSS-20B
- Desktop models: Llama 3.1-70B、Qwen3-Next-80B-A3B、Qwen3.5-122B-A10B、GPT-OSS-120B
- GLM-Z1-9BはFP16、GPT-OSSはnative MXFP4、その他はINT4
- 主比較には同じGPU memory budgetのllama.cpp等を使用

## 主要結果
論文はllama.cppとの比較でprefill throughputを最大1.94倍、decode throughputを最大3.29倍改善し、decode中の平均GPU SM利用率を約70%高めたと報告する。負荷変動試験では、外部CPU負荷時に静的方針より性能低下を13%抑え、GPU+PCIe contentionでは38%抑えた。これらは最大値・特定条件の結果であり、全modelで一律に得られる倍率ではない。

## 限界
- 事前profilingを前提とし、hardware・kernel・modelが変われば配置価値も変わる。
- 効果はCPU性能、RAM帯域、PCIe帯域、VRAM量に強く依存する。
- Laptopではthermal/power制約で長時間decodeの安定性が低いことを著者ら自身が指摘する。
- 約15,000行のllama.cpp拡張として実装されたが、一次資料から公開code repositoryは確認できず、現時点では第三者再現性が限定される。
- 高並列datacenter servingではなく、低concurrencyのlocal interactive inferenceを主対象とする。

## 既存研究との差
llama.cppなどのlayer単位、MoE hybrid runtimeのexpert単位より細かいtensor単位でGPU residencyを決める。PowerInferやKTransformers系がmodel構造・activation patternを利用するのに対し、ATSInferは個々のtensorの実測CPU/GPU性能と実行中のdevice loadを直接配置・転送判断へ使う。

## 一般的な実装への示唆
VRAM不足時のCPU offloadでは「何GBをGPUへ置くか」だけでなく、同じ容量でCPU実行時間を最も減らせるtensorを選ぶ方が合理的である。またconsumer GPUではweight transferとactivation transferを同じcopy engine queueへ単純に流すと短い転送が長い転送に塞がれるため、SM copyとcopy engineを役割分担する設計が有効になり得る。
