# SHIELD: A Segmented Hierarchical Memory Architecture for Energy-Efficient LLM Inference on Edge NPUs

> エッジNPUではオンチップSRAMが小さく、注意機構の一時活性値まで高密度eDRAMへ置くと、データを保持するための周期リフレッシュがメモリエネルギーを消費する。SHIELDはBF16の1ビット符号と8ビット指数を通常リフレッシュ領域へ固定する一方、誤りに比較的強い7ビット仮数をデータ寿命で分離する。長く残るKV仮数はリフレッシュ周期を1216µsまで緩め、各層内で1.5ms未満しか生存しないQと注意出力の仮数はリフレッシュ自体を止める。故障注入とeDRAMセルモデルを組み合わせ、標準リフレッシュ比で35%のリフレッシュエネルギー削減を報告する。
## 書誌情報
- **著者**: Jintao Zhang, Xuanyao Fong
- **公開**: arXiv:2604.07396v2; AICAS 2026採択
- **種別**: 国際会議採択論文 / arXiv
- **対象**: エッジNPU、eDRAM、リフレッシュ制御、活性値メモリ、KVキャッシュ、BF16、省電力、ハードウェア・ソフトウェア協調設計
- **実装**: 3T-eDRAMセルの保持誤りモデル、DESTINYによる2MBメモリ評価、PyTorch系の層フックを用いたBF16故障注入で検証するアーキテクチャ提案。実際のエッジNPUへSHIELDメモリコントローラを実装したシリコン評価ではない。
## 問題設定
エッジNPUでは中間活性値を置けるオンチップSRAMが1〜8MB程度に限られる一方、Qwen3-8BのQと注意出力だけでも一時作業領域が約32MB必要になる例があり、高密度eDRAMを活性値領域として使う動機がある。しかしeDRAMは電荷を保持するため周期的なリフレッシュを必要とし、そのエネルギーが無視できない。従来研究はKVキャッシュのように長く残る状態のリフレッシュ削減や、オフチップ転送削減を主に扱うが、Qと注意出力は各層の内部だけで短時間使われて捨てられるにもかかわらず同じ保持保証を受けやすい。さらにBF16では符号・指数の誤りが値を大きく壊す一方、仮数の下位誤りは比較的影響が小さいため、テンソル寿命だけで一律にリフレッシュを弱めると品質を壊し、全ビットを守ると省電力余地を失う。
## 新規性
SHIELDは活性値を『何のテンソルか』と『BF16のどのビットか』の二軸で分割し、異なるeDRAM領域へ配置する。1ビット符号と8ビット指数は数値影響が大きいため通常周期で保持する。7ビット仮数は、生成中ずっと残るKVなら誤り率10^-4以下を保つ1216µsの緩和リフレッシュを使い、各層内で1.5ms未満しか残らないQと注意出力ならリフレッシュを完全に止める。つまり全活性値へ一つの保持時間を適用するのではなく、数値感度と実際の生存期間から必要な保持強度を選ぶことで、計算や転送量を変えずにメモリ保持エネルギーを削る。
## 手法
### 手法のあらまし
まずSHIELDはLLM推論時の活性値寿命を測る。Qと注意出力は現在のTransformer層の注意計算が終われば不要になるのに対し、KとVは後続トークン生成で参照するため文脈全体にわたって残る。H100上で複数モデルを測定するとQO活性値の有効寿命は1.5ms以内だった。この時間差を使えば、短命データには通常の長期保持保証が不要になる。

次にBF16を符号1ビット、指数8ビット、仮数7ビットへ分けて故障注入する。全ビットへ一様に誤りを入れると誤り率10^-6を超えた付近からパープレキシティが急速に悪化するため、符号・指数まで弱く保持するのは危険である。一方、QOの仮数だけなら非常に高い故障注入率でも品質劣化が小さく、KV仮数はQOより厳しいが10^-4程度まで安定する。この違いから、数値の上位9ビットは通常領域、仮数7ビットは寿命別領域へ物理的に分離する。

メモリは三種類のバンクで構成する。標準リフレッシュバンクは符号と指数を45µs周期で保持する。緩和リフレッシュバンクには長寿命のKV仮数を置き、3T-eDRAMセルモデルで誤り率10^-4以下となる1216µsを周期とする。リフレッシュなしバンクには短命QO仮数を置き、使用中に自然保持できると見なして周期リフレッシュを行わない。メモリコントローラはテンソル種別とBF16ビット位置に応じて書込み先バンクを決める。

この方式は演算結果を別形式へ圧縮するのではなく、同じBF16値のビット群を異なる保持特性の物理領域へ分割する。省電力効果はQOとKVが活性値領域を占める比率によって変わる。プリフィルやデコード初期のように短命QOの割合が大きい時はリフレッシュ停止領域の比率が増えて利得が大きく、生成が進みKVが増えると1216µs周期の緩和領域が中心になる。それでも通常45µsより大幅に長い周期なので省電力を維持する。

### BF16の重要度別セグメント配置
入力となるBF16活性値を、数値を大きく左右する符号・指数9ビットと、比較的誤りに強い仮数7ビットへ分ける。故障注入では全ビットへ一様に誤りを入れると低い誤り率でもパープレキシティが崩れるため、符号と指数はQO・KVの区別なく標準リフレッシュ領域へ置く。仮数だけを寿命に応じて別バンクへ送り、QO仮数とKV仮数へ異なる保持強度を適用する。これにより『短命だから全ビットを弱くする』危険を避けながら、誤り耐性のある部分だけで省電力余地を使う。物理的なビット分割と再結合に追加配線・データ移動が必要になる点は実装コストとして残る。

### QO仮数のリフレッシュ停止
Qと注意出力は各Transformer層の内部で消費された後に破棄されるため、KVのように後続トークンまで保持する必要がない。実測では評価モデル群のQO有効寿命が1.5ms未満で、仮数への故障注入も高い誤り率まで品質に強い。この二つを根拠に、QO仮数を専用eDRAMバンクへ置いて周期リフレッシュを完全に無効化する。保持中に多少の電荷劣化が起きても、データが捨てられるまでの時間と仮数の誤り耐性に収まるという設計である。ただし実際のエッジNPUで層処理時間が1.5msを大きく超える場合は、同じ無リフレッシュ設定を安全とみなせない。

### KV仮数の緩和リフレッシュ
KとVは自己回帰生成中に長期間残るため、QOと同様にリフレッシュを完全停止すると誤りが累積して長文生成を壊す。そこで3T-eDRAMセルの保持時間とビット誤り率のモデルを使い、KV仮数で許容する誤り率10^-4を超えない境界を求める。その結果、通常の45µsに対して1216µsまで周期を延ばせるとし、KV仮数専用バンクだけこの緩和周期で更新する。リフレッシュ回数を約27分の1へ下げながら、符号・指数は標準周期のまま守るため、長寿命データの品質と省電力を両立する。セル特性や温度がモデルと異なる実チップでは安全周期の再評価が必要になる。

### 全体のデータ／制御の流れ
SHIELDのメモリコントローラは活性値生成時にテンソル種別をQOかKVか判定し、さらにBF16の符号・指数と仮数を分離する。符号・指数は標準バンクへ、KV仮数は緩和バンクへ、QO仮数は無リフレッシュバンクへ書く。読み出す際は対応するビット群を合わせて通常のBF16値として演算器へ渡す。演算スケジュールや注意アルゴリズム自体は変更せず、活性値の寿命と数値感度をメモリ保持ポリシーへ写す構成である。評価は実NPU実装ではなく、GPU上で得た活性値寿命、故障注入による許容誤り率、3T-eDRAM保持モデル、DESTINYのメモリ電力値を組み合わせて安全性とエネルギーを推定する。
## 評価条件
- **ハードウェア**: NVIDIA H100によるQO寿命プロファイル、3T-eDRAMセルモデル、2MB活性値領域を想定したDESTINYメモリモデル
- **ソフトウェア**: BF16活性値への層単位故障注入、WikiText-2、PIQA、ARC-Easy評価、DESTINY
- **モデル**: Qwen3-1.7B、Qwen3-4B、Qwen3-8B、Mistral-7B、Llama-3-8B
- **データセット／トレース**: WikiText-2、PIQA、ARC-Easy、文脈長2048のストーリー生成による寿命測定
- **比較対象**: 全領域45µs標準リフレッシュeDRAM、KVだけを緩和するKelle型方針、2MB SRAMとの漏れ電力比較
- **正確性・品質**: 品質評価は実メモリ上の自然故障ではなく、BF16の対象ビットへ確率的な故障を注入して行う。Qwen3、Mistral、Llamaの複数モデルでWikiText-2パープレキシティとPIQA、ARC-Easy精度を測り、SHIELD設定が無故障基準からほぼ変化しないことを確認する。
- **活性値寿命測定**: 文脈長2048のストーリー生成をH100上で実行し、Qwen、Mistral、Llama系1B〜9B級モデルの層処理時間からQと注意出力が必要な時間を測る。全評価モデルでQO寿命が1.5ms以内に収まることを無リフレッシュ領域の根拠とする。
- **BF16故障注入**: QOまたはKVへ層フックを入れ、指定誤り率でBF16ビットを反転する。全ビット一様、QO仮数のみ、KV仮数のみを分け、無故障時からパープレキシティが3%以上悪化する境界などを使って数値感度を評価する。
- **eDRAM保持モデル**: 3T-eDRAMの保持時間とビット誤り率をモデル化し、標準周期45µsに対してKV仮数の許容誤り率10^-4を守る1216µsを緩和周期として採用する。QO仮数は1.5msの有効寿命内で想定誤り率が0.04%程度に留まるとして周期更新を行わない。
- **推論場面別エネルギー**: プリフィル中心、プリフィル・デコード均衡、長デコード中心の三場面に加え、プリフィル128段・デコード256段の生成トレースを用い、QOとKVの占有比が変化した時の標準eDRAM、Kelle型、SHIELDの正規化効率を比較する。
実行時間の観測、ビット誤り耐性、セル保持モデル、電力モデルを段階的に組み合わせる評価である。まずQOの短寿命をGPUで測り、次にBF16のどのビットとテンソルが誤りに耐えるかを故障注入で測る。その安全境界から各eDRAMバンクのリフレッシュ周期を決め、最後にDESTINYと解析式でメモリエネルギーを算出する。したがって実チップの消費電力測定ではなく、モデルとプロファイルに基づく設計評価として解釈する必要がある。
対象はエッジNPU向けオンチップeDRAM活性値メモリのリフレッシュエネルギーであり、NPU全体のエンドツーエンド消費電力、推論速度、オフチップDRAM・SSD転送は評価していない。実NPUシリコンではなくモデル評価なので、温度、製造ばらつき、ECC、バンク切替・ビット再結合回路の実装費は今後の検証事項である。
## 主要結果
SHIELDは標準45µs周期で全活性値を更新するeDRAMに対し、BF16の符号・指数を通常保護しながらQO仮数の更新を止め、KV仮数だけ1216µsへ緩和することで、リフレッシュエネルギーを約35%削減する。プリフィル中心、均衡、長デコード中心の三場面でも正規化効率はおよそ1.35倍で安定する。WikiText-2、PIQA、ARC-Easyの複数モデル評価では無故障基準との差がほぼゼロである。ただし数値は実NPU電力測定ではなく、GPU寿命プロファイル、故障注入、3T-eDRAM保持モデルと解析式を組み合わせた評価である。

- eDRAMリフレッシュエネルギー / 標準リフレッシュ比35%削減 (比較対象: 全領域を45µs周期で更新する標準eDRAM; 条件: 符号・指数は標準周期、KV仮数1216µs、QO仮数はリフレッシュなし) — BF16の全ビットを同じ保持強度で守らず、短命かつ誤りに強い仮数領域だけ更新頻度を下げることで、演算量を変えず保持エネルギーを削る。

- QO活性値寿命 / 全評価モデルで1.5ms未満 (比較対象: 通常の長期保持を前提とするeDRAM運用; 条件: H100、文脈長2048、Qwen/Mistral/Llama系1B〜9B級モデル) — Qと注意出力は層内だけで消費されるため、KVと同じ長期保持を保証する必要がないことを実行時間から裏付ける。

- KV仮数の安全な緩和周期 / 1216µsでビット誤り率10^-4境界 (比較対象: 標準45µs周期; 条件: 3T-eDRAM保持モデルとKV仮数故障注入) — KVは長寿命なので更新を完全停止せず、品質に必要な誤り率を守る範囲で約27倍長い周期へ延ばす。

- 2MBメモリの漏れ電力 / SRAM 452.25mW、eDRAMデータ配列0.95mW (比較対象: 2MB SRAM; 条件: DESTINYによる高密度活性値領域比較) — リフレッシュ費を考慮しても、容量の大きい活性値領域をSRAMだけで構成するよりeDRAMを使う動機がある。

- 場面別正規化効率 / SHIELDは約1.35倍を三場面で維持 (比較対象: 標準eDRAM; 条件: プリフィル中心、均衡、長デコード中心) — QO比率が大きい時は無リフレッシュ領域、KV比率が増えた後は緩和周期領域が効くため、推論段階が変わっても省電力効果が残る。

- 品質変化 / WikiText-2、PIQA、ARC-Easyで無故障基準との差は概ねゼロ (比較対象: 故障なし; 条件: Qwen3-1.7B/4B/8B、Mistral-7B、Llama-3-8B) — 重要な符号・指数を通常保護し、仮数だけ許容範囲で保持を弱める分割が、評価した誤りモデルでは品質を維持する。

### 負の結果・境界条件
- **実NPUのエンドツーエンド電力ではない**: 35%はeDRAMリフレッシュ部分に対する削減であり、NPU全体の演算、データ移動、制御回路を含む総エネルギーを35%削減する意味ではない。
- **実シリコン未評価**: リフレッシュ周期は3T-eDRAMセルモデルと故障注入から決めており、温度、製造ばらつき、経年変化、ECCを含む実チップで同じ1216µsが安全かは未確認である。
- **ビット分割回路の費用が十分に含まれない**: 符号・指数と仮数を異なるバンクへ物理配置し、読み出し時に再構成する必要がある。論文も浮動小数点実行器と分割メモリ階層のより緊密な共同設計を今後の課題として挙げ、ビット移動費の削減余地を残す。
- **寿命が伸びる実装では無更新前提が崩れる**: QO無リフレッシュは評価環境で1.5ms以内という寿命測定に依存する。より低速なエッジNPU、混雑、異なるスケジュールで活性値保持時間が伸びれば、安全な保持方針を再計算する必要がある。

### 結果の読み方
SHIELDの利得は通常のメモリ階層のようにデータを別媒体へ逃がすのではなく、同じeDRAM内部で『どれだけ長く正確に保持する必要があるか』を細分化することから生じる。符号・指数は少数ビットでも誤り影響が大きいため保護を維持し、仮数だけを寿命別に緩和することで品質と省電力の両方を狙う。QOが多い初期段階では更新停止が効き、KVが増える後半でも長周期更新が効くため、段階間で効果が極端に失われにくい。
## 品質への影響
評価したBF16故障モデルでは、WikiText-2パープレキシティとPIQA・ARC-Easy精度の差はほぼゼロに保たれる。ただし確率的故障を許容するメモリ方式なので数学的な無損失ではなく、実デバイスの保持誤り分布が想定から外れれば品質リスクが生じる。
## 既存研究との差
- Kelleは長寿命KVキャッシュのeDRAMリフレッシュを緩和するが、各層で短時間だけ存在するQと注意出力の大きな活性値領域は通常保護のまま残る。SHIELDはQO仮数を独立領域へ置き、寿命が保持時間より短いことを利用してリフレッシュ自体を止める。
- FlashAttentionやLEAPはタイル化やデータフローでオフチップ入出力を減らす研究であり、eDRAMセルの周期更新エネルギーは主対象ではない。SHIELDは注意演算の量を変えず、オンチップ活性値を保持する電力だけをテンソル寿命・ビット感度に応じて削減する。
- 一般的な階層メモリ研究がGPU、CPU、SSDなど保存媒体を変えるのに対し、SHIELDの『階層』は同じeDRAM内部の保持保証の違いである。標準、緩和、無リフレッシュの三バンクにBF16ビット群を分けるため、容量オフロードではなく保持品質の階層化と見る方が正確である。
- 近似KV圧縮は保存値の精度を意図的に下げて容量や帯域を削る。SHIELDはKV仮数で自然保持誤りを一定範囲まで許容するが、容量削減を目的とせず、符号・指数を標準保護したままリフレッシュ回数を減らしてメモリエネルギーを削る。
## 限界
- 実NPUシリコンへ実装した評価ではなく、H100での活性値寿命測定、BF16故障注入、3T-eDRAMセルモデル、DESTINYを組み合わせた設計評価である。
- 報告する35%削減はeDRAMリフレッシュエネルギーに対する値であり、NPU全体の推論エネルギーやシステム電力を同率で減らすとは限らない。
- QO無リフレッシュは評価したモデルで寿命1.5ms未満という前提に依存する。低速NPUや異なるスケジュール、より大きなテンソルで保持時間が伸びれば再検証が必要になる。
- 3T-eDRAMの保持時間は温度、工程ばらつき、電圧、経年変化に左右される。固定1216µs周期が量産デバイスの最悪条件でも誤り率10^-4を守る保証は示していない。
- BF16のビット群を異なるバンクへ分けることで、書込み・読出し時の配線、ビット並べ替え、制御回路が増える。論文の解析エネルギーはこれらの完全な実装費を詳細には含まない。
- WikiText-2、PIQA、ARC-Easyで品質を確認しているが、長い自由生成、コード生成、数値推論など誤り伝播特性が異なるタスクへの一般化は追加検証が必要である。
## 実装状態
AICAS 2026採択のアーキテクチャ研究。Qwen、Mistral、Llama系の活性値寿命をH100で測定し、層フックによるBF16故障注入と3T-eDRAM保持モデル、DESTINYを用いて設計を評価する。SHIELD対応の実エッジNPUシリコンや専用公開コードリポジトリは確認できない。
## 研究上の位置づけ
エッジ・オンデバイスLLMシステム系統のメモリエネルギー研究に位置づけるのが適切である。GPU・CPU・SSD間の容量階層やKV転送最適化ではなく、オンチップeDRAMのリフレッシュを活性値寿命とBF16ビット感度に合わせて変える回路・アーキテクチャ提案である。既存論文との重要な差は、永続KVだけでなく短命QO活性値も対象にし、QO仮数では更新そのものを不要にした点にある。SSD活用との直接関係は薄いが、『データの寿命と誤り耐性に応じて保存保証を変える』考え方は、将来の多階層推論で短命活性値を高性能階層へ残し、長寿命状態だけを低速・高密度階層へ置く判断軸として転用できる。
## 監査メモ
arXiv:2604.07396v2の5ページ全文を確認した。35%はシステム総電力ではなくeDRAMリフレッシュエネルギー削減として記録し、QO寿命1.5ms未満、KV仮数の1216µs緩和周期、標準45µs、2MB SRAM 452.25mW対eDRAM配列0.95mW、複数モデルの品質差ほぼゼロを条件付きで整理した。実NPUシリコン測定ではない点も明示した。
