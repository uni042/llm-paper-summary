# AceSpec: An Asymmetric Edge-Cloud Collaborative Framework for Communication-Efficient LLM Inference

> edgeの小型modelが投機的に状態を先回りしてcacheし、reject時のedge-cloud全体rollbackをlocal lookupへ置き換えつつ非対称通信でWAN転送量を抑える。

## 書誌

- **著者**: Yida Zhang, Zhiyong Gao, Shuaibing Yue, Jie Li, Rui Wang
- **公開**: arXiv:2609.02514v1, 2026-09-02

## 問題

edge-cloud speculative decodingではedge側の小型modelがdraftしcloud側が検証できるが、WANが遅く変動する環境ではdraft rejectのたびにpipelineが止まり、rollbackの通信が協調推論の利得を消しやすい。

## 手法

AceSpecはedge側の余剰計算を使って将来状態の確率的cacheを先に構築する。rejectが起きてもnetwork-wide pipeline flushを繰り返さず、可能な状態をlocal memoryから引くことで復旧をO(1) lookupへ近づける。

通信は対称に全状態を交換せず、uplinkではmain-chain indexを最小限送り、downlinkではsparse distributionを圧縮して返す。さらにWAN条件と計算資源を入力にしたLagrangian optimizationで、local state-cache hit rateが高くなるようresource allocationを変える。

## 主要結果

評価では最大 **3.52× throughput向上**を報告し、**50 Kbps**まで帯域を絞ったWANでもpeakに近い推論性能を維持したとしている。

## 既存研究との差

一般的なsplit inferenceのactivation転送や、単純なedge draft / cloud verificationと異なり、reject後の復旧状態そのものをedgeへ先回りcacheする。主目的はdraft精度だけでなく、volatile WANでrollback communicationを発生させにくくすることにある。

## 限界

- edge側に余剰computeとstate cache用memoryが必要になる。
- WAN遅延・帯域やdraft acceptance特性が変わるとresource allocationの最適点も変化する。

## 一般的な実装含意

edge-cloud inferenceでは平均通信量だけでなく、speculation failure時に何往復必要かがtail latencyを支配し得る。失敗時の状態をlocalに準備する設計は、不安定なWANで投機実行を成立させる有力な方向である。
