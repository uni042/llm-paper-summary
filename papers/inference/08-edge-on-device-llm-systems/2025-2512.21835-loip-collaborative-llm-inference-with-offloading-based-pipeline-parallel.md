# LOIP：重み退避と交互配置パイプラインによる異種エッジ端末の非圧縮LLM推論

## 概要

LOIPは、端末ごとのメモリ容量・演算性能が異なる複数のNVIDIA Jetsonを連携させ、モデルのパラメータを量子化・枝刈りせずに推論するための実行基盤である。対象は、70B級モデルの重み全体を単一端末の共有メモリに収容できず、一部をSSDに置かざるを得ない環境である。単純な層分割と重み退避を組み合わせると、各トークンの生成中にSSDから重みを読み込む時間が空白時間となり、計算器や通信路が待たされる。LOIPは層を複数の交互配置段階へ分散し、ある段階の計算中に次段階の重みを読み込ませる。さらに、層配置の費用モデル、共有メモリ構成に合わせた読込経路、生成が進むにつれて増えるKVキャッシュの再配置を一体化する。

著者らはJetson Xavier NX 16GB、AGX Orin 32GB、AGX Orin 64GBを混在させた実機で、LLaMA2-13B、Qwen3-32B、LLaMA3.3-70B-Instructを評価した。論文v3の総括では比較対象に対して単一入力で最大8.8倍、並行入力で最大20.3倍の復号高速化を報告する。これはモデルの推論精度を改善したという主張ではなく、元の重みを変えない条件での**生成トークン当たり遅延**の測定である。比較対象の一部はメモリ不足で実行不能、または実用上の時間閾値を超えるため、単純なGPU単体の高速化率とは解釈できない。

## 問題設定と設計上の制約

LLaMA3.3-70B-Instructの重みには少なくとも約130GBが必要だと論文は述べる。一方、Jetson Xavier NXの共有メモリは16GBしかなく、GPU専用メモリとは別に巨大なCPUメモリを確保するクラウド向け退避方式は前提にできない。CPUとGPUが同じ物理メモリ容量を奪い合う統合メモリアーキテクチャ（Unified Memory Architecture; UMA）では、常駐重み、SSD読込用バッファ、実行時活性、成長するKVキャッシュを同じ予算で管理する必要がある。単に層を均等配分すると、遅い端末が律速になるうえ、メモリ不足時には頻繁なSSDアクセスが必要になる。

端末間の通信帯域も100〜200Mbps級に制限される場合がある。テンソル並列（Tensor Parallelism; TP）では層内部で頻繁な同期と通信が必要になるため、エッジネットワークでは不利になりやすい。一方、通常のパイプライン並列（Pipeline Parallelism; PP）でも、重みを段階ごとに入れ替えると読込待ちが発生する。さらに自己回帰生成の進行でKVキャッシュが増え、開始時に実行可能だった層配置が途中からメモリ制約を破る。この3つ、すなわち重み読込待ち、端末間通信、KV増加を同時に扱うことが論文の問題設定である。

LOIPの「非圧縮・損失なし」は**元のモデルパラメータの数値表現を変更しない**という意味であり、実行中の演算順序・並列スケジュールが通常実行とビット単位で完全一致することや、通信障害下での正確性を証明した意味ではない。品質ベンチマークによる再評価は主眼ではなく、主な測定対象は復号時間である。

## 手法

### 1. 退避対応の交互配置パイプライン

各端末 $i$ に割り当てるデコーダ層集合を $\mathcal{L}_i$、そのうちSSDから読み込む層を $\tilde{\mathcal{L}}_i$ とする。LOIPは端末の担当層を複数の段階（stage）へ均等に分け、各段階に常駐層と退避層を混ぜる。現在段階で退避層を使用し終えたら、同じ読込バッファを次段階の重みに再利用する。次段階のSSD読込は、現在段階の常駐層の計算、別端末の計算、隣接端末との中間状態通信と重ねられる。従来の「層をまとめて実行→退避→次の層を読み込む」処理では露出する読込待ちを、別作業の裏に隠すのが主要な仕組みである。

段階数を増やすほど重み読込を隠せる機会は増えるが、段階境界を跨ぐ中間状態の通信も増える。論文はこの交換条件を無視して段階数を最大化せず、後述の費用モデルで選択する。さらに各段階は少なくとも1層を含み、モデル本来の層順序を保存する。したがって、任意の順番で層を飛ばしたり、計算内容を近似したりする方式ではない。

### 2. 計算・通信・読込待ちを結ぶ費用モデル

LOIPは、各端末で実測した層計算時間 $comp(\cdot)$、SSDからの重み読込時間 $load(\cdot)$、ネットワーク帯域 $bw_{net}$、段階数 $s$、層間で送る隠れ状態のサイズ $h_{size}$ を入力にする。1トークンの時間を、総計算時間 $T_{comp}$、段階境界の通信時間 $T_{comm}$、他作業と重ならずに露出する読込待ち $T_{uncover}$ に分解する。通信項は論文のモデルでは $s|\mathcal D|h_{size}/bw_{net}$ となり、段階数に比例する。

重みメモリ制約には、端末に常駐する層のサイズ、1段階で同時に必要な退避層の最大読込バッファ、生成長 $n$ に応じたKVキャッシュ量 $M_i^{KV}(n)$ を同時に含める。これによって「割り当てられた重み総量がメモリ以下」という誤った制約ではなく、退避を前提にしても実行時のピーク容量を超えない配置を求める。論文は式を整理して、$b_i$ を端末 $i$ の退避層の読込時間と計算時間の合計とすると、$T_{total}=\max\{T_{comp}+T_{comm},\max_i b_i\}$ で評価できるとする。この最大値の第2項が、重み退避を多く引き受けた端末が全体の律速になる現象を表す。

このモデルには同コストのデコーダ層を仮定する近似がある。モデル内で層ごとの実行時間が大きく違う場合や、SSDの競合・温度制約で測定時の読込時間が変わる場合は、予測値の再検証が必要になる。また初期の層配置はKVキャッシュ占有をゼロとして解き、実行中の成長は別のオンライン機構へ委ねる。

### 3. 動的計画法とブロック単位の層配置

配置器は段階数 $s$ を列挙し、各端末に $k$ 層を与えた場合に最低何層を退避する必要があるか $q_i(k)$ を求める。制約は、常駐層 $k-q$ と各段階で最大 $\lceil q/s\rceil$ 層を読み込むバッファの合計が端末の予算に収まることである。例えば4層分のメモリしかない端末にも、2段階に分けて2層を常駐・4層を逐次読込とすれば6層を担当させられる。この例は「6層が同時に常駐する」という意味ではない。

次に退避層の読込・計算費用の候補値 $\tau$ を列挙し、各端末の $b_i(k)\le\tau$ を満たす範囲で、先頭 $l$ 層を先頭 $i$ 台へ割り当てる最小計算時間 $F_\tau(l,i)$ を動的計画法（Dynamic Programming; DP）で計算する。全層が割り当てられた解について $\max\{T_{comp}+T_{comm},\tau\}$ を比較し、層数の復元表から配置を得る。これにより、端末ごとの異種性能を考慮しつつ、全配置を単純総当たりするより小さい探索で層数と段階数を選べる。

層単位の解の後、空きメモリが1層分に満たなくても、全結合網（MLP）または多頭注意（MHA）のブロックだけなら常駐できる場合を探索する。退避負担 $b_i$ が最大の端末から、MLPブロックを優先して常駐させ、入らなければMHAブロックを試す。これでSSDから読み込むバイト数を減らし、メモリを余らせない。各変更後に読込バッファの最大サイズも再計算し、費用モデル上の遅延が増えないことを確認する。80層のLLaMA3.3-70B、4端末の例では、配置器は2秒以内に完了したと報告する。ただし配置探索の費用を全トークンに払うわけではなく、主に開始時の配置決定に使う。

### 4. UMAを利用した重みの直接読込

通常の退避経路は、SSDからCPU側へバイト列を読み込み、重みテンソルを構築し、GPU向けの別領域へ転送してから行列積を行う。LOIPは初期化時に最大の重みスライスを収容できる固定アドレスのページ固定ホストバッファを1つ作り、GPUから参照できるよう写像する。非同期入出力機構 `io_uring` でSSDからこのバッファへ直接スライスを読み込み、スライスごとに一度だけ構築した軽量な代理モジュールを再利用する。

代理モジュールは重みテンソルの別コピーを持たず、元の演算設定とバッファ内のバイトオフセットを保持する。専用CUDA演算子が固定バッファのGPU可視アドレスを取得し、cuBLASの行列積へ重みポインタを渡す。こうしてCPU側で毎回テンソルを再構築する費用と、別のGPU重み領域へ重複コピーする費用を抑える。計算ストリームにCUDAイベントを記録し、現スライスの利用終了を確認してからバックグラウンド読込スレッドが同じバッファを書き換えるため、実行中の重みが上書きされないよう同期する。

ここでの利点は、UMAでCPUとGPUが同じ物理メモリを共有するJetsonの構成に依存する。PCIe接続の離散GPUへそのまま同じ実装を移植して同じ速度が出るとは限らない。単一バッファを再利用するため、入出力と計算の重畳はそのバッファを使わない常駐層の計算や他端末の作業に依存する。全スライスが読込を待つ場合は隠せない。

### 5. KVキャッシュ成長へのオンライン適応

生成が進むとKVキャッシュが増え、当初常駐できた重みを退避しなければならない。LOIPは端末 $i$ の残余容量から、生成トークン長の閾値 $TS_i^j$ を計算し、その閾値に到達する直前に追加のMHA/MLPブロックを退避する。追加退避のブロック数 $\alpha,\beta$ を選ぶときは、増えるSSD読込時間を最小化しつつ、解放されるメモリで次のKV増分を収容できることを制約とする。段階ごとに同じバッファを再利用できるため、退避したブロック総量と実際に解放されるピーク容量は単純な一対一ではない。

さらに、空き容量のある別端末へKVキャッシュの一部を一時的に移す。各段階の計算終了後にKVの一部を送り、同じ段階が次に実行される前に受信して復元する。この転送量 $V_i^{trans}$ は送信側・受信側の空き容量と利用可能帯域に基づいて制限される。実効帯域が低下した場合は転送量を速やかに減らして通信待ちを抑え、帯域が上がった場合は次のメモリ閾値が近いときなどに限って増量する。細かな帯域変動で毎回再配置する費用を避けるため、変化幅の閾値 $n_{ts}$ も用いる。

この設計ではKVを削除して情報を失うのではなく、必要な段階の前に取り戻す。ただし転送先の空きメモリが不足した場合や通信遅延が長い場合、転送可能量が減って重みの追加退避が必要になる。従って帯域が低いほど必ず改善する方式ではなく、重み読込とKV転送の費用を合わせて調整する方式である。

### 構成要素除去実験：絶対遅延と寄与

70B、Orin 64GB×2＋Orin 32GB×1＋NX 16GB×1の構成で、LOIPの主要部品を一つずつ外して測定している。表の値は生成トークン当たり遅延で、小さいほど良い。

| 方式 | 単一入力（ms/token） | 並行入力（ms/token） | LOIP比で増える遅延 |
|---|---:|---:|---|
| **LOIP全体** | **1533.9** | **407.1** | 基準 |
| KV転送を無効化 | 1614.2 | 455.6 | 単一＋5.2%、並行＋11.9% |
| 配置器を均等割当に置換 | 1939.8 | 482.2 | 単一＋26.5%、並行＋18.4% |
| UMA読込最適化を無効化 | 2251.7 | 488.4 | 単一＋46.8%、並行＋20.0% |

この除去実験では、単一入力の改善に対するUMA直接読込の寄与が最も大きい。配置器の効果は、遅い端末へ退避層を偏らせず、読込・通信・計算を総合した律速時間を抑える点にある。KV転送の効果は、キャッシュの偏在が重みの追加退避を早める状況で顕在化する。各行は単独の要素を無効化した比較であり、百分率を単純に加算して全体の高速化率を復元できない。

### ネットワークと実行不能条件

50〜250Mbpsをトークン区間ごとに切り替える試験では、並行入力で比較方式に対し3.9〜21.3倍、単一入力で1.7〜8.8倍と報告する。LOIPは転送量を現在の帯域へ追従させるため、固定のKV転送量で通信が詰まる事態を減らす。ただし、帯域低下時はKVを他端末へ移す余地が減り、重み退避を増やすこともある。従って帯域変動への「適応」は通信費用をゼロにするものではない。

厳しいメモリ制約の試験では、比較方式の中にOOMまたはOOTが含まれる。これは重要な結果だが、OOMの方式について無限大の速度比を計算することはできない。論文が報告する有限の速度比は実行できた比較方式に対するものであり、実行可否の改善と、実行できた場合の遅延短縮を分けて読む必要がある。

## 限界・適用条件

1. **対象は非圧縮モデルの分散復号**であり、量子化や低ランク近似と組み合わせた場合の最適性を検証したわけではない。ユーザーがローカル単一GPU上で量子化モデルを動かす場合、SSD読込・端末間通信の構造が異なるため、報告倍率を直接適用できない。
2. **UMAの直接参照に依存**する。Jetsonで有効なページ固定メモリ写像と専用CUDA演算子が、離散GPUや他社アクセラレータでも同等に有効とは限らない。
3. **費用モデルはプロファイル依存**である。端末性能、SSD帯域、ネットワークの競合が計測時から変われば、段階数や配置の選択を再調整する必要がある。初期配置器はKV占有をゼロとして解き、実行中の変化は別機構で対処する。
4. **通信量を増やす段階分割には限界がある**。段階を増やして読込を隠せても、帯域が低ければ段階境界の中間状態転送が律速になる。最適な段階数はハードウェアと入力条件によって変わる。
5. **品質は元の重みの保持によって間接的に論じている**。WikiText-2の固定長入力での生成遅延が主要指標であり、知識・推論・長文脈品質、障害時の再実行、ビット単位再現性を広範囲に検証したものではない。
6. **負荷の範囲が限定される**。単一入力と端末数と同数の並行入力を比較したが、何百要求もの実運用キューや広域インターネットでの不安定な接続に同じ速度比が成立するとは示していない。
7. **公式実装の配布先は確認できない**。論文は実装規模を明示するが、一次論文に公式コードURLはない。再現性の評価ではソース入手可否を別途確認する必要がある。

## 関連研究との差

FlexGenやDeepSpeed-InferenceはCPUメモリを大きな別階層として使う退避を重視するが、LOIPはCPU/GPUで同じ容量を共有するJetsonのメモリ制約と、SSDからの再読込を直接対象にする。EdgeShardは異種端末への層割当を最適化するが、継続的なSSD読込待ちを段階分割で隠す設計とは異なる。TPI-LLMはCPU中心の低資源端末でテンソル並列と重み窓を扱うのに対し、LOIPはGPU上のパイプライン並列を使い、KV増加時の重み・KV配置をオンラインで調整する。

LOIPの主要な独自性は、単に「オフロードする」ことではない。退避層を交互配置する実行順序、読込を隠せる時間を明示した最大値型費用モデル、DPによる端末ごとの層数選択、MHA/MLP単位の残余メモリ活用、UMAでのバッファ再利用、KVの一時移動という複数の操作を、同じメモリ・通信制約の下で結合した点にある。評価ではUMA最適化を除いた単一入力遅延が1533.9から2251.7ms/tokenへ増えることが、その独自性を支える直接の証拠となっている。
