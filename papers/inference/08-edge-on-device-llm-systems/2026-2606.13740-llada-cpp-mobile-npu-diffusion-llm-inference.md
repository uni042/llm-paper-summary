# Efficient On-Device Diffusion LLM Inference with Mobile NPU

> スマートフォンNPU向けに多ブロック投機復号、CPU側の疎な改訂、NPU可視メモリの交換最適化を統合し、LLaDA-8Bを接頭辞KV再利用付きCPU基準比17～42倍高速化する。

## 概要
llada.cppは、ブロック単位の拡散大規模言語モデル（diffusion large language model; dLLM）をスマートフォンのニューラル処理装置（neural processing unit; NPU）へ適合させる推論実行系である。後半ほど有効トークン数が減ってNPUの密行列演算性能を使い切れない問題、未確定トークンの改訂が接頭辞KVキャッシュ再利用を難しくする問題、NPU可視仮想アドレス空間が狭く重み・KV・作業領域の再マッピングと転送が発生する問題を共同で扱う。将来ブロックを投機的に混ぜる多ブロック投機復号、可視化と安定化を分離してCPU側で疎に状態を更新する二経路漸進改訂、計算グラフに基づくNPU可視メモリ配置と二重バッファ転送を組み合わせる。Qualcomm Hexagon NPU向けにllama.cppを12,000行超拡張し、LLaDA-8Bで接頭辞KV再利用付きCPU基準より生成遅延を17～42倍短縮しつつ、4種ベンチマークでCPU経路に近い精度を維持した。

中心的な新規性は、拡散LLMの動的なトークン状態をNPUにそのまま押し込むのではなく、NPUが得意な密計算を維持するため復号順序・改訂経路・メモリ交換を共同設計した点にある。現在ブロック後半の空き計算量へ将来ブロック候補を入れる多ブロック投機復号、トークンを「不可視・可視・安定」の三状態で管理して可視化とKV固定を分離する二経路漸進改訂、計算グラフと実測転送時間からNPU可視領域を配置し二重バッファで交換を隠す実行時機構を一体化する。
## 問題設定
ブロック単位の拡散LLMは、同一ブロック内の複数位置を並列に反復更新できるためモバイルNPUの密なテンソル演算と相性がよい一方、実際の復号進行はNPUが想定する静的・規則的な負荷とは一致しない。ブロック内のトークンが順に確定すると後半の反復ほど未確定位置が減り、同じ前向き計算でも有用な仕事量が小さくなる。さらに現在ブロック内のトークンは後続反復で改訂されるため、その状態を接頭辞KVキャッシュへ早く固定すると品質を損ない、固定しなければ反復ごとに長い文脈を再計算する。実際、単純な接頭辞KV再利用はGSM8Kで39.0から32.5へ精度を落とす。加えてスマートフォンNPUはRPCMEM/DMABUF経由で限定された仮想アドレス領域しか参照できず、重み・KV・作業領域が収まり切らないとマッピングと転送が復号の各反復で発生する。CPU向け最適化や単純なNPUオフロードだけでは、これらの復号依存、品質整合性、アドレス空間制約を同時に解けない。
## 新規性
中心的な新規性は、拡散LLMの動的なトークン状態をNPUにそのまま押し込むのではなく、NPUが得意な密計算を維持するため復号順序・改訂経路・メモリ交換を共同設計した点にある。現在ブロック後半の空き計算量へ将来ブロック候補を入れる多ブロック投機復号、トークンを「不可視・可視・安定」の三状態で管理して可視化とKV固定を分離する二経路漸進改訂、計算グラフと実測転送時間からNPU可視領域を配置し二重バッファで交換を隠す実行時機構を一体化する。
## 手法
### 手法のあらまし
llada.cppはブロック単位の拡散復号を実行しながら、各反復で現在ブロックの未確定トークン数とオフライン計測したNPU段階遅延表を参照する。未確定位置が減っても、将来ブロックの候補を加えて同じNPU遅延段階に留まるなら、その候補を現在の前向き計算へ投機的に混ぜる。これにより後半反復の小さな行列処理を避け、密なNPU計算を維持する。トークンは確信度に応じて不可視から可視、さらに安定へ遷移する。可視トークンは後続位置の文脈として使えるが、安定判定前はKVへ永久固定せず改訂可能に残す。不安定な可視トークンの再評価はCPU側へ疎に送り、NPUが次の密計算を続けている間に更新し、反復境界で結果を統合する。安定トークンについては出力射影・確信度評価・サンプリングも省略する。NPUメモリ側では計算グラフからテンソル寿命と利用順を解析し、重みやKVのような長寿命データと、アクティベーションや一時領域のような短寿命データを分ける。利用可能なNPU可視仮想アドレス容量に収まる長寿命データを常駐させ、収まらないものは演算時間と転送時間のプロファイルを用いて一時転送へ回す。短寿命領域は寿命が重ならないテンソル間で仮想アドレスを再利用する。二つのステージング領域を用意し、NPUが一方を消費している間にCPUが次データの記述子・マッピング・転送をもう一方へ準備する。結果として復号アルゴリズムの動的性とNPUの静的実行制約を分離し、密計算、品質維持、メモリ交換隠蔽を同時に成立させる。

### 多ブロック投機復号
現在ブロックの確定が進んで未確定位置が減ると、通常はNPUへ投入する有効トークン数も減る。llada.cppは確定前線の先にスライド窓を置き、将来ブロックのトークンを下書きとして前向き計算へ混ぜる。将来候補を増やす条件は固定本数ではなく、残存マスク数、メモリ予算、事前計測したNPU段階遅延表から決める。同じ遅延段階の範囲なら余分な候補を入れても総NPU時間がほぼ増えないため、後半の空いた計算能力を有用な将来仕事へ変える。感度分析では残り4トークンで投機を開始する設定が最小遅延となり、早すぎる投機は無駄候補を増やし、遅すぎる投機はNPU空きを残した。

### 二経路漸進改訂
トークンを不可視、可視、安定の三状態で扱い、後続トークンの文脈に使える時点と、接頭辞KVへ永久固定できる時点を分離する。既定では可視化しきい値0.7、安定化しきい値0.9を使う。可視だが未安定のトークンは改訂可能なままにし、NPUの密な前向き処理を止めずにCPU側の疎な更新経路で再評価する。更新結果は反復境界で遅延統合し、安定した位置だけ接頭辞KVへ昇格する。これにより多ブロック投機単独で生じる精度低下を回復する。また安定位置はロジット計算自体を省き、出力射影と後処理の無駄も減らす。

### 交換最適化メモリ実行時
Qualcomm NPUが参照できる仮想アドレス領域に全重み・KV・作業領域が収まらない場合を前提に、計算グラフから利用順・寿命・依存を解析して常駐対象と一時転送対象を選ぶ。重みやKVは原則長寿命、アクティベーションと局所作業領域は短寿命とし、長寿命データまで溢れる場合は演算時間と転送時間の実測値を使って、計算との重なりが大きい対象を一時化する。寿命が重ならない短寿命テンソルは同一仮想アドレス範囲を再利用し、二重バッファのステージング領域で次データのマッピングと転送を先行準備する。256/512トークン境界条件では単純NPU実行が失敗する一方、この仕組みで実行継続できた。

### 全体のデータ／制御の流れ
llama.cppを基盤に、Hexagon SDKでHMX/HVX向けFP16・Q4_0行列積、FlashAttention、RMSNorm等を実装したNPU演算ライブラリと、Android側GGML Hexagonバックエンドを統合する。FastRPCとRPCMEM/DMABUFによりCPUとNPUが同じ物理ページを共有し、ホスト側がブロック復号、KVビュー、トークン状態、CPU改訂、投機位置、出力決定を管理する。
## 評価条件
- **ハードウェア**: OnePlus Ace5 Pro（Snapdragon 8 Elite SM8750、16 GB LPDDR5X、NPU INT8 65.25 TOPS）を主評価に使用。世代差確認としてOnePlus 12（SM8650、45 TOPS）とOnePlus 15（SM8850、89.4 TOPS）も使用。
- **ソフトウェア**: llama.cppを12,000行超拡張したllada.cpp。Qualcomm Hexagon SDK、HMX/HVX、GGML Hexagonバックエンド、FastRPC、RPCMEM/DMABUF。SM8650/SM8750ではNPU版FlashAttention、SM8850では実行時制約からCPU版を使用。
- **データセット／トレース**: GSM8K、BoolQ、ARC-C、HellaSwag
- **比較対象**: CPUで全列を毎反復する通常dLLM、CPU + 接頭辞KVキャッシュ再利用、密Transformer演算のみをNPUへ移すNPU基準、同規模Llama-3-8B自己回帰生成
4データセット各200例から品質評価。遅延は各データセット5例、各実行3回反復し、32/64/128目標生成トークンの壁時計時間を測定する。温度は0。品質はlm-evaluation-harness準拠の正解率。電力はbattery sysfsをサンプリングし、アイドル分を差し引いた積分で要求当たりエネルギーを求める。段階別アブレーション、投機開始しきい値、可視化・安定化しきい値、NPU可視重み予算、長出力のメモリ境界を追加評価。
実機スマートフォン3機種でのオンデバイス評価。Qualcomm Hexagon NPUに実装が特化し、他社NPUへの可搬性は設計上主張されるが実測されない。主なエンドツーエンド・アブレーション・エネルギー結果はSM8750であり、SM8850ではFlashAttentionがCPU実行になる。
## 主要結果
llada.cppは、単なるNPU演算置換ではなく復号とメモリ管理を共同最適化することで、LLaDA-8Bを接頭辞KV再利用付きCPU基準より17～42倍高速化する。SM8750のGSM8K 128トークン分解ではCPU 2996.2秒から最終構成16.1秒まで縮小し、単純NPUオフロードやKV再利用の上に交換最適化、多ブロック投機、段階的安定化が累積的に効く。品質面では多ブロック投機単独の低下を二経路改訂が回復し、4タスクでCPU版LLaDAと概ね同程度を保つ。

- LLaDA-8B生成遅延 / 17～42倍短縮 (比較対象: 接頭辞KVキャッシュ再利用付きCPU基準; 条件: スマートフォン実機、32/64/128トークンを含むエンドツーエンド評価) — NPU向け復号・メモリ共同設計がCPU側KV再利用だけより大幅に速い。

- 128トークンGSM8K遅延 / 16.1秒 (比較対象: CPU 2996.2秒、CPU+prefix KV 607.0秒; 条件: OnePlus Ace5 Pro/SM8750、全主要機構を有効化) — 分解表ではCPU比186.34倍、CPU+prefix比約37.7倍で、抽象化した全体17～42倍という主張の範囲を具体例で裏付ける。

- 4タスク品質 / GSM8K 43.5、BoolQ 80.5、ARC-C 85.0、HellaSwag 49.5 (比較対象: LLaDA CPU 39.0/82.5/84.0/51.0; 条件: 各200例、NPU+MBSD+DPPR) — 高速化が一貫した精度崩壊を伴わず、CPU経路との差は数ポイント以内。

- メモリ境界 / 256/512トークン設定を実行可能 (比較対象: SOMRなしは両設定でfailed、paging-onlyも512でfailed; 条件: SM8750、NPU可視アドレス圧力を高める長出力) — グラフ誘導配置と転送重畳が単なるページ置換より実行可能領域を広げる。

### 負の結果・境界条件
- 128トークン生成では古いSM8650上のllada.cppは同規模Llama自己回帰よりまだ遅く、SM8750/SM8850で初めて上回る。多ブロック投機だけを有効にするとGSM8K 41.5→37.5、BoolQ 82.0→79.5、ARC-C 83.5→82.0、HellaSwag 50.0→46.0へ低下し、品質維持には二経路改訂が必要。交換最適化を有効にしても256目標で224、512目標で401トークン出力となる境界ケースがあり、目標長を完全に満たすことまでは示していない。SM8850ではNPU FlashAttention未対応でCPUを使う。

### 結果の読み方
利得はNPUのピークTOPSだけでは決まらない。古いSoCでは密計算能力が不足して自己回帰Llamaを越えず、新しいSoCではNPU演算が速くなるほどCPU側の状態管理やスケジューリングが露出して相対速度向上が単調でなくなる。段階分解では接頭辞KV再利用とNPU化が大きな基礎利得を作り、その後にSOMRと投機が上積みし、最も大きい追加改善はトークン安定化で得られる。
## 品質への影響
損失なしを数学的に保証する方式ではなく、投機と確信度しきい値を使う近似的実行である。多ブロック投機単独は品質を下げるが、未安定トークンを改訂可能に保つDPPRと疎なCPU側更新により、評価した4タスクではCPU LLaDAに近い精度へ回復する。
## 既存研究との差
Fast-dLLMやdKV-キャッシュなどが拡散復号アルゴリズムや反復間状態再利用を主に最適化するのに対し、llada.cppはスマートフォンNPUの静的な密計算、CPU側改訂、NPU可視仮想アドレスという実機制約まで共同設計する。従来のllama.cpp-npuやHeteroLLMが自己回帰または静的な密グラフ中心なのに対し、ブロック拡散LLM固有の「有効仕事量が反復中に縮む」性質を将来ブロック投機で埋める。リポジトリ内の一般的なエッジLLM実行系に対して、拡散LLMとNPUの組合せを直接扱う補完的な位置にある。
## 限界
Qualcomm Hexagon NPUに実装・評価が集中し、他社モバイルNPUでの実機検証はない。NPU可視アドレス制約やFlashAttention対応はSoC世代依存で、SM8850では一部注意計算をCPUへ戻している。品質維持は4データセット各200例での経験的評価であり、可視化・安定化しきい値が異なるモデルや生成分布でも同様に機能する保証はない。長出力のメモリ境界では実行可能性を改善するが目標トークン数を完全には生成していない。著者公式の公開コードURLは本文から確認できなかった。
## 実装状態
研究試作だが、llama.cppを12,000行超拡張したエンドツーエンド実装を3世代のOnePlus/Qualcomm端末で動作させている。Hexagon DSP共有オブジェクト、HMX/HVX向け演算、GGUF変換、Android GGMLバックエンド、共有メモリと交換実行時まで含む。本文で著者公式コード公開URLは確認できず、再現には実装入手性とHexagon開発環境が制約になる。
## 研究上の位置づけ
オンデバイスLLM推論と拡散LLMシステムの交点に位置する。とくに、CPU/GPU/NPUへ単純に演算を割り当てる研究から一歩進み、復号の意味論を変更してNPUの稼働率を上げ、品質整合性はCPU側の疎な改訂経路で守り、メモリ制約はグラフ誘導交換で隠すというアルゴリズム・実行時共同設計を示す。NPU向け静的グラフ最適化、モバイルメモリ階層、非自己回帰生成を統合した代表例として価値が高い。
