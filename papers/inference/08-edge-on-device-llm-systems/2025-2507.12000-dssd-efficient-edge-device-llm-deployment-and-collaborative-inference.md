# DSSD: Efficient Edge-Device LLM Deployment and Collaborative Inference via Distributed Split Speculative Decoding

> 分散分割投機的復号（Distributed Split Speculative Decoding; DSSD）は、端末の小型言語モデル（Small Language Model; SLM）が候補を生成し、基地局・エッジの大規模言語モデル（Large Language Model; LLM）が検証する協調推論で、検証に必要な計算自体も端末とエッジへ分割する。従来の分散投機的復号（Distributed Speculative Decoding; DSD）が候補ごとの語彙分布を上り送信するのに対し、DSSDは大量の上り通信を50バイト未満級のメッセージと最小限の下り情報へ置き換える。2基H800の同種GPU実験では通常LLM比1.5〜2.4倍の高速化を示し、DSDは同条件で1倍前後またはそれ以下となる。

## 概要

端末だけで大規模LLMを動かすのはメモリ・演算・電力の制約が厳しい。そこで端末へ小さなドラフトモデル、基地局やエッジへ大きなターゲットモデルを置き、投機的復号（speculative decoding）で候補をまとめて検証する方式が考えられる。候補が受理されれば大型モデルの逐次呼び出し回数を減らせる。

しかし分散環境では、ローカルGPU内なら無視できる「検証に必要な確率分布の転送」が大きな通信費用になる。標準DSDでは、ドラフト長γの各候補について語彙サイズ|V|の確率分布を端末から上り送信するため、転送量はγ|V|に比例する。ネットワークが遅いと投機で節約したLLM計算より通信時間が大きくなり、通常推論より遅くなる。

DSSDはこの向きを逆転させる。ターゲット側で検証に必要な分布処理を担い、端末から巨大な語彙分布を送る代わりに、候補トークンなど小さな情報だけを送り、必要なターゲット側情報を下りへまとめる。論文では一回あたり約61,269バイトのDSD上り転送がDSSDでは50バイト未満に減る例を示す。

## 問題設定

投機的復号の局所実行では、総時間は主にドラフト生成時間とターゲット検証時間で決まる。端末・エッジ分散になると、そこへ往復ネットワーク遅延と帯域制約が加わる。

DSDでは一回の通信量がドラフト長γ、語彙サイズ|V|、確率値のビット幅に比例する。語彙分布をFP16/FP32で送れば、候補数を増やすほど通信量も増える。長いドラフトはターゲット呼び出しを減らせるが、ネットワーク上では逆に大きな転送を作る。

さらにドラフトモデルとターゲットモデルの一致率αが低いと、長い候補列を作っても早い位置で棄却される。したがって最適γはモデル対・ネットワーク遅延・帯域の組合せで変わる。

## 手法

### 1. 端末のSLMで候補列を作る

端末側のOPT-125MなどのSLMがγ個の候補トークンを自己回帰生成する。ここは通常の投機的復号と同じで、端末は比較的軽いモデルだけを常駐させる。

入力は現在の接頭辞、出力は候補トークン列と検証に必要な小さな補助情報である。ターゲットLLMを端末へ置かないため、端末メモリ・演算負荷を抑えられる。

### 2. 検証計算を端末とエッジへ分割する

従来DSDでは、端末側ドラフト分布をターゲット側へ送り、各位置の受理判定へ使う。そのためγ個の語彙分布が上り通信へ乗る。

DSSDでは受理計算を代数的に分解し、大きな分布の送信を避ける。ターゲットLLMが持つ側で重い分布処理を行い、端末へ返す情報を必要最小限へすることで、通信量を語彙サイズ依存から大きく切り離す。

### 3. 通信時間を含む解析式でドラフト長を選ぶ

論文は1回の推論時間を、γ回のSLMドラフト、LLM検証、通信、ネットワーク往復時間へ分解する。DSSDでは通信項が、受理率αとドラフト長γに応じて残る最小限の下り転送へ置き換わる。

この解析により、γを長くしすぎたときのSLM計算増加、短すぎたときのネットワーク固定費未償却を同じ式で比較できる。実験でも20 ms/100 Mbpsではγ=4が短すぎる条件があり、最大速度は内部のγで生じる。

### 4. ターゲット品質を維持する検証

DSSDはターゲットモデルの受理/補正規則を変えて近似出力を返す方式ではなく、投機的復号の正しい検証を分散実装する。したがって速度改善のためにターゲット分布からの生成品質を意図的に落とす方式とは異なる。

通信を省くために検証をスキップする既存方式は精度との交換条件を持つが、DSSDは検証手続きを保持しつつ配置を変える。

## 評価

### 評価条件

| 項目 | 設定 |
|---|---|
| ドラフトモデル | OPT-125M |
| ターゲットモデル | OPT-6.7B、OPT-13B |
| 同種GPU | 2×NVIDIA H800。片方を端末相当、片方を基地局相当として使用 |
| 異種GPU | NVIDIA A6000（端末側）＋H800（基地局側） |
| ネットワーク | 往復遅延0/20/50 ms、帯域上限100 Mbps。追加で50/10 Mbps等も評価 |
| 生成 | 共通128トークンプロンプトから128トークン生成 |
| サンプリング | top-k、温度1.0、k=10 |
| 比較 | 通常LLM、DSD、DSSD |
| 主指標 | 通常LLM比スループット高速化、通信時間・通信量 |

### 主な結果

| 条件 | DSD | DSSD | 読み方 |
|---|---:|---:|---|
| 同種H800全体 | 約1倍または1倍未満も存在 | 約1.5〜2.4倍 | 語彙分布通信を消す効果が支配的 |
| 1ラウンド上り転送 | 約61,269 B | 50 B未満 | 通信方向・検証分割が直接効く |
| OPT-125M→6.7B、0 ms/100 Mbps、γ=6 | — | 1.02倍 | ネットワークが理想的でもターゲット計算比で利得は小さい条件がある |
| OPT-125M→13B、0 ms/100 Mbps、γ=6 | — | 1.48倍 | 大きいターゲットほどドラフト費用を相対的に隠しやすい |
| 20 ms/100 Mbps、γ=6 | — | 6.7B: 0.92倍、13B: 1.75倍 | 同じネットワークでもモデル対により損益分岐が変わる |
| 20 ms/50 Mbps、γ=6 | — | 6.7B: 1.38倍、13B: 1.24倍 | 帯域制約で相対関係が逆転する例 |
| 20 ms/100 Mbps、γ=4 | — | 6.7B: 0.82倍、13B: 1.37倍 | 短すぎるドラフトは通信固定費を償却できない |

ここで重要なのは、DSSDでも常に1倍を超えるわけではない点である。A6000→H800の異種構成では、OPT-6.7B・20 ms/100 Mbps・γ=6で0.92倍、γ=4で0.82倍となり通常LLMより遅い。論文の価値は「通信を無視すれば速い」ではなく、通信とモデル計算を一緒にモデル化して有効領域を広げたことにある。

## 既存研究との差

通常の投機的復号はドラフトとターゲットが同一ノードにあり、確率分布の受け渡しをGPUメモリ内処理として扱える。DSDはこれを端末・エッジへ分けるが、語彙分布をネットワークへ載せる。

DSSDはモデル配置だけでなく検証算術も分割し直し、大量上りを小さなメッセージと下りへ変換する。推論品質を犠牲にして検証を省略する方式とは異なり、ターゲット分布と整合する検証を保つ。

## 限界・実装状況

- 利得はネットワーク往復遅延・帯域、ドラフト長、SLM/LLM速度比、受理率に強く依存する。
- 6.7Bターゲットの一部条件では通常LLMより遅い負の結果がある。
- 評価はOPT-125M→OPT-6.7B/13Bを中心としており、現行のより新しいLLM/SLM対への一般化は再測定が必要。
- 端末・基地局間の切断やモビリティによる状態同期、プライバシー、エネルギーは速度式とは別の運用課題である。
- 公式コードは https://github.com/JasonNing96/DSSD-Efficient-Edge-Computing で公開されている。

## 一般的な実装上の含意

端末・エッジ協調では「転送バイト数」だけでなく方向が重要になる。上りが下りより遅い無線網では、大きな中間表現を上りへ置かないよう計算分割そのものを変える価値がある。

投機的復号では受理率だけでドラフト長を決めず、SLM時間、LLM時間、往復遅延、帯域を含む総時間で最適化する必要がある。モデル対が変われば最適γも変わる。
