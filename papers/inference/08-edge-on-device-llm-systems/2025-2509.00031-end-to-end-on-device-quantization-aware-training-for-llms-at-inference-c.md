# ZeroQAT：量子化されたモデルを逆伝播なしで最終損失へ適応させる

## 概要

ZeroQATは、推論時に使う低ビット重み・活性値を、学習時にも実際に量子化した状態で評価し、その結果に基づいて量子化認識学習を行う方法である。従来の学習後量子化では、各層の出力を全精度モデルへ近づけても、ネットワーク全体の言語モデル損失や下流タスクの正答率が必ずしも改善しない。逆に通常の量子化認識学習は、量子化の影響を含めた最終目的を最適化できるものの、逆伝播のために多数の中間活性と勾配を保存しなければならない。ZeroQATはこの二つの欠点の間を狙い、**量子化を含む前向き損失だけ**から更新方向を求める。

主要な工夫は、零次勾配推定、活性値のチャネル別平滑化、非対称重みクリッピングの共同最適化、およびQuery/Value投影のみを高精度で更新する軽量微調整版の四つである。Llama2-7BのW4A4条件ではWikiText2困惑度がOmniQuantの14.26に対して12.95、OnePlus 12のOPT-6.7BではFP16微調整がメモリ不足となる条件で、量子化微調整を6.4GBで実行した。ただし、13Bの全パラメータ量子化事前学習では26.6GBを必要とし、すべての学習が8GBで可能になるわけではない。

## 問題設定：層単位の誤差最小化と最終目的の不一致

低ビット化は重みや活性値を離散的な格子へ丸めるため、外れ値の大きさに量子化スケールを合わせると通常値に割り当てられる有効な段数が減る。SmoothQuantのような手法は、活性値の外れ値を重み側へ移して分布を均す。しかし、固定した平滑化規則が最終的なタスク損失にとって最適とは限らない。OmniQuantは層の量子化後出力を全精度の出力へ近づけるが、前段の量子化誤差が後段へ伝わり、層ごとの再構成目的がモデル全体の困惑度と一致しないことがある。

原著のFigure 1は、層が深くなるにつれて層再構成の改善が小さくなる様子を示す。Figure 2では、再構成損失が減る途中でも困惑度が単調には下がらない。これは、量子化後の最終目的を直接扱う必要性を示すが、同時に通常の逆伝播型QATには大きなメモリ費用がある。量子化の丸めは微分不可能であり、直通推定器で近似勾配を流す従来方式は中間活性や勾配状態の保存を必要とする。ZeroQATは微分を通さず、量子化後の前向き計算の損失差を利用する。

ここで論文の「推論相当のコスト」は主にメモリ常駐量を指す。零次法では一つの摂動方向ごとに正負二回の前向き計算を実行するため、学習更新一回が通常の推論一回と同じ演算量であるわけではない。さらに全パラメータ版では更新対象の全精度重みを保持する。量子化済みの推論専用モデルだけを保持する構成と混同してはならない。

## 手法

### 1. 量子化を含む二点零次勾配推定

学習対象の重みをW、量子化器をQ、バッチをB、摂動方向をu、摂動幅をεとする。各方向でQ(W+εu)とQ(W−εu)を用いた二つの損失を計算し、損失差を2εで割って方向uへ掛ける。複数のランダム方向について平均し、確率的な更新方向を得る。原著の式(2)はこの有限差分推定を定式化し、式(3)で学習率を用いた更新を定義する。前向き評価の内部に丸め処理そのものが含まれるので、量子化演算の微分を仮定しない。

処理順は、摂動方向の生成、正負に摂動した重みの量子化、両方の前向き損失の取得、方向別差分の集約、更新対象パラメータの変更である。出力は量子化されたモデルの最終損失に適応した更新済みパラメータである。利点は逆伝播のための活性値を保持しない点だが、摂動方向の数が増えると前向き回数も増加する。論文の理論的な不偏性は平滑化された目的に対するものであり、離散的な元の損失の厳密な勾配を復元する保証ではない。

### 2. 活性値の平滑化を学習可能な変換にする

線形層Y=XW+Bに対して、入力チャネル別のスケールsとシフトδを導入する。入力側を(X−δ)/sへ変換し、対応する重みをsWへ、バイアスをB+δWへ補正すれば、量子化前の線形写像を維持できる。量子化後は入力と重みの数値分布が変わるため、丸め誤差は同一ではない。ZeroQATはsとδを固定の統計量から決めるのではなく、零次推定を通して最終損失が下がる方向へ調整する。

入力は層の活性値分布と現在の平滑化パラメータ、出力は量子化しやすい範囲へ移された活性値と補償済み重みである。活性値の極端なチャネルだけで量子化範囲が決まる問題を緩和する一方、強く平滑化すると重み側へ外れ値が移る。したがって次のクリッピング機構との同時最適化が重要となる。

### 3. 非対称な重みクリッピングの共同最適化

量子化後の重みを決める刻み幅とゼロ点に加え、切り詰める範囲の上下限を独立の係数で調整する。平滑化で重み分布が偏った場合にも、正負の外れ値を同じ割合で捨てる必要はない。クリッピングの係数も最終損失に基づいて更新され、低ビットの有限段数を主要な重み領域へ割り当てる。入力は平滑化後の重み、出力は非対称範囲で量子化された重みである。

原著の付録Table D.1では、Llama-7BのW4A4において平滑化とクリッピングを両方使う場合の困惑度は12.95、クリッピングを外すと16.64、平滑化を外すと約1.4×10³に悪化する。逆にW2A16のような重みのみの量子化では活性値平滑化の必要性が小さく、重みクリッピングの重要性が増す。二つの機構は同じ誤差を重複して補正するのではなく、活性値と重みの異なる誤差源に対処する。

### 4. Q/V投影に限定する軽量微調整

全パラメータ版は高精度の更新用重みを保持するため、モデル規模が大きくなると端末メモリに収まらない。軽量版はAttentionのQueryとValue投影だけを更新可能な高精度状態で残し、Key投影、出力投影、MLPなど他のパラメータを事前量子化して凍結する。前向き計算では低ビットの凍結部分と更新対象のQ/Vを組み合わせ、零次法でQ/Vの更新方向だけを求める。

全重みを先に低ビット格子へ固定してから小さな摂動を加えると、丸めによって摂動が消える場合がある。大きな摂動にすると学習が不安定になる。Q/Vだけを高精度で残す設計は、この丸め消失を避けつつメモリを減らす折衷案である。付録Table D.4では、全層更新に近い下流精度を保ちながら、軽量版のメモリ比率はW2A16で27%、W4A4で38%と報告する。これは全タスク・全ビット幅での普遍的な比率ではない。

## 評価条件と結果

### 評価の対象と測定単位

サーバー実験にはNVIDIA A100を、端末実験にはSnapdragon 8 Gen 3と16GB RAMを搭載するOnePlus 12を用いる。モデルはLlama1/2の7B・13B、OPTの1.3B・2.7B・6.7B・13Bであり、各表で対象モデルが異なる。量子化条件はW2A16、W4A4、W6A6を区別し、W2A16の一部にはgroup size 128を使う。WikiText2、C4、Penn Treebankの困惑度は小さいほど良く、PIQA、ARC-e、ARC-c、HellaSwag、Winograndeの正答率は大きいほど良い。下流微調整の分類・質問応答にはSST-2、CB、SQuAD、DROP等を使用する。

Table 7の時間は学習更新一回の壁時計時間、Table 8には端末の微調整遅延と生成token/sが別々に記載されている。生成速度、困惑度、微調整時間を一つの「高速化倍率」へまとめることはできない。GPUメモリはモデル容量、更新対象、バッチ、入力長によって変わる。著者は複数回実行の平均を記載するが、Windows GPU、CUDA推論エンジンや大規模サービング環境での再現性は評価していない。

### OnePlus 12での実機測定

OnePlus 12のW4A4（Table 8）では、OPT-1.3Bの微調整メモリがFP16の3.5GBから1.2GB、更新時間が11.2秒から7.8秒へ減少する。OPT-2.7Bは8.1GBから2.6GB、19.6秒から12.3秒へ減る。OPT-6.7BはFP16微調整がメモリ不足で実行できないが、ZeroQATは6.4GBで29.1秒/更新を実測している。29.1秒という値は、スマートフォンで大規模モデルの更新が可能になった証拠であり、学習が高速であることの証明ではない。

同じ端末での生成速度は入力384トークンの条件でOPT-1.3Bが10.9→15.4 token/s、2.7Bが7.58→11.0 token/s、6.7Bが3.13→4.76 token/s。各々およそ1.41倍、1.45倍、1.52倍である。端末の特定のSoC・量子化形式の比較であり、GPUサーバーのバッチ処理やローカルCUDA実装へ倍率を移せない。微調整時のメモリと推論時の生成速度を別表で示した原著の区別を維持する必要がある。

### 数値の読み分けと再現時の注意点

原著の困惑度比較では、量子化の種類を固定してから手法間を比較する必要がある。重みだけを二ビット化した条件では活性値が高精度のまま残るため、重みと活性値の両方を四ビット化した条件とは外れ値の影響も演算経路も異なる。さらにモデル系列が変わると、同じ困惑度の絶対値でも語彙や評価データの前処理が違い得る。論文が表ごとに対象モデルとデータ集合を示す理由はここにある。再現実験では、量子化対象の線形層、グループ幅、平滑化初期化、更新対象、入力系列長を揃え、最終損失と実際の生成速度を独立に測る必要がある。

端末上での利点は、従来の高精度モデルが実行不能となる容量境界を越える点にある。論文で示される学習時の節約は、重みの表現形式だけでなく、勾配計算のための中間状態を保存しないことから生じる。そのため、入力系列を長くした場合の一時的な注意計算用領域や、端末の実際のメモリ管理の費用を別に確認する必要がある。低ビット化しても学習更新一回に数十秒を要するため、長時間の端末内適応や電池消費を含めた実用性は、提示された速度だけでは判定できない。また、低ビット重みを格納できることと、使用する演算器が同じ形式を効率的に実行できることは別問題である。量子化器の丸め規則、演算器が対応する整数形式、逆量子化の位置が変われば、同じビット数でも実行時間は変わる。したがって、端末での速度改善をサーバーや別の機器へ転用するには追加測定が必要である。

### 構成要素除去・感度と負の結果

付録Table D.3では、Llama2-7BのW2A16の量子化事前学習において、全パラメータ版の困惑度29.61に対し、軽量Q/V版は41.05へ悪化する。13Bでも15.95から21.97へ悪化する。下流微調整では有効なQ/V限定が、一般言語能力を作る段階では不足するという重要な反例である。Table D.5ではW4A4の平滑化初期化を行わないとPPL 15.67、2エポック初期化で12.95、20エポックで12.08となる。より長い初期化で品質は改善するが、計算費用も増すため著者は2エポックを既定にする。

Table D.6では学習サンプル数32から512への増加に伴い、W2A16の困惑度は30.18から29.34、W4A4では13.32から13.06へ変化する。しかし中間の128サンプルはそれぞれ29.61と12.95であり、単調に改善するわけではない。零次推定のサンプル効率、平滑化初期化、更新する重みの範囲が性能を左右する。単純に学習データを増やすだけで改善すると断定できない。

## 既存研究との違い

SmoothQuantは活性値と重みのスケールの再配分により、主に推論前の量子化を容易にする。OmniQuantは層単位の出力再構成を通じて量子化パラメータを最適化するが、全体の最終損失とはずれ得る。ZeroQATは量子化された前向きモデルの最終損失から更新方向を得て、平滑化・クリッピング・重みを共同最適化する点で異なる。EfficientQATやQLoRAのような省メモリ微調整と比べる際には、重みのみの低ビット化か、重みと活性値の両方を低ビット化するかを区別する必要がある。

原著は量子化前学習の改善、端末上の微調整可能性、量子化後の推論速度をそれぞれ異なる条件で評価している。推論エンジンのバッチスケジューラ、KVキャッシュ配置、CUDAカーネル、複数GPUの通信効率を最適化する研究ではない。量子化によるモデル容量とメモリ転送量の減少は推論へ関係するが、端末実験以外のエンドツーエンドサービング性能は別途測定が必要である。

## 限界と適用条件

零次推定は逆伝播状態を省けるが、摂動方向ごとに前向き計算を二回必要とする。収束までの総反復回数、学習時間、方向数と分散の関係を、通常のQATと同一の「1更新時間」だけで比較するのは不十分である。平滑化と重みクリッピングは特定の低ビット条件で相補的だが、初期化とハイパーパラメータに依存する。全パラメータ更新では高精度重みの保持が不可避であり、端末上の8GB級動作はQ/V限定の軽量版に依存する。

推論側では、OnePlus 12でOPT系列の生成速度が改善したことは確認できるが、RTX 4070 SUPERなどのGPU環境で同じ高速化が出るとは限らない。W6A6のC4でOmniQuantより悪化する負の結果、事前学習にQ/V限定版を使ったときの品質低下を無視してはならない。公開コードの所在を一次資料から確定できなかったため、論文記載の手法を再実装する際には零次方向のサンプリング、量子化の丸め処理、各表のモデル系列、評価データの一致を追加検証する必要がある。
