# MUXQ: Mixed-to-Uniform Precision MatriX Quantization via Low-Rank Outlier Decomposition

> 活性値の外れ値チャネルを本体と低ランク補助行列へ分解して大きさを分散させ、混合精度を使わない一様な整数量子化で半精度に近い困惑度を保つ量子化手法。GPT-2の3規模で素朴な量子化を一貫して上回ることを示した研究。

## 概要

大規模言語モデルをスマートフォンや組み込み機器のNPU（整数演算に最適化されたアクセラレータ）で動かすには、半精度の浮動小数点演算を整数演算へ置き換える量子化がほぼ必須である。ところが活性値（層の入力となる中間値）には、少数のチャネルにだけ桁違いに大きい値が現れる外れ値があり、これが量子化を難しくする。量子化のスケール（実数を整数の段へ割り当てる換算係数）は範囲内の最大値で決まるため、外れ値があると通常の値に割り当てられる段が粗くなり、誤差が膨らむ。外れ値を無視すれば精度が大きく壊れることも知られている。既存の対処は二つある。LLM.int8()は外れ値の特徴を分離して半精度で処理する混合精度方式で精度を守るが、半精度の演算が残ることでメモリアクセスが不規則になり、演算精度の混在そのものがハードウェア効率を落とす。SmoothQuantは活性値のスケールを重み側へ移して量子化の難しさを均すが、外れ値が通常値よりはるかに大きいという事実自体は残る。

MUXQ（Mixed-to-Uniform Precision Matrix Quantization）は、この外れ値を「大きさの分散」で処理する。本体となる活性値行列の外れ値チャネルを、指数分だけ右シフトして小さくしたものと、その複製である小さな補助行列へ分解し、行列積を本体側と補助側の2回に分けて、補助側へ係数を掛けてから合計することで元の寄与を正確に再構成する。外れ値の大きさが1つのチャネルに集中せず本体と補助へ分散するため、スケールが外れ値に引かれにくくなり、全演算を整数のままの一様な低精度量子化で実行できる。

**代表結果:** GPT-2 smallのテンソル単位量子化（注意層、重み・活性値とも8ビット）では、素朴な量子化の困惑度50.618に対しMUXQは29.5534と大きく改善し、半精度の25.188やLLM.int8()の28.4595に近づいた。GPT-2 mediumでは活性値7ビットで素朴な量子化が35.8196まで悪化する条件でもMUXQは22.3645を保った。ただし活性値6ビットではMUXQの38.2443に対しLLM.int8()が25.009と差が開き、ビットを下げるほど半精度の別処理の優位が増すことも同時に示された。

## 問題設定

量子化誤差の出方を決めるのは、スケールを共有する範囲（量子化の粒度）と、その範囲内の最大値である。絶対最大値方式では、スケールは最大の絶対値を整数の最大段で割って決まる。外れ値チャネルがあると、その列を含む範囲ではスケールが外れ値基準になり、通常の値は少ない段数へ押し込められて量子化誤差が増える。チャネルごとにスケールを持てば精度は上がるが、行列積のカーネルがハードウェアで効率よく支えられず、実務ではトークン単位かテンソル単位の粒度が使われてきた。つまり問題は、粗い粒度のままで外れ値の影響だけを消すことである。もう一つの制約が演算の一様さである。NPUのような整数中心のハードウェアでは、半精度の別経路が混ざるだけで、演算器の利用効率とメモリアクセスの規則性の両方が損なわれる。したがって求められるのは、外れ値を別精度へ逃がすのではなく、整数の範囲内で大きさを均し、粗い粒度の一様量子化でもスケールが壊れない入力へ変換する仕組みである。

## 手法のあらまし

処理の流れは層ごとに行列積の前後で完結する。第1に、入力活性値行列から外れ値チャネルを検出する。判定はLLM.int8()と同じ基準で、大きさが6を超える要素を含むチャネルを外れ値とする。第2に、外れ値チャネルだけからなる部分行列を、指数係数だけ右シフトして小さくした本体と、その本体と同値の補助行列へ分解する。第3に、本体全体と重みの行列積と、補助行列と重みの行列積を、それぞれ整数量子化のまま計算する。第4に、補助側の出力へ（2の指数係数乗マイナス1）を掛けて本体側へ加え、元の外れ値の寄与を再構成する。第5に、この前処理を注意と多層パーセプトロンの主要な射影へ適用し、量子化の粒度やビット幅は通常の設定のまま使う。補助行列は外れ値チャネルの列だけを持つため小さく、追加の行列積は限られる。

## 手法

### 1. 外れ値分解 — 大きさを本体と補助へ分け、和で元へ戻す

観測するものは各層の入力活性値であり、保持する状態は外れ値チャネルの位置だけである。処理の核は恒等式で、外れ値部分行列は「右シフトで小さくした本体」と「その複製である補助」の組に分解され、元の値は本体に（2の指数係数乗マイナス1）倍の補助を加えたものと等しい。浮動小数点数の大きさは指数部が支配するため、右シフトは外れ値の大きさを通常チャネルの水準へ直接下げる。行列積は線形なので、この分解は出力側でもそのまま成り立ち、本体の行列積と補助の行列積を係数付きで合計すれば、量子化前の数学的な寄与は正確に戻る。量子化誤差の観点では、本体の外れ値が小さくなることで、その範囲のスケールが通常値に合った大きさになり、通常値の分解能が戻る。これがボトルネックの減り方である。追加で消費する資源は、補助行列の保存と、外れ値列だけを対象とする小さな行列積1回分であり、外れ値チャネルが少数である前提に依存する。外れ値が多い入力では補助側のコストが膨らむ。失敗条件は、シフトで小さくし切れないほど外れ値が極端な場合や、後述のように活性値のビット幅自体が極端に小さい場合で、その領域では半精度で外れ値を扱う方式に精度で劣る。

### 2. 指数係数の選択 — 量子化の効きと実装コストの交換

指数係数は、外れ値の大きさをどれだけ強く分散させるかを決める。本論文では、外れ値の大きさが通常チャネルと同程度になることを狙って指数係数を2に設定している。係数が1なら再構成は2つの行列積の単純な和で済み実装が最も軽いが、係数が1以外では補助側への係数乗算という追加処理が入り、量子化の効きと実装コストの交換になる。つまり係数は、外れ値を均す強さと、シストリックアレイや積和演算器のようなハードウェアへ載せたときの素直さの間で選ぶ量である。なお本論文の範囲では係数は固定値であり、層ごとや入力ごとに適応させる仕組みは評価されていない。

### 3. 既存手法との組み合わせ可能性 — 入力側の変換として直交する

MUXQは量子化器そのものではなく、量子化される前の活性値の分布を整える入力側の変換である。そのため、スケールの決め方や難しさの移行といった他の量子化手法と競合しない。論文では、MUXQで作った活性値へSmoothQuantの難しさ移行をさらに重ねる使い方が例として挙げられている。評価では比較を単純にするため、スケールは絶対最大値方式で全方式に共通化され、MUXQの構造だけが変数になっている。実装は、Hugging Face TransformersのConv1Dモジュールを置き換える形でGPT-2の注意射影と多層パーセプトロンの射影へ適用される。

## 評価

### まず見るところ

- **結論:** MUXQは素朴な量子化より一貫して困惑度が低く、特にテンソル単位の粗い粒度と、活性値のビットを下げる条件で差が開く。一様なINT8では半精度に近い水準へ届く。
- **速度・効率:** 推論速度の実測はない。評価は量子化を模擬するフェイク量子化（量子化と復元を行ってから浮動小数点で計算する方式）であり、精度の傾向を見るためのもので、実際の整数推論の速さは未検証である。
- **品質:** LLM.int8()との比較では概ね僅差で後れ、活性値6ビットでは差が明確に開く。
- **メモリ・入出力:** 補助行列の分だけ保存と計算が増えるが、外れ値チャネルが少数なら小さい。KVキャッシュの量子化は対象外である。
- **評価の強さ／注意点:** 対象はGPT-2の0.1B・0.3B・0.7BとWikiText-2のみで、現代の大規模モデルや下流タスクでの検証はない。

結果の読みどころは、どの条件で差が開くかである。MUXQもLLM.int8()も外れ値処理をしない素朴な量子化との差は、活性値のビットを下げるほど大きくなる。GPT-2 smallのベクトル単位では、活性値8ビットで三方式がほぼ並ぶ（25.19〜25.38）が、5ビットでは素朴な量子化が152.1251へ崩れるのに対し、MUXQは43.129、LLM.int8()は30.5337と持ちこたえる。テンソル単位では差がさらに早く現れ、注意層の8ビットで素朴な量子化が50.618、MUXQが29.5534、LLM.int8()が28.4595だった。GPT-2 largeでも、活性値6ビットで素朴な量子化の40.0405に対しMUXQは19.2885と半分以下である。一方で上限も見えている。GPT-2 mediumの活性値6ビットではMUXQが38.2443まで悪化し、LLM.int8()の25.009に大きく後れる。外れ値を整数の範囲内で均す方法は、ビット幅が極端に小さくなると、半精度で外れ値をそのまま運ぶ方法の情報量に勝てない、という読み方である。重みのビットを下げる実験では三方式の変化が同程度で、方式間の差は重み側ではなく活性値の外れ値処理から来ることが確認されている。粒度を細かくすると全体の精度が上がり、その分だけ活性値を下げたときのMUXQの優位が見えやすくなるという感度も報告されている。

## 既存研究との差

外れ値への対処は、LLM.int8()の混合精度分解、SmoothQuantのスケール移行、Q-BERTのような重み側の低精度化などがあるが、本論文との差は「外れ値をどこへ逃がすか」にある。LLM.int8()は外れ値を半精度の別経路へ逃がし、精度と引き換えに演算の一様さを失う。SmoothQuantは量子化の難しさを活性値から重みへ移すが、外れ値の大きさ自体は残る。MUXQは発想の出発点がLoRAの低ランク加算にあり、重みにではなく活性値へ補助行列を加えることで、外れ値の大きさを整数演算の内部で分散させる。逃がし先が同じ整数精度の補助経路であるため、一様な量子化と規則的なメモリアクセスを保てる点が差分であり、他の量子化手法と直交して重ねられることも位置づけとして示されている。

## 限界・実装状況

著者が明言する制約は、推論速度を実験で比較していないことであり、INT8の行列積が半精度より効率的という一般論から実務的な利点を見込むに留め、カーネル水準の遅延と電力の実測は今後の課題としている。評価範囲も、GPT-2の3規模とWikiText-2の困惑度のみで、現代の大規模モデル、下流タスク、実NPUでの検証はない。方式の前提として、外れ値チャネルが少数であることに依存し、その前提が崩れる入力での補助コストと精度は測られていない。指数係数も固定であり、層や入力への適応は未検討である。実装面では、著者公式のコードが公開されており、Hugging Faceのモジュール置き換えとして再現可能な形になっている。

## 一般的な実装上の含意

量子化の設計では、精度を守る仕組みが演算の一様さを壊していないかを見る必要がある。外れ値のような局所的な異常は、別精度の例外経路を作るのではなく、同じ精度のまま大きさを分散させる変換で処理できる場合があり、その方がアクセラレータの実行モデルに素直に載る。また、方式の優劣はビット幅と粒度に強く依存し、8ビットで僅差の方式が6ビットでは大きく分かれるため、量子化手法の評価は目標ビット幅そのもので行うべきである。補助構造を足す方式では、その補助が「異常が少数」という前提にどれだけ依存しているかを、コストの側からも明示することが要る。
