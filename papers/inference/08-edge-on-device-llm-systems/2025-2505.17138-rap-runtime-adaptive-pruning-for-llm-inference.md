# RAP：推論時のメモリ制約に応じて注意・FFNを選ぶ動的構造化枝刈り

## 概要

大規模言語モデルの推論メモリには、モデル重みのようにリクエストによらず常駐する領域と、バッチ数・入力長・生成長に応じて増えるKVキャッシュがある。固定の剪定率でモデル重みだけを削る方式は、短い入力では過剰に品質を落とし、長い入力ではKVキャッシュの増加を補えないことがある。RAP（Runtime Adaptive Pruning）は、要求のバッチ数・系列長と実行環境の空きメモリを観測し、注意ブロック（MHA）とフィードフォワードブロック（FFN）のどちらを残すかを要求条件に合わせて変更する構造化枝刈り方式である。

手法は、各ブロックを一つ除去した場合の困惑度を逐次測る**貪欲逐次重要度評価（GSI）**と、GSIの重要度および実行時のメモリ状態を受けて除去操作を選ぶ**深層Q学習（DQN）制御器**からなる。制御器は各層のMHA/FFNを二値的に残す・除く構成を選び、推定ピークメモリが予算内に入るまで逐次処理する。元モデル全体の重みとKVを合計したメモリを予算とするため、同じ重み剪定率だけを比較する方式とは評価軸が異なる。

一次論文v5のTable 1では、Llama2-7Bの**80%メモリ予算**でRAPのWikiText2困惑度は11.80、7種類の常識推論タスクの平均正答率は57.08%で、同条件のLLMPruner（28.42、48.63%）を上回る。ただし非剪定モデルは5.47、66.70%であり、品質無損失ではない。付録Table 6のエッジ端末実測では、RAPは43.36秒・47.23 token/s、元モデルは52.40秒・39.08 token/sである。オンライン制御器は小さい一方、GSIの事前感度測定はLlama2-7Bで**A40約4時間**を要する。このオフライン費用を省いた「無学習・即時圧縮」方式ではない。

## 問題設定：重みメモリとKVキャッシュの比率が動く

Transformerのデコーダ層は、注意ブロックとFFNを持つ。FFNはパラメータの大きな割合を占めるので、FFNを除去すれば重み容量を削りやすい。一方、KVキャッシュは注意層ごとにキーと値を保持する。したがって注意ブロックを除去すると、対応する層のKVキャッシュも不要になり、長文脈・大バッチで大きなメモリ節約につながる。RAPがこの二つのブロックを別々に扱うのは、**どの資源が支配的かが実行中に変わる**ためである。

原著§2.1はLlama2-7Bの32層・32ヘッド・ヘッド次元128を例に、FP16のKVキャッシュが1トークン当たり約0.5MBになると示す。バッチ16・系列長4096ではKVが約32GBとなり、重みの約14GBより大きい。これに対して短い要求ではモデル重みが支配的になりやすい。モデル重みだけを固定比率で削ると、KVが支配的な条件では空きメモリ不足を解決できない可能性がある。

また、モデルが同じでも各層のMHAとFFNが品質へ与える影響は均一でない。あるブロックの除去による困惑度変化は、先に他のブロックを削ったかどうかで変わる。最初の元モデル上で全ブロックを一度だけ順位付けし、下位からまとめて除く静的手法では、層間依存を反映できず強い剪定で品質が崩れる。この二つの問題、すなわち**実行時に変わるメモリ比率**と**除去順序に依存する重要度**を合わせて扱うことがRAPの目的である。

論文はAzure系の推論トレースを例に、要求長と到着率が時間で変化することを動機付けとして示す。ただし実際のRAP評価がその全トレースを使って大規模サービングSLOを実証したという意味ではない。主たる定量評価はモデルの困惑度・常識推論精度と、限定されたエッジ実測である。

## 手法

### 全体処理：校正・制御器学習・要求ごとの選択

RAPの処理は二段階に分かれる。**事前段階**では、校正データ上でモデルの各MHA/FFNブロックを仮に除去して困惑度を測り、重要度を逐次再評価するGSIを実行する。これにより、単に重みの大きさを見るのではなく、各ブロックを外したときの生成確率分布への影響を得る。得られた重要度を特徴量として、メモリ使用量と困惑度の交換条件を報酬にするDQN制御器を学習する。

**実行段階**では、新しい要求が到着した際のバッチ数、系列長、利用可能メモリ、モデルブロックの重要度を状態として制御器へ入力する。制御器は「ここで停止」または「特定のMHA/FFNブロックを一つ除去」を選ぶ。選択に応じて推定重み容量とKV容量が更新され、ピークメモリが予算内に収まれば停止する。最終的な残存ブロック構成で推論する。この流れにより、長い系列でKV容量が大きいときには注意ブロック削減が有利になり、重み容量が支配的な条件ではFFN削減が有利になり得る。

ここで「動的」とは、毎トークンごとに新しい重みを学習することではなく、**事前に測った重要度と学習済み方策を用い、要求条件に応じて実行するブロック集合を変えること**を指す。事前のGSI計算が不要になるわけではない。原著の本文と付録には、重要度を毎回オンライン再計算するようにも読める記述と、GSIをモデルごとに事前計算して再利用する記述が混在するため、実装解釈には注意が必要である。

### GSI：ブロックを一つ外すたびに重要度を測り直す

貪欲逐次重要度評価（Greedy Sequential Importance、GSI）は、元モデルM、校正コーパスC、目標剪定率ρを入力とする。各反復で、現在残っている各ブロックB_iを一つだけ外した仮モデルを作り、その困惑度P_iを校正データ上で評価する。P_iが最小、すなわち削っても予測性能を最も損ないにくいブロックを実際に外し、次の反復では**縮んだモデルに対して再び全候補を評価**する。最終的に、除去したブロックの順序と重要度の推移を出力する。

困惑度は、正解系列へ割り当てる平均対数確率を指数変換した指標で、小さいほど言語モデルの予測が良い。GSIが各反復で困惑度を再測定するのは、例えば一つの注意層を削ると後段FFNが受け取る表現も変わり、残るブロックの価値が元モデルと異なるからである。静的な一回評価より計算量が大きいが、強い剪定での破綻を抑える根拠となる。

論文のAlgorithm 1では、各反復で候補ブロックを一つずつ除去したモデルの困惑度を測定し、最小値の候補を選ぶ。ここには候補モデルを繰り返し実行する大きな校正費用がある。付録Table 5によると、A40でLlama2-7Bの64ブロックに約4.0時間、Llama3-8Bに約3.9時間、Qwen1.5-7Bに約4.5時間、Qwen2.5-7Bの56ブロックに約3.5時間を要する。GSIを「軽量なオンライン計測」と説明するのは不正確である。

### DQN：実行条件に応じてMHA/FFNの除去を選ぶ

制御器の状態は三群からなる。要求状態はバッチ数R_bsと系列長R_sql、モデル状態は各層のMHA/FFNの重要度、システム状態は現在の利用可能メモリSys_availと候補構成の推定必要メモリSys_reqである。状態を受け取った制御器は、次に除去するブロックを選ぶ。元のN層には2N個のMHA/FFNブロックがあるため、すべての二値構成を一括探索すると2^(2N)通りになる。Llama2-7Bの64ブロックでは約1.8×10^19通りで、総当たりは現実的でない。

そこで付録A.1では、行動を「停止0」または「ブロック1〜2Nのいずれかを除去」とする逐次意思決定に分解する。既に除去したブロックは行動マスクで無効にする。付録A.3のDQNは、状態と行動から将来報酬の推定値Q(s,a)を出し、経験再生バッファとターゲットネットワークを使って学習する。学習時には有効な行動集合だけでε-greedy探索を行う。こうして、固定の剪定比率ではなく、各要求のメモリ状態に応じたブロック選択を学習する。

報酬は困惑度の重要度と推定メモリ費用の重み付き結合で、本文式(2)は保持ブロックの二値ベクトルAと係数α、βを用いて表す。実験設定はα=1、β=0.3。αが大きいほど重要ブロックを残す方向、βが大きいほどメモリ節約を優先する方向へ誘導する。付録のパラメータ感度実験はα∈[0.2,1.0]、β∈[0.1,0.5]を探索しており、係数が変われば同じモデル・要求でも選択構成が変わり得る。制御器は2層MLPで約18,000パラメータと小さいが、報酬設計や校正データの代表性まで不要になるわけではない。

### メモリ推定：MHAを削る意味とFFNを削る意味

付録A.2のピークメモリ推定は、残存ブロックの重み容量とKVキャッシュ容量を合算する。KVはバッチ数・系列長・残存注意層数にほぼ比例するため、長文脈でMHAを一つ削ると対応層のKV保存領域を減らせる。一方、FFNを一つ削ると重み容量を削れるが、他層のKV容量は基本的に減らない。この区別により、重みが支配的な要求とKVが支配的な要求で同じ削除を選ぶ必要がなくなる。

ただしMHAの削除はその層の注意演算自体をなくす強い構造変更であり、単に過去トークンの一部を選択して捨てるKV evictionとは異なる。FFNも層の非線形変換を除去するため、どちらも出力品質へ直接影響する。RAPは「重要度の低い部分を選ぶ」ことで品質損失を抑えるが、元モデルの機能を完全に保つ保証はない。要求ごとの構成変更に伴う重み再配置・GPUアロケータ断片化・同時要求間の異なるモデル構成管理など、実運用の詳細は論文で網羅的に評価されていない。

## 評価

### 評価環境と比較方法

| 観点 | 一次論文v5の設定 |
|---|---|
| 主な実験GPU | NVIDIA A40（論文§5.1） |
| 実装 | PyTorch、Hugging Face Transformers |
| モデル | Llama2-7B、Llama3-8B、Qwen1.5-7B、Qwen2.5-7B |
| GSI校正 | Alpacaデータセットを用いた困惑度測定 |
| 言語モデル品質 | WikiText2・PTBの困惑度（小さいほど良い） |
| 下流品質 | BoolQ、PIQA、WinoGrande、HellaSwag、ARC-e、ARC-c、OpenbookQAのゼロショット平均正答率（高いほど良い） |
| 比較 | LLMPruner、SliceGPT、ShortGPT、MHA-Drop、FFN-Skip（モデルによって比較可能方式が異なる） |
| 予算 | 元の重み+KVの推定ピークメモリを100%とし、80%・60%の制約を課す |
| 速度・資源 | GSI事前計算時間、制御器オーバーヘッド、エッジ端末での遅延とtoken/s |

評価の要点は、**剪定率を揃えた比較ではなく、ピークメモリ予算を揃えた比較**である。MHAを削る方式とFFNを削る方式では、同じ重み剪定率でもKV容量の削減効果が違う。Table 4ではLlama2-7Bの80%メモリ予算を満たす重み剪定率が、RAP約24%、LLMPruner35%、FFN-Skip約52%と異なる。60%予算ではそれぞれ約30%、45%、64%となる。したがって「RAPはより少ない重みを削るのに同じメモリへ収められる」という解釈は、注意層のKV容量も減らす設計と対応する。

Llama2-7Bの80%予算ではRAPの平均正答率57.08%がLLMPrunerの48.63%を8.45ポイント上回るが、元モデルの66.70%より9.62ポイント低い。60%予算ではRAPも平均43.00%まで低下し、元モデル比で23.70ポイント悪化する。特にLlama3-8Bの60%予算ではRAPのWikiText2困惑度が246.53まで上昇する。したがって強い圧縮下でも**比較方式より相対的に壊れにくい**ことと、**元モデルに近い品質を保てる**ことは区別すべきである。

Table 1では個別タスクにより改善幅が異なる。Llama2-7B・80%のRAPはPIQA73.99%、HellaSwag65.77%、ARC-c36.69%で、元モデルの79.11%、75.98%、46.25%より低い。平均値だけでは複雑な常識推論での損失を隠すため、運用用途に応じたタスク別検証が必要になる。

| Qwen2.5-7B・80% | ShortGPT | 523.53 | 54.62% |

論文はRAPの異なるモデルへの適用性を主張するが、**Qwen1.5-7Bの80%予算ではMHA-Dropのほうが困惑度・平均正答率の双方で良い**。RAPは全モデル・全予算で全比較方式を支配していない。Qwen2.5-7Bの80%予算ではRAPが比較方式より良い平均正答率を示すが、元モデルの70.30%に対して56.87%で、13.43ポイントの低下がある。構造や学習済み重みが異なるモデルへ適用できることと、性能の優位性が普遍的であることは同義ではない。

## 主要結果の意味

RAPが有効な理由は、ブロックの重要度を再測定するGSIと、要求条件に応じてその重要度とメモリ費用を使い分けるDQNを結合したことにある。GSIがなければ一回評価の誤差が積み重なり、DQNがなければ重み容量とKV容量のどちらを削るべきかを実行時に選びにくい。Llama系の同一メモリ予算比較では、両者の組合せが比較方式より低い困惑度・高い平均正答率につながる。

一方で「低メモリで実行可能になる」と「出力品質が高い」は別問題である。60%予算ではRAPも大きく品質が低下する。メモリ予算はピークメモリの相対値であり、全ての実装が実際にその量だけ物理VRAMを確保できるか、要求混在時にOOMが起きないかまで実証したものではない。特に複数の異なる剪定構成を同時に扱うサービングの実装管理は別の問題として残る。

## 既存研究との差

LLMPrunerは重み・勾配に基づく構造化剪定、SliceGPTは次元削減、ShortGPTは層削減、MHA-Dropは注意層の削除、FFN-Skipは入力依存のFFNスキップを主に扱う。これらは個々のブロックの削減手法として有用だが、RAPの評価軸は**要求時のメモリ予算に対してMHA/FFNを選び直す**ことである。単に剪定率を上げるのではなく、重みとKVキャッシュの合計を推定し、支配的な領域を減らす操作を選ぶ。

KV evictionやKV量子化の方式は、注意層を残したまま保持する過去トークン数や精度を変える。RAPは注意ブロックそのものを除去し得るため、削減効果が大きい反面、注意機能全体を失う品質リスクがある。動的なトークン選択と動的なブロック選択は混同できない。GSIはオフラインでモデルのブロック除去感度を測るため、特定の量子化形式・モデル改変後に同じスコアを無条件で再利用できるとは限らない。

## 限界・負の結果・再現性

**事前費用の大きさ。** GSIはA40で7B級モデルに3.5〜4.5時間を要する。数十B級モデル、異なる量子化版、ドメイン特化モデルごとに同様の校正を行う費用は無視できない。学習済み制御器のオフライン学習も約302秒かかる。公式コードのURLは確認したarXiv v5本文から特定できない。

**品質低下。** Llama2-7B・60%予算ではRAPの常識推論平均が43.00%となり、元の66.70%より大幅に低い。Llama3-8B・60%ではWikiText2困惑度246.53で、元の6.13から大きく悪化する。Qwen1.5-7B・80%ではMHA-DropのほうがRAPより良い。全条件で最高の方式と断言できない。

**状態特徴の不足。** 著者が付録Eで述べるとおり、制御器は主にバッチ数・系列長・瞬間的な空きメモリを観測し、遅延、電力、異種アクセラレータの特性を明示的に状態へ含めていない。低遅延SLOや電力制約を直接保証する学習目的ではない。長文脈でKVが極端に膨張するケースも、付録Eでは今後の課題とされる。

**再現性上の記述不整合。** Table 1とTable 2のLlama2-7B・60%困惑度が84.78と74.78で異なる。また、GSI重要度を要求ごとに再計算するような本文の説明と、付録D.1の「モデルごとに一度事前計算し再利用する」という説明には実装解釈の余地がある。オンラインで完全なGSI再計算を行うなら4時間の事前費用と矛盾するため、実装確認なしにオンライン再測定を性能実測の前提にしてはならない。

**サービング実装の範囲。** 複数GPU・複数モデル・連続バッチ・メモリ断片化・リクエスト間の剪定構成切替・GPU/CPUオフロード・vLLM等の本番推論基盤との統合は主な評価ではない。エッジ実測Table 6は端末のハードウェア詳細を十分に示していない。報告された約1.21倍の実測速度差を任意のローカルGPUや本番クラスタに外挿しない。
