# ConsRoute: Consistency-Aware Adaptive Query Routing for Cloud-Edge-Device Large Language Models

> 応答間の意味的一致を教師信号にし、デバイス側モデルのプリフィル隠れ状態を再利用する軽量予測器とクラスタ別ベイズ最適化閾値で、3層協調推論のルーティングを適応化した研究。

## 概要

大規模言語モデルを携帯端末やモノのインターネットの環境で使うと、品質、遅延、費用の緊張が避けられない。大きいモデルは高品質だが推論遅延と計算とエネルギーが大きく、小さいモデルは効率的だが推論や生成の品質が落ちる。そこで、クラウドに30B級以上の大きいモデル、エッジに7から30B級の中規模モデル、デバイスに4B未満の小さいモデルを置き、クエリごとに処理する層を選ぶ協調推論が使われる。この構成の性能は、ルーティング、つまり小さいモデルの応答が大きいモデルの応答と十分に一致すると見込めるクエリだけを下の層で処理し、そうでないものを上の層へ送る判断の精度で決まる。

従来の生成前ルーティングには3つの弱点があった。第1に、教師信号が品質スコアや報酬の差であり、豊かなテキスト応答を1次元の値へ潰してから差を取るため、両方の応答が高スコアでも内容が食い違う場合を見落とす。第2に、クエリ表現を微調整したエンコーダや外部の埋め込みサービスで作るため、端末側の計算や通信が重い。第3に、振り分けの閾値が全体で1組の固定値であり、クエリの種類や分布の変化に追随できない。本論文のConsRouteはこの3点をそれぞれ置き換える。教師信号は、再ランク付け器で応答同士の意味的類似を直接測った柔らかいラベルにする。表現は、デバイス側モデルのプリフィルで得られる最終層の隠れ状態を、一致を意識させる短い指示文をクエリへ付けた上で再利用し、デバイスで処理することになればそのKVキャッシュもそのままデコードに使える。閾値は表現空間のクラスタごとに、正確さから遅延と費用を差し引いた効用をベイズ最適化で最大化して決め、運用中も新しい観測で更新する。代表結果として、クラウドのみの性能の95パーセント以上を、エンドツーエンド遅延はクラウドのみの60から65パーセント、費用は約70パーセントで達成し、同等の正確さに必要な遅延が既存手法の70から85パーセントであることと比べても良い交換条件を示した。

## 問題設定

ルーティング問題は、品質、遅延、費用の多目的最適化である。各クエリについて、デバイスで処理すれば通信がなく最も速いが品質リスクが大きく、クラウドへ送れば品質は最も高いが通信と大きいモデルの計算を払う。最適な振り分けは、クエリごとに、小さいモデルの応答が大きいモデルの応答とどれだけ一致するかという、生成前には観測できない量に依存する。したがって中核は、この一致を生成前にどれだけ正確に、どれだけ安く予測できるかである。

品質差による教師信号が不十分な理由は情報の潰れ方にある。応答をまず品質のスカラーへ写し、その差を取る2段階の圧縮では、事実内容の食い違いのような、応答間の関係にしか現れない情報が落ちる。論文中の例では、報酬モデルが2つの応答に似た高いスコアを与える一方で、再ランク付け器は意味の不一致を捉えている。人手ラベルとの一致でも、再ランク付け器のスコアは報酬モデルやテキスト評価指標より高い線形相関を示した。もう1つの制約は端末側の資源である。ルーティング自体が重ければ、速くするために入れた仕組みが遅延とメモリを食って本末転倒になる。特にカスケード方式は、小さいモデルで最後まで生成してから判断するため、振り分けの遅延が原理的に大きい。生成前に、しかも端末の既存計算の再利用で判断できることが、モバイル環境では要件になる。

## 手法のあらまし

全体はオフラインの教師構築と、オンラインの振り分けの2相である。オフラインでは、訓練クエリについてデバイス、エッジ、クラウドの各モデルの応答を集め、再ランク付け器でデバイス応答と上位応答の意味的類似を測り、正解がある場合は正誤に基づく規則、正解がない場合は大きいモデルによる判定で補強して、柔らかい一致ラベルを作る。デバイスとエッジの組、デバイスとクラウドの組のラベルを重み付きで融合し、これを教師として、デバイス側モデルの隠れ状態から一致スコアを予測する小さな多層パーセプトロンを訓練する。あわせて訓練クエリの表現をクラスタリングし、クラスタごとに2つの閾値をベイズ最適化で決める。オンラインでは、クエリに固定の指示文を付けてデバイス側モデルでプリフィルし、最終トークンの最終層隠れ状態を取り、予測器で一致スコアを出し、最も近いクラスタの閾値と比べて、デバイス、エッジ、クラウドの順に振り分ける。デバイスに決まればプリフィルのKVキャッシュがそのまま使える。運用中は、処理したクエリの正誤、遅延、費用から効用の観測を蓄積し、一定件数ごとにベイズ最適化を回して閾値を更新する。

## 手法

### 1. 意味的一致ラベル — 品質差ではなく応答同士の近さを測る

観測するものは、同じクエリに対する下位モデルと上位モデルの応答の組である。保持する状態は、再ランク付け器Qwen3-Reranker-4Bが出す意味的類似スコアを主信号とし、正解があるクエリでは、下位が誤りで上位が正しい場合を不一致とする規則による補強、正解がないクエリではDeepSeek V3を判定者とする意味一致の柔らかいスコアによる補強を、重み付きで混ぜたラベルである。3層対応のために、デバイスとクラウドの組と、デバイスとエッジの組でそれぞれラベルを作り、重みで融合したものを最終的な教師とする。この設計が減らすボトルネックは、品質差方式が見落とす意味的な不一致による誤振り分けである。追加費用はオフラインの応答生成と再ランク付けと判定であり、運用時には一切かからない。失敗条件は、再ランク付け器や判定者自体の偏りがラベルへ混入することであり、補強信号を混ぜることはその緩和として位置付けられている。教師信号の違いは評価でも切り分けられており、再ランク付け器による教師は、報酬モデルやテキスト評価指標による教師より、同じ性能に達する遅延と費用が一貫して小さい。

### 2. プリフィル隠れ状態の再利用 — 追加エンコーダなしのクエリ表現

クエリ表現は、クエリの末尾に、小さいモデルと大きいモデルの応答の一致について考えさせる固定の英語指示文と終了トークンを付け、デバイス側モデルへ入力したときの、終了トークン位置における最終層の隠れ状態である。観測はデバイス側モデルがどのみち行うプリフィル計算であり、保持する状態はそのベクトル1本である。指示文を付けることで、表現は次トークン予測のための汎用的な意味ではなく、一致予測という課題に寄った内容を持つよう調整される。切り分けでは、指示なしの隠れ状態を使う変種がGSM8Kで正確さ82.34パーセントにとどまるのに対し、指示付きは87.92パーセントへ上がり、振り分け遅延は20.4ミリ秒から20.9ミリ秒とほぼ変わらなかった。デバイス側モデル自身に明示的に層を選ばせる変種は、推論なしで85.79パーセント、思考連鎖付きで86.44パーセントだが、後者は振り分け遅延が1868.2ミリ秒と桁違いに大きく、暗黙の表現を使う本方式の有利さが分かる。追加費用は指示文の数トークン分のプリフィルだけで、デバイスで処理する場合、そのKVキャッシュはデコードへ再利用されるため実質的に無駄がない。外部エンコーダを使う方式が1億パラメータ級のモデルを端末に常駐させるのと比べ、本方式の追加は予測器の約500万パラメータだけである。

### 3. 軽量予測器 — 隠れ状態から一致スコアへの回帰

予測器は、隠れ状態を入力として0から1の一致スコアを返す小さな多層パーセプトロンであり、融合ラベルに対する二乗誤差で訓練される。選択するものはスコアそのものであり、振り分けの最終判断は次の閾値機構が担う。分離しておくことで、予測の質と、品質と効率の交換方針を独立に変えられる。運用時に動くのはこの予測器だけであり、再ランク付け器も報酬モデルも外部サービスも呼ばない。誤予測時の挙動は非対称である。一致を過大に予測すると弱いモデルの応答がそのまま返って品質事故になり、過小に予測すると上位へ送りすぎて遅延と費用が増える。この非対称の調整は予測器ではなく、クラスタごとの閾値と効用の重みが担う設計になっている。

### 4. クラスタ別閾値とオンラインのベイズ最適化

保持する状態は、訓練表現をクラスタリングした重心群と、クラスタごとに2つの閾値、つまりデバイスで処理してよい下限と、エッジで処理してよい下限である。予測スコアが第1閾値を超えればデバイス、第2閾値を超えればエッジ、それ未満はクラウドへ送る。閾値の学習は、クラスタごとに、正確さから遅延と費用を重み付きで引いた効用を目的とし、ガウス過程の代理モデルと期待改善量によるベイズ最適化で探索する。クラスタ数は肘法で決める。単純な数学問題のようにリスクの高い群では厳しい閾値が、単純な質問の群では緩い閾値が選ばれる余地が生まれ、全体一律の閾値では表せない方針になる。オンラインでは、処理済みクエリの正誤、遅延、費用から効用の標本を作って観測集合へ追加し、一定の窓ごとに最適化を回し直す。分布がずれると静的な変種は正確さが徐々に下がるのに対し、オンライン変種は回復して高い正確さを保ったことが、流れの評価で示されている。ネットワーク条件が悪化すると、効用の中で通信遅延の罰が効いて閾値はデバイス寄りへ動き、回復すると上位へ送る方向へ戻るという、条件変化への追随も確認されている。追加費用は裏側での最適化計算であり、クエリごとの振り分け経路には乗らない。

|---|---|---|---|---|

## 評価

### まず見るところ

- **結論:** 4つのベンチマークで、既存ルーティングより良い正確さと遅延の交換を示し、クラウド性能の95パーセント以上を遅延6割台、費用7割で達成した。モデル族を混ぜた異種構成でも傾向は保たれた。
- **速度・効率:** 振り分け自体の遅延は約20.9ミリ秒で、その大半は再利用されるプリフィルである。追加パラメータは約500万であり、外部エンコーダ方式より端末負担が小さい。
- **品質:** ルーティングは近似であり、下位で処理したクエリの品質は一致予測の正しさに依存する。効用の重みを正確さ寄りにするとクラウドへの振り分けが増えて正確さが単調に上がることが示され、交換は制御可能である。
- **評価の強さ／注意点:** 遅延と費用とスコアは、デバイスのみを原点、クラウドのみを100とする正規化曲線が中心であり、絶対値の表は限られる。費用は起動パラメータ数と生成トークン数からの推定である。実世界の大規模モバイル配備での検証は今後の課題とされている。

## 既存研究との差

カスケード方式は小さいモデルで生成してから判断するため、振り分け自体に生成の遅延が乗る。本手法は生成前に判断する予測型であり、しかも判断の材料を端末のプリフィルから取る。生成前ルーティングの先行研究との差は3点ある。教師信号については、品質や選好や報酬のスカラー差ではなく、応答間の意味的一致を直接測る。表現については、微調整エンコーダや外部埋め込みを使う代わりに、デバイス側モデルの内部状態を再利用する。閾値については、全体で1組の固定値や静的な方針ではなく、クラスタごとの値をベイズ最適化で決めてオンラインに更新する。比較表の整理では、クラウド・エッジ・デバイス配備を対象とし、生成前に判断し、追加エンコーダを持たず、内部状態を再利用し、適応閾値を持ち、オンライン更新を持つ方式は、本手法だけだと著者らは位置付けている。

## 限界・実装状況

- 主結果の提示が正規化曲線中心であり、絶対値での再現や他環境への移植には追加の換算が要る。
- 一致ラベルは再ランク付け器と判定用モデルに依存し、それらの偏りや更新がルーティングの質へ直接影響する。オフライン構築の費用も小さくない。
- 費用の推定はパラメータ数とトークン数に基づく単純な模型であり、実際の課金や消費電力とはずれ得る。
- 評価は模擬ネットワークと研究用の3層構成であり、大規模な実モバイル配備での挙動は未検証で、今後の課題とされている。
- 公式コードの公開先は論文中に示されておらず、サービング基盤への統合実装の報告もない。

## 一般的な実装上の含意

協調推論のルーティングを設計するときは、教師信号を、実際に守りたい性質で定義することが重要である。安いモデルで処理してよい条件は、安いモデルの品質が高いことではなく、大きいモデルの応答と一致することであり、この2つは同じではない。また、判定のための計算は、新しいモデルを足すのではなく、既存の計算、特にプリフィルで得られる内部状態とKVキャッシュを再利用すると、端末側でもほぼ無償にできる。振り分けの閾値は、クエリの種類ごとに分け、運用中の観測で更新できる形にしておくと、分布やネットワーク条件の変化へ、予測器を作り直さずに対応できる。効用の重みを露出させることで、品質と効率の交換を運用方針として調整可能にする点も、実務的な設計原則になる。
