# SwapMoE: Serving Off-the-shelf MoE-based Large Language Models with Tunable Memory Budget

> GPUには少数のexpert用slotだけを置き、RAM上の実expert重みを必要に応じてslotへ入れ替えることで、指定したmemory budget内で既存MoEを動かす近似方式。

## 概要
SwapMoEは、全expertをGPUへ置けない端末で、**少数のexpert用スロットだけをGPUへ用意し、中身をactual expert間で入れ替える**方式である。再学習なしで既成MoEを使える代わりに、常にnative expertが全て利用可能とは限らないため近似推論になる。

## 手法のあらまし

### 1. `Virtual Expert`は新しいexpertではなくGPU上の空き枠
SwapMoEでいうVirtual Expertは、新しいexpertを学習するわけではない。GPU上に置く固定数の **expert slot** を指し、そのslotへactual expert weightを差し替えて使う。例えば64 expertあるlayerでも、GPUには8 slotだけ置き、現在の入力で重要な8 expertをそこへ割り当てる、といった使い方になる。

### 2. 事前にlayerごとのslot数を決める
全layerへ同じslot数を与えるのではなく、layerごとのexpert欠落に対する品質感度、memory cost、swap latencyを測り、限られたmemory budgetをどこへ配るか決める。構成候補が非常に多いため、論文ではgenetic algorithmを使って探索する。

### 3. 実行中にactual expertをslotへ入れ替える
routerが選ぶexpertと最近の利用傾向を見て、GPUにある低頻度expertとRAM側の高頻度expertをswapする。毎tokenで必要expertを全てon-demand loadするのではなく、一度slotへ載せたexpertを複数tokenで再利用することでtransfer回数を減らす。

### 4. static pruningとの違い
static pruningは削除したexpertを二度と使えない。SwapMoEはGPUに常駐していないだけで、RAMには元expertを保持しており、必要に応じて後からslotへ入れ替えられる。このため小さい固定pruned modelより元モデルの容量を活かせる一方、現在slotにないexpertは即座に使えないため、memory budgetを絞るほどquality trade-offが増える。

## 評価
### まず見るところ
- **結論:** 少数のexpert slotを入れ替えることで、4GB級Jetsonでも既成MoEを再学習なしで動かせる。
- **メモリ:** GPU resident expertを大幅に減らせる。
- **速度:** 毎回on-demand loadするよりswapを局所化でき、latencyを削減する。
- **品質:** **近似あり**。slot数が少ないほどnative expert不在の影響が増える。
- **注意点:** Jetson実機だが、taskは要約・日本語LM中心でmodern 70B級MoEやSSD階層は未評価。

### 実機条件
Jetson NanoとJetson AGX Orinを用い、SwitchT-16/32/64はSAMSum要約、GPTSANはJapanese Wikipedia language modelingで評価した。

### 代表的な結果
Switch Transformerではmemoryを14.2 GiBから4.7 GiBへ削減し、同時にlatencyを50%削減、ROUGE-2低下を0.041に抑えた。これはACL 2024最終版のabstractにも記載された代表値である。

SwitchT-16ではmemory budgetを変えた際、実測peak 1.64–3.99 GiBの範囲でlatencyとROUGE-2のtrade-offを調整できる。memoryを増やせば常にlatencyが単調に下がるわけではなく、swap patternやplanner誤差にも左右される。

Jetson NanoでSwitchT-64を約14 GiBから2.6 GBへ落とした条件では、SwapMoEはstatic pruningより品質を大きく維持した。一方On-demand方式はnative expertを読み込めるため品質は守りやすいが、毎回のweight transferでlatencyが大きい。

## 既存研究との差と限界
static pruningと違って元expertをRAMに保持して後から再利用でき、単純なon-demand swapよりexpert再利用を増やして転送回数を抑える。一方で近似推論なのでmemory budgetを絞るほど品質低下があり、主評価はJetson級端末と比較的小規模なSwitch Transformer / GPTSANである。現代的な大規模MoE、NVMe階層、multi-GPU環境で同じtrade-offが成立するかはこの評価からは分からない。

## 一般的な実装への示唆
expertを「常駐か削除か」の二択にせず、限られたGPU slotへ実expertを動的に割り当てることで、再学習なしでもmemory budgetを連続的に調整できる。ただし、expert転送を減らすほどnative routingからの近似が増えるため、latency・memory・qualityを同時に測る必要がある。
