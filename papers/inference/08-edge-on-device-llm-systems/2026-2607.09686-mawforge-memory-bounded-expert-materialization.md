# MawForge: Memory-Bounded Expert Materialization for Local Mixture-of-Experts Inference

> full MoE modelをdiskへ置き、共通tensorを常駐させながらroutingされたexpertだけをbounded cacheへmaterializeして、Apple Siliconの明示的memory budget内で大きなGGUF MoEを動かすsystem。

## 問題設定
MoEはactive parameterが少なくても、一般的なlocal runtimeではfull weight、KV cache、runtime buffer、OS headroomが高速memoryへ収まる必要がある。expert cacheを大きくすればhit rateは上がるが、unified memory pressureによって逆にthroughputが落ちる可能性がある。

## 手法
MawForgeはmodelを共通tensorとexpert tensorへ分けたsplit-pack構造でdiskへ保存し、routing結果に応じて必要expertだけをexecution cacheへmaterializeする。cache sizeは明示的memory budgetから制約し、KV cacheやruntime headroomと競合しない範囲で調整する。

## 評価条件
MacBook Pro M5 Pro、24 GB unified memoryで18 GiBのserving budgetを設定し、3 model profile、5 cache設定、2 context length、4 prompt class、各5 repetitionからなる600-row matrixを評価した。Qwen3.6 35B A3B Q8_0の約34 GB profileやGemma 4 26B A4B Q8_0の約25 GB profileを含む。

## 主要結果
static plannerは30種類のmodel/context/cache cell中27を実行可能と判定し、実行可能な540 generation rowはmemory guardを発火せず96-token completionを返した。重要なのは**cache hit rate最大化とthroughput最大化が一致しない**点で、Qwen Q8では15% cacheが4K/32K contextの双方で最良、Gemma Q8では実行可能点の中で35%が良かった。大きすぎるcacheはhost memory pressureでlatencyを悪化させた。

## 限界
単一のApple Silicon machine、限られたmodel profile、短い固定completionでの検証であり、一般的なGPU serverや長時間servingへ直接一般化できない。論文自身もcache-maximization policyではなく、bounded execution mechanismとmeasurement substrateとして位置付けている。

## 既存研究との差
MoE-Infinityなどがexpert localityを利用してGPU cache hitを高めるのに対し、MawForgeはlocal unified-memory machineで**memory上限を破らないことを第一制約**とし、disk materializationとKV/context/cache budgetの相互作用を測る。

## 一般的な実装上の含意
local MoEではexpert cacheを空きRAMいっぱいまで増やすのが最適とは限らない。KV cache、OS pressure、quantization、context lengthまで含めてcache budgetを決める必要があり、特にunified memoryではresident footprint自体がthroughputへ影響する。

## 引用関係
