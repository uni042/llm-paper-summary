# CATS: Cascaded Adaptive Tree Speculation for Memory-Limited LLM Inference Acceleration

**一文解説:** CATSは、フラッシュからDRAMへの重み転送が支配的なメモリ制約端末で、浅い自己ドラフト、途中層の訂正、木構造の最終検証を一つの転送計画に組み込み、追加ドラフトモデルを常駐させず最大5.08倍の実時間高速化を実現する。

## 書誌情報

Yuning Han、Yangchenchen Jin、Dylan Zhao、Jingwei Sunによる2026年5月のarXiv論文。主分類は機械学習（cs.LG）、副分類は人工知能（cs.AI）。対象は、モデル全体をDRAMへ常駐できず、重みをフラッシュから逐次読み込むエッジ端末での大規模言語モデル推論である。

## 概要

通常の投機的デコード（speculative decoding）は、小さなドラフトモデルが候補トークンを先に作り、大きな対象モデルが複数候補を一括検証することで、対象モデルの重み読み出しを複数トークンへ償却する。しかし、既存方式の多くは対象モデルとドラフトモデルを高速メモリへ同時常駐できることを暗黙に仮定する。Jetson級の端末ではこの前提が崩れ、フラッシュとDRAMの間の転送が支配的になるため、ドラフトモデルの追加重みそのものが負担になる。

CATSはこの環境に合わせ、対象モデル自身の浅い層を使う自己投機的デコード（self-speculative decoding）を三段階に分解する。浅いドラフト段、途中層による浅い検証段、残りの層による最終検証段をDRAM容量に合わせて配置し、途中で生じた訂正候補を木構造にまとめて最後の重い層を一度だけ通す。Vicuna-7B/13BとLLaMA2-7B/13Bを実機エッジ環境で評価し、生成品質を落とさず最大5.08倍の実時間高速化、比較した最良方式に対して最大1.45倍の改善を報告する。

## 問題設定

サーバでは高帯域メモリ（High-Bandwidth Memory; HBM）に対象モデルと補助モデルを置けるため、デコードの主要コストはHBMから演算器近傍への重み供給になる。一方、論文が想定するエッジ環境では共有DRAMが16GB以下程度で、7Bモデルの半精度重みだけでも約14GBを要する。OSや作業領域も必要なので、モデル全体を常駐させられず、約2GB/s級のフラッシュからDRAMへ重みを毎回搬送する必要がある。

このとき単に投機候補数を増やしても、補助モデルや追加アダプタの重み転送が増えれば利得を相殺する。実測でも、サーバからJetson AGX Orinへ移すとKangarooとEAGLEの高速化率がそれぞれ19.8%と24.5%低下した。したがって最適化対象は演算回数だけではなく、「限られたDRAMへどの層をいつ読み、何個の候補をその一回の転送で処理するか」である。

## 手法

CATSの入力は現在までの生成系列と、端末のDRAM予算、対象モデルの層構成である。まずドラフト境界を決め、最初の数層と軽量アダプタだけを使って候補を逐次生成する。次にDRAMへ載せられる中間層までを浅い検証器として使い、候補列を並列評価する。最後に残りの層をフラッシュから順に読み込み、ドラフト本線と訂正枝を一つの検証木として一括処理し、受理できる最長接頭辞を確定する。

### 浅いドラフト

ドラフトモデルは対象モデルの1層目からドラフト境界までを再利用する。境界を深くすれば候補品質は上がるが、一候補を作るたびの演算と常駐メモリが増えるため、CATSはあえて浅く保つ。既定評価ではドラフト境界を3層、ドラフト反復回数を5回としており、5個の候補トークンを逐次生成する。

この設計の出力は単なる候補列であり、まだ対象モデルの最終判断ではない。浅い部分の予測が外れても、そのまま誤ったトークンを確定せず次段の浅い検証と最終検証へ渡すため、生成品質を対象モデルから逸脱させない。失敗時の代償は主に受理長の短縮であり、正しさではなく高速化率が落ちる構造になっている。

### 浅い検証と訂正枝

ドラフト境界より後から浅い検証境界までの中間層は、各サイクルでドラフト層と一緒にDRAMへ読み込まれる。ドラフトした複数候補をこの中間層へ並列に通し、各位置で浅い検証器が予測したトークンとドラフト候補を比較する。一致すれば本線を維持し、不一致なら浅い検証器の予測を訂正候補として保持する。

重要なのは、訂正候補を作るために新たなフラッシュ転送を発生させない点である。すでにDRAMへ載っているドラフト層と中間層を再利用し、訂正候補を浅い検証境界まで再計算する。したがって浅い予測が外れても、その場で対象モデル全体をもう一度読み直すのではなく、転送済みの層だけで訂正枝を準備できる。

### 木構造の最終検証

本線のドラフト候補と各位置の訂正候補は検証木へまとめられ、木構造用の注意マスク（attention mask）で依存関係を表す。残りの対象モデル層はフラッシュからチャンク単位で順にDRAMへ読み込まれ、この木全体を一回の並列前向き計算で処理する。対象モデルの判定で受理できる最長接頭辞だけを出力へ確定し、KVキャッシュを更新する。

この構成では、重い後半層の転送一回あたりに本線だけでなく複数の訂正枝も評価できる。浅い検証が正しければ受理長が伸び、外れても最終対象モデルが枝を選び直す。候補木が有効でない場合は受理トークン数が減って通常デコードへ近づくため、主なリスクは性能利得の縮小である。

### 上位確率トークンに絞った蒸留

浅いドラフトと浅い検証器の能力不足を補うため、CATSは縮約KL損失（Reduced KL Loss）を使う。通常の知識蒸留では語彙全体について対象モデルの確率分布へ合わせるが、受理判定にほとんど影響しない低確率語まで勾配を配ると、小容量アダプタの学習信号が薄まる。

そこで対象モデルが高い確率を与えた上位K個のトークンだけを取り出し、その集合内で確率を再正規化して蒸留する。入力は対象モデルと浅いアダプタの分布、出力は受理に関係しやすい候補へ集中した学習信号である。上位集合が対象モデルの判断を十分表さない例では改善が小さくなり得るが、最終検証は対象モデル自身が行うため生成分布の安全弁は残る。

## 評価条件

評価モデルはVicuna-7B/13BとLLaMA2-7B/13B、タスクはSpec-Bench、MT-Bench、GSM8K、Alpaca、HumanEvalの5種で、対話、コード、数学推論、指示追従を含む。比較対象はREST、Lookahead、Kangaroo、Medusa、EAGLEなど。受理長はB200 GPUサーバで、実時間高速化はNVIDIA Jetson AGX Orinで測定しており、サーバ上の候補品質とエッジ上の実時間性能を区別している。

既定設定はドラフト5回、ドラフト境界3層、浅い検証境界15層で、7Bモデルでは8GB、13Bモデルでは12GB程度のエッジメモリ予算に対応する。アダプタ学習にはShareGPTの68,000標本を使い、Vicunaでは学習率1e-6、LLaMA2では1e-5、B200 GPU 2基で13時間以内に学習している。

## 主要結果

Vicuna-7Bの貪欲デコードでは、CATS単体の平均受理長が3.0598、平均実時間高速化が3.18倍となり、Kangarooの1.92倍やMedusaの2.49倍を上回る。EAGLEの候補分岐を検証木へ組み込む構成では平均受理長3.7050、平均3.71倍まで伸びる。論文全体では条件により最大5.08倍の高速化を報告し、メモリ制約下の最良比較方式に対して最大1.45倍高速としている。

これらの数値は単なる理論演算量ではなく、Jetson AGX Orin上の壁時計時間を含む。CATSの利点は、候補生成の演算を最小化することより、フラッシュから読み込んだ層をドラフト・訂正・木検証で再利用し、一回の重い転送から確定できるトークン数を増やすことにある。

## 既存研究との差

Kangarooなどの自己投機方式は対象モデルの浅い層を使う点では近いが、主にメモリ常駐モデルを前提としてドラフト品質と検証回数を最適化する。CATSはフラッシュ―DRAM転送を第一級の設計変数にし、浅い検証器による訂正枝を作ってから後半層を一回だけ流す点が異なる。EAGLEやMedusaのような高性能候補生成器とも排他的ではなく、EAGLEの枝をCATSの木へ追加できる。

LLM in a Flashなどの重み退避研究はフラッシュからの重み移動量を減らすが、投機的デコードの受理構造そのものは扱わない。CATSは重みが退避されることを前提に、投機的デコードの段階境界と検証木を転送計画へ合わせるため、推論アルゴリズムとメモリ階層の協調設計に位置付けられる。

## 限界・実装状況

評価はJetson AGX Orinを中心とする実機研究であり、端末のフラッシュ帯域、DRAM容量、演算性能の比率が変われば最適な層境界も変わる。論文は小バッチの遅延重視環境では重み転送が主要因としてKVキャッシュを主対象から外しており、長文脈や大バッチでKVキャッシュが支配的になる環境では追加の管理が必要になる。

また、浅いドラフトと検証器には事前学習したアダプタが必要で、完全な学習不要方式ではない。縮約KL損失や境界選択の効果は対象モデルとタスクに依存する可能性がある。それでも最終段は対象モデルによる検証なので、候補品質が悪い場合の主な失敗形態は受理率低下と高速化率低下であり、近似候補を無条件に確定する方式ではない。
