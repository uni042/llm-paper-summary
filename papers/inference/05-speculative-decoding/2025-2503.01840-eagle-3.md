# EAGLE-3: Scaling up Inference Acceleration of Large Language Models via Training-Time Test

> 特徴回帰制約を外して直接トークン予測し、訓練時に自己生成入力を再投入することでドラフト学習のデータ規模拡大を有効化したEAGLE系投機的復号。
## 書誌情報
- **著者**: Yuhui Li, Fangyun Wei, Chao Zhang, Hongyang Zhang
- **公開**: arXiv preprint
- **種別**: Preprint
- **対象**: 投機的復号、ドラフトモデル、訓練時テスト、多層特徴融合、SGLang、vLLM
- **実装**: SafeAILab/EAGLEでコード公開。EAGLE-2の動的ドラフト木と互換で、SGLangおよびvLLM統合評価を実施。
## 概要
EAGLE-3は、投機的復号のドラフトモデルを特徴予測から直接トークン予測へ変更し、訓練時に自己生成した中間表現を次段入力へ戻す訓練時テストで多段予測時の分布ずれへ適応させる手法である。EAGLE/EAGLE-2が対象モデル最上層特徴の次特徴を回帰する制約を持つため訓練データを増やしても改善が飽和する問題を解き、低・中・高層特徴を融合してより豊かな対象モデル情報を再利用する。EAGLE-2の動的ドラフト木と厳密な投機的サンプリング検証を維持し、Vicuna、Llama 3.1/3.3、DeepSeek-R1蒸留モデルで自己回帰比最大約6.5倍、EAGLE-2比20〜40%の改善を示す。SGLangではH100・バッチ64でも1.38倍のスループットを達成する。

EAGLE-3は特徴回帰損失を廃止して直接トークン予測へ移り、その自由度増加で生じる訓練・推論分布ずれを、訓練中に実際のドラフト推論ステップを模擬して自己出力を次段へ戻す訓練時テストで解く。さらに最上層特徴だけでなく対象モデルの低・中・高層特徴を連結・射影して使い、次トークンだけに最適化された最上層表現より多様な意味情報をドラフトへ与える。これにより訓練データ量を増やすほど受理率・高速化が伸びる規模拡大則をEAGLE系で初めて観測する。

代表結果として、Vicuna-13B温度0平均高速化はMT-Bench/HumanEval/GSM8K/Alpaca/CNN-DMで通常自己回帰1.0倍；EAGLE-2平均4.22倍に対して5.51倍、平均受理長6.62。特徴制約除去と訓練時テスト、多層特徴融合でドラフト受理長が伸びる。
## 問題設定
投機的復号は小さなドラフトモデルで複数候補トークンを先に生成し、大きな対象モデルで並列検証することで自己回帰の逐次性を緩和する。EAGLEは対象モデル最上層の特徴を再利用し、次の特徴を回帰してから対象モデルのLM headでドラフトトークンを得るため標準投機より高い受理率を得るが、特徴回帰損失がドラフト表現を対象モデルの最上層特徴へ拘束する。著者らは訓練データを増やしてもEAGLEの受理率・高速化が十分伸びないことを観測し、特徴予測制約が表現力を抑えると分析する。制約を単に外すだけでは一段目の出力が真の対象特徴から離れ、二段目以降で訓練時に見ていない自己生成入力が増えて受理率が急落する。
## 新規性
EAGLE-3は特徴回帰損失を廃止して直接トークン予測へ移り、その自由度増加で生じる訓練・推論分布ずれを、訓練中に実際のドラフト推論ステップを模擬して自己出力を次段へ戻す訓練時テストで解く。さらに最上層特徴だけでなく対象モデルの低・中・高層特徴を連結・射影して使い、次トークンだけに最適化された最上層表現より多様な意味情報をドラフトへ与える。これにより訓練データ量を増やすほど受理率・高速化が伸びる規模拡大則をEAGLE系で初めて観測する。
## 手法
### 手法のあらまし
対象モデルの事前充填または直前検証時に、各トークン位置について低層・中層・高層の隠れ特徴l,m,hを保存する。三つのk次元特徴を連結して3k次元にし、全結合層でk次元へ戻した融合特徴gを作る。ドラフトモデルは単一Transformer decoder層を核とし、対象モデルから既に検証済みの位置ではgを文脈として使う。次のドラフトを生成する際は、直前にサンプリングされたトークンの埋込みeも入力へ連結し、全結合層でk次元化してdecoderへ渡す。decoder出力aを対象モデルのLM headへ入れてドラフトトークンを直接サンプリングする。一段目以降では新しいトークンはまだ対象モデルで検証されていないため真の融合特徴gを得られない。そこで直前段のドラフトdecoder出力aを、その未検証位置のgの代替として次のステップへ再投入する。訓練でもこの推論経路を再現し、通常の教師データを一度処理した後、生成したaを次段入力として複数ステップ回す。自己生成分岐は木状依存を持つため自己注意マスクを対応する木構造へ変更し、元教師系列をkeyとする部分以外は位置対応の内積だけを計算して無駄な行列演算を避ける。特徴回帰損失は使わずトークン予測を直接学習するため、aは対象最上層特徴へ近づく必要がなく、多段ドラフトで役立つ内部表現を自由に形成できる。推論ではEAGLE-2の文脈依存動的ドラフト木をそのまま採用し、ドラフト信頼度で木を拡張・枝刈りする。生成された木を対象モデルの木注意で一括検証し、厳密な投機的サンプリング受理規則に従って先頭からトークンを受理するため、対象モデルの生成分布を変えない。受理後に得た対象モデルの低・中・高層特徴を次サイクルのgとして再利用し、このドラフト・検証を繰り返す。

### 特徴回帰制約の除去と直接トークン予測
EAGLEではドラフト出力を対象モデル次位置の最上層特徴へ近づける特徴損失とトークン損失を併用するが、EAGLE-3は特徴回帰を完全に外す。最終目的はドラフトトークンの受理であり、対象モデルの一意な最上層特徴そのものを再現する必要はないという判断で、decoder出力aをLM headへ直接渡してトークンを予測する。Llama 3.1 8Bの構成要素除去ではEAGLE-2のMT-Bench 3.16倍から特徴制約除去だけで3.82倍、平均受理長4.05から5.37へ改善し、表現自由度が実際の受理率へ効くことを示す。

### 訓練時テストによる自己生成入力への適応
特徴制約を外すと一段目のaは真の対象特徴gから離れるため、推論二段目以降は自己生成aを入力する分布ずれが生じる。EAGLE-3は訓練中に一段目の出力aを生成し、それを二段目、さらに次段へ実際に再投入することで、テスト時と同じ自己回帰入力を経験させる。木状に分岐する予測へ合わせて自己注意マスクも変更し、元教師系列との注意以外は対応位置のベクトル内積へ簡略化する。これにより自己予測値が入力へ増えても受理率がほぼ維持され、EAGLEで見られる多段誤差蓄積を抑える。単なる教師強制では学べない『自分の近似表現を次の文脈として処理する能力』を明示的に訓練するため、特徴回帰制約を外しても二段目以降の受理率を維持でき、追加訓練データの効果が多段ドラフト全体へ伝わる。

### 低・中・高層特徴の融合
対象モデル最上層特徴はLM headの次トークンlogitへ直接対応し、次々トークン以降の予測に必要な情報としては制約が強い。EAGLE-3は低層・中層・高層から各k次元特徴を取り出し、3k次元連結後に全結合層でk次元へ射影して融合特徴gを作る。特徴回帰制約を外したことで入力を最上層特徴に限定する必要がなくなり、異なる抽象度の意味情報をドラフトへ供給できる。構成要素除去では特徴制約除去後の3.82倍から融合特徴追加で4.40倍へ、平均受理長5.37から6.13へさらに改善する。

### EAGLE-2動的ドラフト木と厳密検証
推論側はEAGLE-2の文脈依存ドラフト木を継承し、ドラフトモデルの信頼度から受理されやすい枝へ計算資源を配分する。固定木より難易度に応じて候補数を調整し、木注意で対象モデルが複数候補を一括検証する。温度0だけでなく温度1でも厳密な投機的サンプリング受理条件を使い、拒否時は対象分布とドラフト分布の差から補正サンプルを取るため生成分布を変えない。EAGLE-3の改善はドラフト精度を上げるものであり、この損失なし検証機構と独立に組み合わせられる。ドラフトが外れた場合も対象モデルの検証結果で正しい分布へ補正されるため、受理率向上は品質を犠牲にした近似ではなく、同一出力分布のまま対象モデル前向き回数を減らす方向へ使われる。

### 全体のデータ／制御の流れ
対象モデルから三層特徴を取得・融合する前処理、単一decoder層のドラフトモデル、訓練時テスト用木状自己注意、EAGLE-2由来の動的ドラフト木、対象モデルによる木注意一括検証から構成される。コードはSafeAILab/EAGLEで公開され、SGLangとvLLMで大バッチスループットも評価される。
## 評価条件
- **ハードウェア**: 対象モデルはVicuna-13B、Llama 3.1 Instruct 8B、Llama 3.3 Instruct 70B、DeepSeek-R1-Distill-Llama 8B。GPU制約により405B・671Bは未評価。SGLang v0.4.4の生産系評価は単一H100、Llama 3.1 8B。vLLM大バッチ評価は同8Bモデルで実施。
- **ソフトウェア**: SafeAILab/EAGLE実装。EAGLE-2の動的ドラフト木と互換。比較対象は通常自己回帰、標準投機的サンプリング、PLD、Medusa、Lookahead、Hydra、HASS、EAGLE、EAGLE-2。SGLang v0.4.4とvLLMへ統合してスループットも評価。
MT-Bench、HumanEval、GSM8K、Alpaca、CNN/DailyMailの5タスクを同一ドラフト重みで評価し、温度0と1を測る。速度倍率は通常自己回帰を1.0とし、平均受理長τとn段自己予測入力時の受理率も測定。ドラフト訓練はShareGPT約68K、UltraChat-200K約464Kを使い、対象モデル自身に応答を生成させる。DeepSeek-R1蒸留8BではOpenThoughts-114k-mathも追加。AdamW、β=(0.9,0.95)、学習率5e-5、勾配クリップ0.5。SGLangでは木を使わずchain length 3、バッチ2〜64、vLLMではchain length 2、バッチ2〜56でMT-Benchを評価。
対象モデルの厳密検証を使う損失なし投機的復号であり、品質向上ではなく受理率・遅延・スループットを対象とする。ドラフトモデルを対象モデルごとに訓練する必要があり、学習データ拡大が前提。大規模405B/671Bは未評価で、SGLang/vLLMの大バッチ評価では完全な動的ドラフト木を使わない簡略条件も含む。
## 主要結果
温度0ではEAGLE-3はVicuna-13Bで5タスク平均5.51倍、Llama 3.1 8Bで4.44倍、Llama 3.3 70Bで4.12倍、DeepSeek-R1蒸留8Bで4.16倍の自己回帰比高速化を達成し、各モデルでEAGLE-2を20〜40%上回る。最大はVicuna-13B HumanEvalの6.47倍、平均受理長7.54。温度1でもVicuna平均4.65倍など優位を維持する。SGLangではH100・バッチ1で158.34から373.25トークン/秒へ増加し、バッチ64でも1.38倍のスループットを保つ。

- Vicuna-13B温度0平均高速化 / 5.51倍、平均受理長6.62 (比較対象: 通常自己回帰1.0倍；EAGLE-2平均4.22倍; 条件: MT-Bench/HumanEval/GSM8K/Alpaca/CNN-DM) — 特徴制約除去と訓練時テスト、多層特徴融合でドラフト受理長が伸びる。

- 最大高速化 / 6.47倍、平均受理長7.54 (比較対象: 通常自己回帰; 条件: Vicuna-13B、HumanEval、温度0) — コード生成の固定的構造はドラフトしやすく長い連続受理を得る。

- Llama 3.1 8B構成要素除去 / EAGLE-2 3.16倍→特徴制約除去3.82倍→多層融合4.40倍 (比較対象: EAGLE-2; 条件: MT-Bench、温度0) — 二つの主要設計変更がそれぞれ独立に速度・受理長へ寄与する。

- SGLangバッチ1スループット / 373.25 トークン/s (比較対象: SGLang通常158.34、EAGLE-2 244.10 トークン/s; 条件: 1x H100、Llama 3.1 8B、MT-Bench) — 生産向け実装でもドラフト精度向上が実スループットへ反映される。

- SGLang大バッチスループット / バッチ64で1.38倍 (比較対象: 投機なしSGLang 1.0倍；EAGLE 0.99倍; 条件: 1x H100、chain length 3、木なし) — 従来EAGLEが大バッチで計算余剰を失って逆効果になる条件でも利得が残る。

- vLLM大バッチ / バッチ2で1.75倍、24で1.42倍、56で1.01倍 (比較対象: 投機なしvLLM; 条件: Llama 3.1 8B、MT-Bench、chain length 2) — バッチ増加で利得は縮むがEAGLEより高いバッチまで正の効果を維持する。

### 負の結果・境界条件
- 投機的復号の一般的制約としてバッチが増えるほど対象モデル計算資源の余剰が減り利得は縮小する。vLLMではバッチ56で1.01倍まで低下する。405Bと671BはGPU制約で未評価。特徴回帰制約だけを外して訓練時テストを行わない場合、一段目受理率は上がるが二段目以降は自己生成入力と訓練分布のずれで受理率が大幅低下するため、単純な制約除去だけでは成立しない。

### 結果の読み方
EAGLE-3の本質はドラフトモデルを対象モデルの最上層特徴模倣器として扱うのをやめ、多段トークン予測器として直接訓練する点にある。自己生成した内部表現を訓練時にも入力することで推論時分布へ合わせ、さらに複数層特徴を使うことで一段先専用の最上層表現から解放する。この表現自由度が追加データを受理率向上へ変換し、結果として検証1回あたりの受理トークン数を増やす。
## 品質への影響
厳密な投機的サンプリング受理規則で対象モデルの確率分布を保存するため、生成品質は通常自己回帰と同一という前提の損失なし高速化。温度1でも同じ受理補正を使い、Medusa等の受理条件緩和方式とは区別される。
## 既存研究との差
EAGLE/EAGLE-2は対象モデル最上層特徴の次特徴を回帰し、特徴損失でドラフトを拘束するのに対し、EAGLE-3は特徴回帰を廃止して直接トークン予測し、自己生成内部表現を次段入力へ使う。HASSも訓練時に多段推論を模擬するが、目的はEAGLEの特徴予測誤差蓄積緩和であり、特徴損失と最上層特徴入力を維持する。EAGLE-3は表現制約自体を外し、低・中・高層特徴融合を導入する点が異なる。Medusa/Hydra等の複数ヘッド方式に対しては対象特徴を再利用する単一decoder型ドラフトを使い、EAGLE-2の動的木を継承する。
## 限界
ドラフトモデルは対象モデルごとに別途訓練が必要で、ShareGPT/UltraChat等に対象モデル自身の応答を生成させる学習費がある。データ規模拡大で受理率が伸びることは示すが、405B・671B級はGPU制約で未評価。生産系大バッチでは計算余剰が減るため利得が縮み、vLLMバッチ56では1.01倍まで低下する。SGLang/vLLMの大バッチ実験は完全な動的木ではなく短いchainを用いるため、論文主要表と条件が異なる。多層特徴を対象モデルから取得するため実装側が中間層特徴を効率的に露出する必要もある。
## 実装状態
SafeAILab/EAGLEリポジトリでコード公開。EAGLE-2の動的ドラフト木と互換で、SGLang v0.4.4では単一H100上でバッチ64まで、vLLMでも大バッチスループットを評価。SGLangチームによる統合・評価結果も論文へ掲載されている。
## 研究上の位置づけ
投機的復号のEAGLE系統において、特徴レベル自己回帰から直接トークン予測へ転換し、訓練時テストで多段自己生成入力を学習分布へ取り込んだ後継手法。ドラフトモデルの性能を単に大きくするのではなく、訓練データ量を増やすと受理率・高速化が伸びる構造へ変更した点が重要である。また単一要求の低遅延だけでなく、SGLang/vLLMで従来EAGLEが不利になる大バッチ域まで正のスループット効果を延長しており、実運用の投機的復号比較で主要な基準点になる。
