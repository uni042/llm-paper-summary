# Sangam：DRAMと演算ロジックを分離するCXL接続チップレットPIM

## 概要

LLMの復号段階では、一つの出力トークンを作るたびに大きな重み行列と過去のKVキャッシュを読み出す。バッチが小さいと行列積は実質的に行列とベクトルの積になり、GPUの大量の演算器を十分に使えないまま外部メモリの帯域が律速になる。メモリ内処理（processing-in-memory、PIM）は、DRAMの内部バンク帯域を利用してデータをGPUへ往復させる費用を減らすが、従来のDRAM一体型PIMでは演算器の面積を確保するとメモリセル容量が減り、DRAM製造プロセス上の演算器は高速・複雑な行列積に不向きだった。

SangamはDRAMバンクを含む**メモリチップレット**と、演算器・制御・SRAMを含む**ロジックチップレット**を別の製造プロセスで作り、同一インターポーザ上で結合する。ロジック側に8×8の小型シストリック配列と16レーンのSIMD演算器を置き、各DRAMバンクの内部帯域を直接利用する。モジュールはPCIe 6.0上のCXL Type 3機器としてCPUへ接続し、複数モジュールにモデル重みとKVキャッシュを配置できる。GPUを使わずに推論する構成と、計算集約的な処理をGPUへ任せる協調構成の両方を設計対象とする。

著者らは専用の階層アーキテクチャ評価器HARMONIを用い、LLMの各演算とテンソルの配置、バンク間通信、メモリ電力を考慮した性能を推定した。要旨ではH100系GPUと比較した全要求遅延の高速化として、LLaMA 2-7Bで3.93倍、Mistral-7Bで4.22倍、LLaMA 3-70Bで2.82倍、復号処理量でそれぞれ10.3、9.5、6.36倍を報告する。ただしこれらはワークロード・構成をまたいだ集計値であり、長い入力を短く要約する場合などにはGPUの方が速い。**Sangamの数値は製造済みチップの実測ではなく、論理合成と階層シミュレーションに基づく予測**である。

## 問題設定：DRAM帯域と演算能力の両立

GPUは大きな行列積に強いが、LLMの復号では行列積の行数 $M$ がバッチ数に近くなり、$M=1$ では行列ベクトル積（GEMV）になる。行列の多数の重みを読み込んでも、各重みを一回程度しか使えないため、1バイト当たりの演算数である演算密度（operational intensity、OI）が低くなる。LLaMA 2-7Bの例では、バッチ8の復号時の重み射影はおおむね8 FLOP/byte、過去のKVに対する注意スコア・値集約は約1 FLOP/byteである。一方、長い入力の事前充填では重みを多数の入力トークンで再利用でき、射影のOIは数百FLOP/byteに上がる。

この違いが、どのハードウェアを選ぶべきかを左右する。GPUの高いピーク演算能力は大きな事前充填行列積で有効だが、低OIの復号では外部メモリ帯域が先に上限へ達する。従来PIMはDRAMの内部帯域が大きいものの、メモリバンクの近くに小規模な演算器を置く設計が中心で、行列積を効率よくタイル化して再利用するためのSRAMやシストリック配列を十分に持てない。DRAMダイの中に演算ロジックを増やすと、メモリセル領域を圧迫して容量が減る。

さらに従来のバンク内PIMは、異なるバンクへ置いた行列の部分結果を集約する際、バンク間のデータ移動が高価になる。DRAM製造プロセスで大きなロジックを作ると面積効率や動作周波数でも不利である。SangamはDRAMバンクをそのまま密に作り、バンクへの高速接続を持つ制御・演算ロジックだけを先端のロジックプロセスへ移すことで、容量と演算能力を同時に確保する。

## 手法

### 1. DRAMバンクと中央制御帯を別チップレットにする

通常のDRAMチップにはメモリセルのバンクだけでなく、列デコーダ、入出力バッファ、制御回路を含む中央帯（center stripe）がある。SangamはバンクをDRAMプロセスのチップレットとして保持し、中央帯をロジックプロセスのチップレットへ移す。ロジックチップレットは複数のバンクへ直接接続し、バンクの行バッファから演算器へ高帯域でデータを流せる。論文は、中央帯が32バンクへ接続する構成と、チップ当たり最大約400GB/sの内部帯域を設計上の特徴として示す。

複数のDRAMチップレットとロジックチップレットを一つのインターポーザへ載せる構造を、複数チップ同一インターポーザ（multi-chip on one interposer、MCoOI）と呼ぶ。基本構成は一つのMCoOIに通常DRAMチップ4個分を集約し、複数MCoOIでランク、複数ランクでモジュールを構成する。DRAM側を高密度のまま維持しつつ、中央帯に計算回路とSRAMを追加できるため、演算器のためにDRAMセル面積を削る必要が小さい。

ここで重要なのは、外部CXLリンクの帯域がDRAM内部帯域と同じになるわけではない点である。CXLはCPUとモジュール間の要求・重みロード・結果通知・モジュール間通信に使い、重みやKVキャッシュを置いたモジュール**内部**で大きな行列を演算することで、細い外部リンクを毎トークン大量の重みで占有しない設計になっている。

### 2. 小型シストリック配列とSIMD演算器をバンクに結び付ける

ロジックチップレットは7nm相当のロジック製造を想定し、各バンクに8×8のFP16シストリック配列と16レーンのFP16 SIMD乗算器を対応付ける。シストリック配列は、重み・活性化を隣接処理要素へ流しながら積和する格子状の回路である。行列を小さなタイルに分割すれば、同じ値を複数の積和へ再利用でき、DRAMからの再読込みを減らせる。

大きなシストリック配列では行数の少ない平たい行列積に空き処理要素が多くなるため、Sangamは8×8という小さい配列をバンクごとに多数並列配置する。DDR5バンクの128ビットの接続幅と対応し、複数の配列を並行に動かす。単純なベクトル積や要素ごとの乗算を無理にシストリック配列へ写すと利用率が低くなるため、16レーンSIMD乗算器を別に設け、注意層のGEMVや活性化関数の要素演算を担当させる。

バンクごとの演算器は400MHzで同期動作する構成を想定する。これにより低OIの復号ではDRAMバンク帯域を生かし、高OI寄りの平たい行列積でもタイル内再利用ができる。PIMで単純なGEMVだけを並列実行する方式より、事前充填やバッチ復号に現れる中程度のOIの行列積まで効率よく処理することを狙う。

### 3. CXL接続モジュールとして要求と重みを取り込む

SangamモジュールはCXL Type 3機器としてPCIe 6.0接続され、CPUとは独立したメモリ空間を持つ。ホスト側ドライバがDMAを管理し、初期化時にモデル重みと静的コンパイル済みの推論プログラムをモジュール内へ転送する。この転送は通常、要求ごとに繰り返す必要がない。要求が到着するとホストは入力をDMA転送し、モジュール内で計算を進め、終了時に割込みでホストへ通知する。

複数モジュール間ではCXLスイッチとピアツーピアのPCIe通信を用いる。論文の基本構成では16モジュールを一つのスイッチへ接続できるというリンク数の想定を使うが、モジュール間の帯域は各モジュール内部のDRAMバンク帯域よりはるかに低い。したがって重み・KVをどのモジュールへ置き、どの計算を同じ場所で実行するかが性能に直結する。

GPUとの協調では、入力が長くて計算集約的な事前充填の大行列積をGPUへ渡し、帯域律速の復号をSangam側で処理する考え方を採る。ただし論文の主要比較はSangam構成とH100構成の推論性能モデルに基づき、製品化済みGPUとCXLモジュールを同一実機で連携させた性能測定ではない。

### 4. 重みとKVキャッシュの階層配置を計算グラフへ反映する

SangamはLLMの計算を単に演算器へ均等分配するのではなく、重み・KVキャッシュを配置した場所へ演算を寄せる。論文の階層的なテンソル配置では、ランク単位で重みとKVキャッシュを分け、チップ単位で注意ヘッドや出力列を分割し、バンク単位で行方向へ分割する。各バンク内では8×8タイルをシストリック配列へ入力固定型の順序で流す。

この配置の狙いは、巨大な重み行列やKVキャッシュそのものをモジュール間で何度も送らないことにある。計算グラフの節は、必要なテンソルが存在し、その演算を実行できるロジック節へ割り当てる。複数バンクの部分結果を足し合わせる場合は、階層上で近い共通の集約節へ部分結果を集める。転送されるのは主として中間の隠れ状態であり、LLaMA 2-7BのFP16隠れベクトルなら一つ約8KBという比較的小さな量になる。

HARMONI評価器は、この配置を使って演算グラフの依存関係を更新し、各節の計算時間、バンクやランク間の通信時間、資源待ちを積み上げる。重みランクとKVランクが交互に使われる時間帯には、空いている側でDRAMリフレッシュを行う。通信と計算のクリティカルパスを求めることで、単に理論帯域を足し合わせた速度ではなく、実際に依存する転送・集約の費用を含めて推論時間を推定する。

## 主要結果

### 全要求遅延とワークロード依存性

LLaMA 2-7Bの多数の入力・出力長とバッチ数の組合せでは、Sangam D1〜D4の全要求遅延がH100よりおおむね速く、本文では幾何平均約3.96倍を報告する。要旨の3.93倍とは集計範囲または丸めの差があり、両者を別の実験の速度改善として加算しない。CENT-8に対しても約3.49倍であり、従来の単純なPIMよりタイル化した行列積の処理能力が高いことを示す。

ただし、**入力2,048トークン、出力128トークン以下、バッチ8**という事前充填優勢の条件では、SangamはH100に対して0.55倍の速度に低下する。大きな入力の射影行列積はGPUの高い演算能力が有利で、PIMの高帯域だけでは埋められないためである。一方、バッチ1で入力2,048・出力128ではSangam D1がH100比2.76倍の全要求高速化を示し、CENT-8は0.38倍とH100より遅い。Sangamの小型シストリック配列が、単純なPIMでは不得意な平たい行列積も処理できることを裏付ける。

Mistral-7Bではグループ化問い合わせ注意（GQA）のため、注意計算の行列形状がSangamの小型配列に適する。D3はバッチ1で7.37倍、バッチ8で2.2倍、D4はそれぞれ7.82倍、1.96倍という条件別の高速化を報告する。LLaMA 3-70Bは一台のH100に収まらないため、二台のH100と512GBのSangam D5を比較する。本文ではバッチ1のD5がH100二台比で幾何平均4.2倍、従来PIMのCENT-32との比較では0.89倍へ下がる条件も示す。比較対象とバッチ数を揃えずに「70Bでも常に4.2倍」と一般化するのは不適切である。

### 復号処理量と初回トークンの交換条件

復号段階は重みとKVの繰返し読出しが律速になりやすく、LLaMA 2-7BのSangam構成はH100に対して本文で約10.48倍の復号処理量を示す。要旨ではモデル別の代表値としてLLaMA 2-7Bで10.3倍、Mistral-7Bで9.5倍、LLaMA 3-70Bで6.36倍を掲げる。これは**復号の処理量**であり、事前充填を含む全要求遅延が同じ倍率で短くなることを意味しない。

初回トークン遅延（TTFT）については、入力が大きいとGPUの事前充填が有利になる。論文のSLO交差点分析では、バッチ1のSangamは検討した入力長でSLO違反を生じない条件が多いが、バッチ8では厳しい0.5秒・1.5秒のSLOに対し入力長の許容上限がそれぞれ約425・1,129トークンとなる。3秒のSLOでは2,048トークンまで違反しないという条件も示す。したがって、復号処理量が高いことだけで、厳しいTTFTを満たす長い入力のサービスに最適とは限らない。

### 容量・並列度・通信の感度

Sangamのモジュール数やランク数を増やすと演算器とメモリバンクが増え、計算待ち行列が短くなる。一方で、複数ランク・モジュール間の部分結果集約が増えると通信の割合が上がる。論文の遅延内訳では、構成を変えると通信の全要求遅延に占める比率が14.5%から28.5%へ増える条件があり、演算資源を増やすだけでは比例した速度改善を得られない。

ランクやチップが少ない構成ではタスク待ちが増え、待ち行列の遅延比率が約21〜23%へ変化する。大きな入力は中間活性化の通信量を増やすため、復号中心の短いベクトルをやり取りする場合よりCXL側の転送費用が目立つ。Sangamの性能は、DRAM内部帯域の総量だけでなく、階層配置と通信のクリティカルパスに依存する。

### 面積・電力・価格推定と負の結果

中央ロジックチップレットのPIM演算器は約0.98平方ミリメートル、約185ミリワットと推定される。DRAMの全バンク読出し電力を加えたチップ当たり電力は約1.92ワット、16チップ相当のモジュールでは約30.7ワットとなる。ロジックだけの電力よりDRAMのデータ移動の電力が大きく、推論エネルギーの内訳でもデータアクセスが支配的である。計算と通信のエネルギー割合は多くの条件で全体の約5〜20%にとどまる。

LLaMA 2-7Bでは多くの入力・出力・バッチ条件でH100に対して一桁程度のエネルギー削減を報告するが、**バッチ8、入力2,048、出力32**の条件は例外である。事前充填優勢の短出力ではGPUの計算効率が有利になる。モジュールを増やして遅延を減らしても、読み出すデータ総量が大きく変わらなければエネルギーはあまり減らず、むしろ構成によってわずかに増える。これは高並列化と省エネルギーが必ずしも同時に改善しないことを示す。

著者らはチップレットの歩留まりをインターポーザ94%、ダイ97%、実効約90%などの仮定から推定し、モジュールの製造原価を約61.99米ドルと計算する。ただしこの数値はDRAM・ロジック・接合・パッケージングの**モデル化された製造費用**であり、販売価格、CXLスイッチやホストCPUを含むシステム総費用ではない。H100側もGPUダイやHBMの原価仮定から約12,324米ドルと推定しており、市場価格との直接比較には注意が必要である。

## 既存研究との差

従来のDRAM-PIMはメモリバンク内へ小規模な演算器を置くため、低OIのベクトル積に強くても、バッチ化された平たい行列積を処理するSRAM・シストリック配列を十分に持てない。CENTはCXL接続のPIM専用推論システムとして先行するが、Sangamは演算ロジックをDRAMセルから分離したチップレットへ移し、バンク単位のシストリック配列とSIMDを併用することで、より広い行列形状に対応する。

GPUとPIMの協調や事前充填・復号の分離は他研究でも扱われるが、SangamはDRAMの**物理的なバンク構造、チップレット間接続、CXL上の階層配置**を一つのアーキテクチャとして設計し、通信と計算を含むタスクグラフで評価する点に特徴がある。モデル重みとKVキャッシュを置いた場所で演算し、中間結果だけを階層間で動かすため、外部通信の細い帯域を使って全重みを繰り返し運ぶ必要を減らす。

## 限界・適用条件

第一に、Sangamの主要性能はHARMONIという階層シミュレータによる推定であり、実際にチップレットを製造してCXL経由でLLMを実行した測定ではない。演算器の論理合成、SRAM・DRAMの電力モデル、通信の帯域・遅延モデル、GPU側の実行測定・モデルを組み合わせた比較なので、製造後の熱、信号品質、ドライバ、故障、スイッチ競合、運用時のキューイングまで保証するものではない。

第二に、Sangamの大きな内部帯域はメモリバンクの近くで演算して初めて利用できる。入力が長く、出力が短く、バッチが大きい場合はGPUの事前充填行列積が有利で、実際にH100より遅い条件がある。第三に、モジュール数を増やすと演算並列度は上がるが、CXL通信や中間結果集約の割合が増え、比例した高速化・省エネルギーにはならない。

第四に、論文の評価対象は主としてLLaMA 2-7B、Mistral-7B、LLaMA 3-70Bであり、混合専門家モデル、量子化モデル、より長い会話を複数利用者で共有する本番サービングなどで同じ改善が出るかは未検証である。第五に、製造原価・歩留まりはモデル仮定に依存し、製品価格・保守費用・CXLホストやスイッチの費用を含む総所有費用ではない。ローカルPCの既存GPUをCXLモジュールへ置き換えれば同じ性能が得られるという話ではなく、専用ハードウェアの設計提案として読む必要がある。
