## 概要

LLMのdecoder ブロックではQKV 射影とfeed-順伝播 ネットワークは大きな行列同士を掛けるGEMMになり、バッチがあれば演算密度が高い。一方、注意機構のKV読出しは生成トークンごとに過去KVを走査するGEMV寄りの処理となり、メモリ帯域が支配的になる。NPUはGEMMに強いがGEMVで演算器が遊びやすく、メモリ内処理（Processing-in-Memory; PIM）はGEMVに強いがGEMM性能が不足する。

NeuPIMsは両者を同じ推論パイプラインへ組み込み、GEMMをNPU、GEMVをPIMへ分担する。ただし単純に接続すると、同じDRAM bankをNPUとPIMが交互に占有し、Transformerのデータ依存で片方が待つ。そこでdual 行 バッファとsub-バッチ interleavingを導入し、異なるsub-バッチの独立仕事を重ねる。GPU-only比3倍、NPU-only比約2.4倍、単純統合比1.6倍のスループット改善を報告する。

## 問題設定

異種acceleratorの利点は「各カーネルを得意な装置へ置く」だけでは得られない。既存PIMは通常メモリ アクセス modeとPIM command modeを排他的に切り替えるため、NPUがDRAMへアクセスしている間にPIMが停止する。さらに同じリクエストではGEMMの出力が注意機構の入力になるため、依存関係が並列実行を妨げる。

したがってNeuPIMsは、メモリ bankの同時利用制約とモデル graph上の依存を両方崩す必要がある。

## 手法

### kernel別の異種割当

QKV 射影とFFNのGEMMはNPUへ、注意機構で支配的なGEMVはPIMへ割り当てる。NPUは高い演算密度を利用し、PIMはKVをメモリ近傍で読みながら計算することで大容量KVの外部転送を減らす。

### dual row buffer

各bankへ二つの行 バッファを持たせ、一方を通常メモリ read/write、もう一方をPIM commandへ利用できるようにする。これにより従来のblocked modeで必要だったNPU/PIMの全体切替を緩和し、同じメモリ subsystem上で異なる処理を重ねる。

### sub-batch interleaving

一つのバッチを複数sub-バッチへ分割し、sub-バッチ AがNPUでGEMMを実行している間に、依存の解けたsub-バッチ Bの注意機構をPIMで実行する。単一リクエスト内の逐次依存を消すのではなく、バッチ並列性を使って別リクエスト群の段をパイプライン化する。

### runtime pipeline

ランタイムは各sub-バッチがどの段にいるかを追跡し、NPUとPIMの両方へ仕事が供給されるようinterleaveする。片方の装置だけを速くしても他方がidleならスループットは伸びないため、段間の流量を揃えることがシステム上の核心になる。

## 評価条件

| 観点 | 内容 |
|---|---|
| 対象 | batched decoder-only LLM inference |
| compute | GEMM-focused NPU |
| メモリ compute | GEMV-focused PIM |
| 比較 | GPU-only、NPU-only、naive NPU+PIM |
| 並列化 | dual 行 バッファ + sub-バッチ interleaving |
| 主指標 | スループット |

## 主要結果

| 比較対象 | スループット改善 |
|---|---:|
| GPU-only | 約3倍 |
| NPU-only | 約2.3〜2.4倍 |
| naive NPU+PIM | 1.6倍 |

単純NPU+PIMに対しても1.6倍であることが重要で、異種deviceを併設するだけでなく、メモリ同時利用とsub-バッチ パイプラインが性能へ寄与することを示す。GPU-only比3倍は同じalgorithmを任意GPUで3倍にするsoftware高速化ではなく、専用構成比較である。

## 既存研究との差

NPU単独はGEMV時の演算利用率が低く、PIM単独はGEMM能力が不足する。従来の単純統合はmode切替と依存で同時稼働できない。NeuPIMsはdual 行 バッファというメモリ 構成変更とランタイム interleavingを一体化し、二種類のacceleratorを実際に重ねて動かす点が差である。

## 限界

専用PIM メモリとdual 行 バッファを必要とするため、既存GPU/NPUへsoftwareだけで適用できない。sub-バッチ interleavingは十分なバッチ並列性を前提とし、バッチ 1や低負荷では重ねられる独立仕事が減る。モデル構造やKV長によってGEMM/GEMV比率が変わるため、装置間の最適資源配分も変化する。
