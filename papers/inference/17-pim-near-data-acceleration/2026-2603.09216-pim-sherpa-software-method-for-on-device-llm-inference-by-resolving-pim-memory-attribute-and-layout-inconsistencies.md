# PIM-SHERPA: Software Method for On-device LLM Inference by Resolving PIM Memory Attribute and Layout Inconsistencies

> PIM向け重みを一つだけ保持し、キャッシュ可能バッファへの実行時並べ替えで前処理と生成の属性・配置矛盾を解消してDRAM容量を約半減する。
## 書誌情報
- **著者**: Sunjung Lee, Sanghoon Cha, Hyeonsu Kim, Seungwoo Seo, Yuhwan Ro, Sukhan Lee, Byeongho Kim, Yongjun Park, Kyomin Sohn, Seungwon Lee, Jaehoon Yu
- **著者・所属**: Samsung Advanced Institute of Technology; Samsung Electronics; Yonsei University
- **公開**: arXiv:2603.09216v1
- **種別**: プレプリント
- **対象**: 処理内メモリ、LPDDR、端末内推論、重み配置、二重バッファ、初回トークン時間
- **実装**: 端末内推論基盤ExecuTorchを使用し、コピー用スレッドと計算用スレッドを分けて実装する。PIM向け配置からホスト向け配置へ変換する並べ替え付きメモリコピーを実装し、LPDDR5X-PIMはPIMLibraryをARM向けに変更して模擬する。
## 概要
PIM-SHERPAは、端末内LLMで前処理段階と生成段階を同じ処理内メモリ（processing-in-メモリ; PIM）対応DRAM上で実行すると、重みのメモリ属性と配置形式が互いに矛盾する問題をソフトウェアだけで解く。前処理はキャッシュ可能な連続配置を好む一方、生成でPIMを確実に起動するにはキャッシュ不能かつDRAMバンク内に整列した配置が必要である。従来の二重重み保存は容量をほぼ倍増させる。提案はPIM向け重みを一つだけ保持し、小さなキャッシュ可能バッファへ次層重みを並べ替えながら先読みする二重バッファ方式と、長い入力では各層直前に並べ替えてコピーする逐次方式を用いる。Galaxy S24+上のLlama 3.2評価では二重保存比で約47.8〜49.7%のDRAM容量を削減し、長い入力ではハードウェア変更を仮定するFACIL相当の初回トークン時間へ近づく。

PIM-SHERPAはPIM向けのキャッシュ不能重みを正本として一つだけ保持し、前処理に必要な期間だけ小さなキャッシュ可能バッファへ重みを並べ替えて移す。第一方式は二つのバッファを交互使用して現在層の行列積と次層重みの変換コピーを重ね、コピー遅延を計算で隠す。第二方式は入力系列が十分長く計算時間が支配的な場合、各層の直前に一つのバッファへ逐次コピーして実装を簡素化する。両方式ともメモリ制御器やPIMハードウェアを変更せず、属性矛盾と配置矛盾を同時に解く。

代表結果として、DRAM容量削減はLlama 3.2 1B、二重バッファ / 逐次方式で重み二重保存に対して47.8% / 48.5%。PIM向け単一重みと32MB級の小バッファだけを保持するため、ほぼ半分の容量で両段階を実行できる。
## 問題設定
端末内LLMでは前処理が多数トークンをまとめて処理する行列行列積となり、CPUやGPUで重みを何度も再利用するためキャッシュ可能領域と通常の連続配置が有利である。一方、生成は一トークンずつの行列ベクトル積となり、帯域律速なのでLPDDR-PIMが有利だが、PIM演算はDRAM要求がメモリ制御器まで届くことで起動するため重みをキャッシュ不能領域へ置く必要がある。またPIMは各DRAMバンク内に行列行を連続配置する専用配置を要求する。この属性と配置の二重矛盾に対し、既存HBM-PIM等はホスト用とPIM用の重みを二重保存して容量をほぼ倍増させる。FACILは配置問題をハードウェア変更で解くが属性問題は残る。
## 新規性
PIM-SHERPAはPIM向けのキャッシュ不能重みを正本として一つだけ保持し、前処理に必要な期間だけ小さなキャッシュ可能バッファへ重みを並べ替えて移す。第一方式は二つのバッファを交互使用して現在層の行列積と次層重みの変換コピーを重ね、コピー遅延を計算で隠す。第二方式は入力系列が十分長く計算時間が支配的な場合、各層の直前に一つのバッファへ逐次コピーして実装を簡素化する。両方式ともメモリ制御器やPIMハードウェアを変更せず、属性矛盾と配置矛盾を同時に解く。
## 手法
### 手法のあらまし
モデル重みは最初からPIM向けのバンク内配置で、PIMを確実に起動できるキャッシュ不能DRAM領域へ一つだけ保存する。生成段階ではこの重みをそのまま使い、ホストが通常のDRAM読出し要求を発行してPIMの積和演算を起動する。前処理へ入ると、PIM向け配置のままではホスト側行列積の連続アクセス効率が悪く、キャッシュも使えないため、PIM-SHERPAは必要な層だけを小さなキャッシュ可能バッファへ移す。この移動では重み行列の要素座標からPIM向け物理オフセットを計算し、コピーと同時にホスト向け連続配置へ並べ替える。二重バッファ方式では二つのバッファを用意し、一方で現在層の行列行列積を実行している間に、別のコピー用スレッド群が次層重みをもう一方へ並べ替え付きコピーする。層が進むたびに二つの役割を交換し、Q・K・V・Oやフィードフォワード層の大きさに合わせて転送を分割して負荷を均す。入力系列が長く、行列積時間がコピー時間より十分長いときはコピーが計算の背後へ隠れる。逐次方式ではバッファを一つだけ用意し、各層の直前に必要重みを並べ替えてコピーし、その完了後に通常の行列積を実行する。こちらはコピーと計算を重ねないため遅いが、同期と負荷分散が単純で、長い入力では固定コピー費用の割合が小さくなる。前処理終了後に恒久的なホスト用重みを残す必要はなく、生成は元のPIM向け単一重みへ戻るため、二重保存を避けながら両段階を実行できる。

### DRAM二重バッファ
キャッシュ可能領域へ最大フィードフォワード層二つ分の小さなバッファを確保し、現在層を一方から計算している間に次層重みを他方へ転送する。コピー用スレッドはPIM向けキャッシュ不能領域から読み、配置を変換して書き込む。計算用スレッドは変換済みバッファを通常の最適化行列積ライブラリから読む。層ごとに一度同期し、次層ではバッファの役割を交換する。Q、K、V、O層はまとめて一方へ置き、巨大なフィードフォワード重みは複数の前段計算へ分割して先読みすることで、転送量と計算時間の不均衡を抑える。入力系列が長くなるほど行列積時間が伸びる一方、重みコピー時間はほぼ固定なので、一定長以上ではコピーを計算背後へ隠せる。

### 並べ替え付きメモリコピー
PIM向け配置では一つの行列行が特定DRAMバンク内に連続するよう配置され、ホストが好む仮想アドレス上の連続配置とは順序が異なる。コピー処理は行列要素の行・列座標からDRAMバンク、行、列に対応するPIM向けオフセットを求め、その位置をコピー元、ホスト向け連続位置をコピー先としてデータを移す。変換を行列積カーネルへ組み込む方式も考えられるが、閉鎖的な最適化ライブラリを変更しにくいため、提案はコピー経路だけで変換を完了させる。これにより既存のExecuTorch行列積を変更せず利用でき、同時にキャッシュ不能領域からキャッシュ可能領域へ移すのでメモリ属性と配置形式の二問題を一回のデータ移動で解決する。

### 逐次オンライン重み並べ替え
入力系列が十分長い場合は、各層の行列積直前に必要重みを一つのキャッシュ可能バッファへ並べ替え付きコピーし、コピー完了後に行列積を実行する。二重バッファのようなコピーと計算の重畳を行わないため固定コピー遅延は必ず加わるが、複雑な層間同期、二つのバッファ管理、コピー負荷の分割が不要になる。入力系列が伸びると前処理の行列積時間は系列長にほぼ比例して増える一方、重み一回分のコピー時間は変わらないため、相対的な損失は縮小する。評価では192入力トークンの3Bモデルで16.7トークン毎秒に達し、ハードウェア変更を理想化した比較方式へ近づく。容量は最大層一つ分だけ追加すればよく、二重バッファ方式よりさらに小さい。

### 全体のデータ／制御の流れ
ExecuTorchを基礎に、前処理はCPU上の通常行列積、生成はLPDDR-PIMの行列ベクトル積へ分担する。PIM向け単一重みをキャッシュ不能領域へ置き、前処理時だけ小容量のキャッシュ可能領域へ変換コピーすることで、同一モデルを二つの実行形態から共有する。
## 評価条件
- **ハードウェア**: Samsung Galaxy S24+のExynos 2400を使用する。大コアCortex-X4と中コアA720のうち四コアを行列積、二コアをコピーへ割り当てる。六コア合計のBF16理論性能は321 GFLOPS、LPDDR5X-8533四チャネルの帯域は68.264 GB/s。対象はLlama 3.2 1Bと3B、バッチ1である。
- **ソフトウェア**: 端末内実行基盤はExecuTorch。PIM向け配置変換器、並べ替え付きメモリコピー、二重バッファ用コピー・計算スレッドを実装する。生成時間はARM対応へ変更したPIMLibraryでLPDDR5X-PIMを模擬し、機能確認にはPIM Simulatorを併用する。
比較は重み二重保存、メモリ制御器変更が属性問題まで理想的に解けると仮定したFACIL、SHERPA二重バッファ、SHERPA逐次方式。BF16のLlama 3.2 1B/3BでDRAM必要量と初回トークン時間を測る。入力・出力系列長は主に64〜192。端末のキャッシュ不能連続領域は約1GBしかなく全重みが入らないため、前処理時間はダミー重みで測定し、機能確認は実重みをキャッシュ可能領域へ置いて変換後出力を元のExecuTorchと照合する。生成はLPDDR5X-PIM模擬で時間を測り、実HBM-PIMとの比較では模擬誤差0.1〜3.6%を確認する。
商用スマートフォン上でコピーとCPU前処理を実測する一方、対象端末に実LPDDR5X-PIMがないため生成PIMは模擬である。また約1GBの連続キャッシュ不能領域制約により全モデルを同じ物理配置で端から端まで実測できず、時間経路と機能経路を分離している。GPU/NPUへの適用は議論とモデル化であり実測ではない。
## 主要結果
PIM-SHERPAはPIM向け重みを一つだけ保持し、小容量バッファだけを追加することで、重み二重保存に対してLlama 3.2 1Bで47.8〜48.5%、3Bで49.4〜49.7%のDRAM容量を削減する。二重バッファ方式は入力128〜192トークンで並べ替えコピーを前処理計算の背後へほぼ隠し、ハードウェア変更を理想化したFACIL相当の初回トークン時間に達する。逐次方式は常にコピー遅延を負うが、長い入力ほど差が縮まり、PIMによる生成高速化を維持する。

- DRAM容量削減 / 47.8% / 48.5% (比較対象: 重み二重保存; 条件: Llama 3.2 1B、二重バッファ / 逐次方式) — PIM向け単一重みと32MB級の小バッファだけを保持するため、ほぼ半分の容量で両段階を実行できる。

- DRAM容量削減 / 49.4% / 49.7% (比較対象: 重み二重保存; 条件: Llama 3.2 3B、二重バッファ / 逐次方式) — モデルが大きいほど固定バッファの割合が小さくなり、理想的な単一重み方式の49%台削減へ近づく。

- 逐次方式の前処理性能 / 16.7 トークン/s (比較対象: FACIL理想化方式と二重バッファ方式へ接近; 条件: Llama 3.2 3B、入力192トークン) — 固定の並べ替え費用に対して行列積時間が増えるため、長い入力では逐次方式の単純さを保ったまま差が縮む。

- PIMなし端末比の高速化 / 最大3.3倍 (比較対象: LPDDR5X上のホストのみ実行; 条件: SHERPA逐次方式をLPDDR5X-PIMと組み合わせた系列長範囲) — 前処理の変換費用を払っても生成段階のPIM帯域効果が残る。

- PIM時間模擬誤差 / 0.1〜3.6% (比較対象: 実HBM-PIM; 条件: 複数の入出力次元でHBM-PIM模擬と実機を比較) — 実LPDDR5X-PIMがない評価の妥当性を、同種の実HBM-PIMで検証している。

### 負の結果・境界条件
- 二重バッファの理論モデルでは入力16トークン付近からコピーを隠せる予想だったが、実端末ではキャッシュ不能領域からのコピーがキャッシュ可能領域間コピーの約2倍遅く、二つのコピー用コアではDRAM帯域を飽和できないため、実際には入力128トークン付近まで必要になる。入力64〜96では二重バッファ方式はFACIL理想化方式より約2.5〜19%遅い。逐次方式はコピーと計算を重ねないため全条件で固定コピー遅延を負う。

### 結果の読み方
重み変換時間は入力系列長にほぼ依存しない一方、前処理の行列積時間は系列長とともに増える。このため長文入力ほど変換費用を隠す、または相対的に無視しやすくなる。逆に短入力や演算能力が非常に高い装置では変換が支配的になりやすく、適用境界は装置の演算量対帯域比と入力長で決まる。
## 品質への影響
重みを近似・量子化・削除せず、同じ値の物理配置とメモリ属性だけを変換するため、方式自体は損失なしである。実重みを用いた前処理出力とPIMシミュレータの生成結果をホスト計算と照合して機能を確認している。
## 既存研究との差
HBM-PIMやPAISEは前処理用のキャッシュ可能・ホスト向け重みと、生成用のキャッシュ不能・PIM向け重みを二重保存して矛盾を回避するため容量費用が大きい。FACILはメモリ制御器へアドレス変換機構を追加して単一PIM配置をホスト向けに見せるが、ハードウェア変更が必要でメモリ属性矛盾を直接扱わない。PIM-SHERPAは既存ハードウェアのまま、実行時コピーで属性と配置を同時に変換し、単一重みを共有する。IANUS、NeuPIMs、AttAcc等がPIM演算配置やスケジューリングを主眼とするのに対し、本研究は前処理と生成の境界で生じる実装上の整合性を対象とする。
## 限界
Galaxy S24+には実LPDDR5X-PIMがないため生成性能は模擬であり、端末の約1GBというキャッシュ不能連続領域制約から全モデルを同じ物理配置で端から端まで実測していない。二重バッファはコピー用スレッドと計算用スレッドの同期・負荷分散が必要で、短い入力ではコピーが臨界経路になる。逐次方式は簡単だがコピー遅延を必ず負う。高演算性能のGPU等では同じ入力長でもコピー費用の割合が増えるため、最適な入力長の境界が移動する。
## 実装状態
ExecuTorch上で二重バッファ、並べ替え付きコピー、逐次方式を実装し、Galaxy S24+で前処理の実行時間と機能を評価している。生成側はARM対応へ変更したPIMLibraryとPIM Simulatorを用いる。論文本文から独立した公開PIM-SHERPAリポジトリは確認できない。
## 研究上の位置づけ
PIMを用いたLLM推論の中でも、演算器設計ではなく製品級ソフトウェア統合に焦点を当てる。特にキャッシュ属性とDRAM物理配置という、抽象的な性能モデルでは見落としやすい制約がPIM実用化時に重み二重保存を招くことを示した。今後のPIM対応ランタイムやメモリ制御器設計では、前処理と生成の双方から同一重みを扱う際の基準点になる。
