# Reimagining Memory Access for LLM Inference: Compression-Aware Memory Controller Design

> 重みとKVキャッシュをビットプレーン・チャネル単位に再配置して無損失圧縮を効かせ、動的量子化時は必要ビットだけを読むメモリ制御器で容量・帯域・エネルギーを同時に削減する。
## 書誌情報
- **著者**: Rui Xie, Asad Ul Haq, Linsen Ma, Yunhua Fang, Zirak Burzin Engineer, Liu Liu, Tong Zhang
- **著者・所属**: Rensselaer Polytechnic Institute; Wiseburn Da Vinci Science
- **公開**: arXiv
- **種別**: プレプリント
- **対象**: メモリ制御器、無損失圧縮、KVキャッシュ、ビットプレーン、動的量子化、DRAM帯域
- **実装**: SystemVerilogでビットプレーン集約器、LZ4/ZSTD圧縮・伸長器、ブロック制御・バッファを含むパラメータ化RTLを実装し、7nm PDKで合成評価する。DRAM挙動はDRAMSim3で評価する。公開コードURLは論文本文に記載されていない。
## 概要
LLM推論の重みとKVキャッシュは容量だけでなくDRAM帯域を圧迫する一方、浮動小数点値をそのままLZ4やZSTDへ渡してもビット配置が高エントロピーで圧縮しにくい。本研究はアクセラレータ内蔵メモリ制御器をLLM向けに拡張し、同じビット位置を連続配置するビットプレーン分離と、複数トークンの同一チャネルをまとめて指数部の差分を取るKV再配置を行う。これにより一般的な無損失圧縮器でも重みを最大25.2%、KVキャッシュを46.9%削減する。さらに必要精度のビットプレーンだけをDRAMから読むことで文脈依存の動的量子化を帯域・エネルギー削減へ結び付け、DRAMSim3ではモデル読出し遅延を最大30.0%、DRAMアクセスエネルギーを最大29.9%削減する。7nm RTL試作では32レーン、2GHzで2TB/sを実現し、最大面積はZSTD構成で5.69平方ミリメートルである。

本研究は圧縮アルゴリズム自体を新しくするのではなく、LLMデータのメモリ内表現をメモリ制御器で再設計する。第一に、各浮動小数点値を値単位で並べず、同じビット位置を集めるビットプレーン分離を用いて指数部などの低エントロピー領域を連続化する。第二に、KVキャッシュでは隣接トークンの同一チャネルが似る性質を利用し、複数トークンをチャネル単位でまとめ、指数部を基準値との差分へ変換してからビットプレーン化する。これにより既存LZ4/ZSTDの無損失圧縮率を高める。さらにビットプレーンを独立して格納しているため、動的量子化でFP8が選ばれたなら必要な上位プレーンだけを読み、下位プレーンへのDRAMアクセス自体を省ける。容量圧縮と可変精度帯域削減を同じデータ配置で両立する点が中心的な新規性である。

代表結果として、KVキャッシュ無損失圧縮はLLaMA 3.1 8B、32層、BF16 KV、4KBブロック。提案配置＋ZSTDの総圧縮比は1.81/1.88。で通常配置へZSTDを直接適用した場合の総圧縮比1.21/1.33に対してWikiTextで44.8%、BookSumで46.9%の総フットプリント削減。トークン横断チャネル集約と指数差分によりKVの局所相関を圧縮器が利用でき、通常配置より圧縮比が50.3%/41.7%改善する。
## 問題設定
LLM推論は演算性能だけでなく、重みとKVキャッシュを外部DRAMから繰り返し読む容量・帯域制約に強く支配される。LLaMA 3.1 405Bの重みは約750GB、DeepSeek-R1 671Bは約1543GBに達し、長い系列ではKVキャッシュが総メモリ使用量の90%以上を占め得る。量子化や枝刈りは容量と転送量を減らせるが近似を導入する。一方、LZ4やZSTDのような一般的な無損失圧縮を浮動小数点の重み・KVへそのまま適用すると、符号・指数・仮数が各値の中に混在してバイト単位の規則性が弱く、特にKVではほとんど縮まらない。さらに文脈に応じてBF16、FP8、FP4などを切り替える動的量子化を演算器が行えても、従来のバイト配置では低精度時にも不要な下位ビットを含むメモリ語を読みやすく、演算量の低下がDRAM帯域・エネルギーへ比例しない。
## 新規性
本研究は圧縮アルゴリズム自体を新しくするのではなく、LLMデータのメモリ内表現をメモリ制御器で再設計する。第一に、各浮動小数点値を値単位で並べず、同じビット位置を集めるビットプレーン分離を用いて指数部などの低エントロピー領域を連続化する。第二に、KVキャッシュでは隣接トークンの同一チャネルが似る性質を利用し、複数トークンをチャネル単位でまとめ、指数部を基準値との差分へ変換してからビットプレーン化する。これにより既存LZ4/ZSTDの無損失圧縮率を高める。さらにビットプレーンを独立して格納しているため、動的量子化でFP8が選ばれたなら必要な上位プレーンだけを読み、下位プレーンへのDRAMアクセス自体を省ける。容量圧縮と可変精度帯域削減を同じデータ配置で両立する点が中心的な新規性である。
## 手法
### 手法のあらまし
書込み時、メモリ制御器は重みまたはKVキャッシュであることを識別し、通常の浮動小数点列をビット位置ごとのプレーンへ並べ替える。重みは同じ位置のビットをブロック内で連続させ、そのプレーンをLZ4またはZSTDで圧縮してDRAMへ格納する。KVキャッシュでは先に複数トークンを一群としてバッファし、同じ注意ヘッド・埋め込み次元に対応する値をトークン横断で連続化する。各チャネルの指数部には最小値または最頻値を基準指数として持ち、個々の指数を小さな差分へ変換する。差分化した指数と仮数をビットプレーンへ分けて連結し、ブロック圧縮器へ送る。読出し時は必要ブロックを伸長し、指数差分を基準値へ加えて元の値を復元し、逆シャッフルして演算器が期待する通常配置へ戻す。無損失モードでは全プレーンを取得するため、書込み前の重み・KVと同一の値が復元される。動的量子化が低精度を選んだ場合は、要求精度を構成する上位ビットプレーンだけをDRAMから取得し、不要な下位プレーンへの列アクセスを発行しない。したがって圧縮器による保存容量削減と、部分プレーン読出しによる転送量・エネルギー削減を同じ物理配置で実現する。圧縮・伸長、チャネル再配置、指数差分復元、逆シャッフルをメモリ制御器内で完結させることで、演算器は通常の浮動小数点値を受け取り、上位ソフトウェアが圧縮形式を直接管理する必要を減らす。

### ビットプレーン分離
通常のBF16やFP8では1つの値の符号・指数・仮数が隣接し、次の値へ移るたびにビットの意味が切り替わるため、汎用ブロック圧縮器から見ると規則性が見えにくい。ビットプレーン分離は、ブロック内の全要素について第0ビットだけ、第1ビットだけという形で同じ位置を連続配置する。特に指数上位ビットは値間で共通しやすく、同一プレーンへ集めると長い反復パターンが生じるためLZ4/ZSTDが圧縮しやすくなる。読出し時にはシャッフル網が逆変換するので、無損失経路では演算器へ渡る数値は元と同一である。また各プレーンを独立して扱えるため、FP8相当の精度なら上位8プレーンだけを取得するなど、動的量子化の選択を実際のDRAM転送量へ反映できる。

### トークン横断KVチャネル集約
KVキャッシュは時間とともに内容が変わるため、単純なトークン順の圧縮では重複が少ない。しかし同じ注意ヘッド・埋め込み次元に位置する値は、隣接トークン間で指数や数値範囲が似る傾向がある。制御器は複数トークンを小さな群としてバッファし、各トークンのKVベクトルをそのまま並べる代わりに、チャネルjの値を全トークン分まとめる。この再配置により似た値が近接し、後段のビットプレーン圧縮が利用できる局所的な規則性を増やす。読出し時はチャネル単位の並びを元のトークン単位へ戻すため、注意計算側からは通常のKVキャッシュとして見える。

### 指数差分変換
チャネル単位に集めても指数値にはばらつきが残るため、各チャネルについて最小または最頻の指数を基準値として保存し、各トークンの指数を基準との差分へ置き換える。似た値が集まったチャネルでは差分の絶対値が小さくなり、上位ビットに0や同一パターンが増える。差分指数をさらにビットプレーン化して仮数プレーンと連結すると、汎用圧縮器が反復を捉えやすい。追加状態はチャネルごとの小さな基準指数であり、読出しでは整数加算器が差分と基準を合成して元の指数を復元する。この機構がKVの圧縮率を単なるビットプレーン化より押し上げる。

### メモリ制御器内圧縮・伸長器
再配置だけではDRAM容量は減らないため、オンチップ制御器へLZ4またはZSTDのブロック圧縮・伸長器を組み込む。ビットプレーン集約器、圧縮器、2KBまたは4KB級ブロックを扱う制御論理とバッファを直列に接続し、書込みでは再配置後のブロックを圧縮、読出しでは伸長後に逆配置する。32レーン化してメモリ帯域に追随させる設計で、演算器や高水準ソフトウェアは圧縮形式を直接扱わない。圧縮しにくい低精度データでは追加の無損失利得が小さくなるが、同じビットプレーン配置を部分読出しに使えるため動的量子化側の帯域削減は残る。

### 動的精度に応じた部分プレーン読出し
文脈依存のルータが重みやKVの重要度に応じてBF16、FP8、FP4などを選ぶと、演算器は低精度で計算できる。しかし従来配置では1値の全ビットが同じメモリ語に含まれ、低精度でも余分なビットを転送しがちである。本方式では精度ごとに必要な上位プレーンだけをメモリ制御器が選択して読み、下位プレーンへの列アクセスを発行しない。したがって選択精度が下がるほどDRAM読出し量と活性化エネルギーも減る。ルータ層自体はBF16を維持するなど品質側の制約は動的量子化方式が決め、メモリ制御器はその決定を転送量へ忠実に反映する。

### 全体のデータ／制御の流れ
データ経路は、演算器からの重み・KV書込み要求、LLM種別を認識するメモリ制御器、チャネル集約とビットプレーン変換、LZ4/ZSTDブロック圧縮、外部DRAMの順で構成される。KVではチャネル集約器と指数差分器が前段に入り、基準指数を小さな付随情報として保持する。読出しでは逆順に、必要プレーンの選択、ブロック伸長、指数復元、逆シャッフルを行って通常の浮動小数点配置を演算器へ返す。無損失利用では全プレーンを読み完全復元し、動的量子化利用では要求精度に対応する一部プレーンだけを読む。したがって同じハードウェア経路が、保存容量を減らす無損失圧縮モードと、精度選択に比例して帯域・エネルギーを減らす部分読出しモードを兼ねる。
## 評価条件
- **ハードウェア**: DRAMSim3では1メモリモジュール4チャネル、各チャネル10個のx4 DDR5-4800デバイスを設定する。RTLは7nm PDK、2GHz、32並列レーンで評価し、16,384、32,768、65,536ビットのブロックについてLZ4/ZSTD圧縮・伸長器の面積、電力、スループットを合成評価する。これは商用GPU上の実機測定ではなく、メモリシミュレーションと論理合成を組み合わせたハードウェア評価である。
- **ソフトウェア**: 評価モデルはLLaMA 3.1 8B/70B、Mixtral 8x7B、LLaMA-MoE-3.5B。動的量子化ではC4でルータをLoRA調整し、FP8はAutoFP8、INT4はGPTQをUltraChatで較正する。KVキャッシュ品質例ではLLaMA 3.1 8BとBookSumを用い、完全KV、スライディング窓、Quest、およびページごとにBF16/FP8/FP4を切り替える方式を比較する。
- **比較対象**: KV圧縮ではトークン横断クラスタリングと指数差分を使わず通常配置へZSTD/LZ4を適用する比較対象、DRAM評価ではビットプレーン部分読出しを使わない従来のバイト単位メモリ配置、品質例では完全KVキャッシュ、64トークンのスライディング窓、Questの上位5ページBF16方式、重み圧縮では元のBF16に加えAutoFP8およびGPTQによる損失あり量子化との組合せ
無損失圧縮比は元サイズを圧縮後サイズで割った値として定義し、KVでは4KBブロックを用いる。WikiText-2推論時に得た精度分布に従って、BF16系ではFP12/FP8/FP6/FP4、FP8系ではFP8/FP6/FP4、INT4系ではINT4/INT2を切り替える。提案配置を通常のバイト配置と比較してDRAMアクセスエネルギーと平均モデル読出し遅延を測定し、さらにブロックサイズ別のRTL面積・電力・スループットを報告する。
主要な容量結果は重みについて複数モデル、KVについてLLaMA 3.1 8BのWikiText/BookSumを対象とする。遅延・エネルギー値はDRAMSim3によるモデル読出し経路のシミュレーションであり、エンドツーエンドのトークン生成遅延ではない。RTLも7nm合成評価で、実製品GPUへの統合、配線、圧縮待ち、実ワークロード全体のスケジューリング影響は測っていない。このためモデル系列や注意方式が変わった場合のKV相関と圧縮率、実機統合時の総合性能への一般化には追加検証が必要である。
## 主要結果
提案するLLM認識型メモリ配置は、BF16重みでは約4分の1、KVキャッシュでは約半分近い容量を無損失で削減し、同じビットプレーン表現を動的精度の部分読出しにも使うことでDRAMアクセスエネルギーとモデル読出し遅延を最大約30%削減する。重要なのは、圧縮率の改善だけでなく、量子化済みデータで追加圧縮余地が小さくなっても不要な下位ビットプレーンを読まないことで帯域利得を残せる点である。一方、報告遅延はDRAMSim3上の読出し時間であり、実機の生成速度そのものではない。

- KVキャッシュ無損失圧縮 / WikiTextで44.8%、BookSumで46.9%の総フットプリント削減 (比較対象: 通常配置へZSTDを直接適用した場合の総圧縮比1.21/1.33; 条件: LLaMA 3.1 8B、32層、BF16 KV、4KBブロック。提案配置＋ZSTDの総圧縮比は1.81/1.88。) — トークン横断チャネル集約と指数差分によりKVの局所相関を圧縮器が利用でき、通常配置より圧縮比が50.3%/41.7%改善する。

- 重み無損失圧縮 / LLaMA 3.1 8B BF16で25.2%削減 (比較対象: 未圧縮BF16重み、および通常の浮動小数点配置; 条件: ZSTD圧縮比1.34。LLaMA 3.1 70Bは25.6%、Mixtral 8x7Bは24.4%、LLaMA-MoE-3.5Bは24.9%。) — BF16では指数上位ビットの冗長性をビットプレーン化で露出できるため約25%の無損失削減が得られるが、FP8/INT4では既に冗長性が減り追加利得は小さい。

- 動的量子化との総容量削減 / LLaMA 3.1 8B FP8で54.1%、INT4で75.2%の総削減 (比較対象: 元のBF16表現; 条件: 損失あり量子化による削減へ提案配置上の無損失圧縮を追加。無損失部分単独ではFP8 8.3%、INT4 0.9%。) — 低精度化そのものが容量削減の大半を担い、無損失圧縮の上積みは精度が低いほど縮小するため、提案法の価値は部分プレーン読出しとの併用に移る。

- DRAMアクセスエネルギー / 最大29.9%削減 (比較対象: ビットプレーン部分読出しを使わない従来のバイト単位配置; 条件: DRAMSim3。BF16でLLaMA 3.1 8B 27.8%、70B 25.9%、Mixtral 8x7B 29.9%、LLaMA-MoE-3.5B 27.2%。MixtralではFP8 19.6%、INT4 17.9%。) — 必要プレーンだけを読むことでDRAM活性化を減らせる。低精度では元から転送量が少ないため追加削減率は小さくなる。

- モデル読出し遅延 / 最大30.0%削減 (比較対象: 従来配置で全対象ビットを読むDRAMSim3モデル読出し; 条件: Mixtral 8x7B BF16は705.90msから495.06ms、LLaMA 3.1 70B BF16は910.58msから674.73ms。) — 帯域要求の削減がメモリ読出し時間へ反映されるが、これはエンドツーエンド生成遅延ではなくモデル読出し経路だけのシミュレーション結果である。

- RTLスループットと面積 / 32レーン合計2TB/s、最大面積5.694平方ミリメートル (比較対象: 圧縮器を持たない通常メモリ制御器に対する追加ハードウェアコスト; 条件: 7nm、2GHz、各レーン512Gbps。ZSTD 65,536ビットブロックが5.694平方ミリメートル、LZ4同条件は4.834平方ミリメートル。) — 高い圧縮帯域を狙うと複数レーンと数平方ミリメートル級の追加回路が必要であり、ZSTDはLZ4より圧縮率と引き換えに面積・電力コストが大きい。

### 負の結果・境界条件
- 低精度化済みデータでは追加の無損失圧縮余地が急減し、LLaMA 3.1 8Bでは無損失部分単独の削減がFP8で8.3%、INT4で0.9%に留まる。DRAMエネルギー削減もMixtralでBF16の29.9%からFP8 19.6%、INT4 17.9%へ縮小する。また動的KV量子化では完全KVのパープレキシティ10.49に対し、上位5ページBF16・次5ページFP8で11.60、さらにFP4を含めると11.87へ悪化する。ZSTDは高圧縮率の代わりにLZ4より大きな面積・電力を要する。

### 結果の読み方
効果の中心は、浮動小数点の意味に沿って物理配置を変えると汎用圧縮器が指数部の冗長性を利用できる点にある。KVでは同一チャネルをトークン横断で集めて指数差分を小さくするため、重みより大きな約45〜47%の削減が得られる。低精度重みは元から情報量が少なく圧縮余地が減るので、無損失圧縮の追加利得はBF16より縮小する。一方、ビットプレーンを個別に読める構造は低精度時にも不要プレーンを省くため、圧縮率とは別経路でDRAM帯域とエネルギーを削減する。
## 品質への影響
ビットプレーン再配置とLZ4/ZSTDによる全プレーンの圧縮・伸長は無損失であり、元の重み・KVを完全復元するため、それ自体はモデル品質を変えない。品質変化は別機構である動的量子化が低精度を選ぶ場合にのみ生じる。BookSum例では完全KV 10.49に対して混合BF16/FP8が11.60、FP4を含む設定が11.87であり、容量・帯域削減と品質の交換条件は量子化方針側に属する。
## 既存研究との差
KIVIやKVQuantのようなKV量子化は数値精度を落として大きな容量削減を狙うのに対し、本方式のLZ4/ZSTD経路は全ビットを復元できる。GPTQ/AWQ等とは競合せず、量子化済みFP8/INT4へさらに無損失圧縮を重ねられる。ただし低精度ほど残る冗長性が少なく追加圧縮率は低下する。従来の汎用メモリ圧縮と比べると、単に圧縮器を置くのではなく、重みはビット位置、KVはトークン横断チャネルと指数差分というLLM固有の再配置を前段へ入れる点が異なる。
## 限界
- 実機GPUへ統合したエンドツーエンド推論評価ではなく、DRAMSim3と7nm RTL合成を中心とするため、実製品での制御器統合、配線、タイミング、圧縮待ちの影響は追加検証が必要。
- KVキャッシュの圧縮率評価は主にLLaMA 3.1 8BとWikiText/BookSumであり、モデル系列、注意方式、データ分布が変わった場合のチャネル相関と圧縮率は保証されない。
- KVを複数トークン単位で集約するため小さなバッファと基準指数メタデータが必要で、極端に短い系列や相関の弱いデータでは利得が縮む可能性がある。
- BF16では無損失圧縮余地が大きいが、FP8やINT4では追加の無損失削減率が1〜10%程度へ低下する。
- ZSTD構成はLZ4より高い圧縮を期待できる一方、最大構成で面積5.694平方ミリメートル、電力約7.385Wと資源コストが増える。
- 動的量子化の品質結果はMoDE化とルータ較正を含む特定設定であり、ビットプレーン制御器そのものが量子化方針の品質を保証するわけではない。
## 実装状態
論文はSystemVerilogでビットプレーン集約器、LZ4/ZSTD圧縮・伸長器、ブロック制御とバッファを含むパラメータ化RTLを実装し、7nm PDK、2GHzで合成評価している。メモリ側はDRAMSim3を用いる。したがって概念提案だけではなくRTLレベルの実装評価は存在するが、商用GPUまたは実シリコンへ統合した公開実装・実機エンドツーエンド評価ではない。論文本文で公式コード公開先は確認できない。
## 研究上の位置づけ
本研究は推論時メモリ圧縮、KVキャッシュ削減、動的量子化、ハードウェア・ソフトウェア協調設計の交点に位置する。特徴は新しい圧縮符号そのものではなく、LLMの浮動小数点構造とKVのトークン間相関をメモリ制御器へ露出し、既存の無損失圧縮器と部分読出しを有効化する点である。階層メモリやSSD退避方式とは直接競合せず、DRAM/HBM側で先に圧縮して下位階層へ移すデータ量を減らす前段機構として組み合わせられるため、リポジトリ上ではメモリ階層系と圧縮・量子化系を橋渡しする研究として位置付ける。
