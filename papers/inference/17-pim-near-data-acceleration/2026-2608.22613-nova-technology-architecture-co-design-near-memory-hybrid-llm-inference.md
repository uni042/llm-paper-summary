# NOVA: Technology-Architecture Co-Design of Near-Memory Processing for Attention-SSM-MoE Hybrid LLM Inference

> 4F² DRAMと近メモリ演算器を組み合わせ、注意・SSM・MoEごとに実行層を選び並列化して、GPU比較で平均4.5倍のデコードスループットを報告する推論アクセラレータ。

## 概要

論文の代表結果として、GPU比較で平均スループット4.5倍、エンドツーエンド遅延69.8%削減、エネルギー効率5倍を要約に掲げる。評価はH100と5基のHBM4を想定したサイクル精度シミュレーションで、実機NMP測定ではない。本文のエネルギー効率節は平均7.5倍と記載しており、要約の5倍と不一致があるため、条件を確かめず単一値として引用しない。

NOVAは、注意層（GQA）、状態空間モデル（SSM）、混合専門家層（MoE）が混在する大規模言語モデルの**デコード段階**を、メモリ近傍処理（NMP）で高速化するハードウェア設計である。モデルをGPUから追い出す方式ではなく、GPUに積層するHBMの周辺へ演算器を設け、重みや状態を保存した場所の近くで計算する。論文の狙いは、増え続けるモデルと長い文脈を収める容量を確保しながら、性質の異なる演算を一つのメモリシステムで処理することにある。

対象モデルには、注意・SSM・MoEを層間で組み合わせるNemotron3-NanoとNemotron3-Super、注意とSSMを一層内に混ぜるFalcon-H1R、Transformer系MoEのQwen3が含まれる。GQAはKVキャッシュを小さくするが文脈が伸びれば容量が増える。SSMは系列長に対する状態容量を抑える一方、状態更新でデータを頻繁に読み書きする。MoEは全専門家を保持しながら一部だけを使うため、総重み容量が大きく、専門家ごとの演算量もルーティング結果で変化する。

従来の近メモリ演算器は、得意な演算量対データ量の範囲が限られていた。DRAMダイ内の小さな演算器はデータ帯域を生かす一方で計算量の大きな処理に弱く、HBM基底ダイの演算器は計算能力を持つ一方でメモリ側の帯域に制約される。そのためハイブリッドモデルでは、層ごとに処理がGPUへ戻り、移動と同期が発生する。さらに従来の6F² DRAMセルは10nm級以降の微細化で容量を伸ばしにくいと論じる。

## 問題設定

問題は単純に「メモリが遅い」ことではない。デコード中のGQAはKVキャッシュを読み、SSMは再帰状態を更新し、MoEはルーティングされた専門家の重みを読む。これらは演算量と読み書き量の比が異なり、各処理を単一の近メモリ演算器に合わせると別の処理で資源が余る。未対応処理をGPUへ戻せば、その都度GPUとメモリの間で同期・データ移動が生じ、残った処理が全体の遅延を決める。

もう一つの問題はデコード作業集合の容量である。長い入力はKVキャッシュを増やし、同時実行バッチは複数要求のKVとSSM状態を保持させる。MoEは実行する専門家が一部でも、選択されうる全専門家の重みを収めなければならない。演算器を単にDRAMへ足してセルを減らすと、容量拡張の目的と衝突する。NOVAはセル配置と周辺回路配置を変えて、演算器を加えられる余白そのものを作る。

## 手法のあらまし

NOVAは、メモリ技術と演算器配置を一体で設計する。まず従来の6F²セルを4F²の垂直チャネルトランジスタ（VCT）セルへ置き換え、さらにセル配列の横に置かれていた周辺回路を、セル配列の上に積層する周辺回路上セル（POC）構造へ移す。こうして同じ面積により多くのメモリを収めつつ、論理プロセスで製造する周辺ダイに演算器を配置する。

演算器は二つの層に分かれる。Tier-1はセル配列の上にある周辺ダイに置き、銀行単位・銀行群単位でメモリ帯域を使う。Tier-2はHBMの基底ダイに置き、より高い演算量の処理を担当する。リクエストの現在のバッチや専門家ルーティングから各演算の負荷を見て、Tier-1だけ、Tier-2だけ、あるいは両方を並列に使う。

評価では、プリフィルをGPUで行い、デコード中のGQA・SSM・MoEをNMP側へ割り当てる。GPUはNMPが担当しない投影などを続ける。各処理の中間データと最終出力だけを必要な経路でやり取りし、両Tierが別々のデータ経路を動かせるときは、異なる作業を時間的に重ねる。以下では容量技術、二つの演算層、仕事の振り分け、モデルごとの実行順に分けて説明する。

## 手法

### 1. 4F² VCTセルとPOCで容量と演算器の配置場所を作る

4F²は、DRAMセルが占める面積を表す単位である。VCTではトランジスタのチャネルを垂直方向に配置し、従来の6F²構造よりセルを小さくする。論文の同面積比較では、この変更だけでメモリ密度が1.5倍になる。微細化した際のセル容量を保ち、サブ10nm級へ進めることを狙う技術前提であり、NOVA自身が製造プロセスを実証したという意味ではない。

通常のDRAMでは、センスアンプやワード線ドライバなどの周辺回路がセル配列の横に並び、チップ面積の一部を占める。POCではこれらを別の周辺ダイへ移し、ハイブリッド接合でセルダイの上へ積む。論文が比較するPUC構造では接合信号を周辺ウェハの配線層へ通すため配線資源を使うが、POCは周辺回路をセル配列の上へ重ねる。既報のPOC面積比を用いると追加で1.39倍、4F²化と合わせて同面積比2.09倍のメモリ密度を見積もる。

この上側の周辺ダイは論理プロセスで作る想定で、DRAMプロセスの周辺回路より論理演算器を集積しやすい。NOVAはそこにTier-1を置き、セルダイ側の記憶容量を演算器に置き換えずに近メモリ計算を加える。したがって容量増加と演算器追加は、同じセル面積を取り合う関係にならない。ただし2.09倍という密度は既報技術と配置前提を組み合わせた設計値であり、完成したNOVAメモリ製品の実測値ではない。

### 2. Tier-1の周辺ダイ演算器で低演算量の更新を処理する

Tier-1には、各メモリバンクに対応するバンク処理器（BAPU）と、バンク群の結果をまとめるバンク群処理器（BGPU）を設ける。セルダイで行を開くと、そのデータをハイブリッド接合で周辺ダイ上の行バッファへ送り、BAPU用の太い経路と通常の読み書き経路に分ける。BAPUは小さなデータを近くで処理し、BGPUは複数バンクの部分結果を集約する。

この層は低から中程度の演算量対バイト比を狙う。特にSSMでは、前時刻の状態に係数を掛け、入力由来の値を加算し、次の状態を書き戻す要素ごとの処理が中心になる。状態をCPUやGPUへ一度運んで更新後に戻すのではなく、状態を置いたバンクの近くで更新することで、大きな中間データの移動を避ける。低いKV再利用率のGQAや、少数トークンしか使わない冷たい専門家の処理もTier-1に向く。

### 3. Tier-2の基底ダイ演算器で計算量の多い処理を担う

Tier-2はHBM積層の基底ダイに置く演算器群である。各メモリダイからシリコン貫通電極（TSV）を通してデータを受け取り、行列ベクトル積など計算量の大きい処理を行う。論文の設定では、基底ダイに64 TFLOPS相当、Tier-1に32 TFLOPS相当の演算能力を置き、それぞれのメモリ帯域と釣り合う領域を受け持たせる。

KVキャッシュの再利用が多いGQAは、読み出したデータに対して比較的多くの演算を行うため、基底ダイ単独で処理する選択肢がある。多くのトークンが集まる熱い専門家も、Tier-2側でまとめて行列積を実行する。Tier-1より演算能力を多く持たせた基底ダイは、計算器の不足を補う一方、Tier-1ほど広いメモリ帯域はない。この違いが三つ目の実行モードを選ぶ理由となる。

### 4. 演算量と再利用率に応じて三つの実行モードを選ぶ

第一のモードはTier-1のみを使う方式である。SSMやKV再利用の少ないGQAのように、計算よりメモリ読み書きが支配的な処理を、全バンクを使って分散実行する。第二はTier-2のみを使う方式で、高いKV再利用率を持つGQAなど、計算能力を使い切れる処理を基底ダイへ割り当てる。

第三はTier-1とTier-2の並列実行である。中間的な演算量のGQAやMoEでは、二つの層へ処理を分け、両方の完了時刻が近づくように仕事量を調整する。銀行単位で動くTier-1と、銀行群単位でデータをまとめるTier-2は独立した接続経路を持つ。Tier-1が全銀行を使って計算する合間に、Tier-2は異なる銀行群からデータを受け取るよう時間をずらし、転送待ちを隠す。

### 5. MoEの専門家はルーティング結果から毎ステップ振り分ける

MoEではルーターが各トークンを一部の専門家へ送る。NOVAは専門家の重みを実行のたびにTier間でコピーするのではなく、ルーティングされたトークン数を見て、その場でどちらのTierが計算するかを決める。多くのトークンを処理する熱い専門家はTier-2へ、少数しか処理しない冷たい専門家はTier-1へ割り当てる。重みは配置したメモリに留まるので、負荷分割を変えても重み移動が必要ない。

主要評価では熱い専門家と冷たい専門家を静的に1対9へ分け、熱さは事前プロファイルした。追加の適応方針では各デコード段階のルーター出力を使い、専門家ごとのトークン数を基に二つのTierの処理完了時間が揃う境界を求める。論文の分布ずれ評価では、この動的振り分けが静的な1対9分割に対して最大2.1倍のMoE速度を示す。これは評価した集中・一様・偏り付きのルーティング条件に対する追加結果であり、全体の平均性能値とは分けて読む必要がある。

### 6. バッチと層構造に沿ってデータを配置し、GPUとの移動を減らす

メモリは5つのHBMキューブに分け、GQAとSSMはバッチやヘッド方向、MoEは専門家方向に分割する。各キューブ内で結果を独立に計算し、小さな出力だけをGPU側で集めるため、キューブ間の大きな重み移動を避ける。層ごとに重みと状態を持つ固定の配置計算を使い、要求がバッチへ加わる・抜ける場合は対応する領域を確保・解放する。

GQAではクエリと最終出力、SSMでは入力・状態更新の中間値、MoEでは入力・出力と冷たい専門家の中間値を必要な範囲でTSV経由に流す。論文は5キューブ構成でデコードに必要な作業集合をNMP内に収める設計を評価する。これはプリフィルも含む全処理をNMPへ移すという意味ではない。プリフィルと残る投影処理はGPU上で続き、NMPへ対応したデコード部分を重ねる構成である。

## 評価

### 結果の読み方

論文の要約では、GPU比較で平均スループット4.5倍、エンドツーエンド遅延69.8%削減、エネルギー効率5倍を掲げる。本文のモデル別内訳では、ハイブリッド三モデルのスループットが平均4.2倍、Qwen3が4.8倍であり、遅延削減はハイブリッドモデル平均69.2%、Qwen3で70.3%である。本文のエネルギー効率節はGPU比平均7.5倍としており、要約の5倍と値が一致しないため、代表値は要約の値を採りつつ、この差を論文内の集計差として扱う。

改善は、これまでGPUへ戻していたGQA・SSM・MoEを一つの近メモリ構成で実行し、GPUとHBM間の大量移動を減らすことから生まれる。既存方式が未対応処理をGPUへ残すとSSMなどが全体遅延を支配する。NOVAでは二つのTierが処理特性に合わせて分担し、長い系列や大きなバッチでNMPに載る処理の割合が上がるほど差が広がる。反面、SSMの状態更新はDRAM内部の活性化を頻繁に伴い、負荷が増すとエネルギー効率の伸びを抑える。

| スループット | 要約はGPU比平均4.5倍。本文ではハイブリッド三モデル4.2倍、Qwen3 4.8倍 | NMP内で三種の主要演算を扱い、GPUとの移動を減らす |
| エンドツーエンド遅延 | 要約は69.8%削減。本文ではハイブリッド三モデル69.2%、Qwen3 70.3%削減 | GPUに残る処理の割合が相対的に大きくなると改善幅を制限 |
| エネルギー効率 | 要約は5倍、本文の節ではGPU比平均7.5倍 | 見出しと本文の集計値に差がある。SSM状態更新の動的電力にも注意 |
| 256K文脈 | Nemotron3-Super、バッチ64でGPUと既存NMP比較はメモリ不足、NOVAのみ実行可能 | 容量密度向上が実行可能範囲を広げる例 |
| 面積増分 | 本文で3.94%（約3.9%） | 追加演算器とTSVの設計見積もり |

### 評価環境と制約

NMPの評価はRamulator2を基にした自作のサイクル精度シミュレータで行う。GPUはH100を基準にし、NMPとの同期やキューブ間集約もモデル化する。演算器とSRAMはRTLで設計して14nmで合成し、その面積・エネルギーを周辺ダイ7nm、基底ダイ4nmへ換算している。DRAM内部のエネルギーも既存研究を基に推定しており、NOVAを組み込んだHBM4実機上で測定した結果ではない。

主要実験のバッチは32または64、入力と出力長の組は2K/512、4K/1K、8K/2Kである。大規模なNemotron3-SuperはNVLink接続の2基GPUを使う条件も含む。従って結果はこれらのモデル、精度、メモリ構成、シミュレーション前提の範囲で解釈する。サブ10nmのDRAM製造、POCへの演算器集積、TSV増加、既存のHBM指令との共存は設計上の前提であり、製品実装での歩留まり・信頼性・費用は実測されていない。

## 既存研究との差

AttAccは主にGQA、PIMBAはSSMの状態更新、Duplexは中程度の演算量を持つ処理など、先行NMPは狭い演算領域へ最適化されてきた。未対応の演算はGPUへ戻すため、ハイブリッドモデルの層構成が複雑になるほど、GPUとの往復や未加速処理が遅延に残る。NOVAはGQA・SSM・MoEすべてを同じ二層メモリ構成で受け持ち、演算量の違いに合わせて一方または両方のTierを選べる点が特徴である。

NOVAのもう一つの差は、近メモリ演算器の配置をDRAMのセル技術・周辺回路構造と同時に決めることにある。従来のメモリ内演算では演算器が記憶セルを占有しうるが、NOVAは周辺回路をセル配列上へ移して得た空間を利用する。これによりメモリ容量を減らさずTier-1を足し、基底ダイのTier-2と組み合わせる。ただし密度の改善はDRAM技術進展の仮定を伴い、設計の優位性と物理製造の実現性は別の評価課題である。

## 限界・実装状況

- 評価したNMPはサイクル精度シミュレーションであり、製造済みNOVA装置の実機推論測定ではない。
- 4F² VCT、POC、論理プロセスの周辺ダイ、4nm基底ダイとTSVの集積を前提とする。実装歩留まり、熱、信頼性、製造費用は論文の性能評価だけでは確定しない。
- プリフィル全体を高速化する提案ではない。プリフィルと対象外演算はGPUに残り、NMPが速くなった後は残存GPU処理が遅延の支配要因になりうる。
- MoEの主評価はオフラインで熱さを測った固定1対9分割を使う。適応型の最大2.1倍は別の分布ずれ実験における静的方針比である。
- 要約と本文で平均エネルギー効率の値が5倍と7.5倍に分かれているため、比較条件と集計範囲を確認して引用する必要がある。

## 一般的な実装上の含意

異種モデルの推論装置は、モデル層を一種類の演算器へ押し込むより、メモリ帯域を使う更新処理と計算量の大きい行列処理を別の実行資源へ分け、処理量が中間の仕事は並列化するとよい。NOVAの例では、低演算量のSSM更新、KV再利用率で負荷が変わるGQA、ルーティングで負荷が動くMoEを、同じ「推論演算」としてまとめず、それぞれのデータ移動量と演算量から配置を選ぶ。

また、ハードウェア増強の評価では演算器追加だけでなく、容量への影響、帯域経路、GPUへ戻る未対応処理、メモリ技術の実現性を切り分ける必要がある。NOVAの2.09倍は密度、4.5倍はスループット、69.8%は遅延削減であり、互いに異なる指標である。特に長文脈の256K実行可能性は速度倍率ではなく、従来構成が容量不足で止まる条件を実行可能にした成果として読む。
