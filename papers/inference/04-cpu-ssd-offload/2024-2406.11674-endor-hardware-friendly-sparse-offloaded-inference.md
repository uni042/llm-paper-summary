# Endor: Hardware-Friendly Sparse Format for Offloaded LLM Inference

> 非構造枝刈り重みを非ゼロ値と位置ビットマップへ分離し、CPU/SSDからGPUへの転送量を減らして、退避LLM推論を最大約2.37倍高速化する。
## 書誌情報
- **著者**: Donghyeon Joo, Ramyad Hadidi, Soheil Feizi, Bahar Asgari
- **公開**: arXiv:2406.11674v1
- **種別**: arXivプレプリント
- **対象**: LLM退避推論、SSD、非構造枝刈り、疎形式、GPUダイレクトストレージ
- **実装**: OPT-66BとLlama2-70Bを対象にした研究実装。論文時点ではオープンソース化予定と記載され、公開コードURLは本文で確認できない。
## 概要
GPUメモリに収まらない大規模言語モデルでは、重みをCPUメモリやSSDへ退避し、各層の計算前にGPUへ転送する方式が使われる。Endorは、この方式では計算より重み転送が支配的になることをOPT-66Bで実測し、非構造枝刈り後の重みを非ゼロ値配列と1ビット位置ビットマップに分離して保存する。50%枝刈りしたFP16重みでは全体を元の56%へ縮小し、GPU上で並列復元することで転送削減を復元費用より大きくする。OPT-66Bでは通常のHugging Face Accelerateによる退避推論に対して配置容量増加込みで1.70倍、Llama2-70Bで1.78倍に高速化し、GPUダイレクトストレージを併用するとそれぞれ約2.25倍、2.37倍まで改善する。量子化とも併用可能だが、ビットマップ費用が相対的に増えるため圧縮率と高速化幅は小さくなる。

Endorは非構造枝刈り重みの非ゼロ値だけを連続配列へ格納し、元行列の各位置がゼロか非ゼロかを1ビットのビットマップで表す。整数座標や行ポインタを持つ形式より位置情報を小さく固定でき、50%疎のFP16行列では680MBの密重みを340MBの非ゼロ値と42MBのビットマップ、合計382MBすなわち元の56%へ縮小する。復元はビットマップを並列に読み、1の位置へ非ゼロ値を配置する単純なGPU処理なので、一般圧縮のCPU復号より低遅延である。形式は枝刈り方式や疎率に依存せず、量子化、活性値疎性、GPUダイレクトストレージとも組み合わせられる。

代表結果として、FP16重みサイズは9216×36864、50%非構造枝刈りで密FP16重みに対して680MBから382MB、元の56%。340MBの非ゼロ値に42MBの1ビット位置情報を足すだけなので、CSRより索引費用が小さい。
## 問題設定
GPUメモリに収まらない大規模言語モデルでは、層ごとの重みをCPU DRAMやSSDへ退避し、各層を実行する直前にGPUへ転送する必要がある。著者らがOPT-66B FP16をRTX 4080 16GB、64GB DRAM、NVMe SSDで測定したところ、1回の全層通過は54秒で、SSD配置層1層あたり約1秒の約80%がSSDからCPU、約20%がCPUからGPUへの転送に費やされ、実計算はほぼ0%だった。したがって計算と入出力を重ねる従来のスケジューリングだけでは隠蔽できる計算時間が足りない。枝刈りは重みをゼロ化しても、非構造疎重みを密行列のまま保存すれば転送バイト数を減らせない。一般疎形式は索引メタデータが大きく、構造化疎性は同じ疎率の非構造枝刈りより品質を落としやすい。
## 新規性
Endorは非構造枝刈り重みの非ゼロ値だけを連続配列へ格納し、元行列の各位置がゼロか非ゼロかを1ビットのビットマップで表す。整数座標や行ポインタを持つ形式より位置情報を小さく固定でき、50%疎のFP16行列では680MBの密重みを340MBの非ゼロ値と42MBのビットマップ、合計382MBすなわち元の56%へ縮小する。復元はビットマップを並列に読み、1の位置へ非ゼロ値を配置する単純なGPU処理なので、一般圧縮のCPU復号より低遅延である。形式は枝刈り方式や疎率に依存せず、量子化、活性値疎性、GPUダイレクトストレージとも組み合わせられる。
## 手法
### 手法のあらまし
処理は事前準備、階層配置、層単位転送、GPU復元、通常計算の順に進む。まず推論前にSparseGPTやWandaなどで各重み行列を非構造枝刈りし、行列を一定の走査順で調べて非ゼロ値だけを連続配列へ詰める。同時に元行列の各要素位置について、非ゼロなら1、ゼロなら0を持つ1ビット位置配列を生成する。この圧縮はオフライン処理なので利用者向け推論遅延には含まれない。次に圧縮済みの値配列と位置配列を、GPUに近い層はCPU DRAM、遠い層はNVMe SSDへ配置する。推論が始まると実行系は現在計算する層に対応する圧縮データだけをGPUへ移す。通常経路ではSSD配置層をSSDからCPU、続いてCPUからGPUへ転送し、CPU配置層はCPUからGPUへ転送する。GPUへ到着した後、復元カーネルが位置配列を並列走査し、1が立つ場所へ値配列を元の順番で配置して枝刈り済みの密行列を再構成する。復元後は既存の密行列演算を変更せず実行し、層計算が終われば次層の圧縮データについて同じ転送・復元・計算を繰り返す。圧縮により転送バイト数が減るだけでなく、同じDRAM容量へより多くの層を置けるため、SSD配置層をCPU配置層へ移して階層全体の遅延も下げられる。GPUダイレクトストレージ対応環境ではSSDからGPUへ圧縮データを直接転送し、中間のCPUからGPUへのコピーを省く。したがってEndorの端から端までの効果は、保存形式の縮小、GPU上の低費用復元、階層配置容量の増加、直接ストレージ転送の四つが連鎖して生じる。

### ビットマップ疎形式
各要素の非ゼロ位置を1ビットで保持し、実値は非ゼロ要素だけを元の走査順で保存する。FP16の50%非構造疎では9216×36864の680MB全結合重みが340MBの非ゼロ値と42MBのビットマップ、合計382MBになる。一般的な圧縮疎行列形式のように各非ゼロ要素へ大きな整数座標を付けないため、50%程度の中程度疎率でも索引費用が転送削減を相殺しにくい。位置情報の大きさは元要素数あたり1ビットで予測可能なので、枝刈り方式がSparseGPTでもWandaでも同じ表現を利用できる。保存サイズの削減がそのままSSDからCPU、CPUからGPUへ運ぶバイト数の削減につながる点が、単にゼロ重みを持つ密行列との本質的な差である。

### GPU並列復元
圧縮重みがGPUへ到着した後、GPUカーネルがビットマップを並列に調べ、1が立つ位置へ非ゼロ値配列を元の走査順に配置して枝刈り済み密重みを再構成する。CPUで12コア並列復元した実験では復元時間が転送削減を上回り、CPUからGPUへの転送量も密行列のままなので利益を失った。これに対しGPU上で復元すれば、転送路では小さい圧縮表現を維持したまま、到着後の高い並列性を使って復元費用を抑えられる。復元後は既存の密行列カーネルをそのまま利用するため、非構造疎行列専用の高速演算カーネルを要求せず、保存・転送最適化を既存推論実装へ組み込みやすい。

### 階層配置とGPUダイレクトストレージ
GPUに収まらない層をCPU DRAMとNVMe SSDへ配置し、圧縮された値配列とビットマップだけを層実行前に移動する。圧縮によって同じDRAM容量へ置ける層数が増え、OPT-66BではCPU配置を8層から14層へ増やせるため、単一転送の短縮だけでなく遅いSSDを使う層そのものを減らせる。通常経路ではSSDからCPU、CPUからGPUの二段階転送を行うが、対応環境ではGPUダイレクトストレージを使って圧縮データをSSDからGPUへ直接DMAし、後段コピーを除去する。圧縮形式と階層配置を同時に使うことで、容量効果と帯域効果を積み重ね、OPT-66BやLlama2-70Bの端から端までの遅延をさらに縮める。

### 量子化・他最適化との併用
Endorは枝刈り後の位置と値を表現する保存形式なので、SmoothQuantなどの量子化や活性値疎性による選択的転送と独立に適用できる。例えばINT8かつ50%枝刈りでは非ゼロ値が170MBまで小さくなる一方、位置ビットマップは42MBのまま残るため合計約212MBとなり、FP16の場合より固定位置情報の割合が増える。その結果、圧縮率と転送削減率はFP16より小さくなり、量子化併用時の線形演算高速化は1.48倍にとどまる。これは量子化と競合して使えないという意味ではなく、値のビット幅が小さくなるほど1ビット位置情報の相対費用が増えるという明確な境界条件を示す。

### 全体のデータ／制御の流れ
入力は非構造枝刈り済み大規模言語モデル重みとGPU・CPU・SSDの層配置である。事前圧縮器が非ゼロ値配列と1ビット位置ビットマップを生成し、それらをCPUまたはSSDへ保存する。推論時実行系が層ごとに圧縮重みを転送し、GPU復元カーネルが密重みを再構成して既存の行列演算へ渡す。出力は元の枝刈り済み重みと同一の数値を使った推論結果であり、Endor形式自体は追加の近似を導入しない。
## 評価条件
- **ハードウェア**: 主系はRTX 4080 16GB、ホストDRAM 64GB、SK Hynix P31 NVMe 2TB。OPT-66B FP16は132GB相当で、GPU 0〜4層、CPU 5〜12層、SSD 13〜63層へ配置する。GPUダイレクトストレージ対応経路も評価する。
- **ソフトウェア**: Hugging Face Accelerateの密重み退避推論を比較対象とし、SparseGPTまたはWandaで50%非構造枝刈りを行う。圧縮比較にはZSTD、量子化併用にはSmoothQuant INT8を使用する。
単一バッチのテキスト生成で、まずOPT層の線形演算単体についてSSD-CPU、CPU-GPU転送、復元、計算の内訳を測定する。次にOPT-66B全64層の1回通過時間を同じ配置で比較し、圧縮によりCPUへ置ける層数が増える効果も別に測る。GPUダイレクトストレージ経路、INT8量子化併用、OPT-66BとLlama2-70BのWikiText perplexityを評価する。
主目的は単一バッチの遅延削減であり、高並列サービングのスループット最適化ではない。疎性は保存・転送量削減に使うが、GPU上の行列計算自体は密計算のままで、非構造疎性による演算削減は未利用である。
## 主要結果
Endorは50%非構造枝刈りFP16重みを元サイズの56%へ縮め、GPU復元費用を小さく保つことで転送支配の退避推論を高速化する。同一配置のOPT-66Bでは54秒から35.8秒へ短縮し、圧縮によりCPU常駐層を8層から14層へ増やすと密重みAccelerate比1.70倍となる。GPUダイレクトストレージではOPT-66Bの1回通過が24.2秒となり約2.23倍、論文全体ではOPT-66B最大約2.25倍、Llama2-70B最大2.37倍を報告する。

- FP16重みサイズ / 680MBから382MB、元の56% (比較対象: 密FP16重み; 条件: 9216×36864、50%非構造枝刈り) — 340MBの非ゼロ値に42MBの1ビット位置情報を足すだけなので、CSRより索引費用が小さい。

- OPT-66B同一配置の全層通過 / 54秒から35.8秒、1.51倍 (比較対象: Hugging Face Accelerate密重み退避; 条件: GPU 0-4層、CPU 5-12層、SSD 13-63層) — SSD層は1.64倍、CPU層は1.30倍で、転送削減がGPU復元費用を上回る。

- OPT-66B配置容量込み / 1.70倍 (比較対象: 密重み退避; 条件: 圧縮でCPU常駐層を8層から14層へ増加) — 圧縮は転送量だけでなく、低遅延なCPUメモリへ置ける層数も増やす。

- GPUダイレクトストレージ / OPT-66B 24.2秒、約2.23倍。論文要約では最大2.25倍、Llama2-70B 2.37倍 (比較対象: CPU経由の密重み退避; 条件: SSDからGPUへ直接転送) — SSD-CPUとCPU-GPUの二段転送から後段を除去し、圧縮された小さいデータを直接運ぶ。

- 品質 / OPT-66B perplexity 9.33密、9.34非構造SparseGPT、10.07 2:4疎 (比較対象: 密OPT-66B; 条件: WikiText検証集合) — Endorは枝刈り後の値を変えないため、非構造枝刈りの品質をそのまま保持できる。

- INT8併用 / 線形演算で1.48倍 (比較対象: SmoothQuant INT8退避; 条件: Wanda 50%枝刈りとEndor併用) — 値が8ビットになると固定ビットマップ費用の割合が増え、FP16より転送削減率は小さい。

### 負の結果・境界条件
- CPUで12コア並列復元すると復元費用が転送削減効果を上回り、CPU-GPU転送量も減らない。ZSTDは約58%まで圧縮できるがCPU復元が遅くEndorに劣る。GPU上の演算は密行列のままなので、非構造疎性による演算量削減は得られない。

### 結果の読み方
SSD退避推論では計算最適化より先に重み移動量を減らすことが支配的であり、非構造枝刈りを保存形式まで一貫して扱えば、品質を保ちやすい疎性を実際のI/O削減へ変換できる。
## 品質への影響
形式自体は無損失で、品質は枝刈り方式に依存する。OPT-66BではSparseGPT 50%非構造枝刈りで密モデルとほぼ同じperplexityを維持した。
## 既存研究との差
FlexGen等が配置・バッチ・KV圧縮を組み合わせてスループットを高めるのに対し、Endorは単一要求の退避遅延を支配する重みI/Oそのものを削減する。活性値疎性方式はReLUで非ゼロになる行・列を予測して転送を選別するため対象モデルや層が限定されるが、Endorは枝刈り済み任意重みの非構造疎性を保存形式で表現する。CSRや一般圧縮と異なり、位置情報を1ビットへ固定しGPUで低費用に復元する点が中核である。
## 限界
評価は主に単一バッチ生成であり、多数要求を同時処理するサービングのスループットや尾部遅延は対象外である。GPUでは復元後に密行列演算を行うため、疎性を演算量削減へ使えていない。SSD帯域が依然として上限となり、著者らも複数SSDへの分散を将来課題として挙げる。量子化で値幅を縮めるほど1ビット位置ビットマップの相対費用が増え、圧縮率は低下する。論文時点では対応モデルがOPT-66BとLlama2-70B中心で、コードは公開予定とされるが本文に公開URLはない。
## 実装状態
RTX 4080、NVMe SSD、Hugging Face Accelerate、GPUダイレクトストレージを用いた実機研究実装。OPT-66BとLlama2-70Bをサポートし、SparseGPT/Wanda以外で事前枝刈りした重みも形式上扱える。論文ではオープンソース化予定と記載。
## 研究上の位置づけ
CPU/SSD階層を使うLLM退避推論で、枝刈りアルゴリズムとI/Oシステムの間を埋めるデータ形式研究に位置する。特にNVMe帯域が支配的な個人GPU環境では、量子化、GPUダイレクトストレージ、複数SSD、先読みと組み合わせる基礎要素として重要である。
