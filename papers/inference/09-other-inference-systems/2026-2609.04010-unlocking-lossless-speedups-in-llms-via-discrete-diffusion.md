# Unlocking Lossless Speedups in LLMs via Discrete Diffusion

> 自己回帰分布を維持したまま軽量diffusion weightsで複数tokenを並列提案し、lossless samplingで最大3倍高速化するUno方式。

## 書誌情報

- 公開日: 2026-09-03
- 状態: Preprint
- arXiv: 2609.04010
- 著者: Subham Sekhar Sahooほか
- コード: https://github.com/ifm-ai/uno
- 主題: lossless sampling / speculative-style parallel decoding

## 概要

Unoは、既存の自己回帰（Autoregressive; AR）モデルに軽量な追加重みを組み合わせ、複数tokenを並列に提案して生成を高速化する方式である。専用samplerによって元のAR分布を維持し、近似による分布変化を避けながらthroughputを高める。

## 手法

通常のnext-token predictionを担うbase modelの重みと、複数位置を並列提案する軽量な追加重みを分離する。追加重みはdistillationで学習され、専用のsampling手順で提案tokenを処理する。

別個のdraft modelを用意する必要がなく、base AR modelに補助weightを付加する構成となる。

## 評価

著者報告では、主要なspeculative decoding方式を評価した全batch sizeで上回り、base autoregressive model比で最大 **3倍** のthroughput向上を示す。

また8B Unoは、agentic tool use、coding、long-context reasoningで26B DiffusionGemmaおよびMercury 2を上回ると報告されている。コードとcheckpointも公開されている。

## スコープと制約

- CPU offload、SSD / NVMe offload、KV cache offloadを直接扱う研究ではない。
- MoE expert routingやexpert residencyも直接の対象ではない。
- 高速化には追加weightと専用samplerの実装が必要になる。

## 実装上の含意

複数の将来token候補を先に生成できるため、token generationだけでなく、その候補列を利用した将来計算やprefetchの先行実行へ接続できる余地がある。既存runtimeへ導入するには補助weightのロード、parallel proposal、lossless samplerの実装が必要となる。
