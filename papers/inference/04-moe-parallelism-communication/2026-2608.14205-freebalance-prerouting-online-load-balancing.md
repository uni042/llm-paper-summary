# FreeBalance: Pre-Routing Online Moe Load Balancing via Residual Workload Prediction

> FreeBalanceは前層出力を現層ルータへ先行入力して専門家負荷を予測し、注意計算中に予算内で専門家を交換する。正式ルーティングを維持し、負荷偏りと移動待ちを減らす。

## 概要

FreeBalanceは正式ルーティングを変えず、注意計算中に専門家交換を隠す。8×A800のQwen3/Moonlight評価では最大rank負荷比を最大32.8%、プリフィル遅延を平均13.1%削減し、入力長1Kから8KでTTFT改善が11.0%から23.3%へ増えた。

- **実装**: 前層隠れ状態を既存ルータへ先行入力する予測器、交換候補を評価する決定論的貪欲プランナ、注意計算時間に基づく移動費モデル、非同期専門家重み転送を統合する。追加学習モデルを必要としない。
## 問題設定
専門家並列（エキスパート Parallel; EP）MoEでは各トークンのルーティングが偏ると、最も重いrankの計算完了を全rankが待つためGPU遊休が生じる。オフライン配置は長期的な人気偏りには効くが、実サービスではタスク、層、バッチごとにルーティング分布が変わる。既存のオンライン方式は対象層のルータ結果が出た後に初めて負荷を知り、それから専門家の複製・移動を開始するので、大きな専門家重みの転送時間がそのままMoE層のクリティカルパスへ入る。負荷分散による計算短縮が得られても、そのための移動待ちが利得を相殺しうる。
## 新規性
FreeBalanceは負荷分散の判断時点をルーティング後からルーティング前へ移す。Transformerの残差接続では隣接層の隠れ状態が高い類似性を持つため、対象層の既存ルータを一つ前の隠れ状態へ先に適用すると、対象層の専門家負荷を早期に近似できる。この予測を使って注意計算と並行して専門家重みを交換する。予測結果は配置だけに使い、本来の対象層入力が完成した後は元のルータで正式な選択を行うので、推論結果を近似しない。さらに移動時間を注意計算の重ね合わせ窓以内に制限することで、オンライン負荷分散そのものをクリティカルパスから外す。
## 手法
### 手法のあらまし
対象層ℓの注意計算が始まる時点で、FreeBalanceは前層から得られた隠れ状態を対象層の凍結済みルータへ入力し、各トークンが選びそうな専門家集合を先行予測する。トークンごとの予測選択を集計して専門家別の予測トークン数を得る。別の学習済み予測器や追加パラメータは不要であり、既存ルータを再利用する。論文では予測ルーティングと実ルーティングの類似性が高く、ルーティングlogitのコサイン類似度が一貫して0.98超と報告する。

予測負荷から各rankの総負荷を計算し、最大rank負荷とrank間分散の双方を下げる目的関数を使って専門家交換を選ぶ。移動はrank間の専門家を対で交換するため、各rankが保持する専門家数を一定に保ち、負荷分散のためにHBM容量が増えることを避ける。全交換候補を無制限に実行するのではなく、専門家サイズ、rank間帯域、固定通信費から交換ごとの転送時間を見積もり、改善量と費用を比較して貪欲に選択する。

移動予算は対象層の注意計算時間から安全余裕を引いた時間として設定する。つまり、専門家交換の合計予測時間がこの予算を越えない範囲だけを採用する。専門家重みの転送は注意計算と非同期に開始され、正式なMoEルーティングが必要になるまでに終わることを狙う。決定論的な候補生成・選択を使うため、各rankが同じ統計から同じ交換計画を導け、交換計画そのものを大きな制御通信で配る必要を減らす。

実際のMoE計算時には対象層の正しい隠れ状態を元のルータへ入力し、予測ではなく正式なtop-k専門家選択に従う。予測が外れても出力トークンや専門家選択を変更せず、影響は配置の良し悪しだけに限定される。このためFreeBalanceは品質近似を伴わない。長い入力ほど注意計算時間が長くなって専門家移動を隠せる窓も広がるため、入力長1Kから8Kへ増えるにつれてTTFT改善が11.0%から23.3%へ拡大するという結果につながる。

### 残差表現を用いた先行負荷予測
対象層の正式なルーティング入力がまだ完成していない段階で、一つ前の隠れ状態を対象層の既存ルータへ通し、次に活性化される専門家を予測する。残差ネットワークでは隣接層の表現変化が比較的小さいという性質を利用するため、別モデルの学習やプロファイル専用ネットワークを追加しない。予測されたtop-k専門家をトークンごとに集計し、専門家別・rank別の将来負荷を得る。予測は負荷分散計画だけに使うので、誤予測が生成品質へ伝播しない。重要なのは、予測器の計算が新しい大規模ネットワークではなく既存ルータの追加呼び出しで済む点である。対象層の注意計算より前に専門家需要の概形を得られるため、従来はルータ完了後にしか開始できなかった重み移動を前倒しできる。論文では先行ルータと正式ルータのlogitのコサイン類似度が0.98超で推移し、負荷分散計画に利用できる精度を示す。一方で完全一致を前提にせず、外れた場合も後段の正式ルーティングで正しさを保持する設計にしている。

### 予算付き専門家交換計画
予測rank負荷に対して、最大rank負荷と全rankの分散を同時に抑える目的関数を評価する。候補操作を専門家の対交換に限定することで各rankの専門家数とメモリ占有を一定に保つ。各交換の費用は専門家重みサイズ、rank間の実測帯域、固定通信遅延から見積もり、負荷改善に対して効率の良い交換を優先する。多数の専門家を一度に動かすのではなく、注意計算中に完了できる総移動予算という制約のもとで選択するため、負荷分散の費用が新たな待ち時間にならないようにする。さらにプランナを決定論的にすることで、全rankが同じ負荷予測とトポロジー情報から同じ交換列を再現できる。これにより、中央ノードが交換計画を生成して全rankへ配布する追加同期を避け、オンライン制御そのものの通信費を抑える。対交換なので一方のrankへ専門家が一時的に集中することもなく、HBM容量制約を破らずに配置を更新できる。

### 注意計算との非同期重ね合わせ
従来はルータ後に専門家移動を始めるため、移動がMoE計算開始を直接遅らせる。FreeBalanceは先行予測が得られた時点で転送を開始し、対象層の注意計算と同時進行させる。予算は注意計算の予測時間から安全余裕を引いて決めるため、採用した交換は原則としてMoE実行前に終わる範囲に収まる。実験では1層あたり平均5.1専門家分の移動費を隠し、もし直列実行した場合にはクリティカルパスの約8.5%に相当する費用を重ね合わせで除去できたと報告する。ここでは『専門家移動を速くする』のではなく、『既に必要な注意計算の裏で移動を終わらせる』ことが主要な速度源である。そのため長文プリフィルのように注意計算が長い条件ほど交換予算が大きくなり、より多くの負荷再配置を無追加待ち時間で実行できる。反対に短文やデコードでは重ね合わせ窓が小さくなるため、方式の利得が自然に小さくなる。

### 損失なしの正式ルーティング維持
先行ルータ結果で実際の専門家選択を置換しない点が重要である。対象層の注意計算後には本来の隠れ状態を正式ルータへ入力し、その結果に従って通常どおりトークンをdispatchする。先行予測が誤っていれば専門家配置が最適でないだけで、モデルが選択する専門家、演算精度、出力は変化しない。これにより、近似ルーティングやトークンドロップで速度を得る方式とは異なり、品質保持を前提にオンライン再配置だけを高速化する。専門家の物理的なrank配置が変わっても、論理的な専門家IDとルータの選択結果の対応をランタイム側で追跡して同じ専門家計算へ届ける。この分離により、予測精度は性能上の重要指標ではあるが正しさの条件ではない。負荷予測の信頼性が一時的に低下しても、生成結果を犠牲にせず、最悪でも負荷分散の利得が縮む方向へ劣化する。

### 全体のデータ／制御の流れ
各層で前層出力を利用する予測ルータ、rank負荷集計、専門家対交換プランナ、帯域・専門家サイズに基づく費用モデル、非同期P2P重み転送を組み合わせる。予測と計画は注意計算開始付近で実行され、転送は注意カーネルと重ねる。対象層の正式ルーティング時には更新済み専門家配置表を使いながら元のルータ結果をそのまま実行する。
## 評価条件
- **ハードウェア**: 8×NVIDIA A800-SXM4 GPU、NVLink接続、専門家並列度8。
- **ソフトウェア**: 既存MoE推論経路へ先行ルータ呼び出し、決定論的専門家交換プランナ、非同期P2P重み転送を追加。公開コードは確認できない。
- **モデル**: Qwen3-30B-A3B-Instruct-2507、Moonlight-16B-A3B-Instruct
- **データセット／トレース**: LongBenchの19サブセット、複数タスクを混在させてステップ間の負荷分布変化を作るMixed Tasksワークロード
- **比較対象**: 固定専門家配置のVanilla、エキスパート Parallelism Load Balancer（EPLB）、EPLB + FreeBalance
- **正確性・品質**: 先行予測は専門家配置を決めるためだけに使い、実際のトークン→専門家ルーティングは対象層の正式な隠れ状態と元のルータで再計算する。したがってモデル出力を近似せず、論文は損失なしの負荷分散として扱う。
- **既定構成**: 専門家並列度8、バッチサイズ16、入力長8Kを主要設定とする。Qwen3-30B-A3Bは128専門家・top-8・rankあたり16専門家、専門家重み約9MB。Moonlight-16B-A3Bは64専門家・top-6・rankあたり8専門家、専門家重み約16.5MB。
- **交換予算**: 対象層の注意計算時間から安全余裕を差し引いた値を専門家重み移動の上限時間とし、その窓に収まる対交換だけを実行する。交換費は固定遅延と専門家サイズ／rank間帯域から見積もる。
- **長さスケーリング**: 入力長1K〜8Kを変化させ、注意計算の重ね合わせ窓が広がるほど隠せる専門家交換数とTTFT改善が増えるかを確認する。
まず隣接層の残差表現と正式ルータ入力の近さを調べ、前層表現を使った先行ルータ結果が対象層負荷の予測に使えることを確認する。次に各LongBenchタスクや混合タスクで専門家活性の偏りと時間変動を作り、固定配置、履歴ベースのEPLB、FreeBalance、およびEPLBとの併用を比較する。主指標は最大rank負荷／平均rank負荷、エンドツーエンドのプリフィル遅延、TTFT、1層あたり隠せた専門家交換数である。さらに入力長を変えて、注意計算時間の増加が移動重ね合わせへどう効くかを測定する。
評価は8台A800の単一ノード相当の高速GPU間接続と、2種類のMoEモデル、主にプリフィル処理を対象とする。デコードでは注意計算窓やトークン数が小さく、同じ交換量を隠せるとは限らない。多ノードInfiniBand等の低帯域・高遅延リンクや、専門家がさらに大きいモデルでの交換予算一般化は直接示されていない。
## 主要結果
FreeBalanceは、オンライン負荷分散の効果そのものよりも、専門家を動かすタイミングをルーティング後から注意計算中へ前倒しして移動費を隠すことに主眼がある。Qwen3-30B-A3BとMoonlight-16B-A3B、LongBench等では最大rank負荷／平均rank負荷を最大32.8%改善し、Qwen3系を中心とする集計でエンドツーエンドのプリフィル遅延を平均13.1%削減する。負荷予測と正式ルーティングのlogit類似度は0.98超で、1層あたり平均5.1専門家分の移動を注意計算内へ隠す。入力長が1Kから8Kへ増えるとTTFT改善が11.0%から23.3%へ大きくなり、重ね合わせ可能時間が性能を決めるという設計を裏付ける。

- 最大rank負荷／平均rank負荷比 / 最大32.8%改善、例2.01→約1.35 (比較対象: 固定専門家配置; 条件: 8×A800、EP=8、複数LongBenchタスクおよび動的負荷) — 先行予測に基づいて重いrankと軽いrankの専門家を交換し、最遅rankが全体同期を止める状況を緩和する。

- 平均プリフィル遅延 / 13.1%削減 (比較対象: Vanilla; 条件: Qwen3-30B-A3B、LongBench中心の評価) — 負荷均等化に加え、移動費を注意計算へ隠すため、オンライン再配置を直列に実行する場合の費用をほぼクリティカルパス外へ追い出す。

- 長文時TTFT改善 / 入力1Kで11.0%、8Kで23.3%改善 (比較対象: Vanilla; 条件: 入力長1K〜8Kのスケーリング実験) — 入力が長いほど注意計算時間が長くなり、より多くの専門家交換を隠せるためFreeBalanceの利得が拡大する。

- 隠蔽した専門家移動 / 1層あたり平均5.1専門家、直列ならクリティカルパス約8.5%相当 (比較対象: ルーティング後に移動するオンライン方式; 条件: 既定EP=8構成) — 負荷分散のための重み転送を待ち時間として払わず、既存の注意計算時間を通信隠蔽窓として再利用する。

- 予測ルーティングの類似性 / logitコサイン類似度0.98超 (比較対象: 正式ルータ出力; 条件: 隣接層残差表現を対象層ルータへ先行入力) — 追加予測モデルなしでも、交換計画を作るには十分に近い専門家負荷分布を早期に得られる。

### 負の結果・境界条件
- **短い入力では重ね合わせ窓が狭い**: 1K入力でのTTFT改善は11.0%で、8K入力の23.3%より小さい。注意計算が短いと交換予算も減り、動かせる専門家数が制限される。
- **予測は完全一致ではない**: ルーティングlogitの類似度は高いが、先行予測が正式な対象層ルーティングと常に一致するわけではない。品質は変わらない一方、誤予測時は交換の負荷分散効果が下がりうる。
- **高速相互接続依存の可能性**: 主評価は8台A800とNVLinkであり、より遅い多ノードネットワークでは専門家移動が注意計算時間に収まりにくく、交換可能数や利得が小さくなる可能性がある。

### 結果の読み方
従来のオンラインMoE負荷分散は、正しいルーティング統計を待ってから動くため判断精度は高いが、専門家移動を直列に払う。FreeBalanceは残差表現から十分高精度な負荷予測を早く得ることで、判断の一部を投機的に前倒ししつつ、正式ルーティング自体は変更しない。この分離により、性能上の投機は許してもモデル出力の投機にはしない。特に長文プリフィルでは注意計算が自然な通信隠蔽窓になるため、専門家オフロードや再配置研究にも『重みをどこから持ってくるか』だけでなく『ルータより前に必要性を予測できるか』という設計軸を追加する。
## 品質への影響
正式なルータ結果をそのまま利用するため、予測ミスは専門家の配置効率へだけ影響し、モデルの専門家選択や出力を変えない。論文はこの意味で損失なし（無損失）の方式としている。
## 既存研究との差
- EPLBのような履歴ベース配置は過去の活性統計で専門家配置を更新するため、層・バッチ・タスク単位の短期変動へ即時には追随しにくい。FreeBalanceは対象層のルーティング前に次の負荷を予測し、そのバッチに間に合う交換を行う。
- 一般的なオンライン専門家移動方式は現在層のルータ結果が確定してから再配置を始める。FreeBalanceは残差表現を使ってルータ前に計画を作り、注意計算と重み移動を重ねることで同じ再配置費をクリティカルパスから外す。
- Gimbalは要求配置と実測専門家負荷を閉ループで協調させるサービングスケジューラであり、FreeBalanceは一つのMoE実行内で専門家配置変更をどの時点に開始するかを扱う。両者はオンライン負荷分散でも制御階層が異なる。
- 予測ルーティングで実際の専門家選択を置き換える投機的MoE方式と異なり、FreeBalanceは予測を物理配置計画にだけ使い、正式なルータ結果を保持するため出力品質を変えない。
## 限界
- 主評価は8×NVIDIA A800とNVLinkであり、多ノードやPCIe中心の低帯域環境では注意計算中に隠せる専門家交換数が減る可能性がある。
- 長いプリフィルほど注意計算時間が長く有利で、短入力やデコード段階では同程度の通信重ね合わせ窓を得られない。
- 残差表現に基づく予測は高類似だが完全一致ではないため、急な層間ルーティング変化では交換計画が外れ、性能利得が縮小しうる。
- 評価モデルはQwen3-30B-A3BとMoonlight-16B-A3Bで、専門家サイズ・top-k・ルータ構造が大きく異なる全MoEへの一般性は追加検証が必要である。
- 公開実装は一次資料から確認できず、ランタイムへの統合費用や他の通信・計算重ね合わせとの干渉を第三者が再現できる状態かは不明である。
## 実装状態
8台A800上で専門家並列MoE推論へ統合して評価された研究実装。既存ルータを先行予測にも再利用し、決定論的交換計画と非同期専門家重み転送を追加する。公開コードは2026-09-11時点で確認できない。
## 研究上の位置づけ
本リポジトリではMoE専門家配置・通信系統、特にオンライン負荷分散と専門家プリフェッチの中間に位置する。既存の専門家プリフェッチは将来選択される専門家を予測して低速メモリから先読みするのに対し、FreeBalanceは将来のrank負荷を予測してGPU間で専門家を交換する。したがって予測信号として残差表現を用いる点は専門家プリフェッチ研究へ直接転用可能であり、SSD/CPUオフロードでもルータ確定前に読み込みを始めるための候補信号になる。一方でFreeBalance自体は低速階層を扱わず、高速GPU間移動を注意計算へ隠す方式である。
