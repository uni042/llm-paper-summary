# DWDP: Distributed Weight Data Parallelism for High-Performance LLM Inference on NVL72

> DWDPは注意重みを各GPUへ複製し、MoE専門家重みだけをNVLinkドメイン内で分散する。必要重みを非同期先読みして全対全通信とGPU間同期を減らす。

## 概要

DWDPは専門家重みの非同期共有で全対全同期を減らす。実機GB200 NVL72上のDeepSeek-R1をDEP（データ並列＋専門家並列）と比較し、入力処理では入力長1K〜32K、エンドツーエンドの分離servingでは入力最大8K・出力1K、20〜100 TPS/userで、GPU当たり出力スループットを平均8.8%改善した（入力処理単体は約1.09〜1.11倍）。入力処理GPUを減らすとTTFTが悪化し得るため、スループットと遅延を分けて読む。

## 問題設定
大規模MoE推論では、モデルを複数GPUへ載せるため専門家並列やテンソル並列を使うことが多い。しかしこれらは各層で全対全通信などの集団通信を挟み、同じ並列グループの全GPUがそろうまで次へ進めない。実サービスではリクエストごとに入力長、KVキャッシュの再利用率、選ばれる専門家が異なるため、GPUごとの仕事量は自然にばらつく。すると最も遅いGPUが層全体の進行速度を決め、計算を終えたGPUは同期待ちになる。論文の例では、各GPUの入力長の変動係数が20%程度でも従来のデータ並列＋専門家並列構成で同期オーバーヘッドが約10〜12%に達する。単に通信帯域を増やしても、集団同期という実行規則自体が残る限りこの待ちは消えない。
## 新規性
DWDPの新規性は、MoE重みを複数GPUへ分散して容量を節約しつつ、トークンや活性値を全対全通信で交換するのではなく、各GPUが不足する専門家重みをpeer GPUから自分で引き寄せる点にある。各GPUは他GPUの層進行を待たず、自分が必要な重みだけ到着すれば次へ進める。さらに分割重みを一時的に連結するコピーをなくす行列積カーネルと、複数GPUから同時に読まれる際のコピーエンジン競合を時間分割する転送方式を組み合わせ、非同期化だけでは露出する実装上の費用を抑える。
## 手法
### 手法のあらまし
DWDPでは各GPUを独立したデータ並列ランクとして動かし、注意機構の重みは全ランクに複製する。一方、容量の大きいMoE専門家重みは同じDWDPグループ内のGPUへ分割して置く。ある層を実行するとき、ローカルにない専門家が必要なら、その専門家重みを保持するpeer GPUからコピーエンジン経由で取得する。重要なのは取得を現在層の直前に同期的に行うのではなく、層lのMoE計算と層l+1の注意機構計算を行っている間に、層l+1で使う遠隔専門家を先読みすることである。計算時間が転送時間以上なら、転送はほぼ隠れる。各GPUは自分の先読み完了だけを待つため、他ランクの入力長や専門家負荷が大きくても全体同期には巻き込まれない。

通信にはNCCLのall-gatherやall-to-allのような集団通信を使わず、`cudaMemcpyAsync`によるGPU間コピーを使う。これによりストリーミングマルチプロセッサを主計算へ残しつつ、コピーエンジンで重みを引き寄せる。二重バッファを使って現在層の専門家と次層の先読み専門家を分け、層が進むたびにバッファを交代する。専門家数がグループサイズで割り切れなくてもよく、メモリに余裕がある場合は人気専門家を複製して遠隔転送を減らす配置も可能である。

実装では遠隔重みとローカル重みが別バッファに存在する。既存のgrouped GEMMへ渡すため毎回一つの連続バッファへ結合すると、論文の測定で約34マイクロ秒のGPU内コピーが追加される。そこでCuTeDSLベースの行列積を拡張し、複数の重みバッファを直接参照できるTensorList形式にして結合コピーを除く。また、一つの送信元GPUから複数の受信先へ大きな重み転送が集中するとコピーエンジンが直列化され、ある受信先の重み到着が遅れる。これを約1MBの小片に分け、受信先を巡回しながら送る時間分割方式で緩和する。

ただし通信と計算を重ねれば常に得になるわけではない。GB200ではコピーエンジンと計算器がL2、DRAM、電力枠などを共有し、強い転送と行列積を同時に走らせると電力制限によるGPU周波数低下が観測される。したがってDWDPは高帯域のGPU間接続と十分な計算窓がある入力処理で特に有利で、短い計算窓や生成主体の負荷では転送を隠し切れず利得が小さくなる。

### 専門家重みを引き寄せる非同期データ並列
各GPUはリクエストを独立に処理するデータ並列ランクとして動き、注意機構重みを複製する一方、MoE専門家だけをグループ内へ分割配置する。次層で必要になる遠隔専門家は現在層のMoE計算と次層の注意機構計算に重ねて先読みする。従来の専門家並列はトークンを全対全通信で交換し、各層で全ランクがそろうまで待つが、DWDPは各ランクが自分に必要な重み転送だけを待つ。このため入力長やKVキャッシュヒット率、専門家選択が偏っても、速いランクが遅いランクの同期点へ拘束されない。二重バッファで現在層と次層の重みを分離し、専門家数がランク数で割り切れない場合も冗長配置を許すため、GPU単位で構成を変えられる。

### 分割重みを直接使う行列積
遠隔GPUから取得した専門家重みとローカル専門家重みは物理的に別のバッファにある。従来のgrouped GEMMが一つの連続した重み配列を想定すると、計算前にGPU内コピーで結合する必要があり、論文の代表測定では約34マイクロ秒を消費する。DWDPはCuTeDSLを用いた行列積カーネルを拡張し、専門家ごとの複数バッファをTensorListとして直接参照する。これにより非同期転送で得た時間を結合コピーで失うことを防ぐ。単なる通信方式の変更ではなく、重みが分散したままでも計算カーネルが扱えるようデータ配置と実行カーネルを同時に変える点が、実機での利得に重要である。

### コピーエンジン競合を緩和する分割転送
複数の受信GPUが同じ送信GPU上の専門家重みを同時に必要とすると、送信元のコピーエンジンで大きな転送が直列化される。先頭の大転送が終わるまで後続受信先が待つと、一部ランクだけ先読みが間に合わず計算の空白が生じる。そこでDWDPは大きな重みを約1MBの小片へ分け、受信先を巡回する時間分割方式で転送する。各受信先へ少しずつ進捗を与えることで、通信完了時刻の偏りを減らし、計算窓の短い条件でも先読みを隠しやすくする。評価ではこの競合対策の効果は短い計算窓で特に大きく、長い計算窓ではもともと転送を隠せるため追加利得が小さい。

### 通信と計算の干渉を踏まえた実行設計
コピーエンジンと計算用ストリーミングマルチプロセッサは別資源でも、GPU内部のメモリ階層、相互接続、電力上限を共有する。論文は転送と行列積の同時実行時に周波数が下がり、計算カーネル自体が遅くなる現象を測定している。このため『通信を完全に重ねれば無料になる』とは仮定せず、転送の粒度と時系列を調整して干渉を抑える。計算窓が十分長い入力処理サーバでは遠隔重みの取得を隠せるが、短い入力や生成主体の条件では通信が臨界経路へ露出する。DWDPの適用範囲をNVL72のような高帯域GPUファブリックへ明確に限定している点も実装上の重要な設計判断である。

### 全体のデータ／制御の流れ
分離サービングでは入力処理サーバだけをDWDP化する。要求はデータ並列ランクへ配られ、各ランクが独立して注意機構を計算しながら次層の遠隔MoE専門家重みをGPU間で先読みする。ローカル重みと遠隔重みは結合コピーせず拡張行列積が直接読む。通信要求が一つの送信元へ集中した場合は転送を小片に分けて巡回し、先読み完了時刻を平準化する。生成サーバは従来方式のままなので、エンドツーエンド性能は入力処理側GPUを何台割り当てるかとの組合せで決まる。
## 評価条件
- **ハードウェア**: NVIDIA GB200 NVL72。NVLinkによる高帯域GPU間接続を使用。、DeepSeek-R1をNVFP4/FP8構成で評価。
- **ソフトウェア**: TensorRT-LLM commit 3a89495を評価基盤として使用。、現在はTensorRT-LLM PR #12136として上流へ統合済みとNVIDIA公式技術ブログが明記する。
- **モデル**: DeepSeek-R1
- **データセット／トレース**: 入力処理単体はArtificial Analysis由来の条件設定。、エンドツーエンドはSemiAnalysisワークロードを使用。
- **比較対象**: データ並列＋専門家並列（DEP）
- **正確性・品質**: 同じモデル重みと演算を用い、専門家の配置と通信方式だけを変更するため、近似KV圧縮や枝刈りのような品質損失は導入しない。評価の主眼はスループット、先頭トークン時間、GPU効率であり、精度ベンチマークの差を主張する研究ではない。
- **入力処理単体**: 主に入力長1K〜32K、最大同時トークン数16Kまたは32Kで比較する。入力長の標準偏差も変え、GPU間の要求偏りが大きくなるほど同期除去の効果がどう変わるか測る。
- **エンドツーエンド**: 入力長は最大8K、出力長1K、入力比0.8。利用者当たり生成速度20〜200 TPS/userの範囲で入力処理GPU数を変え、生成側は同一構成としてGPU当たり出力スループットとのパレート前線を比較する。
- **実装アブレーション**: 分割重み結合を除去する行列積と、非同期転送競合を緩和する小片化・時間分割を個別に比較し、単なる非同期化以外の寄与を測る。
まず従来のDEPでGPU間の入力長ばらつきと同期待ちの関係を測定し、実サービス程度の偏りでも同期が無視できないことを示す。次にDWDPの入力処理単体性能を入力長、最大同時トークン数、入力長の標準偏差、DWDPグループサイズを変えて評価する。さらに重み結合コピー除去と通信競合緩和を切り分ける。最後に分離サービングへ組み込み、利用者当たり生成速度をそろえた条件でGPU当たり出力スループットを比較し、入力処理GPUを減らした場合の先頭トークン時間も同時に報告する。
実機GB200 NVL72上のDeepSeek-R1に限定された評価であり、高帯域のGPU間接続を持たないPCIe中心クラスタへそのまま一般化できない。特に生成主体で計算窓が短い場合は遠隔重み転送を隠し切れず、入力処理GPUを減らしてGPU効率を上げると待ち行列により先頭トークン時間が悪化する。
## 主要結果
実機GB200 NVL72上のDeepSeek-R1で、DEP（data＋expert parallelism）を基準に入力長1K〜32Kの入力処理とSemiAnalysisワークロードの分離serving（入力最大8K・出力1K、20〜100 TPS/user）を比較し、GPU当たり出力スループットを平均8.8%改善した。入力処理単体は約1.09〜1.11倍だが、入力処理GPUを減らすとTTFTが悪化し得るため、スループットと遅延を分けて読む。

- エンドツーエンドGPU当たり出力スループット / 20〜100 TPS/user帯で平均8.8%改善 (比較対象: DEP; 条件: DeepSeek-R1、GB200 NVL72、最大入力8K・出力1K、分離サービング) — 入力処理側の同期を除き、同じ利用者当たり生成速度をより少ない入力処理GPUまたは高いGPU効率で実現できる。

- 入力処理単体のGPU当たりスループット / 代表条件で約1.09〜1.11倍 (比較対象: DEP; 条件: 入力長1K〜32K、最大同時トークン数32768) — 十分な計算窓があると遠隔専門家重みの先読みを計算へ隠し、DEPの全対全通信と同期待ちを臨界経路から外せる。

- 8K入力の反復時間 / DEP 1319.85 µs、DWDP 1165.58 µsで11.69%短縮 (比較対象: DEP; 条件: 入力比0.8、最大同時トークン数32768、GB200) — DWDPでは429 µs規模のpeer転送自体は存在するが大部分を計算へ重ねられ、DEPの通信126.74 µsと同期161.85 µsを臨界経路から除ける。

- 入力長ばらつきへの耐性 / 16K平均・標準偏差4096でGPU当たりスループット約1.15倍 (比較対象: DEP; 条件: 入力長標準偏差を増やした入力処理評価) — 従来方式は最遅ランク待ちが増えるのに対し、DWDPは各ランクが独立進行するため負荷不均衡が大きいほど相対利得が増える。

- 高生成速度帯のGPU効率 / 170〜180 TPS/user帯ではGPU当たり出力スループット比0.97 (比較対象: DEP; 条件: エンドツーエンド分離サービング) — 生成側や他の要因が支配的になると入力処理側DWDPの利得は消え、条件によってはわずかに悪化する。

### 負の結果・境界条件
- **先頭トークン時間の悪化**: エンドツーエンド評価ではDWDPの高いGPU効率を利用して入力処理GPU数を減らすと待ち行列が長くなり、中央値の先頭トークン時間が多くの速度帯でDEPより悪化した。20〜30 TPS/user帯では約2.54秒から8.31秒へ増える。
- **短い計算窓では通信を隠せない**: 最大同時トークン数が小さい条件では遠隔重み転送が計算時間を超えやすく、利得が小さい。入力長8K・最大同時トークン数16384の一部条件ではGPU当たりスループット改善が約1%に留まる。
- **通信と計算の重複が計算自体を遅くする**: GB200では強いGPU間転送と行列積を同時実行すると電力上限による周波数低下が観測される。独立したコピーエンジンを使っても通信を完全な無償処理とはみなせない。

### 結果の読み方
DWDPの利得は通信量そのものを消すことより、同期待ちをなくして通信を十分な計算窓へ隠すことから生じる。そのため入力処理のように1反復の計算量が大きく、リクエスト長や専門家活性がばらつくほど有利になる。反対に生成主体で計算窓が短い、GPU間帯域が低い、あるいは入力処理がシステム全体のボトルネックでない条件では改善余地が減る。GPU当たりスループットを上げて入力処理GPU数を削減すると待ち行列遅延が増えるため、運用ではGPU効率と先頭トークン時間を同時に制御する必要がある。
## 品質への影響
計算結果を近似する方式ではなく、同じ専門家重みを別GPUから取得して実行するため、DWDP固有のモデル品質低下はない。性能上の負の影響は主に通信露出、電力干渉、待ち行列による遅延であり、出力品質との交換ではない。
## 既存研究との差
- 従来の専門家並列は活性値やトークンを全対全通信で交換し、各層で全GPUを同期する。DWDPは専門家重みをGPU間で引き寄せ、各ランクが独立して層を進むため、負荷不均衡を集団同期へ伝播させない。
- CPU/SSDへのMoEオフロード研究は容量不足を外部階層で補うことが主目的である。DWDPは同一NVLinkドメイン内のGPU HBMを重みプールとして使い、容量と同期除去を同時に扱う。
- 通常のデータ並列は各ランクがモデル全重みを複製する。DWDPは注意機構だけ複製し、容量の大きい専門家重みを分割するため、データ並列の独立性を保ちながらMoE全重み複製を避ける。
## 限界
- GB200 NVL72級の高帯域GPU間接続を前提とし、PCIeのみの一般的な複数GPU環境では遠隔重み転送が臨界経路へ出やすい。
- 十分な入力処理計算窓が必要で、短いバッチや生成主体の負荷では利得が小さいか逆転する。
- 通信と計算の同時実行は電力上限やメモリ系資源を共有し、GPU周波数を下げる場合がある。
- エンドツーエンドでGPU台数を削減すると先頭トークン時間が悪化するため、GPU当たりスループットだけで構成を決められない。
- 主評価はDeepSeek-R1とGB200 NVL72であり、他のMoE構造や異なる相互接続への一般化は追加検証が必要である。
## 実装状態
論文評価はTensorRT-LLM commit 3a89495に実装。論文本文ではPR #12136による上流統合が進行中とされていたが、2026-09-11時点でNVIDIA公式TensorRT-LLM技術ブログは『PR #12136として統合済み』と明記している。したがって現在は研究プロトタイプだけでなくTensorRT-LLM本流へ取り込まれた機能として扱える。
## 研究上の位置づけ
MoE推論の並列化・専門家配置系統に位置づける。特に『容量不足をCPU/SSDへ逃がす』のではなく、『高速GPU間ファブリックを分散重みキャッシュとして用い、データ並列の非同期進行を維持する』設計である。専門家並列の同期ボトルネックとデータ並列の全重み複製という二つの制約の中間を狙う。今後SSDやCXLをより活用する研究を考える際にも、遠隔重み取得を集団通信ではなくpull型・非同期・先読みとして設計し、分割重みを直接カーネルへ渡すという考え方は階層を跨いで応用できる。
