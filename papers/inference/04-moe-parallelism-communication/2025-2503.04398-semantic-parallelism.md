# Semantic Parallelism: Redefining Efficient MoE Inference via Model-Data Co-Scheduling

> トークンと専門家の活性化親和性を事前学習し、専門家配置と要求・トークン配置を協調させてMoEの全対全通信を削減する推論方式。
## 書誌情報
- **著者**: Yan Li, Zhenyu Zhang, Zhengang Wang, Pengfei Chen, Pengfei Zheng
- **公開**: ICLR 2026
- **種別**: conference
- **対象**: MoE inference、エキスパート parallelism、model-data co-スケジューラ、communication reduction、SGLang
- **実装**: SGLangへのプラグインとして約5000行のPythonと通信向けTritonカーネルを実装。Attention-TP向けにshuffled-reduce-scatterとshuffled-allgatherを追加する。
## 概要
Semantic Parallelismは、専門家並列MoE推論で専門家配置とデータ配置を別々に最適化すると全対全通信が残る問題に対し、トークンと専門家の安定した活性化親和性を利用して両者を協調スケジューリングする。Sem-MoEはオフラインで専門家とトークンを共クラスタ化し、注意層がデータ並列の場合は要求単位、テンソル並列の場合はトークン単位で予測配置する。SGLang上の実装では、DeepSeek-V2-Liteのデータ並列注意でSLO制約下のスループットを最大2.78倍、テンソル並列注意でQwen3-30B-A3Bの初回トークン遅延を最大24.9%削減した。

トークン識別子だけでも専門家活性化が強く偏る実測事実を利用し、モデル配置とデータ配置を同じ親和性目的で協調最適化する。オフラインで専門家とトークンを共クラスタ化し、データ並列注意では要求単位、テンソル並列注意ではトークン単位で親和性の高い装置へ先回り配置する。後者は既存のreduce-scatterへ並べ替えを融合し、追加の独立通信をほぼ作らない。専門家配置だけを改善する従来法と異なり、同じ確率表を要求スケジューラと通信カーネルまで共有するため、専門家を入力へ近づけるだけでなく入力自体も専門家へ近づけられる点が論文固有の着想である。

代表結果として、Attention-DP スループット under SLOは8 GPU, リクエスト rate 10–175 req/sでSGLang with DeepEP / MoETunerに対してDeepSeek-V2-Lite: SGLang比+31%/+221%、MoETuner比+32%/+278%（TTFT/E2E SLO）。要求配置と専門家配置を協調させることで、高負荷時にベースラインへ未処理要求が蓄積する領域でも処理能力を維持した。
## 問題設定
大規模な混合専門家モデルを複数装置で推論すると、各トークンを選択された専門家が置かれた装置へ送出し、計算後に元へ結合する全対全通信が専門家層の主要な律速になる。DeepSeek-V2-Liteを8基の高速接続GPUで動かした予備実験でも、専門家層の前向き遅延の最大59.2%を専門家並列通信が占める。既存法は専門家配置と要求・トークン配置を別々に扱うため、専門家を近づけても入力データが同じ装置に来るとは限らず、遠隔通信が残る。さらに単純な負荷均衡だけでは、通信相手となる専門家と入力の意味的親和性を利用できないため、高速な装置間接続を持つ環境でも専門家層の通信費用が計算時間を上回りうる。したがってモデル側の専門家配置とデータ側の配置を一体で決める必要がある。
## 新規性
トークン識別子だけでも専門家活性化が強く偏る実測事実を利用し、モデル配置とデータ配置を同じ親和性目的で協調最適化する。オフラインで専門家とトークンを共クラスタ化し、データ並列注意では要求単位、テンソル並列注意ではトークン単位で親和性の高い装置へ先回り配置する。後者は既存のreduce-scatterへ並べ替えを融合し、追加の独立通信をほぼ作らない。専門家配置だけを改善する従来法と異なり、同じ確率表を要求スケジューラと通信カーネルまで共有するため、専門家を入力へ近づけるだけでなく入力自体も専門家へ近づけられる点が論文固有の着想である。
## 手法
### 手法のあらまし
入力→処理→出力の流れは次の通りである。入力は対象MoEモデル、代表データから収集したトークン頻度・専門家活性化履歴、実行時の要求列である。処理1では履歴をトークン別専門家選択確率と層間装置遷移確率へ変換し、負荷均衡と遠隔活性化削減を同時目的とする共クラスタ化を解く。処理2では得られた専門家群を装置へ再配置し、ゲート行列の列も同じ順序へ並べ替える。ここで専門家数を各装置で均等に保ち、要求頻度も考慮するため、通信局所性を上げても特定装置へ計算が偏りにくい。処理3のオンライン推論では、データ並列注意なら要求内トークンの親和性を集約して要求を適切なランクへ割り当て、テンソル並列注意なら現在トークンと直前層の装置系列から次の専門家装置を予測し、注意後のreduce-scatter中にトークンを先回り配置する。処理4で通常どおりゲートと専門家計算を実行すると、多くのトークンが目的専門家と同じ装置にあるため全対全通信量が減る。予測が外れたトークンは通常の専門家並列通信へ送るので、予測誤りが生成結果の誤りにはならない。専門家計算後は必要な集約と逆並べ替えを行い、次の注意層または専門家層へ通常形式の隠れ状態を渡す。出力は元モデルと同一意味の推論結果であり、品質を近似化せず装置間通信と遅延だけを削減する。各段階の出力である確率表、配置表、先回り配置済みトークンが次段階の入力になるため、オフライン学習からオンライン通信削減までが一つの機構として接続される。データ並列注意とテンソル並列注意でオンライン処理の粒度は異なるが、どちらも同じトークン・専門家親和性と負荷均衡制約を使うため、並列方式に応じて実装を切り替えながら同一の設計原理を維持する。

### トークン・専門家活性化予測表
代表データをモデルへ通し、各トークンが各層でどの専門家を選んだかを数える。トークンごとに頻度を正規化して専門家選択確率表を作り、未知トークンは埋め込み近傍で補う。DeepSeek-V2-Liteでは上位専門家への累積活性化率中央値が層により約0.833〜0.976で、静的上位専門家だけでも別データ部分で96.3%精度、78.8%F1となる。テンソル並列注意向けには直前層の専門家装置から次層装置への遷移も二グラム表にする。出力される確率表は共クラスタ化の重みとオンライン先回り配置の双方で再利用されるため、重い予測器を推論中に走らせず親和性を利用できる。

### 負荷均衡付き共クラスタ化
入力はトークン頻度、専門家活性化確率、専門家数、専門家並列ランク数である。各トークンと各専門家を一つのクラスタへ割り当て、クラスタ間活性化を減らしつつトークン頻度と専門家数を均衡させる整数計画を近似的に解く。直接解法は大きすぎるため、専門家配置と要求配置を交互に改善する。専門家側では専門家間親和性、要求との親和性、クラスタ負荷を合成し、満杯クラスタを除外しながら配置する。その後、異なるクラスタ間の専門家交換で目的値が改善する場合だけ入れ替える。要求側も同様に親和性と均衡を使う。出力は専門家装置表、トークン装置表、信頼度表で、モデル再配置とオンラインデータ配置へ直接渡される。

### データ並列注意向け要求再バッチ化
到着要求のプロンプトをトークン装置表で集計し、その要求が最も強く親和する専門家クラスタを求める。要求をその専門家群が置かれたデータ並列ランクへ送れば、注意計算後に専門家層へ到達した時点で多くのトークンが目的専門家と同じ装置に存在する。ただし親和性だけで割り当てると一部ランクへ要求が集中するため、連続する専門家並列度個の要求を全ランクへ均等に分配する負荷制約も入れる。出力はSGLangの通常バッチ処理へ渡せる要求配置であり、専門家側の配置表と同じクラスタ定義を共有する。これによりモデル配置だけを変える方法より遠隔全対全通信を直接減らし、高負荷時の処理能力低下を抑える。

### テンソル並列注意向け投機的トークン再配置
テンソル並列注意では全ランクが同じ要求を扱うため要求単位の配置変更ができない。そこで各トークンの識別子と直前層の専門家装置系列から次の専門家装置を予測し、注意後にもともと必要なreduce-scatterへトークン並べ替えを融合したshuffled-reduce-scatterを使う。これによりゲート確定前にトークンを目的候補装置へ先回りして散布する。専門家計算後の復元もshuffled-allgatherへ融合し、予測外れだけ通常の遠隔経路へ流すため正しさは失われない。最適化argsortはPyTorch標準より25%高速で、リング通信への融合追加費用は約1%と報告される。出力は通常の次層入力へ戻り、次層では再び予測表を使って同じ処理を繰り返す。

### 全体のデータ／制御の流れ
Sem-MoEはSGLangへのプラグインとして、オフライン活性化計測・共クラスタ化、配備時の専門家再配置、オンライン要求スケジューラ、テンソル並列通信カーネルを統合する。専門家装置表に合わせてゲート行列列も並べ替えるためモデル意味を保ち、データ並列注意では要求粒度、テンソル並列注意ではトークン粒度でデータを専門家へ近づける。
## 評価条件
- **ハードウェア**: GPU 8基の単一サーバ。各GPUは96GB HBMを持ち、GPU間は400GB/s超の高速専用接続。ホストは44コアIntel CPU 2基とDDR5 2TB。
- **ソフトウェア**: SGLangを基盤にSem-MoEを約5000行のPythonと複数のTriton通信カーネルで実装し、全対全通信にはDeepEPも統合する。
- **データセット／トレース**: MMLU、lmsys-chat-1m、ShareGPT-Vicuna-unfiltered
- **比較対象**: SGLang with DeepEP、MoETuner、vanilla エキスパート 配置
Qwen3-30B-A3BとDeepSeek-V2-Liteを主対象とし、MMLU、lmsys-chat-1m、ShareGPT-Vicuna-unfilteredのプロンプトを使う。各データ集合の20%で活性化予測と専門家配置表を作り、残り80%から評価要求を採る。要求率を10〜175 req/sで変え、データ並列注意では初回トークン遅延と終端間遅延を最軽負荷時の5倍以内とするSLO下の最大スループットを測る。テンソル並列注意では要求率1 req/sで入力長256、512、1024を比較する。局所活性化率、専門家層遅延、負荷不均衡率、予測精度も分解評価する。
高速相互接続を持つ8GPU単一サーバが中心で、データ並列注意とテンソル並列注意の双方を評価する。主結果はDeepSeek-V2-LiteとQwen3-30B-A3Bで、付録にMoonlight-16Bを追加する。
## 主要結果
主結果は、専門家配置と要求・トークン配置を同じ親和性で協調させるSem-MoEが遠隔全対全通信を減らし、DeepSeek-V2-Liteのデータ並列注意でSLO下スループットをMoETuner比最大2.78倍、Qwen3-30B-A3Bのテンソル並列注意で初回トークン遅延を最大24.9%削減したことである。実用上は、モデル品質やMoE構造を変えず、SGLangのスケジューラと既存通信へ配置制御を組み込むだけで、専門家並列通信が律速する配備の処理能力と応答遅延を改善できることを意味する。

- Attention-DP スループット under SLO / DeepSeek-V2-Lite: SGLang比+31%/+221%、MoETuner比+32%/+278%（TTFT/E2E SLO） (比較対象: SGLang with DeepEP / MoETuner; 条件: 8 GPU, リクエスト rate 10–175 req/s) — 要求配置と専門家配置を協調させることで、高負荷時にベースラインへ未処理要求が蓄積する領域でも処理能力を維持した。

- Attention-DP スループット under SLO / Qwen3-30B-A3B: SGLang比最大+98%/+11%、MoETuner比+35%/+32% (比較対象: SGLang / MoETuner; 条件: TTFT/E2E SLO) — 別の専門家構成でも協調配置の効果を確認した。

- Attention-TP TTFT reduction / DeepSeek-V2-Lite: 12.21%/10.60%/18.89%; Qwen3-30B-A3B: 17.16%/24.90%/3.80% (比較対象: best 比較対象; 条件: input length 256/512/1024, 1 req/s) — 予測トークン並べ替えを既存通信へ融合することで、追加通信をほぼ増やさず遠隔専門家送信を減らした。

- local 活性値 rate and エキスパート-層 遅延 / LAR +37%/+43%, エキスパート-層 遅延 -41.8%/-46.6% (比較対象: vanilla 配置; 条件: DeepSeek-V2-Lite / Qwen3-30B-A3B, Attention-TP) — エンドツーエンド改善の直接要因が専門家の局所活性化増加であることを示す。

- co-スケジューラ algorithm / best 比較対象比 local 活性値 rate +15.4%, load imbalance 指標 +36.7% improvement (比較対象: vanilla / MoETuner; 条件: DeepSeek-V2-Lite, EP8) — 通信局所性だけでなく負荷均衡も同時に改善する共クラスタ化が機能した。

- 静的 ルーティング prediction / precision 96.3%, F1 78.8% (比較対象: トークン identity based 静的 top-k エキスパート; 条件: 25% profile / 75% test split) — トークン識別子だけでも実用的な専門家予測信号が存在し、軽量表参照による先回り配置を可能にする。

### 負の結果・境界条件
- 局所活性化率100%は、異なるトークンが互いに矛盾する専門家配置を要求しGPUメモリも有限なため理論的にも一般には達成できない。MoETunerは負荷均衡の効果で一部条件を改善する一方、条件によっては遅くなる。Qwen3-30B-A3Bの入力長1024ではTTFT改善が3.80%まで縮小し、効果量はモデル・入力長・並列方式に依存する。

### 結果の読み方
MoE通信削減では専門家をどこへ置くかだけでなく、どの要求・トークンをその装置へ置くかを同じ親和性モデルで決めることが重要である。特にテンソル並列注意では、もともと必要なreduce-scatterへ予測再配置を融合することで追加通信を避けながら次の専門家層の全対全量を減らせる。
## 品質への影響
専門家とゲート列を透過的に並べ替え、予測が外れたトークンは通常の遠隔通信で処理するため、推論意味やモデル品質を近似化しない。
## 既存研究との差
ExFlowやMoETunerなどの既存法は主に専門家配置というモデル側の問題を解き、データ配置との共同最適化を行わない。Sem-MoEはトークン専門家親和性を共通信号として専門家クラスタとトークン・要求クラスタを同時に作る。専門家オフロード・先読み系はGPUメモリ節約のため次に必要な専門家を予測するが、Sem-MoEは専門家を退避せず、予測を通信局所化へ使う。Pre-gated MoEはモデル構造を変更して次層専門家を予測するのに対し、本手法は既存モデルを変更せず統計表とスケジューラだけで先回りする。データ並列注意とテンソル並列注意で異なる粒度のデータ移動を設計し、後者では既存collectiveへ並べ替えを融合する点も特徴である。
## 限界
評価は主に高速な装置間接続を持つ8GPU単一サーバで行われ、複数ノードEthernetやPCIe主体の環境では通信削減の絶対効果と追加並べ替え費用が変わる可能性がある。活性化予測と専門家配置は代表データの20%を使って事前構築するため、運用トラフィックの分布が大きく変化した場合は再計測・再配置が必要になる。未知トークンは埋め込み近傍で補うため、語彙外や特殊ドメインで予測精度が低下しうる。局所活性化率はトークン間で望ましい専門家配置が衝突し、装置メモリも有限なため100%にはできない。主実験はプロンプト部分に集中しており、長時間の復号で要求内容や専門家利用分布が変化する場合の継続適応は限定的である。
## 実装状態
Sem-MoEとしてSGLang上に実装。約5000行のPython、カスタムTritonカーネル、shuffled-reduce-scatter、shuffled-allgather、最適化argsort、DeepEP統合を含む。論文はICLR 2026採択版。
## 研究上の位置づけ
専門家並列MoEの通信最適化において、静的・動的専門家配置だけでなく入力データの配置まで同一の確率的親和性モデルで扱うモデル・データ共同スケジューリング研究に位置する。オフロードや専門家キャッシュとは補完関係にあり、GPU常駐専門家間の遠隔通信を減らす。サービングスケジューラとMoE並列通信カーネルを跨ぐため、MoE配置研究とLLM servingの要求スケジューリング研究を接続する。
