# SliM-LLM: Salience-Driven Mixed-Precision Quantization for Large Language Models

> 要素単位で重要重みだけ高精度に残すのではなく、重要度が空間的にまとまる性質を使って**グループ単位**で1/2/3ビットを割り当てる。さらに各グループ内部の少数の重要要素を量子化器校正で重く扱い、LLaMA-7Bの2ビット級でWikiText2パープレキシティ14.58を達成する。

## 概要

SliM-LLMは、極低ビットのLLM量子化で生じる「精度のために要素単位混合精度へすると、実機で扱いにくい」という問題を、**重要度（salience）の空間構造**から解く学習後量子化（post-training quantization; PTQ）である。GPTQなどの通常のグループ量子化は、同じ128重み程度のグループを一律2ビットへ落とすため実装しやすいが、重要重みまで粗く量子化して2ビット域で性能が崩れる。逆に一部の重みだけ8/16ビットで残す方式は精度を守りやすいが、同じワード内に異なる精度が混ざり、専用索引・分岐・不規則アクセスが必要になる。

著者らは代理ヘッセ行列（proxy Hessian）から重み要素の重要度を計算すると、重要要素が完全にランダムに散るのではなく、特定チャネル周辺へ集まることを観察する。そこで第一段の**重要度決定ビット割当（Salience-Determined Bit Allocation; SBA）**では、128列などの通常の量子化グループを単位に平均ビット幅を変える。目標2ビットなら、重要グループを3ビット、同数の重要度が低いグループを1ビット、残りを2ビットにして全体平均を保つ。

ただしグループ単位へ丸めると、同じグループ内に存在する約1%程度の局所的な重要重みをまだ取りこぼす。そこで第二段の**重要度重み付き量子化器校正（Salience-Weighted Quantizer Calibration; SQC）**が、量子化尺度とゼロ点の探索で重要要素の誤差を強く評価する。SBAが「どのグループへ何ビット与えるか」、SQCが「そのグループ内の量子化格子をどこへ置くか」を担当する二段構成である。

ICML 2025版の実験では、LLaMA-7Bの2ビット級SliM-LLMがWikiText2 PPL 14.58を示し、実GPUでは重みメモリ12.6 GBのFP16を2.3 GBへ圧縮する。混合精度カーネルの整列処理により速度はGPTQより低いものの、要素単位混合精度と違ってグループ内は単一精度なので整数パッキングを保てる。

## 問題設定：精度を守る混合精度がなぜ遅くなりやすいか

低ビット量子化では、重み (w_{ij}) を少数の格子点へ丸めたときの出力誤差が要素ごとに異なる。SliM-LLMはGPTQ/SparseGPT系の考えを使い、代理ヘッセ行列の逆行列対角成分と重み値から各要素を削除・量子化したときの感度を重要度として評価する。

活性値に外れチャネルがあると、(H=X^TX) の対応する対角成分も大きくなり、そのチャネルにつながる重み群の重要度がまとめて高くなる。つまり重要重みは完全な白色雑音のようには散らず、**チャネル方向にクラスタを作る**。この構造が、要素単位で高ビットを残さなくてもグループ単位混合精度でかなりの重要度を拾える根拠になる。

一方、グループ化だけでは局所的な重要要素を完全には囲めない。論文の可視化では、比較的重要度が低いグループの中にも約1%程度の突出した重要要素が残る。そこでグローバルなSBAとローカルなSQCを分ける。

## 手法

### 1. 要素重要度とグループ重要度を計算する

較正活性値 (X) から代理ヘッセ行列を作り、コレスキー分解（Cholesky decomposition）で逆行列情報を得る。各重みの重要度は、その重みを消去・変更した場合の二次近似誤差に対応するGPTQ/SparseGPT系の指標から算出する。

次に列方向を通常128などのグループへ分け、要素重要度をグループへ集約する。ここで出力は「各グループがどれだけモデル出力へ効くか」という順位になる。この段階ではまだ重みを量子化しない。

### 2. SBA：平均ビット幅を固定したまま重要グループへビットを移す

目標平均ビット幅を (N) とすると、SBAは一部グループを (N+1) ビット、同数を (N-1) ビットへ割り当て、残りを (N) ビットにする。2ビットなら3/2/1ビット混合、3ビットなら4/3/2ビット混合となる。

高精度グループ数と低精度グループ数を同数にするので、平均ビット幅は固定される。どこまで両端から置き換えるかは、全精度出力と混合精度出力のカルバック・ライブラー発散（Kullback–Leibler divergence）が小さくなるよう二重ポインタ探索で決める。グループ数が (k=m/128) なら候補領域はおおむね (0) から (k/2) までで、巨大な整数線形計画を解く必要がない。

比較実験ではLLaMAの2ビット条件で、整数線形計画（integer linear programming; ILP）による割当よりSBAが一貫して良く、7BではWikiText2 PPL 17.55→14.58、65Bでは7.46→5.90となる。単に最適化問題を厳密に解くより、重要度構造と出力誤差に合わせた制約付き探索が有効だった。

### 3. SQC：グループ内の局所的重要重みへ量子化格子を寄せる

各グループ内でも要素重要度を見て、局所的に突出した重みとそれ以外を分ける。通常のMinMaxや平均二乗誤差最小化では多数派の非重要重みが損失を支配し、少数の重要重みの誤差が残る。

SQCは尺度 (Delta) とゼロ点 (z) の候補を探索するとき、重要要素側の誤差を別項として扱い、重要度を反映した損失を最小化する。出力はそのグループ専用の尺度・ゼロ点である。OPT-1.3Bの可視化では、通常量子化器の平均絶対誤差0.0055に対してSQCは0.0039となり、特に局所的重要要素の誤差が下がる。

### 4. GPTQ型誤差補償とパッキング

グループを量子化した後はGPTQと同様に、量子化前後の残差を逆ヘッセ行列で未処理列へ伝播する。したがって処理フローは、代理ヘッセ行列作成 → SBAでグループビット決定 → SQCで量子化器校正 → グループ量子化 → 誤差補償、の順になる。

保存時は1つのグループ内を単一ビット幅に保つ。1/2/3/4ビット値をグループごとに整数へパックし、別の小さな配列へ各グループのビット幅を2ビットで記録する。要素ごとに精度タグを持たないので連続した整数パッキングを維持できる。SliM-LLM+ではSBAをOmniQuant型の学習可能量子化器へ組み込み、さらに較正精度を上げる。

## 評価

### 評価条件

|項目|条件|
|---|---|
|モデル|OPT 1.3B〜66B、LLaMA 1/2、拡張版ではLLaMA 3も評価|
|主精度|重みのみ2/3ビット級、グループサイズ128|
|較正|代理ヘッセ行列を較正活性値から構築|
|PPL|WikiText2、C4|
|ゼロショット|PIQA、ARC-Easy/Challenge、BoolQ、HellaSwag、WinoGrande|
|比較|RTN、GPTQ、AWQ、QuIP、PB-LLM、OmniQuant、AffineQuant等|
|実GPU|NVIDIA A800、AutoGPTQを拡張した混合精度CUDAカーネル|

### 2ビット級の代表PPL

|モデル / データ|GPTQ|QuIP|SliM-LLM|読み取り|
|---|---:|---:|---:|---|
|OPT-6.7B / WikiText2|20.18|18.57|14.41|通常2ビットより改善|
|LLaMA-7B / WikiText2|34.63|33.74|14.58|極低ビット崩壊を大幅緩和|
|LLaMA-2 7B / C4|33.70|31.94|16.00|LLaMA 2でも同傾向|
|LLaMA-2 70B / C4|GPTQはNaN|8.17|7.01|大規模モデルでも有効|
|LLaMA-3 8B / C4|約4.1×10⁴|約1.3×10²|約1.1×10²|新世代モデルは2ビット自体が難しい|

論文がいう「48% PPL低減」は、代表的な勾配不要PTQとの比較をまとめた値である。個々のモデルでは差が大きく異なるため、全モデルへ同じ48%を適用して解釈しない方がよい。

2ビットLLaMA-7Bのゼロショット平均はGPTQ 39.65、SliM-LLM 43.84、OmniQuant 49.11、SliM-LLM+ 51.02である。勾配不要のSliM-LLMはGPTQより改善するが、学習可能量子化器を使うOmniQuantには届かない。SliM-LLM+まで組み合わせると上回る、という位置付けである。

重みメモリはLLaMA-7Bで12.6→2.3 GB、約5.5倍の縮小である。一方、2ビットSliM-LLMはGPTQより生成速度が低い。論文は異なるビット幅を整列させる混合精度処理と、現行ハードウェアで1ビット演算の支援が弱いことを理由に挙げる。したがって「精度を上げつつGPU速度を完全維持」というより、**大きな精度改善と引き換えに一定の速度オーバーヘッドがある**という実測を残すべきである。

## 既存研究との差

GPTQは同じビット幅でグループ量子化し、ヘッセ行列で誤差補償する。SliM-LLMはその実装構造を保ちながら、グループごとの重要度に応じてビット幅を変える。したがって既存GPTQカーネルの考え方を大きく崩さず混合精度化できる。

PB-LLMや高精度外れ値保持法は重要要素を個別に例外扱いするため、値と位置の混在がハードウェア実装を複雑にしやすい。SliM-LLMは例外をグループ境界へ揃え、局所的重要度はSQCで量子化格子側へ吸収する。この「精度の不均一性を、値単位ではなくグループ単位へ構造化する」点が主要差である。

## 限界・実装上の注意

混合精度カーネルは一様精度より複雑で、実測でも2ビットSliM-LLMはGPTQより遅い。特に1ビットグループを混ぜる2ビット平均構成は、現在のGPUで1ビット整数演算が直接強く支援されないため、理論上のビット削減がそのまま演算速度へ変換されない。

重要度とビット割当は較正分布に依存する。外れチャネル構造が実運用データで大きく変われば、オフラインで決めたグループ精度が最適でなくなる可能性がある。また2ビット域ではLLaMA-3など一部モデルで依然PPLが高く、SliM-LLMでも極低ビット化が無損失になるわけではない。

SliM-LLM+はさらに高精度だが勾配ベース較正を導入するため、純粋なSliM-LLMより変換コストが増える。速度・圧縮時間・最終品質のどこを優先するかで両者を区別すべきである。
