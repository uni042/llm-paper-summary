# GPTQ: Accurate Post-Training Quantization for Generative Pre-trained Transformers

> 二次情報に基づく誤差補償をGPU向けに再設計し、175B級LLMを数時間で3〜4bit化して単一A100実行と約3.24倍の生成高速化を実現した基礎的GPTQ研究。
## 書誌情報
- **著者**: Elias Frantar, Saleh Ashkboos, Torsten Hoefler, Dan Alistarh
- **著者・所属**: IST Austria; ETH Zurich; NeuralMagic
- **公開**: ICLR 2023
- **種別**: 国際会議論文
- **対象**: 後学習量子化、重み-only量子化、二次情報、低ビットLLM、GPU推論カーネル
- **実装**: PyTorch実装と量子化重み×FP16ベクトルの専用GPUカーネルを公開。公式コード: https://github.com/IST-DASLab/gptq
## 概要
GPTQは大規模生成Transformerを再学習なしで3〜4bit重みに圧縮する後学習量子化法である。OBQの二次情報による誤差補償を基礎に、全行で量子化順序を共有してHessian逆行列更新を大幅に削減し、128列単位の遅延バッチ更新とCholesky分解でGPU効率と数値安定性を確保する。OPT-175B/BLOOM-176Bを単一A100で約4時間で量子化し、3bit OPT-175Bを単一80GB A100に収容、専用重み-onlyカーネルでFP16比約3.24倍の生成レイテンシ短縮を示した。

GPTQはOptimal Brain 量子化 (OBQ)のHessianベース誤差補償を維持しつつ、巨大行列向けに三つの変更を入れる。第一に、各行で貪欲に別々の重み順序を選ぶ必要性が小さいという観察から全行で同じ固定列順序を使い、Hessian逆行列更新を列ごと1回へ共有する。

第二に、128列をブロックとして局所更新を蓄積し、ブロック完了時だけ残り全列へ行列積で反映する遅延バッチ更新でGPUのメモリ帯域律速を緩和する。第三に、逐次的な逆行列更新の数値不安定性を、1% dampingとCholesky分解による必要行の事前計算へ置き換える。これによりOBQ系の二次情報量子化を175B級へ実用時間で拡張した。

代表結果として、OPT-175B 4bit WikiText2 perplexityはGPTQ per-row asymmetric 4bitでFP16 8.34; RTN 10.54に対して8.37。175B級でも4bit化によるperplexity増加は0.03に留まる。
## 問題設定
175B級LLMはFP16重みだけで300GB超を要し、推論にも複数GPUが必要になる。再学習を伴う低ビット量子化は巨大モデルでは高価で、既存の高精度な後学習量子化も層・重みごとの最適化が重く、数十億〜数百億パラメータへ素直に拡張できない。一方、単純な最近傍丸め(RTN)は175B級まで高速に適用できるが、3〜4bitではperplexityが大きく悪化する。したがって、再学習なし・少量校正データだけで、二次情報を使う高精度量子化を175B級へ数時間で適用し、実際の推論メモリとレイテンシを下げることが課題である。
## 新規性

## 手法
### 手法のあらまし
処理は校正、層単位量子化、誤差補償、次blockへの伝播、圧縮推論の順に進む。まずC4から抽出した128本の2048-トークン系列をモデルへ流し、現在の線形層入力Xを集めてH=2XX^Tを作り、平均対角値の1%を加えて安定化する。目的は量子化前後の層出力差 ||WX-QX||^2 の最小化である。OBQでは各出力行ごとに最小誤差の重みを選ぶが、GPTQは大規模層では順序差の効果が小さいという観察から、すべての行を同一の固定列順序で処理する。これにより未量子化集合と逆Hessianを全行で共有でき、逆行列更新回数を大幅に削減する。各列jを量子化すると、丸め誤差を逆Hessianのj行で重み付けして、まだ量子化していない列へ即座に補償する。

ただし全行列を列ごと更新するとメモリ trafficが支配するため、128列の局所block内だけ逐次補償し、blockが終わった時点で蓄積誤差Eと逆Hessian部分行列の行列積により残り全列へ一括反映する。逆Hessianの必要情報は反復的なGaussian eliminationではなくCholesky分解から事前に得て、大規模モデルでの数値的不定値化を避ける。モデル全体はTransformer blockを一つずつGPUへ載せて量子化し、その量子化済みblockへ校正入力を再度通した出力を次blockの入力にするため、累積誤差を後段校正へ反映しつつ全FP16モデルをGPUへ置く必要がない。完成した3/4bit重みは保存容量を減らし、生成時には専用GPUカーネルが圧縮重みを読みながら動的に展開してFP16 活性値 vectorと積を取る。自己回帰バッチ 1では行列ベクトル積がメモリ帯域律速なので、読み出しbyte数の削減がそのままトークン 遅延低減につながる。

### 共有固定順序による二次情報量子化
OBQは各出力行について、量子化誤差と逆Hessian対角を使って次に丸める重みを貪欲選択し、残り重みを補償するため高精度だが、行ごとに異なる順序と逆Hessian更新が必要になる。GPTQは大きな全結合層ではこの貪欲順序の利得が小さいことを実験的に確認し、全行を同じ列順序で量子化する。

Hessianは重みではなく層入力Xだけに依存するので、未量子化集合と逆Hessianを全行で共有できる。これにより計算量をO(d_row*d_col^3)からO(max(d_row*d_col^2,d_col^3))へ下げ、二次情報による誤差補償を175B級でも使える計算量へ縮小する。

### 遅延バッチ更新
固定順序化だけでは、各列の量子化後に巨大な残り重み行列を少数FLOPで更新するためGPUはメモリアクセス律速になる。GPTQは128列を一つのblockとして処理し、block内の後続列に必要な補償だけを逐次適用する一方、block外の全列への補償は誤差行列Eへ蓄積する。

block完了後にEと逆Hessian部分行列の積として一度に更新することで、細粒度vector更新を高効率なmatrix operationへ変換する。理論FLOP数自体は減らさないが、巨大モデルでは実時間を約1桁改善し、GPUの計算能力を利用できる形へ変える。

### Cholesky再定式化とdamping
OBQ型の逐次Gaussian eliminationを大規模層で繰り返すと丸め誤差が蓄積し、逆Hessianが数値的に不定値化して残り重みを誤方向へ大きく更新する場合がある。GPTQは量子化列qで実際に必要なのが、その時点の逆Hessianのq行の対角以降だけであることを利用する。

この情報列は対称正定値行列のCholesky分解と対応するため、最初に最適化済みCholesky カーネルで必要情報を安定に計算する。さらにHessian対角へ平均値の1%をdampingとして加え、数十億〜175B規模でも量子化処理が破綻しないようにする。

### 逐次Transformer-block校正
175BモデルのFP16全体を量子化用GPUへ載せること自体が不可能なので、GPTQはTransformer blockを一度に一つ、論文実装では6線形層から成る単位としてA100へロードする。校正系列からそのblockの層入力を収集して各線形層を量子化した後、同じ入力を量子化済みblockへもう一度通し、その出力を次blockの校正入力として保持する。

したがって後段層は理想的なFP16入力ではなく、前段で実際に生じた量子化誤差を含む入力に対して最適化される。GPUメモリを抑えながらモデル全体の逐次誤差伝播を校正に織り込む設計である。

### 重み-only生成カーネル
量子化後の容量削減を実レイテンシへ変換するため、著者らは3/4bit量子化行列とFP16 活性値 vectorの積を行う専用GPU カーネルを実装する。重みは圧縮状態でGPUメモリから読み出し、演算直前に動的展開するため、活性値を量子化する必要がない。

バッチ 1の自己回帰生成では大規模線形層がmatrix-vector productとなり演算器よりメモリ帯域が律速するため、展開の追加計算より重み読み出し量の削減が勝つ。OPT-175Bではこの設計によりA100でFP16 230ms/トークンから3bit 71ms/トークンへ短縮し、同時に必要GPU数も5枚から1枚へ減らす。

### 全体のデータ／制御の流れ
GPTQは量子化精度、量子化処理時間、推論メモリ、生成レイテンシを一つの流れとして設計する。校正データから得た二次情報で低bit丸め誤差を補償し、固定順序化で共有可能な状態を増やし、遅延バッチ更新でGPU向けの高算術強度処理へ変換し、Choleskyで大規模時の数値安定性を確保する。

block単位校正により175B FP16全体を単一GPUへ載せずに処理でき、得られた圧縮重みは重み-only カーネルでオンザフライ展開する。したがって『高精度だが遅い二次情報PTQ』と『速いが3bitで壊れる単純RTN』の間を埋めるだけでなく、圧縮率をGPU常駐可能性とメモリ-bound生成速度へ直接結び付けるエンドツーエンドな量子化・推論経路になっている。
## 評価条件
- **ハードウェア**: 全モデルの量子化は単一NVIDIA A100 80GBで実施。OPT-175Bの生成レイテンシ評価はA100 80GBとA6000 48GBを使用し、FP16ではA100 5枚/A6000 8枚、3bit GPTQではA100 1枚/A6000 2枚へ削減。
- **ソフトウェア**: PyTorchとHugging Face版OPT/BLOOMを使用。GPTQは一様per-row asymmetric min-max量子化、基本block size 128、Hessian dampingは平均対角値の1%。生成用に量子化行列×FP16ベクトルの専用GPUカーネルを実装。
校正データはC4からランダム抽出した2048-トークン segment 128本のみで、task-specific dataは使わない。OPT/BLOOM各サイズを3/4bitへ量子化し、WikiText2・PTB・C4のperplexity、LAMBADA・ARC Easy/Challenge・PIQAのzero-shot精度を評価。RTNを主比較対象とし、小型モデルではOBQ/AdaRound/BRECQ等とも比較する。生成速度はバッチ size 1、生成長128で平均トークン 遅延を測定し、FP16との差は主にmatrix-vector カーネルだけになるようHuggingFace/accelerate型の層分割設定を用いる。
OPT 125M〜175BとBLOOM 560M〜176Bを中心に、ResNet/BERT-baseでも量子化器自体を検証する。自己回帰生成の低バッチ・メモリ-bound条件が主対象であり、大バッチのcompute-bound推論、活性値 量子化、現代的attention/serving stackとの統合は直接評価していない。
## 主要結果
GPTQは175B級モデルを単一A100で約4時間で量子化し、4bitではFP16に極めて近いperplexity、3bitでも単純RTNが崩壊する条件で実用的品質を維持した。OPT-175Bの3bit表現は約63GBで、最大2048-トークンのKV キャッシュ約9GBを加えても80GB A100 1枚へ収まる。専用重み-only カーネルではバッチ 1生成の平均トークン 遅延をA100で230ms→71ms、A6000で589ms→130msへ短縮した。

- OPT-175B 4bit WikiText2 perplexity / 8.37 (比較対象: FP16 8.34; RTN 10.54; 条件: GPTQ per-row asymmetric 4bit) — 175B級でも4bit化によるperplexity増加は0.03に留まる。

- OPT-175B 3bit WikiText2 perplexity / 8.68 (比較対象: FP16 8.34; RTN 7.3e3; 条件: GPTQ 3bit) — 単純丸めが破綻する3bitでも品質を維持する。group size 128では8.45まで改善。

- BLOOM-176B 3bit WikiText2 perplexity / 8.64 (比較対象: FP16 8.11; RTN 571; 条件: GPTQ 3bit) — 別モデル系列でも3bit RTNの崩壊を回避する。

- 175B量子化時間 / OPT-175B 4.2h; BLOOM-176B 3.8h (比較対象: ZeroQuant-LKDは1.3Bで約3hと報告; 条件: single NVIDIA A100 80GB) — 高精度二次情報PTQを数百B規模へ実用時間で拡張した。

- OPT-175B生成レイテンシ / A100 230→71ms/トークン (3.24×); A6000 589→130ms/トークン (4.53×) (比較対象: FP16 distributed inference; 条件: バッチ size 1, sequence generation length 128; GPTQ 3bit) — 圧縮によるメモリ traffic削減がメモリ-bound生成を実時間で高速化する。

- GPU必要数 / A100 5→1; A6000 8→2 (比較対象: FP16→GPTQ 3bit OPT-175B; 条件: 生成推論、KV キャッシュを含む) — 3bit化は175Bモデルを単一80GB GPUへ収容可能にする。

### 負の結果・境界条件
- 3bitでは中小OPTやOPT-66Bで4bitよりperplexity悪化が大きく、2bitではgroupingなしの実用性は低い。2bit GPTQはgroup size 128でOPT-175B WikiText2 PPL 9.58、group size 32で8.94まで改善するが、scale/zero-point オーバーヘッドで平均bit数は2bitを超える。速度向上は算術演算削減ではなくメモリ traffic削減由来で、compute-boundな大バッチでは同じカーネル利得を期待できない。活性値 量子化は扱わない。

### 結果の読み方
GPTQの本質は『低bit表現』そのものより、OBQ由来の二次誤差補償を巨大Transformerで実行可能にしたアルゴリズム・システム再設計にある。さらに低bit重みの容量削減をメモリ-boundな自己回帰生成の帯域削減へ結び付けたことで、精度・容量・実レイテンシの三者を同時に改善した。
## 品質への影響
4bitは175B級でほぼFP16品質、3bitは小幅〜中程度の劣化でRTNを大幅に上回る。zero-shot LAMBADA/ARC/PIQAでも同様に4bitは安定し3bit GPTQはRTN崩壊を回避する。一方、2bit/ternaryはgroupingと引き換えに品質・metadata オーバーヘッドのトレードオフが増える。
## 既存研究との差
RTN/LLM.int8()/ZeroQuantの当時の巨大モデル向け重み 量子化が実用速度のため基本的に最近傍丸めへ依存したのに対し、GPTQはHessian近似を使うOBQ系の誤差補償を175B級へ拡張する。OBQは各行で重みを貪欲順序に量子化するため計算量が大きいが、GPTQは全行で列順序を共有し、遅延バッチ更新とCholesky再定式化でGPU効率・安定性を得る。AWQ等の後続手法が活性値-awareな重要重み保護やより軽量な校正へ進む以前の、二次情報重み-only PTQの代表的基礎である。
## 限界
速度向上は低bit整数演算によるFLOP削減ではなく、重みを圧縮してメモリ trafficを減らす効果に依存する。したがってバッチ 1の自己回帰生成のようなメモリ-bound条件には強いが、大バッチのmatrix-matrix計算などcompute-bound条件では専用カーネルの直接的な高速化は限定的である。活性値 量子化は対象外で、KV キャッシュもFP16のまま。評価モデルはOPT/BLOOM中心で、instruction-tunedモデルやMoE、現代的serving stackでの挙動は未検証である。2bit以下はgroupingを必要とし、品質低下とscale/zero-point オーバーヘッドが増える。公平性などperplexity以外の二次的品質影響も十分調べていない。
## 実装状態

## 研究上の位置づけ
LLM推論の量子化系統における基礎論文であり、低bit化を『保存容量削減』だけでなく『GPUメモリ帯域削減による生成高速化』へ結び付けた点がシステム上重要である。175Bモデルを単一A100へ載せる結果は、後続のGPTQ形式、AutoGPTQ、Marlin等の重み-only低bit実装につながる実用的設計空間を明確にした。階層メモリ・オフロード研究との関係では、圧縮によってそもそもの重み転送量とGPU常駐容量を減らす直交的手段として位置付けられる。
