# OA-EM：2ビット加算量子化でコードブック初期化が最終解を左右する

## 概要

LLMを2ビット/重み（2 bpp）程度へ圧縮する際、各重みを独立に少数の整数へ丸めるスカラー量子化では品質低下が大きくなる。加算量子化（AQLM）は、複数の学習可能なコードブックからコードワードを選び、それらの和で重みの小グループを表現する。実行時には事前計算したルックアップテーブルから復元できるため、格子型量子化のように毎グループで追加の行列演算を必要としない。しかし2 bppでは、通常の貪欲なコードブック初期化が悪い解の領域に入り、後段のbeam searchやPV-tuningを増やしても十分に回復できないことがある。

本研究はコードブック初期化を、較正入力の活性から求めた二次情報で重み付けしたOutput-Aware Expectation-Maximisation（OA-EM）へ置換する。重み空間のユークリッド距離ではなく、量子化した線形層の出力再構成誤差に近いHessian重み付きMahalanobis距離でコードワードを配置する。圧縮表現の候補数と重みグループ数の比を表すρ=N/K^Mを導入し、コードブック表現容量が不足する領域で初期化の影響が強くなると説明する。

Llama 3.2 3Bの2 bpp・beam8では、PV-tuning前のWikiText-2困惑度が貪欲初期化60.61からOA-EM 17.39へ改善し、PV-tuning後も11.76から11.53へ差が残る。beam4ではPV-tuning後の困惑度が12.66→11.53となり、量子化時間6.1時間でbeam8の貪欲方式9.9時間より良い最終品質を得る。一方Qwen 2.5 3Bでは困惑度が改善しても6課題平均正答率は0.606から0.603へ小幅に悪化する。低ビット化後の品質改善は、困惑度と下流正答率を区別して評価すべきである。

## 問題設定と表現容量

AQLMではg個の重みを一つのグループとし、M個のコードブックそれぞれからK個の候補の一つを選び、その和で重みベクトルを近似する。通常K=256とし、Mやグループサイズを調整して目標bppを実現する。表現可能なコードワード組合せの数はK^Mである。推論時には選択されたコードの組合せを事前計算したルックアップテーブルで復元でき、重みグループごとの追加乗算を減らせる。

一方、初期化時には各グループをどのコードワードの組合せへ割り当てるかという離散最適化が必要となる。標準的な貪欲初期化はコードブックを順番に適合させ、後からbeam searchで割当てを改善する。しかしコードワード自体が悪い位置にあると、探索を増やしても良い割当ては存在せず、beam searchが悪い候補集合の中で最良のものを見つけるだけになる。

著者は重みグループ数Nとコードブック表現容量K^Mの比ρ=N/K^Mを定義する。ρが1未満なら表現可能な候補がグループ数より多い「過完備」領域、ρが1を超えると候補数が相対的に不足する「不足」領域である。Llama 3.2 3Bでは3 bpp・M=3でρ約0.07、2 bpp・M=2でρ約18とされ、候補容量は256分の1になる。ρは初期化感度の目安だが、モデルの重み分布が異なれば同じρでも品質は異なるため、唯一の決定因子ではない。

## 手法

### 加算量子化のコードブック初期化

各層の重み行列を小グループに分割し、各グループの近似ベクトルを複数コードブックのコードワード和で構成する。貪欲初期化では一つ目のコードブックが大きな誤差を吸収し、後続のコードブックが残差を順次近似する。この順序依存の手順は簡便だが、2 bppでは組合せの自由度が小さく、初期の誤配置が後段の探索で修正されにくい。

AQLMの後段には、コードワード割当てのbeam searchと、量子化したモデルのコードブック・割当てを調整するPV-tuningがある。著者はこの後段を両方式で揃え、初期化だけを置換することで、初期配置が最終品質へ及ぼす影響を調べる。単に探索幅を大きくすることが解決策ではないという仮説を、beam4、8、16や早期停止条件で比較する。

### OA-EMの出力認識型距離

OA-EMはExpectation-Maximisationを利用し、コードワードへの割当てとコードブックの更新を交互に行う。重要なのは距離の定義である。重みベクトルの単純な二乗誤差ではなく、較正データから得た活性の共分散・Hessian近似で重み付けしたMahalanobis距離を用い、線形層の出力へ与える影響が大きい方向の誤差を重く評価する。

ある重み誤差δwが入力活性xへ作用すると、出力誤差はxの方向に依存する。較正入力の二次統計Hを使えば、期待出力誤差はδw転置Hδwの形で近似できる。OA-EMはこの幾何を用いてコードブックを初期配置し、後続のbeam searchで割当てを改善する。重み空間で近いコードワードが必ずしも出力にとって良いとは限らないため、単純なクラスタリングより適切な初期値を作ることを狙う。

これは新しい推論カーネルや量子化フォーマットを提案するものではない。既存AQLMの学習可能なコードブックの初期化段階を差し替える手法であり、量子化後のルックアップテーブル復元という推論経路は維持される。したがって本研究の主な速度測定は量子化を作成するためのオフライン時間であり、実行時のトークン生成速度ではない。

### beam searchとPV-tuningの関係

初期化後、各重みグループのコードワード割当てをbeam searchで改善する。beam幅を大きくするとより多くの候補を保持できるが、初期コードブックが悪い位置にあると、探索幅の拡大だけでは大きな誤差を消せない。さらにPV-tuningはコードブックと割当てをモデル全体で微調整するため、初期化差が縮小する可能性がある。

著者は、PV-tuning後にもOA-EMの品質差が残るなら、異なる初期値が異なる最適化の盆地（basin）へ入っている証拠になると考える。これは非凸最適化の経験的な説明であり、すべての局所解の構造を数学的に証明したものではない。実際、PV-tuningで貪欲初期化の極端な困惑度は大幅に回復するが、最終値ではOA-EMが全設定で低い困惑度を示す。

### 量子化時間と実行時費用の切り分け

OA-EM自体には初期化計算が必要であり、必ず全設定で量子化時間を短縮するわけではない。良い初期値によりbeam searchの収束が速くなれば全体時間を減らせるが、beamを早期停止する条件では初期化の固定費用が相対的に大きくなる。原著は量子化の作成時間を時間単位で比較し、これを推論時のTPOTやスループットとは別の指標としている。

また格子型のQuIP#やGLVQでは、数学的に制約されたコードブックを使い、コードワードの初期配置問題を別の方法で回避する。ただし格子復元では実行時に追加の算術演算が必要になる場合がある。OA-EMは自由形式の加算コードブックを改善し、LUT復元を維持するため、低消費電力CPUやエッジ向けの計算負担を増やさず圧縮品質を上げる方向である。

## 評価

### 実験環境と測定条件

対象はLlama 3.2 3B、Llama 3.1 8B、Qwen 2.5 3Bの三系列。2 bppと3 bpp、beam幅4/8/16、最大100 epochや5 epochの早期停止を比較する。品質はWikiText-2とC4の困惑度、LAMBADA、HellaSwag、PIQA、WinoGrandeなど6つのzero-shot課題の平均正答率で測る。主な実験は単一NVIDIA A100 80GB、Llama 3.1 8BのPV-tuningはB200 192GBを使う。

原著の各条件は固定乱数seed42の単一runであり、複数seedの信頼区間は示されていない。PV-tuning前の困惑度とPV-tuning後の困惑度を混同せず、作成時間の比較も同じモデル・同じ探索条件で行う。2 bppでの効果が特に大きいことを確認するため、3 bppの結果を対照として使う。

### 2 bppのPV-tuning前（表1）

Llama 3.2 3Bでは、FP16のWikiText-2困惑度7.28に対して、貪欲初期化の2 bpp・beam4は352.39、beam8でも60.61、beam16でも46.01となる。beamを4倍に増やしても極端な品質低下が残る。一方OA-EMはbeam4で16.82、beam8で17.39、beam16で16.53と、beam幅に対して比較的安定する。

beam8・100 epochのC4困惑度は、貪欲初期化18.64に対してOA-EMが18.00であり、WikiText-2だけでなく別のコーパスでも改善する。3 bppでは貪欲初期化のWikiText-2 9.52からOA-EM 8.87への改善と小幅であり、C4は13.39から13.51へわずかに悪化する。圧縮率が極端になるほど初期化の影響が増すというρによる説明と整合するが、全データセットで無条件に改善するわけではない。

### PV-tuning後の困惑度と量子化時間（表2）

| Llama 3.2 3B・2 bpp | 貪欲 初期→PV後 | OA-EM 初期→PV後 | 量子化時間 貪欲→OA-EM |
|---|---:|---:|---:|
| beam4・100 epoch | 352.39→12.66 | 16.82→11.53 | 6.1→6.1時間 |
| beam8・100 epoch | 60.61→11.76 | 17.39→11.53 | 9.9→9.2時間 |
| beam16・100 epoch | 46.01→12.01 | 16.53→11.49 | 16.9→15.5時間 |
| beam8・5 epoch | 85.72→12.69 | 18.91→11.76 | 6.8→7.3時間 |

PV-tuningは貪欲初期化の大きな初期誤差を相当程度回復する。beam4では352.39から12.66へ下がり、OA-EMでも16.82から11.53へ下がる。最終差は初期段階の数百ポイントから1.13ポイントに縮小するが、OA-EMの方が低い。beam8では最終差0.23ポイント、beam16では0.52ポイントである。したがって「初期化が全てを決める」ではなく、後段の微調整が大きく改善しつつ、初期化の影響が完全には消えないという結果である。

量子化時間ではbeam8の9.9→9.2時間、beam16の16.9→15.5時間とOA-EMが速い。beam4は同じ6.1時間で、5 epochの早期停止では6.8→7.3時間とOA-EMの方が遅い。著者の主張する品質・計算のPareto優越は、設定によって例外があることを踏まえて読むべきである。OA-EM beam4は6.1時間で最終困惑度11.53を達成し、貪欲beam8の9.9時間・11.76より良い。この比較では約38%の量子化時間を節約するが、推論時の速度が38%向上するという意味ではない。

### 下流タスクの平均正答率（表3）

| モデル・2 bpp・PV-tuning後 | 貪欲初期化 | OA-EM | 差 |
|---|---:|---:|---:|
| Llama 3.2 3B・beam4 | 0.573 | 0.589 | +0.016 |
| Llama 3.2 3B・beam8 | 0.585 | 0.591 | +0.006 |
| Llama 3.2 3B・beam16 | 0.585 | 0.591 | +0.006 |
| Llama 3.2 3B・beam8・早期停止 | 0.563 | 0.572 | +0.009 |
| Llama 3.1 8B・beam8 | 0.649 | 0.656 | +0.007 |
| Qwen 2.5 3B・beam8 | 0.606 | 0.603 | -0.003 |

Llama 3.2 3Bではすべてのbeam設定でOA-EMの平均正答率が高い。Llama 3.1 8Bでも6課題中4課題で改善し、平均は0.7ポイント上がる。ただしQwen 2.5 3Bでは平均が0.3ポイント下がる。著者はQwenでもPV-tuning後のWikiText-2/C4困惑度はOA-EMが改善すると述べるが、困惑度改善と下流正答率改善は同義ではない。6課題の平均値は単一seedの結果であり、0.3ポイント程度の差に統計的な確証があるわけではない。

### ρと圧縮率の影響

Llama 3.2 3Bの3 bppではρ約0.07で、コードブックの組合せ容量が重みグループ数を上回るため、初期化の悪さを後段の探索が吸収しやすい。2 bppではρ約18となり、グループ数に対して表現候補が少ないため、初期のコードワード配置が後段の最適化可能な領域を制限する。著者は三つのアーキテクチャを比較してこの傾向を検証するが、同じρでもQwenの重み統計が滑らかな場合は初期化の悪影響が相対的に弱いと説明する。

ρは、量子化の圧縮率だけでなく、重みグループ数とコードブック数・サイズを同時に考慮する指標である。これを用いることで「3 bppから2 bppへ1ビット減っただけ」と捉えるより、表現可能な組合せが指数的に減るという非連続的な難しさを説明できる。ただしρはモデルの損失関数の凸性や最適解を直接決めるものではなく、コードブック初期化を重点的に最適化すべき領域を示す経験的な診断指標である。

## 限界・負の結果

第一に、下流タスクの正答率は全モデルで改善しない。Qwen 2.5 3Bでは貪欲方式0.606に対しOA-EMが0.603と低い。困惑度の改善が下流タスクの正答率へ常に転移するとは限らず、複数の品質指標を併用する必要がある。

第二に、結果は単一seed42の実験であり、初期値や較正データのサンプリングによるばらつきの信頼区間がない。2 bppで極端な初期困惑度差が生じることは観測されたが、全ての重み分布・モデル規模で同じ大きさの差が出ることは保証されない。

第三に、OA-EMの初期化には追加計算が必要で、早期停止条件では貪欲方式より量子化時間が長くなる（6.8→7.3時間）。量子化を何度も作り直す用途では、この固定費用が重要となる。PV-tuning後の最終差は初期段階ほど大きくないため、利用可能な作成時間と品質改善の交換条件を評価すべきである。

第四に、原著の速度比較は主に量子化のオフライン作成時間であり、2ビットモデルの実行時TPOT、TTFT、同時要求スループットや電力を直接比較したものではない。LUT復元が算術演算を減らすという方式上の利点はあるが、対象ハードウェアで実際に何倍速いかは別途ベンチマークが必要である。

第五に、評価モデルは3Bと8B級であり、数十BのMoE、長文脈KVキャッシュとの相互作用、量子化とLoRAの共同学習、CPUとGPUをまたぐオフロード時の速度は未検証である。A100とB200の測定条件も一部で異なるため、異なるモデル間の作成時間を直接比較してハードウェア効果と結論しない。

## 既存研究との差と実装判断

QuIP#やGLVQは構造化されたコードブック幾何を使って極低ビット精度を確保するが、復元時の算術演算が必要になる場合がある。AQLMは自由形式の加算コードブックでLUT復元を利用するため、実行時の計算負担を小さくできる一方、コードワード配置の初期値に敏感である。OA-EMはこの初期値を較正活性の二次情報で改善し、同じAQLMの探索・PV-tuningへ渡す点で異なる。

実装時には、2 bppでbeam幅を増やす前に初期コードブックの品質を測ることが有効である。ρが大きい場合は、単純な貪欲初期化で作ったコードブックを長時間探索するより、OA-EMで出力認識型の初期配置を行い、少ないbeam幅でPV-tuningする方が品質・作成時間の両方で有利になり得る。ただしQwenの下流正答率の例外や早期停止時の時間増を確認し、最終困惑度だけで導入を決めないことが重要である。
