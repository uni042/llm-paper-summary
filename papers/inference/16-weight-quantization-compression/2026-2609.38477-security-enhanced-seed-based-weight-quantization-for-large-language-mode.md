# Seed-Q — 重み感度に応じたシード生成型量子化と、その故障伝播の実態

## 書誌情報

Qiuyu Ren、Sudipta Paria、Aritra Dasgupta、Swarup Bhuniaによる2026年9月29日公開のarXivプレプリント（arXiv:2609.38477）。対象はLLMの重みのみを圧縮する推論向け表現であり、学習時の活性値量子化やKVキャッシュ圧縮とは別の技術である。原著の§3、§4、付録A〜Dに手法、比較評価、ハードウェア合成、故障試験が記載される。

## 概要

LLMの自己回帰デコードは重み転送に律速される場合があり、低ビット重みの保持だけでなく、圧縮した記号から演算時に重みを生成する方法が検討されている。SeedLMは重みを8要素ずつのブロックに分け、線形帰還シフトレジスタ（LFSR）で生成する擬似乱数基底と少数の係数を記録する。しかし全ブロックへ同じ表現予算を配るため、誤差に敏感な箇所と鈍感な箇所を区別できない。

Seed-Qは、保存済みモデルの正規化ゲインと重みから感度を近似し、各ブロックに異なるシード長と基底係数数を割り当てる。デコーダは共有テーブルとチェックポイントから得られる情報で割当規則を再現し、ブロックごとの明示的な形式識別子を不要にする。LLaMA-2-7B/13B、LLaMA-3-8B、Mistral-7Bの4 bit/weightでSeedLMの困惑度をそれぞれ5.85→5.68、5.18→5.06、7.17→6.92、6.32→5.96へ改善した（原著Table 1）。同等の困惑度を維持しながら平均約3.75〜3.88 bit/weightへ下げるモードも示す。

一方、「security-enhanced」という名称には重要な限定がある。著者の故障実験は、単一ビットの破損が広範囲の重みへ波及して異常を大きくする性質を示すが、実際の検知器、認証、復旧機構を実装して攻撃を防いだ実験ではない。むしろ監視なしではモデル品質を大幅に破壊し得る。圧縮率の改善、回路合成の見積り、セキュリティ実装の完成度は分けて読む必要がある。

## 問題設定と既存方式との差

一般的な重みのみの事後量子化では、各重みを低ビット値やコードブックのインデックスとして保存する。SeedLMは別の方法を採る。8重みからなるブロックを、短いシードから展開した擬似乱数行列と、少数の量子化係数の積として近似する。保存するのは重みそのものではなく、生成規則の初期状態と係数である。圧縮した重みを主記憶から読む量を減らせる反面、復号の計算と回路が必要になる。

SeedLMの基本構成は全ブロックへ同じシード長と係数数を用いる。S-Quantは再構成の難しさに応じて基底数を変えるが、その難しさは最終的な言語モデル損失への感度と一致しない。さらに可変長形式のブロックを読み出す際、各ブロックの形式を別途記録すると、圧縮によって得たビット節約を相殺する。Seed-Qは感度に基づく予算配分と、追加のブロック別形式メタデータを省くことを同時に目標とする。

目的は、平均ビット予算を守りながら、量子化誤差がモデルの出力へ与える損害を小さくすることにある。重み空間の二乗誤差が同じでも、入力活性が大きいチャネルや勾配の影響が強い行では、予測品質への悪影響が異なる。したがって、同じビット数を均等配分するより、重要度の高いブロックへ多くの表現能力を回す方が合理的な場合がある。

## 手法

### 1. シードから8重みを復元する符号化

重み行列を8要素のブロックへ分割し、各ブロックを `U(s) × t` で近似する。`s` はSビットのLFSR初期状態、`U(s)` はその状態から生成される8行k列の擬似乱数基底、`t` はk個の係数である。係数は共通指数と低ビット仮数で記録する。エンコーダは候補シードを探索し、再構成誤差が小さい組を選ぶ。ブロックの保存ビット数は `S + m×k + e`、重み1個当たりはその8分の1である。比較元SeedLMの4ビット構成はS=16、k=3、仮数m=4、指数e=4であり、合計32ビットを8重みで分ける。

Seed-Qでは `(S,k)` を「ラング」と呼び、S=8〜16、k=2〜6の候補からモデルに有用な組を選ぶ。ラングを変えれば再構成品質とビット数の組も変わる。通常の可変形式ならラングの番号を各ブロックに付ける必要があり、候補数によって約0.25〜0.375 bit/weightの追加負担となる。Seed-Qはこの負担を避けるため、エンコーダとデコーダが同じ規則でラングを計算できるようにする。

### 2. データ入力を使わないブロック重要度の近似

線形層 `y=Wx` では、列jの重み誤差の影響は入力二乗モーメント `E[x_j²]` によって重み付けされる。通常ならキャリブレーションデータから活性値を測るが、pre-norm Transformerの多くの投影はRMSNorm後のゲインγを掛けた入力を受け取るため、正規化ベクトルを等方的と近似すれば `E[x_j²]≈γ_j²` を保存済みチェックポイントから得られる。

残る出力投影とMLP下向き投影では、隣接する重みの二乗からモーメントを一段伝播させる。行方向の感度はロジット側から逆伝播した勾配二乗モーメントρで近似し、ブロック重要度を `平均入力モーメント×行感度` とする。入力チャネルを重要度に従って並べ替えて8個ずつまとめ、重要度の違いをブロック間へ集約する。テンソル間の感度スケールは伝播近似による人工的な深さ依存が強いため、テンソル内で平均1に正規化し、低重要度の極端な推定値には下限を設ける。

この「データ不要」は重要度の算出に実際のトークン入力を使わないという意味である。後段のラング別損失曲線はWikiText-2で実測しており、圧縮処理全体が評価用テキストから完全に独立しているわけではない。原著付録A.4でも、損失曲線を学習分割で測ると一部ブロックの割当が変わることを示している。ゼロキャリブレーションと無データ感度推定を混同してはいけない。

### 3. レート・歪み配分と凸包の閾値表

各ラングを全ブロックに適用したときのFP16からの損失増分を `e(g)`、必要ビット数を `r(g)` として測る。最適化の目的は、ブロック重要度 `imp_b` と損失増分の積の総和を小さくしつつ、平均ビット数を上限以下に保つことである。レート・損失点群の下側凸包を作り、隣接ラングの改善勾配を求めると、ラグランジュ乗数λに対して重要度が所定閾値を超えたブロックだけを高いラングへ上げるという階段状の割当になる。

乗数λを二分探索して予算へ合わせ、同じ重要度を持つブロックが閾値に並ぶ場合は決定的な順序で一部を降格させる。こうすればエンコーダとデコーダが同じ割当を再構成でき、各ブロックのラングを別途保存する必要がない。ただしこれは代理目的に対する配分の最適化であって、真の言語モデル損失を全ブロック同時に最適化した証明ではない。損失曲線の測定誤差や重要度近似がずれれば、実際の品質もずれる。

### 4. 極端な外れ値列とデコーダの共有情報

一部の重み列には、ブロック共通指数で表現できない極端に大きい値がある。大きな値を再構成すると、同じブロックの小さな重みへ誤差が漏れ、それが大きな入力活性によって増幅される。Seed-Qは重みの最大値対中央値比や活性スケールから候補を選び、各モデルの4列をFP16のまま保存する。LLaMA-2-7Bでは、ある単一の外れ値列が一様4ビットSeedLMの損失増分0.067のうち0.020を占めるという解析が示される。

デコーダにはRMSNormゲインに加え、一部投影の入力・出力感度の小さなテンソル別表、ラング凸包、λ、下限値、同点処理数、オフセット、外れ値列一覧などの共有情報が必要である。ブロックごとの形式ヘッダがないことは「一切のメタデータがない」という意味ではない。著者は共有表の負担を最大0.005 bit/weightと見積もるが、圧縮ストリームの境界を正しく解釈するため共有表の完全性が重要となる。

## 評価条件と主要結果

### 困惑度・圧縮率

WikiText-2の2048トークン文脈でLLaMA-2-7B/13B、LLaMA-3-8B、Mistral-7Bを比較した。SeedLMの4 bit/weightに相当する困惑度を少ないビットで得るMode 1と、同じ4 bit/weightで困惑度を改善するMode 2を区別する。原著Table 1の主要値は次の通り。

| モデル | SeedLM 4-bit PPL | Seed-Q Mode 1 (bit/PPL) | Seed-Q Mode 2 4-bit PPL |
|---|---:|---:|---:|
| LLaMA-2-7B | 5.85 | 3.77 / 5.85 | 5.68 |
| LLaMA-2-13B | 5.18 | 3.75 / 5.18 | 5.06 |
| LLaMA-3-8B | 7.17 | 3.88 / 7.17 | 6.92 |
| Mistral-7B | 6.32 | 3.78 / 6.32 | 5.96 |

Mode 1の約3〜6%の追加ビット削減は、FP16に対する削減率ではなくSeedLMの4 bit/weightに対する差である。Mode 2は同じ保存レートで損失を下げる構成であり、モード間の数字を混ぜて「4ビット未満でMode 2の困惑度」と解釈してはならない。原著の42%という改善はFP16に対する**超過困惑度の減少割合**であり、困惑度の絶対値が42%下がるという意味ではない。

### ゼロショット精度と負の結果

ARC-Easy、ARC-Challenge、HellaSwag、WinoGrande、BoolQの5タスク平均では、LLaMA-2-7BのFP16が68.74%、SeedLM 4-bitが66.87%、Seed-Q Mode 2が67.38%で、同じ4-bitの改善は0.51ポイントである。LLaMA-3-8BではSeedLM 70.23%に対してSeed-Q Mode 2が71.04%へ改善するが、AWQ 4-bitの71.51%には届かない。LLaMA-2-13BではSeedLM 70.47%に対しSeed-Q Mode 2は71.15%、AWQ 71.14%と近い。Mistral-7BはSeedLM 70.63%から71.73%へ改善した。

重要なのはMode 1が必ずしも同等精度ではない点である。LLaMA-3-8BのMode 1は3.88 bitで平均69.22%となり、SeedLM 4-bitの70.23%より約1.01ポイント低い。困惑度が同程度でも下流タスク精度を完全には維持できない。LLaMA-2-13BのMode 2はFP16 71.71%を下回る71.15%であり、圧縮が無損失という主張ではない。

### 回路合成・理論的転送削減

重み生成器をNangate 45nm標準セルへ論理合成し、Yosys/OpenSTAでセル面積、推定電力、レジスタ間経路遅延を比較した。SeedLMは2,891.7平方µm・0.211mW・1.671ns、Seed-Qは3,781.7平方µm・0.275mW・1.831nsであり、SeedLMに対して面積約30.8%、推定電力約30.5%増となる。一方、論文側で再実装したS-Quantの7,970.4平方µm・0.456mW・3.200nsよりは小さい。評価は16ビットシード、k=3、8重みブロックあたり561サイクルという共通条件である。

3.77 bit/weightの理想的な重み転送量はFP16比で約76.4%少なく、メモリ帯域律速の重み供給量は理論上約4.24倍となる。ただし、これは転送ビット数からの**理想換算**であり、LFSR復号、係数演算、メモリ配置、GPUカーネル、エンドツーエンドのトークン生成を含めた実測速度ではない。45nm合成の数値をGPUでの速度や実測消費電力と混同してはいけない。

### ビット故障の伝播と「セキュリティ」の条件

原著は符号化後・復号前に1ビットを反転させるソフトウェア故障試験を行った。Seed-Qの一部割当入力を壊すと後続ブロックの境界解釈が変わり、LLaMA-3-8Bのある投影で約1,677万重み、99.99%が変化する。比較用SeedLMは同試験で8重みの変化にとどまる。Seed-QのWikiText-2困惑度は6.89→108.11と激しく悪化し、ARC-Easyの100問試験では74%→57%へ低下した（原著Figure 3/4）。これらは障害の検知しやすさの可能性を示すが、サービスの可用性や耐攻撃性を証明する結果ではない。

しかもSeed-QとS-Quantは後続ブロックへの伝播をシミュレートしており、No-Q、AWQ、SeedLMの直接ビット反転とは故障位置・伝播の条件が完全には揃わない。原著自身、検出器と回復経路を実装・評価していないと明記している。改ざんを本当に検知するには、圧縮データだけでなくγやグローバル割当表も保護し、認証・照合・再読み込みを備える必要がある。故障で精度が大きく落ちること自体を「攻撃に強い」と評価するのは不適切である。

## 既存研究との差と適用判断

AWQやGPTQ系は重みを低ビットで直接保持するのに対し、SeedLM/Seed-Qは擬似乱数基底から重みを生成する。SeedLMの均等な符号化、S-Quantの再構成容易性に基づく可変符号化に対し、Seed-Qはモデル損失への感度を推定してビットを再配分する。また、可変長形式のブロック別ヘッダを持たず、復号器が共有情報から割当を決定的に再現することが圧縮率上の特徴である。

一方で実装は単純なINT4 GEMM置換ではない。シード探索・損失曲線計測というオフライン費用、生成器を組み込んだ重み供給回路、共有表の管理、異常な外れ値列のFP16保存が必要になる。論文の性能上の証拠は主にモデル品質と回路合成・転送量の理論値であり、一般的なGPU推論フレームワークでの処理量・TPOT・TTFTを示さない。既存のCUDA量子化方式へ即座に移植可能という保証はない。

## 限界と追加検証

第一に、ブロック感度は等方的RMSNorm入力や勾配伝播の近似に依存する。特に注意のQ/K投影の勾配はsoftmaxヤコビアンを経由するため、行方向の感度を十分に導出できず、著者は一部投影でρ=1としている。推定誤差が大きいと重要なブロックから予算を奪い、均等配分より悪化し得る。外れ値列を別保存するのもこの近似の限界への対処である。

第二に、ラングごとの損失曲線はWikiText-2で測定されている。本文が「data-free」と呼ぶ部分は重要度推定であり、配分の全工程をデータ不要と表現するのは不正確である。評価に用いた同じデータ集合から損失曲線を作る点については、分割を変えた再現試験や別分布での検証が必要である。

第三に、回路の面積・電力・遅延は標準セルの合成・推定値であり、物理設計後の配線、実チップ、DRAMからの実転送、GPUの実行速度ではない。圧縮率と実際の応答速度の交換条件は未測定である。第四に、故障を広範囲へ伝播させる設計は、認証と復旧を備えなければ障害を増幅する危険性もある。脅威モデルに基づく攻撃実験、偽陰性率、監視負荷、復旧時間が別途必要になる。
