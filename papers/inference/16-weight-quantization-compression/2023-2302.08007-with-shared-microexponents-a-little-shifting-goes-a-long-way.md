# With Shared Microexponents, A Little Shifting Goes a Long Way

## 概要

言語モデルの学習・推論を低精度化すると、数値を格納するビット数と積和演算器の面積を減らせる。しかし、ブロック内の全値に一つの尺度を共有させると、少数の外れ値に尺度が引きずられ、通常の値の分解能が下がる。反対に各値へ独立した指数を持たせる浮動小数点は、精度を保ちやすいが指数ビットと複雑な演算器が必要になる。

Rouhaniらは、ブロックデータ表現（Block Data Representation; BDR）という共通の設計枠を用意し、ブロックサイズ、尺度の階層、尺度を保存するビット数、各要素の仮数幅を変えて比較した。その探索から、16要素に共有する第一段の指数と、2要素ごとに共有する1ビットの微小指数を重ねるMX形式を提案する。代表的なMX9、MX6、MX4はそれぞれ平均9、6、4ビット/要素であり、微小指数を2のべき乗のシフトとして適用するため、単純な低精度演算器との両立を狙える。

論文はGPT-3 175Bのゼロショット・少数例推論、生成モデルの学習、翻訳・画像・音声・推薦モデルの品質と、専用ドット積回路の面積・メモリ効率を評価した。重要なのは、数値形式の精度と回路設計上の優位性を示した研究であり、既存のGPUでMX形式を有効化するだけで推論が何倍速くなると実測したものではない点である。

## 問題設定

単純な整数型の量子化では、ある値集合の最大絶対値に合わせて尺度を決め、各値を整数へ丸める。ブロックが大きいと、外れ値が一つ混じるだけで他の値の量子化誤差が大きくなる。ブロックを小さくすると外れ値の影響は局所化できるが、尺度を保存するための追加情報が増え、ソフトウェアで多数の小尺度を扱う負担も増える。ブロック浮動小数点は尺度を2のべき乗に限定し、回路内のシフトで扱うことでこの費用を減らす。

一方、8ビット浮動小数点は要素ごとに指数を持ち、動的範囲を柔軟に保つが、狭い形式では仮数の分解能が不足する場合がある。推薦モデルの埋め込み表や生成モデルの重み・活性・勾配では分布が異なり、同じビット幅でも量子化誤差が変わる。論文は「精度」「回路面積と記憶効率」「導入時の調整負担」という三つの軸を区別し、特定の量子化方式だけを良いものと決めつけずに設計空間を探索する。

## 手法

### 1. ブロックデータ表現による設計空間

BDRは、第一段のブロック幅 $k_1$、第二段の小集団幅 $k_2$、要素の仮数幅 $m$、第一段尺度のビット数 $d_1$、第二段尺度のビット数 $d_2$ を明示する。平均ビット数は、おおむね要素本体の $m+1$ ビットに、第一段の $d_1/k_1$ と第二段の $d_2/k_2$ を加えた値になる。共有する値を増やせば尺度の償却費用は下がるが、局所的な分布差を表現しにくくなる。尺度を高精度にすれば量子化誤差は減るが、保存量と演算器の複雑度が増える。

この表現により、整数量子化、ブロック浮動小数点、8ビット浮動小数点、ベクトル別尺度などを、尺度の共有範囲と数値形式の違いとして整理できる。論文は800以上の候補構成を探索し、数値忠実度と面積・メモリ費用の両方で他に劣らないパレート前線を求めた。これは単に同じ「4ビット」というラベルを付けた方式を比較するのではなく、尺度の追加情報も含めた実効ビット数を評価するための枠組みである。

### 2. 二階層の共有指数と微小指数

MXでは16要素の大きな集合に8ビットの共有指数を置き、その内部を2要素ずつに分けて1ビットの微小指数を共有する。第一段は大まかな範囲を表し、第二段は各2要素の相対的な尺度を補正する。第二段の倍率を2のべき乗へ限定すれば、通常の乗算器で任意の実数尺度を掛ける代わりに条件付きシフトで実装できる。小集団の外れ値が大ブロック全体の分解能を奪う影響を減らしつつ、要素ごとに独立した指数を置くより保存費用を抑える。

代表形式では、MX9が仮数7ビット、MX6が4ビット、MX4が2ビットであり、第一段・第二段のブロック構造は共通である。仮数幅だけを変えた複数の形式を同じ回路設計で扱いやすいことも選択理由となる。1ビットの微小指数を2ビットへ増やすと数値品質は改善するが、論文の探索では費用増加に見合う改善が小さい。小集団を2要素から1要素へ細かくしても、追加費用が大きくなるため2要素を採用した。

### 3. 回路とメモリの共同評価

数値品質には量子化信号対雑音比（Quantization Signal-to-Noise Ratio; QSNR）を用いる。元の値のエネルギーに対する量子化誤差のエネルギーを対数で表し、値が大きいほど元の数値をよく保存できる。論文は様々な分散の確率分布から多数のベクトルを生成し、候補形式のQSNRを比較する。さらに実際の言語モデルの損失との相関を確認し、統計指標だけが良くてもモデル品質が悪化する方式を見落とさないようにする。

回路費用は、長さ64の8ビット浮動小数点のドット積器を基準に、各候補の標準セル面積を合成して相対比較する。メモリ効率は256要素のタイルを64バイト幅のメモリ接続へ格納する際の詰め込み効率から求める。回路面積だけが小さくても、端数が多く帯域を無駄に使う形式は総合的に不利になる。逆に記憶量だけ小さくても、尺度演算の回路費用が高ければ利点が減る。論文のパレート前線は、この二つの費用を組み合わせた指標と数値品質から選ばれる。

### 4. 学習と推論の演算経路

学習では行列積や畳み込みなどの積和演算をMX形式で行い、正規化、ソフトマックス、活性化、残差加算などの要素演算は原則としてBF16やFP32を使う。MXは縮約方向に沿って量子化する方向依存の形式であるため、行列を転置してから量子化する場合と、量子化してから転置する場合は同じにならない。逆伝播で使う重みは順伝播用と別の向きで量子化する必要があり、実装の配置と一時記憶を考慮する。

推論では、高精度モデルを直接MXへ変換する方法と、変換後に短い量子化対応の追加調整を行う方法を比較する。MX9は直接変換でも多くのモデルで品質を保ちやすい一方、MX6やMX4はモデルやタスクによって追加調整が必要となる。重みと活性のビット幅を異ならせる組合せも評価し、狭い重みだけでなく活性も同時に狭くした場合の劣化を明示している。

## 評価

### 対象と条件

論文は20以上のモデルを対象とし、生成言語モデルは小規模GPTから175Bまで、さらに翻訳、BERT、画像分類、拡散生成、音声認識、推薦モデルを含む。既存GPU上では専用CUDAライブラリでMX形式の数値挙動を再現し、品質を測る。面積や電力に関する比較は専用回路の合成・推定であり、同じGPU上でMXがネイティブに動作した実測速度ではない。

| 観点 | 一次論文での条件 |
|---|---|
| 形式 | MX9、MX6、MX4。16要素の共有指数と2要素の微小指数 |
| 比較 | 整数量子化、ブロック浮動小数点、FP8など |
| 数値評価 | 量子化信号対雑音比、モデル損失、推論精度 |
| ハードウェア評価 | 合成ドット積器の面積、メモリ詰め込み効率 |
| 生成モデル | GPT系列6M～175B、混合専門家モデルも対象 |
| その他 | 翻訳、BERT、画像分類、拡散、音声、推薦モデル |

### 回路費用と数値品質

統計的な探索では、MX6はFP8と近いQSNRを持ちながら、面積とメモリ費用を組み合わせた指標が約半分となる設計点として選ばれる。MX9はFP8より高い数値忠実度を持つが、費用は比較的近い。MX4は費用を大きく下げる代わりに量子化誤差が増える。こうした比較は正規化された設計指標に基づくものであり、特定のGPUの消費電力が半分になるという直接の実測ではない。

第一段16要素、第二段2要素という選択には実験的な根拠がある。微小指数を1ビットから2ビットへ増やした場合、QSNRは約0.5dBしか改善せず、費用は約30～50%増える。第二段の共有範囲を8要素から2要素へ縮めると約2dB改善し、費用増加は約3%にとどまる。一方、2要素から1要素へ縮めると改善は約0.7dBで、費用は約30～40%増える。この非線形な交換条件から、1ビット・2要素という微小指数の設計が選ばれた。

### GPT-3 175B推論の実数値

| HellaSwag・ゼロショット | 精度 | 読み取り |
|---|---:|---|
| FP32 | 76.2% | 高精度基準 |
| 重みMX9・活性MX9 | 76.2% | 直接変換で基準と一致 |
| 重みMX6・活性MX9 | 76.0% | 重みを狭くしても小幅な差 |
| 重みMX6・活性MX6 | 75.8% | 両方を狭くした場合の差 |
| 重みMX4・活性MX9 | 74.5% | さらに狭い重みで品質が低下 |
| 重みMX4・活性MX4 | 61.3% | 極端な低精度では大きな品質劣化 |

この表は量子化対応の追加調整を行わず、既存のGPT-3 175Bを直接変換した条件である。低精度形式なら必ず品質が保たれるという主張ではなく、同じ4ビットでも活性の精度を維持するかどうかで結果が大きく異なることを示す。WinograndeやANLIなど別の課題では精度差の方向が変わることもあり、単一指標からすべての言語能力を代表させることはできない。

### 他のモデルと負の結果

翻訳のTransformer-BaseではFP32のBLEU 26.85に対してMX9の学習は26.51、直接変換したMX6推論は26.32、追加調整したMX6は26.81である。BERT-Baseの事前学習時のパープレキシティはFP32が4.58、MX9が4.62となる。推薦モデルDLRMのAUCはFP32が0.8028、MX9学習が0.8026であり、小さな差に収まる条件がある。

一方、条件付き拡散生成モデルの直接変換では、FP32のFID 7.60に対しMX9が7.81だが、MX6は26.62まで悪化する。MX6へ追加調整しても15.72で、元の品質へ戻らない。これは狭い数値形式の有効性がモデルと演算に依存し、追加調整で必ず回復するわけではないことを示す。学習結果についても論文は乱数種や実行環境による変動の範囲を意識しており、わずかな精度差を統計的に確定した優劣として扱わない。

## 限界と実装上の注意

回路合成の面積と正規化メモリ効率は、実際の製品の発熱、消費電力、推論トークン毎秒、モデル全体の処理率を直接測った値ではない。論文のGPU上の品質実験はMXの数値挙動を専用CUDAでエミュレーションしており、既存GPUでネイティブなMX積和器が使えることを示していない。形式の変換費用、レイアウト変更、追加尺度の保存・転送、カーネルの最適化が実装時の性能を左右する。

MXは縮約方向に依存するため、重みの転置や逆伝播の際に別の量子化表現が必要になる。MX4のように極端に狭い形式では生成・拡散など一部のモデルで品質が大きく下がる。専用回路の実装費用は他の形式との共用回路や装置の配線・タイミング条件にも依存し、論文の面積推定をそのまま別の製造工程へ移せない。したがってMXは、量子化形式と演算器の共同設計を検討する根拠であり、特定の既存GPU向け推論ライブラリを入れ替えるだけで得られる高速化結果ではない。

## 既存研究との差

単一の共有指数を使うブロック浮動小数点に対して、MXはその内部に2要素単位の微小指数を加える。各値が独立指数を持つFP8に対しては、指数情報を共有して費用を減らす。ソフトウェアで大きなブロックに尺度を付ける整数方式に対しては、専用演算器が尺度を細かく自動設定することで、ソフトウェアの細粒度尺度管理を避ける。BDRの枠組みはこれらの違いを尺度の階層と償却範囲で表し、精度・面積・帯域のパレート前線を選ぶための共通の物差しを提供する。
