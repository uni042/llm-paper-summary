# GRINQH：入力活性に応じて読出しビット数を変える階層量子化

## 書誌と対象

Jette Oberländer、Jan Finkbeiner、Catherine M. Schöfmann、Emre Neftciによる2026年6月22日公開のプレプリント（arXiv:2606.23419v1）。対象は自己回帰LLMの**重み読出し帯域**であり、KVキャッシュの量子化ではない。線形層の重みを一度量子化した後、生成するトークンごとに入力活性を見て、入力チャネル単位で重みの何ビットをGPUメモリから読むかを決める。提案名は入力依存の段階的量子化階層（Graded Input-based Quantization Hierarchy; GRINQH）である。

## 概要

長い入力をまとめて処理する事前処理（prefill）と、次トークンを1つずつ生成する復号（decode）は、GPU上での律速が異なる。前者は重みを一度ロードして多くのトークンへ再利用できるため計算律速になりやすい。後者、とりわけバッチ1では、大きな線形層の重みを毎トークン読み出すため帯域律速になりやすい。重みを一律に3ビットや4ビットへ量子化すると帯域は減るが、重要なチャネルの精度も同時に失われる。

GRINQHは入力活性の絶対値を重みチャネルの重要度の近似指標とし、活性の大きいチャネルへ高いビット数、活性の小さいチャネルへ低いビット数または0ビットを割り当てる。重みを2ビット単位の上位から下位へ重ねたビット平面で保存し、必要な上位平面だけを読み込む。上位ビットだけの切捨てに伴う系統誤差は中点補正で減らす。さらに事前処理は高精度、復号は動的精度という段階分離で、品質と帯域を両立させる。

Llama3とQwen3の複数サイズで、実効3〜4ビットの固定精度量子化方式より良好な精度を報告する。Qwen3-8BのRTX 4090上では、4ビットMARLINの最適化カーネルより約25%高速な、GSM8K品質とのパレート前線上の動作点を示す。一方、最大精度を使う事前処理のカーネルは最適化4ビット事前処理より約20%遅い条件があり、論文の最大28%の復号速度改善をそのまま全要求のエンドツーエンド速度と同一視してはいけない。

## 問題設定：チャネルごとの誤差感度と帯域

線形層の出力$y=Wx$では、入力チャネル$i$の寄与は$W_{:,i}x_i$である。入力活性$|x_i|$が大きければ、同じ重み量子化誤差$\Delta W_{:,i}$でも出力誤差$\Delta W_{:,i}x_i$が大きくなる可能性がある。逆に$|x_i|$が小さいチャネルは、重みを低精度で読んでも出力への影響が比較的小さい場合がある。GRINQHはこの関係を利用し、チャネルの固定重要度だけでなく、**今処理しているトークンの入力**によって精度を変える。

重みだけを量子化する一般的な方式では、同じ行列を毎トークン同じビット数で読み出す。復号時にメモリ帯域が飽和する場合、不要な下位ビットの読出しも待ち時間を増やす。GRINQHの狙いは、演算そのものをゼロにするだけではなく、DRAMからSRAMへ移動する重みビット数を減らすことにある。

ここで0ビットは、その入力チャネルに対応する重み寄与を省略する構造化疎化に相当する。2、4、6、8ビットは同じ最大精度表現の上位部分を選択的に読み出す。各チャネルを完全に独立した形式で保存するとアドレス計算とメモリアクセスが不規則になり、帯域節約が実際の速度に結びつかない。そこで重みの階層的な格納形式と専用GPUカーネルが必要になる。

## 手法

### 1. 入力活性による動的精度割当

各線形層へ入る活性$x_i$の大きさを見て、事前に校正したしきい値と比較し、チャネルごとの読出しビット数$b_i$を選ぶ。例えば最大6ビット構成では$b_i\in\{0,2,4,6\}$であり、活性が小さい場合は0または2ビット、大きい場合は4または6ビットとする。最大8ビット構成では8ビットまでの階層を使える。精度を高くするほど量子化誤差が減るが、読み出す重みビット数が増える。

ビット数を割り当てる粒度は、線形層の**入力チャネル単位**である。トークンごとの入力活性が変われば、同じ重み行列でもどのチャネルに高い精度を割り当てるかが変わる。重要度を固定した混合精度量子化と異なり、要求・トークンの文脈で重要チャネルを変えられることが特徴である。ただし入力活性の大きさは誤差感度の近似であり、出力誤差や最終正答率の完全な予測器ではない。

### 2. 校正集合から精度分布としきい値を決定

校正にはThe Pile（Uncopyrighted）から128例、各2048トークンを使う。目標の平均実効ビット数$b^*$を設定し、各ビット階層へ割り当てるチャネルの割合$p_i$を調整する。割合の和は1で、目標平均ビット数は概念上$\sum_i p_i b_i$に対応する。入力活性の分布からしきい値を校正し、各階層へ入るチャネル数が所望の比率となるようにする。

著者らは校正時のパープレキシティを探索用の代理指標として用いる。付録の推奨手順では、目標ビット数と許容誤差（例0.05）を決め、単体制約を満たす割合ベクトルを約15件生成し、校正パープレキシティで候補を比較する。実効2〜3ビットの厳しい領域では20%以上の疎化を使って節約したビット予算を重要チャネルへ再配分することが有効だが、実効3.7〜4.3ビットでは疎化を20%より大きくしすぎると必要な重み情報を失って品質が下がる。

この違いは、同じ疎化率をあらゆるビット予算に適用してはいけないことを示す。特に低ビット領域では、少数の重要チャネルを高精度で守るために、重要度の低いチャネルを0ビットにする余地が必要となる。一方4ビット前後では予算が比較的潤沢なので、無理にチャネルを削除するより広い範囲を残す方が良い。

### 3. 2ビット平面による階層的な重み保存

最大$b_{max}$ビットの量子化重みを、2ビットずつの平面に分解する。最大6ビットなら上位2ビット、中位2ビット、下位2ビットの3平面を持つ。各入力チャネルの重みは出力チャネル方向へ連続配置され、同じチャネルの上位平面をGPUがまとまって読み込める。復号時にチャネル$i$へ$b_i=2$が割り当てられれば上位2ビットだけ、$b_i=4$なら上位4ビットまで、$b_i=6$なら全平面を読む。

専用のTritonカーネルは、入力活性に基づいて選ばれた平面をDRAMから取得し、GPU上の近いメモリで重みを復元して行列・ベクトル積を計算する。固定4ビット行列をそのまま読む方式と異なり、読出し量が入力トークンごとに変わる。単にPython上でチャネルごとのビット数を選ぶだけでは、実際のDRAM転送量を減らせない。格納形式とカーネルが共同で設計されていることが性能上の核心である。

### 4. 切捨てによる偏りを中点補正で打ち消す

上位ビットだけを残す切捨ては、下位ビットをゼロにするため、元の量子化区間の下端へ重みを寄せる。これが層を重ねて累積すると、低ビットでも単なるランダムな誤差以上に表現が崩れる。GRINQHは元の量子化スケール$s$、ゼロ点$z$、残すビット数$b$、最大ビット数$b_{max}$に対し、復元重みを

$$\hat w=s\left(q_b 2^{b_{max}-b}+\phi\right)+z,\quad \phi=2^{b_{max}-b-1}$$

とする。$q_b$は上位$b$ビットから構成した整数で、$\phi$は切り捨てられた範囲の中点へ戻す補正である。例えば最大8ビットから上位4ビットだけ読む場合、欠けた下位4ビットを全ゼロとして扱うのではなく、中点相当の補正を加える。

この補正を省くと、論文の実験ではGSM8K正答率が0%となり、WikiText-2のパープレキシティが$10^8$を超える場合があった。これは些細な精度改善ではなく、階層的切捨て量子化を機能させるための必須処理である。なお、ルックアップ表を使う非一様な入れ子型重み表現では各階層が元から中心化されているため、同じ補正は不要と記載される。

### 5. 事前処理と復号を分ける精度戦略

事前処理は多くの入力トークンを一括処理するため、動的な低ビット読出しを適用しても、演算効率や文脈表現の精度を損なう可能性がある。GRINQHはこの段階では最大精度$b_{max}$を固定で使い、復号段階に限って入力活性に応じた低ビット読出しを適用する構成を評価する。これにより、初期文脈の隠れ状態を高精度で形成しつつ、後続トークンで毎回ロードする重み量を削減できる。

この段階分離は同じ重み表現を使いながら読出し精度だけを切り替えるので、異なる精度の重みをモデル全体で別々に保存する方式とは異なる。ただし最大精度の事前処理カーネルは、最適化された固定4ビットカーネルより遅い場合がある。入力長と生成長の比率が変わると、全体の速度利得も変わる。

## 評価

### 評価条件

| 項目 | 条件 |
|---|---|
| モデル | Llama3系1B/3B/8B Instruct、Qwen3系0.6B/1.7B/4B/8B |
| 量子化基準 | RTN、GPTQ、AWQ、QuaRot+GPTQ、AutoRound、NVFP4、AnyPrecisionLLM、SliM-LLM |
| 最大ビット数 | $b_{max}=4,6,8$、実効ビット数は約2〜8を探索 |
| 校正 | The Pile（Uncopyrighted）128例、各2048トークン |
| 量子化群サイズ | 原則128。NVFP4は16、AnyPrecisionLLMはチャネル単位 |
| 品質 | WikiText-2・LAMBADAパープレキシティ、GSM8K・ARC-C・HellaSwag・BoolQ・MMLU等の正答率 |
| 品質評価実装 | PyTorch参照シミュレーションで大きなバッチも使用 |
| 速度評価実装 | 専用Tritonカーネル。事前処理と復号を分けて計測 |
| GPU | RTX 4090、RTX 5070、RTX PRO 6000を含むNVIDIA GPU |
| 主対象 | バッチ1でメモリ帯域が律速となる自己回帰復号 |

品質表の実効ビット数は、すべての重みを固定でそのビット幅に量子化したことを意味しない。0ビットを含むチャネル間の配分を平均した値である。固定ビット量子化との比較では、この違いを明記しないと同じ3ビットモデル同士の単純比較と誤解される。

### 主要結果

### 1. 同程度の4ビット予算での品質

| モデル・方式 | 実効ビット | WikiText-2 PPL（低いほど良い） | GSM8K正答率（%） | 6課題平均正答率（%） |
|---|---:|---:|---:|---:|
| Llama-3.1-8B BF16 | 16 | 8.64 | 85.14 | 74.35 |
| Llama-3.1-8B GPTQ | 4 | 9.41 | 80.82 | 72.85 |
| Llama-3.1-8B RTN | 4 | 9.67 | 79.83 | 71.44 |
| Llama-3.1-8B GRINQH-8b-RTN | 4.01 | 8.97 | 85.14 | 74.34 |
| Qwen3-8B BF16 | 16 | 12.20 | 88.32 | 74.02 |
| Qwen3-8B GPTQ | 4 | 12.68 | 82.79 | 72.18 |
| Qwen3-8B GRINQH-8b-AnyP | 3.95 | 12.23 | 87.72 | 73.91 |

Llama-3.1-8BのGRINQH-8b-RTNは平均4.01ビットで、GSM8KがBF16と同じ85.14%、6課題平均も74.34%でBF16の74.35%に近い。これは「4ビット固定RTN」の79.83%、71.44%と異なる。最大8ビットまで重要チャネルを守り、平均ビット予算を約4に抑えたことが効いていると解釈できる。

### 2. 実効3ビット付近の比較

| モデル・方式 | 実効ビット | WikiText-2 PPL | GSM8K正答率（%） | 平均正答率（%） |
|---|---:|---:|---:|---:|
| Llama-3.1-8B GPTQ | 3 | 12.46 | 60.35 | 63.27 |
| Llama-3.1-8B RTN | 3 | 19.13 | 6.60 | 50.64 |
| Llama-3.1-8B GRINQH-8b-AnyP | 2.96 | 9.22 | 84.23 | 73.69 |
| Qwen3-8B GPTQ | 3 | 14.89 | 67.78 | 64.67 |
| Qwen3-8B RTN | 3 | 22.84 | 15.54 | 44.79 |
| Qwen3-8B GRINQH-8b-AnyP | 3.06 | 12.40 | 87.41 | 73.74 |

Qwen3-8Bでは3ビットGPTQのGSM8K 67.78%に対し、GRINQHの実効3.06ビットで87.41%となる。低ビットでも重要チャネルの精度を確保できるため、固定ビット量子化に見られる大きな性能低下を抑える。ただし最大8ビットの階層を保持して必要な平面を読む方式なので、保存時の形式・実装コストが単純な固定3ビット形式と同じとは限らない。

### 3. 2ビット台の厳しい領域

Qwen3-8BのGRINQH-8b-AnyPは実効2.22ビットで、WikiText-2 PPL 12.95、GSM8K 87.04%、平均73.27%を報告する。対して同表の2ビットAnyPrecisionLLMはWikiText-2 PPL 109.87、GSM8K 0.61%、平均33.80%である。平均ビット数だけでは品質を決められず、重要チャネルへのビット配分と疎化率が大きな差を生む。

### 4. GPUカーネルと全体速度

RTX 4090のQwen3-8Bで、GRINQHは4ビットMARLIN比較で約25%高速なGSM8K品質・ベクトル行列積時間の動作点を報告する。RTX 5070、RTX 4090、RTX PRO 6000の単独カーネル評価では、各GPUで最良の4ビットMARLINを基準に正規化し、その基準の実測時間は順に0.072、0.057、0.034ミリ秒である。ビット幅を2〜8の間で変えても、動的平面読出しの費用は実効ビット数に概ね比例し、固定幅の最適化カーネルと競合できる。

一方、全モデルでの事前処理は最大ビット精度の密な処理を行い、最適化された固定4ビット事前処理より約20%遅い条件がある。復号段階の改善は最大28%と報告されるが、要求全体の生成時間には事前処理も入る。短い応答や長い入力では事前処理費用の比重が増すため、復号単独の改善率をそのまま全体の高速化率として用いない。

### 5. 補正・校正・疎化の感度

中点補正を外すとGSM8K正答率0%、WikiText-2 PPLが$10^8$超となる条件があり、ビット平面の切捨てを単純に使うだけでは深層モデルが崩れる。校正しきい値は異なるモデル・課題で狙った平均実効ビット数に近い値を達成し、入力活性の大きさを使う割当の実装可能性を裏付ける。

実効2〜3ビットでは20%以上の疎化でビット予算を再配分することが重要だが、実効3.7〜4.3ビットでは疎化しすぎると品質が悪化する。最適な割合ベクトルはモデルと目標ビット数で変わるため、論文の代表値をそのまま別モデルへ適用するのではなく、対象モデルの校正データで再探索する必要がある。

## 既存研究との差

GPTQやAWQは重みの量子化誤差を小さくすることに重点を置き、推論時には選ばれた固定ビット形式を読む。AnyPrecisionLLMやSliM-LLMは複数精度を扱うが、GRINQHは**入力活性を観測してチャネルごとの読出し精度をトークンごとに変える**点が異なる。さらに単なる精度配分ではなく、2ビット平面を使う階層的保存形式、GPU上の復元カーネル、中点補正、事前処理と復号の分離を一体化する。

低ビット化の主目的は復号の重み読出し帯域削減であり、モデルの注意KVキャッシュや出力トークンの保存量を直接減らすものではない。バッチ数が大きい場合には同じ重みを複数トークンで再利用できるため、動的精度選択の追加処理が相対的に高くなる可能性がある。

## 限界と実装判断

第一に、入力活性の大きさは重要度の代理指標である。量子化誤差が最終タスクの正答率へどう影響するかを完全には予測しない。校正集合が実運用の入力分布を代表しない場合、しきい値と実効ビット数、品質の対応が変わる。文書長や領域の違う要求を混在させる運用では、校正集合の再選択が必要になる。

第二に、最大精度の階層的重み表現を保持し、必要な平面だけを読み込むため、単純な固定2ビット・3ビット形式と同じ保存・ロード・カーネル互換性ではない。一般的な量子化ファイルをそのまま差し替えて実現できるものではなく、Tritonの平面読出しと復元に相当するランタイム機能が必要となる。

第三に、論文が最大の帯域利得を得るのはバッチ1の復号段階である。事前処理は高精度のため遅くなる場合があり、同時要求数が増えて行列・行列積へ移行すると、単一トークンのベクトル行列積の結果を一般化できない。GPU世代、メモリ帯域、演算器、カーネル融合の違いも影響する。

第四に、2ビット台の好結果は最大8ビットまでの階層と入力依存の疎化を含む構成の結果である。固定2ビット形式でも同等品質を得られるという主張ではない。導入時には実効ビット数、常駐重み容量、事前処理時間、復号時間、実タスク品質を分けて測定することが適切である。
