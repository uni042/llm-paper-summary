# OliVe: Accelerating Large Language Models via Hardware-friendly Outlier-Victim Pair Quantization

> 外れ値を別の疎データ構造へ逃がすのではなく、隣接する低重要度の通常値を「犠牲値（victim）」として使い、外れ値を同じ固定幅ペアの中へ埋め込む。これにより外れ値対応量子化で問題になる座標リストと別演算経路をなくし、4ビットの整列アクセスをテンソルコアやシストリック配列へ直接載せる。

## 概要

OliVeは、**外れ値対応量子化（outlier-aware quantization）をハードウェアで効率よく実行するためのアルゴリズム・アーキテクチャ協調設計**である。Transformerでは0.1%未満の少数外れ値が精度へ大きく効くため、単純な4ビット整数量子化では外れ値がクリップされて品質が崩れる。既存方式は外れ値だけ高精度で別保存し、通常値を低ビットの密行列として扱うが、外れ値座標リスト、疎な読出し、通常経路との合流制御が必要になる。

OliVeの観察は、外れ値そのものは重要だが、**外れ値に隣接する通常値は平均的には重要度が低い**というものだった。2値を隣接ペアとして見ると、BERT-baseでは99.12%が通常-通常、0.84%が外れ値-通常、0.04%だけが外れ値-外れ値で、OPT-6.7Bでも99.33% / 0.64% / 0.03%である。つまり大半の外れ値には「隣に捨てられる通常値」がある。

そこで外れ値-通常ペアでは通常値を犠牲にし、その4ビット領域を外れ値の追加表現へ使う**外れ値・犠牲値ペア（Outlier-Victim Pair; OVP）符号化**を採る。通常-通常ペアとOVPは同じ固定長・同じメモリアラインメントで保存され、デコーダがペア内の識別子だけを見て局所的に外れ値を復元する。外れ値専用の疎な座標リストをDRAMから別途読む必要がない。

論文は4ビット学習後量子化（post-training quantization; PTQ）の品質だけでなく、OVPデコーダをGPUテンソルコア型データパスとシストリック配列型アクセラレータへ組み込んだシステム評価まで行う。RTX 2080 Ti相当GPUシミュレーションでは、GOBO比で平均4.5倍の性能、4.0倍のエネルギー削減を報告する。一方、この値は実RTX 2080 Ti実機測定ではなく、GPGPU-Sim/AccelSimと電力モデルによる評価である点を分けて読む必要がある。

## 問題設定：外れ値を「別保存」すると低ビットの利点が消える

通常の一様INT4では表現範囲が狭く、巨大な外れ値に範囲を合わせると通常値の量子化間隔が粗くなり、外れ値をクリップするとその少数値だけでモデル品質が大きく落ちる。したがって既存の外れ値対応方式は、外れ値を8/16ビット等で残し、低ビット通常値から分離して保存する。

この方式は数値精度には有効だが、ハードウェア上では**密な通常値行列 + 疎な外れ値行列**という二経路になる。たとえばGOBOのような方式は外れ値の座標情報を保持し、通常値演算と高精度外れ値演算を別々に処理して最後に統合する必要がある。外れ値自体が少数でも、座標デコード・ランダムアクセス・オーケストレーションが低ビット化の帯域・演算利得を削る。

OliVeは「外れ値をどこへ置くか」を変える。外れ値に隣接する通常値の一部を失っても品質劣化が小さいなら、その物理スロットを外れ値表現へ転用できる。そうすればペア全体のビット幅とアドレス規則は通常値だけの場合と同じままで、外れ値処理をローカルなデコーダへ閉じ込められる。

## 手法

### 1. 隣接2値を3種類のペアに分類する

テンソルを隣接2値ごとに見て、量子化しきれない閾値 (T) を超える値を外れ値とする。ペアは通常-通常、外れ値-通常、外れ値-外れ値の3種類になる。

- 通常-通常: 両方を通常の低ビット形式で量子化する。
- 外れ値-通常: 外れ値を保持し、通常値を犠牲値として捨てる。
- 外れ値-外れ値: より大きい外れ値を保持し、もう一方を捨てる。

外れ値-外れ値が非常に少ないことが重要である。閾値を下げすぎるとOVP数は増えて通常量子化誤差を減らせるが、外れ値-外れ値も増え、重要な外れ値を捨てる危険が高まる。OliVeは平均二乗誤差（mean squared error; MSE）最小化にOVPを組み込み、この交換条件から閾値を自動決定する。

### 2. 犠牲値の符号領域を「外れ値識別子」に転用する

4ビット符号付き整数を例にすると、通常は (-8) から (7) を表せる。OliVeではビット列1000を (-8) として使わず、**OVP識別子**に予約する。通常値側の範囲は (-7)〜(7) へ少し狭まる。

左側が外れ値なら、左4ビットに外れ値の量子化コード、右4ビットに識別子を置く。右側が外れ値なら逆にする。したがって8ビット単位のペアを読めば、その場で「通常-通常」か「左/右どちらが外れ値か」を判別でき、外部の座標リストが不要になる。

この符号化は論文がいう**「大域的には同一、局所的には識別可能（globally identical but locally distinguishable）」**という性質を持つ。DRAM・キャッシュから見ると常に同じ幅・同じ整列のデータ列であり、PE直前の小さなデコーダだけが形式を分ける。

### 3. 外れ値専用の数値形式で残ったビットを有効利用する

犠牲値の領域を使えるとはいえ、外れ値には通常値より広いダイナミックレンジが必要である。OliVeは外れ値向けに**適応バイアス浮動小数点（adaptive bias float; abfloat）**を設計し、通常値の低ビット形式と表現範囲が重複しすぎないよう指数バイアスを調整する。

通常値側はINT4、flint4、INT8など複数形式を使える。OVPという配置規則と、通常値/外れ値それぞれの数値形式を分離することで、「外れ値を高精度にしたい」というアルゴリズム上の要求を、固定幅の演算データへ落とす。

### 4. デコーダをテンソルコア・シストリック配列の直前へ置く

GPU側では各低ビット演算データパスの前へOVPデコーダを追加し、識別子を検出して通常値または外れ値形式を復元する。外れ値形式用に加算器とシフタを加えるが、別の疎行列演算器や全体オーケストレータは不要である。

論文の面積見積もりでは、RTX 2080 Ti相当12nmへスケールした4ビットデコーダ群は1.88 mm²、GPUダイ面積の0.250%、8ビットデコーダ群は1.25 mm²、0.166%である。シストリック配列型アクセラレータでは22nm RTL合成で4/8ビットデコーダを統合し、低ビットPEへローカル復号を追加する。

OPT-6.7Bでは4ビットOliVeにも大きな劣化が残るため、「4ビットで元精度を完全維持」と一般化するのは不正確である。一方、単純INT4や4-bit ANTは同条件で桁違いに崩壊し、8-bit OliVeはFP32へほぼ一致する。OliVeの価値は、外れ値保護を固定幅データパスへ載せたときの品質・実装効率の両立にある。

### GPUシミュレーションの性能・エネルギー

| 比較対象 | 平均性能改善 | 平均エネルギー削減 |
| --- | ---: | ---: |
| GOBO | 4.5× | 4.0× |
| INT8 | 2.7× | 2.3× |
| ANT | 2.4× | 2.0× |

GOBOは外れ値を保持して品質を守れる一方、重みのみ低ビット化して演算はFP16、さらにDRAM上の外れ値組織化が必要なため、モデルが大きくなるほどOliVeとの差が広がる。OliVeは重み・活性値を低ビットで処理し、外れ値も整列データ内に埋め込むため、帯域削減を演算側まで維持できる。

専用アクセラレータ評価ではOliVeはAdaFloat比4.8×、OLAccel比3.8×、ANT比3.7×の平均速度改善を報告し、エネルギーはそれぞれ3.7×、2.1×、3.3×削減する。論文要旨の「GOBO比4.5× / 4.0×」はGPU統合評価の値で、専用アクセラレータ比較とは基準が異なる。

## 既存研究との差

GOBOなどの方式は外れ値と通常値を別々に保存・演算する。OliVeは「外れ値を高精度で残す」点は共通だが、**物理配置を別経路へ分けない**。OVP識別子をペア内部へ埋め込み、通常値と外れ値のデータを同じアラインメントでストリーミングできることが主な差である。

Outlier Suppressionのように外れ値自体を小さくする方式とは異なり、OliVeは重要な外れ値を保持する。その代わり隣接する低重要度値を失う。つまり誤差の置き場所を「重要な大値」から「重要度の低い近傍値」へ移す設計である。

ANTのような適応データ型とも近いが、外れ値への対応が弱いと4ビットPTQで多くの層をINT8へ戻す必要があり、性能・エネルギー利得が縮む。OliVeはOVPによって低ビットを維持できる層を増やす。

## 限界・実装上の注意

OVPは犠牲値を**実際に削除する近似**であり、完全無損失ではない。隣接値が低重要度であるという統計に依存し、外れ値-外れ値ペアが増える閾値設定では重要外れ値も捨てるため誤差が急増する。このため閾値探索が必要になる。

4ビット品質はモデルにより差が大きい。OPT-6.7BではWikiText2 55.44、C4 32.41まで悪化しており、8ビットOliVeの22.34/10.73とは隔たりがある。低ビット化の可否はモデルごとに確認すべきである。

システム評価は詳細なGPU/アクセラレータシミュレーションとRTL合成に基づくが、GPU性能値は実機RTX 2080 Ti上の直接測定ではない。現在のHopper/Blackwell世代、現行Tensor Core命令、現代のLLMサービング基盤で同じ倍率になるとは限らない。
