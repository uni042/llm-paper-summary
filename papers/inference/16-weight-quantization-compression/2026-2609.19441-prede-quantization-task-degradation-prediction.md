# Predict Before You Deploy: Offline Prediction of Quantization-Induced Task Degradation for World Action Models

> 固定ログ上の行動偏差を少数の閉ループ結果で方策別に較正し、量子化候補を受理・棄却・保留へ分けて実機試験を絞るPreDE。

## 概要

世界行動モデル（World Action Model; WAM）は、動画生成系の大きなバックボーンを用いるため、ロボット上での配備ではメモリ量と推論時間が問題になる。後学習量子化はこの負担を下げられるが、ビット幅、グループ化、量子化器などの組合せが多く、しかも「低ビットなら必ず悪化する」「重み誤差が小さければタスク成功率も保たれる」とは限らない。候補ごとに実ロボットで閉ループ試験を行えば確実だが、そのコスト自体が量子化探索の律速になる。

PreDE（Predict Before You Deploy）は、量子化候補を固定観測ログで走らせたときの**行動出力のずれ**を、少数の閉ループ評価済み候補で方策ごとに較正する。新しい候補は、このオフライン偏差だけから「受理」「棄却」「保留」に分けられる。重要なのは、曖昧な候補を無理に二値判定しない点である。開発候補のラベルと整合する全ての閾値が同じ結論を出す領域だけを自動判定し、境界付近は実際の閉ループ試験へ回す。

論文では5種類のWAM、4つのベンチマーク設定を調べ、量子化によるタスク損失はビット幅だけでも、全方策共通の単一偏差閾値でも説明できないことを示す。2方策の28個の未見量子化構成に対し、PreDEは21件、すなわち75%を閉ループ結果を見る前に判定し、判定した21件は観測された「許容／劣化」ラベルと全て一致した。実ロボットでは450試行を行い、高偏差群では有意な性能劣化、低偏差群では有意な劣化を観測しなかった。さらにW4A4量子化は実機上で行動問い合わせを1.37倍高速化し、ピークメモリを約44%削減した。

## 問題設定

WAMの量子化では、圧縮率だけで候補を選べない。例えば同じ4ビットでも、重みのみか重み・活性値の双方を量子化するか、どの単位でスケールを共有するか、どの量子化器を使うかで、生成された行動列のずれ方が変わる。ロボット制御では小さな出力誤差が時間とともに蓄積し、環境状態を変え、その後の観測まで変えるため、静的な再構成誤差と閉ループ成功率の関係は単純ではない。

一方、候補を全て実機評価すると、試行時間、安全管理、ロボット占有時間のコストが大きい。PreDEが解こうとするのは量子化アルゴリズムそのものではなく、**どの量子化構成なら高価な閉ループ試験を省略でき、どの候補だけは実試験へ残すべきか**という配備前の選別問題である。

## 手法

### 1. 固定観測ログ上で行動偏差を測る

まず基準となる非量子化方策と各量子化候補に、同じ固定観測ログを入力する。ここでは量子化候補自身に環境を動かさせないため、候補間で入力系列を揃えたまま、基準方策と量子化方策が出す行動の差を比較できる。

この「オフライン行動偏差」は、重み空間の量子化誤差ではなく、実際に制御へ渡される出力がどれだけ変わったかを見る指標である。ただし閉ループでは、ある時点の行動差が次の観測状態を変えるため、固定ログだけで成功率を完全に予測できるとは仮定していない。そこでPreDEは偏差を連続値の回帰問題として直接成功率へ写像せず、後段で保守的な三値判定に使う。

### 2. 少数の閉ループ結果で方策固有の境界を較正する

少数の量子化構成だけは実際に閉ループ評価し、タスク性能が許容範囲にある候補と明確に劣化した候補を開発集合として持つ。PreDEは、このラベルとオフライン偏差の順序関係を使って、許容側と劣化側の境界を較正する。

ここで重要なのは、論文が全WAMへ共通の「偏差X以下なら安全」という閾値を置かないことである。実験では、同程度のオフライン偏差でも方策・設定によって閉ループ影響が異なり、ビット幅だけでも劣化を説明できなかった。そのため判定は**方策ごと**に較正される。

### 3. 閾値に関する不確実性を残したまま受理・棄却・保留する

開発ラベルと矛盾しない閾値は一つとは限らない。PreDEは単一の推定閾値を無理に選ぶのではなく、開発集合と整合する閾値の集合を考える。新候補について、その集合に属する全ての閾値が「許容」と判定するなら受理、全てが「劣化」と判定するなら棄却する。

閾値によって判定が割れる候補は**保留**され、閉ループ試験へ送られる。この設計により、自動判定のカバレッジを100%へ押し上げる代わりに誤判定を増やすことを避ける。実際、保留候補の中には許容できたものだけでなく、33パーセントポイントのタスク損失を示した候補も含まれており、境界領域を実試験へ残す意味が確認できる。

### 4. 配備判断としての使い方

実運用では、量子化候補を大量に生成した後、まず全候補を同じ観測ログで評価する。少数の候補にだけ閉ループ予算を使ってPreDEを較正し、残りを受理・棄却・保留へ分ける。受理候補についてはメモリ削減や実測速度などの配備上の利得を比較し、保留候補だけ追加試験する。

したがってPreDEの削減対象は推論時の演算そのものではなく、**量子化構成探索に必要な閉ループ評価回数**である。量子化による実行時の高速化・メモリ削減と、PreDEによる評価コスト削減は別の効果として読む必要がある。

## 評価

### 代表的な評価条件

| 項目 | 内容 |
|---|---|
| 対象 | 5種類の世界行動モデル、4つのベンチマーク設定 |
| 判定評価 | 2つの独立に微調整された方策から28個の未見量子化構成 |
| 実ロボット | Franka Research 3、2方策、合計450試行 |
| 量子化の実行時評価 | 実ロボット上のW4A4構成 |
| 比較するもの | オフライン行動偏差による事前判定と、後から観測した閉ループの許容／劣化ラベル |

### 代表的な結果

| 観点 | 結果 | 読み取り |
|---|---:|---|
| 未見候補の自動判定 | 28件中21件 | 閉ループ試験前に75%を受理または棄却できた |
| 判定済み候補の整合 | 21件すべて観測ラベルと一致 | 自動判定できた領域では誤った許容／劣化ラベルを出さなかった |
| 保留領域 | 許容候補と33ポイント損失の候補を含む | 曖昧領域を強制判定しない設計が必要 |
| Franka実験 | 高偏差群は全て有意な劣化、低偏差比較は有意な劣化なし | オフライン偏差の大小が閉ループ劣化のスクリーニングに使える |
| W4A4速度 | 1.37倍 | 量子化候補を選ぶ実用上の動機 |
| W4A4ピークメモリ | 約44%削減 | 速度だけでなく配備メモリも削減 |

特に「21/28を判定できた」ことと「21件の判定が全て観測ラベルと一致した」ことは分けて読む必要がある。前者はカバレッジ、後者は判定した範囲での整合性であり、PreDEが全候補を事前に正しく分類したことを意味しない。残り7件は、まさに論文が閉ループ評価を残すべきだと判断した領域である。

## 既存研究との差

一般的な量子化探索は、モデル誤差、校正データ上の損失、ビット幅などを使って候補を比較することが多い。PreDEはWAMの最終的な目的が閉ループ制御である点を重視し、**固定ログで観測できる行動出力の偏差を、実際の閉ループ成否ラベルへ少数例で較正する**。

また、単一の代理指標へ成功率を連続的に当てはめて全候補をランキングするのではなく、不確実な領域を「保留」として明示する。実ロボット評価を完全に置換する方式ではなく、実験予算を「判定が難しい候補」に集中させる方式である。

## 限界

PreDEの判定は、同一設定内でオフライン偏差と劣化ラベルの順序が一定方向に並ぶという仮定に依存する。論文自身が示すように、方策間で共通の偏差閾値を使えるわけではないため、新しい方策や大きく異なる環境では少数の閉ループ較正をやり直す必要がある。

また、低偏差群で「統計的に有意な劣化がなかった」ことは、厳密な非劣性を証明したこととは同義ではない。PreDEが保留した候補についても閉ループ試験は必要であり、75%というカバレッジは今回の2方策・28候補で得られた値として扱うべきである。

## まとめ

PreDEは、量子化候補を実ロボットへ全部持ち込む前に、固定ログ上の**行動偏差**を使って閉ループ試験の必要性を絞る。方策固有の少数の閉ループ結果から許容側・劣化側の境界を較正し、確信できる候補だけ受理・棄却、境界付近は保留することで、量子化探索を安全側に保ったまま評価コストを削減する。
