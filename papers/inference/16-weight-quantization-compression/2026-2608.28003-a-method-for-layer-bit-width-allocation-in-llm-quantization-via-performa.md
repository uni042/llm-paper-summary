# A Method for Layer Bit-Width Allocation in LLM Quantization via Performance Maximization Under a Quality-Degradation Constraint

> 品質劣化の予算の下で速度を最大化する層ビット配分として、感度プロファイルに基づきGemma-3-1Bの全結合・注意・語彙射影をブロック単位でW8A8化し、RTX 5090実測で全結合と語彙射影は速くなり短文脈の注意は遅くなることと、品質保持下で11.0%の遅延削減を示す研究。

## 概要

量子化は、重みと活性値を16ビット浮動小数点から8ビット整数などへ落とすことで、メモリ使用量を減らし、整数演算で計算を速くする手法である。GPTQやAWQのような代表的な学習後量子化は全層へ同じビット幅を一様に適用するが、層ごとに量子化への感度は大きく違うため、鈍い層では圧縮の余地を残し、敏感な層では品質を損なう。層ごとにビット幅を変える混合精度にすればこの無駄は減るはずだが、精度の違うブロックの境界では活性値を量子化し直し、逆量子化する追加の処理が入り、その費用が整数演算の利得を上回れば、かえって遅くなる。先行する混合精度の研究は、この境界費用を実測してサブシステムごとに損益を示すところまで踏み込んでいなかった。

本論文はこの問題を、生成品質の劣化予算を制約として、生成速度を目的関数にする配分問題として定式化する。対象は約2ギガバイトでコンシューマ向けGPUに載る小型モデルGemma-3-1Bであり、メモリ節約ではなく計算効率そのものが狙いである。著者の先行研究SA-PTQで得た層感度プロファイル、すなわち層ごとに量子化前後の出力の信号対量子化雑音比を測った地図を手がかりに、全結合ネットワーク（FFN）、注意機構、語彙への射影であるlm_headの三つのサブシステムを、量子化する層の範囲で分けたブロック単位にW8A8化し、TensorRT-LLMの活性値パススルーで実行する。RTX 5090上で13構成を実測した結果、全結合とlm_headでは変換費用が整数演算の利得に相殺される一方、短い文脈では注意機構へ量子化を足すと遅くなるという、サブシステムで正反対の結論が得られた。

**代表結果:** 品質を保つ構成の中で最良なのは、全結合の外側10層だけを量子化する5+5構成にlm_head量子化を組み合わせたもので、FP16の比較対象380.53トークン毎秒に対して422.14トークン毎秒、すなわち1.110倍で遅延は11.0%減り、品質はトップ1一致率98.90%、パープレキシティの悪化は0.85%増にとどまる。全結合の全26層とlm_headを量子化すれば453.27トークン毎秒で1.191倍、遅延19.1%減まで伸びるが、生成文が同じトークンの繰り返しへ崩れる劣化が伴う。

## 問題設定

バッチサイズ1の自己回帰生成では、デコードの各ステップで活性値ベクトルは1行だけであり、行列と行列の積ではなく行列とベクトルの積になる。そのため計算は重み行列全体をメモリから読み出す作業に支配されるメモリ律速の状態にあり、重みを低ビット化すれば読み出す量が減って速くなる余地がある。ただし量子化したブロックと元の精度のブロックが混在すると、その境界ごとに活性値の量子化と逆量子化が挿入され、読み出し削減の利得から差し引かれる。したがって混合精度の成否は、サブシステムごとに「整数演算と帯域削減の利得が変換費用を上回るか」で決まる。

プロファイリングがこの構図を具体化する。デコード1トークンあたりの時間では、語彙数262144への射影であるlm_headが376.58マイクロ秒と突出して大きく、重みは576メガバイトに及ぶ。全結合ではゲートとアップ射影の融合カーネルが22.01マイクロ秒、下向き射影が13.03マイクロ秒であり、層内では全結合が主役である。一方で注意のクエリ・キー・値射影は3.88マイクロ秒、出力射影は3.04マイクロ秒と小さく、注意カーネル本体は11.65マイクロ秒かかるが帯域使用率は低い。つまり全結合とlm_headは帯域律速で量子化の利得が見込め、注意は射影行列自体が小さく、融合済みカーネルの周囲へ変換処理を足す費用が勝ちやすい構造にある。既存の一様量子化はこの差を区別せず、混合精度の先行研究はこの損益を層やサブシステム単位で実測していない。本論文の着眼点は、感度で層を選び、損益をサブシステムごとに実測して、品質予算の中で速度が最大になる配分だけを残すことにある。

## 手法のあらまし

処理の流れはオフラインの配分決定と、実行時の混合精度推論に分かれる。まず先行研究SA-PTQの感度プロファイルを読む。感度は、FP16の重みで計算した層出力とINT8化した重みで計算した層出力を比べた信号対量子化雑音比で表され、値が高い層ほど量子化に強い。全結合については、外側の層ほどこの値が高く中央の層に外れ値が多いという観測に基づき、量子化範囲を外側から広げる三段階のグループ、すなわち最初と最後の5層ずつの5+5、10層ずつの10+10、全26層のall26を用意する。次に選ばれたブロックへSmoothQuantによるキャリブレーション付きのW8A8量子化を適用し、TensorRT-LLMでエンジンを構築する。lm_headについては公式のエクスポート経路が埋め込み共有の都合で機能しないため、平滑化係数を手作業で計算してチェックポイントへ埋め込む専用の実装を使う。最後に全結合、注意、lm_headの組み合わせ13構成を同じ実測手順で比べ、品質が予算内に収まる中で最速の構成を配分の答えとする。

## 手法

### 1. SA-PTQ感度プロファイルによるブロック単位の配分 — 強い層から外側へ広げる

この機構が観測するのは、各層の重みをINT8化したときに層出力がどれだけ歪むかであり、信号対量子化雑音比として数値化する。保持する状態は26層分の感度プロファイルであり、全結合では外側の層0から4と21から25で値が高く外れ値が少なく、中央の層10から15でゲート射影の外れ値が増えるという形をしている。選択するものは量子化する層の集合であり、感度の高い外側から範囲を広げる5+5、10+10、all26の三段階に離散化する。重みと活性値の量子化自体は対称なチャネル単位の方式で、出力チャネルごとに重み行の最大絶対値から量子化ステップを決める。これにより減るボトルネックは、敏感な中央層をFP16のまま残すことで量子化誤差の蓄積を抑えつつ、鈍い層の重み読み出し量と計算を削ることである。追加で消費する資源は感度測定のための事前の順伝播と、精度境界での変換処理である。誤った場合の挙動は評価で裏付けられており、量子化していない中央層が前段の誤差を部分的に補償する補償器として働くため、5+5では活性値の信号対量子化雑音比が最小でも9デシベルに保たれるのに対し、全層量子化では中央層で4から7デシベルまで落ちる。つまり配分を広げるほど速度は上がるが、補償役がいなくなる分だけ品質の余裕は細る。

### 2. TensorRT-LLMの活性値パススルーによる混合精度実行 — 変換費用を隠さず実測する

この機構が観測するのは、精度の異なるブロックの境界で発生する量子化と逆量子化の実時間である。保持する状態は、コンパイル時にQuantConfigで固定されたブロックごとのデータ型であり、実行時に動的に変えることはしない。処理は、量子化対象のブロック内では重みと活性値をINT8で流し、境界で必要な変換を挟みながら、対象外のブロックはFP16のまま計算することである。全結合ではこの方式でINT8同士の行列積カーネルが選ばれ、量子化層が増えるほど高速化が伸びることが確認された。これにより減るボトルネックは、帯域律速な全結合とlm_headにおける重み読み出しと浮動小数点演算である。追加で消費する資源は境界の変換カーネルそのものであり、本論文はこれを一般論で消さず、サブシステムごとに損益を測り分ける。資源不足や条件変化時の挙動として重要なのはハードウェア依存性であり、Blackwell世代のRTX 5090では全層で速いINT8同士のカーネルが選ばれるのに対し、Ampere世代のRTX 3070では量子化層を増やすと遅いINT8とFP32の混合カーネルへ切り替わり、最適な配分が5+5へ戻る。同じ配分でもカーネル選択方針が変われば損益が逆転し得ることが示されている。

### 3. 注意機構へのW8A8適用とその否定的結果 — 融合カーネルの外側では利得が出ない

この機構が観測するのは、注意のクエリ、キー、値、出力の四つの線形射影を量子化したときの速度と品質である。保持する状態は全26層の注意射影に対する量子化集合であり、キャリブレーションはSmoothQuantで、活性値のチャネルごとの最大値と重みの最大値から平滑化係数を決め、量子化の難しさを活性値側から重み側へ移す。ソフトマックスと回転位置埋め込み、KVキャッシュは量子化対象外でFP16のままである。処理としては射影の行列積だけがINT8カーネルで速くなるはずだが、実測では全結合all26の414.98トークン毎秒に対して注意も量子化すると407.28トークン毎秒へ7.7トークン毎秒下がった。理由はプロファイリングで特定されており、注意本体の融合カーネルは量子化してもFP16のまま実行され、速くなるのは小さな射影の行列積だけであり、Gemma-3-1Bはクエリヘッド4に対してKVヘッド1のグループ化クエリ注意で射影行列がもともと小さいため、利得が境界の変換費用に届かない。品質の面では注意量子化を足しても生成品質は許容範囲に収まっており、数値精度の余裕はあるのに実行方式が利得へ変換できていない、という分離が本論文の重要な発見である。誤った場合の扱いとして、著者は融合型のINT8注意カーネル、KVキャッシュ量子化、FP8への移行、注意への部分適用を今後の方向として挙げるが、本論文の範囲では未実装であり、現行の配分では注意はFP16に残すのが答えになる。

### 4. lm_headの手作業SmoothQuant実装 — 公式経路の不具合を迂回して最大の単一カーネルを量子化する

この機構が観測するのは、語彙射影の入力活性値に含まれる外れ値チャネルと、埋め込み表と共有された重み行列の分布である。背景として、lm_headの重みは入力埋め込みと共有されており、公式のModelOptからTensorRT-LLMへのエクスポートでは、スケールだけが書かれて重み本体がFP16のまま残る偽の量子化になる不具合が報告され、修正がないまま課題が閉じられている。保持する状態は、キャリブレーション集合の順伝播で集めた活性値統計から計算するチャネルごとの平滑化係数であり、係数は0.5のバランス係数で活性値の最大値と重みの最大値から決める。処理は、活性値を係数で割り、重みに係数を掛けることで積そのものを変えずに両側のダイナミックレンジを均し、活性値はトークンごとに動的に、重みは行ごとに静的に量子化して、INT8の行列積の後に両側のスケールの積で逆量子化することである。プラグインの出力チャネル上限65536に対して語彙数が262144であるため、重みを4つの行ブロックへ分けて別々に呼び出し、語彙軸で連結する。これにより減るボトルネックは、デコードで最大の単一処理であるlm_headの重み読み出しであり、単独でも1.071倍の高速化が得られる。追加で消費する資源は、トークンごとの動的なスケール計算と4分割の呼び出しである。誤った場合の挙動は明確で、平滑化を省いて直接量子化すると、重みと活性値のスケールが合わず生成が機能しなくなることが、純粋な数値実験と実エンジンの両方で確認されている。また、エクスポート時にはモデル種別を正しく指定しないとGemma-3固有の正規化の重みが失われ、キャリブレーション方式を明示しないと平滑化係数のテンソル自体が生成されないという、実装上の落とし穴も併せて記録されている。

## 評価

結論は三つに分かれる。第一に、全結合の量子化は範囲を広げるほど単調に速くなり、5+5で1.031倍、10+10で1.075倍、全26層では表によって1.090倍から1.10倍と報告され、品質は5+5でのみ良好で、それ以上では劣化側に倒れる。第二に、lm_headの量子化は単独で1.071倍と全結合5+5より大きな利得を持ちながら品質は優秀な側に分類され、全結合5+5との併用で1.110倍が品質保持下の最良解になる。第三に、注意の量子化はどの範囲でも全結合だけの構成を下回り、5+5では1.023倍対1.031倍、10+10では1.054倍対1.075倍、全層では1.069倍対1.090倍と一貫して足を引っ張る。つまり速度の絶対値だけを見れば全結合全層とlm_headの併用が1.191倍で最大だが、生成文が繰り返しへ崩れる劣化構成であり、品質予算という制約を課した瞬間に最適解は5+5とlm_headの併用へ移る。これが、問題を制約付き最大化として定式化したことの実質的な意味である。

この読み方には条件の限定が伴う。すべての実測はバッチサイズ1、短い文脈、RTX 5090という一点の条件であり、著者自身が注意の否定的結果は文脈長に依存すると述べている。実際、バッチサイズ4の予備実験では全体で約1.16倍の高速化が見られたこと、FP8化した全結合では1.46倍が見られたことが今後の方向として記されており、注意の損益もバッチや文脈長が変われば逆転し得る。逆に言えば、本論文の数値はコンシューマ向けGPUでの低バッチ生成という、対象モデルが想定する利用形態に絞った実測であり、その範囲では配分の結論は13構成の同一手順での比較に支えられている。品質評価は信号対量子化雑音比、トップ1一致率、パープレキシティ、生成文の目視的な崩壊判定の組み合わせであり、広範なタスクベンチマークでの正解率評価は未評価である。メモリ使用量の削減や消費電力、複数リクエストのサービング負荷、他モデルへの一般化も論文では未評価であり、高速化は重み読み出し削減からの推定ではなく実測のトークン毎秒で示されている点が強みである一方、適用範囲はこのモデルとこの実行基盤に限られる。

## 既存研究との差

GPTQとAWQとの差は、ビット幅を全層一様にするのではなく、感度に基づいて層の集合を選び、速度を目的関数に据えた点にある。両者は主にメモリ削減と品質保持を狙い、計算グラフ上の変換費用を最適化対象にしていない。特徴量単位で混合精度にするMixLLMと、量子化と疎化の基盤であるTorchAOとの差は、高速化の証拠の出し方であり、本論文はサブシステムごとに実測の損益を示し、注意のように利得が出ない部位を否定的結果として切り分ける。著者の先行研究SA-PTQとの関係では、感度指標そのものは先行研究の成果であり、本論文はそれを配分の入力として実システムへ接続し、品質予算の下での最適構成を実測で決めた点が新しい。SmoothQuantはキャリブレーションの部品として使い、lm_headでは公式経路の不具合を迂回する手作業実装まで含めて初めて有効化した点も実装上の差である。

## 限界・実装状況

限界は、対象がGemma-3-1BとRTX 5090を中心とする単一の組み合わせに限られ、カーネル選択の違いで最適配分が変わることがRTX 3070の観測からも示唆されること、評価がバッチサイズ1と短い文脈に限られ長い文脈でのKVキャッシュ誤差や注意の損益が未評価であること、品質評価がタスクベンチマークではなく信号対量子化雑音比と一致率と生成観察に寄っていること、配分の粒度が三段階のブロックとサブシステムの組み合わせに限られ層単位の最適配分そのものは解いていないことである。実装状況は、TensorRT-LLM 1.2.1とModelOptによる再現手順と、lm_headの手作業SmoothQuantの数式と分割方法が詳述される一方、公式コードの公開先は論文中に示されておらず、lm_head量子化の公式修正も未提供のままである。量子化は近似であり、範囲を広げた構成では生成が繰り返しへ崩れる品質リスクが実測で確認されている。

## 一般的な実装上の含意

混合精度の判断は、ビット幅の理論上の削減率ではなく、サブシステムごとの実測損益で決めるべきである。特に、既に融合カーネルで最適化された処理の外側へ量子化と逆量子化を被せる方式は、数値精度に余裕があっても速くならないことがあり、精度の余裕と実行の利得は分けて測る必要がある。逆に、デコードで支配的な単一の大きな行列積は、共有重みのような特殊事情で公式経路が使えなくても、手作業の平滑化で量子化できれば大きな利得になる。感度に基づく部分適用では、量子化しない層が誤差の補償器として働くため、範囲の設計は速度と品質の単調な交換ではなく配置の問題として扱うのがよい。
