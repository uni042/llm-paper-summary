# LLM-FP4: 4-Bit Floating-Point Quantized Transformers

> 4ビット浮動小数点（floating point; FP）の指数部構成とクリップ範囲を層ごとに探索し、活性値の大きなチャネル間分散はチャネル別指数バイアスを重みへ事前吸収して処理する。LLaMA-13Bの埋め込み・重み・活性値を4/4/4ビットにして、6つの常識推論タスク平均63.1を維持する。

## 概要

LLM-FP4は、重みだけでなく活性値まで4ビットへ落とす学習後量子化（post-training quantization; PTQ）を、整数ではなく低ビット浮動小数点で実現する研究である。低ビット整数は表現範囲と分解能の配分が固定されるため、Transformerで頻出する裾の長い分布やチャネルごとのスケール差に弱い。一方、浮動小数点は指数部を使って広い動的範囲を表せるが、4ビットになると「指数部に何ビット割くか」と「どこでクリップするか」の選択を誤るだけで精度が崩壊する。

提案法は二段からなる。第一に、各層の全精度出力と量子化出力の二乗誤差を基準として、指数部ビット数を含む**浮動小数点形式（floating-point format）**と最大値・クリップ範囲を同時探索する。第二に、活性値のチャネル間分散が大きい問題に対し、チャネルごとの指数シフトを求め、そのシフトを推論時に活性値へ掛け続けるのではなく重み側へ再パラメータ化して事前計算する**事前シフト指数バイアス（pre-shifted exponent bias）**を導入する。

LLaMA-13Bでは、埋め込み/重み/活性値をすべて4ビットにする4/4/4条件で平均63.1を達成し、全精度68.9との差を5.8点に抑える。SmoothQuantの16/4/4は50.4、単純な4ビット浮動小数点MinMaxは36.7であり、単にFP4形式を使うだけでは不足し、形式・範囲探索とチャネル分散処理が必要だと分かる。

## 背景：FP4なら自動的に強いわけではない

浮動小数点表現は符号、指数、仮数からなる。同じ4ビットでも指数部を増やせば広い値域を表せる代わりに仮数が減って細かな値を表せず、指数部を減らせばその逆になる。したがって、E2M1のような形式が全層・全テンソルで最適とは限らない。さらに、有限ビット表現では最大値をどこに置くかによって、外側を切り捨てるクリップ誤差と、内側の丸め誤差の交換条件が変わる。

論文は、量子化対応学習（quantization-aware training; QAT）で用いられた勾配による形式・最大値最適化をそのままPTQへ持ち込むと過学習し、単純MinMaxより悪くなる場合があると報告する。そこで少量の較正データに対して離散的な候補を探索し、各層の出力再構成誤差で直接選ぶ。

もう一つの難所が活性値である。Transformerの活性値は同一チャネル内の分散に比べて、チャネル間の最大値差が大きい。テンソル全体で1つの尺度を使うと、一部の大きなチャネルに範囲を合わせるため小さなチャネルの実効精度が失われる。しかしチャネル別尺度をそのまま活性値へ適用すると、行列積の縮約方向で尺度が異なり、通常の「行列積の外へ1つの尺度を出す」実装ができなくなる。

## 手法

### 1. 浮動小数点形式と最大値の同時探索

各線形演算の全精度出力を (O)、量子化後の出力を (hat O) とし、(|hat O-O|^2) を最小にする量子化設定を探索する。qビットFPで指数部が0ビットになる形式を除き、取り得る指数/仮数配分を候補にする。各形式ごとにクリップ範囲も変化させ、形式と最大値の組を層ごとに選ぶ。

入力は較正データで観測した重み・活性値と全精度層出力で、出力は各対象テンソルのFP形式、尺度、クリップ範囲である。重みはチャネル単位、活性値はテンソル単位を基本とする。これだけでも8ビット・6ビットでは強い基準法になるが、4ビット活性値ではチャネル間分散が大きすぎて性能が落ちるため、次の指数バイアス処理を加える。

### 2. チャネル別指数シフトを重みへ吸収する

理想的には活性値の各チャネルに別々の尺度を持たせれば、チャネルごとの値域へFP4を合わせられる。しかし実行時に各縮約要素へ異なる尺度を掛けると低ビット行列積が複雑になる。

LLM-FP4はチャネル別尺度を2の整数乗に近い形へ分解し、**整数のチャネル別指数バイアス**と**テンソル全体の実数尺度**へ分ける。チャネル別指数バイアスは較正時に求め、対応する重みの行へ逆向きの指数シフトとして吸収する。すると活性値側は推論時にテンソル共通尺度で処理でき、重みはシフト済み低ビットFP値として事前保存できる。

したがって推論時の入力は通常の量子化活性値と事前変換済み重みであり、追加のチャネル別乗算を毎回行う必要がない。チャネル分散を均す効果を保持したまま、低ビットFP行列積へ戻せることがこの機構の要点である。

### 3. 量子化対象と実行フロー

LLaMAでは全結合層の重みと活性値を量子化する。埋め込み（embedding）もビット幅Eとして表中で評価され、4/4/4では埋め込み・重み・活性値がすべて4ビットである。較正データを通して各層の形式・範囲と指数バイアスを決定し、チャネル別シフトを重みへ吸収してから低ビット重みを保存する。

実際の推論では探索処理を行わない。形式選択、クリップ範囲、重みへの指数バイアス吸収はオフライン較正時の一回限りであり、実行時には決定済み形式の低ビットFP値で行列積を行う。したがって動的な入力依存制御ではなく、**較正で分布に合わせた静的な数値形式を作るPTQ**である。

## 評価

### 評価条件

|項目|条件|
|---|---|
|LLM|LLaMA-7B、LLaMA-13B|
|較正データ|C4からランダム32区間、各2048トークン|
|量子化粒度|活性値はテンソル単位、重みはチャネル単位|
|主な比較|MinMax INT/FP、SmoothQuant、GPTQ、LLM-QAT、FPQ baseline|
|LLMタスク|BoolQ、PIQA、HellaSwag、WinoGrande、ARC-Easy、ARC-Challenge|
|評価実装|EleutherAI evaluation harness|
|ハードウェア評価|Verilog HDLで算術器を記述し、Cadence Genus、TSMC 40nm、0.5GHzで合成面積を比較|
|実GPU速度|論文の中心評価では未報告。主に精度と演算器面積を評価|

### LLaMA-13Bの代表結果

|設定|平均精度↑|全精度との差|意味|
|---|---:|---:|---|
|全精度 16/16/16|68.9|—|基準|
|MinMax INT 4/4/4|38.5|−30.4|単純INT4では大幅崩壊|
|MinMax FP 4/4/4|36.7|−32.2|FP4をそのまま使うだけでも崩壊|
|SmoothQuant 16/4/4|50.4|−18.5|活性4ビットが依然難しい|
|FPQ baseline 4/4/4|44.5|−24.4|形式・範囲探索だけでは不足|
|FPQ 4/4/4|63.1|−5.8|指数バイアス処理まで入れると大幅回復|

4/4/8ではLLaMA-13BのFPQが67.5で、全精度68.9との差は1.4点まで縮む。したがって最大の難所は4ビット重みそのものより、4ビット活性値まで同時に押し下げる部分にある。

### 構成要素と較正感度

BERTでの較正数実験では、4/4/4条件で32点だけでもMNLI-M 81.5、QQP 89.4、CoLA 44.4を得るが、128点では82.3、89.2、52.6となり、特にCoLAで較正数の影響が見える。一方、128から256へ増やしても一様に改善するわけではない。探索範囲 ((gamma_1,gamma_2)) も複数設定で結果が近く、極端でない範囲なら比較的頑健と報告される。

### 演算器面積

|形式|加算器 µm²|乗算器 µm²|MAC µm²|
|---|---:|---:|---:|
|INT4|93|182|410|
|E2M1 FP4|111|92|443|
|E2M1×E1M2 混合FP4|105|107|432|
|INT6|132|340|529|
|E3M2 FP6|223|138|498|

FP4はINT4より加算器がやや大きい一方、乗算器は小さく、MAC全体では443対410 µm²と同程度である。チャネル別指数処理も重みへ事前吸収するため、論文が提案する混合FP4 MACは432 µm²で、標準FP4と近い。ただしこれは40nm合成結果であり、H100等の実GPU上でのエンドツーエンド速度測定ではない。

## 既存研究との差

SmoothQuantは活性値外れ値を重み側へ移す再パラメータ化でINT8/低ビット量子化を助ける。LLM-FP4も「活性値の難しさを重み側へ押し込む」点は似るが、対象は浮動小数点の指数表現であり、チャネル別の指数バイアスを重みへ事前吸収する。

GPTQは重み量子化誤差の再構成に強いが、活性値4ビットまで同時に扱うことが主目的ではない。LLM-FP4は数値形式・クリップ範囲の探索と活性チャネル分散への対処を組み合わせ、E/W/A=4/4/4という条件を狙う。

またFP8がハードウェアで普及しつつある背景を利用し、「低ビット=整数」という前提を外してFP4を選ぶ。論文の合成評価ではFP4 MAC面積はINT4と同程度であり、低ビットFP演算器が極端に高価とは限らないことを示す。

## 限界・実装上の注意

本論文のハードウェア評価は演算器の合成面積であり、実際のGPU/アクセラレータ上のメモリ帯域、カーネル実装、スループット、消費電力を直接測ったものではない。したがって63.1という品質結果から「FP4推論がINT4より速い」とは結論できない。

また著者ら自身が、極長系列やストリーミングデータでの一般化は未検証とする。較正はC4の32×2048トークンを基本とし、入力分布が大きく異なる場合の形式選択の安定性は別途確認が必要である。

FP4の指数/仮数形式や混合形式を効率よく実行するには対応するハードウェアまたはカーネルが必要である。論文は回路面積上の可能性を示すが、既存サービング基盤へそのまま投入できることを保証するものではない。
