# IntactKV: Improving Large Language Model Quantization by Keeping Pivot Tokens Intact

## 概要

IntactKVは、低ビット量子化した大規模言語モデル（LLM）において、**入力の最初に置かれる少数の支点トークン（pivot tokens）の鍵・値キャッシュ（KV cache）だけを高精度モデルから生成して保存する**方式である。量子化誤差が特定チャネルに現れることは知られていたが、著者らは入力の先頭にある文頭記号や句読点のようなトークンに非常に大きい活性値が生じ、注意の大部分がそこへ集中する現象に注目した。この支点トークンのKVが量子化でずれると、以後のすべてのトークンが参照する注意の基準がずれ、出力品質へ波及する。

提案法は、通常の量子化済みモデルの重みや演算器を変更せず、先頭のKVだけ高精度のものへ差し替える。LLaMA-7BをINT3・グループ128で重み専用量子化したC4評価では、単純丸め（RTN）のパープレキシティ9.15がIntactKV併用で8.52へ、AWQでは8.26が8.12へ改善する。ただし高精度モデルの7.36へ完全には戻らない。追加で固定システムプロンプトのKVを学習可能パラメータとして較正する派生法も示し、Vicunaの対話品質を改善する。論文中には効果が小さい条件や、特定タスクで悪化する条件もあるため、全方式・全指標で単調改善すると理解してはならない。

## 問題設定：チャネル外れ値と支点トークン外れ値は異なる

通常の活性値外れ値は、複数トークンにわたり同じ特徴チャネルが大きい値を取るものとして議論される。SmoothQuantやAWQなどは、そのようなチャネルの尺度や重みへの影響を制御する。これに対し著者が図1で観測した外れ値は、特定の**先頭トークン位置**で局所的に極端な値が出るもので、LLaMA-30BやLLaMA-2-7Bでは文頭記号[BOS]に加え、先頭付近の句読点にも顕著なピークが現れる。値の大きさが千を超える例も示され、通常の外れ値チャネルより大きいことがある。

こうした位置は注意の吸い込み先（attention sink）となる。注意ヘッドが内容のある後続トークンだけでなく、先頭の特殊トークンに大きい確率を割り当てるため、これらのKVの誤差は広範囲の生成位置へ伝播し得る。論文は、量子化後の注意層・Transformer層の出力と高精度出力との平均二乗誤差（MSE）を比較し、支点トークンを保護するだけで誤差が大きく下がることを確認する。単に最も大きい活性値を持つチャネルを例外扱いする方式とは、保護する対象と配置の単位が異なる。

KVキャッシュ全体を高精度に保てば誤差は減るが、長い系列でメモリを大量に消費する。IntactKVは少数の先頭位置だけを保護し、その他のKVやモデル重みは既存の量子化経路を維持する。重要なのは保護するトークンが**固定された先頭接頭辞**である点であり、任意の途中位置の支点だけを高精度化すれば同じ結果になるとは限らない。

## 手法

### 1. 高精度モデルで固定先頭列のKVを事前生成する

最初に、元の高精度モデルへ[BOS]または固定システムプロンプトを入力し、各Transformer層で得られる鍵・値テンソルを生成して保存する。これは通常の生成時に作られるKVキャッシュと同じ形の状態であり、モデル重みとは別に少量のデータとして持てる。量子化済みモデルは実行時にこのIntactKVをキャッシュの先頭へ配置し、残りのトークンについては通常どおり量子化済み重みで事前充填・復号する。注意計算から見ると、先頭トークンのKVだけ高精度由来の状態になっている。

この方式では、**先頭から連続したトークン列**を選ばなければならない。例えば文頭記号の次に離れた位置の句読点が重要だと分かっても、その位置だけのKVを独立に事前計算して途中へ挿入することはできない。途中位置の隠れ状態はそれ以前のトークンに依存するためである。事前学習済みの通常モデルには[BOS]だけを保持する1トークン版を、固定のシステムプロンプトを先頭に付ける教師あり調整モデルにはそのプロンプト全体を保持する版を提案する。Vicuna-v1.5-7Bのシステムプロンプトは34トークンで、IntactKVの追加保存量は論文の表現でモデルパラメータ量の約0.13%に相当する。

高精度モデルはこの固定列のKVを作る際だけ必要であり、保存後の推論では量子化済みモデルとIntactKVだけを使用できる。固定先頭列を共有できる複数要求であれば、毎回高精度モデルを呼ぶ必要がない。著者は推論時の追加遅延がないと説明するが、これは元々必要なKV参照を差し替えるという設計上の主張であり、あらゆる推論エンジンでコピー・形式変換・転送がゼロになる保証ではない。実装がキャッシュをどの形式で保持するかは別途確認する必要がある。

### 2. 支点KVを軽量に較正する

保存した高精度KVは、量子化によって後続トークンのKVや重みが変わったことまでは補償しない。そこで著者は固定接頭辞のKVそのものを学習可能パラメータ `Θ` として扱う。高精度モデルと量子化済みモデルへ同じ入力を与え、各Transformer層の出力の二乗誤差を合計した損失を最小化する。損失は概念的に `L(Θ)=1/2 Σ_l ||f_l(w,x)-f_l(ŵ,x;Θ)||²` と書ける。ここで高精度の重み `w` と量子化重み `ŵ` は固定し、更新するのはIntactKVだけである。

較正データにはShareGPT由来の128会話例を用い、AdamWで160回の更新、勾配蓄積16、合計20エポックの設定が示される。7Bモデルの較正は一つの計算装置で約10分、13Bでは20分未満と報告される。これはモデル全体の再学習と比較すれば小さいが、較正時には高精度モデルを参照する必要があり、キャッシュだけで任意の未知モデルを学習できるわけではない。著者は[BOS]だけの較正より、システムプロンプト全体を較正する方が改善余地が大きいと観測する。

### 3. 誤差上界による説明

著者の定理1は、注意ヘッド出力の変化 `Δh` を、鍵キャッシュの誤差 `ΔK` と値キャッシュの誤差 `ΔV` のノルムで上から抑える。概念的には `||Δh|| ≤ C1 ||ΔK||_{2,∞} ||ΔV||_F + C2 ||ΔK||_{2,∞} + C3 ||ΔV||_F` であり、係数にはクエリのノルム、出力投影行列、系列長、ヘッド次元が入る。支点位置のKVを高精度に保てば、その位置について `ΔK_p=0`、`ΔV_p=0` とでき、全体誤差の上界を小さくする方向に働く。

この議論は支点KVを保護すると注意出力誤差を抑えやすいことの理論的根拠である。ただし上界が小さくなることと、任意のベンチマーク正答率が必ず上がることは同値ではない。注意の吸い込み先が実際にどれだけ重要か、他のトークンの誤差がどれだけ残るか、対象モデルの量子化方式によって実効改善は変わる。

## 評価

### モデル・量子化・課題

| 項目 | 原著の具体条件 |
|---|---|
| 事前学習モデル | LLaMA 7B/13B/30B/65B、LLaMA-2 7B/13B/70B。付録でLLaMA-3やOPTも検討 |
| 教師あり調整モデル | Vicuna v1.3の7B/13B/33B、v1.5の7B/13B |
| 重み量子化 | RTN、GPTQ、OmniQuant、AWQ。主に非対称INT3/INT4、グループ128 |
| 重み量子化の較正 | GPTQはC4、AWQはPile、OmniQuantはWikiText2。各原著の実装に従う |
| 生成評価 | C4とWikiText2のパープレキシティ。低いほど良い |
| 能力評価 | MMLUの0/5例提示、7種の常識QA、MT-Benchの80件の多段対話 |
| 対話品質判定 | MT-Benchの回答をGPT-4で10点満点評価 |
| IntactKV較正 | ShareGPT 128例、160更新、20エポック、学習率2×10^-4 |

IntactKVは量子化アルゴリズムそのものを置き換えないため、同じ量子化方式に対して「通常」と「先頭KV保護」を比較するのが基本である。ベンチマークによって[BOS]だけを保護する版と、固定システムプロンプトを保護する版を使い分ける。MMLUや常識QAではシステムプロンプトがないため[BOS]版を使い、MT-Benchではプロンプト版を使う。この違いを無視して改善率を一括りにしない。

### 3ビット重み量子化の言語生成

| モデル・C4 PPL | FP16 | 量子化のみ | IntactKV併用 | 差 |
|---|---:|---:|---:|---:|
| LLaMA-7B / RTN INT3 | 7.36 | 9.15 | **8.52** | -0.63 |
| LLaMA-7B / GPTQ INT3 | 7.36 | 8.59 | **8.30** | -0.29 |
| LLaMA-7B / AWQ INT3 | 7.36 | 8.26 | **8.12** | -0.14 |
| LLaMA-2-7B / AWQ INT3 | 7.28 | 8.31 | **8.18** | -0.13 |
| LLaMA-2-70B / RTN INT3 | 5.73 | 6.27 | **6.13** | -0.14 |
| LLaMA-2-70B / OmniQuant INT3 | 5.73 | 6.12 | **6.11** | -0.01 |

表1では幅広いモデルと量子化方式でPPLが改善するが、すでに高精度なOmniQuantなどでは改善が0.01程度にとどまる例もある。低ビット化の難度が高く、支点KVの量子化誤差が大きい条件で相対的に有効と考えられる。ただしモデルが大きいほど必ず改善幅が大きいわけではない。PPLの絶対差とパーセント改善率は区別し、たとえば9.15→8.52は0.63ポイント低下である。

### MMLU・常識QA・対話品質

Vicuna-v1.3-13Bの5例提示MMLUでは、INT3・グループ128のRTNが44.56%から46.73%へ、GPTQが47.83%から48.53%へ、AWQが48.56%から49.05%へ改善する。一方、Vicuna-v1.5-13BのGPTQでは52.95%から52.49%へ**悪化**する例があり、同じ論文の表2を「常に改善」と要約するのは不正確である。OmniQuantのVicuna-v1.5-7Bでも46.62%から46.27%へ悪化する。

常識QAの7課題平均では、Vicuna-v1.3-13BのAWQ INT3が64.56%から65.02%へ改善する。個別課題は一様でなく、同モデルのGPTQ INT3ではOBQA 45.20%→44.00%、ARC-Challenge 46.08%→44.97%と低下する一方、LAMBADAは67.59%→69.03%へ改善する。平均値の改善と個別課題の悪化を併記することが、量子化品質の判断には必要である。

MT-BenchではVicuna-v1.5-13BをAWQ INT3で量子化した場合、GPT-4による10点満点の評価が5.17から、固定プロンプトIntactKVの追加で5.34、さらに較正で5.44へ上がる。元のFP16モデルは5.52であり、較正後も完全一致ではない。Vicuna-v1.5-7BのAWQ INT3は4.74→4.68と**保護だけでは悪化**するが、較正を加えると4.84へ改善する。これらはGPT-4による評価であって、実際の利用者による選好調査と同一ではない。

### KVキャッシュ量子化・活性値量子化への拡張

KVキャッシュ自体を低ビット化する場合、支点KVだけFP16のままにし、残りを低ビット化する混合精度方式を試す。原著の評価実装では量子化KVを注意演算前にFP16へ戻すため、支点KVをFP16で持っていても余分な復元処理は必要ない。これは「すべての量子化注意カーネルで追加費用ゼロ」という意味ではなく、実装がFP16へ戻すという前提に依存する。著者はAWQとKV量子化の組合せでMMLUを改善し、INT4重み量子化では平均0.27ポイントの改善を報告する。

重みと活性値を同時にINT4化する場合には、全KVを低ビットで処理するため支点KVを高精度のまま持てない場合がある。著者は高精度IntactKVの分布が比較的滑らかであることを利用し、先頭KVを一度高精度で生成した後、推論時には低ビットへ変換して使う。原著表6のLLaMA-3-8BではQuaRotのC4 PPL 13.42がIntactKVで12.23、WikiText2 8.21が7.54へ改善する。ただしこの経路は厳密な意味で先頭KVをFP16で保持するものではなく、**高精度由来の良好なKVを後から量子化して使う**という別条件である。

## 主要結果

この研究の発見は、量子化に弱い活性値がチャネルだけでなく**入力先頭の特定トークン位置**にも存在すること、その位置が注意の吸い込み先となり後続トークンへ広く影響することにある。保護すべき先頭位置が少数なら、高精度モデルでKVを一度生成して保存するだけで、量子化済みモデルの重みを再学習せずに品質を改善できる。保護する接頭辞を長くするとMSEが低下する傾向があるが、実装上は固定接頭辞を先頭から連続して保持する必要がある。

もう一つの貢献は、保存したKVだけを学習して後続の量子化誤差を補償できる点である。128例・20エポック程度の較正で対話品質の改善が見られるが、[BOS]だけの保護と長いシステムプロンプトの保護では効果が異なる。品質向上は通常の重み量子化やKV量子化と組み合わせやすい一方、全条件で必ず改善するわけではない。

## 既存研究との差

GPTQ、AWQ、OmniQuantなどは重みをどのように低ビット化するかを主に扱う。IntactKVはその後の注意計算で使う少数のKV状態を高精度モデルから供給するため、これらの量子化方式と併用できる。StreamingLLMなどの注意吸い込み先を保持する研究は、長文脈で重要な先頭トークンを捨てないことを重視するのに対し、IntactKVは**そのKVを量子化誤差なしで用意する**ことを目的とする。位置を保持することと値を高精度に保つことは別問題である。

全KVを高精度化する方式に比べ、IntactKVの追加容量は先頭の少数位置に限定される。一方、動的に選ばれる任意の重要トークンを保護する方式ではないため、入力に応じて支点位置が大きく変わる場合は固定接頭辞の前提が崩れる。KVキャッシュを共有する複数要求の接頭辞が完全一致しているかどうかも、推論エンジンへの統合時に重要になる。

## 限界

著者自身が、PPL、MMLU、常識QA、MT-Benchだけでは言語モデルのすべての能力を測れないと認める。実際、MMLUや個別QAでは一部のモデル・量子化方式で精度が悪化する。先頭の固定トークンを保護する方式なので、任意の動的プロンプトを高精度モデルなしで事前生成することはできない。対話のシステムプロンプトを変更した場合には、その新しい接頭辞に対応するKVを再作成する必要がある。

高精度モデルは推論時には不要でも、事前生成・較正時には必要である。量子化済みモデルしか入手できない状況では、同じIntactKVを再現できるとは限らない。推論時の追加費用ゼロという主張はキャッシュをそのまま連結できる実装が前提であり、KV形式・位置符号化・注意カーネル・バッチ配置が異なる実装での統合費用は別途検証を要する。

また、本論文は量子化モデルの品質改善を中心に評価しており、CPUオフロード、PCIe転送、ピークGPUメモリ、長文脈でのエンドツーエンド速度の統一測定を主結果としていない。FP16の先頭KVは短ければ軽いが、非常に長い固定システムプロンプトをそのまま保持する場合には容量が増える。支点KVの保存によって量子化の誤差上界が小さくなることは、すべての入力での意味品質を数学的に保証するものではない。
