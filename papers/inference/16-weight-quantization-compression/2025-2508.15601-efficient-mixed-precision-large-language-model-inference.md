# Efficient Mixed-Precision Large Language Model Inference with TurboMind

> TurboMindは、重み・活性値・キー・バリュー（Key-Value; KV）キャッシュの精度が混在するLLM推論を、単に低ビットカーネルへ置き換えるのではなく、GPUメモリ階層とテンソルコア命令に合わせて二つのパイプラインへ再設計する。汎用行列積（General Matrix Multiply; GEMM）側はハードウェア対応重みパッキング、注意側は任意のQ/K/V精度組合せ・適応ヘッド整列・KVロード重畳を扱う。16モデル、RTX 4090/L40S/A100/H100の4 GPU群で、既存混合精度基盤より配信遅延を最大61%（平均30%）削減し、スループットを最大156%（平均58%）向上する。

## 概要

低ビット重みやKVキャッシュは転送量を減らせるが、「低ビット形式をGPUがそのまま効率良く計算できる」とは限らない。たとえば4ビット重みを毎回展開してからTensor Coreへ渡せば、変換・共有メモリ転送・レジスタ圧力が新しいボトルネックになる。Q/K/Vの精度が異なる注意では、ヘッド次元やパック幅が命令粒度と合わないこともある。

TurboMindは混合精度を二つの実行パイプラインとして設計する。GEMMでは重みをオフラインでGPU世代・命令形式に合うよう並べ替え、実行時にロード・復号・行列積を重ねる。注意では低ビットK/Vをオンザフライで復号しつつ、現在タイルのQK/PV演算、次スライスのレジスタロード、次タイルのHBM→共有メモリ転送を並列化する。

目的は「圧縮率」ではなく、低ビット化で減ったメモリトラフィックを実際のTTFT/TPOT・スループットへ変換することにある。実装はLMDeployのTurboMind推論エンジンへ統合されている。

## 問題設定

混合精度推論は、モデル内に複数の表現形式を持つ。重み4bit・活性16bit、KV 8bit/4bitなどを組み合わせると、演算ごとにパック形式・変換位置・Tensor Core命令が異なる。

既存フレームワークが個別カーネルを持っていても、形式変換をHBMへ一度書き戻したり、ヘッド幅が命令タイルへ合わずパディングしたりすれば、低ビットの帯域利得を失う。GPU世代が変われば最適命令やメモリ階層も変わる。

TurboMindは「どの精度か」だけでなく、「どこでパックし、どこで復号し、何とオーバーラップするか」をハードウェアごとに最適化する。

## 手法

### 1. GEMM用のハードウェア対応重みパッキング

量子化済み重みをオフラインで、対象GPUのメモリアクセスと行列積命令が読みやすい形式へ並べ替える。実行時に汎用的な転置・再配置を繰り返さない。

入力はAWQ/GPTQ等で量子化された重み、出力はTensor Coreへ供給しやすいパック形式である。GPU世代・ビット形式に応じて自動的にレイアウトを選ぶことで、同じモデル表現でもカーネル内の変換費用を減らす。

### 2. ロード・復号・行列積を命令レベルで重ねる

GEMMカーネル内では、現在タイルの演算と次タイルのロード/低ビット展開を命令レベル並列（Instruction-Level Parallelism; ILP）で重ねる。変換が終わるまでTensor Coreが待つ、あるいは計算中にHBMが遊ぶ時間を減らす。

Qwen 8B AWQ、W4A16KV8、A100のカーネル例では、最適化GEMMがMARLIN比で平均19.2%、最大25.5%高速になると報告される。

### 3. 任意Q/K/V精度を扱う注意パイプライン

注意ではQ、K、Vが異なる精度でも直接処理できるようにし、K/Vを完全なFP16配列へ展開してからFlashAttentionへ渡す経路を避ける。

適応的ヘッド整列（adaptive head alignment）は、ヘッド次元・パック幅・GPUタイル幅の不一致を調整し、過剰パディングや細かい分岐を減らす。低ビットKVを使っても連続した大きなタイル演算を保つことが狙いである。

### 4. KVロードを三段パイプライン化する

注意カーネルでは、(1) 現在のK/VスライスでQKᵀ/PVを計算、(2) 次スライスを共有メモリからレジスタへロードし必要ならオンザフライ復号、(3) さらに次タイルをHBMから共有メモリへプリフェッチ、を重ねる。

これによりHBM帯域とTensor Coreを同時に使い続ける。A100のQwen 8B AWQ例では、注意プリフィルの遅延を平均22.1%（最大48.7%）、デコードを平均7.6%（最大29.9%）削減する。

## 評価

### 評価条件

| 項目 | 設定 |
|---|---|
| モデル | 16種類、約7B〜235B、Dense/MoEを含む |
| GPU | RTX 4090、L40S、A100、H100 |
| 量子化例 | AWQ、GPTQ、W4A16KV8、W4A8KV4等 |
| 比較 | vLLM + MARLIN、TensorRT-LLM、OmniServe + QServe等 |
| 評価 | カーネル遅延、配信遅延、TTFT/TPOT、スループット |
| 実装 | LMDeploy/TurboMindへ統合 |

### 主な結果

| 比較 | 結果 | 読み方 |
|---|---:|---|
| 配信遅延 | 最大61%低減、平均30%低減 | エンドツーエンドでの代表値 |
| スループット | 最大156%向上、平均58%向上 | 全16モデル・4 GPUを通じた混合精度評価 |
| Qwen 8B AWQ GEMM、A100 | MARLIN比平均19.2%、最大25.5%高速 | 重みパッキング＋ILPの寄与 |
| 注意プリフィル、同条件 | 平均22.1%、最大48.7%遅延削減 | KVロード/復号パイプライン |
| 注意デコード、同条件 | 平均7.6%、最大29.9%遅延削減 | 低ビットKVの帯域削減を実速度へ変換 |
| TensorRT-LLMとの一部7/14B比較 | スループット最大118.9%改善、TTFT 52.2%削減 | 実装・モデル条件依存の個別結果 |
| OmniServe+QServe W4A8KV4 | スループット14.1%高い条件 | 低ビット注意の比較 |

最大156%は「すべてのGPUで2.56倍」ではない。平均値は58%であり、カーネル・モデル・精度組合せによって利得幅は大きく変わる。特にデコード注意の平均改善7.6%のように、個別カーネルでは最大値よりかなり小さい条件もある。

## 既存研究との差

vLLM+MARLINは高性能な量子化GEMMを提供するが、TurboMindは重み側だけでなく注意のQ/K/V精度組合せとKVロードまで同じ混合精度設計で扱う。

TensorRT-LLMやOmniServe/QServeも低ビット推論を最適化するが、TurboMindの中心は複数形式・複数GPU世代を一つのハードウェア対応パイプラインへ落とし込む汎用性にある。

## 限界・実装状況

- 高性能化はGPU世代のTensor Core命令、共有メモリ容量、ロード命令に依存し、新アーキテクチャでは再チューニングが必要。
- 最大61%/156%は個別条件の上限で、平均はそれぞれ30%/58%。
- 混合精度のモデル品質そのものは量子化方式AWQ/GPTQ等にも依存し、TurboMindのカーネル最適化だけでは決まらない。
- 低ビット形式を増やすほど実装・テスト空間が広がる。
- 実装はLMDeployに公開されている: https://github.com/InternLM/lmdeploy

## 一般的な実装上の含意

量子化モデルを比較するとき、同じビット幅でも「どのカーネルで」「復号をどこで」「どのGPU命令へ」接続するかによって性能が変わる。メモリ容量の削減率だけでは配信性能を予測できない。

またプリフィルとデコードは同じ最適化でも利得が違うため、TTFTとTPOTを分けて測るべきである。カーネル単体の最大値とエンドツーエンド平均値も混同しない。
