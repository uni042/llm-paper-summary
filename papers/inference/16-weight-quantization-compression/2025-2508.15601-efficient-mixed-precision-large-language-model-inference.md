# LMDeploy Accelerates Mixed-Precision LLM Inference with TurboMind

## 概要

重み・活性値・キー・値キャッシュ（KVキャッシュ）のビット幅を別々に下げる混合精度推論では、モデルの保存容量を小さくするだけでは必ずしも実行時間が短くならない。量子化された重みを行列積の直前に浮動小数点へ復号すると、復号命令と共有メモリへの転送が計算の待ち時間になる。鍵と値だけを低ビット化しても、クエリがFP16であるとテンソルコア命令が期待する配置とずれ、行列積のための並べ替えに費用がかかる。

TurboMindはLMDeployに統合された混合精度推論エンジンで、重み側の汎用行列積（GEMM）と、クエリ・鍵・値（Q/K/V）側の注意計算を二つのパイプラインとして再設計する。重み側はGPU世代と量子化形式に合わせて事前に重みを並べ替え、実行時の復号と行列積を命令レベルで重ねる。注意側は精度が異なるQ/K/Vを整列させ、KVの転送、復号、注意演算を重畳する。単一のGPU世代や単一のW4A8KV4構成へ最適化を固定せず、異なるハードウェアとビット幅を共通の設計原理で扱うことを狙う。

著者らはRTX 4090、L40S、A100、H100の4種類のGPU、密モデルと混合専門家モデルを含む16種類のLLMで評価した。既存の混合精度推論基盤に対して配信遅延を最大61%（平均30%）削減し、処理率を最大156%（平均58%）向上したと報告する。ただし非量子化のW16A16KV16ではvLLMより遅い条件もあり、改善はLMDeployという枠組みだけの一般的な優位性ではなく、混合精度の実装最適化に由来する。

## 問題設定

### 低ビット化が速度に直結しない理由

重みをINT4へ量子化するとHBMから読み込むバイト数は減る。しかしGPUのテンソルコアへ渡す前には、量子化された整数値と尺度を読み込み、必要に応じてFP16へ復号する。重みが不適切に詰められていると、同一ワープのスレッドが連続した領域を読めず、複数のHBMトランザクションが必要になる。共有メモリ上でもバンク競合が起こり、同時アクセスを直列化してしまう。

注意計算では、FP16のクエリとINT4/INT8の鍵を組み合わせると、テンソルコアの行列積命令が想定する要素の配置と実際の低ビット索引配置が一致しない。汎用の並べ替えや一時テンソルを使うと、せっかく削減したKVの読み出し量を追加の転送と変換費用が相殺する。さらにデコード時は各トークンで過去のKVを読むため、現在の演算が終わるまで次のKVをロードしないと、テンソルコアが待機する。

### 論文が整理した六つの障害

著者らはメモリ側の問題を三つ、計算側の問題を三つに整理する。メモリ側は、低ビット重みの大域メモリアクセスが連続しないこと、共有メモリのバンク競合、低ビットKVとFP16クエリのレジスタ配置不一致である。計算側は、低ビットから浮動小数点への復号費用、量子化データとテンソルコアのタイル形状の不一致、KVロードと注意演算が直列化する空白時間である。

これらは互いに独立した障害ではない。重みを転送しやすく並べ替えても、復号が演算を停止させれば全体は速くならない。KVの読み出しを半分にしても、レジスタ内のシャッフルが増えれば利得が小さくなる。TurboMindは個別の低ビットカーネルを追加するだけでなく、メモリ階層を通るデータの順序と、計算命令を発行する順序を一緒に最適化する。

## 手法

### 1. GPU世代に応じた重みの事前パッキング

GEMMパイプラインは、推論を開始する前のオフライン段階と、要求を処理するオンライン段階に分かれる。オフラインでは量子化済みの重みを対象GPUのメモリアクセス幅、共有メモリのバンク構成、行列積命令のタイル形状に合わせて並べ替える。重みを適切な順序で詰め直すことにより、オンライン時に各ワープが連続した大きな領域を読み、追加の転置やシャッフルを減らせる。

この重みパッキングはモデルごとに一度行う処理であり、トークンを生成するたびに繰り返さない。論文は70B級モデルでも事前パッキングを約1.47秒で終える例を報告する。推論の長い稼働時間に比べると一回の準備費用は小さいが、モデルを頻繁に入れ替える環境では初期化時間として計上する必要がある。GPU世代が変わると適した命令やタイルが異なるため、同じ量子化重みでもハードウェアごとの配置を選択する。

### 2. 命令レベル並列による復号と行列積の重畳

オンラインのGEMMでは、HBMから低ビット重みと尺度を共有メモリへロードし、レジスタへ移して復号し、テンソルコアへ渡す。単純な実装は各段階を順番に待つため、復号中にテンソルコアが遊び、行列積中に次の重みの読み出しが止まる。TurboMindは複数の独立した命令を同時に進める命令レベル並列を利用し、現在のタイルの行列積と次タイルの復号・ロードを重ねる。

量子化値をいったんFP16の巨大な中間配列へ書き戻すのではなく、レジスタ内で必要な値へ展開して直ちに演算へ渡す。これにより、低ビット化のメモリ帯域削減が実際の行列積処理率へ反映されやすくなる。論文はA100上のQwen 8Bの量子化行列積で、MARLINに対する平均19.2%、最大25.5%の高速化を報告する。ただしこれは行列積カーネルの比較であり、モデル全体の速度倍率ではない。

### 3. 異なるQ/K/V精度の適応的ヘッド整列

注意計算では、クエリがFP16でも鍵・値をINT8またはINT4へ圧縮する場合がある。量子化された鍵をレジスタへロードする命令は、FP16のクエリと異なる幅の要素を取り出すため、そのままテンソルコアへ渡すと要素の並びが合わない。汎用の変換処理を挟むと低ビット化の利得が失われる。

TurboMindはヘッド次元と量子化形式に応じてデータ配置を調整し、レジスタへロードする時点でテンソルコアが必要とする並びへ整列する。これにより、混合精度のQK転置積と注意重み・値の積を同じ高効率なタイル処理へ接続できる。精度ごとに完全に別のカーネル群を作るのではなく、共通の再配置規則をGPU世代に合わせて具体化する。論文はこの操作が各注意ヘッドにつき共有メモリからレジスタへ読み込む時に一度だけ必要で、追加費用を抑えられると説明する。

### 4. KVメモリの段階的ロードと注意計算の重畳

デコード中の注意は、過去のKVを繰り返し読みながら新しいクエリとの内積を計算する。TurboMindは現在のKVタイルで注意スコアと値の集約を計算している間に、次のタイルを共有メモリからレジスタへロードし、さらにその先のタイルをHBMから共有メモリへ先読みする。低ビットKVの復号も必要な位置で実行し、復号済みKVを巨大な中間テンソルとしてHBMへ書き戻さない。

この重畳は単純なKV容量削減とは異なる。転送を減らしても、テンソルコアが次のデータを待つ時間が残れば処理率は上がらない。先読みの段数とタイル配置を調整してメモリと演算の両方を継続的に使うことで、長い系列や大きいバッチの注意演算を高速化する。実装では量子化形式に応じてKVのロード幅と復号手順を変えるため、すべてのビット幅で同じ性能が出るわけではない。

### 1. 実験の範囲と比較条件

### 2. 配信全体の遅延と処理率（要旨・第5節）

混合精度の対象構成では、既存の混合精度基盤に対して配信遅延が最大61%減少し、全体の平均削減率は30%だった。処理率は最大156%増加し、平均増加率は58%だった。最大値と平均値は異なるモデル・GPU・負荷を集約した指標であり、全構成で61%減または156%増になるという意味ではない。論文は個別モデルとバッチ規模に応じて、平均遅延と高分位遅延、要求処理率を分けて示す。

配信全体の改善には重み側の行列積とKV側の注意の両方が寄与する。量子化重みを使っていても、GPUのテンソルコアへ効率的に渡せなければ行列積は遅くなる。逆に重みの行列積が速くなっても、デコード時のKVロードが律速なら処理率は頭打ちになる。TurboMindの二つのパイプラインはこれらの律速を別々に減らす。

### 3. 非量子化設定の負の結果（図12）

W16A16KV16の一般精度構成でvLLMと比較した場合、LMDeployはQwen3 8BとQwen3 32Bの対象設定でそれぞれ約2.1%と5.2%性能が劣る。論文はこの結果を、混合精度での改善が単に枠組み全体の優位性ではなく、混合精度に特化したカーネル設計に由来することを示す証拠として扱う。したがって、TurboMindがすべての精度形式で常にvLLMより速いと説明するのは不正確である。

### 4. 行列積と注意の個別改善

A100上のQwen 8BのAWQ構成で、重み側のGEMMカーネルはMARLIN比で平均19.2%、最大25.5%高速と報告される。注意側では、同じ量子化条件のプリフィルで平均22.1%、最大48.7%の遅延削減、デコードで平均7.6%、最大29.9%の削減が既存原稿に整理されている。これらはカーネル・フェーズ別の値であり、配信全体の最大61%減少と単純に加算できない。注意のデコードでは平均7.6%という比較的小さな改善もあり、構成要素の効果はフェーズごとに異なる。

|比較の範囲|代表的な結果|注意点|
|---|---|---|
|混合精度の配信遅延|最大61%減、平均30%減|モデルとGPUの組合せに依存|
|混合精度の要求処理率|最大156%増、平均58%増|最大値を全構成に一般化しない|
|A100の量子化GEMM|MARLIN比平均19.2%、最大25.5%高速|行列積カーネル単体|
|A100の注意プリフィル|平均22.1%、最大48.7%遅延削減|KV転送・復号の重畳|

### 5. 低ビットKVの容量と処理率の交換条件

KVキャッシュを16ビットから8ビット、4ビットへ圧縮すると、長い系列を保持するためのメモリ量を減らせる。一方、低ビットの鍵とFP16のクエリを同時に計算するには、適応的なヘッド整列と復号が必要である。論文の第5節はKVビット幅を変えたプリフィル・デコード処理率を比較し、低ビット化が有利な系列長とバッチ条件を示す。4ビットKVがすべての条件で16ビットより速いわけではなく、データ変換費用やタイルの形状が律速になる場合がある。

同じモデルを複数GPUへ展開する評価では、Qwen3 32BをA100で1・2・4・8GPUへ増やしたとき、要求処理率の相対倍率は1.0、1.8、3.2、4.4と報告する。Qwen2.5 72Bの対応する倍率は1.0、1.9、3.5、5.2である。台数を8倍にしても処理率が8倍にはならないため、通信・同期・負荷分散の費用が残る。これは混合精度カーネルの性能と複数GPUの拡張性を別々に扱うべきことを示す。

### 6. 品質と量子化方式の切り分け

TurboMindは量子化モデルを高速に実行する基盤であり、重みを4ビットへ圧縮した際のモデル品質を自動的に保証する手法ではない。品質はAWQ、GPTQなどの量子化方式、校正データ、重み・活性・KVの精度組合せに依存する。異なる量子化方式を使った結果を比較するときは、速度だけでなく同じ精度条件での品質が十分近いかを確認する必要がある。

論文の比較では量子化方式とGPU世代をまたぐ汎用性を強調するが、低ビット化が原因で生じる精度劣化はカーネルの転送最適化では元に戻らない。したがって「同じ品質で速度だけを上げる」条件と「低ビット化で品質を一部犠牲にする」条件を混同しないことが重要である。

## 既存研究との差

MARLINは量子化GEMMの高性能カーネルを提供するが、重みの行列積に重点がある。TurboMindは重みの事前配置だけでなく、Q/K/Vの精度組合せに応じた注意のレジスタ整列とKV先読みを一体で扱う。QServeはW4A8KV4に特化した最適化を持つが、TurboMindは複数の量子化形式とGPU世代を共通の設計原理で扱うことを重視する。

TensorRT-LLMもグラフ最適化とCUDAカーネルを用いるが、低ビット値を復号してからテンソルコアへ渡す経路の費用が残る場合がある。TurboMindは重みの配置、復号命令の重畳、KVの段階的ロードを同時に最適化する。重要なのは量子化の圧縮率だけではなく、GPUのメモリ階層を通るデータの配置と演算命令の発行順序を設計している点である。

## 限界と負の結果

混合精度の性能はGPU世代、テンソルコア命令、共有メモリ容量、メモリアクセス幅に強く依存する。新しいGPUや未対応の量子化形式では、適切な重みパッキングとタイル設計を選び直す必要がある。事前パッキングが短時間で終わる場合でも、頻繁にモデルを入れ替える運用では初期化費用を無視できない。最大61%・156%という値は特定の構成での上限であり、全体平均はそれぞれ30%・58%である。

W16A16KV16の非量子化設定ではvLLMより遅い結果もあり、TurboMindの優位性は混合精度カーネルに依存する。注意デコードの平均改善7.6%のように、個別の構成要素では大きな速度差が出ない条件もある。KVを4ビットにすると容量は減るが、復号や整列が重い条件では速度が改善しない可能性がある。

量子化によるモデル品質の劣化はTurboMindの転送最適化では解消されない。低ビット化で出力の正確性がどの程度変わるかは、使用する量子化方式とモデルに依存する。研究で評価した16モデルと4種GPU以外の組合せや、非常に異なる要求分布に対して同じ性能を保証するものではない。複数GPUの処理率も台数に比例して無限に伸びるわけではなく、通信と同期の費用が残る。
