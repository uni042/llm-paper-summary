# MiLo: Efficient Quantized MoE Inference with Mixture of Low-Rank Compensators

> 3ビットMoEの量子化残差を専門家特性に応じた低ランク補償器で回復し、校正不要の精度改善とTensor Core向けW3A16実測高速化を両立する。

## 書誌

- 著者: Beichen Huang, Yueming Yuan, Zelei Shao, Minjia Zhang
- MLSys 2025
- arXiv: 2504.02658
- 一次資料: https://arxiv.org/abs/2504.02658

## 概要

混合専門家モデル（Mixture-of-Experts; MoE）は1 tokenで一部専門家しか動かさないため演算量を抑えられるが、全専門家の重みを保持するメモリは巨大になる。Mixtral-8×7BはFP16重みだけで約90GBを必要とし、CPU/NVMeへのオフロードはPCIe転送、複数GPU配置は機器費用を増やす。

4ビット量子化は比較的安定だが、3ビットまで下げるとMixtral-8×7BのWikiText-2 PPLはRTNで3.42から4.81、GPTQでも4.61へ悪化する。MiLoは量子化後の誤差行列を低ランク補償器で再構成し、MoE固有の層・専門家差に応じてrankを配る。

さらに3ビット圧縮を実速度へ変換するため、無駄bitのないINT3 packing、bit操作による逆量子化、多段パイプラインを持つW3A16 Tensor Coreカーネルを実装する。Mixtral-8×7BとDeepSeek-MoEで、22%圧縮率条件においてPPL上の精度損失の87%以上を回復し、MARLIN比1.2倍、baseline比最大3倍の高速化を報告する。

## 問題設定

MoEの重みは均質ではない。注意投影や共有専門家など密に活性化される重みと、routerにより一部tokenだけが通る疎専門家では学習時に見るtoken分布が異なる。同一MoE層内でも専門家ごとの活性頻度が大きく違い、DeepSeek-MoEでは最頻専門家が最少専門家の11.7倍活性化される例がある。

INT3量子化では外れ値自体は捉えられても、中程度の多数の重み表現が失われる。すべての行列へ同じ低ランク補償を付けると、重要度の低い箇所へメモリを使い、重要箇所ではrank不足になる。

## 手法

### 量子化後低ランク補償

元重みWを量子化・逆量子化したQ^-1(Wq)だけで近似せず、残差E = W - Q^-1(Wq)をUVという低ランク積で補う。推論時の有効重みはQ^-1(Wq) + UVとなる。

補償器は量子化で失われた中程度の重み情報を表現する役割を持つ。フル精度残差を保存するより小さいrankで済むため、3ビット化の容量削減を大きく失わず精度を戻せる。

### MoE特性に応じたrank配分

MiLoは三つの信号でrankを変える。第一に密層と疎専門家層を区別し、密層へより多くのrankを与える。第二に重み分布の尖度（kurtosis）を使い、外れ値構造が強い行列へ補償容量を配る。

第三に専門家活性頻度を使い、頻繁に選ばれる専門家へ高いrankを割り当てる。これにより「全専門家を同じ精度で補償する」方式より、限られた補償メモリを実際のtoken経路へ集中させる。

### 反復最適化

量子化重みを固定して残差だけを一度SVDするのではなく、量子化表現と低ランク補償器を反復して更新する。両者が同じ情報を重複表現することを避け、3ビット側と補償側で役割分担を改善する。

MiLoは入力校正データを必要とせず、重み自体から補償を構成する。このためGPTQ/AWQのような校正集合への依存と、大規模MoEをforwardする校正費を避ける。

### W3A16 Tensor Coreカーネル

3ビットは通常のbyte境界に合わず、packingと逆量子化が実行時間を食いやすい。MiLoはzero-bit-waste packing、bit操作ベースの逆量子化、複数段のロード/計算パイプラインを組み合わせる。

目的は理論上の25%追加圧縮を実測速度へ変えることで、batch size > 1でもTensor Coreを使うW3A16行列積を提供する。

## 評価条件

| 項目 | 内容 |
|---|---|
| モデル | Mixtral-8×7B、DeepSeek-MoE |
| 比較量子化 | RTN、GPTQ、HQQ系、MARLIN等 |
| 精度 | WikiText-2 PPL、複数下流task |
| 形式 | INT3重み + FP16活性（W3A16） |
| 実装 | NVIDIA Tensor Core向けCUDAカーネル |
| 指標 | PPL/accuracy、メモリ圧縮、量子化時間、latency |

## 主要結果

| 条件 | 結果 | 解釈 |
|---|---:|---|
| Mixtral-8×7B RTN | FP16 PPL 3.42 → INT3 4.81 | 素の3ビット化は品質悪化が大きい |
| Mixtral-8×7B GPTQ | INT3 PPL 4.61 | 校正型でも3ビットは難しい |
| DeepSeek-MoE GPTQ | FP16 5.83 → INT3 7.08 | 別MoEでも同じ傾向 |
| 22%圧縮率条件 | PPL上の精度損失の87%以上を回復 | 低ランク補償が極低bit化を実用域へ戻す |
| W3A16カーネル | MARLIN比約1.2倍 | 3ビットpacking費を抑えて実速度化 |
| システム比較 | 最大約3倍高速化 | 圧縮とkernelの組合せ効果 |

## 既存研究との差

GPTQ/AWQは校正活性を使って量子化誤差を抑えるが、MiLoは校正データを使わない。LoRCのような低ランク残差補償に対しては、MoEの密/疎構造、重み尖度、専門家活性頻度をrank配分へ入れる点が異なる。

また精度アルゴリズムだけでなく、通常hardwareで扱いにくい3ビットをTensor Coreへ載せる専用カーネルまで実装し、batch size > 1の実測latencyを評価する。

## 限界

低ランク補償器は追加重みと追加行列積を必要とするため、純粋なINT3より容量・計算が増える。最適rank配分も対象MoEの重み統計やrouter頻度に依存する。

高速化は専用W3A16カーネルと対象GPU形状に依存し、INT3ファイルを既存runtimeへ置くだけでは再現できない。評価モデルはMixtral-8×7BとDeepSeek-MoEが中心で、より新しい巨大MoEや異なるexpert構造への一般化は追加検証が必要である。
