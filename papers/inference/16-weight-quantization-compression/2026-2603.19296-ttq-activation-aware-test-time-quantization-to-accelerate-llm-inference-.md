# TTQ: Activation-Aware Test-Time Quantization to Accelerate LLM Inference On The Fly

> 量子化の較正を配置前に済ませる前提をやめ、プロンプト自身の活性値からその場で尺度を決めることで、ドメインシフトに弱い静的量子化を、較正データなしで適応できる量子化へ変えた方式。

## 概要

重みの低ビット量子化は、大規模言語モデルの推論を速くする標準的な手段になっている。その中でもGPTQやAWQのような活性化配慮型の学習後量子化は、入力活性の統計を使って量子化誤差の出方を制御し、単純な丸め（RTN）よりずっと良い精度を出す。ただしこの統計は、配置前に集めた較正データから一度だけ計算するのが前提である。ここに運用上の弱点が3つある。第1に、較正データと実際のタスクの分布がずれると（ドメインシフト）、決め打ちした尺度が合わなくなり精度が崩れる。第2に、量子化したモデルを配置した後は全精度の重みが手元に残らず、新しいドメイン向けに再較正できない。第3に、較正そのものにまとまった量のデータと計算が要る。

TTQ（Test-Time Quantization）は、この較正の実行時点を配置前から推論時へ移す枠組みである。入力されてきたプロンプト自身の活性値から、AWQが使う対角相関統計をその場で推定し、閉形式で求まる尺度付き量子化をプロンプトごとに実行する。較正データは不要（ゼロ較正）で、全精度重みを保持したままなので、プロンプトやドメインが変われば量子化もやり直せる。追加の計算は重み行列の要素数オーダーの処理が3回分で、射影本体の計算量に比べて無視できる水準に収まる。極端な低ビットで残る劣化には、量子化残差へ低ランク因子を足す補償を組み合わせる。

**代表結果:** グループサイズ32、2–5ビット、OPT（125M–6.7B）、Qwen3、Gemma3でのパープレキシティ測定（WikiText-2、PTB、C4のマクロ平均）で、TTQは較正に2の17乗トークンを使ったAWQを全条件で上回った。4ビットでは多くのモデルで未圧縮と同等の値に届く（例: OPT-6.7Bで平均13.1、未圧縮13.1）。2ビットは大規模モデルでは差が開き（OPT-1.3BでTTQ 27.2対AWQ 31.7–32.6、RTN 11514.4）が、小規模モデルでは全方式とも実用域に届かない（Qwen3-0.6BでTTQでも1552.6、未圧縮31.7）。速度はクエリ射影モジュール単体の測定で、オンライン量子化を足したTTQ（低ランクなし）はAWQとほぼ同等で、RTX4090上のQwen3-32Bでは低ランクありでも最大4.9倍の高速化が報告されている。実機測定であり、シミュレーションではない。

## 問題設定

静的量子化の弱点は、精度が「較正データの選び方」に引きずられることとして現れる。この論文の表3では、同じAWQでも較正データをWikiText-2、PTB、C4のどれにするかで結果が動き、Qwen3-0.6Bの2ビットでは平均パープレキシティが5388.1から17344.3までばらつく。較正量への感度も大きく、OPT-350Mの3ビット（WikiText-2）では、AWQは較正トークンを2の11乗から2の17乗まで増やしても25.73から25.02までしか改善しない。つまり静的方式は、較正を手厚くしてもなお、データの当たり外れに左右される。

計算量の面では、活性化配慮型の代表であるGPTQは最適脳外科医（optimal brain surgeon）に由来する貪欲な補償を使い、コレスキー分解のために少なくとも3次オーダーの計算が要る。AWQは相関行列を対角で近似することでこの問題を閉形式に落とし、実用的な速度を得た。TTQが引き継ぐのはこのAWQの定式化であり、変えるのは「統計をいつ、どのデータから取るか」である。テスト時には本物の相関行列は未知なので、入力トークンから推定する必要があり、推定の安定性と追加計算の小ささが設計の中心になる。

もう一つの前提として、量子化した重みで線形射影を実行する高速カーネル（vLLMのawq_gemmやMarlin）は既に存在し、量子化の恩恵であるメモリ交通量の削減はそのまま速度に換わる。したがって課題はカーネルの新造ではなく、量子化パラメータの決め方をオンライン化しても、カーネル実行の利得をオンライン処理の追加費用で消さないことにある。

## 手法のあらまし

TTQの処理は、プロンプトが到着したときに層ごとに行う短い前処理と、その後の通常の量子化済み推論に分かれる。前処理では、プロンプトの活性値から入力チャネルごとの二乗和を集め、収縮推定（shrinkage）で安定化した対角相関を作り、AWQの閉形式に従って重みを尺度付きで量子化する。量子化済みの重みは既存の整数行列演算カーネルへそのまま渡る。低ランク補償を使う場合は、量子化の前に重みから低ランク成分を分離しておき、量子化残差に低ランク射影を加えて実行する。ハイパーパラメータ（尺度の指数、収縮の強さ、ノルムの次数）は固定値で使い、探索はしない。

## 手法

### 1. テスト時オンライン較正 — プロンプト自身から統計を作る

量子化の目的関数は、重み \(W\) と量子化済み \(\hat{W}\) の差が出力に与える誤差 \(\mathcal{L} = \mathbb{E}_X \| (W - \hat{W}) X \|^2 = \| (W - \hat{W}) C^{1/2} \|^2\) で、ここで \(C = \mathbb{E}_X [X X^\top]\) は入力活性の自己相関である。静的方式はこの \(C\) を較正データから事前に求める。TTQは代わりに、推論時に到着したトークン列そのものから \(C\) を推定する。プロンプトはそのタスク自身の分布から来ているため、ドメインシフトの問題が構造的に生じない。

推定を安定させるために、標本共分散へ単位行列方向の収縮を入れた推定量 \(C_\lambda = (1-\lambda) X X^\top + \lambda \eta I\)（\(\eta = \|X\|^2 / d\)、Ledoit–Wolf型の収縮）を使う。プロンプト長が短く標本が少ない場合でも、対角成分がゼロに落ちて尺度が発散することがない。

この方式が成り立つのは、全精度の重みを保持し続ける配置だからである。量子化済みの重みはプロンプトごとに作る使い捨てで、元の重みは常駐する。配置後に新しいドメインの入力が来ても、その入力で量子化をやり直せばよい。代償として、量子化前の重みを保持する分のメモリは必要になる（量子化によるメモリ削減は、重み常駐ではなく実行時の交通量削減として得る設計である）。

### 2. 対角相関による閉形式の尺度付き量子化

相関行列をそのまま使うと最適な量子化は閉形式にならないため、AWQの近似を引き継ぎ、\(C_\lambda\) を対角行列 \(D \simeq \mathrm{diag}[X X^\top + \lambda I]^\alpha\) で近似する。この論文は元のAWQの \(\ell_1\) ノルムに基づく対角を \(\ell_p\) ノルムへ一般化しており（元のAWQは \(\ell_1\)、本論文の定式化では \(\ell_2\) も扱う）、対角の各成分は入力チャネルの活性の大きさを表す。この近似の下で、誤差を最小にする量子化は \(\hat{W} = \mathcal{Q}[W D^{1/2}] D^{-1/2}\) という尺度付き量子化・逆量子化（QDQ）の閉形式になる。意味は、活性の大きいチャネルほど重みを大きく割り増してから量子化し、実行時に割り戻すことで、重要なチャネルの量子化誤差を相対的に小さく保つことである。

量子化そのものはグループ単位のQDQで、グループごとに尺度 \(S\) とゼロ点 \(Z\) を持ち、\(q\) ビットへ丸める。グループサイズは標準で32、最近の形式（NVFPなど）が使う16のようなマイクロスケーリングも扱える。

追加計算は、重みの尺度付け、量子化、逆尺度の3回で、いずれも \(\mathcal{O}[d' d]\)（重み行列の要素数）である。射影本体は \(\mathcal{O}[d' d T]\)（\(T\) はトークン長）なので、出力次元とトークン長が十分大きければ相対的な追加費用は無視できる、と論文は示している。GPTQのような3次オーダーの分解は不要である。

### 3. 低ランク補償 — 極端な低ビットで残る劣化を埋める

2ビット級の量子化では、尺度の工夫だけでは劣化が大きい。TTQはQLoRAの発想を転用し、量子化済み重みへ低ランク因子の積を加えた \(\hat{W} = W_q + B A\) の形を取る（\(B\) は \(d' \times r\)、\(A\) は \(r \times d\)、ランク \(r\) は次元よりずっと小さく、実験では \(r = 16\)）。低ランク射影の計算量は \(\mathcal{O}[r (d' + d) T]\) で、射影本体に対する相対追加は小さい。

効果は低ビット側に集中する。OPT-125Mの2ビットでは、低ランクなし（\(r = 0\)）の平均パープレキシティ257.4が、\(r = 16\) で141.7まで下がる（それでも未圧縮31.1には遠い）。4–5ビットでは補償の有無による差はほぼ消えるため、補償は極端な低ビット専用の部品と位置づけられる。

### 4. 実行経路 — 既存カーネルへの接続と、まだ融合できていない前尺度

量子化が終われば、線形射影は既存の整数行列演算カーネル（vLLMのawq_gemm、Marlin）で実行でき、重みのメモリ交通量の削減がそのまま効く。AWQは前尺度（プリスケーリング）を前段のモジュールへ融合して追加の読み書きを消しているが、TTQの尺度はプロンプトごとに変わるため同じ融合ができず、int_matmulのプロローグ側へ融合するカーネルが要る。現状のカーネルはその融合に対応しておらず、論文はTTQ専用カーネルの設計を今後の課題としている。また多くのカーネルは任意のビット幅を想定しておらず、2ビット向けに設計し直せば重みの詰め込みによる交通量半減で理論上さらに2倍の高速化が見込める、と述べている。

## 評価

結論を先に置く。品質（パープレキシティ）では、TTQは較正済みAWQを全条件で上回り、特に「較正データなしで、較正に2の17乗トークンを使った相手に勝つ」点が方式の主張を裏づけている。グループサイズへの耐性も高く、AWQの約2倍のグループサイズまで劣化を抑えられるため、尺度とゼロ点の保持メモリを半分にできる。一方で、2ビットは小規模モデルでは全方式とも崩壊しており、TTQでも救えていない。速度の証拠はクエリ射影モジュール単体に限られ、モデル全体のエンドツーエンド測定は示されていない。

| TTQ（r=16、較正なし） | 24.17 |
| AWQ（C4較正、2の11乗トークン） | 25.73 |
| AWQ（C4較正、2の17乗トークン） | 25.02 |

読み方: AWQは較正トークンを64倍に増やしても25.02までしか下がらず、較正なしのTTQ（24.93、低ランクありで24.17）に届かない。較正の「量」より「どの分布から取るか」が効いていることの証拠になっている。

</details>

## 既存研究との差

GPTQとの差は、最適化の解き方と実行時点の両方にある。GPTQは較正データに対する誤差を貪欲に補償し、コレスキー分解を含む重い前処理を配置前に行う。TTQは対角近似で閉形式に落とすため前処理が軽く、その軽さゆえに推論時へ移せる。

AWQとの差は、統計の出所だけである。定式化（対角相関、尺度付きQDQ、閉形式）はAWQのものを引き継ぎ、較正データから事前に求めていた対角相関を、入力プロンプトからその場で推定する点だけが違う。この一点の変更で、較正データの収集と管理、ドメインシフトへの弱さ、配置後の再較正不能という、静的方式の運用上の問題がまとめて消える。論文中の比較でも、AWQの結果が較正データの選択で大きく動くことが、静的方式の弱さとして示されている。

QLoRAとの関係は、低ランク因子の使い道が逆である。QLoRAは量子化した基盤モデルを学習で適応させるために低ランク因子を訓練する。TTQの低ランク因子は学習のためのものではなく、極端な低ビット量子化の残差を推論時に補償するための部品である。

## 限界・実装状況

第1に、速度の証拠が弱い。測定はクエリ射影という単一モジュールに限られ、モデル全体での高速化率は示されていない。オンライン量子化の追加費用が「無視できる」という主張も、射影本体との相対計算量に基づくもので、層数が多いモデル全体で前処理が何回走るかを含めた実測はない。第2に、TTQ専用カーネルが未整備で、前尺度の融合ができない分だけ現状は不利を抱えており、2ビット向けカーネルも存在しない。速度の主張は既存カーネルで測った暫定値とみるべきである。第3に、品質の主指標はパープレキシティであり、下流タスクでの精度は視覚言語系の付録が中心で、言語モデルのタスク精度は薄い。第4に、2ビットは小規模モデルで全方式とも崩壊しており、TTQの改善（Qwen3-0.6Bで1552.6）も実用化とは言えない。第5に、ハイパーパラメータは固定値で済ませており、感度や動的調整は著者ら自身が今後の課題としている。実装は、論文中に擬似コードがあり、評価はvLLMの既存カーネル上で行われたが、著者らの公式実装の公開は確認できない。

## 一般的な実装上の含意

較正を「配置前の資産」から「推論時の計算」へ移す設計は、量子化以外にも効く考え方である。統計量の推定が十分に軽く閉形式で済むなら、入力分布に依存するパラメータは事前に固定せず、その場の入力から作る方が、分布のずれに対して構造的に強い。ただしその代償として、圧縮済みの成果物だけを配る運用（量子化済みモデルの配布）はできなくなり、全精度の重みを保持・配布する前提に変わる。メモリ削減の内訳も、常駐メモリではなく実行時の交通量へ移る。導入を検討する場合は、どのメモリが実際に減るのかを配置形態ごとに切り分ける必要がある。
