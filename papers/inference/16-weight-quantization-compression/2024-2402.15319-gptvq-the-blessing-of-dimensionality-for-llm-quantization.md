# GPTVQ: The Blessing of Dimensionality for LLM Quantization

> 複数の重みを1ベクトルとして量子化し、代理ヘッセ行列（proxy Hessian）で量子化誤差を後続列へ補償する。Llama 3 8Bの約3.125 bit/value構成では、Snapdragon X Elite上で独自INT4実装よりモデル占有量を約19%減らし、23.81から26.15 token/sへ高速化する。

## 概要

GPTVQは、GPTQ型の学習後量子化（post-training quantization; PTQ）を**ベクトル量子化（vector quantization; VQ）**へ拡張する。通常のスカラー量子化は重み1個ずつを少数の値へ丸めるため実装しやすいが、2〜3ビット級では各重みを独立に表す制約が強く、精度が急激に落ちる。VQでは複数重みをひとまとまりのベクトルとしてコードブック中の代表ベクトルへ置き換えるため、同じ平均ビット数でもより柔軟に重み分布を近似できる。

ただしLLMのVQには二つの問題がある。第一に、単純なユークリッド距離でコードブックを作ると、層出力へ強く影響する方向とそうでない方向を区別できない。第二に、大きなコードブックや高次元ベクトルは圧縮品質を上げても、モバイルCPUでのコードブック参照・復号を重くする。GPTVQは前者へ代理ヘッセ行列に基づく距離とGPTQ型誤差補償を使い、後者へ比較的小さいベクトル次元・コードブックと実装しやすいデータ配置を採る。

評価では、Llama 2/3、Mistral、Mixtralで2〜3 bit/value級まで量子化し、高次元VQほど同一容量でパープレキシティとゼロショット精度が改善することを示す。Llama 3 8Bの2.125 bit/valueではGPTQのWikiText2パープレキシティが約200まで崩れるのに対し、GPTVQの2次元VQは10.8、4次元VQは9.59に抑える。さらにSnapdragon X Elite実機では、3.125 bit/valueの2次元VQが独自INT4実装より小さいメモリ占有量と高い生成速度を両立する。

## 問題設定：なぜ多次元量子化が効き、なぜ実装が難しいのか

スカラー量子化では、各重みを有限個の値から独立に選ぶ。ビット数を下げるほど選択肢が急減し、重み間の相関を利用できない。一方、(d) 個の重みを1ベクトルとして (k) 個の代表点から選ぶVQでは、同じ1重み当たりビット数でも多次元空間へ代表点を配置できるため、分布の形へ合わせやすい。論文が「次元の恩恵（blessing of dimensionality）」と呼ぶのはこの効果である。

しかしLLMの目的は重み自身の二乗誤差を最小化することではない。線形層への入力を (X) とすると、重み誤差が層出力へ与える影響は (H=XX^T) で重み付けされる。したがって、同じ距離だけ重みが動いても、較正入力上で重要な方向の誤差ほど強く抑える必要がある。GPTVQはこの代理ヘッセ行列をコードブック学習と量子化順序の双方へ使う。

モバイル推論では別の制約もある。自回帰デコードは各トークンで巨大な重みをDRAMから繰り返し読むため、CPU演算性能よりメモリ帯域が律速しやすい。VQなら保存重みを小さくできる一方、計算前にインデックスからコードブック値を復号する処理が増える。コードブックを巨大化して圧縮精度だけを追うと、この復号コストが帯域削減を打ち消す。GPTVQは品質とモバイル復号効率の双方を設計対象にする。

## 手法

### 1. 多次元コードブックで重みを表す

GPTVQは連続する (d) 個の重みを1ベクトルとし、各ベクトルを (k) 個のセントロイド（centroid）のいずれかへ割り当てる。保存するのはセントロイド番号とコードブックであり、推論時には番号からベクトルを復号する。

平均保存量は、インデックスの (log_2(k)/d) bit/valueにコードブック自身の償却費を加えた
[
mathrm{bpv}=rac{log_2 k}{d}+rac{k d b_c}{l}
]
で表される。ここで (b_c) はコードブック値のビット幅、(l) は1コードブックを共有するグループサイズである。次元を上げると同じインデックスビットを複数重みで共有できる一方、コードブックは (d) 倍大きくなるため、グループが小さすぎると償却費が増える。

### 2. ヘッセ行列を使ったコードブック初期化

通常のk-meansは各ベクトルのユークリッド距離を等価に扱う。GPTVQでは、代理ヘッセ行列から得る対角項で各座標の距離を重み付けし、層出力再構成誤差へ効く方向を優先してセントロイドを決める。

コードブック学習は期待値最大化法（expectation-maximization; EM）に似た反復で行う。割当段階では各重みベクトルをヘッセ重み付き距離が最小のセントロイドへ割り当て、更新段階で各クラスタの代表値を再計算する。既定では100反復を用い、その後も改善は小さいながら続くことを報告する。

初期セントロイドにはk-means++の代わりに、平均からのマハラノビス距離（Mahalanobis distance）で重みベクトルを並べ、距離空間を代表する点を取る方法を使う。論文ではこの初期化がk-means++と近い最終品質を保ちながら高速であることを示す。

### 3. GPTQ型の誤差補償をVQへ拡張する

コードブックを作った後、GPTVQは重み行列を左から順に量子化する。スカラーGPTQが1列ずつ処理するのに対し、(d) 次元VQでは**(d) 列を同時に**処理する。各行について、対象 (d) 個の重みをコードブックの候補へ置き換えたときのヘッセ重み付き誤差が最小になるセントロイドを選ぶ。

量子化した (d) 列と元の列との差を誤差として計算し、逆ヘッセ行列に基づくGPTQ型更新で未量子化列へ伝播する。これにより、先に丸めた誤差を後続列が補償できる。理論上は同じ列内の (d) 要素をまとめる方が誤差だけなら有利な場合もあるが、論文は実機で連続列を復号しやすいデータ配置を優先して (d) 列単位を採る。

また行列全体で1つのコードブックを使わず、列方向をグループへ分け、通常256列以下の単位で別コードブックを持たせる。前のグループを量子化して誤差補償した後の重み分布へ、次グループのコードブックを適応させられるためである。

### 4. コードブック自体の圧縮とモバイル復号

コードブックをFP16のまま保存すると、低bpv領域ではコードブック費用が無視できない。GPTVQはコードブックを整数量子化し、必要に応じて特異値分解（singular value decomposition; SVD）も検討する。実験では同一保存量なら8ビット整数コードブックが強く、標準設定として使われる。

推論時のVQは重みを保存する形式であり、CPU演算器がVQを直接計算するわけではない。番号を読み、コードブックを参照してネイティブ計算形式へ復号してから行列積を行う。したがって高速化の条件は、**減ったDRAM読出し時間 > コードブック参照・復号の追加時間**である。高次元・巨大コードブックを無制限に使わず、モバイルCPUが効率よく表引きできる設定へ抑える理由がここにある。

2.125 bpvでは、次元を1→2→4と上げるほど概ねPPLとゼロショット平均が改善する。Llama 2 7Bでは4D GPTVQのゼロショット平均が62.9、Llama 3 8Bでは62.3となる。一方、次元を上げるほどコードブック参照・デコード実装は複雑になるため、品質だけで最大次元を決めることはできない。

3.125 bpvでは差は縮むが傾向は同じで、Llama 2 7BのPPLはGPTQ 6.29、GPTVQ 1D 5.95、2D 5.83、Llama 3 8Bでは8.2、7.29、7.00となる。すなわちVQの利点は極低ビットで特に大きい。

### モバイルCPU実測

|Llama 3 8B形式|平均bpv|モデル占有量|生成速度|
|---|---:|---:|---:|
|llama.cpp Q4_0|4.5|4.64 GB|17.95 ± 1.01 token/s|
|独自INT4、group 128|4.125|4.33 GB|23.81 ± 0.27 token/s|
|GPTVQ 2D、group 8192|3.125|3.52 GB|26.15 ± 0.31 token/s|

GPTVQは独自INT4に対し占有量を約19%減らし、生成速度を約10%上げる。ここでは「復号処理があるのに速い」ことが重要で、Llama 3 8Bのデコードがメモリ帯域律速であるため、DRAM転送削減が復号費用を上回ったことを示す。

AQLMは層内のブロック微調整まで行うと品質でGPTVQを上回るが、圧縮時間は大幅に長い。GPTVQはその追加最適化を行わず、比較的短い圧縮時間でGPTQより強い低ビット品質を狙う位置付けである。

## 構成要素・感度

ベクトル次元を上げると理論上の表現力だけでなく実測PPLも概ね改善する。ただし固定bpvでは次元とコードブック数、グループ長の組合せでコードブック償却費が変わるため、「4Dが常に2Dより良い」と単純化はできない。モバイル実装では2Dを採用し、復号効率との交換条件を優先している。

EM反復数は増やすほど緩やかに改善し、既定100反復は品質と圧縮時間の折衷である。量子化後にコードブックを追加更新するとPPLをさらに下げられるが、圧縮時間は増える。コードブック自体の表現では8ビット整数が容量と品質のバランスに優れ、高次元でSVDを使っても必ず優位にはならない。

## 既存研究との差

GPTQは各重みをスカラー量子化し、代理ヘッセ行列で誤差を後続列へ補償する。GPTVQはこの逐次補償構造を保ったまま、量子化単位を複数重みのベクトルとコードブックへ拡張する。したがって「コードブックを使うVQ」と「層出力誤差を考慮するGPTQ」の接続が中心的な新規性である。

AQLMも多次元コードブックによる極低ビット圧縮を行うが、GPTVQはコードブック初期化、ヘッセ重み付き逐次更新、モバイルCPUで復号しやすい配置に重点を置き、層内の高価なブロック微調整を省く。その結果、最高精度だけでなく圧縮時間と実機デコードも評価対象にする。

## 限界・実装上の注意

VQは保存形式であり、低bpvそのものが推論高速化を保証しない。演算前の表引き・復号が必要なので、計算律速の大バッチや高速DRAM環境では容量削減の利得が小さくなる可能性がある。論文の実測高速化はSnapdragon X Elite上のLlama 3 8Bデコード条件で確認されたものである。

高次元VQほど品質は良くなりやすいが、コードブックが大きくなりキャッシュ局所性やベクトル化が悪化する。モバイル向けには精度最良設定ではなく、復号器が扱いやすい次元・コードブックを選ぶ必要がある。

またAQLMのブロック微調整付き構成には一部品質で負ける。GPTVQは圧縮時間を抑える代わりに、層内で量子化済み重みを再最適化する強い補正を行わない。どちらを選ぶかはオフライン圧縮コストと最終品質の交換条件になる。
