## 概要

QServeは、クラウド型の大規模言語モデル（LLM）サービングにおいて、重みを4ビットへ量子化してもGPU上の実行速度が期待ほど上がらない問題を、量子化アルゴリズムと推論カーネルの協調設計によって解く研究である。提案するQoQは重み4ビット、活性値8ビット、鍵・値キャッシュ4ビットのW4A8KV4形式を採用し、GPU上では8ビット整数のTensor Coreを使って高速に行列積を行う。4ビット重みの復元をレジスタ内で並列化し、低速なCUDAコア上の逐次処理を減らすことが中核である。

既存のW4A16は重み転送を削減するが、行列積の内側ループで4ビット重みを16ビット浮動小数点へ戻す必要がある。W4A4は理論上さらに高い演算能力を利用できるものの、細粒度グループ量子化の部分和を浮動小数点へ変換する処理が内側ループへ入り、CUDAコアの低い処理率がボトルネックになる。論文はこの量子化解除の費用が20〜90%に達する条件を示し、ビット数を減らすだけではサービング処理率を改善できないことを説明する。

QoQは段階的グループ量子化で4ビット重みを8ビット整数へ効率よく復元し、SmoothAttentionでKV4の精度低下を抑える。QServe実行系は重みを計算順に並べ替え、レジスタ内4-way並列復元とKV4注意カーネルを使う。A100上でTensorRT-LLMの最良構成比1.2〜2.4倍、L40S上で1.5〜3.5倍の最大スループットを報告した。これは量子化形式だけの比較ではなく、アルゴリズムとGPU実行系を一体で設計した結果である。

## 問題設定：低ビット化とGPUの実測性能が一致しない

クラウド型LLMのデコードでは、多数の要求をまとめて処理するため、バッチサイズによって計算の律速が変わる。小さなバッチでは重みの読み込み量が支配的となり、重みを4ビットにするW4A16が有利になりやすい。一方、大きなバッチでは行列積が演算律速となり、8ビット整数Tensor Coreを利用できるW8A8が速くなる場合がある。論文のA100ルーフライン解析では、両者の理論的な有利領域がバッチサイズ約78付近で入れ替わると示される。

W4A8は重み転送の少なさとINT8 Tensor Coreの演算能力を組み合わせる候補である。しかし4ビット重みを8ビット演算へ供給するための復元処理が内側ループを塞ぐと、理論上の利点は実測性能へ現れない。さらにデコード中の注意演算は過去KVの読み出しが支配的なので、KVを4ビットにして転送量を減らしても、復元処理やカーネル構成が悪ければ速度改善にならない。

W4A4はINT4 Tensor Coreの理論演算能力が高い一方、グループごとの尺度を適用するためにINT32部分和をFP32へ変換する必要がある。論文はA100などでCUDAコアの浮動小数点演算がINT4 Tensor Coreのピーク演算能力に比べて非常に低いことを指摘し、部分和の変換1回が多数のTensor Core演算に匹敵する負担になり得ると説明する。しかもFP32とINT32の部分和を同時に保持するとレジスタ圧迫が増え、同時に走らせられるワープ数が減る。

このためQServeの問題設定は、単に「より低いビット幅を選ぶ」ことではない。重みロード、量子化解除、行列積、KV読み出し、注意カーネルまでの経路で、低速な逐次処理をどれだけ避けられるかが実測性能を決める。

## 手法：QoQとQServeの協調設計

### 1. W4A8KV4を選ぶ理由

QoQは重み4ビット、活性値8ビット、KVキャッシュ4ビットを組み合わせる。重み4ビットはモデル重みの帯域要求を減らし、活性値8ビットはINT8 Tensor Coreで高い行列積性能を得るために使う。KV4はデコードの注意演算で読み込む過去の鍵・値を圧縮する。三つのビット幅は異なるボトルネックを解くために選ばれている。

論文のルーフライン解析では、デコードのGEMMにおける演算強度はバッチサイズmに概ね比例する。小さなmでは重み転送が支配的、大きなmでは演算器が支配的となる。W4A8はW4A16の低帯域とW8A8のINT8演算を組み合わせるため、幅広いバッチサイズで理論的に有利な領域を持つ。ただし、復元処理をTensor Coreの演算と効率よく重ねられることが前提である。

### 2. 保護範囲付き段階的グループ量子化

QoQは最初に重みをチャネル単位の対称8ビット整数へ量子化し、その中間整数をグループ単位の4ビット値へ量子化する。最初の8ビット量子化では通常の−127〜127全域を使わず、保護範囲[−119,119]へ制限する。これにより4ビットから8ビットへ戻す際の演算で値が8ビットの範囲を超えることを避け、飽和補正を省略できる。

この二段階の構成は、グループごとの精度を保ちながら、実行時には8ビット整数のまま行列積へ供給することを狙う。復元時に必要な尺度・ゼロ点を扱う順序も重要で、論文は乗算と減算の順序を変更して、減算を積和の後段へ移す。逐次内側ループに複雑な復元処理を入れないことで、Tensor Coreの処理率を維持しやすくする。

### 3. レジスタ内4-way並列復元

4ビット重みは複数要素が1バイトへ詰め込まれているため、GEMMで使う前に取り出す必要がある。QServeは4個のINT4重みを同時に復元する4-wayレジスタ内並列処理を採用し、逐次的なビット演算の回数を減らす。保護範囲のおかげで飽和処理を挟まずに8ビット表現へ展開できるため、CUDAコアの低速な補正命令を削減できる。

これは単にレジスタを増やして高速化する方式ではない。部分和をINT32とFP32の二組で保持するW4A4方式とは異なり、復元処理を重み側へ寄せてレジスタ圧迫を抑える。行列積の内側ループが長いLLMでは、1回当たりの復元費用の削減が繰り返し回数に応じて大きな効果を持つ。

### 4. 計算順に合わせた重み配置

通常の4ビット重みをメモリから取り出す際、計算タイルが必要とする順序と圧縮配置が一致しないと、ポインタ演算や不規則な読み込みが増える。QServeはモデル重みが推論中に固定されている点を利用し、計算で使う順序に合わせてオフラインで重みを並べ替える。実行時のアドレス計算を減らし、CUDAコアの仕事を行列積に直接関係する処理へ集中させる。

この変換はモデルの準備時に一度行うため、同じモデルを繰り返しサービングする場合に費用を償却できる。ただし新しい重みを頻繁に読み込む環境や、複数の実行カーネルを使い分ける環境では、重み配置の変換と管理の負担が追加される。

### 5. SmoothAttentionによるKV4の精度維持

鍵・値キャッシュを4ビット化すると、特に鍵Kのチャネル外れ値が注意スコアの誤差を増やす。SmoothAttentionは鍵のチャネルごとの大きさをスケーリングして外れ値を抑え、その逆変換を問い合わせQ側へ移す。QとKの内積が保たれるように変換することで、量子化しにくい鍵を扱いやすくする。問い合わせ側はKVキャッシュとして保存しないため、KV4の容量削減を損なわずに精度を改善できる。

値Vは鍵ほど強いチャネル外れ値を示さないため、同じ変換を一律に適用しない。KV4の効果はキャッシュ容量を減らすことだけではなく、デコード時のメモリ帯域要求を下げることにある。QServeは低ビットKVを扱う注意カーネルも設計し、復元処理を含めても注意演算がメモリ律速の領域にとどまるようにする。

### 6. 量子化と実行カーネルの役割分担

QoQは量子化精度と復元しやすい整数表現を定義し、QServeはそれをGPUで効率よく実行する。段階的量子化だけでは重みの転送量が減っても復元費用が残り、カーネルだけを改善しても低ビット化の誤差が大きければ実用にならない。SmoothAttention、重み並べ替え、レジスタ内並列復元、KV4注意を組み合わせることで、モデル品質とサービング処理率を同時に扱う。

## 評価条件

論文はA100とL40Sで複数のLlama系列およびQwen1.5系列を評価し、TensorRT-LLMのFP16、W8A8、W4A16の最良設定、AtomとQuaRotのW4A4などを比較した。基本的なサービング要求は入力1024トークン、出力512トークンであり、最大スループット、メモリ利用、困惑度、ゼロショット精度を評価する。

| 項目 | 条件 |
|---|---|
| GPU | NVIDIA A100、NVIDIA L40S |
| 対象モデル | Llama系列、Qwen1.5系列など |
| 基本入力・出力 | 1024トークン入力、512トークン出力 |
| 提案形式 | W4A8KV4 |
| 主要比較 | TensorRT-LLM FP16/W8A8/W4A16、Atom、QuaRot |
| 処理率 | 最大サービング出力トークン/秒 |
| 品質 | 困惑度、ゼロショット精度 |
| 重要な実装条件 | INT8 Tensor Core、レジスタ内復元、KV4注意 |

論文の実測比較では、各比較方式にとって最良の設定を選ぶため、単純にFP16だけを弱い比較対象にしていない。大きなバッチでの処理率は、小さなバッチの1要求当たり遅延と異なる指標であり、最大スループットの改善率をすべての要求での応答時間短縮率として解釈してはならない。

## 評価結果

### 1. TensorRT-LLMに対する最大スループット

| 対象モデル・GPU | TensorRT-LLMの最良構成比 | 解釈 |
|---|---:|---|
| Llama-3-8B / A100 | 1.2倍 | 小型モデルでも量子化解除費用の削減が有効 |
| Llama-3-8B / L40S | 1.4倍 | GPUが変わっても利得を維持 |
| Qwen1.5-72B / A100 | 2.4倍 | 大型モデルで重み転送と計算の削減効果が大きい |
| Qwen1.5-72B / L40S | 3.5倍 | 帯域・演算資源の組合せで大きな改善 |
| 複数モデルのA100全体 | 1.2〜2.4倍 | 最良TensorRT-LLM構成との比較範囲 |
| 複数モデルのL40S全体 | 1.5〜3.5倍 | L40Sでは比較的改善幅が大きい |

論文要旨と本文の結果であり、各倍率はモデルとGPUの条件に依存する。たとえば3.5倍はQwen1.5-72BのL40Sにおける代表値であり、すべてのモデルが3.5倍速くなるという主張ではない。論文はAtomやQuaRotのW4A4方式に対してもA100で約2.5〜2.9倍の処理率を報告し、理論上のINT4 Tensor Core性能だけでは実行時の優劣が決まらないことを示す。

### 2. 量子化解除が内側ループを塞ぐという負の結果

論文の図2では、A100でLlama-2-7Bを動かしたとき、W4A4のAtomやQuaRotがTensorRT-LLMのW8A8より遅い例が示される。4ビットの理論演算能力は8ビットより高いが、グループ量子化の部分和をFP32へ戻す処理が内側ループに入ると、CUDAコアの処理率がボトルネックになる。論文は復元費用が20〜90%に達する条件を示し、低ビット化だけでは実測速度が上がらない理由を明確にした。

さらに部分和を複数精度で保持するとレジスタ圧迫が増え、GPUが多数のワープを同時実行して待ち時間を隠す能力が下がる。QServeは重み側をINT8へ復元し、Tensor Coreの積和を維持することで、この逐次部分の負担を減らす。性能差はビット幅の単純な比較ではなく、復元処理をどの演算器・どのループで実行するかによって生じる。

### 3. バッチサイズによる最適形式の違い

論文のルーフライン解析では、A100のデコードGEMMでW4A16とW8A8の理論的な優位がバッチサイズ約78で入れ替わる。小さいバッチではW4A16が重み転送量の少なさで有利、大きいバッチではW8A8がINT8 Tensor Coreの処理能力で有利になる。W4A8は両者の長所を組み合わせる設計であり、復元処理が十分に軽ければ幅広いバッチで高い処理率を期待できる。

ただしこの境界はA100の演算性能と帯域、行列の形状に基づく解析であり、すべてのGPUで78という値が普遍的に成立するわけではない。実機での最適な形式は、GPU世代、バッチサイズ、モデルの層構成、注意とGEMMの時間比率によって変わる。

### 4. KV4注意の役割

デコードの注意計算は過去KVを読み込むため、長文脈ではメモリ帯域が支配的になりやすい。論文はバッチ64の条件で注意が総実行時間の50%以上を占める例を示し、KV4の帯域削減がサービング全体へ大きく影響し得ることを説明する。KV8からKV4へ変更すると理論上は転送量が半分になるが、復元処理が増えるため実測速度が同じ倍率になるとは限らない。

SmoothAttentionはKV4の精度を保つための手法であり、KV4注意カーネルは帯域削減を実行時間の改善へ変えるための手法である。両者の役割は異なる。単にKVを4ビットで保存するだけでは、GPUの注意カーネルが十分に効率化されていなければ大きな処理率改善は得られない。

### 5. 精度とサービング費用の注意点

論文はLlama-2の7B、13B、70Bなどで困惑度とゼロショット精度を評価し、FP16からの品質低下を小さく抑えたと報告する。ただし低ビット化による誤差が完全にゼロという意味ではなく、モデルや校正データによって変わる。推論コストについてはL40S上のQServeがA100上のTensorRT-LLMより高い処理率を得る構成を示し、当時のハードウェア価格前提でコストを約3分の1へ削減できると主張する。

この費用削減は論文が置いたGPU単価・処理率・モデルの条件に依存する。現時点のクラウド価格、GPU供給、電力料金、利用率、運用費用を含む総所有費用が常に3分の1になることを保証するものではない。実際の配備判断には、対象モデルの品質、ピークと平均の要求数、GPUの価格と運用費用を別途確認する必要がある。

## 既存研究との差

AWQやGPTQなどは重みの量子化誤差と容量削減に重点を置く。AtomやQuaRotはさらに低いビット幅での演算を目指すが、グループごとの復元処理がGPUの内側ループへ入ると理論性能を発揮しにくい。QServeは量子化アルゴリズムをGPUの実行経路に合わせて設計し、W4A8KV4、段階的グループ量子化、SmoothAttention、重み並べ替え、レジスタ内復元、KV4注意を一体として最適化する。

QServeの特徴は「4ビットにすれば速い」ではなく、「低速CUDAコアの仕事を減らしてTensor Coreの演算を妨げない」ことである。大きなバッチのクラウドサービングを主要な対象とするため、少数要求のローカル推論や小型GPUで同じ改善率を得るかどうかは別問題である。

## 限界・未評価事項

第一に、評価は主としてA100とL40SのGPU特性に基づく。INT8 Tensor Coreの性能、CUDAコアの相対処理率、メモリ帯域、レジスタ容量が異なるGPUでは最適な量子化形式とカーネルが変わり得る。Windows上のllama.cpp、CPUオフロード、他ベンダーGPUへそのまま適用できることは示されていない。

第二に、専用の重み配置、量子化尺度、校正、レジスタ内復元、KV4注意カーネルが必要であり、単に4ビットの重みファイルを用意するだけではQServeの速度は再現できない。モデル準備時のオフライン変換や、実行時に異なるモデル形状へ合わせる管理費用もある。

第三に、低ビット化に伴う精度低下は完全には消えない。SmoothAttentionや段階的量子化で抑えられるが、対象モデル、タスク、校正データによって品質が変化する。最大スループットの改善率を応答品質や単一要求の遅延改善率と混同してはならない。

第四に、論文のコスト比較は当時のGPU価格と配備条件に依存する。最新のGPU世代、異なるクラウド料金、モデルの混在負荷、長文脈の要求分布では、同じ費用削減が得られるとは限らない。実配備では、平均要求数・ピーク要求数・KV容量・GPU使用率を含めて再評価する必要がある。
