# Huff-LLM: End-to-End Lossless Compression for Efficient LLM Inference

## 概要

Huff-LLMは、言語モデルの重みを**数値を一切変えずに圧縮**し、保存先から推論演算器の直前まで圧縮状態を維持する方式である。一般的な低ビット量子化は重みの値を丸めるため、平均正答率が近くても個々の出力が変わることがある。Huff-LLMは浮動小数点重みのビット列を可逆なハフマン符号で表し、演算器へ渡す直前に元の16ビット値を完全復元する。モデルのパラメータ値が変わらないため、量子化に起因する推論品質の変化を導入しない。

通常の可逆圧縮では復号処理が重く、圧縮した重みをDRAMに置いても、推論前に大きな行列を展開するために遅延が増えかねない。著者らは重みの符号・指数・仮数を小さいビット群へ分割し、各群を独立にハフマン符号化する。圧縮されたままの重みをDRAMとオンチップ重みバッファへ置き、シストリック配列またはベクトル積和回路の入力で小型復号器が毎サイクル元の重みを再構成する。この**圧縮状態のまま計算器直前まで運ぶ**設計が、単なるダウンロード容量削減との差である。

Llama、Qwen、OPT、Vicunaの重みで容量削減を測定し、専用推論回路のモデル化で最大約32%の重み容量削減、最大約31%の推論遅延短縮、最大約26%のエネルギー削減を報告する。これらの遅延・エネルギー値は主にシストリック配列やSimba型回路の**シミュレーション結果**であり、既存のGeForce GPU上のCUDA実行速度を測ったものではない。

## 問題設定：可逆圧縮が推論を遅くしがちな理由

重み量子化はモデルのメモリ使用量と転送バイト数を減らせる一方、重み値を変更するため、特定の言語や課題で出力が変わる可能性がある。可逆圧縮なら元のFP16/BF16のビット列を完全復元できるが、一般的な圧縮方式は復号処理が複雑で、演算器へ十分な速度で重みを供給できない。圧縮データをDRAMに保持しても、レイヤー実行前に一括展開すれば復号時間が追加され、オンチップバッファの容量も展開後の重みに使われる。

シストリック配列では各演算素子へ重みと活性値が規則的に流れる。重みの復号器が1サイクルでも停止すれば、配列の空白が広がり演算効率を下げる。したがって可逆圧縮を実際の高速化へ結び付けるには、圧縮率だけでなく、**演算器の要求速度に合わせて元の16ビット値を連続供給できる復号器**が必要である。

既存のハフマン圧縮研究はモデルの転送やダウンロード費用を下げるものの、推論時には展開後の重みをメモリへ置く場合があった。別の方式は圧縮重みをメモリに残すが、層ごとの展開によって推論が遅くなる。Huff-LLMは重みのビット分布を利用して符号化対象を小さく分け、専用回路の比較器で復号を高速化することで、圧縮による帯域節約を演算器の待ち時間削減へ直接結び付ける。

## 手法：小ビット群のハフマン符号化と演算直前の復元

### 16ビット全体を一つの符号表にしない

ハフマン符号は出現頻度の高い値へ短い符号語を割り当てる可逆符号である。FP16の16ビット全体を一つの値として扱うと、取り得る記号数が大きく、1サイクル復号のための比較回路が大きくなりすぎる。論文は、FP16重みの符号1ビット、指数5ビット、仮数の上位5ビット、下位5ビットという**1-5-5-5分割**を採用する。符号ビットはそのまま保持し、残り三つの5ビット群を独立にハフマン符号化する。

Llama-3-8Bの例では16ビット全体の理論エントロピーが約10.54ビット/重み、1-5-5-5分割の各群の合計エントロピーが約10.61ビット/重みである。つまり符号化対象を小さく分けても、理論上の圧縮率はほとんど犠牲にならない。8-8分割でもエントロピーは近いが、8ビット記号の単一サイクル復号回路は大きく、実装上の利点が乏しい。小さい符号表を並列に動かせる5ビット分割が、圧縮率と回路面積の折衷点になる。

### BF16では異なる分割を選ぶ

BF16はFP16と指数・仮数のビット配分が異なるため、同じ分割が最適とは限らない。論文は**1-4-4-7分割**を使い、符号1ビットと圧縮効果の小さい仮数下位7ビットを原則そのまま残し、指数に対応する4ビット群を符号化する。BF16では圧縮可能な偏りがFP16の仮数から指数側へ移る傾向があると報告される。これにより、FP16では圧縮しにくいOPTやVicunaでもBF16なら比較的近い圧縮率が得られる。

圧縮はオフラインで一度実施し、推論中に重みを再学習したり値を丸めたりしない。圧縮ファイルは保存領域から主記憶、オンチップの重みバッファまで小さいまま移動する。演算素子が必要とする瞬間だけ元の16ビット値を復元するため、圧縮率がメモリ容量と転送帯域の両方に作用する。

### 内容照合メモリを用いた1サイクル復号器

5ビット記号のハフマン復号器は、符号語と元記号の対応を**内容照合メモリ（Content Addressable Memory、CAM）**に保持する。論文の設計では32個の符号表項目があり、各項目は可変長符号語、元の5ビット記号、符号語長を持つ。圧縮ビット列を保持するレジスタと読み出し位置Sから、最大符号長に対応する候補ビットをCAMへ与え、一致した項目の元記号を出力する。復号した符号語長LだけSを進め、必要な追加ビットをバッファから補充する。

この回路は毎サイクル5ビット群の元記号を一つ出力できるように設計される。FP16の三つの5ビット群を並列復号し、非圧縮の符号ビットと連結して元の16ビット重みを再構成する。重要なのは、可変長符号を一般CPUで順次復号するのではなく、限られた32記号の比較回路へ置き換えた点である。復号器の遅延が重み供給の周期を超えなければ、演算器へ空白を挿入せずに済む。

### シストリック配列とSimba型回路への統合

シストリック配列では重みバッファと演算素子列の間に復号器列を挿入する。重みバッファは圧縮した三つの5ビット群を別バンクへ格納し、各バンクから符号列を復号器へ送る。復号後の元のFP16値は従来と同じ積和演算へ渡される。したがって配列内部の演算方式を変えず、重みの供給経路だけを置き換える。

Simba型のベクトル積和回路でも、分散重みメモリとベクトル演算器の間に同じ復号器を置く。重みがオンチップへ入った後も圧縮状態を保つため、同じ容量のバッファにより多くの重みを格納でき、DRAMからの読み込み回数や帯域要求を減らせる。復号器が毎サイクル元重みを出力できるという設計前提が成立する範囲では、圧縮そのものによる演算器の停止を避けられる。

## 評価：圧縮率と専用回路の遅延・電力

### 評価環境と測定の種類

| 項目 | 論文の条件 |
|---|---|
| 重み | FP16/BF16のLlama、OPT、Qwen、Vicuna系列、約3B〜13B |
| シストリック配列モデル | 128×128演算素子、1GHz、16nm想定、16TOPS、重みバッファ16KB、DRAM 64/128GB/s |
| Simba型モデル | 16演算素子、2GHz、16nm想定、4TOPS、重みバッファ32KiB、DRAM 64/128GB/s |
| 遅延・エネルギー | SCALE-Sim改造、Timeloop/Accelergy等を用いたアーキテクチャ評価 |
| 回路面積 | Verilogの5ビット復号器・演算素子をGF12プロセスで論理合成 |
| 入力長の代表値 | ARC-Easy平均42トークン、MMLU平均92、Winogrande平均25 |

論文の推論遅延評価はベンチマークの実際の問題文をすべてモデルへ流して正答を採点したものではない。各ベンチマークの**平均入力トークン数**を性能モデルの負荷条件に使い、モデルの重み行列の演算を評価する。可逆圧縮なので元の重みを正しく復元できる限り、量子化による正答率変化は設計上生じないが、これは異なるハードウェア実装での数値演算順序まで完全一致すると実証したものではない。

### FP16とBF16の容量削減

| モデル | FP16の平均ビット/重み | FP16圧縮比 | BF16の平均ビット/重み | BF16圧縮比 |
|---|---:|---:|---:|---:|
| Llama-3-8B | 10.96 | 1.46倍 | 11.68 | 1.37倍 |
| Llama-2-13B | 10.88 | 1.47倍 | 11.59 | 1.38倍 |
| OPT-6.7B | 13.78 | 1.16倍 | 11.68 | 1.37倍 |
| Qwen-2.5-7B | 10.96 | 1.46倍 | 11.68 | 1.37倍 |
| Vicuna-7B | 13.68 | 1.17倍 | 11.59 | 1.38倍 |

FP16のLlamaやQwenは約10.9ビット/重みまで減る一方、OPTとVicunaでは約13.7ビットにとどまる。これは学習済み重みのビット分布が系列によって異なるためである。BF16ではモデル間の圧縮率が約1.37〜1.38倍にそろう傾向がある。要旨の「最大32%削減」は最大条件での値であり、すべてのFP16モデルが32%減るわけではない。

### 遅延とエネルギーの代表値

表6では重み固定型の回路において、Llama系列の推論遅延短縮は約26〜31%、OPT系列は約13〜15%と報告される。例えばMMLUの64GB/s条件では、Llama-3-8Bのシストリック配列で29.40%、Simba型で31.33%の遅延削減、OPT-13Bではそれぞれ14.77%、14.05%である。同じ方式でも圧縮しにくい重みでは転送量があまり減らず、速度改善も小さい。

表7のエネルギーではLlama系列が約16〜26%、OPT系列が約3〜10%の削減となる。MMLUの128GB/s条件でLlama-3-8Bのシストリック配列は25.54%、Simba型は19.33%の削減であり、重みバッファが小さくDRAM転送へ依存する回路ほどエネルギー削減が大きくなりやすい。これらの値は圧縮後の重み転送と専用復号器の費用を組み込んだシミュレーションの結果であり、GeForce GPUの消費電力実測値ではない。

### 復号器の面積と高帯域条件

5ビット復号器をVerilogで記述しGF12で合成した結果、単体復号器の面積は約1199.3平方マイクロメートル、比較した演算素子は484平方マイクロメートルである。128×128シストリック配列の演算部に対する追加面積は**6.13%**と報告される。これはチップ全体の面積増加率ではなく、オンチップバッファなどを分母に含めれば割合は小さくなるという説明である。論文の概要で「約6%」と丸められる場合も、具体値6.13%と矛盾しない。

DRAM帯域を256GB/sへ増やしたシストリック配列では、圧縮前でも演算器のピーク性能に達するため、圧縮しても推論遅延が短くならない条件がある。一方、同じ条件でもDRAMアクセス回数が減るため、Llama-3.2-3BのMMLU負荷では約24%のエネルギー削減を報告する。**速度改善と電力改善は別の律速に依存する**という重要な負の結果である。

## 限界、未検証事項と適用先

Huff-LLMの最大の制約は、**小型ハフマン復号器を組み込んだ専用ハードウェアが必要**な点である。論文の性能改善はシストリック配列・Simba型回路のモデル化と試作に基づき、一般的なCUDAカーネルをそのまま置き換える方法ではない。RTX系GPUへ圧縮ファイルを渡すだけでは、演算器直前で1サイクル復号する機構がないため、同じ遅延・電力改善は得られない。

圧縮率は学習済み重みのビット分布に依存し、FP16のOPTやVicunaではLlamaやQwenより小さい。重み以外のKVキャッシュ、活性値、ランタイムの作業領域を圧縮するわけではないため、モデル全体のGPUメモリ削減率を重み削減率と同一視できない。符号表や復号器の追加費用、符号列の不規則な読み出し、圧縮済みバッファの配置が実機の速度へ与える影響は回路構成ごとに異なる。

可逆性は重みの元ビット列が復元されることを保証するが、ハードウェアの浮動小数点演算順序や丸めモードが変われば最終出力の完全一致は別途確認が必要である。論文は推論品質を量子化ベンチマークのように再測定する必要がないという設計上の立場を取る一方、異なるアクセラレータ間の数値再現性を無条件に保証しているわけではない。

また、DRAM帯域が十分高い条件では圧縮による転送削減が遅延改善へつながらない。低帯域の端末向けアクセラレータで効果が大きい一方、高帯域GPUや計算律速の負荷で同じ改善率を期待すべきではない。モデルを更新するたびにオフライン符号化が必要であり、符号表や圧縮率の管理も発生する。これらの前処理と専用回路の開発費は、推論時の容量・帯域節約とは区別して考える必要がある。

## 既存研究との差とまとめ

量子化や枝刈りが重みの値または数を変更するのに対し、Huff-LLMは元のFP16/BF16値を保持する。クラウド保存だけを圧縮する方式や、レイヤーごとに主記憶で展開する方式に対しては、**オンチップ重みバッファまで圧縮状態を保ち、演算器直前で止まらず復号する**点が新しい。小ビット群へ分けた符号化、32項目CAMによる復号、シストリック配列とベクトル回路への統合が、圧縮率を実際の帯域・遅延・エネルギー削減へ変えるための一連の設計である。効果はメモリ帯域律速と重みの圧縮可能性に依存し、汎用GPUでの即時適用ではなく専用推論回路の設計指針として読むのが適切である。
