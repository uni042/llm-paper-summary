# QSVD：Q/K/Vの共同低ランク化と量子化でVLMのKV状態を圧縮する

## 概要

QSVDは、画像と文章を同時に処理する視覚言語モデル（Vision-Language Model; VLM）の注意層で、問い合わせ（Query; Q）・鍵（Key; K）・値（Value; V）の射影重みを**別々に圧縮するのではなく結合して低ランク分解する**手法である。通常の多頭注意（Multi-Head Attention; MHA）ではQ/K/Vそれぞれの重み行列を使い、過去の各トークンのKとVを独立に保存する。QSVDはQ/K/Vが共有する低次元の射影を一回計算し、その中間表現だけを保存する。必要に応じて中間表現からKとVを復元するため、重み容量と鍵・値キャッシュ（KV cache）の双方を削減できる。

手法は三段階から成る。第一にQ/K/Vの重みを横に連結して特異値分解（Singular Value Decomposition; SVD）し、共通の低次元射影を得る。第二に各層の特異値が損失へ与える影響を推定し、同じ総ランク予算でも重要な層へランクを多く割り当てる。第三にSVD後の中間活性値に現れる外れ値を直交変換と層別のβ調整で抑え、重みと活性値をW8A8、W8A4、W4A4へ量子化する。

最も目を引く最大13.1倍という高速化は、**RTX 4070 12GB上のLLaVA-v1.5 7B、バッチ1、4Kトークン**での測定である。FP16の基準構成はVRAMに収まりきらずCPUへの一部退避を必要とする一方、QSVDのW8A8構成は退避を避けられる。このため13.1倍は低ランク行列積そのものの演算高速化倍率ではなく、GPU内にモデルと状態を収めたことによる転送回避を含む端から端までの改善である。RTX A6000上で行った精度評価とは実験環境が異なる。

## 問題設定：重み圧縮だけではKVが残る

通常の注意層で隠れ次元をE、入力長をLとすると、単純化した一頭のQ/K/V重みの合計は3E²要素、KとVの保存量は2LE要素となる。各重み行列を別々にSVDすれば重みは減るが、KとVのための低次元中間表現を別々に作る必要があり、共通部分の演算を共有できない。視覚入力が多数のトークンへ展開されるVLMでは、画像トークンと文章トークンを同じ注意系列へ置くため、入力長に比例するKV保持量が端末推論の制約となる。

著者は、独立SVDではK/Vの中間状態が2rL、Q/K/Vの分解重みが6rEとなるのに対し、共同SVDならそれぞれrL、4rEに減らせると整理する。これは同じランクrを使う場合の**表現上の要素数**の比較であり、実際のバイト数は精度形式、メタデータ、レイヤ数、KV管理方式に依存する。また、ランクを小さくしすぎると視覚質問応答の正答率が下がるため、どの層のどの特異値を残すかが重要になる。

さらに、低ランク化した中間表現C_qkvを量子化すると、元の入力活性値Xとは異なる外れ値分布が現れる。単純に入力Xだけを平滑化しても、SVDで作ったC_qkvの大きな値が低ビット量子化の誤差を増やす。従って、低ランク化と量子化を独立の後処理として重ねるのではなく、両者の中間表現を考慮して変換を設計する必要がある。

## 手法

### 1. Q/K/Vを結合した共同SVD

§3.1では、W_q、W_k、W_vを横に連結したE×3E行列を作り、ランクrで分解する。共通の下向き射影W_d（E×r）と、Q/K/Vそれぞれの上向き射影W_u,q・W_u,k・W_u,v（各r×E）を得る。入力XはW_dへ一度だけ掛けられ、C_qkv=XW_dを生成する。Q、K、VはそれぞれC_qkvと対応する上向き射影の積で再構成する。過去トークンの状態としてはKとVの完全なベクトルではなくC_qkvを保存する。

この方式の重み要素数とQ/K/V生成の積和演算量は、それぞれ4rE、4LrEとなる。元の3E²、3LE²より小さくする条件はr<0.75Eである。独立SVDの6rE、6LrEと比較すると、共通の下向き射影によって重み・計算の重複が減る。KV側も独立SVDの2rLに対してrLの中間表現だけを保持する。ただし注意の計算時にK/Vを復元する上向き射影の費用は残るため、キャッシュの要素数削減をそのまま全復号時間の削減率とは扱わない。

### 2. 層横断の損失感度に基づくランク配分

§3.2は、特異値が大きい順に残すだけでは下流の正答率を十分保てない問題を扱う。特異値σ_iと左右特異ベクトルu_i、v_iの積が作る一つのランク成分を除いたとき、損失がどれだけ変化するかを勾配G_Wとの内積で近似する。校正データ上でその変化の二乗平均を計算し、各特異値の重要度を得る。これは対角Fisher情報に近い損失感度の推定であり、単に特異値の絶対値を並べる方法とは異なる。

全ランク成分について差分行列ΔW_iを実体化すると層当たりO(E³)の記憶が必要になる。著者はσ_i²[UᵀG_WV]²_iiという変形を使い、重要度計算時のメモリをO(E²)へ削減する。各層の特異値重要度を一つの集合へ集めて全体で順位付けし、総ランク予算kの上位だけを残す。このため、重要度の低い層を一律に圧縮するのではなく、精度への影響が大きい層へランクを配分できる。校正データの勾配を必要とする点は、重みだけで変換する手法より費用が大きい。

### 3. 二つの直交変換とβ最適化による低ビット化

§3.3では入力Xと中間表現C_qkvの双方に現れるチャネル別外れ値を扱う。入力側に直交変換H1、中間側にH2を挿入し、対応する重みへ逆変換を畳み込むことで、浮動小数点の線形写像を保ちながら量子化対象の分布を平滑化する。SVDの特異値を下向き・上向き射影へ分ける指数β（0≤β≤1）も重要で、下向き射影にΣ^βを掛けると、特異値のばらつきがC_qkvの外れ値へ直接反映される。

そこで著者は校正データ上で、量子化前後の注意ブロック出力の二乗誤差を最小にするβを層ごとに学習する。βを固定すると低ビット化で一部チャネルが飽和しやすいが、層別調整により中間表現の値域を抑えられる。実装はW8A8（重み8・活性8ビット）、W8A4、W4A4を対象とし、活性値はトークン単位の対称量子化、重みはチャネル単位の対称量子化とクリッピング率の探索を用いる。量子化は言語モデルの注意・FFNだけでなく視覚符号化器にも適用される。

### 4. 何を保存し、何を復元するか

通常のKVキャッシュは各トークンのK/Vを保持する。QSVDはC_qkvを保持し、注意計算で必要なKとVを上向き射影から生成する。したがって「KVキャッシュを圧縮する」とは、保存形式を低次元へ変更する意味であり、復号のすべての演算からK/Vが消えるわけではない。保存量は入力長Lに比例してrLで増え、長文脈での節約率はr/Eの選び方に依存する。さらに低ビット化によってC_qkvのバイト数を減らせるが、逆量子化や射影演算の費用を含めて測る必要がある。

### 低ランク化のみの品質と費用

LLaVA-v1.5 13BのScienceQA-IMGはFP16で71.78%である。量子化なしのQSVD-noQではR1=60.0%、R2=22.5%で71.79%、R1=40.0%、R2=15.0%でも70.80%を保つ。比較の均一ランク配分は同じ強い圧縮条件で67.72%、Fisher情報を用いた配分は69.96%であり、特異値単位の層横断順位付けが効く。これは表3の同一予算比較であり、ランク削減率を無制限に上げても品質が一定という結果ではない。

LLaVA-Next 7BのScienceQA-IMGはFP16で69.51%で、QSVD-noQはR1=60.0%、R2=22.5%で69.91%、R1=40.0%、R2=15.0%で65.15%となる。モデルによって圧縮の許容量が異なる。VizWizではLLaVA-v1.5 13BのFP16が53.63%で、QSVD-noQのR1=60.0%、R2=22.5%が56.15%と上回るが、低ランク化が常に精度を改善する保証ではない。著者は低ランク化が幻覚を抑える可能性に言及するが、原因の確証は得ていない。

### 量子化後の品質比較

| モデル・条件 | 基準または比較方式 | QSVD | 読み取り |
|---|---:|---:|---|
| LLaVA-v1.5 7B、W8A8、ScienceQA | DuQuant 66.53%、QVLM 64.65% | 67.57%、R2=18.75% | DuQuant/QVLMのR2=50%より小さい中間状態 |
| 同モデルW8A4、ScienceQA | DuQuant 57.36%、QVLM 55.24% | 65.61%、R2=9.38% | 活性4ビットでも高い正答率 |
| 同モデルW4A4、ScienceQA | DuQuant 52.56%、QASVD 12.61% | 55.16%、R2=9.38% | 強い量子化でも比較方式より安定。ただしFP16の68.01%より低い |
| LLaVA-v1.5 13B、W8A8、ScienceQA | FP16 71.78%、DuQuant 69.66% | 72.12%、R2=18.75% | 同一データセットではFP16付近 |
| 同モデルW4A4、ScienceQA | DuQuant 65.80%、QASVD 20.35% | 65.82%、R2=9.38% | 量子化後の精度低下は残る |

ここでR2は元のKV中間表現に対する相対サイズであり、モデル重み、視覚符号化器、CUDA実行時バッファを含む総VRAM使用率ではない。表2は複数の精度形式とモデルを混ぜているため、例えばW4A4のScienceQAだけを抜き出して「全タスクでFP16同等」と要約してはいけない。特にLLaVA-v1.5 7BのW4A4ではFP16の68.01%に対し55.16%で、品質低下が明確に残る。

### 感度・構成要素除去と長文・幻覚評価

βの学習効果を調べた表4では、LLaVA-v1.5 7BのW4A4 ScienceQAはβ=0で54.53%、β=0.4で54.83%、β=0.8では6.09%へ崩れる。層別学習したQSVDは55.16%である。LLaVA-Next 7Bもβ=0で58.80%、β=0.8で15.12%、学習βで59.67%となり、特異値の分配が量子化時の外れ値に強く影響することを示す。これは低ランク分解そのものの有効性とは別の、低ビット化の感度評価である。

HRBench-4KではLLaVA-Next 13BのFP16が45.63%、QSVD-noQのR1=60.0%、R2=22.5%が44.88%、さらにR1=46.7%、R2=17.5%では43.88%である。LLaVA-v1.5 13BのFP16は39.12%、QSVD-noQのR1=60.0%、R2=22.5%が39.88%となる。幻覚に関するHallusionBenchではLLaVA-v1.5 13Bの総合値がFP16の26.70からR1=70%で30.30へ改善するが、これは特定評価指標の結果であり、他の質問応答・生成課題すべてで幻覚が減るという証拠ではない。

### RTX 4070 12GBでの速度

§4.4はLLaVA-v1.5 7B、バッチ1、4Kトークンの条件で、RTX 4070 12GB上のレイヤ単位の推論遅延を比較する。FP16基準とQSVD-noQはVRAM制約で一部をCPUメモリへ退避する。QSVD-noQのランク保持40%/30%は転送量を減らし最大2.1倍高速化する。さらにW8A8のQSVDでランク保持70%/50%とすると、CPU退避を完全に避けて最大13.1倍の高速化を報告する。従ってこの値はGPU内に収まるかどうかという**容量閾値を跨いだ結果**であり、十分なVRAMでFP16も完全常駐できるGPUで13.1倍を得た証拠ではない。

## 限界・未評価事項

第一に、QSVDは事後的な重み分解と校正に依存する。ScienceQA学習分割256サンプルの勾配から特異値の損失感度を計算し、βも同じく校正するため、完全なデータ不要・計算不要の変換ではない。校正分布と実際の利用分布が異なる場合、層横断ランク配分やβの最適値が変わる可能性がある。低ランク化で失われた情報を後段の量子化が自動的に回復する保証もない。

第二に、R1とR2は理論上のQKV射影重み・演算量と中間KV保存量の相対値であり、視覚符号化器、FFN、活性値、GPUカーネルの一時バッファを含む総メモリや実測速度を表す指標ではない。C_qkvからK/Vを復元する行列積も残る。KVキャッシュの要素数が9.38%となる条件を、モデル全体のVRAMが90.62%減ると読み替えてはならない。

第三に、低ビット化が強い条件では品質低下が残る。LLaVA-v1.5 7BのW4A4 ScienceQAはFP16より12.85ポイント低く、β=0.8では大きく崩壊する。直交変換と層別β学習は外れ値を緩和するが、すべてのモデルとタスクで無損失になるわけではない。長文入力、画像解像度、モデルの注意ヘッド構成によっても圧縮の影響は変わる。

第四に、RTX 4070 12GBの13.1倍はCPU退避を回避した条件に強く依存する。基準FP16が完全にVRAM常駐できる環境、異なるバッチや文脈長、ページ化KV管理、GPUの世代・ドライバが異なる環境では改善幅が変わる。主な精度評価はRTX A6000であり、4070の速度と全ベンチマーク精度が同一設定で測られたわけではない。

第五に、原著§5は注意層以外の全ブロックを共同最適化することを今後の課題としている。公開コードの存在は示されているが、あらゆるVLMアーキテクチャへの自動適用や既存推論エンジンへの無改造導入が保証されるわけではない。Q/K/Vの結合と中間KVの再構成は注意実装に影響するため、量子化済み重みファイルの置換だけでは再現できない可能性が高い。

## 既存方式との差と実装判断

ASVDやSVD-LLMがK/Vを個別に低ランク化するのに対し、QSVDはQも含めた共同下向き射影を持ち、保存する中間状態を一つにする。Paluや多頭潜在注意（Multi-Head Latent Attention; MLA）と同じく低次元KV状態を利用するが、既存VLMの重みへ事後的にSVDを適用し、校正データによるランク配分と量子化を組み合わせる点が異なる。量子化だけを行うDuQuantやQVLMとは、重みの低ビット化と中間KVの低ランク化を同時に扱う点で異なる。

12GB級GPUへの適用を考える場合、まず対象VLMのFP16またはBF16構成がVRAMから溢れてCPU退避しているかを確認する。退避が主要律速ならQSVDのような重み・KVの同時圧縮で容量閾値を越える効果が大きい。一方、すでに4ビット重み量子化で完全常駐し、KVも短い場合には、QSVDの追加分解と再構成の費用が上回る可能性がある。したがって比較対象は「無圧縮FP16」だけでなく、現行の重み量子化・KV量子化・オフロード構成を含めるべきである。
