# DSnoT：重みの値を変えずに疎マスクを交換する学習不要のLLM圧縮後補正

## 概要

DSnoT（Dynamic Sparse No Training）は、既存の枝刈り手法で疎化した大規模言語モデル（Large Language Model、LLM）を、勾配逆伝播も重み値の更新も行わずに改善する方法である。通常、重みの一部をゼロにすると密な元モデルと層出力がずれ、困惑度や下流課題の正答率が悪化する。SparseGPTは二階情報に基づいて残す重みを調整し、Wandaは重みの絶対値と入力活性の大きさで重要度を見積もるが、高い疎化率では品質劣化が大きい。DSnoTは、疎化済みモデルのどの重みを生かすかという二値マスクを反復的に交換し、元モデルとの出力再構成誤差を小さくする。

具体的には、現在ゼロ化されている重みから、復活させると出力誤差を減らせそうな一つを選び、同じ行で現在残っている重みから一つを削除する。復活候補の選択では入力活性の平均だけでなく分散を用い、削除候補では外れ値チャネルを守るためのWanda型重要度と誤差方向の条件を使う。各行でこの交換を繰り返しても、疎化率は一定で、元の重み値は変更されない。

LLaMA-V1-7Bの60%疎化では、WandaのWikiText-2困惑度10.69がDSnoT追加後10.22へ改善し、70%では88.84から62.05へ改善する。SparseGPTに追加した場合も60%疎化で10.41から9.65へ改善する。一方、疎化前の密モデルの困惑度5.68へ戻るわけではない。さらに、重みの非構造的疎化が一般のGPUで直ちに実測生成速度を改善するとは限らず、論文の主な証拠はモデル品質と枝刈り処理時間に関するものである。

## 背景と問題設定

大規模言語モデルをローカル装置へ載せるためには、重み容量と推論演算を減らす必要がある。量子化は重みのビット数を減らし、枝刈りは一部の重みそのものを取り除く。枝刈りには行・列・注意頭・層などをまとめて削除する構造的方式と、個々の重みを選んでゼロにする非構造的方式がある。後者は同じ疎化率で品質を保ちやすいことがあるが、通常の密行列積カーネルではゼロの乗算が残り、疎行列用カーネルの対応がなければ推論高速化は限定的である。

Wandaは、重みの絶対値とその入力チャネルの活性ノルムを掛け合わせて重みを順位付けする。大きな入力活性を受けるチャネルの重みを残しやすく、LLMの外れ値特徴を保護する。一方、各重みの局所的な重要度だけで削除集合を決めると、削除後の出力全体のずれを最小化するとは限らない。SparseGPTはヘッセ行列の逆行列に基づく補正を行うが、二階情報の計算・管理は高価である。

通常の疎化後の微調整では、残した重みを勾配で更新して品質を回復させる。大規模モデルでは追加データ、逆伝播、最適化器状態、長い学習時間が必要となる。動的疎学習（Dynamic Sparse Training、DST）は、学習しながら重みの削除と復活を行うが、勾配による重み更新自体は必要である。DSnoTの着眼点は、DSTの「マスクの交換」だけを取り出し、重み値を更新せずに密モデルの層出力へ近づけられるかという問題である。

## 手法

### 1. 密モデルの層出力を基準に再構成誤差を定義する

一つの線形層の重み行列をW、校正データの入力活性をA、二値マスクをMとする。密モデルの出力はWA、疎化後の出力は(M⊙W)Aであり、その差Δ=WA−(M⊙W)Aを再構成誤差とする。ここで⊙は要素積で、マスクが0の位置の重みは無効化される。疎化率pは、全重み数に対するマスク0の割合である。DSnoTはWの数値を固定したまま、Mの0と1を入れ替え、層出力の差を減らす。

入力活性AはC4の128系列・各2048トークンから得る。各出力行の再構成誤差は、その行の重みと同じ入力活性から計算できるため、行ごとに交換処理を独立に行える。全モデルの最終生成損失を直接最適化するのではなく、層ごとの密モデル出力を代理教師として使う。密モデルを保持し校正データで順伝播する費用は必要だが、勾配逆伝播は不要である。

### 2. 復活する重みを誤差の符号・活性平均・分散から選ぶ

既に削除されている重みを復活させると、その重みW_r,kと入力活性A_kの積が層出力へ再び加わる。現在の再構成誤差の平均が正なら、誤差を打ち消す向きに出力を増やす候補が望ましく、負なら逆向きの候補が望ましい。原著の式(2)は、現在削除されている位置を対象に、重みと入力活性の平均の積を入力活性の分散で割った値を、誤差の符号に応じて最大化または最小化する。

分散を入れる理由は、ある校正トークンでは大きく誤差を減らしても、別のトークンでは効果が逆転する不安定な重みを避けるためである。活性の平均だけを見ると、少数の極端な入力の影響で交換先を誤る可能性がある。入力分布の変動を考慮した選択は、平均的な再構成誤差を減らすと同時に、復活させた重みが特定の校正例だけへ過適合する危険を抑える設計となる。ただし分散を用いること自体が未知の入力への一般化を保証するわけではない。

### 3. 削除する重みには外れ値保護の制約を加える

重みを一つ復活させるだけでは非ゼロ重み数が増え、目標疎化率を維持できない。そのため同じ行の別の生存重みを一つ削除する。単純に「削除すれば再構成誤差が最も減る位置」を選ぶと、非常に大きな活性を持つ重要な重みを落とす可能性がある。原著はWanda由来の重要度|W_r,k|・||A_k||_2を使い、さらに削除による出力変化が現在の誤差を減らす向きであるという符号制約を付ける。

誤差平均が正の行と負の行では、削除可能な重みの符号条件を反転させる。こうして、残すべき大きな外れ値チャネルをむやみに切らず、かつ誤差の減少方向に寄与する候補から重要度の低いものを削除する。復活候補の選択と削除候補の選択を別の指標にすることが重要である。同じ誤差最小化指標を両方へ使う単純化は、原著の除去実験で性能が悪化している。

### 4. 交換を反復し、しきい値または最大回数で停止する

各行について、復活位置iと削除位置jを選び、M_r,iを1、M_r,jを0へ変更する。更新後の再構成誤差Δ_rを再計算し、誤差がしきい値εより小さくなれば停止する。収束しない行も無限に回さないよう、最大交換回数Tを設定する。主実験ではT=50、ε=0.1を用いる。各行は独立なので、実装上は終了した行の更新を無効にする二値指示子を用い、GPUで並列に処理できる。

初期の再構成誤差は密な行列積から計算するが、交換ごとの誤差更新は削除・復活した二つの重みの寄与を足し引きして行える。毎回全層の重みを再学習する必要はない。結果は新しいマスクMであり、残存重みの数と値は元の疎化モデルと同じ予算のままである。処理を層ごとに進める際には、前の層の疎化による活性変化が次の層へ伝わるため、層ごとの校正入力をどのモデルから取るかが再現上の重要条件となる。

### 5. N:M疎化では同一ブロック内で交換する

N:M疎化はM個の連続重みのうちN個だけを非ゼロにするパターンで、対応する疎行列演算器があれば実行時に利用できる。DSnoTを無制限に適用するとブロック内の非ゼロ数が崩れるため、復活位置と削除位置を同じブロックから選ぶ。これにより、2:4や4:8の制約を保ったままマスクの再配置ができる。ただし非構造疎化の場合より選択肢が少なく、同じ再構成誤差の改善を保証するわけではない。

## 評価

### 条件と比較方式

| 項目 | 原著の設定 |
|---|---|
| 対象モデル | LLaMA-V1（7B/13B/30B/65B）、LLaMA-V2（7B/13B/70B）、Vicuna-13B、OPT-13B |
| 校正 | C4の128系列、各2048トークン。主に各層を同じ疎化率で処理 |
| 装置 | NVIDIA A100 80GB。PyTorchとTransformersを使用 |
| 基準枝刈り | 重み絶対値（Magnitude）、SparseGPT、Wanda |
| マスク交換 | 最大50回、停止しきい値0.1。勾配・重み値の更新なし |
| 品質 | WikiText-2困惑度（低いほど良い）、PIQA・HellaSwag・StoryCloze・ARC等のゼロショット正答率 |
| 時間 | 論文の枝刈り時間表は各方式に共通する順伝播の費用を除外 |

困惑度は正解トークンにどれだけ高い確率を割り当てられるかを測る指標であり、小さいほど良い。ただし困惑度が下がったことだけで生成速度が速くなったり、すべての下流タスクが改善したりするとは限らない。実験は枝刈り済みモデルにDSnoTを追加するため、初期疎化方式の選択によって改善幅が異なる。

### 60%疎化での主結果

| モデル・方式 | DSnoTなしPPL | DSnoT追加PPL | 解釈 |
|---|---:|---:|---|
| LLaMA-V1-7B、Wanda | 10.69 | **10.22** | 小幅だが一貫した改善 |
| LLaMA-V1-7B、SparseGPT | 10.41 | **9.65** | 二階情報を使った初期枝刈り後にも改善 |
| LLaMA-V1-7B、Magnitude | 約560 | **66.70** | 悪い初期マスクを大幅に修復するが密モデル5.68には届かない |
| LLaMA-V1-65B、Wanda | 5.90 | **5.75** | 大規模モデルでも改善 |
| LLaMA-V2-70B、Magnitude | 13.35 | **6.77** | 大きなモデルでも交換の効果がある |
| OPT-13B、SparseGPT | 21.23 | **16.92** | モデル系列を跨いで改善 |

大きな改善は初期枝刈りが極端に悪い条件で生じやすい。LLaMA-V1-7BのMagnitude枝刈りは60%で困惑度が数百に悪化するため、DSnoTの改善量が大きく見える。これを「密モデルの性能を回復した」と表現してはならない。SparseGPTやWandaで既に品質が比較的良い場合の追加改善は0.1〜1程度の条件もある。

### 高い疎化率と構造制約の感度

Wandaで枝刈りしたLLaMA-V1-7Bの困惑度は、疎化率50%で7.26→7.12、60%で10.69→10.22、70%で88.84→62.05、80%で約4800→約4120、90%で約64万→約8.4万となる。70%での改善幅は26.79だが、80〜90%ではDSnoTを使っても困惑度が極端に大きく、実用品質とは言い難い。高疎化率で相対改善が大きいことと、生成モデルとして利用可能であることは別問題である。

N:Mの制約でも改善が残る。LLaMA-V1-7Bの2:4疎化では、Wandaの困惑度11.53を10.89へ、SparseGPTの11.00を10.03へ改善する。4:8ではWanda 8.57→8.45、SparseGPT 8.61→8.32である。これはマスク交換を同じブロックに制限しても一定の効果があることを示す。ただし、論文のこの表は困惑度を測っており、疎行列カーネルを使ったトークン毎秒の実測高速化を直接示すものではない。

### 下流課題・構成要素除去実験

60%疎化したLLaMA-V1-7Bの6課題平均正答率は、密モデル60.6%、SparseGPT 51.1%、SparseGPT＋DSnoT 52.7%、Wanda 50.7%、Wanda＋DSnoT 51.2%である。困惑度の改善は下流精度の改善にもある程度対応するが、密モデルとの差は残る。65BではSparseGPT 62.6→63.3%、Wanda 63.3→63.7%と改善は小さく、初期手法によって効果が異なる。

最大交換回数が小さ過ぎる、または停止しきい値が大き過ぎると再構成誤差が十分減らない。逆に停止条件なしで反復すると校正データへの過適合で品質が悪化する場合がある。原著の主設定T=50、ε=0.1はこの交換条件を踏まえたものだ。復活と削除の基準を入れ替える除去実験では、誤差だけを減らす削除方針が外れ値重みを落とし、困惑度を悪化させる。原著表7では提案の復活・削除組合せが10.22で、別の組合せでは10.27〜11.24などの悪化が見られる。二つの指標の役割分担が性能に寄与している。

## 先行方式との差と実装上の位置づけ

SparseGPTはヘッセ行列に基づく重み補正を用い、Wandaは活性加重重要度で一度だけマスクを選ぶ。DSnoTは両者を初期化器として利用でき、その後のマスクだけを再配置するため、初期枝刈り手法と補完的である。通常の動的疎学習と異なり、学習中に重みを更新することも、最適化器状態を保持することもない。LoRAと異なり追加の低ランク行列を学習して推論時に保持する必要もない。

導入手順は、まず密モデルと校正データを用意し、既存手法で目標疎化率の初期マスクを作り、DSnoTで各層のマスクを交換し、最後に困惑度と実タスク精度を検証する、という順序になる。N:Mのようなハードウェア対応のあるパターンなら同一ブロック内で交換を制限する。非構造疎化のモデルを通常の密行列カーネルで動かしても、重みゼロがそのまま演算量削減として実現されるとは限らない。実行時の速度・メモリ・消費電力は、利用する疎行列形式と推論ランタイムに依存する。

## 限界・負の結果

第一に、DSnoTは疎化後の品質を改善するが、元の密モデルと同じ品質を保証しない。特に80〜90%の高疎化率では、相対改善が大きくても困惑度は極端に高いままである。用途の品質閾値を満たすかどうかは別途判断しなければならない。

第二に、層出力の再構成誤差は最終タスク損失の代理指標である。校正データが実運用分布と異なる場合、マスクの交換が未知の入力で不利になる可能性がある。原著も停止条件を外した過剰な反復で品質が悪化する例を示すため、反復回数を増やせば必ず良くなるわけではない。

第三に、復活・削除の選択は入力活性の平均・分散や重み重要度に依存する。外れ値チャネルを保護する工夫はあるが、重み間の複雑な相互作用を完全に最適化するものではない。初期枝刈り方式によって効果が変わり、SparseGPTに対する改善幅はMagnitudeに対する改善より小さいことが多い。

第四に、論文の主要な速度値は枝刈り・マスク更新処理の時間であり、実サービスの初回トークン時間、トークン当たり時間、同時要求処理量を測ったものではない。N:M形式が特定のGPUで高速に実行できる可能性はあるが、DSnoTそのものが一般の非構造疎行列を高速化するカーネルを提供するわけではない。

第五に、比較の計算予算は一律ではない。LoRAとの比較では追加学習時間が数時間と秒単位で大きく異なり、性能差と費用差を同一軸へ押し込めない。学習なしで得られる品質と、追加学習を許した場合の最高品質のどちらを重視するかで採用判断は変わる。

第六に、モデル系列はLLaMA、Vicuna、OPTが中心で、MoEの専門家構造、長文脈での実際のKVキャッシュ、量子化と疎化の組合せ、家庭用GPUの実測性能は網羅されていない。12GB級GPUへモデルを載せる際は、重み疎化率だけでなく疎行列の格納形式、量子化形式、KVキャッシュ容量、カーネルの対応を確認する必要がある。
