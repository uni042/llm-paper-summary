# ScoutAttention: Efficient KV Cache Offloading via Layer-Ahead CPU Pre-computation for LLM Inference

## 書誌情報

- **著者:** Qiuyang Zhang, Kai Zhou, Ding Tang, Kai Lu, Cheng Li, Zhenyu Yang, Peng Xu, Jiguang Wan
- **公開:** arXiv:2603.27138, 2026-03-28
- **採択:** 63rd ACM/IEEE Design Automation Conference (DAC 2026)
- **分野:** LLM inference / KV cache offload / GPU–CPU collaborative attention
- **一次資料:** https://arxiv.org/abs/2603.27138
- **コード:** arXiv本文では公開repositoryを明示していない。実装はSGLangを基盤とし、GPU側のblock-wise Top-k選択にFlashInfer、CPU attention workerにIntel Extension for PyTorch (IPEX)を利用する。

## 一文要約

長contextのKV cacheの大部分をCPU DRAMへ置きながら、GPUにある重要blockはGPU、CPUにしかない重要blockだけはCPUでattentionを計算し、さらに**次layerでCPUが担当するattentionを1 layer早く開始する**ことで、KV転送待ちとCPU計算待ちの両方を減らす。

## 問題設定

長contextのdecodeではKV cacheがGPU HBMを圧迫し、batch sizeを増やせない。KVをCPU DRAMへoffloadする場合、大きく二つの実行方法がある。

1. 必要KVをCPUからGPUへ戻してGPUでattentionする方法は、PCIe転送が遅いとGPUがI/O完了を待つ。
2. KVをCPUに置いたままCPUでattentionする方法は転送を避けられるが、CPUがGPUより遅いためGPUがCPU計算完了を待つ。

論文の測定では、InfiniGen型のKV recallではGPU idleが実行時間の61%、HGCA型のCPU co-attentionでは57%に達した。ScoutAttentionは「どちらか一方へ全仕事を寄せる」のではなく、CPUが処理するattention量を小さくしたうえで、その処理開始を前倒しする。

## 手法

### 1. GPU–CPU協調block-wise sparse attention

KV cacheをblockへ分け、各blockを表す小さなdigestだけはGPUへ保持する。decode時には現在のqueryとdigestを比較し、attentionへの寄与が大きいTop-k blockを選ぶ。論文実装ではQuestのblock-wise sparse attentionを使うが、著者はNSAなど他のblock選択方式にも置換可能としている。

選ばれたTop-kのうちGPU HBMに残っているblockはGPUでattentionを計算し、Top-kだがCPU DRAMにしかないblockだけをCPUで計算する。両deviceの部分attention結果を最後にGPU上で統合する。

隣接decode tokenでは重要block集合が大きく変わらないという時間的局所性を利用するため、前stepで重要だったblockをGPUへ残しておけば、CPUが担当するのはTop-k全体ではなく新しく重要になった少数blockだけになる。論文では隣接token間で変化する重要blockは平均15%未満だった。

### 2. layer-ahead CPU pre-computation

通常のGPU–CPU並列attentionでは、同じlayerのGPU計算とCPU計算を同時に始めても遅いCPU側がcritical pathになり得る。ScoutAttentionは、GPUがlayer iを処理している間に**layer i+1でCPUが担当するattentionを先に開始する**。

ただしlayer iの処理中には、本来のlayer i+1のqueryはまだ得られていない。そこでTransformerのresidual connectionにより隣接layerの入力が似ていることを利用し、現在のlayer入力に次layerのquery projection weightを適用して次layer queryを近似する。この予測queryで次layerのTop-k blockを選び、そのうちCPU DRAMにあるblockのattentionをCPUへ非同期投入する。

著者の測定では予測queryと実queryのcosine similarityはQwen 3 8Bで0.94、Gemma 3 12Bで0.93、Llama 3.1 8Bで0.96、Mistral 7Bで0.97、GLM 4 9Bで0.94だった。Qwen3-32Bの例ではGPU attention単体が約300 µs、Transformer layer全体が約900 µsであり、CPU処理を同layer attentionと並列化するだけの場合より約3倍長い計算windowを使える。

### 3. asynchronous periodic KV cache recall

decodeが進むと重要block集合が徐々に変化し、prefill後からGPUに残しているblockだけではCPU担当量が増える。そこで一定間隔で、最近重要になったKV blockをCPU DRAMからGPUへ戻してGPU側cacheを更新する。

このrecallは、そのKVを現在のlayerですぐ必要とするタイミングではなく、attention計算が終わった後に非同期で開始する。次decode stepの同じlayerまでの時間を転送windowとして使うため、細粒度recallをcritical pathから外す。recall間隔はlayerごとにoffline profilingし、CPUが処理するtoken比率が閾値を超えない範囲に設定する。論文の既定閾値12%では平均CPU compute ratioが8.2%、平均recall intervalが8.7 decode stepだった。

## 評価条件

- **実装基盤:** SGLang
- **GPU側block選択:** FlashInferベースのCUDA kernel
- **CPU attention:** Intel Extension for PyTorch (IPEX)を使った最適化worker
- **accuracy評価:** Qwen 3 8B、LongBench 8 dataset、最大64K context
- **performance評価:** Qwen 3 14B、Prefill–Decode分離構成のdecode instance、sparse budget 2,048 token、block size 32
- **比較:** FullKV、InfiniGen、HGCA

性能評価はdecode側だけを対象としており、prefillを同じGPUで混載する通常serving全体のend-to-end比較ではない点に注意が必要である。

## 主要結果

- 64K inputで、decode throughputはFullKVの**5.1倍**。
- 既存offload方式のHGCA / InfiniGenに対して最大**2.1倍**。
- GPU idle比率はHGCA 57%、InfiniGen 61%に対してScoutAttentionは**6%**。
- layer-ahead pre-computation単体でablation上**1.39倍**、periodic recall追加でさらに**1.20倍**のspeedup。
- LongBenchではFullKV比の平均accuracy低下がsparse budget 1,024で2.5%、2,048で**2.1%**。
- batch 16→32でthroughput 1.78倍、32→64で1.48倍となり、比較したoffload方式よりbatch拡大時の伸びが大きい。

## 既存研究との差

- **InfiniGen:** 次layerで必要なKVを予測してCPU→GPU転送を先読みする。ScoutAttentionは大量KVを戻す代わりに、CPU上に残る重要blockのattentionそのものをCPUで先に計算するため、PCIe bandwidthを主要bottleneckにしにくい。
- **HGCA:** CPUとGPUでattentionを分担する点は近いが、CPU側の計算が遅くGPUが待つ。ScoutAttentionはGPUに前stepの重要blockを保持してCPU担当量を小さくし、さらにCPU計算を1 layer前倒しする。
- **Quest等のsparse attention:** どのKV blockを計算するかを減らす方式に対し、ScoutAttentionは選ばれたblockがGPU/CPUのどちらにあるかを考慮して計算場所と開始時刻までscheduleするsystems手法である。

## 限界

- sparse attentionと予測queryによる近似を使うため、full attentionと完全同一の出力を保証する方式ではない。
- layer-ahead予測はTransformerの隣接layer入力の類似性に依存する。評価した5 modelでは高い類似度だったが、異なるarchitectureや将来のmodelでも同程度とは限らない。
- periodic recallの間隔はoffline profilingで決めるため、hardware比率やworkloadが大きく変わると再調整が必要になる。
- performance評価はPrefill–Decode分離環境のdecode instanceに限定され、prefillを含むserving全体のcost / latencyは直接評価していない。
- CPU attentionがPCIe転送より有利という設計判断は、CPU計算能力、GPU性能、CPU–GPU interconnect bandwidthの比率に依存する。

## 一般的な実装上の含意

KV offloadでは「KVをどこへ置くか」だけでなく、**KVのあるdeviceで計算する方が転送より速いか**と、**その遅いdeviceの仕事をcritical pathよりどれだけ前に開始できるか**を同時に考える必要がある。CPU attentionがGPUより遅くても、CPU担当量をattention sparsityで十分小さくし、Transformer layer全体をlatency hiding windowとして使えば、CPU DRAMを単なるstorageではなく補助attention engineとして利用できる。

また、重要KV集合の時間的局所性を利用して「頻繁に使うKVだけGPUへ残す」cache管理と組み合わせることで、CPU計算量とCPU→GPU転送量を同時に抑えられる。これはKV以外の階層memoryでも、data placementとcompute placementを別々に最適化せず協調させる設計の有効性を示す。

## 引用関係

- **InfiniGen (2024):** one-layer-ahead predictionで必要KVをCPUからGPUへprefetchする先行研究。ScoutAttentionは同じ隣接layer入力の類似性を、KV転送ではなくCPU attentionの前倒しに使う。
- **HGCA (2025):** CPU上のoffloaded KVをCPUでattention計算するco-attention系の直接比較対象。
- **Quest (2024):** block digestから重要blockを選ぶsparse attention。ScoutAttentionの実装でTop-k block選択に使用。
- **NSA (2025):** 別のblock-wise sparse attentionとして、ScoutAttentionのdevice協調方式と組み合わせ可能とされる。
