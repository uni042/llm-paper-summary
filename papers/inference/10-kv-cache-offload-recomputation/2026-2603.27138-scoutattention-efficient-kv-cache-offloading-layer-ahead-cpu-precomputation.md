# ScoutAttention: Efficient KV Cache Offloading via Layer-Ahead CPU Pre-computation for LLM Inference

## 書誌情報

- **著者:** Qiuyang Zhang, Kai Zhou, Ding Tang, Kai Lu, Cheng Li, Zhenyu Yang, Peng Xu, Jiguang Wan
- **公開:** arXiv:2603.27138, 2026-03-28
- **採択:** 63rd ACM/IEEE Design Automation Conference (DAC 2026)
- **分野:** LLM inference / KVキャッシュ オフロード / GPU–CPU collaborative 注意機構
- **一次資料:** https://arxiv.org/abs/2603.27138
- **コード:** arXiv本文では公開リポジトリを明示していない。実装はSGLangを基盤とし、GPU側のブロック単位Top-k選択にFlashInfer、CPU注意機構ワーカーにIntel Extension for PyTorch (IPEX)を利用する。

## 一文要約

長文脈のKVキャッシュの大部分をCPU DRAMへ置きながら、GPUにある重要ブロックはGPU、CPUにしかない重要ブロックだけはCPUで注意機構を計算し、さらに**次層でCPUが担当する注意機構を1層早く開始する**ことで、KV転送待ちとCPU計算待ちの両方を減らす。

## 問題設定

長文脈のデコードではKVキャッシュがGPU HBMを圧迫し、バッチサイズを増やせない。KVをCPU DRAMへオフロードする場合、大きく二つの実行方法がある。

1. 必要KVをCPUからGPUへ戻してGPUで注意機構を計算する方法は、PCIe転送が遅いとGPUがI/O完了を待つ。
2. KVをCPUに置いたままCPUで注意機構を計算する方法は転送を避けられるが、CPUがGPUより遅いためGPUがCPU計算完了を待つ。

論文の測定では、InfiniGen型のKV 呼び戻しではGPU停止が実行時間の61%、HGCA型のCPU co-注意機構では57%に達した。ScoutAttentionは「どちらか一方へ全仕事を寄せる」のではなく、CPUが処理する注意機構量を小さくしたうえで、その処理開始を前倒しする。

## 手法

### 1. GPU–CPU協調block-wise sparse attention

KVキャッシュをブロックへ分け、各ブロックを表す小さな要約値だけはGPUへ保持する。デコード時には現在のクエリと要約値を比較し、注意機構への寄与が大きいTop-kブロックを選ぶ。論文実装ではQuestのブロック単位の疎な注意機構を使うが、著者はNSAなど他のブロック選択方式にも置換可能としている。

選ばれたTop-kのうちGPU HBMに残っているブロックはGPUで注意機構を計算し、Top-kだがCPU DRAMにしかないブロックだけをCPUで計算する。両デバイスの部分注意機構結果を最後にGPU上で統合する。

隣接デコード トークンでは重要ブロック集合が大きく変わらないという時間的局所性を利用するため、前ステップで重要だったブロックをGPUへ残しておけば、CPUが担当するのはTop-k全体ではなく新しく重要になった少数ブロックだけになる。論文では隣接トークン間で変化する重要ブロックは平均15%未満だった。

### 2. layer-ahead CPU pre-computation

通常のGPU–CPU並列注意機構では、同じ層のGPU計算とCPU計算を同時に始めても遅いCPU側がクリティカルパスになり得る。ScoutAttentionは、GPUが層 iを処理している間に**層 i+1でCPUが担当する注意機構を先に開始する**。

ただし層 iの処理中には、本来の層 i+1のクエリはまだ得られていない。そこでTransformerの残差接続により隣接層の入力が似ていることを利用し、現在の層入力に次層のクエリ 射影 重みを適用して次層 クエリを近似する。この予測クエリで次層のTop-k ブロックを選び、そのうちCPU DRAMにあるブロックの注意機構をCPUへ非同期投入する。

著者の測定では予測クエリと実クエリのコサイン類似度はQwen 3 8Bで0.94、Gemma 3 12Bで0.93、Llama 3.1 8Bで0.96、Mistral 7Bで0.97、GLM 4 9Bで0.94だった。Qwen3-32Bの例ではGPU上の注意機構単体が約300 µs、Transformer 層全体が約900 µsであり、CPU処理を同層 注意機構と並列化するだけの場合より約3倍長い計算ウィンドウを使える。

### 3. asynchronous periodic KV cache recall

デコードが進むと重要ブロック集合が徐々に変化し、プリフィル後からGPUに残しているブロックだけではCPU担当量が増える。そこで一定間隔で、最近重要になったKV ブロックをCPU DRAMからGPUへ戻してGPU側キャッシュを更新する。

この呼び戻しは、そのKVを現在の層ですぐ必要とするタイミングではなく、注意機構計算が終わった後に非同期で開始する。次のデコード段階の同じ層までの時間を転送ウィンドウとして使うため、細粒度の呼び戻しをクリティカルパスから外す。呼び戻し間隔は層ごとに事前測定し、CPUが処理するトークン比率が閾値を超えない範囲に設定する。論文の既定閾値12%では平均CPU計算比率が8.2%、平均呼び戻し間隔が8.7デコード段階だった。

## 評価条件

- **実装基盤:** SGLang
- **GPU側ブロック選択:** FlashInferベースのCUDA カーネル
- **CPU上の注意機構:** Intel Extension for PyTorch (IPEX)を使った最適化ワーカー
- **正解率評価:** Qwen 3 8B、LongBench 8データセット、最大64K文脈
- **性能評価:** Qwen 3 14B、プリフィル–デコード分離構成のデコード 実行系、疎化予算 2,048 トークン、ブロックの大きさ 32
- **比較:** FullKV、InfiniGen、HGCA

性能評価はデコード側だけを対象としており、プリフィルを同じGPUで混載する通常提供処理全体のエンドツーエンド比較ではない点に注意が必要である。

## 主要結果

- 64K 入力で、デコード スループットはFullKVの**5.1倍**。
- 既存オフロード方式のHGCA / InfiniGenに対して最大**2.1倍**。
- GPU停止比率はHGCA 57%、InfiniGen 61%に対してScoutAttentionは**6%**。
- 層先行計算単体で比較実験上**1.39倍**、定期的な呼び戻しの追加でさらに**1.20倍**の高速化倍率。
- LongBenchではFullKV比の平均正解率低下が疎化予算 1,024で2.5%、2,048で**2.1%**。
- バッチ 16→32でスループット 1.78倍、32→64で1.48倍となり、比較したオフロード方式よりバッチ拡大時の伸びが大きい。

## 既存研究との差

- **InfiniGen:** 次層で必要なKVを予測してCPU→GPU転送を先読みする。ScoutAttentionは大量KVを戻す代わりに、CPU上に残る重要ブロックの注意機構そのものをCPUで先に計算するため、PCIe 帯域を主要ボトルネックにしにくい。
- **HGCA:** CPUとGPUで注意機構を分担する点は近いが、CPU側の計算が遅くGPUが待つ。ScoutAttentionはGPUに前ステップの重要ブロックを保持してCPU担当量を小さくし、さらにCPU計算を1層前倒しする。
- **Quest等の疎な 注意機構:** どのKV ブロックを計算するかを減らす方式に対し、ScoutAttentionは選ばれたブロックがGPU/CPUのどちらにあるかを考慮して計算場所と開始時刻までスケジュールするシステム手法である。

## 限界

- 疎な 注意機構と予測クエリによる近似を使うため、完全な注意機構と完全同一の出力を保証する方式ではない。
- 層先行予測はTransformerの隣接層入力の類似性に依存する。評価した5 モデルでは高い類似度だったが、異なる構成や将来のモデルでも同程度とは限らない。
- 定期的な呼び戻しの間隔は事前測定で決めるため、ハードウェア比率やワークロードが大きく変わると再調整が必要になる。
- 性能評価はプリフィル–デコード分離環境のデコード 実行系に限定され、プリフィルを含む提供処理全体のコスト / 遅延は直接評価していない。
- CPU上の注意機構がPCIe転送より有利という設計判断は、CPU計算能力、GPU性能、CPU–GPU 接続網 帯域の比率に依存する。

## 一般的な実装上の含意

KV オフロードでは「KVをどこへ置くか」だけでなく、**KVのあるデバイスで計算する方が転送より速いか**と、**その遅いデバイスの仕事をクリティカルパスよりどれだけ前に開始できるか**を同時に考える必要がある。CPU上の注意機構がGPUより遅くても、CPU担当量を注意機構 疎化で十分小さくし、Transformer 層全体を遅延 隠蔽 ウィンドウとして使えば、CPU DRAMを単なる保存領域ではなく補助注意機構 エンジンとして利用できる。

また、重要KV集合の時間的局所性を利用して「頻繁に使うKVだけGPUへ残す」キャッシュ管理と組み合わせることで、CPU計算量とCPU→GPU転送量を同時に抑えられる。これはKV以外の階層メモリでも、データ配置と計算配置を別々に最適化せず協調させる設計の有効性を示す。つまり、保存場所の決定と計算開始時刻の決定を同時に扱うことが、転送待ちと計算待ちを重ね合わせる鍵になる。
この設計では、GPUに残すブロックを増やせばCPU計算は減るが、GPUメモリを多く消費する。逆にGPUに残す量を減らせば容量は節約できるが、CPU側の先行計算と呼び戻しの調整が重要になる。したがって、利用可能なGPU容量とCPU性能に応じて、保持量と先行開始時刻を合わせて決める必要がある。

## 引用関係

- **InfiniGen (2024):** one-層先行 予測で必要KVをCPUからGPUへプリフェッチする先行研究。ScoutAttentionは同じ隣接層入力の類似性を、KV転送ではなくCPU上の注意機構の前倒しに使う。
- **HGCA (2025):** CPU上のオフロード済み KVをCPUで注意機構計算するco-注意機構系の直接比較対象。
- **Quest (2024):** ブロック digestから重要ブロックを選ぶ疎な 注意機構。ScoutAttentionの実装でTop-k ブロック選択に使用。
- **NSA (2025):** 別のブロック単位 疎な 注意機構として、ScoutAttentionのデバイス協調方式と組み合わせ可能とされる。
