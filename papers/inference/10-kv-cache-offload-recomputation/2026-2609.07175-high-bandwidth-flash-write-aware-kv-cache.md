# Enabling High-Bandwidth Flash for Generative Recommendation Serving with Write-Aware KV Cache Policy

> 生成推薦の利用者KVキャッシュをHBFへ置く際、LRU-Kで低再利用利用者のキャッシュ書込みを抑え、HBMのみより3.8〜4.7倍のスループットを得つつフラッシュ寿命を約1年から6年以上へ延ばす方式を分析した。
## 書誌情報
- **著者**: Danni Peng, Kai Wu, Tianyu Zuo, Pengfei Xia, Hui Zang
- **著者・所属**: Huawei Technologies Co., Ltd.
- **公開**: arXiv
- **種別**: Preprint
- **対象**: 生成推薦、KVキャッシュ、高帯域フラッシュ、キャッシュ入場制御、フラッシュ耐久性
- **実装**: 解析モデルとシミュレーション評価。論文本文およびarXivの関連コード欄で公式実装URLは確認できない。
## 概要
生成推薦では、同じ利用者の長い履歴から作ったKVキャッシュを次回要求でも再利用すると再計算を減らせるが、利用者数が増えるとHBMは容量不足、CPUメモリは帯域不足になる。本論文は大容量かつ高読出し帯域の高帯域フラッシュ（High-Bandwidth Flash; HBF）へモデル重みと利用者KVキャッシュを置く構成を分析し、通常のLRUではミスのたびに巨大なKVを書き込んでフラッシュ寿命を約1年まで縮める問題を示す。そこで利用者の直近K回の要求履歴を用いるLRU-Kで、再利用頻度が低い利用者をキャッシュへ入れず、ミスと書込みを切り離す。解析モデルによる評価では、HBF構成はHBMのみより3.8〜4.7倍のスループットを示し、K=10では寿命を6年以上へ延ばしながらスループットを維持またはわずかに改善した。

本論文の中心的な考えは、キャッシュミスとキャッシュ書込みを同じ事象として扱わないことである。通常のLRUではミスした利用者を必ず登録するが、LRU-Kではその利用者が過去に十分な回数アクセスされているかを入場条件として使う。低再利用利用者はミス時に履歴を再計算するものの、その大きなKVをHBFへ保存しない。これにより推薦結果を近似したりKVを圧縮したりせず、再利用可能性が低い書込みだけを抑制できる。さらに論文は、ヒット率、入場確率、要求遅延、書込み量、HBF寿命を同じ解析枠組みで結び、Kを変えたときに性能と耐久性がどう動くかを定量化する。
## 問題設定
生成推薦では、各利用者の長い行動履歴を毎回プリフィルし直すと計算量が大きいため、前回までの履歴から作ったKVキャッシュを利用者単位で残し、次の要求では増分だけを計算する。この方式では利用者数に比例してKVキャッシュ容量が増え、HSTU-10Bの例では1万人規模でも高頻度利用者の25%を保持するだけで3.62 TBに達する。一方、厳しい遅延目標を満たすには高い読出し帯域も必要で、8K履歴・20 ms目標では403 GB/sが必要になる。HBMは帯域は十分でも容量が小さく、CPUメモリは容量を増やせてもPCIe帯域が不足する。HBFは大容量と高読出し帯域を両立できるが、NANDフラッシュは書込み耐久性が有限である。通常のLRUではキャッシュミスのたびに長い履歴全体のKVを計算して即座にキャッシュへ入れるため、一度しか来ない利用者にも大きな書込みが発生し、HBF寿命を急速に消費する。
## 新規性
本論文の中心的な考えは、キャッシュミスとキャッシュ書込みを同じ事象として扱わないことである。通常のLRUではミスした利用者を必ず登録するが、LRU-Kではその利用者が過去に十分な回数アクセスされているかを入場条件として使う。低再利用利用者はミス時に履歴を再計算するものの、その大きなKVをHBFへ保存しない。これにより推薦結果を近似したりKVを圧縮したりせず、再利用可能性が低い書込みだけを抑制できる。さらに論文は、ヒット率、入場確率、要求遅延、書込み量、HBF寿命を同じ解析枠組みで結び、Kを変えたときに性能と耐久性がどう動くかを定量化する。
## 手法
### 手法のあらまし
対象システムは、頻繁に更新される中間活性値を1基のHBM4へ置き、モデル重みと利用者ごとの長期KVキャッシュを7基のHBFへ置く。要求が到着すると、まず利用者のKVがキャッシュにあるかを確認する。ヒット時は長い履歴KVをHBFから読み出し、新たに追加された短い履歴部分と候補生成だけを計算し、その増分KVだけを書き足す。ミス時は長い履歴からKVを再計算するが、LRU-Kでは直ちにHBFへ保存せず、その利用者の直近K回の要求履歴を見て入場条件を満たす場合だけ完全なKVを書き込む。入場条件は、対象利用者のK番目に新しい要求時刻が、現在キャッシュされている利用者の中で最も古いK番目要求時刻より新しいかどうかで決まる。したがって単発利用者や長く非活動だった利用者は保存されず、再利用される可能性が高い利用者へHBF容量と書込み回数を集中できる。論文はポアソン到着モデルと特性時間近似を使い、ある利用者が特性時間内にK回以上到着する確率からLRU-Kのヒット率を求める。また、ミスのうち入場条件を満たして完全KVを書き込む確率と、入場せず再計算だけで終わる確率を分ける。この分解により、平均要求遅延とQPSだけでなく、要求当たりの平均書込み量とフラッシュ寿命も同じKに対して計算する。Kを1にすると全ミスを登録する通常LRUへ戻り、Kを大きくすると書込みが減る一方で、頻繁な利用者を優先することでヒット対象の構成も変化する。

### HBF中心の階層メモリ配置
論文はHBFをCPUメモリの下位退避先としてではなく、GPU近傍の大容量・高読出し帯域メモリとして扱う。7基のHBFにはモデル重みと利用者KVキャッシュを置き、1基のHBM4には頻繁に更新される中間活性値を残す。HBFは各スタック512 GB、読出し1.6 TB/sという仮定で、HBM4よりはるかに大きい容量を確保しつつ、KV読み出しではHBM級の帯域を狙う。対して書込み帯域は48 GB/sで、さらにSLC NANDの100K P/Eサイクルという耐久制約があるため、書込み頻度の高い一時データをHBFへ置かない。この配置により、HBMだけでは保持できない多数利用者のKVを近接メモリに残して再計算を減らし、CPUメモリ退避で問題になるPCIe帯域不足も避ける。ただしHBFの利点は高い読出し帯域と十分な容量が実際に得られることを前提としており、書込みを無制限に行えるわけではない。

### LRU-Kによる入場制御
通常LRUは最後にアクセスされた時刻だけで追い出し順を決め、ミスした利用者を必ずキャッシュへ登録する。LRU-Kは各利用者についてK番目に新しい要求を参照し、その時刻が現在キャッシュ中の利用者群に対して十分新しい場合だけ登録する。これは単に古いキャッシュを追い出す方式ではなく、そもそも低再利用利用者をHBFへ入れない入場制御として働く。要求がミスしても、入場条件を満たさなければ長い履歴を計算して推薦結果は作るが、得られた完全KVはHBFへ保存しないため、大きな書込みを回避できる。K=1では全ミスが入場するため通常LRUと一致する。Kを増やすと、短期間に繰り返しアクセスされる利用者が優先され、単発アクセスによるキャッシュ汚染とフラッシュ摩耗を同時に抑えられる。追加コストは利用者ごとのアクセス履歴を追跡し、入場判定を行う管理処理である。

### 性能・書込み・寿命の統合解析モデル
評価ではヒット経路、ミスして書き込む経路、ミスして書き込まない経路を分け、それぞれの計算時間、読出し時間、書込み時間の最大値から要求遅延を求める。ヒット時は過去KVを読み出し、増分プリフィルと候補生成だけを計算する。ミスして登録する場合は履歴全体を再計算し完全KVを書き込み、登録しない場合は同じ再計算を行うが大きな書込みを省く。さらに要求当たりの平均書込み量を、増分KVの書込みと完全KVの書込み確率から算出し、利用可能HBF容量とP/E耐久回数を総書込み量で割って推定寿命を得る。これによりKを上げた際のスループットと耐久性を同じ条件で比較できる。実機でHBFを動かした測定ではないため、帯域、アクセス遅延、寿命モデル、要求到着分布の仮定から外れる環境では結果が変わる。

### 全体のデータ／制御の流れ
要求処理の流れは、利用者識別子でKVキャッシュを検索し、ヒットなら履歴KV読出しと増分計算、ミスなら履歴再計算へ進む。その後LRU-K入場判定を行い、条件を満たしたミスだけ完全KVをHBFへ保存する。キャッシュ容量が不足する場合はK番目の要求時刻が最も古い利用者を置き換える。HBFの役割は大容量で高頻度再利用KVを保持することであり、HBM4は書込みの多い一時状態を担当する。性能モデルは計算とメモリ転送の重なりを屋根線モデルの最大値で近似するため、実装上のキューイング、競合、制御処理、フラッシュ内部管理の細部は明示的には再現しない。
## 評価条件
- **ハードウェア**: 実機HBFではなく解析モデル上の比較である。HBMのみはHBM4を8基、HBM+CPUはHBM4 8基に2 TBのCPUメモリとPCIe 6.0相当128 GB/sを追加し、HBF構成はHBF 7基とHBM4 1基とする。HBM4は1基36 GB、読書き1.6 TB/s。HBFは1基512 GB、読出し1.6 TB/s、書込み48 GB/s、4 KB読出し遅延1 μs、SLC 100K P/Eサイクルを仮定する。HBF各基には3.13 MBのSRAM段階バッファも仮定し、全構成でピーク計算性能2 PFLOP/sを用いる。
- **ソフトウェア**: 特定の実装フレームワークや公開コードを用いた実機評価ではなく、論文で定義した屋根線型の解析モデルとキャッシュ確率モデルで要求遅延、QPS、書込み率、寿命を算出する。通常LRUをLRU-1として扱い、LRU-KのKを1〜20まで変化させる。
- **比較対象**: HBMのみ + LRU-1、HBM+CPU + LRU-1、HBF + LRU-1、HBF + LRU-K
生成推薦の履歴プリフィルと候補生成を、キャッシュヒット、ミスして完全KVを書き込む場合、ミスして書き込まない場合に分解する。各経路の時間は計算時間、KV読出し時間、KV書込み時間の最大値で近似し、要求分布から得た経路確率で平均要求遅延を算出する。キャッシュヒット率と入場確率はポアソン要求モデルと特性時間近似から導く。平均書込み量と利用可能HBF容量、100K P/E耐久性から推定寿命を求める。
評価は解析モデルと合成的な要求到着モデルに基づき、実機HBF、実サービスの完全な要求トレース、フラッシュ制御器の書込み増幅、ガベージコレクション、熱・電力制約、キューイング競合などは直接測定していない。したがって数値はHBFが仮定どおりHBM級読出し帯域と指定書込み帯域を提供し、特性時間近似が利用者局所性を十分表す場合の設計上限・傾向として読む必要がある。
## 主要結果
HBF構成の主な利点は、大容量でより多くの利用者KVを保持し、長い履歴プリフィルの再計算を減らせる点にある。解析結果では6モデルすべてでHBMのみより3.8〜4.7倍高いQPSとなった。一方、通常LRUではミスのたびに完全KVを書き込むためHBF寿命は約1年にとどまる。LRU-KでKを10へ上げると、低再利用利用者の完全KV書込みが大きく減り、全ワークロードで推定寿命が6年以上となった。Kの増加はヒット対象を高頻度かつ履歴の長い利用者へ寄せるため、耐久性を改善しながらQPSもわずかに上昇する。

- HBF構成のQPS向上 / 3.8〜4.7倍 (比較対象: HBMのみ構成; 条件: HSTU 1B/10B/100B MoEとOpenOneRec 1.7B/8B/100B MoE、LRU-1) — HBFの大容量により利用者KVのヒット率が上がり、長い履歴プリフィルの再計算を大幅に減らせるため、HBMだけで容量不足になる条件ほど高いスループットが得られる。

- HBF推定寿命 / 約1年から6年以上 (比較対象: LRU-1; 条件: HBF構成でKを1から10へ増加、6ワークロード) — ミス時の自動登録をやめ、再利用履歴の乏しい利用者をHBFへ書き込まないことで、完全KVの書込み頻度を抑え、100K P/Eサイクルの限られた耐久性を長く使える。

- HSTU-10Bの完全KV書込み確率 / 0.101から0.014 (比較対象: LRU-1; 条件: K=10との比較) — 完全KVを書き込む要求の割合が約7分の1まで低下し、寿命改善の主要因が単なるヒット率変化ではなく入場制御による書込み削減であることを示す。

- CPUメモリ追加時のQPS / 5/6モデルで1.3〜2.0倍 (比較対象: HBMのみ構成; 条件: HBM+2 TB CPUメモリ、PCIe 6.0相当128 GB/s、LRU-1) — 容量を増やすだけでも再計算は減るが、CPU側帯域がKV読出しの上限になるためHBFほど伸びない。HSTU-1BではKVをCPUから読むより履歴を再計算する方が速く、わずかに悪化する。

### 負の結果・境界条件
- HSTU-1BではHBM+CPU構成がHBMのみよりわずかに低速になる。小型モデルでは履歴プリフィル再計算の計算費用が小さく、帯域の限られたCPUメモリから完全KVを転送する方が遅いためである。またHBFの寿命改善は実機測定ではなく、100K P/E、指定帯域、ポアソン要求分布、書込み増幅を明示的に含めない寿命式に依存する。LRU-Kは利用者アクセス履歴を管理する追加処理も必要である。

### 結果の読み方
結果は、生成推薦のKVキャッシュがLLMの通常デコードより書込み頻度を低くできるというワークロード特性に依存する。HBFは読出し帯域と容量の両方を提供することでヒット率を高めるが、通常LRUのままではその容量へ低再利用KVまで書き込んで耐久性を浪費する。LRU-Kは高頻度利用者を優先するため、書込みを減らすだけでなく、長い履歴を持つ活動的利用者の再計算を避けやすくなり、K=10付近ではQPS低下との交換条件がほぼ現れない。小型モデルや再計算が安い条件では、容量拡張より転送帯域が重要になるため効果は小さくなる。
## 品質への影響
モデル重み、KV値、注意計算を圧縮・近似する手法ではないため、論文の想定では推薦品質を直接変えない。キャッシュへ入れなかった利用者は次回ミス時に履歴プリフィルを再計算するため、計算量は増えても意味的には同じKVを再生成する。ただし本論文は推薦精度の実測比較を行っていないため、実装上の数値誤差や制御遅延まで含めた完全な無損失性は実証していない。
## 既存研究との差
既存のKVオフロード研究がHBM容量不足をCPUメモリやSSDへの階層化、圧縮、プリフェッチで解くことが多いのに対し、本論文はHBFをGPU近傍の主たる大容量KV保存先として想定し、性能よりも書込み耐久性を第一級の設計制約として扱う点が異なる。H3などのHBF研究は読出し主体データをHBFへ置く構成を示したが、本論文は生成推薦の利用者KVが要求をまたいで再利用される特性に着目し、キャッシュミス時の書込み方針そのものをLRU-Kで変える。KV圧縮や近似選択とは異なり、保存する値の内容を変えず、どの利用者の完全KVを永続化するかだけを制御する。したがって主な交換条件は精度対容量ではなく、再計算量・キャッシュヒット率・書込み量・フラッシュ寿命の間にある。
## 限界
第一に、評価は解析モデルであり、実機HBF上のエンドツーエンド実装ではない。フラッシュ内部のガベージコレクション、書込み増幅、チャネル競合、温度、電力制御、コントローラ待ち、キューイングなどは簡略化されている。第二に、利用者要求はポアソン過程と特性時間近似で扱われるため、突発的な人気変化、季節性、利用者間相関、実サービス固有の長い裾を持つ到着分布ではヒット率と入場確率が変わり得る。第三に、HBFの読出し帯域1.6 TB/s、書込み48 GB/s、100K P/Eという将来ハードウェア仮定に結果が依存する。第四に、LRU-Kのアクセス履歴管理に必要なメタデータ量と制御処理は詳細評価されていない。第五に、推薦精度への影響は測っておらず、キャッシュ不採用時に同じ履歴を再計算すれば意味上同等という前提で性能だけを議論している。
## 実装状態
論文は数式による解析モデルとシミュレーション評価を提示している。arXiv本文および関連コード欄では、LRU-K対応の生成推薦サーバや評価器の公式公開リポジトリは確認できない。HBF自体も論文の仮定値に基づく将来構成として評価されており、実機統合の再現コードやハードウェア試作は示されていない。
## 研究上の位置づけ
本論文は、KVキャッシュの容量・帯域問題をストレージ階層だけでなく媒体寿命まで含めて扱う研究に位置付けられる。特に生成推薦では、同一利用者の履歴KVを要求間で再利用できるため、LLMセッション内でKVが連続成長する場合よりHBFへ適した読み出し主体のアクセス形態を作れる。その一方で、通常LRUの無条件入場が耐久性を壊すことを示し、アクセス頻度に基づく入場制御をメモリ媒体の耐久設計と結び付けた。リポジトリ上ではKVキャッシュのオフロード・再計算系統とHBF活用研究の接点にあり、今後は実トレース、実機または詳細フラッシュシミュレータ、書込み増幅を含む評価、動的K調整、他の入場制御方式との比較が自然な発展方向になる。
