# PCR: A Prefetch-Enhanced Cache Reuse System for Low-Latency RAG Serving

> RAGの共有接頭辞KVをDRAM・SSDへ階層保存し、待機列を使う先読みLRU、層単位の転送・計算重畳、SSD→DRAMプリフェッチで再利用待ちを隠し、平均TTFTを最大2.47倍高速化する。

- **実装**: vLLMを基盤に、256トークンのKVチャンク、接頭辞木、CUDA 12.8以降のcudaMemcpyBatchAsync、3本のCUDAストリーム、SSDプリフェッチ専用スレッドを組み込んだ実装を評価している。2026-09-14時点で一次資料から著者公式コード公開URLは確認できない。
## 概要
PCRは、検索拡張生成（RAG）で同じ文書接頭辞が繰り返し現れるとき、既計算のKVキャッシュをGPU外へ保存して再利用しても、単純な追い出しでは再利用率が低く、CPU–GPU転送とSSD読出しが先頭トークンまでの時間を再び支配する問題を扱う。文書を固定長チャンクに分けて接頭辞木で管理し、待機列に見えている近未来の要求を使ってLRU優先度を先回り更新する。さらにKV転送を層単位へ分解してGPU計算と重ね、SSD上の一致KVは要求が待機中のうちにDRAMへ非同期プリフェッチする。vLLM上の実装をA6000とRTX 4090環境で評価し、平均TTFTをvLLM比で最大2.47倍高速化した。

PCRの論文固有の着眼点は、RAG配信の待機列を単なる待ち時間ではなく近未来のKV需要予告として利用し、三階層キャッシュ全体を先回り制御する点にある。接頭辞木の葉LRUへ待機要求由来の優先度更新を加え、DRAM上で近く使うチャンクを保護する。同時にCPU–GPU転送はTransformer層ごとへ細分化して計算と重ね、SSD上の一致チャンクは要求が実行対象になる前にDRAMへ移す。この三機構をvLLMのスケジューラと一体化し、正確な接頭辞再利用を維持したまま容量・転送・SSD待ちをまとめて扱う。
## 問題設定
RAGでは検索した長い文書を入力へ連結するため、デコードが短い場合でもプリフィル計算が先頭トークンまでの時間を支配する。同じ文書が複数要求で繰り返されるなら既計算KVを再利用できるが、GPUだけでは保存容量が小さい。DRAMへ広げるとCPU–GPU転送が加わり、さらにSSDへ広げると読出し約3GB/s・書込みはそれより遅いI/Oが同期障壁になる。単純LRUは「すぐ後の待機要求で再利用するKV」も古いという理由で追い出し、再計算やSSD読出しを増やす。従って容量だけを増やしても、追い出し判断、CPU–GPU転送、SSD搬送をスケジューラと協調させなければ再利用利得が相殺される。

## 手法
### 手法のあらまし
要求が到着すると、検索器が関連文書を決めた後、その文書列と質問がvLLMの待機列へ入る。PCRは各文書列を256トークン単位のチャンクへ分け、直前までの接頭辞を含むキーで接頭辞木をたどる。親チャンクが存在して初めて子チャンクを正しく再利用できるため、容量不足時の追い出し候補は木の葉に限定する。通常のLRU順だけでなく、待機列の近い将来に現れる要求を先読みし、その要求が必要とする葉の優先度を上げることで、直後に再利用するKVを追い出さない。DRAMに一致KVがあれば実行時にGPUへ戻すが、全層分を一括転送してから計算するのではなく、最初の層のKVが届いた時点でGPU計算を開始する。次層のCPU→GPU転送、現在層の計算、完了層のGPU→CPU書戻しを別々のCUDAストリームで同時進行させ、見える転送待ちを概ね先頭層の読込みと最終層の書戻しへ縮める。SSDにしかKVがない場合は実行直前の同期読出しでは遅すぎるため、専用プリフェッチスレッドが待機列の一定窓を監視する。対象要求の接頭辞がSSDにありDRAMにないと分かった時点でSSD→DRAM読出しを非同期投入し、要求が実際にスケジュールされるまでの待機時間でI/Oを進める。新しく生成したKVもまずDRAMへ層単位で戻した後、SSDへの永続化は非同期書戻しする。したがってPCRは、どのKVを残すか、いつSSDから上げるか、いつGPUへ渡すかを同じ待機列情報と可用性状態でつなぎ、再計算・PCIe待ち・SSD待ちを別々ではなくパイプライン全体として減らす。

### 待機列先読み付き接頭辞木キャッシュ
入力文書列を固定長チャンクへ分割し、同じトークン列でも前方の接頭辞が異なれば別ノードになる接頭辞木でKVを管理する。位置依存KVの正確性を保つため、子は親がキャッシュされている場合だけ再利用可能であり、追い出しは依存関係を壊さない葉ノードから行う。通常のLRUだけでは、古く見えるチャンクが次の待機要求ですぐ必要でも追い出されるため、PCRはvLLMスケジューラの待機列を一定範囲だけ先読みし、近く使われる接頭辞チャンクの再利用優先度を上げる。これにより未来要求を完全に予測するモデルを追加せず、既に検索が終わって待機している確定要求から近未来需要を得て、DRAMの実効再利用率を高める。代償は待機列が短い低負荷時には先読み情報が少なく、窓を広げすぎると遠い要求のKVまで保護・読込みして現在要求向け容量を圧迫し得る点である。

### 層単位のKV転送・計算重畳
DRAM上の再利用KVをGPUへ一括転送してからプリフィルを始める方式では、PCIe転送時間がそのままTTFTへ加算される。PCRはTransformerのKVが層ごとに独立して配置される性質を利用し、最初の層のKVだけ届けばその層の計算を開始する。CPU→GPU読込み、GPU計算、GPU→CPU書戻しへ別々のCUDAストリームを割り当て、次層の読込みと現在層の計算と前層の書戻しをパイプライン化する。さらに256トークンのPCRチャンクからvLLMの16トークン物理ブロック群へ散らばるコピーをCUDA 12.8のcudaMemcpyBatchAsyncでまとめ、Llama2-13Bの1層チャンクコピーを0.671msから0.261msへ短縮した。効果は各層の転送が計算より短い条件で最大となり、KVが小さいモデルでは同期やイベント管理の固定費が利得を相殺する場合がある。

### 待機列を使うSSD→DRAMプリフェッチ
SSDはDRAMより大容量だが、論文環境の逐次読出しは約3GB/sで、要求が実行対象になってから同期読出しすると層単位重畳だけでは隠せない。PCRはRAGの検索処理がLLM実行より先に終わり、高負荷では要求が待機列に滞在することを利用する。専用スレッドが先読み窓内の要求を調べ、一致する接頭辞KVがSSDには存在するがDRAMにはない場合、要求の実行順が来る前にSSD→DRAM非同期読出しを投入する。DRAMに既にあるKVは優先度だけ更新し、SSDにもないKVは再計算対象として扱うので、不要なI/Oを無制限には発行しない。生成後のKVもSSDへ同期書込みせず非同期で退避する。待機時間をI/O時間へ転用するため高負荷ほど機会が増える一方、先読み窓はモデルと負荷に依存し、Llama2-7Bでは6が最良だったが固定値を他モデルへそのまま適用できない。

### 全体のデータ／制御の流れ
PCRはGPU、CPU DRAM、NVMe SSDの三階層にKVを配置する。GPU側のブロック管理はvLLMのPagedAttentionへ任せ、PCRのキャッシュエンジンがDRAMとSSDの256トークンチャンク、接頭辞木、再利用優先度を管理する。スケジューラは実行要求だけでなく待機要求もキャッシュエンジンへ渡し、先読み保護とSSDプリフェッチを駆動する。実行時には必要KVの所在を確認して層単位転送を開始し、可用性イベントとGPU計算を同期する。新規KVはDRAMへ戻した後にSSDへ非同期書込みするため、階層全体で正確な接頭辞再利用を維持しながらデータ移動を計算・待機時間へ重ねる。
## 評価条件
- **ハードウェア**: 実機2系統。2×NVIDIA A6000 48GB、ホストメモリ256GB、CPU 96コア、4TB NVMe SSDと、2×NVIDIA RTX 4090 24GB、ホストメモリ128GB、CPU 128コア、4TB NVMe SSDを用いる。PCIe 4.0はGPU当たり理論32GB/s・実測約24GB/s、SSD逐次読出しは約3GB/s。
- **ソフトウェア**: vLLMを共通基盤とし、PCRをそのスケジューラ・ワーカー・KVブロック管理へ統合する。CUDA 12.8以降のcudaMemcpyBatchAsyncを使用し、CPU→GPU、GPU計算、GPU→CPUに3本のCUDAストリームを割り当てる。比較対象はvLLM、LMCache、CPU階層のみのCCache、CPU+SSDのSCCache。
- **比較対象**: vLLM、LMCache、CCache（CPU階層）、SCCache（CPU+SSD階層）
Llama3.1-8B、Llama3.2-3B、Qwen2.5-8B、Qwen2.5-14B、Llama2-7B、Llama2-13Bを評価する。Wikipediaを検索文書集合、SQuADを質問集合とし、MiniLMで埋込みを作って上位2文書を各質問へ連結する。1000入力と2000入力の2ワークロードを作り、平均入力長は約6.8kトークン、KV再利用の反復率はそれぞれ40%と35%。各データ集合で2000サンプリングを行い、出力は16トークンへ固定し、到着はポアソン過程で0.5〜1.0要求/秒を掃引する。性能分解では層単位重畳とSSDプリフェッチを順に追加し、先読み窓の大きさも変える。
実機の単一サーバー内でGPU・DRAM・NVMe SSDを跨ぐRAG配信評価であり、分散KVストアやネットワーク越しのSSD、複数ノード障害、長いデコードを対象にしない。入力は平均約6.8kトークン、出力16トークンなのでプリフィル支配型。共有可能性はWikipedia/SQuADから作った35〜40%反復の負荷に依存する。正確な接頭辞一致のみを再利用するため品質比較は近似方式との同条件評価ではなく、主に遅延・再利用効率を測る。
## 主要結果
PCRは評価したハードウェア・モデル・要求率の各条件で平均TTFTを短縮し、特に待機列が伸びてSSDプリフェッチ機会が増える高負荷で差が広がる。RTX 4090上のLlama 8BではvLLM比がワークロード1/2で2.13倍/1.42倍、高要求率では2.47倍/1.59倍まで改善した。性能分解では層単位重畳が平均約15%のTTFT削減を担い、Llama系のようにKVが大きくSSD再利用率が高い条件ほどプリフェッチの寄与が増えた。正確な接頭辞KVを再利用するため、近似的なKV融合・圧縮に伴う品質低下は導入しない。

- 平均TTFT高速化 / 最大2.47倍 (比較対象: vLLM; 条件: RTX 4090上のLlama 8B、ワークロード1、高要求率) — 負荷が高いほど待機列から先読みできる要求が増え、SSD読出しを実行前にDRAMへ移せるため差が拡大する。

- 平均TTFT高速化 / 2.13倍/1.42倍、高要求率で2.47倍/1.59倍 (比較対象: vLLM; 条件: RTX 4090上のLlama 8B、ワークロード1/2) — 再利用率が異なる二つの入力集合でも一貫して改善し、共有接頭辞が多いワークロード1で利得が大きい。

- 層単位重畳の寄与 / 平均約15%のTTFT削減 (比較対象: 重畳なしのPCR基本構成; 条件: Qwen2.5-7B/14B、Llama2-7B/13Bの性能分解) — CPU–GPU転送を層単位でGPU計算へ重ねるため、KVが大きいLlama系ほど転送隠蔽の価値が高い。

- Llama2-7B高負荷の追加機構効果 / 11.133秒 → 重畳5.841秒 → プリフェッチ3.441秒 (比較対象: PCR基本構成; 条件: 1.0要求/秒) — KV容量が大きくSSDヒットが約20%ある条件では、PCIe重畳に加えSSD先読みが大きな追加効果を持つ。

- 先読み窓の調整 / 窓4→6でTTFT 31.06%削減 (比較対象: 先読み窓4; 条件: Llama2-7B、高要求率) — 待機要求が十分あると少し遠い将来までSSD読出しを前倒しできるが、最適窓はモデル依存である。

- 1層KVチャンクのCPU→GPUコピー / 0.671ms → 0.261ms (比較対象: cudaMemcpyAsyncによるブロック逐次コピー; 条件: Llama2-13B、PCIe 32GB/s条件) — 非連続vLLMブロックをcudaMemcpyBatchAsyncでまとめ、層単位パイプラインの固定費を抑える。

### 負の結果・境界条件
- 小さいKVを持つQwen系では、CPU–GPU転送そのものが短いため層単位同期の固定費が相対的に大きく、0.5要求/秒のQwen2.5-7Bでは重畳後0.762秒に対してプリフェッチ追加後0.765秒とわずかに悪化する。QwenのSSD再利用率は実験設定で約10%に留まり、Llamaの約20%よりSSD先読みの利得が小さい。また論文内の尾部遅延記述には、ある図のP99エンドツーエンド遅延を86msとする説明と、別図で3,000〜6,000msとする説明があり、図・指標条件の違いが本文だけでは明瞭でないため、尾部数値の横比較には注意が必要である。

### 結果の読み方
PCRの利得は、単にSSD容量を足したことではなく、I/Oを隠せる時間軸を二つ作ったことから生じる。PCIe転送はTransformer層間の計算時間へ重ね、SSD読出しはスケジューラ待機時間へ重ねる。したがってKVが大きいほど前者の削減余地が増え、高要求率で待機列が長いほど後者の削減余地が増える。一方、低負荷・小KV・再利用率が低い条件では重畳やプリフェッチの固定費が相対的に増え、改善幅が小さくなる。
## 品質への影響
PCRは位置依存性を保った正確な接頭辞一致KVだけを再利用し、再利用できないチャンクは通常のプリフィルで再計算する。KV圧縮や位置非依存近似を導入しないため、PCR固有の高速化によるモデル出力品質の近似損失は想定しない。
## 既存研究との差
RAGCacheなどが接頭辞KVの保存・追い出しを主に最適化するのに対し、PCRはCPU–GPU転送とSSD読出しを明示的なスケジューリング対象へ加える。LMCacheもGPU・CPU・SSD階層を扱うが、PCRはvLLM待機列を将来需要の確定手掛かりとしてLRU保護とSSD→DRAM先読みの両方へ使い、さらに層単位の双方向KV転送をGPU計算と重ねる。CacheBlendや位置非依存チャンク再利用のように再計算を省くための近似を使わず、正確な接頭辞一致に限定して品質を維持する。
## 限界
評価は単一サーバー内のA6000/RTX 4090と4TB NVMe SSDに限られ、ネットワーク越しのKVストア、複数ノード、複数SSD、障害復旧は扱わない。平均入力約6.8k・出力16トークンというプリフィル支配型RAGを対象とし、長いデコードや共有接頭辞が乏しい負荷での利得は不明である。待機列プリフェッチは高負荷ほど有利だが、低負荷では先読み時間が短い。先読み窓もLlama2-7Bでは6が最良だっただけでモデルごとの調整が必要。一次資料に公式コード公開先がなく、本文の尾部遅延数値には条件の読み分けが難しい箇所がある。
## 実装状態
vLLM上に実装し、256トークンKVチャンク、接頭辞木、待機列連携、CUDA 12.8のcudaMemcpyBatchAsync、3ストリーム転送重畳、SSDプリフェッチ専用スレッドを用いた実機評価を報告する。2026-09-14時点でarXiv一次資料から著者公式コード公開URLは確認できない。
## 研究上の位置づけ
KVキャッシュのオフロード・再計算回避とRAG配信最適化の交点に位置する。特にNVMe SSDを容量拡張に使うだけでは同期I/Oが再計算利得を消すため、CPU DRAMを中間キャッシュとして使い、要求待機列からSSD I/Oを先行発行する設計を示す。SSD/NVMeをLLM推論へ活用する研究では、データ配置だけでなく「実行前にどれだけ確実な未来需要が見えるか」をI/Oスケジューリングへ結び付ける比較軸を提供する。
