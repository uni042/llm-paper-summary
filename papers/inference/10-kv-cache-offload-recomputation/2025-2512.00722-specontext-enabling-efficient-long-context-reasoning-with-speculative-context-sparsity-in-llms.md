# SpeContext: Enabling Efficient Long-context Reasoning with Speculative Context Sparsity in LLMs

> 蒸留モデルと元LLMの情報注目の類似を利用し軽量検索ヘッドで重要KVを先読みする。非同期プリフェッチ、差分転送、適応メモリ管理によりクラウド最大24.89倍、エッジ最大10.06倍を報告する。

## 概要

長文推論では生成とともにKVが増え、層ごとの重要KV検索とオフロード復元が同期点になる。

蒸留モデルから埋め込みとQK射影中心の軽量検索ヘッドを作り90%以上のパラメータを削る。本体より先に重要トークンを予測し、KVを非同期転送する。隣接ステップで選択KVが重なるため差分だけを転送し、メモリモデルでGPU常駐量も調整する。

代表評価では、Hugging Face系比較でクラウド最大24.89倍のスループット、エッジ最大10.06倍の高速化を精度低下を小さく保って達成する。 数値は論文固有のモデル、ハードウェア、要求分布、系列長で得られたもので、異なる環境へ倍率をそのまま外挿しない。

## 問題設定

長文推論では生成とともにKVが増え、層ごとの重要KV検索とオフロード復元が同期点になる。

大規模言語モデル（Large Language Model; LLM）の実行では演算性能だけでなく、重みやキー・値キャッシュ（Key-Value cache; KVキャッシュ）の容量、高帯域メモリ、GPU間通信、バッチ形成、待ち行列が律速になる。理論演算量の削減だけでは実測高速化を保証できない。

対象内部には入力長、生成長、注意パターン、外れ値、推論段階、資源量などの不均一性がある。固定方針では過剰計算や品質低下が生じるため、本研究はその差を観測して処理経路へ反映する。

## 手法の全体像

蒸留モデルから埋め込みとQK射影中心の軽量検索ヘッドを作り90%以上のパラメータを削る。本体より先に重要トークンを予測し、KVを非同期転送する。隣接ステップで選択KVが重なるため差分だけを転送し、メモリモデルでGPU常駐量も調整する。

基本処理は状態観測、方針決定、本体処理への反映、状態更新である。補助判断にも費用があるため、本体側で省ける演算・転送・待機が十分大きい条件ほど効果が出る。

## 手法

### 1. 観測

要求属性、モデル内部統計、資源量、キャッシュ状態など対象律速に直結する情報を取得する。校正時に一度計算できる統計と実行時に更新すべき情報を分け、オンライン制御費用を抑える。

観測の目的は未来を完全に予測することではなく、高価な本体処理を省略・再配置しても影響が小さい候補を安価に識別することである。

### 2. 選択と実行

蒸留モデルから埋め込みとQK射影中心の軽量検索ヘッドを作り90%以上のパラメータを削る。本体より先に重要トークンを予測し、KVを非同期転送する。隣接ステップで選択KVが重なるため差分だけを転送し、メモリモデルでGPU常駐量も調整する。

決定結果は実データ経路へ反映し、演算を発行しない、メモリから読まない、通信を減らす、別資源へ移す、要求順を変えるなどハードウェア上の仕事量を減らす。

細粒度最適化は柔軟だが不規則アクセスを増やすため、タイル、ブロック、要求、層、段階などGPUや分散実行系が扱いやすい粒度が重要になる。

### 3. 状態更新

校正統計、コンパイル結果、キャッシュ、予測器など複数要求で再利用できる情報は保持し、入力依存性が高い情報だけ更新する。近似方式では品質、無損失方式でも余分な転送や待機として誤判断の費用が現れる。

### 4. 実行フロー

要求またはジョブ到着後、入力処理と必要統計を取得し今回の実行方針を決める。本体モデルはその方針に従って必要な演算と転送を行い、結果と状態を次段へ渡す。

配信では同時要求間の干渉、学習では障害復旧や再配置も総費用に含める。提案方式はこれらを含む総処理量を減らすことを狙う。

## 評価

Hugging Face系比較でクラウド最大24.89倍のスループット、エッジ最大10.06倍の高速化を精度低下を小さく保って達成する。

比較ではモデル、GPU、系列長、バッチ、品質条件を揃える。カーネル単体、モデル全体、クラスタ全体の倍率、容量削減と実時間短縮を混同しない。

近似では元モデルとの差、配信では平均遅延だけでなく裾遅延やサービス品質目標（Service-Level Objective; SLO）も確認する。

## 既存研究との差

固定した量子化、注意カーネル、並列方式、要求順、資源割当を使う方式に対し、対象の構造や実行状態を利用して処理経路を変える。安全側の過剰計算と強過ぎる削減の間を狙う。

アルゴリズムだけでなく、コンパイラ、メモリ階層、GPUカーネル、分散配置、スケジューラへ接続して実システム指標で評価する点が重要である。

## 限界・実装状況

蒸留モデルと教師の情報注目が十分一致することが前提で、モデル組合せごとに検索精度確認が必要である。

評価と異なるGPU世代、相互接続、CPU-GPU帯域、モデル規模、要求分布では律速が移る。既存基盤への統合にはメモリ管理やスケジューラとの接続も必要になる。

## 一般的な実装上の含意

削減率より、削減が連続メモリアクセス、大きな行列演算、通信重畳、同時処理数増加へ変換できるかを見る。補助制御を含むエンドツーエンド時間を優先する。

品質を変える方式では速度と同じ設定で品質を測り、平均値だけでなく長文、負荷急変、分布変化、裾遅延も確認する。
