# InstAttention: In-Storage Attention Offloading for Cost-Effective Long-Context LLM Inference

> KV cacheを計算機能付きSSD内へ置き、decode attentionもSSD内部で実行することで、巨大なKVをSSDからGPUへ毎token読み戻す転送を避けるlong-context推論system。

旧preprint名は **InstInfer**（arXiv:2409.04992）。HPCA 2025採択版では **InstAttention** に改題されているため、同一研究としてこのページへ集約する。

## 概要

InstAttentionは、SSDへKV cacheを置く従来offloadではdecodeのたびにKVをSSD→host→GPUへ読み戻すI/Oがbottleneckになる問題を、**attention計算そのものをstorage側へ移す**ことで解消する。

対象hardwareは通常のNVMe SSDではなく、SSD controller付近にFPGA等の計算資源を持つ **Computational Storage Drive（CSD）** である。GPUはQKV projection、O projection、FFNなどを担当し、CSDは大量のKV cacheをflashへ保存すると同時にdecode attentionを実行する。

この設計ではPCIeを通るのは主に現在tokenの小さいq/k/vとattention outputになり、KV cache全体はSSD内部のflash channelからattention engineへ直接読まれる。**SSD外部のPCIe帯域ではなく、SSD内部で複数flash chipを束ねた帯域を使う**ことが中心である。

## 問題設定

long-context・large-batchのoffline inferenceではKV cache容量がmodel weightを超えることがある。論文では13B model、batch=32、4K tokensの例でKV cacheを約100GB、model sizeの約4.2倍と見積もる。

FlexGen等はSSD容量を利用できるが、decode attentionではKV cacheを繰り返しGPUへ読み込む必要があり、SSD外部のPCIe bandwidthが支配的になる。

CSDには大容量flashと内部帯域がある一方、計算能力はGPUより低い。そのためInstAttentionはdecode全体をstorageへ移すのではなく、**KV accessが多い割に計算量が比較的小さいattentionだけをCSDへ切り出す**。

## 手法

### 1. Decode attentionだけをCSDへoffloadする

GPUにはmodel weightとactivationを置き、prefillは基本的にGPUで実行する。decodeではQKV projection、O projection、FFNをGPUに残し、KV cacheを読むattention部分だけをCSDへ移す。

attention側はmodel parameterをほぼ必要とせず、主にKVを読み続けるmemory-bandwidth-heavyな処理なので、GPUより計算性能が低いstorage-side acceleratorでも担当しやすい。

### 2. GPUとCSDをhost memory経由なしで接続する

従来SSD offloadではhost filesystemとhost memoryを経由する。InstAttentionはGPUとCSD間のPCIe peer-to-peer DMAを使い、hostへの余分なcopyを避ける。

prefillで生成したKVもlayer単位でCSDへ送るため、一時KV bufferがGPU VRAMを圧迫しにくい。host CPUはrequest管理・scheduling・data movement coordinationを中心に担当する。

### 3. Flashから読むKV自体も重要token中心へ減らす

CSD内部帯域もGPU HBMより低いため、dense attentionをそのままstorageで処理するとKV read量が大きい。

そこで論文はSparQをflash access向けに変更した **SparF Attention** を使う。

まずqueryの一部dimensionだけを使って「どの過去tokenが重要そうか」を安く推定し、その後、重要と判断したtokenの完全なK/Vだけを読む。

つまり、

1. queryの一部dimensionで候補tokenを粗く絞る
2. 重要tokenだけ完全なKVをflashから読む
3. そのKVで最終attentionを計算する

という流れでstorage readを減らす。

### 4. Flash page単位で読みやすい形へKV accessをまとめる

通常のsparse attentionは必要tokenを細かくrandom accessするが、NAND flashはpage単位で読む方が効率がよい。

InstAttentionは複数tokenをflash pageに合うgroupへまとめ、まずpage単位で候補を読み、SSD controller側で不要部分をさらに除外する。

これによりattention sparsityを利用しつつ、細かすぎるflash readを大量発行する無駄を抑える。

### 5. KV専用のflash配置を使う

SSDはlogical addressを実際のflash位置へ変換するmapping layerを持つ。一般にFlash Translation Layer（FTL）と呼ばれる。

InstAttentionは、Kをtoken方向・hidden dimension方向の両方から効率よく読めるように、このmappingとKV layoutを専用化する。

つまり単に「KVをファイルとしてSSDへ保存する」のではなく、**attentionが読む順序に合わせてflash上の物理配置まで設計する**。

## 評価

### 条件

| 項目 | 条件 |
|---|---|
| GPU | NVIDIA A6000 48GB |
| CPU | Intel Xeon 5320 2.2GHz |
| Host memory | 96GB DDR4 |
| Storage baseline | Samsung 980 Pro 2TB |
| CSD compute | Zynq-7045 FPGAベースのInstCSD |
| 想定flash構成 | 8 channels × 1.4GB/s = 11.2GB/s internal bandwidth |
| Model | OPT-13B（accuracyではLLaMA-2-7Bも使用） |
| Precision | FP16 |
| Sequence | input 1024 + output 1024 |
| Dataset | ShareGPT / WikiText-2 / SQuAD / TriviaQA |
| Baseline | DeepSpeed-MII + ZeRO-Inference、FlexGen、FlexGen + SparQ |

### Throughput

1 CSDのdense InstAttentionはbatch=64でFlexGenを **6.85倍**上回った。

SparFを1/8 KV比率で使うとdense InstAttentionから最大 **2.08倍**向上し、batch=256でFlexGen比 **最大11.1倍**のthroughputを報告する。

2 CSD構成ではdense InstAttentionがFlexGenの最大throughputを10.5倍上回った。論文の拡張scaling評価では1→20 CSDでdense 8.99倍、SparF 7.29倍のthroughput向上を示す。

### KV accessとaccuracy

latency breakdownでは、FlexGen batch=64でdecode latencyの98.9%を占めるKV access部分に対し、dense InstAttentionはKV access overheadを大幅に削減する。論文は構成によりKV cache access overheadを最大94.0%削減したと報告する。

SparFはlosslessではないが、1/8設定までのaccuracy低下は論文評価では小さく、SparQと近い挙動を示した。したがって **dense InstAttentionはKV placement / attention offload、InstAttention + SparFはそれに近似的なKV sparsityを加えた構成**として分けて読む必要がある。

## 既存研究との差

### FlexGenとの違い

FlexGenでは通常SSDは低価格な保存階層で、KVは計算時にGPU側へ持ってくる。InstAttentionはCSD内部でattentionを実行するため、**KV cacheをPCIeの外へ出さず、storage内部帯域で消費する**。

### FastDecodeとの違い

FastDecodeもKV cacheとattentionをGPU外へ移すが、実行先は複数CPU nodeのDRAMである。InstAttentionはさらに低価格・大容量なflashへKVを置き、SSD controller近傍の専用acceleratorでattentionを処理する。

両者は「KVをcomputeへ運ぶのではなくcomputeをKVへ近づける」という発想を共有する。

### Memory内部で計算する研究との違い

memory chipやstorageの近くに計算器を置く方式は一般にProcessing-in-Memory（PIM）/ near-data computingと呼ばれる。

論文執筆時点ではこうしたLLM attention研究の多くがsimulation中心だったのに対し、InstAttentionはFPGA-based CSD上のattention engineを実装・評価している。ただし市販汎用SSDでそのまま使えるわけではなく、専用hardware設計を含むprototypeである。

## 限界

- 一般的なNVMe SSDだけでは使えず、attention engineとKV-aware controllerを持つCSDが必要。
- 評価modelの中心はOPT-13Bで、現代的なGQA / MQAや非常に大きいmodelでの検証は限定的。
- 最大11.1倍の結果はapproximateなSparF 1/8設定を含み、dense版とは品質条件が異なる。
- SparFはattention approximationを使うためlosslessではない。
- flash random accessに合わせた専用mapping / data layoutが必要で、既存SSD software stackへ簡単に追加できる機構ではない。
- 多数CSDへのscalingはhardware cost・PCIe topology・実装複雑性を伴う。
- preprintではopen-source予定と記載されていたが、2026-09-06時点で著者による完全な公式実装repoは確認できなかった。

## 一般的な実装上の含意

InstAttentionが示すのは、NVMe offloadの性能を外部PCIe bandwidthだけで考える必要はないという点である。storage内部のflash bandwidthが外部interfaceより高い場合、**KV cacheをstorageからGPUへ読み出すのではなく、KVを大量に読むattention計算をstorage側へ押し込む**ことで内部帯域を利用できる。

一方、そのためにはattention algorithmをflash page粒度やcontroller architectureへ合わせる必要があり、単純なGPU kernel移植では足りない。SSD / CSD offload研究では、capacity・external I/Oだけでなく、device内部帯域とstorage側計算機能の有無を分けて評価する必要がある。
