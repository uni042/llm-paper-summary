# InstAttention: In-Storage Attention Offloading for Cost-Effective Long-Context LLM Inference

## 概要

InstAttention（プレプリント名InstInfer）は、長文脈・大バッチの大規模言語モデル推論で、鍵・値キャッシュをSSDへ退避するとGPUへの読戻し転送が律速になる問題を扱う。従来のSSD退避では、復号時の注意計算に必要な過去の鍵・値をSSDからホスト経由でGPUへ移動させるため、GPUメモリ容量を節約できても外部PCIe帯域が性能を制限する。InstAttentionは、鍵・値キャッシュをSSD内部に保存するだけでなく、そのキャッシュを大量に読む復号時の注意演算もSSD側へ移す。GPUへは現在トークンの小さいクエリなどと注意出力だけをやり取りし、SSD内部の多数のフラッシュチップを束ねた帯域を利用する。

対象装置は通常のNVMe SSDではなく、SSD制御装置の近くにFPGA等の計算機能を備えた計算機能付きストレージドライブ（Computational Storage Drive; CSD）である。GPUは入力一括処理、重みを使う射影、前向き結合層などを担当し、CSDは復号時の注意と鍵・値キャッシュの保存を担当する。CSDはGPUより計算能力が大幅に低いため、モデル全体をSSDへ移すのではなく、計算量の割にキャッシュ読出し量が多い部分だけを移すのが設計の核心である。

論文は、フラッシュに適した疎注意（SparF）、ページ単位の粗い読出しと細かい絞込み、鍵・値の二種類のアドレス対応、GPUとCSDの直接転送を組み合わせる。OPT-13BをNVIDIA A6000と組み合わせた評価では、従来のSSD退避システムFlexGenと比べて最大11.1倍の処理量を報告する。ただし、この最大値は疎注意の近似を含む構成であり、実機CSDの計測と、それを基に較正した仮想SSDによる拡張構成を分けて解釈する必要がある。

## 問題設定と対象条件

大規模言語モデルの復号では、過去トークンの鍵・値を再計算せずキャッシュして再利用する。入力長と同時実行要求数が増えるほどキャッシュは大きくなる。論文の例では、13Bモデルをバッチ32・4096トークンで実行すると鍵・値キャッシュは約100GBとなり、モデル重みの約4.2倍の容量を要する。GPUの高価なメモリに全キャッシュを保持することが難しくなるため、ホストメモリやSSDへ退避する設計が現れる。

従来のSSD退避は容量面では有利だが、復号時にキャッシュをGPUへ戻すための転送が繰り返し発生する。論文のFlexGen分析では、バッチが大きくなると復号遅延のうち鍵・値キャッシュアクセスが最大98.94%を占める。SSDの外部インターフェースは数GB/秒程度でも、SSD内部の複数フラッシュチャネルを合計した帯域は数十GB/秒に達する場合がある。キャッシュをSSDから外へ出すのではなく、SSD内部で消費できれば、外部PCIe帯域を避けられる可能性がある。

しかしCSDの演算能力はGPUより二〜三桁小さいと論文は説明する。入力一括処理の注意、重みを使う行列演算、前向き結合層をCSDへ移すと、演算能力不足が新たな律速になる。InstAttentionは演算強度とメモリ帯域の関係を屋根線モデル（roofline model）で分析し、復号時の注意に含まれる対数値計算と値の加重和が、鍵・値の読出し量に対して計算量の小さい演算であると判断する。オフライン推論の大きなバッチと長い系列が主な対象であり、単一要求の最小遅延を重視するオンライン推論とは目的が異なる。

## 手法

### GPU・CSD・ホストの役割分担

InstAttentionはGPU側のInstGPU、計算機能付きSSD側のInstCSD、制御を担うInstHostからなる。入力一括処理ではGPUが通常の注意を含めてモデルを実行し、生成した鍵・値をCSDへ転送する。復号時にはGPUがクエリ・鍵・値の射影、注意後の射影、前向き結合層を担当し、CSDが過去キャッシュを使う注意演算を担当する。ホストCPUは要求管理、スケジューリング、転送の調整を中心に行い、巨大なキャッシュを毎回ホストメモリへコピーする役割は持たない。

復号時にGPUからCSDへ渡すのは現在トークンのクエリなどの小さいベクトルであり、CSDは保存している過去の鍵・値を内部フラッシュから読み、注意出力をGPUへ返す。これにより、従来方式で必要だった過去キャッシュ全体のSSD→GPU転送を回避する。注意以外の重い演算はGPUに残すため、CSDの限られた計算能力を過度に消費しない。入力一括処理で生成したキャッシュは層単位に直接転送し、GPU上の一時バッファ量を抑える。

### SparFによる二段階の疎注意

密な注意をCSD内部で実行しても、過去の全鍵・値をフラッシュから読む負荷が大きい。そこで論文はSparQに基づくSparFを導入する。まず現在トークンのクエリ `q` の絶対値が大きい上位 `r` 個の隠れ次元を選び、それらの次元に対応する過去の鍵だけを読み出して近似的な注意スコアを求める。次に近似スコアの上位 `k` トークンを選び、そのトークンの完全な鍵・値を読み出して注意出力を計算する。選ばれなかった値ベクトルの寄与は平均値ベクトルを使った補償項で近似する。

この手順には二種類の索引が必要である。最初の粗いスコア計算では鍵を隠れ次元方向に読む必要があり、最後の注意計算では鍵と値をトークン方向に読む必要がある。したがって論文は、鍵キャッシュをトークン方向と隠れ次元方向の二通りに格納する。容量は増えるが、安価なフラッシュ容量を使って読み出し帯域と計算を節約するという交換条件である。SparFは近似的な注意であり、密な注意と数学的に完全一致するわけではない。

### フラッシュページに合わせた二段階読出し

NANDフラッシュの読出し単位はページであり、論文では4KBのページを想定する。一つの注意ヘッドの鍵または値が128次元・半精度なら、トークン一つ分は256バイトである。トークン単位の無作為アクセスをそのままフラッシュへ発行すると、必要なのは256バイトでも4KBを読むことになり、最大16倍の読出し粒度の不一致が生じる。SparFは複数トークンをページに収まるグループとして配置し、まずグループ単位で必要性を判定する。

第一段階では、グループ内のすべての要素が不要と判定されたページだけを読出し対象から除く。必要な要素が一つでも含まれるページはフラッシュからSSD制御装置内のバッファへ読む。第二段階では、制御装置側のフィルタがページ内の不要なトークンや隠れ次元を除き、注意計算器へ渡すデータ量を減らす。論文は、第一段階で疎性の約半分を維持し、第二段階で残りの不要部分を除去する設計を示す。フラッシュのページ粒度と注意の細粒度の選択を両立する仕組みである。

### 鍵・値専用のアドレス対応と書込み

トークン方向の格納では、128次元・半精度の場合、連続する16トークンを4KBページにまとめる。各注意ヘッドのグループを複数フラッシュチャネルへ分散配置し、読出しの並列性を高める。隠れ次元方向の格納では、特定の隠れ次元について多くのトークンを連続して読めるように配置する。論文は複数の隠れ次元をページにまとめ、入力長に応じてグループサイズを調整する方式を採る。これらの論理アドレスから物理ページへの対応は、通常のファイルシステム任せではなく、専用のフラッシュ変換層（Flash Translation Layer; FTL）が管理する。

復号では新しいトークンの鍵・値が少量ずつ発生するが、フラッシュは細かい書込みに不向きである。そのため新しい鍵・値をCSD内部のDRAMグループバッファへ蓄積し、十分たまってから背景処理でフラッシュへ書き戻す。複数の注意ヘッドにまたがるグループをまとめてブロックへ書き込むことで、書込み増幅を抑える。読出し時は同じヘッド内の複数グループを並列化し、書込み時は複数ヘッドをまとめるという、操作の違いに応じた配置が重要である。

### FPGA注意計算器と直接転送

InstCSDには、上位候補を選ぶ回路、注意スコアと加重和を計算する回路、各フラッシュチャネルの制御器に付属するフィルタを配置する。クエリの重要次元を選び、必要な鍵を読み、近似スコアから重要トークンを選び、完全な鍵・値を読んで注意出力を得る。鍵と値の読出しを重ねることや、複数のチャネルを使うことによりフラッシュの長いアクセス遅延を隠す。

GPUとCSDの間では、ピア間直接メモリアクセス（peer-to-peer DMA）を使ってホストメモリへの余分なコピーを避ける。入力一括処理で生成された鍵・値は層ごとに送られ、GPU側の演算と転送を重ねる。これにより、入力一括処理時にGPUメモリ上へ大きな一時キャッシュを保持する必要も抑えられる。通常のNVMe SSDへファイルを書き込むだけではこの仕組みを再現できず、専用の計算器、制御器、アドレス対応、ドライバが必要になる。

## 評価

### 実験基盤と比較条件

| 項目 | 論文の条件 | 解釈上の注意 |
|---|---|---|
| GPU | NVIDIA A6000、48GB | 一般的な単一GPUでの長文脈推論 |
| CPU・主記憶 | Intel Xeon 5320、96GB DDR4 | ホストメモリ退避との比較 |
| ストレージ | Samsung 980 Pro 2TB相当 | 従来SSD退避の比較対象 |
| CSD | Zynq7045 FPGA、8チャネル×1.4GB/秒 | 内部帯域11.2GB/秒の構成 |
| モデル | OPT-13B、半精度 | 主な処理量評価 |
| 入出力 | 入力1024、出力1024トークン | 長い復号と大きなキャッシュを想定 |
| データ | ShareGPT、WikiText-2、SQuAD、TriviaQA | 処理量と近似注意の品質を評価 |
| 比較方式 | DeepSpeed-MII、FlexGen、FlexGen+SparQ | 主記憶退避・SSD退避・疎注意との比較 |
| 提案方式 | 密なInstInfer、SparF付きInstInfer | ストレージ内計算単独と疎注意追加の寄与を区別 |

論文はDaisyplus OpenSSD上の実機試作で細かな遅延を測り、さらにソフトウェア定義の仮想NVMe装置であるNVMeVirtを使って、より実用的なZynq7045と8チャネル構成を評価する。元のOpenSSDは64GB・4チャネルなどの制約があり、現代の一般的なSSDにそのまま対応しない。したがって、最大20台への拡張などをすべて実物の市販CSDを並べて測った結果として扱ってはならない。論文は実機計測に基づく較正と、拡張構成の性能評価を組み合わせている。

### スループットと構成要素の寄与

| 評価 | 条件 | 主な結果 | 何を示すか |
|---|---|---|---|
| 密なストレージ内注意 | CSD1台、バッチ64 | FlexGen比6.85倍 | 鍵・値を外部へ戻さない効果 |
| 疎注意追加 | CSD1台、バッチ256 | 密なInstInferから最大2.08倍 | SparFによる内部読出し削減の追加効果 |
| 最大改善 | CSD1台、SparF 1/8、バッチ256 | FlexGen比最大11.1倍 | ストレージ内注意と疎性の複合効果 |
| 密な方式の最大処理量 | バッチ256 | DeepSpeedの最大処理量を約4.6%上回る | 内部フラッシュ帯域が主記憶より低い制約も残る |
| CSD2台 | バッチ256の密な方式 | FlexGenの最大処理量比10.5倍 | CSD間の注意分割と直接転送の効果 |
| CSD2台の疎方式 | バッチ256 | FlexGen+SparQの最大処理量比3.11倍 | 比較対象も疎注意を使う条件 |
| 20台への拡張 | バッチ256、1台比 | 密な方式8.99倍、疎方式7.29倍 | ヘッド単位分割の拡張可能性 |

最大11.1倍という値は、密な注意の単純な移動だけで得られた倍率ではない。密な方式が6.85倍となる条件と、SparFによって内部読出し量をさらに削減した最大改善の条件を区別する必要がある。疎注意は完全に同じ計算結果を保証するものではないため、密な方式と疎な方式は速度だけでなく品質条件も異なる。論文はSparFを1/8の設定で評価し、SparQに近い精度を維持すると報告するが、すべてのタスクで厳密に同一出力になるとは主張していない。

DeepSpeedはホストメモリの帯域が比較的高いため、バッチ4〜16では密なストレージ内注意より有利な場合がある。バッチが大きくなると主記憶容量を超え、SSDへの退避が発生して処理量が急落する。FlexGenはSSD退避で大きなバッチを扱えるが、鍵・値をGPUへ転送する外部帯域が律速となる。InstInferは層単位転送により入力一括処理の一時バッファも抑え、大きなバッチでのメモリ不足を避ける。

### 遅延内訳と近似注意の品質

FlexGenのバッチ64では、復号遅延のうち鍵・値アクセスが密な条件で約98.9%を占める。密なInstInferではこの割合が80.7%、CSD2台では76.4%へ下がる。疎な条件でも、FlexGen+SparQの92.4%に対して、InstInfer系は82.3%、CSD2台では74.0%となる。論文は構成に応じて鍵・値アクセスの実時間費用を最大94.0%削減したと報告するが、遅延全体が94%短くなったという意味ではない。割合の変化と絶対的なアクセス費用の削減を区別する必要がある。

SparFの精度評価はOPT-13BとLLaMA-2-7Bを使い、SparQ、H2O、局所注意と比較する。フラッシュのページ粒度に合わせた二段階読出しは、選ばれた重要トークンを注意計算器へ渡す前に不要部分を除くため、SparQと近い精度を維持しつつフラッシュ読出しを減らす。論文は1/8の設定まで精度低下が小さいと報告し、その設定を以後の主要な性能比較に用いる。ただし、選択されなかったトークンの寄与は補償項で近似しており、厳密な密注意と同じ数値を出すものではない。

### フラッシュチャネルと台数への感度

CSD台数を増やすと、注意ヘッド単位で鍵・値と計算を分割できるため、複数CSDの内部フラッシュ帯域を同時に使える。論文の拡張評価では、20台構成で1台比の処理量が密な方式8.99倍、疎な方式7.29倍となる。台数と比例した20倍にはならないため、GPU側処理やCSD間の割当て、残る転送などの制約が存在する。疎性を強める感度評価では、細かな無作為アクセスが増えても二段階読出しにより内部帯域の浪費を抑え、処理量が改善する傾向を示す。

FPGA資源の表では、Zynq7045のDSP資源の約85.33%、論理資源の約80.27%を使用する。これは専用注意計算器が軽いソフトウェア変更だけで成立するものではなく、装置内のハードウェア資源を相当程度消費することを示す。計算能力、内部帯域、フラッシュページ粒度のバランスが変わる装置では、同じ性能倍率を保証できない。

## 既存研究との差と適用範囲

FlexGenや一般的なSSD退避は、SSDを安価な容量階層として使い、計算時には鍵・値をGPUへ戻す。InstAttentionは鍵・値の保存先で注意を計算し、ストレージ内部の帯域を使う点が本質的に異なる。FastDecodeのようにCPUや主記憶側へ注意を移す方式とは、安価なフラッシュ容量と専用のCSD計算器を組み合わせる点が異なる。メモリ内計算を使う研究と近い発想だが、フラッシュのページ粒度、アドレス変換、書込み増幅まで設計対象に含める。

推論基盤の実装では、鍵・値をどのメモリ階層に置くかだけでなく、その階層で注意計算を行えるかどうかが重要になる。CSDに計算器がない通常のSSDでは、同じデータフローを実行できない。また、GPUとCSDの直接DMA、フラッシュ変換層の変更、鍵・値の二重配置を必要とするため、既存のSSD退避実装へそのまま追加できるソフトウェア最適化ではない。

## 限界と負の結果

第一に、専用の計算機能付きSSDが必要である。一般的なNVMe SSDは大容量の保存先として使えても、SparFの注意計算器や鍵・値専用のアドレス対応を備えていない。論文の評価は実機試作と較正した仮想SSD構成を含むため、最大11.1倍をあらゆる市販SSDで再現できると解釈してはならない。

第二に、SparFは近似的な注意である。1/8の設定で精度低下が小さいと報告されるが、すべての入力で完全な注意と同じ結果を保証しない。最大処理量の倍率は近似注意を含むため、完全に同一の計算を要求する用途では密な構成を別に評価する必要がある。さらに鍵を二種類の向きで保存するため、ストレージ容量を帯域と交換する費用も発生する。

第三に、主な処理量評価はOPT-13B、入力1024・出力1024、単一A6000を中心とする。現代のグループ化クエリ注意、マルチクエリ注意、大規模混合専門家モデル、複雑な分散推論の性能を包括的に検証したものではない。主目的はオフライン推論の大バッチ処理量であり、オンライン対話の最初のトークン遅延を必ず改善する方式ではない。

第四に、CSD内部帯域がGPUとホスト主記憶間の帯域より低い場合、密な方式だけでは高帯域の主記憶退避を大きく上回れない。論文でも密な方式の最大処理量はDeepSpeedの最大値を約4.6%上回る程度である。SparFによる読出し削減が重要になる一方、その疎性は精度との交換条件を持つ。

第五に、フラッシュへの頻繁な書込みや鍵・値の二重配置は、書込み増幅、寿命、容量利用率、制御器の複雑さに影響する。論文は専用FTLとバッチ書込みでこれを緩和するが、実運用での長期耐久性や大規模導入の総費用を完全に評価したわけではない。CSD台数の拡張も20台で線形の20倍にはならず、装置数の増加に伴うGPU側や転送の制約が残る。
