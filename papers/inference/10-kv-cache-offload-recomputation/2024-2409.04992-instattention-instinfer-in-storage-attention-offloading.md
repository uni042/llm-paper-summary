# InstAttention: In-Storage Attention Offloading for Cost-Effective Long-Context LLM Inference

> KV キャッシュを計算機能付きSSD内へ置き、デコード アテンションもSSD内部で実行することで、巨大なKVをSSDからGPUへ毎トークン読み戻す転送を避ける長文脈推論システム。

旧プレプリント名は **InstInfer**（arXiv:2409.04992）。HPCA 2025採択版では **InstAttention** に改題されているため、同一研究としてこのページへ集約する。

## 概要

InstAttentionは、SSDへKV キャッシュを置く従来オフロードではデコードのたびにKVをSSD→ホスト→GPUへ読み戻すI/Oがボトルネックになる問題を、**アテンション計算そのものをストレージ側へ移す**ことで解消する。

対象ハードウェアは通常のNVMe SSDではなく、SSD 制御装置付近にFPGA等の計算資源を持つ **Computational ストレージ ドライブ（CSD）** である。GPUはQKV 射影、O 射影、FFNなどを担当し、CSDは大量のKV キャッシュをflashへ保存すると同時にデコード アテンションを実行する。

この設計ではPCIeを通るのは主に現在トークンの小さいq/k/vとアテンション outputになり、KV キャッシュ全体はSSD内部のflash チャネルからアテンション エンジンへ直接読まれる。**SSD外部のPCIe帯域ではなく、SSD内部で複数flash チップを束ねた帯域を使う**ことが中心である。

## 問題設定

長文脈・大バッチのoffline 推論ではKV キャッシュ容量がモデル 重みを超えることがある。論文では13B モデル、バッチ=32、4K トークンの例でKV キャッシュを約100GB、モデル sizeの約4.2倍と見積もる。

FlexGen等はSSD容量を利用できるが、デコード アテンションではKV キャッシュを繰り返しGPUへ読み込む必要があり、SSD外部のPCIe 帯域が支配的になる。

CSDには大容量flashと内部帯域がある一方、計算能力はGPUより低い。そのためInstAttentionはデコード全体をストレージへ移すのではなく、**KV accessが多い割に計算量が比較的小さいアテンションだけをCSDへ切り出す**。

## 手法

### 1. Decode attentionだけをCSDへoffloadする

GPUにはモデル 重みと活性値を置き、プリフィルは基本的にGPUで実行する。デコードではQKV 射影、O 射影、FFNをGPUに残し、KV キャッシュを読むアテンション部分だけをCSDへ移す。

アテンション側はモデル パラメータをほぼ必要とせず、主にKVを読み続けるメモリ帯域律速な処理なので、GPUより計算性能が低いストレージ側 アクセラレータでも担当しやすい。

### 2. GPUとCSDをhost memory経由なしで接続する

従来SSD オフロードではホスト filesystemとホスト メモリを経由する。InstAttentionはGPUとCSD間のPCIe peer-to-peer DMAを使い、ホストへの余分なcopyを避ける。

プリフィルで生成したKVも層単位でCSDへ送るため、一時KV バッファがGPU VRAMを圧迫しにくい。ホスト CPUは要求管理・スケジューリング・data movement 調整を中心に担当する。

### 3. Flashから読むKV自体も重要token中心へ減らす

CSD内部帯域もGPU HBMより低いため、密 アテンションをそのままストレージで処理するとKV read量が大きい。

そこで論文はSparQをflash access向けに変更した **SparF アテンション** を使う。

まずクエリの一部次元だけを使って「どの過去トークンが重要そうか」を安く推定し、その後、重要と判断したトークンの完全なK/Vだけを読む。

つまり、

1. クエリの一部次元で候補トークンを粗く絞る
2. 重要トークンだけ完全なKVをflashから読む
3. そのKVで最終アテンションを計算する

という流れでストレージ readを減らす。

### 4. Flash page単位で読みやすい形へKV accessをまとめる

通常の疎 アテンションは必要トークンを細かくrandom accessするが、NAND flashはページ単位で読む方が効率がよい。

InstAttentionは複数トークンをflash ページに合うグループへまとめ、まずページ単位で候補を読み、SSD 制御装置側で不要部分をさらに除外する。

これによりアテンション 疎性を利用しつつ、細かすぎるflash readを大量発行する無駄を抑える。

### 5. KV専用のflash配置を使う

SSDは論理的 addressを実際のflash位置へ変換する対応付け 層を持つ。一般にFlash Translation 層（FTL）と呼ばれる。

InstAttentionは、Kをトークン方向・hidden 次元方向の両方から効率よく読めるように、この対応付けとKV 配置を専用化する。

つまり単に「KVをファイルとしてSSDへ保存する」のではなく、**アテンションが読む順序に合わせてflash上の物理配置まで設計する**。

## 評価

### 条件

| 項目 | 条件 |
|---|---|
| GPU | NVIDIA A6000 48GB |
| CPU | Intel Xeon 5320 2.2GHz |
| Host memory | 96GB DDR4 |
| Storage baseline | Samsung 980 Pro 2TB |
| CSD compute | Zynq-7045 FPGAベースのInstCSD |
| 想定flash構成 | 8 channels × 1.4GB/s = 11.2GB/s internal bandwidth |
| Model | OPT-13B（accuracyではLLaMA-2-7Bも使用） |
| Precision | FP16 |
| Sequence | input 1024 + output 1024 |
| Dataset | ShareGPT / WikiText-2 / SQuAD / TriviaQA |
| Baseline | DeepSpeed-MII + ZeRO-Inference、FlexGen、FlexGen + SparQ |

### Throughput

1 CSDの密 InstAttentionはバッチ=64でFlexGenを **6.85倍**上回った。

SparFを1/8 KV比率で使うと密 InstAttentionから最大 **2.08倍**向上し、バッチ=256でFlexGen比 **最大11.1倍**のスループットを報告する。

2 CSD構成では密 InstAttentionがFlexGenの最大スループットを10.5倍上回った。論文の拡張拡張評価では1→20 CSDで密 8.99倍、SparF 7.29倍のスループット向上を示す。

### KV accessとaccuracy

遅延 breakdownでは、FlexGen バッチ=64でデコード 遅延の98.9%を占めるKV access部分に対し、密 InstAttentionはKV access オーバーヘッドを大幅に削減する。論文は構成によりKV キャッシュ access オーバーヘッドを最大94.0%削減したと報告する。

SparFは無損失ではないが、1/8設定までの正確度低下は論文評価では小さく、SparQと近い挙動を示した。したがって **密 InstAttentionはKV 配置 / アテンション オフロード、InstAttention + SparFはそれに近似的なKV 疎性を加えた構成**として分けて読む必要がある。

## 既存研究との差

### FlexGenとの違い

FlexGenでは通常SSDは低価格な保存階層で、KVは計算時にGPU側へ持ってくる。InstAttentionはCSD内部でアテンションを実行するため、**KV キャッシュをPCIeの外へ出さず、ストレージ内部帯域で消費する**。

### FastDecodeとの違い

FastDecodeもKV キャッシュとアテンションをGPU外へ移すが、実行先は複数CPU nodeのDRAMである。InstAttentionはさらに低価格・大容量なflashへKVを置き、SSD 制御装置近傍の専用アクセラレータでアテンションを処理する。

両者は「KVをcomputeへ運ぶのではなくcomputeをKVへ近づける」という発想を共有する。

### Memory内部で計算する研究との違い

メモリ チップやストレージの近くに計算器を置く方式は一般にProcessing-in-Memory（PIM）/ near-data computingと呼ばれる。

論文執筆時点ではこうしたLLM アテンション研究の多くがシミュレーション中心だったのに対し、InstAttentionはFPGA-based CSD上のアテンション エンジンを実装・評価している。ただし市販汎用SSDでそのまま使えるわけではなく、専用ハードウェア設計を含むprototypeである。

## 限界

- 一般的なNVMe SSDだけでは使えず、アテンション エンジンとKV-aware 制御装置を持つCSDが必要。
- 評価モデルの中心はOPT-13Bで、現代的なGQA / MQAや非常に大きいモデルでの検証は限定的。
- 最大11.1倍の結果はapproximateなSparF 1/8設定を含み、密版とは品質条件が異なる。
- SparFはアテンション approximationを使うため無損失ではない。
- flash random accessに合わせた専用対応付け / data 配置が必要で、既存SSD software stackへ簡単に追加できる機構ではない。
- 多数CSDへの拡張はハードウェア コスト・PCIe topology・実装複雑性を伴う。
- プレプリントではopen-source予定と記載されていたが、2026-09-06時点で著者による完全な公式実装repoは確認できなかった。

## 一般的な実装上の含意

InstAttentionが示すのは、NVMe オフロードの性能を外部PCIe 帯域だけで考える必要はないという点である。ストレージ内部のflash 帯域が外部interfaceより高い場合、**KV キャッシュをストレージからGPUへ読み出すのではなく、KVを大量に読むアテンション計算をストレージ側へ押し込む**ことで内部帯域を利用できる。

一方、そのためにはアテンション algorithmをflash ページ粒度や制御装置 architectureへ合わせる必要があり、単純なGPU カーネル移植では足りない。SSD / CSD オフロード研究では、容量・external I/Oだけでなく、device内部帯域とストレージ側計算機能の有無を分けて評価する必要がある。
