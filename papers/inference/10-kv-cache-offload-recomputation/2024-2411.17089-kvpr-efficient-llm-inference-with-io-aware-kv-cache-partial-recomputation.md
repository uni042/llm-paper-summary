# KVPR: Efficient LLM Inference with I/O-Aware KV Cache Partial Recomputation

> KVPRはCPU上のKVの一部を小さい中間活性値からGPUで再計算し、残りのKV転送と並行してPCIe待ちを減らす無損失方式。

## 概要

A100 40GB＋PCIe 4.0 x16（32GB/s）でOPT-6.7B/13B/30Bなどを評価し、OPT-6.7Bの遅延はHugging Face Accelerate比で最大35.8%削減した。再計算したKVと転送したKVを結合するため、これは近似注意ではなく無損失な実行経路の比較である。


KVPRは、KV キャッシュをCPU DRAMへオフロードしたときにPCIe転送がデコードのボトルネックになる問題に対し、**KV キャッシュの一部を転送せずGPUで再計算する**研究である。

通常は過去トークンのKV キャッシュをCPUからGPUへ読み込んで注意機構を計算する。KVPRでは過去トークンに対応する、K/Vを作る前の中間活性値の一部を先にGPUへ送り、その活性値からK/Vを再計算する。同時に、残りのKV キャッシュはCPUからGPUへ非同期転送する。

GPUは「KVを待ってidleになる」のではなく、**転送待ち時間をKV再計算に使う**。どこまで再計算し、どこから転送するかは固定せず、モデル・系列 長さ・バッチ 大きさ・GPU性能・PCIe帯域を事前測定して自動決定する。

近似注意機構やKV削除ではなく、最終的なKVは再計算分と転送分を結合して通常どおり注意機構を行うため、**計算結果を変えずに「運ぶ仕事」と「作り直す仕事」を交換する無損失なシステム 最適化**である。

## 問題設定

KV キャッシュ オフロードはVRAMを節約できる一方、系列 長さとバッチ 大きさが増えるほどCPU→GPU 転送が大きくなる。

論文のA100 / PCIe 4.0 x16環境では、バッチ=32・系列 長さ=1024で、OPT-30Bの1 層分のKV キャッシュ転送が約27.3 msなのに対し、対応するK/V 射影再計算は約0.61 msであり、**KVを運ぶ方が計算し直すより1桁以上高い**条件が存在する。

ただし全部再計算するとGPU 計算がボトルネックになる。したがってKVPRは、**転送と再計算がほぼ同時に終わる比率**を求める。

SSD / NVMeから直接KVを読む研究ではなく、主評価は**CPU DRAM ↔ GPU HBM間のPCIe I/O**である。

## 手法

### 1. Activationを先に送りKVの一部を再計算する

CPU側にはKV キャッシュだけでなく、そのKVを生成した入力活性値を保持する。

各層で、スケジューラが再計算対象にした部分の活性値を先にGPUへ送り、K/V 射影をGPUで再実行する。活性値は対応するK/Vの2つのキャッシュをまとめて送るより小さいため、同じトークン範囲をKVとして転送するよりPCIe trafficを減らせる。

残りのKV キャッシュは通常どおりCPUからGPUへ送り、最後に再計算分と結合して注意機構を実行する。

### 2. 再計算とKV transferを並行させる

KVPRの核心は、単に「一部を再計算する」ことではなく、**GPUでK/Vを作り直す処理とPCIeで残りKVを運ぶ処理を同時進行させる**点にある。

再計算側が先に終わればGPUは残りKV待ちになり、転送側が先に終わればPCIe側の余力を使い切れない。そのため両者の時間が揃う比率を狙う。

### 3. 実測値から「何割を再計算するか」を自動決定する

profilerはモデル、バッチ 大きさ、系列 長さ、GPU performance、PCIe 帯域などを測定する。

スケジューラはその情報から、再計算するKV量と転送するKV量を**制約条件の下で総時間が小さくなる組合せを解く最適化**で決める。論文の線形 programmingはこの割合決定に使われる。

遅延重視ではトークン方向に少量ずつ進める予定、スループット重視では複数リクエスト/層の転送と計算をまとめて重ねる予定を使い分ける。ランタイムは活性値 / KV キャッシュのメモリ管理とCUDA ストリームによる非同期転送・計算を実行する。

### 4. Weight loadingともpipeline化する

重みもCPUへオフロードするスループット-oriented構成では、KV再計算だけを単独で行うと重み 転送が次のボトルネックになる。

KVPRはKV 再計算と次に必要な重み loadingも重ね、small バッチでKVが小さい場合にも余計な再計算費用が本来の実行時間へ出にくいようにする。

### 5. KV quantizationとも併用できる

論文では、複数要素をまとめた単位ごとにscaleを持たせるグループ-wise 4-ビット KV キャッシュ 圧縮も評価している。KVを圧縮すれば転送量そのものが減るが、KVPRはその上で残ったI/Oと再計算を重ねられるため、両者は競合する手法ではなく併用可能である。

量子化を併用すると最適な再計算比率も変わる。KVを4 ビットへ圧縮すればCPU→GPUで運ぶbyteが減るため、full-精度 KVを前提にしたときより転送側が早く終わり、再計算へ回す割合を小さくした方がよい場合がある。一方で転送したKVには逆量子化の費用も加わるため、profilerは圧縮後の実測転送時間と復号費用を含めて再び分担を決める必要がある。つまりKV量子化はI/Oそのものを小さくするつまみ、KVPRは残ったI/OをGPU計算へ置き換えて同時進行させるつまみであり、両方を使う場合もハードウェアごとに均衡 点を測ることが重要になる。

## 評価

### 条件

| 項目 | 条件 |
|---|---|
| GPU | NVIDIA A100 40GB |
| CPU | AMD EPYC 64 コア, 2.6GHz |
| CPU-GPU | PCIe 4.0 x16、32GB/s |
| Model | OPT-6.7B / 13B / 30B、追加評価でLlama2-7B / 13B |
| 遅延 比較対象 | DeepSpeed Inference、Hugging Face Accelerate |
| スループット 比較対象 | FlexGen |
| 実装 | Transformers 4.46.1 + FlexGenベース |

### 主要結果

遅延-oriented評価では、OPT-6.7BでHugging Face Accelerate比**最大35.8% 遅延削減**を報告した。

スループット-oriented評価ではFlexGen比で、

- OPT-6.7B: 最大15.1%
- OPT-13B: 最大46.2%
- OPT-30B: 最大29.0%

のデコード スループット改善を報告している。

また代表構成ではデコード時の平均GPU utilizationがFlexGenの85%からKVPRの99%へ上がった。MHA ランタイム breakdownではKV 転送の割合が58%から38%へ低下し、代わりにGPU 計算が2.3%から13.3%へ増えており、**I/O待ちを意図的に余っていたGPU計算へ置換している**ことが分かる。

8×A100 + 1 CPUの追加評価ではFastDecodeとも比較し、CPU 注意機構へ依存する方式と異なりGPUごとの再計算を使うため、複数GPUが1 CPUを共有する場合のCPU 計算 ボトルネックを避ける方向も示している。

## 既存研究との差

### FlexGenとの違い

FlexGenはKV / 重み 転送を別のGPU計算と重ねるが、KVが大きくなるとPCIe 転送自体が長すぎて隠し切れない。

KVPRは**転送する仕事そのものを減らし、その分をGPU 再計算へ変換する**ため、PCIe時間とGPU時間の比率を能動的に調整できる。

### FastDecode / NEOとの違い

FastDecodeやNEOはKVがあるCPU側へ注意機構計算を寄せる。これによりKV 転送は減るが、CPU メモリ 帯域 / 計算へ依存し、複数GPUでCPUを共有するとCPU側がボトルネックになりやすい。

KVPRは注意機構自体はGPUで行い、KVの一部だけGPUで再生成するため、CPU 計算への依存を小さくする。

### TwinPilots / HeteGenとの違い

TwinPilotsやHeteGenはCPUとGPU間でoperation / 線形計算を分担する。KVPRはCPUを計算主体として使うのではなく、**GPU 計算とPCIe I/OのトレードオフをKV単位で調整する**。

### ALISAとの違い

ALISAにも一部KVを再計算して残りを転送する考え方があるが、KVPRは再計算と転送を非同期に重ね、ハードウェア プロファイルから最適な分担を決める。またスループット-orientedな予定まで対象を広げている。

## 限界

- 活性値を保持するため、KV キャッシュだけを保存する方式よりCPU メモリ消費が増える。
- 効果はGPU 計算とPCIe 帯域の比率に依存し、I/Oが十分速い環境では再計算の利得が小さくなる。
- 主評価はA100 + PCIe 4.0であり、NVLink-C2Cやより高速なホスト-端末 接続網では最適splitが変わる。
- 再計算はデコードだけを対象とし、プリフィル性能は改善しない。
- モデル architectureや量子化によってK/V 射影 費用が変わるため、プロファイルなしの固定比率では性能を保証しにくい。

## 一般的な実装上の含意

KVPRは、キャッシュを「保存するか捨てるか」だけで考えず、**I/O 費用が再計算 費用より高ければ部分的に計算し直す**という選択肢をランタイムに持たせる価値を示す。

特にGPUが高速化する一方でPCIe 帯域の伸びが相対的に小さい環境では、古い中間結果を運ぶより、より小さいupstream 活性値を運んでGPUで再生成する方が合理的になる領域が広がる。
