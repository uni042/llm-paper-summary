## 概要

大規模言語モデルのデコード段階では、過去トークンの鍵・値キャッシュ（KV cache）を繰り返し参照するため、メモリ帯域が処理率を制約しやすい。GPUの高帯域メモリ（HBM）は高速だが容量が小さく、外部のDRAMは大容量である一方、アクセス帯域が低い。長文脈でKVをすべてHBMへ置けない場合、どのトークンのKVをHBMへ置き、どのトークンを外部DRAMへ置くかが性能に影響する。

本論文は、KVの重要度がデコード中に変化する点に注目する。現在は注意の対象にならないトークンも、後の生成段階では重要になることがあるため、低重要度のKVを永久に削除するのではなく、必要に応じて低速なメモリから再び読み込めるようにしておく必要がある。HBMと外部DRAMを同時に利用できるハードウェアでは、両方の帯域を活用する配置が望ましいが、KVを移動する行為自体も帯域を消費する。

著者はモデル重みをHBMに固定し、KVの配置と移動だけを最適化する数理モデルを作る。将来の注意参照パターンを完全に知っているという理想条件を使い、模擬焼きなまし（simulated annealing）で近似的な最良配置を探す。LLaMA-3.1-8Bの実際の注意トレースをGH200相当のメモリ構成へ入力したシミュレーションでは、静的配置に対して最大5.87倍の処理率差を報告する。ただし、これは実用可能な予測スケジューラの実測高速化ではなく、未来を知る理想条件での性能改善余地を示す。

## 問題設定

注意機構は各デコード段階で過去の鍵と値を参照する。疎な注意方式は、その時点で影響の小さいトークンを読まないことで帯域を節約するが、トークンの重要度は固定ではない。論文はLongBench上のLLaMA-3.1-8Bの注意スコアを観察し、同じ層の特定トークンの重要度がデコードの進行に応じて大きく上下する例を示す。このため、ある時点で重要でないKVも将来の参照に備えて保持しておく必要がある。

HBMと外部DRAMの二階層では、HBMが高速で小容量、外部DRAMが低速で大容量という特徴を持つ。単純な静的配置ではHBMが埋まるまでKVを書き、その後の新規KVは外部DRAMへ置く。しかし、後で頻繁に参照されるトークンが外部DRAMにあり、ほとんど参照されないトークンがHBMを占めていると、速いメモリの帯域を有効利用できない。

逆に、頻繁に参照されるKVを毎回HBMへ移す方式でも、移動費用が大きければ逆効果になる。HBMから外部DRAMへの降格と外部DRAMからHBMへの昇格は、両メモリの読み書きと接続網の転送を必要とする。特に注意参照が頻繁に変わる場合、移動を繰り返しても次の段階で別のKVが必要になり、データ移動が推論の帯域を奪う可能性がある。

この研究は、最適な配置を決めるための将来情報を実際に予測するのではなく、将来を完全に知る理想条件を置いて「配置の改善余地はどれほど大きいか」を調べる。従って、提案の中心は実装済みのオンライン配置器ではなく、遅延モデルと理想上限の探索方法である。

## 手法

### デコード段階の遅延モデル

論文は生成トークンnとTransformer層lの組を一つの推論ステップとして扱い、各ステップの遅延t_(n,l)を足して総デコード遅延Tを求める。HBM側のアクセス時間をt_h、外部DRAM側のアクセス時間をt_eとし、両メモリ経路を並列に使えると仮定して、各ステップの時間をmax(t_h,t_e)とする。片方のメモリが速く終わっても、もう片方が遅ければ全体が待つという考えである。

HBM側のアクセス時間は、HBMから読むKV、HBMへ新規に書くKV、外部DRAMから昇格するKV、HBMから降格するKVの総転送量をHBM帯域で割って計算する。外部DRAM側は、参照の読み込み量と書込み・昇格・降格の量を、DRAM帯域と接続網帯域の制約を考慮して計算する。接続網は全二重と仮定されるため、方向別の転送量とDRAM内部の帯域を分けて扱う。

重要なのは、HBMと外部DRAMの両方を同時に使える場合、すべての高頻度KVをHBMへ集めれば常に最速とは限らない点である。HBMの読込み時間が短くなっても外部DRAM側の時間が長ければ、最大値で決まるステップ時間は改善しない。両階層の負荷を均衡させ、移動費用を含めて総時間を減らす必要がある。

### 配置と移動の決定変数

各ステップでは、HBMから外部DRAMへ移すKV集合M_o、外部DRAMからHBMへ移すKV集合M_i、新規KVのHBMへの書込みH_w、外部DRAMへの書込みE_wを選ぶ。これらの選択により、次のステップでどのKVがどちらのメモリから読まれるかが変わる。HBM容量の上限を守りながら、すべてのステップのmax(t_h,t_e)の和を最小化することが目的となる。

モデルの重みは毎ステップ必要になるためHBMへ常駐させ、配置最適化の対象はKVだけに限定する。外部DRAMには全KVを保持できるだけの容量があると仮定する。この単純化により、モデル重みの退避や再計算を同時に扱う複雑さを避け、KV配置による帯域改善の上限を調べられる。

この最適化は時刻ごとの配置を独立に決める問題ではない。あるKVを今HBMへ昇格させると、その時点では移動費用が発生するが、将来の複数ステップで繰り返し参照されれば費用を回収できる。逆に将来ほとんど使われなければ移動が無駄になる。したがって、未来のアクセス頻度と移動費用を合わせて考える必要がある。

### 将来参照既知の理想上限

現実の推論ランタイムでは、次のトークンが何になるかも、それによってどの過去KVが重要になるかも事前には分からない。本論文は理論的な性能上限を探るため、各デコードステップの注意参照パターンがあらかじめ既知であると仮定する。この情報を使って、将来頻繁に参照されるKVを早めにHBMへ移すことができる。

ただしすべてのステップに対する配置の組合せを完全列挙することは困難なため、著者は二つのパラメータを持つ近似探索を使う。一つは未来のWトークンまでを参照する先読み窓、もう一つは移動候補のうち実際に移動する割合Rである。Wが大きければ将来の需要を長く見られるが、現在の移動を増やしすぎると費用が高くなる。Rを小さくすれば移動量を抑えられるが、HBMに置くべきKVを移せない可能性がある。

### 模擬焼きなましによる探索

模擬焼きなましは、現在のWとRから近傍の設定を作り、総遅延Tが減れば採用し、増えても温度に応じた確率で採用する探索法である。温度が高い初期には悪化する変更も受け入れて広く探索し、温度を下げるにつれて良い設定へ集中する。著者はWだけを変える変更、Rだけを変える変更、両方を変える変更をそれぞれ0.4、0.4、0.2の確率で提案する。

Wの変更幅は±1または±2、Rの変更幅は±0.1である。初期の悪化受理確率を0.8程度とし、冷却率を0.9に設定する。最良遅延の改善が所定のしきい値を下回るか、温度や反復回数の上限に達したら終了する。この探索は将来の注意参照を知っているから可能なものであり、同じ計算を実際のオンラインデコードで低費用に実行できることを示していない。

得られた配置は、将来参照既知という強い仮定の下での近似的な理想性能を示す。論文はこれを理論的な上限と呼ぶが、模擬焼きなましが全組合せの数学的な厳密最適解を証明したという意味ではない。実際に使える配置器は未来の参照を予測する必要があり、その予測誤差と予測計算費用も評価しなければならない。

## 評価

### メモリ構成と注意トレース

著者はGH200 Grace Hopperに着想を得たメモリ構成を振る舞いシミュレータで再現する。HBM帯域4.9TB/s、容量24GB、外部DRAM容量480GB、DRAM帯域500GB/s、接続網帯域900GB/sとする。これは実機GH200そのもののすべての構成値を再現するという意味ではなく、研究で用いたシミュレーションの設定値である。

| 項目 | シミュレーション条件 |
|---|---|
| モデル | LLaMA-3.1-8B |
| 入力 | LongBenchのNarrativeQAから約30Kトークン |
| 出力 | 自己回帰で10Kトークン |
| HBM帯域 | 4.9TB/s |
| HBM容量 | 24GB |
| モデル重み | 約16GBをHBMへ固定 |
| KV用HBM余地 | 約8GB |
| 外部DRAM容量 | 480GB |
| 外部DRAM帯域 | 500GB/s |
| 接続網帯域 | 900GB/s |

LLaMA-3.1-8Bから層ごとの注意スコアを取得し、そのアクセスパターンをシミュレータへ入力する。GPU実機で将来予測器を動かしてKVを移動したわけではない。実際の注意参照トレースを用いている点と、メモリ移動・遅延は数理モデルに基づく点を分けて理解する必要がある。

### 比較する配置方式

| 方式 | 配置・移動規則 |
|---|---|
| Unlimited HBM | 容量制約のないHBMへ重みと全KVを置く理想条件 |
| Static Placement | HBMが埋まるまで新規KVを書き、その後は外部DRAMへ置いて移動しない |
| Reactive Scheduling | 必要なKVがHBMになければ昇格し、LRUのKVを降格する |
| Page Granularity | 16トークン単位のページで移動し、重要度の未来情報を使う理想化方式 |
| SA-Guided | 将来参照を既知としてWとRを探索し、KVの配置と移動を最適化する |

静的方式は移動費用がない代わりに、HBMへ置いたKVが後に使われなくてもそのまま残る。Reactiveはアクセスに追随できるが、作業集合がHBM容量を超えると移動が多くなる。ページ単位方式は重要なKVと一緒に不要なKVまで移動する場合がある。SA-Guidedは未来を知ることで移動の必要性を予測できるが、その仮定が現実的ではない。

### 処理率の主結果

論文はStatic Placementを1とした正規化トークン処理率を比較し、SA-Guidedで最大5.87倍の改善を報告する。感度評価では、多くの条件で静的方式の約4〜5倍の処理率となる。これらはメモリ帯域を主な律速とするシミュレータの結果であり、実機で5.87倍の高速化を達成したという主張ではない。

未来参照を既知とするSA-Guidedと単純な静的配置の差が大きいことは、より良いオンライン予測配置器を開発する余地があることを示す。しかし理想配置を見つける探索にかかる計算時間、未来参照の予測誤差、実機のキャッシュや同期費用が加わると、現実の改善幅は小さくなる可能性がある。

### 注意の疎性による感度

注意の疎性が低い条件、例えば60%未満では、多くのKVを読み込む必要がある。Reactiveやページ単位方式は、HBMに収まらない大きな作業集合を頻繁に移動するため、移動費用が大きくなって静的配置との差が小さくなる。頻繁に入れ替えることがかえって帯域を消費する負の結果である。

一方、注意の疎性が高い条件、例えば80%を超える場合は、同時に必要なKVが少なくなるため移動費用も小さくなり、理想的なSA-Guidedと単純方式の性能差が縮まる。つまり理想方式の相対的な利点は、注意が疎であれば必ず最大になるわけではない。作業集合の大きさと移動費用のバランスで変わる。

### トークン重要度の時間変化

論文は重要トークンの変化が小さい場合と大きい場合の合成トレースも比較する。重要度が安定している場合、一度HBMへ昇格したKVを長く使えるため、動的配置は高い効果を示す。重要度が頻繁に入れ替わる場合は、昇格と降格が増えて移動費用が高くなり、理想的な方式でも改善幅が小さくなる。

この結果は、単に次のトークンで重要なKVを当てるだけではなく、あるKVが将来どれほど長く重要であり続けるかを予測することが配置の効率に関わることを示す。将来の参照頻度が同じでも、短期間に集中する場合と長く分散する場合では移動の回収可能性が異なる。

### 理想上限と実機の区別

Unlimited HBMは、モデル重みと全KVを容量制限なしで高速HBMへ置ける理想ハードウェアである。SA-GuidedはHBM容量を制限したまま、未来参照を使って配置する理想スケジューラである。この二つは異なる理想化であり、同じ意味の上限ではない。SA-GuidedがUnlimited HBMへ近づく条件があっても、HBM容量制約そのものが消えるわけではない。

研究はトークン処理率をメモリ転送量と帯域から見積もる。実機ではGPUの演算、同期、キャッシュ階層、転送起動の固定費用、ページ管理、CPUの負荷なども遅延に寄与する。したがって数理モデルの最大5.87倍は、実機での導入判断のための保証値ではなく、予測配置の研究余地を測る基準値である。

## 既存研究との差

H2OやQuestのような疎なKV選択方式は、注意で重要でないトークンの読み込みを減らすことに主眼がある。これに対し本研究は、KV自体を保持しながら、高速HBMと大容量DRAMのどちらに置くかを動的に決める問題を扱う。重要度が変化するため、ある時点で読まないKVも将来のためにアクセス可能にしておく必要がある。

実機のオフロード方式は、CPUメモリやSSDからGPUへ必要なKVを転送する実行機構を開発する。一方この研究は、将来参照を完全に知るという非現実的な仮定で配置の性能上限を探索する。実行可能なランタイムや予測器を提供するのではなく、何を予測できれば配置を改善できるかを明確にすることが貢献である。

## 限界

第一に、未来の注意参照を完全に知るという仮定は現実のオンライン生成では満たせない。模擬焼きなましはこの情報を利用して配置を探索するため、実用的なスケジューラの性能ではない。予測誤差があれば、本来HBMへ置くべきKVを外部DRAMに残したり、不要なKVを昇格させたりする費用が生じる。

第二に、メモリ帯域が支配的というモデル化に基づくシミュレーションである。実機の転送起動費用、同期、キャッシュ、GPU演算の重なり、複数要求のスケジューリングは完全には再現されない。GH200相当の帯域値を用いていても、GH200実機での速度測定とは異なる。

第三に、モデル重みをHBMに常駐させ、外部DRAMには全KVを置ける容量があると仮定する。重み自体がHBMに収まらないモデルや、SSDを含む三階層の環境には直接適用できない。個人用GPUではHBM容量、DRAM帯域、接続網の条件が大きく異なる。

第四に、評価はLLaMA-3.1-8B、約30K入力と10K出力、NarrativeQAの注意トレースに基づく。MoEや複数要求同時実行、異なる長さ分布の負荷へ一般化するには追加の実験が必要である。重要度の時間変化が激しい場合は理想方式でも移動費用が増え、利得が縮む。

第五に、模擬焼きなましが厳密な大域最適解を証明したわけではない。論文が理論上限と呼ぶのは、将来参照を知る理想条件で探索した高性能な配置点である。実用的な上限やすべての配置方策に対する数学的証明として解釈しない。

## 再監査での修正点

既存解説の最大5.87倍という結果を、未来の注意参照を既知とするシミュレーションの改善余地であると明示した。HBM・DRAM・接続網の帯域を分けた遅延モデル、HBM容量制約、KVの昇格・降格・新規書込み、WとRの模擬焼きなまし探索を具体化した。評価では静的、Reactive、ページ単位、SA-Guided、Unlimited HBMの違いと、注意の疎性・重要度変化による負の条件を整理した。

将来参照既知の上限探索を実装済みのオンライン配置器と取り違えず、実機では予測誤差と移動費用が残ることを限界として記載した。一次資料はarXivの2025年9月15日改訂版である。
