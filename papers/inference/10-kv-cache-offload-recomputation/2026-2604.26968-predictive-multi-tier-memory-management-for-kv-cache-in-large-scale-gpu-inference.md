# Predictive Multi-Tier Memory Management for KV Cache in Large-Scale GPU Inference

> 注意機構ごとの鍵・値キャッシュ（KV cache）容量を正しく見積もり、GPUから遠隔ストレージまでの6階層へ再利用予測で配置する。重要なのは、部品検証の実測と64 GPUクラスタの解析的な性能投影を明確に分けることである。

## 概要

大規模言語モデルの自己回帰推論では、既に処理したトークンの鍵と値を再利用するため、系列長と同時要求数に比例してKVキャッシュが増える。GPUの高帯域幅メモリ（HBM）にすべて保持すると容量が不足し、再計算や要求数制限が生じる。さらに通常の多頭注意（multi-head attention、MHA）、グループ化問い合わせ注意（grouped-query attention、GQA）、複数問い合わせ注意（multi-query attention、MQA）、多頭潜在注意（multi-head latent attention、MLA）は保存すべき状態が異なる。MLAのモデルへMHAの容量式を適用すると大幅な過剰確保になり得る。

本研究は四つの構成要素を組み合わせる。第一に注意方式別のKV容量式、第二にGPU HBM・CPU DRAM・CXLメモリ・GPU直接ストレージ対応NVMe・RDMA遠隔メモリ・並列ファイルシステムという六階層、第三にブロック種類とエージェント遷移から再利用を推定するベイズ予測器、第四に注意ヘッド重要度による追い出しと回転位置埋め込み（rotary position embedding、RoPE）を考慮した先読みである。

DeepSeek-V3のMLAを正しく計算した容量例では、80GB H100・8分割テンソル並列・KV予算30GB・最大系列長4096の設定で最大バッチ数が15から104になる。再利用予測器のトレース再生では70〜84%のヒット率を報告する。ただし64基H100相当の初回トークン時間1.4〜2.1倍短縮、処理量1.7〜2.9倍、費用47%削減は、実機クラスタ全体の測定ではなく解析投影である。

## 問題設定

KVキャッシュの容量は、MHAであれば層数L、KVヘッド数h、ヘッド次元d、要素のバイト幅p、系列長nを使い、概ね2×L×h×d×p×nバイトと書ける。GQAでは問い合わせヘッドの数ではなく共有するKVヘッド数を用いる。MQAはKVヘッド数が1となり、MLAは低ランク潜在次元と回転位置成分を保持する。したがって異なる注意方式に同じ容量式を適用することは、容量の不足または過剰確保を招く。

GPU容量が不足したとき、最近最少使用（least recently used、LRU）のような反応的な追い出しは、後で同じ接頭辞やツール文脈を使う場合にも状態を捨ててしまう。一方、CPUやNVMeなどへすべて退避すれば、必要なKVを戻す転送遅延が増える。保持価値を推定して、将来使う確率が高く再計算費用の大きいブロックを速い階層に残す必要がある。

## 手法

### 1. 注意方式別の容量計算

モデル設定から潜在次元の有無、問い合わせヘッド数とKVヘッド数の比を調べ、MHA、GQA、MQA、MLAを判定する。各層・各トークン当たりのKV容量を正しい式で計算し、重みと活性値に必要な容量を除いたGPU予算を、最大系列長の一要求が使う容量で割って安全な最大バッチ数を得る。DeepSeek-V3のMLAでは潜在次元512とRoPE成分64をBF16の2バイトで保存するため、1層・1トークン当たり(512+64)×2=1152バイトとなる。MHA相当の65,536バイトと比べると約57倍の差がある。

Llama-3-70BのGQAでは1層・1トークン当たり4096バイトで、MHA相当の32,768バイトより8倍小さい。重要なのは、既存基盤でもGQA対応は進んでいるため、GQAモデルで提案方式が必ず大きくバッチ数を増やすわけではないことだ。論文の容量評価ではGQAの3モデルで1.0倍、1.0倍、0.7倍という結果も示される。

### 2. 六階層のKV配置

各階層は確保、読出し、書込み、追い出しという共通操作を持つ。GPU HBMは高速だが容量が小さく、CPU DRAMは比較的大容量、CXLはメモリプールとして利用でき、NVMeはGPU直接ストレージで転送し、RDMAは他ノードとブロックを共有し、並列ファイルシステムは低速だが大容量の最終退避先となる。高速階層への昇格と低速階層への降格を非同期に行い、復号の待ち時間へ転送費用を入れないことを目指す。

原著表IIのH100世代を前提にした代表仕様では、GPU HBMは3.35TB/秒、CPU DRAMは204GB/秒、CXL 3.0は64GB/秒、NVMe+GDSは12GB/秒、RDMAは50GB/秒、並列ファイルシステムは2GB/秒以上としている。ただしこれは論文の解析に用いる仕様・仮定であり、同じ環境で六階層を同時実測した帯域値ではない。GPU観測遅延とデバイス内部遅延を混同してはならない。

### 3. ベイズ再利用予測器

ブロックをシステムプロンプト、ツール文脈、利用者文脈、中間推論の4種類へ分類し、エージェントの遷移を同一ツール反復、ツール切替、推論段階、引継ぎの4種類へ分類する。16組のそれぞれにベータ分布の事前分布を持ち、再利用が観測されるたびに成功側の計数、使われなければ失敗側の計数を更新する。事後平均はα/(α+β)で表され、十分な履歴がある組ほど安定した再利用確率を与える。

推定確率と再計算費用からブロックの保持価値を計算し、価値の高いブロックを上位階層へ昇格する。予測が外れれば、使わないブロックが高速容量を占有するか、必要なブロックの再転送が発生する。履歴が少ない組では最近の利用頻度を補助的に使うが、モデルが常に最適な昇降格を選ぶ保証はない。ツール呼出しの規則性が弱い場合には、推定精度も下がり得る。

### 4. 注意ヘッド別の追い出しと位置認識先読み

各層・注意ヘッドについて、参照の重要度を指数移動平均（exponential moving average、EMA）で追跡する。重要度が低い状態から追い出すことで、単純なLRUでは保護しにくい参照パターンへ対応する。GQAでは複数の問い合わせヘッドが同じKVヘッドを共有するため、追い出し単位も共有構造に合わせる。MLAでは低ランク潜在表現を共有するため、通常のヘッド単位追い出しをそのまま適用しない。

RoPEの位置情報と観測された注意範囲から、近い将来参照されそうなKVブロックを予測して下位階層から先読みする。これによりキャッシュミスが起きてから転送するのではなく、復号と転送を重ねることを狙う。論文はEMAに基づく追い出しと位置認識先読みを組み合わせ、LRU比でミス率を25%減らしたと報告する。これは特定のトレース再生条件での部品評価であり、すべての負荷で25%減るという意味ではない。

### 5. 重複排除と実行時の流れ

要求が到着すると注意方式別計算器が安全なKV予算を算出し、生成されたブロックを内容ハッシュと接頭辞木で識別する。再利用可能な同一ブロックを共有し、予測器が再利用確率を更新する。キャッシュ価値と階層の空き容量に応じて昇格・降格を発行し、復号中は注意ヘッド重要度と位置情報に基づいて先読みする。必要なブロックが高速階層にない場合は下位階層から転送し、保持されていなければ再計算する。

論文の重複排除の部品検証では、Llama-3-70Bの対象チェックポイント相当で327.7MBから251.7MBへ、DeepSeek-V3では70.3MBから49.5MBへ減ると報告する。これらのMB値は論文が示す対象データの範囲であり、モデル全体の重み容量やGPU全体のKV容量と同じものではない。ハッシュ衝突や共有管理の費用も大規模運用では検討が必要となる。

## 評価条件と結果

実装の部品検証は、80GB HBMのNVIDIA GPU 1基と256GB CPU DRAMを備えた単一ワークステーションで行われた。対象モデルはDeepSeek-V3、Llama-3-70B、Mixtral-8x22B、Qwen-2.5-72Bで、ShareGPT、LMSYS-Chat-1M、合成エージェントのツール呼出しトレースを再生する。容量計算、再利用予測、注意ヘッド重要度、重複排除の各部品を確認するが、CXL 3.0・NVMe・RDMA・並列ファイルシステムを統合した64 GPUクラスタの全処理経路は実機で測っていない。

| 評価対象 | 条件 | 結果 | 証拠の種類 |
|---|---|---|---|
| DeepSeek-V3の容量計算 | 80GB H100、KV予算30GB、系列長4096、8分割TP | 最大バッチ15→104 | 注意方式別の容量式に基づく解析 |
| GQAモデル3種類 | 注意方式別の容量見積り | バッチ利得1.0倍、1.0倍、0.7倍 | モデル別容量解析 |
| ベイズ再利用予測 | ShareGPT等のトレース再生 | ヒット率70〜84% | 部品検証 |
| エージェント負荷の再利用 | LRUとの比較 | 80.5%対66.5%、14ポイント差 | トレース再生 |
| ヘッド追い出しと先読み | LRUとの比較 | キャッシュミス率25%削減 | 部品検証 |
| 64 H100相当のクラスタ | 公開仕様と部品結果から推定 | 初回トークン時間1.4〜2.1倍短縮 | 解析投影 |
| 同じ64 GPU投影 | 公開仕様と部品結果から推定 | 処理量1.7〜2.9倍、費用47%削減 | 解析投影 |

論文は64 GPUの構成で、GPU当たり約4150トークン/秒、100万トークン当たり0.43ドルという投影も示す。これらは公開ハードウェア仕様を組み合わせた予測であり、実機の統合測定値ではない。PCIe・CXL・RDMAの競合、帯域共有、複数要求の尾部遅延、故障時の回復を含む全体挙動は未検証で、予測値に誤差棒も付いていない。特にバッチ増加が演算器の飽和まで処理量へ寄与するという仮定に依存する。

DeepSeek-V3の最大バッチ15→104は、既存のMHA相当見積りとMLAの正しい見積りを比較した結果であり、既にMLA対応の正しい容量式を使う基盤に対して同じ利得が生じるわけではない。さらにGQAモデルでは容量式の変更だけで大きく増えるとは限らない。こうした負の結果は「6階層化すれば常に7倍以上の処理量」という誤読を防ぐために重要である。

## 既存研究との差

PagedAttentionはGPU内のページ管理、RadixAttentionは接頭辞再利用、FlexGenはCPUやストレージへのオフロードを中心に扱う。本研究は注意方式別の正確な容量見積りと、GPUから遠隔ストレージまでの統一階層、ブロック種類とエージェント遷移を使う再利用予測、ヘッド別の追い出しを組み合わせる。トークン単位で重要なKVだけを残す圧縮とは異なり、要求間で再利用されるキャッシュブロックの配置が主題である。

## 限界と未評価事項

最大の制約は六階層をCXL 3.0搭載の大規模クラスタで一貫して実測していないことである。単一ワークステーションの部品測定と64 GPU相当の解析投影の間には、転送競合、帯域のばらつき、ノード故障、再利用分布の変化、実際の料金体系などの未確認要因がある。階層の帯域や遅延は公開仕様に基づくため、共有ネットワーク上での性能を保証しない。論文もフルスタックのCXLクラスタ検証を将来課題としている。

一部の実装詳細は特許出願により非公開で、再現性に制約がある。ベイズ予測器はツール呼出しや共通接頭辞の反復が少ない負荷では効果が小さくなり得る。KVの内容ハッシュと遠隔共有はデータ分離やアクセス制御にも注意が必要だが、論文の主要評価は安全性検証ではない。量子化KVとの組合せも補完的な方向性として論じられるが、両者を組み合わせた大規模実測があるわけではない。
