# Predictive Multi-Tier Memory Management for KV Cache in Large-Scale GPU Inference

## 概要

本研究は、大規模言語モデル推論のKVキャッシュをGPU
HBMだけへ閉じ込めず、注意方式に応じた正確な容量計算と六階層メモリへの動的配置を統合する。対象階層はGPU
HBM、CPU
DRAM、CXLメモリ、GPUダイレクトストレージ対応NVMe、RDMA遠隔プール、並列ファイルシステムである。DeepSeek-V3ではMLAをMHA相当として誤って見積もる場合の過剰確保を避け、80GB
H100、8-way
TP、KV予算30GB、最大系列長4096という解析条件で最大バッチ数を15から104へ増やす。トレース再生では70〜84%のキャッシュヒット率を確認する。

クラスタ規模の代表結果として、64基H100相当の構成で初回トークン時間を1.4〜2.1倍短縮、スループットを1.7〜2.9倍向上、費用を47%削減すると投影する。ただし、これらは六階層を実機クラスタで通したエンドツーエンド測定ではない。単一ワークステーション上で検証した構成要素と公開ハードウェア仕様を組み合わせた解析的予測であり、誤差棒も提示されない。この区別が論文を読むうえで最も重要である。

## 問題設定

自己回帰生成では、各新規トークンが過去のキー・値へ注意を向けるため、過去状態をKVキャッシュとして保持する。長文脈化と同時要求数の増加により、このキャッシュがGPU
HBMを圧迫する。さらにMHA、GQA、MQA、MLAでは保存すべき状態量が異なるが、方式差を無視してMHA相当の容量を予約すると、MLAでは極端な過剰確保が起こり得る。

既存基盤のもう一つの問題は、GPU容量が不足すると最近最少使用などの反応的な追い出しを行い、再利用できる状態まで捨ててしまう点である。データセンターにはCPU
DRAM、CXL、NVMe、RDMA、並列ファイルシステムという大容量の下位階層が存在するため、状態を完全廃棄する前にこれらへ退避できる余地がある。論文は「どの状態を、どの階層へ、いつ動かすか」を再利用確率と再計算費用から決める。

## 手法

第一の機構は注意方式別のKV容量計算である。モデル設定からMHA、GQA、MQA、MLAを識別し、それぞれ実際に保存するKVヘッド数、ヘッド次元、潜在次元、回転位置成分、数値精度、系列長を使って必要量を計算する。MLAでは低ランク潜在表現と回転位置成分だけを数えるため、存在しないMHA相当のKV領域を予約しない。モデル重みと活性値を除いた残りGPU予算から最大バッチ数を求め、容量不足と過剰確保の双方を避ける。

第二の機構は六階層のKV配置である。高速だが小容量のGPU HBMから、CPU
DRAM、CXL、NVMe、RDMAを経て、大容量だが低速な並列ファイルシステムまでを共通の確保・読出し・書込み・追い出し操作で扱う。再利用可能性と再計算費用が高いブロックは高速側へ昇格し、価値が下がったブロックは低速側へ降格する。昇降格を非同期化することで、デコードのクリティカルパスへ転送待ちを直接入れないことを狙う。

第三の機構はベイズ再利用予測である。システムプロンプト、ツール文脈、利用者文脈、中間推論という四つのブロック種別と、同一ツール反復、ツール切替、推論段階、エージェント引継ぎという四つの遷移種別を組み合わせ、16組それぞれにベータ分布を持つ。再利用または未再利用を観測するたびに事後分布を更新し、十分な観測がある組では事後平均を、新しい組では直近頻度をより重く使う。予測が外れれば、不要な高速容量を占有するか、必要状態を低速階層から取り戻すことになる。

第四の機構はヘッド単位の追い出しと位置認識先読みである。各層・注意ヘッドの重要度を指数移動平均で追跡し、重要度が低い状態を優先して追い出す。GQAでは同じKVヘッドを共有する問い合わせヘッド群をまとめ、MLAでは共有潜在表現に合わせて集約する。さらに現在位置と観測された注意幅から近い将来に参照しそうな位置範囲を推定し、下位階層から先読みする。論文はこの組合せでLRUに対してキャッシュミス率を25%削減したと報告する。

一要求の流れとしては、まず注意方式別計算器が安全なKV予算を決め、生成されたブロックを内容ハッシュで重複排除しながら階層へ登録する。利用中の再利用観測とエージェントのツール遷移から再利用確率を更新し、価値スコアに応じて非同期の昇格・降格を発行する。デコード中はヘッド重要度で追い出し候補を選び、位置認識先読みが次のブロックを高速側へ準備する。ヒットすれば再計算を避け、ミスすれば下位階層転送または再計算へフォールバックする。

## 評価

部品検証は80GB HBMのNVIDIA GPU 1基とCPU DRAM
256GBの単一ワークステーションで行う。モデル設定はDeepSeek-V3、Llama-3-70B、Mixtral-8x22B、Qwen-2.5-72Bを含み、ShareGPT、LMSYS-Chat-1M、5〜15回のツール呼出しを持つ合成エージェントワークロードをトレース再生する。比較対象としてvLLM、SGLang、TensorRT-LLM、FlexGenの公開結果を利用する。

DeepSeek-V3ではMLAを正しく容量計算することで最大バッチ数を15から104へ拡大する。一方、GQAモデルの容量計算による単体バッチ利得は1.0倍、1.0倍、0.7倍とされ、大きな7.4倍級の利得を一般化できない。再利用予測を含む部品評価では70〜84%のヒット率、位置認識先読みとヘッド単位追い出しではLRU比25%のミス率削減を報告する。

64基H100相当のクラスタでは初回トークン時間1.4〜2.1倍短縮、スループット1.7〜2.9倍向上、費用47%削減を解析的に投影する。これらは実測クラスタ値ではなく、部品の挙動と公開された帯域・遅延仕様を組み合わせ、バッチ増加が計算飽和点まで線形に効くと仮定した推定である。実際のPCIe、CXL、RDMA競合や尾部遅延が強い環境では利得が小さくなる可能性がある。

## 既存研究との差

PagedAttentionやRadixAttentionは主にGPU内ページ管理や接頭辞再利用を扱い、FlexGenはCPUとディスクへの静的オフロードを扱う。本研究はMHA、GQA、MQA、MLAの容量式を一つに統合した上で、GPU、CPU、CXL、NVMe、RDMA、並列ファイルシステムを同じKV階層として扱い、再利用予測で動的に昇降格する。トークン単位の重要度に基づくKV削減とも異なり、要求を跨いだキャッシュブロックの再利用と配置を中心問題にする。

## 限界・実装状況

最大の制約は、六階層全体をCXL
3.0機器と大規模GPUクラスタで実測していないことである。クラスタ規模の性能と費用は解析的予測なので、実運用の共有帯域、同時要求、故障、尾部遅延を十分表現しない。一部実装詳細は特許審査中として非公開である。利用者空間ライブラリとしてCUDAメモリプール、固定CPUメモリ、CXLメモリマップ、cuFile、ibverbsを使う構成と、vLLM、SGLang、TensorRT-LLMへの統合点は記述されている。
