# SwiftCache: Efficient LLM Serving for Multi-turn Conversations with Heterogeneous KV Cache Sharing

> 同一serverでKV需要が低い別modelの空きHBMへprefix KVをNVLink経由で退避し、local GPUには実行中layerのKVだけを流し込んで、multi-turn servingの再読込待ちと文脈長制約を減らす。

## 概要

複数回対話（multi-turn conversation）では過去turnのKVを再利用できるが、履歴が長くなるとlocal HBMに収まらず、CPU DRAMやSSDからPCIe経由で戻す時間が初回token待ち時間（TTFT）を支配する。SwiftCacheは、同じserverに同居する異種model間でKV cache容量需要が異なることと、model間のNVLink帯域が余りやすいことを利用する。

KV需要の低いworker modelの空きHBMを、高需要modelのprefix KVの保存先として貸し出す。さらにlocal GPUには現在実行中layerのKVだけを置き、他layer分は先行転送して計算と重ねる。

## 手法

### master / worker cache

高需要側をmaster、空きHBMを提供する側をworkerとして管理し、prefix KV blockをNVLinkでGPU間転送する。CPUを経由するPCIe offloadより高帯域な経路を使い、同居modelの未利用memoryを活用する。

### layer stream cache

attentionは一度に一つのlayerのKVしか参照しない。SwiftCacheはlocal側に現在layer用bufferだけを保持し、次layerのKV転送を現在の計算と重ねることで、全layer KVの同時常駐を避ける。

### elastic cache

従来のlayer-major layoutでは容量変更時のdata movementが大きい。block-major layoutにより、modelごとの割当をO(1)で変更できる構造とする。

## 評価

ShareGPTとL-Evalの実workloadを用い、Qwen3 familyとLWM-1M-Textを複数GPUで評価する。動機付け実験には96GB H20 GPU 2台、PCIe 4.0（32 GB/s）とNVLink（400 GB/s）を用いる。

vLLMおよびSGLangとの比較で、P99 TTFTを最大69%削減し、最大推論長を最大3.98倍へ拡張した。co-located worker modelへの干渉は小さいと報告するが、効果はNVLink接続、cache需要の非対称性、転送と計算の重なりに依存する。

## 既存研究との差

CPU / SSD階層へKVを退避する方式と異なり、別modelのGPUが持つ余剰HBMをmodel横断で借りる。Aqua等のpeer-GPU offloadに近いが、multi-turn prefix cache、layer単位streaming、動的なmodel間容量再配分を一体化する。

## 限界

- 同一server内に、空きHBMとNVLink帯域を提供できる低需要modelが必要である。
- model間の需要が同時に高まると、利用可能な余剰容量が減る。
- 主要結果は特定のQwen3 family / LWM-1M-Text構成とworkloadに基づく。
