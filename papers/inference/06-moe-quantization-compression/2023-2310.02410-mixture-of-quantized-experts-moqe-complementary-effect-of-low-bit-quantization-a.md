# Mixture of Quantized Experts (MoQE): Complementary Effect of Low-bit Quantization and Robustness

> MoQEは「MoEは1 トークンで少数エキスパートしか計算しないのに、なぜ推論は遅く大きいのか」を**エキスパート 重みの保存量と読出し帯域**の問題として捉え、モデルの92%以上を占めるエキスパート 重みだけを強く低bit化する研究である。

## 概要

混合エキスパート（Mixture-of-エキスパート: MoE）は、たとえば32個のFFN エキスパートを用意しても、1 トークンではルータが選んだ1個だけを計算できる。そのためパラメータ数を大きく増やしながら、理論FLOPsはdense モデルと近いままにできる。

しかし「計算しないエキスパート」はメモリから消えるわけではない。deployment時には32 エキスパートすべての重みを保存し、ルーティングに応じて必要なエキスパートを読み出せるようにしておく必要がある。

論文の5.3B・32-エキスパート モデルでは、fp16 モデル sizeが約9.91GBで、その**92.8%がMoE エキスパート 重み**である。同等FLOPsのdense モデルは約1.18GBにすぎない。さらにA100上の同一バッチ条件では、dense モデルが14.02 sentences/sなのに対し、fp16 MoEは5.37 sentences/sまで低下した。

つまりMoEは計算量を増やしていないのに、巨大なエキスパート 重みを読むメモリ trafficのため遅くなっている。

MoQEの方針は単純である。

- モデル容量の大半を占める**エキスパート FFNだけを低bit化する**。
- 量子化に弱いdense FFN、self-注意機構、cross-注意機構は高精度のまま残す。
- エキスパートは3-bitまで追加学習なしで耐えやすく、2-bitのみ量子化考慮学習（量子化-aware 学習: QAT）で補う。

この設計により、モデル全体を一律に低bit化するより品質を守りながら、メモリを支配する部分だけを強く圧縮できる。

## 問題設定

### MoEでは『active parameters』と『stored parameters』が違う

MoEの効率を説明するときは「1 トークンで何パラメータをactivateするか」がよく使われる。しかしdeployment メモリでは、**その瞬間に使わないエキスパートも保存しておかなければならない**。

32 エキスパートからtop-1を選ぶ場合、計算するエキスパート FFNは1個でも、ルータが次のトークンで別エキスパートを選ぶ可能性があるため32個全部が必要である。

このためMoEの実運用では、

1. モデルがGPU メモリへ収まるか
2. エキスパート 重みをHBMから読む帯域が足りるか
3. オフロードする場合はCPU/GPU間へ何byte運ぶか

がFLOPsとは別のボトルネックになる。

### 全layerを同じbit幅へ落とす必要はない

量子化（量子化）は、fp16 重みをたとえば4-bit整数へ置き換え、scaleと組み合わせて近似する方法である。

bit数を減らすほどメモリと帯域は減るが、重み値の細かな違いを表現できなくなる。特に重み 分布に極端な外れ値（outlier）があると、広い数値rangeを少数の量子化 水準へ割り当てる必要があり、通常値の表現が粗くなる。

MoQEはモデル 構成要素別に感度を測り、**エキスパート FFNは他のlinear 層より低bit量子化へ強い**ことを見つける。そこで敏感な部分まで無理に圧縮せず、エキスパートだけを狙う。

## なぜexpert FFNは低bit化に強いのか

### expert weightはdense FFNより値のrangeが狭い

論文は偶数層にMoE エキスパート FFN、奇数層に通常dense FFNを置くモデルで重み 分布を比較している。

dense FFN、とくに2つ目のlinear 層には大きなoutlierが現れ、重み rangeが広い。一方エキスパート FFNは分布が比較的狭く、極端な値が少ない。

同じ2-bit / 3-bit quantizerを使ったとき、rangeが狭いエキスパート 重みの方が1 量子化 ステップあたりの誤差を小さくできる。

### component別実験でもexpertだけ頑健だった

著者らはモデルを

1. エキスパート FFN
2. dense FFN
3. self-注意機構
4. cross-注意機構

に分け、各部分だけを低bit化した。

3-bitではエキスパート FFNの品質低下は小さい一方、dense FFNは大きく悪化する。2-bitではdense FFNを量子化するとほぼタスク能力を失う条件があるが、エキスパート FFNはまだ意味のある品質を保つ。

この観察が「エキスパートだけを強く量子化し、共有部は高精度で残す」というMoQEの根拠である。

## 手法

MoQEの実行は次のように整理できる。

1. 学習済みMoE モデルを用意する。
2. エキスパート FFNの各重み matrixをchannel単位で量子化する。
3. self-注意機構、cross-注意機構、通常dense FFNはfp16のまま保持する。
4. 8/4/3-bitでは追加学習なしの学習後量子化（post-学習 量子化: PTQ）を使う。
5. 2-bitでは量子化誤差が大きいためQATを行う。
6. 推論時は低bit エキスパート 重みを専用GPU カーネルで読み、dequantizationとmatrix multiplicationを実行する。

重要なのは、ルータやエキスパート数を変えない点である。**どのエキスパートを選ぶかというMoEの計算graphはそのままに、エキスパートの重み表現だけを軽くする**。

## 手法

### 1. expert weightだけをweight-only quantizationする

MoQEは活性値を整数化せず、重みだけを低bitにする重みのみ量子化（重みのみ 量子化）である。

これには2つ利点がある。

- 活性値 量子化由来の追加品質 損失を避けられる。
- モデル sizeと重み 読み出す 帯域というMoEの主要問題を直接減らせる。

MoE 推論では大量のエキスパート 重みを読むことが問題なので、重みのみでもシステム上の効果が大きい。

### 2. matrix全体で1 scaleではなくchannelごとにscaleを持つ

量子化では整数値だけでなく「整数1 ステップが元重みの何に相当するか」を示すscaleが必要になる。

matrix全体へ1個のscaleを使うと、一部channelのoutlierがmatrix全体のrangeを広げてしまう。

MoQEは**channel単位量子化（チャネル単位 量子化）**を使い、出力 channelごとに別scaleを持つ。これにより各channelのrangeへ合わせて量子化 gridを細かくできる。

scale自体はfp16で保存するが、1 channelにつき1値なので追加容量はmatrix パラメータの1%未満である。

### 3. linear quantizationを主に使う

論文は線形量子化（linear 量子化）と対数量子化（log-scale 量子化）を比較する。

低bit エキスパートではlinear方式が良好だったため、主要実験ではチャネル単位 linear 量子化を使う。

概念的には各重みを、そのchannelの最大絶対値から決めたscaleで割り、利用可能な整数rangeへ丸める。推論時にはscaleを掛けて近似重みとして使う。

### 4. 3-bitまではPTQ、2-bitだけQAT

8-bit、4-bit、3-bitは学習済み重みを変換するだけのPTQで評価する。

3-bit エキスパートでも元MoEとの差を小さく保てるため、deployment前の追加学習を必要としない。

2-bitでは量子化水準が少なすぎてPTQだけでは誤差が大きい。そのため学習中から量子化 errorを入れてモデルを適応させるQATを使う。

この違いは実務上重要で、MoQEの「超低bit化」はすべて学習-freeという意味ではない。

### 5. expert以外を高精度に残す

モデル全体の圧縮率だけを最大化するなら注意機構やdense FFNも量子化したくなる。しかし構成要素感度実験では、それらを2〜3-bitへ落とすと品質悪化が大きい。

MoQEは**92.8%を占めるエキスパートだけを圧縮すれば十分大きなメモリ効果が得られる**ため、残りの共有部はfp16で残す。

これは一種の粗い混合精度（mixed precision）設計で、「エキスパートは低bit、共有部は高bit」という構成要素-水準 配分になっている。

### 6. 4-bitだけはruntimeまで最適化して速度を測る

重みを4分の1へ圧縮しても、毎回fp16へ展開してから通常GEMMを呼ぶだけではdequantization オーバーヘッドで速度が出ない。

論文は低bit エキスパート用GPU 実行時を用意し、4-bit 重みの読み出しとdequantizationを効率化する。

一方3-bit / 2-bitには同等に最適化されたカーネルがなく、論文表でもスループットは `Not optimized` とされている。

したがって**モデル sizeの改善と実時間 高速化倍率は別の結果**として読む必要がある。

## 評価

### まず見るところ

MoQEの重要な結果は「2-bitなら5倍速い」ではない。

主結果は、

- エキスパートだけなら3-bitまでPTQで品質を保ちやすい
- 2-bit + QATでもdense fp16 モデル以上のBLEUを維持できる
- モデル sizeはfp16 MoEの約20%まで減らせる
- ただし実測高速化倍率を示す最適化実行時は主に4-bitで、速度向上は1.24倍

という**品質・容量・speedの分離**である。

### 基本条件

| 項目 | 内容 |
|---|---|
| Task | 多言語機械翻訳 |
| Main model | 5.3B parameters、32 experts、top-1 routing |
| Dense comparison | 同じtraining data / FLOPs級のdense model |
| Hardware | NVIDIA A100 ×1 |
| Software | Ubuntu 20.04 / CUDA 11.6 |
| Metric | BLEU、model size、end-to-end throughput |
| Decoding | beam size 5 |

公開WMT系datasetと大規模内部multilingual datasetの両方を使い、頑健性がdataset固有ではないかも確認している。

### fp16 MoEはdenseより大きく、むしろ遅い

比較対象では、

| Model | Throughput | fp16 size |
|---|---:|---:|
| Dense | 14.02 sentences/s | 1.18 GB |
| 32-expert MoE | 5.37 sentences/s | 9.91 GB |

となる。

MoEはBLEUを上げるが、モデル sizeが8.38倍になり、メモリ帯域 pressureによってスループットはdenseの約0.38倍まで低下している。

### 量子化後のquality / size

| 構成 | 平均BLEU | fp16 MoE比size | throughput |
|---|---:|---:|---:|
| fp16 MoE | 46.35 | 1.00× | 1.00× |
| int8 expert | 46.34 | 0.54× | 1.16× |
| int4 expert | 46.18 | 0.32× | 1.24× |
| int3 expert | 46.01 | 0.26× | kernel未最適化 |
| int2 expert + QAT | 45.90 | 0.20× | kernel未最適化 |
| fp16 Dense | 45.06 | — | — |

2-bitではfp16 MoEより品質は下がるが、同じ学習 データのdense fp16 モデルよりBLEUは高い。

### 79.6%削減と4.9倍圧縮

2-bit エキスパート + QATでは、モデル全体のsizeをfp16 MoEから**79.6%削減**し、およそ4.9倍小さくする。

エキスパート以外はfp16のままなので理論上8倍にはならない。それでもエキスパートがモデルの大半を占めるため、全体sizeへ大きく効く。

### 4-bit速度は1.24倍

int4ではモデル sizeが約0.32倍になるが、A100実測スループットはfp16 MoEの**1.24倍**である。

つまり「重み byte数が約3分の1」でも、モデル全体の実行には注意機構、ルーティング、dequantization、カーネル オーバーヘッドなどが残るため、速度は3倍にはならない。

この差は後続のMoE 量子化研究でも重要で、**bit幅削減率をそのままシステム 高速化倍率へ変換してはいけない**。

## 既存研究との差

### dense LLM quantizationとの違い

dense モデルではほぼすべてのFFN 重みが毎トークン使われるため、層ごと・channelごとの量子化感度を考える必要がある。

MoQEはMoE特有の構造を使い、「巨大容量の原因であり、しかも量子化に強いエキスパート FFN」に圧縮を集中する。

### expert pruning / offloadとの違い

エキスパート 枝刈りはエキスパート自体を消すため、ルータが本来そのエキスパートを使う機会を失う。

エキスパート オフロードはfull-precision 重みをCPU/SSDへ残すが、必要時のtransferが発生する。

MoQEはエキスパートを全部残したまま1 エキスパートあたりのbyte数を減らす。そのためオフロードと排他的ではなく、**低bit エキスパートをCPU/SSDから転送すればI/O量も減らせる**ので組み合わせ可能である。

### 後続mixed-precision MoEとの違い

MoQEは全エキスパートを同じbit幅へ量子化する。エキスパートごとの利用頻度やimportanceに応じて2/4/8-bitを変える方式は扱わない。

その意味でMoQEは、後続のエキスパート-wise mixed precision研究に対する単純で重要な比較対象である。

## 限界

- 主評価は多言語機械翻訳MoEであり、Mixtral / DeepSeek / Qwen系decoder-のみ MoEではない。
- 3-bit以下の高速GPU カーネルは評価時点で未整備。
- 2-bitはQATが必要で、完全学習-freeではない。
- 全エキスパートを一律bit幅へするため、エキスパートごとの感度差を活用しない。
- 活性値、KV キャッシュ、ルータは低bit化の対象外。
- size 削減とスループット 高速化倍率の倍率は大きく異なる。

## 一般的な実装上の含意

MoQEから得られる重要な示唆は、MoE 圧縮では**「モデルのどこが容量を占めるか」と「どこが量子化に強いか」の積で対象を決める**ことである。

エキスパートはモデル容量の大半を占め、かつこのモデルではoutlierが少なく低bit耐性が高かった。そのため共有部を無理に圧縮しなくても大きなメモリ 削減が得られた。

またオフロード システムの観点では、エキスパート 1個を4-bitにすればCPU→GPU / SSD→RAMのtransfer byte数も小さくなる。したがって量子化は単なるモデル-storage技法ではなく、**階層メモリのI/O圧縮**としても評価する価値がある。

一方、そのbyte削減を実速度へ変えるには対応カーネルが必要である。3-bit / 2-bitの未最適化結果は、圧縮 algorithmと実行時 実装を別々に設計してはいけないことを示す。
