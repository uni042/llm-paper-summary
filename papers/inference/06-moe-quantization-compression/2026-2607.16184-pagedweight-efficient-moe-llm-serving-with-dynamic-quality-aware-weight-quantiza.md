# PagedWeight: Efficient MoE LLM Serving with Dynamic Quality-Aware Weight Quantization

> KV cache増加で変動する空きVRAMに合わせ、expert weightをpage／bit-plane単位で低bit化・復元し、品質損失当たりの解放byteを最適化する。

## 概要
PagedWeightは、長文servingでKV cacheが増えるたびにexpert weightへ使えるVRAMが減る問題を、**同じexpertのprecisionを実行中に上下させる**ことで解く。KV cache自体をoffloadする研究ではなく、KVによるmemory pressureへweight側が適応する研究である。

## 手法のあらまし

### 1. expert weightを`page`として扱う

通常はexpert weightを一つの連続した固定precision tensorとして持つ。PagedWeightではlinear blockをpage単位で管理し、必要に応じて一部pageのprecisionだけ下げられるようにする。

狙いは、request数やcontext長で空きVRAMが変わっても、モデル全体を再ロードせずmemoryを調整することにある。

### 2. `bit-plane`表現

Any-Precision LLM系の表現を使い、一つのweightをprecisionごとに完全複製するのではなく、bitを上位・下位のplaneとして分けて保持する。

例えば低precisionへ落とす場合は一部bit-planeを外し、余裕が戻れば追加bit-planeを戻す。

つまり、

`高bit expert ↔ 低bit expert`

を別checkpoint間の丸ごとcopyではなく、**bit-planeの追加・削除**として扱う。

### 3. `quality loss per freed byte`

どのblockからprecisionを下げるかは、単純なLRUやrouting頻度だけでは決めない。

offlineで各blockについて、

- Hessian由来の量子化感度
- router activation probability
- block size

を測り、一段低bitへ落としたときの

`推定品質損失 / 解放できるbyte`

を計算する。

この値が小さいblockから降格すれば、**同じVRAMを空けるのに品質への影響が小さい場所を優先できる**。

### 4. runtimeではKV pressureを見て昇降格する

runtimeは、

- 現在のKV cache量
- GPU free memory
- request hidden-state normによる感度補正

を監視する。

VRAMが足りなくなれば低cost blockからprecisionを下げ、request終了などで余裕が戻れば重要blockへbit-planeを戻す。

### 5. migrationは安全な境界でcommit

pageのprecision変更は非同期に行い、layer / iterationの安全な境界でpointerを切り替える。途中状態のweightをforwardが読むことを避ける。

さらにmixed-precision CUDA kernelがbit-planeを直接読み、異なるprecisionのexpert blockをまとめて実行する。

## 評価

### まず見るところ
- **結論:** KV cacheでVRAMが圧迫された時だけexpert precisionを下げ、余裕が戻れば復元すると、固定quantizationよりmemoryを有効利用できる。
- **メモリ:** GPU memoryを最大72%削減。
- **品質:** 同じmemory予算のstatic方式より最大39.3%改善と報告。
- **実速度:** RTX 6000 Ada / GH200でE2E throughput最大1.94倍。
- **重要な区別:** KV cache offloadではなく、**KV pressureにweight precisionを適応させる**研究。

### どんなworkloadで効くか

長文や同時request数が変化し、KV占有量が時間とともに動く場合に利点が大きい。

逆に短い固定contextでKV pressureがほぼ変わらない場合は、最初から適切なstatic precisionを選べるため差は小さくなり得る。

### quality proxyの限界

Hessian lossやhidden-state normは実task品質そのものではなくproxyである。したがって、未知domainで「このblockを下げても必ず安全」と保証するものではない。

またGH200のcoherent memoryと通常PCIe machineではpage migration costが異なるため、hardwareによって最適な昇降格頻度も変わる。
