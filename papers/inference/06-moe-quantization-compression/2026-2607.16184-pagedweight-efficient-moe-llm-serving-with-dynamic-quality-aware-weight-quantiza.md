# PagedWeight: Efficient MoE LLM Serving with Dynamic Quality-Aware Weight Quantization

> KV cacheが増えて空きVRAMが減ったとき、品質への影響が小さいexpert weight部分から段階的にbit幅を下げ、余裕が戻れば高精度へ戻すserving方式。

## 概要
PagedWeightは、長文servingでKV cacheが増えるたびにexpert weightへ使えるVRAMが減る問題を、**同じexpertのprecisionを実行中に上下させる**ことで解く。KV cache自体をoffloadする研究ではなく、KVによるmemory pressureへweight側が適応する研究である。

## 手法のあらまし

### 1. expert weightを小さな管理単位へ分ける

通常はexpert weightを一つの連続した固定precision tensorとして持つ。PagedWeightではlinear blockをpage単位で管理し、必要に応じて一部pageのprecisionだけ下げられるようにする。

ここでのpageはOSの仮想memory pageそのものではなく、**weightを部分的に低bit化・復元するための固定サイズ管理単位**と考えるとよい。

狙いは、request数やcontext長で空きVRAMが変わっても、モデル全体を再ロードせずmemoryを調整することにある。

### 2. bitを上位・下位の部分に分け、必要なprecision分だけ保持する

一つのweightをprecisionごとに完全複製するのではなく、bitを上位側・追加精度側に分けて保持する。

例えば低precisionへ落とす場合は下位bitの一部を外し、余裕が戻ればそのbitを追加する。

論文ではこの保存方式を `bit-plane` 表現と呼ぶ。

つまり、

`高bit expert ↔ 低bit expert`

を別checkpoint間の丸ごとcopyではなく、**追加bitの着脱**として扱う。

### 3. 同じVRAMを空けるなら品質への影響が小さいblockから下げる

どのblockからprecisionを下げるかは、単純なLRUやrouting頻度だけでは決めない。

事前に各blockについて、

- そのblockの量子化誤差がmodel lossへどれだけ効きやすいか
- routerからどれだけ頻繁に使われるか
- blockを一段低bitへしたとき何byte空くか

を測る。

そして、

`推定品質損失 / 解放できるbyte`

が小さいblockからprecisionを下げる。これにより、**同じVRAMを空けるなら品質への影響が小さい場所を優先する**。

### 4. 実行中のKV使用量を見てprecisionを上下させる

runtimeは、

- 現在のKV cache量
- GPU free memory
- 現在requestのhidden stateが各blockの誤差へどれだけ敏感そうか

を監視する。

VRAMが足りなくなれば低影響blockからprecisionを下げ、request終了などで余裕が戻れば重要blockへbitを戻す。

### 5. precision変更途中のweightをforwardが読まないようにする

pageのprecision変更は非同期に行い、layer / iterationの安全な境界で参照先を切り替える。途中までしか変更されていないweightをforwardが読むことを避ける。

さらにmixed-precision CUDA kernelが必要なbitだけを直接読み、異なるprecisionのexpert blockをまとめて実行する。

## 評価

### まず見るところ
- **結論:** KV cacheでVRAMが圧迫された時だけexpert precisionを下げ、余裕が戻れば復元すると、固定quantizationよりmemoryを有効利用できる。
- **メモリ:** GPU memoryを最大72%削減。
- **品質:** 同じmemory予算のstatic方式より最大39.3%改善と報告。
- **実速度:** RTX 6000 Ada / GH200でE2E throughput最大1.94倍。
- **重要な区別:** KV cache offloadではなく、**KV pressureにweight precisionを適応させる**研究。

### どんなworkloadで効くか

長文や同時request数が変化し、KV占有量が時間とともに動く場合に利点が大きい。

逆に短い固定contextでKV pressureがほぼ変わらない場合は、最初から適切なstatic precisionを選べるため差は小さくなり得る。

### 品質影響の推定には限界がある

量子化前後のloss感度やhidden-state normは実task品質そのものではなく、**どのblockを下げると危険そうかを近似的に順位付けする指標**である。未知domainで「このblockを下げても必ず安全」と保証するものではない。

またGH200はCPU側memoryとGPU HBMを非常に高速な接続で共有できる構成で、通常のPCIe machineとはweight移動costが異なる。そのためhardwareによって最適なprecision変更頻度も変わる。
