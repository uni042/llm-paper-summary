# PagedWeight: Efficient MoE LLM Serving with Dynamic Quality-Aware Weight Quantization

> KV キャッシュが増えて空きVRAMが減ったとき、品質への影響が小さいエキスパート 重み部分から段階的にビット幅を下げ、余裕が戻れば高精度へ戻すサービング方式。

## 概要
PagedWeightは、長文サービングでKV キャッシュが増えるたびにエキスパート 重みへ使えるVRAMが減る問題を、**同じエキスパートの精度を実行中に上下させる**ことで解く。KV キャッシュ自体をオフロードする研究ではなく、KVによるメモリ 圧力へ重み側が適応する研究である。

## 手法のあらまし

### 1. expert weightを小さな管理単位へ分ける

通常はエキスパート 重みを一つの連続した固定精度 テンソルとして持つ。PagedWeightでは線形 ブロックをページ単位で管理し、必要に応じて一部ページの精度だけ下げられるようにする。

ここでのページはOSの仮想メモリ ページそのものではなく、**重みを部分的に低ビット化・復元するための固定サイズ管理単位**と考えるとよい。

狙いは、リクエスト数や文脈長で空きVRAMが変わっても、モデル全体を再ロードせずメモリを調整することにある。

### 2. bitを上位・下位の部分に分け、必要なprecision分だけ保持する

一つの重みを精度ごとに完全複製するのではなく、ビットを上位側・追加精度側に分けて保持する。

例えば低精度へ落とす場合は下位ビットの一部を外し、余裕が戻ればそのビットを追加する。

論文ではこの保存方式を `bit-plane` 表現と呼ぶ。

つまり、

`高bit expert ↔ 低bit expert`

を別checkpoint間の丸ごとcopyではなく、**追加ビットの着脱**として扱う。

### 3. 同じVRAMを空けるなら品質への影響が小さいblockから下げる

どのブロックから精度を下げるかは、単純なLRUやルーティング頻度だけでは決めない。

事前に各ブロックについて、

- そのブロックの量子化誤差がモデル 損失へどれだけ効きやすいか
- ルータからどれだけ頻繁に使われるか
- ブロックを一段低ビットへしたとき何byte空くか

を測る。

そして、

`推定品質損失 / 解放できるbyte`

が小さいブロックから精度を下げる。これにより、**同じVRAMを空けるなら品質への影響が小さい場所を優先する**。

### 4. 実行中のKV使用量を見てprecisionを上下させる

実行時は、

- 現在のKV キャッシュ量
- GPU 空き メモリ
- 現在リクエストの隠れ 状態が各ブロックの誤差へどれだけ敏感そうか

を監視する。

VRAMが足りなくなれば低影響ブロックから精度を下げ、リクエスト終了などで余裕が戻れば重要ブロックへビットを戻す。

この制御の狙いは、最大同時リクエスト数を守るためにKV キャッシュを追い出すのではなく、時間とともに変動する重み側の占有量を調整弁にすることである。長いリクエストが増えた瞬間だけ一部重みを低精度化し、queueが軽くなれば高精度へ戻せるため、最悪時のKV量に合わせて全エキスパートを恒久的に低ビット化する必要がない。したがって同じ平均メモリ 予算でも、静的量子化より品質を高く保てる余地が生まれる。

### 5. precision変更途中のweightをforwardが読まないようにする

ページの精度変更は非同期に行い、層 / iterationの安全な境界で参照先を切り替える。途中までしか変更されていない重みを順伝播が読むことを避ける。

さらに混合精度 CUDA カーネルが必要なビットだけを直接読み、異なる精度のエキスパート ブロックをまとめて実行する。

実装上は精度変更そのものが新しい待ち時間にならないことも重要である。メモリ 圧力が短時間で上下するたびに大きな重み テンソルを作り直す設計では、量子化・復元のコストがサービング利得を相殺する。ページ単位のビット追加・除去と安全な参照先切替を使うことで、変更粒度を必要量へ限定し、推論中の重み表現を段階的に更新できるようにしている。

この設計を長文推論の流れに沿って読むと、まず入力を処理してKVキャッシュを確保し、その使用量が増えた時点で重みページを一段ずつ低精度へ移す。要求が終わってKVが解放されれば、外した下位ビットを戻して次の要求に備える。したがって、全モデルを常に最低精度で保持する方式とは異なり、混雑していない時間帯には高精度の重みを使える。精度変更の判断はページ単位なので、品質への影響が大きい部分を保護したまま、必要な容量だけを細かく回収できる。論文の削減率や速度向上は特定のGPU・モデル・負荷条件で得られた値であり、別の装置や文脈長で同じ値になるとは限らない点にも注意が要る。

この仕組みは、空き容量を確保するために品質を一律に犠牲にするのではなく、影響の小さい重みから順に調整する点に意味がある。低精度化と復元を安全な層境界で行うため、要求の途中で不完全な重みを参照する危険も避けられる。実際の運用では、KVの増減を監視する間隔、ページ変更の上限、戻す精度の段階を装置ごとに校正し、品質指標と遅延の両方を確認する必要がある。

## 評価

### まず見るところ
- **結論:** KV キャッシュでVRAMが圧迫された時だけエキスパート 精度を下げ、余裕が戻れば復元すると、固定量子化よりメモリを有効利用できる。
- **メモリ:** GPU メモリを最大72%削減。
- **品質:** 同じメモリ予算の静的方式より最大39.3%改善と報告。
- **実速度:** RTX 6000 Ada / GH200でE2E スループット最大1.94倍。
- **重要な区別:** KV キャッシュ オフロードではなく、**KV 圧力に重み 精度を適応させる**研究。

### どんなworkloadで効くか

長文や同時リクエスト数が変化し、KV占有量が時間とともに動く場合に利点が大きい。

逆に短い固定文脈でKV 圧力がほぼ変わらない場合は、最初から適切な静的 精度を選べるため差は小さくなり得る。

### 品質影響の推定には限界がある

量子化前後の損失感度や隠れ-状態 normは実タスク品質そのものではなく、**どのブロックを下げると危険そうかを近似的に順位付けする指標**である。未知domainで「このブロックを下げても必ず安全」と保証するものではない。

またGH200はCPU側メモリとGPU HBMを非常に高速な接続で共有できる構成で、通常のPCIe machineとは重み移動コストが異なる。そのためハードウェアによって最適な精度変更頻度も変わる。
