# GEMQ: Global Expert-Level Mixed-Precision Quantization for MoE LLMs

> 全layerのexpertを同じmemory budgetの中で比較し、低bit化したとき品質へ効きにくいexpertから強く圧縮したうえで、量子化後のexpert性能に合わせてrouterだけを微調整する手法。

## 概要
GEMQは、layerごとに独立してbitを配るのではなく、**モデル全体の全expertを一つのbit budgetで比較する**mixed-precision量子化である。さらに量子化後はrouterだけを微調整し、低bit化で変わったexpert品質へroutingを再適応させる。

## 手法のあらまし

### 1. 全layerのexpertを同じ尺度で比較する

従来のlayer-local方式では、各layer内で「このexpertが重要」と判断して高bitを配る。しかし、layer Aの重要expertとlayer Bの重要expertを同じ尺度で比較できない。

GEMQは各expertを1/2/3 bitなどへ一時的に量子化し、**そのexpertだけ低bit化したときモデル全体のtask lossがどれだけ増えそうか**を共通尺度へ変換する。

### 2. 量子化誤差がtask lossへどれだけ効くかで重み付けする

単純な出力MSEだけでなく、calibration data上で各weight付近のloss感度を測り、**同じ出力誤差でもtask lossへ強く効くexpertを重要とみなす**。

論文ではこの近似に diagonal Fisher Information を使う。名前より重要なのは、異なるlayerのexpertを

`低bit化したときに推定されるtask loss増加`

という同じ単位で比べられるようにする点である。

### 3. 総bit budgetを超えないexpert-bit組み合わせを選ぶ

各expertについて1/2/3 bitなど複数候補を用意し、

- 各expertはどれか1つのbitを選ぶ
- 全expertの総容量はbudget以内
- 推定loss増加はできるだけ小さくする

という組み合わせ問題を解く。

論文ではこれをbinary LPとして定式化する。ただし極端に低bit化してlayer全体が不安定になるのを防ぐため、**各layerに少なくとも1つ高bit expertを残す**制約も入れる。

### 4. routerだけを量子化後に再学習する

expert weightを低bit化すると、同じrouter scoreでも実際のexpert出力品質が変わる。

GEMQはfull-precision routerをそのまま模倣するのではなく、量子化済みexpertに合わせてrouterを再適応させる。更新するのはrouterだけで、全parameterの0.04%未満。

つまり、**量子化前のroutingを完全保存するのではなく、量子化後モデルにとってより良いroutingへ調整する**。

### 5. 一気に極低bitへ落とさず段階的に圧縮する

いきなり極低bitへ落とすと、高精度状態で測ったexpert重要度が低bit状態では当てにならなくなる。

そこで高bit → 中bit → 低bitと段階的にbudgetを下げ、各段階で重要度推定・bit配置・router tuningをやり直す。

論文ではこれを `progressive quantization` と呼ぶ。

## 評価

### まず見るところ
- **結論:** 全expertをmodel-wide budgetで比較し、routerだけ再適応すると、2〜2.5bit級でも品質を守りやすい。
- **圧縮:** Mixtral級を単一H100へ収まる容量まで削減。
- **品質:** 多くの条件でuniform/PMQを上回るが、最厳2bit条件では常に勝つわけではない。
- **実速度:** optimized kernelで単一H100の実token/sを報告。
- **注意点:** router tuningとcalibration dataが必要で、完全training-freeではない。

### 評価環境

| 項目 | 内容 |
|---|---|
| GPU | H100 80GB ×3（量子化・評価）、単一H100で実行速度も測定 |
| モデル | DeepSeekV2-Lite / Qwen1.5-MoE / Qwen3-30B-A3B / Mixtral-8x7B |
| 評価 | WikiText2、C4、zero-shot、MMLU、GSM8K |

### Mixtral 2.5 bit

| 方式 | WikiText2 PPL | C4 PPL | accuracy |
|---|---:|---:|---:|
| uniform | 6.10 | 10.35 | 65.49 |
| PMQ | 5.10 | 9.21 | 64.34 |
| GEMQ | 5.03 | 9.02 | 65.13 |

GEMQはPPLで最良、accuracyもPMQを上回る。

### モデルサイズと実速度

| 項目 | 結果 |
|---|---:|
| Mixtral weight | 87GB → 約16GB |
| memory削減 | 約82% |
| 単一H100速度 | 82.5 tokens/s |

### calibration data依存

Mixtral 2.5 bitでは、calibrationをC4からMATH+C4へ変えるとaccuracyが65.13 → 66.47へ改善した。

つまりmodel-wide allocationでもexpert重要度の推定はcalibration分布に依存する。

### 例外

Mixtral 2.0 bitではPMQ accuracy 60.38に対しGEMQ 59.98で、全条件で優位ではない。極低bit域ではloss感度の近似や段階的な再最適化を使っても誤差を完全には吸収できない。
