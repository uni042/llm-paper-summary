# A Provably Effective Method for Pruning Experts in Fine-tuned Sparse Mixture-of-Experts

> 事前学習からファインチューニングまでのルーター変化を専門家重要度として使い、視覚MoEで専門家を大きく削減しながら精度を保つ、理論付きの専門家枝刈り法を示す。

## 概要

疎な混合専門家（Mixture of Experts; MoE）は、入力ごとに一部の専門家だけを選ぶため、全パラメータを毎回計算する密モデルより演算量を抑えながら総モデル容量を増やせる。しかし、推論時に使わない専門家であっても、その重みを配置できるメモリ容量は必要になる。下流タスクへファインチューニングした後は、事前学習時に用意された専門家のすべてが、そのタスクに同じ程度必要とは限らない。

従来の枝刈りでは、重みの大きさ、活性値、利用頻度などを重要度として削除候補を決めることが多い。MoEでは「専門家内部の重み」と「どの専門家へ入力を送るかを決めるルーター」が分かれているため、重みの大きさだけではタスク固有の専門家重要度を捉えにくい。本論文は、事前学習済みモデルからファインチューニング済みモデルへ移る間にルーターのL2ノルムがどれだけ変化したかを手掛かりにし、変化が小さい専門家から削る。

この基準は推論ごとに追加の判定器を動かす方式ではなく、ファインチューニング後に専門家を構造的に削除する方式である。簡略化した二値分類MoEでは、一定の仮定の下でこの削除順がテスト精度を保つことを理論的に解析し、実モデルではV-MoEとE3-MoEをCIFAR-10、CIFAR-100、ImageNetで評価する。代表例では、V-MoEのCIFAR-10で後処理のファインチューニングを併用すると専門家75%を削除し、モデル全体のメモリ要求を60%減らしつつ、非枝刈りモデルとの精度差を1%以内に保つ。推論FLOPsと推論時間も約40%削減した。

## 問題設定

MoEの利点は、モデル全体では多数の専門家を持ちながら、各入力では一部だけを活性化する「条件付き計算」にある。ところが、配置時には総専門家重みをGPUやCPU、ストレージのどこかに保持する必要があり、総容量が大きいほどメモリ要求や重み移動の負担は残る。さらに、ルーターが各トークンやパッチを複数専門家へ送る構成では、専門家数が多いほど候補となる演算も増える。

ファインチューニング後には、下流タスクに必要な知識・特徴が一部の専門家へ偏る可能性がある。ここで不要な専門家を安全に削れれば、単に量子化して各重みを小さくするのとは異なり、専門家単位でモデル構造そのものを縮小できる。ただし、頻度の低い専門家が長尾入力には重要という場合もあるため、利用回数だけを見て削ると精度を落とす危険がある。

本論文の着眼点は、下流タスクに適応する過程でルーターがどの専門家への割当をどれだけ変えたかを見ることである。事前学習時からほとんど変化しなかったルーター成分は、その下流タスクの適応に使われた度合いが小さいとみなし、優先的な削除候補にする。これにより、推論時の追加観測を必要とせず、ファインチューニングの履歴そのものを重要度信号に使う。

## 手法

### 1. 事前学習前後のルーター変化を専門家ごとに測る

入力を専門家へ振り分けるルーターについて、事前学習済みモデルとファインチューニング済みモデルを対応付ける。各専門家に対応するルーター重みの変化量をL2ノルムで測り、変化が小さいものから削除順位を付ける。L2ノルムはベクトル差の大きさなので、「その専門家に入力を送る判断規則が下流学習でどれほど更新されたか」を一つのスカラーへ落とす役割を持つ。

重要なのは、専門家内部のパラメータ絶対値を直接比べているのではない点である。MoEでは専門家が有用でもルーターがそこへ入力を送らなければ出力へ寄与しないため、ルーティング側の変化をタスク適応の代理指標として使う。

### 2. 専門家単位で構造的に枝刈りする

順位が決まった後は、変化量の小さい専門家から削る。これは重み行列の要素をばらばらに0へする非構造化枝刈りではなく、専門家を丸ごと除く構造的枝刈りである。そのため、削除後のモデルは専門家重みの保存量を直接減らせ、対応する専門家計算も不要になる。

V-MoEの評価設定では各入力トークンを2専門家へ送るため、層に残す専門家数には下限がある。また、最後から2番目のMoE層が特に敏感で、後処理なしでは大幅な削除が難しいことも報告されている。したがって、単純に全層を同率で減らす方式ではなく、層ごとの感度とルーティング制約を考慮する必要がある。

### 3. 理論保証は簡略MoEの二値分類で与える

理論部分では一般の巨大MoEをそのまま解析せず、簡略化したMoEを用いた二値分類を対象にする。その設定で、ファインチューニングによるルーター変化が小さい専門家を優先して削ることで、一定条件下のテスト精度を保てることを示す。

この保証は、任意のMoE、任意の削減率、任意の下流タスクで無損失を保証するものではない。理論は「なぜこの順位付けに根拠があるか」を支える部分であり、現実のV-MoEやE3-MoEへの一般化は別途実験で確かめる構成になっている。

### 4. 必要なら枝刈り後に短い再学習を行う

後処理なしでも削れる範囲を評価する一方、より高い削減率では枝刈り後のファインチューニングも利用する。V-MoEのCIFAR-10では、後処理なしでは専門家50%・モデル全体35%を削っても非枝刈り精度との差を1%以内に保つ。敏感な層まで含めて再学習すると専門家75%まで削れ、モデル全体60%削減へ到達する。

したがって本手法は「重要度を計算して一度に消せば終わり」というだけではない。許容精度差と追加学習費用に応じて、後処理なしの保守的な削減と、再学習を伴う高圧縮を選ぶ設計になる。

## 評価

### 評価条件

| 項目 | 条件 |
|---|---|
| 主モデル | V-MoE、E3-MoE |
| V-MoE規模 | 約9.79億パラメータ。画像を16×16パッチへ分割し、隠れ次元768、MoE隠れ次元3072 |
| ルーティング | token-choice routing、各トークンを2専門家へ送る |
| データセット | CIFAR-10、CIFAR-100、ImageNet |
| 主指標 | 非枝刈りモデルに対する精度差、削除できる専門家比率、モデル全体削減率、画像当たりFLOPs、推論時間 |
| 比較 | ランダム枝刈り、importance score、重み絶対値、ニューロン変化量などの重要度基準 |
| 後処理 | 枝刈り後の追加ファインチューニングあり／なしを評価 |

### 代表的な評価結果

| 条件 | 指標 | 結果 | 読み取れること |
|---|---|---|---|
| V-MoE / CIFAR-10、後処理なし | 専門家・モデル削減率 | 専門家50%、モデル全体35%を削除して精度差1%以内 | ルーター変化だけでも中程度の構造削減が可能 |
| V-MoE / CIFAR-10、枝刈り後再学習あり | 専門家・モデル削減率 | 専門家75%、モデル全体60%を削除して精度差1%以内 | 再学習を許せば敏感な層も含め圧縮率を上げられる |
| V-MoE / CIFAR-10 | 推論FLOPs・時間 | いずれも約40%削減 | 容量削減だけでなく実際の推論計算にも反映される |
| V-MoE / CIFAR-100 | 最大削減域 | 専門家50%、モデル全体41% | タスク規模が増えると削減可能域が変わる |
| V-MoE / ImageNet | 最大削減域 | 専門家42%、モデル全体35% | 1000クラスでは必要専門家が増え、CIFARより削減余地が小さい |
| E3-MoE / CIFAR-10・100 | 最大削減域 | 専門家75%、モデル全体45%、精度差1%以内 | 別の視覚MoE構造でも同じ順位付けが機能する |

ランダムに専門家を落とすと小さな削減率から性能が急落するのに対し、提案順位は許容精度差1%以内の領域で他の比較基準より高い削減率を保つ。さらに、推論FLOPsと実測推論時間が削減率に伴ってほぼ線形に下がることから、削除した専門家が単なる未使用パラメータではなく、実行コストにも寄与していたことが確認できる。

一方で、ImageNetではCIFARより削れる割合が小さい。論文はクラス数が増えるほど下流タスクに必要な専門家数が増える可能性を示唆しており、「ファインチューニング済みMoEには常に75%不要な専門家がある」という結果ではない。

## 既存研究との差

通常の重み枝刈りや量子化は、専門家内部の行列を小さくしたり低精度化したりする。専門家利用頻度に基づく方法は「どれだけ選ばれたか」を見る。本論文はそれらと異なり、事前学習から下流ファインチューニングまでのルーター変化を、タスク固有の必要性を表す信号として使う。

また、経験的なランキングだけを提示するのではなく、簡略化したMoEで精度保存条件を解析し、その後に実際のV-MoEとE3-MoEで検証する。既存の重み量子化や専門家内部の枝刈りとは併用可能であり、MoEの「専門家数」という別の軸を削る位置付けである。

## 限界

- 理論保証は簡略化した二値分類MoEに対するもので、一般的な自己回帰LLMへ直接適用される保証ではない。
- 実験は視覚MoEに限定される。トークン分布、専門家知識、長尾プロンプトが異なる言語MoEでは再検証が必要である。
- ファインチューニング前後の対応するルーター重みが必要で、元の事前学習チェックポイントが利用できない場合は同じ重要度を計算できない。
- 高い削減率には枝刈り後再学習が必要になる場合があり、圧縮のための追加計算コストが生じる。
- 一部の層は他層より枝刈りに敏感であるため、層一律の削減率を安全に適用できない。
- 平均精度が維持されても、希少クラスや長尾入力で特定専門家を失う影響は別途確認が必要である。
