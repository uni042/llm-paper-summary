# EAQuant: Enhancing Post-Training Quantization for MoE Models via Expert-Aware Optimization

> 密モデル向けの事後学習量子化（Post-Training Quantization; PTQ）をMoEへそのまま持ち込むと、専門家ごとに異なる活性外れ値、量子化後のルータTop-kの入れ替わり、ほとんど選ばれない専門家の校正データ不足が重なる。EAQuantはこれを一つの量子化誤差として扱わず、専門家認識平滑化、ルーティング整合、専門家単位の校正データ均衡の三機構に分解して補正する。

## 概要

混合専門家（Mixture-of-Experts; MoE）モデルでは、各トークンがルータによって一部の専門家だけへ送られる。この疎な活性化により総パラメータ数を大きくしながら実演算を抑えられるが、量子化時には密モデルにはない問題が生じる。

第一に、専門家ごとに受け取るトークン分布が異なるため、活性値の外れ値が出るチャネルや大きさも専門家ごとに違う。第二に、ルータ自身を低ビット化してロジットへ小さな誤差が入ると、Top-k境界付近の専門家順位が入れ替わり、元モデルとは別の専門家へトークンが流れる。第三に、低頻度専門家は通常のランダム校正データでは十分なサンプルを受け取れず、量子化パラメータを安定して決められない。

EAQuantはこの三点をそれぞれ処理する。専門家認識平滑化集約（Expert-Aware Smoothing Aggregation）は専門家別統計から共通のチャネル平滑化量を作り、外れ値を重み側へ移して活性量子化を安定させる。ルーティング一貫性整合（Routing Consistency Alignment）は量子化前後のルータ出力分布を合わせ、Top-k専門家の選択が変わるのを抑える。専門家認識校正データ均衡（Expert-Aware Calibration Data Balance）は低頻度専門家にも十分な校正サンプルが届くようデータを再構成する。

最新稿はW4A4、W3A4、W3A3、W2A4などの強い量子化を含み、OLMoE、DeepSeek-MoE、Qwen3-MoE系の複数アーキテクチャで評価する。設定によって既存方式に対する平均精度改善は1.15〜13.81ポイントまで広がり、ビット幅が厳しいほどMoE固有処理の価値が大きくなる。

## 問題設定

密なTransformerのPTQでは、少量の校正データから各層の活性範囲や重みスケールを決めれば、すべての入力が同じフィードフォワード層を通る。一方MoEでは、同じ層の中に多数の専門家があり、ルータの選択によって各専門家が見るデータ分布もサンプル数も変わる。

この違いを無視して全専門家へ同じSmoothQuant系の平滑化や同じ校正サンプルを使うと、高頻度専門家には合っても低頻度専門家には統計が不足する。またルータ誤差は単なる中間活性誤差ではなく、後段で実行するパラメータ集合そのものを変えるため、その影響が離散的で大きい。

特に低ビット化では、重み誤差・活性誤差・ルーティング誤差が連鎖する。W4A4程度では小さかった差がW3A3やW2A4で急激に広がるため、MoEでは「何ビットにするか」だけでなく「専門家間の不均一性をどう校正するか」が性能維持の中心課題になる。

## 手法

### 1. 専門家認識平滑化で活性外れ値を抑える

SmoothQuant系では、活性値の大きなチャネルを縮め、その逆スケールを重みへ吸収することで、数学的には同等な変換のまま活性ダイナミックレンジを狭める。量子化器は狭い範囲を少ないビットで表現しやすくなる。

MoEで専門家ごとに独立した平滑化係数を使うと、同じ共有入力やルーティング経路との整合が複雑になり、専門家ごとの統計量も不足しやすい。EAQuantは専門家ごとに観測したチャネル統計を集約し、各専門家の外れ値傾向を反映した共通の平滑化ベクトルを作る。

入力は校正データを通した各専門家の活性統計、出力は量子化前に適用するチャネルスケールである。これにより、特定の高頻度専門家だけの統計に引っ張られず、複数専門家で量子化しやすい分布へ揃える。

### 2. ルーティング一貫性整合でTop-kの入れ替わりを抑える

MoEルータは各トークンについて専門家ロジットを計算し、その上位k個を選ぶ。量子化前の第k位と第k+1位が近い場合、わずかなロジット誤差でも順位が逆転する。すると専門家内部の重みが正確に量子化されていても、元モデルと違う計算経路を通る。

EAQuantは量子化後ルータのロジット分布を浮動小数点モデル側へ整合させ、単純な要素誤差だけでなく選択境界を保つ方向へ最適化する。目的はルータ値そのものを完全一致させることではなく、最終的な専門家選択の一貫性を高めることである。

この機構が重要なのは、ルーティング誤差が各層で繰り返されるためである。一層で選択が変わると次層へ入る隠れ状態も変わり、その後のルータ判断まで連鎖的にずれる可能性がある。

### 3. 専門家単位で校正データを均衡させる

通常のPTQは数百〜数千サンプル程度の校正集合を使うが、MoEの低頻度専門家にはそのごく一部しか到達しない場合がある。サンプル数が少ないと活性範囲や再構成誤差の推定が不安定になり、その専門家だけ量子化誤差が大きくなる。

EAQuantは「全モデルで同じ数の校正トークンを見る」のではなく、「各専門家が量子化に必要なサンプルをどれだけ受け取ったか」を基準にデータを組み直す。頻繁に選ばれる専門家だけで校正予算を使い切らず、疎に選ばれる専門家へも代表サンプルを確保する。

入力は校正候補と元ルータの専門家割当、出力は専門家ごとの量子化・再構成へ使う均衡化されたサンプル集合になる。これにより、低頻度専門家での誤差増大を抑える。

### 4. 三機構を通常のPTQパイプラインへ組み込む

処理順としては、まず校正データを浮動小数点モデルへ通して専門家活性とルーティング統計を集める。次に専門家認識平滑化を決め、校正データを専門家単位で整えながら各層を量子化する。その際にルータの量子化前後分布も整合させる。

モデル全体を再学習する量子化認識学習（Quantization-Aware Training; QAT）ではなく、学習済みMoEへ後付けするPTQである点が運用上の利点になる。ただし校正と層ごとの最適化は必要で、完全な「データ不要」量子化ではない。

## 評価

### 主な評価条件

| 項目 | 条件 |
|---|---|
| モデル | OLMoE、DeepSeek-MoE、Qwen3-MoE系の3アーキテクチャ |
| 量子化 | W4A4、W3A4、W3A3、W2A4など |
| 比較 | DuQuantなど密モデル向けPTQ、MoEQuant等のMoE向け方式 |
| 言語モデル指標 | WikiText-2、C4のパープレキシティ |
| 下流タスク | ARC-C/E、BoolQ、HellaSwag、OBQA、RTE、WinoGrande等 |
| 主要指標 | 平均精度、パープレキシティ、強い低ビット化での性能保持 |
| 実装 | 著者公式EAQuantコード |

### W4A4の代表例

| モデル | DuQuant平均精度 | EAQuant平均精度 | 差 |
|---|---:|---:|---:|
| OLMoE | 55.35 | 56.70 | +1.35 pt |
| DeepSeek-MoE | 53.67 | 54.60 | +0.93 pt |
| Qwen3-MoE | 62.93 | 63.16 | +0.23 pt |

論文表では改善率を相対値で併記する場合があるため、上表は読みやすさのため**絶対ポイント差**として計算している。W4A4では差は比較的小さいが、量子化をW3A3やW2A4へ強めると既存方式の崩れが大きくなり、最新版abstractでは三アーキテクチャを通じた平均改善幅を1.15〜13.81ポイントと報告する。

### 評価の読み方

W4A4での利得だけを見ると通常PTQとの差は小さい条件もある。しかしEAQuantの狙いは、MoE固有の三つの失敗要因が顕在化する強い低ビット領域で精度崩壊を遅らせることにある。

一方、この論文の主評価は**精度保持**であり、特定GPU上のエンドツーエンド推論速度を主結果として示すものではない。W3/W2重みや低ビット活性が理論上容量・帯域を減らしても、実速度は対応カーネルと実行基盤に依存するため、精度改善値と速度倍率を混同しない。

## 既存研究との差

SmoothQuantやDuQuantのような密モデル向け方式は、層内の活性外れ値や量子化誤差を扱うが、専門家ごとの利用頻度差やルータTop-kの離散的な入れ替わりを中心課題にはしない。

MoEQuant系はMoEの校正不均衡を意識するが、EAQuantは外れ値平滑化、ルーティング整合、校正データ均衡を一つのPTQパイプラインで同時に扱う。どれか一つの量子化器を置き換えるより、「MoEだから失敗する場所」を三箇所に分けて対処するのが設計上の差である。

## 限界・実装状況

校正データが必要であり、ルーティング分布が配備後に大きく変わる場合、校正時に低頻度だった専門家が本番で高頻度になるなどの分布ずれが起こり得る。極端な低ビットではEAQuantでも浮動小数点モデルとの品質差は残る。

また精度改善がそのまま推論高速化を意味するわけではない。W3A3やW2A4を実際に高速化するには、対象GPUでそのビット幅を効率よく実行するカーネルやパッキング形式が必要である。

著者公式実装は公開されており、重みビット、活性ビット、ルータ重みビットなどを指定して量子化できる。したがってアルゴリズム再現は可能だが、配信基盤へ統合する際は低ビットMoEカーネル側の対応を別途確認する必要がある。
