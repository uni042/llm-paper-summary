# Delta Decompression for MoE-based LLMs Compression

> MoEの専門家同士は完全に別物ではなく、大きな共通知識と比較的小さな専門家固有差分を持つ。D²-MoEはこの構造を「共有基底＋低ランク差分」として明示し、全専門家を保存するコストを減らしながら専門家ごとの特化を残す。

## 概要

専門家混合（Mixture of Experts, MoE）は1トークン当たり一部の専門家しか活性化しないため、総パラメータ数に対して演算量を抑えられる。しかし推論機には全専門家重みを保存する必要があり、MixtralやDeepSeekMoEのように専門家数が増えるとVRAM・DRAM・ストレージの負担が大きい。

既存の圧縮には、専門家そのものを削る枝刈りと、似た専門家を一つへ統合するマージがある。前者は専門家容量を失い、後者は各専門家が学んだ固有差を潰しやすい。D²-MoEは、専門家 (W_i) を共有基底 (W_b) と差分 (Delta W_i=W_i-W_b) に分解する。共通知識は1個の基底として保存し、専門家固有成分だけ個別に残す。

差分は元専門家重みより低ランクになりやすいため、活性統計を使った特異値分解（Singular Value Decomposition, SVD）で圧縮する。一方、複数専門家を混ぜた共有基底は高ランクになりやすいので、低ランク化ではなく構造枝刈りを使う。推論時は共有基底の出力に、ルータが選んだ上位k専門家の低ランク差分出力を足す。

## 問題設定

### 「専門家を統合する」と専門家固有知識まで消える

複数専門家の重みを単純平均すると共通部分は残るが、特定入力に強い専門家が持つ固有成分も平均化される。専門家を削除する方式ではさらに直接的に容量を失う。

D²-MoEの観察では、専門家を共通基底からの差分へ変換すると、その差分行列は元の専門家行列より低ランク性が強い。したがって「共有成分は一度だけ保持し、個別成分だけ圧縮して複数持つ」方が、専門家多様性を残しながら総容量を下げやすい。

### 基底と差分では適した圧縮法が違う

共有基底は多くの専門家情報を集約するためフルランク寄りで、SVDによる強い低ランク化に弱い。差分は低ランク化しやすい。そこでD²-MoEは両者に別の圧縮を割り当てる。

これは単に圧縮器を二つ並べたのではなく、MoE重みを「共有知識」と「ルータで選ばれる専門家固有知識」に再パラメータ化したうえで、それぞれの統計構造へ合う圧縮を選ぶ設計である。

## 手法

### 1. フィッシャー情報で共有基底を作る

単純平均では、性能に重要な専門家とそうでない専門家を同じ重みで混ぜる。D²-MoEはフィッシャー情報行列（Fisher Information Matrix）を各専門家重みの重要度として使い、パラメータごとに重要度付き平均を取る。

勾配感度が高い重みほど共有基底へ強く反映されるため、平均化による重要知識の消失を抑える。実験ではMixtral-8×7Bの40%圧縮設定で、WikiText-2/PTB/C4の困惑度がフィッシャー統合で5.28/20.54/10.10となり、単純平均7.66/46.85/24.39より大幅に良い。

### 2. 専門家固有差分を活性統計付きSVDで圧縮する

各専門家について (Delta W_i=W_i-W_b) を作る。差分へ直接SVDするだけでなく、較正入力から得た活性グラム行列をコレスキー分解し、そのスケール行列を差分へ掛けてからSVDする。

この切断対応SVD（truncation-aware SVD）は、「重み行列として小さい誤差」ではなく「実際の活性を通した時に影響の小さい成分」を落とすことを狙う。上位成分だけを (Delta U_i,Delta V_i) として保存し、専門家ごとの多様性を低ランク因子で残す。

### 3. 共有基底を半動的に構造枝刈りする

共有基底はフルランクで大きいため、列単位の構造枝刈りを適用する。目標疎性の前半は静的に削る。重みノルムと較正活性から列重要度を計算し、入力にほぼ依存せず重要度の低い列を除く。

残り半分は実行時の入力バッチXを使い、保持列について重みノルム×入力活性ノルムを再計算して下位列を削る。これにより常に不要な列は事前に消しつつ、入力ごとに不要な列も追加で止める。

### 4. 推論では「基底1回＋選択差分k個」を計算する

元MoEはルータがtop-k専門家を選び、それぞれの完全な専門家重みを実行する。D²-MoEでは共有基底 (W_bx) を一度計算し、ルータが選んだ専門家についてのみ (Delta U_iDelta V_i x) を計算して加算する。

共有部分を専門家ごとに重複して保存・計算せず、差分も低ランクなので、総パラメータだけでなく活性化パラメータ量と演算量も減る。

## 評価

### 評価条件

| 項目 | 条件 |
| --- | --- |
| GPU | NVIDIA A100 |
| モデル | Mixtral-8×7B、DeepSeekMoE-16B-Base、Phi-3.5-MoE、Qwen2-57B-A14B |
| 専門家規模 | Mixtral 8 experts、Phi-3.5 16 experts、DeepSeek/Qwen2 64 experts |
| 言語モデル評価 | WikiText-2、PTB、C4（困惑度） |
| 常識推論 | OpenBookQA、ARC-e、WinoGrande、HellaSwag、ARC-c、PIQA、MathQA（0-shot accuracy） |
| 較正データ | WikiText-2からランダム512 samples |
| 主比較 | NAEE、MoE-I²、その他枝刈り・マージ・SVD系圧縮器 |
| 速度評価 | Mixtral-8×7B、batch 64、60/70/80%圧縮 |

### 主要品質結果

| モデル・圧縮率 | 元モデル平均 | D²-MoE | NAEE | MoE-I² |
| --- | ---: | ---: | ---: | ---: |
| Mixtral-8×7B 20% | 0.63 | 0.60 | 0.58 | 0.57 |
| Mixtral-8×7B 40% | 0.63 | 0.57 | 0.48 | 0.49 |
| Mixtral-8×7B 60% | 0.63 | 0.52 | 0.36 | 0.36 |
| DeepSeekMoE-16B 20% | 0.56 | 0.54 | 0.53 | 0.50 |
| DeepSeekMoE-16B 40% | 0.56 | 0.49 | 0.46 | 0.45 |
| DeepSeekMoE-16B 60% | 0.56 | 0.41 | 0.38 | 0.37 |

Mixtralの20%圧縮では元性能の約95.2%を維持する。40〜60%の高い圧縮域で差が広がる点が本論文の主張で、単純に専門家を削除/統合するより差分を残す方が高圧縮時に強い。

### 実推論の速度・メモリ

| Mixtral-8×7B, batch 64 | 60%圧縮 | 70%圧縮 | 80%圧縮 |
| --- | ---: | ---: | ---: |
| モデルサイズ | 18.68B | 14.01B | 9.33B |
| メモリ | 34.8 GB | 26.1 GB | 17.3 GB |
| D²-MoE TFLOPs | 481 | 386 | 290 |
| D²-MoE throughput | 277.72 tok/s | 300.33 tok/s | 313.29 tok/s |
| NAEE throughput | 271.89 tok/s | 272.66 tok/s | 278.53 tok/s |
| MoE-I² throughput | 227.60 tok/s | 252.55 tok/s | 294.04 tok/s |

80%圧縮ではD²-MoEがNAEEより12.5%、MoE-I²より6.5%高いスループットを示す。LoSparseは1330 TFLOPsを使って198.04 tok/sであり、パラメータ数だけでなく構造化された実行形へ落とす重要性が見える。

WikiText-2困惑度は60/70/80%圧縮で6.35/8.15/12.95と悪化するため、80%圧縮の高速化には明確な品質コストがある。

### 圧縮前処理の費用

Mixtral-8×7Bではフィッシャー統合に約11分、活性スケール収集＋SVDに合計約44分を要する。Qwen2-57B-A14Bでは統合23分、SVD59分。オンライン学習ではないが、較正と分解に相応の一時メモリも必要である。

## 既存研究との差

専門家枝刈りは専門家単位または重み単位を削り、専門家マージは複数専門家を一つに寄せる。D²-MoEは「マージした共有基底を使いながら、捨てられていた差分を圧縮して残す」点が異なる。

また、単なる低ランク専門家圧縮ではなく、共有基底は構造枝刈り、差分は低ランク分解という異種圧縮を使う。MoE内部の冗長性が一様ではないという観察を、保存形式と実行経路へ反映している。

## 限界・実装状況

半動的枝刈りは入力バッチごとに重要度を更新するため、完全静的な密行列よりランタイム制御が増える。論文のスループット結果では利得が上回るが、batch sizeやGPUカーネル実装が変われば管理費用との釣り合いも変わる。

高圧縮では品質劣化が残り、80%圧縮は「元品質をほぼ維持したまま」の領域ではない。またフィッシャー統合と活性較正にはオフライン処理・一時メモリが必要である。
