# Examining Post-Training Quantization for Mixture-of-Experts: A Benchmark

> MoEのpost-学習 量子化を体系比較し、エキスパート頻度・ブロック位置・線形層ごとの量子化感度を示すベンチマーク。

## 概要
この研究の差分は、量子化方式を一つ発明することより、同一平均ビットで「頻度・ブロック位置・線形層」のどれを高ビット化すると有利かを分離したことにある。Mixtralの均等ルーティングとDeepSeekの不均衡ルーティングを並べたため、頻度ヒューリスティックがモデル依存になることも検証できる。

## 手法のあらまし

### 1. この論文は「新しい量子化器」よりbit配置の比較が主題

比較するのは、全エキスパートを同じビットへ落とす方式だけではない。同じ平均ビット数を保ったまま、**どの部分へ高ビットを残すか**を変えて品質差を見る。

評価粒度は主に次の4段階である。

比較を同じ平均ビット予算に揃えることが重要である。高精度に残す部分を増やせば単純に品質が上がるため、配置戦略の良し悪しを調べるには、全体の平均ビット数をほぼ同じにした上で『どこへ高ビットを使ったか』だけを変える必要がある。この設計により、品質差を容量差ではなくMoE構造に沿ったビット配分の効果として読みやすくしている。

| 粒度 | 何を見るか |
|---|---|
| エキスパート 頻度 | よく使われるエキスパートを高ビットにすべきか |
| ブロック position | 特定のMoE ブロックが量子化に弱いか |
| 線形 層 | gate/up/down等の線形ごとに感度が違うか |
| 共有 / 注意機構 | routed エキスパート以外を保護すべきか |

### 2. `frequency-based allocation`

較正 データを流し、各MoE ブロックでエキスパートが何回選ばれたかを集計する。その上で、高頻度エキスパートだけ4 ビット、残りを2 ビットにする。

ここで重要なのは、**高頻度＝常に重要、とは仮定していない**ことだ。Mixtralのようにルーティングが比較的均等なモデルでは頻度差が小さく、このヒューリスティックの利点も小さい。一方DeepSeekのように偏りが強いモデルでは有効になりやすい。

### 3. `linear-weight outlier scorer`

エキスパート単位より細かく、各線形 重みがどの程度量子化に弱いかを、重みの外れ値量から順位付けする。

上位25%や50%の線形だけ4 ビットへ戻し、それ以外を2 ビットにすることで、**同じ平均ビットでも感度の高い場所へ精度を集中させる**。

外れ値スコアは『その線形層が実際のタスク損失へ何点寄与するか』を直接測るものではなく、低ビット丸めで大きな誤差を生みやすい重み分布の代理指標である。したがって高スコア部分を保護する方式は、全候補をタスク評価して探索するより安価だが、入力分布や較正データが変われば感度順位も変わり得る。この点で、配置は一度決めれば普遍的に最適なものではない。

### 4. `MoE block scorer`

今度は逆に、線形より粗いブロック単位で量子化損失を見積もり、重要ブロックだけ4 ビットにする。

したがってこの論文は、エキスパート / 線形 / ブロックという複数の粒度で、「低ビット化する場所の選び方」を比較したベンチマークとして読むのが分かりやすい。

### 5. GPTQとSmoothQuantの両方で確認

重み-のみではGPTQ、重み+活性値ではSmoothQuantを使う。つまり結果は特定の1つの量子化アルゴリズムだけに依存するというより、**MoE構造を考慮したビット配置そのものが有効か**を確認する設計になっている。

重みのみ量子化と重み・活性値量子化の両方で同じ傾向を確認する理由は、低精度化の誤差源が異なっても『どのMoE構造が敏感か』という順位が利用できるかを確かめるためである。もし特定の量子化器だけでしか成立しないなら一般的な配置指針にはしにくい。複数方式で再確認することで、ブロック・エキスパート・線形層の感度差を量子化器固有の偶然から切り離そうとしている。

## 評価

### まず見るところ
- **結論:** 同じ2〜4bit予算でも、どのエキスパート/ブロック/線形を高精度に残すかで品質が変わる。
- **品質:** 頻度だけでなくブロック/線形感度を使う構造aware mixed 精度がrandom 割り当てより安定する。
- **圧縮:** 平均ビットをかなり下げても高感度部分を保護すれば品質を守れる余地がある。
- **実速度:** **主評価は精度とビット配置で、wall-clock 高速化倍率論文ではない**。
- **注意点:** ルーティング頻度はモデルと較正 データに依存し、Mixtralのような均衡ルーティングでは効果が小さい。

### 評価環境

| 項目 | 内容 |

| GPU | NVIDIA H100 ×3 |

### Mixtral：高頻度expertを高bitにする効果

| 平均ビット | 配置 | 平均精度 |
|---:|---|---:|
| 2.54 ビット | 頻度上位2 エキスパートを4 ビット | 54.20% |
| 2.54 ビット | ランダムに4 ビット | 49.10% |
| 3.03 ビット | 頻度上位4 エキスパートを4 ビット | 63.82% |
| 3.03 ビット | ランダムに4 ビット | 63.70% |

2.54 ビットでは差が大きい一方、3.03 ビットではほぼ同じになる。**高ビット エキスパート数が増えるほど、配置方法の差が小さくなる**ことが分かる。

### DeepSeek：頻度heuristicの読み方

平均2.53 ビットで頻度上位10 エキスパートを4 ビットにした場合は62.99%、ランダムは62.86%で、この設定だけなら差は小さい。一方、高ビットに残すエキスパート数を増やした設定では頻度法がより安定して優位になる。

これは「DeepSeekなら頻度だけで十分」という意味ではなく、**ルーティングの偏りがあるモデルでは頻度をビット配置の手掛かりに使える**という程度に読むのが妥当である。

### activation bitを増やしても改善が小さい例

Mixtralの重み平均2.54 ビット条件でSmoothQuantを使った場合、活性値 4 / 8 / 16 ビットの平均精度は38.30 / 39.79 / 39.71%だった。

この条件では活性値だけ高精度へ戻しても改善が限定的で、**どの重みを低ビット化したかの方が支配的**だった。

### この論文で実速度を主張しない理由

実験にはH100を使っているが、中心指標は精度と平均ビットで、GPU 遅延やトークン/sの横断比較は限定的である。

したがって後続のMxMoEのような「カーネル実時間まで含めてビット 割り当てを決める研究」とは役割が異なり、こちらは **MoE量子化の感度マップを作ったベンチマーク** と位置付けるのが適切である。

このため本論文の高精度なビット配置を、そのまま『最速の実装』と解釈してはいけない。低ビット重みを実時間短縮へ変換するには、対象GPUでそのビット幅を直接処理できるカーネル、復号費用、メモリアクセス量まで含めた実行系が必要になる。本論文はその前段として、限られた精度予算をどの構造へ配るべきかを明らかにする役割を持つ。

このベンチマークから得られる実務的な手順は、まずルーティング履歴を集め、エキスパートごとの利用頻度と量子化後の品質を対応付けることである。頻度上位を高ビットにする規則は、ルーティングが偏るモデルでは有効な出発点になるが、均衡しているモデルではランダム配置との差が小さくなり得る。そのため配置を決める際は、平均ビットだけでなく、対象タスクの較正分布とエキスパート利用分布を同じ条件で評価する必要がある。

また、活性値を高精度に戻しても品質が大きく改善しない例は、誤差の主因が重み側にあることを示す。逆に別のモデルやビット幅では挙動が変わる可能性があるため、単一の結論を全MoEへ外挿してはいけない。後続手法を比較するときも、配置の品質効果、実行カーネルの速度効果、較正データの効果を分けて報告することが重要である。
