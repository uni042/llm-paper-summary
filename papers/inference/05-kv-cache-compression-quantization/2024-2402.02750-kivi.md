# KIVI: A Tuning-Free Asymmetric 2bit Quantization for KV Cache

> キーはチャネル単位、値はトークン単位で2ビット量子化し、直近KVだけ高精度保持することで追加学習なしにKVメモリと帯域を削減し最大3.47倍のスループットを得る。
## 書誌情報
- **著者**: Zirui Liu, Jiayi Yuan, Hongye Jin, Shaochen (Henry) Zhong, Zhaozhuo Xu, Vladimir Braverman, Beidi Chen, Xia Hu
- **公開**: ICML 2024 / arXiv:2402.02750
- **種別**: Conference
- **対象**: KVキャッシュ量子化、2ビット量子化、長文脈推論、GPUメモリ、推論スループット
- **実装**: Hugging Face Transformers上に実装。CUDAで逆量子化をタイル行列積へ融合し、Tritonでグループ量子化カーネルを実装。重み専用量子化と併用可能。
## 概要
KIVIは、LLMのKVキャッシュ分布を分析し、キーには固定チャネルの外れ値があるためチャネル単位、値にはその構造がなく注意出力でトークン混合されるためトークン単位で量子化すべきと示した。これに基づき、古いKVを2ビットのグループ量子化で保持し直近最大128トークンを高精度残差として残す、追加学習不要の非対称KV量子化を提案する。CUDA/Triton実装で逆量子化と行列積を融合し、Llama系で品質をほぼ維持しつつピークメモリを最大2.6分の1、バッチを最大4倍、実ワークロードのスループットを2.35〜3.47倍にした。

KV分布と注意演算の誤差伝播を分けて分析し、キーはチャネル単位、値はトークン単位という非対称な量子化軸が必要だと示した点が中心である。キーには特定チャネルへ持続する大きな外れ値があり、チャネル単位なら外れ値のスケールを他チャネルへ波及させない。一方、値は注意重みで少数の重要トークンが混合されるため、トークン単位で誤差を閉じ込める方が注意出力誤差を小さくする。この原理をストリーミングKVへ適用するため、古いKVをグループ化して2ビット保存し、直近KVを高精度残差として保持する。

代表結果として、ピークメモリ削減はLlama-2-7B、モデル重み込み、単一A100 80GBでFP16 KVキャッシュに対して最大2.6倍少ない。KVだけでなく総ピークメモリが大きく減るため、同一GPUで同時要求数を増やせる。
## 問題設定
自己回帰推論では各層の過去トークンのキー・値をKVキャッシュへ保存し、次トークンごとに全キャッシュをGPU主記憶から読み出す。バッチと文脈長に比例して容量が増え、OPT-175Bの例ではバッチ512、入力512、出力32だけで1.2TBと重みの3.8倍になる。メモリ不足は同時処理バッチを制限し、読み出し中は計算器が待つため帯域も速度のボトルネックになる。単純なKV量子化は有望だが、ストリーミングで追加され続けるKVへGPTQのような最適化型量子化を毎回適用するのは高コストで、キーと値を同じ軸で2ビット化すると大幅な精度低下が起こる。既存のMQA/GQAはモデル学習・微調整が必要で、トークン削除方式は情報自体を捨てるため、既存モデルへ追加学習なしで適用できる極低ビットKV圧縮が必要である。
## 新規性
KV分布と注意演算の誤差伝播を分けて分析し、キーはチャネル単位、値はトークン単位という非対称な量子化軸が必要だと示した点が中心である。キーには特定チャネルへ持続する大きな外れ値があり、チャネル単位なら外れ値のスケールを他チャネルへ波及させない。一方、値は注意重みで少数の重要トークンが混合されるため、トークン単位で誤差を閉じ込める方が注意出力誤差を小さくする。この原理をストリーミングKVへ適用するため、古いKVをグループ化して2ビット保存し、直近KVを高精度残差として保持する。
## 手法
### 手法のあらまし
処理は事前学習や較正なしで各注意層のKV生成から始まる。まず入力プロンプトのプリフィルで通常どおりFP16のキーKと値Vを計算し、その正確なK/Vは次層への計算にはそのまま渡す一方、長期保存するKVキャッシュだけを圧縮する。キーについてはトークン列をG=32などのグループに分け、各チャネル内の値を同じグループとして最小値・最大値からゼロ点とスケールを求め2ビットへ丸める。グループを完成できない末尾と直近RトークンはFP16残差K_rとして残す。値は各トークンのチャネル群をG要素ずつまとめるトークン単位量子化を行い、同様に直近RトークンをFP16残差V_rとして保持する。デコードで新トークンが来るたび、そのK/VはまずFP16残差へ追加される。キー残差がRへ達したら、そのまとまりをチャネル単位2ビットへ量子化して既存の量子化キーK_gへ連結し、キー残差を空にする。値残差がRを超えたら最も古い部分だけをトークン単位2ビット化して量子化値V_gへ移し、最新RトークンをFP16のまま残す。次トークンの注意スコア計算では、クエリQと量子化K_gの積をCUDAの混合精度タイル行列積で計算し、タイル内部で2ビット値をスケール・ゼロ点から逆量子化する。同時にQとFP16 K_rを通常の行列積で計算し、両方のロジットをトークン順に連結してSoftmaxを取る。得た注意重みも古い量子化領域と直近残差領域に分け、前者と量子化V_gの積は同じ融合逆量子化行列積、後者とFP16 V_rの積は通常行列積で計算し、2つの出力を加算して注意出力を得る。こうして全KVをFP16へ復元する中間バッファを作らず、古い大部分は2ビットのまま主記憶から読み、直近情報だけ高精度に保つ。グループ量子化自体はTritonカーネルで実行され、生成終了までこの更新・融合注意を反復する。

### キーのチャネル単位2ビット量子化
キーキャッシュにはモデル層を通じて同じチャネル位置に大きな外れ値が現れる。トークン単位で32要素などを同じスケールへ入れると外れ値が通常チャネルの量子化幅を広げるが、チャネル単位なら各チャネルの値域を独立に扱える。Llama-2-13Bの解析ではキー再構成誤差がトークン単位13.67からチャネル単位4.55へ、注意スコア誤差が47.00から9.60へ低下した。ストリーミングでは複数トークンが揃うまでチャネル方向グループを作れないため、未完成部分を高精度残差として保持しRトークン単位で量子化済み領域へ移す。

### 値のトークン単位2ビット量子化
値キャッシュにはキーのような固定チャネル外れ値が明確でなく、単純な再構成誤差だけならチャネル単位も近い。しかし注意出力は各トークンの値ベクトルを疎な注意重みで混合するため、重要トークン内の量子化誤差を他トークンへ混ぜないことが重要になる。実測では値の再構成誤差はトークン単位4.57、チャネル単位3.73と近いのに、注意出力誤差は3.55対49.89でトークン単位が約15倍小さい。新規値は1トークン単位で直ちに扱えるためストリーミングとも整合し、直近RトークンだけFP16で保持して局所情報の精度を補強する。

### 高精度残差窓と融合GPUカーネル
全KVを即座に2ビット化せず、キーと値の直近最大Rトークンを高精度で残す。長文脈ではR≤128の追加メモリは全キャッシュに対して小さく、GSM8Kのような難しい生成で局所情報の精度低下を抑える。注意計算では量子化済み古い領域と高精度残差領域をそれぞれ計算し結合する。量子化領域を毎回FP16へ全面展開すると帯域削減が失われるため、CUDAで逆量子化をタイル行列積へ融合し、必要なタイルだけをレジスタ/共有記憶側で復元して積和する。Tritonのグループ量子化カーネルと合わせ、2ビット保存による容量削減を実際のスループットへ結び付ける。

### 全体のデータ／制御の流れ
Hugging Face Transformersの注意層へ差し替え可能なKVキャッシュ表現として実装される。量子化済み古いKVと高精度の直近KVを同時保持し、注意演算だけが両表現を統合するためモデル重みや学習済みパラメータは変更しない。重み専用量子化とも独立に併用できる。
## 評価条件
- **ハードウェア**: 効率評価は単一NVIDIA A100 80GB。モデルはLlama/Llama-2 7B・13B、Falcon-7B、Mistral-7Bを中心に評価し、長文脈検索ではLlama-3-8B-Instruct等も確認する。
- **ソフトウェア**: Hugging Face Transformersを基盤にKIVIを実装。CUDAで2ビットKVの逆量子化とタイル行列積を融合し、Tritonでグループ量子化カーネルを実装する。
通常文脈はLM-EvalのCoQA、TruthfulQA、GSM8K、長文脈はLongBenchのQasper、QMSum、MultiNews、TREC、TriviaQA、SAMSum、LCC、RepoBench-Pとneedle-in-a-haystackで評価する。標準設定はグループサイズ32、残差長128で、2ビットKIVIを16ビットKVと比較する。FalconはMQAのため4ビットも重点比較する。効率はShareGPTに基づく平均入力161・出力338トークンの合成ワークロードで、Llama-2-7Bのバッチをメモリ不足まで増やし、ピークメモリとスループットを測定する。残差長32/128の比較とグループサイズ32/64/128のアブレーションも行う。
品質・システムの双方を実測するが、効率値は単一A100とLlama-2-7B中心で、他GPUや分散サービングへの絶対性能一般化には追加検証が必要。長文脈上限はMistralで8192、その他で4096が中心である。
## 主要結果
KIVIはキーと値に異なる量子化軸を使うことで、単純な2ビットKV量子化で生じる精度崩壊を回避した。Llama/MistralではLM-Evalの低下を概ね2%以内、LongBench平均を16ビットとほぼ同等に保ちながらKVを2ビット化できる。Llama-2-7Bの実ワークロードではモデル重み込みピークメモリを最大2.6分の1にし、同程度のメモリ上限でバッチを最大4倍へ拡大して2.35〜3.47倍のスループットを得た。

- ピークメモリ削減 / 最大2.6倍少ない (比較対象: FP16 KVキャッシュ; 条件: Llama-2-7B、モデル重み込み、単一A100 80GB) — KVだけでなく総ピークメモリが大きく減るため、同一GPUで同時要求数を増やせる。

- 最大バッチサイズ / 最大4倍 (比較対象: FP16 KVキャッシュでメモリ不足になるバッチ; 条件: ShareGPT型ワークロード、平均入力161・出力338トークン) — KV容量削減が直接バッチ余地へ変換され、GPU計算資源をより高い並列度で利用できる。

- スループット / 2.35〜3.47倍 (比較対象: FP16 KVキャッシュ; 条件: Llama-2-7B、A100 80GB、残差長32/128を含む実装) — 容量削減とKV読み出し量削減に加え、より大きいバッチを使えることが実ワークロードの処理量増加へつながる。

- キー注意スコア相対誤差 / チャネル単位9.60 (比較対象: トークン単位47.00; 条件: Llama-2-13B、2ビット相当の分布解析) — 固定チャネル外れ値をチャネルごとのスケールへ隔離することがキー量子化の主要因である。

- 値の注意出力相対誤差 / トークン単位3.55 (比較対象: チャネル単位49.89; 条件: Llama-2-13B) — 値では単純な再構成誤差より、疎な注意で重要トークンの誤差を独立に保つことが重要である。

### 負の結果・境界条件
- キーと値の両方をトークン単位2ビットにするとLlama-2-13B CoQAが66.37から52.93へ低下し、両方をチャネル単位にすると2.88まで崩壊する。Falcon-7BはMQAによりKVが元々強く圧縮されており2ビットKIVIでは精度低下が比較的大きく、4ビットが必要になる。グループサイズを128へ広げるとGSM8K性能が20.77付近から17.29へ低下する。量子化処理自体にもオーバーヘッドが残り、著者は前後演算との追加融合を今後の課題としている。

### 結果の読み方
KVキャッシュは一様な活性値ではなく、キーと値で注意演算中の役割と誤差感度が異なる。極低ビット化を成功させた理由は、キーのチャネル外れ値と値のトークン混合という異なる誤差源へ量子化軸を合わせたこと、さらに直近KVを高精度で残して難しい局所依存を保護したことにある。システム側では逆量子化を行列積へ融合し、圧縮したデータを再度全面展開しないことで帯域削減を保持する。
## 品質への影響
Llama/Mistralの主要生成評価では2ビット化による低下は小さい。LongBench平均はLlama2-7Bで44.52→44.27、13Bで44.85→44.69、Mistral-7Bで46.58→45.85。Llama-2-13BのGSM8Kは22.67→20.77と難しい推論で差が出るが、高精度残差窓が低下を緩和する。
## 既存研究との差
FlexGen等の4ビットKV量子化がキーと値へ同じグループ方式を適用するのに対し、KIVIは分布と注意誤差を分析してキーをチャネル単位、値をトークン単位に分け、2ビットまで下げる。SmoothQuantは重み・活性値の変換で8ビット化を容易にするが4ビット以下では精度が落ちやすい。KVQuantは同時期にキーのチャネル外れ値へ着目した並行研究である。H2OやStreamingLLMなどの削除方式と異なりKIVIは全トークンを保持して精度だけを落とし、PagedAttentionやオフロードなどのメモリ管理方式とは直交するため併用できる。
## 限界
2ビットの有効性は注意方式に依存し、MQAのFalcon-7Bでは元々KVが小さく2ビット化の精度損失が大きいため4ビットが推奨される。直近残差窓と量子化スケール/ゼロ点のメタデータがあるため理論上の8倍圧縮がそのまま総メモリ削減にはならない。難しい算術推論ではGSM8Kのように低下が残り、グループサイズを大きくしすぎると誤差が増える。効率評価は単一A100と特定ワークロード中心で、量子化カーネル自体のオーバーヘッドも完全には消えていない。
## 実装状態
公開コードがあり、Hugging Face Transformers上でLlama/Falcon/Mistral系へ適用できる。CUDAの混合精度行列積とTriton量子化カーネルを含み、単なる模擬量子化だけでなくA100上のピークメモリ・スループットを実測している。重み専用量子化との併用も設計上可能である。
## 研究上の位置づけ
KVキャッシュ圧縮系統で、後学習型の極低ビット量子化を実際の推論速度へ結び付けた代表的手法に位置付く。特にキーと値で量子化軸を変える非対称設計と、高精度の直近残差窓は後続KV量子化の比較基準になる。オフロード・ページング・トークン削除がKVの配置や保持数を減らすのに対し、KIVIは1要素当たりのバイト数を減らすため、階層メモリやPagedAttentionと組み合わせて容量・帯域の両方を削る余地がある。
