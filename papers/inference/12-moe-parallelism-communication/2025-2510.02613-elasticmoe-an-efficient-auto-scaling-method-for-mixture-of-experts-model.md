# ElasticMoE: An Efficient Auto Scaling Method for Mixture-of-Experts Models

## 概要

大規模MoEをクラウドで伸縮させる場合、通常の水平スケーリングは現在の推論構成を丸ごともう1複製追加するため、1複製が数十〜数百アクセラレータなら増設粒度が粗い。垂直スケーリングで既存複製の並列度を変える方式は細粒度だが、プロセス再起動、重み再読込、KVキャッシュ再構築が発生し、短時間のバーストに間に合わない。ElasticMoEは推論実行と高帯域メモリ（High Bandwidth Memory; HBM）の所有・管理を分離し、既存の重みとKVを捨てずに並列構成を変更する。

中核はHBM管理モジュール（HBM Management Module; HMM）である。HMMが重みとKVキャッシュを推論プロセスとは独立して保持し、新しい実行プロセスはプロセス間通信（Inter-Process Communication; IPC）のメモリハンドルを介してゼロコピーで既存領域へ接続する。新しいアクセラレータにだけ必要な重みを高帯域P2P転送し、専門家重みは仮想連続アドレスと物理ページを分離してページ表を差し替える。これによりサービスを止めずにデータ並列（DP）と専門家並列（EP）の構成を変える。

Ascend NPU上で3種のMoE LLMを評価し、従来方式に対してスケールアップ遅延を最大9倍短縮し、スケール処理中の推論処理量を最大2倍にした。重要なのは定常時のMoE演算を高速化する方式ではなく、負荷変動時の「再構成期間」を短くし、その期間も要求処理を継続する点である。

## 問題設定

MoEでは専門家重みの総容量が大きく、専門家並列で多数アクセラレータへ分散する。負荷が急増しても、水平スケーリングで完全な複製を増やすと必要アクセラレータ数が大きな単位で跳ね、余剰資源が増える。さらに新複製へ全重みをストレージからロードし、初期化する時間がバースト継続時間より長い場合、スケール完了時にはピークが終わっている。

既存複製のEP度を変更すれば増設粒度は小さくできるが、一般的なランタイムは専門家テンソルを現在のEP配置に合わせた連続バッファとして確保する。EP度変更時に新しい形のバッファを確保して重みをコピーすると、一時的に旧・新バッファが共存しピークHBMが増える。プロセス再起動を伴えばKVキャッシュも失われ、進行中要求を移行できない。

ElasticMoEはこの問題を「推論プロセスの寿命」と「HBM上の状態の寿命」が結合していることに置く。状態を別管理すれば、実行構成だけを交換し、重み・KVを再利用できる。

## 手法

### HBM管理モジュールとゼロコピー接続

HMMは重み、KVキャッシュ、共有テンソルを推論実行プロセスの外で所有する。`IpcSafeAllocator` が共有可能なHBM領域へテンソルを確保し、推論側はIPCハンドルで同じ物理メモリを仮想アドレス空間へ写像する。新しい推論インスタンスを立ち上げても、既存アクセラレータ上の重みを複製する必要がない。

入力は現在のHBM配置と新しい並列構成、出力は新プロセスが参照できるメモリマッピングである。ゼロコピーにより旧プロセスが要求を処理している間に新プロセスを準備でき、切替時にKVを再計算する必要も減る。

### 追加アクセラレータへのP2P転送

スケールアップで新規NPUを追加すると、そのNPUにはまだ重みがない。ElasticMoEはディスクやホストDRAMを経由した再ロードではなく、高速アクセラレータ間相互接続を使う `p2p-copy` で、既存NPUから必要重みを直接複製する。

転送はサービス停止区間の前に進められ、既存構成はその間も要求を処理する。したがって転送時間の多くを推論と重ねられる。転送完了後、新構成へトラフィックを切り替えるため、停止時間ではなくバックグラウンド準備時間として扱える。

### 仮想ページによる専門家再配置

専門家テンソルを物理的な巨大連続バッファとして扱うと、EP度変更のたびに新バッファ確保とコピーが必要になる。ElasticMoEの `vpage-remap` は、モデルが見る連続仮想アドレスとHBM上の非連続物理ページを分離する。専門家の所属NPUや並びが変わっても、必要な物理ページを新しい仮想範囲へ再写像して論理テンソルを作る。

これにより、既存NPU内での専門家再配置は重み本体を丸ごとコピーせずページ表変更中心で済み、EP再構成時の一時HBM増加を抑える。論文が固定するテンソル並列（TP）度を変えないのは、attention層とKVのレイアウトを既存NPU上で維持し、この再利用を成立させるためである。

### スケール変更の流れ

制御側が負荷増加を検出すると、追加NPUを確保し、HMMが必要重みをP2P転送する。同時に既存NPUの重み・KVはゼロコピーで共有可能なまま維持する。仮想ページ再写像で新しいEP配置を構成し、新推論インスタンスが同じ状態へ接続する。準備完了後にトラフィックを新構成へ移す。縮小時も残すNPU側の状態を再利用し、不要インスタンスを切り離す。

## 評価条件

| 項目 | 内容 |
|---|---|
| アクセラレータ | Ascend NPU |
| モデル | 3種の代表的MoE LLM |
| 伸縮軸 | DP・EPを中心に変更、TP度は固定 |
| 基準 | 複製追加や再構成を伴う既存スケーリング方式 |
| 指標 | スケールアップ遅延、スケール中処理量、SLO達成、再構成時メモリ |
| 実装要素 | HMM、zero-copy、p2p-copy、vpage-remap、IpcSafeAllocator |

## 主要結果

| 指標 | 結果 | 意味 |
|---|---:|---|
| スケールアップ遅延 | 基準方式比で最大9倍短縮 | 全複製の再ロード・再起動を避ける効果 |
| スケール中処理量 | 最大2倍 | 再構成と推論を並行させ、停止区間を縮める効果 |
| SLO達成 | 基準方式より改善 | バースト負荷へ資源追加が間に合いやすい |
| 再構成時メモリ | 仮想ページ再写像で一時バッファを削減 | EP変更時の旧・新専門家バッファ二重保持を回避 |

一次資料の代表値は「定常推論が9倍速い」ことを意味しない。9倍はスケールアップ操作の遅延、2倍はスケール処理中の処理量に関する値であり、ElasticMoEの狙いは動的負荷への追従性である。

## 既存研究との差

水平スケーリングは実装が単純だが複製単位が大きく、MoEでは数十〜数百アクセラレータを一度に追加しかねない。既存の垂直スケーリングは細粒度でも、推論プロセスが重みとKVを所有するため再起動や再ロードを伴う。ElasticMoEはHBM状態を実行から分離し、同じ重み・KVへ新旧プロセスを接続できるようにすることで、細粒度と無停止を同時に狙う。

また、専門家配置変更をテンソルコピー問題ではなく仮想メモリ写像問題へ変える点が特徴である。MoEルータの選択規則や専門家計算を近似するのではなく、モデル意味論を変えずシステム状態の所有方法を変える。

## 限界

評価はAscend NPUを中心としており、CUDA/HIP環境で同じIPC・仮想ページ機構を使った場合の絶対性能は主要評価から直接は分からない。P2P帯域が低いクラスタでは、新規アクセラレータへ重みを複製する時間が再び律速になり得る。

TP度を固定してDP/EPを伸縮する設計なので、あらゆる並列軸を任意に変更できるわけではない。attention層やKVレイアウトまで変えるTP再構成は、ゼロコピー再利用を難しくする。

さらに、ElasticMoEは定常時のトークン処理そのものを高速化する方式ではない。負荷が安定しスケールイベントが少ない環境では、9倍というスケール操作改善の寄与はサービス全体の平均処理量へは小さくなる。
