# GRACE-MoE: Grouping and Replication with Locality-Aware Routing for Efficient Distributed MoE Inference

> 共活性に基づく階層専門家配置、動的複製、局所性・負荷認識ルーティング、階層疎通信を組み合わせ、分散MoE推論を最大4.66倍高速化するGRACE-MoE。

## 概要

専門家混合（Mixture of Experts; MoE）モデルは、各トークンが少数の専門家だけを実行するため演算量を抑えられる一方、専門家並列ではルータが選んだ専門家のGPUへトークンを送る全対全通信（All-to-All; A2A）が発生する。複数ノードへ広げるとノード間ネットワークがGPU間接続より遅く、さらに人気専門家へトークンが集中すると、一部GPUだけが計算を終えられず他GPUが待つ。

GRACE-MoEは通信局所性と負荷均衡を別々に最適化せず、**共に選ばれやすい専門家を近くへ置く階層グループ化（hierarchical grouping）、人気専門家の動的複製（dynamic replication）、局所性と予測負荷を使うトポロジ認識ルーティング（topology-aware routing）、ノード間転送を集約する階層疎通信（hierarchical sparse communication; HSC）**を一つの実行系へ統合する。

重要なのは、同じ専門家集合を実行したまま配置先と複製先だけを変えるため、モデルのTop-kルーティング結果を近似して通信を削る方式ではない点である。ルータが選んだ論理専門家は維持し、その専門家のどの物理複製を使うかをシステム側で決める。したがって主な交換条件は精度ではなく、複製に使うGPUメモリ、局所通信量、配置プロファイルの安定性である。

OLMoE、DeepSeek-V2-Lite-Chat、Qwen3-30B-A3Bを複数ノードGPUで評価し、最新版ではMoE層時間を最大80.11%、エンドツーエンド遅延を最大78.55%削減する。最大高速化は4.66倍で、古い版の3.79倍という値より評価範囲が更新されている。

## 問題設定

### 通信削減だけを追うと負荷が偏る

共に活性化されやすい専門家を同一GPUや同一ノードへ集めれば、トークンがネットワークを跨ぐ回数を減らせる。しかし人気専門家同士まで同じGPUへ集めると、そのGPUに計算が集中し、他GPUが通信を終えて待つ時間が増える。

逆に負荷だけを均等にするため専門家を均一配置すると、同時選択される専門家が離れ、同じトークンが複数ノードへ送られる。GRACE-MoEはこの「通信局所性」と「GPU負荷均衡」の対立を、静的配置・複製・実行時ルーティングの三段階で分担させる。

### MoEのノード間A2Aは同じトークンを何度も運ぶ

Top-k MoEでは一つのトークンが複数専門家へ送られる。選ばれた専門家が同じ遠隔ノードに複数存在していても、通常のA2Aでは専門家単位で送受信を組むため、ノード間リンク上で同じトークン内容が重複しやすい。

ノード内NVLink等よりノード間リンクが遅い環境では、この重複が支配的になる。したがってGRACE-MoEは「専門家を近づける」だけでなく、通信そのものをノード階層へ合わせて再構成する。

## 手法

### 1. 共活性行列から専門家の親和度を作る

オフラインの代表ワークロードで各MoE層の専門家選択を記録し、二つの専門家が同じトークンでどの程度同時に活性化されるかを親和度（affinity）として行列化する。共活性が高い専門家を近くへ置けば、一つのトークンが複数ノードを跨ぐ確率を下げられる。

同時に各専門家の平均負荷も記録する。配置問題を親和度だけで解くと人気専門家が一つのグループへ固まるため、以降のグループ寸法制約と複製判断にこの負荷統計を使う。

### 2. 階層グループ化でノード間とノード内を別々に最適化する

GRACE-MoEはスペクトルクラスタリングを用いて高親和度専門家をまとめるが、全グループを完全同数にはしない。完全均一なら負荷は揃いやすいものの親和度の高い集合を分断し、完全な非均一なら通信は減るが一部GPUへ専門家が偏る。

そこで平均グループサイズ (E) に対し、許容非均一率 (r) から ([E-delta, E+delta])、(delta=E r) の範囲へグループ寸法を制限する。論文は親和度利用率とグループ寸法偏差の曲線から折れ曲がり点を選び、通信利得が飽和する前の非均一度を採る。

さらに階層化し、**ノード間ではより自由な非均一グループ化、ノード内GPU間では制御された非均一グループ化**を使う。遅いノード間通信を先に減らしつつ、GPU単位の極端な負荷偏りを抑える狙いである。

### 3. 高負荷グループの人気専門家を動的に複製する

グループ化後も、入力分布によって一部専門家へトークンが集中する。GRACE-MoEは負荷の偏りを監視し、重いグループに属する人気専門家を空きのあるGPUへ複製する。

複製は論理モデルを変えず、同じ重みの追加コピーを作る。これにより次のトークンは元専門家と複製のどちらでも同じ計算結果を得られるため、ルーティング精度を落とさず負荷分散の自由度を増やす。代償は複製分のGPUメモリである。

### 4. 局所性階層と予測負荷で物理複製を選ぶ

実行時ルータは論理専門家を変更せず、利用可能な複製の中から配送先を決める。優先順位は概ね**同一GPU → 同一ノード → 遠隔ノード**で、まず通信コストの低い複製を候補にする。

ただし最寄りGPUが混雑していれば、全トークンをローカルへ寄せると計算待ちが増える。そこで同一局所性階層内では重み付きラウンドロビン（weighted round-robin）と予測負荷を使い、各複製へトークンを振り分ける。遠隔転送を完全禁止せず、「少し遠いが空いている複製」へ逃がせる点が通信最小化だけのルータと異なる。

### 5. 階層疎通信で同一宛先ノードへの転送をまとめる

階層疎通信HSCはA2Aを、まずノード間、その後ノード内の二段階へ分ける。あるトークンが遠隔ノード内の複数専門家を使う場合、ノード間ではトークンを一度だけ送り、到着後にノード内で必要GPUへ複製・配送する。

クロスノード通信では論理的に疎な送受信を構成し、必要な宛先だけへデータを送る。ノード間転送と次段のノード内ルーティング判断をパイプライン化し、通信中に後続の配送準備を進める。

この結果、配置による「遠隔宛先数の削減」と、HSCによる「同じ遠隔ノードへの重複転送削減」が別々に効く。

## 評価

### 代表的な評価条件

| 項目 | 条件 |
| --- | --- |
| モデル1 | OLMoE: Top-8 / 64 experts / 16 MoE layers / 6.92B |
| モデル2 | DeepSeek-V2-Lite-Chat: Top-6 / 64 experts / 26 MoE layers / 15.7B |
| モデル3 | Qwen3-30B-A3B: Top-8 / 128 experts / 48 MoE layers / 30.5B |
| データ | WikiText2-v1、MATH、The PileのGitHub subset等 |
| 構成例 | 2 nodes × 2 GPUs、2 nodes × 4 GPUs等 |
| workload例 | batch 256 / prefill 128 / decode 16、batch 512 / prefill 64 / decode 32 |
| 比較 | Occult等の分散MoE配置・通信方式 |
| 主指標 | MoE層時間、E2E遅延、A2A時間、cross-node traffic、GPU idle、load deviation |

### 構成要素の効果

| 構成 | A2A時間 | ノード間通信量 | GPU idle | GPU負荷偏差 | 解釈 |
| --- | ---: | ---: | ---: | ---: | --- |
| HSCのみ（Occult比） | -35.19% | -35.64% | — | — | 通信階層化だけでも重複転送を削減 |
| 階層グループ化 + HSC | -48.33% | -50.67% | 悪化 | +90.03% | 通信を強く減らすと負荷不均衡が顕在化 |
| 全機構（複製+ルータ含む） | -50.57% | -52.11% | -25.66% | +39.35% | 複製と負荷認識ルータが通信利得を保ちながら偏りを緩和 |

この構成要素除去は、GRACE-MoEが単なる「通信最小化配置」ではない理由を示す。階層グループ化だけでは通信は減るがGPU負荷偏差が約90%増える条件があり、動的複製とトポロジ認識ルータを追加して初めて待ち時間を下げられる。

### グループ非均一度の交換条件

OLMoE、2ノード×2GPUの例では、均一グループがA2A約3494 ms、E2E約6328 msに対し、制御非均一 (r=0.15) はA2A約2846 ms、E2E約5698 msへ改善する。完全非均一はA2Aを約2826 msまで少し下げるもののGPU idleが増え、E2Eは約5748 msと制御非均一より悪い。

つまり「最小A2A」が「最小E2E」と一致しない。これが論文でグループサイズへ上限・下限を付ける直接の評価根拠である。

### 代表的な最終結果

| モデル | MoE層時間削減 最大 | E2E遅延削減 最大 | 最大高速化 |
| --- | ---: | ---: | ---: |
| OLMoE | 80.11% | 78.55% | 4.66倍 |
| DeepSeek-V2-Lite-Chat | 75.45% | 73.17% | 3.73倍 |
| Qwen3-30B-A3B | 78.59% | 77.64% | 4.47倍 |

古い版で見られる最大3.79倍ではなく、arXiv最新版ではOLMoEで4.66倍まで更新されている。これは全条件平均ではなく最良条件の最大値であり、モデルごとの結果を分けて読む必要がある。

### 分布ずれへの感度

配置プロファイルを作ったデータセットと実行データセットを変える交差評価では、同一分布で作った最適配置に対するE2E悪化は最大4.52%以内に収まり、それでもOccultより平均12.06%以上低い遅延を維持したと報告する。

したがってオフライン共活性プロファイルは完全に入力非依存ではないものの、少なくとも評価したデータセット間では即座に無効化されない。一方、より大きな分布変化や長期間のservingで同じ安定性が続くかは別途検証が必要である。

## 既存研究との差

専門家配置だけを最適化する方式は、実行時の人気変化へ追随しにくい。専門家複製だけを行う方式は負荷分散には効くが、共活性した専門家が遠隔ノードへ散っていれば通信量は残る。GRACE-MoEは配置・複製・物理ルーティングを分離し、オフラインの安定した共活性とオンラインの負荷変化をそれぞれ別機構で扱う。

また通常A2Aを前提に配置だけ変えるのではなく、HSCで通信プリミティブ自体をノード階層へ合わせる。これにより「専門家を同じノードへ置いたのに同じトークンを複数回ノード間送信する」という残存コストも削る。

## 限界・実装状況

専門家複製はGPUメモリを消費するため、モデル重みやKVキャッシュで余裕がない構成では複製数を増やせない。共活性プロファイルもワークロード依存で、評価外の大きな分布ずれではグループ配置を再計算する必要がある可能性がある。

HSCの利得はノード内・ノード間帯域差やクラスタトポロジに依存する。単一ノードや非常に高速なノード間接続では、二段階通信の管理費用に対する利得が小さくなる。また論文最新版時点ではコード公開は採択後予定であり、上流推論基盤への統合状態は未確定である。

品質については論理Top-k専門家を変更せず物理複製先だけを変えるため、近似ルーティングによる精度交換条件を主張する方式ではない。ただし実運用では負荷予測・通信実装の同期正当性を保つ必要があり、システム障害時のフォールバックや複製更新コストは代表評価から別途考慮が必要である。
