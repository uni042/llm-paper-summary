# Communication Compression for Tensor Parallel LLM Inference

> テンソル並列の部分活性値を集合通信前に細粒度量子化し、3.5〜4.5倍小さくして、低帯域なGPU間接続で先頭トークンまでの時間を最大2倍短縮する。

## 概要

テンソル並列のプリフィルでは全入力トークン分の部分結果を頻繁に集約し、装置間帯域が低い構成では通信が遅延を支配する。

行方向テンソル並列の線形層直後で活性値をブロック量子化し、圧縮状態で通信して削減演算前に復元する。品質低下3%未満の候補からモデル別に圧縮設定を選ぶ。

活性値サイズを3.5〜4.5倍削減し、NVIDIA L4とA100を含む構成で先頭トークンまでの時間を1.2〜2倍改善する。 この代表値は論文が指定したモデル、装置、入力条件での比較として読む必要があり、別環境へ倍率をそのまま外挿しない。重要なのは、どの資源が律速だったため改善したかである。

## 問題設定

テンソル並列のプリフィルでは全入力トークン分の部分結果を頻繁に集約し、装置間帯域が低い構成では通信が遅延を支配する。

大規模言語モデルの実行時間は演算量だけでなく、プリフィルとデコードの性質、重み・KVキャッシュの読出し、装置間通信、逐次依存によって決まる。したがって理論上の削減率だけではなく、対象ボトルネックを実行経路へ落とし込んで評価する必要がある。

処理は、まず要求またはモデル状態から必要な資源量を把握し、次に削減・配置・圧縮・選択の方針を決め、その方針でモデル計算を進める。得られた負荷や品質情報は次の判断へ利用される。

## 手法

### 1. ボトルネックの観測

テンソル並列のプリフィルでは全入力トークン分の部分結果を頻繁に集約し、装置間帯域が低い構成では通信が遅延を支配する。

方式は要求ごとに変わる系列長、注意分布、候補品質、通信量などと、装置側の容量・帯域・カーネル性能を分けて扱う。固定設定で過剰確保するのではなく、現在条件に必要な資源へ計算を集中する。

### 2. 主要な資源削減

行方向テンソル並列の線形層直後で活性値をブロック量子化し、圧縮状態で通信して削減演算前に復元する。品質低下3%未満の候補からモデル別に圧縮設定を選ぶ。

アルゴリズム上の判断は、ブロック、タイル、トークン群、通信窓、メモリ階層などハードウェアがまとめて扱える粒度へ変換する。不規則な細粒度処理が増えてGPU利用率を落とさないことが重要である。

### 3. 品質と追加費用

削減や近似が外れた場合には、保守的な予算、検証、再計算、通常経路への復帰などで品質を守る。選択器、量子化と復元、補助統計、メタデータにも費用があるため、これらを含めて利得が残る条件を確認する。

一つの要求では、入力状態を観測し、計算・保存・配置を決定し、その構成で次の生成段階を処理する。処理後の状態を次段階へ引き継ぐことで、局所的な削減をエンドツーエンドの遅延・スループット・容量改善へ変える。

### 4. 実装上の接続

既存ランタイムへ統合するときは、連続バッチ処理、接頭辞キャッシュ、テンソル並列、専門家並列などと競合しないかを見る。同じ帯域律速を減らす二方式では単独利得がそのまま加算されない。

誤予測時の回復経路も実装の一部である。平均的な高速化だけでなく、最悪条件で品質を保てるか、通常計算へ戻せるかを運用指標として持つ必要がある。

## 評価

活性値サイズを3.5〜4.5倍削減し、NVIDIA L4とA100を含む構成で先頭トークンまでの時間を1.2〜2倍改善する。

カーネル単体とエンドツーエンド、理論削減と実測速度、容量削減と帯域削減を区別する。比較対象、GPU、バッチ、文脈長が変われば律速も変わるため、代表値は同一条件内の比較として解釈する。

品質についても、元モデルと同じ出力を保証する方式と近似方式を区別する。近似方式では強い削減設定や分布変化での悪化条件まで確認し、品質を緩めた結果を同品質高速化と混同しない。

## 既存研究との差

既存の量子化、KV圧縮、疎注意、投機的復号、モデルルーティング、通信最適化は削減対象が異なる。この論文の差は、対象資源の性質を明示的に扱い、その情報を実行時の選択または実装粒度へ結び付ける点にある。

## 限界・実装状況

高速接続では量子化・復元費用が利得を相殺し、モデル別設定が必要。

研究実装の代表値を本番環境へ直接外挿できない。GPU・NPU世代、相互接続、モデル、要求分布が変われば律速も変わるため、導入時は同じ品質条件で対象環境を再測定する。

## 一般的な実装上の含意

推論高速化では削減率そのものより、現在の装置で何が待ち時間を作っているかを先に特定する。メモリ帯域律速なら転送量、通信律速なら通信量と起動費用、逐次律速なら一回の前向き計算で進める生成量を見る。
