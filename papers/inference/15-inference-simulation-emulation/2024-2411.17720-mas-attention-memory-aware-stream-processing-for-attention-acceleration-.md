# MAS-Attention：端末向け注意演算のメモリ認識型ストリーム処理

## 概要

MAS-Attentionは、演算資源とオンチップ記憶容量が限られる端末向けニューラル演算器において、正確な注意機構を高速化する計算配置方式である。行列積を処理する積和演算部（MAC）と、ソフトマックスを処理するベクトル演算部（VEC）が別々に存在しても、従来の行単位融合方式FLATでは、同じ注意行の `QK^T → softmax → PV` を順に処理するため、片方の演算部が待機しやすい。本方式は異なる行の処理を重ね、二つの演算部に独立したタイル作業列を与える。

提案は三つの仕組みからなる。第一に、行列積とソフトマックスを別ストリームとして実行する半同期の段階的並列化。第二に、行列積には細かい部分行列、ソフトマックスには行単位を使う多段タイル分割と探索。第三に、オンチップ領域が不足するとき、ソフトマックス結果を優先し、再読出し可能なK/Vを一時的に上書きするバッファ管理である。注意の近似・枝刈り・量子化を提案するものではなく、数値演算の対象を変えず実行順と記憶配置を変える。

著者らは、改変TileFlow・Timeloop・Accelergyによる端末向け演算器のシミュレーションで、FLATに対する注意演算サイクルの最大2.75倍の高速化、最大54.03%の推定消費エネルギー削減を報告した。実機のHuawei MatePad Pro 13.2に搭載されたDaVinci NPUではFLAT比1.30～1.76倍、幾何平均1.42倍の注意演算高速化を得ている。最大値と平均値、シミュレーションと実機を混同してはならない（原著§5.2～5.3）。

## 問題設定と対象範囲

通常の注意計算は、入力の問い合わせ行列Q、鍵行列K、値行列Vから、`C=QK^T`、`P=softmax(C)`、`O=PV` を求める。原著はQ/K/Vの形状を `[B,H,N,E]` とし、Bはバッチ、Hはヘッド、Nは系列長、Eは埋め込み次元を表す。CとPをそのまま保持すると系列長Nに対して二次の大きさになる。端末向け演算器ではDRAMとの往復が重く、数MB規模のオンチップ記憶を使って途中結果を保持する必要がある。

FLATはQの行を小分けにし、Cの計算、行ごとのソフトマックス、Oの計算を一つのオンチップ作業として融合する。CとP全体をDRAMに書き出さないため、演算子を分離して実行する方式より外部転送を減らせる。しかし、融合された一行の内部では行列積とソフトマックスの依存をそのまま逐次実行し、行列積専用の積和演算部と要素演算専用のベクトル部を同時には使い切れない。

大型GPUで有効な多数の演算コア・ワープ群を前提とする手法を、そのまま演算部の数が少ない端末向け演算器へ移すことも難しい。MAS-Attentionの対象は、少なくとも独立したMAC部とVEC部を備え、階層的なオンチップメモリを持つ空間型の推論演算器である。データセンター向けLLM全体のサービング・スケジューラや、モデル重みのオフロードを直接改善する論文ではない。

## 手法：半同期ストリームと多段タイル分割

### 1. 依存関係を保つ二つのストリーム

Qをバッチ、ヘッド、系列長方向に分割し、i番目の行群 `Q_i` を作る。対応する注意得点 `C_i=Q_iK^T`、確率 `P_i=softmax(C_i)`、出力 `O_i=P_iV` が一連の単位となる。同じiではCがPに先行し、PがOに先行する必要がある。一方、異なるiのC、P、Oの間には、同一行内ほど厳しい逐次依存がない。この違いを利用する。

立ち上げ段階ではMAC部がまず `C_1` を生成する。続いてMAC部で `C_2` を計算する間、VEC部で `P_1` を計算する。定常段階のi≧3では、MAC部が先行行の `O_{i-2}=P_{i-2}V` を計算し、その間にVEC部が `P_{i-1}=softmax(C_{i-1})` を処理する。MAC部は `O_{i-2}` の終了後、VEC部の仕事が残っていても次の `C_i=Q_iK^T` に進める。最後は残存するPとOを依存順に排出する（原著Algorithm 1）。

この順序では、二つの行列積をMAC部の単一作業列へ配置し、ソフトマックスをVEC部の作業列へ配置する。行iの出力を作るのに必要な確率P_iが完成するまで待つという正確性の条件は守りつつ、他行の行列積で待機時間を埋める。したがって、改善対象は演算回数そのものより演算部の遊休時間である。立ち上げと終了には並列化できない部分が残り、タイル数が少ない場合には理想的な並列効果は得られない。

### 2. 行列積とソフトマックスで粒度を分ける

タイル形状の基本パラメータは、バッチ分割 `B_b`、ヘッド分割 `H_h`、Q側の系列分割 `N_Q`、K/V側の系列分割 `N_{K,V}` である。Qを分割した作業数は `ceil(B/B_b) × ceil(H/H_h) × ceil(N/N_Q)` となる。行列積のK/Vはさらに `N_{K,V}` に沿って分割し、必要な部分だけDRAMからオンチップへ読み込む。ソフトマックスではC_iを行単位に分割し、各行の全注意得点を正規化してP_iを作る。

`C_i` の生成は、Q_iとKの部分行列をMAC部へ順に与えて積を蓄積し、結果をオンチップへ保持する。VEC部は `C_i` の各行から `P_i` を作り、こちらもオンチップに残す。最後の `O_i` 生成では、P_iとVを同じK/V系列区間ごとに分け、`O_i += P_{i,j}V_{i,j}` を繰り返してから完成したO_iだけをDRAMへ書く（原著Algorithms 2～4）。この構造は、C/P全体のDRAM書出しを避けるFLATの利点を維持しながら、異なる行の演算を重ねるための作業単位を与える。

Qの分割を大きくすると呼出しや立ち上げの負担を減らせる一方、C_i/P_iのオンチップ保持量が増える。K/Vの分割を細かくすると収容しやすくなるが、再読出しや管理が増える。MAC部とVEC部の所要時間の差もあるため、単純に最小タイルを選ぶだけでは性能は最大化しない。論文の多段分割は、この容量・入出力・演算器稼働率の競合を同時に扱うためにある。

### 3. タイル形状と演算順序のオフライン探索

著者らは、シミュレーション環境でモンテカルロ木探索（MCTS）により各ループのタイル因子を割り当て、生成された解析木をTimeloop/Accelergyで評価する。続いて遺伝的アルゴリズム（GA）が解析木の演算順序を交叉・突然変異によって調整する。評価値を木探索の上側信頼限界へ戻すことで、よいタイル構成を重点探索する。DaVinci NPUの実機側では格子探索（grid search）を使用する（原著§4.2）。

探索は注意層の形状と対象演算器のL0/L1容量、MAC/VEC構成に依存する。これはオンラインで毎トークン全探索する方式ではなく、論文が述べるのは事前の自動調整である。実行時に利用するタイル因子は探索結果として固定されるため、負荷変化へ追従する汎用ランタイム予測器とは区別する。探索には追加の評価計算が必要で、論文§5.5では約1万回の探索反復以降に性能が収束する傾向を報告する。

### 4. オンチップ不足時の選択的上書き

半同期実行では、VEC部が `P_i` を書き込もうとした時点でMAC部が別行のVまたはKを保持している場合がある。オンチップ容量が不足したら、MAS-Attentionはソフトマックスの完了を優先し、MAC部が `P_{i-1}V` を処理しているときはVの一時領域を、`Q_{i+1}K^T` を処理しているときはKの一時領域を上書きしてMAC部の処理を中断する（原著§4.3）。

この優先順位の理由は、P_iの計算途中の値がオンチップにしかなく、これを失うとそのままDRAMから復元できないことにある。一方、KとVの入力はDRAMにあるので、上書きしたタイルを後から読み直し、必要な行列積をやり直せる。したがって、保存すべきものと再計算可能なものを区別して並列パイプラインを継続する。ただし追加のDRAM読出しと再計算が生じるため、常に転送量まで減る方式ではない。

重要な実装上の前提は、MAC部の計算を安全に中断し、上書き後に正しく再実行できることである。原著はこの操作をアルゴリズムとして記述するが、実機で中断可能性や中断費用を単独に切り出して検証した数値は示していない。したがって、特に長系列での上書き経路の実機移植性は、通常の行列積とソフトマックスの並列化の実機効果とは別に評価する必要がある。

## 実機のエンドツーエンド評価と探索費用

端末実機では、Stable Diffusion 1.5の縮小UNetに含まれる15個の注意演算部を対象とした。最大の注意部は2ヘッド、系列長4096、埋め込み次元64であり、この注意部の実行時間はLayer-Wise比29.4%短縮した。一方、縮小UNet全体の推論遅延の短縮は6%にとどまる（原著§5.2.2）。この差は、注意以外の計算が全体に残るため、注意カーネル単体の改善がモデル全体へ同倍率で反映されないことを示す。

探索実験では、モンテカルロ木探索と遺伝的アルゴリズムの探索曲線が約1万反復以降に収束する傾向を示す。論文§5.5に記載された「探索前から探索後」の数十倍のサイクル差は、タイル探索過程で得た粗い構成と良い構成の差であり、FLAT比の本番推論高速化倍率ではない。探索時間と再探索の費用は、特に頻繁に形状が変わる実装で検討が必要になる。

## 既存研究との差と適用判断

FLATとの違いは、単にQを行分割してオンチップで融合する点ではない。FLATが同じ行の行列積とソフトマックスを順に実行するのに対し、MAS-Attentionは別々の行の処理を重ねてMAC部とVEC部の同時稼働を狙う。Soft-Pipeとの違いは、先頭の行列積とソフトマックスだけでなく、最後の `PV` もオンチップの作業列に取り込み、PをDRAMへ書き出さない点にある。

FlashAttention系との共通点は、注意行列全体をDRAMへ展開しない正確な注意計算であること。一方、本研究の中核はGPUの多数のワープを前提とした最適化ではなく、独立したMAC部とVEC部を持つ少数コアの端末向け演算器における異種演算の同時稼働である。したがって、一般的なGPU推論エンジンへ移植すれば同じ1.42倍が得られるという主張は原著から導けない。

## 限界・負の結果・未検証事項

第一に、必要なオンチップ記憶がFLATより大きい。原著§5.6では、5 MBのオンチップ記憶と半精度の条件で、MAS-Attentionが扱える系列長を約100万トークン、FLATを約200万トークンとする。MAS-Attentionは並列実行中にP_iとP_{i-1}、またはP_iとC_{i+1}の少なくとも二行分を保持する必要があるため、最大系列長はむしろ短くなる。100万トークンで各行が約2 MB、二行で約4 MBとなり、5 MBの制約に収まるという論文の容量上の説明である。これは100万トークンのLLM全体の実機推論を実証したという意味ではない。

第二に、バッファ上書きはK/Vの再読出しとMACの再計算を伴う。実際に一部モデル形状でFLATよりDRAM読出し回数が約1.5倍に増えており、メモリ帯域がより厳しい演算器では速度利得が小さくなる可能性がある。長系列でのMAC処理中断の実装費用・安全な再実行の検証は十分に分離報告されていないため、製品実装の際は確認事項として残る。

第三に、独立したMAC部とVEC部が必要であり、両者が同じ実行資源を奪い合う演算器にはそのまま適用できない。第四に、仮想演算器のエネルギーはAccelergyによる推定であり、実機電力の測定結果と同一視できない。第五に、原著は注意層単位の性能を主に評価し、実機でのエンドツーエンド結果は縮小UNetに限定される。大規模LLMの長文脈サービング、同時要求処理、動的バッチ、GPU間通信についての実測結果はない。

結論として、MAS-Attentionは「正確な注意演算を、限られた異種演算部の間でどう重ねるか」という端末向け推論カーネルの論文として有用である。特に、並列化による演算時間の改善と、オンチップ記憶容量・DRAM再読出し・最大系列長の悪化という交換条件を併記して比較する必要がある。
