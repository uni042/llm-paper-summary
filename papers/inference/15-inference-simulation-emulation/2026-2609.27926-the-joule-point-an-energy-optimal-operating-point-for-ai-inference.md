# The Joule Point：GPUの最大出力と、1推論あたり最小電力量は一致しない

## 概要

LLMや画像生成のGPUサービングでは、カードのTDP付近まで電力を使うと1枚あたりのスループットが最大化されやすい。しかし、GPUにはアイドルに近い状態でも必要な固定電力があり、高負荷領域では電力が処理速度より急激に増える。このため、1回の推論を終えるためのエネルギー（J/inference）は、最大出力でも最低出力でもなく、その中間で最小になる可能性がある。

本論文は、このエネルギー最小の動作点を**Joule Point**と呼ぶ。GPUを「A100を何枚割り当てるか」というハードウェア単位だけで扱うのではなく、**(GPU種類、power cap)** の組を動作点として扱う。GPUごとの電力キャップを下げると単体の推論は遅くなるが、消費電力の減少率が速度低下率より大きければ、同じ総仕事量を少ないエネルギーで処理できる。

20種類の推論モデルと複数GPUの測定データELFを作り、A100とA10GではTDPの43～46%付近のキャップが効率的だと報告する。A100では約29%、A10Gでは約31%のエネルギー/推論削減と引換えに、レイテンシおよび同じ処理能力を維持するのに必要なGPU枚数が約1.2倍になる。これは「キャップを下げれば無条件で運用費が減る」という結論ではなく、電力制約、設備投資、遅延SLOのどれが律速かによって最適解が変わるという分析である。

## 手法：スループットと電力の非線形関係

各GPU・モデル・バッチ条件で、無制限時の最大処理レートをRmax、実際のレートをRとし、正規化したレートをθ=R/Rmaxとする。著者は測定した電力曲線を `P(θ)=P0+a θ^β` で近似する。P0はGPUの固定電力、aは負荷依存項、βは非線形性の指数である。20モデルの測定で中央値R²=0.99と高い当てはまりを示すが、これは同じモデル・GPU・バッチの動作曲線に対する値であり、すべてのバッチを一つの曲線へ混ぜても同じ精度で当てはまるわけではない。

1推論あたりのエネルギーは電力を処理レートで割った値なので、定数倍を除いて `e(θ)=P(θ)/θ=P0/θ+a θ^(β−1)` となる。θが小さいと固定電力を長い時間払い続けるためP0/θが大きい。θが大きいとβ>1の場合に動的電力項が増える。両者の釣合いでU字型の曲線ができる。

微分から、内部最適点は `θ*=[P0/(a(β−1))]^(1/β)`、その電力は `P*=P0 β/(β−1)` と書ける。理論上の電力最適点は固定電力P0と指数βに依存し、aは消える。ただしこれはモデル化した曲線の内部最小点であり、実機で設定できるpower capの下限・上限やクロック制御の制約によって到達できない場合がある。著者は実運用のキャップを解析式だけで決めず、測定した離散スイープから選ぶ。

## 手法：ELF測定データセット

| 項目 | 内容 |
|---|---|
| モデル | FP16の20モデル：事前KVを持つLLM decode step、Stable Diffusion UNet、ViT-B/16・ViT-B/32・Swin-T、CNN 15種類 |
| GPU | L4（TDP 72W）、A10G（300W）、A100-SXM4（400W）、T4（70W） |
| 主な定量解析 | A100、A10G、L4の3種類。T4は電力キャップの可変範囲が狭く除外 |
| 環境 | AWS EC2 g6（L4）、g5（A10G）、p4d（A100）、g4dn（T4） |
| 電力制御 | nvidia-smi -plで各カードのドライバ下限からTDPまで8段階 |
| 計測 | NVMLで20Hzのボード電力、1.5秒の整定後2秒の計測窓、同窓のバッチ反復数でthroughput |
| データ構成 | バッチ32の全GPUスイープ、飽和バッチでの追加スイープ、負荷別スイープ、キャップ応答トレース |
| フリート | 15GPU（L4/A10G/A100各5）の200-tickトレース再生。別にA100 18GPUの静的割当 |

ここでの「1 inference」は測定したモデルの**1バッチforward step**である。バッチサイズは各曲線内で固定されるが、LLMサーバの可変長リクエストや継続的バッチ処理の1リクエストと同一ではない。LLMについても事前にKVを持つdecode stepを使っており、長いprefillとdecodeが混在する本番のエンドツーエンド応答を直接測定したわけではない。

電力キャップを上げながら測る各点では、整定1.5秒の後に2秒窓を測る。著者自身が、最初の窓は電力が完全に安定していない可能性を限界として認めている。各点の誤差や曲線全体の傾向を考える必要があり、1つの測定セルを絶対的な最適値として扱うべきではない。

## 評価結果：Joule Pointの測定結果

| GPU | Joule Pointの傾向 | エネルギー/推論削減 | 同じ総スループットを維持するための代償 |
|---|---|---:|---|
| A100-SXM4 | TDP約43～46%付近 | 約29% | 推論レイテンシ約1.24倍、必要GPU枚数約1.24倍 |
| A10G | TDP約43～46%付近 | 約31% | レイテンシ約1.22倍、必要GPU枚数約1.22倍 |
| L4 | power capの設定下限が最適点より高い | クロック制御で中央値約8%削減 | power capだけでは最適点に届かない |
| T4 | 測定範囲が狭い | 主解析から除外 | 同じ普遍的な最適比率を主張できない |

A100とA10Gでは、同じGPU種類の20モデルに対して最適キャップの位置が比較的安定している。個別モデルの最適値へ毎回調整する代わりにGPU種類ごとに固定キャップを使った場合のエネルギー損失は、A100で平均0.9%、A10Gで0.4%と報告する。これは**測定した高負荷・固定バッチ条件**に限った結果で、推論途中でprefill/decodeが切り替わる本番ワークロードでも常に固定キャップが最善という保証ではない。

Figure 3の代表例ではA100 ViT-B/32の相対エネルギーが無制限時1.00から電力比44.5%で0.65へ下がる。A10G ResNet-50では約39.5%付近で0.62まで下がる。いずれも低電力へ下げ過ぎると、固定電力を長く払うため再びエネルギー/推論が増える。例えばA100代表例では24.5%まで下げると相対エネルギー1.24となり、**無制限よりも悪い**。これが「できるだけ低い電力キャップが最適」という単純な節電策の反例である。

## 評価結果：レイテンシ・GPU枚数・電力予算の交換条件

エネルギー/推論を減らしても、単一GPUの処理速度は落ちる。A100のJoule Pointで約29%節約する場合、1ジョブの実行時間は約1.24倍である。全体のスループットを維持するにはGPUを約1.24倍に増やす必要があり、これは数学的に同じ正規化レートの逆数1/θ*から出る。したがって「29%節電して同じGPU枚数・同じ遅延・同じスループットを全部維持できる」という主張ではない。

反対に、データセンターがGPU枚数ではなく総受電電力で制約されている場合は、同じメガワット内で低電力のGPUを多く動かした方が、合計の推論数が増える可能性がある。論文Figure 6は1MW制約のA100フリートで、Joule Point付近の運用が無制限運用より約50%多い推論/メガワットを供給できるという試算を示す。ただしこの値は**測定曲線に基づく容量シミュレーション**で、実際に5500枚のA100を導入して測った結果ではない。電力以外の冷却・ラック・ネットワーク・GPU購入費用を含めた実装検証も必要である。

また、顧客がGPU時間単位で課金される場合、GPUを遅くすると課金時間が伸びるため、顧客の支払額はかえって増える可能性がある。データセンター運営者の電力効率と、テナントの時間課金コストの最適点は一致しない。著者はこの料金設計を、Joule Point運用の主要な経済的障壁として指摘する。

## 評価結果：フリートシミュレーションとSLO

著者はL4/A10G/A100各5台、合計15GPUの仮想フリートを作り、モデルの重い・軽い比率が周期的に変わる200-tickのシード固定トレースを再生した。総電力予算はTDP合計の50～70%、各ジョブのSLOは最速時レイテンシの1.25倍を基本とする。ベースラインはGPU配置を選んだ後に無制限で走らせる方式、提案は配置したジョブごとに**SLOを満たす最小の電力キャップ**を選ぶ方式である。両者は同じジョブ順序・配置規則を使い、電力設定だけを変える。

この条件では、同じ仕事をこなす際のエネルギー/ジョブを18～45%削減した。さらにA100 18台の静的割当実験では、フリート全体へ同じキャップを掛ける方式と、GPUごとに個別のキャップを選ぶ方式を比較し、電力予算が厳しくなるほど後者のSLO goodputが有利になる。すべてのGPUを一律に絞ると、必要なジョブのレイテンシまで悪化させるが、ジョブごとのSLO余裕を使えば優先すべき仕事を守りやすい。

重要なのは、**18～45%という値は実GPUで測定した応答曲線を再生したシミュレーションの結果**であり、15GPUの実機をライブ制御して得た省エネ率ではないことだ。モデル・バッチ・到着分布・SLOの設定に依存する。キャップの変更が速いことを確認するため、A10Gでは電力が新しい水準の5%以内に整定するまで中央値191msを測定しているが、実サービングエンジンの要求単位の切替えを包括的に検証したわけではない。

## アブレーションと負の結果

- **低過ぎるキャップの逆効果**：A100の代表曲線ではTDP約24.5%で相対エネルギー1.24となり、無制限より24%悪い。固定電力の時間積分が支配的になるため。
- **GPUごとの違い**：A100/A10Gの大きな省エネ率をL4やT4へ外挿できない。L4はドライバのpower cap下限が最適点より高く、クロック制御が必要。T4はキャップ範囲が狭いため定量解析から除外。
- **バッチ条件の違い**：`P(θ)=P0+aθ^β`の高い当てはまりは各負荷状態の曲線ごとであり、異なるバッチサイズを混ぜると同じ単一曲線にはならない。固定キャップがほぼ最適という結論は飽和負荷で強い。
- **レイテンシの代償**：A100で約1.24倍、A10Gで約1.22倍の遅延がある。厳格なP99 SLOのジョブへ一律に適用すると違反が起こり得る。
- **測定窓の偏り**：電力キャップ変更直後の2秒窓で電力を少し低く見積もる可能性がある。著者は結果を測定プロトコルの範囲内で解釈する。

## 限界：既存研究との差

従来のGPU省電力制御は、モデルやジョブごとにオンラインでpower capを探索したり、GPU種類だけを選ぶ。Joule Pointは、電力と処理速度の測定曲線から最適な動作点を求め、飽和負荷では**カード種類ごとの固定キャップでほぼ最適**という観測を利用する。さらにGPU割当だけでなく、割当後の電力キャップまでスケジューラの選択肢に含める。

ただし論文の対象は4種類のNVIDIA GPU（主要解析3種類）と20モデルのFP16推論で、vLLMやTensorRT-LLMの実本番トレース、混合prefill/decode、連続バッチ、GPU間通信、KVオフロード、CPU/DRAM/ネットワークの電力、冷却・施設PUEは十分に評価されていない。ボード電力だけを測ったJ/inferenceを施設全体のJ/requestへ直接置き換えてはならない。さらに固定キャップを設定するにはnvidia-smiの管理権限が必要で、共有GPU環境では変更できない場合がある。

GPUの購入費用、電力料金、時間課金、レイテンシSLO、設備の受電制約のどれが重要かによって最適な運用は変わる。省エネ率を単独で最大化するより、SLOを守る範囲でのJ/request、要求あたりの総費用、同時実行可能な要求数、設備投資を合わせて測る必要がある。とくにGPU枚数が固定されていて需要が高い場合、電力キャップで単体スループットが下がることが大きな不利益になる。

本研究の実用的な示唆は、GPUをフルパワーで走らせることを既定の正解とせず、**GPU種類ごとに一度電力キャップを掃引し、J/inferenceとSLOの両方を測る**という運用手順にある。GPUの最適点はモデルやバッチが変われば再評価が必要で、最新GPUへ43～46%という比率を無検証で適用するべきではない。
