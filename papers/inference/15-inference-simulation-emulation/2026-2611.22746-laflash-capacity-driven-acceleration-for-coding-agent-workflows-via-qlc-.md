# LaFlash: Capacity-Driven Acceleration for Coding Agent Workflows via QLC-HBF

> コーディングエージェントの休止状態を追い出さず保持する方が再計算より速いことに着目し、大容量のQLC高帯域フラッシュへ状態を置くLaFlashで、SLC方式とバッチ拡大の組み合わせに対し平均7.04倍のスループットと10.96倍のエネルギー効率を得る容量駆動の加速アーキテクチャ。

## 概要

コーディングエージェントは、コードの調査、修正、検証をツール呼び出しと交互に繰り返しながら、文脈とKVキャッシュという持続状態を使い回す。ループ型の反復改善や、グラフ型のタスク分解では、実行中の状態に加えて、ツール待ちや分岐で休止している状態が積み上がる。論文はこれを状態増幅と呼び、実測ではループ型で4.2倍、グラフ型で3.0倍の増幅が観測された。保持容量が足りず休止状態が追い出されると、再開時に長文脈のプリフィルをやり直す再計算が必要になる。コーディングエージェントは長文脈で1ターンあたりのデコードが短いため、この再計算が支配的で、文脈長100Kでは外部メモリから読み戻す費用より3桁大きい。LaFlashが提案する容量駆動加速（Capacity-Driven Acceleration; CDA）は、追加のメモリ容量を実行中の同時実行数の拡大ではなく、休止状態の保持へ優先的に割り、再計算をメモリアクセスへ置き換える配分方針である。その受け皿として、1セルに4ビットを記録するQLCフラッシュで高帯域フラッシュ（High-Bandwidth Flash; HBF）を構成し、SLCの4倍の容量を得る。

**代表結果:** トレース駆動シミュレーションによるエンドツーエンド評価で、LaFlashはSLC-HBFとバッチ拡大の組み合わせに対して平均7.04倍のスループットと10.96倍のエネルギー効率を達成し、QLC-HBFにCDAだけを組み合わせた構成に対しても2.36倍のスループットを得た。結論部では設定横断の最大値としてスループット最大10.26倍、エネルギー効率最大17.21倍にも触れている。なお本論文は実機ではなく、HBFSimを拡張したシミュレータによるアーキテクチャ評価である。

## 問題設定

通常の提供エンジンは、追加容量があればバッチを広げて重み読み出しを償却する方向へ使う。しかしコーディングエージェントでは文脈が長く、KVキャッシュの転送はリクエスト間で共有できないため、バッチ拡大の限界効用は早く頭打ちになる。一方で状態増幅により休止状態が増え続け、容量不足は追い出しと再計算を頻発させる。論文の分析では、同時実行に十分な容量を割いた後は、休止状態の保持へ回す方が再計算の消去を通じて大きな加速が得られる。受け皿の候補であるHBFは、NANDフラッシュの密度とHBM級の合算帯域を狙う階層だが、既存設計は読み遅延を抑えるため1ビットセルのSLCに留まり、密度の利点を捨てている。QLCは同じセル資源で4倍の容量を持つ反面、読み遅延が長く、同じ帯域を出すにははるかに多くのプレーン（読み出しの並列単位）を同時に動かす必要があり、書き換え耐久もSLCの約10万回に対して約1000回まで落ちる。データを多くのプレーンへ広げれば読み並列は上がるがブロック利用率が下がって書き増幅が増え、リクエスト専有のブロック割当を守れば書き効率は良いが、休止と再開や文脈長のばらつきでプレーンが遊ぶ。この読み並列と書き効率の両立が、QLC化の中心課題である。

## 手法のあらまし

LaFlashはHBMとQLC-HBFを並列に置く構成を取り、新しく生成されたKVキャッシュはまずHBMへバッファし、再利用の見込みがあるものだけを選んでHBFへ書き戻す。容量の配分はCDAに従い、状態増幅を織り込んで同時実行数を決め、残りを休止状態の保持へ回す。物理配置では、セッションをグループへまとめ、各グループを複数のメガプレーンへ対応付けるセッショングルーピングで、グループ間の実行中リクエスト数と文脈長の合計を均しつつ、リクエスト専有のブロック割当を守る。残る不均衡は、QLCのページ種別ごとの読み遅延の差を使う高速ページ割当で吸収する。均等に配れるデータは遅いページへ置いて並列度で遅延を隠し、配り切れない残りを速いページへ置いて必要な並列度を下げる。書き戻しの制御はホスト側のKVコントローラが行い、再利用適格性と書き込みの緊急度から書き戻しタイミングを決めて、プレーン間で協調したバッチ書きを行う。

## 手法

### 1. 容量駆動加速 — 容量の使い道を保持へ変える配分方針

この機構が観測するのは、ワークフローの状態増幅、つまり実行に必要な分を超えて保持される状態の倍率と、状態の再利用間隔である。保持する状態は休止中のセッションの文脈とKVキャッシュであり、処理は、同時実行数の決定に状態増幅を明示的に織り込み、容量を実行中の分と休止保持の分へ配ることである。これにより減るボトルネックは再開時の再計算で、論文の解析では文脈48Kから96K級で再計算の遅延は外部メモリ読み戻しの1416倍から5772倍に達する。論理効果だけを切り出した評価では、SLC-HBFでもCDAを入れるだけでバッチ拡大比で最大8.62倍の理想スループットが得られ、容量配分の考え方自体が利得の源泉であることが示された。失敗条件として、再利用間隔が10分を超える状態は保持せず追い出す方針であり、再利用が薄いワークロードでは保持の利得が痩せる。推論の長いモデルや通常の多ターン対話では、状態増幅が小さくデコード比重が大きいため利得が1.26倍から1.58倍程度まで縮むことが適用範囲の評価で示されている。

### 2. セッショングルーピング — 読み並列とブロック利用率を両立させる配置

この機構が観測するのは、各グループの実行中リクエスト数と、実行中文脈長の合計である。保持する状態はグループごとのセッション対応とブロック所有であり、処理は、新規セッションを総セッション数の最も少ないグループへ割り当て、グループ内ではリクエスト専有のブロック割当を保ったままプレーン優先の配置を行い、グループ単位の先入れ先出しで入れ替えることである。同時期に始まったセッションは文脈長が揃いやすい性質を使い、明示的な長さ予測なしに均しを実現する点が工夫である。これにより減るボトルネックは、休止と再開のたびに生じるプレーンの遊びと文脈長不均衡による帯域利用率の低下である。追加費用はホスト側の管理メタデータで、GPUあたり11.2キロバイトと小さい。マッピング方式の比較では、LaFlashは理想CDA比で平均68パーセントのスループットに達し、帯域利用率63パーセントとブロック利用率74パーセントを両立させたのに対し、既存方式は帯域利用率かブロック利用率のどちらかが大きく落ちた。失敗条件として、到着直後の偏りなど初期段階の不均衡はグルーピングだけでは消えず、次の機構で補う前提になっている。

### 3. 高速ページ割当 — QLCの読み遅延のばらつきを資源に変える仕組み

この機構が観測するのは、グループごとの遅いページの占有量と、各書き込みの配分の偏りである。QLCでは論理ページごとに必要な読み取り回数が異なり、読み遅延はページ種別で4、6、14、14マイクロ秒とばらつく。処理は、均等に配れる書き込みを遅いページへ回して占有をグループ間で均し、均等に配れない残余を速いページへ置くことである。速いページは遅延が短いため、同じ帯域に必要なプレーン並列が少なくて済み、論文の例では遅いページの3分の1の並列で足りる。これにより減るボトルネックは、グルーピング後も残るグループ間不均衡による帯域利用率の低下である。除去実験では、素朴なQLC構成で0.33倍まで落ちたスループットが、CDAで2.84倍、セッショングルーピングで5.31倍、高速ページ割当を加えて6.18倍へ段階的に回復し、エネルギー効率もSLC比9.98倍まで伸びた。トレードオフとして、速いページと遅いページは同じ物理ブロックを共有するため、ブロック利用率を守るために10Kトークンごとの専有ブロック内でのみ割当を動かす制約が付く。

### 4. HBMバッファリングと書き戻し管理 — QLCの耐久を守る仕組み

この機構が観測するのは、新規KVキャッシュの再利用見込みと、読み書き比である。処理は、新規データをまずHBMへ置き、接頭辞の統合やセッションの成熟度から再利用適格性を判定し、書き戻しは緊急度とバッチ機会を見てまとめて行うことである。セッション終了が近い状態はHBMに残したまま捨てられ、QLCへの無駄な書き込みが消える。これにより減るボトルネックは書き増幅と、それによるQLCの寿命消費である。寿命評価では、再計算を伴う構成で0.29年まで落ちた書き換え寿命が、CDAで8年、HBMバッファリングを加えて10.9年まで回復した。読み書き比が約7000未満の短命なデータを書き戻さないことが効いている。失敗条件として、この寿命は保持要件を緩める耐久強化策を併用した前提の値であり、それなしの実デバイスでの成立性は今後の課題とされる。

| 構成要素 | 入力・観測 | 具体的な動作 | 改善対象 | 主なトレードオフ |
|---|---|---|---|---|
| 容量駆動加速 | 状態増幅と再利用間隔 | 容量を同時実行と休止保持へ配分 | 再開時の再計算 | 再利用が薄いと利得減 |
| セッショングルーピング | グループ別の実行数と文脈長 | セッション割当と先入れ先出しで均す | プレーンの遊び | 初期不均衡は残る |
| 高速ページ割当 | ページ種別の占有と偏り | 残余を速いページへ置く | 残余不均衡 | ブロック内での割当制約 |
| HBMバッファリング | 再利用見込みと読み書き比 | 選別してからまとめて書き戻す | 書き増幅と寿命 | HBM容量の占有 |

## 評価

結論は、エージェント型ワークロードでは容量の使い道と物理配置と書き管理を一緒に設計することで、大容量フラッシュの理論上の利得を実際のスループットへ変えられる、というものである。評価は実機ではなく、論理シミュレータと、HBFSimを拡張したハードウェアシミュレータによるトレース駆動評価で、対象はA100とQwen3-Coder-30B-A3B、H100とMiniMax-M2.7、H200とGLM-5.1の3構成、ワークロードはループ型とグラフ型のコーディングエージェントである。文脈長は平均約106Kトークン、ターンあたりデコードは平均386トークンという、再計算が重くなる条件が前提である。エンドツーエンドの平均利得7.04倍の内訳を見ると、SLCでもCDAだけで1.82倍、QLCの容量で3.04倍まで伸び、残りをLaFlashの配置機構が2.36倍上積みしており、容量の論理と物理配置の両方が必要だったことが分かる。SSDベースの保持方式との比較では、同容量で帯域が14.7ギガバイト毎秒対2048ギガバイト毎秒と桁違いであり、エンドツーエンドで84倍の差が付いた。ハードウェア費用として、CMOSダイは165平方ミリメートルで規格フットプリントの94パーセントに収まる一方、ページバッファが面積の77パーセントを占め、QLCはSLCの少なくとも3.5倍の周辺面積を要する点が実装上の重さとして正直に示されている。モデルの出力品質は変わらない方式であり、品質評価は対象外である。

### 評価上の制約

- 実機ではなくシミュレータ評価であり、QLCの読み遅延は投影値を含む。
- 利得は長文脈で短いデコードというコーディングエージェント条件に強く依存する。
- 寿命の値は保持要件を緩める耐久強化策を併用した前提である。

## 既存研究との差

既存のHBF研究はSLC前提で、FlashAccelはリクエスト専有配置で書き局所性を守るが文脈長不均衡に弱く、HBFlexは寿命の近いリクエストをまとめても実行と休止の不均衡に弱く、Flintは全プレーンへ広げて読み並列を最大化するがブロック利用率を落とす。LaFlashは、容量の配分方針であるCDA、グルーピングによる均し、ページ種別の遅延差を使う割当を組み合わせ、この三者のトレードオフの間で帯域利用率とブロック利用率を両立させた点が異なる。SSDへKVを退避するCachedAttentionなどとは、フラッシュを低帯域な外部ストレージではなくHBM並列の高帯域階層として組み込む点で前提が違う。

## 限界・実装状況

限界は、評価がすべてシミュレーションであり実デバイスの読み再試行や保持劣化といった信頼性の問題を扱っていないこと、QLCの読み遅延に投影値を含むこと、利得がコーディングエージェント特有の長文脈で短いデコードと頻繁な休止再開に依存すること、周辺回路の面積がフットプリントの94パーセントまで迫り余裕が小さいことである。実装状況は、論理シミュレータとHBFSim拡張による評価実装であり、制御ロジックはRTLで検証され45ナノメートルで合成されたが、実チップや実機提供での検証はない。公式コードの公開先は一次資料で明示を確認できなかった。

## 一般的な実装上の含意

追加容量の使い道は、同時実行の拡大が唯一の正解ではなく、再計算と読み戻しの費用比が大きいワークロードでは、休止状態の保持へ回す方が加速になる。保持先の媒体については、容量だけでなく、アクセスの不均衡を吸収する配置の自由度と、書き増幅を抑える選別書き戻しがセットで必要である。また媒体固有のばらつき、ここではページ種別ごとの読み遅延は、欠点として隠すだけでなく割当の自由度として使うと不均衡対策へ転用できる。
