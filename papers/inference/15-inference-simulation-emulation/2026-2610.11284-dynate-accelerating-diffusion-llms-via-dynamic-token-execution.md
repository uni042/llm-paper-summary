# DynaTE: Accelerating Diffusion LLMs via Dynamic Token Execution

> 拡散型LLMの反復デコードで、低効用トークンの計算省略、局所依存の反復内直列精緻化、ロジットのストリーミング処理を、次元再構成可能な演算アレイで支えるハードウェア・ソフトウェア協調設計。

## 概要

拡散型の大規模言語モデル（拡散型LLM）は、自己回帰型のようにトークンを1つずつ生成せず、マスクされたトークン群を双方向の文脈で並列に予測し、信頼度の低いものを再マスクして反復的に精緻化する。この実行形態は、単一トークンの逐次生成を前提にした自己回帰型アクセラレータとも、連続した潜在表現を密に更新する画像向け拡散アクセラレータとも噛み合わない。論文はワークロードを実測し、無駄が3種類あることを示す。第1に、未確定トークンの中には再計算しても予測がほとんど改善しない低効用のものが多いのに、全トークンが毎反復で完全なTransformer計算を受ける。第2に、近傍トークン同士の強い依存は疎で一時的なのに、それを解くには全体の反復をもう1回回すしかない。第3に、各反復で生じるトークン数×語彙数のロジット行列を一度HBMへ書き出して読み戻す転送が、並列トークン数に比例して毎回発生する。

DynaTEはこの3つへ、アルゴリズムとハードウェアを対にして対処する。低効用トークンはクエリ側の注意と全結合計算を層ごとに飛ばし、局所依存は検出器FLDDが見つけた近傍ペアだけを当該反復の中で直列に精緻化し、ロジットはHBMへ出さずにストリーム処理でTop-32候補と分布統計へ要約する。省略で生じる不規則な有効トークン数は、次元再構成可能な演算アレイと精度を分割できるMAC単位で吸収する。代表結果として、LLaDA-8BとDream-7Bの5ベンチマークで、先行する拡散型LLMアクセラレータ比2.05から2.78倍の高速化と2.99から3.93倍のエネルギー効率を報告し、生成品質の低下は全最適化時でも平均0.41ポイントにとどまる。

## 問題設定

自己回帰型アクセラレータは「新しいトークン1個」が実行単位であり、キャッシュは追記だけを前提にする。拡散型LLMは1ブロック内の複数位置を同じ反復で更新し、確定しなかった位置を後の反復で何度も再訪する。画像向け拡散アクセラレータは固定した空間トークン配置を密に更新し続けるが、拡散型LLMは反復ごとに語彙分布を作って離散的な確定・再マスクの判断を行うため、下流の語彙処理とトークン状態制御が要る。先行する拡散型LLM専用アクセラレータは、語彙サンプリングの高速化や反復間の活性値再利用に取り組んだが、全トークンを並列実行に残す点は共通していた。論文の特性評価は、この一様実行のどこに無駄があるかを3つの観測で具体化する。トークンごとの更新利得は偏っており高利得の位置は反復ごとに移るため、固定マスクでは捉えられない。近傍ペアの結合利得が高いのは孤立したペアと反復だけであり、ブロック全体の直列化は過剰である。ロジット転送量は並列トークン数と反復回数の積で増え、Top-32しきい値を超える候補の到着はトークンごとにバースト的で、単独処理では選択パイプラインが遊ぶ。つまり課題は、動的に変わる「どのトークンを、どの依存順で、どれだけの語彙処理で」扱うかを実行へ反映できるかである。

## 手法のあらまし

処理の流れは反復ごとに繰り返される。前反復の分布統計（Top-32で打ち切ったエントロピーと信頼度）と確定済みトークンまでの距離から、低効用と見込まれるマスクトークンの候補を選び、各層ではその候補が受ける注意質量がしきい値未満のときだけクエリ側計算を飛ばす。キーとバリューは通常どおり作るため、飛ばされたトークンも他トークンの文脈としては生き続ける。並行して、近傍位置の分布変化の近さ・候補集合の入れ替わり・エントロピーから局所依存スコアを計算し、高いペアについては確定したアンカーの文脈で近傍トークンを同じ反復内に追加で精緻化する。この直列分はMSMデータフローが並列バッチへ畳み込み、行列積の形を保ったまま実行する。最後に、言語モデルヘッドの出力ロジットはHBMへ書かずにストリーミング語彙エンジンへ直結し、複数トークンの候補列を交互に処理してTop-32と分布統計を作る。この統計はサンプリングだけでなく、次反復の枝刈りと依存検出の入力にも再利用される。演算アレイは有効トークン数に応じて行列の次元配分を組み替え、MACは精度モードに応じて分割する。

## 手法

### 1. トークン単位のクエリ枝刈り — 低効用トークンの計算を層ごとに飛ばす

入力は前反復の分布統計とトークン位置であり、出力は層ごとに増えていく枝刈り集合である。候補になるのは、マスク状態で、打ち切りエントロピーが高く、信頼度が低く、最も近い確定トークンから離れているトークンである。直感的には「分布が散っていて自信がなく、確定した文脈からも遠い」トークンは、この反復で再計算しても予測が動きにくい。ただし候補のまま一律に飛ばすのではなく、各層でそのトークンが有効なクエリから受ける平均注意質量を蓄積し、しきい値未満の層でのみ次層の枝刈り集合へ加える安全弁がある。文脈へ強く影響するトークンは注意質量が大きくなり、飛ばされずに残る。飛ばされたトークンの隠れ状態は恒等バイパスで次層へ通り、キーとバリューは各層で再計算されて他トークンから参照できる。減るのはそのトークン自身のクエリ側注意と全結合計算であり、追加費用は注意確率の流れに沿った軽い蓄積だけである。枝刈りは反復内でのみ持続し、次反復では再評価される。失敗条件は効用の見立て違いであり、論文の品質評価では枝刈り単独のスコア低下は最大0.6ポイントに収まっている。

### 2. FLDDとMSM — 局所依存を全体反復ではなく反復内の直列精緻化で解く

並列デコードは全トークンを更新前の同じ文脈から予測するため、確定したばかりのトークンの情報は近傍へその反復内では届かない。FLDD（高速局所依存検出）は、近傍2位置について、反復をまたいだ分布変化量（Top-32で打ち切ったKLダイバージェンス）の差、連続反復でのTop-4候補集合の重なり、現在のエントロピーの3指標を重み付きで合成し、依存スコアがしきい値を超えた位置をアンカーとして選ぶ。選ばれたら、アンカーを確定させ、その更新済みKV文脈で近傍トークンを追加精緻化する。直列分を独立に実行すると行列ベクトル積ばかりになり演算アレイの利用率が落ち、並列側も止まる。そこでMSMデータフローは、QKV射影と全結合では直列トークンを並列バッチへ合流させ、注意だけを「更新前文脈を使う並列側」と「更新済みアンカー文脈を使う精緻化側」へ分割し、再び合流させる。結果として反復あたり遅延の増加は8.54パーセントに抑えられ、見返りに全体の反復回数そのものが減る。FLDDはオラクルな依存ペアの39.1から45.2パーセントを捉えるにとどまる低費用のヒューリスティックであり、捉え損ねた依存は従来どおり次反復へ持ち越される。

### 3. 次元再構成可能なアレイと分割可能MAC — 不規則な形状と段階的な精度を支える

枝刈りと直列精緻化は、注意と全結合の行列形状を反復ごとに変える。固定形状のサイストリックアレイでは有効トークン数が減るほど利用率が落ちるため、DynaTEは64×4の部分アレイ8個からなる演算アレイの接続を組み替え、全体のMAC数2,048を保ったまま64×32から512×4までの形状を取る。隣接部分アレイ間の横伝播とバイパス、縦方向の経路切替で、トークン次元とモデル次元の配分を変える。各MACは分割可能で、8ビット重み×8ビット活性値の演算1個、または8ビット×4ビットの演算2個並列のどちらかとして働く。加算器の区間を共有する設計により、多精度対応の面積増は6.17パーセントに抑えられる。精度の割当ては、解凍済みトークン比率ごとに較正したルックアップ表で決まり、モジュールごとにW8A8とW8A4を切り替える。アレイ再構成が効く理由は、省略で生じた「小さく不揃いな行列」を詰め直して利用率を80パーセント超に保てることであり、固定アレイで同じアルゴリズム最適化だけを行った対照では累積高速化が大きく目減りすることがアブレーションで示されている。

### 4. ストリーミング語彙エンジン — ロジットをHBMへ出さず複数トークンで平滑化する

入力は言語モデルヘッドが出力するロジットの流れであり、出力はトークンごとのTop-32表と分布統計である。前反復のTop-32候補の現在ロジットから選択しきい値の初期値を立てる温め開始により、全語彙走査でしきい値を超える候補だけが比較パイプラインへ入る。各トークンに生存者バッファを持たせ、共有するトーナメントパイプラインへ複数トークンの候補を交互に流すことで、単一トークンでは5サイクルに1回しか更新できず約20パーセントに落ちるコア利用率を、文脈数の増加とともに最大97.6パーセントまで引き上げる。完全なロジット行列をHBMへ往復させる従来方式と比べ、中間ロジット転送は反復あたり16.0MiBから8.2KiB（LLaDA-8B）へ減り、HBMアクセスエネルギーは1,923倍小さい。分布統計が枝刈りとFLDDへ還流する点も重要で、語彙処理は単なる出力段ではなく、次反復の実行判断の観測点になっている。

| ストリーミング語彙エンジン | 言語モデルヘッドのロジット流 | Top-32選択と分布統計をHBM経由なしで作る | ロジット転送と選択パイプライン利用率 | 前反復候補への依存（温め開始） |

## 評価

### まず見るところ

- **結論:** アルゴリズム側の省略（枝刈りとFLDD）とハードウェア側の形状追随は相補的で、片方だけでは利得が大きく目減りする。語彙のストリーミング化は転送量を桁違いに削るが、全体利得への寄与はアブレーションの最終段分である。
- **速度・効率:** すべてサイクル精度シミュレーションと論理合成・メモリモデルに基づく推定であり、実機測定ではない。比較相手の先行アクセラレータはMAC数を揃えて正規化されている。
- **品質:** 近似の組合せであり、全有効時のスコア低下は平均0.41ポイント・最大0.7ポイントと小さい。ただし評価は5ベンチマークのスコアのみで、生成文の質的な劣化分析はない。
- **メモリ・入出力:** ロジットの中間転送はほぼ消えるが、重みとKVキャッシュのHBM転送は残る。総電力7.36Wのうち5.17WがHBM側である。

**数値の読み方。** 高速化倍率は相手ごとに分けて読む必要がある。要旨の2.05から2.78倍は先行拡散型LLMアクセラレータ（DARTとdLLM-OPU）への範囲、固定形状アレイへの4.32倍は自作の対照実装への値、Jetson AGX Orinへの2.55倍は商用GPUへの値である。アブレーションの累積4.32倍はこの固定形状対照への値と一致する。

## 既存研究との差

DARTは語彙サンプリング段の専用ハードウェアで高速化したが、ロジットは一度HBMへ書いてから読む流れを残した。DynaTEはロジットをヘッド出力の流れの上で直接要約し、この往復自体を消す。dLLM-OPUは反復間の活性値の時間的類似性を使い再計算を減らすが、中間活性値を保持する追加ストレージが要り、トークンの参加自体は一様である。DynaTEは精緻化の効用と局所依存を見てトークンの参加と精緻化順を変える。反復途中で確定したトークンを固定してKVを再利用するSureLockは未確定側ではなく確定側を対象にし、DynaTEの枝刈りはマスク側の低効用トークンを層ごとに飛ばす点が違う。アレイ再構成のPlanariaやReDas、多精度化のBitFusion、Top-K選択のSpAttenといった汎用DNNハードウェア技術に対しても、本論文の差分はそれらを拡散型LLMのトークン動態（枝刈り・直列精緻化・語彙バースト）へ結び付けて一体設計したことにある。

## 限界・実装状況

評価はすべてシミュレーションと論理合成ベースであり、実チップや実ボードでの測定はない。対象はLLaDA-8BとDream-7Bの2モデルで、パート単位デコードと近似KV再利用という特定のデコード方式を前提にするため、他の拡散型LLMや自己回帰型モデルへの一般化は未評価である。枝刈りとFLDDのしきい値、精度切替のルックアップ表はオフライン較正に依存し、モデルごとに調整が要る。FLDDが捉える依存はオラクルの4割前後にとどまり、残りは追加反復で処理される。生成品質はベンチマークスコアのみで測られ、長い生成や分布外入力での劣化は未評価である。論文中に公式コードやRTLの公開先は示されておらず、IEEEへ投稿中と記されている。

## 一般的な実装上の含意

反復精緻化型の生成では、「全要素を毎回同じだけ計算する」前提を外し、要素ごとの改善見込みに応じて計算参加を決めることが大きな削減源になる。その際、省略で生じる不規則なワークロード形状へハードウェア側が追随できないと、アルゴリズム上の削減がそのまま性能にならない点は、ソフトウェア側の動的バッチや疎実行にも通じる。また、中間テンソルはメモリ境界を越える前に要約する（ここではTop-32と分布統計）ことが転送削減の原則であり、その統計を次段の実行判断へ還流させると観測の二重投資を避けられる。
