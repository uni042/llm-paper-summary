# TORTA：将来の負荷とサーバー切替費用を考慮した分散LLM推論GPU配分

## 概要

複数の地域に分散したGPUサーバーへ推論要求を割り当てるとき、現在の空き容量だけを見て最も速そうなサーバーを選ぶと、需要の増加に遅れて起動するサーバーや、短時間で頻繁に移動する要求が生まれる。大きなモデルのロード、GPUメモリの準備、推論エンジンのウォームアップには時間がかかるため、目先の待ち時間を減らす割当が次の時間帯の待ち行列や運用費を悪化させる。

TORTA（Temporal Optimal Resource scheduling via Two-layer Architecture）は、地域間の要求配分と地域内のサーバー選択を二階層に分ける。上位層は需要予測、最適輸送、強化学習を組み合わせ、将来の需要と割当の連続性を考慮して地域間の負荷を配分する。下位層は起動台数を調整し、GPU性能、現在負荷、最近使ったモデルの局所性に基づいて各要求をサーバーへ割り当てる。

原著v2は、4種類のネットワークトポロジーを用いた**シミュレーション**で評価した。最も良い比較対象SkyLBに対し、平均応答時間はAbileneで18.72秒から16.39秒へ12.4%短縮、Polskaでは20.53秒から19.19秒へ6.5%短縮した。電力費はトポロジーに応じて7.2〜16.4%低下した。ただしこれは実際の多地域LLMサービングを本番運用した実測値ではなく、模擬した需要・GPU容量・コストモデルに依存する。

## 問題設定

地域間には需要とGPU供給の偏りがあり、ネットワーク遅延、電力料金、GPU種類も異なる。要求には必要な演算能力、メモリ容量、期限があり、あるサーバーへ集中させると待ち行列が伸びる。空きサーバーを増やせば直ちに処理できるとは限らず、モデル重みのロードやエンジン起動の遅延がある。原著の動機付けでは、V100上のLLaMA-2-7Bの移動に状態直列化約15.2秒、逆直列化約4.8秒、GPUメモリロード約5.6秒、エンジン起動約5.1秒という内訳を示す（§II-B、Fig.3）。これらは特定環境の観測例であり、すべてのGPU・モデルに共通する固定費ではない。

反応的な方式は、時刻ごとに現在の利用率やキューだけを見て割当を解く。次の時刻の需要を見ないため、需要急増時にはサーバーを起動するまで要求が滞留し、負荷が下がると不要なGPUが残る。時刻ごとに最適な配置を選んでも、前時刻からの変更量が大きいと、モデル切替や要求移動の費用が蓄積する。さらに複数地域と多数のサーバー・要求を一度に最適化すると組合せ数が急増し、厳密な整数計画はリアルタイム制御に間に合わない。TORTAは時間的な平滑化と二階層分割で、この両方の問題を扱う。

## 手法

### 1. 状態と目的関数

時刻を離散スロットに区切り、地域ごとのGPU利用率、待ち行列長、地域間ネットワーク遅延、過去の負荷パターンを状態として保持する。各要求には演算量、メモリ量、期限を与え、割当は各要求を一つのサーバーへ結び付ける。最適化の目的は、要求の待ち時間・実行時間・ネットワーク時間を含む応答時間、地域ごとの電力費、前スロットからの配置変更費用を組み合わせた累積費用である。変更費用を含めることで、現在だけ速い割当から、将来も大きな移動を起こしにくい割当へ誘導する。

原著式(1)では応答時間に切替費用と電力費の重み付き和を加える。重みは単位の異なる費用を比較可能にする調整係数でもある。実装ではGPU資源の供給と要求の需要が異なるため、地域間の比率へ正規化した配分と、個々の要求を割り当てる離散的な配置を区別する必要がある。目的関数は実サービスの請求額をそのまま最小化する式ではなく、実験で定義した費用モデルに従う。

### 2. 地域間の最適輸送による参照配分

上位層は、地域別の要求数を正規化した需要分布μと、GPU処理容量を正規化した供給分布νを作る。最適輸送は、地域iから地域jへ要求のどれだけを流すかを示す輸送行列Pを、電力料金と地域間転送費用からなる費用行列に基づいて求める。各行の合計が需要分布、各列の合計が供給分布に一致する制約の下で輸送費用を最小化する（原著式2）。その行を正規化した値が、出発地域から各処理地域へ振り分ける確率の参照となる。

この解はその時点の需給と費用に対して有用だが、翌時刻の需要増加やサーバーの切替費用を十分に考慮しない。そこでTORTAは最適輸送の解を最終配置として固定せず、強化学習の参照信号として利用する。地域間配分を連続値の確率行列で扱うことで、個々の要求とサーバーの全組合せを一度に探索する問題を避ける。

### 3. 需要予測と強化学習による時間的平滑化

履歴の利用率、キュー、時間特徴を入力する予測器をオフライン学習し、次の時間帯の地域別到着要求数を予測する。強化学習の状態には、この予測値と前スロットの配分行列も含める。方策は各地域から他地域へ振り分ける割合を出力し、行の合計が1になるよう正規化する。学習には近接方策最適化（PPO）を使い、最適輸送の参照行列とのずれ、前時刻からの配分変更、現在の待ち行列を罰する報酬を設定する（原著式3〜5）。

この設計は、目先の電力費が安い地域へ大量に要求を移すだけでなく、次の時刻の混雑と移動費用を考慮して割当を滑らかに変えることを目指す。原著は最適輸送からの偏差と切替費用改善に制約を設けた学習損失も提示し、反応的な方式を上回るための十分条件を付録で議論する。ただし理論的な改善条件は費用関数の滑らかさや切替費用に関する仮定を置いており、あらゆる実ワークロードでの優越を保証するものではない。

### 4. 地域内の起動台数と要求配置

上位層の地域別要求配分を受け取った下位層は、現在のキュー長と予測到着数から必要な稼働サーバー数を求める。原著式(6)では、予測需要の平方根に比例する安全余裕を加え、地域内サーバー容量で割って必要台数を決める。急な増減による起動費を避けるため、稼働台数は段階的に変更する。追加起動ではウォームアップ時間とハードウェア適合性を考慮し、停止では長く遊休している低負荷サーバーを優先する。

各要求については、GPUの演算・メモリ要件に合うか、現在の利用率と待ち行列がどの程度混雑しているか、最近同じモデルや類似要求を処理したかを点数化する（原著式7〜10）。モデル重みや中間状態の再利用が期待できるサーバーには局所性の加点を与え、過負荷のサーバーには指数的な減点を与える。期限が近い要求から貪欲に割り当て、割当後は利用率とキューを更新する。容量不足の要求は待機させ、必要に応じて追加サーバーの起動を促す。これにより地域間の粗い配分を、具体的なGPU能力とキャッシュ局所性を考慮した配置へ落とし込む。

### 5. 一つの要求の処理順

新しい要求が到着すると、まず予測器と現在状態から地域間の配分確率が決まる。要求の発生地域に対応する確率行に従い処理地域を選び、その地域のキューへ入れる。地域内では予測需要に基づいて稼働台数を調整し、利用可能なサーバーを互換性・混雑・局所性の点数で比較して配置する。次のスロットでは更新された利用率とキュー、前回の配分行列が上位層へ戻る。上位層の出力と下位層の状態更新が循環することで、単一時刻の配置最適化では扱いにくい切替費用を制御する。

## 評価

### シミュレーション環境と比較条件

| 観点 | 原著v2の設定 |
|---|---|
| 評価形態 | 6時間、45秒間隔の480スロットのシミュレーション |
| トポロジー | Abilene 12ノード・10Gbps・25ms、Polska 12・10Gbps・45ms、Gabriel 25・15Gbps・80ms、Cost2 32・20Gbps・150ms |
| GPU種類 | A100、H100、RTX 4090、V100、T4の異種構成。種類ごとに20〜80台程度を設定 |
| 要求 | 演算量・メモリ量・期限の異なるタスク。処理時間は一様分布に従う模擬要求 |
| 比較対象 | SkyLB（局所優先の地域間負荷分散）、SDIB（負荷偏差・遊休時間最適化）、RR（ラウンドロビン） |
| 指標 | 平均応答時間、負荷均衡係数、電力費、運用切替オーバーヘッド |
| 制約 | 比較方式は同一シミュレーションに適合するよう再実装・調整されている |

ここでの平均応答時間は、要求到着から処理完了までのネットワーク時間、待ち時間、GPU処理時間の合計である。負荷均衡係数は利用率の変動係数を用いた `1/(1+CV)` で、大きいほど利用率が均一になる。電力費の単位は論文図中の千ドル、運用オーバーヘッドは正規化された計画単位であり、実際のクラウド料金の実測ではない。各比較方式の元論文が扱う環境は必ずしも同一ではなく、本論文の環境へ適応した実装で比較している。

### 応答時間（原著Fig.8）

| トポロジー | TORTA | 最良比較SkyLB | 改善率 |
|---|---:|---:|---:|
| Abilene | 16.39秒 | 18.72秒 | 12.4%短縮 |
| Cost2 | 19.31秒 | 21.58秒 | 10.5%短縮 |
| Gabriel | 17.58秒 | 20.07秒 | 12.4%短縮 |
| Polska | 19.19秒 | 20.53秒 | 6.5%短縮 |

どのトポロジーでも改善するが、Polskaでは差が小さい。原著はネットワーク接続性が高い環境では単純な方式でも比較的良い配分を作れるため、時間的な予測の追加利得が小さくなると解釈する。したがって最大の12.4%短縮をすべてのトポロジーへ当てはめない。論文要旨の「最大15%」は全体の総括であり、上表のSkyLBとの4条件比較と区別する。

## 既存研究との差

SkyLBは地域内で処理できる要求を優先し、余剰要求を他地域へ転送する。SDIBは利用率のばらつきと遊休時間を減らす。これらに対しTORTAは、現在の混雑だけでなく次の時間帯の到着予測と前時刻の割当を状態へ含める。最適輸送は地域間の需給と電力費の参照配分を作り、強化学習がそれを時間方向に滑らかにし、地域内の貪欲配置が実際のGPU要件とキャッシュ局所性を処理する。地域間と地域内を一つの巨大な整数計画で解く代わりに、階層を分けてオンラインの意思決定を簡素化する点が差分である。

## 限界

実験はシミュレーションであり、実際の複数地域のGPUクラスタへ本方式を導入した運用実績ではない。処理時間を一様分布で与え、比較方式も同一の模擬環境へ合わせて再実装しているため、実サービスの長文脈生成、モデルごとのKVメモリ、連続バッチ、通信混雑、p95/p99遅延へそのまま外挿できない。地域間の最適輸送は需要と供給を正規化しており、絶対容量不足のときはキューとサーバー起動で対処する必要がある。需要予測が大きく外れる場合は事前起動や地域配分が不適切になり得る。

理論的な改善保証は、切替費用の下限や費用関数の滑らかさ、最適輸送参照からの偏差などの仮定に依存する。原著では時刻ごとの要求数が変化し得るのに、要求単位の割当行列の差を切替費用の表現として書く箇所があり、実装での要求ID整列や次元の扱いを確認する必要がある。また、論文の負荷均衡指標は本文の一箇所で「変動係数の逆数」と記す一方、実際の式は `1/(1+CV)` であり、数値の解釈には後者を用いる。コードの公開URLや実サービスでの再現性は一次論文中で確認できない。
