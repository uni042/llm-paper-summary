# LLM Inference Under Bursty Workload Distribution — 到着率推定でWAITのバッチ閾値を動的更新する

## 書誌情報

Anjali Gangadhar Katageria、Shobha Rani、Raghu Nandan Sengupta。arXiv:2608.06135、2026年8月6日公開のプレプリント。原著本文の§4〜6にアルゴリズムとシミュレーション評価があり、実GPUのオンラインサービス実測ではない。対象は大規模言語モデルのサービングにおける、入力要求の到着が時間とともに変動する場合のバッチ形成と待ち行列制御である。

## 概要

LLMサービングでは、GPUに投入するバッチを大きくすれば1回の演算で多くの要求を処理できる一方、十分な要求が集まるまで待つと応答遅延が増える。既存のWAIT（Waiting for Accumulated Inference Threshold）スケジューラは、要求種別ごとの到着率を事前に知っている前提でバッチ投入の閾値を決める。現実の到着は急増と閑散が交互に起こるため、固定到着率から計算した閾値が現在の負荷に合わなくなる。

本論文のModified WAITは、直近の要求到着時刻から到着間隔を計算し、移動平均・指数移動平均・Savitzky–Golayフィルタで平滑化した到着率を使って、WAITのバッチ閾値を逐次更新する。二状態マルコフ変調ポアソン過程（MMPP-2）で合成した突発的な到着列をMicrosoft VidurのNVIDIA A100シミュレーションへ入力し、元のWAIT、Sarathi、ORCA、vLLMと比較した。推定器の3条件平均絶対誤差は15.39、平均絶対百分率誤差は14.37%。原著は、状態切替の遅い負荷でSarathiとvLLMより高い処理量を示し、元のWAITに近い処理量・遅延を得たと報告する。ただし実運用の要求トレースや実GPUでの測定はなく、改善倍率を普遍的な値としては示していない（§5.2、§6）。

## 問題設定

WAITは要求をm種類に分け、種別jの入力トークン長lj、出力トークン長l'j、到着率λjを扱う。各要求は最初のprefillと、その後のl'j回のdecode段階を進む。待ち行列は要求種別と現在の段階kごとに保たれ、種別jのprefill待ち要求数が閾値nj以上になれば、その種別の各段階から最大nj個をバッチへ組み込む。処理が終わった要求のKVは解放し、未処理要求のKVは保持する。したがって閾値はGPUメモリ占有、待ち時間、反復処理時間の両方に影響する（原著Algorithm 1）。

元のWAITの閾値設計は、メモリ容量Cと平衡必要メモリM*の関係、到着率λj、段階別トークン長から導かれる流体近似に基づく。原著式(1)は反復時間 `ΔT = d0 + d1 Mπ` と `nj/λj` の制約、そして `Mπ = Σj nj(l'j+1)(lj+l'j/2)` を用いる。これは「要求が多ければ何でもすぐに処理する」という単純な閾値ではなく、GPUメモリと処理時間の制約下でバッチ形成を制御するものである。

到着が固定率のポアソン過程ならλjを予測しやすいが、実サービスの要求列は時刻、イベント、ユーザー行動に応じて短時間で変動する。一定の平均到着率を使い続けると、現在の負荷では小さすぎるバッチを投入したり、逆に要求が集まらないまま長く待ったりする。元のWAITを実運用へ適用するには、将来の要求列を知らなくても到着率を推定し、現在の状態に追従する仕組みが必要になる。

## 手法

### 1. 二状態MMPPによる突発的な要求列の生成

評価用の入力生成では、要求到着の状態を低需要と高需要の二つに分ける。状態0の到着率をλ0、状態1をλ1とし、状態間の遷移率q01とq10から指数分布の滞在時間をサンプリングする。各滞在区間で平均到着数 `λstate × duration` のポアソン乱数を生成し、区間内へ要求時刻を割り当てる。状態を交互に遷移させれば、同じ平均要求数でも一定率のポアソン到着とは異なる、まとまった高負荷・低負荷の期間を作れる（Algorithm 2）。

この入力は実際のユーザーから採取した要求ログではなく、変動率と到着率を制御できる合成トレースである。二状態だけなので時間帯依存や多数のトラフィック源の相関を完全に再現するわけではない。著者は到着率の高低と状態切替の頻度を組み合わせ、低需要・低切替（LDLS）、低需要・高切替（LDHS）、高需要・低切替（HDLS）、高需要・高切替（HDHS）の四条件を設けた。ここで「低切替」は負荷の変化が起こる頻度が低いことを意味し、到着率自体が必ず低いことではない。

### 2. 到着間隔からのオンライン到着率推定

ランタイムが観測するのは各要求の到着時刻と入力トークン情報であり、MMPPの真の隠れ状態は観測できない。そこで隣接する要求の到着間隔を求め、最近w件の間隔を平均し、その逆数を局所的な到着率の推定値とする。短い区間の到着率はポアソン雑音で大きく揺れるため、指数移動平均（EMA）で過去の推定と新しい観測を合成する。EMAの係数αが小さいほど一時的な変動を抑えるが、急な状態変化への追従は遅くなる。

さらにSavitzky–Golayフィルタで局所窓に低次多項式を当てはめ、単純な移動平均より変化の形状を残しながら平滑化する。得られた平滑化列から全体の平均到着率を更新し、WAITの閾値計算へ渡す。これは未来の到着を予言する学習モデルではなく、過去の到着間隔だけから現在の到着強度を推定する因果的な制御器である。平滑化窓を長くすると雑音は減るが状態切替後の追従が遅れるため、窓とEMA係数の選択が重要になる。

### 3. 感度試験と推定器の設定

著者はMMPP-2の三つの到着率組（50,100）、（75,175）、（100,250）を使い、EMA係数、Savitzky–Golayの窓幅と多項式次数、到着間隔の移動平均窓を変えて推定誤差を比較した。真のMMPP状態の到着率を正解とし、平均絶対誤差（MAE）と平均絶対百分率誤差（MAPE）を各トレースで計算する。選択された構成はEMA係数0.05、Savitzky–Golay窓151、次数2、移動平均窓5で、三条件平均MAE 15.39、MAPE 14.37%、最大MAE 17.78、MAPE 16.13%である（原著Table 2、§5.2）。

この数値は**到着率推定の誤差**であって、サービングの処理量改善率や応答遅延ではない。窓151は短い急増に対して応答遅れを生み得るし、三つの合成条件で選ばれた設定が実運用の到着率にも最適とは限らない。原著は変動に追従しながら平滑化する実用的な折衷としてこの設定を採用し、その後のスケジューリング評価で固定している。

### 4. WAIT閾値の逐次更新とバッチ投入

到着率の推定値λ̂tを得ると、元のWAITが用いる種別ごとの閾値計算を更新する。原著§5.2では、推定率が増えると閾値を下げてバッチ形成を早め、低負荷時には閾値を上げるという制御の意図を説明する。ただし実際の閾値は原著式(1)のメモリと反復時間の制約も満たす必要があり、単にλ̂tの逆数を閾値へ代入するだけの自由な更新ではない。到着時刻の観測→平滑化→λ̂tの更新→閾値再計算→現在の待ち要求を確認してバッチ投入、という一連の処理を繰り返す。

当初は状態が切り替わるたびに閾値を急変させる方式を試したが、デコードの進行が不安定になりメモリ使用も乱れた。そこで各要求の到着ごとに滑らかな推定値を更新する方式へ変更した。10件ごとにまとめて更新する場合との差は小さかったため、著者は単純な逐次更新を採用した（§4.3）。この失敗経験は重要で、突発負荷への追従を強くしすぎるとスケジューラ自身が処理の安定性を損ねる可能性を示している。

## 評価条件と主要結果

### シミュレーション条件

Microsoft VidurでNVIDIA A100相当の推論処理を模擬し、二状態MMPPの合成要求列を投入する。比較対象は、将来を含む全トレースの平均到着率から閾値を決める元のWAIT、Modified WAIT、Sarathi、ORCA、vLLMで、バッチサイズの上限は統一する。元のWAITは将来の全到着列を利用できるという情報面で有利な対照であり、現実のオンライン実装がその情報を持てるわけではない。一方、それは必ずしも全ての状態で数学的な最適処理量を保証する厳密な上界ではない。

| 評価区分 | 入力構成 | 主要な検証点 |
|---|---|---|
| LDLS / LDHS | 2種の要求、入力各10トークン、出力10/20トークン、二状態の到着率を変化 | 低需要で状態切替頻度が性能へ与える影響 |
| HDLS / HDHS | 3種の要求、入力各20トークン、出力100/200/300トークン | 長い出力と高需要でのメモリ・バッチ制約 |
| 到着率推定 | MMPP到着率組50/100、75/175、100/250 | 真の状態別到着率に対するMAE/MAPE |
| 比較対象 | WAIT、Sarathi、ORCA、vLLM、Modified WAIT | 平均処理量と平均遅延のトレードオフ |

原著Table 3/4では高需要側の要求種別別到着率を状態0で(5000,4000,2000)、状態1で(4000,3000,1000)と設定し、出力長も低需要より長い。数値の単位やGPU実機へのスケーリングを本文の情報以上に補わない。ここで報告される処理量と遅延は**シミュレータの出力**である。実際のA100上で同じ要求を実行した測定ではない。

### 低需要と高需要の結果

低需要では、Modified WAITは全トレースの到着分布を知る元のWAITに近い平均処理量を示した。状態切替が速い条件では遅延が元のWAITに近く、遅い条件では全ての比較方式より遅延が低いとは限らないものの、同程度の範囲に収まる。著者は特に状態切替の遅い条件でSarathiとvLLMより高い処理量を得たと結論する（Figure 6）。これは負荷状態がしばらく続くと、到着率推定が追従する時間を確保できるという機構と整合する。

高需要では、Modified WAITの平均処理量は元のWAITに近く、平均遅延では元のWAITを上回る条件がある（Figure 7）。一方で原著は高切替条件では両WAIT方式に改善余地が残ると認め、全条件で遅延が優れているとは述べていない。原著§6のグラフは処理量・遅延を示すが、本文の数値表に全比較方式の絶対値や改善倍率が掲載されていないため、ここでは**図の曲線から未確認の数値を推測して転記しない**。

この結果から直接いえるのは、到着分布を先験的に知らなくても、オンライン推定でWAITの振る舞いをある程度再現できるという点である。「Modified WAITがあらゆる突発負荷に最適」「実GPUで既存方式より一定倍率高速」という強い主張は実証されていない。平均処理量と平均遅延を測っているが、厳しいP99の尾部遅延、TTFTのサービスレベル達成率、要求の飢餓防止についてはこの評価だけでは判断できない。

### 負の結果と因果的解釈

急な閾値変更の試作はデコードの進行とメモリ使用を不安定化させた。推定器の平滑化はこの問題を緩和するが、負荷状態の切替が速い場合は推定遅れが生じるため、同じ方式が最良とは限らない。高需要では平均処理量を維持しても、長い出力要求の待ち行列やGPUメモリ制約により遅延が悪化する余地がある。したがって到着率の予測誤差だけを最小化すればサービング性能が最大化するとは限らず、閾値制御の安定性も同時に必要である。

## 既存研究との差

WAITの原型は流体近似と既知到着率からバッチ閾値を計算する。Modified WAITは流体モデルやバッチ構造を置き換えず、**到着率の観測・推定部分をオンライン化**する。Sarathiはプリフィル分割とデコードの混在を重視し、ORCAやvLLMは動的バッチや実行・メモリ管理を扱う。Modified WAITの新規性はGPUカーネルやKV圧縮ではなく、要求到着の非定常性を制御器へ取り込み、閾値を適応させる点にある。

MMPP-2は低負荷・高負荷の状態滞在を持つため、一定平均のポアソン到着では見えない閾値更新の応答遅れを試験できる。これにより、負荷切替の速さと閾値制御の安定性を明示的な評価軸へ加えた。ただし新しい到着率推定法そのものは移動平均・EMA・Savitzky–Golayという既存の統計処理を組み合わせたものであり、学習型の予測器や新しい待ち行列理論の証明ではない。

## 限界と今後の検証

最大の制約は、評価が二状態MMPPで生成した合成要求とVidurシミュレーションに限定されることである。実運用の要求長分布、モデル別GPUメモリ圧力、ネットワーク遅延、キャッシュ再利用、混在する利用者の公平性、長い尾部遅延は十分に実証されていない。二状態では時間帯による周期性や連続的な需要変動、外部イベントの相関を捉えきれない場合がある。状態が急速に切り替わる条件では推定の遅れと閾値の過剰反応が問題になる。

著者は今後、EMAと変化点検出の併用、実トレースによる評価、到着要求の種別予測を挙げている。実装可能性を評価するには、要求種別のオンライン識別、閾値再計算のCPU費用、メモリ容量制約の実装、P95/P99遅延とTTFT、GPU実測の処理量を追加検証する必要がある。現段階では、オンライン到着率推定をWAITへ組み込むことが**合成バースト負荷において有効であり得る**ことを示す研究として位置付けるのが妥当である。
