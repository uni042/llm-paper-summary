# Sim-FA: A GPGPU Simulator Framework for Fine-Grained Asynchronous Pipeline Analysis

> HopperのTMAとWGMMAとワープ特殊化をワープグループ単位でモデル化するサイクル精度シミュレータと、波単位の再取得を入れた解析モデルで、FlashAttention-3の遅延を実機誤差平均5.7パーセントで再現し、既存解析モデルの長系列での過小評価の原因を示す研究。

## 概要

現代GPUの高速化は非同期性に寄っている。Hopper世代では、テンソル記述子からハードウェアがアドレスを生成して共有メモリへ一括転送するTMA（Tensor Memory Accelerator）、非同期に発行できるワープグループ単位の行列積WGMMA、転送役と計算役へワープを分けるワープ特殊化が入り、FlashAttention-3はこれらを使って生産者と消費者のパイプラインを組む。ところが学術側の道具が追随していない。代表的なサイクル精度シミュレータはTMAやWGMMAをモデル化しておらず、屋根線型の解析モデルはパイプラインの泡や資源競合を見られないうえ、後述のようにDRAMトラフィックを条件によって大きく外す。性能が合って見えても内部のトラフィックが外れているモデルは、設計空間探索で候補点を誤って順位付けする。

本論文のSim-FAは、この溝を埋めるサイクル精度シミュレーション基盤である。設計の要点は、ワープグループ（連続する4ワープ）をシミュレーション上の論理スレッドとして扱い、TMAとテンソルコアを非同期エンジンとして分離し、非同期バリアの待ちと起床を詳細にモデル化することにある。入力は実カーネルの計装で得たトレースであり、FlashAttention-3専用の前段が、生産者1グループと消費者2グループのイベント列をシミュレータ命令へオフライン変換する。加えて、演算子に依存しないトレース前段をTritonの中間表現レベルで計装する検証も行われ、23種のGEMM形状で実機誤差平均5.49パーセントが報告され、核が単一演算子専用でないことが示される。

**代表結果:** FlashAttention-3のカーネル遅延について、Llama 3の8B・70B・405Bと系列長512から6,144の組合せで、H800実機に対する平均絶対パーセント誤差（Mean Absolute Percentage Error; MAPE）は5.7パーセント、最大12.7パーセントである。併設の解析モデルは、Blackwell世代のGB10上のcuTileカーネルでも検証され、理想キャッシュ前提の既存モデルGenZが長系列でDRAMトラフィックを過小評価する理由を、容量超過時の再取得で説明する。

## 問題設定

不足しているのは、非同期パイプラインの時間的な重なりを再現できる観測手段である。生産者がTMAでタイルを運び、消費者がWGMMAで積を進め、別の消費者がソフトマックスを重ねる動きは、命令の総量ではなく、バリアの到着と完了の順序、共有資源の競合、キャッシュの合体と振る舞いで決まる。従来のSIMT前提のシミュレータは、スレッドブロック単位の同期を中心に組まれており、分割された到着と待機を持つ非同期バリアや、グループ単位で発行される非同期命令を自然に表せない。解析モデル側の問題は別で、理想キャッシュを仮定すると、KとVは一度だけDRAMから読まれる計算になるが、実機では有効キャッシュ容量を超えた途端に、スレッドブロックの波ごとにKとVが再取得され、トラフィックが系列長の二乗に近い伸びへ転じる。最終性能の数字が偶然合っても、この内部量が外れているモデルは信用できない、というのが本論文の動機である。

## 手法のあらまし

流れは三段である。まず対象カーネルへ軽い計装を入れ、ワープごとに固定長のバッファへイベントを原子操作なしで記録する。次にオフラインで、重複を取り除いて生産者と2つの消費者という3本の論理スレッドのイベント列へ直し、TMA発行や行列積発行や待機の各イベントを、段の獲得と解放やバリア到着を含むシミュレータ命令へ翻訳する。ソフトマックス等の非行列積処理は、演算量から見積もったサイクル数の泡として埋め込む。最後にサイクル駆動の核が、スケジューラ、発行段、TMAエンジン、テンソルコアエンジン、共有の非同期イベントキューを回し、L2とDRAMの階層を通して遅延を積み上げる。大きな設計空間を速く走査する用途には、解析モデルのSimFA-pythonが速い経路として併設される。

## 手法

### 1. ワープグループを論理スレッドとする非同期実行モデル — 役割分担のパイプラインをそのまま表す

この機構が観測するのは、トレース上の命令列と非同期操作の完了イベントである。保持する状態は、物理スレッドの占有する共有メモリとレジスタの資源、待ち行列に入ったスレッド、未完了の非同期グループである。処理はサイクルごとに、準備できた論理スレッドを選び、完了イベントで待機スレッドを起こし、TMAとテンソルコアの各エンジンを進め、発行可能な命令を引き渡すことである。待機条件が満たされなければプログラムカウンタを巻き戻してスレッドを止め、対応する待ちリストへ登録する。非行列積の計算は泡として消費サイクルだけを数える。これにより減るボトルネックは、非同期の重なりを潰してしまう粗いモデル化であり、生産者と消費者の重なりや、2つの消費者が行列積とソフトマックスを交互に担うピンポン方式の効果が時間軸上に現れる。追加費用はモデルの複雑さであり、非同期バリアのモデル化が不完全だと重なりを取りこぼして推定が外れることが、論文自身の除去実験でも示される。誤った場合の挙動として、待ちの扱いを誤るとデッドロックではなく静かな誤差として現れるため、実機との照合が前提になる設計である。

### 2. TMAエンジンの較正 — セットアップ、分割L2、追跡資源の三点を実機へ合わせる

この機構が観測するのは、テンソル記述子を持つ転送と持たない一括転送の要求列である。保持する状態は、記述子キャッシュ、要求キュー、未完了要求を追跡する資源の空きである。処理は、要求パスを二つに分けることから始まる。記述子を使う転送だけが記述子キャッシュとセットアップ段を通り、一括転送は迂回する。そのためセットアップの上乗せは、全転送共通の起動分40サイクルと、記述子転送だけに課す130サイクルへ分解して課す。HopperのL2が二つの分割からなる点は、遠い側のスライスで解決した要求に対し、確率的に近い側へ影のラインを差し込む遠隔コピーの代理モデルで表す。追跡資源の数は公開されていないため192から384まで走査し、全体誤差が最小になる256を選ぶ。これにより減るボトルネックは、転送遅延の系統的なずれであり、作業集合10点での遅延照合は全体MAPE 5.45パーセント、分割遷移域を除くと3.65パーセントまで下がる。追加費用は較正の手間であり、代理モデルの確率はH800の遅延曲線へ一度合わせて固定される。失敗条件は、追跡資源を192へ下げるとバースト転送が絞られてMAPE 24.85パーセント、384へ上げると背圧が消えて21.06パーセントと、どちらへ外しても大きく崩れる点に現れ、有限の追跡資源そのものが帯域の律速であることが分かる。

### 3. FlashAttention-3専用前段 — 計装イベントを段とバリアの命令列へ翻訳する

この機構が観測するのは、カーネル実行中にワープの先頭レーンだけが記録する16バイト整列のイベント列である。保持する状態は、リングバッファの段番号と、タイル番号から実アドレスを復元するためのテンソル基底情報である。処理は、ワープ単位の記録をワープグループ単位へ重複除去し、Kタイルの転送発行を段の獲得と転送命令の組へ、行列積の発行を同じグループ識別子を持つ8本の非同期行列積と確定命令へ、待機イベントをグループ待機へ、それぞれ翻訳することである。段の解放は、Kタイルについては最初の行列積の完了直後、Vタイルについては全完了後に差し込まれる。ピンポン方式はバリア到着とバリア待機の挿入で再現する。ソフトマックス側は、行最大、指数、行和、精度変換、再スケーリングの演算量を数えて合計988サイクルの泡とする。これにより減るボトルネックは、手書きトレースでは再現できない実カーネルの細かい依存関係であり、計装は実行を乱さないよう記録だけに徹し解釈はオフラインへ寄せている。追加費用はバッファ溢れを避ける容量確保と翻訳規則の保守であり、失敗条件はタイル形状が変わると泡の見積もりと翻訳前提を合わせ直す必要がある点である。

### 4. 解析モデルSimFA-python — 理想と現実の二つの局面でDRAMトラフィックを切り替える

この機構が観測するのは、バッチ、系列長、ヘッド構成、タイル寸法、SM数と同時実行上限といった構成パラメータである。保持する状態は持たず、閉じた式で計算量、L2トラフィック、DRAMトラフィックを出す。処理の肝は局面の切替えであり、単一のKVヘッドが有効L2へ収まる間は、QとKとVを一度読みOを一度書く理想式を使い、収まらなくなると、同時実行容量から決まる波の数だけKVの再取得が掛かる現実式へ切り替える。演算強度はタイル寸法でほぼ決まり、L2対DRAMのトラフィック比は同時実行容量の程度になるため、将来のハードウェアではDRAM帯域よりL2帯域とSRAM容量が先に律速になる、という読みもこの式から導かれる。これにより減るボトルネックは、サイクル精度模擬が遅すぎて回らない大規模な設計空間探索であり、速い経路としてcuTileカーネルでも検証される。失敗条件は、波の内部のタイミングずれまで式では捉えきれず、48Kから64K級では実測が現実式の予測をさらに上振れる点であり、解析モデルはシミュレータの代替ではなく補完と位置付けられる。

## 評価

結論は、非同期機能を正面からモデル化すれば、学術シミュレータでもFlashAttention-3級のパイプラインを実機の数パーセントで再現でき、しかも誤差の主因が特定の省略にあることを除去実験で示せる、というものである。端から端までの照合では、Llama 3の3規模と系列長5水準の組合せでMAPE 5.7パーセント、最大誤差12.7パーセントであり、模擬から描いたパイプライン図では生産者と2消費者の重なりとピンポンの交代が確認できる。除去実験の読み方が重要で、L2要求の合体を取り除くとMAPEは16.8パーセント、キャッシュスライスのハッシュを単純化すると64.3パーセント、TMAのアドレス重複除去を外すと511.4パーセントへ跳ねる。つまり精度を決めているのは細部の積み重ねではなく、合体、分散、重複除去という三つの構造であり、将来のシミュレータ実装が先に押さえるべき点が順位付けされる。

解析モデル側では、最終レベルキャッシュのトラフィック予測がGB10の実測の伸びと一致し、DRAM側では16Kから24K級では理想局面の予測が実測に近く、32Kから48Kを超えると再取得が支配的になって現実局面へ移ることが確認される。比較対象のGenZは、短系列では再利用と合体が効いて実測よりやや過大に、長系列では再取得を見落として大きく過小になるという逆向きの偏りを示し、性能の見かけが合うことと内部量が合うことは別だという論文の主張が具体化される。未評価の範囲として、対象は主にHopperとFlashAttention-3であり、GEMMなど他演算子とBlackwellへの本格拡張は今後の課題とされる。ただし演算子非依存の前段によるGEMM検証が併記され、核の一般性への手掛かりは示されている。

## 既存研究との差

Accel-Simに代表される既存のサイクル精度シミュレータとの差は、Hopperの非同期機能、すなわちTMA、WGMMA、非同期バリア、ワープ特殊化を、ワープグループを論理スレッドとする抽象で正面から扱う点にある。多GPUを扱う別系統のシミュレータとは狙う軸が違う。解析モデルとの差は、理想キャッシュの一本式ではなく、容量条件で理想局面と現実局面を切り替え、波単位の再取得を掛ける点であり、既存モデルが長系列で過小評価する機構を式の形で示したことが分析面の貢献である。

## 限界・実装状況

限界は、対象が主にHopperとFlashAttention-3へ寄っていること、TMA内部のアウトオブオーダー発行や形状依存の配送戦略など未モデル化の要素が残余誤差として残ること、解析モデルが非常に長い系列では実測を下振れすること、較正がH800の実測曲線へ一度合わせたパラメータに依存することである。実装状況は、シミュレータと解析モデルからなる研究実装であり、公式リポジトリのURLは論文中に示されていないため、コードは明示的に公開先なしとして記録する。

## 一般的な実装上の含意

非同期ハードウェアのシミュレータでは、演算器の細部よりも、要求の合体、キャッシュスライスへの分散、アドレス生成での重複除去といったトラフィック側の構造が先に精度を決める。また解析モデルは、最終性能が実測と合うことではなく、内部トラフィックが局面ごとに合うことで検証すべきであり、容量を超える局面を式に持たないモデルは長系列の設計探索で誤った順位付けをする。
