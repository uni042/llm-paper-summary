# Selective ROM Weight Storage for Responsive LLM Control on Edge Robots

> MLPの下射影など選択した固定重みだけをバンク型ROMへ置き専用路で供給し、出力スライスでのプリエンプションと単一パス意思決定を組み合わせ、シミュレーションでQwen3-8Bの計画遅延を1.52倍高速化しタスク応答P99を約227倍下げた、エッジロボット向けLLM推論のメモリとスケジューリングの協調設計。

## 概要

エッジロボット上で言語モデルを計画器として使うと、クラウドへ逃がす場合の通信遅延を避けられる代わりに、オンチップの制約がそのまま効いてくる。第1にメモリ容量で載せられるモデルが限られ、小さいモデルではタスク完了率が大きく下がる。著者らの測定では Qwen3 系プランナの完了率は0.6Bで32%、1.7Bで41%、4Bで63%、8Bで86%（INT4）から90%（BF16）と、規模が品質へ直結する。第2にデコードは生成トークンごとに重み全体を読み直すため、外部メモリの帯域を活性値や KVキャッシュと取り合う。第3に、推論カーネルが長く計算資源を占有すると周期的なモータ制御が締切を外す。測定では非プリエンプティブな実行は周期制御の締切の74%を外した。

全重みをROMへ置く単純解は面積で破綻する。8Bモデルを全てROM化すると INT4 でも2,000平方ミリ超、BF16 では5,000平方ミリ超と見積もられ、単一レチクルの参照上限858平方ミリへ遠く及ばない。本論文の答えは選択配置である。大きく、プリフィルとデコードの両方で使われ、SRAMへ収まらない MLP の下射影行列29個だけをバンク型ROMへ置き（容量予算2.74GiB）、残りの重みと可変状態は LPDDR へ残す。ROMからは専用路で重みを供給し、スケジューリングは出力スライス境界でのみ割り込む形へ変え、ロボットのフェーズ選択は逐次トークン生成ではなく候補を1回の前向き計算で採点する形へ変える。代表結果として、プリフィルと7回のデコードの合計遅延は34.17%短縮され、タスク応答の P99 は約227.27分の1になり、把持と運搬の試行100件を全て完了した。

## 問題設定

ここで余っているのは LPDDR の帯域のうち重み再読込に使われる分と、長いカーネルに占有される計算アレイの時間であり、足りないのは面積予算の中で確保できる高速な重み供給である。デコードはトークンごとに重みを一巡するため、重み供給が律速になりやすい一方、プリフィルはプロンプトのトークン数分だけ重みの読みを償却できるため、同じ対策でも効き方が違う。さらに制御側の問題は平均遅延ではなく締切で、推論が速くなってもカーネルの途中で制御へ譲れなければ応答の裾は縮まらない。動機づけ測定でも、ROM化だけでスケジューリングを変えない構成は締切ミスが72%に残り、速いメモリと割り込み可能性は別々に必要であることが示されている。つまり本論文の問題は「重みをどこへ置くか」「いつ譲るか」「意思決定を何回で済ませるか」の3問を同時に解くことであり、どれか1つだけでは制御品質へ届かない。

## 手法のあらまし

設計は3層からなる。メモリ層では、選んだ固定重みを64バンクのROMへ置き、重み語の重複をまとめて読み、クレジットで先行発行を抑えながら、専用のステージングを経て通常のシストリックアレイへ直接供給する。LPDDRとSRAMは活性値、残りの重み、動的な KVキャッシュを担当する。スケジューリング層では、行列積を出力スライスへ分割し、制御、デコード、意思決定、プリフィルの順の段階優先度と締切順で実行し、高優先度の到着時にはスライス境界で譲る。意思決定層では、双方向トランスフォーマ型の Jev が指示、ロボット状態、全候補フェーズを1つの系列として読み、候補ごとに付けた印の位置でスコアを取り、1回の前向き計算でフェーズを選ぶ。選択は幾何ガードで検証され、保留中や検証失敗時は PPO 制御器がフォールバックとして動き続ける。

## 手法

### 1. 選択的ROM配置と専用供給路 — 重み転送をLPDDRから切り離す

この機構が観測するのは重みテンソルの大きさと使われ方であり、配置の対象は全層の MLP 下射影行列である。選定理由は、大きくて SRAM へ収まらず、プリフィルとデコードの両方で実行され、層間で読み方が均一で、量子化グループが1つのメモリ空間内に収まるためと説明される。小さいテンソルは SRAM の先読みで隠れるためROMへ置く意味が薄い。供給側では、アドレスをバンクへ写す際にライン内の XOR 写像で2の冪のストライドが特定バンクへ集中する問題を散らし、同一語への要求は1回の読みへまとめて各レーンへ配る。ROMの定常スループットはバンク数、発行幅、戻り幅、在-flight数と遅延で決まる上限式で表され、設計はこの上限がアレイの需要へ届くよう諸元を合わせる。効く理由は、デコードで繰り返される重み読みが LPDDR のキューと SRAM のリフィルポートを経由しなくなるため、その分の競合が活性値や KVキャッシュ側から消えることにある。追加費用はROM面積そのものであり、置けるのは固定重みだけなので、適応や更新が要る重みは対象にできない。

### 2. クレジット型の流れ制御 — 速いROMと遅いLPDDRをロックステップで合わせる

ROMは決定的に速く、LPDDRは遅延が揺れるため、そのまま先行発行を続けるとステージングが溢れる。この機構は二重閾値のクレジットで発行を管理し、各アレイ拍について必要な語の分だけステージングの枠を原子的に予約してから読みを発行し、クレジットはROMの語、SRAMのオペランド、形式変換がそろってアレイが進んだ時点でだけ解放する。入力は先行窓とステージングの空きであり、出力は溢れない範囲での最大の先行供給である。失敗条件は在-flight枠やステージングが不足する構成で、感度評価では容量不足の点で0.72%の悪化が報告されており、供給路を太くしても受け側の枠がなければ利得が出ないことが示されている。

### 3. 出力スライスプリエンプションと段階優先スケジューリング — 締切を守れる割り込み方

長い行列積の途中で任意に止めると、蓄積途中の状態を退避する費用が大きい。この機構は行列積を完全な出力フォールドの集まりであるスライスへ分割し、割り込みをスライス境界だけに制限する。境界では蓄積結果がSRAMへ書き戻され、在-flightのROM要求も自然にゼロへ戻るため、文脈保存の転送が要らない。スケジューラは制御を最優先とし、次にデコード、意思決定、プリフィルの順に段階優先度を与え、同段階内は締切の早い順に処理する。小さい制御カーネルと単一パスの意思決定は原子的に実行し、長いプリフィルとデコードだけが境界で譲る。効く理由は、割り込みの単位を「状態が自然に閉じる場所」へ合わせたため、締切応答性と文脈切替費用の両立ができた点にある。代償は、割り込みの粒度がスライス幅で決まるため、応答の下限はスライス1つ分の実行時間より細かくはならないことである。

### 4. 単一パス意思決定と幾何ガード — 逐次生成を制御ループから外す

ロボット動作をトークン列として逐次生成すると、生成ステップ数だけ意思決定が遅れ、その間に物理状態が進んで判断が古くなる。動機づけ測定では遅延が10倍で完了率が88%から52%へ、20倍で28%へ落ちた。この機構は Jev が候補フェーズ全体を1回の前向き計算で採点し、最もスコアの高いフェーズを選ぶことで、日常的な選択から逐次生成を取り除く。選ばれたフェーズはグリッパと対象物の距離や把持状態を見る幾何ガードで毎制御ステップ検証され、信頼度に応じて速度指令を縮小し、衝突や保留時は保守的な動作へ落とす。保留中も PPO 制御器が動き続けるため、計画の遅れが制御の停止にはならない。失敗条件は候補フェーズの集合に正しい動作が含まれない場合と、採点の誤りがガードでも検出できない場合で、この実行形式は自由な新規計画の生成能力と引き換えに速さを得ている。

### 5. データと制御の流れ

制御ループでは、状態と候補フェーズが Jev へ入り1回で選択が出て、ガードを通ってモータ指令になり、並行して言語モデルのプリフィルとデコードがROMとLPDDRの両方から重み供給を受けて計画を更新し、高優先度の制御要求が来れば次のスライス境界でアレイを譲る。重み供給、譲り方、意思決定形式の3つがそろって初めて「速く、締切を守り、古くならない判断」が成立する、というのが全体の主張である。

| 構成要素 | 入力・観測 | 具体的な動作 | 改善対象 | 主なトレードオフ |
|---|---|---|---|---|
| 選択的ROM配置 | 重みの大きさと使用頻度 | 下射影行列をROMへ置き専用路で供給 | デコードの重み転送競合 | 面積を消費し固定重みしか置けない |
| クレジット制御 | ステージングの空きと先行窓 | 枠を予約してからROM読みを発行 | 供給の溢れと停滞 | 枠不足では利得が出ない |
| スライスプリエンプション | 優先度と締切 | 出力スライス境界でのみ譲る | 制御の締切ミス | 応答粒度はスライス幅に制限される |
| 単一パス意思決定 | 指示、状態、全候補フェーズ | 1回の前向き計算で候補を採点 | 意思決定の遅れと陳腐化 | 候補外の新規計画は作れない |

## 評価

### まず見るところ

- **結論:** ROM配置、スケジューリング、意思決定形式は互いに補完的で、3つを合わせた構成だけが遅延短縮と締切遵守を同時に達成した。メモリだけ速くしても締切は守れないことが分離測定で示されている。
- **速度・効率:** プリフィルと7デコードの合計は34.17%短縮（1.52倍）。内訳はROM配置がデコードを約22%短縮し、スケジューリングがさらにプリフィル19.44%、デコード約18%を短縮する形で積み上がる。
- **品質:** 統合システムで把持と運搬の試行100件を全て完了した。ただしこれは意思決定とガードを含む統合系の結果であり、推論基盤単体の品質指標ではない。
- **メモリ・入出力:** ROMは64バンクでピーク512GB/s、LPDDRはピーク102.40GB/sという想定で、選択した重み2.74GiB分がLPDDR経路から外れる。
- **評価の強さ／注意点:** 全てサイクルシミュレーションであり実チップ測定ではない。面積も投影値で、物理実装と1GHzでのタイミング収束は未検証と著者ら自身が明記している。

この評価で最も重要な読み方は、応答時間の改善（P99で約227.27分の1）と推論の高速化（1.52倍）の桁がまったく違う理由である。P99の短縮は主にスケジューリングの効果で、締切を外していた原因が「推論が遅いこと」ではなく「実行中のカーネルが制御を待たせていたこと」にあったため、割り込めるようにした途端に裾が消えた。対照的に平均的な計画遅延の短縮はROM配置と供給の改善によるもので、デコードで35.98%から36.04%、プリフィルで21.52%という内訳になっている。デコードのほうが大きく速くなるのは、プリフィルでは重み読みが多数トークンの計算で償却されるのに対し、デコードではトークンごとに重みを一巡するため、重み供給の競合がそのまま遅延になるからである。この非対称は分離測定でも裏づけられ、ROM配置だけの効果はデコードで21.96%から22.01%、プリフィルでは2.58%にとどまる。つまりROM配置は「全部を速くする」部品ではなく、「デコードの重み読みを狙って速くする」部品として読むべきである。

スケジューリングの上乗せ効果も分離されている。ROM配置済みの構成へ段階優先と先行供給を加えると、プリフィルが19.44%、デコードが17.97%から17.99%さらに短縮される。供給路が速くても、実行順と割り込み点が決まらなければアレイの空転は消えないという主張に対応する数値である。逆に、動機づけ測定でROMだけを入れた構成の締切ミスが72%に残ったことは、制御用途では平均遅延の改善と締切遵守が別の指標であり、片方の報告だけでは不十分であることを示している。本論文が両方を分けて測っている点は評価の強みである。

感度と一般性の結果は、利得の条件を教えてくれる。供給側の感度では、細いROM源の後ろのリンクを太くしても利得は伸びず、在-flightやステージングの枠が不足すると0.72%の悪化すら出る。追加モデルでは、Mistral-7B、Qwen2.5-7B、Phi-3.5-mini の3モデルでデコード遅延が36.18%から51.82%減り主実験の傾向が再現したが、27Bモデルでは初回デコードの短縮が15.54%へ縮んだ。固定のROM予算がカバーする重みの割合がモデル規模とともに下がるためで、この方式の利得は「ROM予算が重み全体のどれだけを覆えるか」に比例して薄まる。面積の見積もりは、ROMマクロ面積の40%削減などを仮定した投影で525.80平方ミリ、標準見積もり比で38.47%減となり参照上限へ収まる計算だが、仮定依存の数値であり実測ではない。

未評価の軸も多い。消費電力は報告されていない。実機ロボットでの閉ループ評価はなく、タスク評価は ManiSkill3 のシミュレーション内である。モデルの出力品質そのもの（計画の正確さの言語モデル指標としての測定）は完了率を通してのみ見えており、ROM配置が重みを変えないため品質は不変という前提に立っている。複数ロボットや複数テナントでの共有、熱や製造ばらつきの影響も未評価である。したがって本論文の主張は「シミュレーション上で、想定した諸元の範囲では」という留保付きで読む必要があり、特に227倍という P99 の数字は締切ミスの構造が変わったことの表現であって、実機で同じ倍率が出る証拠ではない。

## 既存研究との差

先行のエッジ推論アクセラレータは重みの量子化や PIM などで転送量そのものを減らし、先行のNPUスケジューラは締切のないキャッシュ管理や高コストな途中状態退避を伴うプリエンプションを扱ってきた。具身AI向けの協調設計も、重い推論を遠隔へ逃がす構成が中心だった。本論文の差は、重みを変えずに置き場所を分ける選択配置、状態退避の要らないスライス境界プリエンプション、逐次生成を外す単一パス意思決定を、共有NPU上の1つの設計として束ね、分離測定で各部品の担当範囲を示した点にある。

## 限界・実装状況

- ハードウェア依存条件: 全てサイクルシミュレーションの結果であり、実チップでの物理実装、配線、熱、タイミング収束は未検証である。面積は仮定を置いた投影値である。
- モデル／ワークロード依存条件: ROMへ置けるのは固定重みだけで、モデルの更新や適応が頻繁な用途には向かない。利得はROM予算の被覆率に依存し、27Bでは初回デコードの短縮が15.54%まで縮んだ。
- 実装状況: シミュレータ上の設計提案であり、実機ロボットでの閉ループ実証はない。コード公開の記載は本文にない。
- 品質リスク: 意思決定を候補フェーズの採点へ置き換えるため、候補集合の外にある新規計画は生成できない。ガードで検出できない採点誤りはそのまま動作へ出る。

## 一般的な実装上の含意

リアルタイム系と推論を同じ計算資源へ載せる場合、平均遅延の改善と締切遵守は別の設計問題であり、割り込みの単位を「状態が自然に閉じる境界」へ合わせると文脈保存費用なしに応答性を買える。また、メモリ階層の高速化は、それを使う実行順と受け側のバッファ枠がそろって初めて遅延へ変換される。供給路だけを太くする設計は、在-flight枠やステージング不足で容易に頭打ちになる。
