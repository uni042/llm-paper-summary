# Improving the End-to-End Efficiency of Offline Inference for Multi-LLM Applications Based on Sampling and Simulation

## 概要
SamuLLMは、1つのアプリケーションが複数のLLMを使うオフライン推論を対象にする。単一LLMの最適化と異なり、GPU群へ複数モデルを同時に置くと、モデルごとのテンソル並列・パイプライン並列等の選択と、同時実行モデル集合が互いに干渉する。全モデルを最大並列度で走らせればよいわけではなく、GPU占有と通信の組合せによってアプリケーション全体の完了時刻が変わる。

## 問題設定
最適化変数は主に二つある。第一に、ある時点でどのLLM群を同時実行するか。第二に、各LLMへどの並列化戦略を割り当てるかである。この共同問題はNP困難であり、さらに生成出力長が実行前には未知なので、候補配置の完了時間を正確に比較できない。平均出力長だけを使うとtailやbatch縮退を再現できず、実測で全候補を試すと計画コストが高すぎる。

## 手法
### sampling-then-simulation
SamuLLMは大規模な事前データからモデル・ワークロードに対応する出力長の経験累積分布を作る。計画時にはこの分布から要求ごとの出力長をサンプリングし、その仮想長を使ってLLM推論の反復進行をシミュレーションする。各iterationで残存要求数が変わるため、固定平均値よりdecode batchの縮みを反映できる。反復遅延を積み上げて、候補の並列構成に対する総実行時間を見積もる。

### 貪欲スケジューリング
推定時間をコストとして、限られたGPUへどのモデルを同時配置するか、各モデルへどの並列戦略を与えるかを貪欲に決める。探索空間を総当たりせず、追加配置が全体完了時間へ与える改善を比較しながら構成を選ぶ。

### planningとrunningの二段階
計画段階で得た構成を固定して最後まで走らせるのではない。実行段階では実際に観測された進捗・完了時刻を使い、出力長予測の誤差やモデル間の進行差に応じてスケジュールを動的に調整する。これにより、サンプリングが外れた場合でも初期計画の誤差を後半へ持ち越しにくい。

## 評価条件
| 項目 | 内容 |
|---|---|
| 環境 | 単一ノード・複数GPU |
| 対象 | 複数LLMから成るオフライン推論アプリケーション |
| ワークロード | 3種類のアプリケーション＋混合アプリケーション |
| 予測 | 経験累積分布から出力長をサンプリングし推論をシミュレーション |
| 最適化 | 同時実行モデル集合＋モデルごとの並列化戦略 |
| 指標 | アプリケーション全体のend-to-end完了時間 |

## 主要結果
3つのアプリケーションと混合アプリケーションに対し、SamuLLMは比較方式比で1.0〜2.4倍のend-to-end高速化を示した。利得は単一カーネルの高速化ではなく、複数モデルのGPU占有期間を重ねつつ、通信・並列度の悪い組合せを避けることで得られる。出力長をサンプリングしてiteration単位にシミュレーションするため、モデルごとの平均処理時間だけで計画する方式より、decode batchが時間とともに縮む挙動を扱える。

## 既存研究との差
単一LLMサービングのrequest schedulerは、同じモデル内の要求順序やKV容量を主に扱う。SamuLLMはモデル自体が複数あり、モデルごとに並列化方式も変えられるオフラインDAG的ワークロードを対象とする。また解析式だけの性能モデルではなく、未知出力長を確率的に生成した上で推論iterationを模擬する点が特徴である。

## 限界
経験分布が本番入力とずれると出力長サンプルもずれ、初期計画の精度が落ちる。実行時再調整はこの誤差を緩和するが、モデル再配置や並列構成変更には実コストがある。評価は単一ノード複数GPUであり、ノード間ネットワークを跨ぐ配置やオンラインSLOを持つ対話サービングへ結果を直接一般化できない。
