# TruncFormer: Private LLM Inference Using Only Truncations

> 非線形演算を加算・乗算・切り捨ての列へ展開し、切り捨てを溢れが起きる場所だけへ静的に置くことで、任意の言語モデルへ使えるプライベート推論の変換枠組み。

## 概要

プライベート推論は、利用者のデータをモデル所有者へ明かさず、モデル所有者の重みも利用者へ明かさずに推論を行う秘密計算の応用である。計算は固定サイズの有限体の中で行われ、体の中で完結する加算と乗算は秘密分散などで比較的安く実行できる。一方、除算、指数関数、ReLU、ソフトマックスのような演算は体の中では表せず、ガーブル回路や忘却転送のような通信の重い仕組みが要るため、遅延の支配因になる。

先行研究は非線形ごとに近似や専用プロトコルを作ってきたが、言語モデルのアーキテクチャが変わるたびに新しい非線形が現れ、追いかけが終わらない。本論文のTruncFormerは方向を変え、非線形が微分可能であることを使って、ニュートン法やテイラー展開のような反復近似で全ての演算を加算・乗算・切り捨ての列へ書き下す。切り捨ては、固定小数点表現で乗算結果が体の幅を超えないよう下位ビットを落とす演算で、これ自体は体外演算だが、種類は一つにそろう。さらに、乗算のたびに切り捨てる従来方式を改め、溢れが起き得る場所だけへ静的に切り捨てを配置する。

**代表結果:** Llama-7BとGemma-2Bの広範な課題で、先行する最良方式PUMAと精度はほぼ同等であり、切り捨てにかかる時間を基準にした高速化は課題により1.02倍から1.92倍、最も大きいWikiText-2で1.92倍（Llama-7B）を示した。前提として、切り捨てがプライベート推論全体の遅延の90から99パーセントを占めることが課題横断で測定されており、切り捨ての削減が全体へほぼそのまま効く構造である。

## 問題設定

資源の観点では、ボトルネックは通信を伴う体外演算の回数である。加算と乗算は体の中で処理できるが、固定小数点の乗算は結果のビット幅が入力同士の和まで広がるため、体の幅を超える前に切り捨てが要る。従来の実装は安全側に倒し、乗算のたびに切り捨てを入れるため、行列積のような乗算の塊がそのまま切り捨ての塊になる。測定では切り捨てが全体時間の90から99パーセントを占め、非線形の近似そのものより、切り捨ての回数が遅延を決めていることが分かる。

もう一つの問題は一般性である。ソフトマックス専用、GeLU専用という最適化は、その演算を持たない新しいアーキテクチャには使えない。本論文の着眼点は、最適化の単位を個別の非線形から、近似の展開と切り捨ての配置という全モデル共通の構造へ移すことである。

## 手法のあらまし

変換は次の順で進む。まず対象モデルの各非線形演算を、微分可能性を使った反復近似へ置き換える。指数関数、逆数、逆平方根、ソフトマックス、層正規化、GeLUやSiLUなどが対象で、近似は加算と乗算だけからなる列になる。次に固定小数点表現と体のビット幅を与え、モデルの計算グラフを静的にたどって、各乗算の結果が取り得るビット幅を伝播させ、溢れが起き得る場所だけに切り捨てを挿入する。残りの乗算は切り捨てなしで連続させる。こうして得た計算は、加算・乗算と静的に決まった切り捨てだけで構成され、任意のプライベート推論プロトコルと組み合わせられる。論文はDelphiプロトコルを前提に議論し、評価はコストを模す平文ライブラリで精度と相対遅延を測る。

## 手法

### 1. 非線形の反復近似への展開 — 体外演算の種類を切り捨て一つにそろえる

この機構が観測するのは、モデル内の各非線形演算とその入出力範囲である。保持する状態は近似の反復回数や初期値などの近似設定であり、処理は、指数や逆数などをニュートン法や級数展開で加算と乗算の列へ置き換え、CrypTen系の既存近似を現在の公開モデルで安定するよう直すことである。これにより減るボトルネックは、非線形ごとに専用回路が要る状態であり、体外演算は切り捨てだけになるため、プロトコル側の最適化対象が一種類に絞れる。追加費用は近似の反復に伴う乗算の増加であり、反復を増やすほど精度は上がるが体内の計算も増える。誤った場合の挙動として、入力範囲の端では近似の誤差が広がり、ビット精度が不足する条件ではパープレキシティが急に悪化することが感度分析で示される。近似である以上、元の計算と完全には一致しない点が、無損失な方式との違いである。

### 2. 静的な切り捨て配置 — 溢れる場所だけを切り捨てる

この機構が観測するのは、計算グラフ上の各値のビット幅と、与えられた体のサイズである。保持する状態はグラフを伝播させたビット幅の情報であり、処理は、乗算結果の幅が体の幅を超え得る箇所だけに切り捨てを挿入し、超えない箇所では切り捨てを省くことである。従来方式が乗算ごとに切り捨てていたのに対し、加算と乗算の分離と静的解析で回数を大幅に減らす。これにより減るボトルネックは全体遅延の90から99パーセントを占める切り捨ての回数そのものである。追加費用は変換時の静的解析のみで、実行時の判断は要らない。失敗条件は、ビット幅の見積もりを誤ると溢れで値が壊れることであり、安全側に倒しすぎると切り捨てが増えて利得が消えるため、見積もりの精度が方式の成否を決める。入力の実分布が想定範囲を超える場合も、静的に決めた配置では守れない境界になる。

### 3. 平文エミュレーションによる検証 — 実プロトコルの前に費用と精度を測る

この機構は手法そのものではなく検証の仕組みだが、本論文の主張の読み方を決めるため分けて記す。観測するのは、変換後モデルを平文で実行したときの課題精度と、切り捨て回数に実測の単価を掛けて見積もる相対遅延である。切り捨て単体の遅延は、体のサイズ64ビットと128ビットでガーブル回路の生成側と評価側の時間を実測し、評価側の時間をオンライン遅延の見積もりに使う。処理は課題ごとに単体テストの形で積み上げることであり、これにより大規模な秘密計算を実際に走らせずに比較ができる。限界は、通信や並行実行の実挙動までは模せないため、絶対遅延ではなくPUMAとの相対比較として読むべき点である。

| 構成要素 | 入力・観測 | 具体的な動作 | 改善対象 | 主なトレードオフ |
|---|---|---|---|---|
| 反復近似 | 各非線形と入力範囲 | 加算と乗算の列へ展開 | 非線形ごとの専用回路 | 反復回数と精度の交換 |
| 静的切り捨て配置 | ビット幅と体のサイズ | 溢れ得る箇所だけ切り捨てる | 遅延の9割超を占める切り捨て回数 | 見積もり誤りで溢れか無駄のどちらかになる |
| エミュレーション検証 | 変換後モデルと切り捨て実測単価 | 平文で精度と相対遅延を測る | 検証費用 | 実プロトコルの絶対遅延ではない |

## 評価

結論は、精度をPUMAと同等に保ったまま、切り捨て時間で測った遅延が課題により最大で約2倍改善し、改善幅は課題の構造で説明できる、というものである。入力が長く出力が1トークンの課題ではソフトマックスの切り捨ての 割合が大きく、WikiText-2で1.92倍、MMLUで1.28倍と大きな利得が出る。逆に生成が長い課題や行列積の切り捨てが支配的な条件では利得が1.02倍程度まで縮む。つまり本方式の利得は一様ではなく、どの演算の切り捨てが支配的かに依存する。精度面では、多くの課題で元モデルとの差は小さく、例外としてGemma-2BのWikiText-2パープレキシティが1550.44から1886.23へ悪化する外れ値が報告され、著者らもモデル固有の事情によるものと断っている。ビット精度の感度では、固定小数点の入力サイズが小さい側で精度が崖状に落ちることが示され、表現幅の選択が実用条件になる。

## 既存研究との差

先行方式は、ソフトマックスやGeLUなど個別の非線形へ近似や専用プロトコルを当て、アーキテクチャが変わるたびに追いかける構造だった。本論文は、微分可能な非線形は全て同じ展開で扱えるという一般化と、切り捨ては乗算ごとではなく溢れの解析で置くという、従来あまり注目されなかった切り捨て自体の最適化を組み合わせた。プロトコルを新しく作るのではなく既存プロトコルと併用できる変換として設計されている点も異なる。

## 限界・実装状況

限界は、評価が平文エミュレーションに基づき実プロトコルのエンドツーエンド遅延を測っていないこと、近似ゆえの精度劣化が条件により出ること、Gemma-2Bのパープレキシティ悪化のようなモデル固有の外れ値があること、ビット幅の静的見積もりが入力分布の想定に依存することである。実装状況は、コードを公開すると記され匿名リポジトリが示される。近似の反復回数やビット精度などの設定は本文と付録に記される。

## 一般的な実装上の含意

秘密計算のような高価な実行環境では、演算の種類ごとの最適化より先に、時間の占有率を測って支配的な演算を特定することが効く。本論文では花形の非線形近似ではなく、脇役だった切り捨ての回数が支配因だった。また、安全のために全箇所へ入れた処理は、静的解析で必要箇所を証明できれば大きく減らせるという、一般のシステム最適化にも通じる原則を示している。
