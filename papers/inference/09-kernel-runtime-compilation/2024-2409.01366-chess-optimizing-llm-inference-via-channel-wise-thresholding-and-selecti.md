# CHESS: Optimizing LLM Inference via Channel-Wise Thresholding and Selective Sparsification

## 概要
活性疎化は小さい中間値をゼロにし、後続行列積で対応する演算を省く。しかしLLMのFFNではチャネルごとに活性分布と後段重みへの影響が異なり、全チャネルへ同じ閾値を置くと「値は小さいが出力へ重要」な成分まで落とす。注意層もQ/K/V/O投影を同じように疎化すると品質感度が異なる。

CHESSは疎化を単なる活性値の統計ではなく、後続層出力の変化を最小化する問題として定式化する。FFNにはチャネル別閾値（channel-wise thresholding）を、注意には選択的疎化（selective sparsification）を使い、最後に疎活性を直接処理するカーネルを実装する。

Llama-2-7B/13B/70B、Llama-3-8B、Mistral-7Bと8下流taskで評価し、標準設定で最大1.27倍、より高い疎化率では最大1.72倍の推論高速化を示す。

## 問題設定
既存の閾値型活性疎化は「絶対値が小さい活性は重要でない」と仮定する。しかしFFNのSwiGLU/GeGLUではdown projectionへ入る値がup側とgate側の積で決まり、同じgate活性でもup側の典型振幅が大きいchannelほど削除影響が大きい。

注意投影も同様に一律ではない。特にgrouped-query attentionではK/VとQ/Oで形状・再利用が異なるため、全投影を同じ率で疎化すると削減演算量に対する品質損失が悪化し得る。

## 手法
### 出力誤差に基づくFFN重要度
FFNで削除するindex集合をSとすると、CHESSは後段出力誤差へ効く項を近似し、各要素の重要度を |a_up,i × a_gate,i| と捉える。推論ごとに両方を完全評価してから削ると節約にならないため、up側の絶対値はcalibration sampleから得たチャネル期待値 E[|a_up,i|] で置き換える。

推論時は E[|a_up,i|] × |a_gate,i| に対応するチャネル別閾値を使う。チャネルごとの分布差を事前統計へ吸収するため、単一global thresholdより同じ疎化率で出力誤差を小さくする。

### チャネル別閾値
各channelの活性分布の分位点と重要度統計から固有閾値t_iを作る。目標疎化率kに対して、channelごとに「どこまで小さい値を捨てるか」を変えるため、重要channelを過度に削らず、冗長channelを強く削れる。

これは重みを再学習する方式ではなく、少量のcalibrationで統計を得た後に元モデルへ適用する。追加parameterより閾値tableが主な状態になる。

### 注意層の選択的疎化
注意では重み行列のrow normと入力活性から削除影響を解析し、すべての投影を疎化しない。実験に基づきQ（問い合わせ）とO（出力）投影へ閾値疎化を適用し、K/V投影は保持する。

これにより注意計算でも演算を減らしつつ、K/Vを壊すことで全後続tokenへ誤差が蓄積するリスクを避ける。FFNだけのCHESS w/oに対し、この拡張を含むCHESS w/が追加速度を得る。

### 疎カーネル
ゼロを作るだけではdense GEMMが同じ演算をするため速度は上がらない。CHESSは疎活性のindexを使って必要な重み列/行だけを処理するカーネルを実装し、疎化率が高いほど実計算量を減らす。

## 評価条件
|項目|内容|
|---|---|
|モデル|Llama-2 7B/13B/70B、Llama-3-8B、Mistral-7B|
|品質|8下流task|
|比較|CATS等の活性疎化|
|方式|CHESS w/o = FFNチャネル別、CHESS w/ = 注意選択疎化も追加|
|実行|専用疎カーネル|
|指標|活性parameter比、task品質低下、端から端高速化|

## 主要結果
|条件|結果|意味|
|---|---:|---|
|CHESS w/o 平均品質低下|約1.07%|CATS約1.70%より同程度疎化で品質を保つ|
|注意選択疎化の追加品質低下|約0.04〜0.61%|Q/Oだけを狙うことで追加誤差を限定|
|標準設定の端から端速度|1.17〜1.27倍程度|疎化が実カーネル速度へつながる|
|高疎化率0.7〜0.9|最大1.72倍|より強い近似では速度余地が増える|
|対象範囲|5モデル・8task|単一モデルだけの結果ではない|

## 既存研究との差
CATS等は活性の大きさや統計に基づいて閾値を決める。CHESSは「削除した値が後続層出力へどれだけ効くか」を目的関数から導き、FFNのchannelごとに異なるup活性統計を閾値へ反映する。

またFFNだけを疎化する方式に対し、注意投影の感度差を利用してQ/Oだけを追加疎化する。アルゴリズム上のゼロ生成だけでなく、その疎性を利用する実カーネルまで評価している点も重要である。

## 限界
calibration統計が必要で、入力分布が大きく変わればチャネル期待値や閾値が最適でなくなる可能性がある。最大1.72倍は高い疎化率という品質との交換条件を強めた条件で、標準設定のheadlineは最大1.27倍である。

専用疎カーネルの利得はhardware、行列形状、batch sizeへ依存する。ゼロ率だけから同じ高速化を一般化できない。またK/Vを保持する設計なので、KV cache容量そのものを削減する方式ではない。
