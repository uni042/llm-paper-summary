# FlashSampling：言語モデル出力層に厳密な標本抽出を融合するGPUカーネル

## 概要

自己回帰型の大規模言語モデル（LLM）は、各トークンの生成時に最終隠れ状態を語彙行列へ投影して、語彙の各候補の得点であるロジットを計算する。一般的な実装では、この語彙投影を行列積として実行し、バッチ数×語彙数のロジット配列をGPUの高帯域メモリ（HBM）へ保存する。続いて別の処理がロジットを読み直し、確率への正規化、切捨て、乱数に基づく次トークン選択を行う。語彙数が十万規模に達し、出力を1トークンずつ繰り返すと、この後処理は単なる小さな付属操作ではなくなる。

FlashSamplingは、出力層の行列積（LM-head行列積）の計算中にロジットを小さな語彙タイルごとに生成し、その場でGumbel雑音を加えた最大得点の候補だけを残す。後段ではタイル数に比例する小さな候補表から最終トークンを選ぶ。全語彙のロジットをHBMへ書き出す必要も、明示的なソフトマックスや累積確率和を求める必要もない。**計算する標本の確率分布は通常のカテゴリカル分布と同じであり、近似的なトークン候補の選別ではない**という点が本研究の中心である。

一次論文第3版は、H100、H200、B200、B300の4種類のGPUでのカーネル単体測定と、B200上でのvLLMへの統合測定を報告する。小～中バッチでは、行列積後に別カーネルで標本を選ぶ3方式より高速で、最大値は多項分布基準比2.23倍、FlashInferのtop-k/top-p基準比1.74倍である。一方、実際のモデル全体の出力トークン当たり時間（TPOT）の削減はQwen3-1.7Bで最大10.2%、Qwen3-8Bで最大8.7%、より大きなモデルでは約3%以下であり、カーネル倍率をモデル全体へ転用できない。複数GPUでは語彙方向に分割された出力をまとめて転送する代わりに、タイルの局所候補を生成直後から他GPUへ送る。

## 問題設定と従来方式

### 出力層と標本抽出の間にあるメモリ往復

隠れ次元をD、語彙数をV、同時生成系列数をBとする。通常の出力層は隠れ状態H（B×D）と重みW（V×D）からY=HWの転置積に相当するB×Vのロジット行列を作る。復号バッチが小さいと、演算器が全力で積和演算するよりも、大きな語彙重みをHBMから読み込む時間が支配的になる。この状態でYをHBMに書き出し、別の標本抽出カーネルで再び読むことは、次トークンを一つ選ぶ目的に対して余分な往復である。

著者は先行測定として、単一GPUで標本抽出がトークン生成時間の10%以上、テンソル並列では全ロジットの集約を含め20～38%に達する例を紹介する。ただしこれは引用先の既存研究の状況説明であり、FlashSampling自身の全実験で常にこの割合になるという意味ではない。特に語彙分割テンソル並列では、各GPUが自分の語彙片のロジットだけを計算し、標本抽出前に全体を集める全収集通信（all-gather）が必要になることが問題である。

### 既存の最適化が残す費用

著者が比較する多項分布標本抽出（Multinomial）はcuBLASの行列積後にロジットを実体化し、ソフトマックスと多項分布標本抽出を行う。FlashInfer FI1はtop-k/top-pの最適化されたカーネル、FI2はロジット実体化後にGumbel-Maxを使う方式である。比較ではFI1のtop-k制限を無効、top-pを1にしているため、切捨て分布の違いではなく標本抽出実装の費用を比べる。FI2はソフトマックスを省けるが、**行列積と標本抽出の間のロジット書戻しと追加カーネル**をなお残す。FlashSamplingはこの境界そのものを消す。

## 手法

### 1. Gumbel-Maxによる正確なカテゴリカル標本抽出

温度や加算バイアス、禁止トークンのマスクを適用したロジットをl_iとし、各語彙位置iへ独立な標準Gumbel乱数g_iを加える。最大のl_i+g_iを与えるiを返せば、そのiが選ばれる確率はexp(l_i)を全語彙のexpの総和で割ったカテゴリカル分布と一致する。Gumbel乱数は区間(0,1)の一様乱数uから -log(-log u) で作る。これが、確率配列を作らずに正確な標本を選べる数学的根拠である。

さらに最大値演算は分割可能である。語彙を互いに重ならないタイルへ分け、各タイルで最大のl_i+g_iと元の語彙番号を一つずつ記録し、最後にその局所最大値の最大を選べば、全語彙を一度に調べた場合と同じ添字になる。連続分布のGumbel乱数では最大値の同点がほぼ確実に起きない。この**同一乱数列に対する経路ごとの厳密性**は、後述するグループ分解が**確率分布として厳密**であることと区別される。

### 2. 行列積の出力段に融合する二段階処理

第1段では、TritonのGPUカーネルが隠れ状態のバッチタイルと語彙重みのタイルをオンチップで積和計算する。得られた小さなロジットタイルへ温度・バイアス・マスクを適用し、各要素にGumbel乱数を加える。各行の局所最大得点mと、全語彙中の位置を表すidxの対だけをHBMへ書く。計算したB×Vのロジット行列は、行列積の出力段（epilogue）から外へ出さない。

第2段は、行ごとにタイル候補のmを縮約し、最大値に対応するidxを返す。例えば語彙が151,936で1タイルが128語彙なら、全語彙のロジットではなく約1,187個の候補対だけを比較すればよい。タイル幅はここでは仕組みを説明するための例であり、論文のすべての実験で128に固定したという意味ではない。計算時間の大半を占める語彙投影と標本抽出の仕事が同一カーネルに収まるので、追加カーネル起動とロジット配列の保存・再読込みを減らせる。

乱数をタイル実行順から独立させるため、論文の付録は論理位置(b,i)と乱数キーに結びつく計数器方式の乱数生成器（Philox等）を説明する。一様乱数が0または1だと二重対数が発散するため、32ビット整数rから(r+1)/(2^32+1)として開区間へ写す。重みと入力がBF16でも積和と摂動得点はFP32で計算する。これは浮動小数点の丸めが候補の順位へ影響する可能性を減らす設計であり、理論上の分布厳密性と有限精度実装の完全同一性を混同しない。

### 3. 語彙分割テンソル並列での逐次通信

語彙方向にWを分割するテンソル並列では、GPUごとに担当する語彙片が異なる。従来は全GPUが行列積を終えてから、B×Vのロジットを全収集し、共通の分布から標本を選ぶ。FlashSamplingの実装は各GPUの行列積の出力段から、タイルごとの局所最大得点と語彙番号をGPU間の点対点（P2P）書込みで他のGPUへ逐次送る。次のタイルの行列積やHBM読込みと前の候補の転送を重ねられる。全収集とは異なる非集合通信なので、最終縮約の前にはGPU間の同期障壁を設ける。

原著付録には別の理論的構成として、各GPUで局所標本と局所の対数確率質量を計算し、質量に比例して勝者GPUを選ぶグループ分解も記載される。これは通信する情報をGPU当たり定数個の値へ縮める考え方である。ただし、**論文本文のタイルごとのP2P実装**と、付録の**グループごとの局所質量を使う一般化アルゴリズム**は同じ手順をそのまま記したものではない。両者を混同して「実装はGPUごとに2値しか送らない」とは記載しない。

### 4. グループ分解・オンライン処理の厳密性

語彙集合をグループG_kへ分け、各グループの対数質量L_k=logsumexp(l_i, i∈G_k)を求める。まずexp(L_k)に比例してグループを選び、そのグループ内のexp(l_i)に比例してトークンを選ぶと、積の法則から元の全語彙分布に一致する。並列版は各グループで局所標本とL_kを計算してから勝者グループを選ぶ。逐次版はグループを一つずつ処理し、新しいグループの質量と蓄積済み質量の比率で標本を更新するので、グループ幅に比例する作業メモリで済む。

この階層分解の正確性は確率分布についての主張であり、乱数系列が異なっても全語彙を一括処理したときと同じ**個々の**標本が出るという主張ではない。論文は経路ごとの最大値分割と、グループ分解の分布的厳密性を別々の補題で証明する。推論サービスで実装を差し替える際は、統計的な分布の同一性と、乱数種から完全に同じトークン列が再現されることを別々に検証すべきである。

### 5. メモリ転送量の費用モデル

ロジット配列の要素サイズを一旦省略した理想化モデルでは、基準方式は重みVD、隠れ状態DB、ロジットの書込みVBと読込みVB、出力添字Bに相当する転送を要する。融合方式はVD+DB+Bに近づく。転送量の比は (VD+DB+2VB+B)/(VD+DB+B) で、Vが大きいと約1+2B/Dとなる。したがって、この**転送量だけ**の利得は小バッチで小さく、バッチが増えるほど大きくなる予測になる。

ところが実測では、この予測以上の高速化が得られる。主因は、単なるロジットのHBM往復削減ではなく、別の標本抽出カーネルに要した起動・正規化・走査の費用を行列積の出力段へ吸収できることにある。逆に大バッチでは、cuBLASの行列積がTritonの融合行列積より高効率になるため、融合による節約が一部相殺される。この点は単純な転送量モデルでは表現できない。

原著表7・8の絶対値と相対値を対応させた。Qwen3-1.7BでB=64の改善はばらつきに埋もれ、B=32の最大10.2%をどの同時要求数にも一般化できない。大規模モデルでは注意機構とフィードフォワード層（FFN）の実行が出力層より大きな時間を占めるため、出力層の最適化だけでは全体の短縮率が小さい。TPOTは出力トークン当たりの時間であり、初回トークン遅延や全リクエストの完了時間、スループットの全条件を示すものではない。

### 何が速くなったのかを切り分ける検証

原著表1では、B=64の多項分布基準方式は行列積71.3%・標本抽出28.7%に時間を使うのに対し、融合方式は行列積93.6%・標本抽出6.0%となる。これは融合によって標本抽出が全体に占める割合が小さくなったことを示すが、百分率の母数は方式ごとに異なるため、絶対時間を別に確認する必要がある。付録のロジット書戻し実験では、融合カーネル内でロジットをHBMへ保存する機能だけを有効にし、モデルの転送量予測と実測の傾向が一致することを確認した。**ロジットの書戻しを避ける効果と、別標本抽出カーネル自体をなくす効果を分けている**点が重要である。

### 標本の正確性と品質への影響

数学的には、独立なGumbel乱数と全語彙に対する最大値選択の等価性から、タイル分割による確率分布の近似は導入されない。実装上の標本分布については、原著第3版で語彙数512・10,000標本のカイ二乗適合度検定を実施し、基準実装との有意差が検出されなかった。以前の再現資料にある語彙数100/256・5,000標本の条件とは**版・測定対象が異なる**ので混ぜない。

Qwen3-1.7Bを用いたGSM8Kの1,319問では、FlashSamplingの正答率89.4%、基準89.6%、対応付きブートストラップ検定のp値0.776である。これはこの評価で有意な品質差を検出できなかったことを示すが、任意のモデル・温度・乱数実装で完全同一の出力列を保証する実験結果ではない。貪欲復号（greedy）では標本抽出が不要となるため、この方式の評価対象には含めない。

## 既存研究との差

FlashAttentionは注意行列をHBMへ実体化せずオンチップで処理することによりメモリ転送を減らす。FlashSamplingはその設計思想を**出力層の標本抽出**へ適用するが、数学的に必要な演算は注意のオンライン正規化ではなく、Gumbel-Maxの局所最大値と縮約である。学習時の大語彙交差エントロピーを出力層へ融合する方式とも対象が異なり、本研究は推論時に**標本を1個選ぶ**ことへ特化する。

FlashInfer FI2もGumbel-Maxを使うが、事前に全ロジットをHBMへ実体化してから標本抽出する。FI1やCPUへ標本抽出をオフロードするSIMPLEも、基本的にロジットが既に生成・保存されていることを前提にする。FlashSamplingは出力層の行列積の途中で候補を確定し、別カーネルへのロジット受渡しをなくす。類似の上位候補だけを近似的に求める方式とは異なり、**分布を変えずに**計算と通信を減らす点が新規性である。

## 制約・負の結果・実装状況

第一に、実装の融合対象は出力層の行列積と標本抽出である。出力層が推論全体の小部分しか占めない大規模モデルでは、TPOT改善は2～3%程度に縮む。特にB=256のような計算律速に近い条件では、cuBLASより融合Triton行列積の効率が低く、FI2より遅くなる測定点もある。単純なメモリ転送量モデルから一律の高速化を保証できない。

第二に、任意の切捨て規則をそのままタイル内だけで完結できるわけではない。top-kは各タイルから局所上位k候補を集めて全体上位kを選ぶ拡張が可能だが、top-p（核サンプリング）は全語彙の正規化と累積確率による順位判定が必要で、独立なタイル局所処理だけでは厳密に完結しない。論文はtop-kで候補を減らした後にtop-pを適用する経路を論じるが、これは**元の全語彙に対する純粋なtop-pをそのまま高速化すること**とは別の分布になる場合がある。主な速度評価はtop-k無効・top-p=1の設定である。

第三に、厳密性の理論は正しい独立Gumbel乱数とロジット変換を前提とする。高速近似対数関数を用いる実装モードでは有限精度の歪みが生じ得る。著者は標準対数関数を使う高忠実度モードと高速近似モードを区別しており、後者まで数学的に完全一致と断定しない。乱数種・タイル実行順・GPU数の違いによる出力列の逐語再現も、分布としての正確性とは別問題である。

第四に、論文の実機評価はNVIDIAのHopper/BlackwellとNVLinkに重点を置き、Tritonを使う研究実装および著者側vLLM統合分岐での測定である。著者はTritonの移植性に言及するが、AMDやIntelのGPU、Windowsのllama.cpp、RTX 4070 Superで同じ改善を実測した証拠は示していない。出力層や標本抽出経路の改造が必要で、単に既存推論器のサンプリング引数を切り替えるだけでは導入できない。

## 監査メモからの実装補足

通常のLLM復号は、最終隠れ状態と語彙投影行列の積で語彙全体のlogitsを生成し、GPUの高帯域メモリ（HBM）へ書き出した後、別カーネルで確率分布から次トークンをサンプリングする。語彙数が大きいと、この中間logitsの書込み・再読込みと追加カーネル起動が無視できなくなる。

FlashSamplingは語彙投影の行列積（LM-head matmul）の各タイルでlogitsをオンチップ計算し、各候補へGumbel雑音を加え、そのタイルの最大候補のみを残す。タイル間で最大値を縮約すると、全語彙のGumbel-maxによるカテゴリカル分布の正確なサンプリングと一致する。argmaxは分割ごとの最大値をさらに最大化しても結果が変わらないため、logits全体をHBMへ格納しなくてよい。

テンソル並列時は語彙方向に分割された各GPUが、自分の候補をピアGPUへ逐次書き込む。logits全体のall-gatherを避け、行列積の実行とGPU間通信を重ねる。原著要旨では最大8GPUまでの測定を報告する。オンラインおよびグループ化された変種も、カテゴリカル分布の階層的分解によって正確性を保つと説明する。
