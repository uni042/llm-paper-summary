# Accelerating the Mitigation of LLM Inference Nondeterminism Across GPU Architectures

> BF16重みをレジスタ内FP32化し固定順序のIEEE-754 FMAで積算するTriton GEMMにより、GPU世代を跨ぐbitwise再現性と既存対策比1.17〜3.1倍の推論高速化を両立する。

## 概要

温度0の貪欲復号（greedy decoding）なら同じモデルは同じ出力になると期待されるが、実際にはGPU世代、GPU数、バッチサイズが変わるだけでトークン列が分岐する。原因は浮動小数点加算の非結合性と、cuBLASや生成カーネルがハードウェア・形状ごとに異なるGEMM構成を選ぶことである。上位2トークンの確率差が小さい推論モデルでは、わずかな丸め差がargmaxを反転し、その後の系列全体を変える。

既存の強い対策はBF16重みを推論直前にFP32へ展開してFP32 GEMMを使うが、デコードは重み読み出し帯域に律速されやすいため、FP32化でメモリトラフィックが倍増する。それでもvendor GEMMの削減順序はGPUごとに異なり、完全なbitwise一致にはならない。

## 問題設定

再現性と速度の衝突は、単に精度をFP32へ上げれば解決しない。Tensor Coreの内部蓄積は世代ごとの差があり、FP32指定でもTF32経路が選ばれる場合がある。さらに同じ演算でもtileやsplit-Kが違えば加算順序が変わる。

したがって必要なのは、数値誤差を「十分小さくする」ことではなく、各GPUが同じ順序で同じIEEE-754演算を実行することである。ただしFP32重みをHBMへ置くとデコード性能を失うため、保存形式と計算形式を分離する必要がある。

## 手法

### fused-upcast GEMM

重みはBF16のままHBMへ保存し、GEMMカーネルがタイルを読み込んだ後、レジスタ内でFP32へ変換する。FP32の一時重み行列をHBMへ書かないため、重み読み出し量はBF16相当のままになる。

積算はTensor Coreではなく、結果がIEEE-754で規定されるFMAを使う。これによりハードウェア世代固有のMMA内部丸めを避ける。

### 問題形状だけで決まる固定構成

通常のautotuningはGPUごとに最速tileを選ぶが、それが削減順序の差を生む。提案カーネルはtileサイズ、warp構成、split-Kなどを問題形状だけから決め、GPUのSM数や実行スケジューリングへ依存させない。

小バッチのデコードではsplit-Kを使うが、部分和をatomic加算せず、固定された昇順で結合する。したがって浮動小数点演算列そのものが同じになる。

### batch invariance

同じ要求が何件の他要求と同時にバッチされたかでGEMM形状・削減順序が変わると、同一GPUでもサービング負荷によって出力が変わる。提案方式はデコードbucket内で要求の演算順を固定し、batch-invariantな出力を狙う。

この性質はCI再現、監査、エージェントのreplayで特に重要で、単なるcross-GPU比較より実運用サーバでの価値が大きい。

## 評価

| 項目 | 条件・結果 |
|---|---|
| GPU世代 | NVIDIA Ampere、Ada、Hopper |
| ランタイム | vLLMへ統合 |
| 数値検証 | 線形層出力がテストしたGPU世代間でbitwise一致 |
| end-to-end速度 | 既存の再現性対策比1.17〜3.1倍 |
| 重みメモリトラフィック | FP32一時重み方式から半減 |
| メモリ | 最大1.4GiBの重み関連メモリを節約しKVへ転用可能 |
| 対象形状 | prefill/decode、BF16/FP32重み、ragged dimensionを含むprobe |

論文が比較する従来のFP32-compute方式は丸め差を小さくするが、GPU間でlogit自体は一致しない。提案方式は線形層のbitwise一致を構成上保証しつつ、BF16保存によって帯域費用を下げる。

## 既存研究との差

batch-invariant kernelは同一GPU内の実行再現性を狙うが、Tensor CoreやGPU世代固有演算を残すとcross-architecture一致は保証できない。LLM-42のような検証・rollback方式は高速な非決定的経路を許し、必要時だけ検証する別アプローチである。

本方式は線形層そのものを決定的にし、再実行やrollbackを避ける代わりに、Tensor Coreの最高スループットを使わないという交換条件を取る。

## 限界・実装状況

IEEE-754 FMAへ限定するため、通常のTensor Core最速GEMMに対しては性能を犠牲にする可能性がある。比較対象は「再現性を確保する既存方式」であり、無制約の最速BF16推論に常に勝つという主張ではない。

また線形層のbitwise一致だけでシステム全体のすべての演算が自動的に決定的になるわけではない。sampling、通信、他のreduction kernel、ソフトウェア版差も別途固定する必要がある。

## 一般的な実装上の含意

決定的推論では「高精度化」と「演算順固定」を分けて考える必要がある。メモリ帯域律速のデコードでは、保存は低精度のまま、レジスタ内だけ高精度化する設計が再現性コストを抑える有効な手段になる。
