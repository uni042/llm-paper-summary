# RACE Attention：soft LSHバケット統計で長文注意を系列長・特徴次元に線形化する

## 概要

RACE Attentionは、Transformerのsoftmax注意が系列長Nに対してO(N²d)のQuery-Key相互作用を要求する問題を、別の注意カーネルと確率的スケッチで解決する研究である。FlashAttentionは注意行列の中間保存を減らしてメモリ効率を改善するが、正確なsoftmaxを計算する以上、全てのQueryとKeyの相互作用を計算する必要がある。RACEはこの演算自体を置き換える。重要なのは**softmaxを誤差なく高速化するのではなく、角度類似度に基づく別の正規化注意を学習可能な形で近似する**ことである。

各QueryとKeyをランダムな超平面へ射影し、LSHで定義される少数のバケットへsoftに割り当てる。Keyごとのバケット質量とValueの加重和を一度集計すれば、QueryはN個のKeyへ個別にアクセスせずバケット統計だけで出力を再構成できる。L個の表、各表R個のバケット、埋め込み次元dに対し計算量はO(LNRd)となり、LとRを固定すればNとdの双方に線形である。

原著v5は長文分類、言語モデル、画像分類で品質を評価し、A100 40GBの64Kトークン文書分類でRACE(P=3,L=3)が97.92%・584秒/epoch、FlashAttention2が97.0%・1645秒/epochと報告する（表1）。GH200では単一注意層のforward-backwardを1200万トークン、CPUでは7500万トークンまで実行する（図4–5）。ただし、これは**単一注意層のスケーリング**であり、1200万トークンのLLM全体を学習できるという実証ではない。

## 問題設定：なぜsoftmaxの代替が必要か

softmax注意は `O=softmax(QKᵀ/√d)V` を計算し、行ごとに正規化した重みでValueを平均する。Nが長いとQKᵀのN×N個の組合せが問題になる。FlashAttentionはタイル化によってメモリを節約するが、時間計算量は依然二乗である。既存の線形注意は特徴写像φを用いて `φ(Q)(φ(K)ᵀV)` の順序へ変更するが、φの選び方で品質が大きく変わる。Performerは指数カーネルをランダム特徴で近似するが、特徴数や次元が増えると費用が増え、YOSOは角度カーネルのhard LSHを使うものの勾配の扱いと正規化が難しい。

RACEの着眼点は、softmaxの指数関数そのものではなく、**近いQueryとKeyに大きな重みを与える非線形な類似度**を保持すれば注意として機能する、という点にある。ベクトル間角度を `θ=arccos((q·k)/(|q||k|))` とし、類似度を `(1−θ/π)^γ` と定義する。γを増やすと角度の小さな組合せが強調され、softmaxの鋭い重みに似た振る舞いになる。原著図2–3ではγ=8程度でsoftmaxに近い形になると説明する。ただし角度カーネルと指数カーネルは数学的に別物であり、全入力で同じ注意重みを再現する保証はない。

## 手法

### 1. 角度カーネルをLSHの衝突確率として表す

ランダム超平面を用いたSimHashでは、方向が近い二つのベクトルほど同じ符号パターンへハッシュされる確率が高い。P個の独立した超平面の符号を組み合わせると、同一バケットへ入る確率は角度類似度のP乗となる。したがってRACEは角度カーネルのべき乗を、ハッシュ衝突に基づく統計量として扱える。RACE sketchはL個の独立した配列へKeyを蓄積し、Queryの対応するバケットを参照してカーネル密度和を推定する。独立表を増やすと推定の分散を減らせる一方、演算・メモリは増える。

原著§2–3では各表のバケット数を `R=2^P` とし、Pはランダム超平面数、Lは独立表数とする。Pを増やすと類似度が鋭くなるが、バケット数は指数的に増える。したがってO(LNRd)の「線形」は**LとRを固定したとき**の主張であり、要求品質に応じてPを大きく増やせば定数因子は無視できない。通常のN²行列を保持しないことと、無限の長さを固定メモリで処理できることも同義ではない。

### 2. hard hashをsoftな割当に置き換える

hardなsign関数によるハッシュは勾配が通りにくい。RACEは各表ℓについてGaussian射影行列 `W^(ℓ)∈R^(P×d)` を用意し、`tanh(Wx)` とP次元の±1超立方体頂点 `v_r` の内積を計算する。温度βを掛けてsoftmaxを取ると、入力ベクトルxがR個のバケットへ入る確率分布 `φ^(ℓ)(x)` が得られる。これは微分可能で、学習時にQuery/Keyの表現と一緒に最適化できる。

入力はN×dのQ,K,V、表数L、超平面数P、温度βである。出力はN×dの注意表現である。ハッシュ関数の乱数は各表ごとに独立で、同じ表ではQとKに同じ射影を用いる。角度が近いQとKほど同じバケットへ確率質量が集まるため、softなバケット一致度が角度カーネルの近似になる。ここでsoftmaxは**バケットへの割当確率を作るため**に使われるのであって、N×Nの注意行列を作るためではない。

### 3. Keyの統計量を集約してQueryを復元する

各表ℓについてKeyのバケット確率行列 `Φ_K` から、質量ベクトル `A=(Φ_K)ᵀ1` とValue加重和 `B=(Φ_K)ᵀV` を計算する。Query側の確率行列 `Φ_Q` を掛け、表ごとに `Num=Φ_Q B`、`Den=Φ_Q A` を求めてL表で平均する。最終的な出力は `O_hat=diag(Den)^{-1} Num` である（原著Algorithm 1）。分母で正規化するため、YOSOの事後的なL2正規化とは異なり、注意の重み和を明示的に扱う。

この演算はKeyを一度走査してバケット統計を作り、各QueryはR個のバケットに対してだけ計算する。原著の費用分析では表ごとの射影O(NdP)、バケット確率O(NPR)、集約と復元O(NRd)で、合計O(LNRd)とする。バケット確率を全トークン分保持すればO(LNR)の作業メモリが要るため、時間が線形でも活性メモリがゼロになるわけではない。原著のGPU/CPU実装はこの処理をタイル・走査で実行し、長系列での実メモリ使用量を抑える。

### 4. 因果注意と学習可能性

非因果分類では全Keyを一度集計して全Queryへ参照できる。しかし自己回帰言語モデルでは位置tが未来のKey/Valueを参照してはならない。原著Algorithm 2はバケット質量とValue和を位置順に累積するprefix方式を使い、Query位置tでt以前の統計量だけを読む。OpenMP/CUDAの因果用カーネルを実装し、Tiny Stories等の言語モデル評価へ適用する。

重要な境界は、原著§3.3の近似誤差保証が**非因果設定に限られる**ことだ。因果prefixと乱数特徴が組み合わさった場合の同等のバイアス・分散保証は未解決として明記される。因果カーネルの実装と経験的なPPLは存在するが、非因果理論の誤差上界をそのまま因果モデルの品質保証へ転用しない。

### 5. 理論の仮定

原著Theorem 2は、対象カーネルSの行和が `s_min ≥ C1 N` とゼロから十分離れ、スペクトルノルムが `||S||₂ ≤ C2 N` に抑えられることを仮定する。後者はSの要素が0〜1の範囲なら自然だが、前者はQueryが全Keyからほぼ孤立する極端なケースを除外する。近似誤差は表数L、バケット数R、温度β、入力の条件に依存し、**無条件でsoftmaxの出力に一致するという定理ではない**。理論が評価するのは代替の角度カーネルに対する推定品質である。

## 評価

### 長文分類：A100 40GB、16K〜64K

原著表1はArxiv長文文書分類の1 epoch学習時間・評価時間・正解率をA100 40GBで比較する。64K系列ではRACE(P=3,L=3)が学習584秒、テスト22.5秒、精度97.92%、FlashAttention2が学習1645秒、テスト47秒、精度97.0%である。学習時間は約2.82倍、テスト時間は約2.09倍の差になる。RACE(P=2,L=2)は学習561秒、精度97.14%、P=4,L=4は学習594秒、精度97.4%であり、**表数・超平面数を増やすほど単調に精度が上がるわけではない**。

32KではRACE(P=3,L=3)が学習289秒・精度90.6%、FlashAttention2が471秒・89.7%。16KではRACE(P=3,L=3)が82.4秒・71.3%、FlashAttention2が95.7秒・69.8%である。長文ほど計算量の差が拡大するが、分類データセットにおける正解率が長さとともに大きく変化する点は、文書の切り詰め条件やタスク構成にも依存するため「64Kなら普遍的に精度97%」とは言えない。

### 言語・画像の品質：小規模条件での比較

原著表2ではTiny Stories系列長1024のPPLがRACE(P=2,L=2)で4.2、P=3,L=3で3.2、P=4,L=4で2.6、FlashAttention2で2.7、Performer-256で10.0、単純Linearで7.0である。PとLを増やすと品質が改善する条件があり、P=4,L=4はFlashAttention2よりわずかに良い。ただし、Angularの厳密計算は2.5とさらに良く、近似には誤差が残る。CIFAR-10系列長1024ではRACE(P=4,L=4)が65.9%、FlashAttention2が61.44%、QNLI系列長2048ではRACE(P=4,L=4)とFlashAttention2がいずれも61.1%。単一指標だけで全タスクの優位を断定しない。

原著表3のFood-101画像分類16KではRACE(P=3,L=3)が学習950秒、テスト40秒、精度43.5%。FlashAttention2は2600秒、95秒、42.1%、Linformer-128は1250秒、49秒、20.2%である。画像分類でも時間・品質の両面で良い条件があるが、精度自体は43.5%で高いとは言えず、実用の大規模視覚モデルの精度保証にはならない。

### 単一注意層の超長系列スケーリング

原著図4–5のストレステストはバッチ1、4ヘッド、埋め込み128の**単一注意層のforward-backward**である。GH200 96GBでRACEは1200万トークン、Intel Xeon Gold 5220R CPUでは7500万トークンまで処理した。FlashAttention2/3は同GPUで約400万トークンを超えると実行が困難になる。原著は400万トークンでRACE約0.1秒、FlashAttention2約550秒、約5500倍と報告するが、これは非常に特化した単層条件での実測であり、LLMの全層学習時間や品質を伴う長文推論性能を意味しない。極端な系列長での速度比は、同じモデル規模・同じカーネル精度・同じ目的関数の比較と誤解しない。

### 比較対象と測定の読み方

FlashAttention2は正確なsoftmax、Linear Attentionは簡易特徴写像、Performerは指数カーネル近似、Linformerは長さ方向の低ランク射影、YOSOはhard LSHの角度カーネル近似である。RACEの改善には計算量の差だけでなく、**異なる注意関数へモデルを置換して学習した効果**が含まれる。特にsoftmaxモデルの重みをそのまま差し替えて同じ出力を得る手法ではない。原著は分類・言語モデル・単層速度を別々に評価しており、極端な単層速度と品質指標を同じ一つの実験結果として合成しない。

## 既存研究との差

RACEの特徴は、単に線形注意へ特徴写像を導入するだけでなく、角度カーネルをLSH衝突確率として表現し、Keyのバケット統計でQueryの正規化出力を推定する点にある。YOSOと同じ角度カーネル族を使いながら、soft割当で勾配を直接流し、分母も推定して正規化する。Performerのランダム特徴とはカーネルの対象と計算・誤差構造が異なる。長文処理の別路線としては、既存のsoftmax注意を保ちつつKVを削減する方式、疎注意、リング注意などがあるが、RACEは注意演算そのものを別の計算へ置換する。

## 限界・負の結果・再現性

第一に、softmaxと角度カーネルは異なるため、**既存LLMの重みをそのまま置き換えて同等品質を得られるとは限らない**。品質評価は主に新たに訓練したモデルと分類・小規模言語モデルであり、数十Bパラメータの本番LLMを長文推論で同品質・同速度に置換できる証拠ではない。

第二に、計算量O(LNRd)はLとRが固定のとき線形であり、R=2^Pが大きいと実用上の定数因子が増える。近似精度を改善するためPやLを増やすとメモリと時間が増える。原著表1でP=4,L=4がP=3,L=3より精度を下げる条件もあり、ハイパーパラメータの選択はタスク依存である。

第三に、理論の誤差保証は非因果設定のみ。因果prefixは実装・実験されているが同等の理論的保証は示されない。行和が小さい孤立Queryでは分母の正規化が不安定になりうる。角度カーネル近似の品質保証と、下流の生成正答率・推論SLOの保証も異なる。

第四に、GH200の1200万トークンとCPUの7500万トークンは単一層・固定ヘッド数・埋め込み128での計算限界である。実際のLLMでは層数、FFN、埋め込み、optimizer状態、データ読み込みなどが加わるため、同じ系列長の全モデル学習を示したものではない。GPU推論時のトークン毎のdecode latencyや既存モデルへの組込み費用は別途測定が必要である。

第五に、ランダム射影・soft割当の乱数種、カーネルの再現性、ハイパーパラメータの調整に性能が左右される。公開コードはあるが、別GPU・別言語モデルで同じ速度と精度を得るには再学習・再計測が必要になる。
