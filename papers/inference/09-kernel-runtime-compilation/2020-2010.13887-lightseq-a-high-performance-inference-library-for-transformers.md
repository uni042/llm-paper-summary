# LightSeq: A High Performance Inference Library for Transformers

## 概要

TransformerをTensorFlowやPyTorchの一般実行系で推論すると、行列積以外にも正規化、バイアス加算、活性化、転置、ビーム探索など多数の小演算がGPUカーネルとして個別起動される。モデルが大きくても、特に小バッチや自己回帰復号ではカーネル起動とGPUメモリ往復が相対的に大きくなり、理論FLOPsほどGPUを使い切れない。LightSeqはTransformer系列の構造を前提に実行経路を専用化し、演算融合とメモリ管理をCUDAレベルで行う。

中心機構は三つある。第一に、複数の細粒度演算を粗粒度の融合カーネルへまとめ、グローバルメモリへの中間結果書き戻しとカーネル起動回数を減らす。第二に、ビーム探索などの自己回帰生成で候補管理を階層化し、不要な候補計算とデータ移動を減らす階層型自己回帰探索（Hierarchical Auto-Regressive Search; HARS）を導入する。第三に、演算の生存期間を見てGPUバッファを再利用し、可変長系列で中間テンソルごとに独立確保するメモリを減らす。

標準機械翻訳ベンチマークではTensorFlow実装に対して最大14倍、同時期のCUDA専用FasterTransformerに対して最大1.4倍の高速化を報告する。公式性能表のTransformer-base/Tesla T4の例では、batch 32、beam 4、sequence 32でTensorFlow 536 ms、FasterTransformer 82.82 ms、LightSeq 59.49 msであり、単にフレームワークを避けるだけでなく専用CUDA実装間でも利得がある。

## 問題設定

Transformer推論のボトルネックはGEMMだけではない。層正規化、softmax、バイアス、活性化、残差加算などは個々の演算量が小さいが、別々のカーネルとして実行すると入力をHBMから読み、結果をHBMへ書き、次のカーネルが再び読む。自己回帰生成ではこの処理を出力トークンごとに繰り返すため、メモリI/Oと起動オーバーヘッドが累積する。

さらにビーム探索では各ビームの候補確率、上位候補選択、系列状態更新が必要で、生成長が伸びるほど管理処理が増える。一般フレームワークの動的メモリ確保も、多数の一時テンソルを個別管理するためピークメモリと割当オーバーヘッドを増やす。LightSeqはTransformer推論専用の実行計画を持つことでこれらをまとめて削る。

## 手法

### 粗粒度CUDA演算融合

LightSeqはTransformer層内で連続する要素演算を一つのCUDAカーネルへ融合する。例えばバイアス、活性化、残差、正規化など、GEMM前後の小演算をまとめ、中間テンソルをGPUグローバルメモリへ何度も往復させない。GEMM自体はcuBLAS等を利用し、周辺演算を専用カーネル化する。

この設計はカーネル起動回数とメモリI/Oを同時に減らす。論文は一般フレームワークに比べて起動回数を大きく削減し、特に小さな行列・小バッチでGPU利用率を改善する。追加コストは、対応するTransformer構造ごとに専用カーネルと重み変換を維持する必要があることである。

### 階層型自己回帰探索

自己回帰生成では、各ステップで語彙全体の候補からビームを更新する。HARSは探索処理を階層化し、GPU上で候補を段階的に絞ることで、不要な全候補処理とホスト・デバイス間同期を減らす。入力は各ビームの次トークンスコア、出力は次ステップへ残す上位系列とその状態である。

この機構はencoder-onlyモデルではなく、機械翻訳やテキスト生成のdecoderで効く。GEMMを高速化してもビーム探索がCPU同期や小カーネルで律速すれば生成全体は速くならないため、LightSeqは探索部分までCUDA実行経路へ含める。

### 動的GPUメモリ再利用

Transformer推論中の一時テンソルはすべて同時に必要ではない。LightSeqは演算間の依存とバッファ生存期間を利用し、互いに重ならない一時領域へ同じGPUメモリを割り当てる。可変長系列でも最大必要量を基準に再利用可能な領域を管理し、頻繁なcudaMalloc相当処理を避ける。

これによりピークメモリを抑え、より大きいバッチを同じGPUへ載せやすくする。論文ではメモリ割当量を大幅に減らすことを示し、速度だけでなくサービング時の収容能力にも効く設計として位置付ける。

## 既存研究との差

FasterTransformerもCUDAでTransformerを高速化するため、LightSeqの比較で重要なのはTensorFlow比14倍だけではない。LightSeqは粗粒度融合に加えて、自己回帰探索と動的メモリ再利用を同じライブラリへ統合し、生成処理全体を対象にする。公式表では条件によってFasterTransformerが優位な場合もあるが、中～大バッチではLightSeqが上回る例がある。

また、学習フレームワークを置き換えるのではなく、PyTorch/TensorFlowで学習した重みを推論専用形式へ取り込み、サービングへ接続する設計である。後年のLightSeqは学習も扱うよう拡張されたが、本論文の主題は推論ライブラリである。

## 限界

初期LightSeqはCUDA/NVIDIA GPUへ強く依存し、CPU推論を対象としない。対応モデルや探索アルゴリズムも専用実装が必要で、任意の新規Transformer変種が一般フレームワークのように自動で高速化されるわけではない。公式プロジェクトは後に多くのモデル・INT8へ拡張されたが、論文時点の評価と後年の機能を混同しない必要がある。

また、評価は現在のLLMサービングで一般的な連続バッチ、ページ化KVキャッシュ、プリフィル・デコード分離を対象としたものではない。したがってLightSeqの結果は、Transformer推論専用カーネル融合の初期システムとして読むべきで、現代のvLLM等との直接性能比較ではない。
