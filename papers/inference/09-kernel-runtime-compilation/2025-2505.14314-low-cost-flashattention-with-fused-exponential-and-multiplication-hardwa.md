# Low-Cost FlashAttention：ExpMul融合演算器によるASIC面積・電力削減

## 概要

本論文は、FlashAttention-2の計算アルゴリズムを変えるのではなく、**オンラインsoftmaxに必要な指数関数とValueベクトル乗算をASIC上の一つの演算器へまとめる**ハードウェア最適化を提案する。通常の計算では`exp(x)`を浮動小数点で求め、その結果をValueの各要素へ掛けるため、指数関数回路と浮動小数点乗算器の双方が必要となる。ExpMulは`exp(x)*V`を対数の整数近似と浮動小数点指数部の減算に置き換え、回路面積と演算部電力を削減する。

FlashAttention-2のrunning maximum、指数和、Value加重和の更新構造を維持しつつ、指数和とValue加重和を拡張ベクトルにまとめる。これにより同じExpMul回路を二つの更新項へ適用できる。28nm標準セルライブラリで合成した単一Query向け演算カーネルでは、別々の指数関数器と乗算器を持つ比較設計より平均面積が約28.8%小さく、演算部電力も約17.6〜17.8%小さい。これは**ASIC合成・電力推定結果**であり、NVIDIA GPUのFlashAttentionを差し替えたtokens/sの実測ではない。

数値近似を導入するため、著者らはFLAN-T5でGLUEの10ベンチマークを実行し、FP32/BF16の標準演算とExpMul演算の精度を比較する。全体として近い結果だが、BF16-ExpMulのCoLAやMNLI-mmなどで低下もあり、数学的に厳密なsoftmaxと完全等価とは言えない。著者はHLS用の実装をGitHubで公開しており、論文の対象はGPUソフトウェアの高速化ではなく専用ハードウェアの演算コストである。

## 背景：オンラインsoftmaxとFlashAttention-2

### メモリI/Oを減らす計算順序

標準attentionは`softmax(QK^T/sqrt(d))V`を計算する。すべてのQuery-Key組合せの注意行列を主記憶へ書き出すと、文脈長に対して二乗の中間記憶とメモリI/Oが問題になる。FlashAttentionはタイル化とオンラインsoftmaxで中間注意行列の完全な実体化を避ける。FlashAttention-2では各Queryに対してKey/Valueを順次処理し、running maximum `m_i`、指数和 `l_i`、Value加重和 `o_i`を更新する。最後に`o_N/l_N`を出力すれば、注意重みを一括保存する必要がない。

running maximumが増えると、過去の指数和と出力ベクトルは新しい最大値に合わせて再スケーリングされる。論文Algorithm 2の更新は、`l_i=l_(i-1)*exp(m_(i-1)-m_i)+exp(s_i-m_i)`、`o_i=o_(i-1)*exp(m_(i-1)-m_i)+v_i*exp(s_i-m_i)`である。ここで`s_i`はQueryとKeyの内積スコアである。両式に同じ二種類の指数値が現れ、それぞれを指数関数器で求めてからスカラー×ベクトルの乗算へ渡す構成は、ASICで回路が重くなりやすい。

### GPUカーネルとASIC演算器の違い

GPU版FlashAttentionの主要な改善対象は、データ移動、スレッドブロックの並列化、行列演算器の利用効率である。本論文はその演算順序をハードウェアとして実装した場合の指数関数器と浮動小数点乗算器の面積・電力を対象とする。CPU命令やCUDAカーネルのfusionではなく、専用回路の演算器自体を再設計する。GPUでの命令数が減ることや既存GPUのTensor CoreでExpMulを直接実行できることは示していない。

## 手法

### 1. 指数和とValue加重和を拡張ベクトルへ統合

オンラインsoftmaxの分母`l_i`はスカラー、出力の累積`o_i`はd要素のベクトルである。著者らはこれを`o*_i=[l_i, o_i]`というd+1要素の拡張ベクトルへまとめ、入力Valueも`v*_i=[1,v_i]`とする。すると両方の更新を`o*_i=o*_(i-1)*exp(m_(i-1)-m_i)+v*_i*exp(s_i-m_i)`と一つのベクトル演算で表現できる。元の式では指数和と出力を別々の演算器で計算するように見えるが、拡張ベクトルにより同じ形式の演算器を共有できる。

この統合はattentionの確率分布を変える近似ではない。近似が入るのは後述する指数関数と乗算の実装であり、softmaxの更新順序や最終の除算は維持する。論文Algorithm 4では`ExpMul(m_(i-1)-m_i,o*_(i-1))`と`ExpMul(s_i-m_i,v*_i)`の和で更新し、最後に拡張ベクトルの先頭を分母として使う。既存のFlashAttention-2のオンライン計算をハードウェア向けに書き直したものと理解できる。

### 2. ExpMul(x,V)=exp(x)Vを一つの演算器で近似

softmaxの最大値を引いた指数の入力`x`は必ず0以下なので、`exp(x)`は0〜1に入る。負側では急速に0へ近づき、たとえば`exp(-15)`は約3.1e-7となる。著者らは`x`を[-15,0]にclippingし、16bit固定小数点へ変換する。`-log2(exp(x))=-x*log2(e)`を整数演算で近似し、論文式(7)のshift-and-addによって整数の指数差`L`を得る。すなわち浮動小数点の`exp`を直接計算せず、2の整数冪によるスケーリングへ置換する。

IEEE型の浮動小数点数`V=(-1)^S*2^(E-b)*(1+M)`に`2^(-L)`を掛ける操作は、仮数を掛け算する代わりに指数フィールドEからLを減算することで近似できる。したがってExpMulは、入力のclipping、固定小数点変換、shift-and-addによるL算出、符号・仮数の維持、指数部減算から構成される。原著Algorithm 3では結果の指数が表現範囲外となる場合に0へ飽和させる処理を含む。通常の浮動小数点乗算器を各要素へ置くより単純な回路となる。

重要なのは`exp(x)`が2の冪に近似されるため、演算は数学的に厳密な`exp(x)V`ではない点である。量子化した指数差による数値誤差が発生する。そのため「FlashAttentionと同じ計算順序」を保持しても、ビット完全一致するわけではない。clipping範囲[-15,0]と16bit固定小数点、整数部6bit、残り小数部という設計は論文の評価条件であり、別の精度・別のダイナミックレンジへ無条件で移植できない。

### 3. FlashAttention-2への組込み

拡張ベクトルに対する二つのExpMul演算器と加算器を並べ、running maximumと内積スコアから得た指数差を入力する。FlashAttention-2はKey/Valueを順次ストリーミングし、Queryブロックを並列に保持する。各Queryに対する演算ブロックを複製すれば複数Queryを並列処理できるが、その場合の総面積は単一Queryブロックの面積に複製数を掛けたものへ近づく。論文は各サイクルにd要素のKey/Valueをローカルメモリから供給できることを前提にするため、DRAMやSRAMの帯域が不足すれば演算器だけを縮小してもスループットが上がるとは限らない。

実装はC++で記述され、Catapult HLSでVerilogへ変換する。ベースラインは同じFlashAttention-2計算を独立した指数関数近似器と浮動小数点乗算器で実装する。ExpMul版ではその二つを融合した回路へ置き換える。メモリへのアクセス順序と量は同じであり、アルゴリズム自体のメモリI/Oをさらに削減したわけではない。ハードウェア評価ではこの比較条件をそろえて演算器の差を測る。

## 評価

### 評価設計と測定粒度

| 評価軸 | 条件 | 解釈上の注意 |
|---|---|---|
| 論理合成 | Catapult HLSでC++からVerilogへ変換 | ASICのHLS設計でありGPU実行ではない |
| プロセス | 28nm標準セル | 別プロセスへの面積比・電力比は未実証 |
| 周波数 | 500MHz、initiation interval=1 | パイプライン遅延はdにより8〜12サイクル |
| hidden dimension | d=16、64、256 | すべてのLLM head dimensionを網羅しない |
| 演算精度 | FP32とBF16、ExpMul内部は16bit固定小数点近似 | 演算器以外は対応するFP形式 |
| 面積 | 1 Query向けFlashAttention-2演算カーネル | SRAM/DRAM/システム全体面積ではない |
| 電力 | Cadenceデジタル実装とPowerProの推定、FLAN-T5+GLUE実行 | メモリ・I/O電力は除外 |

| 比較対象 | 分離型指数近似器＋FP乗算器 | 同じFlashAttention-2計算順序を維持 |

原著は、比較した二つのカーネルが同じクロック・パイプライン条件で動くよう設計している。指数関数器の比較ベースラインにも近似を用い、同じような入力範囲へ制限する。電力はFLAN-T5とGLUEを実行した際の演算カーネル平均であり、GPUカード全体やLLMサービス全体のワット数ではない。論文の図は面積と電力の値をd・精度別に示すが、HTMLの図から読み取れない個別絶対値は推測しない。

### 面積・電力の改善（原著Figure 3・4）

| 指標 | ExpMul版と分離型版の比較 | 備考 |
|---|---|---|
| 演算カーネル面積 | 平均約28.8%減 | 28nm、d=16/64/256、FP32/BF16の複数構成 |
| 演算カーネル平均電力 | 要旨は17.6%減、本文は17.8%超減 | 記述間に約0.2ポイントの差がある |
| パイプライン条件 | 500MHz、II=1 | 遅延8〜12 cyclesの条件を維持 |
| メモリ電力 | 評価に含まない | アクセス順序・データフローは同じと仮定 |

著者らはExpMulによってd個の乗算器と指数関数器の負担を減らし、dが大きいほど電力節約が増える傾向を報告する。これは同じ計算カーネルをASICで作る際の回路資源の削減であり、GPUソフトウェアの速度向上率や同じ電力予算でのモデルTPS向上率とは別である。面積が28.8%減ったことを、GPU HBM使用量やパラメータ数が28.8%減ると解釈してはならない。

要旨では平均電力改善17.6%、§V-Bでは17.8%超と表現される。異なる集計または丸めによる可能性はあるが、原著が理由を明示していないため、ここでは**記述差を残して**約17.6〜17.8%と記載する。単一の精密な値に統一して捏造しない。さらに「power」は演算部の平均電力であり、エネルギー/トークンやシステム全体の電力量ではない。

これらは10課題のうちの代表的な行である。精度が改善する課題があるからといって近似演算器の方が本質的に優秀とは言えず、論文も低精度の数値的揺らぎと説明する。逆にBF16-ExpMulのCoLAやMNLI-mmで悪化しているため、すべての課題で完全に精度不変とも言えない。F1の列では同じaccuracyでも差がある場合があり、評価指標ごとの感度を区別する必要がある。比較したモデルはFLAN-T5であり、一般的なdecoder-only LLMの長文脈生成品質やKVキャッシュの影響を直接測定していない。

### なぜ単純なソフトウェア融合では同じ結果にならないか

本論文の節約は、整数shift-addと浮動小数点指数部減算の専用回路が、従来の指数関数器・FP乗算器より小さいという物理設計上の利点に依存する。CUDAで`exp(x)*V`を一つのソース式にしても、GPUのハードウェア演算器がExpMulに置き換わるわけではない。GPUではSIMD/SIMT実行、レジスタ圧力、コンパイラ最適化、Tensor Core利用、命令発行幅など別のボトルネックが支配する。ASIC合成の面積・電力改善を、llama.cpp、vLLM、SGLangへ直接適用できる性能値として扱わない。

## 主要結果と実装上の意味

提案の核は、FlashAttention-2の分母と出力を同じベクトル演算として扱い、`exp(x)*V`を**指数の2冪近似＋FP指数部更新**へ変換することにある。オンラインsoftmaxの計算順序は保ち、追加の全注意行列も作らない。ASIC演算器の構成を単純化することで、28nmで面積約28.8%、演算部電力約17.6〜17.8%の節約を報告する。GLUEによる機能検証では大幅な品質崩壊は見られないが、一部のBF16課題には負の結果がある。

この研究の適用先は、FlashAttention-2を専用アクセラレータのデータパスとして実装する場面である。特に多数のQueryブロックを複製する設計では、一つのブロック当たりの演算器面積削減が全体の面積予算へ効く可能性がある。ただしメモリ系、NoC、制御、入出力、FFN、モデル重みストレージは本研究の評価範囲外であり、SoC全体の面積・電力節約率は別途測る必要がある。

## 既存研究との差

FlashAttentionとFlashAttention-2は主に注意計算のI/O量とGPU上の実行効率を改善する。本論文は同じオンラインsoftmaxをASICへ落としたときの非線形演算・乗算の回路を対象にする。SoftermaxやSOLEなどのsoftmax近似ハードウェアは指数関数や正規化自体を軽量化するが、ExpMulは指数計算と後続のValue乗算を一体化する点が異なる。整数のみでattention全体を処理する量子化アクセラレータとも異なり、FP32/BF16の値表現を保ったまま指数スケーリング部分だけを近似する。

FPの指数部を更新して2の整数冪を掛けるという構成は、softmaxの指数差が常に非正であるという性質を利用する。汎用の`exp(x)*V`演算でxが正や極端な範囲を取る場合には、そのまま適用できない。対象をFlashAttention-2の特定の更新式へ限定したことで、回路を簡略化できている。attentionの数学的意味を変えずに演算器を近似する方向だが、数値誤差があるためFP32/BF16とのビット同値性は保証しない。

## 限界・負の結果・再現条件

第一に、ASICカーネルの面積・演算部電力推定であり、エンドツーエンドのLLM推論性能を測っていない。DRAM/SRAM、I/O、NoC、FFN、重みメモリ、制御回路を含むシステム全体の面積・電力ではない。比較対象のデータフローが同じためメモリ電力も同じと仮定するが、実際のチップ配置やメモリ階層によっては別のボトルネックが支配する可能性がある。

第二に、近似指数演算による精度差がある。BF16-ExpMulのCoLAは72.0から69.0へ、MNLI-mmは83.3から82.1へ低下する。著者はGLUEの範囲では大きな悪化ではないと解釈するが、他のモデルや長文脈生成、数値的に厳しい注意分布に対する保証はない。固定小数点16bit、[-15,0] clipping、shift-add近似という設定に依存し、別の浮動小数点形式へ無条件で一般化できない。

第三に、評価したhidden dimensionは16/64/256、FP形式はFP32/BF16、プロセスは28nm、クロックは500MHzである。先端プロセス、複数チップ、実際の大規模LLMサービング、動的バッチ、prefill/decodeの混合負荷は検証していない。原著要旨と本文に電力改善率の記述差（17.6%対17.8%超）があり、比較値を厳密な単一数字にしない。

第四に、HLSのソースコードは著者のGitHubリポジトリで公開されているが、今回実機で再合成・実行したわけではない。HLSツール、28nmライブラリ、Cadenceフロー、PowerProによる電力推定を再現するには商用EDA環境と標準セルライブラリが必要になる。コードが公開されていることと、すべての評価条件が無償で再現可能であることは異なる。
