# Online normalizer calculation for softmax

## 概要
通常の数値安定softmaxは、まず入力最大値を求め、次にexp(x-max)の和を求め、最後に各要素を正規化する。この安全な実装は同じベクトルを複数回メモリから読む。本論文は最大値と指数和を同じ走査で更新するオンライン正規化子（online normalizer）を導入し、古典的softmaxと数学的に同じ結果を保ちながらメモリアクセスを減らす。Tesla V100のベンチマークでsoftmax単体を最大1.3倍、TopKと融合した処理を最大5倍高速化した。

## 問題設定
softmaxは演算量自体よりメモリ読み書きが律速になりやすい。naive softmaxはexpのoverflowを避けられず、safe softmaxは最大値を先に引くため追加走査が必要になる。特に大きな語彙やattention行で、同じデータを繰り返しHBMから読むことが効率を下げる。

## 手法
入力x_jを左から処理し、時点jのrunning maximum m_j=max(m_{j-1},x_j)を更新する。同時に正規化和d_jを d_{j-1} exp(m_{j-1}-m_j)+exp(x_j-m_j) と更新する。新しい最大値が出た場合、過去に足した指数和を新しい基準へ再スケールするため、最大値を最後まで知らなくても正しい和を維持できる。

この漸化式により、safe softmaxの「最大値を探す走査」と「指数和を計算する走査」を一つへ融合できる。最終的なmとdが得られた後、各要素についてexp(x_i-m)/dを計算すれば通常の数値安定softmaxと同じ値になる。

論文はd_jが1以上j以下に保たれることを示し、running maximumを使った再スケールが数値安定性を壊さないことを証明する。近似softmaxではなく、計算順序だけを変える厳密な最適化である。

さらにTopKがsoftmax後に必要な場合、オンライン走査とTopK選択を融合できる。softmax出力を一度メモリへ書き戻して別kernelでTopKを読む経路を避けるため、単体softmax以上にメモリトラフィックを削減できる。

## 評価条件
NVIDIA Tesla V100上で、ベクトル長とバッチ数を変えてsafe softmax、online softmax、softmax+TopKを比較する。大バッチでは帯域律速の傾向が明確になり、理論的なメモリアクセス削減と実測速度を対応付ける。

| 観点 | 内容 |
|---|---|
| GPU | NVIDIA Tesla V100 |
| 比較 | safe softmax vs online softmax |
| 単体softmax | 最大約1.3倍 |
| softmax+TopK | 融合で最大約5倍 |
| 性質 | 近似ではなく古典softmaxと同値 |
| 主因 | メモリアクセス削減 |

## 主要結果
大きなベクトル・大バッチではonline softmaxがsafe softmaxに対し最大約1.3倍となる。これは要素あたりのメモリアクセスが概ね4回から3回へ減る理論上限1.33倍と整合する。

softmaxとTopKを別々に行う代わりに融合すると、条件によって1.5〜5倍の高速化を報告する。Kが大きくなるとTopKの管理計算が増え、利得は縮小する。したがって高速化は常に5倍ではなく、ベクトル長、バッチ、K、帯域律速度に依存する。

## 既存研究との差
softmaxの近似や関数置換ではなく、safe softmaxの厳密な値を維持したまま走査回数を減らす点が特徴である。このrunning maxとrunning normalizerの考え方は、後のFlashAttention系でブロックごとのsoftmax状態を結合する際の基礎的構成要素にもつながる。

## 限界
論文はsoftmax kernel単体とTopK融合の評価であり、Transformer全体やLLMサービングのエンドツーエンド速度を測っていない。小さいベクトルや低並列度ではメモリ帯域以外の固定費が支配し、理論上の1.33倍へ届かない。TopK融合の大きな利得もKが増えると縮む。
