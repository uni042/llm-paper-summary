# Online normalizer calculation for softmax

## 概要
本論文は、数値安定なソフトマックス（softmax）で通常別々に行う「最大値探索」と「指数和の計算」を一回の走査へまとめるオンライン正規化子（online normalizer）を提案する。入力を順に見ながら現在の最大値と指数和を同時更新し、新しい最大値が現れたときだけ過去の和を新しい基準へ再尺度化する。

近似関数へ置き換えるのではなく、通常の安全なソフトマックスと同じ結果を保ったままメモリアクセス回数を減らす。NVIDIA Tesla V100のFP32実装では、ソフトマックス単体を最大約1.3倍、上位K選択（TopK）まで融合した処理を条件により最大約5倍高速化した。

## 問題設定
素朴なソフトマックスは (exp(x_i)) を直接計算するため、大きな入力で指数がオーバーフローし得る。標準的な安全実装はまず最大値 (m=\max_i x_i) を求め、次に (sum_i \exp(x_i-m)) を計算し、最後に各出力を正規化する。

この方法は数値的には安定だが、最大値探索、指数和、正規化のため同じベクトルを複数回読み書きする。ソフトマックスは演算密度が低いため、GPUでは指数演算よりメモリ転送が律速になる条件が多く、余分な1走査が実時間へ直接効く。

## 手法
### 1. 最大値と正規化和を同時に更新
入力を左から処理し、時点 (j) の最大値を

[
m_j=\max(m_{j-1},x_j)
]

と更新する。同時に指数和 (d_j) を

[
d_j=d_{j-1}\exp(m_{j-1}-m_j)+\exp(x_j-m_j)
]

と更新する。

もし (x_j) が新しい最大値でなければ (m_j=m_{j-1}) なので、過去の和へ新項を足すだけになる。新しい最大値なら、過去に旧最大値を基準として足した指数和全体を (exp(m_{j-1}-m_j)) 倍し、新しい基準へ変換する。この再尺度化により、最終最大値を事前に知らなくても安全な指数和を一回の走査で維持できる。

### 2. 数値安定性
論文はオンライン更新中の正規化和が1以上、処理済み要素数以下に保たれることを示す。最大値を引いた指数は常に1以下なので、素朴な (exp(x)) のようなオーバーフローを避けられる。

最終的な最大値 (m) と正規化和 (d) が得られた後、各要素へ (exp(x_i-m)/d) を適用すれば、標準的な安全ソフトマックスと同じ結果になる。変更しているのは計算順序であり、確率分布の定義ではない。

### 3. メモリアクセス削減
標準の安全ソフトマックスは概念的に、最大値探索、指数和、出力計算にまたがって入力・出力へ約4回のメモリアクセスを要する。オンライン方式は最大値探索と指数和を融合し、約3回へ減らす。

完全にメモリ帯域律速なら理論的な上限高速化は (4/3\approx1.33) 倍である。V100で観測された最大約1.3倍はこの上限に近く、「演算を減らした」というより「1回分のメモリ走査を除いた」効果で説明できる。

### 4. TopKとの融合
復号などではソフトマックス後に上位K要素だけが必要になることがある。論文はオンライン正規化とTopK選択を同じ処理へ融合し、ソフトマックス結果を一度グローバルメモリへ書き戻して別カーネルが再読込する経路を避ける。

この場合は単体ソフトマックスの1走査削減より大きく、中間結果の書出し・再読込と別カーネル起動の双方を減らせる。ただしKが大きいほどTopK候補管理の計算が支配的になり、融合による利得は縮む。

## 評価条件
NVIDIA Tesla V100上のFP32実装で、ベクトル長とバッチ数を変えながら、標準の安全ソフトマックス、オンラインソフトマックス、ソフトマックス＋TopKの分離実装と融合実装を比較した。大バッチではGPUが十分占有されて帯域律速へ近づく一方、小バッチでは起動遅延や低占有率の影響が相対的に大きくなる。

TopKではKも変化させ、候補管理計算が増えたときに融合効果がどう縮むかを測定している。

## 主要結果
ソフトマックス単体は、メモリアクセスを約4回から3回へ減らすことで最大約1.3倍高速化した。これは帯域律速を仮定した理論上限約1.33倍と整合し、オンライン漸化式の追加演算がメモリ走査削減の利益を打ち消していないことを示す。

ソフトマックスとTopKを融合した条件では、バッチ約4000の大規模並列条件で、分離した安全ソフトマックス＋TopKに対し最大約5倍の高速化を報告する。一方、バッチ10程度ではおおむね1.5〜2.5倍で、GPUを十分使い切れないため帯域削減の効果が小さくなる。

Kを増やすとTopK内部の比較・候補保持が支配的になり、融合の相対利得は低下する。したがって「5倍」は特定の大バッチ・小K寄りの条件であり、オンライン正規化そのものの単体利得は最大約1.3倍である。

## 既存研究との差
数値安定性を捨てた近似ソフトマックスではなく、標準ソフトマックスの厳密な値を保ったまま走査回数を減らす点が特徴である。現在最大値が更新されたときに過去の指数和を再尺度化する考え方は、後のブロック化注意カーネルで部分ソフトマックス統計を結合する際にも使われる基本原理となった。

## 限界
評価はTesla V100上のソフトマックス／TopKカーネルであり、Transformer全体やLLMサービングのエンドツーエンド遅延を直接測っていない。小さいベクトルや小バッチではカーネル起動・低占有率が支配し、理論上の1.33倍へ届かない。

TopK融合の大きな利得もKとバッチに強く依存する。さらに現代のGPUではソフトマックスが注意行列積と融合されることが多いため、この単体カーネルの絶対倍率をそのまま移植するのではなく、「オンライン正規化で中間行列の物理化を避ける」という原理として読む必要がある。
