# CoRun：推論の決定性を保ちながらGPUの高速カーネルを使うスケジューリング

## 概要

CoRunが扱うのは、温度や乱数シードを固定したにもかかわらず、同じプロンプトから異なるトークン列が生成される現象である。GPUの浮動小数点加算は結合法則を満たさないため、動的バッチの要求数が変わって演算の分割・集約順序が変わると、最下位ビットの差が生じる。自己回帰生成では、その差が後続のトークン選択を変えて拡大する。再現性が重要なモデル比較や強化学習のロールアウトでは、単なる見かけのゆらぎではなく運用上の問題となる。

従来の対策はバッチ不変（batch-invariant）カーネルに置き換え、入力バッチのサイズや位置にかかわらず同じ順序で計算することだった。しかしこれではGPUが入力形状に応じて分割を最適化できず、行列積や注意機構の並列分割を制限する。CoRunは、一般的な高速カーネルが「バッチ数が変わっても同じ」ではなくても「バッチ形状を固定すれば位置を変えても同じ」である点を利用する。要求ごとの実行形状を制御すれば、カーネルを全面的に置き換えず決定性を得られる。

提案は、①事前計算（prefill）を要求単位に隔離、②復号（decode）を最大同時要求数まで埋めた固定形状のCUDAグラフで実行、③標本抽出の乱数状態を要求へ結び付ける、という三つの接続された機構からなる。位置不変でない例外には固定木の集約通信と復号時のSplit-KV禁止を適用する。vLLM 0.25.0で三つの大規模モデルを評価し、バッチ不変実装に比べて出力トークンスループットを15〜324%改善し、平均初回トークン待ち時間を51.8%、平均出力トークン間隔を48.6%短縮した。ただし低並列時の固定長埋め草は重いという明確な制約がある。

## 問題設定と計算上の原因

### 動的バッチで浮動小数点の演算順が変わる

連続バッチ処理（continuous batching）では、復号中の要求へ新しい要求が加わり、完了した要求が外れる。行列積や正規化のカーネルは、その時点のバッチ行数や縮約次元に応じてスレッドブロックを割り当てる。例えば四要素の和について、二つの処理器へ分割する場合の `(a+b)+(c+d)` と、一つの処理器で逐次計算する場合の `((a+b)+c)+d` は、実数として同じでも浮動小数点では一致しない場合がある。論文の図3は、バッチ数1と4で同じ行の縮約木が変わる例を示す。

注意機構のSplit-KVは長い鍵・値列を複数の分割へ割り当て、部分和を結合する。バッチに含まれる要求やKV長が変わると分割数と結合順が変わり得る。行列積のSplit-Kも同様である。したがって乱数シードだけを固定しても、GPU上の計算経路が同じとは限らない。

### バッチ不変と位置不変の違い

バッチ不変とは、ある要求が異なるバッチサイズ・位置・同時要求集合へ移されても、その要求の出力が一致する性質である。位置不変（position-invariant）は、バッチの形状を同じに保ったまま要求の並びだけを入れ替えた場合の出力一致を要求する、より弱い性質である。論文は置換行列Pについて `F_n(PX)=P F_n(X)` を位置不変性の定義とする。後者では形状nごとに異なる最適タイルを選んでもよく、同じnの内部でだけ一貫した演算順序を保てばよい。

著者らの実装表では、平均、RMS正規化、ソフトマックス、行列積は通常実装でも位置不変だがバッチ不変ではない。一方、リング方式の全GPU集約通信とSplit-KV付きFlashAttentionは位置不変ではない。固定木の全GPU集約通信とSplit-KVを無効にしたFlashAttentionは両方の性質を満たす。つまり形状固定だけで十分とはせず、例外演算子を明示的に置換・制限するのが重要である。

バッチ不変版の平均・RMS正規化・ソフトマックスは、論文の単体測定で通常版より2.12〜5.61倍遅く、行列積では縮約次元によって最大36.2倍の遅延が報告される。これは演算子単体の数字であり、サービング全体の倍率ではない。Qwen3-235B-A22Bのバッチ32・可変文脈の例では、バッチ不変版の一復号ステップ88.4ミリ秒に対し、通常版19.4ミリ秒、CoRunは32.6ミリ秒であった。高速化の主因は行列積などの位置不変な通常カーネルを再利用できることにある。

## 手法

### 1. 孤立した事前計算（isolated prefill）

事前計算ではプロンプト長が大きく変動するため、全要求を一律の長さまで埋めると無駄が多い。CoRunは各要求の事前計算を「バッチサイズ1」として実行する。これにより、ある要求のプロンプトが同じなら他の要求の到着順や長さが変わっても、事前計算の演算形状は同じになる。ここでは位置不変性さえ不要で、同じ要求を単独実行することが再現性の根拠になる。

実装はvLLMの既存スケジューラを置き換えるのではなく、その前後で実行待ちキューと実行中キューを一時的に退避・復元するラッパーである。まず既に事前計算中の要求があれば、その分割事前計算を継続する。なければ待機中の要求から一つ選ぶ。ただし最大同時要求数を超えず、予定された要求の全系列をKV容量へ収容できることを確認してから投入する。これにより後の容量不足による再計算・先取りを抑制する。

選択した要求だけを元のスケジューラへ見せ、事前計算の計画を作った後、退避した他要求を元の順序で復元する。モデル実行器には通常の単独事前計算が渡るので、別の実行経路を実装する必要がない。要求固有のプロンプト長に依存して分割が決まるため、事前計算中のSplit-KVは残してよい。この点は復号時にSplit-KVを禁止する規則と区別しなければならない。

代償として異なる要求の事前計算をまとめる効率が失われ、長い要求の後ろに並んだ短い要求の初回トークンが遅くなる。論文はこの負担を測定しており、決定性が無償で得られるとは主張しない。

### 2. 固定形状の一括復号（fixed-shape batched decode）

復号では各要求が一反復につき一つの照会トークンを処理するため、最大同時要求数をNとすれば、各反復をN行の固定形状へ揃えられる。CoRunは既存のCUDAグラフをN行だけ捕捉し、実際の要求がN未満なら無効な埋め草トークンを加えて同じグラフを再生する。論文の設定例では `cudagraph_mode=full_decode_only`、`cudagraph_capture_sizes=256`、`max_num_reqs=256` を組み合わせる。すべての復号反復は256行のグラフを使い、形状依存のカーネル分割が反復ごとに変わらなくなる。

固定の照会行数だけでは、各要求のKV長が異なる問題は解決しない。Split-KVはKV長と分割割当てによって縮約順序を変えるので、CoRunは復号時だけSplit-KVを無効にする。またGPU間通信はリング型ではなく固定木で集約する。これらを適用した上で、位置不変の通常カーネルが256行のどこに要求を置いても同じ演算順序を使うことを利用する。

GPUグラフは起動の固定費を削減するが、空スロットにも一部計算が必要になる。256要求が活動中なら大部分が有効な処理であり、1要求しかないなら255行が無駄になる。したがってこの機構は高同時実行のオフライン推論向けであり、低負荷の対話型APIへそのまま適用すると性能が悪化する。

### 3. 形状を揃えた標本抽出と要求単位の乱数状態

モデルが同じ対数確率を返しても、標本抽出器がバッチスロットごとに乱数生成器を管理していると、要求の位置が変わった際に別の乱数を消費し得る。CoRunは標本抽出器の入力も事前計算時は一行、復号時はN行へ揃え、乱数生成器の状態をバッチ位置ではなく個々の要求へ結び付ける。無効な埋め草が本来の要求の乱数を消費しないこと、完了した要求を取り除いても他要求の乱数列が変わらないことが必要である。

これにより同じ要求について、同じ対数確率と同じ乱数が与えられる。単なる貪欲復号だけでなく、シード付き多項分布標本抽出についても決定性を検査できる。標本抽出は捕捉したCUDAグラフの外側で動くため、モデル入力の固定化だけでは不十分という実装上の注意点がある。

### 4. 決定性の成立条件

論文は要求状態をプロンプト・生成済みトークン・KVキャッシュ・標本抽出設定と定義し、帰納法で同一性を論じる。基底段階では孤立事前計算が同じ要求状態と乱数初期状態を作る。次の復号段階では、同じN行の形状と位置不変演算子、固定木通信、復号時Split-KV禁止により、同じ要求が異なるスロットへ移っても対数確率とKV更新が一致する。最後に要求単位の同じ乱数が同じトークンを選ぶ。これを生成の各反復で繰り返す。

ただし、この保証は**同じ重み、同じGPU・ソフトウェア構成、同じ数値形式、同じテンソル並列度**を前提とする。GPU世代、カーネル版、並列構成をまたぐビット単位の再現性まで証明したものではない。位置不変でない新規カーネルを組み込めば、前提の再検証が必要になる。

## 評価

### 評価環境と比較の設計

| 項目 | 一次論文の設定 | 解釈上の注意 |
|---|---|---|
| 推論エンジン | vLLM 0.25.0 | 他バージョンへの一般化は未検証 |
| モデル | Qwen3-235B-A22B、DeepSeek-V3、Hy3 | アーキテクチャが異なる三系統 |
| 比較対象 | 通常の非決定的実行（STD）、バッチ不変実行（BI）、CoRun | STDは決定性を保証しない |
| 負荷 | BurstGPT、Blazedit、固定入出力長の合成負荷 | 各負荷から300要求を抽出 |
| 主指標 | 出力トークン/秒、初回トークン時間、出力トークン間隔 | 統計量と対象条件を区別 |
| 決定性試験 | 32プロンプトを単独実行とバッチ32で比較、温度0.6、シード42、最大8トークン | 生成列と各段階の標本抽出対数確率を比較 |

性能比較では同じモデル、同じテンソル並列度、同じメモリ制限、同じ要求集合を使う。論文の集約スループットは、各負荷の処理時間を重みとする時間加重平均であり、六つの数値を単純平均したものではない。決定性の試験では三モデルとも32プロンプトの全生成列と各ステップの標本抽出対数確率が一致した。ただし、これは固定された評価構成での検証であり、あらゆる外部条件での一致を実証したものではない。

上記の15〜324%は「バッチ不変実装BIに対する改善」であり、通常の非決定的STDを一律に上回ることを意味しない。DeepSeek-V3の入力4096・出力128の条件ではCoRunがSTDを上回った例があるが、これはSTDの混合事前計算・復号が特定のMLA注意実装でCUDAグラフ再生を阻害するためであり、普遍的な優位ではない。

### 時間経過と要素除去から分かること

BurstGPTのQwen3-235B-A22Bでは、通常実行STDは事前計算を約20秒、復号を約37秒で完了した。BIは事前計算約40秒、復号約124秒を要した。CoRunは最初の約30秒を単独事前計算に使い、この間復号を行わない。その後の復号ではSTDのピークに近い性能を出す。つまり性能改善は事前計算の直列化を無視したものではなく、復号で取り戻した利得がBIに対する全体性能を押し上げた結果である。

要素除去実験は、埋め草、復号Split-KV禁止、孤立事前計算を切り分ける。可変KV長でのSplit-KV禁止は15〜41%の損失、KV長が近い場合は1〜9%の損失である。孤立事前計算は複数プロンプトの同時処理と事前計算・復号の混合を諦めるため、STDとの差を大きくする。これらは決定性と高速化が完全に両立するわけではないことを示す。

## 既存研究との差

バッチ不変カーネル方式は、同じ要求が任意のバッチ形状に入っても同じ縮約木を使うよう、行列積・正規化・注意演算の内部を制限する。CoRunはその代わりに、要求が観測する形状をスケジューラで制御する。したがって通常の最適化された行列積を利用しやすいが、孤立事前計算と埋め草というスケジューリング費用を払う。

LLM-42のように高速な非決定的経路で一旦生成し、別の決定的経路で検証・巻き戻しする方式とも異なる。CoRunは未検証のトークンを発行せず、検証器も追加せず、そもそもの計算経路を要求単位で固定する。差は、計算を後で正すか、実行前に同じ形状へ制約するかである。

## 限界・適用条件

最大の弱点は低同時実行時の埋め草である。論文の単独要求試験では、埋め草サイズが64を超えるとBIよりも遅くなる。高負荷の評価・強化学習ロールアウトで多数の要求が並ぶ状況を想定しており、常時少数の対話要求を処理するサーバーには適さない。バッチを可変長に戻せばこの費用は減るが、CoRunの決定性証明の前提を失う。

孤立事前計算は要求間の待機を増やす。BurstGPTの長い入力が待ち行列の先頭に来ると、後続の初回トークン時間が階段状に悪化する。Split-KV禁止の性能損失も、要求間のKV長が不揃いなとき大きい。いずれも、負荷分布によって効果が変わることを意味する。

決定性は同一のハードウェア、モデル、ソフトウェア、並列構成を前提にする。異なるGPUや数値精度間でのビット一致、未知のカーネルが追加された場合、さらに広い負荷・モデルでの厳密保証はこの評価の範囲外である。コード公開先は一次資料から独立して確認できず、現時点で実装の第三者再現性を保証できない。
