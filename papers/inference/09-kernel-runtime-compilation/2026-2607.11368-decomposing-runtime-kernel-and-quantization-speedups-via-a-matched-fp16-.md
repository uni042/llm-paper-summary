# Decomposing Runtime, Kernel, and Quantization Speedups via a Matched FP16 Intermediate: A Hardware-Conditioned Case Study on Four NVIDIA RTX A5000 GPUs

> FP16中間構成を挟んで高速化を実行系1.90倍と核・量子化1.36倍へ分け、広いバッチでは実行系が対数で約3分の2を占めること、4枚分割は約1.5倍に留まり不足の約8割が調整作業であることをA5000の4枚構成で示した。

## 概要

推論提供の高速化は、完成した構成を丸ごと入れ替えて測られることが多い。例えば「参照実装から最適化された量子化構成へ替えるとスループットが10倍になる」という数値には、重みの形式、行列積の核、推論実行系の3つの変更が束ねられている。この束ね方では、実務の問い、すなわちどの部分が効いているのか、量子化の品質費用を払わずに実行系だけ替えてもどれだけ得られるのか、モデルが1枚に収まるのに分割する意味があるのか、に答えられない。

本論文は、RTX A5000（24GiB）を4枚持つ単一ホストという、学術・産業の集積系でよくある中位の構成で、この帰属を測る事例研究である。方法の核は中間構成の追加である。速い実行系であるvLLMを、量子化核なしのFP16重みのまま走らせる構成を挟むことで、全体の倍率は「実行系の倍率」と「核と量子化の倍率」の積にちょうど分解される。著者らはこの分解が構成上成り立つ恒等式であり、因果的な独立性を主張するものではないことを繰り返し明記する。

中心となる結果は、交絡を除いた統制条件のものである。本番に近い運用条件では、参照側のバッチ上限8と標本抽出方式の違いが混ざり、全体10.62倍、実行系の対数寄与86パーセントという大きな数値が出る。しかし生成方式を貪欲に揃え、参照側もバッチ64で走らせた3回の統制測定では、同時64要求・出力256トークンの条件で全体は2.58倍、内訳は実行系1.90倍と核・量子化1.36倍、対数寄与は実行系67.9パーセントだった。核と量子化の倍率は、Llama、Mistral、Qwenの7Bから8B級3モデルで最大1.46パーセントしか動かず、この部分のモデル間安定性が確認された。同時実行数を掃引すると、実行系の倍率は広いバッチほど育ち、核と量子化の倍率は約2.4倍から1.36倍へ縮む。

もう1つの主題は4枚の使い方である。1実例を4枚へテンソル並列で分割しても、スループットは単一カードの1.37倍から1.58倍にしかならず、倍増にも届かない。プロファイラの追跡では、広いバッチでの1トークン当たりの不足分の約8割が分割間の調整作業であり、同じハードウェアでの対照ではNVLinkとPCIeの実効帯域がこの大きさの伝送ではほぼ同じだったため、帯域の説明は退けられた。小さいモデルでは長い出力の条件で分割が勝ち、広いバッチでは複数実例が勝つという交差があり、70Bでは2枚ずつの2実例が全条件で平均約7パーセント勝ち、結論が逆転した。さらに、FP16は同時96要求で再現性のあるメモリの崖に落ち、量子化した両構成は同時256要求まで失敗なしで到達し、持続可能な同時利用者数が約4倍に伸びた。

## 問題設定

帰属の問題は、測定の設計の問題である。両端の構成だけを比べると、得られるのは積だけであり、因率は原理的に分離できない。分離には、片方の軸だけを変えた中間点が少なくとも1つ必要になる。ところが提供系の比較では、実行系を替えるとバッチの組み方、キャッシュの管理、標本抽出の方式まで一緒に変わるのが普通であり、中間点を置いても別の交絡が入り込む。本論文が運用条件と統制条件の両方を報告し、その差自体を結果として扱っているのはこのためである。

資源の観点では、広いバッチで不足するのは行列積の演算そのものではなく、バッチを途切れなく埋め続ける调度と、キャッシュの断片化を避ける管理である。参照側の実行系は、要求ごとに連続したキャッシュ領域を確保し、固定バッチが終わるまで次の要求を入れないため、同時実行数が増えるほど遊びが増える。対して量子化核の利得は、重みの読み出しが支配的な生成段階で大きく、同時実行数が増えて注意や调度の割合が増えると薄まる。つまり2つの倍率は同時実行数に対して逆向きに動き、1つの代表条件の数値だけでは系の性格は分からない。

分割の問題も同じ構造を持つ。テンソル並列は各層の行列積を複数カードへ割り、結果を全員で集約する。計算は分かれるが、各生成段階で小さな集約を何度も行うため、伝送量ではなく起動と同期の固定費用が支配的になり得る。特に量子化で1トークン当たりの計算が軽くなった条件では、この固定費用の相対的な重さが増す。帯域の公称値だけを見て分割の可否を判断すると、この費用を見落とす。

## 手法のあらまし

対象は3つの構成である。参照構成はHuggingFace系の実行環境に独自のバッチ调度を載せたFP16、最適化構成はvLLMにMarlinの4ビット整数核を組み合わせたGPTQ量子化、中間構成はvLLMのままFP16重みを使う構成である。各条件で3構成のスループットを測り、実行系の倍率を中間÷参照、核と量子化の倍率を最適化÷中間として定義する。寄与の配分は、倍率の対数を全体の対数で割る対数寄与で表す。測定は2つの形状、全7条件で行い、本番に近い運用条件の単回測定に加えて、生成方式と実効バッチを揃えた3回の統制再測定を全条件へ拡張する。続いて、同じ4枚について、1実例の4分割、1枚ずつの4実例、70Bでは2枚ずつの2実例を同じ費用で比べ、プロファイラで不足分の内訳を追い、接続方式を変えた対照で帯域の説明を切り分ける。最後に同時96要求以上での容量掃引で、FP16のメモリの崖と量子化による到達範囲の拡張を測る。

## 手法

### 1. 中間構成による乗算分解 — 1つの中間点で積を分ける

観測するのは、同じ条件における3構成のスループットであり、保持する状態はその3つの実測値である。動作は、中間構成のスループットで割ることで、全体の倍率を実行系の倍率と核・量子化の倍率の積へ分けることであり、この積が全体と一致するのは定義上の恒等式である。寄与の大きさは対数寄与で比べる。倍率の積に対して対数の比はきれいに配分できるが、単純な倍率の比では先に測った側が過大になるためである。

この設計で減るのは、帰属の不可能性というボトルネックであり、追加で消費する資源は中間構成の測定そのものである。失敗時の挙動として重要なのは、この分解が分けられないものを正直に残す点である。実行系の倍率の中には、連続バッチの调度、ページ化したキャッシュ管理、行列積以外の最適化核が混ざっており、核と量子化の倍率の中にも、核そのものと重みの読み出し量の削減が混ざっている。これらをさらに分けるには別の軸の中間点が要り、現在の実行系では簡単には作れないことが明記されている。つまりこの方法は「2つに分けた」のであって「原因を特定した」のではなく、その境界を著者らが線引きしている点に価値がある。

### 2. 統制再測定 — 交絡を1つずつ潰して数値を締める

最初の運用測定には2つの交絡があった。参照側はHTTPの包みを通してバッチ上限8で動き、生成は貪欲法であり、最適化側は非同期の実行系で同時64まで連続バッチを使い、確率的な標本抽出だった。統制再測定では、生成方式を全構成で貪欲法に揃え、参照側は過程内でバッチ64として上限を外し、3回の独立した実行で測り直す。保持する状態は条件ごとの変動係数であり、代表条件では全構成とも5パーセントの目安を大きく下回る。

結果として、実行系の倍率は7.56倍から1.90倍へ縮み、核と量子化の倍率は1.40倍から1.36倍とほぼ動かなかった。この非対称が示すのは、運用数値の膨張の主因が参照側のバッチ上限にあったという見立てであり、標本抽出方式の分離は今後の課題として残された。失敗時の挙動として、调度の構造そのもの、ページ化したキャッシュと埋め込み型のキャッシュの違いまでは揃えられておらず、統制条件でも実行系の内部は完全には均一でないことが注意されている。それでも、運用の数値と統制の数値はどちらかが正しいのではなく、本番で入れ替えたときに見える数値と、条件を揃えた帰属の数値という、違う問いへの答えとして併記される。

### 3. 分割と複数実例の同費用比較 — 4枚の使い方を比べる

分割の評価では、単一カードの最適化構成を基準に、4枚へ分割した構成の倍率を全7条件で測る。結果は1.37倍から1.58倍、幾何平均1.49倍であり、理想の4倍はおろか実務的な倍増の目安にも届かない。次に同じ4枚を、1枚ずつの4実例にルータで振り分ける配置と比べる。長い出力の条件では分割が約1.28倍から1.30倍勝ち、同時32以降の広いバッチでは複数実例が勝ち、同時64では1.46倍の差がつく。同時128では分割構成が起動時にメモリ不足で落ち、複数実例だけが毎秒7243.57トークンで存続した。

不足分の機構は2つの独立した測り方で確かめられる。スループットから逆算した1トークンの遅延と、提供ライブラリ自身のトークン単位の計時を直接読んだ値が、1ミリ秒未満の差で一致する。その上でプロファイラの追跡により、広いバッチでは不足分の約8割が分割間の調整であることが示された。追加で消費する資源は集約通信そのものであり、失敗時の挙動として、分割側は実行ごとのばらつきも大きく、通信する相手が多い構成ほどホスト側の揺らぎを増幅することが観測されている。複数実例側にも失敗の形があり、単純に4倍へ線形に伸びるのではなく、軽い負荷では実効効率が3割前後まで落ちる。ホストの処理装置とメモリバスと保存経路を4実例で奪い合うためであり、負荷が上がるほど効率は回復する。

### 4. 接続の対照と70Bでの逆転 — 帯域の説明を切り分ける

帯域が原因なら、速い接続へ寄せれば不足は縮むはずである。同じハードウェアで、組になる2つのランクをNVLinkのブリッジ側とPCIe側へ固定して比べる対照では、この大きさの段階ごとの伝送量では両接続の実効的な削減帯域がほぼ同じだった。各集約の費用が起動と同期の固定費用で支配されるため、接続の公称速度が効かないのである。したがって分割の不足は帯域ではなく、集約の回数と参加枚数に帰せられる。

この見方は70Bの結果で強められる。量子化した70Bは1枚に収まらないため、4分割の1実例と、2枚ずつの2実例を比べる。2実例は全7条件で勝ち、平均の改善は約7パーセント、最も広いバッチでは1.17倍だった。遅い接続へ寄せた対照でも平均約5パーセントの優位が残る。プロファイラでは、4分割の1実例は2実例の合計より約200倍多い明示的な削減呼び出しを出し、計算とほぼ同じ時間を調整へ使っていたのに対し、2実例では調整はほぼゼロだった。参加枚数が2枚になると、調整の大半が高速なメモリ内経路へ移るためである。減るボトルネックは調整の回数そのものであり、大きいモデルでは1トークンの計算が重いため固定費用の相対的な重さも下がる。小さいモデルで長い出力の条件に限って分割が勝った結論が、大きいモデルでは全条件で逆転する理由はこの2点にある。

### 5. 容量掃引 — メモリの崖と到達範囲を測る

容量の評価では、同時96要求以上で3構成を測る。FP16は同時96で全ての実行がメモリ不足となり、576件全ての要求が失敗する崖が3回とも再現した。量子化した両構成は同時256まで失敗ゼロで到達する。ここで著者らは、通常のスループットに加えて、スループットへ同時要求数を掛けた独自の提供有用性得点を併記する。これはスループットの改善ではなく、到達できる同時利用者数と提供速度を1つの数へ混ぜた運用の物差しであり、その性質が本文で繰り返し注意されている。

読み分けが重要である。参照の実行系の上では、量子化は同じ負荷ではFP16より遅く、利得は到達範囲だけから来る。対して最適化構成は、同じ負荷でも約10倍速く、到達範囲も広い。ただしこの2構成の差は実行系と核の両方を含むため、容量の領域での差を実行系だけへ帰属させることはできない。中間構成も同時96以上ではメモリ不足で測れないため、この領域では分解自体が成立しないことが明記されている。

## 評価

結論は、帰属、配置、容量の3つである。帰属では、広いバッチでは実行系の変更が高速化の主部であり、量子化の品質費用を払えない場合でも実行系の入替えだけで統制条件の全体2.58倍のうち1.90倍が得られる。配置では、分割はこのハードウェアとこの大きさの伝送では積み上がらず、結論はモデルと条件で逆転する。容量では、量子化は持続可能な同時利用者数を約4倍へ伸ばすが、その内訳は構成によって全く違う。

評価の土台は、単一ホストのA5000を4枚、2枚ずつのNVLinkブリッジとペア間のPCIeという1つのハードウェア構成である。プロンプトは平均約12トークンの合成した10件の固定プールであり、実務の分布ではないことが脅威として挙げられている。条件は長い出力の4条件と広いバッチの3条件で、実行回数は測定の世代によって単回、3回、5回と異なる。主対象はLlama-3.1-8B-InstructのFP16（約16GiB）とGPTQ-INT4（約5.7GiB）であり、70Bは量子化重みのみ、核と量子化の倍率の複製にはMistral-7BとQwen2.5-7Bが使われる。ソフトウェアはCUDA 12.4、vLLM 0.7.3、PyTorch 2.4である。

数値の読み方として、運用条件の10.62倍と統制条件の2.58倍は矛盾ではなく、測り方の違いである。また提供有用性得点の44.30倍はスループットの倍率ではない。さらに、分割の倍率1.5倍前後は「4枚で1.5倍しか得られない」という配置の非効率を示す数値であり、単一カード同士の比較と混同してはいけない。

## 既存研究との差

隣接する提供系の研究は、1つの実行系の内部を最適化するものが中心であり、接頭辞のキャッシュやプリフィルとデコードの分離、调度の改良はいずれも実行系の中での改良である。本論文は実行系をまたいで測り、完成形の高速化のどれだけが実行系の入替えで説明できるかを、中間構成を置くことで分離した点が異なる。量子化の系譜も、数値手法と専用核と実行系を束ねた完成形として headline の数値を報告するのが通例であり、本論文の分解の作法はそれらにもそのまま適用できる一般的な測定法として提示されている。ベンチマークの標準化の系譜が完成形の数値を報告するのに対し、本論文は中間点を欠いた数値は後から分離できないことを示し、今後の提供ベンチマークへ中間構成の併記を求める点で補完的である。分割と複製のトレードオフを論じる先行研究が大規模な構成を扱うのに対し、本論文は4枚の単一ホストという小さい構成で、調整の固定費用が支配的になる領域を実測した点が異なる。

## 限界・実装状況

- ハードウェアはA5000を4枚使う1構成のみであり、4枚全てを1つの高速な交換構造へ載せる構成、新しい世代のカード、ホストへ処理を逃がす構成への一般化は未評価である。
- 対象モデルは8B級が中心で、70Bは量子化重みのみ、他の2モデルでは参照構成を移植していないため、実行系の倍率のモデル間安定性は未評価である。確認されたのは核と量子化の倍率だけである。
- 運用条件と統制条件の実行系の倍率の差は、バッチ上限と標本抽出方式の分離が未完であり、どちらの寄与がどれだけかは未確定である。
- プロンプトは短い合成のものだけであり、入力が長い分布ではプリフィルの比重が変わり、分割の評価も変わり得る。
- 実行回数は測定ごとに単回から5回までばらつき、分割構成は最もばらつきが大きい。クロックや熱の統制もない。
- 他の2つの提供実行系は、集積系側の不整合で導入できず未評価である。3構成の分解自体は変わらないが、実行系の結論の一般性は限られる。
- 実装状況として、測定スクリプトとJSON成果物を含むコード公開物への言及と、付録の成果物一覧があるが、一次資料中に公開アドレスは示されていない。

## 一般的な実装上の含意

提供系の高速化を報告するときは、完成形同士の倍率だけを置かず、軸を1つだけ変えた中間構成を少なくとも1つ併記すべきである。中間点がなければ、後から寄与を分けることは原理的にできない。また、倍率の比較は条件を揃えた統制数値と、本番で見える運用数値を分けて扱う必要がある。バッチ上限のような周辺条件が、主役に見える倍率を数倍に膨らませることがある。配置については、帯域の公称値ではなく、1生成段階当たりの集約の回数と参加枚数、そして伝送量の小ささを見るべきである。小さな伝送では起動と同期の固定費用が支配し、速い接続へ替えても不足は縮まらない。モデルが1枚に収まる場合は分割より複数実例が既定の候補になり、収まらない場合でも、実例を分けて参加枚数を減らす方が1つの大きな分割より良い場合がある。最後に、量子化の評価では固定負荷の速度と到達できる同時実行数を分けて報告すべきであり、両者を混ぜた得点は性質を明記して使う必要がある。
