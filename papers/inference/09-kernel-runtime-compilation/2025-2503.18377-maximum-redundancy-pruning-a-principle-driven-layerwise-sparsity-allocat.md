# Maximum Redundancy Pruning：冗長度の再測定に基づくLLMの層別疎度配分

## 概要

本論文は、大規模言語モデルの重み枝刈りで「**全層に同じ疎度を設定すること**」が精度を損ねる理由を実験的に調べ、その結果から層別疎度を決めるMaximum Redundancy Pruning（MRP）を提案する。WandaやSparseGPTは重要でない重みを見つける強力な局所枝刈り規則だが、どのTransformerブロックへどれだけの削減量を割り当てるかという別の問題が残る。特に全体の70%を削る高疎度では、ある層を削ると出力が急激に悪化する一方、別の層はさらに削っても影響が小さい。層間の差を無視すると、重要層の破壊を引き起こす。

著者らは層別感度の非一様性、感度の枝刈り指標依存性、削減後の層別冗長度の均一性という三つの観測を示した。MRPは、C4校正データを用いて各層の「外れ値でない重み」の比率を測り、**最も冗長なブロックを少しずつ追加枝刈りし、毎回その比率を再計算する**。一度だけ計測して線形写像で配分するOWLと異なり、上流層の削減が下流の活性化分布を変えることを反映できる。

70%疎度のLLaMA2-7Bでは、WandaのWikiText2困惑度が均一配分80.40、OWL 30.47、MRP 23.54となる。SparseGPTでも均一27.52、OWL 20.51、MRP 19.19である。実機ではLLaMA2-7B-chat-hfをDeepSparseでCPU復号したとき、密モデルの390.38msに対して70%疎度で222.39ms、90%で181.37msを報告する。ただし、これは**CPUの疎行列処理系における特定の復号実験**であり、GPU一般やすべての量子化・枝刈りカーネルで同じ倍率が得られるという主張ではない。

## 問題設定と三つの設計原則

### 層別感度の不均一性

モデルMのうち層lだけを所定疎度で削ったモデルをP(M,R_l)とし、元モデルとの性能差を層別枝刈り感度（LPS）と定義する。論文はLLaMA2の7B/13B、OPT-6.7B、Vicuna-7B、Mixtral、LLaVAなどで、Magnitude、Wanda、非構造・半構造・構造化枝刈りを組み合わせてこの感度を調べる。表1では同じモデル内の感度最大値と最小値が大きく異なり、疎度を上げるほど差が拡大する。例えばLLaMA2-7Bの80%非構造Magnitudeでは感度最小0.15、最大16.00と桁違いになる。

ここから導く第一原則は「**全層同一ではなく、削減への耐性に応じた非一様な疎度**」である。これは、深い層ほど常に重要という単純な位置則ではない。論文が示すのは、モデル・疎度・枝刈り方法ごとに感度を確認しなければ一律の割合は安全でないということだ。

### 枝刈り指標による感度順位の逆転

Magnitudeは重みの絶対値を中心に重要度を測り、Wandaは重みと入力活性化の大きさを組み合わせる。ある層がMagnitudeでは重要でもWandaではそうでない、という順位逆転が発生する。原著表3の感度順位逆転率はLLaMA2-7Bで21.37%、Baichuan-7Bで23.08%、OPT-6.7Bで23.39%、LLaMA2-13Bで9.62%である。したがって、Wandaに適した層別疎度配分をMagnitudeへそのまま流用しても最適とは限らない。

第二原則は「**層別疎度を、実際に使う枝刈り指標に依存させる**」である。表4のLLaMA2-7B・70%疎度では、Magnitudeは均一49911.45に対してOWL 59240.68とむしろ悪化するが、Wandaでは均一80.40に対してOWL 30.22と改善する。この対照は、冗長度だけから固定配分する手法の危険性を具体的に示す。

### 枝刈り後の冗長度を揃える

第三原則は、枝刈り後に各層に残る冗長度をなるべく均等にすることである。著者らは外れ値の少なさを冗長度の代理量として使う。各層の入力活性化Xと重みWについて、要素ごとに `A_ij = ||X_j||_2 |W_ij|` を計算し、平均AのM倍を超える要素を外れ値とみなす。非外れ値比率 `D = 1 - (#outliers / #weights)` が層別冗長度（LRL）となり、実験ではM=5を採用する。Dが高いほど、外れ値ではない要素が多いという判定である。

著者らは、削減後の層別Dの最大値と最小値の差が小さい構成ほどWikiText2困惑度が低い傾向を示す。表5ではOPT-6.7Bの均一配分は最大最小差33.17ポイント、OWLは21.25ポイントであり、対応する困惑度は162.92から40.22へ改善する。ただし、これは観測された相関であって、Dの差を小さくすれば任意のモデルで必ず最適になるという一般定理ではない。外れ値の閾値、校正入力、枝刈り指標の選択によって結果は変わる。

## 手法：Maximum Redundancy Pruning

### 1. 校正入力から冗長度を計算する

入力は元モデルM、初期疎度r、目標の全体疎度r_T、初期追加削減幅s_0、最小幅s_min、幅減衰率αである。各Transformerブロックの入力活性化をC4の校正データで観測し、重みと掛け合わせた外れ値スコアから非外れ値比率を計算する。実装上の疎度配分単位は論文の用語上の細かい個別線形層ではなく、**Transformerブロック単位**である。ブロックの内部重みを削る規則はMagnitude、Wanda、SparseGPTのいずれかを選べる。

ここでの「冗長」は単に重みが小さいことではない。入力活性化を考慮した外れ値の比率が少ないことを、重要な情報を残しながら削れる余地の指標としている。重要度推定は正解率の勾配やHessianを各反復で最適化するわけではなく、既存の枝刈り手法と組み合わせるための配分側の軽量な指標として設計されている。

### 2. 小疎度での一律初期枝刈り

Algorithm 1では最初に全ブロックへ初期疎度rを設定し、指定した枝刈り規則Pを適用する。低疎度では層間の感度差が小さいという予備実験に基づき、この初期処理で後続の反復回数を削減する。目標が大きくない場合には、この段階で十分な削減量に達する可能性がある。初期処理後、モデル全体の実疎度r_cを測り、目標r_Tと比較する。

この初期処理は高疎度の一律枝刈りを正当化するものではない。論文表16では20%程度の疎度ではUniform、OWL、MRPの差が小さいが、70%へ近づくほど一律配分の困惑度が急激に悪化する。つまり初期一律処理は計算時間を節約するための限定的な近似であり、最終配分の主役は次の反復である。

### 3. 最も冗長なブロックへ逐次追加配分

各反復で、現在の削減済みモデルから全ブロックのLRLを再計測し、最大値のブロックIDを選ぶ。そのブロックの目標疎度だけをs増やしてP(M,R)を再適用する。次に追加削減幅を `s ← max(s α, s_min)` へ更新し、全体疎度r_cがr_Tに到達するまで繰り返す。出力は、各ブロックに異なる疎度を割り当てて枝刈りしたモデルである。

この更新には二つの意味がある。第一に、冗長度が高い層を優先して削るため、層別疎度は自然に非一様になる。第二に、毎回枝刈り後のモデルで入力活性化と外れ値比率を測り直すため、**先行するブロックの変更によって後続ブロックの冗長度が変化した場合も追随する**。OWLのように最初の冗長度から一度だけ疎度を写像する手法では、この相互依存を直接取り込めない。

論文§4.2は、最大冗長度D_iの層を少量削ってD_iがε下がり、最小D_jを下回らないなら、`max(D)-min(D)` は増加しないという局所的な説明を与える。これは枝刈り後の冗長度均一化を動機づけるが、任意の削減幅・閾値で全体の困惑度が単調改善することまで証明していない。実装ではs_0、s_min、α、校正データの選択が反復回数と品質を左右する。

### 4. 既存の枝刈り手法と推論ランタイムへの接続

MRPは、個々の重みを削る新しいGPUカーネルではなく**層別疎度の割当アルゴリズム**である。各反復でWanda等を呼び、出力として疎行列重みを持つモデルを得る。推論時にはMRPの冗長度測定は走らないが、実際の速度を得るにはゼロ重みを効率的に処理する実装が必要になる。重みをゼロ化しただけの密行列積では、FLOPsやメモリ転送が自動的に減るとは限らない。

著者のCPU速度測定はDeepSparseという疎行列実行エンジンで行っている。GPU上でのMRP自体の校正時間と、CPUでの推論時間は別々の環境で計測される。RTX 4070 SuperのようなGPU上での推論効果を評価するには、対象の疎性パターンを扱えるカーネルとランタイムを指定した追加ベンチマークが必要である。

## 評価

### 評価設定と比較対象

言語モデルの主評価はLLaMA2-7B/13B/70B、LLaMA3-8B、OPT-6.7Bで、WikiText2の困惑度とBoolQ、RTE、HellaSwag、WinoGrande、ARC-e、ARC-c、OpenBookQAのゼロショット精度を比較する。配分方式はUniform、OWL、MRP、枝刈り指標はMagnitude、Wanda、SparseGPTである。主表は**70%全体疎度**での比較であり、同じ疎度・同じ枝刈り指標の行同士を比べる。困惑度は低いほどよい。

著者は視覚・マルチモーダルへの拡張としてConvNeXt-Base、DeiT-BaseのImageNet-1KとLLaVA-1.5-7BのMM-Vetを調べる。これらは主にWandaによる50〜70%枝刈りの精度評価であり、LLM推論速度の測定とは分ける必要がある。枝刈り時のLRL計測はNVIDIA A100、実機デコードは32コアIntel Xeon Platinum 8358PとDeepSparseで行う。

### 70%疎度の言語モデル困惑度

原著表6のうち、改善が明瞭な行を抜き出す。各値はWikiText2検証困惑度で、値が小さいほどよい。

| LLaMA2-7B / Wanda | 80.40 | 30.47 | **23.54** |
| LLaMA2-13B / Wanda | 45.42 | 17.91 | **15.18** |

WandaとSparseGPTではMRPがOWLより一貫して低い困惑度を示すが、70%という高疎度では密モデルの困惑度（LLaMA2-7Bで5.47）からの悪化自体は残る。Magnitudeの行はMRPでも14,055.67と著しく大きく、単に配分法を変えただけでは枝刈り指標の破壊的な性質を完全には解決できない。改善を「密モデルと同等の精度を維持した」と表現するのは誤りである。

### ゼロショット精度と負の結果

表8ではLLaMA2-7B・70%疎度で、Wandaの7課題平均精度が均一37.32%、OWL 43.27%、MRP 46.42%となる。SparseGPTでは均一45.20%、OWL 47.46%、MRP 48.37%。MRPは平均を改善するが、すべての個別タスクで勝つわけではない。例えばLLaMA2-7BのSparseGPT・ARC-eではOWL 45.33%に対しMRP 45.29%、ARC-cでは25.94%に対し25.85%と僅かに下回る。LLaMA2-13BのSparseGPT・OpenBookQAでもOWL 37.60%に対しMRP 36.40%である。全指標で厳密優位という主張を避けるべきである。

同じく表13では、Wandaで枝刈りするならWandaから得た配分がよいという対角線優位の傾向を確認する。ただしMagnitudeで得た配分をWandaへ適用したLLaMA2-7Bの一部組合せはNaNとなっており、異なる指標間の配分移植は破綻し得る。さらに表16の20%疎度では各方式の困惑度が近く、MRPの追加校正費用に見合う精度利得が小さい。高疎度を主な適用範囲とする理由である。

### 推論速度とオフライン処理費用

表9はLLaMA2-7B-chat-hfのDeepSparse・32コアXeonによる**エンドツーエンド復号遅延**を測る。密モデル390.38ms／2.56 tokens/sを基準に、70%疎度では222.39ms／4.50 tokens/s／1.76倍、90%疎度では181.37ms／5.51 tokens/s／2.15倍となる。一方10%疎度では402.71ms／0.97倍、20%では409.20ms／0.95倍、30%では399.37ms／0.98倍で、低疎度は密モデルより**遅い**。疎性処理のオーバーヘッドが削減効果を上回る領域が存在することを示す重要な負の結果である。

表10のLRL計算累積時間はA100でOPT-6.7Bが9.51分、LLaMA2-7Bが16.6分、13Bが20.93分、70Bが53.04分。これは推論リクエスト毎の費用ではないが、モデルを多数・頻繁に更新する運用では無視できない前処理時間となる。MRPの精度改善は一度だけ配分を計算して終わるOWLより高い校正コストと交換されている。GPUでのモデルロード時間や実運用SLOをこの表から推定しない。

### アブレーションと一般化の境界

表14の冗長度最大最小差は、Wandaを使ったLLaMA-7BでOWL 3.43ポイントに対しMRP 2.34、OPT-6.7Bで21.25に対し4.94となり、目的とする冗長度均一化を直接示す。表15のLLaMA1-7B・70%疎度ではUniform 81.18、BESA 42.58、DSA 24.50、MRP 23.22で、探索型の層別配分とも比較している。ただし、これらは特定モデル・指標での実験結果であり、一般の最適配分を数学的に保証するものではない。

表12ではLLaMA2-13Bを46%疎度にして約7B個の非ゼロ重みとし、C4の3万トークンでLoRA調整した場合、WikiText2困惑度5.42となり、密LLaMA2-7Bの5.47を僅かに下回る。LoRAなしでは5.60であり、**枝刈りだけで7B密モデルを超えたという結果ではない**。パラメータ数の比較と保存ファイル容量、推論メモリ消費、実機速度はそれぞれ異なる評価軸である。

表11の70%疎度ではConvNeXt-BaseのImageNet精度がOWL 62.97%、MRP 66.57%、DeiT-Baseは44.70%対49.72%、LLaVA-1.5-7BのMM-Vetは14.10対15.50となる。画像・マルチモーダルへの移植可能性を示すが、ここでの精度改善を「マルチモーダル推論が何倍高速化した」と読むことはできない。

## 限界と実装上の判断

第一に、MRPは冗長度の代理指標を最大化する局所反復であり、**最適な疎度配分を大域的に証明したアルゴリズムではない**。原著の局所的な最大最小差の議論は、最大冗長度を削っても最小を下回らないという小ステップの仮定に依存する。異なる閾値、活性化分布、重み表現、構造化パターンで同じ傾向が成立するかは追加検証が必要である。

第二に、校正データはC4を使うため、対象の業務ドメインや日本語・コード生成に分布が偏る場合は外れ値比率が変わり得る。原著の言語モデル評価はWikiText2と英語中心のゼロショット課題であり、推論サービングの長文脈KVキャッシュ、同時要求、MoE expertロード、混合精度カーネルとの相互作用を直接測定していない。枝刈りによる品質低下が許容できるかは、対象の下流タスクで再評価する必要がある。

第三に、**疎度と実効性能を区別**する必要がある。70%の重みがゼロでも、密なGEMMとして実行すれば計算量がそのまま残る可能性がある。GPUで有利な2:4半構造化疎性とCPUで有利な任意疎性は異なる。MRPの層別配分をGPUへ持ち込むなら、最終的な疎性パターンを実装可能なカーネルへ合わせ、品質とTPSを同時に測ることが必要である。

第四に、校正時間は最大約53分と大きい。少数モデルを長期運用するなら償却できるが、頻繁な再学習や多数のアダプタ別派生モデルを作る場合は負担となる。MRPの配分が異なる枝刈り指標へ一般化しないため、Magnitude用・Wanda用・SparseGPT用に配分を再計算する費用も見積もるべきである。

## 既存研究との差と位置づけ

Wandaは重みと活性化の積で要素重要度を評価し、SparseGPTは再構成誤差を考慮して削減対象を決める。MRPはそれらの置換ではなく、**各ブロックの削減量を決める上位の配分器**である。OWLは非外れ値比率を使う点で近いが、初期統計を層別疎度へ一度だけ写像するため、削減が進むことで下流活性化が変わる問題を扱いにくい。MRPは毎回測り直す反復を追加し、校正時間を費やして高疎度の品質を改善する。

実装を評価するときは「MRP+WandaとOWL+Wandaを同一疎度で比較」「SparseGPTの基底品質を維持」「CPU DeepSparseの実測をGPU性能へ一般化しない」という三点を守ると、論文の貢献と適用限界を区別しやすい。ローカルLLM向けには、まず量子化や既存の2:4疎性サポートとの併用可能性を確認し、VRAM削減と速度改善の両方を実測する必要がある。
