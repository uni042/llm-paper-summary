# ParallelFlow：線形注意の状態更新をフローへ変換して並列化を分解する

## 概要

ParallelFlowは、線形注意機構や行列値状態空間モデル（SSM）の逐次更新を、制御微分方程式（CDE）の区間フローとして表現する理論・アルゴリズム研究である。従来の線形注意はトークンを一つずつ処理すれば少ない演算で済むが、GPUでは系列方向の並列性が乏しい。一方、系列全体を行列演算に展開すると並列性を得られる反面、二次的な演算量や中間メモリが発生する。著者らはチャンクごとの状態遷移を独立に計算し、チャンク間の遷移だけを並列走査で合成する視点を提示する。

具体例として、キーに結び付く値を差分規則で更新するDeltaNetを、ランク1から一般の低ランクRへ拡張する。三角テンソルの逆行列を使う方式（tensorInv）と、ラフパス理論のsignature kernelに着想を得た方式（sigDelta）を導出し、理論上の並列計算量を比較する。原著表1では、tensorInvのO(L²R+d)に対してsigDeltaはO(LR+d)とされ、系列長Lについて一段低い次数になる。ただし、これは数式上の計算量であり、実際の推論速度がL倍になるという測定結果ではない。論文§4は、Tritonで必要なテンソルスライスを効率的に実装できず、sigDeltaの理論的優位を実機で再現できていないと明言する。

## 問題設定：系列方向の並列性と状態メモリの交換条件

通常の自己注意は長さLの系列に対して注意行列を形成するため、系列長に二次的な計算とメモリを要する。線形注意は過去のキーと値を行列状態Sへ集約するため、トークンごとの状態更新を使えば全履歴KVを保存する必要がない。しかし再帰式S_t=S_{t-1}+v_t k_t^Tを逐次評価すると、各時刻が直前の状態に依存する。演算回数が少なくてもGPUの大規模並列実行には不利になる。

一方、系列全体をQ、K、V行列として一括計算する形では、因果マスク付きの積により多数の時刻を並列に扱えるが、原著§1.2は計算量をO(L²d+Ld²)と説明する。逐次状態更新のO(Ld²)に比べ系列長に二次的な項が生じる。結合的な演算を並列走査へ変換すれば理論上O(log L)段の依存にできるが、各時刻のd×d状態を具体化するとメモリ転送量が増える。したがって「演算量を減らす」と「GPUで速く実行する」は別の問題である。

さらにDeltaNetでは、既存キーに対応する記憶を更新するために状態へランク1の変換を施す。元の更新はS_t=S_{t-1}-β_t S_{t-1}k_t k_t^T+β_t v_t k_t^Tであり、状態を掛ける行列はI-β_t k_t k_t^Tという低ランク摂動である。ランクRへ拡張すると表現能力を増やせる可能性があるが、従来のランク1専用カーネルをそのまま適用できない。ParallelFlowはこの低ランク構造を保持しつつ、チャンク計算とチャンク合成の両方を扱う。

## 手法

### 1. CDEの区間フローへの再定式化

原著§2は、行列値状態Sの連続時間更新を dS_t=S_t dω_t+dξ_t と書く。ωは状態へ右から作用する行列値の駆動過程、ξは入力からの加算成分に相当する。区間[s,t]における状態は、初期状態S_sに伝播行列P_{s,t}を掛けた項と、区間内で注入された入力を伝播させて積分した項の和として表される。

この形の利点は、区間をまたぐ依存性を「区間の入口の状態」と「区間内で決まる遷移作用素」へ分けられることである。P_{s,t}と入力の積分項をあらかじめ計算しておけば、途中のすべての状態S_rを順番に生成しなくても区間の出口状態を得られる。各区間のフローは入力系列から独立に計算でき、チャンク間はフローの合成という結合的な演算になる。ここでいう独立は、区間ごとの入力データが既知である場合の計算依存性を指し、自己回帰デコードの未来トークンまで事前に分かるという意味ではない。

### 2. チャンク分割、並列計算、並列走査

原著§3の手順は、(1)時刻範囲をチャンクへ分割する、(2)各チャンクの伝播行列と入力寄与を互いに独立に計算する、(3)チャンクの遷移作用素を並列走査で合成する、という三段階である。これにより、チャンク内部の計算方法とチャンク間の合成方法を分離できる。系列を細かく区切るほどチャンク内計算は小さくなるが、合成すべき区間数が増える。逆に大きなチャンクは合成回数を減らす一方、チャンク内部の行列計算が重くなる。

分割幅は単なる実装上のパラメータではなく、計算量、GPUの並列度、メモリ量、数値安定性を左右する。原著は一様分割のほか、駆動過程の変化に応じた適応分割や高次のlog-ODE法を今後の課題として挙げる。ただし、これらの適応分割方式が既に評価済みという意味ではない。論文が実際に詳細に導出するのは、低ランクDelta規則を離散化したチャンク内部計算である。

### 3. 低ランクDelta規則とテンソル逆行列法

原著§3.1は、ωとξの増分をA_t B_t^T、Ã_t B_t^TというランクRの積で表す。A、Ã、Bはいずれもd×Rの行列値経路であり、R=1の特殊な選択がDeltaNetの既存更新に対応する。これにより、d×dの密な遷移行列を直接扱わず、低ランク因子を使って区間のフローを構成できる。

離散化後の補助状態W、Uは、前時刻までのWまたはUとB^T Aの積を集計する三角型の再帰を満たす。時刻とランク次元をまとめた長さLRのテンソルへ変換すると、因果マスクMを使った線形方程式として書ける。原著定理3.3は、(I-M⊙AB^T)の逆を利用してWとUを得て、そこからチャンク出口S_1を再構成する。行列が三角構造を持つため、一般の密行列逆行列より構造を利用した計算が可能になる。

ただし、三角テンソルを明示的に構築するとO(L²R²)の項を含む中間メモリが必要である。従来のトークン逐次更新に比べ系列並列性を増やせても、メモリ制約の厳しい長系列ではこの二次的な作業領域が問題になり得る。定理は演算の正当性と理論上の並列計算可能性を与えるものであり、メモリ転送の少ないGPUカーネルの存在まで証明するわけではない。

### 4. Signature kernel由来の別解法

原著§3.2のsigDeltaは、前節の三角テンソル逆行列を明示的に計算せず、二つの時刻添字を持つ補助量W(t_m,t_k)を反対角線方向へ更新する。時刻t_kにおける解は補助量の対角成分W(t_k,t_k)から得られる。更新には過去の補助量の差と低ランク因子B^T(A_{k+1}-A_k)を用い、隣接した反対角線に依存する計算を並列化できるようにする。

この構成はラフパス理論で用いられるsignature kernelの計算再帰に似ている。著者らは同じ低ランクDelta規則の解を、逆行列法とは異なる計算グラフで求められることを定理3.5で示す。重要なのは、sigDeltaが注意の近似やトークン削除をするのではなく、同じ状態更新を別の計算手順で求める点である。精度が高いモデルを学習し直す提案でもなく、主眼は数学的に同値な更新の計算構造にある。

### 5. 行列指数による別表現

§3.3では区間フローを行列指数の積として表し、低ランク行列AB^Tの指数をR×Rの小さな行列の演算へ帰着させる関係も述べる。Euler型の離散化は指数の一次近似として理解でき、分割や離散化の選び方が数値精度へ与える影響を分析する道筋となる。ただし、この節で紹介された指数積の表現が、後述するTriton実装で実際に最速であると実測されたわけではない。本文の数式は可逆性などの前提に注意して扱う必要があり、数値的な特異点対策を含む完成ランタイム仕様ではない。

## 評価：理論計算量と実装上の到達点

### 比較条件と定量結果

本論文は主として理論解析とアルゴリズム導出であり、大規模LLMを用いた実運用のTTFT、TPOT、処理率、VRAM消費の統一ベンチマークではない。原著表1のLはチャンク内系列長、Rは低ランク次元、dは状態の次元に対応する。次の値は、表1に記載された**理論的な計算量のオーダー**であり、GPU実測の高速化倍率ではない。

| 指標 | tensorInv（定理3.3） | sigDelta（定理3.5） |
|---|---|---|
| 中間メモリ | O(L²R²+LRd+d²) | O(L²R²+LRd+d²) |
| 逐次計算量 | O(L²R(d²+Rd+LR²)) | O(L²R(d²+Rd+R)) |
| 並列計算量 | O(L²R+d) | O(LR+d) |
| 核心機構 | 三角テンソルの逆行列 | 対角線・反対角線方向の補助量更新 |
| 理論的な系列長次数 | 二次の項が残る | 一次の項へ低下 |

両方式のメモリの漸近次数は同じであるため、sigDeltaを選ぶだけで長文脈メモリがL倍節約できるとは言えない。表の「並列計算量」は論文が採用した理論上の並列計算モデルでの比較であり、CUDAスレッドの実行時間や帯域費用をそのまま示さない。実機で重要なメモリ読み書き、レイアウト変換、カーネル起動回数などは、この表から直接は分からない。

### 数値実装で確認された限界

原著§4は、理論上はsigDeltaが系列長Lについて一段低い計算量を持つにもかかわらず、Tritonでその優位を実現するのが困難だったと報告する。理由の一つは、将来時刻に対応するテンソル値を効率的に並列取得するためのスライス操作である。PyTorch実装ではtorch.rollに相当する操作を使うが、Tritonで同様の処理をGPU向けに効率よく表現するのが難しい。

もう一つは、B_{t_m}^T(A_{t_{k+1}}-A_{t_k})に関係する二次元テンソルから、反対角線の成分を取り出す操作である。sigDeltaの計算量削減に重要なこの操作がTritonの得意な連続メモリ参照と噛み合わず、理論上の並列化を性能へ変換できていない。著者らはPyTorchとTritonの実装を補足資料に含め、より低水準のCUDAカーネルと明示的なメモリ管理が今後必要だと述べる。従って「理論的にO(L)改善」と「GPUで実測L倍高速」は厳密に区別しなければならない。

### 品質・スケーリングの未評価項目

原著には、ランクRを増やしたときのモデル精度を大規模言語ベンチマークで比較した表や、Llama・Qwen級の生成モデルを使った実サービングの処理率表は見当たらない。低ランク更新がより豊かな表現を可能にするという動機は関連理論に基づくもので、提案カーネルによる下流精度改善の実測とは異なる。実際の精度や安定性は、離散化幅、浮動小数点丸め、R、チャンク長などに左右されるが、幅広い設定での定量的な最悪条件は今後の課題である。

## 既存研究との差

通常の線形注意は再帰式と並列行列積の間に、系列依存性と計算量の交換条件を持つ。DeltaNetの既存の高速実装は主にランク1の更新に合わせて設計されており、ランクを増やすと同じ手順を素直に拡張しにくい。ParallelFlowはまず行列値CDEを共通表現に据えることで、チャンク内部の遷移計算をアルゴリズムごとに交換できるようにした。

次に、低ランク因子を保った三角テンソル逆行列法を導出し、さらにsignature kernelの再帰から別解法を得た。これにより、特定のモデル名や一つのCUDAカーネルに依存せず、数学的な更新規則から計算グラフを設計できる。ただしこの抽象化はそのまま推論ランタイムへ組み込める完成品ではない。GPU上でどの演算を融合し、どの中間量を保存し、どのメモリ順序でアクセスするかは別の実装問題として残る。

## 限界と実用上の判断

本研究の最も重要な限界は、理論的に優れるsigDeltaの実機優位が未実証であることだ。Tritonのテンソルスライスと反対角線抽出がボトルネックとなり、計算量の漸近改善をカーネル実行時間へ変換できていない。PyTorchの実装があることをもって、GPU上の性能改善が実現済みだと扱ってはいけない。

また、理論上のメモリ量にL²R²の項が残るため、チャンク長とランクを大きくすると作業領域が膨らむ。GPU HBM容量やメモリ帯域が限られた実装では、演算量より中間量の配置が支配的になり得る。どのL、R、dで従来のDeltaNetカーネルを超えるか、実装時に数値誤差がどう変わるか、生成品質にどの程度影響するかは本文から確定できない。

さらに、区間フローの独立計算は既知の入力系列をまとめて処理する状況で特に意味を持つ。自己回帰デコードでは未来の入力トークンが未確定なので、prefill向け並列化の理論を1トークンずつのdecode高速化へそのまま読み替えられない。論文が示すのは状態更新を並列化する一般的な数理構造であり、E2Eサービング高速化の完成実装ではない。
