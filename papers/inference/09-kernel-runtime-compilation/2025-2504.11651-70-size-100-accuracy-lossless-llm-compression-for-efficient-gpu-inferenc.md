# 70% Size, 100% Accuracy: Lossless LLM Compression for Efficient GPU Inference via Dynamic-Length Float (DFloat11)

## 概要
DFloat11は量子化ではなく、BFloat16重みの**情報エントロピー**を利用する可逆圧縮方式である。LLMの重み値は16bit全域に一様分布せず、指数部・仮数部を含む値の出現頻度に強い偏りがある。そこで頻出値へ短い符号、稀な値へ長い符号を割り当て、平均格納長を約11bitへ下げる。復号後のBFloat16値は元重みと完全一致するため、量子化誤差を許容できない用途でも使える。

## 問題設定
大規模モデルがGPUメモリに収まらない場合、一般には低bit量子化かCPUオフロードを使う。前者は数値を変え、後者はPCIe/NVLink越しの重み転送が生成経路へ露出する。DFloat11は「精度を落とさず、重み転送量と常駐量だけを減らす」点を狙う。可変長符号は境界が不規則なのでGPUでの並列復号が難しく、単純なHuffman復号ではメモリ節約がカーネル遅延に相殺されることが主要課題となる。

## 手法
### 可変長重み表現
モデルごとのBFloat16値頻度を集計し、エントロピー符号を構成する。重みテンソルは可変長bitstreamとして保存されるため、圧縮率は値分布に応じて変わるが、実験対象ではおおむね元容量の70%前後となる。値そのものを近似しないため、復号後の行列積入力は元checkpointと同一である。

### 階層ルックアップ表
可変長bitstreamをGPUスレッドが逐次木探索すると分岐とランダムアクセスが増える。DFloat11は頻繁に使う復号情報を小型の階層ルックアップ表（lookup table; LUT）へ整理し、GPU SRAMに収める。スレッドはbit prefixから候補を引き、必要な追加bitだけを読むことで復号する。

### 二段階GPU復号
可変長符号では各スレッドが何個の出力を書き出すかが一定でない。提案カーネルは軽量な補助変数を用いる二段階処理で読取位置・書込位置を協調させ、並列スレッド間の衝突を避ける。復号単位は個々の行列ではなくTransformer blockを意識してまとめ、復号した重みが直後の演算で消費されるようにして一時メモリと起動回数を抑える。

## 評価条件
| 項目 | 内容 |
|---|---|
| モデル | Llama 3.3、Qwen 3、Mistral 3、Llama 3.1 405B、FLUX.1等 |
| 元形式 | BFloat16重み |
| 圧縮 | 可逆エントロピー符号化、平均約11bit相当 |
| 比較 | 非圧縮GPU常駐、容量超過時のCPUオフロード |
| 指標 | モデル容量、token throughput、最大生成長、出力同一性 |
| 大規模実証 | 810GBのLlama 3.1 405Bを8×80GB GPU単一ノードで推論 |

## 主要結果
モデル容量は約30%削減され、復号後出力は元モデルとbit-for-bitで一致する。固定GPUメモリ予算で非圧縮モデルがCPUオフロードを必要とする条件では、DFloat11は2.3〜46.2倍高いtoken生成スループットを示した。また同一GPU予算で扱える生成長は非圧縮モデルの5.7〜14.9倍となる。これは復号演算が無料だからではなく、PCIe越しに未圧縮重みを繰り返し搬送するより、圧縮重みをGPUに常駐させて局所復号する方が安い条件で大きく効く。

## 既存研究との差
GPTQ/AWQ等の量子化は重み値を近似してbit幅を下げる。DFloat11は元BFloat16値を完全復元するため、品質評価で「ほぼ同等」ではなく数値的に同一の推論を目標にする。一般的な圧縮ファイル形式とも異なり、推論hot pathでのオンラインGPU復号を前提にLUTとカーネルを設計している。

## 限界
圧縮率は重み値の頻度分布に依存し、常に30%削減を保証するものではない。モデルが十分小さく全重みを非圧縮のままGPUへ常駐でき、メモリ帯域も律速でない場合、オンライン復号の追加計算が速度利得を小さくする。activationやKVキャッシュは圧縮対象ではないため、長文脈でKVが支配的な構成のメモリ問題は別途残る。
