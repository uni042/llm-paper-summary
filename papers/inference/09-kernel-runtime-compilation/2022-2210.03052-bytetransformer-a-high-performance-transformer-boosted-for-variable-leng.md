# ByteTransformer：可変長入力の無駄を取り除くBERT推論カーネルの体系的最適化

## 概要

ByteTransformerは、バッチに混在する長さの異なる文章をBERT系のTransformerへ入力する際、最長文章に合わせたゼロ埋め（padding）で発生する計算とGPUメモリ転送の無駄を削減する推論実装である。主な対象は**双方向エンコーダの前向き推論**であり、長文を自己回帰的に生成するデコーダ専用LLMの実測研究ではない。論文の重要性は、入力の有効トークンだけを扱う表現と、注意計算の実行形態を一体で設計した点にある。

従来の可変長入力対応は、似た長さの文章をグループ化してから同じ長さへ埋める方法が多かった。しかしグループ内の長さが完全に一致しない限り、空白トークンの行列積が残る。ByteTransformerは、マスクの前方累積和（prefix sum）で有効トークンを連続領域へ詰め、元の位置を示す写像を保存する。注意計算は短系列と長系列で別の融合カーネルを使い分け、形状の異なる系列にもゼロ埋めを再導入しない。

著者らのNVIDIA A100・半精度浮動小数点（FP16）での測定では、融合多頭注意（fused multi-head attention、FMHA）がPyTorchの標準注意実装に対して**6.13倍**の性能を示した。12層BERTの端から端までの前向き実行では、PyTorch JIT、TensorFlow XLA、TurboTransformer、DeepSpeed-Inference、FasterTransformerと比較した平均処理性能改善をそれぞれ87%、131%、138%、74%、55%と報告する。改善率は「処理速度が何%増したか」であり、遅延が同じ割合だけ減ったという意味ではない。［一次論文：要旨、§III、§IV］

## 問題設定と既存方式との差

標準BERTのエンコーダは、入力から問い合わせ・鍵・値の三つの行列を作る線形射影、注意重みの行列積と正規化、出力射影、前向きネットワーク、残差加算、層正規化を繰り返す。バッチサイズを $B$、最大系列長を $L$、実際の系列長を $\ell_i$ とすると、一般的なゼロ埋め実装は $BL$ 個のトークンを扱うが、有効なものは $N=\sum_{i=1}^{B}\ell_i$ 個しかない。線形射影と前向きネットワークの不要な行は概ね $BL-N$ に比例し、注意の行列積では各系列の $L^2$ と $\ell_i^2$ の差が無駄になる。

先行するTurboTransformerは長さの近い文章をまとめるが、まとめた文章の長さは完全には一致しない。FasterTransformerは可変長を支援するものの、当時の融合注意実装には長系列に対する制約があった。PyTorch JITやTensorFlow XLAはカーネルを最適化できても、ゼロ埋めの無駄そのものは解決しない。ByteTransformerはモデルの枝刈りや追加学習で近似するのではなく、同じ演算の意味を保ったままデータ配置とGPU実行を変えることを狙う。

論文はA100上の標準BERT単層（バッチ16、注意ヘッド12、各ヘッド64次元）を計測し、最大長256と1024でボトルネックを調べた。系列が長くなると多頭注意の実行時間比率が増え、長さ1024では約49%に達する。一方、線形射影以外のバイアス加算・正規化・活性化にもグローバルメモリ往復が残る。このため、単なる有効トークン圧縮だけでなく、注意演算の融合とメモリ帯域節約が必要となる。［§II、§III-B、図3］

## 手法：入力から出力まで

### 1. 有効トークンの圧縮と位置写像

最初に入力の各位置に対する有効性マスク $M_{i,j}\in\{0,1\}$ を受け取り、CUDAカーネルで行方向の前方累積和を求める。各ワープが一つの文章のマスクを走査し、バッチ内で有効なトークンだけを連続した作業領域へコピーする。ここで同時に「圧縮領域の何番目のトークンが元のどの文章・位置に対応するか」という位置オフセット表を作る。例えば長さ5、2、4の三文を最長5でそろえると15行を処理するが、圧縮後は11行だけを処理する。

この位置表は単なる圧縮時の補助情報ではない。問い合わせ・鍵・値の射影、層正規化、活性化、出力の復元が元の系列境界を越えて混ざらないようにするための実行時契約である。特に自己注意は異なる文章間で注意してはいけないため、文章ごとの開始位置と有効長を参照して行列積を構成する。論文ではTensorFlow出力との要素単位比較で数値の整合を確認している。［§III-D、図4］

通常のバッチ行列積は各問題の形状が同一であることを要求する。そのため著者らは、通常の行列積に対しては圧縮表現を維持しつつ、注意演算へ入る直前に一時的な展開が必要な段階を明示している。注意終了後に再圧縮する経路もあり、論文の「全パイプラインでゼロ埋め計算を排除する」とは、**すべての中間配列が常に圧縮形式である**という意味ではない。展開・再圧縮の費用は、バイアス加算や転置といったメモリ演算に融合して目立たなくする。短・長系列用の専用注意カーネルを導入した最終構成では、注意の不要計算も取り除く。

計算量の表では、有効長比率を $\alpha=N/(BL)$ と置くと、射影や前向きネットワークの主要行列積は概ね $\alpha$ 倍の行数になる。一方、従来のバッチ注意行列積は形状固定のため、この改善をそのまま受けられない。融合注意を導入すると注意側でも有効長に応じた二次計算の削減が可能になる。ただし実際の速度向上はカーネル起動、メモリ移動、占有率に依存し、理論演算量削減率と一致するとは限らない。［表II］

### 2. 短系列用の融合多頭注意

最大系列長が短い場合、注意の $QK^T$、最大値減算、指数関数、総和正規化、$PV$ を一つのGPUカーネルへまとめる。論文は系列長384を短系列経路と長系列経路の切替目安とし、短い側では注意の中間行列を共有メモリとレジスタに保持する。ブロックごとに問い合わせの小片と対応する鍵・値を読み、位置写像から有効なトークンだけを参照する。

行列積はAmpere世代のテンソルコア用行列積命令（WMMA）を利用する。バイアス加算や縮尺調整はデータ読み込みに重ね、$QK^T$ の結果を共有メモリへ保持する。ソフトマックスでは各スレッドが必要な行の値をレジスタへ持ち、最大値と指数和の二段階の縮約を行う。次に値行列との積を計算して結果を書き出す。鍵と値の格納に同じ共有メモリ領域を使い回すため、メモリ容量を節約できる。

短系列経路では、問い合わせのタイル長（典型的には32または48）やワープ数がレジスタ・共有メモリ使用量を左右する。最大長が大きくなると全注意行を同時に保持できず、占有率や資源上限の問題が起きるため、同じ設計を無制限に延長できない。この制約が長系列向けの別経路を必要とする理由である。［§III-E.1、Algorithm III.1］

### 3. 長系列用の形状別行列積と正規化融合

長い系列では、各文章・注意ヘッドを別の行列積問題として扱う形状別行列積（Grouped GEMM）を採用する。通常の一括行列積（batched GEMM）は各問題の行列形状をそろえるが、Grouped GEMMは文章ごとに異なる実長を持つ行列積を一つの実行単位へまとめられる。問題数は概ねバッチ数と注意ヘッド数の積であり、CUDAスレッドブロックは複数問題のタイルを順番に引き受ける。

著者らはCUTLASSのGrouped GEMMスケジューラにも手を加え、従来一つのスレッドが担当していたタイル索引計算をワープの32スレッドへ分散する。スケジューラ訪問の回数を32分の1相当に抑え、標準BERT条件でGrouped GEMM自体を約10%高速化したと報告する。これは全BERT推論の10%改善という意味ではなく、当該行列積実装に対する内部効果である。［§III-E.2、図5・図7］

ソフトマックスは $QK^T$ の行列積結果から行方向の最大値と指数和を求める必要がある。著者らは行列積の出力後処理（epilogue）へ部分縮約を融合し、まずスレッド内、次にワープ内で縮約する。別スレッドブロック間の縮約は通常のCUDA実行モデルで直接同期できないため、小さな追加カーネルで全体縮約を行う。この全体縮約は融合注意全体の実行時間の約2%と報告されており、完全な単一カーネル化ではない。

最大値と指数和が求まった後は、次の行列積 $PV$ の主ループに正規化の要素演算を埋め込む。正規化係数をループ開始前に読み込み、共有メモリからレジスタへタイルを運ぶ段階で変換する。Ampereの非同期コピー命令 `cp.async` と複数段の読み込みパイプラインを使い、行列積の計算中にメモリ待ちを隠す。この仕組みにより、大きな注意中間行列を外部メモリへ何度も書き戻す費用を抑える。［§III-E.2、図6・図8、Algorithm III.2］

### 4. 層正規化・活性化の融合と処理の接続

注意以外では、残差とバイアス加算に続く層正規化を一つのカーネルへ統合する。別々に実行すると結果の書き戻しと再読込が必要になるが、融合するとレジスタ上で演算を続けられる。また、前向きネットワークの行列積出力へバイアス加算とGELU活性化を続けて適用するため、CUTLASSの出力後処理を拡張している。

一つのエンコーダ層を通す流れは、(1) マスクから位置表を生成して有効トークンを圧縮、(2) 圧縮した行を使ってQ/K/Vを射影、(3) 実長を使う短系列または長系列の融合注意を実行、(4) 残差・層正規化を融合、(5) 前向きネットワークの行列積とバイアス・GELUを融合、(6) 位置表に従って出力を復元し次層へ渡す、という接続である。位置表の維持と圧縮・展開の費用は追加されるが、無効トークンの行列積と余分なGPUメモリ往復を削る利益が上回る条件を狙う。［§III-C〜E］

## 評価条件と定量結果

### 測定環境と比較の前提

論文の主要実験はNVIDIA A100 GPU、CUDA 11.6u2、最適化フラグO3、主にFP16で実施された。ホストはIntel Xeon Platinum 8336Cを4基搭載し、CPUメモリは2TB。可変長系列は1から最大長までの一様分布を基本とし、結果は複数回の測定で平均化している。BERTの代表構成は注意ヘッド12、ヘッド次元64、12層であり、バッチサイズ1・8・16、最大系列長64〜1024を評価した。平均長が最大長の60%という条件を主要な横比較に用いる。［§IV冒頭、§IV-E］

比較対象の実装バージョンはPyTorch 1.13、TensorFlow 2.8、TurboTransformer 0.5.1、DeepSpeed-Inference 0.7.7、FasterTransformer 5.1である。これは2022〜2023年当時の比較であり、現在の各フレームワークの性能順位を保証するものではない。BERTの**前向き実行**を比較しており、生成時のキー・バリューキャッシュ、複数利用者の連続バッチ、初回トークン遅延などを測った実験ではない。

### 構成要素除去実験と内部指標

単層BERTの段階的な追加実験では、バイアスと層正規化の融合で約3.2%、GEMM後処理へのバイアス・GELU融合でさらに約3.8%の性能改善を示した。ゼロ埋め除去を追加すると、その直前の構成から約24%改善し、最後に融合注意を導入するとさらに約20%改善した。論文の「最終60%改善」はこの累積した単層比較の結果であり、各パーセンテージを単純に加算した値ではない。［§IV-D、図14］

注意単体では、短系列用融合実装と長系列用Grouped GEMM実装をそれぞれ評価する。短系列では共有メモリ・レジスタの再利用が、長系列では形状別行列積と正規化の融合が効く。長系列の最大長448〜1024・平均長比0.6という条件では、論文は標準PyTorch、cuBLAS実装、ゼロ埋めを除去したcuBLAS実装に対する性能改善をそれぞれ451%、110%、79%と記す。これは「標準PyTorchより451%速い」という形式の改善率であって「451倍」ではない。［§IV-C、図12］

重要な**負の結果**として、FlashAttentionとの注意単体比較では小バッチでByteTransformerの融合注意が平均101%高い処理性能を示す一方、大バッチではFlashAttentionが平均59%高い処理性能を示す。論文は、FlashAttentionが一つの注意問題を一つのスレッドブロックへ割り当てる方式であり、並列に割り当てる注意問題が少ない小バッチではGPUの利用率が低下し得ると説明する。逆に注意問題が多い大バッチではFlashAttentionの方が有利になり得る。すべての条件でByteTransformerが最速という主張ではない。［§IV-C、図13］

他モデルへの適用では、ALBERT（12層、16ヘッド）、DistilBERT（6層、12ヘッド）、DeBERTa（12層、12ヘッド）を扱う。ALBERT・DistilBERTでは複数の既存実装に対して優位だった一方、DeBERTaではFasterTransformerとTurboTransformerが対応していないため比較していない。またDeBERTaの系列長1024ではTensorFlowがメモリ不足となり、その測定点は除外されている。これは全モデル・全設定における一律の比較ができているわけではないことを示す。［§IV-F、表IV、図16］

## 実装上の示唆と限界

本研究は、実行時に変わる系列長を「固定長へ埋めてからGPUへ渡す」という上位APIの都合を、そのまま低水準カーネルの演算量へ持ち込まない設計例である。位置写像を一度作って線形層と注意演算の双方で利用し、短系列では共有メモリの収容量、長系列ではスケジューラと行列積タイルを最適化する。可変長バッチを大量に扱うエンコーダ型の検索・分類・埋め込み推論では、今でも原理的に重要な設計である。

ただし、短系列用と長系列用の切替閾値384は対象GPUのレジスタ・共有メモリ量、タイル寸法、モデル形状に依存する。実装はAmpere世代のテンソルコア、CUTLASS、非同期コピー命令に強く結び付いており、CPUや異なるGPU世代へ数値結果をそのまま移植できない。短文がほぼ存在せず有効長比が1に近いバッチでは、ゼロ埋め除去の利益が小さくなり、位置表の作成や圧縮・展開の固定費が相対的に目立つ。

評価はBERT系のエンコーダを中心とし、長いプロンプトを持つ自己回帰デコーダの事前計算（prefill）や、トークンごとの生成（decode）、KVキャッシュ再利用、GPU間分散、複数モデルの連続バッチは直接検証していない。したがって、現代のLLMサービングへ適用する際は、位置写像と可変長注意の考え方を移植する余地はあるものの、実装をそのまま使って同じ倍率を得られるとは限らない。

正確性の検証について、論文はTensorFlowの出力との要素単位比較を行ったと記すが、あらゆる精度・入力分布に対する厳密な数値一致を証明したわけではない。また、論文のベンチマークはランダムな可変長分布を主とし、実サービスの到着時刻、負荷変動、入力長の偏りに関する包括的な尾部遅延評価を提示しない。公開コードを現在のGPUで利用する場合は、CUDA・CUTLASSの版整合、対象形状、バッチ分布を再測定する必要がある。

## 関連研究との比較

TurboTransformerの類似長グループ化はゼロ埋めを減らすが、残余の埋めを計算する。FasterTransformerは可変長入力の支援を持つ一方、当時の融合注意カーネルは長系列に対する制約があった。ByteTransformerは位置写像を保持してゼロ埋めを取り除き、短系列では共有メモリ上の一体型注意、長系列ではGrouped GEMMと二段階縮約を組み合わせる点が異なる。FlashAttentionとの比較では小バッチに強い一方、大バッチでは劣るという条件依存性を明示した。これらは「注意の数値演算を近似する」研究ではなく、**同じ注意計算をどのデータ配置・カーネル分割で実行するか**の比較である。
