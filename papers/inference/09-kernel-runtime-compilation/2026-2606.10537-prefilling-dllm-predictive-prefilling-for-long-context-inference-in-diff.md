# Prefilling-dLLM：拡散言語モデルの長文入力を一度だけ処理する選択的事前計算

## 概要

本研究の対象は、文章の空欄を繰り返し埋める**拡散型大規模言語モデル（diffusion large language model、dLLM）**である。左から右へ1トークンずつ生成する自己回帰モデルとは異なり、拡散型モデルは複数の未確定トークンを同時に更新できる。しかし、一般的な実装では、出力の一部を確定するたびに、既に与えられた長い入力接頭辞までモデルへ再投入する。数万トークンの入力を何十回も処理すると、自己注意の計算と不要な再符号化が支配的になる。

**Prefilling-dLLM**は、この入力接頭辞を長さ一定の小区間へ分け、各区間の鍵・値（Key–Value、KV）表現を事前に一度だけ計算し、問い合わせに関係する区間だけを残して反復的な雑音除去（denoising）に再利用する方式である。さらに、区間内の重要トークン選別と、長いKVを複数の並列部分へ分割して処理する注意カーネルを組み合わせる。学習済み重みを変更する追加学習は不要である。

原著のDream-v0-Base-7B、単一A100、32出力トークンの条件では、標準Transformers実装に対する端から端までの生成高速化が入力長8Kで9.1倍、16Kで16.1倍、32Kで28.0倍となった。ここには擬似回答の作成、区間選別、KV構築、データ移動、反復生成を含む。一方で、全ての課題で高精度とは限らない。例えばInfiniteBenchのKV検索課題では、比較した拡散型モデルの方式がすべて0点であり、要約では語彙検索による区間選択に劣る条件もある。

## 問題設定と背景

### 自己回帰型のKVキャッシュをそのまま使えない理由

自己回帰型モデルでは過去のトークン表現を保持して次の1トークンの問い合わせだけを計算できる。因果的注意では、過去トークンが未来のトークンを見ないため、以前の鍵・値を再計算する必要がない。ところが拡散型モデルは双方向注意を使い、未確定位置が更新されると他の位置の表現も変化し得る。従来の雑音除去実装は、入力接頭辞・質問・未確定出力を合わせた系列全体を反復処理する。

接頭辞長を $L_p$、質問長を $L_q$、出力長を $L_d$、雑音除去回数を $T$ とすると、単純な全系列自己注意の計算量は概ね $O((L_p+L_q+L_d)^2T)$ である。長文脈では $L_p$ が大きいため、出力長が短くても反復のたびに大きな二次計算を支払う。自己回帰型の事前入力処理・復号分離（prefill–decode disaggregation）を、双方向拡散型へ移すには、入力表現のどこまでを固定できるかを決める必要がある。

### 長文脈の位置依存性を設計根拠にする

原著はDream-7Bで、正解文書の位置を変えた複数文書質問応答を測定した。学習時の文脈長2KおよびYaRNによる4K拡張では、各位置の完全一致率が1.0だったが、8K・16K・32Kへ拡張すると回答付近の情報へ注意が偏り、離れた位置の正解を落とす。自己回帰型でしばしば見られる両端優遇のU字型とは異なり、双方向の拡散型では出力に近い位置ほど強い傾向を示した。

また、出力から入力への注意重みは距離とともに減衰し、雑音除去が進むほど局所化する。ただし全体が滑らかに減るだけではなく、区間境界などの重要位置に局所的な突出があり、原著では主要な突出が注意質量の約25%を占める例を報告している。したがって、入力の全位置を毎回同等に再処理する必要はなく、重要な区間を問い合わせに応じて探せば、離れた証拠を失わずに計算を抑えられる可能性がある。

## 手法

### 1. 独立チャンクの事前入力処理

入力接頭辞を大きさ $C$ の非重複区間（chunk）に分割し、$N=\lceil L_p/C\rceil$ 個を得る。各区間の先頭には文頭識別子（beginning-of-sequence token、BOS）を付ける。各区間は他の区間を直接見ず、区間内の双方向注意で処理するため、全接頭辞の一括処理に比べ、長さが一定なら区間数にほぼ比例して事前計算を分割できる。各区間を独立に処理できるので、原理上は複数の装置で並列化できるが、論文の主要速度実験は単一GPUである。

質問だけでは検索すべき証拠が曖昧な場合があるため、著者らは短い仮回答を**擬似ラベル（pseudo-label）**として生成する。Dreamでは全入力を用いる短い雑音除去の前処理で、例えば4トークンの仮回答を得る。各区間と質問、仮回答を連結して双方向モデルへ通し、その区間に対応する鍵・値だけを取り出す。位置番号は区間ごとに0から振り直す。区間の境界と位置を独立化することで、長文全体を毎回参照しなくても区間内表現を準備できる。

この段階で得られるのは、すべての区間のKVを無条件に永続保持することではない。後続の選別に使う区間ごとのKVと関連度を計算し、最終的な復号キャッシュには選択した部分だけを組み立てる。論文の図3では「区間の事前計算→区間とトークンの選択→反復復号」の順にデータが流れる。

### 2. 質問と擬似回答による区間順位付け

各区間 $c_i$ の関連度を、質問に対する平均負対数尤度（negative log-likelihood、NLL）と、仮回答に対する平均NLLの二つで評価する。質問の各位置をマスクした際に、その区間を参照すると正しい質問トークンを予測しやすいほど質問側の得点が低い。擬似回答側も同様に、仮回答の予測を助ける区間ほど低い値を取る。

二つの得点はそれぞれ質問長と擬似回答長で割って正規化し、同じ重みで加算する。小さい合計得点を持つ上位 $K$ 区間を残す。この選択は単純な文字列一致ではなく、拡散型モデル自身の条件付き予測能力を使う。検索結果が選別された時点で固定されるため、反復中に必要な証拠が変化しても自動的に区間を選び直す仕組みではない。

擬似回答生成には追加の推論費用がある。原著のDream主要設定は4個の擬似ラベルトークンと1回の雑音除去であり、長い擬似回答を何回も精緻化する方式ではない。付録の構成要素除去では、擬似回答を増やしても性能が単調に良くならず、問い合わせだけの得点と同程度の結果になる条件も確認されている。したがって、区間順位付けの精度向上と初期計算量を同時に考える必要がある。

### 3. 区間内トークンの二方向重要度

区間選別だけでは、各区間の全トークンをKVとして保持する。そこで追加の区間内疎化（intra-chunk sparsity）では、質問から区間の各トークンへの注意重みと、逆方向の区間トークンから質問への注意重みを足し合わせ、質問に対するトークン重要度を求める。双方向モデルであることを利用した設計であり、片方向の注意だけを見た場合よりも証拠の選別を安定させる狙いがある。

各区間で得点の高い $B$ トークンだけを保持する。例えばDreamの主要条件では、1024トークンの区間を4個選び、各区間から512個を残す。区間選択だけなら復号対象の入力KVは4096トークン、区間内選別を併用すれば2048トークンとなる。ここで4096や2048は、元の128K入力のうち反復復号へ渡す選択接頭辞の予算であって、質問や生成中トークンを含む全系列長ではない。

選別を二段階に分ける理由は、異なる区間に分散した証拠を拾うことと、選ばれた区間内の無関係トークンを減らすことが別問題だからである。原著のLongBenchでは、区間間選別だけのDream平均22.01に対して、区間内選別を加えると34.59へ改善した。疎化を増やすほど必ず品質が下がるわけではないという、拡散型モデル固有の重要な観測である。

### 4. 固定KVキャッシュを再利用する反復復号

選択した区間のKVと質問のKVを固定キャッシュとして構築し、全雑音除去ステップで再利用する。各反復では出力側の未確定トークンの表現を更新し、既に固定した接頭辞側のKVは再計算しない。信頼度がしきい値を超えた未確定トークンから順にマスクを外し、出力が埋まるまで繰り返す。原著の式では、事前計算が $O(N(C+L_q+|m|)^2)$、復号が $O((L_d^2+KC)T)$ という形へ分離される。

この式はアルゴリズム上の注意計算量を示すものであり、実装のメモリ転送・カーネル起動・検索・擬似ラベル作成を全て消せるという主張ではない。特に双方向注意の情報を静的キャッシュへ固定するため、元の全系列再計算と厳密に同じ出力分布を保存する方式ではない。品質の維持はLongBenchなどの実験で検証する必要がある。

### 5. 分割並列注意（Split-S）によるカーネル実装

接頭辞を短い出力から参照する復号では、問い合わせ長が例えば32トークンしかない一方、選択済みKVは数千トークンになる。標準的なFlexAttentionは問い合わせ方向に並列化するため、短い問い合わせではGPUの並列性を使い切れない。著者らは選択後のKV列を $S$ 個の計算片へ分割し、それぞれの注意を並列実行してから対数和指数（log-sum-exp）に基づく正規化で結果を統合する。

この分割は、関連区間を選ぶためのチャンク境界とは別である。区間検索用の4個のチャンクと、注意計算用の4分割を同じ概念と誤解してはならない。後者はGPUカーネルの仕事量分散を目的とし、論文では復号カーネル単体で標準FlexAttention比5.8～10.2倍の高速化を測定した。ただし、この倍率をそのまま全生成時間の倍率としては使えない。

### 主要評価結果

| モデル・課題 | 比較対象 | 提案方式 | 差・意味 |

| UltraLLaDA / LongBench平均 | 通常36.00 | 区間間＋区間内37.02 | +1.02点。元から長文対応するモデルでも小幅改善 |
| Dream-7B / InfiniteBench平均 | Fast-dLLM v2 30.32 | 区間間＋区間内43.62 | +13.30点。128K超の長文評価 |
| UltraLLaDA / InfiniteBench平均 | 通常5.79 | 区間間＋区間内14.19 | +8.40点。ただし絶対水準は低い |

LongBenchの数値は各種課題の集約得点であり、推論の「速度倍率」ではない。Dreamの通常2K設定と128K外挿設定を混同すると、提案手法の品質比較を誤解する。UltraLLaDAはもともと128Kの文脈長を持ち、Dreamのような64倍外挿の条件とは異なる。特にInfiniteBenchの「KV」検索では全ての比較拡散型方式が0点であり、提案方式があらゆる長文検索を解決したという解釈はできない。

### 端から端までの生成速度

| 入力文脈長 | 標準Transformers実装に対する速度倍率 | 比較条件・意味 |
|---|---:|---|
| 8K | 9.1倍 | Dream-7B、A100、32出力、MF-en、5例の壁時計計測 |
| 16K | 16.1倍 | 同一モデル・環境、選択する入力KV量は固定 |
| 32K | 28.0倍 | 同一モデル・環境。入力が長いほど再計算回避の利益が増加 |

この倍率は、単に注意行列積の理論演算回数を割った値ではない。擬似回答の作成、チャンク選択、KV構築、転送、復号を含む端から端までの壁時計時間から求めた。入力が長くなっても選択チャンクを4×1024トークン程度に保つことが主な拡張性の源である。ただし、5例の小規模計測であり、多数同時要求をさばくサービングのスループットや多GPU分離環境での性能を直接示すものではない。

Sparse-dLLMは8Kでは16.62トークン/秒と高速だったが、32Kでは3.51トークン/秒まで落ちた。固定比率でトークンを捨てる方式は、入力が増えるほど処理対象の絶対数も増える。これに対し提案方式は選択予算をほぼ一定にでき、16Kと32KではSparse-dLLMより高速と報告している。高速化の主要な根拠は、拡散反復での入力再計算の回避と、選択対象の上限を保つ点にある。

### カーネル単体の性能と内部挙動

事前計算側の注意カーネルでは、FlashInferが最も低遅延で、FlashAttentionは1.0～1.2倍の所要時間、FlexAttentionは1.4～1.5倍、xFormersは1.6～1.8倍の所要時間を要した。復号側では短い問い合わせが並列度を制限するため、選択済みKVを4分割するSplit-SがFlexAttention比5.8～10.2倍高速化した。これはカーネル単体の測定であり、上表の9.1～28.0倍という全体速度とは異なる評価軸である。

位置制御型の検索評価では、区間の先頭にBOSを付けると、注意の局所的な突出が区間ごとに現れ、離れた証拠を拾う手掛かりになる。8K入力でのBOS注意質量は、通常Dreamの先頭1トークン0.59%、提案方式の先頭1トークン0.30%、全BOS合計2.72%と報告された。自己回帰モデルの典型的な「先頭だけが過大に注意を吸う」現象と同じものではない。境界トークンを定期的な位置手掛かりとして利用する設計だが、境界の追加そのものが全条件で精度を上げるとは限らない。

### 感度・構成要素除去・負の結果

区間長と選択数の積を4096トークンへ固定した位置検索では、16K・32K・64Kで区間長1024、4区間が92.0%、92.7%、95.3%の完全一致率を示した。128Kへの64倍外挿では細かな区間が重要になり、区間長256・16区間で92.3%、区間長1024・4区間では83.0%へ低下した。大きな4096トークンを1区間だけ選ぶ方式は64Kで47.0%、128Kで68.0%となり、単純な固定大区間選択が長文で不利になることが分かる。

MF-enの構成要素除去では、Dreamの区間内疎化あり・上位4区間・512保持で47.54点だった条件を上位6区間へ増やすと45.21点、保持上限256へ減らすと44.46点だった。さらに問い合わせ→区間の片方向注意得点47.54点に対し、双方向得点47.96点となり、区間内選別の指標にも改善余地がある。ここでのMF-en表は、主要LongBench表とは構成と実験設定が異なるため、34.59などの全16課題平均と直接比較しない。

同じトークン予算で語彙検索BM25と比べたMF-enでは、Dreamの提案方式（区間間＋区間内、2K予算）が46.40点、BM25（2K予算）が41.28点で優位だった。一方、Dreamの区間間選別のみ（4K予算）は38.26点でBM25（4K予算）の38.41点をわずかに下回る。したがって、モデルに基づく選別が常に語彙検索より優れるわけではない。

SCBenchの「要約と隠れた証拠の両立」では、全方式が8Kの選択予算を使い、提案方式の総合正確率0.3250とPasskey正確率0.6500は比較中最高だった。しかしBM25＋Fast-dLLM v1の総合F1は0.5074で提案方式の0.4996を上回り、要約F1も0.3898対0.3492で提案方式が劣る。少数の正確な証拠を保持することと、文章全体の内容を統合して要約することは異なる要求である。

## 既存研究との差

Fast-dLLMおよびdKV-Cacheは拡散反復中の表現更新を減らすが、基本的には同じ入力系列を繰り返し処理する構造の内側でKVの再利用や更新を工夫する。Sparse-dLLMは反復中の注意対象を疎化するが、入力が伸びれば固定比率で残るトークン数も増える。Prefilling-dLLMはこれらと異なり、**長い入力の事前計算を反復生成の外側へ切り離す**ことを最初の設計選択とし、その静的KVの量を質問依存の検索で制限する。

DistServeやMooncakeの事前入力処理・復号分離は、主として自己回帰型モデルの計算律速とメモリ帯域律速の違いを利用し、別ノード間で仕事を割り振る。Prefilling-dLLMは「分離」という発想を拡散型へ持ち込むが、論文の中心的な実証は物理的な別GPUクラスタの運用ではなく、**演算段階を分離して静的KVを再利用すること**である。したがって、分散サービングのネットワーク帯域や負荷分散まで最適化した方式として紹介してはならない。

また、MInferenceなどの自己回帰型疎注意は因果マスクを前提に設計されることが多い。本論文は双方向注意に合わせ、質問と区間の双方向重み、短い仮回答、区間先頭のBOSアンカーを用いる。これらは、単に既存のKV圧縮手法を別モデルへ適用しただけでは説明できない、拡散型特有の技術要素である。

## 限界と適用条件

第一に、上位 $K$ 区間は事前計算後に固定される。仮回答が誤っていたり、生成中に必要な証拠が変わったりしても区間を動的に選び直さないため、重要な証拠を失う可能性がある。原著も静的選択は要約のような広域統合に弱いことをSCBenchで示している。第二に、区間長を小さくすると位置精度は改善し得るが、各GPU演算の粒度が小さくなり効率を下げる。選択数と区間長は入力分布・品質要求・予算に合わせて調整する必要がある。

第三に、論文で評価されたFlexAttention経路はページ単位のKVメモリ管理を備えておらず、復号ステップごとに接頭辞KVを再ロードする問題が残る。著者公式リポジトリには後からページ管理対応の推論実行系が追加されているが、論文中の速度実験とは区別する。これは「KVを再計算しない」ことと「KVのメモリ転送がなくなる」ことの違いである。第四に、長文での精度評価はDream-7BとUltraLLaDA、英語中心のベンチマークに限られ、より大きなモデル、多言語、異なる拡散構造への一般化は未確認である。

第五に、主要速度実験は単一A100と少数サンプルの条件であり、多数の同時利用者を受け付けるサービング、異種GPU、CPU/SSD退避、ネットワーク越しのKV転送の性能を実証していない。学習不要という主張はモデル重みの追加学習が不要という意味であって、擬似ラベル生成、KV事前計算、関連度計算、選別用メモリ、注意カーネルの実装費用がゼロという意味ではない。
