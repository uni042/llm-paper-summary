# Scaling LLM Inference via Parallelism: Throughput-Latency Trade-off

## 概要

この研究は、複数GPUでLLMを提供する際の「テンソル並列を増やすか、パイプライン並列を増やすか」という配置判断を、単なる最大スループットではなく、最初の応答までの時間、連続生成の滑らかさ、サービス水準を守れた要求の処理量という複数の尺度から整理する。新しい注意カーネル、重み圧縮器、GPU間通信プリミティブを提案する論文ではない。既存の並列実行方式を同一8基GPU上で比較し、どの要求分布・遅延制約・文脈長で有利な構成が変わるかを示す、サービング構成選択の実証研究である。

対象となる2段階の処理は、入力系列をまとめて計算するプリフィルと、過去のKVキャッシュを参照しながら1トークンずつ出力するデコードである。プリフィルの完了に大きく左右される初回トークン遅延（TTFT）と、デコードの継続速度を表すトークン間遅延（ITL）では、最適なGPU分割方式が一致しない。論文は両者を1つの総遅延へ潰さず、二次元の実現可能領域とパレート前線として扱う。

実験はQwen2.5-14B-Instruct、BF16、NVIDIA H200 141GBを8基、vLLM v0.15.0という条件で行われた。比較した構成はTP8、TP4PP2、TP2PP4、PP8の4通りである。TPを大きくするとデコードのITLが低い一方、PPを大きくすると高並列・入力処理中心の負荷でTTFTが低い。さらに、TTFTの期限を厳しくするとPP側の要求が多く期限内に収まり、期限を緩めるとTP側の生の処理能力が効く。長文脈化ではPP優位の領域が拡大する。これらは本論文の特定モデル・8GPU構成・実験負荷での観測であり、すべてのLLMとGPU網に一般化された定理ではない。

## 背景と問題設定

LLMサービングの処理能力は、単位時間の生成トークン数だけで判断できない。対話用途ではユーザーが最初の返答を見るまでのTTFTが重要で、長い回答を流す用途ではITLが重要となる。入力が長く出力が短い検索・要約要求と、入力が短く出力が長い推論・生成要求では、同じGPUを使ってもプリフィルとデコードの仕事量の比率が違う。単一のベンチマーク設定で最速だった並列構成を固定すると、要求構成が変化した際に効率が悪化する。

テンソル並列（TP）は、各Transformer層の行列演算を複数GPUへ分割する。1層の計算を分担できる一方、層ごとの集合通信と同期が必要になる。GPU数を増やせば常に速くなるわけではなく、1回の演算が小さいと通信の割合が増す。パイプライン並列（PP）は、連続する層群を別々のGPUへ配置する。各層内部の細粒度な集合通信を減らせる反面、段間に活性を渡す必要があり、同時に処理できる要求が足りなければ空き段階（パイプラインバブル）が生じる。

両方式の比較には、モデルを8GPUへ載せられるかだけでなく、プリフィルの計算密度、デコードの逐次性、GPU間転送、同時要求数、入力と出力の長さを同時に考える必要がある。論文はTPとPPの一般的な計算通信モデルを説明したうえで、実機測定されたTTFT・ITL分布から望ましい配置を選ぶための枠組みを組み立てる。ここでの主眼は、TPとPPの一方を常に優位と主張することではなく、負荷とSLOごとの優劣を可視化することにある。

## 手法：並列構成の実現可能領域

### 入力、構成、処理時間の分解

構成を `p=(N_TP,N_PP)` と表し、利用可能なGPU数を `N=N_TP×N_PP` に固定する。要求の負荷は `w=(L_in,L_out,C)` と定義し、入力長、出力長、同時要求数をそれぞれ明示する。対象の処理時間はプリフィル時間とデコード時間の和である。各段階の時間を、計算、GPU間通信・同期、スケジューリングの3成分に分けることで、並列度を変えた際にどの費用が変わるかを追跡する。

この分解は「PPなら必ずプリフィルが速い」「TPなら必ずデコードが速い」という独立した規則を作るためではない。TPを増やせば1GPUあたりの計算は減るが集合通信は増え、PPを増やせば層間の細粒度通信を避けられるがバブルが増える。その交換条件が実際の負荷と同時実行数により変わるため、結果を測定して実現可能な点の集合として扱う。

### TTFT–ITLの二次元前線

各構成・各負荷で平均TTFTと平均ITLを測り、`ell(p,w)=(TTFT_avg,ITL_avg)` という2成分の点を作る。論文は入力長と出力長の合計 `L_seq` と同時要求数を固定し、入力と出力の配分だけを動かす負荷族を定義する。これにより、単に合計トークン数が増えた影響と、プリフィル対デコードの構成比が変わった影響を区別できる。系列長自体を変える場合は、別の実現可能領域を作り直す。

ある構成Aが構成Bに対してTTFTもITLも同等以下で、少なくとも片方が厳密に短いなら、AはBを支配する。どの他構成からも支配されない点がパレート前線である。この定義は、特定のTTFT・ITLの重みを恣意的に先に決めなくても、少なくとも片方の遅延を犠牲にしなければ改善できない構成群を示す。利用者の対話性を重視するのか、連続生成を重視するのかに応じて、その前線上から配置を選べる。

図1の実験では、合計系列長1200トークン、同時要求数128のまま入力と出力の比率を変更する。入力が短く出力が長い場合、逐次デコードの負担が大きく、低ITLのTP8が有利な端に位置する。入力が長く出力が短い場合、プリフィルの負担が増え、低TTFTのPP8が有利な端に移る。TP4PP2とTP2PP4は両端の中間の交換条件を作る。前線は構成の固定ランキングではなく、負荷ごとに形が変わる。

### SLOを満たす処理量としてのgoodput

パレート前線だけでは、要求のうち何件がサービス水準を満たせたかが分からない。そこで、構成pで達成した生の要求スループットを `lambda_p(w)`、TTFTが指定期限 `T_s` 以下となる確率を経験分布関数 `F_p(T_s|w)` として、`G_p(w,T_s)=lambda_p(w)×F_p(T_s|w)` を定義する。これは期限を守った要求だけを処理能力として数えるgoodputである。

たとえば生の処理能力が高くても、TTFT制約を破る要求が多ければgoodputは低い。逆にPPが生のスループットで劣っていても、厳しい期限内に多くの要求を収めれば、実際に有用な処理量で勝てる。各SLOについて4構成のgoodputを計算し、その最大値を与える構成を選ぶ。論文の式は、2構成の優劣が逆転する期限では「期限内達成率の比」が「生スループットの逆比」に一致することも示す。これは、要求処理能力と期限達成率を独立に観察して配置判断を説明できる利点を持つ。

重要なのは、今回のSLOが主にTTFTを対象にしている点である。ITL制約や要求全体の完了期限を同時に満たす複合SLOを実験で最適化したわけではない。goodputの式自体は一般的だが、図で示す最適構成はTTFTを期限にした場合の結果である。

### 長文脈化と前線の再計算

長文脈の実験では出力長と同時要求数を固定し、入力長だけを増やす。入力が長くなるとプリフィル計算とKVキャッシュが増え、TTFTの分布が右へずれる。したがって同じTTFT期限を守る割合は減る。さらに、TPとPPでその減少速度が異なるため、短い入力での勝者が長い入力でも勝つとは限らない。

論文は系列長ごとに生スループットとTTFT期限達成率を測り、積としてgoodputを求める。長い入力ほどTPの層内集合通信がプリフィルのクリティカルパスに効きやすく、PP側が比較的緩やかな期限達成率低下を示す。この効果は特に期限2秒の厳しい場合に目立つ。ここでも、新しい長文脈注意方式やKV圧縮器を導入した結果ではなく、同じモデルの並列構成を変えたときの測定である。

### 前線の観測をどう読むか

図1ではTP8とPP8が単に「速い」「遅い」の2択にならない。TP8は各デコード反復で8基の計算を使えるため、持続的なトークン生成では低ITLとなる。他方、プリフィルでは各層に集合通信が入り、PP8のほうが低TTFTとなる。中間のTP4PP2とTP2PP4は一方の端を完全に置き換えるのではなく、双方の利点を少しずつ取り込む。入力と出力の比率が変われば、各構成の優位性も変化するため、入力長だけを見て最適構成を固定するのは不十分である。

図2の出力長感度では、入力長1000、同時要求256を固定し、出力長200、400、800を比較する。出力が長いとデコード反復数が増え、開始時の固定費用をより多くのトークンへ配賦できる。原著ではTP寄りの構成ほどITL改善が大きく、PP8は比較的小さい。この差は、PPの段間転送やバブル費用が各トークンの処理で残るためと説明される。ただし図の結果を「出力長が増えると個々のGPU演算自体が高速化する」とは解釈しない。測定された平均ITLの償却・スケジューリング効果である。

### SLOによる逆転

図3は入力1200・出力2800・同時256の負荷について、TTFTとITLの経験分布を別々に示す。PP8は早いTTFTを達成する要求の割合が高い一方、TP8は低ITLを達成する要求の割合が高い。平均TTFTが同程度でも、期限を満たす要求割合は分布の形に左右されるため、goodputには経験分布を用いる。

図4と図5はTTFT期限を変えた場合の配置選択を示す。5秒と10秒の厳しい期限ではPP8の期限達成率が高く、たとえ生の要求処理能力がTP寄りより低くてもgoodputが最大となる。期限を20秒、25秒へ緩めると、ほかの構成も期限を満たす割合が増え、最適点は混合方式を経てTP8へ移る。これは同じ負荷・同じGPU総数でも、SLOだけで推奨構成が変わる直接的な証拠である。各構成の生スループットやCDFの正確な交点は本文に数表がないため、ここでは図から勝手に補間しない。

### 長文脈の評価と負の結果

図6・図7では出力長1000、同時128のまま入力長を伸ばし、TTFT期限2秒・5秒でgoodputと達成率を比較する。入力が長くなるほどすべての構成で期限達成率が下がるが、PP寄りは低下が相対的に緩やかである。短文脈で生の処理能力が高いTP寄りが優位でも、長文脈では期限達成率の低下によってgoodputの優劣が逆転し得る。特に2秒の厳しい期限ではこの傾向が強い。PPが長文脈で絶対的に速くなるのではなく、同じSLOを守れる割合が比較的残りやすいという結果である。

この研究の負の結果は、各構成の弱点を明示した点にもある。PP8はプリフィルのTTFTで優れる条件がある一方、デコードのITLが大きく、出力が長い対話では流れる速度が悪化する。TP8はデコードで強い一方、入力が長くTTFT期限が厳しい場合には達成率が急速に低下する。混合方式は妥協点を提供するが、あらゆる条件で両端を支配するわけではない。したがって「PP8を推奨」「TP8を推奨」という一律の結論は原著の実験からは導けない。

## 既存研究との位置付け

Sarathi-Serveはチャンク化プリフィルによってデコードとの干渉を抑え、DistServeはプリフィルとデコードを別資源へ分離してgoodputを最適化する。本研究はそのいずれの実行機構も新規に置き換えるものではなく、単一モデルのTP/PP構成をどのような負荷とSLOで選ぶべきかを測定する。前者はスケジューリングや資源分離という実装上の仕組みを改善し、こちらは既存の並列構成を評価する座標系を提供するという違いがある。

PagedAttentionなどのKVキャッシュ管理技術はメモリ断片化とバッチ収容数を改善する。一方、本研究のパレート前線は、GPU総数が固定された場合の層内計算分割と層間パイプライン化による遅延交換を扱う。長文脈ではKV容量も重要だが、実験の主張はKV圧縮やコンテキスト並列の効果ではなく、入力長を増やしたときのTP/PP間のSLO達成率差である。文脈並列を含む複雑な実サービス全体の最適化へ直接一般化する際は、別途計測が必要となる。

また、論文の式は既存の計算通信費用とgoodputの概念を組み合わせた特徴付けであり、配置をオンラインで無停止切替する完成ソフトウェアの提案ではない。実際に運用へ適用するには、要求の入力・出力長の予測、SLO別の負荷分布、GPU資源の分割、モデルの再配置に伴う費用を考慮する制御器が必要となる。論文はそのような将来の適応的サービングの基礎として前線と選択基準を位置付けている。

## 限界と再現上の注意

第一に、主要な実機比較は8基H200、Qwen2.5-14B-Instruct、BF16、vLLM v0.15.0に集中している。別モデルの層数、注意ヘッド数、MoE構成、GPU間ネットワーク、低精度カーネル、別のGPU台数で同じ順序が成立するかは直接確認されていない。PPのバブルとTPの集合通信はハードウェア・負荷に敏感なので、最適構成の境界はそのまま他環境へ転用できない。

第二に、図1の合計系列長固定という実験は入力と出力の比率を切り分ける利点がある反面、実サービスで入力長と出力長が独立に変動する状況を完全には表現しない。図2、図6、図7では別の固定条件を使っているため、各図の勝者を同じ負荷の結果として一括比較してはいけない。特に同時要求数128と256、出力長1000と2800、TTFT期限2秒と25秒は実験の目的に応じて異なる。

第三に、goodputの実験で設定した期限はTTFTである。ITLや要求完了時間、p95/p99の尾部遅延、複数テナントの異なる期限を同時に制約する実験まで実証したわけではない。低TTFTを優先したPP8が、ユーザーにとっての全体的な体験で必ず優れるわけではない。長い出力を伴うサービスでは、初回応答と持続生成の両方を評価する必要がある。

第四に、論文はパレート前線の観測とgoodputの選択規則を提示するが、実運用の自動切替に伴うモデル再配置時間、KVキャッシュの移行、リクエスト途中の切替可否、トラフィック変動時の制御安定性を評価したとは記載していない。実験で観測された配置の優劣を、そのまま切替器の実現済み性能として解釈しない。

第五に、原著の本文には主な傾向と図の説明があるものの、図中すべての構成・負荷に対応する遅延・スループットの数値表が揃っていない。特定条件で「何倍速い」といった倍率を推測で追加せず、一次資料が明示する設定と定性的な優劣にとどめる。精密な運用判断では原著の図と再実験を確認すべきである。
