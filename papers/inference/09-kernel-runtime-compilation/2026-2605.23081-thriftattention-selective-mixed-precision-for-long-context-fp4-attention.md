# ThriftAttention：長文注意で重要ブロックだけをFP16に戻す混合精度演算

## 概要

Blackwell世代のGPUは4ビット浮動小数点（FP4）の行列積を高速に実行できるが、長い文脈で注意計算を一律FP4へ変えると、モデルの長文理解性能が大きく低下する。ThriftAttentionは、すべてを高精度に戻すのではなく、注意出力に強く影響する問い合わせ・鍵ブロックだけを16ビット浮動小数点（FP16）で計算し、残りをFP4に保つ学習不要の方式である。重要度の選別には、各ブロック内の問い合わせベクトルと鍵ベクトルの平均を取り、その内積を用いる。

原著では全ブロック組の上位5%だけをFP16へ昇格させると、FP4とFP16の長文ベンチマーク得点差の平均89.1%を回復した。上位10%で91.8%、25%で92.4%である。RTX PRO 6000 Blackwell上では、FlashAttention-2のFP16実装に対して復号カーネルが3〜5.5倍速く、Qwen3-8Bの約13.1万トークンの長文生成で端から端まで最大約2倍の高速化を報告する。ただし「平均89.1%回復」は元の正解率が89.1%という意味ではなく、FP4からFP16へ戻すための差分の回復割合である。

## 問題設定

長文の注意計算では、問い合わせQと鍵Kの積から全キー位置に対するスコアを求め、softmaxを通して値Vを加重平均する。FP4へ量子化すると、Q・Kのスコアと確率・値の積の双方に誤差が入り、特に長い系列では小さな誤差が出力へ累積する。BlackwellのFP4 Tensor CoreはFP16に比べ高い演算能力と小さい転送量を持つ一方、低精度の誤差が原因で長文検索・読解の正解率が下がる。

すべてのブロックをFP16にすれば精度は戻るが、FP4の高速化を失う。重要でないブロックを完全に省略する疎注意も選択肢だが、FP4と同じ程度の復号時間を得るには多くのブロックを捨てる必要があり、省略した値の情報を復元できない。ThriftAttentionは、計算を省くのではなく、すべての注意ブロックを計算しつつ、精度だけを選択的に変える。これにより、情報の完全な削除と量子化誤差の間で別の交換条件を作る。

## 手法

### 1. なぜ少数ブロックの精度が重要か

注意出力をo=Σ_j p_j v_j、p_j=softmax(s)_j、s_j=q・k_j/√dとする。スコアへ量子化誤差ε_jが入ると、一次近似で出力の変化はΣ_j ε_j p_j(v_j−o)となる。したがって誤差の大きさは量子化誤差の絶対値だけでなく、注意確率p_jと値の出力平均との差にも依存する。高い注意確率が割り当てられる少数の鍵は、同じ量子化誤差でも出力へ大きな影響を与える。

原著はQwen3-8Bの注意行列でFP16とFP4の確率差を可視化し、誤差が対角線近傍や初期位置以外の注意シンクなど少数のブロックに集中することを示した。この観察は、単純に量子化誤差の大きいテンソルを選ぶより、重要な問い合わせ・鍵の相互作用を高精度へ昇格させる方が有効な可能性を示す。ただし、実際の出力誤差には値ベクトルの方向も関係するため、内積スコアは厳密な最適選択ではなく近似である。

### 2. ブロック平均による重要度推定

問い合わせQを長さB_qのブロックQ_iへ、鍵Kと値Vを長さB_kのブロックK_j、V_jへ分ける。原著実験ではB_q=B_k=64を使用する。各Q_i、K_jのトークン方向の平均ベクトルq̄_i、k̄_jを作り、重要度をŜ_ij=q̄_i・k̄_jで計算する。問い合わせブロックiごとに、このスコアが高い上位k個の鍵ブロックを選ぶ。計算する候補は因果マスクに従って現在の問い合わせ位置から見える範囲に制限する。

平均ベクトルを使うので、全トークン対のFP16スコアを先に計算する必要がない。選別の費用は残るが、ブロックサイズ64なら全トークン対を高精度で計算するより小さい。重要な相互作用がブロック内で打ち消し合う場合や、平均では識別できない局所的なピークがある場合は、真に重要なブロックを取り逃がす可能性がある。原著付録Aは選別ヒューリスティクスの構成要素を比較している。

### 3. FP4とFP16の二経路

選ばれた問い合わせ・鍵ブロック組はFP16のQ_i K_j^Tを使い、対応する値との積もFP16で処理する。それ以外はQ、K、VをBlackwellのNVFP4形式へ量子化し、FP4 Tensor Coreで計算する。NVFP4では各要素をE2M1で保持し、16要素ごとにE4M3の微小スケールを用いる。確率行列についてもSageAttention3に由来する二段階のスケールを使ってFP4へ量子化する。

二経路を別々にsoftmaxして平均するのではなく、FlashAttention型のオンラインsoftmaxで行最大値m、指数和ℓ、出力累積Oを共有する。ブロックごとに現在の最大値へ正規化し直し、FP16とFP4の結果を同じ正規化定数の下で加算する。これにより高精度ブロックと低精度ブロックの重み付けを整合させる。すべてのブロックを処理するため、疎注意のように情報を完全に捨てるわけではない。

### 4. GPU向け統合実装

原著はCUDA C++で一つの統合カーネルを実装する。最初に非選択ブロックをFP4経路で処理し、その後に選択ブロックだけをFP16経路で処理する。FP16問い合わせタイルは選択経路の実行時にだけレジスタへロードすることで、二経路を常時保持する場合のレジスタ圧力を減らす。共有メモリ領域はK/Vタイルの二経路で使い回し、FP4タイルは二重バッファで転送と演算を重ねる。FP16対象がないワープやスレッドブロックはFP16処理自体を省略する。

この設計はBlackwellのFP4 Tensor Coreを前提とする。旧世代GPUではNVFP4のネイティブ演算能力が異なり、同じ高速化を保証できない。また、カーネルのレジスタや共有メモリの使用量が性能に影響するため、精度割合だけから速度を線形補間できない。

## 評価

### 1. 実験条件と比較方式

評価はRTX PRO 6000 Blackwellで、注意ブロックサイズ64を用い、FlashAttention-2のFP16とSageAttention3のFP4を比較基準とする。モデルはLlama3.2-3B、Llama3.1-8B、Qwen3-4B/8B、Ministral 3-8Bの五系列。長文課題はRULER、LongBench-v1、HELMET、負の対数尤度（NLL）の解析にはPG-19を使う。精度回復率は(FP4から改善した得点)/(FP16得点−FP4得点)で計算し、FP16より高い得点が出る場合は100%を超え得る。

### 2. FP16ブロック割合と精度回復

| FP16へ昇格するブロック割合 | FP4→FP16得点差の平均回復率 |
|---|---:|
| 5% | 89.1% |
| 10% | 91.8% |
| 25% | 92.4% |

上位5%で大半の差を回復し、それ以上に高精度ブロックを増やしても平均改善幅は小さい。原著表1の例ではQwen3-8BのRULER得点がFP16の0.840、FP4の0.484に対して、上位5%の混合精度では0.806へ回復する。Llama3.2-3Bでは同じRULERでFP16 0.728、FP4 0.321、上位5% 0.543となり、回復率は54.5%にとどまる。平均89.1%という値はモデルと課題ごとの大きなばらつきを隠すため、個別用途では対象ベンチマークを確認する必要がある。

### 3. 長文課題ごとの負の結果

Llama3.2-3BのLongBench-v1ではFP16 0.267、FP4 0.132、上位5% 0.252だが、上位25%では0.240へ下がる。高精度のブロックを増やせば必ず得点が上がるわけではない。Qwen3-8BのHELMETはFP16 0.259、FP4 0.127、上位5% 0.246で、上位10%では0.268とFP16基準を超える一方、25%では0.246へ戻る。小さいデータセットや生成のばらつき、低精度による出力分布変化のため、精度回復率は単調性を保証しない。

Ministral 3-8BのRULERはFP16 0.848、FP4 0.548、上位5% 0.866で回復率106.0%となる。この値はFP16を理論的に上回る量子化法という証明ではなく、当該ベンチマーク得点の差分計算である。長文におけるNLL解析でも、FP4の誤差が文脈長とともに大きくなる傾向に対し、選択的FP16で差を縮める。原著は系列長に伴う利得の増加を示すが、全モデル・全課題で同じ曲線になるとは述べていない。

### 4. カーネルと端から端までの速度

原著図4では、FP16のFlashAttention-2に対して、事前入力処理カーネルで最大約1.7倍、復号カーネルで3〜5.5倍の速度を報告する。約131kトークンの事前入力処理全体では約1.2倍、Qwen3-8Bの長文生成全体では最大約2倍の速度となる。復号カーネルの3〜5.5倍をそのままモデル全体の速度へ転用できないのは、重み行列積、サンプリング、スケジューリングなど注意以外の処理が残るためである。

速度評価の代表条件はバッチ1、注意ヘッド32、ヘッド次元128である。長文生成ではKVキャッシュ読み出しが大きな割合を占めるため、ほとんどのブロックをFP4でロードする効果が強い。一方、短文や大きいバッチでは選別処理と高精度経路の追加費用が相対的に増え得る。原著付録Cには短文のベンチマーク結果があり、主張は長文で最も強い。

## 既存研究との差

SageAttention3はFP4の演算効率を追求するが、一律FP4の長文精度低下を受け入れる。QuestやSpargeAttnなどの疎注意は重要ブロックを残し、それ以外を省略することで演算量を減らす。ThriftAttentionは省略を行わず、重要ブロックの計算精度を高める。FP4とFP16の両経路を同じオンラインsoftmaxへ統合する点が、単に別々の出力を合成する方式との違いである。精度回復と低ビット演算効率を同時に狙うが、Blackwell固有の実装最適化に依存する。

## 限界と再現性

第一に、NVFP4のネイティブ演算を備えるBlackwell GPUでの結果であり、RTX 4070 Superや従来世代のCUDA GPUで同じ速度は出ない。第二に、重要度はブロック平均の内積という近似であり、稀な重要トークンがブロック内で埋もれる可能性がある。第三に、全ブロックを計算するため、注意演算の二次的な計算量そのものは削減せず、低ビットTensor Coreの実効演算性能とメモリ帯域を利用する。

第四に、長文ベンチマーク得点は必ずしも単調に改善せず、FP16比で一部低下が残る。第五に、カーネル単体の速度、事前入力処理全体、生成全体の速度は異なる指標である。第六に、選別と二経路のためレジスタ・共有メモリの使用量が増え、GPU構成やバッチによって利得が変わる。第七に、公開コードは存在するが、Blackwell専用のビルド・実行条件を確認する必要があり、llama.cpp/Ollamaの既存経路へそのまま組み込めるという保証はない。
