# LeanQuant：損失感度に応じた量子化格子の学習

## 概要

LeanQuantは、大規模言語モデルの学習後量子化（Post-training Quantization; PTQ）で、各重みをどの離散値へ丸めるかを決める**量子化格子の位置**を最適化する手法である。単純な最小最大値ベースのアフィン量子化は、重みの値域を均等に分割するが、同じ丸め誤差でも推論品質への影響は重みによって異なる。提案法は校正データから推定した逆ヘッセ行列の対角成分を用い、出力誤差への影響が大きい重みに格子点を適切に配置する。新しい数値形式そのものを要求するのではなく、既存のアフィン形式と非一様形式を改善する設計である。

Llama-3-8Bを3ビットのアフィン量子化へ変換した11課題平均正答率は、GPTQの37.75、OmniQuantの38.95に対してLeanQuantが56.13である。Llama-3.1-405Bの量子化を48GB GPU二枚と大容量CPUメモリで約20.7時間で完了した。ただし、**量子化処理を高速に終えたことと、量子化済みモデルが推論時に高速であることは異なる**。原著はA100上の生成速度も測定しており、非一様形式が比較対象より遅くなる条件が存在する。

## 問題設定と従来方式の限界

大規模言語モデルの推論では、重みを高精度のままGPUメモリへ載せると必要容量と帯域が増える。4ビットや3ビットへ量子化すれば重みの読み出し量を減らせるが、離散化の誤差が推論品質を壊す可能性がある。学習後量子化では、大規模な再学習をせずに、少量の校正入力から低ビット表現を求める。ここで問題となるのは、誤差を何で測るかと、誤差の小さい丸め先をどのように選ぶかである。

通常のアフィン量子化では、各グループの最小値・最大値から格子間隔を定め、倍率Sとゼロ点Zで整数値を復元する。グループ内の重みが偏って分布している場合でも、格子は等間隔である。一方、非一様量子化は代表値を自由に動かせるが、値の頻度だけを考慮したクラスタリングでは、少数であっても損失に強く影響する重みが粗く丸められ得る。

GPTQなどの反復誤差補償方式は、既に量子化した重みの誤差を残りの重みに移して出力誤差を抑える。ただし補償が優秀でも、最初に選んだ格子点が損失感度を反映していなければ、誤差の大きな重みを正確に表現できない。LeanQuantは、丸め順や誤差補償だけでなく、丸め先格子の設計自体に損失感度を組み込む。

## 手法

### 1. 逆ヘッセ対角による重み別の損失感度

線形層の元の重み行列をW、量子化後をW_hat、校正入力をXとすると、出力の二乗誤差 `||WX - W_hat X||_F^2` を損失増加の近似として使う。校正入力から作る二次近似の行列をHとしたとき、重みw_iをQ(w_i)へ丸める損失誤差は、原著の式(3)に従い、おおむね `0.5 * (Q(w_i)-w_i)^2 / (H^{-1})_ii` と表せる。これはネットワーク全体の厳密な損失ヘッセ行列ではなく、層の入力から構成する近似である。

同じ大きさの丸め誤差でも、逆ヘッセ対角 `(H^{-1})_ii` が小さい位置では損失への寄与が大きい。原著の図1は、Llama-3-8Bの校正入力262,144トークンから計算した逆ヘッセ対角由来の感度分布に外れ値があることを示す。単に重みの最小最大値を均等に分ける格子は、この感度の偏りを反映できない。LeanQuantは格子学習の目的関数に感度の重みを導入することで、品質に重要な重みの丸め誤差を抑える。

### 2. 非一様格子：感度重み付きクラスタリング

bビットなら、非一様格子には `2^b` 個の代表値がある。提案法は各重みを最も近い代表値へ写した二乗誤差に、`((H^{-1})_ii)^(-p)` を掛けた総和を最小化する。pは重要重みをどの程度強調するかの指数で、原著の主実験ではp=4である。p=0なら感度差を考慮しない通常の重み分布に基づく量子化へ近づく。格子位置は重み付きk-means型の反復で更新し、その後にGPTQ型の誤差補償を実施する。

初期格子は単なるランダム初期化やk-means++ではなく、各グループの最小値から最大値まで等間隔に置く。重みはゼロ近傍に密集しやすいため、頻度に偏った初期化だと少数の極端値付近に格子点がなくなるからである。初期化を均等にしてから感度重み付きで格子点を移動させることで、分布の端と中心の両方を候補に含める。もっとも、非一様格子は復号時に代表値の参照が必要となり、既存の整数演算カーネルへそのまま置き換えられるとは限らない。

### 3. アフィン格子：倍率Sとゼロ点Zの探索

アフィン量子化では格子間隔が一定であるため、非一様格子のように各点を独立には動かせない。そこで元の重み範囲RをT=2048の細かい区間に分割し、上下端を少しずつ縮めた候補範囲から倍率Sとゼロ点Zの組を列挙する。それぞれの候補で重みを丸め、前述の感度重み付き二乗誤差を計算し、最小の組を選ぶ。縮小幅の制限は、少数の校正入力に過度に適合して元の重みの広い範囲を切り捨てることを避けるために設ける。

候補数が増えるとCPUでの逐次探索は高コストになる。LeanQuantは重みグループをGPUのスレッドブロックへ割り当て、複数の候補S,Zを並列評価して最小値を選ぶ融合カーネルを実装する。この高速化は**量子化時の格子探索**に効くものであり、推論時の復号カーネルが自動的に高速化されるわけではない。既存のアフィン整数表現を使えることは配備互換性に有利だが、実際の速度は対応する復号・行列積カーネルの品質に依存する。

### 4. GPTQ型の反復誤差補償との結合

格子の学習後、校正入力から構成したHに数値安定化の対角補正を加え、逆行列とコレスキー分解を用いる。重みをブロック単位で量子化し、量子化済み列で生じた誤差を未量子化列へ順次伝搬させる。非一様版とアフィン版は格子点の決め方が異なるが、後段の誤差補償という枠組みは共有する。こうして、格子選択による一次的な誤差抑制と、残りの重みへの補償という二段階の処理がつながる。

原著が検討する非一様版とアフィン版は、ビット幅の表記、補助データの保存量、推論カーネルが異なる。したがって同じ「3ビット」という語でも実効ビット数3.00と3.02を混同しない。また、この処理はモデルを量子化するオフライン段階の処理であり、リクエストごとの動的な重み変更やKVキャッシュ圧縮を行う方式ではない。

低ビットの改善は、逆ヘッセ対角に由来する損失感度を格子点へ反映するという中核機構の証拠となる。特に3ビットでは格子点が8個しかないため、重要重みを表現する位置選びが大きく効く。一方で、2ビットでは4点しかなく、格子最適化をしても品質を十分回復できない。大型モデルの4ビット条件ではGPTQとの差が小さいため、改善幅を単一の代表倍率として要約しない。

### 量子化に要するGPUメモリと時間

原著のメモリ比較では、Llama-3-8Bの量子化時GPUピークはGPTQとLeanQuantがともに7.9GB、Llama-3-70Bは17.1GBと17.2GB、123Bは32.8GBと33.0GBでほぼ同等である。405Bでは比較対象のGPTQがメモリ不足で完了しなかった一方、LeanQuantはGPU二枚合計ピーク65.4GBで量子化できた。ここでの65.4GBはGPUメモリ合計ピークであり、同時に1.48TBのCPU RAMを利用している。GPUだけに405Bの重みを格納したわけではない。

アフィン格子のGPU融合カーネルについて、Llama-3-8Bで格子学習に要する時間は非融合15.1時間から融合0.27時間へ短縮され、比率は約55.9倍となる。グループ長128の4.25bit条件では非融合が100時間超、融合0.40時間と報告される。付録表13の量子化総時間はLlama-2-7B 4bitアフィン14分、Llama-3-8B 4bitアフィン16分、同非一様4.05bitは37分、123Bアフィン4bitは252分、405Bアフィン4.25bitは1241分である。格子学習の時間と全量子化工程の時間を混同しない。

### 生成時の実測性能と逆転条件

付録表12はA100 40GB上でLlama-3-8Bの4bitモデルを測定する。バッチ1での復号速度はSqueezeLLM 26.09、LeanQuant非一様版23.73、アフィン版38.30トークン/秒/バッチである。つまり**非一様版は比較対象より遅い**。バッチ16では順に7.22、9.02、10.20となり、大小関係が変わる。非一様版には専用CUDAカーネル、アフィン版にはExLlamaV2カーネルを使用するため、これはアルゴリズムの格子品質だけを比較した純粋な速度実験ではない。

初回トークン時間の表には、バッチ1でSqueezeLLM 153.26秒、LeanQuant非一様版0.36秒、アフィン版0.33秒という極端な値が載る。これは実装と処理条件の差を含むため、一般的なLLM推論の初回トークン時間が数百倍改善すると読み替えない。品質表の「11課題平均」も、実測トークン毎秒とは別の指標である。A100の結果を、別GPU・別量子化形式・別ランタイムへそのまま適用することはできない。

### 感度評価と構成要素の確認

原著付録Kは損失感度の指数pと格子初期化を変えた構成要素除去実験を行う。p=0で感度を無視すると品質が大きく落ち、p=3と4では差が小さい条件がある。p=4は著者が主実験で固定した値であり、すべてのモデル・ビット幅で最良と証明したものではない。初期格子を等間隔に置く設計も、重み分布の端を初期段階で拾えるかという問題に対する独立の対策である。両者は「感度をどの程度重視するか」と「局所最適化の開始位置をどこに置くか」という別の設計変数である。

## 限界・負の結果・適用範囲

第一に、逆ヘッセ行列は少数の校正入力から近似しており、実運用の入力分布が大きく変わると最適な格子位置も変わり得る。第二に、非一様形式は推論カーネルの対応が必要であり、格子の精度向上がそのまま配備速度向上を保証しない。第三に、2bitでの大きな品質低下や405Bでの小さな改善幅が示すとおり、手法の利得はビット幅・モデルに依存する。

第四に、405Bの量子化成功は48GB GPU二枚に加えて1.48TBのホストメモリを使った結果であり、12GBの民生GPUと32GBのRAMへ直接再現できない。第五に、生成速度はA100上の特定カーネルによる測定であり、Windows、別世代GPU、GGUF形式で同等の性能を保証しない。第六に、量子化時の格子学習を高速化する融合カーネルと、量子化後の行列積・復号の高速化は別問題である。

## 既存研究との差と実装判断

GPTQは重みを順次丸めながら未量子化重みへ誤差を伝搬する。AWQは活性値に基づき重要な重みの表現を保護し、OmniQuantは量子化パラメータを学習する。SqueezeLLMは非一様格子を利用する。LeanQuantは、**逆ヘッセ対角の損失感度を用いて格子点自体を最適化する**点が特徴であり、反復補償と組み合わせる。特にアフィン版は広く使われる整数表現を維持しやすい。

実装では、著者公開の量子化コードと既存の推論形式の互換性を分けて確認する必要がある。llama.cppの既存GGUF量子化方式へ導入するには、格子探索が出力する倍率・ゼロ点または代表値を、その形式の復号規則へ矛盾なく写像できることが条件となる。論文は任意のGGUF形式への完全互換性や特定のWindows/CUDA構成での高速化を証明していない。検証は量子化処理時間、品質指標、生成時の初回トークン遅延と継続復号速度を分離して行うべきである。
