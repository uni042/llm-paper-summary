# Opt4GPTQ: Co-Optimizing Memory and Computation for 4-bit GPTQ Quantized LLM Inference on Heterogeneous Platforms

> ハイゴンDCU上でvLLMのGPTQ 4ビットカーネルへ、共有メモリ集約・ベクトル化ロード・インラインアセンブリの3最適化を統合し、スループットを最大84.42%改善するプラットフォーム適応の実践研究。

## 概要

推論フレームワークの最適化は、対象ハードウェアの世代やベンダーが変わるとそのままでは効かない。vLLMはページドアテンションによるKVキャッシュ管理と連続バッチングでLLMサービングの標準的な実装になっているが、そのカーネルは主にNVIDIA GPU向けに調整されている。本論文の対象は、ROCmエコシステムと互換で理論上CUDA互換をうたうGPGPU型アクセラレータ、ハイゴンDCU（Deep Computing Unit）である。DCU上では既存の推論エンジンがハードウェア特性を引き出せず、特に量子化推論でスループット低下と遅延増大が目立つという問題が出発点にある。

最適化の対象は、重みのみを4ビットへ量子化するGPTQを適用したモデルのGEMMカーネルである。本方式は3つのプラットフォーム水準の最適化を重ねる。第1のSMB-Opt（共有メモリバッファリング）は、多数のスレッドがグローバルメモリへ原子加算する処理を、共有メモリで集約してから単一スレッドで書き戻す形へ変え、原子操作とグローバルメモリアクセスの回数を減らす。第2のVML-Opt（ベクトル化メモリロード）は、半精度データを1要素ずつではなく2要素の組（half2）としてベクトル化ロードし、読み込み回数を半分にする。第3のILA-Opt（インラインアセンブリ）は、半精度の加算と積和の組み込み関数を、GCN/VOP3命令セットのネイティブ命令を直接発行するインラインアセンブリへ置き換え、コンパイラの抽象化費用を避ける。

**代表結果:** ハイゴンDCU Z100上で6つのGPTQモデルを測ると、3最適化の統合でスループットはLlama-13Bで84.42%、CodeLlama-7Bで67.55%、Llama-3-8Bで61.78%向上し、遅延は最大51.35%（LLaMa-13B）削減された。精度はARCのChallenge/Easy両セットで変動が1ポイント以内に収まり、最適化が数値結果を実質変えていないことが確認されている。

## 問題設定

量子化推論のカーネルは、量子化された重みの読み込み、半精度への展開、積和演算、部分結果の書き戻しという、メモリアクセスと演算が細かく交互する処理である。GPU向けに書かれたカーネルを別のアクセラレータへ移植すると、命令セットやメモリ階層の細部が違うため、3種類の無駄が生じやすい。1つ目は、部分和の書き戻しで多数のスレッドが同じアドレスへ原子加算（atomicAdd：読み取り・加算・書き戻しを不可分に行う操作）を発行し、グローバルメモリへの競合が直列化すること。2つ目は、半精度データを細切れに読むため、ロード命令の回数とアドレス計算が支配的になること。3つ目は、高水準の組み込み関数経由ではコンパイラが最適なネイティブ命令を選ばず、レジスタへの余分な移動が残ることである。

プラットフォーム適応の問題は、これらの無駄がモデルやフレームワークの水準では見えず、カーネル内部の実装水準でしか直せない点にある。したがって本論文は、新しい量子化方式やスケジューリングを提案するのではなく、既存カーネルのメモリアクセスと命令発行を対象ハードウェアに合わせて作り直す、工学的な最適化の研究である。

## 手法のあらまし

処理対象は、vLLMの中でGPTQ 4ビット量子化モデルの行列積を担うカーネルであり、入力データの流れは変えない。まずVML-Optが、グローバルメモリから共有メモリへデータを運ぶ段階で、連続する2つの半精度要素をhalf2として一度に読み込み、共有メモリ上では低位・高位を取り出して通常の配置へ戻す。計算段階ではILA-Optが、half2に対する加算と積和をネイティブ命令（v_add_f16とv_mad_f16）で実行し、値はベクトル汎用レジスタ（VGPR）に留まる。書き戻し段階ではSMB-Optが、各スレッドの部分結果を共有メモリ上の集約バッファ（block_result）へ集め、ブロック内のスレッド0だけが原子加算でグローバルメモリへ書き戻す。3つの最適化は、読み込み・演算・書き戻しという異なる段階を担当するため、効果が積み重なる。

## 手法

### 1. SMB-Opt — 共有メモリで集約してから単一スレッドで原子加算する

この機構が観測するのは、各スレッドが持つ部分計算結果と、それが書き戻される先のグローバルアドレスである。保持する状態は、スレッドブロックごとに確保した共有メモリ上の集約バッファblock_result[0]とblock_result[1]である。処理は2段階で、まず全スレッドが自分の結果を半精度の組へ詰めて共有メモリの集約バッファへ合計し（同期を挟む）、次にスレッド0だけが集約済みの2値を原子加算でグローバルメモリへ書き戻す。これにより減るのは、グローバルメモリへの原子操作の回数と、それに伴う競合である。本来はスレッド数分の原子加算が同じ出力要素へ集中しうるが、集約後はブロックあたり2回で済む。追加で消費する資源は共有メモリの小さなバッファと同期であり、失敗条件は、集約バッファの容量を超えるような部分結果の保持が必要になる場合や、同期の費用が原子操作の節約を上回る小規模なブロックである。大きなモデルほど書き戻し量と競合が増えるため、利得はモデル規模に比例して出る。

### 2. VML-Opt — 半精度データを2要素ずつベクトル化して読み込む

この機構が観測するのは、グローバルメモリから共有メモリへの入力行列のロードである。保持する状態は共有メモリ上のタイルblock_aであり、処理は、連続する2つの半精度要素のアドレスをhalf2型として再解釈（reinterpret_cast）し、一度のロードで2要素を取得してから、低位と高位を取り出す組み込み（__low2half、__high2half）で共有メモリの通常配置へ展開することである。量子化重みの並び替え（permutation）が有効な場合は、その並び替えを引いた要素に対しても同じベクトル化ロードが適用される。これにより減るのはロード命令の回数とアドレス計算のオーバーヘッドであり、メモリ帯域が律速な量子化カーネルでは、転送の粒度をハードウェアの自然な幅へ揃えることが効く。追加費用は共有メモリ上での展開処理だけである。失敗条件は、要素数が奇数になるなど2要素の組を作れない境界や、そもそもロードが律速でないモデルであり、論文の実測でも小規模モデルでは利得が小さい。

### 3. ILA-Opt — インラインアセンブリでネイティブ半精度命令を直接発行する

この機構が観測するのは、カーネル内の半精度演算、特にhalf2に対する加算と積和である。処理は、CUDA系の組み込み関数_hadd2と_hfma2を、GCN/VOP3命令セットのネイティブ命令v_add_f16とv_mad_f16を発行するインラインアセンブリ実装（hip_hadd2、hip_hfma2）へ置き換えることである。half2は2つの半精度要素を1つのレジスタに詰めた型であり、ネイティブ命令は1命令で2要素分を同時に処理する。インラインアセンブリの制約指定により値がVGPRに留まるため、レジスタとメモリの間の冗長な移動も減る。これにより減るのは、コンパイラの抽象化を通すことで生じる余分な命令とデータ移動である。追加費用は事実上ないが、代償として可搬性が犠牲になる。この最適化はDCUの命令セットに強く依存し、他プラットフォームでは書き直しが必要である。失敗条件は、コンパイラが既に同等の命令列を生成している場合で、その場合は置き換えの利得が出ない。

| 構成要素 | 入力・観測 | 具体的な動作 | 改善対象 | 主なトレードオフ |
|---|---|---|---|---|
| SMB-Opt | スレッドの部分結果 | 共有メモリへ集約しスレッド0が原子加算で書き戻す | グローバル原子操作と競合 | 同期費用と共有メモリ使用 |
| VML-Opt | 入力行列のロード | half2として2要素ずつ読み共有メモリで展開 | ロード命令数と転送粒度 | 律速がロードでない場合は利得小 |
| ILA-Opt | half2の加算・積和 | v_add_f16/v_mad_f16のインラインアセンブリへ置換 | 命令発行とレジスタ移動 | DCU固有で可搬性がない |

## 評価

結論は、3つの最適化はいずれも単独で効き、特に命令水準のILA-Optの寄与が最大で、統合すると効果がほぼ積み上がる、というものである。スループットの向上率は、SMB-Optが4.94〜17.98%、VML-Optが1.36〜11.03%、ILA-Optが16.75〜57.19%であり、統合版は21.93〜84.42%に達する。モデル規模の大きいLLaMa-13BとMeta-Llama-3-8Bで利得が大きく、Qwen1.5-1.8Bのような小規模モデルでは21.93%にとどまる。読み方として、これは3最適化がすべて「メモリアクセスと命令発行の無駄」を削るものであり、無駄の絶対量が大きい大規模モデルほど削りしろが大きいためである。逆に小規模モデルでは、もともとメモリも計算も逼迫していないため上限が低い。

遅延でも傾向は同じで、統合版の削減率は25.18〜51.35%、内訳はILA-Optが19.42〜37.0%、SMB-Optが4.62〜12.41%、VML-Optが0.55〜2.67%である。VML-Optは遅延への寄与が小さいが、スループット側では一定の利得があり、読み込みの効率化は主に並行処理の詰まりを解く方向に効いていると読める。

精度は、ARCの難問セットとARCの易問セットの両方で、最適化前後の変動が全モデル・全最適化を通して1ポイント以内であり、一貫した上昇・下降の傾向もない。カーネルの再実装が計算順序を変えても、半精度演算の範囲での数値差にとどまることが確認されている。

## 既存研究との差

GPTQやAWQが「量子化の方式そのもの」を研究するのに対し、本論文は量子化方式を固定し、そのカーネル実装を対象ハードウェアへ適応させる点が異なる。vLLMやLMDeploy、TGIなどのサービング基盤は、主にGPUアーキテクチャを前提に最適化されており、異種アクセラレータではカーネル水準の適応が不足するという位置づけである。本論文の新規性は、個々の手法（共有メモリ集約、ベクトル化ロード、インラインアセンブリ）ではなく、ROCm互換プラットフォーム上のGPTQカーネルに対して、書き戻し・読み込み・演算の3段階を系統的に洗い出して最適化した実践と、その寄与分離の測定にある。

## 限界・実装状況

評価は単一プラットフォーム（DCU Z100）と単一のバッチ条件に限られ、バッチサイズ感度や並列デコード時の挙動は今後の課題とされる。スループット・遅延は相対向上率のみで絶対値がなく、他研究との定量比較が難しい。ILA-OptはDCUの命令セットに依存し、他プラットフォームへの移植には書き直しが要る。ベースラインの記述では重みと活性をFP16で保持しつつGPTQ 4ビットを有効化するとあり、比較条件の詳細は読み取りに注意が要る。コードの公式公開先は論文中に示されていない。

## 一般的な実装上の含意

推論カーネルを新しいアクセラレータへ移植する際は、まず「書き戻しの競合」「ロードの粒度」「命令選択」の3点をカーネル内で点検すると、方式変更なしに大きな利得が得られる場合がある。特に原子加算の集約は、部分和の書き戻しが集中するカーネル一般に効く型であり、ベクトル化ロードはデータ型の自然な幅（ここではhalf2）へ転送粒度を揃えるという汎用の原則である。寄与分離の測定（単独適用と統合適用の両方を測る）をしておくと、プラットフォームごとに効く最適化が違う場合でも、移植先で優先すべき順序を判断できる。逆に、方式の新しさだけを追ってカーネル内部の無駄を放置すると、理論上は高速なはずの量子化が現場では遅いままになる。本論文の結果は、推論基盤の移植では、まず実機のメモリ階層と命令セットに合わせて既存カーネルを磨く作業が、最も確実な性能改善の入口であることを示している。
