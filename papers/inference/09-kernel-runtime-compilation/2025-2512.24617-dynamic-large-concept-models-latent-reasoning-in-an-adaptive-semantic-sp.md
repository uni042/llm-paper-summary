# Dynamic Large Concept Models：可変長概念空間へ計算を集中する階層言語モデル

## 概要

大規模言語モデルは、次トークンの予測が容易な部分にも、意味の転換や推論を必要とする部分にも、通常は同じ層数の計算を適用する。Dynamic Large Concept Models（DLCM）は、この一様な計算配分を改め、軽量なトークン符号化器で得た潜在表現から可変長の概念区間を検出し、短縮した概念系列へ高容量のTransformerを適用する。最後に、概念表現を因果クロス注意によってトークン予測へ戻す。固定された文・段落の区切りを使わず、内容によって区間長を変える点が特徴である。

原著は平均4トークンを1概念へ圧縮するR=4の条件を中心に、通常の1.3B Transformerと、概念段に容量を再配分した2.3B DLCMを比較した。両者の推論浮動小数点演算量（FLOPs）を近づけた条件で、12種類のゼロショット課題の平均正解率は41.23%から43.92%へ2.69ポイント改善した。一方、BoolQは64.01%から62.54%、RACEは36.03%から35.31%へ悪化する。推論カーネル単体では概念の鍵・値を複製してFlashAttention VarLenへ渡す方式がFlex Attention比1.26〜1.73倍高速だが、これはモデル全体の生成速度ではない。

本研究の主眼は、総パラメータ数の削減ではなく、トークン段から概念段へ計算を移し、同程度のFLOPs予算でより大きいモデル容量を活用することである。概念K/Vの複製はメモリ使用量を増やし得るため、FLOPs削減、モデル常駐メモリ削減、初回トークン遅延短縮を同義に扱ってはならない。

## 問題設定

標準の因果Transformerは長さLの系列の各位置へ同じ深さの処理を行う。文章の局所的に予測可能な区間と、意味が切り替わる重要な位置で計算密度を変えられない。文単位の概念モデルでは分割粒度があらかじめ固定され、プログラムや数式、複数言語の情報密度の違いに対応しにくい。単純にトークンを削除すると、局所的な否定表現や識別子など次トークン予測に必要な情報が失われる。

DLCMは、トークンを軽量な符号化器に残したまま、より高価な推論段だけを短い概念系列へ移す。符号化器、境界検出、プーリング、概念段、復号器の総計算量を管理する必要があるため、単純な系列長短縮率Rから生成速度を推定できない。とくに境界決定は離散的であり、語彙予測損失をそのまま境界の決定へ逆伝播すると、境界を減らす圧縮目的と情報損失を避ける語彙予測目的が競合する。

## 手法

### 1. トークン符号化と潜在境界

入力トークン列xを因果Transformer符号化器Eへ通し、長さL、幅d_tokenの表現H=E(x)を作る。このHは概念境界を決めるだけでなく、最後のトークン復号器の問い合わせとしても使うため、区間化した後でも細粒度の局所情報を完全には捨てない。各位置tの表現を別々の線形写像Wq、Wkで射影し、直前位置の問い合わせq_(t−1)と現在位置の鍵k_tの余弦類似度から境界確率p_t=(1−cos(q_(t−1),k_t))/2を計算する。最初の位置は必ず境界にする。

学習時には温度を用いて境界確率を鋭くした後、ベルヌーイ抽出で離散境界を決める。推論時にはp_t≥0.5で境界を確定する。境界スコアは学習した潜在表現に依存するが、離散境界の選択を主たる言語モデル損失に完全に微分可能な形で接続する方式ではない。原著の第3.3節と第8.1節は、離散決定と語彙予測損失を意図的に分離して安定性を確保する点を説明している。低い類似度を意味変化の代理とするため、潜在表現が局所意味を十分に表していない場合は境界の品質も落ちる。

### 2. 可変長概念の形成と圧縮率の制御

境界列bに従って連続区間S_1,...,S_Mを作り、各区間のトークン表現を平均プーリングする。平均した表現をW_upで概念幅d_conceptへ射影してc_kを得る。概念系列Cの長さMは通常Lより短く、R=4なら平均M≈L/4である。区間の意味的まとまりを優先するため、すべての系列に厳密な4トークン固定長を強制しない。

圧縮率の制御には全体解析器（Global Parser）を使う。分散学習バッチ全体で境界確率の平均G_globalと実際の境界率F_globalを集約し、目標1/Rに近づける補助損失L_auxを次トークン交差エントロピーへλ倍して加える。集計には全プロセス間のAllReduceが必要で、学習時の通信費用が追加される。バッチ全体の制約とすることで、原著表5ではR=4の下でも英語の一般文3.53、中国語の一般文4.36、コード3.66、数式・科学文4.41トークン/概念という内容依存の差が残る。

### 3. 概念段とトークン復号

短縮したCを深い因果Transformer Mへ入力し、概念出力Z=M(C)を得る。主実験では符号化器10層、概念段16層、復号器6層の計32層、概念幅3072、トークン幅1536を使う。概念段は長さMだけを処理するため、幅と容量を大きくしても同程度の推論FLOPsへ調整できる。これは重みの保存容量が1.3B基準モデルと等しいという意味ではない。

復号側ではZを平滑化した後、符号化器のHから問い合わせQ、概念側から鍵K・値Vを作る。トークン位置tが参照できる概念は、その時点までに現れた境界の累積数j(t)=Σ_(i≤t)b_i以下に制限する。こうして未来トークン情報の漏洩を避けながら、概念段の高水準情報をトークン表現へ残差加算して次語予測する。概念幅とトークン幅の違いは射影で吸収するが、クロス注意自体は追加の計算である。

### 4. 不規則な概念注意を実機カーネルへ写像

数学的には長さLのトークンから長さMの概念への不規則なL×M注意が必要になる。区間長が変動するため、Flex Attentionで直接マスクを生成すると動的マスクと不規則メモリアクセスの費用が大きい。DLCMは各概念のK/Vをその区間に含まれるトークン数だけ複製し、長さLの規則的なK/V列へ展開する。これにより標準の因果マスクを用いるFlashAttention VarLenの最適化済みカーネルを利用する。

複製は概念の内容を変える操作ではなく、同じ概念を区間内の各トークン位置へ対応させる実装変換である。GPUでは不規則マスクの生成を減らせるが、複製後のK/V表現は長くなり、メモリ消費を増やす。この利得と費用の交換は、論文の独立カーネル測定で確認される一方、全体の初回トークン遅延やKVキャッシュ常駐量にはそのまま外挿できない。

### 5. 異種幅モデルの学習安定化と規模則

概念段とトークン段の幅が異なるため、単一の学習率・初期化分散を機械的に適用すると学習が不安定になる。著者らは最大更新パラメータ化（μP）を段別に調整し、トークン段、概念段、埋め込みで幅に応じた学習率を設定する。87Mの代理モデルで調整した設定を274M、468M、834Mへ移し、幅の違いを考慮した移植を検証した。

さらに総パラメータN、学習データD、圧縮率R、概念段へのパラメータ配分率Pを用いる規模則L(N,D,R,P)を導入する。R=2/4/8とP=30/50/70%の組合せで学習損失を予測し、FLOPs予算の下でどこへ容量を割り当てるべきかを調べる。損失曲線の当てはまりが良いことは、GPUの実測遅延や実サービスのエネルギー効率を予測できることを意味しない。

## 評価

### 1. 比較条件と測定指標

主比較は通常Transformer 1.3BとDLCM 2.3Bで、同じ1兆トークンの事前学習、近い推論FLOPsの条件を使う。学習データは英語ウェブ50%、中国語ウェブ25%、コード15%、数学10%を中心に構成される。評価指標は12種類のゼロショット課題の正解率とその単純平均である。モデル規模が異なるので、パラメータ当たりの効率や同じVRAM容量での性能比較ではない。別にカーネル単体の時間、圧縮率の安定性、概念位置ごとの損失、学習規模則を測る。

### 2. 12課題の主要結果

| 課題 | 通常Transformer | DLCM | 差（ポイント） |
|---|---:|---:|---:|
| CommonsenseQA | 19.74% | 21.38% | +1.64 |
| HellaSwag | 45.99% | 46.66% | +0.67 |
| OpenBookQA | 23.80% | 26.80% | +3.00 |
| PIQA | 73.10% | 75.52% | +2.42 |
| ARC Challenge | 33.04% | 34.81% | +1.77 |
| BoolQ | 64.01% | 62.54% | −1.47 |
| RACE | 36.03% | 35.31% | −0.72 |
| MMLU | 25.70% | 25.40% | −0.30 |
| CMMLU | 25.47% | 25.23% | −0.24 |
| **全12課題平均** | **41.23%** | **43.92%** | **+2.69** |

表は原著第7.1節の主要行を抜粋した。平均は掲載していないWinogrande、ARC Easy、C-Evalも含む全12課題から計算される。概念境界に計算を集中する設計は常識推論や知識を問う一部課題に有利だが、否定・局所的な語彙関係に敏感なBoolQやRACEでは劣化する。平均値だけから「全課題で精度を維持した」とは言えない。2.69は正解率の絶対パーセントポイント差であり、推論速度倍率ではない。

### 3. 注意カーネルの単体評価

原著第4.2節では、可変長概念の不規則なクロス注意をFlex Attentionで直接処理する方法と、概念K/Vを複製してFlashAttention VarLenで処理する方法を比較した。隠れ幅1024、2048、4096、系列長2Kから16Kの測定で、複製方式の速度比は1.26〜1.73倍。2Kで平均約1.44倍、16Kで平均約1.70倍、隠れ幅2048・16Kで最大1.73倍だった。規則的なメモリアクセスが不規則マスク生成の費用を避ける効果を示すが、モデル全体の復号速度、同時要求処理量、消費電力は測っていない。

### 4. 境界学習と圧縮率の構成要素除去

原著第8.1節では、8,192トークンを約4倍へ圧縮する目標で、境界の離散決定まで主損失へ接続する方法と、潜在類似度に基づく分離方式を比較した。前者は学習開始時には概念数約2,000だが、進行後は約4,300まで増え、実質圧縮率が約1.9倍へ低下した。後者は約2,000概念を維持した。圧縮を守る補助損失と語彙予測の損失が競合することを示す負の結果である。

原著第8.2節では、全体解析器の実現圧縮率3.92に対し、系列ごとの正則化は3.15にとどまった。ARC Challengeは30.38%対28.58%、CommonsenseQAは24.57%対22.28%と全体解析器が優れる一方、OpenBookQAは32.20%対32.80%で劣る。第8.2節本文には目標R=2と記す箇所があるが、表4と周辺説明はR=4を示すため、原著内の不一致として残す。

### 5. FLOPsと容量の解釈

概念段へ計算を集中させることで、2.3Bの総パラメータを1.3B基準モデルと近い推論FLOPsで使える。原著は構成によって最大約34%のFLOPs削減可能性にも言及するが、これは主表の「正解率+2.69ポイント」と同じ実験条件でGPUの壁時計時間が34%短縮したという測定ではない。重み常駐量、概念K/V複製、カーネル効率を考慮した実測が必要である。

## 既存研究との差

固定の文境界を用いる大規模概念モデルと違い、DLCMは潜在表現の局所差から可変長区間を構成する。H-Netは階層的な境界学習の先行例だが、DLCMはトークン単位の次語予測モデルへ接続し、概念段への容量配分と圧縮率を同時に扱う規模則を示す。専門家混合（MoE）がトークンごとに使用するパラメータ集合を変えるのに対し、DLCMは深い計算を適用する位置の数を減らす。二つは異なる最適化軸であり、併用性能は本論文では確証されていない。

## 限界と再現性

第一に、モデル容量2.3B対1.3Bの比較はFLOPsを近づけたものであり、重み保存量やVRAM使用量が同等であることを示さない。概念K/Vを複製するカーネル実装は速度のためにメモリを増やし得る。第二に、BoolQ、RACE、MMLU、CMMLUでの負の結果から、可変長圧縮が細かな語彙情報を損なう場合がある。第三に、離散境界の学習には圧縮率を守る補助目的と語彙予測の間の緊張があり、主損失で境界を直接最適化すると圧縮率が崩れる実測がある。

第四に、端から端までの生成遅延、KVキャッシュの実際のメモリ容量、多数同時要求の処理量、CPUオフロード、Windows環境での実測は原著の主評価から判断できない。第五に、原著第5節は公開コーパスからデータを構築したとする一方、第7.1節に同一の「proprietary dataset」と記す箇所があり、学習データの公開性に表記上の不一致がある。再現には正確なデータ配合、学習条件、境界学習の実装を確認する必要がある。公式コードの公開場所は一次資料から確証できず、`code: null` とした。
