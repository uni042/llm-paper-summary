# A Thread-Register Decoupled GPU Execution Model for Efficient Tensor Computation

> FIBERはGPUの実行単位から私有レジスタ所有を切り離し、SM内共有レジスタ、動的な並列度変更、レジスタ単位の依存追跡を組み合わせる。LLMのGEMMと非GEMMが交互に現れる処理を対象に、シミュレータ上でAmpere 2.25倍、Hopper 1.8倍、Blackwell 2.09倍のエンドツーエンド高速化を報告する。

## 概要

現代GPUでは行列積を高速に処理するTensor Coreのピーク性能が急速に伸びている。一方、大規模言語モデル（LLM）の推論は汎用行列積（General Matrix Multiplication; GEMM）だけで構成されず、正規化、活性化、注意機構、量子化・型変換、メモリ移動など非GEMM演算を頻繁に挟む。それぞれの段階で最適なスレッド並列度、レジスタ量、データ共有方法が違うため、Tensor Core単体の性能が高くても、その前後をうまくつなげなければGPU全体の利用率は上がらない。

従来の単一命令複数スレッド（Single Instruction Multiple Thread; SIMT）では、スレッドが自分専用のレジスタを所有する。多数のスレッドを起動するとレジスタ消費も増え、SMに同時常駐できるワープ数が減る。一方、演算段階によっては少数スレッドでも十分であり、別段階ではより高い並列度が欲しい。起動時に決めた固定構成は、この変化へ追従しにくい。

もう一つの問題はデータ受け渡しである。別ワープが生成した値を使うには、共有メモリへ一度書き出し、バリアで同期し、別ワープが読み戻す経路になりやすい。これはデータ量そのものだけでなく、粗粒度同期で「一部の値だけ準備できていないのにワープ全体が待つ」空白を作る。

FIBERは、従来スレッドに相当する軽量実行単位「fiber」から私有レジスタ所有を外す。fiberはプログラムカウンタなど最小の制御状態だけを持ち、SM内の物理レジスタを共有ビューとして参照する。これにより、演算段階に応じて実行fiber数を変更し、異なるfiber間でも共有メモリを介さずレジスタから直接値を受け渡せる。

このために命令セットアーキテクチャ（Instruction Set Architecture; ISA）、SMマイクロアーキテクチャ、コンパイラを同時に拡張する。典型的な混合精度LLMサービングをGTSimで評価した結果、Ampere相当で2.25倍、Hopper相当で1.8倍、Blackwell相当で2.09倍のエンドツーエンド実行サイクル短縮を報告する。カーネル単体では最大2.49倍である。一方、Ampereで元のFP16処理だけを比較すると1.15倍であり、2.25倍の大きな差には混合精度処理全体の再構成効果が含まれる。

## 問題設定

### 固定並列度が演算段階の違いを吸収できない

SIMTでは、ワープ内のスレッド数と各スレッドが占有するレジスタが密接に結び付いている。GEMMではTensor Coreへ十分なオペランドを供給するための並列度が必要だが、ベクトル演算や型変換では同じ構成が過剰な場合がある。逆に非GEMM段階に合わせてスレッドを減らすと、Tensor Core段階を埋められない。

カーネルを細かく分けて段階ごとに起動構成を変える方法もあるが、カーネル境界での起動、同期、中間値の退避が増える。FIBERは1つの実行中プログラムの中で並列度を変えたい、という問題設定を取る。

### 私有レジスタがワープ間データフローを遠回りさせる

従来レジスタはスレッド私有なので、他ワープの値を直接読む一般的な経路がない。そのため、Tensor Core前後のプロデューサーとコンシューマーを別ワープへ割り振ると、共有メモリを介した通信とバリア同期が必要になる。これが粗粒度スケジューリングを生む。

AmpereではTensor Coreオペランドをレジスタから供給するため、同じ行列断片を複数スレッドが重複保持する場合もある。Hopper/Blackwellではメモリベースの供給で重複を減らしているが、LLM全体のGEMM・非GEMM混在を動的に編成する問題は残る。

本論文の着眼点は、レジスタを「各スレッドの所有物」ではなく「SM内で共有可能なデータフロー資源」と捉え直し、実行単位数とレジスタ配置を独立に制御することである。

## 手法

### 1. fiber: レジスタを所有しない軽量実行単位

fiberは従来スレッドに似た制御単位だが、専用レジスタ名前空間を持たない。プログラム位置、実行状態など最小限の制御情報を保持し、演算の入力・出力はSM内共有レジスタへ明示的にアクセスする。

同じ命令を同時実行するfiber群はweftとしてまとめられ、従来のwarpに近い役割を持つ。違いは、weftの幅とレジスタ所有が固定的に結び付かない点である。

### 2. SET_FIBER_NUMで実行中に並列度を変更する

FIBERは実行fiber数を変更する命令を追加し、演算段階に応じて有効並列度を変える。例えばTensor Coreへ大量オペランドを供給するときはfiberを増やし、少数のベクトル演算へ移ったら減らす、といったマッピングが可能になる。

この機能の目的は単純な「スレッドを増やせば速い」というものではない。レジスタ容量、実行パイプライン、メモリアクセスの必要量に合わせ、不要なfiberを休止して資源競合を減らすことにある。

### 3. SM全体の共有レジスタアドレッシング

従来はサブパーティション内のスレッドから見えるレジスタが局所的だが、FIBERは命令形式を拡張してSM内の物理レジスタを広く参照できるようにする。これにより、あるfiberが生成した中間値を別fiberが共有メモリへコピーせず直接消費できる。

共有アクセスには競合が生じるため、読み出しポート調停器、選択器、クロスバーを追加する。同一アドレスへの複数要求などをまとめ、レジスタバンク競合で利得を失わないようにする。

### 4. Register Busy Bitmapで依存をレジスタ単位に追跡する

FIBERは各物理ベクトルレジスタが準備済みかどうかをビットマップで管理する。命令は必要な入力レジスタが未準備なら待つが、無関係な命令やfiberまで大きなバリアで停止させる必要はない。

この細粒度依存追跡により、従来のnamed barrierや共有メモリ同期で作られていた空白時間を減らす。論文で分析した一部attention kernelでは、総サイクルの25%超を占めていた同期負担がほぼ消えるケースを示す。

### 5. コンパイラがfiber配置とレジスタデータフローを決める

ハードウェアだけ変えても、既存CUDAコードが自動で共有レジスタを使うわけではない。FIBERはコンパイラ側で演算をfiber/weftへ割り当て、どの段階で並列度を変え、どのレジスタをproducer-consumer間で共有するかを生成する。

したがって提案は単一の新命令ではなく、実行モデル、ISA、依存追跡、オペランド配送、コンパイラマッピングを一体で変えるアーキテクチャである。

## 評価

### 評価条件

| 項目 | 条件 |
|---|---|
| 評価方法 | GTSimによるGPUサイクルシミュレーション |
| 対象世代 | Ampere、Hopper、Blackwell相当 |
| 主ワークロード | 混合精度LLMサービング、attention/GEMM/非GEMMを含む |
| 比較 | 各世代のネイティブCUDA実行モデル。Hopper/Blackwellではwarp specialization等も反映 |
| 主指標 | エンドツーエンド実行サイクル、カーネル高速化、同期停滞、面積・電力見積もり |

|---|---:|---|

### 結果の読み方

最も大きい2.25倍は「Tensor Core自体が2.25倍速くなる」結果ではない。LLMサービング全体で、混合精度化、GEMM前後の非GEMM処理、データ受け渡し、同期を含めた実行サイクルが減った結果である。FP16のみでは1.15倍なので、何をベースラインに含めるかで見える速度向上が大きく変わる。

Hopper/Blackwellでも利得が残ることは、Tensor Coreへのオペランド供給を改善するだけでは、演算段階間の固定並列度と依存管理を解決し切れないという著者の主張を支える。ただしこれもシミュレーション上の比較であり、製品GPUへ同等の回路を載せた実測ではない。

## 既存研究との差

warp specializationは、loader warp、compute warpなど役割別にワープを固定してパイプライン化する。FIBERはさらに、実行単位を私有レジスタ所有から外し、演算途中で並列度を変え、共有レジスタ上でproducer-consumer依存を直接追う。

Hopper/BlackwellのメモリベースTensor Core供給は行列オペランド重複を減らすが、FIBERはそれを特定行列命令だけの機構としてではなく、SM全体の実行モデルへ広げる。目的はピークFLOPSの増加ではなく、異種演算を含むパイプラインの「つなぎ方」の効率化である。

## 限界

- 評価の中心はGTSimであり、実シリコンの周波数低下、配線混雑、物理設計、温度制限を完全には再現しない。
- 共有レジスタアクセスはクロスバーとポート競合を増やす。アクセス局所性が悪いプログラムでは新しい競合が支配する可能性がある。
- ISA・SM・コンパイラを同時変更するため、現行CUDA GPUへソフトウェア更新だけで導入できない。
- LLMサービングで大きい利得が報告されるが、固定並列度や同期が支配的でないカーネルでは改善幅が小さい。
- 面積・電力値は設計見積もりであり、量産チップの実測ではない。
- FP16単独のAmpere結果は1.15倍で、混合精度シナリオの2.25倍と分けて扱う必要がある。
- 将来GPUでより柔軟なwarp-specializationやレジスタ共有機構が標準化されれば、FIBERとの差は再評価が必要になる。
