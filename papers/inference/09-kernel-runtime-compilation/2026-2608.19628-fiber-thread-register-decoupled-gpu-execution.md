# A Thread-Register Decoupled GPU Execution Model for Efficient Tensor Computation

> FIBERはスレッドとレジスタの結び付きを外し、SM内共有レジスタと細粒度依存管理でTensor Core周辺の固定並列度・データ移動を抑えるGPU設計で、LLM配信をシミュレータ上で世代別に最大2.25倍高速化する。

## 概要

GPUでは行列積が大きな割合を占めるため、専用行列演算器（Tensor Core; TC）が世代ごとに強化されてきた。一方、現代のLLM処理は行列積だけで進まず、注意機構、全結合層、活性化、型変換など異なる種類の演算を交互に行う。演算段階が切り替わるたびに必要な並列度やレジスタ量も変わるが、従来のSIMT方式では起動時にスレッド数と各スレッドの私有レジスタ量を固定する。加えて、異なるワープ間のデータ共有は共有メモリを介した段階同期になりやすい。このため、演算器が速くなっても固定された実行構成と粗い同期がパイプライン全体の効率を制限する。

FIBERは実行する単位とレジスタを所有する主体を分離するGPU実行モデルである。従来のスレッドに相当する「ファイバー」はプログラム位置など最小限の状態だけを持ち、個別のレジスタ集合を持たない。同じストリーミング・マルチプロセッサ（Streaming Multiprocessor; SM）上のファイバーは、共有ビューを通じてレジスタファイルへアクセスする。この設計によって、実行中にファイバー数を増減し、演算段階ごとに並列度を合わせることを狙う。

## 問題設定

従来GPUでは、スレッド数を増やすと同時にレジスタ消費も増える。逆にレジスタ使用量の大きなカーネルでは、同時実行できるワープ数が減り、演算器を十分に埋められないことがある。LLMのカーネルはメモリ律速・行列演算律速・ベクトル演算律速の段階を行き来するため、ひとつの固定構成が全段階に適するとは限らない。入れ子状のカーネル起動による動的並列化は起動費用があり、カーネル内部で軽く実行並列度を変更する方法にはなりにくい。

データ依存の管理にも粒度の限界がある。共有メモリによるワープ間受け渡しは広い単位での段階同期を伴う。一方、従来の細粒度依存追跡はワープが所有する私有レジスタに閉じているため、別ワープが生成した値を直接消費するデータフローを表現しにくい。FIBERは実行単位をレジスタ所有から外すことで、同じSM内での並列度調整とレジスタ単位の依存追跡を一体で扱う。

FIBERの代表結果は、論文のエンドツーエンド評価でAmpere世代比2.25倍、Hopper世代比1.8倍、Blackwell世代比2.09倍の高速化を報告した点である。これらはカーネル単体の最大2.49倍とは別の指標で、異なる世代のGPUに対する評価結果として区別して読む必要がある。

## 手法

### ファイバーと共有レジスタ

ファイバーはSIMTスレッドに似た制御単位だが、私有レジスタを持たない。ファイバーの状態はプログラムカウンタや識別子、制御フラグなどに絞り、レジスタ値はSM内で共有されるレジスタ資源に置く。したがって、コンパイラが起動時に各スレッドへ割り当てたレジスタ数に並列度が固定されず、演算段階に応じてスケジューラが実行中のファイバー数を調整できる。

共有レジスタは通信にも使う。ある演算単位が書いた値を別の演算単位がレジスタから直接読み出せるため、ワープ間で値を共有メモリへ書き出し、同期し、再読込する経路を減らせる。共有はSM内に閉じるため、SMをまたぐ任意の通信を可能にするものではない。

### レジスタ依存を使う細粒度スケジューリング

FIBERはレジスタごとにビジー状態を追跡し、値が準備できていない命令だけを待たせる。これにより、大きな演算段階全体を同期させず、依存のない処理を先へ進められる。論文の設計では、共有レジスタアクセス用の選択器・クロスバー、競合を裁く調停器、ファイバー間の依存を記録するビットマップを追加する。

追加ハードウェアが増えると、レジスタポート競合や依存状態管理が新しい律速になり得る。そこで論文は既存の物理レジスタ構成を大きく置き換えず、共有ビューと依存管理を薄く追加する構成を提示している。これはシミュレータ上の設計評価であり、既存製品GPUへソフトウェアだけで導入できる機能ではない。

### 行列演算器へのオペランド供給

行列演算器へデータを供給する方法も世代により異なる。古い方式ではワープごとに行列断片をレジスタへ持つため、同じオペランドの重複保持が起き得る。Hopper・Blackwell世代ではメモリを介して複数ワープが行列データを再利用する方式が使われる。FIBERは共有レジスタを、ワープをまたぐ再利用先として使い、行列演算器に必要な供給を維持しつつレジスタ内での値の受け渡しを行う。

この仕組みが効くかは、演算がレジスタ再利用や同期にどれだけ制約されるかに依存する。行列積演算そのものを新しい数値アルゴリズムへ置き換えるものではなく、演算の並べ方と値の移動経路を変更するアーキテクチャ提案である。

## 評価

評価にはタイル依存関係を中心にGPU実行をモデル化するGTSimを用いる。論文はLLMワークロードを複数世代のGPU構成で評価し、シミュレータがそれらのワークロードで平均絶対百分率誤差1.2〜11.3%を持つことを前提にしている。比較対象は各世代のCUDAネイティブ実行で、HopperとBlackwellではワープ特殊化、ワープグループ行列演算、非同期パイプラインも有効にする。したがって、報告値は実機で測定した遅延ではなく、GTSimのサイクル評価による比較である。

典型的な混合精度LLM配信条件では、実行サイクルの高速化がAmpereで2.25倍、Hopperで1.8倍、Blackwellで2.09倍、カーネル単位で最大2.49倍と報告される。面積増加は0.1%未満、電力増加は0.4%未満という見積もりも示す。Ampereで元のFP16計算だけに限定した場合は1.15倍であり、混合精度シナリオの結果と同一視できない。

## 結果の解釈と限界

FIBERが示すのは、専用演算器のピーク性能を上げるだけでなく、演算器の間で値を共有し、段階ごとに並列度を変える実行モデルが総処理時間に影響することだ。特に固定構成と粗粒度同期の影響が大きいワークロードで改善が期待される。一方、通常のカーネルでレジスタ依存が少ない場合や、メモリ帯域・演算器そのものが支配的な場合に同じ倍率が得られるとは限らない。

評価はサイクルレベルのシミュレーションであり、実チップのクロック、コンパイラ、実際の命令配置、電力・温度制限を含む製品環境での再現を保証しない。論文の数値をGPU世代一般の実測速度向上として扱わず、複数構成のLLMカーネル評価を実機で再現することが次の検証になる。

## 既存研究との差

従来のワープ特殊化は役割の異なるワープを分け、非同期実行や共有メモリで段階間をつなぐ。FIBERはその上で、ファイバーから私有レジスタ所有を外し、SM内共有レジスタを直接データフローとして使う点が異なる。動的並列度、細粒度依存追跡、行列オペランドの再利用を一つの実行モデルに結び付けることが中心的な貢献である。

## まとめ

FIBERは、固定スレッド数と私有レジスタを前提にしたGPU実行から、ファイバー単位の制御とSM共有レジスタを分離した実行へ移る設計を提案する。論文はLLMカーネルを用いたGTSim評価で複数世代のGPUに対する速度向上と小さなハードウェア費用を報告するが、実機での性能保証ではない。今後比較する際は、シミュレーションか実測か、精度、世代、カーネル単位か配信全体かをそろえる必要がある。
