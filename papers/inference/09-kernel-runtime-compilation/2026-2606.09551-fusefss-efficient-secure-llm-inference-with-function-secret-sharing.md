# FuseFSS: Efficient Secure LLM Inference with Function Secret Sharing

> 2サーバ秘匿推論の非線形演算を演算子ごとの手作りプロトコルから、区間と多項式片と述語の仕様を2回の関数秘密分散評価へ落とす単一コンパイラへ置き換え、精度を保って1.24から1.50倍高速化する研究。

## 概要

2サーバ型の秘匿推論は、クライアントが入力を結託しない2台のサーバへ秘密分散し、プロンプトや埋め込みを明かさずにホストされた大規模言語モデルを使える方式である。前処理モデルでは、オフライン相でBeaverトリプル等の相関乱数と関数秘密分散（Function Secret Sharing; FSS）の鍵を用意し、オンライン相では秘密分散のまま低遅延に評価する。近年のGPU実装で線形層は高速になったが、残る支配的費用は固定小数点演算の要素ごとの非線形演算と再スケーリングである。これらは剰余環の回り込みの下での比較と片の選択を要し、従来は演算子ごとに比較、回り込み補正、事前材料を備えた専用プロトコルを手作りしていた。個別設計は正しさの論証を複雑にし、鍵生成の論理を重複させ、新しい演算子を足すたびに符号や回り込みの微妙なバグを招く。

FuseFSSの観察は、一般的な固定小数点非線形演算を通じて、データ依存の部分はほぼ共通だということである。各演算子は、小さな述語ビットの集合で領域を選び、低次の算術形式を小さな定数群で適用する形に書ける。そこでFuseFSSは演算子仕様という型付き記述を導入する。仕様は、環の代表元に対する区間分割、区間ごとの低次多項式、述語回路で表したブール補助ビットを並べたものである。コンパイラは各ゲート実例を、公開されたマスク値に対する2回の標準的なFSS評価へ落とす。1回は必要な全述語ビットのXOR分散を返すパック比較、もう1回は有効な係数と定数を加法分散で返すベクトル区間参照であり、残りはBeaver乗算やブールANDやビットから算術への変換を使う固定した分散後処理回路である。

**代表結果:** 最先端のFSS型GPU秘匿推論であるSigmaと比べ、系列長128・バッチ1のエンドツーエンドで、BERT-tinyは63.90ミリ秒から42.60ミリ秒へ33.3%短縮、BERT-baseは1613.80ミリ秒から1149.50ミリ秒へ28.8%短縮、GPT-2は1423.90ミリ秒から1072.70ミリ秒へ24.7%短縮し、総括では1.24から1.50倍の高速化、オンライン通信の9から16%削減、鍵生成時間の14から23%短縮、鍵サイズの20から24%削減を、モデル精度を保ったまま達成した。

## 問題設定

問題は性能と工学の両面にある。性能面では、マスク付きワイヤのパラダイムでは各当事者が公開マスク値を開示し、その上で述語を評価するが、述語はマスキングの下で書き換えが必要で、マスク由来の繰り上がりや回り込みの情報は秘密分散のまま保たなければならない。演算子ごとにこの書き換えを手作りすると、比較の回数も事前材料も演算子の数だけ増え、GPU実行でも非線形部がオンライン時間と通信の大半を占める状態が続く。BERT-baseでは、Sigmaのオンライン時間の56%、通信の54%が非線形・補助ブロックに帰属すると実測される。

工学面では、個別プロトコルの寄せ集めは正しさと安全性の論証を演算子ごとに繰り返す構造であり、拡張性がない。求められるのは、演算子の意味を宣言的に書けば、述語のマスク書き換え、回り込みの隅の処理、ビット論理と固定小数点算術の相互作用を一括で処理し、正しさと半正直安全性の証明を1回で全演算子へ適用できるコンパイル経路である。さらに、マスク値が公開される設計では、鍵の大きさや公開される実例形状からマスクが漏れる経路を塞がなければならず、形状をマスク非依存に固定するという漏洩側の制約も同時に満たす必要がある。

## 手法のあらまし

処理はコンパイル時とオンライン時で進む。前処理では、各ワイヤごとに独立な入力マスクを標本し、演算子仕様とマスクから、境界をマスク空間へ平行移動し、述語を公開マスク値上の比較と秘密の繰り上がりビットで書き換え、全比較原子を記述順に束ねたパック比較実例と、全区間の係数と定数を束ねた区間参照実例を生成し、形状を固定長へパディングしてFSS鍵と相関乱数を用意する。オンラインでは、まず秘密分散した入力へマスクを加えて公開マスク値を開示し、パック比較で全述語ビットのXOR分散を得て、区間参照で有効な係数と定数の加法分散を得て、固定した後処理回路で多項式評価と補正を行い、出力の分散を返す。ゲート種別ごとにコンパイル済みプログラムは層をまたいで再利用されるが、マスクと鍵はワイヤごとに新しく、再利用はされない。

## 手法

### 1. 演算子仕様 — スカラー固定小数点演算子を区間・多項式片・述語へ分解する

この機構が観測するのは、環の上のスカラー固定小数点演算子の入出力関係である。保持する状態は型付きの仕様であり、代表元区間の分割、各区間の次数上限付き多項式ベクトル、各区間のブール補助ビットを原始述語（閾値との比較、低ビット述語、最上位ビット検査とその論理結合）で表したものである。対象は活性化、負の指数関数、逆数や逆平方根、切捨てや算術右シフトのような再スケーリング補助であり、これら要素ごとの演算が秘匿トランスフォーマー推論の費用を支配する。選択されるのは入力が属する区間と、その区間の係数であり、これにより減るボトルネックは演算子ごとのプロトコル設計そのもので、新しい演算子は仕様を書くだけで同じ実行経路へ乗る。追加で消費する資源は仕様の記述と検証であり、実行時の費用ではない。誤った場合の挙動として、最大値や総和のような座標を混ぜるベクトル演算は単変数スカラー写像ではないため仕様の対象外であり、標準の多者計算サブプロトコルが回路レベルで担う。この境界を明示している点が、コンパイラの適用範囲を過大に主張しない設計になっている。区間指示子は2つの比較のXORで表せるため、区間選択に追加のANDゲートが要らないことも仕様側の工夫である。

### 2. マスク配慮型コンパイルと2回のFSS評価 — 述語と係数を一括で取る

この機構が観測するのは、公開マスク値と前処理で標本されたマスクである。保持する状態は、平行移動した境界、秘密分散された繰り上がりビット、固定順に束ねられた比較原子の列、区間ごとの係数ペイロードである。処理は三段であり、境界をマスク空間へ移すと最大で1区間だけが原点を回り込むため分割は最大で区間数+1個になり、述語は「マスク値とずらした閾値の比較」と「マスク由来の繰り上がりビット」のXORへ書き換えられ（繰り上がりビット自体は秘密のまま）、全述語を1回のパック比較で、係数と定数を1回のベクトル区間参照で取得する。これにより減るボトルネックは、演算子ごとに分散していた比較の往復と鍵生成の重複であり、ゲートあたりのFSS呼出しが定数2回へ揃う。追加で消費する資源は形状固定のためのパディングであり、代表的なGELUゲートではパディングで評価時間が0.264ミリ秒から1.014ミリ秒へ増えるという実測の代償が正直に報告される。これはマスク依存の形状が鍵長を通じてマスクを漏らすため、漏洩モデル上必須の費用である。誤った場合の挙動として、マスクをワイヤ間で再利用すると公開値の差から秘密の関係が漏れるため、再利用は禁止され、プログラムの再利用と材料の再利用が明確に区別される。再利用の除去実験では、層ごとにプログラムを生成し直すと初期化が0.903ミリ秒から10.389ミリ秒へ増えるがオンライン評価は変わらず、節約の所在が初期化にあることも切り分けられている。

### 3. 固定した後処理回路とバッチ化 — 残りの計算を標準部品で揃える

この機構が観測するのは、述語ビットのXOR分散と係数の加法分散、そして公開マスク値から局所的に復元できる未マスク入力の分散である。保持する状態は演算子によらない固定の後処理回路であり、処理は、環の加算、Beaverトリプルによる乗算、XOR分散へのブール演算、ビットが算術をゲートする場合のビット・算術変換といった標準の前処理プリミティブだけで、多項式の評価と切捨てや算術右シフトの補正を行うことである。これにより減るボトルネックは、演算子固有の後処理を持ち回ることによる実装の分岐であり、バッチ化された評価と合わせてGPU実行の規則性が上がる。追加で消費する資源はBeaverトリプル等の相関乱数であり、ワイヤごとに一回性の材料として消費される。誤った場合の挙動として、ソフトマックス内部の最大値リダクションのようなベクトル処理はこの回路の外に残り、実際、コンパイル経路を高速化した後は最大値リダクションがソフトマックスの残余費用の主役になることが実測で示される。つまりFuseFSSの利得は、対象をスカラー非線形と補助演算に限定したからこそ得られ、その外側は相補的な最適化対象として残る。

| 構成要素 | 入力・観測 | 具体的な動作 | 改善対象 | 主なトレードオフ |
|---|---|---|---|---|
| 演算子仕様 | スカラー演算子の意味 | 区間・多項式片・述語へ分解 | 演算子ごとの設計 | ベクトル演算は対象外 |
| パック比較 | 公開マスク値 | 全述語ビットを1回で取得 | 比較の往復と重複 | パディングの費用 |
| 区間参照 | 平行移動した分割 | 有効な係数と定数を1回で取得 | 片選択の材料 | 形状固定が必須 |
| 後処理回路 | 述語と係数の分散 | 標準プリミティブで補正と評価 | 実装の分岐 | 相関乱数の消費 |

## 評価

結論は、非線形部のコンパイル統一だけで、精度を落とさずにエンドツーエンドの2割から3割強の短縮と、通信・事前材料の削減が同時に得られる、というものである。主表（系列長128、バッチ1、2台のRTX PRO 6000 Blackwell）では、BERT-tinyが63.90から42.60ミリ秒（33.3%減、通信0.021から0.018GB）、BERT-baseが1613.80から1149.50ミリ秒（28.8%減、通信1.062から0.891GB）、BERT-largeが4034.50から2997.90ミリ秒（25.7%減）、GPT-2が1423.90から1072.70ミリ秒（24.7%減）、GPT-Neoが6326.20から5115.80ミリ秒（19.1%減）となり、モデルが大きいほど絶対量の節約は大きいが相対率はやや下がる。これは線形層と注意の共有費用が分母に残るためであり、ゲート単体では活性化が1.64から2.46倍、通信約24%減、鍵材料が約5から6分の1という大きな利得が、エンドツーエンドでは薄まる構造が付録の帰属分析で説明される。鍵生成はBERT-baseで1.32秒から1.08秒、鍵サイズは18.076GBから13.678GBへ減り、前処理の軽さも一貫する。系列長への感度では、BERT-baseで系列長32では15.1%減にとどまるが、64から512では1.36から1.45倍を維持し、通信の節約は系列長とともに増えるため、短い系列ほど固定費の比率が高いという読み方ができる。帰属の内訳では、ソフトマックス内部のコンパイル経路（負の指数関数と逆数）がBERT-baseで223ミリ秒から49ミリ秒へ4.50倍、GPT-2で4.70倍に高速化され、ソフトマックス全体でも2.22から2.24倍になる一方、最大値リダクションは1.20倍にとどまり、次のボトルネックが移動したことが分かる。モデル全体でもBERT-baseの遅延削減の92.7%をGELU・ソフトマックス・層正規化が説明し、GPT-2ではほぼ全量を説明する。LLaMA系への拡張では利得は小さく、LLaMA-7Bで系列長16から64に対し1.09から1.22倍、LLaMA-3.1-8Bで1.05から1.17倍であり、鍵も71.63GB級と巨大でホスト側バッファとストリーミングを要する点から、大規模生成モデルでは非線形部の比率と材料の大きさが別の制約になることが読み取れる。精度は固定小数点意味論の下でPyTorchとほぼ一致し、GLUEとLAMBADAの差はおおむね±0.6点以内である。ネットワーク投影ではBERT-baseがLANで3.99秒対3.36秒、WANで11.12秒対9.94秒となり、通信削減の分だけ広域でも利得が残る。未評価事項として、SHAFTとの直接比較は提供スクリプトの機器不一致で失敗し、BOLTやBumbleBeeはプロトコル系とハードウェアが異なり同条件比較ができていないため、比較の主張はSigmaへの差し替えという同条件設定に支えられている。悪意ある敵対者への拡張も今後の課題である。

## 既存研究との差

Sigmaとの差は、最適化の単位である。Sigmaが演算子ごとに最適化した building block を手書きで揃えるのに対し、FuseFSSはその手書きを仕様からのコンパイルへ置き換え、同じ固定小数点仕様の下で比較するため、利得が近似を粗くしたことによるものではないと保証する。IRONやBOLTやBumbleBeeといった秘匿トランスフォーマー系との差は、それらが演算子ごとの専用プロトコルで性能を出すのに対し、本論文は拡張性と正しさの単一証明を性能と両立させる点にある。SHAFTがソフトマックス等の特定サブルーチンを掘る方向なのに対し、FuseFSSはスカラー演算子全般を覆うコンパイラであり、両者は相補的と位置付けられる。

## 限界・実装状況

限界は、対象がスカラーの要素ごと演算に限られ、ベクトルリダクションは枠組みの外にあること、安全性が半正直な2サーバ前処理モデルに限られること、形状固定のパディングに実測で無視できない費用があること、大規模モデルでは鍵材料が数十GBから百GB級に達し実運用の制約になること、他システムとの同条件比較がSigma以外で成立していないことである。実装状況は、Sigmaへの差し替えとして実装され同じ仕様で比較されているが、公式コードの公開先は論文中に示されない。精度は固定小数点意味論の範囲で保持され、無損失というより、比較対象と同じ近似の下での一致である。

## 一般的な実装上の含意

秘匿計算のように演算子ごとの手作りが蓄積した領域では、個別最適化を足すより、意味の記述形式を統一してコンパイルする方が、性能・正しさ・拡張性を同時に改善できる。公開値を使う設計では、鍵長や形状のような脇の情報が漏洩経路になるため、形状を入力やマスクに依存させない固定化は性能費用を払ってでも先に決めるべき制約である。材料の再利用とプログラムの再利用は安全性の意味が正反対であり、分けて設計する必要がある。
