# VFA：FlashAttentionの最大値還元・再尺度化を減らすベクトル演算最適化

## 概要

FlashAttentionは、巨大な注意行列をGPUの高帯域メモリへ書き出さず、クエリ・キー・値を小さなブロックに分割してオンチップメモリで処理する。行ごとのsoftmaxを安定に計算するため、ブロックを読むたびに最大値を更新し、以前の累積値を新しい最大値へ合わせて再尺度化する。しかし行列積そのものが高性能な行列演算器で高速化されるほど、行最大値の還元（rowmax）、行和（rowsum）、指数演算、累積値の再尺度化など、行列積以外のベクトル処理が相対的に重くなる。VFA（Vector Relieved Flash Attention）はこの残った部分に焦点を当てる。

提案手法は、キー・ブロックを軽量な代表ベクトルへ要約してsoftmaxの最大値を先に見積もり、注意得点が大きくなりやすい先頭ブロックとクエリ近傍ブロックを先に処理する。続くブロックでは最大値を固定し、行最大値の還元と累積値の再尺度化を省く。行列積そのものや値との積和は続けるため、VFAは注意ブロックを単純に捨てる疎注意ではない。著者らは、オンライン統計を使って不要なブロックを飛ばすBLASST型の方式と組み合わせたVSA（Vector Relieved Sparse Attention）も提案している。

原著はMMLU、MATH500などのモデル評価と注意統計の解析を示し、精度を大きく落とさずにベクトル演算の負荷を減らせる条件を検証した。要旨ではC16V32という計算器構成を基準にC8V32、C4V32、C4V16で約2倍の高速化を報告する。一方、指数演算能力が将来向上したC4V16で6倍に達するという記述は**将来のアーキテクチャに関する見通し**であり、現在のGPUで確認された6倍高速化ではない。これらの構成は演算器の相対性能を論じる設定であり、任意のLLM推論アプリケーションの総処理能力を2倍にする保証ではない。

## 問題設定：行列積が速くなると残る仕事

通常の縮約内積注意では、クエリQとキーKからS=QKᵀ/√dを求め、行ごとにsoftmaxを適用して重みPを作り、出力O=PVを計算する。長さNの系列について注意得点をそのまま展開するとN×Nの中間行列が必要になる。FlashAttentionはブロックごとの処理とオンラインsoftmaxを組み合わせ、中間の注意行列全体を高帯域メモリへ保持しない。これは大きな帯域削減だが、ブロック間でsoftmaxの分母と分子を統合する処理が必要になる。

ブロックjまでの行最大値をm_j、指数和をl_j、重み付き値の累積をo_jとする。新しい得点ブロックS_jを読むたび、通常方式ではm_j=max(m_{j-1},rowmax(S_j))を求める。最大値が変わると、既存のl_{j-1}とo_{j-1}をexp(m_{j-1}-m_j)倍してから、新ブロックの寄与を加える。これにより大きな正の得点で指数が発散するのを抑え、同時に過去ブロックと新ブロックの尺度を合わせる。

行列積はTensor Coreや同等の行列演算器へ載せやすいが、行最大値を求める還元はスレッド間の通信やベクトル演算が必要になる。行和と再尺度化も同様で、特に低精度の行列積が高速な装置では計算資源の釣合いが崩れる。著者らはC16V32、C8V32、C4V32、C4V16のように行列演算側とベクトル演算側の能力比を変えた設定を比較し、行列積をさらに速くしてもベクトル側が残れば全体の改善が鈍ることを問題にする。

FlashAttention-2は仕事の分割やスレッド束の配置を改善し、FlashAttention-3は非同期転送と行列積の重ね合わせを進めた。FlashAttention-4は指数近似と条件付き再尺度化省略などで非行列積処理を軽くする。本研究はさらに、**そもそも毎ブロック最大値を求め直す必要があるか**を問い、最大値の事前見積りとブロック順序の変更によって還元回数を減らす。既存実装の小さな命令最適化というより、オンラインsoftmaxの更新順序そのものを変える提案である。

## 手法：初期最大値、処理順序、最大値固定の三段階

### 1. キー・ブロック代表から初期最大値を作る

VFAは各キー・ブロックK_jを代表ベクトルk_repr,jへ圧縮する。原著のアルゴリズムでは、各次元で絶対値が最大の要素を選び、その符号を残すsabsmaxを使う。例えばある次元のキー要素が+2、-7、+3なら、その次元の代表値は-7となる。単純な平均では大きな絶対値の寄与が相殺されるため、極端な値を保持する代表を使う狙いがある。ただし、この代表ベクトルは実際のどれか一つのトークンのキーと一致するとは限らない。

クエリ・ブロックQ_iと代表ベクトルの積Q_i k_repr,jᵀを取り、クエリ行ごとに近似得点を作る。複数のキー・ブロックの近似得点から最大値を取ったものをm_initとして、オンラインsoftmaxの初期最大値に設定する。通常方式のm=-∞から始めるのと異なり、あらかじめ実際の得点規模に近い尺度を用意する。キー代表はクエリ・ブロックごとに作り直さず、同じ注意呼出しの中で再利用できる。KVキャッシュが増える復号処理では新しいキー・ブロックだけ代表を追加計算できるという実装上の利点も説明されている。

この処理は、完全なQKᵀブロックの最大値を計算する代わりに、はるかに小さい代表ベクトルとの積を使う。もっとも、各次元で最大絶対値を集めたベクトルとQとの内積が、真の行最大値の厳密な上界になるとは限らない。次元ごとの符号、要素の相関、ブロック内のノルムのばらつきが影響するためである。著者らがブロック内の方向類似度やノルムのばらつきを別途解析しているのは、簡単な代表値だけでは完全な注意統計を再現できないことを認識しているからだ。

### 2. 先頭と近傍のブロックを優先する

通常の注意計算ではキー・ブロックを先頭から順に処理する。VFAはクエリ・ブロックiについて、先頭ブロックj=1と、クエリの位置に対応する近傍ブロックj=iを優先する。その後、残りのブロックを処理する。論文のアルゴリズムでは順序を〈1,i,2,3,…〉と表し、同じiを重複処理しない。これは先頭付近に注意が集まる現象（attention sink）と、近い位置へ注意が集中する局所性に基づく。

優先ブロックでは実際にrowmax(S_ij)を求め、保持中の最大値mを更新する。この段階では通常のオンラインsoftmaxと同様に、必要なら指数尺度を合わせて累積値を更新する。大きな注意得点が現れやすい場所を早めに処理することで、その後の最大値更新が不要になる可能性を高める。全ブロックに同じ注意分布があるとは限らないため、この順序が効くかどうかはモデルの注意統計に依存する。

ここで重要なのは、先頭と近傍だけを残す疎注意ではないことだ。その他のキー・ブロックも後から順に読み、得点と値の積を計算する。したがって計算量削減の主対象は、注意行列積のブロック数ではなく、各ブロックで必要になる行最大値還元と再尺度化である。この区別を曖昧にすると、VFAの貢献を単なるトークン削減手法と誤解してしまう。

### 3. 残りのブロックで最大値を固定する

先頭と近傍の処理が終わった後は、保持中のmを固定する。残りのブロックではS_ij=Q_i K_jᵀを計算し、exp(S_ij-m)を用いて指数和lと値の累積oを更新するが、新たなrowmaxを求めず、古い累積値へexp(m_old-m_new)を掛け直す処理もしない。最終出力はo/lで正規化する。最大値が固定されている限り、過去の累積値と新しいブロックの尺度は最初から一致しているため、更新式を単純な加算にできる。

softmaxは、厳密な実数演算であればすべての得点から同じ定数を引いても比率が変わらない。したがって固定されたmを使うこと自体が直ちに「注意重みの近似」を意味するわけではない。ただし浮動小数点では指数のオーバーフロー、アンダーフロー、丸め誤差があり、固定したmが真の大きな得点を十分に覆えない場合に数値安定性が問題になる。VFAが最大値の初期推定と、重要ブロックでの厳密更新を組み合わせるのはこの危険を減らすためである。

原著は、単に先頭・近傍ブロックだけを使って最大値を決める方法では、中間ブロックに真の最大値が現れる場合に失敗し得ると述べる。そのため、キー代表によるm初期化が必要になる。逆に、m初期化だけでは局所的な極端値を完全に捕捉できない可能性があり、先頭・近傍での実際の最大値更新も意味を持つ。三段階はそれぞれ別の失敗要因を補う設計になっている。

### 4. 疎注意との組合せ：VSA

VSAはVFAを、BLASSTのようなブロック単位の疎注意と組み合わせた方式である。BLASSTはオンライン統計から寄与が小さいと推定されるキー・ブロックを飛ばし、処理すべきブロック数を減らす。VFAは残った各ブロックの統計更新費用を下げる。両者は異なる費用を削るため、原理的には相補的である。著者らは、疎化とベクトル演算削減を別々の軸として扱い、両者を組み合わせることで処理ブロック数とブロック当たり費用の両方を減らせると説明する。

ただし、VSAが「常にVFAより速い」あるいは「精度低下が絶対にない」とは言えない。疎ブロックの判定そのものにも費用がかかり、重要なブロックを除外した場合には出力の変化が生じる。VFA単体でブロックを全部処理する条件と、VSAで一部を除外する条件は、数値的な意味も異なる。速度と精度の比較では、疎化による近似誤差と、最大値固定による浮動小数点上の誤差を分けて評価する必要がある。

## 評価：何を測り、何を示したか

### 比較対象と評価の軸

原著はFlashAttention型の標準的なオンラインsoftmaxを比較基準とし、VFAでどの処理を省けるかを演算子単位で対比する。特に、各ブロックのrowmax、最大値更新、指数和と出力累積の再尺度化を取り除ける点を表1で示している。一方、得点のスケーリング、指数化、行和、値との積和、最終正規化は残る。したがって、全体の演算を消す方式ではなく、特定の還元・再尺度化を取り除く方式である。

評価では、行列演算器とベクトル演算器の能力比が異なるC16V32、C8V32、C4V32、C4V16などの構成を検討している。ここで示される性能差は、対象の演算器比率と指数演算能力に依存する。低精度行列積だけを高速化すると、残ったベクトル演算がボトルネックになり、追加の行列演算器を投入しても処理時間が短縮しにくくなる。VFAの主な狙いは、この非対称な資源配分で処理の釣合いを改善することにある。

| 比較項目 | 標準FlashAttention | VFAの設計 |
|---|---|---|
| ブロックごとの行最大値 | 各ブロックで計算 | 先頭・近傍ブロックのみ厳密更新 |
| 最大値の初期値 | 通常は−∞ | キー代表とクエリの積から推定 |
| ブロック処理順 | 基本的に順次 | 先頭・近傍を優先 |
| 過去の累積値の再尺度化 | 最大値更新時に必要 | 最大値固定後は不要 |
| QKᵀ、重みとVの積 | 実施 | 実施 |
| 注意ブロック除外 | 標準方式では行わない | VFA単体では行わない。VSAで併用 |

### 数値結果と読み方

論文要旨では、C16V32を基準に、C8V32、C4V32、C4V16で**約2倍**の高速化が得られると述べる。これはベクトル側が律速になる条件での結果であり、異なるGPU、バッチ、系列長、精度形式へ無条件に外挿してはいけない。著者らは、指数演算器の能力が将来増強されたC4V16では最大6倍の改善が見込めるとも記すが、**将来のハードウェア能力を仮定した推計**である。実測値と将来予測を同じ「達成速度」として並べないことが重要である。

精度面では、MMLUとMATH500などのモデル評価と、注意得点の最大値がどのブロックに現れるかの解析を組み合わせている。原著はVFA/VSAの設計でモデル性能を損なわない条件を報告するが、すべての入力・モデル・精度形式で厳密にビット一致するという保証は提示していない。とりわけVSAは疎ブロック除外を含むため、計算対象そのものを変える可能性がある。したがって「精度を維持した」という実験報告は、測定された課題と構成に限定して読む。

### なぜ初期化と順序が必要か

著者らは先頭と近傍ブロックの注意得点が高くなりやすい傾向を検証し、これらを早く処理すると行最大値が安定しやすいと示す。ただし最大値が必ず先頭または近傍にあるわけではない。中間ブロックに最大値が現れる例を分析し、初期化なしで最大値を固定すると不適切な尺度になる危険を説明する。これは、順序変更だけで十分という仮説を否定する根拠になる。

また、Q/Kの各ブロックを単純な平均や代表値で要約すれば最大値が分かるという仮説も検討している。実際にはブロック内の方向のばらつきとノルム差が大きく、粗い要約が真の最大値を正確に捉えない場合がある。そこでVFAはキー代表からの近似最大値をあくまで初期尺度として用い、先頭・近傍では厳密なrowmaxを実行する。初期化と部分的な厳密更新の併用が、計算削減と安定性の折衷になっている。

## 既存研究との比較と実装上の意味

FlashAttention-2/3/4は、計算ブロックの配置、非同期化、指数演算などを改良してきた。VFAはそれらを否定するものではなく、特に「行最大値更新の回数を減らす」という追加の設計余地を示す。FlashAttention-4の条件付き再尺度化省略と異なり、VFAでは最大値を固定する段階に入れば再尺度化の条件判定そのものを不要にできる。これはGPUカーネルの制御フローを単純化し、ベクトル演算器の負荷を減らす方向である。

一方、VFAは既存の高速な行列積カーネルをそのまま使えば必ず得になるという単純な後処理ではない。キー代表の事前計算、ブロック順序の変更、最大値固定の実装が必要で、クエリ長・キー長・マスク形状によって追加費用が変わる。特に短い系列では代表値の事前計算が相対的に重くなり、ベクトル律速ではなく行列積律速の装置では削減できる時間が少ない可能性がある。

疎注意と組み合わせる場合には、ブロックを除外する判定が利用するオンライン統計と、VFAが固定する最大値の関係を慎重に設計する必要がある。BLASST型の除外条件が、VFAの近似初期値に対しても妥当かを確認しなければ、速度改善のために重要ブロックを飛ばす危険がある。原著は組合せ可能性を示しているが、あらゆる疎化アルゴリズムへの一般的な安全性証明を与えたわけではない。

## 限界・再現上の注意

第一に、VFAの効果は**ベクトル演算が律速となる条件**に強く依存する。行列積がまだ支配的なGPUや小規模な入力では、行最大値の還元を削減しても全体の処理時間への影響は小さい。演算器比率を変えた構成で約2倍という結果を、Windows上のRTX 4070 SUPERで動く任意のQwen系モデルの速度改善と解釈してはならない。実機GPU、カーネル実装、精度形式、系列長、バッチを揃えた追試が必要である。

第二に、最大値を固定したまま後続ブロックを処理するため、真の最大得点が後から現れる入力では数値安定性が問題になり得る。実数演算のsoftmaxは共通定数の平行移動に不変だが、有限精度の指数関数は不変ではない。キー代表の近似が十分でない場合の誤差、指数の飽和、累積の丸め誤差は別途測る必要がある。著者らが中間ブロックの最大値位置を解析していること自体が、この危険を完全には無視できないことを示す。

第三に、注意得点の先頭・近傍への偏りは経験則である。モデルの層、注意頭、位置符号化、長文の検索パターンによって注意分布は変わる。特定のトークンへ遠距離から強い注意が集まるタスクや、通常と異なるマスク構成では、優先ブロックが真の最大値を早期に捕捉するとは限らない。注意統計の分布が学習時や評価時から変わった場合の頑健性は、個別に確認すべきである。

第四に、VFA単体は注意ブロック数を削減しない。QKᵀとPVの主要な行列積は残るため、計算量のオーダーが線形になるわけではない。長文の計算量そのものを減らしたい場合には、別の疎注意・近似注意との併用が必要になる。VSAでは疎化の誤差が加わるため、VFA単体の精度結果をそのまま流用できない。

第五に、論文要旨にある将来構成の6倍は、指数演算能力の拡張を仮定した性能見通しである。これは既存GPUで達成済みの結果ではなく、実測の約2倍と区別する必要がある。また、原著に公式公開コードURLが確認できないため、コードの入手性や既存推論エンジンへの統合状況は未確認である。

## 実務上の示唆

ローカルLLM推論で問題になるのは、重みのメモリ容量、KVキャッシュ容量、GPUの演算器利用率、CPUとの転送、バッチなど複数の資源である。VFAはそのうち**注意カーネル内の非行列積処理**を改善する技術であり、重みの量子化やCPUオフロードを直接置き換えるものではない。モデル重みがVRAMに載らない問題には効かず、KVキャッシュの容量を直接4分の1にする技術でもない。KV容量削減を狙うR-CLAなどとは目的が異なる。

今後の推論エンジンでVFA型の手法が採用された場合、注目すべき指標は「行列積性能がどれだけ高いか」だけでなく、行最大値還元と指数和更新が全体のどれだけを占めるかである。実装の比較では、同一モデル・同一精度・同一GPU・同一系列長で、注意カーネル単体の遅延、初回トークン遅延、復号トークン/秒、モデル精度を分けて測る必要がある。ベクトル律速が解消されても、次の律速がメモリ転送や行列積に移るため、理論上の削減率がそのままアプリケーション全体へ現れるとは限らない。
