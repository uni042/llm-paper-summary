# AlignQuant: Tile-Aligned Mixed-Precision Quantization for Efficient LLM Generation

> 重みの二次元タイルを精度配分・詰め込み保存・GPU実行の共通単位とし、プリフィルとデコード両方の損失感度で各タイルの4ビット／8ビットを決めて、1つの詰め込みモデルを段階専用カーネルで直接実行する混合精度量子化。

## 概要

大規模言語モデルの推論は、重みの保存量、メモリ帯域、計算量の三つに縛られる。学習後量子化は重みを低ビットで表してこの三つをまとめて下げるが、ビットを落とすほど量子化誤差が増える。そこで混合精度量子化は、感度の高い部分だけ8ビットに残し、鈍い部分を4ビットへ落として、モデル全体の保存予算の中で品質を守る。問題は精度の境界の置き方である。チャネル単位や出力特徴単位で精度を共有すると実行は規則的になるが、同じチャネル内でも感度が場所によって違う重みまで同じビット幅へ縛られる。逆に細かく割り当てると、異なるビット幅の重みをどう詰め込み、どう読み出し、どう計算形式へ変換するかという配備の手間が増え、圧縮したのに速くならない事態が起きる。論文はこれを精度境界ミスマッチと呼ぶ。

本論文の答えは、精度を決める単位、保存する単位、実行する単位を最初から同じ二次元タイルにそろえることである。重み行列を既定で64×64のタイルへ分け、各タイルに4ビットか8ビットかを1つ割り当てる。配分はオフラインの較正で決める。各タイルについて8ビット候補を4ビット候補へ替えたときの射影出力の変化を作り、それを言語モデルの損失勾配で重み付けしたスコアで測る。プリフィル（入力処理）とデコード（逐次生成）では活性値も勾配も違うため、両段階で別々にスコアを測り、段階ごとの総和で正規化して大きい方をそのタイルの優先度とする。どちらか一方の段階で重要なタイルは8ビットに残る。保存ではタイルごとに選んだ表現だけを詰め込み、実行時は4ビット重みをチップ上で8ビット整数へ広げて、8ビット活性値との共通の整数演算で処理する。代表結果として、Llama-3.2-3BではA100上でBF16比のスループットが毎秒58.18トークンから132.28トークンへ2.27倍になり、出力トークンあたり時間は17.19ミリ秒から7.54ミリ秒へ縮み、常駐メモリは5.99GiBから2.72GiBへ減った。同時にWikiText-2パープレキシティ（低いほど良い）はBF16の12.49に対し12.61と近傍を保った。4モデル・3種類のGPUを通じた最大の生成高速化はBF16比2.50倍である。

## 問題設定

量子化で重みを低ビット化すると、保存バイト数と読み出し量が減り、デコードのように重み読み出しが支配的な処理ではそのまま速くなる可能性がある。ただし量子化誤差は一様ではない。外れ値を含む領域や、損失へ強く効く出力座標へつながる領域を粗くすると品質が大きく落ちる。スケールを外れ値へ合わせると通常値の分解能が失われるため、回転などの直交変換で外れ値を分散させる工夫も併用される。

既存の混合精度方式は、この感度の偏りを精度配分で吸収しようとしてきた。層単位やチャネル単位の配分は規則的で実装しやすいが、共有単位の中の感度のばらつきを捨てている。本論文の観測では、クエリ射影の重みだけを見ても感度は行列内と層の深さ方向の両方で大きく偏り、高感度タイルは層と射影の種類ごとに不均一に集中する。逆にグループ単位やブロック単位の細かい配分は、異種ビット幅の詰め込み、読み出し時の変換、専用実行経路といった配備費用を抱える。さらにプリフィルとデコードは同じ重みを使うのに処理の形が違う。プリフィルは多数の入力行をまとめて処理し重みを使い回せるが、デコードは1行ずつの行列ベクトル積で並列度を別に確保する必要がある。片方の段階だけを見て精度を決めると、もう片方で重要なタイルを落としかねない。つまり課題は、感度の局所性を残したまま、保存と実行がそのまま受け取れる形で精度を決めることである。

## 手法のあらまし

処理はオフラインの較正と、オンラインの実行の二つに分かれる。較正ではまず、各タイルについてタイル境界へそろえた直交変換をかけた上で、対称量子化による4ビット候補と8ビット候補を作る。次に較正データでモデルを動かし、プリフィルとデコードの両方について、各タイルの候補差が射影出力へ与える変化と、その出力座標に対する損失勾配を集める。変化と勾配からタイルごとのスコアを作り、段階正規化した両スコアの大きい方を優先度として、モデル全体のタイルを順位付けする。目標とする4ビット比率（既定は60パーセント）に達するまで、スコアの低いタイルから4ビットへ割り当て、残りを8ビットに残す。最後に、選ばれた整数値とタイルごとの復元スケールだけを詰め込んだモデルを1つ作る。実行ではこの詰め込みモデルをプリフィルとデコードで共有する。入力側変換をかけて活性値を8ビットへ量子化し、プリフィルはテンソルコアの整数行列積で、デコードは4要素ずつのドット積命令で処理する。4ビット重みはメモリ上では詰め込みのまま読み、チップ上で8ビットへ広げるため、両精度が同じ整数演算へ合流する。

## 手法

### 1. タイル整列した候補構築 — 変換の境界を精度の境界へ合わせる

入力は線形射影の重み行列であり、行が出力特徴、列が入力特徴に対応する。提案法は全射影の重みを等しい大きさの二次元タイルへ分割し、タイルを層・射影・行列内位置で識別する。量子化対象はデコーダのクエリ、キー、バリュー、注意出力の各射影と、フィードフォワードのゲート、アップ、ダウンの各射影である。候補構築では入力側と出力側へブロック対角の直交変換をかける。変換は外れ値をタイル内に分散させて量子化誤差を減らすためのもので、変換後の重みに逆変換を組み合わせることで浮動小数点の射影そのものは保たれる。ここで重要なのは、変換のブロック境界と量子化グループの境界をタイル境界へそろえることである。境界がずれると、変換で混ざった重みが別々の精度領域へまたがり、タイル単位の選択が成り立たなくなる。各タイルはゼロ点を0とする対称量子化で、4ビット候補と8ビット候補の両方を持ち、それぞれタイル固有のスケールで復元した値を同じ座標系で比べられるようにする。活性値も較正と推論で同じ8ビット量子化器を使うため、候補の比較は配備時の入力条件を反映する。追加費用はタイルごとのスケール保持であり、タイルを小さくするほどスケールと精度ラベルの保存量が増える。付録の見積もりでは、その寄与はタイル面積に反比例し、64×64では重みあたり約0.008ビット程度に収まる。

### 2. 損失重み付きスコア — タイルを丸ごと替えたときの出力変化を測る

スコア付けが観測するのは、タイルの8ビット候補を4ビット候補へ置き換えたときに生じる射影出力の変化である。具体的には、較正データから得た8ビット活性値の該当スライスに、4ビット候補と8ビット候補の差を掛けて出力変化の行列を作る。タイル内の重み誤差は入力を通じて足し合わされるため、重み1個ずつの顕著さを足す方式と違い、誤差同士の打ち消しや増幅まで含めてタイル全体の置換効果を測れる。次にこの出力変化を、言語モデル損失の勾配の二乗で要素ごとに重み付けし、二乗ノルムを取る。これは対角の経験的フィッシャー情報による重み付けで、下流の計算を通じて損失へ効く出力座標ほど大きく数える。勾配はトークン平均化された損失から得るため、有効な予測トークン数を掛け戻して合計損失の勾配へ直してから使う。スコアが大きいタイルほど、その段階では8ビットに残す優先度が高い。失敗条件として、このスコアは較正データ上で測った局所的な置換効果であり、複数タイルを同時に落としたときの相互作用までは直接測っていない。最終品質は全タイルを割り当てた後の組み立て済みモデルで別途評価される。

### 3. プリフィルとデコードの共同配分 — どちらかで重要なタイルを守る

同じ重みでも、プリフィルとデコードでは活性値の分布も損失勾配も違う。提案法は段階ごとにスコアを集計し、各タイルのスコアをその段階のモデル全体のスコア総和で割って相対重要度へ直す。正規化により、段階間でスコアの絶対的な大きさが違っても比べられる。その上で両段階の相対スコアのうち大きい方をタイルの最終スコアとする。和や平均ではなく最大を取るため、片方の段階でだけ突出して重要なタイルが、もう片方の低さに薄められずに8ビットへ残る。配分はモデル全体で一括して行う。高感度タイルの分布が層や射影ごとに偏っているため、層ごとや射影ごとに予算を区切ると、必要な場所へ8ビットを寄せられない。すべてのタイルが同じ重み数を持つので、8ビットから4ビットへの置換1件あたりの保存削減量は全タイルで等しい。したがって固定予算の下では、スコアの低い順に目標比率まで4ビットへ割り当てる単純な順位付けが、推定影響の合計を最小にする選択になる。既定ではタイルの60パーセントを4ビットとし、名目上の重み保存量は重みあたり8ビットから5.6ビットへ下がる。

### 4. 詰め込み表現 — 選んだ表現だけを1つ保存する

保存では、各タイルについて選ばれた精度の整数値と、その復元スケール（32ビット浮動小数点）だけを保持する。落とした側の候補は保存しないため、実行時に精度を選び直す方式と違って重みの二重保持がない。4ビット値は1バイトに2個、8ビット値は1バイトに1個を詰める。選ばれた4ビットタイルと8ビットタイルはそれぞれ連続した別バッファへ置き、タイルごとの1ビットの精度ラベルと、出力タイル行ごとの開始位置を示す行オフセットで、論理タイル座標から物理位置を引けるようにする。この引き当て規則があるため、実行側はタイル座標だけから該当する整数値とスケールを特定できる。詰め込み後の実測保存量は、スケールと索引情報を含めても名目式に近く、既定設定では重みあたり5.61ビットである。トレードオフは索引情報の分だけ純粋な整数値より保存量が増えることと、タイルを細かくするほどラベルとスケールの割合が増えることである。

### 5. 段階専用の直接実行 — 詰め込みのまま読み、チップ上で広げる

実行時はまず入力へ入力側変換をかけ、較正と同じ手順で活性値を8ビットへ量子化する。重み側は、4ビット値を詰め込みのままGPUメモリから読み、チップ上で符号付き8ビット整数へ広げる。8ビット重みはそのまま整数オペランドになるため、両精度は同じ整数演算へ合流し、タイルごとの積は32ビット整数で蓄積した後、活性値と重みのスケールで実数へ戻して32ビット浮動小数点で入力タイル方向へ合算する。最後に出力側変換で射影出力を復元する。プリフィルは多数の活性値行があるため、テンソルコアの整数行列積で重みタイルを行グループ間で使い回す。短いプリフィルではチップ上でオペランドを準備し、両精度が混ざる長いプリフィルでは射影の呼び出しごとに一度だけ一時的な8ビットバッファへ展開してから使い回し、変換費用を行あたりで薄める。デコードは活性値が1行しかなく行列ベクトル積になるため、詰め込み重みを直接読み、4要素の8ビット積を32ビットへ蓄積する命令で処理し、出力特徴方向と入力列グループ方向の両方へ仕事を分けて並列度を確保する。さらに、同じ入力と変換を共有するクエリ・キー・バリュー射影やゲート・アップ射影は、入力の変換と量子化を1回だけ行って使い回す。実行制御の工夫として、デコードの分割方法の適応と、繰り返し計算をまとめて投入する仕組みも併用される。段階が切り替わっても精度マップと詰め込みモデルは同じものを使い、重みの再詰め込みは起きない。

## 評価

### まず見るところ

- **結論:** タイル単位の配分は、同率の4ビット予算を持つ構造化・ランダムな配置より品質が良く、詰め込みと段階専用実行により、その品質を保ったままBF16比で最大2.50倍の生成高速化と約半分の常駐メモリへ変換できた。
- **速度・効率:** 主結果は実機のエンドツーエンド測定である。Llama-3.2-3BのA100ではスループットがBF16の毎秒58.18トークンから132.28トークンへ、出力トークンあたり時間は17.19ミリ秒から7.54ミリ秒へ改善した。ただし最初のトークンまでの時間は17.47ミリ秒から19.67ミリ秒へやや悪化しており、利得は生成段階に集中する。
- **品質:** 近似手法である。一般課題では量子化方式の中で最良級のパープレキシティと正解率を保ち、長文脈でも64KでBF16へ近いスコアを残す設定が多い。
- **メモリ・入出力:** 常駐メモリはLlama-3.2-3Bで5.99GiBから2.72GiBへ減る。均一4ビットの参照（2.08GiB）よりは重いが、これは8ビットに残したタイルの対価である。
- **評価の強さ／注意点:** 4モデル、3種類のGPU、文脈64Kまでと範囲は広い。一方で生成の主スイープはバッチ1から8が中心で、大規模サービング負荷や他社アクセラレータでの検証はない。

**数値の読み方。** 高速化の主因は、デコードで毎トークン読み出す重みが詰め込みにより減り、かつ変換をチップ上に閉じて整数演算へ直接つないだことにある。出力長が長いほどデコードの比重が増えるため、BF16比の利得は生成が長い条件で大きくなる。逆にプリフィル側は一時バッファへの展開費用を含むため、最初のトークンまでの時間ではBF16へ勝っていない。品質面では、比較対象のGPTQやAWQが一部の課題で大きく崩れるのに対し、提案法の崩れが小さい点が目立つ。ただしこれは評価条件の違いではなく、同じ評価器・同じ課題設定での比較である。

## 既存研究との差

GPTQやAWQは固定ビット幅での表現そのものを改善する一様量子化であり、感度の偏りは重みの値の作り方で吸収する。チャネル単位や出力特徴単位の混合精度（チャネル単位混合精度、MixLLMなど）は配分を導入したが、共有単位が粗く、単位内の感度差を捨てていた。グループ単位やブロック単位の細粒度方式（SliM-LLM、FGMP、SFMP、ScaleBITSなど）は局所配分を進めたが、再順序付けや混合形式、専用実行支援など、配分と保存と実行を別々に橋渡しする仕組みを要した。段階適応型の方式はプリフィルとデコードで精度を切り替える代わりに、複数の重み表現を保持する費用を払う。本論文の差分は三つある。第一に、配分の単位をGPUの二次元タイルへそろえ、変換・保存・実行まで同じ分割で貫くことで、細かさと規則性を両立させた。第二に、スコアを重み単位の顕著さの集計ではなく、タイル全体を置換したときの射影出力変化を損失勾配で重み付けして作り、誤差の相互作用を含めた。第三に、プリフィルとデコードの証拠を段階正規化の最大で統合し、複数表現を持たずに両段階へ配慮した単一の詰め込みモデルを作った。

## 限界・実装状況

対象モデルは3Bから14Bの4モデルに限られ、それより大きいモデルや専門家混合モデルでの配分挙動は未評価である。精度は4ビットと8ビットの二値だけであり、2ビット級や分数ビットへの拡張は扱っていない。活性値は一様8ビットで固定されており、活性値側の混合精度は設計上の検討にとどまる。較正は文書要約ペアという単一の較正データ構成で検証され、較正分布と大きく違うワークロードでの配分の劣化は、データ量と種別の感度実験の範囲でしか確認されていない。実行は特定ベンダーのGPU向け整数演算（テンソルコアとドット積命令）を前提とし、サービング基盤への統合ではなく独自ランタイムでの測定である。最初のトークンまでの時間はBF16より遅く、短い生成では利得が小さい。公式実装は公開されているが、上流の推論基盤へ統合済みかは論文に記載がない。

## 一般的な実装上の含意

量子化の設計では、精度を決める単位を、保存の単位とカーネルが処理する単位へ最初からそろえることが重要である。配分だけ細かくしても、境界が実行単位を横切れば変換費用が利得を食う。感度の測り方については、重み単体の顕著さより、実際に置換する塊全体が出力へ与える変化を損失側の重みで評価する方が、配置の当たり外れを減らせる。また、処理段階ごとに重みの重要度が違う系では、段階別の証拠を正規化して最大を取る単純な統合でも、複数モデルを保持せずに両段階を守れる。予算対効果の面では、4ビット比率を変えてもスループットがほぼ動かず保存量だけが下がった観測が示すように、整数演算へ統一した後は精度配分は速度ではなく保存量と品質の調整つまみになる。
