# Continuous Semantic Caching：連続クエリ空間でのLLM応答キャッシュ最適化

## 概要

大規模言語モデル（LLM）の推論費用を減らす方法の一つは、過去の問い合わせへの応答を保存し、意味的に近い新しい問い合わせへ再利用する意味的キャッシュ（semantic caching）である。正確に同じ文字列の問い合わせだけを一致させるキャッシュより広い再利用が期待できるが、異なる問い合わせへ同じ応答を返すと、意味の不一致や回答品質の低下が起こり得る。キャッシュの容量は有限であり、どの応答を保存すれば推論費用と不一致費用の合計を小さくできるかが問題になる。

従来の理論的なキャッシュ最適化は、候補となる問い合わせが既知の有限集合に属すると仮定することが多かった。実際の自然言語問い合わせは多様で、同じ内容を異なる表現で尋ねるため、埋め込み（embedding）空間の連続的な位置として扱う方が自然である。本論文は、未知の到着分布と未知のLLM推論費用を持つ連続クエリ空間で、意味的応答キャッシュをどう選び、どう更新するかを定式化する。

提案の中心は、近い問い合わせを代表点へまとめるε-netによる離散化と、観測された一部の推論費用から周辺の費用を推定するカーネルリッジ回帰（kernel ridge regression; KRR）である。到着履歴を事前に使うオフライン方式CUCB-SC-Contと、未知の問い合わせが到着するたびに代表点を増やし、キャッシュ入替費用も考慮するオンライン方式CLCB-SC-LS-Contを示す。合成クエリの実験では、オフラインの最適性差が既存方式より最大73.32%小さく、オンラインの平均後悔（regret）は最大72.41%小さくなった。ただしこれらは正規化された代理コストを使った実験結果であり、実際のLLMサーバのトークン毎秒や回答品質を直接測った値ではない。

## 問題設定：連続的な問い合わせを何に基づいて保存するか

各問い合わせxは、文章を埋め込みモデルで変換した連続空間X上の点として表す。問い合わせの到着確率密度f(x)と、その問い合わせをLLMへ渡したときの期待費用c(x)は未知である。費用には推論時間、計算資源、金額などを対応させられるが、論文の理論では正規化されたスカラー値として扱う。キャッシュMには高々k件の問い合わせと対応する応答を保存する。新しい問い合わせxが来ると、キャッシュ中で最も近い問い合わせuを選び、その応答を再利用するか、LLMへxを送って新しく生成するかを決める。

意味的に似ているだけで同一でない問い合わせへ応答を流用する場合、不一致費用φ(d(x,u))を課す。dは埋め込み空間の距離であり、φは距離とともに増える非減少関数で、論文では最大1に制限する。例えばφ(d)=min(ζd,1)のように距離が大きいほど再利用を不利にする。LLMへ新規に問い合わせる場合の費用はc(x)である。したがって現在のキャッシュに対する1要求の理想的な費用は、LLM実行費用と最も近いキャッシュ応答の不一致費用の小さい方になる。

キャッシュMの期待損失は、問い合わせ分布fにわたってmin{c(x),φ(d(x,M))}を積分したものである。キャッシュの選択問題は、|M|≤kという制約下でこの期待損失を最小化することだが、候補点が無限にあるため、有限集合での組合せ最適化より難しい。論文はこの問題がNP困難であることを示し、厳密な最適解ではなく、近似保証のあるキャッシュ選択を目指す。

もう一つの難しさは観測の偏りである。キャッシュを使って応答を返すと、LLMを実行していないため、その問い合わせを実際にLLMへ渡したときの費用c(x)は観測できない。新規実行した場合だけノイズ付きの費用が得られる。したがって、単純な要求頻度だけでは、キャッシュに入れる価値の高い高コスト要求を識別できない。未知の要求費用を学習する探索と、現在の知識に基づいて費用を節約する利用の両立が必要になる。

## 手法

### 1. ε-netによる連続空間の有限化

ε-netは、連続空間Xの任意の点から距離ε以内に少なくとも一つの代表点が存在するような有限点集合Sである。各問い合わせを最も近い代表点へ割り当てると、空間はVoronoi領域へ分割される。領域ごとの到着確率を重みw_iとして持てば、連続空間上の積分を、代表点の有限個の重み付き和で近似できる。キャッシュには各領域から高々一つの代表的な問い合わせを選ぶ形で候補を制限する。

εを小さくすると元の連続空間を細かく近似できるが、代表点の数が増え、到着頻度や推論費用を推定するための観測が各領域に薄く分散する。εを大きくすると候補数と計算量は減る一方、意味的に異なる問い合わせを同じ代表点へ押し込むため、不一致費用や離散化誤差が大きくなる。論文は、期待損失関数が距離についてLipschitz連続である条件下で、離散化による誤差がL_g ε以下になることを示す。この保証は「εが小さければ回答が必ず正しい」という保証ではなく、論文で定義した数値的損失の近似保証である。

### 2. 完全情報下の連続逆貪欲法

到着分布と推論費用が既知という理想的な設定では、ε-netの代表点集合を最初のキャッシュ候補とし、取り除いたときの損失増分が最も小さい点を順に削除する逆貪欲法（reverse greedy）を使う。残りが容量k件になるまで繰り返す。損失関数の集合に関する構造を利用し、離散化した問題での近似率と、元の連続問題に対する離散化誤差を組み合わせて性能を評価する。

この方法は、すべての候補を追加する通常の貪欲法と違い、最初に候補全体を保持した状態から重要度の低いものを取り除く。離散化した集合上での近似保証は、元の無限空間の最適解そのものに対する厳密一致ではない。実用的なアルゴリズムの性能を議論するときは、近似オラクル（oracle）の最適性と、費用推定の誤差を分ける必要がある。

### 3. オフラインCUCB-SC-Cont：未知費用を近傍から推定する

過去の問い合わせ履歴が利用できる場合、データを二つに分ける。一方で代表点集合Sを作り、他方で各Voronoi領域の到着確率を推定する。これにより、代表点を決めた同じ標本だけで頻度を評価する偏りを避ける。費用c(x)については、LLMを実際に実行した問い合わせだけに観測値が存在するため、全問い合わせの単純な標本平均は使えない。そこでKRRで連続的な費用関数を学習し、近い問い合わせの観測を新しい代表点へ一般化する。

KRRは、観測済み問い合わせ同士の類似度からGram行列を作り、正則化項を加えた逆行列で未知点の費用を推定する。同時に推定の不確実性を表す幅を計算できる。オフライン方式は推定費用に信頼幅を加えた保守的な上界を作り、到着確率の推定と組み合わせて逆貪欲法を実行する。未知の費用を過小評価して高価な問い合わせをキャッシュ対象から外す危険を抑える設計である。

論文の理論は、到着確率の推定誤差、ε-netの離散化誤差、KRRの費用推定誤差を分離する。有限個の問い合わせだけを扱う従来方式にはない、埋め込み空間の次元、局所的な観測密度、カーネルの滑らかさに依存する項が加わる。標本が増えるほどεを小さくできるが、高次元の埋め込みでは必要な代表点数が急増し得る。この次元依存は、実用上の代表点管理費用にも直結する。

### 4. オンラインCLCB-SC-LS-Cont：代表点とキャッシュを同時に更新する

オンライン方式では、あらかじめ全問い合わせを観測できない。新しい問い合わせが既存の代表点からεより離れていれば、新しい代表点としてSに追加する。既存の代表点に近ければ、その領域の到着回数を更新する。これにより、未知の話題が流入したときにキャッシュ候補を増やせる。代表点集合は固定されず、問い合わせの分布に合わせて動的に成長する。

キャッシュを毎回入れ替えると、まだ保存していない問い合わせの応答を新しく生成する費用がかかる。そこで、領域ごとの観測数と全体の到着数に基づく段階的なしきい値を設定し、必要なときだけキャッシュ選択をやり直す。新しい代表点ができたときも更新候補になるが、既存領域内での細かな変動では毎回切り替えない。更新時にはKRRによる費用の下側信頼限界を使い、観測が少ない領域を必要に応じて探索しながら、新しいキャッシュ集合を選ぶ。

オフラインの保守的な費用上界と、オンラインの探索を促す費用下界は目的が異なる。前者は不確実性の下でのキャッシュ選択の過小評価を抑え、後者は未知の費用を持つ領域を探索して将来の意思決定を改善する。オンラインの目的関数には、キャッシュのサービス費用・不一致費用だけでなく、キャッシュへ新しい応答を入れるための追加推論費用も含める。

### 5. 理論保証と必要な仮定

論文は、オンライン方式の累積後悔（regret）について、一定の滑らかさ、カーネル関数に対する費用関数の表現可能性、ノイズの集中、問い合わせが高密度の意味領域に集中することなどの条件下で、時間Tに対しておおむね平方根程度に増える劣線形の上界を示す。後悔が劣線形であるとは、長期平均で最良の固定キャッシュとの差が小さくなるという意味であり、個々の問い合わせで常に最適な応答を返す保証ではない。

理論上の後悔は、費用関数の推定、到着確率の推定、離散化、キャッシュ入替の四種類に分けられる。代表点数の上限は埋め込み空間の幾何学的な被覆数に依存し、高次元空間へ均等に問い合わせが広がる最悪の場合は代表点が爆発し得る。論文は、実際の問い合わせは人気のある話題の近傍に集中するという仮定を導入し、実効的な代表点数が小さくなる条件で保証を得る。この仮定が崩れる運用環境では、同じ理論上界をそのまま適用できない。

## 評価

### 1. 評価データと代理コストの定義

合成データは50種類の元の自然言語問い合わせを用意し、埋め込みへガウス雑音を加えて、同じ意味の近傍に異なる点が連続的に現れる状況を作る。実データはNatural Questionsから2,500件、TriviaQAから2,500件、合計5,000件の問い合わせを使う。384次元の文埋め込みを正規化し、ユークリッド距離をさらに0〜1へ正規化して類似度の代理指標とする。実データの到着は二つのデータセットを交互に偏らせるバースト型とし、内部では裾の重い人気度分布を使う。

重要な点として、**推論費用は実際のLLMのGPU時間ではない**。GPT-2のトークナイザで測った問い合わせのトークン長を最小最大正規化して、期待推論費用c(x)の代理とする。したがって、実際の出力長、モデルサイズ、バッチ構成、GPU占有率、ネットワーク費用、応答品質の差はこのコストへ直接含まれない。キャッシュ再利用時の不一致費用も埋め込み距離の関数であり、回答が事実として正しいかを人手やモデルで判定していない。

| 設定 | 合成データ | 実データ |
|---|---|---|
| 問い合わせ集合 | 50種の元問い合わせ＋埋め込み雑音 | NQ 2,500件＋TriviaQA 2,500件 |
| 埋め込み | 384次元 | 384次元 |
| 到着パターン | 元問い合わせを選び、近傍へ雑音を加える | 二つの集合のバースト、裾の重い人気度 |
| コスト | GPT-2トークン長の正規化値 | 同左 |
| キャッシュの正しさ | 距離由来の不一致費用 | 同左 |

### 2. オフライン：εと履歴長による差

オフラインCUCB-SC-Contは合成データで評価する。キャッシュ容量はk=5とし、20種類の乱数シードで平均を取る。εの影響を調べる実験では履歴長を1,000に固定し、履歴長の影響を調べる実験ではε=0.4に固定する。比較対象は有限クエリ向けCUCB-SC、単純Greedy、Epsilon-Greedy、最頻使用方式LFUなどである。

εが小〜中程度なら提案方式の最適性差は比較方式より小さくなるが、εを大きくし過ぎると代表点が粗くなり、離散化誤差が増えて悪化する。ε=0.4の比較では、既存CUCB-SCに対して最適性差が52.95%小さい。履歴長が100の条件では、CUCB-SCに対して73.32%小さい。これらは特定の設定における**最適性差の相対改善率**であり、LLM推論時間が73.32%短縮したという結果ではない。

履歴が短いときにKRRによる近傍への一般化が効き、同じ問い合わせが何度も現れるまで待つ必要がない。履歴が長くなると有限クエリ向け方式も推定精度が改善して競争力を持つようになるため、連続空間の一般化が常に同じ大きさの利益をもたらすわけではない。εを選ぶこと自体も最適化問題であり、固定値をどのデータ分布へも適用できるとは限らない。

### 3. オンライン：平均後悔と計算時間の交換条件

合成データのオンライン評価では、CLCB-SC-LS-Contの最終平均後悔は0.0083となり、最も強い比較方式CLCB-SC-LSより72.41%小さい。ただしアルゴリズムの実行時間は比較方式より47.8%増える。推論費用を節約するキャッシュ選択が改善しても、KRRや代表点管理の計算が増えるという交換条件を示している。

Natural Questions＋TriviaQAの実データでは、最終平均後悔は0.0061で、Greedyに対して63.27%小さい。またCLCB-SC-LSとの比較では43.14%小さい。論文は両方式のアルゴリズム実行時間がこの設定で約250秒と近いと報告する。ただしここでの約250秒は、実際のユーザー1要求の応答遅延ではなく、実験でキャッシュ選択アルゴリズムを走らせる処理時間に対応する。負荷の大きさや実装言語、実際のLLMサービング構成が異なれば同じ時間にはならない。

| オンライン条件 | 提案方式の最終平均後悔 | 比較と改善 | 追加の注意 |
|---|---:|---|---|
| 合成問い合わせ | 0.0083 | CLCB-SC-LS比72.41%減 | アルゴリズム実行時間47.8%増 |
| NQ＋TriviaQA | 0.0061 | Greedy比63.27%減 | バースト型の実データ到着 |
| NQ＋TriviaQA | 同上 | CLCB-SC-LS比43.14%減 | 比較方式と実行時間は約250秒で近い |

### 4. 何を測っていないか

本論文の数値は、要求の意味的な近さと代理推論費用から定義した数学的損失・後悔の比較である。実LLMの推論エンジンへ接続して、キャッシュヒット率、トークン毎秒、TTFT、GPUメモリ占有、GPU時間、実際の課金額を同時に測ったものではない。応答の意味的な不一致を距離の関数で代用しているため、わずかな語句の差が事実関係や安全性を大きく変える問い合わせに、同じキャッシュ応答を返してよいかは評価されていない。

理論上の最適性差は近似オラクルを基準とするため、全ての可能なキャッシュ候補を厳密に列挙した絶対最適解との直接比較ではない。また、連続空間の次元が高いとε-netの候補数が急増し、KRRのGram行列の計算費用も大きくなり得る。実際の大規模サービスでは、代表点の近傍探索、カーネル近似、候補集合の分割、古いデータの忘却などの追加工夫が必要になる。

## 限界・実装状況

最大の限界は、キャッシュの品質を意味距離に基づく代理損失で評価していることである。例えば医療、金融、法務、個人情報を含む問い合わせでは、意味的に近くても正解が異なることがある。距離だけから安全な再利用可否を決めるのは不十分であり、ユーザー固有情報、時刻依存情報、権限、回答の新鮮さなどの制約を別途実装する必要がある。論文はこれらの実運用条件に対する安全性保証を示していない。

次に、費用の観測はLLMを実際に呼んだ場合だけ得られるため、キャッシュ利用が多い領域ほど費用推定が偏る可能性がある。KRRの不確実性評価と探索で対応するが、費用関数がカーネルの仮定から大きく外れたり、問い合わせ分布が急変したりすると保証の前提が崩れる。埋め込み空間の幾何学的な被覆数は次元に強く依存し、実データで話題の集まりが十分に密であるという仮定が重要になる。

本論文は応答キャッシュの選択アルゴリズムを研究するものであり、Transformer内部のKVキャッシュ圧縮、注意カーネル、GPU間のKV転送を高速化するものではない。KVキャッシュは各要求の推論途中の内部状態を保持するのに対し、ここでのキャッシュは完了済み問い合わせへの最終応答を保存する。対象資源と再利用単位が異なるため、既存のKVキャッシュ研究と同じ指標で圧縮率を比較するのは不適切である。

公開の一次論文にはアルゴリズムの疑似コードと理論・実験の記述があるが、独立した著者実装の公開リポジトリは確認できなかった。再現を試みる場合、384次元の文埋め込み、ε-netの生成、KRRの信頼区間、逆貪欲選択、到着分布のシミュレーション、キャッシュ入替の費用計算を実装する必要がある。実サービスへの導入では、回答の再利用可能性を判断する品質検証器を追加し、距離に基づく代理費用だけではなく実際の推論費用・応答品質で評価することが不可欠である。

## 既存研究との差と位置づけ

既存の有限クエリ向け意味的キャッシュは、候補集合を列挙して到着頻度と推論費用を個別に推定する。これに対して本研究は、連続埋め込み空間で未知の問い合わせが到着することを前提に、ε-netで候補を有限化し、KRRで近い問い合わせ間の費用情報を共有する。オンライン方式はさらに、キャッシュ内容の更新そのものが推論費用を発生させることを目的関数へ含め、段階的な更新で切替頻度を制限する。

結果として、単なる類似度しきい値によるキャッシュヒット判定ではなく、「どの問い合わせへの応答をキャッシュへ残すべきか」を、到着分布、費用、不確実性、切替費用から選ぶ体系を提供する。理論的な価値は、連続空間での離散化・推定・切替の誤差を分けて保証したことにある。実用的な価値は、同じ問い合わせが完全一致で再登場しなくても、近傍からコストを推定してキャッシュ選択を改善できることである。ただし、推論エンジン全体の速度改善や安全な回答再利用まで証明した研究ではない。
