# WIDE: Boosting Adaptive LLM Inference via Token-level Dynamic Width Pruning

> トークンごとに注意ヘッド群とFFNチャネル群の実行可否をルータが決め、マスク並べ替えで不規則な選択をタイル単位の規則性へ変換してブロックごと飛ばす動的幅枝刈りで、削減率50パーセントでも品質を保ちながらプリフィル1.68倍の高速化を得た。

## 概要

枝刈りは、Transformerの層やヘッドやチャネルといった構造を削り、計算量とメモリ移動を減らす手法である。主流の静的枝刈りは、少数の校正データで重要度を測り、不要と判断した構造を恒久的に削除する。実行は稠密なまま規則的でGPUと相性がよいが、どの入力にも同じ削除を適用するため、削減率を上げると品質が大きく崩れる。逆に動的枝刈りは、トークンごとに計算配分を変える。ただし従来の代表方式は層や副層を丸ごと飛ばすかどうかだけを決めるため、モジュールの中の有用な部分まで一緒に捨ててしまう。粒度をヘッドやチャネルまで細かくすれば配分は柔軟になるが、トークンごとに異なる重みの部分集合が要るようになり、それを集めて散らす処理のデータ移動と同期が、削減した計算を相殺してしまう。

本論文の方式WIDEは、この粒度と規則性の両立を狙う。注意機構では、グループ化クエリ注意（Grouped Query Attention; GQA。複数のクエリヘッドが1つのキー・バリューヘッドを共有する方式）にそろえたクエリヘッド群を、全結合ネットワーク（FFN）ではGPUのタイル寸法にそろえた中間チャネル群を、それぞれ最小の枝刈り単位とする。各トークンについて、軽量なボトルネック型ルータが群ごとの実行可否を二値マスクとして出す。推論時はこのマスクを群ごとに並べ替え、有効なトークンをタイル単位の接頭辞へ集約することで、不規則な選択をブロック単位の規則性へ変換する。その上で、完全に不活性なブロックの早期終了、ブロック内での不活性な読み込みの省略、テンソルコア演算の省略という3段階の飛ばしを同じ判定で駆動する。重みは削除されず稠密なまま残り、トークン固有の重み部分集合を実体化しない点が素朴な実装との決定的な違いである。

**代表結果:** 目標削減率50パーセント、ルータ学習のみの校正段階で、Llama3.1-8Bの7つの尤度タスク平均正解率は61.84パーセントとなり、動的深さ型の最強比較対象であるSkipGPTの42.52パーセントを大きく上回った（要旨では最強の動的深さ型比較対象に対する上回り幅を最大20.26ポイントと総括する）。LoRA調整後はQwen3-14Bで稠密モデルの尤度性能の97.6パーセント、生成性能の88.2パーセントを保持した。遅延は別途の実機測定で、稠密比プリフィル最大1.68倍、デコード最大1.55倍だった。

## 問題設定

問題は2つの資源の衝突である。第1に品質側では、トークンごとに必要な計算が違う。意味内容を持つトークンや難しい位置では多くのヘッドやチャネルが要るが、機能語などでは一部で足りる。全トークン一律の削除は、必要量の多いトークンを切りすぎる。第2に実行側では、GPUの行列積はタイルと呼ばれる固定寸法のブロック単位で重みを再利用しながら処理することで速くなる。トークンごとに異なるチャネル部分集合を選ぶと、トークン固有の重み部分集合を集める処理が必要になり、付録の分析ではその中間記憶が有効率に比例する巨大な量になり、稠密な行列積の重み再利用も壊れる。さらに、有効トークンの配置を入力依存のマスクから決める処理はデバイスからホストへの同期を招き、CUDAグラフによる実行の再生を妨げる。つまり細粒度の動的枝刈りは、計算量の帳簿上は得をしても、データ移動と同期と不規則さで実測では損をしやすい。本論文の着眼点は、枝刈り単位をGPUの実行粒度へ最初からそろえ、選択結果を並べ替えて規則性を取り戻すことで、この帳簿と実測のずれを埋めることにある。

## 手法のあらまし

処理の流れは、学習と推論で異なる。学習は2段階で、第1段階ではモデル本体を凍結し、ルータだけを校正データで学習する。第2段階は任意で、本体の線形層へLoRAアダプタを足して品質回復を強め、ルータも引き続き学習する。どちらの段階も、言語モデリング損失に、全体の削減率が目標値へ近づくよう注意とFFNのマスク平均から作る補助損失を加える。推論では、各層の注意とFFNの手前でルータが入力活性値を見て群ごとの二値マスクを出し、群ごとにマスクを降順へ並べ替えて有効トークンを前に集める。カーネルは並べ替え後のマスクからブロック単位の判定を作り、不活性なブロックや読み込みや演算を段階的に飛ばし、出力は保持した元の行位置へ散布して戻す。デコードでは並べ替えなしに元のマスクから直接ブロック単位で飛ばす専用の高速経路を使う。

## 手法

### 1. 群単位の枝刈り単位 — 注意はGQAヘッド群、FFNはタイル寸法のチャネル群

この機構が決めるのは、何を最小単位として飛ばすかである。注意では、キーとバリューの重みは枝刈りせずKVキャッシュを稠密に保ち、クエリ側だけを、共有するキー・バリューヘッド1つに対応するクエリヘッドのまとまり単位で飛ばす。Llama3.1-8Bではクエリ32ヘッド、キー・バリュー8ヘッドなので、群は4ヘッド分になる。この単位にそろえることで、GQA向けの既存のデコード最適化と両立する。FFNでは、中間次元をタイル寸法として使われる2の冪の大きさの連続チャネル群へ分け、上向きとゲートの射影では出力側、下降射影では入力側を同じマスクで制御し、FFN全体を1枚のマスクで表す。減るボトルネックは配分の粗さであり、層丸ごとではなくモジュール内の一部だけを残せるため、同じ削減率でも有用な計算を保持できる。追加で消費する資源は群ごとのマスクとその学習であり、失敗条件は単位の選び方である。群を大きくすると実行は規則的になるが配分が粗くなり、後述のとおりFFN群を512まで大きくするとルータ学習のみの段階で正解率が9.05ポイント落ちる。逆に群を小さくしすぎると、カーネル側の主ループの仕事量が不足して高速化が頭打ちになる。

### 2. ボトルネック型ルータと二段階学習 — トークンの活性値から群ごとの二値を出す

ルータが観測するのは、各トークンの入力活性値である。保持する状態は、隠れ次元から低いランク（評価設定では32）へ圧縮して群数×2のロジットへ広げる2層の重みであり、各群について実行か飛ばしかの二値を出す。学習時はGumbel-Softmaxとストレートスルー推定で微分可能にし、推論時はロジットの最大値で二値を決める。選択するものは各トークンの各群の実行可否であり、これによりトークンごとに実効的な幅が変わる。学習の第1段階では本体を凍結してルータだけを動かし、校正データはLlama系ではRedPajama-1T、Qwen3系ではInfinity-Instructを使う。補助損失の重みは20で、注意とFFNの削減率を等しく重み付けして全体を目標削減率へ寄せる。誤った選択時の挙動は近似そのものである。必要な群を飛ばせばそのトークンの表現が欠け、誤差は層を進むごとに蓄積する。論文はこの蓄積を稠密モデルとの最終層誤差で測り、細粒度化が蓄積を抑えることを示している。逆に不要な群を残せば品質は保たれるが削減効果が目減りする。ルータ自体の計算と、目標削減率を守るための補助損失との釣り合いが追加費用になる。

### 3. マスク並べ替えと3段階の飛ばし — 不規則な選択を稠密型カーネルの規則性へ戻す

この機構が観測するのは、ルータが出した群ごとの二値マスクである。保持する状態は、群ごとにマスクをトークン方向へ降順に並べ替えた結果と、元の行位置を記録した索引である。並べ替えにより、各群の有効トークンは連続した接頭辞へ集まり、境界の1ブロックを除いて各ブロックは完全に有効か完全に不活性かになる。行う動作は3段階の判定である。最も粗い段階では完全に不活性なブロック全体を早期終了し、これはハードウェアに依存しない。次の段階ではブロック内で不活性な行の活性値読み込みを飛ばし、最も細かい段階では不活性な行列積演算の断片を飛ばす。この2つはアーキテクチャ依存の粒度で判定する。対象カーネルは、クエリ射影とFFNの上向き・ゲート射影を担うもの、出力射影と下降射影を担うもの、注意計算そのものの3種である。減るボトルネックは、トークン固有の重みを集めるデータ移動と、そのためのデバイス・ホスト間同期であり、重みタイルは有効行の間で共有される稠密型の主ループが保たれる。追加で消費する資源は、並べ替えと索引による活性値の集約・散布、マスク用の作業領域の初期化、そしてルータ計算である。論文の層内訳では、枝刈り経路が理想上限に近い高速化を示す一方、残りの作業がプリフィル時間の約16.7パーセント、デコード時間の約29.1パーセントを占めるとされる。失敗条件はマスクがランダムに近い場合である。ブロック寸法がトークン数以上になると、完全に不活性なブロックがほぼ現れず、最も粗い段階の飛ばしが効かなくなる。またデコードでは並べ替え自体が割に合わないため、元のマスクから直接判定する専用経路へ切り替える。

| 構成要素 | 入力・観測 | 具体的な動作 | 改善対象 | 主なトレードオフ |
|---|---|---|---|---|
| 群単位の枝刈り単位 | ヘッド構成とタイル寸法 | 注意はGQAヘッド群、FFNはチャネル群を最小単位にする | 層単位枝刈りの粗さ | 群が大きいと配分が粗く、小さいとカーネル効率が落ちる |
| ボトルネック型ルータ | トークンの入力活性値 | 低ランク射影で群ごとの実行可否を二値で出す | トークンごとの計算配分 | 誤判定は品質低下、ルータ計算が常時乗る |
| マスク並べ替えと3段階の飛ばし | 群ごとの二値マスク | 有効行を接頭辞へ集め、ブロック・読み込み・演算の順に飛ばす | 集約・散布の移動量と同期 | 並べ替え費用と、ランダムなマスクでの効果低下 |

### 4. 1トークンの流れ — ルータ判定から散布まで

1つのトークンは次のように進む。層の入力でルータがそのトークンの活性値を見て、注意のヘッド群とFFNのチャネル群について実行可否を決める。注意では選ばれたヘッド群だけが計算され、キーとバリューは稠密に保たれるためKVキャッシュの扱いは変わらない。FFNでは選ばれたチャネル群だけが上向き・ゲート射影と下降射影を通る。バッチや系列内の他のトークンとは選択が異なるため、カーネル内では群ごとに並べ替えられた行位置で処理され、出力は索引に従って元の位置へ戻される。本方式は近似型であり、飛ばされた群の計算は後から取り戻せない。無損失型の投機的実行とは異なり、品質はルータの学習精度と回復学習に全面的に依存する。

## 評価

結論は三点である。第1に、品質では削減率50パーセントかつ校正のみという厳しい条件で、従来の静的・動的方式を大きく上回り、細粒度配分の利得が最もはっきり出た。第2に、速度では削減率25パーセントでは稠密とほぼ同等にとどまるが、50パーセントではプリフィルとデコードの双方で明確な高速化が実機で得られた。第3に、利得はアーキテクチャ依存で、ベクトル化された原子演算を持たないsm80ではプリフィルの利得が維持できず、方式の移植性には条件がある。評価は実機測定であり、品質は尤度タスクのゼロショット正解率と生成タスクで測る。

### 感度・スケーリング・ストレス条件

目標削減率を10パーセントから70パーセントへ動かすと、本方式の正解率は緩やかに下がり続け、多くの水準でLoRA調整後のSkipGPTをルータ学習のみで上回った。注意とFFNへの配分比は、目標10パーセントでは5.9対1、70パーセントでは1.3対1と、削減が深いほどFFN側へも配分が広がる。広い比較対象では、FFNだけを対象とするMoE化方式や半構造化方式を上回った一方、最も細かい粒度で枝刈りするWINAには及ばなかった。つまり粒度の細かさ自体にも品質上の価値があり、本方式は実行可能性との釣り合いで群単位に留めている。

## 既存研究との差

静的幅枝刈りのSliceGPTやDDPは、校正で決めた構造を全入力へ恒久適用する。本論文は削除を恒久化せず、群の実行可否をトークンごとに決める点が異なる。動的深さ枝刈りのMixture-of-DepthsやSkipGPTは、トークンごとに層や副層を飛ばすが、モジュール内部の配分はできない。本論文は判定の対象をモジュール内部のヘッド群とチャネル群へ移し、さらにその細かい判定をGPUで実行可能にするマスク並べ替えとカーネルを一体で提案した。活性値の閾値で細かく飛ばすWINAやPolarSparsityは粒度では上回るが、対象がデコードやプリフィル、あるいは注意のみなど場面が限られる。本論文は注意とFFNの双方、プリフィルとデコードの双方を1つの枠組みで扱う点で範囲が広い。

## 限界・実装状況

論文の結果が示す限界は三つある。第1に、アーキテクチャ依存性である。sm80ではベクトル化された原子演算がないため、分割と原子加算に依存するプリフィル側の利得が維持できず、デコードのみ最大1.62倍にとどまった。第2に、削減率25パーセントでは端から端までの高速化が立たず、稠密の0.98倍相当が最良であり、固定費を回収するには深い削減が前提になる。第3に、品質は近似として残り、特に生成タスクでは削減率50パーセントで稠密の88パーセント程度まで落ち、回復にはLoRA調整の追加学習が要る。対象モデルはLlama3系とQwen3系に限られ、他のモデル族や多リクエストのサービング条件への一般化は未検証である。実装状況としては、公式コードが公開され、カーネルはSGLangの基盤上でTriton、TileLang、CuTeの3実装が用意されるが、ブロック内までの細かい飛ばしはCuTe版のみであり、タイル単位の実装ではブロック単位の飛ばしまでしか得られない。

## 一般的な実装上の含意

動的枝刈りを実測高速化へつなげるには、削減単位をGPUのタイルや注意のグループ化といった実行粒度へ最初からそろえることが先決である。帳簿上の計算削減率ではなく、トークン固有の重みを実体化していないか、デバイス・ホスト間同期が混入していないか、ブロック単位で完全に不活性な単位が生まれるかを点検すべきである。また、削減率が浅い条件では適応機構の固定費が利得を食うため、目標削減率とアーキテクチャの両方で損益分岐を確認する必要がある。層ごとの誤差蓄積を稠密モデルとの距離で測る方法は、粒度選択の良し悪しを最終タスクより前に切り分ける診断として他の枝刈り研究にも転用できる。
