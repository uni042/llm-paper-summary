# KV Admission：何をKVキャッシュに書くかを学習する長文脈推論

## 概要

長文脈の大規模言語モデル（LLM）では、入力を一括処理する事前充填（prefill）における注意計算と、トークンを逐次生成する復号（decode）における鍵・値キャッシュ（KVキャッシュ）の読出しが異なる律速要因になる。標準の自己回帰推論は、各トークンのKVを将来必要かどうか判断せずに蓄積する。既存のKV選択（selection）は読出し時に参照先を減らすが、保存済みKVの容量は基本的に減らさない。KV破棄（eviction）は容量を制限できる一方、一度書いたKVを後で捨てるため、不要な書込みや一時的なメモリ使用を防ぎにくい。

本論文はこの二方式に先立つ第三の操作として、**KV受入れ（admission）**を明示的に定式化する。提案する書込ゲート付きKV（Write-Gated KV、WG-KV）は、トークンごとの将来有用性を注意ヘッド別の小型多層パーセプトロン（MLP）で予測し、長期保持に値するKVだけを大域キャッシュへ保存する。ただし直近のトークンは、予測値が低くても局所キャッシュへ一時保存する。学習済みゲート、局所・大域の二層キャッシュ、疎な事前充填注意、不規則なKV長に対応する復号カーネルを一体として設計した点が特徴である。

単一のNVIDIA H200、バッチサイズ1、PG-19由来の長文入力を用いた実測では、Llama-3.1-8BでKV約80%疎化時に事前充填2.56～3.85倍、復号1.61～2.63倍、全体メモリ36～60%削減を報告する。Qwen3-4B-2507でも事前充填3.23～4.17倍、復号1.59～2.50倍、メモリ53～69%削減となった。これらは**全注意方式との比較**であり、全モデル・全ハードウェアで保証される値ではない。出典は原著v4の§5と付録F・Gである。

## 問題設定と着想

通常のKVキャッシュは、新たなトークンのキーと値をすべて末尾へ追加する。過去のKVを再計算しないためには合理的だが、長い入力の中には将来ほとんど参照されない状態も多い。事前充填ではトークン数に対する注意演算が二次的に増え、復号では過去KVを繰り返しメモリから読み出すため、GPUの演算能力より帯域と容量が制約になる。書込後の重要度推定では、無駄なKVが蓄積した時点の費用を取り消せない。

原著は、注意の有用性に三つの性質を見いだす。第一に少数のトークンへ注意が集中する。第二に重要なトークンはヘッドごとに異なり、同じトークンを全ヘッドから一律削除するのは不適切である。第三に、遠い将来は不要でも直後の数トークンには重要な「一時的有用性」がある。このため、即座に永久破棄する単一ゲートでは品質を落としやすく、**直近は必ず残し、長期保存だけを選ぶ**二段階構成が必要になる。

KV受入れ、読出し時選択、事後破棄は排他的ではない。受入れは新規KVの書込み判断、選択は現在の質問に対する参照判断、破棄は保存後に役目を終えたKVの削除判断である。三者は異なる時点の操作なので併用できるが、原著の速度評価はまず受入れ方式を全注意と比較している。既存の選択・破棄と組み合わせた結果は別の付録実験として扱う。

## 手法

### 1. 注意ヘッド別の書込ゲート

層$l$、KVヘッド$h$、トークン$t$ごとに、回転位置埋込み適用前後のキーをそれぞれ正規化し、連結した特徴量$x_{l,h,t}$を小型MLPへ渡す。出力$g_{l,h,t}$は0から1の書込スコアであり、シグモイド関数で得る。各KVヘッドに個別のゲートを設けるため、あるヘッドでは構文上の区切りを残し、別のヘッドでは固有名詞や数値を残す、といった異なる判断が可能になる。キーの前後両表現を使う点は、位置情報を含む特徴と含まない特徴を同時に参照するためである。

学習時にはゲートをいきなり0/1に切らず、遠方のトークン$j$の注意重みへ$g_j$を掛ける。ただしクエリ位置$i$からの距離が局所窓$W_{local}$未満なら、ゲート値にかかわらず重みを1として扱う。具体的には$m_{ij}=\max(\mathbf{1}[i-j<W_{local}],g_j)$であり、注意の指数重みへ$m_{ij}$を乗じる。実装では$\log(m_{ij}+\epsilon)$を注意スコアの加算バイアスに変換することで、汎用の効率的注意カーネルを利用できるようにする。これは学習中の微分可能な近似であって、推論時に0と1のどちらかを選ぶ操作とは区別される。

### 2. 蒸留と疎化を両立する学習

基盤モデルの重みは凍結し、書込ゲートMLPだけを追加学習する。全注意モデルの最終層隠れ状態との平均二乗誤差を蒸留損失とし、ゲートを小さくする項と中間値を避ける項を加えた疎化損失を、係数$\lambda$で重み付けする。前者は不要なKVの長期保存を減らし、後者は学習時の連続ゲートを推論時の二値判断に近づける。

推論では閾値$\tau$を超えるKVを長期保存する。原著の主要評価は$\tau=0.1$に固定し、$\lambda$を変えて保存率を調整する。閾値と疎化係数は互換ではなく、学習済みモデルのゲート分布に対する閾値変更と、学習目的自体の変更を区別する必要がある。付録Jでは、連続ゲートを学習して最後に二値化する方式と、学習時から離散ゲートを使う方式の疎化・蒸留誤差の境界が、主要な運用範囲では近いと報告する。

学習データはFineWeb-Eduの4K～32Kトークン系列7,500件、約6,300万トークンで、単一H100上の1回の学習に約6時間を要する。推論時のゲートは追加パラメータが基盤モデルの約0.4%に収まるが、**完全な学習不要方式ではない**。推論用の新モデルやヘッド構造へ適用するには、ゲートの追加学習と性能検証が必要である。推論中に全基盤モデルを更新する方式とも異なる。

### 3. 局所・大域の二層KVキャッシュ

推論時は各ヘッドに固定長の局所キャッシュと、ゲートで選ばれた状態だけが増える大域キャッシュを用意する。新規KVはまず局所窓へ書かれる。窓から追い出される古いKVを確認し、その保存時のゲート値が閾値以上なら大域キャッシュへ昇格させ、そうでなければ破棄する。最後に新しいKVで局所領域を上書きし、局所ポインタをリング状に進める。この遅延昇格（lazy promotion）により、直近の密な注意と長期の疎な注意を同時に成立させる。

ヘッドごとに大域キャッシュの長さが異なると、単純な連続テンソル配置は断片化や再確保を招く。WG-KVは論理ページと物理ページを分離し、ヘッド別ページ表で共有KV領域へ対応付ける。原著のページ粒度は16トークンである。固定の最大長をヘッドごとに先取りする必要がなく、保存率の偏りを許容できる反面、ページ表の更新と昇格時の移動・管理が追加費用となる。

### 4. 事前充填の疎注意と復号カーネル

事前充填では、全クエリから見える「大域保存対象」の列と、各クエリの直近局所窓の斜め帯を合わせた縦帯・斜帯型の疎注意マスクを作る。ゲート閾値を満たす列だけを長期参照先とし、近傍トークンは常に参照する。MInference系の疎FlashAttentionを使って、マスク外の演算を省略する。入力の最終局所窓は局所キャッシュへ、それ以前の高スコアKVだけは大域キャッシュへ保存する。

復号ではヘッドごとに異なるキャッシュ長がGPU負荷の不均衡を生む。ヘッド次元をバッチ次元へ折り畳めば一般的な可変長ページ注意を使えるが、原著の実装では長さの偏りが大きく性能を損ねた。このため専用Tritonカーネルを採用し、ヘッド間のKVブロックを均一な処理片へ分けて部分結果を統合する分割・縮約（split-reduce）で負荷を平準化する。**ページ注意への論理的適合性と、最速実装が既存の汎用カーネルであることは同義ではない**。

## 評価

### 条件と比較対象

| 項目 | 一次論文で確認した条件 |
|---|---|
| 基盤モデル | Llama-3.1-8B、Qwen3-4B-2507（非推論版を性能評価） |
| 学習 | 基盤重み固定、ゲートのみ学習。FineWeb-Edu 7,500件・約63Mトークン、単一H100で約6時間 |
| 性能測定装置 | NVIDIA H200を1基、バッチサイズ1、CUDAイベントで時間計測 |
| 入力と復号 | PG-19長文入力、1回のウォームアップ後、復号300トークンの平均を計測 |
| 性能指標 | 初回トークン到達時間（TTFT）と出力1トークン当たり時間（TPOT）、全体メモリ使用量 |
| 品質指標 | HELMETの14タスク・5領域、文脈長32K。検索拡張生成、再順位付け、長文質問応答、要約、多数例文脈学習 |
| 主な比較方式 | 全注意、局所注意、DuoAttention、学習不要のAdaEA++（KV受入れ方式へ適応した比較実装） |
| 主な疎化設定 | Llamaは$\lambda=0.16$、Qwenは$\lambda=0.32$。いずれも約80%疎化、KV受入れ率約20% |

比較方式の局所注意は最近傍と先頭の注意シンクだけを保持する。DuoAttentionはヘッド単位で全KV保持と局所保持を固定的に分ける。AdaEA++は事前計算したクエリ統計とヘッド別閾値から書込判断を行う学習不要の適応方式である。これらを同じ受入れ基盤へ載せた比較は、ゲートの学習価値を検討するものだが、各方式の原著実装同士をそのまま比較した数値ではない。

### 速度・容量・精度

| モデル・条件 | 指標 | 全注意との比較 | 解釈 |
|---|---|---|---|
| Llama-3.1-8B、約80%疎化 | 事前充填の実測速度 | 2.56～3.85倍 | 縦帯・斜帯の疎注意により長文入力の演算を省く |
| Llama-3.1-8B、同条件 | 復号の実測速度 | 1.61～2.63倍 | KV読出し量を減らし、不規則長ヘッドの処理を平準化する |
| Llama-3.1-8B、同条件 | 全体メモリ使用量 | 36～60%減 | KV以外の重み等も含むため、KV疎化率80%とは一致しない |
| Qwen3-4B-2507、約80%疎化 | 事前充填の実測速度 | 3.23～4.17倍 | 別モデルでも疎注意の利得を確認 |
| Qwen3-4B-2507、同条件 | 復号の実測速度 | 1.59～2.50倍 | 別モデルでもKV転送削減を確認 |
| Qwen3-4B-2507、同条件 | 全体メモリ使用量 | 53～69%減 | モデル構成により総容量削減率は変わる |

初回トークン到達時間（TTFT）が小さいほど入力処理から応答開始までが速く、出力1トークン当たり時間（TPOT）が小さいほど生成途中の待ち時間が短い。ここでの速度倍率は両者の時間の逆比に対応する。原著付録Fはゲート計算、ページ割当、索引生成、遅延昇格を測定範囲へ含めるとしている。GPU演算カーネル単体の理想化した値ではない一方、**同時多数要求の実サービングでのスループットを直接測った値でもない**。

HELMETでは受入れ率を変えて品質・疎化率の関係を測定し、特にKVの10%のみを長期保持する条件でも、MS MARCOの再順位付けとInfiniteBench Sum・Multi-LexSumの要約などでほぼ損失のない品質を報告する。ただし「ほぼ損失なし」は評価タスクの観測結果であり、任意の入力で厳密な出力一致を保証するものではない。受入れ率が下がるほど品質劣化の可能性は残り、学習なしの局所注意方式は厳しい予算で急速に悪化した。

### 構成要素・併用・負の結果

局所キャッシュを実質的に外す構成要素除去実験では、窓長を1として同じ目的関数で再学習すると、同じKV容量に対する蒸留誤差が顕著に悪化する。これは「直後には重要だが長期保存は不要」というトークンをゲートだけで判定すると、必要な短期情報を早く捨てすぎることを示す。二層構成のうち局所窓は単なる実装都合ではなく品質維持のための要素である。

読出し時選択のQuestとの併用では、WG-KVで保存対象を約20%へ減らした後、クエリ当たり2,048件の選択予算を課す。事前に候補KVが減るため、Quest単独に比べて復号時のメモリアクセスと注意遅延が低下し、HELMET精度はほぼ同等だった。受入れと選択の効果は重ねられるが、この結果は原著付録Hの特定設定であり、全選択方式への無条件な一般化ではない。

破棄方式のSnapKVとの併用は、Qwen3-4B-2507の**推論版**でAIME25数学問題を解く別実験である。平均KV容量をヘッド当たり4,096トークンに制限し、超過時に重要度下位10%を破棄する。最近256クエリの注意をヘッド群で集計して重要度を求める。厳しい容量制約下でSnapKVだけなら正答率26.7%、WG-KVだけで破棄を避けようと強く疎化した条件では66.7%だったのに対し、$\lambda=0.32$のWG-KVとSnapKVを併用すると80.0%となり、容量無制限の基準方式と同水準だった。**Llamaの性能倍率や非推論版Qwenの評価と混ぜない**ことが重要である。

## 既存研究との差

QuestなどのKV選択は読出し時に必要なKVを探すため、過去に書き込んだ状態の全量保持を前提とする。SnapKVなどの破棄方式は過去の観測に基づき容量を削るが、不要KVが一度はキャッシュへ入る。WG-KVは保存前の段階で長期保持を学習して判断し、局所窓からの遅延昇格で短期参照を守る。さらに、ヘッド別の不規則長というアルゴリズム由来の問題に対して、ページ表と分割・縮約カーネルを組み合わせ、計算量削減を実測の待ち時間短縮へつなぐ。

学習不要のAdaEA++と異なり、WG-KVは追加学習を要するが、入力ごとの複雑な注意の偏りに適応できる。DuoAttentionのような静的ヘッド分担とは異なり、同じヘッドでも入力やトークンに応じて保持率を変える。コード要約とHTML表抽出でヘッド別の保持分布が異なるという付録Lの観察は、この入力依存性を補助的に示している。

## 限界・再現上の注意

第一に、性能実験は単一H200・バッチ1の試作実装が中心である。多要求を連続的に処理するサーバー、複数GPU、PCIe越しのCPUオフロード、消費者向け12GB級GPUなどの環境では、メモリ節約率・カーネル効率・ゲートの追加費用がどう変わるかを原著は定量的に検証していない。上流vLLMへの組込みを説明したものではなく、一般的なPagedAttentionへ形式的に変換できても、原著の最速復号には独自のTritonカーネルが必要だった。

第二に、長期保持を学習済みゲートで近似するため、訓練分布外の文章、極端に低い保存率、特殊な推論経路で重要情報を誤って破棄するリスクがある。著者は推論版Qwenで別の数学データを学習へ追加しており、非推論版での結果をそのまま推論版へ転用できない。局所窓を削った構成で品質が悪化することも、誤予測の影響を局所保持が緩和していることを示す。

第三に、保存率約20%という値はKVキャッシュ内の対象状態の比率であって、GPUメモリ全体が80%減ることを意味しない。基盤モデルの重み、作業領域、ゲート、ページ表は残る。事前充填と復号の速度倍率も異なる指標であり、同時要求数やトークン長の分布によって端から端までの改善は変化する。性能比較は論文にあるモデル・装置・設定に限定して読むべきである。
