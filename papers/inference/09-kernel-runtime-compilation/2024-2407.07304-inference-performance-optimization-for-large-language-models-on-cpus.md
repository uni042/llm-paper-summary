# Inference Performance Optimization for Large Language Models on CPUs

> KVキャッシュ削減、oneCCL分散通信、CPU命令・モデル別カーネル最適化をxFasterTransformerへ統合し、GPUなしのLLM推論を実用化する。

## 概要
GPU不足や費用制約のある環境ではCPU推論が選択肢になるが、LLMは重み帯域、KVキャッシュ容量、分散通信の全てが重い。本論文は一つの新演算だけでなく、KVキャッシュ削減、CPU向けカーネル、複数CPUノードの通信をまとめたxFasterTransformerベースの推論最適化を提示する。実装はIntelのAMX/AVX-512系命令とoneAPI Collective Communications Library（oneCCL）を利用する。

## 問題設定
CPUはGPUより演算密度が低く、デコードでは大きな重みを毎トークン読み出すためメモリ帯域律速になりやすい。長文脈ではKVキャッシュもDRAM容量と帯域を圧迫する。モデルを複数socket/nodeへ分割すると、今度は集団通信（collective communication）が待ち時間になるため、個別のGEMM高速化だけでは十分でない。

## 手法
第一に、精度を保ちながらKVキャッシュ占有量を減らす経路を導入し、長い系列・大きいbatchでのメモリ圧力を下げる。第二に、CPUの行列積・注意・モデル固有演算をAMX/AVX-512など利用可能な命令へ合わせ、一般的なモデルごとに実行経路を調整する。

分散推論ではoneCCLを用いてtensor parallel等に必要な集団通信を実装し、CPU計算と通信のボトルネックをまとめて扱う。公開実装xFasterTransformerはこれらを利用者が個別に再実装せず導入できる形に統合する。

## 評価条件・主要結果
| 項目 | 内容 |
|---|---|
| 主対象 | GPU資源が限られるCPU LLM推論 |
| 実装 | xFasterTransformer |
| 通信 | oneCCLベースの分散推論 |
| メモリ | 精度維持を狙ったKVキャッシュ削減 |
| CPU経路 | モデル別・命令セット別最適化 |
| 公開環境上の制約 | xFasterTransformerはAMX/AVX-512対応CPUを想定し、Intel CoreやWindowsネイティブは対象外 |

論文の公開要旨は特定の一つのend-to-end倍率をheadlineとして示すより、CPU推論の複数ボトルネックを統合的に解くことを主貢献としている。したがって、条件が確認できない速度倍率を補わず、実装対象と最適化経路を主要結果として記録する。

## 既存研究との差
CPU向け単体量子化やGEMM kernelだけでなく、KVキャッシュ、モデル別演算、分散通信まで同一ランタイムへ統合する。GPU推論基盤をCPUへ単純移植するのではなく、CPU命令セットとoneCCLを前提にデータ経路を組み直している。

## 限界
xFasterTransformerの公開要件上、AMX/AVX-512を持たない一般的なIntel Core CPUは対象外で、Windowsもネイティブ対応しない。したがって「CPUならどこでも高速」という方式ではない。評価結果はCPU世代、socket/node構成、メモリ帯域、モデル形状に強く依存する。
