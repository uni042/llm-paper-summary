# Blockwise Parallel Transformer for Large Context Models

> 自己注意とフィードフォワード網をブロック単位で融合実行し、中間活性を全系列分保持しないことで長文脈のメモリ使用量を削減する。

## 概要

自己注意とフィードフォワード網をブロック単位で融合実行し、中間活性を全系列分保持しないことで長文脈のメモリ使用量を削減する。 通常Transformerより32倍長く、従来のメモリ効率化方式より最大4倍長い系列を学習できると報告する。

大規模モデルの推論では、演算回数だけでなく重み・KVキャッシュの読み出し、装置間通信、逐次生成の同期、GPUの電力状態などが実時間と費用を決める。本研究は対象となる律速へ直接作用する実行機構を設計し、理論指標だけでなく実装上の効率改善を狙う。

代表結果は、通常Transformerより32倍長く、従来のメモリ効率化方式より最大4倍長い系列を学習できると報告する。 この数値は論文の評価条件に依存するため、異なるGPU、モデル、系列長、バッチ数へそのまま外挿しない。一方、提案処理のオーバーヘッドを含めて改善が得られることを示す主要な証拠である。

## 問題設定

従来方式は全状態を均一に扱ったり、最悪条件に合わせて資源を常時確保したりするため、入力や負荷の偏りを利用しにくい。また、モデル上の演算量を減らしても、実機でメモリ帯域や通信が律速なら待ち時間は比例して減らない。そこで、どの情報・演算を残すかを選び、GPUが扱いやすい粒度で実行へ反映する必要がある。

評価では、カーネル単体とエンドツーエンド、理論的な削減率と実測高速化、メモリ容量と帯域を区別する必要がある。本論文の意義は、対象ボトルネックを明示し、そのボトルネックを減らす機構と実測結果を接続している点にある。

## 手法

系列を複数ブロックへ分け、注意計算をブロックごとに進めながら、その出力をすぐフィードフォワード網へ渡す。通常は注意層全体の出力を保持してから次層へ進むが、ブロック内で融合することで巨大な中間活性の常駐を避ける。注意の正規化に必要な統計はブロック間で累積し、数学的な注意結果を保ちながらピークメモリを下げる。

手法の因果関係を実行経路で見ると、入力要求が到着した後、まず対象となる状態や統計を観測し、その値から次に使う計算資源・保持状態・実行方式を決める。決定後の計算結果は次の生成反復または次の処理段階へ渡される。重要なのは、削減対象を単独で小さくするのではなく、削減によってGPUメモリ帯域、演算器利用率、装置間転送、待ち時間のどれが実際に減るかを対応付けている点である。

この種の最適化には追加費用もある。状態判定、量子化、検証、配置変更、圧縮・復号、制御処理は無料ではない。したがって提案法が効くのは、追加処理よりも回避できる重い処理やデータ移動が大きい領域である。入力が短い、バッチが小さい、対象ボトルネックが別資源へ移るなどの条件では、論文で示された最大利得より小さくなる可能性がある。

また、品質保護の仕組みを速度改善と切り離して読む必要がある。近似を使う方式では重要情報を保護する窓や検証経路があり、損失なし方式では元の値・分布を再現することが条件になる。配信制御ではサービス品質目標を満たす範囲だけ資源を下げる。こうした制約があるため、単純な最大圧縮率や最低周波数を選ぶ方式とは異なる。

1要求の処理を通して見ると、前処理で得た判断が中核計算へ反映され、その結果を使って次の反復の判断を更新する。複数機構をこの順序で接続することで、アルゴリズム上の工夫をエンドツーエンドの速度・容量・電力へ変換する。誤予測や負荷変動が起きた場合は、より安全な実行状態へ戻すか、追加検証を行う必要がある。

## 評価

通常Transformerより32倍長く、従来のメモリ効率化方式より最大4倍長い系列を学習できると報告する。

実用上は最大値だけでなく、どの条件で利得が生じるかが重要である。対象処理が支配的な領域ほど改善が大きく、別の処理が律速になると速度向上は飽和する。したがって導入時には、論文と同じ品質条件を固定し、対象環境の処理量、遅延、メモリ、電力を同時に測るべきである。

品質についても、近似・量子化・投機・制御を導入した結果として元の精度や出力分布がどう変わるかを確認する必要がある。速度だけを最大化して品質条件を緩めた結果を、同品質の高速化と混同しない。

## 既存研究との差

既存の推論効率化には、量子化、KVキャッシュ削減、投機的復号、専門家配置、カーネル最適化、ハードウェア協調などがある。本研究はそのうち対象資源を具体的に定め、モデル側の情報と実行系またはハードウェアの制御を結び付ける。これにより、単なるパラメータ数・FLOPsの削減ではなく、実際の帯域・通信・待ち時間へ効果を移す。

## 限界・実装状況

結果は論文で使ったモデル、GPUまたはアクセラレータ、入力分布に依存する。異なる環境では律速が変わるため、最大倍率を一般化できない。また追加の制御・圧縮・検証処理が小さい仕事量では相対的に重くなる。既存推論基盤へ統合する場合は、連続バッチ処理、接頭辞キャッシュ、並列化など他の最適化との相互作用を再測定する必要がある。
