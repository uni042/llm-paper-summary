# Blockwise Parallel Transformer for Large Context Models

> 注意だけでなくFFNまで系列ブロック内で融合して学習時活性を保持しないBPT。A100/TPU v4でメモリ効率型注意より2〜4倍長い文脈を学習可能にし、1B・16Kでは通常Transformer比1.20倍の学習スループットを示す。

## 概要

長文脈Transformerで最初に問題になるのは、自己注意のスコア行列が系列長 (s) に対して (O(s^2)) のメモリを使うことだった。FlashAttentionやメモリ効率型注意（Memory Efficient Attention）は、オンラインsoftmaxとタイル計算によって巨大な注意行列を高帯域メモリ（High Bandwidth Memory; HBM）へ完全展開せず、注意部分の活性メモリを線形へ落とす。

しかし注意の二乗メモリを消すと、各Transformer層のフィードフォワードネットワーク（Feed-Forward Network; FFN）が次のメモリ壁になる。FFNは隠れ次元より通常数倍広い中間表現を全系列位置に生成し、学習時には逆伝播のためその活性を保持する。論文の標準的な4倍幅FFNでは、勾配チェックポイント法を使っても最大約 (8bsh) バイトのFFN活性が必要になる。

ブロック単位並列Transformer（Blockwise Parallel Transformer; BPT）は、注意だけをブロック化するのではなく、**一つの問い合わせブロックについて正確な注意を計算し、その出力をすぐFFNへ通してから次の問い合わせブロックへ進む**。全系列分の注意出力やFFN中間活性を同時保持しないため、長文脈でピークメモリを下げられる。モデル構造や注意関数を近似する方式ではなく、演算順序を再編成する方式である。

80GB A100では、1Bモデルの最大学習文脈をメモリ効率型注意の65Kから131Kへ、3Bモデルを16Kから65Kへ拡張した。8枚A100では30Bで16Kから65K、64 TPU v4では70Bで2Kから8Kへ伸ばす。通常注意との最大比は32倍、FlashAttention/Memory Efficient Attentionとの比は2〜4倍である。

本論文の主対象は**学習時活性メモリ**である。OpenWebText学習のスループットも評価するが、自己回帰LLM配信の鍵・値キャッシュ（Key-Value cache; KVキャッシュ）、初回トークン遅延、1トークン当たり遅延を改善した研究ではない。

## 問題設定

### FlashAttentionの後にFFNがメモリ壁として残る

通常注意は (QK^T) とsoftmax後の行列を保存するため系列長に対して二乗の活性を必要とする。FlashAttention系はこれをブロックごとのオンラインsoftmaxで計算し、中間注意行列の完全な実体化を避ける。

一方FFNは各位置を独立に処理するため計算量は系列長に対して線形だが、第一線形層の出力や活性化関数周辺の中間状態を逆伝播用に保持する必要がある。系列が数万〜十数万トークンへ伸びると、この線形項でも絶対量が大きくなる。

したがって既存方式が注意の二乗項を消した後は、**FFNの線形だが係数の大きい活性**が相対的に支配的になる。BPTは注意カーネル単体をさらに改善するのではなく、注意とFFNの層境界を越えて演算順序を変える。

### 単純な系列分割では正確な注意にならない

問い合わせを小ブロックへ分けても、各問い合わせは全ての必要な鍵・値へ注意する必要がある。入力を独立チャンクとして処理すればチャンク外依存を失い、元Transformerと別の関数になる。

BPTは各問い合わせブロックについて鍵・値側の全ブロックを走査し、オンラインsoftmaxの分子、分母、最大スコアを累積する。全 (QK^T) 行列を同時に保持せず、通常注意と同じ結果を得る。

## 処理の流れ

1. 入力系列を問い合わせブロックと鍵・値ブロックへ分割する。
2. 一つの問い合わせブロックを固定し、鍵・値ブロックを順に走査する。
3. 部分注意スコアを計算し、数値安定なオンラインsoftmaxの統計を更新する。
4. 全鍵・値ブロックを処理すると、その問い合わせブロックの正確な注意出力が完成する。
5. その出力を直ちに出力射影、残差接続、FFNへ流す。
6. FFNのブロック出力を最終系列出力へ書き、巨大な中間活性を保持したまま次ブロックへ進まない。
7. 次の問い合わせブロックで同じ処理を繰り返す。

従来の「全系列の注意出力を作る→全系列のFFNを作る」から、「小ブロックの注意→同じ小ブロックのFFN」へ変えることで、中間テンソルの生存区間を短縮する。

## 手法

### 1. 鍵・値ブロック走査による正確なオンラインsoftmax

一つの問い合わせブロックに対し、BPTは鍵・値を複数ブロックへ分けて順に読む。各ブロックで部分的な注意スコアを計算し、現在までの最大値、softmax分母、値との積の分子を持ち回る。

新しい鍵ブロックでより大きな最大スコアが出た場合は、以前の分子・分母を指数補正して新しい基準へ合わせる。このため全注意行列を保持せずに正確なsoftmax結果を得られる。

### 2. 問い合わせブロック単位で注意とFFNを融合する

BPT固有の工夫は、注意結果を全系列分そろえてからFFNへ渡さない点にある。一つの問い合わせブロックの注意が完成したら、そのブロックだけを直ちにFFNへ渡す。

全系列分のFFN中間活性を保持する従来方式に対し、BPTでは同時に生きるFFN中間活性が問い合わせブロック長 (c) に制限される。 (c ll s) の長文脈でこの差が大きくなる。

### 3. 勾配チェックポイント法との組み合わせ

論文評価では各方式に同じ勾配チェックポイント法（gradient checkpointing）を適用し、比較ごとに最良の方針を探索する。BPTはチェックポイント法の代替ではなく、その上で活性をブロック化する。

理論分析では、通常注意の (O(s^2)) 活性を消したうえで、FFN側の大きな中間状態もブロック長へ制限するため、長系列でピークメモリをさらに下げられる。

### 4. ブロック長によるメモリ・速度交換条件

ブロックを小さくすればピークメモリは減るが、走査や高水準JAX演算の管理費用が増え得る。大きくすれば演算効率は上がりやすいがメモリを多く使う。

論文は問い合わせ・鍵値ブロック長を16〜4096から格子探索し、各方式の最良結果を報告する。したがってBPTは固定ブロック長の手法ではなく、装置・モデル・系列長ごとに適切な点を選ぶ必要がある。

## 既存研究との差

FlashAttentionとMemory Efficient Attentionは、自己注意の (s	imes s) 中間行列を完全実体化しないことで注意部分を改善する。一方、FFNは従来どおり全系列に対して実行され、逆伝播用中間活性が残る。

BPTはこの層境界を越え、**注意を小さくした後、その出力を同じブロック粒度のFFNへ即座に流す**。したがって単なる新しい注意カーネルではなく、Transformer層全体の実行スケジュールを変える。

Longformer等の疎注意と異なり、BPTは注意範囲を近似しない。その代わり正確な注意の演算量 (O(s^2)) は残るため、メモリ容量を解決した後は計算時間が次の律速になり得る。

## 限界・実装状況

主評価は**学習**であり、自己回帰LLMのデコード時KVキャッシュや配信スケジューリングを対象にしていない。推論系の分類に置く場合も、配信高速化方式として扱わない方がよい。

実装は簡潔さを優先した高水準JAX演算で、著者はCUDAやTritonへの低水準移植を将来課題として挙げる。公開実装も、低水準の逆伝播カーネル最適化を今後の課題としている。

最大文脈評価は系列数1・データ並列なしというメモリ限界を見る条件である。実際の大バッチ分散学習で同じ倍率の最大文脈が得られるとは限らない。

またBPTは正確な全注意を維持するため、系列長増大に伴う二乗の演算量を削除しない。131Kをメモリへ載せられても、計算時間自体は別の問題として残る。

## 一般的な実装上の含意

長文脈最適化では、最初の最大テンソルだけを削った後に何が次のピークになるかを再測定する必要がある。BPTは注意行列を消した後にFFN活性が支配的になる典型例である。

演算子単体ではなくテンソルの生存区間を見ることも重要である。注意→FFNのように全系列を待つ必要がない処理を同じタイル粒度で生産・消費すれば、算術量を変えなくてもピークメモリを下げられる。
