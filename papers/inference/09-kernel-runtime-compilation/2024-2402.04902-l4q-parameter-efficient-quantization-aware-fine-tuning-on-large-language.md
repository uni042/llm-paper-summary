# L4Q：低ランク適応と量子化認識学習を一体化し、推論時の高精度アダプタをなくす

## 概要

巨大言語モデル（LLM）の低ビット量子化は推論時の重み容量とメモリ帯域を減らすが、精度低下を起こす。量子化後のモデルを低ランク適応（LoRA）で微調整するQLoRAなどは学習メモリを節約できる一方、低精度の基盤重みと高精度のLoRAアダプタを別々に計算する構成では、推論時に追加の行列積が残る。量子化認識学習（QAT）は量子化誤差を学習中に補正できるが、全重みの勾配を保存すると大規模モデルでメモリ消費が重い。

L4Qは、**LoRAの更新を元の重みに合成した後で量子化する**ことにより、学習中に量子化パラメータとLoRA係数を共同最適化し、推論時には低ビットの重みだけを残す方式である。重み勾配を逆伝播中に一時的に計算してすぐ破棄する設計により、通常のQATに必要な大きな勾配保持費用を避ける。LLaMA-1 7Bの学習ピークメモリはLoRAの25.1GBに対してL4Qが25.4GB、通常QATは79.5GBである。一方、量子化済み重みを凍結して学習するQLoRAの7.9GBと比べるとL4Qの学習メモリは大きく、**「LoRA並み」と「QLoRA並み」は区別すべき**である。

推論時は高精度LoRAの別経路を使わないため、EXLLaMA2の4ビット重み用カーネルを利用した比較で、LLaMA-1 7BのFP16モデルに対して平均1.81倍の速度比を報告する。高精度LoRAを残した混合精度QLoRAは同じ比較で1.33倍である。ここでの倍率は特定カーネル・モデル・バッチ範囲での結果であり、あらゆるGPUや推論エンジンに適用できる保証ではない。

## 背景と問題設定

### 量子化と低ランク適応の別々の目的

量子化は重みを16ビットなどから4ビット、3ビットへ減らし、モデル容量や重み読み込み量を削減する。量子化後の重みは元の値を丸めて表すため誤差が入り、特に外れ値を含む分布で性能が落ちる。学習後量子化（PTQ）は主に事前学習済みの重みを固定したまま尺度などを調整する。QATは量子化の丸めを学習時に模擬し、尺度・ゼロ点・重みの更新を通じて誤差を減らすが、通常は大規模な勾配と最適化器状態を要する。

LoRAは基盤重み $W_0$ を固定し、小さな行列 $A$ と $B$ を学習して更新を $\alpha BA$ と表す。通常の推論は $Y=W_0X+\alpha BAX$ となり、基盤重みと低ランク経路の二つを評価する。QLoRAでは $W_0$ を低ビット化して学習メモリを大幅に減らせるが、高精度LoRAの経路が残る場合、推論時には完全に一つの低ビット行列演算へ統合できない。したがって、学習に最も小さいメモリを使う方式と、推論時に最も簡単な低ビット実行経路を持つ方式は一致しない。

QA-LoRAはLoRAの行列構造を量子化群に合わせて制約し、学習後に量子化パラメータへ吸収できるようにする。ただし制約した低ランク表現は、自由なLoRA更新に比べて表現能力を下げる可能性がある。L4Qはこの制約を避け、任意のLoRA更新を重みに合成してから量子化する。

### 素朴なQATとLoRAの併用が不十分な理由

重みを凍結したまま量子化尺度を学習する素朴なQAT-LoRAでは、尺度やゼロ点の勾配を得るために量子化重みの勾配を計算する必要がある。この大きな中間勾配を通常の逆伝播の流れで保持すると、LoRAが小さなパラメータだけを学習する利点が失われる。また、量子化した基盤重みとLoRA更新を別々に扱うと、量子化誤差に対するLoRAの最適化と量子化尺度の最適化が十分に結合しない。L4Qは**前向き計算での合成順序**と**逆伝播での勾配の寿命**を同時に変更する。

## 手法

### 1. LoRA更新を合成してから量子化

原著の式(7)は $W_{\mathrm{comb}}=W_0+\alpha BA$ と定義する。ここで $W_0$ は凍結した事前学習済み重み、$A,B$ は低ランク更新、$\alpha$ は尺度係数である。L4Qはこの合成済み重みを量子化し、量子化整数 $\widetilde{W}$ と尺度 $s$、オフセット $b$ を用いて近似重み $W_q$ を構成する。原著の式(8)〜(10)では、丸めと範囲制限を経た $W_q$ により $Y=W_qX$ と計算する。

重要なのは、学習後に高精度LoRAを別の行列積として追加する必要がないことである。量子化の対象が $W_0$ 単独ではなく $W_0+\alpha BA$ なので、低ランク更新が最終的な量子化重みの中へ入る。これにより推論用の線形層は単一の低ビット重み行列で実行できる。原著の「完全量子化」は線形層を量子化するという意味であり、非線形部分や最終出力層まで全て同じビット幅にするという意味ではない。

### 2. 局所的な重み勾配の計算と即時破棄

量子化尺度 $s$ やオフセット $b$ の更新には、量子化重み $W_q$ に対する損失の勾配が必要になる。L4Qは逆伝播中に $\partial L/\partial W_q=(\partial L/\partial Y)X^\top$ を局所的に計算し、その値を尺度・オフセットの勾配とLoRAの勾配の両方に使う。各層の計算が終わると大きな重み勾配を破棄するため、学習ステップをまたいで全重みの勾配や最適化器状態を保持しない。

丸め演算の微分はそのままでは扱えないので、原著は直通推定器（STE）を使い、量子化範囲内の勾配を近似的に伝播させる。LoRA係数の勾配も $W_q$ を経由して計算するため、LoRAの更新は量子化誤差を直接受け取る。尺度・オフセットの調整と低ランク更新が同じ量子化層の損失から導かれることが、PTQ後にLoRAを追加する二段手順との違いである。

この設計は「全ての勾配計算がなくなる」ことを意味しない。大きな勾配を一時的に生成して再利用し、保持期間を短くする。したがってメモリ節約と引き換えに、逆伝播中の勾配再計算や量子化処理の計算費用が増える可能性がある。原著付録の学習時間比較も、各ステップは重くなるが収束に必要なステップ数を減らすことで総学習時間を抑えるという解釈である。

### 3. 量子化尺度の初期化

QATの尺度初期化は、量子化後の学習が良い解へ到達するかに影響する。重み分布に外れ値があると、標準偏差に基づく狭い範囲は重要な重みを切り詰める。原著は、重みの最小値と最大値が量子化の表現範囲へ収まるよう、正負の最大絶対値を考慮して尺度を決める初期化を提案する。式(15)は量子化の正負端点に対する重み端点の比の最大値を尺度として採用する。

これにより初期段階での外れ値の切り詰めを抑え、学習中に重みが変化しても一定の余裕を持たせる。原著図3は初期化方式によるMMLU得点と切り詰め誤差の違いを比較し、単に量子化幅を狭めるのではなく、外れ値の保持と学習可能性を両立させる重要性を示す。低ビット化の精度は学習アルゴリズムだけでなく初期化にも左右される。

## 評価条件

原著はOpenLLaMA 3B、LLaMA-1の7B・13B・33B、LLaMA-2、LLaMA-3 8B、Mistral 7Bなどを評価する。主な微調整データはStanford Alpacaで、学習用約5万件と検証用約2千件を使用する。学習計算はNVIDIA A100 80GBを中心とし、比較手法はLoRA、通常QAT（LSQ）、GPTQ、OmniQuant、QLoRA、LoftQ、QA-LoRA、素朴なQAT-LoRAである。量子化群はLLaMA・Mistralで128、OpenLLaMAで64、LoRAランクは通常4、Mistralでは8とする。評価指標は常識質問応答（CSQA）とMMLUの正答率、学習ピークメモリ、学習時間、推論処理量である。

推論速度の付録Fでは、線形層を4ビット重み量子化し、最終出力層を除いてEXLLaMA2のカーネルを使用する。混合精度モデルでは高精度LoRA経路を別の行列演算として計算する。512トークンの生成を2000データ点で測り、バッチ1〜64を比較する。ここでの実験は特定の実装・モデルとカーネルに依存するため、他の量子化形式やGPUで同じ倍率になるとは限らない。

## 既存手法との差と適用条件

QLoRAは量子化済み重みと高精度アダプタを併用し、学習メモリの最小化に強い。QA-LoRAはアダプタを量子化パラメータへ統合できるが、LoRA構造に制約がある。L4Qは低ランク更新を自由に学習しつつ、その合成重みをQATで調整して、推論時の高精度経路を消す。素朴なQAT-LoRAと異なり、大きな重み勾配の保持を避ける。したがって、学習時のメモリ容量だけでなく、最終的に推論サーバへ載せる量子化モデルの精度とカーネル効率を重視する場合に有効である。

ただし4ビット重みの推論速度は実行カーネルに依存する。原著はEXLLaMA2の重みのみ量子化カーネルを使い、同じ4ビット重みで高精度LoRAの追加経路が残るかどうかを比較した。GGUFや別の量子化形式、異なるGPU、別のバッチ化実装へそのまま速度倍率を移植できるとは限らない。L4Qの学習手順を実装して得た重みを別の推論エンジンで使う場合は、量子化尺度・ゼロ点・群サイズとカーネルの互換性を検証する必要がある。

## 追加考察：学習費用と推論費用を同時に評価するための設計指針

量子化と微調整を同時に選ぶ際には、学習時の容量、学習時の時間、学習後の重み容量、推論時の演算経路、最終精度を分けて比較する必要がある。これらは互いに独立した評価軸であり、単一の「軽量さ」という指標にまとめられない。学習に使える装置が小さい場合は、最初から量子化した重みを固定する方法が有利になる。一方、十分な学習用メモリが確保でき、完成したモデルを何度も推論に使う場合には、学習中の容量をある程度増やしても、推論時の追加経路をなくすことが運用全体の費用削減につながりうる。

低ランク適応で追加される行列は、全体の重み数と比較すれば小さい。しかし小さな行列だから推論費用も必ず小さいわけではない。基盤の量子化行列積とは別に高精度の行列積を実行すると、異なる精度の演算を切り替える費用や、中間値を読み書きする費用が発生する。特に少数の要求を逐次処理する場面では、演算そのものより重みの転送や実行準備が効くことがある。原著が同じ量子化カーネルを用いて別経路の有無を比較しているのは、この実装上の差を切り分けるためである。

学習中に更新するものについても、重み全体を学習する方式と、低ランク係数だけを学習する方式を分けて考える。通常の量子化認識学習では、大きな重み配列に対応する勾配や最適化器状態を保存しなければならない。提案方式では基盤重みを固定し、実際に更新する低ランク係数と量子化尺度を小さく保つ。量子化尺度を更新するために必要な大きな勾配は、各層の逆伝播が進む間だけ生成して利用し、次の層へ進む前に破棄する。この「保存する状態」と「一時的に計算する値」を区別することが、ピークメモリの削減につながる。

この設計では、勾配の計算自体がなくなるわけではないため、学習時間が短くなるとは限らない。原著の総学習時間には収束までの学習回数の違いが含まれる。各手法の一回の学習更新にかかる時間、同じ精度へ到達するための更新回数、学習を終えた時点の精度は別々に測るべきである。単に学習時間の合計が近いという結果から、同じ回数だけ学習させても同じ費用だとは推論できない。

量子化尺度の初期化も無視できない。重みの大半が狭い範囲に集中していても、少数の大きな値が推論結果へ強く影響する場合がある。最小値と最大値を含めるように初期尺度を決めれば、重要な値が量子化範囲の外へ押し出される危険を抑えられる。しかし範囲を広げると、同じビット数で表せる値の間隔が粗くなるという別の交換関係がある。提案方式は初期化だけで最終精度を保証するのではなく、その後に尺度と低ランク係数を共同で調整することで、初期化による不利を減らすことを目指す。

推論へ配備するときには、学習時に用いた疑似量子化と、実際の整数重みカーネルの数値的な対応も確認する必要がある。量子化群の切り方、尺度の保存形式、オフセットの扱い、最終出力層を量子化するかどうかが異なれば、同じ学習済み係数から変換したモデルでも出力が変わりうる。特に学習時の量子化誤差を補正する方式では、完成した重みを別形式へ再量子化したときに精度が保たれるかを改めて測る必要がある。原著の速度結果は、指定された実行カーネルへ対応した量子化重みを使った条件に限定される。

低ビット化の利点は、モデルがメモリに収まるかどうかという容量の問題と、収まった後にどれだけ速く生成できるかという帯域の問題にも分けられる。容量不足で高精度モデルを実行できない場合、量子化によって実行可能になること自体が大きな価値になる。一方、高精度モデルも十分に収まる装置では、計算カーネルやバッチ数によっては速度差が小さくなる。原著のバッチ別測定で速度比が一定でないのは、このような資源律速の違いを示している。したがって実用上は、学習時の最大使用メモリと、推論時のバッチ別処理量を同じ条件で確認することが重要である。

## 評価結果を読む際の注意点

正答率の比較では、微調整していない基盤モデル、通常の低ランク微調整を施した高精度モデル、学習後に量子化したモデル、量子化を考慮して学習したモデルが同じ表に並ぶ。これらは学習条件も最終的な推論時の重み表現も異なるため、正答率の一点だけを取り出して方式全体の優劣を決めるべきではない。低ビットのまま推論できるか、高精度アダプタを追加で保持するか、学習時にどれだけメモリを必要としたかを合わせて評価することで、どの資源を節約しているのかが明らかになる。

特に、正答率が数値上わずかに上がった例を、量子化によって能力そのものが向上した証拠として一般化するのは危険である。微調整データに対する適応と量子化誤差の補正が同時に起こっているため、微調整前の基盤モデルとの比較と、同じ微調整を施した高精度モデルとの比較を分ける必要がある。原著は両方の列を設けているので、低ビット化による損失と、タスクへの適応による利得を読み分けられる。

また、実行時の速度を比較する際には、単一要求の速度と多数要求の合計処理量を区別する必要がある。少数の要求では重みの読み込みが支配的になりやすく、低ビット化による転送量の削減が大きく効く場合がある。多数の要求をまとめると、行列演算器の利用率や一時的な活性値のメモリ容量が重要になり、速度比は変化する。原著の表でバッチ数を増やすにつれて相対倍率が変化することは、この違いを理解するための手掛かりになる。

最後に、実用環境で採用する場合は、学習を実施する装置と推論を実施する装置が同じとは限らない。大容量の学習用装置で量子化認識微調整を完了し、完成した低ビット重みだけを小容量の推論装置へ配布する運用も考えられる。この場合、学習時のメモリ増加は一度だけ発生する費用であるのに対し、推論時の追加経路をなくす利点は各要求で繰り返し発生する。ただし最終的な費用対効果は、実際の利用回数、推論装置の性能、モデルの更新頻度によって変わるため、原著の単一実験だけで経済的な優位性を確定することはできない。

## 限界

第一に、L4QはQLoRAより学習メモリを多く使う。LLaMA-1 7Bの25.4GBという数値は、12GB級のGPUで原著と同じ学習条件をそのまま再現できることを意味しない。第二に、低ビットの精度改善はデータセット・モデル・量子化群サイズに依存し、全タスクで16ビットの性能を上回るわけではない。第三に、学習の各ステップで大きな勾配を一時生成するため、単純なLoRAより逆伝播の計算費用が増える場合がある。第四に、原著の「完全量子化」は線形層中心の定義であり、非線形部分や最終出力層は高精度のままである。

第五に、推論速度の実験はA100・EXLLaMA2・指定バッチ範囲であり、長文脈KVキャッシュや多数ユーザーの要求スケジューリングの影響を網羅しない。第六に、公式L4Qコードの公開先は確認した原著HTMLから特定できなかった。再現時は重みの合成順序、直通推定器、量子化尺度の初期化、勾配破棄の実装を一次論文の式に照らして検証する必要がある。
