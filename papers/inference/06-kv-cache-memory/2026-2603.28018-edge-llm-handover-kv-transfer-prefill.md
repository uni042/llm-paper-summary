# Low-Latency Edge LLM Handover via Joint KV Cache Transfer and Token Prefill

> Edge LLM移動時にプリフィル再計算するprefix長と残余KVのbackhaul転送を共同最適化し、複数UEの最悪ハンドオーバ停止時間を最小化する。
## 書誌情報
- **著者**: Seunghun Lee, Jihong Park, Ce Zheng, Hyuncheol Park
- **著者・所属**: KAIST; Singapore University of Technology and Design; Pengcheng Lab
- **公開**: arXiv
- **種別**: プレプリント
- **対象**: Edge LLM、KVキャッシュ転送、プリフィル再計算、ハンドオーバ、backhaul スケジューラ
- **実装**: 実システム実装ではなく解析モデルとシミュレーション。固定プリフィル長に対する最小キャッシュ-transfer delayと実現可能なrate スケジューラを閉形式・constructive policyで導出。
## 概要
モバイル端末がEdge LLMを持つ基地局間でハンドオーバすると、target側は過去トークンのKVキャッシュを復元するまで生成を再開できない。全トークンを送りプリフィル再計算するトークン-based HOは計算が重く、全KVをbackhaul転送するキャッシュ-based HOは帯域を圧迫する。本研究のjoint キャッシュ-トークン handover（ctHO）は、複数UEに共通のプリフィル長Lと残余KVのbackhaul rate スケジューラを共同最適化し、worst-user handover delayを最小化する。プリフィル遅延がLとともに増え、最小キャッシュ-transfer遅延が減る単調性から両者を均衡させ、固定Lでは最早deadline優先のconstructive スケジューラで最適値を達成する。Qwen2.5-7B-Instruct由来のKVサイズを用いたシミュレーションで、cHO比最大3.1倍、tHO比最大3.7倍の遅延削減を報告する。

共同キャッシュ・トークンハンドオーバ（joint キャッシュ-トークン handover; ctHO）は、全プリフィルまたは全KV転送という二つの極端な方式を一つの設計空間へ統合する。全端末に共通する接頭辞長Lまでをバッチプリフィル（バッチ プリフィル）で再計算し、それより後ろの残余部分だけをKVとして転送する。固定したLに対する最小の最悪ユーザ転送遅延を累積残余需要から閉形式で導き、その下界を実際に達成する構成的な帯域割当スケジューラを示す。さらに、Lを増やすほどプリフィル遅延は増え、KV転送遅延は減るという単調性を利用し、両者を均衡させるLが全体の最悪遅延を最小化することを示す。通信と計算を単なる二択ではなく連続的に交換可能な資源として扱う点が中心的貢献である。

代表結果として、worst-user HO delay vs cHOは代表点 R_bh=2 GbpsでcHO delayがctHOの3.1×超でcHO (all KV transfer)に対して最大3.1×削減相当。backhaul不足時に一部をプリフィルへ逃がす効果が大きい。
## 問題設定
エッジ大規模言語モデル（Edge LLM）を利用する移動端末が送信元基地局から移動先基地局へハンドオーバすると、自回帰デコード（autoregressive デコード）が依存する過去文脈のKVキャッシュ（KV キャッシュ）を移動先で復元するまで生成を再開できない。トークン方式ハンドオーバ（トークン-based handover; tHO）は過去トークンを送り移動先でプリフィル（プリフィル）してKVを再計算するため計算遅延が大きい。一方、キャッシュ方式ハンドオーバ（キャッシュ-based handover; cHO）はKVを直接バックホール（backhaul）転送して再計算を避けるが、大規模モデルではKVが数百MBからGB級となり共有回線がボトルネックになる。研究課題は、複数端末でハンドオーバ時刻と文脈長が異なる状況において、再計算とKV転送をどう分担・スケジュールすれば最悪ユーザのサービス中断時間を最小化できるかである。
## 新規性
共同キャッシュ・トークンハンドオーバ（joint キャッシュ-トークン handover; ctHO）は、全プリフィルまたは全KV転送という二つの極端な方式を一つの設計空間へ統合する。全端末に共通する接頭辞長Lまでをバッチプリフィル（バッチ プリフィル）で再計算し、それより後ろの残余部分だけをKVとして転送する。固定したLに対する最小の最悪ユーザ転送遅延を累積残余需要から閉形式で導き、その下界を実際に達成する構成的な帯域割当スケジューラを示す。さらに、Lを増やすほどプリフィル遅延は増え、KV転送遅延は減るという単調性を利用し、両者を均衡させるLが全体の最悪遅延を最小化することを示す。通信と計算を単なる二択ではなく連続的に交換可能な資源として扱う点が中心的貢献である。
## 手法
### 手法のあらまし
まずK台の端末をハンドオーバ時刻の順に並べ、端末iの文脈長C_iのうちLまでの共通接頭辞を移動先基地局でまとめてプリフィルし、Lを超える残余トークンに対応するKVだけを送信元基地局から転送する。次に、バックホール容量を1トークン当たりKV量で正規化してトークン毎秒の容量Rとして扱い、任意時刻に全端末へ割り当てる転送率の総和がRを超えないよう制約する。固定Lでは、先頭からk台までの残余KV需要と各端末のハンドオーバ時刻差から、どのスケジューリングでも下回れない最小転送遅延を導く。そのうえで、各端末に共通の最悪遅延から完了期限を設定し、現在転送可能な端末のうち期限が最も早い端末へバックホール全容量を割り当て、端末の到着または転送完了時だけ割当先を切り替える。この構成的スケジューラが解析下界を達成するため、固定Lで最適である。最後に、バッチプリフィル完了時間と最適KV転送完了時間の大きい方がサービス中断時間になるので、前者がLに対して非減少、後者が非増加という性質を使い、両者が交差する接頭辞長を選ぶ。交点が存在しない場合は全KV転送または全プリフィルの境界解を選ぶ。これにより、接頭辞分割、帯域割当、最悪遅延最小化までを一つの端から端までの最適化手順として解く。

### トークン・KV分割による共同ハンドオーバ
共通接頭辞長Lまでの履歴はトークンとして移動先へ渡し、複数端末をまとめてプリフィルしてKVを再生成する。一方、Lより後ろの履歴は送信元に既に存在するKVを直接バックホール転送する。L=0なら全KV転送のcHO、Lが最大文脈長なら全プリフィルのtHOとなるため、従来二方式を同じ変数Lで連続的に表現できる。重要なのは、再計算部分と転送部分が同じ過去文脈を重複して保持するのではなく、接頭辞と接尾辞として明確に分割される点である。このため状態の意味を変えずに計算量と通信量だけを交換でき、モデル品質を犠牲にする圧縮とは異なる最適化になる。また全端末で共通Lを使うことでバッチ処理の効率を保ちつつ、後段の帯域スケジューリングと結合可能な低次元の最適化問題へ落とし込む。

### 固定接頭辞長での最小KV転送遅延解析
各端末のハンドオーバ時刻までに利用できるバックホール時間と、その時点までに到着した端末群の累積残余KV需要を比較し、任意の帯域割当方策が満たすべき遅延下界を導く。これを全端末について最大化することで固定Lに対する最小可能転送遅延を閉形式化し、後段の接頭辞長最適化で繰り返し評価できる形にする。この解析は、ある端末だけを見るのではなく、それ以前に到着した端末の残余需要が共有回線をどれだけ占有するかを累積的に扱うため、複数端末競合を直接反映する。さらに、得られる式は単なる必要条件ではなく後述の構成的スケジューラで達成可能であり、固定Lに対する真の最適値として利用できる。その結果、連続時間の転送率関数を総当たり探索せずに、候補Lごとの通信側ボトルネックを計算できる。

### 期限優先の構成的バックホールスケジューラ
解析で得た共通の最悪遅延から各端末の転送完了期限を定め、転送可能になった端末のうち期限が最も早いものへ全バックホール容量を集中させる。新しい端末がハンドオーバする時点または現在端末の転送が完了した時点だけ割当を更新する。この方策が累積需要から得た下界を達成するため、単なるヒューリスティックではなく固定Lに対する最適スケジューリングとなる。帯域を複数端末へ常時細分化する必要がなく、一度に一端末へ全容量を与えるので実装上の動作も明確である。期限は各端末のハンドオーバ時刻に共通の最悪遅延を加えて定義されるため、早く到着した端末だけを優遇するのではなく、最悪ユーザ遅延という目的関数に整合する。到着イベントと完了イベントだけで切替える構造は、理論的達成可能性の証明と実際の転送制御を対応付ける役割を持つ。

### プリフィルと転送の均衡による接頭辞長選択
接頭辞長Lを増やすと移動先で再計算する量が増えるのでプリフィル遅延は単調に増える一方、直接送る残余KV量が減るので最適転送遅延は単調に減る。したがってサービス中断時間を決める二つの遅延の最大値は、原則として両者が均衡する点で最小になる。交点が範囲外ならL=0または最大文脈長の境界を選び、通信優先か計算優先かを資源条件に応じて自動的に決める。この単調性により、全ての接頭辞長と全ての帯域割当を組み合わせて探索する必要がなく、通信側と計算側の遅延曲線を比較するだけで全体最適を決められる。バックホールが遅い環境では再計算を増やす方向へ、プリフィル計算が遅い環境ではKV直接転送を増やす方向へ解が自然に移る。そのためctHOは固定的な中間案ではなく、利用可能資源に応じてtHOとcHOの間を適応的に選ぶ最適化方式として位置付けられる。

### 全体のデータ／制御の流れ
移動先基地局は対象端末群の共通接頭辞をバッチプリフィルし、送信元基地局は各端末がハンドオーバ可能になった時点から残余KVを共有バックホールへ流す。プリフィルとKV転送は並行して進み、両方が完了した時点でその端末のデコードを再開する。したがって片方だけを高速化しても他方が支配的なら中断時間は縮まらず、提案法は計算側と通信側の完了時刻を均衡させる最小最大（min-max）設計としてシステム全体を扱う。
## 評価条件
- **ハードウェア**: 実機Edge LLMクラスタではなくシミュレーション。LLMパラメータはQwen2.5-7B-Instruct: 28 Transformer 層、4 KV heads、head dimension 128、16-bit elements。これよりKV payloadは458,752 bit/トークン、3072-トークン contextで176MBと算出する。
- **ソフトウェア**: 解析・シミュレーション研究。プリフィル delayはp(L)=aL+bの線形modelで、default a=9.4267e-5、b=2.4e-3。比較は提案ctHO、全トークンをプリフィルするtHO（L=Cmax）、全KVをbackhaul転送するcHO（L=0）。コード公開は論文中に記載されない。
基本設定はK=4 UE、C_iをUnif[1024,Cmax]からsample、バッチ プリフィル cycle Tc=0.01s。source/target BSを300m離した1D line networkに置き、UE初期位置120〜130m、速度20m/s、150m境界でhandoverする。backhaul rate、プリフィル speed 1/a、Cmax、UE数Kをsweepしてworst-user LLM HO delayを比較する。追加評価ではhandover後G=1024 トークンのwireless streamingも含め、BS間距離をsweepする。wireless modelはreference SNR 10dB at 20m、path-loss exponent 3.5、帯域 2MHz、トークン size 12bitを用いる。
理論的global optimalityとネットワーク/LLMパラメータを用いた数値評価が中心で、実際のGPU プリフィル時間変動、KV serialization/DMA、backhaul protocol オーバーヘッド、異種model/BS、handover予測誤差などは実機検証されていない。sourceとtargetは同一LLM architecture/parametersを持つ前提で、hard handover中はデコードを停止する。
## 主要結果
ctHOはbackhaul帯域とプリフィル計算の一方だけへ依存せず、条件に応じて最適prefix長を変えるため、評価した全sweepでtHO/cHO以下のworst-user handover delayを達成した。代表的にはbackhaul 2GbpsでcHOの遅延がctHOの3.1倍超となり、論文全体でtHO比最大3.7倍の改善を報告する。UE数増加時にも差が拡大し、K=12ではctHO約0.95s、tHO約1.25s、cHO約3.35sである。

- worst-user HO delay vs cHO / 最大3.1×削減相当 (比較対象: cHO (all KV transfer); 条件: 代表点 R_bh=2 GbpsでcHO delayがctHOの3.1×超) — backhaul不足時に一部をプリフィルへ逃がす効果が大きい。

- worst-user HO delay vs tHO / 最大3.7×削減 (比較対象: tHO (all トークン プリフィル); 条件: シミュレーション sweep) — プリフィルがボトルネックの領域では残余KV直接転送との並行化が有効。

- K=12 multi-user delay / ctHO≈0.95s, tHO≈1.25s, cHO≈3.35s (比較対象: tHO/cHO; 条件: R_bh=4.5 Gbps) — UE増加で共有資源競合が強くなってもjoint allocationが優位で、特にcHOとの差が拡大する。

- 3072-トークン KV size / 176 MB (比較対象: Qwen2.5-7B-Instruct parameterization; 条件: 28 層, 4 KV heads, d_h=128, 16-bit K/V) — Edge handoverでKV直接転送が現実にbackhaul負荷となる規模を示す。

- HO vs no-HO total streaming / D_bs=500mでno-HOがctHOより2.1s超遅い (比較対象: source BSへ接続継続するno-HO; 条件: R_bh=4.5Gbps, G=1024 generated トークン) — handover自体の停止時間を払っても、無線link劣化が大きい距離ではtargetへ移る総遅延利得が上回る。

### 負の結果・境界条件
- backhaulが十分高速になるとcHOはctHOへ近づき、プリフィルが十分高速ならtHO側の不利も縮むため、joint方式の利得は資源の中間領域で大きい。no-HOとの比較ではBS間距離375m未満でhandover停止時間がないno-HOの方が総遅延が小さい。提案はhard HOを前提にし、handover中もsource デコードを継続するsoft HOは未対応。

### 結果の読み方
本質はKV キャッシュを単なる転送対象ではなく『同じ状態をトークンから再計算可能なデータ』として扱い、通信量と計算量を交換可能にした点にある。プリフィルとtransferのmaxが停止時間を決めるため、両者を等しくする境界がmin-max最適となる。
## 品質への影響
contextに対応する同一KV状態をプリフィルまたは直接転送で再構築するため、compression/量子化のような近似品質劣化は導入しない。論文はCacheGen等のKV圧縮を直交技術として位置付け、組み合わせればさらに転送遅延を減らせるとしている。
## 既存研究との差
tHOは過去トークンを全てtargetへ送りプリフィルでKVを再計算するためbackhaul payloadは小さいがcompute-heavy、cHOは全KVを直接転送してcomputeを避けるがcommunication-heavyである。ctHOは両者をLの両端として包含し、prefixをプリフィル・suffix KVを転送して並行実行する。CacheGen等はKV payload自体を圧縮するのに対し、ctHOはどの部分を再計算しどの部分を送るかとmulti-UE backhaul スケジューラを最適化するため直交する。通常のKV migration研究がキャッシュを状態として移すのに対し、本研究はトークン historyからの再生成可能性を通信-計算tradeoffへ明示的に利用する。
## 限界
評価は解析modelとシミュレーションのみで、実Edge GPU・backhaul上のエンドツーエンド prototypeはない。source/target BSが同一LLM architecture/parametersを持ち、トークン送信時間はKV transfer/プリフィルより無視でき、プリフィル delayを線形p(L)=aL+bで近似できる前提を置く。全UEに共通prefix長Lを使うバッチ プリフィルのため、UEごとに異なる計算/通信境界を最適化する一般形は扱わない。handover時刻とcontext長をsourceが既知とし、hard HO中はstreamingを停止する。soft HO、予測誤差、heterogeneous accelerators、実network jitter、KV serialization/compression オーバーヘッドは今後の課題である。
## 実装状態

## 研究上の位置づけ
KV キャッシュ メモリ系統とEdge/distributed inference系統の接点に位置する。特にdisaggregated servingで議論されるKV transfer対recomputeの判断を、モバイルhandoverと共有backhaulのmin-max スケジューラへ拡張した研究と見なせる。SSD/CPU オフロードとは階層が異なるが、『高価な状態を移動するか再計算するか』という共通の設計原理をネットワーク越しKVへ適用している。
