# Reducing Transformer Key-Value Cache Size with Cross-Layer Attention

> MQA/GQAのKV共有を層方向へ拡張し、隣接層でKV活性を再利用してKVキャッシュを追加で約2倍削減する注意アーキテクチャ。
## 書誌情報
- **著者**: William Brandon, Mayank Mishra, Aniruddha Nrusimha, Rameswar Panda, Jonathan Ragan-Kelley
- **著者・所属**: MIT CSAIL; MIT-IBM Watson AI Lab
- **公開**: arXiv
- **種別**: Preprint
- **対象**: KV キャッシュ メモリ、cross-層 attention、MQA、GQA、long-context serving
- **実装**: Transformerの一部層からK/V projectionを除き、前層で生成したKV活性を再利用するアーキテクチャ変更。標準tensor parallelismと互換。
## 概要
自己回帰LLMのKVキャッシュは系列長とバッチサイズに比例して増え、長文サービングのメモリ制約になる。MQA/GQAは同一層内で複数query headがKV headを共有するが、Cross-層 Attention (CLA) はさらに隣接層間でKV活性を共有する。KV投影を一部層だけで計算し、後続層は直前のKVを再利用することで、CLA2ならKVキャッシュを約2分の1にする。1B/3BモデルをSlimPajamaで事前学習した結果、MQA+CLA2は通常MQAに対してKVキャッシュを2倍削減しつつperplexity悪化を1%未満に抑え、同一メモリ予算では小さいhead dimensionのMQAより良いperplexityを示した。

層間注意（Cross-層 Attention: CLA）は、複数問い合わせ注意やグループ問い合わせ注意が同一層内で鍵・値頭を共有する考えを、層方向へ拡張する。一部の層だけが鍵・値射影を持ち、その後の隣接層は新しい鍵・値を生成せず、共有元の層が同じ語位置について生成した鍵・値活性を再利用する。共有係数が2なら2層につき1組、3なら3層につき1組のKVキャッシュを保持するため、保存容量を概ね共有係数に反比例して減らせる。この層方向の共有は、頭方向の共有である多頭注意（Multi-Head Attention: MHA）、複数問い合わせ注意、グループ問い合わせ注意と直交しており併用できる。論文の探索では特に複数問い合わせ注意と2層共有を組み合わせた構成が、同じKVメモリ予算で従来構成より低い困惑度を得る精度・容量のPareto境界を形成した。

代表結果として、1B KV キャッシュ削減とvalidation perplexityは1B、best learning rateでH128-MQAに対して10240→5120 bytes/トークン (2×削減), 12.39→12.43。KV容量を半減してもperplexity悪化は0.04 point。
## 問題設定
自己回帰型の大規模言語モデルでは、次の語を一つ生成するたびに過去の全位置へ注意を向ける。その再計算を避けるため、各層で過去の鍵と値をKVキャッシュとして保存するが、必要容量は系列長、同時処理要求数、鍵・値の頭数、層数にほぼ比例する。長文と大きなバッチを同時に扱うサービングでは、この保存領域がモデル重みとは別の大きなメモリ消費となり、GPUに載せられる要求数や保持できる文脈長を制限する。複数問い合わせ頭で鍵・値頭を共有する複数問い合わせ注意（Multi-Query Attention: MQA）やグループ問い合わせ注意（Grouped-Query Attention: GQA）は頭数方向の重複を減らすが、各Transformer層は依然として独自の鍵・値を生成して保存するため、層数方向の重複は残る。量子化や重要でない語位置の削除は学習後の別方向の圧縮であり、鍵・値を持つ層そのものの数は減らさない。そこで、通常の注意計算の形を大きく崩さず、隣接層で鍵・値を共有して層方向の保存量を減らし、精度低下を小さく抑える設計が必要になる。
## 新規性
層間注意（Cross-層 Attention: CLA）は、複数問い合わせ注意やグループ問い合わせ注意が同一層内で鍵・値頭を共有する考えを、層方向へ拡張する。一部の層だけが鍵・値射影を持ち、その後の隣接層は新しい鍵・値を生成せず、共有元の層が同じ語位置について生成した鍵・値活性を再利用する。共有係数が2なら2層につき1組、3なら3層につき1組のKVキャッシュを保持するため、保存容量を概ね共有係数に反比例して減らせる。この層方向の共有は、頭方向の共有である多頭注意（Multi-Head Attention: MHA）、複数問い合わせ注意、グループ問い合わせ注意と直交しており併用できる。論文の探索では特に複数問い合わせ注意と2層共有を組み合わせた構成が、同じKVメモリ予算で従来構成より低い困惑度を得る精度・容量のPareto境界を形成した。
## 手法
### 手法のあらまし
処理はモデル設計、学習、推論の三段階で一貫している。まずモデル設計時に、連続する層を共有係数に応じて群に分け、各群の先頭など所定の層だけへ鍵射影と値射影を残す。共有先の層には問い合わせ射影、注意演算、出力射影、正規化、フィードフォワード網を残すが、独自の鍵・値射影は置かない。次に事前学習では、鍵・値生成層が入力隠れ状態から問い合わせ・鍵・値を作り、共有層は自身の隠れ状態から問い合わせだけを作って、同じ群の共有元層が生成した鍵・値へ注意を計算する。この構造を学習開始時から使うため、共有された表現にモデルが適応できる。推論時には語位置ごとに鍵・値生成層の出力だけをKVキャッシュへ追加し、共有層では新規KVを保存せず既存の共有キャッシュを読み出す。2層共有なら保存対象層数が半分になるため、同じ頭寸法ならKV bytes/トークンもほぼ半減する。空いたメモリはより長い系列、より大きい同時バッチ、長期間保持する接頭辞キャッシュへ振り向けられる。一方、共有層も注意演算時には同じKVを主記憶から読み出すので、一回の復号段階における注意本体の読み出し帯域は直接半減しない。最終出力は通常のTransformerと同じ隠れ状態系列で、後続層や語彙出力部へそのまま渡される。

### 層間KV共有
入力は、ある鍵・値生成層の隠れ状態と、その直後に続く共有層の隠れ状態である。生成層は通常どおり問い合わせ、鍵、値を線形射影で作り、その鍵・値を語位置ごとにKVキャッシュへ保存する。共有層は自分専用の問い合わせを生成する一方、新しい鍵・値射影を実行せず、生成層が作った鍵・値を注意の相手として再利用する。したがって各層は異なる問い合わせを持ち、層ごとの処理内容を保ちながら、保存すべき鍵・値だけを共通化できる。推論時の出力は各共有層で通常の注意出力として計算され、その後の出力射影、残差接続、正規化、フィードフォワード網へ渡る。キャッシュ側では共有元の一組だけを保持すればよく、層数方向の重複が除かれる。これは語位置を捨てる方式ではないため、各共有層は過去の全位置へ引き続き注意できる。

### 共有係数による設計空間
共有係数は一組の鍵・値を何層で再利用するかを表す。2層共有では隣接2層につき一組、3層共有では3層につき一組のKVキャッシュを持つ。入力となる設計条件は総層数と希望するKV容量であり、共有係数を大きくするほど保存対象層数は減るが、異なる層が同じ鍵・値表現に依存するため表現上の制約も強くなる。論文は2、3、4層共有を比較し、さらに先頭・末尾層だけ独立させる配置や、独立KV層を前半または後半へ偏らせる非均一配置も試した。その結果、均一な2層共有が最も安定した精度・メモリ交換を示した。3層・4層共有も通常の複数問い合わせ注意より良いPareto点を作るが、同じKV容量の2層共有より困惑度が高い。出力は、目標容量と精度に応じて選べる具体的な層共有配置である。

### 頭方向共有との直交的な組合せ
入力は層方向の共有係数に加えて、各注意層で何個の鍵・値頭を持つかという頭方向の設計である。複数問い合わせ注意は全問い合わせ頭が一つの鍵・値頭を共有し、グループ問い合わせ注意は複数群ごとに一つを共有する。層間注意はその上で、隣接層同士が同じ鍵・値活性を使うため、二つの削減軸を独立に組み合わせられる。実験では複数問い合わせ注意＋2層共有が最も堅牢で、通常の複数問い合わせ注意と同じ頭寸法ならKV容量を2倍削減できる。逆に同じKV容量を固定する場合、共有で節約した分をより大きい頭寸法へ使えるため、小さい頭寸法だけで容量を削った通常MQAより低い困惑度を得られる。つまり出力は単なる圧縮率ではなく、一定メモリ予算で表現能力を再配分する設計自由度である。

### 学習・並列実行上の影響
層間注意は鍵・値射影そのものを一部層から除くため、入力モデルのパラメータ数と前向き・後ろ向き計算量もわずかに減る。テンソル並列では通常の重み分割と両立し、特別な通信を追加せずに各共有群の射影を分割できる。一方、パイプライン並列では同じKVを共有する層を異なる段階へ分けると、共有KV活性を段階間で送る必要が生じるため、共有層を同じパイプライン段階へ置く方が自然である。推論時には保存容量が減るが、各共有層が注意を計算するたび同じKVを再度読み出すので、注意本体のメモリ帯域消費や単一復号段階の中核遅延を直接減らす方式ではない。主なシステム効果は、空いたGPUメモリによってより長い文脈や大きいバッチを収容できることにある。

### 全体のデータ／制御の流れ
新規モデルの注意アーキテクチャとして事前学習開始時から層間注意を導入する。推論ランタイムは鍵・値生成層だけにKVキャッシュ領域を割り当て、共有層の注意演算へ同じキャッシュ参照を渡す。2層共有を複数問い合わせ注意と組み合わせる構成が保守的な推奨案であり、既存MQAと近い精度を保ちながら保存容量を半減する。
## 評価条件
- **ハードウェア**: NVIDIA H100 GPUs。
- **ソフトウェア**: PyTorch、BF16 mixed precision、FP32 gradient all-reduce/accumulation、AdamW。
- **比較対象**: MHA、GQA4、GQA2、MQA with multiple head dimensions、CLA3/CLA4、non-uniform CLA2
Llama-like pre-norm/SwiGLU/RoPEモデルをSlimPajamaからscratchで学習。1Bモデルは20層・hidden 2048・30B トークン、3Bモデルは32層・hidden 3072・100B トークン、sequence length 2048。1BではMHA/GQA/MQA、MQA+CLA2、GQA+CLA2、CLA3/4、非均一共有を広く比較し、learning-rate sweepも実施。3BでもMQAとMQA+CLA2をhead dimension 128/64/32で比較。held-out SlimPajama validation perplexity、Wikitext perplexity、LM Eval Harnessの7 downstream ベンチマーク、16-bit KV bytes/トークンを評価。
事前学習時にattention architectureを変更してKVキャッシュ容量とモデル精度の交換関係を評価する。既存学習済みモデルへのpost-training変換やエンドツーエンド serving スループットは対象外。
## 主要結果
CLA2はMQAのKVキャッシュを層方向にさらに2倍削減しながら、1B/3Bの双方でperplexity悪化を小さく保つ。1Bのlearning-rate調整後ではH128-MQAの10240 bytes/トークン・validation perplexity 12.39に対し、H128-MQA-CLA2は5120 bytes/トークンで12.43、Wikitextでは19.30対19.29だった。同じ5120 bytes/トークンのH64-MQAはvalidation 12.74、Wikitext 20.00で、CLA2が明確に良い。3BでもH128-MQA-CLA2は通常H128-MQAの半分の8192 bytes/トークンでvalidation 9.34対9.52、Wikitext 13.25対13.63とむしろ改善した。別3B実験のH64-MQA-CLA2は通常H64-MQAの半分の4096 bytes/トークンでWikitext 12.99対12.94と差0.05に留まった。

- 1B KV キャッシュ削減とvalidation perplexity / 10240→5120 bytes/トークン (2×削減), 12.39→12.43 (比較対象: H128-MQA; 条件: 1B、best learning rate) — KV容量を半減してもperplexity悪化は0.04 point。

- 1B同一KV予算でのperplexity / 12.74→12.43 validation、20.00→19.29 Wikitext (比較対象: H64-MQA (5120 bytes/トークン); 条件: H128-MQA-CLA2も5120 bytes/トークン) — 層共有で節約した容量を大きいhead dimensionへ使う方が精度/メモリ交換に有利。

- 3B H128 CLA2 / 16384→8192 bytes/トークン、validation 9.52→9.34、Wikitext 13.63→13.25 (比較対象: H128-MQA; 条件: 3B、100B training トークン) — 半分のKV容量でperplexityが悪化せず改善するケースも確認。

- 3B H64 CLA2 / 8192→4096 bytes/トークン、Wikitext 12.94→12.99 (比較対象: H64-MQA; 条件: second 3B experiment) — 半分のKV容量でperplexity差は0.05 point。

- CLA sharing factor ablation / CLA2が最良 (比較対象: CLA3/CLA4/non-uniform sharing; 条件: 1B design-space exploration) — より大きな共有率より隣接2層共有が安定したPareto改善を示す。

### 負の結果・境界条件
- CLA3/CLA4は通常MQAよりPareto改善するが同一KV容量のCLA2よりperplexityが悪い。非均一な共有配置もuniform CLA2より悪い。CLAは各attention層で共有KVを再読込するためcore attentionのメモリ 帯域/遅延を直接削減しない。エンドツーエンド長文サービングの速度改善は未評価でfuture workとされる。3B第2実験は別クラスタ・別software stack・別data orderで再学習しており、第1実験と数値を直接比較しにくい。

### 結果の読み方
KV head数だけでなく『独立KVを持つ層数』も精度を大きく損なわず削減できる。CLA2とMQAを組み合わせると、同じhead dimensionのまま容量を半減するか、同じ容量でhead dimensionを大きくして精度を上げる選択肢が得られる。
## 品質への影響
1B/3Bで通常MQA比2倍のKV削減に対するperplexity変化は概ね1%未満で、downstream 7タスクでは各モデルが一貫して勝敗する傾向はなく、おおむね近い性能を示す。
## 既存研究との差
MQA/GQAは同一層内で複数query headがKV headを共有し、KVキャッシュのhead次元を削減する。CLAはこれと直交して隣接層がKV活性を共有し、層次元を削減する。KVQuant等の量子化は保存bit数、H2O/Scissorhands等の追い出しはトークン数、CacheGenは転送表現を削減するのに対し、CLAはアーキテクチャ自体の独立KV projection数を減らす。FlashAttentionは単一passのIOを最適化するが、CLAはpass間に永続するKV保存容量を狙う。
## 限界
CLAは学習済みモデルへそのまま適用するpost-training圧縮ではなく、K/V projection配置を変えたモデルを事前学習する必要がある。共有KVは各attention層で再度メモリから読むため、KVキャッシュ保存容量は減ってもcore attentionの帯域や1 step 遅延を直接減らさない。長文・大バッチのエンドツーエンド serving スループット/遅延は論文では未評価でfuture work。主要規模は1B/3Bであり、数十B〜数百Bモデルへのスケーリングは未実証。パイプライン parallelismでは共有層を同一stageへ置くかKVをstage間通信する必要がある。
## 実装状態
PyTorchで1B/3Bモデルをscratch学習して実証。CLAはattention blockから一部K/V projectionを除き、前層KVを参照する比較的単純なアーキテクチャ変更として実装できる。論文本文で独立した公開コードURLは確認できない。
## 研究上の位置づけ
KVキャッシュ圧縮のうち、量子化・トークン 追い出し・オフロードではなくモデル設計時の構造共有に属する。MQA/GQAで既にhead方向の冗長性を削った後にも層方向の冗長性が残ることを示し、特にMQA+CLA2を保守的な設計レシピとして提示する。将来の長文サービングでは、節約したKV容量をバッチ拡大や長期キャッシュ persistenceへ転換できる可能性がある。
