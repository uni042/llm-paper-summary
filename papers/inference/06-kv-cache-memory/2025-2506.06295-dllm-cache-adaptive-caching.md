# dLLM-Cache: Accelerating Diffusion Large Language Models with Adaptive Caching

> プロンプトの長間隔キャッシュとV類似度による応答トークン選択更新で、拡散LLM推論の再計算を学習なしに削減する。
## 書誌情報
- **著者**: Zhiyuan Liu, Yicun Yang, Yaojie Zhang, Junjie Chen, Chang Zou, Qingyan Wei, Shaobo Wang, Yichen Zhu, Linfeng Zhang
- **著者・所属**: 一次資料記載の著者情報に従う。
- **公開**: ICML 2026
- **種別**: 国際会議論文
- **対象**: 拡散LLM、推論高速化、適応キャッシュ、KVキャッシュ、特徴再利用
- **実装**: 公式PyTorch実装が公開され、LLaDA、Dream、LLaDA-V、MMaDAをサポートする。
## 概要
dLLM-キャッシュは、双方向注意のため通常のKVキャッシュをそのまま使えない拡散大規模言語モデルに対し、静的なプロンプトと部分的に変化する応答の時間的冗長性を別々に利用する学習不要の適応キャッシュ方式である。プロンプト特徴は長い間隔で再計算し、応答特徴は短い間隔で全更新しつつ、中間ステップではValueベクトルのコサイン類似度を使うV-verifyで変化の大きいトークンだけを再計算する。LLaDA 8BとDream 7BをRTX 4090で評価し、LongBench-HotpotQAで最大9.1倍のFLOPs削減を報告する。

dLLM-キャッシュは冗長性を一様に扱わず、プロンプトと応答で時間スケールを分離する。プロンプト側は長間隔でK/V・Attention Output・FFN Outputを更新し、その間は再利用する。応答側はより短い間隔で全特徴を更新し、中間段階ではValueベクトルの変化を軽量に測定して変化の大きいトークンだけを完全再計算するV-verifyを用いる。Key/ValueだけでなくAttention OutputとFFN Outputまでキャッシュ対象にするため、Transformer層内の後段計算も省略できる。学習やモデル重み変更を必要としない。
## 問題設定
拡散大規模言語モデルは双方向注意でマスク列を反復的に復元するため、長さNの生成で各デノイズ段階に全トークンの注意・FFNを再計算する。実用上N回規模の反復が必要になり、著者は全体計算量をO(N^3)と整理する。自己回帰モデルの因果注意では過去トークンのKey/Valueを固定して再利用できるが、拡散モデルでは全トークンが互いに参照し、応答トークンも段階ごとに変化するため通常のKVキャッシュを直接適用できない。一方、プロンプトは全段階で同一で、応答も隣接段階では大半の特徴がほぼ変化しないため、毎回すべて再計算するのは冗長である。
## 新規性
dLLM-キャッシュは冗長性を一様に扱わず、プロンプトと応答で時間スケールを分離する。プロンプト側は長間隔でK/V・Attention Output・FFN Outputを更新し、その間は再利用する。応答側はより短い間隔で全特徴を更新し、中間段階ではValueベクトルの変化を軽量に測定して変化の大きいトークンだけを完全再計算するV-verifyを用いる。Key/ValueだけでなくAttention OutputとFFN Outputまでキャッシュ対象にするため、Transformer層内の後段計算も省略できる。学習やモデル重み変更を必要としない。
## 手法
### 手法のあらまし
入力は通常のプロンプトcと、生成長Lだけ[MASK]で初期化した応答y(K)である。最初のデノイズ段階k=Kでは通常のdLLM順伝播を全トークン・全層に実行し、各Transformer層lのK、V、Attention Output、FFN Outputをプロンプト部分と応答部分へ分けてPrompt キャッシュ CpとResponse キャッシュ Crへ保存する。次の段階から各層へ入るたび、まずプロンプト側についてkがKpの更新境界なら4種類の特徴を再計算してCpを置換し、境界でなければCpの特徴をそのまま採用する。次に応答側についてkがKrの更新境界なら全応答トークンの4特徴を再計算してCrを同期する。境界でない場合はV-verifyへ進み、全応答トークンについて現在のValue投影Vnewだけを計算し、直前に保存したValueとのコサイン類似度をトークンごとに算出する。類似度が低い順にfloor(rho×応答長)個を変化の大きい集合として選び、その集合だけKey、Attention Output、FFN Outputを現在入力から再計算する。Vnewは選択判定のため全トークン分を既に計算済みなのでCrのValue全体を置換し、他の3特徴は選択位置だけ新値をscatterして非選択位置は旧キャッシュを保持する。こうして得たプロンプト側の再利用/更新特徴と応答側の新旧混合特徴を結合して層出力を作り、次層へ渡す。全層終了後、元のdLLMの予測分布と遷移関数Sで一部マスクを復元してy(k-1)を作る。この処理をk=0まで反復し、定期的なKp/Kr全更新で近似誤差をリセットしながら、間の多数ステップで再計算を省略して最終応答y(0)を出力する。

### 長間隔プロンプトキャッシュ
入力はデノイズ中に不変なプロンプトトークンで、出力は各Transformer層で利用するプロンプト側K、V、Attention Output、FFN Outputである。初回に4特徴を全計算してPrompt キャッシュへ保存し、以後はk mod Kpが更新境界のときだけ現在の層入力から再計算してキャッシュを置換する。境界以外では保存値を注意計算とFFN後段へ直接供給する。プロンプト自体は変化しなくても応答との双方向相互作用で内部特徴は完全不変ではないため永久固定せず、長い周期で同期し直す。これにより長いプロンプトほど毎段階繰り返される固定領域の射影・注意・FFN計算をまとめて除去する。

### 短間隔応答全更新
入力は各段階で部分的に復元される応答トークン列と現在層入力、出力はResponse キャッシュの同期済みK、V、Attention Output、FFN Outputである。応答はプロンプトより速く変化するため、k mod Krが更新境界に達した段階では選択近似を使わず全応答トークンを通常どおり再計算し、4種類のキャッシュを現在状態へ合わせる。この全更新が部分更新期間の開始点となり、過去の近似特徴が何十段階も無制限に残ることを防ぐ。Krを短くすれば品質側、長くすれば計算削減側へ寄せられ、プロンプト用Kpとは独立に応答の変化速度へ合わせられる。

### V-verify適応部分更新
入力は全応答トークンの現在Value投影とResponse キャッシュに保存されたValue、更新率rhoである。まず各トークンについて新旧Valueのコサイン類似度を求め、類似度が最も低いfloor(rho×応答長)個を変化の大きい集合として選ぶ。著者の隣接段階分析ではValue変化が後続のAttention OutputとFFN Output変化と強く対応するため、重い後段演算を実行する前のValueを選択指標にできる。選択トークンだけKey、Attention Output、FFN Outputを再計算して該当位置へ書き戻し、非選択トークンは旧値を再利用する。一方Valueは選別のため全トークン分を計算済みなので全位置を新値へ更新する。既定評価rho=0.25では約4分の1だけを後段再計算し、変化の大きい場所へ計算予算を集中する。

### 層内特徴キャッシュと混合順伝播
各層はPrompt キャッシュとResponse キャッシュからK、VだけでなくAttention OutputとFFN Outputまで受け取り、更新対象位置の新特徴と非更新位置の保存特徴を同じ系列位置へ組み戻す。通常のKVキャッシュのように過去位置を完全固定するのではなく、プロンプト/応答、更新境界/中間段階、選択/非選択という三段階の条件で特徴の鮮度を決める。混合特徴から現在層の出力を構成して次層へ渡し、最終層後は元モデルのデノイズ遷移規則を変更せず次のマスク状態を生成する。したがってキャッシュ制御はモデル重みや学習目的を変更せず推論データパスだけへ挿入でき、定期全更新により近似誤差を抑えながら層内の注意・FFN再計算を広く省略する。

### 全体のデータ／制御の流れ
モデル重みや学習手順を変更せず推論順伝播へ二階層のキャッシュ管理を挿入する。Prompt キャッシュは静的領域を粗い周期Kpで、Response キャッシュは動的領域を細かい周期Krで同期し、Krの間はV-verifyがrho割合のトークンだけを再計算対象へ絞る。各デノイズ段階の出力は元のdLLM遷移関数へ渡されるため生成規則そのものは維持される。Kp、Kr、rhoが速度・メモリ・近似誤差の主要制御点であり、全更新を周期的に挟むことで部分更新による誤差蓄積を制限する。
## 評価条件
- **ハードウェア**: TPSとFLOPsの主要測定は単一NVIDIA RTX 4090 GPUで実施。
- **ソフトウェア**: LLaDA 8BおよびDream 7BのBase/Instruct版を対象に、公式推論構成へdLLM-キャッシュを組み込む。公式PyTorch実装が公開されている。
LLaDA 8BとDream 7Bを複数の数学・科学・一般知識・コード・長文ベンチマークで標準推論と比較する。主要指標はトークン Per Second、平均FLOPs/トークン、各ベンチマークのタスクスコア。全モデルで適応更新率rho=0.25を用い、プロンプト更新間隔Kpと応答全更新間隔Krはモデル・評価設定に応じて指定する。追加分析ではキャッシュ間隔、更新率、長いプロンプト、異なる応答長、メモリ増加と速度・品質の関係を調べる。
代表的なマスク拡散LLMであるLLaDA 8BとDream 7BのBase/Instruct、および単一RTX 4090上の推論が中心。学習不要キャッシュの計算削減と品質保持を直接検証する一方、大規模バッチのオンラインサービング、複数GPU/複数ノード、異種アクセラレータ、長期運用時のスケジューリングやメモリ競合は主要評価範囲外。
## 主要結果
dLLM-キャッシュはLLaDA 8BとDream 7Bで標準推論の反復再計算を大幅に削減し、長い静的プロンプトで特に効果が大きい。LLaDAのLongBench-HotpotQAでは最大9.1倍のFLOPs削減を報告する。LLaDAの代表例ではGSM8K BaseでTPS 7.32から23.19へ3.17倍、FLOPs 16.12Tから3.21Tへ5.02倍削減し、スコアは69.06から70.66。GPQA InstructではTPS 5.33から28.01へ5.26倍、FLOPs 22.07Tから2.73Tへ8.08倍削減し、スコア29.01を維持した。速度向上はプロンプトの長間隔再利用と、応答の25%だけを優先更新する適応部分更新の双方から得られる。

- LongBench-HotpotQA FLOPs削減 / 最大9.1倍 (比較対象: 標準dLLM推論; 条件: 長い静的プロンプトを含むLongBench-HotpotQA) — プロンプト長が大きいほど長間隔Prompt キャッシュの再利用対象が増え、計算削減が拡大する。

- LLaDA Base GSM8K TPS / 23.19 トークン/s、3.17倍 (比較対象: 7.32 トークン/s; 条件: 単一RTX 4090、rho=0.25) — タスクスコアを69.06から70.66へ維持・微増しながら実測スループットを改善する。

- LLaDA Base GSM8K FLOPs / 3.21T、5.02倍削減 (比較対象: 16.12T; 条件: 単一RTX 4090) — 実測TPS向上より計算量削減が大きく、キャッシュ管理やメモリアクセス等の非FLOPs費用が残ることを示す。

- LLaDA Instruct GPQA TPS / 28.01 トークン/s、5.26倍 (比較対象: 5.33 トークン/s; 条件: 単一RTX 4090) — 高難度QAでも大きな速度向上を得る。

- LLaDA Instruct GPQA FLOPs / 2.73T、8.08倍削減 (比較対象: 22.07T; 条件: スコア29.01を維持) — 近似キャッシュでもこの設定では測定タスク品質を落とさず計算を大幅削減した。

### 負の結果・境界条件
- FLOPs削減倍率は実測TPS倍率より大きく、削減した演算量がそのまま端から端までの速度向上にはならない。方式はKp、Kr、rhoに依存し、応答を長く再利用しすぎる、または更新率を下げすぎると近似誤差と品質低下の危険が増えるため、定期的な全更新を必要とする。主要実験は単一RTX 4090であり、オンライン多要求サービングのメモリ帯域・キャッシュ容量競合は直接評価していない。

### 結果の読み方
拡散LLMの反復推論では、全トークンを毎段階同じ精度で更新する必要はない。静的プロンプトは粗い時間粒度、応答は細かい時間粒度、さらに応答内では変化の大きいトークンだけを選ぶ階層的な更新粒度が有効である。
## 品質への影響
LLaDA/Dreamの複数ベンチマークで標準推論とタスクスコアを比較し、最大計算削減時にも競争力のある品質を維持すると報告する。GSM8K Baseは69.06から70.66、GPQA Instructは29.01から29.01で、少なくともこれらの代表点では品質悪化は観測されない。ただしキャッシュは近似であり、全入力分布に対する出力同一性を保証する方式ではない。
## 既存研究との差
自己回帰LLMの通常KVキャッシュは因果注意によって過去K/Vが不変であることを利用するが、dLLM-キャッシュは双方向注意下の近似的な時間安定性を利用する。dKV-キャッシュは復号済みトークンの遅延KV再利用を中心とするのに対し、本方式はプロンプト/応答を分け、K/Vに加えてAttention OutputとFFN Outputも再利用する。Fast-dLLMはブロック単位の近似KVキャッシュと信頼度ベース並列復号を組み合わせる一方、dLLM-キャッシュは応答トークンのValue変化量を直接使う細粒度な選択更新を中心とする。
## 限界
キャッシュ再利用は厳密等価ではなく近似であり、Kp、Kr、rhoの選択によって速度と品質の交換条件が生じる。V-verifyでも全応答トークンのValue投影は必要なので、更新率を下げてもその費用は残る。主要評価はLLaDA 8BとDream 7B、単一RTX 4090が中心で、より大規模な拡散LLM、多GPU、連続バッチ、多利用者サービング、メモリ容量競合での挙動は未検証。長いキャッシュ間隔で特徴が陳腐化する入力分布への頑健性も追加検証余地がある。
## 実装状態
公式GitHub maomaocun/dLLM-キャッシュでPyTorch実装を公開。LLaDA、Dreamに加えLLaDA-V、MMaDA対応が記載される。arXiv v1は2025-05-17、v3は2026-06-06、ICML 2026採択。
## 研究上の位置づけ
拡散LLM推論高速化のキャッシュ系統に位置し、固定KVの可否ではなく中間特徴の時間的安定性を資源として扱う。後続の動的キャッシュ、選択的KV更新、階層キャッシュ研究に対して、プロンプトと応答の非対称性、およびValue類似度を更新優先度へ使う設計点を明確にした基準手法である。
