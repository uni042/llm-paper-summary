# You Only Cache Once: Decoder-Decoder Architectures for Language Models

> 自己デコーダが一度だけ生成した大域鍵値を後半の交差デコーダ全層で共有し、長文脈の鍵値メモリと事前充填時間を桁違いに削減する。
## 書誌情報
- **著者**: Yutao Sun, Li Dong, Yi Zhu, Shaohan Huang, Wenhui Wang, Shuming Ma, Quanlu Zhang, Jianyong Wang, Furu Wei
- **公開**: arXiv preprint
- **種別**: preprint
- **対象**: 長文脈推論、鍵値キャッシュ共有、デコーダ・デコーダ構造、ゲート付き保持
- **実装**: 公式コードはaka.ms/YOCOから公開。推論評価ではゲート付き保持用Tritonカーネルを実装。
## 概要
YOCOは自己回帰言語モデルを自己デコーダと交差デコーダの二段へ分けるデコーダ・デコーダ構造である。前半はゲート付き保持またはスライディング窓注意により定数規模の状態で文脈を処理し、その最終表現から一組の大域鍵値キャッシュを生成する。後半の全交差デコーダ層は同じ鍵値を共有するため、通常Transformerの層数×文脈長に比例する鍵値メモリをほぼ文脈長だけへ削減する。さらに事前充填では後半を通らず早期終了できる。3Bモデルを1.6兆トークンまで学習し、160M〜13Bのスケーリング、1M文脈、H100上の推論を評価し、品質を保ちながら大幅なメモリ・遅延・処理能力改善を示す。

YOCOはモデルを前半の自己デコーダと後半の交差デコーダへ分け、自己デコーダ最終表現から大域鍵値を一度だけ作り、後半全層がそれを共有する。前半には定数推論メモリのゲート付き保持またはスライディング窓注意を使うため、層ごとの長大な鍵値を持たない。後半は層ごとに問い合わせ射影だけを持ち、同じ大域鍵値へ因果交差注意する。これによりデコーダ専用モデルの自己回帰特性を維持しながら、鍵値メモリをO(LND)からO((N+L)D)、注意の事前充填計算をO(LN²D)からO(LND)へ変える。

代表結果として、1M文脈の3B推論メモリはH100、YOCO-3B、1M文脈で同等Transformerは9.4倍のメモリに対して12.4GB。層ごとの大域鍵値複製をなくすことで長文脈の主要メモリを削減する。
## 問題設定
通常のデコーダ専用Transformerは各層が全過去トークンの鍵値を保存するため、鍵値キャッシュ量が層数L、文脈長N、隠れ次元Dの積に比例する。長文脈ではモデル重みより鍵値が大きくなり、65BモデルをGQAと8ビット鍵値量子化で使っても512Kトークンだけで約86GBを要し、H100 80GB一枚を超える。さらに全層で大域自己注意を行う事前充填は長さに対して二乗計算となり、最適化済み7Bモデルでも4枚のH100で1Mトークンに約380秒かかる。GQAは鍵値ヘッド数、量子化は要素当たりビット数、Flash-デコードやカーネル融合は実装係数を下げるが、各層が独立した長文脈鍵値を持ち、入力全体を全層の大域注意へ通す構造は変えない。そのため百万トークン級では容量不足と初回応答遅延が再び支配的になり、単なる後付け圧縮ではなく層方向の鍵値重複と事前充填依存そのものを除く設計が必要になる。
## 新規性
YOCOはモデルを前半の自己デコーダと後半の交差デコーダへ分け、自己デコーダ最終表現から大域鍵値を一度だけ作り、後半全層がそれを共有する。前半には定数推論メモリのゲート付き保持またはスライディング窓注意を使うため、層ごとの長大な鍵値を持たない。後半は層ごとに問い合わせ射影だけを持ち、同じ大域鍵値へ因果交差注意する。これによりデコーダ専用モデルの自己回帰特性を維持しながら、鍵値メモリをO(LND)からO((N+L)D)、注意の事前充填計算をO(LN²D)からO(LND)へ変える。
## 手法
### 手法のあらまし
処理は学習・長い入力の事前充填・逐次生成で同じ二段構造を共有する。まず入力トークンを埋め込み、全L層の前半L/2層を自己デコーダとして順に処理する。各層は事前RMS正規化、効率的自己注意、残差、SwiGLU、残差からなる。既定のゲート付き保持はデータ依存減衰を持ち、学習では並列表現、長い事前充填ではチャンク再帰表現、逐次生成では再帰表現を使えるが、三表現は同じ結果を与える。生成時には全過去トークンの鍵値ではなく固定大の保持状態だけを更新する。次に前半最終表現MをRMS正規化し、一組だけ存在する共有の鍵射影と値射影を全入力位置へ適用して大域K,Vを生成し、これを文脈キャッシュとして保存する。後半L/2層の交差デコーダは、各層の現在隠れ状態から層固有Qを生成する一方、K,Vは全層で同じ共有キャッシュを読む。因果マスク付き標準交差注意の出力へ残差を加え、SwiGLUを通して次層へ渡すので、各後半層は異なる問い合わせ変換を学習しながら全履歴を参照できる。長い入力の事前充填では、共有K,Vの作成に後半交差デコーダの入力位置出力が不要という依存関係を利用し、前半自己デコーダとK,V生成までで早期終了する。したがって入力全体を後半L/2層の大域注意へ通さない。最初の出力トークン以降は、新しいトークンだけを前半自己デコーダの再帰状態へ投入し、その新位置の共有K,Vを追加し、後半全層で既存共有キャッシュへ交差注意して最終ロジットを得る。この流れにより、保存対象は前半の固定状態と一組の長さNの大域K,Vだけとなり、層ごとのN長キャッシュを作らない。

### 定数状態の自己デコーダ
前半L/2層は通常の大域自己注意を避け、ゲート付き保持または固定幅スライディング窓注意を使う。ゲート付き保持は各時刻でデータ依存の減衰係数を計算し、過去の鍵と値の積を固定大の行列状態へ畳み込む。並列表現では学習のGPU並列性、チャンク再帰表現では長文入力の演算量と反復数の両立、再帰表現では一トークンずつ固定状態を更新する低メモリ生成を実現する。三表現が数学的に等価なので、段階ごとに効率のよい計算法へ切り替えてもモデル意味を変えない。固定窓注意を選ぶ場合も保持する鍵値は窓幅Cだけで、文脈長Nには比例しない。この前半の定数状態化が、一組の大域キャッシュだけを残す後半設計を成立させる。

### 一回だけ生成する大域鍵値
自己デコーダ最終表現MをRMS正規化した後、モデル全体で一組だけ存在する共有鍵射影W_Kと値射影W_Vを適用し、入力各位置の大域K,Vを生成する。通常Transformerでは同じN個の履歴位置についてL層それぞれが別のK,Vを持つが、YOCOでは文脈長に比例するキャッシュはこの一組だけである。前半自己デコーダ側は固定大状態なので、全体の鍵値メモリはO(LND)ではなくO((N+L)D)になる。さらに共有キャッシュにはGQAを併用でき、問い合わせヘッドより鍵値ヘッドを少なくして定数係数も下げる。大域K,Vは後半の全層と全生成ステップから再利用されるため、ここがYOCOの『一度だけキャッシュする』境界である。

### 共有キャッシュを読む交差デコーダ
後半L/2層は各層固有の問い合わせ射影W_Q^lを現在の隠れ状態へ適用するが、鍵と値の射影結果は作り直さず、前半から生成済みの同じ大域K,Vを読む。各層は因果マスク付き標準多頭交差注意、残差接続、RMS正規化、SwiGLUを持つため、層ごとに異なる表現変換を学習しつつ全履歴位置への大域アクセスを維持する。完全な再帰モデルのように履歴を固定状態だけへ圧縮せず、検索対象となる位置別K,Vは一組残すことが長距離検索能力の保険になる。外部インターフェースはデコーダ専用言語モデルと同じ次トークン予測なので、自己回帰生成や複数ターン利用の形を変えずに層方向のキャッシュ重複だけを除去できる。

### 事前充填の早期終了
共有K,Vは前半自己デコーダの最終表現だけから決まり、入力プロンプト各位置を後半交差デコーダへ通した結果は、将来トークン生成時に使うキャッシュの構築には不要である。そこで長い入力の事前充填では前半L/2層と共有K,V生成だけを実行し、後半L/2層の入力位置計算を丸ごと省略する。これだけでも層数方向で少なくとも約半分の計算を除き、さらに前半のゲート付き保持や固定窓注意が大域自己注意のN二乗ではなく線形に近い計算となるため、長文脈ほど差が拡大する。生成開始後は新規トークンだけ後半も通すので最終出力は通常のYOCO計算と一致し、早期終了のために推論結果を近似したりキャッシュ内容を捨てたりしない。

### 全体のデータ／制御の流れ
YOCOは既存モデルへ後付けするキャッシュ圧縮ではなく、学習時から共有キャッシュを前提にしたモデル構造である。鍵値の層方向重複を構造的に除去し、自己デコーダの定数状態、交差デコーダの大域参照、事前充填早期終了を一体化することで、長文脈サービングの容量と初回応答遅延を同時に下げる。
## 評価条件
- **ハードウェア**: 推論効率はH100 80GB GPUで32K〜1M文脈を評価。1M長文学習はCUBE内部版を利用。
- **ソフトウェア**: LM Eval Harnessで下流課題を評価。ゲート付き保持の推論用にTritonカーネルを実装。
- **データセット／トレース**: LM Eval Harness下流課題群、Needle In A Haystack、multi-needle retrieval、book long-context validation、repository-level code validation
- **比較対象**: OpenLLaMA-v2-3B、StableLM-3B-4E1T、Llama型Transformer + GQA + Flash-デコード + カーネル 融合、LWM-1M-text、MiniCPM-128K、ChatGLM3-128K、YaRN-Mistral-128K
3B YOCOをStableLM-3B-4E1Tに近い学習設定で最大1.6兆トークンまで学習し、OpenLLaMA-v2-3BやStableLMとゼロショット下流課題を比較する。160M、400M、830M、1.4B、2.7B、6.8B、13Bでは同一データ・設定でLlama型Transformer、ゲート付き保持YOCO、スライディング窓YOCOの検証損失を比較する。長文脈版は64K、256K、1Mへ段階延長し、needle検索、多needle検索、書籍・リポジトリコードの負対数尤度を評価する。推論ではGQA、Flash-デコード、カーネル融合を入れたTransformerを公平な基準とし、32K〜1M入力でGPUメモリ、事前充填遅延、処理能力、収容トークン数を比較する。
品質とシステム効率の双方を、3B実運用プロファイル、160M〜13Bスケーリング、最大1M文脈で検証する。
## 主要結果
主結果は、YOCOが層ごとの大域鍵値キャッシュを一組へ集約しても言語モデル能力を維持しながら、長文脈サービングのメモリと事前充填時間を桁違いに削減できたことである。3Bモデルは1兆トークン学習時の8課題平均0.634でOpenLLaMA-v2-3Bの0.619を上回り、160M〜13BのスケーリングでもLlama型Transformerと競争力を保った。1M文脈へ延長したYOCO-3Bは単一needle検索でほぼ完全な正解率を示し、128Kの複数needleでもより大きい長文脈モデルに匹敵した。実用上の効果は長さと層数が増えるほど大きく、H100上の3B・1M文脈では推論メモリ12.4GBでTransformerの約1/9.4、512K事前充填は約180秒から6秒未満、512K処理能力は4.5から43.1 トークン/sへ向上した。したがって単なるキャッシュ容量削減ではなく、同じGPUでより長い文脈・大きいバッチを収容し、最初の応答までの待ち時間と総処理能力を同時に改善する構造的利得が確認された。

- 1M文脈の3B推論メモリ / 12.4GB (比較対象: 同等Transformerは9.4倍のメモリ; 条件: H100、YOCO-3B、1M文脈) — 層ごとの大域鍵値複製をなくすことで長文脈の主要メモリを削減する。

- 512K事前充填遅延 / 180秒から6秒未満 (比較対象: GQA、Flash-デコード、カーネル 融合適用Transformer; 条件: H100、長文脈入力) — 後半交差デコーダの早期省略と前半の線形効率注意が大幅な初回応答短縮を生む。

- 1M事前充填高速化 / 71.8倍 (比較対象: 最適化Transformer; 条件: 1M入力) — Transformerの二乗増加に対してYOCOは線形に近い増加となる。

- 512K処理能力 / 43.1 トークン/s (比較対象: Transformer 4.5 トークン/s; 条件: 事前充填と生成を含む) — 事前充填短縮と低メモリによる大きなバッチの両方が処理能力を上げる。

- 65B鍵値収容能力 / 1GBで128Kトークン (比較対象: GQA Transformerは1GBで1.6Kトークン; 条件: 65Bモデル) — 共有大域キャッシュの利得は層数が増えるほど大きい。

- 1T学習の下流平均 / 0.634 (比較対象: OpenLLaMA-v2-3B 0.619、StableLM-base-alpha-3B-v2 0.612; 条件: YOCO-3B、ゼロショット8課題) — 効率化構造が言語モデル品質を犠牲にしていない。

- 128K multi-needle / N=1/2/4/8で0.98/0.98/0.84/0.56 (比較対象: LWM-1M-text 1.00/0.90/0.76/0.62; 条件: YOCO-3B-1M、比較相手LWMは7B) — 半分以下のモデル規模でも競争力ある長距離検索を示す。

### 負の結果・境界条件
- YOCOは既存Transformerの後付け最適化ではなく新規学習が必要である。1M文脈への到達には64K、256K、1Mの段階的継続学習と専用チャンク並列化を使う。multi-needleの8本条件では0.56でLWM-1M-textの0.62を下回る。スライディング窓版よりゲート付き保持版がスケーリングで良く、自己デコーダ方式の選択が品質へ影響する。

### 結果の読み方
鍵値メモリの主因は各層が同じ長文脈に対して別の鍵値を持つ層方向の重複である。YOCOは大域参照用キャッシュをモデル内の一箇所へ集約し、各後半層は問い合わせだけ変えて共有するため、文脈長と層数の積を避ける。同時に共有キャッシュ生成までで事前充填を止められる計算依存が遅延削減を生む。
## 品質への影響
構造変更後も同規模Transformerに匹敵する言語モデル品質を維持し、ゲート付き保持版は一部スケーリング条件でTransformerを上回る。
## 既存研究との差
GQAやMQAは各層内の鍵値ヘッド数を減らすが層ごとのキャッシュは残す。YOCOは後半全層が同一の大域鍵値を共有し、層方向の重複自体を除く。KIVIやKVQuant等は各鍵値のビット数を減らすため既存モデルへ後付け可能だが、YOCOは構造変更でキャッシュ個数を減らす。MambaやRetNet等の完全な再帰・状態空間モデルと異なり、後半は共有大域鍵値への標準交差注意を残すため、明示的な全履歴参照を維持する。
## 限界
既存の学習済みTransformerへ適用できる後付け手法ではなく、YOCO構造でモデルを学習し直す必要がある。1M文脈モデルは段階的な長文脈継続学習と専用分散学習基盤を用いており、単純な構造置換だけで同じ能力が得られるわけではない。自己デコーダの効率機構により品質が変わり、実験ではゲート付き保持がスライディング窓より良い。推論プロファイルは主に3BとH100で、全モデル規模の実測速度を網羅しない。
## 実装状態
公式コードをaka.ms/YOCOで公開。ゲート付き保持のTritonカーネル、長文学習のチャンク並列化を実装。
## 研究上の位置づけ
YOCOは鍵値キャッシュ問題を圧縮器やオフロードではなくモデル構造から解く系統である。通常Transformerの鍵値量が文脈長×層数で増える原因を、各層が同じ履歴から別々の鍵値を作ることと捉え、大域鍵値を一組へ集約する。これにより後半層は大域参照能力を保持しつつ、共有キャッシュを読むだけになる。

重要なのは、単なる共有キャッシュだけでなく前半の自己デコーダも定数状態化している点である。前半が通常の大域自己注意なら依然として層ごとの長文脈鍵値が必要になる。ゲート付き保持または固定窓注意を前半へ置き、後半だけ一組の大域鍵値を持つことで、長文脈で支配的なメモリをO(LN)からO(N+L)へ落とす。

さらに計算グラフ上、大域鍵値の生成には後半交差デコーダの事前充填出力が不要である。入力プロンプトを処理するときは前半終了後に大域鍵値を作って止め、生成トークンから後半も使う。この早期終了が、キャッシュ容量削減とは独立に初回応答遅延を大きく下げる。512Kで180秒から6秒未満という差はこの構造と線形効率注意の組合せによる。

オフロード・量子化・削除とは補完関係にある。YOCOで大域キャッシュを一組にした後、その共有キャッシュを4ビットや2ビットへ量子化すれば次元の異なる削減を積み重ねられる。CPU/SSDオフロードを使う場合も転送対象が一組なので帯域圧力が下がる。また論文自身が将来方向として共有キャッシュ圧縮と索引化を挙げ、層ごとではなく一つの索引だけを維持できる利点を指摘する。

したがってリポジトリ内では、鍵値量子化・削除が『既存の層別キャッシュを小さくする』のに対し、YOCOは『層別キャッシュを作らない』設計として区別される。新規学習が必要という導入コストと引き換えに、長文脈ネイティブモデルではメモリ、事前充填、処理能力を同時に改善できる基盤構造である。
