# PILL：拡散言語モデルの補完長を予測し、近傍候補を並列生成する

## 概要

PILLは、拡散言語モデル（diffusion language model）が文章やプログラムの**既知の前半と後半の間を補完する課題（infilling）**において、欠落部分の長さをあらかじめ固定しなければならない制約を扱う。双方向注意を使う拡散モデルは前後両方の文脈を見られる一方、復号開始時にマスク位置の個数を決める必要がある。長さを短く見積もると必要な語句を出し切れず、長すぎると余分な出力が混ざる。既存の可変長方式は長さを反復探索したり生成途中に伸縮操作を挿入したりするため、推論回数が増える。

PILLは、長さの決定と内容生成を分離する。まず**一つのマスク位置の隠れ状態**から軽量な長さ予測器で補完長を推定し、その近傍にある複数の長さ候補を、互いに情報が漏れない注意マスクで同時に復号する。最後に各候補の内部整合性と、既知の後続文脈への接続の自然さを一度の追加順伝播で採点し、最も適切な候補を選ぶ。基盤となる拡散モデルの重みは凍結したままでよい。

論文は、LLaDAとDream系列の5モデル、コード・自然言語の8課題で、最強比較対象CALよりコード成功率を平均**4.8ポイント**、テキストBLEU-2を平均**6.0ポイント**改善したと報告する。具体的なLLaDA-8B-Base／HumanEval-Sでは、CALの成功率64.74に対しPILLは71.35、時間2.13秒に対し1.18秒で**1.82倍**速い。ただしこの1.82倍は同じ表の特定設定の比較であり、あらゆるモデル・課題の平均速度倍率ではない。

## 問題設定：補完長と補完内容の相互依存

自己回帰型モデルは通常、左から右へトークンを生成し、終了記号で止まれる。拡散言語モデルは複数のマスク位置を反復的に確定していくため、補完のために最初に何個のマスクを置くかを指定する必要がある。前後文脈が与えられる場合でも、適切な欠落長`L*`は実際に生成すべき内容と結びついており、推論開始時には未知である。論文図1(a)は、同じコードの補完でマスク長を少し変えるだけで正答が不正解になる例を示す。

CALは初期長から出発し、復号の確信度を使って長さを探索するが、初期値によって局所的な長さへとどまることがある。DAEDALなどは生成領域を動的に広げるが、後続文脈が固定されている補完課題では領域の拡張だけでは適切な接続を保証しない。複数長を順に試す方式は、各候補について拡散モデルの順伝播を繰り返すため、候補長が増えるほど計算費用が膨らむ。PILLは、初期長を人手で与える代わりに直接予測し、**長さの不確実性を少数の並列候補で吸収する**。

## 手法

### 1. 長さ予測：単一マスクの双方向表現を読む

前半の確定文脈を`P`、後半を`S`とし、`P ⊕ [M] ⊕ S`という一つだけマスクを挟んだ入力を構成する。凍結した拡散モデルを一回順伝播させると、マスク位置の隠れ状態には前後文脈の情報が含まれる。PILLはマスク位置の最終層隠れ状態だけでなく、**前半の末尾4トークンの平均隠れ状態、マスク位置の隠れ状態、後半の先頭4トークンの平均隠れ状態**を連結した特徴ベクトルを用いる。これにより欠落箇所の直前・直後の意味と構文上の制約を長さ推定へ反映する。

三層の多層パーセプトロン（MLP）が、この特徴から補完長の対数を予測し、指数変換と整数への丸めで推定長`L̂`を得る。長さそのものではなく対数を予測することで、正の長さを扱いやすくし、非常に長い補完区間が学習を支配する影響を抑える。予測器だけを学習し、基盤モデルは更新しないため、基盤モデルの通常の拡散生成能力を保持できる。長さ探索のために何度もモデルを実行する代わりに、**追加の順伝播はこの一回**で済む。

### 2. 予測長近傍を候補集合へ展開

予測長が正確である保証はないため、PILLは`L̂−r`から`L̂+r`までの整数長を候補として用意する。標準的な半径`r=2`なら五つの候補である。半径を大きくすると真の長さを含む可能性は高まるが、候補数と採点対象が増え、正しい候補を選び出すのも難しくなる。論文の感度分析では、候補集合の理想的な上限は半径とともに上がる一方、実際の選択精度は半径2付近から飽和する。

各候補長を別々に完全復号すれば五倍近い計算が必要になる。PILLは候補を一つの長い入力内の**複数スロット（multi-slot）**として配置し、共有する前後文脈と各スロットを同時に処理する。これにより、拡散モデルの復号反復数を候補数に比例させずに済む。

### 3. スロット間の情報漏れを防ぐ注意マスク

入力の配置は、共有の`P`、長さ`L̂`の中央マスク、`S`、その後に各候補長を持つスロット`S1…SN`を並べる形とする。共有領域は前後文脈を表し、候補スロットは自分のトークンと共有領域だけに注意を向けられる。**別候補スロットの生成内容は見せない**ため、候補同士が互いの答えを参照して同質化したり、異なる長さの仮定を混ぜたりしない。共有領域の鍵・値キャッシュは復号中に再利用でき、候補ごとに同じ前後文脈を再計算する費用を抑える。

重要なのは位置識別子（position ID）の設計である。候補スロットの長さが異なるのに、後半文脈の位置を候補ごとにずらすと、モデルが補完すべき位置の範囲を誤解する。論文は、後半の開始位置を`p_S = p_P + L̂ + 1`に固定し、各候補のトークン位置を前半の直後から後半の直前まで**線形補間**する。これにより候補長が異なっても、全候補が同じ前後文脈の位置関係を参照する。

論文第4.3節の例では、二トークンで答えるべき算術補完に位置の隙間を残すと、モデルが答えの片方のトークンしか生成しない。左右どちらかへ単純に詰める配置では、後半との位置的な隙間が残りやすい。線形補間はこの**位置ずれによる過少生成**を防ぐための機構であり、単なるGPU並列化の小技ではない。

### 4. 事後選択：内部整合性と後続文脈の接続を採点

拡散モデルはマスクされた位置を予測するよう学習されているため、完成済みの候補列を自己回帰モデルの次トークン尤度と同じ方法で直接採点しにくい。単純な疑似対数尤度では各位置を順番に隠して何度も順伝播する必要がある。PILLは、候補`C_j`と後続文脈から選んだ少数のトークンを並べ、各観測位置に対応する**採点用マスク（scoring probe）**を設置する。

可視トークンは自分以前の可視トークンだけを参照し、採点用マスクは自分の正解トークンを見ず、それ以前の文脈だけを見るよう注意を制限する。これにより、採点したい答えが注意経路を通じて漏れ込むことを防ぎ、候補内の各トークンと後続文脈の各トークンの条件付き対数確率を一回の順伝播で求める。候補を個別に採点するのではなく、複数候補の採点領域も相互遮断して同時に実行する。

各候補について、候補内部の平均対数確率`score_inner`と、候補を置いた後で既知の後続文脈が自然に続く度合い`score_suffix`を計算し、`α×score_inner + (1−α)×score_suffix`を最大にする候補を選ぶ。標準設定は`α=0.5`である。内部整合性だけを最大化すると前半とは自然でも後半へ接続しない補完を選び得る。後半への適合だけを使うと候補内部の破綻を見落とす。両者を同時に見ることが、長さの異なる候補から正しい橋渡しを選ぶ根拠になる。

### 5. 後続文脈の少数トークンを選ぶ理由

後続文脈の全文を採点する必要はない。PILLは、後半の先頭にある接続上重要なトークンと、補完領域から強い注意を受けた後続の重要トークンを選ぶ。遠くの変数名など、後半の先頭だけでは分からない制約を拾える一方、採点するトークン数を抑えられる。論文は後半の参照範囲を最大32トークン、実際に採点する数をおおむね4〜8とする。図4の感度分析では、採点数を増やしすぎるとむしろ性能が下がり、4付近で良好だった。

この選択は、単なる文章の流暢さを測るのではなく、**補完内容が後半の既知のコードや文章へ無理なく接続するか**を評価するための設計である。候補の生成と選択を分けた結果、長さ予測が多少外れても近傍候補から回復できるが、候補集合に正しい長さが存在しなければ事後選択では救えない。

### コード・文章の集計と負の結果

論文表1では5種類の基盤モデルと8課題を比較し、コード課題では最強の可変長比較方式CALに対し平均+4.8ポイント、文章課題ではBLEU-2平均+6.0ポイントの改善を報告する。ただし**すべての組合せで勝つわけではない**。たとえばLLaDA-8B-InstructのHumanEval-Sでは、CALが69.77、PILLが67.86であり、PILLの方が低い。平均改善を個別条件の一律改善として扱わないことが重要である。

DAEDALは生成領域の末尾への拡張を主眼とするため、後半文脈を固定して間を埋める課題ではかえって精度が悪化することがある。LLaDA-8B-BaseのWikiTextでは固定長基盤モデルのBLEU-2が34.48、DAEDALが20.78、CALが37.25、PILLが44.96である。これは可変長化の仕組みが存在するだけでは補完課題へ適合せず、**後続文脈への接続を明示的に扱う必要がある**ことを示す。

### 長さ予測と候補選択の上限

論文表3では、HumanEval-Sにおける長さ予測の平均絶対誤差（MAE）がPILLで約2.50、CALの初期長4で約3.56、初期長32では約24.13となる。CALは初期長が大きいほど誤差が増えるが、PILLは人手の初期長を必要としない。ただしPILLの正解長との差3以内の割合は78.22%であり、**常に正解長を候補集合に含められるわけではない**。予測の不確実性が大きい事例では、半径2の候補から正解長が外れる。

PILL (Oracle)は、PILL自身が生成した同じ候補集合から、正解判定を使って最も良い候補を選ぶ実験上の上限である。LLaDA-8B-Base／HumanEval-Sでは通常PILLの71.35に対してOracleは81.90で、**候補集合内に良い答えがあっても事後選択で取り逃す余地**がある。これは、より大きな候補集合を作ることと、候補を正しく選ぶことが別問題であることを示す。

### 構成要素除去実験

位置識別子の線形補間は、左寄せ・右寄せのパディングよりも平均成功率が高い。論文表4の平均Pass@1は左寄せ28.2、右寄せ31.6、線形補間51.6であり、候補を完全に独立して生成した場合の52.9に近い。つまり、複数候補を一括復号しても、正しい位置設計なら独立復号に近い品質を保てる。

事後選択についても、候補をランダムに選ぶとPass@1は51.62、予測長の中央候補のみでは66.02、内部整合性のみ69.02、後続文脈適合度のみ63.99、両方を半々に組み合わせると71.35となる。二つの信号を併用する効果は数値で確認できるが、完全な正解評価器による選択との差は残る。

## 既存研究との差

CALは初期長を固定して確信度を見ながら繰り返し探索するのに対し、PILLは双方向隠れ状態から長さを直接予測する。DAEDALは生成領域の拡張を行うが、後半文脈との接続を考慮する補完に必ずしも適さない。DreamOnは長さ変更を扱うために基盤拡散モデルの追加学習を必要とする一方、PILLは基盤モデルを凍結し、長さ予測器と推論時の注意マスク・採点を追加する。

PILLの新規性は「長さを予測する」だけでなく、**予測誤差を近傍の並列候補で吸収し、後半文脈との整合性で選択する一連の設計**にある。特に候補スロット間の注意遮断、後半位置の固定と線形補間、採点用マスクへの正解漏れを防ぐ因果注意の三つが、単純な複数候補生成との違いを作っている。

## 限界と未評価事項

第一に、長さ予測器の誤差が大きいと、候補集合に正解長が入らない。半径2の候補集合は多くの事例で機能するが、すべてを覆うわけではない。半径を増やせば理想的な候補集合の上限は上がる一方、採点と選択が難しくなるため、無制限に広げれば良いわけではない。

第二に、事後選択の精度には余地がある。Oracleとの差は、候補の生成品質だけでなく、内部整合性と後続文脈適合度という二つの代理指標では正解判定を完全に代替できないことを示す。後続文脈の一部しか採点しない設計は高速だが、遠くにある制約や複雑な依存関係を取り逃す可能性がある。

第三に、論文の評価は単一のNVIDIA A40上で、7B〜8B級を中心とする拡散モデルに限られる。より大きなモデル、多GPU、長い入出力、複数要求が混在するサービングでの処理量は検証されていない。複数候補を一つの入力に並べる方式では、候補数や文脈長が増えると注意計算・メモリ需要も増えるため、追加順伝播が2回という事実だけで総計算費用が常に一定とは言えない。

第四に、論文自身が複数階層の欠落区間やリポジトリ全体にまたがるコード修正など、より複雑な編集を未評価の課題として挙げている。PILLは「単一の前半・後半に挟まれた一つの欠落区間」を中心とする方式であり、一般的な自律コード編集の全問題を解決したわけではない。

## 再監査所見

元の8,056バイト原稿は三段階構成と集計結果を記述していたが、長さ予測器に用いる前後4トークンの特徴、スロット位置識別子の補間式、採点マスクの情報漏れ防止、後半の重要トークンの選び方、比較対象ごとの絶対値、負の結果、候補選択の上限との差が不足していた。一次論文の第4〜5節、表1〜5に戻り、**長さの推定→並列候補→漏れのない一括採点**という処理の因果関係と、評価条件を区別できるよう再構成した。
