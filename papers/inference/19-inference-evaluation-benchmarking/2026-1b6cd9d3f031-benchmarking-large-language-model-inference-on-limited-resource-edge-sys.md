# Benchmarking Large Language Model Inference on Limited-Resource Edge Systems

> 12件の小型・中型モデルについて生成型精度とJetson実機のスループット・電力を二重測定で結び付け、GPU実行が電力増にもかかわらずエネルギー効率を0.453から0.823トークン毎ジュールへ上げることと、精度と効率の交換がモデル規模で決まることを示すベンチマーク。

## 概要

大規模言語モデルをクラウドではなくエッジで動かすと、遅延とプライバシーと通信依存は改善するが、メモリ容量とメモリ帯域と電力・熱の制約が厳しくなる。ところが従来の評価は、課題の正解率だけを測るものと、ハードウェア効率だけを測るものに分かれがちで、あるモデル構成を選んだときに品質と電力費用を同時にどれだけ払うのかが分かりにくかった。本論文は新しいモデルや圧縮手法を提案する研究ではなく、この測定の隙間を埋めるベンチマーク研究である。

方法は二部構成である。第一部では生成で答えを出す形の精度課題を、より速く回せるデスクトップ機で測る。第二部では対象のエッジ機であるNVIDIA Jetson Orin Nano Superの上で、同じモデルタグと同じ決定論的デコード設定を使い、スループットと消費電力とエネルギー効率を測る。精度と効率は別々の機械で測るため、両者の交換関係はエンドツーエンドの単一ベンチマークとしてではなく、モデル構成の水準で結び付けられる点が、この設計の前提であり限界でもある。電力測定ではJetson内部のテレメトリによるレール値に加え、デジタルマルチメータで基板の直流入力そのものを測る二重の経路を用意し、オンチップの推定とシステム全体の実入力の差を分けて読めるようにした。

**代表結果:** 全モデルと全プロンプトを通した中央値では、GPU実行のスループットは毎秒18.13トークンで、CPUのみの実行の毎秒7.12トークンの約2.55倍だった。平均の外部入力電力は15.11ワットから22.03ワットへ約46パーセント増えたが、スループットの伸びがそれを上回るため、エネルギー効率は1ジュール当たり0.453トークンから0.823トークンへ改善した。モデル規模で見ると、1億未満級が最も速く効率が高く、7から8B級は精度が高い代わりにトークン当たりのエネルギー費用が大きく跳ね上がる。

## 問題設定

エッジ推論のボトルネックは三つに整理される。第一にメモリ容量である。モデルがメモリに収まらなければページングやスワップが起き、計算ではなく遅いストレージ入出力が支配的になる。第二にメモリ帯域である。自己回帰デコードでは生成トークンごとに重み全体とKVキャッシュへ触れるため、演算性能よりもデータ移動が律速になりやすい。第三に電力と熱である。短時間の測定で速くても、発熱で周波数が落ちれば長時間の挙動は別物になる。

既存のモバイル・組み込みベンチマークは視覚系の固定形状入力を前提にしたものが多く、モデルの読み込み、プロンプト処理、可変長の逐次生成、伸び続けるKVキャッシュを持つ言語モデルの測定にはそのまま使えない。また内部テレメトリだけに頼る評価では、基板側の変換損失を含む実際の入力電力が見えず、効率の絶対値を過大に読む危険がある。本論文の着眼点は、生成型で測る応答品質、実機のスループット、内部と外部の二経路の電力測定を、同じモデル構成へひも付けて提示することにある。

## 手法のあらまし

評価対象はOllamaで配布されるGGUF形式の12モデルで、1億未満、1から4B、7から8Bの三つの規模帯を含み、Gemma、Qwen、Llama、Mistral、Phi、DeepSeek-R1の蒸留系などの系統をそろえる。精度側はlm-evaluation-harnessを使い、OllamaのOpenAI互換のチャット補完インターフェース経由で生成させて採点する。課題は指示追従のIFEval、数学推論のGSM8K、真実性志向の自由生成であるTruthfulQA_genの三つで、いずれも対数尤度ではなく生成結果で採点できる課題に限る。Jetson側は自作のPythonハーネスがOllamaのネイティブな生成インターフェースへ非ストリーミングで要求し、文脈長1024トークン、生成上限192トークン、温度ゼロの決定論的設定で、7種類の固定プロンプトを流す。各構成につき予備実行3回の後に測定5回を行い、測定間には冷却時間を置く。実行方式はGPUを使う方式と、GPUオフロードを切り全CPUスレッドを最高性能設定で使う方式の二つを、同じ条件で比べる。

## 手法

### 1. 二部構成の測定設計 — 精度と効率をモデル構成で結ぶ

この設計が観測するのは、モデル構成ごとの課題品質と、同じ構成をエッジ機で動かしたときの時間と電力である。保持する状態は、固定したモデルタグ、量子化形式を含むGGUFファイル、決定論的デコード設定、固定プロンプト集合であり、精度側と効率側でこれらをそろえることで、別々の機械で測った値を同じ構成の性質として並べられる。処理は、精度をデスクトップで測って構成の性質とし、スループットと電力をJetsonの性質として記録し、最後に両者を規模帯ごとに突き合わせることである。これにより減るボトルネックは、精度だけ見て選ぶと電力費用を見落とす、あるいは速度だけ見て選ぶと品質を見落とすという、モデル選択の誤りである。追加費用は、精度がJetson上で測られていないため、同一ランタイムと同一ファイルでもプラットフォーム差がゼロだという仮定に依存する点であり、著者らもこの点を明示して、結果を単一の統合ベンチマークとして読まないよう求めている。

### 2. 二重の電力測定 — 内部レールと外部入力を分ける

この機構が観測するのは、Jetson内部のテレメトリが50ミリ秒間隔で出すレール電力と利用率と温度と周波数、そして外部のデジタルマルチメータが直流入力で測る電圧と電流の積である。外部測定は別のRaspberry Pi 5が約毎秒2サンプルで記録し、壁時計の時刻でベンチマークと同期する。保持する状態は、各実行の開始前の待機時ベースラインと、レール別の平均・ピーク値である。処理は、内部値と外部値を別々にエネルギー効率へ換算して比べ、結論が測定経路に依存しないかを確認したうえで、より保守的な外部値を主たる参照として以降の分析に使うことである。これにより減るボトルネックは、オンチップ推定だけでは基板の変換損失を捉えられず効率を甘く見積もる問題であり、実際、外部値は内部の入力レール値より一貫して高く出た。追加費用と失敗条件は、外部測定にハードウェアトリガも再校正もないため、得られるのは実行区間の平均入力電力の推定であって、高周波の過渡的な電力変動は捉えられないことである。

### 3. GPU実行とCPUのみ実行の対照 — 加速器の寄与を規模効果から分ける

この対照が観測するのは、同じモデル、同じプロンプト、同じ文脈長と生成上限のもとでの実行方式だけの差である。CPUのみの条件は、GPUオフロードを無効化し、全コアを最高性能の周波数設定で使う最良条件のベースラインとして設計される。処理は、両方式で各420回の測定実行を行い、スループットと平均電力とその比であるエネルギー効率を規模帯ごとに比べることである。これにより減るボトルネックは、モデルの大きさの効果と加速器の効果が混ざって読めなくなる問題である。結果として、電力トレースの形も方式で分かれ、GPU実行は短く鋭い高電力のバーストと待機への復帰を繰り返し、CPUのみは広く持続する電力の plateau を描いた。つまりGPUは瞬時電力が高い代わりに仕事を早く終えて低電力状態へ戻るため、総エネルギーでは得になるという読みが、トレースからも裏付けられる。誤った読み方への注意として、この対照は単一のランタイムと単一デバイスでのものであり、別のカーネル実装では絶対値が変わり得る。

### 4. 複合精度指標 — 9指標の正規化平均

精度側の要約には、GSM8Kの柔軟抽出による完全一致1指標、IFEvalの4指標、TruthfulQA_genのBLEUとROUGE系4指標の計9指標を、モデル間で最小最大正規化して無重み平均した複合スコアを使う。この指標が担うのは、課題ごとに単位も範囲も違う値を一つの相対順位へ畳むことであり、論文自身が、これはベンチマーク固有の相対指標であって応答品質の普遍的な尺度ではないと明記する。したがって複合スコアは、効率との散布図で交換関係を見るための道具として読み、絶対的な品質値として引用しないことが前提になる。

## 評価

結論は、GPU実行が電力増にもかかわらずエネルギー効率を改善すること、モデル規模が精度と効率の交換をほぼ決めること、そしてプロンプト種別の影響はモデル選択と実行方式の影響より小さいことの三点である。精度ではLlama 3.1 8Bが複合スコア首位で、Gemma 3 4Bが続き、Phi-3 3.8BとMistral 7Bも規模の割に競合した。逆にGemma 3 270MとQwen3 0.6Bは精度が大きく低いが、Jetsonでは最高のスループットと効率を示した。読み方として重要なのは、この逆転こそが単一指標で選ぶ危険を示しており、用途が対話応答か継続分析かで最適な規模帯が変わるという点である。

プロンプト別の分解では、効率の値はモデルごとの帯の中に収まり、種別間のばらつきはモデル内でも毎秒1トークン未満が典型だった。つまり今回の固定文脈長と固定生成上限のもとでは、平均化したモデル別値で比べても結論は変わらない。ただしこれは文脈長や生成長を振った結果ではないため、長文脈でのKVキャッシュ増大が効く条件へそのまま広げることはできない。未評価の点として、非ストリーミング測定のため最初のトークンまでの時間は測られておらず、対話用途の体感遅延は別途の測定が要る。また持続的な熱の耐久試験ではなく冷却を挟む短時間測定であり、詳細なメモリ使用量のプロファイルも範囲外とされる。

## 既存研究との差

従来のJetson系評価の多くが内部テレメトリだけに頼っていたのに対し、本論文は外部の基板入力測定を併用し、両経路で相対結論が一致することを確認したうえで保守的な外部値を主参照にする点が測定方法上の差である。また精度か効率の一方だけを報告する先行評価に対し、生成型の精度課題と実機の電力測定を同じモデル集合へ結び付け、複合精度と効率の散布として交換関係を示した点が、ベンチマークとしての寄与である。新しい圧縮やスケジューリングの提案は含まず、既存手法の優劣ではなくモデル選択の判断材料を提供する研究として位置付けられる。

## 限界・実装状況

限界は、精度と効率の分離測定であること、単一デバイスと単一ランタイムへの依存、最初のトークンまでの時間が未測定であること、冷却を挟む短時間測定で持続的な熱スロットリングを評価していないこと、詳細なメモリフットプリントの分析が範囲外であること、外部電力が平均推定にとどまり過渡応答を捉えられないことである。実装状況は、固定モデルタグと決定論的設定と実行単位の生ログを残す再現手順が記されるが、公式コードの公開先は示されず、生データは対応著者への請求で提供されるとされる。したがって第三者による完全な再実行は、ハーネスの再実装を前提とする。

## 一般的な実装上の含意

エッジのモデル選択では、正解率の順位とトークン当たりエネルギーの順位が逆転し得るため、少なくとも品質、スループット、平均電力、エネルギー効率の四つを同じ条件表で見る必要がある。電力は内部テレメトリだけで判断せず、可能なら基板入力の実測で保守側へ寄せて読むべきであり、瞬時電力の高さだけで方式を否定せず、仕事を終えるまでの総エネルギーで比べることが重要である。またGPUの有無のような実行方式の差は、モデル規模の差と分けて測らなければ、改善の出所を取り違える。
