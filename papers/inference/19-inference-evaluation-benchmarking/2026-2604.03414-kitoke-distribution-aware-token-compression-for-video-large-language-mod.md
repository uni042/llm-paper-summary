# KiToke：動画全体の密度を利用する視覚トークン圧縮

## 概要

動画を理解する大規模言語モデルは、複数フレームから大量の視覚トークンを作り、テキストの質問とともにLLMへ渡す。背景、静止した物体、繰り返し出現する場面などには冗長性があるため、視覚トークンを減らすとprefillを速くできる。ただし単純な重要度選択は、頻繁に現れる多数派の視覚パターンへ保持枠を使い、短時間しか現れない重要な物体や場面転換を見落とす。特に保持率1%など極端な条件では、複雑な既存手法が一様ランダム抽出より低い精度になることもある。

HuangらのKiTokeは、動画全体の視覚トークン埋め込み分布を推定し、**密な領域のトークンほど選択確率を下げ、希少な領域ほど選択確率を上げる**。選択しなかった情報は完全に捨てず、場面転換を跨がない時間区間内で残したアンカーへ統合する。質問文を見て重要度を決めず、モデルの再学習も必要としない。

LLaVA-OneVision-7Bの4ベンチマーク平均では、視覚トークン10%保持で無圧縮精度の98.5%、1%保持で89.2%を維持した。単一A100で測った圧縮処理込みのLLM prefill時間は、無圧縮448.0msに対して10%保持66.2ms、1%保持35.9msで、6.8倍と12.5倍の高速化に相当する。**動画のデコードや視覚エンコーダの処理、LLMの自己回帰復号を含む全要求時間の倍率ではない。**

## 問題設定：頻出パターンへの保持枠の偏り

動画トークンを圧縮する方法には、フレーム平均との類似度で削るVidCom2、時間方向の静止・動きを利用するPruneVID、局所時間区間で密度ピークを選ぶFastVIDなどがある。これらは一定の保持率では有効だが、同じ視覚パターンが動画全体に繰り返し現れると、その多数派が保持枠を占める可能性がある。動画の最初と最後に似た背景が現れる場合、局所区間だけで重複を判断すると動画全体の冗長性を見落とす。

一様ランダム抽出は頻度に比例してトークンを選ぶ。大量に繰り返す背景のトークンが多ければ、残す集合も背景に偏る。KiTokeは「その埋め込みに近い他のトークンが動画全体で何件あるか」を冗長性とみなし、少数派のパターンにも保持枠が配分されるようにする。目的は、ある質問に対して重要な物体を推測することではなく、**質問が未知でも動画の視覚的多様性を幅広く残すこと**である。

この方式は視覚エンコーダが出した埋め込みの幾何に依存する。似た埋め込みが似た内容を意味するという仮定が破れる場合、密度を冗長性とみなす判断も誤り得る。

## 手法

### 1. 動画全体のKDEで冗長性を推定

Tフレームから各M個の視覚トークンを取り、動画全体のN=T×M個の埋め込みx_iを集める。各トークン間の距離にGaussian kernel K(x_i,x_j)=exp(−||x_i−x_j||²/(2α))を適用し、全トークンへの類似度の和D_iを計算する。これは定数倍を除くカーネル密度推定（KDE）であり、近い埋め込みが多数あるほどD_iが大きい。

選択用スコアはS_i=1/D_iとする。密度の高い背景などは個々の選択重みが小さく、動画内に少数しかない視覚パターンは重みが大きい。密度は**フレーム内でも時間区間内でもなく、動画全体**で推定する。離れた時刻に再登場する同じ物体を、独立した希少パターンとして過大評価しないためである。

完全KDEはN件同士の距離計算を要するため、動画が非常に長い場合は計算・メモリ費用が課題となる。原著は近似最近傍検索（ANN）による代替も付録で評価しているが、通常の主結果は完全KDEを使う。したがって全トークン数に対するスケーラビリティと、LLM側のトークン削減による利得は別々に評価する必要がある。

### 2. 逆密度重み付き固定件数サンプリング

保持率γから予算B=floor(γN)を決め、S_iを全体で正規化してq_iを得る。各トークンの包含確率π_iをmin(1,λq_i)で設定し、合計がBになるようλを調整する。pivotal samplingにより、包含確率を保ちながら重複なしで**ちょうどB件**のアンカーを選ぶ。確率重みの高いものを単純に上位B件選ぶのではなく、確率抽出を使うことで多様性を残す。

原著Proposition 1では、埋め込みが互いに分離したG個の群へ分かれ、各群の密度が群サイズにほぼ比例する場合、逆密度重み付けによる各群の総選択確率が群の大きさに依存せず、理想条件では約1/Gになることを示す。例えば背景トークンが1000件、短いイベントが10件でも、類似した群として分離できれば、群単位の保持枠をほぼ均等に配れるという直観である。ただし群間の類似度や確率の飽和が強いと、この均等配分は近似にとどまる。

### 3. 場面転換を跨がないトークン統合

選ばれなかったトークンにも有用な視覚情報が残る。KiTokeは未選択トークンを最寄りのアンカーへ割り当て、埋め込みを重み付き平均して情報を統合する。ただし動画全体で無制限に混ぜると、異なる場面の物体や動作を一つの表現へ混ぜてしまう。そこで、フレーム間のトークン変化量から時間区間の境界を推定する。

原著のフレーム変化スコアc_tは、同じ空間位置同士の距離と、次フレーム内の最も近い位置との距離を併用する。さらに隣接する変化量との差Δ_tを計算し、絶対的な変化または局所的な急増が閾値を超えた時点を区間境界とする。これは単なるフレーム平均の差より、移動した物体と場面転換を捉えやすくする狙いがある。

各区間に最低1つのアンカーが残るように調整した後、未選択トークンを**同一区間内**の最近傍アンカーへ割り当てる。アンカーに属する元トークンの埋め込みをS_i=1/D_iで重み付け平均し、頻出パターンが統合結果まで支配しないようにする。統合後のアンカーは元の時間・空間順に戻してLLMへ渡す。選択時と統合時に同じ逆密度重みを使うことが重要である。

### 4. 推論時の流れ

動画からフレームを抽出し、視覚エンコーダとプロジェクタで視覚トークンを作る。動画全体の埋め込み密度を計算し、指定した保持予算に合わせて逆密度サンプリングを実施する。フレーム変化から時間区間を作り、各区間内で未選択トークンを残したアンカーへ統合する。得られた少数の視覚トークンをLLMのprefillへ渡し、質問への応答を生成する。選択は質問文の意味に依存しないので、同じ動画を複数の質問で利用する場面にも適する。ただし圧縮処理自体の費用が追加されるため、保持率を小さくするほど常に総時間が短くなるとは限らない。

Table 1の同一バックボーン比較では、25%保持のKiTokeが59.4と無圧縮59.1をわずかに上回る。これは圧縮が必ず精度を改善することの証明ではなく、ベンチマークとサンプリングの条件下で観測された結果である。1%保持ではFastVID 47.6、Random 49.6、KiToke 52.7となり、既存の複雑な選択手法がランダム抽出を下回る一方、KiTokeは3.1ポイント上回る。極小予算で少数派の視覚パターンを残す効果が現れやすい。

LLaVA-VideoやQwen3-VLでも、原著Figure 3と付録Table 6/7で保持率を下げたときの優位性が報告される。ただしモデルごとのトークン構造や画像エンコーダは異なり、LLaVA-OneVisionの絶対精度を他モデルへ転用してはいけない。追加のCVRR-ESやVideoMMMUは、主な4ベンチマークとは評価の種類が異なるため別に扱う。

Table 4はVideoMME 100件、バッチ1、単一A100 80GBでの平均値である。圧縮費用を含むため、単にLLMへ渡すトークン数から推測した速度倍率より信頼できる。ただし測定対象は**視覚エンコード後の圧縮処理とLLM prefill**に限定される。映像のフレーム抽出・デコード、視覚エンコーダ、生成トークンの復号を含むエンドツーエンドの時間ではない。

1%保持では視覚トークンが平均6272から62程度になり、LLM側の演算量が大きく減る。しかし圧縮の12.3msとLLM prefillの23.6msが残るため、保持率を1/100にしても全処理が100倍速くなるわけではない。視覚エンコーダが重いサービスでは、総要求時間の利得はさらに小さくなる可能性がある。

## 構成要素の検証と負の結果

原著の統制実験では、選択規則以外の入力・予算・区間・統合方法を固定し、逆密度選択を比較した。1%保持のLLaVA-OneVisionで動画全体の密度推定を用いると平均精度52.7、フレームごとの密度推定では50.8、時間区間ごとでは51.5となる。動画全体に繰り返し現れるパターンをまとめて冗長とみなすことが有効である。

未選択トークンを単純に捨てるより、時間区間内でアンカーへ統合すると情報を保持しやすい。原著のTable 12では、同じ区間数でも内容適応的な境界は均等な時間区間より1.3ポイント改善し、同じアンカー集合と割当でも逆密度重みの統合は0.5ポイント改善した。つまり選択、時間区間、統合重みの各要素に独立の寄与がある。

極小保持率ではVidCom2やPruneVID、VisionZipなどの一部方式がRandomより低い結果を出す。これは重要度推定が頻出パターンへ偏り、保持枠が少ないと見落としの損失が大きくなることを示す。KiTokeも無圧縮の精度を完全には維持できず、1%保持の絶対平均は59.1から52.7へ下がる。相対89.2%を「無損失」と表現するのは不正確である。

長い動画に対する完全KDEは計算が増える。著者は近似最近傍を使った代替を付録で検討しているが、近似の精度・費用の交換条件を別途評価する必要がある。保持予算を一定にしてフレーム数を32から320へ増やす実験では、VideoMME精度が58.4から61.6へ改善したが、これはより長い時間範囲をカバーした効果であり、すべての動画でフレーム数を増やすほど良いという保証ではない。

## 既存研究との差

VidCom2は平均視覚トークンへの距離を冗長性の指標にするが、分布が複数の離れた群を持つ場合、平均の近くにある希少パターンを誤認し得る。PruneVIDは時間方向の静止・動きに注目するが、動きながら繰り返す内容の冗長性を十分に表せない。FastVIDは時間区間内の密度ピークを選ぶが、異なる区間に再登場する同じパターンの頻度を全体で調整しない。KiTokeは**動画全体の密度で選択重みを決め、時間区間内だけで統合する**ことで、グローバルな冗長性評価とローカルな場面境界の保護を両立する。

質問依存のFastVなどとは異なり、KiTokeは質問内容を見ずに圧縮する。複数質問で同じ動画を使う場合に圧縮済み表現を再利用しやすい一方、質問に必要な希少情報を確実に残す保証はない。学習不要で既存モデルへ追加しやすいが、視覚トークンの配置、時間位置、特殊トークンの扱いはバックボーンに合わせた実装が必要である。

## 限界と実務上の導入判断

実験は特定のVideo LLMとA100環境であり、一般の画像1枚だけのVLM、低VRAM GPU、動画ストリーミングの逐次入力で同じ効果が出るとは限らない。完全KDEは動画全体を事前に見て密度を計算するため、未来のフレームが未到着のリアルタイム処理にはそのまま適用しにくい。近似密度推定を使う場合も、メモリ消費と品質の追加検証が必要である。

また、質問非依存の保持枠配分は多様性を保つが、ある質問にとって決定的な1フレームを必ず残す保証はない。実装では短いイベント、テロップ、細かい動作、場面転換を含むテストを用い、保持率ごとの正解率と圧縮時間を確認するべきである。動画デコード・視覚エンコード・生成復号まで含めた総レイテンシと、複数同時要求時のGPUメモリも別途測る必要がある。
