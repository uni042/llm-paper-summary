# From Words to Watts: Benchmarking the Energy Costs of Large Language Model Inference

## 概要
LLMの環境・運用コストを議論するとき、学習時の消費電力は比較的よく測定される一方、推論は利用回数が非常に多いにもかかわらず、モデル規模、GPU世代、モデル分割数、バッチサイズ、生成長がエネルギーへどう効くかの公開実測が少なかった。本論文は新しい高速化方式を提案するのではなく、LLaMA 7B/13B/65Bを実機で動かし、スループットとGPUエネルギーを同時に測ることで、推論構成の交換条件を明らかにする。

中心は65Bモデルである。V100 32GBでは最低8枚、A100 80GBでは最低4枚が必要で、V100では8/16/32分割まで拡張する。AlpacaとGSM8Kから各4,096入力を使い、出力長やバッチを変えながら、単なる秒当たりトークン数だけでなく、ワット、出力トークン当たりジュール、応答当たりエネルギーを測定する。

重要な観察は「GPUを増やせば速くなるのでエネルギーも有利」とは限らない点である。65Bでは分割数を増やすほど秒当たり消費電力と出力トークン当たりエネルギーが概して増える。さらにA100 4枚で電力上限を250Wから175Wへ30%下げると、平均推論時間は6.7%伸びるが総エネルギーは23.21%減る。性能とエネルギーの運用点をハードウェア設定で調整できることを示した。

## 問題設定
大規模モデルは重みだけで複数GPUを必要とし、推論ではモデル分割のための通信と各GPUの演算が発生する。GPU数を増やせば各GPUが担当する重みは減る一方、通信とアイドルを含むシステム全体の消費電力は増え得る。したがってレイテンシだけを最小化した構成が、ジュール/トークンや総運用電力でも最適とは限らない。

また入力タスクにより出力長や生成挙動が変わる。論文は自然言語指示のAlpacaと算術推論のGSM8Kを分け、同じモデル・ハードウェアでもワークロード差がエネルギー特性に現れるかを見る。これによりモデル規模だけでなく、GPU世代・分割数・バッチ・生成長・タスクを推論エネルギーの説明変数として扱う。

## 手法
### 実機計測
MIT SupercloudのV100 32GBノードとA100 80GBノードを使う。LLaMAはPyTorch/FairScaleでモデル分割し、V100の大規模実験では8、16、32 shardまで増やす。GPU状態はnvidia-smiを100 ms間隔で取得し、DCGMからrank-0ノードの集約GPUエネルギーを得る。多ノードではrank-0計測値にノード数を掛けて全体を推定する。

### 複数粒度のエネルギー指標
一つのジョブは4,096 promptを処理する。総GPUエネルギーを実行秒数で割って平均電力、出力トークン数で割ってジュール/トークン、応答数で割って応答当たりエネルギーを作る。性能側もtoken/s、word/s、response/sを測るため、速さとエネルギーを同じ実験から比較できる。

### 電力上限制御
65BをA100 80GB×4で動かし、GPU電力上限を250W、175W、150Wに変える。モデルやデータを変えず、電力だけを制約することで、低電力化による総エネルギー削減と推論時間悪化を直接比較する。

## 評価条件
| 項目 | 条件 |
|---|---|
| モデル | LLaMA 7B / 13B / 65B |
| GPU | NVIDIA V100 32GB、A100 80GB |
| データ | Alpaca、GSM8K、各4,096入力 |
| 65B分割 | V100 8/16/32、A100は主に4 GPU |
| 生成設定 | temperature 0.8、top-p 0.95 |
| 計測 | nvidia-smi、NVIDIA DCGM |
| 指標 | token/s、response/s、W、J/token、J/response |

## 主要結果
| 条件 | 結果 | 読み取り |
|---|---|---|
| LLaMA 65B、V100 | 最低8×32GB V100 | 非圧縮65Bの容量制約が分散実行を強制する |
| LLaMA 65B、A100 | 最低4×80GB A100 | 大容量GPUは必要GPU数を半減 |
| 8→32 shard | 平均電力は概ね増加、約300W〜1kW級 | GPU追加はエネルギー面で無料ではない |
| 出力長512付近 | 約3〜4 J/出力tokenの例 | token単位でも分割数の影響が見える |
| 250W→175W | 時間+6.7%、総エネルギー-23.21% | 緩い電力制限は有効な運用点になり得る |
| 250W→150W | 平均推論時間+19.49% | 強すぎる制限では性能ペナルティが急増 |

## 既存研究との差
学習時の炭素・電力推定や単一GPUの性能測定ではなく、公開LLMの生成推論を最大32 GPUまで実機分割し、性能とエネルギーを同時に測った点が主眼である。特に電力上限、分割数、バッチ、出力長を運用パラメータとして比較し、LLM推論の「速い構成」と「省エネルギーな構成」が一致しない可能性を直接示す。

## 限界
著者自身が予備的分析と位置付けており、連続バッチ、量子化、到着率を持つオンラインサービング、出力品質を統制した比較は行っていない。多ノードの総エネルギーはrank-0ノードのDCGM値をノード数倍する推定であり、ネットワークやCPU等を含む施設全体のエネルギーではない。対象もLLaMA世代とV100/A100に限られる。
