# A Survey of RWKV：再帰型言語モデルの構造、推論実装と長文脈の限界

## 概要

本論文は、Receptance Weighted Key Value（RWKV）という再帰型言語モデルの原理、世代別アーキテクチャ、実装、応用と評価方法を整理するサーベイである。通常のTransformerの自己注意では、生成が進むにつれ過去トークンのKVキャッシュが増える。RWKVは、過去の情報を固定形状の再帰状態へ畳み込むことで、生成時に全トークンのKVを保持しない設計を取る。入力を並列処理しやすい学習形態と、トークン単位の再帰更新を組み合わせることが研究の中心にある。

対象となる主な世代はRWKV-4、RWKV-5（Eagle）、RWKV-6（Finch）である。RWKV-4は時間方向の指数減衰和とチャネル混合を基本とし、RWKV-5は多頭の行列値状態、RWKV-6は入力依存の時間混合と減衰を導入する。著者らは17種類の評価ベンチマークを整理し、長文脈・文脈内学習・数学・安全性などの観点を比較する。ただしこれは既存文献の整理であり、17ベンチマークを同一モデル・同一ハードウェアで再実行した独自実験ではない。

サーベイの重要な結論は、計算量の漸近的な優位性と、長文脈を正確に理解できることが別問題だという点である。原著はLooGLE、RULER、S3EVALなどの報告を参照し、長距離依存や非常に長い入力における性能低下を明記する。したがって「KVキャッシュが伸びないから無限文脈を完全に扱える」という理解は適切でない。

## 問題設定と調査の位置付け

Transformerの全注意は、入力長Tに対して注意スコア行列の要素数が概ねTの二乗で増える。推論時のKVキャッシュも通常はTに比例して増加し、長い会話や文書でメモリを圧迫する。RNNは各時刻の状態を更新するため推論状態の形状を一定にできるが、古典的なRNNでは学習時の時間方向の並列化が難しく、長期依存の学習も課題だった。RWKVはこの両者の設計空間を再検討する。

このサーベイは新しいRWKVモデルを提案する論文ではない。既存のRWKV原論文、改良モデル、ソフトウェア実装、応用例とベンチマークを体系化することが貢献である。対象は推論の効率性だけでなく、自然言語理解、視覚、音声、Webアプリケーションまで広い。そのため本サーベイにとって重要な部分は、再帰状態の構造、実装・カーネル、長文脈性能の限界であり、アプリケーション一覧の多さを推論速度の証拠と混同してはいけない。

著者らはRNN、Transformer、Attention Free Transformer（AFT）を背景として説明し、その後RWKVの各世代を比較する。時間混合が過去情報をどの形で保持するか、チャネル混合が現在トークンの特徴をどう更新するか、状態がベクトルから行列へ変わると表現力とメモリがどう変化するか、という順で読むと理解しやすい。

## 手法

### 1. RWKV-4：時間混合とチャネル混合

RWKV-4の基本ブロックは、時間混合（Time Mixing）とチャネル混合（Channel Mixing）を残差接続で積み重ねる。時間混合では現在トークンの入力 `x_t` と直前の `x_{t-1}` を、学習可能な混合係数 `μ` で線形補間して `r_t`、`k_t`、`v_t` を得る。R（Receptance）は過去情報をどの程度受け入れるかを制御し、KとVは過去の内容を重み付きで集約するために用いる。Wは時間に伴う指数減衰を表す。論文の式16–20がこの構造を示す。

過去トークンの重み付き和は、位置ごとに再び全履歴を読み直すのではなく、前時刻の累積量を再帰的に更新できる。現在位置の寄与には別の係数 `u` を与え、過去からの減衰和と区別する。この性質によって、逐次生成では状態の形状が系列長とともに増えない。ただし、必要な状態サイズは層数・隠れ次元・ヘッド構造に依存し、モデル全体のVRAM使用量が系列長から完全に独立するという意味ではない。出力トークン、入力バッファ、実装の一時メモリなどは別途必要になる。

チャネル混合では、時間混合後の特徴に対して現在・直前の入力の補間と非線形変換を適用する。式21–23では、ゲートされた特徴と二乗ReLUに類する変換を用い、トークン内部の特徴次元を再構成する。時間混合が時系列情報を集約し、チャネル混合が各時刻の特徴を変換するという役割分担である。Transformerの自己注意とFFNに似た機能分担だが、過去情報の保持形態は異なる。

### 2. RWKV-5（Eagle）：行列値の多頭状態

RWKV-4の時間混合状態はベクトル的な集約が中心であり、複数の異なる関係を同時に表現する際に制約がある。Eagleは各ヘッドに行列値の再帰状態を持たせ、鍵と値の外積に相当する情報を蓄積する。論文の式24–30では、`lerp` と呼ぶ現在・直前トークンの線形補間からR/K/V/ゲートを生成し、ヘッドごとの減衰行列を使って過去情報を更新する。

減衰係数 `w=exp(-exp(ω))` は0と1の間に収まるように構成され、古い情報の寄与を段階的に減衰させる。行列値状態により、ベクトル値状態より豊かな鍵・値の関係を表現できる一方、各ヘッドの状態は二次元行列になる。ここでの「系列長に依存しない」と「状態サイズが小さい」は同義ではない。ヘッド次元が大きければ、固定サイズでも状態容量・更新演算が増える。

Eagleの出力は、ヘッド別の再帰状態に現在のReceptanceを作用させ、正規化とゲートを通して結合する。逐次生成の処理は各ヘッドの状態更新と出力計算に帰着し、過去トークンを全て保存するTransformer型KVキャッシュとは異なるメモリアクセスになる。この差はローカル推論のメモリ設計に重要だが、実際の速度は実装されたカーネルやGPUの並列度にも依存する。

### 3. RWKV-6（Finch）：入力依存の混合と忘却

Finchは、Eagleまでの比較的固定的な時間混合を入力依存にする。論文の式31–37では `ddlerp` と呼ぶデータ依存の補間を導入し、現在の入力と前時刻の入力から混合比率を変える。内部では低ランク行列A/Bと非線形変換を使って、各特徴次元の補間量を動的に調整する。これにより、現在の入力が過去の状態をどの程度参照するかを文脈に応じて変えられる。

同時に減衰係数 `w_t` も時刻依存になり、入力から計算した値に基づいて状態を更新する。固定的な指数減衰だけでは、急に話題が切り替わった場面や特定の遠距離情報を保持したい場面に柔軟に対応しづらい。Finchはこの制約を緩和しようとするが、動的なゲート・低ランク演算が増えるため、実装が単純なベクトル再帰より複雑になる。モデル設計上の表現力向上と実機の低遅延化は別途検証が必要である。

### 4. 推論・学習で計算の形を切り替える

RWKVの重要な特徴は、学習時には時系列の演算を並列化できる形で表し、逐次生成時には再帰状態を更新する形で実行できる点である。生成時には過去トークンごとのKVを保持せず、現在トークンのR/K/Vと再帰状態から次の状態を計算する。長い生成でKVキャッシュ容量が線形増加しないことが主な利点である。ただしprefillの並列化、カーネルの数値安定性、ヘッドごとの状態更新の実装は世代によって異なり、抽象的な計算量の比較だけでは実効トークン速度を決められない。

原著はRWKV-7（Goose）にも言及するが、本文の体系的な数式解説と比較は主としてRWKV-4/5/6である。RWKV-7の最新の実装状況をこの2025年初頭のサーベイ記述から推測してはならない。2026年時点の新しいRWKV世代や実装は、別途公式リポジトリの最新版を確認する必要がある。

## 評価

### 収録した主要分類

| 分類軸 | 具体的な調査対象 | 推論システムにとっての意味 |
|---|---|---|
| 構造 | RWKV-4の時間混合・チャネル混合 | 再帰状態による系列長非依存の生成状態 |
| 状態表現 | RWKV-5の多頭行列値状態 | 表現力向上と固定状態サイズ増加の交換条件 |
| 適応性 | RWKV-6の入力依存混合・減衰 | 文脈変化に応じた保持・忘却の柔軟性 |
| 実装 | PyTorch、C/C++、Rust、Go、MLX、ONNX、NCNN、QNN | CPU/GPU/端末向け実行経路と最適化の差 |
| 評価 | 長文脈、文脈内学習、数学、頑健性、言語理解 | 漸近的効率と生成品質の両立を検証する観点 |
| 応用 | 文章生成、視覚、音声、Web、RAG | 対象領域の広さ。ただし全領域での速度優位の証拠ではない |

### 17種類の評価ベンチマークの位置付け

原著Table Iは、RWKV関連研究で使われる17種類のベンチマークを列挙し、それぞれが測る能力を整理している。たとえばLongctxBench、LooGLE、RULER、S3EVALは長い入力の扱いを、LongICLBenchは長文脈での多数ラベルの文脈内分類を、CMATHは数学的問題解決を扱う。BIPIAは間接的なプロンプト注入攻撃、CoDI-Evalは制約付き指示への追従、Freshbenchは時間変化への一般化を対象とする。

| ベンチマーク | 主な評価対象 | サーベイから読み取れる注意点 |
|---|---|---|
| LongctxBench / LooGLE | 長文脈理解・長距離依存 | 定数状態の設計でも依存関係の保持に限界がある |
| RULER / S3EVAL | 長文脈の合成・複雑課題 | 入力が非常に長い条件で性能低下が報告される |
| LongICLBench | 多数ラベルを持つ長文脈分類 | 文脈内で新しい情報を使う能力がボトルネックになる |
| CMATH / MANGO | 数学・空間推論 | タスクごとに得意不得意があり、速度だけで評価できない |
| BIPIA / CoDI-Eval | 安全性・指示追従 | 生成モデルとしての頑健性は別途必要 |
| Freshbench / Head-to-Tail | 時間一般化・低頻度知識 | 再帰状態だけでは知識保持や更新の課題を解決しない |

この表は著者らが独立に全ベンチマークを再実行した結果ではない。原著は各ベンチマークや関連研究の知見を収集しており、モデル規模、学習データ、評価プロンプト、実行ハードウェアは研究ごとに異なる。したがって、異なる文献の速度倍率や正答率を一つの横並びランキングへ統合することはできない。

### 長文脈の負の結果と実装上の制約

LooGLEの長距離依存課題では、RWKVが複雑な長文脈依存を十分に扱えない条件が報告される。RULERでは入力長が増えると有効性が低下し、S3EVALでも非常に長い文脈の課題で限界が観測される。MANGOやMAGNIFICOを使った検証では、空間推論や新しい語義への迅速な適応に弱点が見られる。これらは「状態メモリが一定」と「任意に長い情報を正確に思い出せる」を分離して理解すべき根拠となる。

推論実装の調査では、公式PyTorch系だけでなく、C/C++、Rust、Go、MLX、Android CPU向けONNX、NCNN、Qualcomm QNNなどが挙げられる。Flash-Linear-Attentionを用いたRWKV-6の実装や、rwkv.cppを介したCPU量子化推論も紹介される。しかしこれらの実装は対応モデル、精度形式、カーネルの最適化段階が異なる。サーベイの実装一覧に名前があることだけで、現時点のすべての環境で同じ機能・速度が得られるとは断定できない。

## 既存研究との差と本サーベイの意義

RWKVの原著論文は個別世代の構造・学習・性能を報告する。一方本サーベイは、世代間で何が変わったかを時間混合・再帰状態・適応的減衰の軸で整理し、実装の広がりと評価上の課題を一緒に示す。Transformer、AFT、Mamba、RetNet、Hyenaとの比較も扱うが、これらを同一条件で一斉に再測定する比較ベンチマークではない。主たる価値は、設計上の漸近計算量、実装の選択肢、能力評価の限界を結び付ける調査地図にある。

特に、長文脈でKVキャッシュが増えるTransformerと、固定サイズの再帰状態を持つRWKVでは、メモリ容量の制約が異なる。ただしRWKV-5以降の行列値状態には独自の計算・容量負担があり、状態圧縮に伴う情報の忘却が品質を制約する。従ってGPUメモリの使用量だけで最適モデルを決めず、必要な文脈内検索・長距離推論・生成品質と合わせて比較する必要がある。

## 限界

本論文は2025年1月時点のサーベイであり、後年のモデル世代、公式カーネルの更新、GPU/CPU最適化の進展を網羅しない。採録対象の選択と整理の詳細な系統的レビュー手順、すべての文献を同じ評価条件へ正規化した比較は示されていない。性能に関する記述の多くは引用先の研究に由来するため、原著Table Iの17ベンチマークを「著者が17種類の実機評価を実施した」と読み替えてはいけない。

著者らは長系列処理、マルチモーダル・クロスモーダル学習、効率的な微調整、頑健性と公平性、プライバシー、ハードウェア高速化を将来課題として挙げる。推論システムの観点では、再帰状態の数値安定性、異なるハードウェアでの実測性能、長文脈の正答率、複数要求を同時処理するサービング性能を同時に測る必要がある。単一トークンの状態更新が軽いことだけでは、実運用のスループット・レイテンシの優位性を保証できない。
