# DyLLM: Efficient Diffusion LLM Inference via Saliency-based Token Selection and Partial Attention

## 概要

マスク拡散型の言語モデルは、応答系列をマスクから始め、複数トークンを並列に埋めながら反復的に復号する。自己回帰型LLMと異なり、過去のトークンを一方向に固定していくとは限らず、双方向注意の文脈が毎ステップ変わるため、**系列全体を何度も事前充填に近い形で計算し直す**。この反復が大きな計算費用を生む。DyLLMは、隣接する拡散ステップで多くのトークンの内部表現がほとんど変化しないことに着目し、変化した少数のトークンに演算を集中する。

注意文脈ベクトルの時間方向余弦類似度を層ごとに測り、閾値より低い位置をsalient（重要変化）トークンと判定する。salient位置ではFFNを再計算し、注意も正確に更新する。非salient位置では以前のFFN出力を再利用し、注意文脈は重要変化トークン由来の差分だけで近似する。重みを追加学習せず、独自CUDAカーネルで細粒度の疎演算を実装する。

H100上のLLaDA 8BではGSM8Kで11.47→87.21 tok/s（7.60倍）、Dream 7Bでは12.57→120.62 tok/s（9.60倍）を報告する。ただしこれは元の拡散LLM実装に対する改善であり、自己回帰LLMより9.6倍速いという意味ではない。またDreamではFast-dLLM DualCacheが153.21 tok/sとさらに速いが、GSM8K正答率は68.39%へ低下する。DyLLMは速度だけでなく品質を維持する運用点を探す方式である。

## 問題設定

自己回帰LLMは確定したprefixのKVをキャッシュし、次トークンのために新しい位置だけを計算できる。一方、マスク拡散モデルでは応答をマスクトークン列として初期化し、反復ステップでマスクを徐々に解除する。更新されたトークンが双方向注意を通じて他の位置の文脈を変えるため、単純な自己回帰KVキャッシュを適用できない。並列に複数トークンを確定できる利点が、毎ステップ全系列の再計算で相殺される。

Fast-dLLMはprefixや応答ブロックを固定間隔で再計算し、dLLM-Cacheは一定数のトークンの活性化を更新する。しかし固定された更新頻度やトークン数は、モデル・層・入力の状態によって必要な計算量が変わることを反映しにくい。全系列を更新するrefreshステップが挟まると、長い文脈や並列解除トークン数が多い条件で計算量が急増する。

DyLLMは同じトークンでも浅層ではほぼ不変、深層では変化が大きい場合があることを観測する。LLaDAのGSM8K・256反復での注意文脈の時間的余弦類似度は大部分が1に近いが、深層ほど低類似度の裾が広がる。この観測から、層ごとに再計算対象を変える方式を設計する。

## 手法

### 1. 時間的saliency判定

トークンi、拡散ステップt、層lの注意文脈ベクトルを `C_(t,l,i)` とする。前ステップとの余弦類似度 `s=(C_t·C_(t-1))/(||C_t|| ||C_(t-1)||)` を求め、`s<τ` のトークンを重要変化集合 `A_(t,l)` に含める。閾値τが高いほど多くのトークンを再計算し、低いほどキャッシュ再利用が増える。論文の代表設定はLLaDAで0.99、Dreamで0.995である。

最初の4ステップは全計算してKV、注意文脈、FFN出力を初期化し、その後はsalient-onlyステップへ移る。各層で次の層へ渡すsalient集合を更新するため、同じ拡散ステップでも層によって再計算数が異なる。浅層で少なく深層で増え、終盤では再び減る傾向が付録表4に報告されている。

### 2. FFN再計算の省略

注意出力が前ステップとほぼ同方向であれば、出力射影とRMSNormを通した後の入力も近いと考える。著者は出力射影が良条件であると仮定し、正規化後の近似誤差が条件数 `κ(W_o)` と `sqrt(2(1-s))` で抑えられる関係を示す。ただしこの上界は射影行列の条件数に依存し、任意の層で誤差が無条件に小さいという保証ではない。

非salient位置ではFFNを呼ばず、前ステップのFFN出力を再利用する。salient位置だけにFFNを実行することで、拡散反復で支配的なFFN計算の重複を減らす。重要変化の判定は入力トークンのマスク状態だけでなく、**実際に計算された注意文脈の変化**を参照するため、固定間隔更新より適応的である。

### 3. 重要行と重要列の近似注意

注意文脈の差分は、値ベクトルの変化 `ΔV` による寄与と、注意重みの変化 `ΔS` による寄与へ分解できる。salient queryの行では全KVへ注意して正確な文脈を求める。非salient queryでは注意重みの変化が小さいと近似し、salient位置に対応する値差分だけを前回の文脈へ足す。これにより注意出力の更新を全系列の完全再計算から、重要トークンに関係する差分更新へ移す。

論文は理想化した疎演算の複雑度を `O(N·|A|·d)` と説明する。ただし付録Algorithm 4の疑似コードは一度 `QK^T` を計算してsoftmaxし、その後で重要列だけを抽出する形で記述されており、**疑似コードをそのまま実装すれば完全な二乗計算が残る**。実測高速化は§4.1で述べるFlashAttention風の融合CUDA疎カーネルに依存するため、理論式と擬似コード、実装最適化を区別すべきである。

### 4. 応答トークン中心の計算

プロンプトは拡散ステップ間で固定されるため、重要変化は応答側へ集中しやすい。DyLLMは応答のみを処理するステップを設け、一定間隔（論文では4ステップ）でプロンプトも含む入力を与える。ただし全入力を与えるステップでもFFNなどの高価な演算はsalient位置へ限定する。固定間隔で全トークンを強制再計算する方式と異なり、全系列入力と全系列再計算を同一視しない。

### 5. 並列復号との組み合わせ

一度に解除するトークン数 `n_u` を1、2、4と変える条件や、信頼度に応じて解除数を変える方式を評価する。固定refresh型では解除数を増やすと全系列更新の頻度が上がり、性能改善が鈍化する。DyLLMは重要変化トークンを更新するため、解除数を増やしたときも全系列を再計算しない。並列解除による速度と品質の交換は残るが、疎演算と並列解除を組み合わせられることを示す。

## 評価結果と考察

### 元実装・他の高速化方式との比較

| H100・`n_u=1` | 元実装 | DyLLM | Fast-Dual | 注意点 |
|---|---:|---:|---:|---|
| LLaDA GSM8K 正答率 | 77.79% | 79.08%（τ=.99） | 78.24% | 高速化してもこの条件では正答率改善 |
| LLaDA GSM8K throughput | 11.47 tok/s | 87.21（7.60倍） | 75.24（6.56倍） | DyLLMが両指標で上回る |
| LLaDA MBPP 正答率 | 29.20% | 30.00%（τ=.99） | 25.40% | コード課題でも差が出る |
| LLaDA MBPP throughput | 33.11 | 169.62（5.12倍） | 165.44（5.00倍） | 改善幅は課題に依存 |
| Dream GSM8K 正答率 | 75.59% | 78.09%（τ=.995） | 68.39% | Fast-Dualの品質低下が大きい |
| Dream GSM8K throughput | 12.57 | 120.62（9.60倍） | 153.21（12.19倍） | **Fast-Dualの方が速い**が品質が低い |
| Dream MBPP 正答率 | 54.60% | 55.40%（τ=.995） | 51.60% | 品質維持の比較が必要 |
| Dream MBPP throughput | 19.62 | 141.56（7.22倍） | 205.40（10.47倍） | 最速ではない |
| Dream MMLU-Pro 正答率 | 47.94% | 47.21%（τ=.995） | 46.73% | DyLLMでも0.73ポイント低下 |

「最大9.6倍」はDreamのGSM8Kで元実装と比較した倍率である。全モデル・全課題の平均ではない。DreamではFast-Dualがより高いthroughputを出すが、GSM8Kで約7.2ポイントの正答率低下を伴う。品質を固定した等性能比較と、同じ設定の生の処理量比較は別物である。

LLaDAのMMLU-Proでは元37.31%に対しDyLLM τ=.99は36.42%で0.89ポイント低下し、Dreamでも元47.94%に対して47.21%へ低下する。全課題で精度が上がるわけではない。一方、MATHではLLaDA 33.22%→38.08%、Dream 37.60%→43.80%（各τ=.99/.995）となる。近似計算による誤差がたまたま予測分布を改善することもあるが、因果的に「疎化すれば推論力が上がる」とは断定できない。

### saliency閾値と精度

LLaDAのGSM8Kではτ=.995で78.01%、τ=.99で79.08%、Dreamではτ=.9975で79.30%、τ=.995で78.09%、τ=.99で76.04%である。閾値を下げると再計算位置が減り速度は上がりやすいが、品質が単調に改善するわけではない。MBPPのLLaDAではτ=.995で28.20%、τ=.99で30.00%と差が逆向きになる。したがって「一つの閾値でどのモデルにも無損失」は成立せず、モデルごとの校正が必要になる。

### 応答のみ更新と並列解除

1024プロンプト＋256応答トークン、ブロック32の例では、Fast-dLLM PrefixCacheは通常ステップで144トークン、DualCacheは32トークンを処理するが、refreshでは双方1280トークンを再計算する。`n_u=1`での平均はPrefixCache `(144×31+1280)/32=179.5`、DualCache `(32×31+1280)/32=71` トークン/ステップである。DyLLMはrefreshでも高価な計算をsalientへ限定するため、並列解除数を増やしたときにrefreshの費用が支配的になりにくい。

信頼度適応の並列解除を併用したGSM8Kでは、LLaDAの元実装が平均解除3.28トークン/ステップ・正答率77.86%、DyLLM τ=.995は3.20・78.47%となる。Dreamでは元3.82・75.51%、DyLLM τ=.995は3.89・78.62%となる。ただしLLaDA τ=.99は3.18・77.03%へ低下し、こちらも閾値の影響がある。

### B200での再評価

付録のB200・batch16では、LLaDA GSM8Kの元実装31.27 tok/sに対しDyLLM τ=.99は196.24 tok/s（6.28倍）、MATHでは44.41→244.28 tok/s（5.50倍）を報告する。H100での最大9.6倍と同じ倍率をすべてのGPUへ一般化できないが、異なるGPUでも大幅な改善が観測された。ただしB200の数値はバッチ条件が明示されており、H100の全条件と単純なGPU世代間比較を行うべきではない。

## 既存研究との差

Fast-dLLMはprefix/応答ブロックを一定の規則でキャッシュし、一定間隔でrefreshする。dLLM-Cacheは固定の更新割合やデータセット別パラメータに依存する。DyLLMは**各拡散ステップ・各層の注意文脈の変化**を使って更新位置を決めるため、入力や層による計算必要量の違いを反映できる。FFNの省略だけでなく、非salient queryの注意文脈を値差分から更新する点も異なる。

また、元のモデルを再学習しないことは導入コストを下げるが、専用のCUDAカーネルと追加キャッシュを必要とする。一般的なPyTorchのインデックス操作だけでは細粒度疎演算のオーバーヘッドが大きく、論文の高速化はカーネル実装と不可分である。

## 限界・負の結果・再現性

DyLLMはKV以外に注意文脈とFFN出力も保存するため、キャッシュ容量は通常のKVのみの方式より増える。原著はKVだけの保存に比べ、GQAの共有数gと隠れ次元dを使った追加メモリ式を示す。長文脈・大バッチ・VRAM制約が厳しい場合には、計算を減らすための追加キャッシュが同時要求数を制限する可能性がある。

近似誤差の理論上界は出力射影の条件数に依存し、閾値の設定にも敏感である。DreamのMMLU-Proでの精度低下や、閾値を下げ過ぎた場合の品質悪化が示すように、無条件の厳密一致ではない。最速の比較方式より遅い条件もあり、元実装比の最大倍率だけで選ぶと誤る。

さらに、対象はLLaDA 8BとDream 7Bのマスク拡散LLMであり、自己回帰LLMや全種類の拡散モデルへの一般化は未実証である。元の拡散実装と比較した処理量は、他のサービングシステムや大規模分散環境でのTTFT/TPOT/電力効率を保証しない。カーネルと疑似コードの注意計算量の違いにも留意する必要がある。


## 実装時の評価設計と追加監査

DyLLMの運用点を選ぶ場合、単にGSM8Kで最大のtokens/sを示す閾値を選ぶのではなく、各モデルの数学・コード・一般知識ベンチマークで許容できる正答率低下を先に定義する必要がある。原著ではLLaDAとDreamで推奨するτが異なり、同じモデルでもMMLU-ProとGSM8Kでは品質変化の方向が違う。したがって実装時には「高速化倍率が最大」の一行ではなく、タスク別の精度差、生成長別のレイテンシー、各層のsalient率をセットで報告するのが妥当である。

また、DyLLMは前ステップの注意文脈とFFN出力を保存するため、長文脈でのメモリ容量に制約があるGPUでは、計算量の節約がメモリ使用量の増加によって相殺される可能性がある。ユーザーがGPUの空きVRAMを制約とする場合、KVのみのキャッシュ方式と、追加の活性化キャッシュを含むDyLLMを同じ「キャッシュ有効」の条件として比較してはならない。特に並列バッチを増やしたとき、モデル重みの共有と異なり、各要求の活性化キャッシュは要求数に比例して増える。

原著の理論上界は注意文脈の時間的類似性を出発点とし、出力射影の条件数に依存する。特定の層で射影が悪条件であれば、余弦類似度が高くてもFFN入力の変化を過小評価する可能性がある。実機の再現では、重要変化判定を行うタイミング、CUDAカーネルの起動数、salient位置の分布、キャッシュ書換え費用を個別に計測することが必要である。実装の細粒度スパース化が高いGPU利用率を保てない場合、理論上の計算省略量がそのまま高速化に結びつくとは限らない。
