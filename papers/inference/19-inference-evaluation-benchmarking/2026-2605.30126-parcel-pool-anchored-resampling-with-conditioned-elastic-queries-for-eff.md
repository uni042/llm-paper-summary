# PARCEL：空間プールを足場にした可変予算の視覚トークン圧縮

## 概要

視覚言語モデル（Vision-Language Model; VLM）では、画像エンコーダが生成する大量の視覚トークンを言語モデルへ渡す。視覚トークン数が多いほど事前入力処理（prefill）の注意計算と、後続の鍵・値キャッシュ（Key-Value Cache; KVキャッシュ）の負担が増える。PARCELは、視覚トークンの数を16、64、256など異なる予算へ縮めても、空間的な位置関係と画像の細部を両立して保つための、可変予算の視覚表現設計である。

従来の空間プーリング（spatial pooling）だけでは画像を粗い格子へ縮める際に細かな形状や文字が失われる。一方、学習可能なクエリだけで画像全体を少数のトークンへ要約すると、明示的な格子位置の情報が薄れ、物体の位置を指定する課題に弱くなる。PARCELは空間プールトークンを低周波の配置の足場として残し、その足場に条件付けた可変個数のクエリトークンに、プールだけでは失われる補完的な視覚情報を担当させる。

27種類の評価課題を横断した全体平均の性能保持率は、視覚トークン256個で95.6%、64個で95.3%、16個で88.3%と報告された。これらは圧縮しない元のモデルに対する相対的な性能保持率であり、正答率95.6%を意味しない。実機のトークン毎秒やGPUメモリの実測削減率とも異なる。比較対象の空間プールだけ、クエリだけの圧縮より、多くの予算と課題で良い精度・トークン数の交換を示すことが研究の主張である。

## 背景：空間プールとクエリ要約の交換

画像エンコーダの出力を二次元の特徴格子として見ると、隣接するパッチの情報はしばしば似ている。この冗長性を減らす最も単純な方法は、近傍パッチを平均して粗い格子へ縮めることである。格子の位置は残るため、物体が画像のどこにあるかという大まかな配置は保ちやすい。しかし、解像度を落とすと、細い線や文字のような高い空間周波数の成分が失われる。十分な低域通過処理なしに間引けば、高周波成分が低周波へ折り返すエイリアシング（aliasing）も起こり得る。

もう一つの方式は、学習可能な少数のクエリが画像特徴を横断的に参照して、情報を集約するクエリ再標本化（query resampling）である。画像全体から必要な情報を選ぶ自由度がある反面、元の格子と各トークンの位置対応が明示的でなくなる。少数トークンで「左上の物体」「ある領域にある文字」を扱う場合、位置の足場が弱いことが問題になる。

可変予算圧縮では、1つの学習済みモデルを複数の視覚トークン数で動かす。圧縮の程度に応じて別モデルを学習し直すのではなく、運用時に予算を選べることが重要である。従来のネストしたプーリングやクエリの方式は、特に16トークンのような強い圧縮で性能が落ちやすい。PARCELは、少数予算でまず配置の基礎を確保し、余裕があるときにクエリを追加する役割分担でこの問題に取り組む。

## 手法

### 1. 空間プールを基礎トークンとして残す

画像特徴の格子を空間的に縮約し、位置対応のあるプールトークンを生成する。これらは画像の低周波成分、すなわち大きな物体の配置や大まかな輪郭を表す基礎として機能する。強い圧縮ではプールトークンだけを残す場合もあり、予算が増えたときに追加のクエリトークンを使う余地ができる。

この設計では、画像のどの位置を代表するかが分かるプールトークンを捨てないことが重要である。学習クエリだけに全情報を集約すると、画像全体の意味はある程度保てても、局所的な位置関係が失われやすい。PARCELは空間配置を低周波の足場として先に固定し、その上に細部の抽出を追加する。元の画像特徴そのものをすべて復元することが目的ではなく、言語モデルの視覚理解に必要な情報を限られたトークンへ収めることが目的である。

### 2. プール条件付きクエリ再標本化（PCQR）

プール条件付きクエリ再標本化（Pool-Conditioned Query Resampling; PCQR）は、追加の学習可能なクエリが、画像特徴を参照するときにプールで得た空間の足場を条件として使う。プールがすでに持っている大まかな配置情報をクエリが重複して表すのではなく、プールでは拾いきれない細部や補完的な特徴を集めるように設計する。

この「役割の分担」は、画像特徴を直接読むクエリのみの方式と、空間プールのみの方式の中間に位置する。プール側が空間の位置関係を保ち、クエリ側が高い空間周波数や局所的な手掛かりを補う。原著はこの設計を、空間プールだけでは生じるスペクトルの折返しと、クエリだけでは生じる空間接地の喪失の両方を緩和するためのものと位置付ける。

クエリの寄与は予算によって変わる。少ない予算ではプールの足場を優先し、予算が十分なときにはクエリを追加して細部を拾う。したがって、クエリが多ければ常に良いという単純な方式ではなく、どの予算でどの種類のトークンを使うかという配分規則が必要になる。

### 3. 予算に応じた段階的な割当て

PARCELは16、64、256視覚トークンの各予算で同一モデルを動かすため、プールトークンの数とクエリトークンの有効数を予算に応じて切り替える。原著は予算対応の段階的なルーティング（budget-aware piecewise routing）を使い、低予算では空間プールを優先し、高予算では空間基礎に加えてクエリの寄与を増やす。学習にはネストした予算を扱う仕組みが用いられ、1回の学習で複数のトークン予算へ対応する。

この設計の効果は、固定プール配置を使う除去実験で確認できる。16トークンに対応する強い空間圧縮の配置を、64や256トークンの予算でも固定すると、追加の予算があっても大きな改善が得られない。反対に、64トークン向けの比較的細かいプール配置を維持すると、16トークンの極端な予算には適用できない。予算の増減に応じて、空間配置の足場自体も変える必要がある。

### 4. 画像特徴の周波数解析

原著は圧縮後の特徴がどの空間周波数を保つかを調べるため、二次元の離散フーリエ変換（Discrete Fourier Transform; DFT）を用いた解析を行う。画像特徴の各チャネルから空間平均を引き、二次元変換で得たパワーをチャネル平均して周波数ごとの強度を測る。元の格子と縮小後の格子は解像度が違うため、同じ範囲の周波数を無理に比較しない。論文はそれぞれの格子に収まるナイキスト半径を用いて比較範囲を限定する。

この解析は、プールが低周波を残し、クエリが補完的な高周波情報を拾うという仮説を検討するためのものである。周波数スペクトルだけで質問への正答率を証明することはできないため、後述の空間接地、文書画像、動画のベンチマークも必要になる。

## 評価条件

| 項目 | 内容 | 注意点 |
|---|---|---|
| 対象 | 視覚言語モデルの視覚トークン圧縮 | LLMの重み量子化やKV事後削除とは別 |
| 視覚トークン予算 | 256、64、16 | 同一の学習済みモデルで切替 |
| 評価 | 画像・動画を含む27ベンチマーク | 各課題の尺度を相対保持率で集約 |
| 主な比較 | MQT、M³などの可変予算圧縮方式 | 同じ視覚トークン予算で比較 |
| 空間接地 | RefCOCO系 | 物体位置の理解を確認 |
| 細部の理解 | DocVQA、ChartQA | 文字・図表・局所情報を重視 |
| 動画理解 | 複数の動画課題 | 時間方向の情報も含む |
| 主指標 | 元の圧縮なしモデルに対する性能保持率 | 正答率そのものではない |

「保持率95%」は元のモデルの課題得点を100としたときの比率である。元モデルが60%正答なら、保持率95%の圧縮後の正答率は約57%であり、95%正答ではない。トークン数の削減がそのままGPUの端から端までの速度向上率になるわけでもない。論文の主結果は精度と視覚トークン数の交換を示す。

## 主要結果

### 27課題の平均性能保持率

| 視覚トークン数 | PARCELの全体平均保持率 | 解釈 |
|---|---:|---|
| 256 | **95.6%** | 比較的余裕のある予算で高い保持率 |
| 64 | **95.3%** | 256と近い平均保持率 |
| 16 | **88.3%** | 強い圧縮で品質が下がるが比較方式より優位 |

画像課題だけを平均した場合は256トークンで95.1%、64トークンで94.7%、16トークンで86.8%だった。動画課題の平均はそれぞれ98.0%、97.9%、95.0%と報告される。画像と動画では元の視覚情報の分布が異なり、同じ16トークンでも平均的な品質低下幅が違う。全体平均だけでは画像の細部を要する課題の悪化を見落とす。

### 空間接地と細部の認識

RefCOCO系の空間接地課題では、16トークンの平均保持率がPARCEL80.5%、クエリ型比較MQT79.0%だった。256トークンではPARCEL90.6%で、MQTを4.2ポイント、M³を8.9ポイント上回る。プールで空間の足場を保持する設計が、物体の位置を扱う課題で有利に働くという解釈を支える。

DocVQAやChartQAなど解像度に敏感な課題群のうち、圧縮に敏感な上位3課題を平均すると、16トークンではPARCEL77.1%、M³75.5%、MQT74.2%だった。64トークンではPARCEL90.0%、256トークンでは90.8%と報告される。少数トークンでも相対的には最良だが、16トークンの保持率77.1%は元の性能から約23%の相対低下があることを意味する。細部の認識が厳しい用途ではこの品質損失を許容できるかを確認する必要がある。

動画の圧縮に敏感な上位3課題では、16トークン時の保持率がPARCEL92.8%、MQT91.1%、M³88.8%だった。平均的な動画課題の保持率95.0%と、特に難しい課題群の92.8%は異なる集合の指標である。動画全体の情報を少数の視覚トークンへまとめるため、質問に関係する時間的な出来事が失われる可能性も残る。

### 構成要素除去実験

| 方式 | 256トークン | 64トークン | 16トークン | 主な示唆 |
|---|---:|---:|---:|---|
| PARCEL全機構 | 95.6% | 95.3% | 88.3% | 全体の基準 |
| 空間プールのみ4×4 | 対象外 | 対象外 | 83.1% | クエリを使わないと低予算でも性能が落ちる |
| 空間プールのみ2×2 | 対象外 | 92.8% | 対象外 | 64トークンでは全機構に劣る |
| 4×4固定配置 | 90.2% | 89.6% | 88.3% | 高予算でも強圧縮配置を維持すると伸びない |
| 2×2固定配置 | 95.6% | 95.2% | 対象外 | 高予算には適するが16には対応不可 |
| 画像特徴のみを読む交差注意 | 95.2% | 95.3% | 87.9% | プール条件付けなしでは一部低下 |
| 二重交差注意（画像＋プール） | 95.4% | 95.2% | 88.0% | 単純に注意経路を増やすだけでは最良でない |
| 自己注意を追加したMQT | 93.3% | 92.5% | 87.8% | 比較方式の容量増加だけでは差を埋められない |
| 自己注意を追加したM³ | 92.2% | 90.4% | 86.8% | 同上 |

固定4×4の空間プール配置では、16トークン時の88.3%は全機構と同じだが、64や256へ予算を増やしても89.6%、90.2%にとどまる。これは、クエリ数だけ増やせば高予算を有効活用できるわけではなく、空間の足場の解像度も予算に合わせる必要があることを示す。プールのみの16トークンは83.1%で、PARCEL全体88.3%より5.2ポイント低い。

クエリの注意設計では、画像特徴だけを参照する場合に16トークン87.9%、画像とプールの二重交差注意では88.0%、PARCEL全体では88.3%だった。差は大きくないが、プールに条件付けて補完的な情報を抽出するという設計と整合する。ただし、この程度の差について統計的な有意性が別途示されているとまでは断定しない。

## 既存研究との差

ネストした空間プールだけの方式は、格子位置を維持できるが細部の情報を失いやすい。ネストしたクエリだけの方式は、重要特徴を選ぶ自由度があるが、画像内のどこに何があるかという位置情報が弱くなりやすい。PARCELはプールを空間の低周波の足場として固定し、クエリをその足場へ条件付けることで、両方式の弱点を補う。

視覚トークンの圧縮は、生成後にKVキャッシュだけを間引く方式とも異なる。言語モデルへ入る視覚トークン自体を減らすので、入力処理の計算とKVキャッシュの両方へ影響する。一方、圧縮後に失われた画像情報は後段の層で直接復元できない。したがって、事後的なKV削除より事前の圧縮品質が重要になる場合がある。

「一度学習して複数の予算で動かす」という点では、各予算専用のモデルを別々に訓練する方式より配備の柔軟性が高い。低遅延の要求では16トークン、品質を優先する要求では256トークンなど、同じ重みで予算を切り替えられる設計である。ただし、要求ごとに切り替えた場合のスケジューラやGPU実測性能は、この精度表だけでは評価できない。

## 限界・実装上の注意

第一に、結果は27課題の相対性能保持率を中心とする。保持率は視覚トークン数の減少に対する品質の維持度を表すが、実際のGPU処理量、P95遅延、VRAM消費、電力を直接示すものではない。視覚トークンが減っても画像エンコーダの計算や言語モデルの生成処理が残るため、トークン数の削減比をそのまま速度倍率に換算できない。

第二に、画像の高周波情報をクエリが拾うという設計でも、16トークンの極端な圧縮ではDocVQA・ChartQAなどの細部課題で保持率が約77%に下がる条件がある。文字や細い境界が正答に必須の用途では、平均保持率だけでなく課題別の最悪条件を調べる必要がある。

第三に、プールの格子解像度とクエリの役割分担は、画像エンコーダの出力形状、入力解像度、視覚トークン予算に依存する。16、64、256以外の任意の予算で連続的に最適化できることや、別の視覚言語モデルへ学習なしで移植できることを今回の結果からは保証できない。

第四に、同じ重みを複数の予算で動かすための学習設計が必要である。学習済みの任意の視覚言語モデルの視覚トークンを単に間引けばPARCELと同じ精度になるわけではない。今回確認した原著の範囲では公式実装URLを特定できず、公開コードが直ちに使えるとは断定しない。

**採用判断:** 画像や動画の入力で言語モデルの事前入力処理とKVキャッシュが重い場合、複数の視覚トークン予算を1つの学習済みモデルで切り替える設計として有用である。特に空間接地と細部の認識の両方を要求する場合、プールとクエリの役割分担が重要になる。ただし、実機の処理時間と厳しい圧縮下での品質損失を別途測定してから採用すべきである。
