# ServeGen: Workload Characterization and Generation of Large Language Model Serving in Production

## 概要
LLMサービング研究では、ポアソン到着とShareGPT等の静的データセットを組み合わせた人工負荷が頻繁に使われる。しかし本番では、要求到着率、バースト性、入力・出力長が時間と顧客によって同時に変化する。ServeGenはAlibaba Cloud Model Studioから4か月、12モデル、合計35.4億要求を分析し、集約負荷の複雑さの多くが少数の大口顧客の到着率変化で説明できることを示す。言語モデルだけでなく画像・音声・動画を含むマルチモーダルモデルと推論モデルも対象にする。

提案するServeGenは負荷全体へ単一分布を当てず、顧客ごとに到着過程と入出力データ分布をモデル化して最後に合成する。この因果的な分解により、単純生成では失われる時間変動と異質性を再現する。Qwen2.5-14Bを2枚のA100 80GBで動かすvLLM設備計画では、P99の最初のトークンまでの時間（Time To First Token; TTFT）2.25秒、トークン間時間（Time Between Tokens; TBT）0.5秒という条件で、実負荷に必要な24相当のインスタンスに対しServeGenは25台（4%過剰）、単純生成は12台（50%不足）と推定した。

## 問題設定
既存の負荷生成は「到着時刻」と「要求内容」を独立にサンプリングすることが多い。実負荷ではこの独立仮定が崩れる。例えばM-smallでは2,412顧客のうち上位29顧客だけで90%の要求を占め、各顧客のバースト性や入出力長は比較的安定している一方、顧客ごとの到着率が時間で変わる。その合成結果としてサービス全体のバースト性や平均長が大きく移動する。

この差は単なる統計上の見栄えではない。入力長はプリフィル計算、出力長は復号時間、到着のバーストは待ち行列とバッチ形成を変えるため、負荷生成が簡単すぎると必要GPU数やプリフィル・復号分離比率まで誤る。マルチモーダルでは前処理・エンコーダ負荷、推論モデルでは長い思考列も加わるため、従来のテキスト中心traceだけでは不足する。

## 手法
### 大規模本番負荷の特徴抽出
言語モデルについて、短時間の到着間隔、5分窓の要求率と変動係数、入力・出力長、両者の相関を分析する。短期到着は変動係数が1を超えるバーストを頻繁に示すが、指数・ガンマ・ワイブルのどれか一つが常に最良ではない。一般用途モデルの入力長はパレートと対数正規の混合で裾を表しやすく、出力長は指数分布がよく合う例が多い。平均長も時間で動き、観測例では入力平均が最大1.63倍、出力平均が最大1.46倍変化する。

### 顧客分解
集約traceを顧客IDで分け、各顧客について要求率、バースト性、長さ分布を推定する。重要な観測は「大口顧客の局所的な振る舞いは比較的安定し、主に要求率が変化する」ことにある。ServeGenはこの性質を使い、顧客ごとの局所モデルを入力として時間窓ごとの要求列を生成し、最後に全顧客を合成する。出力は到着時刻、入力・出力長等を持つサービングtraceである。

### マルチモーダル・推論負荷
画像、音声、動画では入力個数とトークン化後長さがテキストとは異なる不規則な分布を持ち、テキスト量との相関も弱い。推論モデルでは思考tokenと回答tokenを分け、長い思考長や複数ターン到着を分析する。これらも顧客単位へ分解することで、単一の全体分布より実負荷に近い合成を行う。

### 設備計画と分離実行への接続
生成traceをvLLMやSGLangへ実際に流し、TTFT/TBTのサービス水準目標（Service Level Objective; SLO）を満たす最大要求率を測る。設備計画ではその最大率から必要instance数を計算し、実traceを流した結果と比較する。プリフィル・復号分離の事例ではQwen2.5-72Bを4ノード×8 H20で動かし、プリフィル側と復号側のinstance比率を変えて、負荷モデルが設計選択へ与える影響を見る。

## 既存研究との差
BurstGPT等は特定の到着特性を分析するが、ServeGenは言語・マルチモーダル・推論モデルを同一の本番基盤から大規模に比較し、さらに顧客分解を生成モデルへ直接接続する。単に公開traceを再生するのではなく、顧客ごとの安定分布と時間変動するrateを組み合わせるため、規模や時間帯を変えた合成が可能である。

## 限界
観測元は一つの大規模クラウド事業者であり、別地域・別製品の顧客構成が同じとは限らない。要求本文そのものではなく匿名化されたメタデータを中心に扱うため、意味内容に起因する計算差は直接モデル化しない。設備計画例では予算上、本番M-largeそのものではなくQwen2.5-14Bを使う。ServeGenは現実性を高める負荷生成器であり、将来の未観測アプリケーションの分布変化を自動的に予言するものではない。
