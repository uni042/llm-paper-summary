# SABER: Stability-Aware Early Exit for LLM Reasoning via Adversarial Branch Probing

> 推論の途中で「前の推論は間違い」と揺さぶる短い分岐を伸ばし、答えが揺らがなければ収束したとみなして早期終了する方式で、推論トークンを3から4割削りながら正解率を保った。

## 概要

大規模推論モデルは、長い思考連鎖を生成することで難しい問題を解く。しかし生成の後半は、新しい情報を生まない検証や反省の繰り返しになりがちである。中間の答えが既に安定しているのに推論を続ける過剰思考は、トークンと遅延を浪費し、場合によっては誤りの蓄積で正解率まで下げる。止めるべき時点をどう判定するかが課題であり、従来の信号には弱さがあった。信頼度やエントロピーを使う方式は、推論モデルが誤っていても高い信頼度を示す較正のずれに弱い。中間答えの一致を使う方式はより確かだが、複数ステップにわたる一致の蓄積を待つため、終了の判断自体が遅れる。

本論文の出発点は、正解へ向かう軌跡と不正解の軌跡で、摂動への反応が違うという観測である。中間状態へ意味的な揺さぶりを加えたとき、正解軌跡では分岐先の予測が次第に一致し、信頼度の変動も小さくなる。不正解軌跡では、後半でも答えが食い違い、信頼度が大きく揺れ続ける。提案するSABERはこの性質を判定信号へ変える。推論の遷移点で、現在の推論接頭辞から2種類の短い分岐を伸ばす。1つは「要約しよう。答えは」という中立の促し、もう1つは「前の推論は間違っていた。直すと答えは」という敵対的な促しである。各分岐で答えを短くサンプリングし、両分岐の答えの一致度（意味的一致）と信頼度の平均の差（信頼度安定）を合成した推論安定性スコアを計算する。スコアがしきい値を超えたら推論が収束したとみなし、終了タグを注入して最終回答の生成へ移る。

**代表結果:** 数学と科学の7ベンチマークと3モデル（Qwen3-4B、Qwen3-8B、DeepSeek-R1-Distilled-Qwen-7B）で、SABERは推論トークンを30.2から39.8パーセント削減しながら、通常推論と同等以上の正解率を保った。DeepSeek系の7Bでは全体正解率が67.8から69.0へ上がり、使うトークンは69.8パーセントだった。推論遅延は平均48.8パーセント減り、プローブ自体の追加トークンは全体の平均3.8パーセントにとどまる。

## 問題設定

早期終了の難しさは、止める判断の誤りが非対称な費用を持つことにある。早く止めすぎれば、まだ固まっていない推論を誤答で固定する。遅く止めれば節約にならない。しかも判定信号は、判定のために余分な生成を要するなら本末転倒であり、安くなければならない。信頼度は安いが、推論モデルは誤った軌跡でも高い信頼度を維持しやすく、単独では収束と自信を区別できない。一致型は、将来のステップまで実際に生成して初めて分かるため、節約できるはずのトークンを判定のために先に使ってしまう。本論文は、収束を「将来の生成を待つ」のではなく「その場で揺らして反応を見る」ことで測る問題として設定し直す。揺さぶりに使う分岐は最大10トークンに制限し、並列に実行できるため、判定費用は小さく抑えられる。さらに、答えの一致だけでは「安定して間違っている」軌跡を止めてしまう危険があり、信頼度の安定を併用する理由もここにある。

## 手法のあらまし

推論は通常どおり自己回帰で進む。SABERは軌跡を監視し、「Wait」などの遷移語が現れた時点で分岐プローブを実行する（評価では追加費用を抑えるため、主にWaitの出現時に限定）。現在の推論接頭辞に中立と敵対の2種類のプローブ文を続け、各分岐で答えを最大10トークンだけ、既定では4回サンプリングする。得られた答えの集合から意味的一致を、信頼度の集合から信頼度安定を計算し、重み付き和の推論安定性スコアがしきい値（モデルにより0.9または0.95）を超えたら、終了タグを注入して最終回答を生成させる。超えなければ分岐は捨てられ、通常の推論が再開する。学習は行わず、モデルの重みは変えない。

## 手法

### 1. 敵対分岐プローブ — 中立と敵対の2つの促しで中間状態を揺らす

この機構が観測するのは、遷移点における現在の推論接頭辞である。保持する状態は持たず、その場で2種類の分岐を作る。中立分岐は推論を要約して答えを出させる促しであり、敵対分岐は「前の推論は間違っていた」という誤った訂正信号を注入して、同じ接頭辞から答えを出させる。各分岐では確率的デコードで答えを複数回サンプリングし、答えの多重集合と、各続きのトークン確率から計算した信頼度を集める。行う動作は、完全な軌跡を最後まで展開するのではなく、答えに絞った短い続きだけを生成することであり、これが判定を安くする核心である。減るボトルネックは、一致の確認のために本流の推論を先へ進める必要である。追加で消費する資源は分岐の生成であり、総トークンの平均3.8パーセントである。失敗条件は、敵対の促し自体が弱すぎて揺らぎを生まない場合や、逆に正しい推論を本当に崩してしまう場合であり、プロンプト様式の感度は付録で分析されている。なお本流の生成は分岐の影響を受けず、分岐は捨てられるだけなので、止めない限り生成結果は変わらない。

### 2. 推論安定性スコア — 答えの一致と信頼度の安定を合成する

この機構が観測するのは、2つの分岐から得た答えの多重集合と信頼度の集合である。意味的一致は、両分岐における各答えの出現頻度の小さい方と大きい方の比を、全ての答えについて合計した多重集合版のジャッカード類似度である。信頼度は、各続きについてトークンごとの最大予測確率の幾何平均を取り、その分岐内平均同士の差に感度係数（全実験で3）を掛けて指数関数で変換したものが信頼度安定になる。保持する状態は持たず、2つのスコアを重みで合成した推論安定性スコアだけが判定へ渡る。重みの最適値は課題の難しさで変わり、簡単なGSM8Kでは意味的一致の重み0.7が最良で、難しいOlympiadBenchでは信頼度安定を重くする小さい重みが最良だった。これは、難しい課題では意味的に一致していても誤っている軌跡が増えるためである。減るボトルネックは、単一信号の盲点である。一致だけなら安定した誤答を止めてしまい、信頼度だけなら自信過剰な未収束状態を止めてしまう。誤った場合の挙動として、両信号とも高いのに誤っている軌跡では早期終了が誤答を固定する。この危険は除去実験で、片方の信号だけを使う変種が難しいベンチマークで大きく落ちることからも裏付けられている。

### 3. 早期終了の決定 — しきい値を超えたら終了タグを注入する

この機構が観測するのは推論安定性スコアであり、しきい値と比較する。行う動作は、スコアがしきい値を超えた時点で推論の終了タグを接頭辞へ注入し、モデルに最終回答を生成させることである。しきい値が高いほど終了は慎重になり、正解率は上がるがトークンも増える。OlympiadBenchでの感度分析では、しきい値0.8から0.95の範囲で性能は比較的安定しており、細かい調整は要らない。サンプル数の感度では、4回までは正解率が大きく上がる（MATH-500で88.8から91.6パーセント）が、32回まで増やしても追加の改善は0.4ポイントにとどまり、プローブの割合は3.3から22.7パーセントへ増えるため、既定の4回が費用と精度の釣り合い点である。減るボトルネックは、安定後の検証や反省に使われる推論トークンそのものであり、難しい課題ほど推論が長いため、遅延の削減率は平均48.8パーセントと、トークン削減率より大きくなる。

## 評価

### まず見るところ

- **結論:** 摂動下の安定性は、信頼度単独より確かな終了信号になる。トークン3から4割減、正解率は維持か改善、遅延は約半減だった。
- **速度・効率:** 実機測定。推論トークンの圧縮率はモデル平均で60.2から69.8パーセント（通常推論比）、遅延は3ベンチマーク平均で48.8パーセント減。プローブ費用は総トークンの2.8から4.9パーセント。
- **品質:** 近似。全体では通常推論と同等以上だが、信号の片方だけを使う変種は難しい課題で落ちる。併用の重要性が除去実験で示されている。
- **評価の強さ／注意点:** 4Bから8Bの文章推論のみで、大規模モデル、多モーダル、エージェント条件は未評価と論文が明記している。

評価はvLLM、RTX 3090を8基搭載したサーバーで行われ、最大文脈長32K、最大生成長16K、温度0.6である。ベンチマークはGSM8K、MATH-500、AMC23、OlympiadBench、AIME24と25、GPQA Diamondの7つで、指標は正解率、平均推論トークン数、通常推論に対する圧縮率である。比較対象は通常推論、推論を省くNoThinking、信頼度型のDEER、一致型のDynasorである。小さいベンチマークは各事例を4回評価して平均している。

## 既存研究との差

DEERは中間状態の信頼度で終了を決める方式であり、本論文は信頼度を摂動下での安定性として測り直す点が異なる。Dynasorは中間答えの一致を使うが、一致の蓄積に複数ステップを要するのに対し、本方式はその場の分岐で一致を測る。隠れ状態へプローブを学習させる方式群とは、学習不要でモデル固有の適応が要らない点が異なる。推論パスの摂動そのものを研究する先行研究は脆弱性の分析が目的であり、本論文は摂動への安定性を効率化の制御信号へ転用した点に新規性がある。

## 限界・実装状況

- 評価は4Bから8Bの文章推論ベンチマークに限られ、大規模モデルでは未検証である。計算資源の制約によるものと論文が述べている。
- 多モーダル条件とエージェント条件では、中間表現や信頼度の動きが異なり得るため未評価であり、今後の課題とされる。
- 重みとしきい値はモデルとデータセットごとに探索で選ばれており、未知の課題へそのまま持ち越せるかは未検証である。ただししきい値0.8から0.95では性能が安定していると報告される。
- 安定しているが誤った軌跡では早期終了が誤答を固定する危険が残る。実装は公式GitHubリポジトリで公開されている。

## 一般的な実装上の含意

生成を止める判断は、生成物の統計（信頼度）だけを見るより、入力へ小さな摂動を加えて出力の揺らぎを測る方が、収束の判定として確かになり得る。この能動的な測定は、判定用の分岐を短く制限し並列化すれば、本流の節約量より十分安くできる。早期終了を入れる際は、節約率だけでなく、判定自体の費用率と、信号を片方だけにしたときの劣化を併せて測ると、方式の弱点が見える。
