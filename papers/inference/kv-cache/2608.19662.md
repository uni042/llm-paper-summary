# ReCache: Efficient KV Cache Reuse and Compression for Tool-Augmented LLM Agents

> ツール／スキル定義を組合せ非依存のKVブロックとして再利用し、重要な層・KVヘッド群と呼出し必須フィールドだけを残して、エージェント推論のプリフィルとKVメモリを削減する。
## 書誌情報
- **著者**: Yichu Fang, Sitong Wei, Haozhe Hu, Xiaoyu Shen
- **著者・所属**: Shanghai Jiao Tong University; Eastern Institute of Technology, Ningbo; Xi’an Jiaotong University
- **公開**: arXiv:2608.19662v1
- **種別**: プレプリント
- **対象**: KVキャッシュ、エージェント推論、ツール呼出し、プリフィル高速化、キャッシュ圧縮
- **実装**: 著者公式コード EIT-NLP/ReCache が公開されている。
## 概要
ReCacheは、エージェント型LLMが要求ごとに異なる順序・組合せで再利用するツール／スキル定義を、通常の接頭辞キャッシュでは再利用できず毎回プリフィルする問題を扱う。各リソース内だけで注意を計算し位置番号もリソース内で付け直すことで、周囲のリソースに依存しないKVブロックを作る。さらに呼出し損失への寄与で重要な層とKVヘッド群だけにリソースKVを見せ、リソース名・引数名・引数説明・末尾トークンだけを保持する。Qwen3-4Bを中心とした7データセット統合評価で、再利用だけなら密注意とほぼ同等の呼出しF1を保ちつつTTFTを3.655倍高速化し、完全構成ではKVテンソル割当量を92.43%削減、注意計算を1.423倍高速化した。

ReCacheは再利用可能性を後処理で近似するのではなく、KVを作る時点で各ツール／スキルを独立した計算単位へ変える。リソース間注意を除き、各リソースの位置番号を0始まりの局所位置へ戻すことで、前後にどのリソースが置かれても同じKVブロックを生成する。そのうえで、呼出し損失をどれだけ減らすかという寄与を使って重要な層とKVヘッド群を選び、選ばれた経路だけがリソースKVを見る。さらにリソース名、引数名、引数説明、末尾トークンを残すフィールド認識型の意味枝刈りを行い、正確なAPI呼出しに必要な情報を優先して保持する。

代表結果として、先頭トークン待ち時間はリソース単位注意の完全可視構成、分布内でDense 26.319 msに対して7.200 ms。組合せ非依存KVの再利用により3.655倍高速化。
## 問題設定
エージェント型LLMでは、ユーザー要求に応じて多数のツールやスキルから必要な定義を検索し、そのスキーマを入力へ挿入する。同じツール定義は要求をまたいで何度も現れるが、組合せや並び順が変わるため、同一接頭辞を要求する通常のKV接頭辞キャッシュでは再利用できない。その結果、内容が変わらないリソースを毎回プリフィルしてKV状態を作り直す。位置非依存キャッシュは位置補正や一部再計算を必要とし、さらに完全なリソースKVを保存・読み出すだけでもリソース数と長さに比例してメモリと注意計算が増える。ツール呼出しでは名前や引数の厳密性が必要なため、一般文章向けの強い圧縮をそのまま適用すると呼出し失敗や幻覚が増える。
## 新規性
ReCacheは再利用可能性を後処理で近似するのではなく、KVを作る時点で各ツール／スキルを独立した計算単位へ変える。リソース間注意を除き、各リソースの位置番号を0始まりの局所位置へ戻すことで、前後にどのリソースが置かれても同じKVブロックを生成する。そのうえで、呼出し損失をどれだけ減らすかという寄与を使って重要な層とKVヘッド群を選び、選ばれた経路だけがリソースKVを見る。さらにリソース名、引数名、引数説明、末尾トークンを残すフィールド認識型の意味枝刈りを行い、正確なAPI呼出しに必要な情報を優先して保持する。
## 手法
### 手法のあらまし
処理はオフラインのキャッシュ構築・経路選択と、オンライン要求処理に分かれる。まずシステム指示を共有接頭辞として、各ツール／スキル定義を別リソースとして符号化する。このときリソースAのトークンからリソースBへの注意を遮断し、各リソースの位置番号を先頭から同じ局所番号へ付け直す。したがって同じリソースなら、検索された順序や隣接リソースが変わっても同一のKVブロックを生成でき、事前保存したブロックを要求間で再利用できる。次に学習済みモデルを用い、会話側からリソースKVをまったく見せない状態を基準に、特定の層またはKVヘッド群だけへ可視性を戻したとき正解ツール呼出し区間の損失がどれだけ下がるかを測る。寄与の大きい層上位K個とヘッド群上位K個の直積だけをリソース可視経路として固定し、それ以外の経路は通常会話文だけを見る。さらに保存・参照するリソースKVを、リソース名、引数名、引数説明、末尾トークンへ絞る。オンラインでは問い合わせに対して検索されたリソースIDから事前KVブロックを読み出し、意味枝刈り済み状態を選択経路へ接続してデコードする。これにより毎要求のリソース再プリフィルを除去し、同時にKVメモリと会話からリソースへの注意計算を削減する。

### リソース単位注意
各ツール／スキル定義を独立キャッシュ可能にする入口である。通常の因果注意では前に置かれた別リソースも参照するため、同じツールでも並び順が変わるとKVが変化する。ReCacheはリソース内トークンから共有システム接頭辞と同一リソース内だけへの注意を許し、別リソースへの辺を消す。総リソース長をD、各リソース長をDiとするとリソース間の注意計算はDの二乗から各Di二乗の和へ減る。さらに各リソースの位置番号を局所的に0始まりへ揃え、大域的な挿入位置への依存を除く。出力は組合せと順序に依存しないKVブロックであり、同じリソースを別要求へそのまま差し込める。代償としてリソース間の意味的相互作用と大域順序情報を捨てるため、それらが呼出し判断に重要なタスクでは品質が落ち得る。

### 寄与誘導型の構造枝刈り
再利用可能KVを作っても、全36層・全KVヘッド群から長いリソースを参照すればデコード注意とKV読出し費用が残る。そこで会話トークンがリソースKVを見られる経路を層とKVヘッド群の組として定義する。基準状態では全リソースを不可視にし、ある層だけ、またはあるKVヘッド群だけを可視に戻したとき、正解のツール／スキル呼出しトークン区間の負の対数尤度がどれだけ下がるかを寄与得点とする。正の寄与を正規化し、層とヘッド群それぞれの上位K個を選んで直積を最終経路にする。Qwen3-4Bでは36層中20層と8群中3群で、約79.2%の経路からリソース可視性を除く。選外経路は会話文の通常因果注意を維持するためモデル全体を削除するわけではない。

### フィールド認識型の意味枝刈り
構造枝刈り後も、選ばれた経路が完全なツールスキーマを見るとKV容量と注意長が残る。一般文書の要約圧縮ではツール名や引数キーのような一文字違いでも失敗する情報を失いやすいため、ReCacheはスキーマ構造を利用する。各リソースから実行対象を特定するリソース名、JSON等のインターフェースを決める引数名、値制約を伝える引数説明を保持し、さらに因果表現として前方情報を集約できる末尾トークンを残す。その他の説明・書式トークンのKVは選択経路から除外する。出力は短いリソースKV列であり、構造枝刈りと組み合わせることで参照経路数と各経路の参照トークン数を同時に減らす。アブレーションでは名前だけでは不十分で、引数名と引数説明を順に戻すほど呼出しF1が回復する。

### 全体のデータ／制御の流れ
キャッシュ構築とオンライン利用を分離する。比較的安定したシステム指示とリソーススキーマに対して、リソース単位注意で再利用可能KVを事前構築する。学習・選択段階では呼出し損失から可視経路を決め、意味枝刈りで保存対象トークンを決める。オンライン要求では検索されたリソースの既存KVブロックを再利用し、会話側は選択された層・KVヘッド群だけから圧縮済みブロックを参照する。未知の組合せでもリソース自体が既知なら再符号化を避けられる一方、リソース間相互作用や順序そのものが意味を持つ環境では、独立化の仮定が崩れて精度低下し得る。
## 評価条件
- **ハードウェア**: 主モデルQwen3-4BはNVIDIA A800 GPUで完全微調整し、構造予算のモデル規模感度を調べるQwen3-1.7Bの予備実験はNVIDIA RTX 5000 GPUで実施する。
- **ソフトウェア**: Qwen3-4BとQwen3-1.7Bを使用。著者公式コードはEIT-NLP/ReCacheで公開。比較対象には通常の密注意、リソース間注意だけを遮断するBlock、SPEED、注意量で経路選択する方式、Gist、活性値 Beacon、フィールド認識型意味枝刈り単独などを含む。
ToolACE、APIGEN、ToolMind、ToolRet、Toucan、SkillRouter、WildToolBenchの7データ源を統合する。無効呼出しや未宣言リソースを除外し、同じリソース名・候補集合への偏りを抑える多様性優先抽出を行い、学習49,424例を構成する。予備実験は5,000例。評価は学習で見たリソースを使う分布内1,000例と、学習に存在しないリソースだけを使う分布外1,000例。正確なリソース名と全引数が一致した場合だけ正解とするターン平均呼出しF1、リソース識別F1、存在しないリソース名の幻覚率を測る。効率はキャッシュ命中時の先頭トークン待ち時間、出力1トークン当たり時間、注意計算遅延、KVテンソル割当メモリを測る。
エンドツーエンド結果は主にQwen3-4Bで、Qwen3-1.7Bは構造予算の規模依存性確認に使う。評価はツール／スキル呼出しという構造化リソース利用に集中し、一般長文生成や検索拡張生成全般を直接対象にしない。完全パラメータ微調整が前提で、凍結モデルへの適用、Qwen以外のアーキテクチャ、大規模な実運用エージェント基盤は未評価である。
## 主要結果
リソース単位注意だけでも、密注意の呼出しF1 82.4に対して82.3を維持し、キャッシュ命中時の先頭トークン待ち時間を26.319msから7.200msへ短縮して3.655倍高速化した。Qwen3-4Bで36層中20層・8 KVヘッド群中3群を残す寄与誘導型構造枝刈りは、KVメモリを79.27%削減しつつ呼出しF1 82.1を維持する。構造枝刈りと意味枝刈りを組み合わせたReCacheは、分布内でKVテンソル割当を92.43%削減し注意計算を1.423倍高速化、呼出しF1は80.3となる。分布外では密注意66.3に対して60.8で、未知リソースでも密注意性能の91.8%を保持する。リソース長が1万トークン以上へ伸びる条件では、密注意の先頭トークン待ち時間が5秒超へ増える一方、ReCacheは約5ms強でほぼ一定、KV割当も0.03GiBに抑える。

- 先頭トークン待ち時間 / 7.200 ms (比較対象: Dense 26.319 ms; 条件: リソース単位注意の完全可視構成、分布内) — 組合せ非依存KVの再利用により3.655倍高速化。

- KVテンソル割当メモリ削減 / 92.43%削減 (比較対象: Dense; 条件: 完全ReCache、分布内) — 構造経路と保持トークンの両方を削ることで大幅なKV削減。

- 注意計算高速化 / 1.423倍 (比較対象: Dense; 条件: 完全ReCache、分布内) — リソースKVを参照する層・ヘッド群・トークンを同時に減らした効果。

- 呼出しF1 / IND 80.3 / OOD 60.8 (比較対象: Dense IND 82.4 / OOD 66.3; 条件: 完全ReCache) — 密注意性能の97.5%と91.8%を保持し、未知リソースで損失が大きくなる。

- 長リソース時のスケーリング / TTFT 約5ms強、KV 0.03GiB (比較対象: DenseはXLでTTFT 5,000ms超、KVは約8GiB; 条件: 総リソース長1万トークン以上) — 事前構築KV再利用によりオンラインプリフィル費用が総リソース長へほぼ依存しない。

### 負の結果・境界条件
- 圧縮を強くすると精度損失は無視できない。完全ReCacheの分布外呼出しF1は66.3から60.8へ低下する。一般要約型GistはKVを99.22%削減する一方、分布内呼出しF1が39.2、分布外9.7まで崩れ、細粒度な名前・引数情報を捨てすぎる。小さいQwen3-1.7BではKVヘッド群を強く削ると性能が落ちやすく、6/8群保持でも予備データでは完全可視より呼出しF1が18.7%低下した。

### 結果の読み方
エージェント用スキーマでは、別リソースとの相互注意や大域的な並び順よりも各リソース内部の意味が支配的であるため、KVを独立化しても品質がほぼ保たれる。一方、呼出しに必要な情報は層・ヘッド群・トークン全体へ均等には分布せず、寄与の大きい経路と構造化フィールドへ集中している。この二種類の偏りを利用することで、再利用だけでは残るKV保存・注意計算費用まで削減できる。
## 品質への影響
再利用だけの構成は密注意と0.1ポイント差の呼出しF1だが、完全ReCacheではINDで2.1ポイント、OODで5.5ポイント低下する。したがって大幅な効率改善と引き換えに、特に未知リソースでは一定の有効性損失がある。幻覚率は完全ReCacheでIND 0.2%、OOD 0.6%と低く、SPEEDや注意量ベース構造枝刈りより未知リソースで頑健だった。
## 既存研究との差
通常の接頭辞キャッシュは同一先頭列にしかKVを再利用できない。Prompt キャッシュ、EPIC、CacheBlend、KVLinkなどの位置非依存再利用は、位置補正、選択的再計算、コンパイルなどで既存KVを統合するのに対し、ReCacheは学習時からリソース間注意を切り位置を局所化し、各リソースのKV自体を組合せ非依存にする。DepthKVやDuoAttention、SPEEDなどは層・ヘッドのKV可視性を削るが、ReCacheはツール呼出し損失への寄与で層とKVヘッド群を選ぶ。GistやBeaconなど一般文圧縮と違い、リソース名・引数名・引数説明を明示的に保持してAPI呼出しの厳密性を守る。
## 限界
評価はQwen3-4BとQwen3-1.7Bの2規模に限定され、主結果は4Bである。より大きいモデルや別アーキテクチャへの一般化は未確認。注意マスクと位置配置を変更するため完全微調整を前提とし、凍結モデルへそのまま適用できない。システム指示とリソーススキーマが比較的安定し、同じリソースを要求間で再利用できる環境を想定する。リソース間依存や検索順序自体が重要な動的環境では、リソース独立化が情報を失う可能性がある。完全ReCacheは特に分布外で密注意より呼出しF1が5.5ポイント低い。

著者公式GitHub EIT-NLP/ReCacheでコード公開。arXiv v1は2026-08-20公開。論文はQwen3の完全微調整と独自の注意マスク・位置再配置・構造／意味枝刈りを前提とする。
## 研究上の位置づけ
KVキャッシュ再利用とエージェント推論の交点に位置する。従来のKV共有が文章断片や同一接頭辞の再利用を主対象にしたのに対し、ReCacheはツール／スキルスキーマを再利用単位として定義し、動的な検索組合せでもキャッシュを使えるようにする。さらにKV圧縮をトークン、層、KVヘッド群の3次元で組み合わせるため、エージェント基盤でツール数が増えた際のプリフィル、メモリ、デコード注意計算を一体的に削る系統として位置づけられる。
