# MeSH：再帰Transformerの隠れ状態を明示的メモリと動的ルータへ分離する方式

## 概要

MeSH（Memory-as-State-Highways）は、同じTransformerブロックを複数回適用する**再帰Transformer（recursive transformer）**の性能低下を抑えるため、反復ごとに読み書きを制御する状態メモリを導入する手法である。再帰Transformerは、同じ重みを何回も使うことで、計算上の深さを維持しながら固有パラメータ数を減らせる。しかし、単純に同じブロックを繰り返すと、最初の反復だけが大きな状態更新を行い、後続反復はほぼ同じ状態を繰り返すことがある。さらに一つの隠れ状態が、長期的に保持したい情報と、その反復で一時的に処理したい情報を同時に担うため、表現が低次元へ縮退する。

MeSHは複数の状態スロットを持つ明示的メモリを設け、各反復に固有の軽量な書き込みルータと読み出しルータを付ける。共有された主計算ブロックは反復ごとに中間出力を作り、書き込みルータがその出力をメモリへ分配し、読み出しルータが次の反復に使う状態を合成する。反復番号ごとに異なるルータを持つため、同じ主計算ブロックを使いながら、各反復が異なる役割を学習できる。

原著はPythia系列の複数規模で事前学習し、1.4B規模の比較では非埋め込みパラメータを約33.3%減らした再帰構成が、通常の非再帰Transformerのゼロショット平均49.50%に対し**50.56%**、5ショット平均51.93%に対し**52.79%**を達成した。改善幅はそれぞれ1.06ポイント、0.86ポイントである。これは同等の計算深さでのパラメータ効率を示す結果であり、**推論計算量や遅延を33%削減したという意味ではない**。

## 背景：重み共有による再帰の難しさ

標準Transformerでは各層が固有の重みを持つ。計算の深さを増やすと、一般にパラメータも増える。一方、再帰Transformerは小さい計算ブロックをK回適用することで、重みの量と計算深さを分離する。単純な形式は h^(t+1) = f_core(h^(t)) であり、f_coreの重みはすべての反復で共有される。これによりモデルを小さくできるが、同じ関数を同じ種類の隠れ状態へ繰り返し適用するため、各反復が異なる計算を担当するとは限らない。

論文は、Pythia-410M相当の再帰モデルで、反復ごとの状態更新の大きさ、反復間の中心化カーネル整合性（Centered Kernel Alignment、CKA）、状態行列の特異値スペクトルを分析する。単純再帰では第一反復の状態更新が大きく、後続の更新が小さくなる。反復間のCKAが高く、隠れ状態が同じ表現に近づくことも確認される。さらに特異値の減衰が速く、状態の情報が少数の方向に集中する。著者らはこれを、反復ごとの機能分化が起きないことと、一つの隠れ状態への情報過負荷という二つの問題に整理する。

従来の対策には、前回の状態を足す残差型（residual）や、最初の状態を毎回足すアンカー型（anchor）がある。これらは古い情報の喪失を抑えるが、どの情報を残すかを反復やトークンに応じて選ぶわけではない。また、共有ブロックに「現在は何回目の反復か」を直接知らせる仕組みが乏しく、反復間の機能分化を十分に促せない。MeSHは固定の加算経路を、学習可能な読み書き機構へ置き換える。

## 手法

### 1. Prelude–Recurrent–Codaの構造

MeSHは、最初に入力を処理するPrelude、重みを共有して反復するCore、最後に出力を作るCodaという構成を前提とする。入力埋め込みをh_embとすると、Preludeが初期状態h^(0)を作り、CoreをK回実行した後、Codaが最終表現を得る。論文の「4+8R2+4」はPrelude 4層、共有Core 8層を2回、Coda 4層という意味で、計算上は4+16+4=24層相当だが、固有重みは4+8+4=16層相当となる。

通常の再帰構成では、同じCoreが各反復の隠れ状態を更新する。MeSHはCoreの内部を大きく変更する代わりに、反復の入出力をつなぐ状態伝達部分を変更する。これにより、Coreの共有というパラメータ削減の利点を保ちながら、反復ごとの状態合成を学習可能にする。

### 2. 複数スロットの明示的状態バッファ

MeSHはB個のメモリスロット M={m_0,...,m_(B-1)} を持つ。各スロットは系列長Lと隠れ次元Dに対応するL×Dの状態行列である。初期化時には最初のスロットm_0へ入力埋め込みh_embを保存し、他のスロットはゼロにする。これにより、元の入力情報を反復中も直接参照できる経路を確保する。

重要なのは、メモリが単なるKVキャッシュではない点である。ここで保存するのは、生成済みトークンの注意鍵・値ではなく、**同じ系列に対する反復計算の中間状態**である。したがって「長文脈のKVキャッシュを圧縮する方式」として分類するのは不正確であり、再帰ネットワークの状態管理・パラメータ効率化の研究として扱うべきである。

### 3. 反復ごとの書き込み・読み出しルータ

反復tでは、共有Coreが現在の状態h^(t)を処理し、中間出力h_m^(t)=f_core(h^(t))を作る。書き込みルータと読み出しルータはそれぞれ一層の線形射影とソフトマックスで構成され、各トークンに対してB個のスロットの重みを出力する。ルータの重みは反復tごとに固有であり、Core本体は共有される。

書き込み時には、各スロットへ既存内容にh_m^(t)を重み付きで加える。式(5)では m_b^(t+1)=m_b^(t)+h_m^(t)⊙w_write,b^(t) と表される。読み出し時には更新後の各スロットをw_read,b^(t)で重み付き合成し、次の状態h^(t+1)を作る。書き込みも読み出しもトークンごとに異なる重みを持つため、系列全体で一律に同じスロットへ書く必要はない。

固定の残差やアンカー加算と違い、ルータはある反復では入力に近い情報を強く参照し、別の反復では直前の計算結果を重視するように学習できる。論文の事例分析では、異なる反復が異なるスロットを主に使い、同じ反復でもトークンによって読み書き比率が異なることを可視化している。この動的な経路選択が、反復ごとの機能分化を促す中核となる。

### 4. パラメータ数とメモリの交換条件

主計算Coreの重みは共有されるが、反復別ルータの重みは追加される。ルータは隠れ次元DからBスロットへの線形射影であり、Core全体と比べると軽量だが、厳密に追加パラメータがゼロではない。また各スロットはL×Dの状態を保持するため、メモリの占有量はスロット数B、系列長L、隠れ次元Dに比例する。これは重みパラメータの削減と引き換えに、反復状態の保持領域を追加する設計である。

推論時にCoreをK回実行すること自体は省略しないため、固有重みが約3分の2になっても演算回数が同じ割合で減るわけではない。GPUの重み読み出しやモデルの配置には有利となり得るが、追加メモリとルータ演算があり、実際の遅延は別途測定が必要である。

410Mで50%削減した3回再帰構成では、通常版のゼロショット43.87%に対し、単純再帰41.94%、アンカー42.85%、MeSH43.53%であった。MeSHは単純再帰より1.59ポイント改善するが、通常版には0.34ポイント届かない。5ショットでは通常版45.31%に対しMeSH46.04%で、0.73ポイント上回る。圧縮率を高めると評価条件によって得失が変わるため、ゼロショットと少数ショットの両方を見る必要がある。

### 内部状態の診断と構成要素の寄与

原著Figures 3～5では、単純再帰、残差、アンカー、MeSHの状態を比較した。単純再帰では第一反復の更新が支配的で後続反復の更新が小さくなる。CKAで見ると反復間の表現が非常に似ており、特異値スペクトルも急速に減衰する。これは同じ計算を繰り返しているにもかかわらず、追加の計算深さを十分に活用できていないことを示唆する。

MeSHでは各反復の状態更新がより均等になり、反復間のCKA類似度が下がり、特異値スペクトルが広がる。論文はこれを、反復ごとの機能分化と、長期記憶を明示的バッファへ移した効果として解釈する。ただし、状態可視化は機構を支持する診断結果であり、それだけで全下流課題の因果的な性能改善を厳密に証明するものではない。主要な性能改善は別の困惑度・下流課題評価で確認する。

### 学習過程と規模依存性

1.4B相当の学習曲線では、MeSHは事前学習中の損失が単純再帰や固定の残差・アンカー方式より低く、下流のゼロショット平均も良好に推移した。これは最終チェックポイントだけの偶然の改善ではなく、学習過程の複数時点で差があることを示す。410M規模でPrelude、Core、Codaへの層配分を変えた比較でも、MeSHは複数の配分で単純再帰より低い困惑度を達成した。

論文は1.4B規模の比較を、非埋め込みパラメータ約805MのMeSHモデルと約1.2Bの通常版として説明し、ゼロショット50.6%対49.5%、5ショット52.8%対51.9%を挙げる。パラメータ効率を1.46倍と表現しているが、これは同等以上の評価品質をより少ない固有パラメータで得るという意味であり、訓練処理量や生成速度が1.46倍になるという意味ではない。

## 既存研究との差

残差型の再帰では、各反復の出力に直前の状態を加える。アンカー型では最初の状態や入力埋め込みを加える。これらは古い情報を保持する経路として有効だが、どの情報を保存するかを動的に選ぶことはできない。MeSHは複数スロットへの書き込みと読み出しを、反復ごと・トークンごとの重みで制御するため、固定加算より表現力が高い。

通常のMoEでは入力トークンを複数の専門家ネットワークへ割り当てるが、MeSHのルータは**専門家ネットワークの選択ではなく、反復間で使う状態メモリの選択**を行う。したがって専門家の動的活性化や推論サーバーのKVオフロードと混同しない。目的は、計算ブロックの重みを共有してパラメータを減らした際に失われる表現能力を回復することである。

## 限界と実用上の評価

第一に、主要な比較はPythia準拠モデルとPile由来データであり、現代の数十B～数百B規模のMoEやマルチモーダルモデルに同じ改善が出るとは限らない。論文の補足では6.9B規模も扱うが、さらに大きい基盤モデルや異なる学習制度での一般化は未検証と明記している。

第二に、パラメータ削減率は非埋め込み重みを基準とする。明示的状態バッファは系列長・隠れ次元・スロット数に比例するメモリを消費し、読み書きルータの演算も増える。重み容量が減った分だけ推論時のGPUメモリ総量やレイテンシが減ると推定するのは不適切である。特に長文脈・大きいバッチでは状態バッファの占有が無視できなくなる可能性がある。

第三に、同じ計算深さを保つ比較なので、再帰化によるパラメータ削減と、トークン当たりのFLOPs削減は別である。実際の推論サーバーでのトークン生成速度、スループット、GPU利用率、通信量、量子化との併用を評価した研究ではない。ローカル推論でのVRAM削減に利用するには、モデル重みの配置と状態バッファのメモリを実測する必要がある。

第四に、メモリルータの重みは反復ごとに固有であり、反復回数やスロット数を増やすと追加コストが増える。すべての反復を同じ共有ブロックで実行するという前提も残るため、全層固有の非再帰Transformerが持つ機能分化を完全に再現するとは限らない。160M規模の一部評価では通常版より低い結果であり、適用前に目標課題で精度・メモリ・速度を測る必要がある。
