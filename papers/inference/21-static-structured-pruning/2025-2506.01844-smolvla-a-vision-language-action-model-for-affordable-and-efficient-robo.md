# SmolVLA：小型視覚言語行動モデルと非同期行動チャンク推論

## 概要

SmolVLAは、視覚・自然言語・ロボット状態を入力として連続的な制御指令を生成する**視覚言語行動モデル（vision-language-action model; VLA）**を、消費者向けGPUやCPUでも扱える規模へ縮小する研究である。中核は、SmolVLM-2を使う視覚言語部の上位層を省略し、1画像の視覚トークンを64個に抑え、行動専門家（action expert）に交差注意と自己注意を交互に配置する設計である。主モデルは4.5億パラメータ、うち約1億が行動専門家であり、50ステップの行動チャンクを予測する。

推論システムとして特に重要なのは、ロボット側の制御ループと方策モデルの推論を分離した**非同期実行（asynchronous inference）**である。従来の同期方式は50個の行動をすべて実行してから次の観測を送るため、次の推論が終わるまでロボットが待つ。SmolVLAの非同期方式では、前の行動チャンクを実行しながら新しい観測を方策サーバへ送り、推論結果を既存キューへ重ねて統合する。キュー残量と観測類似度によって新規推論の頻度を制御し、遅延を行動実行で隠す。

実機のPick-Placeでは同期推論の平均完了時間13.75秒に対し、非同期推論は9.70秒、固定時間内の成功した物体移動数は9個から19個へ増えた。一方、三課題の平均成功率は同期78.3%から非同期73.3%へ下がり、Sorting単独では70%から50%へ低下した。したがって**高速化と品質維持は別の評価軸**であり、「非同期化で必ず成功率も上がる」とは言えない。出典：原著§3.1〜3.3、§4.5〜4.7、図5、表2〜13。

## 問題設定：視覚言語処理の計算と制御周期の不一致

ロボットはカメラ画像、関節角などの自己状態、言語で与えられたタスク指示から、関節や把持器をどう動かすか決める。大規模なVLAは汎化能力が高い反面、画像符号化、言語モデルの注意計算、行動生成を行うため、低価格ロボットに搭載できる計算資源では遅い。特に高解像度画像を多くの視覚トークンへ展開すると、言語モデルの注意計算が重くなる。

もう一つの問題は、方策推論と制御の時間尺度が異なることだ。ロボットはたとえば30Hz、すなわち約33ミリ秒ごとに動作指令を消費する。しかしVLAの1回の行動予測がそれより長いと、毎制御周期でモデルを同期実行することは難しい。そこで複数時刻分の行動をまとめて予測する行動チャンク（action chunk）を使うが、チャンクを最後まで使ってから次の予測を始めると、次の推論が終わるまで制御指令が途切れる。

一方、毎制御周期に新しいチャンクを生成すれば反応性は高いが、画像の処理と行動予測を過剰に繰り返す。SmolVLAは**モデル一回当たりの計算量削減**と**チャンク間の待ち時間隠蔽**を別々に設計し、消費計算量と閉ループ反応性の両立を狙う。学習データの不足も背景にあるが、本サーベイで重視するのはモデル軽量化と実行系の接続である。

## 手法：軽量な視覚言語部と行動専門家

### 1. 入力の整形と視覚トークン64個への削減

視覚言語部はSmolVLM-2を使い、画像符号化器SigLIPとSmolLM2言語復号器から特徴を得る。入力は複数カメラのRGB画像、言語指示、関節などの自己状態である。画像を視覚トークンへ、指示をテキストトークンへ変換し、自己状態は線形射影で1個の状態トークンへ写す。これらを連結して言語復号器へ通し、得られた特徴を行動専門家の条件入力にする。

高解像度画像を複数領域に切り分けて処理する画像タイル化は、視覚理解には有効でも計算を増やす。SmolVLAは全体画像だけを使い、画素シャッフル操作によって**1フレーム当たり64視覚トークン**に抑える。入力系列が短くなるので、視覚言語部の自己注意と後段の交差注意の両方の負荷が下がる。細かな局所情報を切り捨てる可能性があるため、極小物体や高精細認識への一般化は評価範囲に注意が必要である。

### 2. 上位層の省略と中間特徴の活用

SmolVLAは事前学習済み視覚言語モデルの最終層出力を必ずしも必要とせず、前半の中間特徴で行動を条件付けする。言語復号器の総層数を $L$、使う層数を $N$ とすると、後半の $L-N$ 層を実行しない。主設定は $N=L/2$、具体的には最初の16層であり、視覚言語部の処理深さを半分にする。

この操作は全層を残して2層に1層だけ飛ばす方式とも、最初から小さなモデルを学習する方式とも異なる。原著の表8では使用層数を8、16、24、32と変えて成功率を測り、層数と成功率の交換条件を確認している。8層ではLIBERO平均75.0%、16層78.5%、24層79.5%、32層80.3%となる実験条件があり、16層は最大精度ではないが計算を減らせる選択肢である。別条件の主表で87.3%という値を示すが、表8の数値と同じ学習設定の結果として混ぜない。

### 3. フローマッチング型の連続行動生成

行動専門家は、観測から得た視覚言語特徴に条件付けて、時刻 $t$ からの連続行動列 $A_t=(a_t,\ldots,a_{t+n})$ を生成するTransformerである。単一の離散的な行動トークンを自己回帰で1個ずつ出すのではなく、雑音を含む行動列をフローマッチング（flow matching）のベクトル場で変換する。学習では正解行動列 $A$ と正規雑音 $\epsilon$ を混合した $A^{\tau}=\tau A+(1-\tau)\epsilon$ を入力し、行動専門家 $v_\theta$ が原著の定める速度場 $\epsilon-A$ を近似するよう二乗誤差を最小化する。

推論では複数回の更新によって行動列を生成する。原著の主設定は**10回のフローマッチング更新、チャンク長50**である。行動専門家の隠れ幅は視覚言語部の0.75倍に抑え、必要な計算量を削減する。更新回数が固定されているので、モデル一回の推論時間は通常の1トークン復号とは異なる。チャンク長を増やせば予測を呼ぶ頻度を下げられる一方、予測が古い観測に基づく時間が長くなり、環境変化に対応しにくくなる。

### 4. 交差注意と因果自己注意を交互に配置する

行動専門家の層は、視覚言語部の特徴を参照する交差注意（cross-attention; CA）と、行動トークン同士の関係を扱う自己注意（self-attention; SA）を交互に置く。交差注意では行動側が問い合わせ、視覚言語側が鍵・値となる。自己注意ではチャンク内の行動トークンが互いに関係を調整し、因果マスクによって未来位置の情報を見ないようにする。

交差注意だけでは視覚条件を取り込めるが、行動列内部の滑らかな整合を表現しにくい。自己注意だけでは行動間の依存を扱えても、視覚言語特徴との接続が弱くなる。表6のLIBERO実験では交差注意のみ79.0%、自己注意のみ74.5%、交互配置85.5%であり、両者の補完性が示される。表7では双方向自己注意67.5%に対し因果自己注意74.5%であり、未来行動への依存を抑える構造の方が良い条件があった。

## 非同期推論：RobotClientとPolicyServerを分離する

### 1. キュー残量を使った先読み要求

ロボット側のRobotClientは、現在の行動キュー $A_t$ から次の指令を取り出して実行する。方策を実行するPolicyServerは、ロボットから受け取った観測に基づいて次の行動チャンクを予測し返す。同期方式ではキューを使い切ってから次の観測を送り、サーバの推論と通信を待つため、その間はロボットが停止する。

非同期方式では、キュー残量の割合 $|A_t|/n$ が閾値 $g$ を下回った時点で次の観測を送る。たとえば $g=0.7$ ならチャンクの約30%を消費した頃から次の推論を開始する。サーバの計算中もクライアントは残りの行動を実行し、返ってきたチャンクは既存キューの重複する時間位置と統合する。これにより**推論時間を行動実行時間へ重ね合わせる**ことができる。

推論待ち時間を $\ell$、制御周期を $\Delta t$、チャンク長を $n$ とすると、待ち時間中に消費する行動数は概ね $\ell/\Delta t$ である。原著は通信時間が小さく平均サーバ遅延が支配的な場合、$g\ge(\mathbb E[\ell_S]/\Delta t)/n$ を待ち時間隠蔽の目安として導く。これは平均遅延に基づく設計式であり、ネットワーク遅延の大きな揺らぎや極端な推論遅延でも絶対にキュー切れしない保証ではない。

### 2. 類似観測の除外とキュー更新の競合

毎回の制御時刻で新しい観測を送る $g=1$ に近い設定は、反応性を高めるが推論呼び出しを増やす。しかもほぼ同じ関節状態の画像を繰り返し送ると、似た行動チャンクが頻繁に返り、キューを統合し直す負荷や制御の不安定さを生む。そこでRobotClientは観測間の関節空間距離を閾値 $\epsilon$ と比較し、近すぎる観測の再送を省く。ただし行動キューが空になった場合は類似度にかかわらず観測を送る。

非同期推論の状態管理では、観測を送った時刻、応答が対応する制御時刻、既に実行済みの行動、まだ実行していない行動を区別する必要がある。古い観測から生成されたチャンクを単純に全置換すると、実行済み時刻へ遡る指令や急な制御の飛びが生じる。原著の方式は重複する時間位置でキューを統合し、推論が未完了の間は現在のキューを使い続ける。**モデルが出す行動列をどの時刻に適用するか**という制御系の整合性が、単なる推論スループット以上に重要となる。

### 3. 遠隔実行と計算資源の分離

PolicyServerはロボット本体とは別のGPUマシンに置くこともできる。ロボット側には観測送信、キュー管理、行動実行だけを残し、重い視覚言語推論を遠隔で実行する。これはローカルの低消費電力CPUしか持たない機体にも高性能モデルを利用できる利点がある。一方、往復通信が長い場合には必要な先読み量が増え、古い観測に基づく行動を実行する時間が伸びる。遠隔化の効果を評価する際にはサーバ処理時間だけでなく、観測の転送量、ネットワーク遅延、ロボット側キュー切れの割合を確認すべきである。

|---|---:|---:|---|
| LIBERO 40タスク平均 | 87.3% | $\pi_0$ 3.3B・事前学習あり86.0% | 小型でも競争力あり |
| Meta-World 50タスク平均 | 57.3% | $\pi_0$ 3.5B・事前学習あり47.9% | 異なるシミュレータでも改善 |
| SO-100三課題平均 | 78.3% | $\pi_0$ 3.5B 61.7%、ACT 48.3% | 実機の同一表内比較 |
| SO-100 Stacking | 90% | $\pi_0$ 40%、ACT 50% | 把持後の積み上げで差が大きい |
| SO-101 Pick-Place-Lego（既知位置） | 90% | ACT 70% | 別ロボットへ微調整した条件 |
| SO-101 Pick-Place-Lego（未知位置） | 50% | ACT 40% | 未知位置で成功率が低下 |
| SO-100事前学習なし多タスク平均 | 51.7% | 事前学習あり78.3% | コミュニティデータの事前学習効果 |

SmolVLAは主モデル0.45Bに対して比較対象の$\pi_0$が約3.3Bなので、パラメータ規模に大きな差がある。しかし事前学習データの種類、学習量、入力設定が同一とは限らない。SO-101の未知位置では成功率が50%であり、既知位置の90%と比較すると環境変化への限界が残る。

### 3. 同期と非同期の比較：速度改善と負の結果

| 実機指標 | 同期推論 | 非同期推論 | 読み取り |
|---|---:|---:|---|
| Pick-Place平均完了時間 | 13.75秒 | 9.70秒 | 約29.5%短縮 |
| Pick-Place完了時間の標準偏差 | 2.42秒 | 2.95秒 | 非同期のばらつきはやや大きい |
| 固定時間内の成功した物体移動 | 9個 | 19個 | この実験では2.11倍の処理数 |
| 三課題平均成功率 | 78.3% | 73.3% | 5.0ポイント低下 |
| Pick-Place成功率 | 75% | 80% | 5ポイント改善 |
| Stacking成功率 | 90% | 90% | 変化なし |
| Sorting成功率 | 70% | 50% | **20ポイント悪化** |

この実験での「非同期化で30%高速」は、ロボットのタスク完了までの実時間短縮を指す。モデルの単発推論遅延が30%減ったという意味ではない。固定時間内の処理数9→19は別の評価であり、平均完了時間の比13.75/9.70とは一致しなくてよい。非同期では待機時間が減り、繰り返し作業に使える時間が増えるためである。

Sortingの成功率低下は重要な負の結果である。Pick-Place向けに調整した非同期閾値を他のタスクにも流用したと原著は記載する。タスクの状態変化や制御の精密さによって最適な先読み量が異なり、速度優先のキュー更新が正確性を損なう場合がある。したがって実装の選択は平均完了時間だけでなく、タスク別成功率と制御の安定性で決める必要がある。

### 4. 構成要素除去実験（ablation）

| 変更条件 | LIBERO平均成功率 | 示唆 |
|---|---:|---|
| 交差注意のみ | 79.0% | 視覚条件は使えるが行動間整合が弱い |
| 自己注意のみ | 74.5% | 視覚条件の取り込みが不足 |
| 交差注意＋自己注意を交互配置 | 85.5% | 両者の組合せが有効 |
| 双方向自己注意 | 67.5% | 未来行動への依存が悪化する条件 |
| 因果自己注意 | 74.5% | 双方向より改善 |
| 行動専門家のフローマッチング学習 | 80.25% | L1回帰75.25%より改善 |
| チャンク長1 | 50.0% | 一歩ずつの予測では不利 |
| チャンク長10 | 84.0% | この比較では最良 |
| チャンク長50 | 80.3% | 標準設定。長さ10より低い |
| チャンク長100 | 74.5% | 長すぎるチャンクで低下 |
| 行動実行後1ステップで観測更新 | 80.3% | 頻繁な観測が有効 |
| 50ステップまで観測更新しない | 51.8% | 開ループが長すぎると大きく低下 |

これらの表はそれぞれ異なる構成要素を切り替えた実験であり、同じ設定の単一多変量実験として足し合わせない。主設定のチャンク長50が構成要素除去では最良ではないこと、観測更新を50ステップまで遅らせると成功率が大きく落ちることが、非同期キューを設計する際の実用的な注意点となる。

## 既存研究との差

OpenVLAなどの大規模VLAは高い表現能力を持つが、ロボット本体に載せるには計算とメモリの負担が大きい。SmolVLAは小型VLMの中間層を利用し、視覚トークン削減と軽量な行動専門家で推論負荷を下げる。ACTは画像と状態からチャンクを生成するが、主に回帰・変分自己符号化器型の学習であり、SmolVLAはフローマッチングを使う。$\pi_0$もフローマッチング型の行動生成を用いるが、SmolVLAはモデルサイズと注意の配置を変え、消費資源を抑える。

非同期推論はモデルのアーキテクチャとは独立に、行動チャンクを出力する方策に適用可能な実行方式である。前のチャンクを実行中に次のチャンクを予測するため、推論そのものの計算量を減らさずとも待ち時間を隠せる。これはLLMサービングでの事前充填と復号の重ね合わせやパイプライン処理と同様に、異なる資源の作業を時間的に重ねる最適化と理解できる。ただしロボットでは遅延だけでなく、古い観測から生成された行動が物理的な失敗を生む点が異なる。

## 限界・実装上の注意

第一に、モデルの小型化は視覚・制御の精度と交換条件にある。画像タイル化を省き64トークンへ圧縮し、VLMの後半層を削るため、微細な物体認識や長期計画に必要な情報を保持できるかはタスクに依存する。原著自身も短時間・比較的単純な操作から長期タスクへの拡張を課題としている。

第二に、データは481のコミュニティ集合から選んだ約22,900エピソードだが、主にSO-100型のロボットに由来する。SO-101へ微調整できた結果は、異なる形状・制御方式のロボットへ無条件で転移する保証ではない。カメラ位置の命名を手作業で統一し、曖昧な指示を別のVLMで補正しているため、学習前のデータ整形コストも無視できない。

第三に、非同期実行の平均速度向上と成功率は両立しない場合がある。Sortingの20ポイント低下が示すように、チャンク更新のタイミング、重複チャンクの統合、観測の類似度フィルタ、ネットワーク遅延の変動が実機の品質に影響する。キューを使い切った場合の再推論、古い応答の棄却、緊急停止や障害物検知など、安全側の制御は実装環境で別途設計する必要がある。

第四に、単一GPUで学習可能という説明は実際の事前学習が1GPUで完了したことを意味しない。原著は4GPUで事前学習し、研究全体で約30,000 GPU時間を報告している。推論のCPU対応も、CPUでの全タスク・全設定の実時間制御性能を保証するものではない。計算資源・ロボット・ネットワーク条件を分けて再現性を評価すべきである。
