# I-BERT：非線形演算まで整数化するBERT量子化

## 概要

Transformerの重みと行列積を8ビット整数へ量子化しても、推論全体が整数だけで実行できるとは限らない。GELU、Softmax、LayerNormのような非線形演算は、従来の量子化実装で浮動小数点のまま残されることが多い。その場合、整数行列積の後で一度FP32へ逆量子化し、非線形演算を行ってから再びINT8へ変換する必要がある。浮動小数点演算器を持たない小型プロセッサでは、この経路そのものが実行不能になる。

I-BERTは、非線形関数を**整数だけで計算できる近似演算**へ置き換え、埋込み、行列積、正規化、注意計算を含む推論経路全体から浮動小数点への変換を取り除く。GELUとSoftmaxには二次多項式近似、LayerNormの標準偏差には整数平方根を使う。重みと活性値はINT8、積和の累積はINT32とし、非線形演算後も整数表現を維持する。

RoBERTa-BaseとRoBERTa-LargeのGLUE評価では、FP32基準に対する平均スコアがそれぞれ0.3点と0.5点高く、少なくとも対象課題で明確な品質低下は見られなかった。Tesla T4上の予備的な整数カーネル実装では、FP32比で2.4～4.0倍の推論高速化を報告する。ただしこの値はBERT系モデル、特定のTensorRT実装、特定の比較条件で得たものであり、現代の生成LLMのトークン生成速度に直接当てはめてはならない。

## 問題設定：量子化した行列積の間に残る浮動小数点

低精度の重みを保存するだけなら、整数から浮動小数点へ戻して計算してもモデルの保存容量は減らせる。しかし実行速度と省電力を改善するには、計算自体を整数演算器へ載せる必要がある。特にTransformerの自己注意では、QK行列積の後にSoftmaxがあり、その後にValue行列積が続く。SoftmaxだけFP32であれば、前後で逆量子化と再量子化が発生し、整数データ経路が切れてしまう。

GELUは滑らかな非線形関数で、誤差関数や指数関数に関係する。Softmaxも指数と正規化を含み、LayerNormは入力ごとに平均と分散を計算して平方根を求める。CNN向けの整数推論で扱いやすいReLUや、推論時に統計量を固定できるBatchNormとは難しさが異なる。これらを単純な整数近似へ置き換えると、関数値の誤差が下流課題の精度へ影響する。

本論文の狙いは、重み圧縮率を最大化することではなく、**モデル全体で浮動小数点演算を一度も要求しないこと**である。したがって整数近似の誤差、量子化のスケール、積和のビット幅、整数専用カーネルの性能を同時に設計する。

## 手法

### 1. 対称・静的量子化と整数データ経路

実数値を8ビット整数へ写像するとき、値の範囲をクリップし、固定スケール `S` で割って丸める。原著は対称量子化を用い、量子化整数 `q` が `x≈Sq` を表すようにする。スケールは推論中に変化させない静的方式を採用し、実行時のスケール計算費用を避ける。

埋込みや行列積ではINT8の乗算を行い、積の累積はINT32で保持する。後段の非線形演算はこの整数累積値を入力とし、必要に応じて整数の乗算・加算・除算・ビットシフトで再量子化する。推論中に `Sq` をFP32の値として復元する必要はない。近似係数とスケールの関係はあらかじめ計算し、整数の定数として保持できる。

単にINT8の重みを読み込んでFP32演算へ変換する方式とは異なり、モデルの演算グラフに沿って整数表現が途切れないことが設計上の要点となる。これにより整数演算器しか持たないハードウェアでも、必要な演算を構成できる。

### 2. 整数二次多項式の基本形

二次多項式 `a(x+b)^2+c` は、入力を整数 `q` とスケール `S` に分けて扱えば、整数の加算と乗算で近似計算できる。係数に相当する整数と出力スケールを事前に求め、実行時には `(q+q_b)^2+q_c` のような整数演算を行う。高次多項式は理論上の近似誤差を減らせても、乗算回数が増え、低精度整数のオーバーフロー対策も難しくなる。

著者らは二次式を中心に設計し、計算費用と近似精度を折り合わせる。関数の定義域全体を一つの多項式で無理に近似するのではなく、関数の対称性や単調性、入力値が実際に現れる範囲を使って誤差を減らす。

### 3. 整数GELU

GELUは `x` と誤差関数 `erf` を組み合わせた滑らかな活性化関数である。一般的な近似にはSigmoidを使うものもあるが、そのSigmoidをそのまま評価すると再び浮動小数点演算が必要になる。別の簡単な整数近似であるh-GELUは実装しやすいが、GELUとの差が大きく、下流の精度を落とし得る。

I-BERTのi-GELUは、誤差関数が奇関数であることを使って正の入力側だけを近似し、入力範囲をクリップした二次式を組み合わせる。原著の係数は `a=−0.2888`、`b=−1.769` で、近似した誤差関数からGELUを求める。整数表現とスケールを保ったまま計算するため、推論中にFP32の誤差関数を呼び出さない。

原著の比較ではi-GELUの平均近似誤差は約 `8.2×10^-3`、最大誤差は `1.8×10^-2` である。h-GELUの平均 `3.1×10^-2`、最大 `6.8×10^-2` より小さい。関数の近似誤差を減らすことが、モデル全体の量子化後品質を守るために重要である。

### 4. 整数Softmax

Softmaxは各注意得点に指数関数を適用し、全要素の和で正規化する。I-BERTはまず最大値を引いて指数の入力を非正にし、指数関数を整数演算へ変換する。指数関数をそのまま広い範囲で二次式へ当てはめるのではなく、2のべき乗への分解と小区間での多項式近似を組み合わせることで、扱う数値範囲を制御する。

近似した指数値を整数の比として正規化し、後続のValue行列積へ渡す。原著が報告するSoftmaxの最大近似誤差は約 `1.9×10^-3` である。注意重みの計算にFP32を挟まないため、QK行列積からSoftmax、Value行列積まで整数のまま処理できる。

ただし、Softmaxは複数要素の正規化を伴うため、近似誤差は入力の分布とスケールに依存する。単一の最大誤差値だけであらゆる系列長・モデルへの適用を保証することはできない。I-BERTの結果は対象としたRoBERTaモデルの量子化条件で評価されている。

### 5. 整数LayerNorm

LayerNormでは、各トークンの特徴値から平均と分散を求め、分散の平方根を使って正規化する。平均と分散の加減乗除は整数演算で実行できても、平方根をFP32関数へ渡すと整数専用の条件を満たさない。

I-BERTは整数平方根の反復アルゴリズムを利用し、整数の除算、加算、ビットシフトで平方根の整数部分を求める。入力値の大きさに応じた初期値を使うことで反復回数を抑える。論文は32ビット整数に対して最大4回程度の反復で計算できる構成を示す。

これはBatchNormのように固定の平均・分散を事前融合するのではなく、**入力ごとに変わる統計量を整数だけで計算する**点に意味がある。LayerNormの構造を残したまま完全整数推論を成立させる。

## 評価条件

原著はRoBERTa-BaseとRoBERTa-LargeをGLUEで評価し、別途Tesla T4上で整数専用非線形カーネルの遅延を測る。GLUEの品質比較と、T4上の実行速度は目的と実装条件が異なるため、同じ表の値を混ぜて解釈しない。

| 項目 | 原著の条件 |
|---|---|
| 品質評価モデル | RoBERTa-Base、RoBERTa-Large |
| 品質評価 | GLUEの下流課題、FP32モデルとの比較 |
| 量子化 | INT8重み・活性、INT32積和累積、整数専用非線形演算 |
| 速度評価GPU | NVIDIA Tesla T4 |
| 速度評価実装 | TensorRTを利用した整数カーネルの予備実装 |

## 評価結果と解釈

### 1. GLUE品質は概ね維持

RoBERTa-BaseとRoBERTa-LargeのGLUE平均では、I-BERTがFP32基準をそれぞれ0.3点、0.5点上回ると報告される。これは量子化後のモデルが対象タスクで明確な精度低下を起こさなかったことを示す。ただし「整数化すると一般に精度が上がる」という普遍的な主張ではない。量子化学習の設定、微調整、評価データのばらつきによって小さな差は変わり得る。

著者らは単に全体スコアだけを見るのではなく、非線形関数の近似精度を個別に測る。i-GELUの最大誤差 `1.8×10^-2`、整数Softmaxの最大誤差 `1.9×10^-3` は、二次近似が十分な精度を持つことを示す。より粗いh-GELUでは近似誤差が増え、下流精度が悪化する条件がある。したがって整数演算器へ載せることだけでなく、関数近似を適切に設計することが重要である。

### 2. T4上のINT8速度

原著の予備的な実機測定では、INT8推論はFP32に対して約2.4～4.0倍高速となる。既存の論文原稿に記録された表の集計では、Baseの平均は約3.08倍、Largeの平均は約3.56倍である。最良の4.0倍は特定のモデル・系列長・バッチ条件での最大値であり、すべての設定の代表値ではない。

| 指標 | 報告値 | 読み取り |
|---|---:|---|
| GLUE平均差（Base） | +0.3点 | FP32との差であり速度倍率ではない |
| GLUE平均差（Large） | +0.5点 | 大型モデルでも対象課題の品質を維持 |
| T4の速度比（全体範囲） | 約2.4～4.0倍 | FP32に対するINT8推論速度 |
| T4のBase平均 | 約3.08倍 | 系列長・バッチ条件を集計した値 |
| T4のLarge平均 | 約3.56倍 | モデル規模によって速度比が変わる |
| GELU最大近似誤差 | `1.8×10^-2` | 関数近似の誤差でありGLUE誤差ではない |
| Softmax最大近似誤差 | `1.9×10^-3` | 関数近似の誤差であり推論速度ではない |

系列長とバッチ数によって、行列積の占める割合、カーネル起動費用、非線形演算の相対費用が変わるため、速度比も一定ではない。量子化重みの容量削減率と実行時間の短縮率も同一ではない。

### 3. 非線形近似の比較

i-GELUはh-GELUより平均・最大の近似誤差が小さい。これは単なる数値計算の改善にとどまらず、量子化したTransformerの品質を守るための条件になる。h-GELUのような粗い近似では、整数演算で動作しても下流精度が悪化し得る。LayerNormも浮動小数点の平方根を呼び出さずに処理することで、全体を整数専用に保つ。

各非線形演算の近似を組み合わせた結果としてGLUE品質を維持できたのであり、GELUの誤差だけを最小化すれば全モデルで精度が保証されるわけではない。量子化スケール、累積幅、正規化、モデルの重み分布を合わせて検証する必要がある。

## 既存方式との差

従来のBERT量子化は、重みの保存量や行列積の整数化に重点を置き、GELU、Softmax、LayerNormは浮動小数点のまま残す方式が多かった。I-BERTは、これらの演算を整数で実行できる近似式へ置き換え、整数行列積の間にFP32変換が挟まらないようにする。

CNN向け整数専用推論とも異なり、Transformerで重要な滑らかな非線形関数と入力依存の正規化を扱う。したがって「重みをINT8で保存するだけ」の量子化と「推論グラフ全体が整数演算で完結する」量子化の違いを明確に示す研究である。

## 限界と現在の推論基盤への適用

第一に、実機速度の根拠はTesla T4上のTensorRTによる予備実装である。FP32との比較条件、カーネルの融合度、バッチ数、系列長によって速度比は変わる。最新のFP16/BF16高度最適化カーネル、別世代GPU、CPU上の実行と直接比較した値ではない。報告された最大4倍を現代のLLM推論速度へそのまま転用してはならない。

第二に、主な対象はBERTとRoBERTaのようなエンコーダ型Transformerである。自己回帰生成のデコード、KVキャッシュ管理、長文脈の注意、MoEルーティングなどは本論文の主要評価対象ではない。現在の生成LLMへ整数専用推論を拡張するには、対象アーキテクチャの演算と数値範囲を改めて調べる必要がある。

第三に、整数専用で動作することと、浮動小数点演算器を持たないマイクロコントローラ上で十分な速度を出せることは別である。著者らは小型プロセッサ向けの実装基盤不足を課題としており、実際の低消費電力端末でのエネルギーや遅延を広範囲に測ったわけではない。整数除算、平方根反復、メモリ転送の費用は装置によって異なる。

第四に、二次多項式近似は関数値の範囲を限定することで誤差を抑える。モデルの活性値分布が大きく異なる場合、量子化のクリップと近似の誤差が重なる可能性がある。INT8での品質がGLUEで維持されたとしても、すべての言語・モデル規模・下流課題で同じ結果になる保証はない。導入時には対象モデルの精度を独立に確認する必要がある。

### 実装上の確認項目

既存の推論エンジンへ取り込む場合、非線形演算の前後でFP32への暗黙の変換が残っていないか、INT32累積からの再量子化が適切か、整数平方根が必要な精度で動くかを検査する必要がある。さらに、整数専用カーネルの起動費用やメモリ配置によって、理論上の演算量削減が実時間の改善につながらない場合もある。モデルファイルの圧縮率だけで実用性能を評価しないことが重要である。
