# Learning to Skip for Language Modeling

## 概要
通常のTransformerは、句読点のような容易なトークンにも推論上重要なトークンにも同じ層数を適用する。SkipLayerは任意の層を学習可能な二値ルータで包み、各トークンについてその層を実行するか、恒等写像で迂回するかを決める条件付き計算 (conditional computation) である。早期終了 (early exit) と異なり、一度ある中間層を飛ばしても後続層では再び計算へ参加できる。

中心的な狙いは、**モデルの総容量と1トークン当たりの実行計算量を分離すること**にある。例えば6層密モデルと平均6層だけ実行する12/24/48層SkipLayerを比べ、総パラメータを増やしながら実効層数をほぼ固定する。離散的な実行判断はStraight-Through Gumbel-Softmaxで学習し、各層の実行率を目標値へ近づける補助損失でFLOPs予算を制御する。

## 問題設定
soft gateだけではforward時に実際の層計算を省けず、top-1 routingもsoft確率を掛けるだけでは実際の実行率を正確に制御しにくい。またトークンごとのskip数が動的なので、単純にmaskした後で全トークンへFFNを計算すると演算削減にならない。したがって本論文は、離散ルーティングを微分可能に学習する問題と、動的に残ったトークンだけをアクセラレータで効率よく処理する問題を同時に扱う。

## 手法
### 二値SkipLayerルータ
入力表現Xから2クラスの線形ルータが「実行/skip」を選ぶ。forwardではGumbel-Softmaxから0/1の離散maskを使い、実行なら元層F(X)、skipなら入力Xをそのまま出力する。backwardでは対応するsoft probabilityを使ってstraight-throughに勾配を流すため、学習時にもforwardの疎な実行構造を保てる。

各層の実行率r_iを目標確率Pへ近づける補助損失 sum_i (r_i-P)^2 を負の対数尤度へ加える。これにより全入力を実行して精度だけを上げる逃げ道を塞ぎ、同じ平均計算予算の中で損失低減に寄与しやすい「難しい」トークンを優先的に実行させる。総層数Lを増やしPを下げれば、平均実行層数L×Pをほぼ一定にしたままパラメータ容量を増やせる。

### gather/scatterによる実計算削減
動的maskを得ても全トークンでFFNを実行すれば速度は変わらない。実装では非skipトークンだけをgatherし、固定group sizeにまとめてFFNへ投入し、結果を元位置へscatterする。groupが大きすぎるとskipトークンを埋める無駄が増え、小さすぎると細粒度groupが増えて並列性が落ちる。主実験ではGsize=1024を使う。

自己注意では事情が異なる。skipトークンも将来トークンから参照される文脈なのでKey/Value投影は全トークンについて計算し、キー・値キャッシュ (key-value cache; KV cache) に残す。一方、skipされた現在トークン自身についてはQuery投影、注意出力、FFNを省く。この設計により「計算を飛ばした過去トークンが後続から見えなくなる」問題を避ける。

## 評価条件
| 観点 | 条件 |
|---|---|
| 事前学習データ | 1.6兆token。web、books、Wikipedia、conversation、forum、news等 |
| モデル幅 | hidden 1536、FFN幅8倍、attention head次元64 |
| 学習系列 / batch | 1,024 token / 256 sequences |
| 規模 | 408Mの6層密モデルから5.79Bの96層SkipLayerまで |
| 実効層数 | 6、12、24を揃え、総層数とdensityを変更 |
| 評価 | 4 NLG + 20 NLUの24タスク、1-shot |
| NLG | TriviaQA、NQS、WebQS、SQuADv2、greedy decoding、Exact Match |
| NLU | ANLI、ARC、BoolQ、HellaSwag等20タスク |
| 速度 | single TPU v3でdecode、single TPU v4でtraining |
| 比較 | Standard、WideFFN、HighwayNet、Random Gating |

## 主要結果
同じ実効層数でも総層数を増やして疎にすると1-shot性能が上がる。6層密モデルに対し、平均6層を実行するSkipLayer 24層・density 25%は、計算FLOPsを18.2%増やす代わりにNLG平均を51.5%相対改善する。12層密モデルに対する48層・25%は19.2%追加FLOPsで28%、24層密モデルに対する96層・25%は20%追加FLOPsで22%の改善を報告する。さらに96層・12.5%は24層密モデルより少ないFLOPsで、より高い1-shot性能を示す。

実時間ではSkipLayer 12層・50%は6層密モデルとほぼ同じtoken当たりdecode時間、24層・50%も12層密モデルと近い。48層・50%は24層密モデル比で1-shot性能+8%に対しdecode時間+6%である。一方96層・25%は48層密モデルに対し品質低下約0.5%だけでdecode効率を約20%改善する。したがってFLOPsだけでなくgather/scatterの疎実装も実速度へ反映されている。

学習側でも、24層・50%は対応する全密モデルより18%高速、48層・12.5%は約3倍高速である。ただし総層数を増やすほどrouter、残差経路、Key/Value投影などskipできない固定費が増えるため、理論的なdensity比ほど速度は伸びない。

構成要素除去実験 (ablation) では、同じdensityで各トークンを無作為に実行するRandom Gatingより学習済みルータがNLG/NLUの両方で明確に高い。つまり利得は「大きいモデルから同数の層をランダム実行する」だけでは得られず、文脈依存の計算配分に由来する。可視化でもtokenごとのskip数は一定でなく、情報量の高いtokenほど多くの層を通る傾向を示す。

## 既存研究との差
早期終了は一度終了したtokenが後段計算へ戻らないのに対し、SkipLayerは各中間層を独立に実行・迂回できる。混合専門家 (Mixture-of-Experts; MoE) が同じ深さでFFN expertを選ぶのに対し、SkipLayerは層そのものの深さ方向の計算を選ぶ。またLayerDropのような学習時正則化後に固定深度を切り出す方式と異なり、推論時にもtokenごとに異なる実行経路を使う。

## 限界
既存の密モデルへ後処理だけで適用する手法ではなく、事前学習時からrouterと補助損失を学ぶ必要がある。動的gather/scatterはgroup sizeへ敏感で、大きすぎるとpadding的な無駄、小さすぎると並列性不足が生じる。自己注意のKey/Valueはskip tokenでも保存するため、FFNやQuery計算は減らせてもKVキャッシュ容量そのものを同じ比率では削減できない。また評価は最大5.79B・TPU上の単一モデル中心で、現代の数十B級モデル、連続バッチ処理、SLO制約下の多利用者サービングについては直接検証していない。
