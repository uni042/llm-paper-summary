# Latent-Condensed Attention：MLAの潜在空間で意味と位置を別々に圧縮する

## 概要

長文脈推論の効率化には、鍵・値（KV）キャッシュの容量削減と注意計算の削減という二つの課題がある。多頭潜在注意（multi-head latent attention、MLA）はトークンごとのKVを低次元潜在へ圧縮するが、文脈の全トークンを保持し、注意計算も全長に対して行う。疎注意（sparse attention）は計算するトークンを減らせるが、MLAの圧縮済み潜在表現に直接適用できない方式では、フル次元KVの復元費用が必要になる。

本論文の潜在圧縮注意（Latent-Condensed Attention、LCA）は、MLAの圧縮済み潜在をさらにグループ単位で縮約する。意味を表す潜在ベクトルは問い合わせに応じた重み付き平均で集約し、回転位置埋め込み（rotary position embedding、RoPE）に由来する位置キーは重み付き平均せず、最も重要な一つを選ぶ。直近の文脈は圧縮せず残す。この二経路の設計で、キャッシュのトークン数と注意計算を同時に減らす。

DeepSeek-V2-Liteを使った128K文脈のRULERでは、初回トークン遅延が標準MLAの10.78秒から4.40秒へ短縮し、KVキャッシュは10.13GBから0.71GBへ減少した。RULERの128K得点は23.96から24.38と同程度である。一方、複数文書質問応答ではLongBench-Eの得点が11.15から8.90へ低下する。**圧縮による局所的な情報消失を無視して「精度無劣化」と断定することはできない。**

## 背景と問題設定

MLAでは各トークンの隠れ状態を低次元の共有潜在 $\mathbf{c}^{KV}$ へ射影し、鍵・値を復元するための低次元表現と、位置を表すRoPEキー $\mathbf{k}^{R}$ を保持する。一般的な多頭注意（multi-head attention、MHA）よりトークン当たりのキャッシュ容量を小さくできるが、過去トークン数 $L$ に比例してキャッシュが増え、事前充填（prefill）の密注意は概ね $O(L^2)$ の計算を要する。

既存の動的疎注意は、復元後の鍵・値の類似度や注意得点を使って一部のブロックを計算する。しかしMLAの潜在ベクトルを完全な鍵へ復元してから間引くと、低次元表現のまま計算する利点が薄れる。LCAは**復元する前の潜在空間**で情報をまとめることにより、トークン数そのものを減らす。

単純な平均が危険な理由は、MLAの保存表現が意味成分と位置成分に分かれているためである。意味成分は近い内容を平均しても一定の意味を保持できる場合があるが、異なる位置のRoPEキーを平均すると、どのトークンの位置にも対応しないベクトルになり、相対位置の整合性が崩れる。したがって、意味は集約、位置は選択という異なる操作を使う。

## 手法

### 1. 過去文脈をグループに分割する

系列長を $L$、直近の未圧縮窓を $w$、グループサイズを $g$ とする。古い部分を $g$ トークンずつ $m=\lfloor(L-w)/g\rfloor$ 個の連続グループに分ける。直近の $w$ トークンと、割り切れない端数トークンは元の精度で保持する。標準設定は $g=16$、$w=1024$ である。

問い合わせ依存の重要度を計算するため、直近 $g$ 個の問い合わせベクトルを平均した $\bar{\mathbf q}$ を作る。各グループ $G_j$ 内のトークンについて、問い合わせと鍵の内積に基づく得点 $s_i=\bar{\mathbf q}^{\top}\mathbf k_i/\sqrt{d_h}$ を計算し、グループ内ソフトマックスで $\alpha_i^{(j)}$ を得る。得点はその時点の問い合わせに依存するので、固定位置だけで選ぶ方法と異なり、質問に関係するトークンへ重みを寄せられる。

### 2. 意味潜在は重み付き平均する

各グループの代表潜在を $\mathbf c_j^{rep}=\sum_{i\in G_j}\alpha_i^{(j)}\mathbf c_i^{KV}$ とする。これは全トークンを捨てて一つだけ残す選択ではなく、全トークンの意味潜在を重み付きでまとめる操作である。論文の命題1は、重要度 $\alpha$ に従って標本化したグループ内潜在に対する期待二乗再構成誤差を最小にする代表ベクトルが、この重み付き平均であることを示す。

ただし、この最適性は**与えられた重みの下での潜在再構成誤差**についてであり、最終的な言語モデルの全タスク正答率が最大になることを保証するものではない。重み付けに使う要約問い合わせが将来の全質問を正しく代表するとも限らない。

### 3. 位置キーは最大重要度のトークンを選ぶ

RoPEの位置情報を混ぜないため、各グループの重要度最大トークン $I_j=\arg\max_{i\in G_j}\alpha_i^{(j)}$ を位置アンカー（positional anchor）として選び、$\mathbf k_{I_j}^{R}$ を代表位置キーとして残す。意味潜在の重み付き平均と、位置キーの単一選択を組み合わせて代表KVを構成する。

この設計により、位置キーが実在トークンの位置を指すという性質を保つ。一方、グループ中の他のトークンが持つ個別の位置・識別情報は失われるため、複数文書から固有名詞や数値を厳密に検索する課題では誤差が生じうる。

### 4. 直近窓と代表潜在を統合して注意計算する

古い文脈から作った代表KV $\mathbf K^{rep},\mathbf V^{rep}$ と、直近の未圧縮KV $\mathbf K^{loc},\mathbf V^{loc}$ を連結し、その縮約済み集合に対して注意を計算する。全長 $L$ に対する注意の代わりに、代表数 $m$ と直近窓 $w$ の合計に対する注意になる。短い系列 $L<w+g$ では縮約の利点が小さいため標準MLAへ戻す。

デコード中は新しいトークンを直近窓へ追加し、グループサイズに達した古いトークン群を一つの代表へ縮約してキャッシュへ追加する。保存するトークン単位の状態は概ね $O(m+w)$ であり、古い全トークンの潜在を個別に保持し続ける必要はない。問い合わせ依存の縮約をオンラインで更新するための追加演算がある点には注意が必要である。

### 5. 誤差上界の前提

論文は、問い合わせノルムが有界、値ベクトルのノルムが有界であり、各グループ内の元の鍵・値と代表鍵・値の偏差が一様に $\delta_k,\delta_v$ で抑えられるという条件で、標準MLAとLCAの注意出力の誤差上界を導く。この上界は系列長そのものに依存しない。ただし、偏差の上界が小さいことを無条件に保証する定理ではない。**グループ内に異質なトークンが多い場合は偏差が大きくなり、理論上界が実用的に緩くなり得る。**

## 評価

### 実験条件と比較対象

| 項目 | 条件 |
|---|---|
| 主対象 | DeepSeek-V2-Lite（16B、MLA） |
| 拡張検証 | MiniCPM3-4B（MLA）、DeepSeek-R1-Distill-Qwen-7B（GQA） |
| 追加学習 | SlimPajama、系列長32K、1,000ステップ |
| 主要ハイパーパラメータ | グループサイズ16、未圧縮窓1024 |
| 実機 | 8×NVIDIA H200 GPU |
| 実装 | 著者によるTritonカーネル最適化 |
| 比較 | 標準MLA、MInference、FlexPrefill、KDA |
| 長文評価 | LongBench-E、RULER（4K～128K） |
| 短文評価 | MMLU、GSM8K、MBPP |
| 指標 | 各課題の得点、初回トークン遅延（FTL）、デコード間隔、KVキャッシュ容量 |

MInferenceとFlexPrefillは通常の注意を対象とするため、著者はMLAからフル次元KVを復元して適用する形に調整している。KDAは本来スクラッチ学習を想定するため、同じ1,000ステップの追加学習で適応させた比較であり、各方式の最適な独立実装同士の比較とは限らない。

### DeepSeek-V2-Liteでの長文品質と速度

| 条件 | 標準MLA | LCA | 解釈 |
|---|---:|---:|---|
| LongBench-E平均 | 29.51 | 29.09 | 0.42点低下。平均としては近い |
| RULER 4K～128K平均 | 58.91 | 58.80 | 0.11点低下 |
| RULER 128K得点 | 23.96 | 24.38 | LCAが0.42点高いが統計的優位は未確認 |
| RULER 128Kの初回トークン遅延 | 10.78秒 | **4.40秒** | 2.45倍の短縮、論文では約2.5倍 |
| 128KのKVキャッシュ | 10.13GB | **0.71GB** | 約93.0%削減（論文本文は約90%と表現） |
| 128Kのデコード間隔 | 基準 | 約1.8倍改善 | 図からの著者報告。絶対値はここでは記載しない |

LongBench-Eの内訳では、コード生成が58.17から58.67へ改善し、要約も17.52から23.74へ改善する。一方、複数文書質問応答では11.15から8.90へ低下し、単一文書質問応答も23.92から22.61へ低下する。平均値だけでは、正確な固有情報検索で生じる損失を見落とす。

RULERでは64K得点が標準MLAの47.57に対しLCAは50.63、128K得点が23.96に対し24.38だった。ただし長文脈の検索課題における改善は、データや設定に依存し得る。数値の差が小さい場合は統計的有意性が示されていない限り過大評価しない。

### 別モデル・別注意機構への一般化

| モデル・課題（128K） | 基準品質 | LCA品質 | 初回トークン遅延 | KVキャッシュ |
|---|---:|---:|---|---|
| MiniCPM3-4B、LongBench-E平均 | 43.28 | 42.05 | 8.05秒→3.61秒（2.2倍） | 4.36GB→0.30GB（93%削減） |
| DeepSeek-R1-Distill-Qwen-7B、OlympiadBenchMath | 50.85 | 50.13 | 9.87秒→3.04秒（3.25倍） | 7.00GB→0.49GB（93%削減） |

後者はMLAではなくグループ化問い合わせ注意（grouped-query attention、GQA）を使うため、位置を持つ鍵を最大重要度で選び、値を重み付き平均するように変更している。これにより原理がMLA専用ではないことを示すが、異なる注意機構で完全に同一の処理を行うわけではない。

### 構成要素除去実験と性能上の交換関係

代表意味潜在の生成方法と位置キーの生成方法を組み合わせて比較したところ、意味潜在を重み付き平均、位置キーを最大選択とした組み合わせがLongBench-E平均29.09で最高だった。両方を平均する場合は26.39であり、RoPE位置キーの単純平均が不利なことを裏付ける。

グループサイズを32から16、8へ減らすとLongBench-E平均は28.32→29.09→29.38と改善するが、保持する代表が増えて計算・キャッシュ費用も増す。直近窓を512から1024、2048へ増やすとRULER 128K得点は23.68→24.38→25.53へ改善する一方、遅延が増える。よって $g=16,w=1024$ は万能な最適値ではなく、品質と速度の妥協点である。

著者はTritonカーネルとPyTorch実装を比較し、64Kでカーネル単体最大24.4倍の高速化を報告する。ただし、これは**カーネル実装同士の比較**であり、標準MLAに対するモデル全体の初回トークン遅延が24.4倍改善したことを意味しない。PyTorch実装は64K超でメモリ不足となる条件がある。

## 既存研究との差

MLAは各トークンのKVを低次元に保存することでキャッシュの**幅**を減らす。LCAはさらに古いトークンをグループ代表へまとめて保存トークン数という**長さ**も減らす。単純なKV削除は重要でないと判断したトークンを失うが、LCAの意味潜在集約は全グループ要素の寄与を重み付きで残す。一方、位置は混合せず一つの実在トークンをアンカーにする。

MInferenceやFlexPrefillのような疎注意は注意計算する領域を選ぶが、比較実装ではMLA潜在からのフル次元KV復元が必要になる。LCAは潜在空間で直接集約するので、復元を介さずキャッシュと注意計算の両方を削減できる。KDAは異なる注意構造と学習手順を持つため、単純な同条件の疎注意置換とは比較条件が異なる。

## 限界・負の結果

第一に、グループ代表への縮約は元の全トークンを保持する可逆変換ではない。複数文書QAでは11.15→8.90と明確な品質低下がある。長い会話履歴やRAGで、固有の数値・識別子・引用箇所を正確に再現する用途では、単なる平均品質だけで採用を判断しない。

第二に、誤差上界は各グループ内の鍵・値の偏差に条件を置く。グループ内で話題が大きく切り替わると偏差が増える可能性があり、長さ非依存の上界を「情報損失が絶対に増えない保証」と読み替えてはいけない。

第三に、Tritonの専用カーネルと1,000ステップの追加学習が前提である。標準の推論エンジンにコードを貼るだけで再現できるわけではない。著者自身、低精度のINT8などでは最適化を十分検証していないと明記している。低精度KV量子化との併用性能は未評価である。

第四に、比較方式には著者がMLA用に改変したものがあり、すべての方式の最適な独立実装を比較したわけではない。実測環境も8×H200に集中しているため、単一のRTX 4070 Super 12GBで同じ倍率を期待する根拠はない。

第五に、論文はグループサイズや未圧縮窓が精度と速度を変えることを示す。タスク特性に応じて自動調整する方式は今後の課題であり、現在の固定値は用途を跨いだ普遍的な最適解ではない。
