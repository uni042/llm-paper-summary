# GGUFメタデータによるllama.cpp単一系列処理速度の予測

## 概要

ローカル大規模言語モデルを選ぶとき、GGUF形式の複数の量子化モデルを実際に読み込み、同じ入力長で速度を比較する作業は重い。モデルファイルの大きさだけで推定すると、混合専門家モデル（MoE）では保存されている全専門家を毎トークン使うかのように過大計算する。また、KVキャッシュの大きさを全層で同じ文脈長として扱うと、滑動窓注意や再帰状態を含むモデルで転送量を過大評価する。

本論文は、GGUFヘッダーに含まれる重み構成、専門家数、選択数、層ごとのKVヘッド数・次元・注意窓を用い、帯域上限を基礎にした復号速度モデルを作る。量子化形式ごとの実行効率は少数の既知モデルの測定から求め、未測定モデルへ適用する。MacBook Pro M4 Max、Mac Studio M4 Max、NVIDIA RTX 5080での未知モデル予測は平均絶対百分率誤差（MAPE）13.1%、14.4%、36.1%であり、全重みを毎トークン読む基準方式の49.4%、55.3%、51.9%より改善した。

ただし事前計算（prefill）用の簡易モデルはRTXで108.2%のMAPEとなり、論文自身が予測失敗を明示する。GPU上の物理的なメモリ常駐や転送経路を観測していないため、RTXでの誤差の原因を量子化カーネルだけへ帰属できない。

## 問題設定

### ファイル容量とトークン当たり重み交通量は異なる

密なTransformerでは、復号の各ステップで多数の重みを読み、行列・ベクトル積を実行する。バッチが1に近い場合、重みを読み出すための帯域が速度の上限となる。単純な屋根線モデル（roofline model）は、メモリ帯域Bを1トークン当たりの転送バイト数Dで割り、生成トークン毎秒を予測する。しかし実行効率、量子化解除、キャッシュ、転送などの実装差を無視すると実測から外れる。

MoEは特に注意が必要である。ファイルには全専門家の重みが保存されるが、各トークンが通るのは一部の専門家だけである。総パラメータ数Pに比例して転送量を計算すると、実際に有効化される重み量P_aを過大評価する。論文はファイルサイズSにP_a/Pを掛けて重み交通量の近似を作る。ただし共有テンソルと専門家テンソルの量子化率が違う場合、この近似は厳密ではない。

### KVキャッシュの層別構造

復号では過去トークンのKVも読み出す。全層が全文に注意するモデルなら文脈長cに比例するが、滑動窓注意では窓幅wを超える過去を読まない。再帰状態を使う層ではKV配列を持たず、固定長の状態交通量だけが必要な場合がある。GGUFメタデータの層別情報を使えば、この差を事前に計算できる。論文は全層をグローバル注意と仮定した際の10倍以上の過大評価を実測モデルで示す。

## 手法

### 1. 有効化パラメータの近似

総パラメータPのうち専門家バンクがP_e、専門家数E、1トークンで選ぶ専門家数kであれば、有効化パラメータ数を次のように近似する。

\[
P_a=P-P_e+(k/E)P_e
\]

密なモデルではP_a=Pとする。GGUFのテンソル形状とルーティング関連フィールドからP_e、E、kを推定する。保存容量Sは全モデルの量子化重みを含むが、復号の各トークンで読む量はS(P_a/P)と近似する。これは専門家ルーティングが概ねk個を選び、重みバイト数がパラメータに比例するという仮定に依存する。

### 2. 層別KVと再帰状態の交通量

層iのKVヘッド数をh_i、ヘッド次元をd_i、窓幅をw_iとする。FP16のKVを使う条件では、鍵と値の二組に対し各スカラー2バイトを読み出すため、論文は次の式を使う。

\[
K(c)=\sum_i 2h_i d_i\min(c,w_i)b_{KV}+S_{state},\quad b_{KV}=2
\]

全注意層ではw_iを無限大とみなし、滑動窓層では過去長が窓幅で頭打ちになる。再帰状態の層はh_i=0として固定状態S_stateへ加える。これにより、GGUFの層構成が異なるモデルを同じ文脈長で比べてもKV転送量を一律に見積もらない。

### 3. 帯域モデルと量子化別校正

1トークン当たりの総交通量はD(c)=S(P_a/P)+K(c)であり、ホストhの校正帯域B_hと量子化形式qに対する係数η_{h,q}から復号速度を次式で予測する。

\[
\widehat T_d(c)=\eta_{h,q}\frac{B_h}{D(c)}
\]

ηは基準測定のT_dD/B_hを量子化形式ごとに計算した中央値である。未知の量子化形式にはホスト全体の中央値を代用する。中央値を使うのは、極端に速い小型モデルが最小二乗回帰を支配しないようにするためである。ηは単純なGPU利用率ではない。分母の交通量と帯域校正は近似値なので、係数が1を超えても物理帯域違反を意味しない。

比較モデルは三つである。B0は係数を学習せず総ファイル容量とKVを使う素朴な帯域上限、B1はホスト・量子化別係数を学習するが全パラメータを読み出すとみなす方式、B2は同じ校正規則のまま有効化重みと層別KVを用いる提案方式である。B1とB2を比較することで、校正方法の差ではなく活性化重みを数える効果を切り分ける。

### 4. 事前計算の別モデルと失敗条件

事前計算では重みの行列積が中心になるため、校正された行列演算性能F_hと有効化重みP_aから、ゼロ文脈の事前計算速度を\(\widehat T_p=\phi_{h,q}F_h/(2P_a)\)と推定する。P1はホストごと、P2はホストと量子化形式ごとに係数φを当てはめる。

この式には文脈長による注意演算の増加が含まれない。長文脈への外挿には原理的に弱く、GPUカーネルや演算の形状による差も帯域モデルより大きい。論文は失敗した事前計算モデルを成功例へ混ぜず、復号の結果とは別に報告している。

## 評価条件

| 項目 | 設定 |
|---|---|
| 実行基盤 | MacBook Pro M4 Max 64GB、Mac Studio M4 Max 128GB、NVIDIA RTX 5080（報告VRAM 16,302 MiB） |
| 計測ソフト | llama.cppのllama-bench。Studioは記録済みb10794、RTXのバージョン照会は不完全、MacBookの旧版は未特定 |
| ホスト校正 | コピー帯域380.1、396.7、801.1 GB/s。FP16行列演算13.95、15.00、118.83 TFLOP/s |
| 対象 | 23 GGUFファイルの共有一覧から、成功した53ホスト・ファイル構成、22ファイルを採点 |
| 測定 | 事前計算512トークン、復号128トークン。文脈深度0、4096、16384。各5回反復 |
| 量子化・KV | 複数量子化形式、KVはFP16固定、FlashAttention有効 |
| データ分割 | モデル系列ごとに学習と未知モデルへ固定分割。MacBook 15/4、Studio 15/5、RTX 12/2構成 |
| 観測値 | 318件の局面・深度測定。復号の採点対象は159行 |
| 指標 | 平均絶対百分率誤差（MAPE）。低いほど速度予測が実測に近い |

モデルのロード状態は測定していない。RTXではGPU層数99を要求したが、最大モデルの理論作業集合が報告VRAMを超えるため、すべての層が物理GPUメモリに常駐したとは保証できない。

## 評価

### 1. 未知モデル系列に対する復号速度予測

| ホスト | B0未知モデルMAPE | B1未知モデルMAPE | B2未知モデルMAPE | P2事前計算MAPE |
|---|---:|---:|---:|---:|
| MacBook M4 Max | 46.9% | 49.4% | **13.1%** | 18.7% |
| Studio M4 Max | 58.0% | 55.3% | **14.4%** | 22.2% |
| RTX 5080 | 41.7% | 51.9% | **36.1%** | 108.2% |

B2はすべてのホストでB1より良い。B1がB0より悪い未知モデル条件もあり、量子化係数を当てはめるだけでは一般化しない。MoEの有効重みと層別KVという構造情報を入れることが改善の主要因である。一方、RTXのB2誤差36.1%はApple系より大きく、単純な帯域律速だけで十分な予測とはいえない。

### 2. 層別KV構造の効果

Gemma-4の二つの例で、すべての層がグローバル注意だと仮定すると16K文脈のKV転送量を10.7〜13.7倍過大評価する。層別の窓幅・再帰状態を使い、同じ校正方式で比較すると、未知モデルMAPEはMacBookで21.2→13.1%、Studioで21.0→14.4%、RTXで37.9→36.1%へ改善した。RTXでの改善幅は小さいため、KV構造の補正だけで全ての誤差を説明できない。

### 3. ホスト間係数転移

対象ホストの係数を使わず、他の二機種で学習した係数を対象ホストの帯域へ移した場合、未知モデルMAPEはMacBook 11.6%、Studio 16.8%、RTX 36.0%だった。対象ホストに合わせたB2と近い場合もあるが、同じファイルが学習元ホストに含まれるため、ホストとモデルを同時に完全に未知とする試験ではない。

三機種で共通する14構成では、RTX/MacBookの復号速度比は構成により1.76〜3.26倍の範囲に広がる。GPU帯域比だけから全量子化形式に共通の倍率を掛ける方法では、この差を説明できない。Qwen3.8-27Bの低ビット比較では、Apple二機種でQ2がIQ2より2.2%速いのに対し、RTXではIQ2が13.7%速い。なおIQ2は比較対象よりパラメータ数が1.55%少なく、厳密な同一モデル・同一形式比較ではない。

### 4. 事前計算の明確な負の結果

P2の未知モデルMAPEはMacBook18.7%、Studio22.2%、RTX108.2%となり、RTXでは速度予測として機能していない。さらに文脈深度16Kでの事前計算MAPEはそれぞれ76.2%、68.1%、133.3%まで悪化する。これはP2がゼロ文脈の行列演算のみを表現し、長文の注意演算を扱わないことと整合する。RTXでばらつきの大きい測定を中央値へ置き換えてもMAPEは85.5%残るため、少数のノイズ測定だけでは失敗を説明できない。

### 5. 測定の安定性と残差

復号の繰り返し測定の変動係数の中央値はMacBook0.83%、Studio0.42%、RTX0.43%である。大きな予測誤差と短時間の計測揺らぎは同一ではない。RTX未知モデルでは中央値誤差25.8%、最大誤差69.0%があり、GPU常駐、量子化カーネル、ランタイム版などの差が残っている可能性があるが、未計測の原因を断定しない。

## 既存研究との差

通常の屋根線モデルは計算能力と帯域のどちらが律速かを概算する。LLMCompassはハードウェア設計探索、Vidurは配信負荷のシミュレーションを主対象とする。本論文は単一系列のGGUFモデル選択に焦点を絞り、未測定モデルの復号速度をファイルメタデータと少数の実機基準測定から推定する。特にMoE有効重みと層別KVの構造補正を独立に検証した点が重要である。

## 限界

未知モデルのRTX評価は二つのQ4_K_Mファイルに限られ、幅広いGPUや量子化形式で同じMAPEが成立する保証はない。モデルの実際のGPUメモリ常駐、共有メモリへの退避、クロック、電力は観測されていない。MacBookの旧ランタイム版も特定できず、同じGGUFでもランタイムとハードウェアの組合せで速度順位が変わる。係数の学習に必要な基準モデル数について学習曲線も示されていない。

したがって本方式は「このホストでどのGGUFが速そうか」を絞る補助として有用だが、実機測定の代替として普遍的な精度を保証するものではない。特に例えばRTX 4070 Superのような未評価GPUへ5080の係数をそのまま移すことは、論文の実験から支持されない。


### ローカル推論環境での再現設計

未知GPUへ適用する場合は、論文の係数を流用せず、そのGPUで少数の基準GGUFを測定してηを再推定する。少なくとも密モデルとMoEモデル、Q4系とQ8系、短文脈と16K文脈を分け、実行時のGPU層数・メモリ常駐量・共有メモリ退避の有無を記録する必要がある。実際の常駐量が未確認のまま理論上の重みバイト数だけを式に入れると、ホストRAMとGPU VRAMの転送経路を無視することになる。

測定対象を単一系列に固定し、バッチサイズ、生成長、KV量子化、FlashAttentionの有効・無効、コンテキスト長、CPUスレッド数、電力制限を一定にする。次に各量子化形式で学習用の基準モデルと未知モデルを分ける。モデルの量子化形式が同じでもカーネルの実装はランタイム版で変わるため、llama.cppの正確なコミット、CUDA版、GPUドライバ、OSも保存する。これらは論文が報告したランタイム版の欠落を補う再現性の要件である。

モデル系列の分割はランダムなファイル単位ではなく、同じ基本モデルのQ2/Q4/Q8が学習とテストへまたがらないようにする。そうしないとメタデータの差よりもモデル系列の共通性を覚えてしまい、未知モデルの誤差を過小評価する。GPU間の係数転移を評価するときも、同じGGUFが元ホストの学習集合にあるかを明記する。

### 予測モデルを拡張する場合の論点

RTXでの誤差が大きい理由を調べるには、重み転送の実測帯域、量子化解除の演算時間、CUDAカーネルの起動回数、CPU-GPU転送を別々に計測する。B2はD(c)をすべて同一の帯域で運ぶ近似だが、GPUに収まらないモデルではPCIeやシステムRAMからの転送が混じる。これを一つのηで吸収すると、同じホストでもモデル容量を変えた際に係数が破綻し得る。メモリ常駐状態に応じて帯域項を切り替える区分モデルが必要かを検証すべきである。

事前計算は単純なF_h/(2P_a)では長文脈に対応できないため、注意演算の二乗項、行列演算形状、量子化形式別の演算効率、バッチサイズの効果を明示的に追加する必要がある。ただし自由な係数を増やしすぎると小規模な学習集合へ過適合するため、係数数と学習ファイル数の関係を示す学習曲線が不可欠である。
