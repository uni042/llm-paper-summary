# MoBiQuant：残差ビットスライスとトークン別選択による可変精度LLM推論

## 概要

大規模言語モデル（Large Language Model; LLM）の推論における重み量子化は、GPUメモリ容量と重み読み出し帯域を節約する一方、ビット幅を下げるほど丸め誤差を増やす。従来の事後学習量子化（Post-Training Quantization; PTQ）は3ビット用、4ビット用など、選択した精度ごとに校正するのが一般的である。しかし、端末の空きメモリや他アプリケーションとの資源競合が変動する場合、精度ごとにモデルを保存・ロードし直す設計は扱いにくい。

**MoBiQuant**は、一つの重み集合を2ビット単位の残差スライスへ分け、入力トークンごとに使うスライス数を選ぶ。**MoBiSlice**が単一の基礎表現から2、4、6、8ビットの重みを再構成し、**MoBiRoute**が各トークンの量子化誤差への敏感さと平均ビット予算を考慮して必要な残差を選ぶ。通常の固定精度PTQとは異なり、同じ層の別トークンが異なる演算精度を使える。スライスをビットプレーンとして保存し、GPUカーネルで必要なスライスだけを読み出すため、理論上の精度切替を実際の転送削減へつなぐことを狙う。

原著の表1では、LLaMA2-7Bの平均3ビットでWikiText2困惑度（Perplexity; PPL、低いほど予測が良い）がAnyBCQの6.25から6.07へ改善し、同時に復号処理量が268から311 token/sへ増えた。ただし、LLaMA3-8Bの2ビットではMoBiQuantのPPL 58.12はQTIPの7.25より大幅に悪く、極低ビットで常に最良とはいえない。速度・品質の利得はモデル、平均精度、比較対象によって変わる。

## 問題設定と背景

### 固定ビット幅校正が精度変更へ一般化しない理由

量子化では、浮動小数点重みを限られた整数符号へ丸め、尺度やクリッピング範囲を校正データで調整する。たとえば4ビットでは16段階、3ビットでは8段階しか使えない。外れ値に量子化範囲を合わせると普通の重みの刻みが粗くなるため、OmniQuantなどは校正時に範囲・変換を学習して出力誤差を減らす。しかし、3ビットに合わせて決めた尺度が4ビットでも最適とは限らない。

著者らは、LLaMA3-8Bを3ビット用に校正した後、重みだけ4ビットへ切り替えると、4ビット専用校正に比べPPLが**2.65ポイント**悪化する例を示す（原著図1）。これは単に精度を増やせば必ず改善するという直感に反する。トークン単位の量子化誤差を調べると、3ビットで誤差が大きいトークンと4ビットで誤差が大きいトークンの集合が一致しない。著者はこの分布変化を**外れ値移動（outlier migration）**と呼ぶ。

重要なのは、外れ値移動をモデル全体の重み外れ値の移動と誤解しないことである。論文の観測対象は、同じ入力トークンが異なるビット幅で推論されたときの**トークンごとの出力量子化誤差**である。校正で特定の精度の誤差が大きいトークンへ適合しすぎると、精度を変えた後の誤差分布をうまく扱えない。

### 可変精度方式の実装上の難点

単一モデルから複数の精度を取り出す既存方式には、重みの低ビット表現を増分的に拡張するAnyPrecisionLLM、精度別尺度を持つAnyBCQ、上位ビットを切り出すMatQuantなどがある。ただし、ベクトル量子化の参照表やビット転置、精度ごとの尺度、オフライン再パッキング、別カーネルの起動が必要なら、切替の管理費用が実際の推論利得を打ち消す。

MoBiQuantの設計課題は三つある。第一に、単一重みから各精度を**共通尺度で再構成**できること。第二に、トークンごとのビット幅選択が追加の大きな推論負荷を生まないこと。第三に、使わないビットスライスのメモリ読み出しを本当に省き、GPUの連続アクセスと負荷均衡を維持することである。著者は単なる量子化誤差の改善ではなく、この三つを一体として扱う。

## 手法

### 1. MoBiSlice：共通尺度による再帰残差量子化

各線形層の重み行列をW、最初の残差をR₁=Wとする。第e段で残差Rₑをbₑビットへ量子化してスライスWₑを得た後、Rₑ₊₁=Rₑ−Wₑを次段へ渡す。したがって、第k段までの和W⁽ᵇ⁾=Σₑ₌₁ᵏWₑは、元の重みを順次細かく近似したものになる。既定構成は**2ビット×4スライス**であり、先頭1段で2ビット、2段で4ビット、3段で6ビット、4段で8ビット相当の再構成を得る（原著§4.1、式2・3）。

第1スライスは最上位ビット（Most Significant Bits; MSB）に相当する全トークン共通の基礎表現であり、追加の残差スライスは近似を細かくする役割を持つ。第e+1段の尺度は第e段の尺度から2^(bₑ−1)で除して求めるため、精度ごとに独立した尺度群を学習する必要がない。ビットプレーン上でシフトと加算を使って合成でき、同じ種類の低ビット演算を再利用できる。

これは「2ビット重みモデルを複数個別保存する」方式ではない。基礎スライスと残差が共有されるため、異なる精度で使用する上位部分は同一である。ただし、最大8ビットまでの全スライスを保存する以上、単一の2ビットモデルと同じメモリ量になるわけではない。省メモリ効果の比較対象は**複数の精度のモデルを別々に保存する構成**である。

### 2. MoBiRoute：トークンごとの残差スライス選択

MoBiRouteは入力トークン表現Xを2層の多層パーセプトロン（Multi-Layer Perceptron; MLP）へ入力し、トークン数T×スライス数EのスコアSを出力する。各Sᵢₑはトークンiが残差スライスeを必要とする度合いである。推論ではしきい値を越えたスライスを有効化し、選択されたスライスによる行列積の結果を合計して出力を作る（原著§4.2、式4・6）。最初の2ビットスライスは全トークンで必ず通過させ、極端な低精度でも基礎演算を残す。

単純な硬い二値判定では勾配を流せないため、校正時はシグモイド関数の温度τを段階的に上げる。初期には柔らかくスライスを混ぜ、校正終了時には0/1のマスクに近づける。ここで学習されるのは事前学習済みLLMの本体重みではなく、量子化パラメータΘqとルータパラメータΘrである。元の重みを凍結したまま、線形層の浮動小数点出力と量子化出力のL2誤差を小さくするように校正する。

平均ビット数を無制限に増やすと品質がよくなるだけなので、ルータには**平均ビット予算を守る正則化**を加える。原著式7では、訓練ステップtに応じた目標b(t)を高精度側（例8ビット）から目標b（既定3ビット）へ対数的に下げる。現在の平均ビット数が目標より大きければ余分なスライスを減らす方向へ、少なければ追加スライスを使う方向へ誘導する。これにより同じ平均3ビットでも、敏感なトークンは4ビット、そうでないトークンは2ビットといった混合が成立する。

### 3. 実行時の精度変更と「再校正不要」の境界

校正後はスコアSに対するしきい値δを変えることで有効スライス数を調整する。δを大きくすると通過スライスが減り平均ビット幅が下がり、小さくすると増える（原著式10）。重み自体の再パッキングや各ビット幅専用の量子化パラメータ再学習は必要ない。

ただし、付録C.2では、目標平均ビット幅`target_bit_eval`を指定した場合、**校正サンプル上のルータスコアから層ごとの分位点しきい値を求め直す**と明記している。したがって「任意の精度へ変更する際に一切の校正作業がない」とは言えない。モデル重みの再量子化と、平均ビット数を目標へ合わせるルータしきい値の再推定は別操作である。論文の「繰り返し校正不要」という表現は、前者の再学習を避ける意味に限定して読むべきである。

### 4. GPUカーネル：使うビットだけを読むためのデータ配置

重みをビットプレーン優先でパックし、必要なスライスだけを読み出す。AnyPrecisionLLMのビット転置・重心表参照を避け、パック済みビットプレーンに直接二値行列積（Binary Matrix Multiplication; BMMA）を適用する。AnyBCQが精度ごとに複数尺度を持つのに対し、MoBiQuantは共通尺度を使い、下位スライスをシフト加算して復元する（原著§4.3、図3）。これによりメモリ転送と復号演算の両方を抑えることを狙う。

トークンごとに必要なスライスが異なると、単純な実装では入力が飛び飛びになり、GPUのメモリアクセスが非連続となる。そこでルーティング後に同じスライスを使うトークンを並べ替えて連続領域へ集める。さらに低位のスライスほど使用頻度が高く、追加スライスの計算量が不均衡になるため、独立したCUDAストリームで基礎スライスと追加スライスの演算を重ねる。

ルータのMLP自体にも追加の行列積がある。これを抑えるため、同一層の投影を永続カーネル内へ融合し、入力を共有メモリで再利用する。重要なのは、**ビット数の減少だけで実行時間が比例して短くなるとは限らない**という点である。ルータ、トークン並べ替え、ストリーム同期、GPU占有率などの費用を含む実測が必要であり、論文は後述のA100実験で一部を測定している。

### 5. 1トークンが線形層を通る流れ

入力トークンの隠れ表現をルータへ渡してスライスの選択スコアを得る。目標平均ビット予算に合わせたしきい値でマスクを決め、全トークンに共通の先頭2ビットスライスを通す。敏感なトークンには追加スライスを選び、同じスライスを使うトークンをまとめてGPU上の連続したバッチへ並べ替える。GPUカーネルが必要な重みビットプレーンだけを読み、スライスごとの行列積を実行し、適切に重み付け・合算して層の出力を作る。残差スライスの追加は近似精度を上げるが、追加の重み読み出しと演算を要する。この一連の選択を線形層ごとに行い、層をまたいで平均ビット数の傾向が異なることも評価している。

### 4. GPUカーネルとメモリ（原著§5.4、図7）

著者はLLaMA2-7Bの単一バッチ復号で、FP16および低ビットカーネルABQ-LLMと比較する。FP16に対して復号遅延が**最大約4分の1**になる条件を報告するが、これはFP16対低ビットの比較であり、AnyBCQに対して4倍速いという意味ではない。原著表1の同一平均ビット条件では、AnyBCQ比の処理量改善は約1.14～1.43倍の範囲にある。

ルータとパッキングの追加費用は、原著図7中央で4ビット時の総遅延の**18%**、8ビット時の**10%**と報告される。原著本文はこれを小さい負担と評するが、18%は無視できるゼロではない。トークン数・バッチ・精度が変われば、並べ替えと同期の固定費が支配的になる可能性がある。

複数精度モデルを個別に配備する場合と比べ、単一の残差スライス集合で最大**3.5倍のメモリ削減**を報告する。これは「FP16モデルを3.5分の1にする」という比較ではなく、複数ビット幅のコピーを保存する構成との差である。モデル重み以外のKVキャッシュ、ルータパラメータ、ランタイム常駐メモリを含む全システムの節約率とも区別する。

### 5. 感度評価、負の結果、再現性（原著§5.3、§5.5、付録D）

外れ値移動の分析では、ビット幅変更で誤差が大きくなるトークンほどルータのスコアが高く、追加スライスを使う傾向が図5で示される。平均3ビットでは2ビットと4ビットのトークンが多く、目標5ビットでは4～6ビット側へ分布が移る（図6）。また、同じ目標ビット幅で校正しても、初期層やMLPの線形ブロックは他の層と異なるビット割当てになり、モデル全体で一律の割当てにはならない。

校正データの感度を示す付録表3では、LLaMA3.2-1B・3ビットのC4校正条件でWikiText2評価PPLが**OmniQuant 22.611に対しMoBiQuant 26.360**と悪化する。C4評価でも33.198対33.382、PTB評価でも38.096対43.888で悪化する。一方、PTB校正ではWikiText2が22.689対16.909と改善する。したがって「校正データを変えても常に優位」ではない。原著の『多くの組合せで優位』という表現を、全組合せでの優位と読み替えない。

正則化の予定（スケジュール）を線形、余弦、指数、対数で比較すると、平均2.5～3.0ビットの低精度域で差が大きく、対数・指数が線形・余弦より良い。最良はデータセットによって変わり、著者は対数予定を採用する。学習時の目標ビット幅も2.5、3.0、3.5、4.0、5.0で比較しており、3.0付近が総合的に良いが、低ビットへ特化した校正は他のビット幅での品質を悪化させ得る。**単一の校正済みルータがすべての精度へ無条件に一般化するわけではない**。

さらに、論文には同じ平均ビット数でトークンへ**ランダムにスライスを割り当てる対照**が明示されていない。したがって「トークンの敏感さを学習したこと」自体の効果と「トークン間で精度を混ぜられること」の効果を完全には分離できない。これは本稿の方法論的な評価上の限界であり、論文がその対照実験を実施したと主張してはいけない。

## 既存研究との差

固定精度のOmniQuantやGPTQは、選択したビット幅での誤差最小化を目的とする。MoBiQuantはOmniQuantを校正基盤に採用しつつ、残差スライスを共有することで単一重み集合から異なる精度を構成し、さらにトークン単位で追加スライスを選ぶ点が異なる。したがって「OmniQuantの精度をそのまま改善する新しい校正損失だけ」の研究ではない。

AnyPrecisionLLMは複数精度の表現を増分的に構成するが、原著が比較する実装ではビットプレーンの転置と重心表参照が処理量の障害となる。AnyBCQはビット幅ごとの尺度が追加の保存・復元負担になる。MoBiQuantは2ビット単位の再帰残差と共通尺度、直接BMMA、トークン並べ替え、ストリーム重畳を組み合わせ、これらのカーネル費用を下げる。MatQuantは上位ビットの切り出しによる複数精度化であり、MoBiQuantのように入力トークンの敏感さで残差スライスを動的選択する機構は中心ではない。

静的なQuIP#やQTIPはベクトル量子化の品質で強い条件があるが、原著表1の評価カーネルでは重心参照が処理量を制約する。静的方式のPPLが良くても必ず実時間で速いとは限らず、逆にMoBiQuantの速度が良くても低ビットの品質差を無視できない。評価目的がモデル容量、応答品質、単一バッチ復号速度のどれかによって採用判断は変わる。

## 限界・実装状況・実運用への示唆

第一に、評価は主としてLLaMA系とNVIDIA A100/CUDA12.9であり、他のGPUアーキテクチャ、異なるカーネル命令集合、長時間の多利用者サービング、分散推論への一般化は示されていない。トークン並べ替え・複数CUDAストリームの効果はバッチサイズやGPU構造に依存する。RTX 4070 Superなど消費者向けGPUの性能・VRAM節約率を原著数値から直接算出することはできない。

第二に、最悪の低ビット条件での品質劣化が顕著である。LLaMA3-8B・2ビットではPPL 58.12で、同じ平均ビット数のAnyBCQ 19.01、静的QTIP 7.25と大差がある。用途が回答精度重視なら、2ビットへ無条件に落とす運用は避けるべきである。逆に3ビットや4ビットでの処理量改善も、同品質制約で再測定してから採用判断すべきである。

第三に、目標平均ビット数へ合わせる層別しきい値の再校正が付録C.2に存在する。重みの再校正・再パッキングは不要でも、ルータのしきい値調整が完全に無料とはいえない。動的な実行時負荷変動に対して、どの頻度でしきい値を更新し、更新費用が何ミリ秒かは原著で十分に分離評価されていない。

第四に、ルータが敏感なトークンを選ぶ因果効果の分離実験が不足する。異なる平均ビット数、固定PTQとの比較、誤差とルータスコアの相関は示されているが、同じビット予算で無作為に精度を混ぜた対照がない。性能差の一部が単なる混合精度化による可能性を排除できない。

第五に、原著v2は論文中に公式コードURLを明示していない。著者の実験条件（128校正系列、20 epoch、A100、CUDA12.9、group size 128）は記載されるが、実装公開、再現性、測定分散や信頼区間は確認できない。数値は著者らの評価結果であり、別環境で再現された独立実証とは区別する。

## 主要な結論

MoBiQuantの寄与は、**残差を2ビット単位で再帰量子化することで一つの重み集合から複数精度を得る**こと、**トークンごとに追加精度を選ぶルータを校正する**こと、**選んだビットプレーンだけをGPUカーネルで読み出す**ことを一体にした点にある。単一バッチA100評価では可変精度の比較方式より高い復号処理量を示した。一方、極低ビットでの品質崩壊、固定PTQとの条件別逆転、校正データ依存、層別しきい値再推定、GPU実装依存という制約を伴う。したがって、実用上は平均ビット数だけでなくPPL・下流正答率・実機token/s・校正費用を同時に測る必要がある。
