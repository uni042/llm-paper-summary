# M-ANT: Efficient Low-bit Group Quantization for LLMs via Mathematically Adaptive Numerical Type

## 概要
M-ANTは、LLMの細粒度グループ-wise量子化で「同じテンソル内でも64〜128要素程度の小グループごとに値分布が大きく違う」という問題へ、数値型そのものをグループごとに適応させる方式である。固定INT4は復号と積和が単純だが分布適合性が弱く、ANTのようにINT/PoT/flintから型を選ぶ方式も候補集合が離散的である。一方、グループごとにk-means codebookを持てば適応性は高いが、metadata、lookup、FP16への展開が重い。M-ANTはこの両極の間を、1つの係数 \(a\) で連続的に形を変えられる数学的適応数値型（Mathematically Adaptive Numerical Type; MANT）で埋める。

対象は重みだけではない。長いデコードではKVキャッシュがメモリと注意機構計算の大部分を占めるため、K/Vも4 bit級へ落とさなければlinear層だけの低bit化の利得が頭打ちになる。しかしKVはトークン生成中に増えるのでoffline量子化できない。M-ANTはKとVの生成方向の違いに合わせたreal-time量子化器、MANTを直接計算できる処理要素（processing element; PE）、systolic arrayを共同設計し、重みとKVを同じ低bit基盤で扱う。

## 問題設定
LLaMA-7BをINT4で量子化する予備評価では、経路-wiseだとWikiText-2 パープレキシティがFP16の5.68から6.85へ悪化する。グループ サイズ 128へ細分すると誤差は大きく減るが、さらにグループを小さくするとscale metadataが増える。しかも著者らがテンソル/経路/グループ単位の累積分布を比較すると、テンソル同士は似ていてもsmall グループ同士の分布は大きくばらつく。したがって「テンソル全体へ最適な型」を選ぶ従来適応型 formatでは、グループ-wise量子化の自由度を十分使えない。

理想的にはグループごとに任意codebookを学べばよいが、16-entry codebookを8 bit値で持つだけでもグループごとに128 bitの追加情報が必要となり、低bit化の利点を食う。さらにcodebook lookup後にFP16へ展開してからGEMMを行うと、メモリとデコード オーバーヘッドが戻る。必要なのは、分布への適応範囲を広げつつ、整数中心のdata pathで直接演算できる表現である。

KV側には別の制約がある。K キャッシュは注意機構計算上transposeされ、グループの要素が同一iterationに揃いやすいのに対し、V キャッシュではグループ要素が複数デコード iterationにまたがって生成される。そのため同じreal-time量子化回路を単純に流用すると、V グループが埋まるまで待つか高精度バッファを長く保持する必要がある。

## 手法
### 係数aで形を変えるMANT表現
4 bitの符号付き整数コード \(INT\) に対し、量子化gridを
\[
\mathrm{Value}_{grid}=\pm(a|INT|+2^{|INT|})
\]
と定義する。グループごとの定数 \(a\) を変えるだけでgridの点間隔を滑らかに変形できる。\(a=0\) ではPower-of-Two型になり、\(a=17\) 付近でfloat、\(a=25\) 付近でNormalFloatに近い分布を表現できる。論文では \(a>128\) で分布変化が小さくなることから範囲を128以内へ制限し、係数metadataを8 bitで表せるようにする。

この式の重要点は、任意codebookのlookupではなく「整数値に比例する項」と「2の冪項」の和なので、shift/add中心で復号と積和を融合できることにある。型の候補を増やすたびに別decoderを追加するのではなく、同じPEが \(a\) の違いを処理する。

### groupごとの型選択
各グループの値分布へ最も合う \(a\) を選択する。KVではcalibrationデータから分散と適切な \(a\) の対応を作り、ランタイムにはグループ 分散から係数を決める。評価時の代表設定ではグループ サイズ 64を使い、重み/KV用の候補 \(a\) を有限集合から選ぶ。活性値はINTを用いるため、すべてを同じ適応型 formatにするわけではない。

重みはofflineで量子化できるので、グループごとにscaleと \(a\) を決めて格納する。推論時は低bit コード、scale、\(a\) を読み、MANT PEが高精度テンソルへ全面展開せず計算へ取り込む。これによりグループ-level adaptivityのmetadataを小さく保ちながら、decoder オーバーヘッドを抑える。

### K/Vのreal-time量子化
K キャッシュではグループ要素が空間方向に同時生成されるため、十分なreal-time 量子化 unitを並べ、最大値・分散・scale/\(a\) をその場で決めて4 bit化する。

V キャッシュでは同じグループの64要素が時間方向の複数iterationにまたがる。MANTは生成直後の値を一旦INT8へ量子化しながらグループ統計を蓄積し、64番目が揃った時点で4-bit MANTへ再量子化する二段構成を使う。これによりグループ完成までFP16 Vを丸ごと保持する必要を避ける。量子化用のmax/分散計算はsystolic arrayの出力ストリームとパイプライン化し、主要GEMMと重ねる。

### MANT PEとsystolic array
MANT式は \(a\times INT\) と \(2^{|INT|}\) を含むため、PE内で係数項とshift項を積和へ融合する。重み/KVの復号、dequantization、GEMM、次のKV量子化をなるべくdataflow内で処理し、中間FP16展開と外部メモリ 通信量を減らす。real-time 量子化 unitもarray周辺へ統合し、重み linear層と注意機構の両方を低bit化する。

## 主要結果
品質面では、4-bit 重み/活性値条件でMANTが従来適応型形式より大幅に低いパープレキシティを示す。LLaMA-1-7BではFP16 5.68に対しMANT W4A4が6.09で、ANT W4A4 61.35、OliVe 32.15、Tender 23.85より大幅に近い。W4A8では5.79まで戻り、LLaMA familyでFP16からのPPL差を0.11以下に抑える。これは「型をグループごとに変える」ことが、単にscaleを細かくする以上に局所分布へ効くことを示す。

KVまで4 bit化したLLaMA-2-7Bでは、重み/活性値 W4A8を共通にしたTruthfulQAがFP16 KVで27.55、INT4 KVで25.48、MANT 4-bit KVで26.19、TriviaQAは86.38、85.13、86.86である。MANT KVはINT4より品質を回復し、論文はKV量子化によるlossを1.7%未満とまとめる。動的KVを低bit化しても、固定INT4よりグループ分布適応が有効という評価になっている。

linear層のみではMANTはTender、OliVe、ANT*、BitFusionに対して平均1.83×、1.96×、2.00×、4.93×高速で、energy reductionはそれぞれ1.39×、1.54×、1.57×、4.16×。量子化unitが完全に隠れない末尾部分のオーバーヘッドは代表GEMMで0.3%と報告される。

注意機構まで含む全層では、系列が長くなるほどKV/注意機構側の低bit化が効き、OliVe比で2.04〜4.54×の高速化倍率、1.76〜4.12×のenergy reductionを示す。SOTA比較としてTenderに対し、複数系列 lengthの平均2.99×（最大4.46×）高速化倍率、平均2.81×（最大4.10×）energy reductionを報告する。これは専用accelerator同士、同等area/PPL条件でのシミュレーション結果であり、CUDA GPU上のカーネル 高速化倍率ではない。

## 既存研究との差
ANTは複数の既成data typeから選ぶためdecoder候補が有限で、グループ-levelの多様性へ追随しようと型を増やすほどハードウェアが複雑になる。GOBO/Mokey系のclusteringは任意分布へ合わせやすいがcodebook lookupと高精度展開が必要になる。MANTは単一数式の係数 \(a\) を変えることで広い型familyを表し、同一PEで直接計算できる点が異なる。

また多くの重み-only/重み-活性値 acceleratorが注意機構 KVを高精度のまま残すのに対し、MANTはK/Vのランタイム生成方向まで考慮してreal-time量子化器を設計する。長文脈でKVが支配的になるとlinear層だけの最適化が飽和するため、この統合が2Kから128Kへ文脈を伸ばしたときの利得へつながる。

## 限界
主要な速度・energy値は28 nm相当の専用ASIC構成をcycle-level simulatorで比較したもので、実GPU/TPUの実時間値ではない。比較対象のTender/OliVe/ANTは注意機構を量子化しないため、長文脈ほど「MANTだけKVを低bit化する」という機能差が倍率へ強く反映される。用途に応じてこの差をアルゴリズム利得とハードウェア実装利得へ分けて読む必要がある。

グループごとにscaleと係数 \(a\) のmetadataを持ち、K/Vの分散計算と二段量子化回路も必要である。量子化unitのオーバーヘッドは代表条件で小さいが、極端に小さい行列や異なるdataflowで同じように隠せるとは限らない。また評価対象はLLaMA/OPT系と限られたgeneration タスクで、MoE、マルチモーダル、現行GPU native FP4との直接比較ではない。
