# AutoSelect：分散保存雑音による視覚トークン選択の学習と推論前置処理の短縮

## 概要

視覚言語モデル（Vision-Language Model, VLM）は画像符号器が出力する多数の視覚トークンを大規模言語モデル（LLM）へ渡す。高解像度画像や複数画像では、視覚トークンの長い前置列が注意演算と鍵・値キャッシュ（KV cache）の費用を増やす。重要度の低いトークンを削除する既存手法は、注意重み、類似度、固定削減比などの代理指標を使うことが多く、最終回答に必要な情報を最適に残せるとは限らない。

AutoSelectは、視覚トークンを単に捨てる問題を「K個のトークンに相当する情報容量をどの位置へ割り当てるか」という学習問題に再定式化する。凍結した視覚言語モデルへ重要度採点器（Scorer）と雑音除去器（Denoiser）を付け、学習時には全トークンを残したまま、重要度に応じて分散保存雑音を混ぜる。ソフト上位K選択（Soft Top-K）で勾配を維持し、回答の次トークン予測損失だけで採点器を訓練する。推論時は雑音除去器を除き、重要度上位K個の元の視覚トークンだけをLLMへ渡す。

LLaVA-1.5-7Bの576視覚トークンを64個へ削減した条件で、10ベンチマークの平均性能維持率96.5%を報告する。単一NVIDIA A6000、バッチ1、FP16の実測では、初回トークン時間が149.51msから72.73msへ短縮し、選択器の追加費用は0.69msである。LLMの前置処理は118.66msから41.61msへ約2.85倍高速化するが、画像符号化も含む初回トークン時間全体の高速化は約2.06倍であり、二つの倍率を混同してはならない。

## 問題設定と既存手法との差

従来の画像トークン削減は、注意重みの小さい位置を捨てる方式、互いに似た特徴を統合する方式、LLMの途中層で削減する方式などに分かれる。途中層削減は言語情報を使える一方、初期層では全視覚トークンを処理するため、計算節約が遅れる。画像符号器の直後に削減する方式は全LLM層の入力長を短縮できるが、言語モデルの内部でどの情報が必要になるかを事前に判断しにくい。

AutoSelectは、画像符号器とモダリティ射影器の間に選択器を置く。画像符号器と射影器とLLMの重みは固定し、追加の採点器・雑音除去器だけを学習する。学習時に硬い削除を直接行うと、選択されなかったトークンへ勾配が流れず、重要度採点を改善しにくい。そこで重要度の低いトークンへ雑音を注入し、情報を実質的に失わせつつ、計算グラフ上では全位置を残す。

この設計では学習中の全Nトークン処理が必要で、訓練自体を低費用にすることは主目的ではない。利得は学習後の推論で、採点器だけを通したあとK個へ減らすことにある。画像の特徴だけで採点するため、同じ画像について異なる質問を繰り返す場合には採点結果を再利用し得るが、質問依存で重要位置が変わる用途では不利になる可能性がある。

## 手法

### 1. 視覚符号器とLLMの間に置く二つのモジュール

入力画像Iを凍結した画像符号器Evへ渡し、N個・次元dvの視覚特徴Xvを得る。通常は射影器Pv→lでLLMの埋め込み次元へ変換してテキスト列と結合する。AutoSelectはこの間に採点器Sと雑音除去器Dを置く。Sは各視覚トークンの重要度s_iを算出し、Dは学習中に雑音を受けた特徴をLLMへ渡せる分布へ戻す。原著では画像符号器の費用が総推論費用の5%未満であるとし、画像符号器の前ではなく後で削減する。

SはL個のTransformer符号器ブロックと線形射影から構成され、N個の入力特徴からN個のスカラー得点を出力する。得点は画像特徴だけに依存し、言語の質問文は直接参照しない。出力の意味は単純な分類確率ではなく、固定された情報容量の中でどの位置を残すべきかという順位である。SのパラメータとDのパラメータを学習し、既存VLM全体の重みは凍結する。

### 2. ソフト上位K選択による固定予算配分

採点器の生得点sをz得点正規化し、温度τで割ってソフト上位K演算子ΦKへ入力する。出力α_iは0から1の連続値で、総和はおおむねKになる。通常のソフトマックスが総和1の確率分布を作るのに対し、ΦKはK個分の情報容量を割り当てる制約を持つ。Kは入力画像ごとに学習される数ではなく、あらかじめ決めた予算である。

温度は余弦スケジュールで高温から低温へ下げる。学習初期には多くのトークンに中間的なαを与え、後半にはαが0または1に近づく。こうして推論時の硬い上位K選択へ近づける。重要度を早期に二値化すると誤って落としたトークンが回復しにくいが、連続的な容量配分なら低得点の位置にも学習信号を残せる。

### 3. 分散保存雑音ゲートによる情報の抑制

各視覚トークンx_iには、次の分散保存雑音（Variance-Preserving noise）を加える。

`x_tilde_i = sqrt(alpha_i) * x_i + sqrt(1 - alpha_i) * epsilon_i`、ただし`epsilon_i ~ N(0,I)`。

α_iが1なら元特徴をそのまま通し、0なら独立なガウス雑音へ置き換える。中間値では信号と雑音を混合する。平方根の係数を使うため、入力が適切に正規化されている条件で出力の分散を概ね保てる。単純に特徴をα_i倍する方法では、低重要度の位置にも方向情報が残り、後段LLMの正規化層が再び情報を読み取る余地がある。雑音ゲートは特徴の意味内容そのものを破壊するため、採点器は回答に必要な位置へ高いαを割り当てるよう学ぶ。

重要なのは、学習中はトークン数をNから減らさない点である。情報を通しにくくすることと、計算量を実際に削減することは異なる。雑音ゲートは削除操作の微分可能な近似であり、実際の計算節約は推論時の硬い上位K選択で得る。

### 4. 対角注意の雑音除去器で情報漏出を防ぐ

雑音を混ぜた特徴は、凍結された射影器とLLMが期待する特徴分布からずれる。Dは1個のTransformer符号器ブロックを使い、特徴をLLMへ渡しやすい形へ変換する。ただし、普通の全域自己注意を使うと、低得点で雑音化されたトークンが高得点トークンを参照して元情報を補えるため、情報容量の制約が破れる。

そこでDの注意行列を対角に制限し、各トークンが自分自身にしか注意できないようにする。価値射影と前向きネットワークを通じた位置ごとの非線形変換は可能だが、他位置から情報を盗むことはできない。雑音で失われた情報を別トークンから復元できないので、採点器に本当に必要な位置を選ばせる圧力が保たれる。Dは学習時専用であり、推論時には除去される。

### 5. 次トークン予測損失と推論経路

学習では、Dが変換した視覚特徴とテキスト入力を凍結LLMへ渡し、正解回答の次トークン予測の負の対数尤度を最小化する。補助のトークン重要度ラベルや物体位置の注釈を要求しない。採点器と雑音除去器だけに勾配を流し、画像符号器・射影器・LLMは更新しない。原著はImageNet-1K由来のキャプションデータで約8400万個の追加学習パラメータを訓練したと記す。

推論時には雑音ゲートとDを外し、Sが計算した得点で上位K個の元の視覚トークンを抽出する。選ばれた位置の元の位置識別子を保持し、回転位置埋め込み（RoPE）が画像格子の位置関係を誤認しないようにする。これらを射影器とLLMへ渡すため、言語モデルの全層で視覚トークン数がKへ減る。採点器の計算費用は残るが、Dの計算費用は推論へ持ち込まれない。

### 高解像度・異種構造への適用：表2・3

LLaVA-NEXT-7Bでは視覚トークン2880個を320個へ削減した条件で、AutoSelectの平均維持率96.1%、HoloV 95.7%、DART 95.6%である。画像解像度が上がっても前置削減の性能が維持されることを示すが、比較は特定の画像集合・モデル・保持数に限定される。

Qwen2.5-VL-7Bでは、削減率66.7%でAutoSelect 98.3%、HoloV 94.3%、FastV 92.3%、77.8%で95.9%、90.8%、89.2%、88.9%で93.1%、87.0%、84.3%という平均維持率を報告する。固定格子やCLSトークンを前提としない採点器が、可変長の視覚入力にも適用できる点が特徴である。ただしQwenの平均は表3に掲載された5課題であり、LLaVAの10課題平均と直接比較してはいけない。

### 選択器単独の評価と構成要素除去：図3・表5

採点器の品質をLLMから切り離すため、CLIP ViT-L/14の24×24格子から選んだトークンを14×14格子へ対応させ、別のViT-B/16分類器へ入力する試験を行う。K=6、つまり約3%の保持では、AutoSelectのTop-1分類精度がHoloVより約10ポイント高いと報告する。これは学習した重要度が画像内の情報の多様性を拾うことを示唆するが、別の分類器での代理評価であり、LLM生成品質の直接測定ではない。

構成要素除去では、LLaVA-1.5-7Bの4課題平均維持率を使う。K=64で分散保存雑音＋対角注意の基本構成は95.5%、雑音除去器を全域注意へ変えると92.7%、雑音ゲートを単純な倍率ゲートへ変えると93.2%である。K=128では順に97.3%、95.0%、94.8%、K=192では98.3%、95.9%、96.5%となる。対角注意で他位置からの情報漏出を防ぐことと、雑音で情報内容そのものを抑えることの両方が、採点器の学習に寄与している。

この構成要素除去の基本構成K=64の95.5%は、10課題平均の96.5%とは異なる4課題集合の値である。母集団の違う平均値を一つの表へ混ぜて方式の改善量を算出してはならない。

## 限界・悪化条件

第一に、AutoSelectは視覚特徴だけから重要度を予測し、質問文を採点器へ入力しない。画像の細かな文字や局所的な物体を後から問う場合、質問にとって重要な位置が選択から漏れる可能性がある。平均性能維持率が高くても、個別質問での誤答増加を否定できない。Kを小さくするほどこの危険は増える。

第二に、学習ではN個の視覚トークンを全て処理し、約8400万の追加学習パラメータと雑音除去器を使う。推論時の雑音除去器費用はゼロでも、訓練費用がゼロという意味ではない。異なる基盤モデルへ移す場合には、同じ学習手順を適用できるとしても、採点器を学習し直す費用が発生する。

第三に、削減対象は画像符号器の出力であり、画像符号器自体の処理量は減らない。表4でも画像符号化は約30msのままである。画像符号器が支配的なモデルや非常に短い視覚列では、初回トークン時間全体の改善が小さくなる可能性がある。推論中の出力トークン生成（decode）速度も、表4の初回トークン時間とは区別する。

第四に、重要度の上位K選択は元の位置識別子を維持する必要がある。実装が選択後に位置を0から振り直すと、回転位置埋め込みの空間関係を変えてしまう。画像格子の位置符号化方式や視覚トークンの展開方法が異なる基盤では、位置保持の実装互換性を確認する必要がある。

第五に、論文の速度評価はA6000、FP16、バッチ1、単一画像を中心とする。量子化済みLLM、複数GPU、長い動画、CPUへのKVオフロード、同時要求の混雑、視覚入力のキャッシュ共有といった運用条件を包括的に評価したものではない。GPUメモリ容量の絶対節約量も、この評価だけでは一般化できない。

第六に、性能維持率は課題ごとの比率を平均するため、低い絶対得点を持つ課題や特定の難問の失敗が平均に埋もれる可能性がある。192保持条件ではPRUNESIDにわずかに及ばず、64保持でもGQAなどの絶対得点は下がる。速度と精度の交換条件は用途に合わせて設定する必要がある。

## 実装・関連研究との差

著者は公式コードを `https://github.com/MedHK23/AutoSelect` として示す。方式は画像符号器後の視覚特徴に軽量採点器を追加するため、LLM内部の各層へ削減器を挿入する方法より構成変更が少ない。一方、採点器の学習には元のVLMを凍結したまま回答の教師データと計算資源が必要である。学習済み選択器をそのまま別モデルへ無条件に流用できると解釈してはならない。

DARTやFastVはLLM内部の情報を使って削減するため、言語文脈を利用できるが、削減前の層の計算は残る。HoloVやPRUNESIDはLLM前に削減する点で比較しやすく、AutoSelectの差は採点の学習信号と選択器の低遅延性にある。特にPRUNESIDは高い平均維持率を得る条件がある一方、選択器の時間が大きい。論文の結論は「上位K削減そのもの」よりも、「削減に適した重要度を雑音ゲートで学び、推論時の判断を安くする」点にある。
