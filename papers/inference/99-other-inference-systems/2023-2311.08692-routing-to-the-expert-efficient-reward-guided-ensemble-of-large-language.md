# Routing to the Expert: Efficient Reward-guided Ensemble of Large Language Models

## 概要
複数の既製大規模言語モデル（LLM）は、同じ平均性能でも数学、コード、対話など得意領域が異なる。報酬モデル順位付け（Reward Model Ranking; RMR）はこの補完性を利用できるが、問い合わせごとに全候補LLMへ生成させ、その出力を報酬モデルで採点するため、候補数に比例して推論計算が増える。

ZOOTERは「生成してから選ぶ」のではなく「問い合わせを見てから生成前に1モデルを選ぶ」。学習時だけ全候補LLMの出力と報酬モデルを使い、その相対報酬分布を小型ルータへ知識蒸留する。実運用時は86Mパラメータのルータと選択された13Bモデル1つだけを推論する。6候補、26評価subsetでは44%のタスクで首位となり、最良単一モデルの31%を上回る。

## 問題設定
RMRは候補LLMが6個なら6個すべてを推論してから選ぶ。Oracleに近いreward rankerなら品質は上がるが、13B×6の生成コストとrankerのコストを毎問い合わせ支払うため、低資源環境では単一モデルより不利になり得る。一方、単純な問い合わせ ルータを教師付き学習するには「どの問い合わせでどのモデルが最良か」というラベルが必要で、各モデルの事前学習・alignment dataが非公開なためexpertiseを直接記述できない。

ZOOTERは、既存reward モデルが各候補出力へ付けるスコアを「潜在expertiseの銀教師」とみなす。高品質な人手回答ラベルを要求せず、問い合わせ集合だけを用意してofflineで候補を評価し、その結果をルータへ移す。

## 手法

### 報酬蒸留
学習問い合わせ `q` について各候補モデル `m_i` が応答を生成し、既製reward モデルが `r_i` を付ける。これをsoftmaxして「この問い合わせが各モデルのexpertiseへ属する確率」に変換する。ルータ `Z(q)` はこの分布へKullback–Leibler divergenceで合わせる。

入力は応答ではなく問い合わせだけなので、online時には候補モデルを先に実行する必要がない。学習時の高コストRMRを一度だけ行い、onlineでは小型分類器の順伝播へ置き換えるのが計算削減の核心である。

### タグ基準ラベル強化
reward モデルの標本単位スコアには不確実性があり、スコア entropyが高い問い合わせではMT-Bench性能が低い傾向を論文は観測する。そこで局所 taggerで問い合わせへタグを付け、同一タグ群の平均reward `r_t` を計算する。最終教師は標本 reward `r_i` とtag平均 `r_t` を係数βで線形結合する。

これは単純な離散 ラベル化ではなく、細粒度問い合わせ情報と粗粒度domain priorを混ぜる。β=1なら標本のみ、β=0ならtagのみであり、評価ではβ=0.3が全ベンチマーク平均のmean タスク ランク（MTR）1.97で最良だった。標本のみβ=1の2.34より良く、reward noiseをtag priorが実際に緩和している。

### オンラインルーティング
学習済みルータは問い合わせを入力し、候補6モデルの確率を出す。最大確率のモデルだけを呼び出すため、RMRの「6×13B生成＋ranker」に対し「86M ルータ＋1×13B生成」となる。ルータが誤ると後から別モデルへ救済する仕組みは基本設計に含まれず、効率は事前選択の正確さと直接交換条件になる。

| 項目 | 条件 |
|---|---|
| 候補LLM | WizardLM、WizardCoder、WizardMath、Vicuna、OpenChat、Llama-2-Chat |
| 候補規模 | 各13B |
| ルータ | mDeBERTa-v3-base、86M |
| 銀教師 | QwenRMを中心に比較 |
| 学習問い合わせ | DIVINSTRUCT 47,986件、6,270タグ、13 source dataset |
| 評価 | AlpacaEval 5 subset、FLASK 10、MT-Bench 8、MMLU/GSM8K/HumanEval 3、計26 |

| 比較 | best-モデル-average、複数RMR、Oracle、GPT-3.5/GPT-4参考値 |

## 主要結果

| 方法 | online推論量 | 全26 subset MTR | 首位率 | 解釈 |
|---|---|---:|---:|---|
| best-モデル-average | 1×13B | 2.23 | 31%相当 | 単一モデル基準 |
| ZOOTER | 86M + 1×13B | 1.94 | 44% | 小さい追加計算で平均順位を改善 |
| RMR + QwenRM | 6×13B + 7B ranker | 1.58 | 67% | 品質は高いがonline計算が大きい |
| Oracle | 6×13B | 1.00 | 100% | 補完性の上限 |

ZOOTERはAlpacaEval、MT-Bench、MMLU/GSM8K/HumanEval群で単一モデル基準を上回り、MT-Benchでは平均スコアを0.39改善する。OAssistRM、LLM-Blender、Auto-Jを用いたRMRより少ない計算で高い総合順位を得る一方、QwenRM/UltraRMを使う強いRMRには届かない。

## 既存研究との差
LLM-Blender等のgenerate-then-ランク/fuse方式は候補出力をonlineで必要とする。ZOOTERはreward モデルをonline selectorとして使うのではなく、offlineで生成したreward分布を問い合わせ-only ルータへ蒸留する。さらにgold response不要の問い合わせ集合を使い、タグpriorでreward uncertaintyを補正する点が、単純なベンチマーク-ラベル ルータとの差である。

## 限界
品質上限はルータと教師reward モデルに依存する。論文自身もMMLU、GSM8K、HumanEvalではreward モデルが知識・数学・コードを正確に判定しにくいと報告する。また候補は6つの13B Llama系中心で、サイズ・料金・遅延が大きく異なる異種APIモデルをコスト-awareに選ぶ評価ではない。オンライン計算は大幅に減るが、offlineでは全候補生成とreward付与が必要であり、候補モデルを頻繁に入れ替える場合は再蒸留費用が生じる。
