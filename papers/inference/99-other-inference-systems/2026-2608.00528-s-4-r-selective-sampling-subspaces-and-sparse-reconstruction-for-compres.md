# S4R：選択標本SVDと疎な再構成による長文脈KVキャッシュ圧縮

## 概要

S4R（Selective Sampling, Subspaces, and Sparse Reconstruction）は、長文脈言語モデルのキー・値（KV）キャッシュを低ランク係数として保持し、復号時には注意計算に重要な位置だけを元の次元へ戻す方式である。長い入力全体から特異値分解（SVD）を実行するオンライン圧縮はプロンプトへの適応性がある一方、プリフィルが高価になる。外部校正データから固定基底を得る方式は処理費を抑えられるが、入力分布が変わると品質が落ちる。S4Rは「基底を作るためのトークン標本」と「復号時に再構成するトークン集合」を別々に絞り、この二律背反を緩和する。

実験では、Llama-3.2-1B、Llama-3.1-8B、Qwen3-4B、Qwen2.5-14BのLongBench、Qwen2.5-7B-Instruct-1Mの128K RULERを評価した。RULERで2.5倍圧縮時の平均は93.61、非圧縮93.97、xKV 93.47である。ただしFWEは非圧縮83.33に対して76.67へ低下する。120Kトークン入力から512トークンを生成するQwen3-4Bの未最適化実装では、S4Rの出力速度8.32 token/sは非圧縮の9.33 token/sを下回る。したがって本論文の「最大5倍」は主にKVの保存容量削減であり、生成処理5倍高速化ではない。

## 問題設定

通常のKVキャッシュは、各層の全過去トークンのキーと値を元のヘッド次元で保存する。系列長に比例して常駐メモリが増え、長文脈の同時要求数を制限する。低ランク表現を使えば、各トークンを短い係数ベクトルで保持できるが、どの部分空間を選ぶかが精度を決める。固定の基底は校正コーパスに偏りやすく、プロンプト全体から都度分解する基底は長いプリフィルにSVD費用を加える。

さらに、圧縮係数だけを永続保存しても、毎復号ステップで全トークンのKVを元の次元へ復元すると、展開計算と一時バッファが必要になる。圧縮による常駐メモリ削減と復号スループットは同じ指標ではない。S4Rは基底構築を代表標本に限定し、復号時には係数空間の代理注意から重要位置を選択して復元する。注意シンクと直近の位置は別扱いとし、近似に弱い情報の欠落を抑える。

## 手法

### 1. プリフィル：注意シンク保護と代表トークンの標本抽出

先頭の`s`個の注意シンクは、後続クエリから繰り返し参照されるため元の精度で保存する。既定値は`s=4`。残る非シンク部分について、全体を均一に抽出する位置と、プロンプト末尾から連続抽出する位置を組み合わせ、代表集合`T'`を作る。論文の既定は直近対均一を7:3とし、標本数は入力長と目標保持比率から決める。これにより遠方の多様な文脈と最近の話題の両方を基底推定へ入れる。

標本のキーと値はRoPE適用前の表現を用いる。各トークンのベクトルを正規化したうえで切断SVDを実施し、キー基底`B^K`と値基底`B^V`を得る。全系列をSVDするのではなく標本を使うため、分解費用を下げつつ、現在のプロンプトに応じた部分空間を作れる。正規化は大きなノルムを持つ一部トークンが基底を支配するのを抑える。ただしアブレーションではモデルによって正規化を外した方がわずかに高精度となる場合があり、無条件の改善ではない。

### 2. 係数キャッシュ：全非シンクKVの射影と更新

基底ができたら、標本に選ばれなかったものも含む非シンク全トークンのKVを、それぞれランク`r`の係数へ射影する。元の次元を`D'`とすると、キー係数は概念的に`C^K=S^K B^K`、値係数は`C^V=S^V B^V`となる。永続保持するのは係数列、基底行列、フル精度のシンクKV、および短いクエリ係数窓である。新しいトークンが生成されると、そのK/Vを同じ基底へ射影して係数列末尾へ追加する。毎ステップ全プロンプトのSVDをやり直さない点が重要である。

直近クエリもキー基底へ射影し、固定長`W`の先入れ先出し窓`C^Q`を維持する。既定の品質評価では`W=32`であり、速度測定では`W=4`へ縮めた別条件を使う。クエリ窓は重要位置を推定するための観測履歴であり、過去の全クエリを保持するわけではない。圧縮ランクを下げるほどメモリは節約できるが、重要な特徴方向が消えるため品質の損失が増え得る。

### 3. 潜在空間の注意スコアで復元対象を選ぶ

復号ステップでは、短いクエリ係数窓と蓄積キー係数の積から`Z=C^Q(C^K)^T/√r`を計算し、因果マスクとsoftmaxを適用する。クエリ窓方向の平均からトークンごとの重要度を作り、隣接位置のプーリングとヘッド群の集約でスコアを安定化する。既定では系列方向にカーネル7の最大プーリング、群方向に平均を使う。このスコアは元次元で計算した正確な注意ではなく、どの過去位置を復元するか決める代理指標である。

復元対象は必ず残す直近`W`個の位置と、それ以外の重要度上位`k=max(⌊ρL_t⌋−W,0)`位置の和集合とする。`ρ`は再構成比率、`L_t`は非シンクキャッシュ長である。選ばれたキー・値係数だけを基底で元の次元へ復元し、フル精度シンクKVと合わせて実際の注意計算に供給する。元の位置情報を維持してRoPEを扱うため、選択後に詰めた配列順を元のトークン位置と混同してはいけない。代理スコアが重要位置を見落とす場合には、復元されない情報を注意が利用できず品質が下がる。

### 4. 容量と実行時費用の分離

論文の式(20)では、各層の永続メモリ要素数を概ね`2sD' + 2L_t r + GW r + 2D'r`と表す。項は順にシンクKV、非シンクK/V係数、クエリ係数窓、キー/値基底である。長文脈で`s`と`r`が小さい場合、非圧縮比はおおむね`r/D'`に近づく。ただしこれはシンク・基底・クエリ窓の固定費用を無視できる場合の漸近的な比率であり、全モデルの実測ピークVRAM比率をそのまま意味しない。

一方、復号時には選択位置数`m_t=max(W,⌊ρL_t⌋)`に対して元次元へ復元したK/Vの一時バッファ`2m_tD'`が必要になる。常駐係数キャッシュと一時再構成バッファは別に勘定すべきである。スコア計算、位置選択、基底との行列積、疎な注意演算が加わるため、常駐容量の削減が生成速度の改善を必ず伴うわけではない。

## 評価

### 1. LongBench：モデルごとの品質差

LongBenchは長文書質問応答、少数例、複数文書、コード補完、検索などを含む。Table 1では、Qwen3-4Bの非圧縮平均49.62に対しS4Rは47.79、ShadowKV 47.38、xKV-2 44.00、xKV-4 45.22、Palu 3.35であった。Llama-3.2-1Bでは非圧縮31.58に対してS4R 28.09で、ShadowKV 25.72、xKV-4 26.01を上回った。ここでの保持比率`η`はQwen3-4BやLlama-3.2-1Bで0.2、Qwen2.5-14Bでは0.3であり、同一の圧縮率を全行へ適用した表ではない。

一方、Llama-3.1-8BではS4R 53.03、xKV-4 54.19、非圧縮55.18であり、Qwen2.5-14BでもS4R 53.19、xKV-2 54.80、非圧縮55.37である。S4Rが全モデル・全設定で最良ではない。固定基底のPaluは強い圧縮で大きく品質を落とし、S4Rのプロンプト適応の利点が見えるが、モデル規模やタスクにより他の適応方式が優位となる。

### 2. RULER：平均と特定課題の乖離

Table 2はQwen2.5-7B-Instruct-1Mの128K文脈、KV圧縮2.5倍での結果である。非圧縮平均93.97、S4R 93.61、xKV 93.47、ShadowKV 89.61、SnapKV 88.81、Palu 82.22、StreamingLLM 48.39となった。S4Rは複数キー検索・複数クエリ検索などで100点を維持する一方、FWEでは非圧縮83.33、xKV 83.33に対して76.67へ低下する。平均値だけで「完全に品質を維持」と言うのは不適切である。

### 3. 120K文脈のモデルレベル速度と測定条件

Table 3はQwen3-4B、GovReport由来の120K入力、512出力トークン、システム・カーネル・演算子レベルの最適化なしという条件である。速度測定のS4Rはクエリ窓`W=4`を使用し、品質表の既定`W=32`と異なる。Table 7によればこの変更後のQwen3-4B LongBench平均は47.73で、既定47.79と近いが、全モデルで同様とは限らない。

| 方式 | TTFT | 512トークン生成遅延 | 出力速度 |
|---|---:|---:|---:|
| 非圧縮KV | 24.74秒 | 54.89秒 | 9.33 token/s |
| Palu | 24.58秒 | 57.06秒 | 8.97 token/s |
| ShadowKV（値をGPUに保持） | 36.14秒 | 56.92秒 | 8.99 token/s |
| xKV | 79.90秒 | 260.76秒 | 1.96 token/s |
| S4R（`W=4`） | 27.65秒 | 61.54秒 | 8.32 token/s |

S4RはxKVに比べてTTFTと生成時間を大幅に減らすが、非圧縮より遅い。ShadowKVの値をCPUへ退避する標準構成ではなく、GPUに置いた有利な比較条件であることも原著脚注に明記される。速度比較の差をアルゴリズム単体の効果と実運用サーバーの改善へ直結させない。

### 4. 構成要素除去実験

Table 4で先頭4シンクの保護を外すと、Llama-3.2-1BのLongBench平均は28.09から24.60、Qwen3-4Bでは47.79から45.58へ下がる。Qwen3-4Bのpassage retrievalは96.17から82.00へ低下する。これはシンクの精度を保持する設計の重要性を示すが、他の全トークンを正確に復元する保証にはならない。

Table 5でSVD前のトークン正規化を外すと、Llama-3.1-8Bでは平均53.03から53.32へわずかに上がる一方、Qwen2.5-14Bでは53.19から46.27へ下がる。したがって正規化は頑健性のための既定選択であり、普遍的に優越する処理ではない。Table 6のプーリング・群集約の4方式では、平均差はモデルにより0.18〜0.67点程度であり、主要な精度差は基底品質やシンク保持に比べて小さい。

## 限界

論文自身が述べるように、実装にはシステム・GPUカーネル・演算子レベルの最適化がない。報告された速度は手法のアルゴリズム費用を比較するもので、多数の同時リクエストを捌く実サービスのP95/P99遅延、GPU占有率、メモリ断片化、CPUオフロードとの複合運用などを検証していない。LongBenchとRULERは長い入力に対して出力が比較的短い課題が中心で、非常に長い生成、他のモデル系列、長時間の対話で基底が古くなる影響は不明である。

固定基底はプロンプトに適応するものの、生成中の新しいトークンでSVDを繰り返し更新する設計ではない。話題や情報分布が急変すると基底が十分な特徴方向を含まない可能性がある。潜在注意の代理スコアが正確な注意と異なるため、重要位置を取り逃がすリスクも残る。FWEの負の結果はその実際の品質差の一例である。公式コードの公開URLは原著から確認できず、再現性・他のGPUへの移植性・専用カーネルを実装した場合の性能は未検証である。

## 既存研究との差

PaluやEigen Attentionのような固定・校正済み低ランク基底は前処理後の費用が軽いが、入力分布への適応に限界がある。xKVはプロンプトに応じてクロスレイヤーの基底を作るが、長いプロンプトで分解・再構成の費用が大きい。ShadowKVはプロンプト依存のキー低ランク化と値の退避を組み合わせる。S4Rはキーと値の双方についてプロンプト内の代表標本から基底を作り、潜在空間で位置を選んでから疎に復元する点が異なる。Lokiは主として疎注意のための低ランクキー検索を行い、永続KVキャッシュそのものの削減を主目的としない。

評価の主張は、強い圧縮で固定基底方式より品質を保ち、全プロンプトSVDを行う方式より費用を抑えられるという条件付きの交換関係である。5倍の容量圧縮、非圧縮に近い平均正答率、非圧縮より遅い絶対速度という三点を同時に保持して理解するのが妥当である。
