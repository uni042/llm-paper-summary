# MoHD — 隠れ次元の共有・専門サブ次元混合による条件付き活性化

## 概要

Mixture of Hidden-Dimensions（MoHD）は、TransformerのFFN中間次元ではなく、**トークン表現そのもののhidden dimension**を疎に活性化するモデルアーキテクチャである。隠れ次元を複数のsub-dimensionに分割し、全トークンで利用する共有部分と、入力トークンに応じてrouterが選択する専門部分を組み合わせる。AttentionのQ/K/V/O投影とFFNのup/gate/down投影を同じ隠れ次元の選択に合わせて部分実行し、総パラメータ数を増やしても1トークン当たりに活性化するパラメータ数を抑える。

この研究の焦点は、既存モデルのKVキャッシュ圧縮や推論後処理ではない。LLaMA2型モデルをMoHD構造で**新規に学習**し、同じ活性化パラメータ数に対する表現容量とタスク性能を高めることにある。LLaMA2型355Mの10指標平均は全活性42.7、MoHDの50%活性42.3、75%活性43.2だった。1.13B型では全活性44.2に対し50%活性45.9、75%活性46.0を報告する。ただし、推論実行時の絶対レイテンシやGPUメモリ削減をこの平均得点から推定してはいけない。

## 問題設定と実測された疎性

Transformerの隠れ次元`d`を一様に拡張すると、Attention投影とFFN投影の行列サイズが増え、学習・推論の演算量とメモリ費用が増加する。一方、著者がLLaMA2-7Bの隠れ状態を調べると、全次元が均等に利用されているわけではない。16層のAttention入力では、上位1,000/4,096次元が活性化量の71.96%を占める。論文の別集計では上位50%の次元が総活性化量の92.54%を担う。

さらに高活性の位置には、複数トークンで持続する次元とトークン固有の次元がある。Figure 5では、5トークン間で約400次元が共通して強く活性化し、各トークン固有の高活性次元が約200個あると観察する。これは全次元を同じ条件で実行するより、共通部分を保持しつつ専門部分を選択する方が計算資源を有効利用できる可能性を示す。ただし活性化量が小さい次元を消しても必ず品質が維持されることを直接証明するわけではない。情報の流れを保つ補助機構が必要になる。

AttentionとFFNでは活性化の分布も異なる。Figure 4は、AttentionのQ/K/V投影や出力投影を通る間に活性化量が大きく変化する一方、FFN側は比較的安定していることを示す。残差接続とLayerNormが各ブロックの活性化規模を補正するため、両モジュールで同一の選択routerを使うと必要な特徴を保持しにくい。この観察を根拠にMoHDはAttentionとFFNで別々のrouterを設ける。

## 手法

### hidden dimensionの分割とtoken-wise router

隠れ状態`x ∈ R^d`に対し、元の重み行列を隠れ次元方向へ複数のsub-dimensionに分割する。例えば`W_up`や`W_gate`では、選択された隠れ次元に対応する行を計算し、`W_down`では対応する列を使う。Attention側も`W_Q, W_K, W_V`の入力側と`W_O`の出力側を対応する部分に分割する。選択された部分行列だけで計算することが、通常のMoEがFFN中間次元やexpert全体を切り替える方式との違いである。

routerは入力トークンの隠れ状態と各sub-dimensionの学習可能な中心ベクトル`φ_i^l`の親和度を計算し、Softmax得点の上位`K`部分を選ぶ。選ばれなかった部分はゲート重み0となる。AttentionとFFNにはそれぞれ`Gate_attn`、`Gate_ffn`があり、同じトークンでもモジュールごとに異なる隠れ次元の部分集合を選択できる。選択した部分の出力を連結・加重して元の隠れ次元へ戻すため、残差経路や後続ブロックとのインターフェースを維持できる。

このルーティングはトークンごとに動的であり、どのsub-dimensionが活性化するかは入力によって変わる。モデル全体で固定の次元を削除する通常の枝刈りと違い、総パラメータを残しながら1トークンで参照する部分を変える。総パラメータ数と活性化パラメータ数を分離することが、MoHDの拡張・圧縮の両設定に共通する基本構造である。

### 共有部分と専門部分の混合活性化

単純なtop-K専門部分だけでは、複数トークンで常に必要な共有特徴が毎回の選択競争に巻き込まれ、情報が不安定になる。MoHDは一部のsub-dimensionを共有部分として常時活性化し、残りをrouterが選ぶ専門部分とする。共有部分は共通特徴の安定的な通路を確保し、専門部分はトークン固有の意味差を表現する。Figure 5の共通約400次元と固有約200次元という観察に対応する設計である。

Table 3の主要設定ではAttentionとFFNのrouterはいずれもtop-K=4を使用し、共有sub-dimension数は3。50%圧縮では総sub-dimension数8、75%圧縮では12、拡張2倍/3倍/4倍では8/12/16とする。これらは論文の実験設定であって、全モデル・全トークンで最適と証明された一般則ではない。共有部分を取り去ると検証perplexityが10.25から11.08へ悪化するため、共有経路は単なる飾りではない。

### Sub-Dimension ScalingとGroup Fusion

隠れ次元を疎にすると、選択後の出力振幅が小さくなり、次のブロックへ渡る情報が弱まる。著者は活性化の規模を補正するSub-Dimension Scalingを導入し、選択部分の情報を元の表現空間で適切な大きさへ戻す。さらにGroup Fusion Layerで選択部分の出力をグループ単位で混合し、次元削減による情報欠落を補う。これらはrouterの選択そのものではなく、**選択後のactivation flowを保つ**機構である。

Table 4では、基準MoHD×2-710Mの検証perplexityが10.25なのに対し、Scalingを除去すると11.41へ+1.16悪化、Group Fusionを除去すると10.47へ+0.22悪化した。特にScalingの寄与が大きい。疎性だけを利用して同じ計算量へ落とすと性能が失われやすく、情報流の補正が実際の品質維持に重要である。

### 負荷分散と学習目的

top-K routerは、一部のsub-dimensionだけを選ぶように学習が偏る可能性がある。そこでSub-Dimension Load Balance Lossを追加し、router得点と選択頻度を組み合わせて割当てを均す。学習目的は言語モデルのcross-entropyとこの負荷分散損失の和である。Table 4では負荷分散を除去するとperplexityが10.25から10.41へ+0.16悪化する。

この損失はexpertの過集中を避けるMoEの考え方に近いが、対象はexpertネットワークではなくhidden sub-dimensionである。共有部分の常時活性化と負荷分散損失を併用することで、共通特徴の経路を残しつつ、専門部分の選択が少数の次元へ崩壊しないようにする。AttentionとFFNを別routerにした理由も、各モジュールの活性化の時間的・層的変化が異なるという原著の観察に基づく。

## 評価条件

| 項目 | 一次論文の設定 |
|---|---|
| アーキテクチャ | LLaMA2型Transformer、MoHD版をスクラッチから事前学習 |
| 基準規模 | 355M、495M、1.13B総パラメータ |
| 基準の活性化パラメータ | 289M、396M、約1B（埋め込み層を除く） |
| 圧縮設定 | hidden dimension活性化50%、75% |
| 拡張設定 | 総パラメータ2倍、3倍、4倍。活性化パラメータ数を基準と同程度に固定 |
| 学習データ | RedPajama（CommonCrawl、C4、GitHub、Wikipedia、Books、arXiv、StackExchangeなど） |
| 評価 | SciQ、PIQA、Winogrande、ARC-E/C、HellaSwag、LogiQA、BoolQ、LAMBADA、MMLUの10指標平均、検証perplexity |
| Router | Attention/FFN別、top-K=4、共有部分3、総sub-dimension 8/12/16など |
| 主な比較 | 同規模のLLaMA2型密モデル、圧縮MoHD、拡張MoHD、各構成要素除去 |

評価の「活性化パラメータ数」は1トークンで実行される部分を指し、モデルが保持する総重み数とは異なる。2倍拡張MoHDが289Mの活性化パラメータで動いても、総重みは約710Mになる。したがって計算量とストレージ・VRAM常駐量を同じものとして扱ってはいけない。

## 主要結果

### 圧縮・拡張の得点と活性化パラメータ数

| 条件 | 活性化パラメータ | 10指標平均 | 比較対象 |
|---|---:|---:|---|
| LLaMA2型355M | 289M | 42.7 | 基準 |
| MoHD 50%・355M | 145M | 42.3 | 基準より−0.4ポイント |
| MoHD 75%・355M | 217M | 43.2 | 基準より+0.5ポイント |
| MoHD×2・総710M | 289M | 44.9 | 同じ活性化289Mの基準より+2.2ポイント |
| MoHD×3・総1.06B | 289M | 44.5 | 同じ活性化289Mの基準より+1.8ポイント |
| LLaMA2型495M | 396M | 43.8 | 基準 |
| MoHD 50%・495M | 198M | 44.1 | 基準より+0.3ポイント |
| MoHD×3・総1.48B | 396M | 46.0 | 同じ活性化396Mの基準より+2.2ポイント |
| LLaMA2型1.13B | 約1B | 44.2 | 基準 |
| MoHD 50%・1.13B | 503M | 45.9 | 基準より+1.7ポイント |
| MoHD 75%・1.13B | 755M | 46.0 | 基準より+1.8ポイント |
| MoHD×3・総3.41B | 約1B | 47.9 | 同じ活性化約1Bの基準より+3.7ポイント |

原著Table 2の平均得点。差は**百分率ではなく表の平均得点のポイント差**である。355Mの50%活性は活性化パラメータを約半分にしても平均得点が42.7から42.3へ小幅に落ちる。一方1.13Bの50%活性は44.2から45.9へ改善した。圧縮で常に性能が上がるわけでも、モデル規模を増やせば同じ傾向が保証されるわけでもない。

2倍・3倍拡張は、総重み数を増やす代わりに1トークンで実行する部分を制限して得点を上げる。355M基準の活性化289Mに対し、総710MのMoHD×2は44.9と基準42.7を上回る。ただし総重みが約2倍なので、VRAMへ全重みを保持する運用ではメモリ費用が増える。推論の実時間が活性化パラメータ数に完全比例するとは限らず、routerや部分行列アクセスのオーバーヘッドも生じる。

### アブレーション：どの機構が効いているか

| MoHD×2-710Mの構成 | 検証perplexity | 基準との差（悪化） |
|---|---:|---:|
| 完全構成 | 10.25 | — |
| 共有・専門混合活性化なし | 11.08 | +0.83 |
| 負荷分散損失なし | 10.41 | +0.16 |
| Group Fusionなし | 10.47 | +0.22 |
| Sub-Dimension Scalingなし | 11.41 | +1.16 |
| 密なLLaMA2型355M | 11.61 | +1.36 |

Table 4より。混合活性化とScalingの寄与が大きく、疎にしただけの方式と異なる理由が見える。負荷分散損失の効果は比較的小さいが、routerの集中を防ぐ役割を持つ。各除去は単独の比較であり、寄与の数値を足し合わせて完全構成の効果とみなすことはできない。

### AttentionとFFNの非対称性

Table 5はLLaMA2型355Mを用い、AttentionとFFNの活性化割合を別々に変更した結果を示す。両方100%のMoHDでは活性化289M、perplexity11.43。FFNだけ50%へ落とすと活性化195Mで11.31へ改善したが、Attentionだけ50%へ落とすと239Mで12.25へ悪化した。Attentionを25%へ落としてFFNを100%に保つと213Mで14.31まで悪化する。

この非対称性は、Attentionの隠れ次元を無差別に減らすことが特に危険であることを示す。Attentionの出力が層によって変動しやすいという著者の観察とも整合する。実運用で活性化率を調整するなら、AttentionとFFNを同率にするより、性能に敏感なAttentionへ多くの容量を割り当てる設計を検討すべきである。ただしTable 5の結果は355Mでの学習実験であり、7B級で同じ閾値が最適とは限らない。

## 既存研究との差

従来のMoEは主にFFNの中間次元を持つexpert群から一部を選び、モデル容量を増やしつつ1トークンの計算量を抑える。MoHDはさらに細かいhidden dimensionの行・列に注目し、AttentionとFFNの双方でトークン別に部分活性化する。MoEの「expert単位の疎化」に対して「隠れ次元部分集合の疎化」を提案した点が特徴である。

静的枝刈りとも異なり、入力トークンに応じて専門sub-dimensionの選択が変わるため、総パラメータを残したまま条件付きに利用できる。共有部分は複数トークンで必要な表現を維持し、専門部分は個別トークンの情報を表す。ScalingとGroup Fusionは、疎化に伴う活性化量低下を補正する機構としてアブレーションで裏付けられている。

## 限界・実装上の注意

第一に、既存チェックポイントの後処理としてMoHDを適用した評価ではない。主実験は355M、495M、1.13BのLLaMA2型モデルをスクラッチから学習している。既存の7B/30B級モデルを再学習なしでMoHDへ変換し、同じ性能を維持できるという根拠はない。

第二に、総重み数と活性化重み数が異なる。例えば総3.41BのMoHD×3は約1Bの活性化で平均47.9を達成するが、総重みは3.41B必要になる。GPUメモリが限られる場合、活性化計算量だけでなく全重みの格納、転送、部分行列のアクセス局所性が制約となる。本文の平均得点からトークン毎秒や実測VRAMを推定しない。

第三に、部分行列の選択にはrouter計算とインデックス操作が必要である。小さいバッチでは不規則アクセスの費用が相対的に増える可能性がある。論文は学習後のperplexityとタスク得点を主な根拠とするため、推論サーバーでの実際のprefill/decode時間、カーネル効率、複数同時リクエストでのスループットは別途評価が必要である。

第四に、圧縮の負の結果が存在する。355Mの50%活性は平均得点が42.7から42.3へ下がり、Attentionの活性化を25%にするとperplexityが11.43から14.31へ悪化した。共有部分やScalingを外した場合も明確な品質低下がある。疎性の観測だけを根拠に、任意の隠れ次元を半分にすれば同じ品質が得られるとは言えない。

最後に、論文の「3.7%高い性能」などの総括値は、特定規模・設定における平均得点の比較に由来する。実験表の平均得点差と相対改善率を混同しない。モデル規模やタスク構成が異なれば改善幅は変わる。公式コードURLは今回の原著確認範囲で特定できず、公開実装の有無を断定しない。
