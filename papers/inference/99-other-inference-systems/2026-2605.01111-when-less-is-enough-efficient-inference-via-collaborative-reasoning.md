# When Less is Enough: Efficient Inference via Collaborative Reasoning

## 概要

複雑な数学や科学の問題を解く推論モデルは、最終回答に到達する前に長い思考の連鎖を生成する。大きなモデルに問題の理解、推論、回答の書式整形まですべて担当させると、能力を要しない部分にも高価な生成計算を使う。単に思考列を途中で切ると必要な論理が失われる可能性があり、短い思考列を一律に要求するだけでは正解率を維持できない。

DUET（Dual-model Efficient Two-stage inference）は、高性能なモデルが「小モデルに渡すのに十分な推論信号」を生成し、軽量モデルが入力とその信号から最終回答を作る方式である。推論信号を短くすることと、小モデルが正解できることを共同で学習する。大モデルが小モデルの正解率をどれだけ上げたかという限界効用報酬と、生成トークン数の予算を満たすよう調整する長さ罰則を組み合わせる。

原著はQwen3-4Bの思考モードとQwen3-0.6Bを用い、MATH500、AMC23、AIME2024、AIME2025、GPQA-Diamondで評価する。AMC23では大モデルの出力6948トークンが1800になり、正解率は0.90から0.88へ変わる。GPQA-Diamondでは6928から2402トークンとなるが、正解率は0.53から0.48へ低下する。したがって「正解率を完全に維持して全条件で60%削減」とは読めない。実際の指標は主に高性能モデルが生成したトークン数であり、GPU上の壁時計時間を直接測った速度倍率とは異なる。

## 問題設定と先行方式

通常の単一モデル推論では、同じ大モデルが推論の難しい部分と単純な回答生成の両方を担当する。長い思考列は正答に役立つ一方、計算資源と応答遅延を増やす。モデルを単に小さくする蒸留では、大モデルの能力を完全に再現できない場合がある。思考列を固定長で打ち切る方式では、どのトークンが重要かを見ずに削除するため、長い論理の途中で結論に必要な情報が失われる。

投機的復号（speculative decoding）は小モデルが次トークン候補を生成し、大モデルが候補を検証する。DUETはこれと逆に、大モデルが先に短い推論信号を作り、小モデルが最終回答を作る。大モデルが最終回答の各トークンを検証する仕組みではないため、出力分布を厳密に保つ損失なし復号方式と同一視してはならない。また、質問ごとに小モデルか大モデルの一方へ振り分けるルーティング方式とも異なり、一つの質問で両モデルが順番に働く。

問題は、どこまで推論信号を短くしても小モデルが正しく答えられるかである。高性能モデルが単に「正解」だけを伝えることを許すか、証拠を十分に含む信号を求めるかは、課題の報酬設計と訓練の制約に依存する。著者は、最終回答の報酬と推論信号長の制約を共同で扱い、必要な情報を残しつつ冗長な出力を減らす学習問題として定式化する。

## 手法

### 1. 二モデルの入力と出力

入力を`x`、大モデルを`M_θ`、小モデルを`m_φ`とする。第一段階で`z ~ M_θ(.|x)`として推論信号を生成する。第二段階では元の質問`x`と推論信号`z`を小モデルへ渡し、`y ~ m_φ(.|x,z)`で最終回答を作る。大モデルは最終回答までの長い文章を書く必要がなく、小モデルは難しい推論のすべてをゼロから行う必要がない。この役割分担が生成トークン数の節約を狙う中心である。

推論信号はテキストトークン列であり、隠れ状態を直接共有する特殊なモデル接続を前提としない。大モデルが遠隔サーバー、小モデルがローカル機器にいる構成も概念的には可能だが、論文はネットワーク転送や実機での端末分散を主要実験として測定していない。二段階に分けることによる追加の小モデル生成費用や、モデル間のプロンプト受け渡しは残る。

### 2. 正解率と推論信号長の制約付き目的

大モデルが作る推論信号の長さを`L(z)`、目標平均長を`B`とする。目的は、小モデルの最終回答の期待報酬`R(x,y)`を最大化しながら、`E[L(z)] ≤ B`を満たすことである。実装ではラグランジュ乗数`λ`を使い、報酬から`λ L(z)/B`を引く。推論信号が長いほど罰則が増え、同じ正答率なら短い信号を好む。

大モデルと小モデルのパラメータを交互に最適化する。小モデルは大モデルからの信号を使って正解するよう学習し、大モデルは小モデルが読み取れる情報を短く表現するよう学習する。両方を固定せず更新するため、初期状態の小モデルが理解しにくい圧縮表現でも、訓練の過程で解読方法を合わせられる。ただし、学習が進めば常に短く正確になるわけではなく、後述の報酬修正がないと極端な短縮へ崩壊する場合がある。

### 3. 限界効用（marginal utility）報酬

単純に小モデルの最終回答の正解報酬だけを大モデルへ返すと、小モデルが自力で正解できる簡単な問題では、推論信号を出さなくても一定の報酬を得られる。長さ罰則だけが効き、大モデルが空に近い信号を生成する退化解へ進む危険がある。そこで同じ質問を小モデル単独で解かせた回答`y_m`を比較対象とし、`R(x,y_Mm)−R(x,y_m)`を大モデルの貢献度とする。

この差分報酬は、大モデルの信号が小モデルの正答を実際に改善した場合に価値を与える。小モデルが信号なしで正解できる問題では、大モデルが長い説明を出しても限界効用は小さい。反対に小モデルが単独では解けず、短いヒントで解ける問題では、そのヒントが高く評価される。学習時に小モデルの単独解答も生成する費用があるため、訓練コストは増えるが、推論時には二モデルの通常の二段階生成を実行すればよい。

### 4. 適応的な長さ罰則

固定の長さ罰則係数では、強すぎると推論信号がほぼ空になり、弱すぎると長い思考列を出し続ける。DUETは各学習段階で実測した平均信号長を目標予算`B`と比較し、`λ_t = [λ_(t−1) + η(E[L(z)]/B − 1)]_+`で係数を更新する。平均が予算を超えれば罰則を強め、下回れば弱める。負の罰則にならないようゼロで下限を設ける。

この更新は制約付き最適化の双対上昇法に対応する。大モデルが最初から短い表現を知っている必要はなく、学習しながら予算へ近づく。原著の構成要素除去実験では、限界効用を外すと正解率低下が目立ち、限界効用と長さ罰則の調整を両方外すと空に近い信号への崩壊が起こる。一方、長さ罰則の調整だけを固定係数に置き換えた場合の差は比較的小さい。二つの工夫が同程度に不可欠だと主張するのは不正確である。

### 5. 学習と推論の切り分け

原著は両モデルを群相対方策最適化（Group Relative Policy Optimization; GRPO）で訓練する。大モデルには正答の限界効用と長さ罰則、小モデルには最終回答の正答報酬を与え、交互に更新する。推論時は、訓練時の比較用小モデル単独解答や報酬計算を毎回実行する必要はない。学習時に二つのモデルを協調させる費用と、推論時に大モデルの出力を短くする利得は別の段階にある。

大モデルがもともと訓練問題を解けない場合、限界効用の信号は弱く不安定になる。実験では基準の大モデルがLIMO訓練集合で約10〜20%しか正解できず、150ステップ学習しても十分な圧縮を学べなかった。これはDUETが新しい推論能力を創出する方法というより、既にある大モデルの能力を少ないトークンで小モデルへ伝える方法であることを示す。

## 評価

### 1. モデル、データ、費用指標

| 項目 | 設定 |
|---|---|
| 大モデル | Qwen3-4B、思考モード有効 |
| 小モデル | Qwen3-0.6B |
| 学習資源 | H100 GPU 4基を利用できる環境 |
| 訓練集合 | MATH-LightEval、DeepScaleR、DAPO-Math-17kをそれぞれ利用 |
| 評価 | MATH500、AMC23、AIME2024、AIME2025、GPQA-Diamond |
| 学習方法 | GRPOで両モデルを交互に最適化、推論信号長に罰則 |
| 比較 | 大モデル単独、固定長の思考打切り、プロンプト短縮、単一モデルの短縮学習、ThinkPrune、L-GRPO |
| 指標 | 正解率、大モデル出力トークン数、正解率を1000トークン当たりで正規化したIPT |

論文のトークン数は基本的に**大モデルが生成した出力トークン**を数える。小モデルは平均1000トークン未満の回答を出し、著者は大モデル換算で100トークン未満程度の費用と見積もる。ただし小モデルのトークンを無条件にゼロとみなしたり、GPUの実測実行時間が同じ割合で減ったと断定したりしない。モデル間通信、バッチ化、KVキャッシュ、GPU稼働率を含む実測は別途必要である。

### 2. 主な比較結果

| 課題 | 大モデル単独 正解率 / トークン | DUET 正解率 / トークン | 大モデルトークン削減率 |
|---|---|---|---:|
| AMC23 | 0.90 / 6,948 | 0.88 / 1,800 | 約74.1% |
| AIME2024 | 0.66 / 12,458 | 0.63 / 5,337 | 約57.2% |
| GPQA-Diamond | 0.53 / 6,928 | 0.48 / 2,402 | 約65.3% |
| MATH500 | 0.89 / 4,358 | 0.88 / 1,106 | 約74.6% |

これは原著Table 1の比較であり、トークン削減率は各行の大モデル出力長から計算したもの。全課題で正解率が厳密に等しいわけではない。AMC23では2百分点、AIME2024では3百分点、GPQA-Diamondでは5百分点、MATH500では1百分点の低下がある。費用指標は大モデルの生成トークン数なので、表から「エンドツーエンド遅延が74%短縮した」とは言えない。

論文の情報量効率指標IPT（intelligence per token）は正解率を1000トークン当たりで正規化する。AMC23では大モデル単独0.130からDUET0.489へ、MATH500では0.204から0.796へ改善する。ただしIPTは正解率を多少犠牲にしてもトークン数が大幅に減れば上昇するため、正解率と必ず並べて解釈する必要がある。

### 3. 学習データを変えたときの汎化

MATH-LightEvalで学習したDUETは、より難しいAIME2024で正解率0.63・大モデル出力5,013トークン、AIME2025で0.47・6,418トークンを報告する。基準の大モデルはそれぞれ0.66・12,458トークン、0.53・12,625トークンなので、削減率は約60%、約49%である。これは訓練問題より難しい問題でも圧縮の振る舞いが移ることを示すが、AIME2025では正解率が6百分点低下している。

DeepScaleRで学習した場合はAIME2024で0.63・5,337、AIME2025で0.47・5,887、GPQA-Diamondで0.47・2,402を得る。DAPO-Math-17kで学習した場合はAIME2025で0.43・7,819となり、学習集合により品質と削減率の組み合わせが変わる。著者は大モデルが訓練集合で十分に高い正答率を持つことが重要だと指摘する。

### 4. 小モデルの共同学習と構成要素除去

小モデルを固定し大モデルだけを学習しても、ある程度の推論信号短縮は可能である。しかし小モデルも共同学習したDUETの方が、同じトークン数で高い正解率を得やすい。大モデルが出す圧縮信号に合わせて小モデルが解読を学ぶため、単に大モデルの文章を短くする以上の効果がある。

限界効用報酬を取り除くと、小モデルが単独で正解できる訓練問題で大モデルが信号を出さなくなる退化解に近づき、正解率が低下する。長さ罰則の係数更新だけを固定にすると、既定方式と近い結果を得る場合があり、主に限界効用の設計が重要である。両方を外した条件では極端に短い信号へ崩壊する。原著はこの失敗を明記しており、単純なトークン長罰則だけで同じ結果が得られるという説明は避ける。

## 既存研究との差

従来の蒸留は大モデルの能力を小モデルへ移すことを主眼とする。DUETでは大モデルを推論時にも使い、能力の必要な部分だけを短い信号として出力させる。大モデルを完全に置き換える方式ではない。投機的復号とは異なり、大モデルが小モデルの候補を検証するのではなく、最終回答生成を小モデルへ委任する。したがって原理的に大モデル単独と同一の出力分布を保証するものではない。

単一モデルの思考短縮方式との違いは、信号を受け取る小モデルの学習まで最適化する点にある。短い推論信号が小モデルにとって解釈可能であることを報酬で確かめ、単なる文字数削減ではなく伝達情報量を最適化する。二モデル間の信号はテキストなので既存の言語モデルを利用できるが、将来の連続潜在表現や双方向の問い合わせプロトコルは原著の実装結果ではなく今後の方向性である。

## 限界と実装状況

評価された高性能モデルはQwen3-4Bであり、より大きなモデルや異なる組み合わせへの適用性は未検証である。評価は正解・不正解で報酬を作れる数学・科学の問題に集中し、文章生成や曖昧な品質評価が必要なタスクへの一般化は確認されていない。正解率の数百分点の低下が許容できるかは用途に依存する。

大モデルがそもそも問題を解けない訓練集合では、限界効用の報酬が不安定になり、圧縮が学習できない。二モデルの共同訓練には計算資源と訓練手順が必要であり、任意の既存大モデル・小モデルを並べるだけで同じ削減率になるわけではない。小モデルの生成費用は小さいと見積もられているが、GPUでの実測遅延、遠隔モデル間の通信費用、バッチ化、サービングの同時実行性は主要実験で測られていない。

著者は公式コードURLを明示するが、コードの全環境での動作確認や推論基盤への統合はここでは行っていない。ユーザーのローカルGPUに対しても、Qwen3-4Bと0.6Bをどう配置するか、どの量子化を使うかにより費用が変わるため、原著のトークン削減率をそのまま速度改善率とみなすべきではない。
