# 自己確認型反省の抑制による推論トークン削減

## 概要

推論特化言語モデルは数学問題などに対して長い思考過程を生成する。その中には、既に正しい計算を終えたにもかかわらず「ちょっと待って、もう一度確認しよう」と先行内容を繰り返し肯定する部分がある。著者らはこの振る舞いを**自己確認型反省（Self-Affirmation Reflection）**として、誤りを発見して修正する反省と区別した。単純に全ての反省を禁止すると誤り訂正まで失われるため、どの反省が冗長かを生成時の確率から見分けることが問題となる。

論文は反省文の冒頭語に注目し、自己確認型の反省では冒頭語の生成確率が他の反省より低い傾向を報告する。これを利用し、モデルが「Wait」や「wait」を低確率で選びそうなとき、その語の確率をゼロにして別の継続を選ばせる。モデルを再学習しない推論時介入のほか、効率的推論を学習する強化学習のロールアウトにも適用する。R1-Distill-Qwen-1.5Bでは学習不要設定で平均出力長8,237.6から6,694.2トークンへの18.7%削減が得られるが、平均精度は64.9%から64.2%へ下がる。同じモデルで閾値0.1なら出力長7,721.1トークン、精度66.1%であり、**削減率と正解率の両方が閾値に依存する**ことが重要である。

## 問題設定と観察

推論モデルの「長すぎる思考」には、難しい問題を解くために必要な探索、途中計算の誤り訂正、既に正しい答えを再確認するだけの冗長な反省が混在する。従来の推論予算制御や強化学習による短縮では、どの種類の反省を減らしたかを細かく区別しない場合がある。著者らは、出力を短くするだけでなく、正答に必要な再検討を残しながら自己肯定的な再確認を抑えたいと考えた。

論文の例では、正しい数値解に到達した後にも「本当にこれでよいか」と同じ計算を何度も繰り返す。著者らは反省部分を二段階の判定で分析し、まず反省行動かどうか、次に先行する解答内容を肯定するだけかどうかを判定した。特定の反省位置から複数回生成を再開し、先頭候補語と後続の振る舞いを調べると、自己確認型の反省では別の推論ステップへ進む選択肢が比較的多く、他の反省では反省の継続が一貫している傾向が見つかった。

この分析から、反省の開始語の確信度が選択的抑制の手掛かりになる。とくに「Wait」の生成確率分布は自己確認型とそれ以外で部分的に重なりながらも異なる。完全に分離できる分類器ではないため、閾値を大きくすると有用な反省も除去してしまう危険がある。実験の長さ・精度の交換条件はこの不完全な識別を反映している。

## 手法

### 反省の役割を分けて統計を取る

著者らは推論出力中の反省候補を取り出し、現在の文が反省か、さらに直前の正しい推論を肯定するだけかを判定する。反省文の冒頭語の出現頻度と、その語をモデルが出す際の確率を集計する。単なる「wait」という文字列の出現数ではなく、**その語が反省を始める文脈と、生成確率**を観測する点が特徴である。

冒頭語の候補を変えて同じ位置からロールアウトすると、自己確認型の反省では反省を続けるか次の解法ステップへ進むかが揺らぐ。これに対して実際の誤り訂正を含む反省では継続の選択が比較的一貫する。論文は「But」の直後に「wait」が続く場合も観察しており、単語境界だけで全ての反省開始を把握できるわけではない。反復ループによって頻度が偏らないよう、末尾で同じ反省が繰り返される例を主要統計から除外し、別途付録で分析している。

### 学習不要の生成時介入

推論時に、生成候補の「Wait」「wait」の確率が設定閾値より低い場合、その候補の確率をゼロにする。確率を再正規化した後、残る語から次トークンを生成するため、モデルが必要と判断する高確率の反省開始は残り得る。論文はこの二つの表記を合わせてwaitトークンと呼ぶ。注意機構やモデル重みを変更するのではなく、生成分布に対する小さな介入として実装できる。

この操作は反省文全体を事後削除するものではない。**反省の入口にある候補語を選べなくする**ことで、後続の生成経路を別方向へ誘導する。ある語を消しても別の語から必要な反省が始まる可能性があるため、完全な反省抑制ではない。また確率閾値はモデル・問題の分布で最適値が異なり、複数の開始語を一括して抑制すると意図しない推論の変化が増える。

### 強化学習ロールアウトへの介入

学習を伴う実験では、短い正答へ高い報酬を与える既存の効率的推論学習（EfficientReasoning）へ、waitトークンの抑制を組み込む。学習時の正例と負例を区別せず全てのサンプルを短くすると、誤答から学ぶための多様な負例まで縮める可能性がある。著者らは生成前に正答かどうか分からない問題を避けるため、ロールアウトごとに確率的に介入する近似策を用いる。

論文では、waitトークンの確率が0.3未満のときの抑制を使い、ロールアウトの一部（例：25%）に介入する。これは推論時の単純な閾値適用と異なり、後続の学習データ分布と報酬最適化を変える。介入割合を上げれば常に良いわけではなく、過剰介入では学習する負例の性質が変わり、正解率を損なう。学習不要の結果と学習を伴う結果は同じ推論エンジンの直接比較ではない。

## 評価条件

| 項目 | 内容 |
|---|---|
| 推論モデル | R1-Distill-Qwen-1.5B / 7B / 32B、QwQ-32B、Qwen3-32B |
| データセット | AIME24、AMC23、MATH500、GSM8K。学習併用の比較は主にAIME24・MATH500・GSM8K |
| 試行数 | AIME24・AMC23は問題当たり8応答、MATH500・GSM8Kは1応答 |
| 出力長制限 | 最大32,000トークン |
| ハードウェア | NVIDIA L20 GPU。Qwen3-32BはvLLMを利用したゼロショット推論 |
| 指標 | 正解率（Acc）と回答1件当たり平均生成トークン数（LEN）。出力短縮はトークン数の削減であり、TTFT・TPSの実測倍率ではない |
| 比較 | 無介入モデル、同時期のUnderthink、強化学習を使うEfficientReasoningとの組合せ |

モデル規模や出力長によって生成トークンの削減が計算費用へ及ぼす影響は異なる。論文は主に正答率とトークン数を報告しており、GPU上の実測サービススループットを同じ割合で高速化したとは示していない。とくに長い推論の後半を短縮した場合と短い応答の前半を短縮した場合では、KVキャッシュ長やメモリ負荷への影響も異なる。

## 評価結果

### 学習不要の介入：短縮と正解率は同時に単調改善しない

| R1-Distill-Qwen-1.5B・4データセット平均 | 正解率 | 平均出力長 | 無介入からの変化 |
|---|---:|---:|---|
| 無介入 | 64.9% | 8,237.6 | 基準 |
| wait閾値0.1 | 66.1% | 7,721.1 | 長さ6.3%減、精度1.2ポイント増 |
| wait閾値0.3 | 65.2% | 7,701.5 | 長さ6.5%減、精度0.3ポイント増 |
| wait閾値0.5 | 62.9% | 7,009.1 | 長さ14.9%減、精度2.0ポイント減 |
| wait閾値0.7 | 63.1% | 6,963.3 | 長さ15.5%減、精度1.8ポイント減 |
| wait閾値0.9 | 64.2% | 6,694.2 | 長さ18.7%減、精度0.7ポイント減 |

一次論文Table 1の値。閾値を高くすると一般により多くのwait候補が抑制されるが、正解率は単調に変化しない。最大の18.7%短縮は完全な精度維持と同義ではない。小さい閾値では長さを少し削減しながら精度を改善する条件もあり、どの点を採用するかは精度許容範囲に依存する。

モデル間の短縮率はR1-Distill-Qwen-1.5B/7B/32Bでそれぞれ最大18.7%、14.3%、11.1%、QwQ-32Bで9.1%、Qwen3-32Bで8.4%と報告される。ただしこの最大短縮率は各モデルの選択閾値と評価条件に依存する。異なるモデル間で同じ閾値をそのまま転用して同じ削減率が得られるわけではない。

### 反省開始語の選択と過剰介入

付録Table 6では「wait」のみ、さらに「alternatively」、さらに「but」を加えた場合を比較する。抑制する語の集合を増やすと出力長が短くなる傾向はあるが、正解率を失う条件も増える。例えばR1-Distill-Qwen-1.5Bでwait＋alternatively＋butを閾値0.5で抑制した場合、平均長は5,651.5、平均精度64.6%であり、waitのみ閾値0.5の長さ7,009.1・精度62.9%とは異なる交換条件を示す。語の組合せと文脈依存性があり、単一の「冗長反省検出器」として完璧に働くわけではない。

強化学習の実験では、既存の効率的推論学習だけのR1-Distill-Qwen-1.5Bが平均精度66.6%、平均長4,292.7となる。介入確率25%を加えると精度65.7%、平均長3,613.0、50%では65.2%・3,630.5、100%では62.3%・3,593.1だった（Table 4）。25%の介入は学習済み基準より長さを約15.8%減らすが、精度は0.9ポイント低下する。100%介入では精度がさらに下がる。元の学習前モデル7,211.3トークンからの削減率と、既に効率化した学習基準4,292.7トークンからの削減率を混同しないことが必要である。

### 数値の解釈

論文が示す学習あり条件の最大50.2%という短縮率は、学習前のR1-Distill-Qwen-1.5Bと学習を伴う短縮方式を組み合わせた条件の比較であり、学習不要介入だけの18.7%とは基準が違う。評価表では、トークン数を短くしたからといって正解率が必ず維持されるわけではないことが読み取れる。従って「追加計算コストなしで推論を50.2%高速化」と言い換えるのは誤りである。

## 既存研究との差

単純な最大トークン数制限は、必要な誤り訂正まで打ち切る可能性がある。反省全体を別の思考状態へ変換するSEALは中間活性値へ介入するのに対し、本研究は反省の冒頭語の確率だけを操作する。Underthinkは一定の区間でlogitを操作する比較方式であり、本研究は自己確認型反省とその他の反省を区別する確率傾向に介入の根拠を置く。学習によって短い正答を選好させるEfficientReasoningに対しては、学習ロールアウトの生成分布そのものを変える補助手法として位置付けられる。

## 限界

第一に、自己確認型反省と有用な反省の冒頭語確率分布は重なっている。閾値を高くしすぎると必要な再検討も抑制され、R1-Distill-Qwen-1.5Bの正解率は閾値0.5で62.9%まで下がった。閾値の最適値はモデル・問題・生成設定に依存する。

第二に、Wait/waitという英語の開始語を中心にした方式であり、多言語の反省、異なるトークナイザー、複数語の「But wait」のような表現では同じ規則が通用するとは限らない。反省を事後的に識別する分析にもモデルによる判定が含まれ、分類誤りが統計へ影響する可能性がある。

第三に、論文は平均出力トークン数を主指標としており、生成速度、エネルギー、実サービスでのP95遅延、同時要求スケジューリング、GPUメモリの実測削減率を網羅的に評価していない。トークン削減率はそのまま推論時間の削減率ではない。Qwen3-32BでvLLMを使用したという事実は、全モデルのオンライン提供性能を測定したことを意味しない。

第四に、強化学習のロールアウトへ介入すると、正例・負例の長さ分布が変わる。正解を生成前に識別できないため、確率的な介入で近似している。Table 4で介入割合100%の精度が62.3%に低下することは、過剰な短縮が学習信号を損なう可能性を示す。末尾の自己確認反省ループや複数開始語の相互作用も完全には解決していない。
