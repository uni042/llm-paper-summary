# Transformer-VQ: Linear-Time Transformers via Vector Quantization

## 概要

Transformer-VQは、通常のソフトマックス（softmax）自己注意を使いながら、系列長Tに対する注意計算を二次の`O(T²)`から線形の`O(T)`へ変えるデコーダ専用Transformerである。基本の着想は、過去の鍵ベクトルを学習可能なコードブックの少数の代表ベクトルへ量子化すると、異なるトークン位置でも同じコードを持つ鍵は同じ注意得点になる、という性質にある。過去の各位置を個別に問い合わせる代わりに、**コードごとに値ベクトルを集計し、代表鍵への注意を計算する**ことで、古い履歴を一定サイズの集約状態として扱う。

ただし過去のすべてを単純に集約すると、近いトークン間の位置情報や因果マスクの扱いが難しい。Transformer-VQは近傍のブロックについては通常の位置依存注意を残し、それより古いブロックだけをコード別の圧縮キャッシュへ蓄積する。各コードの値の合計と出現件数を保持すれば、softmaxの分子と分母を分けて計算でき、**量子化済み鍵を使った密な注意**と数学的に同等の結果が得られる。これは元の非量子化鍵を使う注意と完全一致するという意味ではない。

ICLR 2024掲載版では、Enwik8の0.99ビット/バイト、PG-19の単語パープレキシティ26.6、ImageNet64の3.16ビット/バイトを報告する。TPU v3での訓練処理率は同規模の二次注意モデルと比べ、系列長8192で3倍超、32768で12倍超となり、131072トークンまで大きな処理率低下なく動作した。ただしこれは指定されたモデル・実装・ハードウェアでの結果であり、現代のFlashAttention付きGPU推論器へそのまま同倍率を適用できるわけではない。

## 問題設定

標準的な自己注意では、各問い合わせ位置が過去の鍵位置すべてとの内積を計算し、ソフトマックスで正規化して値ベクトルの重み付き和を求める。長さTの系列に対する注意行列はT×Tとなり、長文脈では演算量と中間メモリが急増する。局所注意や疎注意は参照位置を減らすが、遠い位置にある重要な情報を捨てる場合がある。カーネル化した線形注意はソフトマックスとは別の計算式に置き換えるため、元のsoftmax注意の性質を維持しにくい。

Transformer-VQは、鍵の数値表現をあらかじめ少数の代表値へ置換する。コードブックCにS個の代表鍵を用意し、各鍵k_tを最も近い代表鍵C[z_t]へ割り当てる。同じコードzを持つ位置は、ある問い合わせqに対して同じ内積`q·C[z]`を持つ。過去位置を個別に処理する必要はなく、コードごとの値の合計と件数から、密な注意を再現できる。**計算の線形化は量子化済み鍵を前提とする**ので、鍵の量子化誤差は学習・評価で確認しなければならない。

モデルは単一ヘッドの門付き注意単位（gated attention unit; GAU）を主に用い、問い合わせ・鍵へ正規化を施し、値ベクトルに門を掛ける。通常のTransformer層をそのまま置換するのではなく、量子化された鍵を学習する構造を採る。コード数Sや近傍ブロック長Lはモデル設計時に決めるため、厳密な計算量は`O(T(S+2L)(D_k+D_v))`であり、SとLを固定したときに系列長へ線形となる。

## 手法

### 1. 鍵のベクトル量子化

各トークンの鍵k_tに対し、コードブックCの中でユークリッド距離が最小の代表ベクトルを選ぶ。コード番号を`z_t=argmin_s ||k_t−C_s||²`とし、量子化鍵を`k̂_t=C_{z_t}`とする。問い合わせq_tは量子化せず、各代表鍵との内積を計算する。量子化によって鍵の種類が最大S個に減るため、注意得点の異なる列の種類もS個以下になる。

最近傍コードの選択は離散操作なので、そのままでは誤差逆伝播ができない。著者は直通勾配推定器（straight-through estimator; STE）を用い、前向き計算では代表鍵を使い、後向き計算では量子化前の鍵へ勾配を流す。コードブックの学習には量子化誤差を抑える補助損失を加える。これは量子化後の推論だけを工夫する方式ではなく、**鍵が量子化されても有用な注意を学習できるよう訓練する**方式である。

### 2. コード別の値の集約

同じコードzに属する過去位置集合をI_zとする。softmaxの分子は、各コードについて`exp(q·C_z) × Σ_{j∈I_z} v_j`を足せばよい。分母は同じ重み`exp(q·C_z)`に、そのコードの出現件数`|I_z|`を掛けて足す。したがって、過去の各トークン位置に対する注意行列を明示せず、S個の代表鍵に対する得点と、コード別に集計した値ベクトル・件数だけで注意出力を計算できる。

この集約は、量子化済み鍵を使った密なsoftmax注意の数値を代数的に並べ替えたものである。注意対象を恣意的に削る近似ではなく、**量子化で同じ鍵になった位置をまとめることによる正確な集約**である。量子化前の鍵と量子化後の鍵は異なるため、モデルの品質には別の近似誤差が残る。

### 3. 因果マスクと近傍注意の分離

自己回帰デコーダでは未来位置を見てはならず、直近位置には相対位置の偏りも必要になる。Transformer-VQは系列を長さLのブロックに分け、現在のブロックと直前のブロックには通常の因果マスク付き注意を適用する。それより古いブロックだけを圧縮状態へ入れる。こうすると、近傍ではトークン位置を区別でき、遠い履歴では同じコードの鍵をまとめて扱える。

ブロック番号nに対し、古い履歴のコード別値集約をU(n)、コード別出現件数をL(n)として更新する。新しいブロックを処理するたびに、そのブロックの各値を対応コードの集約へ加える。現在ブロックの出力は、二つ前までの圧縮集約からの寄与、直前ブロックへの通常注意、現在ブロック内の因果注意の三つを合成して計算する。分母についてもコード件数と近傍の指数重みを足し、最後に分子を割って正規化する。

この分割は、過去をすべて固定長の要約ベクトル一つに圧縮する方式ではない。S個のコードそれぞれに値の集約と件数を持ち、直近2Lトークンは位置ごとのKVを保持する。SとLを増やせば表現力が増える一方、集約状態のメモリと演算も増える。

### 4. 数値安定化と学習

古い履歴の値を単純に加算し続けると、系列が長い場合に値の大きさが増える。著者はコード別の値の合計ではなく平均を保持し、件数の対数をsoftmaxの指数側へ移す等価な計算を使って数値安定性を高める。これは数学的な出力を変えずに、長系列でのオーバーフローや精度劣化を抑える実装上の工夫である。

学習損失は自己回帰の交差エントロピーと、鍵をコードへ近づける量子化補助損失の和である。直通勾配推定を使うため、鍵の連続表現を作る射影と離散コードの双方を訓練できる。補助損失の重みが大きすぎると表現の自由度が減り、小さすぎるとコードが安定しない可能性がある。論文はコードブックサイズの感度も測り、Sを増やすと表現力が上がるが計算時間も増えることを確認した。

### 5. 計算量とキャッシュ容量

S個の代表鍵と近傍2Lトークンだけを参照するため、一つの問い合わせブロックの計算はおおむね`O(L(S+2L)(D_k+D_v))`となる。系列長Tに対してブロック数はT/Lなので、全体は`O(T(S+2L)(D_k+D_v))`である。SとLが固定ならTに線形であり、長文脈でも注意計算の増え方が抑えられる。古い履歴をコード別に集約しても、量子化済み鍵に対する注意の情報を失わない点が、通常の不可逆なキャッシュ削除と異なる。

一方、量子化で元の鍵の細かな差は失われる。さらに、圧縮状態にはコード別の値集約・件数・近傍キャッシュが必要であり、メモリ使用量が系列長に完全に依存しないという主張は、コード数やブロック長を固定した計算モデルの範囲で読むべきである。生成中のキャッシュ更新は逐次できるが、学習時の逆伝播や実機でのメモリ転送は別の費用を持つ。

### モデル品質の読み方

Enwik8の0.99 BPBは、当時のTransformer-XLなどの水準に達したことを示すが、0.94〜0.95を報告する先行方式もあるため、Enwik8で絶対最高精度という意味ではない。PG-19の26.6 WLPはBlock-Recurrent Transformerの26.5とほぼ同じであり、再帰状態を明示的に導入せずに長文脈で競争力のある性能を示した点が重要である。

ImageNet64の3.16 BPBは、画像をバイト列へ変換して自己回帰的に予測した密度推定の結果であり、画像分類正解率ではない。さらにImageNet64の先行研究には異なるダウンサンプリング方式を使うものがあり、論文自身が一部の数値の直接比較は適切でないと注意している。従ってImageNet64での「最高水準」という評価は、データ処理の差を含むことを明記する必要がある。

### 速度と圧縮キャッシュの交換条件

圧縮キャッシュを外す構成要素除去実験では、1学習反復の実行時間は約1.1倍短くなる一方、Enwik8のBPBが明確に悪化した。したがって圧縮キャッシュは単なる速度向上部品ではなく、長い履歴を品質を保ちながら利用するための重要な構成要素である。コードブックを大きくすれば量子化の表現力が増す可能性があるが、代表鍵に対する内積や集約状態が増え、速度との交換条件が生じる。

TPU v3での訓練速度測定は、同じ規模のモデルを系列長ごとに全長逆伝播させた条件である。実測倍率はGPUの単一トークン復号遅延を直接示さない。現代のFlashAttention付きGPUでの速度や、量子化重みとKVを使う既存推論基盤への組込み効果は別途測る必要がある。

## 既存研究との差

疎注意や局所注意は遠い位置の一部を参照しないことで計算を減らす。Transformer-VQは量子化済み鍵に対する**密なsoftmax注意の集約を代数的に再編成**するため、同じコードに属するすべての過去位置の値が集約へ寄与する。カーネル化した線形注意はsoftmaxの式そのものを別のカーネルへ近似するが、Transformer-VQは量子化した鍵を使う範囲ではsoftmaxの分子と分母を保つ。

通常のキャッシュ削除方式は不要と判定した過去トークンを捨てるため、後で参照したい情報が消える可能性がある。Transformer-VQは過去位置の値をコード別に蓄積し、位置ごとのKVを保持しない代わりに集約情報を残す。ただし鍵を量子化した段階で情報が変わっているので、元の密な注意と完全一致するという保証ではない。

## 限界と適用条件

第一に、鍵のベクトル量子化には誤差があり、元の非量子化鍵の細かな区別を失う。コードブックのサイズや学習方法によって品質が変わり、同じコードへ割り当てられた二つの鍵を区別することはできない。線形時間の「正確さ」は量子化後の鍵に対する注意計算の同等性を指す。

第二に、計算量はコード数Sと近傍ブロック長Lを固定したとき系列長に線形となる。SやLを文脈長とともに増やせば費用は増える。古い履歴のコード別値集約と件数、近傍2LトークンのKVを保持するため、追加の管理状態が不要になるわけではない。

第三に、主な速度比較はTPU v3の訓練処理率であり、GPU推論でのTTFT・トークン間遅延・同時要求処理率を直接測ったものではない。FlashAttentionやPagedAttentionなどの最新実装との同条件比較は必要である。現代のGPUに同じ12倍を外挿できない。

第四に、品質評価はEnwik8、PG-19、ImageNet64を中心とする。指示追従、コード生成、数学推論、長文検索、MoEの専門家選択、複数利用者の連続バッチ処理で同じ品質と速度を維持するかは未検証である。

第五に、ImageNet64の比較対象には画像前処理が異なる先行研究が含まれる。論文の3.16 BPBは公式検証集合での結果であり、すべての先行研究と厳密に同一条件で測った絶対的な優劣とは解釈できない。
