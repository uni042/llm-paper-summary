# NPFT：外れ値重みの感度を抑え、単一精度量子化を実用化する微調整

## 概要

大規模言語モデルの低ビット重み量子化では、全重みを一律に丸めると少数の敏感な重みが出力品質を大きく悪化させる。従来のSqueezeLLMやSpQRはこれらの外れ値をFP16などの高精度で別保存し、残りを低ビット化することで精度を保つ。しかし、重みを複数の形式で保持する方式は、疎な高精度成分の読み込み、異なる演算カーネルの組合せ、メモリ配置の複雑化を伴う。論文は外れ値を保護するのではなく、**量子化誤差に対する外れ値の損失感度自体を小さくする**ことを狙う。

提案するNoise Perturbation Fine-tuning（NPFT）は、Fisher情報による近似感度で外れ値重みを選び、これらの位置へランダムな摂動を加えた状態でLoRAアダプタを微調整する。学習後にLoRAを基底重みへ統合すれば、既存のRTN、GPTQ、SqueezeLLMなどの量子化器で同一ビット幅に圧縮できる。量子化器や推論カーネルを新設する方式ではなく、量子化前のモデルを頑健にする前処理である。

原著のOPT-1.3B・4ビットRTNではC4のperplexity（PPL）が24.68から21.74へ、WikiText2では48.19から36.30へ改善した。LLaMA2-7B・4ビットRTNではC4 PPLが7.72から7.42となり、同じ表のGPTQ 7.42に並ぶ。RTX 4090でOPT-1.3Bの128トークン生成を測ると、FP16外れ値0.5%を保持したsqLLMの2.62秒に対し、外れ値を保持しないNPFT併用版は2.40秒であった。ただし学習コストがあり、全ての量子化条件を救済するわけではない。

## 問題設定と従来方式との差

量子化した重みの誤差が同じ大きさでも、その誤差が損失関数へ及ぼす影響は重みごとに異なる。特に大きな感度を持つ外れ値では、小さな丸め誤差が損失を増やし、低ビット量子化後の言語モデリング性能を低下させる。SqueezeLLMは外れ値を高精度の疎行列として保存し、SpQRは高精度グループを残す。AWQは活性の重要性に応じた尺度調整を行う。これらは量子化器側で誤差を抑える設計だが、混合精度や特殊な表現を伴う場合がある。

NPFTの発想は、重みが敏感なままなら高精度で保存するしかない、という前提を変更することである。外れ値が摂動されても損失が増えにくいようにモデルを少量微調整し、量子化時に外れ値も他の重みと同じビット幅で扱えるようにする。低精度のまま正確に計算できる新しいGPU命令を作るわけではないため、推論時の利得は採用する量子化器とカーネルに依存する。

重要な区別として、本研究は量子化済みモデルを直接訓練する通常のQATではない。浮動小数点の基底モデルにランダムな重み摂動を加えて損失を最小化し、その後でPTQを行う。したがって3ビット用と4ビット用のモデルを個別に学習し直す必要はなく、同じ微調整済みモデルを複数の量子化器・ビット幅へ渡せる。ただしLoRA微調整という学習処理は必要であり、完全な学習不要PTQとは異なる。

## 手法

### 外れ値位置の選択：Fisher近似

論文は量子化前の重み行列をW、量子化後をWq、損失をLとし、損失増分を重み摂動のTaylor展開で近似する。事前学習済みモデルが収束付近にあれば一次の勾配項が小さく、二次のHessian項が重み誤差の影響を支配すると考える。Hessianを全パラメータについて直接求めるのは計算量・メモリ量の点で非現実的なので、損失勾配の二乗からFisher情報を近似し、感度が高い重みを選択する。

外れ値の割合は摂動比率γで指定する。原著のOPT実験ではγ=0.5%、LLaMA2実験ではγ=0.05%が標準設定である。128個のC4サンプルを使って外れ値の位置を決めるため、選択結果はモデルと較正データに依存する。ここでの「外れ値」は重みの絶対値だけで決めた大きな値ではなく、損失感度の高い重みである点が重要である。

### Hessian感度の暗黙的な抑制

損失Hessianのtraceを直接微分して最適化するのは高価である。論文はランダムベクトルzを用いるtrace推定の関係から、収束付近で重みへゼロ平均摂動を加えたときの期待損失増加がHessianのtraceに関係することを利用する。均一量子化の丸め誤差はおおむね量子化間隔Δの半分以内なので、摂動を一様分布から抽出して量子化ノイズの代理とする。

実際には感度が高い位置にノイズを入れ、摂動付きの損失を下げる。これにより外れ値の周辺で損失曲面が平坦になることを期待する。ただしこの導出はTaylor近似と収束付近の仮定を用いており、Hessian traceの厳密な最小化や任意の下流タスク精度の保証ではない。外れ値感度の変化は論文Figure 3の可視化で確認されているが、理論と実測の範囲を混同すべきではない。

### チャネル単位ノイズとLoRA最適化

外れ値は行列の特定チャネルに集中しやすいため、実装では出力チャネル単位でランダムなノイズを生成し、平均を引いてゼロ中心にした後、選択した位置に加える。各epochの初めにFisher感度から位置を選び直し、学習ステップごとに独立した摂動を与える。原著Algorithm 1では重み行列、摂動比率γ、較正データを入力として、感度に応じた位置とノイズ行列を構築する。

self-attentionとMLPの両方にLoRAアダプタを適用し、基底重みWにノイズzとLoRA更新を加えたモデルの損失、およびノイズなしの更新モデルの損失を同時に最小化する。論文の目的関数は `L(W+z+UᵀV) + β L(W+UᵀV)` であり、β=0.5を用いる。後半の項はノイズへの頑健化だけを追って元のモデル性能を損なうことを抑える役割を持つ。微調整終了後、LoRAの更新を基底重みにマージしてから既存量子化器を実行する。

この設計は、ノイズが量子化後ではなくFP16基底重みに加えられるため、学習中に低ビットの微分を近似する必要がないという利点を持つ。一方で、外れ値選択のための勾配計算、LoRA学習、ノイズ行列の保持は追加費用である。学習を行わずにその場でモデルを圧縮したい配備条件には直接適用できない。

## 評価

### モデル・データ・量子化器

主な実験はOPT-1.3B、OPT-2.7B、LLaMA2-7Bで、C4とWikiText2の言語モデリングPPLを比較する。128個・各512トークンのC4サンプルで感度を求め、OPTは6epoch・学習率5e-6、LLaMA2は3epoch・学習率5e-5で微調整する。量子化器は均一量子化のRTN/GPTQ、非均一量子化のSqueezeLLMを中心とし、AWQも比較に含まれる。PPLは小さいほど良い。精度は単一GPU上の生成速度とは別指標である。

原著Table 1とTable 2の代表値を以下に示す。特に3ビットRTNではNPFTを加えてもPPLが無限大になるOPT条件があり、改善が全条件で成立するわけではない。

| モデル・条件 | 量子化器 | C4 PPL | WikiText2 PPL |
|---|---|---:|---:|
| OPT-1.3B、4ビット | RTN | 24.68 | 48.19 |
| OPT-1.3B、4ビット | RTN + NPFT（γ=0.5%） | 21.74 | 36.30 |
| OPT-1.3B、4ビット | GPTQ | 16.97 | 15.47 |
| OPT-1.3B、4ビット | GPTQ + NPFT | 15.57 | 15.50 |
| OPT-2.7B、4ビット | GPTQ | 15.00 | 12.87 |
| OPT-2.7B、4ビット | GPTQ + NPFT | 13.76 | 12.88 |
| LLaMA2-7B、4ビット | RTN | 7.72 | 6.12 |
| LLaMA2-7B、4ビット | RTN + NPFT（γ=0.05%） | 7.42 | 6.08 |
| LLaMA2-7B、4ビット | GPTQ | 7.42 | 5.90 |
| LLaMA2-7B、4ビット | GPTQ + NPFT | 7.40 | 5.94 |

OPT-1.3BのGPTQではC4 PPLが改善してもWikiText2では15.47から15.50へわずかに悪化する。LLaMA2-7BのGPTQでもWikiText2が5.90から5.94へ悪化する。これは「NPFTは全量子化器・全評価データで必ず精度改善」という主張を否定する負の結果である。非均一量子化のsqLLMはもともと外れ値誤差を抑えているため、NPFTの上積みは比較的小さい。

### RTX 4090の推論効率と学習費用

Table 3はRTX 4090単体で128トークンを生成した場合のsqLLM比較である。OPT-1.3Bでは、外れ値をFP16で0.5%保持する方式が2.62秒・CUDAピークメモリ1.09GB・C4 PPL14.94、外れ値を別保持しないNPFT併用方式は2.40秒・1.08GB・PPL14.87だった。約8.4%の時間短縮であり、本文の約10%という総括と整合する。LLaMA2-7BではFP16外れ値保持が5.01秒・4.74GB・PPL7.08、NPFT併用の均一低ビット版が4.80秒・4.46GB・PPL7.08だった。こちらは約4.2%の時間短縮である。

この高速化は「NPFTの微調整そのものが推論を高速化する」という意味ではない。FP16外れ値を別途保持・処理する混合精度経路をなくした結果であり、同じsqLLMカーネル系で測ったものだ。実際、外れ値を保持しない通常sqLLMも2.40秒／4.80秒であり、NPFTがこの単一精度ベースラインより高速になったとは示されていない。利得は同等のPPLを保ちながら外れ値保持を省ける点にある。

Table 4ではLLaMA2-7BのNPFT γ=0.05%が3/4ビット双方に使える微調整を合計1.03時間で完了するのに対し、EfficientQATは3ビット用、4ビット用に各4.8時間を要する。比較条件のphase別ピークメモリはNPFTが15.23GBと6.11GB、EfficientQATは8.5GBと6.4〜7.0GBであり、NPFTは時間が短い一方で第1段階のメモリが大きい。単純な「学習時間が4分の1だから資源コストも4分の1」という読み方はできない。

### アブレーションと長文出力

Table 6ではOPT-1.3Bの4ビットでself-attentionのみ摂動した場合、C4 PPL24.03、MLPのみでは23.83、両方では21.74であり、全層に適用した方がよい。WikiText2でも49.04、37.44、36.30と同じ傾向である。ノイズなしの基底モデル損失を加えるβ項は学習の収束を安定化させ、摂動比率を大きくしすぎると学習が難しくなる。LLaMA2-7BはOPTより摂動に頑健という観察もある。

付録Table 10ではOPT-1.3B・4ビットの2048トークン生成において、FP16外れ値保持sqLLMが43.65秒、NPFT併用版が40.11秒となる。128トークンでは2.62秒対2.40秒、512トークンでは10.47秒対9.65秒であり、生成長が増えると絶対時間差が大きくなる。ただしこの表も同じGPUと特定カーネルの条件であり、別ハードウェアや大規模バッチでの性能を保証しない。

## 限界と実務上の判断

NPFTは外れ値を高精度で保持せずに済むよう、量子化前のモデルに追加学習を施す。事前学習済みモデルを一切変更できない運用、学習用データを用意できない環境、短時間で多数モデルを試す用途ではこの追加工程が障害になる。外れ値の選択はFisher近似と較正データに依存し、学習中にノイズを生成するためのメモリも必要である。論文はこの費用を将来の層別計算で改善できる可能性に言及するが、実測済みの成果ではない。

主な評価はOPTとLLaMA2系列、C4・WikiText2のPPLであり、現行のMoEモデル、長文対話、コード生成、指示追従、マルチモーダル、サービス負荷下のTTFT/TPOT/P99遅延は測定していない。RTX4090の128トークン生成は特定のsqLLMカーネル条件であり、一般的なvLLMやllama.cppの速度に直接換算できない。3ビットRTNの破綻を救済できない例や、GPTQでWikiText2がわずかに悪化する例を含め、改善は量子化器と評価データに依存する。

従来の「外れ値だけFP16で保持する」方法と比べ、NPFTは同じビット幅で推論できる可能性を増やす。しかし、混合精度をなくす利得と、学習前処理の費用は別々に見積もる必要がある。多種類のビット幅へ繰り返し量子化するなら1回の微調整費用を償却できるが、単発の小型モデル配備では通常PTQの方が総費用で有利な場合がある。これらは実務的な解釈であり、論文が実測していない運用条件の性能値を推定したものではない。

## 追加検証：3ビットと4ビットの非対称性

LLaMA2-7Bの3ビットRTNでは、C4 PPLが404.45から224.39へ、WikiText2が542.86から320.64へ改善するものの、GPTQの10.45・8.97には遠く及ばない。これはNPFTが敏感な重みの影響を軽減しても、量子化器そのものの再構成誤差が極端に大きい場合は回復が不十分であることを示す。OPT-1.3B/2.7Bの3ビットRTNではNPFT後もPPLが無限大となる条件がある。4ビットでの改善を根拠に、3ビット以下でも一律に有効と主張することはできない。

また、原著Table 3の「FP16外れ値を保持しないsqLLM」と「NPFTを加えてFP16外れ値を保持しないsqLLM」は、生成時間が同じ2.40秒（OPT）または4.80秒（LLaMA2）である。NPFTは実行カーネルを高速化するのではなく、外れ値を別保存しない単一精度のままで品質を回復する技術と整理するのが正確である。推論効率を評価するときは、同等のPPLという品質制約を固定したうえで比較すべきである。
