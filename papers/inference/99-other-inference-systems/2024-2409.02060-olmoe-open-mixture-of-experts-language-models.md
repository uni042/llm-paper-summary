## 概要

混合専門家（Mixture-of-Experts; MoE）は総パラメータを増やしながら、各トークンで一部専門家だけを実行することで、密 モデルより計算量を抑えられる。しかし公開MoEの多くは重みだけが公開され、学習data、ルーティング設計、失敗した設定、チェックポイント、logが不足し、なぜその構成が選ばれたかを再現しにくかった。

OLMoEは総6.9Bパラメータのうち1 トークン当たり1.3Bを活性化する完全公開MoEである。各MoE層に64個の細粒度専門家を置き、ルータがトークンごとに上位8 専門家を選ぶ。5.1T トークンを事前学習し、同程度の活性 パラメータを持つ公開モデル群で最高水準を示す。さらに専門家粒度、共有専門家、ルーティング方式、sparse upcycling、補助損失を一つずつ変える制御実験と、学習中の専門家専門化解析を公開する。

## 問題設定

MoEの推論コストは活性 パラメータで概ね決まる一方、全専門家 重みはメモリへ保持する必要がある。したがって「総容量を増やせる」という利点と、「ルーティング、読み込み balance、専門家配置、重み メモリが複雑になる」という負担が同時にある。

特に、専門家を何個に分けるか、何個を同時活性化するか、トークンが専門家を選ぶか専門家がトークンを選ぶか、共有専門家を置くか、といった選択は互いに影響する。OLMoEは完成モデルだけでなく、これらを制御実験で比較し、MoE設計の再現可能な証拠を作ることを目的とする。

## 手法

### 1. 細粒度64 expert・top-8活性化

OLMoE-1B-7Bは各MoE層に64個の小さい専門家を持ち、各トークンで8個を活性化する。総パラメータは6.9B、活性 パラメータは1.3Bである。大きな少数専門家より細粒度にすることで、トークンごとに組み合わせられる専門家集合を増やしつつ、1 トークンの実行量を抑える。

ルータは入力表現から64 専門家のlogitを計算し、top-8のsoftmax重みで専門家出力を加重和する。したがってSwitch Transformerのtop-1より1 トークン当たりの専門家計算は増えるが、より細かな専門化と組合せが可能になる。

### 2. dropless token-choice routing

最終構成は各トークンが自分のtop-k 専門家を選ぶトークン-choiceで、容量超過トークンを捨てないdropless ルーティングを使う。専門家側が受け入れるトークンを選ぶ専門家-choiceとも比較し、最終的にはトークン-choiceを採用した。

負荷偏りを抑えるため読み込み-balancing lossを重み0.01で加え、ルータ logitの過大化を抑えるz-lossを0.001で加える。cross entropyと合わせてルータの学習を安定させる。

### 3. scratch事前学習と公開性

密 モデルから専門家を複製するsparse upcyclingも比較するが、十分なcompute budgetではscratchからMoEを学習する構成を採用する。OLMoE-Mix約4.06T トークン相当のsource mixtureを用い、実際には5.1T トークンまで学習する。

モデル 重みだけでなく、data、コード、途中チェックポイント、学習 logを公開する。このため最終性能だけでなく、ルーティングがいつ固定化し、どの専門家がどのdomain/トークンへ専門化したかを学習過程に沿って調べられる。

### 4. routing専門化の解析

学習途中チェックポイントで同じ入力がどの専門家へ送られるかを追跡する。top-8集合は事前学習の1%、約20B トークン時点ですでに最大約60%が最終ルーティングと一致し、40%時点では最大約80%へ達する。後段層ほど早く飽和し、第1層は遅い。

また専門家同士の共活性、domain specialization、vocabulary specializationを測定し、専門家がランダムな計算分割ではなく入力domainや語彙に応じた役割を形成することを示す。

## 評価条件

| 項目 | 条件 |
|---|---|
| モデル | OLMoE-1B-7B: 6.9B total / 1.3B 活性 |
| 専門家 | 64 専門家/層、top-8 活性 |
| ルーティング | dropless トークン-choice |
| pretraining | 5.1T トークン |
| data | DCLM、StarCoder、peS2o、arXiv、OpenWebMath等 |
| 評価 | OLMES、DCLM、MMLU、GSM8K、HumanEval、AlpacaEval等 |
| 公開物 | 重み、data、コード、checkpoints、logs |

## 主要結果

| 条件 | 結果 | 意味 |
|---|---:|---|
| 同活性規模モデル比較 | OLMoEが最高水準 | 1.3B 活性でも総容量6.9Bを利用 |
| OLMoE-Instruct | AlpacaEval 84% | Llama2-13B-Chat等の大型密 モデルも上回る |
| top-8 ルーティング、20B トークン | 最大約60%飽和 | 専門家割当が学習初期から形成 |
| top-8 ルーティング、40%学習時点 | 最大約80%飽和 | 後半は既存専門化を精緻化 |
| 専門家構成 | 64中8 活性 | 細粒度ルーティングを採用 |
| auxiliary loss | 読み込み balance 0.01 / z-loss 0.001 | dropless ルーティングの偏り・安定性を制御 |

Instruction モデルではSFT後にDPOを適用し、測定したモデル群で最高の平均性能を得る。論文は、共有専門家が必ずしも有効でないこと、sparse upcyclingの利得がcompute budgetに依存することなど、最終設計に採用しなかった結果も報告する。

## 推論システム上の意味

OLMoEはサービングシステムそのものではないが、推論時には1 トークンにつき8/64 専門家だけを実行するため、活性 computeと総重み メモリが分離する。これは専門家 並列化、専門家 キャッシュ/オフロード、全対全通信通信、読み込み balanceを考える際の代表的な実モデル構成である。

一方、6.9B全重みを保持する必要はあるため、密 1B モデルと同程度の演算量でもメモリ footprintは同じではない。論文自身も、同程度活性 パラメータの密 モデルに近い推論コストでありながら、総7B相当のGPU メモリが必要になると明記する。

## 既存研究との差

Switch Transformerはtop-1 ルーティングでMoEを単純化し、MixtralやDeepSeekMoE等は高性能なopen-重み MoEを提供した。OLMoEの中心的差は、最終重みだけでなく学習data、コード、logs、途中チェックポイントと設計実験まで公開し、専門家設計・ルーティング・専門化を再現可能にした点にある。

また最終構成は64個の細粒度専門家から8個を選び、共有専門家を使わない。これは少数大型専門家やshared 専門家を採る別系統MoEとの具体的な設計差になる。

## 限界

MoEは活性 computeを抑えても全専門家 重みのメモリを必要とし、分散推論では専門家 ルーティングに伴う通信が発生する。本論文はモデル設計・学習・解析が中心で、vLLM等のサービングランタイム上でのTTFT、TPOT、全対全通信通信量を主評価していない。また制御実験は設定ごとにbase モデルが変わる場合があり、著者自身も全hyperparameter選択の普遍的最適性を保証しないとしている。
