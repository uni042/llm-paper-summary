# GateLoop：データ制御の線形再帰と並列走査による系列モデル

## 概要

GateLoopは、長い系列を処理する再帰モデルにおいて、**過去をどれだけ保持するかを入力トークンごとに決める**方式である。従来の状態空間モデルS4・S5や線形再帰単位LRU、RetNetでは、状態遷移の減衰を固定パラメータから計算する場合が多い。これに対しGateLoopは、入力から生成するキー・クエリ・値に加え、複素数の状態遷移係数そのものを入力依存にする。これにより、保持すべき情報を残し、不要な過去を忘れる振る舞いを系列内容に応じて変更できる。

理論上は、生成時に状態を逐次更新する線形計算量O(L)の再帰表現、学習時に結合的走査（associative scan）を用いるO(L log L)の並列表現、注意演算との関係を示すO(L²)の等価表現を導出する。ここでLは系列長である。実験では125MパラメータのWikiText-103言語モデルの試験パープレキシティが13.4であり、同表に示されたTransformer 18.6、Hyena 18.5、S5-Hyena 18.3より低い。**ただし、この結果は言語モデルの予測品質であって、推論処理量や実測GPUメモリの改善率ではない**。実機サービング性能の評価は論文の主要結果には含まれない。

## 問題設定と従来法

通常の線形再帰では、状態h_nを固定行列Aで変換し、新しい入力を加算して次状態を作る。固定Aは、どの入力を受け取っても同じ減衰特性を使うため、あるトークンが過去の記憶を消去すべき合図であっても、別のトークンと同じ割合で過去を保持してしまう。言語や合成記憶課題では、境界記号や話題の切替に合わせた保持・忘却の制御が重要となる。

自己注意（self-attention）はトークン対の相互作用を直接表現できる一方、全系列の注意行列は通常O(L²)の演算・記憶要求を持つ。線形再帰は一定サイズの状態を引き継ぐため長文の逐次生成に向くが、固定遷移では柔軟性を欠く。GateLoopは「線形再帰の小さい状態」と「入力に応じた状態遷移」を両立させる。これは既存Transformerの重みをそのまま量子化する手法ではなく、別のモデル層の設計である。

## 手法

### 1. 入力依存の状態更新

各時刻nで入力x_nから線形射影によりキーk_n、クエリq_n、値v_nを生成する。さらに入力x_nから複素数の状態遷移a_nを生成し、状態を `h_n = h_(n-1) a_n + k_n^T v_n`、出力を `y_n = q_n h_n` として計算する。入力項k_n^T v_nは現在トークンを状態へ書き込み、a_nは古い状態を残すか弱めるかを制御し、q_nは読み出す成分を決める。状態遷移の大きさと位相を別々に扱えることが、単純な実数ゲートとの違いである。

実装では、入力の線形射影から状態遷移の大きさと位相を作り、大きさにシグモイドを用いる。大きさを0から1の範囲に制限することで状態の無制限な増幅を抑える一方、位相は複素数平面上の変化を表す。固定遷移のRetNetはこのa_nを定数へ置き換えた特別な場合に相当する。状態遷移の動的制御により、単純な再帰のまま「この入力で記憶を消す」という条件付き動作を表現できる。

### 2. 結合的走査による並列計算

逐次更新は一時刻ずつ状態を求めるため、学習時に全トークンを一括処理するとGPU並列性を十分に使えない。GateLoopは各時刻を組 `(a_n, b_n)`、ただし `b_n=k_n^T v_n` と表し、二組の合成を `(a,b) ◦ (c,d) = (ac, cb+d)` と定義する。この演算は結合則を満たすため、並列の前方累積計算（prefix scan）で全時刻の状態を得られる。

この構成では、再帰の数値結果を保持しつつ、二分木状の並列計算で長い系列を処理できる。論文はO(L log₂ L)の並列方式を説明するが、これは漸近的な演算・仕事量の記述であり、実装における全条件のレイテンシ改善を保証しない。論文自身も、長い系列と多くのヘッドを同時に走査すると、途中の状態を保持する作業メモリがボトルネックになると注意している。

### 3. 注意演算としての等価表現

再帰を展開すると、時刻mの入力が時刻nの出力へ与える寄与は、mからnまでの状態遷移の積によって重み付けされる。状態遷移の累積積π_nを使うと、クエリを `q_n π_n`、キーを `k_m π_m^{-1}` に変換した因果注意の形式として書ける。すなわち、各トークンから作られる複素累積積が、入力依存の相対位置情報として機能する。

このO(L²)の注意表現は理論的な等価性を示すためのものであり、**高速推論に推奨する実装経路ではない**。著者は累積積を直接計算するとアンダーフローの危険があると明記している。したがって「注意行列を作れば速くなる」という解釈は誤りで、実用上の高速化候補は再帰更新または結合的走査である。

### 4. 実装と状態の持ち方

論文の実験では並列走査の実装を使う。著者の公開実装はJAX系であり、入力系列から状態を更新する層と、モデルの層ごとの持続状態（carry）を返す実行方式を備える。新トークンを生成する際は過去の全トークンを再走査せず、carryに新入力を適用する設計が可能となる。ただし、公開コードの別設定にある真の再帰重みを有効にした追加モードは、論文で比較した線形再帰と完全に同一の計算経路ではないため、性能評価を混同しない。

## 評価

### 合成Memory Horizon課題

合成課題では、途中に挿入されるリセット記号より前の情報を忘れ、リセット後の入力を記憶する必要がある。状態遷移を入力依存にしたモデルの試験正解率は0.43、固定遷移版は0.25だった。絶対差は0.18、相対では約1.72倍である。入力依存版はリセット位置で遷移の大きさをほぼ0へ落とす動作を学習し、固定版より長い記憶距離でも性能を維持した。これは記憶消去の機構を直接検証するための合成評価であり、自然言語サービングの性能測定ではない。

### WikiText-103言語モデル

WikiText-103の自己回帰言語モデルを125Mパラメータで比較した原著表1では、GateLoopの試験パープレキシティは13.4。比較対象はTransformer 125Mで18.6、Hybrid H3 125Mで18.5、Hyena 125Mで18.5、S5-Hyena 125Mで18.3、Transformer-XL 258Mで18.4だった。パープレキシティは低いほどよく、GateLoopはこの表の比較方式より小さい値を示した。ただしTransformer-XLだけはパラメータ規模が異なる。比較値の一部は先行研究の報告を引用したもので、全方式を同一実装環境で著者が再学習したとは読み取れない。

著者はモデルに注意層を使わず、複雑な状態空間初期化や長い暗黙畳み込みにも依存しない点を利点としている。一方、予測品質だけでは計算速度・GPUメモリ使用量・実行時の安定性を判定できない。O(L)再帰という漸近性から「実測でTransformerより何倍速い」と数値化することはできない。

## 限界・再現上の注意

第一に、主な自然言語実験は125M級のWikiText-103であり、数十億パラメータの指示追従モデルや長文推論で同等の性能優位があるとは未検証である。第二に、推論速度、トークン処理量、消費電力、KVキャッシュ容量の実測比較を原著は提示していない。再帰状態が小さくても、ゲートの射影、複素数演算、並列走査の中間状態は追加費用となる。

第三に、注意等価表現での累積積には数値的なアンダーフローがあり、並列走査も系列長と状態次元の積に応じた作業領域を要する。第四に、固定遷移方式との合成課題の差は課題設計に依存し、すべての言語タスクで同じ差になる保証はない。最後に、著者は初期化方式、ゲート活性化、学習済み状態遷移の解釈可能性を今後の課題として挙げている。

## 関連研究との差とシステムへの示唆

S4・S5は構造化状態空間の効率的計算を、LRUは初期化の簡素化を、RetNetは入力依存の入出力ゲートと固定遷移を重視する。GateLoopの固有の差は、**忘却率に相当する状態遷移までトークン依存にすること**と、そのまま結合的走査で並列化できる点にある。Mambaなどの選択的状態空間モデルと比較する際は、状態の形、複素数演算、走査実装、学習設定を合わせる必要がある。

本サーベイでは、KVキャッシュを縮小する既存Transformer用パッチではなく、長文逐次生成向けの再帰型アーキテクチャとして位置付ける。llama.cppへ単純な戦技のように追加できるものではなく、モデルの層構造、学習済み重み、再帰状態の保存形式を新たに実装する必要がある。
