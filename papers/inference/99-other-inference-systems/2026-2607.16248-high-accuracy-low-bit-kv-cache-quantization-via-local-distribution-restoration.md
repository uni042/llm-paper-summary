# High-accuracy Low-Bit KV-Cache Quantization via Local Distribution Restoration

> 1ビットKVキャッシュを維持したまま、量子化で崩れた高確率候補の局所順位だけを検出・補正し、RULER精度を47.8%から83.2%へ回復するDGAP。
## 書誌情報
- **著者**: Gradwell Dzikanyanga, Yanqi Pan, Weihao Yang, Donglei Wu, Wen Xia, Hao Huang
- **著者・所属**: Harbin Institute of Technology, Shenzhen
- **公開**: arXiv:2607.16248v1
- **種別**: arXiv preprint
- **対象**: KVキャッシュ量子化、低ビット推論、分布復元、長文脈推論、デコード効率
- **実装**: Python 3.10 / PyTorch 2.5.1+cu121 / Transformers 4.45.1 / CUDA 12.1 / PyTorch SDPAによる統一実装を論文中で評価。2026-09-24確認時点で本文には公式コード公開URLの記載を確認できない。
## 概要
DGAPは、1ビット級KVキャッシュ量子化で精度が崩れる主因を、ロジット値の一様な誤差ではなく高確率候補の局所的な順位入れ替わりとして捉え、永続KV表現を高精度化せずにデコード時だけ候補分布を修復する方式である。量子化ロジットから分布リスクを推定する軽量検出器を毎ステップ実行し、危険なステップだけ量子化top-K候補へ補正器を適用する。補正器はFP16/低ビットの対になったオフライン軌跡から、局所KL損失と順位整合損失で学習される。Llama-3.1-8BのRULERではK1V1の47.8%を83.2%まで回復し、FP16の84.2%へ近づける一方、Qwen2.5-14BではFP16比14.2倍のKV圧縮率を維持する。デコード遅延増は約1.06倍、スループット低下は6%未満で、利益は1ビット級の強い量子化ほど大きい。

DGAPは永続KVのビット幅を上げるのではなく、量子化ロジットに残る「structured local misranking」をデコード時に検出し、回復可能なステップだけtop-K候補分布を補正する。分布リスク検出器と選択的top-K補正器を分離し、前者は量子化ロジット由来の軽量特徴のみ、後者は危険ステップの小さな候補集合だけを処理する。さらにキー精度ごとにFP16候補質量を十分覆う最小回復窓K_bをオフライン校正し、KL分布整合と確率差重み付き順位損失を組み合わせて、局所確率形状と相対順位の双方を復元する。

代表結果として、RULER accuracyはK1V1 + DGAPでLlama-3.1-8B K1V1; FP16は84.2%に対して47.8% → 83.2%。1-bit KVの大きな品質崩壊の大半を永続KV精度を上げずに回復する。
## 問題設定
長文脈LLMではKVキャッシュが文脈長とバッチサイズに比例して増え、メモリ容量と帯域がデコードの主要制約になる。低ビットKV量子化は容量を削減できる一方、K1V1のような強い量子化では品質が急落する。著者らの制御実験では、FP16ロジットの値を維持して量子化後の順位だけを課すと精度が31.8ポイント低下する一方、順位を保ったスコア変化はFP16から1.2ポイント以内であり、主因は高確率候補の局所的な並べ替えだと示される。問題は、FP16参照を実行時に再計算したり全語彙を補正したりせず、この局所的な分布崩れだけを低コストで修復することである。
## 新規性
DGAPは永続KVのビット幅を上げるのではなく、量子化ロジットに残る「structured local misranking」をデコード時に検出し、回復可能なステップだけtop-K候補分布を補正する。分布リスク検出器と選択的top-K補正器を分離し、前者は量子化ロジット由来の軽量特徴のみ、後者は危険ステップの小さな候補集合だけを処理する。さらにキー精度ごとにFP16候補質量を十分覆う最小回復窓K_bをオフライン校正し、KL分布整合と確率差重み付き順位損失を組み合わせて、局所確率形状と相対順位の双方を復元する。
## 手法
### 手法のあらまし
入力は既存の低ビットKVデコーダが各ステップで生成する量子化ロジットである。まずentropy、top-K確率質量、候補間gap、確率集中度、分散などから検出器がリスクr_tを推定する。r_tが閾値τ以下なら元の量子化ロジットをそのまま使用し、τを超えると量子化top-K_b集合だけを抽出して補正器が疎なロジット更新量を予測する。K_bはキー精度別に、FP16高確率候補集合の確率質量が量子化top-Kへ十分含まれる最小サイズとして校正される。この判断は各トークンの選択直前に行われ、量子化デコーダ本体の注意計算や保存済みKVの形式は変えない。

学習ではPG-19から同一prefix/targetについてFP16 KVと低ビットKVを対にした軌跡を作る。検出器には、FP16と量子化後の局所分布の距離が閾値を超え、かつFP16高確率候補の十分な質量が回復窓内に残るステップを正例として与える。補正器はFP16局所分布とのKL損失、FP16の相対順位を再現する確率差重み付きpairwise rank loss、更新量のL2正則化で学習する。実行時にはFP16教師も追加forward passもKV再構築も不要で、永続低ビットKVは一切変更しない。

### 分布リスク検出器
検出器は量子化ロジットだけを入力にし、entropy、量子化top-K_bに含まれる確率質量、上位候補間のlogit gap、確率集中度、候補分散などのcompactな分布形状特徴を作る。これらは、候補間のmarginが小さい、あるいは確率質量が広く分散しているときに非一様な量子化誤差で順位が反転しやすいという観察を利用する。FP16ロジットや追加のreference forward passはオンラインでは使わず、各デコードstepでrisk score r_tだけを予測する。

教師信号はPG-19から作ったFP16/低ビットのpaired トレースから得る。FP16高確率候補集合と量子化top-Kの和集合上で正規化した局所分布距離を測り、分布歪みが閾値を超え、なおFP16候補質量が回復窓に十分残るstepだけを「回復可能な危険step」として正例にする。r_tが校正済み閾値τ以下なら補正器を完全にbypassし、不要な計算を発生させない。これにより高コストなFP16照合をオンライン経路から除外する。

### ビット幅別回復窓
回復窓K_bは固定の共通値ではなく、KVのbitwidthごとにオフライン校正する。まずFP16 next-トークン分布から累積確率質量αを満たす最小の高確率候補集合を作り、その候補のFP16確率質量が量子化後top-K内で平均して目標ρ_K以上回収される最小Kを選ぶ。キー量子化はquery-key scoreを直接変えるため、bit数が少ないほど候補順位の変動が強くなり、より広い回復窓が必要になるという設計である。

この仕組みにより、全語彙を毎step補正する計算を避けつつ、実際にFP16側で重要だった候補を補正対象に残す。K1V1のような強い量子化では大きなK_bで回復可能性を確保し、K4V4/K8V8のように元の分布が安定する設定では小さな窓へ縮める。したがって回復精度と候補処理量の折衷がbitwidthに追随し、永続KV精度を一律に上げる必要がない。回復不能なほど重要候補が窓外へ落ちたstepは検出器の正例からも外し、局所補正の適用範囲を明確に限定する。

### 選択的top-K補正器
r_tがτを超えたstepでは、量子化ロジットからtop-K_b候補集合だけを選び、各候補の局所logit、順位、margin、確率に検出器の分布特徴を合わせて補正器へ入力する。補正器は選択候補に対する疎なlogit更新量だけを出力し、それを元の全語彙logitへmergeする。候補集合の外側は変更せず、r_tがτ以下なら全logitをそのままトークン selectionへ送るので、stable stepでは補正器のコストが発生しない。

補正後の目的は単に絶対logit誤差を小さくすることではなく、FP16の局所確率形状と相対順位を戻すことである。これにより、1-bit KVを保持したままトークン選択直前の分布だけを修復できる。base modelやattention カーネル、stored KV tensorを作り直さず既存低ビットdecoderの後段に追加する構成なので、KVのpersistent メモリ削減と補正の計算コストを分離して扱える。補正はK_b≪Vの局所sliceに限定されるため、語彙全体を走査・更新するdense correctionを避ける。

### 局所分布・順位の共同学習
補正器の教師は検出器と同じpaired FP16/量子化-KV トレースから作る。選択されたtop-K_b候補についてFP16と補正後logitをtemperature付きsoftmaxで局所分布へ変換し、FP16から補正後へのKL divergenceを最小化する。さらにFP16でiがjより上位だった候補pairに対し、補正後もその順序を保つようpairwise rank-consistency lossを加え、各pairの重みにはFP16確率差を使う。大きな更新を抑えるL2正則化も加える。

この三項目的により、確率質量の形、上位候補の相対順位、補正量の安定性を同時に扱う。pairwise項はオフライン学習時だけに使い、オンラインでは学習済み補正器が局所候補への更新を直接出すため追加のpair列挙は不要である。著者は常時動く単一エンドツーエンド correctorではstable stepにも重い処理が必要になるとし、軽い検出と条件付き補正を分離してデコード時のメモリ trafficとcompute オーバーヘッドを抑えている。補正器は危険かつ回復可能なstepだけに適用されるため、学習目標と実行時gateが同じ局所回復仮説に沿っている。

### 全体のデータ／制御の流れ
オフライン段階でPG-19の長文書から複数の文脈長を持つprefixを採り、同一モデルをFP16 KVと対象低ビットKVで実行してpaired トレースを収集する。そこから各stepのFP16/量子化局所分布、候補被覆率、分布特徴を算出し、検出器と補正器を学習する。同時にrisk threshold τとbitwidth別recovery window K_bをvalidation トレースで校正し、推論時に固定して使う。学習用PG-19と評価用LongBench、RULER、MMLU、WikiText-2は分離されるため、評価ベンチマークの答えを直接教師へ混入させない構成である。

オンライン段階では既存の低ビットKV attentionが通常どおり量子化KVからlogitsを生成し、その直後にDGAPを置く。検出器が毎stepの量子化logitsからrisk scoreを出し、閾値以下なら何も変更せずトークン selectionへ流す。閾値超過時だけtop-K_b候補を補正器へ渡し、疎なlogit更新を全語彙logitへmergeしてから次トークンを選ぶ。したがってbase model 重み、attention カーネル、persistent KV layoutを再構成せず、K1V1の保存容量を維持したまま分布修復だけを追加できる。現在の実装はこの後段補正をPyTorch上で評価しており、Triton/CUDA融合やonline calibrationは将来拡張として残されている。
## 評価条件
- **ハードウェア**: NVIDIA A100 80GB GPU。長文脈でKV容量とデコード遅延が支配的になるバッチ size 1を基本条件とする。
- **ソフトウェア**: Python 3.10、PyTorch 2.5.1+cu121、Transformers 4.45.1、CUDA 12.1、PyTorch SDPA。
- **モデル**: Llama-3.1-8B-Instruct、Mistral-7B-Instruct、Qwen2.5-14B-Instruct
- **データセット／トレース**: PG-19（DGAPのオフライン学習・校正。評価集合とは分離）、LongBench、RULER、MMLU、WikiText-2
- **比較対象**: FP16 full-precision、uniform K1V1/K2V2/K4V4/K8V8、KIVI 2-bit、KVQuant 3-bit、TurboQuant 2.5-bit
- **正確性・品質**: 同じmodel–ベンチマーク pairでは評価prompt、デコード設定、random seedを統一。DGAPの学習/校正はPG-19のトレース-training/validationに限定し、LongBench/RULER/MMLU/WikiText-2から分離。persistent KV bitwidthを変えずに品質回復を比較する。
- **精度条件**: K1V1〜K8V8を比較し、特にK1V1を極端な低ビット条件として評価。
- **校正**: τ、K_b、temperature T、loss 重みはvalidation トレースで選びtestでは固定。既定のrisk thresholdはτ=0.60。
- **遅延計測**: CUDA synchronizationを用い、p95 トークン デコード 遅延とスループットを測定。
- **メモリ評価**: Qwen2.5-14Bについて8K〜128K contextのpersistent KV メモリを比較。
LongBenchの8タスク平均、WikiText-2 perplexity、MMLU accuracy、RULER accuracyに加え、FP16とのlocal distribution driftを測る。機構検証では、FP16ロジットへ量子化順位だけを適用する条件と順位保存スコア変換を比較して、品質低下の原因を順位崩れと値変化へ分離する。ablationではKV精度、補正対象、検出器/補正器のarchitecture、閾値τを変える。
単一A100-80GB上のバッチ-size-1デコードを中心としたアルゴリズム評価であり、大規模multi-tenant servingや複数GPUスケジューリングは評価対象外。3モデルと4種の評価ベンチマークで一般化を確認するが、校正値の異なるモデル/運用分布への無調整移植は保証しない。
## 主要結果
DGAPはK1V1の永続メモリ量を変えず、局所的な候補分布補正だけで強い品質回復を示す。Llama-3.1-8BのRULERでは47.8%から83.2%へ改善し、local distribution driftは0.38から0.14へ低下する。Qwen2.5-14Bでは128K contextで7.58GBのK1V1/DGAP KVに対しFP16は107.69GBで、14.2倍の圧縮を維持する。代償は約5〜6%のトークン 遅延/スループットであり、高ビットKVでは元から分布が安定するため追加利得は小さい。

- RULER accuracy / 47.8% → 83.2% (比較対象: Llama-3.1-8B K1V1; FP16は84.2%; 条件: K1V1 + DGAP) — 1-bit KVの大きな品質崩壊の大半を永続KV精度を上げずに回復する。

- local distribution drift / 0.38 → 0.14 (比較対象: Llama-3.1-8B K1V1; 条件: DGAP適用) — 提案が直接狙う局所候補分布のずれ自体が縮小している。

- LongBench average / 29.99 → 40.85 (比較対象: Llama-3.1-8B K1V1; KIVI-2bit 40.65, KVQuant-3bit 41.02; 条件: 8 LongBench tasks) — 1-bit footprintのまま主要2/3-bit方式と同水準まで回復する。

- persistent KV compression / 14.2× vs FP16 (比較対象: Qwen2.5-14B FP16; 条件: 8K〜128K context; 128Kで107.69GB → 7.58GB) — DGAPはstored KVを変更しないためK1V1の圧縮率を完全に維持する。

- p95 トークン デコード 遅延 オーバーヘッド / 約5.6〜6.3%増 (比較対象: Qwen2.5-14B K1V1 without DGAP; 条件: 8K〜64K context) — 補正を危険ステップのtop-Kだけへ限定することで追加計算を小さく抑える。

- DGAP gain vs bitwidth / +31.9点(K1V1) → +0.2点(K8V8) (比較対象: Llama-3.1-8BのNIAH/MK/MV平均; 条件: K1V1/K2V2/K4V4/K8V8) — 価値は強い量子化で最大になり、高ビットでは追加補正の必要性が小さい。

### 負の結果・境界条件
- **高ビットでは利得が小さい**: K4V4/K8V8では元の候補順位が既に安定しており、DGAPの平均改善は0.2〜0.6点程度。
- **ゼロオーバーヘッドではない**: Qwen2.5-14B K1V1でトークン 遅延は約5.6〜6.3%増え、スループットは約5.3〜5.9%低下する。
- **校正依存**: risk thresholdとrecovery windowはpaired FP16/量子化 トレースによるオフライン校正に依存し、運用分布変化へのonline適応は未実装。
- **serving-system評価なし**: 大規模multi-tenant serving、batching、multi-GPU環境との統合効果は未評価。

### 結果の読み方
DGAPの主要な意味は「KVそのものをより正確に保存する」のではなく、「低ビットKVから生じた最終候補分布の局所的誤りをトークン選択直前に直す」ことである。したがってメモリ側の圧縮率と品質回復を分離できる。制御実験で順位崩れの寄与を切り分け、driftとend-task qualityの双方が改善するため機構との整合性は高い。ただし結果はバッチ-size-1 A100中心で、serving全体のスループット/SLO効果までは示していない。
## 品質への影響
K1V1のような極端な量子化では品質回復が大きく、Llama/Mistral/QwenのLongBench・RULER・MMLU・WikiText-2で高ビット方式に近い値へ戻る。一方、高ビットでは元々の品質がFP16に近いため改善幅は急速に縮む。DGAP自体はbase model 重みやpersistent KV representationを変更しない。
## 既存研究との差
- **KIVI/KVQuant/TurboQuant等との違い**: 既存法が量子化表現、outlier処理、校正、混合精度などでKV表現自体の誤差を減らすのに対し、DGAPは既存低ビットデコーダの後段でトークン候補分布を選択的に修復する。
- **KV 追い出し/retention方式との違い**: SnapKV/PyramidKV等が保持するトークン/headを減らして容量を削るのに対し、DGAPは保持集合ではなく低ビット表現が起こす局所順位崩れを対象とするため直交的に組み合わせ得る。
- **量子化誤差の見方**: absolute logit errorの大きさではなく、高確率候補の相対順位と局所確率質量の歪みを直接の修復対象として定式化する。
## 限界
- 現行実装はオフライン校正したrisk threshold τとbitwidth別recovery window K_bを使い、deployment-specificなonline calibrationは将来課題。
- 検出器/補正器の追加計算は小さいがゼロではなく、K1V1でトークン 遅延約5〜6%増、スループット約5〜6%減がある。
- 評価はA100-80GBのバッチ-size-1中心で、大規模multi-tenant serving、continuous batching、複数GPU/異種GPUでのsystem-level効果は未検証。
- カーネル-level Triton/CUDA 融合は将来課題とされ、現実装の統合コストや他attention カーネルとの相互作用は十分評価されていない。
- 利益はaggressive low-bit量子化で最大で、高精度KVでは改善幅が小さい。

## 研究上の位置づけ
KVキャッシュ圧縮系の中でも、storage representationをさらに工夫する系列ではなく、量子化後のデコード-time output distributionを復元する補助層という位置づけ。K1V1級の極端な圧縮で容量削減を維持しつつ品質を戻すため、KV量子化・長文脈推論・distribution-aware correctionの交点にある。システム面ではvLLM等のpaged KV管理やオフロード/追い出しと競合するというより、その上で用いる低ビットKVの品質補償として併用可能。
