# RAGCache: Efficient Knowledge Caching for Retrieval-Augmented Generation

## 概要
検索拡張生成 (retrieval-augmented generation; RAG) では、検索した文書をプロンプトへ連結してから大規模言語モデル (large language model; LLM) のプリフィルを行うため、同じ知識文書が何度も検索されても、そのトークンのキー・値キャッシュ (key-value cache; KV cache) を毎回再計算しがちである。RAGCacheは検索文書を「再利用可能な知識単位」として扱い、文書列に対応する中間KVをGPUメモリとホストメモリへ階層的に保存する。再検索された文書列の最長接頭辞を再利用することで、初回トークン時間 (time to first token; TTFT) の大部分を占めるプリフィルを省く。

単なる接頭辞キャッシュだけでは、文書長が不均一、検索頻度が偏る、同じ文書でも前に置かれた文書列によってKVが変わる、GPU容量が小さい、といったRAG固有の問題が残る。RAGCacheは、文書順序を表現する知識木 (knowledge tree)、接頭辞認識型置換方策 (prefix-aware replacement)、キャッシュ認識型要求並べ替え (cache-aware reordering)、動的投機パイプライン処理 (dynamic speculative pipelining) を組み合わせて対処する。

## 問題設定
ある文書 (D_3) のKVは、入力列が ([D_1,D_3]) の場合と ([D_2,D_3]) の場合で異なる。TransformerのKVはそれ以前のトークンを条件に生成されるため、「文書IDが同じならKVも同じ」として単独オブジェクトをキャッシュできない。またRAGの検索頻度には強い偏りがあり、論文のMMLU解析では少数の人気文書が多数の要求から参照される。この偏りはキャッシュ機会を作る一方、容量不足時に単純な最終使用時刻 (least recently used; LRU) だけで追い出すと、サイズや再計算費用の大きい文書を失う。

さらに、検索処理とLLM処理を直列にするとベクトル検索完了までLLMが待つ。高要求率では、同じ文書を必要とする要求が離れて到着すると、GPUキャッシュが交互に入れ替わるスラッシングも起きる。RAGCacheは「何をどこに残すか」「どの要求を先に走らせるか」「検索待ち時間をどう隠すか」を一体で最適化する。

## 手法
### 知識木と階層KVキャッシュ
RAGCacheは共有システムプロンプトを根とし、検索文書IDを順序どおりのノードとして持つ知識木を構築する。根からノードまでのパスが「その順序の文書列」を表し、各ノードは対応するKVブロックのアドレスを指す。要求が到着すると検索文書列を根から接頭辞一致させ、木に存在する最長部分のKVを再利用し、残りだけを計算する。探索時間は木の高さ (h) に対し (O(h)) である。

KV本体はvLLMと同様に非連続のメモリブロックへ置き、頻繁に使うノードはGPU、次点は大容量ホストメモリ、価値の低いものは解放する。GPUから一度追い出したKVはホスト側コピーを保持する「一度だけ退避 (swap-out-only-once)」を採用し、同じノードがGPUから再び追い出されるたびにPCIe転送を繰り返さない。

### PGDSF置換
接頭辞認識型Greedy-Dual-Size-Frequency (prefix-aware Greedy-Dual-Size-Frequency; PGDSF) は、各ノードの優先度を概ね
`Clock + Frequency × Cost / Size`
で評価する。頻度 (Frequency) は時間窓内の検索回数、サイズ (Size) はトークン数に対応するKV占有量、費用 (Cost) はその接頭辞条件でKVを再計算する時間である。低優先度ノードから追い出し、GPU用とホスト用に別々の論理時計 (Clock) を持つ。

RAGでは同じ文書でも前置文書により再計算費用が変わるため、PGDSFは単純GDSFより接頭辞の計算依存を費用へ反映する。これにより「よく使う」「小さい」「失うと再計算が高い」KVを優先的に残す。目的は命中率そのものだけでなく、命中が失われた際の実際のプリフィル費用を減らすことにある。

### キャッシュ認識型要求並べ替え
到着順のままでは、異なる文書集合を参照する要求が交互に来てKVが入れ替わる。RAGCacheは短い並べ替え窓内の要求を優先度付きキューで並べ、キャッシュ済み接頭辞が長い要求や、追加計算に必要なメモリが小さい要求を先に処理する。これにより現在GPUにあるKVを使い切る前に追い出す事態を減らす。論文の例では単純な交互要求で0%になり得る命中率を、同一文書要求を寄せるだけで66%まで改善できる。ただし待ち時間を無制限に伸ばさない公平性制約も入れ、飢餓を避ける。

### 動的投機パイプライン処理
ベクトル検索は途中段階で候補文書を返せる。RAGCacheは最終検索結果を待たず、中間候補でLLM側のプリフィルを先行開始する。検索が進んで最終文書集合が確定したら、先行計算と一致する部分を利用し、異なる部分だけを修正する。これによりベクトル検索時間とLLMプリフィルを重ね、検索待ちをTTFTの外へ隠す。検索が長いほど重畳余地は大きいが、途中候補が最終結果と大きく異なると投機計算が無駄になる。

## 評価条件
| 観点 | 条件 |
|---|---|
| 主実験機 | AWS EC2 g5.16xlarge、AMD EPYC 7R32 64 vCPU、256 GiBホストメモリ、NVIDIA A10G 24 GiB、PCIe 4.0×16 |
| 大規模モデル | NVIDIA H800 80 GiB×2、NVLink、PCIe 5.0×16、384 GiBホストキャッシュ |
| モデル | Mistral-7B、LLaMA2-7B、Mixtral-8×7B、LLaMA2-70B |
| 実装 | vLLM 0.3.0を基盤に約5,000行のC++/Python拡張 |
| 検索 | Wikipedia知識ベース、Faiss IVF 1024クラスタ、既定top-k=2 |
| ワークロード | MMLU、Natural Questions |
| 比較対象 | vLLM、SGLang |
| 主指標 | 平均TTFT、TTFTサービス水準目標を満たすスループット、キャッシュ命中率 |

## 主要結果
Mistral-7BとLLaMA2-7B、MMLU/Natural Questionsで要求率を変えた総合評価では、RAGCacheは同じ要求率のvLLMに対して平均TTFTを1.2〜4.0倍、SGLangに対して1.1〜3.5倍短縮する。TTFT制約下の処理能力はvLLM比1.3〜2.1倍、SGLang比1.2〜1.8倍である。改善源は、人気文書のKVをGPU+ホストへ残してプリフィル再計算を避けることにある。

同じキャッシュ容量でも効果はモデル依存である。LLaMA2-7Bは同じトークン数でMistral-7Bの約4倍のKV容量を必要とし、同一メモリでは命中率が下がるためRAGCacheとvLLMの差が小さくなる。また文書再利用の偏りが強いMMLUはNatural Questionsよりキャッシュ利得が大きい。つまり「ホット文書が再利用される」「KVがキャッシュ容量へ収まる」ほど効く。

大規模モデルでは、Mixtral-8×7BとLLaMA2-70Bに対して低要求率時の平均TTFTをvLLM比1.4〜2.1倍短縮し、vLLMが設定したTTFTサービス水準目標を外れる要求率でもRAGCacheはより高い負荷まで目標内に留まる。

構成要素除去実験 (ablation) では、PGDSFはGDSFより命中率を1.02〜1.32倍、LRUより1.06〜1.62倍、最小頻度使用 (least frequently used; LFU) より1.06〜1.75倍高め、その結果平均TTFTも比較置換法より1.05〜1.29倍低い。キャッシュ認識型並べ替えは高要求率で平均TTFTを1.2〜2.1倍短縮する。動的投機パイプライン処理は検索と生成の非重複時間を1.5〜4.3倍減らし、TTFTを最大1.6倍短縮する。さらに知識木探索・更新、並べ替え、投機判断を含むスケジューリング時間は毎要求1 ms未満で、秒単位TTFTに対して小さい。

## 既存研究との差
一般的なLLM接頭辞キャッシュは文字列・トークン接頭辞の再利用を主に扱うのに対し、RAGCacheは「検索文書の順序付き列」を第一級のキャッシュ対象として知識木へ格納する。さらにGPUだけでなくホストメモリまで使った階層配置、接頭辞ごとの再計算費用を考慮する置換、要求順序とベクトル検索の重畳までRAGワークロード向けに協調させる点がシステム上の差である。

## 限界
利得は検索文書の再利用局所性に依存するため、ほぼ毎回異なる文書が取得されるワークロードではキャッシュの価値が落ちる。KVの大きいモデルでは同一容量に置ける文書数が減り、実際にLLaMA2-7BはMistral-7Bより改善幅が小さい。ホスト階層は容量を増やす代わりにPCIe転送を伴うので、命中してもGPU常駐ほど安くない。要求並べ替えには公平性との交換条件があり、投機パイプライン処理は中間検索結果が外れれば余分な計算を行う。また評価はvLLM 0.3.0時点の実装であり、現在の分離型サービングや区間化プリフィル (chunked prefill) と組み合わせた性能は論文の直接評価範囲外である。
