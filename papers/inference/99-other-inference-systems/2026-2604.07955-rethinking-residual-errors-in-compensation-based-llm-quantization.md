# ResComp：重み補償の途中で生じる残差誤差を正しく扱う低ビット量子化

## 概要

GPTQなどの学習後量子化（Post-Training Quantization; PTQ）は、線形層の重みを一列ずつ低ビット化し、量子化によって失われる出力を残りの未量子化重みの更新で補償する。GPTAQは、既に量子化した前段層の出力誤差が後段へ蓄積することを考慮し、量子化モデルの入力と全精度モデルの入力を分けて較正する。しかしGPTAQの列単位の反復最適化では、**途中まで補償した重みが作る出力**を目標にしており、**量子化前の元の全精度重みが作る出力**とのずれを見落とす。

本論文は、この差を補償認識誤差（Compensation-Aware Error; CAE）として定式化する。元の重み `W^(0)` と途中の補償済み重み `W^(q)` の差を、前段から伝播する入力誤差と別の残差項として重み更新へ加える。GPTAQのニューロン分解とGPTQの遅延更新を利用し、全出力を毎列で再計算せずに実装できる。GPTQにもGPTAQにも組み込める**量子化前処理の改善**であり、生成時に新しい演算を追加する手法ではない。

Llama2-7Bの3ビット重み専用量子化ではGPTQのC4パープレキシティー（Perplexity; PPL）13.60が本手法の追加で8.34に改善した。Llama3.1-8B-InstructのGPTAQではゼロショット6課題平均70.3%→72.3%となった。ただし量子化時のメモリ・時間は増え、70Bの3ビット重み専用ではGPTAQ単独よりゼロショット平均がわずかに下がる条件もある。品質改善を全条件で保証する方式ではない。

## 問題設定：補償済み重みを目標にする誤差

線形層の元の重みを `W^(0)`、列 `q` まで量子化・補償した重みを `W^(q)` とする。前段まで量子化した経路の入力活性を `X`、全精度モデルの経路の入力活性を `X̃` とする。通常のGPTQは `||Ŵ X−W X||²` を小さくするが、既に前段が量子化されているため、その `X` 自体が元のモデルの入力とずれている可能性がある。GPTAQは層単位では `||Ŵ X−W X̃||²` を目標にし、前段層から伝播する入力のずれを補償する。

しかしGPTAQの列ごとの最適化では、現在の補償済み重み `W^(q)` と元の全精度入力 `X̃` の積を基準としてしまう。`q=0` なら `W^(q)=W^(0)` で問題ないが、既に複数列を量子化した `q≥1` では両者が異なる。したがって途中の補償済み重みの出力へ合わせ続けても、最終的に元の全精度層出力を再現するとは限らない。

著者は列更新の正しい目的を `min_ΔW ||(W^(q)+ΔW)X−W^(0)X̃||_F²` とし、量子化済み列は固定して未量子化列だけ更新する制約を付ける（原著式10）。これは各反復で常に元の全精度出力を参照することを意味する。単なる誤差の名前の変更ではなく、**列ごとに何へ近づけるかという最適化目標の修正**である。

## 手法

### 1. 残差の二項分解

元の全精度層出力と、途中の補償済み重みを量子化経路へ通した出力の差を `r'=W^(0)X̃−W^(q)X` と定義する。原著式13はこれを `r1=W^(q)(X̃−X)` と `r2=(W^(0)−W^(q))X̃` に分解する。`r1` は前段までの量子化による**入力のずれ**で、GPTAQが既に扱っていた残差である。`r2` は同じ層の**補償済み重みと元の重みの差**が引き起こす残差で、今回追加した補償認識誤差に当たる。

`r2` を無視すると、列の量子化誤差を補償するために変更した重み自体が、次の列更新の目標をずらしてしまう。補償を何度も行うほどこの内部のずれが残る可能性がある。`r1` と `r2` を合計した残差を、GPTQの逆ヘッセ行列に基づく標準更新へ加える。概念上は `Δw=標準GPTQ更新+(r1+r2)X^T H^(-1)_{-q}` となる（原著式14）。

### 2. 逆ヘッセ行列と逐次列更新

GPTQは較正活性から `H≈XX^T` を作り、逆ヘッセ行列の情報を使って量子化済み列の誤差を残りの列へ分配する。全重み行に共通の列順を用い、逆ヘッセのCholesky分解を事前計算して更新費用を下げる。ResCompはこの仕組みを変えず、補償認識誤差の補正項を追加する。すでに確定した量子化列を後から変更するわけではなく、未量子化列の浮動小数点重みを更新する。

各列で `r1` と `r2` をフルサイズの出力行列として作り直すと、数十億パラメータのモデルでは較正が遅くなる。そこでGPTAQ由来のニューロン分解を用い、各列 `q` に属する重みと活性の寄与だけを抽出して逐次更新へ反映する。原著式16〜19では `r1` と `r2` を列ごとの積の和へ分解し、現在の列の情報だけから補正できる形へ変換している。

### 3. P1・P2の事前計算と遅延更新

量子化経路と全精度経路の活性差 `ΔX=X̃−X` から、`P1` は従来の入力誤差補償、`P2` は元重みとの差を補正するための係数行列となる。逆ヘッセのCholesky因子と上三角マスクを利用して両方を事前計算できる（原著式20）。さらに `X̃X^T=XX^T+ΔXX^T` を使うため、全精度活性と量子化活性の積を別にすべて保持する必要がない。

最終的な列更新は `標準更新+W^(q)_{:,q}P1_{q,q:}+(W^(0)_{:,q}−W^(q)_{:,q})P2_{q,q:}` の形になる（原著式21）。最後の項が新規のCAEである。GPTQへ組み込む場合は同じ入力経路を使うため `ΔX=0` となり、`P1` は不要で `P2` だけ追加すればよい。GPTAQでは`P1`と`P2`の両方を使う。ブロック内更新とブロック外の遅延更新を維持するので、各列の更新を行列演算にまとめてGPU効率を保てる。

### 4. 処理順と導入上の意味

まず較正入力を全精度モデルと量子化済みの前段モデルへ通し、`X̃` と `X` を用意する。元の重み `W^(0)` を保存し、ヘッセ近似とCholesky因子、`P1/P2` を計算する。各ブロックの各列を量子化し、標準補償、前段入力誤差、CAEを加えて未量子化列を更新する。ブロックの処理が終われば残りの列へまとめて更新を反映する。完成後の低ビット重みは通常の量子化重みと同じ形であり、推論時にCAEを計算しない。

CAEは量子化の**作成時の品質**を改善する方式で、モデルの推論カーネルやトークン生成アルゴリズムを高速化するものではない。出力品質の改善が実測のトークン/秒を改善したことにはならず、同じビット幅・同じランタイムなら基本的な保存重み量も変わらない。逆に較正時には元重みと追加の行列を保持するため、ピークGPUメモリが増える。

## 評価・実験条件と定量結果

### 対象モデル・較正・指標

対象はLlama 2とLlama 3系列の1B〜70Bモデルで、WikiText-2とC4のパープレキシティー（小さいほど良い）、PiQA、ARC-Easy、ARC-Challenge、HellaSwag、Winogrande、BoolQのゼロショット正答率（高いほど良い）を評価する。較正はWikitext2またはC4から2048トークンの128例を使い、量子化設定ごとに指定する。重み専用では群サイズ128の対称3ビットを主に評価し、さらに回転変換を組み合わせた2ビット、重み・活性・KVを同時に低精度化するW2A4KV4を調べる。

実装はPyTorchで、量子化列順にはヘッセ対角の大きさに基づく `act_order` を使う。70Bモデルの量子化はNVIDIA H20 96GB、他のモデルはA6000 48GBを使用した。比較対象はGPTQ、GPTAQ、AWQ、回転方式のQuaRotやSpinQuantなど。比較は**同じモデル・ビット幅でCAEを追加した差**と、異なる量子化方式間の差を区別する必要がある。

### 3ビット重み専用の主要結果（原著表1）

Llama2-7BのGPTQではC4 PPLが13.60→8.34と大きく改善し、ゼロショット平均も64.9→66.5%に上がる。一方、Llama3-70BのGPTAQ+CAEはPPLを改善しても、6課題平均正答率は74.7→74.4%と0.3ポイント悪化している。したがって、**PPLの改善がすべての下流課題の改善を保証するわけではない**。Llama3-8BでもGPTQ+CAEのゼロショット平均69.0%はGPTQ単独69.3%より0.3ポイント低い（原著表1）。改善を過度に一般化しない。

### 2ビット重み専用とW2A4KV4

回転方式QuaRotを組み合わせた2ビット重み専用（W2A16、原著表2）では、Llama2-13BのQuaRot+GPTAQがWikiText-2 PPL7.5、6課題平均55.8%、CAE追加後が7.3、58.2%だった。Llama3-70BでもQuaRot+GPTAQのPPL11.0・平均58.3%が、CAE追加後10.5・59.0%へ改善する。厳しい2ビット条件でも補償認識誤差が有効な例である。ただしこれらの性能にはQuaRotによる事前回転の効果も含まれるため、CAEだけの効果と混同しない。

重み2ビット・活性4ビット・KV4ビット（W2A4KV4、原著表3）では、Llama2-13BのSpinQuant+GPTAQがWikiText-2 PPL9.55・平均50.2%、CAE追加後は8.60・52.2%となった。QuaRot+GPTAQでは同モデルのC4 PPL17.2がCAE追加で16.5となる。一方Llama3-70BのSpinQuant系では、事前学習済み回転行列がW16A4KV4向けに最適化されているため、2ビット重みへの適用時にPPLが極端に悪化し、CAEを追加しても完全には回復しない。論文はSpinQuant+GPTAQのC4 PPLが10万超、CAE追加後も約5万という失敗条件を報告する。

### 構成要素除去実験（原著表4）

より厳しい回転付き2ビット条件で、CAEをGPTQへ単独追加するとLlama2-7Bの平均正答率は44.9→47.5%、Llama2-13Bは50.5→54.3%へ改善した。GPTAQへ追加するとLlama2-7Bは51.5→54.0%、Llama2-13Bは55.8→58.2%へ改善した。GPTQでは前段入力誤差項 `P1` が存在しないため、**`P2` だけでも効果がある**ことを示す。GPTAQでは`P1`と`P2`の併用が効果を持ち、入力経路の補償と同一層内の補償は相補的である。

ただしこの構成要素除去はすべてのモデルでの独立な因果保証ではなく、指定の回転・ビット幅・較正条件での比較である。特に極端な低ビット条件では、基盤となる回転方式の不安定性がCAEの改善幅を上回る場合がある。

### 量子化前処理のメモリと時間（原著表5・6）

Llama2-7Bの量子化時ピークGPUメモリはGPTQが8.5GB、GPTAQが19.8GB（全精度活性をCPUへ移せば10.1GB）、GPTAQ+CAEが20.6GB（同11.0GB）である。Llama3-70BではGPTQが23.2GB、GPTAQが63.7GB（CPU退避35.8GB）、GPTAQ+CAEが69.5GB（CPU退避41.5GB）となる。追加の元重みと`P2`がメモリを消費する。**これは量子化処理中のピークであり、完成した低ビットモデルの推論メモリ増加ではない**。

H20単一GPUでの3ビット重み専用量子化時間は、Llama2-7BでGPTQ 796±10秒、GPTAQ 952±30秒、GPTAQ+CAE 1001±12秒。Llama2-13Bでは1354±3、1626±11、1728±17秒。Llama3-70Bでは4746±120、5883±123、6344±153秒である。GPTAQ比で追加約5〜8%の前処理時間がかかる。著者の「約5%」は代表的な見積もりで、全モデルに厳密に同じ割合ではない。推論時にはCAEの演算を追加しないため、同じ量子化形式を使う限りランタイムの追加計算はない。

## 既存研究との差

GPTQは量子化経路の入力だけを使い、列ごとの補償で生じる誤差を残りの列へ分配する。GPTAQは前段層の量子化で変化した入力と全精度入力の差を考慮し、層間の誤差蓄積を抑える。ResCompはさらに、**同一層内で補償済み重みが元の重みから離れる誤差**を目標出力とのずれに加える。両者の残差は別の原因で生じるため、GPTAQの上に追加しても有効な条件がある。

QuaRotやSpinQuantは重み・活性の分布を回転して量子化しやすくする方式であり、CAEは量子化後の補償更新の目的関数を改善する方式である。原著はこれらの組合せを評価しているが、回転そのものの品質向上とCAEの品質向上を分けて読む必要がある。ResCompは推論時の生成速度改善ではなく、同じ低ビット容量での出力再現性と下流性能を改善する前処理である。

## 限界・負の結果・実装上の注意

第一に、低ビット量子化によるモデル能力の損失は残る。例えばW2A4KV4のLlama3-70BでSpinQuant系は極端なPPL悪化を示し、CAEだけでは実用的な品質へ戻らない。第二に、PPLが改善しても下流平均正答率が低下するモデル・条件がある。第三に、較正は全精度活性と量子化経路の活性を扱うため、前処理のピークメモリと時間が増える。70Bの量子化を低VRAMで実行するにはCPU退避や分割処理が必要になる。

第四に、論文の速度・メモリ評価は主として**量子化前処理**に関するもので、llama.cppやGGUFでの生成トークン/秒を比較していない。第五に、ヘッセ近似と較正入力に依存するため、較正分布と運用分布の違いが品質へ影響し得る。第六に、低ビットの誤差を補償する数式は指定の列順・ブロック更新・量子化演算子を前提とし、別実装で完全に同じ効果を保証しない。

## 再現と実装への展開

再現では同一のモデルと較正128例、群サイズ128、`act_order` を揃え、GPTQ、GPTQ+CAE、GPTAQ、GPTAQ+CAEを比較する。PPLだけでなく6課題の個別正答率と平均、量子化所要時間、ピークGPUメモリ、完成重み容量を記録する。2ビットやW2A4KV4ではQuaRot/SpinQuantの回転条件を固定し、CAEの追加分だけを差分として測る。特に70Bの失敗条件と下流得点の逆転を監査する。

llama.cppへ応用するなら、完成済みのGGUFへ後付けの実行時パッチを適用する方式ではなく、GGUF化前の重み量子化工程へCAEを組み込む必要がある。著者実装の量子化済み重みがGGUFの量子化形式へそのまま変換できるか、推論カーネルが対応するかは別途確認する。RTX 4070 Super 12GBでのローカル量子化は、論文が使ったA6000 48GBやH20 96GBとはメモリ条件が異なるため、原著の前処理時間・メモリをそのまま適用できない。
