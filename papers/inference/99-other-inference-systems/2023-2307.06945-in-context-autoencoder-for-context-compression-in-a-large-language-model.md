# In-context Autoencoder for Context Compression in a Large Language Model

## 概要
長文脈LLMは入力トークン数に比例してプリフィル計算とKVキャッシュを増やす。文書を単純要約するとトークン数は減るが、後続タスクに必要な細部を自然言語要約へ落とせない場合がある。In-文脈 Autoencoder（ICAE）は、長い文脈を通常のテキスト トークンではない少数の学習済みメモリ slotへ圧縮し、その連続表現を同じLLMが後続生成の条件として直接読む。

ICAEはLlamaを基盤に約1%の追加パラメータで構成され、まずautoencodingと言語modelingの二目的で大量テキストを学習し、文脈の内容をメモリ slotへ詰める。その後instruction dataでfine-tuneし、圧縮メモリと質問から回答を生成できるようにする。論文は4倍文脈 compressionを達成し、通常文脈を直接入力する場合より推論遅延とGPU メモリを改善すると報告する。

## 問題設定
通常のTransformerでは文脈をそのままトークン列として保持するため、同じ長文書を複数回利用すると毎回長いプリフィルが必要になる。KVキャッシュもトークン数に比例して増える。文脈 windowを拡張するだけでは、保持できる長さは増えても計算・メモリ費用は解決しない。

必要なのは、後続LLMが意味情報を利用できる形でトークン列を短い内部表現へ変換することである。自然言語要約と異なり、ICAEは「人間が読める短文」を作る制約を持たず、LLMの隠れ space上のメモリ slotへ情報を圧縮する。

## 手法

### memory slotへの圧縮
ICAEは入力文脈の後ろに少数の特別メモリ トークンを置き、encoder側処理で各メモリ トークンの隠れ 状態へ文脈情報を集約する。この隠れ 状態を圧縮表現として保存し、元の文脈 トークン列を後続LLMへ渡す代わりに使う。

圧縮率は元トークン数とメモリ slot数の比で決まる。4倍圧縮なら、後続処理が読む条件系列をおおむね4分の1へ減らせる。これによりプリフィル 注意機構とKV保存対象を短くできるが、圧縮段階そのものの計算は必要である。

### autoencoding目的
事前学習の一つは、メモリ slotだけを条件に元文脈を再構成するautoencodingである。圧縮表現が表面的なtopicだけでなく、元テキストを復元するのに必要な情報を保持するよう学習させる。

復元能力を強く要求することで、特定QA タスクだけに必要な特徴へ過度に特化するのを避ける。一方、有限slotへ全情報を完全保存することはできず、圧縮率を上げるほど再構成誤差との交換条件が強くなる。

### language-modeling目的
もう一つの目的では、文脈をメモリへ圧縮した後、そのメモリを条件に後続テキストを予測する。これは「元文を復元できる」だけでなく、「通常のLLM条件文脈としてメモリを使える」ようにする役割を持つ。

autoencodingとlanguage modelingを組み合わせることで、メモリ slotを単なるencoder ボトルネックではなく、生成LLMが直接消費できるin-文脈表現へする。基盤LLM全体を大きく作り直すのではなく、追加パラメータは約1%に抑える。

### instruction fine-tuning
事前学習後、instruction dataでfine-tuneし、圧縮文脈と質問・命令から望ましいresponseを生成するよう適応する。推論時には文脈を一度メモリ slotへ圧縮し、そのslotとプロンプトをLLMへ条件として与える。

同じ文脈を複数問い合わせで再利用できる場合、圧縮メモリを使い回せれば長文脈を毎回トークン列として再プリフィルする費用を避けられる。ただし論文の中心は表現学習であり、大規模multi-user 推論提供 キャッシュのスケジューラまでは扱わない。

## 主要結果
|条件|結果|意味|
|---|---:|---|
|代表設定|4倍文脈 compression|長文脈を少数メモリ slotへ縮約可能|
|モデル オーバーヘッド|約1%追加パラメータ|独立した大型encoderを追加しない|
|推論|遅延改善|後続LLMが読む条件系列短縮が計算量へ反映|
|推論|GPU メモリ改善|短いメモリ slotにより文脈保持費用を削減|

論文は圧縮メモリが単なる要約ではなく、元文脈のmemorizationとinstruction応答の双方へ使えることを評価する。4倍という値は「重みを4分の1にする」のではなく、文脈 表現の長さを4分の1相当へする圧縮率である。

速度面でも、文脈を圧縮するencoder処理を含めるか、圧縮メモリを複数問い合わせで再利用するかでエンドツーエンド利得は変わる。したがって推論提供 システムとしてのスループット倍率と解釈してはいけない。

## 既存研究との差
自然言語summarizationは人間可読テキストへ圧縮するが、ICAEはLLM 隠れ 状態上のメモリ slotへ圧縮するため、語彙トークンとして表現しにくい情報も保持できる。プロンプト compressionでトークンを選択・削除する方式とも異なり、複数トークンの情報を新しい連続表現へ集約する。

長文脈 モデルそのものを拡張する方式は元トークンを保持して注意機構するが、ICAEは後続計算が見る系列を短くする。KV 追い出しとは異なり、過去トークンを重要度で捨てるのではなく、学習されたencoderで文脈全体を固定数メモリへ写像する。

## 限界
圧縮は無損失ではなく、メモリ slot数を減らすほど細部の復元・下流タスク品質が悪化し得る。圧縮器を学習するための追加pretraining/微調整も必要で、既存任意LLMへ完全なtuning-free方式として適用するものではない。

一度しか使わない短文脈では圧縮処理の追加費用を回収しにくい。大規模推論提供でのキャッシュ 追い出し、multi-tenant スケジューラ、CPU/SSD オフロード等も論文の直接対象ではないため、4倍文脈 compressionからproduction スループットを推定してはいけない。
