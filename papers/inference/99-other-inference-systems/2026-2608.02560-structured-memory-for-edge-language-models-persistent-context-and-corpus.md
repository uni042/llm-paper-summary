# Structured Memory for Edge Language Models: Persistent Context and Corpus Retrieval via O(1) SSM State Injection

> 文書を隠れ状態として事前に保存し質問時に初期状態へ注入することで、検索付き生成の入力処理を約27秒から6ミリ秒未満へ短縮し、質問応答の品質が文脈内検索とほぼ一致することを示した。

## 概要

検索付き生成は、質問に答えるために検索した文書を、その都度プロンプトの先頭へ連結してモデルに読み込ませる。この読み込みはプリフィルと呼ばれ、費用は文書の長さに比例する。データセンターの高速な装置では許容できても、端末では深刻である。本論文の対象モデルは端末で毎秒19トークンしか処理できず、512トークンの文書断片1件を読むだけで約27秒かかり、最初の応答トークンが出るまで利用者を待たせる。さらに通常の注意機構を使うモデルでは、読み込んだ内容を保持するキー・バリューキャッシュが文脈長に比例して増え続け、生成のたびに読み直す帯域も増える。

本論文は、状態空間モデルでは事情が違う点に着目する。状態空間モデルは過去の内容を固定長の隠れ状態へ圧縮して保持し、1トークンの処理費用は文脈長によらず一定である。しかもその状態は位置に依存しない。ある文書を読んだ直後の状態は、その文書の完全な要約であり、どこで読んだかという情報を含まない。したがって文書を事前に読んで状態だけを保存しておけば、質問時にはその状態をモデルの初期状態へコピーするだけで、文書を読んだのと同じ出発点から質問の処理を始められる。これが提案方式の中核であり、入力処理の費用は文書長によらない定数時間になる。

代表結果は次の通りである。質問応答のベンチマークで、提案方式の先頭1件注入は完全一致率58.0、F1値73.4を記録し、同じ重みで文書を実際に読み込む方式の58.2、73.6とほぼ一致した。一方で応答開始までの時間は約27秒から6ミリ秒未満へ下がり、約4500倍の短縮である。この一致は偶然ではなく、状態の更新規則が時刻に依存しないことから導かれる等価性の帰結であり、論文はこれを定理として証明している。あわせて論文は、会話履歴などの蓄積する文脈についても同じ状態注入を使い、認知領域ごとのクラスタと忠実度の調整つまみを持つ階層型の永続メモリとして整理する仕組みを示す。評価は実在のモデル重みでの質問応答実測が中心で、端末の遅延と電力は試作測定とシミュレーションの組み合わせである。

## 問題設定

問題は2つの資源の偏りから生じる。第1に計算時間である。検索付き生成では検索自体は高速でも、得られた文書をモデルが読み直すプリフィルが応答全体を支配する。端末のように毎秒の処理トークン数が小さい環境では、数百トークンの文書でも数十秒の待ち時間になり、対話用途として成立しない。第2にメモリ帯域と容量である。注意機構のモデルでは過去トークンのキーと値を保持し続ける必要があり、その量は文脈長に比例する。生成のたびに全量を読み直すため、長い文脈では帯域が先に枯渇する。

既存の対策はいずれも読み込みを残す。文書を圧縮して短くする方式は読み込む量を減らすがゼロにはしない。キー・バリューキャッシュを事前に計算して使い回す方式は、位置符号化のために位置がずれると無効になり、共有する接頭辞がある場合にしか効かない。さらにキャッシュの容量は文書長に比例するため、文書集合全体をキャッシュとして保存すると容量が爆発する。本論文の計算では、512トークンの断片1件で比較対象モデルのキャッシュは約16メガバイトに達し、状態空間モデルの状態192キロバイトの約85倍である。1万件の文書集合では160ギガバイト対1.9ギガバイトとなり、端末の保存容量では後者だけが現実的になる。つまり不足しているのは計算の工夫ではなく、位置に依存せず固定長である再利用可能な文脈表現そのものであり、本論文は状態空間モデルの隠れ状態がまさにその性質を持つことを使う。

## 手法のあらまし

処理は大きく2段階である。事前準備では、文書集合を512トークン程度の断片へ分割し、各断片を状態空間モデルに一度だけ読ませて、24層分の最終隠れ状態を取り出す。各断片について、文章埋め込みで作った検索用の鍵と、192キロバイトの状態を組にしてフラッシュへ保存する。鍵だけは小さなベクトルなので主記憶へ読み込んで近傍探索の索引を作り、大きな状態本体は必要になるまでフラッシュに置く。

質問時は逆の順序で進む。質問文を同じ文章埋め込みで符号化し、余弦類似度で最も合う断片を探す。選ばれた状態をフラッシュから読み出してモデルの再帰状態へ書き込むと、モデルはその文書を読み終えた直後の状態から出発する。あとは質問文のトークンだけを処理して回答を生成する。文書トークンの処理は一切発生せず、追加費用は質問の埋め込み計算が約5ミリ秒、索引探索が1ミリ秒未満、状態の転送とコピーが合わせて1ミリ秒程度で、合計約6ミリ秒である。複数断片が必要な場合は上位の状態を類似度で重み付けして平均する拡張も用意されるが、こちらは等価性が成り立たない近似である。永続メモリの拡張では、会話の断片も同じ方法で状態化し、領域クラスタへ振り分けて保存し、会話開始時には統合済みの意味状態を初期状態へ書き込むことで、蓄積した履歴の長さによらず一定時間で会話を始められる。

## 手法

### 1. 事前符号化と状態注入 — 文書を読む作業を保存可能な状態へ変える

この機構が観測するのは文書断片の全文であり、保持する状態は断片を読み終えた時点の層ごとの隠れ状態である。状態空間モデルの更新は、現在の状態へ入力依存の減衰を掛け、現在のトークンの寄与を加える形であり、更新規則自体は絶対位置を参照しない。そのため断片を事前に読んで得た状態と、質問の直前に読んで得た状態は、浮動小数点の丸めを除いて一致する。選択されるのは検索で最も類似度が高い断片の状態であり、配置先はモデルの再帰バッファそのものである。これにより減るボトルネックはプリフィルのトークン処理であり、512トークンで約27秒かかっていた作業が、192キロバイトのコピーへ置き換わる。追加で消費する資源は保存容量で、断片あたり192キロバイトは元の文章の約200倍にあたる。失敗時の挙動として、検索が外れて無関係な断片の状態を注入した場合は、その文書を実際に読んだ場合とまったく同じ誤り方が再現される。つまり注入自体は誤りを増やさず、誤りの責任は検索精度側にある。逆に状態の一部層だけを注入する部分注入は等価性を失い、下位層だけなら品質をほぼ保てるが上位層だけでは大きく崩れることが除去実験で示されている。

### 2. 等価性の保証と記憶の射程 — なぜ一致し、どこで崩れるか

等価性は、状態の更新が現在の状態と現在のトークンだけで決まることへの帰納法で示される。文脈と質問を連結して処理することは、文脈で得た状態から質問を処理することと定義上同じになる。注意機構ではキーが位置回転を含むためこの性質が成り立たず、事前計算したキャッシュは別の位置では使えない。ここで重要なのは、等価であることと覚えていられることは別だという点である。状態への各トークンの寄与は、その後のトークンによる減衰の積で弱まるため、断片の冒頭の情報は指数的に薄れる。論文はこの実効的な記憶長を測り、対象モデルでは末尾から約256トークン以内の寄与が支配的だと述べる。注入はこの忘却をそのまま引き継ぐので、長い断片では文脈内検索より不利になる場面が出る。追加資源は不要だが、失敗条件は明確で、答えが断片の冒頭にある長い文書では品質が下がる。対策は断片を短く分割することであり、論文の標準設定512トークンはこの射程の内側に収まるよう選ばれている。

### 3. 階層型の永続メモリ統合 — 蓄積する履歴を有界な状態へ畳む

文書検索が静的な集合を対象にするのに対し、この機構は利用とともに増える会話履歴を対象にする。観測するのは時刻や話者などの付随情報を持つ会話断片であり、まず文章埋め込みと領域の代表ベクトルの類似度で、感情・時間・社会・空間・事実という5つの認知領域のいずれかへ振り分け、次に領域内の小クラスタへ振り分ける。保持状態は2種類ある。具体的な出来事を正確に思い出す必要があるクラスタでは中間状態まで含めた軌跡を残し、繰り返し現れる文脈を扱うクラスタでは最終状態だけを残す。保持する状態の数を決める整数パラメータが忠実度と容量の調整つまみであり、全保持なら断片あたり約96メガバイト、最終状態だけなら192キロバイトになる。長期の意味状態は小クラスタごとに1つだけ持ち、新しい断片の最終状態との指数移動平均で更新されるため、履歴がどれだけ増えても意味メモリ全体は4メガバイト未満に収まる。会話開始時は冒頭の発話から支配的な小クラスタを特定し、その意味状態を初期状態へ書き込む。これにより減るボトルネックは、蓄積した履歴を毎回読み直す費用であり、会話開始は履歴長によらず約6ミリ秒で済む。失敗時の挙動として、どの小クラスタにも合わない断片は忘却候補として扱われ意味状態へ寄与しないため、分類を外れた出来事は長期記憶から抜け落ちる。また移動平均は古い情報を薄める方向に働くので、利用者の嗜好が変わった場合に古い嗜好が残る期間と、新しい嗜好への追随速度は平均の係数で決まる交換条件になる。

### 4. 検索時の統合 — 文書状態と履歴状態を同じ土台で混ぜる

質問時には、文書集合の索引と履歴側のエピソード保存の両方を並行に検索し、候補全体から上位を選び、類似度をソフトマックスで重みに変えて状態の平均を作る。さらに現在の会話の意味状態を土台として加える。こうして静的な知識と蓄積した文脈が、どちらもトークンとして読み直されることなく1つの初期状態へ畳まれる。ただしこの平均は等価性の対象外の近似であり、断片数を増やすほど無関係な状態の混入で品質が下がることが実験で確認されている。利得が最大になるのは複数文書の証拠が要る質問で、関係ない文書が混ざる条件では利得が消える。

## 評価

### まず見るところ

結論は、単一断片の注入が文脈内検索と品質でほぼ一致し、応答開始の遅延だけが約4500倍下がることである。品質の一致は証明の帰結として位置付けられ、実験はその検証である。速度の数字はプリフィル部分の比較であり、生成速度そのものは変わらない点に注意が要る。メモリ面では、断片あたりの保存量がキー・バリューキャッシュの約85分の1になる一方、文章そのものの保存よりは約200倍大きいという交換条件が明示されている。評価の強さとしては、品質は同一重み・同一精度での実測だが、対象は1つのモデルと質問応答系のデータセットに限られ、端末の電力はシミュレーションを含む。

結果の解釈で効くのは、主結果が単一断片で足りる質問を中心に測られている点である。複数文書が必要な質問と長い文書での結果は除去実験側にあり、そちらでは提案方式の不利も数値で出ている。

### 感度・スケーリング・ストレス条件

断片長への感度が最も重要で、600トークン未満では文脈内検索と差がないが、それを超えると差が単調に開き、2400トークン以上で15点差になる。断片数への感度は非単調で、複数文書の質問では3件が最適で10件では利得がほぼ消える。文書集合の規模については、状態保存なら約500万件まで消費者向け容量に収まるという見積もりが示される一方、文章保存との容量差約200倍は規模とともに効いてくる。

## 既存研究との差

従来の検索付き生成は、検索した文章をどう短く読むかを競ってきた。圧縮方式は読む量を減らすが読み込み自体は残り、キャッシュ再利用は接頭辞の共有がある場合に限られる。隠れ状態を保存して混ぜる先行研究は存在するが、状態の合成方法を学習させる訓練時の変更を前提としており、通常の学習をしたモデルへそのまま適用はできなかった。本論文の差は、注入が近似ではなく等価な再構成であることを示し、追加学習なしで使える形にしたこと、そして対象をデータセンターではなく読み込み遅延が支配的な端末に置き、永続メモリまで同じ土台で扱ったことにある。何を動かす研究かで言えば、先行研究が文章やキャッシュを動かすのに対し、本論文はモデルの内部状態そのものを保存・移動・初期化に使う。

## 限界・実装状況

- 等価性が成り立つのは単一断片の全層注入だけで、複数断片の合成と部分注入は近似であり品質低下が実測されている。
- 状態の記憶の射程が有限で、長い文書の冒頭の情報は失われる。長文への適用には射程の長い基盤モデルか断片分割の工夫が要る。
- 保存容量は文章保存の約200倍であり、遅延ではなく容量が制約になる環境では通常の検索の方が合理的である。
- 端末の数値は試作と電力シミュレーションに基づき、実際のチップでの検証は今後の課題とされる。
- 公式コードの公開は一次資料で確認できず、対象モデルも著者所属の環境に依存するため、第三者による再現は容易ではない。
- 特許出願が関連技術として言及されており、利用条件は論文だけでは判断できない。

## 一般的な実装上の含意

推論基盤の設計では、再利用したい文脈表現が位置に依存しないかどうかを最初に確認する価値がある。位置依存の表現は接頭辞共有のような限られた再利用しか許さないが、位置非依存の固定長状態は保存・検索・初期化という一般的なデータベース操作の対象になる。あわせて、等価な再構成と近似の合成を混同しないことが重要である。正確さが保証される範囲を定理や測定で切り分け、その範囲の外では品質低下を数値で示す進め方は、キャッシュや状態の再利用を扱う他の基盤でもそのまま使える。また容量と遅延の交換条件は環境で逆転するため、どちらが拘束条件かを利用場面ごとに判定してから方式を選ぶべきである。
