# Unified Normalization for Accelerating and Stabilizing Transformers

> UNはTransformerのoffline normalizationを、activation/gradient統計の平滑化とadaptive outlier除去で安定化し、固定統計を線形層へ融合してSwin-Tで31.2% throughput向上を示す。

## 概要

層正規化（Layer Normalization; LN）はTransformerの各tokenについて、そのhidden dimension内の平均と分散をその場で計算し、activationを正規化する。Batch sizeに依存せず安定して使えるためTransformerの標準部品になった一方、推論時にもtokenごとのreduction、平方根、除算が必要になる。GEMMのような大きな線形演算と比べると演算量自体は小さくても、別kernel・memory traffic・synchronizationを発生させやすく、完全なlinear-layer fusionが難しい。

Batch Normalization（BN）のように学習中に統計を蓄積し、推論時は固定した平均・分散だけを使えれば、normalizationはaffine transformとして前後のlinear operationへ畳み込める。しかしTransformerへ単純なBN型offline normalizationを持ち込むと、精度低下だけでなく学習が発散する場合がある。

Unified Normalization（UN）の中心は「LNの代わりに別の式を使う」ことより、**Transformerでoffline statisticsがなぜ壊れるかを分析し、その統計を学習中に安定して推定すること**にある。論文は二つの異常を観測する。第一はactivation/gradient statisticsがiteration間で大きく揺れること、第二は深いlayerほど極端なoutlier statisticsが現れることだ。

UNはこの二つへ、(1) 変動平滑化（fluctuation smoothing）と、(2) 適応的外れ値除去（adaptive outlier filtration）を導入する。Forward側のactivation statisticsはwindow内の幾何平均（Geometric Mean; GM）で平滑化し、backward側ではgradient statisticsへ算術平均（Arithmetic Mean; AM）とmomentumを組み合わせる。さらに現在の統計が過去windowから見て極端ならmoving statistics更新から外し、異常値が後続iterationへ伝播するのを防ぐ。

学習後は固定したstatisticsを使えるため、UN normalizationをlinear operationへ融合できる。RTX 3090でSwin-Tを評価すると、ImageNetでは最大allocated memoryが9978 MBから8213 MBへ17.7%減り、throughputは1179.5から1547.8 images/sへ31.2%向上する。COCOのMask R-CNNではbackbone以外の処理が残るため、memory -6.1%、throughput +24.2%と改善幅は小さくなる。

## 問題設定

### LNはなぜhardware上で「小さいが消しにくい」処理なのか

LNは入力vector (x) について平均 (mu) と分散 (sigma^2) を計算し、

`y = gamma * (x - mu) / sqrt(sigma^2 + eps) + beta`

を実行する。ここで (mu) と (sigma) は入力tokenごとに変わるため、推論前にweightへ畳み込めない。

つまりGEMMの前後で、hidden dimensionを横断するreductionを実行し、その結果が出るまで次のnormalization計算を待つ必要がある。平方根と除算も含むため、単純なelement-wise scale/biasよりhardware-friendlyではない。

固定statisticsを使うoffline normalizationなら、

`y = a * x + b`

の形へ変形でき、(a,b) を前後のlinear weight/biasへmergeできる。推論時にnormalization kernelそのものを消せるのが速度上の狙いである。

### なぜBN型moving averageをそのままTransformerへ使えないのか

CNNではbatch statisticsをmoving averageしてinference時の固定値にする方法がよく使われる。しかしTransformerではactivation statisticsがiterationごとに大きく変動し、単純なexponential moving averageが不安定な値を追い続ける。

さらに深いlayerでは、ごく一部iterationでstandard deviation等が極端に大きくなるoutlierが観測される。この値をmoving statisticsへ混ぜると、そのiterationだけでなく以後のnormalization scaleも崩し、gradientの爆発・消失やtraining collapseへつながる。

UNはしたがって「offline statisticsを使う」こと自体ではなく、**offline statisticsを壊さず推定する仕組み**を主な学習時機構として持つ。

## 手法

### 1. Forward fluctuation smoothing — activation統計を幾何平均で平滑化する

各iterationで得られるactivation statisticsをそのままrunning valueへ入れるのではなく、直近 (M) stepのwindowを保持する。

Activation側では幾何平均（Geometric Mean; GM）を使って変動を平滑化する。極端なscale差があるstatisticsを単純な算術平均だけで追うより、multiplicativeな変化をならしやすい。

入力は現在stepと過去windowのactivation statistics、出力は推論時に使える安定したrunning statisticsである。Window (M) は大き過ぎると古いdistributionを引きずり、小さ過ぎるとiteration noiseを十分に消せない。COCOでは (M=2,4,6,8) の範囲でほぼ同等のAPを保ち、(M=10)でわずかな低下が見られる。

### 2. Backward fluctuation smoothing — gradient統計は算術平均＋momentumで追う

Offline normalizationを安定にtrainするにはforward activationだけでなく、normalizationを通るgradientのscaleも重要になる。

UNはbackward側で直近gradient statisticsを算術平均（Arithmetic Mean; AM）し、さらにmomentum (alpha) を使って更新するcompound moving strategyを採用する。AblationではAMまたはmomentumを外すと性能が落ち、両方を外す設定ではIWSLT14 trainingが収束しない。

Momentum感度では (alpha=0.7,0.8,0.9) はIWSLT14で同程度のBLEUを保つが、(alpha=0.6) はFAILになる。一方COCOでは0.6〜0.9の範囲でAP変化が小さく、**安定性に必要なmomentum強度はtask依存**であることも示している。

### 3. Adaptive outlier filtration — 深いlayerの異常statisticsをrunning値へ混ぜない

Window内statisticsのvarianceが大きいとき、現在値が通常の変動範囲から外れたoutlierである可能性が高い。

論文は算術平均と幾何平均の差をvarianceで上からboundできる関係を使い、過去windowのvarianceからadaptive thresholdを作る。現在statisticsがそのthresholdを超えるoutlierと判断された場合、そのstepのmoving-average更新をdropする。

固定thresholdではlayerごと・training phaseごとのscale差へ対応しにくい。Varianceベースなら深いlayerで変動が大きくなる状況に合わせてthresholdも変化する。

効果は強い。Outlier filtrationを外すablationではT2T-ViT-14 ImageNet、Faster R-CNN、Mask R-CNNなど複数設定がFAILし、Swin-T ImageNetも81.0%から80.7%へ下がる。これはoutlier処理が単なる微調整ではなく、offline Transformer normalizationの収束を支える主要機構であることを示す。

### 4. Inference fusion — 固定statisticsをlinear layerへ畳み込む

Trainingが終わるとUNのactivation statisticsは固定される。するとnormalizationは入力依存のmean/variance計算ではなく、channelごとのscale/shiftとして扱える。

このaffine transformを隣接するlinear projectionへmergeすれば、inference graphから独立したUN kernelを取り除ける。LNで必要だったper-token mean/variance reduction、sqrt、divisionを実行しなくてよい。

したがってUNのtraining-time machineryは推論時には残らない。Runtime speedupは「平滑化を高速に実行した」からではなく、**平滑化によって固定statisticsを安全に学習できた結果、normalizationをoffline化・fusionできる**ことから生じる。

## 評価

### 代表的な評価範囲

| 分野 | Model / task | 主な比較 |
|---|---|---|
| Neural machine translation | Transformer / IWSLT14 | LN、RMSNorm、PowerNorm系、offline norm |
| Image classification | T2T-ViT-14、Swin-T / ImageNet、CIFAR | LN、BN、MABN、PowerNorm |
| Detection / segmentation | Swin-T backbone + Faster/Mask R-CNN / COCO | LN、BN、MABN、PowerNorm |
| 実機効率 | Swin-T / RTX 3090 | LN vs fused UN |

UNの主張は「LLM decode専用kernel」ではなく、Transformer全般でLNをoffline/fusable normalizationへ置き換えられることにある。そのため評価もNLPとvisionを跨ぐ。

### 実機効率

| Task | Method | Max allocated memory | Throughput | 改善 |
|---|---|---:|---:|---:|
| ImageNet、batch 512 | LN | 9978 MB | 1179.5 img/s | — |
| ImageNet、batch 512 | UN | 8213 MB | 1547.8 img/s | memory -17.7%、throughput +31.2% |
| COCO、Mask R-CNN、batch 2 | LN | 955 MB | 17.8 img/s | — |
| COCO、Mask R-CNN、batch 2 | UN | 897 MB | 22.1 img/s | memory -6.1%、throughput +24.2% |

Throughputは1000 batch平均、GPUはGeForce RTX 3090で測定される。COCOで改善が小さい理由として、LNを置換できるのはSwin-T backbone側であり、FPNやdetection head等の時間はそのまま残ると論文は説明する。

### 品質とtraining stability

Swin-T ImageNetではBNがLNよりtop-1を0.5 point落とす一方、UNは81.0%まで回復する。COCO Mask R-CNNではLNのbox AP 46.0 / mask AP 41.6に対しUNは45.6 / 41.4で、差は-0.4 / -0.2 pointに留まる。

Outlier filtrationの有無では差がより明確である。

| 条件 | T2T-ViT-14 ImageNet | Swin-T ImageNet | Faster R-CNN box AP | Mask R-CNN box/mask AP |
|---|---:|---:|---:|---:|
| UN w/ filtration | 80.9 | 81.0 | 42.2 | 42.8 / 39.2 |
| w/o filtration | FAIL | 80.7 | FAIL | FAIL / FAIL |

つまりspeedupだけを見ると「固定statisticsへ変えればよい」と思えるが、その単純置換がtraining collapseするため、fluctuation smoothingとoutlier filtrationが必要になる。

### Component ablation

COCO Mask R-CNNではforward側GM、backward側AM、momentum (alpha) を一つずつ外すとbox/mask APが低下する。IWSLT14ではbackwardのmoving strategyをすべて外すと収束しない。

Window size (M) は2〜8で比較的robustだが、momentum (alpha) はNMTで0.6まで下げるとFAILする。UNは完全hyperparameter-freeではなく、taskにより安定領域が異なる。

## 既存研究との差

RMSNormはLNのmean subtractionを省くなど式を簡略化するが、入力依存のnormalization statisticsを推論時にも計算するonline normalizationである。そのためaccuracyを保ちやすい一方、UNが狙う「固定statisticsをlinear layerへ完全融合する」利点は得にくい。

Batch Normalizationやmoving-average型offline normはinference fusionには向くが、Transformerのactivation/gradient fluctuationsと深層outlierへ弱く、training instabilityが起こる。

UNはこの二者の中間を狙い、**training時にはTransformer固有のstatistics変動へ適応し、inference時にはBN型の固定statisticsとして消せる**ようにする。

## 限界・実装状況

本論文は2022年のTransformerを対象にしており、主な実機speedupはSwin-T/RTX 3090で測られている。現在のLLMで主流のRMSNorm、FlashAttention、fused MLP、tensor parallelismを組み合わせたdecoder-only servingで同じ31%が得られることを直接示した結果ではない。

またoffline statisticsはtraining distributionから推定するため、入力distribution shiftに対してper-token統計を毎回計算するLNより頑健とは限らない。論文はNLP/CV task間のgeneralizationを示すが、長文脈LLMのactivation driftは別途検証が必要である。

Training側ではoutlier filtrationやmoving statisticsが必要で、momentum設定を誤ると一部taskでcollapseする。既存pretrained LN modelへtraining-freeで差し替える手法でもない。

論文は公式repository URLを提示しているが、導入にはmodelをUN構成で学習またはfine-tuneし、inference graphでlinear fusionを行う実装が必要になる。

## 一般的な実装上の含意

Transformer inferenceで「FLOPsが小さいoperation」は必ずしも無視できない。Reductionやsqrt/divisionのようにGEMMへfusionしにくいoperationは、kernel launch・memory traffic・synchronizationのため実時間で目立つことがある。

一方、そのoperationをoffline化するには、training時に入力依存性を安全に固定statisticsへ吸収できることが前提になる。UNは **runtime最適化を可能にするためのtraining-time stabilization** という設計パターンを示している。
