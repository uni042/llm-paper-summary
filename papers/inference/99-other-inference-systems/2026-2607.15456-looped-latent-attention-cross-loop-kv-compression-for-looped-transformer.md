# Looped Latent Attention：ループ型Transformerの反復軸KVキャッシュを低ランク圧縮する

## 概要

ループ型Transformerは、同じTransformerブロックを何度も適用することで、モデルの深さに相当する反復計算を少ない重みで実現する。重みは共有されるが、自己注意のキー・値（KV）キャッシュは反復ごとに別々に生成される。例えば24層を4回反復するモデルは、パラメータの格納量は24層相当でも、キャッシュは実質96層相当になる。長い文脈や多数の同時リクエストでは、モデル重みよりもリクエストごとに増加するKVがメモリを占め、重み共有の利点を打ち消す。

Looped Latent Attention（LLA）は、同じトークン・層・ヘッドに対応する複数反復のK/Vを、一つの低ランク潜在ベクトルとして保存する。注意計算で反復番号が決まったときだけ、その反復に対応する復元行列を適用してK/Vを取り出す。K/Vを単に最終反復の値へ置換するのではなく、反復に沿った短い軌跡を表現することが本質である。元の教師モデルの重みと注意演算を保ったまま、キャッシュの表現だけを交換する設計になっている。

Ouro-1.4Bを用いた同一キャッシュ容量比較では、4倍圧縮のLLAはGSM8K厳密正解率0.800を記録し、教師の0.794とほぼ同等だった。ヘッド軸を圧縮する方式は0.522、層軸共有は0.660、KV量子化は0.702、最終反復だけを再利用する方式は0.000だった（原著表1）。一方、別プロトコルの低ランク数探索では4倍圧縮時のGSM8Kは0.590に下がり、表ごとの評価経路・対象数を混同してはならない。

単一H200・文脈4096の容量試験では、Ouro-1.4Bの最大バッチは非圧縮32から4倍圧縮で128、21.3倍圧縮で768へ増加した。ただし実際に潜在ベクトルだけを保存する経路は、読み出しのたびにK/Vを再構成するため計算律速であり、ピーク生成速度は非圧縮748 token/sに対し108 token/sへ低下した。したがって本研究の確立した実装上の利点は**メモリと同時処理容量**であり、同じ条件で生成処理が高速化するという主張ではない。

## 問題設定と既存研究との差

### 重み共有とKVキャッシュ非共有の非対称性

通常のTransformerでは、層ごとに異なる注意射影を持ち、各層のKVを次トークンの計算に再利用する。ループ型モデルでは一組の層を繰り返し適用するため、同じ重みから反復番号ごとに異なる隠れ状態とKVが作られる。反復をT回、共有ブロックの層数をD、ヘッド数をH、各ヘッドの次元をdとすると、各トークン・層の従来KV保存量は2THd個のスカラーとなる。重みの共有だけではT倍のKV保存負担を減らせない。

既存の多頭潜在注意（MLA）は主としてヘッド・チャネル方向、層間共有は層方向、KV量子化は数値精度方向、トークン追い出しは系列方向を圧縮する。LLAはこれらと異なり、ループ型モデルに特有の**反復方向**を対象とする。どの軸が本当に低ランクかは、同じ圧縮率にそろえて比較しなければ判定できない。著者らは凍結した教師のK/Vを反復・ヘッド・層の各軸に並べて特異値分布を比較し、反復軸の規格化有効ランクがOuro系列で約0.61～0.63と低いことを観測した。ヘッド・層軸は相対的に平坦である。

反復が進むほど内部状態が一定値に近づくことは、全反復のKVを同一値へ置換してよいことを意味しない。最終反復KVをすべての反復で再利用する対照方式は、4倍のメモリ削減を実現する一方、GSM8K生成の正解率がゼロになった。途中反復の小さな差が次の注意計算へ作用し、生成されるトークンの違いへ増幅されるためである。LLAはその差分を単一の固定点ではなく低ランク軌跡として保存する。

### 対象とする最適化範囲

本手法は任意の通常Transformerへそのまま適用できる一般的KV圧縮器ではない。複数反復で同じブロックと射影を使う構造が前提である。学習済みの重みを凍結し、事後的に圧縮器を追加する点では導入可能性があるが、圧縮器の校正と蒸留、注意時の復元計算、長文生成での再調整が必要になる。圧縮率はメモリ上のスカラー数を基準にした理論上厳密な比率であり、ランタイムの割当粒度、固定の復元行列、カーネル実装を含む総GPUメモリ使用量や速度の同倍率削減を意味しない。

## 手法

### 反復別KVの行列化と潜在表現

LLAは各層・各ヘッド・各トークンについて、反復1からTまでのKベクトルを縦に連結した長さTdのベクトルを作る。Vについても別に同じ処理を行う。教師モデルの校正データから反復別平均μを求め、中心化したベクトルを低ランク射影W_downへ通して潜在表現cを得る。注意計算時には、その時点の反復番号tに対応するW_up,tを使ってK_tまたはV_tを再構成し、平均μ_tを戻す。

この設計では、保存する潜在ベクトルはトークン・層・ヘッドごとに一つで済む。反復ごとに別の復元行列を持つため、同じ潜在から各反復の異なるKVを再現できる。KとVは別の潜在と射影を持ち、次元をr_kとr_vとする。論文のスペクトル観測ではVの反復間変化がKより遅く収束するため、r_vをr_kより大きく割り当てる。例えば4倍圧縮の構成はr_k=96、r_v=160であり、両者を128ずつにする同容量設計より誤差が小さかった。

キャッシュに保存するスカラー数は従来の2THdから(r_k+r_v)Hへ変わり、圧縮率はρ=2Td/(r_k+r_v)となる。復元行列はトークンやリクエスト間で共有される固定パラメータで、長文脈ほど増加するリクエスト固有キャッシュとは分けて数える必要がある。さらに極端な圧縮向けのLLA-2Dはヘッド軸も一つの潜在に折り込み、(r_k+r_v)個だけを保存するが、射影の入力次元がTHdに増えるため、反復数の多いHuginnでは復元行列のパラメータ負担が問題になる。

### 位置符号化と注意への接続

元のモデルが回転位置埋め込み（RoPE）を用いる場合、LLAは位置回転前の内容キーを圧縮し、復元後にRoPEを適用する。同じトークン位置は各反復で共通なので、反復ごとの位置位相を別々に学習しなくてよい。復元したK/Vは通常の多頭注意へ渡し、注意の結果が次の反復の隠れ状態へ進む。したがって、反復計算自体を間引くのではなく、各反復が読む過去KVの保持形式を変更する。

この区別は性能上重要である。実装には、再構成したフルKVを保持する経路と、潜在だけを保持して読み出し時に復元する経路がある。前者は元の注意カーネルを使いやすいが、復元済みKVを保持する限り圧縮メモリ利得が実現しない。後者は保存量を減らす一方、過去トークンを読むたびに復元計算が必要となる。論文の容量試験と高速経路の遅延試験は、この二つを明示的に区別している。

### SVD初期化、教師蒸留、注意出力の照合

圧縮器の初期化では、校正データで観測した教師KVを反復方向に積み、中心化した行列の特異値分解（SVD）から上位r方向を取り出す。これをW_downの初期値にし、対応する反復別の切片をW_up,tへ設定する。ランダム初期化より、実際に教師が訪れる低ランク軌跡に近いところから学習を始められる。

初期化後は教師本体を凍結し、圧縮後モデルのトークン分布と教師の分布のKL距離、および各層・反復の注意出力の二乗誤差を組み合わせて圧縮器だけを更新する。注意出力項の重みはλ=0.5である。後段のトークン分布だけでなく、中間注意の再現も直接制約することが、長い反復連鎖でのずれを抑える狙いである。原著の4倍圧縮・300ステップ構成要素除去実験では、SVD初期化の保持データKLは0.105、ランダム初期化は0.771であり、初期値の寄与が最も大きかった。K/Vを等ランクにすると0.129、注意出力項を外すと0.110となった。

標準の変換学習は3,000ステップ、バッチ8、系列長512、AdamW、学習率10^-3、100ステップのウォームアップと減衰を使用する。比較用の各圧縮軸も同じ学習手順を使い、軸の選択以外の条件をできるだけ合わせている。最良KLのチェックポイントを採用するため、最終ステップのモデルだけを機械的に比較してはいない。

### 長文生成のためのオンポリシー再調整

教師の正解prefixを与えて圧縮器を学習しても、実際の自己回帰生成では圧縮モデル自身が直前に生成したトークンを次の入力にする。序盤の小さなKV復元誤差で生成が分岐すると、その後のprefixは教師データで学習した状態分布から外れる。MATH-500の長い推論では、この分布ずれが正答率低下や最終回答のない長い生成として現れる。

LLAの追加段階では、圧縮モデルが自分で生成したprefixを教師に再入力し、そのprefixに条件付けた教師分布と圧縮モデルの分布のKLを小さくする。生成サンプリングには勾配を流さず、教師は凍結したまま、圧縮器のパラメータだけを更新する。正答した生成だけを選ぶ強化学習や報酬最適化ではなく、実運用で訪れる状態に対する教師蒸留である。これにより、情報がまだ潜在に残る中程度の圧縮では、長い生成に特有の誤差増幅を減らせる。ただし潜在次元を削り過ぎて失った情報は、この追加学習では回復できない。

### モデル規模と別系統への転移（原著表2・3）

Ouro-2.6B-Thinkingでは、4倍圧縮のGSM8KはLLA 0.834、ヘッド軸0.585、LLA-2D 0.660、KV量子化0.814であった。10.67倍でもLLA 0.821、ヘッド軸0.775、LLA-2D 0.820となり、教師の約0.83を維持した。規模を大きくしても、反復軸が有利という傾向は保たれる。ただしLLA-2Dは圧縮率によって差が縮まり、単一モデル・単一ベンチマークで全条件の優劣を断定しない。

Huginn-3.5Bでは32反復という異なる構造へ転移した。ここでは教師強制入力に対するKLとtop-1一致を主に評価しており、Ouroと同じ長文生成の正解率を直接比較していない。SVDだけのLLAは16倍でKL 0.005・top-1一致0.970、32倍でKL 0.010・top-1一致0.954を記録した。64倍ではSVDのKL 0.197が蒸留で0.145、128倍では0.763が0.177へ改善した。極端な圧縮には蒸留が効くが、32倍までの近似忠実性と64～128倍の追加学習後の結果は分けて評価すべきである。

### 文脈長に対する検索品質（原著図8・表12）

5桁の鍵を埋め込んだ正確な検索課題では、Ouro-1.4Bの回収率0.9以上を保つ最長文脈が、圧縮5.33倍以下で64k以上、10.67倍で16k、14.2倍で8kへ短縮した。15.5倍以上では短い文脈でも完全回収できず、圧縮そのものが鍵トークンの識別情報を失わせる。長文での劣化を「一般に長文脈が苦手」とまとめるのではなく、文脈長が閾値を越えたときだけ落ちる条件と、どの長さでも落ちる条件を区別できる。

2.6Bでは同じ10.67倍圧縮でも32kまで完全回収でき、1.4Bの同条件より余裕がある。一方、2.6Bの64k測定ではprefillメモリ不足（OOM）となったセルがあり、正答率ゼロと扱ってはならない。ここでの指標は人工的な鍵回収であり、現実の長文検索や多段推論を全面的に保証するものではない。

|---|---:|---:|---:|
| Ouro-1.4BのKV/トークン（原著表記） | 768 KiB | 192 KiB | 36 KiB |
| 1M文脈の1.4B KV | 768 GiB | 192 GiB | 36 GiB |
| H200・4k文脈での最大バッチ（1.4B） | 32 | 128 | 768 |
| H200・4k文脈での最大バッチ（2.6B） | 16 | 64 | 未測定 |
| フルKV保持の高速経路のdecode遅延 | 63.6 ms/token | 74.1 ms/token | 未測定 |
| 潜在のみ保持する容量経路のピークdecode処理量 | 748 token/s | 未測定 | 108 token/s |

容量経路ではメモリ削減が正確にバッチ上限へ反映される。1.4Bで32から768への増加は24倍のバッチ容量だが、これは処理速度が24倍という意味ではない。復元済みフルKVを持つ高速経路では4倍圧縮器を使っても実際のキャッシュは元の大きさに近く、遅延も63.6から74.1 ms/tokenへ悪化する。潜在のみ保持する経路は圧縮の利点を得る一方、復元計算が律速でピーク生成速度が748から108 token/sへ低下する。原著は両者の測定条件を分けているため、メモリと速度を同時に改善した実証と誤読しない。

著者らは注意計算のキー射影をクエリ側へ移し、潜在へ直接注意する吸収型経路も検討した。形状をそろえたランダム重みの262k文脈マイクロベンチマークでは、復元後に注意する方式より2.3倍速い。しかし事後的なRoPE分離で元の注意出力が再現しにくく、学習済みモデルのKLはクエリ適応を加えても0.34で、完全RoPE再構成の0.059には及ばない。この実験は高速な計算経路の可能性を示すが、精度を維持した実モデルの総合高速化を実証したものではない。

## 限界と適用判断

第一に、反復方向の低ランク性は重み共有型の構造から生じるため、反復のない通常Transformerや異なるアーキテクチャへ無条件に一般化できない。検証は主にOuro系列とHuginn系列であり、さまざまな生成モデルや混合専門家構成への適用可能性は未検証である。特にヘッド軸までまとめるLLA-2Dは反復数が大きい場合に復元行列が巨大になり、潜在保存量だけを見て実装を選べない。

第二に、圧縮比率はキャッシュのスカラー数を厳密に減らすが、総GPUメモリ・エンドツーエンド遅延・消費電力の改善を保証しない。潜在をそのまま読む高速注意カーネルと、元モデルの位置符号化を両立する方法が未完成である。実際の潜在保持経路はピーク生成速度が大幅に低下したため、メモリ不足で並列要求を載せられない運用と、単一要求の低遅延を求める運用で採否が変わる。

第三に、長文生成では教師強制のKLが低くても回答が逸脱する。自モデルの生成prefixを使う再蒸留は3.2～5.33倍圧縮で有効だが、21.33倍では正解率を改善しない。長文の正確な検索では、圧縮を強めるほど許容文脈長が短くなる。容量を優先して極端な圧縮を選ぶ場合、長文の数学推論や鍵情報の保持が必要なサービスには個別の品質ゲートが要る。

第四に、原著の比較はモデルと評価経路の組合せに依存する。表1の同容量GSM8Kと表8のcold-start探索は異なる標本・再構成経路を用いる。Huginnの主な結果は教師入力上の分布一致であり、実際の自己回帰長文生成の正答率とは同義ではない。GPU容量試験はキャッシュを人工的に構築してOOMまでバッチを増やしたもので、到着トレース、SLO制約、複数テナントの待ち行列を含む実サービスのスループットではない。

それでも本論文は、重み共有によるパラメータ削減がKV削減を伴わないという特有の盲点を明確化し、圧縮すべき軸の選択を教師KVの特異値構造と同容量比較で裏付けている。KVを削るだけでなく、反復ごとの意味的差異を保つ必要があること、圧縮後の長文生成に別の学習分布が必要になること、容量利得と復元計算費用を分けることが、推論システム研究としての主な意義である。
