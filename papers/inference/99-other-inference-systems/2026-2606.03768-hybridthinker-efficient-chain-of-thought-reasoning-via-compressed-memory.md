# HybridThinker：圧縮記憶と直近の生思考を併用するKVキャッシュ管理

## 概要

長い思考連鎖を出力する言語モデルでは、過去の推論過程もトークン列として残るため、自己注意の計算とKVキャッシュ容量が増加する。LightThinkerのような方式は、各思考段階を少数の記憶トークンへ圧縮して、元の思考トークンのKVを即座に削除する。しかし、直前に計算した数値、制約、条件分岐などの細かな情報が圧縮表現だけでは取り出しにくくなり、次の段階で誤りを生じることがある。

HybridThinkerは「すべて残す」と「圧縮後すぐ消す」の中間を採る。各思考段階を記憶トークンへ圧縮しつつ、直近の数段階に限り生の思考ステップのKVも保持する。時間が経過した生ステップだけを削除し、古い推論情報は記憶トークン経由で参照する。さらに、学習時に生ステップが常に見えているとモデルが記憶トークンを学ばなくなる問題を、注意マスクの混合で解決する。

## 問題設定

思考連鎖をS1、S2、…、Skとし、質問文のKVをQ、段階Stの生のKVをS̃t、圧縮用の固定長記憶トークン列Mから得るKVをM̃tと表す。通常の非圧縮推論ではQと全S̃を保持し、段階が進むほどキャッシュは増える。既存の段階圧縮では各M̃tのみを残すため容量を抑えられるが、S̃tにしかない細かな情報が直後の計算で失われる。

必要な情報には時間的な局所性がある。直前の式の変数や補助計算は次の数段階で特に参照されやすく、さらに古い経緯は短い記憶表現でも十分な場合がある。この観察に基づき、生のKVの保持期限を思考段階数wで指定する。wを増やせば詳細を利用できる期間は延びるが、ピーク容量も増える。したがって、精度と容量の交換条件を段階単位で制御する。

## 手法

### 1. 推論時の三段階処理

時刻tの思考段階Stを生成するとき、モデルは質問のKV、全過去段階の記憶KV、直近w−1段階の生KVを参照する。段階を生成し終えたら、新しい固定長の記憶トークンMを一回前向き計算し、Stの内容をM̃tへ圧縮する。最後にStとM̃tをキャッシュへ追加し、期限を過ぎた生のS̃t−w+1を削除する。質問KVとすべてのM̃は最後まで残すため、古い情報への参照経路は維持される。

この操作は過去の文章を再生成する方式ではない。削除した生の思考ステップを再読するのではなく、圧縮時に生成したKV表現を保存する。圧縮処理自体には追加の前向き計算が必要であり、圧縮トークン数と保持期限によって追加費用が変わる。推論時に使う注意マスクは、質問・記憶トークンを全段階から参照可能にし、生ステップは保持期間内の段階だけに可視化する。

### 2. 学習時の近道問題

推論時の可視性をそのまま教師強制学習に適用すると、記憶トークンと生の思考ステップが同時に見える。生の文章は情報を直接持つため、モデルは圧縮表現を介さず生ステップから必要情報を読む。結果として、記憶トークンへの圧縮・検索経路に十分な学習信号が流れず、保持期限が切れた後の推論が不安定になる。これが論文の近道学習（shortcut learning）である。

逆に、学習時に生ステップを完全に隠すボトルネック注意（Bottleneck Attention）だけを使えば、記憶トークンの圧縮能力は学べるが、推論時に有効な生ステップの直接参照経路を学べない。学習と推論の注意パターンが異なり、直近情報を活用する利点を失う。

### 3. 混合注意による二経路の学習

提案する混合注意（Hybrid Attention）は、学習系列中の思考段階を無作為に二つの集合へ分ける。一方では生ステップを直後w−1段階まで参照できる短絡注意（Shortcut Attention）を適用し、もう一方では生ステップの参照を自段階とその記憶トークンのみに制限するボトルネック注意を適用する。質問と記憶トークンは両集合で参照可能にする。段階単位でマスクを混ぜることにより、同じ学習例の中で直接経路と圧縮経路の双方に予測損失が作用する。

学習目的は思考ステップの次トークン交差エントロピーであり、質問や記憶トークン自体は同じ目的関数の対象にしない。記憶トークンは後続思考の予測に寄与することで、役に立つ圧縮表現を獲得する。無作為なマスク分割により、特定の段階がいつも生のKVを利用できるという偏りを防ぐ。論文の式(5)が可視性、式(6)が学習損失を定義する。

### 4. キャッシュ容量の考え方

思考段階数がk、各段階の長さが概ねL、記憶トークン数がmなら、全保持はおおよそkL、即時圧縮はkm、HybridThinkerはkmに直近w段階の生トークンを加えた量が主要項となる。実際の段階長は一定ではなく、表のPeakは実測の最大保持トークン数である。固定のKV予算へ切り詰めるH2O等とは異なり、記憶表現を生成し続けるため、kが無制限に増えれば記憶トークンも増える。従って「長さに依存しない定数メモリ」とは言えない。

## 評価

### 条件と比較対象

| 項目 | 一次論文の条件 | 解釈 |
|---|---|---|
| 基盤モデル | Qwen2.5-7B、Llama3.1-8B | 2モデルで確認 |
| 追加学習 | Distill-R1系から初期化しBespoke-Stratos-17kを利用 | 未学習の既存モデルへそのまま適用する手法ではない |
| 課題 | GSM8K、MMLU、GPQA、BBH | 数学・知識・複雑な推論を混合 |
| 比較 | CoT、Distill-R1、Vanilla、LightThinker、H2O、SepLLM | 追加学習方式と無学習KV削減を区別 |
| 指標 | 4課題平均正答率、全サンプル推論時間、ピークKV保持トークン数 | トークン数だけで速度を推定しない |
| 主な比較対象 | 同じ追加学習条件の非圧縮Vanilla、即時圧縮LightThinker | 圧縮・保持期限の効果を評価 |

### Qwen2.5-7Bでの主要結果

原著表1では、追加学習した非圧縮Vanillaの4課題平均正答率は68.78%、推論時間21.54、ピークKVトークン数3299である。LightThinkerは62.94%、17.45、1115、HybridThinkerは68.78%、17.15、1264となる。HybridThinkerはVanillaと同じ平均正答率で、ピーク保持トークン数を約61.7%、推論時間を約20.4%減らす。一方LightThinkerよりピークKVは149トークン多い。精度改善は「同じ容量での改善」ではなく、少量の生KVを追加保持する交換条件の上に成立している。

GPQAではLightThinkerの37.37%に対してHybridThinkerは47.98%と大きく改善するが、MMLUでは60.66%から63.39%、BBHでは66.46%から73.13%と改善幅が異なる。GSM8Kでは87.26%から90.60%である。四課題の平均改善は約5.8ポイントで、これはQwen2.5-7B系列におけるLightThinkerとの差である。

### Llama3.1-8Bでの主要結果

Llama3.1-8Bでは、Vanillaの平均68.99%、推論時間27.32、ピーク3460に対してHybridThinkerは66.98%、20.83、1233である。平均正答率は非圧縮基準に約2.0ポイント届かない一方、保持トークン数は約64.4%少ない。LightThinkerの64.25%、22.12、1132と比較すると、正答率は2.73ポイント改善し、推論時間は短く、ピーク保持トークン数は101多い。モデルを変えると「非圧縮と完全同等」という結論は成立しない。

### 混合注意の除去実験

原著表2のQwen2.5-7Bで、同じ一時保持推論を使いながら学習マスクだけを変更すると、混合注意は平均68.78%、時間17.15、ピーク1264、短絡注意のみは66.87%、25.14、1836、ボトルネック注意のみは57.67%、18.00、1324である。生ステップを学習中に常時見せると、圧縮記憶の能力が弱まり、結果として長い出力や高い保持容量を招く。逆に生ステップを一切見せないと、推論時の直接参照経路が十分に学習されず品質が大きく下がる。混合注意は二つの極端な設定より高い精度と効率を示す。

### 時間とメモリの注意点

表のTimeは各課題のサンプル全体の推論時間を集計した値であり、1トークンの固定遅延や本番サービングの秒当たりトークン数とは異なる。出力する思考トークン数が短くなれば、保持するKVがやや多くても全体の推論時間は短くなり得る。実際、HybridThinkerの短絡注意のみより速い結果は、圧縮経路の学習と不要な反復推論の抑制が寄与していると解釈できる。ただし、専用のPagedAttentionカーネルや多要求同時実行での性能は論文表から確定しない。

## 既存研究との差

H2OやSepLLMは既存KVの重要度を測って削除する。圧縮表現を学習して作るわけではないため、捨てた詳細情報は原則戻せない。LightThinkerは段階終了ごとに記憶トークンへ圧縮するが、元の生ステップを直ちに捨てる。HybridThinkerは古い情報を記憶へ残しながら直近の生KVを保持する点で異なり、さらにその二経路を学習時に意図的に切り替える。単なる「保持期間wの追加」だけでは、学習時の近道問題を解消できない。

本方式は入力プロンプトを事前に圧縮するLLMLingua等とも異なる。思考内容は生成されるまで分からないため、生成中に圧縮と削除を繰り返す必要がある。記憶トークンはモデル内部のKVであり、文章要約を別モデルへ問い合わせる外部記憶ではない。

### KVキャッシュを実装する際の境界条件

思考ステップの境界をトークン化したとき、段階Stを圧縮する記憶トークンMtのKVは、Stとその時点で有効なキャッシュを参照して計算する必要がある。圧縮が終わる前に生のStを削除すると、記憶トークンがStを見られなくなり、提案手法と異なる。圧縮後は古い生ステップだけを取り除き、質問KVとすべての記憶KVを保持する。位置符号化や注意マスクの更新が不整合だと、削除したはずのトークンが参照可能になったり、保持すべき記憶が見えなくなったりする。これらは論文式(2)と式(3)から直接導かれる実装上の不変条件である。

連続バッチ化された推論サーバーへ導入する場合は、要求ごとに思考段階の長さと境界が異なる。ある要求は短い段階を連続して圧縮し、別の要求は長い一段階を生成し続けるため、単一の固定トークン窓だけで削除時刻を管理できない。必要なのは要求別の段階番号と記憶トークン領域の追跡であり、ページ単位でKVを管理する実装では、ページ内に保持期限の異なる段階が混在する可能性にも注意する。論文はこのようなサービング統合の性能を実測していないため、ここでの説明は移植時の検証課題である。

### 精度・メモリ・速度を分離した読み方

HybridThinkerはLightThinkerより生KVを多く残すにもかかわらず、表1では推論時間が短い条件がある。これはKV容量が少ないほど必ず速いという単純な関係を否定する。長い思考の繰返しや誤った分岐を減らして出力トークン総数が短くなれば、各時刻の注意対象が増えても総時間は減り得る。ただし、どの割合が出力長の短縮によるもので、どの割合がカーネルの効率化によるものかは、原著の集計時間だけでは完全に分離できない。

容量の比較では、ピーク保持トークン数と実際のGPUメモリバイト数を同一視しない。後者はモデルの層数、KVヘッド数、ヘッド次元、精度、ページ断片化で変わる。Qwen2.5-7Bでの1264対3299という比率は同じモデル内のKV保持量を示すため有用だが、異なるモデル間の絶対メモリを比較する値ではない。FP16、FP8、低ビットKV量子化を併用する場合は、その実装条件を固定して再評価する必要がある。

## 限界

第一に、圧縮記憶の品質は追加学習の分布とモデル規模に依存する。評価は7Bと8Bの二系列、四つの推論ベンチマークであり、より大規模なMoEやコード生成、多ターンエージェントへ一般化できるとは限らない。質問と記憶トークンのKVは残るため、非常に長い思考連鎖での容量は一定にならない。

第二に、即時圧縮のLightThinkerよりピークKVは増える。Qwenで1264対1115、Llamaで1233対1132という差があり、絶対的な最小メモリを重視する環境では不利な場合がある。保持期間wの最適値は段階長やタスクの依存関係で変わり、固定wが常に最適とは言えない。

第三に、表の推論時間は単一の測定条件であり、GPU機種、カーネル、バッチ処理、連続バッチ化、CPU退避との組合せは十分に検証されていない。思考トークン数が短縮する効果と、各トークンの注意計算が速くなる効果は分ける必要がある。

第四に、非圧縮基準との精度差はモデル依存である。Qwenでは平均が同じでも、Llamaでは約2ポイント低下している。四課題の単純平均は個々の課題の難度や信頼区間を表さず、すべての質問で品質が保存される保証ではない。

第五に、学習時の混合注意は、思考ステップの区切りを認識してマスクを構築することを要求する。自然文に明確な区切りがない場合や、モデルが区切りを安定して生成しない場合には、圧縮と削除の時点を誤る可能性がある。実装ではKV位置、マスク、記憶トークンの対応を一貫させる必要がある。
