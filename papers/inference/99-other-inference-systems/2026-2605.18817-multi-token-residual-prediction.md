# Multi-Token Residual Prediction：拡散LMの隣接ステップ差分を利用する復号

## 概要

拡散言語モデルは、マスクされたトークン列を何度も予測し直して文章を生成する。複数トークンを同時に確定できるため並列性がある一方、一度に確定する数を増やすと、まだ周囲の文脈が確定していない位置で誤った予測を採用しやすくなる。品質を重視するとノイズ除去ステップ数が増え、大型モデルの実行回数が多くなる。

XuらはMulti-Token Residual Prediction（MRP）を提案する。隣接するノイズ除去ステップのlogit分布はかなり似ており、次ステップの分布を最初から計算する代わりに、その差分だけを軽量なTransformerで推定できるという観察に基づく。凍結した拡散言語モデルの隠れ状態と、部分的に確定したトークン列を入力し、次の状態との差分を予測する。

MRPには三つの運用がある。品質を維持する静的ノイズ除去では、MRPが複数トークンを先行提案し、大型モデルが検証することで1.17〜1.40倍のスループット改善を得る。検証を省いた直接生成ではさらに速くできるが、近似誤差による品質低下が残る。多数のトークンを一度に確定する動的ノイズ除去では、MRPの予測を使って誤って早く確定した位置を再びマスクし、低閾値での品質を回復する。ただし再マスクは追加計算を伴うため、同じ閾値の通常方式より遅くなることが多い。

## 問題設定

自己回帰モデルは過去のトークンが確定した順に次を生成するため、依存関係を守りやすいが逐次性が強い。拡散言語モデルはマスクされた複数位置を同時に予測し、確信度の高い位置から確定していく。固定個数rを確定する静的方式と、確信度が閾値τを超えた位置をすべて確定する動的方式がある。

静的方式は一度に少数のトークンを確定するため品質が良いが、大型モデルを何度も呼ぶ必要がある。動的方式は低い閾値で多くのトークンを確定できるため速いが、周囲の情報がまだ不確かな位置を誤って確定すると、その誤りが後続のノイズ除去に伝わる。品質と速度の交換条件を改善するには、次ステップで大型モデルがどう予測を変えるかを安く推定する必要がある。

MRPの着眼点は、隣接ステップのlogitと隠れ状態の差分が、元の状態そのものより小さいことである。SDAR-1.7B/4B/8BのGSM8Kで測ると、一つのトークンを確定した場合のlogit差分の大きさは元のlogitの約20%程度であり、ブロック全体16トークンを確定する場合でも差分は元の状態より小さい。この比較は差分が常に予測しやすいことの証明ではないが、小型モジュールで近似する動機を与える。

## 手法

### 残差予測モジュールの構造

凍結した大型モデルの隠れ状態と、既に一部が確定したトークン列の埋め込みを学習可能な射影で融合し、小型Transformerへ入力する。出力は次ステップのlogit全体ではなく、現在のlogitと次ステップのlogitの差分である。最終的な近似logitは「大型モデルの現在のlogit＋MRPの予測残差」として得る。

この構造はEAGLE系の小型予測ヘッドに似るが、出力の対象が次トークンの分布そのものではなく、隣接ノイズ除去ステップの補正である点が異なる。複数回MRPを適用する場合は、隠れ状態の残差とlogit残差を累積し、大型モデルを再実行せずに仮想的な次のノイズ除去ステップを進める。

### 凍結backboneを教師とする差分蒸留

学習では正解応答のトークンをランダムにマスクし、ノイズのある入力状態を作る。次にブロック内の正解トークンをr個だけ確定させた状態を作り、凍結した大型モデルを両方の状態で実行する。前者から得たlogitと後者から得たlogitの差分が教師信号となる。

MRPは前者の隠れ状態と部分的に確定した系列から残差を予測し、予測logitを現在のlogitへ足した分布が教師の次ステップ分布に近づくよう、まだマスクされている位置だけでKL損失を最小化する。大型モデルの重みと語彙ヘッド、トークン埋め込みは更新しない。原著の主設定ではMRPは3層、学習時は2回のMRP反復を展開し、温度1.0の順方向KLを使う。

学習データはOpenHermes-2.5、GenQA、Infinity-Instructを混ぜた約1,240万会話のSFTDatasetV3である。AdamWと余弦学習率スケジュールを用い、1エポックで学習する。モデルの元の大規模な事前学習をやり直すわけではないが、小型モジュールの蒸留学習には追加のデータ・計算が必要である。

### 静的方式その1：検証なしの直接生成

大型モデルが一度実行され、最も確信度の高いr位置を確定した後、MRPが次ステップの残差を予測する。補正logitからさらにr位置を確定し、この操作をK回繰り返す。大型モデルの実行回数を増やさずに複数ステップを進められるため、高いスループットを得やすい。

ただしMRPの残差は近似であり、反復回数Kを増やすほど誤差が蓄積する。大型モデルによる再検証をしないため、元の拡散モデルと同じ出力分布や品質を保証する方式ではない。速度と精度の交換を許容する運用である。

### 静的方式その2：検証付き投機的生成

MRPが候補トークンを複数回提案した後、大型モデルを使って候補を検証する。提案された位置の予測と大型モデルのargmaxが一致しない場合、その位置を再びマスクして確定を取り消す。これにより、検証なしの近似生成とは異なり、大型モデルの検証規則に従う品質維持型の加速を狙う。

原著の「lossless」はこの検証付きの方式についての主張であり、MRPを使うすべての運用で厳密に分布が保存されるという意味ではない。特に検証がargmax一致に基づくため、確率的サンプリングを含む任意の生成方式についての一般的な分布保存保証とは区別する必要がある。

### 動的方式：過剰な確定を取り消す再マスク

動的ノイズ除去では、確信度が閾値τを超えた多数の位置を一度に確定する。低いτは高速だが、まだ文脈が整っていない位置まで早く確定してしまう。MRPは次ステップの補正logitを推定し、先ほど確定したトークンの信頼度を再評価する。補正後の確信度が閾値に達しない位置は再マスクし、次の大型モデル実行で改めて予測させる。

この運用は直接生成と逆で、トークンを追加で確定するのではなく、一度確定したものを取り消す。低閾値での品質を戻すための処理であり、同じτの動的方式よりトークン確定数が減り、MRPの追加実行も必要になる。したがって、速度の利得ではなく、速い設定で失われた品質を回復することが主目的となる。

## 評価

### 実験条件

| 項目 | 条件 |
|---|---|
| 大型モデル | SDAR-Chat 1.7B、4B、8B |
| ブロック長 | 16トークン |
| MRP | 3層Transformer、凍結backboneへ追加 |
| 学習 | SFTDatasetV3、約1,240万会話、1エポック |
| 推論基盤 | SGLang、NVIDIA H100単体でスループット測定 |
| 数学 | GSM8K、MATH500、0-shot CoT |
| コード | HumanEval、MBPP |
| 静的方式 | 毎ステップr個を確定。直接生成K=1/2、投機生成K=3 |
| 動的方式 | 閾値τで複数位置を確定し、MRPで再マスク |

評価では正答率とトークン毎秒を分けて報告する。スループットの倍率は同じモデルのr=1の通常静的復号を基準とする。異なるモデル規模の絶対トークン毎秒をそのまま速度倍率として比較しない。

### 残差学習と直接学習の比較：原著Table 1

同じ小型モジュール構造と学習条件で、次ステップのlogit全体を直接蒸留する方式と、logitの差分だけを蒸留する方式を比較した。MRPを一回だけ使う場合は両方式の差が小さいが、反復回数を増やすと直接学習の誤差が蓄積する。GSM8KでK=2の4Bモデルでは残差学習が直接学習より68.0ポイント高く、8Bでも17.2ポイント高い。K=4では1.7Bで12.9ポイント、4Bで55.3ポイント、8Bで73.1ポイントの差がある。

この結果は、差分の小ささが単なる観察にとどまらず、複数回の軽量推定における学習安定性へ結び付くことを示す。ただし実験はSDAR系列であり、すべての拡散言語モデルで同じ差分の構造が成立する保証はない。

投機方式は全体で1.17〜1.40倍の速度改善を示し、品質は基準に近い。直接方式は1.43〜1.91倍程度の速度改善を得られるが、特にコード生成で正答率が下がる。単純にr=2として多くのトークンを一度に確定すると、1.7BのHumanEvalが53.7から29.9へ低下するため、MRPの直接方式は同じ速度域でも品質を保ちやすい。ただし近似による品質損失は残る。

### 動的復号の再マスク：原著Table 3

低い閾値τ=0.5では、MRPの再マスクが多くの誤った早期確定を取り消す。4BのGSM8Kは63.4%から81.1%へ17.7ポイント改善し、8BのHumanEvalは32.3%から54.9%へ22.6ポイント改善する。原著は低閾値で全モデル規模・全タスクに大きな改善があると報告する。

閾値を高くすると、もともと保守的に確定するため再マスクの必要性が下がる。τ=0.8〜0.9では改善が小さくなり、4BのHumanEvalでは−1.8ポイントや−1.2ポイント、4BのMBPPでは−0.8ポイントの負の結果がある。数学系のタスクでは評価した閾値・規模で改善が一貫するが、コードでは確定済みの正しいトークンを誤って取り消す場合がある。

### 再マスクの速度費用：原著付録Table 5

同じτの通常動的方式と再マスク方式を比べると、再マスクは追加のMRP実行と確定取り消しによって、通常はトークン毎秒が低下する。数学系のタスクでは通常動的方式の約0.76〜0.88倍の速度にとどまる条件が多い。例えば1.7B・τ=0.5のGSM8Kは975トークン/秒から792トークン/秒、4B・τ=0.5は720から558、8B・τ=0.5は507から416へ下がる。

したがって、再マスクは「同じτで高速化する」方式ではなく、「速いが不正確な低τの設定から品質を取り戻す」方式である。品質と速度を同時に評価する際には、より高いτの通常方式との比較も必要になる。

### MRPの深さと費用

原著はMRPの層数を1、2、3、4、8と変えて、残差予測の容量と実行費用の交換を調べる。深いMRPは直接生成での精度改善に役立つ一方、追加演算が増えるため投機生成の速度改善には不利になる場合がある。主実験の3層は唯一の最適解ではなく、品質を重視する直接方式と、検証付きの速度改善を重視する方式では選ぶ深さが変わり得る。

## 既存研究との差

従来の拡散言語モデルの高速化は、一回に確定するトークン数を増やす、閾値を調整する、別の小型モデルで候補を生成するなどの方法を使う。MRPは隣接するノイズ除去ステップのlogit残差を学習し、同じ大型モデルの隠れ状態から次ステップを近似するため、完全な次分布を予測するより軽量にできる。

同じMRPを、検証付きの品質維持型投機、検証なしの速度優先型生成、過剰確定を取り消す品質回復型再マスクへ切り替えられる点が特徴である。三方式は目的と保証が異なるため、論文の最大速度倍率と最大正答率改善を同時に達成した一つの運用として合算してはいけない。

## 限界と実務上の判断

評価はSDAR-Chatの1.7B/4B/8B、ブロック長16、数学・コードの代表的なベンチマークが中心である。他の拡散モデル、異なるブロック長、長い対話、異なる言語での同等の効果は未検証である。小型モジュールの学習には約1,240万会話のデータと追加の蒸留計算が必要であり、完全な学習不要の推論最適化ではない。

検証なしの直接方式では品質低下があり、投機方式の品質維持は原著のargmax検証規則に依存する。任意の確率的サンプリング分布について厳密な保存を保証するものと混同しない。再マスク方式は同じ閾値での速度が通常より低いことが多く、コード生成の高閾値条件では小さな品質悪化もある。

実務では、品質を保ちたい場合は検証付き投機、速度を優先して多少の品質低下を許容する場合は直接方式、低閾値の動的方式で誤りが多い場合は再マスクを検討する。いずれも対象モデル・GPU・バッチサイズで正答率とトークン毎秒を同時に計測する必要がある。
