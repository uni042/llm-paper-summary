# AttnPO：最終回答が参照する思考段階に基づく低負荷な過剰推論抑制

## 概要

強化学習で訓練された推論モデルは、難しい問題を解く際に長い思考連鎖（Chain-of-Thought; CoT）を生成する。一方、既に答えへ到達した後も検証や言い換えを繰り返し、追加のトークンを消費する「過剰推論（overthinking）」が起こる。単純な長さペナルティは回答全体へ同じ報酬を与えるため、無駄な検証と正解に不可欠な計算を区別できない。短くする圧力を強めすぎると、難しい問題で必要な推論まで省略し、正答率を下げる危険がある。

AttnPO（Attention-guided Policy Optimization）は、モデルが最終回答を生成するときに過去の思考のどの部分へ注意しているかを、**思考段階ごとの重要性の代理指標**として使う。最終回答から必要な思考段階へ強く注意する少数の注意ヘッド（Key-Focus Heads; KFH）を探索し、各段階の注意スコアで強化学習の優位性を再重み付けする。正答した応答のうち、報酬上の優位性が正の場合は冗長段階への強化を弱め、負の場合は重要段階への罰を弱める。追加の大きな報酬モデルや多数の反事実的な生成を毎回要求しない点が特徴である。

DeepSeek-R1-Distill-Qwen-1.5Bでは数学6課題の平均正答率が54.5%から61.8%へ7.3ポイント改善し、平均生成トークン数は8005から3114へ約61.1%減った。7Bでは70.2%から73.1%へ2.9ポイント改善し、6561から2922へ約55.5%減った。ただし同じ長さ報酬を使うTLMREと比較すると、正答率は1.5Bで62.2%から61.8%、7Bで73.7%から73.1%へわずかに低下する。**元モデルとの比較で精度が上がることと、最強の比較方式を全指標で上回ることは異なる**。

## 問題設定と先行方式

### 回答全体の報酬では段階の役割を区別できない

検証可能な報酬による強化学習（Reinforcement Learning with Verifiable Rewards; RLVR）は、数学問題の最終回答の正誤を使ってモデルを更新する。GRPOやRLOOのような手法は、同じ質問から複数の回答を生成し、相対的に良い回答の確率を上げる。しかし、回答の中に有用な途中計算と冗長な言い換えが混在していても、全トークンへ同じ軌跡単位の優位性を適用することが多い。

短い回答に追加報酬を与えるTLMREのような方式は、トークン数の削減には役立つが、重要な検証段階を誤って削除すると精度が下がる。過程監督（process supervision）で各段階を評価する研究もあるが、途中で回答を打ち切って複数回サンプリングする方式や、冗長な段階を検出する補助モデルを訓練する方式は、GPU時間と教師ラベル作成費用を増やす。AttnPOは、既に存在するモデルの注意行列から段階の役割を推定できないかを調べる。

### 最終回答の注意は必要性を示すか

モデルは思考部分と最終回答部分を分けて生成する。最終回答のトークンは、過去の思考の一部を参照して答えをまとめるため、必要な計算段階へ注意が集中する可能性がある。ただし注意重みは因果的な寄与を直接証明するものではない。著者はまず少数の問題に必要・冗長の教師ラベルを付け、注意ヘッドがこの区別をどれだけ再現するかを調べる。注意スコアの大小をそのまま正答保証とみなさず、実際に高スコア段階を削除したときの性能低下も調べている。

## 手法

### 1. 思考連鎖を意味的な段階へ区切る

思考部分は、ためらい・方針転換を示す表現、順序を示す表現、結論を示す表現を手掛かりに段階へ分割する。極端に短い段階は隣接部分と統合するが、方針転換を示す段階は冗長な再検証の検出に重要なので、前の段階から分離して扱う。単純に固定トークン数で区切る方式と異なり、論理的な推論単位に近い粒度を得ることを狙う。

この分割は言語依存であり、接続詞が省略された文章や、自然言語と数式が混ざる思考では境界が曖昧になり得る。段階境界の誤りは、後続の注意スコアと報酬の割当てに影響するため、段階分割器の品質も本方式の一部である。

### 2. 重要注意ヘッドの探索

著者はDeepScaleRから1.5Bモデルが8回の生成で平均正答率0.875以上となる比較的容易な300問を選ぶ。各問題で8回答を生成し、正答のうち長さが中央値に近い回答を使う。思考を段階に分割した後、複数のLLM判定器が必要・冗長のラベルで一致した段階だけを教師として残す。容易な問題に限定したのは、難問での探索や再検証が一見冗長に見えても実際には必要な場合があり、教師ラベルの信頼性が下がるためである。

各注意ヘッドについて、最終回答の各トークンから一つの思考段階に向かう注意重みを合計し、段階のトークン数で割ったスコアを計算する。長い段階ほど注意の総量が大きくなる偏りを軽減するための正規化である。必要段階と冗長段階の全組合せで、必要段階のスコアが高い割合を**段階順位正答率（Step Ranking Accuracy; SRA）**として測る。

一部の注意ヘッドはSRAが0.9を超え、最良のヘッドは1.5Bで約95%、7Bで約96%に達した。一方、多数のヘッドは無作為な順位付けに近い。重要ヘッドは中層から後層に多く、複数ヘッドを無制限に加えても精度は改善しない。著者は上位3ヘッドを基本設定に採用する。長さ報酬で学習したチェックポイント間のSRA分布の相関が0.85を超えることも示し、ヘッドの性質がある程度安定していると報告した。

### 3. 重要段階の削除実験

AIME2024で最終回答が正しかった思考から、注意スコアの高い段階の上位30%を削除する条件と、低い段階の下位30%を削除する条件を比較する。削除後の思考を与えて最終回答を再生成すると、高スコア段階を除いた場合はpass@32が悪化する一方、低スコア段階を除いた場合は性能への影響が小さい。これは注意スコアが完全な因果的寄与指標であるという証明ではないが、段階の重要性を推定する代理指標としての妥当性を補強する。

### 4. 正の優位性を持つ正答軌跡では冗長段階の強化を弱める

各回答に対して、正答かどうかと長さに基づく軌跡単位の報酬を計算し、他の回答との比較からRLOOの優位性`A_i`を得る。通常は同じ`A_i`を回答内の全段階に適用するが、AttnPOは段階`k`ごとに`A_hat(i,k)=γ(i,k)·A_i`と再重み付けする。`γ`は非負で、優位性の符号を逆転させない。

正答した回答で`A_i>0`の場合、重要注意ヘッドのスコアが段階固有の基準より低い段階を冗長候補とみなし、`γ`を1未満へ減らす。これにより、正答へ寄与しない反復や検証をモデルが繰り返す確率を上げすぎない。問題の難易度は同一質問の生成群における正答率で近似し、難しい問題では減衰を弱め、訓練の後半まで減衰の開始を遅らせる。難問の探索を早期に潰さないための設計である。

### 5. 負の優位性を持つ正答軌跡では必要段階の罰を弱める

同じく最終回答は正しいが、他の回答より長いなどの理由で`A_i<0`になった場合、軌跡全体の確率を下げると、正答に必要だった計算段階まで減らされる。AttnPOは高スコアの必要段階に対して`γ=0`として負の優位性を遮断し、低スコアの冗長段階には罰を残す。これは必要段階へ新しい正の報酬を加える方式ではなく、**不要な罰を除く**方式である。

両方の調整は**正答した応答にだけ**適用する。誤答した思考では、途中段階が正しいのか、誤りへつながったのかを注意だけで判定することが難しく、誤った教師信号を与えないためである。負の優位性の遮断だけで全段階を保護するのではなく、正の優位性の減衰と組み合わせることで、短縮と正答率の両立を狙う。

### 6. 学習時の追加費用

著者はVeRL基盤で、方策の古い対数確率を計算する前向き処理に注意スコアの取得を組み込む。独立した大規模な報酬モデルの前向き計算や、段階ごとの大量の追加ロールアウトを要求しない。付録C.2では1.5Bの初期20学習ステップを比較し、ほぼ同じ生成長の条件で追加時間が小さいことを示す。ただし「追加費用がゼロ」ではなく、注意行列の取得、段階境界の計算、ヘッド選択、スコア集計には実装上の費用がある。推論時には訓練済みモデルを通常通り生成するため、段階判定器を逐次呼び出す必要はない。

| 7B基盤 | 49.6% / 9095 | 44.6% / 6891 | 69.7% / 1245 |
| 7B TLMRE | **53.5%** / 3988 | **49.1%** / 3988 | **70.0%** / 712 |
| **7B AttnPO** | 52.3% / **2873** | 48.6% / **2873** | 69.8% / **547** |

原著表2。1.5BではコードとMMLUの正答率がTLMREより高いが、GPQAは39.2%から36.4%へ下がる。7Bでは三課題すべてでTLMREより正答率が低いものの、生成長は短い。著者は数学だけで訓練したモデルの域外一般化を報告するが、**すべての域外課題で精度が改善するわけではない**。この負の結果は総合AESだけでは見えない。

### 4. 構成要素除去

原著付録表6では、1.5BのTLMREを基準に、正の優位性を持つ冗長段階の減衰（PA）だけを追加すると、数学6課題の平均生成トークンが4047から3167へ減る一方、正答率は62.2%から60.5%へ下がる。さらに必要段階への負の罰を弱める（NA）と、平均トークン3114、正答率61.8%へ回復する。PAは主に長さの圧縮、NAは主に精度の回復へ寄与するという設計意図を支持する。

ただしNAを追加してもTLMREの62.2%へ完全には戻らない。注意ヘッドが誤って必要段階を冗長とみなす可能性が残る。難易度依存の閾値とスケジュールを弱める構成要素除去では、生成長はさらに短くなるが正答率が悪化する。難問で早期に探索を止めすぎないための制御が必要である。

### 5. 実測速度ではなく生成量の削減

生成トークンが61%減れば、逐次復号で必要な前向き計算回数は大きく減る可能性がある。しかし実際の応答遅延には、入力事前充填、モデル重みの読み込み、KVキャッシュの配置、生成時のバッチサイズ、トークンあたりの処理時間が影響する。原著の主要結果は**生成トークン数と正答率**であり、GPU上の同時要求処理量やミリ秒単位の応答時間の比較表ではない。訓練時の追加負荷も、初期20ステップの比較で小さいことを示すが、全学習期間のエネルギー消費や大規模分散学習へのスケーリングを測ったものではない。

## 既存研究との差と実装上の意味

TLMREは正答と回答長から軌跡単位の報酬を作るが、どの思考段階が重要かを明示しない。AttnPOは同じ報酬を出発点とし、最終回答時の注意を利用して段階ごとの優位性を調整する。追加の報酬モデルを学習する方式と異なり、モデル内部の注意ヘッドの性質を再利用する。難易度に応じて減衰の開始時期と強さを変えることで、短い回答を学習させながら難問の探索を残す。

既存のモデルを推論時だけ書き換える短縮器ではなく、**学習時の報酬配分を変えて短い思考をモデルに身に付けさせる方式**である。したがって、完成したモデルを通常の推論エンジンで使う場合は、学習時の注意スコア計算を実行する必要がない。一方、元モデルからAttnPO版を再現するには、注意ヘッドの選定、段階分割、相対優位性の計算、強化学習の更新を実装する必要がある。モデルの推論実行だけを目的とするllama.cppやOllamaの設定変更では、同じ学習効果を直接得られない。

## 限界

**注意重みは因果的な必要性の完全な証明ではない。** 最終回答がある段階へ注意していても、別の段階を削除したときの結果を完全には予測できない。ヘッド選定用の教師は容易な数学問題を中心に構成され、難しい問題の有益な探索が冗長と誤認される可能性がある。注意スコアによる段階順位の高さを正答保証として扱ってはいけない。

**評価モデルは1.5Bと7Bに限定される。** さらに大きいモデル、混合専門家モデル、異なる注意構造、視覚言語モデルで同じKFHが見つかるかは示されていない。最終回答と思考を明示的に分けないモデルでは、同じスコアを計算できない場合がある。

**学習は数学中心。** 訓練集合はDeepScaleR-Previewで、コード・科学・知識問題は主に域外評価である。7Bの域外3課題ではTLMREより正答率が小幅に低く、一般化を過大評価できない。複雑なエージェントの長期計画や複数ツール呼出しを対象とした評価もない。

**教師ラベルとヘッド選定に外部モデルを使う。** 訓練時の各段階の報酬には大きな追加モデルを必要としないが、KFHを最初に発見するための探索データでは複数のLLM判定器の一致を用いている。完全に教師なしで全工程が完結するわけではない。選定済みヘッドの転移性と再選定費用はモデルの変更に依存する。

**最良の比較方式より精度が低い条件がある。** 数学6課題の平均ではTLMREより1.5Bで0.4ポイント、7Bで0.6ポイント低い。1.5BのGPQA、7BのLiveCodeBench/GPQA/MMLUでも精度低下がある。長さを短くするほど常に正答率が上がるという主張ではない。

**実測推論速度は未確定。** 出力トークン数を削減しても、事前充填、キャッシュ、バッチ処理の費用が残る。GPUでの実測遅延や電力削減を61%・55%と断定できない。ローカル実装では量子化やCPUオフロードによってトークンあたりの処理時間も変わるため、別途測定が必要である。
