# Learning to Compress Prompts with Gist Tokens

> Gistingは、毎要求で長い指示文を再エンコードする代わりに、その指示を少数の「gistトークン」へ圧縮し、後続入力がその圧縮表現だけを参照するよう学習する。モデルごとの新しいアダプタを保存するのではなく、タスク指示を通常のキー・値キャッシュ（Key-Value Cache; KVキャッシュ）として再利用可能な短い状態へ変換する。

## 概要

同じシステム指示やタスク記述を多数要求で繰り返す配信では、指示部分のプリフィル計算とKV保存が毎回発生する。通常の接頭辞キャッシュでも同一文字列なら再利用できるが、保存するKV長は元の指示長に比例する。

Gistingは命令微調整時の注意マスクだけを変更し、入力指示とユーザー入力の間に少数の特別gistトークンを置く。後半トークンから元指示への直接注意を遮断し、gistトークン経由でしか指示情報へアクセスできないようにすることで、モデル自身に「この数トークンへ必要情報を押し込む」ことを学習させる。

LLaMA-7BとFLAN-T5-XXLで、最大26倍のプロンプト圧縮、最大40%の浮動小数点演算（Floating-Point Operations; FLOPs）削減、最大4.2%の壁時計短縮を報告する。計算削減に対して壁時計利得が小さい点も、実システムで読むべき重要な結果である。

## 背景と問題設定

### プロンプトは「重み」ではなく要求ごとに渡すタスク状態である

微調整ならタスク知識を重みへ埋め込めるが、新タスクごとに学習・モデル複製が必要になる。プロンプトなら柔軟だが、長い指示を毎回コンテキストへ入れ続ける。

Gistingはこの中間として、指示を入力依存の小さい中間状態へ変換する。一度gistを計算して保存すれば、同じタスクの新しい例では元指示を再入力せずgist状態から開始できる。

## 手法

### 1. 指示と入力の間にgistトークンを挿入する

学習系列を「指示 → gistトークン → 個別入力 → 出力」と構成する。gist数は固定の小さい値を設定できる。

### 2. 注意マスクで情報経路をgistへ強制する

個別入力・出力から元指示トークンへの注意を遮断し、gist位置だけを見せる。したがって損失を下げるには、gistの隠れ状態に後段で必要な指示情報を保持する必要がある。

### 3. 推論時はgistのKVだけを保存・再利用する

タスク指示を一度通し、gist位置のKVをキャッシュする。新しいユーザー入力では、この短いKVを接頭辞として使うため、元指示の長さに比例した保存・再プリフィルを避けられる。

### 4. タスクごとの追加重みを持たない

方式は通常の命令微調整と同時に学習でき、タスク別LoRA等を個別保存する必要はない。一方、任意の未学習モデルへ事後処理だけでgist能力を付けられるわけではなく、gisting用学習が必要である。

## 評価

### 評価条件

| 項目 | 条件 |
|---|---|
| モデル | LLaMA-7B、FLAN-T5-XXL |
| 比較 | キャッシュなし、通常の指示KVキャッシュ、gistキャッシュ |
| 指標 | タスク品質、圧縮率、CUDA壁時計、GFLOPs、保存KV長 |
| 学習 | 命令微調整にgist注意マスクを追加 |
| 代表効率測定 | 同じ指示を再利用する推論条件 |

### 主な結果

| 観点 | 結果 | 解釈 |
|---|---:|---|
| プロンプト圧縮 | 最大 **26倍** | 長い指示を少数gist位置へ集約 |
| FLOPs | 最大 **40%削減** | 元指示の再計算を避ける |
| FLAN-T5-XXL壁時計 | **4.2%短縮** | FLOPs削減がそのまま同倍率の時間短縮にはならない |
| LLaMA-7B壁時計 | キャッシュなし比約 **6.8%短縮**、通常指示キャッシュ比は約 **1%** | 既存KVキャッシュが強い基準では追加利得は小さい |
| 平均KV長例 | 通常指示キャッシュ26に対しgist 1 | 保存容量削減の直接指標 |
| 品質 | 最小限の低下で圧縮を報告 | 圧縮率だけでなくタスク性能と同時評価 |

「40% FLOPs削減」と「4.2%壁時計短縮」は矛盾しない。短い行列演算、カーネル起動、個別入力・出力側の処理など、gistで消えない時間が残るためである。

## 既存研究との差

接頭辞キャッシュは同一プロンプトのKVをそのまま保存するが、保存長を縮めない。蒸留や微調整は指示をモデル重みへ吸収するがタスク別更新を要求する。Gistingは「入力状態として保持するが、元プロンプトより短い」という位置にある。

## 限界・実装状況

圧縮可能性は指示の複雑さとgist数に依存する。非常に長く多数の例外条件を持つ指示を1トークンへ圧縮すれば品質低下が大きくなり得る。

また、既に高効率な通常KVキャッシュを使う配信では、壁時計上の追加利得は小さい場合がある。価値は計算だけでなく、保存KV量やコンテキスト窓の解放にもある。
