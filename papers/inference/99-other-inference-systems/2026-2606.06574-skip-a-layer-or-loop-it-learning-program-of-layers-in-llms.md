# 層を飛ばすか、もう一度実行するか：PoLarによる入力適応型LLM推論

## 概要

一般的なTransformer型の大規模言語モデル（Large Language Model; LLM）は、入力の難易度や内容によらず、事前学習時に決まった順序で全層を一度ずつ実行する。ところが、この固定的な計算経路は、必ずしも各入力で正答を得るための最短経路でも、最も正確な経路でもない。本論文は、学習済みの各層を関数とみなし、その呼出し順と回数を入力に応じて変える「層プログラム（Program-of-Layers; PoLar）」を提案する。連続する層のまとまりごとに、実行しない、通常どおり実行する、もう一度実行する、の三択を行う。基盤LLMの重みを変更しない点が特徴である。

著者らはまずモンテカルロ木探索（Monte Carlo Tree Search; MCTS）で代替実行経路の存在を調べ、正答できる経路がしばしば通常の全層実行より短いこと、単純な層の間引きだけより層の再実行も許した方が正答率が高いことを示した。ただしMCTSは入力ごとに大量の候補経路を試すため、本番推論には高価である。そこで、MCTSで見つかった正解経路を学習データとし、入力から層の区切りと実行操作を直接予測する小型ネットワークを別途学習する。実行時には、この予測器が作った層プログラムに従い、凍結した基盤LLMを一回実行する。

Qwen1.5-MoE-A2.7B-Chatの24層を対象にした実測では、予測器・埋め込み器・候補探索を含む追加費用は合計3.05ミリ秒、通常の全層実行の0.8%だった。DART-Mathの易しい問題では通常373.45ミリ秒に対しPoLarは311.41ミリ秒、難しい問題では353.31ミリ秒と報告する。一方、主たる精度評価は数学問題であり、一般的な会話生成のトークン当たり遅延や大規模同時配信での改善を直接示すものではない。これらの数値は表4に基づく同一モデル・対象設定での比較であり、全LLMへ一般化した保証ではない。

## 問題設定と技術的背景

### 固定層実行が抱える計算配分の問題

深さDの事前学習済みTransformerを、各層の関数 `f_0, f_1, ..., f_(D-1)` の合成として表す。通常の推論は `f_(D-1) ∘ ... ∘ f_0` という一つの固定プログラムをすべての入力へ適用する。計算量は各層の実行回数に強く依存するが、簡単な入力でも全層を通り、難しい入力でも追加の内部反復を行わない。出力トークンを長く生成する思考連鎖とは別に、モデルの隠れ状態を処理する内部計算の回数そのものを制御する余地がある。

従来の層スキップ（Layer Skipping）は、重要度の低い層を飛ばすことで計算を減らす。しかし、飛ばした層が必要な入力では正答率が落ちる。早期終了（Early Exit）も途中で処理を打ち切るため、必要な深い処理を行えないことがある。一方、層反復（Layer Recurrence）は同じ層を再利用して内部計算を増やせるが、反復のみでは不要な層を減らす自由度がない。PoLarの問題設定は、**省略と反復を同一の入力別プログラムに組み込めるか**、さらにそのプログラムをオンラインの高価な探索なしで決められるか、という二点にある。

### 正しい実行経路の存在とオンライン探索の限界

著者らはDART-Mathの難度1～5について、LLaMA-3.2-3B-Instruct、Qwen1.5-MoE-A2.7B-Chat、Qwen2.5-3B-Instruct、Qwen3-8Bの4モデルでMCTSを実施した。これは通常推論のたびに使う手法ではなく、どのような代替経路が存在するかを調べ、後段の予測器へ教師信号を作るためのオフライン手段である。MCTSは候補の部分プログラムを選択・拡張・評価し、正答する経路を探索する。探索中の「正解を知った上で最善経路を選べる」状況は、本番で予測器が一度に経路を当てる状況とは異なる。

探索で見つかった正解プログラムでは、元の通常経路で正答した入力の71.9%に、さらに短い正解経路が存在した。元の通常経路で誤答した入力についても、34.0%で、通常より短くかつ正答する代替経路が見つかった。これは存在証明・探索統計であり、オンラインの予測器が71.9%または34.0%を自動的に再現できるという意味ではない。別の構造分析では、見つかった層区間の57.7%が単一層で、3分の2超が連続2層以下、非連続層主体の区間は2.9%未満だった。この偏りを利用して、実用的なプログラム表現を小さくする。

## 手法

### 1. 層を再利用可能な関数として扱う

深さDのモデルに対し、層プログラムを整数列 `π=(i_1, ..., i_K)` として定義する。実行結果は `F_π=f_(i_K) ∘ ... ∘ f_(i_1)` である。KはDより小さくても大きくてもよく、同じ層番号が複数回現れてもよい。重要なのは層の重みを更新することではなく、**事前学習済みの層関数をどの順で何回呼ぶか**を変更する点である。層スキップでは実行回数を減らし、層反復では計算を追加する。通常の固定経路は、すべての区間に保持操作を選んだ特殊例に当たる。

全層の任意並べ替えを許すと候補数が巨大になるため、実装では連続層の区間（segment）をモジュールとしてまとめる。区間の最大長は `K_max=4` とし、前述のMCTS分析で短く連続した区間が大半だったという観測に基づいて候補空間を縮小する。区間開始位置を長さDの二値ベクトル `z_seg` で表し、区間の先頭にだけ三値の操作ラベル `z_op` を割り当てる。区間の長さが上限を超えるときは区切りを挿入するため、予測器の出力がそのまま無制約の実行経路になるわけではない。

操作は `skip`（区間の層を実行しない）、`keep`（一回実行）、`repeat`（区間全体を同じ順序でもう一回実行）の三つである。たとえば区間が層4と層5なら、反復は `4→5→4→5` となる。層4だけを二度呼ぶ `4→4` とは異なり、区間単位で隠れ状態の変換を繰り返す。論文の実装では一つの区間の追加実行は一回に制限する。これは探索で深い反復が稀だったための設計であり、原理的に反復回数を増やせないという制約ではない。

### 2. 入力から層区間と操作を予測する小型ネットワーク

予測器は、入力文を凍結した `Qwen3-Embedding-0.6B` でトークン表現へ変換し、学習可能な射影で内部次元へ写す。各基盤LLM層番号に対応する学習可能な層埋め込みを問い合わせ（query）とし、入力トークン埋め込みを鍵・値として交差注意（Cross-Attention）を計算する。こうして各層番号が、現在の入力に関する特徴を受け取る。続く軽量Transformer符号化器は層方向に自己注意を行い、ある層を飛ばす判断が他層の選択から独立しないよう、深さ全体の依存を反映する。

この層別表現から二つの出力頭を計算する。一つは区間開始の二値予測 `ℓ_seg`、もう一つは区間ごとの `skip/keep/repeat` の三値予測 `ℓ_op` である。訓練ラベルはMCTSが見つけた正解プログラムを決定的に変換して作る。区間境界には二値交差エントロピーを、操作には区間開始位置だけを対象とするマスク付き交差エントロピーを用い、その和で予測器を学習する。複数の正解経路がある場合、通常の全層経路より短い正解経路が存在すれば、全層経路の損失寄与を下げる。これは単に正答率だけでなく、不要な計算を減らす方向へ予測を誘導する工夫である。

「学習不要」という表現は**基盤LLMを再学習しない**という意味であり、PoLar全体が学習不要という意味ではない。予測器にはMCTS由来の正解経路の収集と教師あり学習が必要である。別の入力分布や基盤モデルでそのまま同じ予測器が使えることも、論文は無条件に保証していない。

### 3. 推論時のプログラム復号と実行

本番の推論では、まず入力を予測器へ渡し、区間境界の予測値を閾値処理して区間を決める。`K_max` を超える区間には追加の境界を入れる。各区間の開始位置について三つの操作の対数確率を計算し、独立に最大確率操作を選ぶ代わりに、制約の小さいビーム探索（Beam Search）で区間間の相互作用を考慮した複数の全体プログラム候補を作る。各候補は具体的な層呼出し列へ決定的に展開され、凍結した基盤モデルの層関数がその順序で実行される。

ここでのビーム探索は、MCTSのように候補ごとにLLMを実行して正答を確認する大規模なオンライン探索ではない。予測器が出した区間操作確率に対して、小さな離散的候補集合を探索する。したがって追加計算は主に入力埋め込み、層別予測器、区間操作の候補生成から成る。ただし `pass@k` 評価では上位k個の**異なる実行プログラム**を実際に試すため、kを増やすほど基盤モデルの実行回数が増える。単一経路の低遅延と、複数経路を試す正答率向上は別の運用点である。

### 4. エンドツーエンドの処理とシステム上の含意

一つの要求に対する流れは、入力の埋め込み生成→各層への交差注意→層間符号化→区間境界と操作の予測→小規模ビーム探索→選んだ層プログラムによる基盤LLM実行→回答、となる。基盤LLMのパラメータはそのままで、推論実行グラフを入力ごとに変える。予測器の計算を先払いしても、実行層数を減らせれば総遅延が下がる。難しい入力では反復を増やして精度を高める余地がある。

一方、この論文が直接測定したのは限定された推論環境での層実行数と遅延であり、実運用の継続バッチ処理、GPUカーネル融合、KVキャッシュの分岐管理、複数同時要求におけるスケジューラとの統合までは実証していない。動的な層実行順序は、固定グラフ前提の実行最適化やキャッシュの扱いを変え得る。特に生成時の反復層で既存のKVキャッシュをどのように再利用するかは、導入時に別途確認すべき実装課題である。

## 評価

### 評価設計と比較対象

論文は、探索による実行経路の存在分析と、学習した予測器による実用評価を分ける。前者はMCTSで見つけた経路の正答率と深さを調べるため、**正答を確認しながら探索する上限的な分析**である。後者はMCTSで得た教師信号を使うPoLar予測器を別途学習し、未知の入力での `pass@k` 正答率と実行時間を測定する。両者の数字を同じ「PoLar本番推論の精度」として混同してはならない。

| 観点 | 原著の条件 |
|---|---|
| 基盤モデル | LLaMA-3.2-3B-Instruct、Qwen1.5-MoE-A2.7B-Chat、Qwen2.5-3B-Instruct、Qwen3-8B |
| 基盤モデルの重み | 全モデルで固定。PoLar予測器のみ別途学習 |
| 正解経路探索 | MCTSをオフライン実行し、層スキップ・反復の正解経路を教師信号化 |
| 分布内評価 | DART-Mathの難度別 DM-1～DM-5。改訂版では問題文の重複を除去し、難度ごとに訓練・評価分割 |
| 分布外評価 | ASDiv、MAWPS、MMLU-Proの複数分野。DART-Mathの全難度訓練データで学習した予測器を追加学習なしで評価 |
| 比較対象 | 通常全層実行（貪欲・サンプリング）、ShortGPT、MindSkip、FlexiDepth、DR.LLM |
| 指標 | 正答率 `pass@k`、実行層数、予測器追加遅延、エンドツーエンド遅延 |
| 実測遅延の代表モデル | Qwen1.5-MoE-A2.7B-Chat、24層。表4で予測器の構成要素別費用を測定 |

`pass@k` は、k個の試行のうち少なくとも一つが正答する割合を示す。PoLarではk個の異なる層プログラム、通常のサンプリング比較ではk個の出力サンプルを試す。`pass@5` の改善は一回の回答が必ずその確率で正答することを意味せず、最大5回の候補実行を許した条件である。論文の表2はLLaMA-3.2-3B-Instructを中心に、表3はQwen1.5-MoE-A2.7B-Chatでの分布外評価を示す。

| PoLar、DM-1 | 311.41 ms | 平均23.30層、相対時間0.83、正答率+5.7ポイント |
| PoLar、DM-5 | 353.31 ms | 平均23.76層、相対時間0.95、正答率+9.4ポイント（表4） |

原著表4の測定で、追加費用3.05ミリ秒は、埋め込み器を含む予測系のコストを分けて計上した値である。DM-1の相対時間0.83は通常の83%の所要時間という意味で、速度が0.83倍へ低下した意味ではない。遅延短縮は約16.6%である。DM-5の短縮は約5.4%で、難しい問題では反復の必要性が増すため利得が小さくなる。論文の表4で報告された「平均層数」と実測遅延の比は単純な比例関係ではないため、**削減層数だけから速度改善を推算しない**。

予測器の学習パラメータ数は論文の比較対象モデル群で約210万、基盤LLM全体の0.01～0.06%と報告する。ただしQwen3-Embedding-0.6Bのような凍結した埋め込みモデルを呼び出す点を無視して「総追加モデルが210万パラメータだけ」とは言えない。論文が示す小さい追加遅延は測定された条件での結果であり、入力長や並列実行形態が変われば同じ割合になるとは限らない。

### 分布外評価と適用範囲

分布外評価では、DART-Mathで学習した予測器を、追加の対象データ学習なしでASDiv、MAWPS、MMLU-Proの複数分野へ適用した。Qwen1.5-MoE-A2.7B-Chatの `pass@1` はASDivで通常59.1%→PoLar63.8%、MAWPSで41.7%→46.7%、MMLU-Proの数学で13.9%→18.5%、物理で15.6%→20.3%となる。原著表3では法学、工学、経済、健康、心理、生命科学、哲学、歴史などでも通常全層実行より高い数値が示されている。

この結果は、入力の意味特徴から層プログラムを予測する方式が、学習した数学問題と同一形式の問題だけに限定されない可能性を示す。ただし分布外評価は基盤モデルをまたぐ予測器の無条件転用ではなく、同一の対象モデルを使った異なる入力分布への評価である。長文脈対話、マルチモーダル入力、実運用の要求到着分布、生成トークンごとの持続的なスケジューリング負荷は表3の対象ではない。

## 既存研究との差

ShortGPTは層重要度に基づいて静的に層を削り、入力ごとの層反復を行わない。MindSkipとFlexiDepthは軽量なルータで動的に層を飛ばすが、反復によって内部計算を追加する経路を直接表現しない。DR.LLMはスキップと反復を学習するものの、各層の中間状態に基づいて逐次ルーティング判断を行うため、複数の連続層をひとまとまりで再実行する `4→5→4→5` のような経路を扱う点でPoLarと異なる。PoLarは全層プログラムを基盤モデル実行前に予測し、区間間の判断をまとめて行う。

Universal Transformerやその他のループ型Transformerは、反復計算を前提にした構造や学習が必要になる場合がある。PoLarは既存の基盤モデルの層重みを凍結したまま、呼出し経路を変える。ただしその代わりに、正解経路を収集するオフラインMCTSと予測器学習という準備工程が増える。単純な「再学習不要・追加費用ゼロ」の手法ではなく、基盤モデルの再訓練を避けながら入力別の経路を予測する方式と位置づけるのが正確である。

## 限界・悪化条件・実装上の注意

第一に、オンラインで使う予測器は、正解を知っているMCTSと異なり、入力だけから適切な実行経路を推定する。したがってMCTS探索の大幅な正答率上限はそのまま達成できない。実際、LLaMA-3.2-3BのDM-5における単一経路の改善は0.3ポイントと小さく、難度ごとに効果が異なる。正答率と実行層数の両方を監視する必要がある。

第二に、予測器は別途学習する。基盤LLMの重みを凍結していても、オフラインMCTS探索、教師ラベル収集、入力埋め込み器、層プログラム予測器の訓練が必要であり、モデルや運用分布を変更した際の準備費用が残る。論文の表4は実行時の追加費用を示すが、学習・探索に要する総GPU時間をオンライン推論遅延へ按分した費用までは示さない。

第三に、実測のエンドツーエンド遅延は24層のQwen1.5-MoE-A2.7B-Chatを代表例とする。層を繰り返す実行経路は通常の固定グラフ推論と異なるため、連続バッチ処理や複数同時要求のサービング、既存の高速実行エンジンへの統合、GPUメモリ使用量やKVキャッシュへの影響は別途検証が必要である。論文の主評価は数学推論の正答率と層実行の効率であり、GPUメモリ節約率、電力削減率、同時配信スループットを測定したとみなしてはならない。

第四に、評価には `pass@k` が含まれる。kを増やして複数の層プログラムを試す方式は正答率を上げるが、その分だけ基盤モデルの実行回数が増える。単一候補での低遅延運用と複数候補での正答率向上は交換条件を持ち、同じ計算予算での単純比較ではない。論文の分布外改善は有望だが、医療や法律など高リスク領域での頑健性・較正・安全性まで検証したものではない。

第五に、最大区間長4、一回までの追加反復、連続層区間という設計は、探索で多かった経路の構造に合わせた近似である。より複雑な最適経路が存在しても表現できない可能性がある。逆に候補空間を無制限に広げると予測器の学習と実行が高価になる。PoLarの効率は、構造的な制約と経路の表現力の均衡に依存する。

## 総括

PoLarの本質は「難しい要求に対して生成する文章を長くする」のではなく、「同じ学習済み層群を入力別の小さなプログラムとして実行する」ことにある。MCTSによる構造分析から、連続する短い層区間と一回程度の反復が有効だと分かり、それを二値の区間境界と三値の区間操作の予測へ落とし込む。小型予測器の費用を上回る層実行削減が得られれば、基盤モデルを再学習せずに低遅延化できる。主要な数値上の貢献は、24層モデルでの3.05ミリ秒の追加費用と、DART-Mathでの373.45→311.41ミリ秒の遅延改善、および複数モデル・分布外問題での正答率改善である。大規模サービングやKV管理への適用は今後の検証課題として残る。
