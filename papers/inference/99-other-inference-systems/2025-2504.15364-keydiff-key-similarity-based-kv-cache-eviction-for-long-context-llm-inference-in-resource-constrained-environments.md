# KeyDiff: Key Similarity-Based KV Cache Eviction for Long-Context LLM Inference in Resource-Constrained Environments

> 注意重みではなくキーの幾何学的多様性を重要度代理として使う学習不要KV削除法で、ブロック長文処理でも厳密な容量上限を守りつつ、8K予算で約23%削減・LongBench差0.04%以下、既存削除法比で遅延最大30%短縮を示す。
## 書誌情報
- **著者**: Junyoung Park, Dalton Jones, Matthew J Morse, Raghavv Goel, Mingu Lee, Chris Lott
- **著者・所属**: Qualcomm AI Research
- **公開**: NeurIPS 2025 / arXiv:2504.15364v4
- **種別**: 査読済み国際会議論文・arXivプレプリント
- **対象**: KVキャッシュ削除、長文推論、キー類似度、ブロック単位プリフィル、メモリ制約、FlashAttention、学習不要圧縮、エッジ推論
- **実装**: 論文はキー平均、余弦類似度、上位選択で構成される実装手順と計算量を詳細に記載するが、著者はチェックリストでコードを独占的として非公開と明記している。再現にはHugging Face系モデルへブロック処理と削除処理を組み込む必要がある。
## 概要
KeyDiffは、長文LLM推論を厳しいメモリ上限の下でブロック単位に処理すると、従来の注意重み依存KV削除が将来ブロックを見られず重要トークンを早期に捨てる問題を扱う。著者らは、他のキーとの余弦類似度が低い幾何学的に特徴的なキーほど高い注意重みを得やすいことを観測し、注意重みを明示的に生成せず、キャッシュ内キーの平均ベクトルとの余弦類似度だけで保持対象を決める学習不要の削除法を提案する。効率版はキー数に対して線形計算量で、FlashAttentionのような注意行列を実体化しない高速注意と両立する。Llama 3.1/3.2やQwen 2.5、DeepSeek-R1蒸留モデルで評価し、LongBenchでは8K予算で平均約23%のKV削減時に非削除基準との差を0.04%以下に抑え、既存削除法に対する最初のトークンまでの時間を最大30%短縮した。

KeyDiffはクエリ依存の注意重みではなく、キャッシュ中のキー同士の幾何学的な多様性を重要度代理にする。著者らは平均的に他のキーと似ていないキーほど高い注意重みを受ける負の相関を観測し、保持集合内の余弦類似度を小さくする部分集合選択としてKV削除を定式化する。さらに全キー間の二乗計算を、キャッシュ中キーの平均ベクトルをアンカーとして各キーとの余弦類似度を一度ずつ計算する線形計算へ緩和し、注意行列を生成せずに同じ削除原理を実装する。

代表結果として、LongBench・6K KV予算はLlama 3.1-8B-Instruct / Llama 3.2-3B-Instruct、主にブロックサイズ128で非削除KVキャッシュに対して非削除基準から約1.5%低下、平均約33% KV削減。全プロンプトを一括保持せず処理途中から容量を制限しても、キー多様性による選択で大半の長文性能を維持できる。
## 問題設定
長文LLMではKVキャッシュが処理済みトークン数に比例して増え、端末や割当メモリが小さい環境では、全プロンプトを一度にプリフィルしてから削除する方式は削除前の一時キャッシュだけで上限を超えてしまう。そのため入力を小ブロックへ分割し、各ブロック処理後にKVを容量以下へ戻す必要がある。しかしH2O、TOVA、SnapKVなど従来の削除法は注意重みを重要度として使うため、本来は全プロンプト中の将来クエリから受ける重要度を知りたいのに、ブロック処理時には現在までのクエリしか存在しない。誤った早期削除は後続ブロックへ累積し、さらに注意重みの実体化はFlashAttentionのようなメモリ効率の高い注意実装と相性が悪い。したがって、処理途中から厳密な容量上限を守りながら、未来トークンや注意行列を使わずに長期的重要度を推定できる削除指標が必要になる。
## 新規性
KeyDiffはクエリ依存の注意重みではなく、キャッシュ中のキー同士の幾何学的な多様性を重要度代理にする。著者らは平均的に他のキーと似ていないキーほど高い注意重みを受ける負の相関を観測し、保持集合内の余弦類似度を小さくする部分集合選択としてKV削除を定式化する。さらに全キー間の二乗計算を、キャッシュ中キーの平均ベクトルをアンカーとして各キーとの余弦類似度を一度ずつ計算する線形計算へ緩和し、注意行列を生成せずに同じ削除原理を実装する。
## 手法
### 手法のあらまし
入力は固定ブロックに分割され、各ブロックで新しいキー・値を既存KVキャッシュへ連結した後、設定したトークン予算を超えた分をKeyDiffで削除する。この操作をプリフィル中の全ブロックと生成中の各トークンで繰り返すため、キャッシュは推論過程のどの時点でも予算を大幅に超えない。基本形では各キーを正規化し、キー間の全余弦類似度の総和が小さいキーを残す。これは互いに似た冗長キーを捨て、幾何学的に散らばったキーを保存する考え方である。直接計算はキー数の二乗になるため、効率版では正規化キーの平均をアンカーベクトルとし、各キーとアンカーの余弦類似度だけを求める。アンカーから遠い、すなわち類似度の低いキーを上位選択して残すことで、計算量と追加メモリをキャッシュ長に対して線形にする。実験では正規化前キーの平均を使っても精度低下がなく、実装をさらに単純化できるとする。理論面では、高い注意重みを得るキーとクエリの整列、および平均キーとクエリの方向関係から、クエリに強く整列する重要キーほど平均キーから離れやすいことを上界で結び付ける。また付録では、保持キー集合のペアごとの余弦類似度総和を最小化する組合せ最適化を、全体平均を使って緩和するとKeyDiffのスコア式が得られることを示す。推論やコード生成のように直近文脈が重要な場合は、KV予算の一部を固定長の滑動窓に割り当て、残りだけをKeyDiffで選ぶ拡張も用いる。

### ブロック単位の厳密容量管理
全プロンプトを一括で処理して最後に圧縮するのではなく、入力を小さなブロックへ区切り、各ブロックのKVを既存キャッシュへ追加するたびに設定予算まで削除する。これにより入力長そのものがKV予算を大幅に超えていても、削除前に全入力分のKVを一時保持する必要がなく、推論過程の途中からメモリ上限を守れる。生成段階ではブロックサイズ1として同じ更新規則を繰り返す。重要なのは、この逐次処理では削除時点より後のクエリがまだ存在しないため、現在ブロックまでの注意重みだけで将来重要になるKVを判断すると誤削除が累積しやすい点である。KeyDiffはこの制約を例外ケースではなく設計前提に置き、未来トークンを参照しないキー固有の指標で各段階の保持集合を更新する。

### キー多様性による注意非依存スコア
キャッシュ内で他のキーと方向が似ていない特徴的なキーほど、複数の層とヘッドで高い注意重みを得る傾向があるという観測を利用する。基本形では保持候補のキー同士の余弦類似度を集計し、他キーとの類似度総和が低いものを残すことで、同じ方向へ重複した表現を削り、方向的に多様なキーを保存する。順位付けに必要なのはキーだけなので、未来クエリも注意重みも必要ない。したがってブロック処理でも尺度の定義が変わらず、注意行列を明示的に生成しないFlashAttention型の高速注意と削除法を併用できる。Llama 3.2-3Bでは負のキー類似度と注意重要度の層平均順位相関が約0.94と報告され、単なる直感ではなく実測でも代理指標として強い関係を示す。

### 平均アンカーによる線形化
全キー対の余弦類似度を直接計算する基本式は、キー数nに対して二乗の時間と中間メモリを要求し、KVを節約するための削除処理自身が長文時の新しいボトルネックになり得る。効率版では、キャッシュ中のキーの平均ベクトルをアンカーとして一度求め、各キーとアンカーの余弦類似度を一回ずつ計算する。保持集合内のペア類似度を最小化する組合せ最適化について、候補部分集合の平均を全キーの平均で置き換える緩和を行うと、この順位付けに帰着する。付録の解析では主要演算量はnに対して線形で、ブロックサイズBと予算Nに対する実行時間・追加メモリもおおむねO(N+B)となる。実験では正規化前キーの平均でも精度を維持でき、実装時の正規化処理を簡略化できる。

### 滑動窓との併用
長い推論やコード生成では、キー空間での希少性だけではなく直近トークンの局所的な連続性が重要になる。そこでKV予算の一定割合を最新トークン専用の滑動窓として予約し、残りの領域だけをKeyDiffの多様性基準で管理する拡張を用意する。直近領域は順位計算から保護されるため、最新の推論手順やコード状態を確実に残しながら、古い文脈については冗長なキーを削除できる。滑動窓の導入は新しいスコア計算や追加メモリを必要とせず、全体の固定KV予算も変えない。Math-500ではDeepSeek-R1-Distill-Llama-8Bにこの構成を使い、8K生成・4K予算などで非削除基準と同等近傍の精度を示す一方、Qwen蒸留モデルでは低下が残り、局所保持だけでは解消しないモデル依存性も確認できる。

### 全体のデータ／制御の流れ
各Transformer層のKVキャッシュに対し、ブロック処理後にキー平均と各キーの余弦類似度を計算し、設定予算に収まるインデックスを選択してキーと値を同じインデックスで収集する。注意計算そのものは既存の高速注意へ委ねられるため、KeyDiffはモデル構造や重みを変更せずKV管理層として差し込める。
## 評価条件
- **ハードウェア**: LongBenchおよび最初のトークンまでの時間の主要評価はNVIDIA A100 80GB GPUで実測する。
- **ソフトウェア**: Hugging Face標準推論経路を用い、通常注意とFlashAttentionを切り替えて削除法の追加費用を比較する。コードは著者方針により非公開。
- **比較対象**: 非削除KVキャッシュ、H2O、TOVA、SnapKV、StreamingLLM系シンク保持
Llama 3.1-8B-Instruct、Llama 3.2-3B-Instruct、Qwen 2.5-3B/7B-InstructをLongBenchとNeedle-in-a-Haystackで評価し、H2O、TOVA、SnapKV、StreamingLLM系のシンク保持、非削除を比較する。厳しいメモリ環境を再現するためプロンプトを主に128トークンのブロックへ分け、生成時は1トークン単位で処理する。KV予算は2K、4K、6K、8Kを掃引する。推論課題ではDeepSeek-R1-Distill-Llama-8B/Qwen-7BをMath-500で評価し、滑動窓併用も調べる。遅延実験ではLlama 3.2-3B-Instruct、A100 80GB、ブロックサイズ64/128/256で最初のトークンまでの時間を測り、通常注意とFlashAttentionの双方でTOVA/SnapKVと比較する。
固定KV予算を推論途中から守るメモリ制約型の長文推論が主対象で、一般的なサーバーで全プロンプトを一括プリフィルできる条件だけを想定した圧縮評価ではない。実GPU評価を含む一方、主要モデルはGQA系であり、MLA等への一般化は未検証である。
## 主要結果
KeyDiffは、処理途中から固定KV予算を守る難しい条件で、注意重み型削除より精度と遅延の両面で安定した。LongBenchではLlama 3.1-8B/3.2-3Bを中心に、6K予算で平均約33%のKV削減を行っても非削除基準からの低下を約1.5%に抑え、8K予算で約23%削減時には差を0.04%以下にした。注意重みを実体化しないためFlashAttentionを利用でき、Llama 3.2-3Bの最初のトークンまでの時間はTOVAやSnapKVより最大30%短い。推論課題ではDeepSeek-R1-Distill-Llama-8Bに滑動窓を併用すると非削除に近い性能を維持する一方、Qwen蒸留モデルでは削除感度が高く、万能な無損失法ではないことも示す。

- LongBench・6K KV予算 / 非削除基準から約1.5%低下、平均約33% KV削減 (比較対象: 非削除KVキャッシュ; 条件: Llama 3.1-8B-Instruct / Llama 3.2-3B-Instruct、主にブロックサイズ128) — 全プロンプトを一括保持せず処理途中から容量を制限しても、キー多様性による選択で大半の長文性能を維持できる。

- LongBench・8K KV予算 / 非削除基準との差0.04%以下、平均約23% KV削減 (比較対象: 非削除KVキャッシュ; 条件: Llama 3.1-8B-Instruct / Llama 3.2-3B-Instruct) — 比較的緩い予算では、実質的に基準精度を保ちながらメモリを削減できる。

- 最初のトークンまでの時間 / TOVA/SnapKV比で最大30%短縮 (比較対象: TOVAおよびSnapKV; 条件: Llama 3.2-3B-Instruct、NVIDIA A100 80GB、FlashAttention、複数ブロックサイズ) — 注意重み行列を実体化しないため高速注意を維持でき、削除スコアの追加費用を含めてもエンドツーエンド遅延を抑えられる。

- キー幾何と注意重要度の相関 / Spearman順位相関の平均約0.94±0.02 (比較対象: 負のキー余弦類似度と注意重みの比較; 条件: Llama 3.2-3B-Instruct、LongBench-Musique、各層平均) — キー空間で特徴的な方向が注意上の重要トークンを代理できるという中心仮説を複数層で支持する。

- Math-500・Llama蒸留モデル / 8K生成・4K予算でFlex 0.844 / Exact 0.634、非削除0.840 / 0.628 (比較対象: DeepSeek-R1-Distill-Llama-8B非削除; 条件: KeyDiff＋滑動窓、複数応答平均) — 生成が長い推論でも適切な予算と直近保持を組み合わせれば、削除なしに近い、場合によっては僅かに上回る結果を得る。

### 負の結果・境界条件
- 極端な容量制約では削除による情報損失が避けられず、全課題で非削除と同等になるわけではない。DeepSeek-R1-Distill-Qwen-7BではLlama蒸留モデルより低下が大きく、著者らはQwenの少ないKVヘッドによる情報圧縮が削除感度を高める可能性を指摘する。Phonebook Lookupでも文脈が長くなるほどKeyDiffの検索精度は低下し、完全保持との差が広がる。全プロンプトを一括処理できる十分なメモリがある場合には、将来を含む注意重みで重要度を測れる注意型削除が有利になり得る。

### 結果の読み方
改善の核は『より賢い注意重み集計』ではなく、重要度推定から注意行列への依存そのものを外したことである。ブロック処理では未来クエリが見えないため現在の注意重みは不完全だが、キー自身の方向的な希少性は将来ブロックが来ても変わりにくい。加えて平均アンカーとの線形スコアに落としたことで、削除処理が長文推論の新しい二乗ボトルネックになることを避け、高速注意の利点も保持する。
## 品質への影響
近似KV削除であり品質は予算依存。8K程度ではほぼ無損失に近いが、6K以下やモデル構造によって低下する。モデル重みや算術精度を変更しないため、品質変化は保持する文脈トークンの選択だけから生じる。
## 既存研究との差
H2O、TOVA、SnapKVなどは注意重みを観測して過去KVの重要度を推定するのに対し、KeyDiffは注意重みを一切使わずキー空間の多様性だけで選ぶ。これにより、将来ブロックが未観測な逐次プリフィルでもスコアの意味が崩れにくく、注意行列を実体化しないFlashAttentionとの併用も可能になる。KVQuantやKIVIのような量子化は各KVを残したままビット幅を下げ、Questなどの疎注意は保持KV全体から読み出す部分を減らすのに対し、KeyDiffはキャッシュからトークン単位のKVそのものを削除して容量を固定する。
## 限界
主評価はLlama/Qwen系のGQA注意で、MLAなど別形式への拡張は将来課題である。キー多様性は将来クエリ重要度の代理であり、厳しい予算では情報損失が避けられない。モデルによって削除感度が異なり、Qwen蒸留モデルではMath-500の低下がLlamaより大きい。全プロンプトを十分なメモリで一括処理できる場合は完全な注意重み型選択が有利になり得る。コードが非公開なので、公開実装間でのカーネル最適化や本番統合コストの比較は不足している。
## 実装状態
NeurIPS 2025採択論文として手法・擬似式・複雑度・実験設定は公開されているが、著者は論文チェックリストで実装コードは独占的で非公開と明記する。アルゴリズム自体は平均キー、余弦類似度、上位選択、同一インデックスによるK/V収集で実装可能である。
## 研究上の位置づけ
KVキャッシュ最適化の中では、量子化・オフロード・ページングとは異なるトークン削除系統に属する。特にサーバー全体の容量管理ではなく、単一要求の長文を固定メモリ内で最後まで処理する局所的なキャッシュ選択を狙う。端末側推論やGPUメモリ割当が小さい環境で、全プロンプトを一括保持できない場合の基盤技術として位置付けられる。
