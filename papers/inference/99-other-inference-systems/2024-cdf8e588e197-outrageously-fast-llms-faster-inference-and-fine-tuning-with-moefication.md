# Outrageously Fast LLMs: Faster Inference and Fine-Tuning with Moefication and LoRA

## 概要

本報告は、既に学習済みの密なTransformerを再学習なしに部分活性化型の専門家モデルへ改造し、その際に失われたタスク精度を低ランク適応で回復する二段階の実験を扱う。第一段階はFFNの隠れニューロンを複数の小さな専門家へまとめ、入力ごとに一部の専門家だけを選択するMoEficationである。第二段階は、疎な専門家をまたぐ行列補正を避けるため、独立して常時活性化するLoRA相当の枝を追加する。重要なのは「MoE化すれば常に速い」という結果ではないことだ。T5-smallでは通常モデルより約35%遅く、T5-baseでも補正枝を加えると約1.4%遅い。他方、T5-3Bでは元の推論時間の71.1%となり、大きなモデルでは演算削減がルーティングとメモリ移動の固定費を上回る。分類精度の測定はT5-baseだけであり、3Bで品質が維持された証拠はない。

この成果は2024年冬学期のStanford CS224Nの学生プロジェクト報告である。査読済みのMLSys/NeurIPS論文や、2026年のMoEサービング実測と同列に一般化しない。書誌の月は同学期の最終レポート提出月を採用し、ウェブ公開の厳密な日付を意味しない。

## 問題設定と対象

密なTransformerのFFNでは、トークンごとに大部分の中間ニューロンを通す。FFNの一部が特定の入力でほとんど活性化されないなら、重みを専門家群に分け、必要な群だけ実行すれば計算量を減らせる。しかし既存チェックポイントのFFNはもともと疎なルーティングを前提に学習していない。学習済み重みを分割しても、ルータの予測が外れれば重要な専門家を実行できず、品質が落ちる。また専門家ごとの小行列積、散布・収集、ルータ推論の固定費が発生する。そこで、密なモデルを再学習するのではなく、事後変換と小さな補正枝の組み合わせが有効かを問う。

対象はT5-small、T5-base、T5-large、T5-3Bというエンコーダ・デコーダ型の系列であり、現在主流のdecoder-only生成モデルそのものではない。精度評価はT5-base（約220Mパラメータ）のSST-2、MNLI、RACE分類で行う。性能評価はRTX 3090での単体推論時間であり、同時リクエスト数、分散推論、KVキャッシュ、連続バッチ処理の性能を測った研究ではない。

## 手法：FFNの分割から低ランク補正まで

### 1. FFNを均等サイズの専門家へ再構成する

通常のFFNは入力隠れ状態を中間次元へ射影し、非線形変換後に元の隠れ次元へ戻す。著者らは入力側行列と出力側行列の中間ニューロン対応を保ちながら、制約付きk-meansでクラスタ化する。T5-baseでは中間次元3072を96個の専門家へ分割し、各専門家は32ニューロンを担当する。単なる任意のブロック分割と違い、同じ入力で活性化される傾向を利用して、少数の専門家を実行したときの誤差を抑える意図がある。元の密な行列積は専門家出力の総和として書き直せるため、全専門家を実行する限りは構造上の計算を保持できる。

### 2. 中間活性からルータを教師あり学習する

学習用入力を既存モデルに通し、FFNに入る隠れ状態と専門家の活性を記録する。その観測値から、二層MLPのルータが各専門家の重要度を推定できるように学習する。推論時にはルータが入力を受け取り、96個のうち20個を選ぶ。残り76個の専門家のFFN演算を省くため、理想的には大きな演算削減が得られる。ただしルータの順位誤差により、密なFFNに寄与していた専門家を落とす可能性がある。論文は全計算の出力に照らして最適な専門家を事後選択する「MoEfied GT」も設け、実用ルータの精度低下と、疎化そのものの不可避な低下を区別している。

### 3. 専門家構造を壊さない常時活性LoRA枝

密なFFNの二つの射影行列へ通常のLoRAを直接足すと、元の専門家境界を横断する交差項が現れ、どの専門家を計算すべきかという疎な実行規則と衝突する。著者らは、既存の専門家の行列をすべて低ランク補正する代わりに、専門家出力の総和とは別の低ランク枝を設ける。この枝はルータの選択に関係なく常に実行され、タスク固有の情報を補う。T5-baseではランク32とし、各専門家の中間幅32に揃えている。補正枝の追加は計算を無料にするものではなく、常時活性の分だけ小さな実行費用を増やす。品質回復と実行時間の両方を同時に測る必要がある。

### 4. 訓練と推論の流れ

実行前には既存のT5重みを取り込み、ニューロンをクラスタ化し、活性スナップショットを収集してルータを学習する。タスク適応時にはルータと専門家を持つモデルに補正枝を加え、LoRA相当部分を更新する。推論時には、入力を受けた各FFNでルータが20専門家を選び、それらの出力に常時活性枝の出力を足して後段へ渡す。したがって本手法はモデルの量子化でも、注意機構のKVキャッシュ圧縮でもない。FFNの条件付き演算とタスク適応の結合である。選択する専門家数を減らすほど演算は減るが、情報損失やルータ誤りが増えるため、単純な疎度最大化は目的にならない。

## 評価設計

原著のTable 1〜4、Figure 1、および§5の分析を照合した。SST-2は感情二値分類、MNLIは三値の自然言語推論、RACEは四択読解であり、生成文の品質ではなく選択肢の正答率を評価する。T5-baseを共通基準に、密な元モデル、全計算に基づく専門家の理想選択、実用MLPルータ、実用ルータ＋LoRA枝、実用ルータ＋全面微調整を比較する。RACEだけは事前学習済みモデルを元タスクに適応するための全面微調整を先に実施して基準モデルを作る。

| 項目 | 原著の条件 |
|---|---|
| 品質評価モデル | T5-base、FFN中間幅3072 |
| 専門家構成 | 96専門家、各32ニューロン、推論時20専門家選択 |
| LoRA | ランク32、3エポック、学習率1e-3 |
| RACE基準モデルの調整 | 全面微調整3エポック、学習率1e-4 |
| SST-2 | 約67.3k学習例、バッチ64、最大512トークン |
| MNLI | 約393k学習例、バッチ8、最大1024トークン |
| RACE | 約87.9k学習例、バッチ4、最大1536トークン |
| 推論時間 | NVIDIA RTX 3090、GPU同期前後の経過時間、最初の10試行を除外 |

推論時間は各T5サイズの元モデルを100%として正規化している。100%より小さければ高速、100%より大きければ低速である。表の71.1%を「71.1%高速化」と解釈してはいけない。時間比71.1%は約28.9%の時間短縮、速度倍率では約1.41倍に相当する。品質測定と速度測定で対象サイズが異なることにも注意する。

## 主要結果

### 分類正答率：ルータの損失を補正枝が回復

| 条件 | SST-2 | MNLI | RACE |
|---|---:|---:|---:|
| 密なT5-base | 93.9% | 85.6% | 71.6% |
| 理想的な専門家選択（GT） | 93.5% | 85.0% | 70.1% |
| 学習済みMLPルータ | 92.3% | 83.5% | 67.5% |
| MLPルータ＋LoRA枝 | 93.1% | 85.3% | 69.7% |
| MLPルータ＋全面微調整 | 93.2% | 84.5% | 67.9% |

SST-2ではMLPルータ単独の92.3%がLoRA枝で93.1%に戻るが、元モデルの93.9%には届かない。MNLIでは83.5%から85.3%に改善し、原著の理想専門家選択85.0%をわずかに超える。RACEでも67.5%から69.7%に回復するが、元モデル71.6%との差1.9ポイントは残る。全面微調整はSST-2で93.2%と僅かに上回るものの、MNLI84.5%、RACE67.9%ではLoRA枝より悪い。パラメータを多く更新するだけでは、選択されない専門家が担う情報を戻せない可能性が示唆される。ただし、理想選択は密な出力を観測して決める評価用上界であり、実際の推論でそのまま利用できるルータではない。

### 推論時間：サイズによって符号が逆転する

| モデル | 元モデル | MoE＋MLPルータ | MoE＋LoRA枝 |
|---|---:|---:|---:|
| T5-small | 100.0% | 134.8% | 135.1% |
| T5-base | 100.0% | 98.8% | 101.4% |
| T5-large | 100.0% | 85.8% | 88.9% |
| T5-3B | 100.0% | 71.8% | 71.1% |

小型T5では、専門家の散布・収集、メモリアクセスの費用が、FFNの演算削減を上回る。T5-smallのMoE＋LoRAは元の1.351倍の時間を要し、T5-baseも1.014倍である。T5-largeでは11.1%、T5-3Bでは28.9%の時間短縮を達成する。T5-3BにおけるLoRAありの71.1%とLoRAなしの71.8%の差は小さく、LoRAが一般的に速度を改善すると主張できる規模ではない。原著Figure 1ではサイズと時間のべき関数近似が提示され、密なモデルは指数約0.88、MoE版は約0.725の傾向が示されるが、測定された四サイズでの経験則であって任意のLLM規模への外挿保証ではない。

### 負の結果と原因分析

原著§5は小型モデルの遅さをルータ計算そのものより、GPU上の専門家入力のscatter/gatherとメモリ移動に帰している。小さい行列積を多数に分割すると、理論FLOPsの減少が壁時計時間に結びつかない。SST-2の誤分類23例では、肯定を否定としたもの15例、否定を肯定としたもの8例で、曖昧な感情表現や比喩的表現が残る。著者は長尾の専門知識が選択されにくい専門家に分布している可能性を述べるが、これは定量的な因果実証ではなく、失敗例からの仮説である。

## 既存研究との差と位置付け

従来のMoEficationは、学習済みの密なFFNを専門家へ変換し、疎な選択で計算を省くことを主眼とする。本報告の差分は、その変換後のルータ誤差による品質低下を、専門家構造を崩さない常時活性の低ランク枝で補正する点にある。普通のLoRAを各FFN射影へ直接加える設計とは、専門家を横断する交差項を避ける構成が異なる。LoRAを追加すれば必ず元モデルの品質へ戻るという結果ではなく、タスクごとに残余誤差があり、サイズによって速度損益も変わる。

現在の大規模MoEサービング研究では、専門家並列、通信、ルータ偏り、バッチング、メモリ階層などが重要になる。本報告のRTX 3090単体測定はそれらを直接扱わない。したがって「3Bで約29%短縮」は同条件のT5系での実測として有用だが、分散GPUでのトークン毎スループットや商用推論のSLO改善と読み替えられない。逆に、小規模で疎化が遅くなる結果は、FLOPsと実測速度を分けて評価するうえで重要である。

## 限界・再現性・実務上の注意

第一に、品質はT5-baseの分類3タスクだけで確認されている。T5-3Bでの精度、長文脈生成、対話の継続性、推論時の複雑なデコードを評価していない。第二に、ルータの学習、クラスタ化、活性スナップショット取得には前処理コストがある。推論時に省ける計算だけで、変換の総所有コストを判断してはいけない。第三に、専門家ごとのscatter/gatherが実装依存であり、GPUやFastMoE実装が変わると損益分岐点が動き得る。第四に、分類結果は元の密なモデルに届かないタスクがあり、精度を厳密に維持する方式ではない。第五に、モデルのエンコーダ・デコーダ構造とGPU上の単体実行に依存し、現代のdecoder-only MoEで同じ効果を期待するには再実験が必要である。
