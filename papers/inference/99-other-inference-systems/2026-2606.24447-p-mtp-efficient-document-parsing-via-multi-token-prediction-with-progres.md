## 概要

画像から表・数式・文書の構造化テキストを生成する視覚言語モデル（VLM）は、入力画像を一度理解した後も、MarkdownやHTMLなどの出力を一トークンずつ自己回帰的に生成する。この復号処理は、表のセルやタグのように規則的な文字列が長く続く場合にも、毎回重い基盤モデルの前向き計算を要求する。複数トークン予測（MTP）を使って将来のトークンを軽量に先読みし、基盤モデルで検証してまとめて確定できれば、同じ意味内容をより少ない大規模推論回数で生成できる。

P-MTPはこの先読みを文書解析へ適用する研究であり、二つの問題に対応する。第一に、先読み深度Kを増やすほど遠い位置の予測が不確実になり、全深度に同じ重みで損失を与えると学習が不安定になる。第二に、推論時に固定長のdraftを出すと、容易な表タグでは先読み能力を使い切れず、難しい内容では多くの候補が棄却される。著者らは訓練時に経路信頼度と目標トークンの整合性で損失を動的に重み付けするProgressive Curriculum Loss（PCL）、推論時に累積候補確率で先読み長を変えるConfidence-Gated Dynamic Drafting（CGDD）を組み合わせる。

最も大きい5.24倍という数値は、Qwen3-VL-2BでPubTabNetの表解析を行う際の**単体復号遅延**26.71→5.10の比である。精度指標TEDSは85.09→84.78と0.31点低下した。一方、vLLMのバッチサイズ4〜64で測ったトークン/秒の改善は1.52〜1.59倍であり、同じ「5倍高速化」と表現してはいけない。文書全体の解析では精度低下がより大きい例があり、先読み深度を18へ伸ばすと速度・精度が悪化する。（一次論文Table 2〜10と補足を照合）。

## 問題設定と既存手法

通常の次トークン予測（NTP）は、長さTの出力を得るためにおおむねT回の自己回帰的な前向き推論を行う。MTPは一回の基盤モデル推論に対して、軽量モジュールでK個先まで候補を生成し、基盤モデルによる検証で採用できた先頭連続トークンを確定する。採用率をα、軽量MTPモジュールの一深度当たりの相対計算費をγとすると、論文は理論的な高速化の近似をS≈(1+αK)/(1+γK)と示す（式1）。この式は単純にKを大きくすれば速くなるとは言っていない。深い候補が棄却されればαが下がり、MTPの計算が増えればγKが大きくなる。したがって、先読み長と採用率、追加演算量のバランスが重要である。

Medusaのような複数headを並列に置く方式は、将来トークン同士の依存を十分に表現できないことがある。EAGLEやDeepSeek-V3に代表される逐次的な特徴空間draftは依存を捉えやすいが、深い先読みの学習が難しく、headを増やすほど演算費用も増える。既存方式では通常Kが3程度以下に抑えられる。文書解析では視覚情報から定まる文字列や構造タグが多いため、正確に予測できる箇所では深い先読みが有利な一方、数式や意味の切り替わりでは固定長の先読みが無駄になる。

P-MTPの重要な区別は、基盤モデルそのものの計算量を一律に減らす圧縮手法ではなく、候補生成と検証の実行回数を減らす復号高速化であることにある。MTPで生成した候補がすべて受理されるわけではなく、基盤モデルが検証した結果に従って確定する。論文の実験は文書解析を中心に構成され、汎用対話・コード生成で同じ採用率を保証しない。

## 手法

### 軽量な逐次共有MTPモジュール

P-MTPは基盤VLMの隠れ状態と候補トークンの埋め込みを入力とし、RMSNorm、連結、線形縮約、残差MLPを組み合わせた共有モジュールを逐次再利用する。深度kの特徴状態は一つ前の特徴状態と対応するトークン埋め込みを融合して作り、共通の言語モデルheadから将来位置の予測確率を得る（原著式2）。深度ごとに重いTransformer層を複製するのではなく、同じ軽量MLPを繰り返す設計である。

Table 1では逐次共有MLPがTEDS 84.78、遅延5.53、平均受理長7.29を達成した。逐次共有DecoderLayerはTEDS 84.84と僅かに高いが、遅延7.85、受理長6.27である。並列共有DecoderLayerは受理長7.26でも遅延9.53となる。したがって、候補を長く予測できることだけでなく、候補一個を作る追加費用が低いことが必要である。最良のTEDSだけを理由に重いheadを選ぶと、実時間の利得を失う。

### Progressive Curriculum Loss：先読み経路の信頼度で訓練する

訓練の目的関数は基盤モデルの次トークン予測損失と、K個の先読み予測の損失を足し合わせる。従来の一様な深度重みや固定指数減衰では、学習の初期から難しい遠方位置に強い損失を与えたり、逆に遠方位置をいつまでも弱くしか学習させられなかったりする。PCLは位置tと先読み深度kごとに異なる動的重みω(t,k)を使い、近い予測が安定した後で遠い予測へ学習負荷を移す。

一つ目のSequential Path Constraintは、深度kまでの先行する正解トークンに割り当てた確率を累積積として求める（式6）。近い位置の正解確率が低い経路では、その後の遠い位置の予測に対する訓練信号を小さくする。例えば直前の予測が不確かなのに、その予測を前提に5トークン先を強く学習させても、誤った経路を強化しかねない。累積積は経路の一貫性を表す重みとなる。

二つ目のRetrospective Target Constraintは、同じ目標トークンを異なる近距離の起点から予測したときの正解確率を累積する（式7）。遠くから見た予測だけが偶然高確率でも、近づいてきたときに一貫して正しい目標を指していなければ、遠方予測への学習重みを抑える。二つの重みを掛けたω(t,k)=ω1(t,k)×ω2(t,k)で、MTPの各深度・位置の交差エントロピーを重み付けする（式8・9）。これは学習の進行に応じて短い予測から長い予測へ重点が移る自動的なカリキュラムである。

Figure 3では訓練ステップが進むにつれて、先読み深度1〜9の損失構成比が近距離から遠距離へ移動する。Table 3ではω1単独で4.22倍、ω2単独で4.39倍、両者の積で4.83倍の固定draft高速化が報告された。これらは同一PubTabNet条件の比較であり、どちらか片方の重みだけで完全版と同等になるわけではない。

### Confidence-Gated Dynamic Drafting：推論時に候補長を変える

固定K個の候補を毎回出すと、容易な領域ではKを超えて予測できても打ち切られ、難しい領域では後半候補が棄却されて計算を浪費する。CGDDは訓練時の深度Kより大きい最大候補数H=2Kを許し、候補列の各トークン確率の累積積が閾値δを上回る範囲までdraftを伸ばす（式10）。累積信頼度が閾値を下回ったらそこで打ち切る。これは局所的な一トークンの最大確率だけでなく、先行候補を含めた経路全体の信頼度を評価する。

閾値δは訓練済みモデルの損失・信頼度を用いて調整する。具体的には、収束後の検証損失L̄、訓練深度K、感度係数λを用いてδ=δ_base×exp(λL̄/K)と定義する（原著式11）。δ_baseは0.3、λは通常2と記載され、学習損失が大きいモデルほど閾値を上げて慎重に先読みする。閾値が常に最適であると保証するものではなく、推論時の確信度を調整する経験的な仕組みである。信頼度の高い表タグの連続などでは長い候補を許し、確信の低い箇所では短くする。最終的な受理は基盤モデルの検証で決まるため、ゲートが正しいと予想した候補を無条件に採用するわけではない。過度に長い候補を作れば、軽量モジュールであっても追加計算と検証の費用が増える。

AppendixのTable 9ではK=9のモデルに対し、最大draft深度K、1.3K、2K、3Kの順に平均受理長が7.38、8.38、8.60、8.75と増える一方、遅延は5.67、5.17、5.10、5.24となった。最大受理長の3Kが最速ではない。論文は2Kを実用的なバランスとする。これがCGDDの価値と限界を同時に示している。

## 評価条件

一次資料はECCV 2026の23ページの著者原稿（本文、補足実験、参考文献）を使用した。主な性能測定は単一のNVIDIA A100 40GB GPU上で実施された。訓練は2エポックで、第1エポックに標準の教師あり微調整を行い、第2エポックにMTPの目的関数を追加する。基盤モデルの最大学習率は1×10^-5、MTPモジュールは5×10^-5、ウォームアップ比率0.05、全体バッチサイズ8と記載されている。表にはPubTabNet、数式にはUniMERNet、文書全体にはOmniDocBenchを用いる。文書全体の公開訓練データはLightOnOCR-2の約42万サンプルであり、後述の社内約150万件との違いを混同しない。主なablationはPubTabNetの表認識でQwen3-VL-2Bを用い、構造的な表類似度TEDS、生成遅延、平均受理長τ、高速化倍率を報告する。実装のサービング評価ではvLLMのバッチサイズを4、16、32、64に変えてTPSを測る。一般化の評価はInternVL3.5-1B、Qwen3-VL-2B/4B/8B、PaddleOCR-VL-1.5-0.9B、数式・表・文書全体を含む。

## 評価結果

### 表解析の遅延と精度

| NTP基準 | 85.09 | 26.71 | 1.00 | 1.00倍 |
| K=3、PCL・固定draft | 85.00 | 9.34 | 3.81 | 2.86倍 |
| K=3、PCL・動的draft | 85.00 | 7.79 | 5.39 | 3.43倍 |
| K=6、PCL・固定draft | 84.80 | 6.52 | 5.93 | 4.10倍 |
| K=6、PCL・動的draft | 84.80 | 5.85 | 7.67 | 4.57倍 |
| K=9、PCL・固定draft | 84.78 | 5.53 | 7.29 | 4.83倍 |

Table 2の値から、K=9での動的draftは固定draftに対して遅延5.53→5.10、平均受理長7.29→8.60の追加利得を持つ。基準TEDSとの差は0.31点で小さいがゼロではない。K=3ではTEDSが85.00、K=6では84.80であり、先読み深度を深くすると表解析品質がわずかに低下する傾向がある。対照の一様重みK=9ではTEDS 82.54、遅延7.82、高速化3.42倍で、深い先読みを単純に増やしただけでは品質と速度がともに悪化する。固定減衰K=9はTEDS 85.33とPCLより高い一方、遅延5.95とPCLより遅い。したがってPCLが全評価軸で常に最良というわけではない。

Table 1のhead比較では逐次共有MLPの遅延5.53、TEDS 84.78、受理長7.29に対し、逐次共有DecoderLayerは7.85、84.84、6.27となる。モデルを重くすれば精度がわずかに上がっても実時間の高速化が失われる。軽量な共有モジュールという設計選択は単なる実装詳細ではなく、MTPの理論式にある追加費用γを抑えるための重要要素である。

Table 4のTPSはバッチ処理のスループットである。基準は標準のSFTモデルによるNTPであり、P-MTPはK=9のPCLとCGDDを使う。単体遅延の5.24倍をそのままバッチ処理能力へ換算することはできない。基盤モデルの検証、バッチ内の不均等な候補長、サービング基盤のスケジューリングなどが効率を制限するためと考えられるが、論文はこの要因をすべて分離計測したわけではない。結果は特定のvLLM構成における測定であり、任意の同時ユーザー数やp99遅延を示すものではない。

Appendix Table 6ではQwen3-VLの2B、4B、8Bに対して、TEDSがそれぞれ85.09→84.78、86.68→86.60、86.30→86.20、遅延が26.71→5.10、34.25→8.43、45.14→10.21となった。平均受理長は8.60、10.92、11.67へ増加するが、モデルが大きいほど高速化倍率が単調に増えるわけではない。PaddleOCR-VL-1.5-0.9Bでは表TEDS 81.05→82.03、TPS 4454→6034で約1.35倍の改善である（Table 7）。これらは対象モデルとタスクの条件が異なるため、速度比だけで優劣を断定できない。

### 過大な先読み深度の負の結果

補足Table 10はK=9とK=18を比較する。PCLとCGDDを使うK=9ではTEDS 84.78、遅延5.10、受理長8.60、5.24倍である。K=18ではTEDS 83.75、遅延5.20、受理長9.00、5.13倍となり、**候補がより長く受理されても速度と品質は悪化**する。追加のdraft生成と検証費用が受理長の小さな増分を上回るからである。一様損失でK=18を訓練するとTEDS 77.18、遅延17.32、受理長1.53、1.54倍まで崩れる。深い先読みの学習安定性と推論費用の両方が限界となることを示す。

## 既存研究との差

Medusaは並列headを用いるが、候補間の逐次依存を十分に表せない。EAGLE系列は特徴空間のdraftを使い、DeepSeek-V3のMTPも逐次予測を利用するが、P-MTPは文書解析の規則的な出力に合わせて共有MLPを軽量化し、深度ごとの損失重みを経路信頼度で動的に変える。固定的な深度減衰では遠方の予測を学習しきれない場合があるのに対し、PCLは近距離の正解確率が高くなってから遠距離の学習を強める。CGDDは訓練済みの先読み能力を使い、推論時の最大深度を固定Kより広げながら、累積信頼度で不確かな候補を打ち切る。

一方、単純にトークン数を減らす視覚トークン枝刈りやKVキャッシュ量子化とは異なり、P-MTPは生成過程の計算回数を減らす方式である。前処理の視覚エンコーダが重い場合、生成が速くなっても文書全体の処理時間が同じ倍率で短縮するとは限らない。論文は生成遅延とvLLMのTPSを報告するが、画像取り込み、後処理、複数文書の並列処理などを含めた一貫した業務システムのエンドツーエンド時間をすべて計測したものではない。

## 限界と適用条件

最も重要な限界は、5.24倍の速度改善が表解析の単体復号条件で得られた値であり、vLLMバッチスループットの1.52〜1.59倍とは異なる点である。また精度劣化は表TEDSでは小さいが、文書全体や数式認識ではより大きくなる条件がある。訓練データの質と規模、文書の構造的規則性、基盤モデルの予測確信度に性能が依存する。社内約150万件データで改善するという補足実験は、外部再現の容易さを保証しない。

候補の受理率はコンテンツの予測しやすさで変わる。自由形式の長文推論やコードのように、次トークンが不確かな領域ではCGDDが短い候補に戻る可能性がある。先読み深度を過度に大きくすると、候補生成・検証費用が増えて逆に遅くなる。K=18の負の結果があるため、深度を無制限に伸ばせば性能が上がるとする一般化は避けるべきである。

また、追加モジュールの訓練費用、再学習に必要なデータ、基盤モデル更新時の互換性、GPUごとの検証カーネル効率、サービング時のメモリ使用量などは導入判断に重要だが、報告された速度比だけでは十分に評価できない。実務では自分の文書分布と精度許容値で、表・数式・文書全体を分けて検証し、単体遅延と並列スループットをそれぞれ測る必要がある。
