# Training with Quantization Noise for Extreme Model Compression：極端なモデル圧縮のための量子化雑音学習

## 概要

学習済みモデルの重みを低ビットや積量子化で保存すると、推論時の重み容量を減らせるが、各層で生じた量子化誤差が次層の入力へ蓄積し、精度が急激に落ちることがある。一般的な量子化認識学習（Quantization-Aware Training; QAT）は全重みを順伝播で量子化し、非微分な丸め処理の勾配を直通推定（Straight-Through Estimator; STE）で近似する。しかし、圧縮が強い場合にはこの勾配近似の偏りが大きくなり、全重みを同時に量子化する学習が不安定になる。

本論文の量子化雑音（Quant-Noise）は、**毎回の順伝播で無作為に選んだ一部の重みブロックだけへ量子化誤差を加える**。残りのブロックは元の重みを使い、偏りのない勾配が流れる機会を維持する。量子化を受けるブロックは毎回変わるため、学習後のモデルは強い量子化へ耐えやすくなる。ICLR 2021の原著では、16層Transformerの942MBを反復積量子化で38MBへ圧縮した場合、量子化雑音なしのテスト困惑度25.2に対して20.7へ改善した。RoBERTaは14MBでMNLI精度82.5%、画像モデルEfficientNet-B3は3.3MBでImageNetの正解率80.0%を達成した。

## 問題設定と背景

単純な固定小数点量子化は、各重みを例えば8ビット整数へ丸め、適切な演算器で推論を高速化できる。しかし4ビット以下やベクトルをまとめる積量子化では、誤差が大きくなりやすい。積量子化（Product Quantization; PQ）は重み行列の部分ベクトルをクラスタの代表値へ割り当て、代表値表と短い索引だけを保存する。保存容量を大きく減らせる一方、代表値へ置き換えた各層の出力が変わり、後段の入力分布までずれる。反復積量子化（iterative Product Quantization; iPQ）は下層から順に量子化して上層を再調整するが、依然として品質と容量の交換条件が残る。

全重みを量子化して学習するQATでは、量子化演算がほとんどの点で勾配0となるため、実際にはSTEで量子化を通り抜ける勾配を代用する。8ビット程度ならこの近似は機能することが多いが、代表値への大きな置換や極端な圧縮では学習方向の偏りが強い。著者の主張は、量子化の対象と誤差を学習中に部分的・確率的に制御すれば、全重みが毎回偏った勾配で更新される状態を避けられるというものである。

この研究は学習アルゴリズムを提案するが、目的は**推論時に用いる圧縮済み重みの品質と保存容量**である。学習時の一部量子化を推論時にもそのままランダム実行するわけではない。推論時には対象の量子化方式でモデル全体を圧縮し、必要なら代表値や整数演算を使う。学習費用と推論時のメモリ・演算を別々に評価する必要がある。

## 手法

### 1. 対象量子化に合わせて重みをブロック分割する

重み行列 $W$ をブロック $b_{kl}$ に分ける。固定小数点のスカラー量子化なら1重みが1ブロック、積量子化なら列の一部の部分ベクトルがブロックになる。圧縮方式ごとにどの単位が代表値へ写されるかが異なるため、量子化雑音も同じ単位へ与える。学習の各順伝播でブロック集合 $J$ を無作為に選び、$J$ 内には歪み関数 $\phi$ を適用し、それ以外は元の値を使う。

式では $\psi(b_{kl}|J)=\phi(b_{kl})$（選択時）、$\psi(b_{kl}|J)=b_{kl}$（非選択時）とする。これを組み立てた $W_{noise}$ で出力を計算し、逆伝播ではSTEを使う。全ブロックを選べば通常QATと同じ形になるが、一部だけを選ぶ場合には選ばれなかった重みへ非量子化の勾配が流れる。選択集合を毎回変えるため、長期的には各重みが量子化誤差へさらされつつ、偏りのない勾配を受け取る機会も持てる。

### 2. 固定小数点と積量子化で雑音の形を変える

固定小数点では、スケール $s$ とバイアス $z$ により $\phi_{intN}(w)=(\mathrm{round}(w/s+z)-z)s$ と丸めた値を使う。対象がint4またはint8なら、量子化後に現れる離散化誤差を学習時の一部ブロックへ注入する。丸め処理をそのまま微分できないためSTEを使うが、全ブロックが毎回丸められる場合と違い、非選択ブロックでは元の重みを経由して学習できる。

積量子化では、部分ベクトルをコードブックの最も近い代表値へ割り当てる。実際の代表値を使った歪みを毎ステップ計算するのは高価なので、著者は選択した部分ベクトルを0にする**代理雑音** $\phi_{proxy}(v)=0$ も提案する。これは量子化の厳密な再現ではなく、構造化された脱落（structured dropout）に近い摂動であり、後で代表値へまとめやすい重み構造を促す。代理雑音を使って学習し、最終的な圧縮はiPQで行う点を区別する必要がある。

### 3. 複数の圧縮方式と枝刈りを組み合わせる

量子化雑音の演算子は組み合わせられるため、重みの積量子化と8ビット整数化、さらに層の構造化脱落（LayerDrop）を一つの学習方針で扱える。iPQでは重み部分ベクトルを代表値索引へ置き換え、代表値も8ビットで保存し、活性値も8ビットにする構成を評価する。コードブックの代表値と各部分ベクトルの索引が主な保存要素となるため、単純に「全重みを8ビットへする」場合より高い圧縮率を狙える。

LayerDropを併用する場合は、学習中に一部の残差ブロックを落とし、推論時には必要な層数を削減する。層の枝刈りは演算量を減らし得るが、iPQの重み保存容量削減と同じものではない。量子化雑音は枝刈り後の品質を保つ学習上の補助手段であり、学習時のランダム脱落が推論時に残るわけではない。

### 4. 既存学習済みモデルへの適用

ゼロから全期間学習するだけでなく、既存モデルに量子化雑音を加えて追加微調整し、その後に圧縮する方法も検討する。WikiText-103の言語モデルでは追加10エポック、RoBERTaでは追加25,000更新を用いた。量子化済みモデルの品質を保つために追加学習が必要であり、推論だけで即時に同じ効果を得る事後量子化とは異なる。学習期間全体で量子化雑音を使った場合に比べ、追加微調整のみの結果はわずかに劣るが、元モデルを再学習する費用を避けられる。

## 評価

### 評価環境と比較対象

| 対象 | モデル・データ | 主な評価指標 |
|---|---|---|
| 言語モデル | 16層Transformer、WikiText-103 | テスト困惑度（低いほど良い）、圧縮後MB |
| 文章分類 | RoBERTa Base、MNLI | 開発集合の分類精度（高いほど良い）、圧縮後MB |
| 画像分類 | EfficientNet-B3、ImageNet-1k | 上位1件正解率、圧縮後MB |
| 追加検証 | ResNet-50、ImageNet | 同じ圧縮率での分類精度 |
| 圧縮手法 | int4、int8、iPQ、iPQ＋int8、共有・枝刈り | QATや雑音なしの比較、圧縮率 |

原著はPyTorch、言語モデルとRoBERTaにfairseq、画像分類にClassy Visionを使う。モデルサイズは重みの保存容量であり、実行時GPUのピークメモリ量ではない。困惑度は正解語の予測確率に関する指標であり、小さいほどよい。画像分類の上位1件正解率とMNLI精度は別タスクの指標なので直接比較できない。

### 16層Transformerの量子化方式別比較

| 方式 | 保存容量 | 圧縮率 | テスト困惑度 |
|---|---:|---:|---:|
| 元モデル | 942 MB | 1倍 | 18.3 |
| int4のみ | 118 MB | 8倍 | 39.4 |
| int4＋通常QAT | 118 MB | 8倍 | 34.1 |
| int4＋量子化雑音 | 118 MB | 8倍 | 21.8 |
| int8のみ | 236 MB | 4倍 | 19.6 |
| int8＋通常QAT | 236 MB | 4倍 | 21.0 |
| int8＋量子化雑音 | 236 MB | 4倍 | 18.7 |
| iPQのみ | 38 MB | 25倍 | 25.2 |
| iPQ＋通常QAT | 38 MB | 25倍 | 41.2 |
| iPQ＋量子化雑音 | 38 MB | 25倍 | 20.7 |
| iPQ＋int8＋量子化雑音 | 38 MB | 25倍 | 21.1 |

原著表1の比較では、iPQに通常QATを加えると25.2から41.2へ**かえって悪化**する。量子化雑音を使うと20.7まで改善し、同じ38MBという容量で大きな品質差が生じた。int8では雑音なし19.6、通常QAT21.0、量子化雑音18.7と差が小さく、強い圧縮ほど提案法の利点が顕著になる。一方、元の非圧縮モデル18.3には届かず、極端な圧縮に品質費用が残ることも確認できる。

### 画像分類と低ビット化の影響

| 方式 | EfficientNet-B3容量 | 圧縮率 | ImageNet上位1件精度 |
|---|---:|---:|---:|
| 元モデル（著者再実装） | 46.7 MB | 1倍 | 81.5% |
| int4のみ | 5.8 MB | 8倍 | 45.3% |
| int4＋通常QAT | 5.8 MB | 8倍 | 59.4% |
| int4＋量子化雑音 | 5.8 MB | 8倍 | 67.8% |
| iPQのみ | 3.3 MB | 14倍 | 79.0% |
| iPQ＋通常QAT | 3.3 MB | 14倍 | 55.7% |
| iPQ＋量子化雑音 | 3.3 MB | 14倍 | 80.0% |
| iPQ＋int8＋量子化雑音 | 3.1 MB | 15倍 | 79.8% |

原著表1では、3.3MBのiPQで通常QATを使うと55.7%まで悪化するのに対し、量子化雑音なら80.0%を保った。これはiPQに対する学習時の勾配処理が結果を大きく左右することを示す。int4では67.8%に留まるため、量子化雑音を使えばどの圧縮方式でも元モデルに近い精度になるわけではない。論文本文の画像モデル比較には別実装の基準値が登場するが、表1の同一比較では著者再実装の81.5%を基準に読む。

### 文章分類と共有・枝刈りによる極端な圧縮

原著表2では、RoBERTaの元モデル480MB、MNLI精度84.8%に対し、iPQのみ38MBで82.5%、iPQ＋量子化雑音38MBで83.6%となる。重み共有を追加すると14MBで82.5%、枝刈りを追加した別の構成では8MBで78.8%となる。**14MB・82.5%は重み共有を組み合わせた結果**であり、38MB・83.6%の設定と同一ではない。圧縮率を上げるほど精度が下がる場合があり、どの組合せを使ったかを併記する必要がある。

WikiText-103でも、iPQ＋量子化雑音38MBで困惑度20.7、重み共有追加19MBで22.0、枝刈り追加10MBで24.7という容量・品質の交換条件が報告される。元モデル942MB・困惑度18.3からの圧縮率は38MBで約25倍、10MBで約94倍である。枝刈りでは層やブロックを減らすため演算量の削減にもつながるが、単なる重み量子化の25倍圧縮を25倍の推論高速化と読み替えてはならない。

### 追加微調整と雑音率の感度

原著表3では、iPQ圧縮後の言語モデルの困惑度は、量子化雑音なし学習25.2、追加微調整で量子化雑音を導入した場合20.9、最初から量子化雑音で学習した場合20.7であった。RoBERTaのMNLI精度は順に82.5%、83.4%、83.6%。既存モデルへの追加微調整でも改善が大きく、ゼロからの再学習との差は小さい。一方、追加10エポックまたは25,000更新の学習費用を無視できない。

原著付録の雑音率実験では、iPQ用の代理雑音を重みの半数超に適用すると性能が悪化した。int8では高い雑音率の悪化は比較的小さいが、全ブロックへ雑音を加える設定は通常QATに近づく。したがって「雑音を強くすればするほど量子化耐性が上がる」とは言えず、対象量子化方式と選択率の調整が必要である。著者は学習速度の追加費用を5%未満と報告するが、これは学習時の費用であり、推論時の実測速度改善率ではない。

## 既存手法との差

通常QATは全重みを毎回量子化しSTEで勾配を近似する。量子化雑音は対象ブロックを無作為に限定することで、各重みが非量子化の勾配を受ける機会を残す。事後量子化だけでは圧縮誤差に適応できず、反復積量子化では層間のずれを順次補正するが、量子化雑音は学習過程自体を量子化誤差に頑健にする。蒸留・枝刈り・共有は容量削減の異なる操作であり、量子化雑音はそれらと組み合わせて最終的な容量・品質の選択肢を増やす。

## 限界と推論基盤への適用

本方式は推論時に必要な重み容量を減らすことが主眼であり、実機の生成トークン/秒、最初のトークン遅延、GPUメモリピーク、CPUオフロードの帯域、PCIe転送を体系的に測った研究ではない。固定小数点演算が速いかどうかは対象ハードウェアとカーネルに依存する。積量子化では代表値の復号や索引参照が必要であり、保存容量が25倍小さくても計算時間が25倍短くなるとは限らない。

評価対象は2020〜2021年の16層言語モデル、RoBERTa、画像分類器であり、現代の数十億〜数千億パラメータの生成LLMやMoEへの直接の性能保証ではない。学習中のランダムブロック選択、代理雑音の種類、量子化率に依存し、極端な圧縮では元モデルからの精度低下が残る。例えばWikiText-103の38MBモデルは20.7で元モデル18.3より悪く、RoBERTaの8MBモデルも元の84.8%から78.8%へ下がる。追加微調整が必要な場合には計算資源と元学習データへのアクセスが障壁となる。
