# FlashQuant：外れ値認識量子化の疎密融合GPU実行

## 概要

FlashQuantは、大規模言語モデルの重み4ビット・活性値16ビット量子化（W4A16）で生じる「低精度の密行列積と、高精度で残した少数の外れ値による疎行列積を別々に実行する」という問題を、GPUカーネルの内部構造から解決する研究である。外れ値を保存することは量子化精度を守る一方、疎行列用カーネルの起動、入力活性値の再読込み、中間出力の往復を追加する。自己回帰復号では小さいバッチで大きな重み行列を何度も読むため、こうした余分なメモリアクセスが性能を左右する。

提案は、低ビット密行列積（GEMM）と高精度疎行列積（SpMM）を単一の協調スレッド配列（CTA）に割り当て、同じ活性値タイルと出力部分和をオンチップで共有する**疎密の内容共有融合**である。密行列と疎外れ値を対応するタイルへ分ける階層化、疎要素のタイル局所符号化（Tile-COO）、列と要素の並べ替え、二重バッファによる先読みを組み合わせる。量子化アルゴリズムの精度向上そのものより、精度を守る疎経路の実行費用を抑えることが新規性である。

著者らはRTX 3090・4090・5090で340種類の演算子形状と外れ値密度を評価した。BF16のcuBLASに対するカーネル高速化は2.74〜4.18倍だが、これは4ビット量子化の効果も含む。融合の追加効果を表す非融合のSputnik＋Marlin比較では、3090で1.03〜1.16倍、4090で1.12〜1.37倍、5090で1.23〜1.53倍である。vLLMに組み込んだLLaMA3-8Bの復号では、バッチ8で56.9から114.4トークン/秒、バッチ16で56.1から107.6トークン/秒へ改善した。ただしGPTQ＋Marlin単独より遅く、品質改善のために外れ値を保持するという交換条件を伴う。一次論文の表3・表4と第5節に基づく。 

## 背景と問題設定

重みを一律4ビットへ圧縮すると、16ビットの重み保存に比べて必要な帯域と容量を削減できる。ところが同じ量子化尺度に大きな絶対値の重みを含めると、尺度が外れ値に引っ張られ、通常の小さい重みの量子化刻みも粗くなる。そのため外れ値だけをBF16で保持し、残りの重みをINT4へ変換する外れ値認識量子化がある。論文が示す例では、LLaMA3-8Bを通常のGPTQで量子化したWikiText2の困惑度（PPL）は6.896だが、外れ値を残した構成の一例では5.979まで改善する。困惑度は小さいほど言語予測の損失が低い指標であり、完全なBF16モデルの5.538と同一品質になったことを意味しない。

入力活性値をX、量子化密重みをW_Q、高精度疎外れ値をW_Oとすると、線形層は概ね `Y = X·dequant(W_Q) + X·W_O` と計算される。第一項は低ビット重みを読みながらテンソルコアで規則的に演算する。第二項は非ゼロ要素の位置情報を参照しながらCUDAコアで不規則な乗算加算を行う。二項を独立のGPUカーネルにすると、同じXを二度読み、出力Yへの寄与も別々に書く。これは外れ値率が1〜3%と小さくても、疎経路の追加データ移動とカーネル起動の固定費が目立つ理由である。

自己回帰生成では1ステップで処理するトークン数が小さく、重みの読み出しに対する計算量が小さい。RTX 5090の論文記載のピークテンソルコア性能209.5 TFLOPSとメモリ帯域1792 GB/秒は、演算器を使い切るには高い算術強度が必要であることを示す。バッチが小さい復号ではその条件を満たしにくい。したがって疎補正に伴うメモリ往復の削減は、計算量の削減以上に実行時間へ効く場合がある。

しかし密行列積は固定寸法タイルをテンソルコアに投入したい一方、疎補正は非ゼロ要素の分布が不規則で、出力列ごとの作業量が異なる。単に一つのカーネルにまとめるだけでは、スレッド間の仕事量不均衡、共有メモリのバンク競合、出力への競合書込み、レジスタ圧力が新たな律速になる。FlashQuantはこの違いをタイル階層・疎表現・ワープ割当の三層で解消する。

## 手法

### 1. 事前処理と疎密共通タイル

最初に既存の外れ値認識量子化に従い、元の重みをINT4の密行列W_QとBF16の疎行列W_Oに分離する。これはモデルのロード時に一度だけ行う事前処理であり、推論要求ごとに量子化し直すわけではない。W_Qを通常のテンソルコア行列積が利用する協調スレッド配列（CTA）タイルへ分割し、同じ行・列範囲に属するW_Oの外れ値を対応する疎タイルへ集約する。入力Xと出力Yの担当領域を揃えることで、密計算と疎補正が同一のオンチップ活性値を消費できるようにする。

CTAレベルでは一つの出力タイルに対する両経路を同居させ、活性値タイルを共有メモリへ一度だけ置く。複数CTAへの仕事の分配には、出力タイル数だけを均等に分ける方式で生じる偏りを抑えるため、積和演算の反復空間を分割するStream-K方式を採る。CTAは連続する演算範囲を受け持ち、場合によって複数の出力タイルにまたがる。分配と局所再利用を両立する設計であり、密疎の仕事を完全に同一命令列へ押し込むものではない。

ワープレベルでは役割を分ける。密経路はテンソルコア命令に適した断片へ分割し、K方向の部分和を各ワープが計算してCTA内で縮約する。疎経路はCUDAコアを用い、出力列の集合を疎ワープ間で重複しないよう割り当てる。単純に非ゼロ要素数だけで分配すると複数ワープが同じ出力へ加算するため原子的操作が必要になるが、列を排他的に担当すれば競合書込みを避けられる。疎側が待ちやすい場合は追加ワープを割り当て、疎処理の待機時間を隠す。

スレッドレベルでは密経路のテンソルコア用メモリ配置を維持しつつ、疎側は1要素ずつ活性値を読む。共有メモリが複数のバンクに分かれるため、疎スレッドが同じバンクへ集中するとアクセスが直列化される。論文は活性値に8要素の並べ替え配置を採り、疎ワープ内のスレッド群をさらにバケットへ分割する。タイル・ワープ・スレッドの三段階で、密経路の規則性を壊さず疎経路の不規則性を制御している。

### 2. タイル局所の外れ値符号化（Tile-COO）

通常の疎行列形式では行列全体の行・列位置を保存し、独立した疎行列積を効率化する。しかしFlashQuantでは密タイルと同じ境界を保ち、バケット単位で必要な疎要素だけを取り出すことが重要である。そこで三つの配列を持つTile-COOを使う。`tile_indptr`は各タイルの開始位置を32ビットで保持し、`bucket_info`はタイル内バケットの開始位置と非ゼロ数を16ビットで保持する。`packed_outliers`は行・列の局所位置とBF16外れ値をまとめて格納する。

最大共有メモリタイルが256×256であることを利用し、局所行・列の座標はそれぞれ8ビットで表せる。外れ値を4個ずつまとめて読み込む形式により、メタデータの読み出しと復号処理をベクトル化する。論文の容量式ではTile-COOの格納量は `(N_tile+1)×4 + N_B×4 + nnz×4` バイト、比較するCSR形式は `(K+1)×4 + nnz×12` バイトである。ここでnnzは非ゼロ要素数、N_Bはタイル数とバケット数から決まる。密重み全体の容量ではなく**疎外れ値表現の付加容量**を比較した式であることに注意する。

4個単位へ揃えるため、外れ値が少ない列には埋め合わせ要素が生じる。論文はこの空き領域へ元の重み値を保持して精度を補う余地も述べる。したがってTile-COOの効果は単純な索引圧縮だけでなく、密タイルと疎タイルを同じ実行単位へ揃え、共有メモリ上で連続的に復号できることにある。逆にタイルが小さくバケットが多すぎる場合は、タイルとバケットのメタデータ自体が無視できなくなる。

### 3. 列負荷均衡とバンク競合回避の二段階並べ替え

同じ疎密タイルでも外れ値は特定の出力列に集中し得る。列を元の順序のままワープへ配ると、一部ワープだけ非ゼロ数が多くなり、他のワープが終了してもCTA全体が待つ。FlashQuantは各タイルの列を非ゼロ数の多い順へ並べ、累積非ゼロ数が最も少ないバケットへ順次割り当てる。最小ヒープを用いる貪欲な配分であり、疎処理量を近づけながら出力列の担当を重複させない。

次にバケット内の要素順序を、共有メモリでアクセスするバンク群が重なりにくいよう調整する。論文では行インデックスkから `floor(k/2) mod 4` で群番号を作り、バケット番号によって群の巡回順をずらす。図5の例ではバンク競合数が4から1へ減る。列の並べ替えは**ワープ間の仕事量不均衡**を、要素の並べ替えは**同時メモリアクセスの競合**を対象にしており、別の問題を解く。両処理はモデル展開時に実施し、要求ごとの実行経路には持ち込まない。

### 4. 二重バッファと疎要素復号

オンライン実行では、グローバルメモリから活性値・量子化重み・疎タイルをロードし、レジスタや共有メモリに段階的に配置する。重みの逆量子化と疎要素の復号を次の演算と重ね、テンソルコアの密計算とCUDAコアの疎計算を進める。二重バッファにより現在タイルの演算中に次タイルのデータを準備し、グローバルメモリの待ちを隠す。

疎経路の各スレッドは担当バケットの開始位置と非ゼロ数を読み、4個単位に梱包された行位置・列位置・値を復号する。行位置は活性値の共有メモリ配置に合わせて並べ替え、対応する活性値をロードして4つの融合積和演算を進める。部分和をオンチップへ蓄積し、必要に応じてStream-Kの最終縮約を経て出力へ書き戻す。原著の第4.2節にある、バケット情報の読出し、次要素の先読み、4個単位の演算という処理順を保つことが重要である。

この実装は単に「疎密を一カーネルへまとめる」だけではない。密経路のテンソルコア断片と疎経路のCUDAコア断片を同じ活性値タイルへ対応させ、局所索引・負荷分配・二重バッファを通じてメモリ往復を削減する。疎要素が増えるほど補正演算そのものは増えるので、完全に無料で外れ値を扱えるわけではない。

外れ値密度を1%から3%へ増やすと、FlashQuantでも疎演算量は増える。しかしSputnikの非融合経路より遅延増加が小さいという傾向が報告される。密度が高いほど速くなるわけではなく、**悪化幅が比較的小さい**という意味である。GPU世代が新しいほど浮動小数点演算能力が増え、融合で増える計算の相対費用が下がる一方、削減できるメモリ往復の価値が残ると論文は解釈する。

### バッチ・事前処理・メモリ容量の感度

図8のRTX 4090でのバッチ感度試験では、バッチ32でもFlashQuantが非融合方式を上回る。一方、バッチが8未満の場合、実装は入力を最低8へ埋め合わせるため、バッチ1・2では不要な計算が増え、優位が縮小する。一般に「小バッチ復号に向く」と述べる際も、**最小バッチ8のパディング制約**を無視してはならない。バッチ1で常に最良とは原著は示していない。

事前処理はタイル整列・外れ値符号化・並べ替えからなり、図9では評価した全行列で100秒未満だった。これはデプロイ時の一回限りの費用で、定常推論のカーネル測定から除外される。モデルの頻繁なロード・切替がある場合、100秒未満であっても運用上無視できるとは限らず、初回ロードを含めた時間を別途測る必要がある。

図10の外れ値疎行列の保存費用は、密行列を基準とする相対値である。外れ値密度1.0〜3.0%で、CSRの付加容量が約3.0〜9.0%に対しTile-COOは約2.6〜6.6%に抑えられる。メタデータが外れ値値本体より大きくなる条件があるため、局所8ビット索引とバケット情報の圧縮が効く。ただしこれを「モデル全体の容量が6.6%」と読んではならず、疎補正表現の相対保存費用である。

## 既存研究との差と限界

既存のSpQRやSqueezeLLMは、どの外れ値を高精度に残し、残りを低ビット化するかという量子化・精度の問題を扱う。Marlinは低ビットの密行列積を高速化するが、高精度疎外れ値の追加計算を統合しない。SputnikやcuSPARSEは疎行列積を提供するが、密行列積と共通する入力・出力のタイルを一体化して最適化することを前提としない。FlashQuantは両経路の数学的な分離を保ちながら、実行の局所性だけを共有する点で異なる。MixQは活性値外れ値、FLUTEは参照表型量子化を対象にするため、論文の主比較とは演算の定義が違う。

第一の限界は、INT4の密重みとBF16の疎外れ値という特定の混合精度演算子に対象を絞っていることである。2ビット量子化、別の疎形式、複数GPU通信、長い文脈での注意KVキャッシュ最適化へそのまま拡張できる証拠はない。第二に、最小バッチ8の埋め合わせによりバッチ1・2では余分な演算が発生する。第三に、モデルロード時の疎並べ替えと符号化に最大100秒弱の前処理が必要で、頻繁にモデルを切り替える用途の総遅延を評価していない。

第四に、評価はRTX 3090・4090・5090の代表演算子と、vLLM上の2モデルの復号に集中している。GPUの共有メモリ容量、テンソルコア命令、ワープ数、帯域と演算比が変わると最適なタイル・ワープ配置も変わる。FP16/BF16元モデル比の倍率を他のGPUや高バッチ事前充填へ無条件に外挿できない。第五に、困惑度の改善は外れ値を高精度で保存するSpQR側の利点であり、融合カーネル自体がモデルの予測精度を向上させたと主張してはならない。実装の公式公開コードURLは確認できず、再現には論文記載のアルゴリズム・評価条件の再構成が必要である。
