# PRINMIX：SVD差分重みの量子化誤差から混合精度を最適化する

## 概要

PRINMIXは、同じ基盤LLMから多数の微調整済みモデルを提供する場面を想定し、各モデルに固有の**差分重みΔW**だけを圧縮する方式である。基盤重みを共有し、ユーザーやタスクごとに異なる微調整差分を保存・読み込むと、モデル全体を複数コピーするよりメモリとディスクを節約できる。ただし差分を極端に圧縮すると、微調整で獲得した数学、推論、コード、視覚言語の能力が失われる。

PRINMIXはΔWを特異値分解（SVD）し、低ランク因子の量子化ビット幅を一律にせず、各成分に異なるビット数を配分する。従来のDelta-CoMeは大きい特異値に対応するベクトルを優先して高精度にする経験則を採用するが、PRINMIXは実際の較正入力に対する**量子化再構成誤差**をビット幅候補ごとに推定し、総ビット予算の下で誤差を最小化する整数計画を解く。さらに先にVを量子化した結果を踏まえ、後から量子化するUの再構成目標を補正するRTCを追加する。

原著v3の7B級8評価平均では、差分を1/16へ圧縮したDelta-CoMeが71.9、PRINMIXが74.0、微調整済み非圧縮モデルが76.0である。7BのAIME2024では30.0から36.7へ改善する一方、13-14BではMetaMath Math500が22.9から21.7へ悪化する。提案方式は差分圧縮品質を改善するが、あらゆる評価で勝つわけではなく、整数計画の解法時間も無視できない。

## 問題設定：微調整差分を圧縮する際のビット配分

基盤モデルW_baseと微調整済みモデルW_ftの差分ΔW=W_ft−W_baseを保存すれば、複数のタスク特化モデルは共通のW_baseと個別のΔWから復元できる。差分のサイズが大きければ多テナント配信のメモリやディスクの負担が残るため、差分に低ランク近似と低ビット量子化を重ねる。これは基盤モデル全体をW4A8などにする通常の重み量子化とは別の問題である。

Delta-CoMeはSVDでΔWを分解し、特異値の大きさに応じて高精度ビットを割り当てる。特異値は重み行列のエネルギーの尺度になるが、較正入力を通した出力誤差や下流タスクでの重要度と必ずしも一致しない。大きな特異値を持つ成分へ多くのビットを使っても、同じ予算で最小の量子化誤差になる保証はない。PRINMIXはビット配分を経験則でなく、量子化後の再構成誤差に基づく離散最適化問題として定式化する。

差分重みのSVDではΔW=UΣVと表し、UとVの両因子を量子化する。片方を先に量子化すると、その時点で出力目標が変わるため、もう片方を元のUのまま量子化することが最善とは限らない。PRINMIXはビット割当と、この**量子化順序による誤差伝播**の両方を扱う点が特徴である。

## 手法

### 1. SVD差分の量子化誤差の分解

入力は差分行列ΔW、較正入力X、候補ビット幅集合Q、平均ビット予算G_bである。まずΔW=UΣVへ分解し、Vの各行と対応するUの各列を量子化する。単純な重み行列の二乗誤差ではなく、入力Xを通した出力の差、すなわち||ΔWX−ΔW_hat X||²_Fを小さくすることを目標とする。これはGPTQ系の再構成誤差をSVD因子へ適用したものである。

原著は二次近似を用いて、量子化された各行の誤差を較正入力から求める。特異値Σは量子化誤差に対するスケーリング項として効くが、同じビット数で量子化したときの実際の差分項も効くため、単に特異値の順位でビット数を決めるだけでは最適化にならない。候補ビット幅ごとにシミュレーション量子化を行い、Vの各行の誤差E_i^V(b)を計算して後段の最適化へ渡す。

ここで得るのは、候補の各ビット幅を採用した場合に、どのSVD成分の出力再構成がどれだけ悪化するかという誤差表である。これは数学やコード生成の評価スコアを全候補について測る方式とは異なり、較正入力から得た再構成誤差を利用する。最終的な下流タスクの改善は、この代理指標が有用であるかどうかを別途実験で検証する必要がある。

### 2. 0/1整数線形計画によるビット幅選択

Algorithm 1では、各候補ビットbでVを仮量子化し、その誤差E_i^V(b)を保存する。行iの候補ビットbを選ぶかどうかを二値変数S_{i,b}とし、目的関数Σ_i Σ_b E_i^V(b) S_{i,b}を最小化する。制約は、(1) UとVの総保存ビット数が予算G_b以下、(2) 各行についてビット幅を一つだけ選ぶ、(3) 利用可能な候補ビット幅だけを選ぶ、(4) 実際に使用するビット幅の種類をf_max以下に制限する、という四群である。

Vの行とUの対応列は同じ選択ビット幅を使うため、候補ビットbの保存費用は入力次元と出力次元の和に比例する。整数計画の解は、同じ総ビット数でどの行を高精度にし、どの行を低精度にするかの割当表になる。著者はCVXPYとSCIPを用いてこの0/1 ILPを解き、選んだビット幅でVを本量子化する。

重要なのは、この割当はビット数だけの単純な大小順ではない点である。特異値が大きい成分でも低ビットで誤差が小さい場合があり、特異値が小さくても量子化しにくい成分がある。各成分の候補ビット幅ごとの再構成誤差を測り、全体予算と実装上のビット幅種類数を同時に満たすようにする。

### 3. V先行量子化後のReconstruction Target Correction（RTC）

Vを先に量子化すると、後段Uが掛かる入力側の表現がV_hat Xへ変わる。Uを元のまま量子化すると、目標とすべきUΣVXとのずれを残したまま量子化誤差が積み重なる。PRINMIXのRTCは、V_hatを固定した状態で、元の出力UΣVXを最もよく再構成するU_tildeを求める。

原著の式7は、U_tildeを最小二乗の閉形式で計算する。分子には元のUΣVXXᵀV_hatᵀΣᵀ、分母にはΣV_hat XXᵀV_hatᵀΣᵀの逆行列が現れる。これは量子化後のV_hatを前提としてU側の再構成目標を更新する操作であり、学習時の誤差逆伝播を必要としない。最後にU_tildeを、ILPが選んだ対応ビット幅で量子化してU_hatを得る。

RTCはVの量子化誤差を消す魔法ではなく、残されたU側の自由度で元の差分出力を近似し直す補正である。較正入力の分布が異なれば最小二乗で適合する出力も変わり、行列の数値安定性や較正サンプル数にも依存する。著者はこの補正を混合精度配分と組み合わせ、同じ圧縮予算で差分の再構成誤差を下げる。

## 評価条件

原著は数学・推論・コード生成・多モーダルの四領域で、7Bと13〜14B級の微調整済みモデルを評価する。基盤と微調整済みモデルの差分を1/16へ圧縮し、SVD低ランク、BitDelta、Delta-CoMe、PRINMIXを比較する。較正データはC4の128例、各2048トークン。評価はNVIDIA L20 GPUで行い、生成にはgreedy decodingを用いる。Delta-CoMeとPRINMIXは3回測定の平均と標準偏差を示す。

|---|---|
| 基盤・適応モデル | Qwen2.5-Math、Qwen2.5-Coder、Qwen2.5-VL、DeepSeek-R1-Distill-Qwen、MetaMath、LLaVA-v1.5など |
| 規模 | 7B、13〜14B級 |
| 差分圧縮 | 主比較はα=1/16、追加付録で別圧縮率を調査 |
| 較正 | C4から128例×2048トークン |
| 推論ハードウェア | NVIDIA L20 GPU |
| 推論方法 | greedy decoding、数学・推論・コード・視覚言語の四領域 |
| 品質 | Math500、AIME2024、GSM8K、HumanEval、MBPP、GQA、ScienceQA-image |

## 評価結果

### 1. 7B級：数学・コード・視覚言語の比較

7Bの表2では、8評価の平均が未圧縮Aligned76.0、Delta-CoMe71.9、PRINMIX74.0である。PRINMIXはDelta-CoMeより2.1ポイント高いが、未圧縮との差2.0ポイントは残る。DeepSeek-R1-Distill-QwenのAIME2024は30.0±3.30から36.7±3.35へ6.7ポイント改善し、Math500は82.4±1.11から82.7±0.83へわずかに改善する。

DeepSeek-R1-Distill-Qwen-14Bでは、使用可能なビット幅種類数f_maxを2、3、4、5、6と変えた。f_max=2のMath500は80.7、AIME2024は33.3、平均57.0。f_max=4では80.2、31.1、平均55.7。f_max=6では79.5、33.3、平均56.4である。種類数を増やせば必ず品質が上がるわけではなく、実装上のビット幅種類数を少なく抑えても良い配分が得られる場合がある。

### 4. 量子化順序と差分再構成の意味

RTCは、先に量子化したV_hatを使ってU_tildeを再計算し、元の差分出力UΣVXに近づける。原著はRTCを量子化誤差最小化の設計に組み込み、ビット配分の誤差表と再構成目標の整合性を保つことを重視する。ビット配分だけを最適化しても、Uを元のまま量子化すればV_hatが導入した誤差を後段で補えない。ここでRTCが効く対象はSVD差分の逐次量子化であり、任意のフルモデル量子化方式へ同じ閉形式を直接適用できるとは限らない。

評価表はDelta-CoMeとPRINMIXの3回測定の平均と標準偏差を併記しており、AIME2024では標準偏差が数ポイントある。7BのAIME2024改善6.7ポイントは重要だが、試行回数と分散を考えると任意のサンプルで常に同じ差が出ると解釈すべきではない。HumanEvalの0.6ポイントなどの小差についても同様である。

## 既存研究との差

BitDeltaは差分を極低ビットで表す一方、SVD因子の重要度とビット予算の配分をPRINMIXと同じ形では扱わない。Delta-CoMeはSVD因子を混合精度量子化するが、大きい特異値を持つ成分ほど重要という経験的なルールを採用する。PRINMIXは、各候補ビット幅で実際にどれだけ再構成誤差が生じるかを較正入力から測り、0/1 ILPでビット予算を配分する点が異なる。

もう一つの差はRTCである。VとUを順に量子化すると後段のUが最適化すべき目標は変化する。PRINMIXはV_hatが固定された後にU_tildeを最小二乗で補正してから量子化する。ビット配分と再構成目標の両方を誤差最小化へ揃えることで、微調整差分の機能を保持しやすくする。

この方式はLoRAのように微調整時から低ランクパラメータだけを学習する方式とも異なる。PRINMIXはすでに密な差分として得られた微調整済みモデルを後から圧縮する。したがって、既存の高品質な微調整済みモデルを多テナント配信する場合に適合するが、微調整工程の計算を減らすこと自体を目的とした研究ではない。

## 限界・負の結果

第一に、PRINMIXでも元の微調整済みモデルを完全には再現しない。7Bの八評価平均はAligned76.0から74.0、13〜14Bでは66.6から64.7へ低下する。7BのDeepSeek-R1-Distill-QwenのAIME2024はAligned40.0に対しPRINMIX36.7であり、微調整で得た推論能力の一部は失われる。

第二に、13〜14BのMetaMath Math500やLLaVAのGQA/ScienceQAではDelta-CoMeより悪い。特に視覚言語では7Bで改善しても13〜14Bで逆転するため、モデル規模や適応データが変わったときに混合精度割当の利得が普遍的とは言えない。

第三に、ILPの求解は無視できない準備費用を伴う。Qwen2.5-Math-7B-Instructの29.4分は通常の量子化処理全体や推論速度の測定値ではなく、整数計画ソルバの時間である。モデル差分を頻繁に更新する場合は、品質改善と圧縮準備時間の交換条件を考える必要がある。

第四に、誤差代理指標はC4較正入力の分布に依存する。下流のAIME、コード、視覚質問応答の損失を直接最小化しているわけではない。RTCの閉形式も、較正行列や数値安定性の条件に依存する。評価はNVIDIA L20を使った限定されたモデル群であり、ローカル12GB GPUや異なるCPU/GPUオフロード構成での速度・メモリを直接示すものではない。

第五に、論文の「16倍圧縮」は差分ΔWの表現サイズについての主比較であり、共有する基盤モデルW_baseを含むシステム全体のGPUメモリが16分の1になるという意味ではない。推論時に基盤重みを読み込む費用は残り、差分を復元して適用する方式によって実際の処理量は変わる。
