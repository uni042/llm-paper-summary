# Efficient Training-Free Multi-Token Prediction via Embedding-Space Probing（ESP）

## 概要

ESP（Embedding-Space Probing）は、通常は次トークンだけを学習した自己回帰LLMから、**重みを変更せずに複数の将来トークン候補を取り出す**ための推論時手法である。プロンプトのトークン埋め込みを平均して作ったソフトなマスク表現を入力末尾に挿入し、モデルの出力分布から未来位置の候補を得る。候補は確率に応じて木構造へ展開し、元のLLMがまとめて検証する。受理された候補だけを出力へ確定するため、提案候補が誤っていても元モデルの逐次復号と同じトークン列を保てる。

SpecBenchでのH100実測では、ブロック複雑度BC=60のLLaMA3.1-8B-Instructで自己回帰復号比1.38倍、Qwen3-32Bで1.48倍の速度比を報告した（原著Table 1）。ただし性能はタスク・モデル・候補木の大きさに依存する。特にコード補完やRAGなどプロンプト内のn-gramをコピーしやすい課題では、STANDの方が高い受理長を得る場合がある。さらに木注意マスクと位置IDの実装が非効率だと、受理トークン数が増えても実時間は遅くなる。**「追加学習不要」と「実装が軽い」は別の性質**である。

## 背景と着眼点

通常の自己回帰生成は1回の前向き計算で1個の次トークンを確定するため、バッチ1の生成ではGPUの計算並列性を使い切れない。投機的復号は先に複数トークンの候補を用意し、元の大きなモデルでまとめて検証することでモデル呼び出し回数を減らす。従来の代表例では小型ドラフトモデルや複数の追加出力ヘッドを学習し、学習データ、追加パラメータ、GPUメモリが必要になる。

ESPの問いは、**次トークン予測だけを学習した既存モデルの内部に、未来トークンを予測する潜在的な能力が残っていないか**というものである。Future Lensなどの機構解釈研究は隠れ状態に将来の情報が線形に読み出せることを示したが、それをそのまま実際の高速復号へ利用できるとは限らない。ESPは、通常の語彙IDに対応しない連続値の埋め込みベクトルをマスクとして挿入し、LLMの自己注意とLMヘッドを通して未来位置の分布を誘発する。

この方法は外部ドラフトモデルを持たないが、同じ基盤モデルの計算を候補生成と検証の両方に利用するため、計算が完全に無料になるわけではない。並列化によって受理トークン数を増やす利得が、候補木の計算・マスク処理の追加費用を上回る必要がある。そこで論文は平均受理長だけでなく、実測速度比と候補木のブロック複雑度を併記している。

## 手法

### マスク埋め込みの生成

プロンプトのトークンIDを既存の埋め込み行列Eでベクトルへ変換し、各ベクトルの平均をマスクの初期値とする。式(4)では、入力長tの埋め込みe1…etから `m = (1/t) Σ e_j` を計算し、複数のマスク位置へ同じ初期値を与える。これは語彙の[MASK]トークンを追加学習する方式ではなく、**その入力に合わせて連続値のマスク表現をその場で合成**する方式である。

生成が進むとマスクを直近の生成トークンの埋め込みへ少しずつ近づける。式(5)の更新は `m_{s+1} = m_s + λ(e_{t+s} − m_s)` であり、主実験のλは0.1。全マスクの初期埋め込みが同じでも、候補木上の位置IDと参照可能な過去トークンが異なるため、各位置で同じ未来候補が出るとは限らない。木注意マスクは、別枝の候補が不正に互いの情報を参照しないようにする。

著者らはマスクの初期化として、プロンプト末尾の既存トークン埋め込みを流用するhard初期化、語彙埋め込み全体に合わせた正規分布からのサンプリング、プロンプト平均を比較した。原著Table 5ではプロンプト平均がLLaMA3系で最も良い受理長を示し、入力文脈の統計を反映することが重要と解釈している。語彙分布から外れたマスク初期値では受理性能がやや下がるという追加実験もある。

### 候補トークンの木と検証

マスク位置から得た語彙logitsのTop-K候補を将来トークンとして展開する。各候補の累積確率は、親ノードまでの経路確率と次トークンの条件付き確率の積で更新する。Algorithm 1は候補木の予算Bを受け取り、確率が高い経路を優先してノードを残す動的な木構築を記述する。固定幅の木と違い、確信度が高い経路へ計算を寄せ、曖昧な位置では分岐を増やすことができる。

木は無制限に広げない。**ブロック複雑度BC**を、最後に受理したトークン、候補木のノード、候補に対応するマスク位置を含めた一回の並列処理トークン数として定義する。マスク数k、各深さの候補数Kiに対して、式(7)は概ね `(k+1)(1+ΣKi)` という関係を示す。例えばマスク2個で深さ2の候補がK1、K2なら `3(1+K1+K2)` となる。候補を増やすと受理長は改善し得るが、同時に検証の計算負担も増えるため、比較ではBC=10、30、60を揃えている。

候補木の枝が親と同じトークンを繰り返す場合などは、単純な重複枝を除き次点の候補へ置き換える。これは「言語モデルの出力から繰返しを禁止する」処理ではなく、**投機候補として無駄な枝を避ける**ための枝刈りである。元モデルの検証に失敗した候補は出力として確定されないので、最終的な復号規則を変えるものではない。論文の追加アブレーションでは、この木枝刈りにより平均受理長が最大約4%改善する条件がある。

### 同じ基盤モデルによるlossless検証

候補生成後、基盤モデルが木の各候補を適切な因果マスクの下でまとめて評価する。候補トークンが、その時点の元モデルの次トークン選択と一致した場合にだけ受理する。受理が続けば複数トークンを一回の検証で確定でき、途中で一致しなくなった場合はそこで通常の復号へ戻る。論文はこの処理をlosslessと呼ぶが、その意味は**基準となる元モデルの復号結果を変えない**ことであり、モデルの事実性や正答率を向上させるという意味ではない。

論文の理論部分では、マスクの隠れ状態と真の次位置の隠れ状態が十分近ければ、正しい次々トークンがマスクから得たTop-Kに含まれるという補題を述べる。LLaMA3.2-3B-Instructの文章生成サンプル100件では、受理される候補のマスク表現と真の未来トークン表現のコサイン類似度が後半層で約0.45へ上がり、拒否される候補は約0.35付近にとどまる（Figure 2）。これは候補生成の経験的な裏付けであるが、あらゆる入力で高い類似度や長い受理長が得られるという保証ではない。

### GPU向けの木注意マスク・位置ID更新

木に新しいノードが加わるたびに注意マスクと位置IDをPython側で一から組み立てると、GPUへ渡す前処理のオーバーヘッドが大きくなる。ESPは固定構造の木について注意マスクをキャッシュし、受理トークンが増えたときに必要な列を増分追加する。位置IDも単純なオフセットで更新し、既存の配置を再利用する。これはモデルの重みや学習方法ではなく、推論ランタイムの実装最適化である。

原著Table 4では、この最適化によりLLaMA3.1-8Bの各構成の速度比が素朴実装より平均約21%改善した。特にBC=60では約29〜30%の改善がある。候補の平均受理長が同じでも、実装だけで速度比が大きく変わるため、受理長をそのまま実時間短縮へ換算してはならない。

### 木の構成とマスク数の負の結果

Table 2でLLaMA3.1-8BのBC60、マスク2個の動的木はτ1.712、固定[15,4]は1.708、固定[12,7]は1.701、固定[6,13]は1.624である。動的木は有利だが、最良の固定構成に対する改善は小さい。LLaMA3.2-3BのBC60では動的木1.630に対し固定[15,4]が1.631とわずかに上回り、**動的木が全条件で厳密に最高とはいえない**。

さらにTable 3では、LLaMA3.1-8BのBC60でマスク1個・木幅[29]がτ1.73、マスク2個・[15,4]が1.71、マスク3個・[7,5,3]が1.57となる。マスクを増やせば未来を深く予測できる一方、同じBC内で使える候補ノード数が減り、受理長が下がることがある。LLaMA3.2-3Bでも1.65、1.63、1.51の順であり、同じ傾向を示す。したがって「将来位置を多くマスクすれば常に高速」という単純な設計則は成り立たない。

### 実装最適化の有無による逆転

原著Table 4でLLaMA3.1-8BのBC60・マスク1個では、同じτ1.73でも素朴な木処理の速度比は1.05倍、効率化実装では1.36倍となる。マスク2個でも素朴実装1.07倍に対し効率化実装1.38倍。LLaMA3.2-3BのBC60・マスク1個は素朴実装0.95倍と通常復号より**遅い**が、効率化実装では1.20倍へ改善する。候補受理長が高くても、GPUマスク・位置IDの更新費用が大きければ速度は失われるという明確な負の結果である。

### タスク別の例外

Figure 4、Figure 5ではESPが多くのタスクで高い受理長・速度比を得る一方、LLaMA3.1-8Bのコード、RAG、要約ではSTANDが上回る場合がある。これらの課題はプロンプトに同じn-gramが現れやすく、コピーを利用するドラフト方式に利点がある。反対に数学・推論ではESPの潜在的な未来予測が有効で、LLaMA3.1-8BのBC60ではτ1.81、速度比1.43倍、Qwen3-32Bの同課題ではτ1.75、速度比1.53倍と報告する。平均値だけを見ず、入力の反復性とタスクの種類を考慮する必要がある。

## 既存研究との違い

MedusaやEAGLE系の投機復号は、未来トークンを予測する追加ヘッドやドラフトネットワークを学習する場合がある。ESPは基盤モデルの重みを凍結し、入力時のマスク埋め込みを用いて未来候補を得るため、追加学習や外部ドラフトモデルの保守が不要である。ただし候補生成と検証は同じ大きなモデルを用いるので、ドラフトの計算費用が小さい専用モデル方式に対して無条件に有利という意味ではない。

PLDやSTANDはプロンプト内の文字列・n-gramの繰返しを利用する傾向があり、LADEは既存の生成情報から未来候補を作る。ESPは語彙埋め込みの平均から未来位置を直接プローブするため、プロンプトにコピー可能な長い繰返しがなくても候補を出せる。この違いが数学や文章作成での強みになる一方、コピーが強い課題ではSTANDが勝つ例外を説明する。

## 限界と実装上の注意

第一に、追加学習が不要でも、任意の推論ランタイムにそのまま挿せるわけではない。語彙IDではないソフト埋め込みの注入、木状の因果注意、位置IDの整合、候補木の検証を実装できる必要がある。特に木マスクを毎回再生成する素朴な実装では通常復号より遅い条件がある。

第二に、速度比はブロック複雑度、入力タスク、モデル規模、生成長、GPUに依存する。Table 1はH100・256トークン出力の条件を明記しており、A100の別実験設定や一般的なオンラインSLOへ同じ数値を転用できない。単一GPU・小バッチの結果を複数ユーザーの連続バッチサービングへ外挿するには追加測定が必要である。

第三に、マスク表現と未来トークンの隠れ状態の類似度が高いことは候補の受理率と相関するが、あらゆる未来位置で正しい候補が出る保証ではない。候補が拒否されれば計算は浪費され、木を大きくするほど無駄な枝も増える。BC=60より大きい木やマスク3個で受理長が必ず改善するわけではない。

第四に、losslessは元の復号規則との一致を意味する。誤答を減らす、知識を増やす、生成品質を改善する方式ではない。確率サンプリングを用いる場合も、分布を保存する検証規則が適切に実装されていることが前提である。論文の主な数値は温度0の実験であるため、温度1の条件は付録を参照して別途評価すべきである。

第五に、比較対象は主に学習不要のドラフト不要方式である。学習型の投機復号器や専用の小型ドラフトモデルと、同じハードウェア・メモリ予算・実装最適化の下で直接比較した結果と混同しない。
