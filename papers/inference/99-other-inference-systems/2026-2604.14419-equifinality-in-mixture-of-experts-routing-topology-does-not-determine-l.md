# MoEの経路トポロジー同等性：多段ルーティングはどこまで必要か

## 概要

本論文は、専門家混合（Mixture of Experts、MoE）の経路選択が複雑になるほど言語モデルの品質が高くなるという仮説を、小型Transformerの収束実験で検証した研究である。著者は学習可能な重心ベクトルとの余弦類似度で専門家を選ぶ幾何学的ルータを作り、一段で多数の専門家を選ぶ方式、複数段で少数ずつ選び直す方式、段ごとの射影を変える方式などを比較した。

主要な結論は、**同じルータ容量と専門家群を持つ余弦ルーティングの複数構成は、十分学習すると困惑度がほぼ同じ範囲へ収束する**というものである。76～84Mパラメータ、1.64Bトークン、3乱数種の15実験では、5方式の困惑度（Perplexity、PPL）は33.93～34.72であり、1 PPL以内という事前に定めた同等性幅を用いる統計検定で全10組が同等と判定された。これは「どのMoEルータも完全に同じ」という一般命題ではない。比較対象は同じ幾何学的ルータ族に限られ、より大きい容量の線形ルータはPPL 32.76と優れていた。

著者はさらに、多段ルーティングで各段が加える更新ベクトルの方向が非常に近いことを示し、経路の複雑さが実際には表現の繰り返し増幅になっている可能性を検討した。この冗長性を利用し、各段の相対更新ノルムが小さいトークンの処理を推論時に打ち切ると、収束モデルでMoE部分の浮動小数点演算数を25%減らし、PPL悪化を0.12%に抑えた。多段MoEを使う場合、複雑な経路の設計より、容量と実際に有用な段の見極めが重要であるという示唆を与える。

## 問題設定：経路の複雑さと容量を分離する

標準的なMoEでは、各トークンの隠れ状態から線形射影で専門家ごとのスコアを出し、上位k個だけを実行する。全専門家のパラメータを保持しつつ、実行する計算を限定できる。しかし専門家数を数百～千以上へ増やすと、経路選択器の行列も大きくなり、学習可能な経路パラメータと実行時のメモリ参照が増える。専門家数を増やした効果、ルータの表現容量を増やした効果、経路の段数を増やした効果を混同しやすい。

多段ルーティングでは、最初に選んだ専門家の出力を状態へ加え、その更新済み状態を再度ルータへ渡す。理論上は、最初の専門家で得た特徴に応じて次の専門家を選び、段階的な合成を行える。しかし実際には各段でほぼ同じ方向へ状態を動かすだけなら、計算段数を増やしても新しい能力を得られない。学習途中で多段方式が有利に見えても、長く学習した単段方式が追いつく可能性がある。

著者は、この疑問に対して同一の学習データ・予算・実装を用いた比較を設計した。評価は主にWikiText-103のPPLであり、汎用的な対話能力や数十B規模の商用MoEの品質を直接測るものではない。論文の結論を適用する際には、**学習の収束条件とルータ容量が揃っているか**を必ず確認する必要がある。

## 手法：64次元の幾何ルータと専門家更新

### 余弦類似度による専門家選択

トークンの隠れ状態hを学習可能な射影行列で64次元へ写し、L2正規化して位置ベクトルpを得る。各専門家iには学習可能な64次元重心c_iを持たせ、正規化した内積 `s_i=τ<p,c_i>` を経路スコアとする。スケール係数τは基本設定で30であり、softmax後に上位k専門家を選び、その集合内で重みを再正規化する。

通常の線形ルータはモデル幅と専門家数の積に比例するパラメータを持つ。比較実験の8層、各1024専門家の構成では標準ルータが約8.39Mパラメータなのに対し、64次元の射影と重心を使う幾何ルータは約1.57Mであり、約80%少ない。ただし経路パラメータがゼロになるわけではない。低次元のボトルネックを入れたことでルータ容量が減っており、これが品質差の一因になる。

### 専門家の二種類のパラメータ化

静的専門家では、専門家ごとに学習済みの更新ベクトルを一つ持ち、選択重み付きの和を隠れ状態へ加える。この構成は非常に軽いが、何段通っても更新の足し算となり、経路の順序が新しい非線形計算を生まない。多段で真の合成を調べるには不十分である。

そこで著者は、専門家ごとに低ランクの二つの行列を持つMLP型専門家も導入する。更新は概念的に `Δh=Σ_i w_i W_up,i SiLU(W_down,i h_current)` であり、現在の状態に応じて専門家出力が変わる。ランク1なら各専門家は一つの入力方向を読み、一つの出力方向へ非線形に書き込む。ランクを増やすと専門家の表現力は増すが、同じ計算予算で選べる専門家数は減る。

### 多段経路と再選択

各段では更新ベクトルを累積し、次段の経路位置を `normalize(proj_in(x+h_accum))` で再計算する。専門家集合は段間で共有する。三段・各段4専門家を選ぶDeep方式と、一段・12専門家を選ぶWide方式は、選択する専門家の延べ個数を合わせた比較となる。Deepは逐次的な三段処理が必要であり、Wideは一度に選択した専門家を並列に実行しやすい。

学習損失は通常の言語モデル交差エントロピーに、Switch Transformer型の負荷分散損失を加える。分散係数は0.05で、専門家の選択頻度と平均選択確率を用いて偏りを抑える。負荷分散がないと一部の専門家へ要求が集中し、ルータ比較の条件が揃わないためである。位置射影、重心、専門家MLPは全て通常の勾配法で更新する。

## 実験設定と比較上の注意

| 項目 | 原著の設定 |
|---|---|
| データ | WikiText-103、32K語彙のBPE分割 |
| 小規模 | 36～38Mパラメータ、4層、512専門家、5Kステップ、82Mトークン |
| 大規模 | 76～84Mパラメータ、6～8層、1024専門家 |
| 収束実験 | 50Kステップ、1.64Bトークン、約14エポック |
| 基本経路 | 64次元、余弦スケール30、top-4、三段、ランク1専門家 |
| 乱数種 | 42、137、7。5方式×3種の15実験 |
| 統計 | 対応付きブートストラップ1万回、TOST同等性検定 |
| ハードウェア | NVIDIA RTX 3090/3090 Ti 24GB、混合精度bfloat16 |
| 総実験量 | 62実験、約460 GPU時間 |
| 主指標 | 検証困惑度（PPL）。小さいほど良い |

論文は学習途中の5K～20Kステップと、十分学習した50Kステップの結果を分けている。初期段階では多段方式や非線形専門家が有利に見える条件があるが、収束後にはその差が縮まるか逆転する。したがって早期のPPL差だけを使って「深い経路が本質的に優れる」と結論づけてはいけない。

また、計算量を揃える比較と、総パラメータ数を揃える比較は別物である。MoEの目的は総パラメータを大きくしながらトークン当たり実行する専門家を限定することである。同じ総パラメータを持つ密なFFNは、はるかに多くの演算を実行できるためPPLで有利でも不思議ではない。両者を同じ条件のモデルと扱うと、疎性の価値を誤解する。

## 主要結果：収束後の経路同等性

| 方式 | 経路 | 最終PPL（代表実行） | 3乱数種の平均±標準偏差 |
|---|---|---:|---:|
| Wide | 1段×12専門家、余弦 | 33.93 | 34.22±0.25 |
| Deep | 3段×4専門家、余弦 | 34.62 | 34.65±0.03 |
| 段別射影 | 3段、射影を分離 | 34.05 | 34.05±0.10 |
| スカラー増幅 | 1段、学習可能係数 | 34.11 | 34.10±0.08 |
| 非対称段数 | 層ごとに段数変更 | 34.59 | 34.60±0.12 |
| 標準線形ルータ | 1段×12専門家 | 32.76 | 単一設定 |
| 密な同演算量モデル | FFN幅12 | 34.49 | 単一設定 |
| 密な同パラメータモデル | FFN幅1120 | 29.36 | 単一設定 |

余弦ルータ5方式の15実験は33.93～34.72の範囲に収まり、1 PPLという同等性幅で全10組がTOST検定を通過した。これは差が厳密にゼロであることの証明ではなく、**事前に決めた実用上の許容差の範囲内である**という統計的な結論である。5方式の平均値間には最大約0.60 PPLの差があり、最良方式が常に一意に決まらない。

標準線形ルータはPPL 32.76と明確に良いが、経路パラメータが8.39Mで余弦方式の1.57Mの5.3倍ある。余弦方式の経路次元を341へ増やし、経路パラメータを8.38Mへ揃えるとPPLは33.14まで改善し、線形との差1.17 PPLの約67%が解消した。残る差は0.38 PPLであり、機構そのものの差は約1.2%と解釈される。したがって「ルータの形状は無関係」と断定するのではなく、**経路容量の方が経路トポロジーより影響が大きい**と読むのが正確である。

逆に専門家MLPの幅を増やした実験では、総パラメータを増やしてもPPLが34.92へ悪化した。単純に専門家を太くすることが最適とは限らず、どの方向へ容量を配分するかが重要である。密な同パラメータモデルはPPL 29.36でMoEより優れるが、FFNの活性演算量は約93倍なので、MoEの計算効率上の目的を否定する結果ではない。

## 経路の収束理由：更新方向と専門家選択

多段方式の第1段と第2段が作る更新ベクトルの余弦類似性は0.805で、異なる意味的変換を直交的に積み重ねるというより、ほぼ同じ方向を増幅している。Wideへ学習可能な一つの出力スカラーを加えるだけでPPL 34.11となり、Deepの34.62と同じ範囲へ入った。スカラー係数は学習後に約5.04へ収束した。

段ごとの射影を独立にして更新方向を意図的に分離すると、更新間の余弦は0.805から0.049へ低下する。しかしPPLは34.05に留まり、元の同等性帯を大きく超える改善にはならない。更新を異なる方向へ向けるだけでは、専門家群が表現できる能力の上限を変えられない可能性がある。

さらに収束後のDeepは段間で約97%の専門家を再選択しており、実際の経路がほぼ固定されていた。それでも経路を完全に固定するとPPLは34.62から37.26へ7.6%悪化する。残る約3%の専門家変更が一部のトークンで重要な修正を担うためである。**「段間でほぼ同じ専門家を使う」ことと「再経路選択を除いてよい」ことは同義ではない**。

別の乱数種で学習した専門家の重みベクトルは一致しないが、語彙へ投影した機能の重なりは無作為対応より約500倍高かった。モデルは異なるパラメータを使って似た機能を分担できる。これが経路同等性の一つの機構的説明である。ただし個々の専門家の役割が無意味になるわけではなく、専門家単位の因果的な制御可能性は別の問題である。

## 推論時の相対更新ノルムによる早期停止

多段経路が冗長なら、トークンごとに十分小さい更新が現れた時点で残りの段を省略できる。著者は各段の更新 `Δh` に対し、`||Δh||/(||x+h_accum||+10^-6)<ε` ならそのトークンの経路を終了する規則を用いた。これは学習済みモデルに対する推論時の閾値処理であり、早期停止を学習するための再訓練は必要ない。

| 閾値ε | 平均実行段数 | MoE演算量削減 | PPL変化 |
|---:|---:|---:|---:|
| 0.02 | 2.58 | 14.2% | +0.00% |
| 0.05 | 2.44 | 18.8% | +0.03% |
| 0.10 | 2.25 | 25.0% | +0.12% |
| 0.15 | 2.08 | 30.7% | +0.43% |

表は50Kステップまで収束したDeepモデルでの測定である。ε=0.10ではMoE部分の理論演算量を25%削減し、PPL悪化を0.12%に抑えた。RTX 3090の別プロファイルでは、一処理ステップの遅延が4.32ミリ秒から3.26ミリ秒へ24.6%短縮した。ただしこれは測定対象の小型MoEであり、実際の大規模サービング全体の処理量が同じ比率で改善するという保証ではない。

静的ベクトル専門家では更新ノルムがトークン間で似やすく、閾値を少し変えると平均段数が急落する。一方MLP専門家ではトークン依存の更新が生じるため、段数とPPLが滑らかに変化する。実用的な早期停止には、単なる閾値の導入だけでなく、更新ノルムが入力に応じて十分変化する専門家構造が重要となる。

学習中から段数を確率的に減らす実験は失敗した。最大3段を保証せずに訓練すると、モデルが後段の計算へ依存しなくなり、3段実行時のPPLは通常学習の302.54から316.14へ悪化した。推論時に段を省くことと、学習時に段を省くことは異なる。著者は、全段を使って学習してから、実行時に冗長な更新だけを省く方式を推奨している。

## 追加検証と負の結果

ハッシュルーティング、固定乱数重心、top-1経路を試すとPPLはそれぞれ36.04、35.03、36.14となり、学習可能な余弦ルータの最良33.93より1.1～2.2 PPL悪化した。これらは単一乱数種の結果であり、5方式の正式な同等性検定には含まれない。単純な経路でもモデルが完全に破綻しないことを示すが、学習ルータと同等であることを示したものではない。

ゼロショットのHellaSwag、ARC-Easy、WinoGrandeでも複数方式を比較したが、2ポイント幅での正式な同等性検定は9比較中1比較しか通過しなかった。WideはPPLでは良くてもHellaSwagとARC-Easyでは他方式より悪い場合がある。さらに76～84M規模ではHellaSwagが約25%、WinoGrandeが約50%と偶然水準に近く、下流能力の違いを十分に識別できない。**PPLの同等性を下流タスクの完全な同等性へ拡張してはいけない**。

小規模・学習途中では多段方式が有利な条件もあり、専門家数と一専門家の幅によって最適構造が変わる。512個のランク1専門家を持つ細粒度構成では多段が有利な一方、64個のランク8専門家では一段で幅広く選ぶ方式が有利だった。著者はこの違いを、64次元空間に置かれた重心の密度が経路の細かい再選択を支えるためと解釈する。これは「段数は全く意味がない」という単純化を避ける重要な結果である。

## 既存研究との差と実装上の含意

標準的なSwitch TransformerやMixtral系MoEでは、学習済みの線形ルータが専門家を選ぶ。より複雑な階層ルータや多段ルータは表現力を増す可能性があるが、実際にはパラメータ数と学習予算の増加を同時に伴う。本研究は、経路容量を明示し、複数乱数種で十分学習した上で、トポロジーの違いそのものを評価した点に意義がある。

実装を検討する場合、まず専門家選択の容量と実行時のメモリアクセスを測定し、経路の段数を増やす前に、単段で選択する専門家数や射影次元を調整する価値がある。多段を採用する場合も、更新方向の余弦、段間で選ばれる専門家の重複率、相対更新ノルムを記録すると、実際に段ごとの新しい計算が行われているかを評価できる。早期停止の閾値は推論時に調整できるが、性能劣化の許容幅をベンチマークで確認する必要がある。

論文はRTX 3090上の小型モデルで、ルータ処理がCUDA時間の約21.5%を占めると報告する。大規模MoEでは専門家の分散配置、通信、GPU間の負荷分散、KVキャッシュなど別の費用が支配的になり得る。ルータパラメータを80%減らすことが、総モデルメモリや推論時間を80%減らすことではない。専用Tritonカーネルによる改善は可能性として述べられているが、本研究でその最適化の性能を実証したわけではない。

## 限界・適用条件

第一に、モデルは76～84Mパラメータ程度であり、数十億から数千億パラメータのMoEに同じ同等性が成立するとは確認されていない。専門家数1024という設定は大きく見えるが、専門家はランク1など非常に小さい。一般的な巨大FFN専門家を持つMoEとは計算の粒度が異なる。

第二に、主要な同等性検定はWikiText-103、同じ学習設定、5種類の余弦ルータに限定される。標準線形ルータはより低いPPLを示し、パラメータ数を揃えても0.38 PPLの差が残った。下流タスクの同等性も正式にはほとんど確認できていない。ルータ機構を全て無差別に交換できるという主張ではない。

第三に、統計的な同等性は1 PPLという許容幅の選択に依存する。0.1 PPL以内のような厳しい条件なら同じ結論になるとは限らない。15実験の乱数種のばらつきと方式間の差は小さいがゼロではない。正式な検定結果を「数学的に同一の品質」と解釈しない。

第四に、早期停止で25%削減したのはMoE部分のFLOPsであり、注意演算、埋込み、通信、メモリ管理を含む全体の計算量ではない。小型GPU上のステップ遅延の実測はあるが、大規模分散サービングのスループット、エネルギー、尾部遅延を直接評価していない。

第五に、段数をランダムに減らして学習するとモデルが浅い経路に適応してしまい、通常の3段でのPPLが悪化した。推論時の早期停止が成功したからといって、同じ規則を学習時へ導入してよいわけではない。段の役割が学習される過程と、学習済み段の冗長性は区別する必要がある。

第六に、公式コードとチェックポイントについて原著は公開予定と記すが、今回確認した一次資料には確定した公開URLがない。実装再現には専門家の配置、負荷分散、段ごとの再射影、乱数種、WikiText-103の分割方法、収束までの学習予算を合わせる必要がある。原著の数値は著者報告であり、独立した再現実験ではない。
