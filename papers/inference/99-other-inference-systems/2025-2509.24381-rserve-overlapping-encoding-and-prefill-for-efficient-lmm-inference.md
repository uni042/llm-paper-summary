# RServe: Overlapping Encoding and Prefill for Efficient LMM Inference

## 概要
大規模マルチモーダルモデル（Large Multimodal Model; LMM）は、画像・動画などを埋め込みへ変換する符号化段、その埋め込みとテキストを処理するプリフィル段、トークンを逐次生成するデコード段を持つ。符号化とLLMを別GPUへ分離しても、従来方式では一要求の全マルチモーダル埋め込みが完成するまでプリフィルを開始できず、言語モデル側に待ち時間が残る。

RServeはこの依存を細粒度化する。要求内では、テキストや符号化済み画像部分に対応する「準備済み埋め込み」だけ先にプリフィルへ流し、残りの画像符号化とLLM順伝播を重ねる。要求間では、今すぐ処理可能なschedulable tokenを複数要求から集め、token budget内でmicro-batchを形成する。代表評価では遅延最大66%削減、スループット最大109%改善を報告する。

## 問題設定
Encode-Prefill-Decode（EPD）分離は各段の資源干渉を減らせるが、段間のデータ依存まで消えるわけではない。高解像度画像では符号化が全推論時間の無視できない割合を占め、プリフィルGPUが埋め込み待ちになる。

一方、画像を一個ずつ細かく符号化すれば重畳開始は早くなるが、符号化GPUのバッチ効率が落ちる。したがってRServeは、要求内の細粒度重畳と、要求間の十分なバッチ量を同時に確保する必要がある。

## 手法
### 埋め込み追跡器
各要求について、テキスト埋め込みとマルチモーダル埋め込みのready状態を追跡する。テキストは直ちにready、画像等は符号化完了時にreadyへ変わる。先頭から連続してreadyになったtoken範囲だけをプリフィルへ送ることで、自己回帰モデルの順序を壊さず部分実行できる。

### 符号化スケジューリング
マルチモーダル項目を即座に一件ずつ処理せず、一定のtoken量Cが溜まるまでまとめる。Cを大きくすると符号化GPUの効率が上がるがプリフィル開始が遅れ、小さくすると重畳は増えるが小batch化する。この閾値で二つの効果を調整する。

### schedulable tokenとtoken budget
要求間では「対応埋め込みがreadyで、かつそれ以前のtokenが処理済みまたは同じ回で処理可能」というtokenをschedulableと定義する。schedulerは複数要求のschedulable tokenをglobal token budgetまで詰め、chunked prefillとして実行する。要求全体がreadyになるまで待たずにmicro-batchを作れる。

### メモリ寿命管理
プリフィルが消費した埋め込みは追跡器から解放し、符号化済みデータを長時間GPUへ残さない。これにより重畳のための中間状態がGPUメモリを圧迫するのを抑える。

## 評価条件
|項目|内容|
|---|---|
|モデル|Qwen2.5-VL 7B / 32B / 72B|
|GPU|主評価で8×NVIDIA H100、追加構成も評価|
|ワークロード|MMMU由来入力、SGLang系ベンチマーク|
|比較|tensor-parallel一体型、EPD分離型等|
|主要指標|TTFT/遅延、スループット、SLO達成|
|実装|既存LMM serving基盤を拡張|

## 主要結果
|条件|結果|意味|
|---|---:|---|
|基準方式比|遅延最大66%削減|符号化待ちをプリフィルと重ねる効果|
|基準方式比|スループット最大109%改善|要求間micro-batchの負荷平準化|
|EPD分離比|TTFTをさらに約18〜19%削減する条件|分離だけでは残る段間直列性を削る|
|SLO曲線|達成領域を拡大|単なる単要求高速化だけでなくserving負荷にも効果|
|高負荷|EPDとの差が縮む傾向|資源飽和時は重畳余地が減る|

## 既存研究との差
EPD Disaggregationは符号化・プリフィル・デコードを別資源へ置いて干渉を減らすが、一要求内では段階を比較的直列に扱う。RServeは分離を前提に、埋め込み準備状態をtoken粒度で追跡して符号化途中からプリフィルを始める。Sarathi-Serve等のchunked prefillがテキストLLM内のprefill/decode調停を扱うのに対し、RServeはその考えを前段のマルチモーダル符号化まで広げる。

## 限界
重畳効果は符号化時間が十分大きく、符号化側とLLM側に同時実行余力がある条件で大きい。非常に高い要求率で全資源が飽和するとEPD分離との差は縮む。符号化batch閾値Cやtoken budgetは入力解像度・モデル・GPU構成に依存し、別環境では再調整が必要になる。また、埋め込みready状態と部分プリフィルを扱うため、既存runtimeへ単純な設定変更だけで導入できる方式ではない。
