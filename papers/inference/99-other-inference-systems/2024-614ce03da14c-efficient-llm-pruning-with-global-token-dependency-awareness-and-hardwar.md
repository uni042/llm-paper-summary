# TVA-Prune：全層トークン依存とGPU演算器の寸法を考慮する構造的LLM枝刈り

## 概要

TVA-Prune（Token Dependency-aware Variational Adapted Pruning）は、LLMの注意ヘッド、FFNの中間次元、トークンの隠れ次元をまとめて削減する構造的枝刈り方式である。変分情報ボトルネックの考え方を用い、各層の圧縮された表現がそれ以前の層の情報をどの程度保持する必要があるかを考慮して、不要な次元を選ぶ。さらに、枝刈り後の行列の縦横の大きさをGPUのTensor Coreが効率よく処理できる倍数へ調整する。理論上のパラメータ削減が実際の推論速度改善に結びつかない問題を重視した設計である。

Llama2-7Bを約50%枝刈りした場合、WikiText-2の困惑度は元の5.11から14.15へ悪化するが、A100上の推論速度は1.8倍になる。LoRAで追加学習すると困惑度は9.58へ改善する。寸法を調整しない場合、同じ困惑度14.15でも速度は1.1倍にとどまる。したがって、本研究の重要な結果は「半分削れば自動的に速くなる」ではなく、枝刈り後の行列形状をGPU演算器に合わせる必要があるという点にある。

## 問題設定

非構造的枝刈りは個々の重みをゼロにするが、通常の密な行列演算ではゼロの重みも読み込んで計算することがある。構造的枝刈りは注意ヘッドや隠れ次元を丸ごと削除するため、残ったモデルを小さな密な行列として実行できる。しかし、モデルの層をまたぐトークン表現には依存関係があり、一つの層だけの統計から削除する次元を決めると後続層の性能が落ちる可能性がある。

また、Grouped Query Attention（GQA）では複数のクエリヘッドが同じキー・値ヘッドを共有する。キー・値ヘッドだけを削除したり、対応関係を無視してクエリヘッドを削除したりすると、注意の形状が不整合になる。さらに、枝刈り後の行列が例えば128や256の倍数から外れると、GPUの専用演算器を効率よく利用できず、パラメータを減らしたのに速度が伸びないことがある。TVA-Pruneはこの三つの問題を一緒に扱う。

## 手法

### 1. 変分情報ボトルネックによる次元マスク

各層の隠れ表現に、学習可能な平均μと分散σを持つ確率的なマスクzを掛ける。原著式(2)では、標準正規雑音εを使って `z = μ + εσ` と表す。圧縮された表現は元の層出力にマスクを要素ごとに掛けたものである。マスクの分散と平均を学習し、予測に必要な情報を保ちつつ、不要な次元の情報を抑える。

目的関数は、モデルの予測を維持する負の対数尤度と、圧縮表現の分布を簡単な事前分布へ近づけるKL正則化を組み合わせる。原著式(1)の情報ボトルネックは、各層の表現が前の層だけでなく、それ以前の層の表現にも依存することを考慮する。局所的な重みの大きさだけで削除するより、モデル全体のトークン依存を見て圧縮することが狙いである。

### 2. 注意ヘッドとGQAの整合性

通常の多頭注意ではヘッドを比較的独立に削除できるが、GQAでは一つのキー・値ヘッドを複数のクエリヘッドが共有する。TVA-Pruneはキー・値ヘッドを削除する際に、それを参照するクエリヘッドもまとめて削除する。これによって残存ヘッドの形状と対応関係を保つ。原著式(3)は、キー・値ヘッドの圧縮表現にも前層全体の依存を考慮するマスクを適用する。

注意ヘッド、FFNの中間次元、トークン隠れ次元のマスクを同時に学習するため、各部分の削除量を独立に決めるより全体の性能を考慮しやすい。一方、マスクを学習する計算は必要であり、完全なデータ不要の枝刈りではない。モデル重みは原則として凍結し、マスクと疎性制約を調整する。

### 3. 目標削除率と二値化

学習中の確率的なマスクは、推論時には実際に次元を削除する二値マスクへ変換する。原著§2.3では、平均と分散の比に基づく重要度から閾値を決め、指定した目標削除率に近づくよう制約する。目標疎性と期待疎性の差に対して、線形と二乗の違反ペナルティを加え、ラグランジュ係数も学習する。これにより、品質を守るだけでなく、必要な圧縮率へ近づける。

二値化後には、削除した次元に対応する重み行列の行と列を実際に取り除く。ゼロ値を残すだけではなく、小さな密な行列を作るため、一般的なGPUの密な演算を利用できる。追加のLoRA学習は任意の回復手段であり、追加学習前後の精度は別条件として報告する必要がある。

### 4. GPUのTensor Coreに合わせた寸法調整

枝刈り後の行列寸法がGPUの効率的なブロックサイズに合わないと、演算器の利用率が低くなる。原著式(4)〜(5)は、二値マスクで残った次元数nを、例えば64や128の近い倍数n'へ丸め直し、その次元数に合うよう重要度を再順位付けしてマスクを調整する。これにより実際の残存行列がGPUの演算器に適した形状になる。

この処理では、元のマスクで残す予定だった次元が追加・削除される可能性があるため、削除率や困惑度がわずかに変わる。ただし原著の実験では、速度の改善に対して追加のパラメータ変化は小さい。理論上の演算量を減らすことと、実際のカーネルが効率よく実行できることを区別する設計である。

## 評価

### 実験条件

| 項目 | 原著の条件 |
|---|---|
| モデル | LLaMA-7B、LLaMA2-7B、Mistral-7B、LLaMA3-8B |
| GPU | NVIDIA A100 40GBを一台 |
| 較正・マスク学習 | C4の5000サンプル、系列長512、バッチ1 |
| 主評価 | WikiText-2困惑度、生成速度、6つのゼロショット常識推論タスク |
| 比較 | Wanda、LLM-Pruner、FLAP、Bonsai、LoRAPrune等 |
| 削除率 | 通常の多頭注意モデルとGQAモデルで約20〜50%の構造的枝刈り |
| 追加学習 | LoRAあり・なしを明示して比較 |

### ゼロショット精度と枝刈り費用：原著Table 4/5

LLaMA-7Bの6タスク平均正答率は元モデル70.48、TVA-Prune＋LoRA 52.44である。Bonsai＋LoRAは52.33、LoRAPrune＋LoRAは52.17で、近い水準となる。ただし、TVA-Pruneの52.44は元モデルから18.04ポイントの低下であり、競合方式より良いことと元の能力を保持することは同じではない。

LLaMA2-7Bを50%枝刈りする実験では、TVA-Pruneの圧縮時間はA100一台で2 GPU時間、Bonsaiは一台で40 GPU時間と報告する。これは20分の1の圧縮費用であり、論文の「90%以上の時間削減」の根拠である。LLM-Prunerは4GPUで1時間と報告され、GPU台数と経過時間が異なるため、単純な壁時計時間だけで比較してはならない。

## 既存研究との差

WandaやFLAPは局所的な活性・重み統計に基づいて構造を削除する。Bonsaiは候補部分モデルの評価を繰り返すため圧縮時間が長い。TVA-Pruneは変分マスクを学習して前層全体のトークン依存を考慮し、GQAのヘッド関係を保ち、さらにGPUの実行効率を考慮して残存行列を調整する。モデルの表現をどこまで削除するかだけでなく、残した行列が実際に速く動くかを重視する。

この研究は単純な層削除ではなく、注意ヘッド、FFN、隠れ次元を同時に扱うため、ShortGPTとは削除粒度が異なる。両者は速度改善と品質劣化の交換条件を持つが、TVA-Pruneは行列形状をGPUの演算器へ合わせる工程を明示的に設けている点が特徴である。

## 限界

50%の枝刈りではPPLが元モデルより大幅に悪化し、LoRA後でも完全には回復しない。ゼロショット6タスクの平均正答率も70.48から52.44へ低下する。競合方式より相対的に良いことを、無損失圧縮と解釈するべきではない。枝刈りにC4の5000例を使い、LoRAによる回復には追加学習費用が必要である。

実測速度はA100 40GB単体に依存し、他GPU世代や小さなVRAM、異なるバッチサイズで同じ倍率になるとは限らない。Tensor Coreに合わせる最適な行列寸法はモデルごとに異なり、64や128の倍数が必ず最良とは限らない。論文は短い文脈のベンチマークを中心とし、長文脈検索、コード生成、複雑な推論への影響は十分に示されていない。

### 再現時に区別すべき費用

圧縮を行う際には、元モデルの重みを凍結したままマスクだけを学習する段階と、圧縮後に残存重みを追加学習する段階を区別する必要がある。前者は不要な構造を決める工程であり、後者は圧縮で失われた予測能力を回復する工程である。追加学習後の困惑度を、追加学習を行っていない比較方式の結果と直接比べると、圧縮方式そのものの優劣を正しく評価できない。今回の原著は、両方の条件を示すことで、速度改善と精度回復の費用を切り分けられるようにしている。

また、モデルの削除率を同じにしても、どの行列のどの次元を削除するかによって実際の演算時間は変わる。ある層の次元を減らすと、次の層が受け取る入力の形も変わるため、全層を通して寸法の整合性を維持する必要がある。特に注意ヘッドの削除は、クエリとキー・値の共有関係を守らなければ実行できない。したがって、単純に重要度の低い次元を個別に消すだけでは、実行可能な圧縮モデルが得られない場合がある。

推論速度の測定には、GPUの種類、バッチサイズ、入力長、出力長、カーネルの実装が影響する。行列の大きさが演算器のブロックに合わないと、理論的に計算量が減っても余分なパディングや低い利用率が発生する。寸法調整後の速度が大きく改善したという結果は、実際のハードウェアを考慮した圧縮が必要であることを示している。ただし、異なる世代のGPUでは最適な倍数が変わり得るため、原著の設定を固定して使うより、実際に使う演算器の形状と速度を測定するのが適切である。
