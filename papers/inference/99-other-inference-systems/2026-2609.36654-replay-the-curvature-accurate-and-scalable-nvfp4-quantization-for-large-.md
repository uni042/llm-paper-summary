# Schur Replay：GPTQの逐次補償を考慮したNVFP4量子化と大規模処理基盤

## 概要

NVFP4は、16個の重みを4ビットのE2M1形式で表し、各16個のまとまりにE4M3形式の共有スケールを割り当てる低精度表現である。重みの保存量とメモリ転送量を減らせる一方、16個の値に共通のスケールを使うため、一つのスケールの選択がブロック全体の丸め誤差を左右する。さらにGPTQでは、先に量子化した列の誤差を後続列へ補償するので、ブロックの最初の値だけを見てスケールを選ぶと、実際の逐次処理で生じる誤差を正しく評価できない。

本論文は、候補スケールごとにGPTQの列順更新をブロック内で再現し、まだ量子化していない列が補償できる分を考慮した誤差を測るSchur Replayを提案する。別の貢献として、巨大モデルの事後量子化で一度に保持する重みを一層に限定し、校正活性をGPU・CPU・ディスクに分けて保持し、同じ層の出力行を複数GPUへ分配する実行基盤を設計する。

Qwen3.5-397B-A17Bでは7評価課題を問題数で重み付けした正答回復率がBF16比99.35%、Llama-3.3-70B-Instructでは100.84%となる。397Bモデルの層単位GPTQ処理はModelOpt比15.17倍、LLM Compressor比23.14倍速い。ただしこれらの速度比は基盤の比較であり、Schur Replayの追加スケール探索時間を含まず、397Bの全モデル処理時間は実測ではなく推計である。

## 問題設定：共有スケールと逐次誤差補償

通常の量子化は、元の重みをスケールで割って表現可能な値へ丸め、再びスケールを掛ける。広い範囲の重みを同じスケールで表すと、少数の外れ値のために大半の重みの分解能が低下する。NVFP4は小さなブロックごとにスケールを持たせ、局所的な値域を表現しやすくする。形式上はE2M1の4ビット値とブロックスケールの記録が必要で、重み一個あたりの実効保存量は約4.5ビットになる。

GPTQは校正活性から得た二次統計を使い、量子化した列の誤差を未量子化列へ補償する。列を一つ処理するたびに後続列の値が変わるため、同じ16個のブロックでも、先頭で見た重みと、実際に量子化される時点の重みは異なる。ブロックを独立に丸めた誤差が小さいスケールでも、GPTQの逐次補償後には品質が悪化する可能性がある。

また、数百Bパラメータのモデルでは、全精度重み、校正活性、二次統計を一つのGPUへ載せられない。従来の層単位オフロードでは、一層を一つのGPUに割り当てるため、巨大な層の計算が直列になり、GPU数を増やしても処理が進まない場合がある。Schur Replayはスケール選択の問題と、巨大モデルを量子化する実行基盤の問題を分離して解く。

## 手法

### 条件付き誤差をSchur補完で評価する

現在の16列ブロックより前に量子化済みの列を固定し、現在のブロックと後続の未量子化列を分ける。候補スケールを選んだときの誤差のうち、後続列の重みを自由に調整すれば打ち消せる成分を除き、現在のブロックを確定した後に残る誤差を評価する。数学的には、入力活性の二次統計を分割し、未量子化列を消去したSchur補完の二次形式で候補スケールを比較する。

原著§4.1の式(7)〜(9)では、現在ブロックの誤差ベクトルと条件付き曲率行列から、後続列が最適に補償した後の再構成誤差を定義する。この評価は、単純な重みの二乗誤差や現在ブロックだけの曲率では見落とす、後続列の補償余地を考慮できる。ただし後続列は連続値として最適に補償できると仮定しており、実際には後続列も離散的に量子化されるため、最終的な全層損失そのものを厳密に計算したわけではない。

### スケール候補の提案と逐次再生

スケールと量子化コードの関係は非線形なので、まずコードを固定した二次最小化で有望なスケールを推定する。原著はこの更新を3回繰り返し、候補が集中しそうな領域を選ぶ。その周囲のハードウェアで表現可能なE4M3スケールだけを取り出し、各候補を同じブロック開始状態からGPTQの列順に再実行する。

再生中は、最初の列を丸めた誤差を次の列へ反映し、次の列を丸めてさらに後続へ反映する。16列の量子化結果が確定したら、Schur補完で定義した条件付き誤差を計算し、最も小さい候補を選ぶ。候補ごとに独立した作業状態を持つため、先に試した候補の補償が次の候補の評価へ混入しない。

現在使っているスケールも候補集合へ含めるので、選んだスケールの条件付き誤差が元のスケールより悪くならないというブロック単位の保証がある。ただしこれは校正データ上の条件付き二次目的についての保証であり、すべての下流タスクの正答率が単調に改善することを意味しない。

### メモリ階層と同一層の出力行並列

実行基盤では、量子化中の一層だけをGPUへ載せ、校正活性をGPU、CPUメモリ、SSD、HDFSへ段階的に退避する。量子化が終わった全精度層はNVFP4形式へ書き出して解放し、次の層を読み込む。処理が途中で中断されても量子化済み層を再利用できるようにし、巨大モデル全体を最初からやり直さずに済むようにする。

GPTQの列順更新は同じ出力行の中では逐次的だが、異なる出力行は独立している。そこで一つの層の出力行を複数のテンソル並列ランクへ分け、同じ層を複数GPUで同時に量子化する。層全体を一つのGPUに割り当てる方式と異なり、幅の大きい層でも複数GPUを活用できる。アルゴリズム自体の量子化品質と、基盤の処理速度を別々に測定することが本論文の評価上の特徴である。

## 評価条件と主要結果

| 項目 | 原著の条件 |
|---|---|
| モデル | Qwen3.5-397B-A17B、Llama-3.3-70B-Instruct |
| 量子化 | NVFP4、W4A4を中心にW4A16も補足評価 |
| 品質評価 | MMLU-Pro、GSM8K、CMath、LiveCodeBench、MGSM、HumanEval、GPQA-Diamond |
| 問題数 | 7課題合計15,461問、問題数で重み付けした回復率 |
| 比較 | GPTQ、ScaleSweep、SOAR、AWQ、SmoothQuant、ARCQuant、MR-GPTQ等 |
| 基盤比較 | ModelOpt、LLM Compressorと層単位処理時間・メモリを比較 |

### W4A4の品質

| Qwen3.5-397B-A17B | 問題数重み付きBF16回復率 |
|---|---:|
| GPTQ | 96.69% |
| ScaleSweep | 97.28% |
| SOAR＋GPTQ | 98.38% |
| Schur Replay | **99.35%** |

| Llama-3.3-70B-Instruct | 問題数重み付きBF16回復率 |
|---|---:|
| GPTQ | 98.67% |
| ScaleSweep | 99.03% |
| SOAR＋GPTQ | 100.20% |
| Schur Replay | **100.84%** |

原著Table 1〜2。100%を超える回復率は、有限の評価問題における正答数がBF16をわずかに上回ったことを意味し、量子化が一般に全精度より高品質であると証明したものではない。Qwen3.5ではBF16のMMLU-Pro正答率76.09に対しSchur Replayは75.40、LiveCodeBenchでは44.75に対し42.25、GPQA-Diamondでは55.05に対し52.53と悪化する課題がある。平均の改善だけで個別タスクの損失を隠してはいけない。

### 候補探索のアブレーション

候補窓の半幅を1、4、8、16と変えたQwenのマクロ回復率は、それぞれ97.70%、98.92%、98.62%、97.21%である。探索窓を大きくすると条件付き誤差の最良候補を含む割合は上がるが、下流の正答率は必ずしも改善しない。半幅4では最良候補の被覆率が約83.3%、半幅8では99.96%以上となる一方、マクロ回復率は半幅4の方が高い。

原著Appendixの比較では、逐次再生を使わず静的にブロックを丸めた場合や、Schur補完ではなく通常の二乗誤差で評価した場合に正答数が減る。Qwenの合計正答数はBF16が12,047問、提案方式が11,968問、静的再生＋Schurが11,953問、逐次再生＋単純二乗誤差が11,878問である。したがって、逐次補償を再現することと、条件付き曲率で評価することの両方に寄与がある。

### 量子化基盤の処理時間

397Bモデルの同じ入力条件における層単位GPTQ処理時間は、提案基盤120.25秒、ModelOpt 1,824.29秒、LLM Compressor 2,782.89秒である。速度比は15.17倍と23.14倍になる。ピークGPUメモリは提案基盤35.0GB、ModelOpt 218.6GB、LLM Compressor 86.6GBと報告される。

一方、397Bの全モデル処理時間として示す2.01時間、30.63時間、46.42時間は、層単位の実測から計算した推計であり、全モデルをそれぞれ実際に完走して測定した値ではない。70Bについては全モデルの実測があり、提案基盤0.80時間、ModelOpt0.91時間、LLM Compressor2.09時間となる。397Bの層単位での大幅な高速化が、70Bの全モデルでも同じ倍率になるわけではない。

さらに、Schur Replayのスケール探索そのものは追加費用を伴う。著者は70Bで1.22時間、397Bで2.67時間の追加校正処理を別途報告しており、基盤の15.17倍・23.14倍という速度比にこれらの時間を含めていない。アルゴリズムの品質改善と基盤の処理時間短縮を一つの端から端までの速度比として扱うのは不適切である。

## 限界と既存研究との差

既存のNVFP4量子化では、スケールの初期値やブロック内の分布を調整する方式が多い。Schur Replayは、実際のGPTQの逐次誤差補償を再現したうえでスケールを比較する点が異なる。また、同一層の出力行を並列化する基盤は、従来の層単位オフロードやモジュール単位分散とは異なる並列化の軸を使う。

ただし、論文は2026年9月時点のプレプリントであり、著者はコードと量子化済みモデルを採録後に公開する予定としている。現時点で一般に再現できる完成実装が公開済みであるとは扱わない。著者の内部資産や運用統合も公開対象外であり、巨大モデルでの全工程の独立再現には制約がある。

品質の比較では、質問数の多いMMLU-Proが全体の回復率を強く左右する。LiveCodeBenchやHumanEvalのように問題数が少ない課題の損失は、問題数重み付き平均では相対的に小さく見える。コード生成や数学的推論が重要な用途では、平均回復率だけでなく課題別の精度と出力の失敗例を確認する必要がある。量子化による生成トークン毎秒の実測改善も、この論文の主要な評価対象ではない。

実用上は、巨大モデルをNVFP4へ変換する際の校正精度と量子化準備のGPU費用を改善する研究として位置付けられる。実際の運用速度、ピークVRAM、KVキャッシュ、バッチ処理の利得は別途測定が必要である。397Bの全モデル時間が推計である点と、追加スケール探索費用が基盤速度比に含まれない点は、導入判断で特に重要な留保となる。
