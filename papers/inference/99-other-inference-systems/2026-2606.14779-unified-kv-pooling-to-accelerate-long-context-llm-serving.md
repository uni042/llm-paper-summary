# Unified KV Pooling to Accelerate Long-Context LLM Serving

> 複数RAM/SSDを帯域幅比例の単一KVプールとして並列利用し、SPDK直アクセスでファイルシステムを迂回して長文脈KV再取得を高速化する。
## 書誌情報
- **著者**: Minchul Kang, Changyong Shin, Jinwoo Jeong, Jaerim Park, Woohyun Kim, Bonyul Gu, Dongwoo Kang, Gyeongsik Yang, Chuck Yoo
- **著者・所属**: Korea University; KT Corporation
- **公開**: arXiv:2606.14779v1
- **種別**: Preprint
- **対象**: KVキャッシュ、長文脈推論、SSDオフロード、SPDK、階層メモリ、並列I/O
- **実装**: 既存LLM servingのKV オフロード経路へKV orchestrator、GLT、帯域-aware allocator、SPDKベースKV-passthroughを実装。公開コードURLは一次本文から確認できない。
## 概要
長文脈LLMではGPUから退避したKVキャッシュの再取得がホストメモリとSSDの直列I/O経路に集中し、128K文脈でTTFTが約30.7秒まで増大する。さらにSSD再取得時間の84%をカーネルファイルシステム処理が占める。Unified KV Poolingは複数のホストメモリモジュールとSSDを帯域幅比で束ねた単一論理プールとして扱い、KV orchestratorがKV断片を帯域比例で配置して並列にオフロード/retrieveする。SSD側ではKV-passthroughがSPDKを用いてユーザー空間からLBAを直接読み書きし、ファイルシステムを迂回する。LLaMA 3.1-8B、GPT-OSS-20B、Qwen3-30B-A3Bで長文脈TTFTを既存法比最大約4.1倍短縮し、全設定を10秒未満にし、blocked I/Oを最大23.2倍削減した。

提案法は主記憶モジュールとSSDを別々の退避先ではなく一つの論理的なKVプールとして扱う。KVオーケストレータが各装置の実効帯域から配置比率を計算し、鍵・値キャッシュを層順に分割して装置ごとの作業スレッドへ並列発行する。さらにKVパススルーが大域参照表に保持したSSDの論理ブロックアドレスを用い、SPDKからユーザー空間でNVMe命令を直接発行する。大規模言語モデルの実行系は対象KVの識別子と配置を既に把握しているため、一般用途のファイル名探索やメタデータ管理を省ける点が新しい。

代表結果として、128K TTFT / LLaMA 3.1-8Bは128K contextでLMCache比約2.9倍、LMCache+LP比約2.6倍、LMCache+LP+AsyncKV比約2.1倍短縮に対して5.6 s。複数メモリ/SSDの並列帯域とfilesystem bypassを統合すると、長文脈でも10秒要件内へ入る。
## 問題設定
長文脈の大規模言語モデルでは、過去トークンの鍵・値キャッシュが文脈長に比例して増えるため、GPUだけでは保持できず主記憶やSSDへ退避する。ところが既存の退避機構は、再取得要求を一組の主記憶とSSDへ直列に流す設計が中心で、サーバに複数のメモリチャネルや複数SSDがあっても同時利用できない。論文の測定では128K文脈で最初のトークンまで約30.7秒、GPUが入出力を待つ時間が13.8秒に達し、SSD再取得時間の84%は実デバイス転送ではなくカーネルのファイルシステム処理だった。既存の層単位パイプライン化や非同期読み込みは計算と入出力の重なりを増やすが、単一経路への集中とファイルシステム処理そのものは残る。このため、モデルやキャッシュ内容を変えずに、階層メモリ全体の合計帯域を同時利用し、SSDまでのソフトウェア経路も短くする必要がある。
## 新規性
提案法は主記憶モジュールとSSDを別々の退避先ではなく一つの論理的なKVプールとして扱う。KVオーケストレータが各装置の実効帯域から配置比率を計算し、鍵・値キャッシュを層順に分割して装置ごとの作業スレッドへ並列発行する。さらにKVパススルーが大域参照表に保持したSSDの論理ブロックアドレスを用い、SPDKからユーザー空間でNVMe命令を直接発行する。大規模言語モデルの実行系は対象KVの識別子と配置を既に把握しているため、一般用途のファイル名探索やメタデータ管理を省ける点が新しい。
## 手法
### 手法のあらまし
処理は退避対象の鍵・値集合が生じた時点から始まる。まずプール構成器が利用可能な主記憶モジュールとSSDを列挙し、それぞれの帯域を全装置の帯域合計で正規化して割当比率を求める。次に帯域認識KV割当器が退避対象を層順に走査し、この比率に従って装置別集合へ分ける。各装置には独立した作業スレッドがあり、主記憶にはメモリコピー、SSDにはKVパススルー経由の非同期書き込みを同時発行する。書き込み完了後は、各KVの検索キーと実際の保存装置・保存位置を大域参照表へ登録し、後続要求から直接位置を引ける状態にする。

再取得では推論器が必要なKVの検索キーを渡し、大域参照表がそれらを保存装置ごとの要求へ変換する。主記憶側はメモリコピー、SSD側は保存済み論理ブロックアドレスへの非同期NVMe読み込みを並行して開始し、SSD完了は専用CPUコアのSPDKポーリングで回収する。各装置から戻ったKVをGPUへ転送し終えると、通常の注意計算がそのまま再開する。高帯域装置ほど多く配置してあるため並列経路の終了時刻が揃いやすく、単一装置への要求集中とファイルシステム処理の双方を除くことで、退避開始から再取得・GPU復帰まで一貫して待ち時間を削減する。

### 大域参照表（GLT）
退避した各KVについて、検索キー、装置番号、装置種別、装置内位置の四情報を保持する。主記憶ならメモリアドレス、SSDなら論理ブロックアドレスを記録するため、再取得時にファイル名やディレクトリを探索せず、要求KVから物理的な保存位置へ直接到達できる。

退避時には帯域認識割当器が実際に選んだ装置と位置を書き込み、再取得時には検索キーから複数KVを装置別に束ねる。この表があることでSSDを通常ファイルとして管理する必要がなくなり、後段のKVパススルーへ論理ブロック位置を直接渡せる。したがって配置決定と直接入出力を接続する中核メタデータである。

### プール構成器
サーバ上の複数主記憶モジュールと複数SSDを一つの資源集合として列挙し、各装置の帯域幅に比例したKV割当比率を決める。高帯域装置には大きなデータ量、低帯域装置には小さなデータ量を担当させ、並列読み込み時に特定装置だけが長時間残る状態を避ける。

単純な均等分割では、主記憶とSSD、あるいは性能の異なるSSD間の帯域差によって遅い装置が全体完了を支配する。そこで装置性能を割当量へ反映し、後段の割当器がその比率どおりに退避集合を作れるようにする。出力は各装置が担当すべきKV量の割合であり、実データ配置そのものは次段が担う。

### 帯域認識KV割当器
退避対象KVを層順に列挙し、プール構成器の比率に従って装置ごとの退避集合へ分割する。各装置専用の作業スレッドが独立した入出力列として書き込みを発行するので、従来の一経路直列化では遊休していたメモリチャネルとSSDを同時に動かせる。

各書き込みが確定すると保存装置と位置を大域参照表へ戻し、再取得では同じ表を使って要求を装置別に再構成する。このため帯域比例の配置方針が読み出し側でもそのまま並列性へ変換される。単に複数装置へ散らすのではなく、装置性能に応じて担当量を変えることで最遅経路を短くする役割を持つ。

### KVパススルー
SSD上のKVを通常ファイルとして扱わず、SPDKを介してユーザー空間からNVMe装置へ直接アクセスする。保存処理では割当済みKV集合に必要な連続論理ブロック領域を確保し、非同期書き込みを発行してその位置を大域参照表へ返す。

再取得では表にある装置番号と論理ブロックアドレスから非同期読み込みを直接発行し、専用CPUコアのポーリングで完了を検出する。推論器はKVの識別子と配置を自前で管理しているため、一般用途のファイルシステムが提供する名前解決やメタデータ処理を必要としない。これによりSSD再取得時間の84%を占めたソフトウェア処理を経路から外す。

### 並列再取得経路
推論器から再取得要求を受けると、大域参照表で要求KVを保存装置ごとにまとめ、主記憶コピーと複数SSD読み込みを同時に開始する。既存の層単位パイプライン化と併用しながら、計算との重なりだけでなく入出力自体も装置間で並列化する。

帯域比例配置によって各装置の担当量があらかじめ調整されているため、並列要求の完了時刻が揃いやすい。各経路のKVがGPUへ戻れば通常の層計算へ接続され、モデル側に特別な処理は要求しない。この経路が最終的にGPUの停止時間を減らし、最初のトークンまでの遅延改善へつながる。

### 全体のデータ／制御の流れ
モデル重み、注意計算、KV表現は変更せず、推論器のKV退避・再取得層だけを置き換える。GPUの下に複数主記憶と複数NVMe SSDから成る論理KVプールを置き、位置管理を大域参照表、配置と並列発行をKVオーケストレータ、SSDの直接データ経路をSPDKベースのKVパススルーが担当する。SPDKの完了確認は専用CPUコアで行い、通常のKV処理との干渉を避ける。

既存の層単位パイプライン化や非同期KV読み込みは排除せず、その上で保存装置の並列性と直接SSD経路を追加する構成である。したがって入力は通常の退避対象KV、出力はGPUへ復帰した同一KVであり、上位の推論スケジューラやモデル計算からは透過的に利用できる。制御情報の追加費用は長文脈でも84ミリ秒未満と報告され、主な遅延削減を打ち消さない。
## 評価条件
- **ハードウェア**: 複数ホスト-メモリ moduleと複数NVMe SSDを備えたGPU serverで評価し、SSD direct I/OはSPDKを使用する。SPDK completion pollingには専用CPU coreを割り当てる。論文の主張はdevice数と帯域を横断したpooling効果を測る。
- **ソフトウェア**: LMCache系KV オフロードを比較基盤とし、layerwise pipelining (LP) と asynchronous KV loading (AsyncKV) を段階的比較対象として比較。提案系はKV orchestrator、GLT、帯域-aware allocator、SPDK KV-passthroughをserving pathへ統合する。
LLaMA 3.1-8B、GPT-OSS-20B、Qwen3-30B-A3Bを用い、主に16K〜128Kの長文脈でTTFTとblocked I/O timeを測定する。比較対象はLMCache、LMCache+LP、LMCache+LP+AsyncKV。主評価はfull unified KV pooling、orchestrator-only、passthrough-onlyの比較を含み、複数device並列化とfilesystem bypassの寄与を分離する。さらにpool metadata/coordination オーバーヘッドを測り、長文脈でも84ms未満かつTTFTの約0.8%以下であることを確認する。
対象はKVをホスト-メモリ/SSDへオフロードして後でretrieveする長文脈servingであり、KV圧縮・量子化・モデル精度改善は扱わない。SPDK pollingはCPU利用率を増やし専用coreを必要とする。複数tenantがstorage 帯域を競合する条件は主要評価外で、user-level interruptやhybrid pollingは将来課題。
## 主要結果
Unified KV Poolingは128K級長文脈で全3モデルのTTFTを10秒未満へ抑え、既存LMCache系列に対して最大約4.1倍の短縮を示す。LLaMA 3.1-8Bでは128Kで5.6秒、GPT-OSS-20Bでは5.2秒、Qwen3-30B-A3Bでは9.8秒。blocked I/OはGPT-OSS-20BでLMCache比23.2倍、Qwen3-30B-A3Bで17.9倍低減し、直列device利用とfilesystem オーバーヘッドの双方を外すことが効く。

- 128K TTFT / LLaMA 3.1-8B / 5.6 s (比較対象: LMCache比約2.9倍、LMCache+LP比約2.6倍、LMCache+LP+AsyncKV比約2.1倍短縮; 条件: 128K context) — 複数メモリ/SSDの並列帯域とfilesystem bypassを統合すると、長文脈でも10秒要件内へ入る。

- 128K TTFT / GPT-OSS-20B / 5.2 s (比較対象: LMCache比約4.1倍、LMCache+LP比約3.7倍、LMCache+LP+AsyncKV比約3.3倍短縮; 条件: 128K context) — 主結果中で最大のTTFT改善を示す。

- 128K TTFT / Qwen3-30B-A3B / 9.8 s (比較対象: LMCache比約3.7倍、LMCache+LP比約3.5倍、LMCache+LP+AsyncKV比約3.1倍短縮; 条件: 128K context) — MoEモデルでも10秒未満を維持し、KV storage path最適化がモデル構造を跨いで効く。

- Blocked I/O / LLaMA 3.1-8B / 0.6 s (比較対象: LMCache比約7.8倍、LMCache+LP比約2.7倍、LMCache+LP+AsyncKV比約1.7倍低減; 条件: 長文脈主設定) — GPU待機の主要因だったstorage retrievalを直接縮める。

- Blocked I/O / GPT-OSS-20B / 最大約23.2倍低減 (比較対象: LMCache比23.2倍、LMCache+LP比19.9倍、LMCache+LP+AsyncKV比19.2倍; 条件: 長文脈主設定) — filesystem bypassとmulti-device parallelismの効果が特に大きい。

- 制御オーバーヘッド / 84 ms未満、TTFTの約0.8%以下 (比較対象: 提案機構なし; 条件: context増大時を含む) — GLT/allocator/device coordinationの追加コストは主なTTFT利得に比べ小さい。

### 負の結果・境界条件
- SPDK pollingはカーネル interruptを避けて低遅延化する代わりにCPU利用率を増やし、実装では専用CPU coreを割り当てる。pooling metadataとcoordination オーバーヘッドは文脈長とともに増えるが84ms未満に留まる。提案はSSD容量そのものやKV footprintを減らさないため、容量不足には圧縮・量子化・ホスト オフロード等との併用が必要。

### 結果の読み方
既存のKV オフロードではSSD性能そのものよりsoftware pathとdevice利用率が支配的ボトルネックになり得る。複数deviceを帯域比例で同時利用し、既知KV objectに一般filesystemを介さないことで、SSDを単なる大容量tierから実効帯域を集約できるserving資源へ変える。
## 品質への影響
KV値・モデル重み・attention計算を変更しないため、精度を犠牲にする圧縮ではなくI/O 遅延のみを最適化する。
## 既存研究との差
LMCacheはKV再利用・オフロード層を提供するが、既存経路では特定ホスト-メモリ/SSDへの直列アクセスが残る。Layerwise pipeliningやAsyncKVはI/OとGPU計算のoverlapを増やすのに対し、Unified KV PoolingはI/Oそのものを複数deviceへ分散し、さらにSPDKでfilesystemを除去する。KV圧縮・量子化・追い出し系とは直交し、KVの情報量を変えずstorage hierarchyのdata pathを高速化する点が異なる。
## 限界
KV footprint自体は減らさず、十分なホスト-メモリ/SSD容量が前提である。SPDK pollingはCPU coreを継続消費し、user-level interruptやhybrid pollingによる改善余地がある。複数tenantが同一pool帯域を競合する場合の公平性・QoSは主要評価外である。性能は複数メモリ/SSDを備えるserver構成に依存し、単一device環境ではpoolingによる帯域集約利得が小さい。
## 実装状態

## 研究上の位置づけ
CPU/SSD/NVMeを使う階層メモリ型LLM推論の中でも、SSDを単なる容量拡張ではなく複数deviceのaggregate 帯域として扱う研究に位置する。特にエキスパート/KV オフロードで問題になる『PCIe/NVMeは速いのにsoftware stackと単一queueで詰まる』問題へ、帯域比例配置とuser-space direct I/Oを組み合わせる設計例を示す。KV圧縮と併用すれば転送量削減と経路高速化を重ねられるため、SSD活用型推論基盤との関連が強い。
