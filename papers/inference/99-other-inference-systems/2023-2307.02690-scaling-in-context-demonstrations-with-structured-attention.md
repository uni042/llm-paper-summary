# SAICL：文脈内学習の例示間注意を削り、例示数に線形の計算量へ変える

## 概要

文脈内学習（In-Context Learning、ICL）は、質問と回答の例示をプロンプトに含め、モデルの重みを更新せずに新しいタスクへ適応させる。例示数を増やせば精度が改善する可能性があるが、全ての例示を連結して密な自己注意を実行すると、系列長の二乗に比例する演算量とメモリが必要になる。さらに例示の順番を変えるだけで予測結果が変わり、良い並び順を探索する追加費用も発生する。

SAICL（Structured Attention for In-Context Learning）は、**例示どうしの直接注意を取り除き、テスト入力を情報集約のハブにする**。各例示のトークンは自分自身とテスト入力のトークンだけを参照し、テスト入力は全例示を参照する。次の層ではテスト入力が集約した情報が各例示へ伝わるため、例示間の情報伝達を完全に切断せずに密な全結合を避けられる。相対位置符号化を例示内に閉じることで、例示の順序を変えても同じ出力を得る対称性を設計上確保する。

論文はT5-LM-adapt large（770Mパラメータ）を用いてメタ学習し、全注意のT5、例示を独立に符号化するFusion-in-Decoder（FiD）などと比較した。全注意と同等以上の結果が28設定中13、FiDを上回る結果が28設定中18と報告する。推論速度は例示64件で最大3.4倍、128件で6.3倍の改善を報告する。ただし、これはT5系のエンコーダ・デコーダ構成での評価であり、一般的なデコーダ専用LLMの長文生成をそのまま6.3倍高速化するという意味ではない。

## 問題設定：例示を増やすと何が律速になるか

### 例示連結と全注意の計算費用

例示数をk、例示ごとの最大トークン長をLとすると、全ての例示を連結した入力長はおおむねkLになる。密な自己注意のスコア行列は(kL)×(kL)なので、計算量・注意行列メモリはO(k²L²)で増える。例えば例示数を16から64へ4倍にすると、注意スコア要素数は単純計算で16倍になる。テスト入力も含まれるが、支配項の増え方は変わらない。

一方、例示の理解に必要なのは、各例示内部の入力と正解の関係、およびその関係をテスト入力へ適用する情報である。例示Aの全トークンが例示Bの全トークンを毎層直接参照する必要は必ずしもない。ここに構造化注意の余地がある。ただし例示間の依存を完全に消すと、例示を組み合わせて判断する能力を損なう可能性がある。

### 順序依存の問題

通常の連結プロンプトでは、同じ例示集合でも順序によって相対位置が変わり、予測が変化する。最後に置いた例示のラベルへ引きずられる新近性バイアスが知られる。順序を最適化するために多数の並べ替えを評価すると、推論費用がさらに増える。SAICLは例示の集合としての対称性を注意マスクと位置符号化へ組み込むことで、順序探索の必要性を減らそうとする。

## 手法

### 1. 例示内とテスト入力を中心とした注意マスク

k個の例示と一つのテスト入力があるとする。通常の全注意は任意の例示トークンから全ての例示トークンへの注意を許す。SAICLでは例示iのQueryが参照できるKey/Valueを、例示i自身とテスト入力のトークンに制限する。他の例示jのトークンへ直接注意する経路は設けない。対してテスト入力のQueryは、全ての例示とテスト入力自身へ注意できる。

この非対称なマスクが重要である。テスト入力は全例示から必要な情報を集約し、次のエンコーダ層で各例示がテスト入力を参照することで、例示間の情報を間接的に受け取れる。各例示を完全に独立処理するFiDよりも、層を重ねる間に情報が往復する余地を残す。注意のスコア自体は各許可領域で通常のQuery/Key内積とsoftmaxを使い、学習済みモデルの外側に単なる検索器を追加する方式ではない。

### 2. 線形の例示数依存

各例示内部の注意は長さLに対してO(L²)であり、k個ならO(kL²)となる。テスト入力から各例示への全域注意も、テスト入力長をL程度と見なせばO(kL²)である。従って総計算量はO(kL²)となり、全注意のO(k²L²)から例示数kについて一次の増加へ変わる。注意行列の中間メモリも同様に削減できる。

ただし、この計算量は**例示ごとの長さLを固定した場合**の漸近比較である。各例示自体が非常に長いとL²の費用は残る。また疎な領域ごとの処理はカーネル起動やデータ再配置のオーバーヘッドがあるため、例示数が小さい条件では理論比ほど速くならない。論文も少数例示では利得が小さいと認めている。

### 3. 例示順序に対する不変性

T5のエンコーダは相対位置に基づく注意バイアスを用いる。SAICLは位置バイアスを各例示内部、またはテスト入力内部に限定し、例示をまたぐ位置差を使わない。全ての例示を入れ替えても、各例示の内部構造とテスト入力が参照する集合は変わらない。このためモデルの構造上、例示の並べ替えに対する不変性が得られる。

この設計はT5の双方向エンコーダと相対位置符号化を活用している。デコーダ専用モデルの因果マスクでは、前の例示から後の例示への情報の流れが非対称なので、同じ性質を無変更で実現できない。論文は位置符号化と注意マスクの変更により適用可能と議論するが、GPT系への同等の大規模実測を示してはいない。

### 4. メタ学習と予測経路

著者はCrossFitとUnifiedQA由来の142ソースタスクを用い、例示とテスト入力の組をプロンプトにしたメタ学習を行う。入力を例示ごとに分割し、構造化注意で符号化した表現をT5デコーダへ渡し、テスト入力に対する候補回答の条件付き確率を評価する。分類ではマクロF1、非分類では正答率を用いる。

実験では直接方式（テスト入力から回答を予測）より、回答候補を条件にテスト入力の確率を求めるチャネル方式（channel method）を主に採用する。これは確率の較正が良いという先行知見に基づく。したがって、原著の性能値を単純な「回答を一トークンずつ生成するデコーダ専用チャットモデル」と同一視してはならない。

## 評価

### モデル、転移設定、比較対象

| 項目 | 条件 |
|---|---|
| モデル | T5-LM-adapt large、770Mパラメータ |
| 学習 | 142ソースタスク、7転移設定、例示16または64でメタ学習 |
| テスト | 未見のターゲットタスク、例示16/64、各5種類のランダム例示集合で平均 |
| 比較 | 全注意T5、FiD、GPT-2を使うMetaICL系の参考値 |
| 指標 | 分類のマクロF1、その他の正答率、推論時間 |
| 推論速度環境 | RTX A6000、各条件10回平均、例示長64/128の合成入力 |

全注意T5とFiDも同様の転移設定でメタ学習して比較する。MetaICLの一部は別モデル系列の参考値なので、同一アーキテクチャの直接比較として扱わない。論文は全ての転移設定でSAICLが最良とは主張していない。

### 転移精度の代表値と負の結果

| 全ターゲットの転移設定 | T5全注意 64-shot | FiD 64-shot | SAICL 64-shot |
|---|---:|---:|---:|
| 高資源→低資源 | 52.7 | 50.7 | 53.6 |
| 分類→分類 | 57.2 | 57.6 | 58.3 |
| 非分類→分類 | 58.9 | 48.6 | 53.3 |
| QA→QA | 46.4 | 46.6 | 46.3 |
| 非QA→QA | 44.6 | 45.3 | 44.3 |
| 非NLI→NLI | 48.1 | 53.7 | 48.9 |
| 非言換→言換 | 55.6 | 57.2 | 57.8 |

原著表1では、64-shotの分類→分類などでSAICLが優位になる一方、非分類→分類では全注意T5の58.9に対してSAICLは53.3で劣る。非QA→QAでもFiD 45.3に対しSAICL 44.3である。したがって、**精度が常に全注意以上というわけではない**。本文の「28設定中13で全注意と同等以上」「28設定中18でFiDを上回る」は、全ての設定で勝ったという主張ではない。

### 推論速度とメモリ

論文は各例示の長さ64または128の合成入力を用い、RTX A6000上で例示数を増やしたときの推論時間を10回平均で測定した。全注意は例示数が増えると急速に遅くなり、64-shot付近でA6000のメモリ上限に達する条件がある。SAICLは例示数に線形の注意費用を持ち、64例示で最大3.4倍、128例示で6.3倍の速度向上を報告する。全注意がメモリ不足となる条件では、単純な時間比を測れないため、比較可能な範囲と外挿を区別する必要がある。

これらはT5ベースの例示符号化における測定であり、GPUカーネルやバッチサイズ、デコーダの生成長、KVキャッシュを含む本番配信のTTFT・TPOT・P99を評価したものではない。速度改善の理由は主にエンコーダ側の例示間注意を削ったことにあり、全てのLLM推論にそのまま適用できる倍率ではない。

### 例示数を増やすときの品質

FiDは例示を個別に符号化するため、例示を増やしても相互の関係を使いにくく、品質改善が飽和する場合がある。SAICLはテスト入力を介して層間に情報を流せるため、数百例示まで拡張して性能が改善する条件を示す。これはモデルに明示的な例示数上限を置かない設計上の利点である。ただし各例示の内容が矛盾する場合や、例示選択の質が悪い場合に、無制限の改善を保証するものではない。

### 未見ドメインへの転移と計算量の解釈

原著表1には、学習時と異なる医療・金融・気候などの未見ドメインに属するターゲットタスクを抜き出した結果もある。64-shotの高資源→低資源では全注意54.7、FiD55.3、SAICL57.4で、構造化注意の方が高い。一方、未見ドメインの非NLI→NLIでは全注意62.3、FiD67.6、SAICL63.4となり、FiDに劣る。つまり、例示間の密注意を削っても転移できる場合はあるが、例示間依存が重要な条件で最良となるとは限らない。

また、例示数kに線形という計算量の議論は、注意演算に関する上界である。モデルの前向き全体にはフィードフォワード層、エンコーダ・デコーダ間の交差注意、候補回答のスコア計算がある。これらの固定費用やメモリ読出しが支配的になると、全体速度は理論的なk倍差ほど伸びない。SAICLが測定した高速化は、実装済みのT5構成において例示が多い条件で得られた値であり、一般の長文脈LLMのデコードカーネルを直接置換した結果ではない。特にテスト入力が長くなると、全例示へ注意するテスト側の計算費用も無視できなくなる。

## 既存研究との差

通常の全注意は任意のトークン対を結び付けられるが、例示数の二乗費用と順序依存を持つ。FiDは各例示を独立に符号化してデコーダで結合するため線形費用と順序不変性を得やすいが、エンコーダの中で例示間情報を交換しにくい。SAICLはテスト入力の全域注意を情報ハブとして残すことで、FiDの効率と全注意の例示間情報融合の中間を狙う。

LongformerやBigBirdなどの一般的な疎注意は、任意の長文書に使える注意パターンを設計する。SAICLは文脈内学習の「例示の集合＋テスト入力」という構造に特化しており、一般長文の意味関係を保つことを目的としない。この対象の狭さが、計算削減と順序不変性を両立させる設計上の前提である。

## 限界・負の結果

第一に、主な評価はT5エンコーダ・デコーダの770Mモデルであり、デコーダ専用の数十BモデルやMoEでの実装・速度・品質は実測していない。T5の相対位置符号化と双方向注意が順序不変性の実現に寄与しているため、RoPEや因果マスクを用いるモデルへは追加設計が必要になる。

第二に、全注意に対する品質の優位は一貫していない。非分類→分類、非QA→QAなどで全注意やFiDに劣る結果がある。例示間の直接注意を除くことで失われる情報もあり、すべてのタスクで例示を増やせば改善するわけではない。

第三に、速度実験は例示長を固定した合成入力であり、実運用の可変長・複数要求・デコーダ長・GPUメモリ断片化・長文脈生成を網羅しない。少数例示では疎注意の実装オーバーヘッドで利得が小さくなる。数百例示の能力は理論上と一部の転移設定の結果であり、無限長コンテキストの保証ではない。
