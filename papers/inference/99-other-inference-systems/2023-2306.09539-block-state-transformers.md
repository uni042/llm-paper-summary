# Block-State Transformers

## 概要

長い系列を処理するTransformerでは、全トークン間の自己注意が系列長の二乗に比例する計算を要する。局所窓へ注意を限定すれば計算量は下がるが、遠く離れた語の関係を扱いにくくなる。一方、状態空間モデル（State Space Model; SSM）は長い系列の情報を再帰的状態または畳み込みとして表現でき、長距離文脈を効率的に要約する。ただし従来のSSM単独モデルは、言語モデルの局所的な語の組合せを扱う際にTransformerへ届かない条件があった。

Block-State Transformer（BST）は、同じ層の中に長距離文脈を担当するSSM副層と、局所表現を担当するブロックTransformer副層を組み合わせる。SSMは入力系列全体を畳み込みで並列処理し、各時刻に過去情報を含む文脈状態を生成する。その出力から選んだ少数の文脈状態を、ブロック内のトークンが交差注意で参照する。ブロック内の自己注意は短距離の関係を処理し、SSMが提供する文脈状態は過去ブロックの情報を届ける。

従来のブロック再帰Transformerは、過去の情報を再帰状態へ更新するためブロックを順番に処理しなければならなかった。BSTはSSMを高速フーリエ変換（Fast Fourier Transform; FFT）による畳み込みで処理できるため、ブロックごとの逐次再帰を取り除ける。単一頭、多頭、複数フィルタの三種類の文脈状態を検証し、文脈の取り出しやすさと状態の冗長性の交換条件を調べる。

PG19の書籍、数学論文のarXiv、ソースコードのGitHubからなる長文言語モデル課題では、同程度の計算予算の混合モデルよりPPLを改善する構成がある。GPUで測った層単体の順方向計算は、ブロック再帰方式に対して単一頭BSTが6〜11倍速い。ただしこれは層単位の測定であり、モデル全体の実時間生成速度が同倍率になることを保証しない。

## 問題設定

全系列の自己注意は入力長`L`が伸びるほど演算と注意行列の記憶量が増える。ブロック長`W`で局所注意へ限定すれば、各ブロックの計算を小さくできるが、現在ブロックから過去の遠い位置を直接参照できなくなる。Block-Recurrent Transformer（BRecT）はブロック間で再帰的な状態ベクトルを更新し、長距離情報を補う。しかし各ブロックの処理が前のブロックの状態更新を待つため、系列方向の並列化を妨げる。

SSMは線形動的系として過去の入力を圧縮した状態へ蓄積する。状態の更新は逐次式として書けるが、時間不変の線形系なら同じ演算を畳み込みへ展開し、FFTを使って系列全体を並列処理できる。そこでBSTは、過去ブロックの状態を逐次再帰で渡す代わりに、SSMで系列全体の文脈状態を先に作り、局所注意へ渡す。

ただしSSMの最終状態一つだけでは、過去のどの語が重要だったかを細かく取り出しにくい。逆に連続する多数のSSM出力をそのまま渡すと、似た状態が多くなり冗長である。BSTはこの取り出しやすさと冗長性を設計問題とし、文脈状態の作り方を三方式で比較する。

## 手法

### 状態空間モデルの文脈生成

SSMは内部状態`x_k`を `x_k = A x_{k-1} + B u_k` で更新し、出力`y_k = C x_k + D u_k`を得る線形動的系で表せる。時刻`k`の出力は過去入力の重み付き和であり、重み列 `K_j = C A^j B` を用いて畳み込み `y=K*u` として計算できる。これにより長さ`L`の系列に対する文脈生成をFFTで概ね `O(L log L)` の計算へ変換し、ブロックを逐次走査せずに全時刻の文脈を得られる。

論文は二種類のフィルタを検証する。一つはS4に代表される構造化状態空間モデルで、行列`A,B,C`から畳み込み核を構成する。核を系列長に応じて生成できるため、学習より長い系列にも構造上は拡張できる。もう一つはHyena型に着想を得た明示的な学習フィルタで、核の各位置をパラメータ化する。後者は複数フィルタを使う場合の核再構築費用を抑えられるが、位置表現を学習長へ依存させやすく、未知の長い系列への一般化が弱い。

SSM副層は系列長`L`と埋め込み幅`D`を持つ系列を受け取り、同じ長さの文脈系列を出す。そこからブロックTransformerへ渡す`S`個の文脈状態を構成する。通常は`S`を`L`より十分小さくし、単一頭方式ではブロック長`W`と同じにする。因果的な言語モデルで未来情報が漏れないよう、現在トークンより後ろに相当する文脈状態には注意マスクを適用する。

### ブロック内自己注意と文脈への交差注意

入力を長さ`W`のブロックへ分け、各ブロックで局所自己注意を計算する。同時に、ブロック内のトークン表現をクエリとして、SSMから取り出した文脈状態へ交差注意を行う。自己注意の出力と交差注意の出力を結合し、線形射影で次層の表現を作る。局所注意が最近の語順や構文を扱い、交差注意がSSMの長距離要約を必要に応じて取り出す。

BRecTと比べた本質的な違いは、文脈状態をブロックごとに再帰更新する回路が存在しないことである。SSMの畳み込みで全系列の文脈を一括生成し、各ブロックの注意計算を並列実行できる。層の理論的な処理費用は、SSMの系列長依存 `O(D L log L)` とブロック内注意の `O(W²)` の和として説明される。ただしブロック数、幅、実装上の定数を省いた概略式であり、GPU上の実測速度はFFTの効率とブロック並列化の程度に左右される。

### 単一頭（SH）方式

単一頭方式では、一つのSSMフィルタが各時刻に出す文脈状態から、現在ブロックに対応する連続`S=W`個を選ぶ。各状態にはそれ以前のブロックの情報が含まれるが、隣接状態は互いによく似るため冗長である。代わりに、現在ブロック直前の細かな情報を取り出しやすい。文脈状態を通常の線形射影で複数の注意頭へ展開し、現在ブロック内の未来時刻の状態には三角形の因果マスクを適用する。

書籍のPG19では、この連続した状態を保持する設計が有利になりやすい。著者らは、局所的な語のつながりを復元するために冗長な近接状態が役立つと考察する。最も単純で速度も良い一方、すべての注意頭が同じ元SSM系列から特徴を受け取るため、頭ごとの専門化には限界がある。

### 多頭（MH）方式

多頭方式では、SSM内部状態から出力を取り出す行列`C`を注意頭ごとに別々に用意する。各頭が同じ内部履歴から異なる特徴を取り出せるため、単一頭より相補的な文脈を提供できる可能性がある。文脈状態は時間順に並ぶため、単一頭と同様に因果マスクが必要になる。

ただし実験では、多頭S4方式は単一頭より約8%多くのパラメータを要し、言語モデルのPPLはほぼ同程度だった。このため著者らは多頭方式を大規模に展開せず、主に単一頭と複数フィルタを比較する。頭ごとの独立出力が常に品質向上へつながるわけではないという負の結果である。

### 複数フィルタ（MF）方式

複数フィルタ方式では、`S`個の独立した畳み込みフィルタが入力系列をそれぞれ処理する。現在ブロックの直前に位置する各フィルタの最終出力を一つずつ集め、合計`S`個の文脈状態にする。連続時刻の状態を並べるのではなく、異なるフィルタが抽出した特徴を並べるため、文脈間の冗長性を小さくできる。すべての状態が前ブロックから来るため、現在ブロック内の未来情報を遮断する追加マスクは不要である。

複数フィルタでは文脈状態が時刻ではなく特徴に対応するので、各特徴を区別する学習可能な文脈識別子を追加する。単一頭・多頭方式では畳み込みの時間的順序が位置情報を含むため、同じ識別子を必要としない。MF方式は数学論文やソースコードのように離れた概念・定義を区別して保持したい場合に有利な条件があるが、連続状態を使うSHより直近の局所情報を取り出しにくい可能性がある。

### 実装上の効率化

FFTが特にTPU上の学習費用を占めるため、SSMへ渡す埋め込みを元幅の4分の1へ射影し、SSM計算後に元の幅へ戻す。これにより必要なFFTの本数を減らす。大規模MF方式ではSSMの状態次元もさらに縮め、PPLを大きく損なわずに計算費用を抑える。モデルの位置情報には、SSMの時間的情報とT5型の相対位置バイアスを組み合わせ、全系列の絶対位置埋め込みに依存しない。

## 主要結果

### 言語モデルのPPL

| モデル | パラメータ | PG19 PPL | arXiv PPL | GitHub PPL |
|---|---:|---:|---:|---:|
| BRecT:fixed:skip | 196M | 11.55 | 2.36 | 2.04 |
| BST:SH:S4 | 202M | 11.57 | 2.51 | 2.14 |
| BST:MF:S4 | 217M | 11.63 | 2.48 | 2.07 |
| BST:SH:unstruct | 206M | 11.52 | 2.49 | 2.09 |
| BST:MF:unstruct | 221M | 11.56 | 2.44 | 2.03 |
| GSS-Hybrid-L | 373M | 10.52 | 2.51 | 1.88 |
| BST:SH:S4-L | 366M | 10.47 | 2.49 | 1.86 |
| BST:MF:S4-L | 383M | 10.52 | 2.46 | 1.84 |
| BST:SH:unstruct-L | 371M | 10.37 | 2.46 | 1.85 |
| BST:MF:unstruct-L | 388M | 10.42 | 2.41 | 1.83 |

小モデルではBRecTのPPLがarXivで2.36と良く、BSTの2.44〜2.51より低い。したがってBSTが全規模・全データでBRecTのPPLを上回るわけではない。大モデルでは、GSS-Hybrid-Lに対しBSTの構成によってPG19で10.52から10.37、arXivで2.51から2.41、GitHubで1.88から1.83へ改善する。著者らが示す1.5〜4%程度の改善は、主にこの同程度の学習計算予算での大モデル比較に対応する。

小モデルのPG19ではSHの方がMFより良い条件があり、arXiv・GitHubではMFが有利な条件がある。これは、文脈状態の冗長性を小さくするだけが常に最適ではなく、直近状態を連続的に保持する取り出しやすさにも価値があることを示す。S4方式と明示フィルタ方式の比較では、明示フィルタが4K学習長で良いPPLを得ることがあるが、長さ一般化は構造化S4が優れる。

### 学習長を超える系列への一般化

約400Mモデルを4Kトークン系列で学習し、512、16K、65Kへ評価長を変える。構造化S4を使うBST:SH:S4-Lは、PG19・GitHub・arXivの65K条件で比較方式より良好なPPLを示す。SSMの核が`A,B,C`から系列長に合わせて再生成できることが、未知の長い系列への拡張を支える。

対して明示フィルタのBST:MF:unstruct-Lは、学習した4K付近では高品質でも、16K・65Kへ伸ばすとPPLが悪化する。GSS-Hybrid-LもarXivでは長い系列でPPLが急増する条件がある。BRecTはarXivの長い系列で良好な結果を示すことがあり、過去ブロックの表現を保持する再帰的な仕組みが数学論文中の定義・記号の参照に役立つ可能性が論文で議論される。構造化SSMの長さ一般化もデータ分布によって競合との差が変わる。

### 層単体のGPU実行時間

GPU上で窓128、SSM内部状態16、注意16頭、SSM入力幅512とした層単体の順方向計算を比較すると、BST:SHはBRecTに対して約6〜11倍、BST:MHは約3〜4倍高速である。4K系列長ではBRecT層が再帰処理なしのSlide:12L層より約15倍遅いのに対し、BSTはその差を2倍未満へ縮める。これはブロックを逐次処理する再帰を、SSMの畳み込みと並列ブロック注意に置き換えた効果を示す。

65Kトークンまでの長さ試験でも、構成によって約6倍の利得が残るが、その付近からハードウェア飽和が始まると著者らは述べる。FFT実装はJAXの標準処理を使っており、専用の入出力最適化カーネルによる追加改善余地はある一方、論文中の測定はあくまで**層単体の前向き計算**である。学習全体の時間や、自己回帰生成での1トークン当たり遅延を同じ倍率で短縮した結果ではない。

## 既存研究との差

Transformer-XLやSlide:12Lは局所的な注意と過去のキャッシュを利用するが、長距離文脈の保持能力と窓長の制約が残る。BRecTは再帰的状態を加えて長距離依存を補うものの、ブロックの逐次実行が必要になる。BSTはSSMが全系列の文脈を並列に生成し、ブロック内注意がその文脈を交差注意で取り出すため、再帰更新を待つ必要がない。

GSS-Hybrid-LはSSM層とTransformer層を交互に積み重ねるが、BSTは同じ層の注意計算へSSMの文脈状態を直接渡す。長距離要約と局所注意を別々の層に分離せず、各ブロックの予測に両者を同時利用する点が異なる。またBSTは単一頭・多頭・複数フィルタの状態抽出方法を比較し、単にSSMを追加するだけでなく、文脈の取り出しやすさと冗長性の設計を検証している。

## 限界と適用範囲

本論文の主な実験は約200M〜400Mパラメータのモデルであり、現代の数十B〜数百Bモデルや混合専門家モデルの実運用性能を直接示さない。評価は長文言語モデルのPPLと層単体速度が中心で、対話生成の品質、GPUメモリ使用量、長時間の連続バッチ推論、分散通信などは主要評価に含まれない。

構造化S4は未知の長い系列へ一般化しやすいが、畳み込み核の生成とFFTに計算費用がある。明示フィルタは複数フィルタで高速・高品質な条件があるものの、学習長を超える系列で性能が落ちる。多頭方式は追加パラメータが必要でもSHより明確なPPL改善を示さない。どの文脈状態が最良かは文書の性質によって変わる。

並列化による高速化はハードウェアの同時実行能力に依存する。長い系列ではFFTが律速となり、65K付近ではハードウェア飽和が観察される。理論上の複雑度や層単体速度から、任意のデバイスで同じ倍率を得られるとは言えない。また、SSMの内部状態を継続的に更新する自己回帰デコード実装と、論文が主に評価した系列一括順方向計算は区別する必要がある。

最後に、モデル構造そのものを変更する方式であり、既存の凍結済みTransformerのKVキャッシュだけを交換する推論時プラグインではない。導入には対応する混合層を持つモデルの学習または再構成が必要である。長文モデル設計の先行研究として重要だが、既存LLMサービングへ無改変で適用できる高速化手法と誤解してはならない。
