# SparseVLM: Visual Token Sparsification for Efficient Vision-Language Model Inference

## 概要

SparseVLMは、視覚言語モデル（VLM）の入力画像から生じる大量の視覚トークンを、現在の質問に必要な情報をできるだけ残しながら削減する追加学習不要の方式である。視覚トークンの重要度を画像だけから決めず、質問のどの語が画像に関係するかを選んだうえで、言語トークンから画像トークンへ向けられた注意重みを利用する。さらに注意行列のランクから層ごとの冗長度を推定して枝刈り量を変え、削除予定トークンの一部をまとめて残す再利用機構を備える。

LLaVA-7Bの標準576視覚トークンを192に減らす条件では、平均精度は元の99.1%相当を維持し、行列演算量は4.62兆から2.14兆演算、CUDA処理時間は57.82msから36.50msになった。128トークンでは平均精度96.7%相当、CUDA処理時間33.28msとなり、元モデル比で約42.4%短縮した。原著の要約が述べる37%の遅延削減と97%精度保持は、特定の圧縮条件の代表値であり、すべての削減率で成立するわけではない。

重要な点は、視覚トークン数の削減、計算量の削減、実測遅延の削減、正答率の維持を別の量として測ることである。視覚トークンを約8割削っても、注意行列の取得、重要度推定、クラスタ化と再構成には費用がかかるため、CUDA遅延が同じ割合だけ減るとは限らない。

## 問題設定

画像や動画をLLMへ渡す際、視覚符号化器は画素をパッチなどの特徴列へ変換する。標準的なLLaVAでは336×336画像から576トークン、高解像度の672×672画像では2304以上のトークンを生成する場合がある。質問文が数十トークンしかなくても、画像側は何百から何千トークンにもなり、後段の自己注意と順伝播層がその全列を処理する。高解像度画像や動画フレームでは、視覚列が計算とKV保存の大きな割合を占める。

ところが質問に答えるために必要な画像領域は、常に画像全体とは限らない。例えば薬のラベルについて質問している場合、背景の壁や机よりラベル文字が重要になる。単に視覚トークンを等間隔で間引く方式や、画像の見た目だけで重要度を決める方式は、質問ごとに変わる重要領域を考慮しない。逆に追加の重要度予測器を学習する方式は、モデルやデータ集合を変えるたびに追加学習・管理が必要になる。

SparseVLMは既存モデルの注意重みを利用し、質問に関連する画像領域を推定する。モデル重みの追加更新を不要にする一方、注意重みが必ず因果的な重要度を表すという保証はない。そのため、質問との関連度だけでなく、層ごとの冗長度、削除予定トークンの情報再利用を組み合わせて、単純な重要度上位選択より安定した品質を目指す。

## 手法

### 1. テキストから視覚への注意部分行列を取り出す

視覚トークン数をL_v、テキストトークン数をL_tとし、LLMの自己注意行列Aのうち、テキストのクエリ行と視覚のキー列が交差する部分Pを取り出す。Pの各要素は、あるテキスト位置がある視覚位置をどれだけ参照したかを表す。選択したテキスト位置についてPの列方向の値を平均し、各視覚トークンの重要度ベクトルを作る。高い値を持つ視覚トークンを残すことが基本の枝刈り方針である。

ただし、すべての質問語を同じ重みで平均すると、画像と無関係な助詞・一般的な説明語が評価へ混ざる。例えば「棚に貼られたラベルに何が書いてあるか」という質問では、「ラベル」「書いてある」に関連する視覚情報と、質問を構成する一般語の重要性は異なる。そこでSparseVLMは、画像特徴と質問語埋め込みの相関を先に調べ、視覚との結び付きが強い質問語だけを評価者として選ぶ。

### 2. 画像関連語の選択を事前に計算する

画像符号化器の特徴Z_vを射影して視覚埋め込みH_vを作り、質問文の埋め込みH_qとの類似度行列を計算する。視覚位置ごとに正規化した類似度を集約し、各質問語の関連度r_iを得る。平均関連度m以上の語を選択集合sに入れ、これらだけを視覚トークン評価の基準にする。論文の式(5)(6)に対応する処理である。

この選択は各層で新しい分類器を実行するのではなく、デコーダに入る前に一度行う。計算量はおよそ2DL_tL_vの積和に比例し、追加学習パラメータは必要ない。選択集合に質問の核心語が含まれなければ枝刈りが誤る可能性があるため、単純なテキスト全語平均との比較でこの処理の効果を検証している。

### 3. 注意行列のランクで層ごとの削減数を決める

各層で視覚重要度Pを得た後、その行列のランクを冗長度の指標として使う。論文は削減数Nを、N = λ[L_v - rank(P)] と定義する。λは削減強度の係数で、Pが低ランクで冗長な場合は多く削り、独立した情報が多い場合は保守的に残す。Nが0となる層では枝刈りを行わない。

重要度の低いN個の視覚トークンを削除候補にするが、層ごとに同じ数を削るわけではない。情報がすでに言語表現へ取り込まれた後段の層と、視覚情報が必要な前段の層では、冗長度が異なる。注意ランクを測るための費用はL_t×L_v×min(L_t,L_v)に比例し、トークン削減で節約する本体計算と比較する必要がある。ランクを正確に計算する負担が大きい場合には、制御処理の実装が速度上の律速になり得る。

### 4. 削除予定トークンをクラスタ化して再利用する

重要度の低い視覚トークンをすべて捨てると、質問への回答に必要な細部が偶然削除される場合がある。SparseVLMは削除候補のうち重要度上位τ%を再利用対象として取り出し、特徴空間の近傍関係に基づいてクラスタ化する。局所密度と高密度点までの距離を用いてクラスタ中心を選び、他のトークンを類似度の高い中心へ割り当てる。各クラスタの特徴を要素ごとに加算して、より少数の再構成トークンへ圧縮する。

再利用対象がL_r個、クラスタ中心がC個なら、C個の圧縮表現として残す。これにより元のL_r個をそのまま保持するより後段の系列長を短くできる。単純削除に比べて情報損失を抑える一方、近傍探索・密度計算・クラスタ割当て・再構成の費用が増える。特に元からトークンが少ない場合には、この制御費用が節約分を上回る可能性がある。

### 5. 層を進むにつれて系列長を減らす

視覚トークンの枝刈りはデコーダの途中層で順次行う。残ったトークンと再構成トークンは次層の入力となるため、以降の注意と順伝播層で計算対象が減る。削減の利得は注意の二乗項だけでなく、各トークンにかかる行列積の線形項にも現れる。論文は削除N個、再構成C個、隠れ幅Dに対する理論削減量を概ね6(N-C)D² + 2(N-C)²Dと表し、そこから関連語選択・ランク推定・再構成の費用を差し引く。

この計算モデルは、枝刈り後に処理するトークン数が減るほど本体の演算量が下がることを説明する。ただしCUDAの実時間は、カーネル起動回数、メモリアクセス、GPUの並列度、制御処理の実装にも依存する。演算量の削減率をそのまま応答時間の短縮率として扱わない。

### 6. 高速注意カーネルとの互換性

FlashAttention系の実装では通常、注意行列全体をGPUメモリへ書き出さない。SparseVLMはテキストから視覚への重要度を得る必要があるため、必要な注意成分を取得するための経路を実装している。これは注意行列の取得を完全に無料にするものではないが、学習済み予測器を新設するより追加パラメータが少ない。論文付録では高速注意との互換性と制御費用を別途扱っている。

| 項目 | 条件 | 解釈 |

LLaVAの各結果は、元モデルの精度を100とした正規化平均精度である。異なるベンチマークでは評価尺度が違うため、単純な生点の平均ではない。例えばMMEは千点単位の得点、POPEは百分率、MM-Vetは別の評価値を持つ。表にある99.1%などは「元の正答率が99.1%」という意味ではなく、複数課題での相対的な精度保持率である。

## 評価結果

### LLaVAの視覚数・演算量・実時間

| 方式と残存視覚数 | 正規化平均精度 | 演算量 | CUDA時間 | 読み方 |
|---|---:|---:|---:|---|
| 元LLaVA、576 | 100.0% | 4.62 T | 57.82 ms | 元モデルの基準。 |
| ToMe、192 | 88.9% | 2.05 T | 34.06 ms | 圧縮は速いが精度損失が大きい。 |
| FastV、192 | 87.9% | 2.11 T | 34.87 ms | 固定的な削減の品質低下。 |
| PDrop、192 | 95.9% | 2.03 T | 36.74 ms | 演算量は少ないがSparseVLMより精度が低い。 |
| SparseVLM、192 | **99.1%** | 2.14 T | 36.50 ms | 0.9ポイント相当の低下で66.7%の視覚数削減。 |
| SparseVLM、128 | **96.7%** | 1.72 T | 33.28 ms | 77.8%の視覚数削減。 |
| SparseVLM、64 | **89.3%** | 1.30 T | 29.89 ms | 88.9%の視覚数削減、品質低下は拡大。 |

192トークンの条件では演算量は4.62Tから2.14Tへ約53.7%減り、CUDA時間は57.82msから36.50msへ約36.9%減った。元モデル精度に対する保持率は99.1%で、ToMeの88.9%やFastVの87.9%を大きく上回る。128トークンでは演算量1.72T、CUDA時間33.28ms、精度96.7%となり、本文の「97%保持」という代表値に近い。64トークンではさらに速くなる一方、精度保持は89.3%まで低下する。したがって最も強い圧縮が最適とは限らない。

同じ192トークン条件でPDropの演算量は2.03TとSparseVLMより少ないが、平均精度は95.9%と低い。SparseVLMのCUDA時間は36.50msでPDropの36.74msに近く、演算量だけで実時間の優劣を決められないことも分かる。制御費用が小さいとはいえゼロではなく、GPUカーネルの実装や系列長によっては理論演算量と実測時間の順位が変わる。

### 高解像度モデルと動画モデル

| モデル・条件 | 結果 | 比較上の注意 |
|---|---|---|
| Qwen2-VLの動的視覚数（約1320） | MMBench 80.5、POPE 86.4、TextVQA 84.3、平均83.7 | 元モデルの基準。 |
| Qwen2-VL、600トークン | 79.6 / 86.5 / 80.3、平均82.1 | 元平均の約98.1%を維持。 |
| Qwen2-VL、400トークン | 79.0 / 85.8 / 77.1、平均80.7 | 強い削減でTextVQAが下がる。 |

| Video-LLaVA、194トークン＋FastV | 平均正答40.5、生成評価3.27 | 元正答の約84.6%相当。 |
| Video-LLaVA、194トークン＋SparseVLM | 平均正答47.0、生成評価3.40 | 元正答の約98.1%相当。 |

動画の表では正答率の「相対保持率」を課題ごとに平均すると95.0%となり、単純な生平均47.0/47.9と一致しない。論文が報告するFastVとの差14.7ポイントも、課題ごとの相対精度保持率を集計した尺度である。動画4課題は各1000例を使い、別の生成回答評価も行っている。視覚2048から194へ削る非常に強い圧縮でも、SparseVLMはFastVより精度を維持した。ただしすべての動画質問で同等精度という意味ではなく、TGIF-QAの正答は18.9から14.9へ下がっている。

### 構成要素除去と記憶容量

質問関連語を選ぶ機構の比較では、同じ64視覚トークン条件で全語を評価者とする場合に比べ、TextVQAで0.8ポイントの改善があり、選択せずテキスト語だけを使う場合に比べてPOPEで2.7ポイント改善した。画像に関連しない語を評価から外すことが、枝刈りの判断へ寄与している。

削除トークン再利用の構成要素除去では、64/96/128/192トークン条件のGQA平均が56.2から57.0へ、POPE平均が79.8から82.4へ上がった。特に64トークンのPOPEは再利用なし72.8から再利用あり77.5へ改善した。論文本文の別箇所には相対改善率の表現もあるため、表の絶対得点差と百分率の改善を混同しない。

KVキャッシュに関しては、元LLaVAの302.4MBが100.8MBとなり約67%削減しつつ、代表設定で精度99.1%を維持したと報告する。これは測定条件におけるキャッシュ量であり、モデル重み、視覚符号化器、全GPUメモリを合わせた総容量が67%減ったという意味ではない。

## 既存方式との差

ToMeは視覚表現を類似度に基づいて統合するが、質問文が求める領域の重要性を直接考慮しない。FastVも視覚トークン削減を行うが、SparseVLMは質問に関連するテキスト語を評価者として選び、視覚トークンへの注意を基準にする。PDropなどの方式と比較しても、同程度のCUDA時間で精度を高く保つ条件がある。

SparseVLMの新規性は、質問語の選択、注意ランクによる層別の削減量調整、削除予定トークンのクラスタ再構成を一体化した点にある。単純な「上位注意トークンを残す」方式ではなく、どの語が画像を評価するか、どの層でどれだけ削るか、捨てる情報の一部をどう戻すかを連続した手順で扱う。さらに既存VLMの重みを更新しないため、モデルごとの追加微調整費用が不要になる。

## 限界と実装上の注意

注意重みは質問への因果的重要性を厳密に保証しない。質問が画像全体を必要とする場合や、注意が拡散している場合、重要領域の推定を誤って必要な視覚情報を削除する危険がある。再利用は損失を緩和するが、削除された細部を完全復元するものではない。64トークンまで削ったLLaVAでは精度保持率が89.3%へ下がり、強圧縮には明確な品質費用がある。

ランク計算、注意行列の取得、質問語選択、クラスタ化、再構成は追加計算を伴う。特にFlashAttentionのように注意行列全体を通常は出力しないカーネルでは、重要度取得のための実装上の工夫が必要であり、制御費用が環境によって増える。CUDA時間は単一A100上の同一入力条件の値であり、サービス全体の初回トークン遅延、連続要求の処理量、CPU・通信費用まで含めた評価ではない。

評価対象は主として画像・動画を扱うVLMである。純テキストLLMの復号高速化、MoEの専門家間通信、長文脈KVオフロードへ直接適用できると示したものではない。モデルの視覚トークン数、質問の種類、層構成によって効果が変わるため、別モデルへ移す場合は品質と実時間を再測定する必要がある。
