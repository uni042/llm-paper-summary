# 上位k注意による既存Transformerの省メモリ化

## 概要

通常の自己注意では、系列内の各問い合わせと全鍵の類似度を計算して重み付けするため、系列長が増えると注意行列の中間状態が二乗に増える。既存の効率的注意には、ハッシュや局所窓で計算する組合せを制限する方式と、注意関数自体を近似する線形注意がある。しかし、通常のソフトマックス注意で事前学習済みのモデルへ異なる関数を差し込むと、精度回復のために追加の事前学習が必要になる場合がある。巨大なモデルほど、その再学習費用は無視できない。

本論文の上位k注意（Top-k Attention）は、全鍵との内積を計算する点を保ちながら、問い合わせごとに最も大きなk個のスコアだけを残す。問い合わせを固定サイズの塊に分けて処理するため、一度に保持する類似度行列は小さくなる。さらに訓練時には上位kのスコアと位置だけを保存し、逆伝播で必要な活性化値を再構成する。この設計は、メモリ使用量の削減と既存の学習済み重みとの互換性を優先し、時間計算量を必ずしも線形化しない。

著者らは自己注意に加え、Transformerのフィードフォワード層を問い合わせ・鍵・値形式に書き換え、ソフトマックスではなく正規化線形関数（ReLU）を用いる場合にも上位k選択を適用する。原著のA100実測では、65,536トークンのBERT-base形状の単層注意を10GiB未満で処理し、通常注意は10,000トークン超で30GiBの測定上限に収まらない。事前学習済みUnifiedQA-11Bのフィードフォワード中間次元65,536では、上位256〜512成分だけでも多くの質問応答課題で通常層に近い正答率を維持した。

## 問題設定：メモリを減らすことと演算を減らすことは異なる

問い合わせ数を `L_Q`、鍵数を `L_K` とすると、通常の注意は `QK^T` の `L_Q×L_K` 個のスコアを扱う。長文脈の自己注意では両者が系列長に比例するため、中間行列の記憶量は二乗で増える。前向き推論だけなら問い合わせを小分けにすれば一時領域を抑えられるが、訓練では自動微分が中間活性を保持するため、単純な小分け処理だけでは層全体のメモリが減らない。

著者らが解きたいのは、学習済みの重みを変えずに通常注意に近い関数を使い続けながら、必要な中間状態だけを保存することである。局所注意のように位置の近さだけで選ぶと、遠くの重要な鍵を落とす場合がある。上位k注意では入力に応じて全鍵のスコアを計算し、上位を厳密に選ぶため、長距離でも大きな類似度を持つ位置は保持される。ただし選択に必要な内積計算は残るので、純粋な線形時間アルゴリズムではない。

フィードフォワード層も重要である。入力系列が比較的短い場合、注意行列より巨大な中間次元の活性がメモリを支配することがある。著者らはこの層も上位k選択の対象にすることで、注意層だけを軽量化しても残るボトルネックへ対処する。

## 手法：問い合わせ分割から逆伝播まで

### 1. 全鍵のスコアから上位kを厳密に選ぶ

入力は問い合わせ `Q`、鍵 `K`、値 `V`、保持数 `k` である。各問い合わせ `q_i` と全鍵 `k_j` の内積を計算し、その行の上位k個だけを残して他の位置を無効化する。注意層では選択されたスコアへソフトマックスを適用して値を集約する。上位位置の選択はハッシュや近似探索ではなく、実際の内積に基づく厳密な選択である。

このため、スコアの大きい遠方の鍵も残る。注意分布が少数の位置へ集中する場合は小さなkでも品質を維持しやすいが、分布が広い場合は小さなkで多くの寄与を落とす。kの選択は精度と保存メモリの交換条件になる。

### 2. 問い合わせを塊に分割して前向き計算する

全ての問い合わせを同時に処理せず、サイズ `C` の塊 `Q_C` ごとに `Q_C K^T` を作る。各塊の一時スコア行列は `C×L_K` であり、処理が終われば次の塊へ移れる。入力・出力自体を除く作業メモリは、固定Cの下で `L_K` に線形となる。原著第2.2節では、系列長65,536の単層注意で、C=512または1024付近が速度とメモリの良い均衡になると示している。

ただし塊を小さくし過ぎると、GPUに十分な並列仕事を与えにくくなり、塊の逐次処理が増える。大きくし過ぎると一時スコア行列のメモリが増える。従ってCは、対象GPUのメモリ容量と系列長を踏まえて選ぶ必要がある。

### 3. 上位スコアと位置を保持して逆伝播を軽量化する

通常の勾配計算では、前向き計算で作った注意活性を後で使うため保持する。単純な入力再計算方式では、逆伝播時に再び全スコア `Q_C K^T` を求める必要があり、計算費用が増える。原著は、入力 `Q,K,V` に加えて、各塊の上位kスコアとその位置を保存する。保存量は `L_Q×k` 規模で、全スコアの `L_Q×L_K` より小さい。

逆伝播では、出力勾配から選択された位置の活性勾配を求め、保存した上位スコアへ活性化関数を再適用する。得られた疎な勾配を使い、問い合わせ・鍵・値の勾配を計算する。重要なのは、全ての問い合わせと鍵の内積をもう一度求めるのではなく、保存済み上位スコアから必要な活性だけを再構成する点である。原著の疑似コードでは、前向きで全スコア行列を消去し、逆伝播で上位活性とその疎な配置を一時的に作ってから解放する。

単純な再計算は、前向きと逆伝播を合わせた演算量を最大約50%増やし得る。上位k注意は大きな内積を再計算しないことで、この追加費用を抑える。ただし疎な勾配を密行列と掛ける演算は残るため、逆伝播が無償になるわけではない。

### 4. フィードフォワード層を注意の形式へ書き換える

通常のフィードフォワード層は、入力 `x` に重み行列を掛けて中間次元へ展開し、活性化して元の次元へ戻す。著者らは中間層の各重み行を固定鍵、出力側の対応する重み列を値と見なし、`ReLU(QK^T)V` と表現する。自己注意と異なり、鍵と値は入力ごとに変わるトークン表現ではなく学習済みの重みである。

ここでReLU後の中間活性の上位kだけを残すと、全中間次元の活性を保存せずに出力を近似できる。鍵は位置に沿って並んだ系列ではないため、局所窓を使う方式の「近い位置が関連する」という仮定は当てはまらない。またソフトマックスを無作為特徴写像で近似する線形注意を、そのままReLUへ適用することも難しい。上位kの厳密選択は活性化関数に依存せず利用できる点で適用範囲が広い。

既存のT5やUnifiedQAの重みは変更しないため、再事前学習せずに差し替えられる。ただしkを極端に小さくすれば必要な中間成分も失われ、特定課題で正答率が落ちることは実験で確認されている。

### 1. 単層注意と大規模フィードフォワード層の資源効果

単層注意では、通常注意が系列長10K超で30GiBに収まらない一方、上位k注意は65K系列でも10GiB未満に収まる。原著の図1では、上位k注意のメモリ使用量は長系列でPerformerと同程度になり、系列長4K以下では実行時間がPerformerより短い条件もある。65K系列では、通常注意を問い合わせ分割するだけの方式に比べ、上位kの追加によってメモリを約3分の1に削減する。

フィードフォワード層では、バッチ512、入力512、合計262,144問い合わせの条件で、中間次元65Kを上位k注意なら約11GiBで処理できる。通常方式は中間次元2Kでほぼ同じ11GiBを消費する。著者らはメモリ使用量を線形外挿し、30GiBの装置では上位k注意なら中間次元205K、通常方式なら7K程度を扱えると推定する。この205Kと7Kは実際にその規模のモデルを完走させた測定値ではなく、回帰線による推定である。

12層デコーダでは、上位k注意によって32Kトークンの入力を30GiB級GPUで扱えると示す。ただし入力が非常に長い場合の実行時間は二乗計算の影響を受け、著者ら自身も長系列データ全体を一から学習する用途には課題が残ると述べる。

### 3. UnifiedQA-11Bの学習なし置換と負の結果

UnifiedQAはT5を基盤とした11Bパラメータの質問応答モデルで、フィードフォワード中間次元は65,536である。原著の表2では、12種類の質問応答課題について追加学習なしで中間活性を上位kに置換する。下表は全12列から代表課題を抜き出したものであり、全課題平均ではない。

| k（65,536次元中） | AI2小学校科学 | BoolQ | CommonsenseQA | OpenBookQA | SQuAD v1 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 64 | 82.9 | 88.7 | 72.4 | 77.4 | 86.1 |
| 256 | 91.1 | 90.0 | 75.9 | 85.4 | 86.8 |
| 512 | 91.1 | 90.4 | 77.0 | 83.6 | 86.9 |
| 4096 | 91.9 | 90.8 | 77.6 | 85.2 | 87.0 |
| 通常FFN（65,536） | 91.9 | 90.7 | 77.5 | 85.2 | 87.0 |

### 4. BERT-largeの自己注意とT5-base微調整

微調整済みBERT-largeのSQuAD v1開発集合では、通常自己注意の完全一致率86.9に対して、上位16位置を残す場合は86.2となった。k=16は入力長の約4%であり、学習済み重みを変更せず小さな低下で差し替えられる。一方、同じ評価でPerformerを256特徴量で差し替えた結果は0.38であり、著者らは追加事前学習なしでの互換性の違いを示す。ただし、この比較は論文中の指定された実装・設定での結果であり、あらゆる線形注意が必ず失敗する証明ではない。

T5-baseの5課題微調整では、フィードフォワード中間次元3072に対してtop-256を使う。BoolQは通常微調整83.3に対し83.1、CommonsenseQAは61.9に対し62.0、ROPESは54.0に対し53.8と近い。一方、MCTestは81.2から79.4、OpenBookQAは58.8から58.0へ低下する。追加の再事前学習なしでも微調整できるが、課題ごとに小さな損失が残ることを確認する必要がある。

## 既存方式との差

Performerなどの線形注意は、注意行列を特徴写像で近似して計算量も削減することを目指す。上位k注意は、全鍵との内積を計算した後に大きなスコアだけを残すため、時間計算量では二乗のままである。代わりに通常注意と近い数値演算を使い、学習済み重みを変更せず置換できることを重視する。性能比較ではメモリ削減と計算時間を別々に見る必要がある。

Reformerの可逆残差接続と問い合わせ分割を使う方式も、逆伝播時に活性を再計算してメモリを減らす。しかし可逆構造はモデルの関数自体を変えるため、既存BERTやT5へ直接適用するには追加の調整が必要になる。上位k注意は元の重みを保持し、選択スコアと位置の保存により、全内積の再計算を避けるという異なる設計を採る。

フィードフォワード層の中間ニューロンを固定鍵と値とみなす点も重要である。系列上の近傍関係を利用する局所注意と違い、中間ニューロンの並びには位置的意味がない。上位kの値そのものを選ぶため、ReLU活性を使う中間層でも入力依存の疎化ができる。

## 限界と実装上の注意

最大の制約は、全ての問い合わせと鍵の内積を計算するため、系列長に対する時間計算量が二乗のままであることだ。原著第5節は、長系列を最初から大規模学習する場合には実行時間が障害になると明記する。32K入力をメモリに収められることは、同じ系列を高速に学習できることを意味しない。

また原著の実装では、疎行列と密行列の積で疎性を十分に活用していない。著者らはPyTorchの疎座標形式を使う試みも行ったが、kが鍵数の1%であっても性能結果は芳しくなかったと報告する。したがって、上位kの保持によるメモリ削減が、そのまま演算時間短縮につながるわけではない。専用のブロック疎カーネルなどを使う改善は今後の課題として挙げられている。

品質面では、ListOps、UnifiedQAの一部課題、T5微調整のMCTestなどで精度が低下する。重要な情報が多数の鍵へ分散する場合は、上位kだけを残す近似で損失が生じ得る。kと問い合わせ塊Cの選択は、精度、メモリ、並列効率の三者の交換条件になる。

最後に、評価は2021年時点のBERT/T5/UnifiedQAとA100上の前向き・逆伝播が中心である。現代の生成LLMの連続バッチ処理、KVキャッシュの長期保持、トークン間遅延、複数GPUでの実機提供性能を直接測定してはいない。推論システムへ導入する場合は、現行の注意専用カーネルやメモリ管理方式との追加比較が必要である。
