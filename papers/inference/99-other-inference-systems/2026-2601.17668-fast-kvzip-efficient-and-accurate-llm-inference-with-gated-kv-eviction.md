# Fast KVzip: Efficient and Accurate LLM Inference with Gated KV Eviction

## 概要

長文脈の言語モデルは、生成のたびに過去の鍵・値（KV）を参照するため、文脈が長くなるとキャッシュがGPUメモリを圧迫する。重要でないKVを削除する方法は容量を減らせるが、何を消すかを決めるために過去の注意を再計算すると、圧縮器自体の費用が大きくなる。先行研究KVzipは文脈再構成に基づいて将来使われるKVの重要度を推定するが、圧縮のためにプリフィル計算がほぼ二重になる問題があった。

Fast KVzipは高費用な再構成を推論時に行わず、あらかじめ小型のゲートへ重要度推定を蒸留する。モデル本体の重みを凍結し、各注意層に入力隠れ状態からKVの保持価値を推定する分岐を追加する。ゲートはシンク注意（sink attention）を模した低次元の計算であり、プリフィルと生成中の両方でキャッシュ削除に使える。Qwen2.5-1M、Qwen3、Gemma3の評価では、KVを元の30～40%へ縮めても多くの長文理解・コード・数学推論で元性能に近い品質を維持した。圧縮率と実際の時間短縮は別の指標である。

## 問題設定

KV削除には二つの難しさがある。一つは、今の問い合わせから目立つ位置が、将来の別の質問や後続の推論にも重要とは限らないこと。もう一つは、重要度推定の計算量が大きいと、注意演算を削った利益が圧縮処理へ奪われることである。文脈を一度読み込むだけのタスクと、長く考え続ける数学推論では、新しいKVが増える頻度と参照の分布も異なる。

H2OやSnapKVのような既存方式は注意統計や局所的な問い合わせを用いる。KVzipは文脈を再構成するときに各KVが受ける注意から、問い合わせに依存しない重要度を求めるが、再構成を推論時に繰り返すと遅い。Fast KVzipは「将来の利用価値は、生成時の隠れ状態から安価に予測できる」という仮説を採り、高品質な教師スコアの計算を事前学習段階へ移す。

## 手法

### 1. 各層に独立したKV保持ゲートを置く

注意層 $l$ の入力隠れ状態を受け取り、その層のKV頭ごとに0～1の保持スコアを返す関数 $g_l$ を追加する。ゲート分岐は本来の注意出力へ加算されず、KVをキャッシュに残すかどうかだけを制御する。したがって、削除されなかったKVを使う注意の計算式自体は元モデルと同じであり、基盤モデルの重み更新も必要ない。ただし削除によって参照できる過去情報は変わるため、最終的な生成品質が厳密に無損失であるわけではない。

スコアは層ごと・頭ごとに求められ、全層で同じ割合を削除する必要はない。各頭の重要度分布に応じてキャッシュ予算を配分することで、長距離情報を多く持つ頭へ容量を残せる。実験の分析では早い層の一部の頭が非常に疎になり、中後段ではより多くのKVを残す傾向が報告されている。これは全層を一律に短い窓へ置き換える方式と異なる。

### 2. 低ランクのシンク注意ゲート

隠れ状態から低次元の問い合わせと鍵を投影し、通常の注意スコアに似た式で各KVの保持価値を計算する。ただし分母には層ごとに学習する固定のシンク鍵を加え、対象KVのスコアを相対化する。論文はシンク鍵16個、低次元特徴16という共通設定を用いる。シンク鍵は追加の過去KVキャッシュではなく、層に固定された学習パラメータであるため、過去長に比例した新しいゲート用キャッシュを持たない。

線形ゲートや二層の多層パーセプトロンも比較しているが、シンク注意型は特に検索課題で品質が良い。入力として隠れ状態を使う設計も、回転位置埋め込み後の鍵や位置埋め込み前の鍵を使う場合より良い結果を示した。位置情報はゲートの学習表現へ強く混ぜるより、別途最近のトークンを保持する窓として扱うほうが安定するという実験的判断である。

### 3. 文脈再構成からの教師スコアとゲート学習

KVzipの再構成処理を学習用データへ一度だけ実行し、各KVが再構成中に受けた最大注意スコアを教師とする。元モデルの全パラメータは凍結し、各層のゲートを二値交差エントロピー損失で独立に最適化する。言語モデルの重みへ逆伝播せず、前向き計算から教師を取得するので、全モデル微調整に比べてメモリ費用が小さい。ただしゲート自身の勾配更新は存在するため、完全な学習不要方式ではない。

学習データにはFineWeb-Eduから10K～30Kトークンの系列を抽出し、合計約100万トークンを使用する。下流の検索、長文質問応答、数学問題の正解ラベルをゲート学習へ使わない。論文では次トークン予測や特定の質問応答を教師とする方式も比較し、文脈再構成を教師にした場合のほうが未知の下流タスクへ一般化しやすいと報告する。タスク別の教師では特定の質問に関係する位置だけを残し、別の質問に必要な情報を失いやすいという説明である。

### 4. 分割プリフィルと生成時の一括ゲート評価

長い入力は16Kトークン単位でプリフィルし、各区間のKVを生成すると同時に保持スコアを求め、予算を超えた古いKVを削除する。これにより入力を最後まで読み終えてから巨大なキャッシュを一括圧縮する方式より、処理途中のピークKV容量を抑えられる。直近の4Kトークンは保持し、局所依存を守る。ここで保持するのは最近の位置に対する保護窓であり、全ての過去位置のゲート判定を無効化するものではない。

生成時に毎トークン個別にゲートを起動すると、関数起動とメモリ読出しの負担で遅延が30～60%増える場合があった。そこで新しい隠れ状態を128トークン分だけ蓄積し、まとめてゲートを評価してキャッシュを更新する。生成側でも直近128トークンは保護する。論文ではこの一括処理により、ゲート自体の負担がモデルの前向き計算時間の平均約1%に下がる。ゲート計算を安価にするには、低ランク化だけでなく呼出し回数の削減が必要だったことが分かる。

### 5. 保持予算と元モデルとの関係

保持率30%とは、元のKV位置数の約70%を削除することを意味する。ただし実際のメモリ削減率はKV頭数、層別配分、直近窓、ゲートのパラメータ、管理情報などに左右される。混合スライディング窓注意を持つGemma3では、長文脈で容量を支配する大域注意のKVを対象とし、全ての局所注意キャッシュを同じように削除するわけではない。量子化されたQwen3の重みを使う実験でも、ゲートは別途KV保持位置を選ぶため、重み量子化とKV削除は別の最適化軸となる。

## 評価

### モデル、負荷、比較方式

学習・評価はNVIDIA H100 80GBを1基使用し、PyTorchとFlashAttention-2を組み合わせた。モデルはQwen2.5-7B/14B-1M、Qwen3-8B/14B、Qwen3-8B-FP8、Gemma3-12Bなどである。プリフィル中心の長文脈理解にはSCBenchの複数質問・コード理解、MRCR、SQuADを使い、最大約170Kトークンまでを評価する。生成中心の数学推論ではAIME24とMATHを用い、最大生成長をそれぞれ32K、16Kとした。

| 観点 | 条件 |
|---|---|
| ゲート学習 | FineWeb-Eduから約100万トークン、10K～30K長の系列 |
| 学習・推論GPU | H100 80GB×1 |
| 比較 | KVzip、SnapKV、Expected Attention、DuoAttention、R-KV、TrimKVなど |
| 長文脈 | SCBench、MRCR、SQuAD、最大約170K |
| 数学推論 | AIME24、MATH、長い生成を伴う設定 |
| 実時間評価 | Qwen2.5-7B-1M、保持率30%、160K/240K/320K |
| キャッシュ更新 | 入力16K区切り、生成128トークン単位の一括ゲート |

### 学習費用と保存量

| 対象モデル | H100学習時間 | ゲート保存量 |
|---|---:|---:|
| Qwen3-8B | 0.59時間 | 0.18GB |
| Qwen3-30B-A3B | 0.70時間 | 0.11GB |
| Qwen3-14B | 0.83時間 | 0.30GB |

この時間は基盤モデルの全重みを再学習した費用ではなく、モデルごとのゲートを学習する費用である。ゲートの保存量もゼロではないが、対象モデルの全重みと比べれば小さい。学習データが約100万トークンで済むことは、ゲート学習の実用性を支える一方、まったく新しいモデル構造へ学習なしで適用できることを保証しない。

### 品質・速度の主な結果

12データセットの集約評価では、元KVの30～40%だけを保持しても、全KV保持の品質に近い結果を報告した。Qwen3の数学推論では4KのKV予算でも性能が大きく崩れにくく、思考トークン数を単に途中で打ち切る比較方式より良い結果が示される。これは「必要な推論過程を生成し続けること」と「過去の推論過程をすべてKVとして保持すること」が同じではないことを示す。ただし評価は有限の課題集合であり、全ての推論に厳密な同一出力を保証するものではない。

プリフィル効率では、元のKVzipが重要度を求めるため文脈再構成を追加実行するのに対し、Fast KVzipは同じ前向き処理内のゲートで選択する。論文はQwen2.5-7B-1M、保持率30%、160K・240K・320KのH100評価で、KVzipよりプリフィル時間とピークメモリが小さいことを示す。一方、元KVzipの生成速度はFast KVzipに近いと注記される。つまり主な時間利得は、生成カーネルを別物にすることではなく、プリフィル時の高費用な重要度再計算を消したことにある。

一部の長文脈タスクでは全KV保持より圧縮後のスコアが良い場合も報告されるが、著者は注意の雑音を減らす効果という仮説を挙げているにとどまる。特定の圧縮率が常に品質を上げると結論づけるべきではない。削除率70%は多くの評価でほぼ損失なしという範囲の主張であり、個々のデータセットの最悪値や全ての長文脈指示で無損失とは異なる。

## 限界・適用範囲

ゲートはモデルごとに学習し、下流タスクへ転用する構成である。別のモデル系列や大きく変更した注意構造へそのまま転用できるとは限らない。文脈再構成に基づく教師スコアの生成は推論時から除去されるが、事前学習時の計算としては残る。学習時に見ない特異な長文書、非常に稀な位置の厳密検索、長い数式証明などでの品質を完全に保証するものではない。

復号のゲートを128トークンごとに評価するため、保持判断には時間的な粒度があり、直近窓の確保と削除予算の配分が必要である。保持率を下げれば全体のキャッシュ容量は小さくなるが、ゲートの計算と保存費用、モデルの重み、注意以外の演算は残る。H100とFlashAttention-2の評価値をWindows上の異なるGPUや別の推論ランタイムの速度へそのまま転用することはできない。

## 既存研究との差

KVzipは文脈再構成による高品質な重要度を得るが、推論時の再構成費用が大きい。Fast KVzipはそのスコアを事前に学習した低ランクゲートで近似し、同じような保持判断を安価に行う。Locretは学習済みの保持頭を使うがプリフィル中心であり、Fast KVzipは生成中の更新も対象とする。DuoAttentionのように頭の注意パターンを固定する方式とは異なり、各KV位置の入力依存の保持価値を推定する。モデルの注意演算そのものを飛ばす方式ではなく、後続の注意が読むキャッシュを選択的に縮める設計である。
