# EvoPrune：視覚符号化器の内部から始める段階的な視覚トークン削減

## 概要

高解像度画像や多数フレームの動画を扱う大規模マルチモーダル言語モデルでは、視覚トークンの数が急増する。多くの既存削減方式は、視覚符号化器が全トークンを処理した**後**に削減を行うため、後段の言語モデルの事前入力処理は軽くできても、視覚符号化器がすでに使った演算量は取り戻せない。特に動画では視覚符号化器が全体遅延の大きな割合を占め、後段だけを削っても高速化の上限が低くなる。

EvoPruneは、視覚符号化器の複数の層にトークン統合処理を挿入し、初期段階から処理対象数を減らす。どのトークンを統合するかは、視覚特徴の類似度、近傍での多様性、注意重みによる重要度を組み合わせて決める。情報量が低い重複トークンをまとめ、重要な領域は保護する。追加の再学習を必要とせず、既存モデルへ組み込むことを目指す。

NVIDIA H20上のLLaVA-Video-7Bでは、64フレーム動画の視覚トークンを62.1%削減した条件で、平均評価値は元モデル57.9から57.7へわずかに低下し、相対全体遅延は0.55倍になった。さらに81.1%削減では平均評価値56.7（元モデル比98.0%）、全体遅延0.47倍だった。言語モデルだけでなく視覚符号化器の処理を早期から削ることが、動画での大きな実行時利得につながる。ただし結果は特定の視覚モデルとGPUでの実測であり、あらゆる動画・高解像度入力で同じ倍率を保証するものではない。

## 問題設定：後段の削減では視覚符号化の費用が残る

マルチモーダル言語モデルは、画像をパッチなどの視覚トークンへ変換し、視覚変換器（Vision Transformer）で特徴を抽出してから言語モデルへ渡す。入力が1枚なら視覚符号化の費用が相対的に小さくても、8枚、64枚と増えると符号化器の自己注意と中間層の処理が大きな負担になる。従来の視覚トークン削減は、すでに符号化が完了した特徴を間引くことが多い。そのため、言語モデル側の計算量を減らしても、符号化器の処理時間が下限として残る。

著者らは、入力画像数が増えるほど従来方式の高速化効果が薄れることを処理段階ごとの時間分解で示す。後段削減を使っても、元の実行時間に対する残存時間は単一画像で約64%、8画像で約72%、64画像で約74%となる。これは、画像数が多いほど符号化器の未削減費用が相対的に支配的になることを示す。したがって新しい方式の目的は、言語モデルへ渡すトークン数を減らすだけでなく、**視覚符号化器の残りの層で処理するトークン数を途中から減らす**ことである。

ただし符号化器の初期段階で統合すると、後段の視覚特徴が完成する前に細かな情報を失う。類似したパッチでも、数字の一部や物体の小さな差が質問の正解に関わる場合がある。したがって単純に特徴が似たトークンをまとめるだけでは不十分であり、異なる意味を持つ領域を残し、注意が集中する重要な領域を保護する仕組みが必要になる。

## 手法

### 1. 視覚符号化器内の段階的な削減予算

視覚符号化器を $L$ 層、初期トークン集合を $T_0$、全体で統合したいトークン数を $R$ とする。EvoPruneは各層へ統合予算 $r_l$ を割り当て、$\sum_{l=1}^{L}r_l=R$ とする。各層ではまず通常の多頭自己注意を計算し、予算が正ならスコアに基づくトークン統合を実施し、その後に前向き全結合層（MLP）へ渡す。削減が早いほど後続層の処理対象が少なくなる一方、早過ぎると情報損失の危険が高い。

主要実験では、視覚符号化器の**一層おき**に統合を行い、統合する層の間で全体予算を均等配分する。これにより、全層で一度に大量のトークンを削るのではなく、特徴抽出と削減を交互に進める。層ごとの配分は推論前に定めるため、実行時に最適な削減スケジュールを探索する方式ではない。処理の出力は、元より短い視覚トークン列であり、その後の符号化層、投影器、言語モデルがこの短い列を処理する。

### 2. 二部マッチングによる統合候補の選択

各層の視覚トークンを添字の偶奇で二つの集合 $a$ と $b$ に分け、集合間の候補対だけを評価する。各 $a$ 側トークンについて $b$ 側の最も高い統合スコアを持つ相手を選び、その候補対の中から上位 $r_l$ 組を統合する。統合後は残りのトークンを並べ直し、次の符号化処理へ送る。この二部マッチング構造により、全トークン対を無制限に統合するのではなく、決められた予算だけ統合できる。

統合候補は、特徴の近さだけでなく、情報の独自性と注意上の重要度を考慮する。すなわち、互いに似ていて他の情報と重複するパッチは統合候補になりやすく、独自の情報を持つパッチや後段推論に重要なパッチは統合を避ける。統合により視覚トークン数を減らすが、完全に無関係な領域をまとめると情報が失われるため、スコアの設計が品質を左右する。

### 3. 意味類似度と局所多様性

類似度項は二つの視覚埋め込みの余弦類似度を使う。方向が近い埋め込みは表す情報が似ている可能性があり、統合候補として優先する。ただし単純な類似度だけでは、複数の異なる重要領域が同じように見える場合の誤統合を防げない。

多様性項は、各トークンの近傍 $K$ 個との二乗ユークリッド距離から局所密度を推定し、周囲と異なる特徴を持つトークンを識別する。具体的には距離にガウス核を適用して近傍の類似性を測り、局所的な独自性を表す値 $d_i$ を計算する。統合スコアへ $\exp[-\lambda_d(d_i+d_j)]$ の重みを掛け、独自性の高いトークン同士が容易に統合されないようにする。これにより、類似度だけでは区別しにくい視覚領域の多様性を保とうとする。

### 4. 注意重要度による重要トークン保護

視覚符号化器の自己注意重みをトークン・ヘッド方向に平均し、各トークンの重要度 $s_i$ を求める。重要度が高いトークンの上位一定割合を**保護集合**へ入れ、統合候補から除外する。主要実験の保護割合（Critical Token Ratio; CTR）は0.25である。層のトークン数と統合予算に応じて保護数の上限を調整し、削減が進んだ後に保護数が過大にならないようにする。

保護集合のトークンを含む候補対は統合できないようにし、画像の主要な意味や後段の推論に重要な情報を残す。ここで使うのは**視覚符号化器内部の注意重み**であり、生成中の言語モデルの質問依存注意ではない。そのため、質問に必要な領域が生成途中で変わる場合まで完全に追従する仕組みではない。注意重みが低い細部を誤って統合する可能性は残る。

### 5. 統合スコアと実行順

候補対 $(i,j)$ の統合スコアは、余弦類似度 $Sim_{ij}$、多様性に基づく重み $w^{div}_{ij}$、注意保護重み $w^{attn}_{ij}$ を組み合わせる。論文では $Score_{ij}=Sim_{ij}\,w^{div}_{ij}\,w^{attn}_{ij}$ と表す。重要トークンを含む候補は選択対象から除外するよう扱う。実装時には無効な候補を除外してから上位選択することが必要であり、負の無限大を数値の積へ直接使う実装では未定義値に注意が必要である。

各統合層では、(1) 自己注意から特徴と重要度を取得、(2) 類似度・局所多様性・注意保護を計算、(3) 偶奇集合間の候補対を作る、(4) 保護対象を除いて上位予算分を統合、(5) 短縮した列を次の層へ送る。この処理を選択層で繰り返す。全視覚符号化が終わってから削る方式と異なり、後続の符号化層の自己注意とMLPの演算も減るため、動画で大きな速度利得を得られる。

## 評価条件

| 項目 | 条件 |
|---|---|
| 画像モデル | LLaVA-1.5-7B、初期視覚トークン576個 |
| 動画モデル | LLaVA-Video-7B、言語基盤はQwen2 |
| 動画入力 | 64フレームを一様抽出、各フレーム384×384画素、プーリング後64×169トークン |
| 実行装置 | NVIDIA H20 GPU |
| 画像評価 | VQAv2、MME、MMBench英語・中国語、MMVet |
| 動画評価 | MVBench、LongVideoBench、Video-MME |
| 比較方式 | FasterVLM、VisPruner、DART、DivPrune、CDPruner |
| 削減条件 | 画像は128・64・32トークン保持、動画は各フレーム64・32・16トークン保持 |
| 統合スケジュール | 一層おき、統合層間で均等予算、CTR=0.25 |
| 指標 | 各ベンチマーク得点、元モデル比の平均精度保持率、符号化前段・言語モデル・全体の相対遅延、先頭トークンまでの時間 |

動画モデルでは符号化器と言語モデルの間にプーリングがあり、従来の削減方式はプーリング後の短くなったトークン列へ作用する。一方EvoPruneはプーリング前の視覚符号化器内で大量のトークンを処理・統合する。この挿入位置の違いは、単純な「同じ位置で同じトークン数を削った」比較ではないことを意味する。論文の相対遅延は元モデルを1.00とした比であり、0.47倍は元モデルより53%短いという意味である。

## 評価結果

### 1. 画像理解：精度と遅延の交換関係

| LLaVA-1.5-7B | 元モデル | EvoPrune 128保持 | EvoPrune 64保持 | EvoPrune 32保持 |
|---|---:|---:|---:|---:|
| 平均評価値 | 76.5 | 74.9 | 72.9 | 68.7 |
| 元モデル比の平均精度 | 100% | 97.9% | 95.3% | 89.8% |
| 全体相対遅延 | 1.00 | 0.84 | 0.77 | 0.75 |
| 言語モデル相対遅延 | 1.00 | 0.77 | 0.73 | 0.71 |
| 言語モデル前の相対遅延 | 1.00 | 1.10 | 1.07 | 1.06 |

画像では、保持128トークン時に元モデル比97.9%の平均精度を維持しつつ、全体遅延を16%削減した。ただし**言語モデル前の処理は元モデルより10%遅い**。単一画像では統合スコア計算の追加費用が符号化処理の節約を上回るためと考えられる。動画での利得を画像一枚の遅延へそのまま一般化してはいけない。

比較方式のCDPrunerは128トークン保持時の平均評価値73.9、全体遅延0.91で、EvoPruneは74.9・0.84だった。64トークン保持時はCDPruner72.2・0.86、EvoPrune72.9・0.77だった。32トークン保持ではEvoPrune68.7・0.75に対し、CDPruner69.6・0.80であり、**最も強い削減ではCDPrunerの方が平均精度が高い**。EvoPruneが全条件で精度最高と解釈するのは不正確である。

### 2. 動画理解：符号化器から削る利点

| 64フレーム動画 | 元モデル | EvoPrune 64/フレーム | EvoPrune 32/フレーム | EvoPrune 16/フレーム |
|---|---:|---:|---:|---:|
| トークン削減率 | 0% | 62.1% | 81.1% | 90.5% |
| 平均評価値 | 57.9 | 57.7 | 56.7 | 55.4 |
| 元モデル比の平均精度 | 100% | 99.7% | 98.0% | 95.8% |
| 言語モデル前の相対遅延 | 1.00 | 0.54 | 0.50 | 0.46 |
| 言語モデル相対遅延 | 1.00 | 0.45 | 0.30 | 0.24 |
| 全体相対遅延 | 1.00 | 0.55 | 0.47 | 0.43 |

64トークン保持では平均精度57.7で、元モデル57.9から0.2ポイントの低下にとどまる。全体遅延0.55は約1.82倍の高速化に相当する。32トークン保持では平均精度56.7、全体遅延0.47で約2.13倍の高速化となる。16トークン保持では全体遅延0.43まで減るが、平均精度55.4へ下がる。削減を強めるほど速度が改善する一方、精度も低下するという通常の交換関係は残る。

従来方式は、64トークン保持時の全体相対遅延がおおむね0.77〜0.78であるのに対し、EvoPruneは0.55だった。これは言語モデルだけでなく符号化器と中間処理を早期に軽くできるためである。著者らの先頭トークン時間の分解では、視覚符号化器の速度が約1.8倍、中間処理が約5倍、言語モデルが約2倍になり、全体では約2倍の高速化と報告される。ただしこれらは同じパイプラインの**段階別速度比**であり、倍率を単純に掛けて全体速度を算出してはいけない。

### 3. 構成要素除去実験

| 動画の構成 | 平均評価値 | 元モデル比 |
|---|---:|---:|
| 削減なし | 57.9 | 100% |
| 類似度のみ（注意保護・多様性なし） | 55.9 | 96.5% |
| 多様性あり・注意保護なし | 56.7 | 97.9% |
| 注意保護あり・多様性なし | 57.3 | 98.9% |
| EvoPrune全機構 | 57.7 | 99.7% |

注意保護と多様性の両方を除くと平均評価値は55.9となり、全機構の57.7から1.8ポイント低下する。注意保護を外す方が、多様性を外すより悪化が大きい。すなわち、この評価条件では注意重要度の高いトークンを守ることが、局所多様性だけを考慮するより重要だった。両機構の効果は補完的であり、類似度だけの単純な統合では同じ精度を保てない。

## 既存研究との差

FastV、FasterVLM、DivPruneなどの視覚トークン削減は、視覚符号化後または言語モデル内でトークン数を減らすものが多い。これらは言語モデルの入力やKVキャッシュの負荷を減らせるが、視覚符号化器が全画像を処理する費用は残る。EvoPruneは、**視覚符号化器の内部で段階的に統合する**ことを主眼とするため、入力フレーム数が多いほど削減位置の利点が大きくなる。

類似度に基づくDARTやDivPruneとの違いは、統合候補の選定で局所多様性と注意重要度を併用し、重要トークンを明示的に保護する点にある。さらに一層おきの予算配分により、初期の特徴抽出を一部残しながら後段の処理数を減らす。モデル本体の重みを再学習しないことは適用の容易さにつながるが、視覚符号化器内部へ介入するため、単純な出力後処理だけで導入できるわけではない。

## 限界・負の結果・導入条件

第一に、画像一枚では言語モデル前の相対遅延が1.06〜1.10と増加した。統合スコアの計算とトークン整理には費用があり、入力が少ない時には符号化器の削減利得を上回る。したがって本研究の最も大きな利点は多数フレームの動画にあり、単一画像の推論では常に最速とは限らない。

第二に、早い層での統合は不可逆的であり、細かな数字や図形の区別に必要なトークンを失う可能性がある。注意保護と多様性でこの危険を減らすが、生成中に新たに必要になった視覚領域を復帰させる機構ではない。32トークン保持時の画像平均精度は68.7で、CDPrunerの69.6より低い。極端な削減では品質低下が残る。

第三に、動画の比較ではEvoPruneが視覚符号化器のプーリング前に介入するのに対し、従来方式はプーリング後の視覚列を削る。この違いは実用的な比較の一部だが、同じ位置・同じ内部トークン数を削った条件ではない。結果を「統合スコアの選び方だけで2倍速い」と解釈せず、早期の挿入位置と処理段階の削減が主な利得であると理解する必要がある。

第四に、主要評価はLLaVA-1.5-7B、LLaVA-Video-7BとNVIDIA H20で行われた。異なる視覚符号化器、量子化された言語モデル、Windows上のローカル推論、CPUオフロード、多数同時リクエストでの動作や速度は、この論文の実測からは保証できない。GPUメモリ節約量も主要表では直接的な定量指標として示されていないため、トークン削減率をそのままメモリ削減率へ置き換えてはならない。

第五に、CTR=0.25と一層おきの統合予算は主要実験で固定されている。視覚入力の難易度や質問内容に応じた最適な統合時点・保護割合は別途検討を要する。モデルの内部処理に組み込む必要があるため、外部APIの返り値だけを操作する文脈圧縮と異なり、モデル実装へアクセスできることが前提となる。
