# Speculative Pipeline Decoding — SPD

## 書誌情報

Yijiong Yu、Huazheng Wang、Shuai Yuan、Ruilong Ren、Ji Pei。Oregon State UniversityおよびDeepSolution。arXiv:2605.30852、2026年5月投稿、7月27日更新のv3（11ページ）を一次資料として確認。対象は、単一系列・低同時実行数のLLM自己回帰デコードにおける投機的生成とパイプライン並列である。

## 概要

通常の投機的復号では、小型ドラフトモデルが将来の複数トークンを先に作り、ターゲットLLMが一度に検証する。EAGLE-3などはターゲットの隠れ状態を利用して予測精度を上げるが、先へ進むほどドラフト自身の推定状態に依存して誤差が累積する。またドラフト生成を終えてからターゲットが検証するため、ドラフトの計算時間がクリティカルパスに現れる。

Speculative Pipeline Decoding（SPD）は、ターゲットLLMをn個のGPU段へ分割し、**同じ系列の異なるトークンを異なる段で同時に処理**する。次に入れるトークンは、別GPU上のPipeline Draft Module（PDM）が、ターゲット内部で既に得られた複数深度の隠れ状態を使って1トークンだけ予測する。PDMは各パイプライン段の計算と並行実行され、後から古い投機トークンをターゲット出力で検証する。ドラフトの誤りがあれば未確定トークンとKVをロールバックし、正しい分布に戻す。

Qwen3.5-4B/9BのH20分散環境で、8段・PDM3層のSPDは、温度0の総合実測高速化が4Bで2.53倍、9Bで2.67倍となり、EAGLE-3のそれぞれ1.97倍、2.54倍を上回る。一方16段では理論上の高速化が高くても、通信・同期・検証の固定費用が支配的になり、実測が4Bで1.43倍に低下する。**多数GPUを消費して単一系列の遅延を短縮する**設計であり、1GPU当たりの演算効率や総クラスタ費用の改善とは区別する。

## 問題設定

通常の自己回帰デコードでは、ターゲットのL層をトークン1個がすべて通過しないと次のトークンを確定できない。単一GPUのメモリ帯域律速ではモデル重みの読み出しを繰り返すため、低同時実行時の1トークン当たり遅延が高い。一般的なパイプライン並列は複数リクエストのマイクロバッチで段を埋めるが、SPDは**一つの系列**で段を埋めたい。この場合、未確定の将来トークンを前段へ投入する必要がある。

EAGLE-3のようなmulti-token predictionは、k個先へ進むほどドラフトの中間状態を入力として使うので受理率が下がる。PPSDは単一系列をパイプラインに載せるが、初段の浅い隠れ状態のみで予測するため受理率が低く、しかも各段計算の後でドラフトを実行するため待ち時間が残る。SPDの課題は、パイプラインを埋めるだけの受理率を維持しながら、ドラフトを段計算の背後へ完全に隠すことである。

## 手法

### 1. ターゲットをn段へ分割し、同一系列のnトークンを流す

ターゲットのL層をn段にほぼ均等分割する。飽和時には、最も古い未確定トークンが最終段、最新のトークンが最初の段に位置し、各サイクルで全トークンが1段進む。各サイクルの計算時間は理想的にはL層全体ではなくL/n層分になる。例えばL=32、n=8なら各段4層で、8個のトークンが異なる深さで並走する。

この構造は、次の入力トークンがまだターゲットの最終出力として確定していないという循環依存を生む。SPDはPDMが次トークンを予測して第1段へ供給することで依存を解消する。PDMは一度に多数の未来トークンを自律生成するのではなく、サイクルごとに1トークンだけ提案する。これにより、予測に必要な未確定状態の深さがパイプライン幅nで上限づけられる。

### 2. Multi-Depth Feature Aggregation

ターゲットの層0（埋め込み）、8、16、24、31など、複数の深さにアンカーを設ける。各トークンが既に通過した段数kに応じ、**その時点で計算済みのアンカーだけ**を取り出し、隠れ状態を連結して射影する。これをトークンごとの集約特徴gᵏとし、確定済みトークンの深い特徴と、未確定トークンの浅い特徴を、PDMへ系列として入力する。

例えば最も新しいトークンは埋め込み段階なのでg⁰、前のトークンは1段分の特徴g¹、さらに古いトークンはより深い特徴を使う。PDMはこの深度階段を見て次のトークンを予測する。重要なのは、**ドラフトが自分で生成した隠れ状態を次の入力に再帰的に使わない**ことである。EAGLE-3の多トークン先予測で生じる特徴ドリフトを避け、常にターゲットが実際に計算した特徴に依拠する。

PDMはLs層のTransformerデコーダと独立LMヘッドを持ち、ターゲットがQwen3.5の混合注意構造でも、PDMはQwen3型の標準注意を使う。深度別の特徴連結を射影するためのFCを備える。ターゲットの隠れ状態を全てGPU間転送する必要があり、アンカーの配置と通信量は設計上の負担となる。

### 3. Pre-stepドラフトとパイプライン計算の重畳

通常の「段を計算してから新しい隠れ状態でドラフトする」方式では、段の処理後にPDMが動くので直列の待ちが残る。SPDはサイクル開始時点で既にあるpre-step特徴をPDMへ渡し、ターゲットの各段が次の前向き計算をする**同じ時間帯**にドラフトを実行する。現在の段の結果を待たないため、ドラフトとターゲット段の間に同一サイクル内の依存関係がない。

pre-step特徴はpost-stepより1段浅く、Qwen3.5-4Bではドラフト受理率が約5%低くなる条件がある。しかしドラフト計算をクリティカルパスから隠す利得が大きく、実測ではこの選択が有利だった。PDMの実行時間を1段の計算時間以下にするため、著者は `Ls ≈ L/n − 1` を実用的な目安とする。L=32、n=8なら3層PDMがほぼ限界で、4層にすると受理率が少し上がってもドラフト時間が表に出て実測速度が悪くなる。

この並行化には**n段のGPUとは別にPDM専用GPUが1台必要**である。n=8なら9 GPU、n=16なら17 GPUで、単一GPUのEAGLE-3とハードウェア占有が等価ではない。

### 4. 遅延した逐次検証とロールバック

PDMが提案したトークンは、約nサイクル後に先行トークンがターゲットの最終段を抜けた時点で検証される。各サイクルでは1個の後続投機トークンを確認し、貪欲生成ならターゲットのargmaxとの一致を要求する。サンプリングでは通常の拒否サンプリングを用いて、ターゲット分布との一致を保つ。

受理なら新しいドラフトトークンを第1段へ投入して流れを継続する。棄却なら、最後に正しく確定した位置までKVキャッシュを切り詰め、進行中の段間活性化を破棄し、ターゲットの分布から再選択したトークンで第1段を再開する。したがって投機による**品質近似ではなく、正しい検証と棄却処理を伴う復号**を意図している。ただし棄却時のパイプライン洗い替えは高価で、受理率が下がるほど速度利得も下がる。

## 評価結果

### 理論値と実測値を区別した高速化

原著表2のOverall欄を抜粋する。数値は「理論値 / 実測値」の順で、通常の単一GPU自己回帰デコードに対する倍率である。

| 方式 | Qwen3.5-4B T=0 | Qwen3.5-9B T=0 | Qwen3.5-4B T=1 | Qwen3.5-9B T=1 |
|---|---:|---:|---:|---:|
| EAGLE-3 k=7 | 2.72 / 1.97 | 3.17 / 2.54 | 2.06 / 1.46 | 2.26 / 1.78 |
| PPSD n=8、Ls=1 | 1.68 / 1.25 | 1.96 / 1.44 | 1.44 / 0.95 | 1.68 / 1.10 |
| SPD n=4、Ls=4 | 2.64 / 2.27 | 2.70 / 2.32 | 2.48 / 1.95 | 2.57 / 2.01 |
| SPD n=8、Ls=4 | 3.51 / 2.41 | 3.62 / 2.44 | 3.13 / 1.84 | 3.34 / 1.93 |
| SPD n=8、Ls=3 | 3.39 / 2.53 | 3.61 / 2.67 | 3.05 / 2.05 | 3.33 / 2.21 |
| SPD n=8、Ls=2 | 3.32 / 2.47 | 3.46 / 2.56 | 2.96 / 2.03 | 3.16 / 2.15 |
| SPD n=16、Ls=2 | 3.70 / 1.43 | 3.90 / 1.49 | 3.19 / 1.06 | 3.46 / 1.13 |

SPDの8段3層構成は、4BのT=0でEAGLE-3 k=7の1.97倍から2.53倍へ実測が改善し、9Bでも2.54倍から2.67倍へ改善する。温度1では4Bで1.46倍から2.05倍、9Bで1.78倍から2.21倍となる。一方16段は理論値が4Bで3.70倍、9Bで3.90倍でも、実測はそれぞれ1.43倍、1.49倍へ崩れる。これらはGPU数を揃えた比較ではなく、**SPDは9台または17台を使い、EAGLE-3は1台**という条件を併記する必要がある。

原著表3。n=8でLsを3→4へ増やすと、温度0の受理率は0.3721→0.3799と約0.8ポイントしか改善しないが、4Bの実測高速化は2.53→2.41倍へ低下する。したがってPDMの深さは、受理率だけを最大化するのではなく、段の実行時間内に終わるかで選ぶべきである。

### 固定オーバーヘッドと負の結果

原著図2ではQwen3.5-4Bの飽和サイクル時間が、n=4・Ls=4で9.25ms、n=8・Ls=3で5.41msとなる。段数を倍増してもサイクル時間が半分にならないのは、段間通信、PDMへの特徴転送、検証、制御、同期などが固定的に発生するためである。n=16では段の前向き計算が短くなり、固定費用が支配するため、理論倍率が増えても実測が悪化する。

post-step特徴を使う派生版は、深い情報が得られるため理論上の受理率は改善するが、ドラフトが段計算後に直列化する。原著表4では4B、n=16、Ls=2、T=0で、ドラフト費用ゼロなら理論3.66倍でも、費用を入れると1.83倍まで下がる。pre-stepを使って並行化するという設計選択は、この差を避けるためのものである。

原著は幅4のdraft treeについて理論上の改善を示すが、分岐KV、tree attention、段間同期の実装が必要なため、**tree版の実測wall-clockは報告していない**。単一路版の実測倍率をtree版の性能として流用してはいけない。

## 既存研究との差

EAGLE-3はターゲットの隠れ状態から複数トークンを連続ドラフトし、ターゲットはその後にまとめて検証する。SPDはターゲット自体を段分割し、各サイクルで1トークンだけ提案して古い提案を逐次検証するため、未来へのドラフト長kに依存した誤差累積を避ける。両者は「小型ドラフトでターゲットの演算を減らす」という共通目的を持つが、並列化の位置が異なる。

PPSDも単一系列のパイプライン化を試みるが、初段特徴のみのPDMで予測し、段計算後にドラフトする。SPDは複数深度のターゲット特徴を利用して受理率を上げ、ドラフトを段計算と同時に走らせる。DFlash等の並列ドラフト方式はドラフト内部を高速化するが、ターゲットの処理順序をパイプライン化するSPDとは異なる軸であり、組合せの可能性は論文でも将来課題として挙げられる。

## 限界と実用性

最大の制約はGPU占有数である。8段なら9GPU、16段なら17GPUを使い、単一GPUのEAGLE-3より1系列に割り当てる資源が大幅に多い。低遅延を優先する特殊な単一要求には意味があるが、GPU当たりのトークン処理量や同時利用者数、クラスタ全体の費用対効果が向上した証拠ではない。多数のGPUをまたぐ通信・同期は、実装の違いやネットワーク構成に強く依存する。

またSPDの理論値はドラフト費用が段計算に隠れることを仮定する。PDMが深すぎる場合や段の処理が短すぎる場合、この仮定が破れ、16段のように固定費用が主役となる。パイプラインの巻き戻しはKVと中間活性化の廃棄を伴い、受理率が低いタスクでは利得を失う。thinking modeを無効化したQwen3.5-4B/9Bのバッチ1評価であり、長い推論過程を持つreasoning modeや高並行配信のSLOを直接示すものではない。

実測はデコード部分だけでプリフィルを除外している。モデルを複数GPUに配置する準備時間、最初のトークンまでの時間、通信トポロジーの違いを含めた要求全体の遅延やコストは別途評価が必要である。EAGLE-3はSGLang、SPD/PPSDは独自PyTorch実装であり、実装差が倍率へ影響する可能性もある。将来のtreeドラフト版は実測未実装で、理論値だけを実運用の性能とみなせない。
