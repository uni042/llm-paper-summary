# SweetSpot: An Analytical Model for Predicting Energy Efficiency of LLM Inference

## 概要

本研究は、大規模言語モデル（LLM）の推論に要する電力量を、入力トークン数と生成トークン数から予測する解析モデル「SweetSpot」を提案する。一般に生成トークン数が増えるほど総電力量は増えるが、**出力1トークン当たりの電力量**は必ずしも増え続けない。短すぎる出力では入力の一括処理費用を十分に償却できず、長すぎる出力では逐次復号の計算・メモリアクセス費用が増える。両者の中間に最もエネルギー効率の高い生成長が存在するというのが主張である。

著者は、入力長と出力長を64～4096トークンの範囲で変化させ、1B～9Bの13種類のモデルをNVIDIA H100とTensorRT-LLMで測定した。演算量だけでなくメモリアクセスを加えたモデルは、出力トークン当たりエネルギーの平均絶対百分率誤差（MAPE）1.79%を報告する。測定条件内で、最良と最悪の入力・出力長の組合せの効率差は平均33.41倍だった。ただしこれはモデルを改造して同一タスクの電力を33倍節約したという意味ではなく、**異なる入力・出力長のワークロード間の効率比**である。

## 問題設定

LLMの電力消費を入力長と出力長の単純な線形結合として扱うモデルは、自己回帰生成の二段階構造を十分に表現できない。入力をまとめて処理するプリフィル（prefill）では注意機構の演算に入力長の二次項が生じる。一方、復号（decode）は既存のキー・値キャッシュ（KV cache）を利用し、生成ステップが増えるにつれて参照する過去トークン数が増える。生成が進むほど一回の注意計算・メモリ読み出しは増加する。

従来の「出力トークン当たり一定のジュール」という近似では、長い入力と短い出力の高コスト、出力長を少し伸ばした場合の初期費用の償却、非常に長い生成におけるKV読み出し費用を一つの式で説明しにくい。論文の狙いは、実測曲線への単なる高次式の当てはめではなく、Transformerの演算とメモリ操作の構造から必要な項を導くことである。

## 手法

### 1. 演算量によるプリフィル費用

モデルの層数をL、隠れ次元をd、入力長を `n_in`、出力長を `n_out` とする。原著は行列積の積和を2浮動小数点演算と数え、単一層のプリフィルの演算量を `24*n_in*d^2 + 4*n_in^2*d` と表す。前半は注意投影とフィードフォワード層（FFN）の行列積、後半は注意得点の計算と値ベクトルの重み付き和に対応する。L層なら全体をL倍する。

この導出では、投影のQ・K・V行列、注意出力の投影、FFNの二段階変換を数え、正規化やソフトマックスなどの費用は主要行列積に比べて小さいとして省略する。したがって任意の最適化済み注意カーネルの実際のGPU命令数と一致する式ではなく、構造に基づく近似である。

### 2. 逐次復号費用と生成長の二次項

復号ステップtでは過去に `n_in+t-1` トークンがあり、KVキャッシュを使う注意処理はこの長さに比例する。原著の単一層・単一生成ステップの演算量は `24*d^2 + 4*(n_in+t-1)*d` である。これを `t=1...n_out` にわたり足し、層数Lを掛けると、生成長に比例する投影・FFN費用、`n_in*n_out` の交差項、`n_out*(n_out-1)/2` の累積項が得られる。

総演算量を生成トークン数で割ると、プリフィル費用は出力が長いほど薄まり、逐次復号の蓄積費用は出力が長いほど増える。この反対方向の依存性が、出力トークン当たりのエネルギーに極小値を生む基本的な仕組みである。

### 3. メモリアクセス費用の追加

演算量だけではGPU上のエネルギーを十分に説明できない。著者は、入力投影の読み書き、注意行列、FFNの重みと中間結果、復号時のKV読み出しを数え、プリフィルと復号それぞれのメモリ操作量を推定する。プリフィルには入力長二次の注意行列項があり、復号には生成済みトークンに応じて増える読み出し項がある。

計算とメモリアクセスの項をまとめ、係数を実測データから当てはめる。完全版の出力トークン当たり電力量は、原著の記法で `E_tok = θ0 + θ1*n_in^2/n_out + θ2*n_in + θ3*n_in/n_out + θ4*n_out + θ5/n_out` と表される。θ0は基礎的な生成費用、θ1は入力長二次の初期費用、θ2は入力と出力の交差効果、θ3は入力長に比例する償却項、θ4は長い復号で増える費用、θ5はメモリ操作に由来する追加の固定的費用を出力長で償却する項に対応する。

最後の `θ5/n_out` が演算量だけの版との主要な差である。係数θはモデル・実行環境・計測条件に依存するため、任意のGPUへ同じ数値を移植して使うことはできない。

### 4. 最適な生成長の解析的予測

入力長を固定して `E_tok` を `n_out` で微分し、0になる点を求める。係数が物理的に妥当で極小値が存在する条件では、最適な出力長は `n_out* = sqrt((θ1*n_in^2 + θ3*n_in + θ5)/θ4)` となる。これは「入力が長いほど初期費用の償却に長い出力が必要になり得る」ことと、「復号費用が大きいほど早めに出力を終える方が効率的になり得る」ことを一つの式で表す。

ただし、数式上の最適出力長をアプリケーションで自由に選べるわけではない。質問への回答長、品質、生成停止条件、サービスレベル目標（SLO）によって許容される出力長が決まるため、実運用では候補の生成長や入力要約方式を比較する際の指標として使う。

## 評価条件

測定対象はLlama 3.2（1B、3B）、OPT（1.3B、2.7B、6.7B）、Qwen2（1.5B、7B）、Gemma 2（2B、9B）、Granite（3B、8B）、Falcon-RW（7B）、Llama 3.1（8B）の計13モデルである。注意方式は通常の多頭注意（MHA）とグループ化クエリ注意（GQA）を含む。

実行環境はIntel Xeon Platinum 8480+搭載サーバー、H100 GPU、TensorRT-LLM。サーバーにはH100が4基搭載されるが、評価エンジンはテンソル並列とパイプライン並列をともに1とし、**各推論は単一GPU実行**としてデバイス間通信を除外した。最大系列長8192、最大バッチサイズ1024、最大同時トークン数8192に固定した。

入力長・出力長は64、128、256、512、1024、2048、4096の組合せを使い、固定長の合成要求を作成した。最初にFalcon-RW 7Bで要求数10、100、1000を比較し、その後は1000要求を使ってモデル横断評価した。実行は `trtllm-bench` のスループット重視モードであり、対話サービスの単発応答遅延の評価ではない。

GPU電力はNVMLを通じて500ミリ秒間隔で標本化し、台形則で積分したジュールを `E_tot` とする。生成トークン当たり電力量は `E_tok = E_tot/n_out`、エネルギー効率はその逆数 `E_eff = n_out/E_tot`（トークン/ジュール）である。論文の効率数値を読む際は、ジュール/トークンとトークン/ジュールの大小関係が逆になることに注意する。

## 主要結果

### 予測誤差と比較対象

| 方式 | 13モデル平均MAPE（%） | 解釈 |
|---|---:|---|
| 定数のトークン当たり電力量（Baseline 1） | 130.45 | 入出力長の非線形性を表現できない |
| 出力長のみ（Baseline 2） | 130.49 | 入力長依存を取り逃す |
| 入出力の合計長（Baseline 3） | 106.25 | 入力の二次費用を表せない |
| 先行する入力・出力依存モデル（Baseline 4） | 31.40 | 交差項を含むが近似精度が不足 |
| SweetSpot演算量のみ | 2.27 | 演算構造から主要依存性を説明 |
| **SweetSpot完全版** | **1.79** | メモリアクセスの固定費用項を追加 |

原著表3の平均値。完全版のモデル別MAPEはOPT 2.7Bで0.91%、Qwen2 7Bで2.88%、Llama 3.1 8Bで2.84%などで、全モデルが同じ誤差率というわけではない。論文は平均1.79%・標準偏差0.61ポイントを報告する。演算量のみから完全版への平均MAPE改善率は18.6%と説明されるが、これはトークン生成速度の改善ではない。

### 最も効率の高い入出力長の存在

入力長64を固定した曲線では、Llama 3.2 1Bの効率は出力長256で120.71トークン/ジュール、出力長4096で51.90となる。Falcon-RW 7Bでは同じ条件で18.78から2.18へ下がる。入力が短い場合でも、出力を長くすれば無制限に効率が上がるわけではないことを示す。

入力・出力長の組合せ全体で、最も効率の良い条件と悪い条件をモデルごとに比較すると、平均33.41倍（標準偏差4.90倍）の差があった。最悪条件は長い入力と短い出力に位置する。これは「ある特定の要求を33.41倍省エネ化できる」保証ではない。入出力の仕事量が異なる条件の相対効率であり、生成内容の品質やユーザー体験はこの倍率には含まれない。

### モデル構造・バッチサイズへの依存

13モデル全条件の平均効率では、Llama 3.2 1Bが55.91、Falcon-RW 7Bが5.12トークン/ジュールであった。OPT 1.3BとQwen2 1.5Bでは、パラメータ規模が近くても注意方式の差などにより平均効率が20.66対49.06となる。ただし、MHAとGQAだけの純粋な因果差を同一モデルで切り分けた実験ではない。層数、隠れ次元、FFN構成などの交絡が残る。

バッチサイズはSweetSpotの式に含まれていない。著者は追加検証でLlama 3.2 1Bの最大バッチサイズを64～1024へ変え、要求数1000・入力長64の場合、最大効率が120.71（バッチ1024）から48.90（バッチ64）へ落ちると示す。出力長4096ではバッチ256と1024の差が47.27対51.91へ縮む。従って、係数を学習したときの同時要求数・バッチ設定が変わると、推定式の一般化には再校正が必要となる。

## 既存研究との差

従来の定数モデルや入出力長の単純な関数は、モデル構造から必要な項を導かない。SweetSpotは、プリフィルの二次項、出力長に応じて償却される固定費用、KVキャッシュを使う復号の逐次増加項を明示し、実測エネルギーへ係数を当てはめる。メモリアクセスの追加で、演算量のみの式が見落とす一定の初期費用を取り込める。

運用上は、モデル選択、入力の切り詰めや要約、出力長の上限、バッチ方針を検討する際に、単なる「短いほど省エネ」という仮定を避けられる。もっとも、式は学習済みの推定器であり、入力と出力の内容を読んで意味的に最適な長さを決める仕組みではない。最小ジュール/トークンの点は、総ジュールの最小点とも必ずしも一致しない。

## 限界と適用上の注意

第一に、対象は1B～9Bの比較的小さいモデル、単一H100、TensorRT-LLM、固定の合成ワークロードである。MoEや70B以上の大規模モデル、CPUオフロード、異なるGPU世代、別の推論エンジンにそのまま係数を適用する根拠はない。ローカルPCのRTX 4070 Superに適用するには、同じ電力積分と入出力長の実測から係数を再推定する必要がある。

第二に、式はバッチサイズを明示的な入力に持たない。実際の並列要求数、スケジューラ、同時バッチ上限でエネルギー効率が大きく変わることは著者自身が追加実験で示している。オンラインサービスの到着間隔や混在する系列長を含めた予測は未完成である。

第三に、500ミリ秒間隔の電力サンプリングと固定長合成要求による計測であり、極短時間の電力変動、実際のプロンプト内容、応答品質、早期停止の分布は直接検証していない。平均MAPEは評価した条件内でのモデル当てはめ精度であって、未知のハードウェア・未観測長への外挿誤差を示すものではない。

第四に、エネルギー効率を上げるために生成長を変えると、回答の完全性や利用者の要求と衝突し得る。エネルギー最小化だけでなく、回答品質・サービスレベル目標・待ち時間・総消費電力量を同時に評価する必要がある。33.41倍という倍率を、品質を保った最適化アルゴリズムの効果として扱わない。
