# SweetSpot：入力・出力長からLLM推論の省電力点を予測する解析モデル

## 概要

SweetSpotは、大規模言語モデル（LLM）の推論で、入力トークン数と生成トークン数が変化したときの**出力1トークン当たり電力量**を予測する解析モデルである。単に出力が短ければ省エネルギーとは限らない。入力全体を一括計算する事前充填（prefill）には出力長に依存しない固定費があり、極端に短い回答ではそれを少数トークンへ割り振るため単位出力当たりの費用が高くなる。一方、出力を長くし続けると逐次復号（decode）で参照するキー・値キャッシュ（KV cache）が増え、各ステップの計算とメモリアクセスが増える。二つの効果の釣合いから、特定の入力長に対して効率が最も高い出力長が存在する。

著者らは、Transformerの計算量とメモリアクセスの数え上げから式を導き、NVIDIA H100上のTensorRT-LLMを用いて1B～9Bの13モデルを評価した。入力長と出力長は各64～4096トークン、要求数は主要評価で1000とした。従来の入力・出力依存モデルの平均絶対百分率誤差（MAPE）31.40%に対し、演算量だけのSweetSpotは2.27%、メモリアクセスも含む完全版は1.79%だった。最も効率的な系列長の組合せと最悪の組合せでは平均33.41倍の差がある。ただし、異なる長さの要求間の比較であり、同一質問の品質を保って電力量を33.41倍削減した実験ではない。

## 問題設定

従来の簡易推定では、入力長と出力長の線形結合、あるいは一定のジュール/トークンで電力量を近似する。しかしTransformerの注意計算は入力長の二次項を含み、復号では生成済みトークン数に応じて参照履歴が増える。事前充填と復号の費用を単一の比例定数で扱うと、長い入力・短い出力の高コストや、中程度の出力で効率が改善した後に再び悪化する現象を説明できない。

対象指標は総エネルギーだけではない。総エネルギーを出力トークン数で割った出力当たり電力量を最小化し、その逆数であるトークン/ジュールを最大化する。したがって「最小の総消費電力量」と「最も効率よく出力を生成する系列長」は別の最適化問題である。ユーザーが求める回答の長さ、完全性、正確性は式の直接の目的関数には入らない。解析モデルは、複数の許容可能な入出力長の候補を比較するための性能予測器である。

## 手法

### 1. 事前充填の演算量をモデル構造から数える

隠れ次元を`d`、層数を`L`、入力長を`n_in`、生成長を`n_out`とする。論文は1回の乗算と加算を合わせて2浮動小数点演算（FLOPs）と数える。1層の事前充填では、Q・K・V射影と出力射影が`8*n_in*d^2`、注意得点行列と値の重み付き和が`4*n_in^2*d`、フィードフォワードネットワーク（FFN）の二つの行列積が`16*n_in*d^2`となる。合計は`24*n_in*d^2 + 4*n_in^2*d`で、全層では`L`倍する。

この式の入力はモデルの隠れ幅と入力長、出力は事前充填の演算数である。入力長の二次項は注意行列の計算に由来するため、入力を倍にしたときに費用が常に単純に倍になるわけではない。正規化、ソフトマックス、バイアス等は主要行列積に比べ小さいとして省略されており、実装済み融合カーネルの正確な命令数を示す式ではない。

### 2. 逐次復号で増える履歴参照を積算する

KVキャッシュを保持する復号ステップ`t`では、既存の`n_in+t-1`トークンを参照する。1層の1ステップの演算量は`24*d^2 + 4*(n_in+t-1)*d`であり、前者は射影とFFN、後者はクエリと履歴キーの内積および値の重み付き和に対応する。`t=1`から`n_out`まで合算すると、`24*n_out*d^2 + 4*d*(n_in*n_out + n_out*(n_out-1)/2)`を得る。全層では再び`L`倍する。

ここで重要なのは、復号費用が単に出力長に比例するだけでなく、生成が進むにつれてKVキャッシュ参照が長くなることである。総演算量を`n_out`で割ると、事前充填の費用は生成が長いほど償却される一方、累積復号の項は生成長とともに増える。両者の逆向きの依存性が単位出力電力量の極小を生む。

### 3. メモリアクセスを加えて実測エネルギーへ接続する

演算回数だけでは、GPUの高帯域メモリ（HBM）からの読み出しや中間テンソルの書き込みを表せない。そこで著者は事前充填における重み・中間表現・注意行列の読み書きと、復号における重みおよびKVキャッシュの継続的な読み出しを数える。メモリアクセス量を含む係数付きモデルを、各モデルの実測データへ非線形最小二乗法で当てはめる。

完全版の出力トークン当たり電力量は、`E_tok = θ0 + θ1*n_in^2/n_out + θ2*n_in + θ3*n_in/n_out + θ4*n_out + θ5/n_out`である。`θ1`は入力二次の初期費用、`θ3`は入力依存の償却、`θ4`は生成の伸長で増える費用、`θ5`はメモリ操作に関係する追加の固定費用を出力長で償却する項として解釈できる。最後の`θ5/n_out`が演算量のみの式にない主要な追加項である。各係数はモデル・GPU・推論エンジン・要求分布の測定条件に依存し、別の環境へそのまま移植できない。

### 4. 最も効率の高い出力長を解析的に求める

入力長を固定して`E_tok`を`n_out`で微分し、極小条件を解くと、`n_out* = sqrt((θ1*n_in^2 + θ3*n_in + θ5)/θ4)`となる。分子は主に初期費用の償却必要量、分母は長い復号の追加費用を表す。入力が長いほど償却に長い出力が必要になり得る一方、復号単位費用が高いほど最適な出力は短くなり得る。ただし係数が物理的に妥当で極小が存在すること、入力・出力長が実験で扱った範囲にあることが前提である。

### 5. 計算モデルと実運用の区別

SweetSpotは、推論を途中で自動停止させる学習済み分類器でも、回答品質を直接測る評価器でもない。出力長の候補に対するエネルギー効率を推定し、例えば入力要約、最大生成長、要求のバッチ化方針を比較する材料を提供する。最適長が計算できても、その長さで質問に十分答えられるとは限らない。実運用では、許容される品質・応答期限を満たす候補の中で省電力性を比較すべきである。

### 評価設計の補足

論文はまずFalcon-RW 7Bで要求数10、100、1000を比較し、要求が少ない場合はGPUが十分利用されず、短い計測区間では電力サンプリングの相対誤差も大きくなると分析した。そのため主要な13モデル比較では要求数1000を採用する。実行エンジンの最大系列長8192、最大バッチサイズ1024、最大同時トークン数8192を固定し、モデル間で同じ測定枠組みを使う。係数は各モデルの観測データに当てはめており、あるモデルで学習した係数を別モデルへ移して検証した結果ではない。

## 評価結果

### 1. 比較方式と予測誤差

| 方式 | 13モデル平均MAPE | 主要な意味 |
|---|---:|---|
| 基準1：一定の出力トークン当たり電力量 | 130.45% | 入力長・出力長の依存性を表せない |
| 基準2：出力長のみ | 130.49% | 長い入力の初期費用を取り逃す |
| 基準3：入出力の合計長 | 106.25% | 非線形な入力二次項を表せない |
| 基準4：先行する入力・出力依存モデル | 31.40% | 改善するが曲線の形を十分表せない |
| SweetSpot：演算量のみ | 2.27% | Transformer演算構造を取り込む |
| **SweetSpot：演算＋メモリアクセス** | **1.79%** | 固定的なメモリ費用を含む6項モデル |

原著の表3におけるモデル別の完全版MAPEは、OPT 2.7Bで0.91%、Qwen2 7Bで2.88%、Llama 3.1 8Bで2.84%、Gemma 2 9Bで1.81%である。全モデルで一律1.79%という意味ではなく、13モデル平均と標準偏差0.61ポイントを示す。演算量のみから完全版へ拡張した平均MAPEの相対低下は18.6%と報告されるが、これはトークン生成速度の改善率でも実消費電力の削減率でもない。比較したのは、測定条件内での予測誤差である。

### 2. 効率の極大点と系列長による差

入力64トークンでは中程度の出力128～256トークン付近で効率が高く、長い入力4096トークンと短い出力64トークンの組合せでは低い。最良と最悪の組合せのモデル別効率比を平均すると33.41倍、標準偏差4.90倍だった。これは同一質問への二つの生成方法を比較した介入実験ではない。出力の内容や品質、要求の仕事量が異なるため、33.41倍を無条件に「省エネ化できる倍率」と宣伝すべきではない。

Llama 3.2 1Bでは、入力64トークンで出力256トークンの効率が120.71トークン/ジュール、出力4096トークンでは51.90だった。Falcon-RW 7Bの対応する値は18.78と2.18である。生成を長くすると固定費用の償却効果は増えるが、長い復号でのKV読み出し費用が支配的になると単位出力効率が下がることを示す。最も効率的な入出力長はモデルごとに変わり、単純なトークン長比例則では予測できない。

### 3. モデル構造とバッチの影響

13モデルの全条件平均ではLlama 3.2 1Bが55.91トークン/ジュール、Falcon-RW 7Bが5.12トークン/ジュールだった。近いパラメータ数のOPT 1.3BとQwen2 1.5Bでも平均効率が20.66対49.06となる。注意方式がMHAかGQAかの違いは一因と考えられるが、層数・幅・FFN構成も異なるため、これを注意方式単独の因果効果とは解釈できない。

原著第6.2節の追加実験では、Llama 3.2 1Bの最大バッチサイズを64、128、256、512、1024へ変えた。要求数1000・入力64トークンでは、最大効率がバッチ1024の120.71からバッチ64の48.90へ低下した。出力4096トークンではバッチ256と1024の差は47.27対51.91まで縮む。要求数128の条件では、最大バッチを128より大きくしても利用可能な要求が増えないため利得はない。したがってSweetSpotの係数はバッチや同時要求数を変えると再較正が必要である。

### 4. 測定の限界を含む結果の解釈

GPU電力は500ミリ秒刻みのサンプルから積分されるため、非常に短い要求や短時間のピークでは誤差が相対的に大きくなる可能性がある。主実験を1000要求に固定したのは、飽和条件で比較しやすくするためでもある。低同時実行の対話推論では、スケジューラの空き時間、ホスト処理、通信、キュー待ちなどの比率が変わる。MAPE 1.79%はこの測定環境での当てはめ誤差であり、未知のGPUや未観測系列長へ外挿したときの誤差上限ではない。

## 既存研究との差

定数モデルや単純な入力・出力長の線形モデルは、入力一括処理の二次費用、復号のKVキャッシュ参照の累積、出力トークン当たりの固定費用償却を構造的に区別しない。SweetSpotはTransformerの演算数とメモリアクセス数を数え、これらから入出力長の交差項、入力二次項、出力長比例項を持つ解析式を導く。係数を実測から当てはめる点は経験的だが、項の形は計算構造に根拠を持つ。計算のみの版とメモリアクセスを加えた版を比較して、追加項の寄与を独立に示した点も重要である。

既存の推論高速化アルゴリズムのようにGPUカーネルを置換したりKVキャッシュを圧縮したりする研究ではない。入力要約・最大生成長の設定、バッチサイズやモデル選択の方針を決める際に、どの系列長で単位出力エネルギーが高くなるかを予測する評価枠組みである。推論基盤やハードウェアが変われば同じ式の係数を測り直す必要がある。

## 限界・適用条件

**モデルとハードウェアの範囲。** 評価は1B～9Bの13モデルと単一H100、TensorRT-LLMに限られる。70B級モデル、混合専門家（MoE）、CPU・GPUオフロード、複数GPU間通信、民生GPU上の別推論ランタイムではボトルネックが変わる。RTX 4070 Super 12GBへ係数や33.41倍を直接移すことはできない。異なる環境で用いるなら、その環境の実測データで再推定しなければならない。

**バッチ・到着分布の未モデル化。** 式はバッチサイズを独立変数に含まず、最大バッチ1024で較正された。第6.2節の実験はバッチ上限の変更が最大効率を大きく変えることを示す。オンライン要求の到着間隔、複数系列長の混在、優先度、キュー待ち時間、サービスレベル目標（SLO）は主要モデルの入力にない。低負荷や遅延制約の厳しいサービスでは、最も省電力な条件が最適な運用条件とは限らない。

**測定対象と外挿。** 500ミリ秒電力標本、固定長の合成入力・出力、単一推論エンジンを用いる。モデルの推論内容や回答品質を固定した比較ではない。冷却、電源変換、ホスト全体、ネットワークの電力量を含むデータセンター総電力でもない。各モデルに対して測定点へ係数を当てはめたMAPEは、未知のモデル・未観測系列長・別GPUへの予測保証ではない。

**品質と総エネルギーの別目的。** 出力トークン当たり電力量の最小化は、総消費電力量の最小化や回答の十分性と同じではない。回答を必要以上に長くすれば総エネルギーが増える。出力を短くしすぎれば必要な情報が欠落する。論文は品質を保った生成停止規則や実サービスでの総合最適化を実装・評価したわけではない。アプリケーションでは回答品質・応答期限を先に制約として定め、許容範囲内でモデルの予測を利用する必要がある。
