# ART：注意出力の収束を監視してKVブロックの走査を早期終了する

## 概要

ART（Attention Run-time Termination）は、大規模言語モデルの復号中に、注意計算の累積出力が十分安定したと判断できた時点で残りのキー・値（key-value; KV）ブロックへのアクセスを止める方式である。既存のKVキャッシュ圧縮が「どのトークンのKVを保持するか」を決めるのに対し、ARTは**保持されたKVをどこまで実際に走査するか**を実行時に決める。KVの保持方針を置き換えるのではなく、密注意にもSnapKVやPyramidKVのような疎注意にも重ねられる。

主要な着想は、トークンの重要性を注意スコアだけから推測するのではなく、FlashAttention型のオンラインsoftmaxが更新する中間注意出力を直接観察することである。注意出力はキーKによる重みと値Vの両方の影響を受ける。大きな注意スコアが付いたトークンでも値ベクトルが小さければ出力への影響は小さく、逆に注意スコアだけでは見落とす重要な値もある。ARTは中間出力の**大きさの変化**と**方向の変化**を監視し、一定数のブロックで安定したときだけ打ち切る。

Mistral-7BとLlama-3.1-70Bを使ったLongBench評価では、複数のKV管理方針を平均した出力トークン当たり時間（time per output token; TPOT）を、それぞれ約10.5%と9.7%短縮した。大バッチでは生成処理量が最大20%向上したと報告する。ただし、**長距離の情報検索では危険な早期終了が起こる**。Qwen3-8BのRULER Needle-in-a-Haystack（NIAH）では、32K文脈の完全KVで99.34%だった正解率が、単純な新しいKV優先走査にARTを加えると78.65%へ落ちた。したがって「品質をほぼ落とさず高速化」と一括りにするのは不正確で、走査順序と課題依存の誤差を必ず区別する必要がある。

## 問題設定

長文脈の自己回帰復号では、新しいトークンごとに過去のKVキャッシュを参照する。文脈が伸びるとKVの読み出し量と注意演算が増え、HBM帯域やGPUカーネル時間が律速になる。既存の圧縮・疎化手法は、注意スコア、重要トークンの頻度、近傍保持、接頭辞アンカーなどに基づいて参照するKVを減らす。しかし、注意スコアは出力への寄与を完全には表さない。注意演算は`softmax(QK^T/sqrt(d))V`であり、実際の出力への寄与にはVが掛かるからである。

値ベクトルまで含めた重要度を事前に計算する方式もあるが、予測器や追加の前処理を必要とし、推論時の負担を増やす。ARTは、既存のFlashAttentionカーネルがブロック単位の累積出力をもともと保持していることを利用する。KVを順に処理したとき、後続ブロックが累積出力をほとんど変えなくなれば、残りの走査を省ける可能性がある。

この最適化は**近似注意**である。最後までKVを走査した結果と、途中で止めた結果は厳密には異なる。さらに途中で安定したように見えても、まだ未走査の遠い位置に重要な情報があれば結果が大きく変わる。ARTの効果と安全性は、停止判定のしきい値だけでなく、重要なKVを先に処理できる走査順序に依存する。

## 手法

### 1. FlashAttentionの逐次ブロック累積を監視する

FlashAttention型の注意カーネルは、KVをタイルに分けて読み込み、オンラインsoftmaxの正規化と累積出力を更新する。t個のブロックを処理した時点の出力を`O^(t)`、全Tブロック処理後を`O^(T)`とする。通常は最後まで処理してから出力を返すが、ARTは各ブロック処理後に`O^(t)`の変化を評価し、出力が収束したと判断できれば残りのKV転送と演算を行わない。

この処理を外部で完全な出力ベクトルのノルムとして計算すると、スレッド間の集約やメモリ転送の費用が増えて利得が消える。著者らはGPUの行列積累積（matrix multiply-accumulate; MMA）レジスタ配置を利用し、**warp 0の32レーンそれぞれの先頭要素**を取り出した小さなプローブベクトルx^(t)を使う。MMAの要素配置が分散しているため、これは出力の連続した32要素ではなく、ヘッド次元に散らばる要素を観察する近似である。プローブの安定性を出力全体の安定性の代理指標として使う。

プローブは完全な出力を代表する保証がない。論文付録Bはプローブと完全出力に基づく理想判定の整合性を実験的に調べるが、任意の出力ベクトルに対して32値だけで十分とする無条件の数学的保証ではない。停止判定に連続安定回数を要求するのは、この近似の誤判定を緩和するためでもある。

### 2. 出力の大きさと方向を分けて判定する

ARTは連続するプローブx^(t-1)とx^(t)の差を、二つの尺度で測る。大きさの変化は`d_scale=||x^(t)-x^(t-1)||_2`、方向の変化は`d_direction=1-cos(x^(t),x^(t-1))`である。前者が閾値τ未満、かつ後者が閾値φ未満であれば、そのブロックの更新を「安定」と判定する。

一つのL2差分だけで判定すると、ベクトルの長さの変化と方向の変化を同じしきい値に押し込むことになる。長さがほぼ同じでも意味的に重要な方向へ回転する場合と、方向は同じでも値の大きさが変わる場合を区別しにくい。ARTは二条件を分けることで、スケールだけに敏感すぎたり方向の変化を見落としたりする問題を減らす。実装の標準設定は`τ=10^-5、φ=10^-3`である。

さらに、連続してp個のKVブロックで二条件が成立したときだけ打ち切る**忍耐回数（patience）**を設ける。標準設定はp=5である。途中の1ブロックだけ出力が変化しなくても、後続ブロックが重要な値を含む可能性があるため、短い一時的安定を即座に終了と解釈しない。論文アルゴリズム1は、各タイルの読み込み、累積更新、プローブ抽出、二条件判定、連続安定回数更新、早期終了、最後の正規化という順序を明示する。

### 3. 走査順序と既存KV選択方式との合成

ARTが扱うKVブロックの候補集合は、既存のKV管理方式が決める。完全KVではすべてのブロックが候補であり、ARTは最近のトークンから過去へ向かって走査する。これは最近の文脈への注意が高いことが多いという経験則を利用する。StreamingLLMのようなパターン保持型では、注意シンクと最近のトークンを維持しつつ、残ったブロックを新しいものから走査する。SnapKVのように各ブロックの重要度スコアがある場合は、そのスコアが高い順に処理する。順序変更はインデックス対応表による間接参照で実現し、どのKVを保持するか自体は変更しない。

ここで重要なのは、**走査順序が停止の安全性を左右する**ことである。重要な情報を早く処理すれば累積出力の収束が後続の小さな寄与を示す。しかし、検索すべき情報が古い位置にあり、最近のブロックを見ただけで早期終了すると、その重要情報を一度も参照しない。SnapKVやPyramidKVのように検索関連のKVを優先できる方式と組み合わせた場合にARTの品質が改善するのは、この順序依存性と整合する。

すべての選択済みブロックを最後まで処理する場合、順序を変更しても注意の定義は同じであり、差は通常の浮動小数点演算の非結合性程度である。しかし途中で停止すれば近似となるため、既存のKV圧縮による誤差にARTの打ち切り誤差が追加される。両者を「同じ圧縮率で比較した」としても、処理したブロック数と品質は異なる。

### 4. 条件付きの打ち切り誤差境界

論文は、最終安定窓の後で未走査ブロックの正規化された注意質量が走査順に減衰するという**質量制御された走査（mass-regulated traversal）**を仮定する。また、プローブが重要な出力更新方向を十分に保存することを仮定する。この条件の下で、停止位置t*、全ブロック数T、安定窓開始位置b=t*-p+1、プローブの保存性νなどを用いて、完全注意出力と早期停止出力のノルム差を`((τ b+Δμ)/ν) ln(T/t*)`で抑える形の上界を与える。

この上界は、**どの順序でKVを読んでも正しい情報が保持されるという保証ではない**。未走査の重要ブロックが突然現れるような順序では前提が崩れる。しかも評価対象は注意出力の近似誤差であり、下流の長距離検索問題で正解することの保証ではない。論文のRULER実験が示すように、出力の局所的な安定と検索の正しさは同義ではない。

|---|---|---|---|
| 完全KV | 99.95 / 1.00 | 99.73 / 1.00 | 99.34 / 1.00 |
| 完全KV+ART | 89.11 / 1.10 | 85.77 / 1.17 | 78.65 / 1.27 |
| SnapKV | 92.65 / 1.11 | 99.54 / 1.16 | 99.37 / 1.18 |
| SnapKV+ART | 92.73 / 1.11 | 98.93 / 1.21 | 95.68 / 1.36 |
| PyramidKV | 90.09 / 1.10 | 99.36 / 1.18 | 99.24 / 1.19 |
| PyramidKV+ART | 90.72 / 1.11 | 97.78 / 1.21 | 96.00 / 1.37 |
| StreamingLLM | 80.13 / 1.12 | 81.42 / 1.20 | 77.78 / 1.21 |
| StreamingLLM+ART | 80.25 / 1.12 | 81.30 / 1.26 | 75.81 / 1.42 |

この表はARTの品質境界を最もよく示す。完全KVにARTを足した32K条件では速度が1.27倍になる一方、正解率は99.34%から78.65%へ**20.69ポイント低下**する。これは単なる小さな誤差ではない。最近のKVから処理している間に出力が安定したと判断してしまい、遠い位置の検索対象に到達しない場合がある。

一方、SnapKVやPyramidKVの重要度順走査と組み合わせると、32Kでもそれぞれ95.68%、96.00%の正解率を保ちながら1.36〜1.37倍へ速度を上げられる。ただし完全KVの99.34%と同じ品質ではなく、ベースのSnapKVやPyramidKVからも数ポイントの低下がある。長距離検索に敏感な用途では、元のKV選択方式とARTの停止判定を一体で評価する必要がある。

### 構成要素除去：大きさ・方向・忍耐回数はどれも必要

| Mistral-7B、LongBench、完全KV | LongBenchスコア | FlashAttentionカーネル時間 |
|---|---:|---:|
| ART全構成 | 45.74 | 0.633 ms |
| 大きさの変化条件なし | 19.34 | 0.135 ms |
| 方向の変化条件なし | 43.87 | 0.628 ms |
| 忍耐回数なし | 41.54 | 0.506 ms |

大きさの変化を無視すると、方向がほぼ一定のまま値だけ変わるケースで極端に早く止まり、LongBenchスコアは45.74から19.34へ低下する。方向の変化を無視しても43.87まで下がり、忍耐回数を外しても41.54となる。停止判定を単純に緩めればカーネル時間は短くなるが、重要な情報まで飛ばしてしまう。論文はこの構成要素除去により、三つの条件の組合せが速度と品質の両立に必要であると説明する。

## 既存研究との差

SnapKVやPyramidKVは、推論前または実行中にKVのどの部分を保持するかを決める。ARTはその選択済み集合を入力として受け取り、**注意カーネルの内部で実際に読み込むKVブロック数を動的に減らす**。両者は最適化する段階が異なる。注意スコアだけでトークン重要度を予測する方式に対しては、累積出力の変化を観測することで値ベクトルの寄与を含めて判定できる。値を考慮した別の重要度予測器に対しては、追加の予測モデルを置かず、カーネルに既にある中間状態を使う点が特徴である。

一方、ARTは重要なKVを見つける検索機構ではない。注意出力の局所的な安定性を見て後続を省略するだけである。したがって、どのブロックを先に見るかという探索順序が品質の前提条件となる。長距離の情報検索に対する大きな品質低下を論文が明示している点は、既存のKV圧縮研究との比較で重要である。

## 限界・実装上の注意

第一に、早期終了は近似であり、完全注意の数学的な同値変換ではない。論文の誤差上界は残余注意質量の減衰とプローブの代表性を仮定しており、任意のKV走査順序・任意の長距離検索課題での正解率を保証しない。特に、長文脈で重要情報が最近の窓にない場合は、完全KV+ARTの32K NIAHで正解率が20.69ポイント落ちた。これは利用時に必ず確認すべき重大な失敗例である。

第二に、warp 0の32レーンを使うプローブはGPUのMMAレジスタ配置に依存する。異なるカーネル、GPU世代、ヘッド次元、量子化・疎注意実装にそのまま移植できるとは限らない。標準パラメータτ、φ、pも論文のモデルと実装で評価された値であり、別のGPU・モデル・負荷では調整が必要になる。第三に、性能改善はKV読み出しが律速となる長文脈・大バッチで大きく、短文脈や演算律速の条件では停止判定の追加費用が利得を相殺する可能性がある。

最後に、最大20%の生成処理量増加は実験条件付きであり、LongBenchの平均TPOT短縮率約10%と同じ指標ではない。単一の「ARTは20%高速化」といった要約だけでは、どの負荷・品質条件で達成したかが不明になる。長距離検索や厳密な引用が必要な用途では、SnapKVなどの検索対応方針と組み合わせ、正解率を検証した上で採用する必要がある。
