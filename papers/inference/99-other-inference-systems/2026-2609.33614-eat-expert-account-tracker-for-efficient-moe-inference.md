# EAT: Expert Account Tracker for Efficient MoE Inference

## 概要

本論文は混合専門家モデル（Mixture-of-Experts、MoE）の推論時に、各トークンで何個の専門家ネットワークを実行するかを決める問題を扱う。固定個数選択（Top-K）では容易なトークンにも同じ数の専門家を割り当てる。一方、累積確率に基づく可変個数選択（Top-P）は、そのトークンでルータが出した確率だけを見るため、専門家が過去にどの程度頻繁に使われ、どの程度大きな出力を作ったかを反映しない。EATは専門家ごとの履歴を保持して瞬時のルータ出力と合成し、選択閾値も動的に変更する。

原著はMixtral-8x7B-v0.1、Phi-3.5-MoE-instruct、Qwen3-30B-A3Bを8枚のA100上で比較する。固定選択の平均活性専門家数を約25%以上減らし、同程度の活性数に調整したTop-Pより多くの課題で精度が高いと報告する。具体例としてPhiのBoolQはTop-Pの69.36からEATの76.42、QwenのCHIDは32.67から50.61となった。ただしQwenのMMLUでは77.85から73.96へ低下し、すべての課題で改善するわけではない。性能回復を目的とした追加学習（OPD）を適用するとQwenのCHIDは67.46まで回復するが、追加の学習費用が発生する。

本研究の主張は「モデルの重みを圧縮して保存容量を減らす」ことではなく、「各トークンで実際に実行する専門家数を減らす」ことである。全専門家のパラメータをGPUから追い出す方式ではないため、メモリ容量の改善、通信量削減、同時要求時の処理量改善を同一視できない。原著の速度表は特定の生成条件に限られ、推論配信システム全体の初回トークン時間やサービス品質制約を評価したものではない。

## 問題設定と既存方式の限界

MoE層では、入力隠れ状態をルータへ渡し、複数の専門家の中から少数を選び、その出力をルータ重みで加重合成する。密な全専門家実行に比べて計算量を抑えられる一方、標準的なTop-Kは入力の難易度が変化してもK個を必ず起動する。MixtralとPhiの原著設定は最大2個、Qwen3-30B-A3Bは最大8個である。必要な専門家数が少ないトークンにも固定個数の計算を課すため、活性数をさらに減らす余地がある。

Top-Pはルータ確率の大きい順に累積確率を見て、閾値を満たす個数を選ぶ。しかし同じルータ確率でも、ある専門家が過去の多数の入力で一貫して役立っていたか、偶然高得点になったかを区別しない。EATは過去の活性頻度、平均ルータ重み、実際の出力ノルムを持続的な統計として扱う。現在の入力だけで判断するよりも、履歴に裏付けられた専門家を残すことを意図する。

ただし「専門家を減らすほど必ずよい」わけではない。原著の感度分析では、Mixtralで平均活性数を1個まで落とすとパープレキシティ（perplexity、PPL）が約4.3へ悪化する。平均約1.36個付近では品質変化が比較的小さく、下位層と上位層で重要度も異なる。この観察が、専門家を少なくしつつ下限と上限を設ける設計の根拠である。

## 手法

### 1. 専門家履歴の記録と総合得点

EATの第一段階では専門家ごとに三種類の状態を蓄積する。第一は過去の活性回数 `N_i` であり、入力列全体でその専門家が何度選ばれたかを数える。第二は活性時にルータが付けた重みの累積 `P_total,i` であり、回数で割った平均を利用する。第三は専門家出力ベクトルの二乗ノルムではなく、L2ノルム `||o_i||_2` の指数移動平均 `C_s,i^(t)` である。式は `C_s^(t)=(1-α) C_s^(t-1)+α ||o||_2`。原著の実験では `α=0.95` とする。

これらを重み付きで合成する履歴得点は、原著式(1)で `S_h,i = w1 N_i/(Σ_j N_j) + w2 P_total,i/N_i + w3 C_s,i^(t)` と定義される。表1の係数は順に `w1=0.3`、`w2=0.3`、`w3=0.4`。一つ目は過去の使用頻度、二つ目は活性時のルータの評価、三つ目は実際の出力規模を表す。三指標は尺度が異なるため、原著式が示す以上の厳密な確率解釈はできない。特に未活性専門家で `N_i=0` の場合の除算回避方法は式からは明らかでなく、実装検証が必要である。

第二段階では現在トークンのルータ確率 `p_i` と履歴得点を `I_i=(1-β)p_i+β S_h,i` で合成する。実験では `β=0.6` なので、履歴側に相対的に大きい重みを与える。瞬間的な確率が小さくても履歴上有用な専門家は残りやすい。一方、分布が急変して過去の統計が古くなる場合には、その履歴が現在の最適な選択を妨げる可能性がある。

### 2. 閾値の算出と調整

原著式(3)〜(5)では、生のルータ得点 `g_i` の平均 `μ_w` と標準偏差 `σ_w` を計算し、初期閾値を `τ=max(α1 μ_w, μ_w-α2 σ_w)` とする。表1の値は `α1=0.5`、`α2=1.0` である。得点分布が尖っているか広がっているかに応じて閾値を変え、固定閾値に比べてトークンごとの専門家数を調整しやすくする。

さらに原著は、現在と前回のPPLを比較し、悪化時に `τ` を20%増加、改善時に10%減少させると説明する。その後、ルータ分布の10〜90パーセンタイル相当の範囲で上下限を設け、`κ1=0.7`、`κ2=0.3` による平滑化を行う。入力依存の閾値変化が激しすぎると選択専門家数も不安定になるため、上下限と平滑化を置くという設計である。

**一次資料の注意点:** 原著は「PPLが悪化したらより多くの専門家を選ぶ」と述べるが、同じ本文の式(6)は `I_i > τ_final` の専門家を選ぶため、他の条件が固定なら閾値を20%引き上げると選択集合はむしろ縮小する。この説明と数式の符号関係はそのままでは整合しない。本文だけから正しい実装挙動を断定できないため、実装確認が必要な論点として残す。またPPLを生成中にどの教師信号で計測するか、その測定費用や運用時の可用性も明確でない。オンラインで真の次トークンが分からない一般的な推論配信にそのまま適用できると断定しない。

### 3. 可変個数の専門家選択と出力合成

閾値決定後は `I_i > τ_final` を満たす専門家を候補集合とする。候補が0個なら得点最大の1個を必ず残し、候補が1〜K個ならそのまま使い、K個を超えた場合は得点上位K個に切り詰める。したがって選択数は常に1〜K個であり、全専門家の同時起動やゼロ個の出力を避ける。

選択された専門家には二値マスク `m_i` を付け、元のルータ重みを `g_norm,i=g_i m_i/(Σ_j g_j m_j+ε)` で再正規化する。原著の `ε=10^-8` は分母が極小になる場合への対処である。重要度 `I_i` は選択のために使い、最終的な専門家出力の合成重みはマスク後の元ルータ重みから計算する点が重要である。専門家重み自体を削除・再学習しなくても、この選択マスクを導入できる。

ただし、履歴得点を更新するためには実行した専門家の出力ノルムを観測し、各専門家・各層の状態を保持しなければならない。履歴集計の追加メモリや計算時間はゼロではない。また選択数が小さくなってもGPU実装の専門家束ね方や通信粒度によって実際の高速化は変わり、活性数削減率がそのまま速度改善率になるわけではない。

### 4. 追加学習による品質回復（OPD）

強い疎化で失った品質を回復するため、原著は最適化による性能回復（Optimized Performance Recovery、OPD）を追加する。各順伝播でルータ確率をトークン平均して正規化し、そのエントロピーに関する正則化を学習目的へ加える。ルータ得点を再重み付けする処理も組み合わせ、専門家の利用が一部へ極端に偏るのを抑える。実験では正則化係数 `λ_opd=0.8` を使用し、無効化する場合は0とする。

OPDはモデル全体ではなくルータ重みのみを更新する。学習率は `5×10^-5`、勾配蓄積は1、最大入力長256、最大出力長64、温度0.8と報告される。追加データ数は9,000例で、原著の感度分析では250更新ステップ付近が良好とされる。データを増やしすぎたり更新を重ねすぎたりすると性能が悪化するという負の結果もある。学習データの課題分類は評価対象に合わせて構成されており、完全に未知の配信ドメインへ一般化する保証はない。

## 評価

### 実験環境と比較条件

原著は8枚のNVIDIA A100を使用し、Mixtral-8x7B-v0.1、Phi-3.5-MoE-instruct、Qwen3-30B-A3Bを対象にする。評価にはOpenCompassを使い、HellaSwag、PIQA、CHID、WSC、BoolQ、MMLU、CMMLU、XSumの8課題を用いる。CHID、XSum、WSCは生成モード、それ以外はPPLに基づく評価モードである。Top-P比較は活性専門家数が概ね近くなるようモデル別に `P=0.6`（Mixtral）、`0.2`（Phi）、`0.4`（Qwen）へ設定する。固定Top-KのKは前二者が2、Qwenが8である。

この比較設計は「固定Kからどれだけ削れるか」と「近い活性数のTop-Pに対して品質を維持できるか」を分けて評価できる。一方、Top-Pの閾値はモデルごとに固定され、全ての課題で厳密に同じ活性専門家数になるわけではない。各表の活性数と品質を対で読む必要がある。

### 課題精度の代表結果（原著表2）

|モデル・課題|固定Top-K|Top-P|EAT|EAT+OPD|読み取り|
|---|---:|---:|---:|---:|---|
|Mixtral / BoolQ|69.11|66.15|68.40|69.25|疎化で落ちた精度を履歴選択とOPDで回復|
|Mixtral / WSC|61.54|60.58|63.46|64.83|EATは固定方式も上回る|
|Mixtral / MMLU|71.67|65.38|70.37|71.59|Top-Pから改善するが固定方式にはわずかに届かない|
|Phi / BoolQ|75.32|69.36|76.42|77.60|履歴選択の利得が大きい|
|Phi / WSC|68.27|71.15|67.31|67.88|Top-Pより悪化する負の例|
|Qwen / CHID|44.81|32.67|50.61|67.46|OPDの効果が大きいが固定方式との差も変わる|

表2は単一の総合得点ではなく課題ごとの指標である。たとえばQwenのCHID改善だけを取り出して「全課題でTop-Pを上回る」と要約すると誤る。PhiのWSCやQwenのMMLU、XSumのような不利な結果を併記することが、提案方式の適用範囲を判断するうえで重要になる。

### 活性専門家数（原著表3）

Mixtralの固定Kは各課題で2.00個、EATはHellaSwagで1.47、PIQAで1.46、BoolQで1.45、MMLUで1.47となる。Phiも固定2.00個に対し、PIQAで1.34、BoolQで1.70、CMMLUで1.44である。Qwenは固定8.00個に対してPIQAで5.90、MMLUで5.50、XSumで6.28となる。活性数が一定ではない点は、トークンや課題に応じて専門家の必要数を変えるという設計に対応する。

一方、EAT+OPDの活性数は常にEAT単独より小さいわけではない。MixtralのMMLUはEATの1.47からOPD後1.69、PhiのCMMLUは1.44から1.44、QwenのXSumは6.28から6.63である。品質回復のために活性数が増える場合があるため、「OPDを付けても疎化率が完全に不変」とは断定しない。

### 生成速度（原著表4）

|モデル・入力+最大出力|固定Top-K|Top-P|EAT|解釈|
|---|---:|---:|---:|---|
|Mixtral / 2048+256|0.5214|0.5100|0.5196|固定方式には僅差で届かない|
|Mixtral / 1024+128|0.3931|0.3739|0.3864|Top-Pより速いが固定方式より遅い|
|Mixtral / 512+32|0.3814|0.1596|0.3671|Top-Pより速いが固定方式より遅い|
|Phi / 2048+256|1.1319|0.9479|1.1600|両比較方式より速い|
|Phi / 1024+128|0.9295|0.9073|0.9158|固定方式より遅い|
|Phi / 512+32|0.8060|0.8719|1.1421|両比較方式より速い|

単位は原著表4のトークン/秒である。Mixtralの3条件ではEATはTop-Pを上回るが、固定Top-Kをいずれも上回らない。Phiの1024+128でも固定方式より遅い。従って、専門家活性数の削減は推論速度改善の必要条件にも十分条件にもならず、ルータ追加処理、モデル構造、入出力長の影響が残る。これらの数値は極めて低い絶対生成速度であり、実運用配信系の性能を直接代表するとは限らない。

### 感度分析と構成要素の検証

原著図2は平均活性専門家数とPPLの関係を示す。活性数を1個に制限するとMixtralのPPLが約4.3まで悪化し、平均1.36個付近では安定するという観察がある。これは最低限の専門家数を残す必要性を支持するが、すべてのモデル・課題で1.36が最適という意味ではない。

原著図3は層ごとの重要度の違いを示し、下位層0〜23では平均1.3〜1.5個程度まで削りやすく、上位層24〜30では最大Kに近い活性を維持する方がよいと説明する。層ごとに一律のKを使わない設計の余地を示すが、全モデルで同じ層番号に境界があると一般化してはいけない。

OPDの感度分析（原著図4・図5）では、9千例、250ステップ付近が良好で、それ以上のデータや更新回数では悪化し得る。これは小規模調整でも回復できるという主張の根拠である一方、学習データの選び方に敏感であることも示す。原著は専門家活性の履歴得点・閾値・OPDを個別に取り外した包括的な実機負荷評価までは提示していないため、各部品の速度寄与の分離には限界がある。

## 既存研究との差と技術的位置付け

固定Top-Kは入力に関係なく専門家数を固定し、Top-Pはその時点のルータ確率から可変個数を選ぶ。EATはそこへ「過去にどれだけ使われ、どれだけ大きい出力を出したか」という状態を加える。静的な専門家枝刈り（pruning）や重み結合（merging）とは異なり、全専門家の重みを残したまま、実行時の選択マスクだけを変更する。

Ada-KやXMoEなども可変個数選択を扱うが、EATの差分は三種類の履歴統計と現在ルータ確率を同一得点へ統合する点である。追加のOPDは学習なしの推論時制御とは別工程であり、精度を回復する代わりにルータの事後調整が必要となる。この二つを混同せず、EAT単独とEAT+OPDを別方式として評価表に残す。

オフロードや専門家並列化の研究との関係では、EATが直接減らすのは「起動した専門家の演算」である。重み配置、PCIe/NVLink転送、GPU間All-to-All、KVキャッシュ容量、要求スケジューリングなどを最適化する研究とは対象ボトルネックが異なる。推論配信系へ組み込む場合は、活性専門家数の削減が実際のGPUカーネル実行数や通信量へ変換されるかを別途測定する必要がある。

## 限界

第一に、履歴得点は長期統計を使うため、入力分布が変わると過去に高評価だった専門家を過剰に選ぶ恐れがある。出力ノルムは必ずしも最終予測への因果的貢献を表さず、重要度の代理指標にすぎない。履歴の初期化、未活性専門家の除算、モデル再起動後の状態復元、要求間の統計共有などは原著から十分に確定できない。

第二に、PPLに基づくオンライン閾値調整の実装仕様が明確でない。原著はPPL悪化時に閾値を上げて専門家数を増やすと述べる一方、選択式では高い閾値ほど候補が減る。数式と説明の整合を実装で確認する必要がある。真の次トークンを知らない配信推論でPPLをどう取得するかも追加費用を含めて未解決である。

第三に、評価は8枚のA100と三種類のMoEに限定される。モデル並列化の方式、GPU世代、同時要求数、量子化精度、オフロード条件を変えた実測はない。速度表は0.1〜1トークン/秒台を含み、実用推論基盤の処理率や初回トークン遅延を直接予測できない。全専門家重みは保持されるため、必要なGPUメモリ容量が活性数と同率で減るわけではない。

第四に、OPDは9千例の事後学習とルータ更新を必要とする。EAT単独の性能低下がOPDで常に回復するわけではなく、課題によってはTop-Pや固定方式に届かない。評価課題と似た分類の調整データを使っており、未知の業務領域や分布外入力に対する頑健性は別途検証が必要である。

第五に、平均活性専門家数だけでは負荷分散や最大メモリ占有量は分からない。特定専門家へ要求が集中すると、全体の演算量が減ってもGPU間の負荷偏りや通信待ちが増える可能性がある。EATが専門家配置や通信経路を直接変更する設計ではないことから、実システムへの統合効果は独立した評価課題である。
