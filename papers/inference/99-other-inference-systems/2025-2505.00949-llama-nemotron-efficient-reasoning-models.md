# Llama-Nemotron: Efficient Reasoning Models

## 概要

Llama-Nemotronは、推論モデルの能力向上を「生成時に長い思考列を出させる」だけで解かず、モデル本体の実行効率まで設計対象にした系列である。Nano（8B）、Super（49B）、Ultra（253B）の3規模を用意し、Llama 3系を出発点として、層ごとに異なるTransformerブロックを選ぶ異種アーキテクチャへ変換する。狙いは、同じ推論品質を得るためのGPU計算・メモリを減らし、DeepSeek-R1級の推論能力と高い推論スループットを両立することである。

効率化の中核は、Puzzleと呼ばれるニューラルアーキテクチャ探索（neural architecture search; NAS）である。元モデルの各ブロックに対して、計算量や構造の異なる代替ブロックを局所蒸留し、その候補群から品質損失と実機効率の交換条件を満たす組合せを選ぶ。したがって単純な一様枝刈りではなく、層ごとに必要な容量を変える。

さらに推論時には通常チャットと推論モードを切り替える動的推論トグルを持つ。簡単な問い合わせでは長い推論列を省き、必要な問題だけ追加の生成計算を使えるため、モデル構造側の効率化と要求単位の計算量制御を組み合わせている。

## 問題設定

推論モデルでは、難問に対する精度を上げるほど出力する思考tokenが増え、モデル自体も大型化しやすい。結果として1要求あたりのデコード時間、重みメモリ、GPU台数が増える。単にLlama系モデルをそのまま事後学習して推論能力を付与すると、この基礎的な推論コストを引き継ぐ。

一方、モデルを一様に縮小すると全層へ同じ削減を課すため、重要な層で品質が落ちやすい。Llama-Nemotronは「どの層をどの種類のブロックへ置き換えるか」を探索問題にし、ハードウェア上の効率制約を直接選択条件へ入れる。

## 手法

### Puzzleによる異種アーキテクチャ探索

まずLlama 3由来の各Transformerブロックについて、幅や計算構造の異なる代替候補を作る。各候補は元ブロックの入出力を教師として局所的に知識蒸留される。この段階ではモデル全体を候補ごとに再学習せず、層単位の置換可能部品を準備する。

次に候補ブロックごとの品質代理指標と、対象ハードウェアでのスループット・遅延・メモリ等のコストを組み合わせ、混合整数計画（mixed-integer programming; MIP）で層ごとのブロック選択を行う。出力は全層同形のTransformerではなく、層ごとに計算量が異なる異種モデルになる。これにより、品質への寄与が小さい場所で計算を強く削り、重要な場所へ容量を残せる。

### 蒸留と継続事前学習

探索後のアーキテクチャは、そのままでは元Llamaの能力を完全には保持しないため、知識蒸留と継続事前学習で回復させる。ここは学習工程だが、目的は探索で作った軽量アーキテクチャを実用的な推論モデルへ仕上げることにある。

### 推論重視の事後学習

その後、教師あり微調整と大規模強化学習で推論能力を付与する。通常チャットと推論モードを同一モデルで扱えるようにし、利用時に動的推論トグルで切り替える。簡単な要求では追加の推論tokenを抑え、難しい要求では計算量を増やすという、要求単位の交換条件を提供する。

## 評価条件

| 項目 | 条件 |
|---|---|
| モデル系列 | Nano 8B / Super 49B / Ultra 253B |
| 出発点 | Llama 3系列 |
| 構造最適化 | 層単位候補ブロック + Puzzle NAS |
| 最適化目標 | 品質と推論スループット・遅延・メモリ効率の交換条件 |
| 推論形態 | 通常チャット / reasoningを動的切替 |
| 比較の中心 | DeepSeek-R1等の推論モデル、対応するLlama系基準モデル |

## 主要結果

| 観点 | 論文の結果 | 読み取れること |
|---|---|---|
| 系列規模 | 8B / 49B / 253Bの3点を提供 | 単一サイズではなく配備資源に応じた選択が可能 |
| 推論効率 | 同世代の高能力推論モデルに対して高いthroughputとmemory efficiencyを報告 | アーキテクチャ探索を能力だけでなく実行効率へ結び付けている |
| 推論制御 | 標準応答とreasoningを推論時に切替可能 | 要求ごとに生成計算量を調整できる |
| 公開性 | モデル、事後学習データ、関連学習基盤を公開 | 再現・派生モデル作成に必要な資源を広く提供 |

論文の主張は、NASだけで推論能力が生まれるというものではない。構造探索で基礎推論コストを下げ、その後の蒸留・継続学習・事後学習で能力を回復・強化する一連の工程として評価する必要がある。

## 既存研究との差

DeepSeek-R1等の推論モデルは推論時の長い思考で高い能力を得るが、Llama-Nemotronはその前段としてモデル構造自体を推論効率向けに変える。通常の枝刈りが同一規則で層を削るのに対し、Puzzleは層ごとに候補ブロックを用意し、実機コストを含む制約下で異種構造を選ぶ。

また、推論モードを別モデルとして分離せず、同じモデルで通常応答とreasoningを切り替えられる点も、サービス側が要求ごとのコストを制御するうえで異なる。

## 限界

本報告はモデル系列の開発全体を扱うため、サービング・スケジューラ、鍵値キャッシュ（KV cache）、オフロード等のランタイム方式を新規提案する論文ではない。効率改善には大規模な蒸留・継続学習・事後学習が伴い、既存チェックポイントを無学習で軽量化する方式でもない。

動的推論トグルは生成token数を制御できる一方、どの要求でreasoningを有効化すべきかを自動判定するサービス側方策までは主題ではない。実サービスでの同時要求スループットや待ち行列遅延は、採用する推論ランタイムとハードウェアに依存する。
