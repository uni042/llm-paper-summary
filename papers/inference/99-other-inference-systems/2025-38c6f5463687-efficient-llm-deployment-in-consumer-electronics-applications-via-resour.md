# Efficient LLM Deployment in Consumer Electronics Applications via Resource-Aware and Salience-Guided Quantization

## 書誌情報と研究の位置づけ

PangらによるIEEE Transactions on Consumer Electronicsの論文である。2025年12月11日に電子公開され、2026年2月号（72巻1号、2122–2134ページ）に収録された。端末で大規模言語モデルを動かすときの、**量子化精度の配分**と**利用可能なメモリ・遅延制約**を同時に扱う。論文が提案するResource Awareness-Based Salience-Weighted Mixed-Precision Quantization（資源認識・重要度加重型混合精度量子化、RAS-MQ）は、推論サーバーの要求スケジューラでもGPUカーネルでもなく、端末に載せる重み表現を決めるオフライン量子化手順である。

## 概要

モバイル端末では他のアプリケーションや人工知能処理との競合により、利用できるRAMや計算能力が変動する。全層を一律2ビットへ下げるとモデルは小さくなるが、重要な重みの量子化誤差によって生成品質が悪化し得る。反対に要素ごとに例外的な高精度を記録すると、ビットマップや符号表、逆量子化の管理費用が増え、端末に載せる目的に反する。RAS-MQは、対象端末の資源制約を満たす層ごとのビット幅を先に計画し、層内では重要度の高い重み群へ1ビットを加え、低い群から1ビットを引くことで平均ビット幅を保つ。さらに重み群内の重要値を考慮した量子化範囲調整で誤差を減らす。

評価ではLLaMA2-13BをJetson Orin NX 16GB向けに2ビット量子化した場合、五つのゼロショット課題の平均正答率はRAS-MQ 57.21%、SqueezeLLM 56.36%、QuIP 56.03%、LLM-MQ 49.57%、AWQ 36.15%だった。RAS-MQは同条件の比較最良方式より**0.85パーセントポイント**高い。重み容量はFP16の24.5GBから4.1GBに縮小し、容量比は約5.98倍である。一方、同論文の速度改善は特定Jetson機種・量子化設定の結果であり、任意のスマートフォンや汎用GPUへの外挿はできない。

## 問題設定：端末制約と重み精度の衝突

量子化前のLLaMA2-13BはFP16重みだけで約24.5GBを要するため、16GB級の端末にそのまま載せられない。重みの容量だけでなく、埋め込み、正規化、キー・値（KV）キャッシュ、バッチ数、入力長、生成長に伴うメモリ消費も計画対象である。推論の初期入力処理（prefill）は計算能力に、逐次生成（decode）はメモリ帯域に影響されやすく、同じビット幅でも端末の演算性能と帯域の組合せによって遅延が変わる。

既存のGPTQ、AWQ、QuIPのような比較的一様なビット幅の方式は管理しやすいが、2ビット級では特定層・重みの誤差が大きくなる。LLM-MQは層の感度を使い、SqueezeLLMは重要値を別表現で保護するが、細かな要素単位の記録は量子化時メモリと端末側復元費用を押し上げる。RAS-MQの設計課題は、限られた平均ビット幅の範囲で「どの層に何ビットを与えるか」と「同一層のどの重み群を守るか」を分離して決めることである。

## 手法

### 1. 端末資源の見積もりと層別ビット幅選択

最初に対象端末の空きメモリ上限`Mmax`と許容遅延`Lmax`、浮動小数点演算能力、メモリ帯域、想定する入力長・バッチ数・生成長を取得する。モデル側では各層の重み行列、埋め込みと出力ヘッド、KVキャッシュを容量計算に入れる。埋め込みや正規化など精度保持が重要な部分は高精度のまま扱い、主に線形層の重みへ2、3、4ビットの選択肢を設ける。量子化で容量が下がってもKVキャッシュや他タスクの使用分が消えるわけではない点が重要である。

遅延は、入力の事前計算について層別演算回数を対象端末の演算性能で割り、逐次生成について推定メモリアクセス量を帯域で割る二段構成とする。さらに量子化ビット幅、代表的な入力長・バッチ条件での標本計測から回帰モデルを作り、単純な演算量・帯域モデルとの差を補う。これにより、同じ層を2ビットへ落としたときの容量と遅延の変化を機器ごとに予測する。

校正データの活性値から代理ヘッセ行列を構成し、重みを量子化した際の層別出力誤差を見積もる。整数線形計画（integer linear programming、ILP）では、各層のビット幅`b_i ∈ {2,3,4}`を選択変数とし、総メモリ`Σ M_i(b_i) ≤ Mmax`、総遅延`Σ T_i(b_i) ≤ Lmax`を満たしながら、層別量子化誤差の合計を小さくする。Gurobiで解くため、強化学習による何度もの量子化試行で方策を訓練する必要がない。ただしILPが最小化するのは代理誤差であって、最終課題の正答率を直接厳密最適化するわけではない。

### 2. 重み群の重要度に基づく高低ビット幅の相殺配分（BASWQ）

層の基準ビット幅が決まった後、各重み行列を128チャネル程度の群へ区切る。校正活性値から作ったヘッセ行列の逆行列を用い、個々の重みを量子化した場合の二次近似誤差`δ_{i,j}`を重要度の代理量とする。各群内の重要度を平均して順位付けし、高順位の群を`b_i+1`ビット、低順位の群を`b_i-1`ビット、中間群を`b_i`ビットへ割り当てる。

高ビット群と低ビット群を同数にする補償制約`|G_(b-1)| = |G_(b+1)|`を置き、群ごとの細かな保護をしても層の平均ビット幅が大きく増えないようにする。高重要度側と低重要度側から二つのポインタを中央へ動かす探索で、二乗誤差と量子化前後の出力方向を測る余弦類似度の対数損失を考慮する。ここで重要なのは**要素単位のビットマップを全重みに持つのではなく、群単位のビット幅指定で管理費用を抑える**ことである。群が粗過ぎると重要重みと非重要重みをまとめてしまい、細か過ぎるとメタデータと処理費用が増える。

### 3. 重要重みを考慮した量子化範囲の切り詰め（RCSWQ）

群内では平均と標準偏差から3σ則を用いて重要度の高い重みを区別するマスクを作り、重要値とそれ以外の値の量子化誤差を別々に計測する。重みの最大・最小値をそのまま整数表現の端点へ対応させると、少数の極端な値のために量子化刻みが広がり、多くの値の誤差が増えることがある。そこで範囲の上限・下限に係数`α`、`β`を掛けて量子化の尺度とゼロ点を調整する。

係数は`[1-λ, 1+λ]`の区間から探索し、重要値と非重要値それぞれの平均二乗誤差の合計を小さくする。論文の実験では`λ=0.1`、候補の分割数に関係する`x=100`を用いる。重要値だけをFP16で別保持する方式とは異なり、同一群内で共通の範囲係数を使いながら損失への影響を抑える。最後にGPTQ系の誤差補償を行って量子化済み重みを得る。この工程は重み量子化時のオフライン処理であり、各生成トークンにヘッセ行列の逆行列計算を繰り返すものではない。

### 4. 端末への配置と一要求の処理経路

処理の順序は、(a)端末の空きメモリ・演算資源を調べる、(b)モデル層とKVキャッシュの容量・遅延を予測する、(c)ILPで層別の許容ビット幅を決める、(d)群の重要度に応じてビット幅を相殺配分する、(e)範囲切り詰めと誤差補償で量子化済み重みを生成する、(f)その重みを端末へ配置する、となる。推論時には端末が量子化済み重みで通常の自己回帰生成を実行する。論文の測定では、量子化自体はA100搭載サーバーで行い、Jetson端末は主に推論の評価対象となる。端末上で重みの再量子化を瞬時に行う機構が実証されたわけではない。

## 既存研究との差

HAQやReLeQなど強化学習によるビット幅探索は、方策学習と反復評価に時間が掛かる。RAS-MQはメモリ・遅延を見積もってILPで層別配分を決めるため、**求解そのもの**を短縮する。ただし校正データ収集とヘッセ行列の計算には依然として数十分を要し、量子化作業全体が10秒で終わるわけではない。

AWQは活性値の外れ値に着目して重要チャネルを保護するが、RAS-MQは端末制約から層の平均ビット幅を決めた後に、ヘッセ近似の重要度を使って重み群ごとのビット幅を調整する。SqueezeLLMは重要な重みを疎な高精度行列として残すのに対し、RAS-MQは群単位の表現で要素単位の追加記録を抑える。両方式は同じ「重要値を守る」目的でも、重要値の格納形式と前処理メモリ負担が異なる。

## 限界・適用条件

本研究の評価対象はLLaMA2系とLLaMA-30B、Jetson二機種に限定される。近年の巨大な混合専門家モデル（MoE）や、多数のモデルが同時にロードされる汎用スマートフォンで同じ速度・精度が得られるとは確認されていない。端末の資源が動的に変わるという問題設定に対し、論文は制約条件に応じた量子化モデルを作る方法を示すが、生成途中の負荷変動に対して重みをその場で切り替えるオンライン再構成の性能は実証していない。

量子化処理はA100 80GBのサーバーで実施され、Jetson側では量子化済みモデルの推論を測る。したがって「端末単体で学習不要・瞬時に量子化可能」とは解釈できない。ILPのメモリ・遅延モデルは測定誤差を持ち、負荷が変化した場合には予測から逸脱する可能性がある。平均正答率の改善幅0.85ポイントは小さく、個別課題では比較手法が勝つ例もある。高圧縮下の品質維持と端末配置可能性は支持される一方、モデル一般の品質保証やKVキャッシュ量子化の改善を示す研究ではない。

また、重み群の重要度は校正データと代理ヘッセに依存する。校正分布と実運用の問い合わせ分布が異なると重要度順位が最適でなくなる可能性がある。小群化は精度を高めても、ビット幅メタデータ、実行カーネルの実装容易性、群間の復元費用との交換条件を伴う。著者の公式コード配布先は今回の一次資料から確認できず、既存量子化基盤へ即時組み込めると断定しない。
