# RetrievalAttention: Accelerating Long-Context LLM Inference via Vector Retrieval

## 概要

長文脈LLMの復号では、過去トークンの鍵値キャッシュ（KVキャッシュ）を保持して再計算を避けても、次トークンごとに過去の鍵を走査して注意重みを求めるため、文脈長に比例してメモリ容量と読出し時間が増える。RetrievalAttentionは、注意重みが少数トークンへ集中する動的疎性を利用し、全KVをGPUで走査する代わりに、CPU上の近似最近傍探索（Approximate Nearest Neighbor Search; ANNS）から現在の問い合わせに重要なKVだけを取得する学習不要方式である。

単純に既存ANNSを使うと、問い合わせとkeyが異なる射影行列から生成されるため分布外（Out-of-Distribution; OOD）になり、IVFでは高い再現率を得るのに約30%の鍵を走査する必要がある。RetrievalAttentionはプリフィル中の問い合わせとkeyの近傍関係を使って「問い合わせから見て近いkey」を反映した索引を構築し、1〜3%の鍵走査で高い再現率を狙う。GPUには常に重要になりやすい先頭トークンと直近windowを残し、CPU側の動的検索とGPU側の注意を並列実行して結果を結合する。

RTX 4090 24GB、128K文脈の8Bモデルでは1 トークン生成0.188秒を報告し、exact KNN検索比4.9倍、従来ANNS比1.98倍のデコード遅延短縮を達成する。∞-BenchではLlama-3-8Bの平均48.9〜49.6に対し全体 注意機構は50.4であり、長文脈品質をほぼ維持する。

## 問題設定

Llama-2-7BのFP16 KVは論文の例では100万トークンで約500GBに達し、A100 80GB 1枚には収まらない。CPUへ全KVをオフロードして毎段階必要量を転送するだけではPCIe帯域が律速になる。一方、実測では64K文脈でも注意出力を支配するトークンはごく少数で、top-36 トークンだけでも全体 注意機構出力に対する平均二乗誤差が10^-6未満になる例がある。

しかし重要トークンは問い合わせごとに変わるため、固定windowやプリフィル時に一度選んだトークンだけを保持する静的疎注意では取りこぼす。そこで各デコード 問い合わせごとに重要keyを検索する必要があるが、通常のベクトルDBは問い合わせと検索対象が同じ埋め込み分布にあることを暗黙に想定する。注意ではQとKが別射影なので、この仮定が崩れる。

## 手法

### query分布を反映する注意向けベクトル索引

プリフィル時には多数の問い合わせとkeyが既に得られる。RetrievalAttentionは各プリフィル 問い合わせについてexact k近傍keyを求め、Q→Kの接続を作る。これにより「key同士が近いか」ではなく「実際の問い合わせから同時に近いと見えるkeyは何か」という関係を収集する。

そのまま問い合わせ ノードを索引へ残すと容量と探索費が増えるため、cross-modal ANNSの射影手法を使い、同じ問い合わせから接続されたkey同士を結ぶK-only graphへ投影する。デコード時の問い合わせはこのgraphを辿ることで、OODの問い合わせ視点に合ったkey候補へ到達する。評価では1〜3%のkey走査で高い再取得を得て、IVF索引より検索遅延を74%削減する。

### GPU静的KVとCPU動的KVの分割

すべてをCPU検索へ回すと、常に重要なトークンまで毎回索引探索・CPU計算することになる。そこでプリフィルで観測できる静的patternとして先頭トークンと直近sliding windowをGPUへ常駐させ、それ以外の大部分をCPUメモリへ置く。

デコード 問い合わせごとにCPU側はANNSで動的重要KVを検索し、GPU側は常駐KVへ通常の注意を計算する。両集合は重ならないよう管理し、CPUとGPUで部分注意を並列計算する。

### 部分注意の結合

CPU側とGPU側で別々にsoftmaxを完結すると正規化分母が一致せず全体 注意機構の近似にならない。RetrievalAttentionは各側の部分的な指数和と重み付きvalue和を使い、共通のsoftmax正規化に相当する形で結果を結合する。これにより大量のCPU KVをGPUへ丸ごと転送せず、検索された部分だけで注意出力を近似できる。

## 既存研究との差

StreamingLLMやSnapKVは静的またはプリフィル由来の重要トークンをGPUに残すため、デコード中に重要度が変化するトークンを取りこぼし得る。InfLLMはブロック代表を使うが、RetrievalAttentionはトークンの内積検索を注意機構向け索引で高速化する。

通常ANNSとの差は索引構築にある。key同士の幾何だけでgraphを作らず、プリフィル 問い合わせがどのkeyを近傍と見るかを介してkey graphを作るため、Q/K分布ずれを索引設計へ直接取り込む。

## 限界

論文は長文脈プロンプトのプリフィルが事前に完了している状況を主対象にし、主性能評価はsingle-バッチである。多数リクエストの連続バッチ、CPU側索引を複数tenantで共有した際の競合、索引構築のproduction運用費は主要評価軸ではない。

精度は取得するkey数に依存し、複雑なKV 検索ではtop-100だけでは全体 注意機構との差が残るためtop-2000も評価している。CPU DRAM容量と検索性能にも依存し、CPUが遅い、PCIe/メモリ帯域が競合する環境では利得が縮む。
