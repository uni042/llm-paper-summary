# Block Pruning For Faster Transformers

## 書誌と概要

本論文はFrançois Lagunas、Ella Charlaix、Victor Sanh、Alexander M. Rushによる2021年の構造化枝刈り研究である。対象はBERTとBARTを中心とする事前学習済みTransformerであり、現在の巨大な自己回帰LLMへ直接実測した研究ではない。論文の貢献は、重みを不規則に零にするだけでは通常のGPUで速くならないという問題に対し、微調整中にブロック単位の重みを消す学習を導入し、最終的に小さな密行列や削除可能な注意ヘッドへ変換する点にある。

元の移動量に基づく枝刈り（movement pruning）は、タスク損失に加えて重みの重要度スコアを学習し、不要な重みを零にする。BERTのSQuADでは約94%の重みを除いてF1を87.5程度に維持できるが、不規則な零を含む大きな行列を通常の密行列演算で実行しても大きな高速化にはならない。一方、知識蒸留で得た小型モデルは密な行列の形状自体が小さく速いが、精度を維持したままパラメータを最大限減らせるとは限らない。

Block Pruningは各行列を固定形状の小ブロックに分割し、ブロック単位の学習スコアで有効・無効を決める。フィードフォワード層（FFN）では中間次元を丸ごと削除し、注意機構では32×32ブロックの学習が注意ヘッド全体の削除へつながる性質を利用する。SQuAD v1.1ではBERT比約2.4倍の実行速度で、F1を約1点低下させたモデルが得られ、BART-largeの要約では復号器の重みを約3.5倍圧縮し、約1.39倍の高速化を報告する。どちらも指定タスク・指定GPUでの結果であり、重み圧縮倍率がそのまま生成速度倍率になるわけではない。

## 問題設定：パラメータ疎性と実機高速化のずれ

TransformerのFFNは、隠れ次元から大きな中間次元へ広げる行列W1と、元の次元へ戻す行列W2を持つ。注意機構はQ、K、V、出力の各射影行列を持ち、複数ヘッドの演算をまとめて実行する。標準的なGPU行列積は、規則的な密行列の連続領域をまとめて読み、並列に計算することを前提とする。重みの九割を零にしても、非零位置がばらばらなら、標準演算は元の行列の大きさを保ったまま計算し、期待した時間削減が得られない。

非構造化枝刈りはどの重みを消すかの自由度が高く、精度を保ったまま高い疎化率を得やすい。一方、行・列・ヘッドを丸ごと消す構造化枝刈りは実行形状を縮めやすいが、重要な重みをまとめて失う危険がある。Block Pruningは、削除単位を小ブロックから大きな機能単位まで選べるようにして、学習の自由度と実行時の規則性の中間を狙う。

本論文が区別する三つの数値は、零にした重みの割合、圧縮後の線形層パラメータ数、実機で測った推論時間である。零の割合が大きくても、実際に小さな行列へ詰め直せなければ速度は上がらない。逆に、注意ヘッドやFFN次元を物理的に消せれば、特殊な疎行列カーネルなしで標準の密行列演算を利用できる。どの構造を消せるかが速度へ直結する。

## 手法

### ブロック共有スコアの学習

各重み行列WをM×Nとし、ブロック形状をM'×N'とする。Block Pruningは各ブロックに一つのスコアSを割り当て、スコアが閾値を超えたブロックの重みだけを残す。個々の重みに別スコアを持たせる非構造化方式と異なり、同じブロック内の重みは一緒に削除される。論文の式では、行列要素W(i,j)へ対応するブロックスコアの二値マスクを掛ける。これにより学習時のスコア勾配がブロック単位の削除判断へ集約される。

タスク損失とスコアの疎性正則化を同時最適化する。正則化はシグモイド変換したスコアの総和を減らす形であり、スコアを小さくしてブロックを消す方向へ圧力をかける。二値マスクは通常の微分が難しいため、直通推定（straight-through estimator）で勾配を近似する。教師モデルの出力に合わせる蒸留も併用するため、単に重みを切るだけではなく、微調整の中で残った構造へ知識を移す。

FFNと注意機構はパラメータ量やスコア勾配の性質が異なる。著者は注意用とFFN用の正則化係数を別々に設け、両者を同じ強さで一律に削らない。実験では注意射影に共通のブロック形状を使い、FFNの二行列にも共通の規則を与える。ブロック形状を行列ごとに無制限探索するのではなく、代表的な候補へ制限して設計空間を小さくしている。

### ブロック形状とGPUでの実行可能性

論文は4×4から32×32の正方形ブロックを比較し、主な注意設定に32×32を使う。GPUではある程度まとまった連続領域を計算するほうが効率的であり、論文は16×16程度以上のブロックが適切なカーネルで扱いやすいと説明する。しかし大きなブロックは削除判断が粗く、必要な重みを巻き込むため精度を落としやすい。小さなブロックは精度を守りやすいが、非零の断片が残って実行形状を縮めにくい。

別の候補として、FFNの中間次元に対応する行と列を対で消す次元単位の枝刈り、および注意ヘッド全体を単位とする枝刈りを比較する。これらは単なる疎行列ではなく、行列の実際の行数・列数を減らす設計である。論文は、ブロックの細かさを選ぶこと自体が精度と速度の交換条件を制御すると位置付ける。

### FFNの次元削除とHybrid構成

FFNのW1である中間次元への出力列と、W2で同じ中間次元を入力として使う行は対になっている。片方だけを零にしても計算形状は残るが、対応する行・列を一緒に消せば、中間次元そのものを削除して小さな密行列へ変換できる。Hybrid方式はFFNでこの次元単位の枝刈りを使い、注意射影では32×32ブロックの枝刈りを使う。両者を組み合わせるのは、FFNと注意では高速化に利用できる削除単位が異なるからである。

注意射影の行や列を無秩序に削ると、Q/K/V/Oのヘッド分割・再整形の費用がかえって増える。論文は注意の小ブロックを学習させた結果、明示的にヘッド単位で消すよう制約していなくても、あるヘッドに属するブロックがまとまって零となり、ヘッド全体を削除できることを観測する。これが単なる重み圧縮を超えて実行速度へ結び付く理由である。

### Hybrid Filledと精度回復

注意ヘッドの一部だけが零になっても、そのヘッドが残るなら実行形状は小さくならない。Hybrid Filledは、削除できずに残るヘッド内の零重みを再初期化し、縮小後のモデルをさらに微調整する。最終的に必要なヘッド数は増やさず、残す必要がある部分の表現力を回復する。これにより、速度を保ちながら精度を改善できる場合がある。

著者は初回の枝刈りで生き残るヘッドを特定し、元の事前学習済み重みから再学習する巻き戻しも検討した。しかし顕著な差が見られず、主要結果は巻き戻しを使わない。Hybrid Filledが常に最良というより、速度・圧縮率・精度の間でどの点を選ぶかを広げる設計と解釈するべきである。

### 学習と推論の実行順序

実際の手順は、事前学習済みBERT/BARTを取得し、ブロックスコアと重みをタスク別に微調整しながら疎性正則化と教師蒸留を適用する。学習後に閾値でブロックを確定し、削除可能なFFN次元と注意ヘッドを検出して物理的に取り除く。必要ならHybrid Filledで残存ヘッド内の重みを再学習する。最後に小さな密行列を持つモデルとして推論する。学習中に存在するマスクと、推論時の縮小済みモデルの形状を区別する必要がある。

### SQuAD v1.1：速度とF1の交換条件

論文の表2はBERT-baseを速度1.00、線形層パラメータ85M、F1=88.5、完全一致80.8として比較する。Hybrid Filledは線形層21Mで圧縮率3.94、速度2.25倍、F1=87.7、完全一致80.2を示す。これはBERT-baseのF1から0.8点の低下であり、速度の改善と品質の小さな損失が共存する代表例である。同方式の16M設定では圧縮率5.17、速度2.69倍、F1=86.8へ下がる。より強い枝刈りほど品質が悪化することを示す。

| 方式 | 線形層規模 | 速度（BERT-base比） | SQuAD F1 | 完全一致 |
|---|---:|---:|---:|---:|
| BERT-base | 85M | 1.00倍 | 88.5 | 80.8 |
| TinyBERT | 42M | 1.88倍 | 87.5 | 79.7 |
| DistilBERT | 42M | 2.06倍 | 86.9 | 79.1 |
| Hybrid Filled | 30M | 1.84倍 | 88.7 | 81.7 |
| Hybrid Filled | 21M | 2.25倍 | 87.7 | 80.2 |
| Hybrid Filled | 16M | 2.69倍 | 86.8 | 78.8 |
| Hybrid | 15M | 2.26倍 | 87.15 | 79.4 |
| Struct | 14M | 3.36倍 | 85.9 | 78.0 |

上表の速度とF1は同じ設定点での組であり、各列の最良値を合成した架空のモデルではない。Structの3.36倍は速いがF1=85.9まで低下しており、Hybrid Filledの2.25倍・F1=87.7と同じ品質条件ではない。元論文の「約2.4倍でF1低下約1点」は全条件の代表的なまとめであり、表2の個別設定点とは分けて扱う必要がある。

### タスクを変えたときの品質

表3はTinyBERTとHybridの近い速度の構成を比較する。SQuAD v1.1ではTinyBERTのF1/完全一致が87.5/79.7に対しHybridは88.1/80.6、MNLIの二つの評価はTinyBERTが84.6/83.2に対しHybridが83.2/83.6、QQPのF1は88.0対87.9、SST-2の精度は93.0対91.2である。HybridはSQuADで優れるが、すべてのタスクで蒸留モデルを上回るわけではない。論文は速度が少なくともTinyBERT並みとなる構成を比較している。

大きい教師モデルを使ったHybrid Filled LTでは、SQuADで38M・1.56倍・F1=90.3、20M・2.31倍・F1=88.3などの結果を報告する。大きな教師は高い疎化率まで有利だが、約80%を超える強い枝刈りでは、かえって品質が不利になる場合も観測される。教師が大きければどんな圧縮率でも品質が高くなる、という単純な関係ではない。

### BARTの生成・要約

エンコーダとデコーダを持つBARTでは、デコーダの計算が大きな費用を占める。著者は同じ正則化を両側へ与えるとエンコーダのほうが強く削られると観測し、デコーダ側の圧縮を重視するよう正則化の比率を調整する。BART-largeでは復号器の線形層を約3.5倍圧縮し、約1.39倍の速度を報告する。ROUGE-1/2/Lは基準44.8/21.7/41.8に対し、強い圧縮点で42.7/19.6/39.9へ低下する。生成速度だけでなく要約品質も同時に確認する必要がある。

BART-largeの別の設定では復号器108M、圧縮率2.8、速度1.38倍、ROUGE-1/2/L=43.5/20.3/40.6となる。圧縮率を3.5へ高めても速度は1.39倍とほぼ変わらず、品質はさらに下がる。これはパラメータ削減が常に比例的な速度改善を生むわけではないことを示す負の結果である。比較対象のdBARTは層を減らす蒸留系であり、圧縮の構造と訓練費用が異なる。

### 学習費用と実行速度の制約

著者はSQuAD v1.1で通常2エポック程度のBERT微調整に対し、枝刈りを徐々に進めるため20エポックを使用した。学習時間は標準の約45分から約12時間へ増えると報告する。推論を繰り返す用途なら長期的に回収可能という議論はあるが、どの要求量で損益分岐するかの実測は別問題である。枝刈りの学習費用を無視して単に「省エネルギー」と断定してはいけない。

線形層パラメータの圧縮倍率は、演算量の上限的な目安になるが、測定速度はそれより小さいことが多い。残る演算、GPU起動費、メモリアクセス、バッチ形成が影響する。論文は専用実装でさらに速度を伸ばせる可能性を論じるが、報告した実測倍率と未実装の可能性を混同しない。

## 既存研究との差

Movement Pruningは微調整中の重要度スコアで個別重みを消し、非常に高い疎化率を得る。しかし標準GPUの密行列積は不規則な零を飛ばせないため、実速度があまり上がらない。Block Pruningはスコアをブロック単位に共有し、FFN次元と注意ヘッドという物理的に削除できる構造へ疎性を寄せる。したがって主な違いは「どれだけ零を作るか」ではなく「実行形状をどう縮めるか」にある。

DistilBERT、TinyBERT、MobileBERTなどの蒸留系は、あらかじめ小さな密モデルを設計して教師の出力へ合わせる。Block Pruningは事前に最終構造を細かく決める代わりに、ブロック形状を指定して学習の中で削除可能な部分を選ぶ。両者は排他的ではなく、蒸留を枝刈り学習へ併用することもできる。Hybrid Filledの再初期化は、削除不能な残存ヘッド内の表現力を回復するための追加工夫である。

## 限界・適用範囲

第一に、主な評価はBERTとBARTの比較的小さいTransformerであり、現在の数十億～数千億パラメータの自己回帰LLMにそのまま速度倍率を移せない。特に長文脈のKVキャッシュ、混合専門家の重み転送、分散GPU通信などはこの論文の主な評価対象ではない。対象を「Transformer推論の構造化圧縮」として位置付けるべきである。

第二に、枝刈りはタスク別の微調整を必要とする。20エポック、約12時間という学習費用は標準の微調整より大きく、用途ごとにモデルを作り直す場合の費用が問題になる。蒸留用の教師も必要であり、既存モデルを何も学習せず即座に圧縮する手法ではない。

第三に、ブロックが大きいほど計算効率を高めやすいが、必要な重みをまとめて消して精度を落とす危険がある。小さなブロックでは圧縮しても実行形状が残り、速度が伸びにくい。Structの高い速度と低いF1、BARTで圧縮率を増しても速度がほとんど伸びない条件は、この交換条件を示している。

第四に、速度測定はRTX 3090とバッチ128という特定環境で行われた。低バッチや異なるGPU世代、CPU単独、別のランタイムでは速度が変わり得る。線形層パラメータの削減率を、全モデルのメモリ占有やトークン生成速度と同一視してはいけない。論文の成果は、実行可能な構造へ疎性を誘導する原理と、その指定環境での実測証拠にある。
