# Block Pruning For Faster Transformers

## 概要
Block Pruningは、事前学習済みTransformerをタスク微調整しながら、重みを1個ずつではなく**局所ブロック、FFN次元、注意頭**のような構造単位で削る枝刈り法である。非構造化枝刈りは高い疎性を作れても、通常のGPU/CPUでは疎な行列を元の密形状へ戻すなどして実行するため、パラメータ削減が実速度へ結び付きにくい。逆に蒸留モデルは密な小型行列なので速いが、同等精度で必ずしも最小ではない。

本手法はMovement Pruningをブロック単位へ拡張し、学習可能なスコアをブロック内の全重みに共有する。特にFFNでは行・列を対応して削って物理的に中間次元を縮小し、注意では32×32程度の小ブロックから始めても学習結果が注意頭全体を空にする傾向を利用して、実際に頭を削除する。SQuAD v1.1ではBERTを約74%小さくし、F1低下約1点で2.4倍高速、CNN/DailyMailではBART decoderを3.5倍圧縮し約1.39倍高速化する。

## 問題設定
Movement Pruningは各重みのスコア (S) を学習し、閾値以下をマスクする。BERTのSQuAD v1.1では約94%を枝刈りしてF1 87.5（元BERT 88.5）まで保てるが、重みが不規則に残るため標準的な密行列積では速度利得が小さい。必要なのは、精度をなるべく保ちながら、実装が**小さい密行列として実行できる形**へ疎性を集約することである。

ただし構造単位を大きくしすぎると、必要な重みまでまとめて消して精度が悪化する。小さすぎれば精度は保ちやすいが、ハードウェアが高速に利用できる規則性が不足する。Block Pruningはブロック形状をこの精度・速度交換条件の制御変数にする。

## 手法
### ブロックMovement Pruning
各重み行列 (Winmathbb{R}^{M	imes N}) を固定形状 ((M_0,N_0)) のブロックへ分割し、ブロックごとに1個の学習スコアを持つ。閾値を超えるブロックだけを有効にし、元のMovement Pruningと同様にタスク損失と疎性正則化を同時最適化する。注意行列群とFFN行列群では勾配規模・パラメータ量が違うため、正則化係数を (lambda_{att}) と (lambda_{ffn}) に分ける。

論文はGPUで少なくとも16×16程度のブロックが扱いやすいことを背景に、4×4〜32×32を比較する。注意の主設定には32×32を用いる。ブロックが大きいほど実行効率は上がりやすいが、削除判断が粗くなるため品質リスクが増える。

### Hybrid: FFN次元と注意ブロックを別構造で削る
FFNの2行列 (W_1,W_2) は、同じ中間ニューロンに対応する列・行を対にして削る。最終的に空になった次元を物理的に除去し、残った行列を再び完全な密行列へ詰め直せる。これにより標準密行列演算で中間幅削減を直接速度へ変えられる。

注意では任意の行・列だけを削るとQ/K/V/O投影の再整形コストが大きく、速度へ利用しにくい。そこで32×32ブロックで徐々に疎化する。興味深いことに、明示的に頭単位だけを指定しなくても、学習後には複数ブロックが揃って0となり、注意頭全体が削除可能になる。HybridはFFNの次元削除とこの注意ブロック削除を組み合わせる。

### Hybrid Filled
ブロック枝刈り後に、完全には空にならず速度短縮へ寄与しない注意頭内の0重みは、そのまま残しても実行形状を小さくできない。Hybrid Filledは「どうせ残す必要がある頭」内の0重みを再初期化し、縮小済みモデルを追加微調整する。実行形状は変えず利用可能なパラメータを戻すため、速度を犠牲にせず精度を回復する。巻き戻し (rewinding) も比較したが有意差が小さく、主要結果は巻き戻しなしで報告される。

## 主要結果
SQuAD v1.1では、同程度のF1 87.5付近でHybrid Filledは約2.5倍高速となり、TinyBERTの約1.88倍より速い。TinyBERT/DistilBERTはBERTのencoderパラメータを約50%保持するのに対し、Hybrid Filledは同等精度で約25%まで縮小する。論文要旨ではF1低下約1点の点で2.4倍高速・74%小型化と要約される。単純Movement Pruningはパラメータ自体は強く減らせても、規則的な空次元・空頭が少なく、速度ではHybridに劣る。

BERT-largeをSQuAD v1.1でHybrid枝刈りした評価では、元227M線形パラメータ、F1 93.2、速度1.0に対し、54MでF1 91.0・2.9倍、41MでF1 90.2・3.2倍となる。大モデルから強く削った41Mモデルは、BERT-baseより小さい線形パラメータ数でありながらBERT-baseのF1 88.5を上回る。これは同じ最終サイズなら大きい教師的初期モデルから削る方が有利になり得ることを示す。

ブロックサイズの感度ではSQuAD v1.1で4×4〜32×32を比較し、F1低下なしでは32×32でも最大約1.3倍、F1を2%許すと32×32で約1.75倍になる。16程度から速度改善が飽和する傾向があり、「大ブロックほど常に速くて良い」わけではなく、品質と実行効率の妥協が必要である。

BART-largeのCNN/DailyMailでは、decoder側を重点的に削るHybrid NTで線形パラメータを353M→82M、decoder圧縮率3.5倍、速度1.39倍とし、ROUGE-1/2/Lを44.8/21.7/41.8から42.7/19.6/39.9へ落とす。decoder重みの削減倍率ほど実速度が伸びないのは、枝刈り対象外の演算、encoder、メモリ・カーネル費用が残るためである。dBARTは同程度の速度を別の層削減で得られるが、Hybridはより高いパラメータ圧縮を狙う。

## 既存研究との差
非構造化Movement Pruningは最小パラメータを狙えるが通常ハードウェアで利用しにくい。頭・FFN幅をあらかじめ固定比率で削る構造化枝刈りは高速化しやすいが、探索自由度が低い。Block Pruningは局所ブロック単位の学習可能なマスクから始め、結果として空FFN次元・空注意頭が現れるようにし、精度と実行構造の間を連続的に探索する。

## 限界
枝刈りはタスク固有微調整と同時に行うため、1個の汎用チェックポイントを無学習で圧縮する方式ではない。SQuADでは20 epoch・約12時間と通常微調整より大幅に長く、推論を多数回行うことで初めて訓練費を償却する設計である。速度測定はRTX 3090、batch 128という特定環境で、他GPU・低batch・現代の推論エンジンでは倍率が変わる。ブロックが空になっても物理的な次元・頭削除へ変換できなければ速度利得は得られず、単純な疎性率を実速度として解釈できない。生成モデルではdecoder圧縮3.5倍に対し速度約1.39倍に留まり、Amdahl則的な非枝刈り部分の制約も明確である。
