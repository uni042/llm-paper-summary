# Understanding the Potential of FPGA-Based Spatial Acceleration for Large Language Model Inference

## 概要

大規模言語モデルの推論を再構成可能な論理回路（FPGA）へ載せる従来方式の多くは、同じ演算器を複数の演算子・層へ順番に割り当てる時間多重型である。この方式は異なるモデルへ柔軟に適用できるが、演算子の切替時に中間テンソルを外部メモリへ戻して読み直すため、低バッチ・低遅延の推論では通信費用が支配的になり得る。

本論文は、問い合わせ・鍵・値の射影、注意、前向き層などへ専用処理要素を配置し、先行演算の出力を次の演算へ直接流す空間型データフローを検討する。演算量だけでなく、FPGAの乗算器、オンチップメモリ容量、読書きポート、外部メモリ帯域、複数FPGA間の通信を解析するモデルを構築し、再利用可能な高位合成カーネルで実装を検証した。

AMD Alveo U280上のGPT-2では、同じFPGAのDFXに対してプリフィル2.16倍、復号1.10倍の高速化を報告する。復号はNVIDIA A100比で1.85倍高速、エネルギー効率5.69倍だった。一方、プリフィルではGPUの方が有利である。これはFPGAが常にGPUを上回るという結果ではなく、演算器を十分に埋められない小バッチ復号で空間型が有利になる条件を示した研究である。

## 問題設定と設計上の対立

時間多重型のFPGAオーバーレイは、共通の処理要素を命令や制御によって複数の層へ使い回す。ビットストリームの再利用と短い設計期間が利点だが、ある演算子の全出力を外部メモリへ書き、次の演算子で再読込みする場合、低遅延推論での費用が大きい。空間型では演算子ごとに異なる回路を作り、先行段から少量の中間値が届いた時点で次段を動かす。これにより回路間通信をオンチップのFIFOや多重バッファへ寄せ、パイプラインを重ねられる。

ただしFPGAの乗算器、論理素子、ブロックRAM、超大容量RAMは有限である。全層を完全展開すれば資源不足になるため、演算器数、並列度、ビット幅、オンチップ保持範囲を決めなければならない。入力を一括処理するプリフィルは行列・行列積の並列性が高いが、1トークンずつ生成する復号は行列・ベクトル積に近く、演算器を多数並べても利用率が上がらない。両段階の性質を分けて評価する必要がある。

## 手法

### 演算量と資源制約の解析モデル

著者らはTransformerの問い合わせ・鍵・値射影、注意の二つの行列積、出力射影、前向き層の二つの線形変換について、積和演算数を求める。プリフィルでは入力長lに対して射影が概ね `l d²`、注意が `l² d` に比例する。復号では射影が `d²`、注意は過去長に応じた項となる。演算器数を増やすと理論計算時間は減るが、同時に必要な乗算器、メモリ読出しポート、バッファ容量が増える。

計算資源については各演算子へ割り当てる一サイクル当たりの積和数を合計し、FPGA全体の上限以内に収める。オンチップメモリは重みのタイル、鍵・値キャッシュ、演算子間FIFOを含む。重みがオンチップへ収まらない場合は外部メモリからタイル単位で読み、二重バッファで次の重みの転送を現在の計算と重ねる。ポート数が足りない場合はバッファ分割やビット幅を詰める配置を使い、読出し競合を避ける。

この解析では演算数だけから速度を推測せず、どの演算子が律速となり、どこに計算資源を追加しても効果が薄いかを判断する。モデルの幅、入力長、量子化、外部帯域、演算器の周波数によって最適設計は変わる。複数FPGAへ拡張する場合はテンソル並列やパイプライン並列の通信も計上し、台数増加による計算分割と集団通信の費用を比較する。

### 専用処理要素と直接ストリーミング

空間型の回路では、射影行列積、注意のスコア計算、正規化、前向き層などを個別の処理要素として配置し、FIFOで直結する。先行段が入力の一部を計算し終えれば、全テンソルが完成する前に後段を開始できる。中間値を外部DRAMへ書き戻す回数を減らすことが、単なる演算数削減とは異なる主要な利得となる。

注意で必要な鍵・値は二重バッファを使い、残差接続に必要な一部の活性値は専用のバッファで保持する。モデルの埋め込みや最終サンプリングは不規則なメモリアクセスが多く、全体演算の比率も小さいため、原著はFPGAの中心的な高速化対象から外し、CPU/GPUで扱う方針を取る。つまり実装対象は主にTransformerブロックであり、全ての前後処理を同じFPGAへ統合した結果ではない。

### 再利用可能な高位合成カーネル

行列積、ソフトマックス、正規化、活性化関数などを高位合成（HLS）の部品として実装する。線形演算ではシストリック配列を使い、重みと活性値のビット幅に合わせて乗算器へ複数の演算を詰める。たとえば4ビット重みと8ビット活性値の組合せでは、適切にビット位置を分けて一つのDSPで二つの積を処理できる。非線形演算は数値精度を保つため浮動小数点で処理し、先行する線形演算とのパイプライン重畳で遅延を隠す。

Alveo U280は三つの論理領域に分かれているため、領域をまたぐ信号配線とタイミング制約も考慮する。著者らは問い合わせ・鍵・値射影、注意・出力射影、前向き層を各領域へ分配した。大きなシストリック配列ではタイミングが閉じず、小さな配列を組み合わせるなど、解析上の演算器数だけでは決まらない実装制約も報告している。

資源制約の評価では、単に演算器を増やすだけでなく、各演算器が必要とする重みの供給帯域とメモリポート数を確認する必要がある。多くの演算器が同じブロックRAMの読出し口を奪い合えば、演算器の理論性能は実行速度へ反映されない。重みを複数のバンクへ分けるか、ビット幅を詰めて一度の読出しで複数の値を取り出すかを選ぶことになる。著者らの解析モデルはこのような物理的な制約を組み込み、単純な浮動小数点演算数だけからは見えない設計の限界を示す。

## 評価条件と主要結果

| 項目 | 原著の条件 | 留意点 |
|---|---|---|
| FPGA | AMD Alveo U280、3論理領域、実機周波数約245MHz | 一つの専用ビットストリームに対応する設計点 |
| 実装 | Vitis HLS 2022.1、Vivado、XRT、OpenCL | 解析モデルと実装を照合 |
| モデル | BERTとGPT-2 | 現代の数十B級LLMの実機測定ではない |
| 量子化 | BERTはW4A8、GPT-2はW8A8 | GPU比較では最速のFP16結果を使用 |
| 測定 | 各遅延は50回の平均 | 実機での推論と電力計測 |
| 比較 | FPGAのFQ-BERT、TRAC、DFX、GPUのA100 | 同一FPGA比較と異なるデバイス比較を分ける |

| 評価 | 比較対象・条件 | 原著の結果 | 解釈 |
|---|---|---|---|
| BERT、入力長512、U280 | 実装の遅延 | 26.01ms、解析予測24.07ms | 解析と実測の差は約2ms |
| BERT、入力長512 | FQ-BERT / TRAC | 3.66倍 / 13.36倍高速 | 比較元の別FPGA・入力長128を512へ換算 |
| BERT、CoLA | FP16 / W4A8 | 正解率56.84% / 56.76% | この課題では量子化の低下は小さい |
| GPT-2、U280 | DFXのプリフィル / 復号 | 2.16倍 / 1.10倍高速 | 同じFPGAの時間型オーバーレイとの比較 |
| GPT-2の復号 | NVIDIA A100 | 1.85倍高速、エネルギー効率5.69倍 | 小バッチ復号の条件付き比較 |
| GPT-2、LAMBADA | FP16 / W8A8 | 正解率65.0% / 62.2% | GPT-2の量子化には品質代償がある |

BERTの最大13.4倍は、原著の本文表ではTRACに対する13.36倍を丸めた値である。本文で実装対象の別の設計値としてより大きな倍率が言及される場合もあるが、異なる条件を同一の比較として扱わない。FQ-BERTとTRACは同じU280ではなく、入力長も原著から換算しているため、完全に同条件の実機比較ではない。

GPT-2のプリフィルでは、GPUは多くの演算器を使って長い入力を並列処理でき、FPGAの相対的な利点は小さい。復号では一度に一トークンを生成するため、GPUの高い並列計算能力を使い切れず、FPGAの直接ストリーミングが有利になる。原著のA100比1.85倍、エネルギー効率5.69倍はこの復号条件の結果であり、入力処理を含む全リクエストの速度・電力量が同じ倍率で改善するとは限らない。

解析モデルはプリフィル遅延を比較的正確に予測したが、復号では演算子間の起動間隔などの固定費が予測を上回る場合があった。したがって演算量とメモリ帯域の見積りだけでは、実際のパイプラインの全遅延を完全には再現できない。高位合成カーネルの構成要素除去では、演算器数を維持しながらDSPの詰込みで資源を節約できることや、ソフトマックスの遅延が他の演算と重なることを確認している。

## 既存方式との差

DFXなどの時間多重型オーバーレイはビットストリームの再利用とモデル変更の柔軟性を優先する。空間型はモデル固有の演算子を回路上へ配置し、FIFOで直接つないで中間値の外部メモリ往復を削減する。本研究は特定の一つの高速回路だけでなく、計算資源、オンチップメモリ、読出しポート、外部帯域、分散通信の制約を合わせた解析モデルと、再利用可能なHLS部品を提示した点に特徴がある。

## 限界

FPGAのオンチップ資源は有限であり、モデルの全層・全演算を完全展開することは大規模モデルでは難しい。複数FPGAへ分割すれば計算負担は減るが、デバイス間の通信と配線の制約が増える。モデル固有化は時間型オーバーレイより設計・配置配線に時間がかかり、頻繁にモデルを入れ替えるサービスでは柔軟性が下がる。

実機評価はBERTとGPT-2、Alveo U280、主として単一バッチであり、連続バッチ、最新の注意カーネル、GQA/MQA、MoE、数十B級モデルへ倍率をそのまま外挿できない。GPT-2のW8A8量子化はLAMBADAの正解率を65.0%から62.2%へ下げており、推論速度だけを見て品質が無損失だと考えてはいけない。プリフィルではGPUが有利であるため、FPGAが全ての推論段階で優位という結論も誤りである。
