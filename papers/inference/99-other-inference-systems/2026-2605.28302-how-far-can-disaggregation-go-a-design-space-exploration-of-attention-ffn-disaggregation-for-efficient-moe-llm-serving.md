# How Far Can Disaggregation Go? A Design-Space Exploration of Attention-FFN Disaggregation for Efficient MoE LLM Serving

> 注意とMoE-FFNの演算・通信を別GPU群へ分離する価値を、負荷・モデル・SLO・ネットワークを横断して設計空間探索する。
## 書誌情報
- **著者**: Hanjiang Wu, Abhimanyu Rajeshkumar Bambhaniya, Sarbartha Banerjee, Tuhin Khare, Sudarshan Srinivasan, Suvinay Subramanian, Souvik Kundu, Madhu Kumar, Midhilesh Elavazhagan, William Won, Amir Yazdanbakhsh, Tushar Krishna
- **公開**: arXiv:2605.28302
- **種別**: arXiv preprint
- **対象**: MoE提供、注意FFN分離、事前充填復号分離、設計空間探索、GPU配置、通信シミュレーション
- **実装**: AIC++はAIConfiguratorのGPU計算モデルをAstraSim通信シミュレーションで拡張し、vLLMベースAFD試作で全対全の注意・FFN通信経路を検証する。
## 概要
本論文は、MoE推論で事前充填・復号分離より細かく注意機構と専門家FFNを別GPU群へ分離する方式が、どの負荷・モデル・通信網で有利かを体系的に探索する。GPUカーネル実測を用いるAIConfiguratorとパケット粒度通信シミュレータAstraSimを統合したAIC++で、並列化、事前充填・復号分離、注意・FFN分離、GPU配置を同時探索する。128枚B200上のDeepSeek-V3.2では厳しい遅延SLO下で非AFD方式が実行不能な条件でも約4千トークン/sを維持する一方、純粋な総処理量ではAFDが常に最良ではないことも示す。

本研究は特定AFD構成を一つ提案するより、データ・系列・テンソル・パイプライン・専門家並列、事前充填・復号分離、注意・FFN分離を同じ探索空間へ入れ、計算と通信を一体評価する。AIConfiguratorの実測GPU費用モデルを注意部とFFN部へ分割し、AstraSimの階層通信網へ接続することで、各候補の演算時間だけでなくAFD固有のfan-out dispatch、fan-in combine、競合、配置を評価する。結果から負荷・モデルごとの具体的な注意GPU対FFN GPU比を導き、AFDが厳しい遅延SLOでは不可欠だが最大総処理量では不要な場合も多いという境界を明示する。

代表結果として、厳格SLO下システム処理量はDeepSeek-V3.2、128 B200、Chat/Coding/Agentic Codingの厳格TTFT/TPOTで非AFDは実行可能構成なしに対して約4,000 トークン/s。演算律速FFNとメモリ律速注意を別GPU比率へできることが遅延制約を満たす。
## 問題設定
大規模MoEモデルでは注意機構が鍵値キャッシュ読み出し中心でメモリ帯域律速、専門家FFNは大きな行列積中心で演算律速となり、同じGPU群へ固定すると互いに異なる資源要求を同じ構成で満たす必要がある。事前充填と復号を別GPUへ分けてもモデル内部のこの異質性は残る。注意とFFNをさらに別GPU群へ分離すれば適材適所化できるが、各変換器層で注意から専門家へのdispatchと結果combineが発生し、分離を細かくするほど通信量と配置選択肢が増える。さらに最適解は入力長、出力長、共有prefix、SLO、注意方式、専門家数、GPU数、NVLinkとInfiniBand配置によって変わるため、AFDが常に良いかという単純な比較では決められない。
## 新規性
本研究は特定AFD構成を一つ提案するより、データ・系列・テンソル・パイプライン・専門家並列、事前充填・復号分離、注意・FFN分離を同じ探索空間へ入れ、計算と通信を一体評価する。AIConfiguratorの実測GPU費用モデルを注意部とFFN部へ分割し、AstraSimの階層通信網へ接続することで、各候補の演算時間だけでなくAFD固有のfan-out dispatch、fan-in combine、競合、配置を評価する。結果から負荷・モデルごとの具体的な注意GPU対FFN GPU比を導き、AFDが厳しい遅延SLOでは不可欠だが最大総処理量では不要な場合も多いという境界を明示する。
## 手法
### 手法のあらまし
入力としてモデル構造、GPU種類と台数、scale-up・scale-out通信網、用途ごとのprefix長・入力長・出力長・SLOを与える。探索器は2〜128 GPUの各replica規模について、データ・系列・テンソル・専門家並列の組合せ、集約、事前充填・復号分離、注意・FFN分離の有無、さらに注意側とFFN側のGPU台数比を列挙する。各候補ではAIConfiguratorの実機計測データから注意とFFNの小バッチ計算費用を得る。AFDでは一層ごとに注意出力、トークン識別子、専門家ルーティング情報を注意GPUからFFN GPUへfan-outし、専門家出力を元の注意GPUへfan-inする全対全通信行列を生成し、AstraSimで物理位置、NVLink、InfiniBand、競合を含む転送時間を求める。処理バッチを通信網の全二重性に応じて三または四microbatchへ分け、注意計算、dispatch、FFN計算、combineを異なる資源上で重ねる。各段の実測費用から最遅段を定常律速とし、パイプライン充填・排出分を加えて一回の時間を予測する。配置では毎層発生する高頻度AFD通信を高速なnode内scale-upへ寄せ、要求ごと一回程度の鍵値転送をscale-outへ回す。候補ごとにTTFTとTPOT SLOを満たすか判定し、満たすものだけについて利用者当たり生成速度とシステム総処理量のPareto前線を作る。これをchat、coding、agentic codingと複数モデルで繰り返し、どの負荷なら集約、P/D分離、AFD、両者併用が最適かを抽出する。

### 計算・通信統合の設計空間探索
GPU計算費用だけを推定する既存AIConfiguratorを、注意部とMoE-FFN部を独立GPU backendとして扱えるよう分割し、AstraSimのパケット粒度通信モデルへ接続する。候補ごとにテンソル・データ・系列・専門家並列とreplica規模を変え、AFD時には注意GPU数とFFN GPU数も非対称に探索する。これにより、演算量だけなら有利でもdispatch/combine通信で損をする構成を除外できる。2〜128 GPUのoff-gridなreplica規模も調べるため、2の冪だけでは見つからない長文鍵値容量に適した構成も候補になる。

### microbatchによる四段重畳
AFDの一回の処理を注意計算、注意からFFNへのdispatch、専門家FFN計算、FFNから注意へのcombineという四段へ分ける。全二重通信ならバッチを四microbatch、半二重なら三microbatch程度へ分割し、異なるmicrobatchの計算と通信を別資源上で同時進行させる。各段の費用は小バッチ時の非線形な行列積効率まで実測表から取得し、最も遅い段が定常処理量を決める。残る段はパイプラインの開始・終了時だけ泡として加算するため、AFDの追加通信を単純加算するより実際の重畳可能性を評価できる。

### 通信頻度を考慮したGPU配置
注意とFFNの境界通信は変換器の各層で二回発生するため、要求ごとに一度程度の事前充填・復号間鍵値転送よりはるかに頻繁である。そこで物理GPU位置を持つAstraSimを使い、AFD境界を同一nodeまたは高速scale-up領域へ優先配置し、低頻度の鍵値移動をInfiniBandなどscale-out側へ置く。注意側から多数の専門家GPUへ広がるdispatchと、専門家側から元の注意GPUへ戻るcombineでは混雑位置も異なるため、全対全通信行列としてfan-outとfan-inを別々にモデル化する。これにより単なるGPU台数比だけでなく、どのGPUをどこへ置くかまで含めて分離の可否を判断する。

### 全体のデータ／制御の流れ
AIC++はGPUカーネル実測に基づくAIConfiguratorと階層ネットワークのAstraSimを結合し、vLLMベースAFD試作で通信経路を裏付けた設計探索基盤。
## 評価条件
- **ハードウェア**: 主探索は128枚のNVIDIA B200 SXMクラスタ。GPU計算費用はTensorRT-LLM backendの測定を用い、NVLink等のscale-upとInfiniBand等のscale-outをAstraSimでモデル化する。
- **ソフトウェア**: AIC++はNVIDIA AIConfiguratorの演算・メモリ費用モデルとAstraSim通信シミュレータを統合。vLLMベースのAFD試作で全対全attention-FFN通信経路を機能確認する。
- **データセット／トレース**: Chat: prefix 4096, input 512, output 256、Coding: prefix 2048, input 4096, output 1024、Agentic Coding: prefix 524k, input 256, output 8192、DeepSeek-V3.2、GPT-OSS-120B、Nemotron3-120B、Qwen3-235B
- **厳格SLO比較**: DeepSeek-V3.2ではChat/Coding/Agentic CodingのTTFT上限を50/100/150ms、TPOT上限15msとして128 B200上の実行可能構成を探索する。
- **モデル構造横断**: DeepSeek-V3.2、GPT-OSS-120B、Nemotron3-120B、Qwen3-235Bで注意方式・専門家数の違いが最適attention/FFN比へ与える影響を調べる。
- **ネットワーク配置**: 各層で頻発するAFD通信をscale-upへ、要求単位の鍵値転送をscale-outへ置く配置と、無頓着な配置の通信混雑を比較する。
2〜128 GPUのreplica規模と各並列化、集約、P/D分離、AFD、両者併用を列挙し、各用途のTTFT/TPOT SLOを満たす候補から利用者当たりトークン/s対総トークン/sのPareto前線を作る。モデルはMLA・疎注意、GQA、Mamba混合など異なる注意特性を含む。
主結果はモデル化によるcluster-scale設計空間探索であり、128 B200全体を使った端末間実機測定ではない。AFD通信パターン自体はvLLM試作で検証する。
## 主要結果
設計空間探索の結論は、注意・FFN分離は万能な総処理量最適化ではないが、厳しい利用者遅延制約を満たすための有力な追加自由度になるというもの。128 B200上のDeepSeek-V3.2では厳格TTFT/TPOT条件で非AFD構成が実行可能解を持たない用途でも、AFDを含む構成は約4千トークン/sのシステム処理量を維持する。一方、SLOが緩く総トークン/sを最大化するだけなら、多くの条件でchunked プリフィル集約やP/D分離がAFDを上回る。したがって運用では『より細かく分離するほど良い』ではなく、負荷・注意方式・通信網・SLOから分離粒度を選ぶ必要がある。

- 厳格SLO下システム処理量 / 約4,000 トークン/s (比較対象: 非AFDは実行可能構成なし; 条件: DeepSeek-V3.2、128 B200、Chat/Coding/Agentic Codingの厳格TTFT/TPOT) — 演算律速FFNとメモリ律速注意を別GPU比率へできることが遅延制約を満たす。

- 遅延Pareto前線 / AFDが全評価panelで最良側 (比較対象: 集約およびP/D分離; 条件: 利用者当たりトークン/sを重視) — microbatch重畳と動的attention/FFN比がinteractivityを改善する。

- 総処理量Pareto前線 / AFD単独が勝つのは限定的 (比較対象: chunked-プリフィル集約、P/D分離; 条件: 128 B200設計探索) — 追加通信のため、SLOが緩い時は粗粒度方式が有利な場合が多い。

- DeepSeek長文AFD比 / Agenticで2 attention + 126 FFN GPU、Chatで16 + 112 (比較対象: 対称分割; 条件: DeepSeek-V3.2) — 疎注意とMLAで注意費用・鍵値量が小さいため大半をFFNへ割くのが最適。

### 負の結果・境界条件
- AFDは通信を毎層二回追加するため、純粋な総処理量では常に勝たない。RAGのように入力自体は小さいが共有prefixやcontextが大きい条件では頻繁な跨node転送が分離利得を相殺し、集約が有利になり得る。注意・FFN GPUを物理位置を無視して置くとdispatch/combine混雑が増える。

### 結果の読み方
AFDの価値はモデル内の異質性を別資源へ割り当てられることと、FFN重みをFFN GPU側へ寄せて注意GPUのメモリを鍵値キャッシュへ空けられることにある。ただしその代償が毎層通信なので、高速scale-up配置とmicrobatch重畳が成立する範囲で使う必要がある。
## 品質への影響
モデル計算は変更しないため生成品質への近似損失はない。主な交換条件は通信量、GPU配分、総処理量、利用者遅延。
## 既存研究との差
DistServeやSplitwiseが事前充填と復号というphase単位を分離するのに対し、本研究は一層内部の注意とMoE-FFNまで別GPU群へ分け、その上でP/D分離と組み合わせる。MegaScale-InferがAFDの実装価値を示したのに対し、AIC++は複数モデル・負荷・SLO・並列化・物理ネットワークを横断してAFDが有利になる境界と具体的GPU比を探索することに重点を置く。
## 限界
- 128 B200規模の主要結果は実測カーネル費用と通信シミュレーションを組み合わせた設計探索で、全構成を実クラスタ上で端末間測定したものではない。
- 最適attention/FFN比はモデル構造、prefix、入力・出力長、SLO、通信階層に依存し、論文の具体比率を別クラスタへ固定適用できない。
- AFDは毎層dispatch/combine通信を追加するため、低帯域scale-outしか使えない配置では利得が消える可能性が高い。
- 探索空間が大きく、性能backendや通信モデルの誤差がPareto境界付近の構成順位へ影響し得る。
## 実装状態
AIConfiguratorとAstraSimを統合したAIC++を構築し、vLLMベースのAFD試作で全対全attention-FFN通信経路を検証。cluster-scale性能は主にモデル化探索。
## 研究上の位置づけ
MoE提供、P/D分離、operator-level disaggregation、通信認識配置の系統。細粒度分離を常時推奨するのではなく、分離粒度そのものをSLOとネットワークを含む最適化変数として扱う比較基盤として位置付けられる。
