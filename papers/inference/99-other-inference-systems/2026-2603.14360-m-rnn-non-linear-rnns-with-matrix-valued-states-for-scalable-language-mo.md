# M²RNN：行列状態の非線形再帰層による言語モデルの表現力・効率の両立

## 書誌と研究の位置づけ

Mayank Mishra、Shawn Tan、Ion Stoica、Joseph E. Gonzalez、Tri Daoによる研究。2026年3月15日に公開され、2026年5月13日更新のarXiv第2版を確認した。論文は線形注意やMamba系列の状態空間モデルと、古典的な非線形再帰ニューラルネットワークの利点を統合するモデル構造を提案する。単純に学習済みモデルを量子化する手法ではなく、新しい再帰層を学習したときの言語モデル品質、長文脈検索、GPUカーネル実行効率を研究する。

本論文の推論システムへの関連は、固定サイズの再帰状態を持つモデルの記憶容量、非線形状態遷移の逐次計算、行列演算器の活用、複数GPUへの状態分割にある。学習時のGPU性能を詳しく測定している一方、公開原著で実測した生成トークン/秒や単一要求の復号遅延を、既存Transformerに対する汎用的な高速化倍率として示したわけではない。学習スループットと推論スループットを区別して読む必要がある。

## 概要

通常のTransformerは各トークンからキー・バリューを保存して過去の情報を直接参照できるが、生成が長くなるほどKVキャッシュが増える。線形注意やMamba-2、Gated DeltaNetなどの再帰型方式は固定サイズの状態へ過去を畳み込み、生成時のメモリを一定に保ちやすい。しかし、線形状態更新だけでは複雑な状態追跡を表現しにくく、遠い過去の複数のキー・バリュー対応を思い出す能力にも限界がある。

非線形再帰は複雑な状態遷移を表現できる反面、伝統的なRNNやGRUの状態はベクトルであり、言語モデルとして十分な情報を蓄えるには容量が不足する。単純にベクトル次元を増やすと、状態遷移行列のパラメータ数が二乗で増え、GPUの共有メモリへ載せにくい。さらに非線形演算が各時刻を逐次依存にするため、線形注意で使える並列走査を適用しにくい。

M²RNNは隠れ状態をK×V行列にし、入力のキー・バリュー外積を非線形状態遷移へ加える。これにより状態の大きさをパラメータ数の増加に対して効率よく拡張し、GPUテンソルコアの行列積として計算する。忘却ゲートを状態とは独立に計算できるようにして安定性を高め、通常の注意層と組み合わせたハイブリッドモデルで性能を比較する。7Bの混合専門家（MoE）モデルでは、Hybrid Gated DeltaNetの一部をM²RNNに置き換えるとWikiTextのパープレキシティと長文脈検索が改善する。

## 背景：線形再帰と非線形再帰の交換条件

線形注意の再帰形式では、過去の情報を行列 `H_t` へ蓄積し、入力から計算したキー・バリュー外積で更新する。典型例は `H_t = H_(t-1) + φ(k_t) v_t^T`、読み出しは `y_t = H_t^T φ(q_t)` である。系列長に依存して状態サイズが増えないため、生成時には過去の全KV対を保持しなくてよい。学習時には更新の結合性を利用した並列化やチャンク化が可能で、長い入力を比較的効率よく処理できる。

ただし、線形遷移は過去の情報を固定ランクの更新で混ぜるため、追跡する対象の入れ替わりやプログラム状態の更新などで必要な非線形表現力が不足しやすい。論文は、線形再帰とTransformerの表現可能な計算クラスの議論を背景に、状態追跡課題での性能差を動機とする。理論的な表現可能性は、有限の学習データ・パラメータ・最適化手法で必ず実際に学習できるという保証ではない。著者も理論上は表現できる比較方式が長い未知系列へ一般化しない例を報告する。

一方、従来の非線形RNNは `h_t = tanh(W h_(t-1)+x_t)` のように状態を更新する。非線形変換は複雑な状態機械を実装できるが、hの次元を大きくするとWが二乗で大きくなり、各時刻の密行列積が高価になる。再帰の前時刻の出力を次時刻で利用するため、GPUの複数演算器に分散するとグローバルメモリへの中間値書き戻しと同期が発生する。FlashRNNなどのブロック化方式は共有メモリ内の再利用を狙うが、小さい実バッチをテンソルコアのタイル幅まで埋めるためのパディング演算が無駄になる。論文はバッチ4を16へパディングする例では再帰演算の75%が無駄になると説明する。

## 手法

### 1. 行列値の非線形状態更新

M²RNNは状態 `H_t∈R^(K×V)` を保持し、前時刻の状態と入力由来の外積を使って次のように更新する。

`Z_t = tanh(H_(t-1) W + k_t v_t^T)`

`H_t = f_t H_(t-1) + (1-f_t) Z_t`

`y_t = H_t^T q_t + w_r ⊙ v_t`

WはV×Vの状態遷移行列、kとqはK次元、vはV次元である。入力外積 `k_t v_t^T` によって状態のK×V成分を一度に更新できる。従来のベクトル型非線形RNNで状態次元K×Vをそのまま持たせた場合の巨大な遷移行列を避け、より少ないパラメータで大きい状態を確保する。非線形tanhは状態遷移の表現力を高める一方、時刻方向の逐次依存は残る。

忘却ゲートfは入力から計算されるスカラー値で、状態そのものに依存しない。各ヘッドで前状態を残す比率と新しい非線形候補へ置き換える比率を制御する。状態依存のゲートに比べて前計算を並列化しやすい。著者はK次元のベクトルゲートも試したが、パラメータ数の増加に対する性能改善が小さいためスカラーを選ぶ。出力の残差項は長い再帰で情報が消え過ぎる問題を緩和する。

### 2. 行列状態拡張とテンソルコアの利用

状態をベクトルから行列へ拡張すると、1ヘッド内で行列積 `H W` が自然に現れる。KとVを適切に選べば、テンソルコアが得意とするタイル行列積として計算できる。従来のFlashRNNのように小さいバッチを16などへ人工的に埋める必要を減らし、状態の行方向をタイルの並列軸として活用する。GPU上ではヘッドとバッチの組を別々のストリーミングマルチプロセッサへ割り当て、遷移行列Wと状態Hを可能な限りオンチップに保持する。

これは単純に「行列状態なら常に高速」という意味ではない。Wの大きさ、K・Vのタイル形状、利用可能な共有メモリ、ヘッド数、バッチ数によって効率が変わる。状態を大きくし過ぎるとオンチップに収まらず、HBM読み書きが増える。非線形更新は時刻方向へ逐次実行されるため、長い事前充填では並列走査できる線形注意に対して不利になり得る。著者が一部の層だけをM²RNNに置き換えるハイブリッド構成を重視する理由でもある。

### 3. 初期化、勾配安定化、残差

遷移行列Wについて正規分布、直交行列、単位行列の初期化を比較し、直交と単位が同程度に良かったため単位行列を採用する。非線形状態更新では時刻を遡る勾配がWとtanhのヤコビアンを繰り返し通過するため、爆発・消失の問題がある。著者は再帰状態の勾配を各時刻でクリップし、忘却ゲートと残差で学習を安定化する。これらは推論時に追加の勾配計算を必要としないが、事前学習の安定性と最終モデルの品質に影響する。

### 4. Tritonカーネルの前向き・逆向き計算

著者はTritonで前向きと逆向きのGPUカーネルを実装する。前向きではバッチbとヘッドnの組ごとにGPUの演算器を割り当て、Wと初期状態を読み込み、時刻tのループ内で外積、非線形行列積、ゲート更新、読み出しを実行する。時刻ごとの全状態を保存せず、必要な出力を記録することで前向きのHBM書き込みを抑える。

逆向きでは勾配のために状態履歴が必要となる。著者は再計算を用いて前向き状態を復元し、その後の逆向きループで勾配を計算する。現行Triton実装の逆向きはHBM帯域に制約され、共有メモリをより細かく制御できるCUTLASS版の最適化を今後の課題としている。学習のメモリ削減と推論の固定状態メモリは異なる問題であり、前向きの状態保存削減が逆向きでも同じ割合の節約をもたらすとは限らない。

### 5. テンソル並列化（Tensor Parallelism; TP）

行列状態の多値ヘッド構成ではクエリ・キーヘッドを共有し、複数のバリューヘッドへ分配する。この構造を複数GPUへ分割すると、共有クエリ・キーとヘッド配置の整合が必要になる。著者は、GPU数に合わせてクエリ・キーヘッドを増やし、各GPUに独立したヘッドを持たせるトポロジー依存方式と、パラメータ数を維持する代わりに通信を増やすトポロジー非依存方式を提案する。

前者はM²RNNカーネルの大きな変更なしに標準的なテンソル並列通信で動くが、並列数を変えるとヘッド配置やモデル構成が変わる。後者は並列数からモデルパラメータを切り離せる一方、学習時の追加同期が発生する。どちらも分散学習の実装選択であり、単一GPU推論の自動高速化ではない。小規模ローカル推論に導入する場合は、まず一基のGPUで状態行列がオンチップに収まるかを確認する必要がある。

## 評価条件と結果

410Mパラメータの密モデルと、7B総パラメータ・活性約1Bの混合専門家（Mixture of Experts; MoE）モデルを学習する。410Mモデルは32基、7B MoEは64基のNVIDIA H100を使用し、入力長4096、バッチ1024、同一データ・同一順序で比較する。線形注意、Mamba-2、Gated DeltaNet、通常RNN、GRU、Transformer++、M²RNNおよび注意層を交ぜたハイブリッドを対象とする。混合型は原則8層中1層が注意層で、残りの再帰層を置き換える。三方式混合では1層だけM²RNNに替える構成と複数層替える構成を比較する。

| 実験条件 | 比較方式 | M²RNN系 | 評価上の解釈 |
|---|---:|---:|---|
| 410M密モデル、WikiTextパープレキシティ | Mamba-2 13.73 | 純M²RNN 13.80 | 純M²RNNはこの指標でMamba-2より悪い。すべての構成で優位とはいえない |
| 410M密モデル、WikiTextパープレキシティ | Hybrid Gated DeltaNet 13.51 | Hybrid M²RNN 13.00 | ハイブリッド化で0.51改善（小さいほど良い） |
| 410M密モデル、零ショット課題平均精度 | Hybrid Gated DeltaNet 64.64 | Hybrid M²RNN 65.56 | +0.92点。改善は大きな倍率ではない |
| 410M密モデル、実データ文脈検索6課題平均 | Hybrid Gated DeltaNet 43.1 | Hybrid M²RNN 46.9 | +3.8点。純M²RNNの26.9はGated DeltaNet純型30.8より低い |
| 7B MoE、実データ文脈検索6課題平均 | Hybrid Gated DeltaNet 51.4 | Hybrid M²RNN 55.6 | +4.2点。注意層との組合せが重要 |
| 7B MoE、WikiTextパープレキシティ | Hybrid Gated DeltaNet 21.89 | M²RNNを1層追加21.39 | 1層追加だけで0.50改善 |
| 410M密モデル、LongBench 8課題平均 | Hybrid Gated DeltaNet 15.4 | 同モデルにM²RNNを3層追加23.0 | +7.6点。原著の「最大約8点」に対応 |
| 410M密モデル、LongBench 8課題平均 | Hybrid Mamba-2 10.3 | M²RNNを3層追加17.1 | +6.8点。再帰層の置換による差 |

言語モデルのパープレキシティ改善と長文脈検索精度の改善は関連するが、同一の指標ではない。特に純粋なM²RNNがすべての課題で最良ではなく、長文脈の実データ検索では純M²RNNが線形方式を下回るケースがある。論文の主要な利得は、注意層や線形再帰層を残したまま、非線形再帰を少数挿入することにある。

### 状態追跡と未知長への一般化

状態追跡の合成課題では、訓練系列長128から評価系列長512へ伸ばす。著者はM²RNNとGRUが訓練長を超えて高い状態追跡精度を保つ一方、負の固有値を許すGated DeltaNetやHouseholder積を使うGated DeltaProductは長い未知系列で性能を落とすと報告する。これは非線形状態遷移の表現力と実際の長さ外挿が関係する証拠であるが、合成状態追跡が現実の長文書検索・コード実行を完全に代表するわけではない。

RULERの単一針探索、複数問い合わせ、複数キー、複数値の評価は、訓練入力長4096に対して最大16384で行う。Hybrid Gated DeltaNetへM²RNNを追加すると、多くの複数キー・複数値条件で性能が改善する。しかし、非常に単純な単一針探索ではもとのGated DeltaNetも100%となり、M²RNNの追加が逆に精度を下げる場合がある。追加層の数を増やせばすべての課題が改善するとは限らない。

### 学習効率と推論効率の違い

本研究はGPUのテンソルコア利用率と学習スループットを重視し、線形再帰と非線形再帰の学習時実装を比較する。状態を行列化することで小バッチの無駄なパディング演算を避け、前向きの中間状態をオンチップで再利用する。しかし非線形再帰は時刻方向の並列走査ができず、長い系列では逐次実行がボトルネックになり得る。著者はこの不利を認識したうえで、全層置換ではなく1層または少数層だけの導入を評価する。

推論時には固定サイズ状態であるため、過去の全トークンに対応するKVキャッシュを保存する純注意モデルより状態メモリの増加を抑えやすい。ただし、ハイブリッドには注意層が残るため、その層のKVキャッシュは文脈長に応じて増える。純M²RNNの状態は固定サイズでも、ハイブリッドモデル全体が完全に定数メモリになるわけではない。加えて論文の主要な速度・効率評価は学習系であり、復号時の1トークン遅延や実際の同時サービング性能を同じ倍率で推定してはいけない。

## 既存方式との比較

Mamba-2やGated DeltaNetは状態更新を線形化・構造化することで効率を得るが、状態遷移の表現力に制約がある。従来のGRUやLSTMは非線形の表現力を持つ一方、状態サイズとGPUでの実行効率が課題になる。M²RNNは非線形状態遷移を維持しながら、行列値状態と入力外積を用いて容量を増やす点が特徴である。

FlashRNNやxLSTMのブロック化は非線形再帰のオンチップ実行を狙うが、テンソルコアの形状に合わせるためにバッチ軸のパディングが必要になる場合がある。M²RNNは状態の行方向を活用することで小バッチでも行列積を組み立てやすい。もっとも、ハードウェア効率はK・Vの形状とGPU世代に依存するため、FlashRNN全般に対する無条件の優越ではない。

通常のTransformerは過去トークンの明示的なKVキャッシュを持ち、任意の位置を直接検索しやすい。M²RNNは固定状態へ情報を圧縮するため、遠い過去の厳密な再生ではなお不利になる。ハイブリッドは一部の注意層を残して検索能力を補い、少数の非線形再帰層で状態追跡と表現力を増す設計である。MoEはフィードフォワードの専門家活性化の仕組みであり、再帰層の状態圧縮と異なる軸なので、総パラメータ7B・活性1Bの値を再帰状態の大きさと混同しない。

## 限界・未評価事項

第一に、非線形再帰は各時刻の状態を次時刻で必要とするため、学習時に系列方向の完全な並列走査を使えない。入力が長いほど逐次依存の遅延が顕在化し、すべての注意層を置き換えた場合の事前充填性能は保証されない。少数層の置換で品質を高める設計は、この構造上の制約への現実的な折衷である。

第二に、状態を行列化して容量を増やしても、過去の全トークンを個別に保存する注意機構とは異なる。合成状態追跡で未知長に一般化しても、実データの長文脈検索では純M²RNNがMamba-2やGated DeltaNetに劣る場合がある。7B MoEでも、注意層を残すハイブリッドが性能の中心である。長文脈の性能改善を「KVキャッシュなしで完全な検索能力を達成」と解釈してはならない。

第三に、Tritonの逆向きカーネルはHBM帯域に制約され、著者自身がより低水準のCUTLASS実装を今後の課題としている。状態サイズを増やすと共有メモリ・レジスタ使用量が増え、GPU占有率や並列数を減らす可能性もある。H100を使った学習実験をRTX 4070 Superなどの異なるGPUに外挿する場合、テンソルコアの世代、オンチップ容量、VRAM、Triton対応を確認する必要がある。

第四に、テンソル並列化の一方はGPU数によってヘッド構造が変わり、他方は同期通信を追加する。大規模分散学習での実装の自由度を高めるが、推論サーバーの通信オーバーヘッドや障害耐性、CPUオフロードとの共存を直接評価したものではない。実用化には重み公開モデルを推論エンジンへ統合し、prefill・decodeを分離して測定する追加実験が必要である。

第五に、表の評価は著者の学習条件、データ順序、モデル規模に依存する。7B MoEの活性パラメータは約1Bで、同じ総パラメータの密モデルと計算量が等しいわけではない。パープレキシティ0.5点の改善やLongBench最大約8点の改善は特定の比較条件であり、一般的な生成品質、エネルギー消費、メモリ削減、処理率が同率で改善する証拠ではない。
