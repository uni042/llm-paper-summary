# Serving Chain-structured Jobs with Large Memory Footprints with Application to Large Foundation Model Serving

> 分散パイプライン型の大規模言語モデル推論を、モデルブロック配置、鍵値キャッシュ容量配分、オンライン負荷分散からなるサーバ鎖構成問題として定式化し、実サービング評価で平均応答時間を六十三から七十七パーセント削減する。
## 書誌情報
- **著者**: Tingyang Sun, Ting He, I-Hong Hou
- **公開**: arXiv:2604.14993
- **種別**: arXivプレプリント
- **対象**: パイプライン並列サービング、画像処理装置メモリ配分、負荷分散
- **実装**: 中央オーケストレータが事前のブロック配置とキャッシュ容量配分、オンラインの空き最速サーバ選択による負荷分散を組み合わせる研究実装である。
## 概要
大規模トランスフォーマーを地理的・物理的に分散した画像処理装置へパイプライン配置すると、各要求は全層を順に覆うサーバ鎖を必要とし、装置メモリはモデル重みと要求別の鍵値キャッシュの双方に競合利用される。本研究はこれを大容量メモリを消費する鎖構造ジョブのサーバ鎖構成問題として抽象化し、モデルブロック配置、残余メモリのキャッシュ容量配分、到着要求の負荷分散を分離しながら連携させる。計算困難な配置・容量問題に対して性能保証付きのスケーラブルな手法を設計し、実際の大規模言語モデルサービング系を含む評価で平均応答時間を既存手法より六十三から七十七パーセント削減する。

論文はパイプライン並列の基盤モデルサービングを、大容量メモリを持つ鎖構造ジョブを処理する構成可能なサーバ鎖の問題として抽象化する。物理サーバへの連続ブロック配置、各経路へ割り当てる鍵値キャッシュ枠数、到着ジョブのオンライン振り分けを三つの結合問題へ分解し、前二者をオフラインに解いて処理率と同時実行容量を持つ論理ジョブサーバ群を構成した後、異種サーバ向け負荷分散を適用する。ブロック配置とキャッシュ配分がともに計算困難であることを示し、特殊条件での最適性と一般条件での応答時間上下界を与える。新規性は単なる配置アルゴリズムではなく、重み配置が残すメモリ量を要求同時実行容量へ変換し、その容量を待ち行列の論理サーバ数として扱うことで、配置・メモリ・振り分けを一つの性能モデルへ接続した点にある。

代表結果として、mean response time reductionはmodel-driven シミュレーション and real LLM serving under demands deviating from modeling assumptionsでstate-of-the-art distributed LLM resource-allocation solutionsに対して63-77% reduction。モデル配置とKV同時実行容量を別々にheuristic設定するより、同じGPU メモリ budget内で共同設計した論理server chainsの方が待ち時間と処理時間を大幅に減らす。
## 問題設定
大規模トランスフォーマーを複数の画像処理装置サーバへパイプライン並列で配置すると、一つの推論要求は全レイヤーブロックを順に覆うサーバ鎖で処理される。従来の分散配置問題と違い、装置メモリはモデル重みを常駐させるためにも、各要求の過去トークンに対応する鍵値キャッシュを保持するためにも必要であり、ブロックを多く複製すれば経路選択肢は増える一方でキャッシュ用残余メモリが減って同時実行数が下がる。既存の大規模言語モデルサービング実装はこの配置を経験則で扱うことが多く、負荷分散理論だけでは、どの論理サーバ鎖を何本作れるか自体が未決定である。したがって要求到着後の振り分けだけを改善しても、事前配置が作る処理率と同時収容数の上限を越えられない。モデル複製を増やすほど良いという単純な方針も、重み常駐量の増加で要求ごとのキャッシュ余地を奪うため逆効果になり得る。

## 手法
### 手法のあらまし
モデルを複数の連続サービスブロックへ抽象化し、物理サーバごとにメモリ容量、通信時間、ブロック当たり処理時間を与える。各サーバは連続したブロック範囲だけを保持し、要求は先頭から末尾までを順に覆えるサーバ鎖を選ぶ。サーバのメモリ消費は常駐モデルブロックの重みと、そのサーバが実際に処理するブロック数に比例した要求別鍵値キャッシュ枠の和として表す。ブロック配置が決まると、連続遷移可能なサーバ対、実行可能なサーバ鎖、各鎖の処理時間が決まる。残余メモリを各鎖の同時要求用キャッシュへ配分し、鎖ごとに同時実行容量を与えると、同じ処理率を持つ複数の論理ジョブサーバとして待ち行列問題へ変換できる。設計は二時間尺度で行い、ブロック配置とキャッシュ配分を低頻度の事前処理、到着要求の振り分けを高頻度のオンライン処理にする。平均応答時間を直接最小化すると負荷分散との依存が複雑なため、目標最大負荷の安全余裕を導入し、総処理容量制約の下で応答時間上下界を扱える明示的最適化へ変換する。オンライン側では異種速度の論理ジョブサーバに対して空き最速サーバ選択を使い、空いている中で最速の鎖へ要求を送る。配置とキャッシュ配分の計算困難性を示した上で、構造を利用した効率的アルゴリズムと上下界を導き、設計パラメータを理論値から調整できるようにする。実システムでは固定最大系列長に基づく静的キャッシュ配分と、開始後は鎖を移動しない前提を置き、キャッシュ移送費を避ける。重要なのは、物理サーバ一台を一つの待ち行列サーバとみなさず、配置と残余メモリから生成される実行可能な鎖とその同時収容枠を論理サーバへ展開することである。これにより装置性能差、通信時間、重み占有量、要求別メモリ量を同じ最適化へ取り込める。

### 連続ブロック配置
各画像処理装置サーバへトランスフォーマーレイヤーの連続区間を配置し、隣接サーバ間で全レイヤーを順番に覆える場合だけ実行可能な鎖を構成する。連続区間に限定することでパイプライン通信を隣接分割間へ抑えつつ、ブロック複製によって複数の代替鎖を作れる。ただしブロックを多く置くほどモデル重みが装置メモリを占有し、鍵値キャッシュへ使える残余枠が減るため、経路冗長性と同時実行容量が直接競合する。論文はこの配置自体が計算困難であることを示し、単なる均等レイヤー分割では捉えられないメモリと処理時間の交換条件を最適化対象にする。さらに異種装置では同じブロック数でも処理時間と利用可能メモリが異なるため、速い装置へ機械的に多くのブロックを置くとキャッシュ容量を失い、結果として待ち行列を悪化させる可能性がある。そこで配置段階から後続の鎖構成と同時収容数を意識し、要求が選べる経路の数と各経路の実効容量を共同で作る。

### 鎖別鍵値キャッシュ容量配分
配置後の各サーバ残余メモリを、そこを通るサーバ鎖の同時要求用鍵値キャッシュ枠へ割り当てる。ある鎖へ複数件の同時実行容量を与えると、その鎖は同じ処理率を持つ複数の論理ジョブサーバとして表現できる。各物理サーバでは複数鎖が同じブロックとキャッシュメモリを共有するため、全鎖の容量はサーバごとの残余メモリ制約を同時に満たす必要がある。この配分も計算困難であり、モデル配置で残したメモリをどの経路へ割り振るかが待ち行列容量と応答時間を決める。単一の高速鎖へ残余メモリを集中するとその鎖の並列度は上がるが、別の鎖が使えず到着変動への逃げ道を失う。逆に多数の鎖へ薄く分散すると選択肢は増えるが各鎖の同時実行枠が小さくなる。提案法はこの交換条件を物理サーバごとのメモリ制約として明示し、重み配置後に残った容量を要求処理能力へ変換する。最大系列長に基づく静的配分なので実際の短い要求では保守的になり得るが、要求開始後の大規模なキャッシュ移送を避け、解析可能な容量を事前に確定できる。

### 二時間尺度のサーバ鎖構成
モデルブロックのロードは高コストなので、ブロック配置とキャッシュ配分を要求ごとに変えず、低頻度の事前構成として実行する。これら二つから実行可能な鎖、各鎖の処理時間、同時実行容量を確定し、物理装置群を異種速度の論理ジョブサーバ集合へ変換する。待ち行列応答時間を直接最適化する代わりに目標最大負荷という安全余裕を導入し、総処理容量を確保しながら応答時間を抑える明示的な目的へ変換する。特殊条件では最適性を示し、一般条件では定常平均応答時間の上下界を与えて設計パラメータを調整する。事前構成とオンライン振り分けを分離することで、重み再配置のような高コスト操作を要求到着のたびに行わずに済み、短時間の負荷変動は軽量な振り分けだけで吸収できる。理論上の上下界は、どの程度の負荷余裕を持たせれば応答時間が悪化しにくいかを設計者が判断する基準にもなる。

### オンライン空き最速負荷分散
事前構成後は到着要求を論理ジョブサーバへ割り当てる通常の異種サーバ負荷分散として扱う。中央待ち行列に到着した要求を、現在空いている論理サーバのうち処理率が最も高い鎖へ送る空き最速サーバ選択を用い、鎖が使用中なら容量が空くまで待機する。要求開始後は鍵値キャッシュ移送の大きな費用を避けるため中断や鎖間移動を行わない。配置・キャッシュ配分と振り分けを分離することで、重いメモリ配置は低頻度で安定させながら、要求到着の短時間変動にはオンライン方策で追従できる。ここで一つの鎖に複数の同時収容枠がある場合、それぞれを同じ速度の論理サーバとして扱えるため、複雑な物理メモリ共有をオンライン判断から隠蔽できる。振り分け器は事前計算済みの処理率と空き状態だけを見ればよく、毎回配置最適化を解く必要がない。開始済み要求を移動しない制約は柔軟性を下げる一方、巨大な鍵値キャッシュをネットワーク越しに移す費用を回避し、実装上の予測可能性を高める。

### 全体のデータ／制御の流れ
中央オーケストレータ、連続レイヤーブロックを保持する異種画像処理装置サーバ、事前のブロック配置、残余メモリのキャッシュ配分器、実行可能サーバ鎖構成器、オンラインの空き最速サーバ振り分け器からなる。
## 評価条件
- **ハードウェア**: distributed GPU servers in real LLM serving experiment
- **ソフトウェア**: パイプライン-parallel LLM serving prototype、central orchestrator、server-chain composition algorithms
- **比較対象**: state-of-the-art distributed LLM resource allocation algorithms、heuristic block 配置/リクエスト スケジューラ approaches
まず抽象queueing modelでblock 配置/キャッシュ allocationの性能boundを導出し、model-driven シミュレーションで理論予測を検証する。続いてreal distributed LLM serving systemへ配置・capacity・dispatchを適用し、仮定から外れる実需要でも比較対象とのresponse-time差を測る。
パイプライン-parallel、メモリ-bound、中央orchestrator、各リクエストの静的 maximum-sequence KV allocation、開始後のnon-preemptive/non-migratory executionを主仮定とする。動的 KV growth、tensor parallel中心の密結合cluster、分散orchestratorは主要モデル外である。
## 主要結果
server-chain compositionをblock 配置、KV キャッシュ capacity、online load balancingへ分解した提案方式は、model-driven シミュレーションとreal distributed LLM servingの双方で既存resource-allocation方式より応答時間を大きく短縮した。主要な実システム評価ではmean response timeを63〜77%削減し、元のqueueing modelが置く理想化仮定からreal demandが外れても改善が残った。理論面ではblock 配置とキャッシュ allocationがNP-hardであることを示す一方、重要な特殊caseで最適解を与え、一般caseではsteady-state mean response timeのupper/lower boundsを導出する。実務上はモデルblockを増やしてchainを増やすだけではKV残余メモリが減るため、配置とリクエスト concurrencyを同時に決める必要があることを定量化する。

- mean response time reduction / 63-77% reduction (比較対象: state-of-the-art distributed LLM resource-allocation solutions; 条件: model-driven シミュレーション and real LLM serving under demands deviating from modeling assumptions) — モデル配置とKV同時実行容量を別々にheuristic設定するより、同じGPU メモリ budget内で共同設計した論理server chainsの方が待ち時間と処理時間を大幅に減らす。

- computational complexity / block 配置 and キャッシュ allocation are NP-hard (比較対象: exact global optimization; 条件: general server-chain composition problem) — 単純な最適化をリクエスト arrivalごとに解くことは現実的でなく、offline compositionとonline dispatchの二時間尺度分離が必要になる。

- analytical guarantee / explicit upper/lower bounds on steady-state mean response time; optimality in important special cases (比較対象: heuristic-only allocation; 条件: Join-the-Fastest-Free-Server load balancing) — 経験的配置だけでなく、target loadなど設計parameterを理論boundから調整できる。

### 負の結果・境界条件
- 動的 KV allocationやリクエスト途中のキャッシュ growthは主モデルでは静的 maximum-sequence allocationへ単純化される。
- リクエスト開始後のmigration/preemptionを許さず、KV移送が高価という現実的だが固定的な仮定を置く。
- 中央orchestratorを前提とし、分散制御は今後の課題である。

### 結果の読み方
大規模モデルの分散servingでは、GPU メモリが重みとKVの双方に消費されるため、model 配置を最大化することとリクエスト concurrencyを最大化することが同じresource上で競合する。本研究はこの競合をchain capacityへ明示的に変換し、offlineで論理server群をcomposeしてからonline load balancingへ渡す。63〜77%の応答時間削減は、スケジューラだけでなくスケジューラが選べるserver-chain集合そのものをメモリ-awareに設計する価値を示す。
## 品質への影響
生成計算の内容は変更せず、どのGPU chainで処理するかと何件を同時収容するかを変えるため、モデル品質への近似誤差は導入しない。改善対象はqueue waitingとservice response timeである。
## 既存研究との差
一般的な連続バッチ型の推論エンジンは既に配置されたモデル上で要求順序やバッチ構成を決めるのに対し、本研究は物理的な画像処理装置へどのレイヤー区間を置き、残余メモリをどのサーバ鎖の鍵値キャッシュへ割り当てるかを先に決める。分散したモデルブロックを用いる既存方式に近い側面はあるが、実装固有の経験則ではなく、大容量メモリを消費する鎖構造ジョブとして抽象化し、配置とキャッシュ配分の計算困難性、特殊条件での最適性、一般条件での応答時間上下界を与える。サービス機能連鎖とも形は似るが、計算資源の配置だけでなく、共有されるモデル重みと要求ごとに専有される鍵値キャッシュが同じ装置メモリを競合する点を中心に置く。このため経路を増やすためのモデル複製が同時実行容量を減らすという、大規模モデル推論特有の交換条件を直接扱える。
## 限界
- 要求ごとの実系列長に応じて成長する動的な鍵値キャッシュではなく、最大系列長に基づく静的容量配分を仮定するため、短い要求が多い場合にはメモリ利用が保守的になり得る。
- 一度開始した要求はサーバ鎖間を移動せず中断もしないため、負荷が急変した後に実行中要求を別経路へ再配置する柔軟性は持たない。これは巨大な鍵値キャッシュ移送費を避ける代わりの制約である。
- 中心対象はパイプライン並列であり、テンソル並列や専門家並列を同時に用いる配置、複数の並列方式をまたぐ通信費の共同最適化は主要モデル外である。
- 中央オーケストレータを前提とするため、非常に大規模な地理分散環境での制御遅延、状態収集費、部分故障時の分散合意などは今後の検証課題である。
- 応答時間の理論解析には待ち行列モデル上の仮定があり、実運用の接頭辞キャッシュ再利用、系列長の強い相関、装置障害、通信混雑などをすべて同時には表現しない。
## 実装状態
性能保証付きのブロック配置、残余メモリのキャッシュ容量配分、空いている論理サーバのうち最速の経路へ要求を送る負荷分散を実際の分散大規模言語モデルサービング系へ適用した研究実装である。論文の一次資料からは一般公開された公式コードの所在を確認できなかった。
## 研究上の位置づけ
大規模言語モデルサービングを要求スケジューラだけの問題として見ず、物理装置のモデル配置と残余メモリから、処理率と同時実行容量を持つ論理サーバ群を構成する問題として扱う理論・システム橋渡しの研究である。特にメモリが重みと要求状態の双方に使われる環境では、配置を増やすほど要求容量が減る場合があることを明示し、配置層とスケジューリング層を分離しながら性能指標で接続する。将来、動的キャッシュ管理や複数並列方式と組み合わせる際にも、事前構成がオンラインスケジューラへどの程度の処理余裕を提供すべきかを考える基準になる。
