# H-Scale: Hessian-Guided Scale Refinement for NVFP4 Sub-Byte LLM Inference

## 概要
NVIDIA Blackwellがnative対応するNVFP4は、16要素程度のmicro-blockごとにE2M1の4-bit値とE4M3の8-bit local scaleを持ち、さらにtensor-levelのFP32 global scaleを組み合わせる。groupが細かいため局所的な外れ値を隔離しやすい一方、各16値groupが独立scaleを持つため、scale選択の小さなずれが大量のgroupへ積み重なり、最終品質を左右する。

既存のpost-training quantization（PTQ）は、GPTQのように量子化weight値の再構成やrounding error伝播へ重点を置くことが多い。H-Scaleはここを補完し、**量子化codeは既存NVFP4 pipelineのまま、各groupのscaleだけをcalibration activation由来の対角Hessian近似で選び直す**。重みMSEではなくlayer output perturbationへ近いweighted reconstruction errorを最小化するため、実際の入力で強く励起されるchannelの誤差を優先的に小さくする。

介入箇所はRTN-style scale selectionだけで、最終weightは標準NVFP4形式のままである。したがってBlackwellの既存NVFP4 kernelやmemory layoutを変更せず、推論時の追加演算はゼロである。追加費用はoffline calibrationとgroupごとの有限scale探索に限定される。

## 問題設定
NVFP4ではfull-precision weight matrix \(W\) の各rowを入力channel方向へ \(g=16\) ずつ分割し、group \(w_{r,i}\) を
\[
\hat w_{r,i}=s_{r,i}\cdot \mathrm{Clip}\!\left(\mathrm{Round}(w_{r,i}/s_{r,i})\right)
\]
の形でE2M1 gridへ写す。effective scale \(s_{r,i}\) はtensor-level global scaleとFP8 E4M3 local scaleの積で、通常はgroup内最大絶対値から初期化してhardware-valid値へ丸める。

このときplain weight MSEが小さいscaleと、実入力でlayer output errorを小さくするscaleは一致しない。calibration activation \(X\) に対するoutput mismatchは
\[
\|X(W-\hat W)^\top\|_F^2
=\mathrm{Tr}(\Delta W X^\top X\Delta W^\top)
\]
であり、channelごとの使用頻度・activation energyを反映する。完全な \(X^\top X\) を使って全groupのscaleを同時最適化するとoff-diagonal相関によって離散探索が結合し、組合せ的に重くなる。

H-ScaleはこのHessianを対角へ落とし、groupごとに独立な有限探索へ変える。これによりoutput-awareな感度は残しつつ、既存PTQへ差し込める後処理にする。

## 手法
### calibration activationから対角Hessianを作る
各layerへ4096個のFineWeb calibration sample（sequence length 8192）を通し、入力activation \(X\) から
\[
h=\mathrm{diag}(X^\top X)
\]
を計算する。各 \(h_j\) は入力channel \(j\) のactivation energyに相当し、大きいchannelほどそのweight errorがlayer outputへ強く効くとみなす。

group \(i\) に対応する \(h_i\) を切り出し、候補scale \(s\) ごとに
\[
\|(w_{r,i}-\hat w_{r,i}(s))\odot\sqrt{h_i}\|_2^2
\]
を評価する。\(h_i=\mathbf{1}\) にすれば単なるweight-centric scale searchへ退化するため、構成要素除去実験では「scale探索自体」と「Hessian weighting」の寄与を分離できる。

### hardware-validな近傍scaleを有限探索する
候補は任意の実数scaleではなく、NVFP4が実際に表現できるE4M3 local scaleだけに限定する。baselineのmax-abs/RTN初期値からE4M3 grid上を上下へ歩き、既定では上方向 \(U=6\)、総候補数 \(K=16\) の近傍windowを作る。各候補で標準E2M1 roundingを行い、上記weighted errorが最小のscaleを選択する。

候補windowの感度実験ではQwen3-4B-Instructの全144 linear layerについて、\(U=6,K=16\) でfull-grid探索が得るlayer-output error改善のmedian 100%、P10 99.91%を回収する。\(K=20/24\)へ広げても改善はほぼ飽和するため、短い近傍探索で十分という設計根拠になっている。

### 既存PTQ pipelineへの差し込み
RTN、4over6、ArcQuant、GPTQ、GPTAQ、MR-GPTQに対して、各groupの最終scale chooserだけをH-Scaleへ置換する。GPTQ系はすでにfull Hessianを作るため、そのdiagを再利用でき、column orderingやrounding error propagationは元手法のまま残す。非GPTQ系は1回のactivation passで \(h\) を作る。

出力は通常のNVFP4 weightであり、追加metadata、runtime branch、高精度fallbackを必要としない。つまり品質改善の対価はoffline calibrationで、token生成時のFLOPsやmemory formatは変えない。

## 評価条件
| 観点 | 条件 |
|---|---|
| 量子化形式 | Blackwell NVFP4、weight-only PTQ、group size 16 |
| モデル | Qwen3-30A3-Thinking、Qwen3-30A3-Instruct、Qwen3-4B-Instruct、LLaMA-3.1-8B-Instruct |
| 比較対象 | RTN、4over6、ArcQuant、GPTQ、GPTAQ、MR-GPTQ |
| calibration | FineWeb 4096 sample、sequence length 8192 |
| ベンチマーク | AIME24/25、MMLU-Redux、LiveBench、LiveCodeBench、C-Eval、ARC-Challenge、BBH、GPQA、GSM8K |
| decoding | 各設定3回独立実行して平均。temperature 0.7、top-p 0.8、top-k 20等 |
| offline runtime | 単一NVIDIA H200 |
| ablation | Hessianなしscale-only、候補window幅、calibration size、scale shift統計 |

## 主要結果
Qwen3-30A3-Thinkingでは、H-Scaleを加えた**すべてのPTQ pipelineで平均scoreが上昇**する。BF16平均81.06に対し、RTNは80.03→80.68、4over6は79.99→80.49、ArcQuantは79.73→80.46、GPTQは80.01→81.22、GPTAQは80.21→80.71、MR-GPTQは79.67→80.41である。GPTQ+H-Scaleは観測平均でBF16をわずかに上回るが、論文は各設定を3 run平均とし、小差へ統計的有意性を付与しないと明記している。個別taskでは必ず改善するわけではなく、平均値の一貫した改善が主結果である。

Qwen3-30A3-Instructでも全baselineの平均が上がり、Qwen3-4B-Instructでは例えばRTN 55.38→56.26、GPTQ 55.63→56.53、GPTAQ 56.63→57.52となる。LLaMA-3.1-8B-Instructでも全baseline平均が改善し、4over6 48.86→50.05、GPTQ 50.61→51.32、GPTAQ 49.54→51.48で、Qwen family固有の効果ではないことを確認する。

Hessianの構成要素除去実験（ablation）では、Qwen3-30A3-Instructで単なるscale-only探索は4over6を64.25→63.55、ArcQuantを63.45→63.10へ悪化させる一方、H-Scaleは64.53、64.24へ改善する。GPTQでもbaseline 63.90、scale-only 64.39、H-Scale 64.50で、**近傍scale探索だけでは不安定で、activation感度でweight errorを重み付けすることが重要**だと分かる。

内部指標ではQwen3-4B-Instructの1.68億groupを調べ、31.2%は初期scaleを維持、47.9%は大きいscale、20.9%は小さいscaleを選ぶ。深くscaleを縮める \(\delta\le -4\) groupは全体の0.11%しかないが、選択group内のHessian-weighted rounding errorを平均58.7%削減し、H-Scaleが除去する総errorの8.3%を占める。少数の高感度groupを拾うことが平均改善へ寄与している。

offline費用は単一H200で、4over6が0.2 h→H-Scale付き0.4 h、GPTQが9.6 h→9.9 hである。後者は既存Hessianを再利用するため追加費用が小さい。推論weight formatとkernelは変わらないので、token生成時の追加overheadは0である。calibrationを4096から128 sampleへ減らす追加実験でも、対応baselineより平均改善が残る。

## 既存研究との差
GPTQはfull Hessianをcolumn orderingやrounding error propagationへ使うが、最終的なNVFP4 local projectionでは依然group scaleを選ぶ必要がある。H-ScaleはGPTQ自体を置き換えず、そのscale-selectionだけをoutput-awareにする。4over6やArcQuantのような別のNVFP4手法にも同じ後処理を重ねられるため、baseline-agnosticである。

AWQやSmoothQuantのようにactivation/weight間でscaleを移す方式、SpinQuantのようにweight分布をrotateする方式とも異なり、H-Scaleは**すでに決まったNVFP4 value gridを変えず、hardware-valid local scaleの離散選択だけを改善する**。この限定された介入が、Blackwell native formatを保ったまま品質を上げる理由である。

## 限界
論文が直接評価するのはgroup size 16のNVFP4とtext-only LLMである。同じscale-contraction傾向がINT4、別FP4形式、別group size、multimodal modelへ移るかは未検証である。推論時overheadが0という利点は、最終weightを標準NVFP4のまま保持するからであり、H-Scale単体が既存NVFP4 baselineよりtokens/sをさらに高める方式ではない。

また個別benchmarkではH-Scale追加後にscoreが下がる例があり、主張は「各taskで必ず改善」ではなく「複数task平均で多くのPTQ baselineを一貫して改善」である。offlineではactivation calibrationと有限scale探索が必要で、既存Hessianを持たないpipelineでは4over6の例のように準備時間が増える。
