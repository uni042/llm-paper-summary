# NeUQI：低ビット一様量子化でscaleとzero-pointの初期値を探索する

## 概要

低ビットの言語モデルを作る際、重みを整数格子へ写す一様量子化は既存GPUの整数演算・メモリ削減と相性がよい。しかし2bitや3bitでは、量子化幅を重みの最小値と最大値だけで決めるMin-Max初期化が品質を大きく損ねる。NeUQIは、量子化方式そのものを複雑な非一様符号へ変えるのではなく、**一様量子化のscale（刻み幅）とzero-point（原点のずれ）を、出力誤差に合わせて選び直す**手法である。

主な工夫は二つある。第一に、zero-pointをkビットの非負整数に制限せず、scaleを固定したときの量子化損失が区分二次関数になる性質を使って、最良のzero-pointを効率的に求める。第二に、scaleの候補をMin-Max由来の上限以下で粗く探索し、良い領域を細かく探索する。これによりscaleとzero-pointを独立に全探索する高コストな方法を避ける。

Llama2-7Bの2bitチャネル別量子化では、WikiText2困惑度がGPTQ 6953、GPTAQ 1269、MagR 129に対してNeUQI 17.14、5課題平均正解率がGPTQ 35.08%、NeUQI 47.24%となる（Table 2）。ただし、NeUQIは量子化前処理に時間がかかり、A40でのLlama2-7B量子化はGPTQ 8.75分に対して29.75分である（Table 10）。**推論時の速度改善を測定した結果ではなく、同じ低ビット形式で精度の良い重みを得る方法**と理解すべきである。

## 背景と解く問題

一様量子化では、kビットで表現できる2^k個の格子点を、刻み幅sとzero-point zで定める。実数重みxは、概念的にはx/s+zを丸めて0から2^k−1へクリップし、再びsを掛けて戻す。Min-Max方式は重みの最大値と最小値を格子の端に割り当てるため、外れ値に引きずられて通常値の解像度が低下する。2bitでは格子点が4個しかないため、この問題が特に深刻である。

論文が指摘するMin-Maxの制約は、(1) scaleとzero-pointの両方を最大・最小値から導くため探索自由度が不必要に狭いこと、(2) zero-pointを整数に制限することで格子全体の位置を連続的に調整できないことである。LeanQuantなどの探索法でも、Min-Maxの範囲表現を通じて候補を選ぶと二次元の探索空間が広がり、効率が悪くなる。

NeUQIはPTQの初期化段階でこの二つの制約を取り除く。目的は、量子化した重みと元の重みの差が、実際の活性値を通した線形層の出力へ与える影響を小さくすること。単純な重みの二乗誤差ではなく、活性値から推定する重みの重要度を反映した損失を用いる。

## 手法

### 1. 活性値で重み付けした量子化損失

線形層の重み行列W、入力活性値X、量子化器Q_{s,z}を考える。量子化による層出力差の二乗を期待値で測り、H=E[XᵀX]を代理Hessianと置くと、誤差は重み差とHの二次形式で表せる（式4）。このままでは重み間の相互作用を扱う必要があるため、NeUQIはHの対角成分H_{ii}だけを残し、行単位の損失をL(s,z)=Σ_i H_{ii}(Q_{s,z}(w_i)−w_i)^2とする（式5）。

入力は重み行ベクトルwと較正活性値から得たHの対角、出力はその行に使うscaleとzero-pointである。対角近似によって異なる重みの誤差の相互作用を捨てるため、完全な層出力誤差の厳密最適解ではない。NeUQIの「near-optimal」はこの近似目的と探索条件の下での表現であり、モデル全体の言語生成品質の大域最適性を証明するものではない。

### 2. scaleを固定してzero-pointを最適化

scale sを一つ固定すると、各重みについてx_i=w_i/s、h_i=H_{ii}s²と置ける。損失はΣ_i h_i[x_i+z−clip(round(x_i+z),0,2^k−1)]²となる（式6）。zero-point zが変化すると、丸め後の整数が切り替わる境界だけで式が変わる。したがって重みごとの損失は区分二次関数であり、全重みの和も区分二次関数である（式7）。

Algorithm 1は各重みが整数格子の境界をまたぐzを列挙し、その位置と、境界の左右で二次式がどう変化するかを記録する。境界をzの昇順に並べ、最初の区間で損失の二次式を作る。次の境界へ進むたびに、変化した重みの二次式の差分だけを加算し、区間内の二次関数の最小点を求めて最良候補を更新する。毎区間で全重みの損失を再計算する必要がない。

論文は、単純な全区間走査では計算が重いものの、区間境界をソートして差分更新することで計算を削減できると説明する。さらに、低損失領域を使って遷移点を減らし、zero-point探索の計算量をおおむねO(n log n)へ抑える工夫を加える（§4.2.1）。ここでnは量子化する重み数である。

### 3. coarse-to-fineによるscale探索

scaleを固定したzero-pointの最適化ができれば、残る探索変数はscaleだけになる。Min-Maxで得られるscaleを探索上限とし、その下の候補をT個に離散化する。全T候補に高価なzero-point最適化を行う代わりに、最初は約√T個の粗い候補を評価し、良い候補の近傍を再び細かく評価する（§4.2.2）。論文の既定値はT=2048、粗探索の候補数T_c=64である。

この二段階探索では、scale候補ごとにzero-pointの区分二次最適化を行い、最も小さいHessian重み付き量子化損失を与える組を選ぶ。したがって、scaleを適当に固定してzero-pointだけを改善する方式ではない。粗探索による候補の絞り込みには近似が入るが、Table 1の相対損失はほぼ1.000〜1.003に収まり、探索時間の大幅削減と引き換えの損失増加が小さいことを示す。

### 4. 浮動小数点zero-pointと実効ビット幅

従来のzero-pointはkビット整数である。NeUQIはzを浮動小数点で持つため、量子化重みの格子値を表現する整数コードはkビットでも、scale・zero-pointを格納する追加メタデータが必要になる。特にgroup-wise量子化ではグループごとにパラメータが増えるため、実効ビット幅を比較しないと不公平になる。

論文Table 5では、Llama2-7Bの2bit量子化でgroup=64の整数制約付き比較手法は平均2.28bit、NeUQIのgroup=128は平均2.25bitである。この条件でGPTAQはC4 PPL 12.56・5課題平均49.73%、NeUQIはC4 PPL 13.48・平均51.33%となる。**C4困惑度ではGPTAQの方が良く、平均正解率ではNeUQIの方が良い**。著者の強調する「少ない平均ビット幅で強い性能」は指標を分けて読む必要がある。

Appendix EではBitBLASが浮動小数点zero-pointに対応し、A100やRTX 4090などのGPUで利用可能と説明する。特殊なハードウェア改造が必須ではないが、すべての量子化形式・推論エンジンがそのまま対応するわけではない。既存の整数zero-point専用カーネルへ無変更で持ち込めると解釈しない。

## 主要結果

### 2bitチャネル別量子化

| モデル・指標 | GPTQ | GPTAQ | MagR | NeUQI | 出典 |
|---|---:|---:|---:|---:|---|
| Llama2-7B WikiText2 PPL | 6953 | 1269 | 129 | **17.14** | Table 2 |
| Llama2-7B C4 PPL | 2592 | 246 | 47.55 | **17.50** | Table 2 |
| Llama2-7B 5課題平均正解率 | 35.08% | 34.97% | 39.54% | **47.24%** | Table 2 |
| Llama2-13B WikiText2 PPL | 1735 | 145 | 47.98 | **13.72** | Table 2 |
| Llama2-13B C4 PPL | 433 | 62.05 | 27.94 | **14.39** | Table 2 |
| Llama2-13B 5課題平均正解率 | 35.60% | 35.95% | 38.74% | **48.76%** | Table 2 |

極端に大きなGPTQのPPLは2bitチャネル別という厳しい設定で発生したもので、一般的な4bit GPTQの性能を意味しない。MagRの比較は原著の追加座標降下反復を省いた条件が含まれるため、完全に同じ最適化予算で全手法の最良値を比較したものではない。NeUQIは2bitで特に強いが、4bitへ上げると既存手法との差が小さくなる。

### 初期化だけを変更した比較

Table 4では、Llama2-7Bの2bitチャネル別量子化でMin-Max+のWikiText2 PPL 498、MSE 65.42、LeanQuant 25.69、整数zero-pointのInt-Search 26.26に対し、NeUQIは17.14となる。Llama2-13BではInt-Search 15.67に対しNeUQI 13.72。単に探索を増やしたことではなく、整数zero-point制約を外したことが精度へ寄与するという著者の説明と整合する。

ただし、同じ量子化の下流課題の各項目が常に改善するわけではない。例えばTable 3のW4A4+Hadamardで、Llama2-7Bの5課題平均はNeUQI 62.77%、MagR 62.69%で、差は0.08ポイントと小さい。低ビットでの大幅改善をW4A4のような比較的緩い条件にそのまま当てはめるのは不適切である。

### Hadamard変換との組み合わせ

Table 3ではLlama2-7BにHadamard変換を併用した場合、W2A16のWikiText2 PPLはGPTQ 759、GPTAQ 64.88、MagR 13.79に対しNeUQI 12.41となる。W2A4ではNeUQI 13.63、MagR 20.42。W4A4ではNeUQI 5.99、MagR 6.02と差は小さい。したがって、分布を回転させて量子化しやすくする前処理と、量子化格子の初期値を最適化する処理は競合せず、組み合わせ可能である。

### 軽量蒸留とQATへの移植

Table 6では、Llama2-7B、2bit、group=128の条件でNeUQIに約0.5Mトークン×1エポックの軽量蒸留を加えると、WikiText2 PPL 8.38、C4 PPL 9.81、5課題平均56.77%となる。PV-tuningは約1Bトークン×1エポックでそれぞれ8.49、10.78、52.17%である。これは初期値の良さが後段の微調整効率へ影響することを示すが、蒸留データや実装条件が同一ではないため、学習トークン数の差だけで方法の優劣を確定しない。

Table 7ではEfficientQATの初期化だけをNeUQIへ置き換えると、Llama2-7BでWikiText2 PPL 7.19→6.81、C4 8.79→8.41、5課題平均59.50%→60.01%となる。さらに初段のscaleを凍結すると6.73、8.36、60.11%。Llama3-8Bでは元EfficientQATの9.80/13.22/59.37%に対し、NeUQI初期化+scale凍結は8.87/12.32/61.49%となる。量子化前処理だけでなく、後段の学習にも寄与する。

### 同程度の重みメモリでのモデル選択

Table 8ではQwen2.5-7Bの3bit NeUQI（主重みメモリ2.45GiB）が、Qwen2.5-1.5B BF16（2.62GiB）に対し、C4 PPL 11.72対12.54、5課題平均65.13%対61.30%となる。Qwen2.5-32B 3bit NeUQI（11.72GiB）はQwen2.5-7B BF16（13.05GiB）に対し、平均69.95%対68.04%である。これは**小さい高精度モデルより、大きい低精度モデルを選ぶ方が有利な条件がある**ことを示す。

ただしTable 8のメモリは主としてモデル本体の重みであり、実行時KVキャッシュ、作業領域、量子化メタデータ、カーネルの一時メモリなどの総VRAMを完全に表したものではない。例えば12GB VRAMのGPUで11.72GiBのモデルが確実に動くという意味ではない。

## 計算費用と負の結果

量子化処理時間（Appendix F, Table 10）は単一A40上の2bitチャネル別設定で、Llama2-7BがGPTQ 8.75分、GPTAQ 14.35分、MagR 21.87分、NeUQI **29.75分**。13Bでは15.70、27.23、49.70、**53.03分**、70Bでは76.72、178.08、396.45、**292.93分**となる。NeUQIは7B/13BでMagRよりも遅い一方、70BではMagRより短い。量子化前処理の速度はモデル規模によって相対順位が変わる。

Table 1の粗密探索は、基準となる全面探索の相対実行時間を約0.025〜0.028へ削減し、相対損失を1.000〜1.003程度に抑える。これは**NeUQI内部の最適化前後**の比較であり、NeUQI全体がGPTQより約40倍高速という意味ではない。実際にはTable 10のとおりGPTQより長時間を要する。

4bit量子化では既存手法との差が縮まり、表によってはNeUQIが最高精度にならない。例えばLlama2-7Bの4bit・group=128（Appendix H, Table 13）で5課題平均はGPTQ 64.53%、NeUQI 64.27%である。また3bit・group=128ではGPTAQ 62.84%、NeUQI 61.81%となる。主張の強さは2bitの厳しい設定で最も大きく、すべてのビット幅と評価指標で一律に優位ではない。

## 実装上の注意と限界

浮動小数点zero-pointは通常のkビット整数コードと別に保存されるため、実効ビット幅と実際の推論カーネル対応を確認する必要がある。論文はBitBLASでの対応を述べるが、一般的なGPTQ/AWQファイル形式や特定のローカル推論環境で、そのまま読み込めるとは示していない。既存のvLLMを評価バックエンドとして用いたことと、NeUQIの浮動小数点zero-pointをあらゆるvLLM構成で実行できることも同義ではない。

本手法の最適化対象はHessian対角近似に基づく層出力誤差であり、複数層をまたぐ誤差伝播を完全にモデル化するわけではない。zero-pointの区分二次最適化はscale固定・対角近似という条件で成立する。粗密探索も離散化されたscale候補を扱うため、モデル全体の損失についての数学的な厳密大域最適解ではない。

評価は言語モデルの困惑度と課題正解率が中心であり、生成token/s、TTFT、同時リクエスト時のスループットなど、サービング性能を直接測定した主要表はない。量子化後に追加の推論時演算を必要としないという設計上の利点はあるが、浮動小数点zero-pointを扱うカーネルの実装差による実機性能は別途検証が必要である。

## 既存研究との差

GPTQは重み量子化の誤差補償を行うが、scale/zero-pointの初期値にMin-Maxを用いる設定が残る。MagRは重みの分布を調整する別方向の改善であり、NeUQIは分布変換の後でも量子化格子の初期値を選び直せる。LeanQuantは損失に基づく探索を導入するが、Min-Maxに依存した候補表現と整数zero-point制約が残る。NeUQIは両制約を外し、scaleを固定したときのzero-point損失の区分二次構造を利用する点が固有である。

このため、NeUQIは独立した推論モデルや新しい量子化データ型ではなく、既存の一様量子化パイプラインへ組み込める初期化アルゴリズムである。Hadamard変換、蒸留、EfficientQATと併用した実験は、既存の量子化・学習手法を置き換えるだけでなく、それらの初期条件を改善する用途を示している。
