# SwiftSpec: Ultra-Low Latency LLM Decoding by Scaling Asynchronous Speculative Decoding

## 一文要約

小型draft modelの生成と大型target modelの検証を非同期・分離して独立にscaleし、**draft待ちをtargetのcritical pathから外しながら、tree状候補生成・KV管理・低latency kernelを組み合わせる**ことで単一requestのdecode latencyを下げるsystem。

## 書誌情報

- **Authors:** Ziyi Zhang, Ziheng Jiang, Chengquan Jiang, Menghan Yu, Size Zheng, Haibin Lin, Henry Hoffmann, Xin Liu
- **arXiv:** 2506.11309
- **初回公開:** 2025-06-12
- **Last checked:** 2026-09-07

## 問題設定

speculative decodingとtensor parallelismはどちらもdecodeを速められるが、draftとtargetの計算量差、両者のKV cache整合、small-batch tensor parallelismの通信overheadにより単純併用では効率が落ちる。

## 手法

SwiftSpecはdraft生成とtarget verificationを非同期pipelineとして分離し、各componentを別々にscaleする。draft側は複数候補をtreeとして並列生成し、target側はtree構造に対応したKV cache管理とfused kernelで検証する。これによりdraft生成をtarget検証の直前に逐次待つ構造を避ける。

## 評価条件

- 5 model family、6 datasetで評価。
- highlightとしてLlama-3-70Bを8× NVIDIA Hopper GPUで評価。
- 比較対象は既存のspeculative decoding system。

## 主要結果

- state-of-the-art speculative decoding system比で **平均1.75× speedup**。
- Llama-3-70Bを8 Hopper GPUで **348 token/s** でserveしたと報告。

## 既存研究との差

通常のspeculative decodingはdraft→targetを同期的に進めるためdraft latencyがcritical pathへ残る。SwiftSpecは両componentをdisaggregateして非同期化し、tensor parallel targetとdraft側scaleを独立に選べるようにする。

## 一般的な実装上の含意

低batch・低latency用途では、draft modelを単に小さくするだけでなく、draft生成をtargetの同期依存から外すことが重要になる。その代わりtree候補とKV cacheの世代・分岐をruntime側で一貫して管理する必要がある。

## 限界

- 複数GPUとcomponent分離を前提とするため、単一GPU環境では設計上の利点をそのまま得にくい。
- speedupはdraft acceptance、model family、hardware構成に依存する。
