# DynaCalKV: Key-Value Cache Compression via Head Grouping and Adaptive Rank Allocation

> キー投影の注意ヘッドをCKA類似度で動的に群分けし、群ごとの情報量に応じて低ランク次元を配分することでReCalKVよりキー側パラメータを減らすが、GQAの長文脈では精度低下も確認する。

## 概要

長文脈の推論ではKVキャッシュが系列長に比例して増え、GPUメモリを圧迫する。低ランク圧縮はキー・値投影行列を小さな二つの行列へ分解し、各トークンでは低次元の中間表現だけを保存することでKV容量を減らす方法である。圧縮率を高めれば保存量は減るが、行列近似の誤差が増えるため、どの層・どの注意ヘッドへ何次元を割り当てるかが品質を左右する。

DynaCalKVは、キーと値を同じ方法で圧縮せず、キー側で注意ヘッドの類似性を利用する。先行方式ReCalKVはキーの注意ヘッドを固定4個ずつまとめて低ランク分解するが、実際のヘッド間類似度はモデルや層によって異なる。DynaCalKVは中心化カーネル整合度（Centered Kernel Alignment; CKA）でヘッド表現の類似性を測り、似たヘッドを可変サイズの群へまとめる。さらに各群が持つ特異値エネルギーに応じて低ランク次元を配り、ReCalKV以下のパラメータ予算に収まるよう貪欲に削減する。

単一NVIDIA T4で1〜2B級の3モデルを評価した結果、キー側の圧縮パラメータ数はReCalKVに対してLlama-3.2-1B-Instructで18.23%、Qwen1.5-1.8B-Chatで16.00%、SmolLM2-1.7B-Instructで65.23%少なくなった。標準6課題の平均精度差はそれぞれ-0.1533、-0.8100、+0.4433ポイントと小さい一方、LongBenchではGQAを使うLlama-3.2-1B-Instructが平均-8.03ポイントまで悪化し、MHAのQwen1.5-1.8B-Chatは-1.02ポイントに留まった。したがって「パラメータ削減に対して一般性能を保ちやすい」という利点と、「GQAの長文脈では群分けが危険になり得る」という境界条件の両方が主要結果である。

## 問題設定

低ランクKV圧縮では、元の投影行列をランクrの二行列へ近似する。入力ベクトルに最初の小行列を掛けた低次元表現だけをKVキャッシュへ保存し、注意計算時に二つ目の行列で必要な表現を復元する。rを元次元より小さくすればトークンあたりの保存量を減らせるが、同じrをすべてへ割り当てると、重要な層や複雑なヘッドまで過剰に圧縮する可能性がある。

ReCalKVはキーと値の役割差を考慮し、キー側では複数ヘッドを群としてまとめて圧縮する。しかし群サイズを4ヘッドへ固定するため、互いに似た表現を持つヘッドが別群に分かれたり、似ていないヘッドが同じ群へ押し込まれたりする。さらに各群へ同様の圧縮率を使うと、低ランクで十分表現できる群と高いランクが必要な群の差を利用できない。DynaCalKVはこの二つの固定仮定、すなわち「群の切り方」と「群へのランク配分」を適応化する。

## 手法のあらまし

処理はすべてモデル圧縮時のオフライン工程で行い、オンライン推論へ新しいクラスタリング処理を追加しない。まず校正データから層ごとのフィッシャー情報量（Fisher Information）を求め、重要な層へ多くのランク予算を割り当てる。その後、キー投影と値投影で異なる圧縮を行う。

キー側では各注意ヘッドの表現からCKA類似度行列を作り、複数のクラスタ数候補についてヘッドを群分けする。各群を特異値分解し、特異値二乗和で測る情報量に比例して初期ランクを与える。総パラメータ数がReCalKVを超えないよう、1ランク削ったときの情報損失が小さい群からランクを減らす。最後に再構成誤差と未使用ランクへの罰則を合わせた目的関数でクラスタ数を選ぶ。値側はReCalKVと同様に行列全体を低ランク分解し、校正活性値に対する再構成誤差を閉形式更新で減らす。

### 1. CKAによる動的な注意ヘッド群分け

CKAは二つの表現行列の構造がどの程度似ているかを0から1で測る指標で、値が大きいほど似た表現を持つ。DynaCalKVはキー投影の各注意ヘッド間でこの類似度を計算し、類似度行列をクラスタリングへ入力する。固定順序で4ヘッドずつ切るのではなく、表現が似ているヘッドが同じ群に入りやすいようにするため、群ごとのヘッド数は異なる。

この変更の狙いは、似たヘッドを一つの低ランク部分空間で共有しやすくすることである。ヘッド間の冗長性が高い群なら、小さなランクでも元の投影を再現しやすい。逆に類似性が低いヘッドを無理に同じ群へまとめると、同じ誤差を保つために大きなランクが必要になる。動的群分けはモデルや層によって異なる類似構造を直接使うため、手作業で群サイズを指定する必要もなくす。

### 2. 特異値エネルギーに基づくランク配分

群を作った後は、各群へ何次元を割り当てるかを決める。DynaCalKVは群の特異値の二乗和を、その群に含まれる情報量の近似として使う。エネルギーが大きい群には多くの初期ランクを与え、エネルギーが小さい群には少なく配る。これにより、すべての群を同じ圧縮率にするより、再構成に必要な表現容量を群ごとに変えられる。

ただし可変サイズの群では、そのまま初期ランクを使うとReCalKVより総パラメータ数が増える場合がある。そこで1ランク減らしたときの特異値エネルギー損失を、群の大きさで正規化した費用として計算し、費用が最小の群からランクを一つずつ削る。ReCalKVと同等以下のパラメータ予算になるまで繰り返すため、DynaCalKVは「より柔軟な群分け」を使いながら、比較対象より大きなキー圧縮表現を使わない。

### 3. クラスタ数選択と値側の校正

クラスタ数を増やせば似たヘッドだけをまとめやすくなる一方、細かく分けすぎるとランク利用効率が悪くなる。DynaCalKVは各クラスタ数候補について低ランク近似を作り、元行列とのフロベニウスノルムによる再構成誤差と、割り当てられずに残ったランク数への罰則を足した目的関数を計算する。論文の実験では両項の重みを1として、その値が最小のクラスタ構成を採用する。

値側はキー側と同じ群分けを使わない。値投影行列全体を特異値分解した後、WikiText-2から得た校正活性値に対する出力誤差が小さくなるよう左右因子を閉形式で更新する。通常の特異値分解は重み行列そのものの近似誤差を最小化するが、実際の入力分布を考えた出力誤差とは一致しない。校正によって、モデルが実際に受け取る活性値に対する復元を改善する。これらの工程は圧縮時に一度だけ行うため、ReCalKVに対する追加のオンライン推論処理は発生しない。

## 評価

実装はPalu公式コードを基盤とし、同じ基盤上でReCalKVを再実装して比較条件を揃えている。ハードウェアは単一NVIDIA T4で、モデルはGQAのLlama-3.2-1B-Instructと、MHAのQwen1.5-1.8B-Chat、SmolLM2-1.7B-Instructである。校正にはWikiText-2を使い、一般性能はOpenBookQA、HellaSwag、PIQA、ARC-e、ARC-r、Winograndeの6課題、長文脈性能はLongBenchの8課題で測る。

キー側パラメータ数は、Llama-3.2-1B-Instructで3,612,672から2,953,920へ18.23%減り、Qwen1.5-1.8B-Chatで29,982,720から25,184,384へ16.00%減った。SmolLM2-1.7B-Instructでは33,988,608から11,818,176へ65.23%減っており、モデルによって削減幅が大きく異なる。論文はこの差の一因としてヘッド次元を挙げ、Qwen1.5の128次元に対し他2モデルは64次元であることを示している。

標準6課題ではReCalKVとの差が比較的小さい。平均差はLlamaで-0.1533、Qwenで-0.8100、SmolLM2で+0.4433ポイントである。PIQAとARC-eでは3モデルすべてで改善し、SmolLM2のHellaSwagでは+4.72ポイントとなった。一方OpenBookQAなど一部の推論課題では0.28〜3.00ポイント程度の低下があり、圧縮によって基礎知識検索より複雑な推論過程が影響を受ける可能性を著者らは指摘している。

長文脈では注意機構の違いが大きく現れる。MHAのQwen1.5-1.8B-ChatはLongBench平均でReCalKV比-1.02ポイントに留まり、SAMSumでは+0.71、QMSumでは+0.22ポイントだった。これに対しGQAのLlama-3.2-1B-Instructは平均-8.03ポイントで、TriviaQAでは-18.96、TRECでは-12.50ポイントと大きく下がった。SmolLM2はPalu、ReCalKV、DynaCalKVの全方式がLongBenchでほぼゼロ性能だったため、長文脈比較から除外されている。

この結果から、DynaCalKVの主な価値は「常に精度を維持する新圧縮方式」というより、キー側の表現冗長性を利用してReCalKV以下のパラメータ予算へ圧縮しつつ、MHAでは比較的良い品質を維持できることにある。一方GQAでは複数クエリヘッドが同じKVヘッドを共有する構造のため、キー側の圧縮誤差が長い文脈で広く影響する可能性があり、著者らも保守的な適用を推奨している。

## 既存研究との差

PaluやLoRCは投影行列を低ランク分解し、KVキャッシュへ保存する次元を減らす。AsymKVやReCalKVはキーと値の役割が異なることを踏まえて非対称に圧縮するが、ReCalKVのキー側は固定4ヘッド群と均一な圧縮率を使う。DynaCalKVはこの部分だけを拡張し、ヘッド間類似度から群サイズを決め、群の情報量に応じてランク予算を配る。

したがってDynaCalKVの差は、オンライン時にKVを出し入れするメモリ階層管理ではなく、モデル圧縮時にキー投影をどう分解するかにある。FlexiCacheやSnapKVのような系列方向のページ選択とは直交し、トークン数を減らすのではなく各トークンが保持する低次元表現を小さくする。理論的には系列方向の枝刈りと組み合わせられるが、本論文の評価は主にReCalKVとの圧縮パラメータ数とタスク精度の比較に集中している。

## 限界・実装状況

最大の制約は評価規模である。利用可能GPUの制約から1〜2B級モデルと単一T4に限定され、近年の大規模モデルで同じ傾向が維持されるかは検証されていない。特にGQAのLlama-3.2-1B-InstructでLongBench平均-8.03ポイントの低下があるため、大規模GQAへそのまま適用できる根拠は不足している。

また、システム全体の実測メモリ量、トークン毎秒、初回トークン時間などは主要評価ではなく、キー側の圧縮表現パラメータ数とタスク精度が中心である。パラメータ数削減が実際の推論基盤でどの程度のGPUメモリ削減や速度向上へつながるかは、実装するランタイムの低ランク復元カーネルやメモリ配置にも依存する。そのためシステム最適化として採用する際は、精度だけでなく実測のKV容量とデコード時間を別途検証する必要がある。

## 一般的な実装上の含意

圧縮率を一律に決めるより、構造的な類似性と情報量の両方を使って予算を配る方が効率的な場合がある。DynaCalKVでは「誰と共有するか」をCKAで決め、「どれだけ容量を与えるか」を特異値エネルギーで決める。この二段階の考え方は、注意ヘッド以外でも、複数エキスパートや層を共通表現へ圧縮するときに、固定グループと固定ランクを避ける設計原理として利用できる。
