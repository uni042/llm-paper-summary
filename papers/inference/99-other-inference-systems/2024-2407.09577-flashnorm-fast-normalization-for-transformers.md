# FlashNorm — RMS正規化と行列積の依存関係を解いて並列化する

## 概要

RMSNormは多くのLLMでattentionやFFNの直前に置かれ、活性ベクトルの二乗平均平方根で各要素を割り、学習済みスケールを掛ける。通常はRMSを計算し終わるまで後続の行列積を開始できない。GPUや専用アクセラレータがベクトル演算器と行列演算器を分けて持つ場合、RMS計算中は行列演算器が待機し、特にprefillのような大きなGEMMが続く箇所で並列実行の機会を逃す。

FlashNormは、この依存関係が数式の上では必須ではないことを利用する。RMSNormの学習済みスケールを後続の射影行列へ吸収し、RMSによるスカラー除算を行列積の後へ移す。行列積は未正規化の活性を入力として先に開始でき、別の演算器でRMSを同時に計算する。結果が出た時点で行列積の出力をRMSで割れば、理想的な実数演算では元の結果と等しい。学習済みモデルを再訓練せずに適用できる点が重要である。

原著はさらに、RMSNorm→Linear→RMSNormという連鎖では、RMSのスケール不変性を利用して最初の正規化自体を消去できる条件を示す。Q/K個別正規化やMLAの潜在正規化、RoPE、GLU系FFN、LayerNormなどへの拡張も検討する。ただし全ての正規化・bias・非線形演算で無条件に同じ変形が成立するわけではない。

T4 GPUのnorm-then-project単体実験では、SmolLM2-135M相当の4096トークンで0.704msから0.468msへ、8192トークンで0.929msから0.599msへ短縮した。一方、1トークンや64トークンの条件ではCUDA streamの起動・同期費用が利得を上回るため逐次経路へフォールバックし、改善は0%である。**この33〜35%は正規化＋射影の演算単体の遅延低下であり、LLM全体のprefill時間やTPSの改善率ではない。**

## 問題設定：小さな正規化が大きなGEMMを待たせる

入力活性ベクトルをa、正規化の学習済みスケールをg、次の線形層の重みをWとする。標準的なRMSNormは各要素に`g_i / RMS(a)`を掛ける。RMSは全要素の二乗和から計算するため、正規化済みベクトルを得るには全入力の集約が必要である。その後、射影`(a⊙g / RMS(a))W`を計算する。

RMS計算は主に要素ごとの二乗・加算・平方根であり、行列積とは実行資源が異なる。ハードウェア上で別のユニットが使えるなら、本来は同時に処理できる部分がある。しかし通常の計算グラフでは行列積の入力が正規化済み活性なので、RMSが終わるまでGEMMが開始できない。カーネル融合はメモリ往復や起動回数を減らせても、計算上の依存関係が残れば行列ユニットの待機を完全には解消しない。

FlashNormの目的は正規化の数学的な定義を変えずに計算順序を変え、ベクトル演算と行列演算を重ねることである。重要なのは、これが低ランク近似や量子化のようにモデル精度と速度を交換する方式ではなく、基本的には代数的な等価変換を利用する方式であることだ。ただし実機では浮動小数点演算の丸め順序が変わるため、ビット単位で完全一致することと数学的に等価であることは別問題である。

## 手法：重み吸収と正規化の遅延

### 1. 学習済み正規化係数を射影行列へ吸収する

元の出力は`y = (a⊙g / RMS(a))W`である。gは推論時には固定の学習済みベクトルなので、`W* = diag(g) W`を事前に計算して保存できる。すると`y = (a / RMS(a))W*`となる。元のRMSNormのgを別テンソルとして読み、活性へ要素ごとに掛ける処理が不要になる。モデルの重み数の総量が劇的に減るわけではないが、正規化係数の個別ロードと乗算を減らし、実装を簡素化できる。

この変形は重みの方向に注意する必要がある。行ベクトルaを右からWへ掛ける表記なら、gはWの入力チャネル側へ掛ける。実装の行列配置が転置されている場合は、吸収する軸も変わる。単純にgを出力チャネルへ掛けると誤った結果になる。バイアスを持つ線形層や正規化層の場合は、追加の変形が必要になる。

### 2. RMSの除算を行列積の後へ移す

RMS(a)はベクトルa全体から計算される一つのスカラーである。スカラー除算は線形行列積と可換なので、`(a / RMS(a))W* = (aW*) / RMS(a)`と書ける。右辺ではaW*を計算する際にRMS(a)を知らなくてよい。したがって、GEMMとRMSの計算を別のCUDA streamや演算ユニットで並列に進め、両方が完了した後にGEMMの出力をスカラーで割る。

元の順序は「RMS計算→活性のスケーリング→GEMM」だった。新しい順序は「GEMMとRMS計算を並列→GEMM出力をスケーリング」である。演算の総量がゼロになるわけではないが、GEMMを待たせる時間を短くできる。RMSの計算がGEMMより十分短く、GEMMが計算律速である場合に効果が出やすい。少数トークンでGEMMがメモリ帯域律速なら、並列化の同期費用の方が大きくなり得る。

### 3. 二つ目のRMSNormがある場合は前段を消せる

RMSには正のスカラー倍に対するスケール不変性がある。`RMS(ca)=|c|RMS(a)`であるため、正のcでベクトルをスケーリングしてからもう一度RMSNormへ入れる場合、前段のスケールが後段で打ち消される。原著Proposition 3は、RMSNorm→Linear→RMSNormという連鎖で、前段のRMSによるスケールを完全に消去できる条件を導く。

例えばQ/K個別の正規化を行うモデルや、潜在空間で正規化するMLAでは、二つの正規化が近接することがある。前段のスカラーRMS除算が後段の正規化で消えるなら、最初のRMSを計算する必要自体がなくなる。これは単なるGEMMとの並列化より強い削減である。ただし途中にスケールに対して不変でない演算、バイアス、非線形変換が入る場合は同じ論理をそのまま適用できない。

### 4. LayerNormとbias付き射影への拡張

LayerNormはRMSNormに加えて平均値を引き、学習済みbiasを足すことがある。平均値の引算は、直前の線形層の重みを変形することで吸収できる条件がある。直前の重み行列Vの行ごとの和を使い、各出力から平均を引く演算を、Vの各要素から対応する行平均を引く重み変形として表現する。これにより、平均中心化を別のカーネルとして実行せずに済む。

正規化bias βが続く線形層へ入る場合は、βWを後続の線形biasへ吸収できる。ただし、後段にbiasがあるとRMSによるスカラー除算を最終出力の全体へ単純に移すことはできない。スカラー除算を適用する位置とbias加算の順序を守る必要がある。FlashNormはこの例外を明示しており、LayerNormを含む全ての計算を一律に「正規化は最後へ移せる」と扱わない。

### 5. RoPE、QK正規化、FFNへの適用

QとKの正規化係数は、attentionの内積で組み合わされるため、RoPEの有無や位置ごとの回転に応じて吸収先が変わる。RoPEのcos/sin表へ正規化係数を事前に組み込める構成もあり、正規化のための独立した要素乗算を減らせる。RoPEが適用されないNoPEチャネルでは、QとKの係数を積として統合できる条件がある。ただし回転位置やヘッドごとの配置を無視して係数をまとめると等価性が失われる。

FFNでは、ReLUや線形ゲートを使うGLU変種の斉次性を利用して、正規化スケールを後段へまとめられる。ReGLUやbilinear GLUでは二つの分岐が掛け合わされるため、RMSの逆数が二乗で効く。原著はこれを平均二乗（MS）で扱う形へ変形する。GELUやSiLUなどの非斉次な活性化関数では、同じ簡単な式を無条件に適用できない。拡張の適用可否はモデルの演算グラフに依存する。

### 6. epsilonと数値精度の注意

実際のRMSNormはゼロ除算を防ぐため`RMS_ε(a)=sqrt(mean(a²)+ε)`を使う。εを入れたRMSは厳密なスケール不変性を失うため、二つ目のRMSNormが前段を完全に打ち消すという代数的主張には条件が付く。通常の活性エネルギーがεより十分大きければ差は小さいが、極端に小さい活性では無視できない。原著はεを考慮した付録を設け、数学的に厳密な式と実装上の近似誤差を区別する。

重みfoldingは学習済み係数を重みに掛けるため、低精度形式では重みの値域と丸め誤差が変わる。量子化との組合せは潜在的に有利だが、原著は系統的な比較を将来課題とする。FlashNormを使えばどの量子化モデルでも同精度になるという保証はない。

### 重みfoldingの品質検証

重み吸収は、正規化係数gを後続行列へ事前に掛けるため、モデルを再学習せずに変換できる。原著Table 1ではSmolLM2-135M、Llama-3.2-1B、Llama-3.1-8Bのwikitext、MMLU、HellaSwagで、変換前後の評価結果に損失がないことを確認した。ただしこれは重みfoldingの検証であり、全てのモデル演算を並列実行した場合の数値誤差や、任意の量子化形式への変換の品質を全面的に保証するものではない。

### ハードウェア分析の意味

原著はベクトルユニットと行列ユニットを持つ抽象プロセッサを考え、n=512、演算器幅m=128の例で、逐次実行ではRMSとスケーリングのため行列ユニットに8サイクルの待機が生じることを示す。行列重みを工夫して処理しても待機は残るが、FlashNormでは行列積とRMSを並列化できる。これは**演算資源の同時利用**の分析であり、GPUの実測速度はメモリ階層、カーネル実装、stream同期費用によって変わる。理論上のサイクル削減とT4の実測結果は区別すべきである。

## 既存研究との差

RMSNormの単体カーネルを高速化する手法は、二乗和の計算やメモリアクセスを最適化する。FlashNormは、正規化を単独の演算として速くするのではなく、**次の線形射影と合わせた計算グラフを変形**する。重みfoldingで正規化係数の乗算を消し、除算の位置を変えてRMSとGEMMの依存を解く。FlashAttentionがsoftmaxの正規化分母を遅延して注意計算を効率化する考え方と似ているが、対象はRMSNormと線形射影であり、注意のKVキャッシュやIO複雑性そのものを最適化する方式ではない。

BatchNormのfoldingはCNNで広く使われるが、FlashNormはLLMのRMSNormと後続のattention/FFN射影を対象にし、単なる重み統合に加えて正規化の遅延・消去の条件を整理する。既存の量子化前処理でチャネルスケールを重みに吸収する操作とも関係するが、FlashNormは量子化誤差を減らすことを主目的としない。両者を組み合わせる場合は、スケール吸収後の重み分布と量子化の較正を再検証する必要がある。

## 限界と実装判断

第一に、効果はprefillのような大きなGEMMで顕著である。デコードの少トークン条件では逐次フォールバックとなり、速度利得はゼロである。FlashNormはモデル全体のattentionやFFNの計算量を劇的に減らすものではない。norm-then-projectの局所遅延が35%減っても、モデル全体のTTFTやTPSが同じ割合で改善するとは限らない。

第二に、計算グラフの形に依存する。正規化と線形射影の間に非線形変換や複雑なバイアスがあると、単純な重みfoldingやスカラー除算の遅延は成立しない。Q/K正規化、RoPE、MLA、GLUなどへの拡張には、それぞれ係数の吸収先と演算順序の条件がある。Transformer実装を自動的に書き換える場合、モデルごとの構造検査が必要になる。

第三に、数学的な等価性は実数演算での議論であり、浮動小数点では演算順序の変更で丸めが変わる。εが入ったRMSではスケール不変性が厳密でなくなり、活性が非常に小さい場合に差が生じ得る。量子化された重みや低精度活性での体系的な検証は将来課題である。

第四に、並列化には実装費用がある。CUDA streamを複数使い、GEMMとRMSを同時に実行しても、stream同期やメモリ競合が大きいと改善しない。原著はハードウェア依存の閾値で逐次経路へ切り替える。GPU世代やバッチサイズが変われば最適閾値も変わるため、固定したトークン数で全環境へ適用するべきではない。

実務上は、既存LLMを再学習せずにprefillの局所演算を軽くしたい場合、まず正規化係数の重みfoldingを行い、モデル出力の一致を確認する。その後、GEMMが計算律速となる入力長でだけRMSとGEMMの並列化を有効化し、デコードでは逐次経路を維持するのが原著に沿った使い方である。実際のサービングで採用するには、TTFT、TPOT、TPS、精度、量子化との相互作用を個別に測定する必要がある。
