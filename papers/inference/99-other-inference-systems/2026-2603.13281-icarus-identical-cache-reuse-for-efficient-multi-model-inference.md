## 概要

複数の専門LLMを組み合わせるエージェント処理では、同じ会話履歴や共有文書を複数モデルが読む。それでも通常はモデルごとに異なる重みからK/Vを計算するため、同一入力でもKVキャッシュを共有できない。モデル数に比例してKV容量が増え、GPUメモリ不足でキャッシュが追い出されると、後で同じ入力を再度プリフィルする費用まで発生する。

ICaRusはdecoder-only Transformerを概念的に二分し、KVを作る前半を「論理encoder」、次トークンを予測する後半を「論理decoder」とする。専門化時にencoderを凍結し、decoderだけを調整すれば、全専門モデルのencoder出力は同一になる。したがって同一promptについて一つのKVキャッシュを全モデルで共有できる。8モデルの複数エージェント処理では従来方式に対してP95遅延を最大11.1倍削減し、スループットを最大3.8倍高めた。

## 問題設定

通常の微調整は全層または各層の低ランク適応（Low-Rank Adaptation; LoRA）を変更するため、同じベースモデルから派生した専門モデルでもKVは一致しない。接頭辞キャッシュは「同じモデル・同じ入力」では有効でも、別checkpoint間では再利用できない。この制約はモデル数が増えるほどKV容量を線形に増やし、長い共有履歴を持つエージェント型ワークロードで深刻になる。

ICaRusの難点は、共有KVを作る部分を固定しても専門タスクの精度を維持できるか、そしてdecoder側の追加計算によって共有で得た速度利得を失わないかである。

## 手法

### 論理encoder / decoder分割

各Transformer層を、K/Vを生成して共有キャッシュへ書く論理encoderと、そのK/Vを読みながらquery側を処理して次token予測へ寄与する論理decoderとして再解釈する。専門モデル間でencoder重みを完全に同一に固定すれば、同じprompt tokenから生成される全層KVも同一になる。

この分割の出力は通常の層別KVキャッシュであり、モデルごとにコピーを持つ必要がない。新しい専門モデルを追加しても、増えるのは主にdecoder側の差分で、共有promptのKV容量はモデル数に比例しなくなる。

### decoderのみのタスク適合

タスク別学習ではencoderを凍結し、論理decoderだけを調整する。これにより専門化によるパラメータ差がKV生成経路へ侵入しない。Qwen3ではこの制約下でも通常のタスク別微調整に近い、あるいは一部条件で上回る精度を示す。

一方、LLaMA-3.1-8BのGSM8KではICaRus 67.9に対して通常微調整69.7という条件もあり、凍結encoderが常に無損失とは限らない。この負の結果はシステム利得と品質制約を同時に見る上で重要である。

### LoRAを用いた並列デコード

decoder差分を軽量adapterとして持つ場合、共有encoder側のKV生成と専門decoder側の次token予測を並列化できる。さらにquery表現をまとめてグループ化クエリ注意（Grouped Query Attention; GQA）を一度実行することで、共有KVを複数回読み直す帯域費用を抑える。

これにより「KVは共有できるがdecoder計算が二重化して遅い」という問題を緩和する。特にデコードではKV読出しが帯域律速になりやすいため、共有キャッシュを一度読む構造が重要になる。

## 評価条件

| 観点 | 内容 |
|---|---|
| モデル | LLaMA-3.1-8B、Qwen3 1.7B/8B/14B/32B |
| 専門モデル数 | 最大8 |
| ワークロード | タスク別推論、ReAct型複数エージェント |
| 指標 | タスク精度、P95遅延、スループット、KV再利用 |
| 比較 | 通常の複数微調整モデル、swapを伴う方式 |

## 主要結果

8専門モデルのReAct処理では、通常の複数モデル構成に対してP95遅延を最大11.1倍削減し、スループットを最大3.8倍高めた。swapを使う比較条件ではP95遅延の改善が最大12.1倍に達する。モデル数が増えるほど重複KV容量と再計算が増えるため、共有の利得も大きくなる。

品質ではQwen3-8BのGSM8Kで87.3対85.4、Qwen3-14Bで88.8対85.6と通常微調整を上回る例がある一方、LLaMA-3.1-8Bでは67.9対69.7と1.8ポイント低い。したがって「encoder凍結は常に品質を改善する」のではなく、モデル・タスク依存の交換条件がある。

## 既存研究との差

従来のKV再利用は同一checkpoint内の接頭辞共有を主対象にする。ICaRusは学習方法そのものを制約して、異なる専門モデルのKV生成経路を同一にすることでcheckpoint間共有を可能にする。キャッシュを事後変換するのではなく、専門モデル群を最初から共有可能な構造として作る点が異なる。

## 限界

既に独立に微調整済みの任意checkpoint同士へ後付けで適用できる方式ではなく、専門化時からencoder凍結を採用する必要がある。タスクによっては精度低下があり、decoderだけで必要な専門化を表現できるかを検証する必要がある。最大倍率は共有promptが多く、モデル数が多いワークロードで得られるため、単一モデル推論では主な利点がない。
