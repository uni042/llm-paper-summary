# LLM-CoOpt：異種計算装置向けKV・注意・ページ管理の共同最適化

## 概要

LLM-CoOptは、一般的なGPUとはメモリ階層や実行単位が異なる計算装置にvLLMを移植したときの推論効率を改善するシステム最適化である。著者は、鍵・値キャッシュ（Key-Value Cache; KVキャッシュ）の不要な書込みと読出し、複数の注意ヘッドで重複する鍵・値の演算、長文脈でのページ参照と同期を三つの主要な問題とみなす。それぞれOpt-KV、Opt-GQA、Opt-Paという最適化を導入し、組み合わせた効果をDCU Z100装置上で検証する。

本文第4.3節の5種類のLLaMA系GPTQモデルでは、生成処理量が5.72～12.13%増加し、推論遅延が4.82～6.75%短縮した。ただし要旨には「最大13.43%の処理量向上、最大16.79%の遅延短縮」とあり、本文で列挙されるモデル別値と一致しない。ARC-Cの正答率でも本文説明と表の値に食い違いがある。したがって本稿では、再現条件を確認できるモデル別測定値と原著の未解決な記述不整合を分けて扱う。

## 背景と問題設定

自己回帰復号では、各トークン生成時に過去の鍵と値を参照する。キャッシュ容量は文脈長、層数、鍵・値ヘッド数などに応じて増え、低バッチ時にはモデル重みとKVの読出し帯域が性能を制約する。vLLMはPagedAttentionによってKVのページ管理を行うが、実装を別の計算装置へ移すと、ページ割当、無効領域の読出し、メタデータの参照、スレッド間同期などの費用が装置特性と合わない場合がある。

論文が対象とするDCU Z100は、波面（wavefront）64スレッド、L2キャッシュ約4MB、GDDR6帯域約512GB/s、FP16理論ピーク約15TFLOPSの装置である。FP8演算はINT8命令によって模擬されると記されており、NVIDIAのFP8 Tensor Coreによる実行と同じではない。論文はGPUとCPUのメモリ領域が物理的に分かれていることも述べる。最適化の動機は、この装置のメモリ階層と演算・同期特性に合わせてvLLMのホットパスを変更することにある。

既存のKV量子化、グループ化クエリ注意（Grouped-Query Attention; GQA）、ページ注意はそれぞれ知られた技術である。本研究の主張は、それらを異種計算装置向けに共同調整し、メモリ書込み、読出し、注意演算、ページ単位の計算を連続した推論経路として改善する点にある。新しい注意数学モデルや新しい低ビット量子化理論を提案したものではない。

## 手法

### Opt-KV：不要書込みの除外とFP8読出し

KVキャッシュの書込み時に、トークンのスロット番号が負であるか、除外対象集合SkipSetに含まれる場合には対応する鍵・値を格納しない。無効・重複・不要なスロットを除外して、キャッシュの割当と書込み帯域を減らす。必要なスロットはブロック単位で配置し、保存形式をFP8へ変換する。読出し時にはキャッシュから鍵・値を取得し、注意演算へ渡す前にオンデマンドで逆量子化する。原著は `gather_cached_kv` に相当する専用カーネルによって変換と取得を実装する。

この方式はKVの低ビット化による記憶量削減と、無効なスロットを扱わないアクセス削減の組合せである。FP16からFP8へ保存精度を下げる場合、KVデータの理論的なビット数は半分になるが、実際のメモリ使用量にはスケール、ページ管理情報、アラインメント、バッファなども含まれる。論文は各項目の総VRAM差を独立した定量表で網羅しているわけではないため、全体メモリが必ず半分になるとは扱わない。

また、KVを保存する前にどのスロットを除外してよいかは意味的に重要である。論文のアルゴリズムはスロット番号とSkipSetの判定を示すが、SkipSetの構築が品質に与える影響や、除外の誤判定時の復元手段を十分に定量評価していない。量子化誤差とアクセス除外を区別して検証する必要がある。

### Opt-GQA：鍵・値ヘッドを共有する注意計算

通常の複数ヘッド注意（Multi-Head Attention; MHA）では、各クエリヘッドに対応する鍵・値を持つ。GQAは複数のクエリヘッドを一つの鍵・値ヘッドへ対応させ、KVキャッシュと注意演算の重複を減らす。Opt-GQAは、クエリヘッド数H_qとKVヘッド数H_kからグループ当たりのクエリヘッド数H_g=H_q/H_kを求め、各クエリを対応するKVグループへ割り当てる。各グループ内でsoftmax注意を計算し、グループ出力を連結する。

原著は「動的グループ化」「柔軟なグループ分割」と表現するが、本文の主要な式はヘッド番号を固定したグループ幅で割る方式を示す。実行時に入力分布やGPU負荷に応じてグループ構成をどのように変えるか、ヘッド数を変更したときに既存モデルの学習済み射影行列をどう適合させるかについて、独立した詳細なアルゴリズムと評価は限定的である。したがって、標準的なGQAの共有構造を装置向けに実装したものと、学習済みモデルの構造を動的に変更するものを混同してはならない。

### Opt-Pa：有効ページの選別とブロック内集約

長文脈のページ注意で、実際の入力長に対応する有効ブロックだけを処理する。入力長tとページ大きさBから参照範囲を決め、パディングや無効なページを除外する。鍵を共有メモリへ読み込み、ブロック内でクエリと鍵の内積を計算し、最大値を引いた安定化softmaxを求める。論文はwarp単位の集約に代えて共有メモリを使う `block_sum` を記し、同期とブロードキャストの費用を抑えることを狙う。

この最適化は、注意の計算量そのものを任意の文脈長で線形へ変えるものではない。無効なページを飛ばしても、必要な過去トークンに対する注意の計算は残る。従来のPagedAttentionがページ単位のKV管理を行うのに対し、Opt-Paはそのページを計算カーネルでどう選択・集約するかに重点を置く。著者の実装がDCU Z100に依存するため、別のGPUで同じ共有メモリ集約が有利とは限らない。

### 三方式の組合せ

Opt-KVはキャッシュの書込みと読出し、Opt-GQAは注意ヘッド間のKV共有、Opt-Paは実際に参照するページと集約処理を担当する。処理経路としては、トークンの有効スロットを決めてFP8でKVを保存し、注意時に有効ページだけを取得して逆量子化し、共有KVヘッドのグループに沿ってsoftmaxを計算する。三方式は別々の性能要因を狙うため、単一の改善だけで説明できない複合効果を期待できる。

一方、各最適化は完全に独立ではない。KVのヘッド数やページ配置が変わるとメモリ帯域と集約の粒度が変わる。量子化の復元処理は演算費用を増やす可能性があり、グループ化は学習済みモデルのヘッド構成に制約される。これらの交換条件を、単一方式と組合せ方式の評価で検証する必要がある。

## 評価

### 実験環境と比較条件

| 項目 | 設定 |
|---|---|
| 装置 | DCU Z100、L2約4MB、GDDR6約512GB/s、wavefront=64 |
| 計算 | FP16理論ピーク約15TFLOPS、FP8はINT8命令による模擬 |
| 推論基盤 | 移植したvLLM、未最適化版をOriginalとして比較 |
| モデル | LLaMA-7B-GPTQ、LLaMA2-7B-GPTQ、LLaMA-13B-GPTQ、LLaMA2-13B-GPTQ、LLaMA-Pro-8B-GPTQ |
| 処理量評価 | ShareGPT V3 unfiltered cleaned split、約35,240会話、約178MB |
| 品質評価 | ARC-Challenge（ARC-C）、ARC-Easy（ARC-E） |
| 指標 | 推論遅延、生成トークン/秒、4択質問正答率 |

論文は複数のモデルを同じDCU装置で評価するが、複数GPUのスケールアウト、PCIe/ネットワーク帯域を変えた場合、NVIDIA CUDA GPU上での同等実装を評価したものではない。入力長・出力長・バッチ分布などの細部を網羅した独立の比較表が十分ではないため、他のLLMサービング研究との数値比較には制約がある。

### モデル別の遅延と生成処理量

| モデル | 遅延短縮（%） | 生成処理量増加（%） |
|---|---:|---:|
| LLaMA-7B-GPTQ | 5.59 | 7.20 |
| LLaMA2-7B-GPTQ | 5.48 | 6.13 |
| LLaMA-13B-GPTQ | 6.18 | 12.13 |
| LLaMA2-13B-GPTQ | 6.75 | 10.85 |
| LLaMA-Pro-8B-GPTQ | 4.82 | 5.72 |

この表は原著第4.3.1節の文章に列挙された値である。モデルによって改善率は異なり、13B系で処理量改善が大きい傾向が見られるが、個々のモデルでKV帯域、ヘッド共有、ページ処理のどれが主因かを切り分ける追加の装置内指標は限定的である。**要旨の最大13.43%処理量向上・16.79%遅延短縮は、この本文の5モデルの最大値12.13%・6.75%と一致しない。** 同じ評価条件の最大値として無条件に置き換えることは避ける。

### ARC-CとARC-Eの品質

| モデル | ARC-C Original | ARC-C LLM-CoOpt | ARC-E Original | ARC-E LLM-CoOpt |
|---|---:|---:|---:|---:|
| LLaMA-7B | 27.46% | 27.80% | 30.16% | 31.04% |
| LLaMA2-7B | 35.93% | 36.93% | 48.15% | 49.03% |
| LLaMA-13B | 39.66% | 40.01% | 52.03% | 53.20% |
| LLaMA2-13B | 50.85% | 51.53% | 71.08% | 71.25% |
| LLaMA-Pro-8B | 27.46% | 27.72% | 42.15% | 42.50% |

表の数値は原著表1・表2の転記である。原著第4.3.2節の説明文には「LLaMA2-7BのARC-C正答率は変化せず、LLaMA-Pro-8Bは27.46%から27.12%へわずかに低下した」と書かれるが、**表1はそれぞれ35.93→36.93%、27.46→27.72%と示す**。本文と表が矛盾するため、表に従って全モデルが微増したと断定するのも、説明文に従って一部が悪化したと断定するのも危険である。公式の実行ログや訂正版がない限り、品質の結論は「原著は大きな悪化を報告していないが、個別値の再確認が必要」と留保する。

品質評価は選択式のARCに限定される。KVのFP8化と注意実装変更が長文生成の一貫性、コード生成、数学、長文脈検索などに与える影響は別途確認が必要である。量子化誤差が小さいことと、全タスクで生成が同一であることは別である。

### 感度・構成要素・メモリに関する未評価項目

本文は三方式の構造とモデル別の総合改善を記す一方、GPUメモリのピーク使用量、実際のKV圧縮後のバイト数、FP8復元費用、キャッシュ命中率、文脈長に対する各方式の感度、バッチ数別の改善率を網羅した数値表は提示していない。Opt-KV、Opt-GQA、Opt-Paの個別の改善がどの程度加算・相乗するかも、少なくとも本文からは主要性能表と同じ粒度で独立に検証できない。したがって理論上のKVビット数削減を実測の総メモリ削減率と同一視しない。

## 限界・再現性・適用範囲

第一に、実験の主要対象はDCU Z100であり、装置の波面幅、キャッシュ容量、FP8命令の実現方法がNVIDIA GPUと異なる。vLLMの一般的なCUDA版へそのまま同じカーネルを適用した際の高速化は未確認である。単一GPUの測定からマルチGPU分散推論、CPUオフロード、複数モデル混載の結果は推定できない。

第二に、要旨とモデル別評価値が一致せず、ARC-Cについては表と説明文が食い違う。品質評価で原著の内部整合性が十分でない点は、研究の比較・再現において重要な制約である。実装コードの公式URLも確認できないため、カーネル単体の再測定や原著の実験条件の完全再現には追加資料が必要である。

第三に、GQAのクエリヘッド共有を既存モデルへ適用する際の重み構造、KVヘッド数、既存モデルとの互換性を厳密に確認する必要がある。論文の動的適応に関する説明は、提示された固定グループ割当式より広い主張を含んでおり、動的変更を独立の実測成果として扱わない。Opt-Paは無効ページを除外する実装最適化であり、長文脈での注意計算量の理論的な削減を保証しない。

## 既存研究との差

PagedAttentionはKVをページ単位で管理する仕組みを提供し、LLM-CoOptのOpt-Paは有効ページだけを計算対象へ取り込み、装置の共有メモリを使った集約を改善する。GQAは複数のクエリヘッドで鍵・値を共有するモデル構造であり、Opt-GQAはその共有に合わせて装置側の注意演算を構成する。KVの低ビット化は既存研究にもあるが、Opt-KVは無効スロットを飛ばす書込み経路と、FP8保存からの読出し時復元を同じ推論パスへ組み込む。

この研究を評価する際は、三方式がすべて新しいアルゴリズムであると解釈するより、既知の最適化を特定装置へ共同移植し、メモリ・計算・ページ管理のホットパスを改善したシステム研究として捉えるのが適切である。現時点では、数値の内部整合性と公開実装による再現可能性が主要な確認課題となる。
