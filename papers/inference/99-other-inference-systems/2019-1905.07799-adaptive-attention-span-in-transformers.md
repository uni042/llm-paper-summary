## 概要

標準自己注意は、許可した文脈 window内の全過去位置へ同じ最大範囲で注意機構を計算する。しかし実際には、すべてのヘッド・層が同じ長さの履歴を必要とするとは限らない。短距離の構文的パターンだけを使うヘッドへ長いwindowを割り当てると、メモリと計算を消費する。

Adaptive Attention Spanは、各注意機構 ヘッドが参照できる過去範囲を学習可能にする。ヘッドごとのspan パラメータより遠い位置はsoft maskで抑え、学習中にspanへ正則化を掛けることで、精度に必要な範囲だけを残す。これにより最大文脈を大きく設定しても、実際の平均注意機構範囲を短くできる。

論文はcharacter-level language modelingで最大8K charactersの文脈を使い、text8とenwiki8で状態-of-the-art性能を報告する。主眼は現代的なdecoder-only LLM 推論提供ではないが、注意機構の有効履歴を入力・ヘッドごとではなく学習済みヘッド単位で縮め、計算量とメモリ footprintを直接制御する先駆的な推論効率機構である。

## 問題設定

自己回帰Transformerで長い履歴を使うには、各問い合わせが多数の過去key/valueへ注意機構する。固定windowを伸ばすほど保存する状態と注意機構計算が増える。一方、ヘッドによって役割が違うため、全ヘッドへ最大windowを強制するのは非効率である。

固定の短いwindowでは、長距離依存を必要とするヘッドまで切ってしまう。そこで「最大windowは大きく用意するが、各ヘッドが必要なspanだけを学習する」という構成にし、品質と資源消費の交換条件を学習へ委ねる。

## 手法

各注意機構 ヘッドにspan パラメータを導入し、問い合わせから遠いkeyほどmask値が減衰する連続的なmaskを注意機構 重みへ掛ける。span以内の位置は通常どおり利用でき、境界付近は滑らかに減衰するため、離散的なwindow長を直接探索するより勾配学習しやすい。

span パラメータには長い範囲を使うほど不利になる正則化を加える。言語モデル損失が遠距離情報を必要とすればspanを伸ばす方向の勾配が勝ち、不要なら正則化によって短くなる。結果として層/ヘッドごとに異なる有効文脈が形成される。

推論・学習実装では、学習されたspanより遠いkey/valueを注意機構対象から外せるため、単にmaskを掛けるだけでなく計算自体を省ける。特に最大文脈を8Kのように大きくしたとき、短いspanのヘッドが多数あれば、全ヘッドで8Kを計算する場合よりメモリと計算時間を抑えられる。

論文はさらに動的なspanを扱い、現在の入力状態に応じてspanを調整する拡張も検討する。基本機構の利点は、注意機構 ヘッドの専門化と文脈 budgetを結びつけ、長距離依存が必要なヘッドだけへ資源を残すことにある。

## 評価

| 観点 | 条件 |
|---|---|
| タスク | character-level language modeling |
| dataset | text8、enwiki8 |
| 最大文脈 | 8K characters |
| 比較軸 | 固定注意機構 spanと適応型 span、言語モデル性能 |
| 資源面 | 注意機構 span短縮によるメモリ footprintと計算時間の制御 |

論文はtext8/enwiki8で当時の状態-of-the-artを達成しつつ、ヘッドごとに異なるspanが学習されることを示す。長い最大文脈を与えても全ヘッドが最大範囲を使うわけではなく、短距離ヘッドと長距離ヘッドへ役割が分かれる。

この結果は、文脈 lengthをモデル全体で一つの固定値として扱う必要がないことを示す。長距離情報を保持する能力を残しながら、不要な注意機構 edgeを削ることで資源を抑えられる。

## 既存研究との差

固定局所 注意機構は設計者がwindowを決めるため、タスクやヘッドの役割に対して短すぎる・長すぎる可能性がある。Adaptive Attention Spanはwindowを学習対象にし、ヘッド単位で異なる範囲を獲得する。

後年のsparse 注意機構やKV 追い出しはトークン重要度やブロック patternを推論時に選ぶ方式が多いのに対し、本方式は注意機構 ヘッドが必要とする距離そのものを学習する。選択粒度と適用時期が異なる。

## 限界

評価は2019年のcharacter-level Transformerであり、数十億パラメータの現代LLM、PagedAttention、continuous batching、GPU カーネル融合を含む推論提供 stackでのエンドツーエンド速度は評価していない。8K charactersは現代の長文脈LLMより短く、絶対的なシステム効果をそのまま移せない。

また、ヘッド単位の固定的な学習spanでは、同じヘッドでも要求ごとに必要文脈が大きく変わる場合の最適性に限界がある。短縮したspanを実際のGPU カーネルで効率よく不規則実行できるかも、理論的な注意機構削減とは別の実装問題である。
