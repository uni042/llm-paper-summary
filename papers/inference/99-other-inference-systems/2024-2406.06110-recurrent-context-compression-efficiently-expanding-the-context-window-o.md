# Recurrent Context Compression：反復的な文脈圧縮でLLMの有効文脈を拡張する

## 概要

長文脈の大規模言語モデル（LLM）では、入力トークンの増加に伴ってKVキャッシュの保存量と注意演算の費用が増える。通常のTransformerは、学習時の文脈窓を超えると品質が落ちやすいという別の問題もある。Recurrent Context Compression（RCC）は、長文を短い区間へ分割し、各区間の情報を少数の隠れベクトルへ圧縮して復号器に渡す方式である。これにより、符号化器が一度に処理する長さを抑えながら、復号器からは長文全体を要約した連続表現を参照できる。

論文の新規性は三つある。第一に、符号化器の最終層だけでなく**各層の隠れ状態**を復号器へ接続して圧縮表現の情報量を高める。第二に、短い系列で全パラメータを学習してから符号化器を固定し、長い系列では復号器を学習する二段階方式を採用する。第三に、質問文と文書を一緒に圧縮すると質問の命令性が失われる問題を認識し、復号器に質問文を一度復元させてから回答させる指示再構成を導入する。

主張する32倍圧縮時のBLEU-4約0.95は、特定の短文再構成タスクでの値である。100万トークン級のパスキー検索でほぼ100%という結果は、別途512倍圧縮の専用学習をした合成検索課題である。実文書質問応答ではLongBenchの平均スコアが20点台に留まり、指示再構成が長文で不安定になる。**圧縮率、合成検索の正答率、実文書QAの性能は同じ指標ではない**（原著図3、表1、表2）。

## 問題設定と先行研究との差

文脈圧縮では、入力文脈の全トークンを復号器へそのまま渡す代わりに、符号化器が少数の連続ベクトルを生成する。Gistトークン方式やIn-Context Autoencoder（ICAE）などの先行研究では、圧縮率を高めると文脈情報が失われ、特に長文で品質が低下しやすい。短文で学習した圧縮器をそのまま非常に長い文書へ適用すると、符号化器の文脈窓と訓練時の系列長の双方が制約となる。

RCCは、長文全体を単一の状態へ押し込むのではなく、**一定長ごとに圧縮状態を取り出し、得られた状態列を復号器へ渡す**。このため、復号器が保持する表現数は元の入力長に比例するが、その比例係数を圧縮率だけ小さくできる。Mambaのような状態空間モデルを動機にしつつ、Transformer符号化器でも一定区間の隠れ状態から要約を作れることを利用する。全履歴を厳密に固定個数の状態へ格納する方式ではない。

また、従来の圧縮研究では、入力文書とユーザーの命令を同じ方法で圧縮する場合の影響が十分に扱われていなかった。質問の「何を答えるか」という指示が文書内容の一部として符号化されると、復号器は質問文と回答すべき情報を区別できなくなる。RCCは、文脈内容を圧縮しつつ、復号器が命令の意味を明示的に復元する補助タスクを導入する。

## 手法

### 1. 区間ごとの反復圧縮

入力文脈を符号化器の窓長以下の短い区間に分割する。論文の図2では、符号化器の最大窓長が2,048トークン、圧縮率が32の場合を示す。各区間内で32トークンごとの位置から隠れベクトルを取り出すため、2,048トークンの区間から64個の圧縮ベクトルを得る。区間を順に処理して圧縮ベクトルを連結すれば、元の長文を64個ずつの表現へ縮約できる。

ここで「再帰」は、長文を区間ごとに繰り返し処理するという意味であり、Mambaのような厳密な固定サイズ状態遷移を必須とするわけではない。区間間の圧縮ベクトルは独立して作られ、同一区間内の圧縮ベクトルには符号化器の注意を通じた依存関係がある。全区間の圧縮結果は復号器側で相互に注意を向けられるため、遠く離れた区間の情報を組み合わせて回答できる可能性がある。ただし区間ごとの圧縮で失われた詳細を完全に復元できる保証はない。

圧縮率r、復号器が扱える圧縮ベクトル数をWとすると、概念的には元入力の有効長をr×Wまで拡張できる。これは圧縮器が情報を失わずにr×Wトークンを理解できるという保証ではなく、**入力長に対して必要な復号器側の記憶位置数が減る**という容量上の関係である。符号化器の処理時間と重みメモリも残るため、推論の総計算量がr分の1になるとは限らない。

### 2. 層ごとの圧縮状態を復号器へ渡す

RCCの符号化器は事前学習済みのPythiaやMambaを使い、復号器はTransformerを使う。ICAEのように最終層の表現だけを一度に渡すのではなく、符号化器の各層で取り出した圧縮ベクトルを線形写像して、対応する復号器層へ残差接続する。復号器の最初の層では圧縮ベクトルと通常のトークン埋め込みを結合し、後続層では対応する圧縮位置へ層別表現を加える（原著図2、§3.2）。

この層別接続は、浅い層に残る局所的な字句情報と深い層の意味情報の双方を復号器が利用できるようにする設計と解釈できる。符号化器と復号器の層数が異なる場合は、符号化器層の複製や平均によって対応させる。論文図3(a)の64倍圧縮実験では、全層を使うTransformer版とMamba版がBLEU-4約0.82を達成するのに対し、最終層だけを使う版は約0.6に留まる。層別接続が品質に寄与することを示すが、符号化器と復号器のパラメータを両方保持するため重み容量は増える。

### 3. 再構成と継続の学習タスク

圧縮表現に入力内容を記憶させるため、符号化器に与えた文書の一部を復号器に再構成させる。具体的には、入力文書の途中から短い手掛かり文を選び、その直後の文章を生成させるランダム手掛かり再構成タスクを用いる。復号器には手掛かり部分を非圧縮で与えるが、続く文章の復元は圧縮表現を使わなければならない。もう一つの文章継続タスクでは、符号化器入力の次の文章を予測させ、記憶だけでなく次文生成の能力も維持する。

短文再構成の主学習では、再構成対継続を9対1で混合してから再構成中心に微調整する。評価は2,048トークンの入力を100本用意し、各文書から約10トークンの手掛かりを複数位置で抽出して約500トークンの復元を採点する。BLEU-4はn-gram一致の指標であり、意味理解や質問応答の正答率ではない。圧縮率32で約0.95を達成しても、未知の長文で同じ割合の情報が保持されるという意味にはならない。

### 4. 短文から長文への二段階学習

長い文書を一度に学習すると、符号化器側の勾配保持がメモリを圧迫する。そこで第1段階では比較的短い文書を使って符号化器・復号器の全パラメータを微調整し、圧縮表現の作り方と読取り方を学習させる。第2段階では符号化器のパラメータを固定し、より長い文書から得た多数の圧縮ベクトルを復号器が処理できるように学習する（原著§3.3.1）。

この設計により、長文段階で符号化器全体の勾配を保持する必要がなくなる。ただし第2段階で符号化器の圧縮品質自体を長文に適応させることはできず、復号器の読み方の適応が中心となる。論文の合成パスキー実験では、第1段階に8K、第2段階に32Kの学習文脈を使い、512倍圧縮で最大100万長の検索を試す。実文書QAの学習条件とは異なるため、合成検索の成功をそのまま文書理解へ一般化しない。

### 5. 指示再構成による命令と文書の混同の緩和

質問応答では、文書だけでなく質問文も圧縮器へ入れる場合がある。質問と文書を一緒に圧縮し、復号器に短い回答開始記号だけを渡すと、何を答えるべきかが曖昧になる。RCCは学習時に質問文を文脈の先頭または末尾へランダムに置き、復号器へまず質問文を復元させ、その後に回答を生成させる。これにより、文脈の記憶と指示の理解を分ける補助目標を与える（原著§3.3.2）。

比較条件は、質問文を復号器へ直接渡す「RCC-Ins-Human」、質問文を圧縮表現から復元する「RCC-Ins-Reconstruction」、文書と質問文をまとめて圧縮して短い回答指示だけ渡す「RCC-Ins-Compress」である。質問文を直接渡す方式は復元誤りを避けられるが、質問文を非圧縮で渡す分のトークン費用が残る。質問文を復元する方式は非圧縮入力を減らせるものの、長い質問や長文脈では復元が難しくなる。

## 評価

### 評価条件と数値

原著§4の基本構成はPythia-1.4Bの符号化器と復号器で、比較としてMamba-1.4B符号化器も用いる。学習データはThe Pileから抽出した約50億トークンで、学習は8基のA800 GPUを使うサーバー上で実施される。これは単一GPUで推論する軽量な圧縮フィルタではなく、**符号化器と復号器の両方を学習・実行するモデル構成**である。圧縮率や学習タスクは評価ごとに異なる。

| 短文再構成（図3a,b） | 圧縮率64、全層接続 | BLEU-4約0.8〜0.85 | 最終層のみは約0.6、ICAEは約0.1 |

原著表1の各セルには3つの試行結果が併記されている。32K学習後のTransformer版は1M長で100/100/100だが、Mamba版は100/99/100であり、**「1Mですべて100%」という読み方は不正確**である。8Kのみの微調整でも1M長で高い成績を示す一方、試行ごとの値にはばらつきがある。さらにこの課題は繰り返し定型文の中へランダムな数値を埋め込む合成検索であり、複雑な長文推論や未知の複数証拠の統合とは難しさが異なる。

LongBench-Eの文書QA評価は、単一文書・複数文書QAから4種類の下位課題を選び、各150〜300件程度を評価する。著者は指示微調整データの制約により、LongBench全体の課題を網羅していない。0〜2KのPythia-SFTは30.54で、同じ長さのRCC指示再構成28.12を上回る。長さが8Kを超えるとRCC指示再構成は17.72まで低下し、指示を直接入力する方式の20.48より悪い。したがって「文書QAで無圧縮より常に良い」という結果ではなく、**圧縮して長さを扱えることと、短文時の最高品質は交換関係にある**。

図1のGPUメモリ比較では、元のPythia-1.4Bは入力0、2K、8K、16Kで概ね4.1GB、6.3GB、11.8GB、19.9GBと増える。符号化器と復号器の両方を使うRCC構成では、約7.7GBから8.2GBまでの緩やかな増加に留まる。初期メモリはRCCの方が大きく、入力が長くなったときに逆転する点が重要である。32倍圧縮とは、元の入力を表す圧縮位置数の比であり、**モデル重みを含む総GPUメモリが32分の1になるわけではない**。

### 構成要素の寄与と負の結果

全層接続と最終層のみの比較は、符号化器から復号器への情報の渡し方が圧縮品質を左右することを示す。64倍圧縮で全層接続は約0.82、最終層のみは約0.6という差がある。Mamba符号化器とTransformer符号化器のBLEU-4は近いが、Mamba版の学習時間は約1.5倍であり、状態空間モデルを使えば必ず速いわけではない（原著図3a）。また128倍圧縮では再構成の学習が収束せず、圧縮率の上限がタスク・学習条件に依存することが分かる。

指示再構成の効果は、同時圧縮方式の平均19.61に対して22.61へ改善する点にある。ただし指示を直接与える方式は平均23.15で、8K超の長文では差がさらに広がる。つまり指示再構成は同時圧縮の欠点を軽減するが、完全に解決しない。著者は、長い質問文を復号器が限られた窓内で再構成しきれないこと、長文の指示微調整データが不足していることを明示的な限界として挙げる（原著§6）。

パスキー検索の高精度にも注意が必要である。圧縮率512の実験では、合成データに対する専用微調整を行っており、同じモデルを再構成や文書QAで512倍圧縮しても高品質だと示したわけではない。短文再構成では128倍ですでに学習が不安定なのに、合成パスキー検索では512倍が成立する。これは矛盾ではなく、**保持すべき情報量が「文書全体の再現」と「埋め込まれた一つの数値の検索」で異なる**ためである。

## 限界

RCCは圧縮表現を復号器へ渡すため、復号器側のKVキャッシュ容量を削減できる。一方、圧縮前の文書を符号化器で処理する費用は残る。区間ごとの符号化は並列化できる余地があるが、原著の中心評価は主に品質とGPUメモリ容量であり、最新の配信基盤でのエンドツーエンド遅延・同時要求処理量を体系的に比較したものではない。入力が短い場合、二つのモデルの重みを保持する負担が容量節約を上回る。

モデル重みの合計は、Pythia-1.4Bを符号化器と復号器に使う場合、単一Pythia-1.4Bより大きい。従って、端末GPUの総容量が少ない場合に常に有利とは限らない。図1は十分長い入力でメモリ使用量が逆転する条件を示すが、実際の交点はモデル規模、KV精度、バッチ数、注意実装に依存する。量子化済みモデルやFlashAttention以外のカーネルへ適用したときの具体的な交点は別途測定が必要である。

長い指示文の再構成は特に難しい。指示文を誤って復元すると、文書から必要な情報を保持していても、間違った質問へ正しく答えてしまう。実務では、文書だけ圧縮して短い指示文を非圧縮で渡す方式と、質問文も圧縮して復元する方式を、品質と入力予算に応じて使い分ける必要がある。論文自身も長い指示には圧縮、短い指示には再構成を使う混合学習を今後の課題として提案するが、その優位性を完成した実験結果として示してはいない。

評価に使ったPythia-1.4Bは現代の強い指示追従LLMとは能力が異なる。LongBench-Eの一部文書QAだけを使っているため、コード、複数言語、長期対話、複雑なツール呼出し、推論時の長い思考過程における性能は未確認である。また、圧縮表現の正確な再構成は、最終的な回答の事実性を保証しない。長文脈の入力容量と回答品質を分けて報告する必要がある。

## 関連研究との位置付け

KVキャッシュの低ビット量子化や選択的KV取得は、元のモデル構造をできるだけ保ったまま生成中の記憶を軽くする。一方RCCは、別の符号化器が入力文脈を圧縮して復号器へ渡すため、学習とモデル構造の変更が必要である。Mambaの固定状態推論やInfini-attentionの長期記憶とも異なり、入力を固定長区間に分け、各区間から少数の圧縮ベクトルを作って復号器の注意に与える。したがって文脈窓の拡張と学習済み圧縮表現の設計を扱う系統に位置付けられる。

RCCが示したのは、層別の圧縮状態と段階的学習を使えば、長文を復号器へ短い表現で渡し、合成検索の長さ外挿や一部の文書QAを成立させられるということだ。一方で、短文再構成の32倍・BLEU-4約0.95、合成パスキー検索の512倍・1M長での高正答率、LongBenchの平均22点台を同一の「圧縮しても無損失」という宣伝へまとめるべきではない。目的タスクごとの保持情報量、符号化器の学習費用、指示再構成の失敗を明示して評価する必要がある。
