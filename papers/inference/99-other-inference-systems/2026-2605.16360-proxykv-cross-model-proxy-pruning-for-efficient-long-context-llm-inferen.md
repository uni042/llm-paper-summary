# ProxyKV：小型モデルによるKV重要度の非同期代理予測

## 概要

ProxyKVは、長文脈LLMのKVキャッシュを圧縮するとき、どのトークンを残すかを高精度に決める計算を大型モデル自身にさせず、同じモデル系列の小型モデルへ委譲する方式である。SnapKVのような軽量なヒューリスティックは重要トークンの推定が不正確になりやすい一方、KVZipのような再構成ベースの手法は高精度なスコアを得るためターゲットで二度目のプレフィルを実行し、最初のトークンまでの時間（TTFT）を増やす。ProxyKVはこの両極端の間を狙う。

入力文書を大型ターゲットと小型代理モデルへ同時に渡し、代理の注意スコアから大型モデルのヘッド別重要度を予測する。代理はターゲットの別CUDA stream、または別GPUで実行し、ターゲットのプレフィル終了までにスコアを用意する。予測した重要度をTop-Kで閾値化し、ターゲットのKVを圧縮してからデコードへ移る。ターゲットは追加の教師強制プレフィルを行わず、代理はデコード時のクリティカルパスから外れる。

Llama-3.1-8Bではdual-GPU構成で最大3.21倍のプレフィル高速化、同一GPU上でCUDA streamを共有する構成では約1.5倍を報告する。LongBench、SCBench、RULERの集約ではKVZipの平均精度の約98.7%を回復したとする。Qwen2.5-7Bでは170Kトークンまでの長文脈でも速度利得を確認している。ただし代理モデルと約15Mパラメータのmapperを別途学習・実行する必要があり、dual-GPUと単一GPUの速度倍率は混同できない。

## 問題設定

長文脈のKVキャッシュは系列長に比例して大きくなる。単純に全トークンを残すとGPUメモリが不足し、CPU/GPU間の転送や同時リクエスト数の制限が生じる。KV pruningは重要トークンだけを残すが、重要度の計算が高価ならプレフィル時間が増え、キャッシュを小さくしてもTTFTが悪化する。

KVZipは、ターゲット自身を使った再構成的な教師強制プレフィルから高精度な重要度スコアYを得る。ターゲットを二度走らせるため高価である。SnapKVは末尾観測窓の注意などから安価にスコアを得るが、長距離の意味的依存を十分に拾えない場合がある。ProxyKVは、同系列の小型モデルの注意統計Xから、ターゲットのスコアYに近い予測Ŷを作ることで、品質とスコア計算費用を両立する。

ターゲットの層数L_l、ヘッド数H_l、系列長Nに対し、必要なスコアは各層・ヘッド・トークンの形 `B×L_l×H_l×N` となる。代理の層数L_s、ヘッド数H_sは通常小さく、固定のヘッド対応を仮定するとアーキテクチャ差を吸収できない。さらに、Top-Kで残すトークンを決める目的では、スコアの絶対値を正確に回帰するより、重要トークンと不要トークンの**順位関係**を保つことが重要である。

設計上の条件は `t_proxy+t_mapper≤t_target_prefill` である。この非同期予算を超えると代理の完了をターゲットが待つため、プレフィルの高速化が失われる。また同系列のモデルを使うことを前提とし、無関係な小型モデルから任意のターゲットへ重要度を移す汎用性を実証したわけではない。

## 手法

### 1. 小型代理からターゲットへの非同期スコア転送

代理モデルは入力のプレフィルを実行し、各層・ヘッドについて、クエリ方向に集計したsoftmax注意確率を長さNの重要度特徴Xとして取り出す。N×Nの注意行列をそのまま転送するのではなく、キー位置ごとの累積重要度に集約するため、mapperの入力はトークン方向に線形サイズとなる。ターゲットは通常のプレフィルを並列実行し、代理が生成したXをHybridAxialMapperへ渡す。

mapperはターゲットの各層・ヘッドへ対応するスコアŶを出し、保持率ρに応じてTop-Kマスクを生成する。マスクをターゲットのKVへ適用した後、代理側のKVは解放され、デコードは大型ターゲットだけで進む。dual-GPUなら代理は別GPU上で動く。単一GPUなら異なるCUDA streamを使うが、GPUの演算・メモリ帯域を共有するため、並列性がdual-GPUほど高くならない。

### 2. HybridAxialMapper：時間方向とヘッド方向の分離

代理とターゲットではヘッド数や層数が異なるため、単純な固定ヘッド対応では精度が下がる。HybridAxialMapperは時間方向とヘッド方向を分離して処理する。まず1D Convを2段重ね、BatchNormとGELUで代理のヘッド別スコアを512次元の潜在特徴へ写す。次に6層・8ヘッドのTransformer encoderが系列方向の長距離依存を取り込み、トークン位置間の文脈を表現する。

学習は長さ2048のcropを使うが、推論時にはstride1024の重複スライド窓で長い系列を処理し、重複区間の予測を平均する。これにより170Kのような長文脈でも、mapper自身が全系列の二乗注意を実行しないようにする。潜在特徴をヘッド方向のkey/valueへ変換し、ターゲットのヘッド数H_lに対応するlearnable target queriesでcross-attentionを行い、ターゲット形状のスコアへ写す。

層方向には、ターゲット層番号ℓ_lに対して `ceil(ℓ_l L_s/L_l)` の代理層を対応させる。mapperのパラメータは層ペア間で共有されるが、ターゲット層ごとに前向き計算を行う。全mapperは約15Mパラメータで、1D Conv約0.5M、時間方向encoder約13M、ヘッド方向cross-attention約1.5Mという内訳である。単に「小型モデルを使う」だけでなく、ヘッド数と深さの差を学習可能な写像で埋めることが新規性となる。

### 3. Top-Kの順位整合を学ぶ5項目損失

単純なMSE回帰は、スコアの絶対値をよく再現しても、Top-K境界付近で重要トークンと不要トークンの順位を逆転させることがある。ProxyKVは5項目のMulti-Granularity Hybrid Lossを使う。中心は保持率0.05〜0.5の複数予算で正解Top-Kマスクを作り、低保持率へ重みを掛けたbinary cross entropyを最小化するmulti-ratio binary lossである。

補助損失は、重要スコアの絶対値を重み付けMSEで近似する項、Top-K内部の相対順位を保つfine rank loss、Top-K内外の正負ペアのmarginを確保するglobal rank loss、予測スコアベクトルと教師の方向を揃えるcosine lossである。著者らは重みをMSE20、binary10、fine3、global2、cosine0.5と設定し、同じスコアlogitからbinary用sigmoidと値の大きさ用の別ヘッドを作る。これにより、binary分類でlogitを極端にしたい要求と、MSEで有限値へ近づけたい要求を分離する。

スコア値を完全一致させることより、実際のKV保持集合の一致を優先する点が重要である。例えば教師と代理のスコアが近くても、保持率10%の境界にある二つのトークンの順位が逆転すれば、残すKVが変わって下流品質が落ちる。複数保持率でbinary maskを学ぶことは、単一の固定予算に過適合しないための工夫である。

### 4. オフライン学習と実行時の条件

mapperの学習では、凍結した大型ターゲットにKVZipの教師強制プレフィルを実行して教師スコアYを作り、代理の特徴Xと組にして保存する。学習時には高価な教師スコアが必要だが、推論時にはその教師計算を行わない。AdamW、学習率2×10^-4、weight decay10^-4、batch8、2048-token crop、stride1024、30epochなどを使い、ターゲット・代理ペアごとにmapperを学習する。

学習済みmapperは同系列ペアの間でヘッド数差を吸収するが、モデルを入れ替えればそのまま再利用できるとは限らない。推論時には代理のプレフィル、mapper、Top-Kマスク生成がターゲットのプレフィル完了前に終わる必要がある。ターゲットと代理がGPUメモリを一時的に同時占有するため、低メモリGPUでの導入にはピークメモリを考慮する必要がある。

### 主な定量結果とその条件

原著要旨・本文の主要値は以下の通りである。各値の比較基準とGPU構成を区別する。

| 項目 | 数値 | 読み方 |
|---|---|---|
| Llama-3.1-8B、dual-GPU | プレフィル最大3.21倍 | 代理を別GPUで重ね、ターゲットの二度目の教師強制プレフィルを回避する構成 |
| Llama-3.1-8B、単一GPU共有 | プレフィル約1.5倍 | 同一GPU上で代理とターゲットが演算・帯域を共有し、dual-GPUより利得が小さい |
| LongBench・SCBench・RULER集約 | KVZip平均精度の約98.7%を回復 | 完全一致ではなく、KVZipに対する集約比率。各タスクの点数とは異なる |
| Qwen2.5-7B | 170Kトークンまで速度利得を維持 | 長文脈での評価上限。全モデル・全ハードウェアでの上限ではない |
| mapper | 約15Mパラメータ | Conv0.5M、Transformer encoder13M、head cross-attention1.5Mの概数 |
| 代理・ターゲット比 | 1B/8B、1.5B/7B、4B/32B | それぞれ同系列ペア。異系列間転送は未実証 |
| 学習crop | 2048トークン、stride1024 | 長文脈は重複窓推論で処理する |

「KVZip平均精度の98.7%」は、例えば全てのベンチマークで正答率が98.7%という意味ではない。KVZipの集約スコアに対する相対的な回復率である。保持率を固定した比較での精度回復を表し、全KV密注意の品質との一致を保証しない。3.21倍はdual-GPUでのプレフィル高速化であり、GPUを1基しか使わない場合の利得は約1.5倍である。異なるGPU台数の結果を同じ費用の方式として直接比較できない。

### 失敗し得る条件とアブレーションの解釈

第一に、代理とmapperの合計時間がターゲットのプレフィルを超えると、ターゲットはマスク生成を待つ必要があり、高速化が失われる。これは論文が明示する非同期予算制約である。短文脈・小型ターゲットでは代理計算の相対負担が大きくなり、dual-GPUのような並列性を確保できない場合は速度利得が小さくなる。

第二に、代理のヘッドとターゲットのヘッドを固定対応させるだけでは、ヘッド数・層数が異なる場合に重要度を正しく転送できない。HybridAxialMapperは時間方向の局所・長距離文脈と、ターゲットヘッド方向の対応を分離するための部品である。本文のlossのleave-one-out分析は、binary、fine、global、cosine、MSEがそれぞれ異なる失敗形態を補完することを狙う。ただしアブレーションの全タスク別数値を本稿では再掲せず、効果量を推測していない。

第三に、単一GPUでの1.5倍という値は、dual-GPUで3.21倍だった方式が演算資源を共有すると利得を失うことを示す。GPUメモリの一時ピークも代理の同時実行で増える。代理側KVはプレフィル終了後に解放されるが、ピークメモリを低くできるとは限らない。小型モデルを追加しても単一GPUの演算器・帯域が余っていなければ重ね合わせは難しい。

第四に、KVZip oracleの教師スコアをオフラインで作るには大型ターゲットの高価な追加プレフィルが必要である。推論時にはその費用を省けるが、対象モデルや保持率を変えるたびにmapperの再学習・再校正が必要となる可能性がある。学習不要のSnapKVとは運用コストの構造が異なる。

## 既存研究との差

SnapKVは入力末尾の観測窓などの局所的な注意から重要KVを選ぶ。KVZipは文脈全体の再構成信号から高精度に選ぶが、ターゲットで追加の教師強制プレフィルを実行する。ProxyKVはKVZipの高精度なスコアを**同系列小型モデルから非同期に予測**し、ターゲットの追加プレフィルを避ける。KVの圧縮形式自体を新しくする研究ではなく、圧縮対象のスコア生成経路を変える研究である。

IAMやSmallKVは同系列モデル間の注意相関を利用するが、固定的なヘッド・層の対応では、代理とターゲットの深さ・ヘッド数の違いを吸収しにくい。ProxyKVは時間方向の1D ConvとTransformer encoder、ヘッド方向のlearnable queriesを分離し、ターゲット形状へ写す。さらにスコア値のMSEだけでなく、複数保持率のTop-K境界、Top-K内部の順序、正負候補間のmarginを学習するため、最終的な保持集合の一致へ直接最適化目標を近づけている。

投機的復号は未来トークンを草稿として予測し、ターゲットが検証する。ProxyKVは未来トークンではなく、プレフィル時のKV重要度を予測するため、デコード中の草稿・検証反復はない。プレフィル速度の改善を、投機的復号のトークン受理率やデコードTPSの改善と混同してはならない。

## 限界・実装状況

第一に、モデルペアはLlama-3.x、Qwen2.5、Qwen3の同系列に限られ、異系列間の代理転送や、VLM、MoEの複雑なルーティング、特定ドメインの極端な分布変化に対する品質は未実証である。ヘッド数と層数の差を吸収する設計であっても、意味的に異なるモデルの注意重要度を正しく予測できる保証はない。

第二に、専用mapperのオフライン学習が必要で、学習データ作成にはKVZip oracleの教師強制プレフィルを使う。これは推論時に高価な計算を省く代わりに、事前に学習費用を支払う方式である。保持率や対象モデルを変えたときの再学習費用、長期間の運用での更新コストを別に評価する必要がある。

第三に、dual-GPUの最大3.21倍と単一GPUの約1.5倍は別の配置である。代理モデルとターゲットを同時に実行するため、GPUの演算器・帯域・一時的なメモリ容量を共有する。プレフィル終了後に代理KVを解放しても、ピークGPUメモリが常に低いとは限らない。単一の12GB GPUなどへそのまま適用できることは示していない。

第四に、速度の主要指標はプレフィルのwall-clockであり、デコードTPOT、長時間の連続バッチ、同時リクエストのp95/p99、モデルロード時間、電力消費を同じ条件で改善したという結果ではない。170Kトークンまでの結果もQwen2.5-7Bの設定であり、全モデルに一般化できない。

第五に、KVZipの平均精度の98.7%を回復したという集約値は、下流タスクの全てで品質差が1.3ポイント以内という意味ではない。個別タスクでの落ち込みや高い保持率でのトレードオフを別に確認する必要がある。アブレーションの全数値を未確認のまま推測で補わず、原著が明示する設計目的と評価済みの主要値を分けて記録した。
