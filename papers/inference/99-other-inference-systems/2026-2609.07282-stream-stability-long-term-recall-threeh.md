# Separating Stream Stability from Long-Term Recall in Language Models

> 長時間生成の安定性・過去情報への因果アクセス・タスク効用をThreeHの3到達距離へ分離し、注意シンクの安定生成を長期記憶と誤認しない評価契約を示す。
## 書誌情報
- **著者**: Peipei Cao, Xin Zhang, Jie Tang, Xiao Li, Siying Li, Qing Pei
- **公開**: arXiv preprint arXiv:2609.07282v1
- **種別**: arXivプレプリント
- **対象**: ストリーミングLLM、長期記憶、KVキャッシュ、注意シンク、評価方法
- **実装**: 新規サービング実装より評価契約ThreeHと概念的比較が中心。StreamingLLM、再帰状態、検索付きシンク等を同一予算で評価する。
## 概要
長時間ストリーミング生成で『動き続けること』と『古い情報を覚えて使えること』が混同される問題を整理し、安定性・アクセス・実用性の三つの到達距離を分離するThreeH評価契約を提案する。注意シンクを残すStreamingLLMは2Kトークンの固定KV容量でも128Kまで正規化パープレキシティ1.04倍を保つが、通常内容がキャッシュから追い出されると4択記憶は2Wで約26%の偶然水準へ落ちる。対して再帰状態や検索は追加状態を使って意味的到達距離を延ばす。ThreeHは同一の状態・計算予算で連続生成安定性、反実仮想を使う因果的保持、遅延タスク効用を別々の曲線として測り、『無限コンテキスト』という単一長さの主張を分解する。

論文固有の提案ThreeHは、『何トークンまで扱えるか』という単一軸を三つの到達距離へ置き換える。第一は予測損失が悪化せず連続生成できる安定性到達距離、第二は過去入力を反実仮想的に変更したとき現在出力が変わり得る因果アクセス到達距離、第三は古い証拠を使う下流タスクが所定得点を保つ実用到達距離である。特にアクセスを単純な正答率ではなく値だけを変えた対照ストリームへの応答変化として測ることで、言語事前分布による当てずっぽうを記憶から排除する。また装置内状態だけでなく外部保存量、1トークン計算量、通常遅延、検索遅延まで同じ予算へ含め、固定KV窓、再帰圧縮、外部検索を公平に比較する点が単なる指標整理と異なる。

代表結果として、128K正規化PPLは128K ストリームで2K時の各方式PPLに対してWindow 5.40、StreamingLLM 1.04、Recompute 1.02。4個の注意シンクは固定メモリの連続生成安定性をほぼ再計算並みに回復する。
## 問題設定
固定長KVキャッシュを使うストリーミングLLMは、古い状態を捨てながら長時間生成できる。注意シンクでは先頭の数トークンを固定保持することで注意正規化を安定させ、キャッシュ容量を一定にしたまま非常に長い列でパープレキシティ崩壊を防げる。しかし固定先頭トークンのKVは後から来た出来事で更新されないため、追い出された通常トークンの意味を保存する経路にはならない。それにもかかわらず『無限ストリーミング』『無限コンテキスト』『長期記憶』が同じ長さ指標で語られると、局所予測が安定しているだけの方式を遠隔情報へアクセスできる方式と誤認する。パープレキシティ、needle検索、下流タスク精度は別の性質を測るため、一つの最大トークン長ではシステムの能力と失敗原因を特定できない。
## 新規性
論文固有の提案ThreeHは、『何トークンまで扱えるか』という単一軸を三つの到達距離へ置き換える。第一は予測損失が悪化せず連続生成できる安定性到達距離、第二は過去入力を反実仮想的に変更したとき現在出力が変わり得る因果アクセス到達距離、第三は古い証拠を使う下流タスクが所定得点を保つ実用到達距離である。特にアクセスを単純な正答率ではなく値だけを変えた対照ストリームへの応答変化として測ることで、言語事前分布による当てずっぽうを記憶から排除する。また装置内状態だけでなく外部保存量、1トークン計算量、通常遅延、検索遅延まで同じ予算へ含め、固定KV窓、再帰圧縮、外部検索を公平に比較する点が単なる指標整理と異なる。
## 手法
### 手法のあらまし
入力は長時間トークン列、各方式が保持する永続状態、評価する遅延距離dである。まず全方式を時刻tごとに上限Bの状態M_tを更新し、その状態から次トークンを出す一般形へ写像する。Track Aでは自然文を128Kまで連続投入し、2K時点を基準に位置ごとの予測損失・パープレキシティ、1トークン遅延、永続状態量を記録し、局所生成が崩れない距離を得る。Track Bではランダムなキー値結合を0.25W～8W前へ置き、値だけを変更した反実仮想ペアを同じ後続文脈で問い合わせる。出力が値変更へ適切に追随した場合だけ古い入力から現在出力への因果経路が残ると判定する。Track Cでは同じ距離に三択判断の決定証拠を置き、将来質問を状態書込み時には隠したままタスク得点を測る。これを最新窓のみ、先頭4シンク＋最近窓、窓再計算、固定再帰状態、シンク＋外部検索へ同じW=2048基準で適用する。最後に安定性≤1.1倍PPL、保持・実用性≥75%など宣言済み閾値と曲線から三到達距離を算出し、装置内状態B_device、外部状態B_external、1トークン計算量、生成遅延、問い合わせ検索遅延を併記する。したがって入力から状態更新、介入、測定、距離判定、資源比較まで同じ評価手順でつながる。

### 安定性到達距離
自然文ストリームをモデルへ順番に入力し、総列長だけを延ばしながら固定位置区間ごとの予測損失を短い基準列と比較する。固定窓で古いKVを単純追い出しすると、学習時に広く参照されていた先頭位置まで消えて注意正規化が変わり、遠い情報を必要としない次トークン予測自体が崩れる。注意シンク方式は先頭数状態をアンカーとして残し、残り容量を最近Wトークンへ使うことでこの計算幾何を保つ。出力は損失悪化曲線と、許容悪化εを超えない最大距離H_stabである。同時に1トークン遅延と状態量を記録するため、毎回Wトークンを再計算して同じ安定性を得る方式の7.8倍遅延と、シンク方式の1.03倍遅延を区別できる。ここでは古い事実への質問を一切成功条件にせず、『モデルが壊れず走り続ける』性質だけを測る。

### アクセス到達距離
ストリーム中へ将来予測できないランダムなキーと四択値の結合を挿入し、問い合わせまでの距離を0.25Wから8Wへ対数的に増やす。各例には対象値だけを別値へ置換した反実仮想ペアを作り、介入以外の後続文脈を対応させる。問い合わせ出力がその値変更へ適切に追随する場合にだけ、過去入力が現在出力へ因果的影響を残したと数える。固定シンクは結合が現れた後に自身のKVを書き換えないため、通常トークンが最近窓から追い出されると因果経路が消え、2Wで約26%の偶然水準へ落ちる。再帰方式は窓境界で固定状態を書き換え、検索方式は外部ストアへ記録して問い合わせ時に読み戻すので、同じWでもアクセス距離を延長できる。出力は距離ごとの保持曲線とH_accessであり、流暢な推測を長期記憶と誤認しない。

### 実用到達距離
アクセスできる情報が実際の意思決定に使えるかを別に測るため、古い位置へ三択判断の決定証拠を置き、問い合わせを0.25W～8W後まで遅延する。重要なのは、状態を書き込む時点では将来どの質問が来るかを隠すことである。そうしないと圧縮器や検索器が既知の答え部分だけを保存し、長期記憶ではなく質問依存の文脈選択を測ってしまう。検索方式では正しい証拠を取得できても、検索順位、干渉、取得文の解釈、最終行動選択で失敗し得るため、保持率とタスク得点を分ける。実際にStreamingLLMは2Wで36%と三択偶然水準へ近づき、検索方式もアクセス率より実用率が低い。出力は距離ごとのタスク曲線とH_utilで、H_accessが長くてもH_utilが短い方式を可視化する。

### 共通資源予算と失敗分解
方式ごとに装置上の永続状態B_device、外部保存B_external、ストリーム1トークン当たり計算量F_トークン、通常生成遅延L_トークン、問い合わせ時の追加検索遅延L_queryを同時に報告する。これにより小さなKV窓の裏で巨大なベクトルDBを使う方式を『同じ定数メモリ』として比較せず、階層メモリとして正しく費用計上できる。失敗時には反実仮想保持で因果経路の有無を調べ、oracle検索で検索だけを理想化し、全コンテキスト比較でモデル自身のタスク能力を確認する。これにより失敗を、情報が追い出された、圧縮状態で干渉した、検索できなかった、取得したが使えなかった、という段階へ分解できる。単一の最大長では同じ『失敗』に見える現象を別々の設計課題へ対応付けられる。

### 全体のデータ／制御の流れ
新しいメモリアーキテクチャを提案するのではなく、シンク窓、再帰・圧縮状態、外部検索、ハイブリッド方式を同じ座標系へ置く評価・診断枠組みである。
## 評価条件
- **ハードウェア**: 論文本文で具体的GPU/CPU型番は主要評価条件として未報告、装置内状態量と外部状態量をThreeH資源会計で別々に報告
- **ソフトウェア**: StreamingLLM-style sink-window evaluation、conceptual recurrent-state and retrieval 比較対象; exact software versions not reported
- **データセット／トレース**: 128K natural-text ストリーム、four-way random delayed bindings、three-action delayed decision task
- **比較対象**: Window、StreamingLLM、Window recomputation、Recurrent fixed-size メモリ、Sink + retrieval、Dense oracle
Track Aは128K自然文を連続入力し2K時のPPLを基準に位置ごとの劣化を測る。Track Bはランダム結合の値だけを変更した反実仮想ペアで因果保持を検査する。Track Cは将来質問を状態書込み時に隠した遅延三択判断で古い証拠の利用を測る。sink数、窓幅2W、retrieval k=1/4をアブレーションし、安定性・保持・実用性を同じ状態予算で比較する。
注意シンク、窓再計算、固定サイズ再帰状態、外部検索を概念的に比較する評価研究。特定の大規模商用サービング実装や多利用者トラフィックの性能比較ではない。論文本文はGPU/CPU型番やソフトウェア版を主要実験条件として報告していないため、ハードウェア固有の絶対時間比較ではなく相対1トークン遅延と状態予算を中心に解釈する。
## 主要結果
128Kストリームでは単純窓の正規化パープレキシティが5.40倍まで悪化する一方、StreamingLLMは1.04倍、窓再計算は1.02倍で局所生成を安定化した。しかしStreamingLLMの4択遠隔保持は内容が窓外へ出る2Wで26%、8Wで25%とほぼ偶然水準になり、安定性が長期記憶を意味しないことを直接示す。再帰状態は8Wで46%、検索付きシンクは78%を保ち、意味的アクセスには後続内容を書き込む状態または検索経路が必要だった。実用性も別で、StreamingLLMの3択遅延判断は2Wで36%まで落ち、検索方式も保持率より判断精度が低い。したがって『128Kまで安定』という結果から128Kの記憶能力を主張せず、どの性質がどの距離まで成立するかを三曲線で報告する必要がある。

- 128K正規化PPL / Window 5.40、StreamingLLM 1.04、Recompute 1.02 (比較対象: 2K時の各方式PPL; 条件: 128K ストリーム) — 4個の注意シンクは固定メモリの連続生成安定性をほぼ再計算並みに回復する。

- 相対1トークン遅延 / StreamingLLM 1.03、Recompute 7.80 (比較対象: Window 1.00; 条件: stability track) — 注意シンクは毎回窓を再計算する大きな遅延なしで安定性を得る。

- 4択保持率@8W / StreamingLLM 25%、Recurrent 46%、Sink+retrieval 78%、Dense oracle 96% (比較対象: chance 25%; 条件: delayed binding) — 固定シンクは意味内容を保持せず、再帰更新や外部検索がアクセス距離を延ばす。

- ThreeH measured horizons / StreamingLLM: H_stab >64W, H_access 1W, H_util 0.5W (比較対象: Window: 2W,1W,0.5W; 条件: PPL≤1.1x、retention/utility≥75%) — ストリーム安定性だけが大幅に伸び、一般的意味アクセスとタスク利用距離は伸びない。

- retrieval depth ablation / k=1 recall@2W 73% / utility 68%、k=4 89% / 85% (比較対象: 4 sinks only 26% / 36%; 条件: 2W lag) — 検索量を増やすとアクセスと実用性が伸びるが問い合わせ時コストも増える。

### 負の結果・境界条件
- 注意シンクを1から8へ増やすとPPL安定性は改善・飽和するが2W保持率は25～26%で伸びない。
- 固定シンクは後続トークンで更新されないため、アンカーを増やしても一般的長期記憶にはならない。
- 検索は8W保持78%でもタスク効用は保持率より低く、取得成功だけでは正しい利用を保証しない。
- 到達距離はタスク、閾値、トークナイザ、資源会計に依存し普遍的な単一値ではない。

### 結果の読み方
長時間LLMの設計では局所生成の安定化、古い内容を書き残す経路、取得した内容をタスクで使う能力を別モジュール・別目的として扱うべきである。注意シンクは第一の問題を解くが、第二・第三には再帰状態や外部検索など別の仕組みが必要になる。
## 品質への影響
StreamingLLMの価値である固定メモリ・安定生成を維持して評価しつつ、その性質を長期意味記憶へ過大解釈しない。
## 既存研究との差
従来の長文評価は最大入力長、パープレキシティ、needle検索、タスク得点のいずれかを単独で報告しがちである。ThreeHは同じ永続状態・計算予算で安定性、因果アクセス、タスク効用を別々の距離曲線として要求し、外部検索ストレージも資源へ含める。
## 限界
- 到達距離は採用する閾値とタスク分布に依存し、モデル固有の普遍的定数ではない。
- 任意のニューラル内部状態について完全な因果アクセス距離を直接観測できず、実験は介入条件下の境界を与える。
- 反実仮想ストリームの編集が不自然になると保持測定自体へ分布ずれが入る。
- プライバシー、事実性、較正、悪意あるメモリ内容への頑健性はThreeHの三軸に含まれない。
- 概念的5方式比較のため、実運用の大規模サービングでの費用を網羅する性能ベンチマークではない。
## 実装状態
ThreeH評価契約と比較実験を提示する評価・分析研究。新規の本番推論エンジンを提供する論文ではない。
## 研究上の位置づけ
『コンテキスト長』を単一の数字から、安定性・アクセス・実用性という異なるシステム能力へ分解する。bounded-メモリ推論、再帰圧縮、外部メモリを比較する際の評価設計として有用。
