# Interdomain Attention：トークン単位KVキャッシュを固定長の再帰状態へ置き換える注意機構

## 概要

通常の自己注意は、過去の各トークンに対応するキー（K）と値（V）をKVキャッシュへ保持し、生成時のクエリ（Q）と照合する。この方式は必要な過去情報を内容に基づいて選べるが、復号が進むほどKVキャッシュ容量と参照帯域が増える。状態空間モデル（state space model; SSM）は履歴を固定長の再帰状態へ圧縮できる一方、過去の特定の内容をクエリから直接参照する能力が弱い。Interdomain Attentionは、この二つの設計の中間に位置する。

提案方式は、注意のカーネル回帰としての表現を出発点に、キーの特徴と値の履歴をHiPPO系の基底関数へ射影し、S4D再帰によって基底係数を逐次更新する。新しいクエリは個々の過去トークンではなく、固定個数の基底係数へ内容依存で重みを付けて読み出す。これにより、**文脈長Nに比例して増えるトークン単位KVキャッシュを、Nと無関係な固定長状態へ置換**する。単なるSSMへの注意層の追加ではなく、SSMの内部状態そのものを注意の問い合わせ対象とする設計である。

FineWeb-Eduを用いて125M〜1.3Bパラメータの復号型モデルを学習した結果、同じ再帰状態予算のS4Dだけのモデルより検証パープレキシティが13〜16%低い。1.3Bでは同じ学習レシピの通常ソフトマックス注意よりも検証パープレキシティが7.5%低く、8タスクの常識推論平均も3.03ポイント高い。ただし、厳密な文字列検索ではソフトマックス注意が圧倒的に強い。また、RTX 6000 Adaでの復号計測は、バッチサイズ1ではグラフ化した提案方式がわずかに速い一方、バッチサイズ32や64では通常注意の方が速い条件がある。したがって「固定長メモリだから全条件で高速」という主張はしない。

## 問題設定と設計上の対立

### 通常注意の参照精度と状態量

通常の注意ではクエリqと各キーkの類似度から重みを計算し、値vを重み付き和で集約する。履歴トークン数をN、クエリ数をNq、頭次元をdとすると、通常注意の仕事量は概ね `O(Nq N d)`、保存状態は `O(N d)` となる。自己回帰復号では新しいトークンを1個ずつ追加するため、KVキャッシュを保持しても各ステップで過去N個分の参照が必要である。大きなバッチや長い文脈ではメモリ帯域が律速になり、同じモデルでも文脈が長いほど復号時間が伸びる。

これに対してS4DなどのSSMは、固定長の内部状態を新しい入力ごとに更新する。履歴の長さに依存しない保存容量と計算時間を得られるが、全履歴を少数の係数へ圧縮するため、文字列を一字一句そのまま取り出すような内容参照が難しい。Interdomain Attentionの問いは「SSMの固定長状態を保ったまま、クエリに応じた内容参照をどこまで復元できるか」である。

### 注意をカーネル回帰とみなす

注意を `o_i = Σ_n K(q_i,k_n) v_n / Σ_n K(q_i,k_n)` と表す。通常のソフトマックス注意では `K(q,k)=exp(q^T k / sqrt(d))` である。カーネルを有限次元の特徴写像 `ξ` によって `K(q,k)≈ξ(q)^T ξ(k)` と近似できれば、クエリの特徴とキー特徴の積を使って履歴を再構成できる。ここで重要なのは、全トークンを個別に残す代わりに、キー特徴と値の履歴を**共有基底上の係数**へ圧縮できることである。

HiPPOの考え方は、時間とともに変わる入力履歴を基底関数 `φ_m(t)` に射影して少数の係数として保持する。キー特徴の射影を `u_m`、値の射影を `γ_m`、正規化用の基底積分を `η_m` とすると、理想化した読出しは `Σ_m [ξ(q)^T u_m] γ_m / Σ_m [ξ(q)^T u_m] η_m` となる。トークン数Nではなく基底数Mに沿って和を取るため、文脈長が伸びても係数数を固定できる。ただし、この導出は有限特徴近似と基底近似に依存し、実装が厳密なソフトマックス注意と数学的に同一になるわけではない。

## 手法

### 学習可能な基底係数をクエリで読む

### 1. キー・値の二系統入力を一つのS4D再帰へ入れる

各トークンからクエリ、キー、値を作り、キーには特徴写像 `ξ(k_t)` を適用する。実装ではクエリとキーへカーネル幅4の因果的な深さ方向1次元畳み込みを施し、SiLU非線形変換の後でL2正規化する。これにより、固定の理論カーネルをそのまま使うのでなく、データから学習した類似度空間を構成する。入力の安定化のため、キー特徴と値の両方へ別々のRMS正規化と学習可能な頭ごとのバイアスを適用する。

S4Dの入力は `z_t=[ξ(k_t),v_t]` というキー特徴と値の連結である。頭hの状態は `x_t^(h)=Λ_h⊙x_(t-1)^(h)+B_h z_t^(h)` で更新される。`Λ_h=exp(Δ_h A_h)` は複素対角の状態遷移であり、S4D-Inv初期化を用いる。`B_h` と読出し行列 `C_h` は学習可能で、特に `C_h` は頭ごとに全複素行列を使う。これにより、入力が増えるたびに過去のキー特徴と値をまとめた係数 `U_h,Γ_h` を更新する。**過去の全トークンのKとVを別々に保存する処理は行わない。**

HiPPO導出で想定した基底積分と、学習したS4D係数は同一ではない。論文はS4Dの対角近似、学習可能な射影、非線形特徴写像を含む実装を「理論導出の学習可能な緩和」と位置付けている。従って、数式上のカーネル回帰の厳密再現を実験が証明したと解釈してはいけない。

### 2. クエリ依存の係数読出し

新しいクエリにも同じ特徴写像を適用して `F_q` を得る。理想導出では `F_q U^T Γ` を `F_q U^T η` で正規化するが、実装では入力値を正規化・再スケールしており、正規化分母の単位整合が失われる。そのため実装の読出しは分母を除いた `O_h = F_q^(h) U_h^T Γ_h` となる。これは線形注意やDeltaNetに近い形式だが、係数がS4D再帰を通じて更新される点が異なる。

クエリごとに `F_q U^T` が変わるため、同じ固定長状態を保持していても、読み出す係数の重みが入力内容に応じて変わる。単なる固定射影のS4Dと比べた際にこのクエリ依存性が主たる品質改善要因であることは、後述の構成要素除去実験で確認される。各頭は独立の状態を持ち、1.3B実験では32頭を共有せずに使用する。頭間で係数を共有する派生構成も設計可能だが、1.3Bの主要品質実験は完全な頭別状態を使っている。

### 3. 訓練時の融合カーネルと推論時の固定形状

学習時はTritonによるチャンク化融合カーネルを使用する。チャンク内の寄与は行列積へまとめてTensor Coreで計算し、チャンク間の履歴は短い逐次再帰で伝播する。論文は全系列の計算を文脈長Nに対して線形に保つ実装経路を示す。推論時は固定長の再帰状態だけを保持し、チャンク単位の事前計算とCUDAグラフによる1トークン反復の捕捉が可能になる。

状態メモリは頭あたり `O(M(R+d))` であり、Nに依存しない。全複素読出し行列を使う構成の1トークン復号仕事量は `O(M²(R+d))`、対角読出しなら `O(M(R+d))` で、いずれもNに関して定数である。ここで「定数」は**文脈長に対して**という意味で、モデル幅、頭数、基底数、バッチ数に対して一定という意味ではない。実装はMや行列積の大きさに応じて計算量を持ち、特に大きなバッチでは通常注意より遅くなることもある。

### 4. 実際の推論経路とメモリの節約

長い入力を2048トークンずつの固定チャンクへ分け、各チャンクを処理したら中間活性を解放して再帰状態だけを次チャンクへ引き継ぐ。復号に入った後は固定形状の状態を読み書きし、CUDAグラフを再実行する。この方式なら入力長に比例するKVキャッシュを確保しなくてよく、GPUメモリに収まる最大文脈長が通常注意より長くなる領域がある。

ただし、推論時に既存のソフトマックス注意モデルへこの層を単純差し替えして同じ出力を保てるわけではない。論文はInterdomain層を持つモデルを最初から学習し直して品質を評価しており、KVキャッシュの無損失圧縮アルゴリズムとは異なる。推論基盤で採用するには、対象モデルのアーキテクチャと学習済み重みが対応していることが前提となる。

## 評価

### 状態予算、言語品質、長文脈、実測速度

### 言語モデルの比較条件

FineWeb-Eduを使い、Llama型復号器のトークン混合部だけを変えて、125M、350M、760M、1.3Bパラメータの4規模を比較した。学習文脈長は4096、学習トークン数はそれぞれ25億、70億、150億、260億である。比較は通常ソフトマックス注意、提案方式、S4Dのみの方式を基本とする。S4Dのみの方式と提案方式は再帰状態の予算を揃え、通常注意はKVキャッシュが文脈長とともに増えるため固定状態予算の厳密比較から外す。最良学習時点の検証パープレキシティを報告する。

125Mの構成要素除去実験では、完全版のパープレキシティ16.48に対し、クエリ依存読出しを除いた「キー・値二系統入力＋線形読出し」は20.18へ悪化する。逆に二系統入力を一般的な射影へ替えてもクエリ依存読出しを残せば16.94であり、クエリ依存読出しの寄与が大きい。S4Dのみでは19.22、通常ソフトマックス注意では16.65である。位置埋め込みRoPEの有無はこの規模では小さな影響に留まり、改善の中心は位置表現ではない。

1.3BのFineWeb-Edu検証パープレキシティは提案方式7.98、同じレシピの通常注意8.63で、提案方式が約7.5%低い。再帰状態予算を揃えたS4Dのみとの比較では、4規模すべてで13〜16%の改善が報告される。常識推論8タスクの平均正答率は提案方式54.54%、通常注意51.51%、S4Dのみ49.44%である。一方、BoolQでは通常注意61.28%に対し提案方式59.63%と低い。したがって全タスクで一律に優位というわけではない。

### 訓練長を超えた文脈の品質

1.3Bモデルを訓練時の4Kから8K、14Kへ伸ばし、PG19、CodeParrot、GovReport、Qasper、QMSumの5データ集合でパープレキシティを測った。平均値は通常注意が4Kで12.79、8Kで20.54、14Kで55.92へ悪化するのに対し、提案方式は14.36、14.14、14.26とほぼ一定である。S4Dのみも27.24、26.89、26.75とほぼ一定であり、長さへの頑健性は主として固定長再帰状態の性質で、提案のクエリ依存読出しだけが生む特性ではない。

文脈長4Kの範囲では通常注意の平均パープレキシティ12.79が提案方式14.36より良い点も重要である。訓練長を超えると通常注意の性能が急に悪化した結果、14Kでは提案方式が相対的に有利になる。これは同じ学習レシピで訓練した比較であり、長文脈用に追加学習した通常注意モデルや位置埋め込みを拡張した実運用モデルとの一般比較ではない。

### 厳密検索の負の結果

固定長状態へ履歴を圧縮すると、厳密な文字列の取り出しが難しい。1.3BのRULER単一針検索では、1K文脈で通常注意99.5%に対し提案方式65.5%、2Kで100%に対し28.0%、4Kで89.0%に対し9.5%である。電話帳型の厳密照合では、リスト長16〜128のすべてで提案方式の正答率が0%だったのに対し、通常注意は24.0〜54.5%である。

Basedの6タスク平均は通常注意36.53%、提案方式24.63%、S4Dのみ14.44%で、提案方式はS4Dを上回るものの通常注意に届かない。LongBenchの14タスク平均は通常注意0.1240、提案方式0.1229、S4Dのみ0.0857であり、通常注意と提案方式はほぼ同水準である。**長さに対してパープレキシティが安定することと、過去の固有情報を正確に復元できることは別**であり、この論文はその差を明確に示している。

### 実機復号速度とメモリ上限

付録Cでは、1.3BモデルをNVIDIA RTX 6000 Ada（48GB、帯域約960GB/s）上でbfloat16混合精度で計測した。モデル構造は学習済み1.3Bと一致するが、**速度試験では重みをランダム初期化**しており、形状依存の性能を測るための別試験である。通常注意はPyTorchのscaled_dot_product_attentionを用いる即時実行、提案方式は即時実行とCUDAグラフ化の2経路を比較する。2048トークンのチャンク事前計算後、64復号ステップをCUDAイベントで測る。

|---:|---:|---:|---:|---|
| 1 | 13.39〜13.99ms | 12.42〜12.51ms | 1.08倍 | 小バッチでは起動オーバーヘッド削減が効く |
| 8 | 13.81〜21.60ms | 15.73〜15.98ms | 0.88倍 | 長い文脈では通常注意のKV読出しが増える |
| 16 | 13.51〜22.14ms | 19.51〜19.60ms | 0.70倍 | 通常注意は8K事前計算でメモリ不足 |
| 32 | 13.18〜22.75ms | 28.37〜28.58ms | 0.48倍 | 計算律速に近づき提案方式が遅い |

バッチ1では提案方式の即時実行約30msがCUDAグラフ化で約12.5msとなり、同じ方式内で約2.4倍の高速化が得られる。バッチ8では通常注意が文脈4Kまでは約13.8ms、8Kで約21.6msへ増える一方、提案方式は約15.9msでほぼ一定となる。提案方式はバッチ8以下なら文脈16Kまで処理できるのに対し、通常注意はバッチ8で8Kまでが実測上限だった。これはメモリ収容性の利点だが、同じ文脈長・バッチ数での処理時間が常に短いという意味ではない。

### 実測結果をどう読むべきか

「状態メモリが文脈長と無関係」という理論結果は、バッチを増やしても推論時間が増えないという意味ではない。実際には頭別の複素状態行列の計算や行列積がバッチとともに重くなり、バッチ32・64では通常注意より遅い。また、CUDAグラフによる起動費用の節約は提案方式の固定形状が利用しやすいという実装上の利点だが、通常注意側へ同等のグラフ化や最適化を適用した条件での比較ではない。性能差をすべて新しい注意数式の効率だけに帰属するのは不適切である。

## 既存研究との差

MambaやS4DなどのSSMは固定長の状態を持つが、クエリと個々の過去キーを照合しない。線形注意はキー・値の累積状態を構成するが、Interdomain AttentionはHiPPOに着想を得た基底射影を学習可能なS4D再帰で更新し、その基底係数へクエリ依存の読出しを適用する。通常注意とSSMの層を交互に並べるハイブリッド方式とも異なり、**一つの層の内部で履歴圧縮と内容依存読出しを結び付ける**。

また、KVキャッシュの削除や量子化と異なり、学習済みの通常Transformerをそのまま保持するための手法ではない。モデルをこの注意構造で学習する必要がある。推論基盤の観点では、固定長状態による長文脈収容性とCUDAグラフ化の容易さが重要であり、既存モデルへの後付け適用性は未実証である。

## 限界・負の結果・未評価事項

最も重大な制約は厳密検索性能である。文脈長が伸びてもパープレキシティが悪化しにくい一方、電話帳や固有文字列の復元では通常注意を大きく下回る。情報を固定長へ圧縮する構造的な制約と考えられ、クエリ依存読出しを導入しても完全には解消していない。長文書の要約や一般的な言語予測と、固有ID・コード断片の完全再現を同じ指標で評価してはいけない。

実機評価は最大1.3Bモデル、RTX 6000 Ada、特定のPyTorch/CUDA構成、ランダム初期化重みの形状依存計測である。7B以上のモデル、混合専門家モデル、マルチGPU、長文脈の実サービスで同じ利得が出るかは未確認である。通常注意側の実装も固定された比較経路であり、最適化の異なる別サービング基盤への一般化はできない。

理論導出は有限特徴写像とHiPPO基底の積分を前提とするが、実装はSiLU特徴写像、学習可能なS4D係数、分母なし読出しという緩和を採用する。従ってソフトマックス注意と出力が数学的に一致するわけではない。学習の安定性や予測精度は実証されているが、既存モデルを無損失で置き換える保証はない。

最後に、グラフ化による低遅延の利点は小バッチ中心で、大バッチでは逆転する。運用上は最大コンテキスト長だけでなく、要求バッチ分布、同時実行数、メモリ容量、厳密検索要件を見て選択する必要がある。
