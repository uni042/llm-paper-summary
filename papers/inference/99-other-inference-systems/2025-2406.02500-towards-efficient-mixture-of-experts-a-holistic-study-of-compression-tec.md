# Towards Efficient Mixture of Experts：構造削除と量子化を組み合わせるMoE圧縮の体系的研究

## 概要

混合専門家モデル（Mixture of Experts、MoE）は、各トークンについて多数の専門家から少数を選択することで、総パラメータ数の割に活性化計算量を抑える。しかし、**計算するパラメータが少ないことと、重みをGPUメモリに保持する費用が小さいことは別問題**である。例えばMixtral-8×7Bは総計約470億パラメータを持つが、1トークンで活性化するのは約130億パラメータであり、元モデルの重みメモリは原著の環境で87.7GBに達する。専門家を複数GPUへ分散する場合には、トークン配送と結果の結合にも通信費用がかかる。

本論文は、MoEの圧縮を二つの直交する方向に整理する。**専門家の刈り込み（Expert Trimming）**は専門家、MoE層、Transformerブロックなどの構造を削除する。**専門家の軽量化（Expert Slimming）**は残った各専門家の重みを量子化・枝刈りなどで圧縮する。従来の専門家削除（Expert Drop）は重み総量を減らせても、各トークンで選ぶ専門家数を維持する限り計算量と通信がほとんど減らない。この欠点を踏まえ、著者はMoE層全体を除くLayer Dropと、注意層を含むブロックを除くBlock Dropを提案し、AWQ量子化との組合せを比較する。

研究の主要な結論は、**細粒度の専門家削除より、計算グラフ全体から実行経路を取り除く粗粒度の構造削除が速度面で有利になり得る**ということだ。ただし、これは精度低下を伴う圧縮であり、報告される6.05倍は特定のモデル・設定・測定対象で得られた結果である。品質を完全保存したまま全LLMが6倍高速になるという意味ではない。

## 問題設定：専門家を減らしても速度が上がらない理由

MoE層には専門家 `E_1,...,E_n` とルータ `G` がある。ルータは入力xに対して各専門家の選択スコアを計算し、上位k個の専門家へトークンを送る。出力は選択された専門家の出力をルータ重みで加重合成したものである。一般的なTransformerでは、密なフィードフォワードネットワーク（FFN）の代わりにこのMoE層が置かれる。多数の専門家を保持する一方、1トークンで活性化する専門家は一部に限られる。

専門家削除は重要度の低い専門家をモデルから取り除き、ルータの対象も更新する。専門家総数nを減らしても、残存数がk以上なら**1トークンあたりの活性専門家数kは変わらない**。つまり専門家の重み保存量は減っても、FFN計算量は原理的に同じままである。ルーティング先や配置の変化により通信費用が下がる場合はあるが、一般には劇的な実行時間短縮にはつながらない。さらに専門家を減らすと、以前その専門家が担っていた特徴変換を別の専門家が代替できず、予測精度が落ちる危険がある。

原著のMixtral実験では専門家の25%削除でMMLU性能が約23%低下した一方、専門家12.5%削除の速度改善は1%未満だった。削除率と性能低下を混同してはいけない。これらは異なる削除率の例であり、「25%削除で1%未満」という単一条件の数値ではない。著者が粗粒度のLayer DropとBlock Dropを調べる理由は、この構造的な限界にある。

## 手法：圧縮の統一表現

### 1. Expert TrimmingとExpert Slimmingを分ける

統一表現では、残す専門家・構造の集合をT'、専門家iの元の重みをW_i、重み変換をfとし、圧縮後の出力を `y = Σ_{i∈T'} G_i E_i(x | f(W_i))` と表す。T'の選択が構造削除、f(W_i)が個別専門家の軽量化である。Expert DropはT'を縮める。量子化はf(W_i)で重みの数値精度を下げる。枝刈りは重みに二値マスクを掛ける。Layer DropとBlock Dropは、T'を専門家単位より大きい構造へ拡張したものと解釈できる。

この分解は、圧縮率を同じにしても効果が異なる理由を明確にする。量子化は重みメモリとメモリ帯域費用を減らすが、理論的な浮動小数点演算回数（FLOPs）を減らさない。非構造化枝刈りはFLOPsを減らせる可能性があっても、専用疎行列カーネルがなければ壁時計時間が縮まらない。専門家削除はパラメータを減らすが活性専門家数を保つ限りFLOPsが変わらない。Layer DropとBlock Dropは実行する層そのものをなくすため、FLOPsと通信経路の双方を減らせる。

### 2. Layer Drop：正規化とMoE層をまとめて除去する

Layer Dropは、MoE層全体を削除する。重要なのは、MoE単体の入出力を比較するだけでは適切な削除順位が得られないことである。TransformerブロックではMoEの直前に正規化（Norm）があり、残差接続により `y' = x' + MoE(Norm(x'))` と計算される。著者は、MoE単体の `x` と `MoE(x)` の余弦類似度ではなく、残差経路を含めた `x'` と `y'` の余弦類似度 `S^(NM)` を採用する。正規化とMoEを合わせて取り除く設計が、この類似度と実際のブロック機能を対応させる。

具体的には、校正入力をモデルに流し、各MoE層の前後の特徴ベクトルを保存し、余弦類似度を求める。類似度が高い層ほど出力表現の方向をほとんど変えないため、削除候補として優先する。これは精度の数学的保証ではなく、経験的な重要度指標である。削除後のモデルでは、そのMoE層に付随する専門家計算とトークン配送を実行しない。したがってExpert Dropとは異なり、実際の計算グラフから費用が消える。

### 3. Block Drop：注意層を含むTransformerブロックを除去する

Layer DropはMoE計算を削除しても、同じブロックの注意層を残す。Block Dropは注意層とMoE層を含むTransformerブロック全体を除去する。各ブロックの入力特徴と出力特徴の類似度を比較し、冗長性の高いブロックから削除する。注意層が消えることで、注意計算だけでなく、その層の鍵・値キャッシュ（KV cache）も不要になる。

原著は、バッチ128、系列長2048の例で、KVキャッシュが約32GBになる設定から、Block Dropによって約5GB削減できると述べる。ただし、これは指定のモデル・系列長・バッチ・削除数に依存する例であり、あらゆるモデルのKVが一定割合で減るわけではない。ブロック削除は最も粗い圧縮であるため、同じ削除数でもLayer Dropより表現品質を損なう可能性がある。計算削減と精度保持の両方を測って選ぶ必要がある。

### 4. Expert Slimming：残存専門家を量子化する

Expert Slimmingでは、残った専門家の重みを枝刈りまたは量子化する。著者は比較の結果、個別専門家の圧縮には量子化が性能・効率の両面で実用的と判断し、活性化を考慮した重み量子化（Activation-aware Weight Quantization、AWQ）を採用した。量子化は専門家数を変えずに重み保存量と転送量を削減するため、Layer DropやBlock Dropと組み合わせられる。

二段階の圧縮は互いに補完的である。先に構造を削ることで実行する層数を減らし、残存層の重みを量子化することで帯域制約を緩和する。反面、両方の近似誤差が重なるため、精度評価は片方ずつではなく組合せ後に必要である。論文は、量子化だけで元のFLOPsが減ったとは主張していない。表3ではAWQのみのMixtralはFLOPs 54.4Tのまま、重みメモリが87.7GBから24.4GBへ減る。

## 評価条件：モデル、課題、計測対象

原著は主にMixtral-8×7BとDeepSeek-MoE-16Bを用い、密な比較モデルとしてMistral-7Bを調べる。Mixtralは32ブロック、DeepSeek-MoE-16Bは28ブロックの構造削除を比較した。削除順位は校正入力の隠れ状態から算出する。著者はC4、Lima、MetaMathQAの違いやサンプル数の影響を調べ、128例を標準的な校正数として使用した。これは学習データ全体を必要としないが、モデルごとの実行と特徴取得は必要である。

性能は言語モデル評価基盤（LM Evaluation Harness）の8課題、ARC-C、BoolQ、HellaSwag、MMLU、OBQA、PIQA、RTE、WinoGrandeのゼロショット平均で比較する。表3の速度倍率とFLOPsは**系列長2048の入力を順伝播させる条件**で測定された。本文の図8には生成時の平均トークン速度も示されるが、表3の6.05倍を多ユーザー配信の要求完了時間やGPUクラスタの持続処理量に置き換えてはいけない。圧縮モデルの重みメモリと、実行時のKVキャッシュ・ワークスペース・ホストメモリも区別すべきである。

## 評価：専門家削除、層削除、ブロック削除の比較

Layer Dropの効果を示す代表例は、Mixtralの32 MoE層から8層を除いたとき、MMLUが67.9から67.3と小さく下がる一方、8課題平均では71.5から67.0へ低下する点である。**MMLUだけがほぼ維持されても、全課題平均は同程度に維持されるわけではない**。Block Dropで5ブロックを除いた場合は元性能の90%以上を維持したと著者は述べるが、表3では8課題平均71.5から68.6へ低下する。

密なMistral-7Bとの比較は、MoEの冗長性が高い可能性を示す。Mistralで8/32のLayer Dropを行うと4課題平均62.9から38.6へ24.3ポイント下がる一方、Mixtralでは64.6から57.6へ7.0ポイント下がる。同じ削除数に対する損失が大きく異なるため、密なモデルでの枝刈り結果をそのままMoEへ移植してはならない。また、これらは4課題の表2と8課題の表3で評価集計が異なるため、表間で平均値を直接混ぜて比較しない。

図8では同じ圧縮率でExpert DropよりLayer Drop、Block Dropの生成速度が大きく改善する傾向を示す。Expert Dropが速度をほとんど改善しないのは、活性専門家数を保ったまま構造を縮めることに起因する。Layer DropはMoE計算と通信を削り、Block Dropは注意計算も削るため、計算資源の使い方が異なる。ただし削除数が増えると性能は低下し、ランダム予測水準へ近づく場合もある。圧縮率だけを最大化する設計は適切でない。

## 評価：AWQとの組合せの定量結果

| Mixtral-8×7Bの設定 | 速度倍率 | FLOPs | 重みメモリ | 8課題平均 |
|---|---:|---:|---:|---:|
| 元モデル | 1.00倍 | 54.4T | 87.7GB | 71.5 |
| AWQのみ | 5.08倍 | 54.4T | 24.4GB | 70.8 |
| Expert Drop 2/8 | 1.06倍 | 54.4T | 66.7GB | 65.5 |
| Expert Drop 2/8 + AWQ | 5.28倍 | 54.4T | 20.1GB | 64.8 |
| Layer Drop 8/32 | 1.19倍 | 42.9T | 66.6GB | 67.0 |
| Layer Drop 8/32 + AWQ | **6.05倍** | **42.9T** | **20.0GB** | **66.1** |
| Block Drop 5/32 | 1.17倍 | 46.0T | 74.1GB | 68.6 |
| Block Drop 5/32 + AWQ | 5.94倍 | 46.0T | 21.9GB | 68.0 |

この表は原著表3の値を抜粋した。AWQだけでも大きな速度倍率が得られ、構造削除単独の速度倍率は1.17〜1.19程度である。したがって「Layer Dropだけで6.05倍」という解釈は誤りである。6.05倍は**Layer Drop 8/32とAWQを組み合わせた条件**であり、表3ではBlock Drop 5/32とAWQの組合せは5.94倍である。原著本文の一部には「Block Dropと量子化が6.05倍」と読める記述があるが、**表3の行ラベルとは一致しない**。本稿では再現可能な条件の識別を優先し、表の数値と本文の不整合を明記する。

「性能92%以上保持」は、表3の8課題平均66.1を元モデル71.5で割った92.4%程度という**相対的な平均値**の意味である。全課題で92%以上の正答率を達成したわけではない。例えば同じ条件のARC-Cは59.4から46.2、OBQAは46.8から39.0へ下がっており、特定課題の品質損失は大きい。推論サービスへの導入では、実際の利用課題に近い品質検証が必要である。

DeepSeek-MoE-16Bでは元モデルの8課題平均61.8、メモリ30.8GBに対し、AWQのみで60.9、9.8GB、3.16倍となった。Layer Drop 4/28 + AWQでは平均55.8、8.5GB、3.60倍、Block Drop 4/28 + AWQでは平均56.0、8.4GB、3.67倍である。Mixtralと同じ削除割合・性能交換条件ではなく、モデル固有の重要度分布が影響する。

## 評価：校正データ依存性と追加微調整

図9では校正サンプル数を変えたとき、層ごとの類似度順位が大きく変わらないことを示し、著者は128例を標準設定にした。またC4、Lima、MetaMathQAを用いても類似度の傾向が大きく変わらないと報告する。ただし、これは**類似度の安定性**の検証であり、任意の言語・専門領域・長文脈入力で圧縮後の出力品質が不変という保証ではない。図10では深い層が先に削除候補になる傾向を示し、モデル内部の冗長性が層位置に依存することを示唆する。

著者は圧縮後のDeepSeek-MoE-16BにAlpaca-GPT4を用いて3エポックの追加微調整を行い、学習率8e-6、ウォームアップ比0.03、コサインスケジュール、グローバルバッチ32を採用した。Block Drop 4/28では追加学習前の平均56.3が微調整後62.7となり、同じ微調整をした元モデルの平均63.3との差は0.6ポイントとなった。本文の「5.5%から0.6%」という記述はこの比較に対応する。ただし追加学習費用とデータが必要になるため、圧縮だけの学習不要方式と混同しない。

## 既存研究との差と実装上の意味

従来のExpert Dropはルータのスコアなどで重要度の低い専門家を削る。これに対しLayer Dropは正規化・残差接続を考慮した類似度を使ってMoE層全体を消し、Block Dropはさらに注意層を含むブロックを消す。これは単に専門家数を減らすのではなく、**実行する層数、通信経路、KVキャッシュを構造的に減らす**設計である。量子化との併用により、FLOPs削減と重み帯域削減の両方を狙う点が実務上の特徴となる。

実装では、削除後の層インデックス、ルータ構成、残差接続、KVキャッシュ層数を一貫して変更し、モデルファイルの重み配置も再構成する必要がある。AWQとの併用では量子化済み重みの読み出しと演算カーネルが速度に大きく影響する。論文の6.05倍という数値をllama.cppやGPU 12GB環境へそのまま適用することはできない。圧縮後の20.0GBは重みメモリの報告値であり、12GB VRAMへ収まることを示していない。CPUオフロードを併用する場合には、PCIe転送と活性専門家の配置も別途最適化が必要である。

## 限界・未評価事項

第一に、圧縮による品質低下は課題ごとに偏る。平均92%以上保持でも、ARC-CやOBQAの損失が大きい設定がある。第二に、性能改善の大部分がAWQ由来の条件もあり、構造削除単独の効果と組合せ効果を混同してはならない。第三に、論文はMixtralとDeepSeek-MoE-16Bを中心に調べており、より新しいMoE、異なるルータ構造、共有専門家の配置では同じ削除順位を使える保証がない。第四に、類似度計算には校正入力とモデル実行が必要であり、厳密な学習不要と運用費用ゼロは同義ではない。

第五に、表3の速度倍率は系列長2048の順伝播測定であり、長文脈の逐次復号、バッチの混雑、オンライン到着率、サービスレベル目標（SLO）達成率を直接測ってはいない。第六に、実GPUでのAWQカーネル性能、重み配置、分散通信、キャッシュ管理の影響を分離して評価する必要がある。第七に、表3と本文の6.05倍の構成名に不整合があるため、実装再現では表の行ラベルと公開コードの実験設定を確認するべきである。第八に、微調整で性能を回復する場合は、学習コストとデータの品質・ライセンスを考慮しなければならない。
