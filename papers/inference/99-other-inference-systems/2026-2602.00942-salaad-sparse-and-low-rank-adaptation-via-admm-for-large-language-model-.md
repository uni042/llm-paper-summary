# SALAAD：増補ラグランジュ法で学習時から疎・低ランク構造を誘導する可変容量モデル

## 概要

SALAADは、言語モデルの重みを疎成分と低ランク成分の和として表現できるように**事前学習中から構造を誘導**し、配置時には必要なメモリ予算に応じて同じ学習済みチェックポイントを縮小できる方式である。単に学習済みモデルの重みを後処理で削るのではなく、密な学習用重み`X`と構造化された代理重み`L+S`を同時に管理する。学習損失と構造化の制約を増補ラグランジュ法（Augmented Lagrangian Method）で結び、層ごとの低ランク性と疎性を適応的に制御する。

原著の1B規模のLLaMA型モデルでは、密な学習用重み1339Mのパープレキシティ14.74、構造化重み905Mでは14.72、配置時の追加削減で646Mにしたモデルでは15.07と報告する。これは同一の学習済みモデルから容量を調整できる可能性を示すが、**学習済み既存モデルを再学習なしに圧縮できる方式ではない**。また比較法の学習精度がbfloat16なのに対し、主表のSALAADはfloat32で学習しており、訓練費用を揃えた比較ではない。

研究上の価値は、各層へ同じランクや疎率を強制せず、構造化の進行を適応制御して、容量制約を学習と配置の二段階で扱う点にある。低ランクと疎成分の組合せは実装上の演算器・メモリ配置に依存するため、パラメータ数の削減と推論遅延の短縮を同一視してはいけない。

## 問題設定

大規模モデルをGPUやエッジ機器へ配置する際には、モデルのパラメータ数、重み精度、KVキャッシュ、実行時の一時領域がメモリを制約する。通常は異なる規模のモデルを別々に学習するか、既存モデルを枝刈り・量子化・蒸留する。後処理の圧縮では、学習中に形成された重みが低ランクや疎な表現に適していない場合、急激な性能劣化が起こる。

低ランク表現は、行列を小さい二つの行列の積として表し、保存要素数と計算量を減らす。一方、低ランクだけでは局所的に重要な例外成分を表しにくい。疎成分を加えると、少数の大きな残差を保持できるが、疎演算の実装や索引保存の費用が増える。従来の構造化学習法は、層ごとに固定ランク・固定疎率を指定することが多く、埋め込み層や注意射影などの異質性に対応しにくい。

SALAADは、各重みブロック`X_i`を`L_i+S_i`に近づけながら通常の言語モデル学習を進める。必要な配置容量が変わっても、学習をやり直さずに構造化成分の一部を切り落とせるようにする。したがって最適化の対象は単なる低い学習損失ではなく、学習済み重みが**後から複数の容量で利用可能な構造**を持つことである。

## 手法

### 疎・低ランク分解の制約付き最適化

重みブロックを`X`、低ランク成分を`L`、疎成分を`S`とし、`X=L+S`を制約とする。目的関数は通常の学習損失`ℓ(X)`に、低ランクを促す核ノルム`α||L||_*`と疎性を促す`β||S||_1`を加えたものになる。核ノルムは特異値の和で、ランクの緩和として使う。L1ノルムは小さな要素をゼロにしやすくする。`α`と`β`は構造化の強さを制御する。

著者は制約`X-L-S=0`を双対変数`Y`と罰則係数`ρ`で扱う増補ラグランジュ関数を導入する。`X`は言語モデルの勾配で更新し、`L`は特異値分解（SVD）と特異値の軟閾値化、`S`は要素ごとの軟閾値化で更新する。最後に双対変数を制約違反に応じて更新する。この手順によって、密な重みを学習しつつ、構造化代理重みが密な重みを追跡する。

### 学習を二段階に分ける理由

標準的な交互方向乗数法（Alternating Direction Method of Multipliers; ADMM）を全データの反復学習に直接適用すると、各更新で大きな学習データを繰り返し処理する必要があり、LLMの事前学習では高価になる。SALAADは、ミニバッチを用いた通常の勾配更新を`K`回行う第一段階と、構造化成分を`J`回更新する第二段階を交互に実行する。

第一段階では、`ℓ_c=ℓ(X)+(ρ/2)||X-L-S+Y/ρ||_F^2`を最小化する。通常の言語モデル損失に、密な重みが構造化代理重みから離れすぎないための罰則を加える。第二段階では`X`を固定して、`L`の特異値を閾値化し、`S`の小さな要素をゼロにし、双対変数を更新する。これにより、通常の最適化器を維持しながら構造化の制約を徐々に強める。

出力される重みには二種類ある。`X`は通常の密な学習用重みで、必ずしも疎・低ランクではない。`L+S`は構造化が保証された代理重みである。学習中の`X`と`L+S`の差を小さく保つことで、配置時に代理重みへ切り替えても品質が大きく変わらないようにする。ただし完全一致するわけではなく、パープレキシティの差を実測で確認する必要がある。

### 積分制御器による層別構造の調整

各ブロックへ個別の`α,β,ρ`を手作業で設定するのは、層数が多いモデルでは難しい。SALAADは積分制御器（I-Controller）を導入し、目標とする有効ランク比`Γ_hat`と疎成分の密度`Υ_hat`に向けて、各ブロックの閾値を更新する。

低ランク成分の有効ランク比は、特異値の累積和が全体の一定割合を覆うまでに必要な特異値数を、行列の最小次元で割った値である。原著はエネルギー被覆の閾値として`γ=0.999`を使う。疎成分の密度はゼロでない要素の割合で測る。制御器は、観測された有効ランクや密度と目標値との差に応じて`α,β`を少しずつ更新する。

同じ目標比率を与えても、実際に形成される構造は各層の学習過程と重要度に応じて異なる。これにより、注意射影と埋め込み層などの異質なブロックへ固定のランクを押し付ける問題を緩和する。実験では全モデル規模に対して目標有効ランク比0.15、目標密度0.05を用い、制御係数を調整している。

### 配置時の同型パラメータ配分

学習後には、低ランク成分の小さな特異値と、疎成分の絶対値の小さい要素を追加で削減する。原著は同型パラメータ配分（Homomorphic Parameter Allocation; HPA）を提案する。削減予算`C`のうち割合`κ`を低ランク成分へ、残り`1-κ`を疎成分へ割り当てる。全ブロックに同じ削減割合を適用するが、各ブロックの元のランクと密度が異なるため、最終的な構造の異質性は保持される。

これは重要度を厳密に最適化する方法ではなく、特異値の大きさと疎成分の絶対値を重要度の代理とする貪欲近似である。`κ`を変えると、同じ総パラメータ予算でも品質が変わる。原著は複数予算にわたって`κ>0.5`、すなわち低ランク側の削減に多めの予算を割く方が良い場合が多いと報告する。ただし最適な`κ`があらゆるモデルやタスクで共通とは保証されない。

### 低ランクと疎演算の実装上の注意

低ランク成分`L`は二つの小行列の積として保存し、疎成分`S`は非ゼロ要素と索引で保存する必要がある。原著のパラメータ数は主に構造化表現の保存量を示すが、疎演算カーネルの効率、GPUの行列演算器への適合、索引のオーバーヘッド、モデル読込時間によって実際の速度は変わる。パラメータ数が半分になっても、推論時間が半分になるとは限らない。

## 実験設定

| 項目 | 原著の条件 |
|---|---|
| モデル | LLaMA型の60M、130M、350M、1B |
| 学習データ | C4、同じ学習トークン数を使って比較 |
| GPU | NVIDIA A100またはH100。時間分析はH100 80GB×8 |
| 主表の学習精度 | SALAADはfloat32、比較法は主にbfloat16 |
| 推論精度 | bfloat16 |
| 比較法 | Full-Rank、LoRA、ReLoRA、GaLore、LORO、CoLA、SLTrain、LOST |
| 学習制御 | Adam、重み減衰0、目標ランク比0.15、目標疎密度0.05 |
| 評価 | パープレキシティ、構造化後のパラメータ数、ゼロショット正答率、学習時の損失・構造追跡 |
| 公開実装 | https://github.com/HaoMAFRLu/salaad |

原著の主表ではSALAADだけがfloat32で学習しているため、同じ計算資源や学習メモリ予算での厳密な公平比較ではない。著者も学習時メモリを主表では報告しないと明記する。配置時の省メモリを主目的とし、学習計算費用の増加を許す研究設計である。

## 主要結果

原著表1から、構造化された`L+S`とHPAでさらに削減した`Ltilde+Stilde`の値を示す。PPLは低いほど良く、パラメータ数は保存する構造化表現の規模を示す。

| モデル規模 | Full-Rank PPL / M | SALAAD `X` PPL / M | SALAAD `L+S` PPL / M | HPA後 PPL / M |
|---|---|---|---|---|
| 60M | 34.06 / 58 | 31.59 / 58 | 31.26 / 50 | 31.97 / 44 |
| 130M | 24.36 / 134 | 22.90 / 134 | 22.65 / 126 | 23.90 / 97 |
| 350M | 18.80 / 368 | 18.30 / 368 | 18.04 / 276 | 19.70 / 194 |
| 1B | 15.56 / 1339 | 14.74 / 1339 | 14.72 / 905 | 15.07 / 646 |

1B規模では、HPA後の646MはFull-Rankの1339Mより少なく、PPLも15.07対15.56と低い。これは**SALAADで学習したモデルの構造化と容量調整が機能する**ことを示す。ただし、同じ646Mでの比較法LOSTはPPL15.02を報告しており、SALAADが全比較法に一貫して優れるわけではない。またLOSTは追加の非線形層を使うため、元のアーキテクチャを維持するかどうかという条件が異なる。

### 下流課題の品質

1Bモデルのゼロショット評価では、HPA後646Mのモデルと密な`X`の比較で、MMLUは23.0対23.0、ARC-Cは22.0対22.0、HellaSwagは36.0対36.0で一致する。一方COPAは71.0から69.0へ、BoolQは54.0から52.0へ低下し、PIQAは68.0から69.0へ上がる。全指標が不変という意味ではなく、代表的な多肢選択課題で大きな崩壊が起きなかったという範囲の結果である。

### 制御器と圧縮率の感度

原著表3では350Mモデル、`ρ=5×10^-8`、`Δα=0.2`固定のとき、`Δβ`を0.003から0.1へ増やすと、構造化モデルのPPLは18.43から20.81へ悪化し、パラメータ数は241Mから218Mへ減る。別条件で`Δβ=0.005`固定のとき、`Δα`を0.08から0.2へ増やすと、PPLは17.97から18.96へ変化し、268Mから228Mへ減る。これはより強い構造化制約がメモリ削減と品質低下の交換条件を作ることを示す。

表4では`Δα=0.1, Δβ=0.01`のとき、`ρ`を`5×10^-8`から`1×10^-7`へ増やすと、構造化モデルのPPLは18.23から19.26へ悪化し、257Mから221Mへ削減される。制御係数を大きくするほど必ず良いわけではない。適切な容量と品質の組合せを選ぶ必要がある。

### 構造化対象と学習精度の影響

埋め込み層も構造化対象に含めた350Mモデルの分析では、埋め込み層の有効ランク比が約21%、疎成分密度が約12%へ収束し、他ブロックの学習曲線はほぼ変わらなかったと報告する。一方、出力言語モデルヘッドでは同じ良好な構造が現れないと付録に記載される。したがって全種類の重みが同程度に圧縮可能とは言えない。

付録のbfloat16学習では、60M・130M・350Mで学習と推論をbfloat16に揃えた条件も報告する。350Mの`L+S`は287MでPPL18.93、HPA後194Mで19.73であり、float32主表の対応値276Mで18.04、194Mで19.70と異なる。精度を揃えた比較は可能だが、主表の最良値だけを使ってbfloat16学習の費用を推定してはいけない。

### 学習時の追加費用

SALAADは、通常の勾配更新のほかに特異値分解、疎成分の閾値化、双対変数の更新を行う。原著は350Mと1BのH100×8で学習時間の内訳を調べ、追加費用の中心がADMM更新であると説明する。構造化ブロックを複数GPUに分散すると追加費用は低下するが、学習メモリを一律に削減する仕組みではない。むしろ密な重み、低ランク成分、疎成分、双対変数などを学習中に保持するため、推論時の節約と学習時の節約を混同すべきではない。

## 既存研究との差

LoRAは主に学習パラメータの低ランク化を目的とし、元の重みを保持したまま適応する用途で広く使われる。SALAADは学習済みモデル全体の重みが疎・低ランクに分解できるよう誘導し、配置時の保存容量を可変にすることが主眼である。学習後の枝刈りや量子化とも異なり、学習時から圧縮可能性を高める。LOSTやSLTrainなどの構造化学習と比較すると、各ブロックの有効ランクと密度を制御器が自動調整する点、学習後のHPAで容量を連続的に選べる点が特徴となる。

量子化と組み合わせる可能性はあるが、原著の表1の削減率は基本的にパラメータ構造に関するもので、4ビット量子化と同じ評価ではない。メモリ制約のある端末で使うには、低ランク行列積、疎演算、量子化、KVキャッシュを合わせた実装評価が必要である。

## 限界・負の結果

第一に、事前学習から手法を導入する必要があり、一般の既存モデルを重みだけ受け取って即座に同じ品質で圧縮できるとは限らない。第二に、比較法の主な学習精度がbfloat16なのに対してSALAAD主表はfloat32であり、学習時メモリ・計算量の公平性が制限される。第三に、実験最大規模は約1Bであり、30Bや70B、MoEモデルへの拡張性は実測されていない。

第四に、疎成分は索引や不規則メモリアクセスの費用を伴い、パラメータ数の減少がそのまま推論速度向上につながるわけではない。第五に、HPAの配分係数`κ`は重要度の大きさに基づく貪欲近似であり、予算によって品質が変わる。第六に、強い構造化制約はパープレキシティを悪化させる。原著の構成要素除去表はこの交換条件を明確に示す。

第七に、埋め込み層は比較的圧縮しやすいが、出力ヘッドは同じ性質を示さないという負の結果がある。第八に、ゼロショット評価は1Bモデルの限定された分類・多肢選択課題であり、長文脈生成、対話品質、コード生成、大規模サービングでの品質保証ではない。
