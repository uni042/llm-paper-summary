# Attention Buckets：回転位置埋め込みの注意の谷を並列推論で補う

## 概要

大規模言語モデルが外部ツールを選ぶ際には、利用可能な機能、引数、実行条件などの説明を長い文脈から正しく参照する必要がある。しかし、必要な情報を入力に含めたにもかかわらず、置かれた位置によってモデルが参照に失敗する場合がある。本研究は、その一因として回転位置埋め込み（Rotary Position Embedding、RoPE）による注意スコアの位置依存の波形を調べ、情報が注意の「谷」に置かれると参照精度が下がり得ることを示す。

提案方式Attention Bucketsは、学習済みモデルの重みを変更せず、同じ入力文脈を複数の分岐へ複製し、それぞれ異なるRoPE基数を適用する。ある基数で注意が弱くなる位置を別の基数の強い位置で補うことを狙い、各分岐の次トークン予測確率を信頼度に応じて加重平均する。各分岐の最終文章を多数決する方式ではなく、**生成の各トークンで語彙分布を合成する**ことが重要である。モデルの再事前学習や追加微調整を必要としない一方、複数の分岐を同時に動かすメモリ費用が発生する。

ACL 2024正式論文では、ToolBenchのToolLlama-7Bとツール検索器付き深さ優先探索設定において、平均の課題達成率が67.3%から71.3%、ChatGPTを判定器とする勝率が63.1%から71.5%へ改善した。検索拡張生成（Retrieval-Augmented Generation、RAG）に相当する開放領域質問応答でも、Natural Questionsが48.5から50.3、WebQuestionsが51.7から53.1へ改善した。ただし、これらは特定のモデル・評価設定に関する精度指標であり、GPUの計算時間やスループットが同じ比率で改善したという意味ではない。

## 問題設定と着想

一般のTransformerでは、入力の問い合わせと鍵の内積から注意スコアを計算する。RoPEは各位置に応じて問い合わせと鍵を回転させ、相対距離を内積に反映する。回転角の周波数は基数に依存するため、同じ内容でも文脈内の位置と基数の組合せによって注意の強さが変わり得る。著者らは、相対距離に対する注意スコアの長期的な減衰に加えて、周期の異なる波が重なるような山谷が生じると観察した。

文脈中のどの箇所が重要かを実際のツール利用の前に確定できれば、その情報を注意の山へ移す方法も考えられる。しかし、未知のユーザー要求、ツール説明、過去のAPI応答が混在する実運用では、何が重要になるかを先に知ることは難しい。さらに、最適なRoPE基数は文脈長や要求によって変わる。単一の基数を選ぶだけでは、ある位置を改善して別の位置を悪化させる可能性が残る。

著者らは、無作為なキー・値の組をJSONとして並べ、指定されたキーに対応する値を復元させる合成検索課題を設計した。Llama-2-chat-7Bを使い、基数を10,000から30,000まで5,000刻みで変え、40組または50組のキー・値を配置する。各条件で、標的の最後のトークンを注意の山または谷に合わせ、入力長を揃えて精度を比較した。これは位置だけの影響を調べるための制御実験であり、ツール利用そのものの実験とは区別する必要がある。

## 手法：複数RoPE基数の推論を分布合成する

### 1. 回転角基数と注意波形

RoPEの次元を`d`、周波数成分の添字を`i`、基数を`B`とすると、各回転成分の角周波数は`B^(-2i/d)`に比例する。問い合わせ位置`m`と鍵位置`n`の回転後内積は、相対距離`n-m`の関数として表せる。原著第2.1節と付録Aは、これを正弦・余弦の和として整理し、注意の位置依存の山と谷を説明する。これは単一の厳密な周期を持つ波ではなく、複数周波数の合成であり、文脈長に応じて波形が変化する。

注意の山谷はモデルの最終正答率と一対一に対応する決定論的な法則ではない。著者らは合成検索課題で統計的な対応を観測し、位置依存の弱点を複数の基数で補完するという設計を導く。基数を学習時の値より小さくすると、学習時に経験していない回転位置を生む可能性があるため、探索範囲の下限は学習時の基数に置く。

### 2. 補完的な基数集合の探索

推論分岐に使う基数集合`Bc`を、候補集合`Bs`から段階的に選ぶ。最初に学習時の基数`Btrain`を集合へ入れ、残りの基数は、既存集合の山と候補の谷、既存集合の谷と候補の山の位置差が小さくなるよう選択する。これにより、ある分岐が弱くなる相対位置を別分岐が補いやすくする。

原著の例では、`Bmin=10,000`、`Bmax=30,000`、刻み500、分岐数6とし、`{10,000,17,500,18,000,19,000,20,000,25,000}`を選ぶ。探索は推論の各トークンで行うのではなく、波形から基数集合を事前に決める手続きである。探索対象の文脈長を超える位置への性能は、この集合の選択だけでは保証できない。

### 3. 並列分岐と信頼度の計算

入力文脈を`N`個に複製して一つのバッチとして扱い、分岐`j`に基数`Bj`を割り当てる。各分岐は同じ学習済み重みを使うが、位置回転が異なるため、次トークンの語彙分布`p_j(v)`が異なる。著者らは各分岐の最大トークン確率を`c_j=max_v p_j(v)`として取り出し、その値をソフトマックスで正規化した重み`α_j`を求める。重みは`α_j=exp(c_j)/Σ_i exp(c_i)`である。

この重みを用いて合成分布`p̂(v)=Σ_j α_j p_j(v)`を計算し、そこから次トークンを復号する。採用したトークンを各分岐の共通の生成履歴へ追加し、次の生成位置でも同じ手続きを繰り返す。したがって、分岐ごとに完全な文章を最後まで生成してから投票する自己整合性法とは、計算経路も合成対象も異なる。

最大確率を信頼度の代理指標にすることは、モデルの確率が常に正答の確信度として適切に校正されているという保証ではない。誤った候補へ高確率を与える分岐がある場合、その分岐に大きな重みが付く可能性がある。手法の有効性は、異なる基数の位置感度が相補的であるという経験的な仮定に依存する。

### 4. 実行基盤とメモリ費用

分岐をバッチ内で並列に処理できるため、GPUに十分な空きメモリと演算資源がある場合、分岐数に比例して応答時間が延びるとは限らない。原著は全実験を単体A100 80GBで実施し、十分なメモリがある条件では推論速度を損なわないと説明する。ただし、複数の文脈を同時に保持するため、鍵値キャッシュと中間活性の費用は増える。基数が異なる分岐間で全てのKVを無条件に共有できるわけではない。

この研究は、低精度量子化、CPUへの退避、SSD階層化、複数GPUの通信削減を直接提案するものではない。むしろ同じモデルを複数の位置設定で同時に評価することで品質を上げる方式であり、メモリに余裕のない推論基盤では採用可否を別途判断する必要がある。

### 1. 位置による正答率の差

| RoPE基数 | 40組・山 | 40組・谷 | 50組・山 | 50組・谷 |
| ---: | ---: | ---: | ---: | ---: |
| 10,000 | 79.8 | 76.8 | 47.6 | 44.0 |
| 15,000 | 96.6 | 96.2 | 75.8 | 75.2 |
| 20,000 | 85.2 | 85.0 | 82.6 | 80.4 |
| 25,000 | 70.8 | 70.0 | 59.2 | 55.6 |
| 30,000 | 62.2 | 57.6 | 51.8 | 24.4 |

原著表1は、同じ基数でも注意の谷へ重要情報を置くと山より低い正答率になりやすいことを示す。特に50組、基数30,000では山51.8%に対して谷24.4%であり、27.4ポイントの大きな差がある。一方、40組の基数20,000では85.2%と85.0%で差は小さい。したがって、位置効果が常に同じ大きさで生じるとはいえない。また40組の最良基数は15,000、50組では20,000であり、最適基数を固定する難しさを示す。

### 2. ToolBenchの主要結果

| ToolLlamaの方式 | 平均課題達成率（pass） | 平均勝率（win） |
| --- | ---: | ---: |
| DFSDT-Retriever（通常） | 67.3% | 63.1% |
| 注意波形を事前平均する単一分岐 | 56.0% | 45.3% |
| 注意ソート | 67.8% | 64.6% |
| 普遍的自己整合性 | 68.1% | 65.9% |
| **Attention Buckets** | **71.3%** | **71.5%** |
| GPT-4＋DFSDT（別モデル比較） | 71.1% | 70.4% |

原著表2・3に基づく。提案方式は同じToolLlamaの通常設定に対して課題達成率を4.0ポイント、勝率を8.4ポイント改善する。GPT-4＋DFSDTの71.1%、70.4%を数値上わずかに上回るが、比較対象のモデルや探索経路が異なるため、7Bモデルがあらゆる条件でGPT-4より優秀になったと一般化してはいけない。勝率はChatGPTによる判定であり、人手による絶対的な正解判定ではない。

ToolBenchは、既知ツールに対する新しい指示、同じ分類内の未知ツール、未知分類のツールという難しさを含み、単一ツール・同一分類内の複数ツール・異なる分類をまたぐ複数ツールの場面を評価する。著者は6種類の組合せを報告し、提案方式がほぼ全体で改善することを示す。しかし、I2-Cat.のように、DFSDT-Retriever通常のpass68.5%に対して提案方式71.0%であっても、勝率は60.8%から64.5%という別の幅で変化する。二つの指標を混同して「成功率が8.4%上がる」と表現しない。

### 3. 構成要素除去：事前平均では代替できない

波形を複数用意しても、推論前にそれらを単一の位置回転へ平均してしまうと、分岐を同時に使う設計とは異なる。原著表3では、この単一分岐方式のpass56.0%、win45.3%は、通常の67.3%、63.1%を下回る。著者は、平均した波形が学習時と異なる位置表現を生むことを一因として挙げる。これは「基数の平均」と「各基数での予測分布の平均」が同等ではないことを示す重要な負の結果である。

注意ソートは、文脈を注意スコアの大きさに従って並べ替え、重要と推定した内容を後方へ置く方式である。通常設定よりpass0.5ポイント、win1.5ポイントの改善にとどまる。普遍的自己整合性は複数の完成回答から整合性の高いものを選ぶ方式で、通常比pass0.8ポイント、win2.8ポイント改善した。提案方式は同程度の追加推論を用いて、最終回答の選別より前の**各生成トークンで位置感度を補う**ため、同じ比較でより大きな改善を得たと著者は解釈する。

### 4. 検索拡張生成への適用

| 方式 | Natural Questions | WebQuestions |
| --- | ---: | ---: |
| FiD-XL 3B（専用読解器） | 50.1 | 50.8 |
| Llama-2-7B（通常） | 48.5 | 51.7 |
| Llama-2-7B＋注意ソート | 48.9 | 52.1 |
| Llama-2-7B＋普遍的自己整合性 | 47.6 | 51.7 |
| **Llama-2-7B＋Attention Buckets** | **50.3** | **53.1** |

原著表4では、DPRが検索した10文書を入力し、許容される回答文字列を含むかどうかで評価する。提案方式は通常Llama-2-7BからNatural Questionsで1.8ポイント、WebQuestionsで1.4ポイント改善する。Natural Questionsでは専用読解器FiD-XLの50.1をわずかに上回り、WebQuestionsでは50.8を上回る。ただし、検索器、モデル、訓練データ、入力長が異なる比較も含むため、差を全てRoPE基数の効果だけに帰属することはできない。

### 5. 別のツール利用課題と基数探索の除去実験

付録EのToolAlpacaは模擬ツールのみを使う。ToolAlpaca-7Bの全体評価は60.0から65.0、13Bは70.0から74.0へ改善した。手順・応答・全体の各得点も、7Bでは63.0/69.0/60.0から69.0/73.0/65.0、13Bでは70.0/73.0/70.0から75.0/78.0/74.0へ改善する。実際の外部APIを使ったツール実行については、元のToolAlpacaコードの再現性制約により、この追加実験から直接保証できない。

付録FのNQ除去実験では、基数10,000の単独正答率48.56に対し、基数20,000の単独は50.28、6基数の探索集合は50.22、7基数の別の探索集合は50.31である。探索集合は50.22〜50.31の範囲に収まり、等差的に並べた基数集合の49.89〜50.19を概ね上回る。ただし、**基数20,000単独の50.28は一部の探索集合を上回る**。従って、提案集合が全ての入力に対して最適であるとする証拠ではなく、事前に未知の入力長・課題へ適用する際の頑健性を狙った方式と理解すべきである。

## 既存方式との差と推論システム上の位置付け

本研究は、推論エンジンのGPUメモリ配置、専門家並列化、KVキャッシュ圧縮を直接改良するものではない。RoPEを使う学習済みモデルの位置依存の注意弱点を、推論時に複数の位置回転を試すことで補う。文脈を一度だけ並べ替える注意ソート、回答を複数生成して最後に選ぶ自己整合性、注意波形を事前に一つへ平均する方式とは、分岐ごとの予測分布をトークンごとに合成する点が異なる。

基数集合を選ぶための山谷探索は、推論要求のたびに大規模な訓練を行う処理ではない。分岐を同時に実行できるGPU環境なら、位置感度の異なる複数の計算経路を一つのバッチとして扱える。しかし、バッチを増やすほどKV保持量、演算量、GPUメモリ帯域への要求は大きくなる。複数利用者の要求をすでに大量に処理している提供基盤では、この追加バッチが他要求の待ち時間やスループットに影響する可能性がある。

実装上、異なる基数の分岐を同一のモデル重みへ接続できることは利点だが、分岐ごとに回転後の鍵や注意状態が異なるため、単純な一個のKVキャッシュで全分岐を完全に代用できるわけではない。GPUメモリの絶対増分、要求当たりの実際の時間、同時実行下の劣化を定量化するには、著者の精度実験とは別の推論システム計測が必要である。

## 限界・負の結果・再現性

第一に、著者自身が、RoPE以外の位置埋め込みへ一般化できるかは未検証とする。注意の山谷に関する導出と基数の変更はRoPEの回転構造を利用している。絶対位置埋め込み、相対バイアス、別の線形状態モデルへ同じ方式をそのまま移すことはできない。さらに、注意スコアの波形は正答率の一因を説明するが、どのトークンが実際に重要かを正確に検出する万能な判定器ではない。

第二に、メモリと速度の交換条件が未解決である。原著はA100 80GB上で十分なメモリを確保して実験し、並列処理によって速度を維持できると説明するが、全分岐の絶対メモリ占有量、初回トークン遅延、生成トークン間遅延、同時要求数を網羅した表はない。6分岐を単体12GBのGPUへそのまま適用できる保証はなく、CPU/RAMへの退避や量子化を併用したときの性能も報告していない。

第三に、単一分岐へ波形を事前平均する方式は、原著表3で通常方式より明確に低精度となる。これにより、計算費用を削減する単純な近似が必ずしも有効でないことが分かる。複数分岐の出力確率を最大確率で加重する設計も、誤った分岐の過信に対して数学的な正答保証を与えるものではない。

第四に、評価指標の解釈に注意が必要である。ToolBenchのwin率はChatGPTの判定を含み、ToolAlpacaの評価は模擬ツールだけであり、実APIの失敗・副作用・呼出し費用を測っていない。NQとWebQAの改善も指定されたDPR検索・10文書・Llama-2-7Bの設定に限られる。2024年当時の7Bモデルで得られた利得が、現在の長文脈モデルや異なるRoPEスケーリングを採るモデルでも同じとは限らない。

第五に、基数集合の探索結果は課題や文脈長で変わる。付録Fでは単一基数が探索集合の一部を上回る例もあり、探索集合の厳密な最適性を示したわけではない。分岐数を増やせば注意の谷を補う可能性は高まるが、必要なメモリも増え、精度の単調増加は保証されない。実用上は対象モデル、入力長、利用可能なGPUメモリを踏まえて分岐数を選ぶ必要がある。
