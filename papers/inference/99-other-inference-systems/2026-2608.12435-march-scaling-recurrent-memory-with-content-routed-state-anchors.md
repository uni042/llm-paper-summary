# MARCH: Scaling Recurrent Memory with Content-Routed State Anchors

## 概要
Transformerは過去トークンをKVキャッシュとして残すため長距離検索に強いが、推論メモリは文脈長に比例する。Gated DeltaNetのような再帰型モデルは履歴を固定サイズ状態へ畳み込むため復号は軽い一方、古い関連情報が後続更新で上書きされやすい。

MARCH（Memory-Anchor Routing across Context History）は、累積再帰状態を一定間隔で状態 anchorとしてチェックポイントし、各anchorに内容依存の小さなルーティング keyを付ける。各トークンは現在状態の通常読み出しに加え、ルーティング queryで過去anchorを選び、その状態 読み出しを残差として加算する。再帰の高速経路を維持したまま、総記憶容量だけを文脈とともに増やす設計である。

## 問題設定
固定状態の再帰モデルでは計算量・メモリが有利でも、複数文書QAやneedle retrievalのように過去の特定事実を再取得する課題で性能が落ちる。単に状態サイズを増やすと毎トークンの更新コストが増える。MARCHは「常に更新する状態」と「まれに保存し必要時だけ読む履歴状態」を分離する。

## 手法
### State anchor
既定では512トークン程度のchunk境界で累積状態を保存する。anchor トークンの隠れ representationから小次元keyを作るため、anchorの時刻ではなく内容に応じて後続queryが選択できる。

### 内容ルーティング
現在トークンからルーティング queryを生成し、因果的に参照可能なanchor keyとのsoftmaxを計算する。learned null optionも候補に含め、過去参照が不要な場合はanchor branchを実質的に無効化できる。選ばれたanchor 状態を通常の状態-read queryで読み、現在状態の出力へ加える。

### 疎ルーティングと融合実装
anchor数が増える長文脈ではTop-K（評価ではTop-4）だけを読む。producer 段が通常の再帰更新とチェックポイント生成を行い、reader 段がquery×anchorをtile化した融合カーネルで読む。巨大なルーティング中間行列をHBMへ書き出さない。

## 評価条件
| 項目 | 条件 |
|---|---|
| 事前学習 | 50Bトークン |
| 学習文脈 | 16K |
| 規模 | 約780M、21層、隠れ 1536を中心 |
| 基底 | Gated DeltaNet |
| 比較 | vanilla GDN、Log-Linear GDN、サイズ整合Transformer |
| 長文評価 | LongBench、RULER/NIAH、6種in-context retrieval |
| 効率 | 密 ルーティング、Top-4 ルーティング、FlashAttention-2比較 |

## 主要結果
| 指標 | Gated DeltaNet | 強い再帰比較対象 | MARCH |
|---|---:|---:|---:|
| LongBench平均 | 11.9 | 12.5 | 14.9 |
| in-context retrieval平均 | 19.2 | 20.5 | 23.3 |
| 8K single NIAH | 55.3 | — | 81.7 |
| 8K RULER aggregate | 16.9 | 16.9 | 30.8 |

LongBenchは基底GDN比で約25%相対改善、retrievalは強い再帰比較対象比で約14%改善する。16Kで学習したにもかかわらず32K NIAHでも非ゼロ精度を維持する課題があり、長さ依存パラメータを持たないcontent ルーティングの外挿性を示す。128KではTop-4 ルーティングが密 MARCHのスループットを2倍超にし、FlashAttention-2も上回る。

## 既存研究との差
Log-Linear系が単一再帰状態への読み書きを改善するのに対し、MARCHは過去の「状態そのもの」を複数保存する。Transformerのトークン KVより粗い512-トークン単位の状態メモリなので、履歴解像度と容量をchunk サイズで調整できる。

## 限界
anchor bank自体は文脈長とともに増えるため、完全な定数メモリ再帰ではない。Top-K ルーティングは効率を改善するがNIAH品質では密 ルーティングに劣る条件がある。実験は約780M級の事前学習が中心で、数十B級LLMや実サービングデコードで同じ速度・品質曲線になるかは未確認である。
