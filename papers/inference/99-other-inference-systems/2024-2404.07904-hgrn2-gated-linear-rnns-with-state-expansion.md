## 概要

HGRN2は、階層ゲート付き線形RNN（Hierarchically Gated Recurrent Network; HGRN）の弱点だった小さい再帰状態を、**追加パラメータなしの外積更新**で行列状態へ拡張する。Transformerは自己回帰推論で過去tokenごとのKV cacheを保持するが、線形RNNは固定サイズ状態だけを更新できるため推論memoryが系列長で増えない。一方、固定状態が小さすぎると連想記憶や言語モデリングで表現力が不足する。HGRN2はこの「固定状態の効率」と「記憶容量」の間を狙う。

元HGRNの階層忘却ゲートは維持しつつ、入力vectorを要素積でstateへ書く代わりに外積を使う。これにより状態サイズはvectorの `d` からmatrixの `d²` へ増える。多頭化すると実効state sizeは `d²/H`、拡張率はhead dimension `d/H` となり、計算costを制御できる。さらにこの再帰式はゲート付き線形注意（Gated Linear Attention; GLA）と同型なので、学習時はGLA向けchunkwise GPU kernelを再利用できる。

## 問題設定

HGRN1は入力依存の忘却ゲートに加え、下層ほど短期、上層ほど長期情報を保持しやすくする層別下限を持つ。各layerのforget gate下限を累積softmax（cumax）で単調増加させ、下層のlocal dependencyと上層のlong dependencyを役割分担する。

ただし元のstateは `h_t∈R^d` であり、全履歴をこの `d` 次元へ圧縮する。著者らはまずlow-rank、group linear transformation、Khatri-Rao product、Kronecker product等でstateを `nd` へ広げるParameter-Efficient State Expansion（PESE）を試す。10B-token Pile実験ではHGRN1 PPL 5.10に対してlow-rank n=4で4.76、n=8で4.77まで改善する。しかし `nd` 次元の要素wise recurrenceはTensor Coreのmatrix multiplyを利用しにくく、nを大きくするとFLOPとI/Oが急増する。性能は改善してもtraining efficiencyがscaleしない。

HGRN2は「projectionを巨大化する」のではなく、**state update演算そのものをmatrix形式へ変える**ことでこの問題を避ける。

## 手法

### 1. HGRN1の階層忘却を維持

入力 `x_t` からforget gate `g_t`、input vector `i_t`、output gate `o_t` を計算する。layer `l` ごとに学習する下限 `β^l` を用い、

`f_t^l = β^l + (1-β^l)⊙g_t^l`

として実際のforget gateを得る。上層ほど `β^l` が高くなるため、上層stateは急激に消えにくい。HGRN2でもこの時間scale制御はそのまま残る。

### 2. 外積によるstate expansion

HGRN1の更新はvector stateへ

`h_t = f_t⊙h_{t-1} + (1-f_t)⊙i_t`

と要素wiseに書き込む。HGRN2ではこれを

`H_t = H_{t-1}·Diag(f_t) + i_t⊗(1-f_t) ∈ R^{d×d}`

へ変える。新規入力 `i_t` とwrite strength `1-f_t` の全組合せを外積としてstate matrixへ保存し、outputは

`y_t = H_t·o_t`

というmatrix-vector積で読む。

入力・forget・output gateを生成するprojection自体は元の `d→d` のままなので、stateだけが `d²` へ拡張され、dense `d→nd` projectionの追加parameterを必要としない。これは「何を記憶するか」の容量を増やしつつ、HGRNの「どの時間scaleで残すか」という階層gateを維持する構成である。

### 3. 多頭化

単一の `d×d` stateではrecurrence costが `O(BNd)` から `O(BNd²)` へ増える。そこでdimensionを `H` headへ分割し、各headで `d_h=d/H` のmatrix stateを持つ。総state sizeは `d²/H`、計算量も `O(BNd²/H)` となる。

このとき元のvector state `d` に対する拡張率は `d_h=d/H`。WikiText-103とPile subsetのablationでは拡張率を増やすほどPPLが改善するが、head dimensionが128を越えると利得が鈍る。そこで主実験は `d_h=128` を選ぶ。つまりstateを大きくし続ければ無条件に改善するわけではなく、128付近からmemory capacity追加の限界効用が小さくなる。

### 4. GLAとの対応とGPU学習

HGRN2の再帰はGLAと同じmatrix recurrenceに書ける。HGRN2のoutput gate `o` がGLAのquery、`1-f` がkey、input `i` がvalue、forget `f` がdecayに対応する。HGRN2はGLA側の追加output gateを省き、keyをforget gateと `k=1-f` として結び付けるためparameterを節約する。

この同型性により、逐次RNN recurrenceだけで学習する必要はなく、GLA用のchunkwise algorithmと最適化kernelを直接利用できる。推論時は固定state recurrence、学習時はmatrix multiply中心のparallel/chunkwise formを選べることが、PESE方式との重要な差である。

## 評価条件

記憶容量はMulti-Query Associative Recall（MQAR）でHGRN1と比較し、拡張率64/128と複数learning rateをsweepする。言語モデリングはWikiText-103の約44M model、SlimPajamaの1.3B/2.7B modelを100B tokenで学習し、The Pileでは150M/350M/1Bを100B token、さらに0.4B〜7B級を300B tokenでLLaMA/Mamba等と比較する。長文脈はSCROLLSで評価する。

## 主要結果

MQARではsequence length・model dimensionを変えた全条件でHGRN2がHGRN1を上回る。これは外積state expansionが単なるPPL改善だけでなく、固定stateへkey-value associationを保持する能力を増やしていることを示す。

WikiText-103ではHGRN1 test PPL **24.82**に対しHGRN2は**23.73**。同条件Transformerは24.78、RWKV-4は25.07、TNNは24.67で、HGRN2はそれらを上回るがMambaの23.19には届かない。

SlimPajama 100B-tokenでは1.3B HGRN2のdownstream平均が**51.9**でTransformer++ 50.5、Mamba 49.8、GLA 50.4を上回る。2.7BではHGRN2 **55.4**、Transformer++ 53.8、Mamba 52.9、GLA 53.5。GLAとrecurrence formが同じでもparameterization差で結果が変わるという著者らの主張に対応する。

Pile 100B-tokenのHGRN1→HGRN2平均は150Mで41.27→42.15、約0.35Bで43.60→46.47、1Bで47.61→50.84と一貫して改善する。300B-token比較では3B HGRN2平均54.98、Mamba 55.31、LLaMA 53.93、7BではHGRN2 58.12、LLaMA 56.57で、一般commonsense評価では競争力がある。

ただしSCROLLS長文脈では3B HGRN2平均15.4がMamba 14.7、LLaMA 13.9を上回る一方、7BではHGRN2 **13.5**に対しLLaMA **14.6**へ逆転する。論文自身も7B HGRN2はLLaMAほど強くないとし、線形modelの長文脈scale則には未解決点があると述べる。

## 既存研究との差

Mamba、GLA、RWKV-6などもdata-dependent decayとstate expansionを使う。HGRN2の特徴は、HGRN由来の階層忘却下限を保ったまま、外積だけで非parametricにstateを広げ、GLAと同型のmatrix recurrenceへ落とす点にある。PESEのような高次元element-wise recurrenceよりTensor Core向けmatrix kernelを使いやすい。

## 限界

固定サイズstateはTransformerの増大するKV cacheを避けるが、過去tokenを明示的に保存するわけではなく情報は圧縮される。state expansionはretrievalを改善するものの、head dimension 128を越えると利得は飽和し、stateを増やすほど計算量 `O(BNd²/H)` とstate memoryも増える。

また本論文はarchitecture/quality中心で、vLLM等の実serving環境におけるTTFT、TPOT、同時request数、GPU memoryのend-to-end測定は行わない。長文脈SCROLLSでも7B時点でLLaMAに劣る負の結果があり、固定state方式がscaleすれば必ずattention modelを上回るとは示していない。
