## 概要

推論時に長い思考連鎖（chain-of-thought; CoT）を生成するreasoningモデルは、token数を増やすほど難問の精度が上がる一方、問題ごとの必要量を制御できず、簡単な問題で過剰計算したり難問で早く停止したりする。L1は、promptに目標token長または最大token長を明示し、その制約を守りながら正答するよう強化学習する。

長さ制御方策最適化（Length Controlled Policy Optimization; LCPO）は、正解報酬と長さ誤差の罰を一つの報酬へ組み込む。L1-Exactは指定長へ近づけ、L1-Maxは上限内なら短くてもよい。推論時はモデルを再学習せず、prompt中の長さ指定を変えるだけで計算予算と精度の交換条件を動かせる。

## 問題設定

長いCoTは推論時のdecode step、KVキャッシュ保持時間、計算量を直接増やす。従来のbudget forcingで上限到達時に強制打切りすると、推論途中で切れて正答率が落ちる。逆に「Wait」などを挿入して強制延長すると、不要なreasoningを増やし得る。

必要なのは、停止時に外から切るのではなく、モデル自身が最初から指定token予算へ収まるreasoningを構成することである。L1はこの性質を学習目標へ入れる。

## 手法

### LCPO-Exact

入力prompt xへ目標長 n_gold を追記し、モデル出力yの最終回答が正しいかを示す報酬と、生成長 n_y と n_gold の絶対差に比例する罰を組み合わせる。論文の報酬は `I(correct) - alpha * |n_gold - n_y|` で、alphaが正答と長さ遵守の重みを決める。

訓練では目標長を100〜4000 tokenからサンプリングするため、単一長へ過適合せず、promptで異なる予算を指定できるようにする。推論では512、1024、2048、3600 tokenなどの目標を指定する。

### LCPO-Max

最大長だけを守りたい用途では、上限超過を滑らかに罰しつつ、正答して上限内なら短いreasoningも許す報酬へ変更する。これにより簡単な問題へ指定上限いっぱいまでtokenを使わせる必要がなくなる。

L1-MaxはL1-Exactから追加強化学習し、exact指定とmaximum指定の両方を扱う。論文ではDeepScaleR-1.5B-Previewを基礎に、VeRL上のGRPOでExactを700 step、Maxをさらに120 step学習する。

## 評価条件

| 観点 | 内容 |
|---|---|
| 基礎モデル | DeepScaleR-1.5B-Preview |
| 学習 | GRPO / VeRL、Exact 700 step + Max 120 step |
| 学習context | 4K token |
| 評価context | 8K token |
| 目標長 | 512 / 1024 / 2048 / 3600 token |
| 主task | AIME 2025、MATH、AMC、Olympiad-Bench |
| OOD | GPQA、LSAT、MMLU |
| baseline | DeepScaleR、DeepSeek-R1-1.5B、S1 |

## 主要結果

512および1024 token予算では、L1はS1に対し100〜150%の相対、20〜25ポイントの絶対性能改善を報告する。同じ長さ制約でも、推論途中を外部から切るのではなく、予算内にreasoningを再構成する学習が効いている。

L1-Maxは基礎となるDeepScaleR-4Kの性能に近づきながら、条件によってL1-Exactより最大約2倍少ないtokenで解答する。soft budget violation（目標から500 token超のずれ）は0.3〜2.3%、平均1.3%である。一方、OOD taskの長さ誤差は20〜40%まで増えるため、長さ制御の一般化は完全ではない。

## 既存研究との差

S1は推論時に打切りや特殊token挿入で長さを外部制御する。LCPOは学習段階で正答と長さ制約を共同最適化し、モデル内部のreasoning自体を予算へ適応させる。単なる短文化ではなく、promptから複数の計算予算を選べる点が主眼である。

## 限界

効率改善には追加RL学習が必要で、既存reasoningモデルへ無学習で適用できない。評価は1.5Bモデル中心で、長大な24K reasoningを直接訓練できず4Kへ制限している。token数は計算量の近似であり、GPU上のwall-clock、バッチ効率、KVメモリの実測削減は主要評価ではない。
