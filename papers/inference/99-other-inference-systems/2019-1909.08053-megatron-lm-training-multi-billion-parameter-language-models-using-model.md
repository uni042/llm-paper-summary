# Megatron-LM：Transformerの層内分割で巨大言語モデルを学習する

## 概要

この論文の対象は、巨大な言語モデルの**学習時**に、モデル重み・勾配・最適化器状態が単一GPUのメモリに収まらない問題である。データ並列だけでは各GPUがモデル全体を保持するため、この容量制約を解消できない。Megatron-LMはTransformerの行列演算を層の内部で複数GPUに分割し、非線形関数の直前で不要な通信を発生させない分割方向を選ぶ。従来のモデル全体を別の言語や専用コンパイラで書き直す方法とは異なり、PyTorchの既存Transformer実装へ少数の集約通信を挿入する設計である。

論文の中心的成果は、単に重みを分割したことではなく、**二つの行列積を一組として扱い、その間の活性化をGPU間で集めずに計算する**ことにある。多層知覚器（MLP）と多頭自己注意の双方にこの配置を適用することで、通常のTransformer層に必要な集約通信は順伝播で2回、逆伝播で2回となる。語彙埋め込みも分割するが、出力側では全語彙の対数確率計算用テンソルを単純に集約せず、交差エントロピー損失と融合して通信量を抑える。

最大の学習実験は、83億パラメータのGPT-2型モデルをTesla V100 32GB×512基で学習したもの。8基で1モデルを分割し、同構成を64組に複製してデータ並列を行う。アプリケーション全体の持続計算性能は15.1 PFLOPS、強い単一GPU基準（39 TFLOPS）に対するスケーリング効率は本文の詳細評価で約74%、要旨では76%と記載される。この違いは概数・評価条件の表記差として扱い、同一条件の厳密な数値として混同しない。性能結果は**学習時の計算処理量**であり、推論トークン毎秒や生成遅延を測定した値ではない。

## 問題設定と既存方式の制約

Adamなどの最適化器は、重み本体のほかに勾配とモーメントを保存する。モデル規模が増すと重みだけでなくこれらの状態も増え、学習に必要な活性化まで含めると単一GPUの32GBを超える。活性化再計算は一時状態を削減するが、モデルの重み・最適化器状態を各GPUへ完全複製するデータ並列の基本制約は残る。

層単位のパイプライン並列では、別GPUが異なる層を受け持つ。これはモデルを分散できる一方、前段の出力を後段へ渡す依存があり、ミニバッチを小分けして流す際にパイプラインの空き時間が生じる。汎用的な分散テンソル計算方式は多様な分割を表現できるが、論文当時は新しい計算記述やコンパイル基盤を要求する例があった。

Megatron-LMは、**Transformer層の中でどの行列をどちら向きに分割すれば通信を最小化できるか**を限定的に解く。したがって全モデル構造を自動分割する汎用最適化器ではない。また、GPU間の集約通信そのものを消すわけではない。行列積を十分大きく保ち、通信が計算に対して小さくなることを狙う方式である。

## 手法

### 1. MLPの列並列→行並列：非線形関数の前で同期しない

TransformerのMLPは、入力を大きな中間次元へ射影し、GeLU非線形関数を通した後、元の隠れ次元へ射影する二つの行列積からなる。第一行列を行方向へ分割すると、各GPUの部分積を合計しなければGeLUへ渡せない。一般に `GeLU(XA1 + XA2)` と `GeLU(XA1) + GeLU(XA2)` は等しくないため、GeLUの直前に全GPUの通信が必要となる。

著者らは第一行列を**列方向に分割**し、各GPUが `GeLU(XAi)` を独立に計算できるようにする。第二行列は逆に**行方向へ分割**し、各GPUが保持している中間活性化の担当部分をそのまま入力する。第二行列の部分出力を最後に合計すれば、元のMLPと等価な出力が得られる。これにより二つの行列積の間に同期点を置かず、MLP順伝播に必要な全GPU集約（all-reduce）は最後の1回だけになる。

逆伝播でも対応する勾配の集約が必要である。論文は順伝播で恒等・逆伝播で集約を行う `f` と、順伝播で集約・逆伝播で恒等を行う `g` という共役の自動微分演算を示す。単に「通信をなくした」のではなく、**通信を非線形関数の間から行列積の外側へ移した**点が実装上の要点である。各GPUの局所計算量が小さすぎる場合には、この残存集約の比率が高くなる。

### 2. 自己注意の頭ごとの分割と出力射影

多頭自己注意では、問い合わせ（Q）・鍵（K）・値（V）を作る射影行列を列方向に分割し、各GPUへ異なる注意頭の計算を割り当てる。各頭の注意重みと値の積はそのGPUの局所情報だけで計算できるため、頭ごとの注意計算を終えるまでGPU間通信は不要である。複数頭を統合する出力射影行列を行方向に分割すると、MLPと同様に局所出力を最後に合計できる。

ここでも、前半の射影を列並列、後半の射影を行並列にすることで、途中の注意頭を全GPUに集める操作を避ける。MLPと自己注意の各ブロックが順伝播で1回ずつ集約するため、Transformer層全体では順伝播2回・逆伝播2回の集約となる。これは論文図4の基本配置に対応する。注意頭の数や隠れ次元を並列GPU数で適切に割り切れることが望ましく、任意の極小モデルを多数GPUへ分けても同じ効率になるとは限らない。

### 3. 語彙並列と損失融合

言語モデルの語彙数は数万に達する。GPT-2では語彙50,257を扱うため、出力側の隠れ状態から語彙全体のロジットを作る行列積も大きい。論文では入力・出力埋め込みの重み共有を維持したまま、語彙方向へ行列を分割する。実験では行列積を効率化するため、語彙を51,200へパディングして8GPU分割に適合させた。

単純な実装では、GPUごとに計算した部分ロジットを全GPUから集め、形状が `バッチ×系列長×語彙数` の巨大なテンソルを通信する。著者らは、分割されたロジットと交差エントロピー損失の計算を融合し、語彙次元を縮約してから通信する。したがって損失計算のために全語彙ロジットを各GPUへ複製する必要がない。論文の表現では、通信対象を語彙全体のロジットから系列位置ごとのスカラー損失へ縮小することが重要である。

入力埋め込み側では、語彙を分割して保持するため集約が必要になる。出力側だけを取り上げて「埋め込みには通信が不要」と解釈してはいけない。重み共有、語彙分割、損失融合を同時に成立させた設計が特徴である。

### 4. 集約を減らすための重複計算と局所最適化

層正規化、残差接続、ドロップアウトを一部GPUだけで実行して結果を配布すると、そのたびに通信が増える。Megatron-LMはこれらの比較的小さな演算をモデル並列グループ内のGPUで重複実行し、通信回数を抑える。分割された重みは担当GPUが局所的に最適化し、複製された小さなパラメータについては必要な一貫性を保つ設計を採る。

これは通信と演算量の交換である。重複計算を完全に排除することより、巨大な行列積を各GPUで効率よく実行し、その間に同期点を増やさないことを優先する。各GPUの担当行列が小さくなりすぎたり、集約に使う接続帯域が低かったりすると利得が下がるため、ハードウェア接続と並列度は評価の重要な前提となる。

### 5. モデル並列×データ並列の直積配置

83億パラメータモデルでは、1つのモデル並列グループを8GPUで構成し、それを64組複製する。合計は8×64=512GPUである。グループ内では層内の部分行列に関する集約を行い、グループ間では**同じ分割位置を担当するGPU同士**でデータ並列の重み勾配を集約する。すべてのGPUが同じ全モデルを持つわけではなく、8GPUが協力して1つのモデルを保持し、64組が異なるデータを処理する。

この通信構造を混同すると、モデル並列の8GPU集約とデータ並列の64GPU勾配集約を同一の通信として誤算する。実装はPyTorchからNCCLを呼び出す。論文の実験環境では同一DGX-2Hサーバ内のNVSwitch接続をモデル並列グループに活用し、サーバ間のデータ並列通信をInfiniBandで行う構成である。

### 6. 並列領域ごとの乱数系列

ドロップアウトを使う場合、分割していない残差接続の処理は各GPUで同じ入力を持つため、モデル並列グループ内で同じドロップアウトマスクを使わないと複製された状態が不一致になる。一方、注意内部のように各GPUが異なるテンソル部分を保持する領域では、全GPUが同一マスクを使うのは適切でない。

著者らは、モデル並列グループ内で共有する乱数系列と、GPUごとに別の種を与える並列領域内部の乱数系列を区別する。これは分割実行の数値的整合性と学習の確率的性質を両立するための実装上の条件であり、集約通信だけを追加しても同じ学習動作になるとは限らないことを示している。

### 7. 大規模BERTの残差・正規化順序

論文は分散化と別に、大きなBERT型モデルの学習安定性も検討する。元のBERT型構成では、モデルを大型化すると学習損失が悪化する場合があり、層正規化と残差接続の配置順序を変更することで大型モデルの学習を安定させた。図7では従来配置と変更後の学習損失を比較し、336Mモデルより大きい設定で差が明確になる。

これは通信削減そのものの効果ではなく、**モデルの構造変更による収束安定化**という別の寄与である。83億パラメータGPT-2の学習性能と、39億パラメータBERTの精度向上を、同じ一つの速度最適化の結果として合算しない。

### 並列度と性能の比較

| 条件 | 計算処理量・効率 | 比較の読み方 |
|---|---|---|
| 1.2B、モデル並列1基 | 単一V100で39 TFLOPS | 強い基準。理論ピークの約30%を既に達成 |
| 8.3B、モデル並列8基 | 理想線形比約77% | 8GPUで重みを分割した場合の弱スケーリング |
| 8.3B、モデル並列8基×データ並列64組 | 15.1 PFLOPS、本文の詳細説明で約74% | 512GPUのアプリケーション全体。要旨には76%の概数表現がある |

モデル並列のみの弱スケーリングは、モデル規模をGPU数とともに増やす評価であり、**同じ83億パラメータモデルを1GPUで動かした速度との比較ではない**。83億モデル自体が単一GPUへ収まらないことがこの研究の前提である。したがって効率77%は、GPUを8倍にすれば同一問題を約6.16倍速く解けるという強スケーリングの測定値ではない。

512GPUの測定はモデル並列とデータ並列を組み合わせたときの勾配集約通信を含む。本文の図5と説明では8GPUモデル並列の約77%から512GPU混成並列の約74%へ効率が低下する。要旨の76%という数値と完全一致しないため、評価条件と本文値を併記し、どちらかへ恣意的に統一しない。

### 感度、内部指標、学習時間

弱スケーリングは1.2B→2.5B→4.2B→8.3Bとモデルを大きくする系列で示される。論文表1では注意頭あたり隠れ次元を96に固定し、隠れ次元1536/1920/2304/3072、層数40/54/64/72を用いる。これは行列積の形状を大きく変えずに並列化の効果を観測するための条件であり、任意の注意頭数やGPU分割数でも同じ効率になる証拠ではない。

GPT-2型品質評価の表2では、83億モデルの1エポック相当68,507反復に約2.10日を要する。2.5Bモデルは約2.27日、355Mモデルは約0.86日であり、GPU数・モデル規模・実験設定が異なる。これらを同一モデルの学習時間短縮率として計算するのは誤りである。83億モデルの学習は全体30万反復を設定しており、論文の学習費用は大規模GPU設備を前提にする。

構成要素除去実験として、本文はBERT型で層正規化・残差の配置を変えた場合の損失曲線を提示する。従来構成は大型化した際に不安定化し、変更構成は低い学習損失を維持する。ただし「MLP分割のみ」「注意分割のみ」「語彙損失融合なし」を全組合せで比較した包括的な通信アブレーション表は、この論文の主評価として提示されていない。したがって各工夫の速度寄与を独立した倍率で作らない。

## 既存研究との差

GPipeは層間のパイプライン化によってモデルを分割する。Megatron-LMは層内部の行列積を分割するため、異なる軸の並列化であり、論文は両者を補完的と位置付ける。層内方式ではモデル並列グループ内で毎層集約が必要だが、パイプラインの小分け処理による空き時間とは異なる費用を持つ。巨大モデルでは両方を組み合わせる余地がある。

Mesh-TensorFlowは分散テンソル計算の記述とコンパイルを一般化する。Megatron-LMはそのような汎用コンパイラを設計せず、TransformerのMLP・注意頭・語彙という固定構造に合わせて分割を手で決め、PyTorchとNCCLの集約通信で実装する。これは実装の単純さと、対象構造の限定性との交換である。

BERT大型化に伴う精度悪化への対応としては、ALBERTがパラメータ共有を採るのに対し、本論文は層正規化と残差の順序変更を評価する。分散化の主張と、学習安定化の構造変更は別々に理解する必要がある。

## 限界と再現上の注意

**GPU接続への依存。** 実験はDGX-2H内の高速NVSwitchとサーバ間InfiniBandを前提とする。層内の全GPU集約は各Transformer層で発生するため、PCIeのみの接続や小さな行列では通信が計算を圧迫し得る。512GPUの効率を一般的なネットワークへ外挿できない。

**弱スケーリングの解釈。** 77%や74%はモデルサイズをGPU数とともに増やした比較である。同じモデルをGPU数だけ増やす強スケーリング、学習完了までの総コスト、1GPU推論速度の改善率ではない。15.1 PFLOPSは持続演算性能であり、理論ピークや推論性能を意味しない。

**モデル形状と並列度。** 注意頭と中間次元の分割可能性が重要である。GPU数を増やして各GPUの担当行列が小さくなると行列積効率が低下し、通信の固定費が支配的になり得る。本文は最大8GPUの層内モデル並列を主要な検証範囲とする。

**学習品質の帰属。** WikiText103、LAMBADA、RACEの結果は、モデル大型化、学習データ、正規化配置などを含むモデル全体の成果である。並列化単独で品質が上がったと断定できない。RACEの90.9%はアンサンブルであり単体の値ではない。

**適用範囲。** 対象はTransformerの学習で、2026年のMoE分散推論や推論時KVキャッシュ移送を直接扱う論文ではない。著者らは16B超モデルでは単一DGX-2H内に収めるのが難しくなり、層内と層間のハイブリッド並列やノード間モデル並列が必要になると述べる。論文当時の規模とハードウェアで成立した設計を、現在のあらゆるLLMへ無条件に一般化しない。

**再現性。** 公式実装は公開されているが、論文の数値は2019〜2020年当時のコード・V100構成に基づく。現行のMegatron-LMリポジトリが同一コード版であるとは限らない。再現時は論文版・GPU世代・通信トポロジー・混合精度・データ前処理を固定する必要がある。
