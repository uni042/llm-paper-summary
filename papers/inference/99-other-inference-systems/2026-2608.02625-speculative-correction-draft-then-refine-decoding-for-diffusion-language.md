# Speculative Correction：拡散言語モデルで全回答を先に下書きし、双方向に推敲する復号方式

## 概要

Speculative Correctionは、拡散言語モデル（Diffusion Language Model、DLM）が持つ双方向の修正能力を、実際の文章生成へ生かすための二段階復号方式である。現在のブロック自己回帰型の拡散復号では、文章を短いブロックへ分割し、各ブロック内では並列にノイズを除去するが、確定した前のブロックを後から修正しにくい。これは生成途中の全体構造が間違っていても、後続の推論がその間違いを前提に進むという制約を生む。

著者らは、まず文章全体を短い計算予算で下書き（draft）し、その後に下書きの全範囲を編集可能な状態へ戻して双方向に推敲（refine）する方式を提案する。同じLLaDA2.1-flashモデルを両段階に使うflash–flashと、小型LLaDA2.1-miniで下書きし大型flashで推敲するmini–flashの二構成を評価する。flash–flashではGSM8Kの正答率を0.848から0.899へ改善し、同じ問題集合のモデル実行時間を18.77秒から15.96秒へ短縮した。mini–flashではMATH-384でflash単独0.300に対して0.294という近い観測精度を保ちながら、平均モデル時間を40.90秒から18.82秒へ短縮し、2.17倍の速度比を報告する。

ただし、これらは選択された構成と評価集合での結果であり、全タスクで品質・速度が同時に改善するわけではない。MBPPのflash–flashは正答率が上がる一方で単独flashより遅くなる条件があり、mini–flashのMATH-512はflash単独より有意に精度が低い。著者らは、同一モデルでの全体推敲の効果と、異種モデルで品質・速度の交換条件を作る効果を明確に分けている。

## 問題設定：ブロック単位の確定が双方向修正を妨げる

自己回帰言語モデルでは、トークン列の次位置を順に確定する。拡散言語モデルは複数位置を同時に更新できるが、長い回答を一度に全マスクから生成することは学習分布と計算費用の面で難しいため、実際の生成器ではブロック自己回帰（block-autoregressive）方式が採用される。ブロック内部では並列修正できても、前のブロックを固定すると、回答全体にわたる整合性を後から回復する機会が失われる。

例えば数学問題で途中の推論手順を誤ったまま後半へ進む場合、最後の答えだけを修正しても論理が合わない。コード生成では先に決めた関数構造や変数の使い方を、後から全体として変更した方が正しい場合がある。著者らの仮説は、まず完成形に近い下書きを生成すれば、全体の長さ・構造・依存関係が推敲段階へ渡り、局所ブロックを独立に確定するよりも有利になるというものである。

本研究の対象は、下書きのトークンを検証して採択する通常の投機的復号（speculative decoding）とは異なる。通常の投機的復号では目標モデルの出力分布を保つための受理・補正規則を使うことが多いが、本方式は生成済みの下書きそのものを拡散モデルの編集過程で書き換える。出力分布の厳密な保存ではなく、最終タスクの品質とモデル実行時間の改善を狙う。

## 手法

### 1：全回答の下書きを先に完成させる

第一段階では、通常のブロック自己回帰型の拡散復号を使って、最大384または512トークンの回答全体を下書きする。各ブロックのノイズ除去回数、ブロック長、確信度閾値などを調整し、推敲段階へ渡せる構造を少ない計算で生成する。下書きは最終出力ではなく、後段が編集するための初期状態である。

同一モデル構成flash–flashでは、LLaDA2.1-flashが下書きと推敲の両方を担当する。異種モデル構成mini–flashでは、LLaDA2.1-miniが安価に下書きを作り、より強いLLaDA2.1-flashが全体を推敲する。両者は同じ下書き・推敲という処理順を持つが、前者は全体修正そのものの有効性を調べ、後者は小型モデルの高速性を使って品質・速度の中間点を探すことが目的である。

下書きの長さと構造は重要な制約になる。後段の編集機構は、初期の下書きが表現した系列長の中で修正するため、必要な解答が下書き段階で極端に短く切り詰められた場合、単に推敲回数を増やしても完全な構造を回復できるとは限らない。著者らは、下書きモデルを将来学習する場合には、素の次トークン精度だけでなく、長さ予測や構造の保持、修正可能な不確実性の表現を最適化すべきだと論じる。

### 2：全体を編集できる拡散推敲

第二段階では、下書き全体を初期状態として、LLaDA2.1のトークン編集型の拡散過程で再評価する。ブロックごとに過去を固定するのではなく、回答の先頭から末尾までを編集可能な範囲として扱うため、後半の情報に応じて前半のトークンを変更できる。これが「全体的な双方向推敲」であり、下書きの一部だけを局所的にノイズ除去する方式との差である。

推敲はゼロから全マスク系列を生成する処理ではない。下書きがすでに長さ、単語列、構造的な手がかりを提供しているため、同じ推敲計算予算でも初期状態なしより品質が高くなる可能性がある。原著は下書きだけ、推敲だけ、64トークンの局所推敲、全範囲の推敲を別々に評価し、単に追加の拡散ステップを使っただけでは説明できない効果を調べる。

下書きの生成と推敲の双方に計算費用がかかるため、全体推敲を無制限に増やせば速くなるわけではない。下書きの計算予算と推敲の計算予算を配分し、ブロック自己回帰の基準方式と同じか近い遅延範囲で比較する必要がある。原著は探索的な構成走査の後に代表的な設定を固定し、より大きな問題集合で再評価している。

### 3：同一モデル効果と異種モデル効果を分離する

同一モデルのflash–flashでは、下書きモデルと推敲モデルの性能差という交絡要因がない。従って、単独flashと比べた品質改善は、全体下書きと全体推敲という復号の順序に由来する可能性が高い。一方、mini–flashでは小型モデルの下書きの誤りと、flashの修正能力の両方が結果を左右するため、単に「小型モデルで先読みしたから速い」と解釈できない。

著者らはmini単独、flash単独、mini–flashの三方式を比較し、小型モデルから大型モデルへの品質差の何割を回復したかを指標にする。品質差回復率は(score_mini–flash−score_mini)/(score_flash−score_mini)で定義する。分母が小さい場合やmini–flashがflashを上回る場合には、回復率が100%を超えることもある。これはモデルの絶対精度が100%を超えるという意味ではない。

また、mini–flashは小型モデルの下書きと大型モデルの推敲を組み合わせるため、モデルを二つ保持する費用や、モデル切替え時のメモリ管理を考慮する必要がある。原著の速度指標は主に同一評価ループ内のモデル実行秒数であり、実サービスの多数要求、モデル切替え、キャッシュ共有、外部通信を全て含んだスループット測定ではない。

## 評価

### 実験設計と統計的な比較

| 項目 | 原著の設定 |
|---|---|
| モデル | LLaDA2.1-mini、LLaDA2.1-flash |
| 主な方式 | flash単独のブロック自己回帰、flash–flash、mini単独、mini–flash |
| 最大生成長 | 384または512トークン、入力プロンプトを除く |
| 評価 | GSM8K、MATH-500、MBPP、HumanEval、合成算術2系列 |
| 品質指標 | 数学は最終解答正答率、コードはテスト実行のpass@1 |
| 時間指標 | 1問題あたり平均モデル実行秒数、下書き＋推敲の合計 |
| 信頼区間 | 問題ID単位で繰り返し生成を平均し、対応付きブートストラップで95%区間 |
| 比較調整 | 単独flashもブロック長、ステップ数、閾値、最大長を走査し、遅延±15%の比較方式を用意 |

固定構成の実験ではGSM8Kの384トークン設定に1115固有ID、512設定に793固有IDがあり、比較表の一部では同じ問題IDを抽出した500件で再比較する。MATHは500件、MBPPは257件、HumanEvalは164件、合成算術は各1000件を使う。無効な生成、構文エラー、時間切れなどは不正解として扱い、都合の悪い例を除外しない。

著者らは探索的な構成走査を実施した後、代表的な設定を固定して大規模評価を行う。95%信頼区間は固定した設定の問題集合上での不確実性を表し、探索空間全体から最良設定を選んだことによる選択バイアスを完全に補正したものではない。論文自身がこの制約を認め、単独flashにも遅延窓を合わせた設定選択を実施して、基準方式の調整不足だけで改善を説明できないかを検証する。

### 結果1：同一モデルの全体推敲は数学・コードで品質を改善

| 条件 | 単独flashの品質・秒 | flash–flashの品質・秒 | 解釈 |
|---|---|---|---|
| GSM8K-384、固定設定 | 0.848 / 18.77秒 | **0.899 / 15.96秒** | 品質と時間の双方が改善 |
| GSM8K-512、固定設定 | 0.850 / 19.46秒前後 | **0.907 / 15.8秒前後** | 品質改善と速度改善 |
| MBPP-384、固定設定 | 0.545 / 7.14秒 | **0.693 / 8.01秒** | 品質は改善するが時間は悪化 |
| HumanEval-384、固定設定 | 0.415 / 約7.9秒 | **0.622 / 約9秒** | 品質は上昇、速度は比較基準次第 |

原著の遅延窓を合わせた比較表では、GSM8K-384の最終比較基準0.832/19.08秒に対しflash–flashは0.900/15.61秒、差+0.068、95%区間[+0.032,+0.104]、速度比1.22倍となる。GSM8K-512でも差+0.072、速度比1.23倍である。固定設定の0.848→0.899と遅延窓比較の0.832→0.900は、問題集合と比較手順が異なるため、同じ数値の行として混ぜない。

MBPP-384の遅延窓比較では0.545→0.693と品質が大きく改善するが、時間比は0.90倍であり、むしろ遅い。HumanEvalでは、調整された単独flashの比較品質が0.561となり、flash–flashの0.622との差+0.061に対する95%区間は[-0.030,+0.159]でゼロを含む。HumanEvalの品質向上を、統計的に確証された一律の改善として扱わない。

### 結果2：全体推敲が本当に必要かを除去実験で検証

GSM8K-384の同じ問題集合における除去実験では、下書きだけの品質0.677、下書きなしでマスクだけを推敲する方式0.004、64トークン局所推敲0.872、全体推敲0.899となる。全体推敲は局所推敲を+0.027上回り、対応付き95%区間[+0.015,+0.039]はゼロを含まない。これは下書きが有用な初期状態を提供し、全体の修正が局所修正よりも追加価値を持つという主張を支持する。

MBPP-384では下書きのみ0.510、局所推敲0.681、全体推敲0.693であり、局所との差+0.012の区間[-0.012,+0.035]はゼロを含む。従って、コード生成では下書きと推敲の組合せ自体は有効でも、全範囲を編集することが64トークンの局所推敲より確実に優れるとは言えない。

MATH-384のmini–flashでは下書きだけ0.272、局所推敲0.296、全体推敲0.294となり、全体が局所より高精度ではない。単独flashの0.300に対しても統計的に同等であると証明したわけではない。著者らは、タスクによって全体推敲の因果的な寄与が異なることを負の結果として報告する。

### 結果3：小型下書き＋大型推敲は速度と品質の中間点を作る

| 条件 | mini単独 | flash単独 | mini–flash | flash比速度 |
|---|---:|---:|---:|---:|
| MATH-384 | 0.272 | 0.300 | **0.294** | **2.17倍** |
| MATH-512 | 0.314 | 0.392 | 0.336 | 1.92倍 |
| MBPP-384 | 0.401 | 0.545 | **0.568** | 1.11倍 |
| MBPP-512 | 0.401 | 0.549 | 0.564 | 0.97倍 |
| 合成算術expanded-384 | 0.661 | 0.850 | 0.740 | 1.89倍 |
| 合成算術varied-384 | 0.664 | 0.797 | 0.769 | 1.49倍 |

MATH-384ではflash単独とmini–flashの差が-0.006で、対応付き95%区間[-0.046,+0.032]はゼロを含む。観測上は非常に近い品質だが、同等性検定で同等と証明した結果ではない。一方MATH-512では差-0.056、区間[-0.096,-0.016]と明確な品質低下があり、速度1.92倍との交換条件になっている。

MBPP-384ではmini–flashがflash単独を観測上0.023上回るが、区間[-0.054,+0.101]はゼロを含む。MBPP-512では品質が上回っても速度は0.97倍となり、flashより遅い。合成算術expandedではminiより改善してもflashより0.110低く、品質差が残る。これらをまとめると、mini–flashは全タスクでflashを置き換える方式ではなく、用途別に選ぶ品質・速度のパレート前線の候補である。

### 推敲が誤答を直す場合と壊す場合

原著は単純な正答率差だけでなく、対応する生成のどれが誤答から正答へ変わり、どれが正答から誤答へ変わったかを調べる。GSM8K-384のflash–flashと単独flashの除去実験では、全体推敲が局所推敲より正答へ修正した例37件に対し、正答を誤答へ変えた例7件である。これに対して、MATH-384のmini–flashは全体推敲が単独flashに対して改善した例と悪化させた例が拮抗する。

この違いは、推敲を行えば必ず誤りが減るわけではないことを意味する。全体推敲は先行トークンも変更できるため、正しい推論経路を壊す可能性も持つ。特に異種モデルの下書きは、大型モデルが自然に生成する初期状態と分布が異なり、推敲がその違いを十分に吸収できない場合がある。

## 先行研究との差と運用上の含意

EAGLEやMedusaのような通常の投機的復号は、主に自己回帰型目標モデルの検証処理を減らすことを狙う。DFlashなどの拡散を使う投機的生成でも、目標モデルの候補受理と生成速度が中心になる。本研究は、拡散モデルが本来持つ全体の編集可能性を利用して、すでに作った文章を後から修正する点で異なる。

LLaDA2.1はトークン編集型の公開インターフェースを持つため、全回答の双方向推敲を実験できる。SDARやFast-dLLM v2の公開デコーダは、ブロック内での双方向処理を中心とするため、同じ全回答編集をそのまま実装するにはサンプラーの変更が必要と著者らは説明する。従って、どの拡散言語モデルでも本方式を無改造で利用できるという意味ではない。

実用上は、全回答を下書きしてから推敲するため、ストリーミング出力の利用者体験と相性が悪い可能性がある。回答の途中をユーザーへ逐次確定表示した後で前半を書き換えるには、表示の撤回や編集を許容するインターフェースが必要になる。原著のモデル実行秒数は、このような利用者インターフェースの費用やサービス側の同時処理量を評価したものではない。

## 限界・未評価事項

第一に、主実験はLLaDA2.1系列のminiとflashに限定される。完全な全回答編集ができない拡散モデルや、別の学習方式のモデルへ結果を一般化できない。著者ら自身も、複数サイズの完全編集可能な拡散モデル群への拡張を今後の課題としている。

第二に、下書きと推敲は独立に訓練された既存モデルを組み合わせる。下書きモデルは推敲されやすい構造を生成するよう訓練されておらず、推敲モデルも異種モデルの下書きを初期状態として使うよう特別に学習していない。この不一致がmini–flashの品質低下に関係する可能性はあるが、原因を切り分けた決定的な実験ではない。

第三に、品質と時間の改善はタスクごとに異なる。MBPPの同一モデル方式では品質が改善しても時間は悪化し、MATH-512の異種モデル方式では速度が改善しても精度が低下する。GSM8Kの改善率だけを全タスクの性能値として転用できない。

第四に、モデル時間は同じ評価環境での下書き＋推敲呼び出しの合計である。GPUメモリに二つのモデルを同時配置する費用、切替え、長い対話のKVキャッシュ、複数要求の待ち行列、実サービスでの応答時間は別途検証が必要である。

第五に、探索した復号設定の中から代表点を選んで評価している。対応付きブートストラップ区間は選択された設定の統計的不確実性を表すが、探索による選択バイアスを完全には補正していない。HumanEvalやMBPPの区間がゼロを含む結果は、品質改善の確実性を過大に評価しないために重要である。
