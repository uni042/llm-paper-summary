# Hungry Hungry Hippos: Towards Language Modeling with State Space Models

## 概要
H3（Hungry Hungry Hippo）は、状態空間モデル（state space model; SSM）が長系列をほぼ線形時間で扱える一方、言語モデリングでは注意機構（attention）に劣る理由を合成taskで分解し、「過去tokenの想起」と「系列中のtoken同士の比較」が不足していると突き止めた上で、その二能力を明示的に実装するSSM layerである。入力をQ/K/Vに投影し、shift SSMとdiagonal SSMを乗算的に接続することで、attentionに似たkey-value記憶・検索を線形時不変系の計算へ落とす。

さらにFlashConvは、SSM trainingで必要なFFT convolutionをGPUのmemory hierarchyへ合わせて再設計する。8K程度まではfused block FFTをSRAM内で処理し、それ以上はSSMのrecurrent stateをchunk間で渡すstate-passingを用いる。H3単体はOpenWebTextでTransformerに0.4 perplexityまで近づき、attentionを2層だけ残した125M hybridはTransformerを1.0 perplexity上回る。FlashConvによりLRAのS4 trainingは従来S4の約2倍、Transformerの5.8倍、1.3B hybridの生成はTransformer比最大2.4倍となる。

## 問題設定
S4系SSMはsequence lengthに対してほぼ線形にscaleし、長距離signal processingでは強い。しかしlanguage modelingではTransformerより複数perplexity悪いことがあり、「SSMの表現力が本質的に足りないのか」「architectureよりhardware/kernel成熟度の差なのか」が不明だった。

著者らはsynthetic languageを使い、attentionが得意な二機構を切り分ける。第一は特定event後に現れたtokenを後で呼び戻すrecall、第二は離れた二位置のtokenを比較して条件分岐する能力である。既存SSMは長い履歴を状態へ圧縮できても、入力依存のkeyに基づく選択的read/writeを表現しにくく、これらtaskでattentionに負ける。

system側でも、理論上 `O(N log N)` のFFT convolutionが必ず速いわけではない。cuFFTではFFT→pointwise multiply→inverse FFTの各段階で中間tensorをHBMへ書き戻し、Tensor Coreのmatrix multiply throughputも十分使えないため、短〜中sequenceではquadratic attentionより遅いことさえある。

## 手法
### 1. H3 layer
入力 `u∈R^{N×d}` を3本の線形projectionでQ/K/Vへ写す。Kをまずshift SSMへ通す。shift SSMは状態を1 stepずつずらすようなA行列を持ち、直前・局所tokenの情報を明示的に保持する。この出力とVを要素積し、「どのkeyのときにどのvalueを記録するか」に相当するmultiplicative interactionを作る。

次にその積をdiagonal SSMへ通す。diagonal SSMは長い系列へ情報を累積・伝播しやすく、過去に書き込まれたkey-value情報を長距離へ保持する。最後にその出力とQを要素積し、現在queryに応じて必要なvalueだけを読み出す。attentionのsoftmax score matrixを明示的に作らず、二つのSSMとgateでassociative recallに必要なstore→propagate→recall構造を近似する。

合成associative-recall構成では、shift SSMが「keyの次に来たvalue」を1 stepずらして揃え、diagonal SSMが過去のkey-value pairを蓄積し、queryとのmultiplicative gateが一致するpairを選ぶ。これが既存linear SSMとの差である。

### 2. hybrid H3-attention
pure H3はsynthetic taskではattentionに追いつくが、自然言語の全依存を完全には代替しない。そこで大半のlayerをH3にしつつ、2層だけstandard attentionを残すhybridを作る。125Mだけでなく355M、1.3B、2.7Bまで同じ方向でscaleさせ、H3のrecurrent/linear-time性とattentionの柔軟なcontent-based routingを併用する。

### 3. FlashConv: fused block FFT
SSMをtraining時にparallel計算すると、filterとのlong convolutionとしてFFTを使う。FlashConvはFFTを小さいblock matrix multiplyへ分解し、FFT、周波数domainのpointwise multiply、inverse FFTを可能な限り一つのfused kernel内で進める。中間結果をHBMへ何度も出さずSRAMに保持し、Tensor Core向けmatrix multiplyへ変換することで算術強度（arithmetic intensity）を上げる。

A100ではこの方式がSRAMへ収まる目安がsequence length 8K付近で、そこまではblock FFTを直接使う。

### 4. state passing
8Kを超えるとsequence全体を一つのfused FFT workspaceへ置けない。SSMにはrecurrent form
`x_t=A x_{t-1}+B u_t`
があるため、sequenceをSRAMへ収まるchunkへ分け、各chunkのconvolutionをFlashConvで計算しながら、chunk終端stateだけを次chunkへ渡す。

これによりlong sequence全体の巨大FFTをmaterializeせず、chunk内部では高効率block FFT、chunk間では小さいstate transferでつなぐ。sequence lengthを増やしてもnear-linear wall-clock scalingを保つ狙いである。

## 評価条件
表現力分析ではsynthetic language taskとしてrecall/comparison系taskを用い、attention、S4D、gated SSM等と比較する。自然言語では125M規模をOpenWebTextで比較し、その後125M/355M/1.3B/2.7B hybridをThe PileでGPT-3系hyperparameterを用いて学習する。zero/few-shot評価はSuperGLUE系task。

system評価ではA100を中心に、sequence 256〜32KでH3/FFTConv forward+backward、Long Range Arena（LRA）のend-to-end training、1.3B language model generation throughputを比較する。LRAではTransformer、FlashAttention、block-sparse FlashAttention、S4、S4+FlashConvを比較する。

## 主要結果
### 表現力
synthetic recall/comparisonでは既存SSMが大きく崩れるのに対し、H3はattentionにほぼ一致する。自然言語でもpure H3はOpenWebTextでTransformerとの差を約0.4 perplexityまで縮め、既存SSMとの差約3.4 PPLを大きく改善する。

125M hybrid H3-attentionはattentionを2層だけ残すことでTransformerより約1.0 perplexity良い。これは「H3だけですべてのattentionを置換する」のではなく、少数attentionがH3の弱いcontent routingを補う方が品質上有利という負ではないが重要な結果である。

The Pile上の125M〜2.7B hybridも同parameter規模Transformerより低perplexityを示し、SuperGLUEのzero/few-shotでも過半数taskでmatchまたは上回る。したがって125M固有の現象ではなく、少なくとも2.7Bまでscaleした。

### FlashConvと長系列training
LRA end-to-end speedではTransformerを1倍とするとFlashAttention 2.4倍、block-sparse FlashAttention 2.8倍、S4 2.9倍、S4+FlashConv 5.8倍。つまりmodel architectureをS4へ変えた利得だけでなく、FlashConvがS4自体をさらに約2倍にする。

kernel比較では短sequenceでkernel fusionだけでもcuFFTより速く、長くなるほどblock FFT/state passingの効果が大きい。H3 trainingはlong sequenceでattentionより4〜8倍速い範囲を示す。

### 生成
SSM部分はrecurrent stateだけで次tokenへ進めるため、生成時に全historyへattentionする必要がない。1.3B hybrid modelではTransformer比で最大2.4倍のgeneration throughputを報告する。ただしhybridにはattention層が2枚残るため、pure recurrent SSMの理論的定数memory decodeにはならず、そのattention層のKV/cache costは残る。

## 既存研究との差
S4は長距離memoryと効率的convolutionを確立したが、input-dependentなassociative recallの弱さを直接解いていない。H3はattentionを「sequence-wide comparison」と「key-value recall」というprimitiveへ分解し、multiplicative gate + shift/diagonal SSMでその部分を実装する。

FlashConvも単なる新しいSSMではなく、同じSSM convolutionをGPU上で速くするsystem algorithmである。FlashAttentionがattentionのI/O patternをSRAM-awareに再設計したのと同じ発想をFFT/SSMへ適用する。

## 限界
H3は後のselective SSMのようにA/B/Cをtoken内容に応じて動的変更する構造ではなく、content-dependent selectionはmultiplicative projectionで補っている。pure H3が常にTransformerを上回るわけではなく、自然言語の最良構成は2 attention layersを残したhybridである。

FlashConvの絶対速度はGPU SRAM容量、Tensor Core、sequence shapeに依存する。8Kというchunk境界もarchitecture固有で、他GPUでは変わる。LRAの5.8倍はend-to-end training条件、2.4倍は1.3B hybrid generation条件であり、すべてのbatch/contextで同倍率ではない。

最大modelは2.7Bで、現在の数十〜数百B LLM規模、serving concurrency、KV offload、Mixture-of-Experts等は評価していない。したがって本論文の価値は「SSMで言語能力のgapをどう埋めるか」と「FFT型SSMをhardware-efficientにする基礎」を示した点にある。
