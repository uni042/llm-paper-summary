# Unlimiformer: Long-Range Transformers with Unlimited Length Input

> 交差注意の全encoderキーをk近傍探索索引へ退避し、各decoderヘッドが上位kだけ取得することで既存encoder-decoderモデルを500kトークン入力まで拡張する。

## 概要
encoder-decoder Transformerの交差注意は、デコーダが全入力キーを参照するため入力長が伸びるとメモリと計算が増える。Unlimiformerはencoder出力をk近傍探索（k-nearest-neighbor; kNN）索引へ格納し、各デコーダ層・注意ヘッドが現在のクエリに近い上位kキーだけを取得して交差注意する。索引はGPUまたはCPUメモリに置け、既存モデルへ追加学習重みを入れず、BookSumで500kトークン入力を切り捨てず処理した。

## 問題設定
長文書要約では入力全体をencoderへ通せても、デコード中に全encoder状態へ毎回交差注意すると系列長に比例した大きな計算・メモリが必要になる。入力を固定窓で切ると遠方の重要情報を失う。必要なのは、全入力を保持しつつ各クエリで参照する候補を絞る仕組みである。

## 手法
入力はチャンク化して既存encoderへ通し、得られたキー・値表現を単一のkNN索引へ登録する。デコード時には各層・各ヘッドのクエリを使って索引を検索し、内積が大きい上位kキーを取得する。kNN距離をそのまま注意の内積スコアとして使えるため、検索結果へ通常の交差注意を適用できる。

索引をCPUメモリへ置けばGPU容量を超える入力も保持できる。検索は全キー走査より小さい計算で候補を返す一方、CPU配置ではGPUとの転送と検索遅延が追加される。上位kへ絞るため、検索で必要キーを落とすと品質へ影響する。

## 評価条件・主要結果
長文書・書籍要約ベンチマークでBARTやLongformer等へ適用し、モデル本体のコード変更や追加学習重みなしに入力長を拡張する。BookSumでは500kトークン入力をテスト時に切り捨てず処理可能と報告する。

| 観点 | 結果 |
|---|---|
| 最大例 | BookSumで500kトークン入力 |
| 参照方式 | 各層・各ヘッドでtop-kキー検索 |
| 索引配置 | GPUまたはCPU |
| モデル変更 | 追加学習重みなし |
| 対象 | encoder-decoder Transformerの交差注意 |

## 既存研究との差
固定長の長文脈モデルへ再学習するのではなく、既存encoder-decoderモデルの交差注意だけを外部索引で置換する。情報を入力時に切り捨てず、クエリ時に検索して参照集合を選ぶ点が特徴である。

## 限界
自己回帰decoder-only LLMのKVキャッシュを直接解く方式ではない。CPU索引では検索・転送が遅延要因になり、top-k検索の再現率が低いと必要情報を失う。500kトークン処理可能という結果は要約タスクとencoder-decoder構成での評価である。
