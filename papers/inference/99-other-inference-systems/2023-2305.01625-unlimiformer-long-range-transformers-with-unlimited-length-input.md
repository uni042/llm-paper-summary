# Unlimiformer: Long-Range Transformers with Unlimited Length Input

## 概要

従来の符号器・復号器型Transformerでは、入力文書を符号器へ通し、復号器の各層が符号器出力の全位置に交差注意する。文書が長いほど参照すべきキーと値の数が増え、推論時のメモリ使用量と注意計算が膨らむ。長文専用の注意構造へモデルを変更する方式は再事前学習や追加の位置埋め込み学習を要する場合がある。Unlimiformerは、既存の学習済みモデルを変更せず、入力全体から現在の復号に重要な位置だけを検索して交差注意する方法を提案する。

本方式では、入力を重複する短いチャンクへ分割して既存符号器で処理し、得られた全位置の隠れ状態を近傍探索（k-nearest-neighbor; kNN）索引へ保存する。復号器の各層・各注意ヘッドは現在のクエリに対応する上位kの入力位置を索引から検索し、検索した位置のキーと値に対して通常の交差注意を計算する。全入力へ毎回注意するのではなく、復号に必要な少数の位置へ動的に注意を割り当てるため、固定窓を超える入力も扱える。

中心となる工夫は**層・ヘッドごとに索引を作らない**ことである。通常の注意キーを事前に索引化すると、各層・各ヘッド固有の射影行列のため大量の索引が必要になる。著者らは内積の行列積順序を変え、キー側の射影をクエリ側へ移す。これにより符号器の最終隠れ状態だけを単一索引へ置けばよく、各ヘッドは自分の射影行列で変換したクエリを同じ索引へ送る。索引をCPUメモリへ退避できるため、GPUメモリを全入力の交差注意状態で占有せずに済む。

長文書要約のGovReport、テレビ番組台本要約のSummScreen、書籍要約のBookSumで評価し、BARTやPRIMERAなどの既存モデルへ推論時だけ適用しても改善を報告する。BookSumでは50万トークンを超える文書をテスト時に切り捨てずに扱い、単純な要約スコアだけでなく、参照要約中の固有表現をどれだけ回収したかを示す指標でも利点を確認する。したがって、主な貢献は「巨大な注意窓を持つ新モデルの学習」ではなく、既存モデルの符号器出力を外部索引で再利用して長入力を処理する推論機構である。

## 問題設定

BARTの典型的な入力上限は1,024トークン、Longformer系でも4,096〜16,384トークン程度の設定が一般的だった。一方、BookSumの書籍本文は平均14万トークンを超え、最長では50万トークンを超える。先頭の1,024トークンだけで要約を作ると、後半に登場する人物、出来事、結末などを入力として参照できない。符号器をチャンクごとに実行しても、その出力をすべて復号器の交差注意へ渡すと、復号ステップごとに全入力長へ比例した計算とメモリを消費する。

長文入力を短いチャンクへ分け、復号器に全チャンクを一度に注意させる方法もある。しかしそれでは交差注意の対象が全チャンクにわたり増え続け、GPUメモリ容量が入力長の上限になる。固定位置の抜粋や単純な先頭切り捨ては、必要な情報がどこにあるかを復号クエリごとに判断できない。Unlimiformerは、現在生成している語や文に関係する入力位置を、復号器の各層・各ヘッドの注意クエリから選び直す。

別の問題は、外部記憶を注意へ接続する際の索引数である。各復号器層の各注意ヘッドは異なるキー射影を持つため、キーと値を射影後に索引化すると層数L、ヘッド数Hに対して概ね2LH個の索引を保持する必要がある。入力が数十万トークンならこの重複は大きく、記憶の構築と検索の費用も増える。索引数を増やさず、元の注意内積と同じ順序を保持して検索できることが必要となる。

## 手法

### 重複チャンクによる長入力の符号化

最初に長文を、基底モデルの符号器が扱える長さの重複チャンクへ分ける。各チャンクを既存の符号器へ通し、出力された隠れ状態のうち中央半分だけを採用する。中央を使う理由は、各トークンの符号化時に左右の文脈を十分含めるためである。チャンク境界付近の出力をそのまま使うと、片側文脈が欠けた状態が索引に登録され、境界の位置だけ不利になる。

各チャンクから採用した隠れ状態を入力順にまとめ、Faissなどの近傍探索索引へ登録する。索引に登録するのは、特定の注意ヘッド用に射影したキーや値ではなく、符号器の最終隠れ状態そのものである。類似度には内積を用いる。したがって入力位置が100万個あっても、索引の論理的な項目は入力位置当たり隠れベクトル1本で済む。

符号器のチャンク処理は入力全体を読む必要があるため、入力長と無関係な計算になるわけではない。節約するのは、復号器が生成トークンごとに全入力位置を参照する交差注意の負担である。また全チャンクの符号化と索引構築は入力に対して先に実行するため、初回生成までの待ち時間にはその費用が含まれる。

### 全ヘッド共通の索引を成立させる代数変形

復号器隠れ状態を `h_d`、符号器隠れ状態を `h_e`、クエリとキーの射影行列をそれぞれ `W_q`、`W_k` とすると、通常の交差注意の内積は `QK^T = (h_d W_q)(h_e W_k)^T` である。これを行列積の結合則により `QK^T = (h_d W_q W_k^T) h_e^T` と書き換える。すなわち検索クエリを `q' = h_d W_q W_k^T` とすれば、**符号器の元の隠れ状態 `h_e` をそのまま索引化しても、元の交差注意内積と同じ順位で検索できる**。

この変形は単なる近似ではなく、浮動小数点誤差を除けば内積の計算順序を変えただけである。近似が入るのは、その後に全位置ではなく上位k個だけを取り出してソフトマックスを計算する点である。論文の予備実験では上位kの注意キーで99%超の注意質量を覆える場合があると報告するが、これはすべての入力で厳密に保証される性質ではない。

`W_q` と `W_k` は層・ヘッド固有だが、索引化する `h_e` は共通である。各ヘッドは自分専用の変換済み検索クエリを単一索引へ送る。検索した位置の `h_e` に `W_k` と `W_v` を適用して必要なキーと値を作り、通常の交差注意を計算する。こうして索引を2LH個作る方式と異なり、全層・全ヘッドが1個の索引を共有できる。

### 検索した上位kへの交差注意

復号ステップごとに、各層・各ヘッドのクエリを索引へ送り、内積の大きい入力位置を上位k個選ぶ。kは基底モデルの交差注意で扱う文脈窓に合わせた固定予算として設定できる。取り出した隠れ状態からキー・値を生成し、選択位置だけで正規化した注意重みを計算して復号器の状態を更新する。したがって各復号ステップの注意対象数は全入力長ではなくkに抑えられる。

選択位置は復号ステップ、復号器層、注意ヘッドごとに異なる。例えば人物名を生成する際には文書の登場人物の説明へ注意し、結末を生成する際には後半の出来事へ注意することが可能である。単に文書を最初に要約して圧縮する方法と違い、何を取り出すかを復号器の現在の状態が決める。

索引検索は近似近傍探索を使うため、計算時間が全入力の線形走査より小さくなることを狙う。ただし実際の時間は索引方式、検索設定、索引配置、メモリ帯域に依存する。索引をCPUメモリに置く場合はGPUへの転送や検索同期が必要で、長文での速度改善を単純な計算量だけから保証できない。論文は16ビットの1,024次元隠れ状態なら100万トークン分が約2GBの生ベクトル記憶に相当すると説明するが、索引の管理情報や実装上の追加費用を含む全プロセス使用量とは区別すべきである。

### 追加学習なしから長文対応学習まで

最も低費用の方法は、通常どおり先頭の固定長入力で微調整したBARTへ、テスト時だけUnlimiformerを注入することである。学習済みの重みはそのままで、長文全体をチャンク符号化し、復号時に索引から検索する。さらに検証時の早期停止判定だけUnlimiformerを使えば、長文全体を参照した生成品質でチェックポイントを選べる。訓練自体の計算費用はほぼ通常の微調整と同じである。

別の低費用案では訓練文書を固定長チャンクへ分割し、それぞれを独立の訓練例として使う。学習時に元文書の全トークンを異なる例として見せ、推論時にはUnlimiformerで全文を参照する。単なるチャンク訓練だけでは十分な利得が出ない場合もあるが、全文検索と組み合わせると大きな改善を示す。

計算費用を増やしてもよい場合は、訓練中にも長文をチャンク符号化して索引を使う。ランダム符号化訓練は参照位置を無作為に選んで検索処理を近似し、検索訓練は実際の近傍探索で位置を選ぶ。交互訓練は両者を交互のバッチで実施し、上位kだけに依存し過ぎないようにする。学習時はGPUメモリの制約から16,000トークン程度まで切り詰める条件がある一方、テスト時にはそれを超える全文を索引化できる。**学習時も50万トークンを一度に処理したわけではない**ことに注意が必要である。

## 主要結果

### 学習を増やさずに既存モデルを拡張した結果

|モデル・条件|GovReport ROUGE-1|SummScreen ROUGE-1|解釈|
|---|---:|---:|---|
|BART-base、通常微調整|48.7|29.7|先頭の固定窓を使う基準|
|BART-base、推論時のみUnlimiformer|49.7|30.9|追加学習なしで全文参照の効果|
|BART-base、検証時もUnlimiformer|51.0|32.1|長文を使った早期停止でさらに改善|
|BART-base、チャンク訓練＋Unlimiformer|53.4|29.3|GovReportで大幅改善、SummScreenでは単純な組合せが最良とは限らない|
|PRIMERA、通常微調整|55.1|32.3|長文要約用の強い基準|
|PRIMERA、推論時のみUnlimiformer|56.5|33.3|既存長文モデルにも追加適用可能|

通常BARTへテスト時だけ適用する場合、GovReportはROUGE-1が48.7から49.7へ、SummScreenは29.7から30.9へ上昇する。論文本文は改善幅を概ね1〜1.8点と説明するが、表に示された特定のBART-base設定では上記の差分となる。検証時の早期停止にも全文検索を使うと、GovReportは51.0、SummScreenは32.1となる。さらにチャンク訓練との組合せはGovReportで53.4へ改善する一方、SummScreenでは29.3と必ずしも上回らない。追加処理がすべての課題で単調な改善を保証するわけではない。

PRIMERAはLongformer型の長文符号器を用いた強いモデルだが、Unlimiformerを追加するとGovReportが55.1から56.5、SummScreenが32.3から33.3へ上がる。これは通常のBARTだけでなく、既に長文用の構造を持つモデルにも外部索引が補完的に働くことを示す。SLEDを推論時だけ追加したBARTはGovReportで45.8、SummScreenで27.5となり、同条件ではUnlimiformerより低い。検索する位置を各ヘッドのクエリに応じて絞ることが、全チャンクを単純に融合する方式と異なる。

### 長文を用いた学習まで許容した結果

|モデル・訓練|GovReport ROUGE-1/2/L|SummScreen ROUGE-1/2/L|
|---|---|---|
|BART-base、通常微調整|48.7 / 19.2 / 22.8|29.7 / 6.2 / 17.7|
|BART-base、SLED|54.7 / 24.4 / 25.4|32.7 / 7.9 / 19.1|
|BART-base、Memorizing Transformers近似|55.2 / 25.1 / 26.4|32.7 / 7.4 / 19.2|
|BART-base、Unlimiformer交互訓練|56.6 / 26.3 / 27.6|34.7 / 8.5 / 19.9|
|PRIMERA、通常微調整|55.1 / 23.9 / 25.9|32.3 / 7.1 / 18.3|
|PRIMERA、Unlimiformer交互訓練|57.4 / 26.2 / 28.0|33.3 / 7.6 / 18.9|

追加の長文対応訓練を認めた比較では、BART-base＋UnlimiformerのGovReport ROUGE-1は56.6、SummScreenは34.7となり、SLEDの54.7と32.7、Memorizing Transformers近似の55.2と32.7を上回る。PRIMERAでもGovReportのROUGE-1は55.1から57.4、SummScreenは32.3から33.3へ改善する。長文対応学習によって検索対象の分布に復号器を慣らすことで、推論時だけの注入より高い品質を得られる条件がある。

ただしMemorizing Transformersの比較は、公式実装が再現困難なため、外部記憶を一つの復号器層に適用する近似実装を用いたものである。完全に同じ最適化条件の公式実装同士の比較ではない。この制約を無視して「先行法を必ず上回る」と一般化すべきではない。

### BookSumの超長文での情報保持

BookSumでは全文が数十万トークンになる。通常のBART-baseを先頭だけで微調整した条件のROUGE-1は36.4、固有表現言及再現率EntMentは10.0である。推論時にUnlimiformerを追加するとROUGE-1は35.5へわずかに下がる一方、EntMentは21.9へ大きく改善する。検索訓練を行ったUnlimiformerはROUGE-1 36.8、EntMent 20.3となる。

この結果は、要約文の表面的な語句一致と、書籍全体の固有名詞や登場人物を実際に参照したかが異なることを示す。先頭だけからもっともらしい要約を生成してもROUGEでは比較的高い値が出る可能性があるため、全文参照によってどの情報を回収できたかを別の指標で確認する必要がある。50万トークンを超える入力を処理したという主張は、符号器・復号器型要約のこの実験条件であり、あらゆる生成課題で同じ品質を保証するものではない。

### 計算・メモリの読み方

索引は各入力位置につき隠れベクトル1本を保持する。16ビットの1,024次元表現なら100万トークンの生ベクトルは約2GBであり、ヘッド・層ごとに複製した索引を持つ方式より記憶効率が高い。復号ステップの注意対象はk個に固定できるため、全入力をGPUへ展開する交差注意よりメモリを抑えられる。一方、チャンク符号化と索引構築の費用は残り、CPUに索引を置くと検索・転送の費用も加わる。

近傍探索の時間は索引実装と検索精度に依存し、入力長に対する理論的な劣線形検索を、常に実測遅延の劣線形増加と同一視できない。特に出力が短い場合は索引構築の初期費用を回収しにくい。したがって「入力長に事実上の上限を設けない」ことは、メモリと計算がゼロになることを意味しない。

## 既存研究との差

LongformerやLEDは注意構造を変更して長文へ対応するが、モデル固有の事前学習や位置表現の調整が必要になることがある。Unlimiformerは既存の符号器・復号器の重みを変更せず、交差注意直前に検索を挿入できる。モデルの学習済み能力を残したまま入力長の上限を拡張できる点が異なる。

SLEDは入力をチャンク符号化する点では似ているが、復号器が多数の入力位置へ注意するため、入力がさらに長くなると交差注意のメモリ費が大きくなる。Unlimiformerはチャンク符号化した全状態を外部索引へ退避し、各復号器ヘッドがその都度上位kだけを検索する。固定長の注意対象を保ちながら全文の任意位置を候補にできる。

Memorizing Transformersも近傍探索を使うが、層・ヘッド別の射影済みキー・値を扱う方式では索引数が増え、実装上は限られた層へ外部記憶を適用する。Unlimiformerは内積の結合則で射影をクエリ側へ移し、単一の符号器隠れ状態索引を全層・全ヘッドで共有する。追加の学習可能なゲートや重みを必要とせず、既存モデルの推論時にも適用できることが実装上の利点である。

## 限界

主手法は符号器・復号器型Transformerの交差注意を対象とする。復号器のみの現代LLMが保持する自己注意のKVキャッシュをそのまま圧縮する方法ではない。論文や公開コードで他構成への対応が言及されても、主要な定量評価を実施したBART/PRIMERAの設定と区別する必要がある。

入力が長い場合も、符号器は全チャンクを処理し、索引は全位置の隠れ状態を保持する。CPUメモリへ退避してGPU容量の制約を緩められるが、CPU側のメモリ使用量、索引構築、近傍探索、GPUとの転送費用は残る。無制限という名称は理論上の固定窓制約を取り払う意味であり、実際の計算資源が無制限という意味ではない。

検索対象を上位kへ限定するため、必要な位置が上位kに入らなければ情報を失う。論文は予備実験で上位kの注意質量が99%超になる例を示すが、全入力、全ヘッド、全課題での保証ではない。遠くの一語や希少な事実が重要な場合は、検索誤りが生成結果へ直接影響し得る。

長文対応訓練は学習時に最大16,000トークン程度へ入力を切り詰める条件を含み、50万トークン全文を学習時にも一度に処理したわけではない。BookSumの評価は書籍要約に集中し、検索を必要とする対話、コード生成、長期エージェントの履歴保持などで同じ品質が得られるかは未検証である。

ROUGEとEntMentの差が示すように、要約の表面的な文字列一致だけでは全文情報の利用を評価しきれない。BookSumでは全文検索によりEntMentが改善してもROUGE-1が少し下がる条件がある。単一の指標だけで最良手法を決めることは避けるべきである。またMemorizing Transformers比較は再現性上の制約から近似実装であり、厳密な公式実装比較ではない。
