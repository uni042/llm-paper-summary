# MemSizer：固定スロットのキー・値メモリでTransformerを線形化

## 概要

MemSizerは、標準Transformerの自己注意を、入力系列長に依存しない少数のキー・値メモリへ置き換える軽量な系列生成モデルである。通常の自己注意では、クエリが過去の全キーを参照するため、系列が長いほど注意の計算とKV保存量が増える。MemSizerはキーを入力非依存の学習パラメータとし、値を入力系列から固定数のスロットへ集約する。生成中にはスロットの集約状態だけを更新するので、系列長に対して線形の計算量と定数サイズの再帰状態を目指せる。

WikiText-103の言語モデルでは、MemSizerのテスト困惑度20.8は標準Transformerの18.5より悪いが、256トークン生成の速度指標は3165対1932、メモリ使用量は3.373GB対19.21GBである。WMT翻訳では英独BLEUが28.4で標準Transformerの28.9を下回る一方、英仏42.4対42.2、中英24.5対24.2で小幅に上回る。XSUM要約ではROUGE-Lが25.8対25.3だが、CNN/DailyMailでは33.1対35.8へ低下する。計算効率と生成品質の交換条件がタスクによって異なることが重要である。

## 問題設定

標準の多頭自己注意は、系列中の各トークンが他のトークンへ注意を向けるため、入力長が大きいと二次的な注意計算が発生する。生成時に過去のキーと値をキャッシュしても、過去の系列に応じて保存量は増え、長い文脈ではメモリが大きくなる。Linformerは系列方向を低ランクへ射影して計算を減らすが、射影行列の入力長が固定されるため、可変長の自己回帰生成で扱いにくい。

カーネル近似型の線形Transformerは再帰的な状態更新によって系列長に依存しない生成が可能だが、短い生成では追加計算のために標準Transformerより遅くなったり、精度が低下したりする。MemSizerは、可変長系列を固定スロットへ集約するLinformerの考え方と、再帰的に状態を更新する線形注意の利点を両立することを狙う。

## 手法

### 1. 入力非依存のキーと入力依存の値

標準Transformerは入力トークンからクエリ、キー、値をそれぞれ線形射影して作る。MemSizerはこのうちキーを、入力系列に依存しない学習可能な固定行列へ置き換える。クエリは入力から計算するが、照合するキーの数は固定のメモリスロット数に限られる。値は入力系列全体の情報を固定スロットへ集約した行列である。キーと値を対称に扱わず、値の表現力を重視する非対称な設計が特徴である。

メモリスロット数をk、特徴次元をdとすると、キー行列はk個の学習パラメータを持ち、入力長nに依存しない。クエリと固定キーの類似度をsoftmaxで正規化し、値スロットを重み付き平均して出力を作る。入力の各位置に対して全n個のキーを参照する必要がなく、kがnより小さい条件で注意計算を減らせる。ただしkが小さすぎると、入力の細部を保持できず生成品質が悪化する可能性がある。

### 2. 可変長系列の値メモリへの集約

Linformerの固定長射影と違い、MemSizerは入力トークンの特徴から二つのアダプタ射影を計算し、その積を系列方向に加算して値メモリを作る。原著式(8)は入力長に固定された射影行列を必要とせず、入力トークンから得られる二次統計量に似た集約を用いる。集約後には層正規化と系列長に応じた尺度調整を行い、入力が長くなると値の振幅が不安定になる問題を抑える。

この値メモリは各トークンの完全な履歴を保存するのではなく、全体の情報を少数のグローバルなスロットへ押し込む。従って入力長が変わってもメモリ行列の形は一定であり、可変長の入力と生成を扱いやすい。一方、厳密なトークン位置や引用文を再現する必要があるタスクでは、集約によって情報が失われる可能性がある。

### 3. 軽量な多頭注意

MemSizerでは複数の注意ヘッドが同じ値メモリを共有し、キー側のヘッドごとの確率重みを平均してから一回の値メモリ積を計算する。標準Transformerのようにヘッドごとの出力を連結して大きな出力射影を適用する必要がない。原著式(9)は、ヘッドごとの出力を平均することと、ヘッドの注意重みを平均して一回だけ値行列へ掛けることが等価であることを示す。

この設計は多頭化による計算負担を抑えるが、標準多頭注意のように各ヘッドが別の値表現を持つ柔軟性は低い。効率のために値を共有することが、タスクごとの精度差へ影響している可能性がある。

### 4. 再帰状態の更新

自己回帰生成では、次のトークンが追加されるたびに入力系列全体を再集約するのではなく、前ステップの値メモリへ新しいトークンの寄与を加える。原著式(10)〜(11)は、入力特徴から作った積の累積和を再帰状態として保持する。これにより、生成の各段階で必要なメモリは過去の系列長に依存せず、固定サイズの状態を更新するだけでよい。

計算量の解析では、標準注意の系列長二次項を、メモリスロット数kに依存する線形項へ置き換える。メモリ使用量は系列長nに依存せず、kと特徴次元に依存する。これらは注意層の理論的な計算量であり、実際のモデル全体の推論速度にはFFN、埋め込み、バッチサイズ、GPUカーネルの費用も影響する。

### 系列長・スロット数の感度

原著Figure 1では、英独翻訳の系列長を512まで増やした場合、MemSizerは標準Transformerに対して約300%の速度改善を報告する。標準注意は系列長が増えるほど計算が重くなる一方、MemSizerの生成速度は比較的一定である。Figure 2ではスロット数を増やすとWikiText-103の困惑度が改善する傾向があり、メモリを増やして品質を高める交換条件がある。固定スロット数を無制限に減らせばよいという設計ではない。

## 既存研究との差

Linformerは系列方向を固定長へ射影して計算量を減らすが、固定の入力長を前提とする。カーネル近似型の線形Transformerは再帰状態を更新できるが、近似精度と短い生成での追加計算が課題となる。MemSizerは入力非依存の固定キーと、系列長に依存しない値メモリを用いるため、固定長の射影行列を持たずに可変長生成を扱える。さらに値メモリを共有して多頭計算を軽量化する。

本方式はKVキャッシュを量子化する技術ではなく、注意機構そのものを置き換えるアーキテクチャ研究である。既存の大規模LLMの重みをそのまま利用してメモリだけ減らす方法とは異なり、原著では各モデルを初期化から学習している。したがって、サービングシステムへの導入ではモデルの再学習費用と既存チェックポイントとの互換性を考慮する必要がある。

性能比較では、系列の長さが長くなるほど標準の注意演算に対する優位が大きくなる。短い系列では、注意の計算そのものより特徴変換やメモリの読み書きが支配的になりやすく、理論上の計算量の違いだけでは実測速度差を説明できない。原著が翻訳・要約・言語モデルの三種類を評価したのは、このような入力長と生成長の違いを比較するためでもある。また、固定スロットの数を増やせば元の文脈を保持しやすくなるが、スロットに対する照合と状態更新の費用も増える。実用時には要求する精度に応じてスロット数を選択する必要がある。

## 限界

標準Transformerと比較するとWikiText-103で困惑度が18.5から20.8へ悪化し、CNN/DailyMailの要約ROUGE-Lも35.8から33.1へ低下する。固定スロットへ集約するため、原文の正確な語句や長距離の細部を保持する能力に限界がある可能性がある。機械翻訳のBLEU改善は小さく、統計的な有意差の確認も限定的である。

評価は2022年当時の翻訳・要約・言語モデルを初期化から学習したもので、数十億パラメータの既存LLMを直接圧縮した実験ではない。再帰状態の理論上の定数メモリ性と、現代のGPU上での実際のオンライン生成速度、複数ユーザー同時要求、長文脈検索品質は別途検証が必要である。標準注意の表現力を犠牲にして固定スロットへ情報を集約するため、用途に応じて精度と効率を比較すべきである。
