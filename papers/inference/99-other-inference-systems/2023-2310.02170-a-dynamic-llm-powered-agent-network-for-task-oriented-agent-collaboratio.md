## 概要
複数LLMエージェントの協調は単一実行より精度を上げられるが、全タスクへ同じ人数・同じ通信グラフを使うと不要なAPI呼出しが増える。DyLANはタスクに応じて参加エージェントを選び、問題解決中の通信構造も動的に変える。

## 問題設定
静的multi-agent方式は、簡単な問題でも全エージェントを全round動かしやすい。また役割の異なるエージェントのうち誰が最終解答へ実際に寄与したかを定量化しないため、チーム編成を手作業に依存する。

## 手法
第1段階のTeam Optimizationでは候補エージェントを予備試行し、後段の解答へどれだけ有用な情報を渡したかをAgent Importance Scoreとして推定する。教師ラベルなしで寄与度を順位付けし、対象タスク/domain向けのチームを選ぶ。

第2段階のTask Solvingでは選択チームを時間方向のfeed-順伝播 ネットワークとして動かし、各roundで必要な接続を作る。推論時エージェント選択とearly stoppingを使い、不要な後続呼出しを抑える。

## 評価条件
|項目|内容|
|---|---|
|課題|MATH、HumanEval、MMLU、意思決定・一般推論|
|比較|単一GPT-3.5-turbo、固定multi-agent 比較対象|
|制御|Agent Importance Score、動的通信、early stopping|
|指標|accuracy/pass率、計算コスト|

## 主要結果
単一GPT-3.5-turbo実行に対してMATHで13.0ポイント、HumanEvalで13.3ポイント改善する。MMLUの一部科目ではTeam Optimizationによる適切なエージェント選択がaccuracyを最大25.0ポイント押し上げる。

## 既存研究との差
固定討論グラフや固定role集合を使うmulti-agent方式に対し、DyLANは「誰を使うか」と「いつ通信するか」をタスク依存にする。これは後のagentic 推論提供で問題になるモデル呼出し数・依存グラフ最適化の初期例と位置付けられる。

## 限界
Agent Importance Scoreを得るため予備試行が必要で、少数回しか現れないタスクでは償却しにくい。実験はAPI/論理呼出し量を中心にしており、GPU配置、KV共有、queueingを含む推論提供 ランタイム最適化そのものではない。
