## 概要
複数の大規模言語モデル（large language model; LLM）エージェントを協調させる方式では、役割の異なる複数回答を相互評価できる一方、人数と通信構造を全タスクで固定すると、不要なモデル呼出しが増え、専門外のエージェントが有用な回答へ干渉する。DyLAN（Dynamic LLM-Powered Agent Network）は、協調を時間展開したフィードフォワードネットワーク（temporal feed-forward network; T-FFN）として表し、「どのエージェントを使うか」と「実行中に誰を残すか」を分離して最適化する。

処理は二段階である。チーム最適化（Team Optimization）では候補エージェントを予備協調させ、後段の回答へ実際に寄与した度合いをエージェント重要度（Agent Importance Score）として逆向きに集約し、タスクや分野ごとの上位エージェントを選ぶ。タスク解決（Task Solving）では選ばれたチームをT-FFN上で動かし、途中のLLMランカーが低評価エージェントを次時刻から外すチーム再編成（agent team reformation）と、回答が十分一致した場合の早期終了を行う。狙いは単純な「エージェント数を増やす」ことではなく、実際の協調履歴に基づいて不要・有害な計算枝を減らしながら精度を保つことである。

## 問題設定
固定型のマルチエージェント（multi-agent）法には二つの無駄がある。第一に、問題が容易でも全エージェントを所定ラウンドまで動かしやすく、API呼出し数が膨らむ。第二に、役割名や人手の直感でチームを作っても、その役割が対象タスクで実際に貢献するとは限らない。特に複数ラウンドでは、あるエージェントの回答が直接最終出力へ採用されなくても、後続エージェントの改善を介して間接的に効くため、単一時刻の応答品質だけでは寄与を測りにくい。

DyLANはこの依存を計算グラフとして明示する。時刻 (t) の各エージェントをノード (v_{t,i})、前時刻からの応答受け渡しを辺としてT-FFNを作る。この表現を使うと、通常の推論は前向きメッセージ伝播、寄与度推定は後ろ向きメッセージ伝播として同じグラフ上に記述できる。

## 手法
### T-FFNによる協調表現とタスク解決
T-FFNの各層は協調の1時刻に対応し、ノードはその時刻のエージェント、辺は前時刻から受け取るメッセージを表す。LLMエージェントの場合、前段の複数応答と元の問題をプロンプトへ連結し、批評・修正・回答生成など役割ごとの処理を行う。ツールノードなら必要な構造化入力だけを抽出して実行する。これにより固定討論、コード生成とレビューなど異なる協調形態を共通のグラフとして扱える。

実行途中のチーム再編成では、追加のLLMランカーが現在時刻のエージェント応答を順位付けし、上位エージェントだけを次時刻へ接続する。出力は単なる順位ではなく、次のT-FFN層に残るノード集合と辺集合であり、低評価エージェントは以後のモデル呼出しから外れる。さらに同一層で3分の2を超えるエージェントが同じ答えに合意したと判定すると早期終了し、最大時刻まで無条件に回す場合の呼出しを削る。

### エージェント重要度によるチーム最適化
本番タスク解決の前に、候補全体で予備試行を1回行う。各ノードは前段の複数回答を評価し、前段ノード (i) から後段ノード (j) への評価値 (w_{t-1,i,j}) を作る。最終層の寄与を初期化した後、後段ノードの寄与と評価値を掛けて
[
I_{t-1,i}=\sum_j I_{t,j}w_{t-1,i,j}
]
の形で後ろ向きに伝播する。同じエージェントの時刻別寄与を合計したものがAgent Importance Scoreで、上位 (k) エージェントをタスク別チームとして採用する。単一応答の自己評価ではなく、後続ノードからの評価を多段に伝えるため、「最終回答へ間接的に役立ったエージェント」も評価対象になる。

この方法は教師付きの正解寄与ラベルを必要としないが、予備試行とLLMによる相互評価が必要である。したがって選抜費用は一度だけ使うタスクでは純粋な上乗せになり、同一分野で繰り返し使う場合ほど償却しやすい。

## 主要結果
HumanEvalでは単一実行がPass@1 73.2、1 API callに対し、DyLANは82.9、16.85 callsである。LATSの81.1を上回る一方、LATSは48 callsを要する。したがってDyLANは単一実行より計算量を増やして精度を上げる方式であり、「単一LLMより安い」のではない。一方、同程度以上のマルチステップ法と比べると、品質と呼出し数の交換条件が改善する。

WebShopでは直接実行の報酬50.6・成功率28.0・14.52 callsに対し、DyLANは68.3・42.0・24.85 callsである。LATSは報酬64.5、成功率38.0だが400 calls超で、DyLANは大幅に少ない。MMLUでは単一実行66.4・1 call、LLM Debate 69.3・12 callsに対し、DyLANは70.5・4.39 callsとなり、論文はLLM Debateよりaccuracyが約10.2%相対改善、API callsが10.6%少ないと分析する。MATHでは標準CoTの単一実行31.6に対してDyLAN 35.7（+4.1ポイント）、Complex-CoT系でも34.1から37.6（+3.5ポイント）であり、既存サマリーにあった「MATH +13ポイント」という読み方は一次表と一致しない。

チーム最適化そのものを見ると、HumanEval相当のコード生成設定では候補12→8人で性能76.2→82.9、呼出し23.04→16.85、WebShopでは8→4人で報酬53.0→68.3、呼出し32.03→24.85へ改善する。MMLUでは7→4人でaccuracy 69.5→70.5、呼出し8.30→4.39となる。特定科目では、例えばcollege mathematicsが40.0→65.0で+25.0ポイントとなり、役割選択の効果が分野依存で大きいことを示す。

構成要素除去実験では、早期終了なしだとMATHでAPI calls 7.15→13.00、MMLUで4.39→13.00へ増える一方、精度差は35.7→35.0、70.5→70.1と小さい。したがって早期終了は主として呼出し削減へ効く。チーム再編成を外すとHumanEvalのPass@1は82.9→76.2、WebShop報酬は68.3→66.0となり、特にコード生成で動的な枝刈りが品質にも寄与する。最適チーム人数の分析では、一般推論で3人の選抜チームが未最適化チームや4人LLM Debateを上回り、呼出し効率も改善しており、「人数が多いほど強い」とは限らない負の干渉を示している。

GPT-4-0613での追加評価ではDyLANはHumanEval Pass@1 92.1、15.94 callsで、単一GPT-4の88.4より高いが、LATSの94.4より低い。LATSは40 calls超を要するため、ここでも最良精度ではなく費用対性能の中間点に位置する。

## 既存研究との差
固定ラウンド討論や固定役割集合は通信グラフとメンバーを事前に決める。DyLANは、予備協調から得た後向き寄与伝播で「誰を残すか」を決め、本番中はランカーでさらに「いつ残すか」を更新する。このため、チーム構成の事前最適化と実行時の動的構造変更を同じT-FFN表現で扱える。推論システムの観点では、GPUカーネルやKVキャッシュを直接最適化する研究ではなく、上位のエージェント呼出しグラフを削減・再構成する方式である。

## 限界
論文自身が、コード生成の早期終了で応答一致を測るためBLEUを使っており、CodeBLEUなどタスク固有指標の方が適切な可能性を挙げる。Agent Importance ScoreもLLMの相互評価に依存し、データが少ない場合は人手評価との併用が必要になり得る。候補エージェントの大半が対象タスクと逆方向の能力・指示を持つ極端な場合には、選抜してもチーム全体の品質が低い可能性がある。

また、主コスト指標はAPI呼出し数であり、トークン長、モデルごとの価格、並列実行時間、GPU配置、キュー待ち、KVキャッシュ共有などを直接測定していない。予備のTeam Optimizationにも費用がかかるため、単発のクエリでは総費用削減にならない場合がある。したがってDyLANの結果は「動的なエージェント構成が有効」であることを示すが、そのまま低レベル推論ランタイムの速度向上倍率へ換算できない。
