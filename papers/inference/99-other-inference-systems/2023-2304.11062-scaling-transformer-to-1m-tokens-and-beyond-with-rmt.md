# Scaling Transformer to 1M tokens and beyond with RMT

## 概要

再帰メモリTransformer（Recurrent Memory Transformer; RMT）は、長い入力を固定長の区間（segment）へ分割し、少数の学習可能なメモリトークン（memory tokens）の状態だけを次の区間へ再帰的に渡すことで、事前学習済みTransformerの有効文脈を伸ばす。各区間内では通常の全注意（full attention）を使うが、過去全体のhidden stateやKVを保持しないため、区間長を固定すれば推論計算量は入力全長に対して線形、推論時メモリはほぼ一定になる。

重要なのは、専用の外部メモリ読書き機構を追加しない点である。メモリトークンは通常トークンと同じTransformerへ入力され、モデル自身が注意を通じて「何を保存し、何を保持し、いつ読み出すか」を学ぶ。著者らはこのwrapperをBERTのようなencoder-onlyとGPT-2/GPT-Neoのようなdecoder-onlyへ適用し、合成記憶課題では学習時より桁違いに長い系列へ外挿できること、自然言語・形式言語では追加の過去区間がperplexity改善に使われることを検証する。

## 問題設定

標準Transformerは系列長 `L` に対して自己注意の計算・中間メモリが概ね `O(L²)` で増える。長文脈向け疎注意はこの増加を抑えられるが、モデル構造やattention pattern自体の変更を要する方式も多い。Transformer-XLのような再帰方式は過去hidden stateを再利用するが、過去情報量と保持状態の設計がモデルごとに異なる。

RMTは、過去の詳細なtoken stateを固定個数 `m` のメモリベクトルへ圧縮する。したがって長さ方向の計算・メモリ増加を抑えられる一方、メモリ容量が情報ボトルネックになる。この圧縮状態を将来必要な情報へ使えるように学習することが核心になる。

## 手法

### 1. 区間間の再帰メモリ

長い入力を固定長区間へ分割し、最初の区間に `m` 個の実数値学習可能メモリベクトルを付加する。区間 `τ` をTransformerで処理した後、対応するメモリ位置の最終hidden state `H̄^mem_τ` を取り出し、それを次区間 `τ+1` のメモリ入力 `H^mem_{τ+1}` としてそのまま渡す。本文tokenそのものや全過去hidden stateは次区間へ保持しない。

encoder-onlyでは区間先頭に単一のmemory sectionを置く。因果maskを使うdecoder-onlyでは、前区間から読むread memoryを先頭、現在区間から次へ書き出すwrite memoryを末尾に分ける。これにより本文tokenが過去memoryを読め、write memoryは現在区間本文を見て次区間用状態を更新できる。backbone Transformerの層構造やattention演算自体は変えない。

### 2. 区間内だけの全注意と計算量

各stepで全注意を計算する範囲は「固定長segment + 少数memory token」に限定される。入力が長くなれば同じ固定costのstepを繰り返すため、segment lengthを一定にしたRMTは総長に対して線形にscaleする。論文のOPT構成を用いたFLOP推定では、2,048,000 tokenでfull-attention Transformerに対する削減幅が小型modelでは最大約295倍、OPT-175Bでも約29倍に達する。

利得は長文脈ほど大きい。短い系列では再帰wrapperとmemory tokenの固定費があり、full attentionとの差は小さい。一方、非常に長い系列ではfull attentionの二次増加を避ける効果が支配的になる。

### 3. 区間単位のcurriculum learning

学習時には後続区間のlossからmemory経路を通して前区間へ勾配を流す逆伝播（backpropagation through time; BPTT）を使う。いきなり長いunrollで学習するのではなく、まず1 segmentで収束させ、2、3…と段階的にsegment数を増やす区間単位のcurriculumを採用する。さらに自然言語モデルでは各curriculum段階でhistory長を混ぜる方が未学習長への一般化が改善する。

この設計により、memoryは単なる平均poolingではなく、将来のlossに役立つ情報を選択して保持する状態として学習される。ただしBPTTは学習時に複数segmentの計算graphを保持するため、推論の定数メモリ性とは別に学習costが残る。

## 評価条件

### 合成長期記憶

BERTをbackboneとし、memory size 10で、bAbI由来のfactとQuALITY由来の無関係背景文を組み合わせた3課題を評価する。Memorizeは先頭のfactを最後のquestionまで保持、Detect & Memorizeは長いnoise中からfactを発見して保存、Reasoningは離れた2 factを保持して組み合わせる。BERTの最大入力512のうちspecial token 3個とmemory placeholder 10個を除くため、実本文segmentは499 tokenである。

モデルは最大7 segment程度までcurriculum学習し、推論時には最大4096 segment、約2,043,904 tokenへ外挿する。単なる「長い文章を入力できたか」ではなく、末尾questionへの分類accuracyでmemoryに保存したfactを回収できるかを見る。

### 自然言語・形式言語

自然言語ではHugging Face GPT-2へmemory token 2個を追加し、The PileのArXiv文書を固定長segmentへ分ける。複数history segmentを順次処理し、最後のtarget segmentだけでloss/perplexityを測る。

形式言語ではLean 3 / Mathlibの定理・lemma・proof系列を用い、GPT-Neo 1.3Bへmemory token 10個、segment size 2028を設定する。memoryなしGPT-Neoと同じ学習token数で比較し、系列全体および最後のsegmentのperplexityを測る。

効率の補助実験は単一NVIDIA A100 80GB、Hugging Face GPT-2、FP32、FlashAttentionなしという条件で行われるため、最新kernelを使う現代serving stackの絶対性能とは分けて解釈する必要がある。

## 主要結果

合成課題では、5 segment以上で学習したcheckpointが学習長の約2倍までほぼ完全に一般化し、7 segmentまで学習したRMTを4096 segmentへ伸ばしても高いretrieval accuracyを維持した。特にDetect & Memorizeが最も容易で、複数factを扱うReasoningが難しい。attention可視化では、fact出現時にmemoryへ書き込み、無情報segmentでは保持し、最後のquestion時にmemoryを読む挙動が観察される。これは「再帰状態が単に残っている」だけでなく、taskに応じた書込み・保持・読出し操作が学習されたことを示す。

GPT-2のArXiv language modelingでは、処理するhistory segment数を増やすほどperplexityが改善し、同じstep数を学習したmemoryなしbaselineより低いperplexityを示す。segment先頭では通常GPT-2は局所contextが少なくlossが高いが、RMTは前segmentのmemoryを持ち越すことで先頭tokenの予測を改善する。一方、直前本文を圧縮せずそのまま与える方式はさらに大きなloss改善を得られ、圧縮memoryと品質の交換条件も確認できる。

Lean/MathlibではRMTがmemoryなしGPT-Neoよりperplexityを改善するが、**4 segment以上へ学習長を増やしても長系列予測がさらに改善しない**負の結果がある。著者らは、現在のdata構成では関連lemma全体を記憶するよりsegment境界をまたぐlemma末尾予測を学びやすい可能性を挙げ、loss設計とdata preparationの改善が必要だとしている。

効率面では固定segmentにより推論メモリが入力長で増えず、長文脈になるほどfull attentionに対するFLOP差が拡大する。実装実験でも通常GPT-2が長さ増加でmemory limitへ達する一方、RMTはsegment反復で処理を継続できる。ただし2M tokenのheadline結果は合成記憶課題であり、一般的な2M-token generation品質を実証したものではない。

## 既存研究との差

Transformer-XLは過去segmentのhidden stateをcacheして次segmentから参照するが、RMTは固定個数の専用memory tokenへ過去情報を圧縮し、それ自体を再帰状態にする。Longformer/BigBird等の疎注意は長い入力内のattention patternを変えるのに対し、RMTはbackbone Transformerを変えずwrapperとして追加できる。外部memory networkと異なり、専用addressing/read-write moduleも導入しない。

この互換性の代償として、任意の過去tokenへ正確に再アクセスする機構はない。RMTが使えるのはmemory stateへ圧縮された情報だけであり、何を残すかは学習に依存する。

## 限界

論文自身が、curriculum設計が長さ一般化へ大きく影響すると報告している。2M tokenまでの結果も専用の合成課題で、同規模の一般NLP benchmarkは評価されていない。BPTTはfull attentionより軽いものの学習costは依然大きく、より大規模modelや、より長いunrollを必要とするtaskでは負担が増える。

また、固定個数memoryは過去のexact hidden stateを保持しない圧縮表現である。資源が十分なら、全履歴を直接参照できるfull attentionが品質上の上限になり得る。したがってRMTは「無制限長を損失なく扱う」方式ではなく、長さに対する計算・memory costと、保持できる情報量を交換する方式と捉えるべきである。
