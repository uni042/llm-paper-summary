# Untangling Component Imbalance：混合型線形注意の成分崩壊と修復

## 概要

事前学習済みTransformerの通常のsoftmax注意を線形注意（LA）へ置き換えれば、過去のキーと値を全トークン分保持せず、一定サイズの再帰状態へ集約できる。しかし注意機構を変更しただけでは元モデルの精度が下がるため、注意転写と追加微調整を行う。局所的な情報の欠落を補うため、LAにスライディングウィンドウ注意（SWA）を足す混合型も使われる。本研究は、この混合型の高い正答率が、実際にはLAではなくSWAだけに依存している場合を発見した。

中心的な証拠は、学習済みモデルの推論時に片方の枝をゼロにして比較する除去実験である。LoLCATs型のMistral-7Bでは、LA+SWAの6課題平均65.48に対し、SWAのみ65.56、LAのみ34.78、注意を全部消した場合34.40だった。LAの存在が全体の正答率を改善していないだけでなく、LA単独では有効な情報検索がほぼできない。この発見は「モデル全体の性能回復率」だけを示す混合注意研究の評価方法そのものに警鐘を鳴らす。

著者は原因を注意転写の学習目標、特徴写像の次元、活性化関数に分解し、推論時だけの混合化、HedgeCATs、Scheduled Sliding-window Dropout（SSD）の三方式を検証する。主たる貢献は高速カーネルの実測改善ではなく、線形枝が本当に動作しているかを確かめる診断と、学習時にその枝を無視させない変換手順である。

## 問題設定

標準softmax注意は長さTの系列に対しQKᵀのT×T組合せを計算する。線形注意は特徴写像φで `S_t = Σ_{i≤t} φ(k_i)v_iᵀ` と `z_t = Σ_{i≤t} φ(k_i)` を蓄積し、`o_t = φ(q_t)ᵀ S_t / (φ(q_t)ᵀ z_t)` として出力を読む。固定したヘッド幅なら状態サイズは系列長に依存しない。ただし有限次元のφで通常softmaxを厳密に再現することは一般にはできず、元の重みからの変換には蒸留・微調整が必要となる。

混合型は `g·SWA(Q,K,V) + (1−g)·LA(Q,K,V)` を計算する。著者の基本設定はg=0.5、窓幅64であり、LAは窓の外の履歴を担当する。これは混合係数を均等にしただけで、両枝が同程度に**有用な情報**を出している保証にはならない。特に常識・知識ベンチマークは、局所文脈やモデル内部の記憶だけでも解ける問題を多く含み、長距離のLA経路が機能していなくても総合精度が高くなり得る。

既存LoLCATsのように教師softmax注意の出力と生徒の混合出力をMSEで合わせると、強力なSWA枝が教師を近似して損失を下げられるため、LA枝に情報を保持させる必要がなくなる。著者はこの迂回路を「成分崩壊」と呼び、学習済み枝の寄与を直接測る設計を採用する。

## 手法

### 1. 推論時の成分除去による診断

学習済みチェックポイントはそのまま固定し、注意出力を次の4通りに切り替える。SWA-onlyではLAの出力をゼロにする。LA-onlyではSWAをゼロにする。attention-sinks-onlyでは冒頭8位置のsoftmax注意だけを残す。no-attentionでは注意出力全体をゼロにする。チェックポイントを再学習せず同一の6課題で評価するため、学習量の差ではなく各枝の実際の寄与を観測できる。

この診断ではSWA-onlyが混合型とほぼ同じ、LA-onlyがno-attentionとほぼ同じなら、線形枝は性能を支えていないと判断する。逆に、混合型がSWA-onlyを有意に上回り、LA-onlyも無注意を上回れば、少なくとも線形枝の情報利用を確認できる。ただし枝をゼロにする操作自体は学習時の分布から外れるため、LA-onlyの絶対精度だけを本番推論の品質と同一視してはならない。

### 2. 注意転写の損失と特徴写像を切り分ける

HedgeHogの注意転写は、教師softmax注意と線形注意の**注意重み分布**をsoft-label交差エントロピーで一致させる。LoLCATsの転写は、教師の**全注意出力**と生徒の**LA+SWA混合出力**をMSEで一致させる。第三の比較では教師の全注意出力と生徒の**LA単独出力**をMSEで一致させる。後二者は出力の誤差という点では似ているが、混合出力を使うとSWAが教師を肩代わりできることが決定的に異なる。

転写損失だけの効果を見る段階では、後続のLoRA微調整を入れない。Mistral-7BのLA-only平均は、注意重み転写46.94、LA単独出力転写47.23、混合出力転写35.41、無注意34.40である。LAを直接監督した二方式だけが明確に有効であり、学習目的が枝の崩壊を引き起こす主要因だと分かる。

特徴写像φの射影幅も独立に比較する。HedgeHog型はヘッド幅dに対してd×dの射影を用い、正負の写像を連結する。LoLCATs型のd×(d/2)へ縮めると、同じ重み転写で46.94→43.25、LA単独出力転写で47.23→42.60に低下する。小さい特徴写像は状態量と演算量を節約する反面、教師の注意を近似する容量も減らす。

さらに活性化関数を変えると、Mistral-7BのLA-only平均はsoftmax型46.94、指数型46.11、ReLU36.07、1+ELU35.12、活性化なし34.81となる。指数族が相対的に良く、LoLCATsの失敗を「softmax活性化そのものの不適切さ」だけで説明することはできない。

### 3. 対策A：LA単独の変換後、推論時にSWAを加える

最初にLAだけを使って教師の注意を転写し、線形枝が独立に動く状態を作る。その後、混合注意を用いた追加微調整は行わず、推論時だけSWAを足す。LAを訓練する時点ではSWAによる迂回が存在しないので、長距離履歴の情報をLA側へ学習させられる。推論時の混合では、LAが窓外のみを見る場合と窓内も重複して見る場合を比較する。

原著Figure 2では、LA単独の追加微調整はLA-onlyの精度を上げても、SWAの寄与を下げることがあり、混合型の最高精度は追加微調整なしで得られる条件がある。窓内をLAにも重複して見せると性能が下がる条件もある。固定g=0.5が重複情報を適切に重み付けできない可能性があり、入力依存の混合係数は未検証である。

### 4. 対策B：HedgeCATs

第一段階でHedgeHog型の注意重み転写を使い、LA単独が教師に近い注意分布を出せるようにする。第二段階でSWAを戻し、Q/K/V/Oの射影へLoRAを適用して下流精度を回復する。重要なのは、LoRAを長く続けるほど良いとは限らない点である。Figure 3ではLlama3-8Bで微調整を進めると混合型が悪化する一方、SWA-onlyが改善する傾向が見られる。Mistral-7Bでは両者とも悪化する条件がある。LAの寄与が失われる前に早期終了する必要がある。

### 5. 対策C：Scheduled Sliding-window Dropout

SSDは混合型のLoRA微調整中にSWA枝を確率的に遮断する。最初のエポックではLAに大部分の問題を解かせ、学習が進んだらSWAを段階的に戻す。原著Figure 4(a)はSWAのdropout率0.9→0.75→0.5、窓幅32固定であり、初期の強いdropoutによってLAの利用が促され、混合型の精度が微調整とともに伸びる。

対照として、dropoutを0.5に固定して窓幅4→8→16→32→64と拡大する方式、およびdropout0.5・窓幅16固定を試す。窓幅拡大のみでは、初期の極端に短い窓で生じた性能低下を十分回復できない場合がある。三条件を比べると、SWAを一時的に強く遮断してLAへ勾配を流すことが、単なる窓幅の調整より直接的な対策となる。

## 既存研究との差

HedgeHogは注意重み分布の転写を重視し、LAを単独で動作させる。LoLCATsはLAとSWAを混ぜた出力を教師へ合わせ、少量の追加学習で高い総合精度を得る。本論文は両者の目標関数と特徴写像幅を切り分け、LoLCATs型の高精度がLAの成功を意味しないことを成分除去で実証する。HedgeCATsは両方式の長所を組み合わせるが、学習を早く止めなければLAが再び無視される。SSDは窓注意を一時的に落とすことで、LAが学習に寄与せざるを得ない状況を作る。

本研究は通常の注意カーネルの速度比較でも、別のKV圧縮方式の導入でもない。混合注意が本当に長距離経路を利用しているかを診断する評価プロトコルと、成分崩壊を防ぐ訓練方法が寄与である。今後の混合注意のベンチマークでは、総合精度だけでなく枝別除去・長文脈課題・実機速度を組み合わせる必要がある。

## 限界・再現性

第一に、主要評価はゼロショットの常識・知識課題であり、長い文書から遠方の情報を検索する能力を測っていない。LAの容量限界や長文脈での劣化は別途検証が必要である。第二に、混合係数を0.5に固定したため、学習可能・入力依存の混合では別の結果になり得る。第三に、LA-only変換の成否はMistralとLlamaで大きく異なり、全モデルへ同じ学習設定を適用できるとは限らない。

第四に、HedgeCATsは学習の進行によってSWA依存が強まり、混合型が悪化するという失敗条件を持つ。SSDもdropoutと窓幅の組合せに依存し、単に窓を広げれば解決するわけではない。第五に、論文は学習・推論を再現するためのLoLCATs公開実装との関係を説明するが、原著5節の再現性声明では独自コード公開を準備中としており、論文専用コードを既に公開済みと扱えない。GPU型番・速度・ピークメモリの実測比較は主評価では示されないため、理論上の線形計算量を実機での速度改善と同一視しない。
