# Leave No Context Behind: Efficient Infinite Context Transformers with Infini-attention

> Infini-attentionは長文を固定長セグメントへ分け、現在セグメントには通常の局所注意、過去セグメントには固定サイズの圧縮メモリを使う。古い全KVを保存するのではなく、キーと値の外積を再帰的に累積した長期メモリへ問い合わせることで、文脈長が伸びてもメモリ量を一定に保つ。

## 概要

通常Transformerは長い文脈を扱うほど注意計算とKV保存が増える。単純なスライディング窓では古い情報を捨てるため、数十万トークン前の事実を参照できない。

Infini-attentionは一つのTransformerブロック内に、現在セグメントへの因果注意と長期の圧縮メモリ注意を置く。セグメントを処理した後、そのキー・値を固定サイズメモリへ追記ではなく集約し、次セグメントからはそのメモリを線形注意として読む。

1Bモデルでは5K長で微調整した後に最大1MのPasskey Retrievalを解き、8Bモデルでは32Kで微調整して最大500KのBookSumを評価する。長さ方向にKVを保持し続けないことと、長距離情報を完全に切らないことを両立させる。

## 背景と問題設定

### 「保持し続ける」か「捨てる」かの二択を避ける

全注意は過去を高解像度で保持するがコストが増え続ける。有限窓注意はコストを抑えるが窓外を失う。Infini-attentionは古い情報の解像度を落として固定状態へ圧縮する第三の選択肢である。

## 手法

### 1. 入力を固定長セグメントへ分割する

論文の代表設定ではセグメント長2Kを用いる。現在セグメント内は通常のマスク付き注意で処理するため、近距離の正確なトークン関係を保つ。

### 2. 過去セグメントを連想メモリへ圧縮する

処理済みセグメントのキー・値から固定サイズの行列状態を更新する。新しいセグメントが来ても古いトークン数に比例して状態を追加せず、同じメモリへ再帰的に蓄積する。

### 3. 現在クエリで局所注意と長期メモリを同時に読む

現在クエリは現在セグメントの局所KVへ通常注意を行う一方、圧縮メモリへ線形注意として問い合わせる。二つの出力は学習可能なゲートで統合される。

### 4. セグメント終了時にメモリを更新し次へ渡す

推論時は「局所KV + 固定長長期メモリ」だけを次セグメントへ持つ。したがって総文脈が100Kから1Mへ伸びても、過去全KVの保存量は比例増加しない。

## 評価

### 評価条件

| 項目 | 条件 |
|---|---|
| モデル規模 | 1B、8B |
| セグメント長 | 代表設定2K |
| Passkey | 1Bモデル、4K継続事前学習、5K長微調整、最大1Mで評価 |
| BookSum | 8Bモデル、8K継続事前学習、32K微調整、最大500K入力 |
| 生成条件例 | BookSumで最大1024復号ステップ、temperature 0.5、top-p 0.95 |
| 主指標 | Passkeyトークン精度、長文言語モデリング、ROUGE、メモリ増加量 |

### 主な結果

| 観点 | 結果 | 解釈 |
|---|---:|---|
| Passkey Retrieval | **最大1M**文脈を解答 | 微調整長5Kを大幅に超えて検索 |
| BookSum | **最大500K**入力で評価 | 長く入力するほどROUGE改善傾向 |
| メモリ | 長期状態は固定サイズ | 文脈長に比例するKV成長を避ける |
| 学習長外挿 | 4K/5K・8K/32Kから大幅に長い評価長へ | 位置表現だけの長さ拡張とは異なる |

## 既存研究との差

Transformer-XL等のセグメント再利用は過去状態を有限個保持する。スライディング窓は古い状態を捨てる。Infini-attentionは過去を固定サイズの連想メモリへ「圧縮して残す」点が異なる。

## 限界・実装状況

固定サイズメモリは情報の損失圧縮であり、1Mトークンをトークン単位で完全保存するわけではない。Passkeyの単一事実回収と、多数の事実を同時に厳密比較する推論は難しさが異なる。

また、本手法は通常Transformerへ推論時だけ後付けするキャッシュ管理ではなく、Infini-attentionブロックとして学習するモデル設計である。
