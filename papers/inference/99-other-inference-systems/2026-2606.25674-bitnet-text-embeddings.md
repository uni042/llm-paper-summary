# BITEMBED：三値エンコーダと多ビット出力ベクトルを共同最適化する埋め込みモデル

## 概要

テキスト埋め込みの推論コストには二つの異なる要素がある。一つはクエリや文書を埋め込みベクトルへ変換するエンコーダの計算・重みメモリ、もう一つは大量のベクトルを保存・検索する索引のストレージ・帯域である。従来の量子化研究はモデル本体の低ビット化に偏りがちで、ベクトルの保存精度を下げると検索の類似度構造が崩れることもある。

BITEMBEDは、**エンコーダ本体の三値化**と**出力埋め込みベクトルの多精度保存**を一つの学習パイプラインで扱う。Qwen3-0.6BとGemma3-270MをBitNet型の重み三値・活性量子化構造へ変換し、対照学習と教師蒸留で意味表現を回復する。さらに出力ベクトルを1、2、4、8、16ビットで使うことを訓練時から考慮し、同じチェックポイントから異なる保存精度を選べるようにする。

MMTEB英語v2の平均ではQwen3系FP16教師67.95に対してBITEMBED67.60、Gemma3系66.71に対して66.10である。CPU8スレッドのエンコード速度はQwen3系364.36→830.50 token/s、Gemma3系1181.28→2055.47 token/sへ改善する。一方、Qwen3の1ビット出力では平均64.43、検索カテゴリ45.85と、16ビット出力の67.60/54.03より明確に悪化する。**モデルの重み精度と出力ベクトルの保存精度は別の軸**として評価する必要がある。

## 問題設定：エンコーダと索引の二重のコスト

大規模な検索システムでは、文書の埋め込みを事前に計算して索引へ保存し、クエリの埋め込みとの内積やコサイン類似度で候補を探す。エンコーダが大きいと文書登録・クエリ応答が遅く、出力ベクトルが1024次元FP16なら1件あたり少なくとも2048バイトの生ベクトルが必要になる。数千万件を保存すると、ベクトルそのものだけで数十GBに達する。検索索引の構造やメタデータを含めればさらに増える。

重みを単純に三値化すると、生成モデルの次トークン分布だけでなく、埋め込みの相対距離・類似度順位が変わり、検索のnDCG@10が低下する。出力ベクトルを後から1ビットに丸めるだけでも、特に類似度の細かな差が重要な検索で劣化が大きい。著者は、エンコーダ変換後の表現を再学習し、**教師が持つ相対類似度とトークン間の関係**を引き継がせる設計を採用する。

## 手法：重み三値化と教師蒸留

### 1. BitNet型バックボーン変換

Qwen3-0.6BとGemma3-270Mの全精度バックボーンを、重み三値化と活性量子化を用いるBitNet系の線形層へ変換する。低ビット演算はエンコーダの計算量・メモリ帯域を減らせるが、三値化によって正規化・活性分布が変わる。BITEMBEDはSubLNという軽量な正規化補助を追加し、極端な量子化下で表現を安定化させる。SubLNを外すとMMTEB平均が67.60から65.48へ低下し、重要な構成要素であることがアブレーションで確認される。

### 2. 継続対照事前学習

モデルを三値化した直後の埋め込み表現は十分でないため、1Bのテキスト対を用いて継続対照事前学習を行う。正例対の類似度を高め、負例との距離を広げることで、量子化後の表現空間を検索向けに再調整する。これは**重みを後から丸めるだけのPTQではない**。大規模な追加学習データと計算費用を使う点が、推論時に得られる低ビット効率と交換されている。

### 3. 教師付き対照学習と二種類の蒸留

教師付き段階ではBGE-en-ICL由来の学習データを使い、クエリ、タスク指示、正例文書、hard negativeを組み合わせる。クエリ側にタスク指示を付けるinstruction-aware embedding形式で、学習時のhard negativeは7件、バッチサイズ128である。

第一の**類似度分布蒸留**は、教師と生徒が正例・負例集合に対して出す類似度スコアの分布を揃える。単一の正例を正しく選ぶだけでなく、候補間の相対順位・難易度を保持する。第二の**注意関係蒸留**は、Q/K/V投影から作るトークン間の関係分布を教師と生徒で比較し、KL divergenceを最小化する。Qwen3-0.6Bでは18層、Gemma3-270Mでは10層を用いる。全層の注意行列を蒸留するのではなく、選んだ1層の関係を教師信号として使う。

学習損失は対照学習に類似度分布蒸留と注意関係蒸留を加えたもの。論文の設定は温度τ=0.02、類似度蒸留重み0.2、注意蒸留重み10⁴。教師は学習率5e−6、生徒の蒸留SFTは3e−5を用いる。追加学習に依存するため、推論専用のモデル変換器を既存の任意モデルへ無学習で適用できるわけではない。

### 4. 出力埋め込みの多精度共同学習

エンコーダの最終出力ベクトルeについて、保存精度集合R={1,2,4,8,16}を定義する。16ビット枝は元の出力を使い、1ビット枝はベクトル内の最大絶対値による尺度と符号で±1の値を表す。2/4/8ビット枝は同じ尺度を使う均一量子化を行う。各ビット精度で再構成したベクトルの対照学習・類似度蒸留を平均し、注意関係蒸留も加える。こうして同じエンコーダから、索引の容量要件に応じて出力ビット数を選べるようにする。

1ビットは16ビットの**生ベクトル要素の理論的な容量比で16分の1**だが、実際の索引には尺度、ID、メタデータ、ANN構造、アラインメントなどのオーバーヘッドがある。索引全体の実メモリが16分の1になるという実測結果ではない。また出力ベクトルの1ビット化は、三値重みの1.58ビット/重み相当の保存と同じ操作ではない。

## 評価条件

| 項目 | 内容 |
|---|---|
| バックボーン | Qwen3-0.6B、Gemma3-270M |
| 教師 | 同じバックボーンからFP16で教師付き学習した埋め込みモデル |
| 学習データ | 継続事前学習1Bテキスト対、教師付きデータ約210万例 |
| ベンチマーク | MMTEB（eng, v2）：分類、クラスタリング、ペア分類、再ランキング、検索、STS、要約 |
| 評価指標 | 分類accuracy、クラスタリングV-measure、ペア分類AP、再ランキングMAP、検索nDCG@10、STS/要約Spearman等 |
| エンコード速度 | CPU8スレッド、トークン処理速度token/s |
| 出力保存精度 | 1/2/4/8/16ビット、Qwen3系は1024次元 |

各カテゴリは異なる指標で採点される。MMTEBのAvgはベンチマーク定義に沿う集計値で、単純な分類正答率ではない。FP16教師は同じバックボーン・同じSFTデータを使っており、別の巨大な専用埋め込みモデルと比較したランキングではない。したがって「既存の全埋め込みモデルに匹敵する」という一般化はできない。

## 主要結果：精度とCPU速度

| バックボーン | FP16教師 MMTEB平均 | BITEMBED MMTEB平均 | 教師 CPU token/s | BITEMBED CPU token/s | 速度比 |
|---|---:|---:|---:|---:|---:|
| Qwen3-0.6B | 67.95 | 67.60 | 364.36 | 830.50 | 約2.28倍 |
| Gemma3-270M | 66.71 | 66.10 | 1181.28 | 2055.47 | 約1.74倍 |

原著Table 1。Qwen3系は0.35ポイント、Gemma3系は0.61ポイントの平均低下で、CPUトークン処理速度は改善した。これは**CPU8スレッドのエンコーダtoken/s**であり、検索システム全体のQPS、ANN検索時間、GPUでのエンコード速度を測ったものではない。ベクトル索引への追加・更新・検索のコストも含まない。

カテゴリ別に見ると、Qwen3系の検索nDCG@10は教師55.34、BITEMBED54.03で1.31ポイント悪化する。クラスタリングは55.48対55.42でほぼ同じ、STSは81.15対81.15で同値、分類は86.37対86.49と微増する。Gemma3系では検索52.97対51.47で1.50ポイント低下する一方、要約カテゴリは28.36対32.97と改善する。平均だけでなく用途別の劣化を評価する必要がある。

## 評価結果：出力ビット数ごとの品質

| Qwen3系出力精度 | MMTEB平均 | 検索nDCG@10 | 16ビットに対する生ベクトル容量 |
|---|---:|---:|---:|
| 16bit | 67.60 | 54.03 | 100% |
| 8bit | 67.55 | 54.03 | 50% |
| 4bit | 67.45 | 53.86 | 25% |
| 2bit | 64.90 | 47.17 | 12.5% |
| 1bit | 64.43 | 45.85 | 6.25% |

原著Appendix Table 7。8/4ビットでは平均性能の低下が小さい一方、1/2ビットでは検索性能が明確に悪化する。Gemma3系でも16bit平均66.10、4bit65.96、2bit63.24、1bit63.01となり、同じ傾向がある。したがって「1ビットで教師と同じ検索精度」という表現は誤りで、**4～8ビットが精度と保存容量の折衷点**になりやすい。

多精度共同学習をせず、16ビット出力を後から量子化するPost方式との比較では、Qwen3系1bit平均64.43対63.71、2bit64.90対64.03、4bit67.45対66.31となる。検索カテゴリの差は1bitで45.85対43.21（+2.64）、2bitで47.17対44.07（+3.10）である。これは量子化を訓練時に考慮することの効果であり、単純な後処理のビット丸めだけでは同じ品質を得られない。

## アブレーション：追加学習と蒸留の寄与

| Qwen3-0.6B、16bit出力 | MMTEB平均 | 完全版からの低下 |
|---|---:|---:|
| BITEMBED完全版 | 67.60 | 0 |
| SubLNなし | 65.48 | −2.12 |
| 注意関係蒸留なし | 66.49 | −1.11 |
| 類似度分布蒸留なし | 66.37 | −1.23 |
| 両蒸留なし | 64.76 | −2.84 |
| 継続対照事前学習なし | 64.77 | −2.83 |
| 三値変換後の単純SFTのみ | 58.92 | −8.68 |

原著Table 2。SubLN、継続対照事前学習、2種類の蒸留がそれぞれ寄与する。とくに三値化後に単純な教師付きSFTだけを行うと平均58.92まで低下し、**三値重みだけで精度を保てたわけではない**。低ビットモデルの性能回復には大規模な対照学習と教師の構造的な情報が重要である。

Matryoshka Representation Learning（MRL）との比較では、同じ保存予算でBITEMBEDが多くの条件で優れるが、**1/8容量の条件ではMRLが0.44ポイント上回る**という負の結果もある。出力ビット数の調整と、埋め込み次元を切り詰める方式の優劣は予算・用途によって変わる。出力ベクトルの全次元を残して各次元を低ビット化する方式が、すべてのストレージ条件で最良とは限らない。

## 限界：既存研究との差

BitNetやBitNet b1.58は主に生成モデルの重み・演算を低ビット化する。一方BITEMBEDは検索・分類・類似度評価に必要な**相対的な埋め込み空間の構造**を守るため、対照学習と類似度分布・注意関係蒸留を追加する。単なるモデルのW1.58量子化だけでなく、出力ベクトルの保存精度まで共同最適化する点が特徴である。

ただし、本方式は無学習PTQではない。1Bのテキスト対による継続学習と210万例の教師付きデータが必要で、学習計算・データ整備・教師モデル維持の費用を伴う。教師と同じバックボーンでの比較であり、全埋め込みモデルの精度順位を示すものではない。CPU8スレッドのエンコード速度が改善しても、GPU、ARM CPU、NPU、特定の検索サーバで同じ倍率になるとは限らない。

さらに、1/2ビット出力は検索性能の低下が大きい。16倍の生ベクトル容量削減は、索引全体のメモリや検索時間の16倍改善ではない。ANN索引では距離計算の実装、量子化コードの復元、メタデータ、グラフ構造、キャッシュ効率が別途効く。1ビットベクトルで内積を高速化できるかどうかも、専用カーネルの有無による。

MMTEB（eng, v2）での結果は主に英語タスクであり、多言語の一部評価があっても、すべての言語・ドメインに一般化できない。高精度が必要な法律・医療検索、固有名詞や識別子の完全一致、長文検索、RAGの最終回答品質は別途評価すべきである。三値化と出力量子化の誤差が組み合わさる場合、平均スコアが近くても個別の難しいクエリで順位が変わり得る。

実用上は、モデルのエンコード処理がCPU律速で、かつ大量の文書ベクトルを保存する用途に適する。まず4/8ビット出力で検索nDCG@10と索引容量を測り、さらに強い圧縮が必要な場合だけ1/2ビットを検討するのが合理的である。エンコーダの低ビット化と出力ベクトルの低ビット化を分離して測定することで、どちらが性能低下や速度改善を生んだか判断できる。
