# Out of the Memory Barrier: A Highly Memory Efficient Training System for LLMs with Million-Token Contexts

> チャンク再計算・ページ化KV/勾配・非同期CPUオフロード・疎注意を統合し、Qwen2.5-7Bの4M文脈学習を単一H200で実現する。
## 書誌情報
- **著者**: Wenhao Li, Daohai Yu, Gen Luo, Yuxin Zhang, Fei Chao, Rongrong Ji, Yifan Wu, Jiaxin Liu, Ziyang Gong, Zimu Liao
- **著者・所属**: Xiamen University; Peking University; University of Illinois Urbana-Champaign; Shanghai Jiao Tong University; Shanghai AI Laboratory
- **公開**: arXiv
- **種別**: プレプリント
- **対象**: 長文脈学習、CPUオフロード、ページ化KVキャッシュ、疎注意、活性化再計算
- **実装**: Triton/CUDAカーネル、固定ページ管理、pinned CPU メモリ、専用CUDA ストリームを用いる公開研究実装。
## 概要
OOMBは長文脈LLM学習で系列長に比例して増える活性化メモリを、チャンク再帰型処理とオンザフライ再計算によりO(1)へ抑え、残るKVキャッシュと勾配の増大をページ化管理、非同期CPUオフロード、ページ単位疎注意で処理する学習システムである。Qwen2.5-7Bでは文脈10Kトークン追加あたり学習メモリ増加を約10MBに抑え、単一H200で4M文脈学習を可能にした。

OOMBの新規性は、チャンク再帰型学習だけでなく、学習時のKVキャッシュとその勾配を推論用PagedAttentionに類似した固定ページへ載せ、PyTorch autograd外の専用カーネルで前向き・後ろ向きと勾配加算を直接実行する点にある。その上で、GPUに残る系列長依存状態をCPUへ非同期退避し、密注意・局所注意では次層ページを先読みし、検索型疎注意ではquery射影後に必要ページを決めてK/V射影と転送を重ねる。ページ単位Top-K疎注意も同じページ管理上へ統合するため、計算量削減とCPU-GPU転送量削減が同時に効く。SeCOのチャンク学習を、演算子・ページ管理・オフロード・疎注意まで共同設計した実用システムへ拡張した位置付けである。

代表結果として、長文脈メモリ増加率はCPU オフロードを含む構成でQwen2.5-7B OOMB エンドツーエンド trainingに対して約10MB / 追加10K トークン。系列長依存状態の大部分をCPUへ移し、GPU上の増分を極小化する。
## 問題設定
LLMの長文脈継続学習では、モデル重みや最適化状態だけでなく各トークンに対応する活性化と注意用KV状態が系列長に比例して増える。FlashAttentionや通常の勾配チェックポイントを用いても、単一GPUでは32K程度から活性化メモリが支配的になり、文脈並列は複数GPUと高帯域通信を必要とする。長文脈能力の獲得自体は比較的少ない学習ステップで済む場合があるため、著者らは最大スループットよりも限られた装置で一つの極端に長い系列を学習可能にすることを主目的に置く。チャンク単位で直列化すれば活性化を捨てて再計算できるが、その場合は過去チャンクのKVキャッシュと、その逆伝播勾配が新しい線形メモリ障壁になる。さらに単純なtensor concatでは再確保・コピー・断片化が生じ、理論必要量の約3倍まで膨らみ得る。
## 新規性

## 手法
### 手法のあらまし
OOMBの処理は、長い学習系列を固定長チャンクへ分けて順番に前向き計算するところから始まる。チャンクiは現在チャンクのトークンだけを新たに計算する一方、注意ではチャンク1からi-1までに生成済みのkey/valueを参照するため、モデルから見れば通常のcausal Transformerと同じ過去文脈を利用できる。通常学習なら各チャンクの中間活性化を逆伝播まで全て保持するが、OOMBはチャンクの前向き終了時にその活性化を捨て、逆伝播がそのチャンクへ到達した時だけ同じ前向きを再実行して必要な活性化を復元する。したがってGPU上に同時に存在する通常活性化は基本的に一チャンク分となり、系列全長Nに対する活性化メモリ増加をO(1)へ変える。ただし過去トークンのKVと、後ろ向きでそこへ流れるdKVは系列全体にわたって必要なので、次にこれらを固定サイズpageへ分割する。page tableで論理トークン位置と物理pageを対応付け、追加KVを既存tensorへconcatせず空きpageへ書く。専用Triton/CUDA演算子はこのpaged layoutを直接読み、注意のforwardとbackwardを実行し、dKVはatomic_addでpageへin-place累積する。KV/dKVをPyTorch autograd graphの通常tensorとして追跡させないことで、中間バッファと不要な保持も避ける。系列がさらに長くなりGPU page容量を超える場合、KV/dKV pageの主保持先をpinned CPU メモリへ移す。密注意と局所注意では次に必要な層のpageが事前に分かるため、層i-1のGPU計算中に層iのpageを専用CUDA ストリームとDMAでプリフェッチし、backwardでも対称に重ねる。Top-K疎注意ではqueryができるまで必要pageが確定しないため、query projection直後に各key page代表ベクトルとの類似度を計算してpageを選び、選択pageの転送をK/V projectionと並行させる。forwardで選んだpage indexはbackwardへ保存し、backward側では通常プリフェッチと同様に先読みする。このように活性化再計算でGPU常駐活性化を固定し、paged KV/dKVで断片化を除き、CPU オフロードで系列長依存状態を容量の大きいホスト メモリへ逃がし、必要ならsparse attentionでGPUへ戻すpage数と注意計算量そのものを減らす、という順にボトルネックを一段ずつ解消するのがエンドツーエンド機構である。

### チャンク再帰型学習と活性化再計算
入力系列を例えば4K程度の固定長チャンクへ分け、チャンク内部はGPU上で通常どおり並列計算しつつ、チャンク間だけを時系列に処理する。チャンクiのforwardはそれ以前の全チャンクが生成したKVを参照するのでcausalな長文脈依存は維持されるが、forward終了後にattentionやMLP等の中間活性化を保持し続けない。backwardがチャンクiへ到達した時点で、そのチャンクのforwardを同じKV状態から再計算して活性値を復元し、勾配を求めたら再び解放する。通常の層 checkpointingでは系列全体に対応するcheckpointや状態が増えるのに対し、この方式では同時に必要な活性値量が一チャンク分で決まり、全系列長Nに対してO(1)となる。代償は各チャンクのforward再計算と、全系列を一括処理する方式より低い並列性である。OOMBは長文脈fine-tuningでは学習step数よりメモリ到達性が支配的という前提から、この計算対メモリ交換を積極的に選ぶ。

### 学習対応ページ化KVキャッシュと勾配管理
活性値を固定化すると、全過去トークンについて残す必要があるKV キャッシュと、そのbackward gradientであるdKVが次の線形メモリ要因になる。OOMBは推論用PagedAttentionの考え方を学習へ拡張し、KVとdKVを固定サイズpageへ分割してpage tableで管理する。新しいチャンクのKVは巨大tensorを再確保してconcatするのではなく空きpageへ直接追記するため、コピーとallocator fragmentationを抑える。既存paged attentionは通常backwardを持たないため、著者らはTriton/CUDAの専用カーネルを実装し、paged layoutのままattention forward/backwardを行う。gradientはatomic_addで対応pageへin-placeに累積し、余分な一時gradient バッファを作らない。さらにKVをPyTorch autogradからopaqueな外部状態として扱うことで、frameworkがKVを活性値として保存したり複雑なgraphを構築したりすることを防ぐ。このpage粒度は後段のCPU オフロードとsparse page selectionの共通単位にもなり、単なる断片化対策以上に全システムの基盤となる。

### 注意型別の非同期CPUオフロード
paged KV/dKV自体は依然として系列長に比例するため、百万トークン級ではGPU HBMだけに置けない。OOMBは使用していないpageをpinned CPU メモリへ置き、必要になる直前にGPUへ戻す。密注意やlocal attentionでは層ごとに次に読むKV集合が決まっているため、現在層 i-1のattention/MLP等をGPUが計算している間に、専用CUDA ストリームで層 iのpageを非同期プリフェッチする。backwardでも次に必要な層を予測して同じパイプラインを逆方向に構成する。転送はDMA engineへ任せ、compute ストリームとの重畳でPCIe等の待ち時間を隠す。検索型sparse attentionでは必要pageがquery内容に依存するので事前プリフェッチできないが、query projectionが終わった直後にpage retrievalを開始し、選択された少量pageのDMAをその後のkey/value projectionと重ねる。forwardで選択indexを保存しておけばbackward時には必要pageが既知となり、通常のプリフェッチへ戻せる。論文ではdense/localのオフロード エンドツーエンド オーバーヘッドを5%未満とし、オフロード構成では文脈増加に対するpeak GPU メモリをほぼ一定に保つ。

### ページ単位Top-K疎注意
dense attentionはメモリをオフロードできても計算量が系列長の二乗で増えるため、OOMBは同じpaged layout上にpage-level sparse attentionを追加する。Qwen2.5のようなdense-attention modelでは各key page内のkeyを平均して代表ベクトルK_avgを作り、現在query chunkの各トークンとの類似度を計算する。softmaxしたscoreをquery page単位で集約する投票により関連key pageを選び、そのpageだけを実際のattention対象としてGPUへ転送する。forwardで選んだpage indexをbackwardでも再利用するため、gradient計算でも同じ疎構造を使える。page size 128のH200ではretrieval オーバーヘッドは小さいと報告される。GPT-OSSのようにdense 層とlocal 層が混在する場合、dense 層は同じTop-K page retrieval、local 層は直近pageだけを取得する。これによりattention FLOPsだけでなくCPUからGPUへ戻すKV量も同時に減り、長い系列ほどdense版に対する速度差が広がる。ただしこれはfull attentionの近似なので、OOMBはdense版も残し、精度近似なしのメモリ最適化と、追加高速化を狙うsparse版を分離して評価する。

### 全体のデータ／制御の流れ
OOMBは一つの最適化で長文脈学習を解くのではなく、最初に活性値 recomputationで系列長依存活性値を消し、その結果顕在化したKV/dKVをpaged メモリへ変換し、pageをCPU階層メモリへ非同期退避し、さらに必要に応じてpage-level sparse attentionで転送・計算対象を削る。専用カーネルがautograd外でpaged KVとgradientを管理するため、PyTorch側は一チャンク分の通常計算graphに集中できる。CPU側は大容量の長期KV/dKV保持層、GPU側は現在チャンクと直近にプリフェッチされたpageの高速計算層として役割分担する。pageという共通粒度をメモリ allocation、オフロード、sparse retrieval、backward gradient accumulationの全工程で共有するため、それぞれの機構が相互に接続され、単独適用よりも大きな長文脈到達性を得る共同設計になっている。
## 評価条件
- **ハードウェア**: 主評価はNVIDIA H200。単一H200でQwen2.5-7Bの8K〜256K効率・メモリを測定し、4×H200テンソル並列で256K/1Mの疎注意学習と最大8Mのスケーラビリティを評価する。チャンクサイズablationには単一A100 80GBも使用。Ring Flash Attention比較は4×H200等を含む。
- **ソフトウェア**: Qwen2.5-7B、bfloat16全パラメータ微調整、Adam (lr 5e-5, betas 0.9/0.98)、per-GPU バッチ size 1。OOMBはTriton/CUDAのページ化注意・逆伝播、pinned CPU メモリとCUDA ストリームによるオフロード、Top-Kページ疎注意を実装。比較対象はFlashAttention+層 gradient checkpointingとRing Flash Attention。
arXivデータを連結して指定文脈長を作り、ピークGPUメモリをPyTorch max_メモリ_allocated()、反復遅延をCUDA eventsで測定し、3回独立実行の最小値を報告する。8K〜256Kでチャンクサイズ4K/8K/12K、疎注意budget、checkpoint、CPU オフロードをablationする。文脈並列とはdevice当たりトークン/sで比較する。疎注意の品質は16K〜1Mでdense attentionに対する勾配近似誤差とlossを測定し、256K/1Mで実際の学習曲線を確認する。
主にQwen2.5-7Bの長文脈継続学習システム効率を検証する。4M単一H200の到達可能性と4×H200で8Mまでのスケーラビリティを示す一方、下流長文脈ベンチマークでの最終能力、より大規模な密モデル/MoEの広範な品質評価、CPU-GPU帯域が低い環境での一般化は限定的である。
## 主要結果
OOMBは活性化再計算とKV/dKVのページ化・CPUオフロードにより、Qwen2.5-7Bで文脈長に対するGPUメモリ増加をほぼ平坦化した。著者は追加10Kトークンあたり約10MBの学習メモリ増加を報告し、単一H200で4M文脈を学習可能とする。64K以上では疎注意が大きな速度向上を示し、256Kでは最大約13.5倍の高速化を報告する。4×H200では1M文脈256 stepを約10時間で学習し、追加実験では8M文脈まで動作を示す。

- 長文脈メモリ増加率 / 約10MB / 追加10K トークン (比較対象: Qwen2.5-7B OOMB エンドツーエンド training; 条件: CPU オフロードを含む構成) — 系列長依存状態の大部分をCPUへ移し、GPU上の増分を極小化する。

- 最大単一GPU文脈 / 4M トークン (比較対象: 従来の単一GPU長文脈学習; 条件: Qwen2.5-7B, 1×H200) — 著者らが比較する文脈並列の大規模クラスタ依存を避ける。

- 疎注意速度向上 / 約3.7× at 64K、最大13.5× at 256K (比較対象: dense/parallel training 比較対象; 条件: 長文脈でpage-level sparse attention) — ページ検索で注意計算量とCPU-GPU転送量を同時に削減する効果が文脈長とともに増える。

- 256K device スループット / OOMB dense 266.13 tok/s、sparse 1301.60 tok/s (比較対象: 4×H200 RFA 218.41 tok/s per device; 条件: OOMB 1×H200、4K chunk、checkpoint+CPU オフロード、sparse budget 8192) — 単一H200でもRFAのdevice当たり処理量を上回り、疎注意では差が大きい。

- 1M学習実行 / 256 stepsを約10時間 (比較対象: なし; 条件: 4×H200 TP、sparse attention; 4K+8192では176.305 s/iter・67944MB/device) — 百万トークン級で単なるメモリ到達性だけでなく継続学習を実行可能である。

### 負の結果・境界条件
- チャンク直列化には完全並列学習に対する遅延上の代償がある。疎注意は密注意の近似で、1Mでは大きい32K retrieval budgetでも学習後半に軽微な不安定性が観測された。疎注意lossは1Mでdense 4.3125に対し4K+8192が4.71875、4K+32768が4.78125であり、極端な長さで近似が常に無損失とは言えない。オフロード性能はCPU-GPU接続帯域に依存する。

### 結果の読み方
OOMBの中心的成果は『活性化をO(1)にする』だけでなく、その結果支配的になるKV/dKVを学習向けページ管理と階層メモリへ再設計した点にある。密注意版は精度近似なしでメモリ効率を改善し、疎注意版はさらに計算・通信を削る代わりに近似誤差を受け入れる二段階の設計空間を提供する。
## 品質への影響
密注意構成は注意を近似しない。疎注意構成はTop-Kページ選択により勾配とlossへ近似誤差を導入するが、256Kでは8K/32K budgetの学習曲線がほぼ一致しloss<1.2へ収束した。1Mでは収束するものの軽微な不安定性とdenseとの差が残る。
## 既存研究との差
Ring Attention/Ring Flash AttentionやDeepSpeed Ulyssesは系列を複数装置へ並列分割してGPUメモリを増やすのに対し、OOMBは一つの系列をチャンク直列化し、活性化を再計算して単一装置でも扱えるようにする。SeCOもチャンク学習でO(1)活性化を狙うが、OOMBは学習時KV勾配まで扱うページ管理、autograd外専用カーネル、非同期CPUオフロード、ページ疎注意を統合し、単一GPUでの到達文脈を大幅に伸ばす。PagedAttention系の推論研究とは、同じページ化思想を逆伝播とdKVへ拡張した点が異なる。通常の活性値 checkpointingは層内活性化を再計算しても系列長に比例する状態を残すが、OOMBはチャンク単位で全系列活性化保持を避ける。
## 限界
チャンク間を直列処理するため、十分なGPU群を使える完全並列・文脈並列方式に対して遅延面の不利が残る。CPUオフロードはPCIe/NVLink等のCPU-GPU実効帯域に依存し、低帯域環境では計算との重畳が崩れる可能性がある。Top-Kページ疎注意は密注意を近似するため、密な大域依存を必要とする下流タスクへの影響は十分検証されていない。品質検証は主にlossと勾配近似誤差で、長文脈推論ベンチマークの最終能力評価は限定的である。主要な詳細評価がQwen2.5-7B中心であり、より大規模なモデルや異なる注意構造への一般性は今後の課題である。
## 実装状態
公式コードがGitHubのwenhaoli-xmu/OOMBで公開されている。論文はv4 (2026-03-01) のarXivプレプリント。Triton/CUDAカーネル、pinned CPU メモリ、専用CUDA ストリームを用いた実システムとしてH200/A100で評価されている。
## 研究上の位置づけ
階層メモリを用いたLLM学習の中でも、CPUを単なる重み・optimizer オフロード先ではなく、系列長とともに増えるKV/dKVの主保持層として使う点が重要である。推論で成熟したページ化KV管理と非同期プリフェッチを長文脈学習へ持ち込み、活性値 recomputationと疎注意を同じページ粒度へ統合したため、オフロード、長文脈訓練、疎注意、メモリ管理の系統を横断する研究として位置付けられる。
