# 推論時計算の最適配分：探索・自己修正と事前学習の計算量交換

## 概要

本論文は、大規模言語モデル（LLM）の推論時に追加の計算予算を与える場合、その予算を**何回の独立サンプリング、何段の探索、何回の逐次自己修正**へ割り当てるべきかを分析する。単純に候補回答をN個作って最良を選ぶbest-of-N方式に対し、問題難易度を考慮した計算配分が、同じ計算予算で高い正答率を実現できると示す。

対象は主にMATH数学問題集とPaLM 2-S*モデルである。研究は二つの経路を扱う。一つは、途中の推論手順を評価する工程報酬モデル（process reward model、PRM）を使って候補解を探索する経路。もう一つは、モデルが前の解答を参照して修正案を逐次生成する経路である。両者とも問題の難易度によって有効な計算の使い方が異なる。難易度に応じて方式を選ぶと、条件によってbest-of-Nに対して約4分の1の生成予算で同等以上の正答率に達する。

さらに、小型モデルの推論時追加計算と、約14倍大きいモデルの事前学習を浮動小数点演算回数（FLOPs）で揃えて比較する。容易・中程度の問題や推論要求量の少ない条件では小型モデルの推論時計算が有利になり得る。一方、最難問や推論要求量が多い条件では大きなモデルの事前学習に計算を回した方がよい。**推論時に計算を増やせば、どんな条件でもモデル規模を置き換えられる**という主張ではない。

## 背景：同じ追加計算でも使い方が異なる

通常のbest-of-Nは、元のモデルから独立にN個の回答を生成し、採点器・検証器が最も有望なものを選ぶ。候補を増やせば正答を含む確率は上がるが、候補の選別器が誤った特徴を高く評価する場合、増やした計算が必ずしも正答率の向上に結び付かない。難問では、そもそも元のモデルが正しい方針をほとんど提案できないこともある。

別の使い方として、工程報酬モデルで部分的な解法を評価しながら木探索する方法がある。途中の段階で見込みのある経路へ計算を集中させるため、正答に至るまでの無駄な候補生成を減らせる可能性がある。ただし、報酬モデルの誤りを繰り返し最適化すると、見かけ上高得点でも無意味な解法へ偏ることがある。

さらに、前の回答をコンテキストへ含め、同じモデルが誤りを修正する逐次自己修正がある。初回回答が正解に近いときは有効だが、そもそも別の方針が必要な問題では独立候補を並列に探索する方がよい場合がある。本論文はこれらの差を、**問題固有の難易度と利用可能な計算予算**の関数として捉える。

## 手法

### 工程報酬モデルの学習と集約

工程報酬モデル（PRM）は、回答全体の最終正誤だけでなく、解答の各途中段階から最終正答に到達できる見込みを推定する。論文はPRM800Kの人手ラベルをそのまま使うのではなく、対象のPaLM 2モデルの出力分布に合うよう、各途中段階からモンテカルロ展開を行い、将来の正答可能性を教師信号としてPRMを学習する。既存の他モデルの解法で学習したPRMをそのまま使うと、分布ずれによって容易に報酬を悪用できたことが動機である。

複数段階のPRMスコアを回答全体へまとめる方法も比較した。積や最小値ではなく、最後の段階におけるPRMの予測を解全体のスコアとする方式が良好だった。複数の回答が同じ最終答えへ到達した場合には、その最終答えに対応する候補の検証スコアを合算する重み付きbest-of-Nを使う。これにより、候補の表面上の言い回しではなく、同じ答えへ集まる証拠をまとめて扱う。

### 独立候補、ビーム探索、先読み探索

比較した方式は、独立にN個の回答を作るbest-of-N、各段階でPRMのスコアが高い部分解を残すビーム探索（beam search）、さらに先読み展開で部分解を評価する先読み探索（lookahead search）である。ビーム探索では、ある段階でN個の部分候補を採点し、上位の候補を残して次のステップを展開する。論文ではビーム幅を4または√Nに設定し、最大40ラウンドまで展開する。

先読み探索は、現段階のPRMスコアだけでなく、そこから1段または3段先へ展開した結果を使って候補を評価する。先読みが深いほど追加計算が必要なので、論文は先読みk段の費用を概ね`N×(k+1)`相当の生成予算として換算する。**候補数が同じだから同じ計算費用**とする比較はしていない。

結果は単調ではない。小さい生成予算ではビーム探索がbest-of-Nより良いが、予算を増やすと改善が頭打ちになり、best-of-Nを下回る場合がある。先読み探索は、PRMの誤った好みを強く最適化してしまい、低情報量の反復ステップや1〜2段だけの短すぎる解答を選びやすく、同一予算では概して不利だった。探索を深くすること自体が品質向上の保証ではない。

### 難易度に応じた方式の選択

論文は問題難易度を5つの階層に分け、各階層で良い方式を選ぶ。難易度の理想的な定義は、各問題で2048個の回答を生成したときの正答率pass@1に基づくもので、これは正解ラベルを必要とする「神託難易度」である。実運用では正解を知らないため、同じ2048サンプルのPRMによる最終回答スコアから難易度を推定する「予測難易度」も試す。

容易な問題（難易度1〜2）では、ビーム探索を強くするとPRMの誤った評価基準を増幅し、正答率が下がることがある。中程度の難問（3〜4）では、ビーム探索がbest-of-Nより良い場合がある。最難問（5）では、どの探索法でも改善が小さい。方式の最適性は、難易度の単純な昇順で決まるのではなく、モデルが正しい候補を提案できるかとPRMが有効に識別できるかに依存する。

難易度別に探索方式を選ぶと、低予算領域ではbest-of-Nの64生成相当に近い正答率を16生成相当で達成できる例があり、**約4倍の生成予算効率**が得られる。図4の比較は「4倍のトークン毎秒」という推論エンジン速度の実測ではない。候補の生成予算を同等品質へ達するためにどれだけ節約できたかを表す。

### 手法2：逐次自己修正と並列探索の配分

### 自己修正モデルの訓練

一般的なLLMに「前の解答を見て修正せよ」と指示するだけでは、数学推論の品質は必ずしも改善しない。著者は自己修正に特化したモデルを追加学習した。訓練例は、誤答の後に正答が続く軌跡であり、モデルが前の解答の誤りを修正するように学習する。

実装上は、元のモデルから高温で64個の回答を独立に生成し、正しい回答と複数の誤った回答を後処理で組み合わせて疑似的な多ターン修正軌跡を作る。誤答は正答と編集距離が近いものを優先して選び、完全に無関係な解答を修正するより、部分的に正しい解答を改善する学習信号を作る。訓練時には直前の誤答を最大4件まで文脈に含め、推論時にそれ以上の修正を続ける場合は直近4件だけを保持する。

### 逐次修正と独立サンプリングの混合

同じN回の候補生成予算でも、N個の回答をすべて独立に生成する方式、最初の回答を繰り返し修正する方式、複数の独立系列を作って各系列を順番に修正する方式がある。独立サンプリングは大きく異なる解法を探索しやすく、逐次修正は既存の解法を局所的に改善しやすい。

容易な問題では初回回答が正解に近いため、予算の多くを逐次修正に回す方が良い。難しい問題では異なる解法を並列に探索する必要があるので、逐次と並列を混ぜる方が良い場合がある。図7では計算予算が大きくなると、単純な完全逐次または完全並列より、中間の比率が有利になる条件を示す。

問題難易度に応じて逐次と並列の比率を選ぶと、図8では通常のbest-of-Nが256個の候補を使う場合と比べ、64個相当の生成予算で同等以上の正答率を得る条件がある。これも**生成回数に換算した効率**であり、GPU実行時間や電力が厳密に4分の1になったという測定ではない。

## 評価

| 項目 | 論文の設定・結果 |

| 主要モデル | PaLM 2-S*（Codey）を数学推論・自己修正・検証向けに追加学習 |
| データセット | MATH、訓練約12,000問、評価500問 |
| 難易度階層 | モデルの正答可能性に基づく5階層 |
| 難易度推定 | 問題当たり2048サンプルによる正答率またはPRMスコア |
| 探索予算 | 最大256生成相当、ビーム幅4または√N、先読み1/3段 |
| 探索の効率 | 例：16生成相当でbest-of-Nの64生成相当へ近い性能 |
| 自己修正の効率 | 例：64生成相当でbest-of-Nの256生成相当を上回る条件 |
| 比較するモデル規模 | 約14倍大きい事前学習済みモデル |
| 事前学習・推論比 | 推論トークン/事前学習トークン比Rを0.16、0.79、22で比較 |

実験は工程報酬モデルや自己修正モデルを別途学習した上で行っている。汎用モデルの重みを変更せずに、単純に推論回数を増やしただけでこの結果が得られるわけではない。難易度階層を得るための2048サンプルの追加費用は、主要な計算予算比較から除外されている点も重要である。

## 事前学習計算と推論時計算の交換

著者は、パラメータ数N、事前学習トークン数D_pretrain、推論トークン数D_inferenceに対し、事前学習費用を概算`6N D_pretrain`、通常の推論費用を`2N D_inference`のFLOPsで近似する。モデルを約14倍大きくする場合と、小さいモデルのまま追加の探索・修正を行う場合の総計算を揃えて比較する。

重要な変数は`R = D_inference / D_pretrain`である。推論するトークン数が事前学習トークン数に比べて小さいなら、モデルを大きくするための事前学習費用を、比較的少ない推論要求へ振り替えることができる。一方、大量の利用者が長期間モデルを使い、推論トークン数が膨大になると、毎回の追加推論費用が積み重なり、大きいモデルを一度学習して効率よく使う方が有利になる場合がある。

原著はR=0.16、0.79、22を比較する。容易・中程度の問題でRが小さい条件では、推論時の探索・修正が約14倍のモデル規模拡大を上回る場合がある。難しい問題やRが大きい条件では、追加事前学習へ計算を回す方が良い。これは**事前学習と推論の総FLOPsを揃えた比較**であり、個別の問い合わせに対する応答遅延が小型モデルで短くなるという意味ではない。推論時に多数の候補を生成するなら、ユーザーが待つ時間はむしろ長くなり得る。

## 限界

第一に、実験はMATHとPaLM 2-S*に集中している。数学問題では正答を検証しやすいが、自由形式の文章作成や実世界の曖昧な判断へそのまま移せるとは限らない。第二に、工程報酬モデルは探索によって悪用される可能性があり、探索深度を増やすほど品質が上がるという前提は成立しない。第三に、自己修正モデルは特別な訓練を要し、既存モデルへのプロンプト追加だけでは同等の結果を期待できない。

第四に、難易度推定の費用が主要比較へ十分に計上されていない。2048候補を作って難易度を判定する方式をそのまま本番運用すれば、難易度推定自体が大きな計算負担になる。低コストな難易度推定器を開発し、探索に使う予算との配分を一緒に最適化する必要がある。第五に、生成回数で正規化した比較は、KVキャッシュ、並列処理、バッチ処理、検証器の実装差を含む実測GPU時間とは異なる。

第六に、推論時の計算は精度向上のために費やすものであり、単一トークンのデコード速度を上げる手法ではない。低遅延サービングや限られたGPUメモリでの実装を考える際には、正答率、平均・末尾遅延、総処理量、追加計算費用を別々に測る必要がある。第七に、最難問ではどの方式も改善が小さいため、単純に予算を追加しても解決能力の不足を補えない。

## 技術的意義

この論文は、LLMの推論時追加計算を一つの固定手法として扱わず、**問題の難易度に応じて「探索する」「修正する」「追加計算を使わない」を切り替える資源配分問題**として定式化した。推論時の計算とモデルの事前学習規模の交換を、利用頻度Rと問題難易度の両方で考える点も重要である。

実運用へ応用するなら、まず問題難易度を安価に推定し、検証器が信頼できる条件と自己修正が有効な条件を測り、予算別に方式を選ぶルータを設計する必要がある。長期的には、探索・修正で得た良質な回答を再びモデルへ蒸留する方法が考えられるが、本論文でその継続学習ループの有効性まで実証したわけではない。
