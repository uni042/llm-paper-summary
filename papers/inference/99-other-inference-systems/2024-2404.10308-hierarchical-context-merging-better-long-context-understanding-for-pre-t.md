# HOMER：階層的文脈統合による長文入力の省メモリ推論

## 概要

既存の大規模言語モデルは、学習時の文脈長を超える入力を処理すると位置表現が外挿領域に入り、回答精度が低下する。回転位置埋込み（RoPE）の尺度を変更する位置補間やYaRNは、長文への適応を容易にするが、入力全体を同時に自己注意へ渡す場合の計算量やKVキャッシュ容量は原理的には削減しない。逆に長文を短い区間へ完全に分割すると、各区間は互いの情報を参照できず、質問に必要な離れた文脈を結合しにくくなる。

HOMER（Hierarchical cOntext MERging）は、入力を小区間に分けて初期層を処理し、中間層へ進むにつれて隣接区間を統合する。統合前に不要なトークンを削減するため、上層の系列長が無制限に増えない。さらに、上層で残すと決めたトークンを下層の埋込みにも反映する「伝播的精錬」と、二分木を深さ優先に処理する計算順序を組み合わせる。事前学習済みモデルの追加学習は不要である。

ICLR 2024の原著では、Llama-2-13B-chatの32Kトークンにおけるパスキー検索正答率が80.4%、位置尺度変更方式との併用で86.0%だった。単一A100 GPUで64K入力を処理する際のピークメモリはHOMER単独で21.3GB、通常方式は80GBを超え実測実行できなかった。これは位置埋込みの外挿と、系列処理時のメモリ効率を同時に扱う設計の効果である。なお32K検索正答率はモデル規模と併用方式によって異なり、すべてのモデルで80.4%となるわけではない。

## 問題設定

通常の自己注意は、入力長が長くなるほど各トークンが参照する候補が増える。長文の事前充填では注意の演算量と中間状態が増え、推論時のKVキャッシュも長くなる。RoPEの位置尺度変更は位置番号の外挿を助けるが、全トークンを保持する構造自体は変えない。論文が比較する位置補間（PI）、NTK尺度変更、YaRNは、この意味で計算・記憶資源の削減手段とは独立である。

単純に長文を切り分けるだけでは、前半の指示と後半の質問が別のチャンクへ分かれ、下位層で相互参照できなくなる。独立した各チャンクの埋込みを後からまとめるだけでは、文脈間の相互作用が不足する可能性がある。HOMERは「初期層は局所処理で安く計算し、上位層は削減済みの情報を統合して全体を理解する」という分業を狙う。

原著は入力長に対するメモリ使用量の増え方も課題とする。全チャンクを同時に保持してから統合すると、チャンク数に比例した一時状態が残る。二分木状の統合を深さ優先に進め、完了した部分木の中間結果だけを必要に応じて保持すれば、保持する未統合の中間状態を木の深さに近い数へ抑えられる。論文の対数的メモリ増加という主張は、この計算順序と固定チャンク幅等の前提に基づくものであり、全GPUメモリ消費が任意の長さで純粋に対数関数になるという意味ではない。

## 手法

### 1. 長文の分割と共通の前後文脈

入力トークン列を長さのそろった複数のチャンクに分割し、初期Transformer層では各チャンクを独立に処理する。ただし単純な切断では、チャンク中央のトークンが冒頭の指示を参照できず、末尾の質問に必要な文脈も失う。そこで原著は入力の冒頭と末尾の部分を各チャンクへ共有の接頭・接尾文脈として付与する。これらの共通部分は後の統合時に重複してしまうため、対応する埋込みを平均して統合する。

この段階の入力は長文と共有前後文脈であり、出力は初期層を通したチャンク別の中間埋込みである。各チャンクが局所的な自己注意だけを実行するため、全入力を同時に処理する場合の二乗的な注意演算を避けられる。一方、共有接頭・接尾文脈はチャンクごとに再計算されるため、短い入力やチャンク数が多い設定では追加費用となり得る。

### 2. 注意位置バイアスを補正したトークン削減

隣接チャンクをそのまま連結すると、上層へ進むほど系列長が増えて効率上の利点が消える。HOMERは統合前に各チャンクの一部トークンを削除する。重要度の代理として、チャンク末尾トークンから各トークンへの注意の対数値を利用する。末尾トークンはそのチャンクの内容を集約する位置にあるため、その注意が小さいトークンを削るという発想である。

しかし、末尾に近いトークンは内容と無関係に注意が大きくなりやすい。原著は距離ごとの平均的な注意の対数値を位置バイアスとして求め、各トークンの注意対数値から差し引く。原著式(1)の重要度は「実際の注意対数値 − 末尾からの距離に対応するバイアス対数値」である。補正後の重要度が低いトークンを固定数削除し、共有接頭・接尾部分は削除しない。

入力はチャンク末尾からの注意と距離別バイアス、出力は残すトークンの添字集合である。単純な注意上位選択だけでは末尾付近の位置効果を過大評価するが、補正後の選択は内容への注意をより反映しやすい。補正値の推定と上位選択には追加処理があるものの、後続層の自己注意に渡すトークン数を減らせるため、長文では計算削減が上回り得る。

### 3. 中間層での階層統合

削減後の隣接チャンクを連結して新しいチャンクとし、さらに上位のTransformer層で処理する。これを二分木状に繰り返し、最終的には全入力を代表する一つの上位層埋込みへ統合する。各段階で削減してから連結するため、上位層での系列長は抑えられる。初期層は局所文脈、上位層は複数チャンクをまたぐ文脈を扱う構造になる。

位置番号は全チャンクに単純な連続番号を付けるのではなく、異なるチャンク間で再利用する。共有接頭・接尾部分は対応する位置番号をそろえ、既存のRoPE尺度変更方式との併用も可能とする。原著の実験ではHOMER単独とYaRN・NTKとの組合せを区別して評価する。位置番号の再利用は元モデルが学習した位置範囲を保つ助けになるが、離れたチャンクの絶対的な時系列位置をそのまま保持するわけではない。

### 4. 上位層の選択を下位層へ伝える精錬

階層統合の直後は、上位層ほどトークン数が少なく、下位層には長い中間埋込みが残る台形状の状態となる。このまま生成時に使うと層ごとのKV長が異なり、下位層のメモリ使用量も大きい。そこでHOMERは、上位層で残ったトークンの添字を下位層にも伝播し、下位層の埋込みから対応する位置だけを集め直す。

この「伝播的精錬」によって各層が固定長の埋込みを持ち、通常の自己回帰生成で使うKVキャッシュへ置き換えられる。各層で独立に重要度を測り直して選ぶのではなく、上位層の判断を下位層へ同期させることが重要である。上位層の注意が意味的に重要なトークンを識別しやすいという仮説に依存するため、上位層が誤ったトークンを削除した場合はその誤りが下位層へ伝播する可能性がある。

### 5. 深さ優先の計算順序

各チャンクを二分木の葉、統合結果を内部節点として扱う。すべての葉を同時に処理する代わりに、左の部分木を処理・精錬し、次に右の部分木を処理・精錬し、両者を連結して親節点へ渡す。原著のAlgorithm 1はこの再帰手順を示す。完了した部分木の不要な中間状態を解放できるため、必要な同時保持状態が木の深さに比例する。

この最適化は計算順序を変えることでピークメモリを減らすもので、各層の重み容量を減らすわけではない。また、逐次的な部分木処理によってGPUの並列実行機会が減る可能性もある。原著はメモリ使用量と生成時間を実測し、単に計算量の漸近記号だけで実装性能を評価していない。

## 評価

### 実験条件と比較の読み方

主なモデルはLlama-2-7B/13Bで、パスキー検索と質問応答にはチャットモデル、言語モデルの困惑度には事前学習済みモデルを使う。長文検索は4K、8K、16K、32Kで各500サンプルを評価し、質問応答はQuALITY検証集合を用いる。言語モデルの評価はPG-19から抽出した25件の長文で、最大64Kまでの困惑度を測定した。困惑度は小さいほど次のテキストを高い確率で予測できることを表す。メモリ・生成時間は単一A100 GPUで測定し、比較方式にもFlashAttention-2を適用している。

比較対象は素のLlama-2、位置補間、NTK尺度変更、YaRNと、それらの一部にHOMERを組み合わせた方式である。各方式は位置尺度の設定可能長が異なるため、長文で実行できない条件と、実行できても正答率が低い条件を区別する。原著の64Kメモリ表では比較方式が単一A100の容量を超えるため、比較方式の64K値は実測ではなく「80GB超」という下限である。

### パスキー検索：原著表1

| モデルと方式 | 8K正答率 | 16K正答率 | 32K正答率 |
|---|---:|---:|---:|
| Llama-2-7B-chat + HOMER | 92.4% | 89.0% | 77.6% |
| Llama-2-13B-chat + HOMER | 94.4% | 88.2% | 80.4% |
| Llama-2-7B-chat + YaRN（32K設定） | 65.4% | 69.6% | 0.2% |
| Llama-2-13B-chat + YaRN（64K設定） | 82.6% | 36.4% | 22.4% |
| Llama-2-7B-chat + YaRN（8K設定）+ HOMER | 98.4% | 87.6% | 80.2% |
| Llama-2-13B-chat + YaRN（8K設定）+ HOMER | 100.0% | 97.4% | 86.0% |

32KではLlama-2-13B-chatにHOMER単独を適用して80.4%、YaRN併用で86.0%となる。原著の「最良の比較方式22.4%」は特定の32K条件の値であり、モデル規模と位置尺度設定を無視してすべての比較方式が22.4%以下と一般化することはできない。検索正答率は、長文に埋め込んだ短い数値を取り出せるかの試験であり、複雑な推論や文書全体の忠実な理解を保証しない。

### 質問応答と困惑度：原著表2・表3

QuALITY検証集合の質問応答正答率は、素のLlama-2が32.7%、HOMER単独が35.8%、NTK尺度変更単独が37.9%、NTKとHOMERの併用が38.8%だった。HOMER単独がすべての位置尺度変更方式を上回ったわけではないが、NTKとの併用で改善した点が重要である。論文の冒頭にある「32.7→35.7%」は丸め方の差を含み、表2の値は0.358であるため、表の数値を優先する。

PG-19の長文25件における困惑度では、Llama-2-7BのHOMER単独が8Kで7.29、16Kで7.78、32Kで8.43、64Kで9.64だった。YaRNとHOMERを併用するとそれぞれ7.09、7.52、7.95、8.83へ改善した。Llama-2-13BではHOMER単独の64K困惑度が7.59、YaRN併用が7.44である。元モデルや位置尺度変更だけの方式は長文で困惑度が大きく悪化する条件があり、HOMERは少なくとも原著の評価範囲で安定していた。ただしこの測定は、長い前文脈を圧縮して次の2K区間の予測を繰り返す方式であり、全64Kトークンを未圧縮のまま同時注意へ入力した困惑度と同一条件ではない。

### 構成要素除去実験：原著表4

| 16Kパスキー検索の構成 | 正答率 |
|---|---:|
| ランダムなトークン削除 | 0.6% |
| 補正なしの注意上位選択 | 5.6% |
| 距離バイアス補正付きの注意選択 | 89.0% |
| 下位層の精錬なし | 0.2% |
| 下位層でランダム選択 | 11.6% |
| 下位層ごとの独立した注意上位選択 | 4.0% |
| 上位層選択を下位層へ伝播 | 89.0% |

距離バイアスの補正を外すと16K検索の正答率が89.0%から5.6%へ落ちる。単なる注意上位選択だけでは位置依存の偏りが強く、HOMERの主要機構として補正が不可欠である。また下位層を各層独立に削ると4.0%に留まり、上位層の選択を伝播する構成では89.0%を得る。したがって精度を支えるのは「チャンクを結合した」という一般的な構造だけではなく、位置補正と層間で整合したトークン選択である。

### ピークGPUメモリ：原著表5

| 入力長 | 比較方式 | HOMER単独 | HOMER＋位置尺度方式 |
|---|---:|---:|---:|
| 4K | 18.2GB | 16.3GB | 19.2GB |
| 8K | 23.6GB | 16.5GB | 20.1GB |
| 16K | 34.4GB | 16.7GB | 20.3GB |
| 32K | 56.7GB | 17.6GB | 20.8GB |
| 64K | 80GB超 | 21.3GB | 22.5GB |

比較方式は位置埋込みだけを変え、メモリ容量が同じなので一つの値としてまとめられている。32Kでは56.7GBに対してHOMER単独17.6GBで68.9%削減。64Kでは比較方式が単一A100に収まらず、HOMERは21.3GBで少なくとも73.4%削減という下限評価になる。4KではHOMERと位置尺度方式の併用が19.2GBとなり、比較方式18.2GBより5.5%増える。短い入力では共有前後文脈と統合処理の費用が利得を上回る条件があることを示す。

### 推論時間と計算効率

原著図1(c)は単一A100で長文入力から100トークンを生成する平均推論時間を比較する。長文ほどHOMERのメモリ削減と計算削減が有効になるが、本文の主要表には全入力長の厳密な秒数が一覧化されていないため、図から読み取れない小数値を捏造しない。効率改善の内訳は、初期層の局所チャンク処理、統合前のトークン削減、生成用の短いKV、深さ優先処理による同時保持状態の削減である。これはカーネル単体の速度ではなく、長文処理の構成変更による効果である。

## 限界と適用条件

HOMERは上層の注意を重要度の代理としてトークンを不可逆に削除する。正答に必要な細部が削除されれば、後から生成段階で復元する仕組みはない。16Kの構成要素除去実験で位置バイアス補正を外すと検索正答率が5.6%へ落ちることから、重要度推定の誤りに敏感な方式である。長文のすべての情報を完全に保持する方法ではない。

実験対象は主としてLlama-2-7B/13Bで、近年の混合専門家モデルや異なる位置符号化方式、マルチモーダルモデルへの適用性能は原著で検証されていない。共有接頭・接尾の複製、統合時の選択・連結、部分木の逐次処理には追加費用がある。4KのHOMER＋位置尺度方式では比較方式よりピークメモリが増えるため、短文の高速化を普遍的な利点とすることはできない。

「対数的なメモリ増加」は、固定チャンク幅と二分木の深さ優先順序に関する理論的な性質であり、モデル重みやGPU実行環境の全メモリを含む一般的な法則ではない。長い入力に対する原著の64Kメモリ削減は比較方式が容量超過であるため下限比較となる。原著は生成品質の偏り、幻覚、毒性を直接解決しないとも明記する。実運用へ導入する場合は、対象モデルと入力分布で重要トークンの欠落率、初回トークン遅延、生成時処理量、ピークメモリ、回答品質を同時に確認する必要がある。
