# Titans：テスト時に学習する長期記憶と局所注意の統合

## 概要

長い系列を処理する言語モデルでは、直近の情報を精密に参照する短期記憶と、遠い過去から重要な情報を残す長期記憶の両立が難しい。通常の自己注意は参照可能な文脈内で正確なトークン間相互作用を計算できるが、文脈長とともに計算・記憶費用が増える。一方、線形再帰型モデルは過去を小さな状態へ圧縮できるが、重要な出来事をどのように選択して長く保持するかに制約がある。Titansはこの問題を、推論時に更新されるニューラル長期記憶をモデルの構成要素として設けることで扱う。

Titansの長期記憶は、固定の重みを読み出すだけではない。入力に対する記憶の予測誤差から「驚き」を測り、記憶モジュールの重みをテスト時にも更新する。更新には運動量（momentum）と忘却係数（forgetting factor）を導入し、単発の大きな誤差だけに反応して過去の情報を破壊しないようにする。短期注意と長期記憶を結ぶ方式として、記憶を文脈へ挿入するMAC、ゲートで融合するMAG、別の層として重ねるMALを比較する。

原著の言語実験では170M、340M、400M、760Mパラメータの構成を調べ、760MモデルはFineWeb-Eduの30Bトークンで事前学習した。表1の常識推論平均はTitans MACが52.51、MAGが52.50で、同規模Transformer++の48.69を上回る。ただし、これはモデルの学習・評価条件に依存する品質比較であり、推論サーバーの毎秒トークン数やGPUメモリの改善倍率を示すものではない。

## 問題設定：何を記憶し、いつ忘れるか

長い会話や文書では、すべてのトークンを同じ精度で保持する必要はない。直近の語順や参照関係は局所注意で精密に処理できる一方、遠い過去の重要な事実は圧縮した状態として保存できれば効率的である。しかし、固定サイズの再帰状態へ情報を押し込むと、新しい入力で過去が上書きされる問題がある。Titansは「記憶容量を増やす」だけでなく、「どの入力が予測しにくく、記憶する価値があるか」を更新規則に反映する。

短期記憶には注意機構を使い、限られた窓内のトークンを直接比較する。長期記憶には小さなニューラルネットワークを用い、入力から得た特徴をその重みに書き込む。さらに、タスク全体に共通する知識を保持する学習可能な固定パラメータを永続記憶（persistent memory）として用意する。この三つの記憶を分離することで、入力文脈によって変わる記憶と、タスク一般の知識を同一の状態に無理に詰め込まない。

重要なのは、ここでいう「テスト時学習」が通常のモデル全体を毎トークン再訓練することではない点である。主たる言語モデルの重みを固定したまま、専用の長期記憶モジュールのパラメータを入力に応じて更新する。記憶更新は推論計算の一部なので、従来のKVキャッシュを読むだけの推論とは計算・メモリ・再現性の条件が異なる。

## 手法

### 1. 入力の驚きを長期記憶の更新信号にする

Titansの長期記憶は、入力特徴を受け取って関連する情報を出力する関数として設計する。入力が既に記憶された内容と一致していれば大きな更新は不要だが、予測できない入力は記憶へ新しい情報を書き込む候補となる。著者らは記憶モジュールの損失に対する勾配を驚き（surprise）の信号として利用する。更新量を入力依存にすることで、すべてのトークンを均等に書き込む方式より、重要な変化を選択して記憶することを目指す。

単純な勾配更新だけでは、新しい入力に敏感すぎて過去の記憶を失う。そこで、直近の更新方向を累積する運動量と、過去の記憶を徐々に減衰させる忘却機構を導入する。運動量は複数の入力に共通する更新方向を残し、忘却係数は保持し続けるべきでない情報を薄める。両者は同じ働きではなく、前者は更新の方向と継続性、後者は過去の記憶がどれだけ残るかを制御する。

### 2. 長期記憶を小さなニューラルネットワークとして扱う

記憶の内部は線形写像だけに限らず、多層パーセプトロンへ拡張できる。記憶モジュールは入力からキーと値に相当する表現を作り、自己教師ありの再構成・関連付け損失を通じて重みを更新する。重み自体が文脈から学習した情報を蓄積するため、通常の固定重みモデルにおける推論とは異なる「重みへの書込み」を伴う。長期記憶をどの程度深くするかは、表現力と更新計算の費用の交換条件になる。

この方式は、過去のすべてのトークンをそのまま保存するのではなく、ネットワークのパラメータへ圧縮する。従って長期記憶が小さければメモリ消費を抑えられる可能性があるが、情報を無損失で保持するわけではない。新しい入力に応じて重みが変わるため、記憶内容を読み出す際の出力も時間とともに変化し得る。文脈の中の厳密なトークン位置を参照する用途では、局所注意との併用が重要になる。

### 3. チャンク単位の並列化

毎トークン記憶重みを更新すると、時間方向の逐次依存が大きくなる。原著第3.2節は、入力をチャンクに分けて更新式を変形し、同一チャンク内の勾配をまとめて計算できる形を導く。線形記憶を例に、各トークンの更新係数と忘却係数の積を対角行列で表し、行列演算としてまとめる。運動量についても線形再帰として書き、並列結合走査（parallel associative scan）でチャンク内の状態を求める。

この変形は、記憶更新が存在すること自体を消すのではなく、GPUが得意なまとまった演算へ置き換えるものである。チャンク単位で忘却率や学習率を固定する簡略化も議論されるが、原著の主実験では入力トークン依存の係数を用いると明記する。したがって、チャンク定数化による追加の高速化を主実験の測定済み性能として扱うことはできない。

### 4. 永続記憶を入力の先頭へ付加する

長期記憶は入力文脈に応じて変わるが、タスク一般の知識は毎回上書きする必要がない。Titansは学習可能な永続記憶トークンを入力系列の先頭に追加する。これらはテスト時には固定され、注意機構が必要に応じて参照する。通常の注意には先頭トークンへ重みが偏る現象があるため、永続記憶トークンを明示的に置くことには、その偏りをタスク知識の保持へ利用する狙いもある。

永続記憶と長期記憶は混同しない。前者は学習済みの固定パラメータ、後者は現在の入力を処理する途中でも更新される文脈依存の状態である。短期注意は限られた範囲を精密に参照し、長期記憶は遠い情報を圧縮して持ち、永続記憶はタスク一般の表現を補う。三者の役割分担がTitansの中心的な設計思想である。

### 5. MAC：記憶を現在の文脈へ挿入する

Memory as Context（MAC）では入力系列を固定長のチャンクに分け、前チャンクまでに学習した長期記憶を現在チャンクから問い合わせる。得られた過去の情報を、永続記憶トークンと現在チャンクのトークンへ連結し、その結合系列に通常の注意を適用する。注意は「過去から取り出した情報」と「現在の情報」のどちらを使うべきかを選び、その出力を用いて長期記憶を更新する。

原著第4.1節では、現在チャンクからクエリを作って前状態の記憶を読み出し、永続記憶・長期記憶の読出し・現在チャンクを結合して注意を計算する。その出力を次チャンクへ渡す記憶更新にも利用する。過去を単なる固定ベクトルとして加えるのでなく、現在の注意が何を記憶へ残すべきかを選ぶ点が特徴である。ただし、チャンク境界での情報の扱いと、記憶読出しの品質が性能に影響する。

### 6. MAG：局所注意と長期記憶をゲートで融合する

Memory as Gate（MAG）は、短期の滑動窓注意（sliding-window attention）と、長期記憶モジュールの出力を並列の経路で計算し、非線形ゲートで融合する。局所注意は現在近傍の正確な依存関係を扱い、長期記憶は古い情報を圧縮して返す。両者の出力を正規化した後に学習可能な係数と非線形関数で組み合わせる。MACのように長期記憶を注意入力へ連結するのではなく、二つの経路の寄与をゲートで調整する。

この構成は、局所注意と長期記憶の表現が異なる性質を持つことを積極的に利用する。短期の細かな語順情報が必要な場面では局所経路を、遠い過去の情報が必要な場面では長期経路を重視できる。ただし、ゲートの学習が不十分なら片方の経路へ偏り得る。長期記憶の更新計算と局所注意の計算はどちらも残るため、単純な線形再帰モデルと同じ実行費用とは限らない。

### 7. MAL：記憶を独立した層として配置する

Memory as Layer（MAL）は、長期記憶モジュールを系列変換の一層として使い、その出力を滑動窓注意へ渡す。構造は比較的単純で、既存の再帰モデルと注意のハイブリッドに近い。原著第4.3節は、この方式では一方の層が作った表現の制約を後続層が受けやすく、MACやMAGのような補完的な処理が難しいと説明する。

著者らは注意を持たない長期記憶単独モデルも評価し、Titans LMMと呼ぶ。これは、記憶機構自体が系列モデルとしてどの程度機能するかを調べるためである。LMM単独、MAC、MAG、MALを並べることで、性能向上が単にパラメータを増やした結果なのか、短期注意と長期記憶の組合せによるものなのかを検討する。

主な表1は、モデル規模ごとに異なる学習トークン数を使う。340Mや400Mの15Bトークンの結果と、760Mの30Bトークンの結果を、モデル構造だけの差として直接比較することはできない。各規模の中で同条件の比較対象を確認することが重要である。さらに、常識推論の平均値は複数タスクの集約指標であり、WikiTextの困惑度とは別の尺度である。

### 言語モデリングと常識推論

原著表1の340M・15Bトークン条件では、Transformer++の常識推論平均42.92、Gated DeltaNetが45.42、Titans LMMが46.17、MACが47.36、MAGが47.54、MALが46.55だった。MACとMAGは長期記憶単独より高く、短期注意と長期記憶を組み合わせる利点を示す。WikiTextの困惑度はTransformer++が31.52、MACが25.43、MAGが25.07、MALが24.69で、困惑度が低いほど良い。

400M・15Bトークン条件では、Transformer++の平均45.64、Gated DeltaNet-H2が47.69、Titans LMMが47.83、MACが48.65、MAGが48.60、MALが47.87となる。400MでもMACとMAGが比較的強いが、MALがすべての評価で最高というわけではない。長期記憶の組込み方によって品質が変わることを示す結果である。

760M・30Bトークン条件では、Transformer++が48.69、Gated DeltaNet-H2が51.49、Titans LMMが51.56、MACが52.51、MAGが52.50、MALが50.97だった。MACのWikiText困惑度は19.93、MAGは18.61、Transformer++は25.21である。LAMBADAの困惑度はMAC20.12、MAG19.86、Transformer++27.64で、長期記憶を利用する構成が言語予測の面でも競争力を持つ。ただし各方式の評価タスク間には差があり、平均が高い方式がすべての列で最高とは限らない。

### 統合方式の比較と負の結果

MACは長期記憶を注意の入力へ追加し、MAGはゲートで局所経路と融合し、MALは記憶層を前段に置く。340Mと400Mの常識推論平均ではMACとMAGがMALより高い。760MでもMALの50.97はLMM単独の51.56より低く、単純に注意を後段へ重ねれば性能が向上するわけではない。これは長期記憶の存在だけでなく、短期記憶との情報交換の仕方が重要であることを示す。

Titans LMM単独が比較的強い点も重要である。340Mでは平均46.17で、Transformer++42.92やGated DeltaNet45.42を上回る。760Mでは平均51.56で、MACやMAGに近い。したがって、改善のすべてを注意とのハイブリッド化に帰するのは不正確であり、テスト時に更新するニューラル記憶自体の寄与もある。一方、MALは統合しても単独より低い場合があり、アーキテクチャの選択が品質を左右する。

### 長文と実行効率の解釈

原著は長い文脈、needle-in-a-haystack型の情報検索、DNA系列、時系列予測も評価対象とする。長期記憶の狙いは、局所注意の窓を超える情報を記憶の重みへ蓄積することにある。ただし、本稿で具体的に照合した数値は主に表1の言語評価であり、長文検索の最大長や速度の未確認数値を補っていない。論文の長文能力を、そのまま任意長の文書での完全な再現率保証として扱うことはできない。

計算量については、チャンク単位の勾配計算と並列走査により逐次更新の一部をまとめられるが、記憶重みの更新自体が消えるわけではない。通常の推論では固定モデルの行列積とKVキャッシュ更新を行うのに対し、Titansは記憶モジュールに対する追加の学習演算を必要とする。実行効率の比較では、系列長、チャンク長、記憶の深さ、バッチサイズ、GPU上の実装を明示しない限り、単純に「線形だから高速」とは結論できない。

## 既存研究との差

Transformerの自己注意は、与えられた文脈内のトークン間依存を高精度で表現するが、文脈が長くなると二次的な計算と記憶を要する。MambaやRetNetなどの再帰型モデルは、過去を固定サイズの状態へ圧縮することで系列長方向の効率を改善する。Titansは、その圧縮状態を単なる固定の更新式で進めるだけでなく、入力の驚きに応じて記憶ネットワークの重みを更新する点で異なる。

テスト時学習（Test-Time Training、TTT）系の研究とも関連するが、Titansは記憶の選択性を驚き・運動量・忘却の組合せで設計し、短期注意と永続記憶を別の役割として組み込む。特にMACでは、現在の注意が過去の記憶を読み、何を長期記憶へ戻すかを選ぶ。MAGでは局所と長期の経路を並列化し、MALでは直列の層構成を比較する。この三方式の比較が、記憶を単に追加するだけでは十分でないことを示す。

永続記憶トークンは入力文脈に依存しないタスク知識を表し、長期記憶は入力の履歴に依存して変化する。通常のプロンプトキャッシュやKVキャッシュは既に計算した特徴を再利用するが、Titansの長期記憶は重み更新を伴うため、状態の意味と運用上の性質が異なる。従って、キャッシュ容量削減手法と同じ分類に入れるだけでは、その技術的な貢献を捉えきれない。

## 限界・運用上の留意点

第一に、主な言語評価は170M〜760Mパラメータであり、数十B〜数百Bパラメータの生成LLMや商用推論サーバーに同じ結果がそのまま成り立つことは示されていない。大規模化すると、記憶モジュールの更新計算、パラメータの常駐容量、並列実行時の状態管理が新たな課題となる。モデル品質の改善をGPU推論スループットの改善倍率へ変換してはならない。

第二に、テスト時の重み更新は要求間の独立性と再現性に影響する。同じ入力でも記憶の初期状態や処理順序が異なれば出力が変わり得る。複数ユーザーの文脈を一つの長期記憶に混ぜると情報分離の問題が生じるため、実サービスでは要求・セッション単位の状態分離、記憶の初期化、保存・復元を設計する必要がある。原著はこの運用上のすべての問題を解決したと主張していない。

第三に、長期記憶は情報を圧縮するため、遠い過去のすべてのトークンを正確に復元できるとは限らない。重要情報を選ぶ驚き信号が、利用者にとって重要な情報と一致する保証もない。新しい入力への適応が速すぎれば古い記憶が消え、遅すぎれば新しい重要情報を取り込めない。運動量と忘却係数はこの交換条件を調整するが、完全に解消するわけではない。

第四に、チャンク並列化は実装を高速化する可能性があるが、チャンク内の近似や更新順序の制約が残る。原著が将来の可能性として示すチャンク単位の固定係数化を、主実験で検証済みの方式として扱ってはならない。局所注意の窓長や記憶ネットワークの深さが変われば、速度・メモリ・品質の関係も変化する。

第五に、公式コードの確定URL、vLLMやSGLangなどの推論基盤への統合、Windows上の実行互換性、CPUオフロード時の性能は今回確認した一次資料から保証できない。ローカルGPUで試す場合は、記憶更新の計算グラフ、CUDAカーネル、状態の保存形式、同時実行時のメモリ容量を個別に確認する必要がある。
