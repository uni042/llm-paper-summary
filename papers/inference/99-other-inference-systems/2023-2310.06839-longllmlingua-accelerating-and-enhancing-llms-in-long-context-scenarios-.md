# LongLLMLingua: Accelerating and Enhancing LLMs in Long Context Scenarios via Prompt Compression

> 質問に応じた段階的プロンプト圧縮と重要情報の再配置で、約10kトークン入力を2〜6倍圧縮しエンドツーエンド遅延を1.4〜2.6倍高速化する。

## 概要
長文脈では入力トークンが増えるほどプリフィル計算とAPI費用が増え、重要情報が文脈中の位置によって利用されにくくなる。LongLLMLinguaは、質問に関係する情報密度を高めるようプロンプトを圧縮し、同時に重要情報の位置を調整する。NaturalQuestionsではGPT-3.5-Turboへの入力を約4分の1にしながら性能を最大21.4%改善し、LooGLEでは費用を94.0%削減した。約10kトークンの入力を2〜6倍圧縮した条件ではエンドツーエンド遅延を1.4〜2.6倍高速化した。

## 問題設定
長いプロンプトの全トークンをそのままLLMへ渡すと、注意計算とKVキャッシュ生成の対象が増える。単純な切り詰めでは質問に必要な情報を失い、一般的な圧縮でも長文脈モデルの位置バイアスにより中央部の重要情報を利用しにくい場合がある。したがって「何を残すか」と「残した情報をどこへ置くか」を質問に応じて決める必要がある。

## 手法
LongLLMLinguaは小型言語モデルを使い、質問に対する条件付きの重要度から文書、文、トークンを段階的に評価する。粗い単位から先に不要部分を落とすことで、全トークンへ同じ高コスト評価を掛けることを避ける。圧縮率も一律ではなく、重要度の高い部分へより多くのトークン予算を割り当てる。

さらに、長文脈モデルで重要情報の位置が性能へ影響する問題に対し、圧縮後の情報を質問との関連度に応じて再配置する。単に文字数を減らすだけではなく、残した証拠をモデルが利用しやすい位置へ移す点が特徴である。

圧縮器自身の計算が追加されるため、短い入力や圧縮率が低い条件では利益が小さくなる。また、小型モデルの重要度推定が外れると必要情報を削除する危険がある。

## 評価条件・主要結果
NaturalQuestions、LooGLEなどの長文脈タスクで、圧縮後の下流LLM性能、入力費用、エンドツーエンド遅延を評価する。

| 条件 | 結果 |
|---|---|
| NaturalQuestions / GPT-3.5-Turbo | 約4倍少ないトークンで性能を最大21.4%改善 |
| LooGLE | 費用を94.0%削減 |
| 約10kトークン、2〜6倍圧縮 | エンドツーエンド遅延を1.4〜2.6倍高速化 |

性能改善が同時に出るのは、圧縮が単なる計算削減ではなく、不要情報を減らして重要情報密度と位置を改善するためである。

## 既存研究との差
従来のプロンプト圧縮に対し、長文脈特有の位置バイアスと質問依存の情報重要度を明示的に扱い、文書・文・トークンの多段階圧縮と再配置を組み合わせる。

## 限界
圧縮器の追加推論が必要で、圧縮後に失われた情報は下流LLMから復元できない。報告された速度・費用利得は入力長、圧縮率、利用するAPIやモデルに依存する。
