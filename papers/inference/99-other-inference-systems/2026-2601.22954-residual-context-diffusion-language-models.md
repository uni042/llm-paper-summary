# 残差文脈拡散（RCD）：再マスクで失う確率情報を次の拡散ステップへ渡す

## 概要

マスク型拡散大規模言語モデル（dLLM）は、複数のトークン位置を同時に予測し、確信度が高い位置だけを確定しながら残りを反復更新する。一般的な方式では、確定しなかった位置を再び`[M]`に戻すため、その反復で計算した語彙確率分布を捨ててしまう。残差文脈拡散（Residual Context Diffusion、RCD）は、この未確定位置の確率分布にも将来の正解に関する手掛かりが含まれると考え、語彙埋め込みの期待値へ変換して次の反復へ受け渡す。単に最大確率トークンを保存するのではなく、確率分布全体を使い、エントロピーに応じて元のマスク埋め込みと混合する。

本論文の主要な貢献は、①再マスク位置の分布情報を正規化エントロピーで重み付けした残差として次ステップに渡すこと、②再帰的な逆伝播を必要としない参照モデル・対象モデルの二段階学習、③学習時の参照分布と推論時の自己予測分布の違いを温度調整・初期化で補うことである。SDARの4B・8B系列とLLaDAを対象に、数学推論の正答率と反復回数、実測トークン処理量を評価する。

SDAR-8Bでブロック長64のMATH500正答率は通常の逐次ノイズ除去（Sequential Denoising、SeqD）の64.20%から74.40%へ、AIME24は7.08%から18.75%へ改善する。LLaDAのMinervaMathは31.10%から37.00%へ改善する。一方、同じ生成エンジンで比較した実測処理量は少し下がる場合がある。論文の「4～5倍の計算削減」は、**同等の正答率を達成するためのノイズ除去反復数**に関する主張であり、実測の生成時間が常に4～5倍速いことを意味しない。

## 問題設定

### 再マスクが計算結果を破棄する

通常の拡散言語モデルは、出力ブロックの全位置を`[M]`から始める。各反復でモデルは未確定位置それぞれに語彙分布`p_i`を予測し、最大確率などで確信度を計算する。確信度の高い上位位置を確定し、それ以外を`[M]`に戻す。これを全位置が確定するまで繰り返す。この過程では、採用されなかった位置に対してもモデル全体の順伝播と語彙分布計算を済ませているが、その分布を次回へ渡さない。

著者らはLLaDAで、各反復の上位5候補が最終的に確定するトークンを含む割合（recall@5）を測定し、早い段階の未確定分布にも意味情報があることを示す。したがって、毎回すべてをマスクの単一埋め込みへ戻すことは、反復で得た文脈の蓄積を妨げる。ここで解決したいのは、語彙分布から有益な情報を残しながら、拡散モデルが前提とする離散マスク学習を壊さないことである。

### 生の隠れ状態を足すだけでは不安定

モデルの最終隠れ状態と入力埋め込みは同じ分布とは限らない。特に8B級以上のモデルでは入力埋め込みと語彙出力頭の重みが分離されることがあり、生の隠れ状態を入力へ加えると大きさが合わず、訓練や生成が不安定になる。RCDは、**対象モデル自身の入力埋め込み表**で語彙分布を加重平均するため、次の入力と同じ表現空間のベクトルを作れる。混合率を0～1に制限することで、残差がマスク表現を無制限に上書きすることも防ぐ。

## 手法

### 1. 語彙分布を連続的な残差文脈へ変換

位置`i`、反復`k`で予測した語彙確率`p_{i,j}^{(k)}`と、対象モデルの入力埋め込み行列`E`を使い、残差`Δ_i^(k) = Σ_j p_{i,j}^{(k)} E_j`を計算する。これは一つの予測語ではなく、複数候補の確率を反映した軟らかいトークン表現である。次反復でも未確定の位置だけに対して、入力埋め込みを`(1-α_i)*E([M]) + α_i*Δ_i`へ置き換える。すでに確定した位置は元の離散トークン埋め込みをそのまま使う。

混合率`α_i`には、確率分布のシャノンエントロピーを語彙数`V`の対数で割った正規化値を用いる。`α_i = -Σ_j p_{i,j} log p_{i,j} / log V`で0～1となる。確信度が低く候補が広く分散した位置ほど残差情報の寄与が大きくなる。高確信度位置は既に確定しやすく、再マスク位置の不確実な文脈に重点を置く設計である。単純な残差加算ではなく、元のマスク埋め込みと補間するハイウェイ接続である点が重要である。

この残差は次のモデル順伝播の**入力**を変える。従って推論を一回で終わらせる手法ではなく、未確定位置の条件付き分布を改善し、同等の精度に達するために必要な反復回数を減らせる可能性を作る。残差を計算するために語彙分布の加重平均とエントロピー計算が追加されるため、1反復当たりの計算量が完全に同じとは限らない。

### 2. 参照モデルを用いる二段階学習

残差を前反復から受け取るモデルを、そのまま全反復にわたって逆伝播で学習すると、モデルが作った残差が次の入力を変えるため、長い計算グラフの展開が必要になる。これはメモリ負担が大きく、学習初期には残差分布が不安定になる。そこでRCDは、まず小型の参照モデルを通常のマスク復元目的で微調整し、固定した確率分布の教師信号を得る。次に対象モデルを、参照モデルが生成する分布・エントロピーから作った残差を含む入力で学習する。

参照モデルの語彙確率は残差の**重み**として使うが、ベクトルへの変換は対象モデルの入力埋め込み表で行う。これにより、1.7Bの参照モデルから8Bの対象モデルへ情報を渡す場合も、対象モデルの表現空間に残差が位置する。対象モデルは残差を含む入力から元の正解トークンを復元する通常の交差エントロピーで学習できる。学習の各サンプルで参照モデルを凍結するため、対象モデルが自分の予測分布を変えるたびに教師信号まで変化する問題を避ける。

SDARではOpenR1-Math-220kから長文例を選んだ約3億トークンのデータを使い、LLaDAではOpenMathInstruct-2から約4億トークンの部分集合を使う。論文の主比較ではRCDもSeqDも同じトークン数で5エポック学習し、さらに1エポックのみの約3億トークンでの収束を別実験として示す。「3億トークンで十分」という記述は1エポック実験を指し、主表の全モデルが1エポックのみという意味ではない。

### 3. 推論時の自己残差と初期化

学習時には固定参照モデルが残差を作るが、推論時には対象モデル自身が前反復で出した確率分布を使い、次の残差を再帰的に生成する。ここに分布差があるため、語彙logitを残差用温度`T_res`で割ったsoftmaxからエントロピーを計算し、参照モデルの分布に近い残差重みへ較正する。過度に尖った確率分布でエントロピーが小さくなりすぎる場合は、温度を上げることで残差の寄与を増やせる。

最初の反復には前回残差が存在しない。初期化の選択肢は、参照モデルを一回だけ呼ぶ温開始と、ゼロベクトルなどを置く冷開始である。論文のSDAR主評価はゼロ初期化、LLaDAは参照モデルを使う温開始と明記する。さらにSDAR-8Bでの構成要素除去では、Dirichlet分布で初期化する方法が参照モデルより良い精度を示し、著者の公式実装は2026年6月以降、推論時の参照モデルを不要とする冷開始へ更新されている。**学習時に参照モデルを使うこと**と**推論時に毎回参照モデルを呼ぶこと**を区別する必要がある。

| エンジン・課題 | SeqD：token/s・正答率 | RCD：token/s・正答率 | 解釈 |

| Fastdllm / LLaDA / GSM8K | 75.00・76.12% | 65.56・78.70% | 速度約12.6%低下、正答率+2.58ポイント |
| D2F / SDAR / MinervaMath | 130.54・50.82% | 124.86・59.82% | 速度約4.4%低下、正答率+9.00ポイント |

論文はこれを「ほぼ同等のトークン処理量で高い品質」と説明する。表の数値を確認するとRCDの処理量が上回るわけではなく、各設定でわずかに低下している。したがって、同じ設定での**トークン毎秒高速化**として報告してはいけない。正答率を固定した場合の反復数削減と、反復当たりの処理量を固定した場合の品質改善という、二つの異なる比較を区別する。

### 並列復号と構成要素除去

確信度閾値を0.5～1.0へ変えて反復当たりの確定トークン数を増やすと、通常SeqDは品質が崩れやすい。RCDは残差文脈を保持するため、同程度の正答率でより多くの位置を同時に確定でき、最大で約4～5倍少ない反復ステップで基準精度を達成する設定がある。これはグラフ上の精度・反復数の優越であり、すべてのGPU設定で4～5倍の壁時計時間短縮を実測したという主張ではない。

混合率`α`の実験では、正規化エントロピー、最大確率、固定0.3、単純残差（1.0）、最大確率の一語だけを使う方法、逆エントロピー、逆確信度を比較する。正規化エントロピーが高い並列度でも品質を保ち、単純残差と最大確率一語の残差は品質が大きく低下する。これは、残差の大きさを制御することと、分布の豊かさを残すことが両方必要であることを示す。

SDAR-8B-b64のMATH500初期化比較では、SeqDが64.2%、1.7B参照モデルによる温開始74.2%、4B参照モデル71.8%、自己モデル76.4%、ゼロ開始75.6%、Dirichlet開始77.4%である。大きな参照モデルが必ず有利という結果ではなく、質の低い初期残差が推論を妨げることがある。さらにSeqDの学習を5から8エポックへ延長してもMATH500は68.00%で、RCDの74.40%に及ばない。単に学習を長くすれば情報破棄の問題を解消できるわけではない。

## 既存方式との差

通常の拡散LLMは未確定位置を再マスクして、前反復の確率分布を失う。Loopholingのような連続状態を使う方式は、生の隠れ状態を次入力へ渡すが、入力埋め込みとノルム・分布が異なると不安定になる。RCDは**語彙分布→対象モデルの入力埋め込み期待値→エントロピー補間**という経路を選ぶ。単一トークンを確定する方式ではなく、未確定位置に複数候補の情報を残す点が異なる。

一エポック約3億トークンのSDAR-4B-b64比較では、Loopholingが評価可能な数学解答を生成できなかったのに対し、RCDはGSM8K 86.35%、MATH500 66.20%を報告する。ただしこれは同じ学習予算での適応容易性を示す実験であり、全設定でのモデル性能を単純に比較した結果ではない。

## 限界・適用条件

RCDは追加の参照モデル学習と対象モデルの再微調整を必要とする。著者らは8B対象・1.7B参照モデルの学習費用上乗せが50%以内と報告するが、追加学習がゼロではない。推論時は冷開始により参照モデルを省けるものの、既存の任意の拡散LLMへコードだけ挿して同じ効果が出るとは限らない。残差温度や確信度閾値、ブロック長、初期化方法によって品質が変わる。

確率分布全体の語彙埋め込み加重平均を作るため、反復ごとに追加演算・メモリアクセスが発生する。実測表でもトークン毎秒が低下する条件がある。最大4～5倍という数値は**同等精度に必要な反復回数**に関する条件付き結果で、バッチ処理、ハードウェア、エンジン実装によって壁時計速度の改善幅は異なる。実測はH100×8のFastdllm/D2Fに依存し、CPUオフロードやWindowsローカル環境、別GPU世代への性能移植は未検証である。

主評価は数学推論に偏り、一般会話・コード生成・長文検索などの幅広い品質を同じ強度で検証していない。Chat版と推論特化版では学習データ・出力長が異なるため、異なる版の正答率をそのまま改善率としない。著者自身がGSM8Kで元Chat版のデータ汚染可能性を指摘している。再マスク分布を保持することは、生成内容の正しさを理論的に保証するものではない。
