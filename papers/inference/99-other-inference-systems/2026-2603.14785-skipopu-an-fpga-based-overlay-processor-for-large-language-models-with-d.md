# SkipOPU：動的なトークン・層省略をFPGA上で実行する推論プロセッサ

## 概要

SkipOPUは、トークンごとに注意計算やフィードフォワード計算を実行するかを変える大規模言語モデルを、再構成可能な論理回路（FPGA）で実行するための専用オーバーレイである。計算を省いた結果、演算回数だけは減っても、通常の推論器ではルーティング、正規化、異なる層からの鍵・値（KV）参照が新たな律速要因になる。本研究は、非線形処理の待機を隠す融合データフロー、浮動小数点活性値と4ビット整数重みを扱うDSP演算器の高密度実装、層をまたいで変化しないKVを保持するオンチップ履歴バッファを一体設計した。

AMD Alveo U280上のLlama2-7Bで140.8トークン/秒、帯域効率86.7%を報告する。13Bでは75.6トークン/秒、帯域効率89.1%である。比較先に対する帯域効率の優位は査読採録版および本文で1.31〜2.55倍、KV記憶量削減は最大25.4%とされる。ただし、この倍率はハードウェア条件を統一した実時間速度倍率ではない。さらに、7BのWikiText2におけるパープレキシティは、密なFP16モデルの5.47から提案構成の8.52へ悪化している。計算削減と品質低下を同時に評価する必要がある。

## 問題設定と前提

通常の自己回帰型モデルでは、入力全体を一括計算する事前充填（prefill）と、過去のKVを読みながら次の1トークンを作る復号（decode）とで支配的な処理が異なる。事前充填では大きな行列積が多く、復号では重みとKVの読み込みが支配的になりやすい。固定形状の演算器は両者に対応できても、トークンごとに実行層が変わるモデルではルータの判定待ち、処理対象の圧縮、層間のKV参照先の不規則化が追加される。

対象とするSkipGPT型の動的計算では、各層の自己注意とフィードフォワードの前に軽量な二値ルータを置く。トークン状態から得たロジットをもとに実行か迂回かを選び、迂回なら残差経路を通して値を次層へ送る。自己注意を省いたトークンについては、その層で新しい鍵・値を計算しないため、直前に実際の注意処理を通った層のKVを代用する。このため、同一トークンのKVが連続する複数層で不変になる場合がある。

ここに三つの課題が生じる。第一に、ルータと二乗平均平方根正規化（RMSNorm）を順に処理すると、縮約が終わるまで後段の行列積を始められない。第二に、4ビット重みと半精度活性値を組み合わせた乗算は、汎用浮動小数点DSPを単純配置すると回路面積を浪費する。第三に、KVを層ごとに複製して帯域を守ると省略による記憶量削減を失い、重複を消すと異なる層のHBM領域を飛び回る短い転送が増える。SkipOPUは単なる層省略アルゴリズムではなく、これらを同時に扱う回路・メモリ配置の研究である。

## 手法：融合データフロー

### ルータと正規化の並行処理

入力活性行列をタイルに分割し、タイルをチップ内へ読み込んだ時点で、ルータの射影と正規化に必要な統計量の更新を並行させる。ルータは各トークンに対して実行・省略の判定を返し、統計処理側は入力要素の和や二乗和を分割区間ごとに累積する。すべての要素を読み終えた時点では判定結果と統計量がともに準備できているため、実行対象の行だけを選択して正規化し、そのままQKV生成用の行列積へ送れる。正規化した活性は同じオンチップ領域へ上書きし、後続の行列積で繰り返し利用する。

原著のアルゴリズム1では、活性の行方向タイルと縮約方向タイルを分け、ルータの二次元ロジットを積和で蓄積する処理と、正規化の統計を蓄積する処理を同じループへ置いている。判定が省略なら後段の演算対象から除き、実行なら正規化済みの値を行列演算配列へ渡す。非線形関数を実行する小型専用処理器（NPE）を独立させることが重要であり、単にRMSNormの数式を別の形に書き換えた最適化ではない。

### 自己注意における縮約と行列積の重畳

注意スコアのソフトマックスについても、行ごとの最大値と指数和をブロックごとに更新し、すべての注意スコアが揃う前から縮約統計を作る。原著はFlashAttentionで使われるオンライン縮約の考え方を利用し、QとKの積を演算器配列で進めながら、非線形処理器が統計を更新するようにしている。さらに複数の注意ヘッドを同時に配置し、ヘッドごとに細かく分かれたKV読み出しを集約する。

注意スコアのタイルは必要に応じて外部メモリへ流し、正規化に必要な小さな統計だけをチップ内へ残す。ここは一般的な「注意行列をすべてオンチップ保持する」方式とは異なる。注意ヘッドをまとめると同時に保持すべきスコアが増えるため、縮約をオンライン化することで保存領域を抑えている。スコアと対応する値ベクトルを同じ並び替えで扱えるなら、値の加重和は加算順序に依存しないため、元のトークン順に戻すための大規模な並べ替え回路を省ける。ただし浮動小数点の演算順序に伴う丸め差まで厳密に同一とするものではない。

### 何が高速化されるか

融合の直接的な効果は、ルータ・正規化・ソフトマックスに起因するパイプラインの空白時間を減らすことにある。入力が長く、行列演算と縮約を重ねられる事前充填で効果が大きい。原著の注意サブモジュールの比較では、通常構成に対して部分省略のみ約1.14倍、KV再利用追加で約1.29倍、融合データフロー追加で約1.40倍の処理量を報告する。一方、復号はメモリ帯域律速なので、非線形処理を融合した効果は系列長が伸びるほど小さくなる。融合による改善とKV履歴バッファによる改善を混同してはいけない。

## 手法：混合精度DSP演算器

### 精度の非対称性

重みを4ビット整数にしても活性値やKVを半精度で保持する設定では、同じ乗算器で整数と浮動小数点を扱う必要がある。SkipOPUは活性の浮動小数点値をブロック浮動小数点（BFP）形式へ変換し、固定小数点の積和と共通指数を利用して計算する。これにより積和のたびに高価な浮動小数点加算器を使う構造を避ける。固定小数点で蓄積した値は必要な境界で浮動小数点へ戻す。

さらにDSP48E2の乗算・加算資源へ複数の低精度演算を詰め込む過密配置を使う。隣接する積の桁が干渉しないようガード領域を設け、一部の仮数を切り詰めたうえで補正項を内部の加算経路に回す。これは単なる重みの4ビット量子化とは別の回路技術であり、演算器数と配線量を減らすことが狙いである。

### 回路資源との対応

原著の表3では、U280の処理要素配列に4096個のDSPを使い、非線形処理器に266個、総計4618個のDSPを使う。総使用率はDSPで51.17%、参照テーブル（LUT）で98.85%、UltraRAMで53.33%に達する。特にLUTの余裕が非常に小さく、過密配置を外した設計では演算列当たりのLUT使用量が6716から13598へ増え、128列へ展開すると約174万LUTが必要になる。これはU280の約130万LUTを超えるため、過密配置は単なる小幅な速度調整ではなく、設計を物理的に実装可能にする条件でもある。

演算器の密度を高める代わりに、FP16とINT4の混合計算、BFP変換、仮数切詰めの誤差を管理する必要がある。論文は言語モデルのパープレキシティを別途測定しているが、演算結果が密なFP16実行とビット単位で一致することを証明していない。LUT使用率98.85%という値から、別のFPGAや機能追加へそのまま移植できる余地は限定的である。

## 手法：層間KV不変性を使うメモリ階層

### 省略されたトークンのKVの所在

トークンiが層lで自己注意を省いた場合、その位置の鍵・値は直前に実際の計算が行われた層から継承される。したがって、論理的には層lのKVを参照していても、物理的な実体は層lより前に置かれていることがある。単純な層別配列に従ってアクセスすると、各トークンが異なる層へ飛ぶため、HBMの連続バーストが分断される。これを避けるため同じKVを各層へ複製すると、層省略の主要な利点である保存量削減が失われる。

SkipOPUは、同じトークンのKVをまとまった連続領域へ置くトークン単位の配置を採用する。各トークンの読み出しを特定のHBMポートへ寄せることで、複数層をまたぐ参照でも比較的長いバースト転送を作る。さらに、次層でも値が変化しないことが既に分かっているKVは、前の注意計算と並行してUltraRAMの履歴バッファへ先読みする。次層での読み出しは外部HBMではなくオンチップのバッファから行う。

### 履歴バッファとアクセス順序

原著の回路は512個のUltraRAMを用い、最大1024トークン分の対象KVを保持する。16の独立したポートと48×16のクロスバを通じて、次層で必要な再利用分を選択する。新たに更新されたKVはHBM側へ格納し、連続して省略されたトークンについては履歴バッファから供給する。複数層を隔てて自己注意が再開する場合など、すべての参照をバッファだけで満たせるわけではないため、HBMアクセス自体は残る。

原著の実測比較では、密な配置の実効HBM帯域が408.7GB/秒、KVを省いても従来のインターリーブ配置を使うと最悪55.8%の帯域利用率に落ちる。トークン単位の配置へ変更すると実効帯域は360.2GB/秒へ回復し、履歴バッファを加えるとオンチップ再利用を含めた合算の有効帯域が467.8GB/秒になる。この467.8GB/秒はHBMの物理インターフェースを通ったデータ量ではない。オンチップから供給したKVも同等の処理量へ換算した集計値であり、物理HBMの規格帯域を超える転送が発生したと解釈してはいけない。

高い省略率では履歴バッファの書き戻しと読み出しが増え、ポート帯域が不足する。原著では省略率25%以下で理論的な演算削減を上回る改善が得られる条件がある一方、40%以上ではUltraRAM側の競合により高速化が頭打ちになる。KVの最大25.4%削減も、特定のモデル、系列長、省略率での結果であり、すべての運用で固定の削減率ではない。

## 評価条件と再現可能性

| 区分 | 論文で明示された条件 | 解釈上の注意 |
| --- | --- | --- |
| 対象装置 | AMD Alveo U280、HBM2 8GB、DDR4 32GB | 他のFPGAへの一般化は未証明 |
| 回路実装 | SystemVerilog、Vivado 2020.1、225MHzの演算核、450MHzのHBMインターフェース | Pythonだけのモデル実行ではなく合成可能な回路設計 |
| 主なモデル | Llama2-7B、Llama2-13B、GPT-2 345M | モデルごとに計算・制御律速が異なる |
| 動的計算 | SkipGPT型、約25%の省略率 | 品質は省略率と量子化に依存 |
| 数値形式 | 4ビット対称量子化重み、FP16活性値・KV | FP16密モデルと数値同値ではない |
| 入力長 | 128、256、512、1024トークン | 事前充填の感度評価 |
| 出力長 | 512または1024トークン | 1024超の履歴バッファ挙動は不明 |
| バッチ | 1 | 多数要求をまとめたサービングは未評価 |
| 品質指標 | WikiText2、Penn Treebankのパープレキシティ | 生成速度とは独立の品質測定 |

HBM2は理論帯域460.8GB/秒、DDR4は38GB/秒である。重みと使用中のKVはHBMに、活性値・ルータや正規化の小さな係数はDDR4に、再利用するKVはUltraRAMに配置する。論文の表5はGPU、複数世代のFPGA、異なる量子化精度、異なる系列長を含む比較なので、装置横断の「トークン/秒」を単純な優劣として並べるべきではない。

| Llama2-7B / WikiText2 | 5.47 | 5.86 | 7.81 | 5.54 | 8.52 |
| Llama2-7B / PTB | 20.83 | 28.03 | 30.58 | 24.14 | 35.96 |
| Llama2-13B / WikiText2 | 4.88 | 5.67 | 6.78 | 5.96 | 7.84 |
| Llama2-13B / PTB | 28.92 | 35.84 | 41.69 | 30.59 | 45.51 |

パープレキシティは小さいほどよい。7BのWikiText2ではSkipOPUの8.52は密なFP16の5.47より約56%高く、13BのPTBでも28.92から45.51へ悪化する。著者は計算量と性能の折り合いを許容可能と評価するが、品質劣化がないという意味ではない。量子化単独、動的省略単独、KV再利用を伴う省略の比較を置くことで、性能悪化の原因が単一の回路最適化だけにあると誤認しないようにする。特に推論の正確性が重要な用途では、利用者が許容する品質水準で省略率を再調整する必要がある。

### 帯域効率と生成速度

| 条件 | 生成速度 | 帯域効率 | 意味 |
| --- | ---: | ---: | --- |
| SkipOPU / Llama2-7B / U280 | 140.8トークン/秒 | 86.7% | 代表的な大型モデル評価 |
| SkipOPU / Llama2-13B / U280 | 75.6トークン/秒 | 89.1% | 重み規模増加で絶対速度は低下 |
| SkipOPU / GPT-2 345M | 論文表5に別条件の値を掲載 | 48.8% | 小型モデルでは制御・計算律速が目立つ |
| GPU上のvLLM / Llama2-7B | 45.3トークン/秒 | 31.5% | FP16等の条件が異なるため単純速度比較不可 |
| FlightLLM / Llama2-7B | 55トークン/秒 | 66.0% | 量子化方式と装置条件が異なる |

原著は重み容量を基準とした正規化処理量も計算し、帯域効率の比較を1.31〜2.55倍とする。ただし、この正規化式にはモデルのパラメータ量と量子化形式に関する仮定が含まれる。原著の概要欄には1.23〜3.83倍という旧表記が残るが、本文・査読採録版の1.31〜2.55倍を採用し、版の差を明記する。モデル規模、量子化精度、入力・出力長を揃えた同一GPUとの厳密な生成速度比較としては扱わない。

### 最適化の分離評価

注意サブモジュールでは、部分省略→KV再利用→融合データフローと段階的に改善した際、事前充填の処理量が基準比約1.14倍→1.29倍→1.40倍となる。メモリ配置では、KV重複を減らしただけでは帯域が大きく低下し、トークン単位の配置と履歴バッファの追加によって回復する。この二つの評価は、演算量の削減とデータ供給効率の改善が独立した効果であることを示す。

Llama2-7B、省略率25%、入力512・出力1024トークンの累積最適化では、DSP過密配置が事前充填に約1.94倍の改善をもたらし、全構成で基準比の事前充填2.51倍、復号1.36倍の処理量改善となる。1.94倍と2.51倍は別々の設定の比なので単純に掛け合わせない。最終段階の正規化総遅延を1.0と置く図の読み方も、各段階の絶対時間を示すものではない。事前充填と復号の比率は実際の入力長・生成長で変わるため、要求全体の平均遅延は一つの固定倍率では表せない。

## 既存方式との相違

SkipLayerやSkipGPTは「どのトークンがどの層の演算を通るか」というモデル側の判断を扱う。一方、SkipOPUの主な新規性は、判断後の不規則な計算とKV参照をFPGAで実行するための回路・メモリ設計である。従来の密なFPGA推論器や固定疎行列用のアクセラレータは、演算パターンがあらかじめ決まることを前提にする。SkipOPUはルータの結果で処理対象が変わっても、正規化統計の先行計算とチップ内KV再利用によってパイプラインを維持する。

重み量子化方式だけを変更する研究とも異なる。4ビット重みは前提の一つに過ぎず、DSP48E2を過密配置して混合精度の積和を実行し、同時にUltraRAMへKVを退避する点が回路の貢献である。GPU向けの通常のKV圧縮・オフロード方式では、層間で値が不変なトークンを知っていてもHBMのポート配置とUltraRAMのバッファへ直接対応させることはできない。ソフトウェアのKV参照管理と物理的なメモリ転送の違いを区別する必要がある。

## 限界・監査事項

第一に、動的省略と量子化は近似であり、品質の低下が実測されている。特に7BのWikiText2で5.47→8.52という悪化は無視できない。省略率25%前後での推論効率改善が、別のモデル・指示追従・コード生成でも同程度の品質を維持することを証明するものではない。

第二に、評価はバッチ1、復号長最大1024を中心とする。実装の履歴バッファも最大1024トークン分として説明されており、数万トークン文脈や多数同時要求を処理する場合の容量・ポート帯域の振る舞いは示されていない。特に40%以上の省略率ではUltraRAMポートの競合が支配的になる。より多く省略すれば常に高速化する、という単調な関係ではない。

第三に、比較表は異なるハードウェア、重み精度、モデル規模、系列長を混ぜる。帯域効率という正規化指標は有用だが、原著の正規化処理量の算出条件を完全に揃えた独立再測定ではない。表5の行数と列見出しにはテキスト抽出上の崩れもあり、比較対象の個別数値を再利用する際は原PDF表の列対応を確認すべきである。

第四に、回路資源のLUT使用率が98.85%と高い。モデルの別構成への変更、同時要求用の追加バッファ、機能拡張を同じU280で実装できる余裕は小さい。DSP過密配置は機能的に有効でも、FPGA固有のDSP48E2構造、配置配線、HBM/UltraRAM構成に依存するため、一般のGPU推論ランタイムへ設定だけで導入できない。

第五に、467.8GB/秒はオンチップ再利用を含む集計有効帯域であり、HBMの物理実測転送帯域ではない。原著の説明にある「オンチップ再利用が外部帯域を補う」という機構と整合するが、物理HBMが規格上限を超えたと解釈することは誤りである。

第六に、論文のarXiv概要には帯域効率1.23〜3.83倍、本文・ACM採録版には1.31〜2.55倍とある。一次資料間の版差を残し、現行本文の比較条件を優先した。公式の公開RTLリポジトリは一次資料から特定できていないため、再現性は回路記述・合成条件・図表の記載に依存する。
