# Delay-Adaptive Speculation Control：通信遅延に応じた分散投機的復号の草稿長制御

## 概要

本論文は、端末・クラウド分散推論（edge-cloud inference）で投機的復号（speculative decoding）を行うとき、草稿モデルが一度に生成するトークン数を通信遅延に応じて決める問題を扱う。端末には小型草稿モデル、クラウドには大きな検証モデルを置く。草稿を長くするとネットワーク往復の回数を減らせる反面、後方トークンまで連続して採択される確率は下がり、草稿計算が無駄になる。短い草稿は無駄が少ないが往復が増える。この二律背反を、検証で確定したトークン当たりの期待時間を最小化する**比率型最適停止問題**として解く。

理論上の主要成果は、独立した位置別採択率を一定値とみなす幾何モデルの下で、最適草稿長が有限であること、通信遅延が増えると最適長が短くならないこと、臨界遅延以下では草稿長1が最適であること、遅延増大に対して最適長が概ね対数的に増えることである。環境パラメータが未知なら、各草稿長を腕とする上側信頼限界型（Upper Confidence Bound; UCB）の学習器 **UCB-SpecStop** を用いる。時間と採択数の「平均の比」を使う点が、各回の時間／採択数を単純平均する方式と異なる。

実機では、端末Jetson Orin Nano Super（8GB）とクラウドRTX 3090 Ti（24GB）を接続し、Qwen系とLLaMA系の草稿・検証モデル対を評価した。片道遅延の掃引で最適草稿長が1から2以上に変わる位置は、Qwenで約83ms、LLaMAで約111msであった。SpecDec++との比較でトークン当たり遅延を最大22.4%削減する条件がある。ただし最大改善値は**Qwenの片道20msという特定条件**であり、全遅延条件での一律改善ではない。低遅延域では探索費用によって最良固定長より悪化し、LLaMAでは理論の幾何モデルと実測の先頭トークン採択が食い違う。こうした負の結果を含め、理論・校正・実機の範囲を分けて解釈する。

## 問題設定と既存研究との差

通常の自己回帰生成では、大きなモデルが1回の前向き計算で次のトークンを1個決める。投機的復号では小さな草稿モデルが先に複数候補を作り、大きなモデルがそれらを並列検証する。棄却が起きるまでの接頭辞だけを確定し、検証モデル側の追加トークンも得ることで、重いモデルを呼ぶ回数を減らす。分布を保存する検証規則を使えば、草稿の提案が外れても出力分布を目標モデルに合わせられる。したがって本論文の制御対象は「何を出力するか」ではなく「検証前に何トークン提案するか」である。

端末とクラウドを別装置にすると、草稿生成時間、検証計算時間、端末・クラウド間の往復時間が1周期の費用になる。草稿長kを伸ばすと端末計算は概ねkに比例して増えるが、同じ周期で確定できるトークンの期待数は採択率の減衰によって頭打ちになる。反対にkを1にすると採択効率は高くても、通信が遅いとトークン1個ごとにネットワーク待ちを払う。このため単一の固定kをどのネットワークにも適用する設計には構造的な無駄がある。

従来のSpecDec++は、草稿内容から推定する採択可能性をもとに草稿を早期終了する。これは内容依存の不確実性には反応できるが、通信遅延の増減を直接最適化するわけではない。SLEDやFlexSpec、ConfigSpecなど通信を考慮した分散推論方式もあるが、本論文が狙う差分は、草稿長の**最適解の構造を数式で特徴づけること**と、未知の環境でその最適化目標に整合する学習則と後悔上界を与えることである。GPU間の層配置、推論前処理・復号の分離、量子化ビット数の選択自体は主たる提案ではない。

## 手法

### 1. 1周期の時間と確定トークン数を結ぶ費用関数

草稿長をk、草稿モデルの1トークン計算時間をc_d、クラウドの検証費用をc_v、片道通信遅延をDとする。論文の簡略モデルは、草稿k個の生成、往復2D、検証モデルによるk+1位置の処理を合わせ、周期時間を `T(k,D)=k c_d+2D+(k+1)c_v` と置く。検証は複数位置を並列処理するものの、式では位置数に応じた有効費用として表現する。実機ではkによる処理効率の変化があるため、この定数c_d、c_vの式だけで測定を再現できるわけではない。

各草稿位置が条件付き独立に確率αで採択されると仮定する。長さkの草稿に対して、棄却までに確定できる接頭辞と検証モデルの追加トークンを含む期待確定数は `B(k)=(1-α^(k+1))/(1-α)` となる。分子の周期時間はkとともに伸びるが、分母B(k)は高々 `1/(1-α)` に飽和する。従って長い草稿を無限に延ばしても効率が良くなり続けることはない。平均片道遅延をdとすれば、最適化対象は `C(k,d)=[k(c_d+c_v)+2d+c_v]/B(k)` である。これは1周期の時間そのものを最小化する目的ではなく、**確定トークン1個当たりの時間**を最小化する目的である。

同じ草稿長でも採択率が高ければB(k)が大きくなり、より長い草稿を選ぶ余地が生まれる。一方、ネットワーク遅延dが大きくなると固定往復費用2dを多くの確定トークンで償却したくなる。両者の作用を同一のC(k,d)で比較できるため、通信・計算の単なる重み付き和ではなく、分子と分母を同時に追う必要がある。

### 2. 最適停止、閾値構造、臨界遅延

草稿を1個生成するごとに、さらに生成するか、現在の草稿を送って検証するかを選ぶ最適停止（optimal stopping）として定式化する。既知の平均遅延での費用関数C(k,d)は、採択数の増加が飽和するため、十分大きいkで必ず増加する。論文は離散的な単峰性と最初の費用交差を利用し、`C(k+1,d)≥C(k,d)` が初めて成り立つkを最適長として求められることを示す。

最適長の重要な性質は遅延単調性である。kが大きいほど期待確定数B(k)が大きいため、通信遅延dの増加は長い草稿に相対的に有利に働く。最小の最適解と最大の最適解のいずれも、dを増やして短くなることはない。従ってネットワークの往復時間が増えたときに、他条件が同じなら草稿長を短くする方策は、この簡略モデルでは最適でない。

さらに論文は、草稿長1と2の費用が交差する臨界片道遅延 `d_c=((c_d+c_v)(1+α))/(2α²)-(c_d+2c_v)/2` を導出する。dがこの閾値より小さければ長さ1が最適、閾値で1と2が同率、超えると複数トークン草稿が有利になり得る。最適長の増加は `Θ(log d / log(1/α))` の範囲にあり、遅延が2倍になっても草稿長を2倍にする必要はない。ただし、この閉形式は採択確率の幾何減衰や費用の定数近似に依存する。実際の採択確率が位置によって大きく変わる場合、臨界値の数値は実測で校正し直す。

### 3. 変動する通信路と状態依存の停止則

実ネットワークでは遅延が一定ではなく、通信路が良い状態と悪い状態を遷移する。論文はマルコフ変調通信路（Markov-modulated channel）へ問題を拡張し、観測した状態sに応じた往復費用を用いる。無限の草稿長を許す一般問題で無条件に閾値が成立すると主張するのではなく、有限の最大草稿長K_maxと、Dinkelbach変換で得られる停止領域の単調性を仮定して状態依存の閾値方策を示す。

Dinkelbach変換は、時間／確定数という比率の最小化を、候補の費用率λに対する `E[N−λ B]` の加法的最小化へ変換する操作である。これにより状態遷移を含むベルマン方程式（Bellman equation）で、続行と停止の費用を共通の単位で比較できる。良好な通信状態では短い草稿で頻繁に検証し、遅い状態では長い草稿で往復回数を抑える。通信状態を観測する価値がない場合は単一の固定長で足りるが、良好・不良の状態で最適kが異なる場合には状態観測が費用を下げ得る。

ただしこの状態依存則は、ネットワーク状態を正しく観測できること、遷移モデルや採択特性が適切に扱われることを前提とする。状態観測の計算・通信費用が大きい環境や、急激な分布変化でモデルが追従できない環境まで無条件に優越することは証明されていない。

### 4. UCB-SpecStop：未知環境での比率型オンライン学習

α、c_d、c_v、遅延分布が未知の場合、候補草稿長 `k∈{1,…,K_max}` を多腕バンディット（multi-armed bandit）の腕として扱う。各周期で選んだkに対して、実際に費やした時間N_tと確定トークン数A_tを観測し、腕ごとに累積時間S_N(k)、累積確定数S_A(k)、選択回数T_kを保持する。重要なのは費用推定量を `Ĉ_k=S_N(k)/S_A(k)` とする点である。各周期の比率 `N_t/A_t` を平均する方法は、分母A_tが変動するため `E[N]/E[A]` と一致せず、最適化対象とずれる。

選択則は、この推定費用から不確実性に応じた信頼幅を引き、**最も小さい楽観的費用**を持つ草稿長を選ぶ。信頼幅は `L_max sqrt(log(4 K_max T²)/T_k)` に比例する。まだ試していない草稿長は探索し、十分試した草稿長は測定された効率に基づいて活用する。選択後に実測時間と採択数を累積へ加えるため、環境を事前に完全に同定する必要がない。

論文の後悔（regret）上界は、最大遅延D_max、最大草稿長K_max、各周期の採択数の上下界などが成立し、探索係数βが十分大きい場合に導出される。最適腕との費用差Δ_kに依存する対数型上界と、差が小さい場合にも使える `O(L_max sqrt(K_max T log(K_max T)))` 型の上界がある。これは理論モデルの下で累積の余分な費用が時間とともに相対的に小さくなるという意味であり、有限回数の実験で常に最良固定長を上回るという意味ではない。

### 5. 実機での校正と1周期の実行経路

実装では、端末側の草稿モデルがk個の候補を生成し、ネットワーク経由でクラウドの検証モデルへ送る。検証結果から採択された接頭辞と追加トークンを確定し、実測された時間・採択数・通信状態を記録する。次の周期のkは、通信遅延が既知なら閾値表や校正された費用曲線から、未知ならUCB-SpecStopの蓄積統計から選択する。これを生成終了まで繰り返す。

理論式のc_dとc_vはkによらない定数だが、実機ではまとめて検証するトークン数に応じて実効費用が変化する。そこで論文はR1で各kの計算時間を測り、R2で採択接頭辞の長さごとの確率を測り、R3で遅延と草稿長の費用格子を構築する。理論の幾何分布をそのまま使う予測と、実測採択曲線を使う経験的な予測を分ける。後者は単純モデルの限界を補うが、校正用の実測と計算が必要であり、測定条件から大きく外れたネットワーク・モデル対に無検証で適用するべきではない。

## 評価

### 実験条件と測定指標

論文の実験は、R1（腕別計算費用の校正）、R2（位置別採択率）、R3（臨界遅延の測定）、R4（方式比較）、R5（オンライン後悔と探索係数感度）、R6（通信状態の観測価値）の6段階で構成される。遅延はLinuxの`tc netem`で注入しており、物理的に離れた広域ネットワーク上で長期運用した測定ではない。片道遅延dを注入した実験と、往復遅延（RTT）を同じ値として読むことはできない。

| 条件 | 設定・観測値 |
|---|---|
| 端末 | NVIDIA Jetson Orin Nano Super、8GB、0.5B～1B草稿モデル |
| クラウド | NVIDIA RTX 3090 Ti、24GB、7B～8B検証モデル |
| Qwen対 | Qwen2.5-0.5B草稿 / Qwen2.5-7B-Instruct検証 |
| LLaMA対 | Llama-3.2-1B-Instruct草稿 / Llama-3.1-8B-Instruct検証 |
| 通信 | ローカルネットワーク、Linux `tc netem`による片道遅延注入 |
| 校正時の基本往復時間 | Qwen 10.01ms、LLaMA 9.02ms |
| R3の片道遅延d | 0、5、20、40、55、83、111、150ms |
| R4 | 各方式1,000周期、同じ入力列と遅延設定 |
| R5 | 臨界近傍で5,000周期、後悔の経時推移を比較 |

トークン当たり時間（ms/token）は、小さいほど同じ確定トークン数を短時間で生成できる指標である。比較の中心は `Σ時間/Σ確定トークン数` であり、個々の周期のms/tokenの単純平均ではない。これは推論サービスの同時要求処理量や初回トークン時間（TTFT）とは別の指標である。草稿の採択率は「生成した草稿の何割がその位置まで連続採択されたか」を測り、検証モデルの出力品質そのものの評価ではない。

### 採択率の校正と理論モデルのずれ

R1の腕別費用は、Qwenの草稿1トークン当たり平均85.14ms、検証平均8.09ms、LLaMAでは67.37msと8.37msである。ただしk=1とk=10の実効草稿費用はQwenで106.25msと73.70ms、LLaMAで90.40msと52.59msへ変化する。まとめて生成・検証する長さが計算効率にも影響するため、理論の定数費用は近似である。

R2では、草稿の最初の位置の採択確率がQwenで0.462、LLaMAで0.382なのに対し、2位置目以降の幾何的な減衰率はそれぞれ約0.828、0.845と推定される。先頭だけ採択が低く、後続は比較的高い「重い先頭（heavy-head）」の形であり、全位置を一つのαで表す仮定に反する。このため論文は理論的な幾何予測に加えて、実測の位置別採択確率を使う経験的な最良固定長を比較基準に置く。特にLLaMAでは幾何予測が高遅延での適切なkを過小評価する。

### 臨界遅延と最適草稿長

R3では、片道遅延が増えると最良の草稿長が階段状に増え、Qwenは83ms、LLaMAは111msで初めて1より大きくなる。以下は論文表IIIの実測最適長と、そのときのトークン当たり時間である。これは各遅延条件で事後的に最適kを選んだ**校正結果**であり、UCB-SpecStopのオンライン実行時間とは区別する。

| 片道注入遅延d | Qwen最適k | Qwen ms/token | LLaMA最適k | LLaMA ms/token |
|---:|---:|---:|---:|---:|
| 20ms | 1 | 138.52 | 1 | 134.12 |
| 55ms | 1 | 187.19 | 1 | 180.82 |
| 83ms | 2 | 223.00 | 1 | 221.63 |
| 111ms | 3 | 251.45 | 4 | 251.76 |
| 150ms | 4 | 287.68 | 7 | 293.72 |

Qwenのkは55→83→111→150msで1→2→3→4、LLaMAは1→1→4→7となる。単調増加という定性的予測には合うが、LLaMAの実測k=7に対し幾何モデルの予測はk=3であり、**理論の構造が合うことと個別数値が合うことは異なる**。最適kはモデル対・採択特性・計算費用を校正しない限り移植できない。

### UCB-SpecStopと比較方式の絶対遅延

R4では固定草稿長、ゼロ遅延を想定する貪欲則、SpecDec++、理論最適長、校正済み幾何最適長、経験的最良固定長、素朴なUCBを比較する。論文表IVから代表条件を抜き出す。各列は同じモデル対と片道遅延でのms/tokenであり、低いほどよい。

|---|---:|---:|---:|---:|
| Qwen・20ms | 139.38 | 212.23 | 142.77 | 164.78 |
| Qwen・55ms | 189.31 | 250.18 | 191.67 | 214.78 |
| Qwen・111ms | 269.55 | 298.33 | 272.29 | 276.04 |
| Qwen・150ms | 299.29 | 312.80 | 298.07 | 299.92 |
| LLaMA・20ms | 130.81 | 168.24 | 135.05 | 141.46 |
| LLaMA・55ms | 178.02 | 203.56 | 180.50 | 180.76 |
| LLaMA・111ms | 256.53 | 261.10 | 264.59 | 261.94 |
| LLaMA・150ms | 304.63 | 301.98 | 324.28 | 301.40 |

Qwen・20msでSpecDec++の212.23ms/tokenから164.78ms/tokenへの短縮は22.4%に相当し、要旨の最大改善に対応する。ただし経験的最良固定長139.38ms/tokenよりは18.2%遅い。低遅延条件では多腕探索の追加費用が目立ち、静的な最適kが分かっていればオンライン学習は不要な場合がある。Qwen・55msでも経験的最良固定長比で13.5%悪い。一方、Qwen・150msでは経験的最良固定長との開きが0.2%まで縮む。

LLaMA・150msでは素朴なUCBが324.28ms/tokenなのに対し提案法は301.40ms/tokenで、素朴方式に対して約7.5%の追加費用を避けている。ここではオフライン最良**固定**長304.63ms/tokenよりも良いが、これは各周期で腕を混ぜる方策と有限標本の比率集計の結果であり、完全に適応する最良方策を超えたという証明ではない。比較対象の「オラクル（oracle）」は最良固定腕である点を明確にする必要がある。

### オンライン学習、探索係数、通信状態の価値

R5では臨界近傍で5,000周期の累積後悔を調べ、UCB-SpecStopと素朴なUCBの両者に概ね平方根型の成長傾向が観測される。ただしQwenの最終累積後悔は提案法447,657ms、素朴なUCB448,805msであり、LLaMAでも65,601ms対65,651msと差は小さい。論文自身が**95%信頼区間の中に収まる差**と記しており、この条件で提案法が統計的に明瞭に勝ったとは主張していない。比率型推定の採用根拠は、特定の実測点差よりも目的関数との整合と理論的保証にある。探索係数βの感度実験では0.5～2.0で平均後悔がほぼ横ばいで、最小平均はβ≈1.5付近だが信頼区間は重なる。

R6では、良好・不良状態を各周期0.1の確率で切り替える2状態マルコフ通信路を使う。Qwenの良好／不良片道遅延は37／111ms、LLaMAは27／83msで、いずれも状態別最良kが1／2になる。通信状態を知らない学習器と比較し、状態を観測する方式はQwenで228.72→221.82ms/token（3.02%改善）、LLaMAで240.32→223.95ms/token（6.81%改善）となる。これは状態が異なる最適草稿長を持つときに通信状態の観測が役立つことを支持する。ただし二状態・対称遷移・注入遅延での実験であり、複雑な移動通信網全体で同じ改善率になるとは限らない。

## 限界と適用上の注意

第一に、理論は独立した一定採択率αと草稿長によらない計算費用に依存する。実測では最初の草稿位置の採択率が低く、草稿長によって実効計算費用も変わる。幾何モデルは最適草稿長の方向性を説明するが、LLaMAの高遅延条件で正確なkを与えない。採択分布がさらに重い裾を持つ場合、最適長の対数増加という定量的結論もそのままは成り立たない。

第二に、実験は単一の端末・クラウド対、2種類のモデル対、人工的な片道遅延注入に限定される。多数同時要求、クラウドGPUの競合、通信断、パケット損失、実際の移動体ネットワークの揺らぎ、デバイス消費電力、検証モデルを大規模に分散配置した場合は本研究の主評価対象ではない。R4の改善率を大規模サービングの要求処理量、SLO適合率、エンドツーエンド応答時間の改善と読み替えない。

第三に、オンライン制御には探索費用があり、低遅延域では経験的最良固定長より明確に悪化する。モデル対と通信路が安定していて最良kを事前校正できる場合、固定長の方が簡単で速い可能性がある。状態依存方式は通信状態の観測価値がある条件でのみ優位性が期待できる。通信路の状態遷移や草稿モデルの採択率が時間とともに大きく変化するときの再学習費用は別途評価が必要である。

第四に、R5での提案法と素朴なUCBの最終後悔の差は信頼区間内であり、有限回の実験での一貫した優越を示すものではない。理論の後悔上界も、有界な遅延と採択数、適切な探索係数、確率過程に関する仮定の下での保証である。品質を落とさない投機的検証自体は既存の正しい検証規則に依存し、草稿長制御だけが目標モデルと同じ出力分布を保証するわけではない。

## 既存方式との比較と実装上の示唆

本研究の貢献は、草稿モデルを新しく学習することやGPUカーネルを改良することではなく、通信遅延を含む投機的復号の実行費用を**トークン当たりの比率目的**として明示し、最適長の性質とオンライン選択則を結び付けた点にある。SpecDec++のような内容依存の早期終了器とは制御信号が異なり、両者の併用は検討余地があるが本論文で実証された組合せではない。固定長方式に対しては、環境が安定しているなら事前校正で足り、遅延が変動する場合に適応制御の価値が生じるという適用境界を示している。

実装する場合は、まずモデル対ごとに草稿長k別の生成時間、検証時間、位置別の採択接頭辞分布を実測し、ネットワークの片道遅延をRTTと区別して観測する。次に固定長の最良条件と、実行中に草稿長を変える方式を同じ入力列・通信条件で比較する。オンライン制御では1周期ごとのms/tokenを単純平均せず、累積時間を累積確定トークン数で割る。ネットワーク状態を使う場合は、状態別に最良kが実際に変わるかを確認してから観測・学習の追加費用を支払う。これらは論文の理論と実機評価から導ける設計上の示唆であり、他のGPUやランタイムでの同等改善を保証するものではない。
