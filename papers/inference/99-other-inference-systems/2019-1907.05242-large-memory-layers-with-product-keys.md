# Large Memory Layers with Product Keys：積キーによる大容量記憶層

## 概要

通常の密な順伝播層はパラメータを増やすと毎トークンの行列積が重くなる。キーと値を大量に持つ記憶層も、全キーと問い合わせを照合すれば記憶容量に比例した探索費用が生じる。本論文の積キー記憶層（Product Key Memory; PKM）は、二つの部分キー集合の直積で巨大なキー集合を暗黙的に作り、各部分集合の上位候補だけを調べて**全積キー集合に対する正確な上位選択**を行う。検索結果に対応する少数の値ベクトルだけを読み出して加重和を計算するため、総パラメータ容量と活性計算量を分離できる。

著者は約280億語の英語ニュースを学習した自己回帰型Transformerで評価した。隠れ次元1024、12層に記憶層を1個挿入した構成のテスト困惑度は15.6184で、記憶なし12層の17.6566、記憶なし24層の16.0186より良い。論文図4の12層＋記憶と24層の構成比較では推論速度がほぼ2倍だった。これは**記憶層を同じ12層モデルに追加したら速度が2倍になる**という意味ではなく、半分の層数でも予測精度を上回れるという構成上の交換条件である。

## 問題設定と既存研究

学習可能な記憶を大きくすると、通常のキー・値記憶では入力ごとに大量のキーを比較する必要がある。キー数が百万規模なら、その内積計算や索引維持が重い。先行する近似最近傍索引型の疎記憶では、学習中にキーが更新されるため索引を繰り返し再構築しなければならず、索引と学習済みキーのずれが検索品質へ影響する。これに対してPKMは、近似索引を外付けするのではなく、検索空間自体を直積として設計し、学習可能なキーを保ったまま厳密な検索を実現する。

本方式は後年の混合専門家モデル（Mixture of Experts; MoE）に通じる条件付き計算の一種と考えられるが、専門家間の分散配置やCPUへの退避を直接解決するものではない。値表を巨大化させても毎回アクセスする値を少なくできる一方、値ベクトルを格納する**物理的な重みメモリ容量は必要**である。この区別は、GPUメモリ削減を主張する研究と比較する際に重要となる。

## 手法

### 問い合わせ生成と利用率の制御

入力隠れ状態を $x\in\mathbb{R}^{d}$ とし、問い合わせ網 $q(x)$ で $d_q$ 次元のベクトルへ変換する。論文の典型設定は $d_q=512$ で、線形層または多層パーセプトロンを使う。キーはランダム初期化されるため、学習初期の問い合わせが狭い領域へ偏ると、選ばれない値スロットが更新されず、記憶容量を増やしても予測性能が伸びにくい。問い合わせ網の後段にバッチ正規化（Batch Normalization）を挿入し、問い合わせ分布を広げて多くのキーが学習で利用されるようにする。これは推論の検索アルゴリズムだけでなく、学習中の値スロット利用率を改善する構成である。

### 二組の部分キーによる正確な上位選択

二つの部分キー集合 $\mathcal{C},\mathcal{C}'$ を持ち、各キーの次元を $d_q/2$ とする。全キーは組 $(c_i,c'_j)$ の集合であり、各部分集合の大きさを $n$ とすると全キー数は $n^2$ となる。問い合わせも $q=(q_1,q_2)$ に分割する。直積キーのスコアは $q_1^Tc_i+q_2^Tc'_j$ に分解できるので、まず二つの部分集合でそれぞれ上位 $k$ 個を選び、その最大 $k^2$ 組の中から最終上位 $k$ 個を選ぶ。

全キー上位 $k$ 組がこの直積候補内に入るのは、片側の部分キーが上位 $k$ に含まれなければ、反対側を固定してそれより得点の高い $k$ 個の組を構成できるためである。したがって選択は**定義された直積キー集合について厳密**であり、近似最近傍探索のような取りこぼし率を持ち込まない。ただしこれは生成回答の正確性や他の任意のキー集合への最適性を保証するものではない。

平坦な全キー照合の演算量 $O(|\mathcal{K}|d_q)$ に対し、等サイズの部分集合を使う場合は $O((\sqrt{|\mathcal{K}|}+k^2)d_q)$ となる。キーが $1024^2$ 個で $k$ が小さい場合、論文は検索演算を全件比較の約千分の一にできると述べる。しかし、GPUでの値表への散在アクセス、候補選択、複数頭の処理が残るため、モデル全体が千倍高速になるわけではない。

### 値ベクトルの疎な読み出しと学習

最終的に選んだキー集合 $\mathcal{I}$ に対して内積スコアをソフトマックス正規化し、$m(x)=\sum_{i\in\mathcal{I}}w_i v_i$ を返す。$v_i$ は入力トークンから動的に作る自己注意の値ではなく、学習可能な記憶パラメータである。順伝播で上位 $k$ 個だけを読み、逆伝播でも選択された値を中心に疎に更新する。総値表を全入力で密に掛け算する方式と異なり、記憶容量を増やしてもアクセス数は主として $k$ と頭数に支配される。

値表の大きさ自体は $|\mathcal{K}|$ に比例する。したがって「検索が平方根規模」という主張は、重み保存領域やCPU・SSDからの転送量が平方根規模になるという意味ではない。特にオフロード構成では、選択した値の不規則な読み出しが帯域と遅延を制約する可能性があるが、原著はその構成を実験していない。

### 複数記憶頭とTransformerへの組込み

複数頭の記憶検索では、頭ごとに独立した問い合わせ網と部分キー集合を持つが、値表は共有する。各頭が選んだ値の重み付き和を合算する。これは通常の自己注意で特徴次元を頭に分割する方式とは違い、各頭が独立の問い合わせを作って**共通の大きな値表を参照**する設計である。頭数 $H$ と各頭の選択数 $k$ を増やすと、入力ごとの最大参照数は概ね $Hk$ に増える一方、問い合わせ生成や候補選択の費用も増す。主実験では $H=4,k=32$ を用いた。

Transformerでは一部層の順伝播網（Feed-Forward Network; FFN）をPKMへ置換し、残差経路に $x\leftarrow x+\mathrm{PKM}(x)$ を適用する。例えば16層に2記憶を配置する場合は第6層と第12層のFFNを置換する。処理は「隠れ状態→問い合わせ生成→二分割→部分キー検索→直積候補の再選択→疎な値参照→加重和→残差加算→次層」の順であり、原著の実験は通常FFNを残したまま単純に追加する方式と同一ではない。

## 評価

### 評価環境と指標

| 項目 | 原著で確認した条件 |
|---|---|
| タスク | 自己回帰言語モデルの次語予測。評価はテスト困惑度（低いほど良い）と推論語数/秒 |
| 学習データ | Common Crawl由来の英語ニュース約4000万記事、約280億語、140GB |
| 検証・テスト | 学習から除いたニュース各5000記事、60kのバイト対符号化（BPE） |
| モデル | 12・16・24層、隠れ次元1024または1600、注意頭16 |
| 記憶の主設定 | $512^2=262144$ 値スロット、記憶頭4、各頭の上位 $k=32$ |
| 学習環境 | PyTorch、32基のVolta GPU、半精度演算、Adam |
| 構成要素除去 | 主に6層・注意頭8の小型構成で容量・正規化・位置・頭数・検索方式を比較 |

記憶利用率はテスト入力の全体で一度以上参照された値スロットの割合であり、GPUメモリ使用率やキャッシュ命中率ではない。値へのアクセス分布と一様分布のKL発散も報告され、低いほど特定スロットへの集中が小さい。速度はモデル構成に依存するため、異なる表の速度数値を同一実験条件として混ぜない。

### モデルの深さと予測性能

| 隠れ次元 | 構成 | テスト困惑度 | 意味 |
|---|---|---:|---|
| 1024 | 12層・記憶なし | 17.6566 | 同じ深さでの追加効果の基準 |
| 1024 | 12層・記憶1個 | 15.6184 | 同じ12層で予測性能が改善 |
| 1024 | 12層・記憶2個 | 14.7886 | さらに記憶を増やすと改善 |
| 1024 | 12層・記憶3個 | 14.4727 | 記憶増設の追加効果 |
| 1024 | 24層・記憶なし | 16.0186 | 12層＋記憶1個に劣る |
| 1600 | 12層・記憶なし | 14.9994 | 同次元の基準 |
| 1600 | 12層・記憶1個 | 13.6522 | 24層・記憶なし13.9515より良い |
| 1600 | 24層・記憶なし | 13.9515 | 比較対象 |

原著表1と図4は、密な層を深く積む代わりに疎な記憶を使うと、同じ隠れ次元でも良い困惑度と高い語/秒を両立できることを示す。隠れ次元1024の12層＋記憶1個は24層・記憶なしより推論がほぼ2倍速い。ただしこれは層数の違う構成比較で、全てのGPU・バッチ・系列長で一定倍率を保証する結果ではない。

### 記憶容量と問い合わせ正規化の感度

| 値スロット数 | 正規化 | 困惑度 | 利用率 |
|---:|---|---:|---:|
| 16k | なし | 22.7972 | 100% |
| 262k | なし | 20.4776 | 64.4165% |
| 262k | あり | 19.7805 | 97.8580% |
| 1M | なし | 19.7913 | 25.8314% |
| 1M | あり | 17.9819 | 80.3043% |

原著表2では、1Mスロットに拡張しても正規化なしでは利用率が25.8%に落ち、正規化を入れると80.3%に改善する。困惑度も19.7913から17.9819へ低下した。値表の容量だけでなく、問い合わせがどれだけ広い値領域を選択するかが精度に効くことを支持する。1MでのKL発散は正規化なし2.0609に対して正規化あり0.9497で、アクセス偏りも小さい。

### 平坦キーと積キーの速度差

| 値スロット数 | 平坦キー（千語/秒） | 積キー（千語/秒） |
|---:|---:|---:|
| 16k | 35.0 | 35.8 |
| 65k | 28.5 | 36.7 |
| 147k | 13.9 | 36.4 |
| 262k | 7.7 | 36.3 |
| 1M | 1.2 | 35.7 |

原著表4は6層の構成要素除去実験であり、1Mスロットでの35.7/1.2≒29.8倍は**平坦キー検索と積キー検索を用いたモデル同士の比較**である。主実験の12層対24層のほぼ2倍という結果とは比較対象が異なる。小容量16kでは差が小さく、容量が増えるほど全件照合の費用が顕在化する。一方、積キーは選択する値の数が固定されている限りほぼ一定の語/秒を保った。

### 挿入位置・頭数と負の結果

6層構成で記憶を第1層へ置いたときの困惑度21.4669に対し、第4層20.0513、第5層19.7805、第6層20.2931であった。初期層では抽象特徴が十分形成されず、最後の層では検索結果を後続層で加工する余地が少ない可能性を著者は指摘する。第5層が最良というのはこの6層条件の観測であり、全モデルで固定の層番号が最適とは言えない。頭数 $H$ と選択数 $k$ の積が64となる複数構成では、利用率が約70%、困惑度が約20.5と近く、単に頭数だけを増やしても利得が単調に増えない。頭数増加は検索・集約の追加費用を伴う。

## 既存研究との差

Raeらの大容量記憶は外部近似索引の再構築を必要としたのに対し、PKMは学習可能な部分キー集合そのものを検索構造にしている。積量子化（Product Quantization）に着想を得ているが、固定データベースを量子化して近似検索する方式とは違い、値スロットを学習するニューラルネットワーク層である。混合専門家モデルと同様に条件付きで少数のパラメータを活性化するが、専門家間の通信・分散配置・負荷分散スケジューラを設計するものではない。

## 限界・適用条件

第一に、値表の全パラメータを保存するメモリは必要である。検索演算を平方根規模に減らしても、値スロットが百万個ならその分の値ベクトルを保持しなければならない。CPUメモリやSSDへ退避した場合の帯域、PCIe転送、キャッシュ命中率は原著の実験対象外である。疎な値参照はGPUメモリアクセスの局所性に影響する可能性があるが、2019年の結果から現行ハードウェアでの性能を断定できない。

第二に、記憶利用率は学習の分布に依存する。1Mスロットの正規化なしで利用率25.8314%という負の結果は、大きい値表だけでは容量を使い切れないことを示す。正規化ありでも80.3043%であり、全値スロットが均等に使われるわけではない。頭数と選択数を増やすとアクセス数・計算費用が増え、挿入層の選択によって予測性能が悪化する。

第三に、評価は英語ニュースの次語予測を中心とし、現代の対話LLMの回答品質、長文脈のKVキャッシュ、複数要求の待ち行列、初回トークン遅延、分散サービングのスループットを測っていない。主結果の「ほぼ2倍」は特定の12層対24層の比較であり、モデル全体の推論速度が検索演算削減倍率に比例するわけではない。
