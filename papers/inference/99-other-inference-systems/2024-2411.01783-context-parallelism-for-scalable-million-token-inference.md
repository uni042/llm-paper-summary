# Context Parallelism for Scalable Million-Token Inference

## 概要
百万トークンのプレフィルでは、単一GPUに全系列のKVと注意中間状態を置くことが難しく、注意計算量も巨大になる。テンソル並列だけではモデル重みを分けても系列長方向の状態が残る。文脈並列（context parallelism）は入力系列をGPU間で分割し、各GPUが一部トークンだけを保持・計算することで、メモリとプレフィル計算をGPU数へ分散する。

本論文は近似や疎化を使わず、正確なソフトマックス注意をリング通信で実行する二方式、pass-KVとpass-Qを提示する。完全プレフィルだけでなく、既存KVを再利用するプレフィルとデコードで通信方向を使い分ける。16ノード128基のH100でLlama 3 405Bの1Mトークンプレフィルを77秒、並列化効率93%、浮動小数点演算利用率63%で実行し、128Kでは3.8秒を報告する。

## 問題設定
長文脈の注意は各queryが多数のkey/valueを参照するため、系列をGPUへ単純分割するとGPU間で情報交換が必要になる。全K/Vを全GPUへ一括複製すればメモリ削減を失い、逐次通信すれば通信待ちが演算を止める。

さらにプレフィルとデコードでは形状が異なる。完全プレフィルはQ/K/Vがいずれも長いが、デコードでは新規Qが小さく既存KVが巨大である。一つの通信方式だけでは、ある局面でネットワーク転送量が不利になる。

## 手法
### pass-KV
各GPUはローカルqueryを保持し、K/Vのチャンクをリング上で隣GPUへ渡す。受け取ったK/Vに対してローカルQの部分注意を計算し、次のK/V転送と計算を重ねる。全K/Vチャンクを一周させれば、各Qは全系列を正確に参照できる。FlashAttention型のオンラインsoftmax集約により、全注意行列を保持せず部分結果を正規化して統合する。

### pass-Q
逆にK/Vを所有GPUへ固定し、Q側をリングで回す。各GPUは受信Qと自分のK/Vから部分出力・softmax統計を作り、結果を集約する。既存KVが巨大で新しいQが小さい局面では、K/V全体を動かすよりQを動かす方が通信量を抑えられる。

### ワークロード別選択
完全プレフィル、永続KVプレフィル、デコードではQとKVの相対サイズが違うため、実装はpass-KV/pass-Qを使い分ける。リング通信とattention kernelを重畳し、ネットワーク転送をGPU計算の背後へ隠す。RDMAだけでなくTCP接続でもスケーリングを評価し、中低帯域の一般的なデータセンターネットワークへの適用性を確認する。

## 評価条件・主要結果
|観点|条件・結果|
|---|---|
|モデル|Llama 3 405B|
|GPU|最大128 NVIDIA H100|
|ノード|最大16ノード|
|ネットワーク|RDMAおよびTCPを評価|
|1Mプレフィル|77秒|
|1M並列化効率|93%|
|1M FLOPS利用率|63%|
|128Kプレフィル|3.8秒|

93%の並列化効率は、GPUを増やした際に通信が支配して速度向上が早期飽和していないことを示す。RDMAとTCPの双方で似たスケーラビリティを観測した点は、超高価な専用相互接続だけを前提にしないという設計主張を支える。

## 既存研究との差
系列並列・リング注意の発想自体は学習にも存在するが、本研究はLLM推論の完全プレフィル、既存KV付きプレフィル、デコードを同じ枠組みで扱い、QとKVのどちらをリング転送するかをワークロード形状に合わせる。疎注意やKV削除とは異なり、出力は完全注意と同じで品質近似を導入しない。

## 限界
多数GPUを使うことで単一要求のプレフィル遅延を下げるため、GPU資源消費との交換条件がある。デコードはプレフィルより演算密度が低く、同じスケーリング特性とは限らない。評価はH100クラスタとLlama 3 405Bを中心とし、少数GPU・小型モデルでは通信固定費の割合が増える可能性がある。
