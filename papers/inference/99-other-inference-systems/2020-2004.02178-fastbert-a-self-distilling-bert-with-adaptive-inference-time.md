# FastBERT: a Self-distilling BERT with Adaptive Inference Time

## 概要

FastBERTは、入力文が容易でも難しくてもBERTの全12層を通過させる従来の固定深さ推論を、**入力ごとに必要な層数を変える分類推論**へ置き換える。12層の中間出力に小型の分類器を付け、その時点の予測確率が十分に集中していれば後続の層を実行しない。予測が曖昧な入力は後段へ送り、最終層まで到達した場合は教師分類器の出力を用いる。この設計は文章生成の各トークンを省略する方式ではなく、主に文章分類と文対照合に適用される。

中間分類器をそのまま教師あり学習するのではなく、先に最終層の教師分類器をタスクに適応させ、教師の確率分布を中間層へ蒸留する点が重要である。これにより、入力を途中で止めても深い層が持つクラス間の関係を利用できる。早期終了の閾値は正規化エントロピーに対して設定するため、運用者は一組のモデル重みで演算量と精度の交換条件を変更できる。

ACL 2020論文は中国語6件、英語6件の計12データセットで、基準BERTに対する入力当たりの浮動小数点演算回数（FLOPs）の比率を報告する。例えば中国語THUCNewsでは閾値0.1で分類精度96.71%を維持しつつ計算量が約6.05分の1、英語DBpediaでは同閾値で99.31%から99.28%への微小な低下と引き換えに約10.57分の1となる。ただし英語Amazon Fullでは同じ閾値でも約1.03倍の削減にとどまり、**入力難度の分布が利得を強く左右する**。これらは演算回数の比であって、GPUでの実測遅延倍率と読み替えてはならない。

## 問題設定と従来方式の不足

BERT-baseは約1億1000万パラメータ、12層の双方向エンコーダであり、分類時には全入力が全層を通る。単純な肯定・否定の短文と、曖昧な文対照合を同じ深さで処理すると、前者では後段の特徴抽出が不要な場合がある。一方で、すべての入力を浅いモデルへ統一すると、難しい事例で精度を失う。FastBERTが解こうとするのは、固定計算の過剰と固定小型化の精度不足を同じ推論系で緩和することである。

BERTを6層や3層へ圧縮する通常の知識蒸留では、推論開始後に入力別の計算予算を変えられない。重み枝刈りや量子化はモデル内の演算・表現形式を変更するが、分類が十分確信できた入力を後段層から除外する仕組みとは別である。FastBERTはモデル全体を複数個配置する代わりに、同じエンコーダの中間表現を使う分岐を増設し、実行する層数そのものを変える。

この選択が正しく機能するには、浅い層の分類器が確信を持つときに実際の正答率も高いことが必要である。論文はこの関係を「不確実性が低いほど正確である」という仮説（LUHA）として置き、単なる固定深さの比較に加えて不確実性区間ごとの正答率を調べている。確信度が高いが誤っている事例では早期終了が品質低下を生むため、エントロピーは完全な正解保証ではない。

## 手法：エンコーダ、自己蒸留、早期終了

### 1. 共通エンコーダと中間分類枝

入力文は語彙、位置、文区分の埋め込みを足し合わせた系列 `e` に変換される。各層の隠れ表現を `h_i = Transformer_i(h_{i-1})` として順次更新する。12層の最後にはタスクの教師分類器を置き、最終隠れ表現からクラス確率 `p_t` を出す。中間層のそれぞれには、同じ層の隠れ表現 `h_i` を受け取る学生分類器を接続し、クラス確率 `p_{s,i}` を出す。重要なのは、学生分類器が次層の特徴を計算する前に判定できることであり、早期終了が成立した入力については残りのTransformer層を実行しない。

分類器は768次元の特徴を128次元へ縮約し、128次元で自己注意と全結合を適用してクラス数に応じた確率へ射影する。論文表1のモデル化では、Transformerの1ブロックが約1,809.9百万回の浮動小数点演算なのに対し、分類器は約46.1百万回である。したがって、浅い層で終了できる入力が十分あれば、分類枝の追加費用より省略するTransformer層の費用が大きい。この比較は演算量の内訳であり、GPU実装時のメモリ転送やカーネル起動の費用を直接測ったものではない。

### 2. 教師のタスク適応と学生の自己蒸留

学習は三段階に分かれる。第一にBERT系の事前学習済みエンコーダを利用する。第二に対象タスクのラベル付きデータを使い、共通エンコーダと最終教師分類器を微調整する。この段階では中間学生分類器は動作させない。第三に共通エンコーダと教師を固定し、各中間学生分類器だけを教師のクラス確率へ近づける。中間分類器同士は独立しているため、浅い層と深い層がそれぞれ同じ教師分布を目標にできる。

自己蒸留の損失は、各学生の予測分布 `p_{s,i}` と教師分布 `p_t` のカルバック・ライブラー情報量（KL divergence）の総和として定義される。教師が例えば肯定0.75、否定0.20、中立0.05と出す場合、学生は最大確率のラベルだけでなく、残りのクラスにどの程度の確率を配分すべきかも学ぶ。論文はこの柔らかな教師分布を使うため、教師を確定した後の蒸留では追加の人手ラベルを必須としないと説明する。ただし教師自身の誤りや確信度の偏りは学生へ継承され得る。

通常の別モデルへの知識蒸留と違い、学生は独立した小型BERT全体ではない。共通エンコーダの途中に付けた分類器である。従って複数の推論深さを提供するために、層ごとに別のエンコーダ重みを保存する必要がない。一方、分類器枝は各層の出力に接続するため、学習時の枝の追加パラメータと、推論時に不確実性を計算する費用はゼロではない。

### 3. 正規化エントロピーによる入力別の終了判定

各層の学生分類器がクラス確率 `p_{s,i}` を出したら、`-Σ_c p_{s,i}(c) log p_{s,i}(c) / log N` で正規化エントロピーを求める。`N` はクラス数であり、全クラスへ均等な確率を割り当てたときは1に近く、単一クラスに確率が集中すれば0に近い。クラス数の異なるデータセットでも値の範囲を0〜1にそろえられる。論文が「Speed」と呼ぶ閾値は、この不確実性と比較される停止境界である。

不確実性がSpeedより小さければ、その入力はその層の分類結果を確定して終了する。閾値以上なら次のTransformer層へ送る。バッチに4入力があれば、1層目で2件が終了し、残る2件だけを2層目へ送ることができる。閾値を大きくすると浅い層で終了する入力が増えて計算量は減るが、まだ誤りやすい入力も早期終了し得る。逆に閾値を厳しくすると多くの入力が後段まで進み、精度を守りやすいが演算削減幅は縮む。

この方式では、停止するかどうかの判断は教師の正解ラベルを推論時に参照しない。実際に使用するのは学生の予測分布だけである。したがって学習時に教師の確率分布を使う段階と、実行時に学生の不確実性を使う段階を区別する必要がある。また、エントロピーの低さは正答を数学的に保証しないため、閾値は評価データで精度との関係を確かめて選ぶべき制御量である。

### 4. 一つの要求が通過する経路と追加費用

処理順をまとめると、入力文の埋め込みを作り、Transformer層を1層進め、中間分類器で確率を計算し、その正規化エントロピーとSpeedを比較する。終了条件を満たせばその場で分類ラベルを返し、満たさなければ同じ系列表現を次層へ渡す。最終層まで残った入力は最終教師分類器の出力を用いる。この反復によって、入力難度の分布が層別の計算量へ変換される。

ただし論文の演算量評価は、動的にバッチを縮めるためのデータ再配置、GPU上での分岐制御、入力ごとの層数差が並列性に与える影響を十分には評価していない。早期終了する入力が多くても、少数の難しい入力が同じGPU実行単位に残れば、壁時計の処理時間はFLOPs削減率ほど短くならない可能性がある。この点は論文の演算量ベースの主張と、実際のオンラインサービングへ導入するときの設計課題を分けて理解すべきである。

## 評価条件と比較方式

論文は中国語のChnSentiCorp、書籍レビュー、商品レビュー、LCQMC、Weibo、THUCNewsと、英語のAG News、Amazon Full、DBpedia、Yahoo、Yelp Full、Yelp Polarityを用いる。中国語は文章分類5件と文対照合1件、英語は文章分類6件である。BERTとFastBERTにはGoogleのBERT事前学習済み重みを用い、固定深さの比較には6層のDistilBERTと、同様の蒸留方法で作った3層・1層版を含める。

| 評価条件 | 論文で固定・指定された値 | 解釈上の役割 |
|---|---|---|
| エンコーダ | 12層、注意ヘッド12、隠れ次元768 | FastBERTとBERTの基本構成をそろえる |
| 入力系列長 | 最大128トークン | 長文脈・生成モデルでの利得を直接示さない |
| 微調整 | AdamW、学習率2×10^-5、warmup比0.1、3エポックから最高精度を選択 | 教師のタスク適応条件 |
| 自己蒸留 | 学習率2×10^-4、5エポック | 学生分類器の教師確率への適応 |

## 評価結果：演算量、正答率、入力難度

論文表2は正答率と平均FLOPsを対で報告する。倍率は常に同じデータセットの12層BERTを1倍とした**計算量比**である。以下の数値は表2から取り、正答率は百分率、FLOPsは百万回単位とする。異なるデータセットの倍率を直接比較して「どのGPUでも高速」と結論付けることはできない。

| データセット・条件 | 比較BERTの正答率 / FLOPs | FastBERTの正答率 / FLOPs | BERT比削減倍率 | 読み取れること |
|---|---:|---:|---:|---|
| ChnSentiCorp、Speed 0.1 | 95.25% / 21,785M | 95.25% / 10,741M | 2.02倍 | 精度を維持して約半分の演算量 |
| ChnSentiCorp、Speed 0.8 | 95.25% / 21,785M | 89.75% / 2,315M | 9.40倍 | 大きな演算削減には5.50ポイントの精度低下 |
| THUCNews、Speed 0.1 | 96.71% / 21,785M | 96.71% / 3,595M | 6.05倍 | 浅い層で終了可能な入力が多い |
| LCQMC、Speed 0.8 | 86.68% / 21,785M | 77.45% / 3,310M | 6.57倍 | 文対照合では閾値を緩めると9.23ポイント悪化 |
| DBpedia、Speed 0.1 | 99.31% / 21,785M | 99.28% / 2,060M | 10.57倍 | 容易な分類課題では浅い層でもほぼ同精度 |
| Amazon Full、Speed 0.1 | 65.50% / 21,785M | 65.50% / 21,005M | 1.03倍 | 難しい入力ではほとんど早期終了できない |
| Amazon Full、Speed 0.8 | 65.50% / 21,785M | 61.70% / 2,356M | 9.24倍 | 高い閾値では3.80ポイント悪化 |
| AG News、Speed 0.5 | 94.47% / 21,785M | 93.14% / 2,108M | 10.33倍 | 中間閾値でも速度・精度交換が必要 |

固定深さ比較では、中国語ChnSentiCorpで6層DistilBERTは88.58%・2.00倍、3層版は87.33%・4.01倍である。これに対しFastBERTはSpeed 0.1で95.25%・2.02倍となり、ほぼ同程度の計算量削減でも精度が大きく異なる。入力に応じて難しい事例を深い層へ送る設計の価値を示す比較である。ただし蒸留手順と教師構成が完全に同一ではないため、差のすべてを終了判定だけへ帰属させることはできない。

同じFastBERTでもTHUCNewsとAmazon FullではSpeed 0.1の倍率が6.05倍対1.03倍と大きく異なる。これは単一の閾値から一定の高速化率が保証されるわけではないことを示す。閾値を高くすれば両者とも演算削減が進むが、Amazon Fullでは正答率低下が発生する。したがって運用時に閾値を選ぶには、対象の入力分布で品質許容範囲を測る必要がある。

## 内部挙動の検証

論文4.4節は書籍レビューデータセットで、最初の学生分類器、中間の学生分類器、最終教師分類器の不確実性を区間に分け、各区間の正答率を比較する。図4では各分類器とも不確実性が低い区間ほど正答率が高い傾向が確認され、LUHA仮説を実験的に支持する。ただし同じ不確実性区間で学生の正答率が教師を上回る部分があっても、教師は低不確実性区間に入力が多く分布するため、全体の正答率では教師が優れる。この条件付きの区間比較と全体精度を混同してはならない。

論文4.5節と図5では、書籍レビューの早期終了層の分布をSpeed 0.3、0.5、0.8で調べる。Speed 0.8では最初のTransformer層の直後に61%の入力が終了し、終了層の平均番号は0.92、中央値は0となる。一方、Speed 0.5では平均2.3、中央値1、Speed 0.3では平均3.2、中央値2である。これは閾値が上がるほど浅い層で終了する入力が増えるという機構を直接裏付ける。層番号は0始まりであり、平均0.92を「平均0.92層だけ実行した」と誤読しない。

図6は各層の不確実性分布が閾値によってどう変わるかを示す。早期終了で確信度の高い入力が除かれるため、後段に残る入力集合は元のデータセット全体と同じ分布ではない。この選別効果が計算量削減の中核であると同時に、残存入力の難度が高いほど後段の計算が必要になる理由でもある。単に各層の平均正答率を上げるだけでは、この動的選別の効率は説明できない。

### 現行版に記載されていた難度別の負の条件

入力の内容によって途中終了が可能な層の分布は異なる。DBpediaのように浅い層で高信頼に分類できる例が多い課題は小さい計算予算でも効果が得られるが、Amazon Fullのように必要層が深い課題では、論文のSpeed=0.1条件で約1.03倍と利得が小さい。特定データセットの最良例から、すべてのテキスト分類や自己回帰型LLMの生成速度へ同一倍率を一般化しない。

## 既存研究との差

DistilBERTやTinyBERTのような知識蒸留は、小型の独立モデルを作り、全入力をその固定深さで推論する。FastBERTの自己蒸留は最終教師と中間学生が**一つの共通エンコーダ内に共存**する。学習時には中間分類器を教師の柔らかな出力へ合わせ、推論時には不確実性を使って入力ごとにどの層まで進めるかを選ぶ。学習時の教師情報と推論時の動的分岐を組み合わせる点が特徴である。

BranchyNet型の早期終了は分類器の途中分岐という発想を共有するが、本論文はBERT系言語エンコーダへ適用し、最終分類器からの自己蒸留で中間枝の予測を調整する。重み量子化や構造化枝刈りとは削減対象が異なり、FastBERTが直接省くのは**個別入力が通過しなくてよい後続Transformer層**である。これにより推論開始後に閾値を変える運用が可能になるが、モデル自体の重み容量が同率で減るわけではない。

## 限界・負の結果・適用範囲

第一に、主評価は分類と文対照合であり、自己回帰型の生成モデルで各トークンを逐次出す場合の適用可能性は検証されていない。BERTの双方向エンコーダで入力ごとに一度分類する仕組みを、そのまま生成モデルの途中終了へ移植できるとは限らない。長い文脈や複雑な推論を要する生成課題の品質保証にも、本論文の12データセットの結果だけでは答えられない。

第二に、論文の速度倍率はFLOPsから求められており、GPU上の壁時計レイテンシ、バッチ再編成費用、カーネル起動、メモリ帯域、同時要求時のスループットを直接示さない。各入力が異なる層で終わる設計は、逐次実行では有利でも大規模な並列バッチでは利用率を下げる場合がある。したがって本番推論基盤への統合には別の実測が必要である。

第三に、早期終了は確率分布の集中度を利用するため、過信した誤予測が起きれば深い層で修正する機会を失う。実際にLCQMCのSpeed 0.8では正答率が86.68%から77.45%へ下がる。Amazon FullでもSpeed 0.1では削減がほぼなく、閾値を上げると精度が低下する。したがって一律に大きいSpeedを選べばよいわけではない。

第四に、タスクごとに教師を微調整し、その教師の確率分布で学生分類器を蒸留する学習手順が必要である。タスクや入力分布が変わった場合、閾値の再校正や学生の再学習が必要になり得る。論文はこの再学習費用や長期的な入力分布の変化を含む運用実験を主題としていない。精度・演算量の調整可能性と、実際の運用費用を区別する必要がある。
