# FastMTP：単一の複数トークン予測ヘッドを再帰的に使う投機的復号

## 概要

FastMTPは、複数トークン予測（multi-token prediction、MTP）モジュールを推論時の投機的復号に再利用するための学習・実行方式である。通常の自己回帰生成は大きな言語モデルをトークンごとに一回実行するため、長い回答で逐次的な実行回数が支配的になる。投機的復号は小さい下書き生成器で複数の候補を先に作り、大きな主モデルでまとめて検証する。候補が多く採用されれば主モデルの逐次実行回数が減る。

既存のMTPでは、未来の各位置に専用のヘッドを置く構成や、単一ヘッドを最初の未来位置にだけ利用する構成が多い。単一ヘッドを何度も再帰的に呼ぶと、訓練時に想定していない入力分布へ移り、2番目・3番目の候補の採用率が急落する。FastMTPは主モデルを凍結したまま、一つのMTPヘッドを将来位置ごとに同じ重みで再帰的に使う訓練を行い、推論時の使い方へ一致させる。さらに下書き生成器の語彙射影を言語別の高頻度語彙へ縮小し、候補作成の演算量を減らす。

MiMo-RL-7Bを対象とした単一NVIDIA A10（24GB）上の7課題評価では、通常デコードの平均31.55トークン/秒に対し、3ステップのFastMTPは64.12トークン/秒で2.03倍の速度となった。同じMTPヘッドを未調整で再帰利用した方式は3ステップで38.04トークン/秒、1.21倍である。主モデルの出力分布は厳密な投機的検証によって維持されるが、これは本文で採用した温度0・単一バッチ・検証規則の条件に基づく実測であり、あらゆるGPU・バッチサイズで2.03倍を保証しない。

## 問題設定とMTPの既存利用

多くのLLMは次トークン予測で学習する。MTPはさらに複数の未来位置を予測する補助損失を加えるが、学習中に役立った補助ヘッドがそのまま効率的な下書き生成器になるとは限らない。複数の独立ヘッドを推論時に読み込むと重み・中間状態・キャッシュが増え、下書きのための制御が複雑になる。単一ヘッドを再帰的に使えば軽いが、最初の追加トークンだけを予測する訓練では、それ自身の前ステップ出力を入力とする長い再帰系列に適応できない。

論文の比較では、未調整MTPの採用率は第1候補で約70%あっても第2候補で約11%、第3候補で約2%へ下がる。FastMTPの調整後は同じ位置で約81%、56%、36%へ改善する。採用率が増えたことと最終速度は同義ではない。下書きステップを増やすと主モデルの実行回数は減り得る一方、下書き器自体の実行時間が増えるため、最適な長さを別途決める必要がある。

## 手法

### 1. 単一MTPヘッドの再帰構造

主モデルのTransformer層を $\mathcal F$、MTPヘッドを $\mathcal M$ とする。まず主モデルが文脈から隠れ状態を作り、次のトークンを予測する。その後、MTPヘッドは直前の隠れ状態と、将来位置に対応して一段ずらしたトークン埋込みを組み合わせ、次の未来トークンを予測する。第2ステップ以降は前のMTP呼出しが作った隠れ状態と直前のトークン埋込みを受け取る。

重要なのは、未来の位置ごとに別々のヘッドを置くのではなく、全てのステップで同一パラメータの $\mathcal M$ を再利用することだ。これにより複数ヘッドの重み常駐を避け、実行時には一つの小型生成器を連続呼出しするだけでよい。ただし生成系列は因果的であり、各下書きステップは前の候補に依存する。全候補を同時に無条件生成する方式ではない。

### 2. 推論時の再帰に合わせた訓練

長さ $T$ の訓練系列について、予測深さ $K$ まで将来位置をずらしてMTPヘッドを再帰適用する。各位置の交差エントロピーを単純に同じ重みで加えるのではなく、遠い未来ほど不確実になることを考慮して指数減衰重みを与える。

$$\mathcal L_{MTP}=\sum_{k=1}^{K}\alpha_k\,\mathrm{CE}(\hat t^{(k)},t^{(k)}),\qquad\alpha_k=\frac{\beta^{k-1}}{\sum_{j=1}^{K}\beta^{j-1}}.$$

評価設定では $K=3$、$\beta=0.6$ とする。近い未来を重視しながら第2・第3ステップも明示的に訓練するため、再帰を重ねたときの誤差蓄積を抑えられる。主モデルのTransformer、埋込み、出力ヘッドは凍結し、MTPヘッドの210.8Mパラメータのみ更新する。主モデルは7,833.4Mパラメータなので、更新対象は3%未満である。

### 3. 主モデル自身の出力による自己蒸留

元の教師データの回答は、対象主モデルの出力分布と一致するとは限らない。下書き器の役割は一般的にもっともらしい文章を作ることではなく、主モデルが次に出す候補を当てることである。そこで元データから多様なプロンプトを取り出し、主モデル自身に回答を生成させ、その回答をMTPヘッドの訓練対象とする。これが自己蒸留（self-distillation）である。

訓練用の英語・中国語サンプルは計389.4千件で、一般知識、数学、コードなどを含む。3エポック、AdamW、最大学習率5×10^-5、ウォームアップ率0.05、全体バッチ64で訓練した。著者はms-swiftを使い、単一H20サーバーで1日未満と報告する。これは追加ヘッドの訓練費用であり、巨大な主モデルを一から再訓練した費用ではない。

### 4. 言語別の頻出語彙だけを下書きで計算

通常の出力射影では、隠れ状態を全語彙152kトークンへ射影して候補確率を求める。小型MTPヘッドでもこの射影が繰り返し発生するため、下書き費用が無視できない。FastMTPはFR-Specの頻度に基づく語彙圧縮を応用し、言語 $l$ の高頻度語彙集合 $\mathcal V_{high}^{(l)}$ に対応する出力重みの行だけを取り出す。

$$\tilde W^{(l)}=W[\mathcal V_{high}^{(l)},:].$$

英語中心の頻度表を中国語にそのまま使うと、中国語で頻出するトークンが候補集合から落ち、採用率が悪化する。そこで入力文脈から言語を選び、その言語に合わせた頻度表へ切り替える。8k・16k・32k・64k語彙を比較し、英語と中国語で最適な圧縮度が異なることを示す。語彙を縮めるのは下書き生成側だけで、主モデルの検証は全語彙を維持するため、正規の検証規則を使う限り最終出力の正確さを損なう近似とは区別される。

### 5. EAGLE系の下書きと主モデル検証

実行時にはまず主モデルが次のトークンを一つ生成し、その隠れ状態をMTPヘッドへ渡す。MTPは直前候補の埋込みと自身の隠れ状態を繰り返し使って最大 $K$ 個の追加候補を作る。主モデルはこれらの候補を一括で検証し、最初の不一致までの連続した候補を採用する。これはEAGLE系の隠れ状態とトークンを併用する下書きに近いが、下書き器がMTPヘッドであり、再帰利用のために専用訓練している点が異なる。

検証に近似を入れず主モデルの規則で受理するため、投機的復号が生成するトークン列は通常の自己回帰生成と同じになる。論文の実測では温度0の貪欲復号を採用している。確率的サンプリングに拡張する場合も、適切な受理・補正分布を実装しなければ出力分布保存は主張できない。下書きの語彙圧縮だけで出力を決めているわけではない。

## 評価

### ハードウェア・モデル・ベンチマーク

| 項目 | 論文の設定 |
|---|---|
| 主モデル | MiMo-7B-RL、36層、主モデル7,833.4Mパラメータ、語彙152k |
| 更新するパラメータ | 単一MTPヘッド210.8M、主モデルは凍結 |
| 訓練 | 英語・中国語の自己蒸留389.4kサンプル、3エポック、H20サーバーで1日未満 |
| 主評価GPU | NVIDIA A10 24GB、一部の下書き長感度分析はA100 |
| 実行環境 | SGLang、単一バッチ、温度0、最大生成1,024トークン |
| 評価7課題 | MT-Bench、LiveCodeBench-v6、MATH-500、Natural Questions（RAGとQA）、CNN/Daily Mail、C-Eval |
| 指標 | 平均採用長 $\tau$、位置別採用率、トークン/秒、通常デコード比速度 |

### 主結果：下書き3ステップの比較

| 方式 | 平均採用長 | 平均トークン/秒 | 通常生成比 |
|---|---:|---:|---:|
| 通常の逐次デコード（K=0） | 1.00 | 31.55 | 1.00倍 |
| 未調整MTPを再帰利用（K=3） | 1.83 | 38.04 | 1.21倍 |
| 元データで微調整（K=3） | 2.54 | 52.68 | 1.67倍 |
| 自己蒸留で微調整（K=3） | 2.73 | 57.01 | 1.81倍 |
| 自己蒸留＋言語別語彙圧縮（K=3） | 2.66 | 64.12 | 2.03倍 |

数値は論文表1の7課題平均である。最後の構成は自己蒸留のみの構成より平均採用長が2.73から2.66へわずかに下がるが、下書き語彙の射影が軽くなるため速度は57.01から64.12へ上がる。つまり採用長最大化と実時間最小化は別の目的である。未調整MTPのK=1は約1.32倍、K=3は1.21倍となり、候補を長くするだけでは遅くなる場合がある。

### 語彙圧縮の交換条件

中国語C-Evalでは全152k語彙の構成が54.364トークン/秒（1.719倍）に対し、16k語彙では62.928トークン/秒（1.990倍）となる。英語MT-Benchでは全語彙56.333トークン/秒（1.801倍）、32k語彙では63.420トークン/秒（2.028倍）である。8kまで極端に縮めると候補の採用長が減り、64kでは射影費用が増えるため、適切な中間サイズが最良になる。中国語と英語の両方に英語中心の頻度表を固定する方式では、中国語候補が不足しやすい点を著者は明示する。

### 下書き長を増やすと必ず高速になるわけではない

A100を用いた追加実験では、学習済みヘッドが7ステップまで候補を作れる場合も、速度の頂点はK=3であり、図3の条件で約140トークン/秒だった。Kを増やすと平均採用長は増加しても、再帰ヘッドの逐次呼出し費用と遠い未来の低採用率によって速度は低下する。A100上の140トークン/秒とA10上の64.12トークン/秒は別ハードウェア・別実験の数値であり、同一条件の比較に使わない。

### 各位置の採用率と改善の意味

第1、第2、第3候補の採用率は、未調整MTPの約70%、11%、2%から、FastMTPの約81%、56%、36%へ改善する。特に第2・第3候補の改善が大きいのは、単一ヘッドの再帰入力を明示的に訓練したためである。平均採用長 $\tau$ は一回の主モデル検証で確定できるトークン数に関係するが、下書き時間と検証時間を含む実速度を直接表さない。そのため論文は両方を測定している。

## 既存方式との違い

通常のMTPは補助訓練目的で、推論時の複数ヘッド実行や単一ヘッドの長い再帰には最適化されていない。FastMTPは一つのヘッドへ重みを共有し、自己蒸留データを使って主モデルの生成傾向へ合わせる。EAGLEのように隠れ状態を使う投機的復号の実行構造を利用しながら、主モデルの大規模な再訓練を不要にする。

FR-Spec型の頻度語彙圧縮を単に組み込むだけでなく、言語別に語彙集合を切り替える点も実務上重要である。英語の頻出トークンだけを優先すると中国語のような別言語で候補分布が偏り、受理率が下がる。最終検証は全語彙で行うので、下書き候補集合を縮めることと最終出力を縮めることを区別できる。

## 限界と適用条件

評価はMiMo-7B-RLと単一バッチ・温度0を中心とし、別の主モデル、長いバッチ、同時要求のサービングで同じ高速化を保証しない。主モデルが元から高品質なMTPヘッドを持つ場合、微調整の追加利益は小さい可能性がある。言語識別と頻度語彙の構築にも適切なコーパスが必要で、言語混在や珍しい専門語では候補が落ち、受理率が低下し得る。追加ヘッドは210.8Mパラメータあり、極端なVRAM制約では無視できない。

出力同一性は主モデルが候補を厳密に検証するという前提に依存する。誤った検証実装や候補を無条件採用する実装では同じ保証は成立しない。下書き長を伸ばし過ぎると速度が低下するという負の結果は、採用率と計算費用を一緒に最適化する必要性を示す。論文の実測はトークン生成速度を主に扱い、学習費用の償却、実サービスでの電力効率、マルチGPU分散環境の収容力までは十分に示していない。
