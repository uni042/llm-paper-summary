# Sheared LLaMA：指定した密な小型構造へ枝刈りし、データ配分を動的に変える

## 概要

Sheared LLaMAは、既存の大型言語モデルを小型化する際に、単に重みの一部をゼロにするのではなく、一般的な推論実行器が扱いやすい密な小型モデルの形状を先に指定する研究である。LLaMA2-7Bから約13億および27億パラメータのモデルを切り出し、層数、隠れ状態の幅、注意ヘッド数、フィードフォワード網の中間幅を同時に縮める。枝刈り直後に失われた能力は継続事前学習で回復するが、その際にも学習データを元の比率で使い続けず、領域別の損失回復状況に応じて再配分する。

論文の主目的は、小型モデルをゼロから学習するより少ない計算量で競争力のあるモデルを作ることである。ただし、枝刈り後の形状が均一であるため、同じ程度の疎性を持つ不規則な構造化枝刈りモデルより推論が速くなる点も実機で評価している。A100 80GB上の単一生成で、13億パラメータの均一形状は毎秒58トークン、非均一形状は51トークン、27億では43対37トークンであった。この速度改善と、事前学習計算量を減らす主目的を区別して解釈する必要がある。

## 問題設定

非構造的な枝刈りでは重み行列の多数の要素をゼロにできるが、通常の密行列積カーネルがゼロ要素を自動的に飛ばすわけではない。構造化枝刈りでヘッドや中間次元を削ると実際の行列サイズが小さくなるが、層ごとにヘッド数が違うなど不規則な構造では、標準実行器の最適化を妨げることがある。そこで、モデルを圧縮する時点で実装上扱いやすい目標の層数・ヘッド数・次元数を制約として与える。

第二の問題は、枝刈りしたモデルの知識が領域ごとに均一には残らないことである。論文ではコードのような領域の損失が想定より早く下がる一方、C4のような一般文書の損失が遅れていることを確認する。元の事前学習混合比を維持すると、既に回復した領域へトークンを使い続け、遅れている領域への配分が不足する。継続学習で小型モデルの性能を回復させるには、残っている弱点を定期的に測る必要がある。

## 手法

### 目標形状を直接指定する構造化枝刈り

入力はLLaMA2-7Bのような既存の全重みモデルと、最終的に欲しい層数・隠れ幅・注意ヘッド数・中間幅である。著者らは層単位、全層に共通する隠れ次元単位、各層の注意ヘッド単位、各層のフィードフォワード中間次元単位へ、それぞれ残すか削るかを表すマスクを置く。マスクは零または一へ寄る連続分布で表現し、勾配による最適化を可能にする。

通常の疎性率だけを制約するのではなく、残存する各構造の個数が指定した目標形状へ一致するよう、ラグランジュ乗数と二乗罰則を用いた制約を追加する。言語モデルの損失を小さくしながら、各種類の残存構造数を合わせる。これにより、単に「約60%削る」ではなく「層数とヘッド数がこの値のモデルを作る」という目的を最適化へ直接組み込める。

枝刈り用マスクの学習は通常の言語モデル学習より約五倍遅い。そこで枝刈り段階には比較的短い計算予算を割り当て、学習後は高い保持スコアの構造を選んで確定し、残りを物理的に削除する。最終モデルはゼロ要素を大量に持つ特殊な疎行列ではなく、層や行列の寸法そのものが小さい密モデルになる。推論側で不規則疎性用の特別な演算器を要求しないことが重要である。

### 継続事前学習の領域別データ再配分

構造を削った直後のモデルは、すべての分野で同じだけ性能を失うわけではない。著者らはRedPajamaの七領域について、それぞれの検証損失を定期的に測定する。参照損失は、元のLLaMA2系列の規模と損失の関係から推定した小型モデルの目標値などを用いる。現在の検証損失から参照損失を引き、正の差だけをその領域の未回復量とする。

各領域のサンプリング比率は、直前の比率へ未回復量の指数を掛け、全領域で合計一になるよう正規化して更新する。例えばC4の損失が目標より高ければC4を多く読み、GitHubコードの損失が既に目標へ近ければコード領域の比率を下げる。更新は一定学習ステップごとに行い、枝刈り段階と継続事前学習の両方へ適用する。補助の代理モデルを別途学習せず、対象モデル自身の検証損失を使う。

この方法は、検証領域の構成と参照損失が適切であることに依存する。参照損失を誤って設定すると、配分も誤る。また検証と比率更新の追加処理が必要だが、全モデルの学習に比べれば小さい。著者らは参照損失を規模則から推定する方法と元モデルの損失を使う方法を比較し、前者が数学・コード課題でやや良いと報告する。

### 全体の処理順と推論への接続

まず大型モデルへマスクを挿入し、目標形状の制約付きで短い枝刈り学習を行う。次に残す層・ヘッド・次元を確定して密な小型モデルを作る。続いて検証領域ごとの損失を観測しながらデータ配分を更新し、約500億トークンで継続事前学習する。最後に通常の小型Transformerとして保存し、既存の密行列積実装で推論する。学習時のマスクや動的データ選択は推論へ持ち込まない。

## 評価条件

| 項目 | 一次論文の条件 |
|---|---|
| 元モデル | LLaMA2-7B |
| 目標 | 1.3BはPythia-1.4B相当形状、2.7BはINCITE-Base-3B相当形状 |
| 学習データ | RedPajama七領域：CommonCrawl、C4、GitHub、Wikipedia、Books、arXiv、StackExchange |
| データ予算 | 枝刈り約4億トークン、継続学習約500億トークン、系列長4096 |
| 品質評価 | 常識・読解・知識など11下流課題、指示追従用の追加調整 |
| 比較モデル | OPT、Pythia、TinyLlama、INCITE、OpenLLaMA等の同規模モデル |
| 推論速度評価 | NVIDIA A100 80GB一基、単一モデルで最大512トークン生成 |

## 評価結果と解釈

| 条件 | 比較対象 | 提案モデル | 読み取れること |
|---|---|---|---|
| 1.3B、11課題平均 | Pythia-1.4B 48.9、TinyLlama-1.1B 50.0 | 51.0 | 少ない継続学習トークンで同規模モデルへ競争力 |
| 2.7B、11課題平均 | INCITE-3B 54.7、OpenLLaMA-3B-v2 55.7 | 56.7 | 元モデルの構造を活用した小型化が有効 |
| 1.3B、均一形状と非均一形状 | CoFiPruning：PPL9.1、51トークン/秒 | PPL10.3、58トークン/秒 | 品質指標がやや悪くても均一形状は推論が速い |
| 2.7B、同比較 | CoFiPruning：PPL7.0、37トークン/秒 | PPL7.7、43トークン/秒 | 同規模でも形状の規則性が実速度へ効く |
| 継続学習のデータ比率 | RedPajama原比率：C4 15.0%、GitHub 4.5% | 動的配分：C4 49.2%、GitHub 0.8% | 未回復領域へ計算資源を集中 |

約500億トークンの継続学習で作った2.7Bモデルは、約一兆トークンを使ったOpenLLaMA-3B-v2の下流課題平均55.7に対して56.7である。著者らは同等規模の小型モデルをゼロから学習する場合と比べて約3%の計算予算で同等水準を得たと説明する。ただし、元の7Bモデルを事前学習した計算量まで含めた総費用が3%という意味ではない。既存の大型モデルを利用できることが前提である。

推論速度比較には重要な負の結果もある。CoFiPruningによる非均一形状の方が、枝刈り直後のパープレキシティは低い。それでも均一な目標形状の方が、1.3Bで毎秒58対51、2.7Bで43対37トークンと高速である。これはパラメータ数やパープレキシティだけでは実行効率を予測できず、演算器に合う層構成が重要であることを示す。論文では同等品質に達するために均一形状側が追加で約5億トークンの継続学習を必要とするとも報告する。

データ配分の構成要素分析では、C4のような回復の遅い領域へ学習比率が大きく移り、GitHubのように回復済みの領域は比率が下がる。領域別損失の差が縮まることに加え、下流課題の性能も改善する。したがって動的配分は単なる学習データの見かけの変更ではなく、残っている能力損失へ追加学習を集中する機構として機能している。

## 既存研究との差

SparseGPTなどの非構造的な枝刈りは、専用の疎演算経路がなければ速度を直接改善しにくい。CoFiPruningは構造を削るが、層ごとに異なる形状を生み得る。Sheared LLaMAは目標形状を最初に指定し、標準的な密演算経路に適した均一モデルを作る。データ配分についても、固定の事前学習混合比や別の代理モデルを使う方法とは異なり、枝刈り後モデル自身の領域別検証損失を使って更新する。

## 限界とサーベイ上の位置付け

中心的な研究課題は学習済みモデルからの小型モデル構築と継続事前学習の費用削減であり、推論サービングの待ち行列、複数要求の同時実行、鍵・値キャッシュなどは主要対象ではない。推論側で直接測ったのはA100一基での単一生成速度であり、実運用の同時要求スループットや初回トークン遅延へ一般化できない。枝刈り学習は通常学習より約五倍遅く、性能回復には約500億トークンを要する。主要実験は7B元モデルまでで、より大規模な元モデルや別のハードウェアで同じ交換条件が成立するかは未確認である。したがって本論文は推論基盤そのものの提案ではなく、推論しやすい小型密モデルを作る関連技術として扱うのが妥当である。
