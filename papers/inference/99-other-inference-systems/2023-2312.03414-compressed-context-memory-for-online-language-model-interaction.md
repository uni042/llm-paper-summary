## 概要

オンライン対話では、会話が続くたびに過去トークンのキー・値（KV）状態が増える。全履歴を残せば過去情報へ直接注意できるが、メモリ使用量と注意計算量が継続的に増え、長時間サービスのスループットを下げる。固定長のスライディング窓は資源を一定にできる反面、窓外へ出た情報を失う。

Compressed Context Memory（CCM）は、古い文脈のKV表現を小さな記憶へ繰り返し圧縮する。圧縮器として軽量な条件付き低ランク適応（conditional LoRA）を言語モデルの順伝播へ組み込み、基盤モデル全体を微調整せずに圧縮動作を学習する。再帰的な圧縮過程は訓練時に単一の並列計算へ変形され、逐次圧縮を一段ずつ学習する費用を避ける。

会話、個人化、複数課題学習で、CCMは全履歴を保持するモデルと同程度の性能を約5分の1の文脈メモリで達成する。さらに履歴が際限なく増えるストリーミング設定では、古い情報を単純に捨てるスライディング窓より高い性能を示す。

## 問題設定

Transformerの自己注意では、過去トークンのキーと値を保存しておけば、生成済み部分を毎回再計算せずに次トークンを生成できる。しかし対話履歴が長くなるほどKVキャッシュ容量は増え、各新規トークンが参照する過去位置も増える。オンラインサービスではセッション継続時間に応じて資源要求が増えることになる。

単純な履歴切り捨てはメモリ上限を保証するが、以前のユーザー情報、過去の課題例、会話中に与えられた事実を失う。CCMの目的は、古い履歴をそのまま保持せず、後の生成に必要な情報を小さなKV表現へ畳み込むことである。

## 手法

### 再帰的な文脈圧縮

入力文脈を一定単位で処理し、現在の圧縮記憶と新しい文脈から次の圧縮記憶を作る。時間が進むたびに過去をすべて連結するのではなく、前段で作った記憶を次段の入力へ再利用するため、保持する記憶サイズを制御できる。

出力は通常の自然言語要約ではなく、言語モデル内部で注意に利用できるKV表現である。このため、後続生成は圧縮記憶へ直接注意でき、テキストへ復元して再符号化する工程を必要としない。

### 条件付きLoRA

圧縮動作を基盤モデルへ学習させるため、CCMは条件付きLoRAを順伝播へ追加する。LoRAは大きな重み行列そのものを更新せず、低ランクの追加行列だけを学習する方式である。CCMでは圧縮を行う位置・条件に応じてこの追加経路を使い、通常生成用の基盤能力を大きく変更せずに「文脈を記憶へ変換する」処理を追加する。

基盤モデル全体を長文脈用に再学習する方式と比べ、更新対象パラメータを限定できる。一方、圧縮器は情報を不可逆に要約するため、将来どの情報が必要になるかを完全には予測できない。圧縮率を上げすぎると細部が失われる。

### 並列化した訓練

実際のオンライン推論では、記憶は時系列に沿って再帰更新される。この逐次過程をそのまま訓練すると、前の圧縮結果を待って次を計算するため並列性が低い。論文は再帰圧縮を単一の並列化した順伝播としてモデル化し、訓練効率を高める。

推論時には学習済み圧縮器を使い、履歴が増えるたびに古い文脈を固定サイズ側へ吸収する。これにより、セッション長そのものと保存メモリ量を切り離す。


圧縮記憶は次の圧縮時にも入力として使われるため、一回限りの要約ではなく状態更新器として働く。これにより過去全体を再読込せず、新しい区間と既存記憶から次状態を作れる。ただし誤って失った情報は後段で復元できないため、圧縮器の学習品質が長時間セッションほど重要になる。

## 評価

| 観点 | 内容 |
|---|---|
| 課題 | 会話、個人化、複数課題学習 |
| 比較 | 全文脈保持、スライディング窓など |
| 主な資源 | 文脈KVメモリと注意計算 |
| 主結果 | 全文脈モデル相当の性能を約5分の1の文脈メモリで達成 |
| ストリーミング | 無制限に履歴が伸びる設定でスライディング窓を上回る |
| 実装 | 公式PyTorchコード公開 |

5倍のメモリ削減結果は、単にKVを削除した結果ではなく、圧縮記憶へ情報を残したうえで下流性能を維持したことが重要である。スライディング窓との比較は、固定メモリ予算で古い情報を捨てる方式より、学習した圧縮の方が長期依存を残せることを示す。

### 結果の読み方

全文脈モデルと同程度の性能を5分の1の文脈メモリで得た結果は、固定長窓による単純削除よりも、学習した圧縮表現が後続課題に必要な情報を保持できることを示す。会話だけでなく個人化と複数課題学習を含めて評価したことで、直前の局所文脈だけでは説明できない過去情報の利用も確認している。無制限ストリーミング設定では、セッション長に比例して記憶を増やさずに処理を継続できる点を評価し、同じく固定メモリで動くスライディング窓より高い性能を示す。

一方、この結果はKVキャッシュのバイト数や注意演算時間が常に厳密に5分の1になることを意味しない。5倍は文脈記憶サイズに関する代表結果であり、条件付きLoRAによる圧縮計算自体には追加費用がある。エンドツーエンドの速度利得はモデル規模、圧縮頻度、GPU実装に依存するため、品質維持とメモリ削減の証拠と、実時間高速化の証拠を分けて読む必要がある。

## 既存研究との差

スライディング窓は一定距離より古いKVを削除するため実装が単純だが、必要な情報かどうかを区別しない。CCMは古い文脈を固定サイズの学習済み表現へ変換し、履歴全体の情報を圧縮して残そうとする。

テキスト要約を外部メモリとして保存する方式とも異なり、CCMはTransformer内部のKV表現を直接圧縮する。検索拡張生成のように外部文書を後から検索する方式ではなく、同一セッション内で蓄積した内部状態を継続更新する設計である。

## 限界

圧縮は不可逆であり、将来重要になる細粒度情報を落とす可能性がある。固定長記憶へ情報を詰め込むため、セッションが極端に長くなるほど情報密度は上がり、全履歴保持と完全に同等である保証はない。

条件付きLoRAの訓練も必要であり、任意の未調整モデルへ単純なキャッシュ管理だけで適用できる方式ではない。評価は論文が選んだ会話・個人化・複数課題学習を中心としており、コード生成や非常に細かな逐語記憶など別種の長期依存で同じ圧縮率が最適とは限らない。
