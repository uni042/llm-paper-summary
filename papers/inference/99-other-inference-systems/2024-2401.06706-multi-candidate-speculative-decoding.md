# 複数候補投機的復号（Multi-Candidate Speculative Decoding）

## 書誌と調査対象

Sen Yang、Shujian Huang、Xinyu Dai、Jiajun Chenによる2024年1月の研究である。今回の監査では、arXiv:2401.06706の15ページの原著本文、図1〜4、表1〜5、アルゴリズム1・2、付録の記述を確認した。正式な会議採録を裏付ける一次情報を確認できなかったため、旧原稿にあった「NAACL 2024」という掲載先の断定は引き継がず、確認済みのarXiv版として記録した。原著第1ページの脚注には、著者の公式実装、データ、モデルの公開先としてNJUNLP/MCSDが記載されている。

## 概要

投機的復号（speculative decoding）は、大きな対象モデルの逐次実行を、小さな下書きモデルによる候補生成と、対象モデルによる候補列の並列検証へ置き換える。標準方式では各深さに一つの候補しかない。最初の不受理位置が見つかると、その後に下書きモデルが計算した候補は、条件付き文脈が異なるため使えなくなる。この無駄は、下書きと対象の確率分布が離れている翻訳や微調整済みモデルの組合せで大きい。

本論文は、各投機深さで一つではなく複数の候補を用意し、対象モデルによる検証時に枝を選べるようにする。単に上位候補を採用するだけでは対象モデルの出力分布が変わるため、複数候補の受理・拒否・補正トークンの抽出を確率的に設計した。さらに、枝ごとに共通接頭辞を複製する代わりに木注意（Tree Attention）を用い、同じ祖先の鍵・値キャッシュ（KV cache）を共有する。したがって、研究の核は「候補幅による受理率向上」「分布保存の検証」「共有接頭辞による検証費用削減」の三点である。

LLaMA-68Mを下書き、Vicuna-33Bを対象にしたAlpaca・貪欲復号（温度0）の実測では、通常の逐次生成を1とした最良の標準投機的復号が1.70倍、本方式が2.06倍である。これは本方式が標準方式の2.06倍速いという意味ではない。最良標準方式に対する上積みは約21%であり、モデル・タスク・温度が異なれば上積み幅も変わる。論文は複数候補化が受理率を上げても、下書き計算と検証計算が増えれば壁時計時間の利得は頭打ちになることも示している。

## 問題設定

### 単一候補の受理率がボトルネックになる理由

標準投機的復号は、長さγの下書き列を逐次生成し、対象モデルが各位置の条件付き確率を一度の前向き実行で評価する。検証は先頭から行い、最初の不受理位置で停止する。全γ個が受理された場合は対象分布から追加の一トークンを出せるが、先頭で棄却されれば確定するのは補正トークンだけになる。したがって、対象モデルを一度呼んで確定できる平均トークン数は、下書きの受理確率とその連続性に左右される。

下書きモデルの確率分布をq、対象モデルの確率分布をpとする。標準の受理確率は、下書きが提案したトークンxについてmin(1,p(x)/q(x))である。分布全体の平均受理率はΣ_x min(p(x),q(x))に等しく、二つの分布の重なりが小さいほど下がる。棄却されたときはmax(0,p−q)を正規化した残差分布から補正トークンを引く。この補正を省略して下書き候補を強制採用すると、生成分布が対象モデルからずれてしまう。

原著表1では、LLaMA-68MからLLaMA-13Bを対象とするAlpaca・温度0の受理率は0.76だが、同じ下書きでVicuna-33B・WMT・温度0では0.22、温度1でも0.24である。微調整や翻訳タスクへの変化は、モデル規模だけを変えるより分布一致に強く影響する。論文が比較するAlpacaの平均プロンプト長は9語、WMTは29語であり、タスク・文脈長の差が受理率の変化に関連するという観測も記載されている。ただしこの二つの要因を独立に制御した因果実験とは読めない。

### なぜ単に下書きを長くするだけでは足りないか

下書き長γを増やすと、一度の対象モデル実行で長い列を受理できる可能性は増す。しかし早い位置の候補が不受理になると、その後の候補はすべて捨てる。したがって、下書きの逐次生成時間を追加しても平均確定トークン数がほとんど増えない領域がある。特に対象と下書きの確率分布がずれていると、後半の長い候補列へ到達しにくい。

複数候補を各位置に置けば、先頭の候補が不受理でも同じ位置の別候補を検証できる。一方、全ての枝を別々のバッチ系列に展開すると、共有するプロンプトのKVキャッシュを枝数だけ複製し、対象モデルの注意演算で同じ鍵・値を繰り返し読み込む。候補幅を増やすほどこのメモリ転送と検証費用が増えるため、確率的な受理規則と木構造の実装を組み合わせる必要がある。

## 手法

### 複数候補の木と候補予算

投機深さγの各位置iにk_i個の候補を置き、選ばれた候補を親とする後続候補を分岐させる。例えば「4×2×2×1×1」は先頭に4候補、その後に2、2、1、1の分岐数を割り当てる構成である。各深さで枝が乗算的に増えるため、葉の候補列の組合せ数はK=∏_{i=1}^{γ} k_iとなる。**旧原稿のK=Σk_iという記載は原著の積記号と一致せず、今回修正した。** 原著はK≤32、k_i∈{1,2,4,8,16,32}という探索範囲を用いる。Kは葉の組合せ予算であり、木の全ノード数や実際の計算量が単純にKに一致するという意味ではない。

生成では、下書きモデルが各位置の分布qを計算し、同じ文脈に対する複数の候補トークンを引く。候補が一つの枝へ決まった後も次の位置で再び複数候補を用意するので、対象モデルの検証は先頭から一つの生き残り経路をたどる。候補数を前段に厚く割り当てると、後続深さへ進める確率が高まりやすい。反対に後段ばかり広げても、そこへ到達する前に棄却されると計算が無駄になる。図4は同じ予算なら4×2が2×4より有利になる例を示している。

### 複数候補の確率保存型受理規則

原著アルゴリズム1は、同じ下書き分布qから復元抽出（with replacement）した候補x_1,…,x_kを順に試す。最初の候補を、対象分布pと下書き分布qの比に基づく確率で受理する。棄却されたらpをmax(0,p−q)の正規化残差へ更新し、次の候補を新しいpに対して評価する。どの候補も受理されなければ、最後の残差pから補正トークンを抽出する。付録Aはこの操作で最終出力が対象分布pに従うことを示している。

重要なのは「候補を多く出したから、そのうち対象モデルが好きなものを選ぶ」という恣意的な操作ではないことである。候補を棄却するたびに対象分布の残りの確率質量を明示的に再配分し、受理できなかった場合の補正も含めて分布を保つ。標準方式の一候補に対する拒否サンプリングを複数候補へ拡張したものと理解できる。生成品質を別の近似基準で評価して速さと交換する方式ではなく、同じ対象モデル分布のサンプルをより少ない大規模モデル呼び出しで得る方式である。

### 重複候補を避ける非復元抽出

復元抽出では、確率の高い同一トークンを複数回引く可能性がある。一度棄却されたトークンは残差pから確率質量が取り除かれるため、同じ候補をもう一度検証しても受理機会が増えない。原著アルゴリズム2の非復元抽出（without replacement）では、既に引いた候補の質量をqから除去し、残りを再正規化して次の候補を生成する。検証側もpとqの残差を候補ごとに更新し、最後に補正トークンを抽出する。付録Bが分布保存を証明する。

この機構が解くのは「候補数は多いのに実際には同じ語ばかり」という無駄である。候補の多様性を確保し、固定された候補予算を別のトークンへ使える。ただし原著の除去実験では、復元抽出との差は木注意の有無による差ほど大きくない。小さなkでは重複自体が頻発しないことが理由として挙げられている。非復元抽出が常に大幅な高速化を保証するわけではない。

### 木注意による共有接頭辞の一括検証

複数候補を別々の系列としてターゲットモデルへ渡すと、同じプロンプトや同じ祖先候補のKVキャッシュが各枝へ複製される。木注意（Tree Attention）は、枝のノードを一つの系列へ詰め、各ノードが自分の祖先だけを参照できる注意マスクを設定する。位置符号は枝に沿った元の位置を保ち、兄弟枝のトークン同士が不正に注意しないようにする。これにより対象モデルは一回の前向き計算で各候補の確率を取得できる。

一つの系列へまとめることで候補ノード数だけ系列長は増えるが、長い共有接頭辞のKVを各枝で複製して層ごとに転送する費用を避けられる。原著は、追加の注意計算より共通接頭辞の転送削減の方が重要な評価条件を示している。受理アルゴリズムは生成分布を保存する役割、木注意はその同じ候補木を安く検証する役割であり、両者の効果は区別する必要がある。

### 一ラウンドの処理経路

要求の文脈を受け取った下書きモデルは、まず深さごとの候補数k_iに従って複数の候補を生成する。候補の祖先関係と位置を保持した木を作り、木注意マスクを使って対象モデルへ一括入力する。検証器は木の根に近い位置から複数候補受理規則を適用し、受理された候補に対応する子枝へ進む。ある深さで全候補が不受理なら残差分布から補正トークンを返してそのラウンドを終える。最後まで枝が残った場合は対象モデル分布から追加トークンを抽出する。

この順序なら、どの枝へ進むかは対象モデルが計算した確率で決まり、木の別枝のトークンが確定系列へ混入しない。次ラウンドは確定した接頭辞から再開する。実際の利得は、一度の対象モデル実行で確定したトークン数が増える効果と、下書き・木検証に追加で使った時間との差で決まる。モデル分布の一致率、候補木の形、プロンプト長、下書きモデルの速度がいずれも効く。

## 評価

### 実験環境・指標と比較対象

| 項目 | 原著の条件 |
|---|---|
| 実機 | 単一ノード、NVIDIA RTX A6000 48GB ×4、半精度 |
| 対象モデル | LLaMA/Vicuna 13B・33B。一般化試験にLLaMA2およびOPT系列 |
| 下書きモデル | LLaMA-68M、LLaMA-160M。追加の微調整試験でVicuna-68M、OPT-125M |
| GPU配置 | 13B対象は1GPU、33B対象は2GPU。下書きは対象と同居し追加GPUを占有しない |
| ワークロード | 指示データAlpaca、英独翻訳WMT En-De。WMTは翻訳指示テンプレートを使用 |
| 復号 | 温度0の貪欲復号と温度1の標準確率サンプリング |
| 出力長 | 最大128新規トークン |
| 探索範囲 | 候補列予算K≤32、各位置の候補数k_iは1,2,4,8,16,32 |
| 比較対象 | 通常自己回帰生成、同じ投機深さγの標準投機的復号、最良γの標準投機的復号 |
| 評価指標 | 受理率α、ブロック効率τ、壁時計時間に基づく生成高速化倍率 |

受理率αは、一つの下書き候補が検証で受理される確率である。ブロック効率τは、対象モデルを一度呼び出したラウンドで平均何トークン確定できたかを表し、最低1、最大γ+1である。壁時計高速化は通常の自己回帰生成に対する実時間の比率であり、τが増えても下書き生成と木検証の追加費用によって比例しない。原著が三つの指標を分けたのは、確率的受理改善と実機の推論時間改善を混同しないためである。

### 対象モデル・タスク・温度による受理率の違い

原著表1で、下書きLLaMA-68Mの受理率αはLLaMA-13B/Alpaca/温度0で0.76、LLaMA-33Bでは0.75と近い。一方Vicuna-13Bでは0.49、Vicuna-33Bでは0.52へ下がる。同じVicuna-33BでもWMT/温度0では0.22、温度1では0.24である。したがって単に対象モデルが大きいことより、微調整とタスク変更が分布不一致へ結び付く条件を強調すべきである。

LLaMA-160Mへ下書きを大きくするとLLaMA-13B/Alpaca/温度0のαは0.80、Vicuna-33B/WMT/温度0は0.25となる。受理率はわずかに改善するものの、下書きモデルを実行する費用も増える。論文は160Mで投機深さの最適値が縮む場合を報告しており、下書きモデルを大きくするだけでは推論が速くならないことを示す。

LLaMA-33B/Alpaca/温度0では標準方式の受理率が元々高く、上積みは5.9%にとどまる。Vicuna-33B/WMT/温度1では標準方式が1.14倍と小さな利得しか得られないが、本方式は1.42倍へ改善する。ただし1.42倍は絶対的に大きな高速化とは限らず、候補木の追加費用が残る。これらは同一GPU構成での短い生成長の実測であり、連続バッチや多ユーザーサービングの処理率ではない。

### 複数候補数と受理率の感度

原著表5では、Alpaca上でk=1から4へ増やすと、LLaMA-68M→LLaMA-13B/温度0のαは0.76から0.88へ、Vicuna-13B/温度0は0.49から0.67へ改善する。温度1ではLLaMA-13Bが0.51から0.72、Vicuna-13Bが0.35から0.57へ改善する。さらにLLaMA2-13B-chat/温度0は0.47から0.66、OPT-125M→OPT-iml-30B/温度0は0.81から0.93へ上がる。異なる系列と微調整済みモデルでも複数候補化が有効なことを示す。

図3の受理率曲線は候補数を増やすと上昇するが、kが32を超えると収束傾向になる。これは幅を無限に増やしても受理率改善が頭打ちになることを示す。さらに図4では、同じ予算なら前段に候補を多く置く単調減少配置が有利であり、予算32は予算16よりブロック効率が高いのに、壁時計速度が低くなる条件がある。候補数だけで方式を評価せず、追加の下書き計算・木検証・メモリ転送まで含める必要がある。

### 構成要素除去実験：受理アルゴリズムと木注意の役割

原著表4はLLaMA-68M下書き、Alpaca、温度1で複数候補受理と木注意を比較する。LLaMA-13B対象では、非復元抽出MCSSと木注意を両方用いると1.91倍、τ=2.45である。復元抽出MCSSは1.89倍、τ=2.39と僅差である。一方、単純な複数候補の素朴な検証MCNSは1.21倍、τ=1.52に下がる。複数候補を用意するだけでなく、対象分布を保つ適切な受理規則が受理効率に重要であることが分かる。

同じ非復元抽出MCSSでも木注意を外すと1.61倍、τ=2.47になる。木注意ありのτ=2.45とほぼ同じなのに、実時間では1.91倍から1.61倍へ悪化する。これは木注意が確率的受理を変えるのでなく、共通接頭辞のKV複製と転送を削減するシステム最適化として働くことを示す。Vicuna-33B対象でも木注意あり1.73倍・τ=2.10に対し、なし1.51倍・τ=2.09で同じ傾向がある。

### 下書き微調整との併用と一般化

著者はShareGPTで下書きモデルを追加微調整したVicuna-68Mなどを使い、複数候補化と分布一致を改善する学習が競合しないことを確かめている。Vicuna-68M→Vicuna-13B/Alpaca/温度0ではk=1から4でαが0.56→0.76、温度1では0.46→0.68になる。LLaMA2系列やOPT系列でも改善が観測されるため、提案は特定の下書きモデルだけを再学習して成立する方式ではない。

ただし「すべてのモデルで同じ倍率になる」という一般化ではない。原著の一般化試験は限られたモデル系列、特定のデータセット、指定された生成長である。ドラフトの追加微調整は受理率改善に寄与し得るが、それ自体の学習費用は本方式の推論時費用とは別に考える必要がある。

## 既存研究との差

標準投機的復号は、一位置に一つの下書き候補を生成し、最初の棄却以降を補正トークンで置き換える。Multi-Candidate Speculative Decodingは候補幅を持たせ、確率質量の更新を伴う複数候補受理規則を定式化した。したがって主たる新規性は単に木注意を採用したことではなく、対象分布を保存しながら同じ位置の複数候補を順に試せる検証手続きにある。

SpecInferなどの木型投機推論は複数候補の並列検証を扱うが、本研究は復元・非復元抽出に対応する確率的な受理・補正を導出している。著者が関連研究で言及する別方式には、最適輸送問題として複数候補の受理を定式化し、線形計画を必要とするものもある。本方式は候補を順に試し残差分布を更新する実装を提示する。学習済みの予測ヘッドを追加する方式とは異なり、既存下書きモデルを使っても動作する点も特徴である。

## 限界・負の結果

候補予算を増やすと受理率やブロック効率は改善する一方、ドラフトモデルの生成回数、ターゲットモデルの木検証、注意マスク処理、KVの読み書きが増える。図4では予算32が予算16より高いブロック効率を持ちながら低い実時間高速化となる条件があり、「受理率向上＝実行時間改善」という単純な関係は成立しない。モデルとデータごとに候補木の形を探索する必要があり、本論文は本番負荷に応じてオンライン最適化するスケジューラを提供していない。

復元抽出は重複候補を生成するため候補予算を浪費し得るが、非復元抽出の利得も小さいkでは限定的である。対象と下書きの分布が非常に異なる場合、候補数を増やしてもすべての候補が不受理となるラウンドは残る。Vicuna-33B/WMT/温度1では標準方式1.14倍、本方式1.42倍であり、絶対的な高速化の上限がまだ厳しい。対象分布を厳密に保存する性質は、速度改善や受理率の下限保証を意味しない。

評価は単一ノード、A6000、半精度、最大33B級、最大128新規トークンの生成を中心とする。現代の大規模MoE、複数要求の連続バッチ、長時間のキャッシュ再利用、CPU/GPUオフロード、ネットワーク越しの分散サービング、低ビット量子化された対象モデルでの実機利得は、この論文の結果から直接は言えない。木注意の実装費用やGPUメモリ容量の制約も、モデル・系列長・枝幅が変われば再評価が必要である。

本稿での定量値は原著の表1〜5と図3〜4に対応する条件付きの報告値であり、最新ハードウェアでの性能を推定した値ではない。旧原稿の「K=Σk_i」という誤った予算式と、未確認の会議採録、未確認扱いになっていた公式コードURLを今回の再監査で修正した。
