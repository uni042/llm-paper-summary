# Multi-Candidate Speculative Decoding

> 各投機位置で複数候補をサンプリングして木として一括検証し、ターゲット分布を保ったまま単一路の投機的復号より受理率を高める。

## 概要

標準的な投機的復号（speculative decoding）は、小さなドラフトモデルがγ個のトークンを直列に提案し、大きなターゲットモデルがそれらを一度の前向き計算で検証する。候補がターゲット分布と一致すれば複数トークンを一度に確定できるが、途中の1トークンが棄却されると、その後ろの候補は条件付き文脈が変わるため利用できない。したがって速度はドラフトとターゲットの受理率αへ強く依存する。

本論文は「1位置1候補」という制約を外す。各投機位置で `k_i` 個の候補をサンプリングし、複数の候補系列を木構造としてまとめる。ターゲットモデルは木の全ノードを一括で検証し、ある候補が外れても兄弟候補が受理されればその枝を継続できる。総候補予算は `K=Σ k_i` とし、論文ではK≤32の範囲で `k_i ∈ {1,2,4,8,16,32}` を探索する。

単にtop-k候補を並べるとターゲットモデル本来の出力分布を変えてしまうため、論文は複数候補のサンプリングと検証規則を設計する。主要方式の置換なし複数候補サンプリング（Multi-Candidate Speculative Sampling without replacement; MCSS）は、既に引いた候補を除いた残余ドラフト分布から次候補をサンプリングし、ターゲット側の残余確率と対応させて受理する。これにより複数候補化してもターゲット分布を保存する。

## 問題設定

標準SDの効率は、ドラフト1トークンが受理される確率αと投機長γで決まる。αが高いLLaMA-13B・Alpaca・greedyのような条件では標準SDでも速いが、微調整済みVicunaや翻訳WMT、温度1のサンプリングではドラフトとターゲットの分布差が増え、受理率が大きく下がる。実測ではLLaMA-68M→Vicuna-33BのWMTでαはgreedy 0.22、温度1で0.24に過ぎない。

このとき投機長γを伸ばすだけでは、早い位置の棄却で後続候補が無駄になる。複数候補なら、同じ位置で別の候補へ分岐しておくことで「正しい枝」を木の中に含める確率を上げられる。一方、候補を増やし過ぎるとドラフト生成、ターゲット検証、KV複製、注意計算の費用が増えるため、候補数と配置を制御する必要がある。

## 手法

### 位置ごとの複数候補生成

投機深さγの各位置iで `k_i` 個の候補を生成する。たとえば `4×2×2×1×1` なら、先頭で4候補、次の二段で各2候補、その後は単一候補とする。論文は受理率の低い先頭側へ候補予算を厚く配る構成を多く選んでおり、固定kの完全k分木を作る方式ではない。

総候補数を無制限に増やすとターゲットの一括検証が重くなるため、Kを最大32へ制限して候補構成を探索する。実験ではkを1から4へ増やすだけでも多くのモデル組合せで受理率が0.1〜0.2程度上がり、OPT-iml-30B/WMTでは0.40→0.77（+0.37）という大きな改善も観測される。

### 分布を保存するMCSS

置換なしMCSSでは、同じ位置の候補を重複して引かないよう、既にサンプリングしたトークンの確率質量をドラフト分布から除いて再正規化し、次候補を引く。検証側も候補を順に処理し、ターゲット分布pと残余ドラフト分布qの比に基づく受理確率を使う。

候補が受理されなかった場合は、標準SDと同様に残差分布から補正トークンをサンプリングする。この構成により、候補数を増やして受理機会を増やしても、最終的に出力されるトークン列はターゲットモデルの分布に従う。greedyだけを対象にした近似高速化ではない点が重要である。

### 木注意による一括検証

複数候補系列を単純にバッチへ複製すると、共通接頭辞のKVや注意計算が枝数だけ重複する。論文は候補系列を木へまとめ、各ノードが自分の祖先ノードだけを参照できる木注意（Tree Attention）マスクを使う。これにより共有接頭辞を一度だけ保持しつつ、ターゲットモデルの1回の前向き計算で複数枝を検証する。

構成要素除去では、LLaMA-68M→LLaMA-13B、Alpaca、温度1でMCSS+木注意が1.91倍、木注意を外すと1.61倍まで低下する。受理効率τは2.45対2.47とほぼ同じなので、木注意は「受理数を増やす」のではなく、同じ候補木を安く検証するシステム最適化として効いている。

### 候補構成の探索

候補予算Kが同じでも `k_i` の配置で速度が変わる。先頭へ多く候補を置けば早期棄却を避けやすいが、後段へ候補を残さないと長い連続受理の機会を失う。論文は複数構成を実測し、ブロック効率τだけでなく実壁時計速度も比較する。

この区別は重要で、候補を増やしてτが上がっても、ドラフト生成と木検証の費用が増えれば速度は比例しない。最適構成はターゲットモデル、ドラフトモデル、データセット、温度によって変わる。

## 評価条件

| 項目 | 条件 |
|---|---|
| GPU | 4× NVIDIA RTX A6000 48GB |
| 精度 | 半精度 |
| ドラフト | LLaMA-68M、LLaMA-160M。追加評価でVicuna系、OPT-125M |
| ターゲット | LLaMA/Vicuna 13B・33B、LLaMA2系、OPT-13B/30B/OPT-iml-30B |
| データセット | Alpaca、WMT En-De |
| サンプリング | greedy（temperature=0）、standard sampling（temperature=1） |
| 最大生成長 | 128 new tokens |
| 候補予算 | K≤32、各 `k_i∈{1,2,4,8,16,32}` |
| 指標 | token受理率α、block efficiency τ、wall-clock speedup |
| 比較 | 通常自己回帰、同じγの標準SD、最良γの標準SD |

13Bターゲットは1 GPU、33Bターゲットは2 GPUへ配置し、ドラフトモデルは同じサーバ上へ置く。WMTは翻訳指示テンプレートへ埋め込み、Alpacaより平均プロンプトが長い。

## 主要結果

| 条件 | 最良標準SD | 複数候補 | 読み取れること |
|---|---:|---:|---|
| LLaMA-68M→LLaMA-33B、Alpaca、temp=0 | 2.89×、τ=3.70 | 3.06×、τ=3.93 | 元々受理率が高い条件でも追加利得 |
| LLaMA-68M→Vicuna-33B、Alpaca、temp=0 | 1.70×、τ=2.03 | 2.06×、τ=2.56 | 分布差が大きい微調整モデルで差が拡大 |
| 同LLaMA-33B、WMT、temp=1 | 1.43×、τ=1.69 | 1.72×、τ=2.08 | sampling+翻訳でも改善 |
| 同Vicuna-33B、WMT、temp=1 | 1.14×、τ=1.31 | 1.42×、τ=1.70 | 標準SDの利得が小さい条件を底上げ |
| LLaMA-68M→Vicuna-13B、Alpaca、temp=1 | 1.56×、τ=1.79 | 1.64×、τ=2.00 | 13Bでも改善 |
| MCSS、木注意除去、LLaMA-13B/Alpaca/temp=1 | — | 1.91×→1.61× | 木注意が検証オーバーヘッドを抑制 |

受理率そのものはk=1→4で、LLaMA-68M→LLaMA-13B・Alpaca・greedyが0.76→0.88、Vicuna-13Bが0.49→0.67、LLaMA2-13B-chatが0.47→0.66へ上がる。温度1でもLLaMA-13Bは0.51→0.72、Vicuna-13Bは0.35→0.57となる。改善幅は一定ではなく、ドラフトとターゲットの初期不一致が大きいほど複数候補の価値が高い。

## 既存研究との差

標準的な投機的復号は1本の候補列を検証するため、受理率を上げるにはドラフトモデルをターゲットへ近づける、投機長を調整する、といった方法が中心になる。本方式はドラフトを再学習せず、同じドラフト分布から複数候補を引いて探索幅を増やす。

SpecInferのような木型投機推論も複数枝を検証するが、本論文は確率的サンプリングでターゲット分布を厳密に保つ複数候補受理規則を主眼に置く。候補木と木注意はその確率アルゴリズムをGPU上で効率よく検証するために接続される。

## 限界

候補数を増やせば必ず速くなるわけではない。Kが増えるほどドラフト生成とターゲット検証の計算が増え、速度はブロック効率τより低くなる。最適 `k_i` はモデル・データ・温度依存であり、論文では有限候補集合を探索しているため、本番負荷でのオンライン最適化は別問題である。

評価は主に単一ノードA6000と最大33B級で、現代の大規模MoEや高並列サービングでの同時要求スループットは直接評価していない。また生成長を128 tokenへ制限しており、長文生成時のKV増加と木検証コストの相互作用は限定的にしか分からない。

さらに低受理率条件では改善するものの、Vicuna-33B/WMT/temp=1でも1.42倍であり、候補木だけでドラフトとターゲットの大きな分布差を消せるわけではない。
