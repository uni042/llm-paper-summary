# Dynamic-LLaVA: Efficient Multimodal Large Language Models via Dynamic Vision-language Context Sparsification

## 概要
Dynamic-LLaVAは、マルチモーダル大規模言語モデル（Multimodal Large Language Model; MLLM）の高速化を、画像tokenだけの削減ではなく「画像文脈と生成済み言語文脈の両方を、推論段階に応じて動的に疎化する」問題として扱う。従来のFastVなどはprefill時に画像tokenを減らせるが、出力が長くなるほど生成済みtext tokenがcontextの大半を占め、decodeの計算・KV cache容量に対する画像削減の寄与が薄れる。

Dynamic-LLaVAはTransformerの早い層に二つの軽量予測器を置き、画像tokenを残すか決める画像予測器と、各生成text tokenを今後の計算/KV cacheへ残すか決める出力予測器を学習する。予測は一度だけ行い、そのkeep/drop決定を後続層すべてで共有する。prefillでは画像tokenだけ、KV cacheなしdecodeでは画像+過去出力token、KV cacheありdecodeでは新たに生成したtokenのKVを保存するかを選ぶ。

LLaVA-1.5 7B/13B上の評価では、画像tokenを576から115へ減らし、画像関連prefill計算を約75%削減する。生成中もtext文脈を疎化し、KVなしdecode計算を約50%、KVありdecodeのKV memoryを約50%削減しながら、理解・生成指標の低下を小さく保つ。さらにTokenPacker等の効率的vision projectorとも併用できる。

## 問題設定
LLaVA型MLLMでは、vision encoderが多数の画像tokenを作り、text promptと連結してdecoder-only LLMへ渡す。prefillでは画像+text tokenすべてを一度処理するため、画像token削減は直接計算削減になる。しかしdecodeが長くなると、KV cacheなし推論では過去出力token全体を再計算し、KV cacheあり推論では各生成tokenのK/Vを追加保存する。

したがって出力長 (N^{OT}) が大きくなると、計算量またはmemoryは画像token数より生成済みtext token数に支配される。画像だけを75%削っても、後半decodeでは削減した画像tokenは全contextの小部分になり、speedup/memory削減率が徐々に消える。

Dynamic-LLaVAの目的は、prefillの画像冗長性とdecodeの言語履歴冗長性を別々のpredictorで減らし、一回限りのtoken削減ではなく生成全期間にわたる効率改善を得ることである。

## 手法

### 1. 二つの二値予測器
画像token集合に対する画像予測器 (P^I) と、生成text tokenに対する出力予測器 (P^{OT}) を追加する。各token featureからkeep/dropの2-class scoreを出し、二値maskを作る。予測器は小型多層networkで、追加計算は全体の1%未満と報告される。

標準設定では第2 decoder layer後に一度だけpredictorを適用する。そこでdropされたtokenは後続層へ渡さず、keepされた集合だけを残りのdecoderへ入力する。同じtokenを各層で再判定しないため、layerごとの不規則なsequence length制御や複雑なsparsity scheduleを避ける。

### 2. prefill時の画像疎化
prefillでは画像token featureを (P^I) へ入力し、keepされた画像tokenと元のtext promptを結合して第3層以降を実行する。text prompt自体はここでは削らない。これにより大部分のLLM層で画像token数を減らし、attentionだけでなくFFNなどtoken数に比例する計算も減らす。

画像keep率は学習時の正則化で所望値へ誘導する。評価設定ではLLaVA-1.5の576画像tokenを115程度まで減らす構成があり、画像tokenに関するprefill TFLOPsを7Bで10.1→2.5、13Bで19.6→4.7へ削減する。

### 3. KV cacheなしdecodeで画像+言語を疎化
KV cacheを使わず毎step全contextを再計算する場合、画像tokenだけでなく過去に生成した出力text tokenへ (P^{OT}) を適用する。ただし今まさに次tokenを生成するための最新出力tokenは必ず保持する。

dropされた過去text tokenは後続層のattention/FFNから除かれるため、生成が長くなっても処理sequenceが元の出力長に比例して増え続けるのを抑える。このモードでは「どのKVを保存するか」ではなく、後続層で実際に再計算するtoken集合そのものを小さくする。

### 4. KV cacheありdecodeではonline KV cache圧縮
KV cacheありの場合、現在tokenはそのstepのattentionには必ず含める。出力予測器は、そのtokenから生成されたK/Vを「次step以降のcacheへ追加するか」を決める。drop判定なら現在stepの計算には使った後、K/Vをcacheへ保存しない。

この判断は現在tokenのfeatureだけで行い、過去KV全体のattention scoreを再走査してeviction対象を選ばない。したがって著者らはonline KV cache compressionと位置付ける。同一keep/drop決定を後続layerへ伝えるため、第2層より後では不要tokenのKV増加を抑え続けられる。

### 5. end-to-end疎化学習
binary maskは通常のargmaxでは微分できないため、学習時にはGumbel-Softmaxと直線通過勾配推定器（Straight-Through Gradient Estimator; STE）を用いる。drop tokenがkeep tokenへ情報を流してpredictorが不正に補償することを防ぐため、masked softmaxで不要tokenの影響を遮断する。

さらに実keep率が指定 (r^I,r^{OT}) へ近づくよう正則化項を加える。短い回答までtext sparsificationを強制すると学習が不安定になるため、出力token数が閾値 (LEN^{OT}) 以上のsampleだけに言語mask制約を適用する。速度・memoryと品質の交換条件はkeep率を変えることで調整する。

## 評価

### 条件
主なbackboneはLLaVA-1.5 7B/13B。vision understandingではVQAv2、GQA、ScienceQA、TextVQA、POPE、MME、MMBench、SEED等を用い、生成能力はLVIS-VQAなどでperplexityとMETEORを測る。比較にはFastVなどvision token reduction法、効率的projectorのTokenPacker、KV cache compressionのH2Oなどを含む。

実機効率の例はNVIDIA A100 80GB、batch size 8などで測定され、論文は理論TFLOPsだけでなく実GPU latency/memoryも付録で評価する。

### prefill
LLaVA-1.5-7Bは576画像token・10.1 TFLOPs。Dynamic-LLaVAの画像疎化は115 token・2.5 TFLOPsで約75%削減し、13Bでも576 token・19.6 TFLOPsから115 token・4.7 TFLOPsへ約76%削減する。

7BのVQAv2/GQA/ScienceQA/TextVQA/POPEではfull baseline 78.5/62.0/66.8/58.2/85.9に対し、画像+言語疎化版は77.9/61.3/68.6/56.5/85.9で、削減率に比べ品質差は小さい。ScienceQAでは+1.8ポイントとなる一方、TextVQAでは-1.7ポイントで、全taskが改善するわけではない。

### decodeとKV memory
LVIS-VQAの7B例では、画像+言語疎化によりKV cacheなしdecode TFLOPsが2.75/2.99から1.52/1.57へ約45〜47%減る。KV cacheありの最大cache量も103/91から63/46へ約39〜49%削減する。METEORは0.3103のbaselineに対し0.3108でほぼ同等である。

ランダムに半分捨てる方式や単純構造規則は同程度の計算削減でもPPLが11.52/9.69まで悪化し、H2Oを直接MLLMへ適用した例ではMETEORが0.0388まで崩れる。したがって「token数を減らすこと」だけでは品質維持できず、MLLM featureから学習したpredictorと段階別のdrop規則が必要である。

### TokenPackerとの併用
Dynamic-LLaVAはvision encoder/projector自体を置き換えないためTokenPackerと直交的に組み合わせられる。TokenPacker-7Bの144画像token・2.5 TFLOPsに対し、Dynamic-LLaVA併用では57 token・1.1 TFLOPsまで下がり、vision understanding平均は62.3程度を維持する。13Bでも144 token・4.9 TFLOPsから57 token・2.1 TFLOPsへ削減する。

## 既存研究との差
FastVなどvision context sparsificationは主にprefillの画像token数を減らし、長いdecodeでtext履歴が支配的になると相対利得が小さくなる。Dynamic-LLaVAは画像と生成textへ別predictorを持ち、prefill、KVなしdecode、KVありdecodeで削減対象を切り替える。

H2Oなど一般LLM向けKV圧縮は既存cacheのattention/importanceを使って保持KVを選ぶことが多い。Dynamic-LLaVAは現在生成tokenのfeatureから将来cacheへ残すか即時判断するため、KV cacheのないprefill/KVなしdecodeにも同じ言語疎化思想を適用できる。

## 限界
学習不要法ではなく、binary predictorをMLLMへ追加してend-to-end sparsification trainingを行う必要がある。keep率、predictorを挿すlayer、短出力を除外する (LEN^{OT})、正則化重みなどの設定に品質が依存し、新しいbackboneへそのまま移植して最適とは限らない。

一度dropしたtokenは後続層へ戻らないため、後半層で初めて重要になる細部を失う可能性がある。text sparsificationも現在tokenだけから将来価値を予測するので、長距離依存が後から顕在化するtaskではcache evictionが不利になり得る。

評価の中心はLLaVA-1.5 7B/13Bであり、現代のより大きなMLLM、video長系列、複数画像、高並列continuous batchingでのserving性能は直接検証していない。約50%というdecode計算/memory削減は設定したkeep率と生成長に依存する。
