# Let's Sample Step by Step: Adaptive-Consistency for Efficient Reasoning and Coding with LLMs

## 概要
自己整合性（自己一貫性）は、同じ問題へ複数の思考連鎖を標本化し、最終回答の多数決を取ることで単一生成より頑健にする。しかし標準方式は、最初の10本中9本が同じ答えの簡単な問題でも、回答が割れ続ける難問でも一律に40本など固定数を生成する。適応的一貫性はLLMやpromptを変更せず、**何本まで生成するか**だけを問題ごとに変える。

主要停止規則は、これまでの回答回数を確率分布の観測とみなし、現在の最多回答が真の最多確率を持つ信頼度を計算する。論文は完全なディリクレ判定と、その軽量近似であるBeta判定を検討し、実験ではBeta方式を適応的一貫性として使用する。信頼度が0.95を超えた問題は現在の多数派で終了し、割れている問題だけ最大予算まで生成する。

## 問題設定
固定自己整合性の費用はほぼ「一候補の生成費 × 候補数」で増える。難度が異なる問題へ同じ (k) 本を割り当てると、容易な問題の余剰候補が難問の精度改善へ使われず捨てられる。一方、単純に「過半数になったら停止」すると、序盤2対1のような弱い多数派でも終了してしまう。

必要なのは、現在の先頭候補の票差だけでなく観測数も考慮し、「さらに同じサンプリング 過程を続けても先頭候補が入れ替わりにくい」ことを安価に判定する基準である。適応的一貫性は停止規則以外を標準自己一貫性と同じに保つため、モデル再学習なしで既存CoT/PAL/コード サンプリングへ追加できる。

## 手法
### Dirichletによる多数派安定性
これまで (n) 本を生成し、異なる回答が (m) 種、回数を (v=[v_1,ldots,v_m]) とする。最多回答を1番目とし、回数からディリクレ分布を構成する。目的は、未知の回答確率 (p) をこのposteriorから考えたとき
[
P(p_1>max_{ige2}p_imid v)
]
が十分高いかを求めることにある。

例えば10本中 [8,1,1] なら多数派は安定しているが、[4,4,2] なら追加サンプリングが必要である。完全ディリクレ積分は回答種類数が増えるほど高価で、また「まだ観測していない新回答種類」を直接扱わない。論文はChinese Restaurant 過程（CRP）方式も分析し、この仮定を緩めるが、主要実装にはより単純なBeta近似を使う。

### Beta停止規則
多数派が2位候補に勝つことへ問題を縮約し、上位2候補の回数 (v_1,v_2) に非情報事前分布Beta(1,1)を加えてBeta((v_1+1,v_2+1))を作る。この分布から1位が2位より確率的に優勢である信頼度を計算し、(C_{thresh}=0.95) を超えたら停止する。

入力は回答文字列そのものではなく、その時点までの正規化済み回答回数で、出力はcontinue/停止と現在の多数回答である。一標本追加するごとに判定するだけなので、LLM forwardに比べ統計計算費は小さい。信頼度が上がらない問題は最大本数まで進むため、簡単な問題でだけ費用を削る。

### code生成への拡張
コードでは異なるプログラムが同じ機能を持ち、単純なsource文字列一致は使えない。論文は生成プログラムを評価 事例へ実行し、出力で同値化する。一つ目の方式は全評価出力vectorを一つの回答として投票する。二つ目は評価 事例ごとに多数派信頼度を計算し、各事例の確率の幾何平均が閾値を超えたとき停止する。

後者は「一つの評価だけ偶然安定した」状態で止まることを避け、複数評価全体の安定性を判定する。HumanEval/MBPPは最大100候補、APPSは50、CodeContestsは1000候補まで生成する設定なので、固定予算との差が推論 タスクより大きくなり得る。

## 評価条件
| 観点 | 条件 |
|---|---|
| モデル | GPT-3.5-Turbo、Vicuna-13B、コード-DAVINCI-002 |
| タスク数 | 17 データセット、4カテゴリ |
| 数学 | GSM8K、SVAMP、ASDiv |
| 常識 | StrategyQA、Date Understanding、SNARKS、Ruin Names、Salient Translation |
| 記号推論 | Tracking Shuffled Objects、Logical Deduction、Boolean Expressions、Disambiguation QA、Penguins |
| コード | HumanEval、MBPP、APPS、CodeContests |
| 推論 サンプリング | temperature 0.7、最大40 生成 |
| コード サンプリング | APPS 50、HumanEval/MBPP 100、CodeContests 1000 |
| 主停止閾値 | Beta 信頼度 0.95 |
| 比較 | 固定自己一貫性、random/多数決/エントロピー/ディリクレ/CRP停止規則 |
| 指標 | 精度、平均生成数、同一サンプリング コストでの精度 |

## 主要結果
4カテゴリ平均では、数学が精度 73.2→73.1で40→13.8 生成、常識が66.0→65.8で40→15.8、記号推論が72.8→72.8で40→13.1、コード生成が35.2→35.6で312.5→173.6である。コードでは早期停止しながら平均精度が+0.4ポイントになっており、固定本数を使えば必ず高精度という単調関係ではない。

モデル別ではGPT-3.5-Turboが精度 76.4→76.2、平均生成 40→10.0で4.4倍削減。Vicuna-13Bは54.0→54.1、40→21.7で1.9倍、コード-DAVINCI-002は69.7→69.8、104.1→49.4で3.4倍である。全データセット/model平均では約3.3倍少ないサンプルで、精度差は0.1ポイント未満。個別条件の最大削減は7.9倍と報告される。

同じサンプリング コストへ揃えた比較では適応的一貫性が固定自己一貫性より最大約5 精度ポイント高い。これは総予算を減らしたときにも「全問題を同じ本数へ切る」より、難しい問題へ多く候補を残す方が有利であることを示す。

停止規則比較では、単純多数決やエントロピーだけより、Beta/ディリクレ系がコストと精度の交換条件を良くする。完全ディリクレは計算量が増える一方、Beta近似は1位対2位だけを見るため軽量で、主要実験ではほぼ同等の実用性能を得る。このため論文はBeta方式を既定の適応的一貫性としている。

## 既存研究との差
標準自己一貫性は候補生成法・多数決は同じだが、問題ごとの停止時刻を持たない。適応的一貫性はモデル内部のearly exitでもtoken-level早期終了でもなく、**独立な推論 trajectoryを何本生成するか**を制御する。

後発のESCのような「小窓の全回答一致」を停止信号にする方式とも異なり、適応的一貫性は観測回数全体から多数派信頼度を確率的に見積もる。このため票が完全一致しなくても十分なmarginと標本数があれば停止できる一方、信頼度閾値という調整parameterを持つ。

## 限界
信頼度は「LLMのサンプルが同じ分布から得られ、回答回数が多数派の安定性を表す」という前提に立つ。モデルが同じ誤答へ系統的に集中する場合、強い信頼度でも正解ではない。早期停止は自己一貫性の多数決を効率化するだけで、基礎モデルのcalibrationや推論 biasを修正しない。

Beta近似は1位と2位の競争へ縮約するため、多数の候補が近接する分布では完全ディリクレ/CRPより情報を落とす。free-form回答では同値化規則も必要で、コードでは評価 事例の質が投票同値性を左右する。

また効率指標は主に**LLM 生成数**であり、GPU kernelのwall-clockを直接測っていない。複数候補を大きなbatchで同時発行するsystemでは逐次停止判定を待つことがlatencyへ不利になり、生成数3.3倍削減がそのまま3.3倍高速化になるとは限らない。
