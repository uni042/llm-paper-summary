# AgentArk：複数エージェントの討論を単一モデルへ蒸留して推論時費用を減らす

## 概要

複数のLLMエージェントが同じ問題を検討し、相互に批判・訂正して最終回答を合意する方式は、単独モデルより複雑な推論を改善できることがある。しかし、複数モデルの呼出しと数ラウンドの討論を実行時に繰り返すため、トークン数、推論遅延、GPU利用量が増える。誤った議論が他のエージェントへ伝わり、誤りを増幅する場合もある。AgentArkは、こうした討論の利点を訓練時に学習させ、推論時には単一の学生モデルだけを動かす研究である。

教師の複数エージェントによる討論を記録し、正答へ到達した推論過程と、途中で誤りを修正した過程を抽出する。これを単なる正解ラベルだけでなく、推論付き教師あり微調整（RSFT）、多様な軌跡のデータ拡張（DA）、過程報酬モデルを使う過程認識蒸留（PAD）の3系統で学生モデルへ転写する。PADは途中の論理の妥当性を学習した報酬モデルで学生の出力を評価し、グループ相対方策最適化（GRPO）で重みを更新する。

Qwen3、Gemma3、Llama3系を含む120の実験で、単一モデルに比べた推論品質の改善と、学習信号の種類・学生モデルの規模・教師エージェント数の影響を分析する。平均的な単独モデル比改善は約4.8%と報告されるが、課題・学生モデル・分布内外によって幅がある。推論時の多重呼出しを減らす代わりに、教師討論のデータ生成、過程報酬モデルの訓練、強化学習へ計算費用を前払いする。**推論費用が減ることと、訓練を含む総費用が常に減ることは別である。**

## 問題設定

### 複数エージェントの推論は高価で不安定

討論型の複数エージェント方式では、同じ質問を複数のモデルへ送り、各モデルが別の解法を提案し、他の解答を批判し、必要に応じて自分の解法を訂正する。複数の視点が誤りを見つける可能性を高める一方、モデル呼出し数はエージェント数とラウンド数に応じて増える。全員が互いの履歴を参照する密な接続では、転送する文脈も増える。モデルを多く使えば必ず品質が上がるわけではなく、誤った仮説が討論内で広がることもある。

AgentArkは、推論時の多重対話を必須にせず、討論によって生まれる「代替仮説の比較」「論理の誤りの発見」「訂正して結論へ進む」という能力を、単一モデルの生成過程へ学習させる。学生モデルが単独で解答するなら、実行時に複数エージェントの同期や討論ログを生成する必要がない。これは推論システムの実行経路を単純化するが、学習前に高価な教師データを作る必要がある。

### 正解だけでは討論の価値を学習しきれない

最終回答だけを使った教師あり学習では、問題と正解の対応を覚えても、どの途中推論が誤りで、どの批判により修正されたかを学びにくい。論文は予備実験で、正解だけの微調整が分布外の推論へ安定して一般化しないと述べる。そのため、正答へ至った推論列、異なる解法、途中の訂正という段階的な教師信号を使い、どの信号が単独モデルの品質を改善するかを比較する。

## 手法

### 1. 討論履歴の生成と正答の選別

入力問題xに対し、同じ基盤モデルを共有するn個の教師エージェントを用意し、Kラウンドまで討論する。各エージェントは前ラウンドの他エージェントの推論を見て、自分の解答を更新する。正答へ収束した問題では、最終の合意回答と、そこへ至る推論軌跡を保存する。教師が誤答から正答へ修正した軌跡を特に重視する。

最終回答は問題の正解ラベルと照合し、正しい回答へ到達した軌跡を選ぶ。正答が同じでも、数学的な分解、途中の仮定、問題解決の順序が異なる複数の推論を保持できる。誤った討論を無条件に教師信号へ入れると学生が誤りを学ぶため、正答確認と軌跡の選別が重要である。主な実験は同種の教師モデル5エージェントで行い、10・20エージェントへ増やした場合も検討する。

### 2. 推論付き教師あり微調整（RSFT）

RSFTは、最終回答だけでなく正答へ至る推論列も学生の学習対象にする。学生モデルが入力問題を見て推論トークン列を生成し、続けて最終回答を出す確率を最大化する。損失は推論列の対数尤度と最終回答の対数尤度の和を基本とする。単なる回答の模倣より途中の思考形式を学びやすいが、教師の推論を文字列として再現するだけでは、論理的に誤った段階を自分で発見する能力を十分に獲得できない可能性がある。

この方式の利点は通常の教師あり微調整に近い実装で利用できることにある。欠点は、正答へ至る複数の経路を十分に利用しない場合、教師の一つの推論様式へ過度に依存することである。RSFTが常にPADと同等の効果を持つわけではないため、論文は次の二方式と比較する。

### 3. 多様な正答軌跡によるデータ拡張（DA）

DAは討論ログから正しいが異なる解法を複数抽出する。論文はQwen2.5-72B-Instructを補助的な判定器として使い、正答であることを確認した候補の中から、構造的に異なる1〜3本の推論を選ぶ。判定器は最終回答の正しさを代替して判定するのではなく、正答条件を満たした候補の多様性を判定する役割を持つ。

学生は同じ問題について異なる正答経路を学ぶため、一つの表現や手順への依存を減らせる。ただしデータ数が増えれば自動的に品質が上がるわけではない。小さい学生モデルは複雑で長い教師軌跡を吸収しきれず、ノイズの多い教師信号で学習が不安定になる場合がある。論文のデータ規模実験でもRSFT・DAはデータ増加に対して非単調な品質変化を示す。

### 4. 過程認識蒸留（PAD）と過程報酬モデル

PADは、推論の最終正誤だけでなく途中の論理の妥当性を評価する過程報酬モデル（PRM）を訓練する。まず学生モデルの基盤重みからPRMを初期化し、最終層と報酬ヘッドだけを学習して正誤信号を合わせる。次に基盤全体を解凍し、推論過程に特化して学習する。正しい推論段階と誤った段階の報酬差を大きくする対照的な損失を用い、単純な二値分類だけでは捉えにくい相対的な質を学習する。

その後、学生モデルから同じ問題に対する複数の推論出力を生成し、PRMで評価する。GRPOはグループ内の報酬平均・分散から相対的な利得を求め、良い推論を生成する確率を高めるよう学生の重みを更新する。参照方策とのKL距離も制約に含め、学習が急激に元モデルから離れないようにする。PRMと学生を別々のモデル規模にできるため、報酬モデルの容量が学生の改善へどう影響するかも検証できる。

PADの特徴は、討論の「誤りを発見して修正する」過程を学習信号として扱うことである。推論時にはPRMや複数教師エージェントを毎回呼ぶ必要はなく、学習後の学生モデルが単独で解答する。ただし学生自身の出力が複数の推論トークンを含むことはあり、生成長がゼロになるわけではない。推論回数の減少と回答トークン数の減少は分けて評価する必要がある。

### 5. 訓練費用を推論時からオフラインへ移す

この方式は、教師エージェント群の討論、正答照合、PRM訓練、学生の方策最適化という費用をオフラインで支払う。その後は単一学生モデルを通常の自己回帰生成として実行する。大量の同種推論を繰り返す場合には、オフライン費用を多くの要求へ償却できる可能性がある。しかし少数の要求しかない場合、教師データ生成と訓練の費用が実行時の節約を上回ることもあり得る。損益分岐は教師生成量、訓練GPU時間、推論要求数、学生と教師のモデル規模、生成長によって変わる。

## 評価

### モデル、課題、実験条件

| 項目 | 原著の設定 |
|---|---|
| 教師モデル | Qwen3-32B、Gemma3-27B-itなど |
| 学生モデル | Qwen3-8B・1.7B・0.6B、Llama3-8B、Gemma-7Bなど |
| 主な教師群 | 同種モデル5エージェントの討論 |
| 拡張した教師数 | 10・20エージェントも比較 |
| 課題 | GSM8K、MATH、MedMCQA、MetaMathQA、QASPER、HotpotQA、QMSum |
| 比較方式 | 単独学生、教師の複数エージェント討論、RSFT、DA、PAD |
| 実験数 | モデル・方式・課題を変えた計120実験 |
| 主品質指標 | 正答率、分布外のF1・ROUGEなど |
| 訓練費用の測定 | NVIDIA H100 80GB、8B学生、全体バッチ4 |

モデル間で教師と学生の規模が異なり、学習の強さも方式ごとに異なる。論文は品質改善と、複数エージェントの実行を省く構造上の利点を示すが、全課題のエンドツーエンドGPU実時間を統一条件で示すわけではない。品質値と訓練費用を分けて解釈する。

### 品質改善と分布外一般化

論文は3種類の蒸留が単独学生を改善し、平均で約4.8ポイント相当の改善を報告する。特にPADは、RSFTやDAより課題をまたいで安定した改善を示す。分布内の改善は分布外より大きく、論文は最大改善が分布内約30%、分布外約7%、平均改善は分布内4〜6%、分布外1〜3%と記載する。これは各課題・モデルを横断する傾向であり、すべての学生に同じ改善が保証されるという意味ではない。

学生モデルが小さいほど、教師エージェントを増やす効果は早く頭打ちになる。Qwen3-0.6Bでは5エージェントを超えて教師群を増やしても改善しないか、悪化する場合がある。Qwen3-8Bでは教師数の増加から一定の利得があるが、追加利得は次第に小さくなる。これは教師の多様性だけでなく、学生が複雑な推論を表現できる容量が必要であることを示す。

### 過程報酬モデルの容量と学習信号

PRMを0.6Bから8Bへ大きくしたとき、同じ学生モデルでも正答率が改善する場合がある。原著付録表4はPRMと学生モデルの規模を分離して比較し、PRMの容量と推論品質の関係を検証する。ただし表は異なる学習データ・評価課題・モデル規模の集計であり、PRMだけを大きくすれば必ず同じ倍率で改善するとは言えない。教師信号の正しさ、学生の表現能力、報酬の較正も影響する。

DAで正答軌跡を増やすだけでは、性能が単調に改善しない。PADの過程報酬を用いる場合はデータ量に対する品質変動が小さいと報告する。これらは「大量の推論列をそのまま模倣する」よりも「論理の良い途中段階を選んで学習する」方が有効な場合があるという示唆であり、どのモデルにも共通する最適なデータ量を確定したわけではない。

### オフライン訓練費用

| 蒸留方式 | 追加の訓練条件 | 原著の時間 |
|---|---|---:|
| RSFT | H100 1基 | 約6時間 |
| DA | H100 1基 | 約8時間 |
| PAD（PRM＋GRPO） | H100 8基 | **約20時間** |
| PADのPRM部分 | H100 8基 | 約8時間 |
| PADのGRPO部分 | H100 8基 | 約12時間 |

8B学生、全体バッチ4、同一系列長という条件で比較する。PADは単純なRSFTより多くのGPU時間を要し、8基のH100で約20時間という値を、単一GPUの20時間と同一視してはならない。また表は**追加の学生訓練費用**を示し、全方式に共通する教師エージェント討論のデータ生成費用を含めていない。したがって、PADが推論時に安いという利点だけで全ライフサイクルの費用が小さいとは言えない。

### 推論時の費用と未測定項目

学習後のAgentArkは単一の学生モデルが一度の生成系列を出す構造であり、複数エージェントの討論を実行時に再現しない。このため要求ごとに複数モデルの呼出しと討論ラウンドを重ねる方式より、呼出し数を減らせる。論文付録は推論遅延とGPU利用量が減るという構造上の説明を行うが、ここで確認できた費用表は主としてオフライン訓練のGPU時間である。すべての課題で測定した絶対ミリ秒、ピークVRAM、トークン毎秒、運用費用の一覧を示してはいない。

品質を保つために学生が長い推論列を生成する場合、単一モデルの出力トークン数が増えることもある。したがって、教師5エージェントを1学生へ置き換えたからといって、GPU費用が厳密に5分の1になると計算することはできない。モデルサイズや生成長、バッチ化の有無を揃えた実測が必要である。

### 方式の組合せと構成要素の注意

RSFTの後にDAを追加する場合、GSM8Kで68.61から70.27、PADの後にDAを追加する場合は70.03から70.69へ改善した設定が報告される。改善はあるが小さく、追加訓練の費用に見合うかは別途判断する必要がある。PPOとGRPOの比較については、本文中の定性的な記述と付録の結果解釈に差があるため、単純にGRPOがあらゆる条件で精度優位とは扱わない。GRPOは価値関数を別に学習しないため訓練費用を抑えられるが、精度との交換条件がある。

## 既存研究との差

通常の複数エージェント討論は、実行時に異なる候補と批判を生成して品質を改善する。最終回答だけの蒸留は、結果を模倣するが途中の訂正能力を学びにくい。AgentArkは正答の推論過程、複数の正答経路、途中段階の良否という三種類の信号を整理し、単一モデルへ移す方法を比較する。PADはPRMを使って訂正・検証の過程を学習させる点で、単なる最終回答の教師あり学習と異なる。

実行基盤の観点では、複数エージェントの討論をサーバー側で高速化するのではなく、そもそも推論時の多重呼出しをなくすアプローチである。vLLMやSGLangのバッチスケジューリングと競合する技術ではなく、学生モデルを通常の推論基盤で提供する際に上位層の要求数を減らす技術と位置づけられる。

## 限界と未評価事項

**オフライン訓練の費用が大きい。** PADは8基のH100で約20時間の追加訓練を要し、教師討論のデータ生成費用はさらに必要である。少量の推論要求では償却できず、頻繁に変化する業務やモデルでは再訓練が必要になる可能性がある。実際の損益分岐点は、要求数・モデル規模・生成長・GPU単価に依存する。

**対象は主に推論課題である。** 論文は数学、知識、多段読解などの正答が測れるタスクを中心に扱う。実世界のツール操作、ファイル編集、外部環境の記憶管理、長期の自律行動については主たる検証対象ではない。複数エージェントの実行時の能力を、すべて単一モデルへ移せたと一般化してはいけない。

**教師の正答判定とPRM品質に依存する。** 教師群の合意が誤っていたり、正答判定が不完全だったりすると誤った推論を学生へ伝える。PRMが高容量でも学習データの偏りがあれば、表面的にもっともらしい推論へ高い報酬を付ける可能性がある。学生が小さすぎる場合には多様な教師軌跡が逆効果になり得る。

**推論時の絶対性能を保証しない。** 単一モデルへ置き換えることで呼出し数は減るが、生成長や学生のモデルサイズが異なるため、GPU時間、電力、メモリ、実運用料金が一定倍率で減るとは限らない。連続バッチ、複数同時要求、ネットワーク遅延、異なるGPU世代の条件を揃えたシステム評価が必要である。

**モデル・課題による一般化差がある。** 分布外の平均改善は分布内より小さく、0.6B学生では教師群を増やしても悪化する場合がある。大きいPRMを用いることで小学生モデルの改善が見られても、全ての学生・全ての課題で同じ効果が出るわけではない。モデル重みへ固定された知識は、外部環境の変更に追従するために再学習が必要になる可能性がある。
