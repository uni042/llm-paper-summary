# Script：視覚冗長性と質問関連性を組み合わせた視覚トークン削減

## 概要

Scriptは、画像・動画を扱う多模態大規模言語モデル（MLLM）の視覚トークン数を、モデルの再学習なしで減らす推論時最適化である。高解像度画像や長い動画では、視覚エンコーダが生成した大量のパッチ表現を言語モデルへ渡すため、事前充填の計算量、KVキャッシュ容量、応答までの待機時間が増大する。視覚的に似たパッチを単純に削ると、質問が指す小さな対象を失うことがある。Scriptは、**画像内での重複**と**質問に対する必要性**を別々に評価し、両方を満たす視覚トークンを残す。

手法は、余弦類似度の二部グラフを用いて冗長な視覚トークンを削るグラフ構造化枝刈り（Graph-Structured Pruning; GSP）と、質問との関連性に加えて特徴の多様性を考慮する質問条件付き意味枝刈り（Query-Conditioned Semantic Pruning; QCSP）から成る。QCSPでは質問と各視覚トークンの類似度を計算し、行列式点過程（Determinantal Point Process; DPP）に基づいて似すぎた候補を避ける。二つの候補集合を組み合わせることで、視覚的な冗長性と意味的な重要性の両方を扱う。

LLaVA-1.5-7Bで視覚トークンを576個から64個へ削った場合、10画像課題の平均指標は63.47から61.49となり、無削減モデルに対する**相対性能96.88%**を保持した。LLaVA-NeXT-7Bでは2,880個から640個への削減時に相対性能99.88%と報告する。著者の図では特定条件の事前充填時間が246ミリ秒から35ミリ秒へ短縮したと示されるが、これは**全生成処理の6.8倍高速化を意味しない**。対象モデル、トークン予算、計算量、精度指標を混同せずに読む必要がある。

## 背景と既存方式の弱点

多模態モデルは、視覚エンコーダで画像や動画の特徴を取り出し、投影器を介して言語モデルの入力空間へ変換する。LLaVA-1.5の典型的な336×336画像は576個の視覚トークンを生成し、LLaVA-NeXTでは一画像あたりさらに多数のトークンを使用する。画像パッチが増えるほど事前充填の行列演算と注意処理の負荷が高まり、生成時に参照するKVキャッシュも大きくなる。

注意得点による枝刈りは、モデルが強く注目した領域を残すが、特定のトークンに注意が集中する現象や、背景の小物が質問にとって重要である場合に弱い。類似度に基づく枝刈りは、似た視覚特徴を除去する点で効率的だが、質問が変わっても同じトークン集合を残しがちである。出力変化を最小化する方式も、計算量やモデル依存性が課題となる。例えば台所の画像で「花があるか」と問われたとき、視覚的に目立つ鍋や果物だけを残すと答えに必要な花を見落とす。

Scriptの設計は、視覚特徴間の類似性が冗長性の指標になるという経験的観察と、質問との関連性を明示する必要性を組み合わせたものだ。論文は10,000枚のCOCO画像で近接パッチの類似度を調べ、近傍だけでなく離れたパッチ間にも冗長性があると観察した。完全な類似度計算より軽い二部グラフを使う一方、質問の意味を使う第二段で誤削除を補う。

## 手法：二部グラフと質問条件付き選択

### 入力・出力と処理位置

入力は画像または動画X、ユーザー質問q、視覚エンコーダと投影器から得たトークン行列 `H_v∈R^{n×d}` である。言語モデルへ入力する前に、n個の視覚トークンから目標個数mを選ぶ。テキストの質問トークンは保持し、選別された視覚トークンと連結して通常の言語モデルに渡す。モデル重みや学習データを更新する手法ではなく、既存モデルの推論時に差し込む前処理である。

### 第1段：GSPによる視覚冗長性の除去

GSPは視覚トークンを偶数番目と奇数番目の二群へ分け、一方の群から他方の群へ全結合の二部グラフを作る。辺の重みはL2正規化した視覚特徴の余弦類似度である。全トークン対を比較する完全グラフに比べ、同一群内の辺を省くことで類似度評価の候補を減らす。これにより、近接パッチだけでなく離れた位置の似た内容も比較できる。

閾値τ以上の類似度を持つ辺を残し、各トークンの高類似度隣接数d(t_i)と平均類似度μ(t_i)を計算する。冗長性得点は、隣接がある場合に `d(t_i)×exp[γ(μ(t_i)-τ)]` とし、孤立点では元のグラフの平均類似度を用いる。冗長性得点が高いトークンから削除候補とする。付録の標準設定はτ=0.3、γ=5である。二部グラフは完全類似度方式より計算を節約する一方、偶奇分割と閾値の選び方によって検出されない冗長対も生じ得る。

前段の検証ではPOPEの90%削減条件で、完全比較の分類精度85.14%・時間100ミリ秒に対し、二部グラフは84.49%・35ミリ秒であった。完全比較が選ぶ上位集合との重なりは0.93、ランダム選択の重なりは0.52である。これは**冗長性推定段だけの比較**であり、Script全体の端末間速度を表すものではない。

### 第2段：QCSPによる質問関連性と多様性の保持

QCSPは質問トークンの埋込みを平均して質問ベクトルを作り、各視覚トークンとの余弦類似度を計算する。得点は0～1へ正規化し、視覚トークンの「この質問への関連性」を近似する。続いて、視覚トークン同士の類似度行列Sを作り、関連性の対角行列Qで両側から重み付けした `L=Q^{1/2} S Q^{1/2}` 型の核を構成する。実装説明では正規化関連性を対角行列として左右から掛ける形も示されており、正規化と核の具体式は原著の各節の定義に従う必要がある。

DPPでは、選択集合Iに対する行列式 `det(L_I)` が大きいほど、関連性の高いトークンが互いに異なる特徴を持つ集合を優先する。似たトークンだけを大量に残すことを抑え、質問に対応する多様な視覚証拠を選ぶ。固定サイズkのDPPによる最適部分集合探索は一般に計算が難しく、原著は近似的な選択処理を用いる。DPP核の正定値性や関連性得点の正規化、選択個数は実装上の重要な条件となる。

### 第3段：二つの集合の統合

GSPが残す構造的候補とQCSPが残す質問関連候補の積集合を最終候補とする。積集合だけでは目標個数mに足りない場合は、QCSP側で選択個数を増やして補充する。したがって、二つの基準のどちらか一方だけで全トークンを選ぶ方式ではない。質問に重要だが視覚的に重複したトークンや、独特だが質問に不要なトークンをどう扱うかという相反を、二段階の選別と補充で調整する。

学習不要という利点はあるが、二部グラフの類似度計算、質問埋込みの集約、DPPの選択処理にも費用が発生する。大量の視覚トークンを極端に減らすときの言語モデル側の計算節約と、選択器の追加計算を合算して評価する必要がある。

## 評価条件・比較対象・定量結果

### モデル、データ、実装環境

原著はLLaVA-1.5-7B、LLaVA-NeXT-7B、Video-LLaVA-7B、InternVL3を中心に画像・動画14課題で評価した。画像課題にはGQA、ScienceQA、VQAv2、TextVQA、VizWiz、MMVet、MMBench、MMBench-CN、MME、POPEを含み、動画課題にはLongVideoBench、VideoMME、MLVU、MVBenchを含む。比較手法はFastV、TRIM、SparseVLM、DivPrune、VisionZipなど。条件のそろうモデル・トークン予算で比較する。

実装付録ではNVIDIA H100 80GB、bfloat16、温度0.2、top-k=1、各ベンチマーク3回の平均を採用したと記載する。画像の解像度処理は336×336または672×672、動画は64フレームを均等にサンプリングして384×384へ変換する。性能保持率はモデルごとに無削減の課題スコアを100%とした**相対値**であり、正答率が99.88%に達したという意味ではない。

### 画像モデルのトークン予算別比較

この表の値は原著の表2・3に基づく。なお、原著の表3では320トークン条件のScriptは63.95・97.78%である一方、直後の本文では63.97・97.09%と記載され、表と文章が一致しない。ここでは実測比較の表を優先して採用し、不一致を監査事項として残す。LLaVA-1.5-7Bの無削減演算量は約3.817 TFLOPs、LLaVA-NeXT-7Bは約20.825 TFLOPsである。したがって「10倍削減」は特定のトークン予算における計算量の比であり、常に生成スループットが10倍になることではない。LLaVA-1.5の64トークン条件では、SparseVLMの相対性能90.86%に対しScriptは96.88%を保持し、約6ポイントの差がある。

### 動画モデルと部分機能の寄与

Video-LLaVA-7Bの64フレーム条件では、無削減の64×169トークンに対し、64×64（62.1%削減）で相対性能98.22%、64×32（81.1%削減）で95.00%、64×16（90.5%削減）で89.30%と報告する。64×32条件のScript平均スコア58.99は、FastVの54.70、DivPruneの58.04、SparseVLMの56.82を上回る。一方、圧縮が進むと無削減の62.19から58.99へ下がっており、完全な性能維持ではない。

LLaVA-1.5-7Bで16トークンのみ残す機能除去試験では、単純な削減で相対性能63.73%、GSP単独で66.58%、QCSP側の構成で91.19%、全構成で92.19%と報告する。視覚冗長性だけを削るより、質問に必要なトークンを選ぶ機構が強く寄与していることを示す。ただしこの試験は4課題の平均であり、前述の10課題平均89.51%と分母・課題集合が異なる。92.19%と89.51%を矛盾とみなしたり、同一の性能指標として直接比較したりしない。

### 事前充填・KVキャッシュ・計算量

論文図2は特定のLLaVA-NeXT-7B条件で、事前充填時間246→35ミリ秒、KVキャッシュ量約1,440→169MB、演算量約41.7→4.1 TFLOPsという比較を示す。図の条件と表3の単一画像・トークン予算別演算量（20.825→2.314 TFLOPsなど）は計測対象が異なる可能性があり、数字を合成して一つの架空の測定値にしない。最初のトークンまでの時間、モデル全体の生成速度、KVメモリ、演算量は異なる評価軸である。

## 限界・再現性・適用上の注意

第一に、質問条件付き選別では質問を平均埋込みに圧縮するため、複数対象・否定・位置関係・時間的な参照を含む質問の意味が十分に残らない場合がある。質問の語順や複雑な関係を扱うための明示的な言語推論モデルを学習するわけではない。視覚特徴の余弦類似度も、似て見えるが正答に必要な微小な違いを保持する保証にはならない。

第二に、DPPによる多様性重視の選択とGSPによる冗長性除去は補完的だが、どちらも追加の前処理計算を必要とする。GPUや入力長、バッチサイズによっては削減前処理が事前充填の節約を相殺し得る。論文の最大6.8倍は特定条件の事前充填であり、単一の低解像度画像や短い動画、生成トークンが長い対話で同じ倍率になるとは限らない。

第三に、モデル間・タスク間の平均指標はベンチマークの重み付けに依存する。特にMMEのような他の指標と尺度が異なる評価値を正規化して平均する際、全タスクで一律の改善が起きたとは限らない。保持率96.88%も、絶対スコア61.49/63.47という差を伴う。極端な削減では小さな対象や詳細なOCR情報の欠落が増える可能性がある。

第四に、主実験はH100 80GB・bfloat16の高性能GPUで行われた。Windows上の12GB級GPUやCPUオフロードを含む構成での前処理費用、メモリ割当て、バッチ化性能は実測されていない。ユーザー環境への導入を検討する場合、まず同じ視覚エンコーダ・投影器から得た特徴を取得できるか、既存推論エンジンの入力経路に間引きを挿入できるかを確認する必要がある。

最後に、本文は再学習不要・モデル非依存と説明するが、実装時には各モデルの視覚トークン配置、動画フレーム構造、位置符号化、特殊トークンの取り扱いに注意が必要である。著者固有の公式コードの動作確認はできていないため、原著の結果は一次PDFで照合した報告値であり、独立再現済みの数値ではない。
