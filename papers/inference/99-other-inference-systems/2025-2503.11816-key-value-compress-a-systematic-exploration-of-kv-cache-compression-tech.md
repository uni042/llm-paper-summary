# Key, Value, Compress：KVキャッシュ圧縮の四軸分類と評価条件の横断比較

## 概要

Neusha Javidnia、Bita Darvish Rouhani、Farinaz KoushanfarによるCICC 2025の論文である。長文脈の大規模言語モデルで問題になるキー・バリュー（KV）キャッシュの容量を減らす方式を、**どの軸の冗長性を削るか**という視点で整理する。四つの軸は、Transformerの層、注意ヘッド、履歴トークン、ベクトルの隠れ次元である。さらに、モデルを最初から学習する方式、学習済みモデルを追加学習する方式、学習不要で推論に適用する方式を区別し、代表研究の品質指標と遅延倍率を一覧化している。

この論文は新しいKV圧縮アルゴリズムを実装して従来方式を同一GPUで比較した研究ではない。表1〜4は各先行論文に記載された数値を集めたもので、モデル規模、課題、評価指標、バッチ、GPU、ベースラインが異なる。著者自身も第6節で、同一条件の公平な比較と、GPUメモリ量・処理量の標準化評価が未実施であることを今後の課題とする。したがって表4の2.87倍と1.86倍を並べて前者が後者より優れた方式と結論付けることはできない。

## 問題設定と分類軸

自己回帰生成では、過去トークンのキーKとバリューVを層ごとに保存し、新しいクエリQがその履歴を参照する。KVキャッシュは履歴長、層数、KVヘッド数、ヘッド次元に比例して増える。論文は例として、グループ化クエリ注意（GQA）と8ビットKV量子化を使う65B級モデルでも、512Kトークンを保持すると約86GBのGPUメモリが必要になり、80GB級の単一GPUを超える場合があると記す。この例は著者が引用した既存研究に由来し、すべての65Bモデルへ一般化できる値ではない。

KV圧縮の議論では「何を削るか」を混同しやすい。層を削る方式は一部の層のKVを作らない。ヘッドを共有する方式は複数クエリが同じKVを読む。トークンを削る方式は履歴の一部を捨てるか圧縮する。隠れ次元の量子化は保持する値のビット数を減らす。いずれも保存量を下げ得るが、品質低下の原因と必要なモデル変更が異なる。著者はこの構造上の違いを最初の分類軸にし、その上で追加学習の要否を別軸としている。

| 圧縮軸 | 何を共有・削除するか | 代表方式 | 典型的な条件・費用 |
|---|---|---|---|
| 層方向 | 層間でKVを再利用、または一部の注意層を削除 | YOCO、Attention Drop | モデル設計変更や事後の層削除・回復学習が必要になり得る |
| ヘッド方向 | 複数クエリヘッドに同一KVヘッドを共有 | MQA、GQA、MLA | 学習済みモデルのヘッド構造や投影を変える必要がある場合が多い |
| トークン方向 | 履歴トークンの選択、結合、入力文脈の短縮 | H2O、LazyLLM、FastGen、DMC、LLMLingua | 保持判定や前処理、情報欠落、タスク依存性の費用 |
| 隠れ次元方向 | K/Vの数値精度・表現幅を圧縮 | 量子化一般 | 量子化誤差、尺度情報、復元カーネルの費用 |

論文第4節は層・ヘッド・トークンの具体例を重点的に説明し、隠れ次元の量子化は一般的な技術として短く扱う。したがって本論文を「量子化方式の網羅的な性能比較」と紹介するのは不正確である。

## 手法：KV圧縮の分類体系

層間共有（Cross-Layer Attention）は、各Transformer層が独立にKVを保存するという前提を緩め、特定の層が生成したKV表現を後続層でも使う設計である。論文図1は連続する層間の共有と、後半層のみの共有という二つの形を描く。例に挙げられるYOCO（You Only Cache Once）は、前半の自己注意側で得たキャッシュを後半の交差注意側が共有する構成であり、通常のTransformerと異なるモデル設計・学習が必要になる。キャッシュを一度だけ保持できる利点はあるが、既存の任意のモデルに学習なしでスイッチを入れるだけの方式ではない。

選択的注意削除（Layer-Selective Attention）は、そもそも全層に注意機構が必要かを問い、冗長な注意層を見つけて取り除く。論文はAttention Dropを例に、層の入力と出力の余弦類似度を用いて冗長性を推定し、学習済みモデルに事後適用する流れを説明する。図2では、注意層がない部分には対応するKVキャッシュも不要になることを可視化している。層間共有と違い、削除した層の機能を他層へ肩代わりさせる必要があり、品質・回復学習・層配置の選択が重要になる。

この二方式は「層方向」という分類では同じだが、共有は計算に使うKV表現の参照先を変え、削除は注意演算自体を消す。キャッシュ容量だけでなく演算量・モデル品質への影響が異なるため、同一の速度倍率を期待するのは誤りである。

### ヘッド方向の圧縮：MQA・GQA・MLA

多クエリ注意（Multi-Query Attention; MQA）は、複数のクエリヘッドが一組のキー・バリューを共有する方式である。KVヘッド数を減らせるので、デコード時のKV読み出し帯域を減らす効果がある。ただしクエリごとの独立したKV表現が失われるため、モデルを学習・調整して品質を保つ必要がある。論文はT5-XXLを基準にした事後学習の比較を表2へ収めている。

グループ化クエリ注意（Grouped-Query Attention; GQA）はMQAと通常の多ヘッド注意（MHA）の中間である。クエリヘッドをグループへ分け、グループ内でKVヘッドを共有する。KV容量とヘッドごとの表現能力を交換する構造であり、共有グループ数によって容量・品質が変わる。表2のGQA-8-XXLはT5-XXLの同じ課題集合に対し平均47.2から47.1となり、MQA-XXLの46.6より元の精度に近い。ただし、ここからすべてのモデルでGQAがMQAより優れるとは結論できない。

多ヘッド潜在注意（Multi-Head Latent Attention; MLA）は、低次元の潜在表現を保持し、注意に必要なキー・バリューを投影して使う設計として紹介される。MQA/GQAのような単純なヘッド共有とは機構が異なり、KVを低次元潜在空間へ圧縮するため、ヘッド軸と隠れ次元軸の境界に位置する。論文の分類ではヘッド方向に置かれているが、実装を比較する際は潜在ベクトルの復元計算・回転位置符号化・カーネル対応も評価しなければならない。

### トークン方向の圧縮：三つの異なる設計

第一は**履歴トークンの選択・削除**である。H2Oは注意で重要なトークンを残し、相対的に重要度の低いKVを追い出す。LazyLLMは生成時に層ごとの注意情報を使ってトークンを選別し、後段で処理する集合を段階的に減らす。いずれも元の長い入力から一部を落とすため、削除した情報が後の質問に必要になる場合は品質が低下し得る。FastGenはプロンプト処理時に注意ヘッドごとの振る舞いを調べ、局所的なヘッドでは遠方文脈を捨て、特別トークンを重視するヘッドではそれ以外を落とすなど、ヘッド単位の異なる圧縮規則を選ぶ。

第二は**入力プロンプトそのものの短縮**である。CPCは文単位の関連性を使って重要な文を選び、LLMLinguaは小型言語モデルのPPLからトークンを間引く。LongLLMLinguaは質問と文書の関連性を先に評価して文書単位の粗い選別を行い、その後に細かいトークン圧縮を適用する。TCRAはT5系の別モデルで要約または意味圧縮を行う。これらは通常、生成モデルのKVを生成後に追い出すのではなく、最初から生成モデルへ渡す入力を短くする方式である。プロンプト前処理の時間・追加モデルの費用があるため、単にKV容量の削減率だけで比較してはいけない。

第三は**新規トークンのKVを結合する動的メモリ圧縮**である。Dynamic Memory Compression（DMC）は各ステップで現在のKVを新しいエントリとして追加するか、直近エントリへ重み付き平均で統合するかを予測する。削除したトークンを復元しない方式とは異なり、近接した複数トークンの情報を一つのKV状態へ圧縮する。学習済みモデルへの追加学習を要し、論文表2では元のLlama2-7B平均43.03に対しDMC 2倍圧縮が43.73となる。ただしこの上昇を圧縮自体の純粋な効果と断定できず、追加学習の寄与を分離する必要がある。

### 学習条件による第二の分類

著者は圧縮軸とは独立に、最初からモデルを学習する方式、事後学習する方式、学習不要の方式を比較する。新規学習型はYOCO、Mamba、Mamba2などであり、既存の重みへ即時適用することはできない。事後学習型はAttention Drop、MQA/GQA、DMCなどで、元モデルを利用しながらも追加学習の計算・データが必要になる。学習不要型はCPC、LongLLMLingua、LazyLLM、H2Oなどで、利用者の入力やKV保持方針を変えることによって即時に適用できる可能性がある。

ただし「学習不要」は追加処理ゼロを意味しない。CPCは文の関連性推定、LongLLMLinguaは別の言語モデルによる重要度計算、LazyLLMは層ごとの注意情報を使った選別が必要になる。モデルの学習費用とオンライン実行費用は別の軸で評価すべきであり、本論文はそれらを同じ計算資源で実測してはいない。

## 評価：原著結果の比較と限界

原著第5節の表1〜3は、方式の種類ごとに元論文から性能平均を転記したものである。課題集合や尺度が異なるため、表中の「平均値」を別方式間で単純比較することはできない。以下は特に誤読しやすい条件を残した抜粋である。

| 方式・比較 | 原著の平均値（基準→方式） | 相対変化 | 注意すべき条件 |
|---|---:|---:|---|
| YOCO-3B 対 OpenLLaMA-3B-v2 | 61.9 → 63.4 | +2.42% | 最初から学習する別アーキテクチャ同士の比較 |
| Mamba-2.8B 対 RWKV-3B | 59.6 → 63.3 | +6.21% | モデル構造が異なり、KV削減のみの因果効果ではない |
| Attention Drop-4 対 Llama-2-13B | 68.2 → 68.5 | +0.44% | 注意層4個を削除した条件、事後調整を伴う |
| MQA-XXL 対 T5-XXL | 47.2 → 46.6 | -1.27% | CNN、翻訳、QAなど複数指標の平均 |
| GQA-8-XXL 対 T5-XXL | 47.2 → 47.1 | -0.21% | 同じT5系比較だがヘッド共有設定が異なる |
| DMC 2倍圧縮 対 Llama2-7B | 43.03 → 43.73 | +1.63% | MMLU、CS-QA、HumanEvalなどの混合指標 |
| CPC 対 GPT-3.5-turbo | 44.0 → 50.0 | +13.64% | LongBench、学習不要の入力圧縮 |
| LongLLMLingua 対 GPT-3.5-turbo | 44.0 → 48.3 | +9.77% | LongBench、CPCと処理費用は同一ではない |
| LazyLLM 対 Llama2-7B | 32.65 → 32.29 | -1.10% | LongBenchで小幅な品質低下 |
| H2O 対 Llama2-7B | 43.03 → 40.83 | -5.11% | MMLU、CS-QA、HumanEvalの混合評価 |

この表で重要なのは、圧縮が常に品質を悪化させるわけではない一方、品質向上を圧縮だけの効果と解釈できない点である。新規学習型ではモデル構造や学習条件が変わり、事後学習型では追加学習が効く。入力圧縮では冗長文脈の削除による正則化的な効果も考えられる。反対に、H2Oの-5.11%やLazyLLMの-1.10%は、履歴の一部を削除する方式で品質低下が起こる具体例である。

### 遅延比較は同じ指標ではない

表4は速度倍率の一覧だが、初回トークン遅延（TTFT）、プリフィル、次トークン生成、終端遅延が混在する。さらにH100、A100、V100などGPUと基準モデルが異なる。

| 方式 | 比較条件 | 倍率 | 遅延の種類 | 計算基盤 |
|---|---|---:|---|---|
| YOCO-3B | 32K文脈、GQA・Flash-Decoding・融合カーネルを使うTransformer基準 | 2.87倍 | プリフィル | H100 80GB |
| Attention Drop-4 | 512〜4096トークン、Llama-2-13B基準 | 1.05倍 | 終端遅延 | A100 80GB |
| LazyLLM | 入力3376＋生成68、Llama2-7B基準 | 2.03倍 / 1.33倍 | 初回トークン / 終端 | A100 |
| DMC 8倍圧縮 | 入力2K＋生成2K、Llama2-7B基準 | 1.25倍 | 次トークン生成 | H100 80GB SXM |
| LongLLMLingua | 入力3376＋生成68、GPT-3.5-turbo基準 | 2.6倍 | 終端遅延 | V100 32GB |
| H2O | 入力2048＋生成2048、OPT-6.7B-FlexGen基準 | 1.86倍 | 終端遅延 | A100 80GB |
| FastGen | 入力4096＋生成4096、Llama1-7B-DeepSpeed基準 | 1.56倍 | 終端遅延 | V100×8 |

CPCの10.93倍はLongLLMLinguaを比較対象とした別の行であり、GPT-3.5-turboの無圧縮基準と比較した値として使わない。さらに、原著表4のYOCO 2.87倍は**プリフィルのみ**の倍率であり、生成全体が2.87倍速いとは書けない。LazyLLMの2.03倍は初回トークン、1.33倍が終端遅延である。DMCの1.25倍は次トークン生成であり、プリフィルを含むエンドツーエンド倍率ではない。

## 限界：調査範囲と論文固有の限界

本研究の意義は、容量削減の次元と適用段階を直交した二軸で整理し、同じ「KV圧縮」の中にもモデル再学習が必要な構造変更と、推論時の履歴選択が混在することを示した点にある。モデルを新規学習するYOCOと、プロンプトを短くするCPCを一つの速度ランキングへ混ぜる危険性を明確にした。表1〜4に、どの方式がどの課題・GPU・指標で評価されたかを残した点は、後続研究が公平な比較条件を設計する際の出発点になる。

一方、著者は自ら同一モデル・同一GPU・同一データセットで再実験していない。表中の相対精度は、異なる評価指標の平均を採用する場合もあるため、方式間の精度差の統計的有意性を直接判定できない。バッチサイズ、文脈長、プロンプト構成、KV実メモリ容量、圧縮・復元処理のGPUカーネル時間も統一されていない。GPUメモリ使用量とトークン/秒の包括的な比較が不足していることを、論文自身が第6節で明示する。

また層・ヘッド・トークン・隠れ次元という分類は便利だが、実際の方式は複数軸にまたがる。YOCOは層間共有とGQAを組み合わせ、MLAはヘッド共有というより潜在次元圧縮、MambaはそもそもTransformer型のKVキャッシュを持たない。したがって「四軸は相互排他的な分類」ではなく、どこに主要な節約効果があるかを示す整理として読むべきである。

推論基盤の設計へ適用する際には、対象モデルを固定し、元の品質を揃えた上で、ピークKV容量、プリフィル時間、初回トークン遅延、デコードのトークン/秒、終端遅延、追加学習費用を分けて比較する必要がある。量子化・トークン追い出し・CPU退避を組み合わせた場合の誤差と帯域負荷も、このサーベイの表だけでは決定できない。

## 既存研究との差・今後の検証課題

個別のH2O、LazyLLM、DMC、YOCOなどは、それぞれ独自方式の有効性を評価する。一方、本論文は**圧縮する対象軸・学習の要否・報告された速度指標**を同じ表で追えるようにした比較研究であり、単一手法の最高性能を主張するものではない。今後の統一評価では、同一の元モデルを使える方式群とモデル再学習が必要な方式群を分け、同一GPU上で圧縮前後の品質と資源消費を測定する必要がある。特に短い生成では前処理費用が支配的になる一方、長文脈の多数並列ではKV帯域と容量が支配的になる可能性があり、用途別の最適方式は変わり得る。
