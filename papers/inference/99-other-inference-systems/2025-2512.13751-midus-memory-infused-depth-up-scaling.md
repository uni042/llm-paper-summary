# MIDUS：注意ヘッド別の検索型メモリで層拡張を軽量化する

## 概要

MIDUS（Memory-Infused Depth Up-Scaling）は、既存の言語モデルの層数を増やすDepth Up-Scaling（DUS）の追加パラメータと計算を削減するモデル拡張方式である。一般的なDUSはTransformerブロックを複製するため、追加した注意層だけでなく、幅の広い全結合フィードフォワードネットワーク（FFN）も複製される。MIDUSは追加ブロックのFFN枝を検索型メモリに置き換え、注意ヘッドの出力をそのままメモリ検索クエリに利用する。

具体的には、Head-wise Memory Layer（HML）が各注意ヘッドに別々の積鍵検索空間を持たせ、Head-wise Implicit Value Expansion（HIVE）が共有潜在値表からヘッド固有の出力を生成する。これにより、メモリスロットを多数持っても毎トークンで全スロットを計算せず、全ヘッド分の巨大な値表も必要としない。モデルの重みを縮小する量子化ではなく、**新たに追加する層の設計を変える**研究である。

Llama-3.1-8Bから拡張した構成では、OpT-DeUSの総11.52Bパラメータ・推論GPUメモリ27.0GB・生成41.3 tokens/sに対し、MIDUS-HMLは8.45B・20.1GB・50.5 tokens/sを報告する。生成処理率は約1.22倍、推論メモリは約25.6%減である。ただし測定は単一RTX 6000 Blackwell上の指定条件であり、既存の8Bモデルに後付けするだけで速度が上がるという意味ではない。［一次資料：Table 2、Appendix A.8］

## 問題設定と既存研究との差

既存のDepth Up-Scalingは、事前学習済みブロックを複製・挿入し、追加部分を継続事前学習（CPT）で適応させる。SOLARは連続するブロック群を積み、Llama Proは選択した位置に複製ブロックを挿入する。LESAやOpT-DeUSは挿入位置や初期化を改善するが、追加ブロックがFFNの大きな密行列を持つ点は共通する。FFN複製は、追加した容量に比例して重み容量、学習時の活性保持、推論時の行列積を増加させる。

一方、Product-Key Memory（PKM）はキーを行・列の2つの小表へ分解し、全スロットを直接走査せずに少数の値だけ検索できる。UltraMemは暗黙的な値表現を導入して容量を抑える。ただし、値をヘッド間で共有する設計では、異なる役割を持つ注意ヘッドが同じ実現済み値空間へ制約される。MIDUSの独自性は、単にFFNをPKMへ置換することではなく、**注意ヘッドごとの検索キーと、共有潜在値表からのヘッド別出力射影を両立する点**にある。

本論文は「学習高速化のみ」ではなく、拡張後のモデルの生成スループットと推論GPUメモリを測定しているため、推論システムのアーキテクチャ・モデル圧縮系統にも直接関連する。ただしモデルの追加学習を必要とするため、学習済みチェックポイントへ学習なしで適用するランタイム最適化とは区別する。

## 手法

### 1. 追加ブロックの挿入と初期化

標準のTransformerブロックを `B(x)=a(x)+FFN(LN(a(x)))`、`a(x)=x+Attn(LN(x))` と表す。従来のDUSでは、選んだアンカーとなるブロックの**後ろ**に複製ブロックを置く。MIDUSでは、同じアンカー位置に対応するMemoryブロックを**前に**置く。これにより、追加Memoryブロックの注意パラメータを直後の事前学習済みブロックから初期化でき、対応する文脈表現を使って検索型残差を学習する。配置順序の違いは原著の式(3)・(4)に明記されている。

追加Memoryブロックは `M(x)=x+Mem(a(x))` とし、値表をゼロで初期化する。開始時には `Mem(a)=0` となり、追加ブロック全体が恒等写像として振る舞う。このため、挿入直後のモデル出力を元のバックボーンから大きく逸脱させず、CPTで残差を徐々に獲得できる。これは通常のDUSで追加層の初期化が不適切な場合に起こる学習不安定性への対策である。値表のゼロ初期化は推論時のスロット検索を不要にするものではなく、あくまで学習開始時の性質である。

Llama-3.2-1Bでは16層に8つ、Llama-3.1-8Bでは32層に16の追加モジュールを挿入し、最終的な深さはそれぞれ24層・48層になる。基礎モデルの重みはCPTで凍結し、挿入モジュールを学習する。SFT段階では全パラメータを更新する。追加位置の分散配置（Distributed）と上層集中（Top-heavy）は、同じ計算費用ではなく品質と学習費用の交換関係を持つ。［Appendix A.4、A.7.5］

### 2. HMLの積鍵検索：ヘッドごとにTop-kだけを取得

通常の線形メモリは、クエリ `q` と全 `N` 個のキーの内積を計算するため、検索演算量がスロット数に比例する。HMLは注意の出力射影前の各ヘッド出力 `a_h(x)` を直接クエリ `q_h` に使い、追加のクエリ投影 `W_q` を省く。ヘッドを分離したまま、クエリを行側と列側に分割する。各側には `n` 個の部分キーを用意し、その直積 `N=n²` がアドレス可能な複合キーとなる。

各トークン・各ヘッドについて、まず行・列それぞれの部分キーとの類似度を計算する。各側からTop-kを選ぶと、直積は最大 `k²` 個の候補ペアになる。候補ペアのスコアは行・列のスコアの和で定義し、そこから最終Top-kを選択する。選択スコアをsoftmaxで重みに変換し、対応する値表の行だけを読み出して加重和を取る。デフォルトは `n=64`、`N=4096` スロット/ヘッド、`k=4` である。

この段階的な候補選択は、全複合キーのスコアを作る `O(T N d_q)` に対し、部分キーへのスコア計算を `O(T n d_q)` 程度に削減する。`N=n²` なので、キー照合部分の規模はスロット数の平方根に比例する。ただし実際にはTop-k選択、索引アクセス、値の集約とCUDA起動の費用が加わるため、式の計算量削減だけで生成速度を予測してはいけない。［§4.2、Appendix A.3.1］

### 3. HIVE：共有潜在値表をヘッド固有の出力へ展開

各ヘッドに完全独立な値表 `V_h∈R^(N×d_h)` を置くと、値パラメータ数は `H N d_h` になる。HIVEは代わりに共有潜在表 `V̄∈R^(N×r)` と、ヘッド別の小さな射影 `W_h∈R^(r×d_h)` を持つ。ヘッドごとの検索で得た潜在値の加重和 `M̄_(h,t)` を計算し、`M_(h,t)=M̄_(h,t) W_h` によりヘッド固有の出力へ変換する。全ヘッドの結果を連結し、Memoryブロックの入力 `x` へ残差加算する。

必要な値パラメータは `N r + H r d_h` となり、完全独立な値表の `H N d_h` より小さい。論文が用いる `r=d_h` なら `N d_h+H d_h²` であり、スロット数が大きい場合ほど共有の効果が大きい。検索キーはヘッド固有、潜在値の格納先は共有、最終的な値の解釈はヘッド固有という三段構成である。単一の共有値表を各ヘッドがそのまま読むPKMとは、**同じ潜在行を読んでもヘッド別射影で別の意味の補正を生成できる**点が異なる。追加計算として各ヘッドの小行列射影が必要であり、値の集約は不規則なメモリアクセスを伴う。［式(5)］

### 4. 実装上の律速とCUDA最適化

HMLの検索はGEMM中心のFFNと違い、索引付き読み出し・疎な重み付き集約が主体になる。著者は行・列のTop-k候補の直積選択を融合して小バッチでのカーネル起動負担を抑える。また、検索値の集約を専用のCUDA処理へ寄せることで、不規則アクセスのオーバーヘッドを減らす。訓練の逆伝播では複数トークンが同じ値表の行へ勾配を書き込むため、原子的加算の競合が発生する。

Appendix A.3のdeduplicated backwardでは、まず各検索結果から値表の勾配寄与を作り、検索された行番号を重複排除し、同じ行への寄与を事前集約してから一回の書込みにまとめる。数式上は通常の値表勾配と同等だが、浮動小数点の加算順序は変わり得る。この工夫は主に学習時の値表更新費用を減らすもので、推論時のトークン処理率改善を直接保証する機構ではない。

## 限界・負の結果・解釈上の注意

第一に、MIDUSは学習なしの後付け高速化ではない。新しいメモリブロックのCPTと、場合によってはSFTが必要であり、単にモデルのFFNをメモリへ差し替えれば品質が保たれるわけではない。初期化で恒等写像を保証しても、学習後のヘッド別メモリがどの程度のタスク一般化を獲得するかは別問題である。

第二に、推論速度は拡張なしのBaseを超えない。Table 2の生成処理率はBase 61.0、MIDUS-HML 50.5 tokens/sである。推論GPUメモリもBase 19.2GBに対しMIDUS 20.1GBと増加する。提案の利点は**追加容量を持つDUS方式同士の比較**で成立する。一般のKVキャッシュ圧縮やモデル全体の量子化と同じ性能軸で直接比較することはできない。

第三に、HMLのメモリ検索は不規則なアクセスを伴う。本文の平方根スケーリングはキー候補スコア計算に関するもので、Top-k、インデックス生成、潜在値集約、ヘッド別射影、メモリ帯域の総費用まで含めたエンドツーエンド計算量ではない。CUDA最適化を実装しても、別のGPU、短い入力、バッチ1で同等の高速化が出るかは検証されていない。

第四に、数学的な優位性は固定検索係数を仮定した制限付き最小二乗モデルの結果である。各ヘッドの理想値表が共有潜在因子に分解可能である等の条件下では、HIVEがヘッド固有値表の最適値を実現し、単一共有値表には誤差下限が残る。しかしこれは、学習可能なTop-k検索を含む任意の非線形TransformerやFFNを一律に支配するという定理ではない。著者自身もFFNとの比較を構造上の類推に限定している。［Theorem 4.1、Appendix A.9］

第五に、Llama-3.1-8BのTable 1の比較値には先行論文から転記された結果が含まれ、比較条件の完全同一性には注意が必要である。LongBenchのSyntheticでの悪化、Top-k増大時の処理費用、Top-heavyとDistributedの学習費用差など、提案方式に不利な結果も評価に含まれる。公式コードは論文脚注に公開先があるが、ここでは公開リポジトリの再現実験・コミット固定・RTX 4070 SUPERでの実機再測定は行っていない。

## 既存研究・推論系統との位置付け

MIDUSはMoEのようなトークンごとの専門家ルーティングとは異なり、**挿入された残差ブロックのFFN容量を、ヘッド別の疎検索型メモリへ置き換える**。PKMやUltraMemとは、積鍵検索の要素を流用しながら、注意ヘッドの役割に合わせた値の実現方法を変える点で異なる。Llama Pro・OpT-DeUSとは、層の挿入位置だけでなく追加ブロックの計算形態そのものが違う。

推論サーベイでは、`model architecture / conditional or sparse computation / memory-augmented inference` の交差領域に位置付けるのが妥当である。継続事前学習は必要だが、最終成果のモデル容量、推論時GPUメモリ、生成処理率が測定されている。民生GPUへの適用は、メモリ表の配置、Top-kカーネル対応、CUDA実装のビルド互換性、量子化併用の品質影響を別途検証する必要がある。
