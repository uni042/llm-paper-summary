# Self-attention Does Not Need O(n^2) Memory

## 概要
本論文は、標準的なソフトマックス自己注意（softmax self-attention）そのものを近似せず、計算順序と再計算だけを変えることで、通常実装が保持する (n\times n) の注意行列を不要にできることを示す。単一クエリの注意は系列長に対して (O(1)) の追加メモリ、自己注意全体は理論上 (O(\log n)) メモリで厳密に計算できる。並列アクセラレータ向けの実用実装では並列性との折衷として (O(\sqrt n)) メモリを用いる。

系列長16,384では、標準実装に比べ注意部分のメモリオーバーヘッドを推論で59倍、微分で32倍削減した。時間計算量は依然 (O(n^2)) だが、「正確な自己注意には二次メモリが必須」という実装上の前提を崩した点が重要である。

## 問題設定
標準Transformerでは、全クエリと全キーの内積から (n\times n) の注意スコア行列を作り、ソフトマックスを適用して値（value）と掛ける実装が一般的である。系列長が伸びると、この中間行列がGPU/TPUメモリを二次的に消費し、演算能力が残っていてもメモリ不足で長系列を処理できなくなる。

疎注意や低ランク近似は計算量・メモリを減らせるが、注意演算そのものを変更する。本論文は出力を変えず、必要な統計量だけを逐次保持することで中間行列を物理的に保存しない。

## 手法
### 1. 単一クエリのオンラインソフトマックス集約
あるクエリに対して全キーのスコアを一度に保存する代わりに、キー・値を順に処理し、現在までの最大スコア、指数和、値の重み付き和だけを保持する。新しいスコアが現在最大値を上回った場合は、過去の指数和と重み付き和を新しい最大値基準へ再尺度化する。

このオンライン更新により、数値安定なソフトマックスと同じ結果を得ながら、長さ (n) のスコア列を保存しなくてよい。単一クエリについて必要な状態は系列長に依存しないため、追加メモリは (O(1)) になる。

### 2. 自己注意をチャンクへ分割
自己注意では多数のクエリを同時に処理するため、クエリとキー・値をチャンク（chunk）へ分割する。各クエリチャンクに対してキー・値チャンクの部分統計を計算し、最大値の基準を合わせながら結合する。全注意行列ではなく、現在処理しているブロックと集約状態だけを持つ。

理論的には再帰的な分割で (O(\log n)) メモリまで減らせるが、GPU/TPUでは小さすぎるチャンクが並列性を壊す。そこで実用実装はおおむね (sqrt n) 規模のチャンクを使い、空間量 (O(\sqrt n)) と十分な行列積並列性を両立させる。

### 3. 逆伝播は再計算で中間保存を避ける
学習時の微分では、標準実装なら順伝播で保存する注意中間値を、必要時に再計算するチェックポイント（checkpointing）方式を使う。これによりメモリは減るが、同じ注意計算を一部繰り返すため、推論より大きな速度費用を払う。

この設計は、メモリ削減の原因が注意近似ではなく「中間状態の保存を再計算へ置換したこと」にあると明確に分離している。

## 評価条件
JAX/Flax実装を用い、長系列の合成注意ベンチマークとTransformer学習の双方で評価した。系列長を増やしながら、標準注意と提案実装のメモリオーバーヘッド、推論時間、微分時間を比較している。

学習品質についてはWMT英独翻訳（WMT En-De）の簡易Transformerを用い、100,000ステップ学習した標準注意と省メモリ注意を比較した。提案方式は数学的に同じ注意を計算するため、ここでは速度・メモリのために学習品質が崩れていないかを確認する役割を持つ。

## 主要結果
系列長16,384では、推論時の注意メモリオーバーヘッドを標準実装から59分の1、微分時には32分の1まで減らした。微分の例では標準注意が約2.0GBの追加メモリを使う条件で、省メモリ実装は約64MBに抑えている。

推論速度は標準注意から数%程度の差に収まる条件が多い一方、微分では再計算のため速度低下が大きく、系列長16,384付近ではおよそ35%の計算速度低下を報告する。したがって学習では「メモリを32倍減らせるが再計算費用を払う」という明確な交換条件がある。

WMT英独翻訳では100,000ステップ後の評価精度が提案方式62.69、標準注意62.59で、BLEUも同程度だった。小さな数値差は提案法が別の近似注意を学習したためではなく、同じ注意式を異なる計算順序で処理していることと整合する。

メモリ削減は系列長が大きいほど効く一方、時間計算量自体は (O(n^2)) のままである。したがって本方式が解消するのは主に二次メモリであり、極端な長系列では最終的に二次演算量が律速になる。

## 既存研究との差
疎注意・線形注意は、注意パターンやカーネルを変更して時間計算量も下げようとする。本論文は標準ソフトマックス注意を厳密に保ち、オンライン正規化、ブロック分割、再計算だけでメモリを削減する。この「注意行列をHBMへ実体化しなくてよい」という設計は、後のFlashAttention系の入出力認識型（IO-aware）注意カーネルへつながる基礎的な考え方である。

## 限界
時間計算量は (O(n^2)) のままなので、系列長がさらに増えると演算時間そのものは解消されない。実用実装の (O(\sqrt n)) メモリは、理論上の (O(\log n)) より大きい代わりにアクセラレータの並列性を優先した折衷である。

学習時は中間値の再計算が必要で、メモリ節約の代償として速度が低下する。評価実装はJAX/Flaxと当時のアクセラレータ環境を対象としており、後年の融合カーネルや現代GPUで同じ絶対性能差になるとは限らない。
