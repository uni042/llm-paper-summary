# Self-attention Does Not Need O(n²) Memory：注意行列を保存しない厳密な自己注意

> ソフトマックス注意の最大値、指数和、値の重み付き和を逐次更新し、全注意行列を実体化せず同じ数学的出力を得る。理論上の省メモリ算法と、TPU向けのチャンク並列実装、再計算を使った微分を示す。

## 概要

標準的な自己注意は、全クエリと全キーの内積を`n×n`のスコア行列へ格納してからソフトマックスを適用する実装が多い。そのため系列長nが大きくなると、入力・出力テンソルよりも注意行列の中間メモリが大きくなり、GPUやTPUの計算能力が余っていても長い系列を処理できない。疎注意や線形注意は注意演算を変更して計算量を削減するが、本論文は**標準のソフトマックス注意を近似せず、計算順序と保存する中間値だけを変える**。

単一クエリでは、各キー・値を順に読みながら指数スコアの総和と値の重み付き総和を更新する。指数計算が数値的に発散しないよう、これまでの最大スコアも保持し、新しい最大値に合わせて総和を再尺度化する。これにより系列長に依存しないO(1)の作業メモリで注意出力を計算できる。すべてのクエリを順に処理する自己注意では、理論上O(log n)の追加メモリに抑えられる。

ただしGPU/TPUで完全な逐次処理をすると並列性が失われる。そこでクエリとキー・値をチャンクに分け、チャンクごとの部分集約を結合する実用実装を示す。系列長に対する作業メモリはO(√n)となり、計算量は従来どおりO(n²)のままである。単一TPUv3で系列長16,384を評価した結果、標準実装に比べ注意演算の**追加メモリが推論で59分の1、微分で32分の1**になった。これは入力・出力やモデル重みを含む総メモリの削減率ではなく、注意演算の中間メモリに関する値である。

## 問題設定：注意行列を保存する必要はあるか

あるクエリqとn個の鍵k、値vに対する注意は、各スコア`s_i=q·k_i`を指数化し、`Σ exp(s_i)`で割った重みを値へ掛けて足し合わせる演算である。普通の実装はすべてのスコアを一度保存するため、単一クエリでO(n)、全nクエリの自己注意でO(n²)の中間メモリが必要になる。しかし最終出力は、各スコアの指数和と値の重み付き和の比だけで決まる。全スコア列そのものを保存する必要はない。

論文はこの観察を「正確な自己注意には二次メモリが不可欠」という主張への反例として示す。計算するスコアの組み合わせは依然n²個あるため、二次の演算量は解消されない。節約するのは中間行列の実体化に使う装置メモリであり、長系列でメモリ不足が先に起きるアクセラレータに向いている。疎注意のように遠いトークンを省略したり、線形注意のように別のカーネルへ近似したりしない点が重要である。

数学的な出力が同じでも、浮動小数点の加算順序を変えると丸め誤差は発生する。特にソフトマックスの指数は大きいスコアでオーバーフローしやすい。実用上は単に指数和を足すだけでなく、数値安定性を保つ更新式が必要となる。論文はそのための最大値追跡を明示している。

## 手法

### 1. 単一クエリのオンライン集約

クエリqに対して、鍵・値を順番に読み、スコア`s_i=q·k_i`を計算する。値の重み付き和をベクトル`v*`、指数重みの総和をスカラー`s*`として、各キー・値の処理ごとに`v*+=v_i exp(s_i)`、`s*+=exp(s_i)`と更新する。すべての鍵を処理したら`v*/s*`が注意出力になる。スコア列を保持する代わりに、値次元のベクトルと少数のスカラーだけを保持すればよい。

この計算は分配法則に基づく式の組み替えであり、数学的には標準ソフトマックスと同じである。入力としてクエリを先に読み、続いて鍵・値の対を順番に受け取れるとき、系列長に関する作業メモリはO(1)となる。入力順序の索引を追加で保持する場合にはO(log n)の記録が必要となる。出力テンソルそのもののメモリはこの追加メモリの計算から除外している。

### 2. 数値安定な最大値追跡

前述の単純な指数和は、スコアが大きいと指数が無限大となる。そこで処理済みスコアの最大値`m*`を追加し、常に最大値を引いた指数で和を保持する。新しいスコア`s_i`が来たら`m_i=max(m*,s_i)`とし、過去の重み付き和を`exp(m*−m_i)`倍、新しい値の寄与を`exp(s_i−m_i)`倍して加える。指数和にも同じ再尺度化を適用し、最大値を`m_i`へ更新する。

これにより後から大きいスコアが現れても、過去の集約を新しい基準へ変換できる。スコア全体を見てから最大値を引く標準実装と同じ数学的比率を保ちながら、途中のスコアを保存しない。最大値・指数和・値の重み付き和の三つが更新状態となり、系列長に依存しない。正確な注意をメモリ効率よく計算するための中核機構である。

### 3. 全クエリへの拡張と理論上のメモリ量

自己注意では各位置のクエリに対して同じ計算を繰り返す。クエリをひとつずつ処理すれば、現在のクエリの集約状態と、次に処理するクエリの索引だけを持てばよい。索引の記録にO(log n)ビットを使うため、全体の追加作業メモリはO(log n)と整理できる。結果のn個の出力ベクトルは別途必要であり、O(n)の出力保存領域まで不要になるという主張ではない。

ただし全クエリを逐次処理するとアクセラレータの並列演算器を活用できない。理論上の最小メモリをそのまま実機で使うと、メモリは減っても時間が大幅に増える可能性がある。論文はこのトレードオフを認め、次のチャンク化を実用実装として提案する。

### 4. TPU向けチャンク化と部分統計の結合

実用実装では、まずクエリを固定長のチャンクへ分ける。各クエリチャンクに対し、鍵・値もチャンクへ分割して部分的な注意を計算する。各鍵チャンクからは、最大スコア、指数和、値の重み付き和という三つの部分統計を出力する。最後に全チャンクの最大値を求め、各部分統計をその最大値へ再尺度化して足し合わせ、注意出力を得る。

鍵チャンク長をおおむね√nとすれば、必要な部分統計の数も√n程度となるため、追加メモリはO(√n)で済む。クエリチャンクを順に処理し、完成した出力を出力テンソルへ直接書き込めば、クエリチャンク間で大きい中間行列を保持する必要がない。チャンク内では行列積をまとめて実行できるため、完全な逐次処理よりGPU/TPUの並列性を活用できる。

論文のJAX実装はクエリチャンクと鍵チャンクのサイズを引数で指定でき、TPUで実用的な初期値を選んでいる。チャンクを小さくすれば中間メモリは減るが、カーネル起動や行列積の効率が落ちる。大きくすれば演算効率は良くなるが、部分的なスコア行列が大きくなる。最適な値はハードウェアと系列長に依存する。

### 5. 微分と再計算

学習時の逆伝播では、標準実装が順伝播中に保存した注意重みや中間スコアを再利用する。省メモリ実装はこれらを保持しないため、必要な箇所でチャンク内の計算を再実行する。JAXのチェックポイント機構を利用して、保存する中間値と再計算する演算を分離する。これにより微分のメモリ使用量を削減できるが、再計算に伴う追加演算時間を払う。

重要なのは、微分の数学的対象も元の注意式と同じであることだ。注意を近似することで勾配を変えるのではなく、同じ式を別の計算順序と再計算で実装する。したがって品質面の違いは主に浮動小数点の丸めや学習の非決定性によるものであり、注意機構を別物へ変更したわけではない。

### メモリ・時間の代表結果

| 条件 | 標準注意 | 省メモリ注意 | 結果 |
|---|---|---|---|
| 系列長16,384、推論 | 注意追加メモリ約1GB | 約17MB | 約59分の1 |
| 系列長16,384、微分 | 注意追加メモリ約2GB | 約64MB | 約32分の1 |
| 系列長4,096、推論 | 64MB | 16MB | 4分の1 |
| 系列長65,536、推論 | メモリ不足 | 21MB | 標準実装が動かない長さも処理 |
| 系列長1,048,576、推論 | メモリ不足 | 256MB | 約100万トークンでも注意演算自体は実行可能 |
| 系列長16,384、推論時間 | 標準実装を基準 | 11.3ms、約13%遅い | メモリ節約と実行時間の交換条件 |

59倍・32倍は注意演算の**追加メモリ**を比較した値であり、入力・出力・重みの容量を含めたアプリケーション全体が同じ倍率で小さくなるわけではない。系列長100万では、注意スコアの組み合わせが約1兆になるため、メモリ上は実行できても計算時間は45秒程度かかる条件が示される。時間計算量O(n²)は残ることを具体的に表す結果である。

推論時間は短い系列では標準実装とほぼ同程度で、系列長4,096では約8%、16,384では約13%遅いという測定である。測定は単一TPUv3上の注意演算単体であり、Transformer全体の一トークン生成時間へそのまま外挿できない。論文は系列長16,384で標準実装との差の最大絶対値が約1.8×10⁻⁷だったことも報告し、計算順序を変えても数値的に近い結果が得られることを確認している。

### 微分と翻訳品質

微分では、系列長16,384の注意追加メモリが2GBから64MBへ減る。逆伝播で中間値を再計算するため、推論より時間費用が大きい。論文の時間表は、微分の性能が系列長に応じて変化し、長い系列ではメモリ削減の利得と引き換えに再計算費が増えることを示す。標準方式がメモリ不足で停止する系列長では、単純な実行時間倍率だけでは比較できない。

WMT英独翻訳の小型Transformerを100,000ステップ学習した実験では、提案方式と標準注意の評価指標はほぼ同じだった。これは、同じソフトマックス注意を計算しながらメモリ配置を変えたことと整合する。論文は学習速度についても、注意演算単体での差とモデル全体の訓練速度が一致するとは限らないと注意している。

## 既存研究との差

疎注意は注意するトークンの範囲を制限し、線形注意は注意式自体を別の特徴写像へ置き換える。これらは時間計算量の削減も狙うが、元の完全ソフトマックス注意から演算内容が変わる。本論文は注意式を維持したまま、最大値・指数和・重み付き和のオンライン集約とチャンク化によって、二次の中間行列を物理的に保存しない。演算量は変わらず、メモリ階層の利用法を変える研究である。

後の入出力認識型注意カーネル（FlashAttention等）と共通する考え方は、巨大な注意行列を高帯域メモリへ実体化しない点にある。ただし本論文の実装はJAX/FlaxとTPUv3を対象とし、後年の融合GPUカーネルと同じタイル設計・性能を報告したものではない。先行する遅延ソフトマックスの再発見にも言及しつつ、メモリ計算量の整理、数値安定化、実用チャンク化、微分の検証を統合したことが貢献である。

## 限界

時間計算量は依然O(n²)なので、極端な長系列では計算時間が律速となる。理論上のO(log n)追加メモリを実機でそのまま使うと並列性が低く、実用実装はO(√n)へメモリを増やす折衷を選ぶ。クエリ・鍵チャンク長の最適値はTPUやGPUの特性で変わり、異なるアクセラレータで同じ速度・メモリ倍率になるとは限らない。

学習時には逆伝播で中間値を再計算するため、メモリ削減と計算時間の交換条件がある。論文の59倍・32倍は注意演算単体の追加メモリであり、モデル重み、KVキャッシュ、出力テンソルなどを含む総メモリではない。逐次生成における長期KVキャッシュを圧縮する研究でもなく、主に入力系列の密な注意計算で二次の中間行列を避ける研究である。
