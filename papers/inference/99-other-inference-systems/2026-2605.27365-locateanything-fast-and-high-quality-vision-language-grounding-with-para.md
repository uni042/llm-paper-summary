# LocateAnything：位置座標を一箱ずつ並列生成する視覚言語モデル

## 概要

物体検出や視覚的指示理解に用いる視覚言語モデル（Vision-Language Model; VLM）は、画像を読み、言語で指定された物体の位置を矩形の四座標 `(x1,y1,x2,y2)` として返せる。しかし通常の自己回帰復号では座標を数値文字列または離散座標トークンへ変換し、一つずつ生成する。四座標が同じ矩形を構成するという強い関係があるにもかかわらず、個々の座標は別々の復号ステップに分断される。多数の物体を列挙すると、物体数と座標トークン数に応じて逐次生成が長くなり、視覚理解の計算ではなく出力形式の生成が律速となる。

LocateAnythingは、矩形全体を一つの構造化単位として扱う箱単位並列復号（Parallel Box Decoding; PBD）を導入する。各矩形を、四つの量子化座標と構造トークンからなる長さ6のブロックで表し、ブロック内部は同時に予測する。一方で、異なるブロック間は因果順序を保ち、先に出力した物体を後続の予測が参照できる。さらに書式異常や位置の曖昧さを検知したブロックだけを通常の逐次復号でやり直すハイブリッド方式を備える。

主要な実機評価は、NVIDIA H100を1基、バッチサイズ1、BF16精度で実施した。COCO上の箱生成速度はハイブリッド方式で12.7箱/秒、Rex-Omni-3Bで5.0箱/秒、Qwen3-VL-4Bで1.1箱/秒である。ただし、これは生成された矩形数に対する復号処理能力であり、サービス全体の要求処理能力や同時接続時の応答時間ではない。位置推定精度では、LVISの平均F1が50.7でRex-Omni-3Bの46.9を上回る。モデル固有の復号機構と、約1億3800万件規模の学習クエリから得る精度向上は分けて解釈する必要がある。

## 問題設定と従来方式

通常の次トークン予測（Next-Token Prediction; NTP）は、前に生成したトークンを次の入力へ加え、言語モデルを順次実行する。座標を文字列で書く方式では数値の桁数まで生成回数に影響し、離散座標方式でも `x1→y1→x2→y2` の順に依存が残る。矩形の左右・上下の関係は本来同時に決まる幾何制約だが、逐次生成はそれを四つの独立した予測機会へ分散する。結果として座標同士の整合が崩れ、混雑した画像では隣接物体の境界を取り違えやすい。

複数トークン予測（Multi-Token Prediction; MTP）なら一度に数トークンを出せるが、単純な固定長分割では、あるブロックに前の物体の末尾座標と次の物体の種別が混在することがある。この境界越えは、学習すべき幾何的な相関とは無関係な組合せを増やし、速さを得ても位置精度を損なう。論文の比較対象であるSDLMやBlock Diffusion型の汎用ブロック方式に対して、PBDは**ブロック境界を矩形・点という意味単位に一致させる**ことを設計の中心に置く。

対象は画像上の一般物体検出、自然言語による参照対象特定、画面操作対象の位置推定、文書レイアウトと文字領域の位置特定などである。論文の速度指標である箱毎秒（Boxes Per Second; BPS）は単位時間に出力できる矩形数を測る。位置のF1は適合率と再現率の調和平均で、矩形同士の重なり率（Intersection over Union; IoU）が所定閾値を超えたものを正解とする。IoU=0.95は0.5より厳密な境界一致を要求するため、同じF1でも高閾値の改善は座標精度の改善を示す。

## 手法

### 1. 画像・言語入力から構造化ブロックへ

基盤モデルはMoon-ViT画像符号化器とQwen2.5言語復号器を多層パーセプトロンの投影器で接続する。画像 `I` から元解像度に対応する視覚トークン `Z=Encoder(I)` を作り、テキストの問い合わせ `E` とともに言語復号器へ渡す。予測対象は通常の文字列ではなく、`B=(b1,...,bN)` という箱単位の系列である。系列全体では `P(B|Z,E)=∏P(bi|b<i,Z,E)` として先行ブロックに条件付ける。

連続座標は0〜1000へ正規化して離散トークンへ写す。長さ `L=6` のブロックには四座標と `<box>`・`</box>` などの構造要素を収める。四つのブロック種別は、物体の言語的名称を表す意味ブロック、四座標を表す箱ブロック、対象不在を示す否定ブロック、生成終了を示す終了ブロックである。長さが足りない名称は複数の意味ブロックへ分割し、未使用位置は `<null>` で埋める。この一定長化により、同一ブロック内の位置を同じモデル実行で扱える。

### 2. 逐次系列と並列系列を同時に学習する

学習時は画像入力 `x_vis`、質問 `x_q`、通常の逐次正解列 `x_ntp`、箱単位に整列した並列列 `x_blk` を連結する。並列列では、各ブロックの先頭トークンを文脈として残し、それ以外をマスク記号へ置換して一度に復元させる。逐次系列と並列系列は同じ正解を異なる分解で表すため、言語的な因果予測を維持しつつ、矩形内の相関を同時に学習できる。損失は `L=L_ntp+L_mtp` である。

注意マスクには三つの異なる規則がある。画像・質問・逐次系列には通常の因果注意を適用し、並列系列から未来の逐次系列を覗けないようにする。並列系列のブロック間にも因果順序を課し、過去の確定済み矩形を後続の矩形が参照できるようにする。一方、**同じブロック内だけは双方向注意**を許し、四座標を同時に整合させる。逐次系列と並列系列を不適切に相互参照させないことが、教師信号の漏洩を避ける鍵になる。ブロックサイズ1にすると通常の逐次予測に帰着する。

### 3. 高速・低速・ハイブリッドの切替

低速方式（Slow）は座標を逐次予測して複雑な配置でも安定性を優先する。高速方式（Fast）は各ブロックを同時予測して矩形の生成速度を最大化する。ただし、異なるカテゴリの境界付近で `<box>` と座標が混在する書式異常や、碁盤目状の密集物体で隣接候補の中間位置を選ぶ空間的曖昧さが発生する。

ハイブリッド方式（Hybrid）は原則として高速方式を実行し、二種類の危険信号を検出したブロックだけ破棄して最後の正常な接頭辞へ戻る。書式が不正な場合は直ちにやり直す。位置が曖昧な場合は、座標トークンの最上位確率が0.7未満、**かつ**上位5候補の最大・最小座標差が正規化空間で80を超える、という二条件を同時に満たすと切り替える。そのブロックのみ逐次復号で確定した後、次のブロックから高速方式へ復帰する。全面的に低速化せず、危険箇所のみに費用を払う設計である。

推論時の注意マスクも、確定済みブロック間の因果性と現ブロック内の双方向性を維持する。各並列ステップ後、鍵値キャッシュ（KV cache）は**実際に確定したトークンだけ**を保持するよう切り詰め、マスク用トークンと重複した起点トークンを破棄する。これを怠ると、次のステップが学習時に想定していない擬似履歴へ注意してしまう。速度利得にはブロック同時予測だけでなく、この履歴整合性の維持も必要である。

### 4. 大規模位置教師データと学習基盤

LocateAnything-Dataは、画像約1200万枚、言語問い合わせ約1億3800万件、矩形注釈約7億8500万件を主な規模として報告する。一般物体検出、GUI、自然言語参照、OCR、レイアウト、点位置推定の六領域を含み、密集した多数の物体や否定例も扱う。学習は基礎的な視覚言語知識を先に獲得する二段階と、位置推定を重点的に学習する二段階の合計四段階で進める。最終段階は一般データの比率を20%へ減らし、MOT20DetやSKU110Kなど物体数の多い画像を重視する。

学習時の逐次・並列の二系列化は可変長を増やすため、実装では最大長予算へ複数標本を詰めるストリーム充填を用いる。32標本の待機バッファから残り長に最もよく収まる標本を選び、論文は95%超の充填効率を報告する。標本境界は `sub_sample_lengths` で保持し、異なる標本同士に注意が漏れないようMagiAttentionの不均一注意マスクへ渡す。これは**学習側の資源利用最適化**であり、後述のH100で測定した箱生成速度の改善率そのものとは区別する。

## 評価結果と解釈

### 最終モデルの検出精度と箱生成速度

| 評価条件・指標 | 比較対象 | LocateAnything-3B | 解釈 |
|---|---:|---:|---|
| H100・batch 1・COCO、BPS | Rex-Omni-3B 5.0 | Hybrid 12.7 | 同程度の3B規模で約2.54倍の箱生成速度 |
| H100・batch 1・COCO、BPS | Qwen3-VL-4B 1.1 | Hybrid 12.7 | 約11.5倍。ただしモデル構造・学習データも異なる |
| LVIS、IoU閾値平均F1 | Rex-Omni-3B 46.9 | 50.7 | +3.8ポイント |
| LVIS、IoU=0.95 F1 | Rex-Omni-3B 20.7 | 31.1 | +10.4ポイント。高精度な境界一致で改善が大きい |
| COCO、閾値平均F1 | Rex-Omni-3B 52.9 | 54.7 | +1.8ポイント |
| Dense200、閾値平均F1（本文表2） | Rex-Omni-3B 58.3 | 58.7 | +0.4ポイント。大幅改善とは言えない |
| VisDrone、閾値平均F1（本文表2） | Rex-Omni-3B 35.8 | 39.9 | +4.1ポイント |
| ScreenSpot-Pro、平均正答率 | GUI-Owl-32B 58.0 | 60.3 | +2.3ポイント。比較対象は異なるモデル規模 |
| DocLayNet、閾値平均F1（本文表4） | Rex-Omni-3B 70.7 | 76.8 | +6.1ポイント |
| M6Doc、閾値平均F1（本文表4） | Rex-Omni-3B 55.6 | 70.1 | +14.5ポイント |
| HumanRef、閾値平均F1 | Rex-Omni-3B 79.9 | 78.7 | -1.2ポイント。全課題で優位ではない |

高閾値のIoUでLVISの差が大きいことは、単に物体の有無を当てるだけでなく、矩形境界を正確に出す能力に改善があることを支持する。一方、Dense200の本文表2では差は小さく、HumanRefでは比較対象より悪い。論文の「多様な課題で優れる」という総括を全指標の一律改善として読まない。

### 復号方式そのものを切り分けるCOCO実験

最終モデルは大規模な追加データで学習されているため、他モデルとの精度差をPBDだけの効果とは断定できない。論文はCOCOだけで学習した構成要素除去実験を別途設け、座標表現、並列化方法、逐次・並列損失の寄与を分けている。

| COCOのみの統制実験 | BPS | 平均F1 | 読み取り |
|---|---:|---:|---|
| 数字文字列を逐次生成 | 1.3 | 49.1 | 桁数も逐次復号するため低速 |
| 量子化座標を逐次生成 | 3.9 | 50.1 | 文字列より速いが四座標の逐次依存は残る |
| PBDのSlow | 3.9 | 52.1 | 同じBPSでも構造化教師によりF1が改善 |
| PBDのFast | 16.9 | 49.6 | 最大速度を得るが誤りも増える |
| PBDのHybrid | 13.2 | 51.6 | 低速方式に近いF1を維持しつつ高速 |
| 汎用SDLM・ブロック長6 | 5.5 | 46.1 | 箱境界を無視したブロック化の不利を示す |
| 汎用Block Diffusion・ブロック長6 | 4.7 | 44.8 | 同様に構造化が重要 |

同じCOCO実験で、逐次損失だけの学習ではSlowのF1が50.1、並列損失だけではFastのF1が47.2だった。両損失を併用するとSlow 52.1、Fast 49.6、Hybrid 51.6へ改善する。したがって速度向上は「並列トークンを出す」だけでは成立せず、ブロック境界に意味を持たせ、逐次復号を共同学習し、危険なブロックを再実行する設計の組合せに依存する。図7の物体数20〜300の感度分析では、逐次方式の生成時間が増える一方、並列方式は増加が小さく、箱生成速度は約12から約25 BPSへ増えたと報告する。ただし箱数増加に対する全システムの応答時間が不変であるとは述べていない。

### 異なる基盤モデルへの適用

COCOのみで学習したQwen3-VL-4Bへの適用実験では、通常逐次復号がF1=50.8、2.8 BPS、PBDのHybridがF1=52.0、9.4 BPSだった。PBDのFastは11.4 BPSだがF1=49.6へ下がり、Slowは2.8 BPS、F1=52.2である。この結果はPBDがMoon-ViT＋Qwen2.5の特定構成にしか適用できないわけではないことを示す一方、モデル変換だけでどの視覚言語モデルにも同等の利得が得られると保証するものではない。

### 精度と速度の交換条件、追加評価

最終モデルの付録表12では、Fast / Hybrid / SlowのBPSはそれぞれ15.3 / 12.7 / 4.3と報告される。COCOの閾値平均F1は52.2 / 54.7 / 55.1、LVISでは47.0 / 50.7 / 52.6である。速度最優先のFastと、精度最優先のSlowの間で、Hybridが局所再実行により折衷点を提供する。OCRのSROIEではFast 38.8、Hybrid 39.3に対しSlow 64.4であり、**ハイブリッドでも逐次方式との品質差が大きく残る領域**がある。HierTextでもHybrid 29.1に対しSlow 43.2である。GUIのScreenSpot-Proでは59.7 / 60.3 / 60.5と差が小さい。用途によって再実行規則の閾値を調整する余地があるが、閾値の全探索や最悪遅延の保証は示されない。

点位置推定の追加実験では、COCOのF1@Pointが83.9、Dense200が87.6、RefCOCOg testが91.0だった。矩形以外の幾何単位にも構造化復号が適用できることを示す。ただし、点の正解判定は予測点が正解領域内にあるかであり、IoUに基づく矩形F1と同じ尺度ではない。

## 既存研究との差

Qwen3-VLのような汎用視覚言語モデルは座標を自然言語に近い系列で生成し、Rex-Omniは離散座標の生成により文字列生成より高速化する。LocateAnythingはこれらの「何を出すか」に加え、「四座標を何回のモデル実行で出すか」を変える。単なる投機的復号（Speculative Decoding）のように別の草稿モデルが先に候補を生成して対象モデルが検証する方式ではなく、学習時から矩形単位の同時予測をモデルへ組み込む。SDLMや一般的なブロック拡散方式と異なり、並列化する単位を任意の固定長テキスト片ではなく物体位置の構造に一致させる。

また、WeDetectのように検出を並列検索問題へ変換する方式とは異なり、物体名称・位置・不在・終了を含む生成系列を維持するため、自然言語の問い合わせに柔軟に応じられる。一方で、この設計は一般的な文章生成の高速化を直接証明するものではなく、座標や点のような強い内部構造を持つ出力に適合した手法と理解すべきである。

## 限界・実装状況・監査上の注意

1. **評価負荷の範囲**：速度は単一H100、バッチ1、COCO上の箱生成で測定した。複数GPUのサービング、連続バッチ、同時リクエスト、GPUメモリ容量制約下での処理能力や電力効率は評価されていない。箱毎秒から直接、端末内での応答時間や要求毎秒を推定できない。
2. **学習と復号の寄与**：最終モデルは1億件超の追加データを使用し、他モデルとの比較は同一学習条件ではない。COCO限定の構成要素除去実験がPBD自体の寄与を補足する。最終モデルの性能差すべてをPBDだけに帰属させない。
3. **失敗時の挙動**：書式異常と空間的曖昧さを検出すると逐次復号へ戻るため、難しい場面が多いほど高速方式の利得は減る。論文も密集物体・カテゴリ境界の問題を認め、強化学習による切替改善を将来課題とする。特にSROIEとHierTextではHybridがSlowの精度に届かない。
4. **注意マスクとKV管理の実装負担**：ブロック内双方向・ブロック間因果の不均一マスク、確定済みトークンのみを保持するKVキャッシュ切詰めが必要。一般的な逐次復号ランタイムへ重みだけ置けば同じ速度が得られるとは限らない。
5. **一次論文内の表の不整合**：Dense200のHybrid平均F1は本文表2が58.7、付録表12が61.3であり、VisDroneも本文表2の39.9に対し付録表12は39.8。DocLayNetは本文表4が76.8、付録表12が77.7、M6Docは70.1対70.5である。異なる評価手順か転記差かを本文から確定できないため、表番号と数値を混ぜず記録した。また、データ総数は本文に「約138M queries」、付録表10には六領域合計で約139.56M queriesと記され、集計対象が完全には一致しない。未説明の差を推測で補わない。
6. **実装公開状況**：一次論文のリンク先としてNVlabs/Eagleリポジトリ内のEmbodiedディレクトリが示される。実際にどのチェックポイント・実行スクリプト・学習データが再現可能な形で配布されているかは、この読解では実機動作確認していない。公開リンクの存在と実験の再現成功は区別する。
