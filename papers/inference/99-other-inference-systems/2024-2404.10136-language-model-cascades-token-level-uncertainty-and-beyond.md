# Language Model Cascades：トークン単位の不確実性を用いたモデル委譲判断

## 概要

本論文は、入力ごとに必要な推論計算量を変える「モデル段階実行」（model cascade）の委譲規則を、生成言語モデルに合わせて設計する研究である。小型モデルで処理できる入力はそこで完了し、難しい入力だけ大型モデルを追加実行する。全入力を大型モデルへ直接送る方式に比べて平均計算費用を下げられる可能性があるが、委譲すべき入力の選択を誤ると回答品質が低下する。

分類問題では、最も高い予測クラスの確率が低ければ大型モデルへ委譲するという規則が自然である。しかし生成問題では出力が複数トークンで、長さも入力ごとに異なる。出力系列の確率を単純に掛け合わせると長い回答ほど小さい値になり、長さで正規化すると逆に短い回答を委譲しやすくなる。著者らは各トークンの確率分布から複数の分位点（quantile）を取り、事後学習した判定器へ渡す方式を提案する。

FLAN-T5 BaseからFLAN-T5 Largeへ委譲する実験では、分類、質問応答、翻訳などで、単純な確信度総和・平均より良い品質と委譲率の交換条件を得た。例えばMNLIの委譲曲線下面積は総和方式0.627、分位点事後学習0.711、さらに大型モデルの初期中間表現を利用した方式0.722であった。一方、分位点の固定値がどの課題でも最良とは限らず、中間表現の取得には大型モデルの部分計算という追加費用がある。

## 問題設定：なぜ生成では委譲判断が難しいか

二段階の推論では、まず小型モデルが入力xに対して予測を生成する。判定器r(x)が0なら小型モデルの出力を採用し、1なら大型モデルも実行してその出力へ切り替える。小型モデルの費用をc1、大型モデルの費用をc2、委譲率をDとすると、平均費用は概念的にc1 + D×c2となる。大型モデルへ委譲した要求も小型モデルを先に実行済みなので、費用をc2だけと見積もってはいけない。

この費用式から、委譲率が低いほど計算を節約できるが、難しい要求を小型モデルのまま確定させると品質が悪化するという関係が生じる。最適化の目的は、所定の平均費用予算を守りながら期待回答品質を高めることである。実際には小型モデルの出力からスコアを計算し、閾値を動かして委譲率を制御する。

単一クラスを返す分類器なら予測確率の最大値が簡便な確信度となる。生成モデルは、時刻tごとに「直前までに生成したトークンを条件とする次トークン確率」を持つ。回答中の冠詞・句読点などの確率は高くても、固有名詞や数値の一部だけ低いことがある。出力全体の確率を一つに集約すると、この局所的な難しさを見落とす。

また、出力長が変動すると確率の集約値自体が長さに依存する。対数確率の総和は各トークンで非正の値を足すため、長い回答ほど値が低くなりやすい。平均は長さの単純な効果を取り除くが、短い回答で確率の低い重要語が占める比率を過大評価する場合がある。したがって、総和と平均のどちらか一つに置き換えるだけでは十分でない。

## 手法

### 系列確率の総和と平均という基準方式

著者らはまず、Chow-Sumと呼ぶ出力系列の対数確率総和を基準とする。小型モデルが生成したトークン列の各トークン対数確率を足し、値が低い要求を大型モデルへ委譲する。これは分類器の「予測クラス確率が低いときに棄却する」という考えを、生成文の確率へ直接拡張した方式である。

次の基準はChow-Averageで、各トークンの対数確率を出力トークン数で割る。長い出力ほど対数確率総和が小さくなる偏りを補正するが、論文の翻訳例では短い出力を過剰に委譲する傾向が現れた。長い出力が反復や未知語のため実際に低品質なこともあるため、長さを完全に無視するのも適切ではない。

### トークン確率の分位点による局所的な不確実性

Chow-Quantileは、小型モデルが出力した各トークンに割り当てた確率を集め、その分位点を一つの確信度スコアとする。0分位点なら最も確率の低いトークンを重視し、0.8分位点なら確率分布の上側の位置を使う。これにより、総和や平均では埋もれる「一部の重要なトークンだけ不確実」という状態を検出できる。

例えば翻訳文に未知語の代替表記や不自然な反復が現れる場合、最小トークン確率を使う規則はその箇所を検知しやすい。逆に高い分位点を用いる規則は短い出力の不確実性を相対的に強く拾う場合がある。論文はWMT翻訳でこれらの振る舞いを確認したが、どの分位点が最良かは課題によって変わった。固定分位点を普遍的な委譲規則とみなさないことが次の設計につながる。

### 分位点特徴量を使う事後学習判定器

Post-Hoc-Quantileは、複数分位点を固定長の特徴ベクトルへまとめ、さらにChow-SumとChow-Averageも加えて、小さな順伝播ネットワークで委譲スコアを学習する。論文は5層の多層パーセプトロンを使用する。入力は小型モデルが既に出力した確率列の統計量で、出力は閾値と比較する連続スコアである。

学習用ラベルは課題ごとに異なる。正誤判定できる分類・質問応答では、「大型モデルは正解するが小型モデルは誤答する」入力を委譲すべき例とし、二値ロジスティック損失で学習する。翻訳では大型モデルと小型モデルのBLEURTスコア差を目標値とし、二乗誤差で学習する。ここで大型モデルの結果は学習時の教師情報として使う。推論時に大型モデルを毎回完全実行してから委譲を決めるわけではない。

分位点を特徴量へ変換することで、出力長が異なる場合も同じ次元の入力を判定器へ渡せる。確率列を単にゼロ埋めして与える方式は付録の一部条件で劣るため、分位点の集約は可変長を扱う上で意味を持つ。ただし学習した委譲器は評価課題の分布に依存し、新しい課題へ無調整で転用できるとは示されていない。

### 中間埋込みを用いる追加情報と実行費用

Post-Hoc-Embed-1は、小型モデルの最終デコーダ層のトークン埋込みを平均した特徴を判定器へ追加する。Post-Hoc-Embed-1+2は、さらに大型モデルの第1デコーダ層における最初のトークンの中間埋込みを使う。大型モデルの深い層まで計算しなくても、浅い層の表現が入力の難しさを見分ける情報を含むかを調べる設計である。

ただし後者は、委譲を決める前に大型モデルの初期層を実行する必要がある。したがって、単純なc1 + D×c2という費用式には、中間埋込みを取得する追加費用を加えなければならない。論文もこの費用が無視できないと注意しており、品質曲線が改善しただけで運用コストが同じ割合で下がるわけではない。分類のように短い回答では最初のトークンの表現が有用だが、長文翻訳では重要語が後半に現れるため利得が小さくなる可能性がある。

### 一つの要求の処理順

要求を受けると、小型FLAN-T5が出力を生成し、各生成トークンの確率を記録する。確率列から総和・平均・複数分位点を求め、必要に応じて小型モデルの埋込みや大型モデルの初期中間表現を加える。事後学習した判定器がスコアを計算し、設定した閾値を下回れば大型モデルへ委譲する。そうでなければ小型モデルの回答を返す。閾値を変えることで大型モデルへ送る要求割合と期待品質の曲線を得る。

## 評価条件

| 観点 | 論文で用いた条件 | 結果を読む上での意味 |
|---|---|---|
| 主なモデル | FLAN-T5 Base→FLAN-T5 Largeの二段階 | 指示調整済みエンコーダ・デコーダモデル。デコーダ専用LLMではない |
| 推論方法 | 少数例プロンプト、貪欲復号 | 温度サンプリングを含む全ての生成設定へ直ちに一般化しない |
| 課題 | MNLI、ANLI、TriviaQA、SQuAD、TyDiQA、WMT翻訳、BoolQ、IMDb、Winogrande等 | 分類・質問応答・読解・翻訳で出力長と品質尺度が異なる |
| 比較規則 | Chow-Sum、Chow-Average、分位点0/0.4/0.8、事後学習、埋込み追加 | ルータの特徴量と学習の有無を比較 |
| 主指標 | 委譲率と品質の曲線下面積AUC-DF | 同じ課題では高いほど良いが、課題をまたぐ絶対値比較は不適切 |
| 評価回数 | 事後学習法は5回の無作為実行の平均 | 単一学習試行の偶然を減らす |
| 実コスト | 委譲率を主な代理変数として費用・品質を比較 | GPU時間、消費電力、サービング同時実行性能の実測とは区別 |

AUC-DFは、委譲スコアの閾値を動かして大型モデルへ送る要求の割合を変え、その各点の品質を結んだ曲線の下側面積である。固定した委譲率一つでの正答率ではなく、広い費用予算でどの程度良い要求を選べるかを要約する。値が高いほど望ましいが、MNLIとTriviaQAのように品質尺度が異なる課題のAUC値を直接比較して優劣を判断することはできない。

## 評価結果

### 代表的な委譲曲線下面積

| 課題 | 総和方式 | 分位点事後学習 | 大型モデル初期埋込み併用 | 読み方 |
|---|---:|---:|---:|---|
| MNLI | 0.627 | 0.711 | 0.722 | 事後学習で大幅改善し、追加埋込みでさらに改善 |
| TriviaQA | 0.073 | 0.097 | 0.100 | 総和方式は無作為委譲より悪く、学習規則で改善 |
| WMT DE→FR | 0.390 | 0.404 | 0.404 | 翻訳では埋込み追加の上積みが小さい |
| ANLI-R1 | 0.524 | 0.534 | 0.563 | 難しい推論を含む分類課題で埋込みが有用 |
| BoolQ | 0.838 | 0.840 | 0.854 | 分位点学習のみの差は小さい |
| SQuAD | 0.410 | 0.409 | 0.412 | 事後学習が総和を常に上回るわけではない |
| TyDiQA-SW | 0.170 | 0.163 | 0.162 | 一部の課題では総和方式の方が高いという負の結果 |

数値は原著表1のAUC-DFである。例えばMNLIでは、単純な系列確率総和より分位点事後学習の曲線下面積が0.084高い。これはMNLIの正答率が8.4ポイント増えたという意味ではない。TriviaQAでも総和方式の低いAUCを改善するが、全課題で一律の改善が保証されるわけではない。

著者らはWMT翻訳の長さ別分析も行い、総和方式が長い回答を過剰に委譲し、平均方式が短い回答へ偏りがちであることを示した。最小分位点は未知語の代替表記や反復を含む回答を検出しやすく、0.8分位点は短い回答の不確実性を拾いやすい。両者の長所が異なるため、単一分位点を固定するより複数分位点から判定器を学習する設計に意味がある。

### 学習した判定器と中間表現の比較

Post-Hoc-Quantileは多くの課題で、手動で選んだ分位点規則と同程度かそれ以上のAUC-DFを得た。しかし表1のSQuADでは総和0.410に対して学習方式0.409、TyDiQA-SWでは0.170に対して0.163と逆転する。したがって「全課題で学習方式が常に最良」と断定できない。大型モデル初期埋込みの併用はMNLIやANLIなどの短い出力の分類課題で特に効く一方、翻訳では改善幅が小さい場合がある。

原著付録は、可変長確率列をゼロ埋めして学習器へ直接入力する単純案が一部条件で不利なことも報告する。分位点を用いる方式は単に学習器のパラメータを増やすのではなく、入力長が変わっても比較可能な確信度情報へ整形するという役割を持つ。

### コスト評価で確認できる範囲

論文は委譲率を変えた際の品質曲線を中心に評価する。小型モデルを必ず先に実行し、委譲された要求だけ大型モデルを実行するという構造上、委譲率が小さければ大型モデル呼び出しを減らせる。しかしGPUメモリ消費、実測の秒単位レイテンシ、バッチ効率、同時リクエストのスループット、クラウド課金額を主要表で実証した研究ではない。

特に大型モデルの第1デコーダ層を委譲判定に使う方式は、委譲しない要求でも大型モデルの一部計算が必要である。AUC-DF改善を実コスト削減として解釈するには、この追加費用と判定器の実行費用を含む実機ベンチマークが別途必要となる。逆に分位点だけを使う方式では小型モデルの生成確率から特徴量を抽出するため、追加の大型モデル部分実行は不要である。

## 既存研究との差

FrugalGPT等の既存カスケードは入力プロンプトや生成結果から委譲を学習するが、本論文は生成中に得られる**トークン単位の確率列**を明示的な入力にする。単一のクラス確率を使う分類器向け棄却規則を、長さの異なる生成文へそのまま適用すると偏りが生じることを実験的に示し、分位点特徴量で補う。

また、最初から入力だけを見てモデルを選ぶルーティングとは異なり、小型モデルの回答とその確率を実際に観測してから大型モデルを呼ぶか判断する。入力のみの選択器は小型モデル実行費用を省ける場合があるが、今回の方式は小型モデルが実際に苦手としたトークンの情報を使える。どちらが総費用で優れるかはモデル速度と委譲率に依存し、論文のAUC-DFだけで結論できない。

## 限界と適用条件

第一に、主な実験対象はFLAN-T5というエンコーダ・デコーダ型モデルである。著者らはデコーダ専用モデルへの拡張を将来課題として挙げる。現在の大規模対話モデルで同じ分位点規則が同程度に有効か、モデル系列ごとの確率較正の差がどう影響するかは未確認である。

第二に、判定器の教師信号は大型モデルの正解・不正解、または翻訳品質差から作る。評価データや正解ラベルが少ない運用環境では、この教師信号を準備する費用と分布ずれが問題になる。課題ごとに最良の分位点が異なるという結果は、汎用の固定閾値が難しいことも示す。

第三に、出力トークン列を生成してから委譲する方式なので、長い出力ほど小型モデルで先に使った計算が無駄になる可能性がある。大型モデルへ委譲した場合、小型モデルの出力を再利用する投機的復号ではなく、追加で大型モデルの推論を実行する。したがって高い委譲率では小型モデルを先に実行する分だけ直接大型モデルへ送る方式より高コストになり得る。

第四に、中間埋込みを使う方法は大型モデルの一部を事前実行する必要があり、GPU配置やモデルロード費用、通信費用を考慮した運用が必要である。短い分類出力での効果を、長い翻訳・対話出力へそのまま外挿してはならない。

第五に、AUC-DFは品質と委譲率の代理指標である。実際の推論サービングではトークン長、バッチ形成、モデル切替、並列要求、キャッシュ共有によって費用が変化する。実装時には委譲率だけでなく実測TTFT、TPOT、GPU時間、追加モデル呼び出し費用を測り、期待品質との交換条件を再評価する必要がある。
