# DORA: A Scalable Asynchronous Reinforcement Learning System for Language Model Training

## 概要

DORAは、大規模言語モデル（Large Language Model; LLM）の強化学習（Reinforcement Learning; RL）による後学習を、生成する応答の長さが大きく偏る状況でも効率よく進めるシステムである。通常の同期方式では、一つの学習更新に必要な応答を全て生成し終えるまで学習器が待つ。数学やコードの長い推論軌跡は短い軌跡より桁違いに長く、しかも学習に有用な情報を含むため、単純に捨てることは学習データの偏りを生む。論文はこの対立を「長い裾のジレンマ」と位置付ける。

提案の核は、**一つの軌跡の生成中には方策の重みを変更しないまま、複数の方策世代を生成クラスタで共存させる**点にある。完成した軌跡を即座に学習器へ送り、長い軌跡は旧世代で継続する。さらに各世代への演算資源の割当を動的に変更し、同じ方策世代を実行する別インスタンスへ鍵・値キャッシュ（Key-Value Cache; KVキャッシュ）を移送することで、長文を再び入力処理する費用を避ける。

公開評価では64基のH800でロールアウトのみの時間を14.9分から1.8分へ短縮し、128基では同期方式比2.12倍の実効学習スループットを達成した。製品規模の約5000億パラメータの専門家混合（Mixture of Experts; MoE）モデルでも長い応答への利得が報告される。ただし、許容する方策世代差を大きくすると収束がやや遅くなるという明示的な制約がある。

## 問題設定

強化学習による後学習の反復は、現行方策からの応答生成、報酬・参照値などの経験準備、学習器による重み更新で構成される。著者らの対象ワークロードでは応答生成段階が反復時間の50〜80%を占める。応答の長さが偏ると、ある装置では短い要求を全て終えているのに同じ装置の長い要求を待ち、さらに速く終了した装置群も最も遅い装置群を待つ。論文は前者を装置内の遊休時間、後者を装置間の遊休時間として区別する。

この問題は出力長の99パーセンタイルが中央値の10倍を超える条件で深刻になる。単に要求を余分に生成して、所定件数に達した時点で残りを破棄する方式は、長い推論過程を学習から選択的に排除してしまう。一方、長い応答を途中で分割し、重み更新後の新しい方策で続きを生成する方式では、同じ軌跡が複数の方策の出力を連結したものになる。旧世代のKVキャッシュは新世代の重みと整合しないため、生成済みの全接頭部を再計算する必要が生じる。

DORAが同時に守る条件は、軌跡内の方策一貫性、採取した軌跡を捨てないデータ完全性、方策の陳腐化の上限である。非同期性だけを増してもこれらが破れると、装置稼働率が改善しても学習の目的関数や収束を変えてしまう。したがって待ち時間を減らす機構と、学習に渡すデータの意味を保つ機構を一体に設計する必要がある。

## 手法

### 1. 複数世代を共存させる軌跡単位の逐次学習

生成要求を配る管理器（RolloutManager）は、各入力に方策世代の識別子を付け、その世代の重みを保持するデータ並列群へ割り当てる。各データ並列群は一つの方策世代だけを実行し、一度開始した応答は終了まで同じ重みで生成する。完成した軌跡は非同期転送待ち行列（TransferQueue）に入り、学習器（Trainer）が必要件数を受け取ると、未完了の軌跡を待たずに経験準備と重み更新を開始する。旧世代で進行中の長い要求は中断も破棄もされず、後続の学習反復へまたがって完了する。

一反復で配る入力数を `RBS`、学習で消費する軌跡数を `TBS` とすると、`RBS > TBS` として生成要求を先行投入できる。通常の同期方式のように、全ての要求が一斉に終わる境界を作らないため、短い要求から得た学習材料が長い要求に足止めされない。軌跡の途中で方策を切り替えないため、応答の確率はその軌跡に付いた単一の行動方策で評価できる。これにより、途中切替方式に固有の軌跡内方策混合を回避する。

ただし非同期のまま旧世代を無制限に保持すると、学習器が古い方策の応答を使う危険が増える。そこで活動中の世代集合を大きさ `K` 以下の滑動窓として管理し、最も古い世代の軌跡が全て収集・転送されるまで窓を前へ進めない。論文の非同期学習条件は、学習側の方策世代 `v(θ)` と生成側の世代 `v(w_i)` の差 `v(θ)-v(w_i) ≤ K` で表される。`K` は効率と学習の新鮮さの交換条件を定める設定値である。

### 2. 方策世代間の動的資源編成

複数世代の共存だけでは、旧世代の残り要求が減るにつれて旧世代専用の装置が余り、新世代の要求が集中する問題が残る。中央の負荷分散編成器（Load-Balancing Orchestrator）は、世代別の活動要求数、KVキャッシュ占有、生成の進捗を監視し、各世代へ割り当てるデータ並列群の数を現在の仕事量に応じて組み直す。

再編成には三つの契機がある。学習反復の終了時には新しい方策世代の配置を促進する。KVキャッシュの圧力が閾値を超える場合には、強制追い出しと再計算を防ぐため再配置する。さらに周期的に旧世代へ取り残された要求を検査する。編成器は目標の群数を計算し、同一世代を保持するインスタンス間で進行中の要求を移し、空いた資源へ新しい方策の重みを装置間転送（Peer-to-Peer; P2P）で配布する。

再配置後には、最新世代へ優先的に追加要求を投入して古いデータの比率を抑え、その後で旧世代の空き枠も利用する。これにより、旧世代の長い応答を維持しながら装置群全体の利用率を高める。資源の再編成は要求の中断・廃棄ではなく、同じ方策を維持する移動である点が重要である。一方で再配置計画、重み転送、要求移動には費用が発生するため、頻繁な再編成が無償というわけではない。

### 3. 同一世代間のKVキャッシュ再利用

要求を別装置へ移すときに、従来のように生成済みの全文をもう一度事前入力処理（prefill）すると、長文やMoEで費用が大きい。DORAでは、軌跡の全トークンが同じ方策世代 `w` から生成されるため、同じ世代の重みを持つどのインスタンスでも、その軌跡のKVキャッシュの意味が等しい。この性質を利用し、再入力処理ではなく既存KVキャッシュを装置間転送して続きを生成する。

移動は制御情報と実データを分けて実施する。要求識別子、生成状態、出力済みトークン数、方策世代タグなどの小さな情報は遠隔手続き呼出し（Remote Procedure Call; RPC）で送る。大きなKVキャッシュ本体は高速な集合通信機構で転送する。可能なら要求を元の計算順位へ戻して局所性を保ち、物理的な転送自体を避ける。移動が不可避な場合だけキャッシュ転送を行う。

長い要求が集中して装置メモリを圧迫する際は、KVキャッシュを一時的にホストメモリへ退避し、後で再開できる状態を保持する。これは重みの異なる世代間でキャッシュを再利用できるという主張ではない。**再利用の成立条件は移動元と移動先が同じ方策世代を保持すること**であり、異なる世代間での再入力処理を一般的に不要にする方式ではない。

### 4. 学習器との整合と遅延の制御

生成側の行動方策と学習側の現在方策が異なる場合、軌跡単位で生成に用いた世代を識別し、その方策の確率を重要度比の分母に使う。論文は群相対方策最適化（Group Relative Policy Optimization; GRPO）を代表例として、各軌跡の行動方策を固定した非同期目的関数を記述する。これは複数世代を同時に走らせても学習データの確率的な意味を追跡するためである。

ただし、陳腐化の上限を設定したことは、どんな大きさの `K` でも同じ収束速度を保証するという意味ではない。古いデータの比率が増えるほど学習器の現在方策とのずれが増し、重要度比の切り詰めにも依存する。DORAの実装は固定の `K` と既存の方策最適化手法を前提にするため、適応的な遅延補正は今後の課題である。

## 評価条件

一次論文は、公開可能な実験として8基のH800を搭載する16ノード、合計128基のクラスタを使用し、64基と128基の構成を比較した。ノード内通信はNVLink、ノード間は高速ネットワークを用いる。密なモデルはQwen2.5-32B、学習データはDAPO-Math-17Kで、入力長上限2,000トークン、出力長上限30,000トークンとした。学習反復は入力512件に各16応答を生成する設定で、学習へ渡す応答数は8,192件である。報告値はウォームアップ後の5反復平均と明記されている。

推論側はvLLM 0.8.5、学習側はMegatron-LM、ソフトウェア環境はCUDA 12.4、PyTorch 2.6.0、NCCL 2.28を利用した。比較対象は同期方式、一反復だけ古い方策を使う非同期方式、生成を途中で分割する方式であり、著者らの同じ社内基盤へ実装して条件を揃えた。独立した公開実装同士をそのまま比較した値ではない。

| 評価軸 | 条件・指標 | 比較の読み方 |
|---|---|---|
| 公開クラスタ | H800を64基または128基、密な32Bモデル | 規模による効果の変化を検証 |
| 学習課題 | DAPO-Math-17K、出力上限30Kトークン | 長い裾を持つ数学推論の生成 |
| 速度 | ロールアウトだけの残存時間、反復時間 | 生成段階の改善と学習全体の改善を区別 |
| 実効処理量 | 学習に実際に消費されたトークン毎秒 | 破棄した応答を処理量へ水増ししない |
| 学習品質 | 72基、100反復での平均報酬 | 同期方式と陳腐化上限別の収束傾向を比較 |
| 部品の寄与 | KVキャッシュ転送あり・なし | 再入力処理回避の独立した寄与を確認 |

## 主要結果

### 生成段階と学習全体の改善

| 条件 | 指標 | 同期方式 | DORA | 主要な差 |
|---|---|---:|---:|---|
| H800×64 | ロールアウトのみの残存時間 | 14.9分 | 1.8分 | 8.2倍短縮 |
| H800×64 | 反復時間 | 基準 | 提案 | 1.56倍短縮 |
| H800×128 | ロールアウト時間 | 基準 | 提案 | 5.9倍短縮 |
| H800×128 | 反復時間 | 基準 | 提案 | 1.93倍短縮 |
| H800×64 | 実効学習スループット | 基準 | 23,327トークン/秒 | 同期方式比1.65倍、途中分割方式比1.17倍 |
| H800×128 | 実効学習スループット | 基準 | 34,135トークン/秒 | 同期方式比2.12倍、途中分割方式比1.11倍 |

64基では、同期方式の反復時間に占める「学習と重ねられない生成」の割合が65%だったのに対し、DORAでは12%に低下した。128基でも同割合は73%から24%へ減る。ただし、ロールアウトだけの高速化率と反復全体の高速化率は異なり、8.2倍という数字を学習全体へ転用してはならない。

128基での34,135トークン/秒は、生成した全トークンを無条件に足した値ではなく、学習で実際に消費した軌跡のトークンを基準にする。途中分割方式に対する改善幅は同期方式に対する改善幅より小さく、長い応答への待ちを取り除くだけではなく、途中分割方式の再入力処理を回避した差が表れている。

### 構成要素除去と追加費用

KVキャッシュ再利用を無効にすると、密な32Bモデルの平均ロールアウト時間は183秒であり、再利用を有効にすると約166秒となった。これは約9%の短縮で、複数世代の共存だけでは解決できない移動時の再入力処理費用を示す。資源再編成機構はシステムの動作に必須であるため、著者らは独立した除去実験を実施していない。この未実施項目を「寄与ゼロ」と誤読してはならない。

| 追加費用 | 64基 | 128基 | 解釈 |
|---|---:|---:|---|
| 負荷分散・再編成・重み転送 | 反復時間の0.4% | 1.5% | 規模拡大で増えるが主要利得より小さい |
| 要求移動・KVキャッシュ転送 | 3.6% | 2.1% | 大規模化で償却される条件を確認 |
| 不要キャッシュの解放 | 0.03%未満 | 0.03%未満 | 測定上は小さいが完全に無費用ではない |

製品環境では、長い応答が多いエージェント型の課題ほど利得が大きいと報告され、約500BのMoEモデルで最大6.2倍の生成段階高速化が示される。ただし、製品環境のアクセラレータと通信構成は公開H800クラスタと異なる。これらを同じ条件の性能曲線として結合することはできない。

## 品質への影響と負の結果

学習品質について、72基の構成で100反復の平均報酬を追跡した結果、陳腐化上限 `K=1` と `K=3` のDORAはいずれも同期方式に近い推移を示した。ただし `K=3` は `K=1` よりやや収束が遅い。したがって「精度への影響なし」という総括は、この実験条件で大きな劣化が観測されなかったという意味であり、任意の遅延幅やデータ分布で同じ収束を保証するものではない。

長い軌跡を切り捨てる方式と異なり、DORAは長い応答を後続反復へ送るため、長い軌跡を失うことによる標本の長さ偏りを避ける。ただし、最新世代の応答だけを学習に使う完全同期方式ではないので、古い行動方策のデータを用いること自体のずれは残る。このため方策世代の識別、重要度比、遅延窓の上限が必要である。

## 既存研究との差

同期方式は学習の整合性が分かりやすいが、長い軌跡の終了待ちで装置が遊ぶ。一反復遅れの非同期方式は生成と学習の重なりを作れるが、同じ生成段階内での長い裾は解消しない。過剰投入方式は長い要求を破棄するため、特に群相対の学習では長さに応じた標本の偏りを生む。途中分割方式は装置の遊休を減らす一方、同一軌跡が複数方策世代をまたぎ、重み更新後にKVキャッシュを再利用できなくなる。

DORAは、軌跡を丸ごと単一世代で生成するという学習上の制約を維持したまま、生成要求間で複数世代を同時に実行する。この選択が、長い軌跡の保存、同期境界の除去、同一世代間のKVキャッシュ移送という三つの機構を同時に成立させる。動的資源編成とキャッシュ移送を切り離して考えると、旧世代へ残された装置の遊休、または要求移動時の再入力処理という別の費用が残る。

## 限界と実装状況

第一に、陳腐化上限 `K` は手動で設定する。大きくすると生成側の稼働率を高められる一方、現在方策とのずれが大きくなり、実験でも `K=3` は `K=1` より収束が遅い。著者らは適応的な遅延制御や明示的な遅延補正を将来課題としている。第二に、実験は社内の統一基盤を用いており、公開された別の強化学習基盤（veRL、AReaL等）と直接比較した結果ではない。

第三に、同一世代の重みを保持するインスタンスが必要であり、複数世代の共存そのものに重みの配置費用がある。長い文脈でKVキャッシュ転送は再入力処理より安くても、ネットワークが飽和する環境では移動費用が増え得る。第四に、約500BのMoEモデルに関する拡張性の主な証拠は製品環境であり、同規模の公開再現実験が提供されているわけではない。

本稿の実装情報は論文に記載された社内構成を説明するもので、公式コードの公開を意味しない。論文で記述されたGPU環境はCUDA 12.4・H800中心であり、家庭用GPUやWindows環境での実行性能・再現性を直接示すものではない。
