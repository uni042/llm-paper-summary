# End-to-End Latency-Minimizing and Load-Balanced Request Scheduling for Edge LLM Inference in Agentic AI Services

> キー・バリューの量と滞在時間、リアプノフ長期制約、遅延報酬再配分を組み合わせ、分散エッジ推論の遅延と負荷分散を同時最適化する割当方式。
## 書誌情報
- **著者**: Zhen Li, Jun Cai, Haoran Gao, An Li, Tan Li
- **公開**: arXiv:2609.17193
- **種別**: preprint
- **対象**: エッジLLM、要求割当、負荷分散、キー・バリューキャッシュ、強化学習
- **実装**: 評価はPyTorch 1.8による模擬実験で、Llama-3.2-1BをRTX 3080、3090、4090上のvLLMで事前計測した処理速度を利用する。公開コード置き場は論文ページで確認できない。
## 概要
分散したエッジ計算機へ大規模言語モデル要求を割り当てる際、通信、事前充填、反復生成、キー・バリューキャッシュの変化を時間枠をまたいで追跡し、長期平均遅延を抑えながら計算機間の負荷偏りも制御するLYREOを提案する。キー・バリュー占有量と滞在時間の積を負荷指標とし、リアプノフ仮想待ち行列で長期制約を扱い、長短期記憶網による将来収益予測で要求完了まで遅れて現れる結果を過去の割当判断へ再配分する。

本手法は三つの要素を結合する。第一に、無線上り通信、同期待ち、複数要求の事前充填、反復単位の生成、完了要求の退出、新規要求の途中参加を一つの時間軸で追い、各時間枠の終端に未完了状態を次へ渡す。第二に、負荷を要求数ではなくキー・バリューキャッシュの占有量を時間積分したメモリ時間消費で測り、異種計算機の能力で正規化する。第三に、長期負荷偏差をリアプノフ仮想待ち行列へ変換して適応的な制約圧を作り、長短期記憶網が状態・行動列から将来収益を予測して、完了時にしか分からない遅延結果を原因となった以前の割当へ再配分する。これにより、長期制約と遅延報酬を通常の方策最適化へ同時に取り込む。

代表結果として、学習収束時平均E2E 遅延は5 seeds、シミュレーションでLy-PPO 約3.9 s、PPO 約5.2 sに対して約2.4 s。Ly-PPOとの差はreward redistributionの寄与を示す。
## 問題設定
自律型サービスが複数のエッジ計算機上の大規模言語モデルを共有する場合、一つの要求は通信、事前充填、反復生成を経て複数の時間枠にまたがる。その間にも新しい要求が到着するため、ある要求を一台の計算機へ割り当てる判断は、その要求だけでなく既に生成中の要求のバッチ幅、キー・バリュー占有量、反復速度、完了時刻まで変える。従来のエッジ計算のように要求を一時間枠で終わる原子的仕事として扱うと、この相互作用を表せない。また単純な待ち行列長や要求数は、入力長と出力長が異なる要求がどれだけのメモリをどれだけ長く占有するかを区別できない。さらに割当判断の良否を示す端末間遅延は要求完了時まで観測できず、その間に次の割当を何度も決めなければならない。固定の負荷罰則だけでは、長期間に蓄積した偏りへ適応的に反応しにくい。このため、実行状態を時間枠をまたいで追跡する遅延モデル、メモリ量と占有時間を同時に表す負荷指標、遅れて得られる結果を過去の判断へ帰属する学習機構が必要になる。
## 新規性
本手法は三つの要素を結合する。第一に、無線上り通信、同期待ち、複数要求の事前充填、反復単位の生成、完了要求の退出、新規要求の途中参加を一つの時間軸で追い、各時間枠の終端に未完了状態を次へ渡す。第二に、負荷を要求数ではなくキー・バリューキャッシュの占有量を時間積分したメモリ時間消費で測り、異種計算機の能力で正規化する。第三に、長期負荷偏差をリアプノフ仮想待ち行列へ変換して適応的な制約圧を作り、長短期記憶網が状態・行動列から将来収益を予測して、完了時にしか分からない遅延結果を原因となった以前の割当へ再配分する。これにより、長期制約と遅延報酬を通常の方策最適化へ同時に取り込む。
## 手法
### 手法のあらまし
各時間枠の冒頭で、利用者の入力長、推定出力長、位置、無線状態と、各エッジ計算機に残る未完了要求の生成位置・キー・バリュー量を観測し、各新規要求を一台へ割り当てる。まず上り帯域を同じ計算機へ送る要求で分け、最も遅い送信が終わるまでの同期待ちを計算する。その間、既存要求の生成は停止せず進み、生成済みトークンに応じてキー・バリュー量を更新する。新規要求の送信がそろうと入力トークンをまとめて事前充填し、その終了後、容量が許す新規要求を既存の生成バッチへ参加させる。各生成反復では現在のキー・バリュー総量から処理速度を求め、出力を終えた要求は反復境界で即座に退出して状態を解放する。時間枠内で終わらなかった要求は生成位置と状態を次の時間枠へ引き継ぐ。こうして割当から完了までの端末間遅延と、各計算機でキー・バリューが占有した量と時間を算出する。長期負荷偏差は仮想待ち行列へ蓄積し、偏りが続くほど次の方策更新で強い補正圧を与える。ところが遅延費用は完了まで得られないため、状態と行動の列を長短期記憶網へ入力し、有限長に切った将来収益へ価値関数の残りを足して予測目標を作る。隣接時点の予測差を再配分報酬として各判断へ与え、その報酬でPPOの方策と価値関数を更新する。したがって実行モデルが正しい遅延と負荷を作り、仮想待ち行列が長期制約を即時信号へ変え、収益予測器が遅延結果を時間方向へ戻し、方策が次の割当を改善する閉ループになる。

### 時間枠横断の動的入退出推論モデル
未完了要求を時間枠をまたいで保持し、新規要求の送信と事前充填中にも既存要求の生成を進める。各時間枠では、同じ計算機へ割り当てた利用者が上り帯域を分け合うため、要求ごとの送信時間と最も遅い要求に合わせた同期待ちをまず求める。この待ちと事前充填の間も既存要求は反復生成を続け、生成トークンの増加に応じてキー・バリュー占有量が増える。事前充填が終わると新規要求は生成バッチへ途中参加し、以後は既存要求と同じ反復で一トークンずつ進む。出力長へ到達した要求は反復境界で即座に退出し、そのキー・バリューを解放するため、バッチ構成とメモリ量は反復ごとに変化する。生成速度は現在の総キー・バリュー量に応じた事前計測関数から求めるので、ある新規要求の割当が既存要求の反復時間をどれだけ延ばすかまでモデルへ反映される。時間枠の終わりに残った要求は生成済み位置と状態を次枠へ引き継ぎ、要求が一枠で完了するという従来近似を置かない。これにより割当判断、通信競合、事前充填、生成バッチ、メモリ状態、完了遅延を一つの因果列として扱える。

### キー・バリューのメモリ時間負荷
負荷分散の対象を単純な要求件数や瞬間的な待ち行列長ではなく、各要求が保持するキー・バリューキャッシュの量と、その状態が計算機上に残る時間の積として定義する。入力が長い要求は開始時点から大きなキャッシュを持ち、出力が長い要求は生成に伴ってキャッシュを増やしながら長時間残るため、同じ一件でも資源圧力が大きく異なる。この差を時間積分したメモリ消費として数え、さらにRTX 3080、3090、4090のような異種計算機の能力差を考慮して正規化する。各計算機の長期平均負荷が全体平均からどれだけ外れるかを偏差として制約し、その超過をリアプノフ仮想待ち行列へ蓄積する。高性能な一台へ要求を集中すれば短期平均遅延は下がるが、その計算機のキャッシュ余白が失われ、長い要求や交通量増加時に99百分位遅延が悪化する。本指標はその将来リスクを現在の割当へ反映するための状態量であり、論文の除去実験では要求数だけに置き換えると平均遅延、99百分位遅延、負荷偏差、高占有率の全てが悪化している。

### リアプノフ誘導の遅延報酬再配分
長期負荷偏差は一回の割当だけで評価できないため、偏差の超過分を仮想待ち行列へ蓄積し、過去の偏りが大きいほど現在の目的関数で強い補正を与える。これにより固定係数の罰則と異なり、長期間同じ計算機へ要求が集中した状況へ適応的に反応する。一方、端末間遅延は要求が通信、事前充填、複数回の生成を終えるまで確定せず、割当直後には正解となる報酬がない。そこで二層の長短期記憶網へ状態と行動の列を入力し、将来の累積収益を予測する。無限先まで待つ代わりに一定長で系列を切り、末尾以降の期待収益は価値関数で補う。ある時点までの予測と一つ前までの予測との差を再配分報酬として作ることで、最終的に得られた遅延結果を、その結果を生んだ以前の割当判断へ時間方向に戻す。この報酬と仮想待ち行列による制約項をPPOの方策・価値更新へ使うため、方策は遅延だけでなく蓄積負荷の将来影響も学習できる。Ly-PPOとの比較で収束遅延が約3.9秒から約2.4秒へ下がることは、この再配分機構を加えた効果を示す。

### 全体のデータ／制御の流れ
サービス割当器は無線状態、要求長、利用者位置、各計算機の処理能力、未完了要求、キー・バリュー状態を観測し、要求ごとに割当先を選ぶ。実行模擬器は通信から生成完了までを時間枠横断で進め、遅延とメモリ時間負荷を返す。長期制約器は負荷偏差を仮想待ち行列へ変換し、報酬再配分器は遅延して現れる結果を状態・行動列へ分解する。方策学習器はこれらを合わせた即時信号で更新されるため、単なる最短遅延の一台集中ではなく、将来のメモリ余白を保ちながら端末間遅延を下げる割当を学習する。
## 評価条件
- **ハードウェア**: シミュレーション parameterはRTX 3080/3090/4090相当の10/20/24 GB GPU。各serverにLlama-3.2-1Bを配置し、プリフィル rate 2,500/4,000/8,000 トークン/s、デコード スループットは対応GPU上のvLLM offline profilingからKV占有量の関数として設定。
- **ソフトウェア**: PyTorch 1.8。PPO actor/criticは各4層fully connected network、reward redistributionのreturn predictorは2層LSTM hidden dimension 64。learning rate 3e-4、PPO epoch 10、discount 0.98、5 random seeds。
LMSYS-Chat-1Mからリクエスト長を抽出し平均input 70、output 215 トークン。800 slot、1 slot=1s、各userは毎slot 1 リクエスト、200×200m領域で位置変動。KV 16 KB/トークン、server 帯域 6–14 MHz、load-balance tolerance 0.01。比較はLy-PPO、通常PPO、静的 batching、Least-Loaded、Random。学習時は完全trajectoryを事前利用せず、800 slot後の未完了リクエストは完了まで実行して最終rewardへ反映。
実GPUでスループット profileは取るがエンドツーエンド結果はシミュレーションであり、実network/serving cluster deploymentではない。output lengthを既知または推定済み入力と仮定し、downlink response 遅延は無視。各slotで全userが1 リクエスト生成する規則的arrival modelで、実traffic burstやoutput-length prediction errorへの頑健性は直接評価しない。
## 主要結果
LYREOはLyapunovによる長期constraint処理とreward redistributionの両方が効き、Ly-PPO/PPOより低い平均遅延と小さいload-balance queueへ収束する。load balanceを外すと平均遅延は下がる一方、P99とhigh-KV率が大幅悪化し、単なるリクエスト countを負荷指標にすると全指標が悪化する。

- 学習収束時平均E2E 遅延 / 約2.4 s (比較対象: Ly-PPO 約3.9 s、PPO 約5.2 s; 条件: 5 seeds、シミュレーション) — Ly-PPOとの差はreward redistributionの寄与を示す。

- 収束時平均load-balancing queue length / 約0.02 (比較対象: Ly-PPO 約0.09、PPO 約0.22; 条件: post-hoc comparison) — Lyapunov guidanceとredistributed rewardの組合せでimbalance蓄積への反応が改善。

- user数20–60での遅延 / 約2.3→3.3 s (比較対象: Ly-PPO 約2.9→5.6 s; 条件: edge server S=8) — tested range平均でLy-PPO比約33%低減し、load deviationを約0.009未満に維持。

- load-balancing ablation / LYREO: avg 2.63 s、P99 3.74 s、deviation 0.008、high-KV 6.42% (比較対象: LYREO-Count: 2.79 s/4.56 s/0.011/8.04%; 条件: count-based ワークロードへ置換) — メモリ-time 指標はリクエスト countよりresource pressureをよく表す。

- load-balance constraint除去 / avg 遅延 2.02 s (比較対象: LYREO 2.63 s; 条件: LYREO-NoLB) — 平均は23.2%改善するがdeviationは125%増、P99 6.73 sで79.9%増、high-KV 14.35%で123.5%増。

### 負の結果・境界条件
- load-balance制約を外すと平均遅延は2.02sまで下がり、LYREOの平均遅延最小化だけなら制約がcostになる。
- リクエスト countだけのbalancingは平均・P99・deviation・high-KVの全てでメモリ-time指標より悪い。
- 結果はシミュレーションであり、実edge clusterでスケジューラ オーバーヘッドやwireless measurement errorを含むエンドツーエンド検証ではない。

### 結果の読み方
主要な価値は、stateful LLM servingの負荷を瞬間queue長ではなくKVの量×時間で表し、完了まで遅れる遅延 feedbackをdecision時系列へ再配分した点。高負荷ほどreward delayが長くなるため、user増加時にLy-PPOとの差が広がる。
## 品質への影響
平均遅延だけを追うとserver集中でtail 遅延とメモリ riskが悪化するため、LYREOは平均値を少し犠牲にしてP99とKV headroomを改善するtradeoffを明示している。
## 既存研究との差
vLLM/Orca等が単一engine内のcontinuous batchingやKV管理を最適化するのに対し、LYREOは複数edge serverへのリクエスト assignmentを通信状態と未完了デコード状態まで含めて扱う。従来edge DRL/Lyapunov スケジューラはslotごとの即時signalやatomic task近似が中心だが、本手法はリクエスト completionまで遅延するfeedbackをredistributeする。Least-Loadedのリクエスト数ではなくKV メモリ-timeをloadとして使う点も差分。
## 限界
実評価はvLLM profiling値を使うシミュレーションで、実際のmulti-edge serving deploymentではない。output トークン長を既知/推定済みと仮定し、その推定誤差は評価しない。プリフィルはKV容量が十分ならデコードから独立したrateとし、downlink 遅延も無視する。1秒slot・毎user毎slot1 リクエストというarrival abstractionはburst性や非同期arrivalを簡略化する。
## 実装状態
PyTorch 1.8によるpolicy/reward predictorと、RTX 3080/3090/4090上のLlama-3.2-1B vLLM offline profilingを用いたシミュレーション実装。論文・arXivページに公開code repositoryは記載されていない。
## 研究上の位置づけ
本リポジトリのserving スケジューラ系では、GPU内バッチ スケジューラより上位のdistributed edge ルーティング層に位置する。KV キャッシュを単なる容量制約でなくtime-integrated ワークロード signalとして使うため、Llumnix等のstate-aware スケジューラやdisaggregationと接続しやすい。将来的には実serverのKV pressure、network RTT、プリフィル/デコード分離clusterのtelemetryをvirtual queue stateへ直接入れ、シミュレーション前提を外すことが重要。
