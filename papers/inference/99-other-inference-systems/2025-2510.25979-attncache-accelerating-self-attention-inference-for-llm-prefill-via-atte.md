# AttnCache：異なる入力間の注意行列を再利用するprefill専用推論

## 概要

本論文が狙うのは、一般的なチャットの長い応答を逐次生成する処理ではなく、入力を一度符号化して分類ラベルや埋め込みを得る**prefill-only推論**である。例えば選択肢の記号一つを出力する質問応答、文の類似度を測る埋め込み生成、感情分類などでは、長い系列を符号化する一方、後続の自己回帰decodeは不要または最小限となる。この条件ではKVキャッシュを次のトークン生成に再利用する意義が小さく、長い系列に対する自己注意の計算が律速になる。

AttnCacheの発見は、文意の異なる入力でも、複数層・複数ヘッドにわたる**注意行列の形状が似る場合がある**という観測である。各入力のQとKから毎回softmax(QKᵀ/√d)を作る代わりに、以前の別入力に対して計算済みの注意行列を取り出し、現在入力のVに乗算する。これによりQ/K射影、回転位置埋め込み、注意重みの計算を省く。ただしV射影、注意行列×V、FFNなどは残る。従って「注意計算全体をゼロにする」方式ではない。

著者の実測はCPUで平均1.2倍のエンドツーエンド（E2E）高速化、自己注意部分で平均2倍、GPUでE2E平均1.6倍、注意部分で平均3倍を報告する。ここで平均値は論文が採用したprefill-onlyタスク・モデル・再利用閾値での値であり、通常の会話生成にそのまま適用できない。特にヒット率が低い入力集合では特徴計算と検索の費用だけが増える。

## 問題設定と設計上の難点

標準のTransformer注意は入力長Lに対しL×Lの注意行列を形成する。各層でQ/K/V射影を行い、QKᵀの行列積、正規化、Vとの積を計算するため、長い入力では二次的に増える演算が問題となる。通常のKVキャッシュ最適化は、prefillで得たK/Vを後続decodeで繰り返し使う場合に効果がある。しかし本研究のように一回の入力符号化で処理が終わる用途では、キャッシュすべき対象をK/Vから**注意行列そのもの**へ変える余地がある。

単に過去の注意行列を保存するだけでは実用にならない。第一に、新しい入力と過去の入力の注意行列がどれほど似ているかを、実際にQKᵀを計算する前に予測しなければならない。注意行列を先に計算して類似度を測るのでは高速化の意味がない。第二に、注意行列は系列長やヘッド数に依存して巨大で、保存と検索でメモリ帯域を消費する。第三に、PyTorch等が効率よく行列演算するには連続したメモリ領域が必要だが、索引から拾った多数の行列は物理的に散在しやすい。従来のコピー方式では複数回の読み書きが追加される。

本論文はこの三点を、軽量な**特徴射影器**、二つの索引付きデータベース、**仮想メモリマッピング**で解く。精度を守るため、検索で近い候補が見つからなければ標準注意計算へ戻す。従って利得は「十分似た注意行列が頻繁に現れる入力分布」と「検索・読み出しが標準計算より軽い記憶階層」の両方に依存する。

## 手法

### 1. 特徴射影器を学習して注意行列の近さを予測する

入力文Sを通常のトークン化・位置情報付加などで埋め込みhへ変換し、二層の多層パーセプトロン（MLP）で低次元の特徴fへ射影する。特徴射影器は、文意の類似性そのものを検索するためのものではない。狙いは、**注意行列が似た入力同士が特徴空間でも近くなる**ように学習することである。この違いは重要で、文の意味が違っても注意の重み分布が似ていれば再利用候補となる。

教師ラベルを人手で作る代わりに、同一重みを共有する二つの射影器からなるSiamese構造を使う。入力埋め込みX₁、X₂の特徴ベクトル間距離 `ŷ=||f_W(X₁)-f_W(X₂)||₂` を、事前計算した注意行列のヘッド別距離とトークン長の差から作る教師値yへ近づける。論文の式(2)ではヘッドごとの注意行列の差を集約し、係数αで重みを調節しながら系列長の差も考慮する。学習損失は外れ値に強いSmooth L1である。

長さの差を特徴学習へ入れる理由は、行列が似て見えても系列長が大きく違えばそのまま置換できず、出力誤差が増えるためである。実験では特徴次元128、α=0.2を採用する。射影器の計算が重いと、節約した注意計算を特徴抽出に使い切るので、深いTransformerではなく二層MLPとする。この小ささは実装上の性能要件であり、単なるモデル選択の好みではない。

### 2. 特徴データベースと注意行列データベースを共通索引で結ぶ

オフライン構築では、学習用の文をLLMへ入力し、各層・各ヘッドの注意行列を収集する。対応する入力埋め込みを射影器に通して特徴ベクトルを作り、**特徴ベクトルDB**へ保存する。各特徴には索引idxを割り当て、同じidxに紐付く各層の注意行列を**注意行列DB**へ格納する。両DBの索引を一致させることで、オンライン検索結果から層全体の行列群を一度に取得できる。

オンラインで新しい文が来たら、入力埋め込みhからfを計算し、Faissの近似最近傍検索で類似候補とスコアを取得する。論文のAlgorithm 1は、類似度が閾値θ以上の場合にidxを使って全層の注意行列を読み出し、attention cacheへ格納する。実験で主に使うθは0.99。閾値を上げれば再利用率は下がるが不適切な行列置換を抑えられる。閾値を下げればヒット率は上がるものの、品質低下の危険も高まる。

この検索はモデルの**各層で繰り返さず、推論開始時に一度**行う。比較方式AttnCache-fは層ごとに特徴検索を繰り返し、さらに長さ差を学習ラベルへ十分組み込まないため、検索オーバーヘッドと誤置換が増える。層間再利用を狙うSANやLazyFormerとも異なり、AttnCacheは**別の入力文から得た注意行列**を取り出す点が新しい。

### 3. ヒット時の計算経路とミス時のフォールバック

Algorithm 2では各Transformer層で現在入力のVを計算する。キャッシュがヒットした場合、保存済み注意行列Aを使い `A·V_current` を求め、残差接続とFFNを通常通り実行する。この経路では現在入力のQ、K、RoPE、softmaxを省く。過去入力のVまで流用するわけではないため、完全な出力のメモ化とは異なる。層の中で「重み付けパターンだけを過去から借り、内容の値は現在入力から作る」方式である。

検索に失敗した場合は現在入力のQ/Kを計算し、位置埋め込みとsoftmaxを経て標準注意を実行する。これにより品質のための保守的な逃げ道がある一方、射影・検索の追加費用が無駄になる。したがって個別リクエストが必ず速くなるとはいえない。バッチ全体でヒット率が十分高い場合に平均スループットやE2E遅延の改善が期待できる。

### 4. 注意行列を取り出す際のメモリ配置

特徴索引が高速でも、注意行列を散在した物理アドレスから集め、連続テンソルへコピーしてからGPU/CPU演算へ渡すと、複数のメモリ読み書きが増える。論文は層の注意行列をファイルオブジェクトとしてまとめ、隣接層を連続的に配置し、仮想メモリ上では連続する領域へマッピングする。これにより、物理的に離れた行列群を**追加のテンソルコピーなし**で連続領域として参照する。使用後はマッピングを解除する。

ただし仮想アドレスを連続に見せることと、物理的な容量・転送帯域が無限になることは別である。DBがDRAMやGPU HBMを超える場合は、格納媒体からの読み出し遅延が支配的になりうる。論文はDRAMとHDDを組み合わせた構成も検討するが、容量不足の実測では必要な注意行列がDRAMに存在すると仮定した「仮想的な大容量DRAM」条件で時間を評価した箇所がある。これをディスクからの実際のミス込み高速化として読むべきではない。

## 評価

### 対象モデル、課題、機材、比較条件

対象は文埋め込みの意味類似度を測るSTS12〜16、STS-B、SICK-R、二値感情分類SST-2、多肢選択のMMLUである。STSはSpearman相関、SST-2とMMLUは正答率を測る。CPUではLlama-2-7B、Llama-3-8B、Mistral-7Bのfp32重みを使用し、SentEvalで評価する。GPUでは小型のLlama-3系列やNF4量子化したLlama-3-8B、DeepSeek-MoE-16B、Qwen1.5-MoE-A2.7Bを評価する。EncoderモデルのBERT base、RoBERTa、DeBERTaも別途調べている。

サーバーはIntel Xeon Silver 4410Yの24コアCPUを2ソケット、DRAM 512GB、HDD 14TB、NVIDIA A100 80GBを搭載する。各タスクでは特徴射影器とDB構築に使わなかった1,000サンプルを選んで測定する。特徴次元128、バッチ64、基本閾値θ=0.99。Faissの100,000件×128次元の検索は著者環境で0.5ms未満とされ、特徴抽出や注意計算と比較して小さい。ただし実運用ではDBの更新、データ分布、キャッシュ常駐率が変わる。

比較対象は通常の全計算（Full Model）、同一入力内の層間注意再利用を行うSANとLazyFormer、各層で別々に検索するAttnCache-f。精度低下と高速化の両立を見るため、論文は `γ=(Avg_full−Avg_method)/(Speedup_method−1)` という品質低下／高速化比も使う。γが小さいほど同じ高速化に対する品質損失が小さい。これは単一の速度指標ではなく、精度の異なる方式を比較する補助指標である。

### MMLUとモデル種類：GPU・CPU、Dense・MoEを区別する

原著Table 3のMMLU Math、Llama-3系列の短い入力から長い入力までの設定では、CPU注意部分がおよそ2.04〜2.13倍、GPU注意部分が2.97〜3.02倍。E2EではCPU1.19〜1.27倍、GPU1.62〜1.66倍である。注意部分の3倍とE2Eの1.6倍は同じ指標ではなく、FFNなど残存計算が全体速度の上限を作ることを示している。MMLU Mathの0-shotでは基準正答率28.70、AttnCache29.57と上回る一方、5-shotでは47.83から46.96へ下がる。改善だけを選択して「精度向上」とまとめることはできない。

原著Table 5のNF4量子化モデルでは、Llama-3-8BのMMLU Math正答率41.74→40.00、E2E1.48倍、DeepSeek-MoE-16Bは30.43→28.70、E2E1.12倍、Qwen1.5-MoE-A2.7Bは35.65→34.78、E2E1.15倍となる。MoEでも注意計算の節約はできるが、expert計算や他の費用が残るため、注意部分が2倍超でもE2E利得は小さい。Denseモデルの速度倍率をMoE全体の倍率へ流用してはいけない。

原著Table 4のLlama-3-8B一層の内訳では、標準注意482msに対しAttnCacheは156ms、FFN830msは両者で変わらず、合計は1312ms→986ms。Q/K射影・RoPE・注意行列計算を消しても、V射影41msと注意行列×V等115msが残る。AttnCache-fでは特徴計算32ms、検索2ms、注意行列取得18msが各層に加わり、合計1038msとなる。単一検索方式の設計意義を直接示す比較である。

### 閾値・量子化・Encoderへの一般化と負の結果

STS15から100文を取り、θを変化させる感度分析（Figure 6）では、閾値を下げるとヒット率が上がる反面、注意行列の不一致が増え精度が落ちる。θ=0.99の条件ではヒット率約30%でSpearman相関が約2%低下する。検索が成功したときの速度だけを測ると、ミス時の負担を過小評価するため、このヒット率は導入判断に重要である。

EncoderのSST-2では保守的／中庸／積極的な閾値0.995／0.99／0.95で評価し、E2Eは順に1.10／1.18／1.34倍。BERT baseの正答率は91.3%（基準）から積極設定で85.7%へ、RoBERTaは94.8%から90.4%へ低下する。DeBERTaでは保守設定で95.0%→95.5%の例もあるが、全モデル・全閾値で品質が上がるわけではない。3モデルの平均速度は1.21倍、平均の精度低下は1.3〜2.7ポイントと報告される。

量子化やAttention/Block pruningとの併用（Table 8）では、Llama-3.2-3BのSTS平均がFull 72.67、AttnCache単独71.57、Quanto単独71.05、併用70.10となる。BlockDrop単独66.59、AttnCacheとの併用65.45で、圧縮・剪定と再利用の誤差が重なる。方式が組み合わせ可能であることは、精度低下なしを意味しない。

## 既存研究との差

PromptCacheやChunkAttentionは主に**共通prefixのKV**を再利用する。AttnCacheは入力文が一致しなくても注意行列の形が近ければ再利用するため、共通文字列を持たない入力にも適用できる。その代わり近似置換であり、prefixの完全一致キャッシュと違って出力の同一性を保証しない。

SANやLazyFormerは同じ入力の近隣Transformer層間で注意を共有する。AttnCacheは入力間の冗長性を探索するため、特徴射影器の学習とDBの事前構築が必要になる。AttnCache-fとの差は「各層で検索するか、開始時に一度だけ検索するか」と、教師距離に系列長差を含めるかである。比較結果では単一検索の方がオーバーヘッドが小さく、精度保持も良い。

通常のKV圧縮、投機的復号、decode用paged attentionは、長い出力を順次生成するワークロードが中心である。本研究はprefill-onlyに限定して別の計算を省くため、サービング全体でこれらと競合するというより、タスク構成によって補完する関係にある。

## 限界と実装時の注意

**最大の適用制約はdecode非対応**である。再利用時にはKを計算・保持しない。後続の自己回帰decodeでは過去Kが必要で、注意行列もprefillのL×Lから1×(L+t)へ形状が変わる。従って本方式をそのまま通常のチャット生成の高速化へ使うことはできない。要旨の「LLM推論高速化」をすべての生成タスクへ一般化しない。

次にDBの容量が大きい。L×Lの注意行列を層・ヘッド・入力ごとに保存するので、候補数や系列長を増やすとメモリが急増する。論文のメモリマッピングは余分なコピーを減らすが、保存容量や遠隔ストレージからのI/Oを消さない。DRAMに必要な行列が常駐すると仮定した測定値を、HDDミスを含む実環境の保証値として扱わない。大規模コーパスでの再利用DBの更新・削除・陳腐化・マルチテナント隔離も別途設計が必要である。

さらに、特徴射影器は注意行列を教師とするため、対象モデルの層構成・トークナイザ・重みが変わると、既存DBの注意行列が適合する保証はない。類似閾値θは入力分布に依存し、未知分布でヒット率が下がれば検索オーバーヘッドによって標準計算より遅くなる。注意行列の近さは最終タスク精度の十分条件ではなく、重要な局所的注意の差が答えを変える可能性がある。

著者はコードを公開しているが、本稿は論文v3の表・図・Algorithm 1/2に基づく読解であり、再現実験やコード実行を行った報告ではない。とくに「平均1.6倍」はA100を含む著者環境・評価集合に限られ、GPU世代、系列長、DBの常駐率、バッチ数が違う環境への外挿は避ける。
