# Attention Needs to Focus — 注意の過負荷・過少負荷とLazy Attention

## 書誌情報と研究範囲

Zichuan Fuほか9名による2026年1月公開のプレプリント（arXiv:2601.00919v2）。対象はTransformerの注意演算の**正規化と位置バイアスを学習時から変更するモデル構造**であり、既存の学習済みLLMに単純に差し込める推論カーネルではない。論文は「注意の過負荷（attention overload）」と「注意の過少負荷（attention underload）」を区別し、両者を注意重みの不適切な配分として扱う。

## 概要

標準のソフトマックス注意は、ある照会位置に対するキーの重みを必ず合計1にする。関連するキーが少ない場合でも重みをどこかへ割り振るため、最初のトークンへ不自然に注意が集まる注意シンク（attention sink）が起こり得る。逆に、多数のキーへ広く重みを割り振ると異なる特徴が混ざり、隠れ表現が区別しにくくなる。著者らはこれらを別々の不具合ではなく、注意重み配分の両極と位置付ける。

提案するLazy Attentionは、回転位置埋め込み（rotary position embedding; RoPE）に**ヘッド別・距離別の学習可能なバイアス**を足して過負荷を緩和し、ソフトマックスの後に**ヘッド別の負のオフセットと正規化線形関数（ReLU）**を適用するElastic-Softmaxで過少負荷を緩和する。340Mパラメータ・150億学習トークンの条件では複数課題の平均正答率48.01%で比較方式の最高値47.68%を上回るが、760M・300億トークンでは51.53%でTitansの51.56%にわずかに及ばない。品質と重み集中度の両立が主張であり、実機の推論速度を直接示す研究ではない。

## 問題設定：なぜ注意重みを変えるのか

通常の注意では照会 $q_i$ とキー $k_j$ の内積をソフトマックスへ渡す。これにより全てのキーへ非負の重みが付き、行和は1となる。文脈に関係するキーがないときでも正規化を免れず、初期トークンが余剰の重みを引き受けることがある。StreamingLLMなどはこの現象を前提に初期トークンを保持するが、Lazy Attentionは現象自体を抑える設計を試みる。

他方、広い文脈で多くのキーに同程度の重みが付くと、異なる情報が加重平均され、各位置の表現が似通う。論文はこれを注意の過負荷と呼ぶ。単に注意シンクを消せばよいのではなく、必要な局所・遠隔情報へ重みを集中させるために、位置の区別と正規化の自由度を同時に設計する必要がある。

著者らは、固定トークンを学習時の特定位置へ挿入する実験を行う。固定トークンが序盤にある場合はその位置へシンクが移るが、開始位置からおよそ16トークン以上離すと最初のトークンが再びシンクになる。また同じ単語を繰り返した系列を与えると、位置符号化方式が異なる複数モデルでも注意の偏りが変化する。これは位置情報と表現の分散がシンクの出現位置に影響することを示すが、全てのモデルでシンクが同じ原因から生じると断定する証明ではない。

## 手法

### 1. ヘッド・次元を分けた位置弁別

各ヘッド $h$ の注意スコアを、RoPEを施した照会・キーの内積に、相対距離 $|i-j|$ の学習可能バイアス $b^{(h)}_{|i-j|}$ を加えて定義する。

$$s^{(h)}_{ij}=\frac{(R_iq_i^{(h)})^\top(R_jk_j^{(h)})}{\sqrt{d_h}}+b^{(h)}_{|i-j|}.$$

RoPEはヘッド内の次元ごとに異なる回転周波数で距離を表し、追加バイアスは**ヘッド単位でどの距離を重視するか**を学習する。ALiBiのような固定直線勾配と違い、近距離を強く抑えつつ遠距離を再び許容する非単調な分布も表現できる。追加バイアスは局所窓 $W=512$ の内側に限り、それより遠い距離ではゼロにする。これにより距離別の学習パラメータと参照費用を制限し、遠距離の位置区別はRoPEへ任せる。

学習後の可視化では初期層に距離とともに減衰する局所重視の傾向が現れ、中間層では減衰が弱まり、上位層では近傍に正のバイアスを与えた後で中距離を抑え、遠距離の抑制が小さくなる。固定勾配では得られない層・ヘッド別の挙動である。ただしバイアス可視化は解釈を補助するもので、どの形が全タスクで最適かを個別に証明したわけではない。

### 2. Elastic-Softmaxによる重みの切り落とし

標準ソフトマックスの結果 $p_{ij}^{(h)}$ に対して、ヘッドごとに学習するオフセット $\tau^{(h)}$ を照会位置 $i$ の参照キー数で割って加え、負になった値をゼロにする。

$$\alpha_{ij}^{(h)}=\operatorname{ReLU}\!\left(\operatorname{Softmax}(s_{ij}^{(h)})+\frac{\tau^{(h)}}{i}\right),\qquad\tau^{(h)}_{\mathrm{init}}=-1.$$

$\tau=-1$ で全キーの確率がほぼ一様なら、各重みから約 $1/i$ を引くため、関連度の低いキーをゼロへ落とせる。通常のソフトマックスと違って**出力重みの総和が1である必要がない**。したがって「有意なキーがない場合は合計の注意量を小さくする」という選択が可能になる。重みの符号はReLUで非負に保たれる。

ここで重要なのは、単なる事後的な閾値設定ではなく、$\tau^{(h)}$ を学習することである。初期値を0にすると学習初期にシンクへ適応してしまい、後からシンクを減らしにくいという構成要素除去結果がある。逆に全位置で一定のオフセットを引くと、長い系列で過剰に削りやすく、$1/i$ で規模を補正することに意味がある。

### 3. FlashAttentionとの実装関係

Elastic-Softmaxはまず通常のソフトマックス統計を求め、その後にオフセットと切り落としを適用する。論文付録はFlashAttentionのタイル化と両立させるための**二段階処理**を記述する。ただしこれは標準FlashAttentionを無変更で呼ぶだけの機構ではない。行ごとの正規化統計を確定してから補正する必要があり、追加の処理・メモリアクセスが発生し得る。

このため、注意重みが疎になったという数値を、そのまま浮動小数点演算数やGPU実行時間の削減率とみなしてはならない。実際に計算を省略するにはゼロ重みを検出し、疎な計算経路へつなぐ実装が必要になる。論文が測るのは主として学習後の品質、注意配分、シンク抑制である。

## 評価条件

| 項目 | 原著の設定 |
|---|---|
| 学習規模 | 340Mパラメータ・150億トークン、760Mパラメータ・300億トークンの比較 |
| 学習コーパス | FineWeb-Edu。100億/1000億トークンのプールから決定的に抽出 |
| トークン化と系列長 | Llama 2の32K語彙、系列長4096、全体バッチ約50万トークン |
| 最適化 | AdamW、最大学習率$4\times10^{-4}$、余弦スケジュール。ウォームアップ1024または2048ステップ |
| 提案手法の初期設定 | $\tau=-1$、学習可能な距離バイアス窓$W=512$ |
| 主比較 | Transformer++、Sigmoid Attention、RetNet、Mamba2、TTT、Gated DeltaNet、Titans、StreamingLLM |
| 評価課題 | WikiText、LAMBADA、PIQA、HellaSwag、WinoGrande、ARC-Easy/Challenge、SIQA、BoolQ |
| 評価指標 | 困惑度、正答率・正規化正答率、注意密度、初期トークンへの注意比率 |
| 構成要素除去 | 位置弁別を除去、Elastic-Softmaxを除去、オフセットの定数化・初期値変更、512学習文脈からの長さ外挿 |

### 主結果：品質と疎性を分けて読む

| 条件・指標 | 比較対象 | 提案手法 | 解釈 |
|---|---|---|---|
| 340M/15B、課題平均正答率 | Gated DeltaNet 47.68%、Titans 47.54%、Transformer++ 47.29% | Lazy Attention **48.01%** | この学習規模では最高の平均値。ただし差は小さい |
| 760M/30B、課題平均正答率 | Titans **51.56%**、Gated DeltaNet 49.69% | Lazy Attention **51.53%** | この規模ではTitansを上回らない |
| Elastic-Softmaxを除去した340M構成の平均 | Elasticなし48.39% | 完全版48.01% | 注意の疎化を加えると品質はわずかに低下する反例 |
| Elastic-Softmaxの定数オフセット・初期値比較 | $\tau/i$初期値0：平均45.29%、注意密度37.30%、シンク4.15% | $\tau/i$初期値−1：平均45.70%、密度40.24%、シンク0.18% | 初期値と参照長による補正がシンク抑制に重要 |
| 通常ソフトマックスとの比較（構成要素除去表） | 平均45.48%、注意密度94.53%、シンク5.46% | 上記の学習可能オフセットで平均45.70%、密度40.24%、シンク0.18% | 同一表内の正規化方式比較で、余剰の注意配分を大幅に削る |
| 文脈長外挿 | 学習時512、評価512/1024/2048 | 位置弁別ありの完全版が長文での困惑度悪化を抑制 | 外挿は相対比較。実運用の128K文脈性能を示すものではない |

注意密度（density）は、原著の定義では**初期トークン以外へ配分された注意の平均質量**であり、単純な非ゼロ要素数の比率や実測演算削減率ではない。論文が示す約59.58%の「解放された重み」は、この注意集中化の指標として解釈すべきで、GPU処理量が59.58%減ったという意味ではない。

### 構成要素除去と負の結果

位置弁別を除去した340M構成は平均47.89%で、完全版48.01%より低い。一方Elastic-Softmaxを除去すると48.39%となり、完全版より**0.38ポイント高い**。この差を無視して「二機構とも全指標で改善」と結論付けるのは誤りである。著者らの主張は、Elastic-Softmaxでシンクと注意密度を大幅に下げつつ、品質を概ね保つというトレードオフにある。

正規化方式の比較では、単純にソフトマックス後へ位置に依存しないオフセットを加える構成は平均43.83%まで低下し、疎化だけを強くしても品質が維持できない。$\tau/i$ の初期値0ではシンクが4.15%残るのに対し、初期値−1では0.18%まで下がる。したがって負の初期値と参照キー数によるスケーリングは、偶然のパラメータ選択ではなく結果に寄与している。

## 既存方式との差と推論基盤への意味

StreamingLLMはシンクトークンを保持して長文脈生成を安定化させる。Lazy Attentionは学習時から重み総和の制約を緩め、シンクを抑える別の方向である。RoPEのみのモデルと違って、ヘッドごとに近距離・中距離・遠距離の優先度を学習できる。ただしこの設計は**学習済みモデルの注意重みを事後的に変更するだけでは成立しない**。$\tau$ と距離バイアスが学習パラメータだからである。

また、重みの数値的な疎化は自動的な高速化ではない。現在の密な注意カーネルではゼロ重みでも演算経路を通る可能性があり、FlashAttention互換の二段階処理はむしろ追加費用を生む。今後のカーネル実装では、ブロック単位の疎化やタイル単位のスキップを可能にする条件を確認し、**精度、追加正規化費用、実際のメモリ帯域・遅延**を測る必要がある。

## 限界

- **品質優位は規模依存**：340Mでは平均最高だが760MではTitansにわずかに及ばず、全規模・全課題で最良ではない。
- **疎性と性能の非同一性**：論文の主要な疎性指標は注意重みの質量配分であり、実機推論時間、GPUメモリ削減、デコードスループットの改善率を測ったものではない。
- **学習前提**：RoPEに足す距離バイアスとヘッド別オフセットは学習対象であり、既存モデルへの後付けで同じ結果を保証しない。
- **長さ外挿の範囲**：構成要素除去は学習長512から2048までの外挿が中心であり、数万トークン以上の実用文脈や大規模サービングでの有効性は別途検証が必要。
- **注意集中の副作用**：有意な遠距離依存が弱い重みとして現れる場合、閾値処理で情報を落とす可能性がある。オフセットの定数化で品質が悪化する実験は、その調整が重要であることを示す。
