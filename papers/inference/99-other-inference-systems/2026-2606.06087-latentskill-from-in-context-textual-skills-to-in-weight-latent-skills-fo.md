# LatentSkill：エージェントの手順書を重み空間へ移すスキル表現

## 概要

LatentSkillは、言語モデルエージェントが毎回の判断で読み込むスキル手順書を、低ランク適応（LoRA）形式の追加重みへ変換する仕組みである。従来の文脈内スキル方式（In-context Skill）は、作業手順や道具の使用方法を自然言語でプロンプトへ挿入する。複数ステップの作業では同じ手順を繰り返し渡すため、事前充填（prefill）するトークンが増え、文脈長と推論費用を消費する。LatentSkillは、訓練済みの超ネットワーク（hypernetwork）が手順書を読んでスキル専用のLoRAを一度生成し、その後の実行ではスキル文章をプロンプトへ渡さない。

推論時に必要なものは、現在の作業履歴と選択したスキルのLoRAである。スキルを変更するときはLoRAを付け替え、強度を調整するときは係数αを変更する。モデル本体の重みは凍結され、スキルの追加・除去・組合せをモデル全体の再学習なしに行える。一方、スキル生成器の学習には大規模な文書集合と教師エージェントの行動軌跡が必要であり、無学習の圧縮方式ではない。

Qwen3-8Bを基盤としたALFWorldでは、文脈内スキル方式に対し既知課題の平均成功率が52.9%から74.3%、未知課題が56.0%から69.4%へ改善し、事前充填トークン数を約64%削減した。Search-QAでは完全一致率が32.6%から35.6%へ向上し、毎ステップのトークン数が1.10千から0.31千へ減少した。これらは**トークン消費量とタスク品質の結果**であり、生成トークン/秒や実機の総遅延を直接測定したものではない。

## 問題設定：手順書の再注入とスキル管理の両立

エージェントは観測、思考、行動、外部環境からのフィードバックを何度も繰り返す。道具の使い方、失敗時の回復、作業手順などを自然言語のスキル文書として保存すると、必要なときに検索してプロンプトへ差し込める。しかし同じスキルを多くの判断ステップで再注入すると、そのたびに数百から数千のトークンを処理する。通常の接頭辞キャッシュで一部を再利用できても、エージェントの履歴やスキルの選択が変わると完全な共有は難しい。

スキルをモデルの本体重みに学習させれば、推論時の文章は短くできる。しかし複数スキルが同じ重みに混ざるため、個別のスキルだけを削除・更新・組合せするのが難しい。スキルごとに独立したLoRAを訓練する方法はモジュール性を保つが、スキル数が増えると個別訓練の費用が増大する。LatentSkillは、スキル文章からLoRAを生成する共通の超ネットワークを学習し、「文章の繰り返し投入を避けること」と「スキルをモジュールとして扱うこと」を同時に目指す。

この研究の効率化対象はGPUカーネルそのものではなく、エージェントの推論プロンプトに含まれるスキル記述の冗長性である。推論時の入力トークンが減ると事前充填に必要な演算量やKVキャッシュ量を減らせる可能性があるが、LoRAの読み込みや適用の追加費用を含めた実時間の測定がなければ、単純にトークン削減率を速度向上率へ換算できない。

## 手法

### 1. 文章スキルをLoRA更新へ写像する

凍結した基盤モデルをM_θ、自然言語のスキル文書をs、エージェントの時刻tにおける履歴をh_tとする。スキル生成器G_φはsから追加重みΔ_s=G_φ(s)を出力する。文脈内スキル方式ではM_θが(h_t,s)を読んで応答を生成するのに対し、LatentSkillではM_{θ⊕αΔ_s}がh_tだけを読んで応答を生成する。ここでαはスキルの注入強度であり、⊕はLoRAを通した重みの拡張を表す。

各対象線形層のLoRAは、低ランク行列A_s、B_sを用いてΔW_s=B_s A_sと表現される。実際の重みはW'=W+(α/r)B_s A_sとなる。rはLoRAのランクである。G_φは一つの層だけでなく、選択したすべてのTransformer層の複数の射影行列に対して対応するAとBを生成する。入力は文章のスキル、出力は再利用可能なLoRA重み集合であり、モデル本体のパラメータθは更新しない。

LoRA生成後、エージェントのプロンプトには元のスキル文章を置かない。このためスキルが長くても、同じスキルを何度も呼ぶ場合の再注入トークン数はゼロになる。ただしスキルを選択するための情報、作業履歴、道具からの観測は引き続き必要であり、エージェントの全入力トークンがゼロになるわけではない。

### 2. スキル文書事前学習（Skill Document Pretraining）

初期状態の超ネットワークは、任意のスキル文章から有用なLoRAを作れない。そこで著者らは公開スキル文書約17.1万件、合計約3億トークンを収集して、スキル生成器だけを事前学習する。学習目的は文書再構成と文書補完を1対1で混合する。再構成では全文sを生成器へ渡し、LoRAを装着した基盤モデルに元の文書を復元させる。補完では文書の後半を削った接頭部を生成器へ渡し、基盤モデルに全文を補完させる。

学習の勾配は基盤モデルの出力誤差から生成器G_φへ流れる。基盤モデルはスキル本文を直接読まないので、正しい文書を再構成するためには、生成されたLoRAが文書の情報を重みとして運ばなければならない。これにより単なる文字列の埋込みではなく、復号器の各層の動作を変更するパラメータ表現を獲得する。文書補完を混ぜるのは、文書の表層を丸写しするだけでなく、途中までの手順から残りを推定する能力を促すためである。

この段階には、文書収集、約3億トークンの学習、LoRAを生成する超ネットワークの訓練が必要である。学習済みモデルの推論だけで任意の手順書を無条件に高速圧縮できる方式ではない。新しい分野のスキルが事前学習分布から大きく外れると、生成LoRAが必要な手順を十分に表現できない可能性がある。

### 3. 教師軌跡による微調整（Trajectory-Supervised Fine-Tuning）

文書を復元できるだけでは、実際のエージェント行動が改善するとは限らない。そこで次段階では、スキル文書sと、教師が実行した一連の観測h_t・正解行動y*_tからなる軌跡を組にして生成器を微調整する。各軌跡について生成するLoRAは一つで、全ステップに同じLoRAを装着する。各ステップの教師行動を正しく予測する損失を最小化することで、スキルに共通する行動方針をLoRAへ移す。

学習用の教師軌跡は、ALFWorldの237本とSearch-QAの500本である。対象スキルはALFWorldの5種類とSearch-QAの3種類を混合する。教師軌跡はOpenAI o3によって作成され、観測、推論、行動が開始から終了まで含まれる。訓練では基盤モデルQwen3-8Bを凍結し、超ネットワークのパラメータだけを更新する。したがって教師が持つ手順や方針を生成器へ学習させる費用は存在するが、各スキルのために基盤モデルを丸ごと微調整する必要はない。

### 4. 推論時のスキルキャッシュ、強度制御、合成

推論時には、スキルライブラリの文書s_kを一度G_φへ通してLoRAを作り、スキル番号kに対応するキャッシュC[k]へ保存できる。エージェントがスキルを選ぶと、C[k]を基盤モデルへ装着し、現在の履歴だけで判断する。α=0なら追加スキルの効果が消え、αを増やすと追加重みの寄与が強くなる。新しいスキルへ切り替えるときはキャッシュ済みのLoRAを付け替える。

複数のスキルを使う場合、著者らはΔ_K=Σ_k α_k C[k]のような重み空間の加算を検討する。しかし共通部分を含む二つのスキルを単純に足すと、重複する行動傾向が過剰に強くなる。そこでスキル文書を一般的な手順、失敗回避、個別操作などの意味的な部品へ分け、それぞれを別LoRAに変換して共通部品を一度だけ合成する方法も評価する。これはLoRAの数値加算が常に正しいことを保証するのではなく、意味的に整列した部品が必要であるという条件付きの手法である。

## 評価条件

| 項目 | 実験設定 |
|---|---|
| 基盤モデル | Qwen3-8B、補助比較としてLlama3-8B。基盤重みは凍結 |
| スキル生成器 | SHINEと同系統の超ネットワーク、各層のQ/K/V/O、gate、up、down射影にランク8のLoRAを生成 |
| 事前学習 | 約171,000文書、約3億トークン、文書再構成と補完を等比率で学習 |
| 軌跡微調整 | ALFWorld 237本、Search-QA 500本、合計737本の教師軌跡 |
| 学習ハードウェア | H100を8枚、各段階10エポック、最大系列長4,096、AdamW |
| 評価A | ALFWorldの6作業カテゴリ。既知・未知の二分割で成功率とステップ数を測定 |
| 評価B | Search-QAの7データセット。NQとHotpotQAを学習に用い、残り5集合は分布外評価 |
| 比較 | 文脈内スキル、通常モデル、Few-shot、Reflexion、全重み微調整、共有LoRA、スキル別LoRA、SHINE、Text-to-LoRA等 |
| 費用指標 | ALFWorldの毎ステップ事前充填・生成トークン数、Search-QAの毎ステップ総トークン数。GPU実時間ではない |

基盤モデルの推論環境と学習環境を混同しないことが重要である。H100を8枚使ったのは超ネットワークの訓練であり、トークン削減率をH100での実測推論速度向上と読むことはできない。評価はスキル選択が正しい条件に限定されており、誤ったスキルを検索した場合の性能は主要表で測定されていない。

## 主要結果

### 1. ALFWorldの成功率とトークン数

| 指標 | 文脈内スキル | LatentSkill | 差 |
|---|---:|---:|---:|
| 既知課題の平均成功率 | 52.9% | 74.3% | +21.4ポイント |
| 未知課題の平均成功率 | 56.0% | 69.4% | +13.4ポイント |
| 既知課題の平均ステップ数 | 30.8 | 28.4 | 2.4ステップ減 |
| 既知課題の毎ステップ事前充填トークン | 1.21千 | 0.44千 | 約63.6%減 |
| 未知課題の毎ステップ事前充填トークン | 1.23千 | 0.44千 | 約64.2%減 |
| 既知課題の毎ステップ生成トークン | 0.50千 | 0.34千 | 0.16千減 |
| 未知課題の毎ステップ生成トークン | 0.61千 | 0.51千 | 0.10千減 |

成功率の改善と事前充填トークンの削減が同時に見られる。これは単純にスキル文章を削除しただけではなく、教師軌跡で学習した生成器のLoRAが行動選択に有用であることを示す。ただし生成トークンも変化しており、総コストの内訳を事前充填だけで説明することはできない。論文要旨の63.9%減は既知・未知の二条件をまとめた代表値であり、表1の各条件では63.6%と64.2%である。

比較方式のSHINEも超ネットワークを使い、既知59.3%、未知61.2%を達成する。LatentSkillとの差は既知+15.0ポイント、未知+8.2ポイントであり、単に「超ネットワークを使ったから改善した」とは言えない。学習手順とスキル表現の設計が差に寄与していると考えられるが、個々の構成要素の効果を完全に分離したものではない。

### 2. Search-QAの完全一致率と費用

| 指標 | 文脈内スキル | LatentSkill | 差 |
|---|---:|---:|---:|
| 7集合の平均完全一致率 | 32.6% | 35.6% | +3.0ポイント |
| 毎ステップのトークン数 | 1.10千 | 0.31千 | 約71.8%減 |
| HotpotQA完全一致率 | 30.2% | 39.6% | +9.4ポイント |
| Bamboogle完全一致率 | 38.4% | 25.6% | **12.8ポイント低下** |

平均ではLatentSkillが文脈内スキルを上回るが、すべてのデータセットで勝つわけではない。Bamboogleでは38.4%から25.6%へ低下しており、平均値だけを示して「品質劣化なし」とすることは誤りである。また、Search-QAは各データセット原則500例だがBamboogleのみ125例なので、平均は単純な7集合の算術平均ではなく例数に応じた集約値である。評価では検索にE5を用い、モデルが実際に回答するまでのステップにおけるトークン数を比較している。

### 3. 基盤モデルを変えた評価と分布外スキル

Llama3-8Bへ同じ二段階訓練を適用した表3では、ALFWorldの既知課題で文脈内スキル25.0%に対してLatentSkill40.7%、未知課題23.9%に対して31.3%だった。Search-QAの平均完全一致率は24.5%から25.0%へ0.5ポイントの改善に留まる。Qwen3-8Bでの大きな改善率が他の基盤モデルでも同じ大きさで出るわけではない。

訓練時にWebShopの軌跡を使わず、スキル文書だけを渡した分布外評価では、通常モデル10.3、文脈内スキル6.7、事前学習のみのLatentSkill18.5、軌跡微調整後23.9のスコアだった。文脈内スキルが通常モデルより悪化しているのは、長い文章が現在の状態と行動候補への注意を薄める可能性を示すが、分布外の全環境で同じ現象が起きると証明するものではない。

### 4. 注入強度αの感度とスキル合成

αを0から1.2まで9段階で変えると、成功率は単調には増えない。既知課題ではα=0.6で74.29%、未知課題ではα=0.5で70.90%と最大になり、α=1.2では既知22.86%、未知8.21%へ急落する。αを大きくすればスキルが強くなって必ず良い、という解釈は成立しない。既知で最適だったα=0.6を未知へ流用すると、Heat・Pick2・Cleanの各課題で最適値より大幅に悪化するという負の結果もある。

LookとPickの二つのスキルを合成する表5では、意味部品単位の合成が既知84.6%、未知77.8%で最良だった。単純なLoRAの直接加算は既知69.2%、未知61.1%で、単独のLookより悪化する条件もある。共通部品を重複させない設計が重要であり、任意のスキルを足せば機能が加算されるという一般的な保証はない。

### 5. 文章の変形と攻撃に対する頑健性

スキル文書の言い換え、Markdown書式除去、節の並び替え、雑音追加という4種類の変形を評価した。ALFWorldでは文脈内スキルに対する優位が17.2～24.3ポイントで維持される一方、LatentSkill自身の平均成功率は基準74.3%から、言い換え67.9%、順序変更69.3%、雑音71.4%へ低下する。頑健性の改善と、変形による絶対性能の低下は同時に存在する。

命令乗っ取り（Hijack）攻撃では、文脈内スキルのALFWorld成功率が52.9%から8.57%へ低下し、LatentSkillは38.6%を維持した。ただしLatentSkillも通常条件の74.3%から大きく低下しており、攻撃を完全に防ぐ方式ではない。抽出（Extract）攻撃ではスキル文章が直接プロンプトへ存在しないことにより露出を減らすが、重み空間からの情報抽出が原理的に不可能になると証明したわけではない。

## 既存方式との差と実装上の評価

文脈内スキル方式は手順を自然言語のまま与えるため更新が容易だが、毎ステップの入力が長くなる。全重み微調整や共有LoRAは繰り返し投入を減らす一方、個別スキルの更新と合成が難しい。スキル別LoRAはモジュール性を保つが、スキル数に比例して独立した学習が必要になる。LatentSkillは共通の生成器で任意のスキルからLoRAを作るため、事前に生成した重みをキャッシュして、同じスキルを複数回使う場合の文章再投入を避けられる。

推論エンジンの観点では、必要な実装は「スキルID→LoRA重み」のキャッシュと、要求ごとのLoRA装着・切替である。これはマルチLoRAサービングやアダプターの動的読み込みと概念上は近い。ただし論文はvLLM、SGLang、llama.cppなどの具体的ランタイムへの組込み速度、同時実行時のアダプター切替負荷、GPUメモリ占有を測定していない。スキルの種類が多い場合、LoRAキャッシュが大きくなり、スキル生成・転送・選択の費用が追加される。トークン削減と実機の処理能力向上を区別する必要がある。

## 限界と未検証事項

第一に、推論時のスキル文章を省略するために、事前に約3億トークンの文書学習と737本の教師軌跡を使っている。超ネットワークの訓練にはH100を8枚使う。事前学習費用を含む総所有費用や、スキルの利用回数に対する損益分岐は論文で算定していない。新しいスキルを一度しか使わない環境では、生成器とLoRA管理の固定費が得られる節約を上回る可能性がある。

第二に、実測した費用は主にトークン数である。LoRA適用による追加行列演算、生成器の実行時間、スキルキャッシュのGPUメモリ、複数利用者のスキル切替を含むエンドツーエンド遅延やスループットは提示されていない。63.9%の事前充填トークン削減を63.9%の実時間短縮と書くことはできない。

第三に、評価は正しいスキルが選択された条件に限定されている。実際のエージェントは検索器が誤ったスキルを選んだり、複数スキルの内容が矛盾したりする。スキルの選択誤り、スキルライブラリの大規模化、未知の道具仕様への追従、長期運用中のスキル更新は主要表の範囲外である。スキル合成も意味部品を適切に分解した場合に限り有効で、直接加算では性能が下がる。

第四に、成功率の改善は平均値の話であり、Search-QAのBamboogleや一部ALFWorldカテゴリでは文脈内スキルより悪い。注入係数αを大きくすると成功率が急落する条件もある。したがってスキル生成器が常に基盤モデルの性能を向上させるわけではなく、タスク別のα調整と品質監視が必要である。

第五に、スキル文章をプロンプトから外すことは、自然言語としての直接露出を減らすが、モデル重みや生成器からの情報復元を完全に防ぐセキュリティ保証ではない。攻撃下での絶対性能も低下している。研究の安全性実験を実運用での完全な情報秘匿性の証拠として扱わない。
