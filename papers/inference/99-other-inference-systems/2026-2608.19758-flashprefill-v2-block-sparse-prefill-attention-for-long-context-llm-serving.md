# FlashPrefill V2: Block-Sparse Prefill Attention for Long-Context LLM Serving

> 平均補正付きブロック疎注意をHopper向けに再設計し、SGLangの長文事前充填を128Kで最大4.8倍高速化する。
## 書誌情報
- **著者**: Qihang Fan, Huaibo Huang, Zhiying Wu, Bingning Wang, Ran He
- **著者・所属**: MAIS&NLPR, CASIA／UCAS／WeChat, Tencent
- **公開**: arXiv:2608.19758v1
- **種別**: preprint
- **対象**: 長文コンテキスト推論、疎注意、事前充填高速化、GPUカーネル、LLMサービング
- **実装**: 著者実装を公開。CUTLASS/CuTeを用いたHopper向け疎注意カーネルとSGLang向け注意バックエンドを論文中で説明している。
## 概要
長文コンテキストの事前充填で支配的になる二次計算量の注意機構を、訓練不要のブロック疎注意へ置き換えつつ、極端な疎性で失われる確率質量を平均補正で近似的に回復する実用化研究である。従来版の精度劣化、Hopper世代でのカーネル効率不足、ページ化KVキャッシュと連続バッチへの非対応を同時に扱い、疎性選択、Hopper向け実行、SGLang統合までを一つの事前充填経路として実装する。NVIDIA H20上では128K文脈で注意演算子がFlashAttention-2比27.19倍（BF16）・47.26倍（FP8）に達し、SGLangの初回トークン時間も最大3.4倍・4.8倍短縮した一方、復号は密注意へ戻り、短文脈や小さいチャンクでは索引作成費用により利得が縮む。

本研究の新規性は、重要ブロックを正確に計算する疎注意経路に、捨てた各ブロックの平均キー・平均値を用いるゼロ次の平均補正を同じオンラインソフトマックス内で注入し、極端な疎性でも確率質量を近似的に回復する点にある。さらに、その近似を単独のアルゴリズム提案で終わらせず、グループ化クエリ注意向けのPackGQA配置、HopperのTMAとwgmmaを使う生産者・消費者分離、行列積とソフトマックスのピンポン重畳、FP8、圧縮疎行列形式の索引、ページ化KVキャッシュ、可変長・連続バッチを一体化した実装へ落としている。

代表結果として、128K注意演算子速度はQwen3-30B-A3B-Instruct-2507、NVIDIA H20、128K文脈でFlashAttention-2に対して27.19倍（BF16）、47.26倍（FP8）。保持密度が約4.9%まで下がる長文域では、索引作成と平均補正を含めても疎注意の計算削減が大きく勝つ。
## 問題設定
長文コンテキストの事前充填では自己注意の計算量が系列長の二乗で増え、長さが数万〜十数万トークンになると初回トークン時間の主要なボトルネックになる。訓練不要の疎注意は重要ブロックだけを計算することで演算量を減らせるが、従来法は上位k件や累積確率に基づく選択自体が重い場合があり、疎性を強めると捨てたブロックのソフトマックス確率質量が無視できず精度が崩れる。さらに従来のFlashPrefillはFlashAttention-2型の同期的な実行モデルと連続KV配置を前提とし、Hopper世代の非同期転送・行列積機構や、現代のサービングで一般的なページ化KVキャッシュと連続バッチへそのまま接続できない。このため、アルゴリズム上の疎性が高くても実運用の待ち時間短縮へ直結しないという問題が残る。
## 新規性
本研究の新規性は、重要ブロックを正確に計算する疎注意経路に、捨てた各ブロックの平均キー・平均値を用いるゼロ次の平均補正を同じオンラインソフトマックス内で注入し、極端な疎性でも確率質量を近似的に回復する点にある。さらに、その近似を単独のアルゴリズム提案で終わらせず、グループ化クエリ注意向けのPackGQA配置、HopperのTMAとwgmmaを使う生産者・消費者分離、行列積とソフトマックスのピンポン重畳、FP8、圧縮疎行列形式の索引、ページ化KVキャッシュ、可変長・連続バッチを一体化した実装へ落としている。
## 手法
### 手法のあらまし
処理は各注意層で二段階に分かれる。第1段階ではクエリをグループ化クエリ注意のKVヘッド単位に詰め替え、各KVブロックの平均キー・平均値を計算する。平均キーに対するブロック得点を一回の融合行列積で求め、各クエリタイル内の最大得点に係数αを掛けた局所しきい値以上のブロックを選ぶ。先頭のシンク領域、局所窓、因果対角付近は必ず残し、選択結果はKVヘッド単位の圧縮疎行列形式の索引へその場で圧縮する。

第2段階では選択ブロックをHopper向けのワープ特化カーネルで正確に計算し、選ばれなかった完全可視ブロックは平均キー・平均値とブロック長を用いる代理項として同じオンラインソフトマックスの分子・分母へ加える。平均補正はブロック長の対数を得点へ加えることで、一つの平均ベクトルがブロック内全トークンを代表する。実行側では一つの生産者ワープグループがTMAまたはcp.asyncでK/Vを共有メモリへ非同期搬送し、二つの消費者ワープグループがwgmmaを実行する。QK行列積、次ブロックのPV行列積、現在ブロックのオンラインソフトマックスをピンポン方式で重ねる。FP8ではe4m3の動的範囲を使い切る確率スケーリングとレジスタ内配置変換を行い、ページ表と可変長スケジューラを介してSGLangのページ化KVキャッシュと連続バッチへ接続する。

### 平均補正
選択されたブロックは通常どおりトークン単位で正確に計算し、捨てたブロックについては平均キーと平均値から一つの代理ソフトマックス寄与を作る。ブロック長を得点へ反映して分子と分母の双方へ加えるため、単純に捨てる場合に生じるゼロ次の確率質量欠落を打ち消せる。

誤差展開では質量側が二次精度となり、値側にはブロック内の得点偏差と値の共分散に由来する一次項が残る。最大値基準のしきい値が捨てた各ブロックの質量比を抑え、ブロック内分散が小さい条件では残差も小さくなる。補正は別カーネルを起動せず、既存のオンラインソフトマックス主ループへ追加反復として融合される。

### Hopper向け疎注意カーネル
PackGQAで同じKVヘッドを共有する複数のクエリヘッドを同一タイルへ詰め、同じKVブロックの重複読み込みを避ける。生産者と消費者をワープグループ単位で分離し、TMAまたはcp.asyncによる搬送とwgmmaによる行列積を非同期化する。さらにQK行列積、PV行列積、オンラインソフトマックスをピンポンで重ねる。

選択ブロックは圧縮疎行列形式の索引を逆順走査し、分割時には位置範囲ではなく選択ブロック数で均等分割するため、疎性が不均一な末尾タイルの直列化を抑える。FP8ではレジスタ内の並べ替えや共有メモリ内転置を使い、追加の大域メモリ転送を避ける。

### ページ化・連続バッチ統合
K/Vの物理アドレスをページ表から実行時に解決し、各要求のクエリ長と既存KV長から可変長の仕事単位を生成する。索引はSGLangで扱えるKVヘッド単位の圧縮疎行列形式で、前向き計算ごとのメタデータは一度だけ構築して全層で共有する。

事前充填では二段階の疎注意経路を使う一方、1トークンずつの復号ではブロック選択の余地がないため密なFA3/4系注意へ戻す。この境界を明示したことで、疎注意が有効な長文事前充填だけを置換し、既存サーバのモデル定義・KV配置・スケジューラを変更せず導入できる。

### 全体のデータ／制御の流れ
固定タイルはクエリ128行・キー64列、論理選択ブロックは128トークン。既定設定はシンク256トークン、局所窓512トークン、しきい値係数α=0.1で、三つの評価モデルすべてに同じ設定を使う。

索引段階と平均補正はブロックごとに平均ベクトル一つを処理するため密注意よりブロック長分だけ軽い。保持密度4%、ブロック長128では補助演算量は疎注意本体のおよそ19%以下と見積もられ、実測でも高疎性域で補正の絶対追加時間は数ミリ秒に留まる。
## 評価条件
- **ハードウェア**: 演算子単体はNVIDIA H20 GPU 1基で測定。サービングはH20を4基用い、テンソル並列4・データ並列なしのSGLangサーバ1インスタンスで測定する。
- **ソフトウェア**: CUDA 12.9、ドライバ535.161.08、PyTorch 2.9.1、CUTLASS 4.3、SGLang 0.5.10。復号側の注意バックエンドは全構成でFA3/4系密注意に固定する。
- **比較対象**: Full Attention、MInference、FlexPrefill、XAttention、FlashPrefill、FlashAttention-2、FA3/4-aligned dense カーネル、HPC-Ops BSA
RULERとLongBenchをLlama-3.1-8B-Instruct、Qwen3-4B-Instruct-2507、Qwen3-30B-A3B-Instruct-2507で評価する。比較対象は完全注意、MInference、FlexPrefill、XAttention、従来版FlashPrefill、FlashAttention-2、同じワープ特化実行基盤を持つFA3/4整合の密カーネル。全モデルでブロック長128、シンク256、局所窓512、α=0.1を共通使用し、モデル別調整はしない。演算子速度は4K〜128Kで測り、SGLangではバッチ1〜16の初回トークン時間を各条件30回反復する。さらに4K〜128Kの混合プロンプトをポアソン到着させる開ループ評価、8K・16Kのチャンク事前充填、平均補正除去、しきい値掃引、HPC-Opsの疎注意カーネルとの比較を行う。
実機上の長文事前充填とサービング評価であり、主要な速度主張はHopper世代のH20に限定される。精度評価は3モデルとRULER・LongBenchに限定され、復号は疎化していない。したがって他GPU世代、短文脈、長い思考生成など異なる分布への一般化は直接実証されていない。
## 主要結果
長文になるほど保持ブロック密度が下がり、疎注意の実効速度差が拡大する。128Kでは3モデルの密度が4.6〜4.9%まで低下し、BF16の注意演算子はFlashAttention-2比27倍超、FP8は47倍超となる。精度は完全注意から小幅に低下する近似法だが、平均補正によりRULER平均の差を1.1点以内、LongBench平均の差を0.9点以内に抑える。サービング全体では注意以外の計算も残るため演算子ほどの倍率にはならないが、128Kの初回トークン時間を最大3.4倍（BF16）・4.8倍（FP8）短縮する。

- 128K注意演算子速度 / 27.19倍（BF16）、47.26倍（FP8） (比較対象: FlashAttention-2; 条件: Qwen3-30B-A3B-Instruct-2507、NVIDIA H20、128K文脈) — 保持密度が約4.9%まで下がる長文域では、索引作成と平均補正を含めても疎注意の計算削減が大きく勝つ。

- 128K注意演算子速度 / 17.54倍（BF16）、30.49倍（FP8） (比較対象: FA3/4整合の密カーネル; 条件: NVIDIA H20、128K文脈) — 古い密カーネルとの差ではなく、同世代のHopper向け実行基盤と比較しても疎性そのものの利得が大きい。

- RULER平均精度差 / 完全注意との差1.1点以内 (比較対象: 完全注意; 条件: 3モデル、4K〜128K、BF16) — 極端な疎性でも平均補正により品質低下を小さく保つが、厳密一致ではなく近似である。

- LongBench平均 / 49.31、46.96、50.73 (比較対象: 各モデルで最強の比較疎注意は48.25、45.90、49.61; 条件: Llama-3.1-8B、Qwen3-4B、Qwen3-30B-A3Bの21タスク平均) — 検索系だけでなく要約や複数文書QAを含む幅広い長文タスクでも、比較した疎注意法の中で最高平均を得る。

- 128K初回トークン時間 / 最大3.40倍短縮（BF16）、4.83倍短縮（FP8） (比較対象: SGLangのFA3/4注意バックエンド; 条件: Qwen3-30B-A3B、バッチ16、H20×4、128K) — 注意演算子の高速化が連続バッチを含むサービング全体の待ち時間にも反映されるが、倍率は注意単体より小さい。

- 平均補正の効果 / 128K FP8で6.19点を回復 (比較対象: 平均補正なしのV2-FP8; 条件: Qwen3-4B、RULER、128K) — 量子化で得点差が圧縮されると捨てたブロックの確率質量が無視しにくくなり、平均補正の寄与が特に大きい。

### 負の結果・境界条件
- 短文脈では利得が小さい。4Kでは密度が約70%残るためBF16のSGLang全体速度はFA3/4比1.01〜1.09倍に留まり、索引段階の費用が注意削減を相殺する。チャンク事前充填では各チャンクで索引選択を再実行し必須末尾ブロックの割合も増えるため、16 req/sのQwen3-30B-A3BでBF16のP50初回トークン時間短縮がチャンクなし約2.2倍から8Kチャンクで1.2倍へ低下する。復号は1クエリトークンずつでブロック選択余地がないため密注意へフォールバックする。

### 結果の読み方
速度向上が系列長とともに増える主因は、固定しきい値と必須局所領域の組合せにより、文脈が長くなるほど全ブロックに対する選択割合が急減することにある。128Kでは密度が約5%となり、Hopper向け非同期実行とFP8がその疎性を実時間短縮へ変換する。一方、平均補正と索引作成はブロックごとに残るため、短文脈や小さいチャンクでは固定費の割合が上がる。開ループでは事前充填短縮が同時復号の遮断時間も減らすため、初回トークン時間だけでなくトークン間時間と要求スループットも改善する。
## 品質への影響
完全注意と数学的に等価な損失なし手法ではない。選択ブロック外を平均統計で近似するため品質差が残る。RULERではBF16平均差を1.1点以内、128K最大差を1.8点以内に抑える一方、FP8では追加で0.4〜1.2点低下する。平均補正を外すと128K FP8でさらに6.19点落ちるため、極端な疎性と量子化を同時に使う場合の品質維持には補正が重要である。
## 既存研究との差
従来版FlashPrefillは瞬時のパターン探索と最大値基準しきい値で選択費用を抑えたが、強い疎化で捨てた確率質量を補償せず、FlashAttention-2型カーネルと連続KV配置に依存した。V2は平均補正で精度劣化を抑え、FA3/4系のHopper向け非同期パイプラインへ疎走査を移植し、FP8・ページ化KV・可変長・連続バッチまで対応する。MInference、FlexPrefill、XAttentionなどの訓練不要疎注意と比べても、選択規則だけでなく実運用カーネルとサーバ統合を主題に含む。HPC-Opsの疎注意カーネルに対しては、KVヘッド単位の圧縮索引、数均等分割、融合平均補正、BF16対応を加え、64K FP8で6〜7%低いカーネル待ち時間を報告する。
## 限界
評価GPUはNVIDIA H20に集中しており、A100やH100、Blackwellなど別世代で同じ倍率が得られるとは示していない。精度評価もLlama-3.1-8BとQwen3系2モデル、RULERとLongBenchに限られ、ブロック内の得点偏差と値の共分散が大きい分布や長い思考生成で平均補正が同程度に機能する保証はない。復号段階は疎化せず密注意へ戻るため、生成側が支配的な負荷では効果が限定される。チャンク事前充填では選択をチャンクごとにやり直すため利得が低下し、8Kより16Kの方が有利である。平均補正は誤差境界の議論を持つが厳密な完全注意ではなく、極端な分布に対する普遍的な品質保証ではない。
## 実装状態
著者の公式GitHub実装が公開されている。論文ではCUTLASS/CuTeベースのHopper向けカーネル、FP8経路、ページ化KVアドレス、SGLang注意バックエンド統合まで実装・評価済みとされる。実証環境はCUDA 12.9、PyTorch 2.9.1、CUTLASS 4.3、SGLang 0.5.10である。
## 研究上の位置づけ
訓練不要の動的疎注意と高性能LLMサービングの境界を埋めるシステム研究として位置付けられる。特に、疎注意研究でありがちな理論演算量や単体カーネルだけの改善ではなく、捨てたソフトマックス質量の品質補償、Hopperの実行機構、ページ化KVキャッシュ、連続バッチ、開ループ到着まで同じ設計を追跡している点が重要である。リポジトリ上では長文事前充填高速化、疎注意、SGLang/vLLM系サービング基盤の系統に接続し、KVオフロードや階層メモリとは直接競合せず補完的である。保持するKV自体をSSDやCPUへ移す手法ではなく、GPU上で実際に読む注意ブロックを減らすため、メモリ階層化と組み合わせた場合には転送要求量を減らせる可能性があるが、その組合せは本論文では評価していない。
