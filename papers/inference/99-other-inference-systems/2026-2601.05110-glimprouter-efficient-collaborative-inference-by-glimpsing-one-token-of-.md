# GlimpRouter: 思考ステップ冒頭の1トークンで大小モデルを振り分ける協調推論

## 概要

大規模推論モデルは長い思考過程を生成するため、回答までの待ち時間と計算費用が大きい。小型モデルに容易な処理を任せ、難しい部分だけ大型モデルを呼び出す協調推論は有望だが、**何をもって難しい思考ステップと判断するか**が問題になる。小型モデルが一つのステップを最後まで生成してから大型モデルで検証すると、検証が不合格だった場合はその生成計算が無駄になる。トークン単位で常時切り替えると、判定とモデル切替が頻繁になりやすい。

GlimpRouterは、思考ステップの**最初の1トークンの予測分布**に注目する。著者らは、思考の転換点で「Wait」「But」「So」などの表現が現れやすく、ステップ冒頭の不確実性がその後の推論の難しさを反映する可能性を検討した。小型モデルが次ステップの最初のトークンを予測し、その分布のエントロピーが低ければ小型モデルに残りを生成させ、高ければ大型モデルにステップ全体を任せる。追加のルータ学習を必要としない**プローブ後振分け（Probe-then-Dispatch）**が中心的な提案である。

A100-80GBとvLLMで実測した主要設定では、小型Qwen3-4Bと大型DeepSeek-R1-Distill-Qwen-32Bを使うAIME25で、大型モデル単独の正答率46.67%・平均遅延220秒に対し、GlimpRouterは51.67%・163秒を報告する。正答率の改善は**5.00ポイント、相対10.7%**であり、遅延は25.9%減である。さらに大型モデルが担当するステップの内部で投機的復号を使うと130秒になる。ただしこの数値は特定のモデル組合せ、評価問題、GPU環境での結果であり、単一GPUのローカル実行で同じ利得が出るとは限らない。

## 問題設定と設計上の発見

推論過程を $\mathcal T=\{s_1,\ldots,s_K\}$ というステップ列に分割する。各ステップは複数のトークンからなり、問題文と過去のステップを文脈として次のステップを生成する。GlimpRouterは、ステップ単位で生成担当モデルを選ぶ。問題文全体を小型モデルに任せるか大型モデルに任せるかという一回限りの振分けとは異なり、同じ回答の途中で小型・大型を交互に利用できる。

著者らはQwen3-4B、Qwen3-32B、DeepSeek-R1-Distill-Qwen-32Bの推論履歴をAIMEとLiveCodeBenchで調べ、合計1,000万トークンを超える思考ステップを解析した。ステップ全体の平均エントロピーや困惑度は比較的狭い単峰分布を示したが、最初のトークンのエントロピーは二峰性と裾の長い分布を示した。ステップ全体の平均を取ると、少数の重要な判断点が多数の定型的なトークンで薄まる可能性がある。

小型モデルと大型モデルへ同じ文脈を渡して生成させ、両者の出力の一致をBLEU-4とSBERTの意味的類似度で測ると、最初のトークンのエントロピーが高い区間ほど一致度が低下する傾向が見られた。これは小型モデルが大型モデルの代わりを務められるステップと、そうでないステップを冒頭の信号から区別できる可能性を示す。ただし**二つのモデルの出力が似ていることは、両者の回答が正しいことと同義ではない**。ルータはあくまで代理指標に基づく計算配分である。

## 手法

### 1. ステップ分割と冒頭1トークンのプローブ

大型モデルを $M_L$、小型モデルを $M_S$ とする。思考ステップの境界は二重改行などの明示的な区切りを使って認識する。ステップ $s_k$ を始める直前の文脈 $c_k$ には問題文とこれまでの思考が含まれる。ここで $M_S$ に次の1トークンだけの分布 $P_S(\cdot\mid c_k)$ を計算させ、$H_{init}=-\sum_{v\in V}P_S(v\mid c_k)\log P_S(v\mid c_k)$ というシャノンエントロピーを求める。

この1トークンは**難易度の観測用**であり、難しいと判断した場合は小型モデルが試したトークンを破棄して大型モデルへ処理を渡す。従来の「小型モデルに一つの思考ステップをすべて書かせ、後から大型モデルが検査する」方式と違い、破棄される生成は最初の1トークンに限定される。ステップの長さが何十〜何百トークンにもなる場合、事後検証より判定費用を小さくできる。ただし、エントロピー計算には語彙全体の分布が必要であり、単に出力された文字を見て判定するわけではない。

### 2. エントロピー閾値による委譲と介入

あらかじめ設定した閾値 $\tau$ と冒頭エントロピーを比較する。$H_{init}\leq\tau$ なら容易なステップと判断し、小型モデルがそのステップの残りを区切り記号まで生成する。$H_{init}>\tau$ なら難しいステップと判断し、大型モデルがそのステップを生成する。前者を委譲（Delegate）、後者を介入（Intervene）と呼ぶ。閾値を下げるほど大型モデルの担当割合が増え、品質が改善する可能性がある一方で計算費用も増える。

著者らは、思考の転換点では大型モデルが過去の誤った推論を修正する可能性があると説明する。小型モデルに簡単な部分を任せ、大型モデルには難しい判断と自己修正を担当させることで、単に大型モデルの呼出し回数を減らすだけでなく、推論の質も改善し得る。ただし**大型モデルが必ず過去の誤りを修正できるという保証はない**。評価で正答率が上がったことは、特定の問題集合で有効な分担が起きたことを示すものである。

最後の確定回答は常に大型モデルが生成する設計であり、小型モデルに最終出力まで任せる方式ではない。これにより、安価な途中生成と大型モデルによる最終的な回答形成を分離する。推論過程が二重改行などの構造を持つことを前提とするため、ステップ境界が不明瞭なモデルには直接適用しにくい。

### 3. モデル切替と接頭辞キャッシュ

ステップごとにモデルを切り替えると、過去の問題文と思考履歴を別モデルへ渡し直す必要がある。大型・小型の重みが異なるため、**片方のモデルで計算したKVキャッシュをそのままもう片方のモデルのKVとして共有できるわけではない**。著者らは推論エンジンの接頭辞キャッシュ（Prefix Caching）を利用し、各モデルが以前処理した共通接頭辞を再利用することで、文脈の再入力費用を抑える。

この仕組みが効くには、二つのモデルを効率よく呼び出せること、各モデルの過去の接頭辞がキャッシュに残ること、推論エンジンが接頭辞の再利用を支援することが必要になる。キャッシュが追い出された場合やモデルの切替ごとに長い新規文脈を再計算する場合は、振分けの利益が減る。特にメモリの限られたGPUでは、32B級と4B級を同時に常駐させる容量・転送費用が支配的になり得る。

### 4. 投機的復号との階層的な併用

GlimpRouterの制御単位は**思考ステップ**であり、投機的復号の制御単位は**個々のトークン**である。両者は異なる場所の無駄を減らすため、組み合わせられる。容易なステップは小型モデルだけで生成し、難しいステップは大型モデルへ渡す。大型モデルが担当するステップ内では、小型モデルをドラフト役としてトークン候補を3個先読みし、大型モデルがまとめて検証する。これにより、ステップ単位で大型モデルを使う頻度を減らしつつ、使う場合のトークン生成も高速化する。

この併用は単純に二つの倍率を掛ければよいわけではない。投機的復号にはドラフト生成・検証費用と受理率の影響があり、GlimpRouter側にはモデル切替と1トークンのプローブ費用がある。著者の表3は、併用後の**端から端までの平均遅延**を直接測定しているため、単独の最適化倍率を掛け合わせる推測より信頼できる比較となる。

## 主要結果

### 大型モデル単独と協調推論の比較

| 大型モデル | 評価 | 大型単独 正答率 / 遅延 | GlimpRouter 正答率 / 遅延 | 解釈 |
|---|---|---|---|---|
| DeepSeek-32B | AIME24 | 57.50% / 197秒 | **60.83% / 143秒** | 正答率+3.33点、遅延27.4%減 |
| DeepSeek-32B | AIME25 | 46.67% / 220秒 | **51.67% / 163秒** | 正答率+5.00点、遅延25.9%減 |
| DeepSeek-32B | GPQA | 61.62% / 176秒 | **64.02% / 129秒** | 正答率+2.40点、遅延26.7%減 |
| DeepSeek-32B | LiveCodeBench v5 | 52.40% / 219秒 | **54.64% / 160秒** | 正答率+2.24点、遅延26.9%減 |
| DeepSeek-32B | LiveCodeBench v6 | 46.86% / 214秒 | **48.29% / 160秒** | 正答率+1.43点、遅延25.2%減 |
| Qwen3-32B | AIME25 | 48.33% / 231秒 | **51.67% / 147秒** | 正答率+3.34点、遅延36.4%減 |

小型モデル単独はAIME25で45.00%・105秒であり、協調推論の51.67%・163秒より速い。しかし小型モデルだけでは難問の正答率が低いため、GlimpRouterは**最速性ではなく、正答率と遅延の交換条件**を改善する方式である。比較する基準が小型モデル単独か大型モデル単独かで「何%高速化」の意味が変わる。

AIME25での「10.7%精度向上」は、46.67%から51.67%への**相対改善率**であり、10.7パーセントポイントの増加ではない。またDeepSeek-32BのAIME25では163秒である一方、Qwen3-32Bを大型モデルにした場合は147秒となる。異なる大型モデルの数値を混ぜて単一の設定として報告しない。

### 既存の協調方式との比較

| DeepSeek-32B + Qwen3-4B、AIME25 | 正答率 | 平均遅延 |
|---|---:|---:|
| 大型モデル単独 | 46.67% | 220秒 |
| 無作為振分け | 48.33% | 147秒 |
| RSD | 45.83% | 171秒 |
| SpecCoT | 50.00% | 175秒 |
| SpecReason | 49.17% | 169秒 |
| **GlimpRouter** | **51.67%** | **163秒** |

無作為振分けの147秒はGlimpRouterより速いが、正答率は48.33%と低い。したがって「すべての比較方式より絶対に遅延が短い」という主張は成り立たない。GlimpRouterの利点は、同じ程度の品質を保とうとする方式より少ない待ち時間で動くことにある。SpecReasonは小型モデルが一つのステップを作った後で大型モデルが検証するため、生成済みの計算が不合格時に無駄になる。GlimpRouterは最初の1トークンで判断するため、事後検証の費用を回避できる。

### 重要度信号の構成要素除去

| AIME25、DeepSeek-32B + Qwen3-4B | 正答率 | 平均遅延 |
|---|---:|---:|
| **冒頭トークンのエントロピー** | **51.67%** | **163秒** |
| ステップ全体の平均エントロピー | 46.67% | 178秒 |
| ステップ全体の困惑度 | 47.50% | 181秒 |

冒頭エントロピーは、ステップ全体を生成してから測る二つの方式より、正答率と遅延の双方で良好だった。平均エントロピー方式との正答率差は5.00ポイント、相対10.7%である。これは**大型モデル単独との相対10.7%改善とは別の比較**であり、偶然同じ相対率となっている。平均エントロピーや困惑度ではステップ全体を先に生成する必要があるため、難しいと判定した時点でその生成が無駄になる。

### 投機的復号との併用

| AIME25の方式 | 正答率 | 平均遅延 |
|---|---:|---:|
| 大型モデル単独 | 46.67% | 220秒 |
| 大型モデル + 投機的復号 | 45.83% | 149秒 |
| GlimpRouter | 51.67% | 163秒 |
| **GlimpRouter + 投機的復号** | **51.67%** | **130秒** |

| LiveCodeBench v6の方式 | 正答率 | 平均遅延 |
|---|---:|---:|
| 大型モデル単独 | 46.86% | 214秒 |
| 大型モデル + 投機的復号 | 46.29% | 166秒 |
| GlimpRouter | 48.29% | 160秒 |
| **GlimpRouter + 投機的復号** | **48.00%** | **137秒** |

AIME25では協調推論単独163秒から投機的復号併用130秒へさらに短縮する。大型モデル単独220秒から見ると約40.9%減である。LiveCodeBench v6でも160→137秒だが、正答率は48.29%から48.00%へわずかに下がる。**投機的復号は常に正答率を完全維持するわけではない**。比較表の結果を正しく読み、推論ステップ単位の振分けとトークン単位の先読みが異なる最適化層であることを確認する必要がある。

### 閾値とモデルの組合せ

介入率は、ステップのうち大型モデルが担当する割合である。閾値を変えると介入率が変化し、品質と遅延の間で動作点が移る。著者の主結果は、大型モデルへの介入率が概ね20〜30%となるように調整した設定である。つまり、**どの入力でも20%のステップを大型モデルが処理する固定規則ではない**。冒頭エントロピーの分布が変われば、同じ閾値でも介入率が変わる。

小型モデルを1.5Bへ変更する追加実験もあり、異なる規模の組合せへ拡張できることを示す。ただし、両モデルが同じトークナイザや推論形式を持つ場合と、異なる形式を持つ場合では、思考履歴の引渡し費用が異なり得る。著者が示す良好な交換条件は、選んだQwen/DeepSeek系の構成における結果である。

## 既存研究との差

質問単位の振分けは、一度小型モデルを選んだら難しい途中ステップで大型モデルへ切り替えにくい。トークン単位の投機的復号は、大型モデルによる候補検証を繰り返すことで高速化するが、**どの思考ステップに大型モデルの能力が必要か**を直接判断しない。事後検証型のステップ単位協調では、先に小型モデルが書いた長いステップを大型モデルが評価するため、無効なドラフトの計算が大きくなる。

GlimpRouterは「思考ステップ冒頭のエントロピー」という1トークンの信号で、ステップ全体の計算担当を決める。小型モデルに任せられるときは大型モデルの生成を完全に避け、難しいときだけ大型モデルの自己修正能力を使う。さらに大型モデルの担当ステップ内部では投機的復号を使えるため、**ステップ粒度の計算割当とトークン粒度の復号高速化を分離して組み合わせられる**。

重要なのは、提案方式がモデルの重みを再学習する必要がない点である。追加の学習済みルータや報酬モデルを必要とせず、既存の小型モデルが計算する予測分布を利用する。ただし閾値調整、二つのモデルの運用、接頭辞キャッシュ、思考ステップの構造化というシステム上の条件があるため、**学習不要＝導入費用ゼロ**ではない。

## 限界・適用上の注意

著者が明示する第一の限界は、全問題に同じエントロピー閾値を使うことである。数学、一般推論、コード生成ではステップ冒頭の語彙分布が異なり、同じ閾値が同じ難しさを表すとは限らない。入力や領域に応じた閾値の自動調整は今後の課題である。高エントロピーが常に難問を意味するわけでもなく、単に表現の選択肢が多いだけの場合もある。

第二に、思考ステップの境界を二重改行などの明示的な区切りに依存している。モデルが連続した文章で推論したり、区切りの規則が異なったりする場合は、最初の1トークンが意味のある思考ステップの冒頭と一致しない可能性がある。意味的な分割器を導入すれば追加の計算や誤判定が発生し得る。

第三に、複数モデル間のキャッシュ再利用には実装条件がある。モデルの重みが異なればKVテンソルは直接共有できないため、各モデルが以前見た文脈の接頭辞を保持して再利用することが重要となる。長い新規文脈で毎回再計算が必要な場合、切替コストが大きくなり得る。モデルを複数常駐させるGPUメモリ費用や、別GPU間の通信費用を含めた総所有コストの検証も必要である。

第四に、実測遅延はA100-80GBとvLLMの環境で測られた。RTX 4070 Super 12GBなど、32B級モデルをGPUに常駐できずCPU/RAMへオフロードする環境では、重み転送が律速になり、同じモデル切替を頻繁に行うことがむしろ不利になる可能性がある。論文の220→163秒という値を、そのままローカル環境での秒数や改善率として予測することはできない。

第五に、正答率の改善が自己修正によるものか、モデル切替に伴うサンプリング分布の変化によるものかを完全に切り分けるのは難しい。AIME25の51.67%は4回平均の実験値であり、すべての問題分布で再現する保証はない。小型モデルのエントロピーは、そのモデルが見ている次トークン分布の不確実性であって、推論の客観的難易度そのものではない。
