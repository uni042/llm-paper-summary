# Cost-Optimal GQA：長文脈を前提にattention head数とモデル規模を同時設計する

## 概要

Grouped-Query Attention（GQA）は複数のquery headでKey/Valueを共有し、通常のMulti-Head Attention（MHA）よりKVキャッシュ容量と読み出し量を抑える。ただし一般的なモデルは、query head数とhead次元の積を隠れ次元に固定し、KV head数も既存モデルの慣行に沿って決める。**Cost-Optimal Grouped-Query Attention**は、この慣行が長文脈推論において必ずしも費用最小でないと指摘し、モデル規模、query head数、KV head数を**想定する推論文脈長と目標言語モデル損失**に合わせて共同設計する。

長文脈では、重み行列に対する計算のように文脈長に依存しない費用と、attentionスコア計算・KVキャッシュのように文脈長とともに増える費用の比率が変化する。短文脈ではモデルを大きくする方が損失改善に有利な場合があるが、長文脈ではattention head数を減らして文脈依存の計算を節約し、浮いた資源をFFNやモデル規模へ配分する方が、同じ損失に対して総費用が小さくなる場合がある。

原著の代表比較は、**query/KV head=(32,8)の1.2Bモデル**と、**(8,1)の1.8Bモデル**である。128K文脈・NVIDIA A800・batch1での推論処理率は12,921から20,643 tokens/sへ改善し、常識推論8課題平均は45.7%と45.5%で近い。一方、NIAHの128K精度は5.2%と6.7%で、両方とも絶対値として低い。比較対象はLlama-3と同じGQA head構成で新たに学習したモデルであり、公開Llama-3の大規模チェックポイントとの直接比較ではない。

## 問題設定：重み費用と文脈依存費用の配分

通常のGQAは、query head数`n_h`、KV head数`n_kv`、head次元`d_h`、層数`L`、隠れ次元`d`で構成される。`n_kv<n_h`なら複数query headが同じKVを共有する。GQAによってKVの保持数を減らせても、query head数が大きいままなら、queryとkeyのスコア計算・value加重和に必要な演算が残る。

多くのTransformer実装は`n_h * d_h = d`を採用する。この等式は扱いやすいが、attention側の演算量をモデル幅dと結び付ける。原著は、attention出力射影があるため、head総次元と隠れ次元を常に一致させる必要はないと考え、この制約を外す。`n_h`を独立のハイパーパラメータにすれば、FFN等のモデル規模を維持または増加させながら、長文脈のattention演算量を削減できる。

目標は、単にモデルのパラメータ数を最小にすることではない。ある目標損失`L*`を満たすモデルの中から、**期待する文脈長Tでの推論メモリとFLOPsを最小にする構成**を選ぶ。品質を固定して比較しないと、小さいhead数で損失が大きく悪化したモデルが、単に安いという理由で選ばれてしまう。

## 手法

### 1. 推論費用を四つに分解する

原著§3は、モデルパラメータ数N、層数L、head次元d_h、query head数n_h、KV head数n_kv、文脈長Tを用い、推論の一トークン当たりFLOPsを概ね次式で表す。

`C_infer(T) ≈ 2N + 4 T L d_h n_h`

前半`2N`は重み行列の計算に対応する文脈長非依存の費用、後半は過去T個のkey/valueへ注意を計算する文脈長依存の費用である。後半はTとn_hに比例する。モデル規模Nを増やしてもn_hを大きく削れば、長いTでは総FLOPsを減らせる可能性がある。

同様に、保存するパラメータとKVの要素数に基づくメモリ費用は、概ね次式で表す。

`M_infer(T) ≈ N + 2 T L d_h n_kv`

前半はモデル重み、後半はKVキャッシュであり、後半はTとn_kvに比例する。ここでのMは要素数に基づく簡略式であり、実バイト数へ換算するには重み・KVの精度を考慮する必要がある。GPUカーネルの作業領域、通信バッファ、ランタイムの断片化などは含まれない。

この二式から、`n_h`は主に文脈依存のattention FLOPs、`n_kv`は主に文脈依存のKVメモリ、Nは主に固定の重み費用を制御すると理解できる。もちろん実際にはquery/KV射影のパラメータもhead数によって変わるため、完全に独立した三つのノブではない。原著の費用分解は設計空間を理解するための近似である。

### 2. 目標損失を満たす構成の最適化

原著§4は、目標損失`L*`に対し、`(N, n_h, n_kv)`を変えた候補の中から推論費用Zを最小にする問題を定式化する。Zはメモリ費用とFLOPs費用を重み付きで組み合わせる。メモリ重視か演算重視かを表す重みλ、スケールを調整する指数α、βを含むため、**唯一の絶対最適GQAが存在するという主張ではない**。最適解はT、L*、λ、モデル系列に依存する。

全てのhead数・モデル規模・学習条件を総当たりで訓練すると費用が高い。そこで著者らは、まず小規模な構成群を訓練して損失のスケーリング関係を測定し、構成ごとの損失とNの関係を回帰し、目標損失を満たす最小Nを推定したうえで、費用式から最良構成を選ぶ三段階の探索を提案する。これにより、全候補を完全に学習して比較する必要を減らす。

重要なのは、推定された損失曲線が対象のモデル規模と学習条件で十分に当てはまることである。実際の品質が推定曲線から外れれば、選んだ構成が目標損失を満たさない可能性がある。原著は推定の有効性を実験範囲で検証するが、全ての大規模モデルや学習データに対する普遍的なスケーリング則ではない。

### 3. head数を減らしモデル規模へ再配分する

原著の探索では、想定Tが長いほど、同じ目標損失の下で`n_h`と`n_kv`を少なくする構成が選ばれやすい。head数の削減は文脈依存の演算・KV費用を減らし、その代わりモデル規模Nを大きくして損失を維持する。これは単純な量子化や剪定とは異なり、**最初からモデルアーキテクチャを再設計して訓練する**方法である。

このため、公開済みのLlama-3チェックポイントに対してhead数の設定値だけを書き換えれば同じ性能が得られるわけではない。head数が変われば重み行列の形状と学習済みの表現が変わり、原著の性能を得るには適切な訓練が必要となる。既存チェックポイントを無再学習で変換する技術ではない点は実務上重要である。

## 評価

### 実験設定と比較の公平性

原著の探索は最大1.2Bパラメータ程度の複数GQA構成で損失曲線を調べ、代表的な実機比較では1.2BのLlama-3型head構成と1.8Bの最適化構成を訓練する。比較に用いるLlama-3型とは**head数がLlama-3の設計と同じ**という意味であり、公開Llama-3の訓練済み重みや訓練量を使用したものではない。

代表的なモデルはまず4K文脈で20Bトークンを訓練し、続いて128K文脈で1Bトークンの継続訓練を行う。推論速度はNVIDIA A800 1台、batch size 1、文脈長128Kで測定した。品質は8種類の常識推論タスク平均と、文脈長を変えたNIAHで比較する。原著の別実験では、モデル間の学習FLOPsを揃えて学習データ量を変える条件もあり、これを同一トークン数訓練の比較と混同してはいけない。

### 1. 長文脈ほど最適head数が減る

原著Table 4は、期待文脈長Tと目標損失に応じて最適な`(n_h, n_kv)`が変わることを示す。例として目標損失2.7では、T=8Kで`(32,4)`、16Kで`(16,2)`、32K/64Kで`(16,1)`、128Kで`(8,1)`が選ばれる。目標損失2.5では8Kで`(32,16)`、16Kで`(16,8)`、32Kで`(16,4)`、64Kで`(16,2)`、128Kで`(16,2)`となる。目標損失を厳しくすると、品質を保つためにhead数を増やす必要がある。

これらは原著のモデル系列・費用関数・学習設定に基づく探索結果であり、別のTransformerやMoE、MLAへそのまま移植できる定数表ではない。想定Tを変えれば最適構成が変わるという傾向と、具体的なhead数の推奨を分けて読む必要がある。

### 2. A800でのbatch1 throughputと品質

原著Table 5の代表結果を示す。

| 指標 | Llama-3型GQA (32,8)、1.2B | 最適化GQA (8,1)、1.8B |
|---|---:|---:|
| 学習throughput（tokens/s） | 18,655 | **31,260** |
| 推論throughput（tokens/s） | 12,921 | **20,643** |
| 常識推論8課題平均 | **45.7%** | 45.5% |
| NIAH 1–8K | 90.9% | **96.9%** |
| NIAH 16K | 30.4% | **46.0%** |
| NIAH 32K | 15.1% | **18.7%** |
| NIAH 64K | 6.1% | **7.9%** |
| NIAH 128K | 5.2% | **6.7%** |

推論throughputの比は20,643/12,921≒**1.60倍**である。これは128K文脈・batch1・A800で測定された値であり、多数同時要求を扱うサーバーの総TPSや、RTX 4070 Super等の小容量GPUでの速度を保証するものではない。学習throughputも約1.68倍であるが、モデル構成・学習条件の比較であり、通常のdecode TPSとは異なる。

常識推論平均は45.7%と45.5%でほぼ同じであり、著者らは目標損失を維持したうえで効率を改善したと評価する。しかしNIAHの絶対値を見ると、32Kを超える文脈で両モデルとも成功率が低い。128Kでは最適化構成の6.7%が比較対象の5.2%より高くても、実用的な長文脈検索性能を達成したという意味ではない。**相対的な改善と絶対的な品質水準を分ける**ことが不可欠である。

### 3. モデル規模が大きくても速くなる条件

最適化構成は1.8Bであり、比較対象1.2Bより重みパラメータ数が多い。にもかかわらず長文脈のthroughputが高いのは、head数削減によりTに比例するattention費用を大きく下げたためである。文脈が短ければ2Nに対応する固定費が相対的に大きくなるため、必ずしも同じ優位が続くとは限らない。これは、モデルのパラメータ数だけで長文脈推論費用を予測するのが不十分であることを示す具体例である。

### 4. 学習FLOPsを揃えた場合

原著§5.6は、比較する構成の学習トークン数を単純に揃えるのではなく、**総学習FLOPsを揃える**別条件を検討する。計算効率の良い構成にはより多くの学習データを与えられるため、head数の少ない構成の優位がさらに大きくなる。図4では、同じ損失に対してメモリ88%、FLOPs83%の削減が示される。

この88%・83%は学習費用を揃えた別条件での理論的・モデル比較の値であり、代表のA800 batch1 throughput 1.60倍と同一の測定ではない。また、図のメモリ・FLOPsは原著の費用モデルに基づく比較であり、実機のピークVRAMと消費電力が同じ割合で下がったという意味ではない。

### 5. head数の品質感度

原著§5.4は1.2Bモデルを使い、query head数とKV head数の増加が言語モデル損失に与える影響を調べる。両者とも増加による損失改善には逓減があり、同程度のパラメータ増加ならquery head数の増加の方がKV head数の増加より損失を改善しやすいと報告する。KV headを増やすと保持表現は増えるが、文脈長に比例するメモリも増える。query head数を増やすと表現力が増える一方、attention計算費用が増える。最適化はこの品質と費用の感度差を利用する。

## 主要結果の解釈

本研究の貢献は、新しいattentionカーネルを単体で高速化したことではなく、**モデルを訓練する前に想定文脈長を設計変数としてGQA構造を決める**方法を示したことである。既存モデルを圧縮してKVを減らす手法とは異なり、モデルの容量を維持・増加させながらattention側の冗長性を減らす。長文脈のモデル設計では、パラメータ数とKV容量と演算量の三つを一体で見積もる必要がある。

一方、目標損失は事前学習時の言語モデル損失であり、あらゆる下流タスクで同等の能力を保証するわけではない。原著のNIAH長文脈スコアが低いことは、lossを合わせただけで長文脈の正確な検索能力が保証されないことを示す。特に長文脈検索を主要用途とする場合、損失だけでなくNIAH、LongBench、RULERなどの用途別制約を設計目的へ追加する必要がある。

## 既存研究との差

通常のMHAはquery headごとに独立したKVを保持し、GQAは複数query headでKVを共有することでメモリを削減する。MQAはKV headを一つまで減らした極端な構成である。これらはhead構成の候補を与えるが、**どの文脈長と品質目標でどの構成が費用最小か**を一般に決定するものではない。原著は、`n_h * d_h = d`の制約を外し、モデル規模も含めて費用最小化する探索を導入する。

KV量子化、KV eviction、CPUオフロード、疎注意などは既存のチェックポイントへ後付けしてメモリや帯域を減らす方法であり、本研究の訓練前アーキテクチャ探索とは適用時点が異なる。設計上は直交し得るが、最適化GQAへ追加のKV圧縮やオフロードを適用した場合の品質と速度は個別に再測定する必要がある。モデルを最初から訓練できない利用者にとっては、既存モデルのKV管理最適化の方が実装可能性は高い。

## 限界・負の結果・再現性

**第一に、公開済みLlama-3を直接高速化した結果ではない。** 「Llama-3 GQA」はhead構成(32,8)を採用した独自訓練モデルであり、公開Llama-3チェックポイントと学習データ・パラメータ数・訓練計算量を揃えた直接比較ではない。公開済みの7B/70Bモデルへhead数の設定だけを変更して適用できる方式ではない。

**第二に、モデル規模の検証は限定的である。** 原著の損失曲線は主に最大1.2B、代表の最適化構成は1.8Bである。70B級、MoE、MLA、長文脈に特化した大規模モデルへの外挿は未検証である。原著もhead次元、語彙数、モデルの幅と深さの比率など全ハイパーパラメータの網羅的ablationを行っていないと述べる。

**第三に、最適性は費用関数と想定文脈長に依存する。** λや費用の重み付け、ハードウェアの演算・メモリ帯域比、バッチサイズ、KV精度、通信費、期待文脈長分布が変われば最適head数も変わる。理論的なFLOPs削減がそのまま実測TPS改善になるとは限らない。A800・batch1・128Kの結果を一般化しすぎない。

**第四に、長文脈品質は十分ではない。** 最適化構成は128KのNIAHで6.7%であり、比較対象5.2%より高くても絶対水準は低い。lossが同程度という事実は、長い入力からの情報検索や複数証拠推論の成功を保証しない。長文脈の品質要件を明示的に課した探索が必要である。

**第五に、学習費用の扱いが複数ある。** 同一トークン数での比較と、総学習FLOPsを揃えた比較では、モデルに与えるデータ量が異なる。後者の88%メモリ・83%FLOPs削減は代表のthroughput実測とは別条件であり、数字を一つの比較表へ無条件に混ぜない。

**第六に、実行時メモリは費用式より複雑である。** `N + 2TLd_h n_kv`はモデル重みとKVの要素数を表す近似であり、重み・KVのビット幅、カーネルのワークスペース、通信バッファ、バッチング、ページ管理、GPUメモリ断片化を直接表現しない。量子化やオフロードと組み合わせた最適性は追加検証を要する。
