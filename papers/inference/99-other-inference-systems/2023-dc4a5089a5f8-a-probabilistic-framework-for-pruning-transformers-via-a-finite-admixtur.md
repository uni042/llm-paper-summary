# A Probabilistic Framework for Pruning Transformers Via a Finite Admixture of Keys

## 概要

本研究は、Transformerの自己注意を確率的な混合モデルとして解釈し、**学習可能なkeyの事前重み**を使って冗長な注意スコアとkey/valueを枝刈りする方式「Finite Admixture of Keys（FiAK）」を提案する。通常の自己注意では、queryとkeyの内積をsoftmaxへ通して各queryがどのkeyを参照するか決める。著者らは、この注意重みが特定の仮定の下でガウス混合モデルの事後確率に一致することを利用し、queryごとに異なる混合重みを学習する。混合重みが小さい注意エッジや、全queryからの重みの合計が小さいkey/valueを除去し、残ったモデルを微調整する。

DeiT-tinyのImageNet分類では、密な基準のTop-1 72.23%に対し、注意スコアの60%を削減したFiAKは73.67%を報告する。注意スコア70%削減時でも73.09%で、推論FLOPsはモデル全体で8.50%減る。key/valueも20%削る混合枝刈りでは、モデル全体のFLOPs削減が13.00%、Top-1は72.25%となる。WikiText-103の単語単位言語モデルでは、密なTransformerのPPL 34.29に対し、注意スコア50%削減で34.28とほぼ同等である。

ただし、対象は2023年の比較的小さなTransformerであり、数十億パラメータの現代LLMを同じ設定で高速化した結果ではない。注意スコア70%削減がモデル全体のFLOPs70%削減を意味するわけでもない。推論基盤へ適用する場合は、枝刈りマスクの格納形式、疎行列カーネルの実効速度、因果注意との整合、長いコンテキストでのkey/value削除の不可逆性を別途評価する必要がある。

## 問題設定：注意行列とkey/valueの冗長性

通常の自己注意は、系列長`N`の入力からquery行列`Q`、key行列`K`、value行列`V`を作り、`A = softmax(QK^T / √D)`で注意行列を計算する。出力は`AV`である。`A`は`N×N`の行列なので、密な実装では注意スコアの計算が系列長の二乗に比例し、注意行列を明示的に保持する方式ではメモリも大きくなる。FlashAttentionのように行列を全量保存しない実装でも、どのqueryがどのkeyを参照するかという計算そのものは残る。

多くの注意ヘッドやkeyの寄与は重複している。特定のkeyがほとんど参照されないなら、関連する注意スコアを計算せずに済む可能性がある。特定のqueryとkeyの組が不要なら、そのエッジだけを削る方法も考えられる。しかし、注意スコアの絶対値だけで重要性を決めると、入力や層の違いによる分布の変化を十分に捉えられない。key全体の平均注意だけを用いると、特定のqueryにだけ重要なkeyを見落とす可能性もある。

本研究は、注意スコアを「queryがどのkeyを生成元とするかの事後確率」と見なし、その前に存在する事前重みを学習する。事前重みを明示的な重要度指標にすることで、注意エッジ単位とkey/value単位の二種類の削減を一つの枠組みで扱う。

## 手法

### 1. softmax注意とガウス混合モデルの関係

query`q_i`が、key`k_j`を中心とする等方ガウス分布から生成されたと考える。keyごとの事前確率を`π_j`、ガウス分散を`σ_j²`とすると、Bayes則で`p(j|q_i)`を計算できる。queryとkeyを正規化し、各keyの事前確率が一様で、分散が共通という条件を置くと、二乗距離の項のうち共通部分が相殺され、事後確率は`softmax(q_i^T k_j / σ²)`になる。

`σ² = √D`と選べば、標準Transformerのscaled dot-product attentionと一致する。この対応は、**正規化・一様事前・共通分散という条件の下での数学的な等価性**である。一般の未正規化query/keyや非一様な事前重みで、通常の注意スコアが無条件に同じガウス混合の事後確率になるわけではない。著者らはこの条件付き対応を出発点として、事前重みを学習可能にする。

### 2. 単一混合からqueryごとの混合へ

通常の有限混合モデルでは、すべてのqueryが同じ混合比率`π_j`を共有する。FiAKでは、query`q_i`ごとに異なる混合係数`π_ij`を使い、`p(q_i) = Σ_j π_ij N(q_i | k_j, σ_j² I)`と表す。混合の中心となるkey集合は共有する一方、各queryがどのkeyを重要視するかは異なる。この「共通の成分、queryごとの混合比率」が有限admixtureの特徴である。

事前係数は、注意スコアの最終値とは異なる学習可能なパラメータである。学習時にモデルへ組み込み、queryとkeyの対応の重要度を表すように最適化する。注意エッジの重要度には`|π_ij|`、key全体の重要度にはquery方向に集約した`S(j) = Σ_i |π_ij|`を使う。確率の定義では非負だが、枝刈りアルゴリズムは学習した係数の絶対値を順位付けに用いると記述するため、実装ではパラメータ化と制約条件の確認が必要である。

### 3. 注意スコア枝刈り（Algorithm 1）

注意スコア枝刈りは、全てのquery-key組の中から事前係数の小さいものを一定割合削除する。手順は、(1) 注意層へ追加の`π_ij`を導入、(2) モデルを収束まで学習、(3) `|π_ij|`が小さい注意エッジを所定割合だけ削除、(4) 残った係数を一様事前に対応する1へ戻し、枝刈り済みモデルを追加微調整、という流れである。

最後に係数を1へ戻す点が重要である。学習中の事前係数は重要度を見つけるために利用するが、最終推論では追加パラメータをそのまま保持する必要がない設計になっている。つまり、事前係数の学習費用と推論時の枝刈り効果を分離している。ただし、注意エッジの疎性が不規則な場合、GPUでの実効高速化は疎行列演算やマスク実装に依存する。

### 4. key/valueの混合枝刈り（Algorithm 2）

注意エッジだけでなく、key/valueそのものを削除すると、後段の関連計算と記憶も減らせる。FiAKの混合枝刈りでは、各keyに対して`S(j)=Σ_i |π_ij|`を計算し、値の小さいkey/value組を所定割合だけ削る。自己回帰タスクでは、keyの位置によって参照可能なquery数が異なるため、`1/(N−j+1)`で正規化したスコアも提示される。古いkeyほど参照される機会が多いという位置上の不均衡を調整する意図である。

次に、残存する注意エッジからさらに小さい事前係数を持つものを削除する。論文はkey/value削減率`k₂`と全体の注意エッジ削減率`k₁`を調整し、残存エッジに適用する追加削減率を計算する。key/valueを削ると、そのkeyを参照する全エッジが既に消えるため、エッジ削減を単純に二重計上してはいけない。最終的には残存係数を1に戻し、追加微調整する。

この方式は、枝刈り対象が単なる注意スコアの積和にとどまらず、keyとvalueの格納・生成へ及ぶ点で、注意エッジだけの枝刈りより大きなメモリ節約余地がある。ただし、長文脈LLMのKVキャッシュで同じ規則を使う場合、将来の質問に必要なkeyを過去の統計から誤って消す危険がある。論文が検証した小規模モデルでの枝刈りを、そのままオンラインのKVキャッシュ追い出しアルゴリズムと同一視しない。

### 5. GMM事前によるkey枝刈り（Algorithm 3）

比較対象として、queryごとに異なる事前係数を使わない通常のガウス混合モデルでも、keyごとの事前係数`π_j`を学習してkey/valueを枝刈りできる。これは単一の重要度をすべてのqueryで共有するため、query別の注意パターンの多様性を表現しにくい。FiAKの有効性は、単に「確率的に枝刈りする」ことではなく、queryごとに異なる事前係数を学習することで、key集合を共有しながら参照パターンを多様化できる点にある。

## 評価

### 評価条件とモデル

画像分類ではImageNetを使用し、DeiT-tinyを基準とした。モデルは12層、各層4注意ヘッド、埋め込み次元192である。比較には元のDeiT-tiny、GMMformer、FiAKformer、注意エッジのみの枝刈り、key/valueと注意エッジの混合枝刈りを用いる。さらにhead pruning、S²ViTEとのFLOPs削減率とTop-1精度を比較した。

言語モデルではWikiText-103の単語単位言語モデリングを使用し、テスト困惑度（PPL）を報告する。評価対象は大規模LLMではなく、比較的古い小規模Transformerである。数十億パラメータのモデル、長いコンテキスト、複数GPUのサービング、生成トークン毎秒などの実験はこの論文の範囲外である。

### ImageNet分類精度（原著Table 1）

| 方式 | Top-1精度 | Top-5精度 |
|---|---:|---:|
| 密なDeiT-tiny | 72.23% | 91.13% |
| GMMformer | 72.96% | 91.64% |
| GMMによるkey 30%枝刈り | 71.57% | 90.80% |
| 密なFiAKformer | 73.50% | 91.90% |
| FiAK注意エッジ50%枝刈り | 73.56% | 91.95% |
| FiAK注意エッジ60%枝刈り | **73.67%** | 91.91% |
| FiAK注意エッジ70%枝刈り | 73.09% | 91.57% |
| FiAK混合枝刈り：エッジ70%、key15% | 72.78% | 91.38% |
| FiAK混合枝刈り：エッジ70%、key20% | 72.25% | 91.14% |

注意エッジ60%枝刈りでは、密なDeiT-tinyよりTop-1が1.44ポイント高い。注意エッジ70%枝刈りでも0.86ポイント高い。一方、混合枝刈りでkey/valueも20%削るとTop-1は72.25%まで下がり、基準との差は0.02ポイントに縮まる。削除対象を注意エッジからkey/valueへ拡張すると、記憶と計算の節約余地は増えるが、品質を維持する難しさも増すことを示す。

密なFiAKformer自身が基準の72.23%より高い73.50%を示している点にも注意が必要である。枝刈り後の改善のすべてを「枝刈り操作だけ」の効果と解釈することはできず、学習可能な事前係数を導入したモデル表現と学習過程の影響が含まれる。密なFiAKformerと注意エッジ60%枝刈りの差は0.17ポイントであり、基準との差1.44ポイントとは異なる比較である。

### 演算量と実測処理量（原著Table 2・本文）

| 方式 | モデル全体のFLOPs削減 | Top-1精度 |
|---|---:|---:|
| 密なDeiT-tiny | 0% | 72.23% |
| Head pruning | 23.69% | 68.59% |
| S²ViTE | 23.69% | 70.12% |
| FiAK注意エッジ70%枝刈り | 8.50% | 73.09% |
| FiAK混合枝刈り（エッジ70%、key20%） | 13.00% | 72.25% |
| FiAK混合枝刈り＋S²ViTE | 22.76% | 72.24% |

注意エッジの70%を削除しても、モデル全体のFLOPs削減率は8.50%である。これは、注意エッジの計算以外に線形射影やFFNなどの演算が残るためであり、「70%枝刈りで推論が70%高速化」という解釈は誤りである。混合枝刈りでは13.00%に増え、S²ViTEとの組合せでは22.76%となるが、後者はFiAK単独の削減率ではない。

実測の画像処理スループットについて、密なDeiT-tinyとFiAK注意エッジ70%枝刈りを比較し、GPUでは508から649画像/秒、CPUでは76から95画像/秒へ増加したと報告する。これはGPUで約1.28倍、CPUで1.25倍である。ただし使用したGPU・CPUの詳細や推論バッチの全条件を本稿の抜粋から一意に復元できないため、別環境への性能外挿には使わない。画像/秒は言語生成のtokens/sではない。

### WikiText-103の言語モデリング（原著Table 3）

| 方式 | テストPPL（小さいほど良い） |
|---|---:|
| 密なsoftmax Transformer | 34.29 |
| 密なFiAKformer | **33.69** |
| FiAK注意エッジ40%枝刈り | 33.88 |
| FiAK注意エッジ50%枝刈り | 34.28 |
| FiAK混合枝刈り（エッジ40%、key10%） | 34.21 |

FiAK注意エッジ50%枝刈りのPPL 34.28は基準34.29とほぼ同等であり、混合枝刈りでも34.21である。密なFiAKformerの33.69からは悪化するため、枝刈りの効果は「元のTransformer基準に近い品質を保って計算を減らす」ことであり、密なFiAKformerより常に高精度という意味ではない。

WikiText-103は単語単位言語モデルであり、現代の指示追従LLMや長文脈のneedle retrievalとはタスク特性が異なる。PPLがほぼ同じでも、長距離依存、固有名詞の再現、コード生成、数学的推論などの品質が同じと保証されない。KVキャッシュの容量やデコードの実測遅延もこの表からは分からない。

## 既存研究との違い

Head pruningは注意ヘッド全体を削るため、演算量を比較的大きく減らせるが、特定のヘッドが担う機能も失う。トークン枝刈りは系列要素を削るため、後段の全演算を減らせる一方、必要な情報を取り戻せない危険がある。FiAKの注意エッジ枝刈りは、トークンやヘッドを丸ごと消す前に、query-keyの結び付き単位で不要な計算を選ぶ。混合枝刈りではさらにkey/valueを削り、演算量とメモリを減らす。

FiAKは学習した事前係数を重要度に使い、枝刈り後に係数を一様へ戻して微調整する。この意味で、推論時に毎トークン動的に重要度を再計算するオンラインのKVキャッシュ圧縮とは異なる。モデルの構造とマスクを学習・枝刈りで決める方式であり、推論時の即時的な要求適応を主眼としない。注意エッジの疎性を実機で高速に処理できるかは、モデル構造とは別のシステム課題である。

## 限界・再現性・運用上の注意

第一に、FiAKの確率的解釈は、query/keyの正規化、等方ガウス、共通分散などの仮定に依存する。数学的な類似性は有用だが、任意のTransformerの学習済み注意重みを、無条件で混合モデルの事後確率と解釈できるわけではない。混合係数の学習に追加の計算とパラメータが必要で、枝刈り後の微調整も不可欠である。

第二に、注意エッジ削減率とモデル全体のFLOPs削減率は異なる。疎性が不規則な場合、メモリ転送やインデックス処理が支配的になり、理論FLOPsの削減がそのまま実測レイテンシへ反映されない。著者らはDeiT-tinyで画像/秒の改善を報告するが、長いコンテキストの自己回帰デコードを複数GPUで行う条件は検証していない。

第三に、画像分類のDeiT-tinyとWikiText-103の比較から、現代LLMの量子化済み推論・KVキャッシュ・RoPE・GQA・FlashAttention・PagedAttentionへの互換性を推定することはできない。特に、query-keyペアの固定的な事前係数を学習する設計は、系列長が変動する自己回帰生成や未知の長文脈へそのまま拡張できるとは限らない。オンラインで変わる重要度を使うなら追加の設計が必要になる。

第四に、キーを削るとそのキーを参照するすべての注意エッジと値の情報を失う。学習時の平均重要度が低いキーでも、まれな問い合わせでは決定的に重要な可能性がある。混合枝刈りの精度が注意エッジのみの枝刈りより低くなる条件は、この不可逆性を示唆する。モデルの安全性や知識の保持を評価するには、平均PPLやImageNet Top-1以外のタスク別検証が必要である。

第五に、原著は5ページの会議論文であり、各実験のハードウェア・バッチ・訓練スケジュールの詳細を本文だけからすべて復元するのは難しい。公式コードを参照し、モデル構造・追加係数の制約・マスク適用・微調整手順・疎行列実装を確認することが再現性の条件になる。

## 推論・学習サーベイへの位置づけ

FiAKは、大規模LLMに直接適用できる完成したKVキャッシュ管理システムというより、**注意の冗長性を確率的な事前重要度で学習し、エッジとkey/valueの二段階で削る**設計を示す基礎研究である。現在の高性能推論基盤では、FlashAttentionやPagedAttentionが密な計算とメモリ配置を高度に最適化しているため、FiAKの不規則な疎性がどこまで実機で得になるかは別問題である。

一方、事前係数からquery別・key別の重要度を得る考え方は、長文脈推論でのKV選別、head別のキャッシュ予算、トークン重要度の学習などと比較する価値がある。重要度の推定と実際のキャッシュ削除を分け、削除したキーを後で再取得できるか、計算と通信のどちらが律速かを考えることで、現代の階層メモリ・オフロード研究との違いが明確になる。
