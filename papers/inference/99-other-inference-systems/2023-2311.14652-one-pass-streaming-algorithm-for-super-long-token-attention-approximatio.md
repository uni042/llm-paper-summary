# 超長系列の注意出力を劣線形作業空間で近似する一回走査アルゴリズム

## 概要

長大な文脈を扱う注意機構では、問い合わせ、鍵、値の各行列から計算される注意重みが系列長に伴って大きくなる。注意重み行列を直接保持すれば二次の領域を消費するため、非常に長い系列を一度だけ読みながら処理する場面には向かない。従来の多項式特徴による高速注意近似は、指数核を低ランク因子に分解して計算量を削減する一方、因子の全行を保存すると系列長に比例する作業領域が必要になる。

Addankiらは、入力行列を順に読み捨てる過程で必要な情報を圧縮統計へ加算し、最後に列ごとの疎な注意出力を復元する方式を提案する。中心となる構成は、値行列の線形スケッチ、鍵側特徴の線形スケッチ、正規化済み問い合わせ特徴の疎復元用スケッチである。いずれも元の長さnの行列を丸ごと保存しない。

主結果は実験的な高速化ではなく、厳密な入力条件の下での確率的な誤差・空間・復元時間の保証である。特徴次元dがO(log n)で、入力値と値行列のノルムに制約があり、出力列が疎に近似できるとき、作業領域はO(ε₁⁻¹kn^{o(1)}+ε₂⁻²n^{o(1)})に抑えられる。成功確率は少なくとも0.99である。重要な例外として、同じ入力から問い合わせと鍵・値を作る自己注意では二回の走査を要すると原著が明記している。これは一般的な因果的な自己回帰生成へそのまま組み込めるという主張ではない。

## 問題設定：計算時間と作業領域を区別する

入力は問い合わせQ、鍵K、値Vというそれぞれn行d列の行列である。注意の非正規化行列をA=exp(QKᵀ/d)、各行の総和を対角に置く行列をD=diag(A1)とし、求める出力をY=D⁻¹AVと定義する。ここで指数関数は行列の各要素に適用する。Aはn行n列なので、これを明示的に作れば二次の記憶領域が必要になる。通常のGPUカーネルがAを全量保持しない場合もあるが、それだけでは長いKとVの保持や再読の問題が解消するわけではない。

先行する多項式近似はAをU₁U₂ᵀで近似する。U₁とU₂はそれぞれn行t列で、t=n^{o(1)}の幅を持つ。これにより計算時間をn^{1+o(1)}程度に近づける見通しが得られるが、U₁、U₂を全行保存すれば依然としてnに比例する作業領域が残る。著者らの問いは、注意出力を近似する際に、入力を一度ずつ走査し、作業空間をo(n)にできるかというものである。

本研究でいう「作業空間」は、逐次計算の間に保持する統計や補助状態を指す。最終出力Y自体は形式上n行d列だが、アルゴリズムは各列をO(k)個の非零要素を持つ疎ベクトルとして返す。密なn行d列の結果をメモリへ展開して保持する費用まで消えたという意味ではない。加えて、復元誤差は最良のk疎近似からの距離を基準とする。元の出力が密で、疎な近似自体が悪ければ、保証が成立しても実用上の誤差は大きくなり得る。

## 手法：入力を読み捨てるための三種の圧縮統計

### 多項式特徴の役割と正規化の順序

まず既存の多項式近似により、問い合わせの各行からU₁の対応行、鍵の各行からU₂の対応行を計算する。近似注意行列を明示せず、低ランクの積を通して正規化済み注意出力を扱う。この近似は指数核を置き換えるためのものであり、圧縮統計による誤差とは独立した近似誤差を持つ。

正規化係数を求めるには、鍵側特徴の列方向の総和s=U₂ᵀ1が必要になる。問い合わせのi行に対する近似正規化係数はU₁[i,:]とsの内積で得られる。したがって、鍵側の全行を先に処理してsを確定させ、その後に問い合わせ側を処理する順序が必要である。この依存関係が「任意の順番でQ、K、Vの行を混ぜて読み込める」という誤解を防ぐ重要な点になる。

### 値と鍵側特徴の線形スケッチ

アルゴリズム1は、まず値行列Vを一度走査してΨVを作る。Ψはm₂行n列の内積近似用写像であるが、巨大な密行列を明示的に保存する必要はなく、論文はハッシュ関数などによる簡潔な表現を用いる。各値行が届くたびに対応する写像の列と行の値の積を現在の統計へ加算し、元の行は破棄できる。

続いて鍵Kを一行ずつ読み、対応する多項式特徴U₂[i,:]を計算する。各行の特徴をΨU₂へ加算すると同時に、正規化のための総和sを更新する。走査終了後に保持するのはm₂行t列のΨU₂と長さtのsであり、n行t列のU₂全体ではない。ΨVもm₂行d列に圧縮される。これらの統計は後段の行列積に必要な情報を近似的に残すが、個々の過去トークンをそのまま復元するキャッシュではない。

### 問い合わせ特徴の正規化と疎復元用スケッチ

最後に問い合わせQを一行ずつ読み、U₁の対応行を計算する。先に確定したsとの内積からその行の正規化係数を求め、正規化した特徴をΦD⁻¹U₁へ加算する。Φはm₁行n列の疎復元用写像であり、m₁はO(ε₁⁻¹k log n)程度である。各入力行に対する写像の寄与だけを計算して加算できるため、正規化済みのU₁全体を保持しない。

三つの圧縮統計を結合してZ=(ΦD⁻¹U₁)(ΨU₂)ᵀ(ΨV)を計算する。Zの大きさはm₁行d列であり、系列長n行の行列を中間結果として再構成する必要はない。Zの各列を疎復元器へ入力し、元の注意出力の各列に対応するk疎近似を得る。疎復元器は最良のk疎ベクトルとの差を抑えるため、入力信号がそもそも疎に近いことが実用的な精度の鍵になる。

### 近似誤差の合成

誤差は少なくとも三つの経路から生じる。第一は指数核の多項式近似、第二はΨによる内積・行列積の近似、第三はΦからの疎復元である。原著は多項式近似の誤差をnの逆多項式程度に抑え、Ψの近似には値行列の作用素ノルム制約を使う。最後に疎復元の保証を三角不等式で合成し、列ごとの二乗ノルム誤差の上界を得る。

特にΨの近似については、個々の座標の誤差をε₂/√n以下に抑え、それをn座標で合成して列全体の二乗ノルム誤差ε₂を得る。単に「三つのスケッチを掛ければ正確な注意が再現される」のではなく、条件付きで近似誤差が制御される。疎復元の失敗確率と内積近似の失敗確率も合わせて評価する。

### 自己注意と交差注意の走査回数

原著第4.1節では、異なる入力から問い合わせQと鍵・値K、Vを構成する交差注意と、同じ入力から三者を構成する自己注意を区別する。自己注意では、正規化のために先に鍵側の全体統計を得た後、問い合わせ側をもう一度構成する必要があり、元入力の二回走査を要する。題名の一回走査を一般的な自己回帰モデルの全ての注意計算へ無条件に拡張することはできない。

## 評価：理論上の空間・精度・復元時間

### 評価対象と比較基準

本論文は実装済みGPUカーネルの速度比較ではなく、定理4.1および系4.2を中心とする理論解析である。実験表に相当するものは存在しないため、評価対象は入力仮定、使用する統計の次元、復元される出力の形式、近似誤差、成功確率、復元時間である。比較すべき基準も実測のトークン毎秒ではなく、注意行列を明示的に保持する二次空間、特徴因子を全行保持する場合の系列長依存、最良のk疎近似との差になる。

定理4.1はd=O(log n)、QとKの要素の最大絶対値がO(√log n)で抑えられ、Vの作用素ノルムが1/√n以下という仮定を置く。ε₁は疎復元の乗法的誤差、ε₂は内積近似などに伴う加算的誤差の精度を制御する。kは各出力列の非零成分数の目標であり、kを大きくすれば疎近似の表現力は上がるが、必要な統計の大きさも増える。精度を高めるためにε₁やε₂を小さくすると作業空間が増える点が、空間削減の代償である。

| 評価軸 | 前提・定理の結果 | 解釈上の注意 |
|---|---|---|
| 入力行列 | Q、K、Vはn×d、d=O(log n) | 任意の隠れ次元での保証ではない |
| 入力制約 | Q・Kの要素絶対値はO(√log n)、Vの作用素ノルムは1/√n以下 | 実モデルで自動成立する条件ではない |
| 特徴幅 | t=n^{o(1)} | 既存の多項式特徴近似に依存 |
| スケッチ幅 | m₁=O(ε₁⁻¹k log n)、m₂=O(ε₂⁻² log n) | kと精度に応じて増大 |
| 作業空間 | O(ε₁⁻¹kn^{o(1)}+ε₂⁻²n^{o(1)}) | nに劣線形となる条件付き漸近上界 |
| 出力形式 | 各列がO(k)疎 | 密な出力をそのまま保存しない |
| 近似誤差 | 最良k疎近似誤差の(1+ε₁)倍と加算O(ε₂) | 元の出力が密なら残差が残る |
| 成功確率 | 0.99以上 | 常に正確という保証ではない |
| 復元時間 | O(ε₁⁻¹kn^{o(1)}) | 実装上の実時間ではない |

### 理論結果の読み方と誤差保証

最良k疎近似誤差は、元の列ベクトルに最も近いk疎ベクトルを選んでも避けられない距離を意味する。定理の誤差はこの不可避な距離に(1+ε₁)を掛け、さらに加算項を足したものである。したがって元の注意出力列が密な場合、成功確率0.99の保証が成立していても生成モデルの品質に十分な精度を持つとは限らない。列別の二乗ノルム誤差を保証することと、各トークンの意味表現が維持されることも同義ではない。

作業空間の主要項は、問い合わせ側統計m₁tと鍵側統計m₂tに対応する。値側統計や補助ベクトルも必要だが、論文の漸近表現では主要項へまとめられる。特徴幅tがn^{o(1)}であるため、m₁とm₂の対数因子を含めて劣線形空間の上界が得られる。一方、疎性kが系列長に近いほど増えればこの上界の実用上の利点は失われる。小さなkを採用できる出力分布が重要な前提となる。

原著の証明は、多項式特徴による近似、Johnson–Lindenstrauss型の内積近似、疎復元の保証を順に組み合わせる。値行列の作用素ノルム制約から各列のノルムが1/√n以下となり、各座標でε₂/√n以下の誤差を得る。n個の座標の二乗和を取ることで列全体の誤差がε₂に抑えられる。最終的には近似行列積と疎復元の誤差を三角不等式で合成し、最良疎近似に対する相対誤差と加算誤差の上界へ到達する。

### 実機評価・感度分析が存在しないこと

本論文には、GPUの型番、トークン生成速度、初回トークン遅延、同時要求数、キャッシュ使用量の実測値、実モデルでの精度低下率を示す評価はない。従って「128Kトークンのモデルで何GB減った」「GPUで何倍高速化した」といった定量的な主張をこの論文から導くことはできない。実機の性能はスケッチ更新、疎復元、数値精度、入力順序、通信、出力の展開方式によって変わり得るが、それらの実装上の費用は測定されていない。

さらに、理論の精度パラメータを変えたときの生成品質、注意ヘッド間の差、層を重ねたときの誤差蓄積、文脈の検索能力への影響も報告されていない。証明された漸近上界は数学的に重要だが、通常のLLM推論基盤での有効性を直接示すものではない。システムへの適用可能性は、現実のモデルの注意出力が必要なkで十分疎に近似できるかを検証した後に評価すべきである。

## 既存研究との違い

多項式特徴を使う既存の高速注意近似は、指数核を低ランクの積へ置き換えることで計算量を抑える。しかし全ての特徴行を保持すれば、系列長に比例する作業領域が残る。提案方式は特徴因子そのものではなく、後の積と復元に必要な統計を逐次加算することで、この保存量を減らす。単に注意行列の二次領域を分割計算する方式とも、過去のKとVをページ管理する推論基盤とも異なる。

一方、GPUの注意カーネルや鍵値キャッシュの圧縮方式は、実際の推論速度やメモリ使用量を対象に最適化する。本研究は注意出力を数学的に疎復元する理論アルゴリズムであり、出力の分布や多層モデルでの生成品質まで実証したものではない。理論的な空間改善と、実機サービングの性能改善を区別する必要がある。

## 限界：適用可能性と未検証事項

最も大きな制約は、特徴次元と入力ノルムの仮定である。現実のLLMでd=O(log n)という漸近条件が意味のある範囲で成立するか、QとKの要素やVの作用素ノルムが定理の仮定を満たすかは、モデルごとの検証が必要となる。疎近似の対象となる出力列が密な場合には、最良のk疎近似誤差自体が大きくなる。

自己注意に二回走査を要する点も重要である。入力を一度しか読めないストリーミング環境では、鍵側の正規化情報を得た後に同じ入力を再走査することができない。因果マスクを伴う逐次復号、位置符号化、層ごとの鍵値保持、長距離情報の選択的再取得にどう組み込むかは、論文で解決されていない。

さらに、誤差保証は注意出力の各列についての二乗ノルムであり、生成される文章の正しさや長文検索の成功率に対する保証ではない。確率的な失敗可能性、疎復元の追加計算、GPUに適した並列化の有無、分散環境での通信費用、数値精度の影響も未評価である。したがって、現段階では推論基盤へ即時投入できる実装というより、極端な長系列における情報圧縮可能性の理論的な根拠として位置づけるのが適切である。
