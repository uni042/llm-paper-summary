# CORAL: Co-Evolutionary Optimization of Routing and Adaptive Prompts for Cost-Efficient LLM Deployment

> プロンプトとモデルの割当てを別々に最適化する従来法の限界を示し、プロンプト集団とルータ集団を多目的共進化で同時に育てることで、同一精度での推論コストを最大31.4パーセント削減した研究。

## 概要

大規模言語モデルを実運用すると、推論コストが運用費全体の6〜8割を占める。強いモデルへの1回の問い合わせは、70億パラメータ級のオープンなモデルへの問い合わせのおよそ50倍の価格が付くため、すべてのクエリを強いモデルへ送る運用は割に合わない。そこで、クエリの難しさを見て安いモデルで済ませる振り分け（ルーティング）と、クエリの書き方を変えて正解率を上げるプロンプト最適化という、二つの節約策が育ってきた。ただし前者はクエリの文面を固定したままモデルだけを選び、後者はモデルを固定したまま文面だけを変える。本論文の着眼点は、この分離が構造的に損だという点にある。段階的な推論を促すプロンプトを添えれば、本来は強いモデルが必要だったクエリが弱いモデルでも解けるようになる。逆に、強いモデル向けの最良のプロンプトは短く素直な文面であることが多い。つまり最良のプロンプトはモデルに依存し、最良のモデルはプロンプトに依存する。

著者らはこの結合をプロンプト・ルータ共進化問題（Prompt–Router Co-Evolutionary Problem; PRCP）として定式化し、独立に最適化しても共同空間の一部のパレート最適点には到達できないことを構成的に論証した。そのうえで、プロンプトの集団とルータの集団を二つ保持し、多目的進化アルゴリズム NSGA-II/III で同時に進化させる枠組み CORAL を提案する。ルータはモデルだけでなくプロンプト変種まで含めた組を選び、適応度は両集団の組合せに対して測られるため、プロンプトの改善がルータの判断境界を動かし、ルータの変化がプロンプトへの選択圧を変える。

評価は GPT-4o を強いモデル、Mistral-7B-Instruct-v0.3 を弱いモデル（vLLM で A100 一台に配信）とする二段構成で、MMLU、GSM8K、WildChat の三つのデータセットで行われた。**代表結果:** GSM8K では、精度をそろえた条件で RouteLLM 比31.4パーセントのコスト削減（正規化コスト NACU で0.548から0.376へ）、コストをそろえた条件（NACU=0.5）では RouteLLM の81.4パーセントに対して86.2パーセントと4.8ポイントの精度増、平均クエリ遅延は12.2パーセント減を記録した。MMLU でも同一精度で26.9パーセントのコスト削減があり、三データセット平均のパレート超体積（ハイパーボリューム）は RouteLLM の0.1249、プロンプト最適化と独立に組み合わせた方式の0.1379 に対して0.1842 と最も大きい。

## 問題設定

コストの支配要因は、クエリごとに支払うトークン価格である。本論文のコスト式は、入力トークン価格と入力トークン数の積に、出力トークン価格と出力トークン数の積を加えたものとして定義される。商用 API では出力トークンの単価が入力の数倍に設定されるため、冗長な出力を生む強いモデルの常用は特に割高になる。強いモデルと弱いモデルの価格差が約50倍ある状況では、難しいクエリだけを強いモデルへ送り、残りを弱いモデルで処理できれば、理論上の節約幅は大きい。

既存のルーティング方式（RouteLLM、Hybrid-LLM など）は、クエリの埋め込み表現などから「強いモデルが必要か」を分類し、文面は元のクエリのまま送る。既存のプロンプト最適化（EvoPrompt、OPRO、APE など）は、モデルを一つに固定し、そのモデルに対して最良の文面を探す。どちらの系譜も、もう一方の決定を固定値として扱うため、次の節約機会を構造的に取りこぼす。すなわち、元の文面では難しいと判定されるクエリでも、推論の足場になるプロンプトを付ければ弱いモデルの守備範囲に入る場合がある。固定プロンプトのルータはこのクエリを強いモデルへ送るしかなく、固定モデルのプロンプト最適化は強いモデル向けに文面を磨くため、弱いモデルを助ける文面の領域を探索しない。

本論文はこの主張を命題として整理する。弱いモデル向けの最良プロンプト集合と強いモデル向けの最良プロンプト集合が異なるとき、ルーティングとプロンプトを独立に最適化する系は、共同空間のパレート最適点のすべてを回復できない。弱いモデル向けのプロンプトは課題を分解し文脈を足して不足を補う方向に寄り、強いモデル向けのプロンプトは能力を引き出す簡潔な方向に寄るため、両集合がずれるのは例外ではなく通常の姿だというのが著者らの立場である。

## 手法のあらまし

CORAL はオフラインの最適化枠組みであり、運用時に重い探索は行わない。まず、プロンプト候補の集団（集団A）とルータ候補の集団（集団B）を用意する。各世代では訓練クエリのバッチを取り、各ルータにクエリを判定させて「モデルとプロンプト変種の組」を決め、そのプロンプトでクエリを組み立てて実際にモデルを呼び、精度・コスト・遅延の三つを測る。この三目的の値が両集団の全個体の適応度になり、NSGA-II（前線が増えたら NSGA-III へ切替え）で非支配ソートと選択を行う。集団内の突然変異と交叉に加えて、集団をまたぐ二つの演算子（プロンプト・ルータ交叉と、ルータ情報に基づくプロンプト剪定）が結合を強める。40世代回した後に残るパレート最適な方策集合から、運用者が予算と遅延の条件に合う動作点を選んで配備する。配備後の推論は、軽量な分類器を一度呼ぶこととプロンプト表を引くことだけで済む。

## 手法

### 1. プロンプト遺伝子プール — 文面・対象段・難易度署名の三つ組

集団Aは50個のプロンプト個体を保持する。各個体は、自然言語のテンプレート本文、対象とするモデルの段（弱い段・中間段・強い段）、難易度署名ベクトルという三つ組である。難易度署名は訓練データから学習した軽量な難易度分類の分布に対応し、そのプロンプトがどんなクエリで効くかを示す目印になる。初期集団は三種類で種付けされる。元のクエリそのままの恒等プロンプト、強いモデルに「段階的な推論の手引き付きで書き換えよ」と指示して生成した思考の連鎖（chain-of-thought）型の足場テンプレート群、そして「能力はあるがコストに敏感なモデル向けに簡潔に言い換えよ」と指示して生成した圧縮テンプレート群である。

進化の操作は三つある。第一に、大規模言語モデルを介した突然変異で、「明示的な推論手順を加える」「冗長な文脈を削る」「解いた例を加える」「小さいモデル向けに単純化する」といったランダムな変異指示に従って強いモデルがテンプレートを書き換える。第二に、対象段タグの付け替えで、プロンプトが想定外の段でも効くかを探索する。第三に、トーナメント選択で選んだ別親との交叉である。観測するのは訓練クエリに対する実際の正解・コストであり、保持する状態はテンプレートと段タグと署名の三つ組、選ぶのは生き残る文面である。これにより減るのは、弱いモデルが素のクエリでは解けないために強いモデルへ回されていたクエリの量である。追加で消費する資源は、突然変異のたびに強いモデルを呼ぶ費用であり、変異率は0.2と低めに抑えられている。変異を生むモデル自体が弱いと文面の質が落ち、最終的な超体積が下がることが実験で確認されている。

### 2. ルータ方策プール — モデルとプロンプトを同時に選ぶ分類器

集団Bは30個のルータ個体を保持する。各ルータは勾配ブースティング木による軽量な分類器で、凍結した text-embedding-3-small のクエリ埋め込みに、クエリ長、小さい言語モデルでのパープレキシティから見積もった複雑さ、ゼロショット分類による分野ラベル、数学やコードらしいトークンの有無という四つの手作り特徴を加えた入力を受ける。RouteLLM が強いか弱いかの二値を返すのに対し、CORAL のルータは（モデル識別子、プロンプト変種識別子）の組を返す。したがって判断空間はモデル数ではなく、モデル数と離散プロンプト数の積の大きさになる。ルータの個体は、木の分割を表す可変長ビット列、特徴の重み、品質スコアを離散出力へ写す閾値ベクトルで符号化される。

この機構が観測するのはクエリの埋め込みと四特徴であり、選択するのはモデルとプロンプトの組である。減るボトルネックは、強いモデルへの不要な送客と、それに伴うトークン支出である。追加費用は推論時の分類器呼び出し一度分で、実測上は無視できる水準とされる。誤判定時の挙動は非対称で、難しいクエリを弱いモデルへ誤送すると精度が落ち、易しいクエリを強いモデルへ誤送するとコストだけが増える。共進化の下では後者の誤りはコスト目的を通じて適応度を直接悪化させるため、ルータはプロンプト側の改善に追随して境界を引き直す圧力を受ける。

### 3. 共適応度評価 — 相手の集団の中で測る適応度

結合の核は適応度の測り方にある。各世代で訓練集合から64件のクエリバッチを標本し、集団Bの全ルータを全クエリへ適用して（モデル、プロンプト変種）の組を得る。選ばれたプロンプトテンプレートにクエリを差し込んで実入力を作り、モデルを実際に呼んで、正解率、価格で重み付けした正規化コスト（NACU、強いモデルだけを使う運用を1.0とする）、ミリ秒単位のエンドツーエンド遅延を測る。個体の適応度は、その個体が参加した組合せ全体での三目的の平均である。

この設計により、プロンプトの適応度はどのルータが自分へ送客するかに依存し、ルータの適応度はどのプロンプトがプールにあるかに依存する。どのルータにも選ばれないプロンプトは適応度ゼロとなり、世代交代で消えやすい。逆に、安いモデルで足りるクエリを高価なモデルへ送り続けるルータはコスト目的で不利になる。選択圧が双方向に流れることが、独立最適化との決定的な違いであり、除去実験でも結合を切る変種が最も大きく性能を落とした。

### 4. 集団間演算子 — 交叉と、見えないプロンプトの剪定

通常の共進化では集団内の演算だけを行い、集団同士は適応度評価を通じてのみ結ばれる。CORAL はさらに二つの集団間演算子を確率0.15で適用する。第一のプロンプト・ルータ交叉は、既存ルータの「いつ弱いモデルを使い、いつ強いモデルを使うか」という閾値を、プロンプトプールの難易度分布から導いた閾値へ置き換えて新しいルータを作る。これによりルータは、プールにどんなプロンプト戦略が存在するかを織り込んだ判断をするようになる。第二のルータ情報に基づくプロンプト剪定は、ルータが繰り返し誤送するプロンプト、すなわち実際の推論コストがルータの想定から大きく外れるプロンプトを「ルーティングから見えない」ものとして印付けし、難易度を示す構造的な手掛かり（難易度表示トークンの追加やクエリ複雑さの再構成）を加える専用の変異を掛ける。効く理由は、プロンプト側が自分の難易度をルータへ伝える信号を持つようになり、誤送そのものが減るためである。失敗条件として、集団間演算子の適用率を上げすぎると世代ごとの収束が遅くなることが感度分析で示され、0.15は改善が測れた最小値として選ばれている。

### 5. 多目的選択 — NSGA-II/III によるパレート保持

選択は NSGA-II を基本とし、非支配前線の数が三つを超えたら NSGA-III へ切り替える。親と子を合わせた2倍の集団を非支配ソートし、前線の順に次世代を埋め、最後の前線は混雑距離（NSGA-III では参照点への対応付け）で多様性を保ちながら選ぶ。集団規模はプロンプト50とルータ30の合計80、世代数は40で、超体積の曲線が35〜38世代で頭打ちになることから決められた。プロンプト側の変異率0.2は、モデル介在変異が高価であることと、低すぎると多様性が足りず高すぎると高適応度テンプレートが信号の伝播前に上書きされることの釣り合いで選ばれている。

|---|---|---|---|---|
| プロンプト遺伝子プール | 訓練クエリでの正解・コスト | テンプレート・対象段・難易度署名の三つ組を進化させ、モデル介在変異で書き換える | 弱いモデルでは解けないクエリの量 | 変異のたびに強いモデルの呼び出し費用が掛かる |

## 評価

結論は三点ある。第一に、プロンプトとルーティングの共進化は、両者を独立に最適化して後から組み合わせる方式を、精度・コスト・遅延の全軸で上回る。第二に、利得は構造化された推論課題で最も大きく、開領域の対話では小さい。第三に、共進化の結合そのものが利得の主因であり、部品の単なる足し合わせではないことが除去実験で裏付けられた。

評価条件は次のとおりである。強いモデルは OpenAI API 経由の GPT-4o（gpt-4o-2024-08-06）、弱いモデルは vLLM で A100 一台に配信した Mistral-7B-Instruct-v0.3 で、価格差は約50倍に設定された（GPT-4o は入力100万トークン2.50ドル・出力10.00ドル、Mistral-7B は A100 の時間貸し費用を実測スループットで割った償却コストとして100万トークン約0.05ドル）。MMLU はテスト14,042問と適応度評価用の開発2,000問、GSM8K は訓練7,473問とテスト1,319問、WildChat は実会話100万件から層化抽出した10,000件（易29パーセント、中41パーセント、難22パーセント、専門家級8パーセント）を使う。WildChat には正解がないため、強いモデルのみの運用に対する GPT-4o 判定者のペア勝率で測り、人手評価120組での照合も行われた（判定者と人手の一致率84.2パーセント、評価者間のカッパ係数0.71）。全結果は乱数シードを変えた5回の平均で、RouteLLM に対するペアブートストラップ検定で p<0.01、プロンプト最適化併用方式に対する対応のある t 検定で p<0.05 である。

数値の読み方として重要なのは、CORAL の優位が動作範囲の中央に集中する点である。MMLU のパレート曲線では、NACU が0.3〜0.6の中コスト域で差が最も開き、0.1未満の極端な低コスト域ではどの方式もほぼ全件を弱いモデルへ送るため差が縮み、0.9超では強いモデルが支配的でプロンプト差が効かなくなる。GSM8K で差が最大になるのは、思考の連鎖プロンプトが弱いモデルにとってのクエリ難易度を最も大きく変える課題だからであり、論文の理論的予測と一致する。遅延は方式間の相対比較として読むべきもので、GPT-4o 側はネットワーク往復を含み、Mistral-7B 側は含まないという測定条件の非対称が明記されている。

転移実験では、GPT-4o と Mistral-7B の組で育てたルータを、再学習なしで GPT-4o-mini と Llama-3.1-8B-Instruct の組へ載せ替えても優位が保たれた。進化させたプロンプトの難易度調整構造がモデル系列に依存しないためと著者らは解釈する。最適化自体のコストは、データセットあたり約2,800回のモデル呼び出しと14〜22ドル、単一 A100 と API の併用で3.5〜4時間であり、10万クエリ/日の運用規模では日額130〜280ドルの節約で数時間で回収できる計算である。変異用モデルを Llama-3.1-70B-Instruct へ替えると超体積は0.1841から0.1723へ約6.4パーセント下がるが、最適化費用は2〜4ドルまで下がる。

## 既存研究との差

RouteLLM や Hybrid-LLM などのルーティング研究は、クエリを不変の入力としてモデル選択だけを動かす研究であり、FrugalGPT のカスケードや Automix の格上げも、同じ元のクエリをそのまま次のモデルへ渡す。EvoPrompt や OPRO、APE などのプロンプト最適化は、モデルを固定して文面だけを動かす研究である。DSPy は複数モジュールのプロンプトを共同で最適化するが、どのモデルへ送るかは最適化変数に入っていない。本論文が追加したのは、プロンプトとモデル割当ての積空間そのものを一つの多目的問題（PRCP）として定式化し、適応度を相手集団との組合せで測る共適応度評価と、閾値の差し替えや難易度手掛かりの付与という集団間演算子によって、両決定が互いに応答して変わる仕組みである。実験上も、独立に最適化して後から組み合わせる方式（超体積0.1379）や、進化させずに学習したプロンプト選択器と組み合わせる方式では、共進化の到達点（0.1842）を回復できていない。

## 限界・実装状況

限界は著者ら自身が詳しく挙げている。第一に、オフライン最適化の費用は配備後の節約に比べて小さいとはいえ無視できず、1日1万クエリ未満の低トラフィック用途では回収に時間が掛かる。第二に、適応度評価に使う代表的な訓練分割が必要で、履歴クエリのないゼロショット配備では進化を始められない。第三に、プロンプト変異の質は変異用モデルの能力に依存し、弱いモデルを変異役にすると進化する文面の質が落ちる。第四に、本論文の検証は弱い段と強い段の二値ルーティングに限られ、三段への予備実験では性能が下がっている。第五に、WildChat の評価は GPT-4o 判定者に依存し、自己選好バイアスを人手照合だけでは消し切れていない。また、利得が小さい条件も明示されている。クエリがほぼ自明か真に難問かどちらかで中間の帯域が狭いワークロード、使えるモデルが一つしかない場合、強いモデルと弱いモデルの能力差が小さい場合、弱いモデルへの再試行すら許されない厳しい低遅延要件の場合である。実装状況として、配備時の追加負荷は分類器呼び出し一度とプロンプト表引きのみで、コードと進化ログは出版時に公開予定とされるが、本稿執筆時点で具体的な公開先 URL は論文中にない。

## 一般的な実装上の含意

推論基盤の節約策を設計する際、振り分けの判断材料はクエリそのものだけではない。同じクエリでも、どんな前処理（プロンプト変換）を施すかで必要なモデルの格が変わるため、ルータの入力には「利用可能なプロンプト戦略」も含める余地がある。逆に、プロンプトを自動生成・自動選択する仕組みを持つ基盤では、プロンプト側に自分の難易度を申告させる構造的な手掛かりを持たせると、振り分けの誤りそのものを減らせる。また、オフライン最適化の費用対効果は日次クエリ量で決まるため、最適化への投資判断はトラフィック規模と価格差の二つを見て行うべきであり、小規模用途では固定プロンプトの単純なルーティングが妥当な選択になる。
