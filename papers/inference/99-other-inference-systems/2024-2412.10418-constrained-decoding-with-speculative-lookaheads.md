# Constrained Decoding with Speculative Lookaheads：制約報酬を組み込む投機的先読み

## 概要

本論文の対象は、指定語をすべて含む文章や有害な要求に対する無害な応答など、通常の次トークン尤度だけでは満たしにくい制約付き生成である。既存のCDLH（Constrained Decoding with Lookahead Heuristics）は、現在の複数の次トークン候補を仮採用し、それぞれの未来を高価な大規模モデルで展開してから制約報酬を計算する。この方法は制約達成率が高い一方、次の1トークンを確定するために大量のモデル呼び出しを要する。CDSLは小型のドラフトモデルで未来の候補を先に生成し、大型のターゲットモデルでまとめて検証し、さらに制約報酬で採否を決める。単なる投機的復号と違い、検証モデルの確率分布を確認しただけで候補を無条件に確定しない。

NAACL 2025の一次論文は、OPT-13B、BLOOMZ-7.1B、Qwen1.5-7Bを対象に、CommonGenとHH-RLHF由来の無害応答生成を評価した。CDLHに対する高速化は2.2～12.15倍だが、これは貪欲復号に対する倍率ではない。最大12.15倍の条件では無害率が91.75%から87.85%へ低下しており、品質と計算費用の交換関係が残る。評価器、タスク、ドラフトとターゲットの組合せを分離して読む必要がある。

## 問題設定と先行研究との差

CDLHでは、ターゲットモデルが現在位置で上位k個の候補を提示し、各候補の後ろに長さdの未来列を生成する。未来列の制約報酬が高い候補を選ぶことで、単純な貪欲復号では先送りされる制約を考慮できる。しかしターゲットによるk×d個の先読み生成が重く、原著では貪欲復号の約8.62～15.35倍の実行費用となる条件がある。これに対し、著者はまずCDLH-Appx.という比較方式を導入する。複数候補の先読みを小型モデルへ置き換えるが、各候補を別々に展開する費用は残り、ドラフト列が大型モデルとどれほど一致するかの検証も行わない。

通常の投機的復号は小型モデルの草案を大型モデルの確率分布で検証し、ターゲットの生成分布を保ちながら計算を節約する。ただし、ターゲットが好む文章でも語彙制約や安全性制約を満たすとは限らない。CDSLはドラフトの提案、ターゲットの検証、タスク固有の報酬関数という三つの判定を接続する。したがって本方式が守るのは制約と速度の折衷であり、報酬による選択後の最終出力が無条件ターゲット分布と厳密一致する保証ではない。

## 手法

### 1. 小型モデルによる先読みと大型モデルによる並列検証

入力は現在の接頭辞pfx、ドラフトモデルMq、ターゲットMp、報酬関数R、草案長d、受理率しきい値at、報酬しきい値rt、探索幅kである。Mqは接頭辞からdトークンを自己回帰的に仮生成する。Mpはこの列をまとめて前向き計算し、各位置でターゲットが与える次トークン分布を得る。ハード棄却では各位置のターゲットの最大確率トークンとドラフトを比較し、最初の不一致までの接頭辞を受理する。確率的な投機サンプリングも設計上は利用可能で、ドラフト確率qとターゲット確率pの比から棄却を判断する。原著の主表はハード棄却条件であり、二つの方式の結果を混ぜない。

ターゲットが認めた接頭辞の長さをnとすると、承認スコアa=n/dである。この受理接頭辞についてタスク報酬Rを計算し、報酬スコアrを得る。語彙制約なら要求概念の被覆割合、無害応答なら外部の報酬モデルが算出する無害性スコアを使う。報酬関数の選択はタスク固有で、追加の評価費用と誤判定のリスクを持つ。

### 2. 承認率と報酬の四状態による採否

Algorithm 1はaとrをそれぞれのしきい値と比較する。aとrがともに高い状態S1では、ターゲットが認めた接頭辞をそのまま確定する。通常の投機的復号で行う、検証後の未報酬評価トークンの追加確定はしない。承認率が低い状態S2/S3では、ターゲットによる少数トークンの生成と、ドラフトによる再先読み・報酬評価を繰り返して、制約を満たす候補を探す。成功しなければCDLH-Appx.へ戻る。承認率が高くても報酬が低い状態S4では、ターゲットの高尤度列だけでは制約を満たせないと判断し、近似先読み探索で別候補を選ぶ。

この状態分岐の役割は、受理率だけを最大化して制約違反を増やすことを防ぐ一方、すべてのトークンで高価なCDLH探索をする必要もなくすことである。aが低い場合にはターゲットの呼び出しと再探索が増え、rが低い場合には制約報酬の判定が生成速度を縛る。しきい値at、rtおよびターゲット側へ生成を委ねる上限bはタスクとモデルの組合せに応じて調整する必要がある。Algorithm 1では受理列と再探索で得た列を接頭辞へ追加し、所定の生成長まで繰り返す。

### 3. 速度改善の源泉と成立条件

CDLHでは高価なMpが複数候補の未来を個別生成する。CDSLは安価なMqに未来列を提案させ、Mpは並列に検証し、まとめて受理できた複数トークンの分だけ後続のターゲット呼び出しを節約する。ただしMqの生成は自己回帰であり、報酬評価も無料ではない。草案の一致率が低い、制約が厳しい、再探索が頻発する場合には利得が縮む。公式Appendixのモデル呼び出し数でも、OPT-13BのHTGでCDLHのターゲット呼び出し14.72回/トークンに対し、CDSL（OPT-125Mドラフト）はターゲット0.56回とドラフト8.51回になる。これは「総呼び出し数が0.56回」ではなく、大小のモデルの計算費用を分けた値である。

## 評価条件と定量結果

### 対象、比較対象、計測方法

| 項目 | 原著の条件 |
|---|---|
| タスク | CommonGenの概念語を含む文章生成、HH-RLHF由来の無害応答生成（HTG） |
| データ | CommonGen検証200・テスト1,000、HTG検証100・テスト2,000 |
| ターゲット | OPT-13B、BLOOMZ-7.1B、Qwen1.5-7B |
| ドラフト | 同一系列のOPT-125M/350M/1.3B、BLOOMZ-560M/1.7B、Qwen1.5-0.5B/1.8B |
| 比較 | 貪欲復号、beam、nucleus、CDLH、CDLH-Appx.、CDSL |
| 速度 | 同じタスクのCDLH実行時間を1.0倍とする倍率。貪欲復号比ではない |
| 品質 | CommonGenはsoft被覆率とhard完全被覆率、HTGは外部評価器による無害率 |
| 留意点 | モデル系列・ドラフトサイズ・しきい値を変えた結果を一つの実験条件として混ぜない |

| OPT-13B + OPT-125M、HTG | 12.15倍 | 無害率87.85% | 無害率91.75% |

最大倍率のOPT-13B/HTGでは無害率が3.90ポイント低下する。OPT-13B/CommonGenでは完全被覆率が13.30ポイント低下し、制約が強い場合の品質損失は無視できない。対照として貪欲復号のOPT-13B/HTGはCDLH比14.72倍でCDSLより速いが、無害率は80.30%と低い。CDSLは「貪欲復号より速い」方式ではなく、制約を守るための高価な探索を現実的な費用へ抑える方式である。

### 強い比較方式、感度、負の結果

CDLH-Appx.との比較も重要である。OPT-13B/CommonGenではCDLH-Appx.（OPT-125M）が5.40倍・hard 81.70%に対し、CDSLは5.54倍・hard 79.80%で、追加の速度利得は小さく品質はむしろ低い。BLOOMZ-7.1B/HTGではCDSL（560M）の無害率82.20%は、CDLH-Appx.の85.80%を下回る。単に小型モデルへ先読みを移したことだけで得られる改善と、ターゲットでまとめて検証した追加効果を区別する必要がある。

原著Figure 2では、承認しきい値、報酬しきい値、再探索パラメータbを動かし、速度と制約達成率の曲線を評価している。しきい値の調整は速度だけでなく無害性や語彙被覆を変えるため、ベンチマークごとにチューニングが必要になる。AppendixのTable 5・6ではモデル呼び出し回数を大小別に計測しており、例えばOPT-13B/CommonGenでCDSLのターゲット呼び出しは0.88回/トークン、ドラフト8.79回である。大モデル呼び出し削減が高速化の主因だが、小モデルの呼び出しは増える。

評価の対象は三つのモデル系列と二種類の制約であり、長文コード生成や多数要求を同時に処理するサービングの実測値は主表にない。HTGの無害性は報酬モデルと判定器に依存するため、人間の評価による完全な安全性保証ではない。原著は公式コードURLを示すが、今回の監査はコードの再実行ではなく一次論文の手法と表の照合である。

## 既存研究との差・限界

通常の投機的復号ではターゲット分布を厳密に保つことが目的である一方、CDSLはターゲット検証後に制約報酬を使って出力を選ぶ。CDLHは制約品質の上限に近いが高コストで、CDLH-Appx.は先読みの小型化にとどまる。CDSLは、検証の並列化と報酬による状態分岐を結合する。採用にはタスク固有の報酬関数、ドラフト・ターゲットの語彙整合、しきい値調整が必要であり、報酬が不適切な場合やモデルの分布差が大きい場合は受理率・制約品質とも低下する。速度はCDLHという遅い基準に対する倍率であり、一般の推論エンジンに対する実測高速化として転用できない。
