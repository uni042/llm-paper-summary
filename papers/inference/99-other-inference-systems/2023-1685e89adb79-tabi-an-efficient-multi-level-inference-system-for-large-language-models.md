# Tabi：要求単位で小型・大型モデルを切り替える多段推論システム

## 概要

Tabiは自然言語の分類・回帰において、すべての要求を高精度な大型モデルで処理する無駄を削減する多段推論基盤である。要求を小型モデルへ通し、校正済みの予測確信度に基づいて結果を返すか大型モデルへ転送するかを決める。転送時には小型モデルの注意重みを使って入力語を削り、両モデルの予測を重み付きで統合する。EuroSys 2023の2基V100によるバッチ1評価では、比較対象INFaaSより平均遅延を21～40%削減した。ただし原著が対象とするのはBERT系の**識別型モデル**であり、自己回帰で文章を生成する現在のLLMへ同じ効果を保証するものではない。

## 背景と問題設定

推論サービスがアプリケーション全体の精度目標に合わせて単一モデルを選ぶと、難しい要求のために大きなモデルが選ばれ、簡単な要求にも同じ計算量がかかる。例えばSST-2で95%の精度目標を設定すると、RoBERTa-largeのような高精度モデルが必要になる。一方、DistilBERTは平均精度が目標に届かなくても、個々の要求の大部分で大型モデルと同じ予測を返す。難度を事前に知ることはできないので、小型モデルだけで返すと誤答が増え、全件を大型モデルへ転送すると小型モデルの計算が無駄になる。

INFaaSはアプリケーション単位の単一モデル選択と資源管理を行い、Cocktailは複数の小型モデルの並列実行と予測統合を中心にする。Tabiは小型モデルをまず動かして得た観測値で**要求ごとに次段へ進むか**を判断し、進む場合も小型モデルの中間結果を再利用する。モデル内部の層を途中終了させる方式と違い、既存のエンコーダモデルを変更・再学習せず組み合わせられる。ただし追加のモデル実行と制御費用があるため、要求の難度分布が利得を決める。

## 手法

### 校正された確信度による確率的振分け

要求は最初に小型モデルで分類され、クラス確率、最大確率、注意重みが得られる。最大ソフトマックス確率は過信しやすいため、Tabiは検証データで温度スケーリングを行う。ロジットを温度 `T` で割って確率を再計算し、実際の正答率に近い確信度を得る。確信度がタスク別の下限 `c` 以下なら大型モデルへ進める。`c` を超えていても常に即時返却するのではなく、確信度に応じたシグモイド関数から再転送確率を定める。高確信度ほど小型モデルだけで終わる確率が高い。

この振分けにより、簡単な要求では大型モデルの演算を省き、難しい要求には高精度モデルを使う。SST-2では `c=0.95` で69.8%、MNLIでは `c=0.85` で49.4%の要求を小型モデルだけで返した。両者の違いはタスクごとの難度分布を反映する。ただし校正はモデルと検証データに依存し、分布が変化した入力では過信・誤振分けが再発しうる。確信度を上げるだけで正解を保証する仕組みではない。

### 再転送時の注意重みに基づく入力語削減

大型モデルへ転送する要求では、小型モデルの推論時間が追加される。Tabiはその小型モデルで既に計算した注意重みを使い、重要性の低い入力語を削る。各トークンが他のトークンから受ける注意を列方向に集約して重要度を作り、削減強度 `α` に応じたしきい値で保持位置を決める。大型モデルと小型モデルで部分語の分割規則が違うため、実際の削除はトークンIDではなく**元の単語単位**で行う。単語内の一つの部分語が必要なら単語全体を残し、短くなった文字列を大型モデルへ入力する。

ここで削減するのは大型モデルに渡す入力文章であって、KVキャッシュやモデルの重みではない。SST-2では再転送入力の14.2%の語を削り、大型モデル単体の遅延を17%減らした一方、正答率は0.3ポイント下がった。MNLIでは13.6%削減、遅延15.4%減、精度0.3ポイント低下である。否定語や数量表現などが注意スコアの低さだけで削られると意味が変わり得るため、削減率を高くすれば常に良いわけではない。

### 既存予測の重み付き統合

大型モデルを実行した場合には、小型モデルと大型モデルの両方のクラス確率分布がある。Tabiは `p=w p_L+(1-w)p_S` のように重み付き平均し、最終クラスを選ぶ。`w` は事前測定した再転送要求集合における各モデルの正答率を参考に決める。追加のモデル前向き計算を行わずに、小型モデルの情報を利用する点が特徴である。SST-2では転送要求に対する予測統合で91.4%から91.8%、MNLIでは85.5%から85.8%へ改善した。ただし両モデルが同じ誤りをする場合は改善しない。

### 候補構成の事前測定と制御器

Tabiは単一モデルと複数段のモデル組合せを候補として作り、各候補の精度、平均遅延、校正温度、振分けしきい値、語削減率、統合重みを事前測定する。制御器はアプリケーションの精度目標を満たす候補から遅延の小さいものを選ぶ。実装はPyTorch、Transformers、TorchServeを用い、制御器が要求受理・振分け・語削減・結果統合を担い、モデルはワーカープロセスで実行する。三段以上が自動的に有利とは限らず、著者の主な評価で選択された構成は二段だった。段数を増やすと難しい要求の逐次処理時間が増える。

## 評価

### 実験の前提

| 観点 | 条件 |
|---|---|
| GPU・ホスト | NVIDIA V100を2基、CPU40コア、RAM128GB |
| 実装 | PyTorch、Transformers、TorchServe、GlusterFS |
| モデル | BERT-small、DistilBERT、RoBERTa、DeBERTa等の識別型エンコーダ |
| データ | GLUE、MASSIVE、CLINC150の分類・回帰 |
| 負荷 | 逐次要求、バッチ1。主遅延指標では前処理・トークン化を除外 |
| 比較 | INFaaS（単一モデル）、Cocktail（複数モデルの並列投票） |
| 資源差 | TabiとCocktailは2基V100、INFaaSは1基。GPU数は完全には等しくない |

| タスク | INFaaS平均遅延 | Cocktail | Tabi | 主な解釈 |
|---|---:|---:|---:|---|
| SST-2 | 22.0 ms | 17.8 ms | 13.2 ms | INFaaS比40%減 |
| MNLI | 25.8 ms | 22.9 ms | 20.3 ms | INFaaS比約21%減 |
| RTE | 38.1 ms | 34.7 ms | 30.0 ms | INFaaS比約21%減 |
| QQP | 25.4 ms | 20.8 ms | 16.0 ms | INFaaS比約37%減 |
| MASSIVE | 20.9 ms | 15.4 ms | 13.5 ms | 多クラス分類でも改善 |

SST-2の精度はINFaaS 96.1%、Cocktail 95.4%、Tabi 95.6%で、95%の目標を満たした。MNLIではINFaaS 91.2%、Tabi 90.4%で、90%の目標は満たすが基準方式より0.8ポイント低い。したがって「精度を全く落とさず高速化」とは言えず、指定した精度下限を満たす範囲で遅延を削減する方式である。著者の集計ではINFaaS比21～40%、Cocktail比11～26%の平均遅延削減を報告する。

### 構成要素と悪化条件

SST-2で振分けしきい値を0.75、0.85、0.95と変えると、小型モデルでの早期返却率は92.4%、87.4%、69.8%となる。しきい値を下げると早期返却が増えるが、難しい要求も誤って返すため精度が下がる。語削減強度を上げると大型モデルの入力は短くなるが、意味のある単語を削除する危険が増す。SST-2で削減率を3.8%、14.2%、62.5%と増やした感度評価では、強い削減が品質を悪化させる。

遅延分布では簡単な要求が早期終了するため中央値が改善するが、難しい要求は小型・大型モデルを逐次実行するため、末尾遅延の改善は限定的になる。三段構成が二段構成より平均遅延8.4%、99パーセンタイル遅延70.3%悪化する例も示される。推定コスト27～50%減という値は、実際のクラウド請求ではなくモデルの同時配置数などから算出した代理指標である。前処理を除くバッチ1の比較を、実サービスの多重要求・オートスケール環境へ無条件に外挿しない。

## 限界

最重要の制約は、Tabiが**生成ではなく識別タスク向け**という点である。分類器の確信度は一回の入力に対する最終ラベルの正しさを測るが、生成LLMではトークンごとに確率分布を更新する。分類器の早期返却、注意重みによる単語削除、クラス分布の重み付き統合を、そのまま文章生成の無損失高速化へ転用することはできない。

評価は単一サーバ・バッチ1であり、継続バッチ処理、複数GPUへの分散、GPU間通信、長文脈KVキャッシュ、同時要求時の尾部遅延は測定していない。比較対象間のGPU数が完全には同じでなく、事前測定の費用や校正データの分布変化も実運用上の制約となる。現代の生成LLMサービングを考える際には、要求難度に応じたモデル振分けという設計思想の先行例として位置付け、原著の速度倍率を直接適用しない。
