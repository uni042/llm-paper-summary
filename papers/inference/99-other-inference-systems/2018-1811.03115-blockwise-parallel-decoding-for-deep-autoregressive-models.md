## 概要
自己回帰モデルは、学習時には系列方向を並列化できても、生成時には直前までに確定した出力を条件に次の1 tokenを決めるため、出力長に比例した逐次的なクリティカルパスが残る。Blockwise Parallel Decodingは、この逐次性そのものを完全に捨てるのではなく、複数の将来位置を一度に予測し、元の自己回帰スコアリングモデルで「通常の貪欲復号なら同じtokenを選んだか」を並列検証する。検証に通った最長prefixだけを一括受理するため、厳密検証では元モデルのgreedy出力を保持したまま反復回数を減らせる。

後年の投機的復号（speculative decoding）と同型の「proposal → verification → acceptance」を持つが、本論文では将来位置ごとの補助予測器と、Transformerが複数出力位置を並列採点できる性質を組み合わせる点が中心である。さらに、予測器と検証器を1つのTransformerへ統合してモデル呼び出し回数を減らす実装、top-kや距離に基づく近似受理、系列蒸留が将来予測の一致率へ与える影響まで評価している。

## 問題設定
長さ (m) の出力を通常のgreedy decoderで生成すると、各stepで
(argmax_y p(y_{j+1}mid y_{le j},x))
を求めるため原理的に (m) 回の逐次反復が必要になる。Transformerの各forward自体は並列性が高いが、次stepの入力tokenが前stepの結果に依存するので、単にGPU演算を高速化してもこの依存鎖は消えない。

一方、将来の複数tokenを無条件に一括生成すると、早い位置の予測誤りを後続が条件として見ていないため品質が崩れやすい。必要なのは、複数位置を並列に「提案」しつつ、元モデルが許容するprefixだけを採用して誤差伝播を止める仕組みである。

## 手法
元の自己回帰モデルを (p_1=p) とし、現在のprefix (y_{le j}) から (i) token先を予測する補助モデル (p_i(y_{j+i}mid y_{le j},x)) を (i=2,dots,k) について用意する。1回の反復は次の3段階からなる。

1. **予測（Predict）**: (p_1,dots,p_k) を並列に実行し、現在prefixから次の (k) 位置それぞれの局所的な最尤token候補を独立に得る。
2. **検証（Verify）**: 提案された長さ (k) の候補列を元モデル (p_1) でまとめて採点する。前から順に、候補tokenが、その候補prefixを条件にした元モデルのgreedy選択と一致するかを調べ、最初の不一致直前までの最長prefix (hat{k}) を求める。Transformerでは候補位置を一度にスコアできるため、逐次 (k) 回の検証を必要としない。
3. **受理（Accept）**: 一致した先頭 (hat{k}) tokenだけを確定し、その分だけ生成位置を進める。第1候補は元モデル自身の次token予測なので (hat{k}ge1) が保証され、進捗が止まらない。厳密一致を使う限り、最終出力は通常のgreedy decoderと同じになる。

素朴実装では「proposal用forward」と「verification用forward」の2回が必要で、完全一致しても呼び出し回数は概ね (2m/k) までしか減らない。論文はこれを避けるため、decoder出力の後に隠れ幅 (k	imes d_{hidden})、出力幅 (k	imes d_{model}) のmulti-output feed-forward層と各出力への残差結合を挿入し、元の語彙射影を各出力へ共有適用する**統合スコアリング・提案モデル**を使う。これにより、ある反復のverification時に次反復で必要なproposalも同時に計算でき、初回を除けばモデル呼び出しをほぼ1回/反復へまとめられる。学習メモリを抑えるため、(k) 個のcross-entropyを毎minibatchすべて保持する代わりに、各minibatchで1つのsub-lossを一様サンプリングし、全lossの不偏推定量として学習する。

さらに速度と品質のPareto点を広げる近似受理も検討する。機械翻訳では厳密なargmax一致の代わりに提案tokenが元モデルのtop-k集合へ入っていれば受理する。画像超解像では画素強度の絶対差が閾値 (epsilon) 以下なら一致とみなす。逆に「毎回最低2〜3 tokenは必ず受理する」方式も試すが、これはBLEU低下の割に受理長の伸びが小さく、少なくとも1 tokenで打ち切れる仕組みが品質維持に重要だと示される。

## 評価条件
| 観点 | 条件 |
|---|---|
| 実装 | Tensor2Tensor |
| 機械翻訳 | WMT 2014 English→German。baselineは `transformer_base`、8×P100で100万step学習 |
| 翻訳評価 | newstest2013開発集合でBLEUと平均受理block長、newstest2014で最終比較 |
| 翻訳追加学習 | 各block size (k) について同じ8×P100でさらに100万step。元データとsequence-level distillationデータを比較 |
| 画像超解像 | CelebA、8×8入力から32×32画像を生成。1D local attentionのImage Transformer |
| 超解像追加学習 | baselineを100万step、blockwiseモデルを追加25万step |
| 主指標 | BLEU、平均受理block長、実wall-clock高速化、人手による画像品質選好 |

## 主要結果
翻訳のnewstest2013では、元パラメータを凍結した通常学習でも平均受理block長は最大1.76に達し、品質を大きく変えずに反復数を減らせる。蒸留データでは最大1.91まで伸びる。元パラメータまでfine-tuningし、さらに蒸留を併用すると、(k=8) でBLEU 26.11・平均受理長4.69、(k=10) で25.60・4.95となり、将来予測の整合性は大きく上がるが、大きいblockでは品質との交換条件が現れる。

top-2近似受理では、たとえば (k=8) でBLEU 25.71・平均受理長5.34、(k=10) で25.04・5.67まで反復削減を進められる。top-3でも同様の傾向を示す一方、最低受理長を2または3へ強制する方式は、平均受理長の改善が小さい割にBLEUを大きく落とし、負の結果として報告されている。

実wall-clockでは、翻訳は (k=8)、平均受理長約4.7の設定で最大3.3倍、画像超解像は (k=6)、平均受理長約5.3で最大4.0倍に達する。重要なのは、block sizeや平均受理長をさらに大きくしても壁時計性能は単調には伸びないことである。候補数を増やすほど1反復内の追加計算が増え、翻訳では (k=10) のwall-clock高速化が3.04倍へ低下する。したがって「受理token数/反復」と「実時間高速化」は別の指標として最適化する必要がある。

newstest2014では、蒸留済みgreedy baselineがBLEU 29.11・1.00倍であるのに対し、blockwise (k=2,4,6,8,10) はそれぞれBLEU 28.95/28.54/28.11/27.88/27.40、wall-clock 1.72/2.69/3.10/3.31/3.04倍である。3倍超まで高速化した (k=6) でもbaselineとの差は1 BLEU点程度であり、速度を上げるほど品質が徐々に落ちるPareto関係が明瞭である。

画像超解像では、fine-tuningと距離ベース近似受理を同時に使うと平均受理長が (k=6) で5.25、(k=8) で6.36、(k=10) で6.79まで伸びる。人手評価では各blockwise設定と通常decoderの選好率は概ね50%付近で、著しい知覚品質低下は観測されず、(k=6) の近似設定はむしろ56.8%で選好された。

## 既存研究との差
非自己回帰モデルのように自己回帰依存を学習時から取り除くのではなく、元の自己回帰モデルを**検証器**として保持し、正しいprefixだけをまとめて確定する。そのため厳密受理ではgreedy出力の同一性を保証できる。後のdraft/target型投機的復号と共通する考え方を持つ一方、本論文では将来位置ごとのmulti-output予測を1つのTransformer内へ統合し、verificationと次proposalを重畳する設計が中核である。

## 限界
利得はproposal精度と、検証対象の複数位置を実際に並列処理できるモデル・ハードウェアへ強く依存する。受理長が短い場合は補助出力と検証の追加計算が相殺し、大きすぎるblockは反復数を減らしてもwall-clockを悪化させる。厳密greedy同値性は決定的なargmax復号に対する性質であり、現在一般的な確率的samplingへそのまま同じ保証を与える評価ではない。また補助予測器を得るため追加学習が必要で、完全なtraining-free高速化ではない。
