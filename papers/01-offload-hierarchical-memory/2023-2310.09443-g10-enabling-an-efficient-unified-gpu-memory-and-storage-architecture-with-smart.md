# G10: Enabling An Efficient Unified GPU Memory and Storage Architecture with Smart Tensor Migrations

> GPU memoryとhost memory・storageを統合し、tensorの生存期間と再利用を基に階層間migrationを自動化する学習システム。

## 概要
G10はGPUの限られたHBMをhost DRAMとflash SSDで透過的に拡張し、DNN training中のtensorを先回りして移動する統合GPU memory/storage architectureである。GPUメモリに収まらない全モデルを毎回ページフォルトでSSDから読むのではなく、compilerが実行グラフからtensorのサイズ、依存関係、active期間、次回使用時刻を抽出し、不要なtensorをhostまたはflashへ退避する。調査では各kernelでactiveなtensorは全体の10%未満（平均1%）で、多くのinactive期間はSSD latencyより長いことを示し、転送を計算と重ねられると主張する。対象はBERT、ViT、ResNet、Inceptionv3、SENetなど一般DNN trainingで、MoE expert weightや生成時KV cacheを中心にした研究ではない。使うストレージは通常のNAND flash SSD（NVMe相当）であり、CXLメモリ、HBF、near-storage FPGAとは別階層である。G10はUVM page tableを拡張してGPU／host／flashのアドレスを一つの仮想空間に見せ、アプリケーションを変更せずにmigrationを実行する点が特徴である。従って既存のweight offloadにそのまま当てはめるより、tensor lifetimeを知るcompilerとGPU memory managerの組合せを評価する候補として登録するのが適切である。
## 手法のあらまし
構成はtensor vitality analyzer、smart migration scheduler、unified memory systemの三つである。analyzerはPyTorch等の実行グラフから各tensorのサイズ・依存・active／inactive期間を得る。schedulerは将来kernelまでのinactive時間とtensorサイズ、GPU・host・flashの利用可能帯域を見て、どのtensorをいつどこへevictし、いつprefetchするかを動的に計画する。長いinactive期間で大きなtensorはSSDへ、短いものや高頻度のtensorはhostへ置き、GPU内の空きを次kernel用に確保する。計画はコンパイル段階でg10_pre_evict／g10_prefetch命令として注入され、runtimeのmigration handlerがDMAを起動する。基本UVMのpage fault、相関prefetchのDeepUM+、GPU–SSD直結のFlashNeuronと異なり、G10はtensor semantic knowledgeを用いるため、重みだけでなく中間activationも対象にできる。G10-GDS（GPU–SSD）、G10-Host（GPU–host–SSD）、完全なG10（UVM統合）を段階的に比較できる設計で、host memoryはSSDへ間に合わない高帯域tensorの緩衝に使う。評価フレームワークはA100 traceとSSD-Simでflash page accessやgarbage collectionもモデル化するが、実PCIe DMAや実SSD firmwareを実行するものではない。なお、GPUに置いたKVを圧縮・退避する生成推論のcache管理ではなく、training tensorの寿命スケジューリングである。
## 評価
想定システムはNVIDIA A100 40GB、PCIe Gen3 x16（双方向15.754GB/s）、Samsung Z-NAND相当SSD（read/write 3.2/3.0GB/s、latency 20/16μs、容量3.2TB）、host memoryを持つ。モデル／データセットはBERT–CoLA、ViT–ImageNet、Inceptionv3–ImageNet、ResNet152–ImageNet、SENet154–ImageNetで、FP32、モデルごとにbatchを変える。baselineはIdeal（GPU無限）、Base UVM（page fault）、DeepUM+（相関prefetch）、FlashNeuron（GPU-direct SSD）。G10はFlashNeuron比平均1.56倍、DeepUM+比平均1.31倍、Idealの90.3%、個別最大1.75倍。batch拡大時はFlashNeuron比最大2.67倍、DeepUM+比1.45倍、host増設時はFlashNeuron比平均1.33倍。1–4 SSD（最大12.8GB/s）で多くのベンチがIdealの90–100%へ届く一方、BERT／ViTはPCIeが律速。予測誤差±20%でも劣化0.5%未満、書き込みはDeepUM+比1.37倍、FlashNeuron比2.20倍少ない。制約は全結果がsimulatorとprofile traceに基づき、SSD bandwidth／latency・GC・PCIeを仮定すること、一般DNN trainingのみでLLM serving、MoE routing、KV、continuous batchingを測らないこと。NVMe/flashのcompiler-guided migrationとして、実機HBFやCPU expert offloadの数値と混同してはならない。[arXiv本文](https://arxiv.org/html/2310.09443v1)、[artifact](https://github.com/platformxlab/G10)
