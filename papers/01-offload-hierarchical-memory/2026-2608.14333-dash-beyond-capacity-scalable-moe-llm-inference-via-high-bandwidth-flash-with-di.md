# DASH: Beyond Capacity: Scalable MoE LLM Inference via High-Bandwidth Flash with Direct GPU and HBM Paths

> High-Bandwidth FlashからexpertをGPU／HBMへ直接供給し、従来NVMeを超える大容量MoE推論を狙う階層メモリ設計。

## 概要
DASHは2026年8月公開の将来デバイス評価で、現行のNVMe SSDをGPUへ直結したベンチマークではない。HBFのページ並列性とUCIeリンクを仮定するため、CPU DRAM offload論文のPCIe latencyやSSDのNVMe queue depthと数値を混ぜられない。比較対象は同一HBFで経路だけを変えたRelayOnly／DirectOnlyである。
DASHは、HBF（High-Bandwidth Flash）をSSD/NVMeの遠いストレージではなく、GPU近傍の主メモリ階層として扱うMoE向けアーキテクチャである。HBF resident expert weightをGPUへ運ぶ経路を、HBF→GPUのDirectとHBF→HBM base die→GPUのRelayに分け、expert単位で割り当てて同時転送する。HBMは低遅延の活性・decode KV、HBFは大容量のread-mostly expert weightと大きなprefill KVを担う。CPU DRAM offloadやPCIe経由のweight streamingではなく、UCIe接続のHBM/HBF近傍メモリであり、HBFを通常SSDと同一視しない。KV cacheも扱うが、expert weightとは別に、prefillの大きなKVをHBFへ直接write、decodeの小さなKV更新をHBMでcoalesceしてwritebackする設計である。実機HBFは未実装のため、GPU演算はH100 PCIe 80 GBで実測、HBF read/program・die/plane parallelism・UCIeをevent-driven continuous-batching simulatorで評価する。
## 手法のあらまし
Directはリンクを短くできるがHBF readのばらつきを直接GPUが受け、RelayはHBM base dieのバッファで吸収できる一方、HBM帯域を消費する。expertごとの割当とKVの書き戻しを分離し、この二経路を同時に使うことがDASHの中心である。router条件を満たさないモデルはlookaheadを使えない。
UCIe 3.0でGPU I/O die–HBM base die–HBF base dieを接続し、各physical D2D linkをusable 1.6 TB/sとする。2×512 GB HBF＋2×24 GB HBMを基本構成に、QKV/output重みをHBM/HBFへ複製、expertsをHBFへ配置する。HBF base dieに18 MiB SRAM（usable16 MiB、2つの8 MiB transfer region）を置き、NAND readのsensing latency tR（公称3 μs、範囲1–32 μs）をdouble-bufferで隠す。routerがscale-invariantかつexpert biasなしなら、attention後の通常top-kより前に入力依存項を計算するLookahead Expert Executionで、選択expert readをoutput projectionと重ねる。KVはweight-owned blockとKV-owned erase blockを分離し、GCでweightを動かさない。prefill KVはpage-aligned direct write、decode KVはHBMへ蓄積して大きなwritebackにまとめ、NAND program latency（公称100 μs）とreadを競合させない。Direct/Relayにexpert全体を割当てるため重複weightは不要である。
## 評価

### まず見るところ
- **結論:** HBFからGPUへ直接読む経路とHBM relay経路をexpertごとに分けて併用すると、片方だけを使うより大幅にthroughputを上げられる。
- **速度・効率:** modeled systemではthroughputがほぼ倍増するが、これは現行NVMeの速度ではない。
- **品質:** expertやKVの計算内容を変えず、配置・転送経路だけを変えるため品質は変わらない。
- **メモリ・I/O:** **High-Bandwidth Flash (HBF)＋UCIe＋HBM** の将来階層。通常NVMe SSDやCPU DRAM offloadとは別カテゴリー。
- **評価の強さ／注意点:** **Simulationのみ**。GPU kernel timingの一部は実測だが、HBF silicon・UCIe転送・NAND系はsimulator／仮定に基づく。
