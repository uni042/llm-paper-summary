# MoNDE: Mixture-of-Experts Neural Network Inference with Near-Data Processing

> computational storage上でexpert計算を行うnear-data executionにより、巨大MoEのストレージ帯域とGPU転送を削減する方式。

## 概要
CXLはホストCPUの通常DRAMを単に増設する用途ではなく、論文では演算アレイを備えたメモリデバイスとしてモデル化される。従って結果は「CPU offloadの高速版」とは読めず、NDPの面積・帯域・電力を含む別設計空間の提案である。
expert weightはデバイス側のLPDDRに常駐し、GPUが保有するのはhot分だけである。NDPはGPUのHBMを増量する方法ではなく、CXLリンク越しのactivation転送を許容してメモリ内積を近づける方法であり、低batch時の重み移動を特に問題にする。
MoNDEは、MoE expertの冷たい（cold）部分をGPUへ転送せず、CXL接続のメモリデバイス内near-data processing（NDP）で計算するハードウェア／システム提案である。hot expertは従来通りGPUへweight transferしてGPUで計算し、少数tokenしか受けないcold expertはactivationだけGPUからMoNDEへ送り、device内のexpert weightを読んでGEMMを行う。従ってCPU DRAMの単純weight offloadでも、SSD/NVMeでもなく、CXLメモリ（LPDDR DRAM）＋NDPである。KV cache offloadは目的ではなく、MoE FFN expert weightの移動をactivation movementへ置き換える。Switch-Large-128（expert 51.5 GB、E=128、top-1）とNLLB-MoE（expert 103.1 GB、E=128、top-2）を、A100 PCIe一枚とCXLメモリデバイスで評価する。論文はDAC 2024採択のハードウェア評価で、完成品の実機NDPを測ったものではなく、GPUプロファイル＋cycle-level simulatorで推定する。
## 手法のあらまし
この切替はexpert単位に固定するのではなく、各入力で予測token数を見て動的に行う。したがってrouting skewが大きいほどcold側NDPを活かせるが、全expertがhotになる大batchではGPU転送とNDPの並列性が薄れ、改善幅は小さくなる。KV cacheは配置対象に含めていない。
MoEではexpertごとのtoken数が偏り、cold expertは0–7 token程度しか受けないことが多い。A100＋PCIe Gen4 x16では、1 tokenのexpertでweight transferがGPU計算の最大30倍になり得るため、転送量を削る。従来PMoveのデータ量は概ね2E d_model d_ff、提案AMoveは2BS d_modelで、batch/sequenceが小さいとexpert数・FFN幅に依存するPMoveより小さくなる。MoNDE deviceは8メモリチャネル、容量512 GB、帯域約512 GB/s（1 moduleは64 GB、68 GB/s）、64個の4×4 systolic array、264 KB buffer、1 GHzを想定する。runtime gate後にhot top-HをGPUへPMove、残りcoldをAMoveし、GPUとNDPを同時実行するGPU-MoNDE load balancingを行う。HはPCIe帯域とMoNDE帯域、activated expert数から計算し、profileで係数αをauto-tuneする。CXLのmemory-mapped命令でgemm/gemm+reluを投入し、parametersとactivationsを別bankへ配置する。
## 評価
CPUはXeon Silver 4310（メモリ帯域187 GB/s）、GPUはNVIDIA A100 PCIe、MoNDEは上記の512 GB/s・512 GB NDPモデル。Switch-Large-128はXSum language modeling、NLLB-MoEはFLORES-200 translation、入力長512、batchを変えて評価した。GPU+PM（activated expertをCPUからGPUへ移す）、MD+AM（全expertをNDP）、MD+LB（GPU/NDP協調）、Ideal（無限GPU memory）を比較。MD+LBはGPU+PMに対しSwitchでencoder 3.1倍、decoder 1.1倍、NLLBでencoder 6.7倍、decoder 1.9倍（平均はそれぞれ4.9倍、1.5倍）。abstractの最大値は既存parameter-offloading比encoder 7.5倍、decoder 3.7倍。NLLBのCPU計算＋AMoveと比べてもNDPはencoder 9.1倍、decoder 1.9倍低遅延で、主因はMoNDE帯域がCPUの約2.7倍である。area overheadは3.0 mm²。限界はMoNDE NDPをcycle-level simulatorで置換評価し、GPU・CXL・NDPを統合した実チップ測定でないこと、512 GB/s CXL memory仮定やhot/cold閾値の影響、encoder/decoder個別測定で、KV cacheやonline multi-user servingを評価しない点である。[arXiv本文](https://arxiv.org/html/2405.18832v1)
