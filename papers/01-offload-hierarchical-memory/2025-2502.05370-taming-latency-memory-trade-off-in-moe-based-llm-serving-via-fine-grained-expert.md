# Taming Latency-Memory Trade-Off in MoE-Based LLM Serving via Fine-Grained Expert Offloading

> expertを細粒度blockへ分割して必要部分だけをロードし、MoE servingのメモリ削減と転送遅延を調整する方式。

## 概要
FineMoEの「fine-grained」はexpertの重みを小片に分割する意味ではなく、routingの時間粒度と要求意味を細かく追う意味である。モデル品質を近似せず、必要expertをCPUからGPUへ読むlossless構成なので、削減値はcache/prefetchの待ち時間に対する効果として解釈する。
主眼はGPU cacheを数GBまで縮めてもスループットを保つことにあり、expertをCPUで計算するFiddlerやCXL内で計算するMoNDEとは異なる。CPUは重みの保管場所で、実行は基本的にGPUである。実サービスのrequest arrivalも別途トレースで再生する。
fMoE（本文・改訂版ではFineMoE）は、GPUに置くexpert cacheをrequest単位の粗い人気統計ではなく、iteration単位のexpert選択軌跡とprompt意味情報で制御するlossless expert weight offloadシステムである。expert weightの本体はCPU DRAM、GPUには容量内のcacheを置き、prefetch miss時だけCPU→GPUへ読む。KV cache offloadは提案の中心ではなく、prefill/decodeのTTFT/TPOT測定で通常のGPU KVを使う構成である。Mixtral-8x7B、Qwen1.5-MoE、Phi-3.5-MoEを対象に、LMSYS-Chat-1MとShareGPTの実プロンプト、6×RTX 3090（各24 GB、NVLink、PCIe 4.0 32 GB/s、Threadripper PRO 3955WX 32-core、CPU 480 GB）で評価する。論文は2025年版で、改訂v2はEuroSys 2026表記と数値更新（hit rate 39%）があるため、版を混同せず引用する。
## 手法のあらまし
意味検索はプロンプトの近さを補助信号として使うだけで、重みを量子化したりrouterを再学習したりしない。検索・cache管理を別スレッドで走らせるため、CPU時間とI/Oを消費するが、推論計算のクリティカルパス外へ追い出す設計である。
prefetchは必要以上のexpertを読むと帯域を浪費するため、δと距離dの設定がcacheサイズだけでなくPCIe混雑にも依存する。評価のhit rate改善はrouting軌跡の規則性に依存し、ランダムな要求系列を保証するものではない。
各iteration・各層のgate確率分布をExpert Mapに保存し、履歴mapからtrajectory similarity（expert分布の類似）とsemantic similarity（prompt embeddingの類似）を検索する。検索したmapから各層の確率質量が閾値δに達するまでexpertを選び、prefetch distance d層先へ非同期prefetchする。GPU cache満杯時は予測確率と訪問頻度の積が小さいexpertからCPUへevictし、miss時はprefetchを一時停止して必要expertをon-demandロードする。iteration-level情報は、request全体を集約するMoE-InfinityのEAMより予測エントロピーが低く、prefetch distanceを変えても高いhit率を保つ。Expert Map Store、Searcher、Cacheを分離し、C++/CUDA task poolで検索・I/Oを推論と並行化する。共通モデルの再学習やpredictor訓練は不要で、モデルごとにmapを収集するだけである。
## 評価
70% promptをmap構築、30%をテストに分け、入力長はLMSYS平均37、ShareGPT平均43、生成長は127/122。基線はMoE-Infinity（request-level）、Mixtral-Offloading（stride speculative＋LRU）、ProMoE（再実装）、DeepSpeed-Inference（expert-agnostic on-demand）。prefill TTFTとdecode TPOT、expert hit rateを測った。初期版abstractは推論遅延47%削減、hit rate 36%改善、改訂版はhit rate 39%改善とする。改訂版の平均比較ではDeepSpeedに対しTTFT74%、Mixtral-Offloading67%、ProMoE56%、MoE-Infinity53%削減、TPOTは各46%、38%、27%、22%削減。GPU expert cacheを6–96 GBに振った場合も、6 GBでDeepSpeed比36%、Mixtral-Offloading比25%、ProMoE比16%、MoE-Infinity比29% TPOT削減。A100 80 GB（HBM2e、2 TB/s）では6×3090より差が縮む。online servingではAzure traceから256 request、2.91 req/sを再生し、cold start（Map Store空）でも優位。map store 32K件はCPU 200 MB未満、通常は1K件で十分。限界はCPU DRAM前提でSSD/HBF未評価、map収集時の分布ずれ、prefetch距離・GPU速度への感度、基線ProMoEが再実装である点。[arXiv v1](https://arxiv.org/abs/2502.05370)、[改訂HTML](https://arxiv.org/html/2502.05370)
