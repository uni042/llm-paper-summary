# CoX-MoE: Coalesced Expert Execution for High-Throughput MoE Inference with AMX-Enabled CPU-GPU Co-Execution

> expert tokenを大きなcoalesced batchに集約し、AMX対応CPUとGPUへ処理を分担して、メモリ制約下のMoE serving throughputを高める。

## 概要
CoX-MoEは、全expertをGPUに保持できないMoE servingで、重み転送だけでなくexpert GEMMの低いarithmetic intensityがthroughputを制限する点に着目する。従来のoffloading systemはmicrobatch単位でexpertをロード・実行するため、同じexpertへ送られるtokenが小さく分散し、GPU tensor coreもCPU vector unitも十分に使えない。CoX-MoEは複数microbatch・複数requestから同じexpert向けtokenをまとめ、通常より大きなcoalesced batchとしてexpertを実行する。さらにIntel AMXを備えるCPUを単なるweight置き場ではなく計算資源として使い、GPUとexpert計算を協調実行する。attentionの一部をCPUへ選択的にoffloadしてVRAMを空け、より多くのhot expertをGPU residentにできるようにする。対象はCPU DRAMとGPU HBM間のexpert weight配置、およびCPU-GPU co-executionである。attention／KV処理のCPU配置も扱うが、SSD／NVMeやHBF、CXL memoryは評価しない。KV cache offload専用研究ではなく、MoE high-throughput servingのresource allocationが中心である。DAC 2026採択で、MoE-Lightning、MoE-Infinity、Fiddlerなどの後続として、transfer hidingだけでなくbatch formationとAMX計算を統合した点が新しい。
## 手法のあらまし
runtimeはまずrouting結果を蓄積し、同一expertに向かうtokenをmicrobatch境界を越えてまとめるordinary/coalesced二種のbatchを形成する。coalesced expert executionはGEMMサイズを大きくしてCPU/GPUの演算効率を上げるが、集約待ちが増えるため、non-MoE処理のmicrobatchingと組み合わせてpipeline stallを抑える。次に、短いprofilingから各expertのactivation frequencyと処理コストを推定し、hot expertをGPUに残すexpert-aware stratificationを行う。clustering、sampling、probingにより全探索を避けつつ、GPU memory内に置くexpert集合を選ぶ。CPU側ではAMX向けkernelでexpert FFNを処理し、GPU側と並行に実行する。attention offloadは常時ではなく、VRAMをexpertへ回した方が全体throughputが高い場合に選択する。最適化器はCPU/GPUのcompute capacity、PCIe transfer、expert residency、batch size、non-MoE microbatch sizeをまとめて探索し、straggler側の完了時間を小さくする。元routerのTop-kやexpert出力は変更せず、品質を落として計算量を削るのではなく、同じ計算をより高い利用率で実行するsystem手法である。
## 評価

### まず見るところ
- **結論:** 同じexpert向けtokenをまとめて大きなGEMMにし、AMX CPUも計算へ参加させると、offloaded MoEのthroughputを大きく伸ばせる。
- **速度・効率:** 既存のCPU/GPU offload方式より明確に高速で、throughput-oriented servingに強い。
- **品質:** native routingと全expert計算を維持するため品質は変わらない。
- **メモリ・I/O:** CPU DRAM＋GPU HBMのco-executionで、SSD/NVMeは使わない。
- **評価の強さ／注意点:** **実機**。Intel AMX、CPU memory bandwidth、PCIeへの依存が強く、batch=1ではtoken集約待ちが逆に不利になり得る。

<details>
<summary>評価条件・詳細な数値を開く</summary>

Qwen3-30B-A3Bを中心に、RTX 6000 AdaとIntel Xeon 8452YなどAMX対応CPUを備えた実機で評価している。FlexGenに対して最大7.1倍、登録済みMoE-Lightningに対して最大2.4倍のthroughputを示し、構成・workloadを横断した比較では既存最先端に対して1.7〜2.4倍の向上を報告する。profilingでは、microbatchごとの小さなexpert GEMMを単純にGPU実行するとhardware utilizationが低い一方、coalescingにより演算密度が上がり、CPU AMXも実用的な補助計算資源になることを示す。評価は実機end-to-endでsimulation-onlyではない。native routingと全expert計算を保持するためtask品質は基本的に不変だが、主眼はoffline／throughput-oriented servingであり、対話的batch=1のTPOTやTTFTには集約待ちが不利になり得る。AMX世代、CPU memory bandwidth、PCIe帯域への依存が強く、Apple Siliconや一般的なconsumer CPUへの直接移植にはkernel再設計が必要である。SSD読出し量やenergy/tokenは中心指標でなく、公式コードも一次資料上で確認できないため、再現性と汎用runtimeへの統合状況は限定的である。
