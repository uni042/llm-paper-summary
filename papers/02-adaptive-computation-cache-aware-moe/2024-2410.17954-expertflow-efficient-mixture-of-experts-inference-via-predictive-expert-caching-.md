# ExpertFlow: Efficient Mixture-of-Experts Inference via Predictive Expert Caching and Token Scheduling

> expert活性化とtoken割当てを共同最適化し、MoE推論の負荷不均衡と不要計算を抑えるフレームワーク。

## 概要
ExpertFlowは、CPUへエキスパートをオフロードした単一GPU推論を対象に、予測・トークン再配置・キャッシュを統合したシステムである。構成はRouting Path Predictor（RPP）、Token Scheduler（TS）、Expert Cache Engine（ECE）。RPPが将来層のルーティング経路を予測し、TSが同じエキスパートを使うトークンを同じバッチへ集め、ECEが予測に基づきキャッシュ領域を層間で再配分する。予測外の活性化は実行時の軽量補正で処理するため、予測誤りで正解計算を落とさない。主眼は転送量の削減ではなく、I/OをGPU計算の隙間に隠し、キャッシュミスをクリティカルパスから外すことである。Switch、Mixtral、Qwen、DeepSeekなど異なるエキスパート粒度を含めて比較し、ドメインをまたぐ予測器の汎化も測る。
ExpertFlowの対象は、モデル全体をGPUへ置けない単一GPUの推論であり、予測精度だけでなく「転送が完了するまでの先行時間」とバッチ内の専門家再利用を評価する。Cache-MoEのLRUは層ごとの固定枠で同じ専門家を追い出し、SE-MoEは複数層を先読みするが、モデルごとのルータ実装に依存する。ExpertFlowはこの差をシステム内の予測器・再バッチ・キャッシュ枠管理へ分解した。予測が外れても計算を落とさず、実行中に訂正するため、速度改善と品質維持を同時に測れる構成になっている。
対象モデルがSwitchからMixtralまで異なるため、RPPは特定のexpert番号を固定的に覚えるより、経路の構造を予測することが求められる。論文は同一データだけでなくAlpaca学習器をXSUM/WMT16へ移す条件も置いた。
## 手法のあらまし
RPPは入力特徴から数層先の各トークンのルーティング行列を予測する軽量モデルで、最大95%の予測精度を報告する。TSは隣接バッチの2Tトークンをルーティング経路のハミング類似度で二分するK-means型処理を行い、2バッチ合計の活性エキスパート数を最小化する。KV-cacheの順序が変わるため、MergeとReindexで元のトークン順を復元する。ECEのPLECは予測需要を層ごとのキャッシュ枠へ割り当て、早い層で空いた枠を後続予測へ再利用する。ECEは予測外の要求を検知し、実行中のエキスパートを止めずに優先転送する。Dual-Batch pipelineで現バッチの推論中に次バッチのRPP/TSを重ねる。TSのCPU処理は10ms未満とされる。ベースラインは、層別LRUのCache-MoE、複数層プリフェッチ＋ring schedulingのSE-MoE、ランタイムゲートを置き換えるPre-gated MoEである。ただし後二者はSwitch系列以外のルータ実装に対応しないため、Mixtral/Qwen/DeepSeekではCache-MoEとの比較に限定された。
RPPはモデルのゲート出力を直接置き換えるのではなく、将来のexpert activationを予測してプリフェッチへ使う。TSが同じ経路を持つトークンをまとめることで、一つのバッチで発生する層別expert集合を減らすが、トークン順が変わるためKV-cacheの整合処理が必要になる。ECEでは予測された層ごとの需要がキャッシュ容量を超える場合、確率の高い専門家を優先し、前層の処理終了で空いた枠を後層へ渡す。誤予測の訂正は、必要expertを優先度付きで転送しながら、現在のexpert計算と重ねる。Dual-Batchは、このCPU側の計算・再配置を次の2バッチの準備へ隠す処理順である。
## 評価

### まず見るところ
- **結論:** routing予測・token再編成・cache配置をまとめて最適化すると、CPU offload時のexpert miss待ちを大きく隠せる。
- **速度・効率:** cacheが小さい条件ほど改善が大きく、複数のMoEモデルで既存cache方式を上回る。
- **品質:** 予測はprefetch用で、外れたexpertは実行時に補正するため**lossless**。
- **メモリ・I/O:** GPU expert cacheを大幅に縮めても推論可能。CPU DRAMからのweight offloadが中心。
- **評価の強さ／注意点:** **実機**。RPPの学習と2-batch単位のtoken/KV再配置が必要で、主評価は単一A40。大規模Expert Parallelは未評価。
