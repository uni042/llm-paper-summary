# Adaptive Layer-skipping in Pre-trained LLMs

> 入力と層の状態に応じたlayer skippingで、事前学習済みLLMの品質を保ちながら実行深度を削減する方式。

## 概要
FlexiDepthは、元LLMの重みを凍結したまま、**tokenごと・layerごとにfull処理かskip経路かを選ぶ**plug-in型dynamic depth手法である。

固定layer pruningと違い、簡単なcopy tokenは浅く、計算・不確実性の高いtokenは深く処理できる。各可変層には小型routerとadapterだけを追加し、元attention/FFNは更新しない。

特徴的なのは、skipしても単にhidden stateを素通しせず、`adapter`で表現を補正し、さらに将来tokenのためのK/Vは残すこと。これにより固定skipより品質をかなり守れる。

Llama-3-8Bでは平均8層skipでもbenchmark平均100.7%を維持する一方、論文自身が**wall-clock speedupは未達**と報告する。不規則なtoken分岐とadapter/routerの追加I/Oが、減ったFLOPsを相殺するためである。

## 手法のあらまし

### 1. `FlexiDepth Layer`：full経路とskip経路を並列に持つ

可変層ではrouterが各tokenに対してgating score `g` を出す。

- `g > τ`：通常のattention + FFNを実行
- `g ≤ τ`：重いblockをskipし、小型adapterを通す

つまりlayer自体を削除するのではなく、**tokenごとに二つの経路から選ぶ**。

### 2. `Bottleneck Router`

routerは単純な1本のlinear classifierではなく、hidden dimensionを `d/16` 程度へ縮めて戻す小型MLPを使う。

ablationではlinear routerだと品質保持率が大きく落ちており、token難度を判定するにはある程度の非線形性が必要だった。

### 3. `Skip Adapter`：素通しではなく表現を補正する

attention/FFNを飛ばしたhidden stateをそのまま次層へ渡すと、元modelが期待する表現空間からずれる。

そこでskip側にも中間次元1/16程度の小型FFN adapterを置く。

adapterなしのablationで品質が大きく崩れるため、FlexiDepthでは**「層を飛ばす」より「安い近似変換へ置き換える」**と理解した方が正確である。

### 4. SkipしてもK/Vは残す

attention計算をskipするtokenでも、将来tokenがそのtokenを参照できるようK/Vは作ってcacheする。

つまり削るのは主にquery側attention計算やFFNで、文脈情報そのものを消すわけではない。

`No KV Cache` ablationで品質が落ちるため、この処理が長いgenerationで重要になる。

### 5. `SparseMixer`

routerのhardな経路選択を学習可能にするためSparseMixerを使う。

D-LLMのGumbel-Softmaxと同じく、「推論時は離散的にskipするが、学習時にはgradientを通す」ための仕組みと考えればよい。

### 6. `DepthMap`

FlexiDepthは各tokenが何層使ったかを可視化した `DepthMap` を分析する。

copy / repeatは浅く、summarize / continue / addition / multiplicationは深くなる傾向があり、単なる平均skip率だけでなく「どのtokenへ計算を使ったか」を確認できる。

## 評価

### まず見るところ
- **結論:** token-adaptive routingで固定skipより大幅に品質を守れる。
- **品質:** Llama-3-8Bで8層skipしても平均benchmarkはほぼbaseline。
- **理論計算:** FLOPsは減る。
- **実速度:** **wall-clock speedupは未達**。
- **重要な示唆:** dynamic depthはalgorithmだけでなく、token groupingやspecialized kernelまで必要。

### Llama-3-8B：主要benchmark

| Setting | MMLU | HellaSwag | WinoGrande | GSM8K | HumanEval | CoQA | 平均保持率 |
|---|---:|---:|---:|---:|---:|---:|---:|
| Vanilla | .673 | .706 | .744 | .679 | .299 | .784 | 100% |
| 4 layer skip | .663 | .724 | .756 | .695 | .390 | .810 | **106.5%** |
| 8 layer skip | .616 | .705 | .735 | .662 | .341 | .801 | **100.7%** |

4層skipでは一部taskがbaselineを上回る。

### 8層skip：固定skip系との比較

| Method | 平均保持率 |
|---|---:|
| FlexiDepth | **100.7%** |
| LaCo | 65.3% |
| MindSkip | 60.2% |
| LayerSkip型固定比較 | 43.9% |
| ShortGPT | 32.0% |

特にGSM8K/HumanEvalでは固定skipの崩れが大きい。

### モデルサイズとskip余地

| Model | 平均skip層 | 品質保持率 |
|---|---:|---:|
| Llama-2-13B | 6.42 | 100.2% |
| Llama-3-8B | 6.25 | 102.1% |
| Qwen-2.5-3B | 1.49 | 101.5% |

小型modelほど冗長性が少なく、skipできる層が減る。

### DepthMapの平均使用層

| Task type | 平均使用層 |
|---|---:|
| Copy | 21.95 |
| Summarize | 28.65 |
| Continue | 30.27 |
| Repeat | 20.09 |
| Addition | 22.45 |
| Product | 23.90 |

### Ablation

| 変更 | 品質保持率 |
|---|---:|
| Full FlexiDepth | baseline近傍 |
| Linear router | 68.7% |
| KVを作らない | 84.3% |
| Adapterなし | 28.1% |

adapterとKV保持が手法成立の中心である。

### 実速度が伸びない理由

- tokenごとにfull/skip経路が分かれる
- routerとadapterのweight accessが増える
- GPU kernelがdenseなbatchを作りにくい
- control flowとmemory trafficがFLOPs削減を相殺する

このため、**algorithm上は省計算でも現状runtimeではwall-clock改善なし**。
