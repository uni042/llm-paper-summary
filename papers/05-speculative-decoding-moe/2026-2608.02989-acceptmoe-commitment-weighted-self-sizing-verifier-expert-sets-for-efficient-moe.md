# AcceptMoE: Commitment-Weighted Self-Sizing Verifier Expert Sets for Efficient MoE Speculative Decoding

> draft nodeの受理確率とtarget router scoreから検証expert集合を層ごとに縮小し、offload時はresident expertを優先して転送量を削減する。

## 概要
AcceptMoEは、speculative decodingのverificationで**target routerが本来選ぶexpertを全部実行せず、重要度の高いexpert集合だけに縮める**近似手法である。

SP-MoEやEcoSpecは、どのexpertを先に読むか／どのdraft nodeを検証するかを変えても、最終的にはnative target expertをそのまま実行する。AcceptMoEはそこから一歩進み、rejectされやすいdraft枝のためだけに必要な低寄与expertはverificationから外す。

各draft nodeのacceptance probabilityとtarget router scoreを掛け合わせてexpertの重要度を作り、layerごとに必要なexpert集合の大きさを自動調整する。offload条件ではGPU resident expertを優先し、cache-missする低寄与expertは実行しない。

その結果H2D transferは大幅に減るが、native Top-kを完全には再現しないため**losslessではない**。平均task scoreの低下は小さいものの、品質–I/O trade-offを持つ。

## 手法のあらまし

### 1. `Commitment Weight`

各draft nodeには「そのnodeまでtargetにacceptされそうな確率」がある。

AcceptMoEはこれを、target routerが各expertへ与えるscoreと掛け合わせる。

高acceptanceなbranchでrouter scoreも高いexpertは重要、rejectされやすいbranchだけで使われるexpertは重要度を低くする。

### 2. `Self-Sizing Verifier Expert Set`

通常は各draft tokenについてnative Top-k expertを全部集めるため、treeが広いほどexpert unionが大きくなる。

AcceptMoEはlayerごとのimportance分布を見て、**そのlayerで何expertまで実行するか自体を動的に決める**。

固定Top-k reductionではなく、router entropyや累積importanceに応じて集合サイズを変える。

### 3. Router entropyで縮小強度を変える

router分布が尖っているlayerでは、上位expertの寄与が支配的なので集合を強く縮めやすい。

一方、分布が平坦なlayerでは複数expertが重要なので多く残す。

つまり「毎layer同じ数を削る」のではなく、**そのlayerのrouting confidenceに合わせて縮小率を変える**。

### 4. Offload-aware selection

同程度のimportanceなら、GPU resident expertを優先する。

cache-miss expertを選ぶとH2D weight transferが発生するため、resident expertを使える場合はそちらへ寄せる。

### 5. `Weight Renormalization`

除外したexpertのrouting weightをそのまま消すと出力scaleが変わる。

そこで残したexpertへweightを再正規化し、選択集合内の出力を再配分する。

ただしnative expert出力を別expertで近似するため、ここが品質差の発生源になる。

### 6. EcoSpecとの違い

| 手法 | 削るもの | 品質 |
|---|---|---|
| EcoSpec | draft treeのnode | Lossless |
| EVICT | verification対象node | Lossless |
| AcceptMoE | **verification expert集合そのもの** | **Approximate** |

この違いが最も重要。

## 評価

### まず見るところ
- **結論:** verification expert集合を縮めると、offload環境ではH2D transferを大幅に減らせる。
- **実速度:** 通常SD比平均1.29×、RTX 5090 offload条件で最大2.06×。
- **I/O:** H2D bytesを約74〜77%削減。
- **品質:** **losslessではない**。平均score低下は約0.27 point。
- **注意点:** 長いgenerationで近似誤差が累積するworst caseは十分未検証。

### 品質

平均task scoreの変化は約 **−0.27 point**。

小さい差だがzeroではなく、target native expert集合を変更している以上、lossless speculative decodingとは別カテゴリーとして扱う必要がある。

### Threshold trade-off

| 集合縮小 | 速度 / I/O | 品質 |
|---|---|---|
| 弱い | 改善小 | nativeに近い |
| 中程度 | 大きく改善 | 小さい低下 |
| 強い | 最大改善 | 重要expert除外リスク増 |

### どの条件で効きやすいか

- draft treeが広くexpert scatteringが大きい
- VRAMが小さくcache missが多い
- H2D transferがcritical pathを支配
- router distributionが尖っているlayerが多い

### 制約

- acceptance probabilityのcalibrationに依存。
- router entropyが高いlayerでは強く縮めにくい。
- 長文generationでの誤差蓄積は十分未検証。
- domain shift時の品質保証なし。
- energy/tokenは未評価。
- 公式codeは確認できない。
