# SP-MoE: Speculative Decoding and Prefetching for Accelerating MoE-based Model Inference

> speculative decodingとexpert prefetchを統合し、ドラフト生成中に検証で必要なMoE重みを先読みして待ち時間を減らす手法。

## 概要
SP-MoEは、speculative decodingのdraft処理を単にtokenを先に生成するためだけでなく、**target modelが将来使うexpertを早く知るための先読み窓**として利用する。

CPU offloadされたMoEでは、target routerがexpertを確定してからweight転送を始めるとPCIe待ちがcritical pathに入る。SP-MoEはdraft生成中にtarget側のexpert候補を推定し、その時間を使ってCPU→GPU転送を始める。

ただしdraft tokenが増えるほど候補expert集合も広がり、VRAM cacheを追い出したりPCIeを無駄に使う危険がある。そこで `cutoff layer`、段階的prefetch、転送の優先度制御を入れ、**どこまで先読みするか**まで最適化する。

品質面は通常のspeculative decodingと同じくtarget modelが最終verificationを行うため、prefetch予測ミスは基本的に速度へだけ影響する。

## 手法のあらまし

### 1. Draft hidden stateをtarget gateへ通す

draft modelの各層で得たattention出力をhookし、target model側のgating networkへ入力する。

これにより、targetを本当にその層まで実行する前に「このtokenはどのexpertへ行きそうか」を推定する。

別の専用predictorを学習するのではなく、**draft modelの中間表現＋target gateを組み合わせてroutingを先読みする**点が特徴である。

### 2. `Expert Lookahead Buffer`

予測したexpert IDとconfidenceを、token×layer単位で `Expert Lookahead Buffer` に保存する。

runtimeはこの表を見ながら、verificationで近いうちに必要になりそうなexpertからprefetchする。

### 3. `Cutoff Layer`：深く先読みしすぎない

全layer分を一気にprefetchすると、将来使わないexpertまでGPUへ入り、cache evictionとPCIe競合を起こす。

SP-MoEではhardware latency modelを使い、prefetchを行う深さにcutoffを設ける。

つまり「予測できるだけ先まで読む」のではなく、**今の帯域とcache容量で得になる範囲だけ読む**。

### 4. 3段階のprefetch

転送は大きく3段階に分かれる。

- Phase I：最優先expertを早く送る
- Phase II：空き帯域で追加候補を送る
- Phase III：verification直前に残りの高確率候補を詰める

これにより、urgentなnative demand loadと低優先prefetchが同じPCIeを奪い合うのを抑える。

### 5. `Reordered Inference`

verificationではexpertを元の順番通り待つのではなく、

1. すでにcache済み
2. 転送中
3. まだ未転送

の順に計算する。

cache済みexpertを計算している間に転送中expertを到着させ、I/O stallを隠す。

### 6. Draft lengthは長いほど良いわけではない

speculationを長くするとprefetch windowは広がるが、同時に候補expert集合も増える。

SP-MoEでは、**draft lengthとexpert localityのtrade-off**がMoE特有の問題になる。

## 評価

### まず見るところ
- **結論:** speculative draftをexpert先読みへ再利用すると、CPU offloadのweight I/Oをverification前へ移せる。
- **実速度:** RTX 3090/4090/A100で実測し、modelによって1.1〜3.5倍程度。
- **品質:** target verificationを維持するため**lossless**。
- **注意点:** draftを長くしすぎるとexpert scatteringとcache thrashingが増える。

### 最大値

DeepSeek-Lite + HumanEval + A100では、Mixtral-Offloading系baselineに対して最大約3.5×を報告する。

### Cutoffの意味

prefetch depthを増やすと初めはhit率が上がるが、5層超など深くしすぎるとVRAM evictionとPCIe競合が増え、性能が逆に落ちる条件がある。

### 制約

- batch 1中心。
- greedy speculative decoding中心。
- tree speculationや大規模continuous batchingは未評価。
- predictor missは品質ではなく余分なI/Oとして現れる。
- draft acceptanceとexpert localityの両方に依存。
