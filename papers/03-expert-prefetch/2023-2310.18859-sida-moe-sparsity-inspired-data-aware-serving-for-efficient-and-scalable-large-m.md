# SiDA-MoE: Sparsity-Inspired Data-Aware Serving for Efficient and Scalable Large Mixture-of-Experts Models

> LSTM予測器で次batchの活性expertを推定し、必要重みだけをCPUからGPUへ先読みするdata-aware MoE serving方式。

## 概要
SiDA-MoEは、推論時に実際に選ばれないexpertがGPUメモリの大半を占めるというMoE固有の無駄を、入力データごとのexpert予測で解消するシステムである。学習・finetuning手法ではなく、Switch Transformerの既成重みをedge／consumer GPUでservingする推論ランタイムであり、全expertをGPUへ常駐させず、CPUの大容量main memoryを第二階層として使う。Switch-base-8／64／128／256（expert数8、64、128、256）を対象に、短文SST2、中程度のMRPC、長文MultiRCを測定した。大規模モデルではMoE部分が14–54 GBを占め、Switch-base-256の総量54.62 GB中54.114 GB（99.07%）がMoEパラメータになる一方、1回のforwardで動くexpertは少数である。
従来のStandard、DeepSpeed、Tutelは入力に依存しない常駐・通信最適化で、GPU上に使わない重みを残す。SiDAはLSTM予測器が次batchのexpert活性化を先に推定し、必要なexpertだけGPUへ転送し、他をRAMへ戻す。抽象的な「最大80%節約」だけでなく、Switch-base-128／256のSST2・MRPCで60–80%超のGPUメモリ削減、最大3.93倍throughput、latencyをbaselineの28%まで下げる点が実機導入上の価値である。品質は「ほぼ無損失」とされるが、モデルを変更しない代わりに予測ミスが起きるため、タスク・文長・top-k設定に依存する。
## 手法のあらまし
処理はInference threadとHash-building threadの2本を並列に走らせる。入力batch X_jをhash threadへ送り、hash table H_jに各MoE layer・tokenの予測expertを格納する間、inference threadは直前batch X_iを実行し、H_iを参照してGPU上のexpertを確認する。GPUにないexpertだけをCPU main memoryからCUDAへ移し、layer処理後は次の予測に合わせて不要expertをoffloadする。バッチサイズ1で予測・実行を時間的にずらすため、予測計算を推論critical pathから外し、expert移動と計算を重ねる。
hash predictorは2-layer LSTMにsparse attentionを付け、MoE routerのexpert IDとscaling factorを模倣する。通常のknowledge distillationでは小型LSTMにlogit全体を再現させるのが難しいため、top-T Softmax位置だけを使うTruncated KD（T=30）とcross-entropyを併用し、目的関数を`λL_CE+L_TKD`とする。短文SST2はtop-1、MRPC／MultiRCはtop-3予測を使う。予測精度はSwitch-base-8でSST2 99.00%、MRPC 97.41%、MultiRC 91.74%、Switch-base-128でも98.78%、98.65%、90.49%。sliceとexpertの対応をlayer間で保持し、共有queueを同期するmanagerが必要で、CPU-GPU転送のrace conditionとqueue contentionを避ける実装が要点である。
## 評価

### まず見るところ
- **結論:** 小型LSTMで次batchのroutingを先に予測すると、Switch系MoEのGPUメモリとoffload待ちを大きく減らせる。
- **速度・効率:** 大きなSwitchモデルほどthroughput/latency改善が大きい。
- **品質:** **厳密losslessではない**。予測器がrouterを近似するため、task accuracyは概ね保ててもperplexityは明確に悪化するケースがある。
- **メモリ・I/O:** GPUメモリ削減は大きく、expert本体はCPU RAMへ置く。SSDは評価していない。
- **評価の強さ／注意点:** **実機**だがA100＋Switch中心。長文やdomain shiftで予測精度が落ちると品質・速度の両方に影響する。

実験はNVIDIA A100 80 GBとIntel Xeon Platinum 8358（64 CPU、2.60 GHz）のサーバで、batch size 1、AdamW、hash学習batch 64、SST2／MRPC／MultiRCのtrain/test分割を使用した。ベースラインはStandard、DeepSpeed-MoE、Tutelで、accuracy（SST2）、F1（MRPC／MultiRC）、GPU memory、samples/s、latencyを比較した。Switch-base-128／256のSST2では、baseline平均に対するthroughputがそれぞれ2.60倍／3.93倍、MRPCは2.52倍／3.83倍、MultiRCでも1.26倍／1.57倍。latencyは大規模モデルのSST2／MRPCでbaselineの25%程度、MultiRCで約60%まで低下した。
メモリ削減は短文でSwitch-base-128／256が80%超、MRPCで6.28 GB（base-128）と19.84 GB（base-256）、長文MultiRC（200–500 token）でもbase-128が20%超、base-256が40%超（4.52 GB／9.92 GB節約）。perplexityはSwitch-base-8のpretrained 6.68に対しSiDA 18.49、base-64は4.93→11.84、base-128は4.86→11.73、base-256は4.59→8.11で、特に小型モデルでは劣化が相対的に大きい。fine-tuning fidelityはbase-8で最大99%、base-128で最大96%。限界はA100＋CPUサーバ評価でスマホSoCやSSDを測っていないこと、予測誤り・長文・domain shift、hash threadの追加メモリと同期、routerを置換するため厳密な元モデル出力を常に保証しない点である。
