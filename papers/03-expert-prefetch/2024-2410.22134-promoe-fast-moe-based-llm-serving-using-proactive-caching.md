# ProMoE: Fast MoE-based LLM Serving using Proactive Caching

> 軽量予測器で将来のexpert選択を先読みし、proactive cachingでCPU–GPU転送を計算に重ねるMoE serving方式。

## 概要
ProMoEは、GPU容量より大きいMoE-LLMを消費者向けPCで低遅延に提供するための先行キャッシュ方式である。従来のLRU・静的キャッシュは、要求エキスパートが確定した後にCPUからGPUへ移すため、その転送がクリティカルパスとなる。ProMoEは、過去のゲート出力から複数層先の選択を予測し、推論前にGPUキャッシュへロードする。予測の良さを正解率だけでなく、転送を開始できる先行時間も含むGOODPRED（accuracy×fetch rate）で定義した。さらにchunked prefetch、early preemption、reordered inferenceで低優先度の予測転送と確定要求を調整する。transformersとllama.cppへ約6600行のC++拡張として実装され、vLLM/TGIは当時の量子化MoE・バッチ対応の都合で統合していない。
ProMoEは、expertをCPUへ置くこと自体を減らすのではなく、転送を計算の前に終わらせることを目標にする。特にprefillではプロンプト内の多数トークンがほぼ全expertを触るため、LRUが同じ層でキャッシュを何度も追い出す。この場合、将来アクセスを予測し、アクセス順を入れ替える方が固定キャッシュより有効になる。decodeでは1トークンの計算量が小さく転送が相対的に重いため、ミスの早期検知と先行時間が重要になる。GOODPREDを導入したのは、正解率だけ高くてもロード開始が遅ければ実行に間に合わないという問題を定量化するためである。
## 手法のあらまし
Predictorは履歴ゲート・中間結果を入力に、sliding-windowで将来層のエキスパート集合を出す。Prefetcherは予測集合を低優先度で送り、ゲートが現在層の正確な要求を確定すると、early preemptionで同層の未完了推測を捨て、必要エキスパートを高優先度に切り替える。各FFNは3線形層からなるため、転送を3チャンクに分割し、急なミス要求が来ても最大1チャンク待ちで切り替える。reordered inferenceでは、キャッシュ済み、転送中、未開始の順にエキスパートを計算し、転送中の欠落分を他の計算に重ねる。ProMoEが扱うモデルはDeepseek-moe 16.4B（64層中28、top-6）、DeepSeek-V2-Lite 15.7B、Qwen1.5-MoE 14.3B、Qwen2-57B-A14B、Mixtral-8x7B等である。静的キャッシュ、LRU、Unified Memory（ページ単位）、llama.cppのlayer offloadを比較する。キャッシュ率が低いと、転送量の多さからCPU計算を使うlayer offloadが有利になる場合もある。
predictorの履歴は複数層のexpert選択をまとめて扱い、sliding windowで次に必要になる集合を作る。chunked prefetchは各expertの3つの線形層に対応して転送を分割し、緊急要求が来たとき低優先度処理を細かく中断できる。ゲートの終了時点で現在層の全要求が分かるため、expertを一つ計算してからミスを発見する方式より早くearly preemptionを発行できる。reordered inferenceはキャッシュ済みexpertを先に実行し、その間に転送中expertを待つことで待ち時間を隠す。実装はメモリ管理も引き受けるため、一般的なLLMフレームワークのキャッシュ機構と併用するだけでは再現できない。
## 評価

### まず見るところ
- **結論:** expert予測を早めに出し、転送をchunk化・中断可能にすると、consumer GPUのCPU offload待ちを実際に短くできる。
- **速度・効率:** prefill/decodeとも既存LRU・static cacheより改善し、とくにcache thrashingが強い条件で効く。
- **品質:** 予測ミス時は正しいexpertを高優先度で読み直すため**lossless**。
- **メモリ・I/O:** CPU DRAM→GPUのweight transferを先行させる方式で、SSDは対象外。
- **評価の強さ／注意点:** **RTX 4090実機＋llama.cpp/Transformers**。単一request中心で、continuous batchingやvLLM/TGI servingは未評価。

RTX 4090 24GB、Core i9-14900K、DRAM64GB、PCIe4.0（一方向32GB/s）で、ShareGPTを用い、DS-1/DS-2/QW-1はFP16、QW-2とMixtralはINT4で測定した。transformers実装のprefillではProMoEがStatic比平均1.52倍、LRU比2.32倍、decodeではStatic比1.52倍、LRU比1.33倍。QW-2のcache rate変化ではprefillのLRU比平均1.75倍（最大2.20）、Static比1.43倍、クリティカルパスのロード時間をStaticの54.78〜75.37%に対しProMoEは11.18%まで下げた。DS-1では同ロード時間が25.61%となった。llama.cppではprefillのLRU比1.532倍、Static比1.104倍、decodeのLRU比1.14倍、Static比1.269倍。QW-2のバッチ1→4でLRU比speedupは1.16→1.34倍へ伸び、cache thrashingを抑えた。アブレーションではearly preemptionが1.27倍、reordered inferenceが2.29倍（base比）寄与した。制約は単一要求・エッジ向けで、vLLM/TGIなどデータセンター連続バッチを対象外、予測ミス時は正しいエキスパートを結局オンデマンド転送すること、INT4/FP16の量子化・PCIe・モデル構造に性能が依存することである。
