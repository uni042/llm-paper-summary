# OD-MoE: On-Demand Expert Loading for Cacheless Edge-Distributed MoE Inference

> 常設expert cacheを持たず、shadow modelで数層先を予測してworkerへ必要expertだけを一時ロードする分散edge MoE方式。

## 概要

OD-MoEは、GPUへhot expertを固定常駐する通常のcache方式をやめ、**必要expertを実行直前だけworker GPUへ載せ、計算後すぐ破棄する**cacheless設計である。

構成はmain node、shadow node、8 worker nodesの計10台。

- main：attention / gateなどnon-expert部分
- shadow：軽量化したshadow modelで数層先routingを予測
- workers：expert weightをloadしてFFNを実行

に役割を分ける。

予測ミス時もmain nodeのnative gate結果に従って正しいexpertを後からloadするため、品質はlossless。代わりにnetwork同期とshadow計算のコストを負担する。

## 手法のあらまし

### 1. `SEP`：Shadow-Emulative Predictor

shadow nodeは元モデルをFP16 / INT8 / NF4で軽量化して追跡し、数layer先のexpert routingを予測する。

単純classifierではなく、元modelのstate evolutionをshadow modelでエミュレートする方式である。

### 2. Main / Shadowのstate alignment

autoregressive生成ではshadow側の状態が徐々にずれるため、

- token alignment
- KV-cache alignment

でmain nodeと同期する。

alignmentを省くと長い生成でrouting recallが急落する。

### 3. Workerを4 groupへ分割

Mixtralのtop-2に合わせ、8 workerを2台ずつ4 groupへ分ける。

あるgroupがlayer `l` のexpertを計算している間に、他groupが `l+1`,`l+2`,`l+3` のexpertをloadする。

計算groupとload groupをround-robinで入れ替えることで、network / storage loadをexpert computeへ重ねる。

### 4. Cacheless loading

workerはexpertを恒久cacheしない。

予測されたexpertを実行直前にloadし、計算後は解放する。

固定cache容量をhot expertへ予約しないため、layerごとの需要変動へ柔軟に対応できる。

### 5. Prediction missは速度だけを損なう

SEP予測とnative gateが一致すればexpertは準備済み。

不一致ならnative expertを追加loadしてから実行する。

したがって誤予測でexpertを置換・skipせず、出力品質を変えない。

### 6. Network cost

main / shadow / worker間でembeddingやKV状態を送るため、GPU memory削減の代わりにEthernet trafficが増える。

論文の実機は1 Gbps Ethernetで、この帯域とalignment頻度がend-to-end性能に直接効く。

## 評価

### まず見るところ
- **結論:** cacheを持たなくても、高recallなshadow predictorとworker pipelineがあればedge clusterでMoEを動かせる。
- **速度:** decode平均約3.69 t/s。既存offload系を上回るがall-GPUには届かない。
- **品質:** predictionはloading専用で、native expertへfallbackするためlossless。
- **メモリ:** worker GPUを各約1GBまで削れる一方、shadow nodeに約45GB必要。
- **注意点:** 10-node構成とalignment trafficが大きな実装コスト。

### Testbed

| Role | 台数 | 主用途 |
|---|---:|---|
| Main | 1 | non-expert計算 / native gate |
| Shadow | 1 | SEP prediction |
| Worker | 8 | expert load / compute |

Networkは1 Gbps Ethernet。

### SEP recall

| Shadow precision | Expert recall |
|---|---:|
| FP16 | **99.94%** |
| INT8 | 97.34% |
| NF4 | 95.67% |

既存predictor系の代表値より高い。

### GPU memory

総GPU memoryは約60GB。

- main：約7GB
- shadow：約45GB
- workers：各約1GB

全expertをcacheする構成の約1/3まで削減する。

### Throughput

| Method | 平均 output throughput |
|---|---:|
| OD-MoE | **3.37 t/s** |
| Mixtral Offloading | 2.17 |
| MoE-Infinity | 0.67 |
| HOBBIT | 0.76 |
| AdapMoE | 3.04 |

OD-MoEのdecode単体は平均約3.69 t/s。

all-GPU Transformerは約4.89 t/sで、完全全載せには及ばない。

### TTFT

平均TTFTは約2244 ms。

AdapMoE約1387 ms、Mixtral Offloading約1845 msより遅く、shadow / alignment準備がprefill側では不利になる。

### Alignmentの重要性

INT8 shadowでalignmentを外すと、routing recallはtoken 1で100%近くてもtoken 256付近で約30%、平均約45%まで低下する。

長いgenerationほどstate synchronizationが必要になる。

### 制約

- 10ノード必要。
- shadow nodeが大容量GPU memoryを消費。
- 1 Gbps network同期が性能へ影響。
- 主評価はMixtral-8x7B。
- TTFTでは一部baselineに劣る。
