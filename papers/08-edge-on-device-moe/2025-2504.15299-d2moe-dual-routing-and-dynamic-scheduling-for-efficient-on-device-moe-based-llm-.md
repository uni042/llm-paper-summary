# D²MoE: Dual Routing and Dynamic Scheduling for Efficient On-Device MoE-based LLM Serving

> トークン単位とデバイス単位の二段階routingを協調させ、edge環境でMoEの計算量とデータ移動を抑える手法。

## 概要
D²MoEは、expertを「使う/使わない」だけでなく、**そのexpertを何bitで読み込むか**までtokenごとに選び、SSD/CPU→GPU転送と計算をdevice条件に合わせて組み立てるedge向けruntimeである。

## 手法のあらまし

### 1. `Matryoshka Weight Quantization (MWQ)`

MWQはINT2、INT3、INT4を完全に別々のweight copyとして持たない。

低bit表現を土台にして追加bitを積み重ねる **nested residual形式** にし、

`INT2 + 追加bit = INT3`

`INT3 + 追加bit = INT4`

のように復元する。

そのためINT2/3/4を三重保存するよりmemoryとI/Oを節約できる。

### 2. `bit-width router`

native MoE routerが「どのexpertを使うか」を決めるのに対し、bit-width routerは **そのexpertを何bitで実行するか** を決める。

入力tokenの状態とexpert重要度から、INT2 / INT3 / INT4のどれを使うかを選ぶ。頻繁に重要なexpertや品質感度の高いtokenには高bit、影響の小さい箇所には低bitを割り当てる。

このrouterはC4で追加学習するため、完全training-freeではない。

### 3. deviceごとにI/Oとcomputeをprofileする

各bit幅について、

- `T_io(b,k)`：そのexpert/bitを読み込む時間
- `T_comp(b,k)`：そのbitで計算する時間

を事前測定する。

RTX 3060のようなPCIe＋SSD構成と、Jetsonの共有memory構成では最適なbit配置が違うため、**同じpolicyを全deviceへ固定しない**。

### 4. `HEBF`：Hottest-Expert-Bit-First

Hottest-Expert-Bit-First（HEBF）は、利用頻度が高いexpertの重要bit planeを優先して転送・常駐させるschedulerである。

memoryに余裕があるならhot expertを高bitで保持し、厳しいときは低bit版だけを残す。

### 5. SSD I/OとGPU計算をpipeline化する

bit-width-aware pipelineは、現在のexpertをGPUで計算している間に次のweightをSSD/CPU側から読み込む。

ここで低bit化は単なるVRAM削減ではなく、**SSD→GPUで運ぶbyte数を減らしてI/Oを隠しやすくする手段**としても働く。

## 評価

### まず見るところ
- **結論:** expertごとにINT2/3/4を選び、device帯域に合わせてI/O/計算をscheduleすると、低VRAM laptopでもMoEを実用速度で動かせる。
- **品質:** 近似量子化だが、標準設定では高bit baselineにかなり近い。
- **実速度:** RTX 3060 / Jetson実機で既存edge offloadよりthroughput改善。
- **I/O:** **Samsung 970 EVO SSDからのweight readを含む実機評価**。
- **注意点:** bit-width routerの学習、device profiling、dequantization overheadが必要。

### 実機構成

| 環境 | 主な構成 |
|---|---|
| Laptop | RTX 3060 6GB + i7-11800H + RAM 32GB |
| SSD | Samsung 970 EVO、read約3.5GB/s |
| Edge | Jetson AGX Orin 64GB |

モデルはLLaMA-MoE-3.5BとMixtral 8x7Bを使用する。

### 品質

| モデル | 高精度baseline | D²MoE |
|---|---:|---:|
| LLaMA-MoE PPL | 14.55 | 14.58 |
| Mixtral PPL | 4.04 | 4.09 |
| Mixtral PIQA | 82.4 | 82.29 |

標準設定では量子化による品質低下は小さい。

### RTX 3060でのthroughput

| 比較対象 | D²MoEの改善 |
|---|---:|
| EdgeMoE / LLaMA-MoE系 | 1.14〜1.39倍 |
| MoQE-DynaIO | 1.42〜3.37倍 |

memory使用量も既存方式比33〜53%削減した。

### memory制約が厳しい場合

Hold-in-Memory-AWQは2500MBで94.3 token/s。一方D²MoEは1600MBで89.14 token/sを維持する。

さらに他方式がmemory不足で動かせないMixtral条件でも38.07 token/sを報告する。ここでは最高速度より、**より小さいmemory budgetでモデルを成立させること**が重要である。

### runtime overhead

| 項目 | overhead |
|---|---:|
| bit-width router compute | 0.22〜0.28% |
| router memory | 0.12〜0.53% |
| router latency | 1.04〜1.67% |

一方MWQ dequantizationはより重く、Mixtralではrequest数によって計算overheadが約16〜21%になる。したがって低bit化でI/Oを減らしても、dequantization kernelが弱いと利得を食う。
