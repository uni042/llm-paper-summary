# FreeToken: Efficient Edge-Native MoE Serving with Bandwidth-Adaptive Execution

> GPU・CPU・RAM・PCIeを統合資源として扱い、global expert cache、帯域適応CPU/GPU実行、KV再利用を一体化した個人PC向けMoE runtime。

## 概要
FreeTokenはpersonal machineを「小さなGPU」ではなく、GPU、CPU、host memory、PCIeを束ねたelastic platformとして扱うedge-native MoE serving systemである。固定offload policyはhardwareごとのCPU/GPU比やagentic workloadのphase変化に適応できず、expert cacheとKV cacheがVRAMを奪い合う。FreeTokenはmodel layout／loading、expert residency、CPU-GPU co-execution、agent state reuse、runtime memory allocationを一つのstackでco-designする。登録済みMoE-Infinity、ProMoE、ExpertFlow、FineMoE、HOBBIT、SiDA、SMoE、Pre-gated MoE、Fiddler、KTransformers、HybriMoEを引用し、研究機構をdeployable local softwareへ統合した後続である。8GB laptop GPUから単一workstation GPUまで20以上のMoE modelを対象にし、35Bをlaptop、284Bをgaming desktop、753B GLM-5.2をworkstationでserveできるとする。主memory hierarchyはCPU RAM＋GPU VRAMで、通常SSD／NVMeをperformance-critical expert tierとして詳細評価する研究ではない。KVとexpert重みは明確に別管理しつつVRAM予算を共有する。
## 手法のあらまし
FTW weight formatでlocal loadingとCPU/GPU kernelが扱いやすいlayoutを作り、prefillはfull-layer double bufferingでweight streamingと計算を重ねる。decodeではglobal LRU expert cacheを全layer横断で管理し、layer固定quotaによる未使用spaceを避ける。runtimeは実測したCPU memory bandwidth、GPU throughput、PCIe bandwidthからexpert tokenをCPUとGPUへ動的配分し、どちらか一方のstragglerを抑える。GPU memoryは固定partitionせず、context長とrequest数に応じてexpert cacheとKV cache間で弾力的に再配分する。agentic multi-turn workloadではsemantic anchor checkpointによりtool call前後のKV／stateを再利用し、再prefillを減らす。native routerとmodel qualityは維持し、expert数をpruneするapproximationではない。適応粒度はrequest phase／layer／expert batchで、predictorによる次expert予測よりcache localityとbandwidth feedbackを重視する。
## 評価

### まず見るところ
- **結論:** personal PCのCPU・GPU・RAM・PCIeを一体で使い、expert/KVのVRAM予算まで動的配分すると、巨大MoEをlocalで高throughputにserveできる。
- **速度・効率:** laptop〜RTX 5090まで幅広い実機で既存runtimeを上回り、35B〜753B級までcapacityを拡張する。
- **品質:** native router/expert計算を維持するため**lossless system optimization**。pruning/substitution型ではない。
- **メモリ・I/O:** 主階層は**CPU RAM＋GPU VRAM**。SSDをperformance-critical expert tierとして検証した研究ではなく、KVとexpert cacheは別管理しつつVRAMを共有する。
- **評価の強さ／注意点:** **20以上のモデル・複数consumer GPU実機＋Apache-2.0実装**で成熟度が高い。ただし性能はCPU bandwidth、PCIe、quantized kernel、cache hitに強く依存する。

<details>
<summary>評価条件・詳細な数値を開く</summary>

Qwen3.6-35B-A3B、DeepSeek-V4-Flash、GLM-5.2 753Bを含む20以上のMoE modelを、RTX 4060 laptopからRTX 5090 workstationまで実機評価する。RTX 5090でQwen系77〜83 tokens/s、DeepSeek系22〜25 tokens/s、既存baseline比1.5〜2.3倍。8GB RTX 4060でも35B級modelで39.3 tokens/sを報告し、global LRUは同容量でKTransformers／llama.cppより低いmiss rateを示す。大規模modelを動かせるcapacityとinteractive throughputを同時に評価し、simulation-onlyではない。性能はCPU RAM bandwidth、PCIe topology、quantized kernel、cache hitへ強く依存し、全modelで同じspeedupではない。SSD読出し量、HBF、CXL、学術benchmark qualityの詳細なPareto評価は限定的で、agent state reuseはworkload依存が大きい。一方、Apache-2.0 code、installable package、desktop app、API、tests、documentationが公開され、今回候補中では実装成熟度が高い。
