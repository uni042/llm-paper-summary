# 本文の再確認と永久除外

## 本文を取得できない場合

通常の本文経路と、同じ研究の別の公式経路を各1回確認する。両方失敗したら `insufficient_primary_source` として `survey-state/retry-papers.json` に記録し、次の対象へ進む。本文内容を抄録や検索断片から推測しない。

日次選定中なら当日枠に入れず別候補を探す。精読中なら当日項目を決着させるが全文精読には数えず、その枠を毎時補充しない。保存競合・認証・実行基盤障害は論文の取得失敗と分け、未完了または外部対応が必要な問題にする。

## 再確認の間隔

- 初回失敗から7日後に再確認し、以後も最後の確認から7日以上空ける。期限が来た候補は日次選定で扱う。
- 本文を取得できたら、取得先・確認日・版を残して再確認状態を `available` にし、通常の優先順位で候補へ戻す。取得できただけで精読完了にはしない。
- 初回を含む5回以上が失敗し、初回から28日以上経過したら `dormant` として定期取得を停止する。通信失敗だけを理由に永久除外しない。
- 停止後は、公式の新しい本文経路・新版公開を通常探索で発見した場合、または利用者の再調査指示があった場合に再開する。再開理由と根拠を記録し、過去の試行履歴は保持する。

各項目に `canonical_id`, `status`, `first_attempt_at`, `last_attempt_at`, `retry_after`, `attempts` を持つ。試行には実日時・公式URL・失敗理由・確認した版を保存する。過去の試行日が不明なら日付や回数を推測しない。

## 永久除外の基準

一次資料の根拠がある場合だけ `rejected-papers.json` に記録する。必須属性は `canonical_id`, `reason_code`, `evidence_url`, `checked_at`, `checked_source_version`, `reopen_condition`。確認できなかった版はnullと明記する。

| 理由 | 判定基準 | 再評価条件 |
|---|---|---|
| `duplicate` | 既存研究との同一性を一次資料で確認 | `duplicate_of` の既存ページへ統合。別ページを作らない |
| `out_of_scope` | 最終目的が推論効率化の収録範囲外と一次資料で確認 | 対象範囲または研究目的の実質変更 |
| `not_research` | 公式原文から予告・広告等であり研究論文ではないと確認 | 正式論文が公開されたら、その論文を評価 |
| `withdrawn_or_retracted` | 公式撤回・取り下げを確認し、訂正版への置換もない | 訂正版または公式復活の確認 |

既掲載研究の撤回はページを削除せず、状態と公式根拠を追記する。「永久」は通常探索で同じ条件のまま繰り返し候補化しない意味であり、公式状況変更の追跡を禁止しない。

通信障害、有料公開、未取得、採択未確認、優先順位が低いことだけでは永久除外しない。その他の見送りは理由と再評価条件を候補記録へ残し、正当な再調査を妨げない。
