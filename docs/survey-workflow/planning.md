# 当日の精読・監査対象の選定

## 1. 前日の確定と本数
日次選定枠でだけ前期間を締め、[日次件数調整](completion.md) に従って精読・監査それぞれの次目標を独立して決める。初回は各10本。以下のnはそれぞれの側の目標を意味する。移行前の毎時実績から増減しない。
予定選定枠から次の選定枠直前までを1読書日とする。暦日が変わっても計画を作り直さない。翌選定枠後に保存完了した成果は前期間の締切内読了に遡及計上せず、次期間の繰越の完了として照合する。

## 2. 精読対象の選定
1. 同じ `plan_id` が確定済みなら再選定・本数再調整をしない。選定途中なら保存済み候補から再開する。前日の確定結果と新計画の作成は同じ変更に含め、失敗時に増減を二重適用しない。
2. 未読の繰越を最優先し、古い順にn本まで当日計画へ入れる。既存の未完了候補も失わない。繰越がn本以上なら新規補充は0本とし、超過分は待機キューに保全して翌日以降へ送る。nを超えて割り当てない。
3. 空き枠 `max(0,n-繰越採用数)` だけ新たに探す。引用・被引用に加えてarXiv、OpenReview、会議公式一覧等の独立新着源を使う。初回収集済みの同じ引用鎖だけに偏らない。見送り記録と識別索引を照合し、既読・重複・対象外・一次資料取得不能と分かる候補を避ける。
4. この段階では実在・識別子・一次資料URL・推論研究への関連性を簡易確認する。当日リストの確定を優先し、10本分の全文精読・詳細要約・監査を同時にしない。識別照合の詳細が必要なら [第6章](hourly.md) を読む。
5. 質を落として数合わせしない。有望候補不足ならn未満で確定し、不足数と理由を残す。技術障害で選定途中なら `selecting` として保存し、再開位置を残す。
6. 選定結果を `daily_plan.selected_papers` に保存し、n・選定数・繰越数・新規候補数・各題名・一次資料URLが確認できるようにする。`pending_research` と識別子で整合させる。保存を再取得して確認後に `ready` とする。後続の精読はこの固定リストだけを使う。
7. 基盤ソフトウェア・モデル更新は朝の更新確認モードに残す。

## 3. 監査対象の選定
精読と同じ日次期間で `audit_target=daily_audit_target` 本を決め、`selected_audits` に保存する。未完了の監査を古い順に優先し、繰越を含む総数が目標以下になるようにする。超過分は `pending_audit` に保全する。
不足分は既存の推論論文から補う。優先順は監査形式の欠落／旧版、監査日欠落、出版状態不明、実装未確認、改訂可能性、監査日の古さ。同一系統への偏りを避け、一次確認から14日以内は原則後回しにする。監査可能な論文が目標数以上あれば目標まで選ぶ。
同じ側で同一研究を重複選定しない。精読との重なりは必要なら許容するが、精読と正式監査の全条件・完了実績を別々に管理する。監査本文の確認は毎時に回し、選定時は識別子・既存ページ・一次資料URL・選定理由を固定する。
不足・選定障害・再実行の扱いは精読と同じ。精読選定の障害で監査選定を止めず、その逆も同様。一方が確定すればそのリストは処理可能とし、障害のある側だけ選定を復旧する。両側の保存確認後に計画全体を `ready` にする。

## 完了条件
精読・監査それぞれ前日の増減が最大1回、繰越の欠落なし、各選定数が各目標以下、重複なし、候補の識別子・題名・一次資料URLあり、計画の保存確認済み。探索不足・保存失敗を全件読了と扱わない。
