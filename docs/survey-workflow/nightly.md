# 夜間の全リポジトリ整合性点検

## 専用枠の範囲

起動元が指定する夜間枠を `nightly` として点検専用にする。通常の論文精読・正式監査・新規探索・日次選定・基盤やモデルの新着調査は行わない。点検と安全な修復が終わったら終了し、空き時間を通常作業で埋めない。

目的は全リポジトリの構造・記録・参照の整合性である。すべての論文の内容を再精読すること、すべての外部URLの到達確認、予定タスクの起動保証とは区別する。

## 点検の順序

1. 開始記録を保存し、保守の作業権 `maintenance` を取得する。
2. 検査対象の先頭版を固定し、再帰的な全ファイル一覧（パス・内容SHA）を取得する。途中で切れた一覧を全件として扱わない。`source_commit` と `files: [{path, sha}]` の取得一覧を一時ファイルへ保存する。
3. 全ファイルを同じ版で取得する。Python・依存が使える場合は次の全体検査を実行する。取得漏れがあれば全体合格にしない。

```bash
python scripts/check_repository.py --inventory /tmp/repository-inventory.json --report /tmp/integrity-before.json
```

4. 下表の全領域を確認する。プログラムが確認できない意味上の矛盾は、手順・状態の定義と照合して記録する。
5. 正本から一意に復元できる問題を修復する。論文本文の主張を変える判断や重複研究の統合が必要な問題は正式監査の候補へ送り、この枠で監査完了にしない。
6. 最新先頭版を再取得する。走査中の他実行の変更を取り込み、影響箇所を再検査してから自分の修復差分だけ保存する。
7. 修復後の全体検査を行う。修復前・修復後の結果、対象版、確認範囲、未検査、残件、保存確認版を夜間記録へ残す。検査しただけで修復済みにしない。
8. 終了済み詳細記録を整理し、進捗表示と夜間結果を保存確認して作業権を解放する。日次計画の締め・件数調整はしない。

## 全体検査の対象

| 領域 | 確認内容 | 修復方針 |
|---|---|---|
| 全ファイル | 取得一覧との照合、取得漏れ、JSON/YAMLの読取り、Markdownの内部ファイル参照 | 欠落・破損を記録し、根拠のあるものだけ修復 |
| 推論論文 | 識別子と有効パス、別識別子の重複、必須属性、分類、移動案内 | 索引は再生成。研究同一性が曖昧なら監査へ |
| 一覧・比較 | 件数、一文説明、リンク、その他分類が最後、再生成結果との差分 | `survey.py build` で生成 |
| 分割状態 | 現在計画・全日次計画・未完了一覧・締め履歴・再確認・永久除外・作業権・途中記録 | 成果と照合し、未実施作業を完了にしない |
| 手順書・ひな型・補助処理 | 参照切れ、版の整合、モードの競合、必須属性の定義 | 意味変更が必要なら指摘を残す。通常点検で運用を自己変更しない |
| 基盤更新・モデル情報 | ファイル形式・内部参照・一覧との対応 | 表示修復だけ。新着調査は朝へ |
| 学習領域 | 凍結基準とのファイル指紋比較、参照・構造の読取り確認 | 読取り専用。差分は報告し、自動修復・基準更新をしない |

プログラムの合格は報告内 `checks` の項目に限る。外部URLの到達、ページ内見出しへの参照、科学的正確さ、任意のプログラムの実行結果は全体構造検査の対象外として明記する。

## Pythonが使えない・一枠で終わらない場合

接続機能で同じ固定版の全一覧とファイルを読み、対象を区切って確認する。`coverage` に検査済みパス・未検査パス・検査項目を記録し、`next_action` と再開位置を永続保存する。読めただけで自動検査を実行済みにしない。

未取得・未検査が一つでもある場合は `partial`。単純な生成処理ができない場合は保守待ちとして残す。次の夜間枠で未完了部分を優先し、前回以降の変更ファイルも確認する。朝はこの結果を報告する。

## 記録と完了

`survey-state/integrity/runs/<run_id>.json` に `source_commit`, `started_at`, `finished_at`, `status`, `coverage`, `checks`, `not_checked`, `findings_before`, `repairs`, `findings_after`, `next_action`, `verified_commit` を保持する。検査プログラムの出力をbefore/afterとして添付または参照してよい。`latest.json` はその最新実行への参照であり、未完了実行を除外して成功だけを表示しない。

全対象の予定検査を完了し、必要な修復を保存確認できたら `completed`。残る科学的判断を監査へ正しく引き継いだ場合はその範囲も明記する。未検査・保存失敗・修復途中は `partial`、主要検査に着手できなければ `failed`。`issues_found` と `passed` は検査プログラムの結果であり実行全体の完了状態とは別に記録する。

詳細な終了済み実行記録は24時間を超えたものを夜間に整理する。未解決の途中記録と最新夜間結果は保持し、解決確認まで消さない。日次履歴・永久除外・再確認・未解決問題は詳細記録の削除対象外。直前の完了記録を保存確認してから削除差分を公開する。
