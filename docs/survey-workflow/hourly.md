# 選定済み論文の精読・監査

## 対象と進行

1. [開始処理](state.md)に従い、当日計画・未完了一覧・実成果・識別索引を照合する。当日計画が欠落している場合だけ選定を代行する。
2. 精読と監査の完了率を比較し、概ね1件分以上遅れている側を優先する。同程度なら精読1本、監査1本の順で進む。
3. 対象研究の作業権をリモートで取得確認して着手する。新規作成前は正規識別子・arXiv基本識別子・正規化DOI・OpenReview・別名を照合する。
4. 一次資料本文を読み、問題、新規性、手法、評価条件、結果、限界を確認する。取得不能なら[再確認手順](retries.md)へ送り、次の選定済み候補へ進む。
5. 論文ごとに保存と再取得確認を終え、途中記録を更新して権利を解放する。余裕があれば次の対象へ進み、1本だけを終了理由にしない。

通常の毎時には新規探索・対象補充をしない。当日分を終えた側は翌日の選定まで追加しない。古い期間の計画へ新規着手しない。夜間枠ではこの処理を実行しない。

## 調査結果

本文確認後に `added`, `updated`, `already_recorded`, `not_selected` を確定する。本文取得不能は `insufficient_primary_source` として当日項目を決着させるが、全文精読件数に数えない。

保存競合・認証・権限・実行基盤障害は `blocked` として未完了に残す。同じ外部操作の一時的失敗は追加1回まで。表示だけの不整合は保守待ちへ送り、保存済み研究成果を取り消さない。

## 正式監査の完了条件

一次資料と現行ページで、同一研究の識別、書誌、著者・所属、公開・採択・出版状態、最終採択版、一次資料と実装の公開先・状況、主要性能値の出典位置、機器・モデル・データ・比較条件、評価方法、実機と模擬評価の区別、分類、既存との差、限界を確認する。

すべて確認して保存した場合だけ `last_audited` と `audit_version: 1` を記録する。確認できた比較属性も補う。一覧の件数が古いことだけでは正式監査を未完了にせず、夜間の保守へ送る。
