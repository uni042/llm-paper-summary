# 毎時の精読・監査

## 3.2 精読・監査モード
1. 最新の日次計画・識別索引・成果を照合し、保存済み作業を復旧する。精読リストと監査リストから、それぞれ再試行可能な未完了を確認し、当日リストを今回の処理範囲として固定する。各巡回で次の1本を選び、着手状態を中間保存する。毎時の新規探索・対象補充は行わない。
2. 精読1本と正式監査1本を順番に進める。前回監査が未完了または0本なら監査から、それ以外は精読から始める。片側が全件完了なら残る側だけ進める。片側の取得障害で他方を止めない。
3. 精読は一次資料本文を読み、問題・新規性・手法・評価条件・結果・限界を確認する。第6章と [保存手順](publishing.md) に従い1本ごとに保存確認してから次の作業へ進む。要旨や検索結果だけで読了にしない。
4. 監査は第7章の全条件を満たして初めて完了にする。精読1本・監査1本を1巡回とし、保存・確認・終了記録の余裕がある限り次の巡回へ進む。毎時の本数上限は設けず、1本や1巡回の完了だけを終了理由にしない。片側が完了・保留なら他側を続ける。同じ実行で失敗項目を際限なく再試行しない。片側の未完了で保存済みの他側を取り消さない。
5. 当日分が完了した側は翌日まで対象を追加しない。両側完了なら状態を確認して終了する。精読と監査で同じ研究を選んだ場合も条件と実績を独立して記録し、片側の完了から他側の完了を推定しない。
6. 次の選定枠を過ぎた古い計画に新規作業を開始しない。選定枠が失敗した場合だけ [選定手順](planning.md) に従い保存済みの選定途中から復旧する。通常の毎時探索へ戻さない。
7. 第3版移行後、最初の選定予定枠までは既存の未完了を同じく1本ずつ交互に、保存余裕のある限り処理可。この移行期間は日次増減判定に含めず、初回各10本は維持する。

## 5. 中断対策
キューの既存順序を基本に、取得不能項目は理由を残して同じ側の当日リスト内の次候補へ進んでよい。計画外の候補と差し替えて完了扱いにしない。
同じ外部操作の一時的失敗は1実行につき追加1回まで。認証・権限不足は繰り返さない。`attempt_count`, `last_error`, `next_retry_at` を記録し、3実行連続の同一失敗は24時間保留する。未完了として繰越に残し、品質上の見送りと混同しない。
各巡回で経過時間・残り文脈・直近の保存所要時間を確認する。実行期限が分かる場合は少なくとも直近の保存確認と終了記録に要した時間を確保する。次の1本の処理と保存を安全に終えられない見込み、または中断兆候があれば新しい作業を始めず保存を優先する。実行上限が不明なら捏造しない。精読・監査各1本の保存を実行の最後まで抱え込まない。

## 6. 論文調査と重複防止
### 6.1 精読前の照合
有効な識別索引 → 永続見送り記録 → 最近確認済み記録、の順に調べる。
- arXiv識別子は版番号を外して比較し、版は別に保存する。
- DOIはURL／`doi:`接頭辞を外し小文字化する。
- OpenReviewは公式URLから対応する安定識別子を確認する。
- 題名はUnicode・大小文字・空白・句読点を正規化し補助照合する。近い題名だけで同一研究と断定しない。
- 新しい正規識別子の優先順はarXiv → DOI → OpenReview → その他の安定識別子。一度付けた `canonical_id` は原則固定し、後で得た別識別子を別名として追加する。

### 6.2 新規作成の必須条件
作成前に `canonical_id`、arXiv基本識別子、正規化DOI、OpenReview識別子、別名を照合し、さらに題名の一致・類似候補を確認する。
- 識別子が既存研究に一致すれば新規作成禁止。既存ページの変更なし、更新、移動、統合として扱う。
- arXiv版・会議版・DOI版・題名変更は、同一研究なら1ページへ統合する。
- 題名類似や版対応が曖昧なら一次資料で確認する。索引が古い・照合不能・同一性不明なら新規作成を保留する。
- 見送り済みで重要な変化がなければ再精読しない。新版、採択・出版、大幅改訂、公式実装公開、除外理由を覆す資料がある場合に再確認可。採用へ移したら見送り項目を削除または `status: promoted` にする。

### 6.3 調査結果
一次資料確認を終えた候補を `added`（新規採用）、`updated`（既存更新）、`already_recorded`（既存・変更不要）、`not_selected`（見送り）のいずれかに確定する。一次資料未確認・判定途中は完了扱いせずキューへ残す。
`not_selected` は永続見送り記録へ保存する。重複を見送る場合は既存ページとの対応も残す。
探索は参考文献、被引用論文、独立新着源を組み合わせる。固定比率・件数ノルマは設けず、長期的な同じ引用鎖・情報源への偏りを補正する。

## 7. 正式監査の完了条件
以下を一次資料と現行ページで確認する。修正がなくても全項目を確認すれば完了。確認不能な項目は、不明である事実と確認先を明示する。必要な一次資料にアクセスできず確認自体ができない場合は未完了。
- 同一研究の識別と重複、書誌、著者・所属、公開・採択・出版状態、最終採択版、各公開版の対応、一次資料URL。
- 実装URL、公開状況、上流への統合状況。
- 主要性能値の出典位置、機器・モデル・データ・比較条件、評価方法、実装状態、シミュレーションと実機の区別。異なる版の評価値を混ぜない。
- 系統分類、READMEのリンク・件数・一言説明、既存研究との差と限界。
完了時だけ `last_audited: YYYY-MM-DD` と `audit_version: 1` を記録する（現行監査形式は1）。
新規登録や一次資料を実質再確認した重要更新では `last_verified: YYYY-MM-DD` を記録する。新規登録だけで監査済みにしない。変更なし監査では監査日だけを更新し、形式修正だけで一次確認日を更新しない。途中監査では監査済み情報を更新しない。
