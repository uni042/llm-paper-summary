# 完了判定と引継ぎ

## 実行の状態

`completed` は今回割り当てた仕事を保存確認まで終えた状態、`partial` は一部完了かつ残件あり、`failed` は主要作業に着手できないか保存できない状態とする。夜間は[nightly.md](nightly.md)の検査範囲を基準にする。

研究成果の保存が完了した項目だけ未完了一覧から除く。取得不能は再確認一覧へ移し当日項目を決着させるが、全文精読完了ではない。表示不整合は保守待ちとし研究の完了を戻さない。

## 日次目標の調整

日次選定またはその代行でだけ、精読と監査を別々に判定する。初回目標はそれぞれ10本。既存目標を形式移行で初期化しない。

| 前期間の結果 | 次の目標 |
|---|---|
| n本すべてが全文精読/正式監査まで完了 | n+1 |
| 未完了が残る | max(1, n−1)。未完了を優先繰越 |
| 候補不足でn未満だが選定分を完了 | 据え置き |
| 精読側が全件決着済みだが本文取得不能を含む | 据え置き |

`daily-history.json` の `entries` にplan_idごとに一度だけ締め結果を残す。既存の締め結果があれば再加減算しない。履歴、次目標、当日計画、未完了一覧、runtime参照を同じ変更で保存する。朝・夜間は目標や完了数を変えない。

## 問題の引継ぎ

- 自力で派生表示を再生成できるものは `maintenance-queue.json`。対象、根拠、検出時刻、試行回数、最終エラー、次処理を残す。解決時は解決時刻と修復版を記録する。
- 一次資料の精読や研究同一性の判断が必要なものは監査候補。夜間点検を正式監査件数に加えない。
- 外部復旧・権限・利用者判断が必要なものは `blockers.json`。影響、試行済み対策、必要な対応を保持する。

## 終了記録

終了時刻・状態・成果確認版・残件・次処理を実行記録へ保存する。未解決の途中記録を勝手に完了扱いにしない。夜間結果には未検査も明記する。

終了済みの詳細記録の24時間整理は夜間だけ行う。永久記録や未解決状態は消さない。通知の時刻・条件・実行場所は起動元の設定に従う。
