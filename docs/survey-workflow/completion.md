# 完了判定・日次件数調整・実行記録

## 10. 実行の終了
- 正常完了した項目だけ未完了キューから除く。時間／文脈制約・検証失敗・保存失敗・実行基盤障害は理由と次の処理を残す。一次資料本文の取得不能は [精読・監査手順](hourly.md) に従い取得確認を終えたら `insufficient_primary_source` の永続見送りとして決着させ、再試行キューへ残さない。
- 今回割り当てた作業と保存確認が完了なら `completed`、一部成功かつ今回対象に残りがあれば `partial`、主要作業を実行・保存できなければ `failed`。毎時は余裕のある限り複数本を処理する。終了時には今回着手した対象の完了と、当日リスト全体の完了を区別し、未着手の当日残数も明記する。
- 精読と監査の完了率に偏りがある場合は低い側を優先する。高い側が概ね1件分を超えて先行している状態で、低い側に処理可能候補が残るなら、高い側だけを追加で進めて終了しない。
- 全文精読完了は一次資料本文を精読し、採否・成果を保存確認した状態。採用・更新だけでなく、一次資料本文まで確認して根拠を永続保存した見送りも全文精読完了に数える。要旨選別だけの除外、重複検出だけ、監査だけは全文精読完了に数えない。
- 一次資料本文を取得できず `insufficient_primary_source` として永続見送りを保存した項目は、当日項目としては「決着済み」だが「全文精読完了」には数えない。通知・ログでは全文精読完了数と取得不能見送り数を分けて記録する。
- 旧 `running` は実ファイルと状態で復旧する。保存済み論文を重複作成しない。

## 日次件数の調整
精読と監査に以下を独立して適用する。選定モードで前計画を締める際に側ごとに1回だけ判定する。精読のnは `target`、監査のnは `audit_target`。監査側の「完了」は第7章の正式監査完了と保存確認を指す。
- 精読側でn本すべてが全文精読完了した場合、翌日は `n+1` 本。
- 精読側で未完了が1本でも残る場合、翌日は `max(1,n-1)` 本。
- 精読側ですべての当日項目が決着しているが、`insufficient_primary_source` の取得不能見送りが1本以上あり、その他に未完了がない場合はnを据え置く。取得不能を成功読了として増加判定に使わず、再試行残件として減少判定にも使わない。
- 監査側でn本すべてが期間終了までに正式監査・結果保存確認まで終わった場合、翌日は `n+1` 本。当日監査リストに未完了が1本でもあれば `max(1,n-1)` 本。
- 候補不足で選定数がn未満、かつ選定した項目はすべて完了ならnを据え置く。目標n本を処理できた実績がないため増加しない。選定失敗で確定できなかった日もnを据え置き、失敗を空リストの全件完了にしない。
- 読了0で未完了が残る日も1減らす。未実行日が複数あっても架空の計画・実績を作らず、存在する前計画について1回だけ調整する。
- 初回計画には前日判定を適用せず各10から始める。毎時の連続成功回数や他方の実績から増減しない。精読全件完了・監査未完了なら、それぞれ11・9となる。
- 繰越が翌日のnを超えても削除せず、古い順にn本を選び、超過分を翌日以降へ保全する。

`daily_reading_history` に前計画の識別子、期間と、精読・監査それぞれの目標、選定数、精読側は全文精読完了数・取得不能見送り数・その他見送り数、監査側は正式監査完了数、未完了識別子、次目標、判定理由を保存する。同一 `plan_id` が存在すれば再加減算しない。成果の実体と `completed_at` を確認し、未保存の完了宣言を信じない。

## 実行ログ
`survey-state/execution-log.md` に開始・終了時刻、予定枠、実行識別子、方式版、モード、終了状態、計画識別子、精読・監査それぞれの当日目標／選定数／累計完了数／未完了数、精読側の取得不能見送り数、今回の精読対象と成否、監査の割当・完了・繰越、検証結果、確認できた変更識別子、支障を記録する。
選定モードでは両側の前日判定、次目標、繰越／新規選定／枠外繰越／不足数も記録。朝の更新確認は各作業の成否を記録し、読書目標を変えない。
今回割当数＝今回決着数＋今回対象未完了数。未知の数値は不明と記す。実行識別子単位で更新し、ログは直近24時間だけ保持するが、日次履歴・未完了・見送り・識別索引は削除しない。
通知は起動元の指示に従う。
