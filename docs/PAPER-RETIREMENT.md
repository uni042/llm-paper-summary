# Paper retirement

The optional `.survey/survey-state/paper-retirements.json` registry records papers removed after an unrelated classification. If the file is absent, behavior is unchanged. A present registry is authoritative; malformed records or aliases shared by two retired papers fail closed.

The `paper_retirement.py` entry point accepts a schema-v1 manifest with `source_commit` and 1–25 `entries`. Each entry pins `path`, `canonical_id`, `verified_aliases`, `source_sha256`, `source_git_blob_sha`, `retirement_id`, `classification: unrelated`, `reason`, and `evidence`. `dry-run` checks the pinned clean HEAD, paper bytes, identity aliases, path safety, and direct inbound local Markdown links without writing. `apply` repeats those checks, creates the official immutable `mark_unrelated` request/result through `process_reference_relevance_requests.process_request`, records the registry, and deletes the exact paper file. It does not run against real data as part of this implementation task.

Retired identities resolve as `status: retired` with `retirement_id` and `retired_path`, and never with an active `paper_path`. Import receipts retain the existing `already_represented` status and add `identity_disposition: retired`; discovery duplicate prevention includes retired aliases. Ready Research jobs use existing `superseded` with `superseded_reason: paper_retired`. A matching missing-paper acknowledgement uses the existing `superseded` section with `reason: paper_retired` and `retirement_id`; missing papers without exact registry identity and path proof remain `waiting/paper_missing`. No new public status or acknowledgement section is introduced.

External Library consumers were not available for verification. In particular, their handling of the additional `reason` and `retirement_id` fields in existing superseded rows is unverified. The implementation has not been applied to a production paper, registry, queue, or list, and it does not establish live downstream compatibility.
