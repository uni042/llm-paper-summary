# Expected Attention: KV Cache Compression by Estimating Attention from Future Queries Distribution

## 概要

KVキャッシュ圧縮では「将来attentionされないtokenを消す」ことが理想だが、圧縮時点では未来の問い合わせはまだ存在しない。過去の注意重みを代理にする方式も、FlashAttentionのような現代的実装では完全な注意行列をHBMへ実体化しないため、その履歴を無料では取得できない。Expected Attentionは、未来の問い合わせそのものを予測するのではなく、問い合わせが従う確率分布を近似して、各KV pairが将来受ける期待注意を解析的に計算する。

隠れ状態が概ねガウス分布へ従うという観測から、問い合わせ射影後の平均・共分散を作り、回転位置埋め込み（RoPE）を未来区間で平均して位置を含む問い合わせ分布を得る。固定keyに対する指数内積の期待値はガウス分布のモーメント母関数から閉形式で計算できるため、未来tokenを実際に生成せずに期待attention scoreを得られる。これをvalueの出力寄与ノルムと掛け合わせ、残差流への期待寄与が小さいKVを削除する。追加学習・architecture変更なしでprefillとdecodeの双方へ適用し、論文は最大60%のKV圧縮まで品質を維持できると報告する。

## 問題設定

attention weightだけでKV重要度を決めると二つの問題がある。第一に、現在まで注意されなかったtokenが将来重要になる可能性があり、未来attentionは圧縮時には未知である。第二に、FlashAttentionはscore行列をtile内で計算してすぐ集約するため、過去attentionを蓄積する方式は本来不要なmemory trafficと状態を追加する。

著者らは重要度を「attentionされた頻度」ではなく、そのKV pairがTransformerの残差流へどれだけ大きな更新を与えるかで定義する。時刻tのtoken iの寄与は `Δh_ti = a_ti W_o v_i` なので、その大きさはattention `a_ti` と変換後valueノルム `||W_o v_i||` の積になる。value側は現在計算できるが、未来の `a_ti` が未知であることが核心となる。

## 手法

### 残差流寄与によるKV重要度

各attention headでkey `k_i` とvalue `v_i` を考える。valueが出力射影 `W_o` を通って残差流へ加える大きさ `||W_o v_i||` は、そのtokenがattentionされたときにモデル状態へ与え得る影響を表す。単にkey normや過去attentionを見るのではなく、attention確率とvalueの効果を同じscoreへ入れる。

入力は現在保持しているK/Vと出力射影、出力はKVごとの寄与候補値である。ただし未来attentionが必要なので、この段階だけではscoreは完成しない。次段のExpected Attentionが未知のattention項を置き換える。

### 未来問い合わせ分布の推定

論文はTransformerの隠れ状態 `h` を平均μ、共分散Σのガウス分布として近似する。queryは線形射影とRoPEを通るため、`q = R W_Q h` もガウス分布になり、その平均と共分散を射影行列から計算できる。未来T位置についてはRoPE行列を平均した `R̄` を用い、一つの位置平均問い合わせ分布へまとめる。

この処理の入力は観測済みquery統計、`W_Q`、未来位置区間で、出力は未来queryの平均 `μ̄_q` と共分散 `Σ̄_q` である。個々の未来token内容を当てる予測器は持たず、分布統計だけを使うため追加モデルや学習datasetが不要になる。

### Expected Attentionの閉形式計算

固定key `k_i` に対する非正規化scoreは `exp(q^T k_i / sqrt(d))` である。qをガウス分布と置くと、この指数線形形式の期待値は解析的に求まり、平均との内積項に加えて `k_i^T Σ̄_q k_i /(2d)` の共分散項が入る。全keyの期待非正規化scoreをsoftmaxして期待attention `â_i` を作る。

最終重要度は `(â_i + ε)||W_o v_i||` とし、低いKV pairから指定圧縮率rだけ削除する。これにより過去attention matrixを保持せず、未来queryも生成せずに、将来の残差流への期待影響を順位付けできる。

### head適応型の予算配分

attention headは役割が均一ではないため、全headへ同じ削除率を強制しない。論文は既存の適応型KV予算配分を組み合わせ、重要headへより多くのKVを残す。Expected Attentionがhead内部のtoken順位を与え、head間の予算配分がどのheadへ容量を使うかを調整する。

この構成により、prefill終了時に一度圧縮する条件と、reasoning生成中に継続してKVが増えるdecode条件の双方へ同じscore原理を適用できる。前者では長promptの初期cacheを縮め、後者では生成に伴うcache成長を抑える。

## 評価条件

| 項目 | 内容 |
|---|---|
| prefillモデル | Llama-3.1-8B（128K）、Qwen3-8B（32K）、Gemma3-12B（128K） |
| decodeモデル | Qwen-15B-R1、Qwen-7B-R1、OpenMath-Nemotron-14B |
| 長文脈評価 | LongBenchを含む長文脈課題 |
| 推論段階 | prefill一括圧縮とdecode中の継続圧縮を別々に評価 |
| 圧縮 | 最大60%削除を含む複数圧縮率 |
| 学習 | 追加学習なし |
| 実装 | KVPressとして20方式超を比較可能なライブラリを公開 |

## 主要結果

| 条件 | 結果 | 意味 |
|---|---|---|
| prefill圧縮 | 複数モデル・LongBench課題で既存方式を一貫して上回る | 過去attentionを必要としないscoreでも長promptの重要KVを選べる |
| decode圧縮 | reasoningモデルでも既存方式を上回る | 未来query分布を使うため生成中にも同じ原理を適用可能 |
| 圧縮率 | 最大60%のKV削減で性能を維持する条件を報告 | memory削減と品質保持を両立 |
| 実装互換性 | 完全attention matrixを要求しない | FlashAttention系実装で過去score保存を追加しなくてよい |
| 再学習 | 不要 | checkpointへ後付け可能 |

重要なのは、Expected Attentionが「過去に多くattentionされたtokenは未来も重要」という履歴依存仮定を外している点である。未来queryの平均だけでなく共分散もscoreへ入るため、keyが問い合わせ分布のばらつき方向と整合する場合の期待scoreも反映される。

## 構成要素と感度

value寄与ノルムを掛ける理由は、同じattention確率でもvalueが残差流へ与える実効変化が異なるためである。attentionだけを重要度とするより、出力への影響へscoreを近づける。逆にvalue normだけではどのkeyが将来参照されるか分からないため、期待attentionとの積が必要になる。

未来区間Tとガウス近似は追加hyperparameter・近似源になる。Tが実際の生成範囲と大きくずれたり、query分布が強く非ガウス化したりすれば順位推定が悪化し得る。論文は複数architectureでactivation分布を検証するが、閉形式scoreの利便性はこの分布仮定に依存する。

## 既存研究との差

H2O等の履歴型方式は過去attentionを蓄積してheavy hitterを残す。SnapKV等はprompt末尾のqueryがcontext内の重要位置を予告する性質を使う。Expected Attentionは特定の過去queryを代理にせず、未来queryの分布そのものを統計的に近似する点が異なる。

さらにFlashAttentionとの相性が設計動機に入っている。完全attention matrixを取り出す方式は、I/O削減のためscoreを実体化しない高速attention実装と衝突する。Expected Attentionはquery統計、key、value normからscoreを再構成するため、attention履歴保存を圧縮機構の前提にしない。

## 限界

ガウス分布は経験的近似であり、すべてのlayer・head・taskで厳密に成立する保証はない。分布ずれが大きい生成や、少数の特殊queryが決定的な情報を参照する課題では、期待値による順位がrare eventを過小評価する可能性がある。

score計算は無料ではない。query統計の計算、各keyに対する平均・共分散項、value norm、top-k選択が必要であり、圧縮頻度を高くすると管理costが増える。論文の主眼は品質対圧縮率であり、あらゆるruntimeで圧縮処理自体がend-to-end latencyを必ず改善することを保証するものではない。

また、KVを削除する方式なので一度evictした情報を後で必要になっても復元できない。最大60%という値は評価条件で品質を維持した代表的結果であり、任意のモデル・task・圧縮率で無損失という意味ではない。
