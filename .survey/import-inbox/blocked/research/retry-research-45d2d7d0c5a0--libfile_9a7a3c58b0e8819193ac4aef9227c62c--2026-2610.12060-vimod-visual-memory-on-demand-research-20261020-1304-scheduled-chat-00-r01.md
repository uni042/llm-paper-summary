# Look Back, Think Ahead: Visual Memory on Demand for Efficient Multimodal Reasoning

## 書誌情報と対象範囲

Yicheng Xue、Han Wu、Jufeng Yang、Minjing Dong、Xinghao Chen、Hanting Chen、Jianyuan Guoによる2026年10月8日公開のプレプリント。対象は画像を入力するマルチモーダル大規模言語モデル（MLLM）の**生成中の視覚的注意参照**であり、視覚エンコーダそのものの軽量化ではない。論文の手法名はViMoD（Visual Memory on Demand）。提案は、画像内容に応じた変形可能な領域集約DART、生成履歴に基づく時系列的な証拠選択TRACE、両者を注意の鍵・値に反映するJoint-KVの組み合わせである。

一次資料は[arXiv本文](https://arxiv.org/pdf/2610.12060)の第3〜5節および付録A〜C。結果の数値は主として表1〜5、図6、付録の学習設定から採った。以下では「視覚トークン使用予算」は毎生成ステップの注意対象数であり、保存されたKV総量とは異なることに注意する。

## 概要

長い画像トークンを毎トークンの自己注意に残すと、回答を生成するたびに大量の視覚KVを参照する。FastV、VisionZip、DivPruneのような一度きりの視覚トークン削減はこの費用を減らすが、推論の途中で必要な細部が変わる問題を扱いにくい。例えば、最初にボールとゴールキーパーの位置を調べ、次に別の選手との相対位置を考える場合、最初の選別だけでは後半の証拠が失われ得る。

ViMoDは原画像の細粒度（Fine）KVを捨てずに保存し、常時参照する粗粒度（Coarse）KVを別に作る。DARTは画像の空白部分を強く集約し、文字や境界のある領域には細かな群を割り当てる。TRACEは生成済みテキストの中間表現を時系列状態に集約し、次の推論段階で必要そうな群を更新する。Joint-KVは常時Coarseと選択Fineとテキスト履歴を連結して、凍結した元モデルに注意させる。

Qwen3-VL-4B-Instructで視覚トークン使用予算20%のとき、8つの数学・論理・複合推論課題に対するFull比正規化平均は**ViMoD 80.33、最良の一括削減方式DivPrune 57.78**である。差は22.55ポイント、相対比は約1.390倍。ただし**GPUピークメモリはViMoD 42.67 GiB、Full 38.40 GiB**と増加し、節約するのは主として生成中に参照するKVと計算である（表1、図6）。

## 問題設定：固定削減と時系列推論のずれ

画像を視覚エンコーダで変換すると、N個のFineトークンが得られる。標準の長文脈デコードでは各層がそれらのKVを参照するため、生成トークン数が多いほど視覚文脈への繰り返しアクセスが重い。従来の固定削減は入力段階で重要と推定した視覚トークンを選び、その後の生成では同じ集合を使う。この方法では推論の後段で突然必要になる小さな文字、位置関係、表のセルなどが、選別時に重要でないと判断されていた場合に回復できない。

一方で全トークンを毎回参照すると計算削減は成立しない。ViMoDが解こうとするのは「元画像を再符号化せずに詳細情報へ戻れること」と「毎ステップの参照集合を小さくすること」を両立させる課題である。論文はメモリ総容量を減らす方式とは主張していない。原画像Fine KVを保管したまま参照を間引くため、記憶容量と計算量の交換条件が生じる。

この問題に対する既存の動的参照方式DSTPは、注意の変化から再参照を決める。ViMoDはさらに、将来必要な証拠を生成履歴から予測し、粗粒度の表現と詳細領域の対応表を共同で学習する。比較表に出るDSTP†は原著DSTPをそのまま実行した数値ではなく、**DARTの同じ記憶表現と凍結バックボーンにDSTPの注意変化規則を移植した比較版**である。

## 手法1：DARTによる内容適応型の領域群

### 群の容量を画像内容から決める

Fine埋め込みを `X_F ∈ R^{N×d}`、粗粒度トークン数を `M ≪ N` とする。最初に画像を格子状のM群へ分け、各群の平均特徴から学習スコア `a_j = w_c^T mean(G_j)` を計算する。群jの目標容量は、式(2)の `c̃_j = 1 + (U−1) sigmoid(b_j+a_j+μ)` に従う。`b_j` は初期格子の容量、`U` は一群の最大要素数、共通補正量 `μ` は `Σ_j c̃_j = N` を満たすよう調整される。最後に総和を保つ丸めを行い、整数容量 `c_j` にする。

容量が小さい群ほど画像の細部を表すCoarseトークンを多く使い、後で群全体を再参照する費用も小さい。文字の密な部分や幾何学的な境界を細かく、空白を粗くまとめることが目的である。容量制約を設けることで、群の合計が元のNトークンから逸脱せず、Fine→Coarse対応が決定できる。付録B.2では4:1圧縮時の群サイズ範囲を1〜8、9:1圧縮時を1〜18としている。

### 初期格子を越えて群の所属を変える

初期格子の所属だけでなく、Fine特徴と群の平均特徴を学習射影し、式(3)の `S_ij = γ H^0_ij + (W_F x_i)^T (W_C mean(G_j))/sqrt(d_a)` で所属スコアを作る。`H^0_ij` は元の格子所属を示す指示関数であり、`γ` はその事前制約の強さである。各Fineトークンはスコアの高い順に、まだ容量の残る群へ割り当てられる。そのため画像上の直線や三角形の縁に沿って、元の四角い格子境界をまたぐ群が作れる（図5）。

同じ群の中で所属スコアを正規化した重み `w_ij` を使い、式(4)で `X_C = W^T X_F` を計算する。同時に `Π(j)=G_j` という粗粒度群jから元Fineトークン集合への対応表を保持する。この**集約に使った支持集合と再参照に使う支持集合が同一**であることが重要で、Coarseが表す内容と呼び戻す詳細の対応が崩れにくい。

### Coarse KVを作り、Fine KVを保持する

デコーダ層ℓのCoarseキーは `K_C,ℓ = W^T K_F,ℓ`、Coarse値は `V_C,ℓ = W^T E_φ(V_F,ℓ)` で計算する（式5）。キーは重み付き集約、値は残差型の学習エンコーダ `E_φ` を通してから集約する。原画像のFine KVは消去せず、将来の再参照のために保持する。Coarseの表現品質が悪いと全生成ステップへ影響するため、DARTはFullの出力分布を教師として、正解確認済み軌跡に対するトークン交差エントロピーとKL蒸留を組み合わせて学習する。

群への離散割当はそのままでは微分しにくい。そこで前向き処理は容量制約付きの実際の群を使い、勾配計算には容量制約付きSinkhorn近似を利用する。これは群所属と容量を学習可能にするための追加計算であり、推論時にはすでに学習済みの割当器を実行する。

## 手法2：TRACEによる生成履歴依存の証拠選択

### 多時間尺度の時系列状態を作る

TRACEは16生成トークンごとにルーティング判断を行う（付録B.2表7）。凍結バックボーンの層27・31・35の隠れ状態を学習的に融合し、入力 `u_t` を作る。4つの再帰枝は初期時間尺度1、2、4、8を持ち、式(6)の `s_t^(m) = ρ_t^(m) ⊙ s_(t−1)^(m) + (1−ρ_t^(m)) ⊙ f(u_t)` で状態を更新する。ゲート `ρ` が大きければ過去を長く残し、小さければ新しい情報を優先する。各枝の状態をsoftmax重みで混合した `z_t` が、次にどの画像領域が必要になるかを判断する時系列表現になる。

TRACEの状態次元は256、領域の照合用キー・クエリ次元は128。`z_t` とCoarse領域記述子を内積で照合し、学習した閾値 `e(z_t)` を引いたスコアへsigmoidを適用して各群の必要確率を出す。確率が0.5を超えた群を提案集合 `Â_t` とする。群jを選べば、対応表 `Π(j)` に属する元Fineトークン**全員**が注意対象になるため、群容量が大きいほど再参照の費用も増える。

### 保持と更新を明示的に切り替える

別のゲートが直前の活動集合 `A_(t−1)` と提案集合 `Â_t`、時系列状態を比較し、`HOLD` または `UPDATE` を選ぶ（式7）。HOLDなら集合をそのまま保持し、UPDATEなら提案集合へ置換する。UPDATEは追加だけではなく削除や空集合への更新も可能であり、Fineを一切参照せずCoarseだけで推論する区間も作れる。これにより、各16トークンごとに必ず新しい詳細を読み直すわけではない。

時系列状態はHOLD中にも更新されるため、次に何を参照すべきかの予測を継続できる。ただし更新判断が遅れたり、選択群が外れたりすると必要な証拠が一時的に不可視となる。固定16トークン間隔はこの精度・費用の交換条件の一部である。

### 教師付き初期化と方策最適化

DARTを先に学習して固定し、その後TRACEを学習する。教師モデルQwen3.8-27Bが推論の次区間で参照すべき画像領域を注釈し、その領域と交差するDART群を正解集合 `A*_t` に変換する（式9）。群選択は二値交差エントロピー、更新ゲートは正解集合が変わる時だけUPDATEとする教師信号で初期化する。続いて学生モデル自身の生成軌跡で、正答性とFine活動率を用いたRLOO型の方策最適化を実施する。

付録Bの学習規模はDART用の正解確認済み応答軌跡57,420件、TRACEの教師付きデータ80,000例、方策最適化4,800問である。最後の4,800問は教師付き集合の部分集合であり、別の独立評価集合ではない。凍結した約44.4億パラメータのバックボーンに対し、DART約118.5万、TRACE約123.6万、合計約242.1万パラメータ、すなわち0.0546%を追加する。学習にはNVIDIA H200を使用し、バックボーンは更新しない。

## 手法3：Joint-KVの生成経路と計算量の意味

推論時には、画像と質問を通常のバックボーンで一度プレフィルし、元のFine視覚KVとテキストKVを確保する。DARTがCoarse KVと群対応表を作り、TRACEが生成中に活動群を更新する。生成ステップnで注意へ渡す視覚・テキストの集合は式(8)の `KV_J(n) = [KV_C; KV_F[F_(t(n))]; KV_T(n)]` となる。`F_t = ⋃_{j∈A_t} Π(j)` であり、視覚注意対象数は `N_active(t)=M+|F_t|`。CoarseのM個は常時存在し、Fineは必要な部分だけ有効化される。

この構造の節約対象は**注意が実際に読み出す視覚KVの数**である。元のFine KVと追加のCoarse KVは保存したままなので、視覚KV保存容量をM個まで削減したとは言えない。また画像のプレフィル自体はFull相当を実行するため、プレフィル時間や最初のトークンまでの遅延（TTFT）が常に小さくなるわけではない。回答が長い場合に、後続の自己回帰デコードで減った注意処理が初期化費用を償却する。

視覚使用予算20%、30%、40%とは、Coarseと活動Fineの合計を各生成ステップで数え、例内で平均し、さらに例間で平均した値を元の視覚トークン数で割った目標である。HOLD期間のFineも活動中として計上する。個別質問で常に厳密に20%以下へ制限する方式ではなく、校正後の平均占有率で比較している。この点を、固定方式が一度だけ残すトークン割合と混同してはならない。

ただし表4では一部の方策最適化なし行に複数予算で同一値が並ぶ。ここでは原著表の数値をそのまま記載し、予算別の挙動を推測で補わない。各構成要素除去実験の活動トークン実測占有率が完全に一致するとは限らない点も、原著の注記どおり留保する。

## 実機効率と負の結果

MMMU-Proの効率評価ではH200単体、バッチ8、最大8192トークンの生成条件で、20〜90%の8段階の目標予算を比較している。図6によればViMoDは評価したすべての予算でFullより合計推論時間を短縮した。ただし他方式より必ずすべての個別指標が優れるわけではない。40%予算ではViMoDは一括削減3方式より高精度かつ合計時間15.2〜20.4%短い。一括削減方式はデコードのトークン毎処理量を改善しても、生成する回答がFullより15.9〜29.9%長くなり、合計時間の利点が相殺される。

この評価のFullの実行時間の94.4%は自己回帰デコードである。ViMoDはFullと同等のプレフィルを実行し、その後Coarseを構築するため、20〜50%予算では一括削減方式よりTTFTが悪化する。それでも長い生成における毎トークンの参照削減で、合計時間を短縮できた。したがって短い回答を多く返す対話ワークロードで同じ優位が出るとは論文は示していない。

最も重要な資源上の負の結果は、**ピークGPUメモリがViMoD 42.67 GiB、Full 38.40 GiB**という点である。FineとCoarseの双方のKVを保持するため、使用予算を20%にしても保存容量が20%になるわけではない。追加ネットワークの実行時間比はDART 0.078%、TRACE 0.616%、合計0.694%（表5、8予算平均）だが、初期化・記憶構築・KV保持による費用はこの0.694%だけでは表せない。

図6の50%予算では、ViMoDはFullと同等の精度を達成し、DivPruneが同程度の精度へ到達するのに必要な80%予算より、実測視覚占有率を39.5%低くし、合計時間を3.9%短くした。ただしこの比較は特定のMMMU-Pro・H200・長出力条件であり、他モデルや本番サービングの遅延分布を保証しない。

## 既存研究との差

FastV、VisionZip、DivPruneは最初に視覚文脈を固定的に間引く。これらはKV保存と注意参照を同時に削減しやすい一方、後で必要になる視覚情報を戻せない。ViMoDは細粒度KVを残す代わりに、Coarse表現を常時見せながら生成中に詳細集合を切り替える。DSTP†のような注意変化に基づく再参照と比べ、TRACEは複数の時間尺度を持つ状態空間型の履歴要約と教師注釈から次区間の証拠を予測する。

ViMoDの固有性は「記憶を縮める」ことだけでなく、DARTが作った群の支持集合をCoarse集約とFine再参照で共用し、その同じ群をTRACEが更新し、Joint-KVが元の凍結モデルへ接続する点にある。外部ツールによる画像切り抜き・再エンコード方式とは異なり、画像の元KVを内部に残して取り出す。ただし保存容量を増やすため、KVオフロードや分散キャッシュなどのメモリ階層最適化と組み合わせる場合は別の設計・実測が必要である。

## 限界・再現性上の注意

1. **記憶容量増加。** 元のFine KVとCoarse KVを二重に保持する。GPUメモリ容量が制約の端末・大規模同時処理には不利で、論文は多要求同時サービングでのメモリ効率を測定していない。
2. **初期化の償却条件。** Full相当のプレフィルとCoarse構築が必要であり、短い出力や広範囲の画像詳細を長時間参照する質問では、削減した注意演算が初期費用を回収できない可能性がある。
3. **群粒度と更新周期。** 必要なFineトークンだけでなく同じ群の不要な要素も読み込む。16トークンごとの更新の間に必要証拠が変わると参照が遅れ、選択漏れは回答品質を下げる。
4. **学習と一般化。** 教師モデルの証拠注釈、正解確認済みデータ、方策最適化を要する。Qwen3-VL-4B以外のバックボーンや、異なるサンプリング方式・生成設定での頑健性は未検証。
5. **評価の比較条件。** 主要精度表の正規化平均は絶対精度ではなく、DSTP†は著者の移植版。生成は貪欲復号で、元バックボーンの推奨視覚設定と異なる。本文の結果を他の公開ベンチマーク値へ直接接続しない。
6. **コード公開。** 一次論文本文で公式コードURLを特定できなかった。DARTの容量制約割当・勾配近似・TRACEの教師注釈生成・活動予算校正を忠実に再現するには付録A〜Cの仕様照合が必要。
