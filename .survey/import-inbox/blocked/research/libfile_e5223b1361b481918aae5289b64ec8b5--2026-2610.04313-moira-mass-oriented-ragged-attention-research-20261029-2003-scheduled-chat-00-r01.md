# MOIRA — 可変長KVページ選択と自己計画型注意による長文脈デコード

## 書誌情報

Dich Nhat Minh Nguyen、Tran Dang Duong Nguyen、2026年10月3日投稿、arXiv:2610.04313。現時点で確認した一次資料はarXivの原著全文であり、査読済み会議採録とは断定しない。原著PDF本文には匿名投稿用の書式警告が残るが、arXiv書誌には著者2名が掲載されている。評価対象は長文脈自己回帰LLMの**デコード時の注意計算**であり、学習済み重みの圧縮やKV容量の削除ではない。

## 概要

長文脈デコードでは生成1トークンごとに多数のKVページを読む。重要なページだけを選ぶ疎注意は帯域を削減できるが、必要なページ数は層・KVヘッド・時点で大きく異なる。全ヘッドへ同じ固定予算を与えると大半が過剰読み出しになる。一方、選んだページ数がヘッドごとに違うと、既存のFlashAttention-3やFlashInferではパディングによる無駄、GPUスレッドブロックの負荷不均衡、あるいはCPU側の事前計画が発生する。CPU側計画は各デコードステップをCUDA Graphで再生する設計と相性が悪い。

MOIRAは、各KVページのキーの平均・分散を保持し、現在のクエリに対するページ単位の注意質量を推定する。必要な質量被覆率γを満たす最小限のページをヘッドごとに選び、可変長のリストをGPU上の自己計画型カーネルで読む。vLLM 0.30、H200一基、RULER 128Kではγ=0.99で密注意と統計的に同等の精度を維持し、Llama-3.1-8Bで27.4%、Qwen3-4Bで32.5%のKVページだけを読み、密なFA3に対して出力1トークン時間（TPOT）をそれぞれ19.0→7.7ミリ秒、20.2→9.0ミリ秒へ短縮した（原著Table 1）。γ=0.98ではさらに速いが、精度差が完全にゼロとは限らない。

## 問題設定

グループ化クエリ注意（GQA）では複数のクエリヘッドが一つのKVヘッドを共有する。したがってKVを一度読んで複数クエリへ使う最小の実用処理単位は、リクエストとKVヘッドの組である。Llama-3.1-8Bは32クエリヘッドに対し8 KVヘッドなので、4要求なら1層に32行の注意計算がある。H200の多数のストリーミングマルチプロセッサを満たすには各行を複数のスレッドブロックへ分割し、部分的なソフトマックス統計を最後に統合する必要がある。

しかし各行の長さは、現在のクエリがどのKVページを必要とするかによって異なる。著者のオラクル分析ではLlama-3.1-8BのLongBenchで、注意質量95%を含むのに必要なページは平均21.6%で、最初の層では68%、いくつかの層では9%にすぎない。層間・同一層ヘッド間・時点間のページ数変動係数はそれぞれ0.61、0.74、0.53。90%の行で質量95%を確保する固定予算は、理想の可変予算に対して2.38倍、ヘッドごとに事前調整しても1.73倍のページを読む（Figure 1）。

既存カーネルの問題も具体的である。最長ヘッドに合わせて矩形の処理領域を作ると読み出しが倍増し得る。FA3の可変長処理は正確なページ数だけ読むが長い行が最後まで残り、行長のばらつきで23〜32%遅くなる。FlashInferは行を均等に分割できるものの、毎ステップCPU側で `plan()` を作るためCUDA Graphの内部に収まらない。32K×16要求ではその計画処理だけで注意カーネルの2.4倍の時間がかかる例がある（Figure 2）。必要なのは、GPU上で選択された可変長ページを**その場で分配して読み、ホスト同期なしでGraph再生できる**経路である。

## 手法

### 1. ページ平均・分散による注意質量推定（Estimate）

MOIRAは64トークンのKVページが埋まる時点で、キーの各チャネル平均μPと分散σ²Pを計算し、KVヘッドごとに2D個の要約値を保持する。デコード時のクエリqに対して、ページ内の全キーを読み込まず、平均logitと分散による指数関数補正を足してページの未正規化注意質量を近似する。原著式(2)は `log m̂(g,P) = s qg·μP + 1/2 (s qg)^2·σ²P + log S`（s=1/√D、S=64）である。これは各チャネルのキー分布を独立ガウス近似したときの指数の期待値を用いる。

平均だけでは、少数の大きなlogitが指数関数の総和を支配するページを過小評価し、重要ページを落とす。原著では平均のみだと質量をe^5〜e^7程度過小評価するページがある一方、分散を加えたmvarでは約e^3へ緩和される。最初の注意シンクページとまだ要約が完成していない現在ページは近似せず正確に扱い、後段で常に保持する。要約の追加容量はvLLMのKV予約領域の外に置かれ、報告上のKV収容可能トークン数の減少は約0.06%である。ただし追加の要約計算とバッファはゼロではない（§3.1、§4）。

### 2. 被覆率γに基づく可変ページ選択（Select）

各KVヘッドを共有するG個のクエリヘッドについて、ページ質量のソフトマックス正規化を行い、ページごとに平均した比率を計算する。そこから高質量ページを優先し、合計質量がγに達するまでのページを残す。γ=0.9でページ質量が0.70、0.20、0.08、0.02なら2ページ、γ=0.98なら3ページが必要になる。ページ数を事前に固定するのではなく、**ページ数そのものが現在の注意分布から決まる**。シンクと現在ページは常に保持し、同じページを二重計上しない。

ページ質量を毎層・毎ステップで完全ソートすると選択コストが大きい。著者はソートを避け、質量の閾値τを多分割二分探索で探す。各候補閾値以上の質量総和をGPU内で還元し、γを満たす区間を絞る操作を繰り返す。原著Algorithm 1ではK_B個の閾値を各反復で試し、24/log2(K_B)回で探索範囲を2^24分の1へ縮め、最終的にページリストと長さn_bをGPUメモリへ出力する。ソートを使う試作では密注意比の高速化が3.18倍から1.47倍へ縮んだため、選択演算の削減がシステム性能に直結する。

### 3. 自己計画型注意カーネル（Attend）

CUDA Graphは記録時のスレッドブロック数を固定するが、実行時にGPUメモリのページ数n_bは変えられる。MOIRAは各行に固定数J個のブロックを起動し、各ブロックがn_bを読んで自分の担当ページ区間を計算する。原著式(4)の `c_b = max(C, ceil(n_b/J))` が1ブロックのページ数で、担当区間が空なら即時終了する。例えば8、3、5、2ページの行に同じ4ブロックを割り当てても、余剰ブロックはページを読み込まず終了し、最長行に合わせたパディング読み出しをしない。

GPUのブロックスケジューラは実行中のブロックを分散させるので、長い行の少数ブロックだけが最後まで残る問題を緩和できる。Jは要求数・KVヘッド数などGraph記録時に決まる値から設定し、原著の共通パラメータはC=24、最小行ブロック数N_J=32、全体ブロック数N_T=4096。1ブロックが同じKVタイルからG個のクエリヘッドを処理するため、KVをクエリヘッドごとに重複読みしない。代償として、短い行には即時終了するブロックの起動が残り、計算量が小さい要求では4段カーネルの固定費が目立つ。

### 4. 部分ソフトマックス統合（Merge）とvLLM統合

Attendで複数ブロックに分割された行は、各ブロックの出力と対数和指数（log-sum-exp）統計を出し、Mergeで数値的に正しい重み付き合成を行う。1ブロックだけの行はAttendから直接出力する。これにより、全注意行列を作らずに可変長ページだけを処理する。処理順は **Estimate → Select → Attend → Merge** であり、いずれもGPU上でCUDA Graphへ取り込める。

実装はvLLM 0.30のFA3デコード部分をTritonカーネルへ差し替え、元のモデル重みやKV配置を変更しない。prefillとdecodeが混在するステップでは、decode行をMOIRAへ、prefill行をFA3へ渡し、FA3側にはdecode行の長さをゼロにしたメタデータを渡して二重計算を防ぐ。γ=1で全ページを保持したときFA3との差はbf16の1最下位ビット以内で、CUDA Graphの再生と通常実行はビット一致した。これは選択後の計算経路の検証であり、γが1未満の場合の近似誤差がゼロになる保証ではない。

## 評価条件と主要結果

### 比較設計

H200 141GB一基、bf16重み・KV、64トークンページ、vLLM 0.30とFA3バックエンドを使用。Llama-3.1-8B-Instruct（32層・8 KVヘッド）、Qwen3-4B-Instruct-2507（36層）、長い推論ではQwen3-4B-Thinking-2507を評価した。密なFA3/FlashInfer、固定ページ予算Quest、可変予算Twilight、2bit索引のFFDなどと比較する。精度はRULER-13（128K、13課題×20文書）、AIME 2024+2025（60問×8試行、最大32,768出力）、LongBench（21課題・4,750例）で測定し、速度はTPOT（出力1トークン当たり時間）、注意部分時間、オンライン要求の出力トークン毎秒を分ける。

| RULER 128K、4要求 | 密FA3精度 / TPOT | MOIRA γ=0.98 精度 / TPOT / 読出率 | MOIRA γ=0.99 精度 / TPOT / 読出率 |
|---|---|---|---|
| Llama-3.1-8B | 71.51 / 19.0ms | 69.60 / **7.1ms** / 19.6% | 71.83 / **7.7ms** / 27.4% |
| Qwen3-4B | 83.62 / 20.2ms | 83.54 / **7.6ms** / 24.2% | 83.70 / **9.0ms** / 32.5% |

RULERでγ=0.99の精度は密注意と統計的に区別できない。γ=0.98も統計検定では差が有意でないが、Llamaの点推定値は1.91ポイント低いので「数値が完全一致」とは書けない。密FA3比TPOT倍率はLlamaで2.69倍（γ=0.98）/2.46倍（γ=0.99）、Qwenで2.68倍/2.25倍。選択と注意の時間とTPOTは別の指標で、Quest/TwilightはvLLM上のTPOTが報告されず、FFDは別ランタイムのTPOTである（原著Table 1）。

### 固定予算との公平な比較：AIMEの長い推論

Qwen3-4B-Thinkingで、ページ読出し率をほぼ40%へ揃えて固定予算と可変予算を比較した。密注意の正答率75.2%、上限32Kに達した試行89/480に対し、MOIRA γ=0.98は読出率39.4%、正答率75.2%、打切り94/480だった。比例固定top-kは読出率39.5%とほぼ同じなのに正答率41.0%、打切り231/480へ悪化する。固定K=90は39.8%読出し、72.7%正答、打切り108/480、層・KVヘッドごとに事前調整した固定Kは39.7%読出し、74.6%正答、打切り93/480である（Table 2）。

これはページを節約できるかだけでなく、長い思考連鎖の一部ステップでページが不足すると生成が伸びて長さ上限に達する、という失敗機構を示す。完走した試行だけの正答率は固定K=75で95.7%、MOIRAで93.5%と逆転するが、固定K=75は打切り131/480なので総合正答率は69.8%へ低下する。完走例だけで比較すると、打切りという重要な品質劣化を隠してしまう。AIME 480試行の完了時間は密注意5,110秒に対しMOIRA 2,748秒（1.86倍短縮）だった。

### カーネル、長文脈TPOT、オンライン処理量

可変長リストの負荷分散試験では、8K×32要求でページ長の変動係数を0〜1.2へ増やしてもMOIRAの層当たり時間は69.9〜73.5マイクロ秒に収まり、FA3可変長は23%遅くなる。32K×16でもMOIRAは113.2〜124.5マイクロ秒に収まり、FA3は32%、パディングは3.3倍遅くなる。長さが揃う場合は専用カーネルの優位が小さいため、**ページ選択の利益**と**不均衡カーネルを改善する利益**を分離すべきである（Figure 4）。

| 合成バッチ | Llama密FA3 → MOIRA TPOT | Qwen密FA3 → MOIRA TPOT | 意味 |
|---|---|---|---|
| 8K×32 | 12.66→9.18ms（1.38倍） | 12.42→8.98ms（1.38倍） | 短文脈では固定費が残る |
| 32K×16 | 16.46→8.71ms（1.89倍） | 17.00→8.92ms（1.91倍） | KV読出し削減が優勢になる |
| 130K×4 | 19.32→7.32ms（2.64倍） | 20.26→7.53ms（2.69倍） | 長文脈で帯域節約の利得が大きい |

オンラインの閉ループ処理では、LongBench 4K〜64K要求、同時16件でLlamaの出力処理量が511→743 tok/s（+45%）、Qwenが563→851 tok/s（+51%）となった。一方、同じ短めの要求群で同時1件だとLlamaは152→137 tok/s、Qwenは194→171 tok/sへ**悪化**した。単一要求ではGEMMが支配的で4カーネルの固定費を回収できない。64K〜126Kの長い要求群では同時1件でもLlama 64.9→71.2 tok/s、Qwen 71.5→79.9 tok/sへ改善した（Table 5）。

### 感度・費用・品質の境界

ページ要約をprefillで作る費用は128K単一要求のTTFTをLlamaで10.58→10.60秒、Qwenで10.19→10.21秒へ増やした（約0.2%）。閉ループのTTFTはデコードが速くなったからといって改善するわけではなく、新規prefillが並列バッチの後ろで待つ場合がある。MOIRAはKVページの**読出し帯域**を削るが、全KVを保持するためメモリ容量を圧縮しない。したがってGPUメモリ不足による最大文脈制約そのものを解消する技術ではない。

RULERの短い回答だけでは固定予算の不利が現れにくい。長いAIME推論で初めて比例固定予算の打切り増大が顕著になった。LongBench全4,750例ではLlama密注意49.78、MOIRA γ=0.98が49.90（読出し33.7%）、Qwen密47.59、MOIRA47.31（読出し38.6%）と小幅な差に収まる。ただしLlamaのRULERの変数追跡課題では少数トークンにKL差が集中するため、平均精度だけで特定タスクの頑健性を保証できない。

## 既存研究との差

Questはページ内最大logitの上界で候補を選ぶが予算は固定で、GQAのクエリヘッドごとに候補を選ぶと同じKVを複数回読む。Twilightはクエリヘッドごとのtop-pで可変予算を作るが、ホスト計画と候補絞込みの費用が大きい。FFDは2bitのキー複製を毎ステップ走査して候補を選ぶため、残すページが少なくても索引走査が残る。MOIRAはページの質量を推定して**KVヘッド単位**で被覆率を決め、GPU内で仕事を分配してCUDA Graphを維持する。

原著は同じページリストをFA3とFlashInferへ渡す対照実験も行い、128Kの32行程度では既存カーネル単体も十分速く、MOIRAの速度の多くは選択規則がもたらすページ削減から来ることを示した。一方、行数が増えて長さが不均一になると自己計画カーネルの価値が大きくなる。したがって「新カーネルが常にFA3より速い」とは主張していない。mvarの質量近似自体は先行するCompKVにも見られ、可変被覆率とGraph内の不均衡処理を組み合わせたシステム設計が主な新規性である。

## 限界と適用条件

実測は4B/8Bの2系列、単一H200、bf16 KV、vLLM 0.30に限定される。より大きいモデルではGEMMの占有比率が増えるため相対高速化は小さくなり得る。量子化KV、テンソル並列、潜在注意、複数GPU、実運用の開ループ到着は未評価。Quest/TwilightはvLLM未統合、FFDは別ランタイムであり、全手法のエンドツーエンドTPOTを同条件で直接比較したものではない。ページ単位とトークン単位の読出率を混ぜない。

選択は注意質量の近似であり、γ<1では情報を落とす。AIMEで比例固定予算の失敗が顕著な一方、MOIRAでも32K打切りが94件あり、完全な正確性保証ではない。短い単一要求では明確な低速化があり、要約バッファ・選択カーネル・統合カーネルの費用が帯域節約を上回る条件では密注意を使い分ける余地がある。原著の評価はすべての条件で最高速を主張するものではない。
