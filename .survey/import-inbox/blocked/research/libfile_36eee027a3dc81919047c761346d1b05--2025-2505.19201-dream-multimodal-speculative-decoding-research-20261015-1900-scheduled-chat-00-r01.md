# DREAM：視覚言語モデルの投機的復号を教師特徴・中間層選択・視覚トークン圧縮で高速化

## 概要

DREAMは、画像と文章を同時に入力する視覚言語モデル（Vision-Language Model、VLM）で、自己回帰生成の逐次性を緩和する投機的復号（speculative decoding）を改良する。小型のドラフトモデルが候補トークンを先に生成し、大型の検証モデルが候補列をまとめて照合する方式では、候補が多く受理されるほど検証回数を減らせる。ただし視覚入力は文章入力より処理量が大きく、文章だけで訓練したドラフトは画像依存の予測を誤りやすい。ドラフトに全視覚トークンを渡すと、今度は候補生成自体が重くなる。

著者は三つの設計を統合した。第一に、検証モデルの既計算特徴を鍵・値としてドラフトの特徴から交差注意（cross-attention）を行い、画像と文章の有用な情報を参照する。第二に、検証モデルの中間層のうち注意エントロピーが低い層を教師信号として選び、ドラフトの初期層を蒸留する。第三に、検証モデルの最終層注意から視覚トークンの重要度を求め、ドラフトへ渡す視覚トークンだけを選別する。検証側は完全な視覚入力を保持するので、視覚情報を削減する対象はあくまで候補生成側である。

著者の単一NVIDIA A100 80GBによる評価では、LLaVA-v1.6-Vicuna-13Bで温度0の六課題平均速度比3.06倍、Pixtral-12Bで2.65倍、SmolVLM-2Bで2.27倍、Gemma3-12Bで3.27倍（いずれも通常復号比、表1）を報告する。個別課題の速度比はこれより大きい場合もある。ただし全設定で3倍を超えるわけではなく、画像認識が難しい課題では受理長が縮む。本文4.1節のモデル名と速度比には表1と食い違う箇所があり、以下では表の数値を優先して区別する。

## 問題設定と既存方式の限界

一般の投機的復号では、ドラフト分布と検証分布が近いほど候補の連続受理長が伸びる。検証側が画像を見ているのにドラフト側がその情報を十分に使えないと、物体名、文字、図表上の数値などで候補が早く棄却される。逆に視覚トークンをすべてドラフトへ与えると、交差モダリティの情報を維持できても、ドラフトの事前処理と生成にかかる費用が増す。

原著の処理量測定では、480×300画素の画像、166トークンの文章指示、500トークンの出力というScienceQA由来の一例で、画像を加えた視覚言語モデルの浮動小数点演算量は文章のみの平均2.1倍になった。この値は特定モデル・入力の演算量比であり、DREAMの速度向上率でも、すべての画像解像度に通用する係数でもない。

EAGLE系は教師の中間特徴を使うが、文章向けの特徴結合だけでは視覚構造を保ちにくいと著者は問題提起する。DREAMは教師特徴を単純連結する代わりに、ドラフトの現在の問い合わせに応じて教師側のどの位置を参照するかを学習させる。重要な教師層を固定するのではなく、注意の集中度を用いて選択する点も従来の静的中間層蒸留と異なる。

## 手法：入力から候補検証まで

### 1．教師特徴を参照する交差注意

検証モデルを `M_ta`、ドラフトモデルを `M_da` とし、文章トークン数を `q`、視覚トークン数を `v` とする。検証側は `q+v` 個の入力特徴を処理し、最終層特徴列 `S^L` を保存する。ドラフト側は選別後の `q+round(v/r)` 個の入力特徴を扱う。ドラフトの中間特徴 `E^j` を問い合わせ（Q）、検証側の `S^L` を鍵（K）と値（V）として、`softmax(QK^T/sqrt(z))V` を計算する。得られた融合特徴をドラフト初期層の特徴と置き換えて後段へ伝える。

この操作の重要点は、ドラフトが軽いまま検証側の多モーダルな文脈を利用できることにある。教師側で既に計算した特徴を使うため、ドラフトのたびに大型視覚エンコーダを全面的に再実行する設計ではない。ただし交差注意には追加の投影行列、注意演算、特徴保持が必要であり、受理長の改善がこれらの費用を上回らなければ速度は伸びない。教師の特徴を取得するタイミングと、ドラフトが新しいトークンを生成した際に自分の最終層特徴を鍵・値集合へ連結する処理が、通常の独立ドラフトとは異なる。

最初の検証済みトークンに続いてドラフトが次のトークンを提案するとき、過去の検証側特徴に加えて直前のドラフト特徴を交差注意の参照集合へ加える。複数候補を探索する際はEAGLE-2由来の上位k候補の並べ替えと木状マスクを利用する。ドラフト側で木状に分岐した候補を作り、検証側でも同じ木マスクで並列照合するので、単なる1本の線形候補列に比べて有望な枝を多く試せる。

### 2．注意エントロピーによる中間層蒸留

教師モデルの第ℓ層注意行列を `A_ℓ` とすると、平均注意エントロピーは `AE(ℓ)=-(1/n)Σ_iΣ_j A_(ℓ,i,j) log A_(ℓ,i,j)` と定義される。複数注意ヘッドがある場合はヘッド間でも平均する。各訓練例について `ℓ*=argmin_ℓ AE(ℓ)` を選び、その層の特徴をドラフト初期層の教師信号とする。注意が少数位置へ集中している層を、情報を取り出す際の安定した指導信号として使うという設計仮説である。

訓練損失は、教師最終層とドラフト最終層の平滑L1特徴損失 `L_feat`、選択中間層とドラフト初期層の平滑L1損失 `L_intermed`、教師とドラフトの出力分布のKL損失 `L_KL` を重み付き加算する。原著の設定は `0.2 L_feat + 0.2 L_intermed + 1.0 L_KL` である。中間層を選ぶための注意エントロピーは、訓練前の校正段階で各標本について一度計算して保存し、学習中に全教師層を毎回再探索しない。論文中の「動的選択」は入力例に応じて教師層を変える意味であり、オンライン推論時に毎トークンの全層注意エントロピーを計算する意味ではない。

中間特徴蒸留を省略するとドラフトが多モーダルな教師分布へ十分に追従できず、候補受理長が短くなる。反対に特徴損失の重みを0.4まで増やすと、0.2の場合より受理長と速度比が下がる。教師との特徴一致を強制しすぎると、軽量ドラフトが本来必要な予測能力を学びにくくなるという負の結果である。

### 3．検証側注意による視覚トークン選別

検証モデルの最終層で各入力位置へ集まる注意重みを合計し、視覚トークンに対応する位置だけを重要度順に並べる。保持率に応じて上位位置の索引を選び、ドラフト側へ渡す視覚トークン列を短くする。単純な等間隔間引きではなく、検証側が強く参照した領域を残す点が異なる。検証側は全視覚トークンを使い続けるため、最終出力の検証に使う情報をこの段階で捨てるわけではない。

ただし保持率を下げるほど候補生成が必ず高速になるわけではない。図表や細かい文字などの重要位置を削りすぎるとドラフトが不正確になり、検証で棄却される候補が増える。論文は75%保持を採用し、50%・25%保持では速度比と受理長が悪化する具体例を報告する。ここでの75%は視覚トークンを25%削減する意味であり、75%削減ではない。

## 評価環境と比較条件

| 項目 | 原著の条件 |
|---|---|
| 検証対象 | LLaVA-v1.6-Vicuna-7B/13B、Pixtral-12B、SmolVLM-2B、Gemma3-12B |
| 課題 | MMT-Bench、SEED-Bench-2、ScienceQA、OCRBench、ChartQA、MathVistaの6種 |
| 比較方式 | 通常自己回帰復号、SPD、Kangaroo、Medusa、Hydra、EAGLE、EAGLE-2（モデルにより表掲載の方式が異なる） |
| 主要指標 | 通常復号に対する1トークン当たり壁時計時間の比 `S`、平均連続受理長 `τ` |
| 温度 | 0および1を別々に評価 |
| 推論機材 | NVIDIA A100 80GB 1基、推論バッチ1、KVキャッシュ有効 |
| ドラフト学習 | A100 80GB 2基、68,000反復、AdamW、学習率3×10^-5、バッチ4 |
| ドラフト規模 | 対象モデルに応じ0.28B～0.98Bパラメータ |
| 木探索 | 子ノード数4、深さ6、最大候補長32、視覚トークン75%保持 |
| 反復 | 各設定を3回実行し平均を報告 |

ドラフト学習ではLLaVA mix665kから55,000件、各評価課題から1,000件を使い、教師モデルの応答を正解出力として生成する。訓練・評価データ分割が存在しない課題では乱数種42による層化抽出を用いる。ベースラインも同じデータ・学習条件・機材で再学習していると原著は説明する。学習に必要なA100 2基の費用は、以下の推論時速度比には含まれない。

速度比 `S` は通常復号の平均1トークン当たり時間を方式の平均時間で割った値である。したがって2倍という値は、特定の設定で単位トークン生成時間がおよそ半分であることを示す。画像の符号化、事前充填、ネットワーク通信、モデルのロード、ドラフト学習費用を含む総サービス遅延が2倍改善したとまでは主張できない。原著本文では速度比を「実際の端から端までの遅延」と結びつける表現もあるが、測定定義はトークン単位の壁時計時間であるため区別する。

## 定量評価と負の結果

### モデル別の平均値（温度0、原著表1）

| 検証モデル | EAGLE-2速度比 / τ | DREAM速度比 / τ | 解釈 |
|---|---|---|---|
| LLaVA-v1.6-Vicuna-7B | 2.05 / 5.01 | 2.23 / 5.51 | 候補受理長と速度がともに改善 |
| LLaVA-v1.6-Vicuna-13B | 2.69 / 4.23 | 3.06 / 4.87 | 大型モデルほど検証削減の利益が大きい例 |
| Pixtral-12B | 2.31 / 3.37 | 2.65 / 3.78 | 視覚・文章の特徴融合で受理が改善 |
| SmolVLM-2B | 2.07 / 2.82 | 2.27 / 3.09 | 小型検証モデルでは追加ドラフト費用が相対的に重い |
| Gemma3-12B | 2.71 / 2.25 | 3.27 / 2.36 | 受理長の改善幅が小さくても速度比は上がる |

同じ温度0でもOCRBenchやChartQA、MathVistaなど視覚細部の認識が必要な課題では、画像の重要領域を候補側で取り違えやすく、平均より低い速度比になる。例えばLLaVA-7BのChartQAではDREAMが1.89倍、EAGLE-2が1.77倍であり、同モデルのMMT-Benchの2.52倍より低い。SmolVLM-2BのChartQAはDREAM1.62倍で、EAGLE-2の1.51倍との差も小さい。

温度1の確率的サンプリングでは、候補と検証の一致が不安定になるため温度0より速度比が低下する。LLaVA-7Bの六課題平均はDREAM2.14倍・受理長5.43、EAGLE-2は1.95倍・4.91である。Pixtral-12Bの六課題平均はDREAM2.49倍・3.58、EAGLE-2は2.30倍・3.28である。これらは温度0の数値と混ぜて平均しない。

### 構成要素除去実験（原著表2）

LLaVA-7Bで視覚トークン圧縮を無効にして比較すると、DREAMを1.00とした速度比は、初期復号層を外すとMMT-Benchで0.60、交差注意を外すと0.48、最終復号層を外すと0.73になる。交差注意を外したときの受理長比は0.44であり、特徴融合が単なる付加機能でなく、ドラフト品質を支える中心要素であることが分かる。

交差注意を2層へ増やした変種はMMT-Benchで受理長比1.09へ改善するが、速度比は0.99にとどまる。ScienceQAでは受理長比1.10に対して速度比0.79となり、追加計算費用が受理増加の利点を打ち消す。EAGLE-2のドラフト層数を4層へ増やした場合も、1層版より受理長は改善する一方、速度比が0.63～0.68程度に落ちる。ドラフトが精密であることと速いことは同義ではない。

中間層の選択を固定25%、50%、75%の深さで比較すると、固定75%が固定方式では最良であるが、入力例ごとの注意エントロピー選択がさらに良い。木探索は鎖状候補に比べて平均1.32倍の追加速度向上をもたらすと原著は報告する。これらは構成要素の比較であり、主表の通常復号比に独立して乗算できる改善率ではない。

### 視覚トークン保持率の感度（原著表3）

| モデル・課題 | 100%保持 S / τ | 75%保持 S / τ | 50%保持 S / τ | 25%保持 S / τ |
|---|---|---|---|---|
| LLaVA-13B・MMT | 3.53 / 5.67 | 3.68 / 5.58 | 3.19 / 4.96 | 2.44 / 4.78 |
| Pixtral-12B・MMT | 2.88 / 4.48 | 2.93 / 4.52 | 1.51 / 2.68 | 1.24 / 2.18 |
| Pixtral-12B・ScienceQA | 2.91 / 4.52 | 2.98 / 4.03 | 1.53 / 2.77 | 1.33 / 2.64 |

75%保持は候補計算を減らしながら受理長を概ね維持する。一方、50%・25%保持では視覚情報欠落による棄却増加が処理量削減を上回る。PixtralのMMTでは25%保持の速度比が1.24倍まで低下し、75%保持の2.93倍と大差がある。これは「画像トークンを多く削れば速い」という単純な近似が成立しない実例である。

### 原著の内部不整合と解釈上の注意

原著4.1節は温度0で「LLaVA-7Bが平均3.06倍」と記すが、表1ではLLaVA-7Bは2.23倍、LLaVA-13Bが3.06倍である。同節は「ScienceQAでLLaVA-7Bが3.36倍、EAGLE-2が3.09倍」とも記すが、この組は表1ではLLaVA-13BのScienceQAに対応する。原著の文章だけからモデル別の改善率を転載すると、7Bと13Bを取り違える恐れがある。ここでは表1のモデル行を正とし、矛盾を明記した。

要旨の「最大3.6倍」は概括値であり、表1の個別課題には3.68倍、Gemma3のOCRBenchには4.81倍の行も存在する。測定値を厳密に再利用する際は、どのモデル・課題・温度を指すかを明示する。速度比と平均受理長は異なる指標であり、受理長が長いほど必ず速度比も大きいわけではない。

## 実装・適用範囲と限界

著者は公式実装を公開している。構造としては、教師視覚言語モデルの最終層特徴を取得できること、ドラフトへ交差注意層を追加できること、各学習標本で教師の層別注意を測れること、候補木を検証モデルに渡せることが前提となる。既存の汎用文章向け投機的復号機能をオンにするだけでは、教師特徴の抽出・蒸留・視覚トークン選別が自動的に組み込まれるわけではない。

教師モデルは固定したままドラフトを学習するため、推論時に教師の重みを更新する必要はない。一方、対象モデルごとに0.28B～0.98B規模のドラフトと追加特徴処理を準備する。A100二基を使った学習・校正と、単一A100の推論実験を混同してはならない。RTX系の小容量GPUやCPUオフロード環境で同じ速度向上を得られるかは未測定である。モデル本体とドラフトを同時に置くメモリ費用、教師特徴キャッシュの保持費用、推論基盤との統合作業も必要となる。

視覚情報の細部が不可欠なOCR・図表・数学課題では受理長が短く、視覚トークンを強く削減すると速度が悪化する。学習済みドラフトの画像解像度・視覚エンコーダ・モデル系列への転用も自動的には保証されない。原著の評価はNVIDIA GPUに限定され、AMD GPU、CPUのみの環境、分散サービング、複数利用者を混載した連続バッチ処理では未検証である。

また、本文には上記のモデル名・速度比の食い違いがあるため、モデル別数値を引用する場合は原著表1を再確認する必要がある。評価では応答の意味的正確さを課題別に全面的に再採点した比較表よりも、投機候補の受理長とトークン単位時間が中心となっている。分布保存の受理規則を採用する説明はあるが、すべての実装経路で検証側モデルの確率分布が完全一致することを独立に形式検証した結果までは提示していない。
