# Beyond KV Reconstruction：MLAドラフトの機能再構成

## 概要

本論文は、多頭注意（Multi-Head Attention; MHA）またはグループ化クエリ注意（Grouped-Query Attention; GQA）で事前学習した小型言語モデルを、多頭潜在注意（Multi-head Latent Attention; MLA）へ変換して投機的復号（speculative decoding）のドラフトモデルとして使う際の**受理率低下**を扱う。MLA変換はキー・バリューキャッシュ（KV cache）を低次元潜在表現へ圧縮するが、変換後の単独生成品質が維持されても、検証モデルとの次トークン一致は維持されるとは限らない。低ランク近似と回転位置埋め込み（Rotary Position Embedding; RoPE）の経路変更が、注意層の出力を変えるからである。

提案する機能再構成（Functional Reconstruction）は、変換後のMLA注意層が元のGQA注意層と**出力射影後に同じ関数として振る舞う**よう、較正用の隠れ状態に対する誤差を最小化する。元の注意層を固定した教師とし、MLA側の変換で導入・変更されたクエリ射影とKV射影だけを更新する。検証用大規模モデルからの対数確率や教師ラベルは使わない。低ランクの幅、KVキャッシュ容量、推論時の計算グラフも変えない。

四つのドラフト・検証モデル組、二つの変換器、二つの実行基盤、四つのタスクからなる64個の対応条件で、受理率は37条件で実質改善、26条件で実質同等、1条件で悪化した。ただし、受理率改善は必ずしも実時間の高速化ではない。出力トークン毎秒が実質向上したのは12条件で、50条件は同等、2条件は低下した。論文は**元の未変換GQAドラフトより高速になった**とは結論していない。

## 問題設定：変換の成功とドラフトの成功は異なる

投機的復号では小型ドラフトが先行して複数トークンを提案し、大型の検証モデルがそれらをまとめて確認する。ドラフトが検証モデルと一致するほど一回の検証で確定できるトークンが増える。したがってドラフト自体のKVキャッシュを圧縮して生成を安くしても、受理率が下がれば検証回数が増え、全体性能は悪化し得る。

MHA/GQAからMLAへの変換は、従来のキー・バリュー射影を潜在次元 `r` の行列積に近似し、位置情報をRoPE適用経路と非位置経路へ再配分する。元の射影を積み重ねた行列の階数が `r` を超えるなら、その積を階数 `r` 以下の行列積で厳密に再現することはできない。これは低ランク変換で不可避となり得る誤差を示すが、すべての機能的に等価な注意表現が不可能という主張ではない。

加えて、RoPE適用を残すキー成分と外す成分の再構成では、位置ごとの回転差に由来する誤差が生じる。キー・クエリの小さな誤差は注意のソフトマックスと値の重み付き和を通って出力に影響し、最終的に候補トークンの順位を入れ替える可能性がある。貪欲復号の受理は最大確率トークンの一致という離散事象であるため、連続的な注意誤差が小さいことだけでは受理率を保証できない。

## 手法

### 1. 変換済みMLAを出発点にする

最初にTransMLAまたはMHA2MLAで、元のGQA/MHAドラフトから潜在KVキャッシュを持つMLAモデルを生成する。TransMLAはRoPE分解と低ランクQKV変換を行い、MHA2MLAは部分RoPEとKV射影の共同低ランク近似を用いる。提案法はこれらの代替変換器ではなく、変換後に追加する補正工程である。したがって両変換器の異なる初期値と保持RoPE幅を引き継ぐ。

同一変換器で作ったMLAの初期状態を、従来の部分RoPE再構成と提案する機能再構成の両方に渡す。比較時には潜在階数、保持RoPE幅、KVキャッシュ予算、ドラフト提案長、実行グラフを固定する。こうして改善の原因を、モデル容量やカーネル差ではなく、再構成の目的関数の違いに絞る。

### 2. 出力射影後の注意関数を教師にする

層 `ℓ` の較正隠れ状態 `H_ℓ` を、固定された元GQA注意層と、学習可能な変換後MLA注意層へ同じように入力する。各注意層は、クエリ・キーの内積、位置回転、ソフトマックス、値の集約、最終出力射影 `W_O` を通した出力を返す。提案法は途中のK/V射影行列の一致だけを求めず、**`W_O` の後の最終注意出力**を比較する。この位置ならRoPE経路の違いと低ランク近似誤差の双方が反映される。

有効トークンを示すマスク `M_b`、隠れ次元 `D`、較正ミニバッチ `b` に対し、論文の式(11)は次の形式である。

```text
L_E2E^(ℓ) = E_b [ || M_b ⊙ ( A_MLA^(ℓ)(H_b) − sg[A_orig^(ℓ)(H_b)] ) ||_F²
                    / (D · Σ_t M_(b,t)) ]
```

`sg` は勾配停止、`A_orig` は元の注意層の出力射影後の関数、`A_MLA` は変換後の対応関数を表す。分母は有効トークン数と隠れ次元で正規化する。元モデルへの勾配を止めるので教師は更新されない。MLA側では変換由来のクエリ・KV射影だけを学習し、出力射影と注意以外の重みは固定する。層ごとに独立に較正するため、検証モデルの対数確率、隠れ状態、正解ラベルは不要である。

### 3. 変換器から独立した機能境界

本方式が変換器に依存しないのは、変換器固有の中間変数ではなく、両モデルに共通する層入力から注意出力までの関数を教師信号に選んだからである。部分RoPE再構成は変換器内部の特定の中間写像を近づけるが、その中間写像が近くても最終的な注意出力が一致するとは限らない。逆に個別の射影行列が一致しなくても、複数の変換が相殺されれば最終出力は近づく。

機能誤差を減らしても受理率は単調には改善しない。各層の小さな残差が後段で増幅・相殺される可能性があり、トークン順位の境界を越えるかどうかは離散的だからである。論文はこの連続代理損失と離散受理率の違いを、手法の保証範囲と実験検証範囲を区別する理由としている。

### 4. 実装と再現可能性

著者公開実装はTransMLAの変換コード、MHA2MLAの初期化・再構成コード、Hugging Face（HF）およびvLLMの投機的復号ベンチマーク、較正設定、固定したタスク入力、192条件の結果CSV、試験コードを含む。READMEのLlama-1B例では較正サンプル16件、最大系列長512、300最適化ステップ、学習率 `1e-4`、乱数種42が指定される。TransMLA側の潜在KV階数は例で512、MHA2MLA側の低ランク幅はKVヘッド当たり56とされるが、他モデルの値は設定JSONで異なるのでこの数値を全実験の共通設定として扱わない。

公開READMEにある実験環境はPython 3.12、PyTorch/CUDA、Transformers 4.52.4、vLLM 0.8.4である。vLLMの実行例では従来エンジンを指定し、変換器に応じてテンソル並列度を変える。生成済みモデルのチェックポイントと生の実行ログは公開成果物に含まれないため、結果CSVの存在と再現実行が成功することは同義ではない。

## 評価

### 実験条件と比較設計

提案法の性能は、元の未変換GQAドラフト、同じ変換器で作成した部分RoPE再構成MLAドラフト、提案する機能再構成MLAドラフトの三方式で比較する。主張の検証に直接対応するのは、**変換器・モデル組・実行基盤・タスクを固定して部分RoPEと機能再構成を比較した64条件**である。未変換GQAの値は変換による劣化を示す参照値であり、MLA同士の差を未変換GQAに対する高速化と読み替えない。公開成果物の結果CSVには、四モデル組、二変換器、二実行基盤、三方式、四タスクを掛け合わせた192行がある。

| 要素 | 論文・公開成果物の設定 |
|---|---|
| ドラフト→検証 | Llama-1B→Llama-8B、Llama-3B→Llama-8B、Qwen-1.5B→Qwen-7B、Qwen-3B→Qwen-7B |
| 変換器 | TransMLA、MHA2MLA |
| 実行基盤 | Hugging Face、vLLM |
| 対照 | 未変換GQAドラフト、同じ変換器の部分RoPE再構成、提案機能再構成 |
| タスク | HumanEval（コード）、Alpaca（指示）、Natural Questions（質問応答）、CNN/DailyMail（要約） |
| 入力 | 各タスク200プロンプト。HumanEvalは164問に決定的な重複36問を追加 |
| 復号 | BF16、バッチ1、貪欲復号、最大出力128トークン、乱数種42 |
| ドラフト提案長 | 1B/1.5Bで4、3Bで3 |
| 主指標 | ドラフトトークン受理率（%）、生成出力速度（tokens/s） |
| 実験規模 | 4モデル組×2変換器×2基盤×3方式×4タスク＝192条件、各200出力＝38,400生成 |

受理率は小型ドラフトが提案したトークンのうち大型検証モデルが受け入れる割合であり、高いほど一回の検証で確定するトークンが増えやすい。出力速度は実際に確定した生成トークン毎秒であり、検証の回数だけでなくドラフト計算、注意演算、実行基盤の効率も反映する。論文の「実質差」判定は受理率0.5パーセントポイント超、出力速度0.5 tokens/s超という記述的許容幅で、統計的な信頼区間に基づく有意差ではない。

### 受理率：改善37、同等26、悪化1

64対応条件のうち37条件で提案法が部分RoPE再構成より受理率を0.5ポイント超改善し、26条件は許容幅内、1条件は0.55ポイント悪化した。最も大きい改善はLlama-1B・TransMLA・vLLM・CNN/DailyMailの43.54%→47.77%（+4.23ポイント）である。同じLlama-1B・TransMLA・HFのHumanEvalでは67.61%→71.53%（+3.92ポイント）、Natural Questionsでは47.96%→51.74%（+3.78ポイント）となった。これらは未変換GQAに対する差ではなく、同一MLA変換条件内の再構成方式差である。

| 固定条件 | 未変換GQA | 部分RoPE再構成 | 機能再構成 | 差（対・部分RoPE） |
|---|---:|---:|---:|---:|
| Llama-1B / TransMLA / HF / HumanEval 受理率 | 77.75% | 67.61% | 71.53% | +3.92ポイント |
| Llama-1B / TransMLA / vLLM / CNN/DM 受理率 | 74.53% | 43.54% | 47.77% | +4.23ポイント |
| Qwen-3B / MHA2MLA / HF / CNN/DM 受理率 | 58.82% | 54.00% | 56.29% | +2.29ポイント |
| Qwen-3B / TransMLA / vLLM / CNN/DM 受理率 | 71.66% | 17.58% | 17.03% | **−0.55ポイント** |

変換器とモデル系列の相互作用が強い。LlamaとTransMLAの16条件はすべて改善する一方、LlamaとMHA2MLAの16条件はすべて許容幅内である。QwenとMHA2MLAでは16条件中15条件が改善するが、QwenとTransMLAでは6条件改善、9条件同等、1条件悪化した。したがって「どの変換器でも同程度の改善」という結論は支持されない。元の変換方式がどのような機能誤差を残すかが、追加較正の改善余地を決める。

### 生成速度：受理率の改善がそのまま高速化にならない

出力トークン毎秒については12条件で0.5 tokens/s超の改善、50条件は同等、2条件は悪化であり、差の範囲は−1.01〜+2.77 tokens/sであった。例えばLlama-1B・TransMLA・HF・HumanEvalは37.73→40.50 tokens/sへ改善するが、Qwen-3B・TransMLA・vLLM・CNN/DMでは23.67→23.60 tokens/sでほぼ変わらない。受理率が増えても、実行基盤のカーネル効率や実行時変動のため同じ比率で速度が伸びるわけではない。

論文はタイミングを繰り返し測定した信頼区間を提示していない。そのため小さな速度差を安定した性能差と解釈すべきではない。また、未変換GQAドラフトとMLAドラフトの絶対速度差には、MLAカーネルの成熟度、テンソル並列設定、実行基盤の違いが混在する。**MLAへの変換自体が未変換ドラフトを上回るエンドツーエンド速度向上を達成した証拠ではない**。とくにvLLMではTransMLAがテンソル並列2、MHA2MLAが並列1なので、変換器間の絶対速度を直接比較しない。

### 変換による受理率損失の回復には限界がある

Qwen-3B・TransMLA・vLLM・Natural Questionsでは未変換GQAの受理率71.03%に対し、部分RoPE再構成が10.95%、機能再構成でも12.73%にとどまった。変換で失われた情報や実行基盤との相性が大きいと、局所的な機能誤差を減らしても元の性能には戻らない。一方、Qwen-3B・MHA2MLA・HF・CNN/DMでは58.82%→54.00%→56.29%と、元の受理率に比較的近づく。

この比較は、提案法が変換器によって異なる残留誤差を補正できることと、変換器固有の損失をすべて修復できるわけではないことを同時に示す。未変換GQAは元状態を測る参照であって、検証モデルとの一致率に関する理論上限ではない。したがって元GQAとの差を機能再構成だけの失敗と解釈するのも適切でない。

### 評価の読み方と未評価条件

受理率の64条件集計は、MLAのキャッシュ容量と推論グラフを固定して再構成目的関数を変えた比較であり、追加のランタイム演算なしに受理率を改善し得ることを支持する。一方、実時間の改善は12条件に限られる。論文が扱うのはバッチ1、貪欲復号、提案長3〜4、生成上限128トークンである。高並列サービング、長文脈、長い候補木、確率的復号での性能を、この集計から外挿してはならない。

評価の公開CSVは結果の再計算・照合に役立つが、生成済みチェックポイントと生のランタイムログは公開されていない。公開設定に基づく再学習とベンチマークの再実行は可能でも、表の数値の完全再現を独立確認したことにはならない。以上が今回の評価における主要な再現性上の制約である。

## 既存研究との差

TransMLAとMHA2MLAは主に「実行可能でKVキャッシュの小さいMLAモデルをどう初期化するか」を解く。提案法は初期化後の「注意関数を元モデルへどう合わせるか」を解く。両者は競合ではなく直列に組み合わせる工程である。EAGLEなどの候補木生成や検証スケジューリングの変更とも異なり、提案モデル自体の受理されやすさを改善する。推論時の枝・KV状態・追加層を増やさない点が特徴である。

論文の対応比較は、同じ射影群を更新し、同じ容量・カーネルを使用する部分RoPE再構成を対照にしたものなので、改善を「追加パラメータを増やしたから」と説明することはできない。反対に、元GQAとの差や変換器をまたぐ速度差は統制が十分ではなく、そこまで含めた高速化の一般化はできない。

## 限界・負の結果・導入判断

第一に、学習損失は層ごとの平均二乗誤差であり、最終トークンの順位一致を直接最適化していない。少数だが受理率が悪化する条件があり、層をまたいだ残差の相互作用を捉え切れていない。較正用の隠れ状態が実運用の入力分布から外れる場合、補正が別の入力へ転移する保証もない。

第二に、潜在KVの階数が足りず捨てられた情報は、同じ階数のまま射影を再調整しても原理的にすべて回復できない。RoPE処理、変換器の初期化、推論基盤のテンソル演算の意味が異なると、較正で減らした誤差が実際の復号で同じように減るとも限らない。

第三に、提案は事前較正・学習を追加するため、実行時の演算増分がゼロでもモデル準備時の費用はゼロではない。公式実装の例では300ステップの再構成を行う。モデル系列、潜在階数、較正データ、対象実行基盤が変われば、再較正と受理率・速度の再測定が必要になる。

第四に、論文の主な比較はバッチ1・貪欲復号・提案長3〜4・出力上限128トークンであり、大バッチ、長い提案木、確率的サンプリング、長文脈実サービスの全体スループットを直接検証していない。最大の受理率改善を長文脈の実運用速度向上へ換算するのは不適切である。

導入上は、MLAドラフトのキャッシュ削減が重要な構成で、既にTransMLAまたはMHA2MLAによる変換パイプラインがある場合のオフライン改善候補となる。現場では変換前後の受理率だけでなく、同一ハードウェア・同一テンソル並列設定でのトークン毎秒、検証回数、ドラフト準備費用を合わせて測るべきである。
