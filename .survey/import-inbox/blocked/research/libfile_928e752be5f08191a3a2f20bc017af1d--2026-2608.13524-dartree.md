# DARTree: Speculative Diffusion Decoding with Autoregressive Draft Trees

## 概要
投機的復号は高速なdrafterが複数トークン候補を作り、対象モデルが一度に検証して受理することで、対象の逐次順伝播回数を減らす。拡散言語モデルをdrafterにすると複数位置を並列予測できるが、各位置の分布は「その枝で実際に選ばれた直前トークン」へ因果的に条件付けされていない。そのため候補を木へ広げても、枝ごとの自己回帰整合性が弱く、検証時の受理長を失う。

DARTreeは既学習の自己回帰補正ヘッドをchainからtreeへ拡張する。各深さで固定幅の候補ノードをバッチとして一括展開・スコアし、AR-ヘッド inferenceが終わった後にbest-first 枝刈りで対象へ渡す検証 treeを選ぶ。これにより補正ヘッドをheap操作のたびに逐次呼ぶ経路を避ける。7つの数学・コード・chat ベンチマーク、4 モデル-temperature設定すべてで平均受理率 lengthと高速化倍率が最良となり、最大12.97 トークン/検証、DFlash比98.6%、Domino比27.9%長い受理、通常自己回帰比最大9.73倍の無損失 高速化倍率を報告する。

## 問題設定
拡散drafterはトークン ブロックを一度に予測できるためproposal 遅延が低い。しかし位置iの高確率トークンは、位置i-1で木のどの枝を選んだかを反映していない。単一chainへAR correctionを加える方式は因果情報を戻せるが、候補coverageが狭い。逆にtreeを広げる方式はcoverageを増やせても、各分岐にAR correctionを伝搬しなければ対象モデルが受理する連続列になりにくい。

さらにbest-first searchを素朴に実装すると、priority queueからノードを1つ取り出すたびにAR ヘッドを呼ぶため、GPU上の小さな逐次カーネルが増え、拡散drafterの並列性を相殺する。DARTreeは「tree quality」と「GPU-friendly バッチ expansion」を同時に解く必要があると捉える。

## 手法
### 固定幅のdepth-wise展開
各深さで現在のfrontier ノード群をまとめ、拡散drafter由来の候補とAR correction ヘッドを使って次ノードをバッチ生成する。ノードごとの逐次heap pop→ヘッド inferenceではなく、同じ深さを一括処理するためGPU並列性を維持する。

### 枝ごとの自己回帰補正
AR correction ヘッドは、その分岐上で既に選択されたトークン列を反映して候補スコアを修正する。これにより拡散モデルのposition-wise marginalだけで木を作る場合より、対象モデルの左から右への条件付き分布へ候補pathを近づける。狙いは単純な候補数増加ではなく、検証で連続受理される深いpathを増やすことである。

### 展開と枝刈りの分離
全ノードを無制限に対象へ渡すと検証コストが増えるため、深さ-wise バッチ expansionの後にbest-first 枝刈りを適用し、検証 treeのbudget内へ絞る。重要なのは、heap操作をAR-ヘッド inferenceのcritical pathから外すこと。tree探索の制御処理とGPU推論を分離して、proposal側の逐次性を抑える。

## 評価条件・主要結果
| 観点 | 結果 |
|---|---|
| ワークロード | 数学・コード・対話の7 ベンチマーク |
| 設定 | 4 モデル-temperature configurations |
| 受理率 | 最大12.97 トークン / 検証 round |
| DFlash比較 | 同条件で最大98.6%長い受理 |
| Domino比較 | 同条件で最大27.9%長い受理 |
| E2E | 局所 autoregressive 復号比最大9.73倍 |
| 品質 | 無損失 投機的復号 |

受理長は対象モデル一回の検証で何トークン進めるかを示し、長いほど高価な対象呼び出し回数を減らせる。ただしtreeを大きくすれば検証側の計算も増えるため、DARTreeは候補木の質とbudgetの両方を調整する。

## 既存研究との差
DFlash型の拡散ドラフトは並列proposalを強みにする一方、位置間の因果整合性が弱い。Domino等の補正方式はAR情報を導入するが、chainまたは探索の逐次性が残る。DARTreeはAR correctionをtree 分岐へ拡張しつつ、深さ単位バッチ expansionと後段枝刈りに分けることで、候補品質とGPU実行効率を同時に狙う。

## 限界
最大9.73倍は論文の特定モデル・temperature・ベンチマーク条件での最大値であり、全条件の保証ではない。利得はdrafter品質、AR correction ヘッドの精度、tree width/深さ、検証 budgetに依存する。候補木が広がるほどproposal メモリと対象 検証コストも増える。また学習不要である代わりに、利用可能なpretrained diffusion drafterとcorrection ヘッドの組合せへ依存する。
