# [AAFLOW+] Stateful Operator Abstraction with Zero-Copy Distributed KV Cache Orchestration for Multi-Agent Workflows
## 概要
multi-agent workflowではplanner、retriever、ソルバー、debate 分岐などが同じ長い文脈を繰り返し読む。テキストだけを受け渡すと各agentが同じ接頭辞をプリフィルし直す。AAFLOW+はKV キャッシュを「推論提供 engine内部の副産物」ではなく、workflow graphが配置・転送・分岐できる第一級の分散状態へ昇格させる。

## 問題設定
局所 接頭辞 キャッシュは同一engine内の共有には効くが、agentが別ノード/backendへ移ると状態を持ち越しにくい。長いRAG 文脈ではプリフィルが最初のトークンまでの時間（TTFT）を支配し、分岐数kなら同じプリフィルをk回払う。KVを送れば再計算を避けられるが、KV自体が大きいため低帯域ネットワークでは転送の方が遅い。

## 手法
### stateful operator graph
通常のdata edgeに加えて状態 edgeを持つgraphを構築し、演算子へ入力/出力 KV 状態を付与する。`materialize` はテキストからKVを生成し、`transfer` はノード間移動、`fork` は分岐共有、`compose` は互換な状態の結合、`evict` は寿命終了状態を解放する。コンパイラ/スケジューラがdataと状態の依存を同時に見る。

### KV state metadataと互換性
状態 objectにはモデル/tokenizer構成、KV ブロック、トークン range、位置情報、lineage、配置/ownershipを持たせる。別モデルや位置互換性のないKVを誤再利用すると生成を壊すため、compatibility predicateを満たさない場合はテキストからの通常プリフィルへfallbackする。

### transfer-aware scheduling
スケジューラは `KV size / network bandwidth + resume overhead` と局所 プリフィル コストを比較し、transferかrecomputeを選ぶ。高帯域では一度materializeした状態を分岐へforkする方が有利だが、短文脈や低帯域ではrecomputeへ戻せる。zero-copy data pathを前提にserialization/copy費用も減らす。

## 評価条件
|項目|条件|
|---|---|
|モデル|Mistral-7B、Llama-3-8B|
|workflow|multi-agent debate、tree/分岐型workflow等|
|agent scale|最大16 agent|
|ネットワーク|帯域を変化させる解析|
|評価形態|ハードウェア マイクロベンチマークで較正した解析コスト モデル|
|注意|主要aggregate 遅延/高速化倍率は実Slurm 実時間測定ではない|

## 主要結果
|指標|報告値|解釈|
|---|---:|---|
|TTFT|最大50.2倍短縮|長い共有接頭辞の再プリフィルを避ける|
|16-agent compute コスト|最大7.63倍削減|分岐数増加で共有効果が拡大|
|KV メモリ|1.72〜6.10倍削減|fork/ownership管理で複製を抑制|
|スループット|7.74倍超|解析モデル上のstateflow対textflow差|

重要なのは、これらのheadline値が「実装済み分散ランタイムをエンドツーエンド実測した速度」ではなく、実測マイクロベンチマークをパラメータにしたコスト モデルのaggregate値である点である。したがって50.2倍等はシステム実測として解釈しない。

## 既存研究との差
vLLM/SGLangの接頭辞 再利用は推論提供 engine内のキャッシュ 再利用が中心である。KVCOMMのようなcross-文脈 KV 通信に対し、AAFLOW+はworkflow コンパイラから状態 lifecycleを見せ、materializeからfork/transfer/追い出しまで演算子 algebraとして統一する点を主張する。

## 限界
主要性能値は解析モデル依存で、実際のスケジューラ contention、NIC/GPU copy 重畳、メモリ pressureを含むproduction ランタイムでの再現性は未確立である。共有接頭辞・同一モデルを中心にし、heterogeneous モデル間状態変換、長いデコード、強い追い出し pressureは限定的である。answer qualityへの大規模評価も不足する。
