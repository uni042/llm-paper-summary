# Efficiently Serving Large Multimodal Models Using EPD Disaggregation

## 書誌情報
- canonical identity: `arXiv:2501.05460`
- 著者: Gursimran Singh, Xinglu Wang, Yifan Hu, Timothy Yu, Linzi Xing, Wei Jiang, Zhefeng Wang, Xiaolong Bai, Yi Li, Ying Xiong, Yong Zhang, Zhenan Fan
- 一次資料: https://arxiv.org/abs/2501.05460

## 概要
大規模マルチモーダルモデル（Large Multimodal Model; LMM）は、テキストLLMのprefill/decodeに加えて画像・音声・動画を埋め込みへ変換するencode段階を持つ。従来の分離サービングはprefillとdecodeを分けても、encodeをprefill側に同居させることが多い。その場合、画像数や解像度で大きく変動するencode負荷がprefillのバッチ形成・メモリ利用を乱し、最初のトークンまでの時間（TTFT）と端から端スループットを悪化させる。

EPD Disaggregationは処理をEncode・Prefill・Decodeの3段へ分け、それぞれを専用資源で実行する。分離だけでは中間表現転送や資源不足が新たな費用になるため、マルチメディアtokenのキャッシュと転送、単一request内のencode並列化、負荷に応じた資源配分探索、役割切替を組み合わせる。

評価では一般的なLMMを用い、非分離構成に対してメモリ使用量を最大15倍削減、batch sizeを最大22倍、1 request当たり画像数を最大10倍、利用可能KV cacheを最大2.2倍へ拡大した。TTFTは最大71%短縮される。これらは同一指標の倍率ではなく、異なる負荷・資源条件で観測された最大値なので一括して同時達成と解釈してはいけない。

## 問題設定
LMMのencodeは入力媒体によって計算量が大きく変わる。テキストprefillはtoken長、画像encoderは画像枚数・解像度、動画ではframe数にも依存する。encodeとprefillを同じworkerへ束ねると、重い視覚入力がprefill要求をhead-of-line blockingしやすい。

またencodeは一度作った媒体表現を後段へ渡す必要がある。段階を別GPUへ置くだけでは大きな中間tensor転送が発生し、分離の利点を相殺する。さらに負荷比率は時間とともに変化するので、固定台数のencode/prefill/decode workerでは一段だけが飽和する。

## 手法
### E/P/D三段分離
入力requestをまずEncode workerへ送り、画像等をLLMが利用するマルチメディアtokenへ変換する。次にPrefill workerがテキストtokenと媒体tokenを処理してKV cacheを作り、Decode workerが自己回帰生成を継続する。

各段階の計算・メモリ特性を別資源へ隔離することで、encodeの変動がprefill batchを直接壊さず、decodeの低算術強度処理もprefillと競合しない。出力はE→P間の媒体表現とP→D間のKV状態である。

### マルチメディアtoken cache
E→P分離ではencoder出力を転送する必要がある。システムは媒体tokenを再利用可能な形でキャッシュし、同じ媒体や繰返し参照でencodeをやり直す費用を避ける。これは通常のprefix KV cacheとは異なり、マルチモーダルencoderとLLM prefillの境界に置かれる中間表現キャッシュである。

利点はencode計算の削減と段階間転送の整理だが、追加のcache容量・lookup・転送管理が必要になる。媒体tokenが巨大な場合はネットワーク帯域も設計制約になる。

### request内encode並列化
多数画像や動画frameを含むrequestでは、1 requestのencode自体が長い。EPDは独立に処理可能な媒体要素を複数Encode workerへ分配し、request内並列性を利用する。これにより巨大requestが単一encoderを長時間占有するのを防ぐ。

出力を元の入力順序へ再構成してprefillへ渡す必要があるため、分割・集約の管理費用は増える。画像数が少ないrequestでは並列化利得も小さい。

### 資源配分とrole switching
システムはE/P/D各段の負荷を基に、限られたGPUをどの役割へ割り当てるか探索する。固定分割ではなく、ワークロード変化に応じてworkerの役割を切り替えることで、特定段階だけが飽和する状態を緩和する。

この機構は三段分離を実運用へ適用するために重要である。単に3 poolを作るだけなら負荷比率の変化で遊休GPUとqueueが同時発生するが、role switchingにより供給能力を移動できる。

## 評価条件
| 項目 | 条件 |
|---|---|
| 対象 | 画像等を入力する代表的LMM |
| 比較 | encode+prefillを束ねる非EPD構成 |
| 主指標 | memory utilization、batch size、images/request、KV capacity、TTFT、end-to-end throughput |
| 方式 | E/P/D専用資源、媒体token cache、encode並列、資源配分、role switching |

## 主要結果
| 指標 | 最大改善 | 意味 |
|---|---:|---|
| メモリ使用 | 15×少ない | 段階ごとの状態を隔離し同居ピークを回避 |
| batch size | 22×大きい | 各段のメモリ余裕をバッチへ転換 |
| images/request | 10× | encode資源と並列性を独立確保 |
| KV cache capacity | 2.2× | prefill/decode側のメモリ圧迫を軽減 |
| TTFT | 最大71%短縮 | encode/prefill競合と待ち時間を削減 |

論文要旨のend-to-end throughput表現は改善方向を示すが、個々の数値は条件依存である。特に15×、22×、10×、2.2×、71%は単一設定で同時に得られた一組の値として扱わない。

## 既存研究との差
Prefill/Decode分離はLLMで広く使われるが、LMMではその前に重いencoderがある。EPDはこのencodeを独立した第一級サービング段階として分離し、三段の資源配分問題へ拡張する。

単なるmodel pipeline parallelismとも異なる。目的はモデル層を均等分割することではなく、計算特性と状態が異なるE/P/Dフェーズを別worker poolへ配置し、負荷に応じて役割を変えることである。

## 限界
段階分離によりネットワーク転送とキューが増えるため、媒体tokenやKVの転送帯域が不足すると利得が縮む。小さな画像1枚・短promptのようにencodeが軽いrequestでは、分離管理費用が相対的に大きい。

資源配分はワークロード分布に依存する。急激な変化ではrole switching自体の移行費用が発生する。また最大値は異なる評価条件の代表値であり、すべてのLMM・GPU・入力構成で同じ改善を保証しない。
