# Post-Training Sparse Attention with Double Sparsity

## 書誌情報
- 著者: Shuo Yang, Ying Sheng, Joseph E. Gonzalez, Ion Stoica, Lianmin Zheng
- canonical identity: `arXiv:2408.07092`
- 公開: 2024-08-11
- 一次資料: https://arxiv.org/abs/2408.07092

## 概要
自己回帰decodeはメモリ帯域律速になりやすく、長文脈ではモデル重みだけでなく鍵・値キャッシュ（KV cache）の読出しが支配的になる。重要tokenだけを読む疎注意は有望だが、重要tokenを知るために完全な注意を計算すれば高速化にならず、動的にchannelを選ぶ方式は非連続メモリアクセスでGPU帯域を浪費する。

Double Sparsityは、token重要度はstepごとに変わる一方、注意scoreへ強く寄与するfeature channelは比較的安定するという観察を利用する。offline calibrationで重要channelを固定し、その値だけを小さなlabel cacheへ連続配置する。decode時はlabel cacheから近似注意を計算して上位tokenを選び、そのtokenの完全なK/Vだけを読み、本来のattentionを計算する。

1/16のtoken sparsityとchannel sparsityを同時に使い、A10G/A100上でattention演算を最大14.1倍、Llama-2-7Bのend-to-end推論を最大1.9倍高速化した。offload版では完全KVをCPUに置き、次層で必要なtokenだけを先読みすることで、256K系列長でFlexGen系baseline比16.3倍のdecode高速化を報告する。

## 問題設定
H2Oのようなeviction方式はGPU上のKV容量を減らせるが、一度捨てたtokenが将来重要になると回復できない。SparQのように全KVを残してqueryごとに重要tokenを選ぶ方式は品質を守りやすいが、channel/token gatherが非連続になり、128-byte単位のGPUメモリアクセスやL1/L2 cacheを効率よく使えない。論文ではSparQのattention高速化が約1.3倍に留まることを問題視する。

必要なのは、全KVを保持して将来重要になるtokenを失わず、しかし各stepではごく一部だけを連続的に読む方法である。Double Sparsityは「重要channelはofflineに固定できる」という第二の疎性をtoken sparsityの索引として使う。

## 手法

### 1. offline channel calibration
注意score `A=QK^T` をchannelごとの寄与 `S_i=Q_i*K_i` の和として見て、小さなvalidation set上で寄与が大きいchannelを各層ごとに集計する。重要channel集合 `C` は実行時に動かさないため、動的channel選択のsort/gatherを排除できる。

offlineで選んだchannelとonlineで選ぶchannelの重なりを調べると、channel比率が0.25を超える領域でoverlapが0.95に達する。これが固定channelをtoken検索の近似器として使える根拠になる。

### 2. label cacheによる近似注意
prefill時に、選んだ重要channelだけをKey cacheから抜き、token順に連続した `K_label` として保存する。近似注意はqueryの同じchannel `Q_label` と `K_label` の積だけで全tokenを順位付けし、`argtopk` で上位 `k=βS` tokenを得る。

その後は選ばれたtokenの完全次元K/Vだけを読み、通常のsoftmax attentionを計算する。label cacheは近似順位付けだけなので4-bit保存でき、論文設定ではK cacheの約1/16。非連続channel gatherを実行時にしないため、連続メモリアクセスを保てる。ablationではlabel cacheがない実装よりdecodeを2〜4倍高速化した。

### 3. token sparsityとchannel sparsityの結合
channel比 `α` が近似attentionの読出し量、token比 `β` が本attentionで読むKV量を決める。I/O量は概ね `αSd + 2βSd` で、支配項は選択tokenのK/V読出し `2βSd` になる。1/16設定では全token・全channelを読むfull attentionから帯域要求を大きく削れる。

重要なのは、KV自体を捨てず「読むtoken」を疎にする点である。そのため将来のqueryで重要度が変わっても再選択できる。ただし全KVをGPUへ残す基本版は容量削減にはならず、容量問題にはoffload版を使う。

### 4. Double Sparsity-Offload
offload版は完全KVをCPUへ置き、GPUにはlabel cacheとdouble bufferだけを残す。現在層を処理中に、その層のembeddingを次層のquery projectionへ先に通して近似queryを作り、次層で必要になりそうなtokenをlabel cacheで予測する。そのtokenのK/VをCPUから次bufferへ非同期転送する。

隣接層embeddingはLlama-2-7B/Pileで多くの層対がcosine similarity 0.95超、ほぼ全ての中間層で0.90超だった。したがって一層前のembeddingから次層tokenを予測しても選択集合が大きく崩れにくく、計算とPCIe転送を重ねられる。最初の数層と最終層付近では類似度が低い点は制約である。

## 評価条件

| 項目 | 条件 |
|---|---|
| モデル | Llama/Llama-2 7B/70B、Mistral-7B、Mixtral-8x7B等 |
| 品質 | WikiText-2 PPL、MultiFieldQA、GovReport、TriviaQA、MMLU、KV retrieval |
| GPU | NVIDIA A10G、A100-SXM |
| 実装 | PyTorch近似注意 + Triton top-k attention、gpt-fast統合 |
| 精度 | weight/activation FP16、label cache 4-bit |
| workload | batch 4–32、sequence 1K–16K、offloadは64K–256K |
| 比較 | PyTorch scaled_dot_product_attention、gpt-fast、FlexGen offload、H2O等 |

## 主要結果

| 条件 | 結果 | 意味 |
|---|---:|---|
| attention kernel | 最大14.1×高速化 | KV読出し削減がkernel時間へ反映 |
| end-to-end | 最低1.3×、最大約1.9× | attention以外の層を含めても利得 |
| offload 64K–256K | FlexGen比4–8×、長文脈で最大約16×/256K総括16.3× | 必要tokenだけ転送する効果 |
| WikiText-2 Llama-2-7B | PPL 5.47→5.76 (1/16) | 1/16では品質低下が小さい |
| 同 1/32 | PPL 12.01 | 1/16を超える圧縮で急激に悪化 |
| label cache ablation | 2–4×高速化 | 連続配置が実測性能に重要 |

Mixtral-8x7Bの一部channel選択では悪化が大きく、GQAではK側outlier channelが使えない条件も報告される。したがって「1/16なら全アーキテクチャで無損失」ではない。

## 既存研究との差
H2O/StreamingLLMはKVを捨てるためGPU容量を減らせる一方、将来必要になるtokenを失う。Double Sparsity基本版は全KVを保持し、各stepで読むtokenだけを変えるためこの不可逆性を避ける。

SparQも全KVから動的選択するが、channel gatherが非連続でhardware efficiencyを損なう。Double Sparsityはchannel選択をofflineへ追い出し、連続label cacheを作ることで、アルゴリズム上の疎性をGPUの実帯域削減へ結び付ける。offload版はさらにその索引をCPU常駐KVのprefetchへ利用する。

## 限界
offline calibrationで得たchannel sparsityが配備分布でも安定することが前提で、分布が大きく変わる場合の再calibration頻度は十分評価されていない。GQA/MoEではoutlier種類により品質差が大きく、Mixtralの一部設定は明確に失敗する。

基本版は全KVをGPUに残すため、容量自体を減らしたい場合はoffload版が必要になる。offload版はCPUメモリとPCIe帯域を消費し、隣接層類似性が低い層では先読み精度が落ちる可能性がある。最大倍率は長系列・帯域律速条件であり、短系列やattention比率の低いworkloadへそのまま外挿できない。
