# HAP: Hybrid Adaptive Parallelism for Efficient Mixture-of-Experts Inference

## 概要
混合専門家（MoE）モデルの分散推論では、テンソル並列（tensor parallelism; TP）、専門家並列（expert parallelism; EP）、データ並列（data parallelism; DP）のどれが良いかは一意でない。注意計算と専門家計算では通信形態が違い、プリフィルとデコードでもバッチサイズ・演算密度が大きく変わる。HAPはモデル全体へ一つの並列方式を固定する代わりに、MoE層を注意モジュールと専門家モジュールへ分解し、phaseごとに組合せを選ぶ。

各候補構成の計算・通信遅延を軽量シミュレータで予測し、整数線形計画（Integer Linear Programming; ILP）がメモリ制約とphase切替費を含めて最小遅延構成を求める。MixtralとQwen系MoEを複数GPU世代で評価し、固定TPに対しA100で最大1.68倍、A6000で1.77倍、V100で1.57倍の高速化を報告する。

## 問題設定
TPは専門家重みを複数GPUへ分割して演算を並列化できるが、各層で集合通信が必要になる。EPは専門家をGPUへ分散配置し、トークンを担当GPUへall-to-allする。どちらが有利かは専門家サイズ、トークン数、GPU演算性能、相互接続帯域に依存する。

さらにプリフィルでは多数トークンをまとめて処理するため大きな行列積を効率良く使えるが、デコードは小さいバッチ・1step単位になりやすい。したがって同じモデルでもphaseが変われば計算と通信の支配項が変わる。固定TPを全phase・全モジュールへ適用することがHAPの出発点となる非効率である。

## 手法
### モジュール分解
各MoE層を注意モジュールと専門家モジュールへ分ける。注意側はDP、TP、DP+TP、専門家側はEP、TP、EP+TPなどを候補とし、両者を階層的に組み合わせる。これによりモデル全体を一枚岩として探索するより、各処理の通信パターンに合う構成を選べる。

### 遅延シミュレータ
計算時間はFLOPsとGPUピーク性能、通信時間はデータ量と帯域を基礎にし、実機マイクロベンチマークから得た補正係数を回帰モデルで学習する。理論ピーク値だけでは小行列や集合通信の実効効率を表せないため、ランダムフォレストで実測差を補正する。

### ILPによる構成選択
プリフィル費、出力長に応じたデコード費、phase間の構成切替費を目的関数へ入れ、GPU数の可除性やメモリ容量を制約としてILPを解く。探索は4/8 GPU規模で1秒未満とされ、報告するエンドツーエンド時間にも探索費を含める。

### phase切替
プリフィル最適構成とデコード最適構成が異なる場合、専門家重みの配置変更が必要になる。HAPは直接の集合通信だけでなく、CPU側に保持した量子化重みを利用する経路も比較し、より安い切替を選ぶ。切替を無視して理想構成を選ぶのではなく、その費用も最適化対象に含める。

## 評価条件
| 項目 | 内容 |
|---|---|
| モデル | Mixtral-8x7B、Qwen1.5-MoE-A2.7B、Qwen2-57B-A14B等 |
| GPU | A100、A6000、V100 |
| 実行基盤 | DeepSpeed-FastGen系実装 |
| 比較 | 固定TP中心の推論 |
| 探索 | 4/8 GPUでILP、探索時間1秒未満 |
| 指標 | エンドツーエンド推論遅延、固定TP比高速化 |

## 主要結果
A100では固定TP比最大1.68倍、A6000では1.77倍、V100では1.57倍を達成する。通信制約が強いGPU構成ほど、注意と専門家で通信方式を変える価値が大きくなる。Mixtralだけでなく、専門家構成の異なるQwen系列でも改善を示し、特定の専門家数だけに探索器が依存しないことを確認する。

プリフィルとデコードの最適戦略が異なるケースでは、phase別構成を選ぶことで静的TPを上回る。探索時間を結果へ含めても改善が残るため、長時間のオフライン探索を前提にしない点も実用上重要である。

## 既存研究との差
既存のTP/EPサービングは、実装時に選んだ並列方式をモデル全体・両phaseへ固定することが多い。HAPは注意と専門家を別々に扱い、さらにプリフィルとデコードも別構成にする。自動並列化研究と比べても、MoE固有のall-to-allとphase切替コストを目的関数へ明示的に含める点が特徴である。

## 限界
遅延モデルは計算時間と通信時間の加法性を近似し、回帰補正も事前マイクロベンチマークに依存する。計算通信の重畳や帯域競合が予測外に変化するとILPの最適構成が実機最適からずれる可能性がある。GPUやネットワークを変更すればプロファイルを取り直す必要がある。phase切替用CPU重みはホストメモリも消費し、頻繁な短要求では切替費の相対比が増える。
