# Latent Space Communication via K-V Cache Alignment

> 各LLMのKVキャッシュを共通潜在空間へ出入りする2個のtranslatorで整列し、異種モデル間のprefix状態・soft promptをtoken化せず直接移送する。

## 書誌情報

- canonical identity: `arXiv:2601.06123`
- 著者: Lucio M. Dery, Zohar Yahav, Henry Prior, Qixuan Feng, Jiajun Shen, Arthur Szlam
- 一次資料: https://arxiv.org/abs/2601.06123

## 概要

複数LLMを協調させるとき、通常は先行モデルが知識や推論結果をtextへ復号し、後続モデルがそのtextを再度prefillする。textはモデル間の共通インターフェースとして便利だが、内部状態より帯域が狭く、soft promptや中間KVのような連続表現を直接渡せない。

本論文は、各モデル固有の鍵・値キャッシュ（KV cache）を一つの共有潜在空間 `Σ` へ写像する。モデル `m_i` ごとに `T[m_i→Σ]` と `T[Σ→m_i]` の2 translatorだけを学習するため、全model pairに専用変換を持つO(N²)構成ではなく、モデル数に線形なO(N)個のadapterで任意のsource→target経路を構成できる。

translatorはlayer-wise KVを単純に同じ層番号へ対応させない。モデルごとに層数やhidden次元が違い、同じ層数でも残差接続により潜在空間が直接対応する保証がないため、各層KVをcross-attentionで読みながら固定次元Qの共有表現へ混合し、target側translatorが自モデルのlayer構造へ再構成する。

Gemma-2系100M〜400Mを凍結しtranslatorだけを学習した実験では、異なるcheckpoint、異なる言語fine-tune、異なるrandom seed、異なるmodel size間でprefix KVを移送できる。200Mの異seed 2モデルでは最良translatorのsuffix評価lossがSeed1で3.056（identity 3.089）、Seed2で3.076（identity 3.117）となり、単なる復元ではなく元モデルをわずかに上回る場合もある。

## 問題設定

同じtextを入力しても、異なるパラメータを持つTransformerのKV cacheは互換ではない。各層のKVは前層までの表現に条件付けられるため、小さな表現差が深さとともに蓄積する。したがってsourceモデルのKV tensorをtargetモデルへそのまま挿入すると、次token予測に必要な内部幾何が一致しない。

model pairごとに直接変換器を学習すればNモデルでN(N-1)経路が必要になり、モデルpool拡大時の学習・保存コストが二次的に増える。また層数が4対16のように異なる場合、layer番号を固定対応させる設計自体が成立しにくい。

論文は「共有潜在空間」をハブにして、各モデルがそこへwriteし、そこからreadする形へ問題を変換する。新モデル追加時は既存model pairを再学習せず、新モデル用の入出力translatorだけを学習できることを狙う。

## 手法

### モデルごとの双方向translator

モデル `m_i` のKVは `B×S×L_i×D_i`。local→shared translatorはこれを `B×S×Q` へ写像し、shared→local translatorは逆に `B×S×Q` からtargetモデルの `L_i×D_i` 構造へ戻す。Qはpool全体で共通にする。

共有空間には明示的な「第k層」区切りを持たせない。local→sharedでlayer情報を混合し、target側が必要なlayer分解を学ぶ。これにより異なる層数のモデル間でも、4層sourceから16層targetのような変換を同じ枠組みで扱う。

### cross-attention translator

入力KVにはlayer normalization、線形変換、GELUを適用し、layerごとの中間表現を作る。その後のcross-attentionでは、前translator layerの出力をquery、対応する入力KV layerをkey/valueとして読む。最後に各layer出力を連結し、非線形output transformで共有表現またはlocal KVへ変換する。

keyとvalueでは最初の線形変換パラメータを分ける一方、cross-attention本体は共有する。translator規模は通常設定で各base modelのおよそ1/4になる。これは無視できない追加計算・パラメータであり、通信が無料になる方式ではない。

### suffix language modelling loss

単純な再構成損失は、source KVをtarget KVへ近づけるが、わずかなKV誤差が次token予測で増幅し得る。また完全再構成を目標にするとtargetモデル本来の性能を上限にしてしまう。

そこでtextをprefixとsuffixへ分け、sourceモデルでprefix KVを作り、共有空間経由でtarget KVへ変換し、そのKVを条件にtargetモデルがsuffixを予測するcross entropyを直接最小化する。これにより「tensorが近いか」ではなく「変換後cacheが言語モデルとして役立つか」を学習信号にする。

### pool拡張とsoft-prompt移植

既存3モデルの共有空間へ4番目を追加する実験では、Seed-4の2 translatorだけを学習し、既存translatorは凍結する。Seed-4とSeed-1の直接経路を学習していなくても、共有空間を介したzero-shot変換が学習済み経路に近い性能を示す。

さらにsoft promptをsourceモデルで学習し、そのcache表現を共有空間経由でtargetへ移送する。5.8K meta-train taskと200 meta-test taskのprompt recovery実験で、random promptより大幅に良く、targetごとにsoft promptを直接学習する上限へ近づく。

## 評価条件

| 項目 | 条件 |
|---|---|
| base model | Gemma-2系、100M〜400M（token embedding除外） |
| base重み | 凍結。translatorのみ学習 |
| データ | multilingual C4、主に英語・ロシア語・スペイン語 |
| 最大系列長 | 512。通常prefix 128 |
| translator | 32 heads、head dim 64、通常base modelの約1/4規模 |
| 学習 | 50K steps、AdamW、batch 256/512/1024 sweep |
| model差 | checkpoint、fine-tune分布、random seed、model size |
| module移植 | 約6K prompt task、5.8K train / 200 test |
| 指標 | suffix negative log likelihood / evaluation loss |

## 主要結果

| 条件 | 指標 | 結果 | 比較 | 読み取れること |
|---|---|---:|---|---|
| 200M異seed、Seed1 | suffix loss | 3.056 | identity 3.089 | 共有空間往復で元cacheをわずかに上回る |
| 同、Seed2 | suffix loss | 3.076 | identity 3.117 | 別seedでも同傾向 |
| 100M↔400M | suffix modelling | 100M側を改善 | 未変換100M | 層数4倍差でも変換可能 |
| 4モデルpool拡張 | unseen path | 学習済みpathに近い | Seed4↔Seed1未学習 | hub型共有空間のzero-shot経路を確認 |
| soft-prompt移植 | meta-test loss | randomより大幅改善、direct学習上限へ接近 | random / target直接学習 | task moduleをモデル間移送可能 |

線形写像も同seed分布条件では強いが、共有次元を8倍・24倍へ拡張する設定が必要になる。cross-attention translatorはより少ないパラメータで線形写像を上回り、adapter規模を増やすと性能が改善する。

## 既存研究との差

Text-to-Text型multi-agentは自然言語を共通通信形式にする。本方式はprefix内部状態そのものを通信対象にし、tokenへ復号してから再encodeする必要をなくす可能性を示す。ただし本論文は大規模サービングlatencyの実測研究ではなく、表現互換性の成立を主に検証する。

model pairごとのlatent alignmentに対しては、全pairの直接mapではなく共有hub `Σ` を置き、各モデル2 translatorだけで任意経路を作る点が異なる。新モデル追加時に既存pairを再学習しない設計につながる。

prefix tuningのようなtask moduleは通常モデル固有である。本方式はsoft promptをKV表現へ落とし、共有空間経由で別モデルへ移すことで、skill学習費用をmodel poolで共有する。

## 限界

評価モデルは100M〜400Mの小型Gemma-2系が中心で、数十B級LLMや異なるattention構造を跨いだ実証はない。モデル間通信の概念実証としては強いが、現行の大規模推論基盤へそのまま適用できる性能証明ではない。

通常translatorがbase modelの約1/4規模であり、変換自体の計算・メモリ費用は小さくない。論文はtoken通信に対するend-to-end latency、GPU間転送bytes、multi-tenant throughputを主要指標として評価していない。

再構成損失は異なるvocabulary間へ直接使いにくい。suffix language modelling lossはモデルがtextの別区間を担当するためvocabulary差を許容しやすいが、token位置対応やcache sequence alignmentの問題が完全に消えるわけではない。
