# LayerRoute: Adaptive Layer-Skipping with LoRA-Preserved Quality for Efficient LLM Inference

## 概要
Transformerは通常、入力の難しさに関係なく全トークンを全層へ通す。LayerRouteはQwen2.5-0.5B-Instructの24 blockそれぞれへ小さなbinary ルーティングを置き、入力に応じてblockを実行するかskipするか決める。同時にrank-8 LoRAを注意機構 projectionへ入れ、層を飛ばすことで失われる表現能力をパラメータ-efficientに補償する。

10個の独立seedで学習したところ、全runで中間の層 8〜16という同じ9層がskip-eligibleになる構造へ収束した。壁時計速度は全runで改善し1.02〜1.06倍、平均1.04倍。LoRA適応により評価分割のperplexity差は平均-1.16/-1.11で、backboneより悪化しなかった。さらにskip-eligible 層ではheld-out サンプルの87〜100%でルーティング decisionが実際のskip/runを変え、固定枝刈りではなく入力依存ルーティングであることを確認する。

## 問題設定
層 skippingは計算量を直接減らせるが、固定して層を削ると簡単な入力にも難しい入力にも同じdepthしか与えられず品質低下が起こる。入力依存ルーティングを使う場合も、skipで表現分布が変わるため、元モデルをそのまま使うだけでは品質を維持しにくい。またFLOPs削減が実際のwall-clock高速化へつながるかはルーティング オーバーヘッドやカーネル launchの影響を受ける。

LayerRouteは「どの層を入力依存で飛ばすか」と「飛ばした状態へ残りのネットワークをどう適応させるか」をjoint 学習する。backbone全体を再学習せず、ルーティングとLoRAだけを更新することで学習費を抑える。

## 手法
各24 transformer blockへ約21.5K パラメータの層 hard-gated ルーティングを追加する。ルーティングは隠れ representationからbinary gateを出し、順伝播ではhard decisionでblockを実行/skipする。離散decisionは通常勾配を流せないため、straight-through estimatorを使ってbackpropagation時に近似勾配を通す。

同時に注意機構のQ/K/V/O projectionへrank 8のLoRAを追加し、合計約1.08M パラメータを学習する。backboneは固定される。目的関数はlanguage-modeling lossへgate regularizationを加え、品質だけを追って全層を常時実行する解に戻らないようskipを促す。

重要なのは、ルーティングだけを学習して既存backboneへ無理にskipを課すのではなく、LoRAがskip後のrepresentation distributionへ残りの経路を適応させる点である。この共同最適化により、計算削減とperplexity維持を同じ学習 目的関数内で扱う。

## 評価条件・主要結果
| 観点 | 条件・結果 |
|---|---|
| backbone | Qwen2.5-0.5B-Instruct、24 blocks |
| ルーティング | 各層約21.5K parameters |
| LoRA | rank 8、約1.08M parameters |
| 再現性 | 10 independent seeds |
| skip構造 | 全10 seedで層 8〜16の9層がskip-eligible |
| wall-clock | 1.02〜1.06倍、平均1.04倍高速化 |
| 品質 | perplexity delta平均 -1.16 / -1.11 |
| 入力依存性 | held-out samplesの87〜100%でgateが実skip/runを変更 |
| 学習 | single A100で7分未満 |

大きなFLOPs削減率だけを示すのではなく、全seedでwall-clock 高速化倍率が正であることを確認した点は重要である。一方、平均1.04倍という利得はルーティング オーバーヘッドや小規模モデルの実行特性を含む現実的な値で、理論的なskip率ほど大きくない。

## 既存研究との差
固定層 枝刈りに対し入力依存ルーティングを使い、既存の適応型 depth方式に対してLoRA補償を同時学習する。さらに単一runの良い結果ではなく10 seedで同じskip-eligible中間層へ収束すること、ルーティング decisionがサンプルごとに実際に変化すること、FLOPsではなくwall-clockまで検証することを強調している。

## 限界
評価backboneは0.5B級Qwen2.5であり、70B級やMoE、テンソル-並列 推論提供へ同じ1.04倍が移る保証はない。ルーティングとLoRAの学習が必要なので完全な学習不要最適化ではない。skip可能層が主に中間9層へ集中する結果が他構成でも再現するかも未確定である。また大バッチやcontinuous batchingでは動的 control flowがGPU batching効率を落とす可能性があり、論文の単体wall-clock結果だけでは推論提供 スループットを結論できない。
