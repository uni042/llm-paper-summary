# RouteRAG: Efficient Retrieval-Augmented Generation from Text and Graph via Reinforcement Learning

## 概要

RouteRAGは、言語モデルが推論途中に外部知識を調べる際、通常の文書検索、知識グラフ検索、両者の混合検索を状況に応じて切り替える方策を強化学習で獲得する検索拡張生成方式である。従来の文書検索型の複数ラウンド検索は関係の連鎖を追うのが苦手で、グラフ型は関係をたどれる一方で検索費用が高い。検索方式を固定すると、単純な質問にまで高価なグラフ検索を使ったり、複数段階の質問で文書だけを繰り返し検索したりする。RouteRAGは、推論・検索・最終回答を同じ生成方策の行動として扱う。

著者はQwen2.5-3B/7Bを用い、まず正答を報酬とする学習で検索と推論の基本動作を獲得させ、次に正答した軌跡に限って検索時間の短さを評価する報酬を加える。5つの質問応答集合の平均F1は3Bで55.7、7Bで60.6となり、同じ基盤のSearch-R1の49.3、56.8を上回った。7Bでは効率報酬を除いた構成に対して平均検索ラウンド数が2.70から2.25へ減り、平均F1も59.5から60.6へ上昇した。これらは外部検索を含む回答品質と検索回数の改善であり、GPUの生成速度だけの比較ではない。

## 問題設定

言語モデルの内部知識だけでは最新情報や複数文書にまたがる関係を確実に答えられないため、検索拡張生成では外部の証拠を取得する。文書検索は入力質問と文書の埋め込み類似度から関連箇所を取得するため、直接的な事実照会に適している。一方、複数の人物・場所・出来事を経由する質問では、文章に散らばった関係を接続する必要があり、知識グラフの経路情報が有効になる。ただしグラフ構築・探索には追加の費用がかかる。

固定的な混合検索では、各質問に対して同じ順序・同じ種類の検索を行いがちである。複数ラウンド検索を使っても、検索が必要か、どの資料が不足しているか、いつ回答を確定すべきかを外部の規則だけで決めると柔軟性が低い。小型言語モデルではこの判断を自然言語の指示だけで安定して実行することも難しい。RouteRAGの目的は、検索の種類と検索時点をモデル自身が選び、回答精度を落とさず検索の無駄を減らすことである。

本論文での「効率」は主として外部検索にかかる時間と検索ラウンド数を指す。生成する推論トークン数やモデルの前向き計算量も関係するが、論文の主要報酬は検索時間に基づく。したがって、検索時間が減ったことをそのまま要求全体の実測遅延短縮率やGPUスループット改善率と同一視してはならない。

## 手法

### 1. 推論と検索を統合した逐次行動方策

RouteRAGの入力は質問q、学習対象の生成方策πθ、外部検索器R、最大行動ステップ数Bである。方策は現在の質問とこれまでの推論・検索結果を文脈にしてトークンを生成し、通常の推論を続けるか、`<search>...</search>` で検索要求を発行するか、`<answer>...</answer>` で最終回答を返すかを決める。検索要求には検索用の部分質問と、`[passage]`、`[graph]` の標識を含める。両標識を付ければ混合検索になる。

原著のアルゴリズム1では、検索標識を検出すると要求文から部分質問を取り出し、指定された方式で検索器Rを呼ぶ。返ってきた文書を `<information>...</information>` として文脈に追加し、同じ方策が次の推論・検索・回答を生成する。最終回答の標識を出した時点で終了し、最大ステップ数に達した場合も終了する。ここでの出力は、検索器が直接返す文章ではなく、取得証拠を参照して方策が生成した最終回答である。

このループでは、検索方式の選択、検索用部分質問の作成、次の推論、回答の確定が一つの方策の内部で決まる。例えば一度目の文書検索で人物名が特定できた後、二度目に関係グラフをたどることもできる。固定的な検索順序を事前に指定しない点が特徴だが、方策が不適切な部分質問を生成すると検索器から十分な証拠が得られないため、後述する正答報酬による学習が必要になる。

### 2. 文書・グラフ・混合検索の実装

文書検索は密な文書埋め込みによる検索方式で、質問と文書を同じベクトル空間へ符号化し、類似度上位の文書を返す。3BではContriever、7BではNV-Embed-v2を利用する。グラフ検索はHippoRAG 2を基に、文書から構築した知識グラフ上で質問に関連する節点から個人化PageRankを実行し、複数の関係を経由して関連文書を発見する。文書検索とグラフ検索は取得の根拠が異なるため、両方を使う場合は相互順位融合（RRF）で順位を統合する。

混合検索のRRFは、各文書の文書検索順位とグラフ検索順位に応じて `1/(k+rank)` の寄与を加算し、どちらか一方で上位の文書も候補に残せる。これは二つの検索結果を単純に連結するのではなく、順位に基づいて一つの証拠集合を作る処理である。ただし混合検索では両検索器を実行するため、文書検索だけの場合より外部検索費用が増える可能性がある。モデルが必要な場面だけ混合方式を選ぶことが、効率改善の一部を担う。

### 3. 第1段階：回答正答率を優先する強化学習

学習には群相対方策最適化（GRPO）を用いる。第1段階では最終回答が正解と完全一致すれば報酬1、誤答なら0とする。検索方式や検索回数に直接の費用罰則を与えず、まず「いつ検索し、どの証拠を使って答えるか」を学習させる。検索器から返る証拠を使って多段の質問を解く能力が十分でない段階で、先に検索を減らすように学習させると、単に検索を省いて誤答する方策になり得るため、正答を先に重視する設計である。

GRPOは同じ質問について複数の応答軌跡を生成し、群内の相対的な報酬から方策を更新する。学習対象は回答トークンだけでなく、検索標識や検索用部分質問も含む生成方策である。これにより正しい回答へ到達するまでの検索行動全体を学習する。固定的な検索テンプレートを手作業で列挙するのではなく、モデルが外部検索器とのやり取りを逐次的に選ぶ。

### 4. 第2段階：正答軌跡だけに検索時間の報酬を追加

第2段階では、誤答軌跡の報酬を0のままにし、正答した軌跡に限って検索時間の短さに応じた報酬を追加する。原著式3～4では、正答軌跡の検索時間tと同じバッチの平均検索時間t_avgを比較し、`(t_avg − t)/T` を効率報酬とする。平均より短い検索時間で正解できた軌跡は正の追加報酬、長い軌跡は負の追加報酬を受ける。Tは報酬の尺度を制御する正規化定数である。

この設計の重要な点は、検索を減らしただけの誤答に正の効率報酬を与えないことである。正答の条件を先に満たした軌跡の中で、どの検索経路が短いかを学習する。平均を基準にした相対報酬なので、単純に「検索回数を常に1回にする」ような固定規則ではなく、質問の難易度に応じて必要な検索を残す方向へ更新できる。原著はこの報酬が実際に平均検索ラウンド数を減らすかを、報酬を除いた構成との比較で検証している。

## 実装・評価条件

| 項目 | 原著の条件 |
|---|---|
| 方策モデル | Qwen2.5-3B-Instruct、Qwen2.5-7B-Instruct |
| 学習問題 | HotpotQA訓練集合から10,000質問を抽出 |
| 文書検索器 | 3BでContriever、7BでNV-Embed-v2 |
| グラフ検索器 | HippoRAG 2、個人化PageRank |
| 混合検索 | 文書とグラフの結果を相互順位融合（RRF） |
| 評価集合 | PopQA、Natural Questions、HotpotQA、2WikiMultihopQA、MuSiQue |
| 比較方式 | 通常RAG、Search-o1、Search-R1、R1-Searcher、HippoRAG 2など |
| 指標 | 完全一致率EM、回答のF1、平均検索ラウンド数、検索時間に基づく効率報酬 |

HotpotQAと2Wikiは学習問題と近い多段推論集合であり、原著表1では同領域として標識が付く評価がある。PopQAやNatural Questionsなどの単純な質問では、グラフ検索を使う必要性が小さい場合もある。比較対象のうち、文書検索型の方式は同じQwen2.5基盤で評価されるが、一部のグラフ検索型方式はGPT-4o-miniを用いている。従って全方式が同じ生成モデルという条件ではなく、比較表では基盤モデルの違いを必ず区別する。

## 評価結果

### 1. 5質問応答集合の平均性能

| 基盤・方式 | 平均EM | 平均F1 | 備考 |
|---|---:|---:|---|
| Qwen2.5-3B・通常RAG | 21.6 | 32.0 | 単発文書検索 |
| Qwen2.5-3B・Search-R1 | 40.4 | 49.3 | 複数ラウンド文書検索 |
| **Qwen2.5-3B・RouteRAG** | **47.0** | **55.7** | 文書・グラフ・混合を選択 |
| Qwen2.5-7B・Search-R1 | 48.6 | 56.8 | 複数ラウンド文書検索 |
| **Qwen2.5-7B・RouteRAG** | **51.9** | **60.6** | 文書・グラフ・混合を選択 |
| GPT-4o-mini・HippoRAG 2 | 47.4 | 61.2 | 基盤モデルが異なる参考値 |

原著表1の同じQwen基盤の比較では、RouteRAG-3BはSearch-R1より平均F1が6.4ポイント高く、7Bでは3.8ポイント高い。7BのHotpotQAはSearch-R1のF1 62.0に対してRouteRAGが72.5、2Wikiは58.9に対して64.6、MuSiQueは40.8に対して49.3であり、関係の連鎖を要する集合で利点が大きい。一方、単純なNatural QuestionsではSearch-R1-7BのF1 65.3に対してRouteRAG-7Bは60.4で、全ての集合で優れるわけではない。

GPT-4o-miniを使ったHippoRAG 2の平均F1は61.2で、RouteRAG-7Bの60.6に近いが、異なる基盤モデル・検索構成での比較である。小型モデルが強い外部モデルに近づいたことは参考になるものの、同一ハードウェア・同一推論費用での優劣を示すものではない。

### 2. 二段学習と検索方式の構成要素除去

| Qwen2.5-3Bの構成 | 平均EM | 平均F1 |
|---|---:|---:|
| 強化学習なし | 24.0 | 36.2 |
| 第1段階だけ学習 | 41.1 | 50.2 |
| **二段学習のRouteRAG** | **47.0** | **55.7** |
| 文書検索だけ許可 | 45.3 | 53.6 |
| グラフ検索だけ許可 | 46.7 | 55.6 |
| 混合検索だけ許可 | 45.5 | 54.0 |

原著表2では、正答報酬の第1段階だけでF1は36.2から50.2へ改善し、効率報酬を追加した第2段階でさらに55.7へ上がる。検索方式を一種類に固定すると平均F1は53.6～55.6であり、状況に応じて切り替える完全版が最も高い。ただしグラフ検索だけでも55.6と僅差であり、混合方式の切替が全体の改善を一手に説明するわけではない。主な性能改善には、検索と推論を共同学習する効果も含まれる。

### 3. 効率報酬と検索ラウンド数

| 構成 | 平均検索ラウンド数 | 平均F1 |
|---|---:|---:|
| RouteRAG-3B・効率報酬なし | 2.51 | 55.2 |
| **RouteRAG-3B・効率報酬あり** | **2.43** | **55.7** |
| RouteRAG-7B・効率報酬なし | 2.70 | 59.5 |
| **RouteRAG-7B・効率報酬あり** | **2.25** | **60.6** |

原著の効率報酬除去実験では、3Bの検索ラウンド数は約3.3%、7Bでは約16.7%減少する。7Bの原著表には効率報酬なしの2.70を「約20%多い」と表記しているが、これは2.25を分母にした増加率である。削減率として述べる場合は2.70を分母にして約16.7%となるため、分母を明示する必要がある。検索ラウンド数の削減とF1の改善が同時に観測されることは、正答軌跡にだけ効率報酬を与える設計の有効性を支持する。

ただし、この表は検索回数と回答F1の比較であり、外部検索の壁時計時間、モデル生成時間、検索結果の構築費用を合算した要求全体の遅延を直接示すものではない。グラフ検索1回と文書検索1回の費用は異なるため、検索回数だけで総費用の改善率を算出してはならない。

## 既存研究との差

単発の文書検索型RAGは検索した証拠が不足しても推論途中で補いにくい。複数ラウンド文書検索のSearch-R1は検索のタイミングを学習できるが、検索対象が文書に限られる。グラフ検索型のHippoRAG 2は関係をたどれるが、いつグラフ検索を使うかを言語モデルが推論途中に決める構成ではない。RouteRAGは文書・グラフ・混合の三種類を検索標識で選び、取得した証拠を次の推論へ戻すため、質問の進行に合わせて検索方式を変えられる。

また、正答率だけの強化学習は正解のために何度でも検索する方策を許容する。RouteRAGは正答能力を先に学習し、次に正答した軌跡だけの検索時間を相対評価する。これにより、誤答を増やして検索回数だけを減らす方向を避ける。比較の中心は単なる検索器の精度ではなく、検索器をいつ、どの方式で、何回呼ぶかという生成方策全体の学習である。

## 限界・実装上の注意

第一に、著者自身が、強化学習と評価の対象を3B・7Bモデルに限定したことを限界として挙げている。より大きなモデルでは、外部検索が必要な割合、検索用部分質問の生成能力、推論トークンの費用が異なり、同じ報酬設計が最適とは限らない。検索器の選択効果をモデル規模から独立に一般化することはできない。

第二に、グラフ検索はHippoRAG 2の構築・探索方式に依存する。別の知識グラフ、異なるグラフ密度、関係の更新頻度、グラフ構築費用を含めた条件では評価されていない。グラフを用意するための前処理と保守費用が大きい場合、推論時の検索回数削減だけでは運用費用の改善を保証しない。

第三に、文書検索型の比較とグラフ検索型の比較では生成モデルが異なる部分がある。GPT-4o-miniによるHippoRAG 2のF1をQwen2.5-7BのRouteRAGと比較しても、同じモデル能力・同じ推論費用での比較ではない。モデル生成と検索を含む端から端までの実測遅延、GPU使用率、並列要求処理能力は追加評価が必要である。

第四に、学習質問はHotpotQAから10,000件で、特に多段推論に強く適合する可能性がある。Natural Questionsのような単純な質問では一部の比較方式が優れる。外部検索結果の品質が低い、グラフが古い、検索器が誤った節点へ誘導する場合には、方策が適切な検索モードを選んでも正しい回答を得られない。適用時は検索器の品質とデータ更新運用も別途検証すべきである。
