# LM-Infinite: Zero-Shot Extreme Length Generalization for Large Language Models

## 書誌情報
- 著者: Chi Han, Qifan Wang, Hao Peng, Wenhan Xiong, Yu Chen, Heng Ji, Sinong Wang
- canonical identity: `arXiv:2308.16137`
- 公開: 2023-08-30、NAACL 2024 Outstanding Paper
- 一次資料: https://arxiv.org/abs/2308.16137

## 概要

LM-Infiniteは、4K前後までしか学習していないTransformerを、そのまま数万・数百万tokenへ伸ばしたときに崩れる理由を「位置表現だけ」の問題として扱わない。論文は、未見のtoken間距離、学習時より多いattention対象数、系列冒頭tokenが持つ特殊な表現という3要因を分離し、それぞれを推論時のattention変更だけで抑える。

方式の中心はΛ字型attention maskである。各tokenは系列冒頭の少数tokenと、学習時最大長に相当する直近windowだけを見る。これでattention対象数を上限化しつつ、通常のsliding windowが捨てる冒頭表現を保持する。さらに相対位置距離を学習時最大長でclipするdistance ceilingを入れ、RoPEやALiBiが未見の巨大距離へ外挿することを防ぐ。

この設計は長さ外挿の品質だけでなく、各decode stepで全履歴を見る必要をなくすため計算・memoryも削減する。LLaMA-7B、Llama-2-7B、MPT-7B、GPT-J-6Bで評価し、2K/4K事前学習モデルを最大200M tokenまで動作させ、元モデル比でdecode 2.7倍高速化、GPU memory 7.5倍削減を報告する。

## 問題設定

相対位置符号化を使えば絶対positionの未見値を避けられるが、系列長を伸ばすだけでは3つのdistribution shiftが残る。第1に、学習時より長い相対距離でattention logitが異常化する。論文は相対位置attentionで未見距離を区別し続けるにはlogitが発散するという理論的性質を示し、Llama-2でも4K超で最大logitが増えることを観察する。

第2に、logitをboundedにしてもattention対象token数が無制限に増えるとentropyが学習範囲を超えて増える。単純なdistance clippingだけではこの問題を解けない。第3に、sliding windowで対象数を制限すると、系列冒頭のtokenを捨ててしまう。冒頭tokenは明示的な絶対position embeddingがなくてもhidden-state空間の特殊領域を占めるため、これを失うと後段layerが学習時に見たattention output分布から外れる。

したがって必要なのは「距離をboundedにする」「attention対象数をboundedにする」「冒頭tokenは残す」の3条件を同時に満たす推論時attentionである。

## 手法

### 1. Λ字型attention mask

各queryは、最初の `n_starting` tokenと、直近 `L_pretrain` tokenへattentionする。`L_pretrain` は事前学習時の最大系列長であり、中間の大部分は通常は見ない。実験では `n_starting` を5〜100程度にしても安定し、0にして冒頭spanを消すと性能が大きく悪化する。

これにより各stepのattention対象数は系列全長ではなく概ね `n_starting + L_pretrain` に固定される。長さが増えてもattention entropyを学習時と近い範囲へ保ち、同時に冒頭tokenの特殊なvalue表現を残す。

### 2. Distance Ceiling

冒頭tokenと現在tokenの実距離が学習時最大長を超えても、attention計算へ入れる有効距離を `min(d, L_pretrain)` とする。RoPEでは冒頭spanのkeyを未回転にし、query側を固定距離 `L_pretrain` として回転させる。ALiBiでは距離biasを対応する下限でclipする。

この処理は「未知の巨大距離」そのものをモデルへ見せない。Λ maskだけでは冒頭tokenまでの距離は系列長とともに増えるため、distance ceilingと組み合わせて初めて3要因すべてを抑えられる。

### 3. 中間top-k tokenの選択的再導入

Passkey RetrievalやQasperのように中間情報が必要なtaskでは、上位layerの各headで中間tokenからattention logitの大きいtop-kを追加できる。論文ではheld-out Passkeyで `k=5`、開始layer `h=5` を選び、他taskにも同じ値を使う。

通常のlanguage modelingやgenerationではこの中間top-kを入れなくても品質を保てるため、効率を優先する場合はΛ mask＋distance ceilingだけでよい。下流taskで必要なときだけ検索的な中間アクセスを追加する設計になっている。

### 4. 既存LLMへの推論時差し替え

パラメータ更新は行わず、各Transformer layerのattention関数だけを置き換える。RoPE/ALiBiのような相対位置方式へ適用でき、長文脈fine-tuning用の大規模学習データや追加training costを要求しない。

| 項目 | 条件 |
|---|---|
| モデル | LLaMA-7B、Llama-2-7B、MPT-7B、GPT-J-6B |
| 学習時長 | LLaMA/GPT-J 2K、Llama-2/MPT 4K |
| 位置表現 | RoPE、ALiBi |
| language modeling | ArXiv、OpenWebText2 |
| 長文脈task | Passkey Retrieval、Qasper |

## 主要結果

| 条件 | 結果 | 解釈 |
|---|---:|---|
| 最大長外挿 | 最大200M token | 2K/4K学習モデルを追加学習なしで極端長へ適用 |
| Passkey Retrieval | vanilla/truncation比 +37.2% | 中間top-k再導入が必要情報検索に寄与 |
| Qasper | +1.2% | 長文脈QAでもzero-shot改善 |
| decode速度 | 元モデル比2.7× | attention対象数を系列全長から固定spanへ制限 |
| GPU memory | 元モデル比7.5×削減 | 全履歴KV/attentionを保持・走査しない効果 |
| ablation: `n_starting=0` | 大幅悪化 | sliding-windowだけでは冒頭tokenの特殊表現を失う |

ArXiv/OpenWebText2ではvanilla LLaMA/MPT/GPT-J/Llama-2が学習長を超えるとperplexityが数桁悪化またはNaNになる条件があるのに対し、LM-Infiniteは長さを伸ばしても有限で安定したperplexityを維持する。長文脈専用fine-tuning済みモデルに近い傾向を、追加trainingなしで得ることが主眼である。

## 既存研究との差

単純なsliding-window attentionは計算量を抑えるが冒頭tokenを捨てる。位置外挿法は距離問題を扱ってもattention対象数の増大を必ずしも抑えない。LM-Infiniteは、長さ外挿失敗の3原因を対応付けて、冒頭span、直近window、distance ceilingを一体化した点が異なる。

長文脈fine-tuningやretrieval memoryと比べると、既存weightを変更しないため導入コストが低い。一方で中間contextを通常は捨てるため、全文の任意位置を精密に参照するtaskではtop-k再導入などの補助が必要になる。

## 限界

Λ maskは中間tokenの大半をattentionから外すため、長文全体の密な相互依存を必要とするtaskに対して「200M tokenを完全に理解できる」ことを意味しない。200Mは主に安定したlanguage modeling外挿の実証であり、200M token全域を使う複雑推論の精度保証ではない。

top-k中間token選択は追加attention logit計算を必要とし、完全な固定windowより効率が下がる。さらに、適用対象は相対位置符号化を持つTransformerを中心にしており、異なるattention architectureへそのまま一般化できるとは限らない。

2.7倍速度・7.5倍memory削減も元のfull-attentionモデルとの比較であり、FlashAttentionや最新のpaged KV管理を含む現在のserving stackに対する倍率ではない。
