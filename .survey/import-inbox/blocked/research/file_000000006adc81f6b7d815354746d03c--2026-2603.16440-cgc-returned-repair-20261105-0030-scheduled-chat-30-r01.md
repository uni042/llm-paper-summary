## 概要

Capability-Guided Compression（CGC）は、圧縮前の重みの大きさや活性値の大きさだけでなく、各注意ヘッドがどのような特徴群を表現しているかを圧縮予算の決定に利用しようとする研究である。疎な自己符号化器（SAE）を各ヘッドの出力活性に学習し、活性化する特徴の種類数、特徴活性の分布エントロピー、異なる入力間の特徴集合の一致度から「能力密度」を構成する。高密度のヘッドを多く残し、低密度のヘッドにより強い圧縮を割り当てるという設計である。

実験上の主要な結論は成功ではなく限定的な否定結果である。GPT-2 Mediumの384ヘッドについて能力密度とWanda重要度のSpearman相関は−0.054と低いが、これは能力保護への因果的有効性を証明しない。個別ヘッド切除によるPPL変化との相関もPearson −0.066（p=0.20）、Spearman −0.077（p=0.13）で有意でない。50%の重み保持条件では均等枝刈りPPL 27.57に対しCGC-Lは27.87で悪化した。したがって、現段階では新しい配分指標の提案と小規模な検証として読むべきで、推論性能の改善が確立した圧縮手法として扱ってはならない。

## 問題設定と既存方式との差

Wandaは重み絶対値と入力活性のノルムを掛け合わせ、SparseGPTは重みの再構成誤差を基礎に枝刈りを選ぶ。これらの指標は、どのヘッドが推論、検索、構文処理などの機能を担うかを直接ラベル付けしない。著者は、この「能力を見ない圧縮」が、パープレキシティを維持しても一部能力を失うことや、圧縮率を上げた際の急激な性能低下の原因になり得ると問題提起する。ただし本論文でこれらの因果関係が実験的に証明されたわけではない。

本研究はWandaの重要度を置き換える単純な再重み付けではない。SAEで特徴空間を作り、圧縮率の許容範囲に別の制約を課す設計を提示する。EvoPressのような圧縮設定の探索器へ制約を加えるCGC-Fと、密度に比例する初期配分CGC-Lを区別している。また、既存の圧縮の相転移回避枠組みが圧縮種類間の全体配分を決めた後、各種類の内部で部品ごとに予算を配分する層として組み合わせる構想を示す。

## 手法

### 1. ヘッド別SAEから特徴活性行列を作る

対象モデルの各注意ヘッドを部品cとして扱う。較正用トークン列を通して各ヘッドの出力ベクトルを集め、部品ごとにSAEを学習する。SAEは高次元の辞書特徴へ符号化し、少数の特徴だけを活性化させて元の出力を復元する。実験では各ヘッドの入力次元64に対し辞書サイズ512、トークン当たり活性特徴数k=25のTopK構成を用いた。これにより各トークン・各ヘッドの特徴活性行列を得る。ここにはヘッド数に比例したSAEの学習と較正データ処理の追加コストが発生し、圧縮そのものを高速化する機構ではない。

### 2. 能力密度の3要素を計算する

第一の特徴幅は、較正トークンの一定割合以上で活性化した辞書特徴の個数であり、辞書サイズで正規化する。第二の特徴多様性は、特徴の活性頻度分布のシャノンエントロピーを辞書サイズの対数で正規化する。第三の入力間一貫性は、異なる意味カテゴリから選んだ入力対について活性特徴集合のJaccard類似度を平均したものである。3値を指数各1/3の加重幾何平均で統合し、部品ごとの能力密度δ(c)とする。幾何平均なので、一要素が小さいと全体の密度も下がる。

ただし、特徴幅やエントロピーはSAEの辞書品質、較正コーパス、閾値に依存する。入力間の類似度が高いことが、実際に保存すべき推論能力の高さを意味するかは独立の検証が必要である。「能力密度」という名称だけで機能の因果的重要度が測定されたと解釈してはならない。

### 3. 圧縮予算の配分と探索

CGC-Lでは各部品の密度を全体平均で割った相対重みを求め、全体の保持率を満たす範囲で高密度部品の保持率を上げる。低密度部品には相対的に低い保持率を割り当てる。密度から保持上限を与える変換関数には平方根型の凹関数を用い、中程度の密度にも保護を与える。原稿の式では「保持率の上限」と「高密度部品を保護する」という説明の整合が直観的に明確ではなく、制約方向の実装確認が必要である。数式だけから保証を強く読まないことが重要である。

CGC-FはEvoPress型の進化的探索に密度由来の許容範囲を課し、制約を超える突然変異を棄却する構想である。さらに全体の低ランク化、枝刈り、量子化の配分を相転移回避方式で決め、内部の部品配分へCGCを適用するPACG構想を述べる。しかし本稿の実験表はCGC-Lの注意ヘッド出力射影の枝刈りを中心としており、CGC-Fの大規模実験、複数圧縮法の統合実験、KVキャッシュ圧縮や推論サービング性能の測定は示されない。

### 4. 理論的主張の射程

著者は、能力密度が高い部品ほど活性特徴が広い方向に分布し、均等な枝刈りで特徴が失われやすいと論じる。また、密度に応じて保持率を配分すると特徴破壊が減るという定理・系を提示する。しかし議論にはSAE特徴のエントロピーとデコーダ方向の幾何学的分布の結び付き、損失関数の凸凹性などの仮定が入る。これらは実際のモデルで一般に成立することが確認されていない。著者自身も自己修復現象によって単純な特徴破壊と能力喪失の対応が弱まると述べる。理論保証を現実のモデルの性能保証と同一視しない。

## 評価条件

| 項目 | 論文の設定 |
|---|---|
| モデル | GPT-2 Medium、355Mパラメータ、24層×16注意ヘッド=384ヘッド |
| 実行環境 | NVIDIA T4 GPU 1枚で実行可能な設定として記載 |
| 較正・SAE学習 | WikiText-103-raw-v1学習split、128系列×512トークン=65,536トークン |
| SAE | ヘッドごと384個、入力64、辞書512、TopK k=25、5 epoch、Adam、学習率2×10^-4 |
| PPL評価 | WikiText-103-raw-v1 test、非重複32系列×512トークン、paddingなし |
| 圧縮対象 | 注意ヘッド出力射影の重みを枝刈り、全体保持率50% |
| 比較 | Dense、Uniform、CGC-L、Inverted（密度に逆行する配分） |
| 主要指標 | WikiText-103 perplexity、Wandaとの順位相関、ヘッド単独切除のPPL差 |

この評価は小型モデルの特定層の枝刈りであり、モデル全体の重みを50%に削減したという意味ではない。また、トークン生成速度、GPUメモリ、エネルギー、サービス遅延を測った実験ではない。PPLは低いほど良い。比較表のPPLの小数丸めにより、表示上の差と表中ΔPPLには0.01程度のずれがある。

## 主要結果と負の結果

| 条件・指標 | 比較対象 | 提案方式・観測値 | 解釈 |
|---|---:|---:|---|
| 非圧縮PPL | Dense 26.68 | — | 評価の基準 |
| 50%保持時PPL | Uniform 27.57 | CGC-L 27.87 | CGC-Lが0.30悪化 |
| 50%保持時PPL | Uniform 27.57 | Inverted 27.86 | 逆配分もほぼ同じ程度に悪化 |
| 密度とWanda重要度 | 384ヘッド | Spearman ρ = −0.054 | 順位相関はほぼゼロ。能力の有効性は未証明 |
| 密度と単独ヘッド切除PPL影響 | 384ヘッド | Pearson r = −0.066, p=0.20 | 有意な予測力は確認できない |
| 同上 | 384ヘッド | Spearman ρ = −0.077, p=0.13 | 同じく有意ではない |
| 密度の分布 | 384ヘッド | 平均0.7465、最小0.6289、最大0.7977 | 配分に使える密度差が小さい |

最も重要な結果は、CGC-LがUniformより良くなかったことである。しかも密度の高いヘッドを優遇する配分と、その逆を行う配分がほぼ同じPPLになっており、少なくともこの設定では密度信号の実用的な方向性が示されていない。Wandaとの相関が低いことは既存指標と異なる情報を含む可能性を示すが、統計的独立性そのものの厳密な証明ではないし、予測したい能力低下に有用な情報であることも保証しない。

著者はこの否定結果の原因として、GPT-2 Mediumのヘッド間で密度が均質であること、PPLが推論能力の損失に鈍感であること、SAEをわずか65,536トークン・5 epochで学習したため特徴分解が粗い可能性を挙げる。いずれも妥当な仮説ではあるが、モデルを大型化してSAE学習量を増やした対照実験は本稿にない。したがって「大型モデルなら改善する」は未検証の将来予測である。

## 限界・再現性・適用判断

第一に、論文が提案する機能的な能力密度と、評価に使ったWikiTextのPPLの間には目的指標の不一致がある。GSM8K、ARC-Challenge、MMLU等の能力別評価がなく、圧縮による推論能力の保持は直接測定されていない。第二に、注意ヘッド出力射影だけの枝刈りであり、FFN、重み量子化、低ランク分解、複数手法の同時適用に一般化できない。第三に、SAEの事前学習・較正コストと圧縮後の性能改善との費用対効果が示されていない。第四に、能力密度と切除感度の相関が負で有意でないため、提案理論を実証したと扱うべきではない。

論文中の図の表形式抽出には繰り返し値が多く、ヒートマップの各セルを数値表として二次利用するのは避ける。実験表に明記されたPPL・相関・設定を主たる証拠として採用した。また、保持率と圧縮率の定義が節によって読み替えを要するため、実装する場合は制約の向きと合計サイズ条件を改めて検証すべきである。

本研究はLLM推論に向けたオフライン圧縮予算設計としてサーベイ対象に含める価値がある。一方、現状は実効性能改善が示された方式ではなく、否定結果を伴う研究仮説として位置付けるのが適切である。今後は大規模モデルの能力別ベンチマーク、十分に学習したSAE、同一圧縮予算・同一評価コストでのWanda/OWL/EvoPress比較、SAE学習コストと推論メモリ節約の償却分析が必要となる。
