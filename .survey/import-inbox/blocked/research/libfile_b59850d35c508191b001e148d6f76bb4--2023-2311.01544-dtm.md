# Divergent Token Metrics

## 書誌
Björn Deiseroth, Max Meuer, Nikolas Gritsch, Constantin Eichenberg, Patrick Schramowski, Matthias Aßenmacher, Kristian Kersting。正規識別子 `arXiv:2311.01544`。

## 概要
LLM圧縮では困惑度（perplexity; PPL）やタスクaccuracyがよく使われるが、componentを一つずつ疎化・量子化した際に「生成挙動がどこから変わったか」を細かく測るには粗い。Divergent Token Metrics（DTM）は元モデルと圧縮モデルのtoken予測分布の分岐を直接観測し、component単位の劣化感度を順位付けする。

代表指標First Divergent Token Metric（FDTM）は、圧縮モデルの生成が基準モデルから最初に分岐する位置を利用する。これをattention/MLP componentの個別probeに使い、壊れにくいcomponentへより強いpruningや低精度化を割り当てる。

Llama-2-13Bの75%平均sparsity構成では、160 attention componentのうち40個が90%以上疎化され、15個は完全除去される。量子化ではLlama-2-7Bのcomponentの80%、150 componentを単純なAbsMax int8へ変換し、WikiText2 PPL 5.489付近を保ちながら全面的LLM.int8変換より良いモデル品質を報告する。

## 問題設定
一様pruningは全層・全行列へ同じsparsityを課すが、attentionのQ/K/V/OやMLP、層位置によって冗長性は異なる。量子化も同様で、outlierの多いcomponentと少ないcomponentを一律int8へ落とすと、一部の敏感な行列が全体品質を決める。

PPLはモデル全体の平均的な尤度変化を捉えるが、生成がどの時点で別軌道へ入るかを直接表さない。DTMはcomponentを一時的に圧縮したモデルと基準モデルを同じpromptで比較し、その生成差をprobe信号にする。

## 手法
### First Divergent Token Metric
基準モデルと圧縮候補モデルの生成を比較し、最初に異なるtokenを選ぶまでの挙動から劣化を測る。早い分岐を起こすcomponentほど圧縮に敏感、遅い分岐ほど圧縮余地が大きいとみなす。

### componentwise probingとbalanced pruning
各attention/MLP componentを個別にprobeし、FDTに基づいてsparsity配分を更新する。全componentへ同じ比率を課すのではなく、感度が低いcomponentへ高いsparsityを割り当て、全体平均のsparsity目標を満たす。結果として後半層は前半層より削りやすく、value matrixは比較的残される傾向が観測される。

### 選択的量子化
各componentをnaive AbsMax int8へ変換したときのFDTを測り、劣化の小さいcomponentから低精度化する。FDT順位はoutlier発生数とも相関し、特殊なoutlier処理を全行列へ入れずに安全な大部分だけを単純int8へ落とす方針を導く。

## 評価条件
|項目|内容|
|---|---|
|モデル|Llama-2 family、主に13B pruning / 7B quantization|
|pruning比較|uniform magnitude pruning等|
|量子化|naive AbsMax int8、LLM.int8比較|
|品質|WikiText2 PPL、DTM/FDTM、下流挙動|
|粒度|attention Q/K/V/O、MLP等component単位|

## 主要結果
Llama-2-13Bを平均75% sparseへ収束させた構成では、attention 160 component中40個が90%以上sparse、15個が完全に削除された。第一層・最終層付近には敏感なoutlierがあり、後半層の方が一般にprunableだった。attentionだけを強く削るとprompt extraction能力が悪化し、MLPだけを削るとworld-knowledge QAへの影響が大きいという機能差も観測する。

量子化では150 component、約80%をnaive AbsMax int8へ変換してもWikiText2 PPLはFDT選択で5.489、DPPL選択で5.490付近。FDT選択は平均FDT自体をほぼ50%改善し、全componentをLLM.int8へ変換するよりモデル性能が良いと報告する。

## 既存研究との差
SparseGPT等は重み再構成誤差やHessian近似からpruningを決め、LLM.int8系はoutlier channelを高精度に残す。本研究は圧縮対象componentが実際のtoken生成軌道へ与える影響を直接probeし、その指標をpruningとquantizationの両方へ共通利用する。

## 限界
componentwise probeには候補ごとの生成評価が必要で、圧縮設計前処理の計算量が増える。論文自身もBERTやMoEなど別architectureへの一般化、probe dataset依存性を今後の課題とする。また高sparsityが理論上可能でも、実際の推論高速化には90%超の疎行列を効率よく処理する専用kernelが必要であり、sparsity率そのものをend-to-end速度と同一視できない。
