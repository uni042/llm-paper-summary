# Elastic Attention：課題に応じた注意計算の動的疎化

## 概要

長文脈の大規模言語モデル（Large Language Model; LLM）では、すべての入力トークンへ注意を向ける全注意（Full Attention; FA）が計算量・メモリ帯域のボトルネックとなる。疎注意（Sparse Attention; SA）を用いると参照対象を減らせるが、質問応答のように離れた箇所の正確な証拠を取り出す課題と、文書要約のように大局的な内容を扱う課題では、許容できる疎化の程度が異なる。既存の混合注意方式は、全注意を担当するヘッドの割合をモデルごとに固定することが多く、入力ごとの要求に追従できない。

Elastic Attentionは、各層の注意ヘッドを全注意または疎注意へ振り分ける小規模な注意ルータ（Attention Router）を追加する。基盤モデルの重みは固定し、入力から推定した課題の特徴に応じて、実行時の疎注意ヘッド比率を変える。学習では二値割当と勾配計算を両立させ、実行では融合注意カーネルを用いて異なる種類のヘッドを同じ起動で処理する。著者はQwen3-4B、Qwen3-8B、Llama-3.1-8B-Instructの3モデルを用い、長文脈の実課題、合成検索、長文推論を評価した。

代表例として、Qwen3-4Bの長文脈評価LongBench-Eの平均点は全注意48.45、Elastic Attentionの全注意・ストリーミング疎注意構成48.08である。Llama-3.1-8B-Instructでは全注意53.28に対し同構成53.35である。一方、モデル・疎注意方式・課題によって精度は悪化する。これらは精度と疎化比率の対応を示す数値であり、端から端までの生成速度が一律に何倍になるかを示すものではない。

## 問題設定と着想

混合注意では、重要な情報を遠方から検索するヘッドを全注意として残し、それ以外のヘッドをストリーミング注意やブロック疎注意へ置き換える。ところが、どの程度まで置き換えてよいかは入力の性質に依存する。論文の予備実験では、Llama-3.1-8B-Instructの注意ヘッドを検索能力に基づいて順次疎化すると、単一文書質問応答の全注意に対する相対性能は疎ヘッド比率0.2で71.32%、0.7で56.08%まで低下する。対照的に要約では同条件で98.00%、92.52%、コード課題では98.49%、97.73%を保った。したがって、すべての課題へ固定比率を適用すると、質問応答には疎化が強すぎ、要約には計算資源を残しすぎる可能性がある。

この差を扱うため、著者は課題を「疎化に敏感」と「疎化に頑健」の大まかな二群として捉え、個別課題の正確なラベルを推論時に与えなくても、入力表現から適切な全注意ヘッド数を決めることを目指す。最適な疎化割合そのものを教師ラベルとして学習するのではなく、言語モデルの損失と疎化目標の緩い制約を併用する点が設計の中心である。

## 手法

### 1. 注意ヘッドの計算モードと疎化指標

各層の各キー・値ヘッドに対して、ルータは全注意か疎注意かの二値決定を出す。全注意では全キー・値列へ注意を計算し、疎注意では指定したパターンに従う一部のキー・値のみを参照する。ヘッドの出力を結合する基本構造は変えない。論文は疎注意としてストリーミング疎注意（Streaming Sparse Attention; SSA）とXAttention（XA）を扱い、全注意・SSAの混合をFA-SSA、全注意・XAの混合をFA-XAと記す。

モデル疎化比率（Model Sparsity Ratio; Ω_MSR）は、全層のヘッドのうち疎注意へ振り分けられた割合である。実効疎化比率（Effective Sparsity Ratio; Ω_ESR）は各ヘッドが実際に参照しなかったトークンの割合も考慮する。両者を混同してはならない。例えば疎注意ヘッドが7割でも、残る3割は全トークンを参照し、疎注意ヘッドの参照率も方式によって異なるため、計算量やキャッシュ容量が単純に7割減るとは限らない。

### 2. 入力の境界表現を使う二段ルータ

注意ルータの入力は各層のキー側の隠れ状態である。長文全体を平均すると課題識別に有効な情報が薄まるため、実装では入力系列の先頭100トークンと末尾100トークンのみを集約する境界プーリング（Boundary Pooling）を使う。先頭には指示、末尾には質問などが置かれやすいという観察に基づくが、これはすべての入力形式で保証される性質ではない。

集約した各ヘッドの表現を課題用多層パーセプトロン（Task MLP）へ通し、続くルーティング用多層パーセプトロン（Router MLP）がヘッドごとの二つの計算モードの対数値を出す。最後に二値の割当を選び、各ヘッドが全注意か疎注意かを決定する。ルータの追加パラメータはヘッド次元128の場合、1層当たり約27万と報告される。基盤モデルの重みや注意出力の意味を変更する代わりに、ヘッドが参照する情報量を変える構成である。

### 3. 離散割当を学習する最適化

実行時には硬い二値割当が必要だが、単純な最大値選択では勾配が伝播しない。学習ではガンベル・ソフトマックス（Gumbel-Softmax）により割当確率を連続的に近似し、温度を徐々に下げて二値に近づける。さらに直通推定器（Straight-Through Estimator; STE）を用い、順伝播では二値決定を使いながら逆伝播では連続確率から勾配を伝える。このため、学習中と推論時の計算モードの差を抑えながらルータを更新できる。

目的関数は通常の次トークン予測の交差エントロピーと、Ω_MSRが課題群ごとの目標値から外れる量に基づく正則化を組み合わせる。疎化目標は厳密な等式ではなく緩い制約として与え、正則化項のラグランジュ乗数も学習する。論文の主実験では疎化に頑健な課題群の目標を1.0、敏感な課題群の目標を0.7とする。ただし最終的なΩ_MSRが目標と一致するとは限らない。実測比率は入力の特徴と学習したルータの判断により変わる。

### 4. 異種ヘッドを同時実行する融合カーネル

全注意ヘッドと疎注意ヘッドを別々の高水準演算で順番に実行すると、ルータが計算量を削減してもカーネル起動やヘッドの分割処理が実効速度を損なう。そこで著者は系列位置・ヘッド・バッチを軸とする三次元の実行格子を持つ融合注意カーネルを実装し、割当の異なるヘッドを一回の順伝播で処理する。論文の図4は高水準演算を逐次適用する構成に対するプリフィル時間短縮を示す。

このカーネルの議論は単一GPU上の実装である。ヘッドごとに別GPUへ処理を振り分ける分散並列、通信の重なり、ネットワーク上のキー・値転送は評価対象ではない。また、疎化の割当だけで自動的にメモリ割当やキャッシュ圧縮まで実現するわけではなく、疎注意パターンとカーネルの対応が必要である。

### 評価結果と解釈

#### 1. 実課題の精度と疎化割合

次の表はLongBench-Eの6課題群平均を、各モデル・方式ごとに比較したものである。Ω_MSRは疎注意へ切り替えたヘッドの割合であり、正答率でもトークン削減率でもない。

| 基盤モデル | 方式 | LongBench-E平均 |
|---|---|---:|
| Qwen3-4B | 全注意 | 48.45 |
| Qwen3-4B | DuoAttention | 46.95 |
| Qwen3-4B | Elastic FA-SSA | 48.08 |
| Qwen3-8B | 全注意 | 52.16 |
| Qwen3-8B | PruLong | 51.34 |
| Qwen3-8B | Elastic FA-SSA | 51.51 |
| Llama-3.1-8B-Instruct | 全注意 | 53.28 |
| Llama-3.1-8B-Instruct | Elastic FA-SSA | 53.35 |

Qwen3-4BのFA-SSAは全注意との差が-0.37点で、DuoAttentionより1.13点高い。Llama-3.1-8B-InstructのFA-SSAは全注意を0.07点上回る。一方、Qwen3-8BのFA-SSAは51.51点で全注意52.16点を下回る。著者自身も一部の要約・コード課題で比較方式より低い場合があると述べる。平均点だけから全課題で品質を維持すると解釈してはならない。疎注意ヘッド比率は課題群によって異なり、著者公開の図表説明ではコード課題が概ね0.78～0.82、質問応答が0.63～0.68とされる。

#### 2. 長さ外挿と長文推論

RULERでは学習時の最大64Kを超える256Kまで入力長を伸ばす。著者は長い入力ほどルータがより高い疎注意ヘッド比率を選び、実行速度の優位性が増すと報告する。一方、モデルごとの性能は異なり、8B規模では64Kを超える条件でFA-XAの有効性が高いと説明する。256Kで一部の比較方式がメモリ不足になったことも報告されるが、全手法が同じ条件で実行できたわけではない点に注意が必要である。

RULERとLongBench-V2の例を比較すると、Qwen3-8BのRULER平均は全注意75.74、Elastic FA-SSA 71.74、FA-XA 73.87であり、いずれも全注意には及ばない。他方、LongBench-V2では全注意31.97に対しFA-SSA 33.41、FA-XA 30.74で、疎注意の種類により逆転する。Llama-3.1-8B-InstructのRULER平均は全注意83.47に対しFA-SSA 72.85、FA-XA 81.82であり、長距離検索では疎化の品質代償が残る。論文の「良好な性能」は、比較する疎注意基準に対する優位と、全注意からの低下が限定的な条件を区別して読む必要がある。

#### 3. ルータの構成要素除去・感度

課題用多層パーセプトロンの前後で異なる課題の隠れ表現の余弦類似度を測ると、通過後は課題間の類似度が下がる。これは後段のルータが課題を区別する手掛かりを得ていることを示すが、その観測だけで最終精度向上の因果を確定できるわけではない。中間層の幅をヘッド次元の2倍、4倍、6倍、8倍にした比較では、LongBench・RULER・LongBench-V2の単純平均はそれぞれ45.22、45.92、45.45、46.40。8倍が最高だが、追加パラメータとの交換条件から4倍を標準設定とした。

疎化に敏感な課題の目標値を0.7から0.4へ下げると、全注意の比率が増えて精度が基盤モデルを超える場合もある。しかし、その分だけ疎注意による高速化余地が減る。実際のΩ_MSRは目標値に厳密には一致しないため、学習目標だけで実行時の計算予算を確約することはできない。

全ヘッドを疎注意で実装するXA-SSA構成の追加実験では、Qwen3-4BのLongBench、RULER、LongBench-V2の平均が全注意46.80に対し45.93である。一方、Qwen3-8Bは53.26から49.42、Llama-3.1-8Bは56.48から50.02へ下がる。疎化を極端に進めた際の品質低下はモデル規模に依存し、混合注意の全注意ヘッドを残す価値が確認できる。

## 既存研究との差

DuoAttentionやPruLongのような混合注意方式は、重要な検索ヘッドを識別して全注意に残し、他を疎化することで長文脈推論を軽くする。Elastic Attentionの追加的な貢献は、事前に決めた固定ヘッド集合を入力に応じて変える点と、その判断を小型ルータの学習で実現する点にある。さらに、ルータが決めた混合構成を融合カーネルで実行し、高水準演算を順次呼び出す場合のオーバーヘッドを減らす。

InfLLM-V2など一部の方式は入力長によって全注意と混合注意を切り替えるが、Elastic Attentionは課題の特徴からヘッドごとの割当を決める。単なる入力長閾値の変更ではない。他方、ルータ自体の学習が必要であり、学習不要の単純な固定窓方式より導入費用がかかる。長文脈への適応の柔軟性と、モデルごとのルータ訓練・専用カーネルの保守を引き換えにしている。

## 限界と実運用上の注意

本研究は、基盤モデルの重みを変更せずに注意計算を動的に疎化できることを示すが、すべてのモデル・課題で全注意と同等精度を保証しない。特に質問応答や合成検索では重要な遠方トークンの取りこぼしが性能低下に直結する。Qwen3-8BでのFA-XAの精度低下や、全疎注意構成の8Bモデルでの劣化は、疎化方式・モデル特性の組合せを個別に検証する必要性を示している。

論文の速度測定は単一GPUでの融合注意実装を中心にしたものであり、複数GPUの通信、連続バッチ処理、複数利用者の同時実行、キー・値キャッシュの階層オフロードを組み合わせたサービング全体の性能を測ったものではない。図から数値を正確に読み取れない倍率を推測して記載することも避ける。疎注意ヘッド比率が高いことと、実際のGPU時間・ピークメモリ・トークン当たり生成時間が同率で減ることは別問題である。

また、課題の特徴抽出を先頭・末尾200トークンに依存させる設計は、重要な指示が入力中央に埋め込まれる構成や複雑な複合課題では判別を誤る可能性がある。学習用データは特定の長文質問応答・要約・コード系の組合せであり、別ドメインや異なる疎注意カーネルへそのまま転用した際の効果は追加評価が必要である。
