# Duplex：混合専門家とグループ化注意を演算密度に応じて分担するロジック内メモリ演算装置

## 概要

Duplexは、大規模言語モデルの推論を対象に、通常の高演算密度処理器（xPU）と、広帯域メモリのロジックダイに演算器を設けるメモリ内演算器（Logic-PIM）を同じ装置へ統合する計算機構である。混合専門家モデル（Mixture of Experts; MoE）は選択された専門家だけを計算する一方、連続バッチ処理で多数の要求を混ぜると異なる専門家の重みを頻繁に読み出す。グループ化クエリ注意（Grouped-Query Attention; GQA）も、要求ごとに異なる鍵・値キャッシュを参照するため、計算器よりメモリ帯域が支配的になりやすい。

Duplexは演算数/転送バイト（Op/B）を目安に、行列積などの計算密度が高い処理をxPU、専門家の少量トークン処理や復号時の注意計算をLogic-PIMへ割り当てる。さらに、専門家ごとの担当トークン数と、同じバッチに新規プリフィル要求が混ざるかを見て、両処理器で同時に計算する。H100相当の構成を使うシミュレーションでは、従来GPU基準で処理量が最大2.67倍、平均2.07倍となり、消費エネルギーは最大42.03%、平均28.19%減少した。

**この性能は実チップのベンチマークではない。** 原著はHBM3のタイミングモデルと論理合成を使ったサイクル精密シミュレーションであり、専用Logic-PIMを実装した製品の測定値ではない。GPUが二倍ある比較構成、従来型Bank-PIM、モデルごとの逆転条件も明確に区別する必要がある。

## 問題設定：連続バッチ処理で変わる演算密度

通常の全結合層は多数のトークンを一括処理すると、同じ重みを再利用する大きな行列積になり、演算密度が高くなる。一方MoE層では、各トークンがゲートによって少数の専門家に振り分けられる。連続バッチ処理では、同時要求数が増えると多くの専門家が選択されるが、個々の専門家へ届くトークン数は少ないことがある。専門家重みの読出しが増える一方、重みを再利用できる演算量は十分に増えず、メモリ帯域待ちが支配する。

論文はプリフィル要求を含まない復号専用段と、プリフィルと復号が混在する混合段を区別する。復号専用段では各要求が一つの新トークンを処理し、MoEの専門家ごとの演算密度は低い。混合段では新規要求の長い入力が一度に流れるため、一部の専門家の担当トークン数が増え、同じ専門家層でも高演算密度側へ移る。全段をメモリ内演算器へ固定すると、この混合段の大きな行列積が遅くなる。

注意計算でも、GQAは複数のクエリ頭で鍵・値を共有するため、従来の多頭注意より演算密度が高くなる。原著はGQAの注意演算が概ね4～8 Op/Bに達し、極端に低い演算密度だけを想定するDRAMダイ内PIMでは演算器が不足すると指摘する。GPU側の利用率は、MoEで11%未満、注意で2.06%程度にまで落ちる例を示す。そこで1 Op/B未満だけでなく、およそ1～32 Op/Bの範囲を扱える装置が必要となる。

## 手法

### 1. 同一装置内のxPUとLogic-PIM

DuplexはH100相当の高演算密度用xPUを維持し、HBMの下部にあるロジックダイへ行列積、活性化関数、ソフトマックス用の演算器を追加する。DRAMダイへ多数の演算器を直接置く従来PIMとは異なり、ロジック製造プロセスに近い部分へ計算を集めることで、比較的多い演算を処理する。ロジックダイ側はメモリ読出しを制御し、xPU側は通常のHBM経路で高演算密度処理を続ける。

ロジックダイの演算器は、入力と重みの先頭アドレス、行列寸法などをLogic-PIM制御器から受け取り、HBMから読み出した値で行列積を行う。MoEでは専門家のゲート・上向き投影・下向き投影、注意では行列演算とソフトマックスを処理する。計算結果を外部GPUまで往復させず、メモリ近傍で消費するため、同じ演算数でもHBM外部転送の待ち時間とエネルギーを減らせる。

ただしxPUとLogic-PIMが同じデータバンクへ同時アクセスすると衝突する。Duplexは後述するバンク束とデータ配置を使い、二つの経路が異なる領域を使うようにする。演算器を二種類搭載するだけでなく、重みと鍵・値キャッシュの配置を対応させる点が重要である。

### 2. バンク束・追加TSVによる帯域確保

HBM3の各擬似チャネルには複数のバンク群があり、通常の外部入出力では同時読出しに制約がある。Duplexは一つのランク内の16バンクを8バンクずつの束（bank bundle）に分け、束の複数バンクから並行にデータを読む経路を設ける。DRAMダイとロジックダイを接続するシリコン貫通電極（TSV）を追加し、従来の外部HBM経路と別にLogic-PIM向けの内部経路を確保する。論文はこの構成で通常HBM3比4倍の内部帯域を想定する。

追加TSVは従来のデータ用TSV領域へ密集させるのではなく、電源用TSVの近くに配置し、バンク群からの配線距離とエネルギーを抑える。束単位の読出しにより、Logic-PIMが一つの束へアクセスしている間にxPUが別の束へアクセスできる。ここで得られる4倍は**想定したHBM内部の帯域**であり、アプリケーション全体の処理量が必ず4倍になる意味ではない。

### 3. MoE専門家の共同処理

MoEのゲートが各トークンを選択した後、各専門家へ届くトークン数から処理密度を判断する。少数トークンで重み読出しが支配的な専門家はLogic-PIM、多数トークンで行列積の演算量が増える専門家はxPUへ割り当てる。これにより、同じ層の内部でも二つの演算器が並行して異なる専門家を担当できる。高演算密度の専門家を無理にLogic-PIMへ流すと、演算器数の不足でかえって遅くなるため、専門家単位の振分けが必要である。

Logic-PIM側の専門家重みは複数HBMスタックへ分散する。ゲート投影と上向き投影の重みを列方向に分割し、活性化関数を各スタックで処理した後、下向き投影の部分和を集約する。全専門家の計算が終わった後にxPUが一回の全体和集約（all-reduce）を行うことで、専門家ごとに通信を繰り返す費用を減らす。専門家間で処理量が偏っても、スタック間の作業を均等化する狙いがある。

### 4. プリフィルと復号の注意演算を共同処理

混合段では、新しく入った要求のプリフィルが長いクエリ列を処理し、既存要求の復号は一トークンずつ鍵・値キャッシュを参照する。Duplexは高演算密度のプリフィル側注意計算をxPU、低演算密度の復号側注意計算をLogic-PIMへ振り分ける。別要求間の注意計算には依存関係がないため、同じ段の内部で二つの処理器を並行利用できる。

原著はメモリ空間をバンク束の番号に基づいて四つに分け、専門家重みと鍵・値キャッシュを配置する。復号用キャッシュは三つの領域へ交互に配置し、残りをプリフィルのQ・K・V用に割り当てる。プリフィルで生成したK・Vは次段の復号で必要になるため、注意計算後にxPUがキャッシュ領域へ移動する。これは追加のデータ移動だが、一回だけ行うため原著は費用が小さいとする。

## 評価条件と測定の性格

| 観点 | 一次論文の条件 |
|---|---|

| 基準装置 | NVIDIA H100相当GPU。Duplex側のxPUもH100相当とし、同じ80 GBのHBM3容量を維持 |
| Logic-PIM | 8段積層HBM3、内部帯域は通常HBM比4倍を想定。演算能力21.3 TFLOPS/スタックの構成 |
| モデル | Mixtral 47B、GLaM 143B、Grok1 314B、OPT 66B、Llama3 70B |

| 専門家数 | MixtralとGrok1は8専門家中2個選択、GLaMは64専門家中2個選択 |
| 配置 | Mixtral・OPT・Llama3は4装置/1ノード、GLaMは8装置/1ノード、Grok1は8装置×2ノード |
| 通信モデル | ノード内は双方向900 GB/sのNVLink、8装置超はノード間400 GB/sのInfiniBandを想定 |
| ワークロード | 入出力長をガウス分布から合成、専門家選択は一様分布、連続バッチ処理 |
| 主な入力・出力長 | 256～4096トークン。モデル別にバッチ32～128を比較 |
| 回路・電力 | Verilogの論理合成、7nm予測プロセス、HBM3の時間・電力モデルとSRAMモデルを組合せ |
| 比較 | GPU、装置数2倍のGPU、従来Bank-PIM、共同処理なしDuplex、共同処理あり構成 |

実験はFP16重みを前提にしている。合成された要求分布と専門家選択の一様分布を使っており、実運用の人気専門家偏りや通信混雑をそのまま再現したものではない。面積・エネルギーは回路合成とモデルに基づく見積りで、シリコン試作の測定値ではない。

| GLaMのエネルギー | GPU | 最大42.03%削減 | 専門家数64でメモリ負荷が大きい |
| Grok1のエネルギー | GPU | 最大34.59%削減 | 2ノード通信の影響が残る |

表の「最大」と「平均」は原著の対象構成における集計であり、全モデル・全バッチの最低改善率を意味しない。特にGrok1は2ノードにまたがるため、装置間の通信が律速になり、他のMoEモデルほど大きな速度改善を得にくい。共同処理だけの追加利得が平均4%と小さいことは、論文の主張を評価するうえで重要な負の結果である。

図13の到着率を変えた実験では、Mixtralの入力4096・出力512トークン、最大バッチ128の条件で、基準GPUは毎秒9要求を超えると処理しきれない一方、Duplexは毎秒14要求まで対応した。ただし高到着率では混合段が増え、計算器を二倍持つ2倍GPUの方がトークン間遅延の上位分位点で有利になる条件がある。中央値ではDuplexが良くても、すべての遅延分位点で常に2倍GPUより速いとは限らない。

図14の従来Bank-PIMとの比較では、Mixtralの一部条件でDuplexはBank-PIMより最大1.80倍、平均1.49倍の処理量となる。だがMoEを持たず通常の多頭注意を使うOPTでは、極めて低演算密度の注意計算に対してBank-PIMがDuplexより速い条件がある。提案装置の最適範囲は「MoEとGQAを伴う中程度に低い演算密度」であり、あらゆるメモリ律速演算で既存PIMを上回るわけではない。

## 既存研究との差と適用限界

GPUだけを使う方式は高演算密度の行列積を高速に処理できるが、復号時に重みや鍵・値を頻繁に読み出すと計算器が遊休する。従来のBank-PIMはメモリの極めて近くで低演算密度処理を行える一方、DRAMダイに配置する演算器数に制約がある。DuplexはLogic-PIMをHBMロジックダイへ置き、xPUと共有するメモリを二つの経路から使うことで、MoEとGQAに特有の1～32 Op/B程度の領域を狙う。

ただし、Logic-PIMを実装するには追加TSV、HBM内部のバンク読出し構造変更、制御器、演算器、重み・鍵値の配置規則が必要である。一般のGPUにソフトウェアパッチを当てるだけで実現する方式ではない。特に民生GPUのローカル推論環境では、原著の2.67倍を既存ハードウェア上の設定変更による改善として期待できない。

原著の合成ワークロードは、要求長と専門家選択を確率分布から生成している。現実のモデルで専門家選択が偏る場合、あるいはモデルが異なる量子化形式や注意実装を使う場合、演算密度と配置最適点が変わり得る。二ノードGrok1の通信律速、高到着率での上位分位点遅延、MHAのOPTでBank-PIMが有利な条件は、Duplexの性能上限を示す具体例である。
