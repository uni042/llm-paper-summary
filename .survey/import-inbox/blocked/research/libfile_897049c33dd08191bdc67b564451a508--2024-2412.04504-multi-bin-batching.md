# Multi-Bin Batching for Increasing LLM Inference Throughput

## 概要
固定batch推論ではbatch内の1 requestだけ生成が長いと、短いrequestが終了してもslotを次requestで埋められずGPU資源が遊ぶ。Multi-Bin Batchingは生成時間の近いrequestを同じbinへ振り分け、各bin内でbatchを作ることでstragglerを減らす。

Dolly workloadでは推定出力長を使う8-binがstaticの273.53 token/sから684.02 token/sへ150.1%改善する一方、native continuous batchingの1200.07 token/sには43.0%届かない。したがってcontinuous batchingの置換ではなく、長さ認識のqueue/admission signalとしての価値が中心になる。

## 問題設定
static batchingではbatch完了時刻が最長requestの生成時間で決まる。生成長分散が大きいほど短requestのGPU laneが空く。continuous batchingは終了slotへ新requestを逐次入れて直接緩和できるが、fine-grained refillを使えない環境ではdispatch前groupingが重要になる。

## 手法
### 長さbin
request到着時に予測生成長をk個の区間へ分類する。各binは独立waiting areaで、同じbin内のrequestがbatch sizeに達するとready batchになる。batch内service time分散を小さくする。

### dispatch
複数binでbatchがreadyなら、最も古いrequest IDを含むbatchから中央queueへ送る。長いrequest binのstarvationを避けつつ長さを揃える。

### length estimator
実用評価ではoracle長だけでなく、Llama-3.2-3B-Instructのprompt-prefill hidden stateから軽量regressorでbinを推定する。Dolly 8-binのexact accuracyは56.69%だが隣接binまで含むaccuracyは94.89%で、誤差の多くは近傍に留まる。

## 評価条件
|項目|内容|
|---|---|
|GPU|単一NVIDIA A100 80GB|
|backend|llama.cpp|
|精度|FP16、context 4096|
|controlled|1024 requests、batch 32、生成長500–2000|
|Dolly|1478 requests、batch 64、生成長3–978|
|bin数|2/4/8/16|
|比較|static、native continuous batching|
|指標|generated tokens/s|

## 主要結果
|条件|static|Multi-Bin|continuous|
|---|---:|---:|---:|
|controlled oracle k=16|534.23|1380.48|1348.49|
|Dolly oracle k=8|273.53|965.97|1200.07|
|Dolly estimated k=8|273.53|684.02|1200.07|

controlled oracleではstatic比158.4%改善しcontinuousを2.4%上回るが、Dolly oracleではstatic比253.1%改善してもcontinuous比19.5%低い。推定長ではstatic比150.1%改善する一方continuous比43.0%低い。oracleは実運用で事前に得られない上限であり、推定結果と区別する必要がある。

## 既存研究との差
continuous batchingが実行中batchへrequestを補充するruntime機構なのに対し、Multi-Binはstatic batchingのdispatch前groupingだけを変更する。kernelやKV管理を変えず導入できるが、continuous batchingのslot再利用能力そのものは持たない。

## 限界
出力長予測が主要制約で、binを細かくするほどexact分類accuracyが下がる。Dollyではoracleですらcontinuous batchingより19.5%低い。評価は単一A100・llama.cpp中心で、multi-GPU、tail-latency SLO、KV memory pressureとの相互作用は主要評価外である。
