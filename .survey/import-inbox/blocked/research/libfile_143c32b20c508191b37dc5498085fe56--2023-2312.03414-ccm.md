# Compressed Context Memory For Online Language Model Interaction

## 書誌
Jang-Hyun Kim, Junyoung Yeom, Sangdoo Yun, Hyun Oh Song。ICLR 2024。正規識別子は `arXiv:2312.03414`。

## 概要
オンライン対話、個人化、継続的な少数例学習では、時刻が進むたびに過去の入力と出力が文脈へ追加される。通常のTransformerは過去の鍵・値（key/value; KV）を保持し続けるため、文脈長に比例してKV容量と注意計算が増える。固定文脈を一度だけ圧縮する既存方式も、毎時刻に累積文脈全体を再圧縮するとオンライン用途では費用が増え続ける。

Compressed Context Memory（CCM）は、新しく到着した文脈だけを前回の圧縮メモリと合わせて処理し、専用の `<COMP>` トークンのKVへ情報を凝縮する。CCM-concatは各時刻の圧縮KVを連結し、CCM-mergeはそれらを累積平均して固定長メモリへ統合する。推論時は生の過去文脈ではなく、このメモリと現在入力だけを注意へ渡す。

LLaMA-7Bを用いた会話・個人化・MetaICL評価では、full contextと同等水準の性能を約5分の1の文脈メモリで実現する。MetaICLの時刻16、FP16では、A100 80GB上でfull context 5.3 sample/sに対しCCM-merge 69.9 sample/s、RTX 3090 24GBでは3.5から50.7 sample/sへ増える。これは圧縮そのものの演算短縮だけでなく、KV削減により最大バッチを60→950、10→150へ増やせる効果を含む。

## 問題設定
時刻tで累積文脈長が `t*l_c` になると、full context推論のメモリは `O(t*l_c+l_i)`、注意演算は `O(t*l_c*l_i+l_i^2)` まで増える。固定文脈圧縮は生成側を短くできても、毎回過去全文を圧縮し直すため圧縮処理自体が `O(t*l_c)` のままである。

CCMは圧縮器の入力を「前回メモリ + 今回追加文脈」に限定する。これによりCCM-mergeの圧縮メモリ・計算は時刻tに依存せず `O(l_c)`、CCM-concatでも `O(t+l_c)` とし、生文脈長に比例する再処理を避ける。

## 手法
### COMPトークンによるKV圧縮
各新規文脈 `c(t)` の末尾へ `<COMP>` を置き、このトークンだけが `c(t)` と前回メモリ `Mem(t-1)` を参照する。全L層で得られたCOMPトークンのkey/value、合計 `2×L×d` の状態を `h(t)` として圧縮結果にする。圧縮結果が通常の埋め込みではなく各層のKVなので、生成時は既存Transformerの注意へ直接供給できる。

### 二つの更新則
CCM-concatは `h(1)...h(t)` をそのまま連結する。時間とともにメモリは増えるが、生の各文脈を残すより圧縮率が高く、情報保持性能も高い。CCM-mergeは `Mem(t)=(1-a_t)Mem(t-1)+a_t h(t)` とし、主実験では `a_t=1/t` の算術平均を使う。後者は時刻に依存しない固定長KVを維持する代わりに、強い圧縮で精度との交換条件が生じる。

### 圧縮専用conditional LoRA
通常の全体微調整では、モデルが圧縮メモリを使わず現在入力だけから答える方向へ過適合できる。そこでLoRA更新を `<COMP>` トークンにだけ適用するconditional LoRAを導入する。通常トークンのforwardは基盤モデルの重みWだけを使い、COMP時のみ `W + ΔW` を使うため、学習可能パラメータの役割を圧縮機能へ限定する。

### 再帰を単一forwardへ展開
逐次的にMem(1), Mem(2)…を構築して学習すると時刻数だけforwardが必要になる。CCMはCOMPトークンを時系列に挿入した一つの系列を作り、マスクで各COMPが過去メモリだけを見るよう制約する。これにより再帰圧縮をTransformerの並列forwardとして学習できる。論文は既存の再帰圧縮法より学習を7倍高速化したと報告する。

|用途|DailyDialog、LaMP、MetaICL|

## 主要結果
MetaICLではfull context精度70.8%に対しCCM-concat 70.0%、CCM-merge 69.6%。A100では最大バッチが60、300、950となり、スループットは5.3、24.4、69.9 sample/s。RTX3090では最大バッチ10、50、150、スループット3.5、18.6、50.7 sample/sだった。したがってCCM-mergeの大きな速度差は単一サンプルの注意短縮だけでなく、KV削減がメモリ制約下のバッチ並列度を大幅に上げることから生じる。

ストリーミング評価では文脈長に上限を置かない更新を行い、古い文脈を捨てるsliding windowより高い性能を維持する。CCM-concatは時間とともにメモリが増えるが精度が高く、CCM-mergeは固定長でより強い容量保証を持つ。

## 既存研究との差
GistingやICAEは固定された長文脈を短い表現へ圧縮するが、オンラインで新規文脈が追加されるたび全文再圧縮が必要になる。RMTやAutoCompressorは再帰的な圧縮トークンを使うが、逐次forwardが学習を遅くする。CCMは各層のKVそのものを圧縮状態とし、オンライン更新と並列学習を同時に成立させる。

## 限界
圧縮器を使うためconditional LoRAの事前学習が必要で、完全な学習不要方式ではない。CCM-mergeは固定容量を得る代わりに過去情報を平均へ押し込むため、長期間にわたる細部保持には限界がある。CCM-concatは生文脈より小さいものの時刻に比例して増える。評価は主にLLaMA-7Bと指定タスクであり、より大規模モデル・長大生成・現代的GQAモデルでの実測は論文範囲外である。
