# The KV Cache Is the New Memory Wall

> decodeの重み・KV交通量を閉形式で分離し、文脈長・バッチ・GPUトポロジに応じてKV最適化が効く境界と理論上限を定量化する。

## 概要

長文脈LLMのdecodeでは、モデル重みだけでなく過去全トークンの鍵値キャッシュ（KV
cache）を繰り返し読む。KV圧縮、追放、ページング、共有、オフロードの論文は多数あるが、文脈長、バッチ、GPU、品質指標が異なるため、報告された高速化倍率だけを横並びにすると比較を誤る。

本論文は新しい圧縮アルゴリズムを提案するのではなく、decode 1
stepの重みbytesとKV bytesを明示的に分けた解析モデルを作り、NVIDIA
H100/B200とAMD
MI300Xの帯域・パッケージ分割を入れて、どの条件で何が律速になるかを導出する知識体系化研究である。測定値、他論文の報告値、自身の導出値を区別する方針も採る。

Llama-3-70B BF16では重みが140GB、KVは1 tokenあたり327,680
bytesで、128K文脈の1系列だけで約42GBになる。スループット志向のbatch
32〜256ではKV交通量が重み交通量を超える文脈長が13.4Kから1.7Kまで低下し、長文脈サービングは実質的にKV帯域律速になる。

## 問題設定

decodeの演算強度は低い。H100 SXMのBF16 dense性能989.5
TFLOP/sとHBM帯域3.35 TB/sからroofline ridgeは約295 FLOP/Bだが、batch
1の通常decodeはそこから大きく下にある。Grouped-Query AttentionでKV
headを共有しても、KV読み出し自体は系列ごとに必要である。

バッチを増やすと重み読み出しは複数要求で共有できるため、重み側の演算強度は上がる。しかしKVは各系列固有なので、KV
bytesもattention
FLOPsもバッチに比例し、KV側演算強度は改善しない。これが「大バッチなら計算律速へ移る」という重み中心の直感が長文脈で崩れる理由である。

## 手法

### KV容量と交通量の閉形式

モデルの層数L、KV head数、head
dimension、要素幅、文脈長から1系列のKV容量を計算する。Llama-3-70Bでは327,680
bytes/tokenとなり、128Kで41.9GB、1Mで約328GBへ増える。

decode
stepの総メモリ交通量を、モデル重みの読出しと、batch内各系列のKV読出しの和として表す。両者を等置すると交通量交差文脈長が得られ、これより長い側ではKV削減率が直接速度上限へ効きやすくなる。

### 圧縮効果のregime分解

KV bytesをc分の1にする圧縮の理論速度向上を、圧縮前後の「重みbytes + KV
bytes」の比として表す。短文脈の重み律速領域ではKVだけ減らしても総bytesがほぼ変わらず速度向上は1へ近づく。十分長いKV律速領域では速度向上が圧縮率cへ近づく。

この式により、同じ2-bit
KV方式でも128Kでは1.25倍、512Kでは1.91倍というように、アルゴリズムが同じでも評価regimeだけで見かけの効果が変わることを説明する。

### パッケージ内トポロジ

B200は2 die、MI300Xは8
XCDにHBM帯域が分割される。KVページを一つのpartitionへ固定すると局所帯域しか使えず、複数partitionへstripingできればaggregate帯域へ近づける。

導出上、Llama-3-70BのKV token rate上限はB200でstriped 24.4M
token/sに対しpinned
12.2M、MI300Xでは16.2M対2.0Mとなる。圧縮前でも配置だけで最大8倍の理論差が生じるため、KV
block managerのdie/stack affinityも主要設計変数になる。

B200、batch 1の導出例では128K文脈でBF16 KVが22.7ms/step、2-bit

evictionを重ねた理論値は2.05倍である。これらは実測ではなくrooflineからの導出値である。

## 既存研究との差

個別のKV圧縮論文は品質と圧縮率を最適化し、ページング論文は容量管理、prefix
sharingは重複除去、offloadは階層メモリ利用を扱う。本論文はこれらを同じ「bytes、帯域、容量、品質」の座標へ置き、どのregimeで何が効くかを比較可能にする。

特にページングとprefix
sharingはモデル出力に対してlosslessだが、必ずしもdecode帯域を比例削減しないという区別を強調する。容量問題と帯域問題を同じ「KV最適化」として扱わない点が重要である。

## 限界

本論文の中心値は解析上限であり、実アプリケーションのend-to-end測定ではない。カーネル効率、scheduler
overhead、fragmentation、通信競合、実効帯域によって実測値は下がる。MI300Xのpackage内fabric
bandwidthなど公開されていない値もあり、トポロジモデルには公開仕様の限界がある。

また既存文献の品質評価はperplexity、needle
retrieval、LongBench等に分散し、分散や信頼区間、電力、format conversion
costが十分報告されていないと指摘する。したがって「最良のKV方式」を単一順位で結論する研究ではなく、比較条件を正規化する分析枠組みとして読む必要がある。
