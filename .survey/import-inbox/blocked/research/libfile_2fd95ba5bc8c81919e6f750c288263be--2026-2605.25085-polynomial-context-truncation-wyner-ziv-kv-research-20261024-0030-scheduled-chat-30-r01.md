# 文脈切り捨て感度の冪則とKVキャッシュの保持窓の理論的限界

## 研究目的と主要な主張

本論文は、自己回帰型言語モデルの鍵・値キャッシュ（Key–Value cache; KVキャッシュ）をどこまで削減できるかという問題を、過去のトークンをどれだけ残す必要があるかという時間方向の情報量問題として扱う。量子化の研究は、保持した一つのKV要素を何ビットで表現するかを主に考える。一方、本研究は過去のどの範囲を保持しないと次トークンの予測分布が変わってしまうかに注目する。したがって、INT2量子化や低ランク表現の精度を直接評価する研究ではない。

中心となる経験的観察は、直近wトークンだけを与えたモデルの次トークン分布と、全履歴を与えたモデルの分布の距離が、概ね `w^{-α}` に従って減るというものである。もし指数関数的に減衰するなら短い窓を追加するだけで誤差は急減するが、冪則では長い文脈を保持しても誤差の減り方は緩やかになる。著者はこの観察を「多項式的な文脈切り捨て感度」と呼ぶ。

理論的には、次ステップの問い合わせベクトルを復号側の補助情報とする逐次Wyner–Ziv符号化として圧縮を定式化する。末尾の連続窓しか保持しない方式について、総変動距離の許容誤差をεとすると、長さ `w=O(ε^{-1/α})` の窓で十分であることを示す。さらに、双方向のベイズリスク感度条件が成立すれば `w=Ω(ε^{-1/α})` も必要であり、この限定された方式クラスでは必要メモリが `Θ(ε^{-1/α})` となる。一般の圧縮方式すべての最適メモリ量がこの式で決まるという主張ではない。

## 問題設定：何を圧縮し、何を比較するか

時刻tの全履歴を `X_{1:t-1}` とし、固定されたモデルが出す次トークン分布を `p_t` とする。圧縮器は過去だけを使って符号 `Ĉ_t` を作り、復号器は符号履歴と次ステップの問い合わせ `Q_t` から近似分布 `p̃_t` を再構成する。原著は符号化率を符号の条件付きエントロピー、歪みを `D_KL(p_t || p̃_t)` の平均として定義する。この歪みは文章の最終的な正答率ではなく、予測分布そのものの違いを測る。

問い合わせ `Q_t` を補助情報として扱うのは、次の注意計算がどの履歴を必要とするかを復号側で知る、という理想化に対応する。ただし現実のTransformerでは問い合わせ自身が圧縮後の隠れ状態から計算されるため、補助情報が元のモデルと完全に同じとは限らない。著者はこの単一チャネルの理想化を明記し、すべての層の再帰的な依存関係まで厳密にモデル化したとは主張していない。

分布の近さは総変動距離（Total Variation; TV）とKullback–Leibler発散（KL発散）で測る。全履歴と末尾窓の次トークン分布のTVが `C w^{-α}` 以下という仮定を置く。ここでαは文脈を短くしても分布がどれだけ速く元へ近づくかを表す指数で、モデルやデータ領域によって変わる。αが小さいほど過去文脈の影響が長く残る。

## 理論的結果と成立条件

### 逐次Wyner–Zivの下界

一般のオンライン圧縮では、時刻tの符号は未来のトークンを参照できない。著者は、符号履歴から復元する予測分布の平均KL歪みをD以下にするには、逐次的な情報量に基づく下界 `R*(D)` を下回る符号化率を長期平均で実現できないと定式化する。これはオンライン圧縮の情報理論的な制約を与えるが、特定のKVキャッシュ実装がその下界に到達することを保証しない。

また、符号化率の下界と「保持トークン数」の下界は同一ではない。圧縮された潜在状態、量子化表現、層をまたぐ共有は、保持位置数と符号化ビット数の関係を変える。本研究の末尾窓に関する結論を、すべての圧縮済みキャッシュのビット数へ直接適用してはならない。

### 末尾窓方式の上界と条件付き下界

末尾wトークンを保持してそれ以前を削除する単純な方式は、全履歴と短縮履歴の分布差が `C w^{-α}` で減るなら、許容TV誤差εを満たすために `w` を `ε^{-1/α}` に比例して大きくすればよい。これは実装上の窓長を選ぶ目安になる。一方、必要窓長がこれより短くできないという逆向きの主張は、切り捨てた過去情報が実際に予測リスクへ一定の影響を与えるという追加の両側条件が必要である。

例えばαが0.5なら、誤差を半分にするために保持窓を概ね4倍にする必要があるというスケーリングになる。ただし係数は不明であり、実際のモデルがどの窓長で何点の精度になるかをこの式だけで決定できない。理論は漸近的な依存関係を示すものであり、具体的なGPUメモリ消費量や生成トークン毎秒を予測するものではない。

### Sink-plus-recentとKL歪みの指数

先頭の注意シンクと最近のトークンを残す方式について、追加のシンク安定性条件が成立する場合、KL歪みは予算kに対して `O(k^{-2α})` のように減ると述べる。TVとKLの指数が約2倍異なる根拠は、確率分布の各成分が極端にゼロへ近づかない局所条件下で `KL ≤ C·TV²` という二次的な関係を使えるためである。通常のPinsker不等式は逆方向の制約を与えるため、単にPinskerを適用して指数2倍を主張することはできない。

さらに、窓の末尾が連続している場合と先頭シンクを飛び地として保持する場合では条件が異なる。末尾窓に対する感度仮定だけから、飛び地のシンクを含む方式の挙動が自動的に導かれるわけではない。この点を原著は追加仮定として区別している。

### 達成可能性の未解決部分

論文には遅延した複数文字ブロック符号に関する操作的な比較定理がある一方、オンライン単一文字の符号化方式が情報理論的下界の指数に到達することは予想として残る。具体的に、`w_n=n^{1/(α+1)}` とするブロックマルコフ方式の収束率を主張する部分は、補助変数も同じ切り捨て感度を継承するという未証明の性質を用いており、確立した定理ではない。汎用方式や連続潜在表現への拡張にも予想が含まれる。

この区別を外すと、単純な末尾窓方式があらゆるKV圧縮方式に対して最適だと誤読してしまう。実際、重要トークン選択、再帰的要約、潜在キャッシュ、層別の圧縮は末尾窓クラスに属さないため、理論上の限界を上回る余地がある。

## 実験条件

| 項目 | 一次論文の設定 |
|---|---|
| GPU | NVIDIA RTX 5080、16GB、単一GPU |
| 計算精度 | FP16（主要4モデル）。Qwen2.5-7Bの補足測定は4ビット |
| モデル | Qwen2.5-0.5B / 1.5B / 3B、SmolLM2-1.7B |
| データ領域 | Gutenberg文学、GitHubのPythonソース。主モデルではWikipediaとJSONも追加 |
| 標本 | 各領域100個の文脈接頭辞。主要短窓測定は接頭辞1,024トークン |
| 短窓測定 | 窓長2〜256を掃引、元の位置番号を保持した条件と比較 |
| 長窓測定 | 接頭辞16,500、窓長256〜8,192を掃引して境界効果を回避 |
| 主指標 | 次トークン分布のTV・KL、対数空間の当てはめ誤差、上位1トークンの不一致 |
| 下流検証 | パープレキシティ、針探索（RULER風のキー・値検索） |
| キャッシュ方策 | 末尾窓、シンク＋末尾、無作為保持、注意重要度による保持など |

文脈の先頭を切り捨てて残りを新しい系列として再入力すると、回転位置埋め込みなどの位置番号が変わり、切り捨てそのもの以外の誤差が混ざる。著者は残存トークンの元の位置番号を保持する対照実験を行い、主要モデルでは指数の差が小さいことを確認した。これは測定手順の重要な品質管理である。

## 定量結果：冪則の再現性

| 条件 | 自然文のTV指数α | PythonコードのTV指数α | 解釈 |
|---|---:|---:|---|
| Qwen2.5-0.5B | 0.437 | 0.383 | コードのほうが過去文脈の影響が長く残る |
| Qwen2.5-1.5B | 0.508 | 0.439 | 同じ傾向 |
| SmolLM2-1.7B | 0.574 | 0.371 | モデル系列が変わっても冪則を観測 |
| Qwen2.5-3B | 0.575 | 0.417 | Qwen系列では自然文の指数が大きくなる |

Qwen2.5-0.5Bでは、自然文の冪則当てはめ誤差（対数RMSE）が約0.14、指数関数当てはめでは約0.32であり、Pythonコードではそれぞれ約0.08と0.31である。すなわち少なくとも測定した窓長範囲では、指数関数的な忘却より冪則的な忘却の説明力が高い。Wikipedia散文の指数は0.392、構造化JSONは0.426で、主モデルの追加領域でも同様の傾向が報告されている。

自然文の指数がコードより大きいという観察は、同じ窓長の追加によって自然文の予測分布のほうが比較的速く元へ近づくことを意味する。ただし、各モデルの学習データやトークナイザ、Pythonコーパスの大きさに依存する可能性がある。Qwen2.5-7Bの4ビット補足実験では自然文の指数が約0.57で、3Bから大きくは伸びなかった。これを「モデルが大きくなるほど必ず指数が増える」という普遍法則と解釈することはできない。

長窓の検証では、16,500トークンの接頭辞を使い、8,192トークンの窓でも半分近い履歴を捨てるようにしている。自然文の指数は約0.36、対数RMSEは0.06で、短窓より少し緩やかながら冪則を維持した。短い接頭辞で窓をほぼ全文まで伸ばすとTVがゼロに近づく自明な境界効果が生じるため、その条件を避けた結果である。

## 定量結果：実際のキャッシュ方策と下流課題

| 測定 | 方策・条件 | 報告結果 | 注意点 |
|---|---|---|---|
| KL歪み（自然文） | 512トークン保持、シンク＋末尾 | 約0.011 | 無作為保持の約1.9より大幅に小さい |
| KL歪み（Python） | 512トークン保持、シンク＋末尾 | 約0.003 | 無作為保持の約2.1より小さい |
| 上位1予測の不一致 | 末尾窓 | 予算の約-0.37乗で減衰 | 全キャッシュの最多確率トークンとの違い |
| 上位1予測の不一致 | シンク＋末尾 | 予算の約-0.42乗で減衰 | 自然文のTV指数0.44に近い |
| パープレキシティ | 全保持 | 13.2 | Qwen2.5-0.5Bの自然文 |
| パープレキシティ | 末尾系方策、保持512 | 全保持の3%以内 | 無作為保持は512でも3,000超 |
| 針探索 | 全保持、文脈512〜4,096 | 各長さで正答率0.98以上 | 圧縮時は針の位置が窓内かが支配的 |

この結果は「分布の平均誤差が小さい」ことと「必要な文書中の特定の事実を検索できる」ことの違いを示す。パープレキシティでは512トークン程度の末尾窓で全保持に近づいても、文脈中央に置いた針が保持範囲の外なら検索正答率はほぼゼロとなる。文脈長が2,048以上のとき、512トークンの末尾窓だけでは針を保持できない条件がある。したがって、生成の平均的な言語モデリング品質が保たれることを、任意の長文検索に対する保証とみなしてはならない。

シンク＋末尾のKL誤差の指数がTVの約2倍になるという実験は、局所的な二次近似と整合する。ただし、異なる方策同士の指数を比較すると比率が大きく見える場合がある。著者は同じ保持方策・同じ予算格子で比較した場合の比率を約1.93〜2.04と報告し、確率下限を確保する平滑化実験でも約2.00という関係を観測している。これは測定領域での経験的整合性であり、全モデル・全分布で成立する恒等式ではない。

## システム設計への含意

末尾窓方式を採用する場合、必要な窓長をモデル・ドメイン別に測った切り捨て感度から選ぶという考え方が得られる。コード生成では自然文より古い文脈の影響が長く残る傾向があり、同じ窓長を機械的に使うと品質低下が異なる可能性がある。特にリポジトリ全体から過去の定義や依存関係を検索する課題では、最近のトークンだけで十分という保証はない。

一方、保持位置を重要度で選ぶSnapKVやQuest、層別に予算を配分するPyramidKV、潜在表現を保持するMLAなどは、連続した末尾窓という制約を外す。これらが理論的にどれほど有利かを定量化するには、選択位置の依存関係や潜在表現の次元、問い合わせチャネルの性質を含む追加の解析が必要になる。本論文の枠組みはその出発点にはなるが、実装ごとの最適性証明ではない。

また、著者の実験は分布歪みや検索品質の測定であり、実際の推論速度、GPU間のKV転送量、メモリ断片化、サービスの初回遅延を測っていない。したがって、ここでの `w=Θ(ε^{-1/α})` を「KVキャッシュ容量をその倍率で削ればサービングが速くなる」という性能式に読み替えることはできない。GPU上のカーネル実装やバッチサイズの制約は別途評価が必要である。

## 限界と未解決課題

主要な実測は0.5B〜3Bの四モデル、100接頭辞/領域、比較的小さいPythonコード集合に限定される。7Bは4ビットの補足測定だけで、8B以上の一般的な実運用モデルのFP16検証ではない。さらに、位置番号保持の対照実験は主モデルで確認されており、すべてのアーキテクチャで同じとは限らない。

理論上は、理想的な次ステップ問い合わせを復号側が受け取るという抽象化と、分布の下限・両側リスク・シンク安定性などの追加条件が重要である。オンライン単一文字の達成可能性、汎用的な窓選択、再帰的圧縮要約の最適性、全層の依存関係を考慮した最小ビット数は未解決である。証明された下界・上界、経験的観察、著者の予想を区別することが、この論文を他のKV圧縮研究へ引用する際の最重要点となる。
