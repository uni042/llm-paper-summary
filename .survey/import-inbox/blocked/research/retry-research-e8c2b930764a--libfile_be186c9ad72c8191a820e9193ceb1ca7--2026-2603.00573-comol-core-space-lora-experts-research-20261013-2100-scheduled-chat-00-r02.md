# CoMoL: Efficient Mixture of LoRA Experts via Dynamic Core Space Merging

## 概要

本論文は、低ランク適応（LoRA）を複数の専門家へ拡張する際に、専門家の数に比例して増える学習パラメータと計算量を抑えつつ、トークン単位の細かな経路選択を維持するCoMoLを提案する。従来の専門家混合型LoRA（MoE-LoRA）は専門家ごとに大きな低ランク行列を保持し、すべての専門家を重み付き実行すると演算が増える。事前に専門家の重みを統合する方式は計算を抑えられるが、入力例全体で一つの経路選択をするため、トークンごとに必要な専門知識が異なる場合に適応しにくい。

CoMoLは共有する二つの射影基底の間に、専門家固有の小さな正方行列だけを保持する。各トークンの経路選択値で専門家の小行列を先に統合し、統合後の一つの行列に対して射影を一度だけ行う。経路選択器も共有低ランク空間へ移し、専門家数が増えてもパラメータの増加を抑える。Qwen3-8Bの数学6課題平均正答率は標準LoRAの82.78%から84.48%へ、コード生成のHumanEvalにおけるQwen3-8BのPass@1は39.69%から48.11%へ改善した。一方、実測学習時間は通常LoRAより長く、専門家数を増やしても精度が単調に上がるわけではない。

## 問題設定

通常のLoRAは、固定した重みWに対して低ランク行列BとAの積BAを追加し、元モデルの大部分を凍結したままタスク適応する。入力xに対する追加演算はBAxであり、学習対象はBとAである。専門家混合型LoRAでは、異なるタスクやトークンに対応するためN組のB_iとA_iを持つ。入力ごとの経路選択値G_i(x)で専門家出力を合成すれば表現力は増えるが、学習パラメータはおおむねN倍になり、全専門家の出力を計算する方式では演算量もN倍へ近づく。

専門家を一部だけ実行する疎な経路選択では、活性化する専門家数をkに抑えられるものの、トークンごとに選択・実行を切り替える負担が残る。入力例全体で専門家の重みを事前統合するSMEAR型は高次元の射影を一度にできるが、同じ文の中で異なる専門家を必要とするトークンへ別々に対応しにくい。CoMoLが解こうとする課題は、**トークン別の適応性を維持しながら、専門家ごとの高次元行列と高次元出力の重複計算を除くこと**である。

著者は専門家の更新方向に共通の低ランク部分空間があると仮定し、共通基底の中で専門家ごとの差を小行列に閉じ込める。この仮定が成り立てば、専門家を増やしても保持するのは小さなr×r行列だけで済む。ただし専門家の差異が共有基底で表現できない場合には、専門家の独立性が制限される可能性がある。従って学習パラメータ数だけでなく、実際の正答率とコード生成品質、学習・推論時間を比較する必要がある。

## 手法

### 1. 共有低ランク基底と専門家固有のコア行列

標準LoRAの重み差分を `ΔW = BA` とし、BとAをそれぞれ縮約特異値分解する。原著式9～11では、B側の左特異ベクトルをU_B、A側の右特異ベクトルをV_Aとすると、差分を `ΔW = U_B M V_A^T` と書ける。中央のMはr×rのコア行列であり、二つの共有基底の間の結合強度を表す。CoMoLでは各専門家iの固有パラメータをM_iだけに限定し、U_BとV_Aを専門家間で共有する。

この構成では、専門家N個のB_iとA_iを保持する場合のパラメータ増加量が、おおむね `O(N(m+n)r)` であるのに対し、CoMoLは共有基底の `O((m+n)r)` と専門家ごとの `O(Nr²)` の和になる。モデルの射影次元m,nが数千、階数rが8程度なら、Nを増やしても専門家ごとの増分は小さい。原著は例えばr=8、モデル次元n=4096という桁差を示している。なお共有基底の存在は方式の設計仮定であり、全ての専門家を完全に再現できるという証明ではない。

### 2. トークンごとの小行列統合

各入力トークンxに対して経路選択器が専門家重みG_i(x)を出力し、活性化した専門家のコア行列を `M_merged(x) = Σ_i G_i(x) M_i` として重み付き合成する。出力は `h = Wx + U_B M_merged(x) V_A^T x` となる。重要なのは、各専門家に対して高次元の `U_B M_i V_A^T x` を別々に計算してから合成するのではなく、r×rのコア行列だけを先に合成することである。分配法則により両者は数学的に等価な形であり、トークンごとの経路選択を維持したまま高次元射影を一回にできる。

原著の計算量分析では、専門家ごとの出力を合成する方式の主要演算はNに比例する一方、コア行列統合方式の高次元射影はNに依存しない。残る統合費用はトークン数Lに対して `L r² (N−1)` 程度であり、通常の高次元出力をN個合成する費用より小さい。ただしコア統合と経路選択の処理が完全に無償になるわけではない。表1の理論的な「標準LoRA比1.0倍の専門家演算」は経路選択器の費用を省いた比較であるため、実測時間を別途確認する必要がある。

### 3. 低ランク空間での経路選択

通常の経路選択器は、入力のモデル次元nからN個の専門家重みを直接求めるため、重み行列がN×nとなる。CoMoLは共有射影 `x_hat = V_A^T x` により既に得られたr次元表現を経路選択器へ入力する。経路選択の学習パラメータはN×rに縮小され、同じx_hatをコア統合後の計算にも再利用する。原著式14～15の出力は `h = Wx + U_B (Σ_i G_i(x_hat)M_i) x_hat` であり、経路選択→コア統合→共有基底による出力変換という順序になる。

この構成は経路選択の粒度を入力例単位に下げず、トークンごとに異なる専門家の重みを使える。さらに、経路選択器のパラメータ増加が専門家数Nと階数rに比例するため、モデル次元nに比例する通常方式より小さい。実験ではコア空間経路選択を外したCoMoLと比較し、精度を大きく損なわずに学習パラメータを削減する効果を確認している。共有低ランク表現が入力の全情報を保持するわけではないため、経路選択の情報量を削ったことによる悪化条件も実験で確認する必要がある。

## 実装・評価条件

| 項目 | 原著の条件 |
|---|---|
| 数学の基盤モデル | Qwen3-8B、Qwen3-14B |
| 数学の学習資料 | Math14k。GSM8K・AQuAの訓練問題と推論過程を含む |
| 数学の評価 | AddSub、AQuA、GSM8K、MultiArith、SingleEq、SVAMPの6集合平均正答率 |
| コード生成の基盤モデル | Qwen3-8B、Llama3.1-8B |
| コード生成の学習・評価 | CodeAlpaca-20kで学習、HumanEvalでPass@1/5/10 |
| 主要比較方式 | LoRA、MoLoRA、HydraLoRA、MoLA、AdaMoLE、SparseMoA、DenseLoRA、FlyLoRA |
| 数学の主要設定 | MoE-LoRAの階数8。Qwen3-8Bは専門家8、Qwen3-14Bは専門家4。1エポック学習 |
| 学習対象層 | 注意機構のQ/K/V/O射影とDown射影。Gate/Up射影は対象外 |
| 再現性 | 数学は乱数種3通りの平均・標準偏差。コード生成は検証集合で最良のチェックポイントを選択 |

数学の標準LoRA、DenseLoRA、FlyLoRAは学習パラメータ数を揃えるため階数をそれぞれ16、256、32へ調整している。コード生成ではQwen3-8Bを5エポック、Llama3.1-8Bを1エポック学習する。したがって「全方式が完全に同じ階数・学習期間」という比較ではなく、原著の条件に従って各方式の能力とパラメータ量を比較している。学習・推論時間の比較はCodeAlpaca-20kとHumanEvalを使った別の制御実験であり、数学6課題の正答率から直接推論速度を計算してはならない。

## 評価結果

### 数学6課題平均の正答率と学習パラメータ数

| 基盤モデル | 方式 | 平均正答率 | 学習パラメータ数 |
|---|---|---:|---:|
| Qwen3-8B | 標準LoRA | 82.78% | 2,477万 |
| Qwen3-8B | MoLoRA | 83.85% | 1億735万 |
| Qwen3-8B | CoMoL・コア経路選択なし | 84.47% | 3,339万 |
| Qwen3-8B | **CoMoL** | **84.48%** | **2,516万** |
| Qwen3-14B | 標準LoRA | 85.18% | 3,539万 |
| Qwen3-14B | CoMoL・コア経路選択なし | 86.08% | 4,790万 |
| Qwen3-14B | **CoMoL** | **86.34%** | **3,582万** |

原著表2・表3では、Qwen3-8BのCoMoLは標準LoRAより平均1.70ポイント高く、MoLoRAより学習パラメータ数が大幅に少ない。AQuAではLoRAの37.40%に対してCoMoLは44.62%で、7.22ポイント高い。一方、GSM8KではFlyLoRAが86.20%、CoMoLが83.93%であり、全ての個別課題で最高というわけではない。コア経路選択を外した構成との平均正答率差は84.47%対84.48%とごく小さいが、学習パラメータは約823万減る。ここでは経路選択器の低ランク化が主として容量効率を改善している。

Qwen3-14Bでも平均86.34%で標準LoRAの85.18%を上回るが、差は1.16ポイントである。数学の実験は3乱数種の平均で、Qwen3-8BのCoMoLの標準偏差は1.40ポイントと報告される。差が小さい比較ではこのばらつきを無視して優劣を断定しない。学習パラメータ数の差は明確でも、個別の正答率はデータセットと乱数種に左右される。

### コード生成の品質

| 基盤モデル | 方式 | HumanEval Pass@1 | Pass@5 | Pass@10 | 学習パラメータ数 |
|---|---|---:|---:|---:|---:|
| Llama3.1-8B | 標準LoRA | 26.22% | 54.41% | 67.07% | 2,306万 |
| Llama3.1-8B | CoMoL | **35.00%** | 63.65% | 73.17% | 2,324万 |
| Qwen3-8B | 標準LoRA | 39.69% | 72.29% | 81.71% | 2,477万 |
| Qwen3-8B | CoMoL | **48.11%** | 77.22% | 86.59% | 2,497万 |

原著表4では、CoMoLのPass@1はLlama3.1-8Bで8.78ポイント、Qwen3-8Bで8.42ポイント改善する。学習パラメータ数は両モデルとも標準LoRAに近い。CoMoLのコード生成性能が高いことは、専門家の多様性を小行列に集約しても一定の適応能力を維持できることを示す。ただしQwen3-8BのPass@5はコア経路選択を外した方式77.25%に対してCoMoLが77.22%と僅かに低く、経路選択器の圧縮が全指標で一様に優れるわけではない。

### 専門家数・階数の感度

原著表5では、Qwen3-8Bの専門家数を8から64へ増やしても平均正答率は84.48%から82.72%へ低下する。一方、学習パラメータは2,516万から2,791万へ緩やかに増える。コア経路選択なしでは同じ64専門家で9,378万となる。Qwen3-14Bでも8専門家86.34%に対して64専門家86.23%であり、専門家数の増加は性能改善を保証しない。著者は、限られた学習データで専門家を増やすと十分に専門化できないことを原因候補として挙げている。

原著図2の階数比較では、コード生成でCoMoLは複数の階数にわたり標準LoRAを上回るが、最良は階数16であり、さらに階数を上げても改善しない。コア経路選択なしの方式は階数8ではCoMoLを上回る場合がある。従って小さな経路選択器が常に最適とは限らず、モデルの基盤能力、階数、専門家数に合わせた調整が必要である。

### 実測学習時間・推論時間

| 方式 | CodeAlpaca-20k 1エポック学習時間 | HumanEval累積推論時間 |
|---|---:|---:|
| **標準LoRA** | **0:56:47** | **18.40分** |
| MoLoRA | 4:44:50 | 19.67分 |
| HydraLoRA | 4:15:15 | 19.16分 |
| MoLA | 7:59:02 | 30.03分 |
| AdaMoLE | 8:18:54 | 40.78分 |
| CoMoL・コア経路選択なし | 2:33:27 | 18.62分 |
| **CoMoL** | **2:19:55** | **18.57分** |

原著表6は、学習をバッチサイズ1、推論をバッチサイズ16で計測した別の時間比較である。CoMoLはMoLoRAやHydraLoRAの約半分の学習時間であり、MoLAやAdaMoLEより大幅に短い。推論時間も標準LoRAの18.40分に近い18.57分で、MoLAの30.03分より短い。しかし、**CoMoLの学習時間は標準LoRAの約2.46倍**であり、「標準LoRAより学習が速い」という解釈は誤りである。専門家混合の適応能力を保ちながら、従来のMoE-LoRAに比べて時間とパラメータを削減したことが実験上の主張である。

## 既存研究との差

標準LoRAは学習対象が小さく高速だが、複数の専門的な更新方向を条件に応じて選ぶ機構を持たない。MoLoRAのように全専門家の出力を混ぜる方式は専門家ごとに射影を実行するため、専門家数に応じて計算量が増える。疎なMoE-LoRAは一部だけ実行するが、選択や専門家実行の管理費用が残る。SMEAR型の入力例単位の事前統合は実行回数を減らす一方、トークンごとに異なる専門家を使い分けにくい。

CoMoLは「各専門家の高次元行列を共有基底＋小行列に分ける」「トークンごとに小行列を先に統合する」「経路選択も低ランク表現上で行う」という3段の変更により、トークン単位の動的適応と高次元射影一回の計算構造を両立させる。これは通常のMoE本体の全重みを専門家化する研究ではなく、凍結した言語モデルに加える低ランク適応部分の構造を改善する研究である。よってモデル全体のパラメータが1/Nになるわけではない。

## 限界と実装上の注意

第一に、共有基底が全専門家の更新方向を十分に表せるという仮定が必要である。専門家ごとの独立した高次元射影が必要なタスクでは、小行列だけに差を閉じ込めることが表現力の制約になり得る。今回の評価では数学・コード生成で改善したが、長文脈推論、音声、視覚、異なる専門領域を横断する混合データでは未検証の部分が残る。

第二に、専門家数を8から64へ増やしても精度が改善せず、Qwen3-8Bでは低下する。これは学習データ量と専門家数の不均衡に敏感であることを示す。専門家を大量に増やす設計は、追加の小行列パラメータが少なくても学習の安定性と専門化の問題を解決しない。

第三に、理論的な演算量1.0倍はLoRA専門家部分だけを数えた比較であり、経路選択、コア行列統合、メモリアクセス、実装オーバーヘッドを完全には含まない。原著表6の実測では推論時間は標準LoRAとほぼ同等だが、学習時間は標準LoRAより2倍以上長い。モデル全体の推論スループットやGPU占有率の改善を示すには、さらに要求バッチ・系列長を変えたサービング評価が必要である。

第四に、数学では乱数種3通りのばらつきがあり、モデルや個別データセットで優劣が入れ替わる。Qwen3-8BのGSM8KではFlyLoRAの方が高く、コード生成のPass@5ではコア経路選択なしの方式が僅かに上回る。CoMoLをすべての指標で最良とするのは不適切である。著者の公開実装を利用する場合も、TransformersやLoRA統合層の対応、GPUメモリ容量、低ランク射影の融合カーネル実装を確認する必要がある。
