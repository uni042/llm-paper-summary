# BatchLLM: Optimizing Large Batched LLM Inference with Global Prefix Sharing and Throughput-oriented Token Batching

## 書誌情報
- canonical identity: `arXiv:2412.03594`
- 著者: Zhen Zheng, Xin Ji, Taosong Fang, Fanghao Zhou, Chuanjie Liu, Gang Peng
- 初回公開: 2024-11-29、v3: 2026-04-22
- 掲載: MLSys 2026
- 一次資料: https://arxiv.org/abs/2412.03594

## 概要
一般的なLLM serving engineは到着時刻が未知のonline requestをcontinuous batchingで処理する。一方、評価・データ処理・企業内batch jobでは開始前から大量request集合が分かり、system promptやfew-shot例など長いprefixを多数requestが共有する。この情報をonline前提のLRU prefix cacheへ任せると、後で再利用するKVが早期evictされ、request集合全体の共有構造を活用できない。

BatchLLMはoffline/large-batchという条件を明示的に利用する。全requestから共有prefixをglobalに識別し、同prefix requestを近接して実行する。さらに各requestのprefill/decode構成を考えて順序を変え、decode tokenと後続prefill chunkを同じbatchへ混ぜる。GPUメモリ余裕からtoken batchを決めるmemory-centric batchingと、共有prefix attentionの水平融合を組み合わせる。

## 問題設定
prefillは大きな行列積で計算律速になりやすく、decodeは重みを少数tokenのために読むメモリ帯域律速になりやすい。大規模batchで両者を別々に処理するとGPU資源利用が偏る。online schedulerは将来requestを知らないため、全体最適な順序へ並べ替えられない。

またLRU型prefix cacheは「直近で使ったか」で保持を決めるため、batch後半で大量に再利用されるprefixでも一時的に使われなければevictされる。BatchLLMはrequest集合既知というoffline条件から、再利用順序そのものを制御する。

## 手法
### global prefix sharing
全promptを事前解析して共通prefixを抽出し、同じprefixを持つrequestをgroup化する。group内を連続実行することで一度計算したKVを短期間に再利用し、LRU evictionへ依存しない。prefix lifetimeをrequest reorderで短くするため、同じcache容量でもhitを増やせる。

### throughput-oriented reordering
decode比率が大きいrequestを先に進め、そのdecode tokenを後から来るrequestのprefill chunkと同じbatchへ混ぜる。計算律速prefillと帯域律速decodeを組み合わせ、GPUの演算器とmemory subsystemをより同時に利用する。

### memory-centric token batching
固定token数だけでbatchを切るのではなく、KV・activation等のメモリ需要から安全に載せられるtoken数を決め、利用可能memoryを使い切る方向へbatchを拡大する。offline workloadではlatency SLOよりthroughputが主指標なので、大きいtoken batchを積極的に形成できる。

### prefix-shared attention kernel
同一prefixを共有する複数requestのattention処理を水平融合し、小kernelが多数発生するtail effectとkernel launch overheadを減らす。scheduler側の共有認識をkernel側まで伝える点が、単なるrequest reorderと異なる。

## 評価条件
| 項目 | 条件 |
|---|---|
| workload | large-batch / offline inference、共有prefixを含むmicrobenchmarkとindustry workload |
| 比較 | vLLM、SGLang |
| ハードウェア | 複数hardware環境 |
| 指標 | throughput、GPU utilization、prefix reuse効果 |
| 構成要素 | global prefix grouping、request reorder、token batching、fused attention |

## 主要結果
| 条件 | 結果 | 意味 |
|---|---:|---|
| microbenchmark/industry workload | vLLM/SGLang比1.3〜10.8× | batch全体情報を使う総合効果 |
| prefix sharing | KV再計算・evictionを削減 | global groupingの効果 |
| mixed token batch | GPU utilization向上 | prefill/decode資源特性を補完 |
| fused attention | launch/tail overhead削減 | scheduler情報をkernel最適化へ接続 |

## 既存研究との差
vLLMやSGLangはonline requestを低latencyで捌く汎用engineであり、未来request集合を前提にできない。BatchLLMはoffline batchという制約を受け入れ、全promptを見たglobal optimizationを行う。prefix cachingだけでなく、実行順序とtoken batch、attention kernelまで同じ共有構造へ合わせる。

## 限界
requestが逐次到着するinteractive servingでは未来集合を見られず、global reorderの前提が崩れる。throughput優先の並べ替えは個別request latencyや公平性を悪化させ得る。最大10.8倍は共有prefix率やworkload形状に強く依存し、prefixがほぼ共有されないbatchでは利得が縮む。
