# Harder Tasks Need More Experts：難度に応じて起動専門家数を変える動的経路選択

## 概要

この論文は、混合専門家（Mixture of Experts、MoE）モデルの各トークンに対して、常に同数の専門家を割り当てる必要があるのかを問う。従来の上位K件選択（Top-K routing）は、ルータがどれほど確信していても常にK個を起動する。簡単なトークンでは計算を浪費し、複雑な推論を要するトークンでは専門家数が不足し得る。著者は、専門家選択確率の累積和が閾値pを超える最小集合を採用する動的経路選択を提案し、モデルの学習過程にエントロピー罰則を追加する。

24層、各層16専門家、総パラメータ約35億の小規模混合専門家モデルを1000億トークンで学習した結果、5種類の下流課題の平均は固定Top-2の41.6に対して動的方式42.3となった。推論時の平均起動専門家数は固定2に対して1.76である。難しいBIG-Bench Hard（BBH）では平均1.87専門家、比較的容易なPIQAでは1.72専門家となり、入力の違いに応じた配分が観測された。ただし、これは実機の生成スループットの改善値ではなく、主として起動パラメータ数とベンチマーク得点の比較である。

## 問題設定と仮説

標準的な混合専門家層では、トークン表現xに対しルータが各専門家の確率P_iを計算し、確率の高いK個だけを実行する。Kは層・トークンに依存しない定数として扱われることが多い。著者は、入力の難しさが異なるにもかかわらず専門家の計算予算を一律に配る設計を問題視する。たとえばルータ確率が一つの専門家に極端に集中する場合、二つ目の専門家を必ず起動する根拠は薄い。一方、確率が複数の専門家へ分散する場合は一つの専門家だけでは不足する可能性がある。

提案の前提は、ルータの確率分布を「各専門家への適合の確信度」とみなせることである。この前提は論文の動機づけであり、確率が統計的に校正された難度推定値であることを証明したわけではない。入力の難度を外部の分類器で測定するのではなく、学習済みルータの分布形状を代理信号に用いる点が特徴である。確率が集中する入力では少数、分散する入力では多数を起動するため、入力の意味的な難度と計算量の関係を後から観察できる。

固定Top-1とTop-2の単純な比較では、Top-2が多くの課題で精度を上げるが、活性化パラメータは増える。著者の狙いは、常にTop-2を実行するより少ない平均計算量で、Top-2以上の平均精度を得ることである。この研究は推論時の専門家割当てに直接関係する一方、学習時のルータ損失を変える必要があるため、完全な学習不要最適化とは異なる。

## 手法

### 1. ルータ確率の計算と固定方式との違い

専門家数をN、隠れ状態の次元をdとし、学習可能なルータ行列W_r∈R^{N×d}を用いる。入力トークン表現xに対しP=softmax(W_r x^T)を計算する。通常のTop-KではPの上位K要素を選び、選択集合の確率和で再正規化して専門家出力の重みを求める。論文の式(1)〜(3)は、この基準方式を定義している。ここで比較対象のKは1または2であり、各トークンに対して必ず同数の専門家を実行する。

動的方式では、Pの成分を降順に並べたインデックス列Iを作る。上位t件の累積確率がp以上になる最小のtを求め、集合S={e_{I_1},...,e_{I_t}}を起動する。pは0〜1のハイパーパラメータであり、pを大きくすると選択集合が拡大しやすい。たとえば一位の確率だけでpを超えれば1専門家、二位まで足して初めて超えるなら2専門家が起動する。この選択は各トークン、各混合専門家層で独立に行われるため、同じ文章内でも計算量が変わる。

論文の式(5)では、選択された専門家の重みをP_iのまま使い、選択されなかった専門家の重みを0にする。基準Top-Kの式(3)と異なり、選択集合内で再正規化しない記述であるため、実装比較ではこの差を無視できない。とくに選択確率和が1未満の場合、混合専門家層の出力スケールが変化する可能性がある。論文の性能差を純粋な専門家数可変化の効果と解釈する際は、ルータの重み付け規則も併せて考慮すべきである。

### 2. エントロピー罰則による過剰起動の抑制

単に累積確率閾値を導入しただけでは、ルータが確率を均等に割り当てて多数の専門家を起動し、性能を稼ぐ抜け道がある。例えば16専門家に確率が均等に分布し、p=0.5なら多数の専門家を選ばなければ閾値に届かない。著者はこの状況を避けるため、PのエントロピーH(P)=-Σ_i P_i log P_iを動的損失L_dとして加える。エントロピーが小さいほど分布は尖り、少数の専門家だけで累積閾値を超えやすくなる。

この損失は、トークンの表現を複数の専門家へ均等に割り当てることより、少数の専門家に集中させることを奨励する。したがって、精度だけでなく活性化専門家数を学習時に制御する仕組みである。反面、罰則を強くしすぎれば簡単な入力だけでなく難しい入力でも専門家を過少起動する可能性がある。本文の閾値感度分析で小さなpが精度低下を生む点は、この懸念と整合的である。

### 3. 負荷分散損失と最終学習目的

少数の専門家へ確率を集中させるだけでは、特定の専門家に負荷が偏り、分散実行時の待ち時間や学習効率を悪化させ得る。そこで著者は、専門家iが選択されるトークン割合f_iと平均ルータ確率Q_iから構成される負荷分散損失L_b=N Σ_i f_i Q_iを併用する。f_iは選択集合Sに含まれるかの指示関数から、Q_iはトークン集合上のルータ確率平均から計算する。

最終損失はL=L_lm+αL_b+βL_dであり、L_lmは次トークン予測損失、実験設定ではα=10^-2、β=10^-4を使用する。負荷分散損失は専門家間の均衡、動的損失はトークンごとの専門家数削減をそれぞれ狙うため、両者は異なる方向の圧力をルータへ与える。推論時にはこれらの損失計算は不要だが、学習で獲得したルータ分布が必要になる。既存の固定Top-2チェックポイントに推論時のpだけ追加しても、論文と同等の分布を再現できる保証はない。

### 4. 推論時の選択とシステム上の費用

推論ではトークンごとにN個のルータ得点を計算し、降順の累積確率から起動集合を作り、選択した専門家の出力を合成する。固定Top-2と比較すると、専門家の重み読出しや演算回数を平均的に減らせる可能性がある。論文の実験は実際に平均起動数が減ったことを示すが、専門家の動的個数がGPUのバッチ化、専門家並列、メモリアクセスの規則性をどう変えるかは十分に測定していない。

各トークンで選択集合の大きさが違うと、同一専門家に送るトークンのバッチ長や専門家間の負荷が変化する。専門家を別GPUへ分散配置する場合、転送量の平均削減と最大負荷の偏りが同時に発生し得る。したがって、起動パラメータの削減を、そのままGPU実測のトークン毎秒改善率へ換算してはならない。既存サービング基盤へ移植するなら、ルータ結果の動的圧縮、専門家ごとのトークン束ね、並列通信の負荷均衡を別途測定する必要がある。

## 評価設計

| 項目 | 原著での条件 |
|---|---|
| モデル | LLaMA系構造、24層、隠れ次元1024、語彙32000、混合専門家層に16専門家 |
| 規模 | Dense 374M/570M、MoE全体約3.5B、Top-1活性化374M、Top-2活性化581M |
| 学習データ | RedPajama、共通クロール・C4・GitHub・Wikipedia・書籍・arXiv・StackExchange |
| 学習量 | 主実験では100Bトークン |
| 動的方式 | 推論評価の主設定p=0.4、学習損失係数α=0.01、β=0.0001 |
| 比較対象 | Dense 374M/570M、固定Top-1、固定Top-2、提案動的経路選択 |
| 評価方法 | OpenCompassを使用。PIQA、HellaSwag、ARC-e、CommonsenseQA、BBHの下流課題 |
| 計算量の代理指標 | 1トークン当たり平均起動専門家数。推論の実測スループットとは別 |

論文の表1は5課題の得点を列挙し、表2は学習データ別の起動専門家数、表3は推論課題別の平均起動専門家数を示す。表1の平均は異なるベンチマークの得点を算術平均した値であり、同一尺度の物理性能を意味しない。また、表3は正解を連結した入力を最大2048トークンへ切り詰めて測定しており、自由生成での専門家選択をそのまま示すものではない。

## 主要結果と機構の検証

| 指標・課題 | 固定Top-2 | 動的方式 | 読み取れること |
|---|---:|---:|---|
| 5課題平均得点 | 41.6 | 42.3 | 平均で+0.7ポイント。相対0.7%高速化ではない |
| PIQA | 68.1 | 68.1 | 動的方式で得点改善なし |
| HellaSwag | 43.9 | 44.3 | +0.4ポイント |
| ARC-e | 40.4 | 39.9 | **-0.5ポイントの悪化** |
| CommonsenseQA | 32.1 | 33.6 | +1.5ポイント |
| BBH | 23.3 | 25.6 | +2.3ポイント。推論課題で大きい |
| 推論時の平均起動専門家数 | 2.00（固定） | 1.76 | 平均で12%少ない専門家を起動 |

動的方式は全課題で一様に優れているわけではない。ARC-eはTop-2より0.5ポイント低下し、PIQAは同点である。一方、BBHの2.3ポイント差が全体平均の改善へ大きく寄与する。論文は、難度の高い推論課題ほど専門家を多く割り当てるという仮説を支持するが、課題の難度と必要な専門家数の因果関係を独立した難度測定で立証したものではない。

### 起動数の内訳と入力難度

推論評価での平均起動専門家数は、PIQA 1.72、Winogrande 1.76、ARC-e 1.73、CommonsenseQA 1.74、BBH 1.87、全体平均1.76である。BBHでは複数段階の推論や論理的判断が必要になるため、確率分布がより多くの専門家を必要とする傾向が観察された。ここで表1のHellaSwagと表3のWinograndeは評価対象が一致しないため、二つの表を課題ごとに直接結び付けてはならない。

学習データ別の起動専門家数は、共通クロール1.82、C4 1.84、GitHub 1.88、Wikipedia 1.78、書籍1.73、arXiv 1.90、StackExchange 1.79で、全体平均1.82である。学習初期には多くの専門家を起動するが、600億トークン程度の学習後には平均2未満になるという学習過程の変化も報告される。推論評価平均1.76と学習データ平均1.82は測定分布が異なるため、単純な改善率として比較すべきではない。

### 閾値pの感度と層別の差

著者は学習済みチェックポイントのpを0.1〜0.7へ変えて評価し、pが0.1〜0.2と低すぎると専門家が不足して下流性能が明確に悪化する一方、一定の閾値を超えると得点が安定することを示した。主設定p=0.4は、起動専門家数と性能を両立する一つの設定であり、任意のモデルや層で最適であると主張していない。閾値の変更は選択専門家数だけでなく、確率重みの総和も変える可能性がある点に注意が必要である。

層別の分析では、下位の層ほど多くの専門家を必要とし、上位層では一つの専門家で済む傾向が報告される。これにより、層ごとに専門家数や実行資源を異なる形で割り当てる設計余地が示唆される。ただし、この観察は学習済みの対象モデルについての結果であり、現代の大規模混合専門家モデルの全系列で同じ層分布になると一般化する証拠はない。

## 既存研究との差

従来のTop-K方式は各トークンでK個を固定する。提案方式はTop-P型の累積確率によりKを入力依存にし、学習時にエントロピー罰則を与える点で異なる。単なるTop-P選択だけでなく、過剰な専門家起動を避ける損失を設計したことが重要である。また、負荷分散損失を残すことで、確率集中だけを目的とする方式ではないことが分かる。

推論実装の観点では、既存の専門家オフロード・専門家キャッシュ・専門家並列の最適化と直交し得る。起動専門家が少なくなれば重み転送回数を減らせる可能性はあるが、論文は階層メモリ上の実測オフロード削減や専門家キャッシュ命中率を検証していない。したがって、これらの効果は応用上の仮説として扱うべきである。

## 限界・再現上の注意

第一に、報告された主な効率性は平均起動専門家数・活性化パラメータ数に関するものであり、GPUでのトークン毎秒、初回トークン遅延、ピークメモリ、通信量の実測結果と同義ではない。第二に、対象モデルは全体約35億パラメータ、24層・16専門家であり、より大きなモデル、異なるルータ構造、専門家並列の分散配置へ直接外挿できない。第三に、動的損失と負荷分散損失を加えて学習しているため、固定Top-2の事前学習済みモデルに推論時の閾値を追加するだけで同じ性能を期待することはできない。

第四に、平均値が改善しても課題別にはARC-eで悪化が存在する。低閾値での過少起動も性能を損なう。第五に、表3は正解付き入力を使用して専門家数を測るため、生成中の誤りを含む自己回帰的な入力分布とは異なる。第六に、ルータ分布の確率校正や難度推定の正確性は独立に検証されていない。動的実行に伴うGPUカーネルの分岐、通信のばらつき、実際の負荷分散も実装検証が必要である。
