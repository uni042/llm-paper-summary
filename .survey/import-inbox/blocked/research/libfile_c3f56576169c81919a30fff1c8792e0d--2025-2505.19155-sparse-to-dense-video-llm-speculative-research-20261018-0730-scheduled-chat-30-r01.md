# Sparse-to-Dense：動画LLMの疎い下書きと密な検証による無損失投機的復号

## 概要

本論文は、長い動画を入力する動画大規模言語モデル（Video Large Language Model; Video-LLM）の**出力トークン生成段階**を高速化する。入力動画を多数の映像トークンへ展開すると、最初の入力処理（prefill）で作った鍵・値キャッシュ（Key–Value cache; KVキャッシュ）が巨大になる。通常の自己回帰復号では、出力トークンを1個作るたびに大量の映像KVを参照するため、演算量だけでなく高帯域メモリからの読み出しが支配的になる。論文は、例えばVILAで1時間の動画を5秒間隔で720フレームに分割すると141,120映像トークンになる例を挙げる。

提案する疎から密への復号（Sparse-to-Dense; StD）は、**元の重みを共有する2種類の注意計算**を組み合わせる。下書き時だけ重要な映像KVを少数選んだ疎注意を実行し、提案した複数トークンを元モデルの完全な密注意で一括検証する。下書き専用の別モデルを学習・保持しない。論文の評価では、Qwen2-VL-7B-InstructのMLVU動画理解ベンチマークで通常の密復号比**1.94倍**の壁時計時間（wall-clock time）高速化を報告する。LLaVA-OneVision-7Bでも複数の動画長にわたり1.59～1.83倍である。これは**動画理解タスクの正答率が1.94倍になったという意味ではない**。

著者は検証済みの出力を元の密モデルと同一に保つ「無損失」と説明する。実験表の「Acc.」は下書きトークンの受理率であり、動画質問応答の正答率ではない。実装と適用可能性を評価するときは、この区別が重要である。

## 問題設定と着想

動画LLMの入力は映像トークン数 $m_v$ と文章トークン数 $m_t$ の和からなり、長い動画では通常 $m_v\gg m_t$ となる。著者は映像トークンが1万を超える一方、文章トークンが100程度という状況を想定する。全KVを保持する元モデルの1トークン復号では、注意のために概ね $m_v+m_t$ に比例したKV読み出しが必要になる。従来のKV圧縮や量子化は読み出し量を減らすが、元モデルの生成結果を変えてしまう可能性がある。

そこで著者はQwen2-VL-7Bを用い、MLVUとVideoMMEから抽出した例で、映像KVを重要度上位のみに絞っても**単一の次トークン予測が平均95%以上一致**することを観察した。重要なのは「95%の系列全体が一致する」という主張ではない点である。独立性を仮定した概算でも5トークン連続一致は $0.95^5\approx0.77$ へ下がるため、疎注意だけで最終生成を置き換えると誤りが蓄積する。StDは疎注意を**候補生成のみに限定**し、元モデルの密注意で候補を逐次的に承認する。

この設計は従来の投機的復号（speculative decoding）と同じ「速い下書き→正規モデルで検証」という枠組みを使うが、別の小型Transformerや学習済み予測頭を用いず、**同一モデルのKV参照範囲を変えて下書き器を構成**する点が独自である。重みを二重保持しないため、長い映像入力で別モデルのメモリ費用を増やしたくない場合に適する。

## 手法

### 1. 入力事前充填時に文章から重要映像KVを選ぶ

入力事前充填段階で、各層 $l$ における文章トークン $\hat x\in X_t$ から映像トークン $x\in X_v$ への注意重み $A_l(\hat x,x)$ を観測する。映像トークンごとに文章側からの注意を平均し、その値が大きい上位 $K$ 個のKV位置を保存対象にする。論文の式は

$$\mathrm{Cache}_s[l]=\operatorname{argTopK}_{x\in X_v}\left(\frac{1}{m_t}\sum_{\hat x\in X_t}A_l(\hat x,x)\right).$$

と表される。つまり映像内で視覚的に目立つ領域を単純に抽出するのではなく、**実際の質問文に反応した映像位置**を選ぶ。これが固定窓だけを残すストリーミング型下書きとの違いである。選択位置は層ごと、鍵・値ヘッドごとに異なり得る。グループ化問い合わせ注意（Grouped Query Attention; GQA）では同じKVヘッドを共有する問い合わせヘッドの注意を加算して、共有KVヘッド単位で上位位置を決める。

選択は**事前充填段階で一度だけ**行い、復号の各トークンで重要位置を再計算しない。これにより毎ステップの選択処理が高速化の利益を食いつぶすことを避ける。一方、生成途中で質問の焦点が変わった場合でも選択位置は固定されるので、下書きの受理率が下がり得る。選ばれなかったKVを消去するわけではなく、密検証のため全KVは残す。

### 2. 同じ重みで疎い自己回帰下書きを行う

疎モデル $\mathcal M_s$ は元の密モデル $\mathcal M$ と**同一のモデルパラメータ**を用いる。異なるのは注意処理で参照するKV範囲だけであり、文章KVはすべて、映像KVは上記の上位 $K$ 位置だけを読み込む。疎モデルが次の $\gamma$ 個の候補トークンを1個ずつ自己回帰生成する。密モデルの巨大な映像KVを毎回読む代わりに、小さな部分集合を読むため、下書き1ステップのメモリ転送を削減できる。

疎モデルの予測は元モデルと必ずしも一致しない。しかし一致しやすい位置が多ければ、候補をまとめて検証することにより、元モデルをトークンごとに繰り返すより総読み出し量を減らせる。下書き側に追加の学習は不要で、著者は標準動画LLMから疎モデルを構成する変更量を約20行と述べる。ただしこれは特定の研究用実装における疎モデルへの変更量であり、あらゆる推論エンジンへの組込み工数を意味しない。

### 3. 密注意で並列検証し、不一致以降を棄却する

疎モデルが提案した $\gamma$ 個の候補列を、密モデルが元の全KVを使って**一度の並列検証**で照合する。先頭から一致する $n$ 個（$0\le n\le\gamma$）を採用し、最初に不一致が現れた位置では正規モデルが出したトークンを採用する。論文はこの正規トークンを追加のボーナストークンと呼ぶ。以降の不一致候補は棄却し、採用済みの列を文脈に追加して次の下書き・検証を繰り返す。

したがって疎注意の誤予測が最終列へそのまま伝播しない。ここでの無損失性は**正規モデルの検証規則に従って採用したトークン列が、元の復号規則と整合する**という意味である。論文はサンプリング温度を変えた場合の分布一致検定や全ての確率的復号設定での厳密な保証を別途報告していないため、任意のサンプリング設定への無条件の一般化は避ける。

### 4. 入出力転送量と受理率の損益分岐

論文の簡略化した転送モデルでは、疎下書き $\gamma$ ステップが $\gamma(K+m_t)$、密検証1回が $m_v+m_t$ のKVアクセスに相当する。受理率を $\alpha$ とすると、受理されたトークン当たりの平均転送量は

$$\frac{\gamma(K+m_t)+(m_v+m_t)}{\alpha\gamma}$$

と近似され、通常密復号の $m_v+m_t$ より小さくなる条件は

$$\alpha>\frac{K+m_t}{m_v+m_t}+\frac1\gamma$$

となる。**これは実測遅延の厳密な式ではない**。論文の近似ではボーナストークンやGPUカーネルの起動費用、計算・メモリ転送の重畳などを明示的にモデル化していない。それでも「疎モデルを速くするためKを減らし過ぎると受理率が下がる」「検証長を伸ばし過ぎると連続一致が難しくなる」という設計上のトレードオフを説明する。

| 密モデルの検証候補数 | $\gamma=9$ |
| 出力生成条件 | 思考過程を促すプロンプトで回答を生成 |
| 反復 | 異なる乱数シードで3回、平均を報告 |
| 指標 | 下書きトークンの受理率（Acc.）、通常密復号に対する実時間高速化倍率 |

## 主要結果と比較

下表の「受理率」は動画質問応答の正答率ではなく、**密モデルによる候補採用率**である。高速化倍率は通常の密な自己回帰復号を1倍とする。元モデルのタスク正答率をこの表の数字から逆算してはならない。

| モデル・評価集合 | 下書き方式 | 受理率 | 実時間高速化 |
|---|---|---:|---:|
| LLaVA-OneVision-7B / MLVU | StD | 47.8% | 1.72倍 |
| LLaVA-OneVision-7B / VideoMME短 | StD | 51.8% | 1.82倍 |
| LLaVA-OneVision-7B / VideoMME中 | StD | 52.1% | 1.83倍 |
| LLaVA-OneVision-7B / VideoMME長 | StD | 52.9% | 1.59倍 |
| Qwen2-VL-7B / MLVU | StD | 66.1% | **1.94倍** |
| Qwen2-VL-7B / VideoMME短 | StD | 71.8% | 1.71倍 |
| Qwen2-VL-7B / VideoMME中 | StD | 73.4% | 1.62倍 |
| Qwen2-VL-7B / VideoMME長 | StD | 81.8% | 1.70倍 |

比較対象との違いを具体的に見ると、LLaVA-OneVision-7BのMLVUで、学習なしLayerSkipは受理率10.0%・0.47倍（**通常復号より低速**）、Streamingは34.7%・1.34倍、StDは47.8%・1.72倍である。Qwen2-VL-7BのMLVUでは、LayerSkipが5.2%・0.63倍、Streamingが53.9%・1.61倍、StDが66.1%・1.94倍となる。LayerSkipは下書き自体が軽くても正規モデルとの予測分布の差が大きく、検証が頻発して利益を失う。Streamingは疎注意で一定の高速化を得るが、質問文に基づく映像位置選択のStDの方が受理率を高められる。

著者は全評価設定での平均高速化を約1.74倍、平均受理率に相当する値を約62.2%と記載する。平均値はモデル・動画長ごとの値をまとめた指標であり、どの個別条件でも同じ倍率が得られるという意味ではない。また、動画の**入力事前充填そのもの**の高速化ではなく、主として出力復号段階の壁時計時間の改善を評価している。

## 感度・構成要素の検証

付録Cでは、下書き長 $\gamma$ と疎KVの選択数 $K$ を変えた場合の挙動を調べる。$\gamma$ を大きくすると、密検証1回の費用をより多くの採用トークンへ分散できるため、初めは高速化倍率が改善する。しかし**$\gamma=13$ に達すると倍率が低下**し、長い連続候補が一致しなくなる損失が上回る。本文の固定値 $\gamma=9$ は、この相反する効果のバランスを取る設定である。

$K$ が小さ過ぎると疎モデルが必要な映像情報を失い、候補受理率が下がる。逆に $K$ を大きくし過ぎると疎下書き自体が密モデルへ近づき、KV読み出し削減が減る。したがって「少数のKVだけを読むほど必ず速い」わけではない。論文の選択方法は、映像KVを保持したまま、下書き時に読む位置だけを変えることで、この品質と読み出し量のバランスを制御する。

## 既存研究との差と実装上の含意

従来の投機的復号では、別の小型言語モデル、専用予測頭、層の途中で出力する早期終了モデルなどを下書き器として用いることが多い。これらは追加学習、追加重み、またはターゲットとの予測ずれを伴う。StDは**同じモデルを疎注意と密注意で2回使い分ける**ため、別の学習済み下書き器の重みは必要ない。しかも下書きKVを文章注意に基づいて選ぶ点で、固定の最近傍ウィンドウを残すStreaming型下書きと異なる。

この方式は映像トークンが圧倒的に多い場合に理にかなうが、テキストのみの短文脈推論に同じ倍率を期待する根拠はない。実装側では事前充填中の文章→映像注意重みの取得、層・KVヘッド別の上位位置管理、疎下書きと密検証のKV整合、棄却した候補のキャッシュ処理が必要になる。原著の「約20行で疎モデルへ変換」という表現を、全推論基盤での完全な統合が20行で済むという意味に拡大してはいけない。

## 限界・負の結果

第一に、**全KVキャッシュはGPUの高帯域メモリに保持する**。疎注意は下書きの読み出しを減らすが、密検証に全KVが必要なため、モデルを載せるためのKV容量そのものは基本的に削減しない。論文もGPUメモリ容量によるバッチサイズ制限を明示し、CPUメモリへの退避を将来課題としている。GPUメモリが足りない環境では、先にオフロードや量子化など別の仕組みが必要になる。

第二に、事前充填で選択した重要映像KVは復号中に更新しないため、文章の問いから推測できなかった映像位置が後で重要になると、下書き受理率が落ちる可能性がある。もっとも密検証があるため、採用規則を守る限り下書きの不一致を最終出力へ無検証で流すことはない。第三に、$K$ と $\gamma$ の設定に速度上の最適点があり、極端な設定では利益が失われる。LayerSkip比較で通常復号より遅い結果が実際に存在することからも、投機的復号一般が常に高速になるわけではない。

第四に、実測はA100 80GB、7B級動画LLM、MLVU/VideoMME、バッチ8に限定される。12GB級GPU、CPUオフロード、他のGPUアーキテクチャ、動画以外のLLM、非常に短い生成、異なるバッチ、確率的サンプリングの分布保存について同等の高速化は検証されていない。論文は下書き受理率と壁時計時間を主に報告しており、電力、詳細なメモリ帯域利用率、完全な端から端のサービス水準目標への影響を測ったものではない。
