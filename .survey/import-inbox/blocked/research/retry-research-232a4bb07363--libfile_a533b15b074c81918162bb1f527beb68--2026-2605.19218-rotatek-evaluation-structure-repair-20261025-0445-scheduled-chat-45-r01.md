# RotateK：回転整列による視覚KVキーのチャネル枝刈り

## 概要
視覚言語モデルは一枚の画像を多数の視覚トークンへ変換するため、入力が長い場合にKVキャッシュが膨らむ。従来は重要度の低い視覚トークンを丸ごと削除する方式が多いが、文書の小さな文字や画像全体に散らばる情報を必要とする質問では、削除した位置の証拠を復元できない。RotateKはトークン数だけでなくキーの特徴チャネル数を削る。入力ごとにオンライン主成分分析（PCA）で座標軸を回転し、トークンによって異なる重要チャネルを共通の少数軸へ寄せ、ヘッド単位の構造化マスクで圧縮する。さらにTriton製の融合注意カーネルが圧縮キーを元次元へ復元せず直接処理するため、容量削減を復号の実速度に結び付ける。

## 問題設定
KVキャッシュ容量は、おおむねトークン数N、注意ヘッド数、キー・バリューの次元d、精度に比例する。トークン枝刈りはNを減らし、チャネル枝刈りはdを減らす。固定容量でNを極端に小さくするより、Nを多めに残してdを適切に削った方が、広範な画像証拠を保存できる場合がある。しかしチャネルの重要度は視覚トークンごとに異なる。トークンごとに別々のチャネルを選ぶ非構造化方式は品質上は柔軟でも、GPUのメモリ配置が不規則になり、マスクやインデックスの管理が重い。ヘッドごとに共通のチャネルを選ぶ構造化方式は実装しやすいが、重要な情報が別々の軸へ分散していると品質を落とす。

もう一つの落とし穴は「圧縮してから元に戻す」ことにある。既存のThinKやSparKは圧縮キーを復号時にフル次元へ再構成し、通常のFlashAttentionへ渡す実装がある。この場合、KVを小さく保存できても、毎ステップの再構成・連結・メモリ転送が追加される。したがって圧縮率だけでなく、圧縮表現をそのまま計算できる注意カーネルが必要になる。

## 手法
### 1. 直交回転で情報を失わず座標を揃える
入力は事前入力処理（prefill）終了時の視覚キー行列K（N×d）と各ヘッドの特徴統計である。直交行列Rを用いてキーKと将来のクエリqを同じ座標へ回転すると、すべてのd次元を残す限り内積qKの転置は厳密に保存される。つまり回転自体は圧縮ではない。PCAで分散が大きい方向を前方の軸へ集めると、少数の軸だけを残したときに重要情報を保存しやすくなる。圧縮は上位k軸だけを残す段階で初めて近似を導入する。出力は視覚キーのN×k行列と回転情報である。

### 2. クエリ重み付き主成分分析
単純なキー分散だけでは、実際のクエリが強く利用する方向と一致しない場合がある。RotateKはクエリ側の重みを共分散行列に反映し、注意スコアへの影響が大きい軸を優先する。共分散Cへクエリ由来の対角重みを適用する追加計算はヘッド次元dに関するO(d²)で、長い文脈Nに直接比例しない。回転行列は各ヘッドのprefill後に一度求め、その後の各復号ステップで再利用する。したがってオンラインといっても、毎トークン完全な固有値分解を繰り返すわけではない。

### 3. Choleskyによる部分空間反復
フル固有値分解は理論上の演算数だけでは軽さを判断できず、細かなGPUカーネル起動が積み重なる。RotateKは必要な上位k次元だけを、共分散行列との積とCholesky-QR正規直交化を繰り返して推定する。原著では5回の反復でフル分解と同程度の精度を得たとする。形状が固定された演算列をCUDAグラフでまとめやすく、起動遅延を抑える。近似的な主成分推定であるため、極端な固有値分布や少ない反復回数では精度と前処理時間の交換条件が生じる。

### 4. 復元不要の融合注意
復号時のクエリを保存済みの回転基底へ写像し、視覚トークンについてはk次元キーと内積を取る。テキストや圧縮対象外のトークンには元のd次元注意を使い、二つの経路の部分注意を融合する。Triton製カーネルは疎チャネルのキーをフル次元へ復元しないため、再構成・連結のメモリ入出力を省ける。回転行列の保存やクエリ変換は追加費用だが、ヘッド単位の構造化マスクでトークンごとの大きなマスクを持たない。

## 評価

### 評価条件
| 項目 | 条件 |
|---|---|
| モデル | LLaVA-NeXT-8B、Qwen2.5-VL-7B-Instruct |
| ベンチマーク | TextVQA、InfoVQA、DocVQA、ChartQA、VizWiz、LLaVA-in-the-Wild、MM-Vet |
| トークン枝刈り | FastV、VisionZipにRotateKを組み合わせる |
| チャネル比較 | ThinK（構造化）、SparK（トークン別非構造化） |
| 容量比較 | 同じKVキャッシュ予算になるようトークン・チャネル残存率を調整 |
| 実行性能 | TritonのFlashAttention実装と疎チャネル融合注意カーネルを同条件で比較 |
| 留意点 | 視覚キーのチャネル枝刈りが主題であり、全KVを同率で削るわけではない |

### 評価結果
| モデル・条件 | 比較対象 | RotateK | 意味 |
|---|---:|---:|---|
| Qwen2.5-VL-7B、FastVと同容量、InfoVQA | FastVのみ52.76 | FastV+RotateK 65.79 | 視覚トークン保持を増やす効果 |
| Qwen2.5-VL-7B、FastVと同容量、DocVQA | FastVのみ67.44 | FastV+RotateK 77.40 | 文書中の細部を残す |
| Qwen2.5-VL-7B、FastVと同容量、ChartQA | FastVのみ75.04 | FastV+RotateK 87.28 | 表・図の情報保持 |
| Qwen2.5-VL-7B、VisionZipと同容量、InfoVQA | VisionZipのみ58.46 | VisionZip+RotateK 70.51 | 別のトークン枝刈りとも補完的 |
| LLaVA-NeXT-8B、FastV併用、LLaVA-Wild | ThinK 80.40 | RotateK 85.50 | 同条件のチャネル枝刈りより高い |
| LLaVA-NeXT-8B、VisionZip併用、MM-Vet | ThinK 23.72 | RotateK 26.97 | 長めの自由生成でも品質改善 |
| Qwen2.5-VL-7B、VisionZip併用、MM-Vet | ThinK 35.00 | RotateK 44.04 | ベースライン45.55に近づく |
| 既存チャネル枝刈りの復号遅延 | フルチャネル注意 | ThinK/SparKで最大約1.8倍遅い条件 | 復元費用が圧縮利益を打ち消す |

固定KV予算で比較した40ケースのうち、ThinKがRotateKを上回ったのは5ケースで、その差は0.6%未満と原著は報告する。これは構造化マスクでも、回転によってトークンごとの重要方向を共通化すれば精度を維持しやすいことを示す。高いチャネル疎性ではSparKが一部条件でやや高精度になることもあり、RotateKの優越がすべての条件で成立するわけではない。

prefillではオンラインPCAの費用が発生するが、部分空間反復を使う実装では既存の圧縮方式と同程度の遅延に収まると報告する。復号ではThinK/SparKがフルキー再構成のため通常注意より遅くなる条件がある一方、RotateKは疎チャネル直接注意でその費用を避ける。これらは論文の特定のVLM・入力長・GPU実装での結果であり、他のハードウェアの絶対速度は別途測定が必要である。

## 限界と既存研究との差
FastVやVisionZipはトークン軸、ThinKやSparKは特徴軸を削る。RotateKは特徴軸の構造化削減をオンライン回転と組み合わせ、トークン軸の削減と共存させる。キー側だけを縮める設計であるため、バリューや重みが支配的な状況では全体メモリ削減率が小さくなる。入力ごとの主成分推定、回転行列の保持、カーネルの専用実装が必要であり、既存の汎用注意カーネルへそのまま差し込むだけでは速度利得は得られない。視覚質問応答での品質改善は確認できるが、超長文脈の純テキストLLMや多数同時要求のサービングで同じ利得が出るとはまだ断定できない。


### 注意カーネルと圧縮率の解釈
RotateKが特徴次元をk/dへ減らすと、視覚キー行列の保存量は原理的に小さくなる。しかし実際のKVキャッシュには、バリュー、テキストトークン、圧縮対象外の状態、回転行列も含まれる。論文の固定容量比較では、FastVやVisionZipで残す視覚トークン数と、RotateKで残すキーのチャネル数を組み合わせ、同じメモリ予算でどちらが質問応答精度を保てるかを測る。表の「0.25×」のような値はキー・トークンの各残存率を区別して読む必要があり、すべてのKV状態を4分の1にしたと読み替えてはいけない。

RotateKの実装上の要点は、圧縮されたキーを再構成して汎用注意へ戻さないことである。ThinKやSparKは保存量を減らしても、復号時のフル次元キー復元と連結が増えるため、条件によっては通常注意より遅くなる。RotateKでは疎チャネルと通常チャネルの二つの注意結果を融合する専用カーネルが必要で、圧縮状態を直接読み出す。主成分推定にも費用がかかるが、フル固有値分解の多数の細かなカーネル起動を、形状が揃った部分空間反復へ置き換えることで前処理を軽くする。推論の各段階を分けて評価することで初めて、前処理の追加費用を復号の節約が上回るか判断できる。
