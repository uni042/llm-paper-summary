# PatchKV: Efficient KV Cache Recovery for Dynamically Edited LLM Contexts

## 概要
長時間動くLLM agentではtool resultやメモリを文脈中央へ差し替えつつ、その後ろの長いsuffixはトークン列として同じまま残ることがある。しかし接頭辞が変わるとsuffix 隠れ 状態の因果履歴も変わり、編集長が変われば回転位置埋め込み（Rotary Position Embedding; RoPE）の位置もずれる。したがってトークン IDが同じでも古いKVをそのまま再利用できない。

PatchKVは隣接する文脈 versionをexact 接頭辞、edited span、aligned suffixへ分解し、suffixのうち実際に再計算すべきブロックだけをrepairする。残りはCPU DRAMへ退避していたKVをmixed precisionで復元し、dequantization、RoPE補正、paged KV配置を融合する。

## 問題設定
全体 suffix recomputationは正確だが長いプリフィルをやり直す。Direct KV Reuseは速いがstale causal 状態を伝播する。CacheBlend等の選択的再計算は改善するが、編集位置からのdriftと遠距離の重要トークンを同時に扱い、CPU転送量も抑える余地がある。

## 手法
### Dirty region予測
offlineで編集前後をpaired プリフィルし、suffix距離と状態 driftの関係をモデル別にprofileする。ランタイムでは編集長等から局所dirty boundaryを予測し、編集直後の高drift領域を必ずrepair setへ入れる。

### 非局所attention block
局所driftだけでは遠方のinstructionやretrieved factを落とすため、保存済み注意機構 statisticsから高影響ブロックを少量追加する。repair setはpaged executionへ合わせてブロック boundaryへ丸める。既定ブロック サイズは32 トークン。

### Mixed-precision restore
repairしないsuffix ブロックには保存時に固定したFP16、K8/V8、K8/V4等のprecision tagを使う。fused restore pathでdequantization、position shiftに伴うkeyのRoPE correction、KV-page 配置をまとめる。valueは位置だけでは補正できず、causal content差が大きいブロックはrepair側へ回す。

## 評価条件
| 項目 | 条件 |
|---|---|
| モデル | Qwen3-32B、GLM-4-9B、Llama-3.3-70B |
| ワークロード | HotpotQA-E、2WikiMQA-E、TriviaQA-E |
| ハードウェア | 8×NVIDIA A800 |
| software | PyTorch 2.7、Transformers 5.3、Accelerate 1.14 |
| オフロード | CPU DRAM |
| 比較対象 | 全体 suffix recomputation、Direct KV Reuse、CacheBlend |
| 指標 | resume TTFT、F1、CPU transfer量 |

## 主要結果
全体 suffix recomputationに対するmean resume time-to-first-トークン（TTFT）高速化は2.51〜3.85倍、CacheBlend比では1.26〜2.06倍。9設定中6設定でCacheBlend以上のF1、残り3設定も1.36 point以内に収まる。

mixed-precision transportはFP16 restore比でmean resume TTFTを15.0%短縮し、F1低下は0.35 point。INT8比でも5.6%高速でF1差0.05 point以内。一方uniform INT4はさらに3.5〜3.7%速いがF1を1.15 point失う。

8K-トークン KV チェックポイントの例ではFP16が2007.8 MiB・344.4 msなのに対しPatchKV policyは799.4 MiB・158.0 ms。Qwen3-32B 10K 文脈で注意機構 プロファイリングは122.9〜125.2 ms、resume時repair-set constructionは2.62〜3.30 msである。

## 既存研究との差
接頭辞 キャッシュは中央編集後のsuffixを再利用できない。CacheBlendは層 drift等で部分再計算するのに対し、PatchKVは「編集近傍のvalidity repair」と「遠距離のgeneration influence」を分け、さらにunrepaired ブロックのtransport precisionまで共同設計する。

## 限界
dirty-regionの遷移距離はモデル依存で、モデル-specific offline calibrationが必要である。prototypeのオフロード 階層はCPU DRAMであり、NVMe/CXL等の階層では転送と融合カーネルの最適点が変わる。保存注意機構 statisticsも追加metadataを必要とする。注意機構 fractionやブロック サイズを増やせば品質が単調に上がるわけではなく、ワークロードごとのtrade-offが残る。
