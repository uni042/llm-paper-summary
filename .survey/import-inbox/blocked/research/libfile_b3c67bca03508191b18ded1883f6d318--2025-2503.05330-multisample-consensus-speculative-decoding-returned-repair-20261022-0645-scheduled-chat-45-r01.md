# 複数推論系列の合意を使った投機的復号：追加モデルなしのドラフト生成

## 概要

*Speculative Decoding for Multi-Sample Inference*は、数学的推論でよく使う**自己整合性（self-consistency）**や**Best-of-N標本化**において、同じ大規模言語モデル（LLM）から並列生成している複数の回答候補を、互いの**投機的復号（speculative decoding）**のドラフト供給源として利用する方式である。通常の投機的復号は、別の小型モデルや過去のテキストを格納した検索データベースから先行トークンを提案し、元の大きなモデルで一括検証する。しかし複数回答を同時に生成しているなら、別経路の途中にすでに出現した計算式や説明文の続きが、現在の経路にも役立つ可能性がある。

著者らは、並列経路の接尾辞を他経路の部分列と照合してドラフト候補を集め、表記揺れを許す曖昧照合を行い、重複したトークン遷移を**有向非巡回グラフ（directed acyclic graph、DAG）**へまとめる。モデルが付与した生成確率と経路間の出現頻度を組み合わせて、最も合意の強いドラフトを選ぶ。提案ドラフトは元モデルの検証で受理される範囲だけ利用し、棄却後の部分は通常の生成に戻る。

GSM8KとMATH、Qwen2.5-7B-InstructとLlama-3-8B-Instructの比較では、ドラフト長6での平均受理長がRESTやEAGLE-2より長かった。一方、原著は**バッチサイズ1を超える多系列生成を同条件で最適化した実測総速度**を示していない。評価の中心はドラフト受理長と構築費用であり、推論全体の高速化倍率やGPU利用率を推測して補ってはならない。

## 問題設定：多数の推論候補を作ると生成費用が増える

自己整合性は、同じ問いに対して複数の推論経路を生成し、最終回答の多数決で誤りを減らす。Best-of-Nは複数候補を評価関数で順位付けして最良候補を選ぶ。いずれも単一回答より多くのトークンを生成するため、生成費用は候補数と出力長に大きく依存する。推論の正答率を高めるために標本数を増やすほど、遅延・計算量・GPUメモリが増えるという問題がある。

従来の投機的復号では、提案モデル$q$が次の数トークンを先行生成し、目標モデル$p_\theta$が複数位置をまとめて検証する。提案が目標モデルの出力と一致するほど、少ない検証回数で多くのトークンを進められる。ただし提案モデルの学習・推論にも費用が必要で、外部データベースの検索では現在の数学的推論と異なる分布から候補を引く場合がある。RESTは検索型、EAGLE-2は小型の学習済みドラフト生成器を用いる代表的な比較方式である。

複数の推論経路は、同じモデルが同じ問いに対して出力した系列であり、途中の算術式、論理接続、定型表現を共有し得る。著者はこの**経路間の重複**を外部資源の代わりに利用する。ただし、別経路に出現したというだけで現在の条件付き分布に必ず一致するわけではない。文脈が異なれば同じ接尾辞の続きが不適切になる可能性があるため、最終的な目標モデルの検証が不可欠である。

## 手法

### 1. 並列系列から動的ドラフト候補を収集する

同じ問いについて$N$本の推論経路$y_1,\ldots,y_N$を同時生成する。ある経路$i$が時刻$t$まで生成した末尾$k$トークンを照会文字列とし、他経路$j\ne i$の過去部分列から一致する接尾辞を探す。照合した位置の直後に続いていたトークン列を、現在の経路のドラフト候補として集める。つまり、検索対象は外部の学習コーパスではなく、**今まさに同じモデルが生成中の他経路の履歴**である。

例えば別経路が「両辺を2で割ると、x=5」と生成済みで、現在の経路が「両辺を2で割ると」まで進んでいれば、続きの「x=5」を候補にできる。ただし文字列一致だけでは表記差や同じ意味の別表現を見逃すため、次の曖昧照合を加える。候補が多いほど探索費用が増えるので、外部検索が不要でも候補管理が無料になるわけではない。

### 2. 曖昧な接尾辞一致で表記差を許容する

数学的な途中式は「x²」と「x^2」のように表記が違っても同じ意味を表す場合がある。著者は編集距離$\delta(s,s')$が許容値$\epsilon$以下なら照合可能とする。厳密な一致より多くのドラフト候補を拾える一方、意味が異なるが文字列として近い部分も含まれ得る。曖昧照合は意味同値性の証明ではなく、**候補の取りこぼしを減らすための近似**である。

評価では$\epsilon=1$に設定している。許容距離を大きくすると候補は増えるが、誤った候補も増えて受理率が下がる可能性がある。特定の数学問題での設定を、自然言語全般やコード生成に無条件に適用できるとは限らない。

### 3. 候補を確率重み付きDAGへまとめる

候補列を単純に列挙すると、共通する演算子や語句が何度も現れ、同じ接頭部分を重複保存する。提案方式はドラフトの各深さを層とするDAGを作り、同じ深さに現れる同一トークンを一つの節点に統合する。節点間の有向辺はトークン遷移を表し、異なる推論経路で共有された遷移は合意の強さとして集計される。

辺の重みは、元モデルの生成確率に由来する項と、同じ遷移が候補内に出現した頻度を組み合わせる。原著の式は$w(u,v)=\alpha\sum_i p_\theta(v_i\mid u_i)+(1-\alpha)\mathrm{Freq}(u\to v)$である。各層では流入辺の重みが大きい節点を貪欲に選び、最大ドラフト長または終端まで進む。これは最長共通部分列を一つ選ぶだけでなく、**複数候補の遷移頻度とモデル確率を合わせた合意系列**を構成する手続きである。

DAGは共通トークンをまとめられるため、候補を別々の木で保持するより冗長性を減らし、分岐した経路から同じ後続部分を再利用できる。ただし貪欲探索は一般の最適経路探索を厳密に保証するものではなく、辺重みの定義・候補数・文脈依存の条件で選択結果が変わる。原著の比較ではDAGが木や単純なリストより受理長で有利だった。

### 4. 元モデルでドラフトを検証し、棄却後は通常生成する

得られたドラフトは、目標モデルが現在の文脈で生成するトークンと順に比較する。先頭から一致した最長部分だけを受理し、不一致以降は棄却する。検証には元の目標モデルを使うため、他経路に似た続きがあっても無条件には採用しない。原著は、採用される出力系列が通常の自己回帰生成の分布に従うことを目的とした受理規則を採用している。

ここで重要なのは、**提案分布が目標分布と同じだから必ず受理されるわけではない**点である。同じLLMの別経路でも文脈が違えば条件付き確率が異なる。正しい分布を保つ役割は、DAGの合意重みではなく最終的な検証手続きにある。受理長が長くても、検証の並列化効率や複数経路のスケジューリングによっては実時間短縮が小さくなる可能性がある。

### 5. 一要求内の処理フローと計算資源

入力は一つの問題と$N$本の並列生成状態である。各経路で新しいトークンが増えるたびに、現在の接尾辞を他経路履歴と照合して候補を集め、曖昧照合とDAG集約で長さ$L$以下のドラフトを選ぶ。目標モデルがドラフトを検証し、受理した位置だけ生成を進める。この処理は外部の小型ドラフトモデルや事前構築した検索データベースを必要としないが、経路履歴の保存、照合、DAG構築、候補確率の集約が追加される。

並列経路が少なければ候補の多様性が足りず、経路が多過ぎれば照合・グラフ構築費用が増える。単一GPU上でバッチ処理と検証を効率的に組み合わせる必要があり、著者はバッチ最適化済みの投機的復号方式との統合を未実施と認める。したがってこの研究は「外部ドラフト資源を削除した受理長の改善」であり、「どんなバッチ数でもエンドツーエンドの速度が何倍」と確定した方式ではない。

## 評価

### モデル、課題、比較条件

| 項目 | 原著の条件 |
|---|---|
| GPU | NVIDIA A100を1基 |
| モデル | Qwen2.5-7B-Instruct、Llama-3-8B-Instruct |
| 数学的推論課題 | GSM8K、MATH |
| 比較対象 | REST（外部データベース）、EAGLE-2（学習済みドラフトモデル） |
| RESTのデータ | NuminaMath-CoTから検索データベースを構築 |
| ドラフト長 | 1、2、3、4、6トークン |
| 曖昧照合 | 編集距離許容値$\epsilon=1$ |
| 合意重み | $\alpha=1$ |
| 主指標 | 一回の検証で平均何トークンを受理するか（accept length）、ドラフト構築時間 |

原著は、RESTとEAGLE-2が複数経路の同時生成に合わせて推論時間を最適化していないため、バッチサイズ1を超える条件での総推論時間を主たる比較指標にしていない。これは単なる報告漏れではなく、**評価指標の比較可能性の制限**である。したがって、受理長の増加をそのままGPU処理量の倍率として引用してはならない。

### 受理長の定量比較

原著表1のドラフト長6における平均受理長を示す。数値は受理されたドラフトトークン数の平均であり、最終回答の正答率ではない。

| モデル・課題 | REST | EAGLE-2 | 提案方式 |
|---|---:|---:|---:|
| Qwen2.5-7B / GSM8K | 0.56 | 0.97 | **1.53** |
| Qwen2.5-7B / MATH | 0.77 | 0.98 | **1.89** |
| Llama-3-8B / GSM8K | 0.52 | 1.71 | **2.17** |
| Llama-3-8B / MATH | 0.57 | 1.48 | **2.95** |

Llama-3-8BのMATHではEAGLE-2比で2.95/1.48≈1.99倍の受理長となるが、これは**受理長の比**であり生成速度2倍の実測ではない。ドラフト長が短い場合には必ずしも最良でなく、Llama-3-8BのGSM8Kでドラフト長1の受理長は提案0.66、EAGLE-2は0.70である。ドラフト長2でも両者1.12と同値であり、提案方式がすべての設定で勝つわけではない。

Qwen2.5-7BのGSM8Kではドラフト長6/4/3/2/1の提案受理長が1.53/1.46/1.35/1.12/0.71で、RESTは0.56/0.49/0.41/0.25/0.06だった。長いドラフトほど共有部分の合意から得られる利益が大きい一方、生成経路の多様性と一致の頻度に左右される。

### ドラフト構築時間と測定の限界

原著図1はQwen2.5-7BのGSM8Kで、受理長に対するドラフト構築時間を比較する。EAGLE-2は別のモデルによるGPU推論を必要とするため構築費用が高く、RESTは大きなデータベースの検索費用がかかる。提案方式は生成中の他経路だけを検索するため、比較した条件では構築時間が短い。ただし図1から、すべてのGPU・経路数で同じ絶対ミリ秒が得られるとは言えない。

全体推論時間は、候補構築、DAG探索、元モデルの並列検証、複数経路のバッチ形成、KVキャッシュの保持などを含む。論文の評価は、これらを統一したサーバ上で全方式を同条件に最適化して測定したものではない。特に大量の並列経路では候補の照合とDAG更新が増えるため、構築時間の利点が縮む可能性がある。

### 構成要素と感度

原著の構成要素比較では、候補の表現にDAGを使う方式が木やリストより受理長が長く、曖昧照合を取り除くと受理長が下がった。これは、経路間の部分一致を統合する表現と、表記揺れを拾う探索の双方が貢献することを示す。ただし曖昧照合は意味的な同値判定ではなく、検証で棄却される候補も増え得る。

サンプリング温度の感度では、低温で生成経路が似過ぎるとドラフト候補の種類が不足し、高温で経路が散らばり過ぎると接尾辞一致が減る。中程度の温度で受理長が最大になる傾向を示す。並列標本数を増やすと候補プールが豊富になり受理長が伸びるが、標本数の増加は元モデルの生成費用も増やす。したがって受理長だけを見て標本数を無制限に増やすことはできない。

## 既存研究との差

RESTは外部データベースの文章からドラフトを探すため、現在のモデルが生成しやすい表現と分布がずれる場合がある。EAGLE-2は目標モデルの内部状態を利用する小型ドラフトモデルを学習し、ドラフトを生成するために追加推論を行う。提案方式は、**すでに生成することが決まっている並列推論経路**から候補を得るため、追加モデルと外部データベースを不要にする。

自己整合性やBest-of-Nの最終回答選択規則を置き換えるのではなく、候補回答を生成する過程を効率化する点が重要である。候補数や最終投票方式の正答率改善は別問題であり、論文が示すのは主にドラフトの受理効率である。一般の一回答生成では、利用できる他経路がないため同じ手法をそのまま適用できない。

## 限界・未評価事項

第一に、複数経路を効率的に同時検証するバッチ最適化済みの投機的復号との統合が未実施で、エンドツーエンドの生成速度倍率を直接確定できない。第二に、経路数が増えると曖昧照合とDAG構築の費用が増え、受理長の利点が総遅延の利点へ変換されない場合がある。第三に、数学的推論以外の自由記述、コード生成、多言語生成などへの一般化は検証されていない。

第四に、異なる推論経路の接尾辞が似ていても、その後続が現在の条件付き分布で高確率とは限らない。受理検査の正しさとドラフト提案の精度は分けて考える必要がある。第五に、温度や候補数によって一致頻度が変わるため、最適な探索設定はモデルとタスクに依存する。第六に、公式公開実装URLは一次論文から確認できず、実装を再現する際にはトークン履歴の保持、照合の高速化、グラフ更新、検証バッチの構成を別途設計する必要がある。
