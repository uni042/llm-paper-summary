# Self-Indexing Attention for Compression-Compatible Sparse Long-Context LLM Inference

> 1ビット符号索引をプリフィル・デコード・KV圧縮で共有し、検索用の別メタデータを持たない。注意演算単体の速度とハイブリッドモデル全体の速度を分けて評価する。

## 概要

長文脈の大規模言語モデル推論では、プロンプトをまとめて処理するプリフィルと、1トークンずつ生成するデコードで注意の計算形態が異なる。プリフィルでは大量の問い合わせに対する鍵検索の費用が大きく、デコードでは長くなるKVキャッシュから毎ステップ候補を取り出す費用が増える。従来の疎注意は両段階に別の索引を使いがちで、さらにKVキャッシュを低ビット圧縮すると索引用の高精度表現や補助メタデータがメモリ節約を食い戻す。

自己索引注意は、回転位置埋め込み後の問い合わせと鍵を共通のランダム化Hadamard変換へ通し、変換後の鍵の符号を各次元1ビットで保持する。この符号列は検索用索引であると同時に、圧縮鍵の符号成分そのものである。残る絶対値と値ベクトルはTurboQuantなどの外部量子化器へ渡せるため、独立した学習済み索引器を追加する必要がない。

検索時には符号の一致数を数え、偶然一致の基準を引いて鍵ノルムで重み付けし、候補を順位付けする。プリフィルでは複数の問い合わせを絶対値最大符号プーリングでまとめ、デコードでは同じKVヘッドを共有する問い合わせヘッドの符号をまとめる。どちらも最後は選択した実KVに対して各問い合わせの正確なスコアを計算する。

Qwen3.6-35B-A3BとQwen3.5-9BのLongBench・RULERで、約5%の注意密度でも密注意に近い品質を報告する。注意演算単体の高速化はプリフィルで8Kの3.7倍から64Kの6.1倍へ、デコードで64K・バッチ8の10.3倍に達する。一方、64K・バッチ4のモデル全体では初回トークン時間1.35倍、定常デコードスループット1.23倍の改善であり、演算単体の倍率とは大きく異なる。

## 問題設定と理論上の位置付け

検索用索引を低ビット化すると、検索に必要な方向情報とKV量子化に必要な大きさ情報の扱いが衝突する。単に鍵を圧縮すると内積の近似誤差が増え、別の検索器を保持すれば索引の容量が増える。自己索引注意は、変換後の鍵を符号と大きさへ分け、符号を正確に保持する一方で大きさだけを量子化できる構成を選ぶ。符号が1ビット反転するだけでも一致数と離散的な上位候補集合が変わるため、符号の非可逆圧縮は避ける。

直交変換Rを問い合わせと鍵へ同じように適用すれば、内積は保存される。論文は層とKVヘッドごとにランダム符号対角行列Dと正規化Hadamard行列Hを組み合わせ、`R = D H / sqrt(d)` を使う。変換された座標の相関が元のコサイン類似度に対応することが、符号一致を検索の代理値とする動機である。ただし、構造化Hadamard変換の座標は独立ではない。論文は完全ランダム超平面の局所性鋭敏ハッシュと同じ厳密な衝突確率保証があるとは主張せず、検索品質を実験で検証する。

符号一致だけでは鍵の大きさを区別できない。角度が同じでもノルムの大きい鍵は注意スコアに強く寄与するため、検索順位へ鍵ノルムを掛ける。ノルムは圧縮処理でも使うため、追加の検索専用メタデータを設けずにこの補正を行える。

## 手法

### 1. 共有変換と符号索引の構築

各層・KVヘッドに固定のランダム化Hadamard変換を割り当てる。回転位置埋め込みを適用した鍵を変換し、各座標の正負をビットパックしてKVキャッシュへ保存する。同じKVヘッドを参照する問い合わせヘッドは、同じ変換を使う。新しい鍵がキャッシュへ追加される際に一度変換すれば、その後のデコードで同じ符号列を何度でも検索できる。

検索では問い合わせと鍵の符号が一致する次元数 `a(u,i)` をビット演算で数える。次元数dの半分程度は無関係な符号列でも偶然一致するため、論文は閾値 `tau=d/2` を引き、`max(a(u,i)-tau,0) × ||k_i R||_2` を順位付けに使う。これにより偶然一致の基準を除き、符号だけでは失われた鍵の大きさを補う。最終的な疎注意には、上位候補に加えて先頭の固定トークンと直近の窓を強制的に含める。

### 2. プリフィルの絶対値最大符号プーリング

プリフィルの各問い合わせ行に独立した候補検索を実行すると、選択器自体が大量の計算を消費する。そこで同じKVヘッドを共有する問い合わせをまとめ、既定で64個の問い合わせベクトルを一群とする。グループ問い合わせ注意（Grouped-Query Attention; GQA）の問い合わせヘッドを先にまとめ、次に近いトークン位置をまとめるので、異なるKVヘッドの鍵索引を混在させない。

平均ベクトルを作ってから符号を取ると、正負が打ち消されて重要な問い合わせの情報が失われる。絶対値最大符号プーリングでは、各座標で絶対値が最も大きい問い合わせの符号を採用する。これは「グループ内のどれか一つの問い合わせに重要な鍵」を残すための保守的な代理値である。群で長距離候補を共有しても、実際の注意計算に入る前に各問い合わせ行の因果境界で候補を再フィルタし、未来の鍵を読まないようにする。

### 3. デコードのヘッド共有検索

デコードでは現在位置の問い合わせだけが到着するため、同じKVヘッドへ対応する問い合わせヘッド間で絶対値最大符号をまとめる。プリフィルと異なりトークン位置方向にはプーリングしない。共通の符号索引でキャッシュ済み鍵を順位付けし、予算内の長距離候補と固定先頭・直近窓を組み合わせる。

選択したトークン位置はGQA群で共有するが、最終のQKスコア、ソフトマックス、値の集約は各問い合わせヘッドが個別に実行する。したがって符号索引は候補検索を近似するだけで、選択後の注意演算を1ビット内積へ置き換える方式ではない。検索結果の誤りは、必要なKVが候補集合から外れることによって品質へ影響する。

### 4. KV量子化と索引の共存

変換後の鍵を `sign(z)` と `abs(z)` に分離し、符号は1ビットで正確に保存する。絶対値はTurboQuantなどの鍵量子化器へ、値ベクトルは値量子化器へ渡す。選択時はパックした符号と鍵ノルムだけを使い、選択後に必要な絶対値を復号して符号を掛け、疎注意カーネルへ渡す。検索と圧縮が同じ鍵表現を共有するため、別の索引用浮動小数点コピーを保持しない。

比較対象のSI-KVは2ビットの鍵絶対値に加えて別の1ビット索引を持つ。自己索引注意とTurboQuantのTQ1設定では、鍵の1ビット符号を索引として兼用し、絶対値1ビットと組み合わせる。ビット予算が異なる比較をそのまま品質優劣として読むことはできないため、論文は論理KVペイロード予算を揃えた比較を実施する。

### 5. GPU実装と学習済み索引器との互換

符号のパック、ビット演算による候補検索、上位選択、疎なKV読出し、GQA対応の注意カーネルを実装する。プリフィルでは64問い合わせをまとめることで選択のスコア行数を64分の1にし、1ビット行列積の高い演算スループットも利用する。論文の既定条件では、選択器の費用を単純な密QK採点の約256分の1と見積もるが、これは選択器に関する条件付きの比較であって、モデル全体の計算が256分の1になる意味ではない。

DeepSeekV4-Flashへの互換性実験では、既存の学習済み疎注意の索引キャッシュを1ビット符号索引へ置き換える。モデル重みと後段の疎注意カーネルは維持し、候補選択だけを差し替える。これは新しいモデルを学習し直す実験ではなく、索引表現の代替可能性を検証する実験である。

論文付録ではDeepSeekV4-Flashの学習済みFP8索引を1ビット符号索引へ交換し、二台構成の2プリフィル・1デコードの配備で負荷試験を行う。各ワーカーはテンソル並列4、144要求、入力約128K・出力約32Kの負荷で、Native+HiSparseと符号索引B1+HiSparseを比較する。Native単独は背景容量の比較であり、改善率の分母には使わない。

## 感度評価と構成要素の役割

2WikiQAの構成要素除去では、平均プーリング・共通符号変換の出力誤差4.9438%に対し、絶対値最大プーリング単独は4.4753%、ヘッド別符号変換単独は4.9293%、両者併用は4.1438%である。平均時の符号打消しを防ぐ効果が主であり、ヘッド別のランダム符号も追加的に効くことが分かる。

RULERのCWE密度感度では、注意密度を5%まで上げる間に正答率が急速に改善し、10%へ増やしても一貫した追加利得が見られない。したがって5%は論文の実験で選ばれた妥協点であり、すべてのモデル・課題で最適という保証ではない。密度を下げすぎれば候補落ちが増え、固定先頭・直近窓が占める比率も変化する。

## 既存研究との差

AnchorAttentionはプリフィルの疎化、Questはデコードの検索に重点を置く。SI-KVはデコードと圧縮鍵の検索を結び付けるが、2ビットの鍵絶対値と別の1ビット索引を保持する。自己索引注意は変換鍵の符号を圧縮表現の一部として保存し、その同じ符号列をプリフィルとデコードで使うため、追加の独立索引を必要としない。

Native Sparse AttentionやDeepSeek Sparse Attentionのような学習済みの疎経路とは異なり、自己索引注意の符号検索は追加学習を要しない。DeepSeekV4-Flashの互換性試験ではモデル重みや後段注意演算を維持し、候補選択用の索引だけを交換している。したがって、専用学習済み索引の代替可能性と、通常の密注意モデルへの導入という二つの用途を区別できる。

## 限界・実装状況

構造化Hadamard変換の符号一致は厳密な上位注意トークン保証ではない。変換座標の相関に基づく理論的な動機と、実際の選択精度は区別する必要がある。問い合わせの絶対値最大プーリングも、複数問い合わせのすべての重要トークンを必ず残すものではない。固定の先頭・直近窓と最低選択数は品質を守る一方、疎化できる割合の下限を制約する。

TurboQuantの1ビット鍵設定は単独で品質が大きく下がる場合があり、符号索引と組み合わせても課題ごとの低下が完全に消えるわけではない。付録のDeepSeekV4-Flash配備ではAIMEの正答率が48.75%から47.50%へ低下し、長文脈の一部課題でも負の結果がある。圧縮ビット数や索引の方式だけで品質維持を保証しない。

プリフィル・デコードの注意演算単体は最大6.1倍・10.3倍だが、Qwenの評価対象は全層の約20%だけが密注意を使うハイブリッド構成である。その他の層や非注意演算の時間が残るため、モデル全体の利得は初回トークン時間1.35倍、定常デコード1.23倍にとどまる。別モデル・GPU・バッチ・文脈長・KV圧縮器での性能は再評価が必要である。
