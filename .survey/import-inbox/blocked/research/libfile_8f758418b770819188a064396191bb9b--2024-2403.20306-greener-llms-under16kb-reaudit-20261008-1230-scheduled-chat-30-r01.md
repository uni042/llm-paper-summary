# Towards Greener LLMs: Bringing Energy-Efficiency to the Forefront of LLM Inference

## 概要

本研究は、大規模言語モデルの推論サービングを**遅延と処理量だけでなく、サービス水準目標（Service-Level Objective、SLO）を満たしたときの消費電力・総エネルギー**から特性評価する。新しい注意カーネルやモデル圧縮を提案する論文ではなく、既存の推論基盤にある周波数、要求の入力・出力長、テンソル並列度、最大バッチサイズの設定が、性能とエネルギーの最適点をどう変えるかをNVIDIA DGX-H100実機で測る研究である。

Llama 2-70BをvLLM上で実行し、H100の動作周波数を800〜1980MHzで変更した。短入力・短出力では周波数をほぼ半分へ下げてもSLO内の最大処理量は約20%しか下がらず、多くの条件で遅延・処理量にほぼ影響を与えずに最大消費電力を約20%削減できる。一方、長い入力のプリフィルは演算律速となりやすく、同じ周波数制限が初回トークン遅延へ強く効く。多くのバッチ条件では約2.0GHzから1.6GHzへ下げてもほぼ同じ処理量で総エネルギーを80%未満にできると報告する。重要なのは、**消費電力を下げることと、1要求を完了する総エネルギーを減らすことは同義ではない**という点である。

## 問題設定と測定の狙い

生成型LLMは入力全体をまとめて処理するプリフィルと、出力トークンを逐次生成する復号とで資源特性が異なる。長い入力のプリフィルでは行列積が多くGPU演算器が忙しくなるため、演算周波数を下げると初回トークンまでの時間（Time to First Token、TTFT）が伸びやすい。復号では重みと鍵・値キャッシュの読出しが支配的になりやすく、GPU周波数を上げてもトークン間時間（Time Between Tokens、TBT）が比例して短くなるとは限らない。同じモデルでも要求長と処理段階で周波数への感度が変わる。

サービングでは応答の遅延を最小化するだけでなく、契約上のTTFT/TBTを守れば十分という状況がある。低負荷や短い要求では性能余裕があるため、最高周波数を維持する必要がない。しかし低周波にして処理時間が伸びすぎると、電力が下がっても総エネルギーが増えることがある。またGPU台数を減らすと通信は減るが、単位時間当たりに処理できる要求数も減る。複数GPUのノードを丸ごと占有している場合、未使用GPUがある構成のほうが必ず省エネルギーとは限らない。

著者らの目的は、LLM専用の完成した自動省エネルギースケジューラを実装することではなく、既存のGPUとvLLMで実際に変更可能な制御変数の効果を測り、将来の自動制御に必要な条件を整理することにある。モデルを動的に分割し直す費用やGPU周波数変更時の停滞を無視した「いつでも最適設定へ切り替えられる」という仮定を置かない。

## 手法と評価設計

### 1. GPU周波数を制御変数にする

GPUではCPUほど細かい電圧制御や電源遮断が一般に公開されていないため、論文はGPU全体の動作周波数を実際に変更できる主な制御変数とする。H100の最大周波数1980MHzに対し、800MHzから約200MHz刻みで周波数を変える。各設定でTTFT、TBT、SLO内の最大処理量、最大電力、総エネルギーを計測する。これは**電力上限を直接変更した実験ではない**。周波数を下げた結果として消費電力が変わることを観測する方式である。

周波数を落とすとGPU演算器の処理速度は低下するが、メモリ帯域に律速される復号では遅延の変化が小さい場合がある。反対にプリフィルの長い入力では周波数感度が高くなる。さらに大入力では電力超過による抑制が起きる場合があり、単純に周波数を上げたときの理論演算速度から実効速度を推定できない。これらを実測で切り分ける。

### 2. 入力・出力長を9種類に分ける

入力長を100・500・1024トークン、出力長を50・128・256トークンとし、3×3の9種類の要求形状を用意する。短い入力はプリフィルの演算負荷が小さく、長い出力は復号反復回数とキュー占有時間を増やすため、両者を独立に変化させる。要求到着率も変え、同じモデルでも負荷が低いときと高いときで周波数の最適値が変わることを調べる。

SLOは、要求を単独実行し、バッチ待ちやキュー待ちがない場合のTTFTおよびTBTの5倍に設定する。したがって測定される「SLOを満たした処理量」は、この明示的な余裕を持つSLO条件に対する値である。実サービスのSLOがもっと厳しければ、低周波の余地は小さくなる可能性がある。

### 3. テンソル並列度の効果を測る

同一DGX-H100ノード内で、モデルを2・4・8枚のGPUに分割するテンソル並列（Tensor Parallelism、TP）を比較する。TP2、TP4、TP8では1GPUが担当する計算量と通信量が異なり、GPU数を増やすほど一回の推論を短くできる一方、集約通信も増える。比較では中程度の入力・出力長と中負荷を用い、TTFT/TBT、SLO内の最大処理量、電力、エネルギーの変化を確認する。

GPU数を増やすと性能は上がるが、2倍のGPUが常に2倍の処理量を生むわけではない。またクラウドで8GPUのノードをすでに確保しているなら、TP2で一部だけを使うよりTP8で要求を早く処理するほうが、ノード全体の利用効率の面で有利になる場合がある。この判断はGPU単体の電力ではなく、利用可能なノードの割当単位とSLOを考慮する必要がある。

### 4. バッチサイズとプリフィル・復号混在の効果を測る

vLLMではプリフィルと復号を混ぜたバッチを実行する。最大バッチサイズを大きくするとGPUの利用率が上がり、同じ重みを多くの要求で再利用できる一方、各要求のプリフィル待ちや計算時間が増え、TTFTのSLOに抵触する場合がある。復号はメモリ帯域律速のため、実験範囲のバッチ64までTBTの悪化が小さいことがあるが、全体の処理量がバッチ数に比例するわけではない。

最大バッチサイズを減らすことは一般に処理量を犠牲にするが、低負荷時には要求をまとめる必要が少なく、むしろ電力・エネルギーを下げる余地がある。周波数、並列度、バッチを独立の万能な最適値として扱わず、要求到着率と入力・出力長を条件にした組合せとして検討する。

## 評価

### 実験環境と指標

| 項目 | 一次資料で確認した設定 |
|---|---|
| モデル | Llama 2-70B |
| 実行環境 | NVIDIA DGX-H100、vLLM |
| GPU周波数 | 800〜1980MHz、約200MHz刻み |
| 標準の並列度 | TP8。別途TP2/TP4/TP8を比較 |
| 入力長 | 100 / 500 / 1024トークン |
| 出力長 | 50 / 128 / 256トークン |
| サービス水準目標 | 単独要求のTTFT/TBTの5倍 |
| 主要指標 | TTFT、TBT、SLO内最大処理量、最大電力、総エネルギー |
| バッチ | プリフィルと復号を混在させたバッチ。最大バッチサイズを変更 |

論文はGPU周波数を中心に、既存の推論サービスで利用可能な設定を実機評価したものである。異なるモデル系列や量子化条件を広く網羅した横断実験ではなく、Llama 2-70Bの特性に依存する。特に消費電力と総エネルギーは別指標で、短時間で処理できる高周波設定が総エネルギーでは有利になる場合もある。

### 要求形状と周波数の主要結果

| 条件 | 観測された結果 | 解釈 |
|---|---|---|
| 短入力・短出力 | 周波数を約半分にしてもSLO内最大処理量は約20%減 | 復号のメモリ律速により演算周波数への感度が低い |
| 多くの要求形状 | 遅延・処理量をほぼ変えず最大電力を約20%削減可能 | SLOの余裕を使った周波数抑制が効く |
| 長い入力 | 周波数を下げるとTTFTが大きく悪化 | プリフィルの計算負荷が高い |
| 長い出力 | 復号反復が増えてキュー占有時間が伸びる | 入力長だけではサービング負荷を予測できない |
| 低負荷 | 周波数低下による電力削減の余地が増える | 高負荷時の最適設定を常用する必要はない |

最大電力を20%削減できることは、すべての要求の総エネルギーが20%減るという意味ではない。実行時間が伸びれば積算エネルギーの改善幅は変わる。論文は周波数によるTTFTの感度が長い入力で大きくなる一方、TBTはメモリ帯域律速により比較的小さいと分析する。ただし混合バッチでは長いプリフィルが復号と同居し、他要求のTBTや待ち時間へ影響する可能性がある。

### テンソル並列度と資源効率

| 比較 | SLO内最大処理量の変化 | 読み取り |
|---|---:|---|
| TP2 → TP4 | 75%増 | GPUを2倍にしても処理量は2倍未満 |
| TP4 → TP8 | 40%増 | 並列度を増やすほど限界利得が低下 |
| TP2対TP8の総エネルギー（中負荷） | TP2は約40%低い | ただし処理可能要求数も約60%少ない |

TP8はより多くのGPUを使うため、1回の推論遅延を下げやすいが通信費用が増え、GPU台数に比例した性能は出ない。逆にTP2の総エネルギーが少なくても、必要な要求処理量を満たせないなら実サービスの代替にはならない。8GPUノードを占有するクラウド契約では、空いているGPUを遊休させる構成よりTP8のほうがノード利用効率の観点で有利になる場合がある。この主張はGPUだけを切り出して課金できる環境へ無条件に適用できない。

### バッチと周波数の組合せ

最大バッチ64のSLO内最大処理量は、最大バッチ4の約7倍にとどまり、単純なバッチ数比16倍にはならなかった。バッチを増やすほどプリフィルの待ち時間や計算時間がTTFTの制約になるためである。多くのバッチ条件では約2.0GHzから1.6GHzへ周波数を下げても処理量がほぼ変わらず、総エネルギーが高周波設定の80%未満になった。低負荷時に最大バッチサイズを下げると、さらに最大15%のエネルギー削減余地があった。

ただし、低負荷でのバッチ縮小と高負荷でのバッチ拡大は目的が異なる。高負荷ではSLOを守りつつできるだけ多くの要求を処理する必要があるが、低負荷では十分な余裕を残して電力を下げられる。最大処理量だけを測って常に大きいバッチを選ぶことも、GPU電力だけを測って常に低周波を選ぶことも、エネルギー最適化の答えにはならない。

### 実用上の読み取りと負の結果

論文が示すのは「周波数を下げれば必ず省エネルギー」という単純な関係ではない。長い入力のプリフィルは演算律速で低周波の影響が大きく、SLO違反や処理時間延長の可能性がある。GPU数を増やすと遅延は改善するが通信費用のため性能が逓減する。バッチを大きくしてもTTFT制約により処理量が比例しない。さらに、GPU周波数の変更自体にCPUからの制御停滞があり、TP構成を動的に組み替える場合は重みの再分配が高価になる。実験で見つかった各点を、実運用で毎要求ごとに無償で切り替えられるとは言えない。

## 既存研究との差

従来のLLMサービング研究は連続バッチ、KVキャッシュ管理、投機的復号、モデル並列化などを使い、主にTTFT/TBTと処理量を改善してきた。省電力の研究もあるが、本研究は同じモデルと実行基盤で入力・出力形状、周波数、テンソル並列、バッチを横断的に変え、性能SLOの下で電力・総エネルギーがどう変わるかを測る点に重点がある。専用アクセラレータの新規設計やモデルの再学習を必要とせず、既存GPUで利用可能な設定を対象にするため、運用への示唆が直接的である。

## 限界・適用範囲

第一に、主な測定対象はLlama 2-70B、DGX-H100、vLLMの組合せである。GPU世代、量子化形式、モデルサイズ、メモリ帯域比が変われば、プリフィルと復号の律速や周波数感度も変わる。測定値をRTXなどの単体GPUやCPUオフロード環境へそのまま転用することはできない。

第二に、SLOは単独要求時の5倍という明示的な余裕を持つ設定であり、もっと厳しい対話サービスでは周波数低下やバッチ拡大が許されない場合がある。周波数変更の停滞とモデル再分割の高い費用があるため、測定された最適点をリアルタイムに追うには切替え頻度を抑える制御が必要になる。論文はその完成した制御器を提案・評価したわけではない。

第三に、GPUの電力・エネルギーを中心とした分析であり、冷却、ネットワーク、ストレージ、電力価格、時刻別炭素強度などデータセンター全体の要素を一括最適化していない。エネルギー消費の削減と二酸化炭素排出の削減は、電源構成により一致しない場合がある。結果は「どの負荷でも何%削減できる」という固定値ではなく、要求形状・負荷・SLOに応じて制御変数を選ぶ必要性を示す特性評価である。
