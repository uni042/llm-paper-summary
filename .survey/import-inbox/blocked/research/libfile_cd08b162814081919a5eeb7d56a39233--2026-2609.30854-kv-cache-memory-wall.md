# The KV Cache Is the New Memory Wall

## 概要

長文脈LLMのデコードは「モデル重みを読むメモリ律速処理」と説明されることが多いが、文脈が伸びると毎段階で読み直す鍵値キャッシュ（KV キャッシュ）の通信量が重み通信量を上回る。本論文はこの切替点をモデル構造、バッチ、element幅、ハードウェア topologyから閉形式で求め、KV最適化の効果を同じ座標系で比較するSystematization of Knowledge（SoK）である。

KV対策を、精度を下げる量子化、トークンを捨てる追い出し、断片化を減らすpaging、リクエスト間で共有する接頭辞 キャッシュ、HBM外へ移すheterogeneous tieringの5領域に分ける。Llama-3-70B BF16ではKVは1 トークンあたり327,680 byteで、128K トークンの1 系列だけで約42 GBになる。バッチ 32ではKV 通信量が重み 通信量を超えるcrossoverが13.4K トークンまで下がり、実運用の長文脈デコードがKV律速になりやすいことを定量化する。

## 問題設定

既存論文は圧縮率、速度、品質を異なるモデル・文脈・ハードウェアで報告するため、例えば「2-bit KVが何倍速いか」を横比較できない。重み通信量が支配する短い文脈ではKVを8分の1にしても段階全体のbyteはほとんど減らず、KV 通信量支配後なら同じ圧縮が大きく効くからである。

さらにB200の2 die、MI300Xの8 accelerator chipletではaggregate HBM帯域を単一partitionから常に使えるわけではない。KV pageを一つのdieへ固定するかstripeするかで、同じbyte数でも実効帯域が変わる。本論文はalgorithmだけでなく配置topologyをbyte accountingへ含める。

## 手法

### 統一KV footprint

有効KV容量を構成項、量子化element幅、追い出し保持率、文脈長、接頭辞共有率、fragmentationへ分解する。量子化はelement幅を、追い出しは保持率を、pagingはfragmentationを、接頭辞 キャッシュは共有率を変える。tieringはbyte数を減らさず、HBM/DRAM/NVMeの常駐比率とinterconnectを変える。

この分解により、容量面では複数方式の削減率を組み合わせられる一方、品質費用やカーネル オーバーヘッドは単純積にならないことを明示する。

### traffic crossover

デコード 1 段階の重み byteとKV byteを数え、両者が等しくなる文脈長 `s*` を導出する。`s*` はバッチに反比例するため、バッチを増やして重み readを共有すると、むしろ相対的にKVが支配する時点が早まる。Llama-3-70Bではバッチ 1で427.2K、バッチ 8で53.4K、バッチ 32で13.4K、バッチ 256では1.7K トークンである。

KVを `c` 倍圧縮した理論速度利得も重み+KV byte比から求める。短文脈では1倍へ近づき、KV支配の極限でのみ `c` 倍へ近づく。複数圧縮の個別高速化倍率を掛け算してはいけないことも式で示す。

### topology-aware bandwidth

multi-die deviceでは局所 partition 帯域とpackage 相互接続網 帯域の小さい方から実効帯域を求める。page stripingによりaggregate帯域を使える条件を定式化し、B200ではpinning対stripingが最大2倍、MI300Xでは最大8倍のceiling差を持つ。

## 主要結果

|条件|指標|結果|解釈|
|---|---|---|---|
|Llama-3-70B, BF16, バッチ 32|通信量 crossover|13.4K トークン|128K 推論提供は明確にKV 通信量側|
|同, バッチ 256|crossover|1.7K トークン|バッチ増加はKV律速開始を早める|
|B200, バッチ 1, 128K|2-bit KV理論高速化倍率|1.25×|427.2K crossover前なので8× byte削減が全体へ薄まる|
|B200, バッチ 1, 512K|2-bit KV理論高速化倍率|1.91×|crossover後はKV削減が強く効く|
|512K|2-bit + 50% 追い出し|2.05×|個別高速化倍率の積ではなく共同 byte factorで評価すべき|
|B200/MI300X|striping対pinning ceiling|最大2× / 8×|package内配置もfirst-order要因|

128KのLlama-3-70Bではバッチを増やしても算術強度は8.0〜11.3 FLOP/Bの範囲に留まり、B200のridge 281 FLOP/Bを25〜35倍下回る。長文脈デコードをバッチだけで計算律速へ持ち込めないことを解析的に示す。

## 既存研究との差

既存surveyがKV方式を列挙するのに対し、本論文は「どの方式がどのfootprint因子を変えるか」を統一式へ写し、同じ文脈・モデル・ハードウェアで速度上限を再計算する。特にreported 高速化倍率を平均せず、解析値と各論文の品質値を別の証拠classとして保持する。

またメモリ wallを通信量だけでなく容量とinterconnectの三つへ分ける。paging/接頭辞 sharingは品質を落とさず容量・重複を改善するがデコード byteを直接減らさず、tieringは容量を解決する代わりにPCIe/NVLinkを新たなwallにする、という役割分担を明確にする。

## 限界

多くの速度値は実測ではなくルーフラインとbyte accountingからの導出値であり、論文自身もカーネル実装のgather、dequantization、format conversionで実速度が上限を下回ると指摘する。特に追い出しのragged layoutは密 カーネルへ追加gatherを要求する。

topology モデルもremote partitionのHBM contentionを完全にはモデル化せず、striped配置側に有利な上限となる場合がある。品質値は各原論文の異なるベンチマークから持ち込むため、同一タスクでの完全なquality比較ではない。著者は分散、power、公開ワークロード、TTFTとデコード rateの同時報告不足も既存証拠の限界として挙げる。
