# Dynamic Memory Compression: Retrofitting LLMs for Accelerated Inference

## 概要
自己回帰LLMでは過去tokenのkey/valueを全て保存するため、KVキャッシュは系列長とbatch sizeに比例して増える。Dynamic Memory Compression（DMC）は、固定比率のGrouped-Query Attention（GQA）や推論時のheuristic evictionではなく、モデル自身に「新しいKV slotを作るか、既存slotへ統合するか」を学習させる。

DMCはattention head・layerごとに異なる圧縮率を学べる。既存Llama 2を少量のcontinued pre-trainingでDMC化でき、追加パラメータを必要としない。推論時には生成と同時にcacheを圧縮するため、同じGPUメモリでより長いcontextまたは大きなbatchを載せられる。

## 問題設定
固定GQAは全入力で同じKV head削減率を使い、token単位の冗長性へ適応しない。H2O/TOVAのようなevictionは学習不要だが、高圧縮率で必要tokenを落とすと品質が崩れる。DMCは事前学習済みモデルの知識を大きく壊さず、cache更新規則だけを学習可能にすることを狙う。

## 手法
各attention headで新tokenのkey/valueを得たとき、DMCはappend判定とimportance重みをモデル内部の既存次元から取り出す。appendなら通常どおり新slotを作る。mergeなら直前slotと現在KVをimportanceで重み付き平均し、一つのslotへまとめる。これを逐次行うことでcache長の増加率を抑える。

圧縮目標は学習中に徐々に強め、既存LLMへ急激な分布変化を与えない。head/layerごとに判定が独立なので、圧縮しやすい深い層・headへ強い圧縮を寄せ、重要な箇所は保持できる。GQA済みモデルにも追加でき、KV head数削減と時間方向のDMC圧縮を乗算的に組み合わせられる。

## 評価条件
|項目|内容|
|---|---|
|モデル|Llama 2 7B、13B、70B|
|GPU|NVIDIA H100を主要throughput評価に使用|
|品質|MMLU、CommonsenseQA、HumanEval等|
|比較|元Llama、up-trained GQA、H2O、TOVA|
|圧縮率|2×、4×、6×、8×等|
|追加学習|元事前学習データのごく一部をcontinued pre-training|

## 主要結果
4倍KV圧縮までは元モデルの下流性能を概ね維持し、GQAやH2O/TOVAより高圧縮時の品質が安定する。最新版論文ではH100上の自己回帰推論throughputを最大7倍まで改善する。8倍圧縮ではLlama 2 7BのMMLU低下が約2.8 pointに留まる一方、比較eviction方式はコード生成などで大きく崩れる条件がある。

Llama 2 70Bのように元からGQAを使うモデルでは、GQAの8倍KV head圧縮とDMC 2倍を組み合わせ、合計16倍相当のcache圧縮を構成できる。速度向上は演算自体が常に7分の1になるためではなく、KVメモリ削減により同一GPUへ大batchを載せられることが主要因である。

## 既存研究との差
GQA/MQAはarchitectureとして固定されたKV head共有を使う。DMCはtoken時間軸上のcache更新を入力依存で学習する。推論時evictionは過去slotを削除するが、DMCは生成時点で隣接情報をmergeして圧縮表現を形成する。量子化とも直交し、slot数そのものを減らす。

## 限界
完全なtraining-free方式ではなく、既存checkpointへcontinued pre-trainingが必要である。したがって任意のclosed-weight APIへ後付けできない。圧縮率を極端に上げると品質低下は残り、mergeで失われた個別tokenのKVを後から復元することもできない。throughput利得はbatchを増やせるメモリ律速条件で大きく、低batch・計算律速条件では最大倍率へ届かない。
