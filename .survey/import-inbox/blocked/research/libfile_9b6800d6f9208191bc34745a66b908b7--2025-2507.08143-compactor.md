# Compactor: Calibrated Query-Agnostic KV Cache Compression with Approximate Leverage Scores

## 概要

長文脈推論のKVキャッシュを削る際、生成中のquery attentionを使えば「現在重要なtoken」を選べるが、promptを保存・転送する時点では未来queryが存在しない。Compactorはこのquery非依存条件を正面から扱い、key行列の線形代数的な代表性を近似レバレッジスコア（approximate leverage score）で測る。特定queryへのattentionではなく、key集合の部分空間をどのtokenがどれだけ支えているかを重要度とするため、生成内容を待たずにKVを圧縮できる。

さらに固定圧縮率を全contextへ適用せず、contextごとに「性能が大きく落ちる前にどこまで削れるか」を推定する文脈校正圧縮（context-calibrated compression）を導入する。RULERとLongBenchの27課題、Qwen 2.5とLlama 3.1系列で評価し、競合方式と同等性能を20%少ない保持tokenで達成する。文脈校正を使うLongBenchではfull-KV性能を保ちながらKV memoryを平均68%削減する。

## 問題設定

KV evictionは通常、現在または直近のattention scoreを使ってtokenを順位付けする。しかしprefix cacheの事前圧縮、cacheの永続化・転送、prefill直後の圧縮では、将来どのqueryが来るか分からない。SnapKVのようにprompt末尾のqueryを代理にできる場合もあるが、任意の将来用途に対してはquery依存性が残る。

もう一つの問題は、同じ圧縮率でもcontextごとの冗長度が異なることだ。反復的な文書は大きく削ってもよい一方、needleや多数の固有事実を含む文書では少量の削除でも性能が落ち得る。固定50%などの予算は、容易なcontextではmemoryを無駄にし、難しいcontextでは品質を壊す。

## 手法

### 近似レバレッジスコアによるtoken重要度

レバレッジスコアは、行列の各行がその行列の張る部分空間にどれだけ固有に寄与するかを測る量である。Compactorではattention keyを行として扱い、key集合の低次元構造を保つために重要なtokenへ高いscoreを与える。高score tokenを残すことで、特定queryを知らなくても将来のqueryが利用し得るkey空間を代表するsubsetを作る。

厳密なレバレッジスコアには高価な分解が必要になるため、推論前処理として使える近似計算を採用する。入力は各head/layerのkey表現、出力はtokenごとのquery非依存scoreと保持indexである。valueは対応するkeyと同じindexで残すため、圧縮後のKVは疎で非連続なtoken集合になる。

### query非依存圧縮

score計算に生成queryやattention履歴を使わないため、prompt処理後すぐにKVを削減できる。これはprefix cacheを別requestへ再利用するときにも重要で、将来requestのqueryを事前に知る必要がない。圧縮後は通常attentionが保持indexだけを読み、削除tokenを復元しない。

この設計の利点はtask-agnosticな事前圧縮だが、queryを見れば不要と分かるtokenまで安全側に残す可能性がある。Compactorはその分、線形代数的な代表性で「どのqueryにも使われにくい冗長token」を先に落とす。

### 文脈校正圧縮

固定retention ratioの代わりに、与えられたcontextがどの程度の圧縮へ耐えられるかを校正する。複数の候補圧縮率でcontextの情報保持状態を調べ、著しい性能劣化が始まる手前の最大圧縮を選ぶ。出力はcontext固有のretention budgetであり、そのbudgetをレバレッジscore順位へ適用する。

この機構により、冗長なcontextは強く圧縮し、情報密度が高いcontextは多く残せる。LongBenchで平均68% memory削減しながらfull-KV性能を維持した結果は、この「一律圧縮率をやめる」効果を含む。

### compactor-vLLM

疎な保持token indexは通常の連続PagedAttentionとアクセス形状が異なる。そこで著者らはcompactor-vLLMと最適化Triton kernelを公開し、非連続KVを効率的に読む実行経路を用意する。アルゴリズム上のmemory削減だけでなく、疎index gatherがruntime overheadで相殺されないことを狙う。

## 評価条件

| 項目 | 内容 |
|---|---|
| モデル系列 | Llama 3.1、Qwen 2.5 |
| 代表モデル | Llama 3.1-8B-Instruct、Qwen2.5-14B-Instruct-1M |
| 課題 | RULER、LongBenchの合計27 synthetic / real-world task |
| 条件 | query非依存KV圧縮 |
| 比較 | SnapKV等の既存KV圧縮 |
| 実装 | compactor-vLLM、Triton疎KV kernel |
| 指標 | task性能、保持token率、KV memory |

## 主要結果

| 条件 | 結果 | 解釈 |
|---|---|---|
| 競合方式との同等性能 | 約20%少ないtoken保持で達成 | query非依存でもkey空間の代表性が有効 |
| RULER 4K、50%保持 | full-KV性能の約99% | 中程度圧縮では情報損失が小さい |
| RULER 4K、25%保持 | 約87.1%を維持 | 高圧縮で劣化するが段階的 |
| RULER 4K、10%保持 | 約68.0%を維持 | 極端圧縮では明確な品質低下 |
| LongBench + 文脈校正 | 平均68% KV memory削減でfull-KV性能 | context別budgetが固定率の過不足を減らす |

RULERでretentionを50%から25%、10%へ下げるにつれて性能が99%、87.1%、68.0%へ落ちる結果は、圧縮が無条件に無損失ではないことを示す。一方、context-calibrationはcontextごとにこの崖の位置を推定し、必要以上に保守的なbudgetを避ける。

## 既存研究との差

attention score型方式は特定queryに対する重要度を直接測れるが、queryが未確定のcache事前圧縮には使いにくい。Compactorはkey行列自体の幾何学的代表性を使うため、将来queryやattention履歴を前提にしない。これは「現在のqueryへ最適」ではなく「将来query集合に対してkey部分空間を保つ」方向の設計である。

固定budget型KV圧縮との差は文脈校正にある。同じモデル・taskでもcontextの冗長度が違うことをbudgetへ反映し、圧縮率を入力ごとに変える。また疎な非連続cacheを実際のserving runtimeで扱うためのcompactor-vLLMを提供する点も、scoreだけを提案する方式との差になる。

## 限界

レバレッジスコアはkey空間の線形代数的代表性であり、特定の未来queryが低leverage tokenを決定的に参照するrare caseを完全には予測できない。RULERで10%保持時に性能が68%まで低下することからも、極端な圧縮には品質限界がある。

文脈校正には圧縮可能性を見積もる追加処理が必要で、固定budgetより前処理costが増える。さらに疎な非連続KVは標準attention kernelにそのまま最適ではなく、専用Triton kernelの性能にend-to-end利得が依存する。論文の強い結果はmemoryとtask性能に関するものであり、すべてのserving負荷で同じ比率のlatency改善を保証するものではない。

評価はLlama 3.1/Qwen 2.5とRULER/LongBenchを中心としており、MoE、multimodal、極端に長いreasoning生成など別のKV分布への一般化は追加検証が必要である。
