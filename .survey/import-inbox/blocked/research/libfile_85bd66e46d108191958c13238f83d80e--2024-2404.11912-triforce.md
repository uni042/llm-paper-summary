# TriForce: Lossless Acceleration of Long Sequence Generation with Hierarchical Speculative Decoding

## 書誌情報
- canonical identity: `arXiv:2404.11912`
- 著者: Hanshi Sun, Zhuoming Chen, Xinyu Yang, Yuandong Tian, Beidi Chen
- COLM 2024
- 一次資料: https://arxiv.org/abs/2404.11912

## 概要
長文脈LLMのdecodeでは、各token生成ごとに過去全tokenのKV cacheを読み込む。Llama2-7B-128Kではモデル重み約14GBに対しKV cacheが約64GBとなり、短文脈で支配的だったweight bandwidthに加えてKV bandwidthが大きな律速になる。KV evictionは読み出し量を減らせるが、捨てた情報が後で必要になると生成品質を変えてしまう。

TriForceはKVを永久に捨てるのではなく、full cacheを保持したまま、現在の生成に関連する小さなretrieval cacheを作る。同じtarget modelの重みとretrieval cacheを「中間draft」として使うため、小型draft modelだけよりtargetに近い予測を得られる。しかしtarget model重みを毎回読むdraftは依然重いので、さらにLlama-68M等の軽量モデルが中間draftを投機する。最後にfull KV cacheを持つtarget modelが検証するため、元targetの出力分布を保持するlossless speculative decodingになる。

Llama2-7B-128Kでは単一A100で最大2.31倍。offload設定では2枚のRTX 4090で0.108秒/token、最適化offload baseline比7.78倍を報告し、単一RTX 4090ではDeepSpeed-Zero-Inference比4.86倍である。温度1.0でもacceptance rate 0.9超を維持したと報告され、長文脈・sampling条件でもretrieval draftがtargetに近いことを示す。

## 問題設定
通常のspeculative decodingは小型draftが複数tokenを提案し、大型targetが一括検証する。短文脈ではtarget weight読出し回数を減らす効果が大きい。しかし128K級ではtarget検証時のfull KV読出しが巨大で、weightだけを軽くしても十分ではない。

KV圧縮・evictionでtarget自身を軽くすると、元モデルの確率分布を変える。TriForceは「近似KVはdraftにだけ使い、最終検証はfull KVで行う」ことで、近似を速度のために利用しながら正しさをtargetへ戻す。

## 手法
### retrieval-based drafting
full KV cacheをchunkへ分割し、現在queryと各chunkの代表keyとのattention scoreから重要chunkを選ぶ。Llama2-7B-128Kの代表設定では約4K token、すなわちfull cacheの約3%をretrieval cacheとして使う。

隣接して生成されるtokenは必要とする過去情報が似るというcontextual localityを利用し、一度選んだretrieval cacheを複数decode stepで再利用する。毎token retrievalを作り直さず、acceptance低下や一定間隔で更新することで選択費用を償却する。

### target model + sparse KVという中間draft
中間draftは別に学習した中型モデルではない。target modelと同じ重みを使い、attentionで読むKVだけをretrieval cacheへ制限する。このためモデル重み由来の予測能力はtargetと同じで、KV近似だけが差になる。

retrieval cacheが重要文脈を十分回収できればacceptanceが高くなる。しかしtarget重みをロードする費用は残るので、この中間draft単独ではweight bandwidthが次の律速になる。

### hierarchical speculation
最下層の軽量モデルはStreamingLLM cacheを使い、まずγ1個のtokenを提案する。中間draftがそれを検証しながらγ2個以上の候補列を作り、最上層のfull-cache targetが一括検証する。つまり「small model → target weights + retrieval KV → target weights + full KV」の三段階である。

この階層化は二つの帯域律速を別々に扱う。small modelが中間draftのweight load頻度を減らし、retrieval cacheが中間draftのKV loadを減らす。最終target呼出し回数が減るほどfull KV読出しも償却される。

### lossless verification
最終段では元target modelがfull KV cacheを使って通常のspeculative decoding acceptance ruleを適用する。draftが近似でも、accept/rejectと補正samplingをtarget分布に従って行うため、近似KVを直接最終出力へ採用するlossy cache圧縮とは異なる。

## 評価条件
| 項目 | 条件 |
|---|---|
| モデル | Llama2-7B-128K、Llama2-13B-128K、LWM-Text(-Chat)-128K |
| 小型draft | Llama-68M等 |
| retrieval budget例 | 4K / 約3% KV |
| workload | PG-19、NarrativeQA等、約120K〜130K prefill |
| hardware | A100、1〜2× RTX 4090 |
| 比較 | autoregressive、optimized offloading、DeepSpeed-Zero-Inference等 |
| 品質 | full targetによるlossless distribution preservation |

## 主要結果
| 条件 | 結果 |
|---|---:|
| Llama2-7B-128K / A100 | 最大2.31× |
| Llama2-7B-128K / 2×RTX4090 offload | 0.108 s/token、baseline比7.78× |
| Llama2-13B-128K / 2×RTX4090 | 約0.226 s/token、約7.94× |
| 1×RTX4090 | DeepSpeed-Zero-Inference比4.86× |
| sampling temperature 1.0 | acceptance rate >0.9 |

retrieval budgetを増やすとdraft精度は上がるがKV読出し費用も増える。代表実験では4K付近で速度とacceptanceの釣合いがよく、それ以上ではacceptance改善が飽和する。

## 既存研究との差
StreamingLLMやH2Oは不要KVを捨ててtarget計算自体を軽くするため、情報損失が最終出力へ影響し得る。TriForceはsparse KVをdraftにだけ使い、full cacheを最終検証用に残す。

通常のspeculative decodingは主にmodel weightの償却を狙う。TriForceは長文脈ではKV loadも同等以上の問題になると捉え、KV近似draftとsmall model draftを階層化してweight/KV双方を扱う。

## 限界
full KV cache自体は保持するので、KV容量を消す方式ではない。on-chipでfull cacheが収まらない場合はoffloadが必要で、その帯域が性能を制約する。

retrievalのcontextual localityが弱い生成ではacceptanceが下がり、cache再構築頻度が増える。実装が主にLlama系長文脈モデルを対象とし、任意architectureへの一般化には追加実装が必要である。
