# GPU-Accelerated INT8 Quantization for KV Cache Compression in Large Language Models

> INT8
> KV量子化を4種類のCUDAカーネルで比較し、再利用のない帯域律速処理ではshared-memory
> tilingよりvectorized memory accessが有効と実測する。

## 概要

長文脈推論ではKVキャッシュが系列長に比例して増え、モデル重みと同程度以上のGPUメモリを占め得る。本論文はKVをINT8へ量子化して4倍の容量削減を狙い、その変換自体が推論の新しいボトルネックにならないようCUDA
kernelを設計・比較する。

実装はnaive、shared-memory
tiled、thread-coarsened、vectorizedの4種類である。最大131K×8K、約10億要素まで拡張したmicrobenchmarkではvectorized版がCPU基準比最大1694倍となる。最大絶対復元誤差は全構成で0.00394、head
dimension 8192でも平均attention score誤差0.095である。

重要な観察は、この量子化が「各要素を1回読み、scaleして整数化し、1回書く」再利用のない帯域律速処理だという点である。したがってshared
memoryへtileしても再利用がなく同期命令だけ増え、単純coalesced
accessを超えない。vectorized
load/storeはメモリ命令数そのものを減らすため有効になる。

## 問題設定

KV量子化は保存bytesを減らせても、生成中に量子化・逆量子化を頻繁に行うならkernel
overheadがtoken
latencyを増やす。CPUへKVを送って変換する方式はPCIe転送も必要になり、圧縮によるメモリ節約と相殺する。

GPU上で直接処理する場合も、一般的なCUDA最適化を無条件に適用すれば速くなるわけではない。行列積のようにtile内で値を再利用する演算と異なり、量子化は各値を一度しか使わないため、shared
memoryの価値が低い。

## 手法

### INT8量子化

入力浮動小数点KVをscaleで正規化し、INT8範囲へ丸めて保存する。復元時は整数値へscaleを掛けて近似KVを得る。論文の入力範囲では理論的な最大丸め誤差が約1/(2×127)=0.00394となる。

容量は32-bit浮動小数点表現との比較で4分の1になる。量子化はモデル重みを変えず、KV
stateだけを対象にするため、系列長増大による動的メモリへ直接効く。

### 4種類のCUDA kernel

naive版は列方向にcoalescedなglobal memory
accessを行い、各threadが基本的なscale・round処理を担当する。tiled版はshared
memoryへ一度stageするが、データ再利用がないため追加同期の利点が小さい。

coarsened版は1 threadが連続複数要素を処理し、address calculationやloop
overheadを減らす。vectorized版は複数要素を一つのmemory
instructionでload/storeし、帯域律速で支配的な命令数を削減する。実験ではこの最後の変更が最も大きく効く。

### 誤差検証

単なるkernel時間だけでなく、元KVとの最大絶対誤差・L2誤差を測る。さらに量子化前後KVを使ったattention
score差を測り、数値誤差が下流attentionへどの程度伝播するかを確認する。

L2誤差は要素数とともに増えるが、これは誤差を全要素で集計するためで、1要素あたりの最大誤差は一定である。head
dimension増大時のattention score誤差は概ね平方根的に増える。

## 既存研究との差

KV量子化アルゴリズムの多くは、scale粒度、外れ値処理、低ビット表現、per-channel/per-token方式など量子化誤差の低減を中心にする。本論文の主眼は新しい量子化理論ではなく、単純なINT8変換をGPU上でどう実装すべきかのkernel比較にある。

特に「shared memory
tilingは常に良い」という一般的なCUDA最適化則がこのworkloadでは成立せず、vectorized
global memory
accessの方が直接的に効くことを実測で示す点がシステム上の貢献である。

## 限界

品質評価はKV再構成誤差とattention
score誤差が中心で、長文生成ベンチマーク全体の正解率やperplexityを広範に測ったものではない。「下流品質への影響が最小」という結論は、この数値誤差評価の範囲として解釈すべきである。

1694倍はCPU
baselineに対する量子化kernelの速度であり、LLM全体が1694倍速くなる意味ではない。実際の推論ではattention、MLP、sampling等が残る。またINT4/2-bitのようなより強い圧縮は対象外であり、4倍より大きな容量削減と誤差の交換条件は評価していない。
