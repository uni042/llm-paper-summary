# Native Sparse Attention: Hardware-Aligned and Natively Trainable Sparse Attention

> 圧縮・選択・局所windowの3経路をGQA共有KVに合わせたblock sparse kernelで実装し、長文脈LLMのprefillとdecodeを実GPU上で高速化する。

## 概要

標準attentionは系列長に対して二乗で計算量が増え、64K級の長文脈では推論遅延の主要部分になる。既存の疎attentionには、decodeだけを疎化してprefillは重いまま、あるいはprefillだけを高速化してdecode時のKV読み出しは残る方式が多い。また、token単位の不規則な選択は計算量を減らしてもGPUの連続memory accessとTensor Core利用を崩し、理論FLOP削減ほど実時間が短くならない。

Native Sparse Attention（NSA）はこの問題を、algorithmだけでなくhardware実行形態から設計する。各queryに対して、過去contextを粗く圧縮した表現、重要blockから選んだfine-grained token、直近のsliding windowという3経路へ分け、それぞれのattention出力をlearned gateで統合する。選択はtoken単位ではなく連続block単位にし、Grouped-Query Attention（GQA）でKVを共有するquery head群が同じblock集合を読むようにする。

論文は27B総parameter・3B active parameterのMoE/GQA backboneを用い、270B tokenの8K pretraining後に32Kへ継続学習して比較する。一般benchmark平均ではfull attentionの0.443に対してNSA 0.456で、疎化による能力低下を示さない。さらに64K系列でdecode、forward、backwardの全段階に実効高速化が現れ、長くなるほど差が広がることを報告する。

## 問題設定

疎attentionの目的は、queryが全過去tokenを読む代わりに重要な一部だけを読むことで計算とKV cache accessを減らすことにある。しかし推論ではprefillとdecodeで律速が異なる。prefillは多数queryをまとめて処理するため計算律速になりやすく、decodeは1 tokenずつ生成しながら過去KVを読むためmemory bandwidth律速になりやすい。

このため「attention scoreを減らす」だけでは不十分である。GQAでは複数query headが同じKV headを共有するため、headごとに異なるtokenを選ぶと、集合和としては大量のKV blockをHBMから読むことになる。またrandom token selectionはGPUのblock loadを壊し、Tensor Coreへ規則的なmatrix tileを供給しにくい。

NSAは、疎化の単位・KV共有・GPU tileを同時に揃えることで、計算削減を実遅延削減へ変えることを狙う。

## 手法

### Token Compression

最初の経路は過去tokenを連続blockへ分け、各blockをlearnable MLPで1つのcompressed key/valueへ変換する。block長を `l`、strideを `d` とすると、context全体の粗い意味表現を元token数より少ない表現へ落とす。これによりqueryは遠距離context全体の概要へ低コストでアクセスできる。

圧縮だけでは局所的な重要情報を失うため、NSAはこの経路を最終出力として単独利用しない。compressed attentionで得られるscoreを次のfine-grained block selectionにも再利用し、追加のimportance predictorを別に走らせる費用を抑える。

### Token Selection

第二経路はcompressed attention scoreから重要な元KV blockを選ぶ。NSAではselection blockを連続領域として扱い、top-n block内の元key/valueを保持する。GQAでは同一KVを共有するquery head群のimportance scoreを合算し、group全体で同じblock集合を選択する。

この設計により、headごとに異なるKVを読んでmemory trafficが膨らむ問題を避ける。さらに連続blockはGPU上でまとまってHBMからSRAMへloadできるため、random gather型疎attentionよりhardware utilizationを高めやすい。

### Sliding Window

第三経路は直近 `w` tokenを常に読むsliding windowである。局所依存は言語modelで強く、圧縮・選択経路だけに任せるとlocal patternが学習を支配したり、重要な近傍情報を落としたりする。NSAはlocal contextを専用経路へ分離し、compressionとselectionが長距離情報へ役割を集中できるようにする。

3経路は独立したkey/valueを持ち、各attention出力をlearned gateで統合する。この構成により、粗いglobal情報、選択されたfine-grained情報、確実なlocal情報を同時に残す。

### GQA向けhardware-aligned kernel

NSAのkernelはTritonで実装され、query token単位ではなくGQA group単位でquery headをSRAMへloadする。同一groupのheadは同じsparse KV block indexを共有するため、選択blockを一度loadして複数headで再利用できる。

内側loopでは連続KV blockをSRAMへ読み、Tensor Coreでattention計算する。query/output側のloopはgrid schedulerへ出し、選択block数がほぼ一定である性質を利用してload balanceを取る。これによりdecode時はKV transferを削減し、prefill/training時はblock matrix計算のarithmetic intensityを維持する。

## 1リクエストの処理

prefillでは入力contextからcompression blockを作り、compressed attentionを計算する。そのscoreを使って重要blockを選び、sliding windowと合わせて3経路のattentionを計算する。full attentionのように全token pairを計算する必要はない。

decodeでは新しいqueryに対し、compressed representationから重要blockを決める。GQA group内では選択blockを共有し、必要なKV blockだけをHBMから読む。直近windowは常時保持されるため、local依存を選択誤りで失うことを防ぐ。

## 評価

### 代表的な評価条件

| 項目 | 設定 |
|---|---|
| model | 27B総parameter、3B active parameterのMoE |
| attention | GQA、4 group、64 query head |
| 学習 | 270B token、8K contextでpretraining後32Kへ継続学習 |
| NSA設定 | compression block 32、stride 16、selection block 64、selected block 16、window 512 |
| hardware | kernel性能はNVIDIA A100 |
| 比較 | Full Attentionおよび既存sparse attention |
| 評価軸 | 一般能力、長文脈、reasoning、training/prefill/decode効率 |

### 代表的な結果

| 条件 | 指標 | Full Attention | NSA | 読み取れること |
|---|---|---:|---:|---|
| 一般benchmark平均 | score | 0.443 | 0.456 | 疎化しても平均能力を維持し、わずかに上回る |
| 64K context | decode latency | 基準 | 高速化 | KV access削減が長文decodeで効く |
| 64K context | forward | 基準 | 高速化 | block sparse計算がprefill/training前向き計算に効く |
| 64K context | backward | 基準 | 高速化 | native trainable設計により学習時にも疎性を利用できる |

一般benchmarkの内訳ではMMLU 0.567対0.565と僅かに下がる項目がある一方、MMLU-PRO 0.279対0.286、CMMLU 0.576対0.587、BBH 0.497対0.521、GSM8K 0.486対0.520、DROP 0.503対0.545など改善する項目もある。したがって「すべてのtaskで改善」ではなく、平均としてfull attention相当以上と読むべきである。

## 既存研究との差

H2OのようなKV evictionは主にdecode側を狙い、MInferenceのような方式はprefill側の疎化へ重点を置く。NSAはprefillとdecodeの両方で同じnative sparse architectureを使い、trainingから疎性を組み込む。

また、token-granular selectionは理論上のsparsityが高くても非連続memory accessでGPU効率を落としやすい。NSAはblock selectionとGQA group共有を設計段階から採用し、KV trafficとTensor Core利用を実装上の制約として扱う点が異なる。

## 限界

NSAはpretrained full-attention modelへ後付けするだけの方式ではなく、native sparse architectureとしてtrainingまたは継続学習を必要とする。既存modelを無変更で高速化したい用途では導入costが大きい。

性能はblock size、selected block数、window長に依存し、sparsityを強めすぎれば重要contextを落とす可能性がある。また専用kernelの利得はGPU architecture、GQA/MQA構成、sequence lengthに依存する。短いcontextではfull attentionの高度に最適化されたkernelとの差が小さくなる。
