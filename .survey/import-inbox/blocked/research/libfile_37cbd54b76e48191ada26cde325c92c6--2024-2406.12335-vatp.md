# Attention Score is not All You Need for Token Importance Indicator in KV Cache Reduction: Value Also Matters

## 概要
KV token枝刈りは過去tokenへの注意得点を重要度に使うことが多い。しかしattention出力は注意重みとvalueベクトルの積の総和であり、valueの大きさも寄与を決める。VATPはvalue L1ノルムがtoken間で非一様で、attention sinkでは注意得点が巨大でもvalueノルムが小さい場合があることを観測する。

提案指標は既存の注意重要度 `S_k^t` とvalue L1ノルムの積 `I_k^t=S_k^t||v_k||_1`。LongBench英語16課題、KV予算50%で、H2O版は両モデルで元H2Oを12/16課題、Scissorhands版はLLaMA2で13/16、Vicunaで14/16課題上回った。

## 問題設定
H2Oは累積注意得点、Scissorhandsは直近履歴窓の注意得点でtokenを選ぶ。だが1 headの出力は `Σ a_i v_i` なので、同じ注意重みでもvalueノルムが違えば出力寄与が違う。注意得点だけではこの差を落とす。

一方、sink tokenはvalue寄与が小さくても削除すると残りtoken間の注意分布が変化する。このためVATPは先頭F tokenを明示的に保護し、残余予算を新指標で競わせる。

## 手法
### value認識重要度
H2OまたはScissorhandsが計算する `S_k^t` に `||v_k||_1` を掛ける。KV予算を超えるとIが小さいtokenから削る。L1ノルム補助状態はhead次元128の7BモデルでKVの `1/(2d_head)` と小さい。

### sink保護
先頭付近のsinkは巨大な注意得点と小さなvalueノルムを併せ持つ。積だけなら削除され得るが、sink除去はsoftmax分布を崩すため先頭F tokenを常時保持する。

### 既存方式への組込み
独立予測器を学習せずH2O/Scissorhandsの履歴定義を再利用する。H2O版は累積注意行列取得が必要でFlashAttentionと相性が悪いが、Scissorhands版は直近w tokenだけなのでFlashAttention対応実装が可能である。

## 評価条件
|項目|内容|
|---|---|
|モデル|LLaMA2-7B-chat、Vicuna-v1.5-7B-16k|
|最大系列|4K、8K|
|GPU|A6000 1枚|
|データ|LongBench英語16課題、各150〜500例|
|主KV予算|50%|
|比較|StreamLLM、H2O、Scissorhands、VATP版|

## 主要結果
LLaMA2ではH2O+VATPが12/16、Scissorhands+VATPが13/16課題で元方式を上回る。Vicunaではそれぞれ12/16、14/16。2WikiMultihopQAでKV予算を変えるとScissorhands+VATPはほぼ全予算で最良で、強い圧縮域でも差が残る。全課題で必ず改善するわけではない。

同じKV予算ではScissorhandsへVATPを加えても生成スループットとメモリに顕著な差はない。したがって主な貢献は容量追加ではなく保持token順位の改善である。

## 既存研究との差
H2OやScissorhandsは注意得点を重要度の中心にする。VATPは枝刈り器全体を置換せず、attentionの構成式に合わせvalueノルムを重要度へ加えるため、同じ履歴定義・同じKV予算で比較できる。

## 限界
H2O版は注意行列取得のためFlashAttention非対応で、prefillメモリ問題が残る。論文時点ではGrouped-Query Attention（GQA）へ直接適用できない。評価は7B級2モデル、最大8Kで、超長文脈や大規模GQAモデルへの一般化は未評価である。
