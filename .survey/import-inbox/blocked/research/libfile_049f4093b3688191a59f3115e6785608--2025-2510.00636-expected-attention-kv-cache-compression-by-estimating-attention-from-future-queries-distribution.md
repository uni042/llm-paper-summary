# Expected Attention: KV Cache Compression by Estimating Attention from Future Queries Distribution

## 書誌情報

- canonical identity: `arXiv:2510.00636`
- 著者: Alessio Devoto, Maximilian Jeblick, Simon Jégou
- 初版公開: 2025-10-01
- 一次資料: https://arxiv.org/abs/2510.00636
- 主題: KVキャッシュ圧縮、長文脈推論、学習不要推論最適化

## 概要

長文脈LLMでは、自己回帰生成の各ステップで過去トークンのKey/Valueを再計算しないためにKVキャッシュを保持する。しかし容量は系列長に比例して増え、論文の例では70B級モデルで100万トークンを保持すると約320 GBに達する。単純に古いKV対を捨てると後で必要になる情報を失い、過去の注意スコアを使って重要度を決める方式も、将来クエリを知らないという本質的問題に加え、FlashAttentionのような実装が完全な注意行列を実体化しないため利用しにくい。

Expected Attentionは、この「将来のクエリがまだ存在しない」という問題を、クエリ活性の確率分布を推定する問題へ置き換える。隠れ状態が概ねガウス分布に従うという観測から、将来クエリの平均と共分散を推定し、固定された各Keyに対する非正規化注意量の期待値をガウス分布のモーメント母関数から閉形式で計算する。さらにValueが出力射影後に残差ストリームへ与える大きさを掛け、各KV対が将来出力へ与える「期待寄与」をスコア化する。低スコアのKV対を削除するため、過去の完全注意行列も未来トークンそのものも必要としない。

この方式は追加学習やモデル構造変更を必要とせず、プリフィル時の一括圧縮とデコード中の継続圧縮の双方へ適用できる。論文ではLlama3.1-8B、Qwen3-8B、Gemma3-12Bに加え、推論モデルQwen-15B-R1、Qwen-7B-R1、OpenMath-Nemotron-14Bを評価し、LongBench、Ruler、Needle-in-a-Haystack、AIME25、MATH-500を用いて既存KV削減法と比較している。代表例ではQwen3-8BのRuler 16kで50%圧縮時92.7点を維持し、無圧縮92.9点にほぼ一致する一方、TOVAは76.2、SnapKVは62.8、KeyDiffは74.5まで低下する。長系列では最大15 GBのピークメモリ削減も報告される。

## 問題設定と背景

KVキャッシュ圧縮で難しいのは、単に「過去に注目されたトークン」を残せばよいわけではない点である。あるKV対の価値は、これから生成されるクエリがそのKeyへどれだけ注意し、対応するValueが残差ストリームへどれだけ大きな更新を与えるかで決まる。ところが圧縮判断時点では未来クエリは未生成である。このため、過去注意量を将来重要度の代理にするTOVAやSnapKVのような方式は、話題転換や後から参照される情報を必ずしも正しく評価できない。

さらに現代の高性能注意カーネルでは、注意行列全体をGPUメモリへ書き出すこと自体を避ける。FlashAttentionはブロック単位でsoftmaxとValue集約を行うため、従来の「過去の注意行列を蓄積して重要度を計算する」設計は高速な実装と衝突する。Expected Attentionが狙うのは、注意行列を要求せず、現在利用できるKey、Valueとクエリ統計だけから未来の重要度を推定することである。

論文はKV対の重要度を、単なる注意重みではなく残差ストリームへの寄与として定義する。時刻tで位置iのKV対が与える更新は `Δh_ti = a_ti W_o v_i` であり、そのL2ノルムは `a_ti ||W_o v_i||` となる。したがってKey側の「どれだけ注意されるか」とValue側の「注意されたとき出力をどれだけ動かすか」の両方が重要である。この分解が後段のスコア設計の基礎になる。

## 手法

### 1. 将来クエリ分布の構成

入力は、圧縮時点までに得られたクエリ活性、現在のKVキャッシュ、各注意ヘッドの射影である。論文は隠れ状態 `h` が近似的に多変量ガウス分布 `N(μ, Σ)` に従うという活性分布の性質を利用する。Queryは `q_t = R_t W_Q h_t` と線形射影とRoPE回転で得られるため、ガウス近似の下ではQueryも平均 `R_t W_Q μ`、共分散 `R_t W_Q Σ W_Q^T R_t^T` を持つガウスとして扱える。

ただし将来の位置ごとにRoPE行列が変わるので、そのままでは各未来位置に別々の分布が必要になる。Expected Attentionは次のT位置についてRoPE行列を平均した `R̄` を用い、未来区間全体を一つの位置平均クエリ分布へまとめる。ここでの出力は、各ヘッドについて将来クエリを表す平均ベクトルと共分散であり、後続の期待注意計算へ渡される。未来トークンそのものを予測するのではなく、「将来クエリがどの方向へ分布しそうか」を統計量だけで表現するのが重要である。

### 2. 期待注意量の閉形式計算

固定Key `k_i` に対する非正規化注意量は `z_i = exp(q^T k_i / sqrt(d))` である。qを上記ガウス分布からの確率変数とみなすと、この指数関数の期待値はガウス分布のモーメント母関数を使って閉形式にできる。具体的には平均Key内積に加え、`k_i^T Σ_q k_i / (2d)` という共分散由来の項が入る。このため、平均クエリに近いKeyだけでなく、将来クエリの分散方向と整合するKeyも高く評価できる。

得られた各Keyの期待非正規化スコアを全Key間でsoftmax正規化し、期待注意重み `â_i` を作る。ここまでの出力は「未来区間のクエリから平均的にどのKeyが注目されそうか」という推定である。過去注意スコアを読み出さないため、完全な注意行列を保持しないカーネルと原理上両立できる。

### 3. 残差ストリーム寄与によるKV順位付け

Keyへの期待注意だけでは、対応するValueがモデル出力へほとんど影響しない場合まで重要と判定してしまう。そこでExpected Attentionは、期待注意重みへ出力射影後Valueのノルム `||W_o v_i||` を掛け、`(||Δh_i||)hat = (â_i + ε)||W_o v_i||` を最終重要度とする。εは注意推定が極端に小さい場合でもValue寄与を完全に無視しないための小さな補正項である。

圧縮器は全KV対をこのスコアで順位付けし、指定圧縮率rに応じて下位r%を削除する。例えば50%圧縮ならスコア上位半分だけを残す。さらに注意ヘッドごとの役割差を考慮し、既存の適応的ヘッド別予算配分を利用して重要ヘッドへ多くのKV枠を割り当てる。出力は縮小されたKey/Value集合であり、その後の通常の注意計算がこのキャッシュを使用する。

### 4. プリフィルとデコードへの接続

プリフィルでは入力プロンプトを処理した後に一度スコアを計算し、生成開始前のKVキャッシュを縮小する。デコードでは生成に伴ってKVが増えるため、同じ期待寄与原理をストリーミング圧縮へ使う。これにより、プロンプト側の長文脈だけを対象とする方式と異なり、長い思考過程を生成する推論モデルの出力側KV増大も対象になる。

追加コストは、クエリ統計の計算、Keyごとの平均・共分散項の評価、Valueノルム計算、順位付けである。特に完全共分散を素朴に扱えば計算量が増えるため、圧縮自体が推論時間を悪化させない実装が重要になる。論文の主眼は品質とメモリの圧縮特性であり、現在のPyTorch実装は最適化済み専用カーネルではない。この点は実運用上の制約として区別して読む必要がある。

## 評価条件

| 観点 | 条件 |
|---|---|
| プリフィル対象モデル | Llama3.1-8B-Instruct（128k）、Qwen3-8B（32k）、Gemma3-12B（128k） |
| デコード対象モデル | Qwen-15B-R1、Qwen-7B-R1、OpenMath-Nemotron-14B |
| 長文脈ベンチマーク | LongBench、Ruler、Needle in a Haystack |
| 推論生成ベンチマーク | AIME25、MATH-500 |
| プリフィル比較対象 | TOVA、SnapKV、KeyDiff、利用可能な場合DuoAttention |
| デコード比較対象 | KNorm、StreamingLLM、KeyDiff |
| 圧縮率 | 0%から90%まで複数点。特に50%前後を実用的な品質維持点として評価 |
| 実装上の特徴 | 学習不要、既存モデルへ適用可能。KVPressとして20超の圧縮方式を同一枠組みで比較可能 |

Rulerでは4kと16kの双方で圧縮率を10、25、50、75、90%へ増やし、無圧縮からの性能低下を比較している。LongBenchでも同様に複数圧縮率を評価しており、単一のheadline値ではなく、どの程度までKVを削っても品質を維持できるかという感度曲線が主な証拠になっている。

| Qwen3-8B, Ruler 4k, 75%圧縮 | 平均スコア | 無圧縮95.3、TOVA 62.4、SnapKV 33.1、KeyDiff 64.4 | 88.3 | 強い圧縮でも情報保持能力が比較方式より高い |
| Qwen3-8B, LongBench, 50%圧縮 | 平均スコア | 無圧縮48.63、TOVA 46.49、SnapKV 46.25、KeyDiff 40.08 | 50.10 | 半分のKV予算でも平均値は無圧縮を下回らず、単なる検索タスク以外でも有効 |
| Llama3.1-8B, LongBench, 50%圧縮 | 平均スコア | 無圧縮46.42、TOVA 44.13、SnapKV 45.07、KeyDiff 46.90 | 47.91 | モデルを変えても50%圧縮で品質を維持 |

Rulerの数値は、Expected Attentionの利点が低圧縮率だけの微差ではないことを示す。Qwen3-8Bの16kでは75%圧縮でも85.6点で、TOVA 68.7、SnapKV 41.7、KeyDiff 66.9を上回る。一方90%まで削ると62.7まで低下するため、「どこまで削っても無劣化」という方式ではない。圧縮率を上げれば情報損失が顕在化するという明確な境界がある。

LongBenchではモデルごとの差も重要である。Qwen3-8Bでは50%圧縮50.10、Llama3.1-8Bでは47.91と無圧縮を上回る一方、Gemma3-12Bでは無圧縮51.04に対し50%圧縮47.51であり、TOVAの50.7より低い。この結果はExpected Attentionが全モデル・全圧縮率で常に最良という意味ではない。分布近似と各モデルの注意特性の相性があり、ヘッド別予算を含めてもモデル依存性が残る。

Needle in a Haystackでは長さ約125kまで、needle位置を変えながら50%圧縮時の検索能力を確認している。長文脈の特定位置だけを残すヒューリスティックではなく、意味的に後で参照されるKVを保持できることを補強する評価である。デコード側ではAIME25とMATH-500で長い推論列を生成するモデルを使い、KVキャッシュが出力側でも増え続ける条件でKNorm、StreamingLLM、KeyDiffと比較している。論文は高圧縮率で特に優位になると報告しており、プリフィル専用の圧縮ではないことを示している。

## 既存研究との差

TOVAやSnapKVは実際に観測された注意スコアを利用してKV重要度を決める。これは直近クエリに対して何が重要だったかは捉えられるが、まだ生成されていない将来クエリに対する重要性は直接扱えない。また注意行列を実体化しない高速カーネルではスコア取得自体が実装上の負担になる。Expected Attentionは、過去注意履歴ではなくクエリ分布から未来注意の期待値を計算する点が異なる。

StreamingLLMのような方式は先頭のattention sinkと最近のトークンを保持するという構造的ヒューリスティックを使うため非常に軽いが、遠い過去にある意味的に重要な情報を選択する能力は限定される。KeyDiffはKey埋め込み間の距離から冗長性を判断でき、注意行列不要という利点を共有するが、残差ストリームへのValue寄与と未来クエリ分布を直接モデル化しない。Expected AttentionはKey側の将来注意確率とValue側の出力影響を一つのスコアに結合する。

DuoAttentionのような学習あり方式に対しては、追加訓練なしで既存チェックポイントへ適用できることが利点である。その代わり、モデル固有の最適な圧縮マスクを学習するわけではないため、分布近似が合わないモデルでは学習方式や別ヒューリスティックが勝つ条件もある。

## 限界・悪化条件

第一に、手法は隠れ状態・クエリ分布をガウスで近似する。論文は複数層・モデルでこの性質を検証しているが、将来クエリ分布が大きく非定常になった場合や、現在観測した統計から分布が急変する場合には期待注意推定が外れる可能性がある。特に話題や推論状態が急に切り替わる長生成では、統計更新頻度と圧縮頻度が重要になる。

第二に、圧縮率は外部から与える必要があり、要求ごと・層ごとに品質制約から最適率を自動決定する機構は中心提案に含まれない。90%圧縮ではRulerやLongBenchで明確な性能低下が出ており、利用可能メモリだけを見て極端な削減率を設定すると品質を損なう。

第三に、Expected Attentionのスコア計算そのものにも費用がある。平均・共分散の推定、各Keyとの二次形式、Valueノルム、top-k選択を行うため、KVメモリが減っても圧縮処理が遅ければエンドツーエンドの遅延改善へ直結しない。論文はメモリ・品質のトレードオフを強く評価している一方、最適化された専用カーネルによる包括的なサービングスループット評価は今後の実装課題として残る。

第四に、LongBenchではモデル依存の例外がある。Gemma3-12Bの50%圧縮ではExpected Attention 47.51に対しTOVA 50.7であり、全条件で最良ではない。したがって「未来分布を使えば常に過去注意より優れる」と一般化せず、モデル・タスク・圧縮率ごとの検証が必要である。

## 実装・再利用性

著者らはKVPressを公開し、Expected Attentionだけでなく20種類以上のKVキャッシュ圧縮法を同じ枠組みで実装・比較できるようにしている。これは論文のアルゴリズム自体とは別の貢献で、圧縮法間の比較条件を揃えやすくする。モデル構造の再学習を要求しないため、既存の長文脈チェックポイントへ後付けしやすい点も実用上重要である。

## まとめ

Expected Attentionの中心的な発想は、「未来トークンを予測する」のではなく「未来Queryの分布を予測し、その分布に対する各Keyの期待注意量を解析的に求める」ことである。さらにValueの出力寄与を掛けることで、注意されやすさだけでなく実際に残差ストリームをどれだけ動かすかまで圧縮判断へ入れる。この構造により、過去注意行列を必要とせず、プリフィルとデコードの両方を同一原理で扱える。

評価では50%前後の圧縮で無圧縮に近い品質を維持する条件が多く、Qwen3-8BのRuler 16kでは92.9から92.7への低下に抑えながらKVを半減している。一方、90%圧縮やGemma3-12Bの一部条件では性能低下が明確であり、圧縮率・モデル依存性とスコア計算コストは残る課題である。したがって本論文の価値は「無条件にKVを削れる」ことではなく、将来注意を直接観測できないというKV圧縮の根本問題へ、分布推定と閉形式期待値という実装可能な解を与えた点にある。
