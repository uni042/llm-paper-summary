# Keeping up with Large Language Models：演算・通信・費用を統合したLLMシステムモデル

## 概要

本論文は、LLMの訓練と推論を実機で試作する前に、計算、階層メモリ、GPU間通信、半導体製造費の関係を同じ設計空間で見積もる解析モデルを提案する。従来のOptimusを土台に、FlashAttentionのタイル処理、混合専門家（MoE）のトークン配送、通信網の形状に適した集合通信、チップレットの製造費を追加した。訓練と推論の両方を扱うが、性能値の多くはモデルによる予測であり、製造した新規アクセラレータの実測値ではない。

一次本文の検証では、8基のA100-40GB上のGPT-2系FlashAttention予測は既報の速度向上1.3～1.7倍に対し予測誤差8%以内だった。別のケーススタディでは、MoE-139Bの解析的な訓練速度向上を同程度の総パラメータを持つMegatron-145Bに対して約6.1倍、FlashAttention併用時は約6.5倍と推定した。これらを単一の汎用的な推論速度向上率と解釈してはいけない。

## 問題設定と既存研究との差

LLMシステムの性能は演算ピークだけでは決まらない。長文注意ではHBMからの読み書き、MoEでは専門家へ送る全対全通信、テンソル並列では部分結果の集約が実行時間を左右する。高速なGPUに変更してもネットワークが詰まれば改善しない。HBMを増やすと推論が速くなり得る一方、チップレット面積・パッケージング・歩留まりを通じて製造費も増える。

基盤のOptimusはテンソル・データ・系列・パイプラインの4次元並列化、階層rooflineによるカーネル時間、集合通信などを扱った。しかしFlashAttentionのSRAMタイル化や、MoEの専門家並列、複数通信網ごとの集合通信アルゴリズムと製造費の結合は不足していた。本研究は既存の予測器を置き換えるのではなく、演算グラフ・資源・費用をつなぐ対象範囲を拡張する。

## 手法：システム表現から性能・費用への処理順

### 1. アクセラレータの資源記述とタスクグラフ

入力はGPUやチップレットの構成、面積・電力制約、演算性能、SRAM/HBM帯域、GPU間リンクの帯域・遅延、モデル形状とバッチ、並列化次数である。マイクロアーキテクチャエンジンは資源制約から演算器・メモリ・通信資源の値を導く。既知のGPUについては実機仕様値を直接与えることもできる。次にLLMの訓練または推論を依存関係付きタスクグラフに展開し、各演算を階層roofline、各集合通信を通信網モデルで見積もる。得られる実行時間を費用モデルと組み合わせ、設計候補の費用対性能を比較する。

### 2. FlashAttentionのタイル処理モデル

通常の注意ではQK転置の積をHBMに書き、softmaxを計算して再度HBMへ書き、確率行列とVの積を求めるため、長文で中間行列の転送が重い。提案モデルはFlashAttention-v1のタイル処理を分解し、実行時間を `t_FA = t_HBM-ld + t_GEMM + t_pt-reduc-ops + t_HBM-st` と表す。HBM読込にはQ/K/Vとオンラインsoftmaxの補助状態、書込には出力と補助状態を含める。タイル幅BはSRAM容量Mとヘッド次元dの関係 `4Bd ≈ M` を使って決める。

タイル内の行列積については演算量とレジスタ・SRAM間転送量を算出し、演算律速かSRAM帯域律速かをrooflineで判定する。マスク・softmax等の要素演算は別項で見積もる。中間の巨大な注意行列をHBMに往復させない利得が見える一方、QKV射影やMLPは自動的に高速化されない。したがって全モデルの速度向上には上限があり、テンソル並列のall-reduceが支配的な場合は利得が縮む。

### 3. MoEと5次元並列化

専門家層は一部の専門家のみをトークンごとに活性化する。モデルはDeepSpeed-TEDのテンソル・専門家・データ並列の組合せを採用し、注意側のデータ並列次数 `DP_MHA` と専門家並列次数 `EP` を結び付ける。簡略化として専門家内のデータ並列 `DP_EXP=1` と置き、`EP=DP_MHA` とする。各専門家の第1線形層は列分割、第2線形層は行分割し、局所計算後のall-reduceを明示的に数える。

ゲートでは入力トークンに対する線形変換とsoftmaxを計算して専門家を選ぶ。専門家容量C、専門家数E、埋込次元D、精度から全対全配送量を見積もり、`T_A2A = E C D × precision / BW_A2A` を用いる。容量を超えたトークンは落とし、余った容量はゼロ埋めするGShard型の仮定に依存する。したがって負荷偏りが極端なときの実時間を十分に再現できない。DP・TP・SP・PP・EPを合わせた5次元の選択肢を探索するが、すべての組合せが同じ通信費になるわけではない。

### 4. 通信網の位相と集合通信

リング、スイッチ、完全結合、二次元メッシュ、および多段の階層ネットワークを表現する。点対点の時間は送信量d、帯域b、ホップ数h、リンク遅延l、必要ならスイッチ遅延Drを使い `D_total = d/b + l×h + Dr` とする。all-reduceはリングにはリング還元、スイッチにはRabenseifner方式、完全結合には直接還元、メッシュには二次元還元を割り当てる。通信のアルゴリズムをネットワークの形状と対応させるため、単純なピーク帯域比較では見えないホップ数と転送段数の差が推論時間に反映される。

### 5. チップレット費用モデル

性能予測からGPU構成と接続情報を費用モデルへ渡す。フロントエンドのチップレット配置・ネットリストと、バックエンドのプロセス・材料・組立・試験コスト、欠陥密度を照合する。概念的には `C = (Σ_i C_die,i/Y_die,i + C_assembly)/Y_assembly` で、チップごとの歩留まりと組立歩留まりを別々に扱う。大きな単一ダイを小さなダイへ分けると歩留まりは改善し得るが、追加接続と組立が必要になる。製造費と性能予測を同じ設計候補に紐付けることがこのモジュールの出力である。データセンター運用費を含む総保有費用の計算ではない。

## 評価条件・主要結果

| 対象・条件 | 指標と比較 | 結果・解釈 |
|---|---|---|
| GPT-2 small 125M / medium 355M、8×A100-40GB、NVLink第3世代、文脈長1K～4K | Megatronに対するFlashAttention-v1速度向上と既報実測との一致 | 速度向上1.3～1.7倍、予測誤差8%以内。4K文脈では1Kより利得が大きいが、比較の文脈長を混同しない |
| GPT-3基底6.7B、バッチ1024、SummitのV100（1ノード6基、各16GB）、TP=4、EP次数を変化 | DeepSpeed-TEDの強スケーリング曲線との比較 | 予測は既報の基準方式と最適化方式の間。256 GPU付近では負荷偏りを過小評価しずれが生じる |
| 16×V100、GPU間NVLink 150 GB/s、all-reduce 64MB～1.5GB | ASTRA-simと実機通信時間との比較 | 本モデルの予測は両者の間に位置。スイッチ遅延の取り込みが差の一因 |
| GPT-2 XL 1.5B、文脈2048、16×H100 NVLink第4世代 | バッチ増加時のFlashAttentionの解析速度向上 | 大きなバッチほど利得増。A100/H100/B200の比較でも演算性能の伸びがHBM帯域の伸びを上回る条件で利得が増える |
| GPT-2 medium、8×A100-40GB、DP=8・TP=1からTP=2,4へ変更 | FlashAttentionの解析速度向上 | DP=8・TP=1で約1.7倍。TPを増すとall-reduceが増え、注意高速化の全体寄与が減る |
| MoE 139B、256×A100-80GB、バッチ512、DP=EP=32、TP=8 | ネットワーク帯域の感度 | 全対全通信が30%超となり得る。帯域増で通信比率は下がるが、極端な帯域増には逓減効果がある |
| Megatron-145BとMoE-139B（活性13B）、256 GPU規模の解析比較 | 訓練性能のモデル予測 | MoEで約6.1倍、FlashAttention併用で約6.5倍。精度が実験で同等と実証された意味ではない |
| GPT-3 175B、1024 GPU、A100類似GPUでHBMスタック4/6/8、半面積GPUで3/4/6 | 1エポック訓練、10億推論要求の費用対時間 | 訓練は演算律速でHBM増の費用増が目立つ。推論はメモリ律速でHBM増が相対的に有利。等重みの複合評価では元のA100構成が良好 |

性能費用ケーススタディの並列条件は訓練でバッチ256、DP16・TP8・PP8・SP8、推論でバッチ32、DP1・TP8・PP1・SP8である。論文の費用対時間曲線はGPU製造費と解析性能の積を比べるもので、実際のクラウド請求額、電気代、保守費を算入した運用費の比較ではない。

## 解釈・既存方式との差

本研究の主眼は、FlashAttention単体を再実装して最速化することではなく、注意演算が速くなった後にどこが律速へ移るかをモデル化する点にある。GPUを増やしてTPを強めれば演算は分散されるが、all-reduceが増えて注意高速化の効果が相殺される。MoEの活性パラメータが少なくても、専門家をまたぐ配送が遅ければ通信が支配する。これらの異なる律速を5次元並列化と通信網位相を通じて同時に比較できる。

また、同じGPU構成でも訓練と推論で最適なHBM容量・帯域の選択が変わる。推論はメモリ帯域が効きやすいため、演算ダイを半分にしてHBMを維持する案が費用を節約しつつ速度を維持し得る。訓練ではその選択が演算不足を招きやすい。この違いは推論向けアクセラレータ設計やSSD/外部メモリの研究で、単純な容量追加と通信費を切り分ける際に有用である。ただし本論文自体はSSD階層を直接評価していない。

## 限界・負の結果

MoE評価では負荷不均衡、重複トークン削減、通信を意識した活性再計算をモデル化していない。特に256 GPUで予測がずれる原因を著者は負荷不均衡の過小評価に帰している。全対全通信時間の式は専門家容量と理想化した通信帯域を使うため、実際の不均衡、輻輳、トークン落ちによる品質影響を網羅しない。FlashAttentionモデルはv1を対象とし、後継実装のカーネル固有最適化まで一般化できない。

費用は半導体ダイ・パッケージ等の製造費であり、電力料金、ネットワーク運用、冷却、障害、クラスタ稼働率を含む総保有費用ではない。各ケーススタディは解析モデルによるwhat-ifであって、新規チップレット製品の実測ベンチマークではない。推論の要求分布や実サービスの尾部遅延の測定も提示されていない。学習性能のMoE対Dense比較にはモデル品質の直接実測を伴わない点にも注意する。
