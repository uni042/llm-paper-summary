# Prompt-in-Decoder：共通入力を一度だけ符号化して複数の出力を並列生成する

## 概要

一つの文書・対話に対して多数の質問や構造化出力項目を処理する場合、encoder-decoder型Transformerは同じ長い入力を繰り返し符号化しがちである。例えば対話状態追跡では、対話履歴が同一でも「ホテルの予約日」「飲食店の人数」など約30個のdomain-slotにそれぞれ回答する。従来のPrompt-in-Encoder（PIE）では、各項目の問いを入力文書と結合してencoderへ渡すため、入力を問いの数だけ再符号化し、cross-attentionでも問いごとに異なるencoder表現を読み出す。この重複が演算量だけでなくメモリ帯域の負担となる。

本研究のPrompt-in-Decoder（PID）は、問いをencoderからdecoderへ移す構成変更である。文書Xを一度だけencoderに通し、共有された表現Mを複数のdecoder側プロンプトZ_uに渡す。各問いに対応する出力Y_uは並列に生成し、最後に構造化出力へ結合する。decoderのself-attention計算そのものは消えないが、encoderの重複実行とcross-attentionにおける共通K/Vの重複読出しを削減する。

T5-base・MultiWoZ 2.4では、PIE比で推論FLOPsを約0.1倍にし、NVIDIA A100で単一入力の処理を1.9倍、最適バッチ時の一入力当たり処理を4.6倍高速化した。共同目標精度（JGA）はPIEの76.3に対してPIDは75.5であり、効率改善に小さな精度差がある。医療要約では逆にROUGE-Lが53.8から54.0へ改善した。これらは専門領域向けT5の実験であり、一般的なdecoder-onlyの70B級LLMの生成性能を示すものではない。

## 問題設定：同じ文書に複数の問いを投げるときの重複

対象のタスクは、共有入力XからU個の異なる出力Y_1,…,Y_Uを求める分解可能な課題である。対話状態追跡ならXは全対話履歴、Z_uはドメインとスロット名、Y_uは該当値になる。診療対話要約ならXは医師と患者の会話、Z_uは診療記録の節名、Y_uは節ごとの要約文となる。放射線レポートの質問応答なら、同じレポートを参照して複数の質問に別々に答える。

PIEは`Y_u = Decoder(Encoder(X, Z_u))`という構成である。問いZ_uをencoderの入力へ含めるため、encoder出力M_uは問いごとに変わる。入力長n_sが長く、問いの数Uが多いと、同じXの埋め込みとattentionをU回計算する。さらにdecoderのcross-attentionでは、それぞれ異なるM_u由来のK/Vを読み込まなければならず、GPU上での再利用が難しい。

一般的なencoder-decoderはencoderの自己注意、decoderの自己注意、decoderからencoderへのcross-attentionという三つの処理を持つ。incremental decodingでは、短い出力トークンを逐次生成する際に重みとK/Vを繰り返し読み出すため、演算器の理論ピーク性能よりメモリ転送が律速になりやすい。ここでの演算強度は「浮動小数点演算回数／読み出したバイト数」であり、同じK/Vを一度ロードして多数のqueryへ適用できれば改善する。

本研究は単純なKV容量圧縮ではなく、**共有可能なencoder側K/Vを問い間で一つにまとめる**ことで、実行時のメモリ読出しと重複符号化を同時に減らす。文書Xと問いZ_uが独立に表現できることが前提であり、問いをencoderへ混ぜることで得られる相互文脈化は構成上失われる可能性がある。

## 手法

### 1. Prompt-in-EncoderからPrompt-in-Decoderへの再配置

PIDでは、encoderの入力を共通文書Xだけに固定し、`M = Encoder(X)`を一度計算する。問いZ_uはdecoder側へ移動し、`Y_u = Decoder(M, Z_u)`として個別出力を得る。Mの内容が問いに依存しなくなるため、同一入力のU個の問いすべてに同じMを再利用できる。論文Figure 1では、PIEでU本に分岐していたencoder経路をPIDでは一本へ統合している。

入力の処理順は、(1) 文書Xの符号化、(2) 共通表現Mの保持、(3) U個のdecoderへ各Z_uと同じMを渡す、(4) 各decoderがY_uを生成する、(5) 出力Y_uを構造化された最終回答へまとめる、となる。従来のモデルを無条件に高速化する魔法の設定ではなく、複数の出力へ分解できるタスク表現と、それに合わせたモデルの学習・推論構成が必要である。

問いをdecoderへ移したことで、各出力の生成は問い固有の状態を持つ。したがってdecoder側self-attentionの計算はU個分残る。性能差の主因はencoder側の共通化とcross-attentionのK/V共有であり、生成ステップ数をU分の1にするという主張ではない。

### 2. Cross-attentionの共通K/Vと演算強度

PIEのcross-attentionでは、問いuごとのencoder表現M_uからK_u、V_uを得る。各decoderのquery Q_uに対してK_uを読み出すため、共通文書部分であっても実行時のメモリ読出しはU回発生する。PIDではMが共通なので、K/Vをまとめて読み、U個のQ_uへ適用できる。論文Figure 2は、Kを共有・broadcastして複数のqueryとの内積を計算する点を図示する。

この変更は、QK積の演算回数が必ず減ることを意味しない。各queryと共有Kの内積は必要であり、算術演算数はほぼ同じでも、K/Vのメモリ読出しを共有することで演算強度が上がる。つまり、FLOPsだけでは評価できない帯域効率の改善がある。入力の長さn_s、出力長n_t、隠れ次元d、問い数U、バッチbを用いた原著Table 1の解析では、encoder計算の主要項がPIEのU倍からPIDの1倍へ減る。cross-attentionのencoder表現読出しも、PIEのU・b・n_s・dに相当する項がPIDではb・n_s・dへ減る。

一方で、モデル重みの読出し、decoder self-attention、各問いの出力トークンの計算は残る。入力が極端に短い、Uが小さい、あるいは出力が長くdecoderの計算が支配的な条件では、共有化による利得は縮小する。このため本研究は単純な「U倍の高速化」を保証していない。

### 3. 並列生成とバッチ形成

PIDでは一つの入力Xに対する複数の短い出力Y_uを並列に処理できる。PIEでも複数の問いをバッチ化できるが、各問いに異なるencoder表現が必要で、入力長に比例する重複計算が残る。PIDは共有Mをバッチ内の問いへ再利用できるため、実行器にとっては少ないメモリ転送でより多くのquery演算を実施できる。論文はA100上で単一入力逐次処理と最適バッチ時の一入力当たり遅延を分けて測定している。

出力を短い節へ分解する副次効果もある。診療記録の長い文章を一度に生成するより、主観的症状・診察・所見・評価計画という四節へ分けると、各生成系列の長さと末尾の品質低下を抑えられる場合がある。ただし、この効果はPIEでも得られるため、PID固有の「encoder共通化」と混同しない。PIEとPIDの比較は、分解済みタスクの中で問いをどちら側に置くかの比較である。

### 4. 学習時のデータ構成

PIE-T5の学習データは`(X, Z_u, Y_u)`の組を問いごとに作るため、同じXがU回登場する。PID-T5は`(X, Z, Y)`として同じ入力に属する問いと出力をまとめられ、符号化を共有したまま学習できる。原著ではT5-base/T5-largeをこの構成で微調整して比較した。PIEより学習FLOPsも大幅に減るが、研究の推論上の貢献は「学習手法の高速化」ではなく、推論時に共有入力を再利用できる構造にある。

本研究はT5を主対象とする。decoder-onlyの一般的なLLMで同じ効果を得るには、共通prefixのKV共有、別々のquery処理、生成の並列性を別の方法で設計する必要がある。既存のprefix cachingやPagedAttentionとは近接するが、PIDはencoder-decoderのcross-attentionで共通表現を再利用するため、同一の実装問題ではない。

## 評価

### 実験条件と指標

| 要素 | 原著の設定 |
|---|---|
| 主モデル | T5-base 220M、T5-large 770M。RadQAにはclinical T5を利用 |
| 比較 | PIE-T5、PID-T5、通常T5、LoRA微調整LLaMA2-7B、文献上の既存最高値 |
| ハードウェア | NVIDIA A100、RTX 2080Ti。Table 3の速度比はA100で測定 |
| MultiWoZ 2.4 | 対話状態追跡、約30 domain-slot。指標JGA（全スロットが一致した対話状態の割合） |
| ACI-Bench | 医師患者対話から四節の診療記録を生成。指標ROUGE-L（参照要約との長い共通部分列に基づく一致） |
| RadQA | 放射線レポートに対する2〜6問程度の抽出質問。指標EM（文字列完全一致率） |
| 推論計算量 | FLOPs比。演算回数であり実時間ではない |
| 実時間 | 単一入力の平均遅延、最適バッチ時の一入力当たり平均遅延 |
| 推論標本 | MultiWoZのテストから512件抽出、ACI-Bench/RadQAはテスト全件 |

JGA、ROUGE-L、EMは尺度の意味が異なるため、数値を横断して比較してはならない。さらにFLOPs比と実測遅延の比は同じではない。論文Table 3の速度比は各データセットのPIE-T5を1.0とした相対値であり、異なるタスクの絶対処理速度を直接比較したものではない。

### 主要結果：精度と実時間の両立

| モデル・タスク | 品質（PIE→PID） | 推論FLOPs（PID/PIE） | A100単一入力速度比 | A100バッチ速度比 |
|---|---:|---:|---:|---:|
| T5-base / MultiWoZ 2.4 | JGA 76.3→75.5 | 0.1倍 | 1.9倍 | **4.6倍** |
| T5-large / MultiWoZ 2.4 | JGA 77.5→76.5 | 0.1倍 | 2.8倍 | 4.2倍 |
| T5-base / ACI-Bench | ROUGE-L 53.8→54.0 | 0.4倍 | 1.1倍 | 1.1倍 |
| T5-large / ACI-Bench | ROUGE-L 54.7→55.2 | 0.4倍 | 1.0倍 | 1.5倍 |
| T5-base / RadQA | EM 53.7→52.4 | 0.6倍 | 1.3倍 | 1.3倍 |
| T5-large / RadQA | EM 55.4→54.6 | 0.5倍 | 2.8倍 | 1.3倍 |

MultiWoZの約30項目に対し、ACI-Benchは4節、RadQAは2〜6問である。共有入力に対する問い数が多いほど、encoderの重複計算削減が大きくなるという機構と整合する。ただし出力長、モデルサイズ、バッチ形状も変わるため、問い数だけが速度を決めると断定できない。T5-large/ACI-Benchの単一入力速度比は1.0倍であり、**すべての条件で実時間が速くなるわけではない**。

### 実測ミリ秒とGPU差

| MultiWoZ 2.4 | A100遅延 | RTX 2080Ti遅延 | JGA |
|---|---:|---:|---:|
| PIE-T5-base | 146 ms | 209 ms | 76.3 |
| PID-T5-base | **78 ms** | **91 ms** | 75.5 |
| PIE-T5-large | 413 ms | 625 ms | 77.5 |
| PID-T5-large | **147 ms** | **163 ms** | 76.5 |

これは論文Table 7の単一入力遅延である。T5-largeではA100で413→147ms（約2.8倍）、RTX 2080Tiで625→163ms（約3.8倍）と、帯域制約が厳しいGPUでも利得が見られる。ただし本実験は専用のT5であり、最新のA100向け高性能decoder-onlyサービングと同一条件で比較したものではない。

### 構造化出力と品質の影響

MultiWoZのテストでは、通常T5-baseのJGAは71.5、PIE-T5-baseは76.3、PID-T5-baseは75.5である。問いごとの分解は通常T5より精度を改善するが、問いをencoderへ混ぜるPIEに比べるとPIDは0.8ポイント低い。T5-largeでもPIE 77.5に対しPID 76.5で1.0ポイント低下する。これは共通表現化による効率利得が、精度面では完全に無償ではないことを示す。

ACI-BenchではT5-baseの全体ROUGE-Lが47.9、PIEが53.8、PIDが54.0であり、PIDは分解済みPIEとほぼ同等である。原著Table 9では、通常T5-baseの第4節が17.9、PIEは35.4、PIDは35.9で、長い一括生成の後段に品質低下があることが分かる。これは「分解して生成する」ことの寄与が大きく、PIDのencoder共有だけで精度が上がったと読むべきではない。

RadQAはT5-largeでPIE 55.4、PID 54.6、文献上の通常T5-largeの最高値55.0であり、PIDが常に精度最良とはいえない。論文は、RadQAの質問はMultiWoZの固定スロットほど構造化されておらず、問いをencoder側に含める利点が残る可能性を指摘する。質問が文書の意味解釈を強く変える場面では、共通の問い非依存表現だけでは十分でないことが示唆される。

### 学習費用と低データ条件

MultiWoZのT5-base学習FLOPsは、通常T5が1.5×10^17、PIEが5.0×10^18、PIDが1.2×10^17と報告される。PIEは各問いを個別訓練例に展開するため学習費用が膨らむ一方、PIDは同じXに属する出力をまとめる。ここは推論速度とは別の実験軸である。学習データ5%（約374例）のMultiWoZではPID-T5-baseのJGA 56.4に対し文献上のCodex-davinciは55.4、1%ではPID 41.1に対して48.4と逆転する。少量データ条件でも常に優位なわけではない。

## 既存方式との関係

PIEは問いをencoderに置くため、問いごとの文脈化は可能だが共通入力を何度も符号化する。PIDは問いをdecoderへ移し、共有encoder表現を一度だけ作る。decoder-onlyモデルのprefix cachingやHydragenも共通prefixを再利用するが、PIDはencoder-decoderのcross-attentionにおける共通K/V読出しまで含めて演算強度を高める点が異なる。FlashAttentionなどのカーネル最適化とは異なる層の設計であり、原著は原理的な併用可能性を述べるが、最新の推論基盤での統合性能を実証してはいない。

## 限界・負の結果・適用範囲

第一に、PIDの適用対象は**一つの共通入力に複数の問いがある、分解可能なタスク**である。通常の単一質問・単一回答ではU=1となり、encoderの共有による利得はほとんど生じない。問いの内容に応じてencoderが文書を選択的に解釈する必要がある場合、問い非依存のMでは品質が下がり得る。RadQAの精度低下はその懸念と整合するが、個別の失敗原因を因果的に特定した実験ではない。

第二に、計算量と実時間は一致しない。T5-largeのACI-BenchではFLOPs比0.4倍でも単一入力速度は1.0倍であり、メモリ転送、並列度、出力長、バッチの影響を受ける。表中最大4.6倍はA100のMultiWoZ・T5-base・最適バッチという限定条件である。別のGPUやトークン長で同倍率を保証しない。

第三に、対象はT5-base/largeという比較的小さなencoder-decoderモデルであり、LLaMA2-7Bは比較対象であってPID化されたLLaMAではない。vLLMの最新版、decoder-only大規模LLM、長文生成、分散GPU、KVオフロード、連続バッチングを組み合わせたE2Eサービングの測定は本論文にない。原著の理論式は主要項を残した近似で、問いトークン長などの定数項を簡略化している。これらを実システムへ移す際は追加検証が必要である。

第四に、モデルをPID構成へ微調整する訓練データ設計が必要である。既存の任意のT5チェックポイントに単純な推論フラグを指定するだけで同等品質が得られるとは示されていない。運用時には問い集合を同一入力へ正しく束ね、出力を元の順序・スロットへ戻す処理も必要となる。
