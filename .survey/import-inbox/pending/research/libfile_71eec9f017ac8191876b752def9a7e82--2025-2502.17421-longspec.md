# LongSpec: Long-Context Lossless Speculative Decoding with Efficient Drafting and Verification

## 概要
長文脈での投機的復号は、短文脈より三つの問題が強くなる。第一に自己回帰型ドラフト自身のKVキャッシュが文脈長に比例して増え、対象LLMとは別の大きなメモリを要求する。第二にEAGLE等のドラフトは数千token以下で学習されることが多く、推論時に数万token以上の位置へ出ると位置分布が学習時とずれる。第三に、複数候補を一括検証する木注意の不規則マスクはFlash Attentionのような長文脈向け高速kernelと相性が悪い。

LongSpecは、512-tokenのスライディングウィンドウ自己注意と対象LLMの既存KVを読むcross-attentionからなる1-blockドラフト、短い学習系列でも大きな位置を経験させるAnchor-Offset Indices、prefix部分をFlash Attentionで計算して候補木部分だけ専用Triton kernelへ分離するHybrid Tree Attentionを組み合わせる。5つの長文脈理解データセット・5 target LLMでFlash Attention自己回帰基準比最大3.26倍、QwQを用いる長推論でもwall-clock最大2.34倍を報告する。

## 問題設定
長文脈投機では「ドラフトが小さい」だけでは不十分である。自己回帰ドラフトが文脈全体のKVを保持すれば、モデルパラメータが小さくてもKV容量が文脈長に比例する。特にエージェントや長い推論では生成中にもドラフトKVが増え続け、対象LLMのKVに加えて二重の状態を持つ。

さらに、短文脈学習では小さい位置indexほど出現頻度が高く、大きい位置indexは十分更新されない。長文脈推論で突然大きい位置へ移るとドラフトの一致率が落ちる。検証側でも通常の木attention maskは不規則なので、規則的なcausal attention向けに最適化されたFlash Attentionの効率をそのまま利用できない。LongSpecはこの三つを独立の機構で処理する。

## 手法

### 定数サイズのドラフトKV
ドラフトは自己注意とcross-attentionの二段構成を持つ。自己注意は直近512 tokenだけを見るスライディングウィンドウに制限し、ドラフト自身が保持するKVを文脈長から切り離す。局所情報だけでは長距離依存を失うため、後段cross-attentionが対象LLMの既存KVキャッシュを参照して長文脈情報を取り込む。

対象LLMのKVは投機の有無にかかわらず必要なので、cross-attention用に長文脈状態を二重保存しない。さらにembeddingとLM headも対象とドラフトで共有し、Llama-3やQwen-2.5のような大語彙モデルで追加parameter memoryを抑える。結果としてドラフト追加KVは文脈が伸びてもwindow分で頭打ちになる。

### Anchor-Offset Indices
通常の位置番号0,1,2,…で短い系列だけを学習すると、大きい位置番号はほとんど訓練されない。LongSpecは一部をanchorとして固定し、それ以外の位置へランダムoffsetを加えるAnchor-Offset Indicesを使い、短い系列でも長文脈で現れる大きな位置番号を学習させる。

学習は短文脈の事前段階から長文脈SFTへ移行する複数段階で行われ、後段では通常位置へ戻す。論文ではAnchor-Offset初期化が実長文脈学習で同じlossへ3.93倍速く到達し、Multi-Newsでは85.98→91.11 tokens/s、RepoBench-Pでは85.21→91.28 tokens/sへ改善している。位置一般化が単なる学習曲線だけでなく受理長と推論速度へつながる。

### Hybrid Tree Attention
投機候補の木を対象LLMで検証するとき、長いprefixは通常のcausal attention、追加候補部分だけがtree maskを必要とする。LongSpecはこの二つを一つの不規則kernelへ押し込まず、長いprefix計算をFlash Attentionへ渡し、候補木の小さい部分をTriton実装の `fused_mask_attn` で処理する。

両部分のattention出力を正規化情報に基づいて集約し、標準的なtree verificationと同じ結果を作る。これにより長文脈の大部分では成熟したFlash Attention kernelを利用しつつ、木構造に必要な柔軟性だけを専用kernelへ限定する。論文では対象attention latencyを標準HuggingFace実装比で約75%削減する。

### 投機復号全体
対象LLMが持つ長文脈KVをcross-attentionで参照しながら、軽量ドラフトが複数候補tokenを生成する。ドラフト側の自己注意は512-token windowなので追加KVは増え続けない。候補は木としてまとめ、Hybrid Tree Attentionで対象LLMが一括検証する。受理された最長部分を文脈へ追加して次のstepへ進む。

対象LLMの検証を最終決定に使うため、近似ドラフトによって最終分布を変更する量子化・枝刈り方式とは異なる。速度はドラフト受理長だけでなく、長prefix検証を高速kernelへ載せられるかにも依存する。

## 主要結果
|条件|結果|意味|
|---|---:|---|
|長文脈5データセット|Flash Attention基準比最大3.26倍|高速attentionを既に使った強い基準の上でも利得が残る|
|コード補完条件の代表例|96.96 tokens/s、3.26倍|平均受理長4.46と高速検証が同時に効く|
|QwQ・4数学推論task|wall-clock最大2.34倍|理解benchmarkだけでなく長いreasoning生成でも有効|
|Anchor-Offsetあり / Multi-News|85.98→91.11 tokens/s|位置学習改善が推論速度へ反映|
|Anchor-Offsetあり / RepoBench-P|85.21→91.28 tokens/s|受理長も3.26→3.39へ増加|
|Hybrid Tree Attention|対象attention latency約75%削減|不規則木部分を分離するkernel設計の効果|

重要な負の比較として、MagicDecは低batch条件ではドラフトが重く、guess lengthが3以上で約0.7倍、つまり自己回帰より遅くなる条件がある。PLDもretrievalが弱いデータでは負の高速化になる。LongSpecは「投機を使えば必ず速い」のではなく、長文脈でドラフト状態と検証kernelを軽量化することが必要だと示している。

文脈長別分析では、最短から最長範囲へドラフト時間は8.91→9.25 ms、検証時間は6.18→6.28 msとほぼ一定で、対象モデル時間は25.63→30.89 msへ増える。定数サイズのドラフト状態とHybrid Tree Attentionが、文脈増加時の追加費用を抑えていることを裏付ける。

## 既存研究との差
EAGLE系の自己回帰ドラフトは対象LLMのhidden stateを使って高い受理率を得るが、ドラフト自身のKVが長文脈で増える。LongSpecは自己注意を局所windowへ制限し、長距離情報を対象LLMの既存KVからcross-attentionで取ることで追加状態を定数化する。

TriForce/MagicDecは長文脈向けに対象モデルの疎KV等をドラフトとして使うが、低batchではドラフト計算自体が重くなり得る。LongSpecは1-blockの専用軽量ドラフトを使う。また木検証についても、汎用tree attentionをそのまま長prefixへ適用せず、Flash Attentionと専用tree kernelへ計算を分解する。

## 限界
LongSpecはドラフト学習を必要とし、Anchor-Offsetを含む段階的な訓練工程が追加される。cross-attentionは対象LLMのKV形式へ依存するため、モデルarchitectureごとの統合が必要になる。ドラフト追加KVは定数化されても、対象LLM本体の長文脈KV容量は削減しない。

主な高速化は低〜中batchの長文脈生成で示され、MagicDecのように大batch・tensor parallel向けの方式とは得意領域が異なる。最大3.26倍は特定モデル・データセット条件の値であり、全条件の保証ではない。またlossless投機で品質を維持する代わりに、ドラフト学習・追加kernel・対象KVへのcross-attentionという実装複雑性を受け入れる。
