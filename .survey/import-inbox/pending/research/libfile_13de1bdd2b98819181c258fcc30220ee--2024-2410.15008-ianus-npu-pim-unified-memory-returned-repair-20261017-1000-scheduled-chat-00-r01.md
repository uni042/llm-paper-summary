# IANUS：NPU・PIM統合主記憶とアクセス調停によるLLM推論高速化

## 概要

IANUSは、大規模言語モデル（LLM）の入力処理と逐次生成を、演算特性の異なる二種類のハードウェアへ分担させる推論専用システムである。ニューラル処理装置（Neural Processing Unit; NPU）は行列・行列積に適し、メモリ内演算（Processing-in-Memory; PIM）は低い演算密度で大量の重みを読み出す行列・ベクトル積に適する。単に二つを接続するだけでは重みを双方のメモリへ複製しなければならず、主記憶容量を浪費する。IANUSは**PIMのDRAMをNPUの主記憶としても使う統合メモリ構成**を採り、同じ重みを双方から利用する。

ただし統合したDRAMは、通常のNPU読み出しとPIM演算を同時に実行できない。この競合を放置するとPIMの利点が消える。そこでPIMアクセス・スケジューリング（PIM Access Scheduling; PAS）を導入し、全結合演算（Fully Connected; FC）をNPUの行列演算器とPIMのどちらへ置くかを解析モデルで選び、注意機構内の依存関係とメモリ使用時刻を組み合わせて実行順序を決める。

論文の主結果は、GPT-2系列における**NVIDIA A100比平均6.2倍、先行DFX比平均3.2倍**の推論高速化である。ただしこれらは主として詳細なアーキテクチャ・シミュレーションで得た結果であり、実チップ統合装置のエンドツーエンド測定値ではない。実証試作では商用PIMとFPGA上の制御器を動作させ、NPUはシミュレータで代用した。したがって「全てを実装したハードウェアがA100より6.2倍速い」とは読めない。

## 問題設定：一つのLLM内に計算律速と帯域律速が混在する

Transformerの入力処理段階では複数トークンをまとめて全結合層へ投入するため、重みを一度読み出して多くの乗算に再利用できる。行列・行列積は演算量が大きく、行列演算器の処理能力が効く。これに対して逐次生成では通常一度に一トークンを処理するため、同じ全結合層が行列・ベクトル積となり、重みを読み込む割に乗算数が少ない。高い演算能力を持つGPUやNPUでも、重みを供給する外部メモリ帯域が律速になりやすい。

原著のGPT-2 XL・A100解析では、逐次生成時の全結合層とフィードフォワード網（FFN）が復号遅延の45.4%を占める一方、層正規化と残差加算は演算量の0.06%未満なのに遅延の13.2%を占める。さらに自己注意が復号遅延の41.4%を占め、その注意内部の66.1%がデータ並べ替えなど非算術処理に由来する。よって単に行列積だけを高速化しても、転置、分割、結合、メモリアクセスの待ち時間が残る。

従来のPIM専用アクセラレータは逐次生成の帯域問題には有利だが、入力処理の行列・行列積や柔軟なベクトル演算を得意としない。逆にNPUだけでは逐次生成のメモリ帯域不足が残る。先行のDFXは複数FPGAを使い生成段階を重視するが、入力処理の計算律速部分には不利となる。IANUSの狙いは、**同じLLMの各演算を最適な演算器へ割り振り、入力から生成まで一貫して速くすること**である。

もう一つの問題は、二種類の演算器が同じモデル重みを必要とする点だ。論文はGPT-2の全結合重みが必要データの約91%を占めると示す。NPU用DRAMとPIM用DRAMを別々に設け、重みを二重配置すれば、同じ総容量でも実質的にモデルに使える容量が減る。重みを複製しなければ、NPUとPIMの間で大量の転送が必要となる。統合メモリはこの二者択一を避けるが、今度は**同一DRAMに対する通常コマンドとPIM演算コマンドの排他制御**が必要になる。

## 手法

### 1. NPUの行列・ベクトル演算器とPIMの役割

IANUSのNPUは、行列演算器（Matrix Unit; MU）とベクトル演算器（Vector Unit; VU）を備える。MUには128×64の処理要素配列を用い、入力処理で大きな行列積をまとめて処理する。VUは16個の4幅VLIW処理器を持ち、層正規化、残差加算、マスキング、Softmax、GELUなどを担当する。活性用と重み用のスクラッチパッドは異なる配置形式を持ち、専用DMAで転送する。

PIMは商用GDDR6ベースのAiMに依拠し、各DRAMバンクの演算器が重みをバンク内で読み、積和演算を行う。入力ベクトルはチャネル側の共有バッファへ置き、各バンクが繰り返し参照する。重み行列を外部へ運ぶ必要がないため、生成段階の全結合演算に向く。ただしPIMの演算機能はNPUのMU/VUほど柔軟ではなく、演算を何でもPIMへ移せば速くなるわけではない。

推論の一層を実行するとき、長い入力系列の全結合はMU、単一トークンに近い低演算密度の全結合はPIM、Softmaxや層正規化はVU、という分担が基本になる。注意ヘッド間の並列性を利用するため、照会・鍵・値生成の重みはヘッド単位でPIMチップへ分散し、他の全結合重みは列方向に分割する。層内の同期は注意出力、残差加算、GELUなど依存関係のある箇所に限定する。

### 2. 統合主記憶のデータ配置とコマンド競合

従来の分割主記憶ではNPU用とPIM用に物理メモリを分ける。IANUSはPIM DRAMをNPUの主記憶にもするため、両演算器が同一重みを別のコピーなしに使える。論文は分割配置と比べ、重複を除くことで重みを保持するための記憶占有を概ね半減できると論じる。これは任意のアプリケーションでメモリ使用量が必ず半減するという意味ではなく、**共有する全結合重みの複製を回避する効果**である。

PIMでは重み行列のタイルをDRAMの行・バンク・チャネルへ配置し、各バンクの処理器を並列に使う。具体的には一つのタイル内の要素を同じバンクの演算器が処理できるように行アドレスを構成し、別の行はチャネル・バンクへ分散する。これはPIMの内部帯域を活かす一方、NPUが同じDRAMへ通常の読み出しを要求する時刻と衝突する。したがって、単なるメモリ共有だけでなく、PIM計算中にNPUが何をしているかまで含む調停が必要になる。

PASはPIM制御器（PIM Control Unit; PCU）を介してPIMコマンドと通常DRAMコマンドを扱い、競合する期間を分離する。メモリを使わないVU演算や、既にスクラッチパッドへ読み込んだデータに対するMU演算はPIM処理と重ねられる。この**演算器の非同期性とメモリの排他性の組合せ**が、統合主記憶を単なる容量節約にとどめない要点である。

### 3. 全結合層の適応的配置：入力トークン数からMU/PIMを選ぶ

全結合層を常にMUへ置くと生成段階で重み読み出しが支配的になり、常にPIMへ置くと長い入力の行列積で演算能力が不足する。IANUSの適応配置は、演算命令列と入力トークン数 `n` を受け取り、MU、VU、DMA、PIMそれぞれの処理時間を解析的に推定する。MU候補では行列タイルの大きさ、重みロードと計算のパイプライン、直前のVU演算中に重みを先読みできる時間まで計算する。PIM候補では対応する演算の所要時間を見積もる。

二つの推定時間を比較して速い方へ全結合命令を割り当て、次の命令列へ反映する。FFNの第一全結合をPIMへ置いた場合、PIMが直後のGELUを支援するため、GELUもPIMへ割り当てる。つまり個々の行列積だけを独立に最適化せず、**直前の先読み機会と直後の活性化演算**を含む局所的な命令系列で選ぶ。

論文の図12では、入力トークン数4・8・16を変えたGPT-2系列の全結合演算で、常にPIMへ置く方式に対して平均1.4倍、常にMUへ置く方式に対して平均1.2倍の高速化を報告する。モデルの埋め込み次元がPIMの2KB行サイズに合うかでも優劣が変わるため、「トークン数が小さければ必ずPIM」という固定閾値ではない。解析モデルが重み配置やパイプライン条件を含めている理由がここにある。

### 4. 注意機構のデータ操作をNPU内で完結させる

注意機構では鍵 `K` の転置、ヘッドの分割・結合、照会と鍵の積 `QKᵀ`、Softmax、注意重みと値の積 `SV` が続く。GPUでは、計算量が小さくてもデータ並べ替えのためのメモリアクセスが無視できない。IANUSは活性用と重み用のスクラッチパッド間にDMAの直結経路と中間バッファを設け、転置のためにDRAMへ書き戻すことを避ける。MU側の重み読み出し順序も工夫して転置を完了する。

入力処理では、鍵生成を優先してその転置を値生成と並行させる。Softmax中に値をMUの重み用スクラッチパッドへ移し、直後の `SV` を待たせない。さらに次の注意ヘッドの重みを先読みし、ヘッド間でDMA、MU、VUの実行を重ねる。これにより、PIM側が同じDRAMへアクセスする機会を不必要に奪わず、自己注意の非算術処理の遅延を短縮する。

### 5. 生成段階の注意演算は「全部PIM」ではない

生成段階の `QKᵀ` と `SV` は形式上は行列・ベクトル積なのでPIMに適して見える。しかし注意ヘッド次元64の場合、PIMのDRAM一行が1024個のBF16要素を持つのに対して、実際に有効な64要素しか使わず、**行利用効率は6.25%**に落ちる。しかもPIMに注意計算を集中させると、MUが空き、PIMが長時間主記憶を占有する。

そこでPASは、重みの大きな全結合演算をPIMへ置きながら、`QKᵀ` と `SV` はMUで計算するように割り当てる。PIMが重みを処理する間に、NPUはスクラッチパッド内の鍵・値を使った注意計算を進める。次のヘッドに必要な鍵・値の先読みを組み込み、ヘッド間の依存をパイプライン化する。データをPIMへ置いたまま演算することより、**PIMとNPUが互いの待ち時間を埋めること**を優先した設計である。

### 6. 命令列から実機試作までの実装境界

評価用の構成ではNPUが4コア、PIMメモリ制御器8個、NPU周波数700MHz、PIM演算器1GHz、GDDR6の通常メモリ帯域256GB/sである。PIMチップごとに32処理器、内部帯域1024GB/sを想定し、4チップ合計の内部帯域4096GB/sを利用する。MUの各コアは128×64の演算配列を備え、活性スクラッチパッド12MB、重みスクラッチパッド4MBを用いる。これらは比較を解釈するためのシミュレーション条件であり、現在の一般的なGPU構成へそのまま置き換えられる値ではない。

試作機はXilinx VCU118 FPGAにPCUとPIMメモリ制御器を実装し、GDDR6-AiM搭載の拡張カードを接続する。NPUのRTL全体は一枚のFPGAに収まらないため、NPU側はシミュレータが命令を発行する。NPUのPIM命令はPCIe経由で制御器へ渡され、PCUが細粒度のPIM命令へ変換する。これは実PIMへの命令発行・メモリ制御と機能正しさの検証であって、NPU実チップとPIM実チップの完全統合による速度測定ではない。

### 動的エネルギーと限界条件

論文はNPU-MEMとIANUSの動的エネルギーを比較する。PIM内部演算の電力を通常DRAM読み出しの3倍と仮定したモデルを用い、NPU演算、通常メモリアクセス、PIM演算の動的成分を合算する。高速化に伴って動的エネルギーが減る傾向を示す一方、**静的電力は公平な比較が困難として計算に含めていない**。したがって論文のエネルギー図をデータセンター全体の電力削減率や実機ワット数と読み替えることはできない。

注意機構を全てPIMへ移す設計は、64次元ヘッドに対してDRAM一行の利用効率が6.25%となるため不利である。統合主記憶は分割主記憶よりメモリ効率に優れるが、NPUのDRAMアクセスとPIM演算が同時にできないため、PASを外すと逆に並列性を失う。図13は、同じ容量での分割配置と統合配置、さらに注意演算のMU/PIM割当と調停有無を分けて比較し、統合だけではなく**適切な調停と割当**が利得に必要であることを示す。

### 大規模化・感度・実証

NPUコア数を4から減らすと入力処理主体の設定で悪化が大きく、PIMチップ数を減らすと生成主体の設定で悪化が大きい。これはMU/VU側とPIM側の律速が異なるという設計仮説を支持する。大規模モデルでは一台のメモリ容量が足りず、6.7Bに2台、13Bに4台、30Bに8台のIANUSをPCIe 5.0×16で結ぶ構成を**シミュレーション**する。A100一台比の平均高速化はそれぞれ2.4倍、3.4倍、5.3倍だが、台数・総演算器数が異なる比較であり、一台同士の性能差を示す値ではない。

実証試作はGPT-2 Base/M/L/XLをWikiText-2で動作させ、パープレキシティ（perplexity; 小さいほど良い）30.92 / 22.60 / 19.39 / 17.48を報告する。これは命令・演算の機能的正しさの確認であり、実機の消費電力や全系遅延を裏付けるものではない。原著の試作構成ではNPUがシミュレータであることを必ず併記すべきである。

## 既存研究との差と適用上の限界

DFXなどの帯域重視のFPGA推論機は生成段階に適するが、入力処理の行列・行列積を十分に速くできない。一般的なNPUは逆に行列積を高速化できるが、生成段階で重みの外部読み出しに足を引っ張られる。IANUSは両者を単に並列接続するのではなく、**同一主記憶の重みを共有し、演算ごとに割当先を選び、メモリ競合を命令列で回避する**という組合せが新しい。

この設計はハードウェア構成に強く依存する。PIM側の行サイズ、バンク並列性、内部帯域、GELU支援、NPUのスクラッチパッド容量とMU形状が変われば、最適な割当も変わる。入力長と出力長の分布が異なる現代の長文脈推論、連続バッチ処理（continuous batching）、MoEのエキスパート転送、KVキャッシュの階層オフロードを評価した論文ではない。バッチ1のGPT-2/BERT中心の結果を、現在の数百億パラメータ級の多利用者サービングへそのまま外挿できない。

また、PIMとNPUがDRAMを排他的に使う制約は消えない。PASは競合時間を短くし計算を重ねるが、任意の命令列で完全な重なりを保証するわけではない。大規模化には複数デバイスの相互接続、モデル分割、通信費用、十分な総メモリが必要であり、論文の複数台結果は実機クラスタ測定ではない。静的電力、製造面積、運用コスト、長期間の障害耐性も包括的に評価されていない。
