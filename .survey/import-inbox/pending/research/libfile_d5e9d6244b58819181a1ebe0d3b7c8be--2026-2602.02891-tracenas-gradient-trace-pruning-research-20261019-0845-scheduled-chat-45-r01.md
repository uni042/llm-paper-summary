# TraceNAS：勾配軌跡の相関を用いた学習不要のLLM構造枝刈り探索

## 概要

大規模言語モデル（LLM）の構造枝刈り（structured pruning）は、Transformerの層、注意頭、MLPチャネルなどを物理的に削除して、推論時の計算量と重みメモリを減らす。しかし、どの部分を削るかを単純な重みの大きさや各層の局所指標だけで決めると、層をまたぐ情報の伝達経路を壊し、性能が回復しにくいモデルを選んでしまう。一方、候補ごとに追加学習を実施して性能を測る探索は、探索費用が枝刈り後の回復学習に匹敵する場合がある。

TraceNASは、事前学習済みモデルの勾配の方向と、構造を削った候補モデルの勾配の方向がどれほど一致するかを、低ランク部分空間で比較する。勾配方向が保たれていれば、候補モデルは元モデルの損失地形上で似た機能を持ち、枝刈り後の継続事前学習（continued pretraining、CPT）で性能を回復しやすいと仮定する。候補を毎回学習させる代わりに、少量の校正データで勾配を計算して順位付けする。

Llama-2-7B、Llama-3.1-8B、Qwen-2.5-14Bを対象に、層の有無と各層の注意・MLPの保持率を同時に探索する。著者は、A100換算で8.5GPU時間の探索が学習を伴う方式の約10分の1の費用であり、H200単体なら探索約2時間と報告する。探索は「学習不要」だが、候補の勾配計算と探索後の20Bトークン継続事前学習は必要である。これを混同して枝刈り済みモデルが無学習で同等精度になると解釈してはいけない。

## 問題設定：局所的重要度では全体の回復可能性を測れない

構造枝刈りでは、例えばある層を削ると後続の層へ届く表現が変化する。注意頭やMLPチャネルの重要度を個別に測っても、複数の層を同時に削ったときの相互作用を捉えられない。重みと活性の積に基づく指標や二次近似の再構成誤差は局所的な感度を測るが、モデル全体がどの程度事前学習済みの機能を保持しているかとは異なる。

学習付きの構造探索は候補ごとに短い微調整や蒸留を行い、回復後の性能を見積もる。しかし多数の候補に対し勾配更新を繰り返すため、GPU時間と新規トークンの消費が大きい。TraceNASが狙うのは、候補を作るたびに学習を回すのではなく、元モデルに対する**機能継承の方向的な整合性**を計測して候補の将来性を推定することである。

著者は、元モデルの事前学習損失に関する勾配方向を基準とし、候補モデルがその方向をどれほど保持しているかを調べる。枝刈りで重みの大きさや活性のスケールは変化するので、勾配の絶対値を比較するだけでは不適切である。そこで標準化されたピアソン相関（Pearson correlation）を使い、スケール変化に比較的頑健な方向指標とする。

## 手法：候補生成から勾配整合性による選択まで

### 1. 深さと幅を同時に表現する候補構造

事前学習済みモデルを、削除候補を全て含む上位ネットワークとみなす。候補は `(d,κ)` で表し、`d` は各Transformerブロックを残すかを示す0/1の深さマスク、`κ` は各層の注意部とMLP部を何割残すかを示す保持率である。層の削除と各層内部の幅削減を別々に指定できるので、全層で同じ割合を削る一様枝刈りだけでなく、敏感な層を厚く残す非一様な構造を探索できる。

全体のパラメータ数は上限C以下に制約し、最小の残存層数も設定する。層を削る場合は残差接続を通して情報を次へ渡す。注意部とMLP部の幅は別々の保持率で決めるため、モデル内での重要度の違いを表現できる。

### 2. 活性と重みに基づく幅マスク

保持率を実際の重みマスクへ変換する際は、各チャネルの重みの絶対値と入力活性のL2ノルムを組み合わせた重要度を使う。これはWandaに近い局所的な指標であり、外れ値的な特徴を持つLLMで単純な重みの大きさだけを使うより妥当な候補を作りやすい。計算費用は二次的な局所再構成より軽い。

ただし、この局所指標がTraceNASの最終的な目的関数ではない。局所指標は「指定された保持率に従って、どのチャネルを残すか」を決める。層間の相互作用を考慮して「各層を何割残すか」を評価するのは、後述する勾配整合性の全体指標である。

### 3. 元モデルを一時的にマスクし、候補の勾配を測る

多数の候補モデルを独立に生成してGPUメモリへ載せるのではなく、元モデルの重みに一時マスクを適用し、候補の順伝播と逆伝播を行う。計測が終わったら元の重みへ戻す。これにより候補ごとの重みコピーや最適化器状態を保持する必要がなくなる。

勾配は全モデルの重みについて保持すると巨大になるため、各線形射影へ低ランク適応（Low-Rank Adaptation、LoRA）を付加し、低ランクの勾配部分空間で比較する。少量の校正トークンから元モデルの勾配軌跡 `g_base` を一度取得し、候補ごとの `g_sub` と比較する。これは「逆伝播をしない」方式ではない。逆伝播で勾配を求めるが、探索中には重み更新を行わない方式である。

### 4. 勾配相関と疎密率による全体スコア

各層・各部分の低ランク勾配を平均と標準偏差で標準化し、元モデルとのピアソン相関 `ρ_l` を求める。さらに各注意・MLP部分の保持率を重みとして `Φ=Σ_l r_attn^(l)ρ_attn^(l)+Σ_l r_mlp^(l)ρ_mlp^(l)` を計算する。相関が高いだけで極端に小さい部分が高評価されるのを防ぎ、残存容量の大きい部分の機能継承を重視する設計である。

相関が高いことは、現在の校正データ上で元モデルの勾配方向と似ていることを意味する。将来のあらゆる下流タスクで性能が保証されるわけではないが、著者は枝刈り後の回復学習結果との順位相関を検証し、この代理指標（proxy）の妥当性を評価する。

### 5. 進化探索と最終モデルの回復学習

探索集団を初期化し、深さのマスクには連続区間の交叉やビット反転、幅の保持率には補間交叉とガウス的な変異を適用する。候補の構造を実体化し、少量の校正データで勾配相関スコアを計算して選抜する。著者の主要設定は30候補×50反復、合計1,500候補である。

探索後に選ばれた構造を実際の小型モデルへ変換し、20Bトークンの継続事前学習で性能を回復させる。この回復学習は推論用モデルを完成させる別工程であり、探索時のGPU時間に含めるべきではない。TraceNASの効率改善は主として「良い構造を見つけるための探索費用」を削減することである。

## 評価条件

| 項目 | 原著の設定 |
|---|---|
| モデル | Llama-2-7B、Llama-3.1-8B、Qwen-2.5-14B |
| データ | FineWeb-Edu。候補1件当たり校正65,536トークン（16系列） |
| 探索 | 集団30、50反復、合計1,500候補 |
| 探索装置 | NVIDIA H200単体で約2時間。図1のA100基準は8.5GPU時間 |
| 回復学習 | 20Bトークン、H200を6基、約16時間 |
| 比較 | ShearedLLaMA、E3-Pruner、DarwinLM、Minitron、Flextron、LoRAP、一様枝刈り |
| 品質 | ARC-E/C、LogiQA、PIQA、SciQ、BoolQ、MMLU、WinoGrande、HellaSwag等 |
| 代理指標の検証 | 回復後精度と代理スコアの順位相関、低ランク次元の感度、異なるモデル系列 |

モデル規模と枝刈り率を揃えて比較する一方、各比較手法の回復学習トークン数や探索ハードウェアが異なる場合がある。例えばMinitronはより多い回復学習予算を使う。探索GPU時間、回復学習GPU時間、最終モデルの品質を分けて読む必要がある。

## 評価結果：代理指標と探索費用

著者は70候補モデルの比較で、勾配相関に基づく代理スコアと回復後の下流精度の順位相関が、スピアマンのρ=0.94、ケンドールのτ=0.82となったと報告する。これは候補の順位付けに強い関連があることを示すが、絶対精度を直接予測できるという意味ではない。また、候補数や校正データ分布が変われば相関も変化し得る。

探索費用はA100換算8.5GPU時間で、学習を伴う構造探索に対して約10分の1とされる。H200では単体GPUで約2時間の探索を実行した。比較するGPU世代が異なるので、8.5時間と2時間をそのままアルゴリズムの高速化倍率として解釈しない。重要なのは、候補ごとに重み更新を繰り返さず、低ランク勾配を使った代理評価で探索できる点である。

Llama-3.1-8Bの枝刈りモデルでは、TraceNASの平均正答率66.60%が一様枝刈りの61.50%を上回った。Qwen-2.5-14Bでは70.34%で、DarwinLMの69.80%、E3-Prunerの65.13%を上回る。Llama-3.1のARC-Challengeは52.26%、BoolQは73.00%と報告される。ただし、Minitronはより高い精度を示す場合があり、その比較では約94Bトークンの回復学習を用いている。TraceNASの20Bトークンの約4.7倍の予算であり、品質だけを比較して最優秀方式を決めるのは適切でない。

## 負の結果と限界

第一に、探索時に追加学習は行わないが、各候補について順伝播・逆伝播で勾配を計算する。探索対象モデルをGPUへ載せられない場合や、校正データの準備が難しい場合に費用がゼロになるわけではない。低ランク勾配を使っても、大規模モデルの候補1,500件の評価は一定の計算資源を必要とする。

第二に、勾配方向の一致は回復可能性の代理指標である。事前学習分布と異なる下流タスク、極端な枝刈り率、長文脈の推論品質、量子化と組み合わせた状態では、順位相関が変わる可能性がある。元モデルの校正データに対して機能を保っても、別の利用条件で同じ精度が得られる保証はない。

第三に、枝刈り後の20Bトークンの継続事前学習は依然として必要である。探索時間が短くても、総圧縮工程のGPU費用は探索と回復学習の合計になる。第四に、注意部とMLP部の保持率を調整するため、実際の推論カーネルが不均一な形状を効率的に扱えるかが重要である。理論上のパラメータ削減がそのまま推論速度の同率改善になるとは限らない。

第五に、原著は7B〜14B級のLlama/Qwen系を中心に評価する。混合専門家モデル（MoE）、CPUオフロード、複数GPUの分散推論、長い対話でのKVキャッシュ費用を直接改善する方式ではない。重みと層を削ることで推論用モデルを小さくする研究であり、推論ランタイム自体のスケジューラやKV配置を最適化する研究とは区別すべきである。
