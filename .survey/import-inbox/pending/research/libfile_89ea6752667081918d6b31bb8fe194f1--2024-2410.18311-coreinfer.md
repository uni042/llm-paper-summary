# CoreInfer: Accelerating Large Language Model Inference with Semantics-Inspired Adaptive Sparse Activation

## 概要
動的疎活性化推論は各tokenでFFN neuronの一部だけを計算すればFLOPsとweight読出しを減らせる。しかしDejaVuやPowerInfer型はtokenごとに別MLP predictorを実行し、active neuron集合を更新するためpredictor latency・memoryと頻繁なresource切替が追加される。

CoreInferは「同じsentence内では重要neuron集合が比較的安定し、意味が近いsentence同士では集合も似る」という観測を利用する。prefill時にsentence-wise core neuronsを一度決定し、decodeでは固定subsetだけを実行する。TITAN XP上のOPT-6.7BではHuggingFace 1.92 token/sに対し19.83 token/s、10.33倍。PowerInfer 7.32 token/sに対して約2.71倍でmemoryも7.28GBへ減る。

## 問題設定
token単位predictorは疎化で省くFFN計算とは別に毎step実行される。PowerInferのOPT-6.7B/TITAN XP例ではpredictor latency 15.96ms、memory 3.36GBを要する。active mapがtokenごとに変わるとweight移動も増え、理論FLOPs削減が実測速度へ直結しない。

## 手法
### core neuron
token activation magnitude上位比率αのneuronをtoken-wise coreとし、sentence内token間で頻繁に現れるneuronをsentence-wise coreへ集約する。STS-B/SICKでcore-neuron集合類似度とsemantic similarityに正のSpearman相関が確認され、LLaMA系にも広がる。

### stability-guided prediction
情報抽出やfew-shot QA/翻訳ではprefill tokenから得たcore neuron集合の安定性を利用し、比率βのsentence core neuronsを選ぶ。選択後はdecode中に再予測しない。

### similarity-guided prediction
zero-shot QA/翻訳ではsemantic clusterと対応core-neuron集合を用意し、入力sentence embeddingに近いclusterから集合を選ぶ。QA/情報抽出では約20%、翻訳では約40%のneuronが原モデルに近い品質を得る目安となる。

### static sparse execution
prefillで必要neuron weightをGPUへ配置し、decode中のactivation mapを固定する。追加MLP predictorと毎token weight swapを不要にする。

## 評価条件
|項目|内容|
|---|---|
|モデル|OPT-6.7B/13B/30B、LLaMA2-7B、LLaMA3.1-8Bほか|
|精度|weight FP16、activation FP32|
|task|XSum、SQuAD、TruthfulQA、TriviaQA、WMT16|
|GPU|A100 80GB、TITAN XP 12GB|
|比較|HuggingFace、DejaVu、PowerInfer|
|主parameter|α=0.4、task別β/γ|

## 主要結果
|条件|baseline|CoreInfer|差|
|---|---|---|---|
|OPT-6.7B TITAN XP|HF 1.92 token/s|19.83|10.33倍|
|同|PowerInfer 7.32|19.83|約2.71倍|
|同 memory|HF 12GB、PowerInfer 9.26GB|7.28GB|predictor不要|
|LLaMA2-70B A100系|Transformer比|17.2 token/s|5.5倍|
|QA/抽出|必要neuron|約20%|task依存|
|翻訳|必要neuron|約40%|強い疎化は不適|

品質は完全一致ではなく、LLaMA3.1-8BのXSumは6.2→5.8、SQuADは54.3→49.7と低下する一方、TruthfulQA等では改善する項目もある。

## 既存研究との差
DejaVu/PowerInferはtokenごとにactivation predictorを走らせる。CoreInferはsentence semanticの安定性で予測頻度をprefill 1回へ下げ、decodeを静的subset実行へ変える。恒久pruningと異なりmodel weight自体を削除せずrequest/taskに応じ集合を変える。

## 限界
sentence中で意味・必要機能が大きく変わる長い生成では固定集合が後半tokenを覆わない可能性がある。taskごとに必要neuron比は20〜40%へ変わり品質も完全無損失ではない。10.33倍は12GB TITAN XPでdense baselineがmemory/I/O制約を強く受ける条件で、高性能GPUでは倍率が縮む。
