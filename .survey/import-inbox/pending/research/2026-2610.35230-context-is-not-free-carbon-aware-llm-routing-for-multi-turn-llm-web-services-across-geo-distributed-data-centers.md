# Context Is Not Free: Carbon-Aware LLM Routing for Multi-Turn LLM Web Services across Geo-Distributed Data Centers

> 複数ターン会話の振り分けで、候補のモデル・GPU・地域のすべてに履歴再計算の炭素を課金し、次ターンで逆戻りしそうな切替をゲートで止めることで、キャッシュを壊す移動を避けて排出を減らす炭素配慮ルーティング方式。

## 概要

LLMのWebサービスは複数の地域のデータセンターで動き、電力網の炭素強度（電気1キロワット時あたりの二酸化炭素排出量）は地域と時刻で大きく違う。年平均ではインドの約705グラムとスイスの約35グラムで20.4倍の開きがあり、評価に使う4地域の中でも時刻ごとに最も清い地域が入れ替わる。クエリを清い地域や小さいモデル、効率のよいGPUへ振れば排出は減るはずで、炭素配慮ルーターと呼ばれる方式がモデルと地域の選択を担ってきた。

しかし会話は状態を持つ。あるターンの処理には、それまでの履歴のKVキャッシュ（過去トークンのキーと値を保存し再計算を省く仕組み）が要り、そのキャッシュは以前のターンを処理した配置先にしか残っていない。別の配置先へ移ると履歴を最初からプリフィルし直す必要があり、その炭素コストは会話が長いほど大きい。ShareGPTではクエリの40.3パーセントが4K以上の履歴を持ち、キャッシュミスはクエリの排出量を履歴2Kから4Kで中央値126パーセント、8K超では632パーセント増やす。既存の炭素配慮ルーターは各ターンを独立したクエリとして扱うため、この再計算を価格に入れておらず、キャッシュを持たない配置先を実際より安く見せる。

本論文のCarbonRouterは、クエリごとにモデル、GPU種別、地域を同時に選ぶオンラインフレームワークで、候補のすべてに「その配置先が持っていない履歴ぶんの再計算」を課金する炭素コストモデルを中核に置く。さらに、今回の切替が次ターンで元へ戻りそうな場合に、学習済みの軽量なゲートがセッションを元の配置先に留める。品質と最初のトークンまでの時間には制約を課し、その範囲で推定炭素が最小の配置を選ぶ。

**代表結果:** ShareChatとShareGPTの実会話を使ったトレース駆動シミュレーションで、CarbonRouterは全ポリシーの中で最も低い排出を記録した。同じモデル・GPU・地域の行動空間を持つ最新の炭素配慮ルーターFairCarbonに対して二酸化炭素を平均16.1パーセント減らし（ShareChat 15.1、ShareGPT 17.0パーセント）、セッション固定の方式に対しては54.3パーセント減らした。削減率は会話が長いほど伸び、30ターン超のセッションでは23.1パーセントに達する。予測品質はFairCarbonを上回り、推定した95パーセンタイルの応答開始時間もShareChatで1.67秒から0.52秒へ下がった。実機測定ではなく、解析モデルによるシミュレーション評価である。

## 問題設定

通常の仕組みでは、ルーターはクエリが届いた時点で、モデルの予測品質、各モデルとGPUの組のエネルギー特性、各地域の現在の炭素強度を見て配置を決める。ここで生じる問題は、エネルギーの見積もりが「履歴はどこでも無料で使える」前提で組まれていることである。実際には、履歴のうち配置先がキャッシュしている部分は安い単価で読めるが、持っていない部分は新規入力と同じ単価で計算し直す。履歴が長いクエリほど、この差し引きが配置間の炭素差を上回る。

論文はこの性質を文脈起因の炭素粘着性と呼ぶ。履歴Hトークンを持つセッションについて、元の地域に留まる排出と、清い地域へ移って再計算する排出を比べると、移動が得になるのは移動先の炭素強度が、キャッシュヒット時のエネルギーとミス時のエネルギーの比を下回る場合だけである。再計算のエネルギーは履歴とともに増えるため、この比は会話が進むほど小さくなり、既定のエネルギー比では履歴4Kで移動先が68パーセント清くなければならず、炭素強度比が0.5なら損益分岐の履歴は約1.8Kトークンになる。つまり最も清い地域は、会話にとっての最善とは限らない。

既存対策の不足は二方向ある。セッションを最初の配置に固定する方式はキャッシュを守れるが、難しいクエリで大きなモデルへ移ったセッションがそのまま残り、ShareChatでは87.5パーセントのクエリが70Bモデルで処理されて排出が増えた。逆にターンごとに最も清い配置を選び直す方式は、履歴トークンの27パーセント以上を再計算し続ける。本論文の着眼点は、この二つを配置ごとの課金で統一し、さらに1ターン先の逆戻りまで見て切替を判断することにある。

## 手法のあらまし

クエリが届くと、まず品質予測器が候補モデルごとに期待品質を見積もり、最良候補の一定割合以上の品質を持つモデルだけを実行可能集合に残す。次にコストモデルが、利用可能な全配置について、モデルとGPUの組のエネルギー係数、その配置がキャッシュしている履歴トークン数、地域の現在の炭素強度から、エネルギーと排出量と応答開始時間を見積もる。再計算ぶんは、キャッシュされていない履歴を新規入力の単価で課金することで見積もりに入る。制約を満たす配置の中で推定炭素が最小のものを提案とし、最後にゲートが、提案がキャッシュを持つ直前の配置先から離れる切替である場合に限り、今と次のターンを合わせた節約見込みを予測して、留まったほうがよいと判断すれば提案を差し戻す。処理後にセッション状態の追跡器が、そのターンの配置先と完了時刻を記録する。ルーターはリクエストルーティング層のポリシーであり、背後のモデルや推論エンジンには手を入れない。

## 手法

### 1. 品質予測とモデル絞り込み — 小さいモデルは十分に良いときだけ候補に残す

この機構が観測するのは、現在のクエリに対する候補モデルごとの予測品質である。論文の評価では公開されているルーター用予測器を使い、現在のクエリと直近の文脈からモデルごとに1回ずつ品質を推定する。保持する状態は品質の閾値であり、最良候補の品質に対する割合として運用者が決める。評価では0.85を使った。行う動作は、この割合を満たさないモデルを、そのクエリの候補から外すことである。最良候補自身は常に対象に残るため候補が空になることはなく、難しいクエリでは大きなモデルだけが残り、易しいクエリでは小さいモデルが入る。減るボトルネックは、品質を犠牲にしてまで小さいモデルへ逃がす誤判断であり、炭素の最適化が品質制約の中でだけ動くようになる。追加費用はクエリごとの予測計算である。失敗条件は予測の外れで、予測品質が実品質とずれる場合は制約自体がずれる。論文の品質指標も実測ではなくこの予測値であり、この点は評価の限界として明記されている。

### 2. キャッシュ配慮の炭素コストモデル — 持っていない履歴は全候補に課金する

この機構が観測するのは、候補配置ごとに、そのセッションの履歴のうち何トークンがキャッシュされているかである。この数はディスパッチ時にサービング側から得る。あわせて、モデルとGPUの組ごとに、未キャッシュ入力、出力、キャッシュ済み履歴の3種類のトークン単価をオフラインのプロファイルとして保持する。行う動作はエネルギーの見積もりで、キャッシュ済みの部分はキャッシュ単価、残りの履歴と新規入力は入力単価、出力は出力単価で積み上げ、地域の炭素強度を掛けて排出量にする。全部キャッシュされている場合との差が、その配置における再計算ペナルティとして自動的に現れる。応答開始時間も同じ考え方で、プリフィルする量が未キャッシュぶんだけになる式で見積もる。減るボトルネックは、キャッシュを持たない配置先の見かけの安さであり、セッションは清い地域や小さいモデルの利得が再計算を上回るときだけキャッシュを離れる。追加費用は、配置ごとのキャッシュ状態の取得と、全候補への線形時間の見積もり計算である。失敗条件はプロファイルのずれで、エネルギー単価の比が実機と違えば判断が傾く。ただし絶対値ではなく比だけが順位を決めるため、論文は比の範囲を振った感度分析で結論の頑健さを確認している。なお、この見積もりはネットワーク転送、待ち行列、キャッシュ検索の時間を含まない計算側だけの近似である。

### 3. CCAR — 制約の中で推定炭素が最小の配置を選ぶ貪欲な振り分け

ルーティングアルゴリズムであるCCAR（炭素とキャッシュを配慮するルーティング）が観測するのは、実行可能集合と各候補の推定排出量である。行う動作は三段で、まずキャッシュ状態を取得して品質と応答開始時間の制約を満たす配置を残し、制約を満たす配置が応答開始時間の上限だけを理由に消える場合は上限を緩めて最善努力で処理し、次に全候補の推定排出量を計算して最小のものを提案とする。保持する状態はセッションごとの直前の配置先と完了時刻で、ターンは逐次に処理される。減るボトルネックは配置判断そのもので、候補数に比例する時間で終わるため、クエリごとの判断の追加遅延は無視できる水準に収まる。将来の最適化を諦める代わりに即時性を取る設計であり、残りターン数や将来の炭素強度が分からない以上、厳密なオンライン最適化は不可能だという前提に立つ。失敗条件は近視眼性で、今回の最小配置が次ターンのキャッシュ状態を悪くする場合がある。その穴を埋めるのが次のゲートである。

### 4. 学習済みゲート — 次ターンで戻る切替をその場で止める

ゲートが観測するのは、切替の機会にだけ得られる特徴量で、両候補の推定コスト、キャッシュ状態、サービング側が報告するメモリ圧迫などである。保持する状態は勾配ブースティングで学習した回帰器と、セッションを分けた検証で選んだ閾値である。行う動作は、今のターンと次のターンを合わせて「留まることで節約できる炭素」を予測し、閾値を超えたら提案を棄却してキャッシュを持つ直前の配置先に留めることである。予測器は他のセッションの実績で学習し、2ターン分の実績差を当てに行く。減るボトルネックは往復切替の二重再計算で、一度離れて次に戻ると、元の配置先でキャッシュが追い出されていれば履歴をもう一度作り直すことになる。アブレーションでは、ゲートを外すと排出が3.5パーセント増えるのに対して推定の95パーセンタイル応答開始時間が71.4パーセント増えており、ゲートの主効果は遅延側にある。追加費用は切替機会ごとの予測器の呼び出し1回である。失敗条件は予測の外れと、長いセッションほど介入が増えることで、30ターン超ではセッションあたり4.1回の切替を止める。閾値を無限大にすればゲートなしと等しくなるため、運用者は感度を見て無効化もできる。

## 評価

### まず見るところ

- **結論:** キャッシュ再計算への課金が削減の主因で、最も清い地域で処理するクエリの割合はFairCarbonとほぼ同じ57パーセントなのに、再計算する履歴トークンの割合が27.7パーセントから9.4パーセントへ減ったことが、16.1パーセントの排出削減を生んだ。
- **速度・効率:** 推定の95パーセンタイル応答開始時間は、キャッシュを無視するルーターの1.67秒前後に対して0.52秒（ShareChat）だった。再計算が減るため、炭素と遅延が同じ方向に改善する珍しい結果である。ただしこれはプリフィル時間だけから推定した値で、ネットワークや待ち行列を含まない。
- **品質:** 平均予測品質はセッション固定方式より2.1パーセント低いが、FairCarbonよりは高い。固定方式の品質が高いのは、難しいクエリで大きなモデルへ移ったまま戻らない過剰供給の副作用だと論文は説明する。
- **メモリ・入出力:** 地域の容量とKVメモリはエミュレーションで与えられ、容量が締まるほど削減率は下がる。実データセンターでの測定ではない。
- **評価の強さ／注意点:** 実会話トレースと実炭素強度を使う点は強いが、エネルギーと遅延は公表データ由来の解析モデル、品質は予測値であり、実機での検証は論文自身が今後の課題としている。

数値の読み方として、削減率は比較対象ごとに意味が違う。セッション固定に対する54.3パーセントは「炭素を無視した場合との差」、FairCarbonに対する16.1パーセントは「キャッシュを無視する炭素最適化との差」で、本論文の機構の純粋な寄与に近いのは後者である。さらに課金とゲートの内訳はアブレーションで分かれており、課金が炭素、ゲートが遅延に主に効く。

### 感度・スケーリング・ストレス条件

エネルギー比を振ると、削減率は9.7から18.8パーセントの範囲で常に正だった。キャッシュ単価比が小さいほど、また出力対入力比が小さいほど、履歴がクエリのエネルギーに占める割合が上がり削減も大きくなる。地域容量を締めると削減率は15.1パーセントから9.4パーセントへ下がり、最も清い地域が早く満杯になって両方式とも汚い地域を使わざるを得なくなる。品質要件を厳しくすると、容量に余裕がある場合だけ削減率が下がる。論文が評価していない軸として、実機のエネルギー測定、ネットワーク遅延や待ち行列を含むエンドツーエンド遅延、地域間のKVキャッシュ転送との比較があり、これらは未評価と明記されている。

### 立ち上がり・内部挙動

ゲートの予測器は他のセッションで学習するため、新規セッションへの適用に追加のウォームアップは要らない。内部指標として、最も清い地域で処理されたクエリの割合がFairCarbonとほぼ同じであることが示され、削減が「清い地域の利用増」ではなく「再計算の回避」から来ていることが裏づけられている。

### 評価上の制約

- 実機測定ではなく、エネルギーと遅延は公表データから作った解析モデルによる推定である。
- 品質は予測器の出力であり、実際の回答品質を判定したものではない。
- 遅延モデルはプリフィル時間のみで、ネットワーク、待ち行列、スケジューリングを含まない。
- 地域容量とキャッシュの追い出しはエミュレーションであり、実データセンターの挙動とは異なりうる。

## 既存研究との差

地理的負荷分散や時間シフトなどの炭素配慮コンピューティングは、ワークロードを固定されたものとして扱い、移すコストが小さい前提に立つ。LLM推論の炭素配慮研究では、モデルを固定して地域だけを選ぶ方式や、エージェントタスクをオフラインで計画して移す方式があり、後者は再計算ペナルティを課金するが対話型の到着には使えない。炭素配慮LLMルーターのGAR、CEDAR、FairCarbonはモデルや地域をクエリごとに選ぶが、会話のターンを独立に扱い、キャッシュを離れる再計算を価格に入れていない。本論文の差は、モデル・GPU・地域の同時選択にKVキャッシュの局所性を課金として組み込んだ点と、1ターン先の逆戻りを見るゲートを足した点にある。キャッシュを配慮するサービング側のスケジューラが遅延のためにキャッシュ所在地を使うのに対し、ここでは同じ情報を炭素の判断に使う。

## 限界・実装状況

- 評価はトレース駆動シミュレーションであり、エネルギーとプリフィル遅延は実測ではなく解析モデル、品質は予測値である。実サービングエンジンでの実測検証は今後の課題と論文が明記する。
- 遅延モデルはネットワーク遅延、待ち行列、地域間のKVキャッシュ転送を扱わない。転送でキャッシュを運ぶ方式との比較は未評価である。
- ゲートの予測器は過去セッションへの依存があり、ワークロードの分布が変わった場合の再学習の要否は未評価である。
- 炭素強度はディスパッチ時点の値でリクエスト全体に適用する近似であり、長い生成中の強度変化は見ていない。
- 実装はルーティング層のポリシーとして提示され、成果物は匿名リポジトリで公開されている。本番サービスへの導入実績は論文中に示されていない。

## 一般的な実装上の含意

第一に、状態を持つワークロードの配置判断では、移動先の単価だけでなく「持っていない状態の再構築」を全候補へ課金しないと、見積もりが系統的に歪む。これは炭素に限らず、遅延や金銭コストを目的関数にするルーターでも同じである。第二に、判断が1ターンで完結しない場合は、今回の決定が次回の選択肢をどう変えるかを、厳密な将来予測ではなく学習した小さなゲートで近似するだけでも往復の無駄を大きく減らせる。第三に、最も資源効率のよい配置が状態の所在地と一致しないとき、利得は会話やセッションの長さとともに変わるため、固定の閾値ではなく状態量に応じた損益分岐で判断すべきである。
