# AHASD：モバイルNPU・PIMの非同期投機的復号と先読み制御

## 概要

投機的復号（speculative decoding）は、小さな草稿モデル（draft language model, DLM）が複数の候補トークンを生成し、大きな目標モデル（target language model, TLM）がまとめて検証することで、高価な目標モデルの逐次実行回数を減らす。端末側ではメモリ帯域と電力が限られるため、計算密度の高い目標モデルをニューラル処理装置（neural processing unit, NPU）、帯域に敏感な草稿モデルをメモリ内演算（processing-in-memory, PIM）へ割り当てる構成が有望である。しかし草稿長を実行時に変える適応的な投機的復号では、装置ごとの処理時間が毎回変動する。従来の演算子単位の同期実行では一方の装置が待機し、単純に非同期化すると検証されない草稿を先読みし過ぎて棄却時の計算が無駄になる。

AHASDはこの二つの問題を一体で扱う、モバイルNPUとLPDDR5-PIM向けの異種計算アーキテクチャである。草稿生成と検証をタスク単位で切り離し、非同期キューで接続する。さらに草稿の予測エントロピー履歴と先行バッチ数から先読み継続を判断するEDC（Entropy-History-Aware Drafting Control）、NPU/PIMの残り実行サイクルからPIM側の小規模事前検証を挿入するTVC（Time-Aware Pre-Verification Control）を設ける。LPDDR5-PIMには注意演算用のAAU（Attention Algorithm Unit）とランク単位の高速切替制御を追加する。論文はサイクル精密シミュレーションでGPU単体比最大4.2倍の処理量、最大5.6倍のエネルギー効率、SpecPIM比最大1.5倍の処理量を報告する。これらはシミュレータ上の比較であり、量産スマートフォンの実機測定ではない。

## 問題設定と設計の動機

### 草稿長変動が同期実行を不安定にする

固定長の投機的復号では草稿生成と検証の仕事量を比較的見積もりやすい。しかし実際にはモデルが次トークンにどれだけ自信を持つかが文脈で変わるため、草稿長を可変にした方が不要な生成を抑えられる。演算子単位でNPUとPIMを交互に同期させると、草稿が長い場面ではPIMが律速となりNPUが待機し、短い場面ではNPUの検証が律速となりPIMが待機する。原著はLLaMA2-1.3Bを草稿、LLaMA2-7Bを目標にした予備解析で、PIMの遅延比率が12.3～84.2%の範囲で変動することを示した。この変動幅が、固定的な演算子配置の限界を示す。

タスク単位の非同期実行なら、PIMが草稿を生成している間にNPUが前の草稿を検証できる。しかしNPUからの承認を待たずに次の草稿を作ると、先行する候補が誤りだった場合、後続の候補は無効になる。低信頼の文脈では、非同期化により装置の稼働率が上がっても、正しい出力へ寄与しない計算が増え得る。AHASDは「非同期化だけでよい」という仮定を捨て、草稿を作るべきか、先に一部を検証すべきかを動的に選ぶ。

### 異種装置への役割分担

目標モデルの検証には高い計算密度があり、行列演算器を備えたNPUが向く。草稿モデルの生成は重み転送・注意処理などで帯域制約を受けやすく、LPDDR5-PIMへ配置する。CPUは非同期キューと制御器を管理する。原著の図5では、未検証草稿キュー、フィードバックキュー、事前検証キューを介してNPUとPIMの依存を整理している。タスク内の演算順序は保ちつつ、装置間で異なるタスクを並列に進める。これにより、草稿長の変動で装置間の待機が増える問題を減らす。

## 提案機構

### 1. タスク単位非同期スケジューリング

草稿モデルの生成をPIM、目標モデルの検証をNPUへ固定的に割り当てるだけでなく、両者を非同期キューでつなぐ。検証結果が返る前にPIMが先行草稿を生成できるので、演算子ごとの同期待ちを回避できる。一方、検証結果によって先行草稿が無効化される可能性があるため、CPU側で草稿と検証の進捗を追跡し、棄却された先読みをロールバックする必要がある。非同期化は計算資源の利用率を改善するが、採択率低下を引き起こすという負の効果も同時に生じる。

PIM側には、非線形関数・注意の行方向集約をローカルに処理するAAUを加える。中間値をNPUへ頻繁に往復させずに注意演算を完結させることを狙う。さらに草稿モデルと目標モデルのパラメータを異なるPIMランクに配置し、ランク単位のゲーティングで草稿生成から事前検証へ切り替える。論文では切替時間をマイクロ秒未満とし、装置のアイドルを減らす。AAUは面積と動的消費電力を増やすため、通信削減による利益が上回るかを評価する必要がある。

### 2. EDC：エントロピー履歴による先読み抑制

草稿モデルが1バッチを生成するたびに、出力確率のソフトマックス・エントロピーの平均を計算する。大きいエントロピーは予測が不確かであることを示し、後続草稿の採択率が下がる可能性がある。EDCはこの平均エントロピーを、事前に観測した上限 $H_{max}$ までの8区間へ量子化し、局所履歴表LEHTへ保存する。さらに、NPUによる検証に対してPIMが何バッチ先行しているかを3ビットのLLR（Leading Length Register）で保持する。

履歴エントロピーは前半・後半の2群の平均へ集約し、LLRと結合して9ビットの索引を構成する。これをパターン履歴表PHT（Pattern History Table）へ与え、過去の採択結果を学習したカウンタから先読み継続の可否を決める。検証後に草稿が完全採択されれば対応カウンタを増やし、棄却されれば減らす。局所履歴は検証結果に応じて確定・巻戻しを行い、まだ検証されていない草稿のエントロピーを無条件に真実として使わない。これは重い追加ニューラルネットワークを学習するのではなく、ハードウェアの小規模な履歴表で状態依存の予測を行う方式である。

EDCの目的は、採択率が低い場面で「とりあえず先読みを続ける」ことを止め、PIMの計算を無効な草稿へ浪費しないことである。原著の図8では、非同期化だけで低下した採択率がEDC追加で回復し、処理量とエネルギー効率も改善した。ただしエントロピーと採択の関係はモデル・文脈に依存し、PHTの初期学習期間や分布変化の影響は残る。

### 3. TVC：残り時間に応じた事前検証

EDCが先読みを止めた場合でも、PIMを単純に休止させるとNPUの次の検証に必要な草稿が尽きる可能性がある。TVCはNPUとPIMの実行時間をサイクル数で予測し、NPUが現在の検証を終える前に、PIMが小さな草稿集合を事前検証し、必要なら少なくとも1つ新しい草稿を作れるかを判定する。残り時間が足りなければ事前検証を挿入しない。これにより、無効な先読みを止めつつ、NPUを次タスク待ちで遊ばせない。

NPU側の予測は、最近4回の「KV長あたり実行サイクル」の平均に今回のKV長を掛ける。PIM側の草稿生成と事前検証も、最近4回の「草稿長あたり実行サイクル」から所要サイクルを見積もる。起動直後の履歴不足には事前プロファイル値を用いる。NPU側の残りサイクルから現在経過分と最低1草稿の生成費用を引き、残余でPIM側の事前検証を何トークン処理できるかを求める。原著の式はPIMとNPUの周波数比を換算している。平均値による簡易予測であるため、極端な遅延変動や突発的なメモリ競合に対する厳密な最悪時刻保証ではない。

## 評価方法

原著はONNXimとSAITPublic-PIMSimulatorというサイクル精密シミュレータを接続し、NPU・LPDDR5-PIM・CPUの非同期実行を評価した。CPU側制御にはXiangshanベースのSoCモデルを使用する。実際のモバイルSoCにAHASDの全機構を搭載して測定した結果ではない。比較対象は、GPUで草稿と検証を順番に実行するGPU-only方式と、GPU+PIMで演算子単位の並列化を行うSpecPIMである。GPU基準にはRTX 4090 Laptop（1.335GHz）が用いられ、AHASD側はモバイルNPU+LPDDR5-PIMのモデルなので、性能比は単一GPU上でのソフトウェア最適化率とは異なる。

| 項目 | 原著表1・2の設定 |
|---|---|
| 小規模 | 草稿OPT-1.3B、目標OPT-6.7B |
| 中規模 | 草稿LLaMA2-7B、目標LLaMA2-13B |
| 大規模 | 草稿PaLM-like 8B、目標PaLM-like 30B（アーキテクチャと規模を模した代替モデル） |
| 量子化・生成 | 全モデルINT8、バッチ1、生成長1,024、Alpaca入力 |
| 草稿長制御 | SpecDec++、SVIP、AdaEDL、BanditSpec |
| NPU | 行列演算16 TOPS、ベクトル演算8.2 TOPS（INT8）、2計算チップ、1GHz、スクラッチパッド8MB |
| PIM | LPDDR5-PIM 16ユニット、102.4 GOPS（INT8）、4GB/ランク×16、チップ内256GB/s、チップ外51.2GB/s |
| 面積見積り | CACTI、Yosys、OpenROAD、28nmプロセスを用いた論理・SRAM合成 |

実験は異なるモデル規模と4種の草稿アルゴリズムを横断しているが、モデルの実運用分布やバッチサイズを網羅するものではない。PaLM-likeは原著が明示する代替モデルであり、Googleの実モデル重みを評価したと解釈しない。モデル規模ごとの性能変動を含むため、「最大値」を全条件の平均と混同してはならない。

## 定量結果：非同期化の効果と制御器の寄与

### 構成要素別の消去実験（図8）

| 構成 | GPU-only比の平均処理量 | GPU-only比の平均エネルギー効率 | 主な効果 |
|---|---:|---:|---|
| NPU+PIM非同期 | 2.2倍 | 1.9倍 | 演算子単位の同期待ちを削減。ただし平均草稿採択率が25.1%低下 |
| +AAU | 2.7倍 | 2.6倍 | 注意の非線形演算・集約をPIM内に局所化 |
| +EDC | 3.4倍 | 4.5倍 | 低信頼草稿の先読み抑制で採択率が24.6%回復 |
| +TVC（全機構） | **3.8倍** | **5.2倍** | PIM事前検証の挿入を制御してNPU待機を抑制 |

この表は原著本文に記載されたモデル・アルゴリズム横断の平均値である。最大値は別の比較であり、GPU-only比の最大処理量4.2倍・最大エネルギー効率5.6倍、SpecPIM比の最大処理量1.5倍を報告する。SpecPIMに対するエネルギー効率改善は本文では平均約1.24倍と説明される。構成要素の効果は単純な足し算ではなく、EDCによる採択率の改善とTVCによる待機削減が相互作用する。

EDCを入れない非同期方式では採択率が25.1%下がるという負の結果が重要である。計算装置を並列に動かしても、無効な草稿へ演算を使えばエネルギーが浪費される。EDCの追加で採択率が24.6%回復し、処理量は2.7倍から3.4倍へ、エネルギー効率は2.6倍から4.5倍へ伸びた。TVCはEDCの採択率をわずかに乱すが、NPUの草稿不足待機を減らすため最終処理量は3.8倍となる。LLaMA2+AdaEDLではEDC追加によりAAU構成比33%高速化した一方、OPTでは改善が10%未満という条件差も報告されている。

### 面積・電力費用（原著表3・4）

| モジュール | 合成面積 | LPDDR5-PIMダイ比 |
|---|---:|---:|
| EDC | 0.05 mm² | 0.10% |
| TVC | 0.03 mm² | 0.06% |
| 非同期キュー | 0.01 mm² | 0.02% |
| AAU | 1.25 mm² | 2.50% |
| 合計 | **1.34 mm²** | **2.68%** |

面積の大半はAAUが占め、制御器とキューの合計は0.09mm²に満たない。28nm合成による見積りであり、最終レイアウトやパッケージ制約を含む量産製品の実測面積ではない。原著表4はNPU+LPDDR5を1.0とした電力・処理量の別比較を提示する。NPU+LPDDR5-PIMはLPDDR5電力1.90倍、NPU電力1.10倍、処理量2.20倍、トークン当たりエネルギー0.64倍。AHASDでは順に2.00倍、1.15倍、3.10倍、0.48倍である。メモリ側の瞬時電力が約2倍になっても、完了までの処理時間短縮によりトークン当たりエネルギーが半減するというトレードオフを示す。原著本文は「約50%のエネルギー削減」と表現するが、表の0.48倍に対応する削減は52%である。

なお、著者公式実装リポジトリの2026年10月時点のREADMEには、追加ハードウェア合計0.901mm²など原著表3とは異なる値がある。READMEは別の原稿版や実装の改訂を示している可能性があるが、その理由を原著本文だけで断定できない。本稿では論文v3の表3を正本として扱い、両数値を混ぜて平均したり、無断で書き換えたりしない。

## 限界・実用性・研究上の評価

第一に、性能値はサイクル精密シミュレータに基づく。NPU/PIM実機の製造ばらつき、実際のLPDDR5制御器、OS・ドライバ、熱・電力制限、ホストとの転送遅延を完全に再現できる保証はない。GPU-only比較はRTX 4090 Laptopを使い、AHASD側は専用ハードウェア構成であるため、同一チップ上でソフトウェアだけを切り替えた比較ではない。第二に、論文の主な設定はINT8・バッチ1・生成長1,024で、量子化形式やバッチが変わるとPIMとNPUの負荷分担が変わる。第三に、PIMの追加演算回路が必要なので、既存の通常LPDDR5搭載端末へソフトウェア更新だけで導入できるわけではない。

第四に、EDCの履歴表はエントロピーと採択率の関係を学ぶが、文脈が急変したときや草稿モデルが不確実性をうまく校正できていない場合、先読み判断が不適切になる可能性がある。第五に、TVCの時間推定は最近4件の平均に依存し、最悪遅延の厳密な保証ではない。第六に、エネルギー効率の改善と電力消費の低下は同じではない。表4ではLPDDR5側の消費電力は基準の2倍で、単位トークン当たりエネルギーが0.48倍になったという区別が必要である。

また、草稿生成を先行させるほど無効計算が増えるという原著の負の結果は、異種ハードウェアでの投機的復号を考える上で重要である。同期削減だけを最大化するのではなく、採択率・先行深さ・目標モデル側の空き時間を同時に制御する必要がある。AHASDはEDCとTVCを分けることで、推論内容の不確実性とハードウェア実行時間という異なる信号をそれぞれ扱っている。

## 関連方式との差

SpecPIMは演算子単位のGPU/PIM並列化を用いるが、適応草稿長によるタスク時間の揺らぎに対応しにくい。AHASDは草稿モデルと目標モデルをタスク単位に切り離すことで同期待ちを減らし、その副作用である棄却草稿の計算浪費をEDCで抑える。TVCは装置間の時間予測を使い、PIMでの事前検証がNPU待機を生まない範囲に限定する。AAUは注意演算の局所化、ランク単位のゲーティングは草稿生成と事前検証の切替を担う。したがって新規性は特定の草稿モデルや単一の採択規則ではなく、**非同期実行・信頼度履歴・時間予測・PIM回路**を共同設計したことにある。

この論文はGPU単体の汎用LLM推論ソフトウェアというより、モバイルSoC向けの異種メモリ計算アーキテクチャ研究に位置付けられる。Windowsの単体GPUへそのまま移植できる成果ではないが、投機的復号のタスク分割、非同期キュー、草稿先読み抑制、動的な検証タイミング制御は、異なるアクセラレータやCPU/GPU協調推論にも応用可能な設計原理を提供する。
