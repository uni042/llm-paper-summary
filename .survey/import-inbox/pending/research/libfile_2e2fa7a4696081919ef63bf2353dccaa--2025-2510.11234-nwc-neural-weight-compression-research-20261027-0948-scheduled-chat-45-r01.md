# Neural Weight Compression：LLMの重みを学習済みneural codecで圧縮する

## 概要

Neural Weight Compression（NWC）は、LLMの重みを手作業で設計した一様量子化やHadamard回転だけで圧縮するのではなく、**重み分布からencoderとdecoderを学習**して圧縮する方式である。画像・音声向けのneural compressionを重みに適用する際、層ごとに行列形状とscaleが異なる問題、重みの二乗誤差がそのままモデル出力の劣化に対応しない問題、圧縮済み重みの誤差が後続層へ伝播する問題を扱う。著者らは列単位の正規化と長さ16のchunk化、Hessianによる重要度別rate allocation、層内・層間の誤差補償を組み合わせる。

Llama3-8Bの重みを学習データとしたcodecをLlama2-7B/13Bなどへ評価し、4〜6bitの中〜高ビット幅で良いPPL・正解率と圧縮率の折衷を報告する。ただし極低ビット、特に3bit未満ではQTIPの方が良い条件がある（原著Appendix B.2）。また**圧縮後のLLMをそのまま高速実行できるカーネルは未提供**であり、codecの復号には256×256の重みテンソル当たり14.615msを要する（Appendix B.5、RTX6000 Ada）。したがってNWCは現時点ではモデル重みの保存・転送・圧縮率の研究であり、vLLMのTPS改善を直接示す研究ではない。

## 背景と問題設定

### LLM重みは画像とは違うデータ

通常のneural image codecは、入力画像を連続潜在変数へ写し、量子化した潜在表現をentropy codingで圧縮し、decoderで復元する。LLMの重みも大量の実数なので同様の考え方を適用できるが、モデル内には大きさも分布も異なる行列が多数ある。例えばLlama3-8Bのkey projectionは1024×4096、up projectionは14336×4096であり、同じcodecへ直接入力するのは難しい。

さらに、重みを少し変えたときのモデル出力への影響は一様でない。重要な方向の小さな誤差が性能を大きく悪化させる一方、重要でない方向の誤差は許容できる。単なる重みMSEを最小化すると、PPLや下流タスクの正解率を必ずしも保てない。NWCは重みを**共通サイズのデータ**へ変換し、**重要度を使った歪み関数**を学習する。

### 既存量子化との位置づけ

GPTQはHessian情報を使って逐次量子化誤差を補償し、AWQは重要なチャネルを考慮したscaleを調整する。SpinQuantは回転で外れ値を分散し、QuIP#/QTIPは格子コードや変換を用いて低ビットでの精度を高める。これらは比較的単純なデコーダを使うためGPU上の高速GEMMへ接続しやすい。NWCは**非線形な学習済み変換**で重みを表現できる反面、復号処理が重くなりやすい。著者らはこの欠点を認め、専用ハードウェア・システムとの協調設計が必要だと述べる。

## 手法

### 1. 列単位の正規化と16要素chunk

入力はモデル内の任意の線形層重み行列Wである。まず列ベクトルに分割し、各列の標準偏差が1になるよう正規化する。その後、列を長さd=16の短いベクトルへ切り出す（§4.1、Eq.4）。この前処理により、行列の大きさが違っても同じencoder/decoderへ投入できる。復元時に元のscaleへ戻すため列ごとの正規化係数をFP16で保存し、原著は追加費用を約0.004 bits/parameterと見積もる。

列単位にする理由は、後段のHessian重要度を列ごとに割り当てやすくするためである。chunkを短くすればcodec入力の形を揃えやすく、圧縮時の誤差補償で保持する一時情報も小さくなる。一方、16要素へ分割すると列間の長距離相関を直接モデル化しにくく、別の正規化や重要度割当が必要になる。

### 2. Encoder、量子化潜在変数、entropy model

前処理した16要素の重みchunkをanalysis network g_aへ入力し、潜在変数zへ変換する。量子化されたz_hatをentropy modelで符号化し、synthesis network g_sが重みchunkを再構成する。encoder/decoderはともに幅512の4つのresidual MLP blocksを用い、entropy priorにはdeep-factorized priorを採用する（Appendix A.3）。学習では量子化の非微分性を扱うため潜在変数へ一様雑音を加える近似を利用する。

目的はrateとdistortionの加重和であり、rate項はentropy modelが推定する符号長、distortion項は復元重みが元の層出力へ与える誤差を表す。係数λを変えることで目標bitrateに沿ったrate-distortion曲線を得る。単一の固定2bit/4bit量子化器ではなく、**複数の圧縮率に対応するcodec**として設計されている。

### 3. Hessian対角に基づく重要度の学習

単純なMSEではなく、線形層の入力活性xに対する`E||Wx-W_hat x||²`を考える。入力共分散に相当するHを用いれば、誤差行列E=W-W_hatに対する`tr(E H E^T)`となる。計算を軽くするためHの対角成分を使って近似し、列ごとの重要度を求める（§4.2、Eq.5）。Hは較正データの入力活性から推定する。

学習時にはchunkへ複数の品質レベルをランダムに割り当て、その品質レベルを埋め込みとしてencoder/decoderへ渡す。これにより同じcodecが異なる歪み許容量のchunkを学習できる。圧縮時にはHessian対角の分位に応じて品質レベルを決め、重要な列へ高品質・高bitrateを割り当てる。品質レベルのインデックス保存費用は原著によれば0.001 bits/weight未満である。

### 4. 層内のLDLQ型誤差フィードバック

重み列を順番に圧縮すると、先に圧縮した列の誤差が層出力に影響する。NWCはLDL分解に基づくGPTQ/LDLQ型の補償を用い、すでに圧縮した列の誤差を、これから圧縮する列へ加える。原著Eq.7では、k番目の列を`w_tilde_k = w_k + (W_{1:k-1}-W_hat_{1:k-1}) a_k`へ更新し、a_kはHessianのLDL分解から導く。

これは**圧縮後の推論時に毎トークン重みを更新する処理ではない**。論文でいうinference-time compensationはcodecの圧縮適用段階における誤差補償であり、LLMの通常のテキスト生成ループで実行するものではない。先に圧縮した列の損失を後の列で部分的に打ち消し、層全体の出力誤差を小さくする狙いである。

### 5. 層間のblock-wise回復

一つのTransformer blockには複数の線形層があり、ある層を圧縮すると後続層の入力分布が変わる。NWCはblock内の一部を圧縮した後、まだ圧縮していない層をfine-tuningし、元の未圧縮blockの出力へ近づける。入力には較正データを元モデルへ通した中間特徴を用いるので、複数blockの圧縮を並列に扱える設計である。必要なら最終的なend-to-end回復も組み合わせられるが、主要な比較ではQuIP#/QTIPの最終E2E fine-tuningを外した改変版と比較している。どの手法が追加学習を含むかを揃えずに数値を比較してはいけない。

### 6. Data-freeモード

較正データがない場合はHessianを推定できないので、全chunkに同じ品質レベルを割り当て、誤差フィードバックとblock-wise fine-tuningも使わない簡略版NWCを評価する（§5.3）。この条件ではSeedLMと比較し、原著Figure 6でWikiText2 PPLの改善を報告する。Data-freeの性能を、較正・fine-tuningありの完全版NWCの性能と同じものとして扱わないことが重要である。

## 主要結果

### 1. 4〜6bitでのrate-distortion傾向

原著Figure 4はLlama3-8BのWikiText2 PPLとMMLUをbitrateごとに示し、Figure 5はLlama2-7B/13Bを含むC4 PPLの曲線を示す。NWCは中〜高ビット幅（おおむね4〜6bits/weight）で、多くの手設計量子化法より良いPPL・正解率の折衷を示す。著者は、重み分布の裾が重要になるこの領域で学習済みcodecが有利と解釈する。これは低ビットの一様量子化より常に良いという主張ではない。

数値が主に図として提示されるため、本稿では**図の曲線を読み取った小数点以下の精密なPPLやMMLUを捏造しない**。定量的に確定できるのは対象bitrate、評価モデル・タスク、相対的な優劣の方向である。正確な特定bitrateのPPLを再利用する際は原著PDFの図または実装のログを再確認する必要がある。

### 2. 極低ビットでの負例

原著Appendix B.2のFigure 9は3bit未満で**QTIPがNWCより良い**条件を示す。著者らもこの領域では従来の格子・変換型手法が有利な場合を認める。従って「neural codecならすべてのbitrateで最高精度」とは言えない。低ビット化が進むと、限られたコード数を重要な重みへ割り当てる構造化手法の強みが出る可能性がある。

### 3. Data-freeと重要度割当のablation

原著Figure 6は較正データなしのNWCとSeedLMを比較し、NWCが複数のLlamaモデルで低いWikiText2 PPLを示すと報告する。ただしこの条件では重要度割当もLDLQ補償も使わない。Figure 10はHessian重要度を用いた品質割当が、一様品質割当よりPPLを改善することを示し、Figure 11は層内補償と層間回復がそれぞれPPL改善へ寄与することを示す。これらは主として図示された相対的結果であり、表の精密数値と同じ確度で小数値を転記しない。

### 4. codecの符号化・復号時間

原著Appendix B.5 Table 2はRTX6000 Adaで256×256の重みテンソルを処理したときの平均時間を報告する。

| 処理 | 時間 |
|---|---:|
| 総符号化 | **12.509ms** |
| 総復号 | **14.615ms** |
| 復号内のentropy decoding | **13.840ms** |
| 復号内のsynthesis network | **0.775ms** |

復号時間の約94.7%がentropy decodingであり、neural decoder本体のMLPよりも符号列の復号が支配的である。これは**256×256の重みテンソルのcodec処理時間**であり、LLMが1トークン生成するのに14.615msという意味ではない。全層を復号してから推論する方式なら初期ロード時間が増え、毎回重みを復号する方式なら計算オーバーヘッドが増える。論文は専用ハードウェア支援なしでは実用的な推論時高速化が難しいと明記している。

### 5. 重要度推定とcodec学習の費用

原著Appendix A.3ではencoder/decoderの幅512、residual block各4、entropy model channel 16、Adam、学習率1e-4、補助loss学習率1e-3、rate-distortionのλを30〜10000で探索する。Hessian推定には6144×2048のRedPajama系列を使う。これらは追加のcodec訓練・較正費用であり、GPTQのような比較的単純なpost-training quantizationと同一の変換時間ではない。論文には全モデルのエンドツーエンド変換時間を同一GPU条件で並べた表がないため、NWCの量子化処理がGPTQより速いとは結論できない。

## 既存研究との差

GPTQ/AWQ/SpinQuantは主に重み空間でのスケーリング・回転・誤差補償を使い、復号後の計算を通常のGEMMへ接続しやすい。QuIP#/QTIPは格子やランダム変換を活用し、特に非常に低いbitrateで優れた圧縮を示す。NWCは**非線形encoder/decoderとentropy modelを学習する**ことで、重みの分布に適応する。重要度はHessian対角を用いて列ごとに品質レベルへ割り当て、誤差補償はLDLQとblock-wise回復を組み合わせる。

画像向けのneural codecをそのまま使うのではなく、重みの異なる形状・scaleを列正規化と16要素chunkへ変換し、モデル出力への影響を考慮した歪みで学習する点が独自性である。SeedLMのようなseedからの疑似乱数近似とは異なり、重み分布そのものを訓練データとして使う。さらにCLIP/SigLIP/DINOv2へcodecをfine-tuningして適用できることを示すが、**fine-tuningなしの完全なモデル間汎化**を証明したわけではない。

## 限界・負の結果

第一に、最大の制約は**実行時の復号コスト**である。現状は圧縮重みを専用のGPU低ビットGEMMへ直接接続する実装がなく、実用的なtokens/s改善が示されていない。Table 2の14.615msは小さな重みテンソルの復号時間であり、全LLM重みの復号や常時decode時の費用は別に測る必要がある。専用ハードウェア・codecの演算融合なしでは、保存サイズが減っても推論速度が落ちる可能性がある。

第二に、3bit未満ではQTIPが上回る条件がある。4〜6bitの相対的優位性は全bitrateの支配を意味しない。主要品質結果が曲線図であり、表形式の絶対PPL・正解率が限定されるため、特定の目標BPWで導入を決める際には追加の数値照合が必要になる。

第三に、Hessianの推定には較正データを使い、層内・層間の誤差補償にも処理費用が必要である。Data-free実験は別の簡略版であり、完全版と同じ品質ではない。モデル重みを再学習しないという説明だけで、学習・較正コストがゼロだと解釈できない。

第四に、Llama3-8Bの重みでcodecを学習しており、重み分布が大きく異なる新しいMoE、低ランク適応済みモデル、特殊な埋め込み・出力層などへ無調整で適用できるとは限らない。視覚encoderへの実験でも対象モデルの重みでcodecをfine-tuningしている。高圧縮率での品質低下や、モデル固有の外れ値分布を考慮する必要がある。

第五に、圧縮されたモデルの保存・配布コスト、実際のロード時間、実行時のGPUメモリ、prefill/decode TPS、TTFT、continuous batching、P95/P99レイテンシを統一条件で測ったシステム評価はない。重みファイルの圧縮率がそのままGPU常駐メモリ削減率やLLMサービング高速化率になるわけではない。

## サーベイへの位置づけ

「学習済み重みcodecとモデル圧縮」に位置づける。低ビットカーネルを即利用するGPTQ/AWQ/ELUTQとは異なり、NWCは**重みの保存・配布・通信**を重視する方向の研究である。推論サーバへ適用するには、entropy decodingとGEMMの協調設計、codec復号のキャッシュ、モデルロードの並列化が必要となる。4〜6bitで品質を重視するオフライン配布には示唆があるが、ローカルLLMの推論速度改善策としては現時点で未実証とする。
