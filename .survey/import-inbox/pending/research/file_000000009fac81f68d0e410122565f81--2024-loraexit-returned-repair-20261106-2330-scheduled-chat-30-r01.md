# LoRAExit：出口ごとの低ランク適応と隣接出口蒸留による分類Transformerの適応推論

## 概要

LoRAExitは、入力の難しさに応じてTransformerの途中層から分類結果を返す「早期終了」を、精度と実行時のメモリ・遅延の両面から改良する。従来の早期終了は複数の出口で基盤パラメータを共有し、各出口の損失から逆伝播する勾配が競合する。独立した大小モデルを順に実行する方式はこの競合を避けるが、複数の重みを保持・実行するため資源制約に不向きである。提案方式は出口ごとに異なる低ランク適応器を配置し、出口を独立して学習する。さらに隣接する深い出口を教師とする蒸留と、低ランク演算をまとめるGPU実行方式を組み合わせる。

BERT-baseのGLUE七分類課題では、通常モデルの平均スコア82.83に対しLoRAExitは81.51で、推論時間は通常モデルを1とした0.78、平均使用層数は12から6.56に減った。ALBERT-baseでは平均78.99に対し79.03、相対時間0.79である。これらは分類タスクの適応推論の測定であり、生成型LLMの逐次トークン生成速度を直接示すものではない。

## 問題設定と既存方式との差

複数の中間分類器を付けたモデルでは、浅い出口が簡単な入力を処理して終了し、難しい入力だけが深い層まで進む。理想的には各出口が同じ深さの独立学習モデルに近い精度を持ち、かつ早期終了判定の費用が節約した層計算を上回らない必要がある。しかし、共同学習では浅い出口と深い出口が共有する重みの更新方向が競合する。二段階学習も共有表現と出口分類器の適合に制約が残る。損失の伝播先を局所的に限定する方式は競合を緩和するが、浅い出口が利用できる表現能力を制限しうる。

原著表1のBERT-base・第3層の比較では、PABEEが64.24、PALBERTが64.63、DREEが40.68、同等深さの独立学習モデルが72.27である。第6層でも順に73.38、74.18、34.34、78.95となり、浅い出口の訓練不足が観測される。この比較は提案手法そのものの結果ではなく、既存訓練法の問題を示す導入実験である。

別個のモデルを複数保持する方式にも問題がある。原著表2ではDeBERTa-base相当の比較で、早期終了方式のメモリ280 MB、遅延12.88 msに対し、複数モデル方式は690 MB、24.96 msであった。DeBERTa-large相当では786 MB・24.73 msに対して1625 MB・44.52 msである。出口ごとの独立性を確保するだけでモデル全体を複製しては、GPUメモリの制約を解決できない。

## 手法：出口別LoRA経路

出口を基盤Transformerの第i層に付けるとき、その出口専用のLoRAを第1層から第i層まで用意する。元の線形変換の重みをW、低ランク行列をAとBとすると、出口専用の演算はx(W+AB)で表せる。元のWを共有しながら、出口ごとに異なるAとBを持つ。論文では自己注意のqueryとvalueの射影にLoRAを付け、各出口の末尾にはフィードフォワード型の分類ヘッドを置く。

重要なのは、単に各出口の最後へ小さな分類器を付けるのではなく、**出口へ至る各層に、その出口のための低ランク更新を独立に設ける**点である。浅い出口の損失はその出口専用の適応器と分類器を更新し、他の出口の低ランク更新を直接変更しない。これによって同じ基盤重みを再利用しつつ、複数出口の勾配競合を抑える。低ランク行列の階数が元の隠れ次元より十分小さいことが追加パラメータを抑える前提となる。逆に出口数や階数を増やせば適応器の保存量と計算量は増える。

出口専用の経路を持つため、ある出口における中間表現と別の出口における中間表現は完全に同一ではない。実装では同じ基盤層を共有しながら出口ごとのLoRA寄与を加える必要があり、出口数に比例する素朴な逐次ループを使うと小さい行列演算が大量に発生して遅延を悪化させる。論文はこの点を後述の一括演算で扱う。

## 手法：隣接する深い出口による蒸留

LoRAExitのSuperior-Exit Guided Distillation（SEGD）は、最後の出口Nをまず教師ラベルに対する交差エントロピーで学習し、出口kをその直後の深い出口k+1から順次蒸留する。出口kの損失は、正解ラベルに対する分類損失と、温度Tで軟化したk+1とkの予測分布間のKLダイバージェンスを重みλで混合する。深い出口から浅い出口へ学習を伝えるが、すべての浅い出口に最終層だけを教師として与える方式とは異なる。

直後の深い出口を選ぶ理由は、浅い出口と最終出口の能力差が大きい場合に、遠い教師からの分布模倣が難しくなるためである。隣接出口は深さが近く、浅い経路が表現可能な判断を段階的に移しやすい。最終層の学習から順に進めることで、蒸留に使う教師の予測を先に用意できる。ただし、深い出口の誤りが浅い出口へ伝わる可能性は残り、温度Tとλの設定にも依存する。

表4ではBERT系GLUE平均について、第3層で蒸留なし71.05、最終出口からの蒸留71.47、SEGD71.74である。第6層では76.66、78.34、78.61となる。第9層では80.93、82.13、82.13で、直後の教師が第12層そのものなので両蒸留方式は一致する。この一致はSEGDの構成から説明でき、全層で常に上回ると主張すべきではない。

## 手法：GPU一括演算と実行時終了判定

出口別LoRAを個別のforループで逐次実行すると、共通の基盤行列積と多数の低ランク行列積が細切れになる。論文は各層の処理を、全入力に共通する基盤重みWの行列積と、出口ごとに異なるAiBiの寄与へ分解する。前者をCUDAのGEMM、後者をセグメント化行列ベクトル積（SGMV）でまとめて計算する。出口の異なる入力を同じ基盤演算にまとめられることが、複数の適応器を持ちながら遅延を抑える鍵である。

各層で出口ごとの特徴が得られたら、分類予測の信頼度を使って終了位置を決める。信頼度が閾値を満たした入力はそこで分類結果を返し、満たさない入力は次の層へ進む。閾値を低くすると浅い層で止まる入力が増え、速度は改善しやすいが分類精度を犠牲にしうる。閾値を高くすると深い層まで処理する入力が増え、速度上の利得が縮む。論文の速度・精度曲線は、この終了基準を変化させたときの結果である。

表5の全モデルを一度実行する比較では、LoRAExitの一括処理と通常forループの時間はBERTで7.83対12.58 ms、ALBERTで9.08対12.47 ms、DeBERTaで14.90対19.00 msだった。これらの数値は低ランク演算の実行方法の比較であり、早期終了込みのGLUE平均遅延表3とは別の測定である。SGMV対応GPU環境がない場合やバッチの構成が異なる場合、同じ利得を前提にできない。

## 評価条件と結果

対象は生成型モデルではなく、BERT-base、ALBERT-base、DeBERTa-base/large/xlargeを基盤とする分類モデルである。GLUEのCoLA、RTE、MRPC、QQP、SST-2、QNLI、MNLIの七課題を評価した。CoLAはMatthews相関係数、MRPCとQQPは正解率とF1の平均、残りは正解率を使い、七課題のスコアを算術平均している。したがって平均値は単一の正解率ではない。比較手法はPABEE、PALBERT、DREE、SWEET、独立複数モデル方式であり、基盤モデルの組により比較対象が異なる。

| 基盤・方式 | 通常モデル比遅延 | 平均使用層数 | GLUE七課題平均 |
|---|---:|---:|---:|
| BERT-base通常 | 1.00 | 12.00 | 82.83 |
| BERT-base PABEE | 0.94 | 8.59 | 80.19 |
| BERT-base PALBERT | 1.18 | 9.67 | 80.66 |
| BERT-base DREE | 1.27 | 9.77 | 78.39 |
| BERT-base LoRAExit | **0.78** | **6.56** | **81.51** |
| ALBERT-base通常 | 1.00 | 12.00 | 78.99 |
| ALBERT-base PABEE | 0.88 | 8.64 | 76.80 |
| ALBERT-base LoRAExit | **0.79** | **7.19** | **79.03** |

BERTでは通常モデル比で平均1.32ポイントのスコア低下を伴うが、PABEEより平均1.32ポイント高く、遅延も0.94から0.78へ減る。ALBERTでは通常モデルとほぼ同じ平均スコアを維持しながら遅延が下がる。論文本文には「BERTの全タスクで最高」と読める説明があるが、表3のBERT通常モデルはCoLA等でLoRAExitより高い。比較対象を通常モデルまで含めて無条件の最高性能と解釈するのは適切でない。

| DeBERTa規模・低遅延側 | SWEET：遅延ms / スコア | LoRAExit：遅延ms / スコア |
|---|---|---|
| base | 5.75 / 59.18 | **4.12 / 62.14** |
| large | 10.13 / 64.04 | **8.52 / 67.56** |
| xlarge | 10.79 / 64.12 | **8.97 / 65.78** |

表7の低遅延側ではLoRAExitが全規模でSWEETより短時間かつ高スコアである。対して高精度側では差が縮まり、baseでSWEET15.92 ms・80.40に対しLoRAExit15.60 ms・80.64、xlargeでは35.22 ms・84.89に対し35.12 ms・85.71となる。速度利得は要求精度と終了閾値に依存する。表6の出口単体比較ではDeBERTa-base第1層がSWEET42.97対LoRAExit57.88であり、浅い出口の学習改善が低遅延側の利得へつながる。

## 制約、負の結果、適用判断

第一に、出口専用のLoRAと分類器は追加パラメータと計算を発生させる。実行時にSGMVなどで束ねることができなければ、従来の早期終了法と同様にオーバーヘッドが層削減を打ち消す可能性がある。表3でPALBERTとDREEが通常BERTより遅いことは、平均使用層数の減少だけでは実時間短縮を保証しない例である。

第二に、実験対象は識別型の分類Transformerに限られる。自己回帰生成、トークンごとの終了判定、生成品質、KVキャッシュを保持したままの深さ切替、長文文脈、MoEモデル、SSDへの重み退避などは検証されていない。論文の名称にLLMとあっても、現代の数十億パラメータ生成モデルで同じ速度・精度が得られると外挿することはできない。論文の限界節も生成型モデルや系列ラベリングなどへの拡張を今後の課題としている。

第三に、適応器を出口ごとに分離することで学習時の勾配競合を抑えられる一方、出口の数、低ランク階数、GPUでの一括演算効率、信頼度閾値の設定が実装コストを決める。特に精度を優先して深い出口まで処理すると利得は縮む。低遅延側の比較が良好でも、高精度側での改善は小さい場合がある。

既存のPABEEやPALBERTが主に出口判定と共有モデルの学習に焦点を置くのに対し、LoRAExitの差分は「出口までの全経路を専用LoRAで分離すること」「直後の出口を教師として段階蒸留すること」「基盤GEMMと出口別SGMVを組み合わせること」の三点にある。LLMサービングへの直接的な実装候補というより、将来の動的深さモデルで学習干渉と小行列演算のオーバーヘッドを同時に扱うための設計参考として位置付けるのが妥当である。
