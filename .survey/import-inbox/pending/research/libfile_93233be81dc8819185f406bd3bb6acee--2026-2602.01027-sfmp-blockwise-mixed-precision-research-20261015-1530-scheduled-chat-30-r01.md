# SFMP：探索負荷を抑え、GPUで実行しやすいブロック別混合精度量子化

## 概要

重み量子化は、大規模言語モデル（LLM）の重みを16ビットなどの高精度形式から2～4ビット程度の表現へ圧縮し、GPUメモリ使用量を削減する。しかし同じ平均ビット数であっても、重要な重みまで低ビットへ丸めると精度が大きく落ちる。そこで層や重みごとにビット数を変える混合精度量子化が考えられるが、配分候補を整数最適化で探索する方式は大規模モデルで非常に高コストとなる。一方、重み一個単位で精度を変えると、低ビット重みの格納・復元が不規則になり、GPUが連続メモリを読み出しにくくなる。

SFMPは、この**精度配分の探索費用**と**不規則な混合ビット形式の実行費用**を一緒に扱う。損失への影響を表すFisher情報の対角成分を用い、重要度に従って精度を割り当てる。精度は重み一個単位ではなく規則的な二次元ブロック単位とし、行・列の並べ替えで重要重みを同じ領域へ集める。最後に、2～4ビットの重みを1ビット成分へ分解して処理する共通の参照表型行列演算カーネルを使い、異なるビット数のブロックを同じ実装で処理する。

Llama3.1-70Bでは、A100を4基用いた配分費用がSFMPの0.50時間に対しAMQは44時間と報告された。Llama3.1-70Bを4ビット/重み（BPW）にした場合のゼロショット6タスク平均精度はSFMP 80.47、BF16 80.96である。低ビット化で精度と実行速度を両立する狙いは明確だが、性能は著者の専用CUDAカーネルを用いた測定であり、既存のGGUFや一般のCPU実装へそのまま転用できる結果ではない。

## 問題設定

通常の均一量子化では、ある重み行列全体に同じ2ビットや4ビットを割り当てる。精度を下げるとメモリは減るが、外れ値や出力に敏感な重みが粗い格子へ丸められ、出力誤差が増える。4ビットでは誤差が小さくても、2ビット近傍ではモデル性能が急激に落ちることがある。層ごとにビット数を変えれば重要層を保護できるが、560行列を持つLlama3.1-70Bで候補ビット数が2・3・4なら組合せは$3^{560}$通りになる。整数計画法や発見的探索でも配分計算に時間がかかる。

さらに、重要度が高い重みだけを任意の位置で高ビットにすると、メモリ内で2・3・4ビットの要素が細かく交互に現れる。GPUの行列積（GEMM）は規則的なタイル単位の読出しを前提とするため、要素ごとのビット数判定、ビット列の展開、逆量子化が演算より高くつくことがある。原著の背景比較では、グループ別混合精度方式SliM-LLMは同じ平均ビット数のGPTQより推論スループットが30～50%低い条件があった。したがって、重みを何ビットへ割り当てるかだけでなく、**そのビット配置をGPUがどのように計算するか**まで設計しなければならない。

## 手法

### 1. Fisher情報で重みの量子化感度を近似

量子化前後の重み差を$W-W'$とすると、収束点近傍での損失変化は二次近似により曲率行列で重み付けできる。全Hessianは巨大なので、著者はFisher情報行列の対角成分$F_{ii}$で近似する。$F_{ii}$が大きい重みは、同じ丸め誤差でも損失を大きく変えやすいとみなす。キャリブレーションデータから勾配を計算し、対角成分を推定する。

さらに、量子化誤差が一様に分布し、重みのダイナミックレンジがほぼ一定とする近似を置くと、重み$i$に$b_i$ビットを与えたときの損失寄与はおおむね$F_{ii}/(2^{b_i}-1)^2$に比例する。したがって、平均ビット予算を満たしながら、この総和を最小化する問題になる。重要度が高い重みに高ビットを割り当てるほど、同じ容量で誤差を小さくできるという直感が、配分規則として具体化される。

### 2. 探索を減らす配分規則と平均ビット数

候補が二種類のビット数だけなら、平均ビット数からそれぞれの割当割合が一意に決まる。Fisher対角成分を並べ替え、感度の高い側から高ビットを与えればよい。一般の整数計画ソルバーで全行列の配分を探索する必要がない。例えば2ビットと4ビットを一定比率で混ぜれば、平均3.5ビットのような非整数の保存量も実現できる。ここで「3.5ビット」は一つの重みが3.5ビットで表現される意味ではなく、2ビットや4ビットを混ぜた**重み当たり平均ビット数（BPW）**である。

候補が2・3・4ビットの三種類になると、論文のアルゴリズム1は一つの割当比率を0.01刻みで動かす一次元格子探索を行い、残る比率を平均ビット制約から求める。各候補について重要度順に割り当てたときの近似損失を比較する。したがって「探索不要（search-free）」という名称は、巨大な離散組合せ探索や整数計画ソルバーを不要にする趣旨であり、**あらゆる設定で候補探索がゼロという意味ではない**。著者は三種類を超える候補を増やしても精度向上が小さいと報告し、主要評価では2・3・4ビットに絞る。

### 3. 規則的な二次元ブロックへ精度を割り当てる

要素単位の最適なビット配置はメモリ上で不規則になる。そこで各重み行列を重複しない$m_b\times n_b$の二次元ブロックへ区切り、各ブロックのFisher対角成分を合計して重要度とする。前段の配分規則を個々の重みではなくブロックへ適用するため、同じブロック内では同じビット数を使える。これによりビットパッキングとカーネルのタイル処理を規則化できる。

主要評価ではブロックサイズを512行×128列とし、列方向の128要素を一つの量子化グループとして扱う。GPU向けの説明では256×128なども候補に挙げる。ブロックを大きくするとメタデータと実行分岐は減るが、異なる重要度の重みが同じビット数へ束ねられて精度を失いやすい。小さくすると細粒度の保護が可能になる反面、管理情報と実行費用が増える。著者はこの粒度をハードウェア効率と量子化品質の交換条件として扱う。

### 4. 行・列の並べ替えで重要重みを集約

重み行列の重要度は、行または列に沿って偏る傾向がある。ブロック境界がその偏りとずれると、重要な重みが多数のブロックへ散り、高ビットを広く割り当てなければならない。そこでFisher対角成分を行ごと・列ごとに合計し、両方向の重要度順に重み行列を並べ替える。重要度の高い部分が特定のブロックへ集中するため、同じ平均ビット数で高精度を必要な部分へ集中的に与えられる。

重みの並べ替え自体は量子化前にオフラインで行う。元の線形変換と等価にするため、推論時には対応する入力活性値の順序も並べ替える必要がある。この追加費用は完全なゼロではない。原著の構成要素除去実験では、行・列並べ替えにより推論速度が最大約5%低下する条件があった。一方、低ビットでは精度向上が大きく、4ビットに近づくと既存のAWQだけでも十分な品質が出るため並べ替えの利得が小さくなる。列だけの並べ替えが行だけより有効な条件も多い。

### 5. 1ビット参照表による統一GEMM/GEMV

ビット数の違うブロックを通常の逆量子化方式で計算すると、ブロックごとに展開方法を切り替え、低ビット重みを浮動小数点へ戻す処理が必要になる。SFMPはブロック優先の格納形式（block-major）を使い、同じブロックのビット列を連続配置する。さらに各整数重みを1ビット成分へ分解し、入力活性値とビットパターンの積を参照表（LUT）から求める方式へ統一する。

例えば$q$ビットの重みは$q$個の1ビット成分の重み付き和で表せる。入力活性値の短いグループに対する可能なビットパターンの積和を先に計算し、各ビット成分の結果を参照・加算する。これにより、ブロックごとのビット数が異なっても同じ演算経路を利用できる。高ビットブロックは参照・加算回数が多いが、GPUの多数のスレッドブロックを複数の演算器へ動的配分するため、全体は高ビットブロック一個の遅さだけで決まらない。原著は4,096×4,096行列を256×128タイルへ分割した場合の512スレッドブロックを例に、GPUの演算器数より十分多くの仕事を用意できることを説明する。

## 評価

### 実験条件

| 項目 | 論文の条件 |
|---|---|
| モデル | Llama3.1-8B/70B、Qwen3-8B/14B/32B |
| 装置 | 主実験はNVIDIA A100 80GB。速度図ではA100/H100等を比較し、70B BF16は単一A100/H100に収まらない |
| 感度推定 | C4の1,000サンプルからFisher対角成分を推定 |
| 重み形式 | 候補2・3・4ビット、平均ビット数（BPW）2.25～4程度、主ブロック512×128、グループ128 |
| 比較対象 | GPTQ、AWQ、SqueezeLLM、SliM-LLM、BitStack、AMQ |
| 精度 | WikiText2/C4のパープレキシティ、ARC-Challenge/Easy・PIQA・HellaSwag・BoolQ・WinoGrandeのゼロショット平均、MMLU/GSM8Kの5例提示 |
| 推論速度 | 専用カーネルのGEMV遅延と、バッチ1で128トークン生成した端から端までのtokens/s |
| カーネル比較の注意 | GPTQModelは4ビットでMarlin、2・3ビットでTriton系を用いるため、比較カーネルの成熟度が同じではない |

パープレキシティ（PPL）は小さいほど予測分布が良い。ゼロショット平均正答率は高いほど良い。平均ビット数は量子化スケールや零点の追加記憶も含めたモデル全体の実メモリと完全には一致しない。原著は重み以外のメタデータを含めた実容量を表へ併記している。

### 精度とメモリ

| モデル・平均ビット数 | 比較方式 | PPL（WikiText2 / C4） | ゼロショット平均正答率 | 読み取れること |
|---|---|---|---|---|
| Llama3.1-8B / BF16 | 基準 | 6.15 / 8.89 | 75.01 | 非量子化の参照品質 |
| Llama3.1-8B / 3.0 | AMQ | 9.38 / 13.05 | 68.78 | 層別混合精度の比較 |
| Llama3.1-8B / 3.0 | SFMP | 8.65 / 12.04 | 69.92 | 同容量帯でPPL・正答率とも改善 |
| Llama3.1-8B / 4.0 | SFMP | 6.84 / 9.74 | 74.15 | 4ビットでは基準に近い |
| Llama3.1-70B / BF16 | 基準 | 2.81 / 7.11 | 80.96 | 非量子化の参照品質 |
| Llama3.1-70B / 3.0 | AMQ | 5.84 / 9.47 | 77.80 | SFMPよりPPLが高く、正答率が低い |
| Llama3.1-70B / 3.0 | SFMP | 5.31 / 8.36 | 78.07 | 約28,491MBの重み容量で高い品質 |
| Llama3.1-70B / 4.0 | SFMP | 3.37 / 7.01 | 80.47 | BF16の平均80.96に対し0.49ポイント差 |

上表の70B/3.0のAMQ値は原著表1から確認した。原著表2の同条件ではAWQのPPL 10.86/11.74、平均正答率68.84、SFMPは5.31/8.36、78.07である。極端に低いBPW=2.35付近では、70BのGPTQはWikiText2 PPL 113.22（2.25BPW）、SFMPは8.17（2.35BPW）と大きく異なるが、**平均ビット数が完全に一致しないため厳密な同容量比較ではない**。この点を隠して倍率化しない。

### 配分時間・実行速度・追加メタデータ

| モデル | 方式 | GPU数 | 配分処理時間 |
|---|---|---:|---:|
| Llama3.1-8B | SliM-LLM / BitStack / AMQ / SFMP | 1 / 1 / 1 / 1 | 2 / 12 / 7 / **0.15** 時間 |
| Llama3.1-70B | SliM-LLM / BitStack / AMQ / SFMP | 1 / 4 / 4 / 4 | 8 / >300 / 44 / **0.50** 時間 |

配分時間は原著表3の装置条件込みの値である。SFMPは感度推定が主な費用で、整数計画の長時間探索を避ける。70BではAMQの44時間とSFMPの0.50時間の比は88倍だが、これは**量子化配分処理時間**の差であり、推論トークン生成が88倍速いという意味ではない。

実行速度について、原著図4・7はSFMPのLUT型カーネルが平均ビット数を下げると計算時間も減る傾向を示す。GPTQModelでは逆量子化とビット展開の負荷により、2～3ビットでむしろ遅くなる条件がある。原著は70Bの単一A100/H100上ではBF16モデルを載せられないことを明記しており、BF16との端から端までの直接比較を全条件へ適用してはいない。絶対tokens/sのグラフ読取り値を本文の数字として推測で補完せず、速度は図4の条件付きの傾向として扱う。

ブロックのビット幅と並べ替え索引を保持する追加メタデータは、Llama3.1-8Bの例で約0.006BPWと報告される。重みの格納形式を変えても、メタデータが支配的になる規模ではない。ただし量子化スケール、零点、作業領域などの全実行メモリがゼロになるわけではない。

### 構成要素・感度分析

行・列の並べ替えの有無を比較した図5では、低BPWほど並べ替えの品質改善が目立つ。列だけの並べ替えが行だけより有効な場合が多いが、両方向の組合せが一般に重要重みを最もよく集約する。4ビットでは方式間の精度差が小さくなる。図6では並べ替えにより端から端までの推論速度が最大約5%低下する条件があり、品質向上は無料ではない。

付録Gではブロック行数$m_b$と列数$n_b$、Fisher推定に使うサンプル数、キャリブレーション集合、候補ビット数、格子探索の刻み幅$\Delta$を変えて感度を調べている。特にブロックサイズは量子化品質とGPU実行の規則性を結ぶ設計変数である。著者はビット候補を3種類より増やしても追加利得が小さいと述べるが、これは対象モデル・評価予算での観察であり、任意の量子化対象に一般化する保証ではない。

## 既存研究との差

GPTQやAWQは均一ビット数で重みを量子化する方式であり、重要度を考慮した重みの処理は行うが、モデル全体の平均ビット予算を柔軟に変えるには別の精度配分が必要となる。AMQは層別にビット数を配分するが、大規模な候補探索が必要になる。SliM-LLMやSqueezeLLMはより細かい重みの重要度を使う一方、GPUでの不規則な格納と演算が性能を妨げることがある。SFMPはFisher重要度に基づく単純な配分、規則的な二次元ブロック、行・列の並べ替え、共通のLUT型演算を一体にすることで、この二種類の欠点を減らす。

ここでの「混合精度」は2・3・4ビットの重みをブロック単位で混ぜる意味であり、GPUの行列積をFP16とINT8の標準Tensor Core混合演算へ自動変換するという意味ではない。原著の高速化には専用CUDAカーネルの実装が必要である。

## 限界と導入条件

著者はGPUベースの推論のみを実装・評価し、CPU、NPU、TPUへの拡張を今後の課題とする。重み専用量子化であり、活性値量子化を組み込む場合の演算性能は未検証である。グループサイズ128は固定的に選ばれ、ビット配分とグループサイズを同時最適化する設計ではない。小規模GPUやCPUへのオフロードを伴う推論では、重みの展開・移動・実装互換性が支配的になる可能性があるが、原著はその条件を測っていない。

また、Fisher情報による重要度はキャリブレーションデータと近似仮定に依存する。学習・評価と大きく異なるデータ分布では最適なビット配分が変わり得る。専用の1ビットLUT型カーネルが利用できない推論器へ重みだけを持ち込んでも、原著の速度改善を期待する根拠にはならない。特にllama.cpp/GGUFへの変換互換性やWindows CUDAビルドでの性能は、この論文から確認できないため別途検証が必要である。
