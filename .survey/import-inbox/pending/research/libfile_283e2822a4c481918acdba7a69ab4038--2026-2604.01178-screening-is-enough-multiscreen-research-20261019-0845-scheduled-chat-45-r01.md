# Screening Is Enough：絶対関連度の選別で長文脈を扱うMultiscreen

## 概要

本研究は、通常のソフトマックス注意（softmax attention）が各問い合わせについて全鍵の重みを合計1に正規化するため、「どの鍵も十分に関連しない」という状態を直接表現しにくい点に着目する。入力が長くなるほど、無関係な鍵にも重みの一部が分配され、少数の重要な鍵の信号が相対的に薄まる可能性がある。著者はこの相対的な競争をやめ、各鍵の関連度を独立した有界尺度で評価し、閾値以下を厳密にゼロへ落とす選別（screening）機構を提案する。

提案モデルMultiscreenは、単一の選別関数だけでなく、学習可能な距離窓、必要なときだけ二次元へ作用する位置回転、選別後の値の集約、出力のノルム制御、入力依存ゲートを組み合わせる。これにより、全ての鍵を棄却する場合も扱いながら、文脈が学習時より長くなっても検索精度と困惑度を維持することを狙う。**「疎な注意を速く実装する」だけでなく、何を関連とみなすかという注意の意味を変更する**研究である。

2026年5月の改訂版で、1.3B規模のMultiscreenは同規模のTransformerと比べ、GH200上のモデル側初回トークン時間（TTFT）が入力長にわたり約2.5〜2.9分の1であった。パラメータ規模に関する近似的な学習曲線からは、同等の検証損失に必要なパラメータが約30%少ないと推定する。さらに、286MのMultiscreenは、学習長4KにおけるABCDigits検索で1.3B Transformerの95.18%に対し98.33%を報告した。ただしモデル側TTFTは要求待ち行列や通信を除く演算時間であり、オンラインサービス全体の応答時間ではない。

## 問題設定：相対的な注意重みと絶対的な棄却

通常のTransformerは問い合わせqと鍵kの内積からスコアを計算し、各問い合わせについてソフトマックスで正規化する。この方式では、鍵が全て無関係でも各鍵の重みの総和は1であり、相対順位の高い鍵が何らかの重みを受け取る。文脈が変われば競合する鍵集合も変わるため、同じ問い合わせ・鍵の組合せがどの程度重要かを独立の尺度で判断できない。

選別では、問い合わせと鍵をそれぞれ単位長に正規化し、内積を必ず[-1,1]の範囲へ収める。閾値より低い類似度をゼロへ落とすことで、全ての鍵を棄却できる。残った鍵の重みは合計1に正規化せず、そのまま値ベクトルを集約する。入力長が変わっても閾値の意味が同じ尺度で定義されるため、系列長に応じたソフトマックス温度調整とは異なる長文脈への一般化を狙う。

ただし、閾値だけでは古い情報の扱いを調整できない。短距離の局所パターンに向く鍵と、文脈全体から検索すべき鍵は異なる。そこでMultiscreenは各選別単位に学習可能な距離窓を持たせ、遠い鍵を距離に応じて弱める。十分広い窓では位置回転を無効にし、学習時より長い位置に未知の回転角を適用する問題を避ける。

## 手法：鍵の選別から出力まで

### 1. 正規化された類似度とTrimによる閾値棄却

各トークンの表現から問い合わせq、鍵k、値vを射影し、三者を単位長へ正規化する。最小位置符号化（MiPE）を適用した問い合わせと鍵の内積を `s_ij` とすると、`-1≤s_ij≤1` である。選別の許容幅を `r=σ(s_r)` とし、原著式(8)の `α_ij=[max(1-(1-s_ij)/r,0)]²` を計算する。

この式は `s_ij≤1-r` の場合に重みを厳密にゼロへする。閾値を超えた鍵については、類似度が1に近いほど滑らかに大きな重みを与える。全鍵を一括で正規化しないため、無関係な鍵が大量に増えても、それだけで残った鍵の関連度が下がることはない。ただし、独立の重みを合計すると、通過する鍵が多い場合には集約ベクトルのノルムが大きくなり得る。後段でこの問題を扱う。

### 2. 学習可能な窓と距離依存Softmask

各選別単位は `w=exp(s_w)+1` という窓幅を学習する。因果方向の距離 `i-j` が窓wの外なら重みはゼロ、窓内なら区分二次関数のSoftmaskで距離が大きいほど滑らかに減衰させる。最終関連度は `α^d_ij=α_ij m_ij(w)` であり、内容の類似度と距離の双方を通過した鍵だけが値の集約に寄与する。

推論時には学習された窓が学習時の最大系列長を超える場合、著者の既定規則では無限窓として扱う。これは文脈全体を探索すべき単位に対し、学習長を超えたという理由だけで遠方の鍵を排除しないためである。一方、短い窓を学習した単位では、遠方の鍵の計算を省略できる。全ての単位が常に定数時間で動くわけではなく、無限窓の単位では長文脈の検索費用が残る。

### 3. 最小位置符号化（MiPE）

通常の回転位置符号化（RoPE）は多数の次元を位置に応じて回転するため、学習長を超えた位置では未知の回転位相が発生する。MiPEは問い合わせと鍵の先頭2次元だけを回転し、角速度を窓幅wから決める。原著式(6)では、窓幅が閾値 `w_th` より小さい場合だけ角速度を正にし、`w≥w_th` では角速度をゼロとする。実験設定の `w_th` は256である。

短距離の選別単位では位置関係を利用し、長距離の単位では位置の外挿による余計な回転を避ける設計である。これはRoPEを全ての状況で不要にするという主張ではない。著者の除去実験では、RoPEを残して窓を外した場合より、窓を保持した場合が良く、さらにMiPEへ変更すると長文脈検索が改善する。したがって窓と位置符号化の役割は別々に評価されている。

### 4. 値の集約とTanhNorm

通過した鍵の値を `h_i=Σ_{j≤i} α^d_ij v_j` として集約する。ソフトマックスのように重みの総和を1へ制約しないため、全鍵が棄却されればhはゼロとなり、複数鍵が通過すれば各寄与が加算される。この自由度は絶対関連度の利点である一方、集約ノルムが過大になる危険もある。

原著は `TanhNorm(h)=tanh(||h||)h/||h||` を適用し、方向を保ちながら出力の大きさを滑らかに制限する。hがゼロに近い場合は連続極限を使う。これにより、鍵の通過数が増えたときのスケール変化を抑える。TanhNormは鍵の選別そのものを決めるのではなく、選別後の集約の安定化を担当する。

### 5. ゲート付き選別単位と層の接続

Multiscreenの各層は、複数のゲート付き選別単位（gated screening tile）を並列に持つ。各単位は入力からq、k、vに加えゲートgを射影する。選別・集約後のベクトルuと、`tanh(SiLU(g))` による入力依存ゲートを要素積し、出力射影を通して残差接続へ加える。層の出力は各単位の更新を足したものである。

モデルの入力埋め込み行列は行ごとに単位長正規化され、最終隠れ状態も語彙射影前に正規化される。これらの球面型入力出力正規化（SIO）と問い合わせ・鍵正規化（QKNorm）、出力前正規化（PLNorm）の組合せは、非常に大きな学習率での数値安定性にも関係する。選別関数、距離窓、位置回転、出力ゲート、入出力正規化は別々の役割を持ち、単一の閾値だけで全結果を説明することはできない。

## 評価：条件と比較の境界

| 観点 | 原著の設定 |
|---|---|
| 学習データ・長さ | SlimPajama、各モデル `2^38` トークン、学習系列長 `2^12=4096` |
| モデル規模 | Multiscreen 4M、28M、286M、1.3B、4B。比較Transformerは8M、45M、353M、1.3B |
| 学習装置 | NVIDIA GH200、規模により16基または64基 |
| 実装 | TransformerはPyTorchのFlashAttention-2、Multiscreenは専用Tritonカーネル |
| 主な比較 | Transformer、YaRN付きTransformer、12種類の注意機構の統制比較 |
| 長文脈 | 学習長の最大32倍、長文脈PPLとABCDigits検索、passkey検索 |
| 下流課題 | 1.3Bモデルの9種類のゼロショット課題 |
| モデル側TTFT | 単一GH200で入力長 `2^11`〜`2^17`、トークン化・待ち行列・通信を除外 |
| 再現性 | 小規模モデルは複数乱数種の平均とばらつき、大規模モデルは単一学習run |

同じトークン予算でもTransformerとMultiscreenでは学習率が異なる。Transformerは規模別の学習率、Multiscreenはより大きい `2^-4` を採用しており、モデル構造だけを変更した厳密な同一学習率比較ではない。選別機構の寄与は、同じTransformer骨格で注意機構だけを変える別の統制比較で確認している。

## 評価：主要結果と負の結果

| 条件・指標 | 比較 | MultiscreenまたはScreening | 解釈 |
|---|---|---|---|
| 1.3Bモデル、モデル側TTFT | TransformerのTTFTが提案比2.5〜2.9倍 | **提案の方が短い** | GH200単体の入力処理実測。サービス全体ではない |
| 同等の検証損失を得るパラメータ数 | Transformerの推定必要量 | **約30%少ない** | 学習曲線の当てはめによる推定であり全規模での実測等価ではない |
| 1.3B、9課題ゼロショット平均 | Transformer 52.41% | **53.67%** | 8/9課題で提案が優位。SciQではTransformer 83.40%に対し79.40% |
| ABCDigits、学習長4K | 1.3B Transformer 95.18% | **286M Multiscreen 98.33%** | 少ないパラメータでも意味を持たない鍵値検索に強い |
| 学習長外の検索・困惑度 | YaRNなどは長文脈化で短文脈PPLとの交換条件 | **追加の長さスケーリングなしで最大32倍まで評価** | 最大32倍の全課題で無条件に完全検索するという意味ではない |
| 学習率1の安定性 | Transformer単体・単独正規化は発散 | **Multiscreenは学習継続** | QKNormとSIO/PLNormの組合せをTransformerへ移しても安定化 |

ゼロショットの平均は、HellaSwag、PIQA、ARC、WinoGrande、BoolQ、SciQ、OpenBookQA、MMLU等の9課題を単純平均したものであり、全ての能力が向上したわけではない。SciQでは提案が4ポイント低く、モデル構造の変更が一部の課題で負の影響を持つことが分かる。

著者のABCDigitsは、文字と6桁数値の対応を大量の無関係な対応に混ぜ、指定された文字の数値を正しく再生する課題である。自然言語の意味推測や指示追従に頼らず、長い入力から一つの鍵値関係を正確に取り出せるかを測る。286Mモデルが1.3B Transformerを上回る結果は、検証損失だけでは検索能力を評価できないことを示す。一方、実際の文書検索や推論タスク全般の精度を直接示すものではない。

12方式の統制比較では、学習時と同じ骨格・学習条件の下で、長文脈の低困惑度と高いABCDigits検索を同時に維持したのは選別機構だった。ALiBi、忘却注意、滑動窓注意などは長文脈PPLを保つ場合でも遠方の鍵値を取り出せない。窓を除いた選別より窓を持つ選別が良く、さらにMiPEが検索を改善するため、単なるソフトマックス除去だけが成功理由ではない。

## 限界と実装上の含意

選別が全鍵を棄却できることは意味的に有用だが、無限窓の単位は全過去鍵を参照する。したがって全ての処理が系列長に対して定数時間になるわけではなく、計算量と速度は学習された窓分布、カーネル実装、入力長に依存する。専用Tritonカーネルによる速度向上と、注意機構の変更そのものによる計算量削減は分けて解釈する必要がある。

著者は長文脈の評価で入力長を最大131Kへ伸ばしたが、学習長は4Kである。評価結果は長文脈での検索・困惑度の改善を示す一方、非常に長い文脈の実運用、同時多数要求、KVメモリ容量、P99遅延、量子化、GPU世代間の性能を網羅していない。モデル側TTFTは要求処理の一部分であり、ストリーミング出力の復号速度やクラウド全体の費用削減を意味しない。

また、同等検証損失に必要なパラメータ30%減は、限られたモデル規模からの学習曲線推定である。1.3Bの下流評価ではSciQが悪化しており、あらゆる課題で優位とは言えない。大規模モデルの学習は単一乱数種の実験が多いため、数値の不確実性や別データセットでの再現性を評価するには追加実験が必要である。

vLLMやllama.cpp等の既存Transformer推論エンジンへ単に選別カーネルを追加して同じ結果を得ることはできない。Multiscreenは専用の学習済み重み、選別単位、位置符号化、正規化、ゲート構造を備える別アーキテクチャだからである。研究の実装上の価値は、鍵の絶対関連度と閾値棄却、距離窓の学習、位置外挿の抑制、入力処理カーネルの統合設計という複数の観点にある。
