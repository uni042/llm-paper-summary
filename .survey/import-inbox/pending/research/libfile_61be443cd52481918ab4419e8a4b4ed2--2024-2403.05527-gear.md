# GEAR: An Efficient KV Cache Compression Recipe for Near-Lossless Generative Inference of LLM

## 概要

KVキャッシュは過去tokenのKey/Valueを保持して再計算を避ける一方、系列長とbatch sizeに比例してGPUメモリを消費する。既存のtoken droppingや低ビット量子化は容量を減らせるが、複雑な生成では圧縮誤差が自己回帰的に次tokenへ伝播するため、単純なベンチマークでは見えにくい品質劣化が発生する。GEARはこの「容量」ではなく「圧縮誤差の構造」を直接扱い、量子化後の残差を低ランク成分と疎な外れ値成分へ分けて補正する。

GEARの圧縮表現は、量子化行列 D-hat、head単位の低ランク行列 L、外れ値を保持する疎行列 S の和でKV行列を近似する。量子化は大多数の値を2/4-bitへ落とし、Sは各Key channelまたはValue tokenの上下端の外れ値をFP16で保持する。残る量子化残差には急速に減衰する特異値スペクトルが観測されるため、各attention headごとにrank 4程度の低ランク近似を適用する。これにより、外れ値だけを増やしてメモリを消費するより少ない追加容量で、生成品質に効くコヒーレントな誤差を回収する。

評価ではLLaMA2-7B/13B、Mistral-7B、LLaMA3-8BをGSM8k、AQuA、BigBench Hard、LongBenchで検証した。8-shot Chain-of-Thought条件の2-bit圧縮ではLLaMA3-8Bの3タスク平均がGEAR 47.83%、FP16 48.69%、KIVI 28.82%となり、単純な量子化との差が長い生成で顕在化した。単一V100 16GBでLLaMA2-7B、入力1000 token・生成500 tokenの推論では、最大batch sizeをFP16の3から18へ拡大し、最大5.07倍のthroughput改善を示す。

## 問題設定

KVキャッシュ量子化の目的は、各層・各headのKey/Valueを小さくしつつ、attention出力をFP16時と同等に保つことである。しかし2-bitや4-bitへ強く圧縮すると、量子化誤差が次tokenのlogitを変え、そのtokenが後続のKVへ入るため、誤差は一回のattention近似に閉じない。特にChain-of-Thoughtのように数百tokenを生成し、prompt内の複数stepを参照する処理では小さな差が生成経路を変える。

GEARはKV行列 X を D-hat + L + S で近似し、Frobenius normの残差を小さくする。反復的なSVD・量子化更新ならさらに誤差を下げられるが、online inferenceで毎step実行するには遅すぎる。そのため、一回の外れ値抽出、量子化、効率的なpower iterationによる低ランク近似へ分解し、推論中に実行可能な処理量へ制約している。

## 手法

### 量子化バックボーンと疎な外れ値補正

4-bitでは、Keyをchannel単位、Valueをtoken単位で量子化するKCVTを用いる。KCVTはKIVIのような細粒度groupを持たず、scale/zero-pointとFP16 residual bufferの容量を減らす。一方2-bitではKCVT単独の品質が崩れるため、group size 64のKIVIをバックボーンにする。

量子化前に、Keyでは各channel、Valueでは各token vectorについて最大・最小側から合計s%の外れ値を抽出し、疎行列SとしてFP16保持する。既定値s=2%である。外れ値を量子化rangeから外すことで残りの値へ量子化levelを効率的に割り当てられるが、Sだけを増やすとindexとFP16値の保存量が増えるため、これだけで2-bit近似をnear-losslessにする設計ではない。

### head単位の低ランク残差回復

外れ値除去後のX-Sを量子化してD-hatを作り、残差 R = X - (D-hat + S) をattention headごとの部分行列へ分割する。各R_hに対してpower iterationで上位特異成分を近似し、A_h B_h^Tとして保持する。論文ではn=1024、head dimension=128の例でrank 4が十分小さな設定として示され、prefillではrank 4、decodeの新規buffer tokenにはrank 2を用いる。

この低ランク成分は、複数token間で共有される量子化誤差の方向を回収する。疎成分が個別の大振幅値を補正するのに対し、低ランク成分は残差のコヒーレントな構造を補正するため役割が異なる。構成要素除去では低ランク成分を外すと性能が大きく低下し、疎成分を外した場合の低下は比較的小さい。効率優先版GEAR-Lはこの性質を利用し、疎成分を省いて低ランク補正だけを残す。

### ストリーミングバッファとkernel実装

毎tokenでSVD系処理を行うと圧縮自体がdecode latencyを支配する。GEARは新規KVを小さなFP16バッファBへ蓄積し、既定例では20 tokenごとにまとめて圧縮する。decode側の低ランク近似も新しいbuffer tokenだけに適用するため、過去全KVへSVDを再実行しない。

実装ではdequantizationとmatrix multiplicationをCUDA kernelで融合する。低ランク経路もq_h^T B_hを先に計算してからA_h^Tを掛けることで、完全なLを復元せずattention寄与を計算する。この経路分離により、低ランク・疎成分の追加計算をmodel forwardに比べて小さく保つ。

## 主要結果

| 条件 | 比較 | GEAR | 結果 |
|---|---|---:|---|
| LLaMA3-8B、CoT 3 tasks、2-bit | FP16 48.69%、KIVI 28.82% | 47.83%平均accuracy | FP16に近く、KIVIを大幅に上回る |
| 全モデル/CoT、2-bit | 最良baseline | — | 平均14.95 percentage point改善 |
| LLaMA3-8B、GSM8k 5-shot、2-bit | KIVI 42.54% | 49.96% | +7.42 percentage point |
| LongBench 21 tasks、LLaMA2-7B、4-bit | FP16 26.82 | 27.80 | 圧縮しても平均scoreを維持 |
| V100、LLaMA2-7B、入力1000/生成500 | FP16 KV | 最大batch 18 | FP16の最大batch 3から6倍 |
| 同上 | FP16 KV | 最大5.07倍throughput | メモリ削減で同時request数を増加 |
| 感度評価 | rank/sparsity増加 | rank 4、s=2%でnear-lossless域 | それ以上は精度改善が小さくメモリ増 |
| 構成要素除去 | 低ランクなし | 大きく悪化 | 低ランク残差回復が主要品質要因 |

4-bit CoTではGEARの全モデル・全タスク平均が40.80でFP16の40.52をほぼ維持し、KV sizeは平均31.0%である。2-bitでは平均40.20、KV size 27.6%で、KIVIの平均25.25から大きく改善する。これは単に「低ビット化してもperplexityが近い」という結果ではなく、長い自己回帰生成で回答精度まで確認した点が重要である。

効率面の最大5.07倍は、同一batchの1-token latencyが5倍速くなるという意味ではない。2-bit KVによるピークメモリ削減でV100上の最大batchを3から18へ増やせるため、同時処理数を増やしたthroughput利得が大きい。低ランク・疎成分自体の時間割合は最適化後には小さく、主要時間はmodel forwardに残る。

## 既存研究との差

KIVIやKCVTは量子化groupの設計によってKV値を直接低ビット化する。GEARはこれらを置き換える新しい量子化codebookではなく、任意の量子化後に残る誤差へ低ランク・疎補正を追加する枠組みである。そのため4-bitでは低overheadなKCVT、2-bitでは精度の高いKIVIというようにbackboneを切り替えられる。

H2OやFastGenなどのtoken droppingはattention scoreに基づいてtoken自体を捨てるため、CoTのように多くのtokenが相互依存する条件では必要情報を失う可能性がある。またattention scoreを明示的に扱う方式はFlashAttentionとの統合が難しい。GEARはtokenを捨てず、KV値の近似誤差を下げる方向で容量を削減する。

KVQuantのようなdata-dependent量子化はcalibrationを使って量子化点を最適化するのに対し、GEARは学習・calibration不要のonline補正を狙う。代わりに、低ランク分解と疎行列処理という実行時追加コストを負い、ストリーミングとCUDA融合でそのコストを抑える設計である。

## 限界

低ランクrankを全層・全headのKey/Valueへ同一に割り当てており、層・headごとの重要度差を利用していない。著者ら自身も、低ランクbudgetを適応配分すればさらに性能を改善できる可能性を挙げている。

最大throughput評価は単一V100 16GB、LLaMA2-7B、入力1000・生成500 token、8-bit weightという限定条件である。H100/H200やpaged KV cacheを持つ現代的なserving runtimeで同じ5.07倍が得られることを直接示すものではない。またthroughput利得の大部分は圧縮で最大batchを増やせることに由来するため、低batchの単一request latency改善とは区別する必要がある。

2-bitではKCVT単独が崩れるためKIVIの細粒度groupを必要とし、GEARの量子化backboneが完全に固定不要というわけではない。さらに疎成分は値だけでなくindexも保持するため、外れ値率を上げると精度向上よりメモリoverheadが先に増えやすい。
