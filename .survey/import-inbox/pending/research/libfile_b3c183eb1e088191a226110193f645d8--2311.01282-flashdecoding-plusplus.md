# FlashDecoding++: Faster Large Language Model Inference on GPUs

> 統一最大値による非同期ソフトマックス、細長いGEMMの二重バッファ、ハードウェア適応データフローでLLM推論を最適化し、既存推論エンジン比平均1.37倍を報告する。

## 概要
LLMのデコードは小さなバッチや1トークン生成のため行列積が細長くなり、GPU演算器を使い切りにくい。FlashDecoding++は、注意の部分ソフトマックス同期、細長い一般行列積（GEMM）の低利用率、入力形状やGPUが変わっても固定されたデータフローを使う問題を同時に扱う。Hugging Face実装に対しNVIDIA GPUで最大4.86倍、AMD GPUで最大2.18倍、既存LLM推論エンジンに対し平均1.37倍の高速化を報告する。

## 問題設定
長文脈デコードでは注意を複数部分へ分割して並列化できるが、部分ソフトマックスを結合する際の同期が注意時間の約20%を占める。またデコード時GEMMは一辺が小さく、ゼロ埋め等で50%以上の性能損失が起こり得る。さらに最適なタイル・データフローは行列形状とGPU資源で変わるため単一実装では最大50.25%の性能差が生じる。

## 手法
第一に、各部分ソフトマックスで別々の最大値を使って後から再正規化する代わりに、統一最大値を使う非同期ソフトマックスを導入する。これにより部分結果間の同期を減らし、長文脈注意の結合待ちを抑える。

第二に、細長いGEMMを形状別に扱い、データ読み込みと演算を二重バッファで重ねる。GPUの共有メモリ、レジスタ、演算器のどこが律速かに応じて実行構成を変え、ゼロ埋めで演算量を水増しする方式を避ける。

第三に、入力形状とハードウェア資源を見てヒューリスティックにデータフローを選ぶ。固定カーネルではなく、GPU世代やGEMM形状に応じて資源配分を変えることでNVIDIAとAMDの双方を対象にする。

## 評価条件・主要結果
| 比較 | 結果 |
|---|---|
| Hugging Face / NVIDIA GPU | 最大4.86倍高速化 |
| Hugging Face / AMD GPU | 最大2.18倍高速化 |
| 最先端LLM推論エンジン | 平均1.37倍高速化 |
| 部分ソフトマックス同期 | 従来注意で約20%のオーバーヘッド |
| 固定データフロー | GEMM形状によって最大50.25%性能損失 |

これらは単一カーネルの理論FLOPsではなく、LLM推論で現れる複数のGPUボトルネックを個別に除去した結果である。

## 既存研究との差
Flash-Decoding系の長文脈注意高速化に加え、注意だけでなくデコード時の細長いGEMMとハードウェア依存のデータフローまで一つの推論エンジンで扱う点が差分である。

## 限界
ヒューリスティックなデータフロー選択は対象GPUと形状に依存する。報告倍率は比較実装・GPU・モデル形状で変わり、すべてのサービング負荷で同じ倍率を保証するものではない。
