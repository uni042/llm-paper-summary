# Conduit：prefixが変わったVLMのvisual KVを選択的に再計算する

## 研究課題

Vision-Language Model（VLM）へ同じ画像や文書を繰り返し質問する場合、画像prefixのprefill結果をKV cacheとして保存して再利用できれば大幅な計算を節約できる。ただし同じ画像でも、前後のsystem prompt、質問、文書の配置が変わると、以前のprefixで計算したKVが新しい要求に対して正確とは限らない。全tokenを再計算すれば正確だが高価であり、何も更新せずに再利用すると品質が低下する。この中間に位置する**visual KVの部分的なrefresh**を、どのtokenへ割り当てるかが本研究の問題である。

既存の選択法には、attentionだけで重要tokenを選ぶもの、画像ごとに均等な予算を配るもの、valueの大きさを考慮しないものがある。これらは、現在のqueryに無関係な画像の目立つtokenを更新したり、attentionは高くても残差への書込み寄与が小さいtokenへ予算を浪費したりする。Conduitはattentionとvalue normを組み合わせたtoken scoreと、複数画像のquery relevanceに基づく画像係数を一つのglobal rankingへ統合する。学習済みモデルの重みや構造は変えず、推論時に短いscoring passを一回加える。

対象は**同一visual contentの再利用**であり、新しい画像を初めて処理する一般的なprefill高速化ではない。前のcacheをどの条件で作ったか、cacheを保持するGPU/CPUメモリ費用、画像と周辺textの比率が利得を左右する。論文の主な実験は静止画像・文書のshifted-prefix再利用であり、動画や長期agent memoryは未検証である。

## 数学的動機：残差ストリームのstaleness

### attentionだけでは書込み寄与を表せない

現在のquery qがtoken tへ割り当てるcached-key attentionをα(q,t)とする。古いcacheのvalue書込みと新しいprefixで再計算したvalue書込みの差をξ_tとすると、あるtoken集合Tをrefreshした後のresidual-stream誤差は、おおまかにΣ_{t∉T} α(q,t)ξ_tで近似できる（§3.2、式3）。これは一層・一headの局所一次近似であり、fresh keyに起因するattention分布変化や上流のquery stateの変化、高次の交差項は含まない。

この近似をtoken別のリスクへ分解する際、異なるtokenのstale displacementが常に同方向へ揃わないと仮定し、交差項を落とした対角代理目的を使う。するとrefreshしないことの寄与を、query attentionのRMSとstale value差のノルムの積で順位付けする動機が得られる（式4）。しかし真のξ_tはそのtokenを再計算しないと分からず、選択時点では直接測定できない。ここが実装上の核心である。

Conduitは未知のstale差の大きさを、保存済みのpre-output cached value norm ||V_t^c||で代用する。スコアは概念的にs_t≈attention(q,t)×||V_t^c||となる（§3.3、式5）。attentionが大きくてもvalue normが小さいtokenは低く評価される。反対にvalue normが大きくても現在のqueryが読まないtokenは優先しない。これは厳密なstale errorを直接推定するのではなく、**cacheにすでに存在する量から書込み規模を近似する実用的なprior**である。

### 全層・全headの実装スコア

実際のスコアではquery span、attention head、decoder layerを平均する（式6〜7）。理論の二乗誤差代理ではattention RMSを用いるが、実装ではquery・head平均のattentionを用いる。この差は、理論の最適top-kをそのまま完全実装したのではなく、計算可能な代理へ置き換えたことを意味する。デフォルトは全decoder layerをスコア対象とし、特定の一層だけを恣意的に選ぶ必要はない。

複数画像では、各画像jのvisual tokenに対する平均attention g_jを求め、全画像平均ḡとの比からc_j=(1−λ)+λ(g_j/ḡ)を作る（式8〜9）。画像jのtoken scoreへc_jを掛け、全画像を横断してglobal top-kを選ぶ。画像ごとに固定quotaを割り当てず、質問に関連する画像へ予算を多く振れる。λ=0なら画像係数は1となり、token scoreのみで選ぶ。画像が一つならg_j=ḡでc_j=1となり、同じ方式が単一画像のtoken選択へ縮退する。この統一性は実装上有用だが、画像係数自体は理論から必然的に導いた最適形ではなく、経験的に選んだ増幅規則である。

## 推論パイプラインと評価条件

cache materializationは各比較方式で同一条件に固定する。過去の要求で作ったvisual KV cacheを新しいshifted-prefix要求に渡し、Conduitはcached keyと新しいqueryのscoring passから更新優先度を計算する。visual token総数N_visに対してfloor(r×N_vis)個だけ選び、該当KVを再計算する。比較方式も同じrefresh budgetを使い、cacheをどのように作ったかではなく、**同じ古いcacheからどのtokenを選ぶか**を比較する。

主要モデルはQwen2.5-VL-3B、Qwen2.5-VL-7B、InternVL3-9Bの公開checkpointで、fine-tuningはしない。主なshifted-prefixデータセットはLongDocURL、MMLongBench-Doc、SlideVQA、InfoSeek、ViQuAEの5件。比較対象はCacheBlend、ProphetKV、MPIC、KVShare、無更新cache reuse、全再計算full prefill。単一画像ではMMBench、OCRBench、POPE、MMStarを別途評価する（§4.1）。

実機測定にはnano-vllm派生のcompact serving backendを使用し、paged KV storageとfused attention kernelを備える。scoringは別の行列積とsoftmaxで行い、prefill kernel自体は変更しない。主なTTFT測定はbatch size 1、greedy decoding、bf16であり、cacheの初回作成費用をTTFTから除外する。したがってcacheがすでに存在する条件での**再利用要求のTTFT**であり、初回問い合わせを含む平均TTFTではない。

## 評価結果：精度とrefresh予算

| VLM・5データセット平均 | Full prefill | 更新0% reuse | Conduit更新10% | Full比 |
|---|---:|---:|---:|---:|
| Qwen2.5-VL-3B | 49.60 | 42.31 | **49.33** | 99.5% |
| Qwen2.5-VL-7B | 60.53 | 51.02 | **58.70** | 97.0% |
| InternVL3-9B | 56.96 | 49.44 | **55.97** | 98.3% |

Table 1に基づく。3モデルすべてで、更新10%のConduitが無更新reuseから大きく回復し、full prefillに近づく。Qwen2.5-VL-3Bでは49.60に対し49.33で差0.27、7Bでは60.53に対し58.70で差1.83。これはモデル・データセット別の公式評価指標を平均したscoreであり、token一致率や全要求の正答確率を直接意味する値ではない。

同じ10% budgetのProphetKVに対し、Qwen2.5-VL-3Bでは47.56→49.33、7Bでは57.10→58.70と改善する。InternVL3-9Bでも同様の傾向が報告される。5% budgetでも3モデルの5データセット平均でConduitが最高、15組の個別データセット×backboneのうち13組で最高だった。ただし各データセットの絶対値はモデルと評価指標が異なるため、たとえばOCRBenchの点数をMMLongBench-Docの点数と同じ単位の品質と解釈しない。

単一画像のK=1条件では、そもそも更新0%のreuseがfullに近い。Qwen2.5-VL-3Bの4ベンチマーク平均はfull 74.9、reuse 74.6、Conduitの5%更新75.0。InternVL3-9Bではfull 78.4、reuse 78.7、Conduit 78.9と、無更新でもfullを上回る評価揺らぎがある。これらは「cacheが古いほど常に品質が低い」という単純な関係を示さない。改善余地が小さい場面では、scoringと部分更新の費用を払う意義も小さくなる。

### Ablation：value normと画像係数

Qwen2.5-VL-3Bでλを0から1へ変えると5データセット平均は48.53→49.33に改善する（Table 4）。λ=0.5では49.30、λ=0.75では49.23で、最良値はλ=1だが中間値との違いは小さい。デフォルトλ=1を全モデル・データセットへ固定しており、ベンチマークごとに最適化した値ではない。

Table 5では画像係数c_jを外すとQwen2.5-VL-3Bの平均が49.33→48.53、7Bが58.70→58.23、InternVL3-9Bが55.97→55.43に下がる。value normを外しattentionのみで順位付けすると、それぞれ48.44、57.35、55.44に下がる。特に7Bではvalue normの寄与が大きい。一方、InternVL3-9Bでは二つのablationの差がわずか0.01であり、要素の寄与の大小はbackbone依存である。

Appendix D.3の代理スコア分析では、制御された条件でのranking相関がSpearman 0.79〜0.89程度と報告される。しかしこれはstalenessの真値を常に正確に当てる保証ではない。実際に、Qwen2.5-VL-3BでConduitとfull prefillの回答が異なる23例の手作業監査では、15例がanswer-bearing page内の更新不足、4例が証拠ページとdistractorの近接、4例が未モデル化のattention driftと整合的だった。残る失敗の性質が具体的に説明されている。

## Serving latencyとFLOPs

| MMLongBench-Doc latency subset | Score | Prefill TFLOPs | TTFT秒 | Full比速度 |
|---|---:|---:|---:|---:|
| Full prefill | 43.59 | 90.36 | 0.519 | 1.00× |
| 無更新cache reuse | 41.41 | 2.47 | 0.049 | 10.69× |
| CacheBlend 10% | 41.82 | 11.36 | 0.180 | 2.89× |
| MPIC 10% | 41.78 | 9.97 | 0.090 | 5.76× |
| KVShare 10% | 41.19 | 11.02 | 0.284 | 1.83× |
| ProphetKV 10% | 42.06 | 12.13 | 0.169 | 3.07× |
| Conduit 10% | **43.26** | 12.24 | 0.174 | **2.99×** |

Table 3の測定は3 backbone×4k/8k/16kの9条件を平均した別のlatency subsetで、主な5データセット平均scoreとは一致しない。ConduitはfullのTTFT 0.519秒を0.174秒に短縮し、2.99倍の速度を報告する。prefill FLOPsは90.36→12.24 TFLOPsで約13.5%に低下するが、FLOPsの約7.4倍削減がTTFT約3倍にとどまるのはcache read、kernel launch、scoring、メモリ帯域などの固定費があるためである。

重要な負の比較として、ProphetKVはscore 42.06でConduitより低いが、TTFTは0.169秒でConduitの0.174秒より**わずかに速い**。MPICはscore 41.78と低い一方、TTFTは0.090秒とかなり短い。つまりConduitは品質と速度のPareto上で一律にすべての方式を支配するわけではない。目的の品質閾値とlatency要件に応じて選ぶ必要がある。

16k条件のオンラインTTFT内訳ではcache load 0.020秒、scoring 0.068秒、value-norm access 0.00018秒、部分再計算0.158秒、text prefill等0.014秒、合計約0.261秒と報告する。scoringはTTFTの26.2%を占める。したがってスコア計算が「ほぼ無料」という解釈は誤りである。cached value normはquery非依存なのでcache作成時に保存しておけばonlineでのvalue tensor読取りを減らせる可能性があるが、論文の実測ではその最適化を全面的に利用したものではない。

## 限界と実務上の適用条件

第一に、prefixが変わるたびに新しいqueryを評価するため、scoring pass自体のGPU計算が発生する。cacheが短い、visual tokenが少ない、あるいはtext prefixの方が長い場合、refreshを省く利得がscoring費用を下回り得る。何も更新しないreuseがすでにfullに近い単一画像の実験は、その境界を示している。

第二に、**cached visual KV自体の保存費用は減らない**。本研究はKV圧縮ではなく、再利用時に一部の古いKVを再計算する選択ポリシーである。巨大な画像集合を長期保存する場合、cacheの容量、追い出し、再利用可能性の判定は別の問題として残る。cacheが破棄された後の再生成には通常のprefillが必要となる。

第三に、理論モデルはstale value書込みに注目し、fresh keyによるattention driftやquery-state伝播を明示的に扱わない。実際の差分を観測するにはrefreshが必要であるため、cached value normはあくまで代理であり、異なるprefixの変化が大きい場合やattention patternが大幅に変わる場合に順位を誤る可能性がある。23例の手作業監査でもattention driftに整合的な失敗が存在する。

第四に、実験は静止画像と文書であり、動画、streaming frame、長期agentic workflowへそのまま一般化しない。複数画像の係数c_jを時間的なframe relevanceへ拡張することは可能な研究方向だが、時系列の情報更新や時間経過によるcacheの陳腐化を評価した結果ではない。

第五に、latency測定はnano-vllm派生のcompact backend、batch size 1、bf16であり、production continuous batchingや同時要求数が大きい環境を測っていない。P95/P99 TTFT、goodput、GPUのメモリ圧迫時の挙動、CPU/GPUオフロードを含む条件では再評価が必要である。特にonline scoringが独立した行列積とsoftmaxを必要とするため、batch処理時のkernel schedulingに影響し得る。

第六に、論文は「training-free」をモデル重みの追加学習不要という意味で使う。実装にはcache materialization、query-conditioned scoring、refresh maskを用いたselective recomputationを組み込む必要があり、既存の一般的な推論サーバーへ設定だけで導入できるとは限らない。公開コードの確定URLは一次資料内で確認できなかったため、`code: null`とした。

この論文はKVをどのように小さく保存するかではなく、**同じ画像に対する別の質問で、古いKVのどこを更新すれば品質を回復できるか**という選択問題を扱う。残差書込みの代理スコアと画像レベルの関連度を統合し、限定されたrefresh予算で品質を回復することを示した点が有用である。一方、実際の導入判断では品質–TTFT–cache容量の三つを同時に測る必要がある。
