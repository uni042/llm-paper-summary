## 概要
agent workflowは一要求の中で複数stage・複数LLM呼出しを行うため、各agentへ高価な最大modelを固定するとserving費用が大きい。安価なmodelへ事前routingする方式も、要求実行中にsystem負荷が変化すると、その固定configurationがすぐ非最適になる。

Aragogは精度を保てるworkflow全体のmodel構成を一度抽出し、実行中は各stageの到着時点で最新の負荷を見て候補から選ぶ。高価な精度探索と頻繁なsystem schedulingを分離することで、stageごとの再最適化を安価にする。

## 問題設定
workflowの実行時間は長く、途中でGPU queueやmodel replica負荷が変わる。開始時に全agentのmodelを固定すると、後段が実行される時には別modelのqueueが空いていても切替できない。一方、毎stageで全configurationのaccuracy/costを探索するのは組合せ爆発で現実的でない。

## 手法
### 一回のaccuracy-preserving routing
workflowについて、最も高価な構成と同等の精度を維持できるmodel割当候補を事前に絞る。実行時schedulerは品質を再推定せず、この安全候補集合だけを見る。

### stage単位のjust-in-time scheduler
各agent stageが実行可能になった時点で、model replicaのqueueやsystem負荷を観測し、候補集合から現在最も効率的なmodelを選ぶ。要求開始時ではなくstage直前に決めるため、長いworkflow中の負荷変動へ追従できる。

### 探索とruntime制御の分離
accuracy探索は重いが一回、runtime選択は軽いが頻繁、という責務分離により巨大なconfiguration空間を毎回探索せずに済む。

## 評価条件
| 観点 | 内容 |
|---|---|
| 対象 | multi-stage agentic LLM workflows |
| 比較 | fixed/pre-execution configuration routing |
| 指標 | maximum serving throughput、median latency、accuracy |
| 負荷 | peak request rateを含む動的system load |

## 主要結果
多様なworkflow/model familyで最大serving throughputを50.0〜217.0%増加させ、peak request rateではmedian latencyを32.5〜78.9%削減した。精度は最も高価なconfigurationと同程度を維持する。

## 既存研究との差
通常のmodel routerがrequest単位で一度modelを選ぶのに対し、Aragogは一つのworkflow要求の内部でstageごとに選択を更新する。accuracy制約候補の抽出とsystem負荷schedulerを分ける点も異なる。

## 限界
事前にaccuracy-preserving候補を作る費用が必要で、workflowやmodel集合が頻繁に変わると再探索が必要になる。利得はmodel間の速度・品質差と負荷変動幅に依存する。
