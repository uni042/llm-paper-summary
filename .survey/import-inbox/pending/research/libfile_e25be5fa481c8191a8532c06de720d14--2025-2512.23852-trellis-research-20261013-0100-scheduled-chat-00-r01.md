# Trellis: Learning to Compress Key-Value Memory in Attention Models

## 概要

通常の自己注意では、生成済みの全トークンに対する鍵ベクトルと値ベクトルを保持し、次のトークンでそれらを参照する。生成長を $T$ とするとキャッシュの容量は $T$ に比例し、系列全体での注意計算は二次的に増える。Trellisは、長さに比例して拡張する鍵・値キャッシュを、$m$ 個のスロットからなる**固定容量の状態**へ置き換えるためのモデル構造である。過去を単純に切り捨てるのではなく、新しいトークンが入るたびに既存の状態と照合して再構成誤差を減らす方向へ記憶を書き換える。

提案は、鍵を圧縮して中間表現を得る第1段と、値を圧縮して出力を得る第2段からなる。両段に共通の記憶目標ベクトルを与え、オンライン勾配降下と忘却ゲートで過去情報の保持と置換を調節する。非線形な状態更新をそのまま逐次計算すると並列化しにくいため、チャンク開始時の状態を用いる近似により、行列積と並列走査で処理できる形へ変形している。

790Mパラメータを300億トークンで学習した比較では、言語モデルのLAMBADA困惑度がTransformer++の25.89、Gated-DeltaNetの21.40に対しTrellisは20.28となり、六つの常識推論課題の平均正解率も46.09%、47.52%に対し48.38%であった。1BモデルによるRULERの合成検索課題では9条件平均79.8%で、比較対象中の次点75.8%を上回る。一方、特定の4K・8K検索条件では他方式が上回り、忘却が必ずしも有利でない。これらは**モデル品質の評価**であり、推論基盤での毎秒トークン数やGPUメモリ使用量の実測改善率を意味しない。

## 問題設定：容量制限と長期検索の両立

通常の因果的自己注意では、時刻$t$の問い合わせ$q_t$を過去の全鍵$K_t$と比較し、その重みで値$V_t$を合成する。$K_t,V_t$には各時刻のベクトルが追加されるため、トークンを生成するほど状態が増える。固定容量を維持する単純な方法は、直近$m$トークンだけを保持するスライディングウィンドウである。しかし、その範囲外にある固有名詞や初期条件は検索できなくなる。

固定数のスロットに新しい鍵・値を加算するABC（Attention with Bounded-memory Control）や、その忘却ゲートを備えるGSA（Gated Slot Attention）は、容量を一定に保ちながら過去を圧縮する。しかし単純な外積加算は、既存メモリに何が書かれているかを十分に見ずに新情報を足す。スロットが混雑すると古い情報と新しい情報が干渉し、必要な記憶を保持しながら不要な情報を置き換えることが難しい。

Trellisは、メモリの現在値を入力と照合して「どの方向へ更新すれば目標表現を復元できるか」を求める。鍵・値をそのまま積むのではなく、**記憶内容に依存する非線形な圧縮**をオンラインで実行する。モデルの通常パラメータは推論中に固定し、各系列に対応する小さな内部状態だけを更新するため、ここでいうテスト時学習はモデル全体の再学習ではない。

## 手法

### 1. 固定容量の記憶と二段階圧縮

系列のトークン表現$x_t$から通常の線形射影で問い合わせ$q_t$、鍵$k_t$、値$v_t$を作り、別の学習済み射影$W_\alpha$から$m$次元の目標表現$\alpha_t=W_\alpha x_t$を作る。$m$は系列長$T$と独立した記憶スロット数であり、鍵側・値側の記憶行列はおおむね$m\times d$の固定形状となる。新しいトークンが増えても行数を増やさず、既存行列の中身を更新する。

第1段では、鍵$k_t$と目標$\alpha_t$を使って鍵記憶を更新し、問い合わせ$q_t$から中間表現$\hat y_t$を読み出す。第2段では、その中間表現に正規化・活性化関数$f$を適用し、値$v_t$と同じ$\alpha_t$を用いて値記憶を更新し、最終出力$y_t$を生成する。鍵側が「どの記憶を使うか」に相当する情報をまとめ、値側が「何を返すか」に相当する情報を圧縮する構造である。両段で同じ$\alpha_t$を目標とすることが、異なるスロットへ鍵と値を無関係に書き込むことを防ぐ設計上の接点となる。

本文では中間活性化に正規化したSiLUやLayerNorm付きSiLUなどを検討する。密に圧縮した少数スロットを参照する場合、通常のsoftmaxのように一部だけを強く選ぶ変換が最良とは限らず、表2の構成要素除去実験でも関数の選択が困惑度へ大きく影響する。実装では短い一次元畳み込みで鍵・問い合わせを処理し、Trellis層の後段に正規化とGeLUゲートを配置する構造が図1に示されている。

### 2. 記憶状態に依存するオンライン勾配更新

鍵記憶行列$M_t$の目的は、入力鍵から目標スロット表現を再構成することにある。論文の式(4)では、損失を $\mathcal{L}_t=\|\phi(M_t k_t)-\alpha_t\|^2$ と置く。$\phi$は非線形変換であり、目標とのずれが大きければそのずれを減らす勾配を計算する。新しいトークンを処理するたびに、記憶状態を$M_{t+1}=M_t-\gamma_t\nabla_M\mathcal{L}_t$で更新する。ここで$\gamma_t$は更新の強さを決める係数である。

従来の外積加算と異なり、勾配は$\phi(M_t k_t)$を通じて**すでに保存された記憶内容**に依存する。したがって、同じ鍵が来ても既存状態が異なれば更新方向が変わる。行列全体のヤコビ行列を明示的に構成する必要はなく、ベクトル・ヤコビ積を使って勾配を求めると本文は説明する。これにより、記憶の混雑時に一律加算する方式より、現在の状態を踏まえた修正が可能になる。

このオンライン更新は、学習済みモデルの重みをユーザーごとに書き換えるのではなく、系列の進行とともに変化する「高速重み」としての記憶状態を更新するものだ。外側の学習では射影行列やゲートなどを通常の学習手順で最適化し、内側では系列ごとに記憶を更新する二重の最適化構造を取る。モデルを初期状態から学習する必要があり、既存の量子化済みTransformerに無変更で適用できるとは示していない。

### 3. 忘却ゲートによる過去情報の置換

固定スロットは、新しい情報を無制限に足すと飽和する。そこで損失に記憶行列の大きさへの正則化項を加え、式(8)の形で$M_t=\beta_t M_{t-1}-\gamma_t u_t k_t^\top$と更新する。$\beta_t=1-\lambda_t$は0から1の忘却係数であり、1に近いと既存状態を保持し、0に近いと古い状態を大きく消す。$u_t$は再構成誤差を非線形変換に沿って伝播させた更新方向である。

この係数は単純な「古いトークンから捨てる」規則とは異なり、入力に応じて状態全体の残存度を調節する。話題の切替えで古い記憶を弱め、新しい重要情報を書き込む余地を作る狙いがある。ただし忘却は常に利益とは限らない。RULERの一部の合成検索課題では、古い情報を長く残す単純な方式がTrellisを上回る。固定容量で何を捨てるかという問題は、構造を導入しても消滅しない。

### 4. チャンク単位の近似とGPU向け並列化

各時刻の$M_t$を用いて非線形勾配を逐次求めるだけでは、系列長が長い学習やプリフィル時に並列実行しにくい。Trellisは系列を長さ$C$のチャンクへ分け、チャンク内の勾配計算では開始時の記憶状態$M_{t'}$を共通参照する近似を導入する。チャンク内で「勾配を計算するための基準状態」を固定すると、非線形な依存の一部が取り除かれ、更新を線形漸化式に近い形へ整理できる。

各時刻の忘却係数の累積積$\mu$と、時刻間の減衰積$\Omega$を計算し、式(10)〜(12)でチャンク全体の状態更新と読出しを行列演算へまとめる。更新を一時刻ずつGPUへ発行する代わりに、行列積器で複数トークンを処理し、チャンク境界だけで記憶状態を引き継ぐ。本文はMamba2の状態空間双対性に関連付け、並列走査とチャンク形式による計算・入出力効率の改善可能性を論じている。

ただし、この実装説明は**GPU上の演算形式の導出**であり、vLLMなどの推論サーバへ組み込んだときの実測処理量、CUDAカーネルの単体性能、チャンク近似の精度対速度曲線を示すものではない。後述の評価は主にモデル品質と学習計算量の比較である。再帰的な1トークン更新と、チャンク化した多数トークン処理の性質は分けて解釈する必要がある。

論文表1は約790Mパラメータ・300億トークンで学習したモデルを比較する。LAMBADAの困惑度と六課題の平均正解率は次の通り。常識推論の平均はPIQA、HellaSwag、WinoGrande、ARC-e、ARC-c、SIQAの六課題であり、LAMBADAの正解率は含まない。

| 方式 | LAMBADA困惑度（小さいほど良） | 常識推論6課題平均正解率（%） | 読み取れること |

| Transformer++ | 25.89 | 46.09 | 通常の注意機構を持つ比較対象 |
| Mamba2 | 28.91 | 46.23 | 状態空間型の比較対象 |
| TTT | 27.05 | 46.71 | テスト時学習型の比較対象 |

### 構成要素除去と負の結果

表2は125M、The Pileでの困惑度を比較する。完全構成のTrellisは10.87だが、忘却ゲートを外すと11.28に悪化する。中間活性化をsoftmaxにすると11.29、非線形性を外して線形な更新とsoftmaxを組み合わせると12.71となる。記憶スロット数を32に減らすと11.14、128にすると10.87であり、容量と品質には交換条件がある。完全に非線形な逐次更新に相当するチャンク長1の設定は10.75で、チャンク近似を採ることに小さい品質差があることも示唆する。

| 125M・The Pileでの構成 | 困惑度 | 比較上の意味 |
|---|---:|---|
| 完全構成Trellis | **10.87** | 基準 |
| 忘却ゲートなし | 11.28 | 忘却の選択が品質に寄与 |
| 中間活性化softmax | 11.29 | 圧縮記憶では鋭い選択が最良とは限らない |
| 線形更新＋softmax | 12.71 | 記憶内容依存の非線形更新の寄与が大きい |
| 記憶スロット32 | 11.14 | 記憶を小さくすると品質低下 |
| 記憶スロット128 | 10.87 | より大きい状態では品質を維持 |
| チャンク長1 | 10.75 | 逐次的な非線形更新がわずかに良い |

この構成要素除去実験は、単に「忘却がある」「二段階である」という名称上の特徴ではなく、記憶状態を参照した非線形な勾配更新と忘却を組み合わせることが品質に効く証拠となる。ただし実験表だけでは、チャンク長を変えた際の実GPU時間やメモリ帯域がどれだけ変わるかまでは分からない。

## 既存研究との差

スライディングウィンドウ注意は直近$m$トークン以外を切り捨てる。ABCは固定スロットに鍵・値の外積を加算するが、現在の記憶内容に基づく誤差修正が弱い。GSAは忘却ゲートを加える一方、基本更新は加算型の線形漸化式である。Trellisは、スロットへの書込みを再構成誤差のオンライン最適化として定義し、既存記憶の内容を踏まえて更新する。さらに鍵側と値側の二段階を同じ目標表現で結び、出力を形成する。

Mamba2などの状態空間モデルも系列長に比例しない推論状態を実現するが、Trellisは鍵・値を圧縮する二段階構造と状態依存の勾配更新を明示する。TTTはテスト時学習の枠組みを共有するが、Trellisはスロット単位の鍵・値メモリの圧縮と忘却に焦点を当てる。表1・表2・表4の品質比較はこの設計が有効な条件を示すが、実装の処理量比較や同一モデルの置換実験を代替しない。

## 限界・適用条件

1. **既存LLMへそのまま差し込めない。** Trellisは学習時から新しい記憶更新層を組み込むモデル構造であり、学習済みTransformerのKVキャッシュを後付けで圧縮するプラグインではない。本文は将来の事前学習済みTransformerから再帰型への変換を研究方向として挙げている。
2. **実運用の速度・メモリ容量は未検証。** 固定サイズ状態という計算上の特徴とチャンク並列化の導出はあるが、TTFT、TPOT、毎秒トークン数、実GPU HBM使用量、複数同時要求の実測は論文の中心評価に含まれない。システムの高速化倍率を創作しない。
3. **忘却には検索品質の代償がある。** RULERのS-NIAH-PK 4K/8KではTTTより低く、忘却が保持すべき情報を薄める可能性がある。平均値の改善だけでは全検索条件での保証にはならない。
4. **モデル規模の外挿に制約がある。** 評価は125M〜1Bであり、数十B級MoE、量子化モデル、分散サービングで同じ傾向が成立するかは示していない。
5. **近似的なチャンク更新と逐次更新は同一でない。** チャンク開始時の状態で勾配を近似するため、チャンク長1の困惑度10.75と標準構成10.87の差がある。GPU効率と品質の詳細な交換条件は別途測定が必要である。
6. **データセットと学習条件に依存する。** The Pile、C4、Booksを個別に用い、Transformer++の長文脈ゼロからの学習は8Kまでに制限される。異なるコーパスや事前学習条件の数値を直接の同一条件比較として扱わない。
