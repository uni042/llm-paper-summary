# SelfCP: Compressing Over-Limit Prompt via the Frozen Large Language Model Itself

> 凍結した対象モデル自身に超過分だけを12倍のメモリトークンへ圧縮させ、残りは無加工で読ませることで、学習可能パラメータ17Mのまま長文プロンプトの品質と処理可能量を回復する圧縮方式。

## 概要

要約や質問応答では長い文書がそのままプロンプトになり、文脈内学習では多数の事例がプロンプトを膨らませる。入力がモデルの窓制限を超えると、超過分は切り捨てられ、重要な情報が失われる。かといってプロンプト全体を少数の仮想トークンへ圧縮する従来方式は、生成器が圧縮表現だけを頼りに答えるため生成が難しくなり、圧縮器として別モデルを使う方式は対象モデルとの整合のための学習費用が大きい。著者らはこれを、学習費用、推論効率、応答品質を同時に満たせない三角形として整理する。

SelfCPの着眼点は二つある。第一に、圧縮器として対象モデル自身を使う。事前学習で得た理解能力をそのまま圧縮に流用でき、別モデルの整合が不要になる。第二に、圧縮するのは超過分だけに限定し、制限内に収まる部分は通常のトークンとして無加工で生成器へ渡す。窓の一部を圧縮表現のために空費せず、重要な部分は原文のまま残せるため、圧縮と生成の双方の難度が下がる。対象モデルは凍結され、学習されるのは圧縮器の出力を生成器が読める形へ写す線形コネクタと、圧縮開始を示す特殊埋め込みだけであり、学習可能パラメータは17M、骨格の約0.24パーセントである。

**代表結果:** 領域内のXSUM要約とCICERO質問応答では、窓512の素のVicuna-7BがROUGE-1で19.9と17.3にとどまるのに対し、SelfCPは30.5と33.3まで回復し、窓を1024へ広げた素のモデルに迫る。領域外のDUC要約ではROUGE-1が33.6で、切り捨て時の24.0、LLMLinguaの32.5、AutoCompressorの31.7を上回る。文脈内学習では、24GBメモリで素のVicunaが4事例までしか扱えない条件でSelfCPは64事例まで動作したと報告される。

## 問題設定

問題の資源は入力窓とメモリである。自己注意の計算とKVキャッシュは入力長とともに増え、長いプロンプトはメモリを圧迫し推論スループットを落とす。窓を広げる研究はあるが、長い入力での品質低下自体は残る。トークンを間引く抽出型圧縮は、抽出器と対象モデルの分布のずれという問題を抱え、整合のための微調整が高くつく。ソフトプロンプト型の圧縮は、AutoCompressorが区間ごとに再帰的に圧縮するため長い入力を読めるが圧縮が逐次で遅く、ICAEは一度の圧縮で速いが窓を超えた部分はそもそも読めない。さらに従来のソフトプロンプト型は圧縮表現を常に入力の先頭へ置く前提であり、文書の前半を圧縮して後半を残す、あるいはその逆といった実際の配置に対応できない。本論文は、窓制限Lに対して長さNのプロンプトが来たとき、捨てず、逐次にもならず、位置の自由度を保ちながら超過分を扱うことを課題とする。

## 手法のあらまし

処理は圧縮と生成の二段である。まずプロンプトを、無加工で残す区間と圧縮する区間に分ける。圧縮対象の区間の末尾へ特殊なメモリタグを並べて対象モデルへ通すと、タグ位置の最終層の隠れ状態に区間の情報が集まる。この隠れ状態を線形コネクタで写したものがメモリトークンであり、元の区間の12分の1の長さになる。生成段では、問い、メモリトークン、無加工の区間を元の相対位置を保って連結し、同じモデルが応答を生成する。プロンプトが窓の2倍を超える場合は、無加工区間をLトークン確保し、残りを重ならない局所区間へ分けて各々を独立に圧縮し、局所メモリトークンを連結して全体のメモリトークンとする。各区間の圧縮は独立なので並列化でき、圧縮段数はGPUが同時に処理できる区間数に依存する。学習時はモデルを凍結し、正解応答に対する言語モデリング損失でコネクタとタグ埋め込みだけを更新する。

## 手法

### 1. 自己圧縮とメモリタグ — 対象モデル自身が区間を要約ベクトルへ変える

この機構が観測するのは圧縮対象区間のトークン列と問いである。入力は問い、対象区間、メモリタグの列を連結したもので、タグは入力側でモデルに圧縮役への切り替えを伝え、順伝播を通じて先行区間の情報を吸収する容器として働く。保持される状態はタグ位置の最終層の隠れ状態であり、それ以外の位置の状態は捨てる。この隠れ状態がコネクタで生成器の埋め込み空間へ写され、メモリトークンになる。選択されるのは圧縮対象区間であり、文書要約では経験的に重要な前半を残して後半を圧縮し、中国の判決文生成では人物紹介を含む前半を圧縮するなど、タスクごとに重要度の低い側を圧縮する。これにより減るボトルネックは、切り捨てによる情報損失と、別圧縮器の整合費用である。追加で消費する資源は圧縮段の順伝播そのものであり、区間を並列に処理できる場合は実時間の増分は小さいと測定される。誤った場合の挙動として、圧縮率を16倍まで上げると品質が大きく落ちることが感度分析で示されており、情報の吸収が不十分な区間では要約に必要な固有名詞などが欠落し得る。事例研究では、切り捨てでは失われた航空機の型式名がメモリトークンから復元されたことが示される一方、復元は確率的であり保証はない。

### 2. 前方・後方・連結の三つの圧縮配置 — 圧縮表現の置き場所を固定しない

この機構が扱うのはメモリトークンの相対位置である。前方圧縮は前半を圧縮してメモリトークンを前に置き、後方圧縮は後半を圧縮して後ろに置く。学習時に長さが窓の2倍未満の事例を二分割し、前後どちらを圧縮するかを無作為に選ぶことで、モデルは両配置に対応する。連結圧縮は窓の2倍を超える場合の拡張で、無加工区間以外を複数の局所区間に分け、各区間を独立に圧縮して連結する。これにより減るボトルネックは、従来方式の先頭固定という制約と、超長文での逐次再帰圧縮の遅さである。AutoCompressorの再帰は区間数だけ逐次段数が必要だが、SelfCPの局所圧縮は独立で、並列度が高い場合は一段で済む。追加費用は局所区間ごとのタグとコネクタ処理であり、区間数が増えるほど圧縮段の総計算は増える。誤った場合の挙動として、区間境界で文脈が分断されるため、区間をまたぐ依存が強い文書では情報が落ちやすい。著者らも、再帰圧縮の情報損失を避ける代わりに独立圧縮を選んだことが文脈内学習で有利に働いたと解釈している。

### 3. 文脈内学習向けのメモリ事例バンク — 圧縮済み事例を使い回し検索する

文脈内学習では、各事例を一区間として独立に圧縮し、そのメモリトークンをメモリ事例バンクへ保存しておく。再利用時は事例を再圧縮せずバンクから取り出すため、事例数が増えても圧縮費用が繰り返し発生しない。さらに、各事例の最初のメモリトークンを検索キーとし、問いを圧縮して得た最初のメモリトークンとのコサイン類似度で事例を選ぶ方向性のある選択を備える。これにより減るボトルネックは、事例の再圧縮の繰り返しと、無作為な事例選択の不安定さである。追加で消費する資源はバンクの保持メモリであり、事例あたり元の12分の1のトークン数で済む。誤った場合の挙動として、類似度が低い事例が選ばれると利得が消えるが、固定事例の条件でもSelfCPは比較対象を上回っており、検索は追加の利得として位置づけられる。評価では5000件のバンクからの検索で、XSUMの5事例条件のROUGE-1が27.6から30.0へ上がった。

## 評価

結論は、超過分だけを対象モデル自身に圧縮させることで、切り捨てで失われる品質の大部分を回復でき、領域外タスクや文脈内学習でも比較対象を上回る、というものである。領域内評価では、窓512のSelfCPが窓1024の素のモデルに迫り、同条件でLoRA調整した骨格をも上回る場面がある。これは、単に学習データで調整した効果ではなく、圧縮表現が切り捨てられた情報を実際に運んでいることを示す。領域外では、英語のDUCと中国語のCLCVの双方で最良となり、骨格の得意言語を圧縮がそのまま活かすことも確認された。文脈内学習では、メモリトークンが実事例と同等以上の効果を持ち、事例数を増やすほど差が開く。特にARXIV要約では、素のBlueLMが事例追加で大きく劣化するのに対し、SelfCPは安定しており、長い文書と事例が窓を取り合う条件で圧縮の利点が明確になる。

効率の読み方には注意が要る。長さ1024の入力で後半512トークンを43個のメモリトークンへ圧縮する測定では、SelfCPの総計算量は素のモデルの約3倍になるが、圧縮が並列化できるため実測のGPU時間の増分は小さく、窓を1024へ広げて全文を読む条件よりは軽い。つまり利得は計算量の削減ではなく、窓制限の中で全文の情報を扱えることと、メモリ制約下で扱える事例数の増加にある。圧縮率の感度では4倍から12倍まで品質が比較的滑らかで、16倍で大きく落ちるため、既定の12倍はこの折れ点の手前に置かれている。論文では、実運用のサービング基盤での遅延や、7Bを超える規模への適用は未評価である。

## 既存研究との差

AutoCompressorとの差は、再帰の有無と無加工区間の保持である。再帰圧縮は区間をまたぐ情報を逐次に畳み込むため情報損失と逐次遅延が生じるが、SelfCPは局所圧縮を独立に行い、重要な区間は原文のまま残す。ICAEとの差は、窓を超える入力を扱えることと、LoRAで骨格自体を変えないことである。LLMLinguaのような抽出型との差は、離散トークンを残すのではなく対象モデル自身の隠れ状態から連続表現を作るため、抽出器と対象モデルの分布のずれが生じにくい点にある。長文Transformer系の研究が注意機構そのものを変えて最初から学習し直すのに対し、SelfCPは既存モデルを凍結したまま後付けできる点が実務上の差である。

## 限界・実装状況

限界は、評価が7B級の2骨格と要約・質問応答系タスクに限られる点、圧縮率16倍で品質が大きく落ちる点、区間分割による文脈分断の影響が系統的には測られていない点、サービング基盤での実遅延やスループットが未評価である点である。コネクタは単一の線形層であり、著者ら自身が接続部の選択にはなお探索の余地があると述べている。実装状況として、コードとデータはGitHubで公開されており、学習手順と使用モデルも具体的に示されている。骨格を大きくすることと、圧縮を事前学習の目的自体へ組み込むことが将来課題として挙げられている。

## 一般的な実装上の含意

圧縮は全入力に一律に掛けるのではなく、制限を超えた部分だけに限定すると、生成の難度と情報損失の双方を抑えられる。圧縮器と生成器を同じモデルにすると整合費用が消え、学習対象を小さな接続部へ絞れる。圧縮表現の配置位置を固定しない設計は、指示と文書の順序がタスクごとに変わる実務のプロンプトでは必須の配慮である。圧縮率には品質の折れ点があるため、感度を測って折れ点の手前を既定値にすべきである。
