# MoAS：MHA・GQA・MQAをトークン単位で混合する注意機構の小規模検証

## 書誌と重要な解釈

本稿はarXiv:2512.20650v1（2025年12月16日公開、表紙日付12月25日）の一次論文全5ページを確認した解説である。著者はEsmail Gumaan、題名は「Mixture of Attention Schemes (MoAS): Learning to Route Between MHA, GQA, and MQA」。論文は注意方式の動的選択による将来的な条件付き計算を提案するが、**実際に測定した実装では三つの注意枝をすべて計算し、出力を重み付き平均している**。推論時の枝の排他的な選択、KVキャッシュ削減、トークン/秒の高速化は実証されていない。この区別が本論文を読む上で最も重要である。

## 概要

標準の多頭注意（Multi-Head Attention; MHA）は各問い合わせ頭に独立したキー・バリュー（Key-Value; KV）頭を持ち、表現力が高い一方、生成時のKVキャッシュが大きくなる。多問い合わせ注意（Multi-Query Attention; MQA）はすべての問い合わせ頭が一組のKVを共有するためキャッシュ容量を減らせる。群化クエリ注意（Grouped-Query Attention; GQA）は複数の問い合わせ頭を群にまとめ、KVを共有する中間方式である。

MoASは「すべてのトークンがMHAの表現力を必要とするわけではない」という仮説から、トークンの入力表現を小型ルータに渡し、MHA・GQA・MQAの三方式の混合重みを予測する。各注意方式の出力を重み付き合成し、入力ごとに注意方式の寄与を変える。実験では静的に三方式を平均する場合より検証損失がわずかに小さくなったが、MHA単独より損失が大きく、学習時間も増えた。

WikiText-2の小型4層モデルで、動的MoASの検証損失は**2.3074**、静的混合は**2.3093**、MHA単独は**2.2940**である。低いほど良い指標なので、提案は静的混合より0.0019改善した一方、MHAより0.0134悪い。これは条件付き計算の可能性を示す探索的結果であって、LLM推論の実用的高速化を実証した結果ではない。

## 問題設定

自己回帰生成では、過去トークンのキーとバリューをKVキャッシュに保存する。問い合わせ頭数HとKV頭数H_KVが等しいMHAでは、層数、系列長、頭数に比例してキャッシュ容量が増える。MQAではH_KV=1にして共有し、GQAでは1<H_KV<Hの中間値を採用する。KVを共有するほど保存量は減るが、異なる問い合わせ頭が独立した情報を参照する能力に制約が生じる場合がある。

従来のモデルは通常、MHAかGQAかMQAを設計時に固定する。MoASは、入力トークンの難しさによって必要な注意の表現力が異なるなら、トークンごとに方式を選べるのではないかと考える。混合専門家モデル（Mixture-of-Experts; MoE）がトークンを異なる前向き計算へ振り分けるのと類似した考え方を、注意機構の内部構造へ適用する。

ただし、本論文の評価では「難しいトークンだけMHA、簡単なトークンはMQA」と実際に**排他的に実行したわけではない**。三方式の出力をすべて計算するため、ルータがあることと条件付き計算の節約が成立することは別である。論文の結果から推論時の省メモリを主張することはできない。

## 手法

### 1. 三種類の注意枝を用意する

入力トークン表現xᵢ（次元d）をMHA、GQA、MQAの三つの注意枝へ渡し、それぞれの出力O_MHA、O_GQA、O_MQAを計算する。MHAは問い合わせ頭数HとKV頭数が同じで、すべての頭が独立したKVを持つ。MQAはKV頭数が1であり、すべての問い合わせ頭が共有する。GQAはその中間で、論文の実験では**H=6、G=2**としている。

三枝を同じ入力に対して計算することで、ルータが出力の組み合わせを選べる。これにより注意方式を固定するモデルより表現の自由度が増える可能性があるが、実験の構成では三枝のパラメータと計算を同時に保持するため、通常のMHAよりパラメータ数と計算時間が増える。

### 2. トークン表現から混合重みを予測するルータ

ルータは二層の小型多層パーセプトロン（Multi-Layer Perceptron; MLP）である。式(4)(5)では rᵢ=W₂ GELU(W₁ xᵢ)、gᵢ=softmax(rᵢ) と定義する。W₁はdからd/4への射影、W₂はd/4から3次元への射影であり、出力gᵢは三方式に対する非負の重みで合計1になる。

ルータはトークンの入力表現に依存して重みを変える。固定混合との違いは、MHA/GQA/MQAの寄与率が全トークンで同じではない点である。ルータは三方式のどれか一つだけを選ぶ離散的なスイッチではなく、softmaxによる**連続的な混合比率**を出す。

### 3. 注意出力の重み付き合成

式(6)では、出力yᵢを三枝の注意出力の重み付き和として定義する。具体的には yᵢ=gᵢ,MHA O_MHA+gᵢ,GQA O_GQA+gᵢ,MQA O_MQA である。ルータの重みと各枝の出力が同じモデルの損失を通じて更新されるため、学習により入力依存の注意混合を獲得できる。

この合成は、各枝の結果が得られた**後**に実行する。したがって計算費用の観点では、すべての注意方式を動かしてから平均する。たとえあるトークンのgᵢ,MQAがほぼ1でも、MHA枝とGQA枝の計算を省略していなければ、理論上のKV削減は実測の節約にならない。著者は将来の実運用では選択した枝だけを実行する構成を想定するが、本論文ではその性能を測っていない。

### 4. 負荷均衡の補助損失

学習が進むとルータが一つの枝、たとえばMHAだけを常に使う可能性がある。これを防ぐため、バッチ内の平均混合重みが各方式で1/3に近づくよう、式(7)の負荷均衡損失を加える。各方式kについて、平均gᵢ,kと1/3との差の二乗を足したものである。

この補助損失はルータの出力が一つに偏ることを抑えるが、各トークンで本当に計算量が減るかを直接最適化するものではない。すべての枝を実行する実装では、平均重みが均等になってもGPUの計算量やKVキャッシュの実測容量が減るとは限らない。均衡を強く求めすぎると、品質上MHAが有利な入力でもMQAを使うよう誘導する可能性がある。

### 5. 静的混合との比較構成

著者は、三枝を一定重みで平均する**静的MoAS**と、トークンごとにルータが重みを変える**動的MoAS**を比較する。静的混合も三枝を同時に計算するため、動的混合との差は主としてルータの入力依存性にある。これにより、注意方式を混ぜること自体の効果と、入力ごとに混合比率を学習する効果をある程度分離できる。

一方、MHA単独との比較では、動的MoASは三枝とルータを持つため、パラメータ数が異なる。動的MoASが静的混合よりわずかに良くても、同じパラメータ予算・同じ学習時間で最良という結論にはならない。

## 評価条件

| 観点 | 一次論文の設定 |

| データ | WikiText-2言語モデリング |
| モデル | デコーダ専用Transformer、4層、隠れ次元384、注意頭数6 |
| GQA | KV頭数G=2（問い合わせ頭数H=6） |
| 文脈長 | 256トークン |
| ドロップアウト | 0.1 |
| 学習 | 500反復、バッチサイズ12、学習率3×10⁻⁴ |
| 比較対象 | MHA単独、三枝の静的平均、三枝の動的ルータ混合 |
| 品質指標 | WikiText-2の検証損失（低いほど良い） |
| 費用指標 | パラメータ数、1反復当たりの学習時間（概数） |
| 未評価 | 推論時トークン/秒、実測KVキャッシュ容量、実用規模LLMの正答率 |

この評価は7B/70Bの大規模言語モデルではなく、**約700万～1000万パラメータの小型モデル**で行われている。大規模モデルや長文脈へそのまま結果を外挿することはできない。文脈長256トークンという条件は、長文脈KVキャッシュが支配的な運用状況を直接再現していない。

## 主要結果

| モデル | パラメータ数 | 最終検証損失 | 学習時間（ms/反復） |
|---|---:|---:|---:|
| MHA単独 | 7.19百万 | **2.2940** | 約500 |
| 静的MoAS | 10.14百万 | 2.3093 | 約900 |
| 動的MoAS | 10.29百万 | 2.3074 | 約1,680 |

動的MoASは静的MoASより検証損失が**0.0019小さい**。この差は、入力に応じて混合重みを変えることで、一定の混合比率より良い損失を得られる可能性を示す。しかしMHA単独の2.2940に対しては**0.0134大きい**。提案方式が品質で最良という結果ではない。

計算費用では、動的MoASのパラメータ数は10.29百万で、MHAの7.19百万より約43%多い。1反復当たり学習時間は約1,680msで、MHAの約500msに対して**約3.36倍**である。静的混合の約900msに対しても約1.87倍であり、ルータ導入による追加費用が目立つ。これらは**学習時間**の測定であって、生成推論の遅延ではない。

著者は「動的ルーティングが静的平均より優れる」と解釈するが、報告された損失差は小さく、乱数種ごとの分散や統計的有意性の検証は本文に示されない。再現性を評価するには、複数乱数種での平均・分散と、同一計算予算での比較が必要になる。

### 主要機構と評価の対応

**三枝の混合**は、静的MoASとMHA単独の比較で検証される。静的MoASの検証損失はMHAより悪いため、三方式を混ぜるだけでは品質改善は確認できない。**入力依存ルータ**は動的MoASと静的MoASの比較で検証され、0.0019の小幅改善が得られた。**負荷均衡損失**については独立した要素除去表がないため、均衡項単独の品質・速度寄与を定量化できない。

**条件付き計算の高速化**については、提案したが測定していない。全枝を実行する現行実装では、むしろ学習時間が増えることが確認される。実用化の評価としては、MHA・GQA・MQAのどのKVをどの時点で保存するか、途中で方式が変わる場合に過去KVをどう扱うか、選ばない枝の計算を本当に省略できるかが重要になるが、本文はこれらの実測結果を提示しない。

## 既存研究との差

MHA、GQA、MQAは通常、モデルの注意構造として固定される。MoASは三つの方式を一つのモデル内で並列に保持し、トークン表現に依存するルータで出力の寄与を変える。これは専門家混合（Mixture-of-Experts; MoE）の条件付き経路選択に着想を得た設計だが、MoEで典型的な上位k専門家のみの実行とは異なり、実験のMoASは三枝すべてを動かす。

PagedAttentionはKVキャッシュのメモリ配置を効率化し、MQA/GQAはKV頭数を構造的に減らす。MoASが目指すのは、トークンごとにこれらの注意方式の表現力を切り替えることだが、実際に複数のKV頭数を同一系列で安全に切り替えながらキャッシュを共有する方法は実装上の課題として残る。したがって本稿を「KVキャッシュを削減する実用推論エンジン」として扱うのは不正確である。

## 限界・負の結果・実装上の問題

第一に、実験は4層・隠れ次元384・文脈長256の小型モデルだけである。大規模LLM、長文脈、複数GPU、バッチ推論での結果はない。元々の問題設定は長いKVキャッシュの費用だが、実験ではその費用が支配的な条件を直接検証していない。

第二に、動的MoASはMHA単独より検証損失が悪く、パラメータ数と学習時間も増える。提案の長所は静的混合との比較でわずかに良いという点に限られ、MHA単独に対する品質・費用の同時優位は成立していない。

第三に、softmaxによる混合は三枝の出力をすべて必要とする。実験でのルータは**硬い選択ではなく連続的な混合**であり、MHA枝を実行せずに済むわけではない。論文は将来の上位1枝選択を課題として挙げるが、現行結果を上位1枝選択の性能と読み替えてはならない。

第四に、KVキャッシュの実際の管理が未解決である。MHA、GQA、MQAでは保存するKV頭数が異なる。トークンごとに方式を切り替えるなら、過去トークンのKVをどの形式で保持するか、異なる枝からの参照をどう統合するか、枝の切替費用がいくらかを定める必要がある。論文にはこれらの詳細な実装・測定はない。

第五に、検証損失差0.0019の有意性、複数乱数種、学習曲線の分散、実際の生成品質は報告されていない。500反復という短い訓練設定の結果を、学習を十分に収束させた大規模モデルの性能へ一般化することはできない。

第六に、負荷均衡項がルータ崩壊を抑えるという設計意図は合理的だが、負荷均衡項を外した要素除去実験がない。ルータが各トークンにどの枝をどれだけ割り当てたかという分布の詳細も十分ではない。どの種類のトークンでMHAを使うのが有利か、という当初の仮説は十分に検証されていない。

## 実装・再現性

著者はコードを公開している。論文に近い再現には、4層・d=384・H=6・G=2・文脈256・ドロップアウト0.1・500反復・バッチ12・学習率3×10⁻⁴という条件を揃え、MHA単独、静的三枝平均、動的三枝混合を比較する必要がある。

今後の実用化を検証するなら、まず全枝計算を行う現在の方式と、選択した枝だけを実行する上位1方式を分け、生成時のKVキャッシュ容量、トークン/秒、メモリ転送量、ルータの負荷、回答品質を測る必要がある。これは本論文の既報結果ではなく、未検証の研究課題である。
