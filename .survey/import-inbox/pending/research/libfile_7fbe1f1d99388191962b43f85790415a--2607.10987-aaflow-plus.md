## 概要
複数LLM agentが同じ長いdocumentやprompt prefixを共有しても、通常のtext-centric workflowではagentごとにtextを受け取り、同じprefixを再びprefillしてKV cacheを作り直す。AAFLOW+はtextだけをworkflow edgeで渡すのではなく、既に計算したKV state自体を分散node間で再利用する「状態流（stateflow）」を導入する。

## 問題設定
local prefix cacheは同一serving instance内では効くが、agent graphが複数nodeへ跨がるとstateの所在、互換性、転送、fork、evictionをworkflow runtimeが扱えない。長contextではprefill時間がTTFTを支配する一方、KV tensor自体も大きいため、networkが遅い場合は転送より再計算の方が安い。この境界をschedulerが判断する必要がある。

## 手法
AAFLOW+のstateful operatorは通常のdata input/outputに加えてinput/output stateとstate policyを持つ。workflow graphにはtext/JSONのdata edgeとKV-state edgeを別に表現し、compilerがmaterialize、transfer、fork、composition、eviction operatorを挿入する。

KV state objectはmodel ID、tokenizer/model configuration、KV block、position metadata、lineage、placement/ownershipを保持する。modelやpositionが互換でないstateを誤再利用しないcompatibility checkを行い、条件を満たさなければtext再prefillへfallbackする。

分岐workflowでは共有prefixを一度materializeし、copy-on-write型に複数agentへforkする。node間転送はCPU serializationを避けるzero-copy data pathを使い、受信側backendへKVをinjectしてprefillをskipする。

schedulerは `KV size / bandwidth + transfer overhead` とlocal prefill costを比較し、transferが安い場合だけstateflowを選ぶ。したがって低帯域networkで巨大KVを無条件に送る方式ではない。

## 評価条件
|項目|内容|
|---|---|
|model例|Mistral-7B、Llama-3-8B|
|workflow|multi-agent debate、Tree-of-Thought等のbranching agent workflow|
|比較|text再prefill、local prefix-cache系|
|network|10～100 Gbps級を含む帯域感度|
|評価方式|hardware microbenchmarkでparameter化したanalytical cost model|
|指標|TTFT、aggregate compute cost、KV memory、throughput|

## 主要結果
長contextではTTFTを最大50.2倍短縮し、16-agent規模でaggregate compute costを最大7.63倍削減する。共有blockとforkによりKV memory footprintは1.72～6.10倍削減し、throughputは7.74倍超改善する。

network感度では100 Gbps以上で有意なcontextならstate transferがほぼ常に有利となり、10 Gbpsでも数千tokenを超えるとtransferが再計算を上回る領域が現れる。これは「KV共有は常に速い」ではなく、context長とbandwidthのcross-overをcost modelで選ぶ設計を裏付ける。

## 既存研究との差
vLLMのPagedAttentionやSGLangのRadixAttentionは主にlocal serving scopeでKVを管理する。KVCOMMもagent間KV communicationを扱うが、AAFLOW+はworkflow compilerからstate lifecycle、fork、placement、evictionまでをoperator abstractionへ持ち上げ、agent graph全体をoptimization対象にする。

## 限界
headline値は完全な大規模production deploymentのend-to-end実測ではなく、実機microbenchmarkでparameter化したanalytical cost modelに基づく。この点は50.2倍等の値をproduction実測として解釈してはいけない。KV transferはnetwork bandwidthとmodel/position compatibilityに依存し、低帯域や短prefixでは再prefillの方が有利になり得る。
