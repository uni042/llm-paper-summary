# T-MAC: CPU Renaissance via Table Lookup for Low-Bit LLM Deployment on Edge

> 低ビット重みGEMMをbit-wise LUTへ変換してCPUのdequantization・乗算を除き、llama.cpp比最大4倍の生成throughputと70%のenergy削減を実現する。

## 概要
edge CPUでweight-only量子化LLMを動かす場合、重みは2〜4 bitでもactivationはfp16/fp32であり、CPUに低bit×高precisionのネイティブ積和命令がない。そのため既存実装は重みを高精度へ展開してからGEMMを行い、量子化で減らしたメモリ量が演算効率へ十分つながらない。T-MACは積をbit-wise table lookupへ変換し、dequantizationなしで混合精度GEMMを実行するCPU kernelである。

## 問題設定
低ビット化でモデル転送量は減っても、dequantization、型変換、高精度乗算がdecodeの費用になる。特にedge CPUでは専用Tensor Coreがなく、bit幅を2 bitへ下げても算術量が比例して減らない。

## 手法
T-MACは低ビット重みをbit-planeへ分解し、高精度activationの小グループから可能な符号組合せの部分和をLUTへ作る。重み側bit patternをindexとして部分和を引くことで、要素ごとの乗算をtable lookupと加算へ置換する。

LUT構築はactivationに依存するが、一つのactivation blockに対して多数の重み行から再利用される。重みbit幅ごとにbit-planeを処理するため、kernel計算量はweight bit-widthへほぼ線形に比例する。

実装ではCPU SIMD命令でlookupを並列化し、weight packingとLUT layoutをcache/SIMD幅に合わせる。これにより理論的な乗算削減を実機throughputへ変換する。

## 評価条件・主要結果
|項目|内容|
|---|---|
|対象|低bit Llama、BitNet|
|比較|llama.cpp|
|platform|Apple M2 Ultra、Raspberry Pi 5等のCPU|
|throughput|llama.cpp比最大4倍|
|energy|最大70%削減|
|BitNet-b1.58-3B / M2 Ultra|1 core 30 token/s、8 core 71 token/s|
|Raspberry Pi 5|11 token/s|

単一coreでも30 token/sに達する結果は、低bit化をメモリ削減だけでなく演算削減へ結びつけた効果を示す。bit幅を下げるほど処理量も減るため、従来のdequantize型kernelより低bit化の利得を取り込みやすい。

## 既存研究との差
llama.cpp等の一般的なweight-only kernelがpacked weightを展開して高精度activationと積和するのに対し、T-MACは重み値そのものを乗算operandへ戻さずLUT indexとして扱う。GPU向け低bit Tensor Core依存方式とも異なり、汎用CPU SIMDを主対象にする。

## 限界・実装状況
LUT構築にも費用があり、行列形状が小さく再利用が少ない場合は償却しにくい。性能はCPUのSIMD table-lookup能力、cache、memory bandwidthに依存する。GPU推論や大規模batchサービングを主評価対象にはしていない。一方、実装は公開され、EuroSys 2025の成果としてedge CPUで実測評価されている。
