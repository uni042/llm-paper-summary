# NorthPole推論ラック：オンチップメモリとカード間パイプラインによるLLMサービング

## 概要

大規模言語モデルの生成は、各トークンを出すたびに多数の重みと鍵・値キャッシュ（KVキャッシュ）を参照する。汎用GPUでは外部の高帯域メモリ（HBM）との転送と、複数GPU間の通信が性能・消費電力を左右する。本論文は、IBM ResearchのNorthPole専用推論チップを搭載したPCIeカード288枚を18台の2Uサーバーへ組み込み、モデル配置、量子化、パイプライン、実行時ソフトウェア、クラウドAPIまでを一体で設計した研究試作システムを報告する。

ラック全体の仕様は4ビット整数演算115ペタ演算/秒、チップ内の集約メモリ帯域3.7ペタバイト/秒、設置面積0.67平方メートル、重量約730kgである。8BパラメータのGranite-3.3-8B-Instructを6台のサーバー・84枚のカードへ配置した場合、2,048トークン文脈・28同時利用者の単一インスタンスで、利用者あたりのトークン間遅延（inter-token latency、ITL）2.8ミリ秒、バッチの出力処理量約10,341トークン/秒を報告する。ラックにはこの8B構成を3インスタンス同時配置できる。

本研究は**汎用GPU向けソフトウェア高速化ではなく、専用半導体からクラウドサービスまでの垂直統合設計**である。公表された電力約30kWは6サーバー構成の実測を3インスタンスへ外挿した推定であり、288枚を用いるラック全体で同じ負荷を直接測った実測値と区別する必要がある。

## 問題設定：外部メモリ転送と分散推論の費用

通常のGPU推論では、重みを高帯域メモリから読み込み、各層の注意機構と多層パーセプトロンを繰り返し計算する。バッチが小さい復号では演算器を十分に埋められず、外部メモリから重みを運ぶ費用が大きくなりやすい。パイプライン並列化を使って層を複数装置へ分割すれば、モデルの容量制限を緩められるが、段ごとの処理時間が長いと空き時間が生じる。GPUの高い処理効率を引き出すために大きな小バッチを必要とすると、利用者ごとの次トークンまでの時間が延びる。

NorthPoleは、計算資源と記憶資源を各チップ内に分散して配置し、推論中の重み・中間活性値を可能な限りチップ内で保持する。重みを外部メモリから毎回読む前提を減らすことで、小さい小バッチでも高速に動くという設計を採る。ただし1チップに全LLMを載せるわけではなく、各層をカード間に分割し、カード同士は必要な中間表現を交換する。したがって設計上の課題は、モデルをオンチップ容量へ収めながら、カード間通信を最小限にしてパイプラインを途切れさせないことにある。

## 手法

### 1. NorthPoleチップとカード

1チップは12nm工程の約220億トランジスタを持ち、16×16の256コア配列を構成する。各コアに計算・通信・制御・メモリ資源を持たせ、チップ内の総記憶容量は224MBである。内訳は重みや中間表現に使う192MBと、チップ外の入出力を段取りする32MBのフレームバッファである。整数8/4/2ビットと浮動小数点16ビットをサポートし、4ビット整数演算の集約能力がラック全体の115ペタ演算/秒という仕様につながる。

NorthPoleカードはPCIe形状であり、カードごとにチップと通信・制御回路を持つ。1枚のカードは通常のLLM推論で約55W未満と報告され、空冷を前提とする。チップ内に重みと中間表現を保持するため、カード間では層の出力に相当するテンソルを主に受け渡す。これはGPUの外部HBMアクセスを完全になくすという意味ではなく、専用チップ上の推論経路において**重みと中間活性値のオフチップ転送を減らす**という意味である。

### 2. モデル分割とカード間パイプライン

Granite-3.3-8B-Instructは40層の変換器を持ち、各層の注意ブロックと多層パーセプトロンを別々のカードへ配置する。出力層は4枚のカードへテンソル並列化して配置し、合計84枚のカードを6台のサーバーに分散する。サーバー内の通信はPCIe、サーバー間は200GbEとRDMA over Converged Ethernet（RoCE）を使う。専用の大規模GPU間相互接続装置を前提にしない構成である。

各カードは前段から受け取った中間表現を計算し、次段へ送る。計算時間を短くすることで、1件ずつの小バッチをパイプラインへ多数流しても段間の空き時間を抑える。本文は16段以上のパイプラインでは小バッチサイズ1を採用し、段数とほぼ同数の小バッチを並行させれば空き時間を小さくできると報告する。これは大きなバッチで各GPUを埋める設計とは異なる。

### 3. KVキャッシュをオンチップへ保持する制約

同時利用者の過去トークンに対応するKVキャッシュも、対象モデルのカードに割り当てたオンチップメモリへ保持する。これにより復号中にホストメモリからKVを繰り返し読み戻す経路を減らす。しかし、オンチップ容量は有限である。利用者数を増やすほどKVが増え、同じモデルでも文脈長が長いほど収容可能な同時利用者数は減る。

実際に8Bモデルでは2K文脈で28同時利用者、4K文脈では14同時利用者という設定を用いた。したがって、長文脈の巨大なKVをCPUやSSDへ退避する方式とは解決する問題が異なる。**容量を超えたKVを扱う柔軟性と、オンチップ常駐による低遅延との交換条件**がある。

### 4. クラウド推論サービスと実行時制御

研究試作は単にカードへ演算を割り付けるだけでなく、実際の利用者要求を受け付けるサービスを構築する。入口はストリーミング型のチャット補完APIで、要求にはモデルと優先度が付く。RabbitMQのメッセージ仲介機構を経由して、対象モデルを担当する推論インスタンスが空いたときに要求を取り出す。

各サーバーではNorthPoleアプリケーション用のコンテナがカードを構成・制御する。パイプライン先頭のサーバーには、段間を調整するパイプライン管理コンテナと、トークン化など非ニューラル処理を担当するシーケンス先頭コンテナが追加される。先頭コンテナは同時利用者ごとのワーカースレッドを管理し、推論開始・トークン送出・要求終了を制御する。利用者から見える応答時間には、この非ニューラル処理や要求待ち行列も関与するため、チップ単体の演算速度をサービス全体の速度と同一視できない。

### 5. 低ビット化と精度回復

Granite-3.3-8B-Instructの元の重みはbfloat16で学習されている。NorthPoleへ載せる際は、活性値8ビット・KVキャッシュ8ビット・重み4ビット（A8-C8-W4）へ量子化する。単純に精度を落とすだけでは回答品質が下がるため、SiLQという量子化対応学習（quantization-aware training）で精度を回復する。本文ではH100を8基備えた学習ノードで、バッチ128・系列長1024、約2週間・128,000ステップの微調整を行ったと報告する。

このため本方式は「学習不要で既存の16ビット重みをそのまま実行する」方式ではない。モデルを対象ハードウェアへ適合させる学習と配置計画を前提にする。量子化後のモデルを19種類の評価課題で検証し、平均56.8点と元モデル56.4点の近い水準を報告したが、個別課題では増減がある。

## 評価条件と測定指標

| 項目 | 論文の条件 |
|---|---|
| ハードウェア | 1ラック18台の2Uサーバー、最大288枚のNorthPole PCIeカード |
| CPU・ホスト | サーバー当たりXeon Gold 6354×2、DDR4 1TB |
| 通信 | サーバー間200GbE/RoCE、ラック内ネットワーク機器 |
| 主評価モデル | Granite-3.3-8B-Instruct、40層、A8-C8-W4 |
| 8B配置 | 6サーバー、84カード、ラック内3インスタンスまで |
| 入力・出力 | 文脈2Kまたは4K、入力と生成をそれぞれ約半分に設定 |
| 同時利用者 | 2Kで28人、4Kで14人（単一8Bインスタンス） |
| 測定 | 各条件で1,400要求、最初のトークンまでの時間、トークン間遅延、出力処理量 |
| 電力 | 6サーバーの負荷実測を基にラック全体を外挿 |

最初のトークンまでの時間（time to first token、TTFT）は、事前充填開始から最初の生成トークンまでを測る。トークン間遅延（ITL）は、同一利用者が隣接する生成トークンを受け取る間隔の平均で、小さいほど利用者には滑らかに表示される。バッチの出力トークン/秒は全利用者の生成量をまとめた値であり、利用者1人の速度と混同してはならない。また事前充填時間を含めた有効出力処理量は、生成段階だけの処理量より低くなる。

## 主要結果

| 8B単一インスタンス | 文脈2K・28人 | 文脈4K・14人 |
|---|---:|---:|
| 最初のトークンまでの時間 | 64.8 ms | 96.2 ms |
| 利用者あたりトークン間遅延 | 2.8 ms | 2.8 ms |
| 入力トークン/秒（バッチ） | 78,996 | 82,810 |
| 出力トークン/秒（バッチ） | 10,341 | 5,098 |
| 事前充填込み有効出力トークン/秒 | 9,552 | 4,855 |

2Kの単一インスタンスが出力約10,341トークン/秒を示すため、同条件の3インスタンスをラックに配置すると総出力処理量約30,000トークン/秒と説明される。4Kでは同時利用者数が半分となり、ラック全体で約15,000トークン/秒の構成を示す。これはカードの計算能力が半分になったことではなく、KVをオンチップに収めるための同時利用者制約と測定条件の違いを反映する。

量子化モデルの19課題平均は56.8点、元のbfloat16モデルは56.4点であった。平均値は近いが、論文の図では課題別に改善・悪化があるため、全能力が厳密に同一とまでは言えない。量子化対応学習の追加費用も、この推論性能を得るための事前投資として考慮すべきである。

ラック電力については、カード16枚を搭載した1サーバーに50W/枚の電力枠を与え、空冷・電源余裕を含めて約2.2kW、18台で39.6kWの設計上限を見積もる。一方、実負荷では8Bモデルを6サーバー・84カードへ配置した構成が10.0kWを消費した。そこから3インスタンスへ外挿した値が約30kWである。これはフルラック構成の直接測定値ではなく、実測と外挿を組み合わせた値である。

## 既存GPUサービングとの違い

通常のGPU分散推論は、GPUの大きな演算器と外部HBMを活用し、モデル並列化やKV管理によってメモリ・通信を調整する。NorthPoleは、重みと中間表現を専用チップ内に保持できるようにモデルを量子化・分割し、小さい小バッチを多数のパイプライン段へ流す。専用ハードウェアの演算器とメモリの配置が出発点であり、汎用GPUで同じアルゴリズムだけを実装して同じ消費電力になるわけではない。

本論文はカードの搭載数だけでなく、モデルの精度回復、KV容量に応じた同時実行数、API入口、優先度付き要求キュー、パイプライン管理までを含めた点に価値がある。一方、同じモデル・同じ精度・同じ文脈・同じ要求分布で、最新GPUサービング基盤と消費電力や費用を直接比較する表は示されていない。専用ラックの仕様値と一般GPUの仕様値を単純に割って優劣を決めることはできない。

## 限界と再現上の注意

最も重要な制約は、重みとKVをオンチップへ収める前提である。モデルが大きくなればカード数が増え、文脈が長くなれば同時利用者数が減る。論文は20Bや120B級モデルの配置例も示すが、主たる実測はGranite-3.3-8B-Instructであり、120B級で同じ2.8msの遅延を実測したものではない。汎用GPU上での実装可能性を直接示す研究でもない。

消費電力は設計上限、部分構成の実測、ラック全体の外挿を区別する必要がある。空冷・既製サーバー・200GbEの採用は実運用上の利点だが、初期設備費、量子化対応学習、カード供給、故障復旧、複数モデルの負荷変動を含む総所有費用は論文だけでは評価できない。結果をGPUと比較する場合は、最初のトークン時間、利用者あたり遅延、同時利用者数、出力トークン数、文脈長、精度、電力測定範囲を揃える必要がある。

## サービング容量の設計上の含意

2K文脈で28人、4K文脈で14人という設定は、利用者数と文脈長の積に相当するKV保持予算がほぼ一定であることを示唆する。もっとも実際のKV消費量は層数、ヘッド数、量子化精度、入力と生成の配分に依存するため、単純な積だけで別モデルの収容人数を推定できない。オンチップKV保持を前提にする以上、文脈長が伸びる運用ではカード追加や同時実行数の抑制が必要となり、低遅延の数値と収容能力を常に対にして評価するべきである。
