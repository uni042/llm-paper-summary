# Reformer: The Efficient Transformer

## 概要
Reformerは、長系列Transformerで支配的になる二種類のメモリ問題を別々の機構で解く。第一は全token対全tokenの自己注意が系列長 `L` に対して `O(L²)` のscore matrixを作ること、第二は逆伝播のため各層activationを保持すると層数 `N` に比例してmemoryが増えることである。64K tokenでは単一head以前に `64K×64K` のattention matrixがFP32で16GBとなり、通常実装は現実的でない。

局所性鋭敏ハッシュ（Locality-Sensitive Hashing; LSH）注意は、query/keyをランダム回転に基づくhash bucketへ集め、近いvector同士だけを比較する。可逆残差層は後段activationから前段を再構成して全層activation保存を避け、feed-forward network（FFN）は系列方向chunkへ分けて一時activationを縮小する。これらによりenwik8で64K token、imagenet64で12K tokenを扱い、full Transformerに近い品質を保ちながら長系列で速度とmemoryを改善する。

## 問題設定
通常のscaled dot-product attentionは `QK^T` を作り、batch×head×length×lengthのmemoryと計算を要求する。memory-efficient実装でmatrix全体を保持しなくても計算量は二乗のままで、長系列では時間が律速になる。

さらにattentionだけを疎化しても、各Transformer層の入力activationとFFN中間activationをbackpropagation用に保持すれば `batch × length × d_ff × layers` が残る。Reformerはattention、層activation、FFN一時領域を別問題として分解し、三つを同時に削減する。

## 手法

### 共有QKとLSH注意
Reformerはqueryとkeyへ同じprojectionを使い、正規化したshared-QK空間を作る。各vector `x` にランダム行列 `R` を掛け、`argmax([xR; -xR])` でhash bucketを決める。softmax attentionでは大きなdot productが支配的なので、近いkeyを同じbucketへ高確率で集めれば、全keyを走査せず候補を絞れる。

実装ではquery/keyをbucket番号でsortし、固定長chunkに分け、自chunkと隣接chunkを中心にattentionする。複数hash roundを並列に使えば近傍を取り逃がす確率を下げられるが、その分計算が増える。synthetic duplication taskでは4 hashで学習したモデルが4 hash評価で99.9%、8 hash評価で100%となり、hash数が品質と計算の明示的な調整つまみになる。

### 因果maskとhash後の並べ替え
自己回帰decoderではfuture tokenを参照してはいけないため、bucket sort時に元のposition indexも同じpermutationで移動し、sort後に位置比較してcausal maskを復元する。shared-QKでは自分自身とのdot productが常に大きくなりやすいため、他に有効なtargetがない場合を除いてself-attention-to-selfをmaskする。

この処理によりhash順序へ並べ替えても元系列の因果関係を保持できる。単なるnearest-neighbor検索ではなく、autoregressive attentionとして成立させるための重要な実装条件である。

### 可逆残差層
activationを二分して `y1=x1+F(x2)`, `y2=x2+G(y1)` のような可逆更新を行うと、出力とparameterから入力を復元できる。backward時に層を逆向きに再計算するため、通常Transformerのように全層activationを保存しない。

これによりmemory式から層数 `N` によるactivation保持係数を除ける。ただし計算を再実行するため、memory節約は追加computeとの交換条件である。論文の学習曲線では通常residualとreversible版の品質差はほぼない。

### FFN chunking
FFNは各tokenへ独立に適用されるため、系列全体の `d_ff` 中間activationを同時保持する必要がない。Reformerは系列をchunkへ分け、同じFFNを順次適用する。数値的には元のFFNと同じ計算で、peak temporary memoryだけを減らす。

LSH、reversible layer、FFN chunkingを合わせることで、論文の複雑度表ではReformerのattention関連項が長さにほぼ線形×hash/chunk因子となり、層activationの保存も削減される。

| 項目 | 条件 |

| image | imagenet64 generation、約12K sequence |
| translation | WMT14 English-German |

| batch | 合計8 sequences |

| 公開実装 | Google Trax Reformer |

## 主要結果

| 条件 | 結果 | 意味 |
|---|---|---|
| duplication task、LSH-4学習 | LSH-4評価99.9%、LSH-8評価100% | hash round増加で近似誤差を縮小可能 |
| WMT14 reversible base 100K | BLEU 27.6 | 通常Transformer base 27.3と同等以上 |
| WMT14 reversible big 300K | BLEU 29.1 | 既報big 28.4〜29.3帯に入る |
| enwik8 12-layer | 1.19 bits/dim（20K steps） | 大型長系列modelが単一core memoryへ収まる |
| enwik8 tuned 12-layer | 1.05 bits/dim | 長系列でも品質を維持 |
| attention速度対length | LSHは長さ増加でほぼflat、full attentionは悪化 | 二乗attentionの長系列律速を回避 |

論文は20層級Reformerを長系列で学習できた一方、同条件のfull Transformerはmemoryと速度のため比較学習できなかったと報告する。したがって「何倍速い」という単一headlineより、通常Transformerが実行困難になる系列長へ実行可能領域を拡張した点が主要結果である。

## 既存研究との差
Sparse Transformerのような固定sparsity patternでは、遠距離でも内容的に重要なtokenをpattern外なら直接拾えない。Reformerは内容ベクトルの近さをLSHで近似し、queryごとに候補集合を変える。さらにattention sparsityだけでなく、reversible layerとFFN chunkingを組み合わせてactivation memoryまで同時に処理する点が特徴である。

## 限界
本論文の主目的には学習memory削減が大きく含まれ、現代LLM servingのKV cache最適化を直接扱う研究ではない。LSHは近似なのでhash roundを減らすと精度が落ち、増やすと計算量が増える。hash-sort自体にもoverheadがあり、短い系列ではfull attentionの方が単純で有利になり得る。評価モデルも2020年時点のTransformerで、現在の数十B級decoder-only LLMのdecode latencyを直接測定したものではない。
