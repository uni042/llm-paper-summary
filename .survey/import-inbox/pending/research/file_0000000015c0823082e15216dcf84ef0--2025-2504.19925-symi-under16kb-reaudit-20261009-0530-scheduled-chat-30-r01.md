# SYMI: Efficient Mixture-of-Experts Training via Model and Optimizer State Decoupling

> 人気度が刻々と変わる専門家へGPUの複製枠を割り当て直すため、専門家重みと最適化状態の配置を切り離す。通信量の理論と実機での収束時間を区別して評価する。

## 概要

混合専門家（Mixture-of-Experts、MoE）モデルでは、各トークンを少数の専門家へルーティングするため、すべての専門家が同じ量の計算を担当するとは限らない。学習の進行に伴って人気のある専門家は変わり、同じ専門家へ割り当てられるトークン数が短期間で大きく変動する。静的な専門家配置では、人気専門家の処理が詰まる一方で不人気専門家のGPUは遊休になりやすい。専門家ごとの容量上限を設けて過剰トークンを落とせば反復時間は短くなるが、学習に使われないトークンが増えて目標損失へ到達する反復数が増える。

SYMIは、専門家の**モデル重み**と、それを更新するための**最適化状態**を別々の配置対象として扱う。最適化状態はCPU側のホストメモリへ全ノードにわたって静的に分割し、動かさない。一方、GPU上の専門家重みは前回のルーティング人気度に合わせて毎反復複製数と配置を変更する。更新済み重みをGPUへ戻す通常の通信の宛先を次反復の配置先に変えることで、専門家再配置だけのための追加転送を避ける。

16枚のA100を使う実験では、GPT-Smallの目標損失4.0までの学習時間がDeepSpeedの147.84分から102.68分となり、30.5%短縮する。FlexMoEの再配置間隔10反復の138.61分と比べても25.9%短い。トークン破棄の削減で必要反復数が減る効果と、反復時間自体を短くする効果の両方が寄与する。ただし実機モデルは125M〜760MパラメータのGPT系MoEであり、数千億パラメータ級の本番MoE学習を直接実証したわけではない。

## 問題設定：負荷変動と最適化状態の移動費用

専門家並列ではGPUごとにいくつかの専門家実体を置き、ルータがトークンを担当専門家へ送る。専門家を複製していれば、同じ専門家へ来たトークンを複数GPUへ分散できる。しかしすべての専門家を同数複製する方式では、ルーティングの偏りに対応できない。原論文の図2では32専門家を持つGPT-Smallの一層で、特定専門家の割当トークン数がわずか3反復で16倍以上変動する。50〜100反復に一度の再配置ではこの短周期変動に追随できない。

容量係数を1、2、4と増やした予備実験では、トークン生存率は44.90%、65.56%、74.91%へ改善し、目標損失に必要な反復数は618、527、478へ減る。一方、前向き計算遅延は455.41、506.77、571.42ミリ秒へ増える。トークンを落とすと反復は速いが学習は進みにくく、落とさないと反復が遅くなる。単純な容量上限の調整だけでは両方を改善しにくい。

動的複製で人気専門家を増やそうとしても、従来の実装では専門家重みとAdam系最適化器のモーメント等をまとめて移動する必要がある。論文の例では専門家一つの重みが3.375GB、最適化状態が27GBであり、400Gbpsの相互接続でもそれぞれ0.0675秒、0.54秒の転送費を要する。最適化状態の方が圧倒的に大きく、毎反復の移送は現実的でない。SYMIの問題設定は、この巨大な状態を動かさずに専門家の複製だけを更新することにある。

## 手法

### 1. 専門家重みと最適化状態の分離

SYMIでは、各専門家の最適化状態を全ノードのホストメモリへ均等に分割して保持する。これは専門家が現在どのGPUに複製されているかと無関係な静的配置である。一方、GPU上の専門家実体はルーティング負荷に合わせて増減し、別のGPUへ再配置される。勾配は各専門家実体から最適化状態の分割片があるノードへ送られ、そこでパラメータ更新が計算される。

この分離は、最適化状態を削除したり、専門家重みをCPUだけに置いたりする方式ではない。GPUは専門家の順伝播・逆伝播を実行するため重みを保持し、CPUは最適化状態を保持して更新に必要な通信を受ける。最適化状態を全ノードへ均等に分割するため、ある専門家が人気になっても特定ノードだけに巨大な状態が集まることはない。専門家のGPU配置を変更しても最適化状態の所有者は変わらない。

原論文は最適化状態の総容量が静的方式とSYMIで同じになることを式で示す。専門家クラス数E、各専門家の最適化状態容量Oなら総容量はEOであり、SYMIはそれをNノードへ均等に分割する。最適化状態の総容量そのものを減らす圧縮ではなく、再配置時に移送しないことで通信のピークと反復停止を防ぐ設計である。

### 2. 前反復の人気度を使う動的配置

各反復の前向き計算では、ルータがどの専門家へ何トークンを割り当てたかを集計する。全GPU間で小さな人気度ベクトルを全削減通信し、層ごとのメタデータへ保存する。配置スケジューラは前反復の人気度を次反復の需要の近似として使い、人気専門家の複製数を増やし、不人気専門家の複製数を減らす。学習済みの需要予測器を別途動かすのではなく、短期的な需要の時間的局所性を利用する。

専門家の複製枠の総数はGPU数と各GPUのスロット数で決まっているため、ある専門家を増やせば別の専門家を減らす必要がある。各専門家を少なくとも一つは保持し、ルーティングされたトークンを配置済みの複製へ分配する。人気度の変化に対して毎反復配置を更新できるため、固定容量でのトークン破棄を減らせる。ただし前反復の需要が次反復を完全に予測できるわけではなく、急激な分布変化では一時的な配置ずれが残る。

### 3. 既存の更新済み重み配布に再配置を組み込む

最適化器は各反復で更新済みの専門家重みをGPU上の専門家実体へ配布する。通常の静的方式でもこの通信は必要である。SYMIは更新後の重みを元のGPUへ一度戻してから別GPUへ移すのではなく、**次反復にその専門家を置くGPUへ直接送る**。したがって、配布される専門家実体の総数が一定なら、送る重みの総バイト数は静的配置と同じになる。

原論文の通信量解析では、ノード数N、GPU当たり専門家スロット数s、専門家重み容量W、勾配容量Gに対し、重み配布量は静的方式もSYMIも `sNW`、勾配通信量はどちらも `sNG` と整理される。これは通信量が増えないという主張であり、通信先の局所性やネットワーク競合まで完全に同じという意味ではない。実際の実装では後述する局所性を考慮した通信集合を追加している。

この仕組みにより、専門家の再配置は更新済み重み配布の宛先変更として実現できる。大きな最適化状態を動かさないため、頻繁な再配置でも別途数十GBの状態転送を発生させない。従来のFlexMoE型で頻繁に再配置すると再配置反復の遅延が2.46〜4.10倍になるのに対し、SYMIは毎反復の再配置でも同様のスパイクを避ける。

### 4. 局所性を考慮した勾配集約と送信先分散

同じ専門家を複数GPUへ複製すると、各実体が計算した勾配を一つの更新へまとめる必要がある。SYMIは専門家クラスごとの複製配置が反復ごとに変わるため、静的な全削減グループをそのまま使えない。そこで同一GPUや同一ノードにある複製を先に局所的に集約し、必要なノード間通信を抑える局所性重視の集約を導入する。

最適化状態の分割片へ勾配を届ける際には、同じ専門家の複製から送信元を選ぶ。ローカルに送れる場合はローカルを優先し、リモート転送は複製の間でラウンドロビンに分散する。これにより、人気専門家の勾配が一部のネットワーク経路や送信元へ集中することを防ぐ。更新済み重みの配布もバッチ化したポイント間通信で実装する。

理論上の総転送量が同じでも、通信パターンが悪ければ一部のノードがボトルネックになる。SYMIは動的配置の利点を実時間へ変えるため、全削減の局所性と勾配収集の送信先負荷分散を一体として設計している。これは「最適化状態を固定するだけで必ず高速化する」という単純化を避けるうえで重要である。

### 5. 一反復の処理順序

前向き計算でルータの専門家人気度を収集し、現在の複製配置にトークンを分配する。逆伝播では各専門家複製の勾配を同期する。最適化器ステップで勾配を静的な最適化状態の分割片へ集め、更新を計算する。同時に人気度メタデータから次反復の専門家複製数と配置を決め、更新済み重みを次の配置先へ配布する。この流れが毎反復繰り返される。

SYMIが変更するのは主として専門家の多層パーセプトロン部分の配置と通信であり、Transformerの注意層や正規化層の計算そのものは従来の分散学習基盤へ委ねる。したがって専門家の人気度が均一で静的配置でも十分な条件では、追加のスケジューラを使う利得は小さくなる可能性がある。

## 定量評価

### 1. 目標損失到達時間（原論文表3）

|方式|目標損失4.0までの時間（分）|DeepSpeed比の短縮率|
|---|---:|---:|
|DeepSpeed|147.84|基準|
|FlexMoE 100反復間隔|145.42|1.6%|
|FlexMoE 50反復間隔|141.60|4.2%|
|FlexMoE 10反復間隔|138.61|6.2%|
|SYMI 毎反復|102.68|30.5%|

SYMIはFlexMoE-10の138.61分に対して約25.9%短い。FlexMoE-100の145.42分と比べると約29.4%短い。これらは一反復当たりの速度差ではなく、**目標損失へ達するまでの総時間**である。必要反復数と反復遅延の双方が寄与するため、処理率だけの比較へ置き換えてはいけない。

### 2. 収束に必要な反復数とトークン生存率

GPT-Smallで損失4.0へ到達するまでの反復数は、DeepSpeed比28.5%減少する。FlexMoE-100、FlexMoE-50に対しても必要反復数はそれぞれ15.6%、12.1%少ない。FlexMoE-10は同程度の反復数で到達するが、頻繁な状態移送のため一反復が遅い。したがって、SYMIの優位は人気専門家へ必要な複製をすばやく増やしてトークン破棄を減らすことと、配置変更の転送を抑えることの組合せにある。

学習全体で破棄されたトークン数は、DeepSpeed比69%、FlexMoE-100比64%、FlexMoE-50比62%、FlexMoE-10比43%少ない。専門家の複製数を前反復の人気度に合わせるだけでも、均一固定配置や低頻度再配置より多くのトークンを学習へ利用できる。これは最終タスク正解率の直接測定ではなく、損失収束とトークン生存率に基づく品質・効率の評価である。

### 3. 反復遅延と通信オーバーヘッド

平均反復遅延はDeepSpeed比でSmall 2.8%、Medium 3.2%、Large 9.3%短縮する。追加の人気度全削減、配置スケジューラ、メタデータ更新が占める時間は、各モデルで1.06%、0.82%、0.70%に留まる。一方FlexMoEの再配置反復は2.46〜4.10倍の遅延スパイクを示す。FlexMoE-10はSYMIとほぼ同じ収束反復数を得ても、平均反復遅延が約35%高く、総学習時間で劣る。

さらにFlexMoEはGPT-Largeで最適化状態の移送時に旧状態と新状態を一時的に同時保持する必要があり、メモリ不足で終了する。SYMIは最適化状態を固定しているため、この種類の一時的な容量増加を避ける。これは大きな専門家を頻繁に動かすときのピークメモリ問題を示す負の結果である。

### 4. 理論上の通信量と実際の費用の違い

論文は専門家の重みW、勾配G、総スロット数sNに対して、静的方式もSYMIも各反復の重み配布が `sNW`、勾配転送が `sNG` になると示す。代表的な大規模構成の解析では最適化状態の総量は層当たり約1.7TB、通信量は各反復で約27TBと見積もる。これは実機でその規模を動かした測定値ではなく、通信量が配置方式に依存せず一定になることを示すモデル計算である。

局所性の差まで含む通信時間モデルでは、SYMIは静的配置よりわずかに追加のネットワーク費が生じ得る。したがって「ゼロオーバーヘッド」は主として**再配置のための追加データ移送が不要**という意味であり、CPU上のスケジューラ処理や全削減の実行時間が厳密にゼロという意味ではない。実機では通信集合の局所性改善が総反復遅延を小さくしている。

## 既存研究との差

DeepSpeedの静的な専門家配置は最適化状態の分割やオフロードを行えても、人気度の急変に合わせた複製の再割当は行わない。FlexMoE型の適応配置は専門家重みと最適化状態を一緒に動かすため、再配置頻度を上げると巨大な状態転送が支配的になる。SYMIは最適化状態を全ノードへ静的に分け、更新済み重みの既存配布先を変更することで、毎反復の適応配置を可能にする。

トークン破棄を抑えるための補助負荷均衡損失は、専門家の自然な分化を抑える可能性がある。SYMIは専門家人気度の偏りを許容したまま複製数を変えるため、ルーティング分布を無理に均一化しなくても処理能力を割り当てられる。ただしルータ自体の品質や学習安定性の問題をすべて解くわけではない。

## 限界・負の結果

実機は16枚A100、最大760MのGPT系MoEであり、数百億〜数千億パラメータ級の大規模MoEで同じ収束時間短縮率が得られるとは確認されていない。最終的な言語生成能力や下流課題の正解率よりも、目標学習損失までの時間と破棄トークン数を主要指標とする。損失の収束が速いことと、同じ訓練予算での最終タスク品質が必ず高いことは区別する。

最適化状態をCPUホストメモリへ分割する実装は、GPU-CPU間のPCIe帯域とホストメモリ容量に依存する。ネットワーク構成が異なるクラスタでは、重み・勾配の送受信の局所性と費用が変わる。論文の通信量解析は静的方式との総転送量の等価性を示すが、すべてのネットワークで同じ遅延になるという証明ではない。

前反復の人気度を次反復の予測として使うため、ルーティングが急変した瞬間は配置が追随しきれない。全専門家が同じ人気度のときは動的複製の利得が小さくなる。FlexMoEの比較は著者らによる再実装であり、公開された独立実装の完全な比較ではない。また推論サービング時の専門家オフロードやKVキャッシュ管理を直接高速化する技術ではなく、**学習時の最適化状態と専門家複製の配置問題**を扱う。

再監査では、最適化状態の静的分割、毎反復の複製配置、勾配同期と更新済み重み配布の通信、DeepSpeedとFlexMoEの実験条件、損失収束・トークン破棄・反復遅延の違いを一次論文で確認した。目標損失到達時間30.5%短縮と一反復の速度改善2.8〜9.3%を混同せず、大規模解析と実機測定を区別して記述した。
