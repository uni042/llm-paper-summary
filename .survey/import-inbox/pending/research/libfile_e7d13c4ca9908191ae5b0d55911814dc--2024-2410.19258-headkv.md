# Not All Heads Matter: A Head-Level KV Cache Compression Method with Integrated Retrieval and Reasoning

## 書誌情報
- 正規識別子: `arXiv:2410.19258`
- 著者: Yu Fu, Zefan Cai, Abedelkadir Asi, Wayne Xiong, Yue Dong, Wen Xiao
- 公開日: 2024-10-25
- 一次資料: https://arxiv.org/abs/2410.19258

## 概要
長文脈推論では鍵・値キャッシュ（KV cache）が系列長に比例して増えるため、tokenを選別して古いKVを捨てる圧縮法が使われる。従来法の多くは層ごとに予算を変えても、同じ層内の注意ヘッドへほぼ同じKV予算を与える。しかし注意ヘッドは検索、局所追跡、推論など役割が異なり、長文QAに必要な能力への寄与も均一ではない。HeadKVはこの不均一性を直接利用し、KV予算をヘッド単位で割り当てる。

拡張版HeadKV-R2は、単純なNeedle-in-a-Haystack型検索だけで重要度を測らず、取得した情報を使って推論するReasoning-in-a-Haystack型課題を加える。これにより「文字列を見つけられるヘッド」と「見つけた情報を回答へ結び付けるヘッド」の双方を保護する。Llama-3-8B-InstructとMistral-7B-Instruct、LongBenchとLooGLE等で評価し、KVサイズ64/128の厳しい予算で既存法を大きく上回る。文脈QAでは元KVの約1.5%だけを残して完全KV性能の97%を維持する。

## 問題設定
token重要度だけで圧縮すると、各ヘッドが同じ役割を持つという暗黙の仮定が残る。あるヘッドは遠距離の事実取得に強く、別のヘッドは局所文脈や推論に寄与するため、全ヘッドへ同数tokenを残すと重要ヘッドには不足し、重要度の低いヘッドには過剰な枠を与える。総KV予算が十分大きいと差は隠れるが、64〜128 token/head級の低予算では配分誤差が品質へ直結する。

また検索能力だけで重要ヘッドを決めると、長文中から証拠を拾えても、その証拠を組み合わせて回答する能力を守れない。HeadKV-R2はこの点を評価用課題自体から修正し、検索と推論を統合したヘッド重要度を作る。

## 手法
### ヘッド単位の重要度推定
HeadKVは各注意ヘッドについて長文脈課題での挙動を測り、ヘッド重要度を得る。重要度は「そのヘッドへKV容量を与える価値」を表し、層全体の平均ではなくヘッドごとに保持される。入力は評価用長文脈と各ヘッドの注意挙動、出力はヘッド別スコアである。

この粒度変更により、同じ層の中でも重要なヘッドへ多く、寄与の小さいヘッドへ少ないKV枠を与えられる。総KV数を増やさず配分だけを変えるため、改善源はメモリ追加ではなく予算の再配置である。

### Reasoning-in-a-HaystackによるHeadKV-R2
通常のNeedle-in-a-Haystackは埋め込まれた事実を回収できるかを測るが、文脈QAでは回収後の推論も必要になる。HeadKV-R2は検索と推論を同時に要求する評価例を構成し、そこでの挙動からヘッド重要度を推定する。単純なretrieval scoreだけでヘッドを選ぶより、回答生成に必要な推論ヘッドを保護する狙いがある。

このスコアは実要求ごとに毎回重い探索を行うのではなく、ヘッドの能力プロファイルとして予算配分に使われる。そのため実行時には、既に得られたヘッド別重要度を用いてキャッシュ容量を割り当てられる一方、タスク分布がプロファイル時と大きく異なる場合は重要度順位が最適でない可能性が残る。

### ヘッド別KV予算配分とtoken保持
総KV予算をヘッド重要度に応じて分割し、重要ヘッドほど多くのtokenを保持する。各ヘッド内部ではattentionに基づくtoken選択を使い、割り当てられた容量内で情報を残す。したがってHeadKVは「どのtokenを残すか」だけでなく「どのヘッドに何token分の権利を与えるか」を上位問題として追加する。

この二段階構造により、低予算で重要ヘッドが早期に情報を失うことを防ぐ。逆に総予算が大きい場合は各ヘッドが十分なKVを持てるため、ヘッド間再配分の限界利得は小さくなる。

## 評価条件
| 項目 | 条件 |
|---|---|
| モデル | Llama-3-8B-Instruct、Mistral-7B-Instruct等 |
| データ | LongBench、LooGLE、長文脈能力テスト |
| 比較 | SnapKV、PyramidKV、Ada-SnapKV等 |
| 厳しい予算 | KV size 64 / 128 |
| 主指標 | 文脈QA等のタスクscore、完全KVに対する性能維持率 |

## 主要結果
| 条件 | 比較対象 | 結果 | 読み取れること |
|---|---|---:|---|
| 文脈QA、約1.5% KV保持 | 完全KV | 性能の97%を維持 | 極端な容量削減でも重要ヘッド保護が効く |
| Llama-3-8B-Instruct、KV=128 | Ada-SnapKV / SnapKV / PyramidKV | HeadKV-R2平均32.00、各28.52 / 26.43 / 26.20 | 低予算ほどヘッド別配分差が顕在化 |
| LongBench / LooGLE | 強い層・token圧縮baseline | HeadKV系が一貫して優位 | 特定datasetだけの効果ではない |
| 一部Llama-3設定 | 完全KV | 圧縮版が僅かに上回る例 | 不要情報除去が雑音低減として働く可能性 |

## 既存研究との差
SnapKVは観測windowのattentionから重要tokenを選び、PyramidKVは層間でKV予算を変える。Ada-SnapKVも適応配分を行うが、HeadKVの中心はさらに細かい「注意ヘッド」を資源配分単位にする点である。HeadKV-R2はヘッド重要度の測り方にも変更を加え、単純検索ではなく検索後の文脈推論を評価へ入れる。

## 限界
ヘッド重要度は評価用長文脈課題から得るため、実運用タスクが大きく異なると順位がずれる可能性がある。ヘッド別の可変容量管理は層単位の均一配置よりメタデータと実装複雑性を増やし、複数GPUでは同期・ページ配置が追加課題になる。論文の主結果は品質維持に重点があり、メモリ削減率と同じ倍率の端から端復号高速化を保証するものではない。特に大きなKV予算では各ヘッドが十分な履歴を持つため、HeadKVの相対利得は低予算時ほど大きくない。
