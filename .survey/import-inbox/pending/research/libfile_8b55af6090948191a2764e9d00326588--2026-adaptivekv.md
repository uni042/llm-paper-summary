# AdaptiveKV: Accelerating KV Cache Offloading with a Bandwidth-Adaptive Memory Allocation Mechanism

## 概要
長文脈・大batchのLLM推論ではKVキャッシュがGPU HBMを圧迫するため、古いKVをCPU側memoryへ退避する方式が使われる。しかし複数GPUが同時にhost DDRを読むと帯域が競合し、KVをHBMから追い出せてもdecodeがhost bandwidth待ちになる。Compute Express Link（CXL）memoryを追加すれば容量と帯域を増やせるが、CXLは常にDDRより速いわけではなく、device特性、read/write比、GPU負荷、NUMA配置で実効帯域が変わる。

AdaptiveKVは「DDR優先」「CXL優先」の固定方針ではなく、現在のoffload規模と各memory tierの帯域からKV pageの配分率を実行時に選ぶ。GPU memory conch modelで複数tierを同時利用したときの帯域形状を表し、軽量predictorが最適な割合を推定し、dynamic interleavingがNUMA nodeへpageを実際に配置する。既存のstate-of-the-art memory strategy比で推論throughputを最大1.90倍にし、CXL-to-DDR bandwidth ratioが8%を超えると少なくとも5%の高速化が得られる境界をFPGA emulatorで示す。

## 問題設定
KV offloadでは容量だけでなく「次のattentionまでに必要KVをどれだけ速く読めるか」が重要になる。host DDRへ一括配置すると複数GPUが同じmemory controllerを競合し、CXLへ一括配置するとCXL linkやdevice側帯域が律速になる。OSの一般的なinterleaveはページ数を均等化しても、各tierの実効帯域比が等しいとは限らない。

さらにGPUからのmemory accessはCPU benchmarkと異なるtrafficを作るため、CPU側の静的NUMA policyだけでは最適配分を予測しにくい。AdaptiveKVはGPU workloadでCXL-HBM/DDR経路をprofilingし、KV offload専用の帯域指向allocationとして扱う。

## 手法

### GPU memory conch model
profilingでは、DDRとCXLへ割り当てるpage比率を変えると総帯域が単調に片方へ寄るのではなく、複数経路を並行利用することで最大値を持つ「conch」形状が現れる。この形をGPU数、KV規模、memory特性ごとにモデル化し、単純な容量比ではなく帯域最大点をallocation targetにする。

このモデルにより、CXLがDDRより単体帯域で劣る場合でも、一部trafficをCXLへ逃がしてDDR controller競合を減らせば総帯域が上がる条件を捉える。

### 実行時配分率予測
全配分率を毎request総当たりするとprofiling overheadが大きいため、runtime predictorが現在のoffload条件から最適なDDR/CXL allocation ratioを推定する。入力条件が変わればratioも更新し、multi-GPU負荷やKV量の変動へ追従する。

予測値はpage placementの目標比率となり、単に「CXLを追加memoryとして使う」だけでなく、利用する帯域を能動的に調整する点が特徴である。

### 動的NUMA interleaving
予測した割合を実際のmemory pageへ反映するため、available NUMA node間でKV pageを動的interleaveする。各nodeへ均等round-robinするのではなく、予測された帯域比に応じた重み付き配置を行うことで、複数memory controllerとCXL pathを並行に使う。

KV内容やattention計算は変更しないため、品質を近似で交換する方式ではない。追加費用はprofiling、predictor、page placement管理であり、速度利得はmemory bandwidthがdecode律速になっている条件で大きい。

## 評価条件
|項目|条件|
|---|---|
|対象|LLM KV cache host offloading|
|memory|host DDR + CXL memory pool|
|負荷|GPU/multi-GPU inference、複数offload規模|
|追加評価|性能可変FPGA CXL memory emulator|
|比較|固定/既存memory allocation strategy|
|指標|実効memory bandwidth、LLM inference throughput|

## 主要結果
|条件|結果|意味|
|---|---:|---|
|既存state-of-the-art strategy比|最大1.90倍throughput|tier間帯域配分の最適化が実推論へ反映|
|CXL/DDR bandwidth ratio > 8%|少なくとも5%推論高速化|低速CXLでも一定帯域以上ならDDR競合分散に価値がある|
|multi-tier同時利用|固定一方配置より高い総帯域|capacityではなくaggregate bandwidthを最適化すべきことを支持|

FPGA emulatorでCXL性能を変えた実験は、特定deviceだけの結果ではなく「どの程度のCXLなら導入価値が出るか」を境界として示す役割を持つ。8%という値は論文の評価構成での境界であり、すべてのplatformに普遍的な閾値ではない。

## 既存研究との差
従来のKV offloadはGPU/CPU間の転送量、prefetch、evictionを主に最適化する。CXL tiering研究もcapacity expansionを重視することが多い。AdaptiveKVはGPUがhost memoryを読む際の実効bandwidth曲線を直接測り、DDRとCXLのページ配分率をruntimeで変える点が中心である。KVを圧縮・削除するのではなく、同じKVをどのmemory controllerへ置くかで帯域を稼ぐ。

## 限界
CXL deviceとNUMA topologyごとに帯域特性が異なるため、profiling/model calibrationが必要になる。GPU HBM内にKVが収まりhost offloadが律速でない条件では利得は小さい。8%境界や最大1.90倍は評価hardware・GPU数・KV規模に依存し、CXL世代やDDR構成が変われば再測定が必要である。
