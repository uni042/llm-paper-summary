# A Survey on Large Language Model Acceleration based on KV Cache Management

## 概要
自己回帰LLMは各token生成時に過去tokenの鍵・値を再計算しないようKVキャッシュへ保持する。しかし文脈が長く、batchや同時利用者が増えるほどKV容量が増え、GPU HBMを圧迫する。キャッシュを減らせば容量は空くが、注意品質の低下、検索・量子化の追加計算、CPU/SSD転送、再計算など別の費用が発生する。

本サーベイはこの設計空間を**token-level、model-level、system-level**の3階層に整理する。token層は既存アーキテクチャを大きく変えず、どのKVを残すか・何bitで持つかを制御する。model層は注意構造や状態表現自体を変えてKV生成・再利用を減らす。system層はメモリ割当、prefix共有、スケジューリング、GPU/CPU/SSD階層を使って、同じKVをより効率的に保持・移動する。

## 問題設定
KVキャッシュは再計算を避ける代わりに、系列長とbatchにほぼ比例してメモリを消費する。長文脈では重みよりKVが配備可能な同時要求数を制約することもあり、HBM不足はeviction、offload、recomputationを誘発する。

さらに最適な対策は一つではない。重要tokenだけ残す方法は注意分布の予測が必要で、量子化は精度との交換条件を持つ。CPU/SSDへoffloadすれば容量は増えるがPCIe/I/O遅延が増える。サーベイはこれらを同じ「KVの生成・保持・選択・移動」という軸で比較する。

## 分類体系
### Token-level
選択、予算配分、統合、量子化、低ランク分解の5系統を整理する。選択はstaticとdynamicに分かれ、dynamic方式ではdecode中も重要度を更新する。非選択tokenは破棄するだけでなくCPU等へoffloadする場合があるため、検索処理のオーバーヘッドを隠す非同期化やblock単位検索も重要になる。

### Model-level
注意機構そのものを変更し、KV head数、共有方法、再帰状態等を変える。これはtoken選択より構造的にKV生成量を減らせる一方、既存checkpointへ後付けしにくい方式や、学習・品質との結合が強い方式を含む。

### System-level
メモリ管理、スケジューリング、hardware-aware設計の3方向を扱う。PagedAttention/vLLMのような仮想メモリ型割当、ChunkAttentionやMemServeのようなprefix共有、preemptionやcache-aware scheduling、さらに単一/複数GPU、異種計算、I/O・SSDを含む階層メモリを同じ層で整理する。

## 比較観点
| 階層 | 代表操作 | 主な利得 | 主な追加費用 |
|---|---|---|---|
| token | selection / budget | KV容量・attention計算削減 | 重要度推定・検索 |
| token | quantization / low-rank | bytes/KV削減 | 量子化誤差・復号計算 |
| model | attention構造変更 | KV生成量そのものを削減 | checkpoint互換性・再学習 |
| system | paging / prefix sharing | 断片化削減・重複排除 | metadata管理 |
| system | offload / hierarchy | 実効キャッシュ容量増加 | PCIe/SSD I/O |
| system | scheduling | reuse率・公平性・throughput改善 | queue制御・preemption |

## 主要な知見
KV管理は単一層で閉じない。たとえばtoken-levelのsparse selectionでGPU常駐量を減らしつつ、system-levelで重要度の低いKVをCPUへ退避するALISAのような組合せがある。したがって「圧縮率」だけでなく、検索時間、I/O、再計算、モデル品質を含むend-to-end評価が必要になる。

またsystem-levelでは、OS由来の仮想メモリ抽象、prefix-awareな重複排除、layer-awareな資源配分が別系統として発展している。サーベイはhardware-aware設計まで含めることで、KV最適化をattentionアルゴリズムだけでなくserving基盤の問題として位置付ける。

## 既存研究との差
一般的なLLM高速化サーベイよりKVキャッシュへ焦点を絞り、textとmultimodalの両方を対象に、token/model/systemの3階層を一つのtaxonomyで比較する。特にsystem層でmemory management、scheduling、GPU/CPU/SSDを含むhardware設計を明示的に扱う点が、モデル圧縮中心の整理と異なる。

## 限界
各方式は異なるモデル・文脈長・品質指標・hardwareで評価されており、表のカテゴリがそのまま統一benchmarkの順位を意味しない。論文自身も、3階層を横断した組合せ評価とproduction環境でのcase studyが不足していることを将来課題に挙げる。新しいKV方式の更新速度も速く、taxonomyは改訂時点のsnapshotである。
