# Large Language Model Inference Acceleration Based on Hybrid Model Branch Prediction

> 投機的サンプリングの検証待ちを、分岐予測で受理トークン数を先読みして小モデルの次ラウンド生成と大モデルの検証を重ねることで隠し、無損失のまま投機的サンプリングを上回る速度を出す方式。

## 概要

大規模言語モデルの生成は1トークンずつ進むため、モデルが大きいほど1回の順伝播の費用がそのまま生成速度の上限になる。投機的サンプリング（speculative sampling）は、小さく速いドラフトモデルに複数トークンの下書きを作らせ、対象モデルが1回の順伝播でまとめて検証し、確率比に基づく受理規則で通った分だけを採用することで、出力分布を対象モデルと一致させたまま生成を速くする無損失の手法である。しかし通常の投機的サンプリングでは、小モデルの下書き生成と大モデルの検証が直列に実行される。検証が終わるまで小モデルは次の下書きを作れず、大モデルの検証時間がそのまま全体の待ち時間として残る。

本論文は、プロセッサが条件分岐の結果を予測して投機的に実行を進める分岐予測の発想を、この直列構造へ持ち込む。受理される下書きの個数を予測関数で先に予測し、その予測位置から小モデルに次のラウンドの下書き生成を直ちに開始させる。大モデルの検証はそれと並行して走るため、予測が当たれば検証時間は次の生成の裏に隠れる。予測が外れた場合は検証で確定した位置へ戻って再開するだけで、その場合の所要時間は通常の投機的サンプリングと等しくなる。つまり分岐予測の導入は、最悪でも従来方式と同等、予測が当たる分だけ得をする構造になっている。

予測関数は、受理が独立同分布であるという投機的サンプリング側の仮定から導かれる幾何分布型の理論分布を土台に、実測の頻度分布に合うよう2つの補正項を加えて作る。モデル組ごとに事前に統計を取って決める静的な関数であり、推論中の学習は行わない。

**代表結果:** Llamaアーキテクチャの小規模モデル組での実測では、テキスト生成で1500万パラメータのドラフトと1億1000万パラメータの対象モデルの組で毎秒15.73トークンを記録し、対象モデル単体の毎秒6.13トークンの2.6倍、投機的サンプリングの毎秒12.21トークンを上回った。翻訳課題の4200万と1億1000万の組では対象モデル単体の3.4倍である。要旨で示される範囲は対象モデル比1.2倍から3.4倍で、全てのモデル組と課題で投機的サンプリングを上回っている。

## 問題設定

自己回帰生成では、1トークンを出すたびに対象モデルの全パラメータを通す順伝播が必要であり、生成速度はほぼモデル規模に反比例する。モデルを小さくすれば速くなるが品質が落ち、再学習を伴う圧縮や蒸留は費用が大きい。投機的サンプリングはこの交換を避ける方法で、小モデルが安く作った下書きを大モデルが並列検証するため、検証1回で複数トークンを確定できる。受理規則が対象モデルの分布を保存するように設計されているため、出力の統計的な性質は対象モデル単体と変わらない。

残る非効率は実行の重なり方にある。1ラウンドは「小モデルが下書きを作る時間」と「大モデルが検証する時間」の和であり、どちらか一方の計算資源は常に遊んでいる。特に大モデルの検証は下書き長にほぼ依らず1回の順伝播で済む一方、その間小モデルは何も生まない。検証結果が分かるまで次ラウンドの開始位置が決まらないことが直列化の原因であり、開始位置さえ先に分かれば小モデルは検証と並行して走れる。本論文の着眼点はまさにここで、受理個数はランダムではあるが分布に偏りがあるため、開始位置を予測する価値がある、という点にある。

## 手法のあらまし

生成は複数トークン単位のラウンドを繰り返す。各ラウンドは4段階からなる。第1に、小さい近似モデルが現在の接頭辞から下書きトークンをn個生成する。第2に、予測関数がこのラウンドで受理される下書きの個数γを予測し、先頭γ個が受理されたものとして、γ+1番目を次ラウンドの開始位置に定め、小モデルは直ちに次ラウンドの下書き生成を始める。第3に、それと並行して大きい対象モデルが今ラウンドの下書き全体を検証し、投機的サンプリングの受理規則で実際に受理される個数δを確定する。第4に、予測結果を検査し、成功ならそのまま続行し、失敗なら検証で確定した位置へ巻き戻して生成をやり直す。予測関数は推論開始前に、対象モデルと近似モデルとラウンドあたり生成数nから決まる受理個数の確率密度として用意され、γはそこからのサンプリングで得る。

## 手法

### 1. 分岐予測によるラウンドの重ね合わせ — 検証を待たずに次を始める

この機構が観測するのは、前ラウンドで小モデルが作った下書きと、予測関数が示す受理個数の分布である。保持する状態は現在の接頭辞と、予測で仮置きした次ラウンドの開始位置である。処理は、受理個数γを予測し、その位置から小モデルの次ラウンド生成を開始する一方で、対象モデルの検証を並行に走らせることである。これにより減るボトルネックは、検証完了まで小モデルが待つ直列の待ち時間である。予測成功時には検証時間が次ラウンドの生成時間の裏に完全に隠れる。

予測の成否は検査関数で判定する。対象モデルの1回の推論時間をT、小モデルの1回の推論時間をtとすると、検査値は「T引く（δ引くγ）掛けるt」であり、これが正なら予測成功である。直感的には、予測位置と実際の受理位置のずれが小モデルの生成時間換算で検証時間の範囲内に収まれば、並行化の利益が残るという条件である。失敗した場合は最後に確定した生成位置へ戻って再開し、そのラウンドの所要時間は分岐予測なしの投機的サンプリングと同じになる。追加で消費する資源は、予測が外れたラウンドで投機的に進めた小モデルの生成のやり直し分であり、大モデルの計算は増えない。受理規則自体は変更しないため、予測の当たり外れは速度だけに影響し、出力の分布は常に対象モデルと一致する無損失型である。

### 2. 予測関数 — 二項分布の理論形に実測補正を加える

予測関数は受理個数の確率密度であり、その形の良し悪しが予測成功率と高速化の大きさを決める。土台は投機的サンプリングの独立同分布の仮定である。各位置で近似モデルの出力が対象モデルと一致する確率をαとすると、先頭からk個連続で受理される確率はαのk乗に（1引くα）を掛けた幾何分布型になり、単調減少する凸型の分布になる。ただしn個全てが受理される位置では、それ以上の確率質量が集まるため分布の末尾が跳ね上がる。

著者らはこの理論形が実測と合うかを、1500万パラメータの近似モデルと4200万パラメータの対象モデルで500回のテキスト生成実験を行い、連続受理回数の頻度を数えて確かめた。実測分布も単調減少の凸型で末尾に跳ね上がりがあり、理論形と特徴が一致した。その上で、独立同分布は現実の単純化であるとして、理論分布へ2つの補正項（係数aとc）を加えたものを最終的な予測関数とした。n未満の位置では「a掛けるpのx乗掛ける（1引くp）足すc」という形を取り、xがnの位置に残りの確率質量を全て集める。パラメータはモデル組とnに応じて事前に決める。

この設計の効く理由は、予測が「最も起こりやすい受理個数」に寄ることで、検査関数の許容範囲内に収まる確率が高くなるためである。逆に、モデル組が変わればαも分布も変わるため、予測関数は組ごとに統計を取り直す必要があり、未知のモデル組への汎化は論文では示されていない。

### 3. 究極形としての網羅的実行 — 全ての開始位置を並行に走らせる

論文は分岐予測の極端な形として、全ての可能な開始位置について小モデルを並行に走らせる網羅的方式も検討している。予測関数で1つの開始位置を選ぶ代わりに、n通りの開始位置全てから生成を進め、大モデルの検証が終わった時点で正しい経路を選んで続ける。これにより検証時間は完全に隠れるが、開始位置の候補の数だけ小モデルを並行実行するため計算資源は最大でn倍近くまで増える。分岐予測方式が「1つの予測に賭けて資源を節約する」方式であるのに対し、網羅方式は「資源を払って確実に検証時間を消す」方式であり、両者は資源と時間の交換の両端に位置する。

## 評価

### まず見るところ

- **結論:** 分岐予測を入れた方式は、出力一致を保ったまま、全てのモデル組と課題で対象モデル単体と投機的サンプリングの両方を上回るスループットを示した。理論解析でも、分岐予測方式のスループットは投機的サンプリング以上であることが式の上で示されている。
- **速度・効率:** 指標は生成スループット（毎秒トークン数）である。対象モデル単体のスループットを毎秒1/Tトークン、投機的サンプリングをβ/(nt+T)（βはラウンドあたり平均受理数）と置く理論式と、実測値の両方が示される。
- **品質:** 受理規則は投機的サンプリングそのものであり、出力は対象モデルの分布と一致する無損失型である。品質劣化の測定ではなく、出力一致を前提に速度だけを比べる評価になっている。
- **評価の強さ／注意点:** 実験に使うモデルは最大でも1億1000万パラメータの自前学習Llama系モデルであり、実用規模のLLMや実サービング環境での検証ではない。ハードウェア条件の記載も乏しい。

テキスト生成（TinyStories）では、26万パラメータの近似モデルと1500万パラメータの対象モデルの組で、分岐予測方式が毎秒65.33トークン、投機的サンプリングが毎秒50.12トークン、対象モデル単体が毎秒45.59トークンだった。1500万と1億1000万の組では分岐予測方式が毎秒15.73トークンで、対象モデル単体の毎秒6.13トークンの2.6倍、投機的サンプリングの毎秒12.21トークンを約1.29倍上回る。翻訳（WMT 2018英仏）では、26万と1500万の組で毎秒59.53トークン（投機的サンプリング比で約31パーセント増、対象モデル比1.9倍）、4200万と1億1000万の組で毎秒13.42トークン（投機的サンプリングの毎秒10.01トークンの1.34倍、対象モデルの毎秒4.38トークンの3.4倍）だった。読み方として重要なのは、高速化倍率がモデル規模の比だけで決まらず、課題によって最良の近似モデルが異なる点である。対象モデルが1億1000万の場合、テキスト生成では1500万の近似モデルが最良の2.6倍を出し、翻訳では4200万の近似モデルが最良の3.4倍を出した。受理率と速度の釣り合いが課題依存であることを示している。

ラウンドあたり生成数nの除去実験では、nが小さいほど加速効果が大きい。nが8のとき毎秒15.73トークンで2.6倍、nが20では毎秒7.11トークンで1.2倍まで下がる。nを増やすと1ラウンドの下書きが長くなり、予測位置のずれが検査の許容範囲を超えやすくなるためである。ただしnには、1ラウンドの下書き時間が対象モデルの検証時間を上回るという下限条件（nはT/t以上）がある。網羅方式は毎秒20.01トークンと最速だったが、小モデルの計算資源は最大8倍に増えた。

## 既存研究との差

投機的サンプリングは「小モデルで下書き、大モデルで検証」という枠組み自体を作った研究であり、本論文はその枠組みの実行順序だけを変える。受理規則も分布一致の保証もそのままに、検証の完了を待ってから次ラウンドを始める直列実行を、予測に基づく投機的な重ね合わせへ置き換えた点が差分である。再学習を要する高速化（アーキテクチャ変更や蒸留）とは異なり、既存のモデル組へそのまま載せられることも位置づけとして明示されている。分岐予測というプロセッサ分野の概念を、受理個数の予測という形でデコードのスケジューリングへ移した点が本論文の独自性である。

## 限界・実装状況

限界は、評価モデルの規模が極めて小さいこと、実用規模のモデルや実ハードウェアでの並行実行の詳細が示されていないこと、予測関数がモデル組ごとの事前統計を要し未知の組への汎化が未検証なことである。実装状況は、著者らがLlama系モデルを自前で事前学習して実装・評価しており、公式コードの公開先は論文中に示されていない。近似を使う方式ではないため品質劣化のリスクはないが、予測が外れるラウンドでは小モデルの投機的生成が無駄になる資源効率のリスクがある。

## 一般的な実装上の含意

直列の「生成、検証」パイプラインでは、検証結果そのものではなく「次に始めるべき位置」を予測できれば、検証を待たずに後段を投機的に進められる。予測が外れた場合のコストが「通常方式へ戻るだけ」に設計できれば、予測の導入は下振れのない改善になる。受理個数のように分布に偏りのある量は予測対象として有望であり、予測関数は理論分布に実測補正を重ねる形が実務的である。一方で、下書き長を伸ばすほど予測のずれが大きくなるため、投機の深さと予測精度の釣り合いを測ることが欠かせない。
