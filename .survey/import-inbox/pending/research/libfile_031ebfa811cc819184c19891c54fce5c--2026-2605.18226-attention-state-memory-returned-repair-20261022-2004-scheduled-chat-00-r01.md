# Context Memorization for Efficient Long Context Generation

## 概要

長い固定接頭辞を複数の質問に再利用する際、従来の文脈内学習（ICL）は入力処理の接頭辞キャッシュを再利用できても、生成トークンが接頭辞へ注意する費用を払い続ける。接頭辞を学習でモデルの重みへ取り込む方法はこの注意費用を消せるが、接頭辞が更新されるたびに勾配計算が必要になる。Okoshiらの注意状態メモリ（Attention-State Memory、ASM）は、接頭辞に対する注意の**出力ベクトルと正規化和**を、代表的なクエリに対応する辞書へ事前計算し、推論時には検索と合成で代用する。長い接頭辞を生成のたびに再計算せず、重みも再学習しないことが狙いである。

LLaMA 3.1-8Bでの評価では、ManyICLBenchの五つの課題の平均で1K〜8K辞書エントリ時に同程度の記憶容量を使うICLを上回り、8K時の注意ブロック遅延は1.36倍短縮した。NBA規則の検索拡張生成（RAG）課題では、全20Kトークンの規則を入力する方式が24.1%の正答率に対し、4K辞書は25.5%であった。ただし1K辞書19.4%、16K辞書19.4%と、容量を増やせば必ず良くなるわけではない。検索が近似であるため、オンラインsoftmaxの**合成演算自体が厳密**でも、辞書から取り出した注意状態が元のクエリの厳密値と一致するとは限らない。

## 問題設定：固定接頭辞の再利用と注意の減衰

例えば規則集、タスクの例題、検索文書を多数の利用者が共有する場合、接頭辞は固定でも、質問に続く生成トークンのクエリは利用者ごと・層ごとに変わる。キー・値（KV）キャッシュを保存すれば入力処理を再実行せずに済むが、各生成段階ではそのKV全体を読んで注意を計算する。接頭辞長Lに比例する読み出しが残り、GPUメモリを占有する。しかも生成が進むと新しい生成トークンへ注意が分散し、長い接頭辞の影響が薄れる場合がある。

プロンプト圧縮やKV圧縮はLを短くして負担を減らすが、接頭辞への注意自体は残る。接頭辞ごとの微調整や低ランク適応は注意を除けても、更新時の計算や訓練用データを要する。ASMは、接頭辞に依存する注意の結果を重みでもトークン列でもない外部辞書として表すことで、再利用頻度が高い接頭辞の費用構造を変える。ただし新しい接頭辞を登録する際には事前の校正用クエリと前向き計算が必要であり、任意の接頭辞が無料で登録されるわけではない。

## 手法

### 1. 注意状態の十分性と合成可能性

あるクエリqに対して接頭辞のキー・値ブロックから計算した注意出力をa(q)、指数スコアの正規化和をZ(q)とする。二つの互いに重ならないブロックA、Bの注意状態を(aA,ZA)、(aB,ZB)とすると、結合後の注意出力は `(ZA*aA+ZB*aB)/(ZA+ZB)` で厳密に求められる。これはオンラインsoftmaxの恒等式であり、接頭辞のKVをもう一度読む必要がない。著者はこの組(a,Z)を「注意状態」と呼び、固定のクエリに対しては元のKVの代わりに十分な情報を含むと整理する。

ここで重要なのは、恒等式が**同じクエリについての状態同士**に成り立つ点である。実際の利用者のクエリは無数にあるため、すべてを事前保存することはできない。ASMは類似クエリの注意状態を代表値に圧縮して検索する。この代表化による誤差は恒等式では打ち消せず、後述の辞書構築と検索精度が品質の鍵になる。

### 2. 層別辞書の構築と注意を考慮した集約

オフライン校正では、固定接頭辞と応答トレースを連結して前向き計算し、各層の応答トークンからクエリベクトルqと接頭辞注意状態(a,Z)を収集する。これを層ごとにk-meansでK群へまとめ、各群に代表クエリ、代表注意出力、代表正規化和を保存する。クエリ代表は平均ベクトルである一方、注意出力代表は単純平均ではなく、各サンプルのZで重み付けした平均を使う。正規化和も群の要素数で割り、複数の状態を単純合算したときに注意のスケールが不当に増える問題を避ける。

この辞書は学習済みモデルの重みを更新しない。収集するのは前向き計算で得られる中間状態であり、必要なのは接頭辞と代表的な応答トレースである。ただし辞書品質はトレースの分布に依存する。校正時に現れない質問タイプや少数の代表点へ多様なクエリを押し込む設定では、検索した状態が本来の注意とずれる。

### 3. 長い接頭辞を分割して校正する

全接頭辞を一度に処理すると校正時のピークメモリが長さに比例する。合成可能性を使えば、例えば16Kトークンの接頭辞を4Kずつ四つに分割し、同じクエリに対する部分状態を独立に計算して合成できる。したがって長い接頭辞の校正時に、全長のKVを同時保持する必要を減らせる。これは推論時だけでなく、辞書を作る段階のメモリ上限にも効く。

ただし、各分割で校正クエリを用意し、後で状態を対応付ける必要がある。分割数が増えると前向き計算の総仕事量が必ず減るわけではない。評価では同じ16K接頭辞を4K×4へ分けた方式が単一16Kの精度へ近づくことを示しているが、構築時間のすべてをゼロにする仕組みではない。

### 4. 推論時の近傍検索と正規化合成

利用者の質問から各層でクエリを得ると、辞書の代表クエリとの余弦類似度で最も近いエントリを選ぶ。接頭辞は通常の自己注意から取り除き、現在の質問・生成トークンだけで求めた自己注意状態と、辞書から得た接頭辞注意状態をZに比例する係数で合成する。これにより、生成の各段階で接頭辞長Lに比例するKV走査を省く。検索を単純な全件走査で行えばKに比例するが、階層索引を用いることでKに対して緩やかに増える検索を目指す。

著者は回転位置埋め込み（RoPE）適用前のクエリと共通仮想位置でRoPEを適用したクエリを比較し、さらに共分散で白色化して高分散次元への類似度偏りを抑える。層とヘッドごとに検索表現を設計する必要があり、単なる文字列検索とは異なる。グループ化クエリ注意（GQA）ではKVヘッドを共有するクエリヘッドをまとめた表現を用い、辞書のエントリ数と検索精度を調整する。

## 評価条件

主対象はLLaMA 3.1-8Bの指示調整モデルで、文脈内学習にはManyICLBenchの五つの一般課題と二つの推論課題、検索拡張生成にはRuleArenaのNBA規則課題を使う。ICLの接頭辞は32K、NBA規則は約20Kトークン。辞書の大きさKは1K、2K、4K、8K、16Kを変え、同じ記憶容量で比較するためGQAの表現次元を調整した。比較は全接頭辞を注意へ残すICL、接頭辞なし、学習不要のKV圧縮方式KVzipである。辞書構築のクラスタ方式・検索キーの選択は検証集合で決めるため、事後的に一つの設定を全課題へ押し付けた比較ではない。

| 全規則を入力するICL | 20K | 24.1% |

## 評価結果：精度、構築費用、遅延を分ける

五つのManyICLBench課題では、同じエントリ数を割り当てたICLと比べ、ASMは1K〜8Kで平均精度が同等以上だった。少数のKVだけを残すKVzipではラベル情報のような重要部分が失われやすい一方、ASMの代表状態は接頭辞全体の注意出力をまとめるため、少数のエントリでも情報が残ると著者は説明する。ただしK=1Kでは代表が粗過ぎて改善が小さく、16Kでは校正トレースが不足する課題で性能が伸びない。例えば幾何形状の課題は訓練標本が150件しかなく、大きい辞書を安定して埋められない。

数学・科学の推論課題では、ASMが常にICLより良いわけではない。math_countingでは8K時にICL 26.0%、ASM 24.5%、gpqa_cotでは2K時にICL 28.3%、ASM 24.2%である。接頭辞を長くしてもICL自身の精度が安定して伸びない課題では、ASMの利得も限定的となる。NBA規則では4Kの25.5%が20K ICLの24.1%を上回るが、16Kでは19.4%へ低下する。したがって「20%の記憶量で全課題を上回る」とは言えず、課題別に辞書容量を調整する必要がある。

分割校正のbanking77評価では、4K接頭辞単独を5000反復した場合61.5%、16K一括を1250反復した場合79.0%、4K×4を合成して合計5000反復した場合78.5%だった。分割によって一回に処理する最大長を抑えつつ、16K全体の情報をほぼ保持した結果である。これはピークメモリを減らす実証であり、反復回数が増えたことからも、計算時間まで同時に減ると解釈してはならない。

遅延は512トークン生成時の注意ブロックの平均を測り、同じ記憶容量で比較した。全接頭辞への注意は容量とともにほぼ線形に増えるが、階層検索のASMは増加が緩やかで、約4Kから優位となり、8Kで1.36倍、16Kで1.8倍の高速化を報告する。**これは注意ブロック単位の遅延であり、モデル全体のエンドツーエンド処理量が同倍率で改善したという結果ではない。** 階層検索は小容量では追加費用が大きく、十分なKになって初めて利点が現れる。

## 既存方式との差と限界

従来のKV圧縮は保持トークン数を減らしても、そのトークンへの注意計算が必要である。接頭辞蒸留は接頭辞ごとに重みを更新する。ASMは注意出力と正規化和を外部辞書へ分離し、生成時の接頭辞KV読み出しをなくす点が異なる。オンラインsoftmaxの厳密合成と、クエリ近傍検索による近似を区別することが重要である。前者の数式が厳密だからといって、辞書全体の出力が元の全注意と必ず一致するわけではない。

辞書を作るには接頭辞を反映した校正トレースが必要であり、未知分布への頑健性、頻繁な接頭辞更新時の総費用、複数利用者・複数接頭辞の辞書管理は今後の課題である。性能はモデル・課題・Kの選択に依存し、特に推論課題では利得が不安定である。論文の中心評価は単一の8Bモデルと特定のICL/RAG課題であり、全モデルへの一般化やクラウドの総運用費用の削減を直接示していない。
