# When KV Meets Embeddings: Dynamic GPU Memory Allocation for Accelerating Generative Recommender Serving

> 生成レコメンダのGPU HBMを埋め込みキャッシュとKVキャッシュへ実行時に再配分する問題を定式化し、3層PPO制御器による配分決定、在駐状態を動かさない配分適用、両キャッシュの局所性を併せ見たルーティングを備えるRACERで、静的配分比の限界を実測とともに示した研究。

## 概要

生成レコメンダは、利用者の長い行動履歴をトランスフォーマで読み、次に提示するアイテムを予測するモデルである。代表例であるHSTUの推論は2つの段階からなる。第1に、数十から数百テラバイト規模の埋め込み表から各アイテムのベクトルを取り出す埋め込みルックアップで、表はCPU側メモリに分割配置されるため、取り出しはホストからデバイスへの転送を伴う。第2に、取り出した埋め込み列へ多層の自己アテンションを適用する計算で、過去の履歴分のアテンション状態をKVキャッシュとして保持すれば再計算を避けられる。どちらの段階もGPU上の永続的なキャッシュで速くなる。頻出埋め込みを保持する埋め込みホットキャッシュは転送を減らし、KVキャッシュは再計算を減らす。しかし両者は同じGPU HBMを分け合うため、一方を広げれば他方が狭まるゼロサムの関係にある。

従来のシステムはこの競合を片側ずつ最適化してきた。埋め込み側はプリフェッチやシャーディング、KV側は圧縮や共有やキャッシュ配慮ルーティングが研究されてきたが、いずれも相手側の容量を固定とみなす。本論文の実測では、系列長15kで埋め込み表25個の条件では埋め込みルックアップだけで総遅延の50パーセント超を占め、同時に最適な埋め込み配分比は条件によって約0.20から約0.55まで移動する。つまり最適点自体が時間とともに動くため、どの静的配分にも20〜30パーセントの改善余地が残る。かといって単純に再配分すると、増えた側のキャッシュを埋めるリフィル転送が、もともとバースト時に約10GB毎秒に達する埋め込みミス転送と同じ経路を奪い、P99遅延のサービス品質目標（30〜50ミリ秒）を破りかねない。

提案システムRACERは、配分の決定、配分の適用、リクエストの振り分けを1つの閉ループとして設計する。代表結果として、32ノードのA100クラスタ、埋め込み表5TB、系列長8K〜15Kの評価で、最良の静的配分（オフラインの全探索で選んだ比較対象）に対してP99遅延を24〜38パーセント削減し、30ミリ秒のサービス品質目標に対する満足率は定常負荷で99.6パーセント以上、バースト負荷でも93.5〜95.3パーセントを維持した。配分決定の遅延は32マイクロ秒で、オフライン最適比との差は評価条件を通じて0.024〜0.029に収まる。

## 問題設定

問題の資源はGPU HBMの容量そのものである。埋め込みキャッシュが不足するとミスが増え、ミス1回ごとにCPU側の分割表や他ノードからベクトルを転送するため、転送待ちがエンドツーエンド遅延へ直結する。逆にKVキャッシュが不足すると、再利用できたはずの履歴のアテンション状態が追い出され、長い系列に対する再計算が増える。系列長が伸びるほど両方の圧力は同時に強まる。論文のプロファイルでは、系列長20,480で埋め込みルックアップが総推論時間の40パーセント超を占め、埋め込み表の数が増えるとルックアップ費用はほぼ線形に増える。

さらに厄介なのは、最適配分が静的でない点である。ホットな利用者の割合、KVヒット率、埋め込みヒット率、平均系列長といった要因が配分決定の重要度の60パーセント超を占め、これらは5秒窓でも急変しうる。加えて配分とルーティングは結合している。埋め込み表はノードへ分割配置され、KV状態も利用者ごとに偏在するため、どのノードへリクエストを送るかが各ノードのヒット率を決め、ヒット率が次の最適配分を決める。埋め込みだけを見るルーティングはKV局所性を壊し、KVだけを見るルーティングは埋め込み転送を増やす。したがって解くべき問題は、ノードごとに配分比をオンラインで決め、その変更を稼働中の推論を乱さずに適用し、不均一になったノード条件の下でリクエストを振り分けることの3点セットである。

## 手法のあらまし

RACERはノード内制御とクラスタ全体のルーティングからなる。まず各ノードのSmartAllocatorが、直近のワークロードとキャッシュと遅延の信号から、HBMのうち埋め込みキャッシュへ割り当てる比率を5秒ごとに決める。決定は3層で行う。履歴トレースでオフライン学習して凍結したPPO方策が基本の増減量を出し、オンラインアダプタが実測とのずれを残差として補正し、バースト検出時だけ回復制御器が保守的な上書きを行う。次にメモリマネージャが新しい比率を適用する。在駐しているKVブロックは物理的に動かさず、ページ表の論理境界だけを更新し、新しく空いた容量へのリフィルは専用ストリームで帯域を絞りながら背景実行する。最後にグローバルルータが、各ノードのKV在駐、埋め込み局所性、負荷を採点してリクエストの送り先を決める。ルーティング結果は各ノードのキャッシュ状態を変え、それが次の配分決定の入力へ戻る。

## 手法

### 1. SmartAllocator — 遅延効果を見込む3層の配分制御器

SmartAllocatorが観測するのは7次元の状態である。ホット利用者の割合、KVヒット率、埋め込みヒット率、平均系列長、サービス品質目標の違反率、現在の配分比、正規化したP99遅延を直近窓から集め、すべて0から1へ正規化して入力する。保持する状態はこの窓統計に加え、P99遅延の指数移動平均とその標準偏差、直近の経験を入れる先入れ先出しのリプレイバッファ（容量1,000件）である。選択する対象は配分比の増減量で、行動は±0.06、±0.04、±0.02、0の7通りという小さな離散集合に限る。比率は0.1から0.9の範囲へ切り取られ、どちらのキャッシュも完全には枯渇しない。小刻みな増減にするのは、配分変更の効果がキャッシュのリフィルとエビクションを経て遅れて現れるためで、大きく動かすと過渡期の不均衡と遅延の跳ねを招くからである。報酬は、窓内リクエストのサービス品質目標の満足率から、P99が目標を超えた分への罰則を引いたもので、満足率だけでも尾部だけでもない形にしている。

3層に分ける理由は役割の違いである。基本のPPO方策は2層の多層パーセプトロン（64と128ユニット、パラメータ数25,000未満）で、オフライン学習後は凍結されるため、稼働中に方策が不安定化する心配がなく、決定は28〜32マイクロ秒で済む。オンラインアダプタは3層の小さな残差モデルで、P99の指数移動平均からの乖離が大きいほど学習率を上げる形で背景更新され、オフラインと実環境のずれを埋める。回復制御器は、P99が移動平均に標準偏差の3倍を加えた値を超えたときにバーストと判定し、通常経路を迂回して、ホット利用者割合が0.2を超えていればKV側へ寄せる保守的な上書きを行う。これにより減るボトルネックは、静的配分の取りこぼしと、反応の遅い制御器がバーストで取り残される尾部遅延である。追加費用は、アダプタ学習によるCPU使用率の上昇（ピークで20パーセントから46パーセント、平均32パーセント）であり、これは背景実行で推論経路には入らない。誤った配分を出した場合でも、増減幅が最大0.06に制限され5秒ごとに再判定されるため、被害は1窓分に閉じ、次窓で戻せる。

### 2. 非干渉な配分適用 — 論理境界の更新とリフィルの分離

配分比が決まっても、それを稼働中のノードへどう適用するかが第2の機構である。観測対象は両キャッシュのページ使用状況で、保持する状態は共有のページ式アドレス空間とその論理境界、KV側のフリーリストとLRU順序である。ここでの選択は、どの冷たいKVブロックを回収して埋め込み側へページを渡すか、逆にどの埋め込みエントリを追い出してKV側へ返すかである。核心は、在駐するKVブロックを物理的に移動しないという不変条件である。比率を上げる場合は、まず非アクティブで冷たいKVブロックをメタデータだけのLRUエビクションで回収し、そのページを埋め込み側へ再割当てする。処理中のKVブロックは固定され決して追い出されない。回収可能なページが足りなければ、埋め込み側の拡張は絞られるか次の周期へ先送りされる。境界変更そのものはページ表の更新だけで、1マイクロ秒未満で終わり、データコピーを伴わないためパイプラインの停止は生じない。

残る費用は、新しく確保した容量へ有用な埋め込みを流し込むリフィル転送である。80GB級GPUで4パーセントの比率変更は約3.2GBのホストからデバイスへの転送に相当し、これが埋め込みミスの転送と競合すると尾部遅延を押し上げる。そこでリフィルは優先度付きの専用CUDAストリームで非同期に発行し、埋め込みミス転送の需要に応じて背景帯域を絞る。制御された帯域では3.2GBのリフィルは約1秒で完了し、5秒の決定周期の中に収まるため、適用費用は時間的に償却される。減るボトルネックは再配分そのものが引き起こす遅延悪化であり、これがなければオンライン制御は理論上正しくても本番では使えない。失敗時の挙動も安全側で、リフィルが遅れても正しさには影響せず、ヒット率が一時的に下がるだけにとどまる。

### 3. EMB-KV配慮ルーティング — 両方のミス費用でノードを採点する

配分がノードごとに異なると、ノードはもはや互換ではなくなる。ルータが観測するのは、利用者ごとに前回送ったノード、各ノードにその利用者のKV状態があるか、各ノードが保持する埋め込みシャードと利用者の頻出シャード上位20件との重なり、ノードの負荷である。在駐情報は非同期に更新される軽量なメタデータで、KV在駐表はノードあたり24KB未満に収まる。採点は、KVヒット（0か1）、埋め込み被覆率、負荷の低さの重み付き和に、前回ノードへの小さな親和ボーナス0.05を加えたもので、重みはオフラインで測ったKVミス、埋め込みミス、待ち行列遅延の物理費用から正規化して決める。最も高いノードの負荷が閾値0.85を超えていれば、最も空いているノードへフォールバックする。

この機構が減らすボトルネックは、片側だけを見るルーティングの近視眼である。KVだけを見る方式は埋め込みヒット率を、埋め込みだけを見る方式はKVヒット率を犠牲にするが、合算スコアではRACERが0.47と、埋め込みのみの0.29、KVのみの0.38を上回る。アブレーションでは、配分制御だけでも固定配分比に対してP99が約20パーセント下がり、ルーティングを加えるとさらに10〜25パーセント下がる。追加費用はリクエストごとの全ノード採点と在駐表の維持で、埋め込み被覆の計算は上位20シャードとの積集合という小さな処理である。誤判定時の被害は1リクエストの送り先に限られ、在駐情報が古くてもミスが増えるだけで正しさは壊れない。

### 4. データと制御の流れ

1リクエストの流れは、ルータが両キャッシュの在駐と負荷でノードを選ぶ、選ばれたノードで埋め込みルックアップ（ミス時はローカルCPUシャードかRDMA経由の他ノードから取得）とHSTUのフォワード計算を行う、完了後に在駐と負荷の情報をルータへ非同期に返す、という順である。並行して各ノードでは5秒周期の制御ループが回り、状態観測、配分決定、境界更新、帯域制限つきリフィルが進む。ルーティングが作る局所性が次の配分の入力になる点が、この設計の閉ループ性である。

| 構成要素 | 入力・観測 | 具体的な動作 | 改善対象 | 主なトレードオフ |
|---|---|---|---|---|
| PPO基本方策 | 7次元の窓状態 | 配分比の増減量を7通りから選ぶ | 静的配分の取りこぼし | オフライン学習への依存 |
| オンラインアダプタ | 実測P99と報酬の履歴 | 基本方策へ残差補正を加える | 環境のずれへの追随 | 背景CPU使用率の上昇 |
| 回復制御器 | P99の移動平均と標準偏差 | バースト時にKV寄せへ上書きする | バースト時の尾部遅延 | 通常時は粗い制御になる |
| メモリマネージャ | 新しい配分比とページ状態 | 論理境界を更新しリフィルを帯域制限する | 再配分による干渉 | リフィル完了までヒット率が遅れる |
| ルータ | KV在駐、埋め込み被覆、負荷 | 費用ベースのスコアで送り先を選ぶ | 片側ルーティングの近視眼 | 在駐メタデータの維持 |

## 評価

### まず見るところ

- **結論:** 静的配分は、オフラインで最も有利に選んでも30ミリ秒のサービス品質目標を安定して満たせず、動的配分とルーティングの併用で初めて全条件で目標内に入った。
- **速度・効率:** 主指標はP99遅延とサービス品質目標の満足率である。スループットについては犠牲にしないとされ、弱スケーリングでは32ノード時点で静的比較対象を23〜36パーセント上回る。
- **品質:** 生成品質ではなく推薦サービングの遅延が対象であり、モデルの予測精度への影響は扱わない。
- **評価の強さ／注意点:** 実機32ノードの測定だが、到着トレースは本番ワークロードに基づく再生であり、モデルはHSTUの2構成に限られる。ハードウェア世代の一般化は費用比に基づく議論にとどまる。

P99の内訳を見ると、KVだけを最適化した方式は3層でも33〜38ミリ秒、6層では44〜51ミリ秒と、定常負荷の時点で目標を超えている。これは埋め込みアクセスが一次のボトルネックになる条件では、KV側の改善だけでは尾部を救えないことを示す。最も強い静的比較対象はプリフェッチと全探索で選んだ固定比を備えてもなお目標を満たしきれず、特にバーストでは満足率が56〜78パーセントまで落ちる。対してRACERの満足率はバーストでも93.5〜95.3パーセントで、データセット間のばらつきも1.8ポイント以内と小さい。静的方式のばらつきが12〜22ポイントあることと比べると、動的制御の価値は平均性能よりも、条件ごとの調整を不要にする安定性にあると読める。

制御器の比較も示唆的である。古典的なPIDは決定に約1.2秒、ベイズ最適化は約7秒、MILPは約36秒かかり、5秒周期の制御にはそもそも間に合わないものがある。予測型のLSTM系はミリ秒級だがバーストでの最適比との差が0.128〜0.201まで広がる。PPOのみでも差は0.042〜0.051まで縮むが、オンラインアダプタと回復制御器を加えた完全版は0.019〜0.031へさらに縮み、決定遅延は32マイクロ秒にとどまる。4時間窓の追跡では、学習済み方策の配分比とオフライン最適比の平均絶対誤差は0.023だった。ホット利用者割合が上がる場面では、方策は埋め込みヒット率を9パーセント犠牲にしてでもKVヒット率を25パーセント稼ぐ方向へ比率を下げており、KV側はワーキングセットを割ると急激に劣化し、埋め込み側は緩やかに劣化するという非対称性を捉えている。

感度の観点では、クラスタ規模とホットリクエスト割合を振ると、選ばれる配分比は埋め込み支配（2ノード、ホット割合0.05で比率1.0）からKV支配（32ノード、ホット割合0.60で比率約0.23）まで連続的に移る。ノードが増えると埋め込み表の分割が細かくなりノードあたりの埋め込みワーキングセットが縮むため、均衡はKV側へ寄る。この全域にわたる移動こそ、単一の静的比が原理的に不適である証拠である。悪化条件としては、バースト時にPPOのみの構成ではP99が約46ミリ秒まで跳ねることがアブレーションで示されており、回復制御器なしでは尾部を抑えきれない。完全版でもバースト時のピークは約31ミリ秒まで抑えるのが限界で、目標の30ミリ秒をわずかに超える瞬間があることには注意が要る。

## 既存研究との差

埋め込み側の先行研究は、シャーディング、圧縮、プリフェッチ、量子化でルックアップ自体を速くするが、埋め込みが唯一のメモリボトルネックである前提に立つ。KV側の先行研究は、利用者間のKV共有やKV圧縮で再利用率を上げるが、KVメモリを独立に扱う。生成レコメンダのスケジューリング研究（Mooncake、xGR、BATなど）はKV局所性と負荷を扱うものの、埋め込み配分は静的なままで、配分が動的になると埋め込み転送費用がノードごとに異なるため前提が崩れる。強化学習による資源配分の研究は、共置ジョブ間のGPUメモリ配分やクラスタレベルの複数資源配分が対象で、単一デバイス内の2キャッシュ競合を尾部遅延の制約下で扱ったものはなかった。本論文の差は、競合そのものを問題として定式化し、配分決定・配分適用・ルーティングを一体の閉ループとして設計した点にある。

## 限界・実装状況

- 評価はHSTUという単一の生成レコメンダアーキテクチャと、その3層・6層構成に限られる。他の推薦モデルや大規模言語モデルのサービングへの直接の一般化は示されていない。
- 到着パターンは本番ワークロードに基づく再生であり、実サービスへの導入実績は報告されていない。埋め込み表も5TBへ人工的に拡大したもので、元データセットの頻度分布は保たれているものの実表そのものではない。
- PPO方策は履歴トレースでのオフライン学習を前提とし、新規サービスへの移植時に学習データをどう用意するかは未評価である。
- ハードウェア一般化は、再計算費用と転送費用の比が世代間で大きく変わらないという議論に基づく推論であり、H100やH200での実測はない。
- 公式コードの公開先は論文中に示されていない。実装はオープンソースのHSTUフレームワーク上の研究実装である。

## 一般的な実装上の含意

複数種のキャッシュが同一の高速メモリを共有するシステムでは、各キャッシュの最適化を独立に行う前に、配分比そのものが時間変動するかどうかを実測すべきである。配分を動かす場合は、決定の速さよりも適用の無干渉性が実用上の鍵になる。在駐状態を動かさない論理境界の更新と、背景転送の帯域制限という分離は、KVキャッシュと他の状態が同居する大規模言語モデルのサービングでも応用できる考え方である。また、配分を不均一にした時点でルーティングの前提も変わるため、配分制御と配置制御は別々に設計せず、両方の局所性を費用として採点する形にそろえる必要がある。制御器の選択では、最適化の質だけでなく決定遅延と、効果が遅れて現れる系への適合を併せて見るべきである。
