# Scaling Transformer to 1M tokens and beyond with RMT

## 概要
標準自己注意は文脈長に対して二乗で計算・メモリが増えるため、百万token級の履歴を直接attentionへ入れることは高価である。本研究はRecurrent Memory Transformer（RMT）を事前学習済みTransformerへ適用し、入力を固定長segmentへ分割して、少数のmemory tokenだけを次segmentへ再帰的に渡す。

memory tokenは通常tokenと同じattentionへ参加するため、専用外部メモリ演算を追加せず、モデル自身が「何をmemoryへ書き、次segmentでどう読むか」を学ぶ。合成記憶課題では最大2M token級の系列から情報を回収でき、言語モデルでも処理segment数が増えるほどperplexityが改善する傾向を示した。

## 問題設定
長文脈Transformerで全token間attentionを保持すると計算量が二乗増加する。window attentionは計算を抑えるがwindow外情報を直接参照できない。RMTは過去全tokenではなく圧縮されたmemory stateだけを次segmentへ伝えることで、segment数に対して線形な計算増加へ変える。

## 手法
入力segmentの先頭・末尾へmemory tokenを配置する。現在segmentの先頭memoryには前segment末尾memoryのhidden stateを入力し、通常のTransformer layer群で本文tokenと共同処理する。末尾で更新されたmemory hidden stateを次segmentへ渡す。この再帰を繰り返すため、モデル本体のattention長はsegment長とmemory token数に制限される。

学習時には複数segmentをunrollし、後段lossからmemory経路へ勾配を流す。これによりmemory tokenは単なる固定summaryではなく、将来必要になる情報を保持する内部状態として学習される。長距離情報が固定個数のmemory vectorへ圧縮されるため、計算量削減と情報ボトルネックが表裏一体になる。

|観点|条件|
|---|---|
|方式|事前学習済みTransformer + recurrent memory token|

## 主要結果
|評価|結果|意味|
|---|---|---|
|長距離記憶|最大2M token級でも高いretrieval accuracyを報告|固定attention窓を越えてmemory stateが情報を運搬できる|
|言語モデル|処理segment数増加に伴いperplexity改善|追加の過去segment情報を実際に利用している|
|計算量|入力全長に対する二乗attentionを回避|百万token級へ伸ばす際の計算増加を抑制|

## 既存研究との差
Transformer-XL等もsegment間状態を再利用するが、RMTは専用memory tokenをモデル自身に読み書きさせ、既存Transformer構造への変更を小さく保つ。単純window方式と異なり、window外の情報を固定サイズmemoryへ圧縮して次segmentへ運ぶ。

## 限界
固定数memory tokenは情報ボトルネックであり、全履歴を損失なく保持する方式ではない。2M token結果は主に合成記憶課題であり、百万token級の一般的生成品質やオンラインLLMサービングのTTFT/TPOTを評価したシステム論文ではない。長いunrollを伴う学習コストも別途存在する。
