# ETA-VLA：時間融合とLLM内部の視覚トークン選択による自動運転推論の軽量化

## 概要

複数カメラの過去画像を視覚言語行動モデル（Vision-Language-Action model; VLA）へ入力すると、フレーム数とカメラ数に比例して視覚トークンが増える。画像を単純連結して大規模言語モデル（LLM）へ渡すと、自己注意の二乗計算が膨らみ、軌道予測を行う車載推論系の演算費用を押し上げる。ETA-VLAはこの増加を、LLMへ入る前の**時間方向の融合**と、LLM内部の**意味・多様性を使ったトークン間引き**の二段階で抑える。主題は車両の制御アルゴリズムそのものよりも、VLAにおける視覚系列の効率的な処理である。

原著のNAVSIM v2 Navtest評価では、第4層で35%の視覚トークンを間引く設定において、密な基準の9,105 GFLOPsから6,190 GFLOPsへ計算量を減らし、拡張予測運転モデルスコア（Extended Predictive Driver Model Score; EPDMS）を84.8から85.0へ改善した。一方、85%まで間引くと3,830 GFLOPsまで削減できるがEPDMSは80.5へ落ちる。これらは**演算回数と軌道評価の結果**であり、実機の処理時間を32%短縮した測定ではない（原著表III）。

## 問題設定と処理対象

対象の入力は、現在時刻と直前2フレームの多視点画像、および運転指示文である。各フレームを視覚符号化器へ通して得る特徴をそのままLLMへ連結すると、時刻ごとの特徴トークン数をT、フレーム数をn+1として、視覚系列長はT(n+1)になる。さらに各時刻に複数のカメラがあるため、道路正面・側面・後方の情報が系列内に混在する。これらを一律に保持すると、現在の運転指示に無関係な背景まで自己注意へ投入される。

従来の画像トークン削減方式は、画像符号化器の外側で選ぶか、入力末尾の指示文と視覚トークンの通常注意重みを使って選ぶ場合が多い。後者は回転位置埋め込み（Rotary Position Embedding; RoPE）による距離バイアスを受け、遠い位置に配置された別カメラの重要な特徴を過小評価する可能性がある。また、指示文との一致度だけで上位を残すと、たとえば直進時の正面画像へ選択が集中し、交差点の側面視野などを消してしまう。

ETA-VLAは、時間軸を先に集約したうえで、LLMの途中層にある特徴から指示文と視覚情報の意味的な関連度を再計算する。さらに関連度が低くても視点内で特徴が珍しい領域を少量復活させる。前処理で画像数を減らすだけではなく、**言語推論中の表現を使って残すトークンを更新する**ことが特徴である。

## 手法

### 1. 時間融合器（Temporal Fusion Module; TFM）

視覚符号化器が過去から現在までの画像特徴 `V_(t-n), ..., V_t` を抽出する。各時刻の特徴へ学習可能な時刻埋め込み `E_temp(t)` を加え、時刻を区別できる系列を作る。時間融合用のTransformerはこの系列の自己注意を計算し、フレーム間で共通する背景や移動に伴う差を特徴として表現する。続いて学習可能な時間重み `w_i` を各時刻へ適用し、`V_fused = Σ_i w_i V_seq^i / Σ_i w_i` として時間軸を集約する（原著式1・2）。

出力は単一の融合視覚特徴マップであり、射影層と適応器を経てテキストトークンと結合される。これにより過去の各時刻を独立した長いトークン列としてLLMへ入力する必要が減る。単純な平均とは異なり、時間埋め込みと学習重みによって、現在の判断に有効な過去情報を選択的に強める。ただし融合は情報を不可逆に圧縮するため、細かな時間差分が失われる可能性があり、時間融合器自体にも演算が必要である。

### 2. 動的な指示文アンカー選択

LLMの対象層における隠れ状態 `H` から、視覚位置集合 `V` とテキスト位置集合 `T` に従い `H_V` と `H_T` を取り出す。原著式3では `S=softmax(H_V H_T^T)` により視覚・言語の類似度を計算する。各テキストトークンについて視覚トークン全体との類似度を平均し、その平均に基づく閾値 `τ` を超えたトークンだけを、関連する指示文アンカー `T_rel` として採用する（式4）。

この処理は、単純に指示文の全単語を重要度算出に使う場合の、無関係な語やパディングの混入を減らすためのものである。しかも各層で現在の隠れ状態からアンカーを選ぶため、LLM内部で意味表現が変化した後の関連性を利用できる。多視点画像と指示文が入り組んだトークン配置でも、明示的な位置索引で視覚・言語を分離して処理する。

### 3. 位置埋め込みを外した意味スコア

重要度算出に通常の注意行列をそのまま流用すると、RoPEによる相対位置効果や因果マスクが視覚・言語間の関連性を歪める。そこで間引き用の注意では、隠れ状態から得た回転前の問い合わせ `Q_raw` と鍵 `K_raw` を用い、`A_prune=softmax(Q_raw K_raw^T / sqrt(d))` を計算する（式5）。この行列には因果マスクも適用しない。実際の言語モデルの順方向計算には従来どおりRoPEと因果マスクを適用するため、**生成の注意規則を双方向に変えるのではなく、トークン選択専用のスコアを別に計算する**構成である。

関連テキストアンカー `T_rel` から視覚トークン `i` へ向かう `A_prune` の重みを平均し、視覚重要度 `s_i` とする（式6）。これにより指示文に直接関係する道路、信号、障害物などが優先される。重要度を求める層では注意重みの取得が必要なため、著者は該当層だけ逐次実装の注意を使い、その他の層は最適化されたスケールド内積注意（SDPA）またはFlashAttentionを維持する。高速カーネルからの切替費用は発生するが、後段の系列長を減らすことで相殺する設計である。

### 4. 全体上位選択と視点内多様性による復活

最初に全カメラの視覚トークンを `s_i` で並べ、上位 `K` 個を `I_global` として残す。これだけでは、指示文と強く一致する一部視点へ選択が偏るため、削除候補について視点ごとに特徴の多様性を測る。原著式7の多様性 `d_i` は、同一視点内の他トークンとの余弦類似度の平均を1から引いた値である。ほかの領域と異なる特徴を持つトークンほど大きくなる。

この多様性スコアの高い削除候補を追加で `k_recycle` 個選び、`I_final=I_global ∪ I_recycle` として残す（式8）。原著の主要実験では残すトークンの90%を意味スコアによる上位選択、10%を復活枠に配分した。これにより正面カメラへ偏りすぎた選択を補正し、側面や後方の特異な特徴を保護する。ただし多様性が高いことは安全上の重要性と同義ではないため、この操作が危険物体の保持を保証するわけではない。

### 5. 軌道復号と学習

間引いた視覚トークンを通過したLLMの隠れ状態を、軽量なTransformer軌道復号器の記憶特徴として利用する。学習可能な将来時刻埋め込みを問い合わせとして交差注意を計算し、連続値の将来軌道を出力する。さらにNAVSIM v2用の事前学習済みScorerで軌道を改善する。損失は軌道座標のSmooth L1に、横方向位置、速度平滑性、終点位置の損失を加えた `L_total=L_traj+λ1 L_x+λ2 L_vel+λ3 L_end` である（式9）。

論文は投影・適応器の事前学習と、時間融合器・LLM・軌道復号器の共同最適化を記載する。実験節で明示される訓練設定は、trainvalで8基のA800を使い1エポック、バッチ32・学習率1e-3、その後navtrainで1エポック、バッチ8・学習率1e-5である。過去情報は2フレームに固定されている。従って本手法は学習不要な単純な推論時枝刈りではなく、対象VLA系に合わせた学習を含む。

## 評価

### 評価条件

| 項目 | 原著の設定 |
|---|---|
| モデル | LLaVA-v1.5-7B系、ViT-L/14画像符号化器、Vicuna-7B言語モデル |
| 画像系列 | 現在と過去2フレーム、複数カメラの視覚特徴 |
| データ | NAVSIM v2、Navtest（開ループ）、Navhard（摂動を含む疑似閉ループ） |
| 主指標 | EPDMS（衝突、走行領域、方向、信号、進捗、衝突余裕、車線、快適性など9項目を統合） |
| 訓練 | A800×8、trainval 1エポック（バッチ32・学習率1e-3）→navtrain 1エポック（バッチ8・学習率1e-5） |
| 演算量 | 1入力に対するGFLOPs、密な基準9,105 |
| 間引き | 第2層、第4層、または両層。35%、60%、85%の削減率を比較 |
| 比較方式 | DiffusionDrive、GTRS w/ SimScale、Transfuser、VADv2、ランダム枝刈り、HoloV、SparseVLM |

EPDMSは複数の運転評価指標を統合したスコアであり、言語生成の正答率や実車事故率を表すものではない。Navhardは摂動付きの疑似閉ループ評価であり、実車での閉ループ走行試験と同一ではない。GFLOPsは演算量であって、処理時間や消費電力の実測値ではない。

### 評価結果

### 1. 運転軌道の総合スコア

| NAVSIM v2 | 比較対象 | EPDMS | 解釈 |
|---|---|---:|---|
| Navtest | 人間専門家 | 90.3 | 参照値であり提案方式の到達値ではない |
| Navtest | DiffusionDrive | 84.3 | 既存の拡散型軌道方式 |
| Navtest | GTRS w/ SimScale | 84.6 | 強い既存方式 |
| Navtest | ETA-VLA、35%削減 | **85.0** | 同条件で比較した提案方式の値 |
| Navhard | Transfuser | 23.1 | 疑似閉ループの既存方式 |
| Navhard | DiffusionDrive | 26.0 | 疑似閉ループの既存方式 |
| Navhard | GTRS w/ SimScale | 47.2 | 強い既存方式 |
| Navhard | ETA-VLA、35%削減 | **48.0** | 同条件での差は+0.8点 |

Navtestの85.0は、GTRS w/ SimScaleの84.6より0.4点高いが、人間専門家90.3には届かない。原著の表Iでは無責任衝突なし指標NCが99.2、履歴快適性HCが98.3と報告されるが、拡張快適性ECは65.1にとどまる。総合スコアが高くても全下位指標が一様に改善しているわけではない。Navhardでは48.0と47.2の差は0.8点であり、絶対的な安全性保証と読むことはできない。

### 2. 間引き率と挿入層の感度（原著表III）

| ILSA適用層 | 視覚トークン削減率 | 演算量（GFLOPs） | EPDMS | 密な基準からの計算量変化 |
|---|---:|---:|---:|---:|
| なし | 0% | 9,105 | 84.8 | 基準 |
| 第2層 | 35% | 6,091 | 84.4 | 約33.1%減 |
| 第4層 | 35% | 6,190 | **85.0** | 約32.0%減 |
| 第2層 | 60% | 4,773 | 82.8 | 約47.6%減 |
| 第4層 | 60% | 4,963 | 84.7 | 約45.5%減 |
| 第2層 | 85% | 3,556 | 79.8 | 約60.9%減 |
| 第4層 | 85% | 3,830 | 80.5 | 約57.9%減 |
| 第2・4層 | 35%・60% | 5,447 | 78.9 | 約40.2%減 |
| 第2・4層 | 60%・85% | 4,068 | 77.3 | 約55.3%減 |

同じ35%間引きでも、第2層は計算量がやや少ない一方でEPDMSが84.4、第4層は85.0である。早い層で削ると、後続で使う意味表現を失いやすいことが示唆される。第4層の60%削減ではEPDMS 84.7と密な基準84.8に近いが、85%削減では80.5へ下がる。論文の要旨にある「85%のトークンを削減し、約61%のFLOPsを削減」は第2層の3,556 GFLOPsに対応する値であり、最高EPDMS 85.0の設定と同一ではない。設定を混同してはならない。

### 3. 機構除去・選択方式の比較（原著表IV）

| 設定（Navtest） | EPDMS | 機構への示唆 |
|---|---:|---|
| 時間融合器を外す | 77.2 | 過去情報の集約が重要 |
| 35%をランダムに間引く | 64.0 | 単純な間引きでは運転情報が失われる |
| HoloVを選択器に用いる | 79.7 | 固定的な視点領域選択では不足 |
| SparseVLMを選択器に用いる | 83.3 | 言語依存選択でも位置バイアスなどが残る |
| ETA-VLAの選択器 | **85.0** | RoPEなしスコアと多様性復活を併用 |

時間融合器を外すと85.0から77.2へ7.8点低下するため、時間方向の集約は単なる計算削減ではなく、軌道予測の情報表現にも寄与する。一方、選択器の比較は複数の工夫をまとめて切り替えるため、RoPE除去と多様性復活の寄与をそれぞれ独立に定量化したものではない。原著表IVの下位指標と表Iには同じ総合スコア85.0でも下位値の違いがあり、表の設定差が明確でない項目を無条件に同一実験とみなさない。

## 既存研究との差と実装上の意味

画像符号化器側でトークンを減らす方式に対し、ETA-VLAは**LLMの第4層で形成された意味表現**を用いる。SparseVLMのように通常の注意行列を流用する方式と比べ、選択専用にRoPEと因果マスクを外すため、視覚トークンが入力列の遠方にあっても指示文との意味的な関連性を測りやすい。さらに視点内の余弦類似度を使う復活枠が、指示文だけでは評価しにくい側面・後方の情報を残す。

時間融合器と間引き器の役割は異なる。前者は過去フレームの重複を減らし、後者は融合後も残る空間方向の冗長性を削る。時間融合器だけではLLM内の視覚トークン数を十分に減らせず、間引き器だけでは時間的な動きの整合を学習しにくい。原著の除去実験で時間融合を外すと77.2まで低下することは、この二段階が単純な代替関係ではないことを示す。

## 限界

### 負の結果

第一に、**速度・メモリの実測がない**。論文はGFLOPsの削減を示すが、注意重みを得るために対象層だけ逐次注意へ切り替える費用、時刻融合器の演算、トークン索引操作、GPUカーネル起動などを含む実機の推論遅延は示していない。特に第4層で35%を間引く条件の約32%という値を、車載装置の遅延32%削減と同一視できない。

第二に、間引き率を上げると品質が落ちる。第4層85%削減ではEPDMS 80.5で、最高値85.0から4.5点低い。第2層85%削減では79.8まで下がる。第2・4層の二段階間引きも78.9または77.3であり、削れば削るほど良いわけではない。深い第6・8層でも著者は性能低下を観測し、軌道復号に近い圧縮済み表現の損失を原因と推測している。

第三に、時間履歴は実験上過去2フレームだけである。原著が問題設定で強調する長い履歴系列での二乗計算の悪化に対し、10フレーム以上の長期履歴へ拡張した実測は示されない。カメラ数や視野の異なる装置、別のLLM系統、実際の自動運転ハードウェアへ性能がそのまま移ることは未検証である。

第四に、運転安全性の評価はNAVSIM v2のシミュレーション指標であり、実車の安全性試験ではない。指示文関連度と視点内多様性を用いても、稀な危険物体や見えにくい障害物が必ず残る保証はない。特に85%の大幅な間引きでは情報を取りこぼす可能性が増える。人間の注意配分を模したという説明も、実際の運転者の注視データを用いて検証したものではない。

第五に、学習を要する。時間融合器・選択器・軌道復号器を対象モデルに組み込んで調整するため、既存の汎用LLM推論エンジンにそのまま差し込む軽量なカーネルではない。原著の8基のA800による学習設定とNAVSIM v2に依存する。小型GPUでの再現性や、訓練不要な視覚KV圧縮方式との直接比較は未実施である。
