# CacheGen: Fast Context Loading for Language Model Applications via KV Cache Streaming

> 再利用する文脈のKVキャッシュを、差分符号化と層別量子化と算術符号化でビットストリーム化し、帯域に応じてチャンクごとに圧縮レベルやテキスト再計算を切り替えることで、量子化方式よりサイズを3.5倍から4.3倍、読み込み遅延を3.2倍から3.7倍削減する文脈読み込みモジュール。

## 概要

大規模言語モデルへ長い文脈を与えると、応答を始める前に文脈全体を入力処理（プリフィル）しなければならず、その計算は文脈長に対して超線形に増える。そこで一度計算した文脈のKVキャッシュ、つまり各層が作るキーと値のテンソルを保存し、同じ文脈を再び使うときに再利用してプリフィルを省く仕組みが広がっている。ところが再利用が効くのは、必要なKVキャッシュが手元のGPUメモリにある場合だけである。文脈が数千から数万トークンになるとKVキャッシュは数十ギガバイトに達しうるため、多くの文脈のキャッシュをGPUに置き続けることはできず、ストレージ専用サーバや別の推論サーバからネットワーク越しに取り寄せる場面が生じる。通常のクラウドサーバ間の帯域は1桁ギガビット毎秒程度しかなく、この取得遅延がプリフィルそのものと同じかそれ以上になり、再利用の利得を消してしまう。

本論文のCacheGenは、このネットワーク遅延を正面から扱う文脈読み込みモジュールである。着眼点は、送る対象が推論時にそのまま使える形である必要はない、という点にある。実行時のメモリを減らす量子化やトークン削減はテンソルの形を保たなければならないが、転送時のサイズを減らすだけなら、KVキャッシュをテンソルとして送らず、より小さなビットストリームへ符号化して送り、受け側で復号すればよい。CacheGenはKV値の分布の性質を使った専用コーデックで符号化し、さらに帯域の変動に合わせてチャンクごとに圧縮の強さを変えるストリーミングで送る。

**代表結果:** 長文脈の4データセット、合計662件の文脈と、Mistral-7BからLlama-70Bまでの3モデルで、CacheGenは一様量子化の比較対象に対してKVキャッシュのサイズを3.5倍から4.3倍小さくし、文脈の取得と処理にかかる合計遅延、すなわち初回トークンまでの時間（Time-to-First-Token; TTFT）を3.2倍から3.7倍下げた。ほぼ無損失とされる8ビット量子化と比べても読み込み遅延は1.67倍から1.81倍下がる。品質の劣化は、正解率で2パーセント以内、F1スコアで0.1パーセント未満、パープレキシティで0.1未満と小さい。テキストで文脈を送って再計算する方式と比べてもTTFTは3.1倍から4.7倍速い。

## 問題設定

資源の観点では、ボトルネックは計算と転送のどちらか一方ではなく、その組み合わせである。文脈をテキストで送れば転送量は小さいが、受け側で長いプリフィル計算を払い直す。KVキャッシュをそのまま送れば計算は省けるが、浮動小数点テンソルの転送量が膨らみ、帯域の細い経路では取得だけで数百ミリ秒から10秒を超える遅延になる。先行するKVキャッシュ再利用の研究は、キャッシュが同じGPUメモリに残っているか、NVLinkのような数百ギガビット毎秒の高速リンクでつながっている前提が多く、この中間の帯域条件での取得遅延は十分に扱われてこなかった。

もう一つの制約は、圧縮の判断をクエリが来る前に済ませなければならないことである。クエリを見てから重要でないトークンを落とす文脈短縮の方式は、保存の時点では使えない。したがってCacheGenは、クエリに依存せず、KV値そのものの統計的な性質だけから圧縮率を稼ぐ必要がある。さらに転送には数百ミリ秒から数秒かかるため、その間に帯域が変動しうる。固定の圧縮レベルで送ると、帯域が落ちたときにTTFTのサービス品質目標（Service-Level Objective; SLO）を破る。本論文はこの二つ、つまり符号化による転送量の削減と、帯域変動への適応を一つのモジュールで解く。

## 手法のあらまし

CacheGenはKVキャッシュストリーマーとして三つの役割を持つ。第一に、事前に計算したKVキャッシュをコンパクトなビットストリームへ符号化することであり、これはオフラインで済ませられる。第二に、そのビットストリームを帯域の変動する接続でストリーミングすること。第三に、受け側でビットストリームをKVキャッシュへ復号することである。符号化では、近いトークン同士のKV値が似る性質を使って差分を取り、浅い層ほど量子化の損失に敏感である性質に合わせて層ごとに量子化の粗さを変え、チャネルと層ごとに分けた確率分布で算術符号化する。ストリーミングでは、文脈を約1.5Kトークンのチャンクへ分け、各チャンクを複数の圧縮レベルで用意しておき、直前のチャンクで測ったスループットから次のチャンクの構成を選び、帯域が足りなければテキスト送信と再計算へ切り替える。復号はGPU実装で高速化され、転送とパイプライン化される。

## 手法

### 1. 差分符号化 — 近いトークンのKV値の近さを使う

この機構が観測するのは、同一の層とチャネルにおける、トークン位置ごとのキーと値の変化である。実測では、隣り合うトークン間の差分は元の値よりゼロの近くに強く集中し、差分の分散は元の値の分散より2.4倍から2.9倍小さい。自己注意の計算が前のトークンの情報を引き継ぐ構造であるため、近いトークンのKV値が似るのは自然な帰結である。保持する状態は、文脈を10トークンのグループへ分けたときの先頭トークン、いわゆるアンカートークンのKVテンソルと、残りのトークンのアンカーに対する差分テンソルである。処理は、アンカーを独立に圧縮し、他は差分だけを記録することであり、ビデオ符号化のフレーム間差分に似るが、連続するペアではなく同じアンカーを参照するため、圧縮と復号を並列に進められる。これにより減るボトルネックは、符号化後のビット数が支配する転送量である。追加費用はアンカーの精度であり、アンカーは全体のごく一部だが全差分の基準になるため、8ビット量子化という比較的高い精度で保たれる。差分の局所性が弱い文脈では差分のばらつきが大きくなり、圧縮率が下がる境界がある。

### 2. 層別の量子化 — 浅い層を手厚く、深い層を大胆に

この機構が観測するのは、層ごとの量子化損失への感度である。特定の層群だけに丸めの損失を与えた実測では、浅い層へ損失を与えると平均正解率が大きく下がるのに対し、深い層では影響が小さい。浅い層の情報の欠けが後段の層へ伝播するためと考えられる。保持する状態は、層を最初の3分の1、中間の3分の1、最後の3分の1の三つの層群へ分けた量子化の設定である。処理は、差分テンソルに対して浅い層群ほど量子化の刻みを細かく、深い層群ほど刻みを大きくすることであり、一様量子化のように全層へ同じビット数を割り当てる方式とここが違う。これにより減るボトルネックは、品質を守るために全体を高精度で送らなければならないという制約であり、深い層でビット数を削る分だけ転送量が減る。追加で消費する資源は浅い層に残すビット数であり、感度の見積もりが外れたモデルや文脈では、深い層の粗い量子化が品質へ響く可能性がある。量子化そのものは近似であり、この段で落ちた精度は後の無損失な算術符号化では戻らない点も重要である。

### 3. チャネルと層で分けた算術符号化 — 確率分布の当て方でビット数を削る

この機構が観測するのは、量子化後の記号が層、チャネル、トークン位置のどの軸で似た分布を持つかである。実測では、値をチャネルや層でまとめたときのエントロピーの下がり方が、トークン位置でまとめたときより大きい。保持する状態は、層とチャネルの組み合わせごとにオフラインで数えた差分テンソル用の確率分布と、アンカー用の確率分布であり、同じモデルが作る全KVキャッシュで共有される。処理は、頻度の高い記号へ短いビット列を割り当てる算術符号化を、この細分化した分布で行うことである。これにより減るボトルネックも転送量であり、一つの大域的な分布を使う素朴な方式と比べてビットストリームのサイズが最大で53パーセント小さくなることが報告される。追加費用は分布のプロファイルと、GPUで動く算術符号化ライブラリの実装であり、復号はトークンごとにCUDAスレッドへ割り当てられる。分布が実文脈とずれる場合は符号化効率が落ちるが、復号結果そのものは変わらない無損失段であるため、品質ではなく速度だけが影響を受ける。

### 4. ストリーミング適応 — チャンクごとに圧縮レベルと再計算を切り替える

この機構が観測するのは、直前のチャンクを送ったときの実測スループットである。保持する状態は、文脈を連続トークンのチャンクへ分け、各チャンクについて複数の符号化レベルで用意したビットストリームと、テキスト形式の選択肢である。デフォルトのチャンク長は1.5Kトークンで、大きすぎると帯域変化への反応が遅れ、小さすぎるとテキスト再計算を選んだときにGPUのバッチ処理を活かせないという兼ね合いで選ばれている。処理は、帯域がこのまま続くと仮定して構成ごとの予想遅延を計算し、SLO内に収まる構成の中で圧縮損失が最も小さいものを次のチャンクへ選ぶことである。帯域が大きく落ちれば、より強く圧縮したビットストリームへ切り替えるか、そのチャンクだけテキストで送って受け側でKVを再計算させる。これにより減るボトルネックは、帯域変動によるSLO違反である。各チャンクは独立に復号でき、異なるレベルで送ったチャンクを連結してKVキャッシュを再構成できるため、途中の切り替えが圧縮効率を壊さない。誤った場合の挙動として、帯域推定は最大で1チャンク分遅れて反応し、大半のチャンクを強い圧縮で送らざるを得ない低帯域では品質そのものが下がることが論文でも認められている。同時に届いた複数リクエストについては、同じチャンク番号同士をまとめて送り、遅延の見積もりへ件数を織り込むバッチ処理も行う。

## 評価

結論は、転送時の形を捨ててビットストリーム化することで、実行時メモリ向けの量子化より一段深い圧縮が得られ、帯域適応と合わせるとSLO違反も大きく減る、というものである。品質面では、圧縮による劣化は正解率で2パーセント以内、F1スコアで0.1パーセント未満、パープレキシティで0.1未満にとどまる。読み方として重要なのは、この方式がプリフィル計算そのものを速くするのではなく、再利用の前提である遠隔取得を速くする点であり、利得は帯域が細いほど、文脈が長いほど大きくなる。逆に帯域が20ギガビット毎秒を超える条件では量子化方式との絶対差は縮み、文脈が1Kトークン未満の短さではCacheGen自身がテキスト読み込みへ自動で戻るため、方式の出番は長文脈と中低帯域の組み合わせに限られる。

帯域適応の効果はSLO違反率に表れる。帯域がチャンクごとに0.1から10ギガビット毎秒の範囲で変動するトレースでは、TTFTのSLOが1秒の条件で、量子化方式の違反率81パーセントに対してCacheGenは8パーセントまで下げ、同じ品質を保った。SLOが0.5秒の条件でも違反率は60パーセント低くなった。除去に近い比較として、適応なしのCacheGenはこの改善を出せておらず、違反率の差は符号化ではなく適応機構から来ていることが分かる。構成要素ごとの分析では、チャネルと層で分けた算術符号化と差分符号化がサイズ削減の主因であり、層別量子化がその上に乗る。復号のオーバーヘッドはGPU実装と転送とのパイプライン化によりエンドツーエンド遅延の中で小さく、オフライン符号化も約200ミリ秒と短い。複数レベルで保存してもストレージ量は量子化方式と同程度に収まる。未評価の点として、高性能GPUと低帯域の組み合わせや、OPT-175B級の超大規模モデル、物語生成のような自由記述タスクでの品質は論文でも今後の課題とされる。

### 評価上の制約

- 実験はNVIDIA A40の環境であり、高性能GPUではテキスト方式との差が縮む可能性が論文でも指摘される。
- 対象モデルは長文脈向け微調整版のある3モデルに限られ、超大規模モデルは未評価である。
- 自由記述の生成タスクでは品質指標が定義しにくいとして十分に評価されていない。

## 既存研究との差

KVキャッシュの実行時サイズを減らす量子化や、重要でないトークンを落とす文脈短縮との差は、目的が転送時のサイズであり、テンソルの形を保つ必要がない点にある。そのため差分と算術符号化まで踏み込め、短縮方式の結果に重ねてさらに圧縮できる。NVLink級の高速リンクを前提にGPU間でKVキャッシュを渡す分散推論の研究とは狙う帯域条件が違い、通常のサーバ間リンクでの取得を扱う。プリフィックスキャッシュのような再利用の枠組みとは競合ではなく、その再利用先が遠隔にあるときに取得を速くする部品として組み合わさる位置付けである。

## 限界・実装状況

限界は、評価が高性能ではないGPU環境に寄っていること、超大規模モデルと自由記述タスクが未評価であること、文脈の再利用が実際にどれだけ起きるかを示す産業データが乏しいと論文自身が述べていること、検索結果のように揮発する文脈ではキャッシュ再利用そのものが成立しにくいことである。帯域が非常に高い条件や文脈が短い条件では利得が消える。実装状況は、公式コードが公開され、符号化レベルのデフォルトや適応ロジックの詳細が付録に記される。HuggingFaceとLangChainへの統合が実装済みであり、他の推論ライブラリへの同様の統合も可能とされる。

## 一般的な実装上の含意

実行時に使う形と転送時に送る形は分けてよい。テンソルをそのまま送る前提を外すと、差分やエントロピー符号化のような古典的な圧縮の道具がKVキャッシュにも使えるようになる。また、圧縮率の配分は一様にせず、損失への感度が層ごとに違うことを測ってから決めるべきであり、帯域が変動する経路では、圧縮レベルの異なる複数版を用意してチャンク単位で切り替える設計が、再計算への切り替え先まで含めて初めてSLOを守れる。
