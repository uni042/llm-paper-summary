# Llama-Nemotron: Efficient Reasoning Models

## 概要

Llama-Nemotronは、長い推論過程を生成するモデルの計算負担を、単なる生成時の思考トークン削減ではなく、モデル構造の最適化と学習後の推論制御を組み合わせて軽減する公開モデル系列である。Nano（80億）、Super（490億）、Ultra（2530億）の3規模を提供し、通常の会話と詳細な推論を同じモデルで切り替えられる。論文は構造探索、蒸留・継続事前学習、推論過程を含む教師あり微調整、強化学習、指示追従の整列までを一連の工程として報告する。

推論効率の中心はPuzzleによるニューラル構造探索である。Llama 3の各Transformer層に対して、注意演算の除去や前向きネットワークの幅縮小など複数の候補を作り、層単位の局所蒸留で元の機能を近似させる。候補ごとの品質損失と実機の遅延・スループット・メモリ費用を測り、混合整数計画によって層ごとに異なる構造を選択する。Ultraでは連続する前向きネットワークを統合する垂直圧縮も加え、層間の逐次処理を減らす。

実測ではSuperが単一H100上、バッチ256の指定条件で元のLlama 3.3-70Bに対して5倍のスループットを報告し、Ultraは8枚のH100で元のLlama 3.1-405Bに対して1.71倍の遅延改善を得た。ただし両者は元モデルから構造・学習状態が変わっており、単純に同一モデルのカーネルだけを置き換えた高速化ではない。Superの性能回復には400億トークンの蒸留、Ultraには650億トークンの蒸留と880億トークンの継続学習を要する。推論時の軽量化と追加学習費用の交換条件が重要である。

## 問題設定

高性能な推論モデルは、問題を段階的に解き、検証・再試行・反省を行うため、出力トークン数が通常会話より大きくなりやすい。トークンごとに全層を実行する自己回帰モデルでは、生成トークン数の増加と1トークン当たりのモデル計算量が掛け合わさって応答遅延とGPU費用を押し上げる。長い推論過程を生成させるだけでは、モデルの重み容量、注意層の鍵値キャッシュ、前向きネットワークの計算量は減らない。

一方、すべての要求が詳細な推論を必要とするわけではない。定型的な応答に長い思考列を出すと計算資源が浪費される。Llama-Nemotronは二つの軸を分ける。第一にモデル構造自体を実機推論効率向けに作り直し、各トークンの費用を下げる。第二にシステム指示によって通常会話と推論を切り替え、要求ごとに出力計算量を変える。両者は独立の手段であり、構造最適化だけで高度な推論能力が生まれるわけでも、推論切替だけで重み容量が減るわけでもない。

Nanoは80億規模の軽量モデル、SuperはLlama 3.3-70B、UltraはLlama 3.1-405Bを出発点とする。特にSuperとUltraでは、モデルの各層を同一規則で一様に縮めると重要な層の表現能力を失うため、層ごとに圧縮の強さと構造を変える探索問題を解く。目的は単一の圧縮率を最大化することではなく、品質の許容損失、利用できるGPU台数、処理量、キャッシュ容量、遅延の制約を同時に満たすことである。

## 手法

### 1. Puzzleによる層単位の候補生成

まず元のLlama 3 Instructモデルを基準に、Transformerブロックを置き換える候補群を作る。候補には注意演算を省略したブロックや、前向きネットワークの中間幅を87%、75%、50%、10%などへ変えたブロックが含まれる。Puzzle自体は鍵値ヘッド数を変える群問い合わせ注意や線形注意、恒等写像なども扱えるが、論文のSuperとUltraでは注意層除去と前向きネットワーク圧縮が特に有効だったと報告する。

各候補ブロックは元のブロックを教師として局所蒸留され、元の入出力関係を近似する。全モデルを候補ごとに最初から学習し直すのではなく、独立したブロックを並列に準備し、品質損失と推論費用の組を測る。候補の品質が高くてもGPU上の遅延が大きければ採用されない可能性があり、逆に大幅な幅削減でも品質損失が小さい層なら有力になる。

### 2. 混合整数計画による異種構造の組合せ

次に各層へ一つずつ候補ブロックを割り当てる組合せ最適化を行う。目的関数と制約には、局所蒸留で測った品質代理指標、実機の処理量・遅延・メモリ使用量、利用可能なGPU数などを用いる。混合整数計画の結果は層ごとに注意の有無や前向きネットワークの幅が異なるモデルとなる。したがって、圧縮前のLlamaと同じパラメータ数や同じ計算グラフを保つ方式ではない。

Superは単一H100での実行を重視し、テンソル並列度1でバッチ256を処理する構成を最適化した。FP8精度でのキャッシュ済みトークン容量は約30万トークンを制約とし、例としてバッチ16・系列長18,750を挙げる。UltraはH100を8枚搭載したノードを対象とし、元の405Bモデルに対して少なくとも1.5倍の遅延削減を構造探索時の条件とした。モデルを小さくするだけでなく、対象ハードウェアと並列度を固定して探索する点が重要である。

### 3. Ultraの前向きネットワーク融合

注意層を除いた結果、連続する前向きネットワークだけのブロックが現れることがある。Ultraではこれらをより少数の幅広い前向きネットワークへ置き換える融合を適用する。単に演算数を減らすのではなく、逐次実行しなければならない層数を減らし、複数GPUでの層間通信や同期に伴う遅延を抑える。これによりUltraの最終構成では元のLlama 3.1-405B比1.71倍の遅延改善を報告する。

融合は全層へ無条件に適用できるわけではなく、注意層除去後の構造に依存する。幅広い前向きネットワークが常に速いとも限らないため、GPUの演算特性やバッチ条件を含む実機評価が必要である。

### 4. 蒸留と継続学習による品質回復

層ごとの局所蒸留と組合せだけでは、ブロック間の相互作用による品質低下が残る。Superは約400億トークンの蒸留を実施し、Ultraは約650億トークンの蒸留に加えて約880億トークンの継続事前学習を行う。これは軽量構造へ元モデルの知識を戻す工程であり、追加の学習GPU費用を伴う。

Ultraの継続学習後、推論特化の教師あり微調整や強化学習を施す前の段階で、MMLU 88.1、MATH500 80.4、HumanEval 88.4、RULER 128K 83.2を報告する。元のLlama 3.1-405Bの対応値は88.6、69.6、86.0、73.7であり、すべての指標で勝つわけではないが、圧縮後も多くの能力を保持・回復できている。特にRULERの差は長文脈の能力を単純なパラメータ削減だけで判断できないことを示す。

### 5. 推論の切替を学習するデータ設計

推論を有効にした回答にはシステム指示「detailed thinking on」、通常応答には「detailed thinking off」を与える。推論有効データは数学・プログラミング・科学などの問題から作成し、DeepSeek-R1等の教師モデルで複数の解法を生成する。正解を検証できる問題では誤答を除外し、検証が難しい問題では多数決や評価モデルを利用する。推論無効データは同じ問題に対する短い回答を別の教師モデルで作成し、指示と回答形式を対にして学習する。

この切替は実行時に別モデルをロードするのではなく、同じモデルへのシステム指示で生成の仕方を変える。モデルの重みメモリを二重化せずに要求単位で出力トークン数を調整できる一方、どの問い合わせで推論を有効化すべきかを自動的に判定するサービング方策は本研究の中心ではない。

### 6. 教師あり微調整と強化学習

蒸留で構造の能力を回復した後、数学・コード・科学・一般指示のデータを用いて教師あり微調整を行う。長い推論過程ではトークン単位の損失平均が学習率や系列長と相互作用するため、モデルごとに学習率・エポック数・系列詰め込みを調整する。Ultraでは強化学習も行い、正答判定と出力形式の報酬を用いて、教師あり微調整だけでは超えにくい教師モデルの性能を上回ることを目指す。

Ultraの推論強化学習はグループ相対方策最適化（GRPO）を使い、1問題につき16回答、生成温度1、累積確率閾値1、全体バッチ576、1回の生成群につき2回の勾配更新という設定を記す。学習中の回答生成にはFP8推論を活用して費用を抑える。これは推論ライブラリだけの高速化ではなく、学習中の大量生成を含むモデル開発システムの工夫である。

## 評価条件

| 評価対象 | 条件 | 比較対象・注意点 |
|---|---|---|
| Super構造効率 | 単一H100、テンソル並列度1、バッチ256 | 元のLlama 3.3-70B、同モデルの最適並列度4との比較 |
| Ultra構造効率 | H100×8の単一ノード、元405Bからの遅延改善 | 構造探索と前向きネットワーク融合後の推論遅延 |
| Ultra提供処理量 | 同時250要求、入力/出力長500/2000または5000/500 | Ultraと405BはH100×8、DeepSeek-R1はH200×8。GPU世代の違いに注意 |
| 推論品質 | GPQA-Diamond、AIME24/25、MATH500、LiveCodeBench、IFEvalなど | 推論有効・無効を分けて評価。原則32K文脈で測定 |
| 長文脈能力 | RULER 128K | 継続学習後のモデルを元Llamaと比較 |
| 追加学習 | Superは40B蒸留、Ultraは65B蒸留＋88B継続学習 | 学習費用を含まない単純な推論速度比較と区別 |

公開系列はNano 8B、Super 49B、Ultra 253Bで、モデルの規模が異なるだけでなく出発モデルと構造探索の適用範囲も異なる。Ultraの処理量比較でDeepSeek-R1だけH200を使う点は、同一GPU条件での純粋なモデル速度比較ではないことを意味する。推論品質の指標は単純な知識問題、数学、コード、指示追従などを含み、単一のベンチマークが全用途を代表するわけではない。

## 主要結果

### 1. モデル構造の推論効率

| 構成 | ハードウェアと比較条件 | 論文の結果 |
|---|---|---|
| LN-Super 49B | H100×1、並列度1、バッチ256、元Llama 3.3-70B比 | 約5倍の処理量 |
| LN-Super 49B | 元Llama 3.3-70Bを最適並列度4で動かした場合との比較 | 少なくとも2.17倍の処理量 |
| LN-Ultra 253B | H100×8、元Llama 3.1-405B比、構造探索段階の目標 | 少なくとも1.5倍の遅延改善を制約 |
| LN-Ultra 253B | 同条件、前向きネットワーク融合後 | 1.71倍の遅延改善 |
| LN-Ultra 253B | H100×8、FP8でのキャッシュ済みトークン容量 | 最大約300万トークン |
| LN-Ultra 253B | H100×8、BF16でのキャッシュ済みトークン容量 | 最大約60万トークン |

ここでの「キャッシュ済みトークン容量」は指定精度・ノード構成での総容量制約であり、単一利用者が無条件に300万トークンの文脈を使えることを意味しない。Superの5倍もバッチ256と並列度1という明示条件に依存する。追加学習後の品質と推論効率を同時に評価する必要があり、単にパラメータ数が70Bから49Bになったことだけで5倍を説明することはできない。

### 2. 継続学習後、推論特化事後学習前の能力

| 指標 | Ultra継続学習後 | Llama 3.3-70B | Llama 3.1-405B |
|---|---:|---:|---:|
| MMLU | 88.1 | 81.4 | 88.6 |
| MATH500 | 80.4 | 73.6 | 69.6 |
| HumanEval | 88.4 | 84.1 | 86.0 |
| RULER 128K | 83.2 | 52.2 | 73.7 |

これは最終的な推論モデルの事後学習後スコアではなく、構造最適化と知識回復工程の検証である。MMLUは405Bをわずかに下回る一方、数学・コード・長文脈では上回る結果を示す。圧縮だけで能力が増したと断定せず、650億＋880億トークンの追加学習を含む効果として読む。

### 3. 推論有効・無効の性能差

| モデル・指標 | 推論有効 | 推論無効 | 比較・読み方 |
|---|---:|---:|---|
| Super GPQA-Diamond | 66.7 | 50.0 | 推論無効時の性能は元70Bの50.5に近い |
| Super MATH500 | 96.6 | 74.0 | 難しい数学では長い推論が有利 |
| Super LiveCodeBench | 45.5 | 29.7 | 比較対象の一部より弱い |
| Super IFEval | 89.2 | 89.0 | 指示追従を維持するため追加調整 |
| Ultra GPQA-Diamond | 76.0 | 56.6 | DeepSeek-R1の71.5を上回る条件 |
| Ultra AIME24 | 80.8 | 20.0 | 推論を切ると難問性能が大幅に落ちる |
| Ultra AIME25 | 72.5 | 16.7 | 同じ重みでも生成方式が重要 |
| Ultra LiveCodeBench（2408–2502） | 66.3 | 29.0 | DeepSeek-R1の65.9と近い |
| Ultra IFEval | 88.9 | 89.5 | 通常応答でも指示追従が高い |

Superは推論有効時のGPQA-Diamond 66.7で、比較対象のDeepSeek-R1蒸留70Bの65.2を上回るが、AIME24の67.5は同モデルの70.0を下回る。UltraはGPQA-Diamond 76.0でDeepSeek-R1の71.5を上回る一方、MATH500では97.0対97.3でわずかに下回る。したがって「全ベンチマークで優位」という単純な表現は不正確である。

### 4. モデル品質と提供効率の交換条件

Ultraの精度と処理量の比較では、入力500・出力2000、入力5000・出力500という二つの長さ条件を使い、同時250要求で評価する。Ultraと元405BはH100×8、DeepSeek-R1はH200×8を用いている。論文はUltraが高い精度と処理量を両立することを示すが、モデルサイズ、GPU世代、出力長の違いが混在するため、単一の数字をハードウェア非依存の一般速度比として利用してはならない。

Ultraは強化学習前の教師あり微調整でも高い性能を得るが、GPQA-Diamondは66.4から76.0へ改善している。強化学習の貢献は単にモデルを長く学習したことではなく、正答に基づく報酬を使って教師モデルの能力を超えることを狙う点にある。Superでは指示追従の最適化と会話品質の間に交換条件が見つかり、モデル統合で両者を調整した。指示追従を高めるだけでは利用者評価が必ず上がるわけではない。

## 既存研究との差

従来の推論モデル開発は、強い教師から長い推論過程を蒸留したり、推論時に生成するトークンを増やしたりして能力を向上させることが多い。Llama-Nemotronはこれに加え、推論の各トークンを処理するTransformer構造そのものを、実機の遅延・スループット・メモリを考慮して選び直す。均一な枝刈りと異なり、層ごとの候補ブロックを独立に評価し、混合整数計画で異種構造を選ぶ点が特徴である。

一方、推論有効・無効の切替はモデルのアーキテクチャを動的に変更するものではなく、システム指示で回答の形式・長さを制御する。構造探索は常時の1トークン当たりの費用を下げ、切替は必要なトークン数を調整するため、二つの効率化は別の階層にある。これらを混同すると、切替を無効にしただけで重み容量が減るような誤解につながる。

## 限界と実運用上の注意

最も重要な限界は、構造最適化後に大規模な蒸留・継続学習・事後学習が必要なことである。既存チェックポイントを無学習で軽量化する手法ではない。Superの400億トークン、Ultraの650億＋880億トークンは、一般の利用者が手元のGPUで容易に再現できる規模ではない。推論の運用費用を削減する一方、モデルを開発するための計算資源を大量に消費する。

速度評価はH100を中心に、特定のバッチ、並列度、精度、入力・出力長で行われる。単一H100でのSuperの倍率や8枚H100でのUltraの遅延改善を、消費者向けGPU、CPUオフロード、量子化4ビット実装へそのまま適用することはできない。DeepSeek-R1との処理量比較ではH200を用いるなどGPU世代も異なるため、ハードウェア条件を揃えた純粋なモデル速度比較とは区別する。

推論の有効・無効は利用者やサービス側の指示に依存し、要求ごとに最適な切替を自動選択するスケジューラは主題ではない。長い推論が不要な質問でも常に推論を有効化すれば生成費用は増える。逆に難問で推論を切るとAIMEなどの性能が大幅に下がる。適切な切替規則を設計しない限り、理論上の効率化余地を実運用で完全に活かせない。

また本報告は構造探索から学習後の推論能力までを広く扱うモデル開発論文であり、鍵値キャッシュのページ管理、連続バッチのスケジューリング、CPUへの専門家オフロードなどの独立した提供基盤を提案するものではない。公開モデルと学習基盤が存在しても、全学習データ生成過程やハードウェア費用まで第三者が容易に再現できることを意味しない。モデル性能の評価では推論有効・無効、使用GPU、出力長、精度を必ず併記する必要がある。
