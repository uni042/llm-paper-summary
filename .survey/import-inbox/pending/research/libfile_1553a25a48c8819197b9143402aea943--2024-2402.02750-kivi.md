# KIVI: A Tuning-Free Asymmetric 2bit Quantization for KV Cache

## 概要
自己回帰復号では過去tokenのkey/value（KV）を全層で保持し、次tokenごとに読み直す。文脈長とbatchが増えるほどKV容量とHBM読出しが増え、重みよりKVが大きくなる条件さえある。KIVIはKVを一律に低bit化するのではなく、keyとvalueで量子化に強い方向が異なることを実測し、keyをchannel単位、valueをtoken単位で2bitへ量子化する。

Llama-2-13Bの予備実験ではkey/value双方をtoken単位2bitにするとCoQA 66.37→52.93、TruthfulQA 29.53→24.98まで悪化する一方、keyをchannel単位、valueをtoken単位にすると63.53/28.60まで回復する。KIVIはこの非対称性をstreaming data structureへ実装し、Llama、Falcon、Mistralでほぼ品質を維持しながら、Llama-2-7Bのpeak memoryを2.6倍削減、最大4倍のbatchを収容し、実推論throughputを2.35〜3.47倍へ高める。

## 問題設定
KVキャッシュは生成tokenごとに伸び、各decode stepでattentionが過去KVを読む。例えば論文が引用するOPT-175B条件ではbatch 512、prompt 512、output 32でKVだけで1.2 TBとなり、model weightの3.8倍に達する。容量だけでなくHBMからSRAMへKVを読む時間中は計算器が待ちやすく、帯域律速にもなる。

単純なround-to-nearest量子化は追加学習なしで適用できるが、2bitまで下げると誤差が大きい。重要なのはkeyとvalueがattentionで異なる役割を持つ点である。keyの誤差はqueryとの内積を通じattention scoreへ入り、valueの誤差はattention weightによる加重和へ直接入るため、同じgroup方向が最適とは限らない。

## 手法

### keyのchannel単位量子化
key cacheには、複数tokenにわたり同じchannelで大きな外れ値が現れる。token単位でmin/maxを共有すると一つの外れchannelが量子化rangeを広げ、通常channelの2bit刻みが粗くなる。channel単位なら外れ値の影響をそのchannelへ閉じ込められる。

Llama-2-13Bではkeyの相対再構成誤差がtoken単位13.67に対してchannel単位4.55、attention score相対誤差が47.00に対して9.60となり、後者は約5分の1である。この内部指標が、単なるtask accuracyだけでなくkey側の設計根拠を与える。

### valueのtoken単位量子化
valueにはkeyのような固定channel外れ値が見えない。それでもchannel単位量子化は悪化する。attention outputは各tokenのvalueをattention scoreで重み付けして混ぜるが、attentionは疎で少数tokenの寄与が大きい。token単位量子化なら重要tokenの誤差を他tokenの外れ値から分離できる。

論文の相対attention-output誤差Δはvalue token単位3.55、channel単位49.89で、token単位が約15倍小さい。したがってKIVIの非対称性は「keyに外れ値がある」だけでなく、valueがattention mixerへ入る構造まで含めて決められている。

### grouped cacheと高精度residual
valueのtoken単位量子化は新tokenをそのまま量子化してappendできるが、keyのchannel単位量子化は複数tokenをまとめる必要がある。KIVIはKVを量子化済みgroup部と高精度residual部へ分ける。新keyはresidualへ追加し、residual長Rに達したらG token単位のgroupへまとめてchannel量子化し、量子化済み領域へ移す。

value側も直近R tokenを高精度queueとして保持し、古くなったtokenからtoken単位で量子化済み領域へ送る。直近tokenを高精度に保つことは、streaming実装上の端数処理と精度保護の双方に効く。RはGで割り切れる必要がある。

### 混合精度attention kernel
attention計算では量子化済み領域を単純に全量dequantizeして別tensorへ戻すとmemory利得が帯域費用で失われる。KIVIはdequantizationをタイル化行列積へ融合したQ_Matmulを使い、量子化groupと高精度residualのscoreを計算して結合する。

prefillでは次層へ渡すkey/value自体は元精度を使い、メモリへ保持するKVだけを量子化する。したがって低bit誤差を層間activationへ直接伝播させるweight/activation量子化とは誤差経路が異なる。

## 主要結果
|条件|比較|結果|意味|
|---|---|---:|---|
|Llama-2-13B / CoQA|FP16 66.37|K/V token 2bit 52.93、K channel/V token 63.53|非対称量子化が2bit精度を大幅回復|
|Llama-2-13B / TruthfulQA|FP16 29.53|K/V token 24.98、K channel/V token 28.60|同じ傾向を別taskでも確認|
|key内部誤差|token vs channel|attention score 47.00 vs 9.60|channel量子化がkey誤差を抑える|
|value内部誤差|token vs channel|Δ 3.55 vs 49.89|valueはtoken量子化が必須|
|Llama-2-7B|通常KV|peak memory 2.6倍削減|KV圧縮がmodel込みpeakへ効く|
|実推論|通常KV|最大4倍batch、2.35〜3.47倍throughput|容量削減がbatch拡大と帯域削減へつながる|

## 既存研究との差
FlexGen等のKV offloadはKVをCPU側へ移してGPU容量を空けるが、転送が増える。H2O等のevictionはtoken自体を捨てる。KIVIは全tokenを保持したまま各要素のbit数を減らし、追加学習を要求しない。

weight量子化で知られる外れ値処理をKVへそのまま適用するのでもない。key/valueの分布とattention内での使われ方を分けて分析し、異なる量子化軸を採用した点が中心である。

## 限界
2bit化しても直近R tokenは高精度で保持するため、極端に短い文脈では圧縮率が理論4分の1へ近づかない。Q_Matmul等の専用kernelがない環境ではdequantization費用が速度利得を削る。品質も完全losslessではなく、taskによって小さな低下が残る。

またKIVIはKV容量を減らす方式であり、weight memory自体は圧縮しない。G/Rなどの設定、モデルのattention構造、将来のGQA/MLA型KV形状が変われば最適実装は再評価が必要である。
