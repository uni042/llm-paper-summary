# Attention Score is not All You Need for Token Importance Indicator in KV Cache Reduction: Value Also Matters

## 概要
H2OやScissorhandsは過去トークンの重要度を主に注意重みから推定する。しかし注意出力は注意係数だけでなくValueベクトルにも依存する。論文はValueノルムがトークン間で大きく異なるため、注意係数が小さくても大きなValueを持つトークンを捨てると出力寄与を過小評価すると指摘する。

Value-Aware Token Pruning（VATP）は既存枝刈り法の重要度へValueベクトルのL1ノルムを組み込む。LLaMA2-7B-chatではH2O+VATPがLongBench 16タスク中12、Scissorhands+VATPが13タスクで元方式を上回る。FlashAttention互換のScissorhands統合では入力4096・出力128で、全KV比50%予算1.53倍、25%予算2.08倍の生成スループットをA6000上で示す。

## 問題設定
注意出力はValueの重み付き和なので、注意確率だけの順位はValueの大きさが均一な場合に近い。実測ではValueノルムは非一様で、注意だけの順位と実際の出力寄与がずれる。KV予算が小さいほど順位誤りは回復不能な情報削除へつながる。

## 手法
### Valueを含む重要度
各過去トークンについて注意ベース重要度へ対応ValueのL1ノルムを反映し、出力へ与え得る振幅を順位へ入れる。ノルムはValue生成時に一度計算でき、将来queryで再利用できる。

追加状態はトークンごとのスカラーで、KVベクトル本体より小さい。head dimensionが128なら追加量はKV保存量のおおむね1/(2×128)程度である。

### H2Oへの統合
H2Oは過去注意scoreを累積しheavy hitterを保持する。VATP版はその順位をValueノルムで補正し、注意は中程度でも出力寄与が大きいトークンを残しやすくする。ただしH2Oの累積注意行列はFlashAttentionと相性が悪く、この制約は残る。

### Scissorhandsへの統合
Scissorhandsの履歴窓から重要トークンを選ぶscoreへVATPを適用する。論文設定では重要度選択数k-10、local window 10、history window 400とし、元方式との差を重要度とattention sink保持へ限定する。この経路はFlashAttention互換なので実際のtoken/sも測れる。

## 評価条件
|項目|内容|
|---|---|
|モデル|LLaMA2-7B-chat、Vicuna-v1.5-7B-16k|
|品質|LongBench英語16タスク|
|主KV予算|50%、追加で20〜80%枝刈り|
|比較|H2O、Scissorhandsと各VATP版|
|速度GPU|A100 80GB、A6000 Ada 49GB|
|速度条件|LLaMA2-7B-chat、入力4096、出力128|

## 主要結果
|条件|結果|意味|
|---|---|---|
|LLaMA2 + H2O/VATP|16中12タスクで改善|Value情報が順位改善|
|LLaMA2 + Scissorhands/VATP|16中13で改善|別枝刈り器へ移植可能|
|Vicuna|12〜14/16で改善|モデルを跨ぎ傾向維持|
|A6000、KV 50%|全KV比1.53倍|実測生成高速化|
|A6000、KV 25%|全KV比2.08倍|強い圧縮で帯域利得増加|

20〜80%枝刈りの感度評価では圧縮が強い領域ほどVATPの優位が目立つ。重要トークンを誤って捨てる損失が厳しい予算で大きくなるためである。

## 既存研究との差
H2OやScissorhandsは「いつ何を残すか」の管理方策を提案する。VATPは管理方策を置換せず、注意scoreだけだった観測量をValueノルムまで拡張するため複数方式へ差し込める。

## 限界
H2O経路は完全注意score累積が必要でFlashAttentionと直接両立しにくい。論文はGQAへの直接適用も未解決として挙げる。Valueノルムは将来queryごとの意味的重要性を完全に予測するものではない。
