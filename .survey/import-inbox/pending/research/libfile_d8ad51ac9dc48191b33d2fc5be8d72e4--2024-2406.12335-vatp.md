# Attention Score is not All You Need for Token Importance Indicator in KV Cache Reduction: Value Also Matters

## 概要
長文脈生成では過去トークンのKey・Valueを保持するKVキャッシュが系列長に比例して増える。H2OやScissorhands系の方式は過去の注意重みを累積し、よく参照されたトークンを重要とみなして残す。しかし注意出力は注意重みだけでなくValueベクトルとの積の和であるため、重みが大きくてもValueが小さければ実際の出力寄与は小さい。

Value-Aware Token Pruning（VATP）はこの点を直接重要度へ入れる。著者はValueベクトルのL1ノルムがトークン間・層間で大きく異なり、とくに先頭付近のattention sinkが高い注意重みを集めながらValueノルムは小さい場合があることを観測する。そこで累積注意重要度をValueノルムで補正し、限られたKV予算で出力寄与の大きいトークンを優先する。

## 問題設定
通常の注意出力は各過去トークンのValueベクトルを注意重みで加重和する。したがってトークンiの寄与は、概念的には注意係数だけでなくValueの大きさにも依存する。注意スコアだけを履歴として蓄積すると、頻繁に参照されるが実際の出力ベクトルへの寄与が小さいトークンを過大評価し得る。

KV削減では誤って重要トークンを捨てると、その後の全デコードで情報を復元できない。VATPは新たな学習器や別モデルを追加せず、既にKVキャッシュ内に存在するValueから計算できる統計を使うことで、追加費用を小さく保つ。

## 手法
### Valueノルム観測
各層・各トークンのValueベクトルについてL1ノルムを測り、均一ではないことを確認する。注意重みが同程度でもValueノルムが異なれば注意出力への寄与が変わる。この観測が「注意重みのみ」という既存重要度の不足を示す。

### Value-aware重要度
既存の累積注意スコアへValueベクトルのL1ノルムを組み込み、トークンごとの保持優先度を更新する。過去から高い注意を得ていてValueも大きいトークンは残りやすく、注意だけ高くValueが小さいトークンは順位が下がる。L1ノルムはKV生成時に計算でき、別の推論モデルを必要としない。

### KV退去
キャッシュ予算を超えると、補正後重要度の低いトークンからKVを退去する。方式は既存の注意スコア型退去へ差し込めるため、トークン選択の枠組みを全面的に置き換えるのではなく、重要度指標を改善する設計である。

## 評価
|項目|内容|
|---|---|
|モデル|LLaMA2-7B-chat、Vicuna-v1.5-7B|
|データ|LongBench 16タスク|
|比較|注意スコアのみを使うKV削減方式|
|評価軸|長文脈タスク品質、キャッシュ予算ごとの性能|

VATPは16 LongBenchタスクのうち12を超えるタスクで注意スコアのみの基準方式を上回る。特にキャッシュ予算が厳しい条件では、誤ったトークン退去の影響が大きいためValue情報の追加が効く。論文の主張はエンドツーエンドの大幅な速度倍率ではなく、同じKV削減枠組み・予算の中で保持トークンの質を改善する点にある。

## 既存研究との差
H2OやScissorhandsに代表される方式は「過去にどれだけ注意されたか」を主な保持信号にする。VATPは注意計算式そのものに戻り、出力寄与にはValueの大きさも必要だと指摘する。別の予測器を学習するのではなく、既存KVから得られるL1ノルムを使うため、既存退去方式へ比較的軽量に統合できる。

## 限界
評価は7B級モデルとLongBenchを中心としており、より大規模なGrouped-Query Attentionモデルや高同時実行サービングでの実メモリ帯域・token/s改善は主要結果ではない。L1ノルムは出力寄与の近似であり、方向や後続層での非線形効果を完全に表すわけではない。Valueノルム計算と重要度更新にも小さい追加費用がある。
