# Strata: Hierarchical Context Caching for Long Context Language Model Serving

## 概要
長文脈を繰り返し使うLLMサービスでは、過去prefixのKVキャッシュを再利用すればprefill計算を省ける。しかし長いKVはGPU HBMに収まりきらず、CPUメモリや下位階層へ退避される。再利用時には大量のKVをGPUへ戻す必要があり、PagedAttentionのページ化された配置ではI/Oが細切れになって帯域を使い切れない。さらに通常のスケジューラは「計算時間」中心に要求を並べるため、KV読込待ちを隠せず、キャッシュがあるのにTTFTがI/Oで悪化する。

Strataはこの問題を二つに分ける。GPU補助I/OでGPU上のページ配置とCPU側の転送レイアウトを分離し、連続した大きな転送へまとめる。次にキャッシュ読込遅延を要求スケジューリングへ入れ、I/O待ちが生じる要求と計算可能な要求を組み合わせてストールを隠す。SGLangへ実装してproduction環境でも使用され、長文脈ベンチマークでvLLM+LMCacheよりTTFTを最大5倍短縮し、TensorRT-LLMより最大3.75倍高速化する一方、短文脈性能を低下させない。

## 問題設定
階層KVキャッシュでは、GPUにないprefixをCPUなどから復元する。論理的には同じprefixでも、GPU側ではPagedAttentionが固定サイズpageへ分散配置するため、CPUから各pageへ直接コピーすると小さな転送が多数発生する。PCIe等は大きな連続転送で帯域を出しやすいため、断片化は実効帯域を落とす。

またキャッシュ命中を「prefillを省けるので常に速い」と扱うと、巨大prefixのロード時間を見落とす。計算資源が空いていてもI/O完了待ちの要求しか選ばれていなければGPUが遊休する。Strataは、KV再利用量だけでなくロード完了時刻まで含めてサービング判断を行う。

## 手法
### GPU補助I/Oとレイアウト分離
StrataはCPU側のキャッシュをGPUの物理page配置と同じ形で保持しない。下位階層では転送効率のよい連続レイアウトを使い、GPUへ大きな塊として運ぶ。GPU側で軽量な再配置を行い、PagedAttentionが期待するpageへscatterする。これによりCPUが多数の小さなDMAを発行する代わりに、リンク帯域を使いやすいbulk transferへ変換する。

入力は再利用対象prefixのKVとGPU上のpage割当、出力はPagedAttentionがそのまま参照できるGPU KV pageである。GPU側に再配置計算を追加する代わりに、遅いホスト側の断片I/Oを減らす。したがって利得は長いcache loadほど大きく、もともとI/Oが小さい短prefixでは追加処理を抑える必要がある。

### キャッシュ認識スケジューリング
各要求について、再利用できるKV量だけでなく、そのKVがどの階層にあり、GPUへ戻すまでどれだけ待つかを見積もる。I/O待ちの要求を直ちに実行queueの先頭へ置くのではなく、ロード中に別要求のprefill/decodeを進める。入力は要求のcache状態、転送時間、計算量で、出力はI/OとGPU計算ができるだけ重なる実行順序である。

この機構はキャッシュ命中率を最大化すること自体を目的にしない。巨大cache hitでもロードが計算より長ければloading-boundになるため、補完的な計算を同時に用意してGPU遊休を削る。I/Oを完全に隠せない場合でも、待ち時間を別仕事へ変換することが狙いである。

### エンドツーエンドの流れ
prefix cache hitした要求が到着すると、スケジューラがcache所在とロード時間を見積もる。CPU側では転送向けレイアウトから大きなKV chunkを送り、GPUがpage配置へ変換する。その間に別要求をGPUへ投入し、KV到着後に対象要求を実行可能へ移す。このためI/O最適化とスケジューリングは独立ではなく、前者が転送時間を短縮し、後者が残った時間を隠す。

## 評価条件
|項目|内容|
|---|---|
|実装基盤|SGLang|
|対象|長文脈LLMサービング、階層KVキャッシュ|
|比較|vLLM + LMCache、NVIDIA TensorRT-LLM|
|主要ボトルネック|Paged KVの断片I/O、cache-loading stall|
|主要指標|最初のトークンまでの時間（TTFT）、短文脈性能|
|運用|production deploymentを含む|

## 主要結果
|条件|比較対象|結果|意味|
|---|---|---|---|
|長文脈ベンチマーク|vLLM + LMCache|TTFT最大5倍短縮|断片転送とロード待ちの双方を減らす効果|
|長文脈ベンチマーク|TensorRT-LLM|最大3.75倍高速化|階層cache復元を含む経路で優位|
|短文脈|従来経路|性能劣化なし|長文向け機構の常時overheadを抑制|

最大値だけでなく、論文の主張は「キャッシュを置く」だけでは不十分で、I/Oレイアウトと要求順序を同時に扱う必要がある点にある。GPU補助I/Oは実効帯域を改善し、cache-aware schedulerは残る転送を計算へ重畳するため、二つの効果を分離して解釈する必要がある。

## 既存研究との差
LMCache等の階層KVキャッシュはGPU外へKVを置いて容量を拡張するが、Strataは復元時の断片I/OをGPU側再配置で処理し、さらにロード時間をschedulerの判断へ入れる。単なるcache eviction policyではなく、「転送データレイアウト」と「要求スケジューリング」を同じloading-bound問題の二面として扱う。

## 限界
利得は長いprefix cacheをGPU外から戻す負荷で大きく、cacheがGPUに常駐する場合や短文脈中心では改善余地が小さい。GPU再配置自体にも計算・帯域costがあるため、細粒度転送が十分小さい場合には常に有利とは限らない。公開要旨から確認できる代表値は最大TTFT改善であり、すべてのworkloadで同じ倍率になるわけではない。
