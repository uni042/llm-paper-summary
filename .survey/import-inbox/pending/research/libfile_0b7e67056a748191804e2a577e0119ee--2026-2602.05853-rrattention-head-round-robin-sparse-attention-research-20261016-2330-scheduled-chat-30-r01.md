# RRAttention：注意ヘッドを巡回して長文脈の重要ブロックを探す動的疎注意

## 概要

長文脈の自己注意では、入力長 `L` に対する注意行列の要素数が `L²` で増える。重要なブロックだけを計算する疎注意は演算を減らせるが、固定パターンは入力ごとの重要な依存関係を見逃し、動的パターン探索は前処理や高価な注意スコア計算を要求することがある。RRAttentionは、各注意ヘッドで標本にする問い合わせ位置を巡回させ、系列全体を覆う重要度推定と、問い合わせ同士の独立性を両立する。

提案法は各 `S` トークン区間からヘッドごとに異なる問い合わせを一つ選び、鍵を区間単位で集約して重要度を計算する。さらにブロック単位の累積重要度に応じて保持先を決める。重要度探索の理論計算量は `O(L²/S²)` に縮小する。Llama-3.1-8BとQwen2.5-7BのHELMETでは、注意ブロックの約半分を省略しながら全注意の平均性能の99%以上を再現した。128K文脈では全注意比2.4倍の実測高速化を報告する。ただし主な高速化対象は入力処理（prefill）であり、逐次復号では通常の密な注意を使用する。

## 既存方式との比較と設計目標

固定窓や特定位置への注意を残す方式は、局所的な依存関係には効くが、遠い文書からの検索や動画内の離れたフレーム間の対応を見逃すことがある。動的疎注意のSeerAttentionは蒸留学習を、MInferenceは事前のヘッド別パターン割当を必要とする。FlexPrefillは末尾の問い合わせブロックから重要位置を推測するため、文脈前半にだけ現れる重要な関係を十分観測できない可能性がある。XAttentionは反対角線方向の標本化で全体を観測するが、異なる問い合わせの注意情報を集約することがある。

RRAttentionが同時に狙うのは、事前学習や事前パターン探索の不要性、系列全体の重要度観測、問い合わせ分布の独立性、ヘッドごとの特別なパターン分類を要しないこと、そしてトークン単位より粗い区間単位での重要度計算である。これらはそれぞれ、未知モデルへの導入、遠距離依存の発見、意味の混合の回避、実装単純化、計算費用の削減につながる。ただし動的な重要度推定は実行時に必要であり、探索費用そのものがゼロになるわけではない。

## 手法

### 注意行列のブロック化と巡回問い合わせ標本

入力の問い合わせ行列 `Q` と鍵行列 `K` を、実際に疎注意を実行するブロック幅 `B` で分割する。重要度を探索する際は、これより細かい区間幅 `S` を使う。ブロック対 `(m,n)` を計算するかどうかは二値行列 `B[m,n]` で表し、因果的な自己回帰モデルでは未来位置への注意を許可しない。ブロックを削る目的は、全注意の出力に近い結果を維持しながら計算するブロック対の数を減らすことである。

区間 `i`、ヘッド `h` の代表問い合わせ位置は `P(i,h)=iS+(S-1-(h mod S))` と定義する。例えば `S=4` なら、ヘッドごとに同一区間内の異なる位置を選ぶ。ヘッドを巡回させることで、全ヘッドが同じ位置だけを見る固定標本化と違い、区間内の位置を分散して観測できる。ヘッド数が区間幅以上なら各位置が少なくとも一つのヘッドで選ばれるが、ヘッド数が区間幅より少ない場合は全位置の被覆を保証できない。この制約は原著の限界節でも明記されている。

### 区間単位の重要度推定

各問い合わせ区間の代表ベクトルと、鍵区間内の全鍵ベクトルの和を内積し、`1/(S√d)` で正規化して区間間スコアを得る。`d` はヘッド次元である。各問い合わせ区間に対して鍵区間方向へソフトマックスを適用し、合計が1となる重要度分布を作る。ここでは一つの問い合わせのスコアを別の問い合わせのスコアと混ぜないため、反対角線集約と異なり問い合わせ単位の正規化を保つ。

系列長 `L` で区間数はおよそ `L/S` なので、全区間対のスコア計算は `O((L/S)²)` になる。鍵を区間単位で足す操作には別の費用があるが、密な `L×L` の注意行列を求めずに全系列から重要な関係を推定できる。大きな `S` は探索を安くする反面、局所的な重要トークンが平均化される危険を増やす。したがって理論的な計算量の縮小だけでは実測品質を説明できない。

### 累積重要度に基づくブロック選択

区間ごとの重要度を、実行ブロック `B` の対へ集約する。各問い合わせブロックについて、鍵ブロックを重要度の高い順に並べ、累積重要度がしきい値 `τ` を超える最小限の集合を選ぶ。固定個数ではなく累積質量で決めるため、注意が少数の位置へ集中する場合にはより疎に、広く分布する場合にはより多くのブロックを残す。実験では `τ=0.90` と `0.95` を比較している。

生成品質に影響しやすい末尾の問い合わせブロックについては、全鍵ブロックを無条件に保持する保護マスクを設ける。最終マスクは動的に選んだブロック集合と保護マスクの論理和である。選択後はGPUのブロック疎注意カーネルで残したブロックだけを計算する。したがって選別精度だけでなく、実際のカーネルのブロック配置・メモリアクセスが実測速度を決める。原著の実装はFlashAttention-2系の疎カーネルを基礎とする。

## 評価

### 評価条件

| 項目 | 原著の設定 |
|---|---|
| GPU | NVIDIA H100 |
| テキストモデル | Llama-3.1-8B-Instruct、Qwen2.5-7B-Instruct |
| 動画モデル | Qwen2-VL-7B-Instruct |
| テキスト評価 | HELMET：検索、引用付き生成、再順位付け、文書QA、要約、合成検索等 |
| 動画評価 | Video-MME：900動画、2700問、短・中・長動画 |
| 比較 | 全注意（FlashAttention）、FlexPrefill、XAttention |
| 文脈長 | 8K、16K、32K、64K、128K |
| 対象工程 | 疎注意は入力処理のみ。復号は各方式とも密な注意 |

### テキスト長文脈での精度と疎性

| モデル、方式 | 平均疎性 | HELMET平均性能 | 128K性能 |
|---|---:|---:|---:|
| Llama、全注意 | 0% | 56.42 | 49.74 |
| Llama、XAttention `τ=0.95` | 47.50% | 55.74 | 49.45 |
| Llama、RRAttention `τ=0.95` | 48.68% | **56.24** | **50.37** |
| Qwen、全注意 | 0% | 47.68 | 39.59 |
| Qwen、XAttention `τ=0.95` | 47.35% | 46.64 | 38.09 |
| Qwen、RRAttention `τ=0.95` | 47.56% | **47.17** | **38.51** |

Llamaの平均は全注意56.42に対して56.24で約99.7%、Qwenは47.68に対して47.17で約99.0%となる。これは**ベンチマーク平均性能の比**であり、注意出力が数学的に99%以上一致するという保証ではない。より強い削減の `τ=0.90` ではLlamaの疎性61.02%、平均55.67、Qwenの疎性59.53%、平均46.63であり、精度との交換条件が見える。FlexPrefillはLlamaの疎性66.07%で平均52.54と、より疎だが品質が低い条件がある。

### 動画理解・速度・内部評価

Video-MMEの1フレーム/秒では、Qwen2-VL-7Bの全注意平均63.90に対し、RRAttentionは `τ=0.95`、疎性34.70%で64.30、`τ=0.90`、疎性47.00%で64.00だった。0.5フレーム/秒・字幕ありの設定では全注意67.80、`τ=0.95` のRRAttentionは67.70で、常に無圧縮を上回るわけではない。長動画の時間関係を扱う際に、全体観測による重要ブロックの発見が役立つと考えられる。

Llama-3.1-8Bの128K入力では全注意比2.4倍の実測高速化を報告する。これは入力処理を中心とした比較であり、生成の全トークンで同じ倍率が続くわけではない。重要パターン探索の追加時間はXAttentionより18.2%少ないと報告するが、これは全体速度倍率と別の指標である。構成要素除去実験では、区間幅 `S<32` の範囲で品質が比較的安定し、`S=32` では重要信号が粗い集約で希釈され品質が低下する。ブロック選択の精度とF1でも全注意から得た正解パターンとの一致度を検証している。

## 限界

RRAttentionは入力処理段階の疎注意であり、逐次生成のKVキャッシュ読込を直接削減する方式ではない。復号時の帯域節約は原著で将来課題として挙げられている。区間幅 `S` がヘッド数より大きいと全位置の巡回被覆を保証できず、過大な区間幅では重要なトークンの情報が平均化される。標本化した重要度は近似であり、特定の質問で必要なブロックが必ず選ばれるという保証もない。

実測はH100上の限られたモデル・文脈長と特定の疎カーネルを対象とする。異なるGPU、低並列度、同時要求サービング、既存KVキャッシュの量子化・退避との併用で同じ利得が得られるかは未確認である。公式公開コードのURLは一次論文中で特定できず、実装の移植可能性を断定しない。
