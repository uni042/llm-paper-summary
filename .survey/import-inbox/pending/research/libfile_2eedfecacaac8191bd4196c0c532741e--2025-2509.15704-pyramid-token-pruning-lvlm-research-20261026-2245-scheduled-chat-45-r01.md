# PTP：高解像度VLMの画像タイル・パッチ・指示文を統合したトークン剪定

## 概要

高解像度画像を理解する視覚言語モデル（VLM）は、一枚の画像を複数の局所タイルと全体縮小画像へ分け、視覚エンコーダが生成した多数のパッチ表現を言語モデルへ渡す。解像度を上げると小さな文字や物体を認識しやすくなる一方、画像トークン数が増え、言語モデル側のprefill計算・KVキャッシュ容量・応答遅延が増える。すべての画像領域が質問への回答に等しく必要なわけではないため、画像トークンを減らす余地がある。

Pyramid Token Pruning（PTP）は、追加学習なしで、**画像全体に対するタイルの重要度、タイル内部のパッチ重要度、ユーザーの指示文に対するパッチ関連度**を三段階で組み合わせる方式である。まず各タイルのCLS表現と全体画像CLSの類似度から領域ごとの保持トークン予算を決める。次に視覚エンコーダのCLS→パッチ注意でタイル内部の重要度を測る。さらに言語モデルの早期層における指示文→画像注意を利用し、質問に関係するパッチを救済する。最終的な画像トークン列を短くして後段の言語モデルへ渡す。

InternVL2-2BとInternVL2-8Bの13ベンチマークでは、視覚トークンを半分にしても、無剪定モデルに対する平均正規化品質がそれぞれ99.8%と99.7%だった。2Bモデルを単一L20 GPUで測ると、視覚トークン1792→896、KVキャッシュ336→168MB、GPUメモリ24.6→20.9GBとなる。**平均99.8%は13課題の相対品質集約であり、全課題で正答率99.8%という意味ではない。**

## 問題設定と設計上の前提

### 高解像度タイル化が増やす負荷

InternVL2の画像処理は、元画像を動的に複数のサブ画像へ切り出し、全体縮小画像を追加する。各タイルを448画素へ揃えてViTへ通し、パッチ埋め込みとCLS表現を生成する。視覚言語投影器でパッチをLLMの埋め込み空間へ写像し、テキストの指示トークンと結合する。画像タイルを増やすと視覚エンコーダ処理だけでなく、LLMが参照するトークン列とKV状態も増える。

従来の学習不要な剪定は、ViTのCLS注意だけで重要な画像トークンを選ぶか、LLMのテキスト→画像注意だけを見て剪定する場合が多い。前者は画像として目立つ領域を優先できるが、質問が小さな看板の文字を尋ねる場合など、目立たないが必要なパッチを落とし得る。後者は質問への関連性を捉えられる一方、初期層の注意が十分に安定していない場合や、画像全体の構造を保ちたい場合に弱い。

PTPは画像の大域構造、局所パッチ、テキストの要求を別々に評価して統合する。対象は高解像度画像を多数の視覚トークンへ展開するVLMであり、テキスト専用LLMのKVキャッシュを無条件に圧縮する方式ではない。また視覚エンコーダ自体の入力タイル数を減らす設計ではなく、**エンコード後、LLMが受け取るトークンを減らす**ことが主眼である。

## 手法

### 1. 領域CLSと全体CLSの類似度でトークン予算を配る

画像をm×n個の局所タイルへ分割し、別に全体縮小画像を用意する。局所タイルiのCLSベクトルをcls_i、全体画像のCLSをcls_gとする。領域重要度は `a_i=cos(cls_i,cls_g)` として計算する。全体画像と意味的に整合するタイルへ高いスコアを与え、softmaxでタイル間の配分比率を作る。

全視覚トークン数をT、削除率をrとすると、原著の式(2)は `R_i=(1-r)×T×softmax(a_i)` でタイルiの保持予算を定義する。すべてのタイルへ同じ割合でトークンを残すのではなく、全体の意味に寄与するタイルへ多く配る。局所的に重要なタイルでも、内部のパッチすべてが必要とは限らないため、予算R_iを次段階のトークン順位付けへ渡す。

この方法はタイルごとにCLSを得る必要があるため、視覚エンコーダを丸ごと省略できない。さらに全体画像との類似度は、質問にとって重要だが画像全体では小さい物体を低く評価する可能性がある。その欠点を次のパッチ単位・指示文単位の情報で補う設計である。

### 2. ViTのCLS→パッチ注意で局所トークンを評価する

タイルiのパッチjについて、視覚エンコーダの層LにおけるCLSからパッチへの注意係数を `b_j^(i)=Attn_CLS→patch^(L)(j)` と定義する。CLSが強く参照するパッチはタイルの視覚表現に寄与する可能性が高いという仮説に基づき、パッチを順位付けする。

このbはタイルごとに独立に計算され、画像全体のCLS類似度aとは役割が異なる。aは「どのタイルに予算を多く配るか」、bは「そのタイル内のどのパッチを優先するか」を決める。実験ではViTの中間層から取る注意が安定し、原著Table IIの複数課題では層8が強い結果を示す。浅い層の方がOCRに有利な課題もあるため、どの層が最適かは一律ではない。

### 3. LLM第2層の指示文→画像注意を追加する

視覚埋め込みをLLMの空間へ投影し、質問・指示文トークンと連結してLLMの初期層へ通す。原著は第2 Transformer blockにおいて、各指示文トークンqから画像パッチjへ向かう注意を取得する。パッチjの指示関連度は `c_j=max_(q∈Q) Attn_(q→j)` と定義する。指示文のどれか一つの語が強く注目したパッチを、他の語の平均で埋もれさせないため最大値を取る。

このcは「画像として目立つか」ではなく「今の質問に関係するか」を表す。たとえば背景の大きな建物が視覚的に目立っても、質問が隅の小さな文字についてなら、文字パッチのcが高くなり得る。ただし注意の大きさは正解への因果寄与を直接保証するものではない。第2層の注意を得るために初期のLLM演算が必要であり、PTPの前処理費用はゼロではない。

### 4. 三つのスコアを統合して残すパッチを決める

領域スコアa、視覚パッチスコアb、指示関連度cを[0,1]へ正規化する。各タイルの保持予算はaから決め、タイル内のパッチ順位は `s_j=αc_j+(1-α)b_j^(i)` で計算する。α=0なら視覚的顕著性のみ、α=1なら指示文の注意のみ、α=0.5なら両者を等しく重視する。各タイルでs上位R_i個を残し、全体縮小画像についても同様に保持予算R_gに従って選ぶ。

処理の流れは、(1)タイル分割と視覚エンコード、(2)全体CLSとの比較で予算配分、(3)ViT注意からbを抽出、(4)LLM初期層でcを抽出、(5)bとcを融合して各タイルの上位パッチを残す、(6)短縮された画像トークン列を使ってLLMの後続計算を行う、である。既存重みを更新しないため学習不要だが、視覚エンコーダの注意とLLM早期層の注意を取り出せる実装が必要である。

αを大きくすると質問の意味へ寄せられるが、OCRやグラフの小さなラベルを読む課題では視覚的な局所手掛かりを捨てることがある。逆にαが小さすぎると指示文に必要な領域を落とし得る。原著は固定α=0.5を汎用初期値とし、課題ごとに動的に変える手法は今後の課題としている。

## 評価条件と結果

### 実験環境・比較対象

| 項目 | 原著の設定 |
|---|---|
| モデル | InternVL2-2B（InternViT-300M-448px + InternLM2-1.8B）、InternVL2-8B（同ViT + InternLM2.5-7B-Chat） |
| GPU | NVIDIA L20、48GB、単一GPU |
| 画像 | 高解像度画像を局所タイルと全体縮小画像へ分割、各タイル448画素 |
| 課題 | AI2D、SQA-I、VizWiz、GQA、TextVQA、ChartQA、MME、MMBench、MM-Vet、MM-Star、SEED、POPE、RealWorldQAの13件 |
| 比較 | 無剪定、ランダム、空間一様、VTW、PDrop、FastV、GSearch等 |
| 主要設定 | 視覚トークンを50%残す条件、α=0.5 |
| 指標 | 各課題の正答率・固有スコア、13課題の相対平均、GPUメモリ、KV容量、処理時間、演算量 |

13課題には正答率以外の独自尺度（MME等）も含まれるため、原著のAvg. Acc.は無剪定の各課題スコアを100%に正規化して集約した相対品質である。99.8%を個々のタスクの絶対正答率と解釈しない。また平均がほぼ100%でも、ある課題では品質が下がる。

50%保持時はKV容量がちょうど半減するが、GPU全体メモリは24.6→20.9GBで約15%の削減にとどまる。画像エンコーダの重み、LLMの重み、作業領域などは削減対象外だからである。演算量は6.40→3.04 TFLOPsで約52.5%減、1トークン遅延は34.2→19.7msで約42.4%減であり、画像トークン50%削減が総メモリ・遅延50%削減を保証するわけではない。

**原著には単位・数値の不整合がある。** Table Vの総時間列は「Total Time (s)」と表示される一方、本文§IV-Dは325.7→187.4をmsと記す。ここでは表の数値を保持し、単位は確定しない。また結論§Vには「FLOPsを32.2%削減」とあるが、Table Vの6.40→3.04は52.5%減であり、測定範囲の差が明示されていない限り単一の値に統合しない。

### アブレーション：三要素が必要か

原著Table IVでは、PTP全体を基準に、領域予算配分を外すと平均低下1.71%、さらに視覚パッチスコアbを外すと2.45%、領域配分と指示スコアcを外すと4.25%、ランダム剪定では7.27%の低下と表記される。本文には一部1.65%・2.33%と異なる説明があり、ここでは表の値を優先し、表と文章の差を留保する。

この結果は、領域だけでも、視覚パッチだけでも、指示文だけでも完全なPTPと同じ品質にはならないことを示す。ただし各除去条件で残る機構の組合せが違うため、低下率を単純に足して「各機構の独立寄与率」とすることはできない。注意重みが真の因果重要度を測っているかの直接検証でもない。

### αとViT層の感度

Table IIIでは、OCR系のTextVQA/ChartQAはα=0.2付近がα=0.5より良い場合がある。たとえばChartQAはα=0.2で70.9、α=0.5で70.7、α=1.0で65.6である。一方、RealWorldQAはα=0.5で57.5、α=0.9で58.1となり、指示文の比重を高める利点がある。α=0.5は全タスクの絶対最適値ではなく、汎用の折衷設定である。

ViTの層選択でも中間層8が多くの課題で良好だが、浅い層はOCRなど細部を扱う課題、深い層は場面理解に有利な傾向がある。固定層の選択はモデル・課題分布が変われば再評価が必要であり、どのモデルでも層8が最適と一般化しない。

## 既存研究との差・実装上の意味

PruMergeやFasterVLMは主に視覚エンコーダのCLS注意でトークンを選ぶため、質問文との関連性を直接利用しない。FastVやSparseVLMはLLM内のテキスト→画像注意を使うが、画像タイル全体の重要度や視覚エンコーダの局所手掛かりを十分に利用しない。PTPは**領域ごとの保持枠をまず割り当て、その枠の中で視覚と質問の二種類の重要度を融合する**点が異なる。

PTPは既存の高解像度VLMへ学習なしで追加できることを目指すが、CLSトークンと注意係数を公開するViT、指示文→画像の注意を取得できるLLM、選択後のトークン配置に対応する推論実装が前提となる。FlashAttention等で注意行列を明示的に保存しない実装では、スコア取得のための追加処理が必要になり得る。原著はInternVL2系列の実験であり、任意のVLMへ設定変更だけで適用できることを証明していない。

KVキャッシュ削減の観点では、画像トークンをLLMへ渡す前に減らせるため、画像prefixを含む要求のKV容量が小さくなる。これは一般の長文脈テキストでのKV evictionとは異なり、削除した画像トークンの情報を生成途中で再取得する方式ではない。誤って削除した画像情報は後段のdecodeでは取り戻せず、質問が変わる場合は再選択が必要になる可能性がある。

## 限界・負の結果・未検証事項

第一に、視覚エンコーダは全タイルを処理してCLS・patch注意を生成する。したがって、画像の切出し・ViT推論の費用は基本的に残る。画像エンコーダが支配的な端末では、LLM側のトークン削減が総遅延に占める利得は小さくなり得る。Table VのGPUメモリ削減が画像トークン削減率より小さいことも、重みと前処理の固定費を示す。

第二に、評価はInternVL2-2B/8Bと単一L20 48GB、13の画像質問応答・理解課題が中心である。動画の時系列整合、音声、極端な画像解像度、複数画像間の参照、長時間のマルチターン会話、モデル並列や連続バッチでの実測は主結果として示されていない。画像トークンを減らすことと、実サービスのP99応答時間・スループット改善を同一視しない。

第三に、指示文への注意cは初期層の一時的な注意であり、回答の正しさへの因果寄与を保証しない。誤誘導的な指示文やOCRでは、視覚的に重要なパッチが低く評価される可能性がある。原著自身もPOPEでは視覚スコアの方が信頼できる場合を示し、αを課題に応じて変える方針を今後の課題としている。

第四に、相対平均品質99.7～99.8%は全タスクが不変という意味ではない。ChartQA、TextVQA、SEED等で小幅な低下があり、画像中の希少な文字や小物体の見落としを重視する用途では平均だけでは安全性を判断できない。領域配分のsoftmaxは全体画像との類似度に依存するため、全体で目立たないが質問に必須の領域へ十分な予算が割り当てられないリスクがある。

第五に、原著の表・本文で総時間単位、FLOPs削減率、アブレーションの平均低下率に不整合がある。検証・引用では数値の出所をTable V、§IV-D、§V、Table IVと明記し、異なる測定境界の数字を勝手に整合させない。公開実装URLも今回確認した一次本文では明記されていないため、コード公開済みとは断定しない。
