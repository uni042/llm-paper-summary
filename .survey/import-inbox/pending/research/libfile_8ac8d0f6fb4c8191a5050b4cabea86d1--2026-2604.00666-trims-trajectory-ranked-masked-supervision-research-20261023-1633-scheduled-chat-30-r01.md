# TRIMS：拡散言語モデルに「難しいトークンから確定する順序」を教える軽量追加学習

## 概要

TRIMS（Trajectory-Ranked Instruction Masked Supervision）は、マスク拡散言語モデル（Masked Diffusion Language Model; MDLM）の反復生成で、**どのトークンを先に確定するか**を学習中から誘導する方式である。通常のマスク拡散学習はトークン位置を無作為にマスクして復元するため、推論時の効率的な確定順序を直接教えない。生成時には確信度の高い位置だけを小刻みに確定し、せっかくの並列生成能力を使い切れないことがある。

TRIMSは自己回帰（Autoregressive; AR）教師モデルが正解トークンへ割り当てた確率から難易度を計算し、難しいトークンを先に確定する順序を訓練マスクで模擬する。高価な拡散モデルの軌跡サンプリングや別の蒸留用データセットを大量に生成する必要がない。LLaDA-InstructとDream-Instructを対象に、数学・プログラミング課題で正答率と1ステップ当たり予測トークン数の交換条件を改善した。

**重要な測定上の区別：** 論文で用いるTPSは *Tokens Predicted per Step*、すなわち「推論の1反復で予測できたトークン数」である。通常の推論基盤で使う *Tokens per Second*（1秒当たりトークン数）ではない。TPSが3倍になっても、実際の壁時計時間の生成速度が3倍になったと結論づけることはできない。

## 問題設定：学習時の無作為マスクと生成軌跡の不一致

自己回帰言語モデルは左から右へトークンを1つずつ生成する。対してマスク拡散モデルは、出力の複数位置を[MASK]として持ち、各反復で未確定位置を同時に予測・確定できる。潜在的には並列生成で必要反復数を減らせるが、すべての位置が同じ難しさではない。先に確定したトークンが残りの位置の予測に有益なら、その後の反復で多数のトークンをまとめて確定できる。

標準MDLMの学習では、マスク位置を一様に無作為抽出し、マスク位置の負の対数尤度を最小化する。この学習は各位置の復元確率を高めるが、生成過程の順序を直接監督しない。推論時に難しい位置を後回しにすると、周囲の予測が確定しないまま反復回数が増え、並列化の利点が縮小する。

過去の軌跡最適化には、拡散モデル自身を多数回実行して良い生成順序を採集する蒸留（Distillation）がある。しかし拡散モデルのサンプリングは多数の全系列推論を要し、教師データ作成のGPU費用が大きい。TRIMSは自己回帰教師の一度の教師強制（Teacher Forcing）評価で位置別難易度を得ることで、軌跡監督の取得費用を抑える。

## 手法：難易度からマスク学習へ

### 1. 自己回帰教師によるトークン難易度

訓練例の入力xと正解出力y=(y_1,...,y_L)に対し、自己回帰教師モデルに正解の過去トークンを与え、各位置の正解確率 p_T(y_i | x,y_<i) を計算する。難易度は s_i = -log p_T(y_i | x,y_<i) と定義する。値が大きいほど教師がその正解を予測しにくい位置である。実験ではQwen3-8Bを教師に使い、1,000件規模のs1Kデータセットへ難易度を付与した。

これは拡散モデル自身の「本当に先に確定したほうが良い位置」を直接観測したものではない。あくまで自己回帰教師の条件付き確率を代替信号として利用している。教師の予測分布やトークナイザ、対象課題が変われば難易度の妥当性も変わり得る。

### 2. 難易度の分位バケット化

生の難易度スコアをそのまま使うのではなく、全正解トークンの難易度分布を分位点でK個のほぼ同数のバケット（Bucket）へ分ける。高難度トークンには小さいバケット番号、低難度トークンには大きい番号を付与する。分位点を使うことで教師の負対数尤度の絶対スケールに依存しにくく、各段階におおむね同じ数の位置を割り当てられる。

アブレーションではK=4、8、16を比較し、K=8が最も良好だった。少なすぎると異なる難度のトークンを同じ段階へ混ぜ、多すぎると段階が細かすぎて学習しにくくなるという解釈が示されている。ただし差は大きくなく、あらゆるデータで8が最適という普遍則ではない。

### 3. 難しい位置を先に確定した状態のマスク生成

訓練時にバケット境界kをランダムに選ぶ。b_i<=kの高難度側は「すでに確定済みの文脈」とみなし、b_i>kの低難度側は「これから予測する未来」とみなす。前者はマスク確率 p_context=0.05、後者は p_future=0.95 とする。つまり難しいトークンの大部分を見せ、簡単なトークンの大部分を隠した訓練入力を作る。

これにより、拡散モデルは難しい位置が確定した後の文脈から、残りの多数の位置をまとめて復元する練習をする。難しい位置が先に決まれば他の位置の不確実性が下がるという仮説に基づく。注意点として、この方式は推論時にトークンを強制的に難易度順へ並べ替える後処理ではない。**学習で好ましい軌跡を誘導し、推論時には既存の確信度に基づく選択を使う**。

### 4. 標準MDLM学習との混合

軌跡に基づく特殊マスクを全訓練例へ適用すると、元のマスク拡散事前学習と分布がずれる可能性がある。そのため、特殊マスクを使うのは訓練データの10%だけで、残り90%は標準の無作為マスクを使う。損失関数は標準MDLMの証拠下界（Evidence Lower Bound; ELBO）由来のものを維持する。新しい推論器や複雑な強化学習ループではなく、マスク生成部分の変更が中心である。

### 5. 学習と推論の分離

論文はdLLMコード基盤上でLLaDA-InstructとDream-InstructをLoRA（Low-Rank Adaptation）追加学習した。推論時の選択にはFast-dLLMの確信度に基づくサンプリングを使う。したがって、TRIMSの評価値は「モデルを追加学習したこと」と「既存の確信度サンプリングを用いたこと」の組合せであり、推論側の新しい専用カーネルによる速度改善を示すものではない。

## 実験条件と比較対象

| 観点 | 条件 |
|---|---|
| 対象モデル | LLaDA-Instruct、Dream-Instruct |
| 教師モデル | Qwen3-8B（自己回帰教師） |
| 学習データ | s1K、約1,000例 |
| 追加学習 | 30エポック、系列長1,024、LoRAランク32、α=32 |
| 学習環境 | NVIDIA A100 80GB ×8、DeepSpeed ZeRO-2 |
| 課題 | GSM8K、MATH、MBPP、HumanEval |
| 比較対象 | 元モデル、Fast-dLLM、Fast-dLLM-v2、D2F、dParallel、d3LLM |
| 主指標 | 正答率、TPS（1反復当たり予測トークン数） |

比較方式は学習・蒸留データ量が異なる。特にdParallelとd3LLMは大量の拡散モデルサンプリングで蒸留データを作るため、同じ訓練データ予算の厳密な比較ではない。著者らは品質・並列度に加えて教師データ準備費用も比較している。

## 主要結果：LLaDA-Instruct

一次論文Table 1の代表値を示す。各セルは「正答率 / TPS」。TPSは大きいほど1反復で多くのトークンを確定できることを示すが、実測秒当たり速度ではない。

| 方式 | GSM8K | MATH | MBPP | HumanEval |
|---|---:|---:|---:|---:|
| 元のLLaDA | 72.6 / 1.00 | 32.2 / 1.00 | 41.7 / 1.00 | 38.3 / 1.00 |
| Fast-dLLM | 74.7 / 2.77 | 30.8 / 1.97 | 38.6 / 2.13 | 37.8 / 2.56 |
| dParallel | 72.6 / 5.14 | 30.2 / 3.17 | 40.0 / 2.35 | 39.0 / 4.93 |
| d3LLM | 73.1 / 9.11 | 30.4 / 5.74 | 40.6 / 4.21 | 39.6 / 5.95 |
| **TRIMS** | **74.9 / 6.26** | **34.3 / 4.72** | **41.8 / 2.81** | **37.2 / 3.98** |

GSM8KではTRIMSの正答率74.9が元モデル72.6より高く、TPS6.26もFast-dLLMの2.77を上回る。MATHでも正答率34.3とTPS4.72の組合せは良好である。一方、HumanEvalの正答率37.2は元モデル38.3やd3LLM39.6を下回り、TPS3.98もd3LLM5.95を下回る。**すべての課題で精度と並列度を同時に最大化したわけではない**。

d3LLMはGSM8KでTPS9.11、MATHで5.74とTRIMSを上回るが、後述の蒸留データ準備費用が大きい。したがってTRIMSの価値は最高TPSの記録というより、少ない追加学習資源で良い精度・並列度の点を得られることにある。

## 主要結果：Dream-Instruct

一次論文Table 2の代表値を示す。

| 方式 | GSM8K | MATH | MBPP | HumanEval |
|---|---:|---:|---:|---:|
| 元のDream | 83.9 / 1.00 | 39.6 / 1.00 | 57.2 / 1.00 | 55.2 / 1.00 |
| Fast-dLLM | 79.0 / 1.44 | 38.3 / 1.78 | 53.2 / 1.20 | 54.3 / 1.33 |
| Fast-dLLM-v2 | 77.5 / 2.21 | 48.7 / 2.61 | 50.1 / 2.04 | 61.7 / 2.58 |
| d3LLM | 81.4 / 4.94 | 38.2 / 3.92 | 55.6 / 2.96 | 57.1 / 3.20 |
| **TRIMS** | **80.3 / 4.11** | **42.6 / 2.54** | **56.6 / 6.31** | **57.3 / 2.21** |

MBPPではTRIMSのTPS6.31がFast-dLLMの1.20やFast-dLLM-v2の2.04を大きく上回り、正答率56.6も両方式より高い。ただし元のDreamの正答率57.2よりわずかに低い。GSM8Kでは元のDreamが83.9、TRIMSが80.3であり、並列度向上と引き換えに正答率を失っている。MATHではFast-dLLM-v2が正答率48.7でTRIMSの42.6より高い。したがってDreamでも「TRIMSが常に最高精度」とは言えない。

論文の「最大3倍の並列性向上」は比較対象や課題を限定した表現であり、MBPPの元モデルTPS1.00から6.31への比率を実時間の6.31倍高速化と解釈してはならない。反復回数が減っても、1反復の計算負荷やGPUのバッチ条件が変われば秒当たり処理量は異なる。

## 教師データ準備と追加学習の費用

一次論文Table 3は、教師データ準備のGPU時間をTRIMS 0.6 A100 GPU時間、dParallel/d3LLM 287 A100 GPU時間×対象モデル数と報告する。訓練データはTRIMS約1,000件、蒸留方式約93,000件である。TRIMSは自己回帰教師の教師強制1回で難易度を付与できるため、反復的な拡散サンプリングで軌跡を集める方式より準備費用が小さい。

ただし**0.6 GPU時間は主にデータ準備の費用**であり、TRIMSの追加学習全体が0.6 GPU時間で終わる意味ではない。本文では追加学習に8基のA100で約3時間を要すると説明している。計算資源の比較では「教師データ準備」「対象モデルのLoRA学習」「実際の推論実行」の三つを別々に扱う必要がある。また、蒸留方式は学習データ量も異なるため、全費用を単一の倍率で公平比較したものではない。

## アブレーションと設計上の発見

論文のアブレーションでは、難しいトークンを先に確定する順序（Hard-to-Easy）が、簡単なトークンから確定する順序や無作為な順序より多くの課題で良好だった。ただし無作為なバケット順序でも標準MDLM学習より改善する場合があり、効果のすべてを「難易度の正確な順位」に帰属させることはできない。**軌跡段階を模擬したマスク構造そのものにも効果がある**。

難易度バケット数4/8/16の比較では8が最良で、差は比較的小さい。難易度指標として負対数尤度とエントロピーを比べると、数学課題では同程度、プログラミング課題では負対数尤度が有利だった。これらは教師モデルの予測の不確実性をどう解釈するかが生成軌跡に影響することを示すが、他の教師やモデル規模への一般化には追加検証が必要である。

## 既存研究との差

Fast-dLLMなどの推論時最適化は、学習済みモデルの確信度やマスク確定規則を変更する。TRIMSは推論器を主に変更するのではなく、追加学習でモデルが望ましい確定順序を身につけるよう誘導する。推論時の選択規則と学習時の表現を整合させる方向の研究である。

D2F、dParallel、d3LLMなどは軌跡の改善を狙う点では近いが、特に蒸留系は拡散モデルの生成軌跡を多数収集する費用がかかる。TRIMSは自己回帰教師の正解確率を代替信号として使うため、データ準備を軽量化できる。一方、最高TPSでは蒸留方式に劣る課題があるため、**学習費用と並列度の交換条件を改善する提案**として評価すべきである。

## 限界と推論基盤への適用判断

第一に、評価対象はLLaDA-InstructとDream-Instructの二系統であり、任意の拡散言語モデルで同じ効果が出る保証はない。第二に、数学・プログラミング課題の比較であり、一般会話、長文文書、複数ターン対話や大量同時要求下の品質・速度は主要評価ではない。第三に、自己回帰教師の難易度は拡散モデルの最適な生成順序の厳密な教師信号ではなく、モデル間の不一致があり得る。

第四に、TPSは1反復で確定するトークン数であり、GPU実測トークン/秒、初回トークン遅延、終端間応答時間ではない。第五に、追加学習が必要なので、既存のモデルを単に新しい推論エンジンで起動するだけではTRIMSの効果を得られない。第六に、元モデルの正答率を下回る課題もあるため、対象タスクの許容品質を先に定めて並列度を比較する必要がある。

ローカルLLMの運用観点では、TRIMSはCUDAカーネルやKVキャッシュの最適化というより**拡散モデルの追加学習と生成順序の最適化**に位置付けられる。通常の自己回帰モデルの推論高速化には直接適用できない。推論基盤での効果を主張するには、同一GPU・同一バッチ・同一生成長での実時間計測を別途行う必要がある。
