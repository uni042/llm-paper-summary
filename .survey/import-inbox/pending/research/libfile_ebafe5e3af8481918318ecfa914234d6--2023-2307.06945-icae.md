# In-context Autoencoder for Context Compression in a Large Language Model

## 概要
In-context Autoencoder（ICAE）は長いcontextをtoken列のままLLMへ入れず、短い連続埋め込み列「memory slots」へ変換し、対象LLMが直接条件として読む方式である。圧縮器は対象LLMを基礎にLoRA等の少量parameterを学習し、対象LLM本体は固定する。事前学習では元context再構成と続き予測を同時に学び、instruction fine-tuningで質問等に応じslotから回答できるようにする。

Llama-7Bで512 token→128 slotsの4倍圧縮時、text continuation PPLは9.01→9.50。1×A100 80GB、batch 8、input 2048、output 128では通常24.0秒に対し、圧縮3.4秒+decode 3.9秒=7.3秒（3.3×）。圧縮済みslotを再利用できる固定文書では圧縮時間もcacheできる。

## 問題設定
長contextはprefill計算とKV cacheを増やしcontext windowも消費する。自然言語要約は短縮時に細部を失いやすい。ICAEは人間可読な短文ではなくLLM内部embedding空間へ圧縮し、対象LLMが必要情報を利用できる表現を学ぶ。ただし圧縮率を上げれば損失は増え、k=128では500 token程度まで再構成BLEU 95%以上だがk=64/32では急速に悪化する。

## 手法
context末尾にk個の特殊memory tokenを追加してICAE encoderへ通し、その最終hidden statesを圧縮表現として取り出す。encoderは対象LLMを基礎にLoRAで適応し、約1%の追加parameterを学習する。k個の連続ベクトルは通常token embeddingと同じ入力空間へ入り、凍結decoder LLMが条件として使う。

Autoencoding objectiveはslotsだけから元contextを再構成し細部保持を促す。Language-modeling objectiveはslotsから続きを予測し将来予測に必要な意味を保持させる。両lossの混合λは0.4〜0.6付近が良好。さらにprompt-with-context instruction dataで「圧縮context + query → response」を適応する。

## 主要結果
batch 8×input 2048は24.0→7.3秒（3.3×）、8×512は9.3→4.3秒（2.2×）、32×512は24.3→6.8秒（3.6×）。512→128のPPLはLlama-7B 9.01→9.50、Llama-2-13B 8.15→8.45で、強い対象LLMほど劣化が小さい傾向。頻出contextでslotを事前cacheできる場合、profiling上7倍超の可能性を示す。

## 既存研究との差
自然言語要約/token pruningと異なりLLMが直接消費する連続memory embeddingへ圧縮する。context window拡張とも直交し、windowを伸ばすのでなく入力表現を短くする。soft promptに似るが、固定task promptではなく各context内容を動的符号化する。

## 限界
4倍を超える圧縮では再構成品質が急速に悪化する。速度評価はLlama-7B系と単一A100中心で現代のcontinuous batchingサーバ評価ではない。圧縮器実行時間が必要なので一度しか使わない短contextでは利得が縮む。training-freeではない。
