# Scaling Attention Beyond GPUs for LLM Inference

## 概要
長文脈推論ではキー・バリュー（KV）キャッシュが文脈長と同時要求数に比例して増え、GPUの高帯域メモリ（HBM）を超える。単純なCPUオフロードは、attentionのたびに必要KVをPCIe経由でGPUへ戻すため、GPU演算器よりCPU–GPUリンクが律速になる。Beyondは「CPU DRAMを低速な退避先」とみなさず、CPU側の計算能力とメモリ帯域もattention処理へ参加させる。

## 問題設定
既存のKV offloadはCPUへ置いたKVを選択的にGPUへ再転送するが、転送量を減らすための疎化は品質低下を招き得る。一方、全KVを戻せばPCIe帯域を使い切る。Beyondの狙いは、recent tokenの局所情報をGPU上の密注意で確実に保持しつつ、古い文脈のうち重要部分だけをCPU上で直接処理し、PCIeを通るデータをattention出力など小さい中間値へ縮めることである。

## 手法
Beyondは連続decode中にKVのsalienceを追跡し、recent KVをGPU HBMへ、長期文脈のsalient KVをCPU DRAMへ配置する。GPU側はrecent KVに対して通常のdense attentionを実行する。CPU側はheadごとに選ばれたsalient KVへsparse attentionを並列実行し、CPUのDRAM帯域とvector computeを利用する。

二つのattentionは独立なsoftmax正規化を持つため、単純加算ではfull attentionと整合しない。Beyondは各部分のlog-sum-exp統計を使ってGPU側とCPU側の出力を再正規化して融合する。これによりCPU側KV本体をGPUへ移動せず、両memory tierの帯域を同時利用する。KV選択はhead単位で行われ、全headへ同一の疎集合を強制する方式より文脈依存性を残す。

## 評価条件
|項目|条件|
|---|---|
|対象|長文脈・multi-user LLM inference|
|構成|commodity GPU + CPU DRAM、PCIe接続|
|比較|GPU-only/full attention、KV offload/sparse-attention系baseline|
|主指標|対応文脈長、batch scalability、latency/throughput、accuracy|
|実装|recent dense GPU attention + salient sparse CPU attention|

## 主要結果
論文は、KVがGPU容量を超える領域でCPUとGPUのaggregate memory bandwidthを利用し、既存のsparse/offload baselineより長いsequenceと大きいbatchを処理できると報告する。重要なのはCPUを単なるstorageにせずattention実行主体にすることで、PCIe再読込を最小化しながらrecent部分はdenseのまま維持する点である。公開abstractは単一の普遍的speedup倍率を主張しておらず、条件別数値は本文表を参照すべきである。

## 既存研究との差
CPU offload方式は通常、GPU演算のためのデータ供給源としてCPUを使う。Beyondはattentionをmemory tierごとに分割し、CPU側でもattentionを計算して最後にsoftmax整合な融合を行う。このため「転送するKVを選ぶ」だけでなく「KVが存在する場所で計算する」設計へ変えている。

## 限界
CPU性能、DRAM帯域、PCIe世代、GPU HBM容量の比率で最適な分担は変わる。疎化された古い文脈だけをCPU側で見るため、salience選択が外れるworkloadではfull attentionとの差が増える可能性がある。GPU間NVLinkを使うmulti-GPU clusterやprefill/decode分離環境への一般化は、今回確認した一次資料では中心評価ではない。
