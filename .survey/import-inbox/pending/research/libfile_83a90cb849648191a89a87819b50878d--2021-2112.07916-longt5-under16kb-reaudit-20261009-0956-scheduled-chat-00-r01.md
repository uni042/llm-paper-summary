# LongT5：局所注意と一時的大域トークンで長文入力を扱うT5

> T5のエンコーダを長文向けに置き換え、各層でブロック集約した大域トークンを一時的に作る注意機構を提案する。重要文生成による事前学習と組み合わせ、要約・質問応答で長い入力の情報を利用する。論文の主な評価はモデル品質と学習時の計算費用であり、デコード専用の推論サービング実験とは区別する。

## 概要

標準的なT5のエンコーダは、入力のすべてのトークン対に注意を計算するため、入力長をlとすると自己注意の費用がO(l²)で増える。長文書の要約や長い証拠文書に基づく質問応答では、必要な情報が数千～数万トークンに分散する一方、入力長を伸ばすと学習時のメモリと処理時間が増えてモデル規模も伸ばしにくい。LongT5は、T5のエンコーダに局所注意と一時的大域注意（TGlobal）の2方式を導入し、長い入力とモデル規模の両方を拡大できるようにする。

局所注意は各トークンが左右127個までの近傍だけを参照するため、窓幅を固定すれば入力長に対して線形の注意計算になる。ただし遠く離れた位置の情報は複数層を経由しなければ伝わらない。TGlobalは入力を16トークンずつのブロックに分け、各ブロックの表現を集約した大域トークンを注意層ごとに一時生成する。通常トークンは局所近傍に加えてすべての大域トークンを見ることで、同じ層内に遠距離情報の通路を作る。

著者らは、PEGASUS由来の重要文生成による事前学習もT5へ取り込み、要約・質問応答で評価する。LongT5-XLの16K入力では、arXiv要約のROUGE-1/2/Lが48.35/21.92/44.27、PubMedが50.23/24.76/46.67、BigPatentが76.87/66.06/70.76となった。これらは品質指標であり、GPU推論の出力トークン当たり時間や初回トークン遅延を測定した値ではない。

## 問題設定と既存方式の限界

### 長文入力とモデル規模を同時に拡張しにくい

通常のエンコーダ自己注意では、各トークンが他の全トークンへ照合するため、入力長を2倍にすると注意行列の要素数は概ね4倍になる。T5はさまざまなテキスト変換タスクへ統一的に使えるが、入力を数万トークンへ伸ばす場合には計算とメモリの増大が制約になる。要約のarXiv文書は平均約10,720トークン、PubMedは約4,748トークン、BigPatentは約6,537トークンで、短い入力に切り詰めると後半の情報を直接参照できない。

ETCなどの長文Transformerは、近傍だけを見る局所注意と少数の大域表現を組み合わせて費用を下げる。ただしETCでは大域メモリとして扱う追加のサイド入力をタスクに合わせて設計する必要がある。標準T5の「入力テキストを渡せばテキストを返す」インターフェースへ、そのまま組み込みにくい。逆に単純な局所注意だけでは、離れた段落間の依存を一層で結べない。

LongT5が狙うのは、通常のT5形式や相対位置表現、複数事例の同一系列への詰め込みをなるべく維持しながら、**局所計算の節約と全文書を横断する情報経路を両立**することである。加えて、長文書の意味を学ぶ事前学習目的を変え、入力長を増やしただけでは得られない品質改善を目指す。

## 手法

### 1. 局所注意：固定窓で注意の二次増大を抑える

T5のエンコーダの全注意を、トークン位置tが左右r個以内の位置だけを参照する滑動窓へ置き換える。著者らの標準設定はr=127で、各トークンが参照する範囲は自身と左右の近傍に限られる。入力長lに対する注意計算の主要項はO(lr)であり、rを固定したままlを伸ばすなら線形に増える。全注意のO(l²)より長文での費用を抑えられる。

局所注意は新たな学習パラメータを必要としない。異なる短い事例を同一の長い系列へ詰め込む場合は、事例の境界をまたいで注意しないようマスクを設定できる。一方、ある文頭のトークンが文末のトークンへ直接注意できないため、遠距離の情報は層を重ねて段階的に伝えるしかない。論文のNQ評価では、長い入力を処理できても局所注意だけではTGlobalほどの品質を得られない。

### 2. 一時的大域注意：追加サイド入力なしで遠距離経路を作る

TGlobalでは、入力系列をkトークンずつの連続ブロックへ区切る。各ブロックの埋め込み表現を合計して正規化し、ブロックにつき1個の大域トークンを作る。論文の設定はk=16である。通常の各入力トークンは、左右r個の局所トークンに加えて、入力の全ブロックから作った大域トークンへ注意する。これにより遠くのブロックの情報を一層で集約できる。

大域トークンはETCのように利用者が与える特別な入力ではない。各注意演算で、その層の現在の隠れ表現から動的に構築し、演算が終わると破棄するため「一時的」である。層が変わればその層の表現に応じて再び集約する。ブロックごとの平均化は局所の細部を失う可能性があるが、局所注意経路が元トークンの近傍情報を補う構成になっている。

通常トークンから大域トークンへ向かう注意には、通常のT5に加えてブロック間距離の相対位置バイアスを使う。また大域トークンの正規化用パラメータを導入する。追加パラメータは基礎モデル約1万、大規模モデル約2.5万、XL約5万であり、モデル全体の数億～数十億パラメータと比べて小さい。T5のチェックポイントや複数事例詰め込みを維持し、詰め込み時は別事例の大域トークンを見ないようにマスクする。

局所窓の注意はO(lr)、入力トークンl個が大域トークン約l/k個を見る費用はO(l²/k)なので、TGlobal全体の注意費用は**O(l(r+l/k))**となる。これは全注意より係数を大幅に削減できるが、kを固定するとl²/kの項は二次のままである。局所注意とTGlobalを同じ「厳密に線形の注意」と説明してはならない。入力が非常に長くなると大域トークン数も増え、費用が再び支配的になる。

### 3. 重要文生成による事前学習

標準T5の事前学習は連続する語句の一部を隠し、それを復元するスパン破損（span corruption）を使う。LongT5はPEGASUSの重要文生成（principal sentences generation; PSG）を採用する。文書の各文について、その文を除いた残りの文書とのROUGE-F1を計算して重要度を推定し、上位の文を入力から隠してまとめて生成させる。

重要文は、残りの文書と語句の重なりが多く、文書の主題を表しやすい文として選ばれる。学習時にそれらを再生成させることで、単純な語句復元より文書全体の意味を使わせる狙いがある。論文では文を選ぶ際に同じn-gramの重複を一度だけ数える方式を採用する。マスクする文の割合は0.2で、PEGASUSの元設定と同一ではない。

LongT5はC4を使って入力4096、出力910トークン、バッチ128、100万ステップで事前学習する。学習率はT5系の逆平方根スケジュールでウォームアップ1万ステップ、最適化器はAdafactorである。要約だけでなく質問応答にも効果があることを構成要素除去実験で確認している。ただしこれは学習アルゴリズム上の貢献であり、推論時の速度改善そのものではない。

### 4. 推論時の実行経路と本サーベイとの関係

LongT5はエンコーダ・デコーダ構成で、長い入力文書をエンコーダへ通し、その符号化結果を使って短い要約や回答をデコーダが生成する。提案注意機構は主に**エンコーダ側**に適用し、デコーダは標準T5を使う。従って、長文入力をエンコードする段階の注意計算・メモリ費用に直接関係する一方、自己回帰デコーダのKVキャッシュ管理、MoEの専門家転送、オンライン要求スケジューリングを改善する手法ではない。

実行時は、入力をトークン化し、各エンコーダ層で局所注意または局所＋大域注意を計算し、デコーダがエンコーダ表現を参照して出力を生成する。TGlobalの場合は各層で大域トークンを一時生成・利用・破棄するため、永続的な追加入力や独立した大域トークン系列の管理を利用者に要求しない。長文入力で計算を抑えるという点で推論機構への適用可能性は明確だが、論文の速度計測は主にTPUでの学習処理率である。

## 評価結果：品質と計算費用を分けて読む

### 要約：長い入力で優位だが全データで勝つわけではない

| データセット | 条件・比較対象 | ROUGE-1/2/L | 読み方 |
|---|---|---|---|
| arXiv | LongT5-XL、16K入力 | 48.35 / 21.92 / 44.27 | PRIMERの47.6 / 20.8 / 42.6を上回る |
| PubMed | LongT5-XL、16K入力 | 50.23 / 24.76 / 46.67 | BigBird-PEGASUS大規模の46.32 / 20.65 / 42.33を上回る |
| BigPatent | LongT5-XL、16K入力 | 76.87 / 66.06 / 70.76 | BigBird-PEGASUS大規模の60.64 / 42.46 / 50.01より高い |
| MediaSum | LongT5-XL、4K入力 | 36.15 / 19.66 / 32.80 | BART大規模の35.09 / 18.05 / 31.44を上回る |
| Multi-News | LongT5-XL、8K入力 | 48.17 / 19.43 / 24.94 | PRIMERの49.9 / 21.1 / 25.9には届かない |
| CNN/DailyMail | LongT5-XL、4K入力 | 43.94 / 21.40 / 41.28 | HAT-BARTの44.48 / 21.31 / 41.52と拮抗しR1・RLでは下回る |

ROUGEは参照要約と生成要約のn-gram重なりを測る品質指標であり、計算速度や応答遅延ではない。arXiv、PubMedのような長文書では16K入力で後半まで参照できることが品質改善へつながる。一方、ニュース記事群のMulti-NewsではPRIMERがニュース事象の文書群に特化した事前学習をしており、LongT5の入力長・モデル規模だけでは追い付かない。短めのCNN/DailyMailでも全指標での優位はない。

### 質問応答：大域経路と入力長の相互作用

Natural Questionsでは、TGlobal版LongT5-XLの8K入力でEM/F1が62.66/66.61となり、T5.1.1-XLの4K入力60.75/64.07を上回る。LongT5基礎モデルでは入力を512から12Kへ伸ばすと55.73/59.06から58.12/62.44へ改善した。ただし大規模モデルでは4Kの60.77/65.38から6Kの59.17/63.38へ下がる設定もあり、入力を伸ばせば単調に良くなるわけではない。

TriviaQAではTGlobal版LongT5-XLの16K入力がEM/F1 81.00/84.83を報告し、BigBird-ETCの80.86/84.5と競合する。基礎、大規模、XLと規模を上げた場合のEM/F1はそれぞれ74.67/78.9、78.38/82.45、81.00/84.83であり、長文脈だけでなくモデル規模も品質に寄与する。これはエンコーダ側の長文処理の実用性を示すが、推論速度を直接比較したものではない。

### 学習処理率とメモリの境界

著者らはNatural Questionsを使い、T5.1.1、LongT5局所注意、LongT5 TGlobalについて、入力512からメモリ不足に至るまで系列長を伸ばし、4×8 TPUv3スライス、バッチ128で学習時の毎秒系列数を測定した。図3では標準T5.1.1が長い入力でメモリ制約に到達する一方、LongT5の疎注意はさらに長い入力を処理できる。図4は系列/秒と短答F1を対応させ、局所注意は速度・入力長を伸ばせても品質でTGlobalに劣る場合があることを示す。

ここでの系列/秒は**学習処理率**である。図の数値をそのままGPU上のオンライン推論スループットやトークン生成速度と読み替えてはならない。論文の速度対品質の曲線には各条件一回だけの実験点があり、6K・8Kなどの一部の非単調な変化について著者らは実験ノイズの可能性を指摘している。多数回の繰返し測定による安定した推論遅延分布は報告されていない。

### 事前学習目的の構成要素除去

| 比較 | NQ EM/F1 | arXiv ROUGE-1/2/L | 解釈 |
|---|---|---|---|
| 重要文生成（PSG） | 62.21 / 66.94 | 44.95 / 18.74 / 40.99 | 基礎TGlobal、入力4096の検証集合 |
| スパン破損（SC） | 58.65 / 63.05 | 43.49 / 18.12 / 39.71 | PSGより低い |
| SC＋PSGの混合 | 59.74 / 64.54 | 44.85 / 18.79 / 40.90 | 単純併用はPSG単独を上回らない |

同じ基礎TGlobalモデル・入力4096で比較すると、PSGは要約だけでなく質問応答にも有効だった。混合目的は一部のROUGE-2ではわずかに上回るものの、NQと要約の大半の指標でPSG単独より弱い。よって「学習目的を増やせば品質が必ず上がる」という解釈はできない。

別の実験では、大規模T5.1.1で事前学習入力512に揃えたとき、arXivのROUGE-1/2/LはSCの44.59/18.34/40.65からPSGの45.78/18.94/41.53へ改善した。PubMedでも47.86/22.14/44.39から48.74/23.42/45.24へ上がる。しかしLongT5 TGlobalの16K入力ではarXiv 48.21/21.70/44.03、PubMed 50.12/24.78/46.56まで伸び、事前学習目的だけでなく**長い入力を処理できる注意構造**が最終品質に寄与することが分かる。

## 既存研究との差と推論基盤への接続

ETCはタスク側で大域メモリ入力を設計するが、LongT5のTGlobalは固定ブロックの集約によって大域トークンを注意層の内部で生成・破棄する。LongformerやBigBirdも長文脈の注意を疎化するが、LongT5はT5のエンコーダ・デコーダ形式、相対位置表現、事例詰め込み、既存チェックポイント互換性を重視し、さらにPEGASUS型の事前学習目的を組み合わせる。

本サーベイで注目すべきシステム上の貢献は、エンコーダの全注意を局所窓と一時的大域表現へ置き換え、長い入力の注意演算を減らす構造である。ただしLongT5はKVキャッシュをGPU・CPU・SSDへ移動するオフロード技術でも、オンライン要求を並べ替えるサービング技術でもない。推論の前処理段階における長文入力の計算削減へ適用できる一方、研究の主要な数値結果はモデル品質と学習費用に関するものである。

## 限界と未評価事項

1. **TGlobalは厳密な線形注意ではない。** 大域トークンがl/k個に増えるためO(l²/k)項が残る。局所注意だけより遠距離情報を伝えやすいが、入力がさらに長くなると二次項が無視できない。
2. **局所注意単独には品質の代償がある。** NQでは長い入力を処理できてもTGlobalや標準T5に比べてF1が弱い設定がある。計算削減と遠距離情報の保持は交換条件にある。
3. **主な速度実験はTPU学習時の系列/秒。** GPUのプリフィル遅延、オンライン要求処理量、デコーダのTPOT、KVキャッシュ容量、バッチング時のSLOを測定したものではない。学習処理率を推論速度へ転用しない。
4. **評価タスクとモデル形態が限定される。** 主に英語の長文要約・質問応答を扱うT5型エンコーダ・デコーダであり、現代のデコーダ専用MoEモデルや複数GPUの本番サービングへの効果は未検証である。
5. **長い入力が必ず品質改善するわけではない。** Multi-NewsではPRIMERに届かず、CNN/DailyMailでもHAT-BARTの一部指標を下回る。NQの大規模6K設定などにも非単調な結果がある。
6. **実験反復の少なさ。** 速度対品質の一部の点は単一実験で、著者自身がノイズを指摘する。確信区間付きの推論遅延比較としては扱えない。
7. **事前学習と注意機構の寄与を混同しない。** 重要文生成による品質改善は学習目的の効果であり、TGlobalによる演算削減とは別の機構である。両者の相互作用を一つの速度倍率へまとめることはできない。
