# Accelerating LLM Inference with Staged Speculative Decoding

## 書誌情報
- canonical identity: `arXiv:2308.04623`
- 著者: Benjamin Spector, Chris Ré
- 初回公開: 2023-08-08
- 一次資料: https://arxiv.org/abs/2308.04623

## 概要
小batchのLLM decodeでは、各stepで巨大なtarget model重みを読みながら1 token程度しか進まないため算術強度が低い。通常の投機的復号は小型draft modelで複数tokenを先読みし、target modelの1回のforwardでまとめて検証するが、draft生成自体は自己回帰であり、draftが弱いと受理token数も伸びない。

本論文は二つの変更を行う。第一に、単一の線形draft列だけでなく複数候補をtreeへ構成し、共有prefixを重複計算せずtarget modelで一括検証する。第二に、target←draftという一段だけでなく、draft model自身の生成をさらに小さいモデルでspeculateするstaged構成にする。これによりtarget呼出し回数とdraft生成費の両方を下げる。

## 問題設定
speculative decodingの利得は、1回の高価なtarget passで何token確定できるかと、その候補を作る費用の差で決まる。線形draftでは途中のtokenが外れると後続候補も使えず、target batch内に載せられる候補多様性が低い。一方で候補数を増やすためdraft modelを何度も走らせれば、今度はdraft側がcritical pathになる。

端末内・小batchではthroughput最大化よりsingle-batch latencyが重要であり、target modelの重みbandwidthが支配的になる。この条件に合わせて「1 target passあたりの有効候補」を増やすことが主眼である。

## 手法
### tree-structured speculative batch
draft候補を独立系列として並べるのではなく、共通prefixを共有するtreeにする。target側ではtree maskを用いて複数branchを同時評価し、実際のsampling pathに一致するbranchの受理prefixを採用する。共通nodeを一度だけ計算するため、同じbatch予算でより多くの候補を載せられる。

### staged speculation
中間draft modelも自己回帰生成するとlatencyが残るため、さらに小さいsecond-stage modelが中間draft向け候補を生成し、中間modelがまとめて検証する。その結果を最終targetへ渡す。各stageで同じ「安い予測→高価な検証」の原理を階層化する。

### lossless verification
最終tokenはtarget modelの確率分布に基づく受理・補正手順で確定する。draft modelは候補生成だけを担当し、target分布そのものを置換しないため、通常のspeculative decodingと同様に出力品質を保持する。

## 評価条件
| 項目 | 条件 |
|---|---|
| 主対象 | small-batch / on-device decode |
| target例 | GPT-2-L 762M |
| 比較 | autoregressive target、通常speculative decoding |
| 変更要素 | tree speculative batch、second speculative stage |
| 指標 | single-batch decoding latency、出力一致 |

## 主要結果
| 条件 | 結果 | 意味 |
|---|---:|---|
| GPT-2-L 762M | decode latency 3.16×高速 | tree＋二段階speculationの総合効果 |
| 出力 | 品質完全保持 | target分布を検証で保持 |
| tree化 | 1 batch当たり候補増加 | 共通prefix重複を削減 |
| 二段階化 | draft生成費削減 | draft model自体の逐次decodeを短縮 |

## 既存研究との差
標準speculative decodingは一つのdraft modelが線形token列を作る。Staged Speculative Decodingは候補形状をtreeへ拡張し、さらにdraft生成にもspeculative decodingを再帰的に適用する。後年のmulti-candidate/tree方式と共通する方向性を早期に示すが、主評価は小batch・端末内条件である。

## 限界
stageを増やすほどmodel管理とverification schedulingが複雑になる。draft精度が低い場合はtreeの多くがrejectされ、候補生成・検証overheadを回収できない。3.16倍はGPT-2-L 762Mを中心とする特定条件であり、現代の数十Bモデル、continuous batching、GPU server workloadへそのまま外挿できない。
