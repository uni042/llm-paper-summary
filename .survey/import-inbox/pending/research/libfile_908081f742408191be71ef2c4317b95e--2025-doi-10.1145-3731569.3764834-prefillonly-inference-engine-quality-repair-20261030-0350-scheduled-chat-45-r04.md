## 概要

一般的なLLMサービングは、入力のprefill後に任意長のテキストを逐次生成することを想定する。ところが推薦、信用審査、分類、データラベル付けのような用途では、長い入力を読んで最後に一つのラベルや判定トークンだけを出す場合がある。論文はこれをprefill-onlyワークロードと呼ぶ。出力が1トークンで確定するなら、通常の生成向けエンジンが行う全層KVキャッシュの長期保持や、未知の出力長を考慮したスケジューリングは過剰となる。

PrefillOnlyは、vLLMを基盤にこの特徴を利用する推論エンジンである。注意層以外の線形演算を小さなチャンクで実行し、注意層は入力全体を一回のforwardで処理するhybrid prefillingを導入する。これにより中間テンソルのピークメモリを減らし、同時に使い終えたKVを破棄できる。将来の別要求で再利用できる共通prefixだけは残し、要求固有のsuffixを破棄する。さらに要求ごとの処理時間をprefixキャッシュのヒット状況から再推定し、短い仕事を優先しつつ待ち時間補正で飢餓を防ぐ。

2基のL4、A100、H100を用いた推薦・信用審査の合成ワークロードで、平均とP99の遅延を悪化させず、比較対象より1.4〜4.0倍高いQPSを処理できると報告する。非並列方式と比べ最大入力長を最大5倍へ拡大する。一方、低QPSでNVLink接続が高速な場合は、2GPUテンソル並列の方が一要求の遅延を短くできる。対象は1トークン出力に限定され、通常の長文生成へそのまま適用する方式ではない。

## 問題設定と従来方式の限界

一般的なvLLMなどのエンジンは、次のトークン生成で過去の注意状態を再利用するため、各層の全トークンのK/Vを保持する。prefill-only要求では一回のforwardで判定を終えるため、途中層で使い終えたKVは同じ要求の将来の復号に使われない。理論上は層を処理するたびにKVを捨てられ、メモリ使用量を大きく減らせるはずである。

しかし実際には、KVを捨てるだけでは最大入力長がそれほど増えない。L4上のLlama-3.1-8Bでは、KVの保持をやめても最大入力長の改善は1.6倍にとどまる。原因は、線形層が作る大きな中間テンソルである。通常のchunked prefillなら中間テンソルは小さくなるが、複数のforwardに分割するため次のチャンクで過去トークンを参照する全層KVを保持しなければならず、KV破棄の利点と衝突する。

もう一つの問題はスケジューリングである。通常の生成では出力長が不明なので要求の完了時間（JCT）を正確に予測しにくい。prefill-onlyでは出力が1トークンに固定されるため、入力長とprefixキャッシュヒット数からJCTを予測できる。最短残り仕事優先（SRJF）を使えば平均待ち時間を減らせるが、prefixキャッシュの状態は先に実行した要求で変わるため、到着時に一度だけJCTを予測する方式では誤った順序を選ぶ。

## 手法

### 1. Hybrid prefilling：非注意層だけをチャンク化

PrefillOnlyは、注意層と非注意層を異なる粒度で処理する。線形射影やFFNなどの非注意演算は、各トークンの演算が独立なので、入力列を小さなチャンクに分けて順次処理しても同じ結果を得られる。これにより中間活性テンソルを一度に巨大な形で保持せずに済む。一方、注意層は入力全体を通常の形で処理し、同じ要求を複数のprefill forwardへ分割しない。

この組合せにより、チャンク化による中間テンソル削減と、各層で使い終えたKVの破棄を同時に実現する。通常のchunked prefillはチャンク間でKVを保持する必要があるが、hybrid prefillingは要求全体を一回のforwardとして扱うため、その制約がない。注意計算そのものを分割しないので、注意演算におけるチャンク間同期や再利用の費用も増やさない。

実装では、各チャンクの出力を後で結合する際に二重の出力バッファが生じないよう、計算グラフから出力形状を推定して最終出力領域を先に確保し、各チャンクの結果をその位置へ直接書き込む。入力と出力の形状が同じ場合は入力バッファを出力として再利用するin-place演算も使う。こうしたメモリ管理が、単純なチャンク化だけでは残る中間テンソルのピークを下げる。

### 2. Suffix KV cache discardingとprefix再利用

prefill-onlyでは要求が終わった後に、その要求固有のsuffix KVを保持する意味が小さい。一方、複数の要求が同じ長いprefixを共有する場合、そのprefix KVを残しておけば後続要求のprefillを短縮できる。すべてのKVを破棄するとprefix cachingの利点を失うため、PrefillOnlyは共通prefixのKVを優先して保持し、要求固有のsuffix KVだけを破棄する。

メモリが不足する場合はsuffixを破棄またはCPUへオフロードする設計が可能だが、論文の実装では簡単化のため破棄を採用する。vLLMのsliding-window attentionが提供するKV管理の抽象を利用するため、注意カーネル自体を全面的に作り直す必要はない。hybrid prefillingにより、後続チャンクでsuffix KVが必要になる状況を避けていることが、この設計を成立させる前提である。

### 3. JCTの予測と継続的な再校正

出力が1トークンと決まっているため、要求の処理時間は主に未キャッシュ入力トークン数で決まる。PrefillOnlyは入力長`n_input`とprefixキャッシュにヒットするトークン数`n_cached`を使い、`jct(n_input, n_cached)`を予測する。詳細な方法では最大入力長まで1000トークン単位でプロファイルし、線形回帰で処理時間を推定できる。実測では`n_input−n_cached`だけでも良い代理指標となり、A100上のQwen 32B FP8では実際のJCTとのPearson相関が0.987だったため、これを既定の予測に採用する。

待機要求のJCTは到着時に固定せず、要求を一つ実行するたびに残る待機要求について再計算する。先に実行した要求が新しいprefixキャッシュを作ると、そのprefixを共有する要求の未キャッシュ長が短くなり、優先度が上がる。こうしてキャッシュヒット可能な要求を早く処理することで、prefixが他の要求で追い出される前に再利用できる。

例えばAを実行するとDがAのprefixを再利用できる場合、静的なSRJFはCやBを先に選んでキャッシュを追い出すかもしれない。継続的な再校正はAの後にDのJCTが短くなったことを反映し、Dを優先できる。これは平均待ち時間の改善だけでなく、prefixキャッシュのヒット率を上げる効果も持つ。

### 4. 公平性と飢餓防止

短い要求を優先し続けると、長い要求が待ち続ける可能性がある。PrefillOnlyは予測JCTから`λ×待機時間`を差し引くことで、長く待った要求の優先度を徐々に高める。λを大きくするとP99などの悪い待ち時間を改善できるが、短い要求を優先する度合いが弱まり平均遅延が悪化する。

この調整は、単に最短要求だけを選ぶとP99が悪化し得る問題への対策である。システムの運用目標が平均レイテンシ重視か、長時間待つ要求の抑制重視かによってλを選ぶ必要がある。論文は公平性パラメータを変えた遅延CDFを示し、P99と平均のトレードオフを明示する。

### 5. 一要求ずつ実行するスケジューラ

一般的なLLMサービングでは、バッチングによって重みを多数要求で共有しデコード処理量を増やす。しかしprefill-onlyでは入力が長く、出力が一つだけなので、複数要求を大きくバッチ化すると長い入力に合わせた待ち時間やメモリ使用量が増える。PrefillOnlyは待機要求のJCTを更新し、最も適切な一要求を選んで実行する。複数GPUを利用する場合は、GPUごとに別エンジンを起動し、同一ユーザーを同じエンジンへルーティングしてprefix再利用を維持する。

GPU間のテンソル並列を使わずに長い入力を扱えることが、高QPS時の通信削減につながる。ただし一要求の遅延を最小化したい低QPS環境では、NVLinkで接続された2GPUのテンソル並列が有利な場合がある。PrefillOnlyはすべてのレイテンシ条件で並列化を否定するものではなく、高QPSと長入力を中心に効率を改善する方式である。

## 評価

### ワークロード・ハードウェア・比較対象

| 項目 | 条件 |
|---|---|
| 推薦ワークロード | ユーザー20人、履歴11k〜17kトークン、投稿150トークン、各人50候補、合計約14Mトークン |
| 信用審査ワークロード | ユーザー60人、信用履歴40k〜60kトークン、各人1要求、合計約3Mトークン |
| 到着過程 | Poisson到着、到着率を変えてQPSと遅延を測定 |
| 低価格GPU | NVIDIA L4 PCIe 24GB×2、Llama-3.1-8B |
| 中価格GPU | NVIDIA A100 PCIe 40GB×2、DeepSeek-R1-Distill-Qwen-32B FP8 |
| 高価格GPU | NVIDIA H100 PCIe 80GB×2、Llama-3.3-70B FP8 |
| 高速接続GPU | NVIDIA H100 NVLink 80GB×2、同70B FP8 |
| 比較 | vLLM PagedAttention、chunked prefill、2GPU tensor parallel、2GPU pipeline parallel |
| 指標 | 平均遅延、P99遅延、QPS、最大入力長（MIL）、prefixキャッシュの効果 |

ワークロードは実サービスから取得した要求ログではなく、長さ分布と到着過程を設定した合成データである。推薦では同一ユーザーの履歴prefixを50候補で共有し、prefixキャッシュの効果を強調する。信用審査では40k〜60kの長入力を扱い、単一GPUでの最大入力長の制約が主要な問題となる。両者の性能差は、この入力構造の違いによる。

### 主要な速度・容量結果

| 比較条件 | 報告値 | 解釈 |
|---|---|---|
| 同等の平均/P99遅延を保つQPS | 比較対象比1.4〜4.0倍 | 高負荷時の要求処理量 |
| 非並列基準比の最大入力長 | 最大5倍 | GPU間並列化を使わず長入力を処理 |
| L4、Llama-3.1-8BでKVだけ破棄 | MIL 1.6倍 | 中間テンソルが残り、効果が限定的 |
| A100、Qwen-2.5-32B FP8でhybrid prefilling | chunked prefill比MIL 8.7倍超 | 特定モデル・ハードウェアのアブレーション |
| 同条件のhybrid prefilling単体 | MIL 7.9倍 | 中間テンソルの削減とKV破棄の共同効果 |
| A100、Qwen32B FP8のJCT代理指標 | Pearson相関0.987 | 未キャッシュトークン数が良い時間予測子 |

最大入力長は、モデル・量子化・GPU容量によって大きく変わる。論文の表2ではL4上のPagedAttentionが24k、chunked prefillが46k、PrefillOnlyが130k、A100上ではそれぞれ11k、17k、87k、H100上では15k、25k、97kトークン。これらは異なるモデルが対応するハードウェアでの結果であり、GPU間で単純な性能ランキングに使うべきではない。

同じ表では、2GPUテンソル並列のMILはL4で195k、A100で77k、H100で238kと、PrefillOnlyより長い条件もある。したがってPrefillOnlyが「すべての方式で最大の入力長」を実現するわけではない。重要なのは、GPU間の追加通信を避けつつ、単一GPU方式より長い入力を処理でき、高QPS時のスループットを保つことである。

### 平均遅延・P99遅延と負の結果

論文の図6・7は到着率を変えた平均遅延とP99遅延の関係を示す。高QPSではPrefillOnlyが最も低い遅延を維持し、他方式は通信・パイプラインの空き・prefixキャッシュ不足で遅延が急増する。特に信用審査では、tensor parallelのall-reduce通信やpipeline parallelのバブルが、高QPS時の効率を下げる。

一方、低QPSではPrefillOnlyの単一GPU実行より、2GPUテンソル並列の方が一要求の実行時間を短くできる場合がある。NVLink接続があるH100ではこの傾向が強くなる。PrefillOnlyの「高QPSで優位」という結果を「どの到着率でも最短応答」と解釈してはならない。

公平性パラメータλを大きくすると、長い要求の待ち時間が改善してP99が良くなるが、平均遅延が悪化する。これはSRJFの基本的なトレードオフである。論文は平均とP99を両方報告し、短い要求だけを優先してP99を犠牲にした設計ではないことを確認する。

### 改善要因の切り分け

推薦ワークロードでは共通prefixが多いため、JCTを継続的に再校正してキャッシュヒット要求を優先することが重要になる。通常のchunked prefillでは高QPS時にprefixキャッシュが不足して性能が低下するが、PrefillOnlyは共通prefixを保持しsuffixだけを捨てるためキャッシュ容量を有効利用できる。テンソル・パイプライン並列はprefixを複数GPUへ分散できるものの、GPU間通信の費用が高い。

信用審査ワークロードでは共通prefixの再利用より、長入力を単一GPUで処理できることが重要になる。hybrid prefillingが中間テンソルを抑え、使い終えたKVを破棄できるため、複数GPUへモデルやKVを分割する必要がなくなる。論文はH100のNVLink有無を比較し、NVLinkで並列方式が改善してもPrefillOnlyの高QPSスループット優位が残ると報告する。

## 既存研究との差

vLLMのPagedAttentionはKVのページ単位管理によって断片化を抑え、通常の生成サービングを高効率化する。しかしprefill-onlyでは将来の復号に不要なKVを全層に保持する必要がない。chunked prefillは中間テンソルを小さくできるが、複数forwardに分割したチャンク間で全層KVが必要になる。PrefillOnlyのhybrid prefillingは注意と非注意の処理粒度を分け、この二つの制約を同時に回避する。

スケジューリングでは、一般的なFCFSや未知の生成長を想定するLLMサービングと異なり、出力長1という性質を使ってJCTを予測する。さらにprefixキャッシュの状態変化で待機要求のJCTを再推定する点が、単純なSRJFより進んでいる。suffix KV破棄とprefix再利用の両立が、メモリ管理とスケジューリングを結び付ける。

## 限界と再現性

最も大きな制約は、出力が厳密に1トークンで完了するワークロードを前提とすることである。長文生成では後続トークンのために過去の全層KVが必要になり、同じ破棄方針をそのまま適用すると再計算が発生する。出力が短いが2〜数十トークンある分類・JSON生成にも、追加の設計なしに同じ利益が得られるとは限らない。

評価は合成された推薦・信用審査ワークロードであり、実サービスの到着相関、ユーザーごとのprefix共有、SLO分布と異なる可能性がある。GPUとモデルの組合せも限定される。特にprefixキャッシュの再利用率が低い環境では、継続的JCT再校正の利得は小さくなり得る。

低QPSではGPU間テンソル並列の方が低遅延となる条件があり、最大入力長も2GPUテンソル並列の方が大きい条件がある。PrefillOnlyの優位は主に、通信を増やさずに単一GPUで長い入力を処理し、高QPSでの平均・P99遅延を抑える点にある。公平性λの設定は平均とP99のトレードオフを持つため、運用要件に合わせて調整する必要がある。

KVの破棄はprefixキャッシュの再利用を維持する範囲で行う。実装が共通prefixを正しく認識できない場合や、複数GPU間でユーザーのルーティングが変わる場合は、再利用率が下がる可能性がある。論文は実GPUでの速度・メモリを評価しているが、LLMの判定精度そのものを改善する研究ではなく、出力の意味品質は元のモデルに依存する。

## 主要結果の解釈

PrefillOnlyの中心的な発見は、LLMの出力が1トークンと決まっているだけで、必要なKVの寿命と要求完了時間の予測可能性が大きく変わることである。注意層は一回のforwardで処理し、非注意層だけをチャンク化することで、中間テンソルのピークを減らしつつKV破棄を可能にする。さらに共通prefixを残し、suffixを捨てることで、長入力とprefix再利用の両方を支える。

実務上は、分類・ランキング・検証のように1トークンの判定を大量に処理する用途に適する。導入前には、入力長分布、prefix共有率、GPUの接続帯域、到着率、平均とP99のどちらを重視するかを確認するべきである。一般的なチャット生成エンジンの置換ではなく、特定ワークロードに合わせて実行エンジンを専門化する例として評価できる。
