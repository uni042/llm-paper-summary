# TaDA：ヘッド共通成分と量子化偏差でKVキャッシュを圧縮する

## 概要

自己回帰型言語モデルは過去トークンの鍵（Key）と値（Value）をKVキャッシュに保存し、次のトークンを生成する際に再利用する。長い入力や長い思考連鎖ではKVキャッシュがGPUメモリを圧迫し、同時実行できる要求数を制限する。Key/Valueを2〜4ビットへ量子化すれば容量を削れるが、一部の大きな外れ値が量子化範囲を広げ、他の値の分解能を損なう。外れ値だけを別の疎行列に保持する方式は、保存形式や再構築カーネルを複雑にする。

TaDAは各ヘッドのKey/Valueを、ヘッド間で共有する中心成分と、各ヘッド固有の偏差に分ける。中心成分を高精度で一度だけ保存し、偏差を低ビットで保存する。偏差の精度は層ごとの誤差感度に応じて2、4、8ビットから探索し、最近のトークンだけは高精度のまま保持する。学習済み重みを変更しないため、モデルの再学習は不要である。Tritonの融合カーネルを使い、Keyの位置回転と圧縮、Value射影と圧縮、圧縮状態を使った注意計算を実行する。

AMD Instinct MI300単体での評価では、Llama2-7BのLongBench平均がBF16の46.03に対し、KV容量27%のTaDAで45.87だった。GSM8Kの8-shot思考連鎖（Chain of Thought、CoT）ではBF16 21.30に対しTaDA 21.26である。一方、Llama3-8BやMistralではKV容量35%程度を使う設定があり、常に27%へ圧縮できるわけではない。付録のLlama3.1-70B寸法の単一注意層では2ビットTaDAの実測がBF16より高速だったが、これは**モデル全体の生成速度ではない**。

## 問題設定：外れ値と層別感度

### 一様量子化の限界

通常のKV量子化は、各トークンや各チャネルの値を低精度の整数へ写す。全体に大きな外れ値があると、量子化の最大値と最小値を広げる必要があり、多数の小さい値が粗く丸められる。KIVIはKeyをチャネル方向、Valueをトークン方向に量子化するなど非対称性を活用するが、モデルや層によっては誤差が大きい。GEARなどは疎な誤差や低ランク補正を別途保持する。

TaDAの仮説は、ヘッド間に共通する成分を先に取り除けば、残りの偏差の値域が小さくなり、外れ値を別に保存しなくても低ビット量子化しやすくなるというものである。層によって誤差への感度が異なるため、全層を一律2ビットや4ビットにするより、敏感な層に多くのビットを割り当てる。

### 学習不要の意味

学習不要（training-free）は、元モデルの重みをQATや微調整で更新しないことを意味する。一方、TaDAは対象タスクに近い学習データの少量サンプルで層別精度を探索する。探索データと評価データを分けて情報漏洩を避けるが、**事前較正・探索まで完全に不要**という意味ではない。異なるドメインの要求が混在するサービスでは、探索に用いたデータの代表性が実運用品質を左右する。

## 手法

### 1. Key/Valueの中心化と偏差保存

ヘッド数Hの各Key/Valueについて、ヘッド間で共有する中心成分K_m、V_mを計算する。各ヘッドのKey/Valueとの差を偏差D_K、D_Vとし、中心成分と低ビット偏差をKVキャッシュに保存する。復号時は中心成分から復元した偏差を差し引き、各ヘッドの近似Key/Valueを得る。論文では中心化と呼び、式ではヘッド方向の総和として記載される箇所があるため、厳密な正規化係数の実装は一次論文の式とコードで確認が必要である。ここでは保存・再構築の構造に注目する。

ヘッド間の共通成分は一つ分で済むので、Hヘッド分を繰り返し保存しない。偏差をbビットで保存する場合、中心成分の概算負担は1/H、偏差はb/16、スケールの付加費用が加わる。Llama2-7Bの32ヘッド、ヘッド次元128、偏差4ビットでは、原著の概算が1/32+4/16+2/128≒29%である。実際のKV容量には最近の高精度トークンや層別ビット配分が反映されるため、各実験の報告値は27%や35%と変わる。

### 2. 最近のトークンは高精度のまま保持

量子化誤差が連続生成に蓄積するのを防ぐため、直近Rトークンは未圧縮で保持する。トークン数がRを超えると古い部分を圧縮し、新しく到着したトークンは高精度バッファに追加する。LongBench-EではR=128、GSM8KではR=32を用いる。最近のトークンを高精度に保つ方式はKIVIなどにもあるが、TaDAでは中心化偏差と組み合わせて使う。

長い文脈では高精度のRトークンの比率が小さくなり圧縮率を得やすいが、短い文脈ではこの固定費用が目立つ。したがって「理論上の29%」と「短文脈での実際の割当メモリ」は必ずしも一致しない。

### 3. 層ごとの量子化精度探索

層ごとにKey/Value偏差の2、4、8ビットを候補とし、評価タスクとは別の学習データから抽出した少量サンプルで精度を探索する。LongBenchの設定ではHotpotQAの学習集合からランダムに1000サンプルを使い、GSM8Kではその学習集合を用いる。探索では量子化による品質の変化を見て、敏感な層に4ビットなどの高い精度を割り当てる。付録の候補例ではLlama2-7Bの32層に対し、4ビット29層・2ビット3層の設定で平均45.90、4ビット24層・2ビット8層で45.87、4ビット12層・2ビット20層で37.31だった。

この差は、同じモデルでも層別精度配分が品質に大きく影響することを示す。低ビット層を増やすほど単純に得になるわけではなく、精度予算と品質を合わせて選ぶ必要がある。探索データの偏りにより、別の用途で同じ最適配分が成立しない可能性も残る。

### 4. Triton融合カーネルと推論経路

Keyについては回転位置埋め込み（Rotary Position Embedding、RoPE）の適用と、中心化・偏差量子化を一つのTritonカーネルへ融合する。Valueについては射影計算と圧縮を融合する。注意計算では、LightLLM系のflash-decodingを改造したTaDAFlashAttnが圧縮されたKey/Valueから必要な値を再構築し、注意スコアと出力を計算する。

生成ステップでは、入力からQueryとKeyを計算し、Valueは圧縮融合カーネルへ渡す。KeyにはRoPEを適用しながら中心・偏差・スケールを得る。圧縮されたKey/ValueをKVキャッシュへ追加し、TaDAFlashAttnが既存の圧縮キャッシュを読んで注意出力を返す。圧縮・復元を別々のGPUカーネルとして実行すると中間テンソルのメモリ転送が増えるため、融合が速度の重要な条件になる。

通常のFlashAttentionカーネルはこの中心＋偏差形式をそのまま読めないので、単に保存データを量子化するだけでは性能が出ない。推論エンジン側でKVキャッシュ形式と注意カーネルを一緒に変更する必要がある。

## 評価

### 実験環境と比較の基準

| 項目 | 条件 |
|---|---|
| GPU | AMD Instinct MI300、1 GPU |
| モデル | Llama2-7B、Llama3-8B-Instruct、Mistral-7B、Mistral-7B-Instruct |
| 長文脈 | LongBench-E、4K/8K/32Kのモデル設定 |
| 推論 | GSM8K、8-shot CoT |
| 比較 | BF16、KIVI、GEAR、Quanto |
| 精度探索 | 2/4/8ビット、HotpotQAまたはGSM8Kの学習データ |
| 高精度残差 | LongBench R=128、GSM8K R=32 |
| 別途カーネル評価 | Llama3.1-70B相当の単一注意層、32Kトークン、100回平均 |

### LongBenchの代表値

| モデル | 方式 | BF16基準KV容量 | LongBench平均 |
|---|---|---:|---:|
| Llama2-7B 4K | BF16 | 1.00 | 46.03 |
| Llama2-7B 4K | KIVI 2bit | 0.25 | 43.09 |
| Llama2-7B 4K | GEAR | 0.31 | 45.38 |
| Llama2-7B 4K | TaDA | 0.27 | 45.87 |
| Llama3-8B-Instruct 8K | BF16 | 1.00 | 49.51 |
| Llama3-8B-Instruct 8K | TaDA | 0.35 | 49.43 |
| Mistral-7B-Instruct 32K | BF16 | 1.00 | 49.27 |
| Mistral-7B-Instruct 32K | TaDA | 0.35 | 49.07 |

原著表1の平均は8タスクに対する集約であり、紙面に示される個別タスクは4つだけである。Llama2-7Bでは27%のKV容量で平均差0.16ポイントに抑えたが、GQAを使うLlama3/Mistralでは35%程度の容量を必要とする。モデル構造が変われば中心化と偏差の圧縮効率も変わるため、同じ圧縮率を全モデルへ適用してよいわけではない。

### GSM8Kと負の結果

| モデル | BF16 | TaDA | TaDAのKV容量比 |
|---|---:|---:|---:|
| Llama2-7B 4K | 21.30 | 21.26 | 0.27 |
| Llama3-8B-Instruct 8K | 67.62 | 66.73 | 0.35 |
| Mistral-7B-Instruct 32K | 47.30 | 44.82 | 0.35 |
| Mistral-7B 32K | 38.28 | 37.33 | 0.35 |

Llama2-7Bではほぼ同じ正答率だが、Mistral-Instructでは2.48ポイント低下している。KIVIやQuantoが特定条件で良い値を出すこともあり、TaDAが全ての精度・容量条件で最良とは限らない。原著の比較の一部には先行論文から引用した結果が含まれ、完全に同一実装で全方式を再実行したものではない。

### 単層カーネルのメモリと速度

付録AではLlama3.1-70Bと同じ注意寸法（モデル次元8192、KVヘッド8、注意ヘッド64、最大長32K）で、単一注意層を100回実行した平均を示す。BF16実装はピークメモリ7.8GB、トークン当たり119.35ms、TaDA 2bitは4.6GBと10.83ms、TaDA 4bitは6.7GBと40.71msだった。2bitではメモリ59%、4bitでは85%に低下し、遅延も改善した。

ただしこの実験は**単一注意層のカーネルとKV処理**であり、Llama3.1-70Bの全レイヤを通した生成トークン/秒やサービスのP99遅延ではない。比較したBF16経路と専用融合カーネルの最適化水準も結果に影響するため、約11倍の単層時間差をモデル全体の速度倍率として扱わない。

### 層別感度と外れ値に関する追加分析

原著図2はHotpotQAの学習集合から抽出したサンプルを使い、圧縮前後のKey/Value活性の差をフロベニウスノルムで比較する。初期層ではKIVIとTaDAの誤差が近い場合もあるが、多くの後段層ではTaDAの方が小さい。これは中心化によって偏差の値域を狭め、少ないビット数でも元の活性を再現しやすくなるという仮説を支持する。ただしノルムの小ささは必ずしも全タスクの正答率の高さと一対一で対応しない。

付録Bの精度探索例では、Llama2-7Bで32層中4ビットを29層、2ビットを3層に割り当てた候補と、4ビット24層・2ビット8層の候補のLongBench平均は45.90と45.87でほぼ同等だった。しかし4ビット12層・2ビット20層にすると37.31へ下がった。つまり層の感度に応じた少数の2ビット化なら節約できても、圧縮層を増やし過ぎると急激に性能が崩れる。精度探索は単なる実装の付属機能ではなく、27%程度の容量と品質を両立させるための重要な工程である。

## 既存研究との差

KIVIはKeyとValueの量子化方向を分けて2ビットへ圧縮する。GEARは量子化誤差の疎・低ランク補正を使う。TaDAはヘッド間共通成分を先に取り出すことで外れ値の影響を緩和し、外れ値を別の補助データ構造へ保存する必要を抑える。層別ビット精度探索とTriton融合カーネルを組み合わせる点も特徴である。

一方、TaDAは学習不要だが事前探索を必要とするため、全く較正しない固定ビット量子化より導入手順が複雑になる。既存のKVキャッシュ管理やFlashAttention実装へそのまま差し込める形式でもない。容量削減と品質保持を両立させるには、モデルごとの探索とカーネルの実装が不可欠である。

## 限界・負の結果

第一に、層別精度探索は対象タスクと近いドメインの学習データを必要とする。異なるタスクが混在する推論サービスで単一のビット配分が最適とは限らない。著者自身が、データ非依存の探索や共通較正データセットの構築を今後の課題として挙げている。

第二に、モデル構造によってKV容量比は27%と35%など変わる。短い文脈では高精度残差トークンの比率が大きくなる。中心化の式におけるヘッド平均の正規化係数について、本文の表記は明瞭でない箇所があり、実装の厳密な再現には確認が必要である。

第三に、GSM8KでMistral-Instructなどの精度低下があり、全タスクでBF16を完全維持するわけではない。LongBenchの平均が近いことは、任意の長文生成、コード、対話、ツール利用の品質保証ではない。

第四に、単層カーネルの高速化は本番配信全体の改善倍率ではない。モデル重み、FFN、通信、バッチ化、KVページ管理、量子化スケール、カーネル起動費用を含めた測定が別途必要である。公式コードの公開URLは一次論文本文で特定できなかった。
