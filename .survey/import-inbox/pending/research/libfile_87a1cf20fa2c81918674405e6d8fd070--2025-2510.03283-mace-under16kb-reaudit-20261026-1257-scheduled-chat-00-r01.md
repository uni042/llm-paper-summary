# MACE：LLM推論と継続再学習を同じGPUで混載するスケジューラ

## 概要

推論サーバでモデルを個人の嗜好や新しいフィードバックへ追随させたい場合、モデルの再学習と応答生成が同じGPU資源を奪い合う。一定時間ごとに再学習する方式はモデル更新が遅れ、更新を最優先する方式は利用者への応答を待たせる。MACEはこの二択を、入力の事前計算、逐次生成、LoRA微調整を**反復単位で一緒に詰める**スケジューリング問題として扱う。

中核は、経過待ち時間とアラインメント改善余地に応じて優先度を更新する仕組み、GPUの空きメモリと処理時間の両方を見た最適適合配置、共通接頭辞のKV再利用とデコード時のKVキャッシュ枝刈りである。A6000 AdaではAdaInf比で10%再学習率の推論スループット最大1.46倍、入力事前計算遅延最大63%削減を報告する。ただし、GPUがほぼ飽和するAGX Orinでは利得が限定的であり、KV枝刈りは一部のアラインメント品質を損なう。

## 問題設定

入力事前計算は入力長とバッチに応じて大きな計算を行い、逐次生成は小さな演算を逐次繰り返すがKVキャッシュが成長する。LoRA 微調整は全重み更新より軽いとはいえ、逆伝播と最適化器状態のため推論より高いメモリ・計算需要を持つ。この三者を個別のキューで処理すると、GPUメモリの未使用領域と時間的な待ちが同時に発生する。

比較対象のEkyaは再学習を周期的に実行して推論をブロックする。AdaInfは継続再学習を高優先で処理するためモデル更新は速いが、推論要求が待ちやすい。MACEは一つの反復内へ短い逐次生成と大きな再学習を混ぜ、SLO違反を抑えつつ再学習の飢餓も避ける。最適化対象は純粋な学習スループットではなく、**応答遅延、トークン処理能力、モデルの嗜好追随精度の三者**である。

## 手法

### 時間とアラインメント損失で優先度を変える

要求は入力の事前計算、逐次生成、微調整に分類され、到着時刻と基本優先度を持つ。通常の基本優先度は逐次生成 > 入力事前計算 > 微調整として応答生成を守る。一方、待ち時間に伴う優先度の増加率は微調整 > 入力事前計算 > 逐次生成と逆にする。これにより長く待った再学習は徐々に前へ出て、永遠に延期されない。

微調整要求ではさらにDPO損失を優先度へ加える。現在のモデルが望ましい応答と望ましくない応答を十分区別できていない例は、アラインメント改善余地が大きいとみなして優先的に学習する。入力はユーザーの好みの対（x, y+, y−）、出力は更新されたLoRA重みである。再学習を単純な到着順ではなく、更新価値と待ち時間の双方で扱う。

### 優先度関数と公平性の境界

原著4.1節は、種類ごとの基本優先度を π_w、経過時間による増分を δ_w、到着時刻を t_arr として、優先度を `P_w(t)=π_w+δ_w(t−t_arr)` と定義する。逐次生成の基本優先度を最も高くする一方、微調整の増分係数を最大にするので、短期的な応答保護と長期待機の解消が同時に働く。微調整だけは `γ×L_DPO(x,y+,y−)` を加算し、モデルが嗜好を区別できていない学習例を前へ送る。これらは原著の設計上の順位規則であり、あらゆる到着分布で待ち時間の上限を証明したものではない。

### 反復単位の二次元最適適合

スケジューラは、各候補の必要メモリmと予測実行時間ℓをプロファイルから見積もる。GPUメモリの空きと、同じ反復に詰める他タスクとの実行時間差を重み付きで評価し、メモリ断片化と処理時間の不整合が小さくなる実行枠へ割り当てる。候補実行枠に入らない場合は新しい実行枠を作り、今回実行する先頭実行枠を選ぶ。メモリ閾値やタスク数の閾値に達したら追加を止める。

実行が終わると、逐次生成はEOSまたは最大ステップ数、微調整はDPO損失閾値に基づいて終了判定し、未完了タスクを更新優先度で再キューイングする。論文の図では、初期には複数の逐次生成と入力事前計算を優先し、後の反復で待ち時間の増えた微調整を先行させる。全要求を一度に完了させる静的箱詰め配置ではなく、生成トークン単位で状態が変わるオンラインの箱詰め配置である。

### 実行枠選択の数式と逐次実行

原著Algorithm 1では、候補タスクのメモリ要求を `m`、予測時間を `ℓ` とし、既存の実行枠に収まる場合に限り評価する。選択値は `f=λ1×|空きメモリ−m|+λ2×|実行枠の最長時間−ℓ|` であり、単に空きメモリの大きな実行枠を選ぶのではない。メモリ容量と処理時間の双方を近づけ、短い生成タスクが長い微調整処理を待つ状況を減らす。メモリ使用量の閾値 `τ_mem` またはタスク数の閾値 `τ_task` に達すると詰め込みを止め、先頭の実行枠だけを実行する。残りの実行枠にある未完タスクは優先度を更新して再投入されるため、最適化は反復ごとの局所的な近似である。

### 共通接頭辞共有とKV枝刈り

同じシステム指示文などを持つ要求群に対し、Trie状の共通接頭辞木を構築する。共通接頭辞は一度入力事前計算してKVをキャッシュし、子要求が再利用する。深さ優先走査により共通計算をまとめ、メモリが足りない場合はLRUで不要キャッシュをオフロードする。これにより入力事前計算の再計算を抑え、同じGPUへ再学習タスクを載せる余地を増やす。

逐次生成では容量制約に応じて寄与の小さいKV要素を枝刈りし、キャッシュ占有を下げる。これは可逆な共通接頭辞共有と異なり、過去情報を実際に失う近似操作である。原著のアブレーションでKV枝刈りを無効にしたMACE/Pruneが最も高いCLPDを示す点は、スループット向上とアラインメント精度が完全には両立しないことを示す。

### KV容量のヘッド別配分と削除条件

原著4.3節の枝刈りは、注意出力ベクトル `a_(t,h)` のL2ノルムを各ヘッドで追跡し、直近 `T` 回の平均値 `ā_h` から重み `w_h=ā_h/Σ_j ā_j` を求める。総容量 `C_total` に対して各ヘッドの容量を `C_h=⌊w_h C_total⌋` と配分し、端数の余りは重みの大きなヘッドへ割り当てる。最後に使用した時点から窓幅 `W` を超えるか、出力ノルムが閾値 `τ` 未満であれば削除対象とする。つまり全ヘッドへ均一なトークン数を配る方式ではなく、実行中の注意出力の強さで容量を調整する。ただしノルムは将来の質問に必要な履歴を完全には予測できず、原著の構成要素除去実験でも枝刈りを外した方が嗜好品質が高い。

### 実装と対象範囲

受付スレッドが要求を受け、配車スレッドが優先度・実行枠配置を更新し、実行スレッド群がGPU作業を実行する。対象は単一ノード・単一GPUでの混載であり、複数ノード間のモデル更新同期や分散KVキャッシュ整合性を解決した方式ではない。入力事前計算・逐次生成・LoRA微調整をGPU上で協調させる設計は、複数GPUに独立して分ける分離配置とは異なる。

## 評価

### 実験条件

| 項目 | 条件 |
|---|---|
| サーバ | NVIDIA RTX A6000 Ada、48GB VRAM、Mistral-7B |
| エッジ | NVIDIA AGX Orin、32GB LPDDR5、Mistral-3B |
| 入力・到着 | ポアソン到着の推論要求、再学習率を変化させる混合負荷 |
| 嗜好データ | Anthropic HH-RLHF（無害性）、Stanford SHP（有用性） |
| 再学習 | LoRAとDPOを用いた連続的な嗜好追随 |
| 比較 | Ekya（周期再学習）、AdaInf（継続再学習・FIFO優先） |
| 指標 | 推論スループット、TTFT、TBT、微調整遅延、勝率、CLPD、SLO達成率、GPU利用率 |
| 設計上の制約 | 同一GPU型のオフラインプロファイルを前提。分散ノードの同期評価はない |

CLPDは好ましい応答と好ましくない応答の対数確率差で、高いほど好みを区別する余裕が大きい。勝率は好ましい応答へ高い確率を割り当てた割合である。TTFTは最初のトークンまでの遅延、TBTは生成トークン間の遅延を表す。各改善倍率は異なるベースライン・条件で得られており、一つの条件の全指標が同時に最大改善するという意味ではない。

### 主結果とGPUの制約

| 条件 | 比較・指標 | MACEの結果 | 解釈 |
|---|---|---|---|
| A6000、再学習率10% | AdaInf比の推論処理能力 | 最大1.46倍 | 混載とキャッシュ最適化でGPUの空き時間を利用 |
| Orin、再学習率を変化 | AdaInf比処理スループット | 平均1.12倍 | 計算資源が飽和しやすく利得は小さい |
| A6000 | AdaInf比の入力事前計算遅延 | 最大63%削減 | 共通接頭辞再利用が有効 |
| Orin | AdaInf比の逐次生成遅延 | 最大30%削減 | KVキャッシュ容量を抑える効果 |
| SHP | AdaInf比勝率 / CLPD | 最大1.03倍 / 1.21倍 | 再学習と応答の両立による品質改善 |
| HH-RLHF | AdaInf比勝率 / CLPD | 最大1.02倍 / 1.34倍 | 品質指標ごとに利得が異なる |
| A6000 | GPU利用率（Periodic/Continuous/Hybrid） | 17.8% / 21.1% / 27.7% | 断片化が大きいサーバで混載余地がある |
| Orin | GPU利用率（Periodic/Continuous/Hybrid） | 82.7% / 80.6% / 85.2% | すでに高負荷で混載余地が小さい |

原著Figure 5ではOrinのTTFT改善が0.92～0.98倍程度、TBTは約1.01倍となる比較があり、混載によって全遅延が常に短くなるわけではない。論文のabstractの「最大63%削減」をOrinやすべての負荷へ外挿しない。

### 構成要素除去と負の結果

SLO達成率はTTFTが「順伝播遅延の5倍以内」という期限に入る割合で測る。固定バッチ・FIFOへ戻したMACE/Binは高負荷で達成率が20%未満へ落ち、共通接頭辞共有を外したMACE/Prefixは150 rpsで完全版より達成率が35～40%低い。処理スループットは完全版が225 tokens/s超に対し、MACE/Binは17.6%低下、MACE/PruneとMACE/Prefixはそれぞれ7～11%低下する。三つの機構は異なるボトルネックを減らしている。

一方、**KV枝刈りを無効化したMACE/PruneがCLPDで最良**という原著Figure 12の結果は、枝刈りで必要な履歴情報が失われ得ることを示す。スループットを上げても、生成品質と嗜好追随の両方が単調に良くなるわけではない。

### スケジューラの追加コストと原著内の不整合

原著Table 1はスケジューラ遅延をEkya 0.03ms、AdaInf 0.08ms、MACE 0.15ms程度と記す。一方、直後の本文はMACEの追加オーバーヘッドを「約15ms/request」、AdaInfとの差を「約7ms/request」と説明している。**表と本文で約2桁の差があり、単位または測定粒度の説明が一致しない。** さらに「15msは数十～数百msの実行時間に対して0.1%未満」とする主張も、そのままでは算術的に成立しない。再現・実装判断ではTable 1と本文の数値を同じ指標として扱わず、追加の確認が必要である。スケジューラメモリはTable 1で4MBとされ、本文では5MB未満と説明される。

### 図表の読み方と結果の外挿限界

Figure 9の嗜好追随品質は、SHPとHH-RLHFという目的の異なる二つのデータで比較されている。前者では有用性を選ぶ選好、後者では安全な応答を選ぶ選好を使い、勝率と対数確率差を別指標として報告する。勝率が1.03倍という結果と対数確率差が1.21倍という結果は異なる尺度であり、モデルの生成速度が同じ倍率だけ伸びたという意味ではない。生成速度はFigure 10の毎秒トークン数、応答開始までの時間と生成中の遅延はFigure 11で独立に測定されている。従って「最大1.46倍の処理能力」と「最大63%の入力事前計算遅延短縮」を、同じGPU・同じ負荷・同じ要求で同時に実現する保証として読んではならない。

Figure 12の構成要素除去では、固定バッチへ戻した方式が高負荷でサービス目標を大きく外す。接頭辞共有の無効化は重複する入力計算を増やし、KV枝刈りの無効化は生成中の記憶量を増やす。一方で枝刈りを止めると嗜好品質が最も高くなるため、品質を厳格に維持したい用途では容量削減の強度を別途検証する必要がある。Figure 13では同一のバッチ上限を設定しても混載の方が完了までの反復回数が少なく、反復一回あたりの遅延は近いと報告される。ただし実験は入力到着をポアソン過程で生成しており、実サービスの突発的な到着相関、利用者ごとのLoRA更新競合、分散環境の同期負担を検証していない。

## 既存研究との差

OrcaやvLLMは推論要求の連続バッチ化とKV管理を主眼とし、継続的な嗜好再学習を同じ反復へ詰めることは主題ではない。Ekyaは周期的な再学習により更新鮮度と応答遅延を分離する。AdaInfは更新鮮度を優先するが、入力事前計算・逐次生成・LoRAの異なる資源形状をまとめて扱わない。MACEは**GPUローカルの一反復**を資源配分単位とし、再学習の重要度とGPU空き容量を同時に考慮する。

## 限界・適用条件

対象GPUはA6000 AdaとAGX Orinの単一ノードであり、複数GPU間で異なるモデル版を共有する整合性、ノード間の再学習同期、分散キャッシュは未評価である。GPU型が異なる環境へは入力事前計算・逐次生成・LoRA微調整のオフライン性能プロファイルを再作成する必要がある。CPUへのfallback、異種GPUの通信費用、長期間の概念ドリフト下での安全性評価も主な実験範囲外である。

再学習要求の生成はポアソン到着・特定の嗜好データセットに基づく模擬的な混合負荷であり、実際の大規模マルチテナント環境の障害、チェックポイント競合、プライバシー制御、学習済みLoRA版のロールバックまで実証したものではない。原著内のスケジューラ追加費用の単位不整合は未解決の再現性リスクとして残る。公式コードのURLは確認できない。

## 再監査の根拠と品質境界（2026-10-26）

一次論文 arXiv:2510.03283v1 の4.1〜4.3節、Algorithm 1、Figure 9〜13、Table 1、7節を再照合した。再監査で修正した中心点は、日本語説明率を上げるだけでなく、優先度の二重の順位付け、メモリ・時間の二次元配置、注意出力ノルムからのKV容量配分を具体化したことである。Table 1の0.15ミリ秒と本文の約15ミリ秒は原著の矛盾として残し、どちらか一方を正解として採用しない。実験はGPU単体の評価であり、分散推論や複数ノードのLoRA版整合性を検証していない。
