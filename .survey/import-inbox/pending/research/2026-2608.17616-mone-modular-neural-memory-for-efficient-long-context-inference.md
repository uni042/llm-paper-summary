# MoNe: Modular Neural Memory for Efficient Long Context Inference

> 凍結したトランスフォーマーの各層へ高速重みニューラルメモリを付け、文脈を固定長セグメントごとにテスト時学習で書き込み、推論時は質問だけからメモリトークンを生成して文脈を読み直さないことで、128K文脈の計算とピークGPUメモリを文脈内学習比で約80パーセント削減した研究。

## 概要

長い文書や履歴をそのままプロンプトとしてモデルへ与える文脈内学習（in-context learning）は、自己注意の計算量が文脈長の二乗で増え、保持すべきKVキャッシュ（過去トークンのキーとバリューの蓄積）も文脈長に比例して伸びる。資源の限られたデバイスではこの費用がすぐに上限へ達し、さらに小型モデルでは、文脈がネイティブなウィンドウ内に収まっていても、多数のトークンの中から必要な情報を拾うこと自体が不安定になる。検索拡張生成は関連する断片だけを選んで費用を抑えるが、答えが文脈全体に散らばった複数の断片の統合を要する場合には、埋め込みによる検索では拾い切れない。一方、線形時間の逐次モデルやテスト時学習を使う新しいアーキテクチャは、アーキテクチャ自体を最初から設計して学習し直す必要があり、既存の事前学習済みトランスフォーマーへそのまま持ち込めない。

本論文のMoNeは、この隙間を狙う後付けモジュールである。凍結したバックボーンの各デコーダー層へ、高速重み（推論時に勾配更新される重み）を持つ小型のニューラルメモリを付け、文脈を512トークンのセグメントへ分けて順に読みながら、各層のメモリへ文脈の内容を書き込む。書き込みが終われば、推論では質問トークンだけをメモリへ通してメモリトークンを作り、それをキーとバリューとしてバックボーンの注意へ差し込む。文脈トークンは二度と読まれないため、書き込み側の費用は文脈長に対して線形、質問側の費用は文脈長に依存しない定数オーダーになる。代表結果として、128Kトークンの条件では、文脈内学習と比べて総FLOPsを786.33テラから149.61テラへ約81パーセント削減し、ピークGPUメモリも7.07ギガバイトから1.41ギガバイトへ約80パーセント削減した。追加パラメータはバックボーン比で6.4パーセントである。品質面でも、オフライン学習は最大4Kトークンの文脈だけで行ったにもかかわらず、RULERの単一キー検索・複数キー検索・頻出単語抽出の3タスクで、128Kトークン時点でも0.96、0.94、0.96のスコアを維持し、ネイティブウィンドウを超えて急落する文脈内学習と大きく差が付いた。

## 問題設定

対象は、重みを完全に凍結した事前学習済みのトランスフォーマーである。入力はNトークンの文脈と質問であり、バックボーンのパラメータを一切変えずに、長い文脈を効率よく正確に使えるようにすることが目的である。通常の処理では、文脈全体に対する注意計算が二乗オーダーになり、KVキャッシュが文脈長に比例して増えるため、計算とメモリの両方が文脈長に縛られる。特にピークGPUメモリは文脈長とともに伸び続けるため、デバイス側の上限に当たった時点で処理自体が成立しなくなる。

もう一つの問題は精度である。論文が引く先行知見では、文脈が長くなるほど、関連情報が文脈内に残っていてもモデルがそれを使えなくなる劣化が起きる。つまり長文脈の困難は費用の問題であると同時に、拾うべき情報が注意の海に埋もれるという表現の問題でもある。検索拡張生成は費用側には効くが、断片を独立に切り出して埋め込みで選ぶため、複数の断片を組み合わせなければ答えにならない課題では構造的に弱い。テスト時学習型のメモリは文脈全体を重みへ圧縮するためこの弱点を避けられるが、既存方式はモデル全体の新規学習を前提としており、凍結した既存モデルへ組み込む経路がなかった。本論文の着眼点は、メモリへの書き込みを層ごとに局所化し、バックボーンの順伝播で得られるその層自身の活性値だけから更新を計算することで、バックボーンへ逆伝播を通さずにモジュールとして切り離せる形にした点にある。

## 手法のあらまし

処理は大きく2つの段階に分かれる。第1段階はテスト時学習で、文脈を重ならない512トークンのセグメントへ分割し、順番にバックボーンへ通す。各層では、その層の順伝播で得たキーとバリューを教師として、連想メモリ損失に対する勾配でその層の高速重みを1ステップ更新する。更新は層の中で閉じており、他の層の重みへ勾配は流れない。全セグメントを処理し終えた時点の高速重みの状態が、文脈全体を圧縮したメモリになる。第2段階は推論で、質問トークンをバックボーンのクエリ射影で変換してメモリへ入力し、メモリトークンを読み出す。読み出したトークンを凍結したキー射影とバリュー射影へ通し、質問自身のキーとバリューの横へ連結して注意を計算する。注意が見る相手は質問トークンと固定個数のメモリトークンだけであり、文脈トークンは現れない。最終状態の高速重みは複数の質問で再利用でき、新しい文脈が来れば過去分を処理し直さずに追加のセグメントだけを書き足せる。

## 手法

### 1. メモリの注入 — 質問だけからキーとバリューを作る仕組み

各デコーダー層に付くメモリ本体は、SwiGLU型の多層パーセプトロンである。高速重みは入力側、ゲート側、出力側の3つの行列からなり、いずれもヘッド次元どうしの正方行列で、ヘッドごとに保持される。単一の線形写像ではなく非線形なネットワークを使うのは、同じパラメータ予算の中で連想の表現力を上げ、より豊かな対応関係を重みへ埋め込むためである。生成時には、質問トークンの隠れ状態をバックボーンの凍結したクエリ射影へ通したものをメモリへ入力し、文脈をすべて処理し終えた最終状態の高速重みで変換して、層ごとのメモリトークンを得る。この出力はヘッドごとに二乗平均平方根で正規化され、学習されたヘッドごとのゲートで大きさを調整される。続いてメモリトークンは、バックボーンと共有する凍結したキー射影とバリュー射影でキーとバリューへ変換され、質問自身から作られる通常のキーとバリューの列へ連結される。つまり注意の仕組み自体は既存のまま変えず、注意先の列へ「文脈の要約に相当する固定長の相手」を追加する形で長文脈情報を流し込む。メモリ由来のキーとバリューの組は層ごとにセグメント長と同数の固定サイズであり、文脈長によらず一定なので、KVキャッシュのフットプリントはテスト時学習中も推論中も伸びない。共有する射影行列は複製せず、そこへ小さな低ランク適応（LoRA）のアダプタを足すだけなので、追加パラメータは小さく抑えられる。観測する対象は質問トークンだけ、選択や生成の対象はメモリトークンの内容であり、ボトルネックである文脈全体への注意とKVキャッシュの増大を、この時点で構造的に消している。誤った読み出しが起きる場合、それはメモリへの書き込み段階で情報が落ちたことを意味し、推論段階で文脈へ立ち戻って回復する経路は存在しない点が、この設計の代償である。

### 2. 連想メモリ損失と層局所更新 — 文脈を高速重みへ書き込む仕組み

書き込みの教師は、バックボーン自身の射影から作られる。文脈セグメントをバックボーンへ通すと、各層でキー射影とバリュー射影による変換結果が得られる。キーは射影の後にシグモイド型の活性化とトークンごとのL2正規化を受け、バリューは活性化だけを受ける。連想メモリ損失は、キーでメモリを引いた出力とバリューの内積の負値であり、この損失を下げることは、キーからバリューを連想できるように対応関係を高速重みへ刻むことと等しい。予測誤差を使うのではなく内積を直接最大化する形なので、書き込みは「その層が見たキーとバリューの組を、後でキーから引ける形で重みに残す」操作として閉じる。更新はセグメントごとに行われ、勾配の蓄積にはトークンごとに学習された学習率と、データ依存の運動量減衰が使われる。減衰係数はセグメントの隠れ状態から予測され、内容に応じて過去の運動量を選択的にリセットできる。更新後には重みを行方向にL2再正規化し、書き込みが進んでも重みの大きさが暴走しないようにしている。決定的に重要なのは局所性である。各トークンの損失の勾配は、その層自身の順伝播の活性値だけから計算でき、他の層の高速重みに対する勾配はゼロになる。通常の交差エントロピー損失で更新しようとすれば、出力側からその層まで全層を逆伝播しなければならず、メモリはバックボーンと切り離せない。本方式では更新が層内で完結するため、追加費用はセグメント長の範囲の局所計算だけで済み、モジュールとしての独立性と、ピークメモリが文脈長に対して定数であることの両方がここから生まれる。失敗条件は書き込みの容量側にある。固定サイズの重みへ際限なく連想を刻めば、古い対応と新しい対応が干渉し、後段の除去実験が示すように、層数を絞ると長い文脈で保持が崩れる。

### 3. セグメント局所の位置符号化 — 長さの外挿を可能にする仕組み

位置情報はセグメント局所の回転位置埋め込み（RoPE）でキーへ与えられる。各文脈トークンの位置はセグメント内での添字、つまりトークン番号をセグメント長で割った余りであり、文脈がどれだけ長くなっても位置は常にセグメント長の範囲内に収まる。推論時の質問トークンにも先頭からの位置が与えられるが、質問長はセグメント長より十分短いため、同じ範囲内に収まる。位置の補間や拡張のための追加学習は不要で、モデルが見たことのない絶対位置が一切現れないことが、最大4Kトークンで学習した仕組みが128Kトークンまでそのまま働く理由である。裏返すと、文脈全体を通した絶対的な位置や順序の情報はこの符号化では保持されず、順序そのものが答えに関わる課題では弱点になり得る。論文の評価は位置よりも内容の検索と集計を問う課題が中心であり、この弱点は検証範囲の外にある。

### 4. メタ学習と推論時の運用 — 学習しておくものと凍結するものの切り分け

「再学習なし」という主張には正確な切り分けが要る。バックボーンの重みは一切学習しないが、キー・クエリ・バリュー射影へ足すLoRAアダプタと、層ごとの学習率や運動量の射影、出力スケールといったメタパラメータは、事前にオフラインで学習される。学習目標は、文脈で更新し終えたメモリを条件として答えトークンへ与える生成損失であり、つまり「どう更新すれば後で答えられるか」という更新アルゴリズム自体を学習している。配置後はこれらはすべて凍結され、テスト時学習の更新規則は固定された学習済みアルゴリズムとして動く。オフライン学習はセグメント数が2から8、すなわち文脈長1Kから4Kの範囲のサンプルで行われ、それでも評価では256セグメント、128Kトークンまで一般化した。推論フェーズでは重みの更新は一切行わず、メモリの読み出しだけが行われる。最終状態の高速重みは保存しておけば複数の質問で使い回せ、新しい文脈が追加された場合は続きのセグメントだけを処理すればよく、過去分の再処理は要らない。ここでの追加費用は、質問に答える前に文脈全体を一度走査するテスト時学習の費用であり、質問が1回だけの文脈ではこの前払いが全体費用の大半を占める。逆に質問が増えるほど、質問側の定数費用の安さが効いて平均費用は下がる構造である。

### 5. データと制御の流れ

1つの文脈に対する流れは、分割、書き込み、読み出しの3手である。まず文脈を512トークンずつのセグメントへ分ける。次にセグメントを順にバックボーンへ通し、各層でキーとバリューを作って連想メモリ損失の勾配で高速重みを更新する。このときバックボーン側の計算はセグメント単位で完結し、保持すべき状態は高速重みだけである。最後に質問を処理し、各層でメモリトークンを生成して注意へ差し込み、通常の生成を行う。文脈トークンが注意へ現れるのは書き込み時のセグメント内部だけで、質問の生成過程には現れない。

| 高速重みメモリ | 各層のキーとバリュー | 連想メモリ損失の勾配でセグメントごとに更新する | 文脈情報の保持 | 固定容量への圧縮で情報が落ち得る |
| メモリトークン生成 | 質問トークンのクエリ射影 | 最終状態のメモリから読み出し、正規化とゲートを経てキー・バリュー化する | 推論時の注意先 | 文脈へ立ち戻る回復経路がない |
| 層局所更新 | その層自身の順伝播の活性値 | 他層へ勾配を流さず層内で更新を完結させる | 書き込みの計算とメモリ | バックボーン全体の誤差信号は使えない |
| セグメント局所RoPE | セグメント内のトークン位置 | 位置をセグメント長未満へ折り返す | 長さの外挿 | 文脈全体の絶対位置は保持されない |
| LoRAとメタパラメータ | オフラインの生成損失 | 更新規則自体を事前学習し配置後は凍結する | 書き込みの質 | バックボーンごとに事前学習が要る |

## 評価

### まず見るところ

- **結論:** 凍結した小型バックボーンでも、文脈を高速重みへ書き込むことで、ネイティブウィンドウの4倍の長さまで検索系タスクの精度をほぼ落とさず、計算とピークメモリを約80パーセント削減できることが示された。
- **速度・効率:** 理論上は書き込みが文脈長に対して線形、質問側が定数オーダーであり、実測でも128Kで総FLOPsが文脈内学習の約5分の1になった。ただし費用の大半は書き込み側にあり、質問が少ない文脈では前払いの比重が大きい。
- **品質:** 圧縮を伴う近似方式だが、評価した3タスクでは窓内・窓外とも比較対象を上回った。窓内でも頻出単語抽出では文脈内学習を大きく上回り、圧縮表現が小型モデルの注意の弱さを補う面も見えた。
- **メモリ・入出力:** ピークGPUメモリは文脈長に対して定数で、32Kでも128Kでも1.41ギガバイトに留まった。これはKVキャッシュを持たない設計の直接の帰結である。
- **評価の強さ／注意点:** 実機測定を含むが、バックボーンは0.5Bの1種のみ、タスクはRULERの制御された検索・集計系のみであり、自然な長文質問応答での検証はない。

## 既存研究との差

文脈内学習との差は、注意の相手を文脈トークン全体から固定個数のメモリトークンへ置き換えた点にある。検索拡張生成との差は、文脈を外部の断片集合として残すのではなく、層ごとの重みへ圧縮して取り込む点であり、そのため断片の統合や全体の集計を要する課題でも劣化しにくい。長文脈の微調整や文脈圧縮の研究はバックボーン側の学習や変更を伴うが、本方式はバックボーンを凍結したままモジュールを足すだけでよい。テスト時学習の系譜では、TTTやTitans、大きなチャンク更新でハードウェア利用率を上げたLaCTなどが高速重みによる線形時間処理を示してきたが、いずれもアーキテクチャ全体を新規に学習する前提だった。本論文の差は、その更新を層局所の連想損失で閉じさせることで、既存の事前学習済みトランスフォーマーの注意へ後付けできる形にした点にある。位置符号化をセグメント局所に閉じる工夫も、外挿のために位置補間や追加学習を持ち込まない選択として、この系譜の中では独自である。

## 限界・実装状況

- 評価はQwen2.5-0.5Bという小型バックボーン1種と、RULERの制御された検索・集計タスクだけであり、より大きなモデルや自然な長文質問応答、実在の対話履歴での有効性は論文自身が今後の課題として挙げている。
- 「再学習なし」はバックボーンについての主張であり、LoRAアダプタとメタパラメータにはバックボーンごとのオフライン学習が必要である。新しいバックボーンへ移す際のこの費用は評価されていない。
- 文脈は固定容量の高速重みへ圧縮されるため原理的に近似であり、書き込みで落ちた情報を推論時に文脈へ立ち戻って回復する経路はない。評価タスクの範囲を超えた情報量の文脈で保持がどう劣化するかは未検証である。
- セグメント局所の位置符号化は文脈全体の絶対位置や順序を保持しないため、順序自体が意味を持つ課題への適用には注意が要る。
- 質問が1回だけの文脈では、総費用の大半を占める書き込みの前払いが利得を相殺し得る。削減率が32Kで大きく縮む結果は、その境界を示している。
- 公式コードの公開先は論文中に示されておらず、上流ランタイムへの統合も報告されていない。GPU型番など測定環境の詳細も明記されていない。

## 一般的な実装上の含意

長文脈の費用対策を設計する際は、推論時の注意費用だけでなく、文脈を取り込む前処理の費用と、取り込んだ状態を何回使い回せるかを含めた総量で比べるべきである。本方式のように前処理が線形で再利用できる形なら、質問回数が増えるほど平均費用は下がり、逆に使い捨ての文脈では前払いが割に合わない。次に、メモリのピークを文脈長から切り離すには、保持する状態のサイズを入力長ではなく設計パラメータで決めることが効く。KVキャッシュのように入力に比例して伸びる状態を持つ限り、ピークは必ず入力長に縛られる。また、モジュールを後付け可能にする鍵は、更新計算をそのモジュールと層の内部で完結させることであり、全体の誤差信号へ依存する更新は統合の自由度を大きく下げる。最後に、位置符号化を局所範囲へ閉じる方法は、長さの外挿を得る代わりに大域の位置情報を捨てる交換であるため、外挿が必要な用途では、何を捨てているかを先に確認すべきである。

## 引用関係

高速重みとテスト時学習の系譜としてTTT、LaCT、Titans、Mambaなどを引き、連想メモリの更新式やメモリモジュールの形はLaCTの方式を踏襲している。長文脈の困難については、文脈の途中の情報が使われにくい問題やコンテキストロットを引いて問題設定を支え、評価基盤としてRULERを、検索拡張生成の比較対象として初期のRAG系研究と埋め込みモデルを引用している。LoRAは射影へのアダプタとして引用され、今後の方向としてメモリごとに異なるLoRA系手法を使う案も同系統の引用とともに示されている。
