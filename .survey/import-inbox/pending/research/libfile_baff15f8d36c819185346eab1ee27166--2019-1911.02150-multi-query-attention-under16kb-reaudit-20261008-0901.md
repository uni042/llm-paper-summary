# Fast Transformer Decoding: One Write-Head is All You Need

## 概要

本論文は、Transformerの自己回帰復号におけるメモリ帯域のボトルネックを、複数クエリ注意（Multi-Query Attention; MQA）という簡単な構造変更で緩和する。通常の複数ヘッド注意（Multi-Head Attention; MHA）は、注意ヘッドごとに問い合わせ（Query; Q）、鍵（Key; K）、値（Value; V）を独立に射影する。学習時には全トークンをまとめて処理できるため行列積の計算効率が高いが、自己回帰生成では新しい1トークンごとに過去の全K/Vを読み直す。長い文脈や小さなバッチでは、この読み出しが演算より重くなる。

MQAはQの複数ヘッドを残し、KとVだけを全Qヘッドで共有する。各Qヘッドは同じK/Vに対して異なる問い合わせを作るため、ヘッドごとに異なる注意分布を得られる。過去系列のK/Vキャッシュにはヘッド次元が不要になり、ヘッド数hにほぼ比例した保存量と読み出し帯域を減らせる。注意の算術量を全てh分の1にする方式ではなく、復号時に律速になりやすいデータ移動を直接削る方式である。

著者Noam Shazeerは、WMT14英語→ドイツ語翻訳とBillion Word言語モデルで、MHAからMQAへ置き換えたときの品質・速度を比較した。単一TPUv2での翻訳デコーダは、貪欲復号（greedy decoding）で46 µs/トークンから3.8 µs/トークンへ約12.1倍、ビーム幅4では203から32 µs/トークンへ約6.3倍短縮した。一方、WMT開発集合のBLEUは26.7から26.5、Billion Wordのパープレキシティは29.9から30.2へわずかに悪化した。品質と帯域削減の交換条件を数値で示した先駆的研究である。

## 問題設定

Transformerの自己注意は、学習時には既知の入力・出力系列をまとめて扱い、全位置の問い合わせと鍵の積を大きな行列積として計算できる。並列化によりGPU/TPUの演算能力を利用しやすい。ところが自己回帰生成では、直前に生成したトークンが次の入力を決めるため、未来の問い合わせを先に計算できない。各生成ステップで新しいQを作り、保存してある全過去K/Vと照合しなければならない。

通常のMHAでは、バッチb、ヘッド数h、過去トークン数m、各ヘッドのK/V幅k,vに対し、K/Vの形はそれぞれ概ね `[b,h,m,k]` と `[b,h,m,v]` である。したがって生成が進むほどキャッシュ量が線形に増え、各ステップで読み出すデータ量も増える。特にバッチが小さく行列積の再利用が少ない条件では、計算器の理論演算性能が高くてもメモリ帯域が性能上限になる。

論文の複雑度解析では、幅d、系列長n、バッチb、ヘッド数h、ヘッド幅k=d/hを仮定する。通常の増分MHAではnステップの総演算量がΘ(bnd²)、総メモリアクセスがΘ(bn²d+nd²)であり、演算に対するメモリアクセス比に `n/d+1/b` が現れる。バッチを大きくすれば `1/b` は減るが、長い系列で増える `n/d` は消えない。MQAはこのn/dに相当する項をヘッド数hで割ることを狙う。

## 手法

### Qだけ複数ヘッドを残す

入力隠れ状態xから、問い合わせ射影 `P_q` は従来どおりh組のQを生成する。一方、鍵射影 `P_k` と値射影 `P_v` はそれぞれ一組だけに変更する。各Qヘッドは共有Kとの内積から別々の注意重みを計算し、その重みで共有Vを加重平均する。最後にヘッド別の出力射影 `P_o` で結果を統合する。共有するのは検索対象の記憶であり、何を検索するかという問い合わせではない。

バッチ計算では、MHAのK/V射影テンソルに存在したヘッド次元を取り除き、`K:[b,m,k]`、`V:[b,m,v]` とする。Qは `[b,h,n,k]` のままで、注意得点は `[b,h,n,m]` を保つ。したがって複数の注意分布を計算する能力は残る。単一ヘッド注意へ戻してQ/K/V全ての多様性を失う方式と区別する必要がある。

### 増分復号でのキャッシュ形状

MHAの増分復号は各ステップで `[b,h,m,k]` と `[b,h,m,v]` の過去K/Vを読み、新しいK/Vをヘッドごとに追加する。MQAでは過去K/Vを `[b,m,k]` と `[b,m,v]` に縮小し、生成した新しいK/Vも一組だけ追加する。h個のQヘッドが同じ過去K/Vを共有するため、キャッシュに保持するK/Vの要素数は理想的には約1/hとなる。

この変更はメモリ帯域に効くが、Qヘッドごとに注意得点と重みを計算する必要は残る。Qの射影や出力統合もhヘッド分あるため、モデル全体の演算量がh分の1になるわけではない。論文の増分MQAのメモリアクセス比は `1/d+n/(dh)+1/b` に相当し、系列長に比例する項がh分の1になる。算術律速の学習より、キャッシュ読出し律速の復号で利得が大きいという予測がここから導かれる。

### 同一パラメータ数での比較

MQAではK/V射影行列が小さくなるため、そのままでは総パラメータ数も減る。比較を公平にするため、WMT翻訳実験ではフィードフォワード層（Feed-Forward Network; FFN）の隠れ幅を4096から5440へ増やし、全モデルのパラメータ数を2億1100万へ揃える。Billion Word言語モデルでも約1億9200万パラメータに揃え、品質差を単なるモデルサイズ差として解釈しないようにする。

比較対象には、ヘッド数hを1・2・4へ減らす方式、K/Vの次元を小さくする方式、復号器の自己注意を現在位置と過去31位置に限定する局所注意（local attention）も含む。局所注意は参照するトークン数を減らし、MQAはトークンごとのK/V表現量を減らすため、両者は直交的に組み合わせられる。著者らは局所MQAも学習し、品質と復号時間を測定している。

### 訓練と復号での演算構造の差

学習では各位置のQをまとめて計算でき、同じK/Vを多数の問い合わせから再利用するため、メモリアクセス比は小さい。MQAのK/V共有は学習時にもパラメータを減らすが、演算性能を大きく改善するとは限らない。対して増分復号では各ステップのQが一位置分しかないため、過去K/Vの読出しが目立つ。論文の実測でも学習時間は13.2から13.0 µs/トークンとほぼ変わらない一方、復号器は大幅に高速化する。

この結果は、同じ注意機構でも実行形態によってボトルネックが異なることを示す。学習用の演算最適化だけでなく、復号時のメモリ移動量を別に計測する必要がある。MQAはキャッシュ量と帯域の両方を減らすため、バッチ数と文脈長が増える条件でもメモリ容量上の余裕を作れる。

## 評価条件

| 観点 | 一次論文の条件 |
|---|---|
| 主タスク | WMT 2014英語→ドイツ語翻訳、Billion Word Language Modeling Benchmark |
| 翻訳モデル | 6層符号化器・復号器、隠れ幅1024、Qヘッド8、K/Vヘッド幅128 |
| パラメータ | MHA/MQAとも約2億1100万。MQAはFFN幅5440に拡張 |
| 学習 | 32コアTPUv3、10万ステップ、約20エポック、バッチ128例 |
| 言語モデル | 6層復号器、約1億9200万パラメータ、13万6000ステップ |
| 速度測定 | 単一TPUv2（8コア）、系列長128、増分貪欲復号とビーム幅4 |
| 貪欲復号 | バッチ1024系列、各コア128系列、入力128・出力128トークン |
| 品質指標 | WMTのBLEU、Billion Wordの単語単位パープレキシティ |
| 比較 | MHA、MQA、局所MHA/MQA、少数ヘッド・小次元の代替構成 |

速度測定ではシステムの固定形状制約から、復号器の過去K/Vテンソルを最大長128までパディングしていた。したがって最初の短い復号段階でも長さ128に対応する計算を行う。可変長のキャッシュを伸ばす実装では初期段階の時間が変わり得る。論文の時間値はこのTPUv2構成とバッチ設定における実測であり、現代GPUや長い文脈での速度倍率を保証しない。

## 主要結果

### 翻訳品質

| 指標 | MHA | MQA | 読み方 |
|---|---:|---:|---|
| WMT開発集合BLEU | 26.7 | 26.5 | MQAは0.2ポイント低い |
| WMT開発集合 ln(PPL) | 1.424 | 1.439 | MQAはわずかに悪化 |
| WMTテスト・貪欲BLEU | 27.7 | 27.5 | MQAは0.2ポイント低い |
| WMTテスト・ビーム幅4 BLEU | 28.4 | 28.5 | MQAが0.1ポイント高い |
| Billion Word開発集合PPL | 29.9 | 30.2 | MQAは0.3悪化 |

品質差は小さいが完全に同じではない。特にBillion WordのパープレキシティはMQAが悪化するため、K/V共有には表現自由度の交換条件がある。ヘッド数やK/V次元を単純に減らした比較モデルではBLEUがさらに悪化する場合があり、Qの複数ヘッドを維持することが品質維持に寄与する。

### 訓練・推論時間

| 指標 | MHA | MQA | 改善倍率 |
|---|---:|---:|---:|
| 学習、符号化器＋復号器 | 13.2 µs/トークン | 13.0 µs/トークン | 約1.02倍 |
| 符号化器推論、貪欲 | 1.7 µs/トークン | 1.5 µs/トークン | 約1.13倍 |
| 復号器推論、貪欲 | 46 µs/トークン | 3.8 µs/トークン | 約12.1倍 |
| 復号器推論、ビーム幅4 | 203 µs/トークン | 32 µs/トークン | 約6.3倍 |

訓練や符号化器ではほとんど速度差がない一方、自己回帰復号器では桁違いの改善がある。これはMQAが計算そのものを大きく削るのではなく、過去K/Vを読み直す帯域を削る方式であることと一致する。ビーム幅4では複数候補の状態管理が増えるため、貪欲復号ほど大きな倍率にはならない。

### 局所注意との組合せ

局所MHAは復号器の自己注意を過去31トークンに限定する。これはK/Vキャッシュから読み出すトークン数そのものを減らすため、K/Vヘッド数を減らすMQAとは異なる軸である。論文は局所MQAを併用した構成も評価し、局所注意とMQAを同時に使えることを示す。ただし参照範囲を制限すると長距離情報を失う可能性があり、MQA単体の品質・速度とは別の交換条件が生じる。

### 復号性能の測定条件に関する注意

論文の貪欲復号測定では、1024系列を8コアへ分けて各コア128系列を処理する。入力系列長と出力系列長はともに128であり、符号化器と復号器の時間を別々に報告する。MHAの復号器は各生成段階で過去K/Vの読出しが発生するが、MQAでは同じK/Vを8つの問い合わせヘッドが参照するため、メモリからの重複転送が減る。実測で復号器が約12倍速くなる一方、符号化器は1.7から1.5 µs/トークンしか変わらない。この対照は、学習時の演算能力ではなく逐次生成時の帯域がボトルネックであることを示す。

品質比較では全モデルのパラメータ数を合わせているが、演算の内訳は同一ではない。MQAはK/V射影を小さくした分をFFNへ再配分するため、重み総数が同じでもメモリ移動と演算密度が異なる。したがって、品質の小差と復号速度の大差は、単にパラメータが減った結果ではなく、保存する過去状態の形状を変更した効果として読むべきである。

## 既存研究との差

通常の複数ヘッド注意はQ/K/V全てをヘッドごとに分ける。単一ヘッドへ縮小する方法は、過去KVの保存量を減らせても問い合わせの多様性まで失う。MQAはQの複数ヘッドを残してK/Vだけ共有するため、異なる注意分布を作る能力を残したまま帯域を削減できる。

局所注意や疎注意は参照する過去位置の数を減らす。MQAは参照可能な位置を減らさず、各位置について保存するK/V表現を一組へ減らす。このため長距離参照を保ちつつ容量を削減でき、局所注意とも併用可能である。

後年のグループ化クエリ注意（Grouped-Query Attention; GQA）は、複数のQヘッドをいくつかのKVグループへ割り当てる。MHAはQヘッドとKVヘッドが同数、MQAはKVヘッド数1、GQAはその中間に位置する。MQAは最大級の帯域削減を得る端点であり、GQAは品質と容量の中間点を選べる発展形と整理できる。

## 限界

第一に、MQAはK/Vのヘッド別表現を共有するため、MHAより表現自由度が低い。WMT開発BLEUは26.7から26.5へ、Billion WordのPPLは29.9から30.2へ悪化する。品質を厳密に保ちたい場合、単一KVヘッドではなく複数KVグループを持つ方式などを検討する必要がある。

第二に、復号器の速度改善はTPUv2上の特定のモデル規模・系列長・バッチで測られた。文脈長が短い場合や大きなバッチで演算器を十分使える場合、KV読出しが支配的でなくなり、同じ12倍の改善は得られない。現代のGPUメモリ階層や専用注意カーネルでも同じ倍率になるとは限らない。

第三に、モデル全体の算術量がh分の1になるわけではない。Qヘッドごとの注意得点、値の加重和、出力統合は残り、学習時間は13.2から13.0 µs/トークンとほぼ同じである。学習高速化を目的とする場合にはMQA以外の演算・通信最適化が必要である。

第四に、実験は翻訳と言語モデルが中心であり、数十億パラメータ以上の現代的な対話LLM、長文脈検索、ツール利用、テンソル並列を伴う大規模サービングでの品質は直接評価していない。特に複数デバイスへモデルを分割する場合、単一KVヘッドを複製するか通信するかという配置問題が生じる。

第五に、論文の実装は固定長パディングを用いており、可変長のキャッシュ管理、連続バッチ処理、断片化、同時要求数の変化といった現代サービングの実装費用は主評価ではない。MQAの帯域削減という原理は有効でも、実運用の遅延は別途測定する必要がある。
