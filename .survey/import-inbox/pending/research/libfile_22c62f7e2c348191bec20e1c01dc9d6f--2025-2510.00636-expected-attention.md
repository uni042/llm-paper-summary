# Expected Attention: KV Cache Compression by Estimating Attention from Future Queries Distribution

## 概要

長文脈LLMでは、自己回帰生成のたびに過去トークンのキーと値をKVキャッシュへ保持するため、文脈長に比例してGPUメモリ消費が増える。論文はLlama 3系70B級で100万トークンのKVキャッシュが約320 GBに達する例を挙げる。既存の削除方式は、直近問い合わせがどのキーへ注意したかを重要度に使うことが多い。しかし圧縮したい時点では未来の問い合わせはまだ存在せず、FlashAttention系の実装は完全な注意行列をメモリへ実体化しないため、過去の注意スコアを後から参照することにも実装上の摩擦がある。

Expected Attentionは、未来の問い合わせベクトルそのものを予測する代わりに、その**分布**を推定する。現代LLMの隠れ状態がおおむねガウス分布に従うという観測から、問い合わせ射影後の平均・共分散を求め、各キーが未来の問い合わせから受ける非正規化注意の期待値をガウス分布のモーメント母関数で閉形式計算する。さらに値ベクトルが残差ストリームへ与える大きさを掛け、単に「注目されやすいキー」ではなく「出力へ大きく寄与しそうなKV対」を残す。

この方式は追加学習やモデル構造変更を必要とせず、プリフィル後の一括圧縮と生成中の逐次圧縮の双方へ適用できる。Qwen3-8BのRULER 16kでは、50%圧縮時に無圧縮92.9点に対して92.7点を維持し、TOVA 76.2、SnapKV 62.8、KeyDiff 74.5を上回る。75%圧縮では85.6点まで低下するため、圧縮率を上げても完全に無損失ではないが、同条件の比較方式より劣化が遅い。

## 問題設定

KVキャッシュ内の各対 `(k_i, v_i)` の本当の重要度は、将来の問い合わせ `q_t` がキー `k_i` へ与える注意重みと、値 `v_i` が出力射影を通じて残差ストリームへ与える変化の積で決まる。論文はトークン `i` の寄与を `Δh_ti = a_ti W_o v_i` と分解し、そのL2ノルム `||Δh_ti|| = a_ti ||W_o v_i||` を理想的な重要度として置く。ここでは注意重みだけでなく値側の大きさも含むため、同じ注意重みでも出力への実効寄与が違うKV対を区別できる。

問題は `a_ti` が未来の `q_t` に依存することである。SnapKVやTOVAのように観測済み注意を使う方式は、将来の利用を過去の注意から外挿する。一方、プリフィル終了直後には生成トークン由来の問い合わせがまだなく、デコード中も将来問い合わせは未知である。さらにFlashAttentionはタイル単位でsoftmaxと集約を行い、完全な注意行列を保存しない。このため「過去の全注意を保持して後で重要度を再計算する」設計は、メモリ効率を狙う実装と相性が悪い。

Expected Attentionは、個々の未来問い合わせを当てる問題を「未来問い合わせが従う確率分布の下で、各キーが平均的にどれだけ注意されるか」という期待値計算へ置き換える。これにより、未来トークンを生成する前でもKV対を順位付けでき、注意行列の保存も不要になる。

## 手法

### 残差ストリーム寄与を基準にした重要度

まず各KV対の価値を、注意重みだけではなく残差ストリームへの寄与として定義する。問い合わせ `q_t` とキー `k_i` の内積から得る注意重みを `a_ti`、値の出力射影を `W_o v_i` とすると、KV対がその注意ブロックで加えるベクトルは `a_ti W_o v_i` である。したがって、その大きさを最小化するように削除対象を選べば、注意ブロック出力への摂動を直接抑える方向になる。

値側の `||W_o v_i||` はKV対を作った時点で評価できるが、未来の `a_ti` は直接得られない。そこで次段の期待注意推定が、この未知量を分布期待値で置き換える。つまり、入力は現在までの問い合わせ統計・キー・値で、出力は各KV対の期待残差寄与スコアである。

### 問い合わせ分布と位置情報の平均化

隠れ状態を `h ~ N(μ, Σ)` と近似すると、線形な問い合わせ射影と回転位置埋め込み（RoPE）を通った問い合わせもガウス分布になる。位置 `t` の問い合わせは `q_t = R_t W_Q h_t` なので、平均は `R_t W_Q μ`、共分散は `R_t W_Q Σ W_Q^T R_t^T` になる。

未来の各位置ごとに別々の分布を扱うと計算が重くなるため、論文は次の `T` 位置のRoPE行列を平均した `R̄` を用い、未来区間を1つの位置平均問い合わせ分布 `q̄ ~ N(μ̄_q, Σ̄_q)` で表す。これが「どの未来トークンが来るか」ではなく「将来区間の問い合わせが統計的にどこへ向きやすいか」を表す状態となる。

この近似には、活性分布がガウス近似から大きく外れる場合や、未来位置ごとのRoPE差を平均することで重要な位置依存性が失われる可能性がある。ただし個別未来問い合わせの生成や補助予測モデルを必要としないため、学習不要で圧縮判断を行える。

### 閉形式の期待注意

固定キー `k_i` に対して、非正規化注意は `z_i = exp(q̄^T k_i / √d)` である。`q̄` がガウス分布なら、その指数線形形式の期待値はモーメント母関数から

`ẑ_i = exp( μ̄_q^T k_i / √d + k_i^T Σ̄_q k_i / (2d) )`

と閉形式で求められる。全キーの `ẑ_i` を正規化して期待注意 `â_i` を作るため、未来問い合わせを実際にサンプリングして何度も注意計算する必要がない。

最終スコアは `(â_i + ε) ||W_o v_i||` である。`â_i` がキー側の「将来参照されやすさ」、値ノルムが参照されたときの「残差ストリームへの影響」を表す。圧縮率 `r` が指定されると、このスコアが低い順に `r%` のKV対を削除する。疑似コード上は問い合わせ統計の平均・共分散、キーとの二次形式、softmax、値ノルム、上位選択という処理順になる。

### ヘッド適応予算

注意ヘッドは同じ役割ではなく、削除に敏感なヘッドと冗長なヘッドがある。そのためExpected Attentionは、全ヘッドへ同じ残存数を割り当てるだけでなく、Ada-KVで使われる層・ヘッド適応型の予算配分を取り入れる。重要なヘッドへより多くのKV対を残すことで、同じ総KV予算でも品質低下を抑える。

この機構は期待注意そのものとは別に「限られた残存枠をどのヘッドへ渡すか」を決める。期待注意がヘッド内部のKV順位を与え、適応予算がヘッド間の容量配分を調整するという二段構成になる。

### プリフィルとデコードでの利用

プリフィルでは入力文脈を処理した後に問い合わせ統計を取り、生成開始前にKVキャッシュを一度圧縮する。生成問い合わせがまだ存在しない段階でも期待注意を計算できる点が、観測済み生成注意に依存する方式との差になる。

デコードでは生成に伴ってKVキャッシュが増えるため、同じスコア原理を逐次圧縮へ使う。論文は長文脈理解用のプリフィル評価だけでなく、長い思考過程を生成する推論モデルでも評価し、単一フェーズ専用の圧縮則ではないことを検証している。

## 主要結果

| 条件 | 無圧縮 | Expected Attention | 主な比較方式 | 読み取れること |
|---|---:|---:|---:|---|
| Qwen3-8B / RULER 4k / 50%圧縮 | 95.3 | 94.7 | TOVA 77.6、SnapKV 55.7、KeyDiff 78.6 | 半分削除しても基準値から0.6点の低下に抑える |
| Qwen3-8B / RULER 16k / 50%圧縮 | 92.9 | 92.7 | TOVA 76.2、SnapKV 62.8、KeyDiff 74.5 | 長い16k条件でも無圧縮に近い |
| Qwen3-8B / RULER 16k / 75%圧縮 | 92.9 | 85.6 | TOVA 68.7、SnapKV 41.7、KeyDiff 66.9 | 高圧縮では劣化するが比較方式より高い |
| Qwen3-8B / RULER 16k / 90%圧縮 | 92.9 | 62.7 | TOVA 52.4、SnapKV 26.8、KeyDiff 53.1 | 90%削除では品質低下が大きく、無損失ではない |
| Gemma3-12B / RULER 16k / 50%圧縮 | 86.0 | 76.6 | TOVA 62.5、SnapKV 46.4、KeyDiff 72.6 | モデルによって同じ50%圧縮でも低下幅が異なる |
| Gemma3-12B / RULER 16k / 90%圧縮 | 86.0 | 41.8 | TOVA 32.7、SnapKV 31.4、KeyDiff 37.2 | 極端な圧縮では提案法も大きく劣化する |

結果は「60%程度まで常に無損失」という意味ではない。Qwen3-8Bでは50%圧縮まで非常に安定している一方、Gemma3-12Bの16kでは50%でも86.0から76.6へ低下する。したがって許容できる圧縮率はモデル・データセット・文脈条件に依存する。

論文はデコード側でも、長い推論トークンを生成するQwen-R1系とOpenMath-NemotronをAIME25/MATH-500で比較し、プリフィル専用方式ではなく生成中圧縮でも競争力があることを示す。ただし、本文で報告される中心指標はタスク品質と圧縮率であり、エンドツーエンドのサービング・スループットや初回トークン遅延を主結果として示すシステム論文ではない。

## 既存研究との差

SnapKVやTOVAは観測済みの問い合わせが与えた注意スコアからKV対を順位付けする。これは「過去に注目されたものは今後も重要」という信号を使うのに対し、Expected Attentionは問い合わせ活性の平均・共分散から**まだ存在しない未来問い合わせに対する期待注意**を計算する。したがって生成前のプリフィル圧縮でも同じ原理を使える。

StreamingLLMは初期の注意シンクと直近トークンを残す位置ヒューリスティック、KNormはキーのL2ノルムを用いる。これらは完全注意行列を必要としない点では実装しやすいが、値ベクトルが残差ストリームへ与える寄与と、未来問い合わせ分布を同時には扱わない。Expected Attentionは `â_i` と `||W_o v_i||` を積にすることで、キー側の将来参照確率と値側の出力影響を1つの削除スコアへ統合する。

DuoAttentionのような方式はヘッドを検索型とストリーミング型へ分けるための学習を行う。Expected Attentionは既存の事前学習済みモデルへ追加学習なしで適用することを目的とし、モデル構造自体も変更しない。その代わり、推論時に問い合わせ統計とキーごとの期待値を計算する追加処理を負担する。

## 限界

Expected Attentionの核は隠れ状態・問い合わせをガウス分布として扱う近似であり、モデル・層・入力分布によってこの近似精度が変わり得る。さらに未来の複数位置のRoPEを平均するため、特定位置に強く依存する注意パターンを完全には表現しない。

圧縮判断には問い合わせの平均・共分散と、各キーに対する線形項・二次形式、値の出力寄与ノルムの計算が必要になる。注意行列を保存する必要はないが、単純な位置削除方式より圧縮処理自体の計算は複雑である。圧縮処理時間がサービング全体の遅延・スループットへ与える影響は、論文の主要評価表では中心的に定量化されていない。

品質は圧縮率に対して単調に安全ではない。Qwen3-8BのRULER 16kでは50%圧縮時92.7点だが90%では62.7点、Gemma3-12Bでは50%でも86.0から76.6へ下がる。したがって固定の高圧縮率を全モデル・全タスクへ適用する運用は、論文結果からは支持されない。

評価モデルは8B〜15B級が中心であり、70B級や複数GPUの本番サービング環境での実測メモリ帯域・スループット改善は主要評価範囲外である。手法はKVメモリ容量を直接減らすが、その容量削減が実際の同時実行数やトークン毎秒へどの程度変換されるかは、利用する推論基盤とハードウェアに依存する。
