# FlashPrefill: Instantaneous Pattern Discovery and Thresholding for Ultra-Fast Long-Context Prefilling

> 注意パターンを高速ブロック検索し、並べ替え不要の動的しきい値で疎化することで、プリフィルを256Kで最大27.78倍、4Kでも1.71倍高速化。

## 概要
長文脈のプリフィル（prefill）は全入力トークン間の注意を一度に計算するため、系列長が伸びると二次計算が急増する。疎注意は候補を減らせるが、どこを残すか探す検索処理が高価だと、短中文脈では密注意より遅くなる。FlashPrefillは検索自体を軽量化し、垂直（vertical）、斜線（slash）、ブロック疎（block-sparse）の複数パターンを一度に発見して即座に疎attentionへ渡す。

## 問題設定
既存の動的疎注意は、attention scoreを広く計算した後で上位要素を並べ替える、累積確率を求める、別の検索カーネルを何段も実行する、といった前処理を必要とする。この固定費が4K〜16K程度では疎化の節約を打ち消し、長文脈専用最適化になりやすい。

## 手法
高速ブロック検索（fast block searching）はquery/keyの局所構造から、列方向に繰り返し参照される垂直パターン、近傍へ伸びる斜線パターン、局所的に密なブロックを同時抽出する。別々の探索器を走らせず、一つの検索段階で候補を構成する点が重要である。

動的しきい値処理（dynamic thresholding）は全候補を上位順へソートせず、現在のscore分布から不要な長い裾をしきい値で落とす。固定top-kでは入力ごとの必要疎度を表現しにくいのに対し、しきい値を動的に変えることで重要scoreが多いqueryには多く、少ないqueryには少なくブロックを残す。

## 評価条件・主要結果
| 項目 | 結果 |
|---|---|
| 対象 | 長文脈プリフィル |
| 最大系列長 | 256K |
| 256K | 最大27.78倍高速化 |
| 4K | 1.71倍高速化 |
| 疎パターン | vertical / slash / block-sparse |
| 実装 | PyTorch 2.9、Triton 3.3系の公開実装 |

特に4Kでも1.71倍という結果は、検索オーバーヘッドを小さくした設計意図を示す。長文脈で疎度が上がるほど計算削減が大きくなり、256Kでは27.78倍へ伸びる。

## 既存研究との差
単一の固定疎パターンではなく、入力ごとに複数パターンを同時発見する。上位kを得るための完全sortや累積score計算を避けるため、疎化判定そのものがプリフィルのボトルネックになりにくい。

## 限界
主対象はプリフィルであり、自己回帰デコードのKV読み出し最適化を同じ倍率で高速化する方式ではない。速度はGPU、系列形状、残存疎度、Triton実装に依存する。しきい値で落としたattentionは復元されないため、品質維持はモデルとタスクごとの疎化耐性に依存する。
