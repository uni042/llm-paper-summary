# Ubiquitous memory augmentation via mobile multimodal embedding system

> 端末上のマルチモーダル埋め込みを早期終了の粗い埋め込みで肩代わりし、検索時に残りの層で仕上げるReminisceは、終了予測・共有LoRAによる癒合・投機的な細粒度検索の3設計で、精度低下を抑えながら平均12.4倍のスループットと大幅な省電力を達成する。

## 概要

人が見聞きする情報は膨大で、その大半は忘れ去られる。スマートフォンなどの端末がユーザーの体験を記録し、マルチモーダル埋め込みモデル（テキスト、画像、音声などを共通のベクトル空間へ写すモデル、以下MEM）で全てを埋め込み化しておけば、後から自然文のクエリで過去の体験を意味検索できる「記憶の宮殿」型のサービスが作れる。すでにそのような製品も現れている。しかしMEMは10億パラメータ級と大きく、モバイル機器のCPUでは画像1枚の埋め込みに数十秒かかる。著者らの測定では、CPU動作のMEMが埋め込み化できるのは1日分の画像の2割程度で、全て処理するには100時間を超える。消費電力も大きく、INT4量子化したMEMの消費電力はゲームの1.8倍に達し、連続埋め込みでは電池が2時間もたない。

本論文のReminisceは、埋め込みの「粗さ」を段階的に使い分けることでこの壁を崩す。基本の発想は、早期終了（アーリーイグジット）で途中の層から取り出した粗い埋め込みでも、候補を絞り込む用途には十分役立つという点にある。オフラインの「覚える」処理では粗い埋め込みで全データを安く索引化し、オンラインの「思い出す」処理では、絞られた候補についてだけ残りの層を実行して細かい埋め込みへ仕上げ、正確な検索結果を返す。粗い埋め込みの精度不足は、LoRAによる癒合（ヒーリング）で回復させる。

**代表結果:** 既定のMEMであるImageBind hugeを対象に、4種の実機（Jetson Orin、Jetson TX2、Raspberry Pi 4B、Snapdragon 8 Gen 3搭載スマートフォン）と5種のデータセットで評価した結果、元のMEMに対して平均12.4倍の埋め込みスループットを達成した。音声データセットCLOTHOとJetson Orinの組合せでは45倍のスループットを、既定のクエリ遅延予算1.5秒の下で相対精度低下3パーセント未満に抑えて達成している。消費電力は層単位のベースラインに対して最大29倍、平均20倍低く、単一ブロックとして実行する素朴なMEMに対しても平均7倍低い。

## 問題設定

端末上で常時動く埋め込み処理には、スループットと消費電力の両面で厳しい制約がある。データはユーザーが起きている間ずっと流れ込み続けるため、処理が追いつかなければ未処理のデータが溜まり、サービスの前提である「全てを覚えている」状態が崩れる。電池駆動の機器では、埋め込み処理が電池を食い潰せば本末転倒であり、発熱や他のアプリへの影響も避けなければならない。

一方で、埋め込みの使われ方には非対称性がある。全データに対する埋め込みは索引化のためのもので、その時点で必要なのは「後で候補として拾えること」であって、最終的な検索順位の正確さではない。正確さが本当に要るのは、クエリが来て候補が少数に絞られた後の段階である。にもかかわらず通常の実行は、全データに対して最も細かい埋め込みを最初から作る。早期終了型ネットワークの研究は推論の高速化として知られているが、粗い埋め込みをそのまま使うと検索精度が大きく落ちること、終了位置ごとに適応用のパラメータを用意すると中間結果の再利用と衝突すること、といった課題があり、埋め込み基盤としての利用は進んでいなかった。本論文はこの非対称性に着目し、粗い埋め込みの精度回復と、検索時の仕上げを組み合わせた実行方式を設計する。

## 手法のあらまし

Reminisceは2つのランタイムからなる。オフラインの埋め込みランタイムは、流れ込むデータを早期終了つきのMEMで処理し、粗い埋め込みと、後で仕上げに使う中間活性を保存する。オンラインのクエリランタイムは、クエリの埋め込みで粗い索引を検索して候補を絞り、候補について残りの層を実行して細かい埋め込みへ引き上げてから最終順位を決める。

この土台の上に3つの設計が乗る。第1に、データ依存の事前終了予測器である。サンプルごとに「どの層で終了すれば十分か」を、フルモデルの埋め込みを教師とする教師なしの方法でラベル付けし、中間埋め込みから終了位置を予測する小さなMLPを学習する。終了位置が実行前に分かるため、同じ終了位置のサンプルをまとめてバッチ化でき、層の読み込みと計算を重ねるパイプラインも組める。第2に、段階的なLoRA癒合である。終了位置ごとに別々のLoRAを用意すると中間活性の再利用が壊れるため、全終了位置で1組のLoRAを共有し、層ごとに順に学習を進め、後の終了位置ほど調整する層数（LoRAステップ）を大きくする。これにより粗い埋め込みの検索精度が大きく回復する。第3に、投機的な細粒度検索である。クエリ側も複数粒度の埋め込みを持ち、各粒度で上位候補を集めて統合し、最後に候補の粗い埋め込みを残りの層で仕上げて検証・訂正する。粗い段階で本来の正解を取りこぼす危険を、複数粒度の候補の和集合で抑える設計である。

## 手法

### 1. データ依存の事前終了予測器 — 終了位置を先に知ってバッチ化とパイプラインを可能にする

この機構が観測するのは、各サンプルの中間埋め込みと、フルモデルの細かい埋め込みである。学習時のラベル付けは教師なしで行う。細かい埋め込みFxをそのサンプルの代理クエリとみなし、各粒度の粗い埋め込みCixでFxを検索したとき、最も近い粗い埋め込みが正しい粒度のものであれば、その終了位置は有効だと判定する。こうして得たラベルで、中間埋め込みを入力とする小さなMLP予測器を学習する。保持する状態は予測器そのものと、サンプルごとの予測終了位置である。推論時は、サンプルが来た時点で予測器が終了位置を決めるため、同じ終了位置を持つサンプル同士をバッチにまとめられる。さらに層ごとの重みの読み込みと計算を重ねるパイプラインスケジューリングが可能になり、表層の埋め込みの再利用と合わせて埋め込みスループットが最大で30パーセント向上する。

これにより減るボトルネックは2つある。1つは、サンプルごとに終了位置がばらばらでバッチ化できないことによる非効率である。もう1つは、重みの読み込み待ちで計算が止まる時間である。誤判定時の挙動として、予測が浅すぎる終了位置を選ぶと、そのサンプルの粗い埋め込みの精度が落ちて候補から漏れる危険がある。論文の測定では、予測器は固定層で終了させる方式に比べて検索精度を最大19.8パーセント改善しており、データ依存に選ぶこと自体が精度面でも有利だと示されている。

### 2. 段階的なLoRA癒合 — 共有する1組のLoRAで粗い埋め込みの精度を回復する

早期終了の問題は、途中の層の埋め込みが最終層の埋め込みと分布がずれ、検索精度が落ちることである。通常の対処は終了位置ごとの適応だが、32個の終了位置があれば32組の適応パラメータが要り、しかも終了位置ごとに別のLoRAを当てると、浅い層の中間活性を深い層の計算へ再利用する仕組みと衝突する。そこでReminisceは、全終了位置で1組のLoRAを共有する。学習は層ごとに進める段階式で、前の終了位置のLoRAを固定したまま次の層のLoRAを学習し、後の終了位置ほど調整する層の数（LoRAステップ）を大きく取る。ステップの大きさは予測器の終了統計の転換点に合わせる。

これにより減るボトルネックは、粗い埋め込みの精度不足である。測定では、癒合によりゼロショットの早期終了に比べて検索精度がCOCOで平均37.8パーセント、FLICKRで平均13.2パーセント回復した。追加で消費する資源は、下流タスクごとのLoRA学習と、そのパラメータの保持である。共有方式にしたことで、オフライン処理で保存した中間活性をクエリ時の仕上げにそのまま使える性質が保たれる点が、単なる精度回復策と違うところである。

### 3. 投機的な細粒度検索 — 複数粒度で候補を集め、残りの層で検証して訂正する

この機構が観測するのは、クエリの複数粒度の埋め込みと、索引中の粗い埋め込み群である。保持する状態は、候補集合と、各候補について保存された中間活性である。処理は3段階である。第1に投機的フィルタリングとして、各粒度のクエリ埋め込みで粗い索引を検索し、粒度ごとに上位k件の候補を集める。第2に全体検証として、粒度をまたいで重複を取り除きながら最終候補の上位k件を選ぶ。第3に細粒度の訂正として、候補の粗い埋め込みを残りの層で実行して細かい埋め込みへ引き上げ、その類似度で最終順位を決める。候補プールの既定値は10件である。

これにより減るボトルネックは、クエリ時に全データへ細かい埋め込みを作り直す費用である。粗い検索だけでは精度が不足するが、仕上げの対象を候補10件程度に絞れば、残りの層の実行は安く済む。測定では、細粒度への引き上げにより粗い検索だけの場合に比べて精度が平均35.5パーセント向上し、フルモデルのMEMで検索可能な対象の95パーセント超が粗い段階の候補リストに含まれていた。さらに、縮小層の直前の中間活性を保存して再利用することで、クエリ遅延は最大70パーセント削減される。誤判定時の挙動として、粗い段階で正解が候補プールから漏れれば仕上げでは回復できないため、複数粒度の候補の和集合を取ることで漏れを抑えている。また一度仕上げた埋め込みは恒久的に細かい埋め込みへ置き換わるため、繰り返し検索されるデータについてはクエリのたびに仕上げる費用が消えていく。

| 構成要素 | 入力・観測 | 具体的な動作 | 改善対象 | 主なトレードオフ |
|---|---|---|---|---|
| 事前終了予測器 | 中間埋め込み、フルモデルの埋め込み | 終了位置を実行前に予測し同位置でバッチ化 | バッチ化の失敗と読み込み待ち | 予測ミスで浅すぎる終了を選ぶ危険 |

## 評価

### まず見るところ

- **結論:** Reminisceは、元のMEMに対して平均12.4倍の埋め込みスループットを達成しつつ、検索精度の低下を既定の遅延予算の下で数パーセント以内に抑えた。省電力の効果も大きく、実機の利用シナリオ（SNS閲覧のケーススタディと実トレースの利用者調査）でも電池消費と未処理データの両方を大きく減らしている。
- **速度・効率:** 指標は埋め込みスループット、消費電力、クエリ遅延である。比較対象は、最適化なしのMEM、早期終了のBranchyNet、終了を意識したバッチ化のFluid Batchingなどで、Fluid Batching自体がBranchyNetの3倍、MEMの6倍のスループットを持つ強いベースラインである。その上でReminisceは最大2.4倍を上乗せした。
- **品質:** 品質指標はデータセットごとの検索指標（COCOはR@5、FLICKRはR@1、CLOTHOはR@10、HARSMARTは分類精度）で、フルモデルのMEMの値（順に75パーセント、70パーセント、30パーセント、78パーセント）を基準に相対的な低下で測る。
- **評価の強さ／注意点:** 実機4種とデータセット5種に加え、実トレースの利用者調査まで行う厚い評価である。一方で、対象モデルはImageBindとCLIPの2系統に限られ、癒合には下流タスクごとの学習が前提になる。

データセットは、画像とテキストのCOCO（123,287件）とFLICKR（8,091件）、音声とテキストのCLOTHO（3,938件）、IMUセンサのHARSMART（10,299件）、そしてSNSのミーム画像803件のケーススタディである。実機は、Jetson Orin（省電力モード、INT8、GPU）、Jetson TX2（最大性能モード、INT8、GPU）、Raspberry Pi 4B（INT8、CPU）、Snapdragon 8 Gen 3搭載スマートフォン（INT4、CPU）の4種で、既定のMEMはImageBind huge、追加でCLIPでも評価している。

結果の読み方は次の通りである。まず土台の効果として、Fluid Batchingの時点でBranchyNetの3倍、MEMの6倍のスループットがあり、終了を意識したバッチ化だけでも大きな利得がある。Reminisceは予測器によるバッチ化とパイプライン、癒合による精度回復を重ね、平均12.4倍まで伸ばした。精度側の部品ごとの効果も分けて測られている。癒合は早期終了の精度をCOCOで平均37.8パーセント、FLICKRで平均13.2パーセント押し上げ、事前終了予測は固定終了に比べて最大19.8パーセント精度を改善し、検索時の細粒度化は粗い検索に比べて平均35.5パーセントの精度向上をもたらした。電力では、層単位のベースラインに対して最大29倍、平均20倍低く、素朴なMEMに対しても平均7倍低い。

実利用に近い評価も2つある。SNS閲覧のケーススタディ（スマートフォン、INT4）では、30分の閲覧で発生する画像の埋め込みを、ベースラインが80分超かかるところをReminisceは28分で終え、Fluid Batching比でも3倍のスループットだった。ピークメモリは素朴なMEMの7分の1以下（全体で200MB未満、パイプライン用バッファは50MB未満）、電力は最大4倍低く、クエリ遅延は0.5秒だった。実トレースの利用者調査では、素朴なMEMでは1日に3回超の充電が必要で画像の2割超が未処理になるのに対し、Reminisceは充電回数を3分の1に減らし、全データを処理しきった。保存量の見積もりもあり、INT4の1024次元埋め込みは1件約5KBで、1日6,000枚の画像でも約29.3MB、年約10.4GBに収まる。

## 既存研究との差

早期終了型ネットワーク（BranchyNet等）は、分類などの単一タスクの推論高速化として研究されてきた。本論文の差分は、早期終了を「埋め込み基盤の実行方式」として再設計した点にある。粗い埋め込みを最終結果ではなく候補絞り込みの中間表現と位置づけ、検索時に残りの層で仕上げることで、早期終了の弱点である精度低下を構造的に回避した。終了を意識したバッチ化（Fluid Batching）に対しては、終了位置の事前予測によるバッチ化と層パイプライン、共有LoRAによる癒合、検索時の投機的な細粒度化を重ねた点が前進である。オンデバイスの継続学習や文脈認識の研究が個別のタスク最適化に寄るのに対し、本論文は埋め込みという汎用基盤の層で常時動作を可能にしている。

## 限界・実装状況

限界は、バッチ化の並列性によりピークメモリが層単位の素朴な実行よりやや大きくなること、クエリ時にフルモデルをメモリへ載せる前提があること、癒合が下流タスクごとの学習を要し精度と遅延の交換が残ること、対象モデルがImageBindとCLIPに限られることである。実装状況は、コードの公開先が論文に明示されており、4種の実機で動作評価まで行われている。製品への組み込みではなく研究試作の段階である。

## 一般的な実装上の含意

埋め込みのような基盤処理では、「全件に最終品質を作る」前提を疑う価値がある。索引化の段階では候補として拾える粗さで十分であり、最終品質はクエリ時に少数候補へだけ払えばよい、という非対称性を利用すると、スループットと電力の桁が変わる。その際の要点は3つある。第1に、粗さの段階をデータ依存に選ぶ予測器があると、バッチ化と精度の両方が改善する。第2に、段階ごとの適応は共有パラメータで設計しないと、中間結果の再利用という仕上げの仕組みと衝突する。第3に、粗い段階の取りこぼしは後段では回復できないため、複数粒度の候補の和集合のような保険が要る。常時動作する端末上の基盤モデル一般に通じる設計原則である。
