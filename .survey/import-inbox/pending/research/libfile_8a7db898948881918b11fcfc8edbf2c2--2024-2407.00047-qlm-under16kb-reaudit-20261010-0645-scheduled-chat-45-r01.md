# QLM：期限付きLLM推論要求の待ち行列を予測・再配置する制御基盤

## 概要

QLMは、対話型の低遅延要求と、数分から数時間待てる一括処理要求を、複数の言語モデルが稼働するGPU群で混在させるための待ち行列管理システムである。従来の推論提供システムは、GPU内の連続バッチ処理や鍵・値キャッシュ管理を高速化する一方、GPUへ投入する前の要求をどの順序で、どのモデルの実行単位へ渡すかについては十分に最適化されていない。初回トークンまでの許容時間が異なる要求を単純な到着順で扱うと、余裕のある一括処理が対話要求を待たせる。期限の早い順だけにすると、複数モデルの重みをGPUへ頻繁に入れ替える費用が増える。

QLMは要求のモデル、入力・出力トークン長の分布、初回トークン期限をもとに要求群を作り、各GPU実行単位に対応する仮想待ち行列へ割り当てる。要求待ち時間推定器（Request Waiting Time Estimator; RWT Estimator）が連続バッチ処理の統計的性質と実機測定値から待機時間を予測し、全体スケジューラが期限違反を抑えるよう要求群の順序と実行先を選ぶ。決定した順序は、要求の引き込み、実行中要求の退避、モデルの交換、GPU間負荷分散という四つの操作へ変換される。

著者らはMistral-7B、Vicuna-13B、Llama-70Bを、NVIDIA A10とA100からなる実機群で評価した。ShareGPTの入出力長分布を使った実験では、到着率や比較方式によって期限達成率が40～90%改善し、単一モデルでは要求処理能力が約20%、複数モデルでは最大数倍改善したと報告する。ただし、これは定義した初回トークン期限と負荷分布での実験であり、全ての到着率で期限を保証する方式ではない。

## 問題設定

推論要求は入力プロンプトをまとめて処理する段階と、出力を一トークンずつ生成する段階を通る。生成するトークン数は要求の到着時には確定せず、GPU上での実行時間も一定ではない。このため、画像認識などの固定時間に近い推論を前提にした待ち行列推定をそのまま適用すると、待機時間を過大評価してGPUを不要に分割したり、期限違反を避けるために余分なGPUを割り当てたりする。

論文のサービス品質目標（SLO）は主に初回トークン時間の99パーセンタイルである。対話型要求には20秒、一括処理の第一群には1分、第二群には1時間という代表期限を設定する。実行前の待機時間を短縮しても、GPUがすでに長い一括要求の鍵・値キャッシュで埋まっていれば、対話要求を直ちに実行できない。これが行頭詰まり（head-of-line blocking）であり、単純に待ち行列の先頭へ要求を移すだけでは解決しない。

複数モデルを同じGPUで時分割する場合には別の問題がある。期限の近い要求をモデルに関係なく交互に実行すると、重みをCPU側からGPUへ繰り返し移すことになり、交換時間が実行時間を上回る場合がある。逆にモデルごとにGPUを完全分離すると、緩い期限の要求をまとめて実行できる余裕を活用できない。したがって、期限、要求長、現在の実行モデル、GPUの性能差、交換費用を同じ制御問題として扱う必要がある。

著者らは連続バッチ処理によって多数の要求の出力長が平均化されることに着目した。個別要求の出力長は予測困難でも、十分に長い待ち行列の総出力トークン量は統計的に安定しやすい。待ち行列の前方にある要求群が消化される時間をこの性質から見積もれば、全体スケジューラは期限を守れる組み合わせを判断できる。

## 手法

### 要求群と仮想待ち行列

QLMの入口は、アプリケーションから届く要求を保存する全体待ち行列である。論文の実装例はRabbitMQのような分散メッセージ仲介を用い、実際の要求本体を一元管理する。制御側は各要求のモデル種別、入力と出力のトークン長分布、期限を観測し、似た性質の要求をK-meansで要求群にまとめる。群が大きすぎる場合は分割し、平均バッチサイズに係数δを掛けた上限を超えないようにする。群の内部は比較的同質であり、推定器は群単位の待機時間を扱う。

各推論実行単位には一つの仮想待ち行列が対応する。仮想待ち行列は要求本体を重複保持するのではなく、全体待ち行列の要求群への参照と、その実行順序を保持する。これにより、あるGPUが停止しても他のGPUの仮想待ち行列を維持でき、停止した側の要求群を再割当てできる。群単位で決めるため、個別要求ごとに大規模な最適化を解く費用も抑えられる。

要求群を大きくすると最適化対象数が減り制御費用は下がるが、急ぎの要求だけを細かく前へ出す自由度も減る。反対に群を小さくするときめ細かな順序付けができるが、制御器が扱う変数と計算費用が増える。δはこの交換条件を決める重要な実装パラメータである。

### 要求待ち時間推定器

推定器は、要求群の前に並ぶ仕事がどの程度の時間で処理されるかを計算する。個々の要求qについて、プロンプト処理時間P、出力トークン数Oq、トークン当たり生成時間d、連続バッチ処理による非効率係数εなどを考える。生成時間はおおむね出力長に比例するが、GPUメモリ不足による一時停止や要求の追加で理想的な線形関係からずれるため、εでその損失を表す。要求群の完了時間は群内の要求の完了時間の最大値を基に見積もる。

モデルとGPUの組み合わせごとに、入力・出力長の分布をサンプリングし、実機で一バッチを動かしてプロンプト処理時間や生成速度を測定する。実装ではvLLMへ計測項目を追加し、推定器に必要な定数を取得する。大量の事前学習を新しいモデルごとに実施する設計ではない。長い待ち行列では総仕事量が平均化されるため、論文は四つの要求群を用いた条件で待機時間推定の決定係数R²が0.99に達したと報告する。

ただし短い待ち行列では平均化が働きにくく、推定器は待機時間を保守的に長く見積もる。出力長が観測分布から大きく外れる場合には逆に過小評価し、期限違反を起こす可能性がある。推定値は予測であり、個別要求の生成長を正確に知る仕組みではない。

### 全体スケジューラと線形計画

全体スケジューラは、推定器が期限違反の可能性を検出したとき、各要求群をどの仮想待ち行列のどの位置へ置くかを最適化する。二値変数で群と位置の割当てを表し、各位置までに処理する要求群の待機時間、異なるモデルへ切り替える際の重み交換時間、GPUやモデルごとの処理能力を足し合わせる。各要求群について、推定待機時間からその群の期限を引いた値を違反量として扱う。

論文の線形計画は、群の重複割当てを避ける制約、モデルが変わる位置の交換費用、期限に関する制約を持つ。期限内に収められる配置を探し、違反量を減らす目的関数で群の順序を決める。単純な最短期限優先と異なり、同じモデルの要求群をある程度まとめてモデル交換回数を減らせる。ただし容量不足で実行可能な解がなければ、最適化だけでは期限を守れず、GPUの追加が必要になる。

### 四つの推論提供操作への変換

全体スケジューラが仮想待ち行列を変更すると、各推論実行単位のQLMエージェントが四つの操作を実施する。要求の引き込みは、待ち行列の先頭にある要求をGPUの実行バッチへ追加する操作である。実行中要求の退避は、緩い期限の要求を一時的にバッチから外し、急ぎの要求が使うGPUメモリを空ける操作である。退避した要求の鍵・値キャッシュは非同期にCPU側へ移し、後で続きから再開できるようにする。

モデル交換は、次に実行する群が現在GPUに載っていないモデルを必要とするとき、重みを入れ替える操作である。負荷分散は、複数の実行単位の仮想待ち行列を組み替え、性能の低いGPUへ過剰な仕事が集中しないようにする操作である。これらは単独の新しいカーネルではなく、全体スケジューラが決めた順序を下位推論基盤の動作へ変換する制御機構である。

この連動が重要なのは、単に対話要求を先頭へ移すだけではGPUメモリ不足による待ちが残り、単にモデル交換を減らすだけでは急ぎの要求が遅れるためである。QLMは仮想待ち行列の順序という共通の表現から、要求の投入、退避、交換、負荷分散を一貫して制御する。

## 評価

### 実験構成

| 観点 | 一次論文の条件 |
|---|---|
| 下位推論実行系 | vLLM、連続バッチ処理 |
| モデル | Mistral-7B、Vicuna-13B、Llama-70B |
| GPU | NVIDIA A10 24GBを30基、A100 80GBを50基の構成を用いた異種実機環境 |
| 要求 | ShareGPT由来の入力・出力長分布、各負荷追跡は3,500要求 |
| 到着 | ポアソン到着を使い、到着率を変更 |
| 期限 | 対話20秒、一括処理第一群1分、第二群1時間。主に初回トークン時間の99パーセンタイル |
| 比較 | vLLMの到着順、最短期限優先（EDF）、SHEPHERD |
| 指標 | 期限達成割合、要求処理能力、推定精度、制御費用、異種GPUでの頑健性 |

負荷は単一モデルで対話と一括処理を混ぜる条件、複数モデルで一括処理を混ぜる条件、大きい入力・出力を持つ要求を混ぜる条件に分かれる。大きい要求の代表長は入出力合計3,000～4,000トークンである。対話と複数モデルを同時に混ぜた条件については、モデル交換時間が20秒の対話期限を超えるため、QLMがモデルごとにGPUを分離する結果となり、独立した実験結果としては提示していない。

### 単一モデルの期限達成と処理能力

50基のA100で単一モデルの混合要求を処理すると、QLMは到着率が処理能力を下回る範囲で、到着順・最短期限優先・SHEPHERDより多くの期限を満たす。0.5千要求/秒の対話到着率では、vLLMと最短期限優先に対して要求処理能力が約20%、SHEPHERDに対して約50%高い。最短期限優先は順序だけを変えるため、GPUが長い一括要求で埋まったときの退避を十分に扱えない。QLMは退避によって行頭詰まりを減らす。

ただし到着率がGPUの物理的な処理能力を大きく超えた条件では、どの方式も指定期限を満たせない。これはスケジューラが劣っているというより、要求を処理する最短時間が期限を超えるためである。論文はGPUを増やす拡張を別の対策として評価しており、待ち行列の並べ替えだけで無制限の負荷を処理できるとはしていない。

### 複数モデルでの重み交換削減

複数モデルの一括処理では、同じモデルを必要とする要求を群としてまとめることで、要求ごとに重みを交換する回数を減らす。論文の図12では、到着率に応じて比較方式に対する処理能力が最大約3～4倍となる条件がある。第一群の到着率が0.5千要求/秒未満では、QLMが全期限の90%超を満たす条件も報告される。モデル交換と群の順序付けを同時に扱うことが、この結果を支える。

モデル交換操作を外す構成要素除去実験では、複数モデルの処理能力が大きく悪化する。論文の総括ではモデル交換が複数モデル条件の処理能力を約300%改善し、要求退避が単一モデル条件の期限達成を約80%改善したと述べる。ただしこれらは各操作を外した条件との差であり、全体の比較方式に対する改善率と同じ母数ではない。

### 推定精度、異種GPU、巨大要求、制御費用

要求待ち時間推定器の精度は待ち行列が長くなるほど高く、四要求群の条件でR²が0.99に達する。A10とA100の混在実験では、実機測定でGPUごとの処理能力を把握し、A10へ割り当てる要求を抑えることで、均等な巡回割当てより期限達成を改善する。GPU構成が均一なときより、性能差があるときに負荷分散の価値が大きくなる。

巨大な入力・出力を持つ要求が少数混ざる条件では、それらを別の実行単位へ集め、通常要求の行頭詰まりを避ける利得がある。巨大要求が増えすぎると全GPUで同じ詰まりが起こり、分離だけでは対応できなくなる。論文は要求群サイズの係数δを変えたとき、群を大きくすると線形計画の計算費用が減る一方、粗い割当てによって処理能力が低下することも示す。

大規模待ち行列に対しては、個別要求ではなく要求群を最適化単位にすることで、制御費用を抑える。論文は一部構成で40万要求規模を扱う場合、群当たり約5秒、要求当たりに換算して約5ミリ秒の計算費用という例を報告する。これもGPUと要求群サイズに依存する数値であり、全てのクラスタで同じ計算時間となるわけではない。

## 限界と適用範囲

待機時間推定器は、出力トークン長の分布と実機測定が代表的であることを前提とする。待ち行列が短い場合には待機時間を過大評価してGPUを十分に使えない可能性がある。論文の議論では、出力長が平均から5～10標準偏差以上外れるような稀な要求では、完了時間を過小評価し期限違反につながる可能性も指摘される。モデルや負荷が変わったときのプロファイル更新も運用上必要である。

全体スケジューラは実行可能な割当てが存在しない負荷を解決できない。モデル交換時間が対話期限より長い場合には、異なるモデルを同じGPUで時分割するのが不適切となり、GPUを分離する必要がある。極端に高い到着率や巨大要求が大量にある条件ではGPUの増設が必要となる。要求群による集約は制御計算を減らすが、群内の個別要求のばらつきを隠すため、細かい公平性を自動的に保証しない。

実験の主な品質指標は初回トークン時間の期限達成率であり、生成中のトークン間遅延を直接最適化することが中心ではない。論文は他の仕組みと組み合わせて後者を扱う可能性を述べるが、全ての期限を同時に保証した証拠ではない。実機評価はA10とA100、vLLM、ShareGPT由来の要求分布を基にしており、他のアクセラレータや大幅に異なる生成長分布へそのまま倍率を外挿できない。
