# CommitMoE: Efficient Fallback-Free MoE Inference with Offloading Under GPU Memory Constraints

## 概要

混合専門家モデル（MoE）では、各トークンで一部の専門家しか実行しないにもかかわらず、モデル全体の専門家重みは大きく、単一GPUのメモリに収まりにくい。不要な専門家をCPU側に退避し、必要時だけGPUへ読み込む方式は容量を節約するが、CPU・GPU間の転送が推論遅延を支配する。次の層で使いそうな専門家を予測して先読みすれば待機を減らせるが、予測が外れた場合、先読みした重みの転送が終わってから正しい専門家を改めて読み込むため、むしろ遅くなる場合がある。

CommitMoEは、この**誤予測時の再読み込みそのものを廃止**する。現在の層の隠れ状態から次層の専門家集合を予測し、非同期転送を始める。次層に到達した時点で元のルータが別の専門家を選んでいても、GPUへ準備済みの予測専門家を実行対象として確定する。元のルータの重みは、準備済み専門家の出力を補正する出力重み調整（OWA）に利用できる。この設計は**元モデルの専門家選択を変更する近似推論**であり、正しい専門家を必ず使う無損失な先読みとは区別する必要がある。

著者らはRTX 4090とRTX 2080 Tiの二つのGPU環境、Qwen1.5-MoE-Chat、DeepSeek-V2-Lite-Chat、Mixtral-8×7B-Instructを用いて、vLLMやMoE-Infinityとの端から端までの推論遅延を比較した。GPU・PCIeが制約されるRTX 2080 Ti環境では、vLLMに対してQwenで最大9.4倍、DeepSeekで7.5倍、Mixtralで4.3倍の高速化を報告する。品質は複数の課題で元モデルに近いが、Qwenの平均点が43.17から43.06へ下がる例や、MixtralでOWAを入れると入れない場合より平均点が低い例もある。速度と品質を別々に監査する必要がある。

## 問題設定

### GPUメモリ制約と予測ミス時の二重転送

MoE層のルータはトークンの隠れ状態xから各専門家への確率分布 `G(x)=softmax(W_g x)` を求め、上位k個を選ぶ。GPUに全専門家を保持できない場合、CPUメモリに退避した専門家重みを選択後に転送する。モデルが大きいほどPCIe転送時間が支配的になり、論文図1は活性専門家数が2・4・6の代表モデルについて、オンデマンド方式で転送が層の遅延の大半を占めることを示す。

先読み方式では予測集合Pを先にGPUへ転送し、実際のルータ集合Tと一致すれば転送待ちを隠せる。しかしPとTが異なる場合、CUDAの非同期コピーは開始後に都合よく取り消せず、誤った重みの転送完了を待ってから正しい重みを再度転送する。論文はこの追加の転送により、予測ミス一回につき13.7〜47.6%の遅延増分が生じる例を示す。単に予測精度を少し上げるだけでは、外れたときの最悪費用を消せない。

### ルータの確信度と専門家置換への耐性

著者らはQwen1.5-MoE-ChatとDeepSeek-V2-Lite-ChatのGSM8K推論で、元のルータの確率分布と一様分布とのカルバック・ライブラー発散（KLD）を確信度の指標に使う。分布が尖っているほどKLDが高く、専門家選択が明確である。KLDが高い入力では次層の専門家を予測しやすく、KLDが低い入力では予測が外れやすい。一方、確信度が低い入力では専門家集合を別の候補へ置き換えても、下流課題の正解率が大きく変わらない場合がある。

論文表1では、予測した専門家が元の選択と一つも一致しないトークンに限定して置換を行い、QwenのGSM8Kが53.22%から54.51%、BBHが36.67%から36.75%、DeepSeekのGSM8Kが69.59%から69.74%、BBHが49.12%から49.16%となる。これらは置換に耐える例を示すが、任意の入力や任意の専門家で品質が変わらないという数学的保証ではない。元のルータが強く選好する専門家を誤って置き換えた場合は影響が大きくなる可能性がある。

## 手法

### 1. 次層専門家を予測する確定ルータ

Commit Routerは、現在のMoE層の元ルータに渡す隠れ状態を受け取り、次のMoE層の専門家確率分布を推定する。現在トークン内で隣接層を予測する場合は一層の多層パーセプトロン（MLP）、前トークンの最終MoE層から次トークンの最初のMoE層を予測する場合は、隠れ次元を入力の2倍にした二層MLPを用いる。後者はトークン境界をまたぐため予測が難しく、少し大きな予測器が必要になる。

予測器は事前学習済みMoEの元ルータを変更せず、元ルータの確率分布を教師としてオフラインで学習する。学習目的は、元ルータの正解ロジットを正規化した分布と予測分布のKLDを小さくすることである。次層の上位k個を予測集合Pとして選び、現在層の計算中にCPUからGPUへ非同期で転送する。デコード最初のトークンの最初のMoE層だけは通常の専門家選択を使い、その後のトークン先頭層は前トークンの最終層から予測する。

### 2. 予測集合をそのまま実行する確定方式

次層へ到達すると、CommitMoEは**予測集合Pに含まれる専門家を必ず実行**する。元のルータも通常どおり重み付けスコアを計算するが、その結果が別の専門家集合Tを指していても、Tを新たにロードしない。これが再読み込みなし（fallback-free）の意味である。誤予測のときに正しい専門家を待つ方式と異なり、予測ミスがCPU・GPU間の二重転送を生む経路を断ち切る。

この選択により、元のモデルが実行したはずの専門家の非線形変換を、別の専門家で置き換えることになる。予測器の精度が高いほど近い結果になりやすいが、元の出力分布と完全一致する保証はない。速度が上がる理由は「予測が正確になった」ことだけではなく、**予測が外れた場合にも元の専門家を実行することを諦めた**点にある。無損失先読みの速度比較と同じ品質制約であるかを確認する必要がある。

### 3. 出力重み調整（OWA）

元のルータが選んだ集合Tと、準備済みの予測集合Pが部分的に一致する場合、元のルータが選んだ専門家のスコアを利用して、実行可能な専門家の混合重みを調整する。まずTに含まれるがPに含まれない専門家の重みを集計し、P∩Tの正しく予測された専門家へ再配分する。次に重み全体の大きさが極端に変わらないよう、元ルータの重み総和と調整後の総和を用いて再尺度化する。

論文の式5・6では二つの調整係数α1・α2を使う。α1は欠けた専門家の重みをどれだけ再配分するか、α2は調整後の全体尺度をどれだけ維持するかを制御する。OWAは元の専門家関数を復元するのではなく、実行可能な専門家の出力係数を補正する。元の集合と予測集合が完全に不一致の場合、共通専門家への再配分はできないため、ルータ確信度が低い条件での置換耐性に依存する。

### 4. OWAを使う条件とモデル別設定

OWAは常に適用するわけではなく、予測が一部だけ正しく、元の専門家選択が出力へ強く影響し得る条件で使う。論文の実装では、Mixtralで正解専門家が1個、Qwenで2〜3個、DeepSeekで4〜5個予測できた場合を主な適用対象とする。専門家の活性数が多いモデルでは、重みを再配分できる共通専門家が増えるため、OWAの効果が高くなりやすい。

係数はモデルごとに検証集合で調整する。DeepSeekはα1=1.15・α2=1.00、Qwenは1.30・1.00、Mixtralは1.20・1.06を使用した。著者らは1.0〜1.4の範囲を探索しており、他モデルへ同じ係数を無条件に流用できない。活性専門家が2個のMixtralではOWAを入れない方が平均点が高く、4個以上を活性化するモデルでの利用を推奨している。

### 5. 非同期転送とデコードのパイプライン

実装はPython・C++、PyTorch、MoE-Infinityを基盤に、CUDAの複数ストリームを使って転送と計算を重ねる。現在層の計算が進む間に次層の予測専門家を読み込み、次層へ到達したらその集合で計算する。これにより、元のルータの選択を待ってから重みを転送するオンデマンド方式より、転送時間を前段計算に隠せる。先読みミス時に二回目の転送を起こさないため、PCIe帯域が狭い環境ほど相対的な効果が大きくなる。

### 1. ルータ確信度と予測精度の相関（図2・表1）

ルータのソフトマックス分布が一様分布から遠いほどKLDが高く、専門家選択の確信度が高いと定義する。予測専門家集合と元の集合の一致率が75〜100%の群では平均KLDが高く、0%一致の群では低い。低確信度の入力で予測集合へ置換した場合の品質耐性を調べるため、予測が一つも当たらないトークンだけ置換する実験を行った。

|モデル|課題|元モデル|予測専門家への置換|読み方|
|---|---|---:|---:|---|
|Qwen1.5-MoE-Chat|GSM8K|53.22%|54.51%|この条件では平均正答率がわずかに上昇|
|Qwen1.5-MoE-Chat|BBH|36.67%|36.75%|ほぼ同程度|
|DeepSeek-V2-Lite-Chat|GSM8K|69.59%|69.74%|ほぼ同程度|
|DeepSeek-V2-Lite-Chat|BBH|49.12%|49.16%|ほぼ同程度|

この結果は「予測が外れても必ず正解率が上がる」ことを示すものではない。測定対象のモデルと課題で、低確信度に対応する置換が比較的許容されたことを示す観察である。高確信度の専門家を置き換えた場合には、品質が悪化する可能性がある。

|モデル|元モデル平均|CommitMoE・OWAなし|OWAあり|主要な注意点|
|---|---:|---:|---:|---|
|Mixtral-8×7B-Instruct|50.85|51.02|50.73|OWAがむしろ平均点を下げる|
|Qwen1.5-MoE-Chat|43.17|42.38|43.06|OWAで改善するが元よりわずかに低い|
|DeepSeek-V2-Lite-Chat|47.81|48.16|48.48|この実験ではOWAが有利|

QwenのGSM8Kは元53.22、OWAなし50.34、OWAあり52.24であり、OWAにより元モデルとの差が2.88点から0.98点へ縮まった。DeepSeekのGSM8Kは元69.60に対しOWAあり70.05だった。QwenではOWAによって元ルータの出力とのコサイン類似度が最大19%高くなったと報告する。ただし平均点が近いことは、個々の生成文が同一であることを意味しない。

### 3. 二つのGPU環境における端から端までの高速化（図5）

RTX 4090の環境1では、vLLMに対してMixtralが1.3〜1.5倍、QwenとDeepSeekが最大1.8倍の高速化を示す。より制約の強いRTX 2080 Tiの環境2では、Mixtralが最大4.3倍、Qwenが最大9.4倍、DeepSeekが最大7.5倍となる。GPUの演算性能だけでなく、CPU・GPU間の転送帯域とGPU上に常駐できる専門家の数が結果を左右する。

|環境|Mixtral|Qwen|DeepSeek|基準|
|---|---:|---:|---:|---|
|RTX 4090・PCIe Gen4|1.3〜1.5倍|最大1.8倍|最大1.8倍|vLLM比|
|RTX 2080 Ti・PCIe Gen3|最大4.3倍|最大9.4倍|最大7.5倍|vLLM比|

比較用の「＋Prefetch」版は同じ確定ルータの予測を使いながら、予測が外れた場合には正しい専門家を改めて読み込む。CommitMoEはこの比較版より一貫して速いと報告する。したがって高速化は単に予測器の精度が上がったためではなく、再読み込み経路をなくしたことに由来する。論文は全構成のWilcoxon符号順位検定でp<0.001を報告し、Cohenのdの絶対値は0.567〜7.356とする。これは測定された構成間の統計的差であり、未測定ハードウェアへの速度保証ではない。

### 4. 活性専門家数によるOWAの効き方（第6節）

Mixtralは各トークンで2専門家を選ぶため、予測集合と元の集合が部分一致した際に重みを再配分できる相手が少ない。Qwenは4専門家、DeepSeekは6専門家を活性化するため、OWAが利用できる正解専門家の数が増えやすい。著者らは4専門家以上を活性化するモデルでOWAを推奨し、α1とα2は1.0〜1.4の範囲で検証集合を用いて調整すると説明する。MixtralではOWAなしが最良という負の結果を残し、どのモデルにもOWAを必須としてはいけない。

## 既存研究との差

オンデマンド転送は元のルータ選択を守るが、転送待ちが大きい。MoE-Infinityは過去の専門家活性履歴から先読みを行い、専門家キャッシュの管理を最適化するが、予測が外れた場合には元の専門家を追加ロードする。CommitMoEは次層の専門家を軽量MLPで予測し、その集合を実行対象として確定するため、予測ミスの後に二回目の転送を行わない。予測器の変更と再読み込み廃止を分離するため「＋Prefetch」版も評価している。

CasMoEのように入力文から全層の活性を予測する方式と異なり、CommitMoEは現在層の隠れ状態から次層を予測する。これにより入力文だけでは見えない中間状態を利用できる一方、深い層の転送を入力文時点から始めるわけではない。CommitMoEの主要な新規性は、**元の専門家選択へのフォールバックを廃止し、必要に応じて元ルータの重みを準備済み専門家へ再配分する**点にある。

## 限界と負の結果

CommitMoEは元のルータが選んだ専門家を常に実行する方式ではない。予測を外した際には別の専門家の非線形変換を使うため、生成確率分布、個別トークン、長文脈での累積誤差が元モデルと同一である保証はない。品質評価はGSM8K、BBH、TruthfulQA、WMT16に限定され、稀な入力や分布外の要求での品質を無条件に保証しない。平均点が近い場合でも、個々の要求では誤答が増える可能性がある。

OWAの効果は活性専門家数とモデルに依存する。MixtralではOWAありの平均50.73がOWAなし51.02を下回り、QwenではOWAあり43.06でも元43.17より低い。調整係数はモデル別に探索する必要があり、別モデルへ固定値をそのまま流用できない。予測器の学習には元ルータの隠れ状態と活性パターンの収集が必要で、事前学習なしで任意のモデルへ適用できるわけではない。

最大9.4倍の速度改善はRTX 2080 Ti、PCIe Gen3、バッチ1の制約下での結果である。RTX 4090では改善幅が小さく、CPU・GPU間の転送が律速でない環境や、十分なGPUメモリに専門家が常駐する環境では同じ倍率を期待できない。大バッチの同時要求処理、NVMeからの多段転送、長時間の生成における品質ドリフト、消費電力などは主要評価対象ではない。

### 評価の再現時に分離すべき要因

第一に、先読みの成功率と実行した専門家の一致率を別々に記録する必要がある。予測集合が元の集合と異なっていても、準備済み集合で計算を続ければ転送待ちは生じない。しかし、転送待ちが消えたことと、元の専門家を正しく選んだことは同義ではない。品質評価では、予測集合と元の集合の重なりが少ない要求だけを抽出し、正答率や出力分布の変化を確認することが望ましい。論文の観察は、この重なりがゼロの要求でも一部の推論課題で品質を保てることを示したが、未知の分布での最悪値までは示していない。

第二に、重み調整を適用する範囲と、そのために必要な元のルータの計算費用を明示する必要がある。重み調整を行う場合、元のルータが出した確率分布を参照し、予測と一致した専門家へ重みを移す。この計算は専門家重みの追加転送より軽いとしても、完全に費用がないわけではない。活性専門家が少ないモデルでは再配分先が乏しく、かえって品質が悪化する場合がある。逆に活性専門家が多いモデルでは、元のルータと重なった専門家の寄与を増やすことで、元の出力に近づける余地が大きい。

第三に、推論の高速化を比較するときは、同じモデル、同じ生成長、同じGPUメモリ容量、同じ転送帯域を揃える必要がある。転送帯域が狭い環境では正しい専門家を読み直す費用が大きくなるため、再読み込みを行わない方式が有利になりやすい。反対に、GPU上へ必要な専門家がすでに常駐している状況では、転送を省く余地が小さい。したがって最大倍率を単独で示すより、二つの実験環境で倍率がどの程度変わるかを併記した方が方式の適用条件を正確に表せる。

第四に、元のモデルを変更しないという説明は、元の重みを再学習しないことを意味するのであって、元のモデルと同じ関数を計算することを意味しない。実行する専門家を変更した時点で出力は近似になる。これを明示しないと、再読み込みをなくすことが単なる実装上の高速化に見えてしまう。研究の中心は、多少の専門家置換を許すことで転送待ちを減らすという設計上の選択にある。品質が許容できるかは、実際に運用する用途の要求水準に照らして判断する必要がある。

第五に、平均正答率だけでなく、難しい入力、長い推論、専門家の予測が連続して外れる入力を分けて評価することが重要である。論文の測定では、特定の課題で平均点が元モデルより高くなる場合もあるが、これは元モデルと同じ結果が得られた証拠ではない。ある問題では改善し別の問題では悪化する可能性があり、利用者が求める品質水準に応じて許容範囲が変わる。平均値の小さな差を、個々の要求の誤差が小さいことの保証へ読み替えてはならない。

## 実装状況

PythonとC++、PyTorch、MoE-Infinityを基盤に、次層予測器とCUDA複数ストリームの非同期転送、元ルータのスコアを用いたOWAを実装した。実験はRTX 4090 24GBとRTX 2080 Ti 11GBで実施し、CPU・PCIe帯域も明記している。一次論文とAAAI掲載ページで公式コードの公開先を確認できなかったため、再現用の公開リポジトリがあるとは記載しない。
