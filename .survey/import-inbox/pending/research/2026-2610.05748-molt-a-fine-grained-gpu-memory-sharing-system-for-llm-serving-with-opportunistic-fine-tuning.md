# MOLT: A Fine-Grained GPU Memory Sharing System for LLM Serving with Opportunistic Fine-Tuning

> 推論レプリカの遊休メモリを、実行中PEFTステップの保存済み活性値1個単位で推論へ引き渡し、ステップを捨てずに逆伝播の再計算で取り戻す細粒度GPUメモリ共有方式。

## 概要

大規模言語モデルのサービングは、リクエスト負荷に合わせてレプリカの数を増減させるオートスケーリングで容量を調整する。ところが容量の調整単位はレプリカ全体であり、新しいレプリカの起動とモデルの読み込みには数分かかる一方、レプリカ内部で動的に増減するKVキャッシュは10秒で3.2倍に育つこともある。そのため各レプリカは急な負荷上昇に備えた余裕を常時抱え、たとえばH100を1基使う24Bモデルでは重み43.9ギビバイトの横に20ギビバイトから31ギビバイトのメモリが使われないまま残る。この遊休メモリはレプリカを丸ごと畳まない限り提供者へ返せない。

この遊休分へ別の作業を同居させる候補が、パラメータ効率ファインチューニングである。学習済みの重みを凍結して小さなアダプタだけを訓練する方式なので、推論がすでに持つ重みを共有でき、常駐分は小さく、進捗はスループットで測るため推論の急増時にメモリを譲っても破綻しにくい。しかし既存の同居方式には弱点がある。計算だけを共有する方式はチューニングのメモリが常駐したままで、負荷上昇時にKVキャッシュが入る場所がなくなる。メモリを共有する従来方式は訓練バッチを縮めることで境界を動かすが、最小単位が訓練サンプル1件と粗く、引き渡しのたびに実行中のステップを破棄して小さいバッチで再開するため、秒単位で境界が動く環境では作業が何度も捨てられる。

本論文のMOLTは、共有の単位を訓練サンプルから保存済み活性値へ細かくする。保存済み活性値とは、順伝播が逆伝播での勾配計算のために残しておくテンソルであり、チューニングステップのメモリの大半を占め、しかも再計算で取り戻せる。MOLTはKVキャッシュと保存済み活性値を1つの共有プールへ置き、推論がメモリを必要とすると活性値の置き場であるスロットの物理ページだけを外してKVキャッシュへ渡す。ステップは止まらず、逆伝播は外された活性値を再計算する。代表結果として、24Bから70Bの4デプロイ、H100 SXMとB200でのトレース駆動評価で、推論のサービス品質目標（Service-Level Objective; SLO）達成率は全デプロイで99.7パーセント以上を保ち、完了したチューニング作業量はステップ破棄型のメモリ共有の1.9倍から3.3倍だった。計算だけを共有する方式のSLO達成率は最大でも5.0パーセントにとどまった。

## 問題設定

問題の核心は、余っている資源と足りない資源の時間スケールと粒度のずれである。オートスケーリングが追えるのは日周期のような緩やかな負荷変動で、5分間隔の負荷変化は中央値で1.25倍程度にとどまる。一方でKVキャッシュは秒単位で伸び縮みし、リクエストはKVキャッシュに空きがなければ受け付けてもらえず、最初のトークンまでの時間（TTFT）が伸びてSLOを外す。実行中のリクエストもKVキャッシュを伸ばせなければ止まる。つまり推論の成否を決めるのは計算ではなくメモリであり、同居させる作業からは秒以内にメモリを取り戻せなければならない。

訓練サンプル単位の共有がこの環境で失敗する理由は2つある。第1に粒度である。24Bモデルで入力1024トークン、バッチ1件のLoRAチューニングステップは凍結した重みの横に15.8ギビバイトを持ち、その大半が保存済み活性値で、常駐すべきアダプタ本体や勾配や最適化器の状態は0.4ギビバイトしかない。遊休が20ギビバイトから31ギビバイトしかない場所では、サンプル1件が入らなくなった時点でチューニングは完全に止まる。第2に引き渡しの代償である。従来方式は境界を動かすたびに実行中ステップを捨てて再開するので、ステップの後半で引き渡しが起きるほど、それまでに済ませた順伝播の作業が無駄になる。KVキャッシュが10秒で3.2倍に育つ環境では、この代償が1日の負荷変動の頻度ではなくKVキャッシュの動きの頻度で発生する。

そこで求められるのは、サンプルよりはるかに細かく、しかも引き渡してもステップの進捗が残る単位である。保存済み活性値はこの2条件を同時に満たすほぼ唯一の単位だと論文は位置づける。中間テンソルは寿命が短くて引き渡す暇がなく、常駐状態を動かすと進捗そのものが失われるのに対し、活性値は層ごとや演算子ごとに個別に手放せて、手放した分は逆伝播の再計算で復元できるからである。

## 手法のあらまし

MOLTの処理は次の順に進む。まず起動前に、オフラインのプロファイルで得た活性値の大きさをもとに、各保存済み活性値へ固定の仮想アドレス範囲であるスロットを1つずつ割り当てる。物理メモリは、引き渡しの対象になる共有プールと、対象にならない固定プールへ分ける。共有プールにはKVキャッシュと、裏付けのあるスロットのページが入る。固定プールには凍結した重みや推論の作業領域、アダプタや勾配や最適化器の状態、そして裏付けのないスロットの活性値が入る。スロットの状態はスロット状態表が持ち、裏付けの有無、再計算の費用、実行中カーネルが触り得るかを示すフラグを記録する。チューニングの順伝播では、各演算子を出す前にスロットの裏付けを確認し、裏付けがあれば活性値をスロットへ保存し、なければ固定プールへ置いて順伝播の最後の使用後に捨て、逆伝播で再計算する。推論側でKVキャッシュが共有プールの空きを使い切ると、引き渡し制御器が再計算費用の安いスロットから順に裏付けを外し、そのページをKVキャッシュへ渡す。メモリをチューニングへ戻すのはステップの境界だけであり、空きページを再計算費用の高いスロットから順に再び裏付ける。

## 手法

### 1. 共有メモリプール — 境界をページの付け外しで動かす

共有メモリプールが担うのは、2つの作業の間のメモリ境界を、データを移動せずに動かせるようにすることである。入力は起動前のプロファイルで得た各活性値の大きさと実行順であり、チューニングステップの実行順は安定しているため、スロットの割り当ては一度だけ行う。各スロットは固定の仮想アドレス範囲を持ち、裏付けとはその範囲の背後に共有プールの物理ページを対応付けること、裏付け解除とはその対応付けを外すことである。境界が動いても活性値そのものはコピーされないため、引き渡しの速さはページ表の操作だけで決まる。チューニングに使える予算は裏付けのあるスロットの集合そのものとして表され、推論がページを必要とするたびにこの集合が縮み、ステップ境界で空きがあれば広がる。効果は、境界の最小の動きがサンプル1件分の15.8ギビバイトから活性値1個分へ細かくなることである。トレードオフとして、裏付けのないスロットの活性値は固定プールへ置かれて順伝播の最後の使用後に捨てられるため、その分の再計算が逆伝播で必ず発生する。また層の入力のように再計算できない活性値のスロットは、最初から引き渡しの対象外にされる。

### 2. 柔軟な活性値チェックポイント — 途中で外されてもステップを正しく保つ

この機構が解くのは、ステップの実行中に予算が変わる状況でチューニングを正しく保つ課題である。通常の活性値チェックポイントは訓練開始前に再計算する対象を固定するが、MOLTでは推論の引き渡しがいつ来るか分からないため、保存したはずの活性値が逆伝播の時点で消えていることがある。そこでチューニング側の割当器は、活性値を生む演算子を出すたびにスロット状態表で裏付けを確認し、保存経路と再計算経路を切り替える。裏付けがあれば活性値はスロットのアドレスへ保存され、逆伝播でもそこから読む。ただし保存後に裏付けが外された場合は、逆伝播側でもう一度裏付けを確認して再計算へ切り替える。裏付けがない場合は最初から再計算経路を取り、活性値は固定プールへ置かれて最後の使用後に解放され、逆伝播で作り直される。引き渡し制御器が外すスロットを選ぶときは、再計算費用が記録された順位を使い、費用の安いスロットから外す。すべての活性値を外せば再計算は増えるが、ステップを最初からやり直す破棄型と違い、済ませた順伝播の作業自体は残る。論文の図が示す対比では、破棄型では引き渡し時点までの順伝播がすべて無駄になるのに対し、MOLTの代償は外された活性値の再計算だけである。失敗条件として、再計算できない活性値は対象外であり、また外す量が大きいほど逆伝播の追加計算が増えてチューニングの速度は落ちる。

### 3. 非同期対応スロット保護 — 実行中カーネルが触る場所を外さない

引き渡しで最も危険なのは、GPUがまだ実行しているカーネルが読むスロットを外してしまうことである。CPUはGPUより先行してカーネルを投入するため、引き渡しが来た時点で、数層前に投入したカーネルがその層のスロットをまだ読み書きしている可能性がある。MOLTはスロットごとに投入済みフラグを持ち、ある層の最初の演算子を投入した時点でその層の全スロットにフラグを立て、次の層の完了コールバックが走った時点で下ろす。フラグの範囲を演算子単位ではなく層単位にするのは、残差接続のように後の演算子が前の演算子が書いたスロットを読むためである。完了の境界から投入の境界までの層の集合が保護ウィンドウであり、引き渡し制御器はこの外にあるスロットだけを外す。引き渡しの判断中は保護スナップショットとしてCPUの投入と完了コールバックの進行を止め、判断の途中で新しい演算子が対象スロットへ触りに行く事態を防ぐ。GPU側は投入済みの演算子を実行し続けるため、この停止がチューニングへ与える影響は小さいとされる。

保護ウィンドウが広いと外せるメモリが減るため、MOLTはディスパッチ抑制でCPUの先行量そのものを絞る。投入済み演算子のキューの長さに上限を設け、上限へ達したらGPUの実行が進んでキューが上限の半分を下回るまでCPUの投入を待たせる。上限はオフラインのプロファイルで、ステップ時間を延ばさない最小の値に決める。上限が小さすぎるとGPUがCPU待ちになり、大きすぎると保護ウィンドウが広がるという交換条件がある。テンソル並列ではランクごとに先行量が違うため、各ランクが自分の保護ウィンドウを共有メモリ経由で公開し、全ランクの和集合の外にあるスロットだけを全ランク共通で外す。これにより、ランクごとに再計算する演算子が食い違って集団通信が崩れる事態を避ける。

### 4. データと制御の流れ

1つのチューニングステップを通すと流れはこうなる。ステップ開始時に、引き渡し制御器が共有プールの空きページを再計算費用の高いスロットから順に裏付け直す。順伝播では層ごとに演算子が投入され、その層のスロットにフラグが立ち、各活性値は裏付けの有無で保存経路か再計算経路へ分かれる。途中で推論リクエストが増えてKVキャッシュが空きを使い切ると、推論側の割当器がプロセス間通信でページを要求し、制御器は保護スナップショットを取って外せるスロットから安い順に裏付けを外し、ページをKVキャッシュへ渡す。順伝播の残りの層は新しい裏付け状態を読んで経路を決める。逆伝播では、裏付けが残る活性値はスロットから読み、外された活性値は再計算してから使う。ステップが終われば次の境界で再び裏付け直しが試みられる。

| 構成要素 | 入力・観測 | 具体的な動作 | 改善対象 | 主なトレードオフ |
|---|---|---|---|---|
| 共有メモリプール | プロファイル済みの活性値サイズとKVキャッシュ需要 | スロットへのページの対応付けと解除で境界を動かす | 引き渡しの粒度と速さ | 裏付けなしの活性値は再計算が必須になる |
| 柔軟な活性値チェックポイント | 各演算子の投入時点での裏付け状態 | 保存経路と再計算経路を演算子ごとに切り替える | ステップ破棄の回避 | 外す量が多いほど逆伝播の追加計算が増える |
| 非同期対応スロット保護 | 投入境界と完了境界、ランクごとの保護ウィンドウ | フラグが立ったスロットを外さず、判断中は投入を止める | 実行中カーネルとの競合回避 | 保護中はその分のメモリを推論へ渡せない |
| ディスパッチ抑制 | 投入済みキューの長さ | 上限と半分のしきい値でCPUの先行を絞る | 外せるスロットの割合 | 上限が小さすぎるとGPUがCPU待ちになる |

## 評価

### まず見るところ

- **結論:** 連続引き渡し版のMOLTは4デプロイすべてで推論のSLO達成率99.7パーセント以上と、破棄型メモリ共有より多いチューニング作業量を両立した唯一の構成だった。
- **速度・効率:** チューニングのスループットは絶対値では計算のみ共有の方式に負ける場面もあるが、それはメモリを一切取り戻されない方式であり、SLOを守る構成同士ではMOLTが最も速い。
- **品質:** 共有は無損失である。引き渡された活性値は再計算で復元され、チューニングの数値結果は変わらない。代償は再計算の計算量だけである。
- **メモリ:** 24Bモデル、テンソル並列1の条件では、達成可能な予算の平均86パーセントをチューニングの裏付けに使えた。一方で破棄型は予算の87パーセントを使わずに残した。
- **評価の強さ／注意点:** 実機測定で、推論は実トレース駆動、比較は同一の共有プール大きさで行われている。ただしモデルは2種、ファインチューニングはランク8のLoRAのみである。

**数値の読み方。** SLOは、TTFTと出力トークンあたり時間（TPOT）がどちらも推論単独実行時の平均の3倍以内に収まるリクエストの割合である。チューニング作業量の倍率はSLOを守る構成同士の比較で読むべきもので、計算のみ共有の方式はチューニングが速く見えてもSLO達成率が最大5.0パーセントしかなく、実用上の比較対象にならない。粒度の効果は、境界をステップ境界でしか動かさない自方式の変種との比較で切り分けられており、実装の出来ではなく引き渡し粒度そのものが利得の源泉だと示されている。

## 既存研究との差

同居研究との差は、メモリ境界を動かす単位と、動かすときに何を失うかにある。ステップ間で推論を挟む方式や、トークン単位で交互実行しながらKVキャッシュを静的に確保する方式は、境界そのものを動かさない。LLMStationは演算子単位の交互実行で推論遅延を守るが、チューニングメモリは常駐したままで、本評価でもSLO達成率は最大5.0パーセントだった。SIRIUSは境界を動かすが単位は訓練サンプルであり、引き渡しのたびに実行中ステップを破棄して小さいバッチで再開する。MOLTはLLMStationの交互実行とSIRIUSのページプールを土台に流用しながら、共有単位を保存済み活性値へ変え、境界をステップの途中でも動かせるようにした。活性値チェックポイントの先行研究との差も同じ構図で、従来は訓練開始前に固定した予算の下で再計算対象を決め、再計算で空いたメモリは訓練側に残った。MOLTでは予算そのものがステップの実行中に推論側の都合で変わり、空いたメモリは実行中カーネルが触り得る状況で推論へ渡される。この動く予算と非同期の安全性を一緒に扱った点が新規性である。

## 限界・実装状況

評価は2モデルとランク8のLoRAに限られ、他のアダプタ手法や大規模なバッチ、全面ファインチューニングへの適用は未評価である。再計算できない活性値は引き渡し対象外であり、モデルの構造によっては回収できる割合が下がる可能性がある。メモリの返却はステップ境界でのみ行われるため、推論負荷が下がった直後のステップ内では、裏付け直しを待つ分の再計算が残る。ディスパッチ上限はデプロイごとのオフラインプロファイルで決める前提であり、ワークロードが変わる環境での再調整方法は示されていない。実装はvLLMへのパッチとPyTorch向け拡張ライブラリによる試作で、上流へ統合されたという記述はなく、論文中に公式コードの公開先も示されていない。プレプリント段階の研究である。

## 一般的な実装上の含意

同居システムでは、共有する資源の単位を、その資源を失った側が最も安く取り戻せる単位に合わせると、引き渡しの頻度を上げても全体の無駄が増えにくい。本論文ではそれが再計算可能な活性値だった。同様に、境界を動かす費用は、データを移す設計にするか、対応付けだけを変える設計にするかで桁が変わる。仮想アドレスを固定して物理ページの対応付けだけを付け替える方式は、他のメモリ共有でも応用できる。また非同期実行を前提にする基盤では、先行して投入された作業が触り得る範囲を保護対象として明示し、その範囲自体を投入量の抑制で小さく保つことが、細粒度の資源回収を安全にする条件になる。保護の和集合を全ランクでそろえる考え方は、並列実行で各参加者の安全範囲がずれる場面一般に使える。
