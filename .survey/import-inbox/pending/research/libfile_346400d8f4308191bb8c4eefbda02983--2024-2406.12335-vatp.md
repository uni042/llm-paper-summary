# Attention Score is not All You Need for Token Importance Indicator in KV Cache Reduction: Value Also Matters

## 概要
KVキャッシュ削減の多くは「過去トークンへ向いた注意確率が大きいほど重要」とみなし、累積注意スコアで保持対象を決める。しかし実際の注意出力は、注意確率だけでなく、その確率を掛ける値ベクトルにも依存する。値ベクトルのノルムがトークン間で大きく異なるなら、同じ注意確率でも出力への寄与は同じではない。

Value-Aware Token Pruning（VATP）はこの点を直接使い、従来の注意スコア型重要度へ値ベクトルのL1ノルムを組み合わせる。モデル再学習や追加ネットワークを必要とせず、既存のKV追放器のスコア計算を置き換える軽量な方式である。LLaMA2-7B-chatとVicuna-v1.5-7B、LongBench 16タスクの評価で、注意スコアだけを使う基準法を12タスク以上で上回る。

## 問題設定
自己注意の出力は各トークンの値ベクトル `v_i` を注意重み `a_i` で加重した和である。従来のH2O系やScissorhands系の追放では `a_i` の履歴を重要度として用いるが、`||v_i||` が一定でなければ `a_i` だけでは出力寄与を表せない。論文は実モデルの値ノルムを調べ、位置・トークン間で明確な非一様性があることを示す。

特に厳しいKV予算では、誤って重要トークンを捨てる影響が大きい。追放後はそのキー・値を将来のデコードで参照できないため、後から回復できない。VATPの狙いは、追加の重い検索器を入れず、既にキャッシュ中に存在する値ベクトルから寄与の大きさを推定することである。

## 手法
### 値を考慮した重要度
各過去トークンについて、従来の累積注意スコアと値ベクトルのL1ノルムを組み合わせる。注意重みが高く、かつ値の絶対量も大きいトークンほど保持優先度が高くなる。L1ノルムは値ベクトルから直接計算でき、別モデルによる推定を必要としない。

### 既存追放方式への組込み
VATPはキャッシュ管理全体を作り直すのではなく、注意スコアを使う既存のトークン重要度指標へ値情報を足す。したがって、固定KV予算で低スコアのトークンを追放する流れ自体は維持できる。変更点が局所的なので、モデル重みを更新しない推論時手法として利用できる。

### なぜ効くか
注意出力で実際に加算される量は `a_i v_i` である。`a_i` がやや小さくても `v_i` が大きければ出力寄与は無視できず、逆に高注意でも値が小さければ寄与は限定される。VATPはこの積構造を重要度へ反映し、注意確率だけで起きる順位逆転を減らす。

### 追加費用
値ノルム計算とスコア更新が追加されるが、別の推論モデルや再学習は不要である。一方、L1ノルムは注意出力の方向や他トークンとの相殺まで表現しないため、完全な寄与推定ではない。方式は「注意だけより良い安価な代理指標」と位置付けるべきである。

## 評価条件

|項目|内容|
|---|---|
|モデル|LLaMA2-7B-chat、Vicuna-v1.5-7B|
|ベンチマーク|LongBench 16タスク|
|比較|注意スコアのみを使うKV削減基準法|
|操作|固定KV予算下のトークン追放|
|学習|追加学習なし|
|評価目的|同じキャッシュ制約での長文脈タスク品質|

## 主要結果
16タスクにわたる評価で、VATPは両モデルにおいて注意スコアのみの基準法を12タスク以上で上回った。これは「値ノルムの非一様性は観察上の特徴にすぎない」のではなく、実際のキャッシュ選択へ利用できることを示す。

|観点|結果|意味|
|---|---|---|
|LongBench 16タスク|12タスク以上で基準法を上回る|値情報が追放順位を改善|
|2モデル|LLaMA2-7B-chat / Vicuna-v1.5-7Bで検証|単一チェックポイント固有の現象ではない|
|同一KV制約|品質改善|メモリ予算を増やさず保持対象を改善|
|追加学習|不要|既存推論器へ後処理として導入可能|

## 既存研究との差
H2Oなどの重い打者（heavy hitter）型手法は、過去の注意スコアが将来の重要度を示すという性質を利用する。VATPはその枠組みを否定するのではなく、「注意出力は確率と値の積である」という欠落要因を追加する。新しい圧縮表現や量子化を導入するのではなく、どのKVを残すかという選択指標を改善する点が中心である。

## 限界
L1ノルムは値ベクトルの方向、後続層での変換、複数トークン間の相殺を扱わない。評価は7B級のLLaMA2/VicunaとLongBenchが中心で、より大規模なGrouped Query Attentionモデルや実サービングの処理量・GPUメモリ断片化までは直接評価していない。また、追放方式なので一度削除したKVは後から必要になっても復元できない。
