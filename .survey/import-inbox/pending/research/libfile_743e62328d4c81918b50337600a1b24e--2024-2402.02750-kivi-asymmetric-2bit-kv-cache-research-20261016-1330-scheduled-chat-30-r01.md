# KIVI：KVキャッシュのキーと値を異なる方向で2ビット量子化する

## 概要

大規模言語モデル（LLM）の自己回帰生成では、過去トークンのキー（Key）と値（Value）をKVキャッシュに保存し、次のトークン生成時に再計算を省く。ところが、生成を同時に処理する要求数（バッチサイズ）や文脈長が増えると、モデル重みとは別に保持するキャッシュがGPUメモリを圧迫する。復号（decoding）では新しい問い合わせベクトルが既存キャッシュ全体を参照するため、キャッシュの読み込み帯域も律速となる。キャッシュを低ビット化すれば容量と転送量を減らせるが、キーと値を同じ規則で丸めると、2ビットでは注意計算の誤差が急増する。

KIVIは、キーの少数のチャネルに絶対値の大きい外れ値が固定的に現れることと、値は注意重みによってトークンごとに選択的に混合されることを切り分ける。キーをチャネル単位（per-channel）、値をトークン単位（per-token）で量子化する非対称設計を採用する。さらに、逐次生成とチャネル単位量子化の相性の悪さを、一定長の高精度残差領域と完成済みの量子化済み領域に分けることで解消する。追加学習や微調整を要求せず、既存のモデル重み量子化とも独立して組み合わせられる。

原著はLlama/Llama-2、Falcon、Mistral系列で生成品質を比較し、Llama-2-7Bを単一A100 80GBで動かすサービス負荷では、16ビットKVキャッシュと同程度の最大GPUメモリ使用量のもとで最大4倍のバッチサイズ、2.35〜3.47倍の処理量を示した。ただし、これは**KVキャッシュ自体の2ビット化**と**モデル重みを含む実行全体のピークメモリ**を区別して読む必要がある。2ビットという値だけから実行全体のメモリが8分の1になるわけではない。

## 問題設定と必要な背景

### KVキャッシュが増える場所

Transformerの注意層は、入力隠れ状態から問い合わせQ、キーK、値Vを射影する。事前充填（prefill）では入力文脈のKとVをまとめて計算して保持し、復号では各新規トークンのKとVを末尾へ追加する。単一の注意層について概念的には `K ← concat(K, k_new)`、`V ← concat(V, v_new)` と更新し、注意出力を `softmax(q K^T) V` として求める。従って過去のK/Vの保存量は文脈長と並列要求数にほぼ比例し、過去を読み直す転送量も復号ステップごとに増える。

重みの低ビット化はモデル本体の容量を減らすが、生成中に伸びるKVキャッシュを直接は削減しない。複数問い合わせ注意（multi-query attention）やグループ化問い合わせ注意（grouped-query attention）はKVヘッド数を減らせるものの、既存モデルの構造や学習済み重みの制約を受ける。キャッシュ退避はGPU外への転送負担を増やし、重要トークンの削除は参照不能になる情報を生む。KIVIはキャッシュ内の値を残したまま表現精度を下げる、これらとは異なる設計点を扱う。

### なぜ普通の一様な2ビット量子化では失敗するか

グループごとの最小値・最大値からスケールを決め、各要素を近い整数へ丸める線形量子化を用いる。ビット数Bなら概念上の段数は `2^B` であり、2ビットでは4段階しかない。グループに一つだけ非常に大きい値が混ざると、最大最小の幅が広がり、通常値の細かな差が同じ段へ潰れる。どの要素を同じグループへまとめるかが、低ビット化の精度を決める。

キーには、トークンが変わっても特定のチャネルに外れ値が繰り返し出現する傾向がある。トークン単位で各チャネルをまとめると、外れ値チャネルにスケールが引っ張られ、同じトークンの正常なチャネルの精度まで損なう。チャネルごとに複数トークンをまとめれば、外れ値の影響を当該チャネル内に閉じ込められる。

値ではキーと同じ固定チャネル外れ値の分布は明瞭でない。それでもチャネル単位で量子化すると、注意出力の誤差が大きくなる。注意出力は各トークンの値ベクトルに注意確率を掛けた重み付き和であり、注意確率が少数トークンへ集中する場合、重要なトークンの値の精度が特に重要になる。値をトークン単位で量子化すれば、他トークンの値の分布が重要トークンの量子化範囲を変えない。**Kの誤差を注意確率で評価することと、Vの誤差を最終的な重み付き出力で評価することは別問題**である。

## 提案手法

### 1. キーはチャネル方向、値はトークン方向

原著は、量子化後にいったん復元して通常の注意演算へ渡す擬似量子化（fake quantization）で、グループサイズ32、2ビット、キーと値の量子化方向4通りを比較した。Llama-2-13BのCoQAでは、16ビットが66.37、キー・値ともトークン単位の2ビットが52.93、キー・値ともチャネル単位が2.88、**キーをチャネル単位・値をトークン単位**にすると63.53となる。TruthfulQAでも同じ組合せが、2ビットの比較構成の中で最も16ビットに近い。方向を選ぶことは単なる実装上の好みではなく、モデルの誤差の伝播に直接関係する。

キーの誤差分析では、Llama-2-13Bにおけるキー再構成の相対誤差がトークン単位13.67からチャネル単位4.55へ下がり、注意確率の相対誤差は47.00から9.60へ低下する。値の再構成誤差はトークン単位4.57、チャネル単位3.73であり、**値そのものの復元誤差だけならチャネル単位が小さい**。しかし注意出力の相対誤差はトークン単位3.55に対しチャネル単位49.89となる。値については復元誤差の大小だけでは最終出力品質を予測できないことが重要な実証結果である。

### 2. 逐次生成を可能にするグループ化領域と残差領域

キーをチャネル単位で量子化するには、同じチャネルの複数トークンをまとめて量子化範囲を決めなければならない。一方、復号時には新しいキーが1トークンずつ到着し、まだ将来トークンの値は存在しない。到着のたびに全履歴を再量子化すれば、キャッシュ削減の利点が更新費用で失われる。

KIVIはキーを、量子化済みのグループ領域 `K_g` と高精度の残差領域 `K_r` に分ける。新しいキーはまず `K_r` に追加する。残差長Rに達したら、グループ長Gごとにチャネル単位で量子化して `K_g` に追記し、`K_r` を空にする。RはGで割り切れる値にする。原著の基本設定は **G=32、R=128** である。グループ化済みの過去を固定し、直近部分だけを高精度で蓄積するため、既存の量子化済み履歴を毎ステップ書き換えない。

値も `V_g` と `V_r` に分けるが、値はトークン単位で量子化できるので更新方法が異なる。新しい値は高精度の待ち行列 `V_r` へ追加し、長さRを超えた最古トークンを取り出して、そのトークンのチャネルをまとめた量子化を行い `V_g` へ追記する。キーは一定長の塊を量子化して残差領域を空にするのに対し、値は滑動する最新Rトークンを高精度に保持する。**両者を同じ「直近R個の高精度窓」と単純化すると実装の違いを見落とす**。原著はキー側の高精度窓の期待長をおよそR/2、値側をRと説明する。

### 3. 注意演算での結合と演算カーネル

次のトークンの問い合わせQが来たら、量子化済みキー `K_g` に対する注意スコアと、高精度キー `K_r` に対する注意スコアを別々に求め、トークン方向に連結してからsoftmaxを適用する。重要なのは、グループごとに別々のsoftmaxを計算して平均する方式ではない点である。量子化済み値 `V_g` と高精度値 `V_r` も、注意確率の対応部分を使って重み付き和を作る。過去トークンを削除するのではなく、低ビット領域を復元して注意演算へ供給する。

単純にキャッシュ全体を浮動小数点へ復元してから行列積を行うと、復元用の一時メモリと転送が増える。著者はタイル単位で逆量子化と行列積を融合したCUDAの混合精度演算 `Q_MatMul` と、Tritonによるグループ量子化カーネルを実装した。これにより、圧縮済みキャッシュを全量復元する中間バッファを避け、圧縮率をGPU帯域削減へ結び付ける。モデル重みを量子化する処理とは独立しているため、重みのみ量子化と併用できる。

事前充填時には、後続層の計算へ渡すK/Vは高精度のまま扱い、保存するキャッシュだけを圧縮する。事前充填の途中で低ビット化した値を後続層の入力として再利用する方式ではない。復号時の追加トークンもまず高精度残差に置かれるため、直近文脈への注意に関する誤差を抑えられるが、その分だけ高精度メモリが一定量必要になる。

### 4. メモリの見積りと適用条件

16ビットのK/V要素を2ビットに置き換えた量子化済み領域の**理想的なデータ本体**は8分の1のビット数となる。ただし、実際にはグループのスケールとゼロ点、高精度残差、メモリ配置の余白、モデル重み、演算ワークスペースが残る。従って「KV本体が8分の1」と「プロセス全体のピークメモリが8分の1」は一致しない。原著の総括は重み込みピークメモリ最大2.6分の1である。

文脈が短く残差Rがキャッシュの大部分を占める場合、低ビット化の利得は小さくなる。Gを大きくしすぎるとグループの量子化幅が広がり精度が落ちることがある。すでに複数問い合わせ注意でKVヘッド数を減らしたモデルでは、同じ低ビット化でも追加のメモリ節約や品質への影響が異なる。新しいモデル構造・注意方式へそのまま同一結果を一般化できない。

## 主要結果と解釈

### 1. 生成品質と低ビット化の交換条件

| 条件・指標 | 16ビット基準 | KIVI-2 | 読み取れること |
|---|---:|---:|---|
| Llama-2-7B / CoQA完全一致 | 63.88 | 63.05 | キー・値の非対称2ビット化で小幅な低下 |
| Llama-2-7B / GSM8K完全一致 | 13.50 | 12.74 | 最新の高精度残差が推論課題の品質維持に寄与 |
| Llama-2-13B / CoQA完全一致 | 66.37 | 66.23 | ほぼ同等 |
| Llama-2-13B / GSM8K完全一致 | 22.67 | 20.77 | 1.90ポイントの低下は残る |
| Mistral-7B / GSM8K完全一致 | 38.36 | 36.01 | 2.35ポイントの低下がある |
| Falcon-7B / CoQA完全一致 | 59.83 | 57.48 | KVヘッドが少ない系列では2ビットの影響が相対的に大きい |
| Falcon-7B / GSM8K完全一致 | 4.55 | 3.41 | KIVI-4では4.47であり、4ビットを選ぶ余地がある |

表中の「ほぼ同等」は**全指標で厳密に同じ出力分布を保証する意味ではない**。TruthfulQAではKIVI-2が基準を上回る構成もあるが、これは量子化が普遍的に精度を上げることを意味しない。GSM8Kでは基準を下回る条件があり、特にFalconでは著者自身が4ビットの必要性を指摘する。2ビット化はモデルやタスクごとに品質検証が必要な近似である。

### 2. 長文脈の平均と局所的な悪化

| LongBenchの8課題平均 | 16ビット | KIVI-2 | 差 |
|---|---:|---:|---:|
| Llama-2-7B | 44.52 | 44.27 | -0.25 |
| Llama-2-13B | 44.85 | 44.69 | -0.16 |
| Llama-2-7B-Chat | 45.95 | 45.67 | -0.28 |
| Llama-2-13B-Chat | 45.96 | 45.52 | -0.44 |
| Falcon-7B | 8.71 | 7.95 | -0.76 |
| Mistral-7B | 46.58 | 45.85 | -0.73 |

平均の差が小さくても、個別タスクが必ず同程度とは限らない。例えばLlama-2-7BのMultiNewsは16ビット3.51に対しKIVI-2が1.14であり、平均値の背後に相対的な大幅悪化が存在する。一方、同モデルのRepoBench-Pは59.82から60.23へわずかに上がる。原著のNIAH実験は長文脈中の指定情報を取り出す能力が2ビットでも維持され得ることを示すが、すべての検索長・入力形式に対する完全保証ではない。

### 3. 構成要素除去実験：GとR

| Llama-2-13B / GSM8K | 設定 | 完全一致 |
|---|---|---:|
| グループ長Gを変更（R=128） | G=32 / 64 / 128 | 20.77 / 21.00 / 17.29 |
| 残差長Rを変更（G=32） | R=32 / 64 / 96 / 128 | 20.62 / 19.86 / 20.55 / 20.77 |

G=128では品質が大きく低下し、量子化グループを無制限に広げてよいわけではない。Rの増加は単調な改善ではなく、R=64がこの測定で最も低い。残差領域の効果は単に「大きいほど良い」ではなく、データ分布と量子化タイミングとの相互作用を受ける。擬似量子化で全トークンを低精度にした場合、同じキー・値の非対称方向でもGSM8Kの劣化が大きいことから、**高精度残差を残す実装上の選択自体が品質を左右する**。

### 4. システム処理量とメモリ

単一A100 80GBのLlama-2-7Bで、ShareGPTの長さ分布を模した負荷を用い、バッチをメモリ上限まで増やして比較する。著者はKIVI-2により**最大4倍のバッチサイズ**を許容し、同程度の最大メモリ使用量における**処理量（throughput）を2.35〜3.47倍**にしたと報告する。これは各リクエストの単独遅延が必ず同倍率で縮むことを意味しない。バッチ増加によるGPUの利用効率改善を含むサービング全体の結果であり、低ビット行列積単体の高速化値とも区別すべきである。

総括のピークメモリ最大2.6分の1という数値はモデル重みを含む条件付き結果であり、同一ハードウェア・同一文脈長・同一バッチでの「常に2.6倍削減」を示すものではない。残差R=32と128の比較があり、キャッシュ容量、精度、カーネル実装、最大バッチの間には交換条件がある。論文はKV量子化処理と前段演算のさらなる融合を将来課題としており、現行実装の最適化余地も認めている。

## 既存方式との違い

重みのみの量子化（AWQ、GPTQ）はモデルパラメータを低ビット化するため、文脈長とともに増えるKVキャッシュを直接縮めない。KIVIはキャッシュの量子化であり、重み量子化と組み合わせられる。FlexGenなどの4ビット・グループ量子化は既存のKV圧縮例だが、KIVIはキーと値の統計的役割を区別し、2ビットでも品質を維持しやすい方向を示した。SmoothQuantなどの活性値・重みを調整する手法とは、対象とする値、導入位置、低ビット化の前提が異なる。H2Oなどの重要トークン選択型キャッシュ削減は保存トークンそのものを間引くのに対し、KIVIは全履歴の量子化済み表現を残す。どちらが適切かは、参照可能な履歴の保持、メモリ予算、品質の制約によって異なる。

KIVIの独自性は、単に「KVを2ビットにする」ことではなく、**キーのチャネル外れ値、値の注意出力誤差、逐次更新時のチャネルグループ形成、直近高精度残差、融合カーネル**を一つの復号処理に接続した点にある。特に値については復元誤差の小さい量子化方向が注意出力の誤差も小さいとは限らないという観察が、非対称設計を支えている。

## 限界と適用上の注意

第一に、2ビット量子化は近似であり、モデルの出力分布を厳密保存する方式ではない。GSM8KやFalcon-7Bで品質低下が実際に観測される。低ビット化によって生成の意味が変わり得るため、コード生成や長文検索を含む用途別評価が必要である。第二に、残差窓は完全な2ビットキャッシュではなく、高精度領域と量子化パラメータの追加メモリを必要とする。短い文脈、少数要求、KVヘッドの少ないモデルでは節約率が小さくなる。

第三に、原著の処理量測定は特定のLlama-2-7B、単一A100、ShareGPT由来の合成負荷である。CPU退避、PCIe転送、複数GPUのネットワーク通信、現在のvLLMやllama.cppの各種バックエンド、異なるGPUアーキテクチャで同じ倍率が出ると断定できない。GPUに最適化されたCUDA/Tritonカーネルが実測改善の一部を担っているため、実装なしに量子化規則だけを移植しても同等の性能にはならない。

第四に、文脈が非常に長いとKVキャッシュの圧縮効果は大きいが、長文脈の内容理解や情報抽出の品質がすべての入力分布で維持されるとは限らない。LongBenchの平均だけでなく、MultiNewsのような局所的な悪化を見る必要がある。量子化とトークン削除を併用する場合の複合誤差、現代的な混合注意・特殊KV表現への移植、低負荷での端から端までの遅延は、原著の評価範囲から直接は確定できない。

## 再現・実装メモ

著者公式実装は `https://github.com/jy-yuan/KIVI` に公開されている。基本設定G=32、R=128、キーのチャネル単位量子化と値のトークン単位量子化を合わせて再現し、残差窓を無効にした擬似量子化と混同しないことが重要である。復号時は量子化済みキーと高精度キーのスコアを連結して一度softmaxを適用し、値側の対応する領域から出力を作る。メモリの比較はKV本体のビット数だけでなく、スケール・ゼロ点、残差、ワークスペース、重み、バッチ上限を含めて行う。性能比較では、同一モデル・同一入力/出力長・同一品質条件でバッチ上限と処理量を別々に記録する。
