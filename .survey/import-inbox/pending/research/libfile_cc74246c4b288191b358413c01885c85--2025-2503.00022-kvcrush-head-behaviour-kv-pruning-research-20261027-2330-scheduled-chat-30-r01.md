# KVCrush：注意ヘッドの二値指紋から代表KVトークンを選ぶ圧縮

## 概要

KVCrushは、長文脈のLLM推論でKVキャッシュを縮小する際に、重要度の高いトークンだけを残す既存方式の弱点を補う手法である。H2OやSnapKV、PyramidKVなどは注意スコアを使って重要なトークンを保持するが、選ばれなかったトークンの内容が偏っている場合、文脈中の異なる話題や離れた情報がまとめて失われる。KVCrushは、注意ヘッドが各トークンを重要とみなすパターンを短い二値指紋へ変換し、似た指紋のトークンをまとめたうえで、削除対象の各群から代表を残す。

提案は既存のKV剪定方式を置き換えるのではなく、総予算の一部を代表トークン用に割り当てる追加機構である。LongBenchの評価では、Mistral-7B-Instruct-v0.2の16課題平均でFullKV 41.79に対し、SnapKV+KVCrushが41.40、H2O+KVCrushが40.15となった。平均KV削減率約4倍の条件でも精度低下を小さく抑えられる一方、すべての個別課題でFullKVに勝つわけではない。

Intel Xeon Platinum 8470上のLongBenchマイクロベンチマークでは、同じ4倍圧縮を行うH2Oに対してKVCrush追加の剪定処理費用は約0.2%であった。ただしこの遅延はCPU中心の測定であり、GPU上の本番LLMサービング全体を測った結果ではない。論文の「0.5%未満」は追加剪定費用に関する値であり、全ワークロードで生成速度が同じという保証ではない。

## 問題設定

自己回帰生成では、各新規トークンの注意計算に過去のK/Vを再利用するため、キャッシュ容量はバッチ数、層数、ヘッド数、文脈長に比例して増える。KVを保存すれば過去の注意射影を再計算せずに済むが、長い入力や多数の同時要求ではキャッシュがモデル重みより大きくなることもある。KVを縮小するには、量子化で各値のビット数を減らす方法、低ランク近似、トークンの削除などがある。

重要度に基づく削除では、注意重みが大きいトークンを残し、残りを削除する。しかし同じ種類のトークンが上位に多数集まると、保持した集合が文脈全体を代表しなくなる。例えば遠い位置の別話題の情報は、直近の注意重みが小さいという理由だけで消える可能性がある。KVCrushは「現在重要なものを残す」と「文脈の異なる群を少数ずつ残す」を別の予算として扱う。

通常のクラスタリングで元のK/Vベクトル同士の距離を計算すると、ベクトルの次元数が大きく、トークン数も多いため、クラスタリング費用が圧縮で得る利得を相殺しかねない。著者はトークンの意味を完全に埋め込みで比較するのではなく、各注意ヘッドの振る舞いに基づく短い二値指紋を用いる。ヘッドが特定のトークン種別、局所性、特殊トークンへ異なる注意を向けるという性質を、安価な近似的類似度として利用する。

## 手法

### 1. 総KV予算を重要トークンと代表トークンへ分割

保持できる総トークン数を`B`とし、既存の剪定方式が選ぶ高重要度トークンの予算`Bimportant`と、KVCrushが選ぶ代表トークンの予算`Brepresentative`に分ける。`Bimportant + Brepresentative = B`である。前者はH2Oなどが従来どおり決め、後者は削除されるトークンを二値指紋で分桶して代表を選ぶ。論文のLongBench主要実験ではB=2048、代表用25%（512）、既存方式用75%（1536）を固定する。

重要トークンを全て代表選択へ置き換えないことが設計上のポイントである。高い注意重みを持つ明白な重要トークンは既存方式で保持し、残りの予算で長い文脈の多様性を補う。代表選択に多く割り当てすぎると、本来必要な高重要度トークンが押し出される可能性があるため、予算比率は精度の感度要因となる。

### 2. 注意ヘッドごとの二値指紋を生成

原著Algorithm 1は、各注意ヘッド`h`で得られる注意重みを集約し、トークン`t`の正規化スコア`w_h(t)`を求める。ヘッドごとに設定した閾値`θ_h`以上なら1、それ未満なら0とする。これを全`H`ヘッド分並べると、トークンごとに長さ`H`の二値ベクトル`b_t`が得られる。閾値は各ヘッドで目標保持率を実現するように設定される。

通常のK/Vは数百から数千次元の浮動小数点ベクトルだが、二値指紋はヘッド数に対応するビット数しか持たない。例えばLLaMA3-8Bの実験では32ビットの指紋を使い、元の128要素のFP16ベクトルと比べて表現が大幅に小さい。論文はこの例で約64倍のサイズ差を示す。ただし指紋は元のK/Vを復元するための圧縮表現ではなく、**どのトークンを残すか決めるためだけの軽量な特徴量**である。最終的に残したトークンのK/V自体は通常形式で保持する。

### 3. 単一アンカーへのハミング距離で分桶

原著Algorithm 2では、二値指紋空間にアンカーベクトルを一つ選ぶ。候補としてランダム、全指紋の平均に基づくもの、0と1を交互に並べたものを試す。各トークンの指紋とアンカーのハミング距離、すなわち異なるビット数を求め、距離に応じて`Brepresentative`個の桶へ割り当てる。二値なので距離計算は排他的論理和とビット数計数で実装できる。

各桶では指紋の重心に最も近い実トークンを一つ選び、そのK/Vを代表として残す。他のトークンは削除する。こうして既存方式が保持した重要トークンと代表トークンを合わせて総予算Bへ収める。単一アンカーへの距離計算はトークン数Sにほぼ線形で、全トークン間距離を繰り返す一般的なクラスタリングより安価である。

この分桶は完全な意味クラスタリングではない。同じハミング距離でも異なるビット位置が違うトークンが同じ桶へ入る場合があるため、代表選択は近似である。重要なのは、少数の計算で削除対象の一部を異なる群から残せることである。より厳密なk-meansは精度をわずかに上げる場合があるが、推論時に追加する計算費用が大きい。

### 4. ページ型KVと他の圧縮法との組合せ

KVCrushは個々のトークンだけでなく、複数トークンをまとめたチャンクやページにも適用できる。ページ単位ではページ内の各トークンの二値指紋を連結し、ページ全体の特徴として比較する。原著は32トークンのページ型KVを用い、ページ重要度に基づくH2Oと比較した。トークン単位より粒度が粗くなるため選択自由度は下がるが、vLLMのようなページ管理との接続が可能になる。

量子化とは別軸の最適化なので、残したKVの値を低ビットへ変換する方式や、GQA/MQAのヘッド共有とも概念上は併用できる。ただし、論文で検証した構成と、任意の実装に組み込んだ際の実測速度は区別すべきである。ページのサイズ、圧縮比、ヘッド数、注意スコアの利用可能性により実装費用は変わる。

## 評価

### 実験環境と比較対象

| 項目 | 原著の条件 |
|---|---|
| モデル | Mistral-7B-Instruct-v0.2、LLaMA-3-8B-Instruct、Phi-3-mini-4k-instruct、Llama-2-7b-chat-hf |
| 主評価 | LongBenchの16課題、GSM8K、XSUM |
| 比較 | FullKV、H2O、SnapKV、PyramidKV。代表用の予算を追加した組合せ |
| LongBench予算 | 2048トークン。KVCrush 25%、既存方式75% |
| ページ評価 | 32トークン単位のページKV、H2Oとの比較 |
| ソフトウェア | CUDA 12.2、PyTorch 2.4.1+cu121 |
| 遅延測定 | Intel Xeon Platinum 8470上のLongBenchマイクロベンチマーク |

長文課題には単一文書QA、複数文書QA、要約、少数例学習、合成検索、コードが含まれる。LongBenchの課題ごとに入力長が異なるため、同じ2048トークン予算でも実効圧縮率は一定ではない。論文のTable 3では平均圧縮率を約4倍としているが、課題別には約1倍から9倍まで幅がある。

### LongBenchでの品質保持

Mistral-7B-Instruct-v0.2のLongBench 16課題平均は、FullKV 41.79、H2O 39.49、H2O+KVCrush 40.15、SnapKV 41.32、SnapKV+KVCrush 41.40、PyramidKV 41.06である。H2Oへ代表選択を追加すると+0.66ポイント、SnapKVへ追加すると+0.08ポイントとなる。元方式によって改善幅が異なることに注意が必要である。

同じ評価ではFullKVより平均値が小さいままであり、「4倍圧縮して完全に同じ精度」とは言えない。著者は複数方式のうち良いものを組み合わせたKVCrush*が両モデルで最良の平均を得たと報告するが、これは各条件における最良方式を選ぶ集計である。単一固定設定のKVCrushが全タスクで必ず最良という意味ではない。MistralのQMSumとMultiNewsではFullKVと同等の精度を達成した条件がある一方、他課題では負の差が残る。

### GSM8Kとアンカー選択の感度

原著Table 2は、予算512トークンでH2OとKVCrushのアンカー選択を比較する。Phi-3-miniのGSM8K strict正解率はH2O 70.7に対し、ランダムアンカー75.4、平均アンカー75.2、交互ビット74.6である。LLaMA3-8BのstrictではH2O 74.9、ランダム76.2、平均76.5、交互75.7である。単純なアンカーでも改善が得られることは、複雑なクラスタ中心探索が必須ではないことを支持する。

一方、アンカー方式によって正解率が多少変化し、全モデルで同じアンカーが最良ではない。代表選択の精度を最大化するには、モデルと入力分布に応じた設計が必要になる。原著は今後の課題として複数アンカーと動的予算配分を挙げている。

### 追加遅延と厳密クラスタリングの負の結果

Xeon Platinum 8470のLongBenchマイクロベンチマークでは、FullKVと比べてH2OおよびH2O+KVCrushの4倍圧縮でメモリアクセス時間が約3.2倍短縮された。KVCrushをH2Oへ追加したときの剪定費用は約0.2%と報告される。これはCPU中心の局所実験であり、GPUカーネルの実際のTPOTや全要求の待ち時間を直接保証しない。

原著Figure 3では、k-meansはKVCrushより精度がわずかに高い条件があるものの、推論遅延経路への追加費用が約200%に達する。これに対しKVCrushの追加費用は0.5%未満であり、精度と計算費用の交換が明確である。完全なクラスタリング精度より、既存KV剪定へ安価に組み込めることを優先した設計と解釈できる。

### 代表予算比率とページ型の評価

原著Figure 4では、代表用予算を増やすほど常に精度が上がるわけではない。多くの課題では20〜50%が良好だが、NarrativeQAでは90%まで割り当てる方が有利な場合がある。主要評価で使った25%は固定の便宜的設定であり、全タスクの最適値ではない。既存方式の重要トークン用予算を減らしすぎると、逆に重要情報を落とす恐れがある。

ページ型KVの評価では、ページ内トークンの指紋を連結して代表ページを選び、ページ単位のH2OよりGSM8KとXSUMで良い結果を示した。ただし、ページのサイズや連結指紋の長さはメモリと計算量に影響する。32トークンページの結果を、任意のページサイズのGPU実装へ無条件に一般化しない。

## 既存研究との差

H2Oは累積注意スコアで重要トークンを残し、SnapKVは入力末尾の観測窓から重要位置を選び、PyramidKVは層ごとに削減率を変える。これらは「何を重要とみなすか」の違いを持つが、重要度の低いトークン群の多様性を直接守るわけではない。KVCrushは残りのトークンをヘッドの二値振る舞いで分桶し、代表を少数残すことで既存方式を補完する。

KV量子化は残す各要素のビット幅を減らし、KVCrushは残すトークンの集合を変える。両者は別の軸なので併用可能だが、誤差源も異なる。低ビット化による数値誤差と、トークン削除による情報欠落を区別して評価する必要がある。KVCrushは元のKVを復元する符号化方式ではなく、削除を伴う非可逆のキャッシュ剪定である。

## 限界・再現性

二値指紋はヘッドごとの重要度判定を粗く表すため、内容の意味的類似度そのものを保証しない。同じハミング距離でも異なるヘッドの組合せが混在することがあり、代表選択で重要情報を失う可能性は残る。FullKVより低い平均正解率の条件もあり、精度が完全に維持されるわけではない。

代表用予算を25%へ固定する設定は課題ごとの最適値ではない。オンラインで入力分布や文脈長が変わるサービスでは、重要トークンと代表トークンの予算配分を適応させる必要がある。原著は動的な予算配分と複数アンカーの利用を将来課題としている。

遅延の主な評価はCPU上のマイクロベンチマークであり、実際のGPUサービングのバッチ処理、ページ管理、データ転送、連続生成全体を含む速度測定とは異なる。注意スコアが利用できない最適化カーネルへ統合する場合には、二値指紋を作るための情報取得費用も検討が必要になる。論文の0.2%をどの実装でも得られると断定しない。
