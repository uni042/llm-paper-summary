# Residual-Mass Accounting：部分KV注意の未取得質量を補完する

## 概要

長文脈を持つ言語モデルの逐次生成では、過去の全トークンの鍵・値キャッシュを毎回読むとメモリ帯域が律速になる。重要なトークンだけを選んで読む部分KV方式は読取対象を減らせるが、選ばれなかったトークンの注意の分子と分母を捨てる。すると選ばれた集合だけで確率を正規化することになり、未取得の寄与が大きい場合に注意出力が偏る。本論文は取得対象の選択方法を改善するのではなく、**同じ取得集合を固定した後に未取得の注意質量をどう数えるか**を研究する。

提案法は、正確に計算する先頭・末尾・Top-Kトークンと、それ以外のトークンの寄与を分ける。未取得部分は学習した正値特徴写像の固定長要約で推定し、取得済みトークンの寄与を要約から差し引いて二重計上を避ける。正確な分子・分母と推定した分子・分母を加えてから、一度だけ正規化する。原著のLlama-3.2-3B、64k文脈、正確参照予算1%のRULERでは、Top-Kのみ0.688に対して提案法0.711、全注意0.721だった。ただし未融合の実装は全注意より遅く、推論高速化は実証していない。

原著は2026年5月7日改訂の第2版で題名を変更している。旧題名は*Top-K Retrieval with Fixed-Size Linear-Attention Completion*であり、同じarXiv:2604.05438を指す。旧題と新題を別論文として登録してはいけない。

## 問題設定

単一の問い合わせqに対する通常の注意では、各鍵k_iとの内積から指数重みを作り、値v_iの重み付き和を全重みの和で割る。最初のsinkと直近のtailを常時読む集合A、中間領域M、問い合わせに応じて選ぶK個の集合K(q)を考える。正確に読む集合E=A∪K(q)と、読まない残差集合R=M\\K(q)を区別する。Top-Kのみの方式はEの分子ν_Eと分母Z_Eだけを用いてν_E/Z_Eを返す。

真の注意にはRの分子ν_Rと分母Z_Rも存在する。原著の式(5)では、全注意と選択のみの差が、残差分母の全体に対する割合と、残差集合・取得集合の値の平均の差の積になる。つまりTop-Kの順位が完全に正しくても、注意が広く分散するヘッドでは未取得質量の無視が問題になる。重要トークンをより正確に探すだけでは、この誤差を必ずしも消せない。

本論文はこの効果を独立に測るため、全中間領域の注意スコアを計算する総当たりTop-Kを制御条件として使う。これは実用的な高速検索器ではない。論文中の正確参照予算1%は、最終的な注意計算へ入れるトークン集合の割合であり、検索費用を含む実測メモリ転送が1%という意味ではない。

## 手法

### 1. 正値特徴写像と固定長の要約

層・ヘッドごとに問い合わせ用φ_qと鍵用φ_kを学習し、その内積がsoftmaxの指数重みを近似するようにする。正値にするのは、推定した分母を負にせず、正確な枝と同じ未正規化の尺度で合算するためである。主要実験では特徴次元64を使う。モデル本体の注意や重みは変更せず、写像は残差推定の補助機構に限定する。

入力事前処理の際に中間領域の各鍵・値から、値と鍵特徴の外積和S_M、および鍵特徴の和u_Mを作る。S_Mは値の次元×特徴次元、u_Mは特徴次元の固定形状である。文脈長が増えてもこの要約の形状は変わらず、生成ステップで再利用できる。問い合わせ時にはS_M φ_q(q)が中間領域の未正規化分子、φ_q(q)^T u_Mが分母の推定になる。要約だけで元のKVを消せるわけではなく、正確参照のためのKVは引き続き保持する。

### 2. 取得済みトークンの減算

中間領域全体の要約には、すでに正確に読むTop-Kの寄与も含まれる。そのまま正確な分子・分母へ要約を足すと、Top-Kを二回数えてしまう。そこで取得した鍵・値について同じ特徴写像で寄与を計算し、S_Mとu_Mから差し引く。こうして未取得集合だけの要約S_Rとu_Rを作る。取得済みトークンは正確な枝の計算のために読み込んでいるので、減算のために未取得KVを追加で読む必要はないが、特徴写像の追加計算は必要になる。

### 3. 一回の正規化

残差要約から推定した分子ν̂_Rと分母Ẑ_Rを、正確な集合のν_EとZ_Eにそれぞれ加え、(ν_E+ν̂_R)/(Z_E+Ẑ_R)を返す。生成後のトークンは別の正確な枝として同じ分子・分母へ加える。二つの正規化済み注意出力を適当な重みで混ぜるのではなく、未正規化の質量を同じ尺度で合計してから割る点が中心である。特徴写像が指数核を完全に表現できれば全注意へ一致するが、有限次元の写像では推定誤差が残る。

### 4. 特徴写像の学習費用

元のLlamaモデルを凍結し、非対称な正値写像だけをオフラインで学習する。全注意の教師トレースを使った温度付きKL蒸留に、重要スコア帯や残差分母の較正を促す損失を組み合わせる。学習にはFineWebや長文要約文書、BIGPATENT等を利用する。64k用の写像は1Bで8基のH200を19時間、3Bでは35時間用いて学習したと付録が報告する。追加重みは1Bで378.5M、3Bで559.3Mパラメータと大きい。要約状態が小さいことと、補助学習モデルが小さいことは同義ではない。

## 評価

### 評価環境と比較の設計

| 項目 | 条件 |
|---|---|
| バックボーン | 凍結Llama-3.2-1B/3B-Instruct |
| 文脈 | 4k、8k、16k、64k、主要表は4k/16k/64k |
| 正確参照集合 | sink 4個、tail 16個、残りは総当たりTop-K |
| 参照予算 | 0.5%、1%、2%、4%。先頭・末尾20個を含む |
| 1%での中間取得数 | 4kで21、16kで144、64kで636 |
| 制御タスク | RULER 13タスク各500例、BABILong QA1～QA5計4996例 |
| 自然言語生成 | GovReport、QMSumの要約、MuSiQue、HotpotQAの複数文書QA |
| 主要比較 | 全注意、選択のみTop-K、残差補完、減算なし残差補完 |
| 実行時間 | H200 1基、未融合PyTorch、バッチ1、32トークン生成 |

RULERとBABILongは長文脈から情報を取り出せるかを調べる制御タスクである。LongBenchの要約はROUGE-L、複数文書QAはF1で評価する。評価指標が異なるので、表の数値を横断して単純平均してはならない。主要な正確参照予算は全トークンの1%であり、検索器の総当たり費用を削減した結果ではない。

### RULERとBABILong：同じ集合での質量補完

| モデル・タスク・長さ | 全注意 | Top-Kのみ | 提案法 |
|---|---:|---:|---:|
| 1B、RULER、4k | 0.803 | 0.732 | 0.753 |
| 1B、RULER、64k | 0.581 | 0.541 | 0.548 |
| 3B、RULER、16k | 0.816 | 0.787 | 0.814 |
| 3B、RULER、64k | 0.721 | 0.688 | 0.711 |
| 1B、BABILong、64k | 0.140 | 0.102 | 0.122 |
| 3B、BABILong、64k | 0.215 | 0.184 | 0.197 |

原著表2の全12条件で、提案法は選択のみTop-Kより改善した。3B・RULER 16kでは0.787から0.814へ改善し、全注意0.816に近づく。一方、1B・RULER 64kでは0.541から0.548と改善が小さく、全注意0.581には届かない。正確な集合を固定した制御比較なので、この差は検索精度の改善ではなく、未取得質量を加えた効果として解釈できる。

### LongBench：要約と複数文書QAで結果が異なる

GovReportとQMSumの要約では、二モデルと四予算の16条件中13条件で選択のみより改善し、1条件は同点、平均差は+0.006である。GovReportの3B・1%では全注意0.331、Top-Kのみ0.324、提案法0.333。対してMuSiQueとHotpotQAの複数文書QAでは16条件中改善6、同点2で平均差は-0.001だった。MuSiQueの3B・4%ではTop-Kのみ0.119、提案法0.109へ悪化する。要約で平均的な質量を戻す効果が見えても、質問の答えに必要な証拠が取得集合に含まれるかが重要なQAでは一律の利得にならない。

### 減算の必要性と推定誤差

原著表3の1Bモデルでは、全注意の出力に対する平均相対L1誤差を測る。Wikitext 4kではTop-Kのみ0.267、減算なし補完0.238、減算あり0.191。CWE 4kでは0.210、0.290、0.173となり、減算なしはむしろ悪化する。Wikitext 64kでは0.160、0.147、0.103。取得済みトークンの寄与を減算する操作が、二重計上を避けるための構造的条件であることを示す。残差分母の推定誤差は文書種や長さで正負が変わり、単一の補正係数では全条件を較正できない。

### 実行時間：高速化は未実証

付録Hの未融合PyTorch試作では、1B・64kの生成1ステップが全注意6.84ms、Top-Kのみ52.04ms、提案法84.58msであった。3B・64kでも17.09ms、88.54ms、144.03msと、提案法が最も遅い。総当たりの検索費用と補助特徴写像の演算が大きいため、実用的なKV読取削減システムとしての高速化は現状確認されていない。提案が正確に扱う集合の割合と、実機で実際に読み込んだKVバイト数は別である。将来の効率的な検索器や融合カーネルによる改善余地はあるが、その倍率は原著で測定していない。

### 学習と文脈長の制約

特徴写像の学習には8基のH200を長時間用い、数億の追加パラメータを保持する。64kで学習した写像を64k以下へ使うのが主要設定であり、4kで学習した写像を8k・16kへ延長すると性能が崩れる条件を付録Eが報告する。固定長要約の形状が文脈長に依存しないことと、学習した写像が任意長へ一般化することは異なる。長文脈の容量削減を目的とする場合、要約状態の小ささだけでなく追加モデルのメモリ費用も評価する必要がある。

## 既存研究との差

StreamingLLM、H2O、SnapKV、Quest、RetrievalAttention等は、どのトークンやブロックを保持・取得するかという選択に重点を置く。提案法はその選択集合を固定し、選ばれなかったトークンの未正規化分子・分母をどう補うかに焦点を当てる。線形注意への全面的な置換やモデル構造の変更ではなく、元のsoftmax注意と正確なKV枝を保持したまま残差だけを近似する点で異なる。

## 精度改善と速度改善を分離した判断

残差質量の補完は、選択された少数の過去トークンに過大な注意重みを割り当てる問題を緩和する。その効果を調べるために同一の選択集合を使った点が本研究の実験設計の強みである。反対に総当たりの選択器は実用化を意図したものではないため、性能改善の実証には別途、効率的な候補検索と特徴写像の融合実装が必要となる。

## 限界と結論

実用的な高速検索器は実装しておらず、総当たりTop-Kを使った制御実験である。LongBenchの複数文書QAは混合結果で、特徴写像の推定誤差も残る。補助モデルの学習・重みの費用は大きく、未融合試作は全注意より遅い。従って「1%のKV読込で全注意と同等の品質と速度を得た」とは言えない。研究上の確実な寄与は、取得集合の選択誤差と未取得質量の会計誤差を分離し、後者を改善する規則と制御評価を提示した点である。
