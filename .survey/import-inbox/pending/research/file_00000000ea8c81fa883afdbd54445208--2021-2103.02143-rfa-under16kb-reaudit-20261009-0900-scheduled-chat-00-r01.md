# Random Feature Attention：ランダム特徴による線形注意の再監査・修復

## 概要

本論文が扱うのは、標準的な指数正規化注意（softmax attention）において、各質問ベクトルが過去のすべての鍵ベクトルと内積を計算するため、自己回帰復号で生成長が増すほど注意処理が重くなる問題である。提案するランダム特徴注意（Random Feature Attention、以下RFA）は、指数内積を有限個のランダム特徴の内積へ近似し、先に鍵と値の情報を集約する。各時刻に保持するのは、特徴と値の外積を足した行列、および特徴を足したベクトルであり、過去の鍵値列を毎回走査する必要がない。因果的注意（causal attention）では新規トークンごとにこの二つの状態を更新し、交差注意（cross attention）では入力文の特徴集約を一度作って復号中に再利用する。

提案法は厳密な指数正規化注意の単なる実装高速化ではない。ランダム近似のため注意重みが変化し、モデルはその演算に合わせて学習する。実験では、約3800万・2億4200万パラメータの言語モデル、三つの機械翻訳タスク、長文分類三課題を扱う。機械翻訳の単一TPU v2・バッチ32では基準モデルとほぼ同じ翻訳品質で復号速度1.8～1.9倍、長さ2048の条件付き生成模擬実験では約12倍・使用メモリ10%未満を報告した。一方、512トークン単位で並列計算できる言語モデル学習は約15%遅く、線形の計算量がそのまま全条件の高速化を保証するわけではない。

## 問題設定と性能上の支配項

標準注意では、時刻tの質問q_tに対して鍵k_iの内積を指数化し、全鍵にわたる分母で正規化して値v_iの加重平均を求める。入力全体を一括処理できる符号器では質問を並列化できる一方、自己回帰生成では新しい質問が時刻ごとに到着する。過去長Mに比例した鍵値の読み込みと内積が各生成ステップで発生し、長さNの生成全体では二次の計算になる。過去の鍵値をキャッシュしても再走査がなくなるわけではなく、キャッシュ容量とメモリ帯域の負担が残る。

RFAは、疎注意のように参照する過去位置を選別するのではなく、すべての鍵値の寄与を一つの集約状態に変える。したがって計算量の改善は「注意行列の何割を飛ばすか」ではなく、「質問到着前に鍵側の寄与を畳み込めるか」に由来する。ただし、集約は一般には元の鍵値列を復元できない。古い位置の情報を個別に再選択する柔軟性を失うため、学習済み標準注意モデルへ何も変更せず導入することと、RFAを使ってモデルを学習し直すことを混同してはならない。

## 手法

### 1. 指数内積をランダム特徴の内積へ変換する

出発点は、標準注意の分子・分母に現れる `exp(q·k/τ)` である。著者らは質問と鍵を長さ1へ正規化した場合を基本形とし、ガウス核のランダムフーリエ特徴を用いて `exp(q·k/σ²)` を `φ(q)^T φ(k)` に近似する。ここでσ²は温度に対応し、φは乱数で生成した射影を通した正弦・余弦を並べた特徴写像である。ランダムベクトルの個数をDとするとガウス型の特徴次元は2Dであり、近似分散はDを増やすほど小さくなる。特徴を大きくすると精度は安定し得るが、特徴生成と集約状態の保存費用も増える。

論文の式(4)では、正規化によって生じるガウス核と指数内積の関係を利用している。単に指数関数を一次関数に置き換えたわけではなく、二つの特徴ベクトルの内積で近似できる核を経由する点が重要である。式(5)では分子の `Σ_i φ(k_i)⊗v_i` と分母の `Σ_i φ(k_i)` をそれぞれ質問に依存しない集約へ移動する。質問が来た時点では、φ(q)をこれらに掛け、正規化して注意出力を得る。特徴の外積和は過去のトークン数ではなく特徴次元と値次元に依存する固定形状の状態になる。

厳密な指数正規化注意では内積が非負の指数重みになるのに対し、有限個の正弦・余弦特徴による推定には近似誤差がある。論文は乱数射影の再標本化と特徴数を実験で調整しており、近似誤差の理論的分散と、学習後の予測品質を別々の問題として扱う必要がある。特徴写像が近い核を近似していても、学習済み重みが異なる注意演算へ自動的に移植できることは示さない。

### 2. 因果的復号の二つの再帰状態

時刻tまでの鍵値列に対して、状態行列を `S_t=S_(t-1)+φ(k_t)⊗v_t`、状態ベクトルを `z_t=z_(t-1)+φ(k_t)` と更新する。注意出力は `φ(q_t)^T S_t / (φ(q_t)·z_t)` で得る。状態の初期値はゼロであり、トークンごとに新しい鍵と値を射影して足し込む。ここでSは2D×d、zは2Dの大きさを持つ。したがって過去の鍵値数Mを増やしても保存する状態の形は変わらない。

この式は質問ごとに全履歴を読む操作を、質問特徴と集約状態の行列積・内積へ置き換える。新規トークンの鍵値を状態に反映してからその時刻の質問に答えるため、未来の情報を参照しない因果条件も保たれる。演算順を間違えて質問に答えた後で状態を更新すると自己位置を参照できず、原著の式(6)とは別の計算になる。実装時には状態更新の順序と分母の数値安定性を検証する必要がある。

### 3. 符号器・復号器間の交差注意

交差注意では、入力文の鍵値は生成開始時にすべて分かっている。RFAは入力文からSとzを一度構築し、復号側の各質問が同じ集約を参照する。元の標準交差注意では入力長Mに応じた鍵値表現を保持するが、RFAは特徴数と値次元で決まる集約を保持すればよい。論文の空間計算では質問特徴、S、zを合わせた概算が `O(4D+2Dd)`、標準交差注意の鍵値保存は `O(Md)` である。したがって `2D << M` の長い入力文では、集約状態を作る追加費用を含めてもメモリ削減が期待できる。

ただし短い入力文では特徴の外積行列の方が高価になり得る。論文は通常の翻訳実験で、符号器の注意は標準のまま維持し、復号器の因果注意と交差注意だけをRFAへ置換した。符号器まで一律に置換したと説明すると、実験の設計と速度差の因果関係を取り違える。翻訳時の特徴数は交差注意D=128、因果注意D=64であり、同じDでもガウス型の実特徴数は2Dとなる。

### 4. 最近の情報を重視する学習可能なゲート

RFA-Gateは、復号器の入力表現x_tから `g_t=sigmoid(w_g·x_t+b_g)` を計算し、既存のSとzをg_t倍、新規鍵値の寄与を `(1-g_t)` 倍して足す。ゲートが1に近い場合は過去の集約を長く残し、0に近い場合は新しいトークンの寄与が強くなる。単純な時刻差の固定減衰ではなく、現在の入力から忘却率を学習する設計である。著者らは追加パラメータがモデル全体の0.1%未満であると報告している。

重要なのは、ゲートが二つの状態へ整合的に適用される点である。分子だけを忘却し、正規化に用いる分母を忘却しなければ、値の重み付けと正規化の意味が一致しない。ゲートはRFAの再帰表現に自然に追加できるが、翻訳では品質改善が目立たず、言語モデルでの効果が大きい。従って「ゲート付きがすべてのタスクで最良」とは言えない。

### 5. 射影分散の学習と核の比較

質問と鍵の単位長正規化は指数内積の振幅を狭めるため、固定温度のままでは注意分布が平坦になりやすい。著者らは標準正規分布から得た固定乱数射影を、学習可能な成分別尺度σで再パラメータ化する。乱数ベクトル自体を直接学習するのではなく、尺度を学習する点に特徴がある。論文はこの異方的な学習尺度では、もとの等方ガウス核に対する厳密な不偏性の議論がそのまま成立しないことも明記している。

さらにガウス型の正弦・余弦特徴と、一次の弧余弦核に基づく正規化線形特徴を比較した。後者は同じDで特徴次元が小さく、復号速度とメモリではわずかに有利だが、言語モデルの困惑度ではガウス型が安定して良い。特徴次元を増やすと近似誤差が減る一方、処理量と学習安定性の損益が変わるため、核の種類とDの両方を選ぶ必要がある。

### 長系列復号、特徴数の感度、負の結果

長系列模擬実験は、入力長と出力長を同じに設定し、翻訳と同規模の6層符号器・復号器で行う。単一TPU v2、貪欲復号、バッチ16の条件では、長さ2048で約12倍の復号速度と標準注意の10%未満のメモリ使用量を報告する。図2は入力長と出力長を連動して増やしたときの傾向を示しており、翻訳ベンチマークの実データで2048トークンを必ず生成したという意味ではない。標準注意側にも鍵値キャッシュを用いている点が比較の公平性に関わる。

特徴次元の感度試験はWMT14英独の開発集合で行い、探索復号やチェックポイント平均を行わない条件でBLEUを測定した。交差注意の実特徴次元を32・64・128・256・512と変えると、32と64は学習が収束せず、128で24.9、256で25.8、512で26.0となる。因果注意の実特徴次元を32・64・128・256・512と変えると、32は収束せず、64で25.3、128と256で25.8、512で25.6となる。交差注意256、因果注意128程度から改善が頭打ちになるため、特徴を無制限に増やしても利得がない。

原著の追加実験では、標準注意で学習した重みをそのままRFAで評価したり、その逆を行ったりすると、ほぼ未学習モデルに近い性能となる。つまりRFAで学習したモデルの高い精度は、RFAが各トークンで標準注意の重みを精密に再現した結果ではない。近似注意に合わせてモデルが学習したことを示唆する結果であり、学習済み大規模言語モデルの鍵値キャッシュをそのままRFA状態へ無損失変換できる根拠にはならない。

## 既存手法との違いと推論基盤への含意

疎注意は過去の位置の一部を選んで計算し、線形射影型の長系列注意は系列方向の圧縮を学習する。一方RFAは指数内積をランダム特徴で近似し、すべての鍵値寄与を特徴空間で集約する。近い時期のELU+1型線形注意と比べても、特徴写像を変えるだけでWikiText-103の困惑度と翻訳BLEUに大きな差が生じる。核近似の理論だけでなく、特徴の分散、正規化、ゲート、学習条件が実性能を左右することが分かる。

推論システムの観点では、RFAの利点は生成済みトークン数に比例して増える鍵値キャッシュを、一定形状の再帰状態へ置換できることである。長い出力を単一要求で生成する場合、状態の更新が過去長に依存しない点は重要である。しかし、現代の大規模言語モデルのページ化鍵値キャッシュ、連続バッチ処理、グループ化質問注意、注意カーネルの最適化、プレフィルと復号の分離に対する性能は原著では測っていない。2021年のTPU評価の倍率を現在のGPUサービングにそのまま移すことはできない。

また、RFAの固定状態は個別トークンの鍵値を残さないため、長い文脈から特定位置の情報を精密に再検索する用途で、厳密な指数正規化注意と同じ振る舞いを保証しない。論文は長文分類と機械翻訳では実用的な品質を示したが、複雑な検索・複数文書照合・エージェントの長期記憶などの評価を行っていない。したがってシステム最適化だけでなくモデル品質・学習方法の変更を伴う手法として扱うべきである。

## 限界と再監査判断

第一に、ランダム特徴は有限次元の近似であり、特徴数が小さいと収束失敗が起こる。付録のWMT14感度試験では交差注意の特徴次元32・64、および因果注意32で学習が収束していない。精度が必要なために特徴数を増やすと、固定状態の容量と特徴生成の演算量が増え、短系列では逆効果になる。

第二に、言語モデルでゲート付きRFAの困惑度が良くなったことは、ゲートなしのRFAが標準注意と同等品質だったことを意味しない。ゲートなしガウス型は両モデル規模で基準より悪く、状態継承は過去バッチの情報を追加で利用するため別条件である。言語モデル学習の約15%減速も、復号時の高速化と切り分けて記録すべき負の結果である。

第三に、最大12倍という速度は単一TPU v2・バッチ16・入力と出力を同じ長さにした模擬条件付き生成の結果であり、実際の機械翻訳ベンチマークでは1.8～1.9倍である。長文分類の最大5.3倍はIMDbの長さ4000での処理速度で、生成トークン速度とは別指標である。数値を条件なしで並べると性能を過大評価する。

第四に、論文が扱うモデル規模は現代の大規模言語モデルより小さく、GPUの最新注意カーネルや混合精度、分散推論、鍵値オフロードとの直接比較がない。近似による長距離の選択的検索能力への影響も未検証である。著者公開実装はあるが、その存在だけで現行サービング基盤へ統合済みと判断しない。

以上より、本件は論文固有の核近似、再帰状態、ゲート、温度学習、実験条件と負の結果を原著の式・表・付録と照合して修復した。単なる文字数増加ではなく、言語モデル・翻訳・長文分類・長系列模擬実験の指標と実行条件を分離しており、再監査の意味基準を満たす。
