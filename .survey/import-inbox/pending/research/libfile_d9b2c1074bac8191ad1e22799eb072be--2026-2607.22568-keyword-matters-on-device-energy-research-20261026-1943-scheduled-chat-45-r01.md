# Keyword Matters：オンデバイスLLMの指示動詞と推論電力の実測関係

## 概要

本研究は、オンデバイスLLMに同じ目的の指示を与えても、文頭の命令動詞が違うと生成トークン数やデコード電力量が変わるという現象を、実機で測定した論文である。従来の推論効率化は量子化、剪定、推論カーネル、KVキャッシュ管理などモデル・実装側の変更が中心だった。これに対して本論文は、モデルや実行器を改変せず、利用者の入力文という外側の制御変数を測る。目的は「特定の単語を常に使えば速くなる」という普遍則の発見ではなく、語彙選択によるエネルギー差の存在、そのモデル・端末・タスク間の安定性、回答品質との関係を調べることである。

著者は文章生成と二値感情分類を用意し、元の指示文に含まれる命令動詞だけを10通りに置換した。50件の基礎入力を各10変種へ展開するため、各タスク500件、合計1,000種類の入力を用意し、5モデルで計5,000の入力・モデル実行を行う。端末はOrange Pi 5 ProとGoogle Pixel 9aを使い、応答時間と電力量を収集する。結果の解釈では、絶対電力量と「同じモデルの全動詞平均からの偏差」を区別する必要がある。論文で強調される18.5%、62.6%等は後者の相対値であり、別モデルや別端末の絶対エネルギーをそのまま比較した値ではない。

代表結果は、文章生成のQwen 0.5Bで「create」がデコード電力量をモデル内平均比18.5%減らし、Qwen 1.5Bの「craft」が26.5%増やしたこと、感情分類の「label」が全5モデルで32.1～62.6%低いことだ。ただし、異なるモデル間の動詞順位相関は文章生成で平均Spearman ρ=0.153、感情分類で0.388と低い。**語彙効果は実在するが、最適な語をモデル非依存に決める根拠は弱い**、というのが実装者にとって重要な結論となる。

## 問題設定と先行研究との差

オンデバイス推論は通信不要・プライバシー保護・オフライン動作の利点がある一方、バッテリー、熱、DRAM容量、CPU/GPU/NPUの演算能力に制約される。自動回帰型LLMの出力が長くなるほど、通常はdecodeステップと消費電力の積算が増える。量子化や専用ランタイムは1トークン当たりの計算費用を変えるが、入力の言い回しが引き起こす出力長そのものには必ずしも直接介入しない。したがって、**同じモデル・同じ端末・同じタスク内容で、指示動詞だけを変える**という実験は、ソフトウェアスタックの最適化とは別の制御可能性を調べる意義がある。

FlashAttentionは注意計算のI/Oを削減し、PagedAttentionはKV管理を効率化し、投機的復号は複数トークンの検証をまとめる。これらは内部演算の効率を上げる技術である。対して本論文は推論内部に新しいアルゴリズムを挿入せず、ユーザー指示の動詞を変えたときの出力とエネルギーを比較する。Chain-of-Thoughtや自動プロンプト最適化は回答品質・推論過程を重視することが多いが、本研究は実測電力量と回答品質を同時に扱う。ただし、語彙差がモデル内部のどの注意ヘッドや演算を変化させたかを解析する論文ではなく、エネルギー差の主な媒介として応答長を観測する実証研究である。

## 手法：指示語置換から電力・品質の比較まで

### 1. 入力群の構築と統制

入力は二つのタスク群から構成する。文章生成にはAlpaca-GPT4由来の説明・創作等の指示を50件選び、命令動詞を10種類に差し替える。感情分類にはYelpレビュー50件を固定し、二値の感情を求める短い命令文の動詞だけを10種類に置換する。元の入力内容やレビューが動詞ごとに変わると、語の効果と難易度の効果を分離できない。著者らは初期の「動詞ごとに別の50入力を選ぶ」設計では環境をまたいで不自然に一貫した結果が出たと説明し、同一の基礎入力を使う対応付き設計へ変更した。この実験設計の修正は再現性を考える上で重要である。

文章生成の置換が難易度を大きく変えていないかは、NVIDIAのprompt task/complexity分類器で検証する。元入力の平均難易度0.3048に対して置換後0.3199、差は+0.0151であり、入力単位の難易度順位相関はPearson r=0.942、Spearman ρ=0.944だった。ただし、分類器のスコア分布が近いことは人間にとっての意味的等価性を完全に保証するものではない。特に「label」と「analyze」は求める出力の詳しさを変える可能性がある。

### 2. 実機上での推論・電力計測

Orange Pi 5 ProではPython APIからモデルを実行し、FNIRSI FNB58と電力データロガーを使って外部から電力を測る。Pixel 9aでは電池放電中の消費電力を記録できるようMLCChatを改造する。どちらも推論に付随する時間をTTFT（最初のトークンまで）とTBT（トークン間時間）へ分け、応答長と電力量を記録する。瞬時の電圧・電流は10 Hzで取得し、積算エネルギーをprefillとdecodeに分ける。主結果の図では特記がなければdecodeエネルギーを用いる。

Pixelはroot化し、CPU周波数をコア群ごとに固定し、熱スロットリング、適応輝度、バックグラウンドサービスを無効化している。画面輝度は最低に固定した。Orange Piでは無関係な処理の干渉を減らすためmulti-user modeで計測する。モデルの状態やメモリ蓄積の影響を抑えるため各試行の前にモデルを再ロードし、異常に生成を続ける小型モデルを止めるため出力を最大1,000トークンに制限した。これらの条件は実験の雑音を減らす一方、一般のスマートフォンの日常利用や熱制御が有効な長時間連続実行とは異なる。

### 3. モデル・タスク横断の比較量

Qwen、SmolLM、Gemma、Llamaの4系列から合計5モデルを選び、可能な範囲でパラメータ規模と量子化条件をそろえた。Qwenの0.5Bと1.5Bのようにモデルサイズ差も一部評価している。Gemma以外はinstruction-tunedモデルであり、Gemmaだけ学習・指示追従特性が異なる。論文本文で特定の全モデルの正式checkpointとすべての量子化ビット数を完全には一覧化していないため、ここでは確認できない形式を推測で補わない。

各動詞の電力量は、同じモデルの動詞全体の平均に対する百分率偏差として集計する。これによりモデル間の基礎消費電力の違いを取り除き、語彙の相対順位を比較する。順位の安定性はSpearman相関で測る。**同じ語で電力偏差が小さい**ことと**別の端末でも最小エネルギーになる**ことは同義ではない。さらに、出力長が1,000トークン上限に張り付くと語彙による差が見かけ上縮むため、上限到達は「省エネ語の効果が小さい」という単純な結論を妨げる。

### 4. 回答品質の評価

回答はDeepEvalのG-Evalを使い、GPT-4.1-miniを評価者として関連性、事実性、首尾一貫性、簡潔さの観点で採点する。著者は0～4のスコア尺度で2を合格と説明する。これにより、単に短い出力で電力量が減った場合と、必要な情報を落とさず短く回答した場合を区別しようとする。ただし、この評価は人手で厳密に正解ラベルを照合する方式ではなく、評価モデル自体のバイアスや、関連性と正確性を混同する採点誤差がある。エネルギーと品質の相関はその制約付きで解釈する。

## 評価

### 評価環境と指標

| 軸 | 一次論文で確認できる条件 | 解釈上の注意 |
|---|---|---|
| 端末 | Orange Pi 5 Pro（Ubuntu 22.04）、root化Pixel 9a（Android 15） | Pixelは周波数・輝度・熱制御を固定。通常利用とは異なる |
| モデル | Qwen、SmolLM、Gemma、Llamaの4系列から5モデル | Qwen 0.5B/1.5B、SmolLM2 1.7Bなど。Gemmaは非instruct |
| 文章生成 | Alpaca-GPT4由来50入力×命令動詞10種 | 動詞以外の基礎指示を対応付け |
| 感情分類 | Yelpレビュー50件×動詞10種 | 二値分類、出力長が短い |
| 実行数 | 1,000種類の入力×5モデル＝5,000 prompt-model runs | 各試行1回で反復なし。端末別配分の厳密な総数は本文だけでは断定しない |
| 測定 | 電圧・電流10 Hz、TTFT、TBT、応答長、prefill/decode電力量 | 主結果はdecode電力量。全端末の総バッテリー消費とは異なる |
| 応答上限 | 1,000トークン | ループや長文生成は打ち切り |
| 品質 | GPT-4.1-miniをjudgeとするG-Eval | 人手採点の完全な代替ではない |

論文の装置比較では、Orange Piの平均prefill時間115 msに対してPixelは87,000 msと記載され、TBTはそれぞれ114 msと100 msだった。Pixelのprefillが極端に遅い点は、著者自身が今後の調査対象として挙げている。**この差を純粋なハードウェア性能比と解釈するのは危険**である。測定経路、モデルロード、前処理、端末設定の相違を切り分けた同条件ベンチマークではない。

### 主要結果：語彙ごとの電力量差

| タスク・条件 | 指示語・比較対象 | 報告値 | 読み方 |
|---|---|---:|---|
| 文章生成、Qwen 0.5B | create、同一モデルの動詞平均比 | −18.5% | decode電力量の減少 |
| 文章生成、Qwen 1.5B | craft、同一モデルの動詞平均比 | +26.5% | decode電力量の増加 |
| 文章生成、Llama | output、同一モデルの動詞平均比 | −4.2% | Qwenほど語彙感度が大きくない |
| 文章生成、5モデル平均 | create / generate / output | −7.7% / −4.6% / −2.7% | モデル内偏差の平均。絶対電力差ではない |
| 文章生成、5モデル平均 | construct | +5.6% | 平均で不利だがモデル別例外がありうる |
| 感情分類、全5モデル | label | −32.1%～−62.6% | 5モデル全てで同一モデル平均を下回る |
| 感情分類、5モデル平均 | label / categorize / classify | −48.64% / −24.5% / −19.86% | 識別を要求する短い語が有利 |
| 感情分類、5モデル平均 | analyze / assess | +35.9% / +27.02% | 詳細な分析を促す語が不利 |

文章生成の語彙差はモデルによって大きく異なる。Qwen系列では「create」が両サイズで約18%低かったが、Llamaでは最も省エネな「output」でも4.2%低下にとどまる。Gemmaは語彙感度が最も小さいが、論文では回答品質が低く、反復出力によって最大1,000トークンへ達する例が多かったと説明される。したがって、Gemmaの小さい偏差は「モデルが語彙に頑健」と肯定的に解釈するより、**上限到達による測定値の飽和**を疑う必要がある。

感情分類では「label」が全モデルで有利で、文章生成より大きい百分率差を示した。短い分類回答は、わずかなトークン増減でも相対エネルギーが大きく動く。論文は「label」が常に高品質かつ同じ情報量を出すと保証したわけではない。実際には「analyze」のような語は単純なラベル以外の説明を引き出す可能性がある。要求仕様が二値ラベルのみなら短く指示する設計が妥当だが、根拠説明を必要とするタスクで一律に短縮するとタスク達成度が変わる。

### モデル間・端末間の再現性

| 比較 | Spearman順位相関 | 解釈 |
|---|---:|---|
| 5モデル間のペア平均、文章生成 | ρ=0.153 | 最適動詞の順位はほとんど一致しない |
| 5モデル間のペア平均、感情分類 | ρ=0.388 | 一部共通傾向はあるが普遍的順位ではない |
| Qwen 0.5Bと1.5B、文章生成 | ρ=0.588 | 同系列では比較的近い |
| Qwen 0.5Bと1.5B、感情分類 | ρ=0.867 | 同系列・分類タスクで高い一致 |
| Orange PiとPixel、Qwen文章生成 | ρ=0.261 | 端末間で順位が不安定 |
| Orange PiとPixel、SmolLM文章生成 | ρ=0.697 | Qwenより高いが完全一致ではない |
| Orange PiとPixel、Qwen感情分類 | ρ=0.939 | 端末をまたいで高い一致 |

重要なのは、モデル系列を固定すると相関が上がる例があっても、すべてのモデル・タスク・端末へ転用できる単一の語彙ランキングは得られていないことである。文章生成は開放型でサンプリングの偶然性に左右され、分類は出力の自由度が小さいため比較的安定する、と著者は解釈する。ただし各試行1回なので、観測された差のどこまでが語彙効果で、どこまでが乱数・温度・実行状態に由来するかは統計的に十分に切り分けられていない。

### 品質とエネルギーの交換条件

文章生成では、語彙ごとのエネルギー順位と品質順位のSpearman相関が平均−0.086であり、著者は品質への目立った影響がないと述べる。これは**観測した評価器・モデル・タスクの範囲**での傾向であって、品質不変性の証明ではない。感情分類では相関−0.632であり、エネルギーを多く使う語の方がむしろ低品質と評価される傾向があった。著者は長い回答に誤りが増える可能性を示唆するが、judgeの採点混同があり、因果関係の確定には至らない。

## 実装への示唆と既存技術との接続

本研究をオンデバイスLLMの実装に使う場合、命令文を「モデルごとのエネルギーと品質の測定に基づいて」選ぶ設計が考えられる。特に二値分類のように必要な出力形式が明確な処理では、詳細説明を要求する語を避け、短いラベルを求めることが電力と遅延の両方に寄与しうる。これを実装するには、固定したモデル・量子化・端末・サンプリング設定で複数の動詞を反復評価し、平均電力量、分散、応答長、品質を同時に保存する必要がある。論文はこのような自動書換え器を**将来計画**として挙げるが、完成したGreen Prompt Engineの実測性能は報告していない。

モデル量子化やKVキャッシュ最適化との関係では、語彙変更による出力長の変化と、ランタイム変更によるトークン当たり費用の変化を区別するべきである。両者は理論上併用できるが、実測した節電率を単純加算・乗算できるとは限らない。特にprefillエネルギー、端末の待機電力、画面・通信の費用を含む総電力量は、decode偏差と一致しない。サービス設計では電力だけでなくTTFT、TBT、総遅延、回答の妥当性を同じ条件で測る必要がある。

## 限界・負の結果

第一に、**各入力・モデル条件の測定は1回だけ**で反復・信頼区間がなく、実験の乱数依存や測定ノイズを十分に評価できない。語彙差が18%であっても、その差が再試行で安定するかを示す統計検定はない。第二に、量子化条件は一つに限定され、別ビット幅・別バックエンドでの一般化は未検証である。第三に、基礎データはAlpaca-GPT4とYelpの二系統だけで、コード生成・多言語推論・長文RAG等に外挿できない。

第四に、GPT-4.1-miniによるG-Evalは関連性と正確性を混同している例があり、エネルギー・品質相関の信頼性に影響する。第五に、PixelとOrange Piのprefill時間に極端な差があり、実装・端末設定・計測区間の差を切り分けられていない。第六に、1,000トークン打ち切りに達するGemmaの反復応答は、電力量偏差の小ささを偽装する。第七に、研究の主指標はdecode電力量であり、バッテリー残量や端末全体の運用時間、生成品質を同時に最適化した結果ではない。

総合すると、語彙選択がオンデバイス推論のエネルギーを変えるという問題提起には実機の根拠がある。一方で、現時点のデータから「createやlabelを全モデルで常用すれば一定割合節電できる」と一般化するのは誤りである。むしろ**モデル・タスク・端末別に再測定すべき制御変数**として指示語を扱うのが適切である。
