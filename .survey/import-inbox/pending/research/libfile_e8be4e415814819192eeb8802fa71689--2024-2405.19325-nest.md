# Nearest Neighbor Speculative Decoding for LLM Generation and Attribution

## 書誌情報
- canonical identity: `arXiv:2405.19325`
- 著者: Minghan Li, Xilun Chen, Ari Holtzman, Beidi Chen, Jimmy Lin, Wen-tau Yih, Xi Victoria Lin
- 一次資料: https://arxiv.org/abs/2405.19325

## 概要
k近傍言語モデル（kNN-LM）のような半パラメトリック生成は、現在のhidden stateで外部datastoreを検索し、取得した実文書tokenを基盤LLMの分布へ混ぜる。外部知識を利用し、どの文書に基づいた生成かを追跡しやすい一方、各tokenで検索と分布合成を繰返すため遅く、局所的なnearest tokenへ引かれて文章が不自然になることがある。

Nearest Neighbor Speculative Decoding（NEST）は、検索結果を「次の1 token」だけに使わず、そのtokenに続く実文書spanを複数tokenのdraftとして利用する。各stepで半パラメトリック混合分布を作り、十分有望な近傍があれば対応するcorpus spanを候補列として提示する。近似的なspeculative decoding手順がそのprefixをまとめて受理し、受理できない地点では基盤モデルから新tokenを生成する。

これにより外部文書由来の連続spanを一度に生成へ取り込めるため、出典（attribution）を明確にしつつ、毎tokenの自己回帰処理を減らせる。知識集約タスクで従来kNN-LMより生成品質・attributionを改善し、in-context retrieval augmentationと競争力のある品質を示す。Llama-2-Chat 70Bでは推論時間1.8倍の高速化を報告する。

## 問題設定
標準LLMは重みに知識を埋め込むため、生成文の出典を示しにくく、最新・希少知識ではhallucinationし得る。retrieval augmented generationは文書をpromptへ入れるが、長いretrieved contextのprefillが必要になる。

kNN-LMはtoken生成中にhidden representationでdatastoreを検索し、近傍tokenの分布とLLM分布を混ぜる。しかしtokenごとに検索するためlatencyが高く、取得文書の連続性を活かさず1 tokenずつ選ぶので、実文書の自然なspanをそのまま利用できない。

## 手法
### token-level nearest-neighbor retrieval
現在prefixからquery representationを作り、外部corpusのdatastoreからnearest neighborを検索する。近傍には次tokenだけでなく、そのtokenが現れた原文位置を保持しているため、後続spanを取り出せる。

基盤LLM分布とretrieval分布を混ぜたsemi-parametric distributionを計算し、外部知識を使うべきか、モデル自身の生成を優先すべきか判断する材料にする。

### span proposal
有望な近傍が見つかった場合、その文書中の後続token列をdraft spanとして提示する。これは小型draft modelが未来tokenを生成する通常のspeculative decodingと違い、既存corpusに実在する連続列がdraftである。

出典位置が既知なので、受理されたspanには自然にattributionを付けられる。1 tokenだけでなく複数tokenを受理できれば、検索結果の局所的一貫性も利用できる。

### approximate speculative acceptance
NESTはretrieved spanを基盤LLMと半パラメトリック分布で検証し、妥当なprefixをまとめて受理する。途中で候補が不適切になればそこでspan利用を止め、新しいtokenを生成・検索して続行する。

「approximate」とされる点は、標準speculative decodingのように純粋なtarget model分布を厳密保存することだけが目的ではなく、retrieval mixture自体を生成方針に含めるためである。したがってTriForce等のlossless target accelerationとは品質保証の意味が異なる。

### attribution
受理spanは特定corpus位置に紐づくので、生成結果のどの部分がどのsourceに由来するかを提示できる。モデルが独自生成した部分とretrieved spanを区別でき、単なる速度最適化に加えて根拠追跡を提供する。

## 評価条件
| 項目 | 条件 |
|---|---|
| 基盤モデル | Llama-2-Chatを含むLLM、70B評価あり |
| タスク | knowledge-intensive generation |
| 比較 | conventional kNN-LM、in-context retrieval augmentation、base LM |
| 指標 | generation quality、attribution rate、inference time |
| draft source | 外部corpusのnearest-neighbor後続span |

## 主要結果
| 指標 | 結果 |
|---|---|
| 生成品質 | conventional kNN-LMを上回る |
| Attribution | kNN-LMより改善、実文書spanにsourceを付与 |
| in-context retrieval | 競争力のある品質 |
| Llama-2-Chat 70B inference | 1.8× speedup |

速度利得はretrieved spanが複数token受理される場合に生じる。近傍が弱く毎stepで候補がrejectされると、検索と検証の追加費用が残り、利得は縮む。

## 既存研究との差
kNN-LMは近傍をtoken分布補正へ使うが、NESTは近傍が存在した原文の「続き」をdraft sequenceとして使う。これによりretrievalを知識補完とspeculationの両方へ利用する。

通常のspeculative decodingは小型モデルの計算をdraftへ使い、target modelと同じ分布を効率的にsampleすることが主目的である。NESTのdraftは外部文書であり、attributionとsemi-parametric generationを目的に含むため、完全に同じ問題設定ではない。

## 限界
高い速度とattributionには、queryに適合した高品質corpusとnearest-neighbor indexが必要である。関連spanが見つからない入力では通常生成へ戻り、検索overheadだけが増える可能性がある。

retrieved spanを長く受理するとsource文面への依存が強くなるため、corpus品質・ライセンス・privacyも実運用上の制約になる。1.8倍はLlama-2-Chat 70Bで報告された結果で、すべてのモデルやretrieval hit率へ一般化できない。
