# Not All Heads Matter: A Head-Level KV Cache Compression Method with Integrated Retrieval and Reasoning

## 書誌情報
- 著者: Yu Fu, Zefan Cai, Abedelkadir Asi, Wayne Xiong, Yue Dong, Wen Xiao
- canonical identity: `arXiv:2410.19258`
- 公開: 2024-10-25
- 一次資料: https://arxiv.org/abs/2410.19258

## 概要
長文脈推論では入力tokenごとの鍵・値キャッシュ（KV cache）が系列長に比例して増える。既存の枝刈り方式は重要tokenだけを残すが、多くは層ごとの固定・動的予算を先に決め、同じ層の注意ヘッドには似た容量を与える。HeadKVは「ヘッドごとに検索・推論への寄与が違うなら、同じKV容量を配る必要はない」と捉え、予算配分そのものを全層・全ヘッド横断で行う。

単なる検索ヘッド検出では、needleをそのままコピーする能力に偏り、複雑な文脈QAで必要な推論能力を測れない。そこでHeadKV-R2は、複数候補と推論条件を含む人工needleを使い、正答部分へどのヘッドが注意を向けるかを連続的な重要度として集計する。この分布に応じて共有予算を再配分し、各ヘッド内では直近instruction tokenからの注意を使うSnapKV型選択で実際に残すKVを決める。

Llama-3-8B-InstructとMistral-7B-InstructをLongBenchとLooGLEで評価し、KV size 64/128の厳しい条件でSnapKV、PyramidKV、Ada-SnapKVより一貫して高い品質を示した。論文の総括では、文脈QAでフルKVの約1.5%だけを保持してフルKV性能の97%を維持する。これは「重要token選択」だけでなく「どのヘッドへ何token分の予算を渡すか」が圧縮品質を左右すことを示す。

## 問題設定
通常の多頭注意では、各層・各ヘッドが独立したquery/key/value射影を持つ。長文脈では全tokenのkey/valueを保持するとメモリが増え、decode時に読むKV量も増える。SnapKVは直近tokenからの注意で重要な過去tokenを選び、PyramidKVは上位層ほど予算を減らす。しかし、同じ層の全ヘッドを同等に扱うと、検索や推論に強く寄与するヘッドと、そうでないヘッドへ同じ容量を配る無駄が残る。

Ada-KVはヘッドごとの注意集中度を使うが、層予算を前提として層内で再配分する。RazorAttentionは検索ヘッドを識別するが、重要ヘッドへフルKVを残す。HeadKVは層境界を外し、全ヘッドを1つの予算市場として扱うこと、さらに検索だけでなく文脈推論を測る重要度を使うことを狙う。

## 手法

### 1. Retrieval Head重要度
基準となる検索ヘッド（Retrieval Head）推定では、needle-in-a-haystack形式で外部文脈に埋め込んだ答えをモデルに生成させる。各decode stepでヘッドの最大注意先がneedle内の正答tokenを指した場合に得点を加え、複数位置・例で集計する。これは「必要情報を長文脈から見つけてコピーする」能力を測る。

ただし最大注意先の完全一致を要求するため分布が非常に疎で、論文では約70%のヘッドが0点になる。また、答えをそのまま検索するだけなので、条件を比較して正しい候補を選ぶような推論を反映しない。この欠点がR2重要度の動機になる。

### 2. Retrieval-Reasoning（R2）重要度
R2ではneedleを推論記述 `r` と2つの候補 `c1`,`c2` に分ける。質問へ答えるには、まず `r` を使ってどちらの候補が条件を満たすか推論し、その後正しい `c2` を取得する必要がある。これにより単純コピーではなく「検索→条件推論→正答取得」の連鎖を要求する。

得点も最大注意tokenだけではなく、正答 `c2` 全体へ向いた上位注意の重みを集計する。したがって重要度分布が滑らかになり、正答情報へ継続的に注意を向けるヘッドへ高い予算を与えられる。出力は全層・全ヘッドの重要度 `S_h` で、後段の予算配分へ渡される。

### 3. 全ヘッド横断の予算配分
各ヘッドへ一律予算 `b` を与えるところから開始し、その一部 `b/β` を全 `L×H` ヘッドから回収して共有プール `B=(b/β)×L×H` を作る。各ヘッドの最終予算は基本分 `b-b/β` と、重要度比例の動的分 `S_h×B` の和になる。βは動的プールの大きさを制御する。

この方式では、ある層の重要ヘッドが別層の低重要度ヘッドから予算を受け取れる。層ごとの固定総量という制約を外す点がAda-KVとの重要な違いである。一方、重要度推定が対象task分布とずれると配分もずれるため、事前に得たR2分布の一般化が前提になる。

### 4. ヘッド内token選択
予算数が決まった後は、直近 `α=8` instruction tokenをlocal windowとして残し、そのtokenから過去tokenへの注意スコアをpoolして重要tokenを選ぶ。これはSnapKVと同型であり、HeadKVの新規性は主として「選択器」ではなく「ヘッドごとの保持数」にある。

最終cacheは基本予算、重要度比例の動的予算、直近local windowから構成される。したがって総KV予算を同一に保った比較で、配分戦略だけの効果を測れる。

## 主要結果

| 条件 | 結果 | 読み取れること |
|---|---|---|
| 文脈QA総括 | 約1.5%のKVでFullKV性能の97% | 極端な低予算でもヘッド配分で品質を維持 |
| Llama-3-8B、KV=128 | HeadKV系がSnapKV/PyramidKV/Ada-SnapKVをほぼ全QAで上回る | 同一総予算でも配分先が重要 |
| HeadKV-R2 vs HeadKV-R | R2が文脈推論系で優位 | 検索能力だけの重要度では不足 |
| Needle/Reasoning-in-a-Haystack | 低予算で検索・推論能力をより保持 | 重要度推定の狙いと下流能力が対応 |
| メモリ・遅延 | FullKVより削減、同予算baselineと同等級 | 品質改善のため総KVを増やしていない |

## 既存研究との差
SnapKVやPyramidKVは「各ヘッド内でどのtokenを残すか」または「層ごとに何token残すか」を中心に設計する。HeadKVはその前段に全ヘッド横断の容量配分を置き、重要ヘッドへより多くのtoken枠を移す。Ada-KVもヘッド情報を使うが、層ごとの予算枠を残す点が異なる。

RazorAttention等の検索ヘッド利用方式に対しては、検索ヘッドへフルKVを残すのではなく、全ヘッドを連続重要度で順位付けして圧縮する。またR2は検索だけでなく推論を含む人工taskで重要度を作るため、長文脈QAに必要な能力をより直接反映する。

## 限界
重要度分布はofflineに構成したneedle taskから得るため、実配備のtask分布が大きく違えば最適配分とは限らない。βも候補集合から最良値を報告しており、完全に無調整の方式ではない。

評価は主に7–8B級のLlama/MistralとQA中心で、GQA/MQAのさらに大規模モデル、コード生成、長い自由生成、オンラインservingでの同時要求スループットまでは十分検証していない。97%という総括値も特定の文脈QA評価に対するもので、全task・全予算で同じ比率を保証しない。
