## 概要

LLMを4ビットで実行すると重みや活性値の転送量・計算量を削減できる一方、事後量子化（PTQ）は小さい数値の丸めや外れ値の扱いにより、学習済みモデルの出力分布を変化させる。特に推論エンジン固有のスケール配置や低精度表現を無視して学習したモデルは、実際に配備した際に性能が落ちる。QATFactoryは、配備先で使用する形式そのものを訓練時の順伝播で模擬し、誤差を含む学生モデルを高精度の教師に近づける量子化対応蒸留（QAD）と、量子化した方策で応答を生成する強化学習（QARL）を統合した公開フレームワークである。

論文の重要な特徴は、低ビット行列積を訓練機器に要求しないことにある。訓練中の重み・活性値をいったん量子化してから復元するが、行列積はBF16で実行する。このためNVFP4用Tensor CoreのないH100でもNVFP4の数値誤差に適応できる。推論側は本来のNVFP4等の演算器を使用し、最終的なチェックポイントをvLLMやllama.cpp等のネイティブ形式へ書き出す。8Bから230B級までの密・MoEモデルを扱い、Qwen3.5-9Bの8課題平均ではNVFP4の最良PTQ 65.4%に対してQAD 68.9%、MXFP4の最良PTQ 56.4%に対してQAD 66.0%を報告する。ただしこの精度改善を推論速度の改善倍率と混同してはならない。

## 問題設定と既存手法との差

一般的な事後量子化は既に学習済みの重みを丸め、場合によっては較正データで量子化誤差を抑える。RTNは丸めによる単純な変換、GPTQは重み誤差を考慮した補正を行う。しかし極端に低い精度では、重みだけでなく活性値の丸め、ブロックスケール、実行時の数値表現によって出力分布が大きく変わる。QATは誤差を訓練に組み込めるが、汎用的な整数形式だけを扱う実装では、実際の推論エンジンのNVFP4・MXFP4・Q4_Kへ移すと再変換や較正が必要になり得る。

本研究は訓練で高精度の潜在重みを維持しつつ、配備形式に従って丸めと復元を行い、その誤差を含むモデルを更新する。形式固有の量子化・逆量子化とチェックポイントのパッキングを共通インターフェースで分離するため、訓練ループを形式ごとに書き換えずに済む。さらに全パラメータ更新とLoRA更新の両方、教師分布への蒸留と検証可能な報酬を使う強化学習の両方を対象とする。単に量子化器を増やした研究ではなく、訓練で観測する誤差と配備後の実際の数値形式を揃える設計を検証した研究である。

## 手法

### 配備形式に一致させた擬似量子化

各対応層は潜在重みを受け取り、目標形式に従ってスケールを決め、低ビット値へ丸めた後にBF16へ戻す。重みのみを訓練時に量子化するW4A16と、重み・活性値の両方を模擬量子化するW4A4を選べる。実際の配備時は両形式ともW4A4であっても、訓練時にどちらが適切かは別問題である。順伝播の行列積はBF16で行い、丸めの非微分性は直通推定器（STE）によって勾配を近似する。更新されるのは連続値の潜在パラメータであり、4ビット整数を直接最適化するわけではない。したがって訓練の計算・メモリがそのまま4ビットになるわけでもない。

NVFP4、MXFP4、Q4_Kではスケールの粒度や表現が異なる。QATFactoryは量子化と逆量子化、およびエンジン用の格納レイアウトを形式別に実装する。配備用の低ビット表現を訓練中の誤差モデルとして再現することが肝心であり、形式名だけを指定して別の丸め規則で学習しても同等とは限らない。量子化対象の層や活性値の扱いを揃え、実際に書き出したチェックポイントを推論エンジン上で評価する必要がある。

### 蒸留とパラメータ効率化

QADでは非量子化教師の応答を用いてデータを構成し、教師と量子化模擬学生の出力分布の前向きKLダイバージェンスを縮小する。教師の最尤トークンを模倣するだけでなく、候補トークン全体の確率分布を近づけるため、量子化に伴う出力分布のずれを訓練目標へ反映できる。主な設定は文脈8K、バッチ16、AdamW、学習率の減衰とウォームアップを伴う。多くの蒸留実験はH100を8枚、より大きなMoEでは16枚または32枚使用する。

全パラメータQADは教師、学生、勾配、最適化器状態を保持するためGPUメモリを多く使う。LoRA版では基盤重みを凍結し、低ランク行列の積BAだけを学習する。推論用の出力時には基盤重みWとBAを合成してから量子化するため、アダプターを別途足すのではなく、配備エンジンが直接使える低ビット重みへまとめられる。ただし、低ランク更新で表現できる補正には限界があり、ランクを大きくすれば必ず全パラメータ版へ近づくわけではない。

### 量子化対応強化学習とチェックポイント出力

QARLでは生成側と学習側のサーバーを分ける。生成側はvLLMなどのネイティブ低ビット推論カーネルで応答を生成し、検証器が報酬を付与する。学習側は高精度潜在重みと最適化器を保持し、擬似量子化した順伝播でGRPOやDAPO型の更新を計算する。更新後には量子化値とスケールを配備形式でパックし、生成側へ同期する。これにより生成側で毎回再量子化・再較正する処理を減らし、通信量も低ビット表現に応じて抑えられる。ただし同期処理自体は消えない。

エクスポーターは学習時と同じ量子化設定を使い、形式固有のスケールやメタデータを推論エンジンの格納形式へ変換する。NVFP4の入力活性スケールなど訓練中に追跡した状態は再較正せず保存する。ここでいう「追加の推論オーバーヘッドなし」はQAT専用の演算を配備時に加えないという意味であり、4ビット演算の実速度が全ハードウェアで必ず優位という主張ではない。

## 評価条件と主要結果

| 観点 | 実験条件 |

| モデル | Qwen3.5-9B、DeepSeek R1 Distill Llama 8B、Qwen3-8B、Qwen3-30B-A3B、MiniMax M2.7等。8B〜230B級 |
| 量子化 | NVFP4、MXFP4、llama.cpp Q4_K。W4A4配備に対しW4A16/W4A4訓練を比較 |
| 蒸留環境 | 主にNVIDIA H100×8。大規模MoEはH100×16/32 |
| 強化学習環境 | B200×4、Qwen3-8B-Base、DeepMath-103K、GRPO/DAPO、1024ステップ、1プロンプト16応答 |
| 精度指標 | GPQA-D、MMLU-Pro、MMMLU、WinoGrande、HellaSwag、AIME25、LiveCodeBench、BigCodeBenchの平均。分布忠実度はUltraChat、Pile、WikiText上のKL |
| 比較対象 | BF16参照、RTN、GPTQ、Q4_KのMSE最適化PTQ、BF16 RL後PTQ |

| 条件・指標 | 比較対象 | QATFactory | 解釈 |
|---|---:|---:|---|
| Qwen3.5-9B NVFP4、8課題平均精度 | 最良PTQ RTN 65.4% | QAD 68.9% | +3.5ポイント。BF16参照71.7%には未達 |
| Qwen3.5-9B MXFP4、同平均 | 最良PTQ GPTQ 56.4% | QAD W4A4 66.0% | +9.6ポイント。W4A16 QAD 57.8%より良好 |
| DeepSeek R1 Distill Llama 8B、NVFP4平均 | GPTQ 46.4% | W4A16 QAD 47.7% | 改善は小幅。W4A4 QADは46.6% |
| Qwen3.5-9B、8K学習時GPUメモリ | 全パラメータ166.53 GiB | LoRA r16 57.19 GiB | 約2.9倍削減。ただし精度の完全回復はしない |
| Qwen3-8B-Base、RL後5数学課題平均 | BF16 RL後NVFP4 PTQ 48.1% | NVFP4 QARL 50.8% | +2.7ポイント。BF16 RLそのものは52.1% |
| 同RL、1ステップ所要時間 | BF16 GRPO 41.83秒 | NVFP4 QARL 33.96秒 | 1.23倍の学習処理量。推論サービスの速度ではない |

特に注目すべきは、配備形式が同じW4A4でも、最適な訓練時の活性値精度が異なる点である。Qwen3.5-9BのNVFP4ではW4A16とW4A4の平均精度はともに68.9%だが、KLの平均はW4A16が0.0682、W4A4が0.0746で、教師分布への近さは前者が良い。対してMXFP4ではW4A4訓練が66.0%、W4A16が57.8%となり、活性値の誤差を訓練時に含める利得が大きい。したがって「配備時にW4A4だから訓練時も必ずW4A4が正しい」という単純な規則は成り立たない。

LoRAのメモリ内訳では、全パラメータQADの永続領域123.56 GiBに対してLoRA r16は17.32 GiBである一方、活性値メモリは32.97 GiBから35.37 GiBと減っていない。低ランク化の恩恵は主として勾配と最適化器状態にある。Qwen3.5-9BのNVFP4で全パラメータQADの平均68.9%に対し、LoRA r4は68.0%、r16は67.8%、r64は67.9%、r256は67.6%で、ランク増加による単調な改善は見られない。

長文脈データを使う蒸留では、総訓練トークン数を固定した比較で32K系列を少数用いる方が、4K系列を多数用いるより平均精度が1.9ポイント高いと報告する。これは訓練時の文脈分布が量子化誤差への適応に影響することを示唆するが、あらゆるモデルやタスクで長い系列が常に最適という証拠ではない。強化学習では低ビット生成の時間が37.46秒から28.31秒へ短縮され、同期時間は0.73秒から0.99秒へ増えても総時間は改善した。生成側が主要律速だった条件での結果であり、学習側の計算が支配的な場合は同じ倍率を期待できない。

## 限界と適用上の注意

訓練中の行列積はBF16であり、4ビットの低メモリ・高速訓練そのものを実現したわけではない。特に全パラメータ版は教師・潜在重み・最適化器状態を保持するので、学習設備の負担が大きい。LoRAはメモリを減らすが、今回の条件では全パラメータ版との精度差を消せなかった。量子化形式によって適切な訓練設定が異なるため、形式間の結果を単純に移植できない。

QARLの1.23倍はB200×4を使った特定の数学推論強化学習のステップ時間であり、量子化モデルのエンドユーザー向け推論速度が1.23倍になったという意味ではない。NVFP4の生成にはネイティブ低ビットカーネルを持つBlackwell系を利用している一方、H100上での擬似量子化蒸留はそのような演算器を必要としない。この二つのハードウェア条件を区別する必要がある。

モデルごとの負の結果もある。DeepSeek R1 Distill Llama 8BのNVFP4ではW4A4訓練の平均精度46.6%がW4A16訓練の47.7%より低い。Qwen3.5-9BのNVFP4でもBF16参照71.7%には届かず、量子化による性能損失は残る。平均精度は異なる8課題の算術平均であり、個別タスクの劣化を隠し得るため、コード・数学など用途別の列も確認すべきである。推論エンジンが対応していない形式やハードウェアでは、チェックポイントのネイティブ読み込みができても期待した低ビット演算性能が得られるとは限らない。

## 既存研究との関係と実用的意義

RTNやGPTQのようなPTQは追加訓練をほぼ必要とせず、運用が簡便である。一方QATFactoryは追加の蒸留データ・訓練計算を支払って量子化損失を回復する。低ビット演算を利用するための新しい推論カーネルを提案するのではなく、既存エンジンで実際に使える形式へ学習時の誤差モデルと出力を合わせる点が貢献である。特にNVFP4を学習機器にネイティブ演算器がない状況で準備できること、LoRAによるメモリ節約と品質低下を定量的に比較したこと、生成サーバーと学習サーバーの分離によってQARLのステップ時間を短縮したことは、量子化モデルの作成と配備をつなぐ実務上の論点となる。
