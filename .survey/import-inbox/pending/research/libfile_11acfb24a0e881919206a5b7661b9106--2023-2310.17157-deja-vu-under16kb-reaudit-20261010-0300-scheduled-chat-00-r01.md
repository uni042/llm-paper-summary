# Deja Vu：文脈依存の疎性を予測して密なLLMを高速に復号する

## 概要

大規模言語モデルの小バッチ復号では、一つのトークンを生成するたびに巨大な重み行列をGPUの高帯域メモリから読み出す必要がある。行列積の演算能力が余っていても、重みを読み込む時間が支配的になりやすい。密なモデルから常に同じ重みを削除する静的枝刈りでは、入力に応じて必要な知識が変わるため、文章生成や文脈内学習の品質を損ない得る。DejaVuは、あるトークンに対して寄与の大きい注意ヘッドと多層パーセプトロン（MLP）のニューロンが一部に限られ、その集合が入力・層ごとに変化する「文脈依存疎性（contextual sparsity）」を利用する。

DejaVuは各層の活性値を小さな分類器に渡して次の計算に必要な重みの索引を予測し、不要なヘッドやニューロンの重みを読まずに済ませる。さらに、層をまたいだ活性値の変化が小さいという観測から、次層の疎集合を本体計算と並行して先読みする。予測器を同期的に呼び出すだけではその時間が節約分を上回るため、非同期実行と、索引抽出・行列積を融合したGPUカーネルが方式の重要な部分である。

ICML 2023の原著では、OPT-175Bを8基のNVIDIA A100 80GB（NVLink接続）でFP16復号し、バッチ1・入力128～1024トークンの条件で、FasterTransformer比1.8～2倍、Hugging Face実装比4.8～6倍のトークン生成高速化を報告する。約75%疎性までは対象の言語モデリングとゼロ・少数例課題で大きな品質低下を示さない。ただし、これは全モデル・全バッチに対する無損失保証ではない。

## 問題設定：疎性が存在しても高速化できない理由

入力に対して本当に必要な重み集合を、密なモデルを一度実行してから測れば理想的な疎性を確認できる。しかしそれを推論時に毎回行えば、節約したかった計算を先に支払うことになる。OPT-175BのMLP計算は8基A100上で約0.2ミリ秒なのに対し、高次元の近傍探索を直接使うとHNSWで10ミリ秒超、FAISSで4ミリ秒超を要するという原著の測定がある。近似検索の理論的な計算量だけでは、実際の低遅延生成へ適用できるか判断できない。

GPUは重みを1要素ずつ独立に読むわけではなく、通常は128バイト程度の転送単位を扱う。個々のゼロ要素を飛ばす不規則な疎行列では、メモリ転送が期待どおり減らないことがある。DejaVuは注意ヘッド全体やMLPニューロンという構造化された単位で重みを選び、さらにメモリ上で連続した範囲を読み出せるように行列の配置を変える。

## 手法

### 1. 密計算で教師を作り、層ごとの疎性予測器を学習する

モデルのMLPでは、第一線形層の各行と入力活性値との内積から中間ニューロンの寄与が決まる。DejaVuは各ニューロンの出力が閾値を超えるかどうかを、入力ベクトルに対する分類問題として学習する。原著Algorithm 1は密な計算から正例・負例のラベルを収集し、各MLPブロックに小さな2層全結合予測器を訓練する。予測器SP_Mは現在の層入力から重要ニューロンの索引集合S_Mを出力し、その索引に対応する第一・第二線形層の重みだけを用いて疎なMLPを計算する。

訓練データはC4からランダムに選んだ500例であり、基盤モデル全体を再学習するわけではない。しかし**予測器の追加学習は必要**である。原著ではMLP予測の検証精度が浅い層で99%を超える一方、終盤の層では約93%へ低下する。層ごとに重要集合を予測する理由は、同じ入力でも内部表現が変化し、冒頭の埋め込みだけから全層の索引を固定すると50%疎性でも精度低下が生じるためである。

### 2. 注意ヘッドを選ぶときは、過去トークンのKV欠落を処理する

注意機構の予測器SP_Aも各ヘッドを一つの分類対象として扱い、必要なヘッド集合S_Aを出力する。MLPと違い、注意機構は過去トークンの鍵・値（KV）キャッシュを参照する。過去の時点であるヘッドを省略したのに、後続トークンでそのヘッドが必要になった場合、過去トークンのKVが存在しないという問題が起きる。

原著§4.2では、ある時点で選択したヘッドについてはKVを計算して保存し、選択しなかったヘッドについては元のトークン埋め込みを保持する。将来そのヘッドが必要になったとき、保存した埋め込みを読み出して不足した過去トークンのKVをまとめて再計算する。復号がメモリ入出力律速である条件では、必要な重みをロードする費用が主要項なので、追加の計算が比較的小さいという設計である。したがって単純に「省略ヘッドの過去状態を永久に捨てる」方式ではない。

この遅延再計算は、過去の全ヘッドKVを常時保存する方式とは異なるメモリ・計算の交換条件を持つ。後から多くのヘッドが必要になる負荷では、再計算が増える可能性がある。論文はこの仕組みを導入して注意ヘッドの動的切替を可能にするが、任意の長文脈や頻繁なヘッド切替で追加費用がゼロだとは主張していない。

### 3. 非同期先読みで予測器の待ち時間を隠す

通常の逐次処理なら、各層の入力y_lから注意ヘッド集合を予測し、注意計算を終えてからMLP集合を予測し、MLPを計算する。これでは予測器が直列の待ち時間になる。DejaVuは残差接続によって隣接層の入力ベクトルが近いという性質を利用し、層lの入力から**次の層l+1の注意ヘッドとMLPニューロンの集合**を予測する。予測器の実行を現在層の注意・MLP演算と並行させ、次層が必要とする時点までに索引を用意する。

原著のLemma 4.3は、隣接層の活性値の差が十分小さいとき、近似最大内積探索の品質をわずかに緩めることで前層の入力から次層の選択を行える条件を述べる。これはすべての層で差が小さいことを保証する定理ではなく、近い層間表現があるという実測と条件付きの理論を組み合わせた設計である。予測の先読み距離を伸ばしすぎたり、表現が急に変化する入力では誤予測の危険が増える。

### 4. 索引と行列積を融合し、重みの配置を変える

疎集合S_Mを先に別カーネルで切り出し、その結果を別の行列積へ渡すと、元の行列、切り出した行列、結果を余分に読み書きする。原著はTritonで索引付きロードと積和演算を融合し、選択した重みを一度読みながら出力を作る。通常のPyTorchによる疎実装に対して、この融合は最大4倍の改善を示す。

さらに、MLPの第一線形層と第二線形層は、同じ索引集合で選んでも適したメモリ方向が異なる。第二線形層の重みを列優先に保持し、選択ニューロンに対応する列が連続して読めるようにする。注意出力射影の重みも同様に列優先にする。単なる疎化率ではなく、GPUの転送単位、メモリ結合アクセス、カーネル融合まで含めて初めて端点の復号遅延を下げられる。

## 評価

### 実験条件

| 項目 | 原著の設定 |
|---|---|
| 主モデル | OPT-175B。追加でOPT-66B、BLOOM系も品質を確認 |
| 実機 | 8基のNVIDIA A100 80GB、NVLink。主遅延実験はFP16、バッチ1 |
| 入力長 | 128、256、512、1024トークンの生成遅延を比較 |
| 比較実装 | NVIDIA FasterTransformer、Hugging Face Transformers |
| 予測器学習 | C4の500例から教師ラベルを生成 |
| 言語モデリング | WikiText、C4。指標はパープレキシティ（小さいほどよい） |
| 下流課題 | CB、COPA、Lambada、OpenBookQA、PIQA、RTE、WinoGrande。ゼロ例・5例設定 |
| 追加条件 | MLP単独疎化、注意ヘッド単独疎化、バッチ拡大、4ビット重み量子化との併用 |

図7はトークン当たり平均生成遅延の実測であり、初回トークン時間や学習速度の比較ではない。入力長を変えているため、1つの倍率だけをすべての条件へ適用することはできない。また、FasterTransformerとHugging Faceでは基礎実装の最適化水準が異なるので、後者に対する大きな倍率を前者への改善として引用しない。

図6の全体的な傾向は、約75%の疎性までゼロ例・5例の平均正解率が大きく崩れないことである。ただしTable 4を見ると個々の課題ではRTEなど小幅な悪化が存在する。したがって「すべての指標が完全一致する」とは言えない。モデルの種類も重要で、BLOOMではMLPの活性関数が異なるため、MLP側の疎性を30%へ下げ、注意側50%と組み合わせている。

図8・11のバッチ感度では、複数要求で使う重み集合の和集合が必要になるため、バッチが大きいほど疎性が減りやすい。ただし活性集合の増加は線形ではなく、頻出するヘッド・ニューロンが重複して使われる傾向がある。論文はこれを高処理率運用への可能性として論じるが、主たる1.8～2倍の端点改善がバッチ32でもそのまま成立するという実測ではない。

予測器の検証精度も、MLPでは浅い層99%超・終盤約93%、注意ヘッドでは中間層約93%・浅層と深層で約99%と異なる。誤予測が出やすい層を特定するうえで、この内部指標は端点遅延の倍率とは別の意味を持つ。4ビット重み量子化（W4A16）との併用では、疎化と量子化の誤差が必ずしも加算的に悪化しない例をTable 7で示している。

## 既存研究との差

静的枝刈りは全入力で同じパラメータを削るのに対し、DejaVuは入力と層に応じて必要な重み集合を切り替える。混合専門家モデルは最初から専門家選択を持つように学習されるが、DejaVuは既存の密なTransformerへ小型予測器と疎実行カーネルを追加する。単純な近似近傍探索は推論の本体計算より遅いという実測があり、DejaVuは予測器の学習、層間先読み、融合カーネルを組み合わせてこの問題を解決する。

## 限界

追加の予測器には校正例の収集と学習が必要で、予測精度は層位置やモデルの活性関数に依存する。主な端点性能は8基A100・NVLink・FP16・バッチ1で得られた結果であり、別のGPU、長い系列、複数同時要求で同じ倍率が出る保証はない。動的な注意ヘッド選択は過去トークンのKVを必要時に再計算する設計なので、ヘッドの再利用パターンによっては追加計算・埋め込み保存費用が生じる。カーネル融合や重み配置の変更を欠いた一般的な疎演算では、理論的な重み削減を端点速度へ変換できない。

原著は言語モデリング、選択式課題、少数例課題で品質を検証するが、任意の下流業務や全分布での品質同一性を保証していない。約75%という総疎性もOPT-175Bの主実験条件であり、BLOOMなど異なるモデルへそのまま転用できない。推論用コードは著者の公開リポジトリにあるが、現在の最新GPUや配信基盤への統合状況は原著の評価対象外である。
