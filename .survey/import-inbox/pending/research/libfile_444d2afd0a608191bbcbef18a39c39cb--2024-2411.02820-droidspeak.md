# DroidSpeak: KV Cache Sharing for Cross-LLM Communication and Multi-LLM Serving

## 書誌情報
- canonical identity: `arXiv:2411.02820`
- 著者: Yuhan Liu, Yuyang Huang, Jiayi Yao, Zhuohan Gu, Kuntai Du, Hanchen Li, Yihua Cheng, Junchen Jiang, Shan Lu, Madan Musuvathi, Esha Choukse
- 一次資料: https://arxiv.org/abs/2411.02820

## 概要
複数LLMを組み合わせるworkflowでは、同じ長いcontextを複数モデルが繰返しprefillすることがある。特に同一基盤モデルから異なる用途へ微調整したvariantを連携させる場合、モデル重みの大部分と入力contextは近いのに、各variantが独立してKV cacheを再生成する。この重複計算がmulti-LLM servingのTTFTとthroughputを悪化させる。

DroidSpeakは、あるモデルで計算済みのKV cacheを別のfine-tuned modelへ共有する。ただし重みが異なるモデル間で全KVをそのまま流用すると誤差が蓄積するため、層ごとの再利用可能性を調べ、重要な層だけを受信側モデルで再計算する。入力は送信モデルのKV cacheと受信モデル、処理はcache転送と選択的層再計算、出力は受信モデル用の近似KV cacheである。

完全再計算を避けることでprefillを最大2.6倍高速化し、multi-model serving throughputを最大3倍へ改善しながら、評価したmodel pair・datasetで精度低下を小さく抑える。これは任意の無関係なLLM間で内部表現を翻訳する方式ではなく、同一foundation modelから派生したfine-tuned variant間の構造的類似性を利用する。

## 問題設定
LLM workflowではrouter、専門モデル、judgeなど複数モデルが同じ会話履歴を読む。通常は各モデルがprompt全体をprefillして全層のK/Vを計算する。contextが長いほど、この重複prefillは大きな計算費用になる。

単純なcache共有が難しい理由は、fine-tuningで各層の表現が変わるためである。送信側のK/Vを受信側へそのまま渡すと、後続attentionが受信モデルの重みで本来生成される状態とずれ、出力品質を壊す。一方、全層を再計算すれば品質は戻るが高速化は消える。

## 手法
### cross-LLM KV reuse
DroidSpeakは送信側モデルが同じcontextに対して生成したKV cacheを受信側へ渡す。token列を自然言語として再生成するのではなく、prefill中間状態を直接再利用するため、共有contextが長いほど省ける行列演算が増える。

前提はモデル間に強い構造対応があることで、主対象は同一foundation modelからfine-tuningされたvariantである。hidden sizeやlayer構造が完全に異なる任意モデルを対象とするcache翻訳とは異なる。

### critical layer identification
すべての層がfine-tuning差分に同じ感度を持つわけではない。DroidSpeakは、共有KVを使ったときに出力品質へ強く影響するcritical layerを特定し、その層だけ受信モデルで再計算する。残りは送信側cacheを再利用する。

この選択が計算量と精度の主要トレードオフになる。再計算層を増やせば完全prefillへ近づき精度は上がるが速度利得は減る。減らしすぎるとモデル間差分を補正できず品質が落ちる。

### selective recomputation
受信側はcritical layerで自分の重みを使って状態を更新し、その結果を後続層へ渡す。これにより送信cacheの誤差を途中で補正し、全層再計算より少ない計算で受信モデル固有の挙動を回復する。

この処理はcacheを圧縮して容量を減らすのではなく、cache「生成計算」を共有する方式である。KVをネットワーク越しに移す場合は転送費用が残るので、prefill節約量が転送量を上回ることが必要になる。

## 評価条件
| 項目 | 条件 |
|---|---|
| モデル関係 | 同一foundation model由来のfine-tuned LLM pair |
| workload | 同じcontextを複数LLMが読むmulti-LLM workflow |
| 比較 | 各モデルでのfull recomputation |
| 指標 | accuracy、prefill latency、serving throughput |
| 操作 | KV共有 + critical layer selective recomputation |

## 主要結果
| 指標 | 結果 | 解釈 |
|---|---:|---|
| Prefill | 最大2.6×高速 | 全層再計算を避ける |
| Throughput | 最大3× | 重複prefill削減を同時要求処理へ転換 |
| Accuracy | negligible loss | critical layer再計算でmodel-specific差分を補正 |

最大値はmodel pairやcontext長に依存する。モデル差が小さく共有contextが長いほど再利用余地が大きい一方、fine-tuning差が大きければ再計算すべき層が増え、速度利得が縮む。

## 既存研究との差
prefix cacheは通常、同じモデル・同じprefixで過去requestのKVを再利用する。DroidSpeakは「別のfine-tuned modelが作ったKV」を再利用するため、model boundaryを越える。その代わり完全同一cacheとはみなさず、選択的再計算を入れる。

Cache-to-Cacheのような異種モデル表現変換とは目的が近いが、DroidSpeakは同一基盤由来の構造対応を強く利用し、translatorで全表現空間を学習変換するより、再利用可能な層と再計算層を分ける。

## 限界
同一foundation model由来という前提が強い。アーキテクチャ、tokenizer、hidden dimensionが大きく異なるモデル間へそのまま適用できるとは限らない。

cache転送が遅いネットワークを跨ぐ場合、prefill節約が通信で相殺される可能性がある。critical layerの選択もmodel pair依存で、fine-tuning更新後に再評価が必要になる可能性がある。
