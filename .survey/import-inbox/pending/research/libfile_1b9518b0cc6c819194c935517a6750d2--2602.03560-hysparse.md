## 概要

疎attentionは長文脈の計算量を減らせるが、「どのtokenを残すか」を推定するproxyが必要になり、そのproxy自体の費用と選択誤差が生じる。また計算対象tokenを減らしても各層が完全なKV cacheを保持すれば、生成時memoryは十分に減らない。HySparseはfull attentionを完全に捨てず、少数のfull-attention層を後続sparse層のoracle兼KV供給元として使う。

一つのhybrid blockはfull-attention層と複数のsparse-attention層からなる。full層がFlashAttention計算中にblock単位重要度を取り、Top-K block indexを後続層へ渡す。後続層のglobal sparse branchはそのindexだけへattentionし、KVもfull層のものを再利用する。local sliding-window branchだけは独自KVを保持する。80B MoEの49層構成ではfull attentionを5層だけにし、KV cacheを約10分の1へ削減する。

## 問題設定

従来の動的疎attentionでは、queryから重要KVを予測する補助network、近似score、検索indexなどが必要になる。選択が外れると長距離依存を失い、選択器の計算がattention削減分を食うこともある。

もう一つの問題はcross-layer redundancyである。近接層が似た長距離情報を参照するにもかかわらず、各層が独自のglobal KVを保存するとcache容量は層数に比例する。HySparseはfull層で得た「選択結果」と「KV表現」の双方を複数後続層へ再利用する。

## 手法

### Full-attention oracle token selection

full-attention層は通常のattentionを計算しながらblock単位の最大attention scoreを生成する。完全なscore matrixを別途materializeせず、FlashAttention経路を拡張してimportance scoreを得る。Top-Kで重要block indexを選び、同じhybrid block内の後続sparse層へ渡す。

この選択はproxyによる将来予測ではなく、直前full層が実際に計算したattentionを根拠にする。そのため選択器の別modelを持たず、global token選択の誤差源を減らす。

### Cross-layer KV cache sharing

sparse層のglobal branchは自身のglobal KVを新規保存せず、直前full層のKV cacheから選択blockを参照する。複数sparse層が一つのfull-layer cacheを共有するため、full層の割合を下げるほどglobal KV storageが減る。

ただしすべての表現を共有するとlocal modelingが弱くなる。そこで各sparse層は短いsliding-window attention（SWA）branch用の小さな独自KV cacheを保持する。

### Global/local gated fusion

sparse層はoracle-selected blockへ向かうglobal sparse attentionと、直近tokenを見るSWAを並列に計算し、sigmoid gateで出力を融合する。global branchは長距離情報、local branchは層固有の短距離表現を担当する。

構成要素除去では、SWAまでfull層KVを共有する方式より、global sparse branchだけを共有してSWAを独立させる方が高い性能を示す。したがってcache sharingを最大化するより、表現役割に応じて共有範囲を限定する設計である。

## 評価条件

| 項目 | 条件 |
|---|---|
| model | 7B dense、80B MoE |
| 80B構成 | 49層中5層のみfull attentionの設定を評価 |
| sparse選択 | block単位Top-K、代表設定では1024 token相当 |
| local path | 128-token級SWA branch |
| task | MMLU、MMLU-Pro、GSM8K、coding、RULER等 |
| 長文脈 | 16K/32Kを含む |
| 比較 | full attention、hybrid SWA |

## 主要結果

| 条件 | 結果 | 解釈 |
|---|---:|---|
| 80B MoE / 49層中full 5層 | KV cache約10分の1 | cross-layer sharingがmemoryを大幅削減 |
| 80B / RULER 32K | HySparse 87.4、full attention 82.1 | 長文脈で疎構成が品質を維持・上回る条件がある |
| 80B / RULER 16K | HySparse 90.6、full attention 93.6 | すべての条件でfull attentionを上回るわけではない |
| 7B / GSM8K cache-sharing ablation | globalのみ共有36.7、global+SWA共有30.2 | local KVを独立保持する設計を支持 |

論文は主にmodel qualityとKV容量を評価しており、end-to-end serving throughputやtoken latencyの代表値は報告していない。したがって約10倍のKV削減を約10倍の速度向上とは解釈できない。

## 既存研究との差

proxy-based sparse attentionは各層で重要tokenを推定し、cross-layer KV sharingを行わない方式が多い。HySparseは定期的なfull-attention層を「正確な選択器」と「共有KVのcheckpoint」として兼用し、その間の層だけをsparse化する。YOCO型のcross-layer cache共有と異なり、global sparse branchとlocal SWA branchの役割を分離している。

## 限界

full-attention層は残るため、完全sparse architectureではない。選択blockは直前full層のattention patternに依存し、層間で重要性が大きく変わる場合は不利になり得る。現論文は品質とKV容量の利点を強く示す一方、実servingのthroughput/latencyは未評価である。
