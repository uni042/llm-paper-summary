## 概要

マルチモーダル大規模言語モデル（MLLM）では、vision encoderが作る高密度な特徴列をLLMが扱えるtoken列へ変換するvisual projectorが、視覚品質と推論計算量の両方を左右する。単純な線形projectorは局所構造を十分に扱わず、Q-Formerのようなquery-based方式は出力token数を制御できても空間的な局所性を失う場合がある。

Honeybeeはprojectorに必要な性質を「visual token数を柔軟に決められること」と「vision featureのlocal contextを保持すること」の二つに整理する。そのうえで畳み込みを使うC-Abstractorとdeformable attentionを使うD-Abstractorを設計し、LLMへ渡すtoken budgetを固定的な入力patch数から切り離す。

visual token数を減らせばLLM側のattention・MLP計算とcontext消費が減るため、projectorはMLLM推論効率の入口になる。一方、圧縮しすぎて物体間の位置や細部を失えばVQA等の品質が落ちる。Honeybeeは局所情報を保持するdownsamplingを使い、この交換条件を改善する。

## 問題設定

vision encoderは画像を多数のpatch tokenへ変換する。これをそのままLLMへ渡すと、画像ごとに多くのcontext tokenを消費し、LLM側の計算量も増える。複数画像や高解像度入力ではこの問題がさらに大きくなる。

既存projectorには、token数を自由に変えにくい方式と、少数queryへ圧縮できる代わりに局所空間情報が薄くなる方式がある。Honeybeeはtoken budgetとlocalityを同時に設計変数として扱う。

## 手法

C-Abstractorは畳み込みを中心に構成し、近傍のvisual featureを局所的に統合しながら空間解像度を下げる。畳み込みの局所受容野によって隣接patchの関係を保ち、最終的なfeature mapの大きさを調整することでLLMへ渡すtoken数を制御する。

D-Abstractorはdeformable attentionを用いる。固定格子の近傍だけでなく、学習されたsampling locationから重要な局所featureを集約できるため、少数tokenへ圧縮しながら対象物や領域の構造を保持することを狙う。C-Abstractorより柔軟なsamplingを使う代わりに機構は複雑になる。

projectorの出力はLLMのtoken embedding次元へ写像され、テキストtokenとともにLLMへ入力される。したがってprojectorでvisual token数をNからMへ減らせば、後段LLMが画像由来tokenに対して行うattention/MLP処理もMに基づく量へ減る。効率改善はvision encoderそのものより、LLMへ渡すsequence budgetを削る点にある。

論文はprojectorだけでなく、複数のvisual instruction datasetを組み合わせる学習recipeも検討する。dataset balancing、instructionの多様性、multi-turn例などを調整し、projectorの構造改善が実際のMLLM能力へつながるようにする。

## 評価

| 観点 | 内容 |
|---|---|
| architecture | pre-trained vision encoder + locality-enhanced projector + LLM |
| projector | C-Abstractor、D-Abstractor |
| 効率変数 | LLMへ渡すvisual token数 |
| benchmark | MME、MMBench、SEED-Bench、LLaVA-Bench等 |
| 比較 | 既存MLLM/projector設計と性能・効率を比較 |

Honeybeeは複数benchmarkで既存方式を上回り、特に局所・空間情報が重要なタスクでprojector設計の効果を示す。論文の主張は、visual token数を減らすこと自体ではなく、同じtoken budgetでlocalityを保つことで効率と理解性能のPareto frontierを改善できる点にある。

projectorの構成要素とinstruction data recipeについてablationを行い、単純な線形接続だけでは得にくい局所性とtoken flexibilityが性能に寄与することを確認する。これは、MLLMの効率化をLLM本体だけでなくmodality adapterで行えることを示す。

## 既存研究との差

LLaVA型の線形projectorは実装が単純だが、vision encoderのpatch列を大きく圧縮する機構を持たない。BLIP-2系のQ-Formerやresamplerは少数queryへ集約できるが、query aggregationの過程で局所的な空間関係を失う可能性がある。

Honeybeeは「何tokenへ圧縮するか」を柔軟にしつつ、畳み込みまたはdeformable attentionでlocalityを明示的に保つ。後年のvisual token pruningのように推論時にtoken重要度を選別する方式とは異なり、projector自体が固定budgetの高密度表現を生成する。

## 限界

主評価はMLLMの理解benchmarkであり、online serving環境のTTFT、TPOT、throughput、GPU memoryを直接測るsystem paperではない。visual token削減からLLM計算削減は期待できるが、実際のend-to-end latencyはvision encoder、projector kernel、LLM backendに依存する。

また、projectorで圧縮した後に失われた視覚情報はLLM側で復元できない。細粒度OCRや極端な高解像度入力では、token budgetを小さくしすぎると局所性を保っても情報量そのものが不足する可能性がある。効率と品質の最適点は入力・task依存である。
