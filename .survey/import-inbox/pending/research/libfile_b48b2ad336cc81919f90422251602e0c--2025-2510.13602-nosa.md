# NOSA: Native and Offloadable Sparse Attention


> 学習型疎注意へ明示的なKV選択局所性を組み込み、CPU上のKVを少量転送するNOSI runtimeと協調して品質とoffload throughputを両立する。

## 概要

長文脈デコードではKVキャッシュがGPUメモリを占有し、batch sizeを制限する。CPUへKVを退避し、必要な一部だけGPUへ戻す方式は容量を空けられるが、学習時はdense attentionだったモデルへ推論時だけ疎なaccess patternを与えると長生成品質が落ちやすい。

逆に学習型疎注意はモデル自身が疎な選択を学ぶため品質を保ちやすいが、各decode stepで選ぶKVが大きく変わるとCPU-GPU間で大量の新規KVを転送し、PCIeが律速になる。NOSAはこの二律背反を、疎注意の学習時から「隣接stepで選択集合が重なる」よう制約することで解く。

NOSAはquery-aware選択とquery-agnosticなeviction headを組み合わせ、選択KVの一部をstep間で安定化する。推論側のNOSIはこの局所性を利用してGPU resident KVを再利用し、必要な差分だけを転送する。1B/3B/8Bモデルで、Full Attention、InfLLMv2、ShadowKVに対してdecode throughputを最大5.04倍、1.92倍、1.83倍へ高めつつ、一般・長入力・長生成taskで高い品質を維持する。

## 問題設定

疎注意の演算量が少なくても、選択されたKVが毎step入れ替わればCPUからGPUへ同程度のデータを送り続ける。つまりattention FLOPs削減とoffload通信削減は同じではない。

学習なしのKV offloadでは既存モデルのattention score等から必要KVを推測するが、モデルはその欠落patternを学習していない。特に長い生成で誤差が累積し、品質劣化が現れる。

NOSAは「学習型の品質」と「offloadに適したaccess locality」を同じattention定義に組み込み、runtime側の転送量をモデル側から制御可能にする。

## 手法

### 二成分KV選択

全選択予算kを、query-aware集合 Γq とquery-agnostic集合 Γeへ分ける。Γqは現在queryとkeyの類似度から遠距離でも重要な内容を回収し、通常の動的疎注意の表現力を残す。

Γeはeviction headがqueryに依存しない重要度を出し、複数stepで安定して残すKVを選ぶ。これにより全選択を固定化せず、必要な動的検索とresident reuseを両立する。

### 明示的局所性制約

Γeの予算keを使うことで、隣接decode stepの選択重複率γ(t)に少なくともke/k相当の下限を与える。前stepでGPUへ持ってきたKVの一定割合が次stepでも必要になるため、CPU-GPU差分転送量が上限付きになる。

block-wise選択を使い、sub-block内mean poolingとblock-level max poolingでPCIeに適した連続転送単位を作る。token単位の細切れcopyを減らすことがsystem実装上の目的である。

### Exp-Delayed DMA

query-agnostic scoreをattention biasとして使う際、指数演算を早い段階で適用すると数値範囲と余分な処理が問題になる。Exp-Delayed DMAは指数化を最終attention計算まで遅らせ、scoreをbiasとしてsoftmaxへ統合する。

これによりeviction headの重要度をattention計算へ保持しつつ、offload用選択と実際のattention weightを整合させる。

### NOSI runtime

NOSIはGPU resident集合と次stepのNOSA選択集合の差分を追跡し、新規blockだけCPUから転送する。LayerNorm、RoPE、FFN、eviction head等の融合、CUDA Graph等で小kernel起動費も抑える。

モデル側で局所性が保証されるため、runtimeは「次stepでも多くが残る」という性質を利用できる。単なるcache heuristicではなくattention学習とoffload systemの協調設計である。

## 評価条件

| 項目 | 内容 |
|---|---|
| モデル規模 | 1B、3B、8B |
| workload | 一般task、長入力、長生成 |
| 比較 | Full Attention、InfLLMv2、ShadowKV等 |
| system | NOSI KV offloading runtime |
| 指標 | task品質、decode throughput、CPU-GPU KV transfer |
| 学習 | 短文脈dense pretraining後、長文脈継続学習/SFTでNOSAを有効化 |

## 主要結果

| 比較対象 | 最大decode throughput改善 | 読み取れること |
|---|---:|---|
| Full Attention | 5.04倍 | GPU KV容量とattention読出しを大幅削減 |
| InfLLMv2 | 1.92倍 | 学習型疎注意でもoffload localityが速度差になる |
| ShadowKV | 1.83倍 | 学習なしoffloadより品質と転送効率を両立 |
| 長生成品質 | near-losslessを維持 | training-inference mismatchを抑える設計の効果 |

初期版の小規模評価ではInfLLM-V2比最大2.3倍と報告され、後続版では1B/3B/8BとNOSIを含む評価へ拡張されている。版によるheadline値を同一条件として混同しない。

## 既存研究との差

ShadowKV等は既存モデルへ推論時offloadを適用するため導入しやすいが、疎なKV accessをモデルが学習していない。InfLLMv2等の学習型疎注意は品質面で有利だが、選択集合の時間局所性をsystem要件として強制しない。

NOSAは選択重複率の下限をattention機構へ入れ、NOSIがその性質を通信削減へ変換する。アルゴリズムとruntimeを別々に最適化しない点が差である。

## 限界

NOSAはモデル側の学習を必要とし、既存checkpointへ完全に学習なしで差し込む方式ではない。局所性予算を大きくすると転送量は減る一方、query依存で遠距離情報を選ぶ自由度が減る交換条件がある。

効果はCPU-GPU階層とPCIe転送を前提とする。全KVがGPUへ収まる短文脈・小batchや、別の統合メモリアーキテクチャではoffloadによる利得が小さくなる。
