# Guess-Verify-Refine: Data-Aware Top-K for Sparse-Attention Decoding on Blackwell via Temporal Correlation


> 前decode stepのTop-K安定性を利用して厳密選択の探索範囲を予測・検証・補正し、Blackwell上の疎注意Top-Kをbit-exactのまま高速化する。

## 概要

長文脈の疎注意では、現在queryに重要な少数KVをindexer scoreからTop-K選択し、そのKVだけattentionへ渡す。attention本体とindexerを高速化すると、全scoreから厳密なTop-Kを毎decode step取り出すselection自体が無視できない遅延になる。

Guess-Verify-Refine（GVR）は、連続decode stepではTop-K集合が大きく変わらない時間相関を利用する。前stepのTop-Kから現在の閾値を予測し、事前集計したscore統計を使うsecant-style countingで候補範囲を1〜2回のglobal passに絞る。予測をそのまま近似結果として使わず、候補を検証してshared memory内で厳密Top-Kを完成させるため、production radix-selectとbit-exactに一致する。

DeepSeek-V3.2のDeepSeek Sparse Attention（DSA）をTensorRT-LLMへ統合し、NVIDIA Blackwellで実workloadを評価する。単一operatorはproduction radix-select比平均1.88倍、layer/step最大2.42倍高速化し、TEP8最小遅延配備の100K contextでend-to-endの1トークン間時間（time per output token; TPOT）を最大7.52%改善する。

## 問題設定

一般的なradix-selectはscore bitを段階的に調べてTop-K境界を絞るため、入力分布をほぼ利用しない。毎step独立に同じ探索を繰り返すので、Top-Kが前stepとほぼ同じでもその情報を捨てる。

DSAではRoPEとscore構造により隣接stepの順位が安定する。長文脈ほどscore数が増える一方、Kは比較的小さいため、この安定性を利用できればglobal memory全体を何度もscanする必要を減らせる。

ただし近似Top-Kにすると選択誤りがattention出力を変える。GVRは時間相関を「答え」ではなく探索初期値として使い、最終結果の厳密性を維持する。

## 手法

### Guess: 前stepから閾値予測

前decode stepのTop-K scoreと選択位置を保持し、現在stepのscore分布でK番目付近に来る閾値の初期推定に使う。DSAの時間相関が強いほど予測は真の境界に近い。

score全体を直接sortせず、pre-indexed statisticsから「この閾値以上の要素が何個あるか」を高速に数える。これが次のverify/refineへ渡る。

### Verify/Refine: secant-style counting

予測閾値で候補数を数え、Kより多い／少ない方向を確認する。二つのcount観測からsecant法に似た更新で閾値を補正し、通常1〜2回のglobal passでK境界を挟む。

二分探索のように固定回数でrangeを半分ずつ削るのではなく、実score分布と前step情報を使って大きく跳ぶ。予測が外れてもcountで検証するため、正しさを失わない。

### ballot-free collector

閾値近傍の候補を集める段階ではwarp ballot中心の複雑な競合処理を避け、直接collectorへ書き込む構成を使う。候補数を先に狭めているため、shared memoryへ収まる集合にできる。

最後にshared memory内で厳密selectionを行い、K個を確定する。この段階でbit-exactなTop-Kを保証するため、Guessの誤差は出力誤差へ伝播しない。

### TensorRT-LLM統合

GVRをDSA indexerとattention kernelの間へ入れ、production radix-selectを置換する。単体microbenchmarkだけでなく、DeepSeek-V3.2の実decode stackでTPOTまで測る。

投機的復号時にも利用できるが、複数tokenを一度に扱うことで隣接step相関の利用形が変わり、通常decodeより利得は小さくなる。それでも正の改善を維持する。

## 評価条件

| 項目 | 内容 |
|---|---|
| GPU | NVIDIA Blackwell |
| モデル/workload | DeepSeek-V3.2、実DSA workload |
| runtime | TensorRT-LLM |
| 比較 | production radix-select kernel |
| 配備 | controlled TEP8 minimum-latency |
| 文脈 | 100Kを代表条件、さらに長文脈も評価 |
| 正確性 | Top-K出力bit-exact |
| 指標 | operator latency、per-layer speedup、end-to-end TPOT |

## 主要結果

| 条件 | 結果 | 意味 |
|---|---:|---|
| Top-K operator平均 | 1.88倍高速化 | 時間相関でglobal scanを削減 |
| layer/step最良 | 最大2.42倍 | 相関が強い条件で閾値予測が特に有効 |
| TEP8、100K context | TPOT 最大7.52%改善 | operator改善が実サービング遅延へ波及 |
| より長いcontext | 改善幅増大 | radix selectionの全score走査費が増えるほど有利 |
| speculative decoding | 改善は縮むが正 | 相関利用機会が変わっても効果を保持 |
| 正確性 | bit-exact Top-K | 近似attentionによる品質交換なし |

## 既存研究との差

radix-selectはデータ分布に依存しない汎用選択で、毎step同じ探索を行う。GVRはLLM decode特有の時間相関を使い、前step結果を次stepのselection acceleratorとして再利用する。

近似Top-Kや予測indexerとも異なり、予測を検証・補正して最終的な厳密K集合を返す。そのためモデル再学習やattention品質の変更を必要としない。

## 限界

実装・検証は現行TensorRT-LLMのDSA stackとBlackwellを対象にする。他のGPU世代、異なるsparse attention score分布、時間相関が弱いselectorでは同じpass数やspeedupを保証しない。

Top-Kがdecode step間で大きく変化する入力ではGuessの精度が下がり、追加refineが必要になる。end-to-end改善はTop-Kが全TPOTに占める割合に上限を持つため、operator 1.88倍がそのままシステム1.88倍にはならない。
