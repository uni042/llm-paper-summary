# MSA: Memory Sparse Attention for Efficient End-to-End Memory Model Scaling to 100M Tokens

> 文書単位の疎注意と圧縮KVキャッシュ、文書別位置符号化、GPUとCPUメモリへの階層配置を組み合わせ、学習も推論もメモリ量に対して線形の費用で1億トークン規模の長期メモリを扱い、規模を4桁広げても精度低下を9パーセント未満に抑えた端から端まで学習可能なメモリモデル。

## 概要

人の生涯規模の情報は数億トークンに相当すると見積もられるが、言語モデルの実効文脈長は全注意の制約で概ね100万トークンが限界である。全注意は文脈長の二乗で費用が育ち、長くなるほど精度の低下と遅延の増大も進む。これまでの回避策には弱点がある。線形注意や固定サイズの状態を持つ方式は精度の低下が大きく、検索拡張生成（RAG）やエージェント型の外部メモリは、取得と生成が別部品で端から端までの最適化ができず、メモリ内容を動的に書き換えることも苦手である。大きなコーパスの要約、安定した人格を持つデジタルツイン、長い履歴を持つエージェントの推論といった用途は、この壁に直接当たる。

本論文のMSA（Memory Sparse Attention）は、取得を注意機構の内部へ取り込む。メモリは文書の集合として保持され、各文書は独立に符号化されて、キーとバリューがチャンク単位の平均プーリングで圧縮される。質問が来ると、専用のルータ射影が作る照合キーで関連文書を上位k件だけ選び、その圧縮KVと質問の局所キャッシュを連結した疎な文脈の上で生成する。位置符号化は文書ごとに独立に振るため、学習時に見た文書数よりはるかに大きなメモリへ外挿できる。推論では、照合に要るルーティングキーだけをGPU側へ置き、内容のKVはCPUメモリ側へ置いて選ばれた分だけを非同期に運ぶ階層配置により、A800を2基で1億トークンの推論を実現する。代表結果として、MS MARCOでメモリを16Kから1億トークンへ広げてもスコアは4.023から3.669へ8.8パーセントの低下にとどまり、同一バックボーンのRAGとの比較では9つの質問応答ベンチマーク平均で16.0パーセント高いスコアを得た。針探し課題（NIAH）では100万トークンで検索精度94.84パーセントを保ち、無改変のバックボーンが24.69パーセントまで崩れるのと対照的である。

## 問題設定

長期メモリの難しさは、容量・精度・費用の3つが同時に絡むことにある。全注意では容量を増やすほど1クエリの費用が二乗で育ち、無関係な文脈の蓄積が推論を薄める文脈劣化も進む。外部検索で容量を逃がすと、今度は検索器と生成器の目的がずれ、検索の誤りが生成側で回復できず、メモリの書き換えもパイプラインの再構築になる。固定サイズ状態への圧縮は容量の問題を解くが、細かい事実の保持で精度を落とす。本論文が狙うのは、容量と推論を切り離すことである。つまり、メモリ全体は大きくてよいが、1回の生成が触る量は選ばれた一部だけに抑え、しかもその選択自体を生成と同じ学習で最適化する。あわせて、学習は計算の都合で短いメモリでしか行えないため、短く学んで長く使う外挿の仕組みが別途要る。

## 手法のあらまし

入力は文書コーパスと質問である。オフラインに、全ての文書をモデルへ通して通常のキー・バリューと、照合専用のルーティングキーを作り、チャンク単位の平均プーリング（プーリング幅は64）で圧縮してメモリバンクへ保存する。オンラインでは、質問の隠れ状態からルーティングクエリを作り、圧縮済みルーティングキーとの余弦類似をヘッド平均とトークン最大で集計して文書スコアとし、上位k件（例として16件）の文書を選ぶ。選ばれた文書の圧縮KVを質問の局所キャッシュの前に連結し、その疎な文脈の上で通常の自己回帰生成を行う。多段の根拠が要る質問では、文書IDの生成と文脈の拡張を交互に繰り返すメモリインターリーブがこの流れを反復する。位置符号化は文書ごとに0から振り直し、質問と生成側には取得した文書数ぶんずらした位置を与える。出力は通常の回答テキストである。

## 手法

### 1. ルータ射影による文書単位の疎注意 — 取得を注意の内部で学習する

この機構の中心は、通常のキー射影とは別に用意されたルータ用のキー射影とクエリ射影である。各文書の隠れ状態から通常のキー・バリューと並んでルーティングキーを作り、3者ともチャンク単位の平均プーリングで圧縮する。質問側も同様にルーティングクエリを作り、圧縮ルーティングキーとの余弦類似を、注意ヘッド方向には平均、質問トークン方向には最大で集計してチャンクのスコアとし、文書のスコアはそのチャンクの最大とする。上位k件の文書が選ばれると、それらの圧縮KVだけが生成の文脈へ入る。観測するのは質問と全メモリの圧縮キー、保持する状態は圧縮済みのメモリバンク、選択するのは注意へ参加する文書である。減るボトルネックは、全メモリへの注意の二乗費用と、無関係な文脈による劣化である。MSAのルーティングはモデルの後半の層にだけ適用される。前半の層では隠れ状態に高水準の意味がまだ乗っておらず照合が効かないためで、前半は文書の独立処理だけを行い文脈へは混ぜない。追加費用はルータ射影と圧縮キーの保持であり、誤選択時の挙動は、その文書の情報がその層の文脈から欠けることである。学習時に層ごとのルーティングへ補助損失を与えることで、選択の誤りを生成損失だけに頼らず直接正している。

### 2. 文書別と全体の位置符号化 — 短く学んで長く使う

規模の外挿を妨げるのは位置である。通常の位置符号化で全メモリを連結すると、文書数が増えるほど位置番号が学習時の範囲を大きく超え、精度が崩れる。本論文は各文書へ独立に0から始まる位置を与え、位置の意味をメモリ全体の大きさから切り離す。これにより、学習時に扱った文書数と推論時の文書数が違っても、各文書の内部の位置関係は学習時と変わらない。補完として、質問と生成側の能動文脈には、取得した文書の数だけずらした位置を与え、取得した背景の続きとして読めるようにする。減るボトルネックは学習と推論の文脈長の不一致であり、追加費用はほぼない。失敗条件は、文書をまたぐ順序そのものに意味がある課題であり、論文も文書間の強い依存を限界として挙げている。

### 3. 3段階推論とメモリ並列 — 1億トークンを2基のGPUへ収める

推論は3段階に分かれる。第1段階は全コーパスの符号化と圧縮で、メモリバンクの版ごとに1回だけ行う。第2段階は質問ごとのルーティングと文脈の組み立て、第3段階は組み立てた疎な文脈上での生成である。容量の見積もりでは、1億トークン分の圧縮KVとルーティングキーはBF16で約169GBとなり、A800を2基の合計160GBを超える。そこで配置を分ける。照合に要るルーティングキー（約56GB）はGPUメモリへ分散して置き、低遅延の照合を保つ。内容のキー・バリューはCPUメモリへ置き、上位k件が決まった後に必要な分だけを非同期にGPUへ運ぶ。照合の計算自体もメモリ並列で、各GPUが自分の担当分のキーと照合して結果を全体で集約し、スコア行列の計算はタイル化してピークメモリを抑える。モデル本体は4B級と比較的小さいため各GPUへ複製し、デコード時の通信を避ける。減るボトルネックはGPUメモリ容量と照合の計算量であり、追加費用はCPUメモリからの転送と、バンク構築の1回分の符号化である。メモリバンクが頻繁に書き換わる用途では、この事前計算の償却が効かなくなる点が境界になる。

### 4. メモリインターリーブ — 多段の根拠を反復で集める

1回の取得で足りない多段質問のために、生成と取得を交互に繰り返す機構が用意されている。モデルはまず質問から根拠文書のID列を生成し、その原文を取得して質問側へ足し、足した文脈で次のID生成を行う。十分な根拠が集まったとモデルが判断した時点で、ID生成から最終回答の生成へ切り替える。取得する文書数は固定ではなくモデルが適応的に決める。除去実験ではこの機構を外すと平均で5.3パーセント低下し、多段質問のHotpotQAでは19.2パーセント落ちる。つまり単発の照合では届かない根拠の連鎖を、生成途中の状態を使ってたどることが、多段推論の精度を直接支えている。追加費用は反復回数ぶんの生成と取得であり、反復が長引く質問では遅延が伸びる。

| 構成要素 | 入力・観測 | 具体的な動作 | 改善対象 | 主なトレードオフ |
|---|---|---|---|---|
| ルータ射影＋疎注意 | 質問と圧縮ルーティングキー | 文書を上位k件へ絞り圧縮KVだけで生成 | 全注意の二乗費用と文脈劣化 | 前半層では照合が効かず後半層のみ適用 |
| 文書別位置符号化 | 各文書の内部位置 | 文書ごとに位置を振り直す | 学習と推論の規模の不一致 | 文書間の順序情報は弱くなる |
| 階層配置＋メモリ並列 | 169GB級の圧縮メモリ | 照合キーはGPU、内容KVはCPUメモリへ | GPUメモリ容量 | バンク構築の事前計算と転送が要る |
| メモリインターリーブ | 生成途中の根拠ID | 取得と生成を交互に反復 | 多段質問の根拠の連鎖 | 反復ぶんの遅延が増える |

## 評価

### まず見るところ

- **結論:** 容量を4桁広げても精度低下は1桁パーセントに収まり、同一バックボーンのRAGを全般に上回った。容量と推論の分離が実測で機能している。
- **速度・効率:** 理論複雑性は学習・推論ともメモリ量に対して線形であり、生成部分の費用はメモリ量に依存しない。1クエリの支配項はルーティングの照合である。
- **品質:** 近似手法であり低下はゼロではない。巨大な生成器を使う最良のRAG構成には平均で届くものの、個別データセットでは大規模モデル側が勝つ例もある。
- **評価の強さ／注意点:** 質問応答9件と針探しの両方で、規模を振った劣化の測り方まで含む点は強い。一方、実時間のスループットや遅延の実測値は中心的な報告ではなく、複雑性の分析が中心である。

| MS MARCO、メモリ16K→1億トークン | LLM判定スコア | GPT-4.1等は規模とともに低下 | 4.023→3.669 | 低下8.8パーセント | 容量と推論の分離で文脈劣化を抑える |
| 針探し、100万トークン | 検索精度 | 無改変バックボーン24.69パーセント | 94.84パーセント | 崩壊の有無の差 | 位置の外挿と疎な照合が長文脈で保つ |
| 除去実験 | 平均スコア | 原文の併用を除去で2.325、継続事前学習を除去で2.537 | 完全構成3.694 | 除去で37.1／31.3パーセント低下 | 文書IDの生成だけでは足りず原文の併用が要る |
| 除去実験 | HotpotQA | メモリインターリーブ除去で19.2パーセント低下 | 完全構成 | 多段での寄与 | 根拠の連鎖は反復取得で支えられている |

低下が小さい理由は、生成が触る文脈の大きさがメモリ総量ではなく上位k件で決まるためである。メモリが増えて変わるのは照合の相手の数だけであり、照合の質が保たれる限り生成側の条件はほぼ変わらない。逆に言えば、照合が外れる規模や分布では低下が非線形に出る可能性があり、論文の測定範囲は質問応答型のメモリ利用に限られる。

## 既存研究との差

先行研究は、文脈を伸ばす全注意の改良、固定サイズ状態へ圧縮する線形注意や再帰型メモリ、取得を外部に置くRAGやエージェントメモリに分かれていた。本論文の差は、取得を注意機構の内部の学習可能な部品として組み込み、生成損失と補助損失で共同に最適化したこと、そして容量側の工夫（圧縮KV、文書別位置、階層配置）までを1つの枠組みで揃えたことにある。RAGとの比較で同一バックボーン条件を用意し、アーキテクチャの寄与と生成器の規模の寄与を分けて見せている点も、主張の置き方が具体的である。

## 限界・実装状況

- 構造的な限界: 論文自身が限界として明記するとおり、根拠が複数の文書に強く結びついて分散している課題では、文書単位の独立処理と疎な選択だけでは文書間の構造の整合を保ちにくい。メモリインターリーブは緩和策だが、その効果は設計の効率と原理づけに依存するとされている。
- ワークロード依存条件: 評価は質問応答型のメモリ利用が中心であり、メモリが頻繁に書き換わる用途や、文書間の順序が意味を持つ用途での検証は論文では未実施である。バンク構築の事前計算は、更新頻度が高いと償却できない。
- 実装状況: 著者らの専用推論エンジンによる検証であり、上流のサービング基盤へ統合された形ではない。公式コードの公開先は論文中に示されておらず、codeはnullとする。
- 評価面の限界: 効率は複雑性の分析が中心で、実測の遅延・スループットの体系的な数値は限られる。質問応答スコアはLLM判定への依存を含む。

## 一般的な実装上の含意

大規模メモリを持つ推論基盤では、容量と1回の生成が触る量を分けて設計することが前提になる。本論文の形、つまり照合用の軽い索引だけを高速な階層へ置き、内容は容量の大きい階層へ置いて選ばれた分だけ運ぶ配置は、KVキャッシュの階層化一般にも通じる。また、学習できる規模と運用する規模が違う系では、位置のような暗黙の規模依存を先に断ち切ることが外挿の条件になる。取得を外部部品のままにするか内部の学習対象にするかは、誤りの回復可能性を決める設計判断である。
