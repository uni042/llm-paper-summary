# The KV Cache Is the New Memory Wall

## 概要

長文脈LLMのdecodeは「モデル重みを読むmemory-bound処理」と説明されることが多いが、文脈が伸びると毎stepで読み直す鍵値キャッシュ（KV cache）のtrafficが重みtrafficを上回る。本論文はこの切替点をモデル構造、batch、element幅、hardware topologyから閉形式で求め、KV最適化の効果を同じ座標系で比較するSystematization of Knowledge（SoK）である。

KV対策を、精度を下げる量子化、tokenを捨てるeviction、断片化を減らすpaging、request間で共有するprefix caching、HBM外へ移すheterogeneous tieringの5領域に分ける。Llama-3-70B BF16ではKVは1 tokenあたり327,680 byteで、128K tokenの1 sequenceだけで約42 GBになる。batch 32ではKV trafficがweight trafficを超えるcrossoverが13.4K tokenまで下がり、実運用の長文脈decodeがKV律速になりやすいことを定量化する。

## 問題設定

既存論文は圧縮率、速度、品質を異なるモデル・context・hardwareで報告するため、例えば「2-bit KVが何倍速いか」を横比較できない。重みtrafficが支配する短いcontextではKVを8分の1にしてもstep全体のbyteはほとんど減らず、KV traffic支配後なら同じ圧縮が大きく効くからである。

さらにB200の2 die、MI300Xの8 accelerator chipletではaggregate HBM帯域を単一partitionから常に使えるわけではない。KV pageを一つのdieへ固定するかstripeするかで、同じbyte数でも実効帯域が変わる。本論文はalgorithmだけでなく配置topologyをbyte accountingへ含める。

## 手法

### 統一KV footprint

有効KV容量をarchitecture項、量子化element幅、eviction保持率、context長、prefix共有率、fragmentationへ分解する。量子化はelement幅を、evictionは保持率を、pagingはfragmentationを、prefix cachingは共有率を変える。tieringはbyte数を減らさず、HBM/DRAM/NVMeのresident比率とinterconnectを変える。

この分解により、容量面では複数方式の削減率を組み合わせられる一方、品質費用やkernel overheadは単純積にならないことを明示する。

### traffic crossover

decode 1 stepのweight byteとKV byteを数え、両者が等しくなる文脈長 `s*` を導出する。`s*` はbatchに反比例するため、batchを増やしてweight readを共有すると、むしろ相対的にKVが支配する時点が早まる。Llama-3-70Bではbatch 1で427.2K、batch 8で53.4K、batch 32で13.4K、batch 256では1.7K tokenである。

KVを `c` 倍圧縮した理論速度利得もweight+KV byte比から求める。短文脈では1倍へ近づき、KV支配の極限でのみ `c` 倍へ近づく。複数圧縮の個別speedupを掛け算してはいけないことも式で示す。

### topology-aware bandwidth

multi-die deviceではlocal partition bandwidthとpackage fabric bandwidthの小さい方から実効帯域を求める。page stripingによりaggregate帯域を使える条件を定式化し、B200ではpinning対stripingが最大2倍、MI300Xでは最大8倍のceiling差を持つ。

## 主要結果

|条件|指標|結果|解釈|
|---|---|---|---|
|Llama-3-70B, BF16, batch 32|traffic crossover|13.4K token|128K servingは明確にKV traffic側|
|同, batch 256|crossover|1.7K token|batch増加はKV律速開始を早める|
|B200, batch 1, 128K|2-bit KV理論speedup|1.25×|427.2K crossover前なので8× byte削減が全体へ薄まる|
|B200, batch 1, 512K|2-bit KV理論speedup|1.91×|crossover後はKV削減が強く効く|
|512K|2-bit + 50% eviction|2.05×|個別speedupの積ではなくjoint byte factorで評価すべき|
|B200/MI300X|striping対pinning ceiling|最大2× / 8×|package内配置もfirst-order要因|

128KのLlama-3-70Bではbatchを増やしても算術強度は8.0〜11.3 FLOP/Bの範囲に留まり、B200のridge 281 FLOP/Bを25〜35倍下回る。長文脈decodeをbatchだけでcompute-boundへ持ち込めないことを解析的に示す。

## 既存研究との差

既存surveyがKV方式を列挙するのに対し、本論文は「どの方式がどのfootprint因子を変えるか」を統一式へ写し、同じcontext・model・hardwareで速度上限を再計算する。特にreported speedupを平均せず、解析値と各論文の品質値を別の証拠classとして保持する。

またmemory wallをtrafficだけでなくcapacityとinterconnectの三つへ分ける。paging/prefix sharingは品質を落とさず容量・重複を改善するがdecode byteを直接減らさず、tieringは容量を解決する代わりにPCIe/NVLinkを新たなwallにする、という役割分担を明確にする。

## 限界

多くの速度値は実測ではなくrooflineとbyte accountingからの導出値であり、論文自身もkernel実装のgather、dequantization、format conversionで実速度が上限を下回ると指摘する。特にevictionのragged layoutはdense kernelへ追加gatherを要求する。

topology modelもremote partitionのHBM contentionを完全にはモデル化せず、striped配置側に有利な上限となる場合がある。品質値は各原論文の異なるbenchmarkから持ち込むため、同一taskでの完全なquality比較ではない。著者はvariance、power、公開workload、TTFTとdecode rateの同時報告不足も既存証拠の限界として挙げる。
