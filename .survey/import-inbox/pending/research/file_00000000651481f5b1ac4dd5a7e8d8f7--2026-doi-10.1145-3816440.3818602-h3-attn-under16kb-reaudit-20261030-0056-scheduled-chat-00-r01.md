# H3-Attn：3D DRAM近傍処理の内部帯域を活かす混成ヘッド並列と階層SFU

## 書誌と研究対象

Li、Jia、Zhao、LiuによるISLPED 2026論文（DOI:10.1145/3816440.3818602）。低バッチLLM推論では、重みを量子化して演算を削減しても、長い文脈の注意演算でKVキャッシュの読み出しとsoftmaxが残る。H3-Attnは3D DRAMのロジックダイへ計算器を配置し、メモリ近傍で注意演算を処理する専用アーキテクチャである。著者の主眼は新しい注意近似アルゴリズムではなく、既存のGQA、MQA、MLAとFlashAttentionを、積層DRAM内部の分散した帯域と限られたロジック面積に適合させることにある。

## 概要

従来の3D DRAM近傍処理（PNM）は、注意ヘッド単位に計算を割り振ると、KVヘッドが少ないGQA/MQA/MLAで担当ロジックブロックが偏る。積層DRAMには多数のバンクと高い内部帯域があっても、使われないバンクの帯域は活用できない。またsoftmaxの指数・最大値・和などを処理する特殊関数ユニット（SFU）は、集中配置すると通信が集中し、各ブロックに大きな非線形回路を配ると面積が不足する。

H3-Attnはクエリヘッドごとの並列性と、共有KVヘッド内部を系列方向に分割する並列性を併用する。KVキャッシュをロジックブロック群へインターリーブ配置し、局所または全体のGather/All-Gather/Reduce-Scatterで部分注意結果を合成する。さらに高頻度の指数演算を近傍側へ残し、低頻度の非線形演算をホストへ逃がす階層SFUを設計し、異なるクエリヘッドの命令を交互に実行して依存待ちを隠す。

原著の評価では、4モデルに対する混成ヘッド並列の注意デコード改善が基準方式比平均1.54〜3.84倍、階層SFUと命令交互実行の計算密度改善が3.20倍である。ここでの数値は28nm回路合成と遅延シミュレーションに基づくもので、実際に製造された3D DRAMチップで測った実測性能ではない。

## 問題設定：ヘッド共有と内部帯域の不一致

標準的な多頭注意はクエリ・キー・バリューをヘッドごとに扱う。GQAでは複数のクエリヘッドが同じKVヘッドを共有し、MQAでは全クエリヘッドが一つのKVヘッドを共有する。MLAはさらに圧縮された潜在KV表現を用いる。これらはKVキャッシュ容量を削減するが、単純にKVヘッド一つを計算ブロック一つへ割り当てる方式では、共有度が高いほど同時に使えるブロックが減る。メモリ近傍の処理ではGPUと異なり、ロジックダイの面積・バンク配置・ブロック間ネットワークが演算の並列性を直接制限する。

FlashAttentionは注意スコアをタイル単位で計算し、最大値と指数和を更新しながら出力を正規化するため、巨大な注意行列を保存せずに済む。ただしタイルごとの最大値・和・部分出力を複数ブロックへ分散すると、統合のための通信が必要になる。SFUに指数関数や縮約を担当させても、前の演算結果を書き戻すまで次の同一ヘッド命令を進められない読後書き依存（RAW）が発生し、回路が空転する。この通信とパイプラインの空転を同時に減らすのが本稿の狙いである。

## 手法

### 3D DRAMとロジックブロックの配置

原著Figure 4の構成は4枚のDRAMダイと1枚のロジックダイを積層し、ロジックダイに16個のロジックブロック（LB）を4×4のメッシュで配置する。各LBには制御器、64KBのローカルSRAM、10個のメモリコントローラ、行列積用Tensor Core、SFU、ルータを置く。各メモリコントローラは近傍のDRAMバンクへTSVやハイブリッド接合を介してアクセスする。総容量10GB、内部帯域2.048TB/sという設定は、全バンクを同時に活用できる場合の能力であり、ヘッド配置が偏ればそのまま実効帯域にならない。

### 混成ヘッド並列：クエリ単位とKV内部分割を結合

クエリヘッドは各自の重み行列から独立に生成できるため、異なるLBへ配置する。一方、複数のクエリヘッドが共有するKVヘッドは、対応するLB群を処理クラスタ（PC）として束ね、系列長方向に分割して計算する。キー行列は列方向、値行列は行方向に分けることで、各LBが担当する系列タイルに対してFlashAttentionの部分積と部分softmaxを計算できる。KVキャッシュのトークンはインターリーブして配置するため、新しいトークンが追加されても特定LBだけに更新が偏りにくい。

処理クラスタ内の部分結果はGather、All-Gather、Reduce-Scatterを使って合成する。GQAのように共有KVヘッドが複数ある場合は小さいPCを複数作り、MQAやMLAのように共有状態が少ない場合は16LB全体を一つのPCとして使う。ローカル通信と全体通信を切り替えられるため、ヘッド数の異なるモデルへ同じ構造を適用できる。通信はメッシュ上のリング方式で実装する想定であり、タイル分割が増えるほど統合通信も必要になるという交換条件がある。

### MLAでの入力から出力までの具体的な流れ

原著Figure 5では、MLAの潜在KV圧縮行列を16LBへ分割し、各LBが潜在ベクトルの一部を計算する。担当LBへGatherした潜在ベクトルをキャッシュへ追加する。各クエリヘッドの射影で得たクエリをAll-Gatherし、16LBがそれぞれ保有する圧縮KVタイルへ行列積を行う。各LBで部分softmaxの最大値・指数和・値との積を計算した後、Reduce-Scatterでヘッド別の部分出力を統合し、最後に出力側射影を実行する。潜在キャッシュの転置・非転置ビューは同じ分割データを再利用し、二重保存を避ける。この実行順が、単に「ヘッドを並列化する」だけでなく、KVキャッシュの物理配置と通信を同時に設計する理由である。

### 階層SFUと複数ヘッド命令の交互実行

従来の分散SFUは多様な非線形関数に対応する補間回路が面積を占める。H3-Attnではsoftmaxで頻繁に使う指数演算を専用の小型回路へ置き、低頻度の平方根逆数・三角関数などはホスト側で処理する。ロジックダイのSFUにはSIMD32の乗算・加減算・指数、33要素の最大値または総和へ切替可能な縮約回路、レジスタファイル、スケジューラ、出力仲裁器を設ける。縮約回路を最大値と和で再利用することも面積削減に寄与する。

同一クエリヘッドでは前の縮約結果が次の命令に必要でRAW待ちが起きるが、異なるクエリヘッド同士は独立している。MHII（複数ヘッド命令交互実行）は、待っているヘッドの代わりに別ヘッドの命令を投入し、パイプラインの空きを減らす。原著Figure 8では演算ごとの遅延が3〜8サイクルと異なるため、書き戻し競合を避けるための停止サイクルはなお必要である。つまり交互実行は全ての依存を消すものではなく、独立ヘッドの仕事で一部を隠す仕組みである。

## 評価

### シミュレーション環境と比較対象

| 項目 | 原著の設定 | 意味 |
|---|---|---|
| 対象モデル | Llama3-8B、Qwen2.5-3B、PaLM-8B、DeepSeekV2-16B（稼働2.4B） | GQA/MQA/MLA、dense/MoEを含む |
| ヘッド構成 | 32/8、16/2、16/1、16/16＋潜在1 | クエリ数と共有KV数が並列性を左右 |
| バッチ・文脈 | バッチ1/4/8、長さ2K/4K/8K | エッジ側の低バッチ推論 |
| 数値形式 | 重みINT4、活性とKVはBF16 | メモリに収めるため重みだけ量子化 |
| ホスト | 1GHzの128×128シストリックアレイ8基、SIMD128を8基 | H2-LLM型のモデル |
| 3D DRAM | 4層、各層40バンク、総10GB、内部帯域2.048TB/s | 設計上の容量・ピーク帯域 |
| LB | 16ブロック、28nm、500MHz、64KB SRAM、4 Tensor Core、2 SFU | 回路合成・面積推定の前提 |
| 推定方法 | Synopsys Design Compiler、Arm Memory Compiler、ORION2.0、Pythonシミュレータ | 製造チップでの実測ではない |
| 比較 | KV-head-parallelism、集中SFU、分散SFU | 並列性とSFUを別々に評価 |

著者はTensor CoreとSFUの合成、SRAM・NoCの面積見積もり、DRAM・計算・ネットワークの遅延モデルを組み合わせてエンドツーエンドの推論時間を推定する。実際の3D DRAM試作品の消費電力、温度、歩留まり、帯域競合の測定ではない点に注意が必要である。OOMとなった条件はFigure 9の比較から除外されており、報告倍率を全構成の平均と見なせない。

### 混成ヘッド並列の利得

Figure 9では、従来のKVヘッド単位の並列化に対する混成ヘッド並列のデコード高速化が、4モデルの設定平均で1.54〜3.84倍と報告される。特にKVヘッドが少ないQwen2.5-3BやPaLM-8B、潜在KVヘッドが一つのDeepSeekV2-16Bで改善が大きい。共有KVヘッド内部を系列方向に分割できるため、従来は遊休だったLBを活用できることが機構上の説明である。一方、バッチが大きくなると従来方式も別要求のKV処理を並列に走らせられるため、混成方式の相対的な利得は縮む。

### SFUの面積・利用率・処理時間

Figure 10(a)では、低頻度演算をホストへ移す階層SFUによりSFU面積を1.76分の1へ削減し、MHIIにより時間利用率を1.82倍へ高め、面積当たり処理密度を3.20倍へ改善したとする。計算密度の単位は系列長/サイクル/mm²であり、モデル全体の生成速度3.20倍ではない。Figure 9での階層SFU＋MHII単独のデコード改善は分散SFU比1.02〜2.74倍で、混成ヘッド並列の1.54〜3.84倍とは別の比較である。

Figure 10(b)のLlama3-8B、バッチ16、文脈2048の面積配分例では、SFUを増やしすぎてもTensor Core側の面積が減り、少なすぎるとsoftmaxが律速になる。提案SFUは小さい面積で演算時間の均衡を取り、分散SFU基準に対してエンドツーエンド推論を28%高速化した。これは特定モデル・設定の面積制約下でのシミュレーション結果であり、Figure 9の注意デコード倍率と同一ではない。

## 限界・負の結果

第一に、本研究の主要結果は回路合成とPython遅延シミュレータから得られた予測であり、製造した3D DRAM PNMチップ上の実測ではない。3D積層の熱、実際のNoC競合、配線遅延、製造制約やソフトウェアの起動・同期費用によって実効性能が変わる可能性がある。特に2.048TB/sは構成上の内部帯域であって、全ワークロードで到達した実測帯域ではない。

第二に、対象は低バッチの3B〜16Bモデル、文脈2K〜8Kに限られ、100K級の長文脈や大規模サービングの実負荷、マルチチップ構成、異なる精度や大容量MoEの実行を検証していない。バッチが大きいと既存のKVヘッド並列も要求間並列性を活用できるため、提案方式の倍率は低下する。OOMケースを除外した比較は、容量不足の構成にも同じ改善が得られる証拠ではない。

第三に、SFUの面積を極端に小さくしても大きくしても全体遅延が悪化する。Figure 10(b)の面積配分はTensor Coreとsoftmax処理の釣り合いに依存するため、他の演算器構成やモデルへ最適面積比をそのまま移植できない。低頻度の非線形演算をホストへオフロードする設計は、その呼出し頻度が増える処理では転送や同期の費用が問題になり得る。

## 既存研究との差・位置付け

KVヘッドを単位にする従来PNM方式は、KV共有が強いモデルほど内部帯域を余らせる。H3-Attnはクエリヘッドの独立性を残しながら共有KVヘッドを複数LBへ分割し、キャッシュのインターリーブ配置とリング通信を一体化した。集中SFU方式の通信集中、分散SFU方式の面積費用という二つの制約には、低頻度演算のホスト移送と独立ヘッド命令の交互実行で対処する。新規性は注意アルゴリズムの数学的近似ではなく、GQA/MQA/MLAの共有構造を3D DRAM近傍処理へ効率よく写像するアーキテクチャの共同設計にある。
