# Rimuru: Unified Memory Management for Modern LLM Serving via Elastic Expert Offloading

> 重みと注意状態で固定に仕切られた装置メモリを共有のページ入れ物で統一し、専門家の滞留量を負荷に応じて伸縮させる管理で、比較対象に対して処理能力を最大十九・〇三倍、最初のトークンまでの時間を平均九十八・一パーセント減らしたと報告した。

## 概要

現代の大規模言語モデルは、大きな重みと注意の状態の両方で装置メモリを圧迫する。特に、多数の専門家の中から一部だけを動かす専門家の仕組みを持つモデルでは、重みの総量が大きく、例えば大きなモデルを八台の装置へ載せても、注意の状態に残るのは一台あたり約七ギババイトしかなく、大きな束の推論ができない。既存の提供系は、重みと状態を別の領域で管理し、その境界は固定である。重い負荷では状態の容量が同時実行を絞って処理能力を落とし、軽い負荷では片側の余りがもう片側へ回らず、高い装置メモリが遊ぶ。

単に一つの入れ物を共有するだけでは足りない。テンソルごとに割当ての粒度も実行時の配置も違い、共有したページをそのまま別のテンソルへ使えるとは限らないからである。本論文は三つの仕組みを組み合わせる。第一に、共有の物理ページに対してテンソルごとの見え方を用意し、多段の割当てで違う粒度の確保と再利用を支える。第二に、ページ表を意識した融合した専門家演算が、キャッシュされた専門家と退避から戻る専門家の重みを、連続した実行用の入れ物へ詰め直さず直接使う。第三に、負荷に応じた調整器が、注意の状態の圧力を見て専門家の滞留量を変え、その変更を非同期の読み込みと実行に協調させる。

代表結果として、資源の限られた条件で、比較対象に対して処理能力は最大で十九・〇三倍、最初のトークンまでの時間は平均で九十八・一パーセント減った。除去実験では、統一管理、調整器、融合演算の順に積み上げることで処理能力が四・一九倍まで伸び、どの機構が効いたかが分解される。実機の、二種のサーバーでの評価である。

## 問題設定

不適合の正体は、需要が動くのに供給の仕切りが静的なことである。要求の到着が増えれば注意の状態の需要は増え、専門家を装置に多く残すほど状態は減る。逆に到着が減れば状態は余り、専門家を戻せば転送と遅延が減る。固定の仕切りはこの往復のどちらにも追随できない。専門家の退避を行う既存系は、専門家の予測とキャッシュで入出力の費用を隠すことに注力し、キャッシュの大きさは固定か手作業の設定であり、状態との競合は管理の外にある。

もう一つの難しさはテンソルの多様さである。現代のモデルは、全注意と線形注意の混成、状態を持つ再帰的な部品、細かい粒度の専門家など、配置と寿命の違うテンソルを混ぜる。ページ単位の管理は鍵値キャッシュでは確立しているが、重みはその管理の外に置かれてきた。問題設定はしたがって、重みと状態を同じ物理の入れ物で扱いながら、各テンソルの実行の形を壊さず、解放した容量が即座に別の用途へ変わるようにすることである。詰め直しの複写が入れば、解放の利得は複写の費用で食われる。

## 手法のあらまし

一つの要求の流れに沿うと次のようになる。装置メモリは共有のページ入れ物として管理され、重みも注意の状態もここから割り当てられる。各テンソルは自分の粒度と配置に合った見え方を通してページを見るため、実行側は従来どおりの形でテンソルを扱える。専門家の重みは一部が装置に残り、残りは主メモリ側にある。調整器が状態の圧力を観測し、逼迫すれば専門家の滞留を減らして状態の容量を増やし、余裕が戻れば専門家を戻す。専門家の計算は融合演算が担い、ページに散った重みをページ表経由で直接読むため、実行前の詰め直しは要らない。変更は差分として装置側へ適用され、読み込みと実行は非同期に重なる。

## 手法

### 1. 多様な見え方と多段の割当て — 共有しても形を壊さない

第一の機構が入力とするのは、粒度と配置と寿命の違うテンソルからの確保要求であり、保持する状態は共有ページの割当て表である。動作は、物理ページを共有しながら、テンソルごとに固有の見え方を与え、割当てを複数の段で管理して、違う粒度の確保と解放と再利用を同じ入れ物で処理することである。この機構が減らすボトルネックは、仕切りによる遊びである。重みの側で余ったページが状態へ、状態の側で余ったページが重みへ、そのまま回る。追加で消費する資源は割当ての管理そのものであり、感度実験ではページに残る専門家の割合を五十から百パーセントへ変えても、平均の追加費用の変化は最大で〇・二二パーセントと小さい。失敗時の挙動として、見え方の変換が実行の形と合わないテンソルではこの共有が使えず、個別の管理へ戻す必要がある。除去実験では、この統一管理を入れる段階が積み上げの土台となり、後段の調整と融合演算の利得を可能にする。

### 2. ページ表を意識した融合演算 — 詰め直さずに散った重みを使う

第二の機構が観測するのは、専門家への振り分けの結果と、各専門家の重みがどのページにあるかであり、保持する状態はページ表である。動作は、融合した専門家演算が、キャッシュされた専門家と退避先から戻る途中の専門家の重みを、ページ表をたどって直接読み、計算することである。通常の実装では、散った重みを連続した実行用の配列へ詰め直してから計算するため、入力処理のように多くのトークンが多くの専門家を動かす場面で複写が特に重くなる。この機構が減らすボトルネックは、その複写である。追加で消費する資源は、ページ表をたどる間接参照であり、逐次生成のように動く専門家が少ない場面では複写の利得自体が小さい。除去実験では、この演算を最後に加えることで処理能力が約三・八五倍から四・一九倍へ伸び、最初のトークンまでの時間は約九七・八パーセント減まで進んだ。失敗時の挙動として、この演算が想定する配置と違う重みの置き方では直接参照が使えない。

### 3. 負荷に応じた専門家キャッシュの調整器 — 滞留量を動く量にする

第三の機構が観測するのは、注意の状態の圧力、つまり同時実行の需要と空きの様子であり、保持する状態は専門家の滞留の上限と現在の滞留集合である。動作は、中央処理装置側の方針が滞留量の変更を決め、装置側が差分として適用し、非同期の読み込みと実行と協調させることである。要求が集中すれば滞留を減らして状態の容量を空け、同時実行を増やす。余裕が戻れば専門家を戻し、転送と遅延を減らす。この機構が減らすボトルネックは、固定のキャッシュ量と変動する需要のずれである。除去実験では、調整器を加えた段階で処理能力は土台の約三・八五倍へ伸び、時間は八十三・九パーセント減った。追加で消費する資源は、滞留を減らした後の再読み込みである。感度実験が示す失敗条件は明確で、退避の上限を大きくし過ぎると、集中の後に専門家を戻す回復が長くなり処理能力が落ちる。逆に上限が最小では固定の退避系と同じになり、状態が足りず要求が溜まって時間が跳ねる。最適点は、専門家を十個程度退避させて同時実行が大きく増える辺りにあり、トークン当たり時間は上限の値にほぼ影響されなかった。

### 品質・精度

生成の方式と重みの値は変えないため、出力の品質の変化は原理的にない。論文は品質の測定を扱っておらず、評価は処理能力と遅延に限られる。

### 感度・スケーリング・ストレス条件

退避上限の感度は上に述べたとおりで、少な過ぎても多過ぎても悪化し、最高点は小さな退避で同時実行が増える辺りにある。構成は単一、二台、八台で確かめられ、規模とともに利得が保たれることが示される。集中する負荷では退避と回復の往復が費用になり、定常の負荷より利得が不安定になる。

## 既存研究との差

提供系のメモリ管理の研究は、鍵値キャッシュのページ化と再利用が中心で、重みは管理の外に置かれてきた。層や配置の多様さに対応する割当ての研究も、注意の側に重み付けがある。専門家の退避の研究群は、予測と先読みとキャッシュで転送を隠すことに注力し、キャッシュの量は固定としてきた。オフラインの負荷を対象に通信と計算の重なりを整える研究もある。本論文は、重みと状態を一つの入れ物で管理し、専門家の滞留量そのものを負荷で動かす量にし、解放した容量を実行の複写なしに使えるようにした点が異なる。

## 限界・実装状況

- 対象モデルは一つの系列に限られ、他の構造のモデルでの検証はない。
- 退避上限の最適値はモデルの構造、装置の容量、負荷で変わり、自動で決める方法は示されていない。
- 集中する負荷では退避と回復の往復が費用になり、利得が不安定になる。
- 評価はグラフ機能を切った条件であり、有効時の振る舞いは未確認である。
- 公式のコード公開先は本文中に示されていない。実装は既存の提供エンジンの上に構築されている。

## 一般的な実装上の含意

資源の仕切りは、需要が動く系では静かな無駄の源になる。仕切りを外す際は、入れ物を共有するだけでなく、実行側が詰め直しなしに他人の領域を使える形まで一体で設計しなければ、解放の利得は複写で消える。また、キャッシュの量のような一見固定の量は、需要の圧力に応じて動かす量として扱うと、固定最適より広い負荷の範囲で効く。動かす量には必ず回復の費用が伴うため、上限と往復の費用を感度として測ることが要る。
