# Gradual Binary Search：射影ごとのクリッピング探索とHadamard次元拡張

## 概要

重み・活性・KVキャッシュを同時に3〜4ビットへ縮めると、活性値の外れ値によって量子化刻みが粗くなり、言語モデルの品質が急落する。QuaRotはHadamard回転によって外れ値を複数の特徴次元へ分散するが、回転後に残る外れ値の切り詰め方は射影によって異なる。著者らは、モデル全体のWikiText-2困惑度（PPL）を直接目的関数とするGradual Binary Search（GBS）を提案した。量子化した射影を順次固定しながら次の射影のクリッピング比を探索するため、先行する量子化誤差を含めて後続の設定を調整できる。

もう一つの寄与は、Hadamard行列の適用可能な次元をPaley構成とゼロ埋めによって広げ、従来のQuaRot実装が直接扱えなかったQwen系へ回転を適用することである。Mistral 7B v0.1の3ビット重み・活性・KVでは、6課題平均がQuaRotの18.43%からGBS併用で58.31%へ改善する。ただしFP16の71.08%より低く、これは生成速度40%向上ではなく正答率39.88パーセントポイントの改善である。

## 問題設定と既存研究との差

一様量子化ではテンソルの最大絶対値がスケールを決めるため、少数の大きな活性値がレンジを占めると通常の値の多くが同じ量子化レベルへ丸められる。Hadamard回転は±1要素の直交行列を使い、値を特徴次元に分散する。著者は単一の突出成分を持つベクトルを仮定した解析で、ランダムな球面上の回転よりHadamard変換の最大成分が小さくなる条件を議論する。ただしこれは任意の実モデルのすべての分布で優越するという普遍定理ではない。

QuaRotやSpinQuantは回転を主な外れ値緩和手段とする。GBSは回転後の活性値を何割まで保持するかというクリッピング比を、**各線形射影で個別に、しかも既に量子化した前段を反映したPPL**によって選ぶ点が異なる。テンソル単位の再構成誤差だけを小さくする最適化は、最終的な生成モデルの困惑度と一致しない場合がある。もう一方の次元拡張は、回転行列を生成できる次元がモデルの特徴幅と一致しない問題に対処するもので、クリッピング探索とは独立した機構である。

## 手法

### 射影別Gradual Binary Searchの入力と処理

入力は学習済みモデルM、校正データD、探索区間幅の終了閾値εである。射影を処理順に並べ、各射影のクリッピング比を0〜1の区間で探索する。現在の射影を量子化したモデルを作り、区間の中点および左右の中間候補を使って校正データ上のPPLを測る。PPLが改善する側へ区間を狭め、幅がε以下になればその射影の比率を確定する。決定済みの前段射影は低ビットのまま保持し、次の射影へ進む。出力は射影ごとに異なるクリッピング比の列である。

この逐次性は重要である。全射影を高精度のまま独立に校正してから一斉量子化すると、前段で発生した誤差が後段の最適比を変える効果を取り逃がす。GBSはモデル全体を評価することで累積誤差を含める。一方、射影数に比例して多数回のPPL評価が必要で、モデルを量子化する前処理時間が増える。論文はPPL対クリッピング比がおおむね単峰であることを探索の前提とするが、すべての射影について厳密な凸性を保証するわけではない。

基盤実装はQuaRotであり、重みの誤差補償にGPTQ、活性値にper-token量子化、KVキャッシュにgroup size 128の非対称量子化を用いる。GBSはこの構成のクリッピング比を選択するもので、GPU上の3ビット演算用に新しい専用行列積カーネルを実装して実機速度を立証する研究ではない。

### Paley型Hadamard構成とゼロ埋め

高速Hadamard変換は2の冪の次元で扱いやすいが、Qwenの特徴次元は必ずしもその条件に合わない。著者は素数pがp≡3（mod 4）を満たすときp+1次元のHadamard行列を構成できるPaley法を利用する。Legendre記号の計算で回転行列を事前生成し、重みと融合するため、その生成計算を各トークンの推論時に繰り返す必要はない。

適合する次元がない場合は、線形射影の重みの入力・出力方向にゼロを付加し、回転を適用できる幅へ拡張する。Qwen2.5-1.5Bの1536次元を例に、原著の§5.2.2は「8次元追加で1542次元」と記載するが、1536+8は1544であり算術的に一致しない。したがって**実際の採用幅は原著の記載揺れが解消されるまで確定できない**。原稿で1542または1544の一方を無条件に正解と断定しない。Qwen2.5-7Bでは3584次元のHadamard生成とMLPの32次元拡張を報告する。

ゼロ埋めした行列に回転を適用した重みを保存すれば、行列生成自体は推論時に不要である。しかし拡張した特徴を処理する演算・メモリの増加はあり得る。論文は低ビット化による演算削減分と次元拡張分の上界を比較する。これをGPUでの実測トークン速度が同じ割合で改善する証拠として扱ってはならない。長文脈・大規模モデルでは拡張の費用とA100メモリ制約が適用範囲を狭める。

## 評価結果

### 4ビット：回転にGBSを加えた差

| モデル | FP16 PPL / 6課題平均 | QuaRot系 PPL / 平均 | GBS追加 PPL / 平均 |
|---|---|---|---|
| Mistral 7B Instruct v0.3 | 5.49 / 71.62% | 5.98 / 67.88% | 5.75 / 70.15% |
| Mistral 7B v0.1 | 5.25 / 71.08% | 5.82 / 66.41% | 5.57 / 69.56% |
| Llama2 7B | 5.47 / 67.19% | 6.21 / 61.92% | 6.04 / 62.74% |
| Llama3 8B | 6.13 / 70.30% | 8.33 / 59.97% | 7.40 / 65.71% |
| Qwen2.5 7B Instruct | 7.45 / 67.57% | 9.21 / 58.70%（QuaRot+） | 8.23 / 62.69% |
| Qwen2.5 1.5B Instruct | 9.64 / 60.00% | 14.44 / 44.41%（QuaRot+） | 12.05 / 49.23% |

4ビットでは6モデル全てでPPLが改善した。Llama3 8BではPPL 8.33から7.40、6課題平均59.97%から65.71%へ改善するが、FP16の70.30%には及ばない。QwenのQuaRot系の数値は**拡張なしQuaRotではなくQuaRot+**である。既存QuaRotの次元制約により元実装の比較値が存在しないことを表に反映した。

### 3ビット：破綻の緩和と残る品質損失

| モデル | FP16 PPL / 6課題平均 | QuaRot系 PPL / 平均 | GBS追加 PPL / 平均 |
|---|---|---|---|
| Mistral 7B Instruct v0.3 | 5.49 / 71.62% | 38.28 / 22.06% | 7.04 / 61.32% |
| Mistral 7B v0.1 | 5.25 / 71.08% | 100.85 / 18.43% | 7.31 / 58.31% |
| Llama2 7B | 5.47 / 67.19% | 332.56 / 18.07% | 9.18 / 43.34% |
| Llama3 8B | 6.13 / 70.30% | 1315 / 16.84% | 12.62 / 46.92% |
| Qwen2.5 7B Instruct | 7.45 / 67.57% | 251 / 18.32%（QuaRot+） | 12.33 / 47.44% |
| Qwen2.5 1.5B Instruct | 9.64 / 60.00% | 3411 / 16.98%（QuaRot+） | 34.97 / 26.05% |

3ビットでは、Mistral 7B v0.1の6課題平均が18.43%から58.31%へ39.88ポイント上昇し、PPLは100.85から7.31へ改善した。Llama3 8BもPPL 1315から12.62まで改善する。ただしFP16の6.13からは遠く、低ビット化を「無損失」と表現できない。Qwen2.5-1.5BはGBS後も6課題平均26.05%にとどまり、FP16の60.00%から大幅な劣化が残る。モデル間の差を無視して全ての3ビット構成が実用的だとは結論できない。

### 他の回転方式・次元拡張の感度

付録のSpinQuant比較では、3ビットMistral 7B InstructのPPLが14.31から8.11、6課題平均が29.34%から54.38%へ改善する。DFRotでは同モデルのPPLが11.26から7.58、平均が47.54%から64.71%へ改善する。GBSの効果はQuaRot固有の回転に限定されないが、4ビットでは改善幅が小さい条件もある。

次元拡張の感度評価では、より多くの特徴次元を付加すると平均正答率が上がる場合がある。しかし論文の図2ではA100のメモリ制約によってLlama3 8Bの拡張幅を約2036次元以上へ増やせず、推論計算量の増加との交換条件がある。追加特徴の効果とGBSの効果を別の寄与として解釈する必要がある。

## 限界と実装上の注意

GBSは射影ごとに何度も校正データ上でPPLを評価するため、A100単機で最大約4日という前処理時間が必要である。これはオンライン生成時の追加時間ではないが、モデルを頻繁に差し替える環境では再量子化の運用費用になる。校正に使うWikiText-2の10%が他の言語、長文脈、対話タスクの分布にも最適なクリッピングを与えるとは検証されていない。

本論文は量子化後のPPLと6課題平均を主に測定する。3ビット専用カーネルの実測TTFT、TPOT、トークン毎秒、GPUメモリ占有、電力削減、複数同時要求下の性能を測った結果ではない。理論上のビット演算削減と実機速度を混同できない。次元拡張は回転適用可能性を改善する一方で、特徴幅・重み形状・演算量を変えるため、ハードウェア依存の最適化が必要になる。

クリッピング比とPPLの関係が単峰でない場合、二分探索が最良値を逃す可能性がある。評価したのはMistral・LLaMA・Qwenの特定モデルと6課題であり、別アーキテクチャ、マルチモーダルLLM、長文脈の品質保持を保証しない。特にQwen小モデルの3ビット結果は、提案手法によっても品質低下が大きく残る明確な失敗条件である。
