# VisCache: Visual KV Cache Pruning for Efficient Vision Large Language Model Inference

## 概要
Vision Large Language Model (VLM)では、画像や動画が多数のvisual tokenへ展開されるため、text-only LLMよりprefill計算とKV cacheが膨らみやすい。既存のKV pruningを全layer・全visual tokenへ同じ比率で適用すると、時間的に重複したframeと意味的に重要なframe、または感度の異なるlayerを区別できず、少ないcache budgetで品質が落ちる。

VisCacheは粗粒度と細粒度の二段階でvisual KVを減らす。まず軽量VLMがvideo/frame列から意味的に有用なkeyframeだけをforwardする。次にPruneKVがmain VLM内部でlayer別budgetを配り、keyとvalueを非対称に処理する。training不要のplug-and-play方式として、KV retentionを19〜28%まで下げながら最大2.35倍の推論高速化を報告する。

## 問題設定
visual contextには隣接frameの時間的冗長性と、同一frame内のtoken冗長性が同時にある。入力前にframeだけを落とすと細粒度token冗長性が残り、KV layer内だけを一律pruneすると、そもそも不要なframeを全modelへ通したprefill費用を回収できない。

またTransformer layerごとにvisual情報への依存度が異なるため、一律budgetは重要layerを過度に削る可能性がある。keyを削ると将来queryが参照できる位置が減る一方、valueには内容情報があるため、単純破棄以外の保持方法が必要になる。

## 手法
### keyframe filtering
軽量VLMを前段に置き、時間的に類似するframe列からsemantic informationが大きいkeyframeを選ぶ。main VLMへ入るvisual token数自体を減らすため、後段KV cacheだけでなくprefill計算も抑える。

### parabolic layer-wise budget
PruneKVは全layerへ同じ保持率を配らず、layer位置に応じた放物線状budgetを使う。重要度が高い領域へ多くのKVを残し、圧縮耐性のあるlayerからbudgetを削ることで、同じ総KV量で品質低下を抑える。

### asymmetric key pruning / value fusion
key側では将来attention候補を選択的にpruneする一方、対応valueを単純に捨てず融合する。これによりkey index数を減らしてattention計算とcache trafficを削減しつつ、除去tokenが持っていた内容情報の一部を残す。key/valueを同じ規則で消すuniform pruningとの差がここにある。

## 主要結果
|条件|結果|解釈|
|---|---:|---|
|複数評価|KV retention 19〜28%|cacheの約72〜81%を削減|
|代表条件|最大2.35× speedup|visual token/KV削減が実時間へ反映|
|同程度budget|既存baselineより高い品質|layer配分と非対称処理の効果|
|training|追加学習なし|既存VLMへ後付け可能|

## 既存研究との差
text-only向けKV pruningをvisual tokenへ一律適用する方式と異なり、VisCacheは入力frame選択とTransformer内部KV pruningを分離する。またPruneKVはkey/valueを同時削除せず、keyを減らしvalue情報を融合する。layer budgetも固定率ではなくparabolicに変えるため、時間軸・layer軸・KV役割の三つの非一様性を利用する。

## 限界
前段keyframe selector自体の計算費用があり、静止画像や時間冗長性の少ないvideoでは粗粒度filterの利得が小さくなる。19〜28% retentionでの品質維持は評価したVLM/workloadの範囲であり、細部認識や一度しか現れないvisual eventではframe/token pruningが情報損失を起こし得る。training-freeである代わりにmodel自身が圧縮へ適応する学習は行わない。
