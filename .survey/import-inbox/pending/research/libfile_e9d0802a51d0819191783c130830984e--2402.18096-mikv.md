## 概要

KVキャッシュ圧縮で一般的なevictionは、attention上の重要度が低いtokenを完全に削除する。しかし「現在重要でない」ことは「将来不要」を意味せず、system promptの安全指示、細かな事実、後続質問で必要な文脈を失うと回復できない。本論文はこの不可逆性を実験的に調べ、安全性破綻、幻覚、文脈喪失を確認する。

混合精度KVキャッシュ（Mixed-precision KV cache; MiKV）はtokenを捨てず、重要KVは比較的高い精度で保持し、eviction対象だったKVもINT2〜INT4等の低精度で残す。これによりcache容量を大幅に削減しつつ、「少量でも情報が残っている」ことを利用して品質を回復する。

## 問題設定

長context・大batchではKV容量がmodel weightを上回り得る。evictionは容量を直接減らせるが、削除は不可逆である。Line RetrievalではH2Oを使った50% evictionでaccuracyが100%から43.2%まで落ちる例があり、重要度予測が完全でないことの影響が大きい。

一様な低bit量子化は全tokenを残せる一方、attentionで重要なKVまで極低bitにすると生成品質を損なう。そこでtoken重要度とbit幅を分離し、重要tokenへbitを多く、低重要tokenへbitを少なく配る。

## 手法

### 低重要KVの低bit保持

既存importance policyがevict対象としたKVを削除せず、低精度表現へ変換して別領域へ保持する。必要時にはattentionへ参加できるため、情報が完全にゼロになるevictionと異なる。

### 重要KVの高精度保持

attention上重要なKVはFP16または比較的高い量子化精度で保持する。これにより、すべてを同じ極低bitへ落とす一様量子化で起きる主要attention経路の誤差を避ける。

### Dynamic Channel Balancer

query/keyにはchannelごとのoutlierがあり、特に極低bit key量子化を難しくする。prefill時にqueryとkeyのchannel scale比を求め、key側outlierを量子化しやすい範囲へ移し、その逆scaleを量子化しないquery側へ適用する。これによりattention内積の等価性を保ちながらkeyの量子化誤差を下げる。

## 評価条件

| 項目 | 条件 |
|---|---|
| model | Llama-2 7B/13B/70B、Mistral-7B |
| task | MMLU、GSM8K、HumanEval、Line Retrieval、AlpacaEval |
| baseline | H2O等のeviction、一様RTN量子化 |
| 低精度側 | INT2/INT3/INT4等 |
| 指標 | accuracy、win rate、KV memory |

## 主要結果

Line Retrievalでは50% evictionで43.2%まで低下する条件に対し、evict対象をINT4で保持すると100%へ回復する例を示す。さらに20% importance ratioのINT2条件ではDynamic Channel Balancerによりaccuracyが64.0%から92.6%へ改善する。

Llama-2-7B、batch 8、sequence 4096の例ではKV memoryを34.36GBから6.87GBへ減らしながらMMLU性能を同程度に保つ。Llama-2-70B-chatのAlpacaEvalでも25% cache-size条件でwin rate低下を抑える。

## 既存研究との差

H2O等は重要度の低いtokenを完全削除する。MiKVはそのimportance policy自体を否定せず、「低重要＝削除」だけを「低重要＝低bit保持」へ変える。一様KV量子化とも異なり、token重要度に応じて精度を分けるため、品質に効くKVへbit budgetを集中できる。

## 限界

全tokenを何らかの形で残すため、完全evictionほどtoken数自体は減らない。実効高速化には混合精度KVを効率良く扱うkernelとmemory layoutが必要で、容量削減率がそのままattention latency削減率にはならない。重要度判定policyへの依存も残る。
