# KVShareArena: KV-Cache Reuse Across Contexts and Model Checkpoints

> 文脈位置とモデルcheckpointが変わるKV再利用を2,150問・5モデル・11方式で品質/計算/メモリ/遅延の同一尺度に揃え、reuse repairの適用限界を測る。

## 概要

通常のprefix cacheは、同じモデルで、再利用するテキストより前のトークン列も完全に同じ場合に安全に使える。しかしRAGでは検索文書の順序や組合せが毎回変わり、エージェントでは別のsystem promptの下で同じツール出力を読む。さらにモデルを新checkpointへ更新すると、同じテキストでも古いモデルが書いたKV値は新モデルと一致しない。

このようなKVを再利用するため、位置補正、部分再計算、キャッシュ融合、学習済みadapter、圧縮など多様なrepair方式が提案されてきたが、各論文が別データ・別モデル・別費用指標を使うため横比較が難しい。KVShareArenaは「cacheが既に手元にある状態」からの品質回復と追加費用を統一して測る。

## 問題設定

文脈が変わったKVには二種類のずれがある。一つは位置ずれで、同じ文書が別位置へ移ると位置符号化とattention関係が変わる。もう一つは文脈相互作用で、元キャッシュ生成時には存在しなかった別文書へattentionしていない。checkpointが変われば、さらに重み差による表現ずれが加わる。

単一文書のneedle retrievalだけで方式を評価すると、位置だけ直せばよい条件に偏り、複数文書を統合して答える難しさを見落とす。逆に完全再計算を基準にするだけでは、どの程度の品質を何FLOPs・何メモリ・何遅延で回復したか比較できない。

## 手法

### 統一reuseシナリオ

2,150問を3つのQAデータセットから構成し、前置文脈が変わる条件、cacheを書いたモデルcheckpointが変わる条件、その両方が変わる条件を作る。回答側モデルと質問自体を固定し、cache条件だけを変えることでrepair効果を分離する。

### モデルと方式の横断比較

4B〜30Bのdense/MoE 5モデルを使い、異checkpoint再利用では6モデルペアを構成する。11方式を6クラスへ整理し、33のmodel-dataset設定で比較する。

単純な位置補正、再エンコードを伴う方式、学習を必要とするadapter、KV圧縮などを同じハーネスへ載せるため、「ある方式が自分の論文内でbaselineより良い」ではなく、同一cache状態からどの方式がPareto上有利かを見られる。

### 四つの費用軸

回答品質だけでなく、追加prefill計算、KVメモリ、要求ごとの遅延を測る。cacheを最初に作る一回限りの費用は別表示し、オンライン要求ごとのrepair費用と混ぜない。

品質は「cacheなし」と「完全再計算」の間の差をどれだけ回復したかという共通尺度も使う。これによりモデルごとに元のQA精度が違っても、reuseによる損失回復率を比較しやすい。

## 評価

| 項目 | 条件・結果 |
|---|---|
| 質問 | 3 QAデータセットから2,150問 |
| モデル | dense/MoEを含む5モデル、4B〜30B |
| checkpoint比較 | 6モデルペア |
| 総設定 | 33 model-dataset settings |
| 手法 | 6クラス11方式 |
| 評価軸 | 回答品質、prefill計算、KVメモリ、要求遅延 |
| checkpoint差 | 学習済みrepair adapterが18 pair-dataset条件中12条件で品質低下 |

単一情報源では位置補正だけでも大きな損失を回復できる一方、複数情報源を統合する質問では、位置だけ直しても元cacheが持たないcross-source attentionを復元できず、部分再エンコードや学習へ追加費用を払う方式が必要になる。

また、異checkpoint再利用ではtraining-free方式が比較的安定する一方、特定checkpointのcacheで学習したadapterは分布ずれを受けやすい。これはモデル更新を頻繁に行う本番環境で、学習型repairの運用費を示す。

## 既存研究との差

従来のlong-context benchmarkやprefix cache benchmarkは、同じ先頭prefixをそのまま使う条件が中心で、reuse自体による品質損失がほぼない。KVShareArenaは「本来そのまま再利用できないcacheを修復して使う」方式だけを比較対象として明示する。

さらにcache build costとper-request costを分離し、メモリ・計算・遅延を同時に記録するため、品質だけ高いが毎回ほぼ全再計算する方式を明確に区別できる。

## 限界・実装状況

ベンチマークであり、新しいKV repairアルゴリズムそのものを提案する研究ではない。モデルは4B〜30Bの5種類に限定され、100B級以上や全ての位置符号化方式へ結果がそのまま一般化するとは限らない。

また、公開QAで測る正答品質と、実運用エージェントの長期的な行動品質は同一ではない。ツール呼び出しや数十ターン後の誤差累積には追加評価が必要である。

## 一般的な実装上の含意

KV再利用を導入する際は「cache hitかどうか」だけでなく、そのcacheがどの前置文脈・どのcheckpointで生成されたかをmetadataとして持つべきである。位置修正で済むreuseと、再エンコードが必要なreuseを分けることで、品質を落とさず費用を抑えやすい。
