# ZeroQuant：大規模Transformerの推論速度を重視した学習後量子化

## 概要

大規模言語モデルの量子化では、重みを16ビットから8ビットへ減らすだけでメモリ転送量は小さくなる。しかし、活性化の外れ値に合わせて一つの量子化尺度を使うと、小さい値の分解能が落ちる。また、トークンごとに尺度を変える精度重視の方式では、尺度計算・量子化・逆量子化のためにGPUメモリを何度も往復すると、低ビット行列積の高速化が相殺される。ZeroQuantは、この「表現誤差」と「変換費用」を同時に扱う推論パイプラインである。

提案は、重み行列のグループ別量子化、トークン別の活性化量子化、量子化誤差を層単位で回復する知識蒸留、そして融合カーネルを組み合わせる。INT8では追加の学習や校正なしでBERT・GPT系の品質をほぼ保ち、NVIDIA A100上のBERT-baseで最大5.19倍、GPT-3 350Mで4.16倍の速度向上を示した。さらに全結合層の重みをINT4にした混合精度構成では、FP16に対してモデル容量を約3分の1へ減らす。これは2022年当時のモデルと実装を用いた結果であり、現代のMoEモデルや異なるGPU世代への一般的な保証ではない。

特に注意すべき点は、GPT-NeoX 20Bの全演算を一律W8A8へ変更すると品質が大きく下がることだ。著者らは自己注意の入力活性化だけFP16へ戻すW8A8/16を採用し、元のFP16版のA100二基・65ミリ秒から、A100一基・25ミリ秒へ変更している。論文の「5.2倍」はGPU使用基数と遅延を組み合わせたシステム効率であり、単純な単一要求の速度倍率は65/25=2.6倍である。

## 問題設定と従来法の不足

### 活性化のトークン別値域

通常の学習後量子化では、重みや活性化を整数へ写す尺度を校正データから求める。固定尺度が十分なら推論時の処理は単純だが、GPT-3 350Mの最終層ではトークン別活性化の最大絶対値が約8から35まで変化する。全トークンを最大側へ合わせると、値域が小さいトークンに割り当てられる整数の段階が少なくなる。実際、原著表1の単純なW16A8では、19個の正答率系課題の平均がFP16の38.9から37.8へ下がり、WikiText-2のパープレキシティ（低いほど良い）は21.5から24.6へ悪化した。

重み側にも同じ問題がある。注意出力行列の行別最大値は約10倍異なり、行列全体を一尺度で量子化すると小振幅の行で表現段階が失われる。INT4では表現可能な値が16段階しかないため、誤差がさらに目立つ。単純なW4/8A16ではGPT-3 350MのWikiText-2パープレキシティが1.76×10^5に達し、実用的な生成が崩れる。

### 量子化を細かくするほど増える実行時費用

重み・活性化を細かい単位で量子化すれば統計的な誤差は減らせる。しかし尺度の計算、データ変換、整数行列積後の逆変換を個別GPUカーネルとして実装すると、カーネル起動と高帯域メモリへの読み書きが増える。特に小バッチの推論では、演算器のピーク性能よりも重みの読み出し時間が支配的であるため、低ビット化による転送量削減が実時間短縮につながるかは変換の実装に依存する。著者らは量子化アルゴリズムとGPU実装を一体で設計する必要があると主張する。

### 蒸留を大規模モデルへ適用する際の費用

量子化対応学習や従来の教師・生徒蒸留では、全モデルを再学習するため、教師と生徒、勾配、最適化器の状態を大量に保持する。モデルが数十億パラメータになると、量子化後の品質回復そのものが高価になる。また元の学習データを利用できない場合もある。ZeroQuantは、INT8には追加学習なしの経路を用意し、INT4混合の場合だけ軽量な層単位蒸留を選択する。

## 手法

### 1. GPU演算タイルを考慮したグループ別重み量子化

重み行列を複数のグループへ分割し、各グループの値域に合わせた尺度で整数化する。行列全体を一つの尺度で変換する場合に比べ、外れ値の影響を局所化し、行ごとの小さな値もより多くの量子化段階で表せる。論文は既存のQ-BERTでも使われたグループ量子化を、学習後量子化と実GPUの高速行列積へ接続する点を重視する。

グループを無制限に小さくすると尺度の数と読み出しが増え、GPUの行列積タイルと噛み合わない。そこでA100のWarp Matrix Multiply and Accumulate（WMMA）で使うタイル形状を考慮し、規則的な低ビット行列積を実行できる粒度を選ぶ。出力はグループごとの尺度と量子化重みであり、推論時に専用整数行列積へ渡す。ここでは量子化誤差を小さくすることと、GPU上で実際に高速化することの両方が制約となる。

### 2. トークン別の動的活性化量子化

活性化は現在の各トークンの値から最小値・最大値を計算し、トークンごとの尺度でINT8へ写す。異なる入力や生成段階で値域が変わっても、各トークンが持つ情報をより細かく保持できる。固定の校正データから全入力共通の活性化範囲を求める必要がないため、W8A8の標準構成では追加の量子化用校正工程を不要にできる。

ただし尺度計算自体は実行時の演算である。ZeroQuantはこれを単独カーネルにせず、直前の層正規化（LayerNorm）、バイアス加算、活性化関数などと融合する。量子化済み活性化を整数行列積へ直接渡し、行列積のINT32累積結果に重み尺度と活性化尺度を適用してFP16へ戻す処理も出力段階に組み込む。これにより別の読み書きパスを減らし、細粒度化による精度向上を実測速度へつなげる。

### 3. CUTLASSを用いた量子化対応行列積

GPU側の行列積にはCUTLASSのINT8汎用行列積を使い、バッチ、系列長、隠れ次元に応じたタイルと実行方式を選ぶ。GPU演算器の効率は入力行列の形状とパディングにも左右されるため、著者らはCUTLASSの性能探索を利用して複数の実行設定を準備する。融合された前後処理と低ビット行列積を一つの流れとして最適化する点が、単純に量子化重みを保存するだけの方式と異なる。

データフローは、前段のFP16演算結果をトークン単位で量子化し、グループ量子化済み重みとのINT8行列積を実行し、INT32累積値を適切な尺度でFP16へ戻して次の演算へ渡す、という順序になる。重みの読出しバイト数を削減する一方、尺度の参照と型変換は残るので、融合によってこれらのメモリ往復を抑える。論文の高速化はGPUのINT8演算器だけではなく、このデータ移動削減を含む。

### 4. 層単位知識蒸留による低ビット誤差の回復

INT4/INT8混合では、重み量子化の誤差が大きくなるため、層単位知識蒸留（Layer-by-layer Knowledge Distillation; LKD）を用いる。対象の第k層について、元のFP16層と量子化層へ同じ前段出力を入力し、両者の出力の平均二乗誤差を小さくするよう量子化層を更新する。前段の第1層から第k-1層は両経路で共有されるので、教師モデル全体の別コピーを常時保持する必要がない。

この更新は一層ずつ進み、追加の重み・最適化器状態は主に現在の層へ限定される。出力ラベルを直接使わない層出力の一致が目的なので、元の事前学習データでなくとも蒸留できる。ただし「データ不要」は入力トークンが一切不要という意味ではない。ランダムなトークン列やWikipediaなどを入力して中間表現を作る必要があり、データ分布に応じて品質回復の程度が変わる。

### 5. INT4/INT8混合精度と20B級モデルでの例外

より強い圧縮を目指すW4/8A8では、容量の大きい全結合層の重みをINT4、自己注意の重みをINT8、活性化をINT8とする。全重みをINT4にするのではなく、精度への感度が高い部分に8ビットを残す構成である。これにLKDを加えて生成品質を回復するが、後述の通りFP16と完全同一にはならない。

GPT-NeoX 20Bでは、全行列積の活性化をINT8にすると精度が大幅に落ちた。著者らは自己注意計算の入力活性化に原因があると分析し、その部分をFP16へ戻したW8A8/16を使う。これは、同じINT8方針を全モデルへ一律に適用できないという重要な負の結果であり、最大5.2倍というシステム効率を読む際の前提でもある。

## 評価

### 評価環境と指標

| 項目 | 一次論文で確認できる設定 |
|---|---|
| 主な実機 | NVIDIA A100 40GB、INT8 Tensor Core、CUTLASS |
| モデル | BERT-base/large、GPT-3型350M/1.3B、GPT-J 6B、GPT-NeoX 20B |
| 品質 | BERTのGLUE、GPT系19個の正答率課題、WikiText-2等のパープレキシティ |
| 速度 | BERTモデル全体の平均推論遅延、GPT系は先頭50トークン生成時の平均遅延 |
| 比較 | FP16、単純な学習後量子化、量子化対応学習、層単位蒸留の有無 |
| 圧縮 | W8A8、W4/8A16、W4/8A8、20B級では注意入力をFP16に保つW8A8/16 |

W8A8は重み・活性化とも8ビットを意味する。W4/8A8は全結合重みが4ビット、注意重みが8ビット、活性化が8ビットという混合構成である。GLUE平均は複数タスクの正答率系指標を集約した値で、高いほど良い。パープレキシティは次トークンの予測の悪さを示し、低いほど良い。これらは同じ指標ではないため、正答率の小さな差だけで生成品質を保証してはならない。

### BERTの精度と蒸留費用

| BERT-baseの条件 | GLUE平均 | 量子化・追加学習費用 |
|---|---:|---:|
| FP16基準 | 83.95 | — |
| 単純なW8A8学習後量子化 | 77.41 | 6秒 |
| ZeroQuant W8A8 | 83.75 | 0秒（追加校正・学習なし） |
| W8A8量子化対応学習 | 83.37 | 2,900秒 |
| ZeroQuant W4/8A8 | 81.55 | 0秒 |
| ZeroQuant W4/8A8＋LKD | 82.71 | 31秒 |

原著表2では、W8A8の細粒度化によって単純な学習後量子化の平均77.41を83.75まで回復し、FP16の83.95へ近づけた。これは「INT8なら必ず精度が同じ」という一般命題ではなく、特定モデル・評価タスク・専用実装での結果である。W4/8A8では蒸留後もFP16に対して1.24ポイント低いが、蒸留費用は31秒に収まった。BERT-largeでもW8A8の平均はFP16の85.03に対して84.81、W4/8A8＋LKDでは81.62であり、RTEなど一部タスクでは大きな劣化が残る。

### GPT系の精度：生成指標で見える負の結果

| モデルと設定 | 19課題平均（高いほど良い） | WikiText-2 PPL（低いほど良い） |
|---|---:|---:|
| GPT-3 350M FP16 | 38.9 | 21.5 |
| GPT-3 350M 単純W8A8 | 37.8 | 26.2 |
| GPT-3 350M ZeroQuant W8A8 | 38.7 | 21.7 |
| GPT-3 350M ZeroQuant W4/8A16 | 33.5 | 88.6 |
| GPT-3 350M 同＋LKD | 37.0 | 30.6 |
| GPT-3 1.3B FP16 | 42.4 | 15.3 |
| GPT-3 1.3B ZeroQuant W8A8 | 42.3 | 15.7 |
| GPT-3 1.3B ZeroQuant W4/8A8＋LKD | 39.90 | 18.2 |

原著表4・5が示す通り、INT8の細粒度化はGPT-3 350MのWikiText-2 PPLを単純方式の26.2から21.7へ戻す。一方、より強いW4/8A16では、LKDを加えてもPPLは30.6であり、FP16の21.5には届かない。正答率平均37.0も38.9より低い。GPT-3 350MでのLKDには約3.1時間、1.3Bでは約3時間が必要であり、BERTの31秒という数字を全モデルへ一般化できない。

### 実測遅延と資源削減

| 実機条件 | FP16 | 提案量子化 | 変化の解釈 |
|---|---:|---:|---|
| A100・BERT-base、系列128、バッチ1 | 2.45 ms | 1.08 ms | 2.27倍高速化 |
| A100・BERT-base、系列128、バッチ128 | 67.08 ms | 12.92 ms | 5.19倍高速化 |
| A100・BERT-large、系列128、バッチ128 | 183.4 ms | 36.62 ms | 5.01倍高速化 |
| GPT-J 6B、先頭50トークン | 29.13 ms | 7.94 ms | 3.67倍高速化 |
| GPT-NeoX 20B、先頭50トークン | 2 GPU×65 ms | 1 GPU×25 ms | 遅延2.6倍、GPU基数を加味した効率5.2倍 |

BERTの表6はバッチ・系列長を変えたモデル全体の遅延であり、最大5.19倍は特定の大きなバッチ条件での結果である。バッチ1では同じモデルでも2.27倍となる。GPT-Jの表7は生成した先頭50トークンについて測った平均遅延であり、全体の長い生成や高同時要求サービングでの倍率を直接意味しない。GPT-NeoXの5.2倍は、GPU数が半分になり、同時に遅延が65/25へ減ったことを組み合わせたシステム効率指標である。

### 構成要素除去実験：どの機構が効くか

原著表9はBERT-largeのW4/8A8で、グループ量子化・トークン量子化・LKDを順に加える。すべてを除くとGLUE平均35.85、グループ量子化だけを入れると66.52、トークン量子化も加えると81.06、最後にLKDを加えると81.62となる。最初の二つの量子化設計が主要な精度回復を担い、LKDの追加効果はこの設定では0.56ポイントに留まる。つまり蒸留が全精度回復の主因という解釈は誤りである。

この構成要素実験は品質指標であり、各機構を個別に無効化した際の推論遅延やGPU転送量を同じ表で比較したものではない。融合カーネルが速度に重要であるという主張は、原著の実装説明と速度表を併せて評価する必要がある。量子化の精度改善と推論システム全体の高速化を一つの数値へまとめないことが重要である。

### 元の学習データを使わないLKDの検証

原著表10ではGPT-3 350MのW4/8A8に対し、LKDなしの19課題平均33.4・PPL92.1から、ランダムトークンによる蒸留で34.5・40.6、Wikipediaで36.2・30.4、元の学習データで36.6・31.1へ改善した。元のデータがなくても有効な学習信号を得られる一方、ランダムデータでは品質が元データ・自然文に劣る。WikipediaのPPLがこの実験では元データをわずかに上回るが、すべての分布でWikipediaが優位という主張ではない。

この実験は層単位蒸留が教師・生徒の中間出力の一致を目的とし、正解ラベルに依存しないことを支持する。しかし、元データへのアクセス不要と、追加のGPU時間や入力テキストが完全に不要であることは別である。INT4混合の量子化には依然として短時間の最適化工程がある。

## 既存研究との差

Q-BERTはグループ別重み量子化を提案したが、量子化対応学習を前提とし、GPU実行時の細粒度量子化の費用まで一体最適化したものではない。従来の学習後量子化は再学習を省ける一方、GPT型のトークン別活性化値域と低ビット実装の双方を十分扱っていなかった。ZeroQuantは、グループ粒度をGPUの演算タイルへ整合させ、トークン別尺度計算を融合カーネルに載せ、さらにINT4混合の誤差を層単位で回復する三層構造を特徴とする。

量子化対応学習では元データや長い再学習を要することがあるが、ZeroQuantのW8A8は追加学習なしで導入できる。W4/8A8のLKDは元データがなくても実行でき、必要な追加モデルメモリを主に一層分へ限定する。これらは、量子化精度だけでなく、実際の配備コストと推論速度を同時に考えるという研究上の貢献を示す。

## 限界と適用上の注意

最大の制約は、品質維持と高速化がモデル・層・ハードウェア・バッチに依存することである。GPT-NeoX 20Bでは全活性化のINT8化が失敗し、注意入力だけFP16に残す例外が必要だった。著者ら自身、20Bで注意入力が敏感である理由を他の超大規模モデルで十分検証できていないと述べている。この結果から、20B以上の全モデルに一律W8A8を適用してよいとは結論できない。

次に、INT4混合では蒸留を使っても品質損失が残る。GPT-3 350MのW4/8A16＋LKDのPPL30.6はFP16の21.5より悪く、BERT-largeのRTEでも低下が大きい。メモリ容量が約3分の1になることと、生成品質を完全に保持できることは同義ではない。また、LKDの処理時間はBERTでは数十秒から数百秒である一方、GPT型では数時間かかる。

評価はA100世代のINT8 Tensor CoreとCUTLASS実装に依存する。量子化粒度と融合方式が別世代GPUの演算タイルやカーネルへ適合するとは限らない。さらに、実験対象はBERT、GPT-3型、GPT-J、GPT-NeoXであり、混合専門家モデル（MoE）、グループ化クエリ注意、最新のKVキャッシュ管理、連続バッチング、多GPUサービング下の干渉、端末のCPU/GPUオフロードを直接評価していない。これらの構成へ速度倍率を転用するには追加検証が必要である。

著者らの「5.2倍の効率」はGPT-NeoXのGPU台数と遅延の積を比較したものであり、単一GPU上の単一要求が5.2倍速くなったという意味ではない。BERTの最大5.19倍もバッチ128の条件であり、バッチ1では2.27倍である。速度・容量・品質の各指標を、同一条件と比較対象を明示して読む必要がある。
