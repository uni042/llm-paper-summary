# Token Sparse Attention：再選択可能なトークン疎注意

## 概要

長いプロンプトを読み込むprefillでは、系列長Lに対する全注意の計算が概ねLの二乗で増える。FlashAttentionはメモリ入出力を効率化するが、演算対象のトークン組を自動的に減らすわけではない。既存のブロック疎注意はブロック内に重要なトークンが少数あってもブロック全体を計算し、初期層でトークンを永続削除する方式は後段で重要になる情報を取り戻せない。

JoらのToken Sparse Attentionは、**各層・各注意ヘッドで選んだQ/K/Vだけを短い密配列へ集め、注意計算後に結果を元の系列長へ散布する**。選ばれなかった位置には注意の出力が加わらないが、残差経路にその位置の情報が残る。次の層では再び全位置から候補を選べるため、層やヘッドごとに変わる重要度へ追従できる。トークンの永久削除と異なり、疎な計算と再評価可能性を両立する。

LLaMA-3.1-8B-InstructのRULERでは、FlexPrefill単独の平均精度87.27%を併用後も87.27%に保ち、128Kでの**注意処理**高速化がFlashAttention比2.44倍から2.76倍へ上がった。これは復号を含む全要求のレイテンシ倍率ではない。著者は最大3.23倍の注意高速化も報告するが、設定ごとの精度・速度の対応を別に確認する必要がある。

## 問題設定と重要度の変動

ブロック疎注意のMinferenceやFlexPrefillは、注意行列の特定の領域を計算しないことで長文脈prefillを速くする。だがトークン単位では、同じブロック内に低重要度の位置が残る。FastKVやGemFilterのようなトークン削除方式は、早い層で残す位置を選んで後段の計算を減らすものの、一度捨てた位置は後の層から見えない。もし層ごとに注目対象が変われば、この不可逆性が精度を下げる。

原著Figure 2(a)はLLaMA-3.1-8B-Instructの各層で上位1%の重要トークンを抽出し、層間での集合の重なりを測る。隣接層では一定の重複があるが、層が離れるほど重複は小さくなる。Figure 2(b)では同じ第18層内でも注意ヘッドごとに重要度順位が異なる。これらは「初期層で全ヘッド共通のトークンを一度だけ選べばよい」という前提が成立しない理由を示す。

提案方式の主な対象は長文脈**prefillの注意計算**である。評価では復号側は通常の密注意を使う。したがってKVキャッシュの長期保存量を恒久的に減らす方式、あるいは復号ステップの帯域を直接削る方式として紹介するのは不正確である。

## 手法

### 1. ヘッドごとのQ/K/V圧縮と出力復元

各層の各注意ヘッドhで、長さLの入力から重要トークン位置の集合S_hを選ぶ。元のQ、K、Vから対応する行を集め、長さL'のQ̂、K̂、V̂を作る。選択集合はヘッド間で共有せず、ヘッドごとの注意対象に合わせる。縮約配列はメモリ上で連続した密なテンソルになるため、通常のFlashAttentionや既存の疎注意カーネルを大幅に改変せずに使える。

縮約配列で計算した注意出力ÔはL'件しかないので、そのまま次層へ渡すと系列長が変わってしまう。そこで元の長さLのゼロ配列を用意し、S_hの位置へÔを散布する。選ばれなかった位置の注意出力はゼロとなるが、Transformerの残差接続により入力隠れ状態は次層へ残る。この**圧縮→注意→散布→残差**の順序が、後続層での再選択を可能にする。

計算対象の注意行列は概念上L×LからL'×L'へ縮む。ただし位置選択のための重要度推定、gather/scatter、索引構築の費用が追加される。単純に(L'/L)²だけ実測レイテンシが下がるわけではなく、原著はその追加費用を別途測定している。

### 2. Dynamic Token Coverage：保持数と保持位置の分離

各ヘッドで直近の少数のQueryを全Keyへ照合して、トークン位置ごとの注意重要度s_hを近似する。スコア算出にはTritonで融合したカーネルを用い、全Queryの完全注意行列を先に作ることは避ける。ヘッド間のスコアを合算・正規化して層全体の重要度分布s_lを得る。

まず層全体の重要度を小さい順に並べ、重要度の累積和が指定閾値τへ達するまでの低重要度トークン数を削除予算k_sparseとする。残す数k_keep=L−k_sparseが決まった後、**どの位置を残すかはヘッドごとのs_h上位k_keep件**で決める。層全体の分布は「何件を計算するか」を決め、ヘッド別の順位は「どれを計算するか」を決める。両者を分離するため、全ヘッドへ一つの位置集合を強制しない。

τを増やすほど低重要度の裾から削る量が増え、計算は軽くなるが精度低下の危険も増える。重要度分布が鋭い入力なら多くを削れ、平坦な入力なら削除数が変わるため、一定比率の固定疎化より入力の性質へ追従する。これは重要度スコアの近似に依存するので、直近Queryが代表的でない場合や、後で重要になる位置を過小評価した場合は品質を損なう余地がある。

### 3. Sparse Layer Selection：疎化する層の選択

全層を疎化すると性能が大きく落ちるため、原著は層ごとの表現変化量を測る。入力隠れ状態h_{l,t}と次層出力h_{l+1,t}の差のL2ノルムを、入力のノルムで割った相対変化量R_lをトークン平均する。R_lが小さい層は表現が比較的安定し、トークン選択による摂動を許容しやすいという仮説である。

Figure 4(b)では3層を無作為に選んでτ=0.99相当の実験条件で疎化し、200回の組合せについて平均ドリフトとRULER精度の相関を調べる。低ドリフトの組合せほど精度が高い傾向を確認した。実装ではドリフト順位の低い側50%の層を選ぶ（δ=0.5）。この層選択はモデルごとの前処理で一度行い、各要求で毎回層の全探索を行う設計ではない。

### 4. 既存の疎注意との合成

縮約Q/K/Vの内部で実行する注意カーネルを差し替えられるため、FlashAttentionのような密注意にも、Minferenceの縦・斜め疎パターンやFlexPrefillのブロック疎注意にも重ねられる。ブロック疎注意が不要ブロックを省く前に、トークン単位の不要位置を減らせる点が相補的である。ただし、二つの疎化を重ねれば誤差が必ず相殺されるわけではない。実験では同一モデル・同一RULER条件で精度と注意速度を両方報告している。

Table 1の6つの系列長の平均を精度として用いた。LLaMAのFlexPrefillは精度を変えずに注意速度が2.44→2.76倍へ向上する。一方、Minferenceとの併用では86.49→86.05と0.44ポイント下がり、MistralのFlexPrefillでも68.16→67.91と0.25ポイント下がる。「常に完全無損失」とは言えない。128Kの個別精度もLLaMAのFlashAttention 74.15→73.68、MistralのFlexPrefill 20.54→19.58と低下例がある。

InfiniteBenchのTable 2では、LLaMAのFlashAttention平均50.86→50.88とほぼ維持した一方、FlexPrefillとの併用は49.53→49.23と0.30ポイント低下した。MistralではFlashAttention 22.93→22.80、FlexPrefill 24.80→24.08であり、特定タスクの差は平均より大きい。例えばMistralの数学項目はFlexPrefill 4.57→3.14へ下がる。平均値だけを見て全課題で品質を保つと判断するのは危険である。

## 感度・構成要素・負の結果

原著Table 3では、τ=0.005の選択層平均注意疎化率が4Kの17.00%、16Kの26.61%、64Kの34.07%、128Kの54.44%へ増えた。長い文脈ほど重要度の小さい裾が大きくなるため、長文で計算を削りやすい。τ=0.010なら128Kで67.36%となり、より強い疎化を得るが精度の交換条件を確認する必要がある。

Table 4のLLaMA RULER比較では、動的τ=0.005が疎化率54.44%、精度87.02%、速度1.36倍、τ=0.010が67.36%、86.84%、1.51倍だった。固定疎化率s=0.3では50.96%、86.91%、1.32倍、s=0.5では74.95%、85.43%、1.57倍である。厳密に同じ疎化率ではないが、同程度の速度領域で動的選択の方が精度を保ちやすい傾向が見える。

Token Eviction比較のTable 5では、128K注意速度をおよそ1.5倍へ揃えたとき、RULER平均はPyramidInfer 78.49、GemFilter 85.12、FastKV 85.64に対して提案方式86.84だった。原著の比較は**prefillの計算速度を合わせた条件**であり、復号時のキャッシュ容量まで揃えた比較ではない。早期削除方式は後段でトークンを再選択できない点が精度差の候補要因となる。

Figure 6(b)の128Kレイテンシ内訳では、重要度計算、索引構築、QKV gather、出力scatterの追加費用が、最も強い疎化設定でも全層注意時間の11%未満だった。ただし短い系列ではこの固定費用が相対的に大きく、Figure 6(a)でも速度改善は長文ほど大きい。GPUカーネルの実装やメモリ配置が変われば、この11%という値を一般化できない。

## 既存研究との差

FlashAttentionは正確な注意を効率的に計算するカーネルであり、トークンを選別するものではない。MinferenceやFlexPrefillは注意行列のブロック・パターンを省略するが、ブロック内の不要トークンが残る。FastKV/GemFilter/PyramidInferは初期の重要度で位置を削り、その後の層で復活させない。Token Sparse Attentionは「層ごと・ヘッドごとのQKV選択」と「注意出力の元系列への散布」を組み合わせ、次層で選択をやり直せる。**情報の表現は残差経路に残し、注意演算だけを疎化する**ことが構造上の新規性である。

本方式はモデルの重みを低ビット化する量子化や、復号時のKVキャッシュ保持を減らす方式とも目的が違う。長文脈prefillの注意行列を小さくするので、長い入力の読み込みに適するが、生成トークンごとのKV読み出しやGPUの重みロードの削減は直接の評価対象ではない。

## 限界・実装上の注意

評価したモデルは8Bと12B、GPUは単一A100であり、MoEモデル、多GPU分散、低VRAM機、同時要求の多いサービスでの性能は未確認である。重要度推定は直近Queryの近似注意に依存し、層・ヘッドごとに必要な位置を誤ると精度が低下する。疎化開始層を決めるドリフト測定はモデルごとの前処理が必要で、別モデルへ同じ層集合をそのまま流用できない。

Table 1と2の一部で精度が下がり、固定比率との比較も全ての条件で完全一致の速度・疎化率ではない。復号では密注意を使うため、KV保存容量が自動的に減るわけではない。評価した速度は注意処理の平均であり、モデル全体のprefill、エンドツーエンド遅延、生成トークン毎秒、TTFTやP99を直接示さない。適用時には対象モデルと文脈長で精度と**実サービスのprefill時間**を別に測定すべきである。
