## 概要
自己回帰modelは次tokenが確定するまでその次を生成できないため、Transformerのようにsequenceを並列処理できるarchitectureでもdecodeは1 tokenずつ進む。Blockwise Parallel Decodingは1回のmodel evaluationで複数の将来位置を提案し、その候補を元のscoring modelで並列検証して、greedy decodingと整合する最長prefixをまとめて受理する。

品質を変えない設定ではgreedy decoderのiteration数を最大約2倍削減し、少量の品質低下を許す設定では最大7倍まで削減する。wall-clockでは最速条件で標準greedy decoding比最大4倍の高速化を報告する。後年の投機的復号（speculative decoding）と同じ「安い提案を作り、強いmodelで並列検証する」発想の先駆けである。

## 問題設定
autoregressive factorizationではtoken t+1がtoken tへ依存するため、通常decodeのcritical pathは出力長に比例する。self-attention modelはtraining時に全位置を並列計算できても、inference時のgreedy generationではこの依存を避けられない。

複数tokenを無条件に同時生成するnon-autoregressive方式はiterationを減らせるが、条件付き依存を弱めるため品質が落ちやすい。必要なのは、最終的なscoring modelの判断を保ちながら、1 iterationで1 token以上進む仕組みである。

## 手法
### block proposal
通常の次token headに加えて、現在prefixから2 step先、3 step先など複数offsetのtokenを予測する補助headを学習する。1回のforwardで将来block全体の候補を並列に得る。

### parallel scoring
提案blockをprefixへ仮置きし、self-attention modelが複数位置を並列処理できる性質を使って各位置のgreedy predictionを一度に計算する。補助headの候補をそのまま信頼せず、元modelのscoreをverificationに使う。

### longest-prefix acceptance
左から候補とscoring modelのpredictionを比較し、一致する最長prefixだけをcommitする。最初に不一致となった位置ではscoring model自身のtokenを採用して次iterationへ進む。厳密設定ではこの規則により標準greedy decoderと同じoutputを維持できる。

### speed-quality tradeoff
受理基準を緩めればより長いblockをcommitでき、iteration数をさらに減らせるがoutput qualityは変化する。論文はlosslessなgreedy-equivalent設定と、品質を少し許容して高速化を増やす設定を分けて評価する。

## 評価条件
| 観点 | 内容 |
|---|---|
| architecture | deep self-attention autoregressive model |
| task | machine translation、image super-resolution |
| baseline | standard greedy decoding |
| 指標 | decoding iterations、wall-clock、task quality |
| parallelism | future-token proposal + parallel validation |

## 主要結果
| 条件 | 比較 | 結果 | 品質 |
|---|---|---:|---|
| strict validation | greedy decoder | iteration最大約2倍削減 | lossなし |
| relaxed condition | greedy decoder | iteration最大約7倍削減 | slight degradation |
| fastest implementation | greedy decoder | wall-clock最大4倍高速 | 条件依存 |

iteration削減とwall-clock speedupは同一ではない。1 iterationあたりは複数positionをscoreする追加計算があるため、7倍のiteration削減が7倍の実時間短縮にはならず、実測最大は4倍である。

## 既存研究との差
non-autoregressive generationは全tokenを並列生成して逐次依存を捨てるのに対し、本方式はautoregressive scoring modelをverificationへ残す。後のdraft-model型speculative decodingと比べると、別小modelではなく同modelに将来offset用headを追加してproposalを作る点が異なる。

## 限界
補助headを学習する必要があり、既存checkpointへ完全training-freeで適用する方式ではない。候補が頻繁に外れるtaskでは1 iterationあたりのadvanceが1 tokenへ近づき、追加proposal/verification計算だけが残る。評価は現在の大規模LLM serving以前のmachine translation等が中心で、KV cacheやcontinuous batchingとの統合は論文の主評価外である。
