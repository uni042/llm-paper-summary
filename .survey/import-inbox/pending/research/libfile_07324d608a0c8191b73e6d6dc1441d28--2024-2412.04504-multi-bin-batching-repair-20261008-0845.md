# Multi-Bin Batching for Increasing LLM Inference Throughput

## 概要

本論文は、LLM推論要求を固定サイズのバッチへまとめて処理するとき、要求ごとの出力長の違いによってGPUが遊ぶ問題を、待ち行列理論と実測の両方から検討する。通常の固定バッチでは、同じバッチの短い要求が終了しても、最も長い要求が完了するまでそのバッチの処理が続く。出力長の短い要求と長い要求を混ぜるほど、短い要求に割り当てられた計算能力が使われない時間が長くなる。

提案する複数区画バッチ化（Multi-Bin Batching）は、各要求の予想実行時間、実装上は予想出力トークン数をもとに、あらかじめ定めたk個の区画へ要求を振り分ける。同じ区画の要求がB件集まったら一つの固定バッチにし、完成したバッチを共通の実行待機列へ入れる。これにより、同じバッチ内の最短と最長の処理時間の差を小さくする。GPUカーネルやモデル重みを変更するのではなく、**バッチを組む前の要求分類**を変更する方式である。

論文はポアソン到着、独立で一様なサービス時間、固定サイズのバッチという理想化モデルを使い、区画境界と処理率を解析する。一様分布なら各区画に等しい確率質量を割り当てることが最適で、区画数を増やすほど固定バッチ方式の理想的な処理能力へ近づく。一方、2026年8月改訂のv2では現代の推論基盤で一般的な連続バッチ処理も明確に比較した。Dolly負荷では推定長で8区画に振り分けると通常の固定バッチより生成トークン処理率が150.1%高かったが、連続バッチ処理には43.0%及ばなかった。したがって、固定バッチの改善と連続バッチの置換は別の主張である。

## 問題設定

LLMは入力を事前処理した後、トークンを逐次生成する。要求ごとに終了トークンや生成上限までの長さが異なるため、同時に開始した要求が同時に終わるとは限らない。固定バッチをB件まとめて一つの処理単位とし、バッチ内の要求を途中で入れ替えられない場合、その処理時間は個々の要求の実行時間の最大値で決まる。

例えば実行時間が1秒、5秒、2秒、6秒の4要求を到着順に2件ずつ組むと、最初のバッチは5秒、次のバッチは6秒で計11秒を要する。長さの近い1秒と2秒、5秒と6秒を組めば2秒と6秒で計8秒になる。処理対象の要求数と個々の実行時間は変わらないが、同じバッチに含まれる要求の時間差が小さくなった分だけ、固定バッチの占有時間が短くなる。

ただし実際のLLMサーバーでは、途中で終了した要求の枠へ新しい要求を投入する連続バッチ処理が広く使われる。連続バッチは固定バッチの「最長要求まで全枠がロックされる」前提を緩めるため、本論文の理論的最適性をそのまま適用できない。v2ではこの点を明確に区別し、固定バッチの理論的容量上限と、連続バッチの実測性能を別々に扱う。

## 手法

### 1. 待ち行列モデル

著者らは、要求が平均到着率λのポアソン過程で到着する単一サーバーを仮定する。待機列容量は無限とし、各要求の実行時間tは独立同分布に従う。解析の中心では、tが区間[l_min,l_max]の一様分布であると仮定する。バッチサイズBは固定で、B件集まった時点で一つのバッチが成立する。実行中のバッチへ新しい要求を追加したり、完了した要求の位置だけを途中で交換したりしない。

このモデルの固定バッチ処理率は、飽和状態で`B / E[t_batch]`と表される。t_batchは同じバッチに属するB件の実行時間の最大値である。処理率は単位時間当たりの完了要求数を表し、入力の到着率λとは異なる。待ち行列の安定条件や各要求の応答時間を評価するには、処理率だけでなく待機時間も必要になる。

理想的な固定バッチの上限は、バッチ処理時間が個々の要求の平均実行時間E[t]まで縮んだ場合の`B / E[t]`である。この上限は、途中参加を許す連続バッチ基盤の普遍的な上限ではない。理論が扱うのは**固定バッチの中で長さの不均一性を取り除くとどこまで改善するか**である。

### 2. 区画への振り分け

要求が到着すると、出力長推定器などを使ってその要求の実行時間を推定する。実行時間の範囲をk個の区間へ分けておき、推定値が含まれる区画へ要求を入れる。区画iにB件集まると、その区画だけの要求から固定バッチを作る。完成したバッチは共通の実行待機列へ入り、論文の基本設定では完成順に処理される。

k=1なら従来の固定バッチと同じで、要求の長さを区別しない。kを増やすほど同一区画内の長さのばらつきが小さくなり、最長要求待ちの無駄が減る。ただし区画を細かく分けすぎると、ある区画でB件そろうまで待つ時間が増える。低負荷や偏った到着分布では、処理率の改善と個々の要求の待機時間が対立する可能性がある。

### 3. 最適な区画境界の理論

一様な実行時間分布では、k個の区画の幅を等しくし、各区画が全要求の1/kを受け取る境界を置くと、固定バッチの期待処理時間が最小になる。境界は`l_i = l_min + i(l_max-l_min)/k`で表される。各区画のバッチ処理時間は、その区画から独立に抽出されたB件の最大実行時間の期待値で計算できる。

区画iの確率をp_i、その区画内の最大実行時間の期待値をm_iとすると、全体の期待バッチ処理時間は`Σ p_i m_i`であり、固定バッチの飽和処理率は`B / Σ p_i m_i`となる。著者らは一様分布の最大値の期待値を使い、区画境界に関する目的関数の微分と凸性から等確率区画が最適になることを示す。

区画数を増やすと各区画の幅が狭まり、同一区画内の最長要求と平均要求の差が小さくなる。極限では固定バッチの理想上限`B / E[t]`へ近づく。ただしこれは**一様分布、正確な実行時間、固定バッチ、飽和処理率**という解析条件の結論であり、実際の長さ分布や予測誤差を含む任意のLLM基盤で無条件に最適という意味ではない。

### 4. 出力長の予測誤差

実際の要求では生成するトークン数が入力時点で確定していない。真の出力長を使った振り分けは、予測器の上限性能を示す理想条件である。実用化には入力文から出力長を推定し、その推定に基づいて区画へ入れる必要がある。予測を誤ると、短い要求と長い要求が同じ区画に混ざり、最長要求待ちが増える。

論文は区画の誤分類を加えた実験と、BERT系の長さ予測器を使う実験を実施している。誤差があっても長さの近い要求をある程度まとめられれば、無分類の固定バッチより良い場合がある。しかし理想的な真の長さを使った改善率を、そのまま予測器込みの実用性能とみなしてはならない。v2ではDolly負荷の推定長と真の長さの結果を別々に報告する。

### 5. 現代の連続バッチとの位置づけ

連続バッチ処理では、生成ステップごとに完了要求を取り除き、新しい要求を投入できる。これにより固定バッチ特有の遊休が減るため、区画化の理論が対象とする損失そのものが小さくなる。v2は連続バッチの実測を強い比較対象として加え、区画化が固定バッチを大きく改善しても連続バッチに届かない条件を示した。

したがって本手法をvLLMやSGLangへ組み込むなら、既存の連続バッチ処理を置き換えるのではなく、要求の受付分類、長さ別の待機列、同時実行数の制御などに応用するのが自然である。ただしそのような統合が論文の理論と同じ倍率で改善することは検証されていない。固定バッチと連続バッチの違いを無視した比較は誤解を招く。

## 主要結果

| 条件 | 結果 | 解釈 |
|---|---:|---|
| Dolly負荷、推定長、8区画、通常の固定バッチ比 | **生成トークン処理率+150.1%** | 予測が完全でなくても固定バッチの長さ混在を抑制 |
| Dolly負荷、真の長さ、8区画、通常の固定バッチ比 | **生成トークン処理率+253.1%** | 長さ予測誤差がない理想条件の上限寄りの改善 |
| Dolly負荷、推定長8区画、連続バッチ比 | **43.0%低い** | 固定バッチの大幅改善でも連続バッチには及ばない |
| Dolly負荷、真の長さ8区画、連続バッチ比 | **19.5%低い** | 完全な長さ情報でも連続バッチが強い |
| 理論、一様分布、k区画 | **等確率区画が最適** | 固定バッチの期待最大実行時間を最小化 |
| 理論、kを増加 | **固定バッチの理想上限へ漸近** | 区画内の実行時間のばらつきを縮小 |

### 数値の読み方

推定長8区画での「+150.1%」は処理率が基準の2.501倍であることを意味し、単純な1.501倍ではない。真の長さでの「+253.1%」は3.531倍である。一方、連続バッチより43.0%低いという値は、推定長方式の処理率がその実験での連続バッチの約57%にとどまったという意味である。比較対象を固定バッチとするか連続バッチとするかで、評価は大きく変わる。

この結果は、理想条件で区画数を増やすほど固定バッチの無駄を減らせるという解析と整合するが、現実のサーバー全体での平均応答時間や末尾遅延が必ず改善することを示すものではない。各区画にB件そろうまでの待ち時間、要求の到着率、長さ推定器の計算費用も実運用では重要になる。

### 理論と実測の対応

論文の理論ではバッチの実行時間を個々の実行時間の最大値とし、出力長に比例する復号費用を抽象化している。実際のGPU推論では事前入力の計算量、KVキャッシュ容量、バッチサイズによる並列効率、生成中の要求終了などが影響する。著者らはモデルを用いた実測でこの抽象化が有用な場面を示す一方、v2では連続バッチを含めた比較によって、理論の適用範囲を明確にしている。

生成長を正確に知っている理想条件では、長さの近い要求を同じ区画へ入れやすい。実用条件ではBERT系の長さ推定器などが誤分類し、同一区画内の長さのばらつきが増える。そのため実測改善率は真の長さを使う場合より小さい。区画数を増やすだけでは、予測誤差や区画ごとの待機列の偏りを解決できない。

## 既存研究との差

連続バッチ処理は生成ステップごとに要求を入れ替えてGPUの遊休を抑える。Multi-Bin Batchingは固定バッチという制約を残したまま、**バッチに入れる要求の組合せ**を変える。Sarathi-Serveは入力事前処理を小区間へ分けて復号との干渉を調整するが、本論文は出力長のばらつきに着目する。出力長推定に基づく短い要求優先のスケジューリングは実行順序を変えるのに対し、本方式は同じ長さの要求が一緒になるようバッチ形成前の待機列を分ける。

量子化やKVキャッシュ圧縮は一要求当たりのメモリ・計算を変える。Multi-Bin Batchingはモデル演算の内容を変えず、固定バッチでの無駄を減らす。これらは直交する可能性があるが、すべてを組み合わせた場合の処理率が個別改善率の積になるわけではない。

## 限界と適用条件

第一に、理論の最適性は固定バッチ、独立同分布の実行時間、一様分布などの仮定に依存する。現実のLLM要求の生成長は長い裾や複数の山を持ち得るため、等幅の区画が常に最適とは限らない。入力長、事前処理、KVキャッシュ容量、生成停止条件、複数GPUでの並列実行も理論の中心には含まれない。

第二に、出力長は事前に分からず、推定器の誤差が区画の純度を下げる。真の長さを使う理想実験の改善率を実装可能な値として報告するのは不適切である。予測器を実行する費用、区画の境界更新、負荷の変化に対する追従も必要となる。

第三に、区画を増やすと一つの区画でバッチサイズBに達するまでの待ち時間が長くなる可能性がある。飽和処理率が高くても、低負荷での初回応答時間や高分位の待機時間が悪化する場合がある。サービス水準を重視するなら、区画ごとの待機期限や小さいバッチでの先行実行を別途設計しなければならない。

第四に、現代の連続バッチ方式は固定バッチの長さ混在問題をそもそも緩和する。v2のDolly負荷では区画化した固定バッチは連続バッチより低い処理率だった。したがって「LLM推論の処理率に対して漸近最適」という主張は、**論文が定義した固定バッチモデルの内部**に限定して解釈するべきである。
