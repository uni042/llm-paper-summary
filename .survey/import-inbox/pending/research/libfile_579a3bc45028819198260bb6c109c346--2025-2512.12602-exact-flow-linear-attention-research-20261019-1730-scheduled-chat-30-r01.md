# 厳密流線形注意（EFLA）：デルタ則の連続時間解を利用した状態更新

## 概要

大規模言語モデルの長文脈推論では、通常のソフトマックス注意が履歴長に応じて過去の鍵・値を読み込むため、計算量とメモリ転送が問題になる。線形注意は過去の鍵と値を固定次元の行列状態に畳み込み、次のトークンの生成を履歴長に依存しない状態更新へ変える。しかし、デルタ則（delta rule）に基づく線形注意では、古い記憶を消して新しい対応を注入する更新を離散的な勾配降下として扱うため、鍵ベクトルの大きさや更新係数によって状態の安定性が変わる。

厳密流線形注意（Exact Flow Linear Attention、EFLA）は、デルタ則更新が、入力を一つのトークン区間で固定した連続時間の微分方程式を前進オイラー法（explicit Euler）で一歩近似したものと解釈できることを示す。その上で、鍵ベクトルの外積が階数1であるという構造を利用し、行列指数関数を一般的な高コスト計算で評価せずに、閉形式の更新係数を得る。**線形注意の再帰状態・計算次数・パラメータ数を保ち、離散化誤差を取り除く**ことが中心的な貢献である。

論文の2026年9月28日改訂第5版を確認した。3億4千万パラメータの言語モデルを80億トークンで学習した条件では、従来のDeltaNetに対してWikitext困惑度が38.09から35.26、LAMBADA困惑度が96.26から79.97、常識推論平均正答率が42.2%から44.1%に改善した。13億パラメータ・500億トークンの条件でも平均正答率が50.5%から51.8%へ上がった。一方、**推論サーバのトークン生成速度が高速化したことを示す論文ではない**。訓練時の処理量はほぼ同等で、品質と安定性の改善が主な実証結果である。

## 問題設定と従来方式

### ソフトマックス注意と線形注意の相違

通常の因果注意は、新しい問い合わせベクトルが過去の鍵ベクトル群と類似度を計算し、ソフトマックス正規化された重みで値を加重平均する。入力処理では長さに対して二乗の注意計算が発生し、復号では履歴の鍵値キャッシュを繰り返し読む。線形注意は過去の鍵・値の相関を行列状態 `S_t` に累積し、`o_t = S_t^T q_t` で出力を求める。状態の形状が固定であるため、履歴全体の鍵値キャッシュを毎回読む必要がない。ただし、この圧縮された状態が必要な情報を維持できるかは更新則に依存する。

最も単純な加算型更新 `S_t = S_{t-1} + k_t v_t^T` は、新しい鍵と値の関係を記憶に加える一方、古い関係を明示的に修正しない。長い系列では複数の関係が干渉する。デルタ則型のDeltaNetは、現時点の鍵 `k_t` を与えたときに状態から読み出される値 `S_{t-1}^T k_t` が、目標値 `v_t` に近づくように誤差補正する。これにより、古い記憶を一部消去して新しい対応を入れる更新が可能になる。

従来のデルタ則更新は `S_t = (I - β_t k_t k_t^T) S_{t-1} + β_t k_t v_t^T` と書ける。`β_t` は更新率、`k_t` は鍵、`v_t` は値、`I` は単位行列である。鍵方向の成分にかかる係数が `1 - β_t ||k_t||²` となるため、更新率と鍵ノルムの積が大きいと、符号反転や過大な更新が起こりうる。通常の更新式だけを見れば単純な勾配降下だが、EFLAはこの不安定さを連続時間の数値積分誤差として定式化する。

### 連続時間モデルへの対応

各トークンの区間内では現在の鍵と値を一定とみなす零次ホールド（zero-order hold、ZOH）を置き、`A_t = k_t k_t^T`、`b_t = k_t v_t^T` と定義する。すると状態行列の連続時間方程式は `dS/dτ = -A_t S + b_t` となる。この微分方程式に対して時間幅 `β_t` の前進オイラー法を適用すれば、上記のDeltaNet更新がそのまま得られる。従来のデルタ則は、区間内の真の連続時間軌道を求めずに、区間始点の傾きで一歩進めた近似に相当する。

ただし、この解釈は**ZOHという選んだ連続時間モデルに対して厳密**という意味である。実世界の全ての注意演算や元のソフトマックス注意と等価になることを主張していない。モデル化の前提と数値積分の精度を区別する必要がある。

## 手法：階数1行列の厳密流

### 1. 行列指数関数の一般解を簡約する

区間内で `A_t` と `b_t` が固定された一次線形微分方程式の厳密解は、`S_t = exp(-β_t A_t) S_{t-1} + ∫[0,β_t] exp(-(β_t-τ)A_t)b_t dτ` である。一般的な行列指数関数を直接計算する方法は状態次元に対して高コストだが、この場合は `A_t = k_t k_t^T` という外積なので階数が1しかない。

鍵の二乗ノルムを `λ_t = k_t^T k_t` とおくと、`A_t² = λ_t A_t`、さらに `A_t^n = λ_t^{n-1} A_t` が成立する。したがって行列指数の級数展開は、`exp(-β_t A_t) = I - [(1 - exp(-β_t λ_t))/λ_t] A_t` に畳み込める。積分項についても `A_t b_t = λ_t b_t` を利用すれば、`[(1 - exp(-β_t λ_t))/λ_t] b_t` に簡約できる。複雑な行列指数と積分が、鍵ノルムから計算する一つのスカラー係数へ帰着する。

ここで `α_t = (1 - exp(-β_t λ_t))/λ_t` と定義すると、最終更新は `S_t = (I - α_t k_t k_t^T) S_{t-1} + α_t k_t v_t^T` となる。さらに実装上は `S_t = S_{t-1} + α_t k_t (v_t^T - k_t^T S_{t-1})` として、DeltaNetと同じ階数1の補正を実行できる。変更されるのは更新係数を `β_t` から `α_t` に置き換える点であり、行列状態の大きさや線形時間の再帰構造は変わらない。系列長 `L`、状態の一辺の次元 `d` に対して計算次数は `O(Ld²)` のままである。

### 2. 更新率と鍵ノルムによる安定化

`β_t ≥ 0` のとき、鍵方向の同次遷移係数は `exp(-β_t λ_t)` であり、0より大きく1以下になる。鍵に直交する方向の係数は1である。このため、厳密流の同次状態遷移は拡大せず、鍵方向の記憶だけを指数関数的に減衰させる。前進オイラー更新の `1 - β_t λ_t` は、`β_t λ_t` が大きいと負になったり絶対値が1を超えたりするのに対し、厳密流はこの特定の数値的不安定性を避けられる。

`β_t λ_t` が小さい領域では `α_t = β_t - (β_t² λ_t)/2 + O(β_t³ λ_t²)` となり、EFLAとDeltaNetの差は高次項だけになる。鍵が正規化されている、または更新率が十分小さい条件では、品質改善が小さくなりうる。逆に鍵ノルムが大きい条件では、従来の離散化誤差が増え、厳密流の利点が現れやすい。したがって、単に「指数関数を使えば必ず精度が上がる」と一般化するのではなく、鍵の尺度と更新率の組合せが重要である。

論文付録の実装設定では、鍵の二乗ノルムがゼロに近い場合にゼロ除算を避けるため `ε=10^-12` の下限を使い、小さな指数での桁落ちを避けるため `expm1` を用いる。`α_t` は数学的には `λ_t→0` の極限で `β_t` に近づくため、数値実装ではこの連続性を壊さないことが重要になる。論文では鍵に `√d` の尺度を与えた場合が良好で、鍵をそのまま使う、またはL2正規化した場合はDeltaNetに近い結果だったと報告する。これらは精度を左右する実装条件であり、再現時に省略すべきではない。

### 3. 塊単位の並列計算を維持する

線形注意の利点はトークンごとの逐次更新だけでなく、学習時に複数トークンをまとめて処理できる点にもある。DeltaNetでは、階数1変換の積をWY表現やUT変換にまとめ、チャンク内の依存関係を効率的な行列積へ変換する。EFLAの状態更新は `β_t` を `α_t` に置き換えても同じ階数1の形なので、この並列化構造を再利用できる。

論文の式(16)～(26)では、チャンク内の遷移積 `P` と書込み項 `H` を展開し、状態更新を `S[t+1] = S[t] + K[t]^T(U[t]-W[t]S[t])` と表す。`W` と `U` は、更新係数を組み込んだ下三角の依存解決によって得られる。重要なのは、単に同じ計算次数を主張するだけでなく、既存の行列積中心のGPU実装が利用するデータフローを保てる点である。ただし、既存のどの推論ランタイムでも無変更で使えることを意味しない。対象モデルがデルタ則型線形注意を備えていることと、実装が係数計算を置換できることが前提となる。

### 4. ゲート付きデルタ則への拡張

実用的な系列モデルでは、鍵に沿った補正だけでなく、状態全体の減衰を制御するゲートを持つことがある。論文はゲート付きDeltaNetについても、ゲートの一様減衰項と鍵外積の階数1項を組み合わせた線形微分方程式を構成し、厳密流に対応する更新を付録Fで導く。これにより、非ゲート型に限らず、ゲート付き構成にも連続時間解の考え方を適用できる。

ゲート付き方式の更新係数は非ゲート型と同じ単純な置換だけでは表せないため、両者を混同して実装してはならない。論文のゲート付き評価では、通常のGated DeltaNetより良い困惑度と平均正答率を示しているが、全てのゲート構造に同じ式が適用できるとは確認されていない。状態減衰と鍵方向の書込みをどのように分離して解くかが拡張の要点である。

## 評価：設定・比較対象・定量結果

### 言語モデルの学習条件

言語モデル評価は8台のA100 80GB GPUを使用し、3億4千万（340M）および13億（1.3B）パラメータのモデルで行った。340MはSlimPajamaの80億トークン、1.3Bは同じ系列の500億トークンを学習し、Mistralのトークナイザを使用した。最適化はAdamW、ピーク学習率 `3×10^-4`、重み減衰0.1、勾配クリップ1.0。340Mの全体バッチは約100万トークン、1.3Bは約200万トークンである。比較対象にはDeltaNet、Gated DeltaNet、Mamba-2が含まれる。困惑度はWikitextとLAMBADA、ゼロショット正答率はPIQA、HellaSwag、WinoGrande、ARC-Easy/Challenge、BoolQ、OpenBookQA、SciQなどで測定した。

| 規模・比較 | Wikitext困惑度（小さいほど良い） | LAMBADA困惑度（小さいほど良い） | 常識推論平均正答率 |
|---|---:|---:|---:|
| 340M DeltaNet | 38.09 | 96.26 | 42.2% |
| 340M EFLA | **35.26** | **79.97** | **44.1%** |
| 340M Gated DeltaNet | 34.93 | 72.46 | 43.9% |
| 340M Gated EFLA | **34.28** | **69.37** | **44.8%** |
| 1.3B DeltaNet | 18.38 | 17.29 | 50.5% |
| 1.3B EFLA | **18.30** | **16.54** | **51.8%** |

340MのDeltaNetとEFLAの比較では、Wikitext困惑度が2.83低下、LAMBADA困惑度が16.29低下、平均正答率が1.9ポイント上昇した。ゲート付き比較ではWikitextが0.65低下、LAMBADAが3.09低下、平均正答率が0.9ポイント上昇した。1.3Bでは困惑度改善が小さくなる一方、平均正答率は1.3ポイント上昇した。モデル規模が増えれば改善率も単調に増えるとは言えない。特に340Mの一部個別課題では、EFLAがDeltaNetより劣る例があるため、平均だけで全面的な勝利と扱わない。

### 攪乱耐性と学習率感度

逐次MNISTでは、28×28画素を長さ784の系列に並べ、隠れ次元64の線形注意分類器をAdamW・バッチ128で学習した。画素のランダム欠落、入力強度の拡大、ガウス雑音という三種類の攪乱を与え、DeltaNetとEFLAの正答率の低下を比較した。入力強度が増えるとDeltaNetの正答率が急激に落ちる条件がある一方、EFLAは劣化が緩やかである。雑音と欠落に対しても同じ傾向が報告される。これは鍵方向の同次遷移が非拡大となるという理論的性質と整合するが、実験は画像系列分類であり、直接LLMの長文脈生成品質を測定したものではない。

学習率は `1×10^-4`、`3×10^-4`、`1×10^-3`、`3×10^-3`、`1×10^-2` の5条件で比較している。EFLAは特に大きな学習率でも高い正答率を保ち、DeltaNetが頭打ちになる条件で改善を示す。ただし、図から読み取れない正確な数値を捏造せず、定性的な傾向として扱う。逐次MNISTの実験は状態遷移の性質を分離して検証するものであり、大規模モデルの学習率を無条件に引き上げてよい根拠ではない。

### 合成記憶課題と訓練処理量

機構設計用合成課題群（Mechanistic Architecture Design、MAD）では、圧縮、曖昧再生、文脈内再生、記憶、雑音付き再生、選択コピーの6課題を評価した。平均得点はDeltaNetの65.7%に対してEFLAが66.4%であり、差は**0.7ポイント**にとどまる。記憶課題では29.9から32.5へ改善するが、改善幅は課題によって異なる。合成課題の小さな差を「長文脈LLMで大幅高速化」と読み替えることはできない。

訓練処理量は、系列長とバッチをそれぞれ2K×8、4K×4、8K×2、16K×1として比較した。論文の図4ではDeltaNetが順に39.7、39.6、39.6、38.5千トークン/秒、EFLAが40.0、39.9、40.1、38.0千トークン/秒と示される。最長の16K条件ではEFLAが38.0でDeltaNetの38.5より**約1.3%遅い**。他の条件ではEFLAがわずかに速いが、測定変動や環境の違いを超える一般的な高速化と断定できない。正確な主張は「訓練時の処理量がほぼ同等」である。

## 既存研究との差分と新規性

加算型線形注意は古い記憶を消去しない。DeltaNetはデルタ則で上書きするが、離散的な更新を用いる。Gated DeltaNetやKimi Delta Attentionなどは減衰ゲートや更新係数を工夫して記憶の干渉を抑える。EFLAはこれらと異なり、**デルタ則を連続時間系の数値積分として再解釈し、階数1構造から厳密な区間解を求める**という数学的な導出を新規性の中心に置く。

この厳密性は、ソフトマックス注意を数学的に再現するという意味でも、学習済みの任意のモデルへ後付けで適用できるという意味でもない。既存のデルタ則型注意を実装するモデルについて、学習・推論時の状態更新係数を変更する設計であり、重みと内部状態の学習分布への影響がある。元のモデルを再学習せず置き換えても同じ品質になるかは、論文の主要評価では実証されていない。

## 限界・負の結果・再現性

論文付録Aは、有限精度演算、最適化過程、学習データの制約、線形注意とソフトマックス注意の近似差が残ることを明示する。除去されるのは、選択したZOH連続時間方程式に対する**前進オイラーの局所離散化誤差**であり、あらゆる誤差を消すわけではない。鍵の尺度によってDeltaNetとの差が縮むことも付録Cに記載される。鍵のL2正規化が強い条件では、数式上の差があっても観測品質の差は小さくなりうる。

モデル規模は最大1.3Bで、現在の大規模実運用モデルより小さい。長文脈サービングの実機ベンチマーク、複数要求のスケジューリング、GPUメモリ占有、生成トークン毎秒、初回トークン遅延、量子化・混合精度との相互作用、8B以上のモデルへの外挿は検証されていない。漸近的に線形時間であることと、特定のGPUで高速であることは異なる。ゲート付き構成の閉形式を実装する場合も、数値安定性を含めて別途検証が必要となる。

公開実装は著者の `declare-lab/EFLA` を確認した。2026年10月19日時点で公式READMEが明示する起動手順は `python mnist.py` による逐次MNISTの学習・評価であり、論文の340M・1.3B言語モデルの全実験を再現できる完成パイプラインが公開されているとは確認できない。READMEの説明を越えて「全ベンチマークが再現可能」とは記述しない。実装にあたっては、更新係数の `expm1` による安定計算、ゼロ近傍の鍵ノルム処理、状態行列の向き、ゲート付き変種の別導出、チャンク並列化を重点検査する。

## 実務上の位置付け

推論基盤の観点では、EFLAはキャッシュのオフロード、連続バッチ化、投機的復号、GPU割当てを直接改善する技術ではなく、**デルタ則型線形注意を使うモデルの状態更新機構**である。したがって、通常のソフトマックス注意を用いるモデルのKVキャッシュをそのまま置き換えるものではない。一方、DeltaNet系やハイブリッド注意モデルが広く利用されれば、履歴長に対して固定次元の状態を使いながら品質を保つ設計の一候補になる。

小規模GPUでの実装評価を行うなら、まず既存のDeltaNet型実装を基準にして、同一学習条件・同一鍵尺度で困惑度、生成品質、GPU時間、トークン当たり状態更新時間を比較すべきである。訓練時に改善した正答率がそのまま推論高速化へつながるとは限らないため、性能と品質を別々に計測する必要がある。
