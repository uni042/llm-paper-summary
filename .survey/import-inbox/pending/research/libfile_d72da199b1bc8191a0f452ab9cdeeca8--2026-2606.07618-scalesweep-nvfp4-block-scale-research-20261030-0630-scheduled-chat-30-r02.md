# ScaleSweep：NVFP4のFP8ブロックスケールを誤差最小化で選ぶ軽量PTQ

## 概要

ScaleSweepは、NVIDIA Blackwell世代でハードウェア対応するNVFP4の重み・活性値・KVキャッシュ・query状態の量子化について、**16要素ブロックのFP8スケールの選び方**を改善する後学習量子化（PTQ）手法である。NVFP4はFP4 E2M1で数値を保存し、ブロックごとにFP8 E4M3のスケール、さらにテンソル全体のグローバルスケールを持つ。従来のAbsMaxはブロック最大絶対値からスケールを決めるため簡単だが、すべての値の量子化誤差を最小化するとは限らない。

著者は、ブロックの量子化再構成誤差をMSEまたは重み付きMSE（WMSE）で評価し、表現可能なFP8スケール候補から最良のものを選ぶ。FP8の正の有限値は126候補程度と限られるため全探索も不可能ではないが、全ブロックで行うと費用がかかる。ScaleSweepはFP4量子化の性質から最適スケールが存在する範囲を導き、基準スケールのFP8ビット列の近傍だけを探索する。

Llama-3.1-8B-Instructの重み・活性・KV・queryをすべてNVFP4にするWAKVQ設定では、GPTQ＋AbsMaxの五タスク平均64.87、BF16の71.71に対し、GPTQ＋ScaleSweepは67.35まで回復する。これはBF16比約93.9%の平均性能回復である。一方、量子化演算子単体のTriton実測では、MSE版はvLLM既定とほぼ同じ遅延だが、WMSE版は約1.37倍の遅延である。**モデル全体の生成速度が1.37倍遅いという意味ではない**。一次論文 <https://arxiv.org/html/2606.07618> の方法・表3〜9・限界を確認した。

## 問題設定：4ビット値よりスケールの初期化が効く

NVFP4では、16個の値を一つの小ブロックとし、各値をFP4 E2M1へ丸める。ブロックのスケールはFP8 E4M3で保存され、テンソル全体のグローバルスケールと組み合わせて値を復元する。細かなブロック単位のスケールは、重みや活性値の局所的な分布の違いを吸収しやすいが、スケール自体がFP8へ量子化されるため、連続値の最適スケールをそのまま使えるわけではない。

AbsMaxは最大絶対値がFP4の最大値へ収まるようにスケールを決める。大きな外れ値を保護できる一方、小さな値の丸め誤差を十分に減らせない場合がある。4/6方式は最大値をFP4の有効な別レベルへ合わせることで改善するが、ブロックの値の分布や重要度を直接最小化するわけではない。ScaleSweepはスケール候補ごとに量子化・復元した値を計算し、MSEまたはWMSEを直接評価して最良候補を選ぶ。

量子化対象は重みだけではない。活性値、KVキャッシュ、query状態まで低ビット化すると、複数箇所の誤差が累積し、言語モデルの性能が大きく悪化することがある。特にKVとqueryは注意スコアへ直接影響するため、重みだけを4ビットにする設定より厳しい。ScaleSweepは、同じスケール選択機構をこれらのテンソルへ適用し、量子化の難度が高まったときにも品質を回復することを狙う。

## 手法

### 1. NVFP4の二段階スケーリング

NVFP4は各要素をFP4 E2M1へ量子化する前に、グローバルスケールと16要素ブロックのFP8スケールで正規化する。復元ではFP4値に両スケールを掛ける。グローバルスケールはテンソル全体のダイナミックレンジを確保し、ブロックスケールは局所分布に適合する役割を持つ。著者はグローバルスケールを固定した後、ブロックごとの最適化を独立に行えることを利用する。

グローバルスケールは、テンソル最大絶対値を`256×6`で割る規則を用いる。これは既存の4/6系設定に基づき、FP8スケールとFP4値の表現範囲を確保するためである。グローバルスケールを最適化する研究ではなく、**固定したグローバルスケールの下で各ブロックのFP8スケールを最適化する**ことが中心である。論文図2ではグローバルスケールの選択を変えても正規化MSEの差が比較的小さいことを確認する。

### 2. MSEとWMSEの目的関数

MSE版は、元の16要素ベクトルと、FP4量子化してFP8スケールで復元したベクトルの二乗誤差和を最小化する。全要素を同じ重要度として扱うため、スケール探索の目的関数は簡単である。WMSE版は要素ごとに重みを付け、重要な値の誤差をより強く罰する。GPTQのHessian対角成分など、出力感度を表す情報を重みとして利用できる。

入力は元のブロック値、グローバルスケール、候補FP8スケール、WMSEの場合は重要度重みである。出力は最小誤差を与えるFP8スケールである。候補ごとにFP4へ丸めた値を復元し、損失を比較する。スケールはFP8の離散値から選ぶため、連続値の最適スケールを求めて最後にFP8へ丸める方式より、実際の量子化後の誤差を直接最適化できる。

MSEとWMSEの違いは重要である。MSEで誤差が小さくても、下流モデルの出力へ敏感な重みを大きく変化させれば品質が悪化する場合がある。WMSEはその感度を反映しやすいが、重要度の推定と追加計算が必要である。論文の結果でもWMSE版が多くのタスクで良い一方、すべての設定でMSE版を上回るわけではない。

### 3. FP8ビット列の局所探索範囲

FP8 E4M3の正の有限値は限られているため、全候補を試すことも理論上は可能である。しかし全テンソルの全16要素ブロックで126候補を試すと、量子化演算子の費用が大きくなる。著者はFP4 E2M1の丸め区間とスケールの関係を分析し、最適なFP8スケールがAbsMax由来の基準スケールから大きく離れないことを示す。

MSEの場合は基準FP8スケールのビット列を中心に`[-3,+7]`、WMSEの場合は`[-8,+7]`の範囲を探索する。WMSEでは最大絶対値の要素の重要度が非常に小さいと最適スケールがより小さくなり得るため、MSEより広い下側の探索を採用する。上限はFP4の量子化特性に基づく理論・計算機支援分析で導き、下限の一部は実務上の設定を含む。したがって全候補の完全な一般証明と、実用的な候補制限を区別する。

この狭い範囲を使うことで、全FP8候補を列挙せず、少数のスケールだけを評価できる。ブロックごとに独立に処理できるため、GPU上で並列化しやすい。著者はMSE用のScaleSweepMSEと、WMSE用のScaleSweepを別々に実装し、精度と演算子遅延を比較する。

### 4. RTN/GPTQとの統合

ScaleSweepは重みをFP4へ丸めるPTQの一部として組み込める。RTN（round-to-nearest）では、スケールを選んだ後、各重みを最も近いFP4値へ丸める。GPTQではHessianを使って重みの量子化誤差を補正し、入力チャネルをHessian対角成分の降順に並べ替える静的再順序付けを使う。ScaleSweepはこのパイプラインのスケール初期化を置き換える。

重みだけでなく活性値、KVキャッシュ、query状態にも同じスケール選択を適用できる。量子化の設定はWA（重み＋活性）、WAKV（さらにKV）、WAKVQ（さらにquery）に分ける。量子化対象が増えるほどモデルの数値誤差が増え、精度回復が難しくなる。ScaleSweepの評価は、量子化範囲を広げた場合にもスケール選択の利点が残るかを確認する設計である。

## 評価設定

| 項目 | 条件 |
|---|---|
| モデル | Llama-3.1-8B-Instruct、Llama-3.2-3B-Instruct、Qwen3-8B、Qwen3-4B。Qwen3は非thinkingモード |
| 量子化 | NVFP4 E2M1値、16要素ブロック、FP8 E4M3スケール |
| 設定 | WA、WAKV、WAKVQ |
| 手法 | RTNとGPTQ、AbsMax、4/6、ScaleSweepMSE、ScaleSweep |
| 校正 | RedPajamaから128系列×2048トークン。別実験でGSM8K学習splitを利用 |
| 品質評価 | MMLU Pro 5-shot、GSM8K 8-shot CoT、IFEval 0-shot、HellaSwag 0-shot、WinoGrande 0-shot |
| モデル品質の実行 | NVIDIA L40上の**模擬量子化** |
| 演算子速度 | NVIDIA RTX PRO 6000 Blackwell、PyTorch 2.9.0、Triton 3.5.0、vLLM 0.13.0 |
| 速度測定対象 | 隠れ次元8192、バッチ128〜32768のNVFP4量子化演算子単体 |

品質の模擬量子化を行ったL40と、NVFP4の演算子速度を測ったBlackwell GPUは別である。前者は実際のNVFP4 Tensor Coreを使ったエンドツーエンド生成速度ではない。後者はモデル全体ではなく量子化演算子のマイクロベンチマークである。二つの結果を組み合わせて「LLMの生成速度が何倍になった」と算出しない。

## 主要結果：Llama-3.1-8Bの強い量子化

表3のLlama-3.1-8B-InstructはBF16の五タスク平均71.71である。WAKVQ、RTN＋AbsMaxは64.48、RTN＋4/6は65.70、RTN＋ScaleSweepMSEは66.23、RTN＋ScaleSweepは66.98へ改善する。GPTQではAbsMax64.87、4/6 66.09、ScaleSweepMSE66.98、ScaleSweep67.35である。WMSE版がこの設定では最も良いが、BF16の71.71へ完全には戻らない。

| WAKVQの方式 | 五タスク平均↑ | BF16比回復率↑ | GSM8K↑ |
|---|---:|---:|---:|
| BF16（量子化なし） | 71.71 | 100% | 84.69 |
| RTN＋AbsMax | 64.48 | 89.93% | 69.90 |
| RTN＋4/6 | 65.70 | 91.62% | 74.22 |
| RTN＋ScaleSweepMSE | 66.23 | 92.35% | 74.98 |
| RTN＋ScaleSweep | 66.98 | 93.40% | 77.33 |
| GPTQ＋AbsMax | 64.87 | 90.46% | 73.16 |
| GPTQ＋4/6 | 66.09 | 92.16% | 76.57 |
| GPTQ＋ScaleSweepMSE | 66.98 | 93.41% | 78.24 |
| GPTQ＋ScaleSweep | 67.35 | 93.92% | 77.33 |

WAKVQではquery状態まで量子化するため、WAやWAKVより品質低下が大きい。ScaleSweepは基準方式より数ポイント回復するが、残り約6%の平均性能差がある。GSM8Kは特に感度が高く、RTN＋AbsMaxの69.90からRTN＋ScaleSweepの77.33へ改善する一方、BF16の84.69には届かない。推論能力の完全保持ではなく、厳しい量子化下での損失縮小と解釈する。

## 主要結果：モデルと量子化範囲による差

WA（重み＋活性）では、Qwen3-8BのRTN＋ScaleSweepが五タスク平均75.22、BF16の75.60に対して99.50%の回復率を報告する。WAKVへKV量子化を追加しても、多くのモデル・RTN/GPTQ設定でAbsMaxや4/6に対し1〜2ポイント程度の回復率改善が見られる。WAKVQのLlama-3.2-3BではRTN＋ScaleSweepが平均60.97、BF16の65.27に対し93.41%、GPTQ＋ScaleSweepが61.17で93.72%だった。

ただし、すべてのモデル・設定でWMSE版がMSE版より良いわけではない。Llama-3.1-8BのWA、RTNではScaleSweepMSEが平均69.85、WMSE版ScaleSweepが68.86で、MSE版が高い。GPTQではWMSE版69.99がMSE版69.18を上回る。これは局所的な量子化誤差を最小化する目的関数と、下流タスクの正答率が完全に一致しないことを示す。

校正データの選択も重要である。表4ではLlama-3.1-8BのGPTQ＋ScaleSweepについて、RedPajamaを使う場合とGSM8K学習splitを使う場合を比較する。WAのGSM8Kは81.50→83.47、WAKVは79.98→81.88、WAKVQは77.33→80.21へ改善する。タスクに近い校正データを使えばそのタスクの精度が上がる可能性があるが、他の用途への一般性やデータリークを含む評価設計には注意が必要である。

## 量子化誤差と演算子オーバーヘッド

図4と付録図6は、各層の量子化誤差を連続FP32の最適ブロックスケールと比較する。ScaleSweepはAbsMaxと4/6より小さなMSE/WMSEを示し、多くの層で最適FP32スケールをFP8へ丸めた方式よりも良い。これは、連続値の最適解を最後に離散FP8へ丸めるより、離散候補を直接評価することの利点を示す。ただし局所誤差の改善がすべての下流タスクで同じ割合の改善になるわけではない。

RTX PRO 6000 Blackwell上の表7では、vLLM既定演算子のバッチ128で0.010ms、32768で0.502msに対し、ScaleSweepMSEはそれぞれ0.010ms、0.502msでほぼ同じ。WMSE版ScaleSweepは0.012ms、0.689msで、32768では約1.37倍の演算子遅延となる。中間のバッチ4096では既定0.072ms、MSE版0.072ms、WMSE版0.099msである。

| バッチ | vLLM既定ms↓ | ScaleSweepMSE ms↓ | ScaleSweep ms↓ |
|---:|---:|---:|---:|
| 128 | 0.010 | 0.010 | 0.012 |
| 512 | 0.016 | 0.017 | 0.021 |
| 4096 | 0.072 | 0.072 | 0.099 |
| 8192 | 0.135 | 0.134 | 0.185 |
| 32768 | 0.502 | 0.502 | 0.689 |

著者はWMSE版の約1.37倍を実用上小さなオーバーヘッドと解釈するが、量子化演算子単体としては37%の増加である。モデル全体の生成時間に占めるこの演算子の割合が小さければ影響は限定的かもしれないが、エンドツーエンドのTTFTやTPOTは直接測定されていない。演算子のメモリ律速性やカーネル融合の余地も、将来の最適化可能性であって既に実現した速度改善ではない。

## 既存研究との差

AbsMaxは最大絶対値に基づく簡単なスケール選択で、4/6はFP4の量子化レベルをより有効に使う工夫である。ScaleSweepは、量子化後のMSE/WMSEを**FP8の離散候補で直接比較**する。FP4の量子化区間を分析して探索範囲を狭めるため、単純な全FP8候補探索より費用を抑えられる。これはGPTQやRTNと排他的な方式ではなく、スケール初期化の部品として組み込める。

QuaRotやSpinQuantは重み・活性値の分布を回転して外れ値を抑える。SmoothQuantは重みと活性値のスケールを移す。ScaleSweepはテンソルの分布を大きく変換するのではなく、既に選んだNVFP4形式のブロックスケールを改善する。したがって改善対象は低ビット量子化の**スケール選択**であり、新しいFP4データ型や新しいTransformer演算子を提案するものではない。

## 限界・再現上の注意

第一に、対象はNVFP4のFP4 E2M1値とFP8 E4M3ブロックスケールである。整数4ビット、GGUFのQ4_K、MXFP4など別の量子化形式へ同じビット列境界を適用できるとは限らない。16要素ブロック、FP8表現範囲、グローバルスケールの規則に依存する。

第二に、品質評価はL40上の模擬量子化であり、Blackwellの実NVFP4 Tensor Coreを使ったエンドツーエンド推論ではない。Blackwellの実測は量子化演算子単体で、モデル全体の生成速度・GPUメモリ容量・バッチ形成・長文脈KVの実効処理率を測ったものではない。WMSE版の演算子遅延は既定より約37%高く、無条件に「追加費用ゼロ」とは言えない。

第三に、スケール選択の局所目的関数は下流の正答率と完全には一致しない。WAのLlama-3.1-8B、RTNではMSE版がWMSE版より高い平均スコアであり、探索範囲を狭めた方が一部の設定で良いこともある。局所MSEを最小化することが常に最良の生成品質を保証するわけではない。

第四に、校正データの分布が結果に影響する。RedPajamaの128系列×2048トークンを使った基準と、GSM8K学習splitを使った場合では数学推論の結果が変わる。専門領域、長文脈、マルチモーダル入力など別の分布で同じ改善が得られるかは未検証である。

第五に、モデルはLlamaとQwenの3B〜8B級が中心で、巨大MoE、70B級、複数GPUの分散サービングを網羅しない。WAKVQで93%以上の回復率は重要だが、BF16から残る品質差があり、特に数学推論の感度を無視できない。品質と演算子費用を用途別に測る必要がある。

## 総括

ScaleSweepは、NVFP4のブロックスケールを最大値から機械的に決める代わりに、FP8の離散候補の中からMSE/WMSEが小さい値を選ぶ。FP4の量子化特性から探索範囲を狭めることで、重み・活性・KV・query状態まで4ビット化した厳しい条件でも品質回復を改善する。Llama-3.1-8BのWAKVQではGPTQ＋AbsMaxの平均64.87から67.35へ改善するが、BF16の71.71には届かない。Blackwell上のMSE版は量子化演算子の遅延が既定とほぼ同じで、WMSE版は約1.37倍である。エンドツーエンドの生成高速化を測った研究ではなく、**NVFP4 PTQの精度・局所演算子費用を改善する部品**として位置付ける。
