# NAtS-L：トークン単位でソフトマックス注意と線形注意を学習選択する混成モデル

## 概要

NAtS-L（Neural Attention Search Linear）は、従来の「ある層はソフトマックス注意、別の層は線形注意」という固定的な混成構成を、**同じ層の中で入力トークン塊ごとに注意演算を選択する構成**へ拡張した研究である。線形注意は過去の鍵・値（KV）を固定サイズの状態へ圧縮できるため長文脈で省メモリだが、過去の細かい情報を任意に取り出す能力には制約がある。一方、ソフトマックス注意は過去のKVを保持して柔軟に検索できるが、文脈長に応じて計算量とKVメモリが増える。

提案法は、各トークン塊の特徴から、その塊を長期検索可能なKVとして残すか、線形注意の状態に集約するかを学習する。線形注意にはGated DeltaNet（GDN）を使い、二つの注意経路の出力を正規化・重み付けして合成する。800M規模での学習実験では、固定的なGDN混成モデルの検索6課題平均37.30に対し、NAtS-L Hybridは45.07を達成した。ただし一般常識課題の平均は51.52対51.41で、すべての評価で勝つわけではない。

この手法は既存の大規模モデルへ単純に後付けする推論時の枝刈りではなく、**学習時から注意経路の選択をモデル重みと共同最適化する新しいモデル構造**である。推論の導入可否を考える際は、この学習前提と塊単位の判定・巻戻し処理を理解する必要がある。

## 問題設定

通常のソフトマックス注意は、文脈長`L`に対して事前処理の注意計算が概ね二次、自己回帰復号では過去のKVを読む費用と保持メモリが概ね一次で増える。線形注意は過去情報を固定サイズの状態へ集約するため、復号の保持メモリを一定に近づけられるが、検索に必要な個々のトークンの情報を状態へ押し込めると失われる可能性がある。

従来の混成モデルは、例えば線形注意3層に対してソフトマックス注意1層のように、層単位で注意演算を固定する。この構成は線形注意だけのモデルより検索能力が高い場合があるものの、ソフトマックス層では入力全体のKVを保持し続けるため、長文脈の律速が残る。NAtS-Lは、過去のトークンをすべて同じ方式で保存する必要はないと考える。短期的な影響しかない塊は線形状態に畳み込み、後から参照される重要な塊だけをソフトマックス側へ残す。

手動の疎注意マスクでは、長期検索に必要な位置を誤って捨てることがある。NAtS-Lは注意の種類を固定規則で割り当てず、言語モデルの学習損失を通じて自動的に選ぶことを狙う。選択はトークンごとに完全独立ではなく、実装上は64トークンなどの塊を単位とする。

## 手法

### 注意演算の統一的な見方

通常のソフトマックス注意は、問い合わせ`Q`と鍵`K`の内積を指数正規化し、値`V`を重み付き集約する。線形注意は過去のKVを状態`S_t`に畳み込み、問い合わせと状態の積で出力を求める。後者は再帰的な更新で表せるが、GPUで並列化するためには塊内を並列処理し、塊間で状態を受け渡す塊単位処理（Chunk-wise Processing）が有効である。

NAtS-Lは、両方式が塊単位で処理できることを利用する。入力系列を長さ`C`の塊に分割し、各塊をソフトマックス注意の長期記憶側に置くか、線形注意の状態更新側に置くかを選ぶ。ソフトマックス側は選ばれた塊のKVだけを保持・参照し、線形側は選ばれた塊で状態を更新する。二つの経路は同じ`Q,K,V`射影を共有し、パラメータ増加を抑える。

### 注意種類を選ぶ得点層

各塊の入力特徴を平均プーリングし、線形射影で注意種類ごとの得点を計算する。塊`t`の得点は`score_t=W_score Mean(X_[t])`であり、得点最大の種類をその塊へ割り当てる。ソフトマックスと線形注意に対応する列方向のマスクを構成し、各演算が自分に割り当てられた塊のKVだけを利用する。重要な過去塊はソフトマックス側に残るため、後の問い合わせがその位置を直接参照できる。

線形注意側のGDNは、過去状態を減衰させつつ新しい鍵・値で更新する。ソフトマックス側へ割り当てられた塊についても線形状態には減衰を適用し、長期間使われない情報が残り続けないようにする。両方の経路は塊内の相関を計算する必要があり、単純に「塊を選ばなかった演算は全計算ゼロ」にはならない。

### 学習時の勾配と選択の最適化

得点最大の種類を選ぶ操作は離散的だが、著者は注意マスクの勾配を通じて得点層を更新する。ソフトマックス側では注意確率と出力の勾配からマスク列の勾配を求め、線形注意側では状態更新の勾配を得点へ伝える。非選択経路の勾配まで厳密に計算すると高価なため、非活性塊については得点勾配をゼロとする近似を用いる。これにより学習時の演算量を実用的に抑えるが、すべての候補構成を網羅的に探索するわけではない。

著者は、ソフトマックスと線形注意の比率を指定する補助損失を加えず、言語モデル損失だけで選択比率を学習させる。したがって、ソフトマックス側に割り当てる塊が多くなる入力や学習設定では、計算・メモリ削減が小さくなる可能性がある。必要なメモリ予算を厳密に守るルータではない。

### 二経路の出力統合

GDN側とソフトマックス側の出力をそれぞれ正規化し、問い合わせ由来の重みで合成してから出力射影へ渡す。単純加算だけでは二経路の尺度が揃わず、情報の優先順位を学習しにくい。原著の構成要素除去実験では、注意出力の正規化や重み付けを外すと検索性能が低下しており、経路選択だけでなく**選んだ二種類の情報をどう混ぜるか**が性能に寄与している。

### 自己回帰復号での塊境界処理

得点層は塊全体を観測してから注意種類を確定する。そのため生成中は塊内で両方の候補状態を仮更新し、塊の末尾で選ばれなかった経路の更新を取り消す。ソフトマックス側へ割り当てた塊なら線形状態を塊開始時へ戻し、線形側へ割り当てた塊なら不要なKVを破棄する。これにより逐次生成と塊単位の選択を両立するが、巻戻しに必要な一時状態や実装上の複雑さが生じる。

原著は概念的な計算量を、ソフトマックスに割り当てたトークン数`L_nla`、線形側の数`L_la`に対し`O(L_nla L + L_la)`と整理する。実際のGPU時間は塊サイズ、メモリ配置、カーネル実装、ソフトマックス塊の割合に左右されるため、理論式だけで速度倍率を決められない。

## 実験設定

| 項目 | 原著の条件 |
|---|---|
| 学習データ | FineWeb-Edu |
| モデル規模 | 380M（150億トークン学習）、800M（500億トークン学習） |
| 学習文脈 | 4096トークン |
| GPU | NVIDIA H100 PCIe 80GB、4〜8基 |
| 比較 | GDN、Mamba2、Transformer、固定GDN Hybrid（GDNとTransformerの層比3:1） |
| 提案の構成 | NAtS-L単独層構成、NAtS-L Hybrid（NAtS-L 6層＋GDN 15層） |
| 選択塊サイズ | 64トークン |
| 短文課題 | LAMBADA、PIQA、HellaSwag、WinoGrande、OpenBookQA、ARC |
| 長文課題 | SWDE、SQD、FDA、TQA、NQ、DROP、RULER、LongBench、PG19、CodeParrot、NarrativeQA |
| 主な指標 | パープレキシティ、正答率、検索平均、長文脈への外挿、計算時間 |

800M規模のモデルを**それぞれ事前学習した比較**であり、学習済みQwenやLlamaへ選択器を追加して速度が上がることを示す実験ではない。長文脈の一部評価では4096トークンで学習したモデルを65536トークンまで外挿するため、訓練時と評価時の分布差も考慮する必要がある。

## 主要結果

原著表1の800Mモデルの代表値を示す。一般常識平均は7課題、検索平均は6課題であり、指標と評価集合を混同しない。

| モデル | WikiText PPL（低いほど良い） | 一般常識平均（高いほど良い） | 検索6課題平均（高いほど良い） |
|---|---:|---:|---:|
| GDN | 19.54 | 51.02 | 31.22 |
| Mamba2 | 19.28 | 51.38 | 29.94 |
| Transformer | 19.27 | 50.78 | 33.66 |
| 固定GDN Hybrid | 18.83 | 51.52 | 37.30 |
| NAtS-L | 19.17 | 50.84 | 39.75 |
| NAtS-L Hybrid | 18.52 | 51.41 | 45.07 |

NAtS-L Hybridは固定GDN Hybridより検索平均を7.77ポイント改善し、WikiTextのパープレキシティも18.83から18.52へ改善する。一方、一般常識平均は51.52から51.41へわずかに低下している。NAtS-L単独構成は検索平均39.75と高いが、WikiText PPLは19.17で、固定GDN Hybridの18.83より悪い。特定の検索課題に対する優位性を、すべての言語理解能力での優位性と表現してはいけない。

検索課題の内訳を見ると、NAtS-L HybridはSWDEで62.38、FDAで67.70であり、固定GDN Hybridの54.64、31.13を上回る。ただしDROPでは20.84で固定GDN Hybridの21.75より低い。NAtS-L単独はDROPで22.90と高い。提案の二つの構成でも得意な課題は異なる。

### 長文脈外挿

PG19、CodeParrot、NarrativeQAでは、学習文脈4096を超える65536トークンまでのパープレキシティを比較する。著者は、固定GDN Hybridが学習長を超えた領域で性能を落とす一方、NAtS-L系列は性能を比較的維持すると報告する。これは重要情報の塊だけをソフトマックス側へ残す設計と整合的である。ただし、長文脈の各位置での詳細な時間やKVメモリを伴わない限り、単に65536トークンで性能を維持したことが、同じ長さでの一定倍率の高速化を意味するわけではない。

### 構成要素除去実験

原著表4はNAtS-L Hybridの別設定を比較する。この表は主表とは異なる評価設定で、基準構成の検索6課題平均が33.49である。主表の45.07と直接差し引いてはいけない。

| 変更 | 検索6課題平均 | 影響 |
|---|---:|---|
| 基準NAtS-L Hybrid | 33.49 | 比較基準 |
| 塊内をソフトマックス出力だけにする | 30.87 | 二経路の塊内相関が必要 |
| 塊内をGDN出力だけにする | 26.98 | ソフトマックス側の情報保持が重要 |
| 線形状態の減衰を無効化 | 32.24 | 減衰も寄与 |
| 二経路の個別正規化を省略 | 29.59 | 出力尺度の調整が重要 |
| 注意出力の重み付けを省略 | 32.34 | 選択後の統合重みも寄与 |
| 重みを問い合わせではなく入力特徴から計算 | 27.64 | 問い合わせ依存の重みが有効 |
| 塊サイズを64から128へ変更 | 27.85 | 粗い塊単位は検索精度を損なう条件がある |

塊サイズを大きくすれば選択処理の頻度は下がるが、重要なトークンと不要なトークンを同じ種類へ割り当てる粗さが増す。塊サイズ128の性能低下は、速度と品質の交換条件を示す負の結果である。学習損失だけで選択比率を決めるため、実際のKV予算に合わせた選択比率制御は今後の課題とされる。

## 既存研究との差

固定的な層混成は、全域注意を使う層では全トークンのKVを残す。NAtS-Lは層内で重要な塊だけをソフトマックス経路へ置くため、固定的な全域注意層のメモリ費用をさらに減らす方向である。疎注意は一部のKV参照を削るが、選ばれなかったトークンの情報を完全に捨てる場合がある。NAtS-Lは選ばれなかった塊をGDNの状態へ取り込むため、短期情報を圧縮状態として残す。

TransMambaのように系列中の一定位置で注意方式を切り替える方式とも異なり、入力内容から選択を学習する。注意種類の選択器と二経路の合成を言語モデル学習と同時に最適化する点が本論文の固有性である。ただしこの学習前提は、既存モデルの重みを変えずに推論だけを高速化したい場合には導入障壁となる。

## 限界・負の結果

第一に、提案法は学習済みTransformerへ容易に追加できる無学習の枝刈りではない。各塊の注意種類を学習するため、モデル構造と学習過程の変更が必要になる。第二に、学習実験は380Mと800M規模であり、数十B〜数百B規模の本番モデルで同じ検索品質と速度の交換条件が得られるとは確認されていない。

第三に、選択比率の制約がないため、ソフトマックス塊の割合が増えればKV容量が膨らむ。実運用の固定メモリ予算や遅延上限を直接守る仕組みではない。第四に、塊の種類は塊全体を観測してから確定するため、逐次復号で両経路の仮更新と巻戻しが必要であり、カーネル実装が複雑になる。

第五に、性能は課題によって異なる。一般常識平均では固定Hybridにわずかに劣り、DROPでもHybrid同士の比較では低下する。構成要素除去では塊サイズ128、個別正規化なし、問い合わせ非依存重みが明確に悪化した。第六に、GPU性能の結果はH100環境と著者実装に依存し、RTX 4070 Super等の小規模GPUで同じ倍率が得られるという根拠はない。
