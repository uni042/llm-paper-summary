## 概要
端末LLMではモデル重みだけでなく、文脈長に比例して増えるKVキャッシュがメモリ容量とデコード時帯域を圧迫する。全tokenを同じ低bitへ量子化すると重要tokenまで強く圧縮し、逆に高bit固定では重要でないtokenへbitを浪費する。

本方式はtokenごとの特徴から重要度を推定する小型controllerを使い、KV精度を2-bit、4-bit、8-bit、FP16から動的に選ぶ。Huffman codingのように重要な情報へ多くのbitを割り当てる考え方をKVへ適用する。

## 問題設定
KVの量子化誤差が生成へ与える影響はtokenごとに異なる。固定4-bit等では、低影響tokenに余分なbitを使う一方、高影響tokenでは分解能不足が品質を落とす。端末ではメモリだけでなくKV読出し帯域も厳しいため、平均bit幅を下げつつ品質を守る必要がある。

## 手法
controllerへの入力はtoken frequency、quality score、attention variance、entropy-based uncertainty等の軽量特徴である。これらから各tokenの保持精度を4段階から選択する。

重要度の高いtokenは8-bit/FP16へ残し、低影響tokenは2/4-bitへ落とす。これにより平均KVサイズと転送量を減らしながら、固定低bitで発生する重要tokenの量子化誤差を避ける。controller計算は追加費用だが、KV帯域削減がそれを上回る条件を狙う。

## 評価条件
| 観点 | 内容 |
|---|---|
| モデル | SmolLM-135M、360M、1.7B |
| 精度候補 | 2-bit / 4-bit / 8-bit / FP16 |
| task | commonsense reasoning benchmarks |
| 比較 | static KV quantization、rule-based、FP16 |
| 指標 | accuracy、ms/token、KV memory |

## 主要結果
SmolLM-360MのHellaSwagでは固定KV量子化に対しデコード遅延を17.75%削減し、accuracyを7.60ポイント改善した。FP16との差は0.30ポイントに収まった。

これは低bit化を一律に強めるより、token重要度に応じてbitを再配分する方がaccuracy-latency Paretoを改善できることを示す。利得はcontroller overheadとKV帯域の比に依存する。

## 既存研究との差
固定precisionや手作り規則に対し、学習済みcontrollerがtoken単位でprecisionを選ぶ。重み量子化ではなく生成中に増えるKVを対象とするため、長文脈ほど容量削減の意味が大きい。

## 限界
評価モデルは最大1.7BのSmolLMであり、大規模LLMやGPU serverで同じcontroller overhead・精度関係になるとは限らない。特徴抽出とcontroller自体の計算・保存費用もゼロではない。
