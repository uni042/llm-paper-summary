# CLAG：小規模言語モデルのエージェント記憶を話題別に進化・検索する

## 概要

CLAG（CLustering-based AGentic memory）は、小規模言語モデル（SLM）を使うエージェントが長期の会話や行動履歴を外部記憶へ蓄積するとき、**無関係な記憶の混入と更新の干渉**を減らす仕組みである。単一の記憶プールから埋め込み類似度だけで検索すると、表面上の語が似ていても現在の質問とは異なる話題の記録が候補に入りやすい。さらに、新しい記憶を使って既存の記憶を自動更新する場合、無関係な記録まで書き換えると長期的な知識の一貫性が損なわれる。小型モデルほど、与えられた無関係文脈に引きずられやすいという問題設定である。

CLAGは、記憶を話題ごとのクラスタへ割り当てる**エージェント主導のルーティング**、割当先クラスタ内だけでリンク生成・要約更新を行う**局所的進化**、質問に関連するクラスタを先に選んでから個別記憶を検索する**二段階検索**の三つを結合する。これらの判断には別々の専用学習モデルを用いず、同じSLMを役割別のプロンプトで複数回呼び出す。クラスタ分割により検索空間と更新対象を限定し、記憶の品質を保ちながら回答品質を上げる狙いがある。

原著表1ではQwen3-0.6Bを使ったBioASQの回答F1が単純な検索拡張生成（RAG）の2.40から22.01へ改善した。表2ではA100上の平均端から端までの時間が、GAMの17,934.32ミリ秒に対してCLAGは514.14ミリ秒である。しかし**最も単純なRAGの289.60ミリ秒よりは遅い**。原著付録Cによれば、200件のBioASQ質問で二段階検索が除外した記憶は平均8.02%にとどまる。したがって「すべての既存方式より高速」「記憶検索量を大幅に削減」という結論は正しくない。主要な貢献は、限られたモデル能力で無関係な記憶を抑え、精度と実行費用の中間的な運用点を作ることである。

## 問題設定：大きな記憶プールで起こる検索ノイズと知識汚染

一般的なRAG型の記憶では、観測、操作、道具の応答、過去の会話を個々の記憶ノートとして保存する。質問時には質問の埋め込みと全ノートの類似度を計算し、上位の記録をモデルの文脈へ渡す。この方法は単純で、保存された記憶の再利用もできる。しかし、会議予定と旅行計画のように異なる話題の記録が同じ索引に混在すると、類似する語を持つ別話題の記憶を誤って取得する可能性がある。検索された文脈の誤りは、パラメータ数の少ないSLMの回答を大きく乱す。

自律的な記憶管理方式では、記憶を追記するだけでなく、既存ノートとの関連付け、重複統合、古い説明の書換えなどを実施する。これを全体プールで行うと、新しい記録の影響が話題の違う既存記録へ波及し、記憶の意味が徐々に変わる。CLAGは検索時だけでなく**記憶を書き込む時点で話題境界を作る**ことにより、更新と検索の双方を局所化する。クラスタは静的な前処理の結果ではなく、記憶の増加に合わせてSLMが選択し、必要に応じて新設・分割する管理単位となる。

ここで最適化する対象は、Transformer内部のKVキャッシュではなく**エージェントが外部に持つ意味記憶の索引・更新・検索**である。埋め込み計算、SLMによるクラスタ判断、ノートの再記述には追加費用があるため、単純なRAGより軽くなる保証はない。評価では回答品質だけでなく、検索時間、全体時間、証拠の適合度、構成要素除去実験を組み合わせて判断する必要がある。

## 手法

### 1. 記憶ノートの構造と初期クラスタ

原著式(1)では記憶ノートを m_i={O_i,C_i,t_i,K_i,G_i,X_i,L_i} と表す。O_iは元の経験・発話、C_iは所属クラスタ、t_iは時刻、K_iは重要語、G_iはタグ、X_iは文脈説明、L_iは他ノートへの関連リンクである。元の文章だけでなくSLMが生成した意味メタデータを保持することで、単純な語句一致より豊かな関連性判断を可能にする。

最初から1件ごとにクラスタを新設するのではなく、初期化段階で100件の記憶をバッファに貯め、K-means法で初期クラスタを3つ作る。以降の書込みは新しいノートの埋め込みと既存クラスタの重心を比較し、近いクラスタ候補を3つ抽出する。SLMは候補の話題要約・タグを読み、最も適切なクラスタを選ぶ。選んだクラスタとの余弦類似度が閾値0.1を下回ると、新しいクラスタを作成する。この二段階の判断により、幾何学的に近いが意味的に異なる記憶を同じ場所へ入れる誤りを抑える。

クラスタが300件を超えた場合にはK-meansによって二分し、長期間の蓄積で一つのクラスタが肥大化するのを防ぐ。新しい記憶が既存の話題へ属するか、それとも新規の話題として分離すべきかをSLMに委ねる点が、固定したクラスタ数を持つオフライン分割と異なる。もっとも、クラスタ重心と意味の不一致や、話題の急変時の誤配置は残り得る。

### 2. クラスタ内だけのリンク生成と記憶進化

新しいノート m_new がクラスタ C_routed に配置されたら、そのクラスタ内で類似度上位5件の近傍ノート M_local を探す。SLMは新しい記憶と近傍記憶の間に、時間順序や因果関係などのリンク L_new を生成する。次に、各近傍ノートについて新しい情報が既存の説明を更新すべきかを判断し、必要ならノートの属性や説明を再構成する。クラスタの話題要約・タグも更新し、以後のルーティングと検索で利用できるようにする。

この手順では、新しい旅行予定が入ったときに旅行クラスタの既存予定は更新しても、無関係な業務会議クラスタまで調べて書き換えない。原著式(2)〜(4)が示す局所近傍の選択、リンク生成、ノート更新の順番が重要である。全体プール M を対象に毎回進化させる方式に比べ、局所集合 M_local だけにSLMの更新判断を適用できるため、計算量と無関係な更新の波及を抑える。ただし、クラスタが誤って割り当てられれば、本来必要なクラスタ間の知識統合を逃す可能性がある。

付録Cの観測ではクラスタ数の平均が5.6±3.56（10例、最小3・最大13）、平均クラスタサイズが67.99±41.90である。この値は局所更新の対象が全記憶集合より小さくなり得ることを示すが、クラスタ数とサイズはワークロード依存である。原著の局所計算量の説明は集合サイズに比例する概念式であり、すべての更新に対する実測CPU/GPU時間をこの式だけから決められるわけではない。

### 3. 質問時の二段階クラスタ選択・個別検索

推論時は質問 q とタグを埋め込みベクトルへ変換し、まずクラスタ重心の距離で候補クラスタ3つを選ぶ。SLMは各候補の話題要約・タグを読んで、質問に本当に必要なクラスタだけを可変個数で選択する。この**第1段階**が、語句の似た別話題クラスタを検索対象から外す役割を持つ。単純に重心が近い上位3クラスタを必ず全部検索するわけではない。

**第2段階**では、選択されたクラスタに含まれる記憶ノートだけを対象に個別の類似度検索を行い、上位10件を取得して回答生成に渡す。質問と記憶の間に「話題クラスタ」という判断層を挟むため、同じ埋め込み空間に似た語が存在しても、無関係な記憶が混入する確率を減らせる。検索範囲を縮める効果と、検索結果の意味的な適合性を上げる効果は別である。原著の平均検索範囲削減は8.02%と小さいが、回答品質への寄与は残っている。

クラスタのプロフィールを選ぶ判断、リンク生成、記憶更新は同一の小型言語モデルを異なる役割のプロンプトで呼び出して行う。したがって専用の大型ルーターモデルを必要としない一方、複数回のSLM推論とプロフィール管理が発生する。検索時の効率は、クラスタ数、プロンプト長、埋め込み計算、ノート更新頻度によって変わる。

### 4. 具体的な既定パラメータと処理順

| パラメータ | 原著付録Dの設定 | 役割 |
|---|---:|---|
| 初期記憶バッファ n | 100件 | 最初のクラスタ生成まで蓄積 |
| 初期クラスタ数 n_init | 3 | 初期K-meansの分割数 |
| ルーティング候補 k_route | 3 | 新しい記憶の所属先をSLMへ提示 |
| 新規クラスタ閾値 τ | 0.1 | 選択先との類似度が低い場合に新設 |
| クラスタ分割閾値 τ_split | 300件 | 肥大化したクラスタを二分 |
| 更新時の局所近傍 k_local | 5件 | リンク生成・再記述候補 |
| 検索第1段階の候補 K_stage1 | 3 | 質問から近いクラスタの候補 |
| 最終取得 k_retrieve | 10件 | 回答へ渡す個別記憶数 |

記憶書込み時は、まずノートの属性を作り、初期化後なら重心候補抽出→SLMによるクラスタ選択→必要なら新設→局所リンク・進化→クラスタプロフィール更新と進む。質問時は質問埋め込み→クラスタ候補抽出→SLM選択→選択クラスタ内検索→回答生成である。書込みと検索の経路を区別することが、性能上の費用と利点を把握するために重要である。

## 主要結果

### 1. 回答品質：モデルとデータセットの違い

以下は原著表1のF1値である。すべて同一指標だが、異なるデータセット間で絶対値を直接比較して優劣を決めることはできない。

| バックボーン・データセット | 単純RAG | GAM | CLAG | 主要な読み取り |
|---|---:|---:|---:|---|
| Qwen3-0.6B・LoCoMo | 12.90 | 16.05 | 20.99 | 会話記憶の雑音下で改善 |
| Qwen3-0.6B・HotpotQA | 11.75 | 7.81 | 15.50 | 複数段質問で改善 |
| Qwen3-0.6B・BioASQ | 2.40 | 3.40 | 22.01 | 専門用語の多い記憶で大きな差 |
| Llama-3.2-1B・LoCoMo | 18.04 | 22.63 | 21.05 | **GAMの方が高い**負の例 |
| Llama-3.2-1B・HotpotQA | 9.46 | 13.85 | 14.20 | 既存自律記憶方式を僅差で上回る |
| Llama-3.2-1B・BioASQ | 5.12 | 6.52 | 10.16 | 専門領域で改善 |
| DeepSeek-R1-Distill-Qwen-1.5B・LoCoMo | 11.54 | 12.34 | 15.46 | 複数モデルで有効 |
| DeepSeek-R1-Distill-Qwen-1.5B・HotpotQA | 5.54 | 6.45 | 9.12 | 小型推論モデルで改善 |
| DeepSeek-R1-Distill-Qwen-1.5B・BioASQ | 2.81 | 2.78 | 6.18 | 専門領域で改善 |

Qwen3-0.6BのBioASQでCLAGが大きく改善した理由として、原著は、医学用語の表面上の類似性が全体プール検索を混乱させるのに対し、クラスタ単位の話題選択が無関係な証拠を除外するためと説明する。これは医学的な診断性能の実証ではなく、BioASQ形式に変換した質問応答での比較である。Llama-3.2-1BのLoCoMoではGAMのF1が22.63でCLAGの21.05を上回るため、「全条件で最高精度」と記述してはならない。

### 2. 遅延：最速ではなく中間の運用点

原著表2はQwen3-0.6B、LoCoMo、A100単一GPUの平均値を示す。

| 方式 | 検索遅延 | 端から端までの遅延 | CLAGとの関係 |
|---|---:|---:|---|
| 単純RAG | 17.80 ms | 289.60 ms | **RAGの方が速い** |
| A-mem | 18.54 ms | 408.68 ms | **A-memの方が速い** |
| MemoryOS | 220.79 ms | 968.75 ms | CLAGが約1.88倍速い |
| GAM | 8,303.41 ms | 17,934.32 ms | CLAGが約34.88倍速い |
| CLAG | 142.43 ms | 514.14 ms | 比較基準 |

CLAGの検索処理は、単純RAGの17.80ミリ秒に対して142.43ミリ秒と約8倍かかる。全処理でも289.60ミリ秒から514.14ミリ秒へ約1.78倍に増加する。一方、GAMの全処理17,934.32ミリ秒に対しては約34.9倍速い。これは「エージェントによる記憶更新・検索の高度化」と「単純検索の低遅延」の間の交換条件であり、CLAGが検索処理の全方式中最速であることを意味しない。

### 3. 証拠検索品質と構成要素除去

原著表4のQwen3-0.6Bにおける証拠F1は、LoCoMoでRAG 1.12、A-mem 1.17、CLAG 2.07、BioASQでRAG 2.29、A-mem 2.20、CLAG 25.11である。一方、HotpotQAではRAG 11.44に対してCLAG 11.17と僅かに低い。回答F1と検索証拠F1は別指標であり、検索証拠の値が低くても記憶ノートの統合・再記述によって最終回答が改善する可能性を原著は論じる。MemoryOSとGAMは取得件数が固定Kでないため、この証拠F1比較表からは除かれている。

| BioASQ・Qwen3-0.6Bの比較 | 回答F1 | BLEU-1 | 何を外したか |
|---|---:|---:|---|
| CLAG全機構 | 22.01 | 17.23 | 全機構を使用 |
| 全体プール更新へ変更 | 19.55 | 17.25 | クラスタ内だけの更新を廃止 |
| 全体プール検索へ変更 | 20.25 | 16.56 | 二段階クラスタ検索を廃止 |
| 幾何学的K-meansクラスタのみ | 15.64 | 13.36 | SLM主導のクラスタ判断を廃止 |
| 余弦類似度のみのクラスタ | 14.78 | 12.53 | SLM主導のクラスタ判断を廃止 |

局所更新を全体更新へ置換するとF1は2.46ポイント低下し、二段階検索を全体検索へ置換すると1.76ポイント低下する。SLM主導の意味判断をK-meansだけへ変えた場合は22.01から15.64へ低下する。これらは主要機構それぞれが品質に寄与する根拠である。ただし局所更新を全体更新へ変えた際のBLEU-1は17.23から17.25へ僅かに**上昇**しており、すべての指標で単調改善するわけではない。

### 4. 検索範囲と初期クラスタ数の感度

付録CではBioASQの200質問に対し、選択クラスタに含まれる記憶数と全記憶数の比から検索空間の削減率を測った。**平均削減率は8.02%、標準偏差17.29%、最大89.57%、最小0%**である。特定の質問では検索対象が大きく減るが、平均では9割以上の記憶が検索候補に残る。この数値は「平均約90%の検索削減」ではなく、最大値と平均値を区別する必要がある。CLAGの利点は、検索件数を大幅に減らすことだけではなく、話題の誤った記憶を除外して回答の整合性を改善する点にある。

付録DのLoCoMo／Qwen3-0.6Bの初期クラスタ数比較では、3クラスタでF1 20.99、5クラスタで22.71、10クラスタで21.71だった。初期値3は最高得点の設定ではなく、構造の簡潔さを優先して採用されている。また、新規クラスタ判定閾値τ=0.10のF1は20.99、τ=0.15は22.41である。ハイパーパラメータの最適値はワークロードに依存し、原著既定値を普遍的な最適値として扱えない。

### 5. 大きいモデルでの効果

原著表6ではQwen3-8Bを追加し、LoCoMoでCLAGのF1 21.50、単純RAG 19.06、A-mem 21.44、HotpotQAでCLAG 25.40、RAG 23.66を報告する。BioASQではCLAG 25.40に対しMemoryOS 28.83の方が高い。モデルが大きくなるほど、無関係な証拠への頑健性が増すため、CLAGと比較方式の相対差が小さくなる傾向があると著者らは述べる。従って小型モデルでの大きな利得を、そのまま8B以上へ外挿することはできない。

## 既存研究との差

単純RAGは記憶を固定した検索索引として扱い、入力の意味に最も近い個別ノートを全体から検索する。A-memやGAM、MemoryOSは記憶の更新・圧縮・階層化を進めるが、原著の問題設定では、更新や検索が広い記憶集合をまたぐことで異なる話題が混ざる余地がある。CLAGは**書込み時にSLMが意味クラスタを選ぶ**ことと、**同じクラスタ内でだけ記憶を進化させる**ことを一体化する。さらに検索時にクラスタのプロフィールを使って意味的な絞込みを行うため、保存時の分類結果が検索時のノイズ除去に再利用される。

この研究は、LLM推論エンジンの重み量子化やGPUカーネル高速化ではなく、エージェントがモデルへ渡す外部文脈の構築方法を扱う。KVキャッシュを減らす方式とは対象のメモリ層が異なる。記憶の更新処理と検索の両方を最適化する点で、単なるプロンプト短縮や検索器の変更だけの研究とも区別できる。

## 限界と実用上の条件

第一に、SLMがプロンプトに従ってクラスタを選び、プロフィールを生成する方式であるため、プロンプトの文面やモデル版が変わると挙動が変わり得る。論文の限界節でも、分布の大きな変化、新しい話題、文体の急変時のルーティングの安定性は体系的に検証されていないと述べる。第二に、クラスタ境界をまたぐ関連情報がある場合、局所更新と局所検索は重要な記憶を見落とす可能性がある。Open Domainの質問では他方式が勝る条件があり、選択クラスタを柔軟に広げる仕組みが今後の課題となる。

第三に、**単純RAGより遅い**。Qwen3-0.6BのA100実験では全処理時間が289.60ミリ秒から514.14ミリ秒へ増加している。したがって、検索件数の局所化と実行時間短縮を同一視できない。SLMへの複数回の問い合わせ、クラスタプロフィール管理、ノート更新の費用がある。第四に、200質問での検索範囲削減は平均8.02%と小さく、巨大な記憶集合で同じ割合・遅延が維持される保証はない。

第五に、専門領域のBioASQはHotpotQA形式に変換されており、原データセットのすべての利用形態に一般化するものではない。評価は主にLoCoMo、HotpotQA、BioASQと少数のモデル系列であり、オンラインの長期間運用や大量同時要求、端末上の省電力推論を実証していない。第六に、記憶には過去の操作・発話や個人情報が含まれ得るが、アクセス制御や保存期間の安全性は今後の課題として挙げられており、厳密な保護機構の評価は示されていない。
