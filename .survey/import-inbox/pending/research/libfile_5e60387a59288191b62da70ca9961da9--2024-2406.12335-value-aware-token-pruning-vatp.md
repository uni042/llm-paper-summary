# Attention Score is not All You Need for Token Importance Indicator in KV Cache Reduction: Value Also Matters

## 書誌情報

- 著者: Zhiyu Guo, Hidetaka Kamigaito, Taro Watanabe
- canonical identity: `arXiv:2406.12335`
- 初版: 2024-06-18
- 一次資料: https://arxiv.org/abs/2406.12335

## 概要

長文脈LLMでは、過去tokenのkey/valueを保持するKVキャッシュが系列長に比例して増える。H2OやScissorhandsのようなtoken枝刈り方式は、過去のattention scoreを重要度として蓄積し、低スコアtokenのKVを捨てることで容量を抑える。しかしattention出力はattention weightだけでなくvalue vectorそのものにも依存するため、同じattention weightでもvalueの大きさが違えば出力への寄与は同じではない。

本論文はvalue vectorのnormがtoken間・layer間で一様ではないことを観察し、Value-Aware Token Pruning (VATP)を提案する。VATPは既存の累積attention scoreへvalue vectorのL1 normを組み合わせ、KV予算を超えたときにこの複合スコアが低いtokenから削除する。新しい予測器を学習せず、既存のH2O/Scissorhands型枝刈りへ局所的に追加できる。

LongBench 16タスクの50% KV cache budgetでは、LLaMA2-7B-chatでH2O+VATPがH2Oを12/16タスク、Scissorhands+VATPがScissorhandsを13/16タスクで上回る。Vicuna-v1.5-7B-16kではそれぞれ12/16、14/16タスクで上回った。Scissorhands統合時のthroughputはVATP 103.93 tokens/s、元方式104.28 tokens/sで、peak memoryはいずれも48,380 MiBと報告され、value norm計算の追加費用は小さい。

## 問題設定

attentionの出力は各tokenのvalue vectorをattention weightで重み付けして足し合わせる。従来のKV pruningは「過去に大きなattention weightを受けたtokenは将来も重要」という考えでattention scoreを累積するが、実際の出力寄与は重みだけで決まらない。value vectorの成分が大きいtokenは、小さめのattention weightでも出力を大きく動かし得る。

論文はLLaMA系モデルのvalue vector normを観察し、normが一様ではないことを示す。したがってattention-onlyの順位付けでは、attentionは小さいがvalueが大きいtokenを過小評価して削除する可能性がある。VATPの狙いはKV予算や枝刈りタイミングを新しく設計することではなく、既存方式が「どのtokenを残すか」を決める重要度指標を改善することにある。

## 手法

### 1. value normを重要度へ追加

各attention headでtoken `i` のvalue vector `v_i` からL1 norm `||v_i||_1` を計算する。L1 normはvalueの各成分の絶対値を合計した量であり、そのtokenがattention出力へ与え得る振幅の簡単な代理指標として使う。

VATPはこのnormを既存のattention由来重要度へ掛け合わせる。入力は既存方式が保持しているattention scoreとKV cache内のvalue vector、出力は各tokenの新しい重要度である。追加の学習モデルやoffline calibrationを必要とせず、forward中に既に存在するvalueから計算できる。

### 2. H2Oへの統合

H2Oは過去のattention scoreを累積し、heavy hitterと直近tokenを優先してKV cacheへ残す。VATP版ではこの蓄積attentionだけで順位を決めず、value normを反映した重要度へ置き換える。KV budgetそのものやH2Oの保持・削除フローは維持されるため、比較では「重要度指標だけを変えた効果」を観察しやすい。

この構造上、VATPが効くのはattention-only順位とvalue-aware順位が異なる場合である。value normがほぼ一様なら順位はほとんど変わらず利得も小さい。一方、normのばらつきが大きいlayer/taskでは、attentionだけでは見落とすtokenを保持できる。

### 3. Scissorhandsへの統合

Scissorhandsも過去attentionからtoken重要度を推定し、限られたKV budgetで残すtokenを選ぶ。VATPは同様にvalue normを重要度へ混ぜるだけなので、枝刈り方式全体を置き換えずに適用できる。

この「既存prunerへの差し込み」が論文の重要な設計点である。新しいcache allocatorやGPU kernelを導入する方式ではないため、主な追加費用はvalue norm計算と複合スコア更新になる。実測throughputが元Scissorhandsとほぼ同じなのは、この追加処理が生成全体に対して小さいことを裏付ける。

### 4. KV budget超過時のtoken選択

生成が進んでKV cacheが設定budgetを超えると、統合先方式の規則に従って候補tokenを並べ、VATP重要度の低いものを削除する。残ったkey/valueだけが次token以降のattention対象となるため、メモリ使用量とattentionで読むKV量をbudgetに抑える。

ただし削除は不可逆であり、後で必要になるtokenを低く見積もれば品質を失う。VATPはこの誤順位を減らす指標改善であって、将来attentionを完全に予測するものではない。そのため高い削減率ではvalue-awareでも情報損失をゼロにはできない。

## 評価条件

| 項目 | 条件 |
|---|---|
| モデル | LLaMA2-7B-chat、Vicuna-v1.5-7B-16k |
| ベンチマーク | LongBench 16タスク |
| 主比較budget | KV cache 50% |
| 比較方式 | H2O、Scissorhands、それぞれのVATP統合版 |
| 感度評価 | KV削減率20〜80%の範囲を含む |
| 効率測定 | ScissorhandsとVATP統合版のthroughput / peak memory比較 |
| 主指標 | 各LongBench task固有指標、勝敗task数、throughput、peak GPU memory |

## 主要結果

| 条件 | 比較 | 結果 | 読み取れること |
|---|---|---|---|
| LLaMA2-7B-chat、50% KV budget | H2O+VATP vs H2O | 12/16 tasksで上回る | value norm追加がattention-only順位を改善 |
| 同 | Scissorhands+VATP vs Scissorhands | 13/16 tasksで上回る | 特定prunerだけに依存しない |
| Vicuna-v1.5-7B-16k、50% | H2O+VATP vs H2O | 12/16 tasksで上回る | 別モデルでも傾向を再現 |
| 同 | Scissorhands+VATP vs Scissorhands | 14/16 tasksで上回る | Vicunaではより広いtaskで改善 |
| 効率比較 | Scissorhands+VATP vs Scissorhands | 103.93 vs 104.28 tokens/s | value norm計算のthroughput負担は小さい |
| 効率比較 | peak memory | 48,380 MiB vs 48,380 MiB | 同じKV budgetでは追加peak memoryが観測されない |
| KV削減率感度 | Scissorhands系 | 高削減率を含む多くのbudgetでVATPが優位 | aggressive pruningほど重要度誤順位の改善価値が増える |

論文は「全タスクで必ず改善」とは主張していない。12〜14/16という結果は、残りのタスクでは同等または基準方式が上回る場合があることを意味する。VATPはvalue normを加えれば常に最適なtoken集合が得られる方式ではなく、attention-onlyより情報量の多いヒューリスティックである。

## 既存研究との差

H2Oはattentionのheavy hitter性を利用して過去tokenを残し、Scissorhandsもattention履歴から永続的に重要なtokenを選ぶ。両者は「attention scoreがtoken重要度を十分表す」という前提を共有する。VATPはcache管理の枠組みを作り直さず、この前提だけを修正する。

また、別の学習済みselectorやoffline calibrationを必要とする方式と異なり、VATPは推論中に既に計算されているvalue vectorからnormを得る。そのため既存prunerへの追加が小さく、同じKV budgetで品質を改善する方向に特化している。

## 限界

評価モデルはLLaMA2-7B-chatとVicuna-v1.5-7B-16kに限られ、より新しいGQA/MQAモデルやMoE、極端な長文脈モデルへの一般化はこの論文だけでは確定しない。特にhead間でKVを共有する構造では、token重要度の集約方法が異なる可能性がある。

LongBenchでの勝敗数は改善の広さを示すが、全タスクで改善するわけではない。value normが重要度の完全な因果指標という保証はなく、attention scoreとの積もヒューリスティックである。将来必要になるtokenを誤って削除する不可逆性は残る。

効率評価ではthroughputとpeak memoryの追加負担が小さいことを示す一方、専用GPU kernelによるKV読み出し最適化や大規模オンラインservingでのTTFT/TPOT、同時要求数スケーリングを主眼にしたシステム評価ではない。したがってVATPの主な実証価値は、同じcache budgetでの品質改善にある。
