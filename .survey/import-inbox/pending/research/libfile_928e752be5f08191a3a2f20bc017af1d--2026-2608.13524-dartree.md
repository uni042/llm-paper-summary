# DARTree: Speculative Diffusion Decoding with Autoregressive Draft Trees

## 概要
投機的復号は高速なdrafterが複数token候補を作り、target modelが一度に検証して受理することで、targetの逐次forward回数を減らす。拡散言語モデルをdrafterにすると複数位置を並列予測できるが、各位置の分布は「その枝で実際に選ばれた直前token」へ因果的に条件付けされていない。そのため候補を木へ広げても、枝ごとの自己回帰整合性が弱く、検証時の受理長を失う。

DARTreeは既学習の自己回帰補正ヘッドをchainからtreeへ拡張する。各depthで固定幅の候補nodeをbatchとして一括展開・scoreし、AR-head inferenceが終わった後にbest-first pruningでtargetへ渡すverification treeを選ぶ。これにより補正ヘッドをheap操作のたびに逐次呼ぶ経路を避ける。7つの数学・コード・chat benchmark、4 model-temperature設定すべてで平均acceptance lengthとspeedupが最良となり、最大12.97 token/verification、DFlash比98.6%、Domino比27.9%長い受理、通常自己回帰比最大9.73倍のlossless speedupを報告する。

## 問題設定
拡散drafterはtoken blockを一度に予測できるためproposal latencyが低い。しかし位置iの高確率tokenは、位置i-1で木のどの枝を選んだかを反映していない。単一chainへAR correctionを加える方式は因果情報を戻せるが、候補coverageが狭い。逆にtreeを広げる方式はcoverageを増やせても、各branchにAR correctionを伝搬しなければtarget modelが受理する連続列になりにくい。

さらにbest-first searchを素朴に実装すると、priority queueからnodeを1つ取り出すたびにAR headを呼ぶため、GPU上の小さな逐次kernelが増え、拡散drafterの並列性を相殺する。DARTreeは「tree quality」と「GPU-friendly batch expansion」を同時に解く必要があると捉える。

## 手法
### 固定幅のdepth-wise展開
各depthで現在のfrontier node群をまとめ、拡散drafter由来の候補とAR correction headを使って次nodeをbatch生成する。nodeごとの逐次heap pop→head inferenceではなく、同じdepthを一括処理するためGPU並列性を維持する。

### 枝ごとの自己回帰補正
AR correction headは、そのbranch上で既に選択されたtoken列を反映して候補scoreを修正する。これにより拡散モデルのposition-wise marginalだけで木を作る場合より、target modelの左から右への条件付き分布へ候補pathを近づける。狙いは単純な候補数増加ではなく、verificationで連続受理される深いpathを増やすことである。

### 展開と枝刈りの分離
全nodeを無制限にtargetへ渡すとverification costが増えるため、depth-wise batch expansionの後にbest-first pruningを適用し、verification treeのbudget内へ絞る。重要なのは、heap操作をAR-head inferenceのcritical pathから外すこと。tree探索の制御処理とGPU推論を分離して、proposal側の逐次性を抑える。

## 評価条件・主要結果
| 観点 | 結果 |
|---|---|
| workload | 数学・コード・対話の7 benchmark |
| 設定 | 4 model-temperature configurations |
| acceptance | 最大12.97 token / verification round |
| DFlash比較 | 同条件で最大98.6%長い受理 |
| Domino比較 | 同条件で最大27.9%長い受理 |
| E2E | local autoregressive decoding比最大9.73倍 |
| 品質 | lossless speculative decoding |

受理長はtarget model一回のverificationで何token進めるかを示し、長いほど高価なtarget呼び出し回数を減らせる。ただしtreeを大きくすればverification側の計算も増えるため、DARTreeは候補木の質とbudgetの両方を調整する。

## 既存研究との差
DFlash型の拡散draftは並列proposalを強みにする一方、位置間の因果整合性が弱い。Domino等の補正方式はAR情報を導入するが、chainまたは探索の逐次性が残る。DARTreeはAR correctionをtree branchへ拡張しつつ、depth単位batch expansionと後段pruningに分けることで、候補品質とGPU実行効率を同時に狙う。

## 限界
最大9.73倍は論文の特定model・temperature・benchmark条件での最大値であり、全条件の保証ではない。利得はdrafter品質、AR correction headの精度、tree width/depth、verification budgetに依存する。候補木が広がるほどproposal memoryとtarget verification costも増える。またtraining-freeである代わりに、利用可能なpretrained diffusion drafterとcorrection headの組合せへ依存する。
