# Attention Score is not All You Need for Token Importance Indicator in KV Cache Reduction: Value Also Matters

## 概要
長文脈LLMのKVキャッシュ削減では、過去tokenが将来queryからどれだけattentionを受けたかを累積し、scoreの小さいtokenを削除する方式が広く使われる。しかしattention出力はweightだけでなく、そのweightを掛けるvalue vectorの和である。valueの大きさがtoken間で一様でなければ、attention scoreが小さくても出力への寄与が大きいtokenが存在する。

著者らは実モデルのvalue vectorノルムが顕著に非一様であることを測定し、Value-Aware Token Pruning（VATP）を提案する。既存のH2OやScissorhandsが使う重要度へvalueのL1ノルムを掛けるだけなので、独立した予測モデルを追加しない。LongBench 16 taskで、50% KV budgetを中心にattention-only方式を一貫して改善する。

## 問題設定
通常のattention出力は各tokenのvalue `v_i` をattention weight `α_i` で重み付けして足し合わせる。したがってtoken `i` の寄与を`α_i`だけで順位付けするのは、全`||v_i||`がほぼ同じ場合にしか妥当でない。

実際には層・tokenごとのvalueノルムに大きな差がある。attention scoreのみの枝刈りは、低weightだが大きなvalueを持つtokenを捨てる一方、高weightでも小さなvalueのtokenを残し得る。KV予算が小さくなるほど、この順位誤りが品質へ強く現れる。

## 手法

### Value-Aware Token Pruning
VATPは各tokenの累積attention重要度へvalue vectorのL1ノルムを組み合わせる。直感的には、`attentionで参照される頻度・強さ × 参照されたときに出力へ運ぶ信号量`を重要度とする。

L1ノルムはvalueがKVキャッシュへ格納される時点で計算できるため、別の学習済みselectorや将来query予測を必要としない。tokenを残す・捨てる既存方針自体は変えず、ランキング指標だけを差し替えられる。

### H2Oとの統合
H2Oは過去attentionを累積してheavy hitterを残す。VATP版ではそのscoreへvalue magnitudeを反映する。ただしH2Oはattention scoreを蓄積するため完全attention行列を具体化する実装上の制約があり、FlashAttentionのように行列をHBMへ保存しない方式と相性が悪い。

### Scissorhandsとの統合
Scissorhandsは過去の重要tokenが将来も重要になりやすいという持続性を利用する。VATPはその重要度へvalueノルムを追加し、同じKV budgetで削除対象を変える。この組合せはFlashAttention互換実装でthroughput評価され、品質改善が追加の大きな速度費用を伴わないことを確認する。

### 計算費用
value L1ノルムの追加計算量はattention全体に比べ小さい。7Bモデルのhead dimension 128では、論文はKVキャッシュ規模に対して約`1/(2*d_head)`相当の追加量として整理している。ピークメモリと生成throughputは元の枝刈り方式とほぼ同じである。

## 評価条件

|項目|内容|
|---|---|
|モデル|LLaMA2-7B-chat、Vicuna-v1.5-7B-16k|
|ベンチマーク|LongBench 16 task|
|比較|H2O、Scissorhandsと各VATP版|
|主要KV budget|50%、20〜80% pruningも感度評価|
|速度評価GPU|NVIDIA A6000|
|高速実装|FlashAttention互換Scissorhands + VATP|

## 主要結果

|条件|結果|解釈|
|---|---|---|
|LLaMA2-7B、H2O + VATP|16 task中12 taskでH2O超え|value情報がrankingを改善|
|LLaMA2-7B、Scissorhands + VATP|16 task中13 taskで基準超え|別の枝刈り原理にも移植可能|
|Vicuna-7B|VATP版が12〜14 taskで対応基準超え|モデルを跨いで傾向が維持|
|A6000、50% KV budget|full KV比1.53倍throughput|メモリ削減が実速度へ寄与|
|A6000、25% KV budget|full KV比2.08倍throughput|強い圧縮ほど帯域削減効果が大きい|

20〜80% pruningの感度評価では、特に高い削減率でVATPの優位が目立つ。これはbudgetが潤沢なときは多少のranking誤差が吸収されるが、残せるtokenが少ないとvalueを無視した誤削除が直接品質へ響くためと整合する。

## 既存研究との差
H2O、Scissorhandsなどは「どのtokenを残すか」の中心信号としてattention scoreを使う。本論文は新しいキャッシュ管理機構を丸ごと置き換えるのではなく、token重要度の定義そのものを修正する。このため既存方式へ小さな変更で組み込める。

KIVI等の量子化は各KV要素のbit数を減らすのに対し、VATPは保持token数を減らす。両者は削減軸が異なり、原理上は併用可能だが、論文の主要評価はtoken pruningである。

## 限界
VATPはvalueのL1ノルムを出力寄与の代理にするため、valueの方向や後続の出力射影、head間相互作用を完全には表現しない。attention weightとvalue magnitudeだけで将来全queryの重要度を正確に予測できるわけではない。

H2O統合版はattention行列を必要とするためFlashAttentionとの非互換性が残る。実速度のheadlineはScissorhands統合版であり、すべてのVATP統合方式が同じthroughputを得るわけではない。評価は主に7B級2モデルで、より大規模なGQA/MQAモデルへの一般化は論文範囲を超える。
