## 概要
prefix KV cacheを再利用するには同じprompt prefixを持つrequestを同じinstanceへ寄せたいが、固定affinityは人気prefixのinstanceをhotspotにする。反対にloadだけで散らすとcache hitが消え、prefillを繰り返す。DualMapは一つのmapping空間で両者を妥協する代わりに、requestごとに二つの候補を持たせる。

## 手法
promptを二つの独立hash関数へ通し、二つのcandidate instanceを得る。同じprefixは同じ候補対へ集まりやすくcache affinityを保つ一方、power-of-two choicesとして現在状態の良い方を選べるため、単一hashよりloadを散らせる。

SLO-aware routingは通常cache affinityを優先するが、Time To First Token（TTFT）がSLOを超えそうな時にload-aware選択へ切り替える。hotspot-aware rebalancingは過負荷instanceから低負荷instanceへrequestを移し、skewした人気prefixへ追従する。instance増減時にはdual hash ringを使い、全requestを再mappingするcostを避ける。

## 評価条件
|項目|条件|
|---|---|
|workload|real-world request traces|
|比較|既存cache-affinity/load-balancing scheduler|
|主要制約|同一TTFT SLO|
|指標|effective request capacity、cache reuse、load balance|

## 主要結果
同一TTFT SLO制約下でstate-of-the-art方式よりeffective request capacityを最大2.25倍にする。これは単純なcache hit最大化ではなく、SLO悪化時にload側へ切り替えることで、cache localityを残しながらhotspotによるcapacity collapseを抑えた結果である。

## 限界
二候補の選択はcluster state観測を必要とし、極端なskewや急変ではrebalancing overheadが発生する。最大2.25倍は評価workloadとSLO条件依存で、すべてのprompt分布に一定の倍率を保証しない。
