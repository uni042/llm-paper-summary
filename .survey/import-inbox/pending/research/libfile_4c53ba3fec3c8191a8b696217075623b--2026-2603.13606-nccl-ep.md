# NCCL EP: Towards a Unified Expert Parallel Communication API for NCCL

## 概要
混合専門家（Mixture-of-Experts; MoE）では、routerが選んだexpertの所在GPUへtokenを送るdispatchと、expert計算後の結果を元GPUへ戻すcombineが各MoE層で発生する。NCCL EPは、このexpert parallelism通信をNCCLのDevice API上へ実装し、`ncclEpDispatch` / `ncclEpCombine`という統一プリミティブとして提供する。decodeとprefillではtoken数と通信粒度が大きく違うため、一つのall-to-all実装を使い回さずLow-Latency（LL）とHigh-Throughput（HT）の2経路を持つ。

## 問題設定
MoE通信ではGPUからNICへ直接RDMAを起動するdevice-initiated通信が重要になり、DeepEP等の専用ライブラリが使われてきた。一方で通信スタックがNCCLと別系統になると、topology認識、保守、フレームワーク統合が分散する。さらにdecodeは1〜128 token程度の小batchで1回の通信遅延が重要だが、prefillは4096 token以上の大batchで総帯域が重要で、最適な経路が異なる。

## 手法
### Low-Latencyモード
LLは小batch decodeを対象に、GPU間を直接all-to-allで結ぶRDMA+NVLink meshを使う。中間集約段を挟まずhop数を減らし、少量tokenの固定遅延を抑える。dispatchとcombineの通信領域は二重バッファ化され、あるbufferのexpert計算中に次通信を進めることで通信と計算を重畳する。

### High-Throughputモード
HTはprefillや学習の4096 token以上を対象にする。ノード内/NVLink domain内でtokenを一度集約し、その後にノード間RDMAを行う階層通信を採用する。多数の細粒度RDMAをそのまま飛ばすよりネットワーク利用効率を上げ、受信側でもdomain内に再分配する。

### NCCL Device API統合
両モードともhost側の逐次制御ではなくNCCL Device APIを利用し、GPU起点でintra-nodeとinter-node通信を進める。CとPythonの両APIを提供し、vLLMから呼び出せる形でend-to-end統合する。NCCLのtopology情報を共通基盤として使うため、GPU/NIC構成ごとに別通信ライブラリを管理する必要を減らす。

## 評価条件
| 項目 | 内容 |
|---|---|
| GPU | NVIDIA H100クラスタ |
| 構成 | multi-node、NVLink＋RDMA |
| LL対象 | 1〜128 token程度のdecode batch |
| HT対象 | 4096 token以上のprefill/学習batch |

| API | C / Python、NCCL Device API |

## 主要結果
論文はH100 multi-node構成でLLカーネルが専用expert-parallel通信実装と競合する性能を示し、HTでは大batchを階層化してネットワーク帯域を使う。さらにvLLMへ統合したend-to-end結果を提示し、単独microbenchmarkだけでなく実際のMoE推論経路で動作することを確認している。重要なのは単一headline倍率より、decodeとprefillで異なる通信アルゴリズムを同じNCCL EP APIの下に収めた点である。

## 既存研究との差
DeepEP等はMoEに特化したdevice-initiated RDMAを提供する。NCCL EPは同じ性能領域を、既存NCCLのDevice API・topology管理・フレームワーク資産へ統合する。通常のNCCL all-to-allをそのまま呼ぶ方式とも異なり、expert dispatch/combineのtoken metadataとsmall/large batch特性を前提にLL/HTを別設計する。

## 限界
評価はNVIDIA H100とNCCLが前提で、他ベンダGPUや異種NICへそのまま移植できるわけではない。LL/HTの境界はtoken数だけでなくtopologyやexpert配置に依存し得る。MoE全体の性能はexpert GEMM、router、load balanceにも左右されるため、通信カーネルが高速でも計算偏りが強いモデルではend-to-end利得が制限される。
