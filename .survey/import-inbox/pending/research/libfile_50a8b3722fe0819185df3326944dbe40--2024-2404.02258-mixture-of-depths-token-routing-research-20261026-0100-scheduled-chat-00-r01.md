# Mixture-of-Depths：固定容量のままトークンごとの計算深さを変える条件付きTransformer

## 概要

Mixture-of-Depths（MoD）は、Transformerがすべてのトークンにすべての層の計算を割り当てる必要はない、という仮説から出発する。各ブロックの自己注意とMLPを通過できるトークン数を事前にk個へ制限し、学習したルータがその層で重要と判断した上位k個だけを計算する。残りのトークンは残差経路を通過して、その層の隠れ状態を変更しない。トークンは次の層で再び選ばれる可能性があるため、単純な早期終了とは異なり、途中の層を飛ばして後半層で計算を再開できる。

選ばれるトークンの識別子は入力に応じて変化するが、各層で計算する個数kは固定される。これにより、実行する注意・MLPのテンソルサイズを静的に決められ、条件付き計算でありがちな可変形状によるハードウェア効率の低下を抑える。原著は、系列長2048に対してk=256（12.5%）の経路を隔層に置く設定が良好と報告する。220MパラメータのMoDは、同等の学習損失を持つ通常Transformerと比較して学習ステップが約66%高速になる例を示す。ただし、これは同等の訓練FLOPs予算で最適化した小〜中規模モデル群の比較であり、既存の数十Bモデルへ後付けするだけで66%速くなるという意味ではない。

## 背景と問題設定

通常のTransformerは、系列内のすべてのトークンを各層の自己注意とMLPに通す。トークンの予測難易度は一様でないにもかかわらず、同じ深さの計算を行うことになる。条件付き計算では、計算が必要なトークンだけに演算を配分できれば、同じ計算予算でより高いモデル品質を得るか、同等品質を少ない実行演算で得られる可能性がある。

しかし一般的な動的ルーティングでは、実行するトークン数が要求ごとに変わるとテンソル形状やメモリ割当が変動し、GPU/TPUのバッチ演算に適さない場合がある。MoEは専門家へトークンを分配しても専門家ごとの容量を固定する設計があり、MoDはこの考え方を「計算するか、何もしないか」の二経路へ適用する。演算を省く残差経路が明確なので、全体の演算量を制御しやすい。

MoDの目的は、事前学習済みモデルの任意の層を後から削除することではない。学習中からルータと通常ブロックを一緒に最適化し、各トークンがどの層で情報を更新すべきかを学習させる。従って、層スキップが可能なモデルを**最初から訓練するアーキテクチャ**として理解する必要がある。

## 手法

### 1. ブロックごとの固定容量kを先に決める

系列長Sの入力に対し、自己注意とMLPへ渡すトークン数をkに固定する。通常のTransformerでは全Sトークンが計算を受けるが、MoDではk個のみが計算経路へ入り、残りS−k個は残差バイパスへ送られる。例えばS=2048、k=256なら、対象ブロックで演算するのは12.5%のトークンである。注意のQK積の要素数は単純な密な計算の概算で `(k/S)^2` に比例するため、全トークンを使う場合より大きく削減できる。

ただし、モデルのすべてのブロックが12.5%容量になるわけではない。著者が良好とした構成では、MoDブロックと通常の全容量ブロックを交互に置く。通常ブロックが定期的に全トークンの情報を統合するため、非常に小さいkでも表現力を維持しやすい。kを減らすほど一回の順伝播は軽くなるが、学習損失が必ず改善するわけではなく、容量とルーティング頻度の共同設計が必要となる。

### 2. 線形ルータと上位k個の選択

各トークンの隠れ表現 `x_i` を学習可能なベクトルで線形投影し、ルータ重み `r_i` を得る。各層で重みの大きい上位k個のトークンを選び、自己注意とMLPからなるブロックへ通す。それ以外は前層の表現をそのまま次へ渡す。計算を通るトークンのブロック出力にはルータ重みを掛け、勾配がルータへ流れるようにする。原著§3.4の式(1)は、通過する場合の更新と残差のみの場合の二分岐を明示する。

選択はMoEでいうexpert-choiceに近い。通常のtoken-choiceでは、各トークンが自分の行き先を選ぶと特定経路へ負荷が集中する可能性がある。MoDは計算経路が上位k個を選ぶため、常にちょうどk個が演算を受ける。計算経路と残差経路の二択なので、複数専門家へ重複配置される問題も起きにくい。容量超過を解決する補助的な負荷分散損失を別途設けずに、静的な演算量を守れることが利点となる。

### 3. 注意とMLPの両方を省略する

MoEが主にFFNの専門家選択を行うのに対し、MoDは注意とMLPを含むブロック全体を通すかどうかを選ぶ。選ばれなかったトークンはその層でQueryとして処理されず、同じ層のKey/Value側にも登場しない。そのため単にトークンの表現更新を省く以上の効果があり、他トークンが参照できる情報も変わる。

これは速度面では有利だが、重要なトークンを計算経路から外すと、後続トークンがその層で参照できないという品質上のリスクがある。ルータは現在のトークンの難しさだけでなく、将来のトークンにとってその情報が必要になるかという因果注意の影響も間接的に学習しなければならない。著者は、頻繁に演算経路へ入るトークンと予測エントロピーの高さに相関がある可能性を報告するが、単純な難易度判定器と同一視してはいない。

### 4. 学習時top-kの非因果性を自己回帰復号で解決する

固定容量top-kは系列全体の重み順位を必要とするため、後から来るトークンをまだ見られない自己回帰生成では、そのまま実行できない。例えば現在のトークンが系列全体で上位k個に入るかは、未来のトークンのルータ値によって変わる。これを無視すると、学習時の選択と生成時の選択が不一致になる。

著者は二つの近似法を検討する。一つは、学習時top-kの採否を教師ラベルにして、ルータ出力が0.5を境に採否を予測できるよう二値交差エントロピーの補助損失を加える方法。もう一つは、元のルータと同じ入力を受ける小さなMLP予測器を別に訓練する方法である。後者は元の言語モデリング損失への影響を抑えられ、著者は補助予測が早期に97%以上の正解率に達することを報告する。前者は主要な言語モデル目的に約0.2〜0.3%の影響を与えると記載する。

自己回帰生成では、これらの予測結果を使ってトークンごとの経路を決める。未来のトークンの重みを参照しないため因果性を守れるが、学習時top-kと完全に同一ではない。原著§4.2とFigure 6は、予測器へ置き換えても評価損失の劣化が小さいことを確認する。学習用の静的容量ルーティングと生成時の因果ルーティングを区別することが、実装上の重要点である。

### 5. MoEとの統合：Mixture-of-Depths-and-Experts

原著§4.3ではMoDとMoEを組み合わせたMoDEを検討する。staged方式はMoDの通過/バイパス判定を自己注意の前に行い、その後にMoEを処理する。注意演算まで省ける点が利点である。integrated方式はMoEの専門家集合に「何もしない専門家」を組み込み、同じルーティングでFFN実行と残差バイパスを選ぶ。こちらはルーティング機構が簡潔になる。

著者は、単にMoEの専門家容量を小さくして溢れたトークンを落とす方式より、明示的に残差経路を選ぶ統合方式の方が良いと報告する。これは、トークンが本来の専門家へ行きたかったのに容量不足で落とされる場合と、計算不要と判断して残差を選ぶ場合が学習上異なるためである。MoDEの結果は両者を組み合わせられる可能性を示すが、商用MoEの全サイズでの高速化を直接保証するものではない。

## 評価条件と比較の読み方

| 項目 | 原著の条件 |
|---|---|
| 主対象 | Decoder-only Transformer。MoDと通常Transformer、ランダムルーティングを比較 |
| モデル規模 | 約60M〜3Bパラメータ。例示する220Mモデルの比較を含む |
| 訓練予算 | 6×10^18、2×10^19、1×10^20 FLOPsでisoFLOP比較 |
| 系列・バッチ | 系列長2048、バッチ128。学習率はcosineスケジュール |
| 容量・頻度 | 12.5〜95%の容量を比較。良好な構成は隔層で12.5%容量 |
| 指標 | 学習の対数確率損失、isoFLOP最適点、順伝播FLOPs、学習ステップ速度、自己回帰生成の評価損失 |
| 生成評価 | 同じ保留データ256,000系列、約5億トークンを用いてtop-kから因果予測器への切替を検証 |
| ハードウェア | TPUトポロジーへの言及はあるが、公開図表だけから一意の型番・台数・帯域条件を復元できない |

isoFLOP比較は、同じ総訓練演算予算の中でモデル規模・構造を最適化する比較である。「同じモデルの一回のforwardが軽い」ことと、「同じ総FLOPsを使ったときに損失が低い」ことは別の主張である。またステップ速度は学習やサンプリングの単位処理速度であり、一般的な本番推論のTTFT・TPOT・多要求スループットをそのまま示す値ではない。

## 評価：定量結果、アブレーションと負の結果

### 1. 隔層12.5%容量の設定が有利

Figure 3の6×10^18 FLOPsでのハイパーパラメータ探索では、全ブロックにMoDを入れるより、**一つおきのブロックだけをMoDにし、k=256/2048=12.5%**とする構成が良好である。残りの87.5%はMoDブロックを残差で迂回するが、通常ブロックでは全トークンが処理される。さらに容量を下げると品質が悪化するため、容量をゼロに近づけるほど得というわけではない。

学習したルータを使わずガウス乱数で重みを決めるランダムtop-k方式は、通常Transformerと学習済みMoDの両方に対して大幅に性能が劣る。これは単に演算回数を減らすだけでは十分でなく、どのトークンへ計算を配分するかを学習する必要があることを示す負の結果である。

### 2. 同等の訓練損失で学習ステップ約66%高速化

Figure 3の220Mパラメータ例では、MoDのある構成がisoFLOP最適の通常Transformerと同程度、あるいはわずかに良い損失を達成しつつ、学習ステップ速度を約66%向上させた。これは同じハードウェアで1ステップあたりの演算が減るためであり、総訓練FLOPsを固定した場合は、より多くのステップや別のモデルサイズへ計算を振り分けられる。

原著は「同じ総訓練FLOPsなら通常モデルより最適損失が最大約1.5%改善する」例と、「同程度の損失で一回のforwardのFLOPsを50%以上減らす」例を示す。**1.5%の損失改善、50%以上のforward演算削減、66%のステップ速度改善は同一条件の三つの独立した計測値ではない**。速度を論じる際はどの比較点かを明示する必要がある。

### 3. 予算を変えたisoFLOP比較

Figure 4は6×10^18、2×10^19、1×10^20 FLOPsの複数予算で、MoDの損失とforward演算量を通常Transformerと比較する。MoDでは、同じ予算で最適なモデルが通常方式より大きくなる傾向がある。これは一つのトークンが全層を通らないため、パラメータ数を増やしてもforwardあたりの演算量を抑えられるからである。

ただし、isoFLOP最適なMoDモデルが必ず最も高速にステップ実行できるわけではない。著者は、MoDの最適点が通常方式と同程度のforward演算量を使う場合もあり、そこから少し小さなMoDを選ぶと品質を維持しつつ実行速度を上げられると分析する。モデルサイズと容量の調整を含む設計空間の最適化であって、同一パラメータ数の単純比較だけでは結論できない。

### 4. 自己回帰サンプリングでの品質

§4.2・Figure 6では、学習時の非因果top-kから因果的な補助予測器へ切り替え、256,000系列・約5億トークンの同一保留データで自己回帰生成を評価する。予測器に置き換えたことによる損失悪化は小さく、MoDが通常Transformerより少ないforward演算で同程度以上の品質を示す構成が残る。補助予測器の選択精度が97%以上に達するという結果と整合する。

ただし、この実験は生成品質のモデル評価であり、長文生成の人手評価、推論サーバーの実機TPOT、KVメモリ削減量を統一条件で比較したものではない。モデルの対数確率が近いことだけで、実際の対話品質やコード生成の品質が同等とは断定できない。

### 5. MoDEの組合せと実装上の交換条件

Figure 7では、MoDとMoEを併用した場合の学習損失の改善が報告される。staged方式は自己注意もスキップできる一方、ルーティング機構が追加される。integrated方式は「無演算の専門家」をMoEへ混ぜるため実装を単純化できるが、自己注意の省略効果はstaged方式と異なる。単に専門家容量を下げてトークンを落とすだけでは、学習した残差選択と同じ性能にはならない。

実機上では、選択したkトークンを集める・処理する・元の位置へ戻す操作にメモリ移動が伴う。理論FLOPs削減がそのまま実時間短縮になるかは、ルータ、gather/scatter、カーネル起動、デバイス帯域、バッチサイズに依存する。原著は学習ステップ速度と一部サンプリングを示すが、現代の大規模サービング環境での最適実装は別途検証が必要である。

## 既存研究との差

MoEは通常、トークンごとに異なるFFN専門家を選び、総演算量を抑えながらパラメータ容量を増やす。MoDは「標準ブロック全体を処理するか、残差で何もしないか」を選ぶので、注意演算とFFN演算の双方を削減できる。通常の早期終了では、あるトークンが途中で終了すると後半層へ戻らないが、MoDは途中の層を飛ばしたトークンが次の層で再び計算を受けられる。層ごとに必要な計算を配分する点が独自性である。

CoLT5などの条件付き計算は軽い経路と重い経路を使い分けるが、MoDは静的な容量kを先に決め、同じ容量の演算テンソルを維持する。通常の可変経路モデルに比べて実機の実行形状が予測しやすい。ただし、ルータとトークン集約の実装コストは残る。FiRSTのように入力系列ごとに層全体をスキップする方式とは粒度が異なり、MoDではトークンごと・層ごとの計算有無を選ぶため、注意の相互参照構造にも影響する。

## 限界・未検証事項

最も重要な制約は、学習時top-kが未来トークンの順位に依存する非因果演算であり、自己回帰生成では近似予測器を追加する必要があることだ。補助損失方式は言語モデリング目的へ0.2〜0.3%の影響を与えると報告され、予測器方式も選択の誤りをゼロにはできない。KVキャッシュについても、層で処理されなかったトークンを後続トークンが参照できないため、従来の密な注意と同じ情報利用は保証されない。

原著の中心実験は60M〜3B程度の新規訓練モデルであり、70B級モデル、量子化済みの既存チェックポイント、ローカルGPUでの後付け高速化を直接示していない。ルータと残差バイパスはモデルの学習と不可分であり、既存の任意モデルへ単にパッチを適用すれば同じ品質になるとはいえない。実機のKVキャッシュ使用量削減は可能性として言及されるが、厳密なサービング実測ではない。

「50%以上のforward FLOPs削減」は演算モデルに基づくもので、プリフィル、逐次復号、gather/scatter、モデル重み転送を含むエンドツーエンド遅延とは区別する。学習ステップ約66%高速化も小規模なisoFLOP比較の例であり、別のTPU/GPUやバッチ条件で同じ倍率が出る保証はない。さらに、ルータが将来の注意に必要なトークンを選べるかという問題は、長文脈や検索課題での品質に影響し得る。
