# PrefillOnly: An Inference Engine for Prefill-only Workloads in Large Language Model Applications

> 1トークン出力に限定されたLLM要求で、非注意層のチャンク化、不要KV破棄、接頭辞命中を反映する完了時間スケジューリングを組み合わせ、最大4倍の処理量を得る。

## 概要

推薦、信用判定、データラベル付けでは、LLMに長い入力を与えても最終出力は「Yes/No」やクラス名など1トークンだけで足りる場合がある。PrefillOnlyはこの処理をプリフィル専用ワークロードとして切り出す。通常の生成基盤は後続デコードを想定して全層のKVキャッシュをGPUに保持するが、1トークンで終了する要求では大部分が再利用されない。

提案は三つの機構を接続する。第一に、メモリピークの主因となる多層パーセプトロン（MLP）など非注意層だけをチャンク化し、注意層は一括計算するハイブリッド・プリフィルを使う。第二に、後続デコードに不要な接尾辞KVを破棄またはCPUへ退避できるようにする。第三に、出力長が固定なので要求のジョブ完了時間（Job Completion Time; JCT）を推定し、接頭辞キャッシュの命中状況が変わるたびに再計算して短い要求を優先する。

vLLM上の実装を4種類のハードウェア、3モデル、2トレースで評価し、比較方式より最大4倍の問い合わせ毎秒を処理しながら平均・P99遅延を低く保った。Llama-3.1-8Bでは100KトークンのKVが約12GBになる一方、1トークン出力なら全層KVを保持する必要がないというワークロード固有性が利得の根拠である。

## 問題設定

通常のLLMサービングでは、プリフィル後に多数のトークンを生成するためKVキャッシュを残す。しかしプリフィル専用要求では生成が1回で終わるので、この設計は不要なGPUメモリを占有する。単純にKVを捨てるだけでも、MLPの中間テンソルが大きいため最大入力長は十分には伸びない。論文のLlama-3.1-8B解析ではMLP中間表現が1トークン当たり28,672要素となり、1層分KVより大きなメモリピークを作る。

既存のチャンク化プリフィルは一時活性値を下げる一方、チャンク間で全層KVを保持し、注意カーネルも小さい単位に分割する。テンソル並列やパイプライン並列は複数GPUへ容量を分散できるが、通信やパイプラインの空き時間を生む。さらに通常の生成要求は出力長が不明なため、到着順などJCT非依存のスケジュールになりやすい。

## 手法

### ハイブリッド・プリフィル

入力トークン列を処理するとき、線形層・MLPではトークン方向を小さなチャンクへ分けて順に計算する。これらの層はトークン間依存がないので、チャンク化しても結果を変えずに一時テンソルのピークを下げられる。一方、注意層は入力全体を通常どおり処理し、細切れ化による注意カーネル効率低下を避ける。

この分離により、一つのモデル順伝播中に「大きな非注意活性値」と「全層分のKV」を同時にGPUへ残す必要がなくなる。単純KV破棄がL4/Llama-3.1-8Bで最大入力長を1.6倍程度しか伸ばせないという観測に対し、ハイブリッド化は別のピーク要因も削る。

### 接尾辞KVの破棄・退避

接頭辞キャッシュは別要求から再利用できるため残す価値があるが、各要求固有の接尾辞KVは1トークン出力後には不要である。PrefillOnlyはGPU容量に収まらない接尾辞を破棄する。論文は破棄を主実装とするが、CPU退避機構があれば退避へ置き換えられる。

これにより、最大入力長を伸ばすためにKVを複数GPUへ分散する必要を減らす。代わりに、破棄した接尾辞が将来別要求の共有接頭辞になる場合には再利用機会を失うため、保持する接頭辞と捨てる接尾辞の境界が重要になる。

### 継続JCT較正とスケジューリング

起動時に最大入力長のダミー要求を実行して必要GPUメモリを測り、残余を接頭辞キャッシュへ割り当てる。オンラインでは各待機要求について、入力長だけでなく現在利用できる接頭辞KVを考慮してJCTを再推定する。

一つの要求を実行すると新しい接頭辞キャッシュが生まれ、他の待機要求のJCTが変わる。そのためスケジューラは各選択前にJCTを再較正し、最短の要求を選ぶ。キャッシュ命中要求が先に処理されやすくなり、そのキャッシュが無関係な要求で追い出される確率も下がる。長時間待つ要求には待機時間に応じた補正を加え、飢餓を抑える。

## 評価条件・主要結果

| 項目 | 代表条件・結果 |
|---|---|
| 実装 | vLLMを基盤、ハイブリッド処理は `torch.compile` を利用 |
| 評価範囲 | 4ハードウェア構成、3 LLM、2要求トレース |
| 主指標 | 問い合わせ毎秒、平均遅延、P99遅延、最大入力長 |
| 主結果 | 平均・P99遅延を膨らませず最大4倍の問い合わせ毎秒 |
| メモリ観測 | Llama-3.1-8Bの100K入力でKV約12GB |
| 既存チャンク化の負例 | 20K入力・512チャンクでエンドツーエンド処理量が14%低下する測定 |

この結果は一般的な長文生成を4倍高速化する主張ではない。1トークンだけを返す専用ワークロードだから、KV保持とJCT不確定性を取り除ける点が本質である。

## 既存研究との差

PagedAttentionや通常のvLLMは任意長出力を想定し、デコード再利用のため全層KVを管理する。チャンク化プリフィルはメモリピークを抑えるが注意処理も分割する。PrefillOnlyは「非注意層だけチャンク化」「注意層は通常処理」という分離に加え、1トークン終了という保証をスケジューラまで利用する。

## 限界

適用対象は出力を1トークンへ制約できる分類・ランキング型用途であり、長い自然言語生成にはそのまま使えない。接頭辞キャッシュの再利用度が低いワークロードでは継続JCT較正の利得も小さくなる。破棄方式では後から必要になるKVを復元できないため、将来の共有接頭辞として価値がある範囲を誤ると再計算が増える。
