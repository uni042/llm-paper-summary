# One Pass Streaming Algorithm for Super Long Token Attention Approximation in Sublinear Space

## 書誌
Raghav Addanki, Chenyang Li, Zhao Song, Chiwun Yang。正規識別子 `arXiv:2311.14652`。

## 概要
標準attentionは系列長nに対してattention matrixがn×nとなり、素朴には二次の時間・空間を要する。既存のpolynomial approximationはsoftmax attentionを低ランク因子 `U1,U2 ∈ R^{n×t}` で近似し、計算時間をほぼ線形へ近づけるが、近似行列 `U1 U2^T` を明示的に扱えば依然として二次空間が必要になる。またストリーミング生成では過去K/Vの保持自体も長文脈で重い。

本論文は、データを一度だけ読むストリーミング設定で3つのsketch matrixを更新し、K/V全体を保存せずattention出力を近似するアルゴリズムを与える。狙いは `n >> 2^d` という極端に長い系列で、nに対してsublinearな `o(n)` 空間を実現することである。

重要なのは実装カーネルの高速化論文ではなく理論アルゴリズムである点である。論文の主要主張は、系列長が増えるほど誤差保証が小さくなる一方、保持するsketchの大きさをほぼ一定にできるという空間複雑性であり、実際のLlama等でのトークン毎秒改善を示すものではない。

## 問題設定
単層attentionで `Q,K,V ∈ R^{n×d}` とする。長文脈ではK/Vだけでも `O(nd)` の状態が必要で、完全attention行列を作れば `O(n^2)` となる。polynomial methodは指数kernelを多項式特徴へ写像し `U1 U2^T` で近似できるが、ストリーミング環境でこのn依存状態をそのまま持つことは目的に反する。

そこで「過去トークンを再読できない1-pass」「nが非常に大きい」「保持空間をn未満にする」という制約下で、attention出力を近似する問題として定式化する。

## 手法
### polynomial attention approximationを入口にする
softmaxの指数kernelを低次元特徴へ近似し、query側・key側の特徴因子へ分解する。これにより全query-key pairを明示列挙する代わりに、集約可能な統計へattention計算を変形する。

### 三つのsketch matrix
ストリームから到着するK/V情報をsketchへ逐次集約し、元のK/V行列を保存しない。sketchは将来queryに必要な内積・正規化項を復元できる統計として働く。入力を一度処理した後に過去データへ戻らないため、長大な履歴を外部メモリへ置いて再走査する方式とは異なる。

### sublinear space保証
対象領域 `n >> 2^d` では、sketchサイズをnに対してsublinearに選びながら近似誤差を保証する。n増加に伴って理論誤差保証が改善するという性質を示し、超長系列ほど空間効率の利点が明確になる。

## 評価条件・主要結果
本研究の中心は理論的な複雑性・誤差保証であり、一般的なLLMシステム論文のようなGPU実機ベンチマークは主要証拠ではない。

|観点|内容|
|---|---|
|対象|単層softmax attention近似|
|系列条件|`n >> 2^d` の超長系列|
|入力|Q/K/Vストリーム|
|pass数|1 pass|
|保持状態|3つのsketch matrix|
|空間|nに対してsublinear `o(n)`|
|主評価|理論誤差・空間複雑性|

このため、実モデルでKV cacheを何GB削減するか、prefill/decodeが何倍速くなるか、生成品質がどの程度変化するかは論文の主要結果として報告されない。実装上の価値は、理論的に「履歴全保持が不要なattention近似」が可能であることを示す点にある。

## 既存研究との差
FlashAttention系はexact attentionのI/Oを最適化するが、KV履歴そのものの長さ依存容量を消さない。polynomial attention近似は計算量を下げてもn依存因子を保持し得る。本方式はストリーミングsketchへさらに変形し、過去K/Vを保持しない空間保証を主目的にする。

## 限界
理論設定は `n >> 2^d` の極端な長系列を前提とし、通常の数千〜数十万tokenで常に実用上有利とは限らない。単層attentionの近似保証から、多層Transformer全体の生成品質・数値安定性・GPUカーネル効率へは追加検証が必要である。実機サービングのend-to-end評価が不足しているため、現時点では実装方式というより理論的候補として扱うべきである。
