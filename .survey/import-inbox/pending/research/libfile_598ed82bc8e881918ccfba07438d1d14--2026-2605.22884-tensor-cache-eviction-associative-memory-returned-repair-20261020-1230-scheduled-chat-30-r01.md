# Tensor Cache：追い出されたKVを固定長の連想記憶へ移す二層キャッシュ

## 概要

自己回帰Transformerの鍵・値（KV）キャッシュは、全トークンを保存すると文脈長に比例して増える。直近 $W$ トークンだけを残すスライディング窓（sliding window）はメモリを一定に抑えるが、窓の外へ出たトークンを完全に捨てる。古い指示、固有名詞、対応するキーと値を後で参照する課題では、窓の外の情報を検索できなくなる。Tensor Cache（TC）は、この追い出しを単なる削除ではなく**第二階層の連想記憶への書込み**へ変える。

各Transformer層の第一階層（L1）は直近トークンの正確なsoftmax注意を担当する。第二階層（L2）は、窓から追い出されたKV対を外積で足し込む固定サイズの行列 $A$ であり、将来の問い合わせ $q$ は $qA$ という行列積で古い情報を読み出す。学習可能なゲートでL1とL2の出力を合成する。L2には個々の古いトークンのKVを残さないので、保存状態は文脈長に対して一定になる。ただしL2は複数の連想を同じ行列に重ねるため、**全KVを保存する注意と等価ではない**。

論文のもう一つの焦点は訓練時の書込み式である。チャンクの平均キーと平均値の外積を一度書き込む簡易法は、同じトークンに由来しないキーと値の組を $C^2-C$ 個作ってしまう。これを、トークンごとの外積を減衰重み付きで並列合計する式へ置き換え、逐次更新と相対誤差 $10^{-7}$ 未満で一致させる。合成記憶課題では窓方式が偶然水準の約6%に落ちる条件でTCは100%を維持し、Full KVより72–84%少ない状態量で済んだ。OpenWebTextの32,768トークン評価ではTCの負の対数尤度（NLL）が5.14で、Full KVの6.00、Window KVの5.44を下回った。一方、復号処理量はWindow KVより約30%低く、品質と速度の交換がある。

## 問題設定と設計目標

全KVを保持する方式では、層数、注意ヘッド数、ヘッド次元、文脈長、同時実行要求数に応じてメモリ使用量が増加する。窓方式は過去 $W$ 個だけを保持するため容量を固定できるが、$W$ より前の証拠は参照不能となる。接頭辞を一部だけ残すStreamingLLMの注意シンクも、個々の古いKVをすべて保存するわけではない。

TCの目標は、窓内では正確なsoftmax注意の品質を保ちつつ、追い出した情報を一定サイズの連想記憶へ圧縮して**長期依存を部分的に回復**することである。これはオフロード先をGPUからCPUへ変える仕組みではなく、KV表現そのものを外積の重ね合わせに変えるモデル構造上の改変である。従って、既存の事前学習済みTransformerへメモリ管理ポリシーだけを差し替えれば同じ品質で動くという方式ではなく、学習可能なゲート・更新率・減衰率を含めて訓練する必要がある。

著者らは、全KV、窓のみ、StreamingLLM、Infini-attention、TCの五方式を、同じバックボーン、トークナイザ、最適化器、精度、学習予算で比較する。窓型の比較方式では同じ直近窓を使い、古い文脈の表現方法の差を測る。ただし長文脈評価でFull KVには学習時の最大長を超える位置へNTK対応のRoPE拡張を適用するため、「全KVの保存」と「位置埋め込みの外挿失敗」が結果に混在し得ることを明記している。

## 手法

### 1. L1：直近KVの環状バッファと正確な注意

バッチ数 $B$、ヘッド数 $H$、ヘッド次元 $D$ に対して、各層は問い合わせ・鍵・値を作り、直近 $W$ 個の鍵・値を形状 $B\times H\times W\times D$ の環状バッファに保持する。問い合わせ $q_t$ はこの窓のKVへ通常の因果softmax注意を実行し、局所出力 $y_t^{\mathrm{local}}$ を得る。鍵は回転位置埋め込み（RoPE）適用後にバッファへ格納されるため、後でL2へ移す鍵もRoPE適用済みである。

新トークンのKVが到着して窓が満杯なら、最古のKV対 $(k_{\mathrm{old}},v_{\mathrm{old}})$ を追い出して空きスロットを作り、そこへ新しいKVを格納する。TCは**この追い出された対だけ**をL2更新に使う。直近窓に残るトークンはL1の正確な注意だけが担当し、窓の外のトークンはL2が担当する。この役割分離は、すべてのトークンをL2にも書く方式と異なり、同じトークンを局所注意と圧縮記憶の双方で二重計上することを避ける。

### 2. L2：外積の重ね合わせを固定サイズ行列へ蓄積

各層・各ヘッドは $D\times D$ の記憶行列 $A$ を持ち、初期状態はゼロとする。標準の書込み規則は

$$A\leftarrow\lambda A+\eta\,(k_w\otimes v_w)$$

である。$k_w,v_w$ はL1から追い出されたKV対、$\lambda$ は過去の記憶を減衰させる係数、$\eta$ は新しい対の書込み率で、どちらもヘッドごとにシグモイド変換された学習可能パラメータである。外積 $k_w\otimes v_w$ は一つのキーと値の対応を行列として記憶し、古い記憶と加算して重ねる。保存状態は古いトークン数ではなく $BHD^2$ に比例する。

この行列からの読出しは $r_t=q_tA$ であり、外積を展開すると $q_t(k_i\otimes v_i)=\langle q_t,k_i\rangle v_i$ となる。したがって問い合わせに似たキーの値が、線形注意の形で加重合成される。L2の出力はヘッドを結合して別の射影 $W_{\mathrm{tc}}$ に通し、学習ゲート $g$ を用いて $y_t=y_t^{\mathrm{local}}+\sigma(g)m_t$ としてL1へ足す。ゲートは記憶をどの程度利用するかを学習し、局所注意の正確な経路を残す。

代替としてデルタ規則（delta rule）も実装される。これは $A\leftarrow\lambda A+\eta\,k_w\otimes(v_w-k_wA)$ とし、現在の記憶が既に予測できる値との差分だけを書き込む。重複記憶を抑える利点はあるが、各トークンの残差が直前の $A$ に依存するため、標準の外積規則ほど簡単には正確なチャンク並列化ができない。論文は既定で外積規則を使う。

### 3. チャンク平均の外積が作る偽の連想

訓練で各トークンを逐次処理すると時間がかかる。そこでチャンク長 $C$ のキーと値を平均して、$\bar k\otimes\bar v$ を一度書く近道が考えられる。しかし

$$\bar k\otimes\bar v=\frac{1}{C^2}\sum_{i=1}^{C}\sum_{j=1}^{C}k_i\otimes v_j$$

であり、本来必要な同じトークン同士の $k_i\otimes v_i$ 以外に、$i\neq j$ の交差項が $C^2-C$ 個入る。例えばあるトークンのキーと別トークンの値が結び付けられ、存在しない記憶が作られる。推論時の逐次書込みにはこのような交差項がないため、訓練で学んだ記憶の統計が推論時と食い違う。

この差は、保存指示、埋め草、照会が同じ大きなチャンク内に入る合成課題で特に深刻である。チャンク平均を使った $C=64$ の条件では回答精度が0.265へ低下した。単にチャンクを大きくして訓練を速くすることは、モデルが学ぶキーと値の対応を破壊する危険がある。

### 4. 重み付き並列走査による逐次書込みの再現

著者らは外積更新の再帰式を展開し、長さ $C$ のチャンクに対して

$$A\leftarrow\lambda^C A+\eta\sum_{t=0}^{C-1}\lambda^{C-1-t}(k_t\otimes v_t)$$

を計算する。各トークンの外積を先に作って減衰重みで合計するので、別トークン同士の偽交差項は生じない。この式は外積規則をトークンごとに $C$ 回適用した閉形式であり、バッチ行列演算によって並列に求められる。著者らは逐次更新との相対誤差が $10^{-7}$ 未満であることを確認した。新しい外積記憶演算を発明したのではなく、既存の線形再帰の並列走査を**追い出し条件付きL2記憶の訓練**へ適用したことが寄与である。

デルタ規則では更新前の記憶に依存する残差が必要なため、チャンク開始時の $A$ を各位置で共有する近似を使う。これは厳密な逐次デルタ更新と同一ではない。さらに原著は、訓練時のチャンク走査がチャンク内の**全トークン**を書き込む一方、逐次推論はL1から追い出したトークンだけを書き込むと明記する。したがって重み付き並列走査で「チャンク平均による偽交差項」は除去できても、訓練時と推論時の**書込み対象集合の違い**まで完全に消えるわけではない。

### 5. 推論時の一ステップと計算費用

推論の一ステップは、現在の問い合わせを生成し、L1の窓内softmax注意を計算し、満杯の窓から最古のKV対を取り出してL2の $A$ を更新し、新KVをL1へ入れ、問い合わせでL2を読み、学習ゲートで二経路を融合する順に進む。L1の容量は $W$、L2の行列は $D\times D$ と固定されるので、過去トークンが増えても保持する状態量は一定である。

ただしL2の行列読出しと外積更新は追加の行列演算を必要とする。TCはメモリ節約だけを目的にした単純なKV削除より計算量が多く、短い文脈や十分なGPUメモリがある場合に有利とは限らない。L2の行列へ多数の連想を重ねるとキー同士の干渉も増える。古い情報を保持する能力は無限ではなく、減衰係数とヘッド次元、学習データ中のキーの相関に依存する。

保持状態量の測定ではFull KVが4K時の約0.25GBから128K時の約7.75GBへ増えるのに対し、固定窓の四方式は約0.75–0.80GBにとどまる。TCがWindow KVより追加する約0.04GBはL2行列の費用である。これらは論文の対象モデル・設定での値であり、全てのモデルに共通する絶対容量ではない。

| 64 | 128.4 | 79.0 | 51.8 |
| 128 | 240.8 | 143.8 | 84.2 |

容量は最古のキーの再構成相対誤差が1.0を超えるまでの書込み数で定義する。減衰ありでは $\lambda=0.995,\eta=0.05$ を使う。次元を増やすと容量は増えるが、無関係なキーが多数入ると外積の干渉が大きくなる。特に減衰ありの $D=128$ で容量は84.2書込み程度であり、128次元なら128個の連想を完全保存できると考えるのは誤りである。

|---:|---:|---:|
| 1 | 1.000 / 1145 | 1.000 / 1607 |
| 4 | 1.000 / 359 | 1.000 / 428 |
| 8 | 1.000 / 198 | 1.000 / 243 |
| 16 | 1.000 / 119 | 1.000 / 142 |
| 32 | 1.000 / 82 | 1.000 / 92 |
| 64（チャンク平均の比較方式） | **0.265 / 35** | **0.265 / 35** |

重み付き並列走査を使う $C=1$ から32では両規則とも精度1.000を維持し、外積規則の訓練時間は1145秒から82秒へ約14倍短縮する。一方、$C=64$ の**チャンク平均**比較は35秒とさらに速いが、精度が0.265へ崩壊する。これは「チャンク長64なら正しい並列走査も必ず0.265になる」という結果ではない。原著の表4で64は別の近似式を用いた比較であり、原因はチャンク内の誤ったキー・値の組合せにある。

## 既存研究との差

全KV保持は古い内容へ直接注意できるが、メモリが系列長に比例する。Window KVとStreamingLLMは残すトークンを制限するため固定容量だが、失われたKVを表現する追加の記憶を持たない。Infini-attentionやmLSTMも外積型の連想記憶を使うが、各トークンを逐次書き込む設計である。TCの固有性は、**窓から追い出したときにだけ**書き込むことにある。古いトークンと新しいトークンの責任範囲をL2とL1で分離し、直近の精密な注意を維持しながら古い情報を近似的に読む。

さらに、チャンク平均の外積を逐次外積の近似とみなすと、本来存在しないキーと値の組が大量に生じることを数式で明示した。標準的な重み付き並列走査の適用でこの差を除去し、訓練効率を保ちながら合成想起精度を回復する。新しい数学的外積恒等式そのものが寄与ではない点は、原著も明確に区別している。

## 限界と導入判断

TCは外積の重ね合わせにより情報を圧縮するので、記憶の容量には上限があり、似たキーや長期の減衰で古い情報が失われる。全KVに対する厳密同等性はない。直近窓とL2の融合は学習可能なパラメータを伴い、既存のモデルにKV管理だけを外付けして無損失で使える方式ではない。特に本研究の130MパラメータモデルでのNLLや処理量を、数十B級の既存モデルへそのまま外挿できない。

実装上は、推論時に追い出したトークンだけを書き込む一方、訓練時のチャンク並列処理は全トークンを更新するという差が残る。デルタ規則のチャンク開始時残差近似も厳密ではない。チャンク内に保存から照会までの全過程が収まる場合、正しい外積走査でも照会が同じチャンク内の保存を参照できない失敗がある。著者らはチャンク長の選択と訓練時の展開方式の改善を今後の課題としている。

GPU上の復号処理量はWindow KV/StreamingLLMより約30%低い。固定メモリ化だけを目標にするなら窓方式の方が単純で高速であり、TCは**窓外の連想想起が品質上重要な用途**で追加の計算費用を払う選択となる。OpenWebTextでFull KVよりNLLが低い結果は、Full KVが学習長外で位置埋め込みを外挿していること、評価種の非対称性を踏まえて解釈する必要がある。
