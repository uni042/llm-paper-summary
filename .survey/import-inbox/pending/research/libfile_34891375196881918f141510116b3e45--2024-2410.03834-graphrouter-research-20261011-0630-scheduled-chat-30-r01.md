# GraphRouter — グラフに基づく大規模言語モデル選択

## 概要

GraphRouterは、一つの大規模言語モデル（Large Language Model; LLM）をすべての質問に固定して利用するのではなく、質問内容と要求品質・価格の重みを見て複数モデルから適切なものを選ぶ推論時ルータである。モデルの性能はタスクや質問によって変わり、小さいモデルが大きいモデルより正確に答える場合もある。常に最大モデルを使うと費用が高く、常に最小モデルを使うと精度が不足する。従来の二択ルータやモデル名だけを埋め込む方式では、候補モデルが増えた場合や新しいモデルが登場した場合に適切な選択が難しい。

本研究は、タスク、質問、LLMの三種類のノードを持つ異種グラフ（heterogeneous graph）を構築し、過去の質問とモデルの回答品質・API費用を辺の属性として表現する。異種グラフニューラルネットワーク（Graph Neural Network; GNN）が、未知の質問と候補LLMを結ぶ辺の良さを予測し、品質と費用の重み付けに応じたモデルを選択する。原著の主表では、品質と費用を同等に重視した条件の報酬が0.209となり、比較対象の最高0.196を上回った。新しいモデルがテスト時に追加される条件では、少数の相互作用事例から再学習なしで報酬0.207を達成した。

この研究の「費用」は主として**LLM APIのトークン単価から計算した応答費用**である。GPUカーネルの高速化、KVキャッシュの削減、CPU/GPUオフロードやサービングの実測スループットを直接改善した結果ではない。モデル選択を通じて外部推論サービスの利用費を最適化するアルゴリズムとして位置付ける。

## 問題設定と既存手法の課題

多様な質問に対して複数LLMの候補があるとき、各モデルの回答品質と価格は質問ごとに異なる。推論時ルーティングの目的は、特定の質問に最も大きいモデルを選ぶことではなく、予算と品質目標に応じた適切な候補を選ぶことである。二択のHybrid LLMは小型・大型モデル間の選択に限定される。FrugalGPTは質問に対するモデルごとの品質を予測して費用と比較するが、モデルを名前やIDとして扱うと、新しいモデルの特性を既存の学習表現から推測しにくい。バンディット型のC2MAB-Vは探索と利用を調整するが、候補が追加されると相互作用の収集と適応が必要になる。

GraphRouterは、タスク・質問・モデルの相互関係を一つの異種グラフへ統合する。単純な質問分類器と違い、モデルの得意分野、タスクの類似性、過去の回答品質、価格の関係を隣接ノードから集約できる。新しいLLMを追加する際は、そのモデルの説明文から初期表現を作り、少数の回答例をグラフへ追加して選択できる。著者はこの能力を帰納的な一般化（inductive generalization）と呼び、追加モデルごとにルータを最初から再訓練する転導的方式と区別している。

## 手法

### 1. 相互作用履歴を異種グラフへ変換する

学習データは、タスク、質問、候補LLM、そのLLMの回答、回答品質、トークン課金額から構成される。タスクノード、質問ノード、LLMノードを作り、タスクと質問の所属関係、および質問とLLMの回答履歴を辺で結ぶ。タスクと質問の辺には関係の存在を表す特徴を置き、質問とLLMの辺には回答品質と費用を連結した特徴を置く。異なる種類の辺を同じ行列として扱うのではなく、メッセージの種類ごとに異なる学習重みを用いる。

この構造の利点は、質問とモデルの直接的な観測だけでなく、同じタスクに属する別の質問や同じモデルが過去に解いた別の質問を通じて情報を共有できる点にある。例えば、あるモデルが読解問題では高品質でも算数では弱い場合、単なるモデル名では表せない条件付きの能力をグラフの隣接関係から推定する。これは入力質問を専門家層へ割り振るMoE内部ルータとは異なり、**独立したLLMサービスのうちどれを呼び出すか**を決める外側のルータである。

### 2. タスク・質問・モデルの初期埋め込みを作る

質問ノードは事前学習言語モデルによる質問テキストの埋め込みを使用する。タスクノードは、追加の生成モデルにタスクの説明文を作らせ、その説明をBERTなどの事前学習言語モデルで埋め込む。LLMノードについても、候補モデルの得意分野、価格、文脈長などを記した説明文を作り、同じく文章埋め込みに変換する。

新しいモデルを単なる未学習IDとして扱わず、説明文の特徴を使って既存モデルと比較できることが帰納的選択の鍵になる。ただしこの初期化にはモデル説明の作成と埋め込み計算が必要であり、説明文の品質や価格の更新頻度に依存する。原著では生成モデルを使った説明文作成を記述するが、説明文作成に必要な追加API費用をすべての運用条件で測ったわけではない。

### 3. 異種グラフニューラルネットワークで関係を集約する

グラフの各ノードは、隣接ノードの表現を種類別の学習重みで変換し、平均集約して自分の表現と連結する。タスク・質問・LLMの三種類について異なる更新関数を持つ。質問ノードへはタスク情報とモデルとの相互作用情報が流れ、モデルノードへは過去の質問との回答履歴が流れる。実験の主構成は隠れ次元32、2層のグラフニューラルネットワークである。

学習時には質問ごとに報酬が最大のモデルを正解の接続先とし、その質問と正解モデルの辺に1、他モデルとの辺に0のラベルを付ける。タスク表現と質問表現を多層パーセプトロンで結合し、候補LLMの埋め込みとの内積から辺の適合度を予測する。推論時は各候補LLMの辺予測スコアを比較し、最大のモデルを選択する。これはモデル応答を実際に全部生成してから最良を選ぶ方式ではないため、全候補モデルを毎回実行する費用を避けることを意図する。

### 4. 品質と価格の重み付けを報酬へ変換する

回答品質をPerformance、API費用をCostとして正規化し、報酬を $Reward=\alpha\cdot Performance-\beta\cdot Cost$ と定義する。品質優先では$(\alpha,\beta)=(1,0)$、均衡では$(0.5,0.5)$、費用優先では$(0.2,0.8)$を使用する。これらはモデルの内部計算量を直接表す重みではなく、サービス利用者が重視する品質と価格の優先度を表す。

学習では各重み付けの条件に応じて最良モデルのラベルが変わる。したがって「最良のモデル」は固定ではない。価格を無視すれば高精度モデルが選ばれやすく、価格を強く重視すれば十分な品質を持つ安価なモデルが選ばれやすい。推論時には質問とタスクの埋め込みを得て、候補LLMごとの辺予測値を比較するだけで選択先を決める。選択されたLLMの回答を利用者へ返し、その実績を後の学習に利用できる。

### 5. 新規モデルの少数事例適応

原著の新規LLM条件では、10モデルのうち最初の6モデルだけを通常学習に使い、残り4モデルを未知モデルとして扱う。新規4モデルについて、訓練集合から無作為に選んだ80質問への相互作用を補助データとして与える。GraphRouterはこの補助データを学習器の再訓練に用いず、テスト時にグラフへ追加して推論する。これにより既存ルータが必要とする再訓練時間を避ける。ただし**完全なゼロ事例ではない**。新規モデルの説明文と80質問分の実績が利用可能という前提である。

## 評価条件

| 項目 | 原著の設定 |
|---|---|
| 評価タスク | Alpaca質問応答、GSM8K数学、SQuAD読解、Multi-News要約 |
| サンプル数 | 各600質問、計2400質問 |
| 候補LLM | Llama、Mistral、Mixtral、Qwenなど10モデル |
| 品質評価 | タスクごとのF1または正確率を使用 |
| 費用評価 | Together APIの100万トークン当たり単価と入出力トークン数から算出 |
| 分割 | 質問単位で学習70%、検証10%、テスト20% |
| 比較対象 | 最大モデル固定、最小モデル固定、Prompt LLM、Hybrid LLM、FrugalGPT、C2MAB-V、Oracle |
| 主指標 | 正規化した品質、正規化したAPI費用、加重報酬 |
| 新規モデル試験 | 6モデルを学習に使用、4モデルを未知扱い、80質問の補助事例を提示 |
| ルータ実装 | PyTorch、PyTorch Geometric、2層GNN、隠れ次元32、バッチ32 |
| 実験計算機 | 単一NVIDIA A100 GPUでルータ実験、候補LLMの回答はAPI経由 |

原著の表3における価格は、例えば7Bモデルで100万トークン当たり0.2、70B級で0.9などの**実験時点のAPI価格**である。これを2026年現在の実際の課金額とみなしてはならない。また、原著はGPT-2トークナイザを用いて入出力トークン数を数えると記述しており、各API事業者の実課金トークン数と完全一致する保証はない。

## 主要結果

### 1. 品質と費用の重み付けごとの比較

| 方式 | 品質優先の報酬 | 均衡の報酬 | 費用優先の報酬 |
|---|---:|---:|---:|
| 最大LLM固定 | 0.431 | -0.220 | -0.701 |
| 最小LLM固定 | 0.279 | 0.124 | -0.009 |
| FrugalGPT | 0.517 | 0.164 | 0.057 |
| C2MAB-V | 0.479 | 0.196 | 0.031 |
| GraphRouter | **0.539** | **0.209** | **0.064** |
| 理想選択（Oracle） | 0.588 | 0.231 | 0.072 |

原著表4から抜粋。品質優先ではGraphRouterの0.539はFrugalGPTの0.517より高く、均衡では0.209がC2MAB-Vの0.196を上回る。費用優先では0.064がFrugalGPTの0.057を上回る。原著が述べる「最良の比較対象より最低12.28%改善」という値は、報酬の定義と比較条件に依存する**正規化報酬の改善**であり、GPU演算が12.28%速くなる意味ではない。

均衡条件のGraphRouterは正規化品質0.448、正規化費用0.031で報酬0.209となる。FrugalGPTは品質0.400、費用0.072、報酬0.164である。一方、品質優先のGraphRouterは品質0.539、費用0.725であり、品質を重視すると安価なモデルだけを使うわけではない。報酬が高いからといって品質と費用の両方が全ての条件で同時に最良になるとは限らない。

### 2. 未知モデルを含む少数事例条件

| 方式 | 報酬（均衡） | 時間費用（原著の値） | C2MAB-V比の時間費用削減 |
|---|---:|---:|---:|
| Hybrid LLM | 0.010 | 273.45 | 49.57% |
| FrugalGPT | 0.171 | 63.15 | 88.35% |
| C2MAB-V | 0.189 | 542.25 | 0% |
| GraphRouter（再学習なし） | **0.207** | **3.00** | **99.45%** |
| GraphRouter（再学習あり） | 0.219 | 30.00 | 94.47% |

原著表5による。時間費用は新規モデルに適応するための学習時間と推論時間を合わせた比較値であり、**1件のLLM回答を生成する遅延ではない**。原著は再学習なしのGraphRouterがC2MAB-Vより報酬を9.52%改善し、時間費用を99.45%削減すると述べるが、主にルータ適応・訓練の負担を避けた効果である。再学習ありのGraphRouterは報酬0.219と高いが時間費用30.00を要し、再学習なしの0.207・3.00と明確な交換条件がある。

### 3. グラフ構造の構成要素除去

隠れ次元を16から80まで変えると、報酬は32付近で最大となり、それ以上では低下した。グラフニューラルネットワークの層数を0から5まで変えると、2層で最良となり、深すぎると平滑化や過学習による悪化が見られると著者は説明する。したがって「グラフを大きくすれば選択精度が単調に改善する」とは言えない。学習コストと予測精度の両方を考えて、比較的小さな2層・32次元を採用している。

## 既存研究との差

二択のHybrid LLMと異なり、GraphRouterは多数モデルの候補を同時に扱う。FrugalGPTのようにモデル名や識別子に基づく品質予測だけを行うのではなく、タスク・質問・モデルの相互作用を異種グラフとして表現する。C2MAB-Vのようにモデル追加時の探索・再訓練を必要とする方式と比べ、モデル説明文の埋め込みと少数の補助相互作用を利用して帰納的に新規モデルへ適応する点が新しい。

この研究は、GPUの実行中に専門家を切り替えるMoE内部ルーティングとは対象が違う。GraphRouterが選ぶのは別々のAPIモデルであり、計算資源をどのGPUに割り当てるか、重みをどの階層メモリへ置くか、KVキャッシュをどのノードに保持するかを制御しない。サービング基盤と組み合わせる場合は、ルータの判断をモデル配置や価格に接続する追加設計が必要である。

## 限界・未評価事項

**第一に、費用の中心はAPI課金額であり、物理GPU資源ではない。** 原著の報酬はトークン単価に基づく費用と品質を正規化して重み付けする。GPUメモリ使用量、エネルギー消費、GPU占有率、同時要求の処理率、ネットワーク通信費、待ち行列の遅延を最適化した実験ではない。単一A100はルータの実験計算機であり、候補LLMすべてを同じGPUへ常駐させた測定ではない。

**第二に、新規モデルの適応には少数の実績データが必要である。** 新規4モデルを含む条件では80質問の補助事例を与えており、未知モデルの説明文だけで高精度選択ができると実証したわけではない。新モデルの料金や能力が頻繁に変わる場合は、説明文と相互作用記録を更新する必要がある。さらに、評価時の価格は2024〜2025年頃のAPI単価に依存し、価格変化で最適選択が変わり得る。

**第三に、実験は4タスク・各600質問・10モデルへ限定される。** 学習分割とテスト分割は質問単位であり、タスクそのものが完全に未知となるゼロショット条件、何百ものモデルがある市場、長期的なオンライン分布変化で同じ報酬を維持できるかは不明である。タスクやモデルの説明文を生成する外部モデルの誤りがルーティングへ及ぼす影響も十分に分離されていない。

**第四に、品質の推定には既存ベンチマークの限界がある。** GSM8Kは正答率、他タスクはF1などを用いており、タスク間で正規化しても利用者の主観的な回答品質と一致するとは限らない。誤った回答の安全性、長文生成の忠実性、モデル間の出力形式の違い、品質測定器のバイアスを含めたサービス水準目標の評価はない。

**第五に、ルータ自体の運用費用と品質変動の評価が不足する。** 初期のタスク・モデル説明生成、事前学習言語モデルによる埋め込み、異種グラフの更新、オンライン予測、履歴蓄積の費用が発生する。原著の表5の時間費用は新規モデル適応の学習と推論の合計であり、利用者が感じる最初のトークン遅延、バッチ処理率、モデルロード時間を直接示さない。

**第六に、報酬の重み付けは外部設定である。** 品質優先、均衡、費用優先の三つの係数は人手で選んだ例であり、ユーザーごとの厳密な品質下限や価格上限を保証する制約付き最適化ではない。例えば品質優先での費用は高くなり得る。単一の正規化報酬が高いだけで全ユーザーの制約を満たすとは限らない。
