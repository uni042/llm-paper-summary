# Gradual Binary Search：射影別クリッピング探索とHadamard次元拡張によるW/A/KV 3-bit量子化

## 概要

大規模言語モデルの低ビット事後量子化では、活性値の外れ値が量子化範囲を占有し、3〜4ビットの小さい整数レンジに通常の値を十分に割り当てられない。QuaRotやSpinQuantのような直交回転は外れ値を分散するが、回転だけで3ビットの重み・活性・KVキャッシュを同時に量子化すると、モデルによって正答率が崩壊する。

本研究のGradual Binary Search（GBS）は、各線形射影の量子化時に**クリッピング比をWikiText-2困惑度（PPL）で逐次探索**する。前の射影を量子化した状態を固定し、次の射影を低ビット化しながらその最適なクリッピングを探すため、全射影を同時に一律設定するより累積誤差を抑えやすい。さらにQwenのように特徴次元が2の冪ではないモデルへ、ゼロ埋めとPaley構成のHadamard行列を組み合わせた次元拡張を適用する。

Mistral 7B v0.1を重み・活性・KVとも3ビット化した実験では、QuaRot単独の6課題平均18.43%がGBS併用58.31%へ改善した。ただしFP16の71.08%には届かない。Llama3 8BではQuaRot単独のPPL1315がGBS併用で12.62へ改善する一方、FP16の6.13より大きく悪化したままである。著者の「最大40%改善」は主として正答率の**パーセントポイント差**を指す結果であり、生成速度が40%速くなるという意味ではない。

## 背景：なぜ回転だけでは低ビット化が足りないか

線形層の活性値Xをbビットの対称一様量子化へ変換するとき、通常は最大絶対値に比例するスケールΔを決めて丸める。外れ値が非常に大きいとΔが大きくなり、大多数の通常値は同じ量子化ビンに潰れる。重みの量子化より活性値の量子化が難しいのは、入力トークンや層によって外れ値が急変するためである。

Hadamard回転は、±1からなる直交行列でチャネルの値を混ぜ、極端な成分を複数次元へ分散する。ランダムな直交回転より外れ値を抑えるという理論的議論も論文は与える。しかし変換後にも残る外れ値をどこまで切り詰めるかは射影ごとに異なる。ある層では強いクリッピングが有利でも、別の層では少し切り詰めるだけで重要情報が失われる。量子化テンソルの再構成誤差を小さくする設定が、言語モデルの最終的なPPLを最小化するとは限らない。

QuaRotの実装には、標準的な高速Hadamard変換のために特徴次元が2の冪、または対応可能な小行列の積へ分解できることを要求する制約もある。Qwen2.5-1.5Bの1536次元のように、既存実装の行列生成条件へ直接合わないモデルでは回転パイプラインが適用できない。GBSはクリッピング最適化を、次元拡張は回転行列の適用可能性をそれぞれ解決する独立した寄与である。

## 手法：Gradual Binary Searchの逐次最適化

GBSの入力は、学習済みモデルM、校正データD、探索幅の終了閾値εである。まず各射影のクリッピング比の候補区間を0〜1に置く。モデルの最初の線形射影を量子化し、現在までに決めた射影のクリッピング比を固定して、当該射影の候補比率でモデルを実行し、校正データ上のPPLを評価する。探索区間の中点と左右の中間候補を比較し、PPLが下がる方向へ区間を絞る。区間幅がε以下になったら当該射影の比率を確定する。

次に、確定済みの射影を低ビット状態のまま保持して次の射影へ進み、同じPPL探索を繰り返す。最後まで進むと射影ごとに異なるクリッピング比のリストが得られる。これはすべての射影をFP16で校正して一括適用する方式とは異なる。先に量子化した層が後段へ与える誤差を含めて次の射影を最適化する点が「gradual」の意味である。

探索では、各射影のPPLがクリッピング比に対してほぼ単峰・凸的であると仮定する。著者はPPLの滑らかさと実験結果からこの仮定を支持するが、すべてのモデル・射影で厳密な凸性を証明したわけではない。複数の局所極小がある場合には二分探索が大域最適を逃す可能性がある。加えてPPLを評価するたびに校正データの推論が必要であり、射影数の多いモデルではオフライン時間が大きい。

本研究はQuaRotの基盤を用い、重みをGPTQで量子化、活性をper-tokenで量子化し、KVキャッシュをgroup-128の非対称量子化とする。GBSが変更する中心要素は射影ごとのクリッピング比であり、3ビットの全演算を独自ハードウェア上で直接実行する専用カーネルを提案したわけではない。

## 手法：Paley構成と次元拡張

Hadamard行列Hは直交性を持ち、適切に正規化すれば回転前後で線形層の表現能力を保つ。通常の高速Hadamard変換は2の冪次元に便利だが、任意の特徴次元へそのまま適用できるわけではない。著者はPaleyの構成法を利用し、素数pがp≡3 (mod 4)を満たす場合にp+1次元のHadamard行列を構成する。Legendre記号の計算は事前処理で行い、生成した回転を重みへ融合する。

必要な次元に合わない場合は、射影の重みの入力または出力方向へゼロ成分を追加し、変換可能な次元へ拡張する。たとえばQwen2.5-1.5Bの1536次元は、8次元の追加によって1544次元へ拡張する構成を論文が記述する。Qwen2.5-7Bでは3584次元に対するHadamard生成と、MLPの32次元拡張を用いる。ゼロ埋めした重みと回転行列の積を新しい重みとして保存すれば、推論時に追加のLegendre記号計算は不要になる。

次元拡張の演算費用を無視してはならない。元の内積の共通次元をn、元ビット幅をb、拡張後をn+d、拡張後ビット幅をb'としたとき、同じ行列形状の単純なbit-operation比較では、d≤n(b−b')/b'であれば拡張後のbit-operation数が元を超えないという上界を示す。これは**同じビット幅で拡張しても無料**という意味ではなく、低ビット化で節約した演算の範囲内で次元増加を許す条件である。入力長が増えれば拡張分の計算・メモリも増える。

## 評価条件

| 項目 | 一次論文の条件 |
|---|---|
| モデル | Mistral 7B Instruct v0.3、Mistral 7B v0.1、Llama2 7B、Llama3 8B、Qwen2.5 7B Instruct、Qwen2.5 1.5B Instruct |
| 量子化 | 重み・活性・KVをすべて4ビットまたは3ビット（WAKV） |
| 基盤方式 | QuaRot、SpinQuant、DFRot。QuaRot基盤ではGPTQ重み、per-token活性、group-128非対称KV |
| 校正 | WikiText-2訓練集合の10%を使用し、各射影のPPLを逐次評価 |
| 精度指標 | WikiText-2 PPL、PIQA、HellaSwag、ARC-E、ARC-C、WinoGrande、Lambadaの6課題と平均正答率 |
| 計算環境 | 量子化・GBSにA100 GPU 1基。大モデルの探索は最大約4日 |
| Qwen対応 | 非2冪次元のためPaley行列とゼロ埋め次元拡張を使用 |

実験の平均値は6ベンチマークの正答率の平均である。WikiText-2のPPLは低いほど良く、6課題平均は高いほど良い。ここで測定したのは主として量子化後の**品質**であり、実際のデコードトークン毎秒やGPUメモリ使用量の改善倍率ではない。

## 評価結果：4ビットWAKVの比較

| モデル | FP16 PPL / 6課題平均 | QuaRot系 PPL / 平均 | GBS追加 PPL / 平均 |
|---|---|---|---|
| Mistral 7B Instruct v0.3 | 5.49 / 71.62% | 5.98 / 67.88% | 5.75 / 70.15% |
| Mistral 7B v0.1 | 5.25 / 71.08% | 5.82 / 66.41% | 5.57 / 69.56% |
| Llama2 7B | 5.47 / 67.19% | 6.21 / 61.92% | 6.04 / 62.74% |
| Llama3 8B | 6.13 / 70.30% | 8.33 / 59.97% | 7.40 / 65.71% |
| Qwen2.5 7B Instruct | 7.45 / 67.57% | 9.21 / 58.70%（拡張） | 8.23 / 62.69%（拡張） |
| Qwen2.5 1.5B Instruct | 9.64 / 60.00% | 14.44 / 44.41%（拡張） | 12.05 / 49.23%（拡張） |

4ビットでは全モデルでGBSによるPPL改善が確認できる。たとえばLlama3 8BはPPL 8.33→7.40、6課題平均59.97→65.71%と5.74ポイント改善する。Qwen2.5 1.5Bも平均44.41→49.23%へ改善するが、FP16の60.00%には届かない。QwenのQuaRot単独欄は元実装の次元制約で比較不能であり、表のQwenの基準値は**次元拡張を適用したQuaRot+**の値である。

## 評価結果：3ビットWAKVの比較と失敗条件

3ビットでは回転だけの方式が大きく破綻する条件が多い。論文の表2は以下のような差を示す。

| モデル | FP16 PPL / 平均 | QuaRot系 PPL / 平均 | GBS追加 PPL / 平均 |
|---|---|---|---|
| Mistral 7B Instruct v0.3 | 5.49 / 71.62% | 38.28 / 22.06% | 7.04 / 61.32% |
| Mistral 7B v0.1 | 5.25 / 71.08% | 100.85 / 18.43% | 7.31 / 58.31% |
| Llama2 7B | 5.47 / 67.19% | 332.56 / 18.07% | 9.18 / 43.34% |
| Llama3 8B | 6.13 / 70.30% | 1315 / 16.84% | 12.62 / 46.92% |
| Qwen2.5 7B Instruct | 7.45 / 67.57% | 251 / 18.32%（拡張） | 12.33 / 47.44%（拡張） |
| Qwen2.5 1.5B Instruct | 9.64 / 60.00% | 3411 / 16.98%（拡張） | 34.97 / 26.05%（拡張） |

Mistral 7B v0.1の6課題平均は18.43→58.31%と39.88ポイント改善し、これが著者の「最大約40%」の代表例である。Llama3 8BではPPLが1315→12.62へ大幅に下がるが、元モデルの6.13とは依然差が大きい。Qwen2.5 1.5BではGBS追加後でも平均26.05%であり、極低ビット化の品質維持が難しいモデルが残る。よって「3ビットで無損失」ではなく、**破綻していた3ビット量子化を一部モデルで実用に近づける**という結果として読むべきである。

### 他の回転方式との組合せ

付録のSpinQuant比較でも、3ビットMistral 7B InstructのPPLは14.31→8.11、6課題平均29.34→54.38%へ改善する。DFRotでは同モデルのPPLが11.26→7.58、平均47.54→64.71%となる。GBSがQuaRot専用の細工ではなく、別の回転方式のクリッピング設定にも適用できることを示す。一方、4ビットでは改善幅が小さい場合もあり、追加の校正費用に見合うかは対象モデル次第である。

### 次元拡張の感度

Qwen2.5-1.5Bは1536次元のまま既存のQuaRot実装を利用できず、著者はPaley構成に合う1544次元へ拡張する。Qwen2.5-7BでもMLPに32次元を加える。次元拡張によって量子化後の精度が改善する場合があるが、計算量も増える。Llama3 8BではA100のメモリ制約により約2036次元以上の拡張を試せなかったと記載する。高精度な回転行列が得られるからといって無制限に次元を増やすのは適切でない。

## 限界：方式固有のコストと制約

GBSは射影ごとに複数回モデルのPPLを測るため、モデルのパラメータ数と射影数が増えるほど校正時間が増える。論文は最大のモデルでA100 1基を使い約4日を要したと報告する。これは推論時の追加計算ではなく、量子化準備時の費用だが、モデル更新が頻繁なサービスやローカル環境では大きい。WikiText-2訓練集合の10%を使った探索が、他の分布やより少ない校正データでも同等の最適比を与えるかは未確認である。

探索はPPL対クリッピング比がほぼ単峰であることを仮定する。外れ値が強い射影や異なるタスク分布で多峰性が現れた場合、二分探索が最適値を逃す可能性がある。PPL改善と6課題平均改善は相関するが、個別の数学・長文脈・対話品質の保持を保証するものではない。特に3ビットのQwen2.5-1.5Bでは平均正答率がFP16の60.00%から26.05%へ低下しており、用途によっては許容できない。

次元拡張では追加された特徴が推論時の行列積へ残るため、KV・MLPの形状、カーネル互換性、実際のGPUスループットへ影響する。論文のbit-operation上界は理論比較であり、実機で同じ倍率が得られることを示さない。高速Hadamard変換が利用可能な次元を選ぶ必要もあり、非2冪対応のための行列生成・重み融合の実装が増える。

さらに、重み・活性・KVを3ビット化した精度実験と、GPUの実測メモリ節約量・TTFT・TPOT・生成スループットは区別する必要がある。実装はQuaRotベースで、全演算が専用3ビット整数カーネルとして実行されることを実証したわけではない。量子化の実装を採用する際には、校正時間、拡張次元による費用、実際のカーネル効率を別に計測する必要がある。

## 研究上の位置づけ

QuaRotやSpinQuantは外れ値を回転でならすことに重点を置く。GBSは回転後の分布を固定して終えるのではなく、**各射影のクリッピング比をモデル全体のPPLで評価しながら順次決定**することで、低ビット化の累積誤差に対処する。Paley構成とゼロ埋めは、これまで回転の次元条件で適用が難しかったQwen系にも同じ最適化の流れを持ち込む。

この2つの寄与は互いに補完するが、精度改善と高速化は同義ではない。実務上は、3ビット化でGPUメモリの制約を緩めたい場合の候補となる一方、量子化準備に数日かかる点と、モデルによっては精度低下が大きく残る点を評価する必要がある。
