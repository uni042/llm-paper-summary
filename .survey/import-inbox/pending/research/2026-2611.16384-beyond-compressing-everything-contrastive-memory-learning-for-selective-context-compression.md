# Beyond Compressing Everything: Contrastive Memory Learning for Selective Context Compression

> 同一文書への異なるクエリ同士をハードネガティブとする対照学習とメモリスロット間の双方向注意で、クエリごとに違う証拠を選んで残すソフト文脈圧縮CoMemを提案し、Mistral-7Bの32倍圧縮でも先行圧縮法を全QAベンチマークで上回った。

## 概要

長い文書を質問応答や検索拡張生成へ使うとき、全文をそのままデコーダへ入れると、計算量とKVキャッシュが文書長に比例して膨らみ、無関係な記述が注意を薄める。ソフト文脈圧縮は、文書を少数の学習可能なメモリトークンの隠れ状態、すなわちメモリスロットへ要約し、デコーダにはクエリとスロットだけを見せて答えを生成させる方式である。文書が256トークンの塊ごとに例えば32分の1へ圧縮されれば、デコーダが処理する文脈は劇的に短くなる。

しかし従来のソフト圧縮は、文書をクエリと無関係に圧縮していた。同じ文書でも、質問が違えば残すべき証拠は違う。ある質問では冒頭の日付が決定的で、別の質問では末尾の数値が決定的になる。一様な圧縮は限られたスロットを文書全体の平均的な要約へ使い、質問が実際に必要とする証拠を落としやすい。クエリを圧縮器の入力へ連結するだけの方式も提案されていたが、本論文の観測では、その場合でも異なるクエリに対するメモリスロット同士の類似度は高いままで、選択は実質的に起きていなかった。

本論文のCoMemは、選択を訓練信号として明示的に与える。対照圧縮学習では、圧縮したメモリの平均表現を元の文脈の平均表現へ近づけて内容の保存を促し、同時に、同じ文書へ異なるクエリを付けた例同士を難しい負例（ハードネガティブ）として引き離す。文書が同じ以上、粗い話題の違いでは区別できないため、圧縮器はクエリごとの証拠の違いを符号化せざるを得ない。加えて、メモリスロット同士の間だけ因果マスクを外して双方向に注意できるようにし、スロット同士が相談して証拠を分担できるようにする。代表結果として、Mistral-7Bの4倍圧縮でNatural Questionsの正解率は0.7902と無圧縮の0.7905と同等で、LLM判定スコアは0.8185と無圧縮の0.7671を上回った。32倍圧縮でも4つの質問応答ベンチマーク全てで先行圧縮法を上回り、単一H100でのデコーダ生成時間は64倍圧縮で全文入力の4.82倍速かった。

## 問題設定

ここで不足しているのはスロットの数そのものより、スロットへ何を入れるかの選択である。全文入力では計算とKVキャッシュが余分なトークンに使われ、圧縮入力では落とした証拠はデコーダから二度と回復できない。つまり圧縮は不可逆な情報の取捨選択であり、その良し悪しは「文書をどれだけ忠実に縮めたか」ではなく「その質問の答えに必要な証拠が残ったか」で決まる。既存の質問応答損失だけでは、デコーダが答えを出せさえすれば圧縮器の内部表現がどうなっていてもよいため、違う入力に対して似たメモリが作られる縮退が起きても罰せられない。本論文はこの不足を、生成損失とは別の表現レベルの損失で埋める。もう1つの制約は因果マスクである。通常の言語モデルではトークンは左から右へしか見られないが、メモリスロットは生成される文章ではなく情報を置く器であり、左から右への順序を課す理由がない。むしろ後ろのスロットが前のスロットの担当を見られないと、同じ証拠を重複して保持したり、どのスロットも担わない証拠が落ちたりする。

## 手法のあらまし

入力はクエリ、文書、学習可能なメモリトークン列の順に連結され、エンコーダが処理する。最後の層におけるメモリトークンの隠れ状態が圧縮表現となり、デコーダはクエリとこの圧縮表現だけを条件に答えを生成する。文書は256トークンの塊に分けられ、塊ごとに目標の圧縮率に応じた個数のスロットが作られる。訓練は2段階で、段階1では圧縮器とデコーダの両方をLoRAで学習し、質問応答損失に重み0.1の対照損失を加える。対照損失のために、1つの文書へ少なくとも8つの異なるクエリが付いた例だけを集めた約16万件の訓練集合を作り、ミニバッチを同一文書の異なるクエリで構成する。段階2では圧縮器を凍結し、デコーダだけを約45万件で指示調整する。推論時は、クエリと文書を圧縮してから答える2段階の処理になる。真のクエリが事前に分からない用途向けに、「有用な情報を全て残せ」という汎用クエリで圧縮して使い回す使い方も評価されている。

## 手法

### 1. 対照圧縮学習 — メモリを元の文脈へ寄せ、他のメモリから離す

この機構が観測するのは、圧縮したメモリスロット群の平均ベクトルと、元の文脈トークンの隠れ状態の平均ベクトルである。処理は対照損失で、正の組は同じ例のメモリ平均と文脈平均であり、この組を引き寄せることで、圧縮後も元の文脈の意味内容が残るようにする。負の組はミニバッチ内の他の例のメモリ平均であり、これらを引き離すことで、異なる入力が区別できないメモリへ潰れることを防ぐ。文脈側の表現には勾配を流さないため、動くのはメモリ側だけであり、損失は圧縮器へ直接かかる。効く理由は、質問応答損失が「答えが出るか」しか見ないのに対し、この損失は「メモリが元の文脈を表し、かつ他のメモリと違う」という表現そのものの性質を点検するからである。追加費用は訓練時の平均化と類似度計算だけで、推論時の費用は増えない。失敗条件は、文脈平均という粗い要約へ寄せるため、平均に表れにくい局所的な証拠の保存はこの損失だけでは保証されないことであり、その不足を補うのが次のハードネガティブである。

### 2. 同一文脈ハードネガティブ — 同じ文書の違う質問同士を比べさせる

この機構が変えるのはミニバッチの作り方である。通常の対照学習では負例は別の文書から来るが、別の文書同士は話題が違うため簡単に区別でき、圧縮器は選択を学ばないまま損失が下がってしまう。本論文では、ミニバッチを同じ文書へ異なるクエリを付けた例だけで構成し、負例を全て同一文脈由来にする。すると文書の話題や語彙は共通であるため、メモリ同士を区別するには「このクエリではどの証拠を残したか」の違いを符号化するしかなくなる。これが選択的な圧縮への強い事前分布として働く。アブレーションでは、異なる文脈の負例を使う構成が2Wikiで0.3681、HotpotQAで0.4947だったのに対し、同一文脈の負例は0.3761、0.5211と全データセットで上回った。追加費用は訓練データの条件付けであり、文書あたり8つ以上のクエリが必要になるため、使える訓練コーパスが限られる。失敗条件は、クエリ同士の証拠が実際にほぼ重なる文書では、区別すべき違い自体が乏しく信号が弱くなることである。

### 3. 双方向フローメモリ — スロット同士だけ因果マスクを外す

この機構が変えるのはエンコーダの注意マスクである。クエリと文書の部分は通常どおり因果マスクを保ち、メモリスロットの部分だけを全結合にする。つまり各スロットは文書全体と他の全スロットを見られるが、文書側のトークンは未来を見ない。出力は、互いに重複を避けて分担されたスロット群である。効く理由は、圧縮が「誰が何を持つか」の割当て問題だからであり、割当ては当事者同士の情報交換なしには調整できないためである。決定的な証拠はアブレーションにある。段階1の32倍圧縮で、対照学習なしでは双方向マスクの有無は2Wikiで0.2785対0.2852とほぼ無差別だが、対照学習を入れると因果マスクでは0.2627まで落ち、双方向との組合せで0.3761へ跳ね上がる。つまり双方向化は、選択の信号があって初めて効く補完部品であり、単独の改良ではない。実装はFlexAttentionによるカスタムマスクで、追加のパラメータはない。失敗条件は、スロット数が多い低圧縮率ではスロット間の注意が二乗で増えることと、因果構造で訓練された土台モデルの表現が双方向マスクへ適応するには段階1の訓練が前提になることである。

### 4. データと制御の流れ

1つの質問応答は、まずクエリと文書の塊がエンコーダへ入り、双方向に連携したスロット群へ圧縮され、次にデコーダがクエリとスロットだけを見て答えを生成する、という流れである。訓練時にはこの流れに加えて、同一文書の別クエリの例が同じバッチに並び、メモリ同士の対照が圧縮器を形作る。段階2で圧縮器が凍結されるため、推論時に使う圧縮の振る舞いは段階1で決まったものがそのまま残る。

| 構成要素 | 入力・観測 | 具体的な動作 | 改善対象 | 主なトレードオフ |
|---|---|---|---|---|
| 対照圧縮学習 | メモリ平均と文脈平均 | 正の組を引き寄せ、他のメモリを引き離す | メモリの忠実さと区別可能性 | 平均表現では局所証拠を保証できない |
| 同一文脈ハードネガティブ | 同じ文書への異なるクエリ群 | バッチ内負例を同一文書由来に限定する | クエリごとの証拠選択 | 文書あたり多数のクエリを持つ訓練データが要る |
| 双方向フローメモリ | スロット間の注意マスク | スロット同士だけ全結合にする | 証拠の分担と重複回避 | 対照学習なしでは効かない |

## 評価

### まず見るところ

- **結論:** クエリを条件とする選択的な圧縮は、クエリ非依存の圧縮より明確に強く、4倍圧縮では無圧縮に並び、32倍でも先行法を全ベンチマークで上回る。ただし無圧縮を超えるのは一部のLLM判定スコアに限られ、圧縮率を上げるほど絶対性能は下がる。
- **速度・効率:** 単一H100で測ったデコーダ生成時間は、64倍圧縮で全文入力の4.82倍速い。ただし圧縮と検索の時間は測定から除かれており、エンドツーエンドの高速化ではない。
- **品質:** 圧縮は近似であり、落とした証拠は回復できない。32倍圧縮の正解率は無圧縮のおおむね7割前後まで下がる一方、針探し課題では証拠の部分的保持が強く残る。
- **評価の強さ／注意点:** 2つの土台モデル、4つの質問応答ベンチマーク、針探し課題で測っているが、正解率の指標は答えの文字列を含むかで判定する緩い指標とLLM判定の併用であり、人手評価はない。生成時間以外の実測効率は未評価である。

この評価で最初に押さえるべきなのは、4倍圧縮の結果の読み方である。Mistral-7Bで、無圧縮の正解率とLLM判定は2Wikiで0.7654と0.7088、HotpotQAで0.7751と0.8249、MuSiQueで0.5333と0.5085、Natural Questionsで0.7905と0.7671である。CoMemの4倍圧縮は2Wikiで0.6280と0.6662、HotpotQAで0.6937と0.7045、MuSiQueで0.3359と0.3277、Natural Questionsで0.7902と0.8185であり、正解率では無圧縮に届かないが、Natural QuestionsのLLM判定では無圧縮を上回る。これは圧縮が情報を足したのではなく、無関係な文脈を取り除くことでデコーダの注意が証拠へ集中した結果と読むのが自然であり、全文入力が常に上限ではないことを示す。逆にMuSiQueのような多段推論では正解率が0.5333から0.3359へ大きく下がっており、複数の離れた証拠を連鎖させる課題では、落とした中間証拠がそのまま推論の切断になる。圧縮の利得は課題の構造に強く依存する。

32倍圧縮では順位の構図がはっきりする。CoMemは2Wikiで0.5650、HotpotQAで0.6197、MuSiQueで0.2656、Natural Questionsで0.7389、針探しで0.612を記録し、同じ32倍の先行法では最も強い部類のPISCOがそれぞれ0.5369、0.5683、0.2731、0.6731、0.578、クエリ対応をうたうSeleComが0.2894、0.3445、0.0856、0.6531、0.000である。特に針探しでSeleComが0.000まで落ちるのに対しCoMemが0.612を保つ点は重要で、これは「クエリを見る」だけでは不十分で、訓練信号として選択を強制しなければ、予算が厳しくなった途端に証拠保持が崩れることを示している。MuSiQueだけはPISCOがわずかに上であり、全課題で一様に勝つわけではない点も正直に残る。

圧縮率の感度も読みどころである。Mistral-7Bでは8倍から128倍まで上げても、2Wikiは0.5863から0.5756、HotpotQAは0.6437から0.5975、Natural Questionsは0.7524から0.7294と、劣化は緩やかである。Qwen3-4Bでも128倍での平均低下は8倍比で0.0822にとどまる。これは、対照学習で作られたメモリが「文書の要約」ではなく「証拠の索引」に近い性質を持ち、スロット数が減っても優先順位の高い証拠から残るためと解釈できる。ただし裏を返せば、8倍時点で既に無圧縮との差の大半が生じており、圧縮率を下げれば無圧縮へ戻るという単調な回復はこの範囲では見えない。実務では、圧縮率の選択よりも、そもそも圧縮するかどうかの判断のほうが品質への影響が大きい。

構成要素の切り分けでは、対照学習と双方向マスクの相互作用が中心的な知見である。段階1の32倍圧縮で、両方なしの構成は2Wikiで0.2852、HotpotQAで0.2447、双方向だけでは0.2785と0.2440、対照学習だけを因果マスクで使うと0.2627と0.1492まで落ち、両方の組合せで0.3761と0.5211になる。対照学習だけが悪い理由は、スロット同士が連携できない状態で「互いに違うメモリを作れ」と命じても、割当てを調整する手段がなく、かえって内容の保存が乱れるためと考えられる。段階2については、段階1のチェックポイントなしでは2Wikiが0.5591から0.3932へ落ちることから、選択の能力は段階1で作られていることが分かる。一方、段階2で圧縮器も一緒に更新する構成は2Wikiで0.5782と完全形をわずかに上回る項目もあり、圧縮器の凍結は必須の設計というより安定化の選択である。

効率の数値は割り引いて読む必要がある。理論計算量は4倍圧縮で全文の10031ギガフロップスに対し14074ギガフロップスと、圧縮側のほうがむしろ多い。これは圧縮のためのエンコーダ処理が追加されるためで、圧縮率が上がるほど9985ギガフロップスまで下がる。実測の生成時間は1件あたり全文で0.053秒、4倍で0.026秒、16倍で0.013秒、32倍で0.012秒、64倍で0.011秒であり、高速化倍率は2.04倍、4.08倍、4.42倍、4.82倍である。ここで測っているのはデコーダの回答生成だけであり、文書を圧縮するエンコーダの時間と検索の時間は含まれていない。したがって、文書を一度圧縮して何度も質問に使い回す運用ではこの倍率に近づくが、質問ごとに文書が変わり圧縮が毎回必要な運用では、全体の高速化はこれより小さくなる。論文が汎用クエリで圧縮したメモリをオフラインで作り置く使い方を示し、その場合でも32倍圧縮で真のクエリ使用時の0.5591に対し0.3786と性能が残ることを示したのは、この運用条件への答えとして読める。KVキャッシュの実測削減量、複数リクエストを同時に処理するサービング条件でのスループット、圧縮レイテンシを含むエンドツーエンド遅延は未評価である。

針探しの詳細分析では、7桁の針を完全に再現する指標と、一部でも数字列が残れば数える指標が区別され、64倍圧縮でも後者は段階1で0.98に達する。つまり失敗の多くは証拠の完全な喪失ではなく部分的な崩れであり、デコーダ側の検証や再検索と組み合わせれば回復できる余地があることを示唆する。ただしこれは合成課題での結果であり、実文書での証拠保持を直接保証するものではない。土台モデルをQwen3-4Bへ変えた場合も傾向は同じで、4倍圧縮の針探しは0.948、32倍で0.634であり、方式が特定のモデル族に依存しないことは確認されている。逆に、長い対話や文書の更新が入る運用、圧縮メモリを跨いだ複数文書の統合、生成の事実性への影響は未評価であり、LLM判定への依存も含めて、品質の最終確認は導入側の課題で測る必要がある。

## 既存研究との差

ハード圧縮は元のトークンを削除して読めるプロンプトを残す方式で、積極的な圧縮では証拠そのものを消しやすい。ソフト圧縮は連続ベクトルへ要約するため意味は残しやすいが、ICAEやPISCOはクエリ非依存であり、RAMやSeleComはクエリを入力へ連結しても選択を訓練目標として強制しなかった。本論文の差は、クエリ条件付けを入力の工夫から訓練信号の工夫へ変えた点にある。同一文脈の負例は、文書分類のような粗い区別では解けない課題を圧縮器へ課し、双方向マスクはその課題を解くためのスロット間の調整手段を与える。この2つの組合せが本論文の単位である。

## 限界・実装状況

- ハードウェア依存条件: 効率の実測は単一H100での小さな設定に限られ、圧縮時間を含まない。実際のサービングでの利得は、文書の再利用率と圧縮の頻度に依存する。
- モデル／ワークロード依存条件: 検証はMistral-7BとQwen3-4B、質問応答と合成の針探しに限られる。対話、文書更新、複数文書の統合での振る舞いは未検証である。
- 実装状況: 公式コードが公開されている。ただし圧縮器の訓練には文書あたり多数のクエリを持つコーパスと2段階のLoRA訓練が必要で、既存モデルへ無訓練で差し込む部品ではない。
- 近似の品質リスク: 圧縮で落ちた証拠はデコーダから回復できない。多段推論のMuSiQueでは無圧縮からの低下が大きく、証拠の連鎖が要る用途では圧縮率の選択に注意が要る。

## 一般的な実装上の含意

文脈圧縮の評価では、圧縮率と平均スコアだけでなく、「同じ文書への違う質問で、違う情報が残っているか」を直接測るべきである。メモリ同士の類似度や、クエリを変えたときの出力変化がその代理になる。また、圧縮の効率を主張するときは、圧縮する側の計算を含めたエンドツーエンドで測らないと、再利用が少ない運用では見積もりを誤る。訓練信号の設計としては、簡単に解ける負例ではなく、解くために対象の能力そのものが必要になる負例を作ることが、他の表現学習でも有効な原則である。
