# Online normalizer calculation for softmax

## 概要

本論文は、数値的に安全なソフトマックスで別々に実行していた最大値探索と指数和の計算を、一度の入力走査へ統合するオンライン正規化子を提案する。ソフトマックスは入力の各値を指数化して全指数和で割る関数だが、大きい値を直接指数化すると浮動小数点数があふれる。そのため通常は最初に最大値を求め、最大値を引いてから指数和を計算する。安全性と引き換えに入力を繰り返し読む必要があり、メモリ帯域に律速されやすい。

著者らは走査途中で最大値が変わったとき、それまでの指数和を新しい最大値の基準へ再尺度化すれば、最大値と指数和を同時に更新できると示す。標準的な安全ソフトマックスが入力要素あたり4回の読み書きを要するのに対し、オンライン版は3回で済む。さらに上位K選択まで融合すれば、出力確率ベクトル全体をメモリへ書き出さず、K個の値と位置だけを返せる。

CUDA Cで実装したTesla V100の評価では、十分大きなバッチで単体ソフトマックスが最大約1.3倍、K=5の上位K選択との融合が最大約5倍高速化した。これらはカーネル単体の実測値であり、TransformerやLLM全体が同じ倍率で速くなるという結果ではない。小バッチでは帯域を使い切れず単体利得が約1.15倍に留まるなど、効果が入力形状に依存することも明示されている。

## 問題設定

語彙数Vの分類や次トークン予測では、各候補の対数得点xを確率へ変換するためソフトマックスを使う。素朴な実装は `exp(x_i)` を足して正規化するが、大きな正のxで指数があふれる。安全な実装は最大値mを先に求め、`exp(x_i−m)` の和dを計算し、最後に `exp(x_i−m)/d` を出力する。この三段階は数値的に安定する一方、最大値探索で1回、指数和で1回、出力生成で読み1回と書き1回、合計4回のメモリアクセスが必要になる。

ソフトマックスは要素ごとの演算が比較的軽く、巨大な語彙や大バッチではメモリ転送が実行時間を支配する。安全性を犠牲にして素朴なソフトマックスへ戻れば走査を減らせるが、指数のあふれで結果が破綻する。そこで安全性を保ったまま、最大値と指数和を同じ走査で計算することが狙いになる。

さらにビーム探索などでは、全語彙の確率ベクトルより上位K個の候補と確率だけが必要なことがある。ソフトマックスの全結果を書き出してから別カーネルで上位Kを選ぶと、不要な中間ベクトルの転送が発生する。正規化と上位Kの探索を同時に進めれば、より大きな転送削減が期待できる。

## 手法

### 走査中の最大値と指数和

入力を左から処理し、j番目までの最大値を `m_j = max(m_(j−1), x_j)` とする。同時に正規化和を `d_j = d_(j−1) exp(m_(j−1)−m_j) + exp(x_j−m_j)` と更新する。初期値は最大値が負の無限大、指数和が0である。現在値が最大値を更新しなければ、過去の和へ新しい指数項を足すだけでよい。

新しい最大値が現れた場合は、過去に旧最大値を基準として足した指数和を `exp(旧最大値−新最大値)` 倍する。これは過去の各項を個別に読み直す代わりに、累積和全体を新しい尺度へ一度に移す操作である。したがって最大値を事前に知らなくても、最終的な指数和を一度の走査で得られる。出力の確率値は最後に各入力をもう一度読んで計算するため、ソフトマックス単体では完全な一回読みではなく、3回の読み書きとなる。

### 数値安定性と並列化

論文は帰納法で、オンライン更新が通常の安全ソフトマックスと同じ最大値および指数和を計算することを証明する。正規化和は処理済み要素数jに対して `1 ≤ d_j ≤ j` に収まり、最大値を引いた指数は1以下となる。このため素朴な指数計算のあふれを避けられる。論文は32ビット浮動小数点の正規化和でも非常に長いベクトルを処理できると論じるが、有限精度の丸め差が完全にゼロになるという主張ではない。

GPUで並列に処理するため、部分列ごとに求めた「最大値mと指数和d」の組を結合する二項演算を定義する。二つの組の最大値を新しい基準とし、それぞれの指数和を新基準へ再尺度化して足す。この結合演算は結合則と交換則を満たすため、並列木状縮約へ利用できる。逐次の漸化式をそのまま一スレッドで走らせるのではなく、複数スレッドが部分結果を作って結合できる点がGPU実装に重要である。

### 上位K選択との融合

正規化子の更新と同時に、これまで見た値の上位K個と入力位置を保持する。新しいxを読むたびK+1番目の候補として挿入し、降順を維持するよう必要な交換を行う。全入力の走査が終わったら、保持したK個の対数得点だけを最終最大値と指数和で正規化し、対応する位置と一緒に返す。入力全要素の確率を書き出す必要がなくなる。

標準の安全ソフトマックスと上位K選択を別々に実行する場合、入力要素あたり約5回のメモリアクセスが必要になる。オンライン版を別カーネルで使っても4回残るが、上位Kまで融合すると入力は1回読むだけで済む。中間の全確率ベクトルを作らないため、単体ソフトマックスの4→3回より大きい削減になる。一方、K個の候補を常時並べ替えるため、Kが大きいほど比較・交換の演算が増え、帯域削減の利益が薄れる。

## 評価条件

| 観点 | 一次論文の条件 |
|---|---|
| 実装 | CUDA C、並列縮約にCUB v1.8.0を使用 |
| GPU | NVIDIA Tesla V100 PCIe、16GB |
| 実行環境 | CUDA Toolkit 9.1、ECC有効、永続モード有効 |
| 演算精度 | FP32 |
| バッチ数 | 4000ベクトルと10ベクトル |
| 入力長 | ベクトル長Vを変化させ、約1000、4000、25000などで傾向を確認 |
| 上位K選択 | 主比較はK=5、感度評価はK=10、15、30など |
| 比較対象 | 素朴版、安全版、オンライン版、上位Kを別処理する版と融合する版 |
| 指標 | 1秒あたり処理要素数、同条件の安全版に対する高速化倍率 |

## 主要結果

### ソフトマックス単体

| 条件 | 比較 | 観測された傾向 | 解釈 |
|---|---|---|---|
| バッチ4000、V≲1000 | オンライン版対安全版 | ほぼ同程度 | 小さいベクトルはキャッシュ等の効果で帯域律速になりにくい |
| バッチ4000、V≈4000 | オンライン版対安全版 | 約1.3倍 | 4回から3回へのアクセス削減の理論上限約1.33倍に近い |
| バッチ10、V>1000 | オンライン版対安全版 | 約1.15倍 | GPUの占有率が低く、帯域削減を速度へ転換しにくい |

大バッチではVが1000程度を超えると一次・二次キャッシュでの競合が増え、外部メモリ帯域の制約が強くなる。オンライン版は余分な走査を削った分だけ速くなり、V≈4000で約1.3倍へ達する。対照的にバッチ10ではベクトルごとに1スレッドブロックを起動しても全体で10ブロックしかなく、演算器やメモリ系を十分使えない。演算量やアクセス数が減っても速度比は約1.15倍に留まる。

### 上位Kとの融合

| 条件 | 比較 | 高速化倍率 |
|---|---|---:|
| バッチ4000、K=5、V≈25000 | オンライン融合版対安全版＋別TopK | 約5倍 |
| バッチ10、K=5 | オンライン融合版対安全版＋別TopK | 約1.5〜2.5倍 |
| K=10の感度評価 | 同比較 | 約3.5倍 |
| K=15の感度評価 | 同比較 | 約2倍 |
| K=30の感度評価 | 同比較 | 約1.4倍 |

K=5の大バッチでは5回から1回への転送削減に近い最大約5倍の速度向上が得られる。論文はこの5倍のうち、約2.5倍を関数融合、約2倍をオンライン正規化の寄与として分解している。つまり「オンライン正規化だけで5倍」と読むのは誤りである。Kを30へ増やすと候補挿入・交換が支配的になり、利得は約1.4倍へ縮む。バッチ10でも融合は有益だが、帯域ではなく起動・実行待ちが支配的なので大バッチと同じ倍率にはならない。

## 既存研究との差

階層型ソフトマックスや標本化による近似方式は、計算する候補や確率の定義を変えることがある。本論文は古典的なソフトマックスの定義を保ち、正規化に必要な中間統計の計算順序だけを変える。したがって既存の語彙分割、標本化、投影層の高速化と独立に適用できる。

さらに二項演算で部分正規化統計を結合できるため、GPUの並列縮約と相性がよい。後の注意カーネルでブロックごとの最大値と指数和を結合する考え方にも通じるが、本論文が実測したのは単体ソフトマックスと上位K融合であり、後年の注意カーネル全体の性能値を本論文の結果へ混ぜない。

## 限界

第一に、評価はTesla V100上のFP32カーネルであり、CPU、異なるGPU世代、低精度演算、Transformer全体、LLMサービング全体を実測していない。論文自身もCPUなど別機器で同様の速度向上が得られるかは未検証とする。単体ソフトマックスの約1.3倍を現在の注意カーネルや生成処理へそのまま外挿できない。

第二に、入力が小さい場合やバッチが小さい場合、GPUを十分に占有できず、メモリアクセス削減の効果が小さくなる。論文のバッチ10での単体利得は約1.15倍であり、帯域律速の理論上限とは異なる。高速化はベクトル長と同時処理数の双方に依存する。

第三に、上位K融合の大きな利得はKが小さい場合に限られる。候補数を増やすと候補の挿入・整列が支配し、K=30では約1.4倍に低下する。またビーム探索以外で全確率が必要な処理では、上位Kだけを返す融合を同じ形で適用できない。

第四に、正規化子の走査を削ってもソフトマックス単体は依然としてメモリ帯域に制約される。論文はさらに前段の投影計算との融合を将来課題として挙げるが、その実装や速度は検証していない。現代の注意計算ではすでに前後演算との融合が行われることがあり、比較すべき基準実装は論文当時と異なる。
