# PALUTE: Processing-In-Memory Acceleration via Lookup Table for Edge LLM Inference

> モノリシック3次元DRAMの中でルックアップテーブルを大規模並列に照会し、逆量子化なしの低ビット推論を行うメモリ内処理加速器。毎秒1264トークンを0.16ワットで処理し、既存の表引き・近接メモリ方式より高いエネルギー効率を示す。

## 概要

エッジデバイスで大規模言語モデルを動かす場合、電力と面積の予算が厳しく、プライバシー上の理由からローカル実行が求められる場面も増えている。低ビット量子化は計算とモデルサイズを減らすが、実際の推論では別の費用が残る。低精度の値を通常の演算へ戻す逆量子化が実行時間の2割から9割を占めるという報告があり、ソフトマックスや正規化などの非線形演算子は浮動小数点演算量では0.2パーセント未満なのに実行時間の約39パーセントを占める。さらに、データ移動が総エネルギーの平均62.7パーセントを占めるという測定もあり、演算だけを安くしてもメモリ壁は解けない。

PALUTEは、計算を事前計算済みの表引きへ置き換えるルックアップテーブル方式を、モノリシック3次元DRAMの内部で実行する加速器である。行列積は小さい部分内積へ分割され、活性値の断片が固定されれば重みの断片との全組合せの結果を表として用意できるため、実行時は重みを索引として結果を取り出すだけになり、逆量子化が不要になる。3次元DRAMの縦方向に並ぶメモリアレイタイルへ表を複製配置することで大規模な並列照会を実現し、ロジックダイ上の生成器が表を3サイクルで作って書き戻す。代表結果として、Qwen3系モデルへのW4A4適用で毎秒1264トークンを0.16ワットで処理し、エネルギー効率7738トークン毎秒毎ワットは近接メモリ加速器CHIMEの12.8倍、面積効率はDRAM内表引き方式PIMPALの2.0倍である。

## 問題設定

表引き方式には3つの弱点がある。第1に容量で、表の大きさは入力精度に対して指数的に増えるため、低ビットでなければ成立しない。第2に照会の並列度と遅延で、CPU実装のT-MACはメモリ帯域に、専用回路のFIGLUTはシステムレベルのメモリ壁に、通常DRAM内実装のPIMPALは行バッファやバーストのインタフェースと表の占有面積に制限される。第3に表の生成費用で、先行方式の多くは表が事前に用意されている前提か、その場で作り直す費用を数えていない。加えて3次元DRAM特有の問題として、縦に積まれた層ではワード線の配線長が層ごとに違い、活性化遅延が層によって不均一になる。PALUTEは、縦方向アレイの並列性、符号対称性による半テーブル化、近接生成器、層の性質に応じたデータ配置という4つの手当てで、これらへ同時に答える設計になっている。

## 手法のあらまし

システムは、ロジックダイの上にハイブリッド接合で3次元DRAMの層を積んだ構成で、ダイ間の帯域は約1.38テラバイト毎秒である。処理の流れは、重みと初期トークンをロジックダイへ取り込み、生成器がトークン値から表を作り、表をDRAMアレイへ書き戻し、重みを索引として各アレイが表を照会して結果をバンク単位の累算器へ返し、KVキャッシュはDRAM内に置いてデコードの読み書きを支える、という順序である。行列積用の表は部分内積の全組合せを列挙したもので、非線形演算子用の表は入力値に対する関数値そのものである。アレイ内では、表を置く領域・KVキャッシュの領域・重みの領域が分かれ、頻繁に触るデータほどロジックダイに近い下層へ置く階層配置が遅延の不均一を吸収する。

## 手法

### 1. 縦方向アレイでの表照会 — 並列度を面積でなく高さから取る

各メモリアレイタイルは縦方向に積まれたセル配列であり、1ビットずつの表の値を保持する。表はアレイ内に水平方向へ複製して置かれ、行デコーダ側の照合論理が全行を走査して索引に一致する行を有効化し、選ばれた列の値をフリップフロップへ取り込む。1回の走査で多数の表から同時に出力が得られるため、照会のスループットはアレイの数だけ伸びる。構成は、バンクあたり1024アレイ、チャネルあたり4×4バンク、チップあたり4×4チャネルで、W4A4かつ行バッファ帯域128ビット毎サイクルの前提では、同時照会数の上限は838万8608と見積もられている。平面的なDRAMで同じ並列度を得ようとすると大きな面積が必要になるのに対し、縦方向の積層は面積を増やさずに並列度を稼げる。これが面積効率の源泉である。ただし行バッファの転送幅が上限になるため、32個を超える表の結果は複数回のバーストに分かれ、実効並列度は転送側で制限される。

### 2. 半テーブルと生成器 — 容量と生成費用を半分と3サイクルへ

行列積の表には符号の対称性があるため、非負の値の分だけを保存し、負の場合は索引の符号を反転して引いてから結果の符号を戻す。これで表の容量は半分になり、より長い表をメモリ内に収められる。区間長は2に選ばれ、4ビット値では表の長さは256項目になる。表を作る生成器はロジックダイ上にバンクごとに置かれ、行列積用コアと非線形演算子用コアを持つ。行列積用コアは、重みの絶対値と活性値の積を符号の組合せごとに列挙し、3サイクルで1つの活性断片に対する全項目を生成してDRAMへ書き戻す。先行方式が表の事前配置を前提としたり、処理要素間で同じ表を繰り返し生成したりしていたのに対し、生成をバンク並列の専用回路としてメモリのそばに置くことで、生成費用を推論の主経路から外している。生成器の中では行列積用コアが面積と電力の大半を占める。

### 3. 階層配置とスケジューリング — 層ごとの遅延差へデータを合わせる

3次元DRAMでは下層ほどワード線の寄生容量と抵抗が大きく、活性化遅延が層で異なる。PALUTEはアクセス頻度と局所性でデータを配置し、初期トークンと頻繁に使う重みをロジックダイに近い下層へ、表を中層へ、KVキャッシュを表の近くの上層へ置く。バンク単位の累算器はアレイ最上部、KVキャッシュ領域の直上にあり、表の結果が短い縦経路で累算へ届くため、移動の遅延とエネルギーが減る。KVキャッシュの読み書きはデコードのトラフィックの大半を占めるため、この近接配置はデコード効率へ直接効く。配置を誤ると、頻繁なアクセスが長い配線を往復して縦積層の利益が相殺されるため、配置方針は本設計の性能条件の一部である。

| 構成要素 | 入力・観測 | 具体的な動作 | 改善対象 | 主なトレードオフ |
|---|---|---|---|---|
| 縦方向アレイ照会 | 重み断片を索引とする照会 | 照合論理が全行を走査し複製表から並列に取得 | 照会の並列度と面積 | 行バッファ転送幅が実効上限 |

## 評価

### まず見るところ

- **結論:** 表引きと3次元DRAMの縦構造を組み合わせると、エッジ向けの電力予算の中で高いスループットとエネルギー効率が得られる。生成器まで含めたエンドツーエンド設計として評価されている点が先行方式との違いである。
- **速度・効率:** 毎秒1264トークン、0.16ワット、エネルギー効率7738トークン毎秒毎ワット。面積効率は毎平方ミリメートルあたり11.25トークン毎秒である。
- **品質:** 数値形式はW4A4のままであり、本論文は品質指標を測っていない。品質は採用する量子化方式側の性質として扱われている。
- **評価の強さ／注意点:** 実チップではなく、サイクル精密シミュレーションとRTL合成に基づく見積もりである。想定する3次元DRAM自体が35ナノメートル工程・768層という将来デバイスである。

**数値の読み方。** エネルギー効率の倍率は比較対象ごとに分けて読む必要がある。CHIMEの604.6トークン毎秒毎ワットに対しては12.8倍だが、FIGLUTに対して要旨が述べる1.6倍という値は、表に載るFIGLUTの71.4トークン毎秒毎ワットから単純計算した比とは一致しないため、本まとめでは表の絶対値を正とし、倍率はCHIME比とPIMPAL比の面積効率を中心に扱う。面積効率の比較は、表引きの負担を数えている方式同士に限定されている点にも注意が要る。チップ面積112.4平方ミリメートルにはDRAM全体が含まれるため、ロジックだけの面積で比べる方式とは前提が異なる。

## 既存研究との差

表引き推論の先行研究は、置き場所ごとに限界を持っていた。pLUToは通常DRAM内での照会を示したが生成や管理を含む全体のパイプラインは未整備で、PIMPALはDRAM内算術ルックアップで高速化したが並列度がメモリインタフェースに制限され、FIGLUTは専用回路で表引き行列積を高速化したがメモリ壁そのものは解けず、T-MACはCPU帯域に縛られた。本論文の差分は、表の置き場所をモノリシック3次元DRAMの縦方向アレイへ移して並列度を高さから得たこと、半テーブルを専用回路ではなくDRAM内保存へ適用したこと、そして生成器と階層配置まで含めたエンドツーエンドの設計として閉じたことにある。近接メモリ型のCHIMEや同じ3次元DRAMを使う層状設計の先行研究とも、表引き中心の実行モデルという点で異なる。

## 限界・実装状況

最も大きな留保は、評価が実機ではなくシミュレーションとRTL合成に基づくことである。想定する768層のモノリシック3次元DRAMは将来デバイスであり、製造可能性、熱、歩留まりといった実装条件は論文の範囲外にある。表引き方式の一般的な制約として、表サイズは入力精度に対して指数的に増えるため、成立するのは低ビット領域に限られ、関数や範囲や精度が変われば表の再生成が要る。長い入力ではプリフィルとKVキャッシュの肥大でスループットが下がる傾向も感度評価で示されている。設計段階の提案であり、コードやチップの公開は論文中に示されていない。謝辞ではSRCとNSFの支援が記されている。

## 一般的な実装上の含意

低ビット推論の最適化では、行列積そのものより逆量子化と非線形演算子とデータ移動が支配的になる局面があり、プロファイルで内訳を確認してから加速対象を選ぶべきである。表引きは計算を容量へ変換する手法なので、容量を安く得られる基板、ここでは縦積層メモリ、と組み合わせたときに真価が出る。また、補助機構の生成費用を主経路の外へ置く専用回路として設計し、費用を内訳として開示する姿勢は、他の近似・事前計算型の加速器でも再利用できる。層ごとに遅延が違う基板では、データ配置そのものが性能設計の一部になる。
