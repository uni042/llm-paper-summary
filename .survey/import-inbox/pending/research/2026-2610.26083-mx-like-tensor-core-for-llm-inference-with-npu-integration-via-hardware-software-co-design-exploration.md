# MX-Like Tensor Core for LLM Inference with NPU Integration via Hardware-Software Co-Design Exploration

> ブロック量子化のスケール形式と重み活性値の非対称精度からなる設計空間を、形式特化のデータパスとエヌピー統合で精度とシリコン両面から探索し、エフピー4域ではユーイー5エム3スケールが劣化を25.3パーセント減らしほぼ無償で得られること、高精度域ではスケールは無関係なことを示した研究。

## 概要

ブロック単位の量子化は、テンソルを小さなグループに分け、グループごとに共有スケールを持たせることで、そのグループ内の値の分布に合わせた低ビット表現を可能にする形式である。大規模言語モデルの推論、特にエッジのエヌピーエスへの配備では、この形式がメモリと電力の削減手段として広く使われている。業界の両端には2つの標準がある。オープンコンピュートのマイクロスケーリング形式は、符号なしの2の冪のスケールを採用してハードウェア効率を最優先する。エヌビディアのエヌブイエフピー4は、小数部を持つスケールを採用して量子化精度を取る。どちらも、スケール形式、重みの形式、活性値の形式という3軸からなる設計空間の中の1点に過ぎない。

問題は、その間の空間が体系的に調べられていないことである。アルゴリズム側の先行研究は、要素形式を振ってもスケールを2の冪に固定するか、エフピー4だけに絞って小数部スケールを調べるかであり、スケールと要素形式の相互作用は未整理だった。ハードウェア側も、既存の積和データパスはスケールを1形式に固定し、しかも重みと活性値を対称に扱うため、形式の組み合わせごとの本来のコストが見えない。精度だけ見ても面積だけ見ても不十分で、両方に優れた形式が他方で劣ることがあるため、精度とシリコンのパレート前線そのものが未地図だった。

本論文はこの空間を、ハードウェアとソフトウェアの協調設計として一括に探索する。8ビットのスケール形式の全族を定義し、重みと活性値の非対称な組み合わせと併せて精度地形を測り、形式ごとに特化したデータパスの雛形で面積と電力を公正に測り、オープンソースのエヌピー基盤への統合を含む自動フローで126構成を評価する。得られた指針は精度域で分かれる指針である。6ビット以上の域ではスケール形式はほぼ無関係で、2の冪のスケールが最適である。エフピー4域では逆転し、小数部を持つスケールが決定的に効き、中でもユーイー5エム3が推奨として浮かぶ。

## 問題設定

スケール形式の設計が難しいのは、指数部と仮数部の配分が、表せる範囲と刻みの細かさの交換だからである。指数が広いスケールは、外れ値を含むグループの大きな値まで届くが、刻みが粗くなる。仮数が厚いスケールは刻みが細かいが、届く範囲が狭まる。標準の2形式はこの配分の両端近くにあり、しかもエヌブイエフピー4のスケールは浮動小数点形式との整列のために符号ビットを恒常的に使わずに残しており、8ビットのうち1ビットが実質的に無駄になっている。本論文の形式族は、この全ビットを指数か仮数へ再配分した族として定義される。

非対称性の問題も同じ土俵にある。活性値は裾の重い分布で外れ値が多く、重みはガウス分布に近い。したがって重みと活性値に同じ形式を課す理由はなく、特に重みだけを4ビットまで落とす積極的な量子化では、活性値側の精度を残す方が得になりうる。ただしこの非対称は、ブロック量子化の文脈では体系的に調べられてこなかった。

ハードウェア側の公正さの問題はさらに厄介である。小数部のあるスケールは、2の冪のスケールのようなビットシフトでは処理できず、専用の乗算器が要る。その乗算器の幅は、オペランド同士の積和の幅で決まるため、スケールのコストは重みと活性値の形式と結合してしまう。単一の設計点で面積を比べても、空間全体のコストの形は分からない。運行時に精度を切り替える再利用型のデータパスは、形式を混ぜたときの固有コストを隠してしまう。本論文が形式ごとに特化したデータパスを、同一のマイクロアーキテクチャで生成して比べるのは、この結合を露出させるためである。

## 手法のあらまし

まず設計空間を定義する。スケールは、指数ビット数と仮数ビット数の合計が8になる符号なし形式の族とし、要素形式は整数8ビット、浮動小数点の8ビット、6ビット、4ビットを用いる。ブロック長は16で全構成に共通とし、精度は全精度ベースラインからの相対パープレキシティ劣化で測る。次に精度地形を測って空間を絞る。指数が4ビット未満のスケールは活性値のダイナミックレンジを表せず大きく劣化するため除外でき、実用域は2の冪のスケールからユーイー4エム4とユーイー4エム3までに絞られる。ハードウェア側では、前処理、縮約木、スケール乗算器、双方向シフター、加算器、正規化と丸めからなる積和データパスを、活性値と重みとスケールの形式パラメータで生成できる雛形として実装する。2の冪でないスケールについては縮約木の後段に乗算器を追加する。最後に、この雛形をエヌピー基盤へ統合し、設計時のパラメータ1組から、量子化されたテストデータとソフトウェア参照、実行時の制御値、回路記述、合成結果までを自動でつなぐフローで、精度と面積と電力を同じ構成について揃えて測る。

## 手法

### 1. エムエックス系設計空間と精度地形の絞り込み

スケール形式は、指数部が担う2の冪の部分と、仮数部が担う1を少し上回る小数部分の積として解釈される。指数ビットが0の場合は、非正規の形で小さいスケールを表す。要素形式はオープンコンピュートのマイクロスケーリング仕様に従い、4ビットから8ビットまでを対象とする。これはエッジ配備で最も関係の深い範囲である。精度地形の測定から得られた知見は3つある。第一に、スケールの指数幅には硬い下限があり、4ビット未満ではほとんどの組み合わせで精度が大きく崩れるため、空間の約半分が最初から除外できる。第二に、残った範囲では、小数部を持つスケールが2の冪や標準のユーイー4エム3より測れるほど有利であり、その差はエフピー4域で最も大きい。エヌブイエフピー4が追加するテンソル全体の第2段スケールは、この範囲ではわずかな改善しかもたらさず、テンソル全体を2回余分に走査する費用に見合わないため、本論文はスケール形式の選択を全体スケールより優先する。第三に、重みと活性値の非対称な組み合わせは、対称な組み合わせより同じ重み精度で精度が良く、その差もエフピー4域で最も大きい。これらの知見が、後段の本評価で残す構成と、データパスが非対称を支える必要性を決めている。

### 2. 形式特化の積和データパス — 結合したコストを露出させる

データパスは、オペランドの指数加算と仮数乗算を行い、あらかじめ計算したアンカー位置へ揃えてから共有の縮約木で合計し、スケールを適用し、現在の累積値と桁を合わせて加算し、先行ゼロ検出による正規化と丸めを経て累積レジスタへ戻す、という流れである。先行研究の土台に加えた新規点は2つある。1つは、小数部のあるスケールをビットシフトへ畳み込めない場合のために、縮約木の後段へスケール乗算器を置いたことである。もう1つは、活性値と重みの指数幅と仮数幅、およびスケールの仮数幅という5つの形式軸でデータパスをパラメータ化し、構成ごとに特化した回路を生成することである。各段のビット幅はこれらの軸から式で決まる。積和の幅は、最大の積の位置を示すアンカーと、最小の非正規積の位置の両端から決まるため、指数の広い形式は両側で費用を払う。スケール乗算器はこの積和幅をそのまま引き継ぐため、小数部スケールの費用はオペランドの組と分離できない。具体例として、活性値がイー4エム3で重みがイー2エム1の場合、積和のフィールドは25ビットに広がり、スケール乗算器と累積側の幅もそれに連れて決まる。この構造が、後の面積評価で、小数部スケールの追加面積がオペランドの組によって3.6倍も違うという結果を生む。

### 3. 自動協調設計フローとエヌピー統合

数百の構成について、ハードウェアの実体とソフトウェアの試験条件を手作業で揃えるのは、労力と誤りの両面で現実的でない。そこで本論文は、オープンソースのエヌピー基盤であるエスエヌエーエックスの上に自動フローを構築する。この基盤は軽量なリスクファイブコアが制御レジスタ経由でアクセラレータを駆動するクラスタであり、共有スクラッチパッドとパラメータ化されたデータストリーマが、構成ごとに変わるデータ幅を吸収する。テンソルコア側には、制御管理部と、設計時に空間並列度を決められる演算要素の二次元配列と、再量子化部が入る。最上位の統括部は、オペランドとスケールのデータ型、ワークロード寸法、テンソルコア寸法という統一パラメータを受け取り、ソフトウェア側では量子化されたテストデータと参照出力、メモリ配置とデータフローを決める実行時制御値を導出し、ハードウェア側ではデータパスと周辺部品の回路記述を生成する。生成されたソフトウェアのバイナリとハードウェアは共シミュレーションで数値の一致を確認され、回路は別途合成されて面積と電力が得られる。精度のベンチマークと合わせて、1つの構成について精度とシリコンの両方が同じ土台から測れることが、このフローの要点である。

## 評価

### まず見るところ

- **結論:** スケール形式の重要性は精度域で反転する。高精度域ではコストだけを見て2の冪のスケールを選ぶのが正しく、エフピー4域では小数部スケールが精度を大きく買い、その代金は域が低いほど相対的に安くなる。
- **速度・効率:** 本論文はスループット競争の研究ではない。全構成が同じ演算要素配列と同じタイミング制約で同じスループットを出すよう揃えられており、比べているのはその条件下での面積と電力である。
- **品質:** 精度指標は相対パープレキシティ劣化のみであり、下流課題の精度は未評価である。形式選定の結論はパープレキシティの範囲で読む必要がある。
- **評価の強さ／注意点:** 合成ベースの評価であり、実チップの実測ではない。対象モデルも1ビーから3ビー級と小さく、より大きなモデルでの劣化の形は未確認である。

## 既存研究との差

マイクロスケーリングの仕様を作った研究群は、要素形式を振ってもスケールを2の冪に固定していた。エフピー4の学習や推論で小数部スケールを調べた研究は、エフピー4だけに範囲を絞り、シリコンの裏付けも単一設計点の面積比較にとどまっていた。精度可変のデータパスを作るハードウェア研究は、1つのデータパスで全形式を賄う再利用の立場であり、形式ごとの固有コストを原理的に観測できない。混合精度を扱う設計も、形式の混在に大きな面積を払う形だった。本論文は、スケールの指数と仮数の配分自体を探索軸にし、重みと活性値の完全な非対称と組み合わせ、形式ごとに特化したデータパスでコストを測り、エヌピーへの統合と自動フローまで含めてパレート前線を引いた点で、これらの単一軸の研究と一線を画す。

## 限界・実装状況

評価は合成ベースであり、プロセスも28ナノメートルという比較的緩い条件である。より先端のプロセスでは面積と電力の内訳が変わりうる。精度の測定は小規模モデルとパープレキシティに限られ、大規模モデルや下流課題、実際の推論遅延への影響は未評価である。データパスは構成ごとに特化して生成されるため、1つのチップで多数の形式を運行時に切り替える用途には、そのままでは向かない。再利用型との使い分けが前提になる。また、ブロック長は16に固定されており、ブロック長自体を軸にした探索は行われていない。実装は公式コードとして公開され、オープンソースのエヌピー基盤の上に構築されている。会議論文として採択済みの版が基になっており、配備先の想定はエッジのエヌピーエスである。

## 一般的な実装上の含意

量子化形式の選定では、まず自分がどの精度域にいるかを確認すべきである。6ビット以上ならスケール形式に悩む必要はなく、最も安い2の冪のスケールでよい。4ビットへ攻める場合に限り、スケールの指数と仮数の配分が精度を決める主軸になり、指数に余裕のある形式が外れ値への頑健性で勝つ。重みだけを落とす場合は、活性値を1段厚くする非対称化が最も安い精度の回復手段になる。ハードウェアの評価では、形式のコストを単独で見積もらず、オペランドの幅と結合した形で、特化した実体を作って測る必要がある。
