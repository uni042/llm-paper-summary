## 概要

LLM agentは一回の推論で終わらず、思考、tool呼出し、観測、再思考を長時間繰り返す。このため単一modelのtoken throughputを上げても、不要な大model呼出し、増え続けるcontext、KV cacheを無視したrequest scheduling、過去sessionと似た文字列の再生成が残るとtask完了時間は十分に短くならない。AgentInferはこれらを一つのend-to-end agent systemとして共同最適化する。

四つの構成要素は、進捗に応じて大小modelを切り替えるAgentCollab、KV cache価値を考慮するAgentSched、過去sessionをsuffix automatonへ統合してdraft tokenを作るAgentSAM、reasoningを保ちながらenvironment interaction履歴を非同期要約するAgentCompressである。統合すると無効token消費を50%以上減らし、BrowseComp-zh/DeepDiverで精度を維持しながら1.8〜2.5倍のend-to-end高速化を報告する。

## 問題設定

agent workloadではrequestが互いに独立した短いchatではなく、同じsessionが長いcontextとKV cacheを持って再登場する。単純なshortest-job schedulingはcacheを捨てて再prefillを増やす場合があり、逆にcache保持だけを優先すると短いrequestが待つ。

さらに大modelを全turnで使うと、簡単なtool操作にも高い計算費用を払う。contextにはreasoning上重要な履歴と、検索結果・tool出力のように圧縮可能な環境情報が混在する。AgentInferはこれらの異質性をmodel selection、memory、scheduler、decodeの各層へ分けて扱う。

## 手法

### AgentCollab

大modelは初期planningとreasoning stagnationからの回復を担当し、小modelは進捗が順調な通常stepを担当する。各stepでprogress checkを行い、停滞時だけ大modelへescalateし、回復後は小modelへ戻す。これにより大model呼出し回数を減らしつつ、難しい局面のaccuracyを保護する。

### AgentSched

KV cache容量に余裕があるときは短いjobを優先し、memory pressureが高まるとcache hitを価値として加えたKV-aware schedulingへ連続的に移る。shadow priceを使って「新規KV allocationの費用」を表現し、固定policyではなく現在のcapacityとdemandに応じて優先順位を変える。

### AgentSAM

suffix automaton（接尾辞オートマトン; SAM）を使う投機的復号を、現在sessionだけでなく意味的に近い過去sessionへ拡張する。current contextと検索したhistorical SAMを合成し、繰り返しやすいagent表現からdraft tokenを低overheadで生成する。長contextや大batchで投機利得が小さいときは適応的に無効化する。

### AgentCompress

memoryをreasoning memoryとenvironment-interaction memoryへ分け、後者をcontext threshold超過時に非同期圧縮する。進行中のreasoningをblockせず、検索結果やtool出力を短く再構成することでprefillとattention対象tokenを減らす。

## 評価条件

| 項目 | 条件 |
|---|---|
| benchmark | BrowseComp-zh、DeepDiver |
| 主指標 | task accuracy、end-to-end latency/QPS、token消費 |
| component | AgentCollab、AgentSched、AgentSAM、AgentCompress |
| workload | multi-turn reasoning + tool interaction |
| 比較 | 大model単独、各componentなしのbaseline |

## 主要結果

| 構成 | 結果 |
|---|---:|
| 統合AgentInfer | end-to-end 1.8〜2.5倍高速化 |
| 統合AgentInfer | 無効token消費50%以上削減 |
| AgentCollab例 | accuracy 33.8%（large-only 34.6%、small-only 18.3%）、1.32倍高速化 |
| AgentSched | 平均LLM call latency 0.902倍、KV hit 63%→72% |
| AgentSAM | LLM latency最大26%削減、end-to-end最大21.2%改善 |

componentごとの結果から、統合利得は単一kernelの高速化ではなく、大model呼出し削減、context短縮、cache再利用、decode draftの累積で生じる。16 parallel sessionでは統合時にQPS 2.52倍という条件も報告される。

## 既存研究との差

通常のLLM servingはrequest-level TTFT/TPOTやtokens/sを主指標にし、agentのtool待ちやreasoning loopを外側のapplication問題として扱う。AgentInferはtask completionを最終目的に置き、model routing、context management、KV scheduling、speculative decodingを同じagent lifecycleへ接続する。

## 限界

agent benchmarkとtool interaction patternへの依存が大きく、単純chat workloadで同じ倍率が得られるとは限らない。AgentCollabはprogress self-evaluationが誤ると不要なescalationまたは品質低下を起こし得る。AgentSAMは過去sessionに再利用可能なpatternが少ない場合、AgentCompressは要約可能なenvironment履歴が少ない場合に利得が縮む。公式実装URLは確認した一次資料から特定できなかった。
