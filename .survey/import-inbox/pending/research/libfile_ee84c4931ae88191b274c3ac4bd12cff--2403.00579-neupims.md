## 概要

LLMのdecoder blockではQKV projectionとfeed-forward networkは大きな行列同士を掛けるGEMMになり、batchがあれば演算密度が高い。一方、attentionのKV読出しは生成tokenごとに過去KVを走査するGEMV寄りの処理となり、メモリ帯域が支配的になる。NPUはGEMMに強いがGEMVで演算器が遊びやすく、メモリ内処理（Processing-in-Memory; PIM）はGEMVに強いがGEMM性能が不足する。

NeuPIMsは両者を同じ推論pipelineへ組み込み、GEMMをNPU、GEMVをPIMへ分担する。ただし単純に接続すると、同じDRAM bankをNPUとPIMが交互に占有し、Transformerのデータ依存で片方が待つ。そこでdual row bufferとsub-batch interleavingを導入し、異なるsub-batchの独立仕事を重ねる。GPU-only比3倍、NPU-only比約2.4倍、単純統合比1.6倍のthroughput改善を報告する。

## 問題設定

異種acceleratorの利点は「各kernelを得意な装置へ置く」だけでは得られない。既存PIMは通常memory access modeとPIM command modeを排他的に切り替えるため、NPUがDRAMへアクセスしている間にPIMが停止する。さらに同じrequestではGEMMの出力がattentionの入力になるため、依存関係が並列実行を妨げる。

したがってNeuPIMsは、memory bankの同時利用制約とmodel graph上の依存を両方崩す必要がある。

## 手法

### kernel別の異種割当

QKV projectionとFFNのGEMMはNPUへ、attentionで支配的なGEMVはPIMへ割り当てる。NPUは高い演算密度を利用し、PIMはKVをmemory近傍で読みながら計算することで大容量KVの外部転送を減らす。

### dual row buffer

各bankへ二つのrow bufferを持たせ、一方を通常memory read/write、もう一方をPIM commandへ利用できるようにする。これにより従来のblocked modeで必要だったNPU/PIMの全体切替を緩和し、同じmemory subsystem上で異なる処理を重ねる。

### sub-batch interleaving

一つのbatchを複数sub-batchへ分割し、sub-batch AがNPUでGEMMを実行している間に、依存の解けたsub-batch BのattentionをPIMで実行する。単一request内の逐次依存を消すのではなく、batch並列性を使って別request群のstageをpipeline化する。

### runtime pipeline

runtimeは各sub-batchがどのstageにいるかを追跡し、NPUとPIMの両方へ仕事が供給されるようinterleaveする。片方の装置だけを速くしても他方がidleならthroughputは伸びないため、stage間の流量を揃えることがシステム上の核心になる。

## 評価条件

| 観点 | 内容 |
|---|---|
| 対象 | batched decoder-only LLM inference |
| compute | GEMM-focused NPU |
| memory compute | GEMV-focused PIM |
| 比較 | GPU-only、NPU-only、naive NPU+PIM |
| 並列化 | dual row buffer + sub-batch interleaving |
| 主指標 | throughput |

## 主要結果

| 比較対象 | throughput改善 |
|---|---:|
| GPU-only | 約3倍 |
| NPU-only | 約2.3〜2.4倍 |
| naive NPU+PIM | 1.6倍 |

単純NPU+PIMに対しても1.6倍であることが重要で、異種deviceを併設するだけでなく、memory同時利用とsub-batch pipelineが性能へ寄与することを示す。GPU-only比3倍は同じalgorithmを任意GPUで3倍にするsoftware高速化ではなく、専用architecture比較である。

## 既存研究との差

NPU単独はGEMV時の演算利用率が低く、PIM単独はGEMM能力が不足する。従来の単純統合はmode切替と依存で同時稼働できない。NeuPIMsはdual row bufferというmemory architecture変更とruntime interleavingを一体化し、二種類のacceleratorを実際に重ねて動かす点が差である。

## 限界

専用PIM memoryとdual row bufferを必要とするため、既存GPU/NPUへsoftwareだけで適用できない。sub-batch interleavingは十分なbatch並列性を前提とし、batch 1や低負荷では重ねられる独立仕事が減る。モデル構造やKV長によってGEMM/GEMV比率が変わるため、装置間の最適資源配分も変化する。
