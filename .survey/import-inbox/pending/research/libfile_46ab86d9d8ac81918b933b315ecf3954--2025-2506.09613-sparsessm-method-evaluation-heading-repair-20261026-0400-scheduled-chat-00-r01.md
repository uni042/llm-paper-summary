# SparseSSM：時刻共有状態遷移の重要度を使ったMambaの一回校正剪定

## 概要

Mambaの選択的状態空間モデル（Selective State Space Model; SSM）は、TransformerのKVキャッシュと異なり、再帰状態を更新して長い系列を扱う。入力依存の離散化係数と、系列の全時刻で使い回す状態遷移パラメータが組み合わさるため、通常の線形層向け剪定手法を状態遷移重みにそのまま適用すると、削除してよい状態を見誤りやすい。SparseSSMは、時刻共有の遷移パラメータに対して隠れ状態を用いた近似二次重要度を計算し、時刻ごとに選ばれた削除候補の頻度を集計して、推論時に固定して使える一つの剪定マスクを作る。さらにMamba内部の入力・出力射影を保護するようモジュール別疎化率を割り当てる。

元の研究はKaiwen TuoとHuan WangによるICML 2026の査読付き論文としてPMLR第306巻に掲載された。正式版の要旨は、SSM重み50%を微調整なしで削除した際の品質低下が「限定的」であると説明する。前段のワーカーがarXiv v1の表を照合した数値では、Mamba-370MのSSM重みだけを50%非構造化疎化すると、5課題平均正答率は47.49→47.47とほぼ変わらないが、WikiText-2困惑度は14.32→19.27へ悪化する。構造化剪定の速度測定ではSSMモジュールの処理時間が2.766ms→1.608msとなるが、これはモデル全体の生成速度ではない。今回の差し戻し修復では、機械品質ゲートが手法・評価の説明を正しく認識できるよう、標準の`## 手法`と`## 評価`の下に原稿内容を再構成した。

## 問題設定

Mambaの再帰状態は概念的に`h_t = ΔA_t ⊙ h_(t−1) + ΔB_t ⊙ x_t`で更新され、`y_t = C_t^T h_t`として読み出される。`B_t`、`C_t`、刻み幅`δ_t`は入力に依存する一方、連続時間の遷移行列`A`に対応する`A_log`は全時刻で共有される。実装では`ΔA_t = exp(δ_t A)`という離散化が介在する。したがってある時刻で小さな影響しか持たない`A_log[d,n]`を削っても、別の時刻の長期記憶に大きく影響する可能性がある。

既存のSparseGPTは通常の線形層を対象に、入力活性と重みの局所二次情報を用いて削除損失を抑える。しかしSSMでは同じ遷移重みが繰り返し利用されるうえ、指数関数を含む離散化がある。単一時刻・単一入力のスコアや、重み絶対値だけでは長い系列の状態への影響を十分に表せない。また、SSM以外の射影を同じ比率で剪定すると、特に`in_proj`や`out_proj`の損失が大きくなる。SparseSSMは、時間共有の性質に沿った重要度の集約と、射影ごとの感度に応じた予算配分を組み合わせる。

## 手法

### 1. 状態遷移パラメータの二次重要度

原著§3.2とTheorem 1は、重みをゼロにしたときの損失増加を二次近似するOptimal Brain Surgeon（OBS）の考え方をSSMへ拡張する。状態遷移の対角性や二階交差項を無視する近似のもとで、`A_log[d,n]`の重要度は概ね`A_log[d,n]^2 × Σ_(batch,t) h_(t−1)[d,n]^2`に比例する。ここで`h_(t−1)`はその状態位置の過去隠れ状態であり、単なるFFN入力活性とは異なる。時刻をまたぐ状態の使用頻度・振幅がスコアに入る点がMamba固有である。

実際の導出には`δ_t^2 A[d,n]^2 exp(2δ_t A[d,n])`などの因子があるが、原著は順位付けに際して簡略化する。したがって厳密な損失Hessian全要素の計算ではなく、二次近似に基づく代理スコアである。校正系列をモデルに通し、選択的走査（selective scan）内部の状態を収集する必要があるため、追加学習は不要でも校正forwardの計算・メモリ費用は生じる。状態遷移の対角性だけから最終損失のHessianまで厳密に対角と証明できるわけではなく、後段の射影や状態間結合が近似の限界となる。

### 2. 時刻ごとの削除候補を投票で統合

時刻ごとに異なるスコアから異なるマスクを作って推論中に切り替えると、同じ`A_log`を全時刻で使うSSMの実装と衝突する。SparseSSMのAlgorithm 1は、まず各時刻のスコア`M_t = A_log^2 ⊙ S_t`を計算し、目標疎化率`p`に対して`K = ceil(pDN)`個の最小スコア位置を削除候補として選ぶ。次に位置ごとの候補選出回数`C[d,n]`を蓄積し、最も頻繁に削除候補となったK位置を最終マスクへ採用する。出力は系列の全時刻で固定した二値マスクであり、実行時にトークンごとの剪定判断を追加しない。

この投票は、たまたま一時刻で低重要度となった位置を直ちに削除しないための工夫である。Mamba-370MのSSM 50%疎化における原著Table 6では、単純な時刻方向L2集約のWikiText-2困惑度81.22に対して投票方式は19.27で、5課題平均も45.24から47.47へ改善した。60%、70%疎化でも投票方式の困惑度は単純集約より低い。ただし「頻繁に低スコア」を優先するので、稀な重要時刻を完全に保護する最悪ケース保証はない。時刻別スコアと投票配列の保持にも前処理費用が必要である。

### 3. 射影モジュールの感度に応じた疎化率

MambaではSSM遷移重みだけでなく、`in_proj`、`out_proj`、`x_proj`、`dt_proj`、`conv1d`などが計算に参加する。原著Figure 2とAppendix B.2.2は、同じ剪定率でも`in_proj`と`out_proj`が特に敏感であると報告する。そこで各モジュールのHessianトレースを感度の代理として順位付けし、敏感な射影には小さな疎化率を、比較的頑健な射影には大きな疎化率を割り当てる。

原著の設定では目標疎化率`p`の近傍で変動幅`α=0.04`を許す。入力はモジュール別感度と全体の剪定予算、出力は各射影の目標疎化率である。モジュール重み数が異なるため、単純平均ではなく実際の削除重み数の加重合計が予算と整合するかを確認する必要がある。非構造化のゼロ重みを密行列として格納するだけではメモリ使用量や実行時間は減らず、実際の高速化には疎行列カーネルまたは状態次元を縮める構造化実装が必要になる。

### 4. 半構造化・構造化剪定への拡張

N:M剪定では固定した小ブロックの中で所定数の重みを削り、GPU向け疎行列実装が利用できる可能性を作る。完全構造化では`A`の状態次元方向の列を重要度の集約から選び、削除する列に合わせて`x_proj`の出力次元を再構成する。これにより状態配列自体を短くできるが、単に重みをゼロにする場合とは異なり、モデルの形状と後続モジュールの整合性を保つ実装が必要である。剪定率が同じでも、非構造化、N:M、構造化は品質と実行速度の交換条件が異なる。

## 評価

### 評価環境と指標

### 半構造化・構造化剪定と実測時間（原著arXiv v1 Table 3〜5）

Mamba-370MのSSM行列へ2:4のN:M剪定を適用した場合、WikiText-2 PPLはMagnitudeの77.20に対してSparseSSMが17.07、5課題平均は38.00に対して42.32である。4:8でもPPLは81.56に対して16.77、平均は38.19に対して43.76である。N:Mは密行列の単純なゼロ化と異なり、固定ブロック内の非ゼロ位置制約を持つ。

状態次元を完全構造化で50%削除したMamba-370MのSSMでは、WikiText-2 PPLが18.13、5課題平均が46.31となる。元モデルのPPL 14.32、平均47.49より品質は悪化するが、SSMモジュールの処理時間は2.766msから1.608msへ短縮し、約1.72倍となる。これは**SSMモジュール単体の測定**であり、Mamba全体のTTFT、TPOT、生成tokens/s、ピークVRAM、消費電力の倍率ではない。

### 構成要素除去と感度（原著arXiv v1 Table 6・Figure 4）

時刻別候補を頻度で統合する機構の効果は、単純L2集約との比較で示される。Mamba-370M、SSM 50%でWikiText-2 PPLはL2集約81.22、投票方式19.27である。60%では108.1→22.65、70%では186.3→28.28と、削除率を増やしても投票の相対優位が残る。ゼロショット平均は50%で45.24→47.47、60%で43.07→45.73、70%で41.96→43.80へ改善する。これは「二乗活性を使う」だけでなく、**時刻別候補を投票で固定マスクへ変える**部分の寄与を裏付ける。

Figure 4は、校正サンプル16未満では品質が落ちやすく、64サンプル程度が校正費用と品質の妥協点であると報告する。FFNの感度配分幅`α`も結果に影響し、既定は0.04である。校正系列を増やすとforward実行・内部状態収集が増えるため、剪定の算術演算だけを見て前処理を無料とみなすことはできない。

## 主要結果

本論文の強みは、時刻共有のSSM遷移パラメータを直接対象にした重要度推定と、時刻ごとの低重要度候補を集計して一つの固定マスクへ落とす実装可能性にある。Mamba-370MではSSM重み50%を削っても5課題平均がほぼ維持される一方、困惑度は悪化する。モデル全体の50%疎化では、PPLと正答率の両方に顕著な損失が残る。したがって、剪定対象と評価指標を特定しない「50%無損失圧縮」という要約は不適切である。

速度上の実測利得は、構造化で状態次元を縮めたSSMモジュールの2.766→1.608msであり、通常の非構造化マスクが直ちに同じ速度を出すとは限らない。Mamba全体の生成速度、長文脈実運用、複数同時要求、GPUメモリ実使用量は別途検証する必要がある。

## 既存研究との差

SparseGPTは線形層向けの二次重要度を用いるのに対し、SparseSSMはMambaの時間共有遷移と隠れ状態を明示的に扱う。Mamba-Shedderはブロック・モジュール削除を主とする一方、SparseSSMは状態遷移行列の要素・列単位に入り、非構造化、N:M、構造化の各条件へ展開する。Wanda系の重みと活性の積に近い代理スコアを持つが、再帰状態を観測し、時刻別候補の投票を使うことが異なる。

## 限界と再現上の注意

第一に、OBSの二次近似は状態遷移の対角性と交差項の簡略化に依存し、厳密な全損失最適化ではない。入力分布が変われば重要度順位も変わる。第二に、校正forwardで内部状態を収集するので「training-free」は「data-free」を意味しない。第三に、`in_proj`と`out_proj`の保護に用いる感度配分はモデル構造と目標疎化率に依存し、別のSSMモデルへ同じ`α`をそのまま移せるとは限らない。

第四に、非構造化でゼロを増やしても、密行列格納のままではメモリや実行時間が自動的に減らない。第五に、Mamba-370MのSSMモジュールで観測した1.72倍をモデル全体の高速化と取り違えてはならない。第六に、論文の正式出版版の要旨は「限定的な性能低下」と慎重であり、今回引用した細かな実験数値は前段ワーカーが照合したarXiv v1に基づく。正式版PDFの全表との数値同一性は今回確認できなかったため、両版の差異を解消済みとは扱わない。

最後に、長文脈サービングでのTTFT/TPOT、複数同時リクエスト、電力消費、圧縮形式のデコード費用、GPUピークメモリは原稿の定量表で検証できない。ローカルGPUで導入する場合には、状態次元の構造化削除と後続射影の形状整合をまず確認し、品質・速度・メモリを同一条件で測り直す必要がある。
