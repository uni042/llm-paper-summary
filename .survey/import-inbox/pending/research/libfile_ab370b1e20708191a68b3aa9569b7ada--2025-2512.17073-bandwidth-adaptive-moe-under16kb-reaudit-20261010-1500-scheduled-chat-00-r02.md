# Bandwidth-Efficient Adaptive Mixture-of-Experts via Low-Rank Compensation

## 概要

本研究は、専門家混合（MoE）モデルの重みをGPU外のメモリから必要に応じて読み込む**オフロード推論**で、低ビット化による帯域節約と推論品質を両立する手法を扱う。専門家の数が多いMoEでは、トークンごとに少数の専門家しか計算しない一方、選ばれた専門家の重みをCPUメモリなどからGPUへ移す費用が大きい。全専門家を高精度で転送するとPCIe帯域が律速となるが、全専門家を2〜3ビットへ一様に量子化すると重要な専門家の誤差が出力へ強く影響する。

著者らは、各専門家の低ビット重みを共通の基盤とし、ルータ得点の高い**上位n個の専門家だけ**へ量子化誤差の低ランク補償を加える。補償行列は事前に計算して小さい行列積の形で保存するため、推論時に元の高精度重みを丸ごと転送する必要がない。補償に割り当てるランクは専門家重みの尖度から決め、量子化誤差が大きくなりやすい専門家へ予算を集中する。

H100とCPUメモリを使うオフロード構成、GPUと近傍データ処理（Near-Data Processing、NDP）装置を組み合わせた構成で、Mixtral-8×7B、Mixtral-8×22B、DeepSeek-MoE-16Bを評価する。Mixtral-8×7BのGPUのみの構成では、既存Mixtral-Offloadingの2.37トークン/秒に対し、3ビット版12.27、2ビット版18.11トークン/秒と報告する。ただし速度改善の大部分は重みの低ビット化による通信量削減に由来し、低ランク補償だけの速度改善ではない。

## 問題設定と設計上の観察

MoE層ではルータが各トークンの入力表現から専門家得点を計算し、上位k個の専門家を選ぶ。出力は選ばれた専門家の計算結果にルータ得点を掛けて足し合わせたものである。したがって、同じ大きさの量子化誤差でも、ルータ得点の高い専門家の誤差は層の出力により大きく反映されやすい。すべての起動専門家を一律に2ビット化することは、重要度の違いを無視している。

著者らはMixtralのルーティング分布をC4の約8万トークンで測定し、上位専門家への得点集中を示す。Mixtral-8×7Bの第1位専門家の平均得点は0.41〜0.48、第2位は0.17〜0.20である。Mixtral-8×22Bでも第1位0.46〜0.60、第2位0.17〜0.22という差がある。一方、DeepSeek-MoE-16Bはより均等に得点が分散し、少数専門家だけを補償する効果が小さくなる。**何個の専門家を高品質に復元すべきかはモデルのルータ分布に依存する**。

GPUのみのオフロードでは、著者らはH100 PCIeとAMD EPYC 9334のCPUを使い、Mixtral-Offloadingを拡張してFP16専門家の転送時間を測定する。重み移動が推論時間の大半を占めるため、16ビットから3ビット、2ビットへ減らすと演算より通信の改善が支配的になる。しかし低ビット化は推論品質を損なう。必要な専門家だけを低い追加転送費用で補償することが設計課題となる。

もう一つの観察は、専門家ごとに量子化誤差の大きさが異なることである。重み分布の**尖度（kurtosis）**が大きい専門家では、同じ低ビット化をしても量子化残差が大きくなりやすい。すべての専門家へ同じランクの補償行列を配ると、低誤差の専門家へ過剰な補償容量を使い、高誤差の専門家では補償不足になる。そこで尖度によるランク配分と、実行時のルータ得点による補償対象選択を組み合わせる。

## 手法：事前の残差分解とトークン別の選択的復元

### 量子化残差を低ランクで近似する

専門家iの重みを `W_i`、量子化した表現を `Q(W_i)`、その復号値を `Q^{-1}(Q(W_i))` とする。量子化で失われた成分は `E_i=W_i−Q^{-1}(Q(W_i))` である。著者らは残差を低ランク行列の積 `E_i≈U_i V_i` として近似し、補償が必要なときだけ `Q^{-1}(Q(W_i))+U_iV_i` を用いる。完全な高精度重みの転送よりも、低ランク因子UとVの転送を小さくできることが前提である。

各専門家のゲート・上方向・下方向射影などの行列を量子化し、残差に対して一度だけ打切り特異値分解（SVD）を実施する。得られた特異値の平方根を左右の因子へ分配し、低ランク因子自体もINT3で量子化して保存する。これは推論中にSVDを繰り返す方式ではない。オフラインで作った補償行列を、必要なトークンでだけ取り出す方式である。

### 尖度に応じたランク配分

専門家の重み行列の各要素について平均と標準偏差を求め、四乗中心モーメントを標準偏差の四乗で割った尖度を計算する。尖度が大きいほど量子化残差の相対ノルムが大きいという論文の経験的相関を使い、専門家を尖度の高い順に並べる。補償ランクの候補は `{0,16,32,128,256,512,1024}` の離散集合である。

平均ランク予算 `R_avg` を決め、全専門家のランク合計が `N×R_avg` を超えない範囲で、尖度の高い専門家から大きなランクを割り当てる。尖度の低い専門家はランク0、すなわち補償なしにもできる。割当後にHQQ型の量子化を行い、その残差へ設定ランクのSVDを適用する。尖度は最適ランクを厳密に保証する理論量ではなく、限られた予算を実験的に重要な専門家へ振り分ける代理指標である。

### ルータ得点上位n個だけ補償する

推論時には、通常のMoEルータが選んだ上位k個の専門家のうち、さらに得点が高い上位n個（n<k）だけを補償対象とする。全専門家の低ビット重みは必要に応じて読み込み、選択された上位n個に限ってINT3の低ランク因子を追加転送する。GPU上では量子化重みの復号値へ低ランク更新を加え、その他の起動専門家は補償しない低ビット重みのまま実行する。

Mixtral系列は上位第1位の得点が大きいためn=1、平均ランク予算32とする。DeepSeek-MoE-16Bは上位専門家への得点集中が弱いためn=3、平均ランク予算64とする。これらはモデルごとの実験設定であり、任意のMoEでn=1が最適という結論ではない。上位の専門家を補償することで、全専門家を高精度へ戻すより少ない帯域費用で品質を回復させる。

### GPUのみとGPU・NDP混合での実行

GPUのみの構成では、低ビット重みと選択専門家の補償因子をCPUメモリからGPUへ運び、GPUで復元と専門家演算を実行する。ここで節約されるのは主にPCIe転送量である。NDPを備える構成では、補償対象外の専門家を低ビットのままNDP側で計算し、重要な上位専門家だけGPUへ転送して補償する。NDP側で冷たい専門家を処理できる場合はGPUへ送る重みと活性値をさらに減らせる。

両構成で同じ低ランク補償の考え方を使えるが、NDP側には専用の計算能力とメモリ帯域が必要である。GPUのみの構成とNDP混合構成の速度を単純に比較して、補償方式の純粋な利得だと解釈してはいけない。GPU・NDP構成では512GB/sの帯域と512GBの容量を持つNDP装置を仮定している。

## 評価：品質回復とオフロード処理量

### 評価条件

| 項目 | 一次資料の条件 |
|---|---|
| モデル | Mixtral-8×7B、Mixtral-8×22B、DeepSeek-MoE-16B |
| 専門家構造 | Mixtralは8専門家から2選択。DeepSeekは64専門家から6選択、共有2専門家を常時起動 |
| GPUのみ | NVIDIA H100 80GB、CPU側DDRメモリ、PCIe経由の専門家オフロード |
| GPU＋NDP | H100＋512GB/s・512GBのNDP装置。Ramulator系構成を使用 |
| 量子化 | 低ビット重み2/3ビット、補償因子INT3 |
| 品質評価 | MMLU（5-shot）、MathQA、HellaSwag、ARC、BoolQ、Winogrande、PiQA（zero-shot）、WikiText2困惑度 |
| 比較 | GPTQ、HQQ、Mixtral-Offloading、HOBBIT、MoNDE |
| 処理量評価 | 入力長256と出力長512などの構成で生成トークン/秒 |

### 精度改善の条件差

GPTQの2ビット一様量子化では、七つの常識推論課題の平均正答率がMixtral-8×7Bで70.03%から34.41%、Mixtral-8×22Bで72.62%から37.10%、DeepSeek-MoE-16Bで59.63%から38.50%へ下がると報告する。これは極端な低ビット化の悪影響を示す比較であり、提案法がすべての課題で元のFP16精度を完全回復したことを意味しない。

HQQとの比較では、Mixtral-8×7Bの提案法はINT3で平均正答率0.45ポイント、INT2で8.24ポイント改善し、MMLUではINT3で1.11ポイント、INT2で10.50ポイント改善する。Mixtral-8×22BでもINT3で平均0.74ポイント、INT2で8.70ポイント改善する。一方、DeepSeek-MoE-16BはINT3で平均1.63ポイント、INT2で2.30ポイントの改善にとどまる。ルータ得点の分布が均等なモデルほど、上位少数専門家の補償だけでは回復が限定的になる。

### GPUのみの転送律速環境

Mixtral-8×7BではMixtral-Offloadingの2.37トークン/秒に対し、提案法は3ビット12.27、2ビット18.11トークン/秒で、それぞれ約5.17倍、7.64倍となる。Mixtral-8×22Bでも約5.18倍、7.63倍と報告する。HOBBITとの比較ではMixtral-8×7Bの6.75トークン/秒に対し25.43、36.97トークン/秒で約3.77倍、5.48倍となる。いずれも転送する専門家重みの低ビット化が大きな寄与を持つ。

DeepSeek-MoE-16BではMixtral-Offloading比約4.38〜5.93倍、HOBBIT比約2.95〜3.78倍と、Mixtralより利得が小さい。DeepSeekは起動専門家数が多く、得点の集中が弱いため、補償対象を増やすと追加転送が増える。論文の「最大8倍近い高速化」を、モデルと基準方式を明示せず一般的な高速化倍率として扱わない。

### NDP混合構成

MoNDEとの比較では、Mixtral-8×7Bの11.56トークン/秒から、3ビット54.96、2ビット77.33トークン/秒へ改善する。DeepSeek-MoE-16Bでは61.75から194.51、233.24トークン/秒で約3.15倍、3.78倍となる。これはNDPで低ビット専門家を処理し、GPUへ送る専門家を限定する構成の効果を含む。GPUのみの2.37トークン/秒とNDPの77.33トークン/秒を直接比べ、量子化方式だけで得られた差と解釈してはいけない。

### 構成要素除去と感度

Mixtral-8×7BのINT2条件では上位第1位の専門家だけを補償するとMMLU47.53%、WikiText2困惑度6.32であるのに対し、第2位だけを補償するとMMLU25.26%、困惑度16.76へ悪化する。上位2専門家を補償するとMMLUは48.79%となり、第1位だけの場合からの上積みは小さい。得点の高い専門家を優先することの有効性を示す。

DeepSeek-MoE-16Bでは上位第1位だけの補償でMMLU25.80%、上位3専門家では28.75%へ改善し、WikiText2困惑度も17.81から10.99へ下がる。下位第4〜6位だけを補償するとMMLU25.80%、困惑度16.03となる。補償対象数と対象順位の両方が品質へ影響する。尖度に応じたランク配分は同じ平均予算で高誤差専門家へ補償を集中するための仕組みであり、単純な一律ランクとは異なる。

## 限界と評価上の留保

低ランク補償は量子化誤差を近似するもので、元のFP16重みを完全に復元する可逆圧縮ではない。INT3で保存した補償因子にも誤差があり、2ビット化で失われた情報をすべて取り戻せるとは限らない。得点の低い専門家も重要な情報を持つ場合があり、上位n個だけの補償はルータ分布が均等なモデルで効果が小さくなる。DeepSeekの改善率がMixtralより小さいという実験は、この限界を示す。

尖度と量子化誤差の相関は論文の対象モデルでの経験的観測であり、あらゆる専門家行列に対する最適ランクを保証しない。尖度の高い専門家から大きなランクを割り当てる単純な貪欲規則は、総誤差を最小化する厳密解とは限らない。オフラインでの量子化、SVD、因子のINT3化には前処理費用と保存領域が必要であり、モデルを更新すれば再計算が必要になる。

GPUのみの速度改善はCPUからの重み転送が支配的な環境で測定される。GPUメモリに専門家をすべて常駐できる構成では、低ビット化の通信節約が同じ速度改善へつながるとは限らない。NDP混合構成では専用の近傍データ処理装置を仮定するため、一般的なGPUとCPUだけのPCへ直接適用できない。また、性能比較には低ビット化自体の効果が含まれるため、低ランク補償を付けたことによる純粋な速度利得とは区別する必要がある。

## 位置づけとまとめ

従来の一律低ビット化は転送量を減らすが、MoEのルータが選ぶ専門家の重要度差を無視する。本研究は**全専門家の重みを低ビット化したまま、重要な専門家の量子化残差だけを小さな低ランク因子で補う**。事前の尖度によるランク予算配分と、実行時のルータ得点による補償対象選択が異なる役割を担う。主な適用先はCPUメモリやNDPから専門家を運ぶ帯域律速のMoE推論であり、低ビット化による高速化を維持しつつ推論品質の悪化を抑える方式として位置づけられる。
