# A Fast Post-Training Pruning Framework for Transformers：再学習不要の高速な構造化枝刈り

## 概要

Transformerの計算量と推論遅延を減らすために、不要な注意頭や順伝播層のフィルタを削る構造化枝刈りが使われる。しかし従来方式は、枝刈り後の品質回復のために長時間の再学習を必要とし、展開先のGPUや遅延制約ごとに手間がかかる。本論文は、**学習済みのBERT系Transformerを、少量のサンプルだけで再学習なしに構造化枝刈りする**枠組みを提案する。経験的フィッシャー情報によるマスク探索、層内相互作用を補正するマスク再配置、層出力を再現する最小二乗マスク調整の三段階である。

NeurIPS 2022の原著では、BERT BaseとDistilBERTをGLUE・SQuADで評価した。品質低下を1%以内に抑えながら、BERT Baseでは元の演算量の60〜70%程度まで、DistilBERTでは条件により50%まで減らした。単一NVIDIA V100でのPyTorch推論はバッチ256で幾何平均1.47倍、最大1.56倍高速化した。枝刈りの一連の処理時間はGLUE平均39.3秒、SQuAD平均135.1秒であり、従来の再学習型手法に比べて2〜3桁短い。ただし、この結果はエンコーダ型モデルの分類・質問応答に対するもので、自己回帰生成LLMのトークン生成速度を直接測ったものではない。

## 背景と課題

重みを個別に0にする非構造化枝刈りはモデル容量を減らせても、一般的なGPU上で密な行列積として実行する限り速度改善が小さい場合がある。構造化枝刈りは注意頭やFFNフィルタのまとまりを削り、**より小さな密行列**として実行できるため、特殊な疎行列カーネルなしで遅延改善を得やすい。しかし、どの層のどの注意頭・フィルタを削るかによって品質への影響は異なり、単純な重要度順位で削るだけでは層内の相互作用を見落とす。

既存のDynaBERT、EBERT、Block Movement Pruning、CoFiなどは、枝刈りの探索と品質回復に再学習や追加の最適化を伴う。計算予算を節約したい展開現場で数時間から数十時間の再学習が必要なら、圧縮の実務上の費用が大きい。著者は量子化における事後量子化のように、既に学習・微調整が終わったモデルと少量の代表サンプルだけから、指定した演算量・遅延制約を満たす枝刈りモデルを迅速に作ることを目標にする。

対象はBERTのようなエンコーダ型Transformerで、各層に多頭注意（Multi-Head Attention; MHA）と順伝播網（Feed-Forward Network; FFN）がある。BERT Baseでは12層、注意頭12、FFNの中間幅3072である。著者は埋込み層と最後の分類器は枝刈り対象とせず、注意頭とFFNフィルタに対応するマスクだけを調整する。最終的には0の要素を実際に削除して小さい密行列へ再構成するため、推論時にゼロマスクを乗算するだけの方式とは異なる。

## 手法

### 1. 構造化マスクと資源制約

各注意頭とFFNフィルタの出力にマスク変数 $m_i$ を掛ける。$m_i=0$ なら対応する頭またはフィルタを除去し、$m_i=1$ なら元の寄与を残す。最初は全て1で、枝刈り後の品質損失 $\mathcal{L}(m)$ を小さくしながら、$\mathrm{Cost}(m)\le C$ を満たすマスクを求める。費用は浮動小数点演算数（FLOPs）か、対象ハードウェアの遅延として指定できる。遅延制約を使う場合には、頭数・フィルタ数と遅延を対応させる**対象ハードウェアの遅延参照表**が必要であり、実機依存の制約を単なるFLOPsへ置き換えない。

マスク変数はBERT Baseで約3.7万個であり、全重み約1.1億個よりはるかに少ない。著者はこの小さい探索空間を利用し、各タスクの訓練集合から通常1000〜2000例、実験では2000例を取り出して枝刈りに用いる。モデル本体の重みは固定し、枝刈りマスクだけを探索・調整するので、モデル全体を再学習する必要がない。

### 2. フィッシャー情報による軽量マスク探索

枝刈りによる損失変化を、全マスク1の周囲の二次テイラー展開で近似する。微調整済みモデルが局所的に収束していると仮定し、一次項を無視すると、変化は概ね $(1-m)^T H(1-m)/2$ で表される。ヘッセ行列 $H$ の代わりに、サンプルごとのマスク勾配の外積平均である経験的フィッシャー情報を用いる。全行列をそのまま扱うのは高価なため、第一段階では対角要素 $I_{ii}$ を各頭・フィルタの重要度として扱う。

費用が同じ種類の頭・フィルタ間では、重要度が小さいものから削る方が近似損失を小さくできる。頭とフィルタでは費用が異なるため、残す頭の数を候補として列挙し、その頭数の下で予算内に残せるフィルタ数を計算する。各候補で重要度の小さいものを削り、合計重要度が最小の組合せを選ぶ。これにより全組合せを探索せず、演算量制約に対応する二種類の構造を効率的に配分する。

### 3. マスク再配置で層内相互作用を補正

対角フィッシャー近似は、同じ層の複数頭やフィルタを同時に削ったときの相互作用を無視する。そこで第二段階では、第一段階で決めた各層の残存頭数・フィルタ数を保ったまま、0を置く位置を層内で再配置する。層内の勾配外積から相互作用を考慮し、同じ費用の範囲で損失の小さいマスク配置を探す。重要なのは**残存要素の個数を変えずに配置だけを改善する**ことであり、この段階で目標FLOPsや遅延を超過させない。

単純な重み絶対値による重要度や、マスク勾配だけの一次近似では、同じ構造数でも品質が大きく悪化する条件がある。原著の構成要素除去では、フィッシャー重要度と層内再配置を併用する方が良い枝刈りマスクを得られることを確認している。再配置の結果が良くない場合には後段のマスク調整だけで品質を完全回復できないため、二段階の探索は相補的である。

### 4. 層出力の最小二乗再構成

第三段階では、残すマスク変数を0/1に固定せず、非ゼロの実数係数として調整する。元モデルと枝刈りモデルへ同じサンプルを入力し、各層の残差接続後の出力を一致させるように最小二乗問題を解く。注意頭・FFNフィルタの出力を列に並べると、各層で $\min_{m_l}\|A m_l-b\|_2^2$ という線形最小二乗になる。これによりモデル本体の重みを再学習せず、残した頭・フィルタの寄与係数だけで削除した成分の出力を補う。

巨大な行列を直接解くと数値不安定・高費用となるため、著者はCuPyのLSMR反復解法と固定の減衰係数を使う。調整は第1層から順に行い、前の層の枝刈りで変わった入力分布を後段の再構成へ反映する。マスク係数を変えても残存頭・フィルタ数は変わらないため、FLOPsや遅延の制約を保てる。最終的にゼロの構造を取り除き、非ゼロ係数を出力側へ組み込めば、小さい密行列として実行できる。

### 5. 推論用モデルの生成までの処理

処理全体は「微調整済みモデルと代表サンプルの読込み→マスク勾配計算→フィッシャー対角の推定→費用制約付きの頭・フィルタ数探索→層内マスク再配置→残存係数の最小二乗調整→不要な構造の物理的削除→対象GPUでの推論」の順となる。実行時の遅延を制約する場合は、事前に測定した遅延参照表を使う。枝刈り後の出力は元モデルと完全一致するとは限らないため、タスクの検証集合で品質を確認する必要がある。

## 評価

### モデル・タスク・計測環境

| 項目 | 原著で確認した条件 |
|---|---|
| 対象モデル | BERT Base、DistilBERT。既に下流タスクへ微調整した重みを使用 |
| 評価タスク | GLUEのMNLI、QQP、QNLI、SST-2、STS-B、MRPC、およびSQuAD 1.1・2.0 |
| 枝刈り用サンプル | 各タスクの訓練集合から2000例を抽出 |
| 評価集合 | 各タスクの開発集合。10種類の乱数種による平均 |
| 実装 | PyTorchとTransformers、最小二乗調整にCuPy/LSMR |
| 実機 | 単一NVIDIA V100 GPU。推論遅延はバッチ32と256で比較 |
| 指標 | 元モデルからの品質低下、相対FLOPs、推論速度倍率、枝刈り処理時間 |

GLUEはタスクごとに正解率や相関などの指標が異なり、SQuADは質問応答のF1を用いる。論文の「1%以内の品質低下」は、元モデルの対応タスク指標を基準にした条件であり、全タスクで絶対的に同じ品質水準を達成する意味ではない。枝刈りに使う2000例と、性能評価の開発集合を分けている。

### FLOPsと品質の交換条件

原著図5では、BERT Baseの各タスクで品質低下を1%以内に保ちながら、元のFLOPsの約60〜70%まで削減できた。これは約30〜40%のFLOPs削減に相当する。DistilBERTは既に小型化されているが、STS-BとMRPCでは元の約50%までFLOPsを減らしても品質低下を1%以内に抑えられた。したがって、既に蒸留したモデルにも追加の構造化枝刈り余地がある。ただし、どのタスクでも半分まで削減できるわけではなく、各タスク・モデルでの許容品質と資源予算に応じて選ぶ。

### V100 GPUでの推論高速化

| タスク | バッチ32の速度倍率 | バッチ256の速度倍率 |
|---|---:|---:|
| MNLI | 1.27倍 | 1.34倍 |
| QQP | 1.42倍 | 1.54倍 |
| QNLI | 1.42倍 | 1.53倍 |
| SST-2 | 1.23倍 | 1.56倍 |
| STS-B | 1.34倍 | 1.54倍 |
| MRPC | 1.36倍 | 1.55倍 |
| SQuAD 1.1 | 1.33倍 | 1.34倍 |
| SQuAD 2.0 | 1.37倍 | 1.40倍 |
| 幾何平均 | 1.34倍 | 1.47倍 |

原著表1の数値で、品質低下が1%以内となる枝刈り構成の中から最大の速度倍率を選んでいる。最速のSST-2・バッチ256は1.56倍だが、同じSST-2でもバッチ32では1.23倍である。演算量を半分にしても推論速度が厳密に2倍になるわけではなく、バッチ、対象タスク、GPU上のカーネル効率に依存する。これらはBERT系のエンコーダ推論であり、自己回帰デコードのトークン/秒を測った値ではない。

### 枝刈りに要する処理時間と費用内訳

| 処理 | GLUE | SQuAD |
|---|---:|---:|
| 勾配計算 | 23.8% | 20.5% |
| マスク探索 | 0.3% | 0.1% |
| マスク再配置 | 9.4% | 3.5% |
| マスク調整 | 66.5% | 76.0% |
| 合計処理時間 | 39.3秒 | 135.1秒 |

原著付録表5の単一V100 GPUでの平均。マスク探索そのものは全時間の0.3%以下であり、最も時間を使うのは最小二乗で出力を再構成するマスク調整である。通常の再学習を必要とするDynaBERT、EBERT、BMP、CoFiなどは、原著の比較では5〜33時間の追加訓練を要した。したがって、数分で済むという利点は**モデルを圧縮する準備処理**の速さであって、個々の推論要求が39秒で終わるという意味ではない。

### 構成要素除去と負の結果

原著の構成要素除去では、マスク再配置とマスク調整の両方が品質回復に寄与し、とくにマスク調整が最大2.88%の品質を回復した。対角フィッシャーだけで選ぶと層内の複数削除の相互作用を取り逃し、単純な重要度順位だけでは十分でない。重み絶対値や一次勾配を使った別の重要度では、比較的低い枝刈り率でも精度が大きく落ち、後段のマスク調整でも完全には回復できない例がある。従って「残存係数の最小二乗調整だけでどんな枝刈りマスクも修復できる」という理解は誤りである。

高い枝刈り率では、再学習なしの精度保持が難しくなることも示されている。原著はより強い枝刈りで再学習を組み合わせる場合の比較も行うが、再学習を追加すれば本手法の「再学習不要」という主要な運用上の利点は失われる。適用範囲は品質低下を許容できる中程度の構造化枝刈りと捉えるべきである。

## 既存方式との差

非構造化の重み削除は、GPU上でそのまま速度改善へつながりにくい。量子化は各重みの表現ビット数を減らすのに対し、本手法は注意頭とFFNフィルタの**数そのものを減らす**ため、密行列演算の形を保ちながら演算量を削減できる。DynaBERTやCoFiのような再学習型の構造化枝刈りは高い圧縮率を狙えるが、探索・回復の計算費用が大きい。本手法は少量サンプルと固定済み重みから数分で圧縮を完了し、対象GPUの遅延参照表を使えば資源制約に直接合わせられる点が異なる。

## 限界と推論システムへの適用

本論文の実証対象はBERT BaseとDistilBERTというエンコーダ型Transformerである。デコーダ型LLMでは因果注意、KVキャッシュ、自己回帰生成の連続的なトークン処理、バッチ混在が支配的になる場合がある。注意頭やFFNの構造削除を同じ方法で適用できるか、精度を保てるか、推論速度が何倍になるかは、別途評価しなければならない。MoEの専門家選択やCPUオフロードの性能も直接測定していない。

枝刈り用の代表サンプル2000例が運用データを代表しない場合、重要度推定と層出力の再構成が偏る可能性がある。遅延制約を指定するには対象ハードウェアの遅延参照表が必要であり、GPUやカーネルを変更すれば最適な枝刈り構成も変わり得る。学習済みモデルが局所最適付近にあるという二次近似の仮定や、フィッシャー行列の対角近似は厳密ではない。高い枝刈り率では品質回復に限界があるため、タスクごとの検証を省略できない。
