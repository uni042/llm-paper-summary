# p-DCIM: A 28nm Probabilistic SRAM DCIM based Ising Machine for Near-Memory Context Selection in LLM RAG Pipeline

> RAGの証拠選択を二次最適化として定式化し、試作したSRAMメモリ内計算チップで係数構築からアニーリングまで実行する方式で、選択エネルギーを言語モデル型選択より6桁以上下げ、クエリ全体でも67パーセント削減した。

## 概要

検索拡張生成（RAG）は、外部知識から取得したパッセージを文脈として言語モデルへ渡し、パラメータに無い知識を補う推論方式である。その中間段階である文脈選択、つまり候補パッセージの集合から回答に使う証拠を選ぶ処理は、品質と費用の両方を左右する。従来の上位K件方式は各候補を独立に採点するため、候補同士の冗長性や補完性を扱えない。多段ホップの質問では、単独では順位の低い候補が別の候補と組で必要になることがある。そこで近年の方式は集合レベルの選択を言語モデル自身へ任せるようになったが、これは生成の前に追加のトランスフォーマー推論を挟むことを意味し、出力が少数のパッセージ識別子にすぎない割に、重みの読み出しと計算で大きな遅延とエネルギーを消費する。

本論文のp-DCIMは、この選択段階を意味処理から切り離し、組み合わせ最適化として専用ハードウェアで解く。選択問題は、クエリへの関連度、クエリを分解した要件の被覆、選択費用、候補間の冗長性と補完性を目的関数に含む二次制約なし二値最適化（QUBO）へ定式化される。これを解くのが、28ナノメートルプロセスで試作されたSRAMデジタルメモリ内計算（DCIM）のイジングマシンである。特徴は一つのアレイと符号付き加算木を二つのモードで使い回す点にある。決定論モードでは候補埋め込みを流し込んで内積を計算し、QUBOの係数そのものを構築する。確率モードでは、構築した係数を同じアレイに保持し、スピン更新に必要な局所エネルギー差をメモリ内で評価してアニーリングする。確率性は専用の乱数回路ではなく、低電圧でのSRAM疑似読み出しエラーを利用し、冷却の強さはアナログ電圧ではなく、攪拌へ晒す大きさビットプレーンの数をデジタルに減らすことで制御する。配置先として想定するのは、高帯域フラッシュ（HBF）スタックのロジックベースダイであり、ニアストレージ検索で得た候補埋め込みをメモリサブシステムの外へ出さずに選択し、選ばれたパッセージの識別子だけをGPUへ返す。

**代表結果:** 試作マクロは0.16平方ミリメートル、500メガヘルツ動作で、確率モードの消費電力は0.413ミリワットである。評価条件では文脈選択に約2.2ミリ秒と約0.9マイクロジュールを使い、言語モデル型の選択器が要する1クエリ約358ジュールに対し、選択段階のエネルギーは6桁以上の差になった。要件生成と回答生成はGPUに残るため、クエリ全体では約536ジュールから約175ジュールへ67パーセントの削減である。品質面では、評価したHotpotQA事例で完全一致0.70、トークンレベルのF1は0.8524と、言語モデル型選択器SetRとSetROの0.7857を上回った。

## 問題設定

問題は三層に分かれる。第1に選択の質である。独立採点の上位K件は集合としての効用を最大化しない。冗長な候補を重ねて選び、要件の一部が未被覆のまま残ることがある。第2に選択の費用である。言語モデル型の選択は集合の相互作用を扱えるが、費用構造が生成と同格であり、モデル重みを高帯域メモリから繰り返し読む。選択の出力は識別子の集合にすぎず、投入する計算と見合わない。第3に、最適化へ置き換えても残る構築費用である。QUBOの二次項は候補同士の類似度を必要とし、候補数Nに対してNの二乗の相互作用を評価する。候補埋め込みを一度GPUへ運んでから係数を作るのでは、アクセラレータが避けるはずのデータ移動を最適化の前に払うことになる。特に、ベクトル検索自体をフラッシュスタック内で行うニアストレージ型RAGでは、候補が既にメモリ近傍にあるのに、選択のためだけにパッケージ境界を越えるのは無駄が大きい。したがって求められるのは、係数構築と求解を同じ場所で、できれば同じハードウェアで実行し、結果だけを返す構成である。また、アニーリングの確率性を得るために専用の確率素子や線形帰還シフトレジスタ等の乱数周辺回路を足すと、面積と設計の複雑さが増す。SRAMセルの読み出し攪拌という、メモリに元々ある物理現象を乱数源として使えれば、この追加回路を省ける。ただし電圧に対するエラー率の遷移は約60ミリボルトと狭く、アナログな温度制御としては扱いにくい。これをデジタルな段階制御へ置き換えることが、異種メモリパッケージへの統合でも再現性のある冷却を実現する鍵になる。

## 手法のあらまし

流れは四段階である。まずGPU側でクエリを要件へ分解し、HBFスタック内のニアストレージ検索が候補パッセージとその埋め込みをメモリ近傍で用意する。次にp-DCIMが決定論モードで動き、クエリ埋め込み、要件埋め込み、候補埋め込みの内積から、関連度、要件支持、候補間の冗長性と補完性を計算してQUBO係数を組み立て、量子化して同じSRAMアレイへ書き戻す。制約に由来する罰則項の係数は既知の定数からホスト制御側で作り、埋め込み由来の係数と合成する。続いて供給電圧を下げて確率モードへ移り、疑似読み出し攪拌で係数を揺らしながら局所エネルギー差の符号でスピンを逐次更新するアニーリングを行い、攪拌へ晒すビットプレーン数を段階的に減らして冷却する。最後に、選択されたパッセージの識別子だけをGPUへ返し、GPUはその本文を取得して通常どおり回答を生成する。要件生成と回答生成は言語モデルの仕事としてGPUに残り、組み合わせ選択だけがメモリ近傍の専用基盤へ移る。

## 手法

### 1. 集合選択のQUBO定式化 — 関連度と被覆と相互作用を一つの目的関数へ

この定式化が観測するのは、候補パッセージの集合と、クエリを分解した要件の集合である。保持する状態は、各候補を選ぶかどうかの二値変数、各要件が被覆されたかを示す二値変数、および制約を等式化するためのスラック変数である。行う動作は、線形項として候補の関連度、要件の重み付き被覆、選択費用を置き、二次項として候補間の冗長性への罰と補完性への報酬を置くことである。冗長性は埋め込み類似度と要件支持の重なりの比から、補完性は異なる要件を支える組を優遇する形で定義される。要件被覆の不等式と、文脈予算K以下の本数制約は、二値符号化したスラック変数で等式化し、残差の二乗を罰則として目的関数へ畳み込む。最大化問題を符号反転して標準形の最小化QUBOとし、対角項は1に固定した補助変数との結合へ写すピン留め埋め込みで、通常の積和データパスだけで扱える形にする。減るボトルネックは、独立採点では表現できない集合レベルの相互作用である。追加で消費する資源は、候補数と要件数に応じた変数と係数の規模であり、二次項が支配的になる。失敗条件は、要件分解そのものが誤っている場合であり、その場合は最適化が正しくても被覆すべき要件が欠け、選択の質は要件生成側に制限される。

### 2. 決定論モード — 同じ積和データパスで係数を構築する

この機構が観測するのは、正規化されたクエリ埋め込み、要件埋め込み、候補埋め込みである。保持する状態は、計算途中の部分和と、完成した係数のオンチップバッファである。行う動作は、埋め込みをSRAMアレイへ流し込み、符号付き加算木で内積を評価して、関連度、要件との支持判定、候補間類似度をすべて同じハードウェアで作ることである。埋め込みの次元がアレイ幅を超える場合は複数パスに分けて部分和を累積する。制約由来の罰則係数はデータに依存しないためホスト制御側で作り、埋め込み由来の係数と合成してから8ビットへ量子化してアレイへ書き戻す。SRAMを使う理由は書き換え特性にある。QUBOはクエリごとに係数が変わり、アニーリング中も係数の定期的な復元書き込みが発生するため、重みを固定する前提の不揮発メモリ型基盤より、書き込み遅延が小さく書き換え回数に制限のないSRAMが向く。減るボトルネックは、係数構築のための候補データの移動であり、Nの二乗の相互作用評価がメモリサブシステム内に閉じる。追加費用は係数の書き戻しと量子化誤差であり、8ビット表現が求解精度の前提になる。失敗条件は候補数がアレイ容量を超える場合で、その場合は問題を分割するか振る舞いモデル側の拡張が必要になり、単一マクロで完結しなくなる。

### 3. 確率モードとデジタル冷却 — 疑似読み出しエラーを温度つまみへ変える

この機構が観測するのは、現在の二値状態と、アレイに保持されたQUBO係数である。保持する状態はスピン配置と、名目係数のバッファである。行う動作は、変数を一つずつ選び、その変数を反転したときの局所エネルギー差をメモリ内積和で評価し、符号に従って反転を採否する逐次更新である。確率性は係数そのものへの攪拌として入る。供給電圧を0.6ボルトへ下げると、SRAMの疑似読み出しが確率的にビットを乱し、保持値0と1で非対称なエラー率（実測で約63パーセントと約38パーセント）が得られる。名目係数はオンチップバッファから周期的に復元され、攪拌が累積して係数が壊れることを防ぐ。冷却は、符号ビットプレーンを常に保護しつつ、攪拌へ晒す大きさビットプレーンの数を7、5、3、1と段階的に減らすことで行う。上位プレーンほど数値的な重みが大きいため、晒すプレーン数を減らすと係数攪拌の実効強さが単調に下がり、実測の二乗平均平方根攪拌量もそれに応じて減少する。つまり乱数源は素子の物理現象、温度の制御はデジタルなプレーン有効化信号という分離ができており、狭い電圧遷移を精密に制御する必要も、乱数生成の周辺回路も要らない。減るボトルネックは、アニーリング基盤の周辺回路と制御の複雑さである。追加費用は係数復元の書き込みと、逐次更新ゆえの直列性である。失敗条件は、問題規模が大きく混合が進まない場合であり、逐次更新と固定した反復回数の下では、大規模問題の解の質は振る舞いモデルでの外挿に依存する。

### 4. ニアメモリ統合 — 候補を動かさず識別子だけを返す

システム構成として、p-DCIMはGPUへぶら下がる独立アクセラレータではなく、HBFスタックのカスタムロジックベースダイへ置かれる。ベクトルデータベースとニアストレージ検索はフラッシュダイ側にあり、候補埋め込みはHBFサブシステム内で消費される。高帯域メモリ側の言語モデル重みは選択段階では一切アクセスされず、GPUはクエリ側情報の生成と、返された識別子に基づく本文取得と回答生成だけを行う。データの流れとしてパッケージ境界を越えるのは、クエリ側の小さな情報と、選択結果の識別子だけである。なお、この統合システム自体は試作されておらず、試作されたのはマクロ単体であり、システムレベルの数値は実測パラメータで較正したモデルによる評価である点が、結果を読む前提になる。

| デジタル冷却 | ビットプレーンの有効化数 | 晒す大きさプレーンを段階的に減らす | アナログ温度制御と乱数回路 | 冷却段数が粗く段階的 |

## 評価

結論は三点である。第1に回路レベルでは、試作チップ上でアレイに収まる小規模な最適化問題をすべて解き、10事例すべてで総当たりの最適解と一致した。第2に応用レベルでは、実測統計で較正した振る舞いモデルによるHotpotQA評価で、言語モデル型の選択器と同等以上の回答品質を保った。第3にシステムレベルでは、選択段階のエネルギーが6桁以上減り、クエリ全体でも67パーセントの削減になった。ただし内訳の性質は明確に分けて読む必要がある。チップの電力と確率特性は実測だが、HotpotQA規模の求解とHBF統合システムはモデル評価であり、選択エネルギーの0.9マイクロジュールも実測電力からのマクロ正規化推定である。遅延以外の指標、例えば大規模問題での解の質の統計や、実パッケージでの統合効果は未評価である。

## 既存研究との差

イジングマシンや確率ビットによる組み合わせ最適化は、巡回セールスマン問題や最大カット等の古典的ベンチマークで発展してきた。SRAMメモリ内計算によるアニーラも先行例があるが、対象は問題固有の最適化か、著者らの先行研究のような二値ニューラルネットワークの頑健性検証であり、いずれも係数が外部で用意される前提だった。本論文の差分は三つある。第1に、対象がLLM推論パイプラインの中で繰り返し現れる実務段階であり、最適化の応用先としてRAGの文脈選択を選んだこと。第2に、係数の構築そのものを同じメモリ内計算データパスで実行し、構築と求解を分離しないこと。第3に、確率性の源泉と冷却制御を分離し、疑似読み出しエラーとデジタルなプレーン数制御でアニーリングを構成したことである。RAG側の先行研究である集合選択の定式化とニアストレージ検索（HAVEN）の上に、試作チップによる実測を載せた位置付けになる。

## 限界・実装状況

試作マクロは64×64と小規模であり、実用規模の候補数へは単一マクロでは届かない。タイル化や複数マクロの協調は将来課題として残る。HBF統合は提案段階であり、実パッケージでの帯域や熱の影響は未評価である。品質評価の事例範囲は限定的で、選択定式化の大規模評価は著者らの別報告に委ねられている。係数は8ビット量子化されており、類似度の細かな差が落ちる条件では選択が変わり得る。要件分解はGPU上の言語モデルに依存するため、パイプライン全体の費用と品質はその段階にも左右される。コードやチップ設計の公開は論文本文では確認できず、本稿ではコードなしとして扱う。

## 一般的な実装上の含意

推論基盤への示唆は三つある。第1に、パイプライン内の小さな組み合わせ問題は、言語モデルへ丸投げせず専用基盤へ切り出すことで、費用構造を桁で変えられる。第2に、アクセラレータの効果は求解器単体ではなく、問題の構築に必要なデータ移動まで含めて設計しないと相殺される。第3に、物理現象由来の確率性を使う場合でも、制御はデジタルな段階量へ寄せると、プロセスや統合環境の違いに対する再現性が確保しやすい。
