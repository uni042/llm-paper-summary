# Accelerating LLM Inference with Staged Speculative Decoding

## 概要
端末内の単一要求・小batch推論では、巨大なweightをtokenごとに読み直す一方で行列のbatch次元が小さく、Tensor Core等の演算器を使い切る前にmemory bandwidthが律速になる。Staged Speculative Decodingは、追加計算を許して対象モデルへの逐次呼出し回数を減らす投機的復号を、木構造batchと複数段のdraftで強化する。RTX 4090のroofline分析でもsingle-query GPT-2-Lは完全にmemory-bandwidth boundであり、算術強度を上げることが速度改善の鍵とされる。

通常の投機的復号は小型draftが1本のtoken列を先読みし、対象モデルがまとめて検証する。しかし列を長くするほど全prefixが連続して一致する確率が急速に下がり、batchを大きくしても期待採択token数が伸びにくい。本論文は計算予算を「1本を深く」ではなく「複数候補へ幅広く」配り、さらに低entropy tokenをより安価なdraft段で処理する。

## 問題設定
小batchでは対象モデルの1回のforwardで使える並列性が低く、weight trafficがtoken latencyを支配する。投機的復号は対象モデルの1回のbatch検証で複数tokenを確定できるが、draftと対象モデルの一致率が低いほど後続tokenが捨てられる。したがって性能は、対象モデル1回あたりの期待確定token数と、draftを作る追加costの両方で決まる。

## 手法
### 木構造の投機batch
単一候補列の末尾へ計算を足す代わりに、上位2位・3位候補などへ分岐するtreeを動的に構築する。treeを幅広くすると、誤った1枝の後続計算を浪費せず、oracleが受理できる枝をbatch内に残しやすい。leafはdraft modelを追加実行せずにbatch候補として利用できるため、内部node数に対してoracleへ渡す候補数を増やせる。

### tree-aware attentionとKV処理
候補treeを対象Transformerへ渡す際は、position embeddingとcausal maskをtreeの祖先関係に合わせる。KV cacheはbatch全体の新規KVを一時領域へ保持し、採択されたpathのsliceだけをmain KV cacheへappendする。これにより異なる候補branchが互いの未来tokenを参照せず、1回の対象モデル実行で複数pathを検証できる。

### 多段投機
通常は小Transformer→対象モデルの二層だが、本方式はさらに安価な第2 draft段を前に置く。実験ではN-gram系の予測が空白や定型codeのような低entropy tokenを先取りし、小Transformerが中程度の難度、最終oracleが難しいtokenを担当する。全tokenは最終的にoracleで検証されるため、出力品質は対象モデルと一致する。

### bandwidthとの交換
論文の相対memory bandwidth表ではdeterministic samplingで通常投機がbaselineの0.31、stagedが0.23、top-kでは0.48と0.35である。つまり追加draft計算を増やす代わりに、大モデルweightを読み込む頻度を下げる。これはcompute-boundな大batchより、小batch・端末内推論に適した交換である。

## 評価条件
|項目|内容|
|---|---|
|対象モデル|GPT-2-L 762M|
|workload|HumanEval code completion|
|推論形態|single-batch / on-deviceを想定|
|sampling|deterministic、top-k (k=50, T=1)|
|比較|通常decode、標準speculative decoding|
|指標|相対memory bandwidth、sequential decoding throughput|
|実装上の注意|Python infrastructure overhead約35%|

## 主要結果
deterministic samplingではreference implementation比平均3.16倍、標準投機的復号比1.36倍の速度向上を得る。top-k samplingではstochastic rejectionが増えて両投機方式とも悪化するが、それでもbaseline比1.98倍、標準投機比1.36倍を維持する。

promptごとの差は大きく、現実的promptで約2倍から最大10倍程度まで振れる。indentの多いPython codeなど低entropy部分が多い出力はN-gram段で多く処理できるため利得が大きい。一方、高entropy tokenが密な生成では各段のdraftが外れ、最終対象モデルの小batch decodeへ戻る頻度が増える。

## 既存研究との差
標準投機的復号は単一draft列を検証するのに対し、本方式はtree幅へ予算を配分し、さらにdraft自体を階層化する。高速化源は対象モデルを近似して品質を落とすことではなく、同じ対象分布を保ったままmemory-boundな逐次呼出しをparallel batchへ変換する点にある。

## 限界
評価モデルは762M GPT-2-Lと現在の大規模LLMより小さく、HumanEval中心である。性能は生成entropyとdraft一致率に強く依存し、top-kのような確率samplingではrejectionが増える。実装には約35%のPython overheadがあり、tree構築・複数段draft・一時KV管理の追加costもあるため、compute-boundな大batchでは同じ利得を期待できない。
