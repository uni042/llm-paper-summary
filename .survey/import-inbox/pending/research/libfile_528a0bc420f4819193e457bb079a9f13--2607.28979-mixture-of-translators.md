## 概要

複数LLMを組み合わせるagentやrouting systemでは、同じsystem prompt、検索文書、会話履歴を異なるmodelが読むことがある。しかしキー・バリューキャッシュ（KV cache）は各modelのlayer数、hidden dimension、attention表現に依存するため、あるmodelで計算済みのcontext cacheを別modelへそのまま渡せない。その結果、同じcontextをmodelごとに再prefillする。

Mixture-of-Translators（MoT）はsource modelのKV cacheをtarget modelのcache空間へ写す学習済みtranslator群を導入する。単一projectionではsource-target間の多様な対応を表しきれないとして複数translatorを混合し、さらに変換cacheを注入した後のtarget trajectoryをnative target trajectoryへ合わせるContext Correction Lossを用いる。Qwen2.5、GPT-2、OPT間で評価し、長文cache-augmented generationでは直接contextを与えた品質の96.3%を維持する。

## 問題設定

異種model間のcache translationでは、単にhidden dimensionを線形射影すればよいわけではない。各layerのKVは前段のattention結果に依存するため、変換誤差を早いlayer/positionで注入すると後続生成へ伝播する。一方、変換cacheの利用を遅らせすぎると、target modelがnative contextを処理した場合の最終stateとの差が残る。

論文はこの2種類をpropagated translation shiftとlast-state shiftとして分ける。early injectionはcache再利用量を増やすが誤差伝播が長く、late injectionは誤差伝播を短くする代わりにtarget stateとの接続点が不整合になりやすい。

## 手法

### Mixture-of-Translators

source KVをtarget dimensionへ写す複数のtranslator moduleを用意し、入力contextに応じて複数経路を組み合わせる。単一のglobal latent spaceへ全modelを押し込む方式ではなく、source-target pairの複数変換パターンを直接学習する。

複数translatorにより、token/domainごとに異なる内部表現対応を1つのprojectionへ平均化することを避ける。出力はtarget modelが通常のKV cacheとして消費できる形に整形され、targetは元context全体を再prefillせず生成を継続できる。

### Context Correction Loss

cache要素単体をsource/target間で近づけるだけでは、変換cacheを実際にreplayしたときのtarget trajectoryがずれる。そこでMoTは変換cacheを注入したtargetの後続hidden trajectoryを、native targetが同じcontextを処理したtrajectoryへ合わせる補正lossを加える。

これにより局所的なKV再構成誤差ではなく、生成時に蓄積する機能的な誤差を直接抑える。early injectionのpropagationとlate injectionのlast-state mismatchの両方を評価し、translator mixtureとtarget-side correctionを組み合わせる。

## 評価条件

| 項目 | 条件 |
|---|---|
| model families | Qwen2.5、GPT-2、OPT |
| translation | homogeneous / heterogeneous source-target pair |
| 最大規模例 | Qwen2.5-7B級 |
| tasks | closed-set QA、extractive QA、multi-agent reasoning、long-context cache-augmented generation |
| 指標 | QA accuracy/F1、direct-context品質保持率 |
| baseline concept | native target prefill、単一変換経路等 |

## 主要結果

Qwen2.5-7B級のtranslationでclosed-set QA平均51.0%、extractive QA平均F1 0.43を報告し、異種model間でも変換cacheから有用なcontextを回復できることを示す。

実利用を模したlong-context cache-augmented generationでは、targetへcontextを直接与える場合の品質の96.3%を維持する。multi-agent case studyでも共有memoryをmodel間で再利用できることを示す。これらは「cache変換で品質を完全に一致させる」結果ではなく、再prefill削減と品質保持の交換条件を示す。

## 推論システム上の意味

通常のprefix cacheは同一model内でしか共有できない。MoTが成立すれば、model routerがrequestごとに異なるmodelを選ぶ環境やmulti-agent pipelineで、前段modelが計算した長contextを後段modelへ持ち越せる。これはGPU計算だけでなく、同じcontextを各model用に別々に保存するcache容量も削減できる可能性がある。

一方translator自体の実行costとweight、source-target pair数の増加に伴う管理costが追加される。論文の主要結果は品質保持を中心としており、大規模production servingでのTTFTやtoken/s改善量はheadline評価ではない。

## 既存研究との差

既存のcross-model cache reuseは単一projection pathや共有latent空間を仮定するものが多い。MoTは複数translatorを混合してsource-target mappingの多様性を表し、さらにcache再構成だけでなくtarget trajectoryをContext Correction Lossで合わせる。

## 限界

translatorはmodel pairに対して学習が必要で、model更新や組合せ数が増えるとtraining/storage管理が増える。品質はnative contextの100%ではなく、task/model pairで差が残る。また評価はQwen2.5/GPT-2/OPTを中心とし、MoE、MLA、極端なlong contextやproduction clusterでの実測serving speedupは今後の検証が必要である。
