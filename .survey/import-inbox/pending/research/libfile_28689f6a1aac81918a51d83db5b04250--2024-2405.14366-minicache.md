# MiniCache: KV Cache Compression in Depth Dimension for Large Language Models

## 概要

自己回帰型の大規模言語モデル（LLM）は、各層で過去tokenのkey/value状態を鍵値キャッシュ（KV cache）へ保存し、次token生成時に過去tokenを再計算しない。この仕組みはdecodeを高速化する一方、KV容量は文脈長と層数にほぼ比例して増えるため、長文脈ではGPU memoryを圧迫し、同時処理できるrequest数も制限する。

既存のKV圧縮は、値を低bit化する量子化や、同じ層の中で重要度の低いtokenを捨てる疎化が中心だった。MiniCacheは別の冗長性として、LLMの中層から深層では隣接層のKV状態が互いに似ることに着目する。各層のKVを独立保存せず、隣接層の状態を一つの共有表現へ統合する「深さ方向」の圧縮である。

単純平均では層固有の情報を壊すため、MiniCacheはKVベクトルを大きさと方向へ分解し、方向だけを球面線形補間（spherical linear interpolation; SLERP）で統合する。また隣接層間の差が大きいtokenは統合対象から外して元状態を保持する。学習やmodel weight変更は不要で、量子化や疎化とも併用できる。

LLaMA-2、LLaMA-3、Phi-3、Mistral、Mixtralを複数benchmarkで評価し、ShareGPT上のLLaMA-2-7Bでは4-bit MiniCacheが最大5.02倍の圧縮率、約5倍の推論throughput、FP16完全KVキャッシュ比41%のmemory削減を、ほぼ損失なしの品質で達成した。

## 問題設定

KVキャッシュを低bit化すれば1要素あたりのbyte数は減るが、全層が各tokenのKVを別々に持つ構造自体は変わらない。token evictionも同一層内の冗長性を利用するため、層間に同じような状態が繰り返し保存される冗長性は残る。

MiniCacheの観測では、特にnetworkの中層から深層で、隣接層のKVベクトルのcosine similarityが高くなる。これは一つの状態から二層分を近似できる余地を示す。しかし単純な算術平均では、attentionに効くベクトル方向とnormを同時に変えてしまい、full-cache baselineから品質が落ちる。

したがって必要なのは、似た隣接層だけを共有しつつ、層間差が大きいtokenの情報を壊さず、decode時には各層が必要とする状態を低い追加費用で復元できる表現である。

## 手法

### 層間冗長性を使う共有

MiniCacheは全層を無条件にmergeせず、類似度が高い中～深層から隣接層の組を圧縮する。prefillで通常どおり各層のKVを計算した後、対象となる二層の同一token位置の状態を比較し、一つの共有cacheへ変換する。圧縮後は二つの完全cacheを保持する必要がなくなる。

この設計はtoken方向の削除とは異なり、同じtokenを残したまま「層方向に二重保存されている状態」を減らす。そのため量子化やtoken sparsityと圧縮軸が異なり、両者を重ねられる。

### 大きさと方向の分離

二つのKVベクトルをそのまま平均すると、方向だけでなくL2 normも意図せず縮んだり変化したりする。MiniCacheは各状態をnormと正規化方向へ分解し、方向成分をSLERPで補間する。SLERPは二つの単位ベクトル間を球面上で補間するため、単純な線形平均より方向の幾何を保ちやすい。

補間係数は層間共有表現が双方の状態を再現できる位置を決める。実験ではおおむね0.6付近が良い結果を示す。共有状態から各層を使う際には、保存した大きさ情報を使って層側の状態を復元する。

### 差の大きいtokenの保持

平均的には隣接層が似ていても、すべてのtokenが似るわけではない。MiniCacheは同一位置の状態間の角度差を測り、差が大きいtoken pairを共有から除外する。これらについては元のKV値と位置indexを追加保存する。

decode時には共有cacheを基本として使い、保持対象tokenだけ元状態へ戻す。圧縮率を最大化するために例外tokenまで無理にmergeするのではなく、品質劣化を起こしやすい箇所だけ追加memoryを払う設計である。

### decode時の流れ

prefillでKV生成後、対象隣接層をmergeして不要になった完全cacheを解放する。生成stepでは共有状態を各対象層で利用し、norm情報と保持token情報を使って必要状態を復元してattentionへ渡す。したがって追加計算はmerge/recoveryに生じるが、保存byteとmemory trafficを減らすことで長い生成やmemory-bound条件ではthroughput改善へつながる。

## 主要結果

| 条件 | 指標 | 比較対象 | MiniCache | 読み取れること |
|---|---|---|---|---|
| LLaMA-2-7B, ShareGPT, 4-bit併用 | KV圧縮率 | 非圧縮KV | 最大5.02× | 層間共有と低bit化は重ねて効く |
| 同条件 | 推論throughput | FP16 full cache | 約5× | memory footprint / traffic削減が生成速度へ反映 |
| 同条件 | memory footprint | FP16 full cache | 41%削減 | KV以外のmodel memoryを含むため圧縮率と同じ割合にはならない |
| 複数model / benchmark | 品質 | full cache | near-lossless | 中～深層の類似状態を選択的に共有できる |
| 単純平均との比較 | 品質 | naive layer averaging | MiniCacheが優位 | norm・方向分離とtoken retentionが必要 |
| 補間係数の感度 | 品質 | 係数変更 | 約0.6付近が良好 | 層間共有位置には感度がある |

headlineの5.02倍は「system全体のmemoryが5.02分の1」という意味ではなく、4-bit量子化を組み合わせたKVキャッシュ圧縮率である。同じ代表条件で報告されるsystem memory削減は41%であり、この二つを区別する必要がある。

## 既存研究との差

KIVIなどのKV量子化は、各層に残すKV値のbit幅を減らす。token eviction / sparse KV方式は、各層で保存するtoken数を減らす。MiniCacheはこれらと異なり、隣接層間で似たKV状態が重複していることを利用して、深さ方向の保存数を減らす。

したがってMiniCacheは既存方式を置き換えるというより、別軸の圧縮として組み合わせられる。実際、4-bit量子化との併用で最大5.02倍という高いKV圧縮率を得ている点が、この直交性の実証になっている。

## 限界

利得は隣接層のKV状態が十分似ていることに依存する。浅い層や、特定tokenで層間差が大きい箇所まで強くmergeすると品質が悪化するため、merge開始層とtoken retentionが必要になる。保持tokenが増えるworkloadでは圧縮率も下がる。

学習不要で複数architectureへ適用できる一方、層間merge・復元の追加処理はゼロではない。報告された約5倍throughputはShareGPT上のLLaMA-2-7Bと4-bit併用という代表条件であり、全model・全context長で一律に5倍になる結果ではない。

また、MiniCacheはKV容量を減らすがmodel weight自体を圧縮する方式ではない。system全体のmemory削減はKVが総memoryのどれだけを占めるかに依存する。
