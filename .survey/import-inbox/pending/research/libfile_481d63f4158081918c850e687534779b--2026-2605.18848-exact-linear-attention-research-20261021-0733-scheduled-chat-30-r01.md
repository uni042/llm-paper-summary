# Exact Linear Attention

## 概要

Exact Linear Attention（ELA）は、注意カーネルが有限次元の二つの特徴写像の内積として**厳密に分解できる**とき、注意行列全体を作らずに系列方向の累積統計だけで注意出力を計算する方式である。著者はアダマール指数（Hadamard Exp）、二乗ユークリッド距離の和・差に基づくカーネルを例示し、注意の線形時間化に加えて、層間の残差経路を組み替えるHyper-Linkと、層間の表現差分を扱うMemory Lobeを提案する。

この論文でいう「厳密」は**選択した特徴写像カーネルによる二次形式と、その累積統計による線形形式が数学的に同値**という意味である。標準Transformerの指数内積softmax注意を有限次元の写像で誤差なく置き換えたという意味ではない。例えばHadamard Expは各次元の指数を掛けて足すカーネルであり、exp(q·k)とは異なる。したがって標準softmax注意の事前学習済みモデルを無変更で置換して出力を完全再現する方式とは解釈できない。

論文の主な実験は約584万パラメータの小型GPT相当モデル、451,500学習トークン、30エポックでの損失曲線比較であり、ELAと通常の全注意の学習挙動が概ね近いと報告する。一方、概要の「6倍の復号速度」「KVキャッシュ75%削減」は先行するKimi Linear等の線形注意研究を紹介する背景数値を含み、**ELA自身の大規模言語モデルに対する同条件実測結果ではない**。この区別は実装判断で最重要である。

## 問題設定：二次注意行列と線形注意の難点

標準的な自己注意は、系列長Lの各問い合わせq_iと鍵k_jの組合せに得点を計算する。全L×Lの注意行列を形成する実装では、長い系列ほど時間・中間メモリが増える。推論時には過去の鍵・値をキャッシュして同じ計算を繰り返さないが、キャッシュ容量は系列長に比例し、長い文脈ではGPUメモリを圧迫する。

線形注意は、注意得点の核k(q_i,k_j)を特徴写像φ(q_i)、ψ(k_j)の内積として表し、総和の順序を変えることで、各トークンを過去すべての位置と直接比較せずに済ませる。具体的には過去のψ(k_j)と値v_jの外積を累積した行列S、およびψ(k_j)の累積ベクトルCを保持し、現在のφ(q_i)との内積だけで出力を求める。

ただし単純な線形注意には、正規化分母が小さい場合の数値不安定性、長文脈での注意の希釈、標準softmaxと異なる表現能力という課題がある。論文は、非負性、候補を識別できる性質、幾何学的な解釈可能性、有限次元での厳密な分解可能性を望ましいカーネル条件として列挙する。ここで非負性を保証しない核を採用した場合、正規化した重みを確率とみなすことはできないため、各カーネルの定義域にも注意が必要である。

## 手法：有限特徴写像による厳密な線形注意

### 特徴写像と和の順序交換

問い合わせq_i、鍵k_j、値v_jについて、k(q_i,k_j)=φ(q_i)^Tψ(k_j)と有限次元で正確に書ける核を考える。正規化注意の分子はΣ_j k(q_i,k_j)v_j、分母はΣ_j k(q_i,k_j)である。内積の分配法則を使うと、分子はφ(q_i)^T[Σ_j ψ(k_j)v_j^T]、分母はφ(q_i)^T[Σ_j ψ(k_j)]へ書き換えられる。

因果的な自己回帰生成では、位置iまでの累積量C_i=Σ_{j≤i}ψ(k_j)、S_i=Σ_{j≤i}ψ(k_j)v_j^Tを保持し、出力y_i=φ(q_i)^T S_i / [φ(q_i)^T C_i]を計算する。次の位置では新しい鍵・値の寄与をCとSへ加算するだけでよい。特徴次元と値次元を固定した場合、系列長に関する計算量はO(L)となり、L×Lの行列を実体化しない。

双方向注意では全系列のCとSを一度計算し、各位置から参照する。因果注意では前方累積和（prefix sum）を使う。いずれも「有限次元の核分解が成り立つこと」が前提であり、無限級数の打切り近似を導入していない限り、同じ核を全位置へ適用する二次計算との代数的誤差はない。実際の浮動小数点演算では加算順序が変わるため、丸め誤差までビット単位で一致するとは限らない。

### 二乗ユークリッド距離の和カーネル

k(q,k)=||q+k||²=||q||²+||k||²+2q·kを使う。特徴写像はφ(q)=[q;||q||²;1]、ψ(k)=[2k;1;||k||²]とすれば内積がちょうど核に一致する。元のqとkがd次元なら特徴次元はd+2である。二乗ノルムなので非負だが、q≈−kでは0に近づき、正規化分母が小さくなるケースを考慮する必要がある。

著者は同じ方向を持つ鍵へ相対的に強く注意する核と説明する。ただし核の値は方向だけでなくベクトルの大きさにも依存し、同方向だから必ず最適な証拠検索になると保証するものではない。ここでは幾何学的な類似度の一候補として理解すべきである。

### 二乗ユークリッド距離の差カーネル

k(q,k)=||q−k||²=||q||²+||k||²−2q·kを使う。φ(q)=[q;||q||²;1]、ψ(k)=[−2k;1;||k||²]とすれば厳密に分解できる。こちらはqとkが離れているほど核が大きくなるため、通常の「似ている鍵を優先する」注意とは異なる選好を持つ。著者は対立的な内容や対比の検出へ向く可能性を述べるが、実際に質問応答の反証検索を改善する実験を示したわけではない。

和・差のどちらも核の値が0になりうるので、すべての鍵が近い配置で分母が極端に小さい場合には安定化処理が必要となる。非負性と識別性があっても、学習時の勾配が常に有界になるわけではないことに注意する。

### アダマール指数カーネル

Hadamard Expはk(q,k)=Σ_a exp(q_a)exp(k_a)と定義する。特徴写像はφ(q)=exp(q)、ψ(k)=exp(k)であり、次元dの有限内積に正確に分解できる。指数は各座標に作用するため、核はexp(q·k)ではなくΣ_a exp(q_a+k_a)である。共通して大きい特徴座標が強く寄与し、全要素が正となる。

標準softmax注意はexp(q·k/√d)に比例する重みを使うが、ELAのHadamard Expはこの核を置き換える。両者の違いは単なる計算順序ではなく注意関数そのものの違いである。したがって標準Transformerの重みを流用する場合は、品質の再検証や再学習が必要になる。

指数を直接計算する実装では、大きな正の座標でオーバーフローし、小さな負の座標でアンダーフローする危険もある。原稿は指数カーネルの滑らかさや非負性を利点とするが、実装上の数値安定化を無条件に保証していない。長い系列では累積統計の値域も広がるため、浮動小数点精度と再正規化の設計が重要である。

### 追加の核設計例と非負性の条件

論文はk(q,k)=(q·k+1)(||q||²+1)(||k||²+1)という核も例示する。各側のノルム項を特徴写像へ吸収し、[q;1]と[k;1]の内積へ変換することで、有限次元の分解が可能になる。しかしq·k+1は一般の実ベクトルでは負になりうるため、**正規化重みが必ず非負になるという先の条件を無条件には満たさない**。入力を正規化して内積を−1以上に制限するなど、定義域の条件が必要である。

論文中の核の例は、分解可能性と確率的な注意重みとしての適格性が別問題であることを示す。線形計算ができるからといって、正規化分母の安定性や学習品質が自動的に得られるわけではない。

## 追加機構：Hyper-LinkとMemory Lobe

### 残差経路の再設計

Hyper-Linkは、従来のPre-Normデコーダで注意・FFNをそれぞれ残差に足す構造を組み替え、層間により直接的な接続を作る。論文はゲート付きFFNの出力を用いて層間の信号を調整し、深い層への勾配伝播や初期収束を改善すると主張する。ELAカーネルの数学的な線形化とは独立の工夫であり、両方を同時に採用した結果だけでは、それぞれの寄与を切り分けにくい。

論文の図では、Hyper-Linkを用いた小規模モデルの訓練損失が通常の残差接続より速く下がる条件が示される。しかし、数値表としての最終精度や統計的なばらつきは限定的で、数百億パラメータの大規模モデルで安定するという根拠ではない。著者は実際のクラスタ学習では最終正規化層が安定性のために必要だとも述べている。

### 表現の変化量を記憶するモジュール

Memory Lobeは、隣接する層の隠れ状態差分ΔX_k=X_k−X_{k−1}を「変換の流れ（transformation flow）」と呼び、その差分へ双方向の線形注意を適用する補助モジュールである。層ごとの表現変化を問い合わせ・鍵・値へ写し、モデル内部で処理の傾向を学習させることを狙う。論文の擬似コードではFFN出力に対して双方向ELAを適用し、元の残差と合わせて次層の状態を作る。

著者はこの機構を「質的記憶」と呼び、損失曲線の急な低下を、学習した規則を再利用する効果と解釈する。しかしこれが推論時のKVキャッシュの代替や、外部の長期記憶として機能することを定量的に示したわけではない。用語の類似性だけで、推論メモリ容量の削減方式と混同しない必要がある。

### MoEルーティング得点のバイアス化

さらに論文は、混合専門家（Mixture-of-Experts; MoE）のルーティング得点を、専門家出力の加算バイアスへ組み込む案を紹介する。ルータが選んだ専門家の出力へ、その専門家の意味的な「ラベル」に相当する信号を反映させる設計である。バイアスをFFNの内側へ入れる場合と外側へ入れる場合を比較し、図では大きな差がないと述べる。

ただしこれは専門家間の全対全通信を消す実装ではない。トークン配送の負担は残ると著者自身が説明し、ブロック単位の転送などは構想段階である。MoEのオフロードやGPU間通信最適化の実証論文としては扱わない。

主な比較では、同じ種類のカーネルを全注意層へ適用してモデルを学習する。通常の全注意とELA変種の損失曲線は大きくは変わらず、著者はELAに過学習耐性の小さな利点があると述べる。しかし原稿の数値表には、各カーネルの検証損失の最終値、乱数種による分散、複数データセットでの外部評価が揃っていない。したがって「同等または優越」という主張はこの小型・限定条件での観察と読むべきである。

### Memory Lobeの追加実験

Memory Lobeを加えると、著者は訓練損失が早く低下する傾向を報告する。通常GPTで約750更新ステップ付近に損失曲線の急な折れが現れ、Memory Queryへ因果マスクを掛けるとこの折れが消える。著者は双方向注意が表現変換の規則を捉えた可能性を述べるが、モジュール追加によるパラメータ増加、情報の流れの変化、訓練データの小ささなどが交絡し、因果的な「記憶能力」を独立に証明する実験ではない。

この結果を、推論時に過去のトークンのKVを捨てても長期情報が維持されることの証拠とするのは不適切である。学習時の損失曲線の改善と、長い文脈での正確な情報検索・推論品質は別の評価軸である。

### 速度・容量の数値の出所

論文の序論には、1Mトークン文脈でKimi Linearが1トークンあたり1.84ms、別のMLA系が11.48msという比較と、線形注意がKV容量を75〜90%減らすという一般的な説明がある。これらは**ELA実装を同条件で測った数値ではない**。ELA自体については、大規模LLMのA100/H100等での1トークン遅延、同一重みでの品質差、長文脈におけるキャッシュのバイト数を直接比較した実測表が確認できない。

著者GitHubのREADMEには、原稿以後の画像検出系の実験を含む拡張記述もある。画像検出モデルのCPU/GPU速度やmAPは、原稿の言語モデル推論評価と異なるタスク・モデル・測定条件であり、ELAによる大規模LLM推論高速化の根拠として転記しない。特に論文のタイトルにある「Exact」は精度・速度・モデル品質の保証を一括して意味するものではない。

## 既存研究との差

Katharopoulosらの線形TransformerやFast Weight Programmer系の研究も、有限特徴写像を使って注意の総和を再配置する。ELAの特徴は、分解可能な核の候補を幾何学的な性質とともに整理し、Hadamard Expや距離の和・差を具体例として示すこと、さらに学習の安定化や内部記憶の補助機構を併置する点である。

ただし有限特徴写像の累積和によるO(L)計算という代数そのものは、線形注意の既知の枠組みである。ELAは標準softmaxの指数内積核をそのまま有限特徴次元で厳密分解したわけではないので、既存のsoftmax近似線形注意の近似誤差を「ゼロにした」と理解すると誤る。選択した**別の核**の二次計算との同値性を保証する方式として位置付けるのが正確である。

Kimi LinearやMiniMax Lightning Attentionは、より大規模な実用モデルでの長文脈効率を報告する先行系統である。ELAは小規模学習の検証段階であり、長文脈での実測速度・品質を比較してそれらに勝ると結論できない。KV圧縮や専門家オフロードとは違い、ELAはモデルの注意機構そのものを置換する構造変更である。

## 限界・実装上の判断

有限次元での核分解は正確でも、元のsoftmax注意と同じ出力を与えるわけではない。異なる注意カーネルを使うモデルでは、既存重みの互換性、学習安定性、長距離検索品質、位置情報の保持、生成品質を別途検証する必要がある。分母が小さい場合の不安定性、指数写像の値域、累積統計の精度、複数ヘッドの状態サイズは実装時の重要な問題となる。

評価は約580万パラメータ・約45万トークンの小型学習比較で、モデル規模・データ量・GPU実測のいずれも実用LLM推論へ直接外挿するには不足する。Memory LobeやHyper-Linkの追加効果も、複数機構を同時に変更することによる交絡がある。本文には、長文脈のベンチマーク、7B以上のモデル、実際のキャッシュ占有量、実運用TPS、同品質条件での推論速度比較が不足する。

そのため、本研究は「厳密分解可能な核の実装例と小型モデルの探索的実験」として収録し、ユーザー環境の既存LLMに即座に適用できる高速化手法とは扱わない。今後は同じパラメータ・学習データ・精度条件のsoftmax基準との比較、実際のGPUカーネル最適化、数万〜百万トークンでの速度・メモリ・品質の同時測定が必要である。
