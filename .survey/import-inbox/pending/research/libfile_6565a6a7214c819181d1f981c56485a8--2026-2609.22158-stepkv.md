# StepKV: Step-Aware KV Cache Compression for LLM Agents

## 概要
自己回帰推論の鍵値キャッシュ（KV cache）は、過去トークンの鍵と値を保持して再計算を避ける一方、文脈長に比例して容量と読出し量が増える。H2OやTOVAのような既存圧縮は各トークンの注意量や直近性から重要度を決めるが、複数段階のLLMエージェントでは「情報を生成した単位」が推論段階であるため、トークン単位の局所重要度だけでは後から再利用される観測や中間判断を早期に捨てることがある。著者はこれを**推論連続性破壊（Reasoning Continuity Disruption）**と呼ぶ。

StepKVは、各完了段階に段階効用 $S_k$ を持たせる。新しい段階が終わると、観測が有効か、以前と異なる証拠を得たか、同じ行動を繰り返していないかから即時寄与を計算する。その後、後続観測が過去観測を再利用するたびに過去段階の効用を増やす。各トークンの最終保持優先度は、この段階効用と通常のトークン顕著度を加重合成して決める。

Qwen2.5-7B-InstructとLlama-3.1-8B-Instructで、KVを20%まで絞った条件でも既存のトークン単位方式より大幅に高いExact Match（完全一致率; EM）とF1を維持する。たとえばQwen2.5-7BのHotpotQAでは20%保持時にStepKVがEM 18.07/F1 24.29、H2Oが1.53/3.52、TOVAが0.73/2.98である。

## 問題設定
エージェントは1回の質問から、思考（Thought）、行動（Action）、観測（Observation）を何段階も積み重ねる。ある段階で取得した証拠は直後には重要でなくても、数段階後の統合で必要になることがある。しかしトークン単位のKV圧縮は、現在の注意値が低いトークンを個別に落とすため、同じ推論段階の情報を断片化する。

著者は実際にH2O/TOVAで、古い段階だけでなく直前の段階も1〜2段階後には大きく削られることを観測した。さらに直前段階、2段階前、直近2段階より古い全履歴を意図的に削除する実験では、いずれも完全KVよりEM/F1が悪化した。したがって単に「新しいトークンを残す」だけでは推論依存を維持できない。

## 手法
### 新規段階の即時評価
段階 $k$ が完了すると、StepKVは観測の有効性 `valid`、過去の思考＋観測との差から求める証拠利得 `gain`、過去行動との類似度による冗長性 `red` を計算する。即時スコアは $r_k=valid_k+gain_k-\lambda red_k$ で、エラー観測や反復ツール呼出しを低く、新しい有効証拠を高く評価する。

### 遅延再利用の更新
生成時点では将来の重要性を判断できないため、過去段階ごとに再利用累積値 $c_k$ を保持する。新しい観測が得られるたび、過去観測との類似度に応じて $c_k$ を増やす。段階効用 $S_k$ は、クリップした即時スコアと $\log(1+c_k)$ を重み付きで合成する。このため、生成時には平凡だった段階でも後で証拠が再利用されれば保持優先度が上がる。

### トークン顕著度との合成
段階全体を固定保護すると細粒度圧縮が失われるため、各トークン $i$ の優先度を $P_i=\alpha T_i+\beta S_k$ とする。同一段階のトークンは同じ $S_k$ を受けるが、トークン顕著度 $T_i$ は異なる。全候補を $P_i$ で大域順位付けし、保持予算 $B_t$ の上位だけを残す。段階効用は補助信号であり、極端に重要な個別トークンは低効用段階からも残せる。

計算量は段階比較が $O(t)$、トークン優先度生成が $O(N_t)$、大域順位付けが最悪 $O(N_t\log N_t)$ である。トークン顕著度は既存の観測プリフィル中に取得するため追加モデルforwardを要求しない。

## 評価条件
|項目|条件|
|---|---|
|モデル|Qwen2.5-7B-Instruct、Llama-3.1-8B-Instruct|
|タスク|HotpotQA、2WikiMultihopQA、MuSiQue、BrowseComp-Plus|
|比較|Full KV、ReAct、H2O、TOVA、TokenSkipping|
|KV保持率|主に50%、20%|
|指標|EM、token-level F1、エージェント推論コスト|
|反復|3 random seeds|
|既定混合重み|token $\alpha=0.2$、step $\beta=0.8$|

## 主要結果
|条件|比較|StepKV|既存方式|読み取り|
|---|---|---:|---:|---|
|Qwen2.5-7B / HotpotQA / 50%|EM/F1|23.23/31.81|H2O 12.00/19.57|半分のKVでも推論連続性を大幅に保持|
|Qwen2.5-7B / HotpotQA / 20%|EM/F1|18.07/24.29|H2O 1.53/3.52|厳しい予算で差が拡大|
|Llama-3.1-8B / HotpotQA / 50%|EM/F1|25.07/33.52|H2O 11.80/16.51|完全KV 25.27/34.21に近い|
|Llama-3.1-8B / 2Wiki / 20%|EM/F1|13.80/15.21|H2O 0.87/1.18|長い依存を残す効果が顕著|

構成要素除去でも段階信号が主因である。Qwen2.5-7Bの2Wikiでは段階スコアを除くとEMが15.60、F1が12.45ポイント低下する。再利用更新を除くとMuSiQueのF1が6.45ポイント低下し、遅れて重要になる証拠を追跡する設計を支持する。一方、推論段階が深くなるほど圧縮後のEM/F1は低下し、20%のような厳しい予算では悪化が大きい。

## 既存研究との差
H2OやTOVAは履歴を平坦なトークン列として扱う。StepKVは「段階を丸ごと残す」方式ではなく、段階効用を個々のトークン順位へ注入する。そのため、推論構造を保持する大域信号と、注意由来の細粒度信号を同時に使える。また、段階効用を生成時に固定せず、後続観測との再利用で更新する点が、将来重要になる中間証拠への対策になっている。

## 限界
段階効用は最大64個の抽出証拠キューを使った軽量な文字列類似信号に依存する。著者は、行動と観測の対応が不完全、ツール応答がノイズを含む、重要情報が暗黙的で抽出しにくい場合には推定誤差が生じるとする。評価モデルも7B/8B級と限定的なエージェントベンチマークに限られ、より大規模なモデルや多様なエージェントへの一般化は未確認である。
