# Mixture of Layers：薄い層の疎選択と共有注意を組み合わせるモデル設計

## 研究の焦点

通常の専門家混合（Mixture of Experts; MoE）Transformerは、各層のフィードフォワードネットワークを複数の専門家へ分けるが、注意機構や層の基本構造は単一の大きなブロックとして残る。本研究のMixture of Layers（MoL）は、その分割単位を層全体へ拡張する。幅の狭い完全なTransformerブロックを複数並列に用意し、トークンごとに一部だけを通すことで、総パラメータを増やしながら実際に動かす計算量を制御する。

ただし、ブロックを細かく分割すると一つのブロックに届くトークンが減り、注意機構が十分な文脈を参照できなくなる。そこで全トークンを必ず処理する共有softmax注意ブロックを一つ置き、残りの選択式ブロックにはGated DeltaNetの線形注意を用いる。この組合せは、局所的なブロック選択による専門化と、層ごとの全体文脈へのアクセスを両立させるためのものである。

論文はモデル構造、学習時の品質、推論時の長文入力処理速度を測る。主要な結論は、同等の「有効パラメータ数」ではMoLが優位な条件がある一方、同等の「総パラメータ数」では密なTransformerがなお優位であり、学習コストにも大きな不利があるという交換条件である。したがって、単に「MoLがDenseより優れる」とまとめるのは不正確である。

## 手法

### 手法1：薄いブロックへの分解

元のモデル幅を `d_model`、薄いブロックの幅を `d_thin` とし、`d_thin << d_model` とする。各ブロックは入力を `W_down` で縮小し、その小さな次元で正規化・注意・フィードフォワード演算を行い、`W_up` で元の幅へ戻す。内部ブロックの残差を差し引いて更新量だけを取り出し、外側で元の入力に加える。これにより各薄いブロックが、共通の表現空間へ独立した更新を提案する構造になる。

通常のMoEが主にFFNの専門家だけを切り替えるのに対し、MoLは注意処理も含めた小型の層単位で選択する。複数ブロックの結果は、学習されたルータの上位k選択と正規化重みに従って集約する。外側の残差経路があるため、選択されたブロックの出力が小さくても元の表現は維持され、学習時の勾配伝播を助ける。

原著の式では、薄いブロックが `W_up(Block_dthin(W_down x) - W_down x)` を出し、分割段が `x + (1/k)Σ w_i ThinBlock_i(x)` として更新する。重み `w_i` はルータのsoftmax出力である。ルータが一部のブロックだけを使い続ける崩壊を避けるため、ブロック別のルーティング重みに変動係数の二乗に基づく均衡損失を加え、係数0.05を使用する。

幅を小さくしすぎると投影行列が相対的に大きくなる。薄い幅256では投影部分がブロック関連パラメータの約40%を占め、128では57%、64では73%へ増える。実験では、同等約85Mパラメータで幅256が幅128よりPPLを1.62改善した。ブロック数を増やすだけでは、各ブロックの表現力不足を補えない。

### 手法2：共有softmaxと疎DeltaNetによる混合注意

疎なブロックルーティングでは、あるトークンが選んだブロックと別のトークンが選んだブロックが異なり得る。個々のブロックに届く系列は元の全系列の部分列となるため、通常のsoftmax注意を各ブロックで実行すると、重要な過去のトークンが同じブロックへ入らないことがある。原著の3-of-15構成では、一つのブロックが平均で系列の約20%しか見ず、隣接する観測トークンの間隔も大きくなる。

MoLの混合注意は、ブロック0を全トークンが通る共有softmaxブロックとし、残りのブロックは上位k選択による疎なGated DeltaNetで処理する。例えば `1+3of15` は15ブロックのうち共有1個と、残り14個から選ばれた3個を使い、各トークンは合計4ブロックを通る。共有ブロックが全体文脈を担保し、選択ブロックが専門化された更新を加えるため、疎化による文脈被覆の欠落を緩和できる。

Gated DeltaNetは系列長に対して線形の注意機構であり、softmaxの二次的な注意行列を直接作らない。原著では薄い幅256の条件で、パラメータ数を合わせてもDeltaNetがsoftmaxよりPPLを約0.85改善した。ただし薄い幅を元のモデル幅1024まで増やすとこの差は消え、softmaxがわずかに優位となる。したがって「DeltaNetは常にsoftmaxより精度が高い」のではなく、幅の制約が厳しい場合にその帰納的な性質が有効だったという観察である。

### 手法3：疎なトークン配送

ルータが一部のブロックを選んでも、全ブロックへ全トークンを渡してから不要な出力を捨てれば演算量は減らない。著者らは選ばれたトークンだけを各ブロックの小さなテンソルへ集め、ブロック演算後に元のトークン位置へ戻す疎配送（sparse dispatch）を実装した。入力はルータの選択結果とトークン表現、出力は各ブロックの処理結果を元の位置に再配置した更新量である。

数値検証では、密な制限付き注意実装との最大ロジット差がGPUで約 `5.7×10^-6`、CPUで約 `2.4×10^-7` と報告される。処理対象が全体の57%のとき約1.53倍、20%のとき約2.85倍、10%のとき約4.34倍の前向き計算高速化があり、`torch.compile` 併用では最大約4.94倍に達する。これらは疎配送カーネルの前向き実行時間の比較であり、学習全体や長文生成の処理量が同じ倍率で向上したことを意味しない。

疎配送には集約・散布のメモリアクセスが伴い、選択されたブロックの系列は不連続になる。線形注意を選ぶ理由の一つは、疎な部分系列でも計算量が系列長に線形であり、長文処理で二次注意の費用を抑えやすいことにある。ただし選択したトークンだけを見ることで生じる文脈欠落は、共有softmaxブロックを置かなければ解消されない。

## 評価

### 学習・評価条件

| 項目 | 一次論文の設定 |
|---|---|
| 小規模構造実験 | WikiText-103、103Mトークン、約43〜198Mパラメータ |
| 中規模学習 | Cosmopedia v2、15Bトークン、約104Mパラメータ |
| Web文書実験 | FineWeb-Edu、80M級の構造比較と20Bトークンの大規模比較 |
| 小規模モデル | `d_model=1024`、8層、薄い幅256、薄いブロック4ヘッド |
| 大規模比較 | `d_model=2048`、24層、系列長4096、4×H200 NVL |
| 大規模MoL | 15ブロック、共有softmax 1＋疎DeltaNet 3、総2.08B・有効0.61B |
| 比較基準 | Dense Softmax 0.7B（有効規模寄せ）、Dense Softmax 1.3B（総規模寄せ） |
| 学習設定 | 20Bトークン、約20Kステップ、bf16、勾配チェックポイントあり |
| 品質指標 | パープレキシティ（Perplexity; PPL、小さいほど良い）、8課題のゼロショット転移 |
| 推論速度 | 単一GPUの長文prefill。RTX 3090、A100、H100 SXM、H200を比較 |

評価には、同等有効パラメータ数の比較と同等総パラメータ数の比較が混在する。MoLの総2.08Bは常時すべてを動かすわけではなく、各トークンでは約0.61Bが有効となる。Dense 0.7BとDense 1.3Bは同じ対照ではないため、どちらを基準にした優位性なのかを明示する必要がある。

### 主要結果：品質と容量の交換条件

| 条件 | 比較対象 | MoL | 比較結果 |
|---|---:|---:|---|
| WikiText-103、約85M | rank-1 MoE PPL 33.93 | 密FFN薄ブロック PPL 30.95±0.11 | PPLを2.98改善 |
| WikiText-103、約85M | Dense Softmax PPL 30.26 | MoL PPL 30.95 | Denseが0.69良い |
| WikiText-103、約198M | Dense Softmax PPL 26.89 | 混合注意MoL PPL 29.99±0.08 | 総規模同等ではDenseが3.10良い |
| Cosmopedia 15B | Dense Softmax PPL 6.65 | MoL PPL 6.49 | MoLが0.16良い |
| Cosmopedia 15B | Dense DeltaNet PPL 6.64 | MoL PPL 6.49 | 注意方式だけの差では説明しにくい |
| FineWeb-Edu 20B | Dense 0.7B PPL 18.53 | MoL PPL 18.04 | 有効規模比較でMoLが0.49良い |
| FineWeb-Edu 20B | Dense 1.3B PPL 15.03 | MoL PPL 18.04 | 総規模比較でMoLが3.01悪い |

WikiText-103では密なTransformerに負ける一方、Cosmopediaでは途中の学習35%付近で逆転し、最終PPLも上回る。著者らは、データ量と反復学習の違いが、ブロック専門化の効果を左右すると考察する。Dense DeltaNetがCosmopediaでDense Softmaxとほぼ同じPPLだったことから、MoLの改善を「注意をDeltaNetへ変えたから」と単純化できない。層全体のルーティング構造による寄与が重要である。

ただし、総パラメータ数が同程度のDenseと比べればMoLの品質は悪い。WikiText-103の198M級ではDenseがPPL26.89、MoLが29.99であり、FineWeb-Edu 20BでもDense 1.3Bの15.03に対してMoLが18.04となる。これは「少ない有効計算量でどれだけ良い品質を出すか」と「同じ重み容量を使ったとき最高品質は何か」が異なる最適化問題であることを示す。

1.3B級のFineWeb-Edu実験は各構成単一乱数種の測定である。小規模実験では複数乱数種を用いた結果もあるが、大規模な差に対して同じ統計的確実性があるとは言えない。ゼロショットの8課題ではMoLが二つのDense基準の中間的な成績となり、WinoGrandeではDense 1.3Bの51.6に対してMoLが54.4という個別の勝ちがある。単一課題の優位を全課題へ一般化しない。

### 主要結果：推論の壁時計時間

論文の長文入力処理（prefill）では、どのGPUでどの系列長からMoLがDense Softmax 1.3Bより速くなるかが変わる。RTX 3090ではおよそ5〜6Kトークンで逆転するが、A100・H100 SXM・H200では64K〜128Kの間で逆転する。128K時点ではH100 SXMで約0.98倍とほぼ同等であり、A100では約1.20倍と報告する。256KではH100 SXMとH200で約1.42〜1.54倍の高速化となる。

| GPU・条件 | Dense 1.3Bとの比較 | 読み方 |
|---|---:|---|
| RTX 3090、約5〜6K入力 | MoLが逆転し始める | 比較的短い文脈から有利 |
| A100、128K入力 | MoL約1.20倍 | 長文入力で利得 |
| H100 SXM、128K入力 | MoL約0.98倍 | ほぼ同等、明確な高速化ではない |
| H100 SXM/H200、256K入力 | MoL約1.42〜1.54倍 | 極長文で有利な条件 |

この違いは、GPUの演算能力・メモリ帯域・カーネル実装の組合せによる。著者ら自身も測定点から単純な帯域比例則や演算能力比例則を主張していない。さらに、prefillの逆転点は出力を1トークンずつ生成する復号の逆転点と同一ではない。長文の入力処理だけ速くても、短い要求や長い生成では別の律速が現れる可能性がある。

学習時間には逆の不利がある。FineWeb-Eduの大規模比較では、MoLの学習は各Dense基準の約1.91〜2.29倍の時間を要した。疎なGated DeltaNetを含む計算経路の勾配チェックポイント処理が負担となり、推論での活性化計算の節約がそのまま学習時の壁時計時間短縮にはつながらない。総GPU時間が約1,700時間に及ぶ比較である点も、再現コストの大きさを示す。

### 構成要素除去と失敗条件

共有softmaxを置かず、疎なsoftmaxブロックだけを増やすと、ブロック当たりの系列被覆率が下がり、パラメータ数を増やしても品質が悪化する。原著では疎なsoftmax 3-of-15がWikiText-103でPPL34.73となり、3-of-5の32.04より悪い。これは単にブロック数を増やせば表現力が増すという直感への反例である。共有ブロックは全体文脈の最低限の接続を維持するために必要となる。

薄いブロックのFFNをrank-1のままにすると、同程度のパラメータ数でも品質が頭打ちになる。密なFFNを小さなブロックに使うことで、単純なrank-1専門家では表現しきれない変換を扱える。一方、ブロック幅を極端に小さくするとdown/up投影の費用が支配的となり、実質的な計算に使える容量が減る。幅256が128より良かったという実験は、この制約を裏付ける。

DeltaNetとsoftmaxの品質差も幅に依存する。薄い幅ではDeltaNetが有利だが、元の幅まで増やすとその優位は消える。したがって、MoLの結果を通常の全幅Transformerへ移植する際に、DeltaNetの優位だけを取り出して期待することはできない。

## 適用範囲と限界

従来のMoEはFFN専門家を切り替えるのに対し、MoLは注意を含む層の更新全体を選ぶ。混合注意を持つモデルでも、注意方式を層ごとに交互配置する構成とは異なり、各分割段で共有softmaxと選択DeltaNetが同時に存在する。共有ブロックが文脈の全域を処理し、選択ブロックが専門化するという役割分担が中心的な違いである。

推論速度の利点は系列長とGPUに依存し、同等総パラメータの品質や学習時間には不利が残る。小規模構造実験と1.3B級実験では学習データや系列長が異なるため、すべての数値を同一の実験条件として比較してはならない。加えて大規模実験の単一乱数種という制約、疎配送とGated DeltaNetの実装依存性、ブロック間通信や多GPU配置の未確定な費用を考慮する必要がある。

MoLは長文prefillの一部条件で有望だが、通常のGPUサービング基盤に組み込んで常に生成が速くなるという結果ではない。特に短文中心の対話、長い復号、複数要求の同時処理、学習資源の制約がある用途では、Denseや標準MoEとの総合比較が必要である。適用判断では、同等総規模・同等有効規模・同等壁時計学習予算という三つの比較を分けるべきである。
