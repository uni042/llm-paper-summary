# Mira: Memory-Efficient MoE Inference Using Adaptive Caching and Predictive Expert Staging

> 専門家の将来利用を予測してCPUから先に搬入し、頻出専門家と短期予測専門家を別々のGPUキャッシュで管理する単一GPU向け推論システム。

## 概要

混合専門家モデル（MoE）は各トークンに少数の専門家だけを実行するので、全パラメータ数に比べて一回の演算量は小さい。しかし実行時に選ばれなかった専門家も、将来の別トークンで必要になるため重みを保存する必要がある。専門家全体がGPUのビデオメモリ（VRAM）へ収まらない場合、CPU側へ置いた重みを必要時にPCIe経由で運ぶ。ルータがどの専門家を選ぶか確定するまで搬入を開始できないと、GPUは重み到着を待ち、計算器が遊休する。

Miraはこの「選ばれた後に運ぶ」反応型処理を、層をまたいだ予測に基づく先行搬入へ変える。各MoE層の小さな予測器が、現在の隠れ状態、ルータの出力、最近の専門家選択履歴から2層先の専門家を推定する。予測した専門家は短期のSTAGE領域へ先に転送し、継続的によく使う専門家は長期のHOT領域へ保持する。専門家重みを独自のINT8形式で圧縮することで、転送バイト数と尺度メタデータの搬送回数も減らす。

実機評価では、48GBのRTX 6000 Adaを用いた環境でMoE-Infinity比2.86倍、24GBのRTX A5000環境では同方式比5.71倍の平均スループットを報告する。最初のトークンまでの時間（TTFT）は48GB環境でFiddler比11.71倍、DeepSpeed比18.38倍の改善とされる。ただし比較対象とGPU容量によって倍率は大きく異なり、単一の数字を全条件の一般的な高速化率として扱うべきではない。

## 問題設定

### 疎な計算と重い専門家保存

MoEの専門家は通常、上方向射影、ゲート射影、下方向射影からなる大きな全結合演算を担当する。トークンごとに上位k個だけを実行しても、専門家プール全体の重み容量は変わらない。単一GPUで全専門家を常駐させられない場合、重みの一部をCPUの主記憶へ置くが、GPUへ呼び戻す転送時間は計算時間より長くなり得る。特に単一トークン復号では一層の演算が短く、搬入待ちを計算で隠しにくい。

従来のオフロード方式は、ルータ出力から必要な専門家を判定した後でキャッシュ検索と転送を始める場合が多い。最近使った専門家を残す最終使用時刻方式（LRU）は、直前に一度使われただけの専門家を優先してしまう。単純な使用頻度方式（LFU）は古い人気専門家を残し続け、タスクが変わった後の新しい需要へ追随しにくい。専門家の人気度は偏っており、しかもトークン・課題・層によって変動するため、両者の単純な適用では限界がある。

### 先読みの失敗と容量の競合

先読み自体も無条件には有利でない。予測した専門家が実際には使われなければ、PCIe帯域とGPUの短期領域を浪費する。先読みのために長期頻出専門家を追い出すと、次のトークンで必要になった頻出専門家を再転送しなければならない。Miraは「将来すぐ使うと予測した専門家」と「長期的に高頻度で使う専門家」を異なる寿命で管理し、予測誤りを長期キャッシュへ伝播させにくくする。

もう一つの選択肢は専門家を極端に低いビット数へ量子化し、全専門家をGPUへ置くことだが、復号・逆量子化の計算費と品質劣化が生じる可能性がある。MiraはINT8を選び、圧縮率だけを追うのではなく、圧縮された専門家を何度もCPUから搬入するシステムでの尺度転送やGPU演算の組合せを最適化する。

## 手法

### 1. 専門家のみを圧縮する共通尺度INT8形式

Miraは埋め込み、自己注意、正規化、出力層など専門家以外の部分をBF16のままGPUへ保持し、専門家の3行列をINT8へ変換する。上方向とゲートの行列を`W1`と`W3`、下方向の行列を`W2`とすると、同じ中間次元の添字`r`について3行列の対応する行または列の絶対値最大を調べる。得られた最大値を127で割って尺度`s_r`を作り、その尺度で3行列の値を丸めて符号付き8ビットの範囲へ収める。

通常の行単位INT8では行列ごとに尺度ベクトルを保存するが、Miraは上方向、ゲート、下方向の3行列で同じ尺度ベクトルを共有する。上・ゲートの行と下方向行列の列を対応付けることで、3行列の量子化表現を一組の尺度で扱う。これは重みそのものの8ビット化に加えて、転送時の尺度メタデータ量とコピー呼出しを減らす設計である。尺度の共通化は各行列の最適な個別尺度と一致しない可能性があるため、品質評価も必要になる。

尺度だけを転送する小規模計測では、Mixtral-8x7Bで1.64倍、Mixtral-8x22Bで1.62倍、DeepSeek-V2-Liteで1.68倍の転送時間改善を報告する。**これは専門家全体の転送やモデル全体の速度が1.6倍になったという意味ではない。** 実際の搬送時間はINT8の重み本体に支配されやすく、尺度共有の利点は頻繁な先行搬入で積み重なる管理費用の削減にある。

### 2. CPU常駐重みとGPUの二領域キャッシュ

全専門家はCPU側のページ固定メモリに圧縮表現で置き、GPUのVRAMから非専門家重みやBF16作業バッファの予約分を除いた容量を専門家用に割り当てる。圧縮専門家の一つあたりのサイズから同時常駐できるスロット数を計算し、これをHOTとSTAGEに分割する。専門家のスロットを明示的に数えるので、先読みのためにGPUメモリを際限なく使うことを避けられる。

HOTは継続的に使われる専門家を長く保持する領域であり、頻出専門家をCPUから何度も運ばずに済む。STAGEは予測器が近い将来必要とした専門家を短期間だけ置く領域である。大容量VRAMではSTAGEへ比較的余裕を持たせ、頻出かどうかを観察する時間を増やせる。小容量VRAMではSTAGEを数個程度の短期窓へ絞り、対象層の処理後に積極的に回収する。

STAGEが満杯のとき、新しい予測専門家を無理に追加してHOTを破壊するのではなく、先読みを見送り、実際に必要になった場合はCPU経路へ戻す。この失敗時の挙動は重要である。先読みができないからといって推論を停止させるのではなく、性能を犠牲にして正規の専門家実行へフォールバックする。予測が外れた場合も短期STAGEから回収でき、HOTに長く残りにくい。

### 3. トークン単位の経路統計によるHOT再配置

Miraは各専門家について、直近の一定トークン窓で何トークンがその専門家へ割り当てられたか、HOTから処理したか、STAGEから処理したか、CPUから読み込んだかを数える。HOT命中は既に常駐していた重みの再利用を示し、STAGE命中は予測先読みが役立ったことを示す。CPU経路の件数は、キャッシュに入らず待ちが発生した需要を示す。

一定トークンごとに再配置処理を行う。まずHOT内で使用トークン数が少ない専門家を追い出し候補として評価する。次にHOT外の専門家で需要が高く、CPU経路での処理回数も多いものを昇格候補として評価する。両者の差が十分ある場合に限り、一定数までの交換を行う。交換回数を制限するのは、短期間の人気度変化に過敏に反応して重みを出し入れする振動を防ぐためである。

この判定は「最後に使ったか」だけでなく「何トークンに必要とされ、その際どの記憶階層から供給したか」を含む。需要が多いのにCPUから供給され続ける専門家は、HOTへ置けば将来の転送待ちを減らせる可能性が高い。逆にHOTにいてもほとんど使われない専門家は、貴重なVRAMを占有しているだけになり得る。再配置の周期や一度に交換する数は実験的に調整する値であり、任意のワークロードで無調整の最適性が保証されるものではない。

### 4. 2層先の専門家を予測するMixtureHead

MoE層`i`の予測器は、最後の2層を除き、層`i+2`で使われる専門家の分布を出力する。入力は現在の隠れ状態をトークン方向へ平均した表現、ルータの出力値の平均、実際に選ばれた専門家のヒストグラム、選択頻度上位の専門家などである。これらにより現在の文章内容と専門家の選択傾向を一つの軽量な特徴量にまとめる。

予測器MixtureHeadは、隠れ状態とルータ出力から推測するActHead、直近の選択履歴から推測するHistHeadの二枝を持つ。二枝の予測結果は文脈に応じて変わるゲート重み`alpha`で混合する。文章内容からの予測が有効な状況と、直近の頻出専門家の再利用が有効な状況を同じ固定比率で扱わず、現在の入力に応じて寄与を変えられるようにする。

予測器は基盤モデルを変更せず、別途収集したルーティング記録を使ってオフラインで学習する。層`i`で観測した特徴量と層`i+2`で実際に選択された専門家分布を対応付け、交差エントロピーで学習する。推論時には学習済み予測器をGPUで評価し、上位の予測専門家についてHOTまたはSTAGEに既に存在するかを確認する。未常駐なら高優先度のCUDAストリームでCPUの圧縮重みをSTAGEへ非同期転送し、同じ層向けの重複搬送を防ぐ記録も持つ。

1層先の予測では単一トークン復号の短い演算時間だけしか転送を隠す猶予がない。2層先なら現在層と次層の計算に転送を重ねられる。論文では1層先の予測器も実装して比較し、2層先でも予測精度を保ちつつ転送待ちを隠す時間が増えたと述べる。さらに先まで予測すると不確実性が増すため、2層先を採用する設計上の根拠がある。

### 5. 非同期転送・逆量子化・専門家計算の接続

ランタイムは専門家の呼出しを受けるとHOT、STAGE、CPUの順に重み供給経路を決め、圧縮重みと尺度を必要に応じてGPUへ送る。BF16の作業バッファを事前確保して再利用することで、専門家ごとのメモリ確保を実行経路から減らす。論文は逆量子化用と計算用のCUDAストリームを分け、逆量子化と専門家の全結合演算を融合して、全重みをBF16の常駐配列として展開する中間費用を抑える。

この連携により、予測器が「必要な専門家」を早く知らせ、STAGEが「短期間置く場所」を提供し、INT8圧縮が「転送するデータ量」を減らし、HOTが「頻出重みの再転送」を防ぐ。いずれか一つだけでは全体の効果を説明できない。特にHOTの容量が十分な場合は先読みの追加利得が小さくなり、HOTが小さい場合は予測とSTAGEの価値が大きくなることが後述の容量感度評価で示されている。

## 評価条件と主要結果

### 実機構成と比較対象

| 項目 | 設定・意味 |
|---|---|
| 主モデル | Mixtral-8x7B。別モデルとしてDeepSeek-V2-Lite-Chatも検証 |
| 負荷 | ShareGPTの対話から入力・出力長を変えて抽出 |
| 環境1 | RTX 6000 Ada、48GB VRAM、960GB/s、Xeon w5-2565X |
| 環境2 | RTX A5000、24GB VRAM、768GB/s、AMD EPYC 7352 |
| 環境3 | RTX 3070、8GB VRAM、448GB/s、Xeon w5-2565X |
| CPU条件 | 比較のためプロセッサの使用コア数を8に制限 |
| 比較方式 | DeepSpeed-MII、Mixtral-Offloading、MoE-Infinity、Fiddler、HQQ |
| 主指標 | 最初のトークンまでの時間（TTFT）、端から端までのトークン毎秒（TPS） |
| 品質指標 | lm-eval-harnessでの下流課題正答率 |

DeepSpeed-MIIは重みをCPUやNVMeへ退避する方式、MoE-Infinityは系列単位の専門家使用履歴を使うオフロード方式、FiddlerはCPUとGPUの協調計算で転送を減らす方式、HQQは2ビットの重み量子化で常駐を狙う方式である。Miraはこれらと同一の最適化軸だけを比較しているのではなく、転送、常駐、予測、量子化の組合せで差を測っている。比較対象が実行できない環境では除外理由も確認しなければならない。

| 48GB RTX 6000 Ada | 平均TTFT | Fiddler | 11.71倍改善 |
| 48GB RTX 6000 Ada | 平均TTFT | MoE-Infinity | 7.49倍改善 |

48GB環境で先読みありのMira+Pと先読みなしのMiraを比べると、平均スループットの差は約1.07倍に留まる。HOTへ多数の専門家を常駐させられるため、単一トークン復号ではそもそもCPUへの欠損が少ない。一方、初期のプリフィルは複数トークンが同時に多数の専門家を活性化するため、同じ48GB環境でも先読みがTTFTを1.85倍改善したと報告する。指標が違えば同じ機構の寄与も異なる。

24GB環境ではHOT容量が減るため、先読みのないMiraに対するMira+Pのスループットは1.32倍、TTFTは1.42倍になる。DeepSpeedはCPUメモリ要求が大きく、この環境で適切に実行できなかったため比較から外された。Fiddlerは使用CPUにAVX512命令がなく著しく不利になったため、著者は公平な主比較として扱っていない。この二方式を除外した条件でのMoE-Infinity比5.71倍を、すべての比較対象に対する一般倍率と読み替えてはならない。

| 40GB | 5.26 | 7.29 | 1.39倍 |
| 48GB | 8.97 | 9.66 | 1.08倍 |

この感度実験は48GBの環境1で、利用可能なVRAMを人工的に制限して行ったものである。**16GBの行は物理的な16GB GPUでの実測ではない。** 入力64トークン、出力256トークンの固定系列を用いており、他の系列長へそのまま一般化できない。16GBでは予測により1.70から2.53トークン/秒へ改善するが、48GBでは8.97から9.66トークン/秒への小幅改善となる。中間の40GBで1.39倍へ再び増えており、容量と効果の関係は完全な単調関数ではない。

### 予測器の評価とビーム探索

予測器の評価では、Mixtral-8x7Bの各層について、上位k個の予測専門家が実際のルータによるトークン割当ての何割を覆ったかを測る。これは単なる専門家IDの一致率ではなく、選択された専門家へ流れたトークン量で重み付けした被覆率（Coverage@k）である。上位1、2、3個へ予算を増やすと、予測先読みで覆える需要が増えることを示す。図示された傾向は予測器が需要の多い専門家を上位へ集める証拠だが、異なるワークロードへの分布ずれ耐性まで保証しない。

ビーム探索では、入力64、出力256トークンに固定し、同時に保持する候補系列数を増やして比較する。MiraはFiddler比で平均1.45倍、先読みありMira+Pは平均3.84倍の高速化を報告する。これは通常の貪欲復号とは異なり、複数候補の専門家需要が重なった条件での結果である。論文の3.84倍を全デコード方式に共通の速度改善として引用するのは適切でない。

### 量子化による品質差

| 下流課題 | FP16 | Miraの共有尺度INT8 | 差（Mira－FP16） |
|---|---:|---:|---:|
| ARC-E | 0.870 | 0.871 | +0.001 |
| SCIQ | 0.970 | 0.975 | +0.005 |
| Winogrande | 0.760 | 0.750 | -0.010 |
| TriviaQA | 0.570 | 0.540 | -0.030 |

INT8圧縮は三つの課題で差が1ポイント程度以内に収まるが、TriviaQAでは3ポイント低下している。原著は低ビット量子化と比べて小さい品質影響を強調するが、**すべての課題でFP16と同じ精度を維持したわけではない**。特に知識質問応答に相当するTriviaQAの差は、速度の利益と併せて検討すべき負の結果である。共有尺度のメタデータ削減がモデル品質に与える影響を、単一の平均値で隠さないことが重要である。

## 既存研究との差

MoE-Infinityは系列の活性化履歴に基づく専門家の先読みとキャッシュを用いるが、Miraは現在層の隠れ状態とルータ統計を用いる学習済み予測器から2層先の専門家を推定する。Miraの先読みは単純なキャッシュ命中予測ではなく、実行が到達するまでの二層分の時間をPCIe転送の隠蔽へ使う点に特徴がある。元のMoEルータ自体を改造せず、専門家実行部分へ介入する。

Fiddlerは専門家計算の一部をCPU側へ逃がして転送を避けるが、CPUのベクトル命令や計算能力への依存が大きい。Miraは重みをGPUへ移して計算する設計で、比較環境2のAVX512非対応CPUではFiddlerを公平な比較から外している。HQQは2ビット化によりGPU常駐を狙うが、MiraはINT8の中程度の圧縮と先読みで、品質や逆量子化の費用との折衷を変えている。

LRUやLFUの汎用キャッシュは最近使ったか、過去に何度使ったかで保持を決める。Miraはルータが実際に割り当てたトークン数と、それをHOT・STAGE・CPUのどこから供給したかを組み合わせ、転送費の大きい需要をHOTへ昇格させる。短期予測をSTAGEに隔離することで、予測外れが長期常駐を汚染する危険を抑える。この二つの管理時間尺度の分離は単なるLRUの置換ではない。

## 限界と適用条件

第一に、予測器は事前に収集したルーティング記録で学習される。学習時と推論時の言語、課題、入力長、専門家の使用分布が大きく変われば、予測上位の専門家が外れ、STAGEへの無駄な転送が増える可能性がある。論文は被覆率の実験を示すが、未知の大きな分布変化での長期運用を十分に保証していない。予測器の学習・更新費用も、事前準備が不要な純粋キャッシュ方式とは異なる。

第二に、HOTとSTAGEの分割には限られたVRAMの競合がある。STAGEが満杯なら先読みを断念し、CPU経路で専門家を呼ぶため、先読み効果は容量と転送帯域に制約される。再配置の周期や交換上限は実験的な調整値であり、需要が急変すると短期のミスや交換の振動が残る。16GB人工制限の1.49倍と48GBの1.08倍という差は、先読みの価値がGPUの容量と負荷に強く依存することを示す。

第三に、共有尺度INT8は3行列の対応する成分を同じ尺度へ揃えるため、各行列を独立に量子化する場合とは誤差分布が異なる。元論文の品質表ではTriviaQAがFP16より3ポイント低く、全課題で無損失とは言えない。モデル構造が上・ゲート・下の3行列と異なる場合は、標準的な量子化を使うなど実装変更が必要になる。

第四に、主対象はCPUに専門家を退避する単一GPU推論であり、複数GPUの専門家並列化や集合通信を直接最適化する方式ではない。性能比較はMixtral-8x7Bを中心とした限られたモデル・環境・ShareGPT由来の入力に基づく。RTX 3070の8GB環境も構成として記載されているが、48GBと24GBの倍率を8GBへ機械的に外挿することはできない。CPUメモリやAVX512要件のため比較不能となった方式があり、全方式を同一条件で評価できているわけではない。

第五に、尺度のみの転送計測で得た1.6倍前後の改善は、専門家重み全体の搬送速度でも、端から端までの生成速度でもない。大きな倍率はオフロード待ちが大きい特定の比較方式に対する結果であり、十分なVRAMに全専門家が収まる条件では先読みの効果が縮む。量子化・キャッシュ・予測の組合せの効果を評価する際は、比較対象、GPU容量、入力長、出力長、測定指標を必ず併記する必要がある。

## 再監査判定

元原稿は三つの主要機構を概説していたが、予測器の二枝構成と学習目標、尺度の行列間共有、キャッシュ再配置の計測量、比較不能となった環境の理由、容量制限実験が物理16GB GPUではない点、TriviaQAの品質低下などの説明が不足していた。原著の本文・評価表に戻って各主張と条件を確認し、機構と数値の対応が追えるように修復した。
