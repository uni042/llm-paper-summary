# MetaKV: Adaptive KV Cache Compression for Constrained LLM Inference

## 概要

長文脈推論では鍵値キャッシュ（KV cache）がGPUメモリを大きく消費する。既存の圧縮方式は同じ交換条件を持たない。KVQuantは低ビット量子化でメモリを強く減らせる一方、量子化・逆量子化が遅延を増やし得る。H2Oはattention重要度の低いtokenを削除して計算も減らすが、保持tokenは高精度なので同じ容量まで縮めるには強い削除が必要になる。RocketKVの疎attentionもpromptやtaskによって速度と品質の順位が変わる。

MetaKVは「どの圧縮法が常に最良か」を決めず、promptと利用者の遅延上限・ピークメモリ上限ごとに構成を選ぶ。3方式各3設定とFP16の計10構成について、軽量な勾配ブースティング木（LightGBM）が遅延、ピークKVメモリ、正答確率を予測する。予算を満たす候補を絞り、その中で情報損失が小さい構成を優先する。4データセットの評価では、最良の固定構成に対する制約付き成功率（Constrained Success Rate; CSR）を全試験予算で改善し、平均差は約0.07、最大0.135だった。

## 問題設定

圧縮率だけでKV方式を選ぶと、実際のサービス制約を取り違える。論文の測定ではKVQuant 4-bitは平均ピークKVメモリ11.71 MBまで下げる一方、平均遅延21.67秒で、H2O 60%の2.48秒より大幅に遅い。反対にH2Oは19.09 MBを使う。非圧縮FP16は精度0.645と最良だが34.47 MBを使う。つまり「精度・遅延・容量」の三目的で単一の静的設定は支配的でない。

さらに同じ方式でもprompt長やtaskで結果が変わる。数学ではtoken削除と量子化の品質順位が、科学的選択問題とは異なる。このためMetaKVは配備全体に一つの圧縮率を固定せず、要求単位で選択する。

## 手法

### 資源予測と予算フィルタ

入力はprompt、最大遅延 `L_max`、最大ピークKVメモリ `M_max` である。遅延用とメモリ用のLightGBMが10構成すべての実行資源を予測し、予算フィルタ（Budget Filter）がどちらかの上限を超える候補を除外する。メモリ予測はMAPE 7.7%、R² 0.9981、遅延予測はMAPE 38.19%、R² 0.9651だった。

### 品質を残す構成選択

FP16が予算内なら、圧縮による情報損失を避けるためFP16を選ぶ。FP16が落ちた場合、各方式で最も弱い圧縮設定だけを残し、複数候補が残れば正答確率用LightGBMの予測値が最大の構成を選ぶ。正答予測の統合AUROCは0.70である。

予算を満たす構成が一つもない場合は処理を拒否せず、予測遅延と予測メモリを各予算で正規化した違反scoreを計算し、合計違反が最小の構成へ退避する。したがって厳しすぎるSLOでも選択器の挙動が定義されている。

### 実行

選択されたKV設定とpromptをHugging Face Transformersへ渡して通常の生成を行う。予測器の平均追加時間は10.96 msで、MetaKVの平均LLM推論時間の0.34%だった。選択のための制御処理自体が主な律速にはなっていない。

## 評価条件

|項目|条件|
|---|---|
|モデル|Meta Llama 3.1 8B|
|GPU|NVIDIA RTX PRO 6000 Blackwell Server Edition、96 GB VRAM、1基|
|データセット|GSM8K、HellaSwag、ARC-Challenge、SQuAD 1.1|
|収集|各dataset 2,048 prompt、計8,192|
|評価split|85%学習 / 15%試験、試験1,232 prompt|
|候補|FP16 + KVQuant 2/3/4-bit + H2O 20/40/60% + RocketKV 8/16/32×|
|比較|各予算で学習set上CSRが最高の固定構成、完全予測Oracle|
|主要指標|accuracy、end-to-end latency、peak KV memory、CSR|

## 主要結果

|条件|指標|比較|結果|読み取れること|
|---|---|---|---|---|
|全試験予算|CSR|最良固定構成|平均約+0.07、最大+0.135|要求単位選択が静的設定を上回る|
|30 MB上限|CSR差|固定構成|+0.10〜+0.13|複数の圧縮強度を使い分ける余地が大きい|
|5 MB上限|CSR差|固定構成|平均約+0.06|極端な容量制約でも適応選択に利得|
|2秒上限|CSR差|固定構成|平均約+0.073|遅延律速でも構成切替が有効|
|全条件|制約違反|Oracle|MetaKVは0〜6 percentage point高い|違反の多くは予測誤差より候補集合の限界|
|全条件|accuracy|Oracle|0.2〜1.8 percentage point低い|選択器は利用可能構成内の上限に近い|

緩い50秒・80 MB条件では74.9%のpromptでFP16を選び、不要な圧縮を避ける。2秒・80 MBではFP16が63.6%へ減り、H2O 60%が22.8%、RocketKVも9.8%使われる。資源制約が変わると実際に選択分布が変わることが、適応機構の直接的な証拠である。

## 既存研究との差

KVQuant、H2O、RocketKVはいずれも「KVをどう小さく・少なく読むか」を提案する個別方式である。MetaKVは新しい圧縮表現を作るのではなく、それらを候補集合として、promptと配備制約に応じて選ぶ制御層を追加する。固定の「最良圧縮率」を求めず、資源予測と正答予測を分離した点が中心である。

## 限界

評価モデルはLlama 3.1 8B、GPUはRTX PRO 6000 1基であり、他モデル・GPUで予測器をそのまま使えることは示していない。候補集合も3方式10構成に限られ、どの候補も予算を満たせない場合はOracle自身も最大35%のpromptで違反する。したがってMetaKVは候補方式の物理的限界を超えない。

遅延予測のMAPE 38.19%と正答予測AUROC 0.70は完全予測から距離がある。実際、MetaKVの違反率はOracleより最大6 point高い。オンライン負荷下の連続バッチング、複数GPUサービング、予測器の分布ずれは本評価の中心ではない。
