# Mitigating Quantization Errors Due to Activation Spikes in Gated Linear Unit-Based Large Language Models

## 概要

本研究は、LLaMAなどの現代的な大規模言語モデルに多いゲート付き線形ユニット（GLU）の活性値を低ビット整数へ変換すると、特定の層と少数のトークンで極端な値が現れ、他の大多数の値の量子化精度を損なう現象を扱う。著者らはこの極端値を「activation spikes（活性値スパイク）」と呼び、通常の外れ値対策だけでは残る量子化誤差の原因として分析した。

提案は二つある。QFeMはスパイクが著しい線形モジュールの**活性値**だけを低ビット化せず、他のモジュールは通常の量子化を続ける。QFePはスパイクを誘発する短いprefixを事前に非量子化計算し、そのKV状態をキャッシュして後続トークンへ再利用する。前者はモジュール方向、後者はトークン方向に問題を隔離するため、両者を組み合わせることもできる。

著者らはLLaMA-2、LLaMA-3、Mistral、Mixtral、SOLAR、GemmaなどのGLU系モデルを調査し、特に粗い粒度の活性値量子化で大きな精度改善を報告した。結論ではLLaMA-2系の量子化精度が従来法より約7～16%改善し、LLaMA-2-13Bの困惑度が最大85.4%低減した例、QFeMの最大10.4%の遅延短縮例、QFePの2Kトークン条件での追加メモリが0.05%未満である例を挙げている。これらはそれぞれ異なる指標と条件であり、一つのモデルで同時に得られる保証値ではない。

## 問題設定：GLUの中間活性値が量子化を壊す理由

TransformerのFFNでSwiGLUなどを使うと、二つの線形射影の一方を活性化してもう一方と要素積を取り、最後にdown射影で隠れ状態の次元へ戻す。入力側の`up`・`gate`と、要素積の後の`down`では活性値の分布が異なる。前正規化（Pre-LN）がブロック入力の大きさを抑えても、GLUの要素積で生成された`down`入力の極端値までは直接制御できない。

per-tensor量子化はテンソル全体に共通のスケールを使うため、最大絶対値が異常に大きいと、その値を表現するために量子化間隔が広がる。結果として、ほとんどの通常トークンの活性値が少数の整数レベルへ丸められ、微小な差が失われる。per-token量子化はトークンごとにスケールを決めるのでこの問題を軽減するが、スケールの算出と適用が細かくなり、実装上の計算・管理費用が増える。

本研究の重要な観察は、極端値がすべての層・トークンに均等に発生するわけではない点である。特にFFNの`down`入力で、初期層と終盤層に大きなスパイクが集中する。トークン方向でも、BOS、改行、アポストロフィなど特定のトークンが**最初に**出現した位置で大きくなり、同じトークンの後続出現では比較的小さい。この位置依存性を利用して、問題のある場所だけ高精度を残す設計が可能になる。

## 事前分析：どのモジュールが問題かを測る

著者らはC4からランダムに選んだ512サンプルを校正データとして流し、各デコーダ層の隠れ状態と線形モジュール入力を観測した。対象は`query`（`key`・`value`と近い位置）、`out`、`up`（`gate`と対になる）、`down`である。校正では絶対値最大を使ってスケールを推定し、層ごとの極端値とトークンごとの分布を比較する。

単に最大値が大きいモジュールを選ぶのではなく、モジュールmのトークン別スケール列をS(m)として、最大値と中央値の比r(m)=max(S(m))/median(S(m))を用いる。最大値だけでは通常の活性値自体が大きいモジュールと、少数トークンだけが異常に大きいモジュールを区別しづらい。中央値で割ると、大多数のトークンから突出したスパイクの相対的な厳しさを表せる。

論文の部分量子化実験では、この比が高い上位4モジュール、中位4、下位4を別々に量子化し、FP16との差を困惑度と最終隠れ状態の平均二乗誤差で比較する。上位4だけを量子化した場合に大きな劣化が現れ、中位・下位では変化が小さいことから、スパイクの大きさと量子化の脆弱性が対応することを確かめた。この比較はQFeMの選択規則の根拠であり、全モジュールを一律に高精度へ戻す必要がないことを示す。

## 手法1：QFeM（量子化を避けるモジュールの選択）

QFeMは校正時に計算したr(m)と閾値αを比較し、r(m)がαを超えるモジュールを活性値量子化から除外する。通常のW8A8では重みも活性値もINT8へ変換するが、除外対象では重みはINT8のまま保持し、計算時にFP16へ展開してFP16活性値と行列積を行う。つまり完全なFP16モデルへ戻すのではなく、問題モジュールに限定してweight-only量子化へ切り替える。

閾値αが大きいほど除外対象は減り、低ビット演算の適用範囲が広くなる。一方、スパイクを含むモジュールも量子化されるため、困惑度が悪化する。αを下げると高精度経路が増え、品質を守りやすい代わりに演算時間が増える。著者らは校正データ上の困惑度と量子化除外数を見ながら二分探索で閾値を選ぶ。論文のLLaMA-2-13Bの例では、トレードオフ曲線の交点としてαが約16の条件が示されるが、これは全モデル共通の固定閾値ではない。

この方式は層の位置やトークン内容を実行時に毎回検査して切り替えるのではなく、校正で得たモジュール単位の選択を使う。実行時の判定費用が小さい反面、校正に現れなかった入力分布ではスパイクの位置が変わる可能性がある。MoEのFFN expertは入力分布がexpertごとに異なるため、論文ではMixtralのexpertについて個別に校正することも記載されている。

## 手法2：QFeP（スパイクを短いprefixへ封じ込める）

QFePはスパイクが特定トークンの初回出現で強いという観察を利用する。あらかじめ短いprefixを作り、そのprefixを**非量子化のモデル**で処理してキーとバリューの状態を計算し、KVキャッシュへ保存する。実際の入力を生成するときは、この保存済みprefix状態を文脈の先頭として使い、後続のユーザー入力と生成部分を量子化したモデルで処理する。

この操作によって、スパイクを誘発する初出トークンが既にprefix側に現れた状態を作る。後続の同種トークンではスパイクが弱まるという観察が成り立てば、通常の活性値量子化が扱う入力分布が安定する。prefixは単に文字列を付け足すのではなく、非量子化で事前計算したKV状態を後続処理へ渡すことが要点である。そうしなければprefix自体が粗い量子化で処理され、避けたい誤差を再び生じさせる。

論文の実験ではBOS、文脈トークン、スパイクを誘発する追加トークンを含む長さ3のprefixを設計し、prefix長のアブレーションも行う。長いprefixほど位置予算とKVキャッシュを消費するため、無制限に増やすのは望ましくない。prefixを変えた場合には再計算が必要で、モデルやトークナイザ、プロンプト構造が異なる環境へそのまま移植できるとは限らない。

QFeMは高精度の計算を一部残すため演算コストを増やす方向の交換条件を持つ。QFePは事前計算と少量のKVメモリを必要とする代わりに、推論時に高精度で処理する箇所を減らせる。二つの作用点は異なるため、組み合わせによる追加改善も評価されている。ただし両方を併用したときの最適な閾値・prefix長は対象モデルごとに確認する必要がある。

## 評価環境と測定方法

| 項目 | 論文の設定 |
|---|---|
| モデル | LLaMA-2（7B/13B/70B）、LLaMA-3、Mistral-7B、Mixtral-8x7B、SOLAR-10.7B、Gemma-7BなどGLU系 |
| 校正 | C4から512サンプル、各モジュールの最大絶対値とトークン別スケール |
| ハードウェア | 小型モデルはRTX 4090、大型モデルはNVIDIA A100 |
| ソフトウェア | Python 3.10、PyTorch 2.2、Transformers 4.38.1、lm-eval-harness |
| 主要量子化 | 重みper-channel、活性値dynamic per-tensor、INT8対称スケールを基本に比較 |
| 比較方式 | FP16、通常のW8A8、per-token活性値量子化、SmoothQuant、OutlierSuppressionPlusなど |
| 品質 | WikiText-2困惑度、PIQA・LAMBADA・HellaSwag・WinoGrandeのゼロショット正解率 |
| その他 | 低ビットW6A6/W4A4、量子化粒度、prefix長、モジュール除外数、推論遅延、追加メモリ |

論文は量子化誤差の機構分析と推論性能の両方を扱うが、すべてのモデルに同一のGPU・精度・バッチ条件を使っているわけではない。小型と大型で評価GPUが異なるため、モデル間の絶対速度を比較して方式の優劣とするのは不適切である。per-token量子化は精度面で強い基準であり、提案の狙いはその精度へ近づけながら、より粗い量子化粒度の速度上の利点を残すことである。

## 主要結果と解釈

| 観点 | 論文が示す結果 | 注意点 |
|---|---|---|
| LLaMA-2のW8A8精度 | QFeM/QFePでFP16に近い水準へ回復。7Bの例でFP16との差が1%未満 | 4種のゼロショットタスク等の条件付きであり全能力の保証ではない |
| 精度改善 | 結論で従来量子化比約7～16%の正解率向上を報告 | モデル・量子化粒度・タスクごとの値を一律に置き換えない |
| 困惑度 | LLaMA-2-13Bで最大85.4%減、LLaMA-2-7Bで50%超減の例 | 劣化した量子化ベースラインからの改善でありFP16比の改善ではない |
| QFeMの遅延 | LLaMA-2-13Bで最大10.4%短縮の例 | 高精度経路を一部残しても、粗い量子化の全体速度を活用できる条件 |
| QFePのKV追加費用 | LLaMA-2-7B、2Kトークン条件でメモリ増分0.05%未満 | prefixを固定して事前計算できる設定の値 |
| 量子化粒度 | dynamic per-tokenは精度が良いが、dynamic per-tensor＋QFeMが近い精度で低遅延となる例 | static per-tensorは最速でも品質低下が大きく、完全には解決していない |
| 他のGLUモデル | Mixtralはスパイク起因の悪化に比較的強く、Gemmaでは改善が不十分 | MoEによるトークン分散やGeGLUとSwiGLUの違いが関係すると著者らは考察 |

実験結果から重要なのは、粗い量子化の失敗を「すべての活性値が量子化不能」と結論しない点である。特定の`down`入力と初出トークンに誤差が集中するなら、量子化を避ける対象を局所化できる。QFeMはこの局所性をモジュールの選別に変え、QFePは初出位置の制御に変える。どちらも新たな重み学習を必要としないため、既存のPTQと組み合わせることができる。

### 既存の外れ値対策との組合せ

SmoothQuantは重みと活性値のスケールを調整して外れ値の負担を移し、OutlierSuppressionPlusも外れ値の影響を抑える。しかし著者らは、これらだけではper-tensorの活性値量子化でスパイクが残る例を示した。原著の既存方式の評価は主にper-tokenを用いていたため、同じ名前の方式でも粒度を変えると品質が異なる。QFeM/QFePを併用することで、従来の外れ値緩和を補完できる場合がある。

W6A6やW4A4などさらに低いビット幅では、per-tokenでもスパイクを扱う利点が残る一方、丸め誤差や表現範囲の制約が増える。論文は低ビット条件も調べるが、全モデル・全方式でFP16品質を再現したと主張していない。どの条件で回復でき、どこで回復しきれないかを分けて読むべきである。

## 限界・負の結果

第一に、GemmaのようにGeGLUを採用するモデルでは、スパイクだけを除去しても品質が十分に戻らない場合がある。著者らは活性化関数の違いを可能性として挙げるが、これを厳密な因果証明とは扱わない。GLUを持つという共通点だけで、すべてのLLMに同じスパイク形状と最適prefixが存在すると仮定できない。

第二に、QFeMでは量子化しないモジュールが増えるほど高精度行列積の割合が増し、推論時間が伸び得る。校正の閾値は品質・遅延のトレードオフを決める重要なパラメータである。MoEではexpertごとの活性値分布も異なるため、校正に使ったサンプルやルーティング分布の変化で選択が適切でなくなる可能性がある。

第三に、QFePはprefixの事前計算、KVキャッシュの保持、位置トークンの消費が必要である。prefixの初出トークンがスパイクを封じ込めるという観察が対象入力に成立しなければ、後続で再びスパイクが発生する可能性がある。可変テンプレートや複数のトークナイザを持つサービングでは、固定prefixを使い回せるか別途確認しなければならない。

第四に、最速のstatic per-tensor量子化は、提案を適用しても大きな精度劣化を残す条件がある。著者ら自身が静的量子化には今後の課題があると述べている。粗い粒度の量子化はスケール計算を節約できるが、量子化誤差の主要原因がスパイク以外にもある場合、QFeM/QFePだけでは十分でない。

第五に、評価は主に困惑度と四つのゼロショットタスク、固定系列の遅延、限定されたGPU環境である。多数同時要求のサービング、KVキャッシュ共有、長文脈検索精度、実サービスのテール遅延、電力や量子化カーネルの幅広い互換性は、この結果だけでは判断できない。公開コードの存在と、任意の推論ランタイムへの無改造導入が保証されることも同義ではない。

## 既存研究との差と実装上の位置づけ

従来の外れ値量子化は、巨大な値をどうスケーリングするか、あるいはどのチャネルを保護するかに焦点を当てることが多い。本研究はGLUの`down`射影で生じる**特定モジュール・特定初出トークン**という二重の局所性を示し、演算モジュールの高精度保護と、文脈prefixの事前計算という異なる解決経路を設計した点に特徴がある。

推論システムで採用する場合は、対象モデルの`down`入力を観測し、校正データでr(m)の分布を確認してから、QFeMの閾値を選ぶべきである。QFePを試す場合は、事前計算prefixが実際に問題トークンの初出を吸収するか、prefixのKVキャッシュが推論エンジンで再利用されるかを確認する。その後、W8A8の品質と実測token/s、TTFT、TPOT、メモリ使用量を同じ条件で測る。これは本論文の機構から導く実装上の確認事項であり、著者がすべての推論エンジンで検証したことを意味しない。
