# Large Memory Layers with Product Keys — 積キーによる大容量記憶層

## 概要

本論文は、言語モデルの容量を増やすときに通常の全結合層を単純に大きくすると、重みの読み出しと行列積の計算が増えてしまう問題を扱う。積キー記憶（Product Key Memory; PKM）は、学習可能な値ベクトルを大量に保持しながら、各入力でごく少数の値だけを読み出す。キーを二つの部分キー集合の直積として暗黙的に表現し、問い合わせも二分割して検索するため、全キーを総当たりせずに**内積スコア上位の積キーを厳密に選択**できる。ここで「厳密」とは積キー集合内での上位選択であり、一般的な最近傍索引の近似精度や生成内容の完全性を意味しない。

2019年の原著では、共通クロール由来の英語ニュース約280億語で学習した自己回帰言語モデルにPKMを挿入した。隠れ次元1024では、記憶なし24層のテスト困惑度16.0186に対し、PKMを1層持つ12層モデルは15.6184となり、低いほど良い困惑度を改善しつつ、論文の図4では推論速度がほぼ2倍となる。これは**12層＋記憶と24層の構成比較**であり、同じ12層モデルへ記憶を足しただけで2倍速くなるという意味ではない。原著の12層記憶なしは困惑度17.6566であり、PKMの効果を層数削減の効果から分けて読む必要がある。

## 問題設定と位置付け

大規模言語モデルでは、パラメータ数を増やすことが学習データへの適合を改善する一方、通常の密な全結合層では増えたパラメータが毎トークンの計算に関与する。記憶拡張モデルが多数のキー・値を持つ場合も、入力を全キーと比較するとキー数に比例して検索費用が増える。既存の近似最近傍索引は検索費用を下げられるが、学習中にキーが更新されると索引を再構築する問題がある。著者が対比するRaeらの疎記憶方式は外部索引の再学習を要し、学習過程と索引の整合性を保つ費用が残る。

PKMは、**キーの表現を最初から直積構造へ制限する**ことで、近似索引を外付けせずに上位選択を高速化する。多数の値ベクトルは学習可能なパラメータとして保持するが、1入力では上位k個だけを読む。この意味で、後年の混合専門家モデル（Mixture of Experts; MoE）と同じく「総容量と一回の活性計算量を分離する」設計に属する。ただし本論文は現代の大規模言語モデルの専門家配置やCPU/GPUオフロードを評価した研究ではなく、Transformerの一部の順伝播層を疎記憶へ置換する2019年の言語モデル研究である。

## 手法

### 1. 入力を検索問い合わせへ写像する

入力隠れ状態を $x\in\mathbb{R}^{d}$ とする。問い合わせ網 $q(x)$ は線形写像または多層パーセプトロンで $d_q$ 次元の検索ベクトルを作り、典型的には $d_q=512$ を用いる。検索キーはランダム初期化されるため、学習の初期段階に問い合わせが一部のキーへ集中すると、多数の値がほぼ更新されず容量を浪費する。そこで問い合わせ網の後段にバッチ正規化（Batch Normalization）を加え、問い合わせ分布の偏りを減らしてキーの利用率を高める。これは単なる出力安定化ではなく、**巨大記憶の各値が実際に選ばれる頻度**を左右する構成要素である。

### 2. 直積キーを明示的に生成せず上位候補を得る

二つの部分キー集合 $\mathcal C$ と $\mathcal C'$ を設け、それぞれのベクトル次元を $d_q/2$ とする。全キー集合は $\mathcal K=\{(c,c')\mid c\in\mathcal C,c'\in\mathcal C'\}$ であり、両集合の要素数が $n$ なら $|\mathcal K|=n^2$ となる。問い合わせを $q=(q_1,q_2)$ に分けると、積キー $(c_i,c'_j)$ の内積スコアは $q_1^Tc_i+q_2^Tc'_j$ に分解される。これが検索高速化の数学的な根拠である。

まず $q_1$ と $q_2$ について、各部分キー集合から上位k個を独立に求める。次にその直積でできる最大 $k^2$ 個の組合せの和スコアを評価し、最終的な上位k組を選ぶ。全キーの上位k組は、各成分が部分集合上位kに含まれる組の中に必ず存在する。もし片方の部分キーがk位より低ければ、相手側を固定したままその成分をより高得点のk個へ置き換えられるためである。この性質により、全 $n^2$ 組を列挙せずとも最終選択は近似ではない。

平坦なキーを全件照合する場合の費用は $O(|\mathcal K|d_q)$、二つの等サイズ部分キーを使う場合は $O((\sqrt{|\mathcal K|}+k^2)d_q)$ となる。これは演算回数の漸近的比較であり、実際の推論時間にはメモリ帯域、選択演算、値ベクトルの不規則アクセスが加わる。原著では $|\mathcal K|=1024^2$ かつ小さなkなら全探索比で約1000分の1の検索演算になると説明するが、**モデル全体が1000倍高速化するという主張ではない**。

### 3. 選択された値だけを重み付き集約する

選ばれたキー集合を $\mathcal I$ とすると、スコアをその集合内でソフトマックス正規化して $w_i$ を作り、記憶層の出力を $m(x)=\sum_{i\in\mathcal I}w_i v_i$ とする。ここで $v_i$ はキーに対応する学習可能な値ベクトルであり、入力系列のトークンからその場で作る自己注意の値ベクトルとは異なる。各入力の順伝播では上位k値だけを読み、逆伝播では選ばれた値だけを疎に更新する。全記憶の値パラメータを毎回掛け算する密な全結合層とは計算の性質が違う。

値表自体の容量は $|\mathcal K|$ に比例して増えるため、**計算量が小さいことと、重みの常駐メモリ量が小さいことは別**である。PKMはパラメータ総量を減らす圧縮方式ではない。多数の値ベクトルを格納するメモリ資源が必要であり、CPUやSSDへ置いた場合の転送遅延を論文が実測したわけでもない。

### 4. 複数問い合わせ頭によって記憶の利用範囲を広げる

複数頭の記憶注意（multi-head memory attention）では、頭ごとに独立の問い合わせ網と部分キー集合を持つが、値表は共有する。各頭が別の上位k値を選び、その出力を加算して最終的な記憶出力を作る。頭が独立初期化されるため、同じ入力でも選択する値の重複が少なく、記憶の利用範囲が広がる。自己注意の「特徴次元を複数頭へ分割する」構成とは異なり、**頭ごとに別の問い合わせを生成し、共通の巨大値表を引く**構成である。

頭数Hや各頭の選択数kを増やせば利用する値の上限はHkとなるが、同時に問い合わせ生成・候補検索・値集約の費用も増える。原著はH=4、k=32を性能と速度の折衷として採用した。Hkが同程度なら記憶利用率も近いという構成要素除去結果は、単に頭数だけを増やせばよいわけではないことを示している。

### 5. Transformerへの挿入と実行順

Transformerの注意層の後ろにある順伝播網（Feed-Forward Network; FFN）を一部だけPKMに置き換え、残差接続で $x\leftarrow x+\mathrm{PKM}(x)$ として戻す。例えば16層モデルで2個の記憶を使うときは第6層と第12層のFFNを置換し、複数の深さの表現に記憶を接続する。原著では通常のFFNを保持したまま記憶層を挿入する変形も可能と述べるが、主な実験はFFN置換である。

一つの入力トークンの処理は、前段Transformerから隠れ状態を受け取る→問い合わせを生成して二分割する→二つの部分キー集合で上位候補を取る→直積候補から最終k個を選ぶ→対応する値を疎に読み重み付き和を作る→残差として後続Transformer層へ渡す、という順序になる。処理時間はキー検索だけでなく、値表への散在アクセスや複数頭の計算にも依存するため、構造上の計算量削減をそのままエンドツーエンドの加速率へ置き換えてはならない。

## 評価条件

| 観点 | 原著で確認できる設定 |
|---|---|
| 研究対象 | Transformerに積キー記憶層を挿入した自己回帰言語モデル |
| 学習コーパス | CC-News相当のCommon Crawl英語ニュース約4000万記事、約280億語、140GB |
| 検証・テスト | 学習集合から除外したニュース各5000記事。60k BPE分割を使用 |
| 主なモデル | 12、16、24層。隠れ次元1024または1600。注意頭16 |
| 代表PKM | 値スロット $512^2=262,144$、記憶頭4、各頭の上位選択k=32 |
| 学習 | Adam、基盤の学習率 $2.5\times10^{-4}$、疎値の学習率 $10^{-3}$ |
| 学習機材 | 32基のVolta GPU、半精度演算。PyTorch実装 |
| 主な指標 | テスト困惑度（低いほど良い）、推論時の語/秒、記憶利用率、アクセス分布のKL発散 |
| 構成要素除去 | 6層・8頭の小型モデルを主に用い、記憶容量、正規化、挿入層、記憶頭数、k、平坦キーとの比較を実施 |

困惑度（perplexity）は言語モデルが正解語列へ割り当てる確率の悪さを測る指標であり、値が低いほど予測性能が良い。記憶利用率はテスト入力全体で少なくとも一度参照された値スロットの割合であり、GPUメモリ使用率やキャッシュ命中率ではない。KL発散は値スロットのアクセス重み分布が一様分布からどれだけ偏るかを示し、低いほど一部のスロットへの集中が小さい。

## 主要結果と条件付き解釈

### 1. 層数と記憶数の交換条件

| 隠れ次元 | 構成 | テスト困惑度 | 読み方 |
|---|---|---:|---|
| 1024 | 12層、記憶なし | 17.6566 | 同じ深さでの追加効果の基準 |
| 1024 | 12層、PKM 1個 | 15.6184 | 同じ12層で予測精度が改善 |
| 1024 | 12層、PKM 2個 | 14.7886 | 記憶を増やすとさらに改善 |
| 1024 | 12層、PKM 3個 | 14.4727 | 記憶増設の追加効果 |
| 1024 | 24層、記憶なし | 16.0186 | 12層＋1記憶より精度が低い |
| 1600 | 12層、記憶なし | 14.9994 | 同次元の基準 |
| 1600 | 12層、PKM 1個 | 13.6522 | 24層・記憶なしの13.9515を上回る |
| 1600 | 24層、記憶なし | 13.9515 | 12層＋記憶の比較対象 |

原著の表1に対応する。次元1024の12層＋1記憶は24層の記憶なしモデルより低い困惑度を達成し、図4の同じ比較では推論時の語/秒がほぼ2倍となる。ただし論文の図4はモデル構成ごとの速度・困惑度の関係を示しており、ここから**あらゆる系列長・バッチ・GPUで2倍**と一般化できない。次元1600で記憶を追加した場合の推論時間増加は小さいと報告されるが、絶対速度は構成ごとに異なる。

### 2. 記憶容量と問い合わせ正規化

| 値スロット数 | 正規化 | 困惑度 | 値利用率 | 観察 |
|---:|---|---:|---:|---|
| 16k | なし | 22.7972 | 100% | 小規模では全スロットを使える |
| 262k | なし | 20.4776 | 64.4165% | 大容量化すると未使用値が増える |
| 262k | あり | 19.7805 | 97.8580% | 問い合わせ正規化が利用率と精度を改善 |
| 1M | なし | 19.7913 | 25.8314% | 大容量でも約4分の3が未使用 |
| 1M | あり | 17.9819 | 80.3043% | 同容量で困惑度と利用率が改善 |

原著の表2による。16kでは正規化なしでも全スロットが使われるが、1Mでは正規化なしの利用率が約25.8%まで低下する。したがって「記憶を増やすほど必ず精度が上がる」と単純化できず、**検索問い合わせの分布を整え、値表の容量を実際に利用できること**が重要である。原著の表2では記憶サイズ1Mで正規化ありのKL発散0.9497、なし2.0609であり、正規化によってアクセスの偏りも小さくなる。

### 3. 積キーと平坦キーの推論速度比較

| スロット数 | 平坦キー | 積キー | 指標・比較条件 |
|---:|---:|---:|---|
| 16k | 35.0k語/秒 | 35.8k語/秒 | 小容量では差が小さい |
| 65k | 28.5k語/秒 | 36.7k語/秒 | 積キーの探索負荷が小さい |
| 147k | 13.9k語/秒 | 36.4k語/秒 | 平坦キーは検索費用が増加 |
| 262k | 7.7k語/秒 | 36.3k語/秒 | 積キーはほぼ一定の速度を維持 |
| 1M | 1.2k語/秒 | 35.7k語/秒 | 平坦キーは極端に低速化 |

原著表4の推論速度。平坦キーではスロット数を増やすと検索演算と記憶の利用偏りが増え、積キーでは約36k語/秒を維持する。1Mの比較では35.7/1.2≒29.8倍だが、これは**6層モデルでの平坦キーと積キーの比較**であり、汎用Transformerサービング全体に対する約30倍の改善ではない。大容量の平坦キー構成については、学習費用が非常に大きいため困惑度の比較値が欠ける列もある。

### 4. 挿入位置と検索頭数

6層モデルでPKMを第1層に挿入すると困惑度21.4669、第4層では20.0513、第5層では19.7805、第6層では20.2931だった。最も入力に近い層では、抽象的な特徴がまだ十分に形成されず、値表を効果的に引けない可能性を著者は指摘する。一方、最終層直前では後続の変換層が少なく、取り出した情報を十分に加工できない。第4〜5層がよいという結果はこの6層設定の観察であり、全モデルで同じ絶対層番号が最適だとはいえない。

頭数Hと上位候補kについては、Hk=64となる(1,64)、(2,32)、(4,16)、(8,8)の設定で利用率が約70%、困惑度が約20.5と近かった。頭数を増やすと精度が改善し得るが計算時間も増す。論文が主設定にH=4、k=32を選んだのは、単に最大のHやkが常に優れるからではなく、検索費用と精度の折衷による。

## 既存研究との差と後続システムへの意味

Raeらの巨大記憶では外部の近似検索索引を再学習する必要があったのに対し、PKMは二つの部分キー集合の構造から上位積キーを厳密に計算できる。通常の密なFFNや密な専門家層とは異なり、全値表を毎回計算せず上位k値だけを集約する。既存の積量子化（Product Quantization）から着想を得るが、PKMはデータベースを量子化して近似検索するものではなく、**学習可能な部分キーから巨大なキー集合を暗黙的に定義する**点が異なる。

現代のMoE推論基盤との接点は、総パラメータ数に比例して演算を増やさずにモデル容量を増やせること、入力ごとの疎なルーティングが値アクセスの局所性を左右すること、活性数Hkが実行費用の重要な変数となることである。ただし本論文は専門家のGPU間配置、分散通信、オフロード、KVキャッシュの削減を提案・評価していない。これらの後続研究への示唆を、原著の実測成果として扱わない。

## 限界・未評価事項

**第一に、値表の常駐容量は減らない。** 積キーの検索計算は平方根規模でも、値ベクトルはスロットごとに保持する必要がある。数億〜十億パラメータの記憶を使う場合、重み保存領域と疎なメモリアクセスの実装効率が制約になる。原著はキー探索の計算を主に削減しており、CPU DRAMやSSDに値表を退避させた場合の転送費用、GPUメモリ容量超過時の性能は測っていない。

**第二に、キー利用率の崩壊が容量の浪費につながる。** 1Mスロットの正規化なしで利用率25.8314%という実測は、大容量の値表を置くだけでは学習で十分に使いこなせないことを示す。正規化で80.3043%まで改善するが、なお約20%の値がテスト集合では未利用である。利用率はデータ分布や学習条件に依存するため、別ドメインで同じ数値が再現される保証はない。

**第三に、頭数と選択数には追加計算費用がある。** 各頭は別の問い合わせ網と部分キー集合を持ち、Hkに応じて疎な値参照も増える。検索の漸近計算量が小さくても、GPU上で不規則な値アクセスが発生することは避けられない。原著の結果は特定のPyTorchとVolta GPUの実装に基づくため、現代のCUDAカーネルや新世代GPUでの相対利得は別途検証が必要である。

**第四に、評価タスクは主として2019年の英語ニュース言語モデルである。** 約280億語の学習、困惑度、語/秒という指標から、現代の指示追従・推論・対話モデルの回答品質、長文脈でのKVキャッシュ効率、同時要求サービングの処理率や最初のトークン遅延は直接評価できない。約2倍の速度は12層PKMと24層基準の比較であり、全てのモデル規模やワークロードへ外挿しない。

**第五に、精度と速度の改善は構成要素に依存する。** 記憶の挿入位置を第1層へ移すと困惑度が悪化し、平坦キーでは大容量ほど速度が落ちる。したがって積キーの構造、問い合わせ正規化、挿入位置、頭数・kの選択を合わせて評価する必要がある。原著にはこれらの構成要素除去結果がある一方、長期運用のメモリ断片化、分散サービング時の再配置、モデル更新時の動的索引整合性などの測定はない。
