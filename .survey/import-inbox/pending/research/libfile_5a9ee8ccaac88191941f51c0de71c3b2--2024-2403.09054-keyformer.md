# Keyformer

## 概要
自己回帰生成では過去tokenのkey/valueを保存するKVキャッシュが文脈長とともに線形に増える。各生成stepはモデル重みだけでなくKVも読み出すため、長文脈ではメモリ容量だけでなく帯域が律速になる。Keyformerはattention重みのおよそ90%が一部tokenへ集中するという観察を使い、重要tokenだけを残す。

単純にattention scoreが低いtokenを削除すると、softmaxの正規化集合が変わり、削除後のscore分布が時間とともにずれる。Keyformerは最近tokenを保持するrecency windowと、履歴から選んだkey tokenを組み合わせ、Gumbel項と温度scheduleを含むscoreで重要度を更新する。モデル再学習を要求しない。

## 問題設定
KV cacheを半分にすれば容量は減るが、誤って将来参照されるtokenを捨てれば品質が崩れる。固定windowだけでは遠い重要情報を保持できず、過去attentionだけを素朴に積算する方式もtoken削除後の分布変化を十分扱えない。

Keyformerの課題は、各生成stepで限られたKV budgetへ「最近必要になったtoken」と「長距離でも継続的に重要なtoken」を共存させることである。追加trainingやmodel改変を避け、既存生成pipelineへ推論時policyとして挿入する。

## 手法
### key tokenの選択
各head/layerで過去tokenへのattentionから重要度を作り、上位tokenをkey tokenとして残す。最近のtokenは別の固定windowとして保護するため、直近局所依存をscore変動で誤って捨てにくい。

### Gumbel正則化付きscore
tokenを削除するとsoftmaxの母集合が変わるため、残存tokenの確率が再配分される。KeyformerはGumbel由来の摂動をscoreへ加え、温度を生成stepに応じて変化させる。これにより一度のattentionピークだけへ過度に固定せず、将来重要になる候補も残せるようにする。

### 固定budgetでの更新
新tokenが生成されるたび、そのKVを追加する一方、budgetを超えればkey scoreに基づいて履歴tokenを落とす。出力は通常と同じKV集合なのでattention kernel自体を別演算へ置き換える必要はなく、減ったKV分だけread量とattention計算が減る。

## 評価条件
| 項目 | 条件 |
|---|---|
| models | GPT-J、Cerebras-GPT、MPT |
| 位置表現 | 異なるpositional embeddingを持つ複数model |
| tasks | summarization、conversation、few-shot等 |
| 比較軸 | accuracy/ROUGE等の品質、KV容量、data movement、latency、throughput |
| 学習 | 追加fine-tuningなし |

## 主要結果
| 指標 | 結果 | 読み取れること |
|---|---|---|
| KV cache | 最大50%削減 | 容量とattention対象を同時に削減 |
| KV data movement | 約2.9倍削減 | memory-bandwidth律速を直接緩和 |
| inference latency | 最大2.1倍短縮 | KV read削減がend-to-end生成へ反映 |
| token throughput | 最大2.4倍向上 | 長文脈生成の処理率を改善 |
| task quality | baselineを概ね維持 | 重要token選択で圧縮損失を抑制 |

## 既存研究との差
量子化のように各KV要素のbit数を減らすのではなく、attention対象tokenそのものを選択する。固定sliding windowだけとも異なり、遠距離の重要tokenをscoreで残す。再学習を必要とするcache圧縮と比べ、既存modelへ推論時に適用できる。

## 限界
attentionが少数tokenへ集中する性質に依存するため、広い範囲へ均等にattentionするtaskでは削除余地が小さくなる。固定budgetを強く絞るほど重要tokenを誤削除する危険は増える。評価modelはGPT-J/Cerebras-GPT/MPT中心で、現代のGQA/MQAを持つ超長文脈modelや大規模multi-tenant servingでのtail latencyは論文の主評価外である。
