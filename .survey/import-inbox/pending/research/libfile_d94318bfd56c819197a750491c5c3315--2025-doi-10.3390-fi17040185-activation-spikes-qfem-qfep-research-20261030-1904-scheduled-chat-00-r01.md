# GLUのactivation spikeを隔離してW8A8量子化を改善する

## 概要

LLMのINT8量子化では、重みだけでなく活性値を低精度にすることで低精度行列積を使いやすくなる。しかしLLaMA系で一般的なSwiGLUなどのGated Linear Unit（GLU）は、FFN内の特定のトークンに極端に大きい値を作る。これを著者らはactivation spikeと呼ぶ。巨大な値に合わせて活性全体の量子化スケールを決めると、大部分の普通の値の量子化刻みが粗くなり、困惑度とゼロショット精度が悪化する。

本研究は、spikeが主にFFNのdown射影へ入る活性で、モデルの前半・後半層、かつ少数のトークンに集中することを実測した。その構造を利用して、**QFeM**（spikeの強いモジュールだけ活性量子化を外す）と**QFeP**（spikeを誘発する短いprefixを事前に高精度計算し、そのKVを再利用する）を提案する。LLaMA-2-13BのW8A8では困惑度が34.089へ悪化するが、両方式併用で5.126となり、FP16の4.789に近づく。4タスク平均精度も55.29%から71.61%へ回復する。これは量子化精度の改善であって、全モジュールを同じビット幅のまま無償で高速化する方式ではない。

## 問題設定

通常のoutlier研究では、Transformerのhidden stateにある極端な値やチャネルを問題にする。しかしPre-LN構造では、各線形層に入る活性は正規化やGLUのゲート積を経て変わる。hidden stateの最大値だけでは、どの行列積が量子化で破綻するかを特定できない。著者らはquery、attention out、FFN up/gate、FFN downなど線形モジュールごとに入力活性を観測した。

C4からランダム抽出した512サンプルをキャリブレーションに用い、各層・各トークンの入力活性の絶対最大値を計測すると、GLUを使うモデルではdown射影の入力に局所的な巨大値が集中した。元のFFNを使うモデルでは同じ分布が顕著ではなく、hidden stateの大きさと線形モジュール入力の大きさは一致しない。さらにspikeを生むトークンは少数で、同じspikeを後続の全トークンが繰り返し発生させるわけではない。この二つの規則性が手法の設計根拠となる。

## 手法

### 1. モジュールごとのspike強度を測定する

各線形モジュールについて、キャリブレーション時のトークンごとの活性スケールを集める。最大スケールを中央値で割ったmax–median ratioを計算し、通常の値に対して極端なトークンが存在するモジュールを検出する。絶対最大値だけでは、モデルや層ごとに元のスケールが異なる影響を受けるため、相対比を使う。

活性量子化をすべてのモジュールへ適用すると、少数のspikeが量子化誤差を支配する。逆にすべてのモジュールをFP16のままにすると、W8A8行列積の利点を失う。そこでspikeの強いモジュールだけを除外することにより、誤差の集中箇所へ高精度計算予算を配分する。

### 2. QFeM：spikeの強いモジュールだけ活性量子化を外す

Quantization-free Module（QFeM）は、max–median ratioが閾値を超える線形モジュールを活性INT8量子化の対象から外す。除外モジュールの重みはINT8のまま保存し、行列積時にFP16へ復元してFP16活性と計算するweight-only相当の実装である。残りのモジュールは通常のW8A8で計算する。Q/K/Vなど入力を共有する兄弟射影はグループとして扱う。

閾値を下げれば非量子化モジュールが増え、精度は守りやすいが低精度行列積の範囲が狭くなる。閾値を上げればより多くのモジュールをINT8にできるが、困惑度が悪化しやすい。論文はキャリブレーション集合での困惑度と量子化可能なモジュール数を見ながら二分探索で閾値を選ぶ。LLaMA-2-13Bの例では閾値がおよそ16付近で両曲線の交換条件が見える。MoEのMixtralではexpertごとにキャリブレーションする必要がある。

### 3. QFeP：spikeを生むprefixを先に計算してKVを保持する

Quantization-free Prefix（QFeP）は、spikeが特定のトークンの初回出現に集中することを利用する。BOS、文脈トークン、spikeを誘発するトークンからなる短いprefixをモデルごとに探索し、FP16で一度処理してそのKVキャッシュを保存する。その後の量子化された推論では、このprefix KVを文脈として利用する。spikeを生成しやすいトークンが既にprefix内で処理されているため、実際のユーザー入力に続くトークンの活性スケールが安定し、per-tensor量子化の精度が上がる。

prefixは無意味な任意の文字列でよいわけではない。著者らは活性スケールの大きいトークン候補と、キャリブレーションデータ中で頻出する文脈候補を組み合わせて探索する。具体的には大きい活性を作る上位3候補と、頻出トークン上位200から文脈を選び、prefix KVを事前生成する。MoEでは活性入力ではなく出力hidden stateのスケールを使う例外処理がある。

QFePはモジュール選択を変えないためQFeMと直交し、併用可能である。ただし、事前計算のFP16 prefix KVを保持するメモリが必要で、prefixの長さだけ利用可能な文脈長も減る。ユーザー入力に対する完全な意味的無影響を理論的に保証するものではなく、短いprefixを追加することによる分布変化は評価で確認する必要がある。

### 4. 量子化粒度と既存outlier対策との組合せ

基本評価は重みper-channel、活性dynamic per-tensorの対称W8A8で行う。細粒度のdynamic per-token活性量子化はスケールを各トークンに合わせられるため、spikeによる全体への影響が小さい一方、スケール計算やカーネルの処理費用が増える。QFeM/QFePは粗粒度でも品質を保ち、より速いINT8行列積を使える領域を増やす狙いがある。

SmoothQuant（SQ）やOutlierSuppressionPlus（OSP）のように活性outlierを重みへ移す方式でも、spikeがあるとキャリブレーションスケールが歪むことがある。QFeM/QFePを前処理へ組み込むと、従来方式がうまく扱えなかったGLU固有のspikeを分離できる。論文はW6A6やW4A4でも評価しているが、INT8での改善値をそのまま4ビットに外挿してはならない。

## 評価条件

| 項目 | 内容 |
|---|---|
| 対象モデル | LLaMA-2 7B/13B/70B、LLaMA-3、Mistral、Mixtral、SOLAR、GemmaなどGLU系 |
| 主量子化設定 | W8A8、重みper-channel、活性dynamic per-tensor、対称最大値スケール |
| 比較 | FP16、通常W8A8、QFeM、QFeP、両方式併用、SQ、OSP、per-token/per-tensor粒度 |
| キャリブレーション | C4から512サンプル、モジュール別活性スケールと困惑度を使用 |
| 精度指標 | WikiText-2困惑度、PIQA・LAMBADA・HellaSwag・WinoGrandeのゼロショット正解率平均 |
| 計算環境 | Python 3.10、PyTorch 2.2、Transformers 4.38.1、RTX 4090またはA100 |
| 実装 | 公開コード https://github.com/onnoo/activation-spikes |

モデルのFFNにGLUを用いることが主な対象条件であり、従来型FFNに同じspikeが生じるとは限らない。主評価の精度はゼロショット4タスクの平均で、長文脈のサービング遅延やマルチユーザー負荷を測るものではない。

| SmoothQuant単独 | 9.907 | 61.08% |
| SmoothQuant＋QFeM | 5.534 | 69.65% |

Table 4では、通常のoutlier緩和策だけでは粗粒度の活性量子化が破綻する例がある。とくにOSP単独の7B困惑度38.490に対し、QFeM併用は5.493へ改善した。反対に、OSPは13B/70Bでは単独でも比較的良好な条件があり、spike対策の追加効果はモデル・量子化粒度に依存する。GemmaではGeGLUという異なる活性化関数のため、QFeM/QFePで他のモデルほど性能が戻らないと著者らは述べる。Mixtralではexpertによるトークン分割のためspikeの影響が比較的小さい。

## 既存研究との差

SmoothQuantなどは主にチャネル間のoutlierスケールの移動・緩和を扱う。本研究はGLUのゲート積が作る、少数トークンかつ特定層に集中するspikeを、線形モジュール入力レベルで分離する。QFeMは層ごとの活性精度を選択し、QFePは時間方向のprefix KV再利用でspikeを入力先頭に押し込む。一般的なKVキャッシュ圧縮とは異なり、QFePの目的はKV容量削減ではなく量子化スケールの安定化である。両手法を組み合わせられる点も特徴となる。

## 限界

第一に、QFeMで非量子化モジュールを増やすと低精度行列積の範囲が狭くなり、量子化の速度上の利点を失う。最適閾値はモデルやキャリブレーションデータに依存し、別の入力分布では同じ閾値が最適とは限らない。weight-only扱いのモジュールはINT8重みをFP16へ戻す追加処理を要する。

第二に、QFePはモデル固有の短いprefixを探し、FP16で処理したKVを保持する必要がある。prefixを挿入することによる文脈の変化、トークン位置の消費、複数同時リクエストでのprefix KV管理は追加要件となる。random prefixやBOSだけのprefixは効果が不安定で、任意のprefixで代用できない。

第三に、GLUのspikeを対象にしており、通常のFFN、注意機構内のoutlier、量子化の別の誤差源には直接対応しない。GemmaのGeGLUで改善が限定的な点や、MixtralのMoEでspikeの影響が比較的小さい点から、アーキテクチャ依存性がある。

第四に、精度表はWikiText-2と4種類のゼロショット評価であり、実運用の長文脈・連続バッチ・P95/P99遅延を保証しない。Figure 7の固定トークン列の遅延比較を、すべてのGPUや実装での速度向上率と見なしてはならない。低ビットW4A4では量子化粒度や別のoutlierがさらに問題になるため、W8A8の回復率をそのまま転用できない。
