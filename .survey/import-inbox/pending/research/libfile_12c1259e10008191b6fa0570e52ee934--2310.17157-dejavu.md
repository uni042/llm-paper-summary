## 概要

大規模言語モデル（LLM）の小batch復号は、巨大なweightを毎token GPU高帯域メモリから読み込むためメモリI/O律速になりやすい。固定枝刈りでparameterを削れば帯域を減らせるが、全入力に共通の小networkへ固定すると精度やin-context learningを損なう。DejaVuは「ある入力で実際に重要なattention headとMLP neuronは全parameterの一部であり、その集合は入力によって変わる」というcontextual sparsityを利用する。

各layerのactivationから次に必要なparameter集合を軽量predictorで予測し、非同期lookaheadでpredictor時間を主計算へ重ね、GPUが効率良く読めるstructuredな疎単位だけを実行する。OPT-175B、batch size 1、約75% sparsityではNVIDIA FasterTransformer比1.8〜2倍、Hugging Face実装比4.8〜6倍のtoken generation高速化を、評価taskで品質低下なしに実現する。

## 問題設定

OPT-175Bでは一つのMLP block自体が8×A100 80GB環境で約0.2 msしかかからないため、疎集合を探す処理が数msかかれば枝刈りの節約を上回る。一般的な近似近傍探索も高次元activationではHNSWが10 ms超、FAISSが4 ms超となり、直接利用できない。したがって疎性が存在するだけでは不十分で、「次layerで使うparameterを本体計算より十分安く予測する」必要がある。

またGPUは128-byte程度のblock単位でmemory transactionを行うため、ランダムなweight elementを点在して削っても実読出し量が比例して減らない。DejaVuはattention headとMLP neuronという比較的大きな構造単位で選択し、疎GEMMが実時間短縮へつながる形にする。

## 手法

### contextual sparsityの定義と観測

入力ごとに各attention head・MLP neuronの出力normを調べ、大きな寄与を持つ集合だけを残して再実行すると、dense modelとほぼ同じ出力を保てることを確認する。OPT-175Bでは完全計算からoracle的に選ぶとattention headで平均80%、MLP neuronで95%程度まで疎化できる条件があり、異なる入力では残る集合も異なる。

これは静的head pruningとは異なる。ある入力で不要なhead/neuronも別入力では使われるため、model parameterを恒久削除せず、token・layerごとにactive subsetを切り替える。

### 軽量sparsity predictor

各layerへ入るactivationを入力として、次に重要となるhead/neuronを予測する小networkを学習する。training dataはC4から500 sampleを使い、dense forwardで得た重要集合を教師にする。MLP predictorのvalidation accuracyは浅いlayerで99%超、後段で約93%まで下がるため、予測難度はlayer位置で異なる。

単にmodel最初のembeddingだけから全layerの疎集合を決めるnon-contextual方式は50% sparsityでもaccuracyを落とす。したがって現在layerのactivationを使うことが、入力依存だけでなくlayer依存のparameter選択にも必要である。

### asynchronous lookahead

predictorを各layerの直前に同期実行すると0.2 ms級の本体MLPに対してoverheadが大きい。DejaVuはactivationがlayer間でゆっくり変化する観測を利用し、先のlayerの疎集合を早めに予測して本体計算と重ねる。予測結果が必要になるまでに計算を終えることで、sparsity discoveryをcritical pathから外す。

この設計は「疎性を探すためにdense計算を先にする」oracle検証とは異なり、実推論では低コストpredictorだけを追加する。activationが急激に変わるlayerでは予測が難しくなるため、predictor精度とlookahead距離がtrade-offになる。

### hardware-aware sparse execution

予測したactive head/neuronだけに対応するweight blockを読み、GPU向けに構造化した疎行列演算で計算する。小batch復号ではweight readが支配的なので、演算FLOPsだけでなくHBMから読むparameter量を減らすことが速度へ直結する。論文のmicrobenchmarkではOPT-175BのMLP sparse implementationがPyTorch dense比最大4.5倍、attention側が最大5倍高速となる。

## 主要結果

| 条件 | 指標 | 結果 | 解釈 |
|---|---|---:|---|
| OPT-175B、zero/five-shot | 品質維持可能な総sparsity | 約75% | in-context learningを保ったまま大幅疎化 |
| OPT-175B、batch 1 | token generation vs FasterTransformer | 1.8〜2倍高速 | 実時間のend-to-end改善 |
| 同条件 | vs Hugging Face | 4.8〜6倍高速 | 一般実装との差 |
| MLP predictor | validation accuracy | 浅層99%超、後段約93% | layerごとに予測難度が異なる |
| MLP sparse kernel | PyTorch dense比 | 最大4.5倍 | HBM read削減がkernelへ反映 |
| attention sparse kernel | PyTorch dense比 | 最大5倍 | head単位疎化も実速度へ反映 |

MLPだけ85% sparsity、attentionだけ50% sparsityにしたablationでも主要taskでaccuracy lossをほぼ生じない。OPT-66Bでも50% sparsityで同様の傾向を確認する一方、別model familyではactivation function差によりMLPで使えるsparsityが低くなる。

4-bit weight量子化（W4A16）との併用では近似誤差が単純に累積せず、複数taskでDejaVu単独または量子化単独と同等以上のaccuracyを示す。このためsparsityとquantizationは競合する代替手段ではなく併用可能な圧縮軸として評価されている。

## 既存研究との差

静的枝刈りは全入力へ同じparameter subsetを使うため、入力ごとの冗長性を利用できない。Mixture-of-Expertsは学習時からrouting構造をmodelへ組み込むが、DejaVuは既存dense LLMに推論時predictorを追加して動的にsubsetを選ぶ。近似近傍探索でactivationとweightを照合する方式に比べ、predictorを学習してlookaheadすることで探索時間を主計算より小さくする。

## 限界

predictor自体に500 sample程度の収集・学習が必要で、完全training-freeではない。主利得はbatch 1のmemory-bound復号で測られており、大batchでは複数requestのactive subsetの和集合が大きくなるためsparsityが減る。ただし論文ではactive parameter分布が一様でなく、batch増加に対して線形には増えないことも観測する。さらにmodel familyやactivation functionが変わると安全なMLP sparsityが変わり、75%という値を任意LLMへ固定適用できない。
