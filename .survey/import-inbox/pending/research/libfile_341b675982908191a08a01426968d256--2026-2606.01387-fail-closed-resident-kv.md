# Fail-Closed Lowering of Resident KV Claims onto LLM Serving Runtimes


> 将来KV再利用の保証を既存runtime機構へ安全に写像するため、claim単位の意味論・証拠・失敗閉鎖条件を形式化して実装境界を監査する。

## 概要

LLMサービング基盤には、鍵値キャッシュ（KV cache）の保持優先度、時間制限、ホスト・ストレージへのオフロード、ブロックイベント、退避禁止スケジューリング、KV認識ルーティングなどが増えている。しかし、これらの機構が存在することと「ある将来時点で、この要求のKVを再利用可能な状態で提供する」という義務をruntimeが受諾することは同じではない。

本論文はこの差をResidentClaimという契約的な意味論で切り分ける。runtimeの機能名が似ているだけでは保証とみなさず、受諾したclaim identity、KVが利用可能になったことを表すmaterialization predicate、順序付きライフサイクルイベント、成功・失敗をclaim単位へ帰属できる結果が揃った場合だけloweringを認める。証拠が不足する場合は推測で「対応」とせずunknownまたはrejectedへ倒すfail-closed方針である。

TensorRT-LLM、SGLang/HiCache、Dynamoの公開機構を記述子で監査した結果、強力な近似基盤や一部adapter証拠は得られるがnative ResidentClaim conformanceとは判定しない。正のsystems witnessとして、局所改変したvLLMでclaim metadataを実際のoffload/load経路へ通し、同一claimの復元失敗をvLLMのinvalid-KV-load経路から順序付きclaim-scoped失敗へ変換できることを示す。これは性能改善論文ではなく、保証を主張できる意味論境界を明確にする研究である。

## 問題設定

保持優先度は「捨てにくくする」ヒントであり、将来再利用の成功を約束しない。ホストオフロードはGPU容量を空けるが、オフロード済みKVが必要時に確実に復元されるか、復元失敗がどの要求のどの義務に対応するかまでは自動的に定まらない。

イベントAPIも同様で、block-levelのload/evict通知があっても、受諾した将来義務とイベントが同じidentityで結ばれていなければ「このclaimが満たされた／破られた」を判断できない。routingも、KVを持つworkerへ要求を送る最適化と、claimを保証する契約とは異なる。

したがって本論文は性能機能の有無ではなく、runtime機構が上位のResidentClaim意味論を保つかを検査対象にする。特に不明な証拠を成功扱いしないことが重要である。

## 手法

### ResidentClaimと義務束

ResidentClaimは将来KV再利用について、対象identityと受諾された義務を明示する。lowering側はclaimをruntimeのpriority、offload、routing等へ写像するだけでなく、そのclaimがどのmaterialized KVへ対応し、どのイベント系列を通り、最終的にどう終端したかを追跡できなければならない。

この設計により「priorityを設定したから保証した」という名前ベースの推論を排除する。runtimeが保持を試みても、claim単位の結果を観測できなければ保証の証拠としては不足する。

### fail-closed lowering relation

各runtime/mode記述子を義務束と照合し、native conformance、adapter-observational evidence、controlled pressure下のadapter-policy evidence、approximation substrate、rejected mapping、unknown evidenceへ分類する。証拠が部分的なら上位分類へ推測昇格しない。

検査器は手作業でアンカーされたruntime descriptorを検証する。したがってソースコード全体を自動証明するものではなく、「記述子に提示された証拠が要求義務を満たすか」を機械的に確認する境界である。

### bad-lowering suite

一見妥当に見えるが意味論を破る写像をbad-lowering suiteとして用意する。claim identityが途中で失われる、イベント順序が不十分、失敗をclaimへ帰属できない、といったケースを検査器が拒否できることを確認する。

この負例群は性能benchmarkではなく、lowering checkerが過度に寛容でないことを示す構成要素除去に近い役割を持つ。

### vLLM systems witness

局所改変vLLMでは、connector/scheduler境界を通してclaim metadataを実際のin-process offload/loadへ伝える。同じclaimに属する復元を意図的に失敗させ、既存のinvalid-KV-load経路へ到達させる。

adapterはこのruntime失敗を、順序を持つclaim-scoped fail-closed outcomeへ変換する。これにより「成功時にKVを再利用できた」だけでなく、「保証を満たせないとき曖昧な成功として継続しない」ことをsystems witnessとして確認する。

## 評価条件

| 項目 | 内容 |
|---|---|
| 対象runtime | TensorRT-LLM、SGLang/HiCache、Dynamo、局所改変vLLM |
| 評価対象 | ResidentClaim loweringの意味論適合性 |
| 検査 | anchored runtime descriptor + checker + bad-lowering suite |
| 正のsystems witness | vLLM connector/scheduler境界の局所patch |
| 性能benchmark | 主目的ではなく、production performance claimを行わない |
| 判定 | native / adapter evidence / approximation / rejected / unknown |

## 主要結果

| 条件 | 結果 | 意味 |
|---|---|---|
| TensorRT-LLM、SGLang/HiCache、Dynamo | 強いsubstrateや一部adapter positiveはあるがnative conformanceなし | 公開機能の存在だけで将来KV保証とは呼べない |
| bad-lowering suite | 不十分な写像をfail-closedに拒否 | checkerが機能名の類似だけで成功判定しない |
| patched vLLM | 同一claimのrestore failureをclaim-scoped失敗へ伝播 | 実runtime経路でも義務identityと失敗閉鎖を保持可能 |
| 性能 | production speedupを主張しない | 本研究の成果は意味論境界と監査可能性 |

## 既存研究との差

KVオフロード、prefix cache、KV認識routingの研究は、容量、転送量、命中率、遅延を主に最適化する。本論文はそれらを置き換えず、上位層が「将来再利用を保証された」と扱ってよい条件を定義する。

形式仕様だけの研究とも異なり、公開runtimeのdescriptor監査とpatched vLLMの実経路を使い、意味論がどこまで既存システムへloweringできるかを具体的に示す。

## 限界

checkerは手作業でアンカーしたdescriptorを検証するため、監査していないruntime実装全体の完全性を証明しない。公開APIが更新された場合もdescriptorの再監査が必要になる。

また、本論文はproduction性能の優位性、広範な互換性、ネイティブ実装の完成度を主張しない。vLLMは局所patchによるpositive witnessであり、そのまま標準runtime機能として利用できることを意味しない。
