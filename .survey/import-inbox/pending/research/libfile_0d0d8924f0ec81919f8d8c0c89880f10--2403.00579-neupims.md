## 概要

バッチLLM推論では、QKV生成とフィードフォワードネットワークは行列同士の積（GEMM）となり、同じ重みを多数リクエストで再利用できるため計算律速になりやすい。一方、attentionは各要求固有のKVキャッシュを読む行列ベクトル積（GEMV）が中心で、メモリ帯域律速になりやすい。NeuPIMsはこの性質の違いを利用し、GEMMをニューラル処理装置（Neural Processing Unit; NPU）、GEMVをメモリ内処理（Processing-in-Memory; PIM）へ割り当てる。

単にNPUとPIMを並べるだけでは、同じDRAM bankのrow buffer競合とTransformer内の依存関係により片方が待つ。NeuPIMsは二重row bufferとsub-batch interleavingを導入し、別sub-batchのNPU計算とPIM attentionを同時進行させる。評価ではGPU-only比3倍、NPU-only比2.4倍、単純NPU+PIM比1.6倍のthroughput改善を報告する。

## 問題設定

NPUのsystolic arrayは大きなGEMMでは高利用率になるが、decode attentionのGEMVでは算術強度が低く演算器が遊ぶ。PIMはDRAM近傍で大量のweight/KV読出しを伴うGEMVを処理できるが、大規模GEMMの演算能力はNPUに劣る。

既存PIM bankは通常memory accessとPIM commandでrow bufferを共有するため、NPU側の通常read/writeとPIMを同時に進めにくい。さらに同一requestではQKV生成→attention→projection/FFNの依存があるため、異種演算器があっても単一batchを順番に流すだけでは並行性が生まれない。

## 手法

### 二重row buffer

各bankに通常memory access用とPIM用のrow bufferを分離して持たせる。これによりNPUからのread/writeとPIM GEMVが同じbank資源を完全に直列化する必要を減らす。memory controllerはDRAM timing制約を守りながら二系統commandを調停する。

### PIM向けattention

attentionのlogit計算とvalue集約はKVキャッシュを大量に読みながらqueryとのGEMVを行う。NeuPIMsはこの部分をPIMへ移し、データをNPU側へ往復させる帯域を減らす。一方、QKV projectionとFFN等のGEMMはNPUに残す。

### sub-batch interleaving

batchを独立した二つのsub-batchへ分ける。一方がNPUでQKV/FFNを実行している間に、もう一方のattention GEMVをPIMで処理するようpipeline化する。要求の系列長が異なるため、MHA latencyを推定し、greedy min-load bin packingでPIM channel負荷を均等化した上でsub-batchを構成する。

## 評価条件

| 項目 | 条件 |
|---|---|
| LLM | GPT3 7B / 13B / 30B / 175B |
| workload | ShareGPT、Alpaca |
| batch | 64〜512 |
| NPU/PIM | ONNXim + DRAMsim3によるcycle-accurate simulation |
| GPU baseline | NVIDIA A100 40GB / PyTorch |
| 主指標 | system token throughput、NPU/PIM利用率 |

## 主要結果

| 比較対象 | NeuPIMs throughput |
|---|---:|
| GPU-only | 3.0倍 |
| NPU-only | 2.4倍 |
| 単純NPU+PIM | 1.6倍 |

詳細分析ではNPU利用率が単純NPU+PIMの28.0%から64.9%、PIM利用率が17.0%から26.4%へ上昇する。二重row buffer単体の寄与が大きく、sub-batch interleavingはbatch 256以上で特に有効になる。したがってheadline倍率は「PIMを追加した効果」だけでなく、メモリ競合除去とbatch間overlapの合成結果である。

## 既存研究との差

NPU-onlyはGEMVで演算器を活かせず、PIM-onlyはGEMM能力が不足する。単純なNPU+PIM構成も同一batchの依存とrow buffer競合で直列区間が残る。NeuPIMsは演算特性に応じた異種割当てに加え、ハードウェア側の二重bufferとランタイム側のsub-batch schedulingを共同設計する。

## 限界

NPU/PIM系の主要結果は実チップではなくcycle-accurate simulationであり、GPU baselineのみ実機である。利得は十分なbatch並列性に依存し、小batchではsub-batch interleavingの重なりが小さい。専用PIM対応DRAMとmemory controller変更を必要とするため、既存GPUだけで再現できるソフトウェア最適化ではない。
