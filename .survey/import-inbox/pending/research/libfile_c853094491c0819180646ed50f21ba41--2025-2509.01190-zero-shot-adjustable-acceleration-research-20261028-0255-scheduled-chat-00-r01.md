# Efficient Large Language Models with Zero-Shot Adjustable Acceleration：学習後に保持率を変更できる隠れ活性の間引き

## 概要

推論時に残すトークン数を減らす方法は、計算量とメモリ使用量を減らせるが、学習時と異なる削除率を適用すると品質が不安定になりやすい。KachueeとSharifkhaniは、注意計算で出力への寄与が小さい隠れ活性を層ごとに間引くDynamic Resource Attentionと、微調整中に活性保持率をランダムに変える学習方針を組み合わせる。微調整を一度済ませた後、保持率αを実行時に変更するだけで速度と品質の交換関係を選べることを「Zero-Shot Adjustable Acceleration」と呼ぶ。ここでzero-shotとは**保持率を変更するたびに再微調整しない**という意味であり、事前学習済みモデルを一切調整せず適用できるという意味ではない。

原著ではGPT-2 137M、LLaMA-3-8B 4bit、Gemma-2-2B 4bitを用い、Tesla T4で評価した。GPT-2のIMDB分類では最大11倍の高速化設定が示されるが、正解率は通常設定92.40から86.48へ低下する。LLaMA/Gemmaの評価はMMLU品質と積和演算数（MACs）の削減が中心で、11倍のエンドツーエンド推論速度が8Bモデルでも得られたという結果ではない。長文生成やリアルタイムサービスへの一般化、公式コード公開状況にも制約がある。

## 問題設定

通常のTransformer注意は、各位置の問い合わせQと鍵Kから注意重みを作り、値Vの加重和として各位置の出力を計算する。長い系列では多数の位置の隠れ活性を次層へ渡すため、計算量と活性メモリが増える。全位置が同じ程度に出力へ寄与するわけではないため、低寄与の位置を落とせば処理を削減できる。ただし誤って重要位置を削ると、特に冗長性が低い入力や複雑な推論で情報が失われる。

固定削除率で微調整したモデルは、後から別の削除率へ変更すると学習時に経験していない計算経路となり、品質が落ちる。逆に学習中に削除率を順番に変えるだけでは、直近の設定に適応し過ぎる可能性がある。著者の目的は、推論要求の負荷や品質要件に応じて保持率を切り替えられるよう、学習中から幅広い保持率に耐える表現を作ることである。これはモデル重みを削る構造化剪定とも、KVキャッシュを量子化する方式とも異なり、**系列上の隠れ活性の数を層ごとに減らす**方法である。

## 手法

### 1. Dynamic Resource Attentionによる活性の選択

注意重みと値ベクトルの寄与を基準として、次の層へ残す隠れ活性を選択する。保持率αは0から1の実数であり、αを小さくするほど削除対象が増える。層lに残す活性数N_lは、前層の活性数N_(l-1)と最低保持数τ_lから、N_l=max(αN_(l-1), τ_l) と定める。論文の実装ではτ_l=5で、削除率を高くしても極端に少ない活性しか残らない状況を避ける。

例えばα=0.3なら、最低保持数の制約に達する前は各層で前層の約30%の活性を保持する。実際には整数化と最低保持数があるため、入力長が短い場合に毎層70%を削れるわけではない。入力系列が長くなるほど層をまたいだ活性数削減の余地が大きい一方、重要な文脈を早期に落とした場合は後続層で復元できない。著者は注意出力への寄与に基づく選択を提案するが、全タスクで意味的な重要性を完全に検出できるとは主張していない。

この機構を注意層に組み込み、選択した活性だけを後続処理へ渡す。保持率は推論時に設定する単一の制御量として扱えるため、負荷の高いときは小さく、品質を優先するときは大きくする運用が可能となる。ただし負荷を観測して自動的にαを最適化するオンラインスケジューラを評価したわけではない。保持率の決定は利用者側の方針であり、SLOに応じた自動制御の性能は未検証である。

### 2. 一様サンプリングによる保持率ロバスト化

微調整時に固定αを用いると、そのα付近では高品質でも別のαに弱い。著者は各学習ステップで α~Uniform(0.02,1.00) とサンプリングし、広い保持率の計算経路を学習中に経験させる。保持率を学習の終盤だけ変える方式では最後の設定に過適合するという問題を、ステップごとの乱数化で緩和する。推論時にはαを指定するだけで、再学習なしに異なる加速設定へ切り替えられる。

この学習方針は従来の微調整を置き換えるもので、著者は追加の学習工程を必要としないと説明する。ただし実際の学習にはGPU資源を要し、既存の一般公開チェックポイントに即座に適用できるわけではない。LLaMA-3とGemma-2では4bit量子化とLoRAを併用しており、実験はその実装条件を含めて解釈する必要がある。学習時のαの範囲と、評価時に実際に使った範囲も区別すべきである。GPT-2はα=0.02〜1.00、LLaMA/Gemmaはα=0.50〜1.00で評価している。

### 3. 計算・メモリ・品質の因果関係

隠れ活性を間引けば、後続の注意やフィードフォワード処理へ渡る位置数が減り、演算数や中間活性のメモリ量を抑えられる。これは重みパラメータを消すわけではないため、常駐モデル重みの容量は原則そのままである。論文Table 3のGPUメモリ削減率は「固定のモデル自身のメモリを除く」測定であり、GPU総メモリが同じ倍率で減ると解釈してはいけない。低バッチ・長系列で活性処理の割合が高いと利得が増え得るが、実装のカーネル効率や選択処理のオーバーヘッドにも左右される。

逆に、削除した位置が質問への回答に必要なら、後続層は情報を失ったまま推論する。著者は長さとタスクに依存して品質劣化が変わることを明記する。特に冗長性の低いサンプルや複雑な概念を含むサンプルでは劣化が大きい。したがって、αは単なる速度スライダーではなく、検証済み品質の範囲内で使う必要がある。

## 評価条件

| 項目 | 原著で確認できる設定 |
|---|---|
| 実装環境 | PyTorch、Hugging Face、NVIDIA Tesla T4 GPU |
| GPT-2 | 137M、IMDB、GLUE、WikiText-103、LAMBADA、PTB、1BW |
| 大規模モデル | LLaMA-3-8B 4bit、Gemma-2-2B 4bit、MMLU |
| 学習 | 学習率4×10^-5、batch 8、5 epochs、dropout 0.1、最低保持数5 |
| 学習時の保持率 | 各stepでαをUniform(0.02,1.00)から抽出 |
| 評価時の保持率 | GPT-2は0.02〜1.00、LLaMA/Gemmaは0.50〜1.00 |
| 指標 | 分類accuracy/F1、言語モデルPPL、MMLUスコア、MAC削減、固定重みを除いたGPU活性メモリ、GPT-2の速度設定 |

GLUEの値はテストサーバ制限のため検証集合で評価したものと原著に記載されている。MRPCとQQPはF1、それ以外の分類はaccuracyである。言語モデルPPLは小さいほどよく、MACは積和演算回数であり実測レイテンシと同じではない。表中の「1.5x」「2.5x」などは原著の加速・MAC削減設定であって、すべてが同じGPU・モデルで実測した秒数の比ではない。

## 限界と実用上の注意

第一に、学習時のランダム保持率により実行時の再微調整は不要になるが、初回の微調整は必須である。論文はコードと学習済みモデルを将来公開予定としており、確認したv2本文に再現可能な公式リポジトリURLは記載されていない。第三者が既存のモデルをそのまま置き換える実用段階とは区別する。第二に、評価はTesla T4、GPT-2中心の実測と、LLaMA/GemmaのMAC・MMLUを含むが、H100等の大規模サービング環境でのTTFT・TPOT・P99遅延、連続バッチ、実際の可変長生成の実測は不足する。

第三に、トークン間の依存が強いタスク、冗長性が低い入力、複雑な推論では高削除率の品質損失が大きい。IMDBの11倍設定の精度低下、GPT-2のPPL悪化、8B/2BのMMLU低下は独立した負の結果である。単に「高い加速でも精度維持」と要約してはならない。第四に、元モデルの注意実装、位置埋め込み、キャッシュ、専用カーネルとの互換性は未検証である。トークンを層ごとに間引く処理は、固定形状を仮定した高速カーネルに選択・再配置の費用を発生させる可能性があるが、原著はそのオーバーヘッドを多様な実装で切り分けていない。

## 既存研究との差と位置付け

従来の重み剪定はパラメータ数を減らすため、固定した小型モデルを得るのに適する。一方、DRAは同じ微調整済みモデルでαを変えるため、負荷と品質要件が変化する運用に柔軟である。動的早期終了は層を途中で止めるのに対し、DRAは層間で渡す系列上の隠れ活性を選別する。トークン併合は情報を統合して残すが、本方式は低寄与の活性を削るため、取り逃した情報は復元できない。特に「一様サンプリングで幅広い保持率へ耐性を付ける」学習設計が、単純な固定削除率との相違点である。

運用判断では、GPT-2での実測加速と、LLaMA/Gemmaでの演算削減を別の証拠として扱い、許容品質損失に応じたαの範囲を個別データセットで校正する必要がある。推論時にαを変更できる点は有用だが、品質を自動保証する機構ではない。論文の貢献は、任意の既存モデルを無学習で11倍にすることではなく、**一度の保持率ランダム化微調整で速度・品質を後から調整可能にする**設計と、その限定条件下の実証である。
