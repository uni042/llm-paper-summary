# Tutti: Making SSD-Backed KV Cache Practical for Long-Context LLM Serving

> GPUネイティブKVオブジェクト、GPU io_uring、余裕時間認識I/OスケジューリングでSSD↔HBMのCPU介入を除き、LMCache比TTFT 78.3%削減・リクエスト率2倍を実現する。

## 概要

長文脈・複数ターン・エージェント型ワークロードでは、接頭辞キャッシュを再利用するとプリフィル計算を大幅に省ける一方、KVキャッシュ総量はGPU高帯域メモリ（HBM）やCPU DRAMを容易に超える。NVMe SSDは容量単価が低いが、vLLMやSGLangが使うページ化KVは16〜32トークン程度の小ブロックへ分散されるため、復元時には多数の微小ランダムI/Oが発生する。GPU Direct Storage（GDS）を使ってもI/Oごとの発行・完了処理はCPUに残り、論文の測定ではSSD復元時にGPUが70〜80%停止する条件がある。

Tuttiは、SSDを単なる大容量退避先として足すのではなく、KVオブジェクトの管理とI/O発行をGPU側へ移す。CPUは層ごとにI/Oカーネルを非同期投入するだけで、個々のKVブロック転送を制御しない。これによりCPU制御量を概念的に O(layer×blocks) から O(layer) へ落とし、GPUが多数のSSD I/Oを並列発行できるようにする。

## 問題設定

既存のHBM–DRAM–SSD階層では、SSDの公称帯域そのものより、ページ化KVの細粒度とCPU中心のI/O制御が問題になる。長い接頭辞を復元すると小I/Oが爆発し、CPUがGPUとNVMeの双方を十分に駆動できない。計算と転送を単純にパイプライン化しても、SSDでは転送をさらに細分化して帯域を落とし、CPUスケジューリング負荷も増える。

その結果、SSDからKVを読むよりプリフィルを再計算した方が速い領域まで生じる。Tuttiの目標は、SSD容量を使いつつDRAM版キャッシュに近い推論性能を得ることであり、KVの選別や圧縮ではなく、ストレージI/O経路そのものを推論向けに作り替える。

## 手法

### GPUネイティブKVオブジェクト

Tuttiは、ページ化KVをストレージ側の生ブロックとして扱わず、GPUから直接操作できるKVオブジェクトへまとめる。GPUファイルプール、NVMeファイルプール、P2Pメモリマッピング表を組み合わせ、割当・索引・高並列アクセスを一つの抽象へ統合する。

この抽象により、論理的には一つの長いKV領域を、物理的には分散ページのまま一括転送対象として扱える。CPUが各ページを列挙してI/O要求を作る必要をなくすことが、単なるGDSとの差になる。

### GPU io_uring

CPU版io_uringに相当する非同期発行・完了処理をGPU側へ移したGPU io_uringを導入する。GPUカーネルがI/O要求を並列発行し、完了もGPU側で扱うため、SSD→HBMのデータ経路だけでなく制御経路からもCPUを外す。

計算カーネルとI/Oカーネルが同じGPU資源を奪い合うと逆効果になるため、TuttiはGPU資源を分割し、I/O発行がTransformer計算を過度に阻害しないようにする。

### 余裕時間認識I/Oスケジューリング

各層の計算時間からI/Oを隠せる余裕時間をオフライン計測し、KV転送をその窓へ配置する。単純な「できるだけ早く読む」方式ではなく、GPU計算のクリティカルパスへ入らないタイミングを選ぶ。

この設計は、SSD帯域を飽和させるだけでなく、I/OカーネルがSMやメモリ帯域を奪って推論を遅くする問題を抑える。KV復元とTransformer実行を同時に考える点が、一般的なGPUストレージ基盤との差である。

## 評価

| 項目 | 条件・結果 |
|---|---|
| 実装 | vLLMへ統合 |
| 比較対象 | SSD-backed LMCache、GDS有効構成、DRAM-backed LMCache |
| 主要指標 | 初回トークン時間（TTFT）、達成可能リクエスト率、GPU stall、サービング費用 |
| TTFT | GDS対応SSD版LMCache比で最大78.3%削減 |
| request rate | 最大2倍 |
| cost | 27%削減 |
| GPU stall | 既存SSD経路の70〜80%級停止をほぼゼロへ近づける |
| DRAM比較 | SSD容量を使いながらDRAM-backed LMCacheに近い推論性能 |

重要なのは、SSDを高速化した結果だけではなく、近年の推論カーネル高速化によって「再計算の方がSSD復元より速い」状態へ悪化していた逆転を解消する点である。高速GPUほどCPU制御の相対コストが大きくなるため、GPU中心I/Oの価値が増える。

## 既存研究との差

LMCacheのGDS経路はGPUとSSDを直接接続してデータコピーを短縮するが、I/O要求の発行はCPUに残る。Tuttiは制御もGPUへ移し、KVオブジェクトという推論専用抽象と組み合わせる。BaMやGPUファイルシステムのようなGPU中心ストレージ技術を、そのまま使うのではなく、ページ化KV・層単位計算・推論SLOへ合わせて再設計している。

## 限界・実装状況

GPU側へI/O制御を移すため、GPUストレージスタックとNVMeのP2Pアクセスを利用できる環境が必要になる。I/Oカーネル自身もGPU資源を消費するため、計算との競合を正しく予測できないワークロードでは利得が小さくなり得る。また「ほぼ無限容量」はSSD容量がHBM/DRAMより十分大きいという実用上の表現であり、物理容量やSSD耐久性が無制限という意味ではない。

## 一般的な実装上の含意

SSDオフロードでは、公称帯域だけでなくI/O発行主体と転送粒度を測る必要がある。GPU DirectであってもCPUが数万の小I/Oを発行するなら、GPU高速化に伴ってCPUが相対的な壁になる。KVのページ構造をストレージへ直接露出せず、推論単位へまとめる設計が重要である。
