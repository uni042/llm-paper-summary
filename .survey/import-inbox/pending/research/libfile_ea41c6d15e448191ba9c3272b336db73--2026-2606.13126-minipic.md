# MiniPIC: Flexible Position-Independent Caching in <100LOC

## 概要
通常のprefix cachingは、過去要求と完全に同じprefixを共有するときだけKVキャッシュを再利用しやすい。検索拡張生成（RAG）やagentic workloadでは、同じ文書、code file、tool descriptionのような再利用可能spanがprompt中の異なる位置へ現れるため、内容が同じでもpositionが違うだけで再prefillが必要になる。既存の位置非依存キャッシュ（Position-Independent Caching; PIC）はこの問題を解くが、server内部へ大規模な変更を入れるか、KVをserver外へ置いてhost-to-device転送を発生させる実装が多い。

MiniPICはvLLMの既存KV管理を保ちながら、位置符号化前のKをcacheし、attention kernel内でrequestごとのlogical positionに基づきRoPEを適用する。さらにblock-aligned padding、span separator（SSep）、prompt depend（PDep）の3 primitiveだけでhashingとblock-level causal dependencyを制御し、Block-Attention、EPIC、Prompt Cacheなど異なるPIC方式を同じrunning vLLM instanceで表現する。2WikiMultihopQAではinterleaved schedulingと組み合わせ、baseline vLLM比prefill throughput 49%改善、cached spanのtime-to-first-tokenを最大2桁短縮、worst-case overhead 5.7%を報告する。

## 問題設定
RoPEを使うTransformerではKへposition-dependentな回転が入る。内容が同じspanでもprompt中の開始位置が変わればKが変わるため、通常のKV cache entryをそのまま別位置へ移せない。RAGで検索文書の順序が変わる、agentが同じtool definitionを別contextへ挿入する、といっただけでcache missになる。

PICでは「spanの内容」と「今回の論理位置」を分離する必要がある。同時に、既存vLLMのpaged KV管理、hash-based prefix cache、CPU offloadなどを壊さず実装しなければ、cache再利用で節約したprefillより管理・転送costが大きくなる。

## 手法
### 位置符号化前KV
MiniPICはKをRoPE適用前の形でKV cacheへ保存する。attention実行時にcacheからK tileを読み出し、そのrequestが現在spanへ割り当てたlogical positionを使ってkernel内でRoPEを適用する。これにより同じcontent-derived Kを別の絶対位置へ再利用できる。VはRoPE対象ではないため同様の位置依存変換を必要としない。

### 3つのprimitive
block-aligned paddingは再利用spanをvLLMのcache block境界へ合わせ、既存block管理とhashを使いやすくする。SSepはspan境界を示してhashing上の独立性を作る。PDepはあるprompt部分がどの先行spanへ依存するかを表し、単純prefixとは異なるblock-level causal attention structureを構成する。これらを組み合わせることで、個別PIC論文ごとに別serverを作らず複数方式を表現できる。

### 既存vLLMとの統合
core engine変更を100行未満へ抑え、重い変更はcustom attention backend側へ局所化する。KV stateをserver外へexport/importする方式と異なり、vLLM自身のcache residencyとCPU offload機構を使えるため、再利用のたびにhost-to-device copyを必須にしない。

## 評価条件・主要結果
| 観点 | 条件・結果 |
|---|---|
| 実装 | vLLM、core変更100 LOC未満 + custom attention backend |
| 対応 | Block-Attention、EPIC、Prompt Cacheを同一instanceで実現 |
| workload | 2WikiMultihopQAを含む再利用span workload |
| prefill throughput | interleaved schedulingでbaseline vLLM比+49% |
| TTFT | cached spanで最大2 orders of magnitude短縮 |
| uncached span | linear prefill scalingを維持 |
| worst-case overhead | 5.7% |

49%はキャッシュ可能spanを含むinterleaved workloadでのprefill throughput改善であり、全tokenが未キャッシュの場合の純attention kernel高速化ではない。2桁TTFT短縮もcache hit時の効果である。

## 既存研究との差
既存PICは個別方式ごとにserver内部へ専用実装を入れるか、KVを外部cache serviceへ移して再注入する傾向がある。MiniPICは「unrotated K + logical positions」と3 primitiveを共通基盤にし、複数PIC semanticsを既存vLLM cache managerの上へ載せる。研究上の新規性だけでなく、実装変更量と既存offloadとの共存を明示的な設計目標にしている。

## 限界
cache hitが少ないworkloadでは位置非依存化の追加処理が純overheadとなり、論文でもworst case 5.7%を報告する。再利用単位をblockへ合わせるpaddingはtoken増加を伴い得る。RoPE適用位置をattention backendで扱うため、対応backend・kernelへの実装が必要であり、全推論エンジンへ無変更で移植できるわけではない。また利得はspan反復率、span長、prompt構造に強く依存する。
