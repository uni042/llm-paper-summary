# Attention Score is not All You Need for Token Importance Indicator in KV Cache Reduction: Value Also Matters

## 概要
KVキャッシュ削減では、過去トークンのうち将来の注意で重要そうなものだけを残す方式が広く使われる。H2OやScissorhandsは注意スコアを重要度の中心に置くが、注意出力は重みだけでなく値（Value）ベクトルとの積で決まる。著者らは値ベクトルのノルムがトークン間で大きく非一様であり、高い注意を集めるトークンでも値ノルムが小さい場合があることを観測した。

値考慮トークン枝刈り（Value-Aware Token Pruning; VATP）は、既存方式が持つ注意重要度 S に値ベクトルのL1ノルムを掛け、I=S×||v||1 として順位付けする。モデル再学習を必要とせずH2O/Scissorhandsへ追加できる。LLaMA2-7B-chatとVicuna-v1.5-7B-16k、LongBench 16タスクで、50% KV予算時に注意のみの基準を12〜14タスク程度で上回る条件があり、FlashAttention互換実装では全KV比で50%予算時1.53倍、25%予算時2.08倍の生成スループットを報告する。

## 問題設定
自己注意の出力は各過去トークンについて注意係数 a_i と値ベクトル v_i の積を足し合わせる。したがってa_iだけが大きくても||v_i||が小さければ出力への寄与は限定される。しかし既存のKV追放方式は、どの過去トークンを残すかを主に注意係数の履歴から決める。

特に系列先頭付近の注意シンクは高い注意を集めやすい。著者らの観測では、こうした位置の値ノルムが小さい例があり、「注意が高い＝出力寄与が大きい」という近似が崩れる。VATPは新しい予測器を学習するのではなく、注意式に元から存在する値の大きさを重要度へ戻す。

## 手法
### 値を含む重要度
復号時刻t、過去トークンkに対し、基礎枝刈り法が与える重要度を S_t^k とする。VATPは I_t^k = S_t^k ||v_k||_1 を使う。値ノルムが大きいトークンは同じ注意スコアでも優先され、小さいトークンは降格する。

L1ノルムは値ベクトル生成時に計算でき、その後キャッシュできるため、毎復号ステップで値全体を再走査する必要はない。追加状態は各KV項目当たりスカラーに近く、d_head=128の代表条件ではKV本体に比べて小さい。

### H2OとScissorhandsへの統合
VATP自体は追放ポリシー全体を置き換えない。H2Oの累積注意スコアやScissorhandsの重要度計算に値ノルムを掛け、その後は各方式の予算制約・追放処理を使う。したがって「どの履歴統計を使うか」と「値を考慮するか」を分離できる。

先頭Fトークンは重要度にかかわらず保持する。論文では概ね20〜40トークンを用いる。これは注意シンクをすべて削除すると注意分布そのものが不安定になり得るためで、VATPは値が小さい注意シンクを無条件に全削除する方式ではない。

### なぜ値ノルムが効くか
注意出力への一次的な寄与は a_i v_i なので、値ノルムは「そのトークンへ注意した結果、どれだけ大きいベクトルを混ぜるか」の粗い代理になる。注意だけの順位では、a_iが大きいがv_iが小さい項目を過大評価し得る。VATPはその誤順位を安価に補正する。

一方、L1ノルムは方向や他トークンとの相殺を見ないため、真の因果的重要度そのものではない。論文の主張は、単純な大きさ情報だけでも注意のみより良い枝刈り順位を作れるという実証である。

## 評価条件
|項目|内容|
|---|---|
|モデル|LLaMA2-7B-chat、Vicuna-v1.5-7B-16k|
|データ|LongBench 16タスク|
|基準|H2O、Scissorhandsと、それぞれへのVATP追加|
|主KV予算|50%、追加で20〜80%削減域を評価|
|実装評価|FlashAttention互換Scissorhands構成、A6000|
|指標|LongBench品質、生成スループット、ピークメモリ|

## 主要結果
|条件|結果|意味|
|---|---|---|
|LLaMA2 + H2O|16中12タスクでVATP版が上回る|値ノルム追加が複数タスクで有効|
|LLaMA2 + Scissorhands|16中13タスクで上回る|特定基礎方式だけに依存しない|
|Vicuna|方式により16中12〜14タスクで上回る|別モデルでも傾向を確認|
|50% KV予算|全KV比1.53倍スループット|品質改善だけでなく圧縮実装の速度利得|
|25% KV予算|全KV比2.08倍スループット|強い圧縮ほどメモリ読出し削減が効く|
|追加計算|スループット・ピークメモリ差は小さい|値ノルム計算の固定費が限定的|

## 既存研究との差
H2OやScissorhandsは過去の注意を「将来も重要である」信号として使う。VATPはその時間的統計を捨てず、注意出力式のもう一方の要素である値ベクトルの大きさを乗算する。新しいキャッシュ構造や学習済み予測器を導入せず、既存枝刈りへ局所的に追加できる点が差である。

## 限界
H2Oは累積注意を得るため注意行列の明示化を必要とし、FlashAttentionと組み合わせにくい。VATPを追加しても基礎方式側のこの制約は消えない。値ノルムは出力寄与の近似で、方向や層間効果を表さない。評価モデルは主に7B級であり、より大きなGQA/MQAモデルや大規模サービング負荷で同じ品質差が出るかは論文の主要評価範囲外である。
