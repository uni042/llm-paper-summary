# Context Memorization：長い固定文脈を注意状態メモリへ外部化する生成方式

## 書誌情報

Yasuyuki Okoshi、Hao (Mark) Chen、Guanxi Lu、Hongxiang Fan、Masato Motomura、Daichi Fujikiによる2026年5月18日公開のプレプリント（arXiv:2605.18226v1）。正式名称は *Context Memorization for Efficient Long Context Generation*。原著の本文、数式(1)〜(8)、表1〜6、付録A〜Cを確認した。公式実装は原著に記載されている。対象は、多数の利用者要求が**同じ長い固定接頭文脈**を繰り返し参照する推論である。

## 概要

通常の文脈内学習（in-context learning; ICL）や検索拡張生成（retrieval-augmented generation; RAG）では、規則集や例示を接頭文脈としてLLMへ入力する。前処理（prefill）のKVキャッシュを再利用しても、生成時には長い接頭文脈のキー・値を読み、現在の問い合わせと注意を計算し続ける。さらに生成トークンが増えると接頭文脈へ向かう注意の相対比率が減る可能性がある。

著者らは注意状態メモリ（attention-state memory; ASM）を提案する。事前に接頭文脈と代表的な問い合わせ列をモデルへ通し、各層で「接頭文脈への注意出力」と「ソフトマックス正規化和」を記録する。問い合わせベクトルのクラスタ化で辞書を小さくし、生成時には近い辞書項目を選び、通常の自己注意結果へ統合する。元の接頭文脈のKVを毎ステップ読む必要をなくし、接頭文脈の長さLではなく辞書の項目数Kに検索費用を依存させる。

LLaMA 3.1-8Bを使うManyICLBenchの主要5課題では、同等のメモリ予算で1K〜8K項目の平均精度が文脈内学習基準と同等以上になり、8K予算では注意演算の遅延を1.36倍改善したと報告する。NBA規則質問では4K項目の正解率25.5%が、全文20Kトークンを入力する基準の24.1%を上回る。**ただし、厳密なのは状態を統合する数式であり、近い問い合わせへクラスタ代表状態を代入する検索は近似**である。したがって全入力で元の接頭文脈と同じ出力になる方式ではない。

## 問題設定と既存方式の不足

長い規則書や多数の例を毎回与える方式では、同じ接頭文脈が何度も使われる。KVキャッシュ再利用は前処理の重複計算を抑えるが、生成時の注意は接頭文脈長にほぼ比例するキー・値の読出しを続ける。接頭文脈を短縮したりKVの一部を削ったりする方式でも、残した接頭文脈への注意計算が必要である。一方、文脈を重みに蒸留する方式は生成時の参照をなくせるが、接頭文脈ごとに学習や適応処理が必要となり、頻繁な規則更新に不向きである。

ASMが解こうとするのは、**モデル重みを更新せずに、接頭文脈の情報を別の参照表へ変換し、生成時の接頭文脈注意を省く**ことである。これは一般的な検索エンジンから新しい文書を探すRAGそのものではない。既に決まった接頭文脈に対してモデル内部で生じる注意出力を、問い合わせベクトルに応じて再利用する仕組みである。従って同じ文脈を多数回使うほど事前構築費用を償却しやすく、文脈が毎回全く異なる場合は構築費用が問題となる。

## 手法

### 1. オンライン・ソフトマックス恒等式と状態の定義

接頭文脈を複数の互いに重ならないKVブロックに分ける。ある問い合わせベクトルqに対し、ブロックbの注意出力をa_b(q)、指数スコアの総和をZ_b(q)と置く。全ブロックを連結した注意出力は `sum_b Z_b(q)*a_b(q) / sum_b Z_b(q)` と等価である。二つの状態 `(a_A,Z_A)` と `(a_B,Z_B)` は、`((Z_A*a_A+Z_B*a_B)/(Z_A+Z_B), Z_A+Z_B)` で統合できる。これは原著式(1)〜(3)のオンライン・ソフトマックス恒等式で、同一のqに対する正確な状態があれば、元のキーと値を保持せずに結合できる。

この対 `(a,Z)` がASMの注意状態である。単なる注意出力aだけを保存すると、接頭文脈と新しい会話部分のどちらへどの程度の重みを割くべきか復元できない。Zを保持することで、後続の通常注意出力と正しい正規化比率で結合できる。各層・各ヘッドの状態を別々に扱う必要があり、モデル全体を一つの文書埋め込みへ置き換えるわけではない。

### 2. 辞書項目の収集：接頭文脈と応答トレースを順伝播

事前構築では固定接頭文脈の集合Pと、ユーザー質問・回答を含む応答トレース集合Tを用意する。接頭文脈pとトレースtを連結して通常の順伝播を実行し、各層でトレースの各トークンに対応する問い合わせqと、そのqが接頭文脈へ向ける注意状態 `(a_p(q),Z_p(q))` を収集する。収集結果は層ごとの三つ組 `(q,a,Z)` であり、モデルの重み更新や逆伝播は行わない。

この段階の計算量とピークメモリは、接頭文脈の長さとトレース数に依存する。原著は複数の接頭文脈ブロックを独立に順伝播し、式(3)で状態を統合できる点を利用する。例えば16Kトークンの接頭文脈を4Kずつ4回に分割すれば、各回で16K全体を保持する必要がなくなる。ただし分割によって構築費用がゼロになるわけではなく、複数回の順伝播と統合が必要である。

### 3. クラスタ化と注意を考慮した代表状態

すべての問い合わせに対する状態を保存するのは非現実的なので、各層の問い合わせベクトルをK-meansでK個のクラスタへまとめる。クラスタの代表問い合わせq̄は所属ベクトルの平均、代表正規化和Z̄は所属Zの平均である。代表注意出力āは単純平均ではなく、各状態をZで重み付けした `sum(Z*a)/sum(Z)` とする。これは原著式(5)の注意を考慮した集約で、正規化和の異なるトレースを同じ重みで扱う誤りを避ける。

Z̄をクラスタ内サンプル数で正規化する理由は、複数サンプルの情報を集約しただけで接頭文脈の注意の重みが不自然に増えることを避けるためである。保存されるのは各層の `(q̄,ā,Z̄)` のK個の項目であり、元の全接頭文脈トークンのKV列ではない。Kが小さすぎれば異なる質問が同じ代表へ潰れ、Kが大きすぎればクラスタを埋める十分なトレースが必要になる。

### 4. 生成時の検索と通常自己注意への統合

生成時には接頭文脈をモデル入力へ付けず、現在の質問・生成履歴だけから問い合わせqを計算する。各層で代表問い合わせq̄との余弦類似度が最大の項目を探し、その `(ā,Z̄)` を取り出す。新しい会話部分への通常自己注意から得た `(a_self,Z_self)` と、検索状態 `(ā,Z̄)` を式(7)で統合し、`(Z_self*a_self+Z̄*ā)/(Z_self+Z̄)` を注意出力として後段へ渡す。

この流れは「辞書検索→接頭文脈相当の注意状態取得→自己注意との結合→次のTransformer処理」という一連の操作になる。通常自己注意は消えず、生成済みトークンのKVキャッシュも必要である。削減するのは固定接頭文脈への再注意であり、モデル全体の計算量やメモリがKに対して完全に一定になるわけではない。最も近い代表状態を使う段階に誤差があるので、数式上の結合が厳密であることをもって推論結果が完全に等価とは主張できない。

### 5. 検索キーと階層索引

原著は回転位置埋め込み（rotary positional embedding; RoPE）適用前の問い合わせを使う方式と、共通の仮想位置でRoPEを適用する方式を比較する。前者は絶対位置の影響を避けて意味的な近さを見やすくし、後者は位置に関係する特徴を残す。さらに問い合わせの共分散を使った白色化（whitening）を組み合わせ、特定の高分散次元が余弦類似度を支配することを緩和する。これらは4種類の検索キー構成として検証される。

全K項目との線形検索では毎トークンの比較がKに比例する。そこで代表問い合わせを階層索引へ配置し、まず第1段階の候補を選び、その配下で詳細検索する。論文の遅延評価では第1段階の上位16候補を展開する設定を採用し、ほとんどの条件で平坦な最近傍検索と近い精度を保つ。著者は検索費用が対数的に増えると説明するが、実装上の具体的な比較回数や索引品質はK、索引形状、データ分布に依存する。小さいKでは階層化自体の費用が上回り得る。

### 6. グループ化問い合わせ注意への対応

グループ化問い合わせ注意（grouped-query attention; GQA）では複数の問い合わせヘッドが同じKVヘッドを共有する。ASMはヘッド群の問い合わせを連結・集約した検索キーを作り、ヘッド群単位の代表状態を構築する。個別のヘッド群ごとにクラスタを持つ方式と、群をまたいで代表を共有する方式を比較し、記憶容量と検索忠実度の交換条件を調べる。検索キーの次元d'を2d_hとするのは、原著の帯域計算でASMの1項目をGQAの1KV項目と同程度のメモリ費用として比較するためである。

原著のGQA比較では、通常注意の接頭文脈読出しが長さLに比例する一方、ASMの検索キー読出しは項目数Kと次元d'に比例する。従って接頭文脈を長くしてもKを固定できれば読出し量を抑えられる。ただし実際のメモリ常駐量には全層の代表状態、索引、通常生成側のKVがあり、単純に「接頭文脈を完全に消してゼロメモリ」とはならない。

ManyICLBenchの主要5課題では、同等メモリ予算の1K〜8K範囲でASMの平均精度がICLと同等以上となるが、16Kでは校正トレースが不足してクラスタの質が落ちる。特にbbh_geometric_shapesは学習例が150しかなく、16K項目の辞書を十分に埋められない。これは「辞書を大きくするほど正確」という単純な仮説を否定する。KVzipは多数の設定でASMより低精度だが、比較は原著で選んだ5つのICL課題に限定される。

数学・科学の2課題では、もともとの長い文脈内学習の利得が小さく、ASMも一貫した大幅改善を示さない。上表のgpqa_cot 2Kでは28.3%から24.2%へ低下する。したがって「平均で改善」という要約だけで全タスクにおける精度改善を保証しない。NBAでも4Kが最良であり、8Kや16Kへ増やすと低下する。クラスタの密度、検索キー、トレースの分布を調整する必要がある。

構築を分割する実験では、16Kを一括入力したbanking77の79.0%に対して、4K×4の統合は78.5%を達成した。4Kだけを使った61.5%より高い。これは「分割したら接頭文脈の残りを捨てる」のではなく、各部分の状態をソフトマックス恒等式で統合することが効いている証拠である。ただし処理トークン総数が消えるわけではなく、前処理回数は増える。

付録BではQwen3-8Bのbanking77で2K予算のICL50.0%に対しASM57.0%、4Kでは66.0%に対し71.5%を報告する。一方、1KではICL50.0%に対しASM32.0%で明確に悪い。LLaMA 3.2-3Bでは4K予算でICL60.5%、ASM77.5%、8Kでは76.0%、ASM84.0%となる。モデルを変えても一部条件で利得がある一方、最適項目数は同じではない。

## 構成要素と感度の考察

検索キーのRoPE適用方法と白色化の有無は、各層の問い合わせ表現がどの程度クラスタに分かれるかを左右する。原著はタスクごとに4種類のキー表現とクラスタ共有方式を検証し、検証集合で最良の構成を採用している。このため、報告された代表精度を「設定を一切調整しない場合の性能」と読むことはできない。推論タスクでは白色化が効く例があるが、万能な一種類のキーは示されていない。

階層検索の実験は8K項目を中心に第1段階から何個の候補を展開するかを変える。上位16候補を展開すれば、多くの設定で全項目を線形走査した最近傍精度に近づくと報告する。これより候補数を減らすと検索誤差が増え得る一方、増やすと検索の計算費用が上がる。原著の対数的な検索費用という主張は、階層索引が適切に機能することを前提とする。

実行時には固定接頭文脈のKVを読み直さないものの、毎トークン・毎層で辞書検索と統合が必要になる。短い接頭文脈ではその固定費用が勝り、本文の遅延図でも小さいメモリ予算でASMが遅い条件がある。4K程度で通常注意より有利になり、16Kで1.8倍という数値は注意演算の測定である。バッチ増大時、ネットワーク越しの辞書参照、複数モデル同時配信、KV階層化を組み合わせた総合スループットはこの論文の主実験ではない。

## 限界と負の結果

最大の仮定は、固定タスクや固定人格の問い合わせベクトルが少数の代表状態へ近似できるほど局所的な分布を持つことである。長い多ターン会話で雑談、技術相談、別タスクが混在し、問い合わせ分布が広く変化するとクラスタ代表の誤差が増える。原著付録Cはこの**接頭文脈の漂移と問い合わせ分布の非定常性**を明示的な限界として挙げる。頻繁に内容が更新される文書では、状態辞書の再構築や更新の費用も考慮する必要がある。

また、ソフトマックス状態の統合演算自体は数学的に厳密だが、クラスタ代表を未知の問い合わせへ代入する段階は近似である。特に未学習の質問型、少ない校正例、極端に小さい辞書、逆にデータ数に比べて大きすぎる辞書では精度が悪化する。NBAの16K項目が4Kより低精度である事実は、この非単調性を示す。数学・科学課題でも改善が限定的であり、元のICLが有効でないタスクではASMだけで能力を引き出せない。

事前構築は「学習不要」であって「計算不要」ではない。多数のトレースに対する順伝播とクラスタ化が必要で、NBAの最大設定では約1.5時間を要する。モデル・層・接頭文脈ごとに辞書を持つため、複数の独立した接頭文脈を同時に運用する際は辞書管理とメモリ常駐量が問題となる。通常生成部分の自己注意・KVも残るため、長い接頭文脈の再注意が消えることとLLM全体の計算が消えることは別である。

## 既存研究との差と運用上の位置づけ

KVzipのようなKV圧縮は接頭文脈のキー・値を減らして残すが、生成時にその残存KVへ注意する。文脈蒸留は接頭文脈の効果を重みへ内在化するが、勾配に基づく追加学習が必要となる。ASMは**重みを変えず、接頭文脈の注意出力そのものを問い合わせで検索できる辞書へ変換**する第三の経路である。前処理を使い回せる固定文脈・多数要求に向く反面、任意の動的な文脈をその場で検索するRAGと同じ自由度はない。

ローカルLLMへ応用する場合は、モデルと接頭文脈ごとの辞書作成、辞書のGPU常駐量、近傍検索カーネルの互換性、入力分布の安定性を先に評価すべきである。論文の1.36倍や1.8倍はRTX Ada 4500上の注意演算の特定条件であり、RTX 4070 Superや任意のLLM推論フレームワークにそのまま適用できる測定ではない。推論基盤の採用判断には、全体のトークン毎秒、初回トークン遅延、辞書構築費用、品質を同時に測る追加検証が必要となる。
