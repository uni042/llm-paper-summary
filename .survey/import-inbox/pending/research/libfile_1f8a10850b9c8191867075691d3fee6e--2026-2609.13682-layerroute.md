# LayerRoute: Adaptive Layer-Skipping with LoRA-Preserved Quality for Efficient LLM Inference

## 概要
Transformerは通常、入力の難しさに関係なく全tokenを全layerへ通す。LayerRouteはQwen2.5-0.5B-Instructの24 blockそれぞれへ小さなbinary routerを置き、入力に応じてblockを実行するかskipするか決める。同時にrank-8 LoRAをattention projectionへ入れ、layerを飛ばすことで失われる表現能力をparameter-efficientに補償する。

10個の独立seedで学習したところ、全runで中間のlayer 8〜16という同じ9層がskip-eligibleになる構造へ収束した。壁時計速度は全runで改善し1.02〜1.06倍、平均1.04倍。LoRA適応により評価splitのperplexity差は平均-1.16/-1.11で、backboneより悪化しなかった。さらにskip-eligible layerではheld-out sampleの87〜100%でrouter decisionが実際のskip/runを変え、固定pruningではなく入力依存routingであることを確認する。

## 問題設定
layer skippingは計算量を直接減らせるが、固定して層を削ると簡単な入力にも難しい入力にも同じdepthしか与えられず品質低下が起こる。入力依存routerを使う場合も、skipで表現分布が変わるため、元モデルをそのまま使うだけでは品質を維持しにくい。またFLOPs削減が実際のwall-clock高速化へつながるかはrouter overheadやkernel launchの影響を受ける。

LayerRouteは「どの層を入力依存で飛ばすか」と「飛ばした状態へ残りのnetworkをどう適応させるか」をjoint trainingする。backbone全体を再学習せず、routerとLoRAだけを更新することで学習費を抑える。

## 手法
各24 transformer blockへ約21.5K parameterのper-layer hard-gated routerを追加する。routerはhidden representationからbinary gateを出し、forwardではhard decisionでblockを実行/skipする。離散decisionは通常gradientを流せないため、straight-through estimatorを使ってbackpropagation時に近似gradientを通す。

同時にattentionのQ/K/V/O projectionへrank 8のLoRAを追加し、合計約1.08M parameterを学習する。backboneは固定される。目的関数はlanguage-modeling lossへgate regularizationを加え、品質だけを追って全layerを常時実行する解に戻らないようskipを促す。

重要なのは、routerだけを学習して既存backboneへ無理にskipを課すのではなく、LoRAがskip後のrepresentation distributionへ残りの経路を適応させる点である。この共同最適化により、計算削減とperplexity維持を同じtraining objective内で扱う。

## 評価条件・主要結果
| 観点 | 条件・結果 |
|---|---|
| backbone | Qwen2.5-0.5B-Instruct、24 blocks |
| router | 各layer約21.5K parameters |
| LoRA | rank 8、約1.08M parameters |
| 再現性 | 10 independent seeds |
| skip構造 | 全10 seedでlayer 8〜16の9層がskip-eligible |
| wall-clock | 1.02〜1.06倍、平均1.04倍高速化 |
| 品質 | perplexity delta平均 -1.16 / -1.11 |
| 入力依存性 | held-out samplesの87〜100%でgateが実skip/runを変更 |
| 学習 | single A100で7分未満 |

大きなFLOPs削減率だけを示すのではなく、全seedでwall-clock speedupが正であることを確認した点は重要である。一方、平均1.04倍という利得はrouter overheadや小規模modelの実行特性を含む現実的な値で、理論的なskip率ほど大きくない。

## 既存研究との差
固定layer pruningに対し入力依存routingを使い、既存のadaptive depth方式に対してLoRA補償を同時学習する。さらに単一runの良い結果ではなく10 seedで同じskip-eligible中間層へ収束すること、router decisionがsampleごとに実際に変化すること、FLOPsではなくwall-clockまで検証することを強調している。

## 限界
評価backboneは0.5B級Qwen2.5であり、70B級やMoE、tensor-parallel servingへ同じ1.04倍が移る保証はない。routerとLoRAの学習が必要なので完全なtraining-free最適化ではない。skip可能層が主に中間9層へ集中する結果が他architectureでも再現するかも未確定である。また大batchやcontinuous batchingではdynamic control flowがGPU batching効率を落とす可能性があり、論文の単体wall-clock結果だけではserving throughputを結論できない。
