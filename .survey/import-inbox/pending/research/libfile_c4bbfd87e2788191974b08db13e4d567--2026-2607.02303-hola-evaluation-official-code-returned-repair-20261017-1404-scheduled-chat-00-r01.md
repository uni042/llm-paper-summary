# HOLA：線形注意の再帰状態に「忘れたくない事実」を保持する厳密KV記憶

## 概要

線形注意（Linear Attention）や状態空間モデル（State Space Model; SSM）は、入力履歴を固定長の再帰状態へ要約するため、過去の全トークンに対応する鍵・値キャッシュ（Key-Value cache; KVキャッシュ）を保存する全注意と比べて、長文脈の記憶容量を一定に保ちやすい。しかし、固定長状態には記憶できる連想関係の数に限りがある。似た鍵方向へ新しい情報を書き込むと、古い鍵と値の対応が上書きされ、遠くにある一度だけ出現した事実を正確に取り出す能力が低下する。

HOLA（Hippocampal Linear Attention）は、この問題を生物学的な補完学習系（Complementary Learning Systems; CLS）の比喩で整理する。再帰状態は一般化しやすい情報を圧縮する「新皮質」に相当し、別に設けた少量の厳密KVキャッシュは、特定の事実を保持する「海馬」に相当する。二つの記憶を併用することで、全注意のように全履歴を保存せずに、重要な遠距離の連想を残すことを狙う。

技術上の核心は二つある。第一に、再帰状態への更新で既に計算している予測残差と書込み強度から、保存すべきKVの重要度を決める。第二に、保存したKVを単純に平均せず、専用の正規化を使って鋭いSoftmax検索を行う。340MパラメータのGated DeltaNet（GDN）に適用した実験では、Wikitext-103困惑度が27.32から22.92へ16.1%改善し、32K文脈の単一needle検索正答率が0.14から0.58へ上がった。これは再帰状態だけを使う同一基盤との比較であり、全注意の精密検索を完全に置き換えたという意味ではない。

## 問題設定

全注意では過去の全トークンの鍵k_iと値v_iを保持し、問い合わせqに対して類似度を計算して参照する。メモリは文脈長Tとともに増えるが、過去の個別トークンを参照できる。一方、DeltaNet系の線形注意は過去の関係を行列Sへ集約し、読み出しをq^T Sで行う。Sの形状は固定なので、文脈が長くなっても保存容量が増えない。ただし、Sの表現能力を超える数の異なる鍵・値関係を詰め込むと、後から来た書込みが古い情報を壊す。

通常の補助キャッシュとして直近wトークンを保存する方式が考えられるが、必要な事実が数千トークン前にあれば窓から追い出される。重要なのは新しさではなく「再帰状態だけでは復元しにくい事実」を見つけることである。HOLAは別途学習する追い出し器を作らず、再帰状態の更新規則そのものが出す残差を利用する。

## 手法

### 1. Delta則の更新量を記憶重要度に転用する

GDNの基本となるDelta則では、時刻tの鍵k_t、値v_t、書込み係数β_tと前状態S_{t-1}から、予測残差e_t = v_t − k_t^T S_{t-1}を計算する。再帰状態はS_t = S_{t-1} + β_t k_t e_t^Tで更新される。k_tが単位長なら、状態更新行列Δ_tのフロベニウスノルムは||Δ_t||_F = β_t ||e_t||になる。

HOLAはこのスカラーm_t = β_t ||e_t||を「驚き度」または書込み量として使う。残差が大きければ、現時点の状態がその値を十分予測できない。βが大きければ、モデルがその残差を状態へ強く反映した。両者の積が大きいトークンを保存すれば、再帰状態が苦手とする例外的な鍵・値対応を優先して残せると考える。これは追加の追い出しネットワークを必要としない。

各層は、これまで見たトークンのうちm_tが大きい上位w件を、厳密な鍵・値の組として保持する。論文の既定値はw=64である。位置の新旧を問わず保存するため、重要度が高ければ遠くのトークンも保持できる。ただしm_tは書込み時に決まり、将来の質問内容を直接予測するものではない。保存されなかったトークンが後から重要になっても復活できない。

### 2. 再帰状態と厳密KVの半パラメトリック読出し

著者は記憶を、入力列から問い合わせqと値vの関係を学ぶ推論時計算の回帰（Test-Time Memory Regression; TMR）として捉える。GDNは固定長状態Sだけからq^T Sを出すパラメトリックな推定器であり、全注意は全KVを保持する非パラメトリックな推定器である。HOLAはその中間に位置し、状態Sと少量の厳密KV集合A_tを併用する。

一般形はo_t = q_t^T S_t + λ_t g_t(q_t)であり、g_tはキャッシュからの検索結果、λ_tは混合係数を表す。これにより、よく圧縮できる情報は再帰状態から、個別の記憶を必要とする情報は厳密KVから補完する。実装では永続的な上位64件に加え、処理中のチャンク内のトークンとヌル用のシンク要素を参照できるようにする。チャンク長C=256のとき、可視KV集合は最大w+C+1≒321件に制限される。

### 3. キャッシュだけを鋭く検索する正規化

DeltaNet/GDNの状態更新には、鍵と問い合わせの単位L2正規化が重要である。このままキャッシュ注意にも使うと、鍵と問い合わせの内積が小さくなり、Softmaxの重みがほぼ一様になる。論文の例では、64件の中に完全一致する鍵があっても、単位L2のままでは注意質量が約3.5%にしかならず、厳密KVを保持した意味が薄れる。

そこでHOLAはキャッシュ読出し経路だけにRMS正規化と学習可能なスケールγを適用する。キャッシュ用の問い合わせと鍵のノルムを概ね√dに戻し、Softmaxの対数スコアの差を拡大して、近い鍵へ鋭く注意を集中させる。再帰状態の更新経路では従来どおり単位L2正規化を維持する。状態更新に大きなノルムを入れると、更新作用素I−βkk^Tの固有値が安定域から外れる恐れがあるため、二つの経路を分離することが重要である。

### 4. GDNへの実装とメモリ費用

実験はGated DeltaNet（GDN）を基盤とし、状態の減衰係数αを含む更新則へHOLAを加える。340Mモデルは24層、4ヘッド、ヘッド次元256で、追加学習パラメータはキャッシュ側のRMS正規化スケールとゲートなど約12,480スカラー、モデル全体の0.004%未満である。

永続キャッシュ64件とチャンク256件をbf16で保持する場合、24層・4ヘッド・次元256のKVは概算31MBである。実測のピークGPU割当はバッチ1の復号時、32Kと128Kの両文脈でGDN 0.72GBに対しHOLA 0.75GBだった。全履歴KVを保存する方式に比べて小さな増分で済むが、厳密KVがゼロになるわけではなく、状態キャッシュと追加KVの双方を保持する。

## 既存研究との差

GDNは全履歴を再帰状態へ圧縮するため、記憶費用は小さいが厳密抽出が苦手である。直近窓付きの混合モデルは最近のトークンを正確に保持できる一方、遠距離の重要トークンを窓から追い出す。HOLAは窓の位置ではなく、再帰状態が予測できず強く書き込んだ情報を保存するため、離れた事実を残せる。

学習可能な追い出しネットワークを使うLTEなどと異なり、HOLAの重要度はDelta則の既存計算から得られ、専用の追い出し器を学習しない。さらにGDNの各層へ少量の厳密KVを直接付けるため、注意層と再帰層を交互に配置する大きな構造変更とも異なる。実装上の代償は、キャッシュの選択・更新と鋭い検索カーネルの追加である。

## 限界・負の結果・実用上の含意

第一に、厳密KVは最大w+C+1≒321件の有界集合であり、全トークンを保持しない。複数の重要事実がこの容量を超えたり、書込み時には残差が小さいが将来の質問で重要になる事実があったりすると、必要なKVが残らない可能性がある。32K単一needleの正答率0.58はその限界を示す。

第二に、HOLAのFDA抽出スコア20.1は全注意Transformer++の46.1に届かない。再帰状態を補助する厳密キャッシュは、任意の過去位置を正確に再生する能力を全注意と同等にはしない。常識課題の平均はGDN、HOLA、直近保持の間でほぼ横ばいであり、すべてのタスクが改善するわけでもない。

第三に、検証は主に340MまでのGDN系列であり、著者は主要規模が単一シードであること、学習可能な追い出し器との同一メモリ条件の比較を行っていないことを明示する。GDN以外のMamba系・全注意モデル、数十億パラメータ以上のLLM、MoEへの移植性は未検証である。今回の論文からWindows 11のllama.cpp、Ollama、RTX 4070 Super 12GBでの動作や高速化を保証することはできない。

第四に、追加メモリが小さいという結果はバッチ1の復号時、特定の340M構成での計測である。複数要求を同時処理する場合は要求ごとのキャッシュと状態が必要になり、メモリは同じ0.75GBに固定されるとは限らない。さらに品質改善は示されているが、エンドツーエンドのサービング処理量やGPUカーネル効率について十分な比較値はないため、困惑度改善を速度改善と読み替えない。
