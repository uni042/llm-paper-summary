# RAGCache: Efficient Knowledge Caching for Retrieval-Augmented Generation
## 概要
検索拡張生成（Retrieval-Augmented Generation; RAG）は検索文書をpromptへ注入するため、同じ知識が複数requestで再利用されても毎回長いprefillを実行する。RAGCacheはretrieved knowledgeの中間状態をcacheし、再出現したchunkのprefillを省くsystemである。

## 問題設定
一般的なprefix cacheは完全一致prefixには強いが、RAGでは複数文書の組合せと順序がrequestごとに変わる。さらにGPUだけへcacheすると容量不足、hostだけでは転送latencyが増える。検索と生成を直列化するとvector retrievalの待ちもTTFTへ加算される。

## 手法
RAGCacheはknowledge chunkを木構造で管理し、共有prefixとなる中間状態をGPUとhost memoryへ階層配置する。replacement policyは通常のLRUだけでなく、RAGの再取得パターンとLLM側の再計算costを考慮し、高価値entryを高速tierへ残す。検索結果が順次得られることを利用してretrievalとLLM側準備をoverlapし、cache hit時には既存stateを再利用して残りだけを計算する。

## 評価条件
|項目|条件|
|---|---|
|LLM runtime|vLLM|
|vector DB|Faiss|
|比較|vLLM+Faiss基準|
|主指標|time to first token、request throughput|
|memory|GPU + host memory hierarchy|

## 主要結果
vLLM+Faissに対しtime to first token（TTFT）を最大4倍短縮し、throughputを最大2.1倍へ改善する。効果の中心はknowledgeのprefill再計算削減であり、同一知識が繰り返し取得されるworkloadほどcache hitの価値が高い。retrievalとのoverlapはcache missでも直列待ちを削る。

## 既存研究との差
一般LLM prefix cacheではなく、RAGのknowledge単位を第一級cache objectとして扱う。knowledge treeにより文書組合せが異なるrequest間でも共有可能な中間状態を再利用し、GPU/CPU階層とreplacementをRAG workloadへ合わせる。

## 限界
cache効果はknowledge再利用率へ依存し、毎回異なる文書が取得されるworkloadではmemory消費に対する利得が小さい。文書更新時のinvalidatonや、現代のchunked-prefill/disaggregated servingとの相互作用は後発systemで再評価が必要である。
