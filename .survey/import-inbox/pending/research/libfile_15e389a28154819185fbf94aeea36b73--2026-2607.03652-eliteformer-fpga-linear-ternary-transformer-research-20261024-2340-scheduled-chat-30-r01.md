# ELiTeFormer：線形注意と三値演算を一体設計したFPGA向けTransformer

## 概要

ELiTeFormerは、言語モデルの注意機構と全結合層を個別に高速化するだけでは、再構成可能な論理回路（Field-Programmable Gate Array; FPGA）の特性を十分に利用できないという問題に取り組む。従来のTransformerをそのままFPGAへ移植すると、長文脈で増大するKVキャッシュ、可変長の注意計算、精度の高い行列積のための演算器が制約になる。提案方式は、短い局所窓の注意と線形注意を併用し、重みを-1、0、+1の三値にした射影を専用処理要素で実行する。重みが三値なら入力を通す・符号反転する・ゼロにするというビット操作で乗算を置き換えられ、FPGAのDSP乗算器に依存しない射影回路を構成できる。

モデルはBitNet b1.58の8B規模の低精度チェックポイントから注意機構を蒸留して作り、FPGA回路は高位合成（High-Level Synthesis; HLS）で生成する。モデル構造の変更と演算回路の設計を一体化する点が新規性である。論文はLLaMA 3 8Bとの比較で重み約10倍、KVキャッシュ約12.8倍の圧縮を主張し、FPGA実機の縮小1B構成で最大3.9倍の生成ステップ遅延短縮を報告する。ただし、8B全体のFPGA結果はシミュレーションであり、8Bモデルをそのまま実機で動かした結果ではない。

**最も重要な交換条件はモデル品質である。** MMLUの5-shot正答率はLLaMA 3 8Bの66.6に対してELiTeFormer 8Bは31.9で、34.7ポイント低い。論文が述べる「BitNet b1.58より3ポイント低い」は34.9対31.9という限定的比較であり、通常のLLaMA 3 8Bに対する品質維持を意味しない。品質が大きく異なるモデル間のFPGA対GPU速度比較を、同品質での推論高速化として扱うべきではない。

## 問題設定

### 長文脈復号で増える状態と専用回路の不整合

標準的な自己注意は、生成位置の問い合わせを過去のすべての鍵と照合し、その注意重みで値を合成する。復号時の1トークンに対する計算・メモリアクセスは過去文脈長に依存し、保持するKVキャッシュはバッチ数と文脈長に比例する。GPUは多数の行列演算を効率よく処理できるが、長い履歴や大きなバッチではメモリ容量と帯域が律速になる。FPGAは任意のビット幅や演算パイプラインを作れる一方、可変長の巨大なKV行列と、精度の高い乗算器を大量に用意する構造は資源効率が悪い。

線形注意（Linear Attention）は、通常のsoftmax注意を分離可能な特徴写像で近似し、過去の情報を固定サイズの再帰状態へ蓄積する。これにより復号時に毎回全履歴を走査せずに済む。ただし通常のsoftmax注意と数学的に同一ではなく、必要な情報を長期に保持できず品質が落ちることがある。短い窓だけを通常の注意で残せば局所的な精密な参照を補えるが、窓長とモデル品質には交換条件がある。

三値重みのBitNet b1.58は、線形射影の重みを-1、0、+1で表現する。FPGAでこの重みと入力を掛けるとき、一般的な浮動小数点乗算を行わずに、符号操作と加算で実現できる。これにより重みの保存容量と演算器の消費を抑えられるが、低精度化した重みを使うために追加学習が必要で、もとのモデルの品質を自動的に保てるわけではない。

## 手法

### 1. 固定状態の線形注意と局所窓注意を並列に使う

ELiTeFormerの注意機構は、線形注意の再帰状態と、直近wトークンの局所窓KVキャッシュを併用する。線形注意側は特徴写像した鍵と値の積を固定サイズの状態へ加算していき、生成時は現在の問い合わせとその状態から出力を計算する。局所窓側は直近wトークンに通常の注意を行い、局所情報を正確に参照する。二つの出力を統合することで、全履歴を保存しない線形注意の効率と、短い範囲のsoftmax注意の表現能力を両立しようとする。

原著のモデル比較表では、標準LLaMA 3の注意キャッシュを概ね2BNhd、ELiTeFormerをBh(2wd+d²)と表す。Bはバッチ、Nは文脈長、hはヘッド数、wは局所窓、dはヘッド次元である。Nが大きくても、wとdが固定なら後者の状態量はNに比例して増えない。これが長文脈でKV容量を削減できる理由であり、演算カーネルだけの圧縮ではなくモデル構造自体の変更による効果である。

局所窓は単に小さければよいわけではない。著者は64、128、256トークンの窓を試し、窓64では開発データのパープレキシティ（Perplexity; PPL、低いほど良い）が大きく悪化することを確認した。最終的には256トークン窓を採用する。線形注意の特徴写像の一部は精度維持のため高精度のまま保持し、これが基底モデルに対して約1%の追加パラメータを要する。すべての計算が三値化されるわけではない。

### 2. 三値重みを乗算器不要の処理要素へ写像する

BitNet b1.58の射影では重みが-1、0、+1のいずれかである。専用の処理要素（Processing Element; PE）は、入力値をレジスタへ保持し、圧縮された重みを読み込む。重みが+1なら入力をそのまま加算し、-1なら符号を反転して加算し、0なら寄与を消す。ビットマスク操作で三値の効果を実現し、専用の浮動小数点乗算器を使わずに線形射影を計算する。

論文の実装例は8ビットに4個の2ビット重みを格納する簡易方式を採る。これは各重みを16ビットとして保存する場合の8倍圧縮に相当する。一方、論文が挙げるモデル全体の約10倍圧縮は、さらに効率的なパッキングなどを考慮したモデル表現の比較であり、実装例のすべてのバス転送が常に10倍になるわけではない。正規化など高精度が必要な小さい行列は浮動小数点のまま読み込む。

射影用PEは、入力の再利用と小バッチ内の並列化を高めるために、入力・出力をオンチップのブロックRAM（Block RAM; BRAM）へ配置する。複数の重みが同じ入力に作用する間は入力を保持し、重みの転送を再利用する。小バッチを増やすと並列度は上がるが、レジスタ・BRAM・論理回路の使用量も増える。局所窓注意の状態はバッチ数に比例するため、線形射影と注意で同じ並列化戦略を無制限に適用することはできない。

### 3. 推論を段階分割して回路パイプラインを組む

FPGA実装は各層を、Q/K/V射影と位置埋め込み、線形注意と局所窓注意、全結合層の上向き・ゲート射影、全結合層の下向き射影という複数段階に分ける。前段からの出力をオンチップBRAMで受け、次段が処理する。各段階は別の小バッチを並行処理できるため、単一トークンだけを順番に計算するより演算器の稼働率を上げられる。

ただし、正規化（RMSNorm）などでは一つのトークンの全成分が揃わなければ次段へ進めず、同期境界が残る。FPGAの演算器を多数配置しても、依存関係を越えて無制限に処理を重ねることはできない。原著はメモリマップAXIインターフェースの512ビット幅と最大4KBのバースト転送を使い、外部DRAMから重みを読み、オンチップで展開・演算・必要に応じて書戻す流れを構成する。

線形注意の再帰状態は各トークンで更新されるため、状態の書戻しは必要である。局所窓注意は直近KVを保持し、古い部分を追い出す。回路が静的なメモリ配置を利用できるのは、注意機構の状態量が事前に決まるためである。これは任意の既存LLMを無変更でFPGAへ載せられるという意味ではなく、専用に学習・蒸留したモデルを前提とする。

### 4. 注意機構の蒸留と学習の工程

著者はBitNet b1.58 8Bのチェックポイントを出発点とし、LoLCATsの注意蒸留（attention distillation）を適用する。元の注意ブロックの出力を教師とし、線形・局所窓のハイブリッド注意が同じような隠れ表現を出すよう、注意部分を中心に学習する。基底モデルの全重みを新たにゼロから学習するのでなく、既存の低精度チェックポイントから注意構造を変換することで学習費用を抑える。

学習には単一A100を使用し、Alpacaの清掃済みデータ5万サンプル、バッチ8、系列長1024、約4000回の重み更新を行う。学習率は2×10^-5から逆平方根型のスケジュールで1×10^-7まで下げる。蒸留後に低ランク適応（Low-Rank Adaptation; LoRA）で追加微調整する試みは、かえってPPLを悪化させたため最終構成には採用していない。これは効率化のための追加学習にも難しさがあることを示す。

### 演算ブロックのシミュレーション

Bambu HLSによる回路単位の比較では、三値射影が通常の高精度射影より平均9.6倍少ないクロック数で処理されると報告する。注意ブロックでは、出力射影を除く中核注意計算が長文脈で最大4.4倍高速化する。これはモデル全体の実機推論速度ではなく、合成したブロックのシミュレーション結果である。特に注意の演算量削減は、全履歴のsoftmax注意を線形・窓注意へ変更した効果を含み、同じ注意演算をより速く計算しただけではない。

### 8Bのシステム推定と帯域正規化

|---|---:|---:|---:|
| LLaMA 3 8B / A100 / vLLM | 544ms | 5.71 tok/s | 5.71 tok/s |
| BitNet b1.58 8B / A100 / bitnet.cpp | 319ms | 14.12 tok/s | 14.12 tok/s |
| ELiTeFormer 8B / VCK5000想定 | 120ms | 12.52 tok/s | **82.27 tok/s（推定）** |

原著Table 4。8BのFPGA数値はVitis HLSに基づくシステム推定であり、実機の8Bスループットではない。遅延120ms対544msは約4.53倍の差、処理量12.52対5.71は約2.19倍の差である。一方、**ELiTeFormerの12.52 tok/sはBitNetの14.12 tok/sより低い**。82.27 tok/sはVCK5000のDDR帯域を別のU280 HBM帯域へ比例換算した予測値であり、実測された性能として比較してはいけない。遅延は単一サンプルの1生成ステップ、処理量はバッチ32で5トークンの平均で、両指標の負荷条件も異なる。

### 縮小1Bの実機遅延・電力

実際にVCK5000へ配置したのは縮小1B構成である。原著Figure 5は長文脈で通常のLLaMA 3 1BをA100で動かす場合に比べ最大3.9倍の遅延短縮、A100上のvLLMに比べ2.6倍の遅延短縮、最適化したBitNet GPU実装に比べ1.3倍の短縮を示す。これは初期化後の単一生成ステップの比較であり、サービス全体の初回トークン遅延やprefillを含むエンドツーエンドの処理時間とは異なる。

| 1B・文脈16,384 | 平均消費電力 | トークン/J |
|---|---:|---:|
| LLaMA 3 1B / A100 / vLLM | 83W | 0.03 |
| BitNet b1.58 1B / A100 / bitnet.cpp | 80W | 0.07 |
| ELiTeFormer 1B / VCK5000 | 26W | 0.30 |

Table 5の値では電力は83/26≈3.19倍低く、トークン/Jは0.30/0.03=10倍である。しかし本文はトークン/Jを5.6倍改善と述べており、**表の丸め値と本文の5.6倍は一致しない**。測定器はFPGA側がxbutil、GPU側がnvidia-smiであり、装置外のシステム電力やデバイス面積を含めた比較ではない。消費電力3.2倍とエネルギー効率5.6倍を同一の指標として扱わない。

### FPGA資源使用率と構成要素の律速

VCK5000の資源推定では、BRAM 41.5%、DSP 19.5%、フリップフロップ30.2%、論理テーブル（Look-Up Table; LUT）44.7%を使用する。三値射影用PEでは専用DSP乗算器を不要にできるが、**システム全体のDSP使用率は0%ではない**。注意計算などに浮動小数点演算が残るためである。設計内のBRAM使用量の約80.4%を注意段階が占め、LUTも約60.5%を注意段階が使う。三値射影をさらに高速化しても、注意側のBRAM・LUTが全体の並列化を制約する可能性がある。

## 既存研究との差

FlightLLMは既存のLLMをFPGAへ写像し、専用命令体系などを使って事前入力と復号を同じ装置で扱う。ELiTeFormerは、モデル自体を線形・窓注意と三値射影へ変え、事前入力は別装置で行う異種構成を想定し、FPGAは主に復号へ特化する。したがって「汎用モデルをそのまま動かす」能力ではFlightLLMの方が適用範囲が広い一方、専用モデルならELiTeFormerの固定状態と三値演算を深く活用できる。

BitNet b1.58は主として低精度のモデル構造・学習方式を提案する。ELiTeFormerはそれをFPGAの処理要素へ落とし込み、さらに注意機構も長文脈向けへ変える。LoLCATsは既存の注意を線形注意へ蒸留する枠組みを提供するが、ELiTeFormerは低精度重みとの組合せ、窓長の感度、回路パイプラインまで一体として検討する。Hedgehogなどの線形注意単独方式とは、重み圧縮と回路専用化が加わる点が異なる。

## 限界・再現性・実装状況

第一に、比較モデル間の品質差が大きい。MMLU 31.9はLLaMA 3 8Bの66.6を大幅に下回り、同品質のハードウェア加速とみなすことはできない。低精度化の前処理に必要な学習費用も無視できず、著者は出発点のBitNetチェックポイントの事前学習に相当する約8700 GPU時間を挙げている。これはELiTeFormerの追加蒸留だけの費用ではない。

第二に、8Bシステムの主要な高速化はHLS推定であり、実機での完全な8B推論実証ではない。実機は1B縮小構成である。8BのHBM帯域正規化82.27 tok/sは別FPGAへの予測であり、実機測定と分離すべきである。FPGA側は事前入力を別装置へ委ねる構成を想定するため、prefillとモデル転送を含むサービス全体の性能を検証する必要がある。

第三に、三値射影で乗算器を不要にしても注意段階ではDSPや高精度演算が残る。BRAMとLUTは注意段階が支配的で、局所窓やバッチを増やすと資源使用量が上がる。新しいFPGAへ移植するにはメモリ帯域、クロック周波数、合成ツール、配置配線の制約を再検証する必要がある。

第四に、論文のモデル比較には異なる事前学習データとチェックポイントが混在する。MMLU等の品質差の原因を、線形注意・三値化・事前学習データのどれか一つへ厳密に分解する実験は十分ではない。蒸留後LoRAの失敗は観測されているが、より大規模な再学習や別の最適化手順で回復可能かは未確定である。

第五に、公開一次資料から実機の完全な再現用コードURLを確認できなかった。Vitis HLS 2021.2、Vivado、Bambu HLS、Verilator、VCK5000、A100等の環境は記載されているが、全測定値を独立再現するにはビットストリーム、重みチェックポイント、FPGA構成とホスト条件が必要である。Table 5のトークン/J改善倍率についても、本文と表の差を解消する追加データが望まれる。

## 主要結果

ELiTeFormerの技術的貢献は、長文脈に対して状態量が固定の注意機構と三値射影を同時に設計し、専用のFPGAデータフローへ写像したことにある。モデル重み・KVキャッシュの圧縮と演算ブロックの高速化は確認できる。縮小1Bの実機で長文脈生成の遅延を減らしたことも意義がある。ただし、8B実機の速度、別帯域への正規化予測、1B実機の速度、モデル品質を混ぜないことが重要である。現状は、汎用LLMを同品質のまま置き換える完成品というより、低精度・線形注意・専用ハードウェアの協調設計により達成できる性能と品質の交換条件を示した研究である。
