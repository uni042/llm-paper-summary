# SPECTRE: Hybrid Ordinary-Parallel Speculative Serving for Resource-Efficient LLM Inference

> 需要の少ない小型model serviceの余剰生成能力を、混雑した大型model service向けの遠隔draft modelとして再利用する。並列化が常に有利とは限らない点をrollback率から理論化し、通常型と並列型をbatch単位で切り替えることで、共有serviceの資源利用率とtarget throughputを同時に改善する。

## 正式監査結果

2026-09-09時点で、同一研究の正本は arXiv:2605.08151v2。arXiv上ではv1が2026-05-04提出、v2が2026-05-12改訂で、PDF本文の日付表示はMay 13, 2026である。著者はJincheng Xie、Yawen Ling、Qi Xiao、Feiyu Zhang、Zhongyi Huang、Wen Hu、Yu Zhengの7名。所属はTsinghua University、AI Infra Team at JDT、JD iCity / JD Technology / JD Intelligent Cities Researchで、PDF著者欄と一致する。

実装参照先はSGLang PR #22272。PRはSPECTREの実装変更を含むが、2026-09-03にclosedとなり、`merged_at = null` である。したがって「SGLangへ正式merge済みの機能」とは扱わず、「論文著者らが提示したSGLang向け実装PR」として記録する。PR差分には、可変draft token数をtarget verification metadataへ反映する変更などSPECTRE用の実装要素が確認できる。

評価は模擬ではなく実機。draftとtargetは別NVIDIA H200 GPUに配置され、Qwen3-0.6B→Qwen3-32B、Qwen3-0.6B→Qwen3-235B-A22B（target TP=8）、DeepSeek-R1-Distill-Qwen-1.5B→DeepSeek-R1-Distill-Qwen-32Bを評価している。datasetはGSM8K、MATH500、Minerva Math、LongBench、MRCR、ShareGPT。baselineはAR、Standalone、EAGLE-3、PEARL、MineDraft。原則greedy decodingでtargetは1 roundあたり4 speculative tokenを検証する。

主要値も本文表と一致する。Qwen3-32B・batch 64・LongBenchはAR 310.59 tok/sに対しSPECTRE 706.81 tok/sで2.28×。DeepSeek-R1-Distill-Qwen-32B・batch 128・LongBenchはAR 480.42 tok/sに対し998.38 tok/sで2.08×、そのsettingで最強baseline比+66.4%。Qwen3-235B-A22B TP=8・batch 128ではLongBench-v2 / MRCR / ShareGPTで最強baseline比+19% / +12% / +14%。shared draft trafficではdraft-QPS=8、target-QPS=32でもtarget throughput低下は2%未満と報告される。

MineDraft比較には明確な注意が必要で、論文自身が公式MineDraft実装はvLLM 0.9.2、SPECTRE側はSGLang v0.5.7と記している。長文条件ではMineDraftにOOMが発生し、一部比較から除外される。したがってMineDraftに対する優位はmethod純粋比較ではなくframework/version差・実装成熟度差を含む。

分類は speculative decoding / LLM serving / multi-tenant resource reuse が妥当。storage I/OやSSD offloadを主題とする研究ではなく、主要資源問題はremote drafter compute、network、draft KV state、target verificationとのoverlapである。品質面はtarget側verificationによりlossless speculative decodingを維持するが、prompt compressionはdraft proposal品質とaccepted lengthを変え得る。

監査上の主要な限界は、H200中心の実験、model pairが3組、prompt retained ratio p=0.1が特定TP8設定向け、tail latency/SLO評価が限定的、MineDraftとのframework差、system-level benefitが公開API価格仮定に依存する点。これらを踏まえても、論文の中心主張である「低稼働tail modelをremote drafterとして再利用し、ordinary/parallelを動的切替してthroughputを改善する」という位置付けと主要定量値は一次資料で確認できた。

## 問題設定と新規性

multi-model LLM servingでは人気大型modelへtrafficが集中する一方、long-tail側の小型modelはonlineのままGPU利用率が低いことがある。SPECTREはこの余剰capacityをspeculative decodingのdraft計算へ転用する。

通常型はdraft生成とtarget検証が直列で、並列型は両者をoverlapできるが、事前生成continuationがtarget検証で無効になるとrollbackが発生する。SPECTREは、(1) rollback率の臨界値から通常型/並列型を動的切替、(2) shared draft serviceでspeculative requestを優先しつつ通常trafficのstarvationを防止、(3) targetが速すぎる場合はdraft側promptだけ圧縮、という3点を組み合わせる。

## 手法

batch sizeをB、speculative token数をgamma、平均accepted lengthをL、draft step latencyをTD、target verification latencyをTTとする。通常型throughputは BL/(TT+(gamma-1)TD)。並列型はrollback率rを含め B[r+(1-r)L]/TT と近似できる。比較から、並列実行が有利な臨界rollback率

r* = ((gamma-1)L TD) / ((TT+(gamma-1)TD)(L-1))

を導く。実行時には直前roundの観測rollback率がr*以下ならparallel、それを超えるとordinaryへ切り替える。

ordinary modeではrollback requestのcontinuationをdraft側で再生成してからtarget batchを作る。parallel modeではrollback requestをbonus token＋paddingで直ちにtarget検証へ進め、同時にdraft側で次round continuationを作る。draft tokenはproposalにすぎず、targetでacceptされたtokenだけがcommitされる。

shared draft serverではspeculative requestをnon-preemptiveに次round優先する。連続speculative stepがK=10に達すると通常requestを1 round優先する。target側がTP等で高速化されdraftがbottleneckになる場合、draft promptの先頭と末尾だけを残す。Qwen3-235B-A22B TP=8評価ではretained ratio p=0.1。

実装はSGLangベース。remote replyはrequest/round IDで照合しstale replyを破棄する。timeout連続時はcircuit breakerでremote speculationを一時停止する。draft serverはdecoded token、speculative token、KV cacheをpersistent stateとして保持し、prefix不一致時にrollbackする。通信はZeroMQ、single-nodeはlocal IPC、multi-nodeはTCPで、heartbeat、bounded queue、batched binary messageを用いる。

| Hardware | draft / targetを別NVIDIA H200 GPUへ配置 |
| Pair 1 | Qwen3-0.6B TP1 → Qwen3-32B TP1 |
| Pair 2 | Qwen3-0.6B TP1 → Qwen3-235B-A22B TP8 |
| Pair 3 | DeepSeek-R1-Distill-Qwen-1.5B TP1 → DeepSeek-R1-Distill-Qwen-32B TP1 |
| Dataset | GSM8K, MATH500, Minerva Math, LongBench, MRCR, ShareGPT |
| Baseline | autoregressive, Standalone, EAGLE-3, PEARL, MineDraft |
| Batch | 主に32 / 64 / 128 |
| Decoding | 原則greedy、targetは1 roundあたり4 speculative token |

MineDraftは公式vLLM 0.9.2実装を用いる一方、著者baselineはSGLang 0.5.7で、long-contextではOOMも発生する。したがってMineDraftとの差には実装世代差が混在する。

## 主要結果

TP1 targetでは報告された全dataset/batchでSPECTREが最高throughput。最大でautoregressive比2.28×、strongest speculative baseline比の追加改善は最大66.4%。Qwen3-32B、batch 64、LongBenchでは310.59→706.81 tok/s（2.28×）。DeepSeek-R1-Distill-Qwen-32B、batch 128、LongBenchでは480.42→998.38 tok/s（2.08×）、最強baseline比+66.4%。

Qwen3-235B-A22B TP=8ではdraft promptを10%保持へ圧縮し、LongBench-v2 / MRCR / ShareGPTでstrongest baseline比+19% / +12% / +14%。

shared draft trafficではdraft-QPS=8、target-QPS=32でもQwen3-32BとDeepSeek-R1-Distill-Qwen-32Bのtarget throughput低下は2%未満。system-level benefitはQwen3-235B-A22BでAR 0.38→SPECTRE 0.48（1.26×）、DeepSeek系で0.37→0.67（1.81×）。

accepted lengthはQwen3-32BでSPECTRE 2.59–3.11、Standalone 3.13–3.22、DeepSeek系で3.00–3.61 vs 3.41–3.77。並列baselineよりStandaloneに近いacceptanceを保ちつつthroughputを上げる。

## 品質・memory/I/O

target側rejection samplingが最終tokenを決定するため、draft prompt圧縮はproposal品質とaccepted lengthには影響し得るが、target output qualityを直接変更しない。

主要bottleneckはstorage I/Oではなくremote draft compute、network、draft KV state、target verificationのoverlap。draft側はrequestごとにKVをpersistent保持しrollback時に不要suffixを解放する。したがって本研究のmemory効果はGPU外offloadではなく、shared drafter上でspeculative stateを長寿命化する点にある。

## 既存系統との差

Standaloneは直列でaccepted lengthを取りやすいがoverlapしない。PEARL等はparallel executionを主軸とするのに対し、SPECTREはrollback率でparallel/ordinaryを切り替える。EAGLE-3は専用draft head/checkpoint中心だが、SPECTREは既存小型model serviceをremote drafterとして再利用するresource-sharing問題を扱う。

## 限界

- 主評価はH200中心で、異種GPU・低速networkの評価は限定的。
- model pairは3組で、family差が大きい場合のacceptance behaviorは不明。
- TP=8のprompt retained ratio 0.1は特定構成向けで自動最適化ではない。
- throughput modelは平均latency/accepted length近似でtail latencyやrequest heterogeneityを完全には表さない。
- speculative priorityの通常user側SLO評価は限定的。
- MineDraft比較にはframework/version差が混在する。
- system benefitはcloud price仮定に依存する。

## 研究上の含意

SPECTREはspeculative decodingを単一modelの高速化algorithmから、複数model service間で余剰capacityを融通するserving primitiveへ拡張した。rollback率、draft latency、target verification latencyに応じた動的coordinationは、将来的な異種GPU・elastic serving・tenant SLOを含むschedulerへ接続しやすい。
