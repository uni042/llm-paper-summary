# Paper quality responsibility split — Library-first v11

この文書は現行の論文品質責任を定義する。旧v10機械品質基準は
`.survey/legacy/quality-v10/` に退避済みであり、現行のGitHub公開・取り込み判定には使わない。

## 1. 原則

品質を二つに分ける。

1. **読解ワーカーの意味品質セルフチェック**
   - 論文を実際に読んだワーカーだけが判定・修正する。
   - 一次資料へ戻らないと修正できない項目は、GitHub側・アップロードワーカー側へ移さない。
2. **GitHub側の公開完全性チェック**
   - 論文を読み直さず機械的に確認できる形式・転送・同一性だけを見る。
   - 内容の良し悪し、説明量、手法の深さ、代表結果の妥当性などをFAIL条件にしない。\n   - 例外として、日本語率は本文だけで機械判定・修正できるため従来の70%/80%基準を維持する。

アップロードワーカーは、読解内容を再監査したり、不足した科学的説明を推測で補ったりしない。

## 2. 読解ワーカーが自己チェックする意味品質

Libraryへ「完成」として保存する前に、読解ワーカー自身が一次資料と照合して次を確認する。

- 一次資料を必要範囲まで読み、canonical identity と対象論文が一致している。
- 推測や未確認の補完を事実として書いていない。
- `summary` と `list_summary` が論文固有で、題名の言い換えだけではない。
- 概要から、問題、提案、対象環境、代表的な結果または主要な発見が分かる。
- 手法は入力・観測、主要処理、出力、機構間の流れ、効く理由、主な失敗条件またはトレードオフを追える。
- 評価条件、比較対象、実機/シミュレーション等の前提を混同していない。
- 主要結果は条件・比較対象・意味を取り違えていない。
- 限界と既存研究との差が具体的である。
- 一次資料URLと書誌情報が確認できる。
- 保存前の成果Markdownが極端に短くない。Library/会話ファイルのメタデータで確認できる場合は **UTF-8 4,500 bytes以上を作成時の最低目安** とする。ただしGitHub側の公開FAIL条件にはしない。

このセルフチェックは、読解中の文脈を保持しているワーカーがその場で修正できることを前提にする。

## 3. 現行GitHub側で確認してよいもの

GitHub側の自動処理とアップロードワーカーは、次のような**論文再読を必要としない公開完全性**だけを検査する。

- UTF-8として読み取れる。
- YAML前付けが存在し、構文として読める。
- 公開・同一性に必要な `canonical_id`、`title`、`source`、`summary`、`list_summary` が存在する。
- Markdownコードフェンス等に明白な構文破損がない。\n- 説明本文の日本語率を測り、**70%未満FAIL、70〜80% WARN、80%以上を目標**とする。書誌情報・一次資料・URL・コード等は比率計算から除外する。\n- `list_summary` も日本語率70%/80%の同じ基準を適用する。
- canonical identity、既存path、blob SHA、重複、競合が整合している。
- 構造化レコードの各slotがJSON objectとして読み取れ、レンダラーが必要とする型を満たす。
- 書込み後にmainから同じpathを再取得でき、意図したidentity/contentが反映されている。

これらは科学的内容の再評価ではなく、転送・形式・同一性の確認である。

## 4. GitHub側から撤廃した旧品質FAIL

次は**現行GitHub側の公開条件ではない**。

- 4,500 bytes以上という公開ゲート
- 説明文2,200文字以上
- 説明10段落以上
- 手法4段落以上
- 主要機構ごとの段落数
- 裸の英語専門語0件
- `list_summary` の45〜180文字という機械FAIL
- `list_summary` の45〜180文字以外の長さ・意味品質FAIL、および裸の英語語彙FAIL
- 概要の代表結果を正規表現等で検出するFAIL
- 問題設定・新規性・手法・結果・限界の文字数下限
- 主要機構数の下限
- 定量結果やnegative result等の必須化
- アップロードワーカーが一次資料を再読しないと修正できないその他の意味品質FAIL

内容上の要件そのものは、必要なものを読解ワーカーのセルフチェックへ移す。

## 5. 旧基準の復元

旧v10基準と当時の実装スナップショットは
`.survey/legacy/quality-v10/` に保存している。

復元するときは、単一閾値だけを戻して整合性を壊さず、同ディレクトリのREADMEに記録された対応ファイルを一式で確認する。

## 6. 現行監査スクリプト

`.survey/scripts/audit_paper_quality.py` と `.survey/scripts/paper_quality_gate.py` は、
名称互換のため残す。役割は**公開完全性（publication integrity）と日本語率**に限定する。\n日本語率は70%未満FAIL・70〜80% WARNを維持するが、それ以外の意味品質を数値化したり、読解内容を再判定したりしない。

GitHub Actionsも現行の公開完全性回帰試験だけを実行し、旧一覧文・概要意味監査を公開条件にしない。
